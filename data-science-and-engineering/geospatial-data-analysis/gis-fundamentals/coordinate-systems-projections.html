坐标系与投影变换

核心概念

坐标系（Coordinate Reference System, CRS）是地理空间数据分析的基石。它定义了如何用数值来描述地球表面上的位置。理解坐标系不仅是学术需求——在实际工程中，坐标系选择错误或转换出错会导致数据偏移数十甚至数百公里，直接影响分析结论的可靠性。

地球不是一个完美的球体，而是一个不规则的椭球体（Geoid）。为了用数学模型描述地球表面，大地测量学发展出了椭球体模型（Ellipsoid）和基准面（Datum）两个核心抽象。椭球体定义了地球的数学形状，基准面定义了椭球体与真实地球之间的对齐关系。不同的基准面产生不同的坐标值——同一个物理位置在 WGS84 和 Beijing54 两个基准面下的经纬度数值可能差异数百米。

地理坐标系与经纬度
地理坐标系（Geographic Coordinate System, GCS）使用经度和纬度来描述地球表面的位置。经度表示东西方向的角度（-180° 到 180°），纬度表示南北方向的角度（-90° 到 90°）。这是最直观的地球定位方式，也是大多数 GPS 设备和全球数据集使用的坐标系。


WGS84（World Geodetic System 1984）是当今最广泛使用的全球地理坐标系。GPS 卫星系统直接输出 WGS84 坐标，几乎所有的全球地理数据集（OpenStreetMap、Google Maps、天地图）都以 WGS84 为基础。在 EPSG 编码系统中，WGS84 的代码是 4326。


CGCS2000（China Geodetic Coordinate System 2000）是中国的国家大地坐标系，与 WGS84 高度接近（两者的椭球参数几乎相同），但在高精度应用中存在毫米级差异。中国的官方测绘数据和国土资源管理使用 CGCS2000。


地理坐标系的一个关键限制是它不适合直接进行距离和面积计算。1° 经度在赤道处约等于 111km，但在北纬60° 处只约等于 55.5km。这意味着在地理坐标系下直接使用欧几里得距离公式会产生严重偏差。正确的做法是使用 Haversine 公式或 Vincenty 公式计算球面距离，或者将数据投影到适当的投影坐标系后再计算。


function haversineDistance(lat1: number, lon1: number, lat2: number, lon2: number): number {
  const R = 6371000;
  const dLat = ((lat2 - lat1) * Math.PI) / 180;
  const dLon = ((lon2 - lon1) * Math.PI) / 180;
  const a =
    Math.sin(dLat / 2) ** 2 +
    Math.cos((lat1 * Math.PI) / 180) * Math.cos((lat2 * Math.PI) / 180) * Math.sin(dLon / 2) ** 2;
  return R * 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
}
地图投影的原理与分类
地图投影（Map Projection）是将三维的地球表面转换为二维平面的数学变换。这个过程必然引入变形——没有任何投影能同时保持面积、形状、距离和方向的正确性。选择投影实质上是选择「保留什么、牺牲什么」。


投影按保持的几何属性分为四类：等角投影（Conformal）保持局部形状不变，适合导航和气象；等面积投影（Equal-Area）保持面积比例正确，适合统计分析和专题地图；等距投影（Equidistant）在特定方向上保持距离正确；折中投影（Compromise）在各属性间取得平衡。

UTM（Universal Transverse Mercator）是全球最广泛使用的投影坐标系。它将地球划分为 60 个纵向带（每带6°），每个带使用独立的横轴墨卡托投影。UTM 的优势是在每个带内变形极小（最大比例因子偏差 0.04%），但跨带分析时需要进行坐标转换。


Web 墨卡托（EPSG:3857）是所有在线地图服务使用的投影。它本质上是一个球面墨卡托投影，在高纬度地区面积变形严重（格陵兰看起来和非洲一样大）。但它的优势是数学简单、瓦片切分方便，非常适合交互式地图渲染。需要注意的是，在 Web 墨卡托下进行面积计算会产生显著误差——进行空间分析时必须转换到等面积投影。


坐标转换的实践
坐标转换（Coordinate Transformation）是地理空间工作中最常见的操作之一。它分为两类：同一基准面下的投影转换（从地理坐标到投影坐标），以及不同基准面之间的基准面转换（从 WGS84 到 CGCS2000）。


PROJ 是地理空间领域最核心的坐标转换库，几乎所有的 GIS 软件和编程工具链（GDAL、PostGIS、GeoPandas、Turf.js）都依赖它。PROJ 使用管道（Pipeline）语法来描述复杂的转换步骤链。


中国地图数据的坐标偏移问题是一个工程实践中的重要陷阱。中国法规要求在线公开的地图数据必须使用 GCJ-02（火星坐标系）加密，百度地图在此基础上还有额外偏移（BD-09）。这意味着从 GPS 获取的 WGS84 坐标不能直接叠加到高德地图或百度地图上——必须先进行坐标加密转换。


EPSG 代码系统是坐标系的全球统一编码标准，每个坐标系都有唯一的数字标识。在编程中使用 EPSG 代码可以避免手动指定复杂的投影参数。常见的 EPSG 代码需要熟记：4326（WGS84 地理坐标）、3857（Web 墨卡托）、4490（CGCS2000 地理坐标）、32650（UTM Zone 50N，覆盖中国东部）。


小结
    

  • 坐标系由椭球体、基准面和投影三个层次构成，选择错误会导致数据偏移数百米
    • 

  • WGS84（EPSG:4326）是全球最通用的地理坐标系，GPS 直接输出该坐标
    • 

  • 地理坐标系不适合直接计算距离和面积，需要使用球面公式或投影后计算
    • 

  • 地图投影必然引入变形，选择投影本质是选择「保留什么、牺牲什么」
    • 

  • UTM 将地球分为 60 个带，每带内变形极小，是空间分析的首选投影
    • 

  • Web 墨卡托（EPSG:3857）适合地图展示但不适合面积/距离分析
    • 

  • 中国地图存在 GCJ-02 和 BD-09 坐标偏移，工程中必须正确处理
    • 

  • EPSG 代码是坐标系的统一标识，编程中应始终使用 EPSG 代码指定坐标系
