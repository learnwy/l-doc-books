PostGIS 与空间数据库

核心概念

空间数据库是在传统关系型数据库的基础上扩展了空间数据类型和空间查询能力的数据库系统。PostGIS 是 PostgreSQL 的空间扩展，也是当今最强大、最广泛使用的开源空间数据库引擎。它将空间数据提升为数据库的一等公民——空间列可以像整数或文本列一样参与查询、索引和事务操作。

PostGIS 的核心价值在于将空间分析从桌面 GIS 软件转移到了数据库层。传统的空间分析需要将数据导出到 QGIS 或 ArcGIS 中进行处理，PostGIS 允许直接在 SQL 中完成缓冲区分析、空间连接、拓扑操作等复杂计算。这不仅提升了效率，更实现了空间分析与业务数据的无缝集成。

Geometry 与 Geography 类型
PostGIS 提供两种核心空间类型：Geometry 和 Geography。理解两者的区别是正确使用 PostGIS 的关键。


Geometry 类型在平面笛卡尔坐标系中操作。所有距离和面积计算基于平面几何——这意味着如果数据存储为经纬度（EPSG:4326），直接用 Geometry 类型计算距离会得到「度」为单位的无意义数值。使用 Geometry 类型时，数据应该投影到适当的投影坐标系（如 UTM），或者在查询时进行即时投影。


Geography 类型在球面上操作。它始终假设数据为 WGS84 经纬度，所有计算考虑地球曲率。ST_Distance 对 Geography 类型直接返回米为单位的球面距离，ST_Area 返回平方米为单位的球面面积。Geography 类型的缺点是支持的函数较少（约 Geometry 的 1/3），且球面计算比平面计算慢。


// 创建空间表
const createTable = `
CREATE TABLE poi (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,
  category TEXT,
  geom GEOMETRY(Point, 4326),
  geog GEOGRAPHY(Point, 4326)
);
CREATE INDEX idx_poi_geom ON poi USING GIST(geom);
CREATE INDEX idx_poi_geog ON poi USING GIST(geog);
`;

// 查询5km内的POI（Geography类型直接用米）
const nearbyQuery = `
SELECT name, ST_Distance(geog, ST_MakePoint(116.397, 39.909)::geography) AS dist_m
FROM poi
WHERE ST_DWithin(geog, ST_MakePoint(116.397, 39.909)::geography, 5000)
ORDER BY dist_m;
`;
实践中的选择策略是：如果数据范围是全球或跨大区域，且主要需要距离/面积计算，使用 Geography 类型；如果数据范围是城市级别或更小，且需要丰富的空间分析函数，使用 Geometry 类型配合适当的投影坐标系。


核心空间查询模式
PostGIS 提供了超过 500 个空间函数，但日常工作中 80% 的需求可以通过掌握几种核心查询模式来解决。


空间连接（Spatial Join）是最强大的空间查询模式。它根据空间关系（包含、相交、邻近）将两个表的记录关联起来。例如，将「订单表」与「行政区表」通过 ST_Contains 连接，就能为每个订单标注所属的行政区——这在传统数据库中无法实现。

KNN（K-Nearest Neighbor）查询是 PostGIS 的一个独特优势。通过 <-> 操作符配合 GiST 索引，可以高效地找到距离指定点最近的 K 个记录，而无需计算所有记录的距离。


缓冲区分析（Buffer Analysis）是最常用的派生几何操作。ST_Buffer(geom, distance) 生成围绕输入几何指定距离的面。在 Geometry 类型下，distance 的单位取决于坐标系（度或米）；在 Geography 类型下，distance 始终为米。缓冲区分析常用于：服务覆盖范围评估（每个门店 3km 服务半径）、环境影响评估（工厂周围 500m 内的居民区）。


空间数据管道与 ETL
空间数据的 ETL（Extract-Transform-Load）比传统数据 ETL 复杂得多，因为需要处理坐标系转换、几何验证、拓扑修复等空间特有的环节。


GDAL/OGR 是空间数据 ETL 的瑞士军刀。ogr2ogr 命令行工具可以在任意空间格式之间转换数据，同时完成坐标系转换、属性过滤和几何裁剪。它支持超过 80 种矢量格式和 160 种栅格格式。


几何验证是空间 ETL 中经常被忽视但至关重要的环节。无效几何（自相交多边形、方向错误的环）会导致空间函数返回错误结果甚至崩溃。PostGIS 的 ST_IsValid 检查几何有效性，ST_MakeValid 自动修复常见问题。在加载数据前应始终进行几何验证和修复。


增量更新策略对于持续运行的空间数据管道至关重要。全量替换在数据量大时不可行，需要设计基于时间戳或变更日志的增量同步机制。PostGIS 的 UPSERT（INSERT ... ON CONFLICT）语法配合空间唯一性约束，可以优雅地处理空间数据的增量更新。


小结
    

  • PostGIS 是最强大的开源空间数据库，将空间分析提升到 SQL 层
    • 

  • Geometry 类型在平面上计算（快速但需注意坐标系），Geography 类型在球面上计算（精确但函数少）
    • 

  • 空间连接、邻近查询、缓冲区分析是三种最核心的空间查询模式
    • 

  • KNN 查询通过 <-> 操作符利用 GiST 索引实现高效最近邻搜索
    • 

  • GDAL/OGR 是空间数据 ETL 的核心工具，支持 80+ 矢量格式
    • 

  • 几何验证（ST_IsValid）和修复（ST_MakeValid）是数据加载前的必要步骤
    • 

  • 空间索引（GiST）是所有空间查询性能的基础，建表后必须创建
    •
