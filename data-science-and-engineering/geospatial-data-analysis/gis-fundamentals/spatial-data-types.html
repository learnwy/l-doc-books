Part IV · 伦理与空间数据地理空间数据分析 简介GIS 基础 简介空间数据类型与格式

空间数据类型与格式

核心概念

空间数据类型定义了地理信息的数学表达方式，而空间数据格式定义了这些信息在文件或数据库中的存储方式。理解两者的区别和联系，是构建可靠地理空间数据管道的基础。选择不当的数据类型会限制分析能力，选择不当的数据格式会导致性能瓶颈和互操作性问题。

空间数据从根本上分为两大阵营：矢量数据（Vector）和栅格数据（Raster）。矢量数据用点、线、面等几何对象来表示离散的地理要素（一栋建筑、一条道路、一个行政区），适合表达边界清晰的人造和自然实体。栅格数据用规则网格的像元值来表示连续的空间现象（地表温度、高程、降雨量），适合表达渐变的自然场。

矢量数据模型与 OGC 标准
矢量数据模型的基础是 OGC（Open Geospatial Consortium）定义的 Simple Features 规范。这个规范定义了一组标准的几何类型和空间操作，是所有主流 GIS 软件和空间数据库的共同语言。


Simple Features 的核心几何类型包括：Point（单个坐标点）、LineString（有序点序列连接的线）、Polygon（由外环和可选内环定义的面）、以及它们的 Multi 版本（MultiPoint、MultiLineString、MultiPolygon）。GeometryCollection 是最通用的类型，可以包含任意类型的几何对象组合。


Well-Known Text（WKT）和 Well-Known Binary（WKB）是 OGC 标准定义的两种几何序列化格式。WKT 是人类可读的文本格式，适合调试和小数据量交换；WKB 是紧凑的二进制格式，适合数据库存储和高性能传输。


const wktPoint = 'POINT(116.397428 39.90923)';
const wktLine = 'LINESTRING(116.39 39.91, 116.40 39.92, 116.41 39.91)';
const wktPolygon = 'POLYGON((116.39 39.90, 116.41 39.90, 116.41 39.92, 116.39 39.92, 116.39 39.90))';
const wktMulti = 'MULTIPOINT((116.39 39.91), (116.40 39.92))';
GeoJSON 是 Web 环境下最流行的矢量数据交换格式。它基于 JSON，天然与 JavaScript 生态兼容，支持 Point、LineString、Polygon 及其 Multi 变体和 FeatureCollection 集合。GeoJSON 规范强制使用 WGS84 坐标系（经纬度），这简化了跨系统的数据交换，但也意味着不能在 GeoJSON 中存储投影坐标。


Shapefile 是 ESRI 在 1990 年代推出的矢量数据格式，至今仍是行业中最广泛交换的格式之一。它实际上由多个文件组成（.shp 几何、.dbf 属性、.shx 索引、.prj 坐标系），这种多文件设计在现代看来笨重且容易丢失组件，但其庞大的历史存量使它短期内不会被完全替代。


栅格数据模型与影像格式
栅格数据将空间划分为规则的网格，每个网格单元（像元/Pixel）存储一个或多个数值。像元大小（空间分辨率）决定了栅格能表达的空间细节程度——30米分辨率的 Landsat 影像每个像元覆盖 30×30 米，0.5 米分辨率的商业卫星影像能分辨出单独的车辆。


数字高程模型（DEM, Digital Elevation Model）是最基础的栅格数据类型。它为每个像元存储一个高程值，可用于生成等高线、坡度图、汇水分析和视域分析。全球公开的 DEM 数据集包括 SRTM（30米/90米）、ASTER GDEM（30米）和 Copernicus DEM（30米）。

Cloud Optimized GeoTIFF（COG）是栅格数据在云时代的重要演进。传统 GeoTIFF 需要完整下载后才能读取任何部分，COG 通过内部分块和金字塔结构允许客户端只请求需要的区域和分辨率级别。这对于处理 TB 级卫星影像档案来说是革命性的——分析师可以在不下载整个文件的情况下查询和分析特定区域。


多波段栅格是遥感数据的核心形式。Landsat 8 提供 11 个波段（从可见光到热红外），Sentinel-2 提供 13 个波段。不同波段捕获不同波长的电磁辐射，通过波段组合和计算可以提取植被指数（NDVI）、水体指数（NDWI）、建筑指数（NDBI）等有意义的信息。


空间索引与性能优化
空间数据的查询性能高度依赖空间索引。没有索引的空间查询需要对每个几何对象进行逐一比较（O(n) 复杂度），而有索引的查询可以在 O(log n) 时间内完成。


R-tree 是最广泛使用的空间索引结构。它将几何对象的最小包围矩形（MBR, Minimum Bounding Rectangle）组织为树形结构，使得空间查询可以快速排除不相关的对象。PostGIS 的 GiST 索引、SpatiaLite 的 R*-tree、以及 Python 的 rtree 库都基于 R-tree 变体实现。


Geohash 是一种将二维坐标编码为一维字符串的空间索引方案。它将地球表面递归划分为网格，每个网格用一个 Base32 字符表示，字符越多精度越高。Geohash 的核心优势是支持前缀匹配——相同前缀的 Geohash 在空间上一定相邻，这使得空间邻近查询可以转化为字符串前缀查询，非常适合 Redis、Elasticsearch 等键值存储。


H3 是 Uber 开发的六边形分层空间索引系统。相比 Geohash 的矩形网格，六边形具有等距邻居的优势——每个六边形与其所有邻居的中心距离相等，这消除了矩形网格中对角线距离大于边距离的问题，特别适合出行距离和服务范围分析。


矢量瓦片（Vector Tiles / MVT）是空间数据在 Web 可视化中的性能优化方案。它将矢量数据按缩放级别预切分为瓦片，每个瓦片只包含该级别需要展示的简化几何和属性。Mapbox 和 MapLibre 的生态系统都基于 MVT 标准。


小结
    

  • 空间数据分为矢量（点线面，表达离散实体）和栅格（网格像元，表达连续场）两大类
    • 

  • OGC Simple Features 是矢量几何的行业标准，定义了 Point/LineString/Polygon 等类型
    • 

  • GeoJSON 是 Web 环境首选的矢量交换格式，强制使用 WGS84 坐标系
    • 

  • Shapefile 历史悠久但多文件设计笨重，正在被 GeoPackage 和 GeoParquet 替代
    • 

  • GeoTIFF 是栅格标准格式，COG 是其云优化版本支持按需读取
    • 

  • 多波段栅格是遥感分析基础，通过波段组合可提取植被、水体等指数
    • 

  • R-tree、Geohash、H3 是三种主流空间索引方案，适用场景各不相同
    • 

  • 矢量瓦片（MVT）是大规模空间数据 Web 可视化的性能关键
    •
