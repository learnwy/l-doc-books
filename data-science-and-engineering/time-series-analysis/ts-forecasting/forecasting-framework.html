预测框架体系

核心概念

时间序列预测框架体系是将预测从"选一个模型跑一下"提升为系统化工程实践的方法论。一个完整的预测框架涵盖数据准备、特征工程、模型选择、超参数调优、集成策略、评估验证和部署监控的全生命周期。在工业级预测场景中，框架化的方法往往比选择某个"最优"模型更重要。

预测框架按照自动化程度可分为三层：手工建模层（分析师手动选择模型和参数）、自动化框架层（AutoML 风格的模型选择和调优）和统一预测平台层（支持多模型、多序列、多任务的企业级系统）。

Prophet 与可分解预测
Facebook Prophet 是当前最广泛使用的商业预测框架之一。它将时间序列分解为三个可加性组件——趋势（trend）、季节性（seasonality）和假日效应（holidays）——并用贝叶斯方法拟合各组件的参数。


Prophet 的核心设计理念是"分析师友好"：它将预测建模中最需要领域知识的部分（趋势变化点、季节性周期、假日效应）暴露为易理解的参数，而将统计推断的复杂性封装在内部。


interface ProphetConfig {
  growthMode: 'linear' | 'logistic';
  changepoints: Date[];
  seasonalities: Array<{
    name: string;
    period: number;
    fourierOrder: number;
  }>;
  holidays: Array<{
    name: string;
    dates: Date[];
    lowerWindow: number;
    upperWindow: number;
  }>;
}

interface ProphetComponents {
  trend: number[];
  seasonal: Record<string, number[]>;
  holiday: number[];
  residual: number[];
}

function decompose(values: number[], config: ProphetConfig): ProphetComponents {
  const n = values.length;
  const trend = estimateTrend(values, config.growthMode, config.changepoints);
  const detrended = values.map((v, i) => v - trend[i]);

  const seasonal: Record<string, number[]> = {};
  let seasonalSum = new Array(n).fill(0);
  for (const s of config.seasonalities) {
    const component = fitFourier(detrended, s.period, s.fourierOrder);
    seasonal[s.name] = component;
    seasonalSum = seasonalSum.map((v, i) => v + component[i]);
  }

  const holiday = fitHolidayEffect(
    detrended.map((v, i) => v - seasonalSum[i]),
    config.holidays,
  );

  const residual = values.map((v, i) => v - trend[i] - seasonalSum[i] - holiday[i]);

  return { trend, seasonal, holiday, residual };
}

function estimateTrend(values: number[], mode: string, changepoints: Date[]): number[] {
  return values.map((_, i) => values[0] + ((values[values.length - 1] - values[0]) * i) / values.length);
}

function fitFourier(values: number[], period: number, order: number): number[] {
  return values.map((_, i) => {
    let sum = 0;
    for (let k = 1; k <= order; k++) {
      sum += Math.sin((2 * Math.PI * k * i) / period) + Math.cos((2 * Math.PI * k * i) / period);
    }
    return sum * 0.01;
  });
}

function fitHolidayEffect(values: number[], holidays: ProphetConfig['holidays']): number[] {
  return new Array(values.length).fill(0);
}
NeuralProphet 是 Prophet 的深度学习升级版，它在保持 Prophet 可分解结构的同时，用自回归神经网络替代了简单的线性趋势模型，用傅里叶基函数的可学习组合替代了固定的季节性拟合，显著提升了非线性模式的捕获能力。


自动化预测流水线
自动化预测流水线的目标是将预测建模过程标准化和自动化，减少对专家经验的依赖。一个标准的自动化流水线包含以下步骤：数据验证与清洗、特征自动提取、模型候选池搜索、超参数优化、交叉验证、模型选择和部署。


interface AutoTSPipeline {
  steps: Array<{
    name: string;
    execute: (data: TimeSeriesData) => TimeSeriesData;
  }>;
  modelPool: string[];
  metric: 'mape' | 'rmse' | 'smape' | 'mase';
  cvFolds: number;
}

interface TimeSeriesData {
  timestamps: Date[];
  values: number[];
  features?: Record<string, number[]>;
}

interface ModelResult {
  name: string;
  params: Record<string, unknown>;
  trainMetric: number;
  valMetric: number;
  testMetric: number;
}

function runAutoTSPipeline(data: TimeSeriesData, config: AutoTSPipeline): ModelResult[] {
  let processed = data;
  for (const step of config.steps) {
    processed = step.execute(processed);
  }

  const results: ModelResult[] = [];
  for (const modelName of config.modelPool) {
    const cvScores = timeSeriesCV(processed, modelName, config.cvFolds, config.metric);
    results.push({
      name: modelName,
      params: {},
      trainMetric: cvScores.train,
      valMetric: cvScores.val,
      testMetric: cvScores.test,
    });
  }

  return results.sort((a, b) => a.valMetric - b.valMetric);
}

function timeSeriesCV(
  data: TimeSeriesData,
  model: string,
  folds: number,
  metric: string,
): { train: number; val: number; test: number } {
  const foldSize = Math.floor(data.values.length / (folds + 1));
  const scores: number[] = [];
  for (let i = 0; i < folds; i++) {
    const trainEnd = foldSize * (i + 1);
    const valEnd = trainEnd + foldSize;
    scores.push(Math.random() * 0.1 + 0.05);
  }
  const avg = scores.reduce((a, b) => a + b) / scores.length;
  return { train: avg * 0.8, val: avg, test: avg * 1.1 };
}

预测系统的工程架构
从单次预测到生产级预测系统，需要解决一系列工程挑战：多序列批量预测的调度、预测结果的存储和查询、模型漂移的在线监控、预测回测（backtesting）系统以及预测结果的可视化展示。


批量预测系统的核心设计决策是"每个序列独立模型"还是"全局共享模型"。独立模型（local model）为每个序列训练一个模型，能够捕获序列的个性化特征，但在数据稀少时容易过拟合。全局模型（global model）在所有序列上联合训练，通过共享参数实现跨序列的知识迁移，但可能忽略个体差异。


在实践中，混合策略最为常见：用全局模型提供基线预测，然后对每个序列进行局部微调。这种方法兼顾了泛化能力和个性化需求，特别适合零售、物流等拥有大量相似但各有特点的序列的场景。


小结
    

  • 预测框架体系将时序预测从单一模型提升为覆盖全生命周期的系统化工程实践
    • 

  • Prophet 通过可分解结构（趋势+季节性+假日）降低预测建模的专家门槛
    • 

  • 自动化预测流水线通过标准化步骤和模型池搜索减少人工干预
    • 

  • 生产级预测系统需要解决批量调度、模型监控、漂移检测等工程挑战
    • 

  • 全局模型与局部模型的混合策略兼顾泛化能力和个性化需求
    • 

  • 选择预测框架时应综合考虑序列规模、自动化需求和团队技术能力
