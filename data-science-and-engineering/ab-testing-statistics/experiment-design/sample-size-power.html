样本量与统计功效

核心概念

样本量计算（Sample Size Calculation）和统计功效分析（Power Analysis）是实验设计中最关键的定量环节。样本量决定了实验能够检测到多小的效果以及实验需要运行多长时间。样本量不足会导致实验"功效不足"——即使处理确实有效果，实验也大概率检测不到（高假阴性率）；样本量过多则浪费时间和流量，延迟了决策和价值实现。

样本量与效应量的关系是平方反比——如果希望检测到原来一半大小的效应，需要四倍的样本量。这个关系使得在小效应场景下，样本量需求会急剧增长，这也是为什么互联网公司的实验平台需要海量用户流量的根本原因。


比率指标的样本量计算
比率指标（如转化率、点击率、留存率）是 A/B 测试中最常见的指标类型。其样本量计算基于两个比率的差异检验（Z 检验）。


from scipy.stats import norm
import numpy as np

def sample_size_proportion(p_control, mde_relative, alpha=0.05, power=0.8,
                            two_sided=True, ratio=1):
    p_treatment = p_control * (1 + mde_relative)

    z_alpha = norm.ppf(1 - alpha / (2 if two_sided else 1))
    z_beta = norm.ppf(power)

    p_avg = (p_control + p_treatment) / 2

    n_control = ((z_alpha * np.sqrt(2 * p_avg * (1 - p_avg)) +
                   z_beta * np.sqrt(p_control * (1 - p_control) +
                                     p_treatment * (1 - p_treatment) / ratio)) /
                  (p_treatment - p_control)) ** 2

    n_treatment = n_control / ratio

    return {
        'n_control': int(np.ceil(n_control)),
        'n_treatment': int(np.ceil(n_treatment)),
        'n_total': int(np.ceil(n_control + n_treatment)),
        'p_control': p_control,
        'p_treatment': p_treatment,
        'mde_absolute': p_treatment - p_control,
        'mde_relative': mde_relative
    }

def sample_size_table(p_control, mde_options, power_options=[0.8, 0.9], alpha=0.05):
    results = []
    for mde in mde_options:
        for power in power_options:
            ss = sample_size_proportion(p_control, mde, alpha, power)
            results.append({
                'mde_relative': f"{mde*100:.1f}%",
                'power': f"{power*100:.0f}%",
                'n_per_group': ss['n_control'],
                'n_total': ss['n_total']
            })
    return results
实际项目中经常需要进行灵敏度分析，在不同的 MDE 和功效水平下计算样本量，帮助决策者理解"多大的改进可以被多大的样本量检测到"。

低基线转化率和小 MDE 的组合会导致天文数字级的样本量需求。对于转化率仅 1% 的场景，检测 5% 的相对提升（即从 1.00% 到 1.05%）需要超过 600 万样本。


连续指标的样本量计算
连续指标（如人均消费金额、页面停留时长、搜索结果满意度评分）的样本量计算基于两组均值差异的 t 检验。与比率指标不同，连续指标的方差需要从历史数据中估计。


def sample_size_continuous(mean_control, mde_relative, std,
                            alpha=0.05, power=0.8, ratio=1):
    delta = mean_control * mde_relative

    z_alpha = norm.ppf(1 - alpha / 2)
    z_beta = norm.ppf(power)

    n_control = ((z_alpha + z_beta) * std / delta) ** 2 * (1 + 1/ratio)
    n_treatment = n_control / ratio

    return {
        'n_control': int(np.ceil(n_control)),
        'n_treatment': int(np.ceil(n_treatment)),
        'n_total': int(np.ceil(n_control + n_treatment)),
        'effect_size_cohen_d': delta / std,
        'mde_absolute': delta
    }

def sample_size_with_variance_reduction(mean_control, mde_relative, std,
                                          cuped_r_squared=0.3,
                                          alpha=0.05, power=0.8):
    adjusted_std = std * np.sqrt(1 - cuped_r_squared)

    original = sample_size_continuous(mean_control, mde_relative, std, alpha, power)
    reduced = sample_size_continuous(mean_control, mde_relative, adjusted_std, alpha, power)

    return {
        'original_n': original['n_total'],
        'reduced_n': reduced['n_total'],
        'reduction_ratio': 1 - reduced['n_total'] / original['n_total'],
        'cuped_r_squared': cuped_r_squared,
        'original_std': std,
        'adjusted_std': adjusted_std
    }
连续指标往往具有高方差和偏态分布特征。人均消费金额的分布通常是右偏的（少数高消费用户拉高方差），这导致样本量需求大幅增加。方差缩减技术（如 CUPED）通过利用实验前的协变量信息降低指标方差，从而在不增加样本量的情况下提升统计功效。


CUPED（Controlled-experiment Using Pre-Experiment Data）是微软提出的方差缩减方法，它利用用户在实验前的历史行为数据作为协变量，通过线性回归去除指标中可被实验前数据解释的方差部分。如果实验前数据能解释 30% 的方差（R² = 0.3），则等效样本量提升约 43%。


多重比较校正
当一个实验检验多个指标或多个变体时，每个检验都有 α 的假阳性概率。随着检验次数增加，至少一个假阳性的概率急剧上升——检验 20 个指标时，即使所有处理都无效，也有 64% 的概率至少看到一个"显著"结果。


def bonferroni_correction(p_values, alpha=0.05):
    m = len(p_values)
    adjusted_alpha = alpha / m

    results = []
    for i, p in enumerate(p_values):
        results.append({
            'original_p': p,
            'adjusted_threshold': adjusted_alpha,
            'significant': p < adjusted_alpha
        })
    return results

def benjamini_hochberg(p_values, alpha=0.05):
    m = len(p_values)
    sorted_indices = np.argsort(p_values)
    sorted_pvalues = np.array(p_values)[sorted_indices]

    adjusted = np.zeros(m)
    for i in range(m):
        adjusted[i] = sorted_pvalues[i] * m / (i + 1)

    for i in range(m - 2, -1, -1):
        adjusted[i] = min(adjusted[i], adjusted[i + 1])

    adjusted = np.minimum(adjusted, 1.0)

    results = np.zeros(m)
    results[sorted_indices] = adjusted

    return [{'original_p': p, 'adjusted_p': adj, 'significant': adj < alpha}
            for p, adj in zip(p_values, results)]
Bonferroni 校正是最保守的方法，将显著性阈值除以检验次数。它严格控制了族错误率（Family-Wise Error Rate），但代价是大幅降低统计功效。Benjamini-Hochberg 程序控制的是错误发现率（False Discovery Rate），在允许一定比例假阳性的前提下保持更高的统计功效，更适合探索性分析场景。

实验时长与周期效应
实验时长的确定不能仅基于样本量除以日流量，还必须考虑业务周期效应。用户行为在工作日和周末、月初和月末、节假日前后存在显著差异。如果实验只覆盖工作日不覆盖周末，结论可能对周末用户不适用。


def calculate_experiment_duration(n_total, daily_traffic,
                                    traffic_fraction=1.0,
                                    min_weeks=2, max_weeks=8):
    daily_eligible = daily_traffic * traffic_fraction

    min_days = int(np.ceil(n_total / daily_eligible))

    min_days_with_weeks = max(min_days, min_weeks * 7)

    recommended_days = int(np.ceil(min_days_with_weeks / 7) * 7)

    recommended_days = min(recommended_days, max_weeks * 7)

    return {
        'minimum_days': min_days,
        'recommended_days': recommended_days,
        'recommended_weeks': recommended_days // 7,
        'daily_eligible_users': daily_eligible,
        'total_users_collected': daily_eligible * recommended_days,
        'overcollection_ratio': daily_eligible * recommended_days / n_total
    }
经验法则是实验至少运行两个完整的业务周期。对于大多数互联网产品，一个完整周期是一周（包含工作日和周末），因此最低运行时长为两周。对于月度付费产品或具有月度周期的场景，最低时长可能需要两个月。新奇效应（Novelty Effect）和学习效应（Primacy Effect）也要求实验运行足够长时间以消除这些初始偏差。


小结
    

  • 样本量与效应量呈平方反比关系，检测小效应需要指数级增长的样本量
    • 

  • 比率指标的样本量取决于基线转化率和 MDE，低转化率场景需要大量样本
    • 

  • 连续指标的方差估计来自历史数据，CUPED 等方差缩减技术可等效增加 30-50% 的样本量
    • 

  • 多重比较校正是多指标/多变体实验的必备步骤，BH 程序在功效和错误控制之间取得平衡
    • 

  • 实验时长必须覆盖完整的业务周期，最低两周是大多数互联网产品的经验底线
    • 

  • 功效分析应在实验设计阶段完成，实验结束后的"事后功效分析"在统计上没有意义
    • 

  • 灵敏度表格帮助决策者直观理解"样本量-效应量-功效"之间的三角权衡关系
    •
