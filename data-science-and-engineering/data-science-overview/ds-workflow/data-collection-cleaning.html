数据采集与清洗

核心概念

数据采集与清洗是数据科学工作流中最基础也最耗时的环节，通常占据整个项目 60%-80% 的时间。"垃圾进，垃圾出"（Garbage In, Garbage Out）是数据科学的铁律——无论模型多么精妙，如果输入数据质量不佳，输出结果必然不可靠。数据采集定义了分析的可能性边界，数据清洗则决定了分析的可信度。

数据采集方法与策略
数据采集不是简单地"拉数据"，而是需要根据分析目标和可用资源，系统性地设计采集策略。


结构化数据采集


关系数据库是企业最核心的数据源。SQL 是数据科学家获取结构化数据的基础工具，但仅会写 SELECT 语句远远不够。理解数据模型（星型模型、雪花模型）、了解索引原理、掌握窗口函数和 CTE 是高效数据采集的前提。在大数据环境下，Hive SQL、Spark SQL 和 Presto 成为主力查询引擎，它们的优化策略（分区裁剪、谓词下推、Broadcast Join）直接影响查询效率。


数据仓库和数据湖是现代企业的数据基础设施。数据仓库（如 Snowflake、BigQuery）以事实表和维度表组织数据，适合分析型查询。数据湖（如 S3 + Delta Lake）以原始格式存储海量数据，提供更大的灵活性。数据科学家需要理解两者的差异和适用场景。


半结构化与非结构化数据采集


API 采集是获取外部数据的主要方式。RESTful API 和 GraphQL 各有特点——REST 简单直接但可能存在 Over-fetching，GraphQL 灵活但学习曲线更陡。采集时需要注意速率限制（Rate Limiting）、分页处理、错误重试和数据一致性。


日志数据是互联网企业最丰富的数据源之一。用户行为日志（点击、浏览、搜索、购买）记录了用户与产品交互的完整轨迹。数据埋点设计直接决定了后续分析的可能性——好的埋点方案应该在系统设计阶段就参与规划，而不是上线后临时补充。


文本、图像和音视频等非结构化数据的采集和预处理有其独特挑战。文本需要处理编码、分词、去停用词；图像需要处理格式转换、尺寸归一化、标注管理；音视频需要处理转码、采样和特征提取。


数据采样策略


当数据规模过大无法全量处理时，采样成为必要手段。简单随机采样保证了无偏性，但可能遗漏稀有类别。分层采样按关键维度（如地区、年龄段）按比例抽取，确保各子群体的代表性。系统采样按固定间隔抽取，简单高效但可能引入周期性偏差。在 A/B 测试中，哈希分桶是最常用的在线随机化方法。

缺失值处理
缺失值是数据清洗中最常见的问题，但处理方式的选择直接影响分析结论的可靠性。


缺失机制分析


在处理缺失值之前，首先要理解缺失的机制。统计学家 Rubin 将缺失机制分为三类：


完全随机缺失（MCAR）：缺失与任何变量都无关，相当于随机丢弃数据。这种情况下，简单删除缺失行不会引入偏差，但会损失统计效率。


随机缺失（MAR）：缺失与其他已观测变量有关，但与缺失变量本身无关。例如，男性更倾向于不填写收入信息——收入缺失与性别相关，但与实际收入水平无关。这种情况下，可以基于已观测变量进行条件插补。


非随机缺失（MNAR）：缺失与缺失变量本身有关。例如，高收入人群更不愿意填写收入——这种缺失最难处理，任何基于已观测数据的插补方法都可能引入偏差。


处理策略


删除法是最简单的策略：按行删除（Listwise Deletion）会损失大量数据，按列删除适用于缺失比例极高的变量。均值/中位数/众数插补快速但会低估方差。回归插补利用其他变量预测缺失值，但可能过度拟合。多重插补（Multiple Imputation）是统计学推荐的方法——生成多组插补值，在每组上分别分析，最后合并结果，能够正确反映插补带来的不确定性。


在机器学习场景中，一些算法（如 XGBoost、LightGBM）天然支持缺失值处理，会在训练过程中学习最优的缺失值分裂方向。创建"是否缺失"的二值特征也是一种有效策略，因为缺失本身可能包含有价值的信息。


异常值检测与处理
异常值既可能是数据质量问题的表现，也可能蕴含着重要的业务洞察。区分两者是异常值处理的关键决策。


统计方法


Z-score 方法假设数据近似正态分布，将超过 ±3 标准差的观测标记为异常。对于偏态分布，修正 Z-score（基于中位数和 MAD）更为鲁棒。IQR 方法不依赖分布假设，将低于 Q1-1.5×IQR 或高于 Q3+1.5×IQR 的观测视为异常，是箱线图的理论基础。


Grubbs 检验和 Dixon 检验是专门用于小样本异常值检测的统计方法。对于时序数据，移动平均和指数平滑可以识别偏离趋势的异常点。


机器学习方法


隔离森林（Isolation Forest）的思想是：异常点更容易被随机划分所隔离，因此需要更少的划分次数。它不需要任何分布假设，对高维数据效果良好。Local Outlier Factor（LOF）通过比较每个点与其邻域的局部密度来识别异常——密度显著低于邻域的点被认为是异常。DBSCAN 聚类的副产品就是将不属于任何簇的点标记为异常。


处理策略


确认为数据质量问题的异常值应该删除或替换。替换方法包括：Winsorization（将极端值截断到特定分位数）、用中位数替换、用回归预测值替换。但如果异常值是真实的极端事件（如电商大促的流量峰值、金融市场的黑天鹅事件），则不应删除，而应建立专门的模型来处理。


在时间序列场景中，区分异常值和结构性变化（Structural Change）尤为重要。单个异常点可能是设备故障，但持续的偏移则可能意味着业务模式发生了根本性变化。


数据整合与一致性
真实项目中的数据通常来自多个系统和源头，数据整合是将这些分散的数据融合为统一分析视图的过程。


实体解析与记录链接


实体解析（Entity Resolution）是确定不同数据源中哪些记录指向同一实体的过程。最简单的情况是精确匹配（如通过用户 ID 关联），但现实中经常需要模糊匹配——同一个人在不同系统中的名字、地址、电话可能有不同的书写格式和拼写错误。


模糊匹配的常用方法包括：编辑距离（Levenshtein Distance）度量两个字符串之间的差异，Jaro-Winkler 距离对前缀相似的字符串给予更高权重（适合人名匹配），Soundex 和 Metaphone 算法基于发音进行匹配。在大规模数据中，需要使用 Blocking 策略先将可能匹配的记录分组，再在组内进行精确比对，避免 O(n²) 的全量比较。


数据类型与格式统一


日期时间是最容易出现不一致的数据类型。不同系统可能使用不同的时间格式（ISO 8601、Unix 时间戳、本地格式）、不同的时区、不同的精度（秒级、毫秒级）。统一时区（通常转为 UTC）和格式是数据整合的第一步。


分类变量的编码统一也是常见挑战。同一类别在不同系统中可能有不同的编码（"M"/"Male"/"男"）或不同的粒度（省级/市级/区级）。建立统一的编码映射表（Code Mapping Table）是保证数据一致性的基础设施。


数值精度的不一致同样需要注意。金融数据的金额可能因为浮点数精度问题产生微小差异，货币单位（元/分/美元/美分）的混淆则可能导致数量级错误。


小结
    

  • 数据采集与清洗占据数据科学项目 60%-80% 的时间，是保证分析可靠性的基础
    • 

  • 数据采集需要根据分析目标系统性设计策略，掌握 SQL、API 和日志采集是基本功
    • 

  • 缺失值处理要先分析缺失机制（MCAR/MAR/MNAR），再选择合适的处理方法
    • 

  • 异常值可能是质量问题也可能是业务洞察，区分两者是关键决策
    • 

  • 数据整合涉及实体解析、格式统一和一致性维护，是多源数据分析的必经之路
    • 

  • 数据清洗不是一次性工作，而应该建立可复现的自动化流程并持续监控数据质量
