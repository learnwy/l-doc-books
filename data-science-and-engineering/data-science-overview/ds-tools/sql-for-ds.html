SQL 在数据科学中的应用

核心概念

SQL（Structured Query Language）是数据科学家获取数据的第一入口，也是与数据工程师、分析师和业务方沟通的通用语言。在数据科学工作流中，SQL 承担着数据提取、初步清洗、特征计算和结果验证等多重职责。一个优秀的数据科学家花在 SQL 上的时间可能超过花在 Python 上的时间——因为大部分数据处理可以也应该在数据库层完成，而不是全部拉到本地用 Pandas 处理。

高级查询技术
数据科学家需要的 SQL 技能远超基础的 SELECT...FROM...WHERE。窗口函数、CTE 和子查询组合是处理复杂分析需求的核心工具。


窗口函数


窗口函数是 SQL 中最强大的分析工具，允许在不改变结果集行数的前提下，对相关行的集合（窗口）执行计算。与 GROUP BY 不同，窗口函数保留了原始行的粒度。


排名函数（ROW_NUMBER、RANK、DENSE_RANK）在数据科学中应用广泛：用户行为的首次/末次事件提取、每组 Top-N 选择、分桶排序。ROW_NUMBER 为每行分配唯一序号，RANK 允许并列排名但留有空位，DENSE_RANK 允许并列排名且不留空位。


累积聚合函数（SUM、AVG、COUNT 搭配 OVER 子句）支持计算运行总计、滑动平均和累积计数。这在计算用户累积消费、滑动 7 天平均活跃度、累积转化漏斗时非常有用。ROWS BETWEEN 子句定义了窗口的物理范围，RANGE BETWEEN 定义了逻辑范围。


LAG 和 LEAD 函数访问当前行的前几行或后几行数据，是计算环比增长率、用户行为间隔和前后对比的标准工具。FIRST_VALUE 和 LAST_VALUE 获取窗口内的首尾值，NTILE 将数据等分为 N 组（用于分位数计算）。


公用表表达式（CTE）


CTE（WITH 子句）将复杂查询分解为可命名、可引用的子查询块，大幅提升了 SQL 的可读性和可维护性。递归 CTE 还能处理层次数据（如组织架构树、类目层级）。


在数据科学场景中，CTE 的典型用法是构建多步骤的数据处理管道：第一个 CTE 提取原始数据，第二个 CTE 计算中间指标，第三个 CTE 聚合到目标粒度，最终 SELECT 输出结果。这种写法比嵌套子查询清晰得多，也更容易调试——只需将最终 SELECT 替换为对中间 CTE 的查询即可检查每一步的结果。


高级 JOIN 模式


除了标准的 INNER/LEFT/RIGHT JOIN，数据科学还常用几种特殊的连接模式。Self-Join 将表与自身连接，用于计算用户的首单-次单间隔、相邻事件的时间差。Cross-Join 生成笛卡尔积，用于构建日期-维度的完整组合（确保没有缺失日期的记录）。LATERAL JOIN（或 CROSS APPLY）对每一行执行子查询，用于 Top-K 关联推荐和最近邻匹配。

SQL 特征工程
在数据科学的特征工程阶段，SQL 是将原始数据转化为模型特征的高效工具。


时间窗口特征


用户行为的时间窗口聚合是最常见的特征构建模式。例如，计算用户过去 7 天、30 天、90 天的购买次数、消费金额、活跃天数。这类特征可以用窗口函数搭配 ROWS BETWEEN 或 RANGE BETWEEN 实现，也可以用 Self-Join 配合日期过滤实现。


时间衰减特征更进一步，给近期行为赋予更高的权重。例如，加权活跃度 = Σ(活跃天数 × exp(-λ × 距今天数))。这种计算在 SQL 中可以用数学函数实现，但超过一定复杂度后转到 Python 更合适。


类别编码特征


在 SQL 中可以直接完成常见的类别编码操作。频率编码使用 COUNT()/SUM(COUNT()) OVER() 计算每个类别的出现频率。目标编码（Target Encoding）使用 GROUP BY 计算每个类别下目标变量的均值——但需要注意防止数据泄露（不应使用测试集数据计算编码值）。


CASE WHEN 是 SQL 中的通用条件编码工具，可以实现分桶（将连续变量离散化）、指示变量（将特定条件转化为 0/1 标志）和复杂的业务规则编码。


交叉特征与衍生特征


多表 JOIN 后的聚合操作可以构建丰富的交叉特征。例如，用户表 JOIN 订单表 JOIN 商品表，可以计算"用户在每个品类的消费占比"、"用户平均购买商品的价格段"等交叉特征。这类特征往往比单一维度的聚合特征更有预测价值。


数据科学家应该建立可复用的特征 SQL 模板库。常见的模板包括：RFM 模型特征（Recency、Frequency、Monetary）、漏斗转化率特征、用户生命周期阶段特征、异常行为标记特征。每个模板参数化后可以快速适配不同的业务场景。


大数据 SQL 引擎
当数据规模超过单机处理能力时，分布式 SQL 引擎成为必要的工具。


Hive 与 Spark SQL


Hive 是最早的大数据 SQL 引擎，将 SQL 查询翻译为 MapReduce 作业。虽然 Hive 本身已经逐渐被更快的引擎取代，但 HiveQL 方言和 Hive Metastore（元数据管理）仍然是大数据生态的基础设施。


Spark SQL 是当前最主流的大数据 SQL 引擎，基于 Spark 的内存计算引擎，性能比 Hive 提升数十倍。Spark SQL 的 DataFrame API 提供了 SQL 和编程式操作的无缝切换——数据科学家可以先用 SQL 完成数据提取和聚合，然后切换到 PySpark DataFrame 进行更复杂的处理。


Presto/Trino 与交互式查询


Presto（及其开源分支 Trino）是 Facebook 开发的分布式 SQL 查询引擎，专为交互式分析设计。与 Spark SQL 不同，Presto 不需要预先将数据加载到内存，而是直接查询存储在 HDFS、S3 或各种数据源中的数据。其查询延迟通常在秒到分钟级，非常适合 EDA 和临时分析。


云数据仓库


BigQuery（Google）、Snowflake 和 Redshift（AWS）等云数据仓库将存储和计算分离，提供了按需伸缩的能力。它们的 SQL 方言接近标准 SQL，同时提供了特有的性能优化功能（如 BigQuery 的嵌套/重复字段、Snowflake 的时间旅行）。

SQL 性能优化
SQL 性能优化是数据科学家的必备技能，特别是在处理大规模数据时。


查询执行计划


EXPLAIN（或 EXPLAIN ANALYZE）是理解查询性能的第一工具。执行计划展示了查询优化器选择的执行策略：扫描方式（全表扫描 vs 索引扫描）、连接算法（Nested Loop、Hash Join、Sort-Merge Join）和数据传输模式。


在分布式环境中，数据 Shuffle（跨节点传输）是最大的性能瓶颈。减少 Shuffle 的策略包括：将小表广播（Broadcast）到每个节点、利用分区键避免不必要的重新分区、在 JOIN 前过滤数据减少传输量。


常见优化模式


分区裁剪是大数据查询中最重要的优化。如果表按日期分区，加上 WHERE dt BETWEEN '2024-01-01' AND '2024-01-31' 可以让查询只扫描一个月的数据而非全表。谓词下推将过滤条件尽可能地推到数据源层执行，减少传输和处理的数据量。


JOIN 优化需要注意：将大表放在 JOIN 的左侧（左表驱动），避免 Cartesian Product（确保 JOIN 条件完整），在 JOIN 前尽量过滤减少数据量。在 Spark SQL 中，当一个表足够小（<10MB 默认阈值），优化器会自动选择 Broadcast Hash Join 而非 Shuffle Hash Join。


子查询的物化策略也影响性能。有些引擎会将 CTE 物化为临时表（每个引用只计算一次），有些则会将 CTE 内联展开（可能导致重复计算）。了解所用引擎的 CTE 物化策略对于写出高效查询至关重要。


小结
    

  • SQL 是数据科学家获取和处理数据的第一工具，大量工作可以也应该在 SQL 层完成
    • 

  • 窗口函数、CTE 和高级 JOIN 是处理复杂分析需求的核心技术
    • 

  • SQL 特征工程能够利用分布式计算能力，高效构建时间窗口、类别编码和交叉特征
    • 

  • 不同的 SQL 引擎适用于不同的数据规模和查询场景，选择合适的引擎至关重要
    • 

  • 查询性能优化的核心是理解执行计划、减少数据 Shuffle 和利用分区裁剪
    • 

  • 建立可复用的 SQL 模板库是提升特征工程效率的有效方法
