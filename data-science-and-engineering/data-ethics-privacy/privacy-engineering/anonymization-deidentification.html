数据匿名化与脱敏

核心概念

数据匿名化（Data Anonymization）和数据脱敏（Data Masking/De-identification）是在保留数据分析价值的同时保护个人隐私的核心技术。匿名化的目标是使数据无法关联到具体个人，即使结合外部信息也无法重新识别。脱敏则是更广义的概念，包括降低数据敏感度的各种技术手段。两者的根本区别在于：真正的匿名化是不可逆的——数据一旦匿名化就无法恢复原始个人信息；而脱敏可能是可逆的（如加密、令牌化），持有密钥的授权人员可以恢复原始数据。在实践中，实现真正不可逆的匿名化远比看起来困难——Netflix Prize 数据集、马萨诸塞州医疗数据等多个经典案例表明，看似匿名的数据通过链接攻击可以被重新识别。

k-匿名与扩展模型
k-匿名（k-Anonymity）是最经典的结构化数据匿名化模型，由 Sweeney (2002) 提出。


k-匿名的定义是：对于数据集中的每一条记录，至少存在 k-1 条其他记录与其在准标识符（Quasi-Identifier）上的值完全相同。准标识符是那些虽然不是唯一标识符但可以组合起来识别个人的属性（如年龄+邮编+性别）。实现 k-匿名的技术手段包括泛化（Generalization，如将精确年龄泛化为年龄段）和抑制（Suppression，删除过于独特的记录）。


import pandas as pd
import numpy as np

np.random.seed(42)
n = 1000
data = pd.DataFrame({
    'age': np.random.randint(20, 70, n),
    'zipcode': np.random.choice(['10001', '10002', '10003', '10004', '10005'], n),
    'gender': np.random.choice(['M', 'F'], n),
    'disease': np.random.choice(['Flu', 'Diabetes', 'Heart', 'Cancer', 'None'], n),
})

def generalize_age(age: int, bin_size: int = 10) -> str:
    lower = (age // bin_size) * bin_size
    return f"{lower}-{lower + bin_size - 1}"

def generalize_zipcode(zipcode: str, level: int = 1) -> str:
    return zipcode[:5 - level] + '*' * level

def check_k_anonymity(df: pd.DataFrame, quasi_identifiers: list[str], k: int) -> bool:
    groups = df.groupby(quasi_identifiers).size()
    return int(groups.min()) >= k

data_anon = data.copy()
data_anon['age'] = data_anon['age'].apply(lambda x: generalize_age(x, 10))
data_anon['zipcode'] = data_anon['zipcode'].apply(lambda x: generalize_zipcode(x, 1))

qi = ['age', 'zipcode', 'gender']
for k in [2, 5, 10]:
    satisfied = check_k_anonymity(data_anon, qi, k)
    min_group = data_anon.groupby(qi).size().min()
    print(f"k={k}: satisfied={satisfied}, min_group_size={min_group}")
l-多样性（l-Diversity）解决了 k-匿名的同质性攻击问题。即使满足 k-匿名，如果同一等价类中所有记录的敏感属性值相同（如都是"癌症"），攻击者仍然可以确定该等价类中每个人的敏感信息。l-多样性要求每个等价类中的敏感属性至少有 l 个不同的值。


t-接近度（t-Closeness）进一步要求每个等价类中敏感属性的分布与全局分布的差异不超过阈值 t。


脱敏技术实践
数据脱敏在开发测试、数据共享和分析环境中广泛应用，技术选择取决于数据类型和使用场景。


**令牌化（Tokenization）**将敏感数据替换为不可逆的令牌值，同时维护一个安全的令牌-原值映射表（Token Vault）。令牌化广泛用于支付数据保护——PCI DSS 标准推荐使用令牌化来减少持卡人数据环境（CDE）的范围。令牌化的安全性完全依赖于令牌库的安全性。


**格式保持加密（Format-Preserving Encryption, FPE）**在加密后保持数据的原始格式和长度。例如，将信用卡号加密后仍然是 16 位数字。FPE 的优势是不需要修改下游系统的数据格式校验逻辑。


合成数据生成通过学习原始数据的统计特征来生成全新的虚拟数据集。合成数据不包含任何真实个体的信息，但在统计层面与原始数据高度相似。常用的合成数据生成方法包括 CTGAN（Conditional Tabular GAN）、TVAE 和基于 Copula 的方法。


重识别风险评估
匿名化和脱敏后的数据并非绝对安全，需要通过重识别风险评估来验证保护的有效性。


链接攻击是最常见的重识别攻击方式。攻击者将匿名化数据集与公开可用的外部数据源（如选民登记名册、社交媒体资料）进行关联，利用准标识符的交集实现重识别。Sweeney 在 2000 年的经典研究表明，仅凭邮编、生日和性别三个属性就可以唯一识别美国 87% 的人口。


推断攻击不需要精确识别个体，而是从匿名数据中推断出敏感信息。即使数据集中的记录无法关联到具体个人，如果特定群组的敏感属性高度同质，攻击者仍然可以做出高置信度的推断。

小结
    

  • 匿名化（不可逆）和假名化（可逆）在 GDPR 下有根本性的法律地位差异
    • 

  • k-匿名是最经典的匿名化模型，l-多样性和 t-接近度解决了其同质性和推断攻击问题
    • 

  • 令牌化和格式保持加密在生产系统中广泛使用，安全性依赖于密钥/令牌库的安全
    • 

  • 合成数据是数据共享和外部发布场景的有前景方向，但隐私保证需要差分隐私来量化
    • 

  • 链接攻击和推断攻击表明"简单删除标识符"远远不足以保护隐私
    • 

  • 重识别风险评估应在数据发布前进行，考虑当前和未来可能的外部数据源
    •
