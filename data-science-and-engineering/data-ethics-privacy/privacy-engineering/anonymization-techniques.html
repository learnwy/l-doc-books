数据匿名化技术

核心概念

数据匿名化是通过技术手段消除或降低数据集中个人可识别信息的关联性，使得数据无法直接或间接地识别到特定个人的过程。在数据科学领域，匿名化是平衡数据利用价值与隐私保护的核心技术手段。有效的匿名化使得组织可以在不泄露个人隐私的前提下进行数据分析、模型训练和数据共享。

数据中的标识符按照识别能力分为三类：直接标识符（姓名、身份证号、邮箱等，可直接锁定个人）、准标识符（年龄、邮编、性别等，组合后可推断个人身份）和敏感属性（疾病、收入、信仰等，需要保护的信息本身）。匿名化技术的核心挑战在于处理准标识符——单个准标识符看似无害，但多个准标识符的组合可能唯一地标识一个人。

K-匿名化
K-匿名化是最经典的匿名化模型，由 Latanya Sweeney 于 2002 年提出。其核心思想是：对于数据集中的每条记录，至少存在 k-1 条其他记录在所有准标识符上的值完全相同。换句话说，任何个人在数据集中至少"隐藏"在 k 个人之中。


interface Record {
  id: string;
  quasiIdentifiers: Record<string, string | number>;
  sensitiveAttribute: string;
}

interface GeneralizationHierarchy {
  field: string;
  levels: Array<(value: string | number) => string>;
}

function checkKAnonymity(
  records: Record[],
  quasiFields: string[],
  k: number,
): { isKAnonymous: boolean; violations: string[][] } {
  const groups = new Map<string, Record[]>();

  for (const record of records) {
    const key = quasiFields.map((f) => String(record.quasiIdentifiers[f])).join('|');
    const group = groups.get(key) ?? [];
    group.push(record);
    groups.set(key, group);
  }

  const violations: string[][] = [];
  for (const [key, group] of groups) {
    if (group.length < k) {
      violations.push(key.split('|'));
    }
  }

  return {
    isKAnonymous: violations.length === 0,
    violations,
  };
}

function generalizeField(value: number, fieldType: 'age' | 'zipcode' | 'date'): string {
  switch (fieldType) {
    case 'age':
      const decade = Math.floor(value / 10) * 10;
      return `${decade}-${decade + 9}`;
    case 'zipcode':
      return String(value).slice(0, 3) + '***';
    case 'date':
      return String(value).slice(0, 7);
    default:
      return String(value);
  }
}
K-匿名化通过泛化（将精确值替换为更粗粒度的范围）和抑制（删除无法满足 k 阈值的记录）实现。泛化的层级结构定义了每个准标识符可以逐步抽象的路径，例如年龄从精确值→5 岁区间→10 岁区间→青年/中年/老年。


K-匿名化的核心局限是同质性攻击：如果一个 k-匿名组内所有记录的敏感属性值相同，攻击者即使无法确定具体是哪个人，仍然可以推断出该组所有人的敏感信息。


L-多样性与 T-接近性
L-多样性是对 K-匿名化的增强，它要求每个等价组中敏感属性的值至少有 L 种不同的取值。这样即使攻击者知道某人属于某个等价组，也无法高置信度地推断其敏感属性。


function checkLDiversity(
  records: Record[],
  quasiFields: string[],
  l: number,
): { isLDiverse: boolean; violations: Array<{ group: string; distinctValues: number }> } {
  const groups = new Map<string, Set<string>>();

  for (const record of records) {
    const key = quasiFields.map((f) => String(record.quasiIdentifiers[f])).join('|');
    const sensitiveValues = groups.get(key) ?? new Set<string>();
    sensitiveValues.add(record.sensitiveAttribute);
    groups.set(key, sensitiveValues);
  }

  const violations: Array<{ group: string; distinctValues: number }> = [];
  for (const [key, values] of groups) {
    if (values.size < l) {
      violations.push({ group: key, distinctValues: values.size });
    }
  }

  return {
    isLDiverse: violations.length === 0,
    violations,
  };
}
T-接近性进一步要求每个等价组中敏感属性的分布与整体数据集中敏感属性的分布之间的差异不超过阈值 T（通常用 Earth Mover's Distance 度量）。这防止了即使属性值多样但分布严重偏斜的情况。

数据脱敏工程实践
在工程实践中，数据脱敏需要作为自动化管道的一部分运行，而非手动操作。一个完整的脱敏管道包括：字段分类（识别需要脱敏的字段）、策略配置（为每类字段选择脱敏方法）、脱敏执行和结果验证。


type MaskingStrategy = 'hash' | 'redact' | 'generalize' | 'noise' | 'pseudonymize' | 'tokenize';

interface MaskingRule {
  fieldPattern: RegExp;
  strategy: MaskingStrategy;
  params?: Record<string, unknown>;
}

interface MaskingPipeline {
  rules: MaskingRule[];
  apply: (records: Record<string, unknown>[]) => Record<string, unknown>[];
}

function createMaskingPipeline(rules: MaskingRule[]): MaskingPipeline {
  const applyRule = (value: unknown, strategy: MaskingStrategy, params?: Record<string, unknown>): unknown => {
    const strValue = String(value);
    switch (strategy) {
      case 'hash':
        return hashValue(strValue);
      case 'redact':
        return '***REDACTED***';
      case 'generalize':
        return generalizeValue(strValue, params);
      case 'noise':
        return addNoise(Number(value), params);
      case 'pseudonymize':
        return pseudonymize(strValue);
      case 'tokenize':
        return tokenize(strValue);
      default:
        return value;
    }
  };

  return {
    rules,
    apply: (records) =>
      records.map((record) => {
        const masked: Record<string, unknown> = { ...record };
        for (const [field, value] of Object.entries(record)) {
          for (const rule of rules) {
            if (rule.fieldPattern.test(field)) {
              masked[field] = applyRule(value, rule.strategy, rule.params);
              break;
            }
          }
        }
        return masked;
      }),
  };
}

function hashValue(value: string): string {
  let hash = 0;
  for (let i = 0; i < value.length; i++) {
    hash = ((hash << 5) - hash + value.charCodeAt(i)) | 0;
  }
  return `H${Math.abs(hash).toString(16).padStart(8, '0')}`;
}

function generalizeValue(value: string, params?: Record<string, unknown>): string {
  const precision = (params?.precision as number) ?? 2;
  return value.slice(0, precision) + '*'.repeat(Math.max(0, value.length - precision));
}

function addNoise(value: number, params?: Record<string, unknown>): number {
  const scale = (params?.scale as number) ?? 1;
  const noise = (Math.random() - 0.5) * 2 * scale;
  return Math.round((value + noise) * 100) / 100;
}

function pseudonymize(value: string): string {
  return `PSE_${hashValue(value)}`;
}

function tokenize(value: string): string {
  return `TKN_${hashValue(value).slice(0, 8)}`;
}
脱敏结果的验证至关重要：需要确认脱敏后的数据仍然满足分析需求（数据可用性），同时验证无法通过逆向工程恢复原始信息（安全性）。常用的验证方法包括唯一性检查（确认脱敏后无唯一值残留）、分布对比（确认统计分布保持一致）和重识别风险评估。


小结
    

  • 数据匿名化是平衡数据利用价值与隐私保护的核心技术，处理直接标识符、准标识符和敏感属性
    • 

  • K-匿名化确保每条记录至少与 k-1 条其他记录在准标识符上不可区分
    • 

  • L-多样性和 T-接近性分别解决同质性攻击和偏斜攻击，是 K-匿名的增强模型
    • 

  • 工程实践中脱敏应作为自动化管道运行，包含字段分类、策略配置、执行和验证
    • 

  • 匿名化技术在安全性和数据可用性之间存在固有的权衡，需要根据应用场景选择合适的保护等级
    • 

  • 准标识符的组合重识别风险往往被低估，需要系统性地进行重识别风险评估
    •
