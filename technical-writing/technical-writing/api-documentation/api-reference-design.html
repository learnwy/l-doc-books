API 参考文档设计

REST API 文档结构

一份完整的 REST API 参考文档应当包含以下核心模块，让开发者能够快速定位所需信息：

模块 内容 优先级
概述 API 的用途、基础 URL、协议说明 必选
认证 鉴权方式、Token 获取流程 必选
接口列表 按资源分组的接口索引 必选
接口详情 路径、方法、参数、请求/响应示例 必选
错误码 全局错误码与业务错误码 必选
速率限制 请求频率限制与响应头说明 推荐
变更日志 版本间的差异与迁移指南 推荐
SDK/工具 官方 SDK 与社区工具链接 可选

接口组织方式

按资源 (Resource) 维度组织接口，每个资源下按 CRUD 操作排列：

API 参考/
├── 用户 (Users)
│   ├── POST   /users          创建用户
│   ├── GET    /users          获取用户列表
│   ├── GET    /users/:id      获取用户详情
│   ├── PUT    /users/:id      更新用户
│   └── DELETE /users/:id      删除用户
├── 订单 (Orders)
│   ├── POST   /orders         创建订单
│   └── GET    /orders/:id     获取订单详情
└── 认证 (Auth)
    ├── POST   /auth/login     登录
    └── POST   /auth/refresh   刷新 Token

版本化策略

API 文档必须与 API 版本严格对应，常见的版本化方式：

策略 格式示例 优势 劣势
URL 路径 /v1/users 直观，易于路由 URL 冗余
请求头 Accept: application/vnd.api+json;version=1 URL 简洁 不便调试
查询参数 /users?version=1 灵活 容易遗漏

文档中应明确标注每个接口所属版本，并对已废弃接口使用醒目标记：

paths:
  /v1/users:
    get:
      summary: 获取用户列表
      deprecated: false
  /v1/legacy/users:
    get:
      summary: 获取用户列表（旧版）
      deprecated: true

OpenAPI/Swagger 集成

使用 OpenAPI 3.0 规范作为 API 文档的单一信息源，从规范文件自动生成文档：

openapi: 3.0.3
info:
  title: 订单服务 API
  version: 2.1.0
  description: 提供订单创建、查询、取消等功能
servers:
  - url: https://api.example.com/v2
    description: 生产环境
  - url: https://staging-api.example.com/v2
    description: 预发环境
paths:
  /orders:
    post:
      operationId: createOrder
      summary: 创建订单
      tags:
        - 订单
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/CreateOrderRequest'
      responses:
        '201':
          description: 订单创建成功
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Order'

常用文档生成工具对比：

工具 输入格式 输出形式 特点
Swagger UI OpenAPI 3.x 交互式网页 支持在线调试
Redoc OpenAPI 3.x 静态网页 三栏布局，阅读体验好
Stoplight OpenAPI 3.x 平台托管 支持协作编辑
Slate Markdown 静态网页 代码示例并排展示

认证文档模式

认证部分应作为独立章节，放在接口列表之前。推荐结构：

Bearer Token 认证示例

curl -X GET https://api.example.com/v2/users \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..."

认证文档清单

要素 说明
认证方式 Bearer Token / API Key / OAuth 2.0
获取凭证 描述如何申请和获取认证凭证
Token 有效期 明确过期时间与刷新机制
权限范围 列出可用的 scope 及其含义
错误处理 401/403 的返回格式与排查方式
安全建议 密钥保管、HTTPS 强制、最小权限原则

最佳实践
    

  • 从消费者视角出发：文档的组织方式应对齐开发者的使用场景，而非内部实现
    • 

  • 保持单一信息源：以 OpenAPI 规范文件为核心，所有文档从中生成
    • 

  • 提供可运行示例：每个接口至少包含一个完整的 curl 示例
    • 

  • 标注破坏性变更：版本升级时明确列出不兼容变更及迁移步骤
    • 

  • 维护接口状态：对 stable、beta、deprecated 接口使用统一标签
    • 

  • 自动化校验：在 CI 中校验 OpenAPI 文件的合法性与文档的同步性
