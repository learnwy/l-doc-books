教练 vs 导师

两种角色的根本区别

在职场成长领域，"教练"（Coach）和"导师"（Mentor）这两个词经常被混用，但它们代表着截然不同的角色定位和互动方式。理解这种区别，能帮你在不同情境下选择正确的支持方式——无论你是寻求帮助的人，还是提供帮助的人。

导师（Mentor）：基于自身经验提供建议和方向。核心动作是"告诉"——"根据我的经验，你应该……"

教练（Coach）：通过提问帮助对方自己找到答案。核心动作是"询问"——"你觉得最好的方案是什么？"

一个简单的记忆法：导师说"我走过这条路，跟我来"；教练说"你想去哪里？让我帮你找到路"。


GROW 教练模型
GROW 模型是最广泛使用的教练框架之一，由 John Whitmore 爵士提出。它为教练式对话提供了清晰的结构：


GROW 模型在工程场景中的应用
interface GROWSession {
  goal: {
    question: string;
    answer: string;
  };
  reality: {
    question: string;
    answer: string;
  };
  options: {
    question: string;
    answer: string;
  };
  will: {
    question: string;
    answer: string;
  };
}

const engineeringExample: GROWSession = {
  goal: {
    question: '关于这次系统重构，你希望达到的理想结果是什么？',
    answer: '希望在不影响业务的前提下，将响应时间从 2 秒降到 200 毫秒',
  },
  reality: {
    question: '目前的系统状况如何？你已经尝试过什么？',
    answer: '数据库查询是主要瓶颈，尝试过加索引但效果有限',
  },
  options: {
    question: '除了优化数据库，还有哪些可能的方向？',
    answer: '引入缓存层、读写分离、异步处理、数据预聚合...',
  },
  will: {
    question: '这些方案中，你准备先尝试哪个？什么时候开始？',
    answer: '先做缓存层 POC，下周三前完成并评估效果',
  },
};
GROW 的关键提问技巧
Goal 阶段的有力问题：


    

  • "如果没有任何限制，你最理想的结果是什么？"
    • 

  • "这个目标对你为什么重要？"
    • 

  • "你怎么知道目标达成了？"
    • 



Reality 阶段的有力问题：


    

  • "目前最大的阻碍是什么？"
    • 

  • "你已经尝试过什么方法？效果如何？"
    • 

  • "如果从 1 到 10 打分，你觉得现在在几？"
    • 



Options 阶段的有力问题：


    

  • "还有没有其他可能？"
    • 

  • "如果你的预算/时间翻倍，你会怎么做？"
    • 

  • "你最佩服的那个人会怎么处理？"
    • 



Will 阶段的有力问题：


    

  • "你的下一步具体是什么？"
    • 

  • "可能遇到什么障碍？你打算怎么应对？"
    • 

  • "你需要谁的支持？"
    • 



何时用教练模式，何时用导师模式
选择教练还是导师模式，取决于具体情境：






情境
推荐模式
原因





学员面对全新领域，毫无经验
导师
需要经验输入，自己没有"答案"可以被提取




学员有能力但缺乏信心或方向
教练
答案在内部，需要被激发出来




紧急技术决策
导师
没有时间引导探索，需要直接建议




职业发展规划
教练 + 导师
用教练帮他探索内心想法，用导师提供行业信息




行为习惯改变
教练
改变必须由内而外，外部建议效果有限




特定技术问题
导师
需要特定领域的知识和经验





最优秀的导师能在两种模式之间灵活切换——大部分时间用教练模式引导思考，在必要时切换到导师模式提供关键信息。


从"告诉者"到"提问者"的转变
很多资深工程师在指导他人时的默认模式是"告诉"——这可以理解，因为他们确实知道答案。但过度的"告诉"会产生两个问题：学员不思考，以及学员的方案永远受限于导师的认知边界。


转变的核心是学会**"忍住不说"**：


const mentoringToCoaching = {
  before: '你应该用 Redis 做缓存',
  after: '你考虑过哪些缓存方案？它们各有什么优缺点？',

  before2: '这个架构有问题，应该这样改...',
  after2: '如果这个系统需要支持 10 倍流量，你觉得哪里会先出问题？',

  before3: '用 TypeScript 比 JavaScript 好',
  after3: '在你的场景下，类型系统会带来什么价值？有什么代价？',
};
教练式领导力在团队中的应用
教练模式不仅适用于一对一场景，还可以融入日常的团队管理：


站会中的教练：不只是问"你今天做什么"，而是"你觉得完成这个任务最大的风险是什么？"


Code Review 中的教练：不直接指出问题和解法，而是提问"你觉得这段代码在高并发下会有什么表现？"


设计评审中的教练：不直接说"应该用方案 A"，而是"方案 A 和方案 B 在可维护性上有什么差异？"


构建团队的教练式提问库
在团队中推广教练模式时，一个实用的工具是"教练式提问库"——一组经过验证的有力问题，可以在不同场景中直接使用：


interface CoachingQuestionBank {
  category: string;
  situations: {
    when: string;
    questions: string[];
  }[];
}

const questionBank: CoachingQuestionBank[] = [
  {
    category: '方案决策',
    situations: [
      {
        when: '学员在两个方案之间犹豫',
        questions: [
          '这两个方案在半年后分别会变成什么样？',
          '如果你是用户，你更希望团队选择哪个？',
          '你觉得哪个方案更容易回滚？',
        ],
      },
    ],
  },
  {
    category: '问题排查',
    situations: [
      {
        when: '学员遇到难以定位的 bug',
        questions: [
          '如果这个 bug 是你写的，你最可能在哪里犯错？',
          '你能把问题的范围缩小到哪个模块？',
          '最近一次正常工作是什么时候？之后改了什么？',
        ],
      },
    ],
  },
  {
    category: '职业发展',
    situations: [
      {
        when: '学员对职业方向困惑',
        questions: [
          '回想过去一年，什么工作最让你兴奋？',
          '三年后理想的一天是什么样的？',
          '如果不考虑薪资，你最想做什么？',
        ],
      },
    ],
  },
];
常见误区




误区
描述
纠正





总是教练

模式切换成熟度
本节小结
教练和导师是两种互补的成长支持模式。导师基于经验"给予"，教练通过提问"激发"。理解两者的区别和适用场景，能让你在帮助他人（和接受帮助）时更加高效。


    

  • 教练的核心是提问而非告诉，帮助对方从内部找到答案
    • 

  • 导师的核心是经验分享，在对方缺乏经验时提供方向指引
    • 

  • GROW 模型（目标-现实-选择-意愿）是最实用的教练式对话框架
    • 

  • 最优秀的指导者能根据情境在教练和导师模式之间灵活切换
    • 



关键行动：


    

  1. 在下次指导他人时，刻意使用 GROW 模型进行一次完整的教练式对话
    2. 

  2. 记录你本周"直接给答案"的次数和"用提问引导"的次数，观察比例
    3. 

  3. 准备一个"有力问题清单"，在指导他人时随时参考
    4. 

  4. 在团队中推广教练式提问文化，从 Code Review 开始实践
    5.
