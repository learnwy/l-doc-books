文档规范

文档的定位与哲学

代码是写给机器和人的，但文档纯粹是写给人的。文档的存在价值在于弥合代码做了什么和为什么这样做之间的鸿沟。优秀的文档体系遵循一个原则：代码说明 How，文档说明 Why 和 When。

文档不是越多越好。过度文档化的代码库和零文档的代码库一样糟糕——前者让人淹没在过时信息中，后者让人在黑暗中摸索。目标是恰到好处的文档：覆盖最关键的决策和入口，让其他内容通过清晰的代码自解释。

内联注释的最佳实践
什么时候写注释
注释应该解释为什么，而不是做什么。如果你发现自己在写"做什么"的注释，说明代码本身不够清晰，应该先改进代码。


const RETRY_DELAY_MS = 1000;
const MAX_RETRIES = 3;
const BACKOFF_MULTIPLIER = 2;

async function fetchWithRetry(url: string): Promise<Response> {
  let delay = RETRY_DELAY_MS;

  for (let attempt = 0; attempt <= MAX_RETRIES; attempt++) {
    try {
      return await fetch(url);
    } catch (error) {
      if (attempt === MAX_RETRIES) throw error;
      await sleep(delay);
      delay *= BACKOFF_MULTIPLIER;
    }
  }

  throw new Error('unreachable');
}
上面的代码几乎不需要注释，因为常量命名和函数结构已经足够清晰。但下面的场景需要注释：


async function processPayment(payment: Payment): Promise<PaymentResult> {

    maxRetries: 5,

TSDoc / JSDoc 规范
TSDoc 是 TypeScript 项目的 API 文档标准。它的核心价值在于让文档与代码共存，编辑器和文档生成工具都能利用这些信息。


/**
 * 根据用户的会员等级和订单金额计算折扣率。
 *
 * @remarks
 * 折扣规则遵循 2024 年 Q2 定价策略文档。白金会员的折扣率
 * 上限为 25%，超出部分以积分形式返还。
 *
 * @param tier - 用户会员等级
 * @param orderTotal - 订单总金额（单位：分）
 * @returns 折扣率，范围 [0, 0.25]
 *
 * @throws {@link InvalidTierError}
 * 当传入未知的会员等级时抛出
 *
 * @example
 * ```typescript
 * const rate = calculateDiscountRate('gold', 50000);
 * // rate === 0.15
 * ```
 */
function calculateDiscountRate(tier: MemberTier, orderTotal: number): number {
  const baseRates: Record<MemberTier, number> = {
    bronze: 0.05,
    silver: 0.1,
    gold: 0.15,
    platinum: 0.2,
  };

  const rate = baseRates[tier];
  if (rate === undefined) throw new InvalidTierError(tier);

  const bonusRate = orderTotal > 100000 ? 0.05 : 0;
  return Math.min(rate + bonusRate, 0.25);
}

架构决策记录 (ADR)
ADR 是记录重要技术决策的轻量级文档。它回答的核心问题是："一年后，当有人问'为什么用 PostgreSQL 而不是 MongoDB'时，我们能给出清晰的答案吗？"


ADR 模板
# ADR-042: 采用事件溯源模式处理订单状态

## 状态

已接受 (2024-03-15)

## 背景

当前订单状态通过直接更新数据库字段来变更。随着业务复杂度增长，出现了以下问题：

1. 无法追溯订单状态变更的完整历史
2. 多个服务同时修改订单状态导致竞态条件
3. 审计合规要求完整的操作记录

## 决策

采用事件溯源 (Event Sourcing) 模式管理订单状态。

## 后果

### 正面影响

- 完整的状态变更审计轨迹
- 消除竞态条件（事件按序追加）
- 支持时间旅行调试

### 负面影响

- 查询复杂度增加，需要维护物化视图
- 团队需要学习事件溯源模式
- 存储成本增加约 30%

import { execSync } from 'node:child_process';

interface ConventionalCommit {
  type: string;
  scope: string | null;
  description: string;
  breaking: boolean;
}

function parseCommitMessage(message: string): ConventionalCommit | null {
  const match = message.match(/^(\w+)(?:\(([^)]+)\))?(!)?:\s*(.+)/);
  if (!match) return null;
  return {
    type: match[1],
    scope: match[2] ?? null,
    description: match[4],
    breaking: match[3] === '!' || message.includes('BREAKING CHANGE'),
  };
}

文档不是项目完成后的附属品，而是工程过程的有机组成部分。最好的文档实践是将文档写作嵌入到日常工作流中——API 变更时更新 TSDoc，架构决策时写 ADR，发版时生成 CHANGELOG。当文档成为工程习惯而非额外任务时，它才能真正发挥知识传承的价值。
