重构策略

安全重构的原则

重构是在不改变外部行为的前提下改善代码内部结构的过程。重构最大的风险不是改不好，而是改出新 Bug。因此安全重构的第一原则是：在有测试保护的前提下进行小步修改。



绞杀者模式（Strangler Fig Pattern）
绞杀者模式是最安全的大规模重构策略——不是一次性替换旧系统，而是逐步在旧系统周围构建新系统，直到旧系统被完全替代。


实现方式
interface FeatureRouter {
  route(request: Request): Promise<Response>;
}

class StranglerRouter implements FeatureRouter {
  constructor(
    private readonly newService: FeatureRouter,
    private readonly legacyService: FeatureRouter,
    private readonly featureFlags: FeatureFlagService,
  ) {}

  async route(request: Request): Promise<Response> {
    const path = new URL(request.url).pathname;

    if (await this.featureFlags.isEnabled(`new-${path}`)) {
      return this.newService.route(request);
    }

    return this.legacyService.route(request);
  }
}

分支抽象（Branch by Abstraction）
分支抽象是 Martin Fowler 提出的在主干开发模式下进行大规模重构的方法——不使用长期分支，而是通过引入抽象层来隔离新旧实现。


interface NotificationSender {
  send(userId: string, message: string): Promise<void>;
}

class LegacyEmailSender implements NotificationSender {
  async send(userId: string, message: string): Promise<void> {
    await this.smtp.sendMail({ to: userId, body: message });
  }
}

class ModernNotificationService implements NotificationSender {
  async send(userId: string, message: string): Promise<void> {
    const preference = await this.getPreference(userId);
    switch (preference.channel) {
      case 'email':
        return this.emailProvider.send(userId, message);
      case 'push':
        return this.pushProvider.send(userId, message);
      case 'sms':
        return this.smsProvider.send(userId, message);
    }
  }
}


Mikado 方法
Mikado 方法用于处理复杂的、互相依赖的重构任务。它的核心思想是通过试错构建一张依赖图，然后从叶子节点开始逐步完成。

关键原则：每次只提交编译通过、测试通过的代码。不完整的重构不要提交到主干。




并行实现（Parallel Change）
并行实现适用于需要修改接口但不能中断使用者的场景。


interface UserService {
  /** @deprecated 使用 getUserById 替代 */
  getUser(id: number): Promise<User>;

  getUserById(id: string): Promise<User>;
}

class UserServiceImpl implements UserService {
  async getUser(id: number): Promise<User> {
    return this.getUserById(String(id));
  }

  async getUserById(id: string): Promise<User> {
    return this.repository.findById(id);
  }
}

Feature Flag 保护
const featureFlags = {
  async isNewOrderFlowEnabled(): Promise<boolean> {
    return flagService.evaluate('new-order-flow', {
      rolloutPercentage: 10,
      allowedUsers: ['internal-testing'],
    });
  },
};

async function processOrder(order: Order): Promise<OrderResult> {
  if (await featureFlags.isNewOrderFlowEnabled()) {
    return newOrderFlow(order);
  }
  return legacyOrderFlow(order);
}

安全重构的核心不是某个具体技术，而是一种纪律——始终保持代码在可部署状态，始终有测试保护，始终小步前进。当你掌握了这套方法论，重构就从"风险行为"变成了"日常实践"，技术债务的偿还也从"集中还款"变成了"持续分期"。
