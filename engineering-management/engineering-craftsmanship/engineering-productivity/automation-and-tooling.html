自动化与工具链

自动化的哲学

如果一个任务需要手动执行两次以上，就应该考虑自动化。这不是偷懒，而是工程纪律——手动操作不仅耗时，更容易出错。自动化的投资回报率几乎总是正的，因为一次自动化投入可以在未来无数次执行中节省时间和防止人为错误。

GitHub Actions 优化示例
name: CI
on: [pull_request]

jobs:
  quality:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile

      - name: Parallel Checks
        run: |
          pnpm run lint &
          pnpm run typecheck &
          pnpm run test -- --reporter=dot &
          wait

  build:
    needs: quality
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - run: pnpm build


代码生成
脚手架工具
重复性的代码结构应该通过生成器来创建，而不是手动复制粘贴：


import { writeFile, mkdir } from 'node:fs/promises';
import { join } from 'node:path';

interface ComponentConfig {
  name: string;
  directory: string;
  withTests: boolean;
  withStory: boolean;
}

async function generateComponent(config: ComponentConfig): Promise<void> {
  const dir = join(config.directory, config.name);
  await mkdir(dir, { recursive: true });

  const componentContent = `
import type { FC } from 'react';

interface ${config.name}Props {
  className?: string;
}

export const ${config.name}: FC<${config.name}Props> = ({ className }) => {
  return <div className={className}></div>;
};
`.trimStart();

  await writeFile(join(dir, `${config.name}.tsx`), componentContent);
  await writeFile(join(dir, 'index.ts'), `export { ${config.name} } from './${config.name}';\n`);

  if (config.withTests) {
    const testContent = `
import { render, screen } from '@testing-library/react';
import { describe, it, expect } from 'vitest';
import { ${config.name} } from './${config.name}';

describe('${config.name}', () => {
  it('renders without crashing', () => {
    render(<${config.name} />);
  });
});
`.trimStart();
    await writeFile(join(dir, `${config.name}.test.tsx`), testContent);
  }
}

脚本化重复任务
常用开发脚本
import { execSync } from 'node:child_process';

function runOrFail(command: string, label: string): void {
  console.log(`\n▶ ${label}...`);
  try {
    execSync(command, { stdio: 'inherit' });
    console.log(`✓ ${label} 完成`);
  } catch {
    console.error(`✗ ${label} 失败`);
    process.exit(1);
  }
}

runOrFail('pnpm run lint --fix', '修复 Lint 问题');
runOrFail('pnpm run typecheck', '类型检查');
runOrFail('pnpm run test --run', '运行测试');
runOrFail('pnpm run build', '构建项目');

console.log('\n✅ 所有检查通过，可以安全提交！');


自定义 CLI 工具
当项目有特定的重复操作时，构建一个项目级 CLI 工具比记忆一堆命令更高效：


import { parseArgs } from 'node:util';

const { values, positionals } = parseArgs({
  allowPositionals: true,
  options: {
    env: { type: 'string', default: 'development' },
    verbose: { type: 'boolean', default: false },
  },
});

const commands: Record<string, () => Promise<void>> = {
  'db:reset': async () => {
    console.log(`重置 ${values.env} 数据库...`);
    await resetDatabase(values.env!);
  },
  'seed:generate': async () => {
    console.log('生成测试数据...');
    await generateSeedData();
  },
  'deploy:preview': async () => {
    console.log('部署预览环境...');
    await deployPreview();
  },
};

const command = positionals[0];
if (!command || !commands[command]) {
  console.log('可用命令:', Object.keys(commands).join(', '));
  process.exit(1);
}

await commands[command]();

自动化不是一次性投资，而是持续的工程文化。每当你发现自己在重复做某件事时，就问自己："这能自动化吗？"答案几乎总是"能"。投入一个下午写一个自动化脚本，可能在未来的一年里为整个团队节省数百小时。这就是工程杠杆效应。
