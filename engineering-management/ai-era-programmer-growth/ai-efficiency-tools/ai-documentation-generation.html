AI 文档生成

文档困境与 AI 解法

软件开发中最普遍的债务之一不是技术债，而是文档债。代码在持续演进，文档却停留在上一个版本。AI 文档生成不是要取代人工编写文档，而是将文档维护从一次性的苦力劳动变为可持续的自动化流程。

JSDoc / TSDoc 自动生成
基本用法
AI 可以为已有函数自动生成规范的 JSDoc 注释：


function calculateDiscount(
  originalPrice: number,
  memberLevel: 'bronze' | 'silver' | 'gold',
  couponCode?: string,
): { finalPrice: number; savedAmount: number } {
  const discountRates = { bronze: 0.05, silver: 0.1, gold: 0.15 };
  const rate = discountRates[memberLevel];
  const discountedPrice = originalPrice * (1 - rate);
  const couponDiscount = couponCode ? 10 : 0;
  const finalPrice = Math.max(0, discountedPrice - couponDiscount);
  return {
    finalPrice: Math.round(finalPrice * 100) / 100,
    savedAmount: Math.round((originalPrice - finalPrice) * 100) / 100,
  };
}
AI 生成的 JSDoc：


/**
 * 根据会员等级和优惠券计算商品折扣价格
 *
 * @param originalPrice - 商品原价（单位：元）
 * @param memberLevel - 会员等级，决定基础折扣率
 * @param couponCode - 可选的优惠券代码，有效时额外减免 10 元
 * @returns 包含最终价格和节省金额的对象，金额保留两位小数
 *
 * @example
 * calculateDiscount(100, 'gold')
 * // => { finalPrice: 85, savedAmount: 15 }
 *
 * calculateDiscount(100, 'gold', 'SAVE10')
 * // => { finalPrice: 75, savedAmount: 25 }
 */

提示词模板
为以下 TypeScript 函数生成 TSDoc 注释：
1. 描述函数的业务目的（不是代码逻辑的直译）
2. 每个参数需要说明含义、约束条件和默认值
3. 返回值需要说明各字段的含义
4. 至少提供一个使用示例
5. 如有异常情况需要用 @throws 标注

提示词：


根据以下项目信息生成中文 README：

package.json: [粘贴]
主入口文件: [粘贴 src/index.ts 的导出内容]
测试示例: [粘贴一个测试文件片段]

要求：
- 标题用英文项目名
- 内容用中文
- 快速开始部分确保复制粘贴就能运行
- 不要虚构功能，只描述代码中实际存在的功能
API 文档自动生成
OpenAPI / Swagger 生成
AI 能从路由定义和处理函数中提取信息生成 OpenAPI 规范：


app.post('/api/users', async (req, res) => {
  const { email, name, role } = req.body;
  const user = await userService.create({ email, name, role });
  res.status(201).json(user);
});

AI 文档生成的质量控制
常见质量问题
AI 生成的文档容易出现以下问题：


    

  • 过度泛化：描述太笼统，没有项目特有的信息
    • 

  • 逻辑直译：将代码逻辑直接翻译为自然语言，缺乏高层语义
    • 

  • 信息虚构：描述代码中不存在的功能或参数
    • 

  • 示例不可用：生成的代码示例无法直接运行
    • 

  • 风格不一致：不同部分的文档风格差异明显
    • 



质量保障流程
自动化检查项目：


    

  • 所有代码示例可以通过语法检查
    • 

  • 所有链接指向有效地址
    • 

  • 函数签名与实际代码一致
    • 

  • 不包含占位符或未完成标记
    • 

  • Markdown 格式正确，无渲染问题
    •

文档自动化工具链
集成到 CI/CD
将文档生成集成到持续集成流程中：


name: docs-check
on: [pull_request]
jobs:
  check-docs:
    steps:
      - name: 检查 API 文档同步
        run: |
          npx typedoc --json /tmp/api.json
          node scripts/check-docs-sync.mjs

      - name: 检查 README 示例可运行
        run: node scripts/validate-readme-examples.mjs

      - name: 检查 Changelog 更新
        run: |
          if git diff --name-only origin/main | grep -q "src/"; then
            git diff --name-only origin/main | grep -q "CHANGELOG.md" || \
              echo "::warning::代码有变更但 Changelog 未更新"
          fi

实践建议
起步阶段： 从单个模块的 JSDoc 自动生成开始，体验 AI 文档的质量和效率。


进阶阶段： 将 AI 文档生成集成到 PR 流程中，每次代码变更自动生成文档更新建议。


成熟阶段： 建立完整的文档自动化流水线，包括生成、校验、发布的全流程。


记住文档的核心价值不是详尽描述每一行代码，而是让新人能快速上手、让维护者能快速理解设计意图。AI 可以帮你完成 80% 的工作量，但那 20% 的业务洞察和设计思考始终需要人来补充。
