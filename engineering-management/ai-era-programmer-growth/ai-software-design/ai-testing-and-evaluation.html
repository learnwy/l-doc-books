AI 测试与评估

AI 系统测试的独特挑战

传统软件测试基于确定性：给定输入 X，期望输出 Y。AI 系统的输出具有概率性——同样的输入可能产生不同的输出，而且"正确"的定义往往是模糊的。

维度 传统软件测试 AI 系统测试
输出确定性 确定的 概率性的
正确性定义 精确匹配 范围匹配/评分
测试数据 手动构造 需要大量真实数据
回归测试 精确对比 统计对比
覆盖率 代码路径覆盖 场景和边界覆盖
测试周期 秒级 分钟到小时级 
Eval 驱动开发
核心理念
Eval 驱动开发（Eval-Driven Development）是 AI 系统的 TDD——先定义评估标准，再优化系统以满足标准。


评估集设计
interface EvalCase {
  id: string;
  input: string;
  expectedOutput?: string;
  acceptanceCriteria: EvalCriteria[];
  category: string;
  difficulty: 'easy' | 'medium' | 'hard';
}

interface EvalCriteria {
  type: 'contains' | 'not_contains' | 'format' | 'semantic_similarity' | 'llm_judge';
  parameter: string;
  threshold?: number;
}

AI 系统回归测试不能使用精确匹配。需要：


interface RegressionResult {
  caseId: string;
  baseline: string;
  current: string;
  semanticSimilarity: number;
  criteriaResults: { criterion: string; passed: boolean }[];
  overallPass: boolean;
}

async function regressionTest(evalSet: EvalCase[]): Promise<RegressionResult[]> {
  const results: RegressionResult[] = [];

  for (const testCase of evalSet) {
    const currentOutput = await runAISystem(testCase.input);

    const similarity = await computeSimilarity(testCase.expectedOutput ?? '', currentOutput);

    const criteriaResults = testCase.acceptanceCriteria.map((criterion) => ({
      criterion: `${criterion.type}: ${criterion.parameter}`,
      passed: evaluateCriterion(criterion, currentOutput),
    }));

    results.push({
      caseId: testCase.id,
      baseline: testCase.expectedOutput ?? '',
      current: currentOutput,
      semanticSimilarity: similarity,
      criteriaResults,
      overallPass: criteriaResults.every((r) => r.passed),
    });
  }

  return results;
}

CI/CD 集成
name: ai-eval
on: [pull_request]
jobs:
  evaluate:
    steps:
      - name: 运行评估集
        run: node scripts/run-eval.mjs
        env:
          EVAL_SET: core

      - name: 对比基准
        run: node scripts/compare-baseline.mjs

      - name: 质量门禁
        run: |
          if [ $(cat eval-results.json | jq '.overallScore') -lt 85 ]; then
            echo "AI 质量评分低于 85，阻止合并"
            exit 1
          fi
实践建议
    

  1. 从评估集开始：任何 AI 功能上线前，至少准备 50 个评估用例
    2. 

  2. 自动化评估：将评估集成到 CI/CD，每次变更自动运行
    3. 

  3. 多维度评估：不只看准确率，还要看延迟、成本、用户满意度
    4. 

  4. 持续扩充：将线上发现的失败案例补充到评估集
    5. 

  5. 版本管理：评估集和基准分数都要版本化管理
    6. 



测试 AI 系统没有银弹。好的评估体系是在不确定性中建立确定性——你不能保证每次输出都完美，但你可以确保整体质量在可控范围内。
