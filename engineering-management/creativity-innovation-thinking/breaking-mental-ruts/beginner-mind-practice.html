Part I · 自我 (Self)创造力与创新思维 简介突破思维定势 简介初心实践

初心实践

Shoshin：禅宗的思维智慧

初心（Shoshin，初心/しょしん）是禅宗中的一个核心概念，由禅师铃木俊隆在《禅者的初心》中向西方世界普及。他说过一句深刻的话："在初学者的心中有很多可能性，而在专家的心中只有少数。"

这句话对经验丰富的程序员来说既是警告也是启示。你的经验是宝贵的资产，但也可能是一种负债——它形成了"知识牢笼"，让你只能看到你已经知道的解决方案。初心实践就是有意识地暂时搁置你的经验和预判，用新鲜的眼光重新审视问题。

初心不是让你假装自己是新手——那是不诚实的。初心是一种元认知态度：保持对经验的觉察，有意识地在使用经验和暂停经验之间切换。


专家的知识诅咒
知识诅咒（Curse of Knowledge）是认知科学中一个重要概念：一旦你知道了某件事，你就很难想象不知道它是什么感觉。这对程序员的影响极为深远：






知识诅咒的表现
对创造力的影响
初心的解药





"这个问题很简单"
跳过了对问题的深入理解
假设你从未见过这个问题




"显然应该用 X 技术"
排除了其他技术方案
假设你不知道 X 技术的存在




"用户应该知道怎么用"
忽视了用户的学习成本
假设你从未见过这个界面




"这段代码的意图很清楚"
忽视了代码可读性问题
假设你是第一次看这段代码




"这个架构是标准做法"
不再质疑架构的合理性
假设你从未听说过这种架构





一个典型案例：一位资深架构师在设计新系统时，几乎自动地选择了微服务架构。当被问"为什么不考虑单体"时，他停顿了——他意识到自己从未认真评估过单体方案。他的经验让"微服务"成了默认选项，跳过了"这个系统真的需要微服务吗"这个最基本的问题。


有意识的去学习
初心实践的核心技能之一是有意识的去学习（Unlearning）——暂时搁置你已知的框架和假设，为新的理解腾出空间。


去学习不是忘记——你不需要也不可能忘记你的专业知识。去学习是松开知识的自动应用机制，让你有意识地选择何时应用经验、何时暂停经验。


去学习的实践方法：


    

  • 假设清零：面对一个问题时，先写下你对它的所有假设，然后逐一标记"这个假设真的成立吗？"
    • 

  • 新手模拟：假装你从未接触过编程，用最朴素的语言描述系统需要做什么——避免使用任何技术术语
    • 

  • 技术清零日：每月花一天时间探索一个你完全不了解的技术领域（如硬件编程、量子计算、生物信息学），感受作为新手的状态
    • 



提问天真问题的力量
初心实践中最实用的技能是提出"天真"的问题。这些看起来简单甚至愚蠢的问题，往往能揭示最深层的假设和最根本的创新机会。


五个经典的天真问题：


    

  1. "为什么要这样做？" ——挑战既有做法的理由
    2. 

  2. "如果不做会怎样？" ——检验需求的真实性
    3. 

  3. "一个孩子会怎么理解这个？" ——检验设计的直觉性
    4. 

  4. "最简单的版本是什么？" ——找到核心本质
    5. 

  5. "如果是第一次遇到这个问题呢？" ——清除路径依赖
    6.

注意"常见的防御反应"——这些反应本身就是知识诅咒的体现。天真问题的价值不在于推翻现有做法，而在于迫使你重新验证那些被视为"理所当然"的假设。


新鲜眼光技术
新鲜眼光（Fresh Eyes）是一种系统化的方法，帮助你在不真正成为新手的情况下获得新手般的观察力。


环境切换法：在完全不同的环境中审视你的工作。如果你通常在办公室写代码，试着在咖啡馆或公园中回顾你的架构设计。物理环境的变化能帮助你的大脑脱离"工作模式"，用更新鲜的眼光看问题。


媒介切换法：如果你通常用 IDE 审查代码，试试把代码打印出来用笔标注。如果你通常画数字架构图，试试用白板画手绘版本。媒介的变化能帮你注意到在熟悉媒介中被忽视的细节。


时间间隔法：写完代码后不要立即 Review——等至少 24 小时后再回来看。这段时间让你的大脑从"创作模式"切换到"评估模式"，你会发现很多当时看不到的问题。


团队中的初心实践
初心不仅是个人练习，也可以成为团队文化的一部分：


新人视角日：定期邀请新加入团队不到 3 个月的成员分享他们的"困惑清单"——那些他们觉得不合理但又不敢说的事情。这些困惑中蕴含着团队最大的改进机会。


天真问题时间：在技术讨论中，专门留出 5 分钟的"天真问题时间"——任何人都可以提出看起来很基础的问题，不允许任何人以"这是常识"来回应。


技术清零实验：每季度花一天时间，让团队用一种全新的技术栈从零构建核心产品的一个功能。不是要替换现有技术栈，而是通过"重新发明"来检验当前方案是否仍然是最优的。


初心与专业的平衡
初心不是要你否定专业知识。最理想的状态是"专家的初心"——拥有深厚的专业知识，同时保持新手般的好奇心和开放性。


实践建议：


    

  • 在问题探索阶段用初心模式：不预设答案，广泛观察
    • 

  • 在方案评估阶段用专家模式：利用经验判断可行性
    • 

  • 在实现阶段两者交替：初心发现新做法，经验保证质量
    • 

  • 在回顾阶段用初心模式：质疑既有做法，寻找改进空间
    •

本节小结
初心（Shoshin）是一种有意识地暂停专家自动反应、用新鲜眼光重新审视问题的思维态度。它不是否定经验，而是在经验的自动应用和有意识的重新观察之间建立灵活的切换。对经验丰富的程序员来说，初心实践的核心技能包括：识别和暂停知识诅咒、有意识的去学习、提出天真但深刻的问题、以及使用新鲜眼光技术。在团队层面，新人视角日和天真问题时间是将初心融入团队文化的实用方法。


关键行动：


    

  1. 对你最熟悉的系统写下 10 个"理所当然"的假设，然后逐一问"这真的必须如此吗？"
    2. 

  2. 在下一次 Code Review 中，假装你是第一次看到这个代码库，记录所有让你困惑的地方
    3. 

  3. 向一个非技术人员解释你正在做的项目，记录你在解释中遇到的困难——这些困难揭示了什么？
    4. 

  4. 在团队中提议一次"天真问题会议"——每人至少提出一个关于现有系统的"为什么"问题
    5. 

  5. 选择一个你从未接触过的技术领域，花 2 小时做入门学习，感受并记录"初学者状态"
    6.
