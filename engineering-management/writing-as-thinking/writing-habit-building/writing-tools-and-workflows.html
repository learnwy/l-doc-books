写作工具与工作流

核心概念：工具为工作流服务

写作工具与工作流（Writing Tools & Workflows）关注的是如何选择和组合数字工具，构建一个从灵感捕获到最终发布的完整写作流水线。对于程序员来说，这和构建 CI/CD 管道的思路一致：每个阶段有合适的工具，阶段之间有顺畅的衔接，整体流程可重复且高效。

工具选择的核心原则是"少即是多"。工具越少，切换成本越低；工作流越简单，坚持的可能性越大。很多人在"挑选完美的写作工具"上花了太多时间，而真正重要的是用任何工具开始写。


程序员在工具选择上有天然的优势：我们熟悉 Markdown、Git、命令行和各种自动化工具。充分利用这些已有技能，可以构建一个高效且可持续的写作工作流。


为什么大多数人的写作工作流是断裂的
观察大多数人的写作过程：灵感出现时在微信里发给自己，素材散落在浏览器书签、笔记 App 和截图中，草稿在 Word 里写，最终手动复制粘贴到博客平台。每个环节之间都有断裂，每次断裂都是写作的一个摩擦点。

写作工具链推荐
灵感捕获工具
灵感转瞬即逝，捕获工具必须做到"3 秒内开始记录"。


interface CaptureToolCriteria {
  launchSpeed: string;
  availability: string;
  syncCapability: string;
  searchable: boolean;
}

const recommendedTools: Record<string, CaptureToolCriteria> = {
  'Apple Notes / 备忘录': {
    launchSpeed: '即时',
    availability: '手机+电脑',
    syncCapability: 'iCloud 自动同步',
    searchable: true,
  },
  'Telegram Saved Messages': {
    launchSpeed: '即时',
    availability: '全平台',
    syncCapability: '实时同步',
    searchable: true,
  },
  'Draft (iOS App)': {
    launchSpeed: '打开即新建',
    availability: '仅 iOS',
    syncCapability: '自动同步',
    searchable: true,
  },
};
长文写作工具
Obsidian 是最适合程序员的写作工具之一：


    

  • 本地存储，数据完全属于你
    • 

  • Markdown 原生支持
    • 

  • 双向链接让笔记之间自然关联
    • 

  • 插件生态丰富
    • 

  • 可以用 Git 做版本管理
    • 



VS Code 作为写作工具的优势：


    

  • 你已经每天在用，零学习成本
    • 

  • Markdown Preview、拼写检查等插件成熟
    • 

  • 集成终端方便 Git 操作
    • 

  • 多光标编辑在文字编辑中同样有用
    • 



版本管理
用 Git 管理写作就像用 Git 管理代码一样自然：


写作的 Git 工作流：

1. 每篇文章一个分支git checkout -b post/writing-tools-workflow

2. 每个写作阶段一个 commit git commit -m "draft: 完成初稿" git commit -m "edit: 结构调整，删除第三节" git commit -m "edit: 句子级编辑和校对" git commit -m "publish: 最终版本"

3. 发布后合并到 main git checkout main && git merge post/writing-tools-workflow
发布工具
从 Markdown 到发布的自动化路径：


    

  • GitHub Pages + Jekyll/Hugo：写 Markdown，push 即发布
    • 

  • Hexo / VitePress：前端工程师友好的静态博客框架
    • 

  • Dev.to / 掘金：直接支持 Markdown 的技术社区
    • 

  • Medium：面向更广泛的读者群体
    • 



实战应用：构建你的写作流水线
端到端写作工作流示例
interface WritingPipeline {
  stage: string;
  tool: string;
  action: string;
  output: string;
}

const myPipeline: WritingPipeline[] = [
  {
    stage: '捕获',
    tool: 'Apple Notes',
    action: '随时记录灵感和想法碎片',
    output: '灵感列表',
  },
  {
    stage: '选题',
    tool: 'Obsidian',
    action: '每周从灵感库中选择一个主题，创建文章文件',
    output: '带标题的空文件',
  },
  {
    stage: '草稿',
    tool: 'Obsidian / VS Code',
    action: '用 25 分钟番茄钟写作，不做编辑',
    output: '粗糙的第一稿',
  },
  {
    stage: '编辑',
    tool: 'VS Code',
    action: '按四层编辑法修改',
    output: '打磨后的终稿',
  },
  {
    stage: '发布',
    tool: 'Git push → GitHub Pages',
    action: '提交并推送，自动构建发布',
    output: '线上文章',
  },
  {
    stage: '反馈',
    tool: '评论区 + Twitter',
    action: '收集读者反馈，记录改进想法',
    output: '下一篇的素材',
  },
];

工具与工作流的成熟度
    

  • L1 无流程：每次写作都从零开始选择工具和流程
    • 

  • L2 基本工具链：固定了写作和发布工具，有基本的流程
    • 

  • L3 流畅管道：从灵感到发布的全流程顺畅无卡点，有模板和版本管理
    • 

  • L4 自动化运转：发布、格式转换、交叉发布等环节高度自动化，将注意力完全释放给内容
    • 



本节小结
写作工具与工作流的目标是消除写作过程中的一切非必要摩擦。选择少而精的工具，建立从灵感到发布的完整管道，然后持续优化这个管道的效率。


核心要点回顾：


    

  • 工具为工作流服务，不是反过来
    • 

  • 程序员应充分利用 Markdown、Git、命令行等已有技能
    • 

  • 端到端工作流比单点工具优化更重要
    • 

  • 模板化和自动化能显著降低写作的启动成本
    • 



关键行动：


    

  1. 选定一个灵感捕获工具和一个长文写作工具
    2. 

  2. 用 Git 管理你的写作文件夹
    3. 

  3. 创建 2-3 个常用的文章模板
    4. 

  4. 搭建一个简单的个人博客（推荐 GitHub Pages + 静态生成器）
    5. 

  5. 画出你当前的写作流程图，标记卡点并逐个优化
    6.
