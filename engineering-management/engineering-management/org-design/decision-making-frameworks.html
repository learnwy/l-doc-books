Part IV · 领导 (Leading)工程管理 简介组织设计 简介决策框架

决策框架

核心概念

工程组织中的决策效率直接影响交付速度和团队士气。一个好的决策框架不是追求完美决策，而是在决策质量和决策速度之间找到最佳平衡。Jeff Bezos 将决策分为两类：不可逆的"单向门"决策需要慎重，可逆的"双向门"决策应该快速。大多数工程决策都是双向门决策，但很多组织却用单向门的流程来处理所有决策。

工程决策的特点

特点 说明
技术不确定性 很多决策在信息不完整时就需要做出
影响范围多样 从几小时的编码决策到影响几年的架构决策
利益相关者多 可能涉及多个团队、产品、技术栈
可逆性不同 命名约定容易改，数据库选型很难改
时效性强 延迟决策本身就是一种成本

决策质量与速度的平衡

达到高质量快速决策的关键：


    

  • 对决策进行分类，不同类型用不同流程
    • 

  • 明确决策权归属，避免不必要的升级
    • 

  • 建立标准化的决策工具和模板
    • 

  • 培养"足够好"的决策文化，而非追求完美
    •

RACI 的使用原则：


    

  • 每个决策事项只能有一个 A（Accountable）
    • 

  • A 角色是决策的最终拍板者，不是做具体工作的人
    • 

  • R 可以有多个，但需要明确分工
    • 

  • C 的意见应该被认真对待，但不具有否决权
    • 

  • I 只需要知道结果，不参与决策过程
    •

RFC 的适用场景：


RFC 运营的最佳实践：


    

  • 评审期通常为 1-2 周，根据决策紧急度调整
    • 

  • 指定 2-3 个核心评审者，其他人可选参与
    • 

  • 所有评论和讨论都书面记录
    • 

  • 超过评审期未达成共识，自动升级到决策会议
    • 

  • RFC 存档在统一的知识库中，便于后续查阅
    •

运作规则：


决策委员会的注意事项：


    

  • 不要变成审批委员会，保持服务意识
    • 

  • 会议频率不宜过高（每 2 周一次为佳）
    • 

  • 决策应该尽量在会前通过异步讨论达成初步共识
    • 

  • 记录所有决策及其理由，形成组织知识库
    • 

  • 定期回顾决策质量，持续优化流程
    • 



决策文化的建设
培养"足够好"的决策文化
关键原则：


    

  • 大多数决策不需要 100% 的信息就可以做出
    • 

  • 快速做出 70 分的决策，好过慢慢做出 90 分的决策
    • 

  • 决策不是一次性的，可以随着信息的增加而调整
    • 

  • 鼓励"disagree and commit"：不同意但承诺执行
    •

反模式与常见陷阱
反模式 1：决策真空
描述： 没有明确的决策者，讨论反复进行但无人拍板。


表现：


    

  • 同一个话题在不同场合被反复讨论
    • 

  • 会议结论是"再想想""再讨论讨论"
    • 

  • 团队不确定某些问题应该找谁决定
    • 

  • 技术方案一直处于"讨论中"状态
    • 



解决方案：


    

  • 为每类决策明确 RACI/DACI
    • 

  • 设定决策时限：超期自动升级
    • 

  • 建立"默认批准"机制：超过期限无反对即视为通过
    • 





反模式 2：HiPPO（Highest Paid Person's Opinion）
描述： 薪酬最高的人的意见自动成为决策，不管其是否具有相关的专业判断力。


表现：


    

  • VP/CTO 的话一出，讨论就结束
    • 

  • 工程师不敢提出不同意见
    • 

  • 决策总是由最高级别的人做出
    • 

  • 讨论会变成汇报会
    • 



解决方案：


    

  • 领导最后发言，先让团队充分讨论
    • 

  • 使用匿名投票收集独立意见
    • 

  • 明确决策权归属，不是所有决策都需要高层参与
    • 

  • 鼓励"以理服人"而非"以位服人"
    • 





反模式 3：分析瘫痪
描述： 过度分析，追求完美信息，迟迟无法做出决策。


表现：


    

  • 需要再做一轮调研
    • 

  • 需要再评估一个方案
    • 

  • 需要等某个数据出来
    • 

  • POC 做了好几轮，还没有结论
    • 



解决方案：


    

  • 为决策设定明确的截止日期
    • 

  • 区分单向门和双向门决策
    • 

  • 接受"足够好"的决策
    • 

  • 决策后快速验证，必要时调整
    • 





反模式 4：虚假共识
描述： 表面上达成了共识，但实际上很多人有不同意见却没有表达。


表现：


    

  • 会议上所有人都点头，但会后私下有很多不同意见
    • 

  • 执行时缺乏积极性和投入
    • 

  • 出了问题后出现"我当时就觉得不对"的声音
    • 

  • 相同的问题反复出现
    • 



解决方案：


    

  • 在决策前主动征求"不同意见"
    • 

  • 使用"红帽思维"：指定某人专门提出反对观点
    • 

  • 采用书面方式收集意见，减少社交压力
    • 

  • 区分"共识"和"同意"：你可以不同意但承诺执行
    • 





反模式 5：决策僵化
描述： 一旦做出决策就不允许质疑和调整，即使环境已经发生变化。


表现：


    

  • "这是之前决定的，不能改"
    • 

  • 原始决策的上下文已经不存在，但决策还在执行
    • 

  • 没有机制来触发决策的重新评估
    • 

  • ADR 写了就忘了，从不回顾
    • 



解决方案：


    

  • 在决策中明确"重新评估的触发条件"
    • 

  • 定期（每季度）回顾重要决策的有效性
    • 

  • 建立决策修正的正常流程
    • 

  • 记录决策依赖的前提条件
    • 



小结
决策框架不是官僚主义的工具，而是提升组织决策效率和质量的系统方法。


核心要点回顾：


    

  • 区分单向门和双向门决策，用不同的流程处理
    • 

  • RACI/DACI 明确决策权归属，避免决策真空
    • 

  • RFC 用于重要决策的充分讨论和记录
    • 

  • ADR 用于轻量级的架构决策记录
    • 

  • 决策矩阵用于多方案的量化评估
    • 

  • 分层授权：个人 → 团队 → 跨团队 → 组织
    • 

  • 培养"足够好"的决策文化：70% 信息时做决策
    • 

  • 建立安全的决策环境，鼓励不同意见
    • 

  • 警惕决策偏见：锚定效应、从众效应、HiPPO
    • 

  • 决策不是一次性的，需要定期回顾和调整
    •
