Babel 插件体系

Babel AST 与 ESTree

Babel 是 JavaScript 生态中最重要的编译工具之一。它将 JavaScript/TypeScript/JSX 源代码解析为 AST，通过插件对 AST 进行变换，再将变换后的 AST 生成为目标代码。Babel 的 AST 基于 ESTree 规范，并扩展了 TypeScript、JSX 和 Flow 等语法节点。

interface BabelNode {
  type: string;
  start: number | null;
  end: number | null;
  loc: SourceLocation | null;
  leadingComments?: Comment[];
  trailingComments?: Comment[];
}

interface SourceLocation {
  start: { line: number; column: number };
  end: { line: number; column: number };
}

interface Comment {
  type: 'CommentBlock' | 'CommentLine';
  value: string;
  start: number;
  end: number;
}

interface BabelProgram extends BabelNode {
  type: 'Program';
  body: BabelStatement[];
  sourceType: 'module' | 'script';
}

type BabelStatement =
  | BabelVariableDeclaration
  | BabelFunctionDeclaration
  | BabelExpressionStatement
  | BabelIfStatement
  | BabelReturnStatement;

interface BabelVariableDeclaration extends BabelNode {
  type: 'VariableDeclaration';
  kind: 'var' | 'let' | 'const';
  declarations: BabelVariableDeclarator[];
}

interface BabelVariableDeclarator extends BabelNode {
  type: 'VariableDeclarator';
  id: BabelPattern;
  init: BabelExpression | null;
}

type BabelExpression =
  | BabelIdentifier
  | BabelNumericLiteral
  | BabelStringLiteral
  | BabelBinaryExpression
  | BabelCallExpression
  | BabelArrowFunctionExpression;

interface BabelIdentifier extends BabelNode {
  type: 'Identifier';
  name: string;
}

interface BabelNumericLiteral extends BabelNode {
  type: 'NumericLiteral';
  value: number;
}
ESTree 节点 Babel 扩展 区别
Literal NumericLiteral 等 Babel 细分字面量类型
Property ObjectProperty 命名更明确
FunctionDecl 同名 增加 TypeScript 字段
— TSTypeAnnotation Babel 扩展 TS 支持
— JSXElement Babel 扩展 JSX 支持 


提示： Babel 与 TypeScript 编译器处理 TypeScript 的方式截然不同——Babel 只做语法转换（擦除类型），不做类型检查。如果你需要类型检查，仍需配合 tsc --noEmit 使用。






Visitor 插件模型
Babel 插件使用 Visitor 模式——每个插件声明它关心的 AST 节点类型，Babel 在遍历 AST 时自动调用对应的 visitor 方法。


interface BabelPluginObj {
  name: string;
  visitor: Record<string, VisitorHandler>;
}

type VisitorHandler =
  | ((path: NodePath) => void)
  | { enter?: (path: NodePath) => void; exit?: (path: NodePath) => void };

interface NodePath {
  node: BabelNode;
  parent: BabelNode;
  parentPath: NodePath | null;
  scope: Scope;
  replaceWith(newNode: BabelNode): void;
  replaceWithMultiple(nodes: BabelNode[]): void;
  remove(): void;
  insertBefore(nodes: BabelNode[]): void;
  insertAfter(nodes: BabelNode[]): void;
  get(key: string): NodePath;
  traverse(visitor: Record<string, VisitorHandler>): void;
  isIdentifier(opts?: { name?: string }): boolean;
  isMemberExpression(): boolean;
}

interface Scope {
  bindings: Record<string, Binding>;
  generateUidIdentifier(name: string): BabelIdentifier;
  hasBinding(name: string): boolean;
  getBinding(name: string): Binding | undefined;
}

interface Binding {
  identifier: BabelIdentifier;
  path: NodePath;
  referenced: boolean;
  references: number;
  constant: boolean;
}

const createRemoveConsolePlugin = (): BabelPluginObj => ({
  name: 'remove-console',
  visitor: {
    CallExpression(path: NodePath) {
      const callee = path.node as unknown as { callee?: { object?: BabelIdentifier } };
      if (callee.callee?.object?.name === 'console') {
        path.remove();
      }
    },
  },
});

const createAutoBindPlugin = (): BabelPluginObj => ({
  name: 'auto-bind',
  visitor: {
    ClassDeclaration(path: NodePath) {
      path.traverse({
        ClassMethod(methodPath: NodePath) {
          const methodNode = methodPath.node as unknown as { key: BabelIdentifier; kind: string };
          if (methodNode.kind === 'method') {
            console.log(`自动绑定方法: ${methodNode.key.name}`);
          }
        },
      });
    },
  },
});

插件执行顺序
Babel 的插件和 preset 有明确的执行顺序规则。理解执行顺序对于编写正确的插件组合至关重要。


interface BabelConfig {
  presets: Array<string | [string, Record<string, unknown>]>;
  plugins: Array<string | [string, Record<string, unknown>]>;
}

// 执行顺序规则：
// 1. plugins 先于 presets 执行
// 2. plugins 按数组顺序从前到后执行
// 3. presets 按数组顺序从后到前执行（反序）

const executionOrder: Array<{ phase: string; item: string }> = [
  { phase: 'plugin', item: 'plugin-transform-arrow-functions' },
  { phase: 'plugin', item: 'plugin-transform-classes' },
  { phase: 'plugin', item: 'plugin-custom-plugin' },
  { phase: 'preset', item: 'preset-env（最后列出，最先执行）' },
  { phase: 'preset', item: 'preset-react（最先列出，最后执行）' },
];

const exampleConfig: BabelConfig = {
  plugins: ['plugin-transform-arrow-functions', 'plugin-transform-classes', ['plugin-custom', { option1: true }]],
  presets: [
    ['preset-react', { runtime: 'automatic' }],
    ['preset-env', { targets: '> 0.25%' }],
  ],
};




规则
说明





plugins 先执行
所有 plugins 在 presets 之前运行




plugins 正序
按声明顺序从前到后




presets 反序
按声明顺序从后到前




visitor merge
同类型的 visitor 方法会合并执行







提示： Babel 会将所有插件的 visitor 合并后进行单次 AST 遍历，而非每个插件遍历一次。这意味着在同一次遍历中，多个插件的 visitor 可能会作用于同一个节点。如果一个插件的变换改变了节点类型，后续插件的 visitor 可能不再匹配。






宏系统
宏是编译时执行的代码变换。Babel 生态中的宏系统（如 babel-plugin-macros）允许在不配置 Babel 插件的情况下使用编译时变换。


interface MacroHandler {
  (params: { references: Record<string, NodePath[]>; state: unknown }): void;
}

const createSizeMacro =
  (): MacroHandler =>
  ({ references }) => {
    const defaultRefs = references.default ?? [];
    for (const ref of defaultRefs) {
      const call = ref.parentPath;
      if (!call) continue;
      const callNode = call.node as unknown as { arguments: BabelNode[] };
      const arg = callNode.arguments[0];
      if (arg && 'value' in arg && typeof arg.value === 'string') {
        const size = new TextEncoder().encode(arg.value).length;
        call.replaceWith({ type: 'NumericLiteral', value: size } as unknown as BabelNode);
      }
    }
  };

// 使用：
// import size from './size.macro';
// const len = size("hello"); // 编译为: const len = 5;

const createInlineSvgMacro =
  (): MacroHandler =>
  ({ references }) => {
    const defaultRefs = references.default ?? [];
    for (const ref of defaultRefs) {
      const call = ref.parentPath;
      if (!call) continue;
      const callNode = call.node as unknown as { arguments: BabelNode[] };
      const pathArg = callNode.arguments[0];
      if (pathArg && 'value' in pathArg) {
        const svgContent = `<svg>...</svg>`;
        call.replaceWith({
          type: 'StringLiteral',
          value: svgContent,
        } as unknown as BabelNode);
      }
    }
  };

小结
    

  • Babel AST 基于 ESTree 规范，扩展了 TypeScript、JSX 和 Flow 语法支持。
    • 

  • 插件通过 Visitor 模式声明关注的节点类型，Babel 在遍历时自动调用。
    • 

  • Path API 提供了丰富的节点操作能力：替换、删除、插入、作用域查询。
    • 

  • 执行顺序：plugins 正序 → presets 反序，所有 visitor 合并后单次遍历。
    • 

  • 宏系统实现编译时代码变换，无需全局 Babel 插件配置，适合库级别的编译时优化。
    •
