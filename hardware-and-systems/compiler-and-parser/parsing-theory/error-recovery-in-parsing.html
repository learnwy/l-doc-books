解析错误恢复

错误恢复的意义

语法错误是不可避免的。优秀的编译器不应在遇到第一个错误时就停止，而应尽可能恢复，继续解析以发现更多错误。错误恢复的质量直接影响开发者体验——它决定了错误消息的数量、准确性和可操作性。

interface Diagnostic {
  severity: 'error' | 'warning' | 'info';
  message: string;
  span: { start: number; end: number };
  line: number;
  column: number;
  suggestions?: string[];
}

class DiagnosticCollector {
  private diagnostics: Diagnostic[] = [];

  report(diag: Diagnostic): void {
    this.diagnostics.push(diag);
  }

  hasErrors(): boolean {
    return this.diagnostics.some((d) => d.severity === 'error');
  }

  getAll(): Diagnostic[] {
    return [...this.diagnostics];
  }
}

短语级恢复 局部修补 精确度高 实现复杂

全局修正 最小编辑距离修正 理论最优 计算代价高 


提示： 错误恢复的黄金法则：一个错误只应触发一条错误消息。恢复后产生的"级联错误"（cascading errors）通常是错误恢复质量差的标志。TypeScript 编译器通过标记"已恢复"状态来抑制级联错误。






恐慌模式
恐慌模式（Panic Mode）是最简单也最常用的错误恢复策略。遇到错误时，解析器丢弃 Token 直到找到一个同步 Token（如 ;、}、关键字），然后从该点重新开始解析。


const SYNC_TOKENS = new Set([TokenKind.Semicolon, TokenKind.RightBrace, TokenKind.EOF]);

const STATEMENT_STARTERS = new Set(['if', 'while', 'for', 'return', 'let', 'const', 'function']);

class PanicModeParser extends Parser {
  private diagnostics: DiagnosticCollector = new DiagnosticCollector();

  parseStatement(): ASTNode {
    try {
      return this.parseStatementInner();
    } catch (e) {
      return this.synchronize();
    }
  }

  private parseStatementInner(): ASTNode {
    const token = this.peek();
    switch (token.lexeme) {
      case 'let':
        return this.parseVarDecl();
      case 'if':
        return this.parseIf();
      case 'return':
        return this.parseReturn();
      default:
        return this.parseExprStmt();
    }
  }

  private synchronize(): ASTNode {
    const startToken = this.peek();
    this.diagnostics.report({
      severity: 'error',
      message: `意外的 Token '${startToken.lexeme}'`,
      span: { start: startToken.offset, end: startToken.offset + startToken.length },
      line: startToken.line,
      column: startToken.column,
    });

    while (!this.isAtEnd()) {
      if (SYNC_TOKENS.has(this.peek().kind)) {
        this.advance();
        break;
      }
      if (STATEMENT_STARTERS.has(this.peek().lexeme)) {
        break;
      }
      this.advance();
    }

    return { kind: 'ErrorNode', span: { start: startToken.offset, end: this.peek().offset } };
  }

  private isAtEnd(): boolean {
    return this.peek().kind === TokenKind.EOF;
  }
  private parseVarDecl(): ASTNode {
    return { kind: 'VarDecl' };
  }
  private parseIf(): ASTNode {
    return { kind: 'IfStmt' };
  }
  private parseReturn(): ASTNode {
    return { kind: 'ReturnStmt' };
  }
  private parseExprStmt(): ASTNode {
    return { kind: 'ExprStmt' };
  }
}

短语级恢复
短语级恢复（Phrase-level Recovery）通过插入或删除单个 Token 来修补局部语法错误，避免丢弃大段代码。


class PhraseLevelParser extends Parser {
  private diagnostics: DiagnosticCollector = new DiagnosticCollector();

  expectWithRecovery(kind: TokenKind): Token | null {
    if (this.peek().kind === kind) {
      return this.advance();
    }

    if (this.canInsert(kind)) {
      this.diagnostics.report({
        severity: 'error',
        message: `缺少 '${TokenKind[kind]}'`,
        span: { start: this.peek().offset, end: this.peek().offset },
        line: this.peek().line,
        column: this.peek().column,
        suggestions: [`在此处插入 '${TokenKind[kind]}'`],
      });
      return this.createMissingToken(kind);
    }

    if (this.canDelete()) {
      const unexpected = this.advance();
      this.diagnostics.report({
        severity: 'error',
        message: `意外的 '${unexpected.lexeme}'`,
        span: { start: unexpected.offset, end: unexpected.offset + unexpected.length },
        line: unexpected.line,
        column: unexpected.column,
      });
      return this.expectWithRecovery(kind);
    }

    return null;
  }

  private canInsert(kind: TokenKind): boolean {
    const insertable = new Set([TokenKind.Semicolon, TokenKind.RightParen, TokenKind.RightBrace]);
    return insertable.has(kind);
  }

  private canDelete(): boolean {
    return !this.isAtEnd() && !SYNC_TOKENS.has(this.peek().kind);
  }

  private createMissingToken(kind: TokenKind): Token {
    const current = this.peek();
    return {
      kind,
      lexeme: '',
      line: current.line,
      column: current.column,
      offset: current.offset,
      length: 0,
    };
  }

  private isAtEnd(): boolean {
    return this.peek().kind === TokenKind.EOF;
  }
}


提示： TypeScript 编译器大量使用短语级恢复。当缺少分号时，TypeScript 利用 ASI（Automatic Semicolon Insertion）规则自动插入虚拟分号，而不是报错——这本质上就是一种编码在语言规范中的短语级恢复。






错误产生式
错误产生式（Error Production）是在文法中显式定义错误模式的技术。解析器将常见的语法错误作为合法的（但标记为错误的）语法规则来处理。


interface ErrorRecoveryRule {
  pattern: string;
  message: string;
  recovery: (parser: PhraseLevelParser) => ASTNode;
}

const commonErrorPatterns: ErrorRecoveryRule[] = [
  {
    pattern: 'if expr { ... }',
    message: 'if 语句缺少条件括号',
    recovery: (parser) => {
      parser.advance();
      const condition = parser.parseExpression(0);
      const body = parser.parseBlock();
      return { kind: 'IfStmt', condition, body, missingParens: true };
    },
  },
  {
    pattern: 'let = expr',
    message: '变量声明缺少变量名',
    recovery: (parser) => {
      parser.advance();
      parser.advance();
      const init = parser.parseExpression(0);
      return { kind: 'VarDecl', name: '<missing>', init, error: true };
    },
  },
  {
    pattern: 'expr expr',
    message: '两个表达式之间缺少运算符',
    recovery: (parser) => {
      const left = parser.parseExpression(0);
      const right = parser.parseExpression(0);
      return { kind: 'BinaryExpr', op: '<missing>', left, right };
    },
  },
];

class ErrorProductionParser extends PhraseLevelParser {
  parseExpression(_precedence: number): ASTNode {
    return { kind: 'Expr' };
  }
  parseBlock(): ASTNode {
    return { kind: 'Block' };
  }
}

Tree-sitter 的弹性解析
Tree-sitter 代表了编辑器场景下解析错误恢复的最先进水平。它基于 GLR 解析，将错误节点作为语法树的合法成员，保证任何输入都能产出一棵完整的语法树。


interface TreeSitterNode {
  type: string;
  isError: boolean;
  isMissing: boolean;
  children: TreeSitterNode[];
  startIndex: number;
  endIndex: number;
  text: string;
}

const analyzeErrorNodes = (
  root: TreeSitterNode,
): Array<{
  type: string;
  text: string;
  position: { start: number; end: number };
  context: string;
}> => {
  const errors: Array<{
    type: string;
    text: string;
    position: { start: number; end: number };
    context: string;
  }> = [];

  const walk = (node: TreeSitterNode, parent: TreeSitterNode | null): void => {
    if (node.isError) {
      errors.push({
        type: 'ERROR',
        text: node.text,
        position: { start: node.startIndex, end: node.endIndex },
        context: parent?.type ?? '<root>',
      });
    }
    if (node.isMissing) {
      errors.push({
        type: 'MISSING',
        text: node.type,
        position: { start: node.startIndex, end: node.endIndex },
        context: parent?.type ?? '<root>',
      });
    }
    for (const child of node.children) {
      walk(child, node);
    }
  };

  walk(root, null);
  return errors;
};

提示： Tree-sitter 的错误恢复策略是：当 GLR 解析的所有路径都失败时，它尝试跳过一个 Token 作为 ERROR 节点的内容，然后重新启动解析。这种"逐 Token 跳过"的方式保证了最细粒度的错误定位。






小结
    

  • 恐慌模式通过跳到同步 Token 快速恢复，是最基础也最可靠的策略。
    • 

  • 短语级恢复通过插入/删除单个 Token 实现局部修补，减少信息丢失。
    • 

  • 错误产生式为常见错误模式提供精确的恢复路径和错误消息。
    • 

  • Tree-sitter 将错误节点嵌入语法树，保证任何输入都产出完整的、可查询的语法树。
    • 

  • 好的错误恢复应遵循"一个错误一条消息"原则，避免级联错误淹没真正的问题。
