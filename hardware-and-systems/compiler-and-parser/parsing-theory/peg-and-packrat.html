PEG 与 Packrat 解析

解析表达式文法

解析表达式文法（Parsing Expression Grammar，PEG）是 Bryan Ford 于 2004 年提出的一种形式化文法。与上下文无关文法（CFG）不同，PEG 使用有序选择（Ordered Choice）替代 CFG 的非确定性选择，从根本上消除了文法歧义性。

type PEGExpr =
  | { type: 'literal'; value: string }
  | { type: 'charClass'; ranges: Array<[string, string]> }
  | { type: 'sequence'; exprs: PEGExpr[] }
  | { type: 'orderedChoice'; exprs: PEGExpr[] }
  | { type: 'zeroOrMore'; expr: PEGExpr }
  | { type: 'oneOrMore'; expr: PEGExpr }
  | { type: 'optional'; expr: PEGExpr }
  | { type: 'andPredicate'; expr: PEGExpr }
  | { type: 'notPredicate'; expr: PEGExpr }
  | { type: 'ruleRef'; name: string };

interface PEGGrammar {
  rules: Map<string, PEGExpr>;
  start: string;
}

提示： PEG 的有序选择意味着 a / ab 永远不会匹配 ab，因为 a 会先成功。在编写 PEG 文法时，必须将更长的替代项放在前面：ab / a。这是 PEG 新手最常见的陷阱。






Packrat 记忆化
PEG 的朴素递归下降实现在最坏情况下需要指数级时间。Packrat 解析通过记忆化（Memoization）将时间复杂度降至 O(n)，代价是 O(n × g) 的空间（n 为输入长度，g 为文法规则数）。


type ParseResult = { success: true; value: ASTNode; pos: number } | { success: false };

type MemoKey = `${string}@${number}`;

class PackratParser {
  private input: string;
  private grammar: PEGGrammar;
  private memo: Map<MemoKey, ParseResult> = new Map();

  constructor(input: string, grammar: PEGGrammar) {
    this.input = input;
    this.grammar = grammar;
  }

  parse(ruleName: string, pos: number): ParseResult {
    const key: MemoKey = `${ruleName}@${pos}`;

    if (this.memo.has(key)) {
      return this.memo.get(key)!;
    }

    const rule = this.grammar.rules.get(ruleName);
    if (!rule) return { success: false };

    const result = this.matchExpr(rule, pos);
    this.memo.set(key, result);
    return result;
  }

  private matchExpr(expr: PEGExpr, pos: number): ParseResult {
    switch (expr.type) {
      case 'literal':
        return this.matchLiteral(expr.value, pos);
      case 'sequence':
        return this.matchSequence(expr.exprs, pos);
      case 'orderedChoice':
        return this.matchChoice(expr.exprs, pos);
      case 'zeroOrMore':
        return this.matchZeroOrMore(expr.expr, pos);
      case 'ruleRef':
        return this.parse(expr.name, pos);
      case 'notPredicate':
        return this.matchNot(expr.expr, pos);
      default:
        return { success: false };
    }
  }

  private matchLiteral(value: string, pos: number): ParseResult {
    if (this.input.startsWith(value, pos)) {
      return { success: true, value: { kind: 'Literal', text: value }, pos: pos + value.length };
    }
    return { success: false };
  }

  private matchSequence(exprs: PEGExpr[], pos: number): ParseResult {
    const children: ASTNode[] = [];
    let current = pos;
    for (const expr of exprs) {
      const result = this.matchExpr(expr, current);
      if (!result.success) return { success: false };
      children.push(result.value);
      current = result.pos;
    }
    return { success: true, value: { kind: 'Sequence', children }, pos: current };
  }

  private matchChoice(exprs: PEGExpr[], pos: number): ParseResult {
    for (const expr of exprs) {
      const result = this.matchExpr(expr, pos);
      if (result.success) return result;
    }
    return { success: false };
  }

  private matchZeroOrMore(expr: PEGExpr, pos: number): ParseResult {
    const children: ASTNode[] = [];
    let current = pos;
    while (true) {
      const result = this.matchExpr(expr, current);
      if (!result.success) break;
      children.push(result.value);
      current = result.pos;
    }
    return { success: true, value: { kind: 'Repeat', children }, pos: current };
  }

  private matchNot(expr: PEGExpr, pos: number): ParseResult {
    const result = this.matchExpr(expr, pos);
    if (result.success) return { success: false };
    return { success: true, value: { kind: 'NotPredicate' }, pos };
  }
}

PEG 与 CFG 的表达力对比
PEG 和 CFG 在表达力上的关系至今没有完全确定的理论定论。已知 PEG 能表达一些 CFG 不能表达的语言（如 aⁿbⁿcⁿ），但也存在一些 CFG 能表达而 PEG 难以自然表达的语言。


// PEG 可以表达 a^n b^n c^n（CFG 无法表达的上下文敏感语言）
// S ← &(A 'c') 'a'+ B
// A ← 'a' A? 'b'
// B ← 'b' B? 'c'

const matchAnBnCn: PEGGrammar = {
  start: 'S',
  rules: new Map([
    [
      'S',
      {
        type: 'sequence',
        exprs: [
          {
            type: 'andPredicate',
            expr: {
              type: 'sequence',
              exprs: [
                { type: 'ruleRef', name: 'A' },
                { type: 'literal', value: 'c' },
              ],
            },
          },
          { type: 'oneOrMore', expr: { type: 'literal', value: 'a' } },
          { type: 'ruleRef', name: 'B' },
        ],
      },
    ],
    [
      'A',
      {
        type: 'sequence',
        exprs: [
          { type: 'literal', value: 'a' },
          { type: 'optional', expr: { type: 'ruleRef', name: 'A' } },
          { type: 'literal', value: 'b' },
        ],
      },
    ],
    [
      'B',
      {
        type: 'sequence',
        exprs: [
          { type: 'literal', value: 'b' },
          { type: 'optional', expr: { type: 'ruleRef', name: 'B' } },
          { type: 'literal', value: 'c' },
        ],
      },
    ],
  ]),
};

小结
    

  • PEG 用有序选择替代非确定性选择，从根本上消除文法歧义性。
    • 

  • Packrat 记忆化以 O(n × g) 空间为代价，保证 PEG 解析的线性时间复杂度。
    • 

  • PEG 能表达一些超越上下文无关语言的模式（如 aⁿbⁿcⁿ），但不支持左递归。
    • 

  • tree-sitter 是当前编辑器生态最重要的解析器生成工具，提供增量解析和错误恢复。
    • 

  • 在 PEG 文法中，替代项的顺序至关重要——总是将更长/更具体的选项放在前面。
