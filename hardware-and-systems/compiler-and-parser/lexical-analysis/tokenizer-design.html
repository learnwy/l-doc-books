词法分析器设计

Token 类型体系

词法分析器的首要任务是定义 Token 类型。每个 Token 由类型标签和词素值组成，是源代码从字符流到结构化表示的第一步抽象。

enum TokenKind {
  Number,
  String,
  Identifier,
  Keyword,
  Plus,
  Minus,
  Star,
  Slash,
  LeftParen,
  RightParen,
  LeftBrace,
  RightBrace,
  Semicolon,
  Equals,
  EqualsEquals,
  Bang,
  BangEquals,
  EOF,
}

interface Token {
  kind: TokenKind;
  lexeme: string;
  line: number;
  column: number;
  offset: number;
  length: number;
}

Token 类型通常分为以下几个大类：

Token 类别 示例 特点
关键字 if, else, return 固定集合
标识符 foo, myVar, _count 用户自定义名称
字面量 42, "hello", true 携带语义值
运算符 +, ===, && 可能多字符
分隔符 (, ), ;, , 单字符
空白/注释 空格、换行、// comment 通常被过滤
特殊标记 EOF, Error, Newline 控制流标记 


提示： 是否将关键字作为独立的 Token 类型（如 TokenKind.If）还是统一归为 Identifier 再查表区分，取决于语言的关键字数量与解析器的便利性需求。TypeScript 编译器选择了为每个关键字分配独立的 SyntaxKind。






状态机驱动的词法分析器
手写词法分析器的核心模型是有限状态机（Finite State Machine）。分析器从初始状态出发，根据当前字符跳转到不同状态，最终在终止状态产出一个 Token。


class Lexer {
  private source: string;
  private pos: number = 0;
  private line: number = 1;
  private column: number = 1;

  constructor(source: string) {
    this.source = source;
  }

  private peek(): string {
    return this.pos < this.source.length ? this.source[this.pos] : '\0';
  }

  private advance(): string {
    const ch = this.source[this.pos];
    this.pos++;
    if (ch === '\n') {
      this.line++;
      this.column = 1;
    } else {
      this.column++;
    }
    return ch;
  }

  private skipWhitespace(): void {
    while (this.pos < this.source.length) {
      const ch = this.peek();
      if (ch === ' ' || ch === '\t' || ch === '\r' || ch === '\n') {
        this.advance();
      } else if (ch === '/' && this.source[this.pos + 1] === '/') {
        while (this.pos < this.source.length && this.peek() !== '\n') {
          this.advance();
        }
      } else {
        break;
      }
    }
  }

  nextToken(): Token {
    this.skipWhitespace();
    const start = this.pos;
    const line = this.line;
    const column = this.column;

    if (this.pos >= this.source.length) {
      return { kind: TokenKind.EOF, lexeme: '', line, column, offset: start, length: 0 };
    }

    const ch = this.advance();

    if (ch >= '0' && ch <= '9') return this.readNumber(start, line, column);
    if (ch === '"') return this.readString(start, line, column);
    if (isIdentStart(ch)) return this.readIdentifier(start, line, column, ch);

    return this.readPunctuation(start, line, column, ch);
  }

  private readNumber(start: number, line: number, column: number): Token {
    while (this.peek() >= '0' && this.peek() <= '9') this.advance();
    if (this.peek() === '.' && this.source[this.pos + 1] >= '0') {
      this.advance();
      while (this.peek() >= '0' && this.peek() <= '9') this.advance();
    }
    const lexeme = this.source.slice(start, this.pos);
    return { kind: TokenKind.Number, lexeme, line, column, offset: start, length: lexeme.length };
  }

  private readString(start: number, line: number, column: number): Token {
    while (this.pos < this.source.length && this.peek() !== '"') {
      if (this.peek() === '\\') this.advance();
      this.advance();
    }
    this.advance();
    const lexeme = this.source.slice(start, this.pos);
    return { kind: TokenKind.String, lexeme, line, column, offset: start, length: lexeme.length };
  }

  private readIdentifier(start: number, line: number, column: number, first: string): Token {
    while (isIdentPart(this.peek())) this.advance();
    const lexeme = this.source.slice(start, this.pos);
    const kind = KEYWORDS.has(lexeme) ? TokenKind.Keyword : TokenKind.Identifier;
    return { kind, lexeme, line, column, offset: start, length: lexeme.length };
  }

  private readPunctuation(start: number, line: number, column: number, ch: string): Token {
    const next = this.peek();
    if (ch === '=' && next === '=') {
      this.advance();
      return this.makeTok(TokenKind.EqualsEquals, start, line, column);
    }
    if (ch === '!' && next === '=') {
      this.advance();
      return this.makeTok(TokenKind.BangEquals, start, line, column);
    }

    const singleCharTokens: Record<string, TokenKind> = {
      '+': TokenKind.Plus,
      '-': TokenKind.Minus,
      '*': TokenKind.Star,
      '/': TokenKind.Slash,
      '(': TokenKind.LeftParen,
      ')': TokenKind.RightParen,
      '{': TokenKind.LeftBrace,
      '}': TokenKind.RightBrace,
      ';': TokenKind.Semicolon,
      '=': TokenKind.Equals,
      '!': TokenKind.Bang,
    };
    const kind = singleCharTokens[ch];
    return this.makeTok(kind, start, line, column);
  }

  private makeTok(kind: TokenKind, start: number, line: number, column: number): Token {
    const lexeme = this.source.slice(start, this.pos);
    return { kind, lexeme, line, column, offset: start, length: lexeme.length };
  }
}

const KEYWORDS = new Set(['let', 'const', 'if', 'else', 'return', 'function', 'while', 'for']);
const isIdentStart = (ch: string) => (ch >= 'a' && ch <= 'z') || (ch >= 'A' && ch <= 'Z') || ch === '_';
const isIdentPart = (ch: string) => isIdentStart(ch) || (ch >= '0' && ch <= '9');


DFA 与 NFA 在词法分析中的角色
词法分析器本质上是一个确定性有限自动机（DFA）。每条词法规则可以表示为一个正则表达式，对应一个 NFA，通过子集构造转换为 DFA。

interface DFAState {
  id: number;
  transitions: Map<string, number>;
  accepting: TokenKind | null;
}

interface DFA {
  states: DFAState[];
  startState: number;
}

const runDFA = (dfa: DFA, input: string, pos: number): { kind: TokenKind; end: number } | null => {
  let state = dfa.startState;
  let lastAccept: { kind: TokenKind; end: number } | null = null;

  for (let i = pos; i < input.length; i++) {
    const next = dfa.states[state].transitions.get(input[i]);
    if (next === undefined) break;
    state = next;
    if (dfa.states[state].accepting !== null) {
      lastAccept = { kind: dfa.states[state].accepting!, end: i + 1 };
    }
  }
  return lastAccept;
};


提示： 最长匹配（Maximal Munch）原则要求词法分析器在多条规则都能匹配时选择最长的匹配。DFA 实现中，这意味着即使当前状态已经是接受状态，也要继续尝试消费字符直到无法继续转移为止。

const lexAll = (source: string): Token[] => {
  const lexer = new Lexer(source);
  const tokens: Token[] = [];
  let token: Token;
  do {
    token = lexer.nextToken();
    tokens.push(token);
  } while (token.kind !== TokenKind.EOF);
  return tokens;
};

const tokens = lexAll('let x = 42;');
现代主流语言编译器（TypeScript、Go、Rust、Swift）几乎都选择了手写词法分析器，原因在于：手写实现可以精确控制错误恢复、轻松处理上下文相关的分词（如 TypeScript 的模板字符串和 JSX），以及实现增量分词用于编辑器场景。




小结
    

  • Token 是源代码的最小语义单元，由类型标签、词素值和位置信息组成。
    • 

  • 手写词法分析器基于状态机模型，通过 peek / advance 驱动字符消费循环。
    • 

  • DFA 保证 O(n) 线性扫描性能，NFA 构造更简单但执行需要回溯或子集模拟。
    • 

  • 最长匹配原则确保词法分析器在多条规则竞争时选择最长的匹配结果。
    • 

  • 现代主流编译器偏好手写词法分析器，因其在错误恢复和上下文敏感分词方面具有不可替代的灵活性。
