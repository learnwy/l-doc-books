Unicode 与编码

Unicode 感知的词法分析

现代编程语言必须处理 Unicode 源代码。从标识符中的中文、日文、emoji，到字符串中的各种脚本——词法分析器需要理解 Unicode 的字符分类，而非仅仅处理 ASCII。

const isUnicodeIdentStart = (codePoint: number): boolean => {
  if ((codePoint >= 0x41 && codePoint <= 0x5a) || (codePoint >= 0x61 && codePoint <= 0x7a) || codePoint === 0x5f) {
    return true;
  }
  const category = getUnicodeCategory(codePoint);
  return (
    category === 'Lu' ||
    category === 'Ll' ||
    category === 'Lt' ||
    category === 'Lm' ||
    category === 'Lo' ||
    category === 'Nl'
  );
};

const isUnicodeIdentPart = (codePoint: number): boolean => {
  if (isUnicodeIdentStart(codePoint)) return true;
  if (codePoint >= 0x30 && codePoint <= 0x39) return true;
  const category = getUnicodeCategory(codePoint);
  return (
    category === 'Mn' ||
    category === 'Mc' ||
    category === 'Nd' ||
    category === 'Pc' ||
    codePoint === 0x200c ||
    codePoint === 0x200d
  );
};

const getUnicodeCategory = (codePoint: number): string => {
  return 'Lo';
};
Unicode 类别 缩写 用途 示例
大写字母 Lu 标识符起始 A, Ω, Д
小写字母 Ll 标识符起始 a, ω, д
标题字母 Lt 标识符起始 ǅ, ǈ, ǋ
修饰字母 Lm 标识符起始 ʰ, ˈ
其他字母 Lo 标识符起始 中, あ, א
数字字母 Nl 标识符起始 Ⅰ, Ⅱ, Ⅲ
非间距标记 Mn 标识符续接 组合变音符号
间距标记 Mc 标识符续接 元音符号
十进制数字 Nd 标识符续接 0-9, ٠-٩
连接标点 Pc 标识符续接 _ 


提示： JavaScript/TypeScript 允许在标识符中使用 \uXXXX 转义序列。词法分析器在处理标识符时需要先解析转义，再判断解码后的码点是否是合法的标识符字符——这是一个容易遗漏的边界情况。






字素簇处理
Unicode 中一个"可见字符"可能由多个码点组成——这就是字素簇（Grapheme Cluster）。例如，é 可以是单个码点 U+00E9，也可以是 e（U+0065）+ ◌́（U+0301）两个码点的组合。


interface GraphemeInfo {
  codePoints: number[];
  displayWidth: number;
  byteLength: number;
}

const analyzeGrapheme = (str: string, index: number): GraphemeInfo => {
  const codePoints: number[] = [];
  let i = index;

  const cp = str.codePointAt(i)!;
  codePoints.push(cp);
  i += cp > 0xffff ? 2 : 1;

  while (i < str.length) {
    const nextCp = str.codePointAt(i)!;
    const cat = getUnicodeCategory(nextCp);
    if (cat !== 'Mn' && cat !== 'Mc' && !isEmojiModifier(nextCp) && !isZWJ(nextCp)) {
      break;
    }
    codePoints.push(nextCp);
    i += nextCp > 0xffff ? 2 : 1;
  }

  return {
    codePoints,
    displayWidth: getDisplayWidth(codePoints),
    byteLength: i - index,
  };
};

const isEmojiModifier = (cp: number): boolean => cp >= 0x1f3fb && cp <= 0x1f3ff;

const isZWJ = (cp: number): boolean => cp === 0x200d;

const getDisplayWidth = (cps: number[]): number => {
  const first = cps[0];
  if (first >= 0x1100 && first <= 0x115f) return 2;
  if (first >= 0x2e80 && first <= 0x9fff) return 2;
  if (first >= 0xf900 && first <= 0xfaff) return 2;
  if (first >= 0x20000 && first <= 0x2fa1f) return 2;
  return 1;
};

UAX#31 标识符规则
Unicode 标准附件 #31（UAX#31）定义了编程语言中标识符的推荐规则。现代语言（如 Rust、Swift、Python 3）均遵循或参考 UAX#31。


interface UAX31Profile {
  start: (cp: number) => boolean;
  continue: (cp: number) => boolean;
  medial: (cp: number) => boolean;
  normalize: (s: string) => string;
}

const defaultProfile: UAX31Profile = {
  start: (cp) => isXID_Start(cp) || cp === 0x5f,
  continue: (cp) => isXID_Continue(cp),
  medial: (_cp) => false,
  normalize: (s) => s.normalize('NFC'),
};

const isXID_Start = (cp: number): boolean => {
  return isUnicodeIdentStart(cp);
};

const isXID_Continue = (cp: number): boolean => {
  return isUnicodeIdentPart(cp);
};

const isValidIdentifier = (s: string, profile: UAX31Profile): boolean => {
  const normalized = profile.normalize(s);
  const codePoints = [...normalized].map((ch) => ch.codePointAt(0)!);

  if (codePoints.length === 0) return false;
  if (!profile.start(codePoints[0])) return false;

  for (let i = 1; i < codePoints.length; i++) {
    if (!profile.continue(codePoints[i]) && !profile.medial(codePoints[i])) {
      return false;
    }
  }
  return true;
};

const validateIdentifiers = (identifiers: string[]): Array<{ id: string; valid: boolean; reason: string }> =>
  identifiers.map((id) => {
    const normalized = id.normalize('NFC');
    if (normalized !== id) {
      return { id, valid: false, reason: '需要 NFC 正规化' };
    }
    if (!isValidIdentifier(id, defaultProfile)) {
      return { id, valid: false, reason: '包含非法标识符字符' };
    }
    return { id, valid: true, reason: '' };
  });


源文件编码检测
编译器需要在词法分析之前确定源文件的编码。大多数现代语言要求或推荐 UTF-8，但编译器仍需处理 BOM（字节序标记）和其他编码的兼容问题。


interface EncodingDetection {
  encoding: 'utf-8' | 'utf-16le' | 'utf-16be' | 'utf-32le' | 'utf-32be' | 'ascii' | 'unknown';
  hasBOM: boolean;
  bomLength: number;
  confidence: number;
}

const detectEncoding = (bytes: Uint8Array): EncodingDetection => {
  if (bytes.length >= 3 && bytes[0] === 0xef && bytes[1] === 0xbb && bytes[2] === 0xbf) {
    return { encoding: 'utf-8', hasBOM: true, bomLength: 3, confidence: 1.0 };
  }
  if (bytes.length >= 2 && bytes[0] === 0xff && bytes[1] === 0xfe) {
    if (bytes.length >= 4 && bytes[2] === 0x00 && bytes[3] === 0x00) {
      return { encoding: 'utf-32le', hasBOM: true, bomLength: 4, confidence: 1.0 };
    }
    return { encoding: 'utf-16le', hasBOM: true, bomLength: 2, confidence: 1.0 };
  }
  if (bytes.length >= 2 && bytes[0] === 0xfe && bytes[1] === 0xff) {
    return { encoding: 'utf-16be', hasBOM: true, bomLength: 2, confidence: 1.0 };
  }

  if (isValidUTF8(bytes)) {
    const hasHighByte = bytes.some((b) => b > 0x7f);
    return {
      encoding: hasHighByte ? 'utf-8' : 'ascii',
      hasBOM: false,
      bomLength: 0,
      confidence: hasHighByte ? 0.95 : 0.8,
    };
  }

  return { encoding: 'unknown', hasBOM: false, bomLength: 0, confidence: 0 };
};

const isValidUTF8 = (bytes: Uint8Array): boolean => {
  let i = 0;
  while (i < bytes.length) {
    const b = bytes[i];
    let seqLen: number;
    if (b <= 0x7f) seqLen = 1;
    else if ((b & 0xe0) === 0xc0) seqLen = 2;
    else if ((b & 0xf0) === 0xe0) seqLen = 3;
    else if ((b & 0xf8) === 0xf0) seqLen = 4;
    else return false;

    if (i + seqLen > bytes.length) return false;
    for (let j = 1; j < seqLen; j++) {
      if ((bytes[i + j] & 0xc0) !== 0x80) return false;
    }
    i += seqLen;
  }
  return true;
};

小结
    

  • Unicode 感知的词法分析器需要基于 Unicode 通用类别 判断标识符字符，而非仅支持 ASCII。
    • 

  • 字素簇是用户感知的"一个字符"单位，影响错误报告中的列号计算。
    • 

  • UAX#31 定义了标识符的标准规则，现代语言在此基础上各有扩展与限制。
    • 

  • 源文件编码检测优先通过 BOM 签名判断，无 BOM 时通过 UTF-8 验证进行推断。
    • 

  • 标识符的 Unicode 正规化（NFC/NFKC）保证同一视觉字符的不同编码形式被视为同一标识符。
