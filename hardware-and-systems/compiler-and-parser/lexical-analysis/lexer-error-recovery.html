词法错误恢复

错误 Token 的设计

词法分析阶段遇到无法识别的字符时，不应直接终止编译。现代编译器设计一种错误 Token（Error Token），将非法字符封装为一个带有错误信息的特殊 Token，交由后续阶段处理。

enum TokenKind {
  Number,
  String,
  Identifier,
  Plus,
  EOF,
  Error,
}

interface ErrorToken extends Token {
  kind: TokenKind.Error;
  message: string;
}

const createErrorToken = (ch: string, line: number, column: number, offset: number): ErrorToken => ({
  kind: TokenKind.Error,
  lexeme: ch,
  line,
  column,
  offset,
  length: ch.length,
  message: `意外的字符 '${ch}'`,
});
错误类型 示例 恢复策略
非法字符 @ 在不支持的上下文中 产出 Error Token，跳过该字符
未闭合字符串 "hello 在行尾或 EOF 处截断，产出字符串
未闭合块注释 /* comment 在 EOF 处截断，产出注释
非法数字格式 0x 后无十六进制数字 产出部分数字 Token + 错误信息
非法转义序列 "\q" 保留原始字符，附加警告 


提示： TypeScript 编译器将词法错误封装为诊断信息（Diagnostic），附加到 SourceFile 上。即使源代码存在词法错误，编译器仍会尝试完成后续的语法解析和类型检查——这就是"容错编译"的核心理念。






同步点选择
错误恢复的关键在于选择合适的同步点（Synchronization Point）。同步点是词法分析器在遇到错误后试图重新对齐正常分词的位置。


const SYNC_CHARS = new Set(['\n', ';', '{', '}', '(', ')']);

class RecoveringLexer extends Lexer {
  nextToken(): Token {
    this.skipWhitespace();
    const start = this.pos;
    const line = this.line;
    const column = this.column;

    if (this.pos >= this.source.length) {
      return this.makeEOF(start, line, column);
    }

    const ch = this.peek();

    if (ch >= '0' && ch <= '9') return this.readNumber(start, line, column);
    if (ch === '"') return this.readStringWithRecovery(start, line, column);
    if (isIdentStart(ch)) return this.readIdentifier(start, line, column, this.advance());

    if (this.isPunctuation(ch)) {
      this.advance();
      return this.readPunctuation(start, line, column, ch);
    }

    return this.recoverFromError(start, line, column);
  }

  private recoverFromError(start: number, line: number, column: number): ErrorToken {
    const errorChars: string[] = [];
    while (this.pos < this.source.length) {
      const ch = this.peek();
      if (SYNC_CHARS.has(ch) || this.isTokenStart(ch)) break;
      errorChars.push(this.advance());
    }
    const lexeme = errorChars.join('');
    return {
      kind: TokenKind.Error,
      lexeme,
      line,
      column,
      offset: start,
      length: lexeme.length,
      message: `无法识别的字符序列 '${lexeme}'`,
    };
  }

  private readStringWithRecovery(start: number, line: number, column: number): Token {
    this.advance();
    while (this.pos < this.source.length) {
      const ch = this.peek();
      if (ch === '"') {
        this.advance();
        break;
      }
      if (ch === '\n') {
        const lexeme = this.source.slice(start, this.pos);
        return {
          kind: TokenKind.Error,
          lexeme,
          line,
          column,
          offset: start,
          length: lexeme.length,
          message: '未闭合的字符串字面量',
        } as ErrorToken;
      }
      if (ch === '\\') this.advance();
      this.advance();
    }
    const lexeme = this.source.slice(start, this.pos);
    return { kind: TokenKind.String, lexeme, line, column, offset: start, length: lexeme.length };
  }

  private isTokenStart(ch: string): boolean {
    return (ch >= 'a' && ch <= 'z') || (ch >= 'A' && ch <= 'Z') || (ch >= '0' && ch <= '9') || ch === '_' || ch === '"';
  }

  private isPunctuation(ch: string): boolean {
    return '+-*/(){}[];=!<>,'.includes(ch);
  }
}

部分分词
在某些场景下（如字符串模板、正则表达式字面量），词法分析器需要进行部分分词——即在特定上下文中切换分词模式。


enum LexerMode {
  Normal,
  Template,
  RegExp,
}

class ModalLexer {
  private modeStack: LexerMode[] = [LexerMode.Normal];
  private source: string;
  private pos: number = 0;

  constructor(source: string) {
    this.source = source;
  }

  private currentMode(): LexerMode {
    return this.modeStack[this.modeStack.length - 1];
  }

  private pushMode(mode: LexerMode): void {
    this.modeStack.push(mode);
  }

  private popMode(): void {
    if (this.modeStack.length > 1) this.modeStack.pop();
  }

  nextToken(): Token {
    switch (this.currentMode()) {
      case LexerMode.Normal:
        return this.lexNormal();
      case LexerMode.Template:
        return this.lexTemplate();
      case LexerMode.RegExp:
        return this.lexRegExp();
    }
  }

  private lexNormal(): Token {
    const ch = this.source[this.pos];
    if (ch === '`') {
      this.pushMode(LexerMode.Template);
      return this.lexTemplate();
    }
    return this.lexDefaultToken();
  }

  private lexTemplate(): Token {
    let text = '';
    while (this.pos < this.source.length) {
      const ch = this.source[this.pos];
      if (ch === '`') {
        this.pos++;
        this.popMode();
        return this.makeToken(TokenKind.String, text);
      }
      if (ch === '$' && this.source[this.pos + 1] === '{') {
        this.pos += 2;
        this.pushMode(LexerMode.Normal);
        return this.makeToken(TokenKind.String, text);
      }
      text += this.source[this.pos++];
    }
    return this.makeToken(TokenKind.Error, text);
  }

  private lexRegExp(): Token {
    return this.lexDefaultToken();
  }
  private lexDefaultToken(): Token {
    return this.makeToken(TokenKind.EOF, '');
  }
  private makeToken(kind: TokenKind, lexeme: string): Token {
    return { kind, lexeme, line: 0, column: 0, offset: 0, length: lexeme.length };
  }
}


提示： TypeScript 编译器通过 ScannerState 维护多种分词模式。在遇到 } 时，解析器会通知词法分析器"我期望的是模板续接部分"，这是语法制导词法分析（Scanner-Parser Feedback）的典型案例。






增量重新分词
在编辑器场景中，用户每次按键修改少量字符，重新扫描整个文件代价过高。增量重新分词（Incremental Re-tokenization）只对受影响的区域重新扫描。


interface TokenWithSpan {
  kind: TokenKind;
  start: number;
  end: number;
  lexeme: string;
}

const incrementalReLex = (
  oldTokens: TokenWithSpan[],
  editStart: number,
  editEnd: number,
  newText: string,
  fullSource: string,
): TokenWithSpan[] => {
  const delta = newText.length - (editEnd - editStart);

  const firstAffected = oldTokens.findIndex((t) => t.end > editStart);
  let lastAffected = oldTokens.findIndex((t) => t.start >= editEnd);
  if (lastAffected === -1) lastAffected = oldTokens.length;

  const reLexStart = firstAffected > 0 ? oldTokens[firstAffected - 1].end : 0;
  const reLexEnd = lastAffected < oldTokens.length ? oldTokens[lastAffected].start + delta : fullSource.length;

  const lexer = new Lexer(fullSource);
  lexer.setPosition(reLexStart);
  const newTokens: TokenWithSpan[] = [];
  while (lexer.pos < reLexEnd) {
    const token = lexer.nextToken();
    if (token.kind === TokenKind.EOF) break;
    newTokens.push({
      kind: token.kind,
      start: token.offset,
      end: token.offset + token.length,
      lexeme: token.lexeme,
    });
  }

  const shifted = oldTokens.slice(lastAffected).map((t) => ({
    ...t,
    start: t.start + delta,
    end: t.end + delta,
  }));

  return [...oldTokens.slice(0, firstAffected), ...newTokens, ...shifted];
};

小结
    

  • Error Token 将非法字符封装为合法的 Token 流元素，保证编译管线不中断。
    • 

  • 同步点决定了错误恢复的粒度——跳到下一个有效 Token 起点是信息丢失最小的策略。
    • 

  • 模式栈支持上下文敏感的词法分析，模板字符串和正则表达式是典型场景。
    • 

  • 增量重新分词只对受编辑影响的区域重扫，为编辑器提供亚毫秒级的词法更新。
    • 

  • 工业级编译器（TypeScript、tree-sitter）通过 Scanner-Parser 反馈实现上下文感知的容错词法分析。
