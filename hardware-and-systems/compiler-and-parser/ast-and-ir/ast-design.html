AST 设计

核心概念

AST 是源代码的结构化表示，其节点类型体系是编译器架构的基石——后续所有分析与转换 Pass 的编程模型都由它决定。核心概念围绕三点展开：

  • 节点类型体系：以带判别字段（kind）的联合类型建模每种语法构造，让节点既统一可遍历，又能安全窄化到具体类型。
  • Visitor 模式：把「对每种节点做什么」从节点定义中抽离，使分析器与转换器无需修改节点类型即可新增，符合开闭原则。
  • Transformer 模式：在 Visitor 基础上返回新节点，以不可变方式自底向上重建整棵树，是编译器中最常见的改写范式。
  • 源码位置追踪（Span）：每个节点记录源区间，使诊断、Source Map 与编辑器定位能追溯到原始字节。

节点设计的取舍（如是否保留 parent 指针、用类还是普通对象）会一路影响后续 Pass 的实现难度，因此值得在项目初期就定型。

AST 节点类型体系

抽象语法树（Abstract Syntax Tree）是源代码的结构化表示，每个节点对应一个语法构造。AST 的节点类型设计是编译器架构的基石——它决定了后续所有分析和转换 Pass 的编程模型。

interface BaseNode {
  kind: string;
  span: Span;
  parent?: BaseNode;
}

interface Span {
  start: number;
  end: number;
  source: string;
}

interface Program extends BaseNode {
  kind: 'Program';
  body: Statement[];
}

type Statement =
  | VariableDeclaration
  | FunctionDeclaration
  | IfStatement
  | ReturnStatement
  | ExpressionStatement
  | BlockStatement;

type Expression = NumberLiteral | StringLiteral | Identifier | BinaryExpression | CallExpression | MemberExpression;

interface VariableDeclaration extends BaseNode {
  kind: 'VariableDeclaration';
  name: Identifier;
  init: Expression | null;
  mutable: boolean;
  typeAnnotation?: TypeNode;
}

interface FunctionDeclaration extends BaseNode {
  kind: 'FunctionDeclaration';
  name: Identifier;
  params: Parameter[];
  body: BlockStatement;
  returnType?: TypeNode;
}

interface BinaryExpression extends BaseNode {
  kind: 'BinaryExpression';
  operator: string;
  left: Expression;
  right: Expression;
}

interface CallExpression extends BaseNode {
  kind: 'CallExpression';
  callee: Expression;
  arguments: Expression[];
}

interface Identifier extends BaseNode {
  kind: 'Identifier';
  name: string;
}

interface NumberLiteral extends BaseNode {
  kind: 'NumberLiteral';
  value: number;
}

interface StringLiteral extends BaseNode {
  kind: 'StringLiteral';
  value: string;
}

语句 IfStatement, ReturnStatement 控制流
表达式 BinaryExpr, CallExpr 有值

提示： TypeScript 编译器使用数字枚举 SyntaxKind 作为节点类型标识，而非字符串。这在高频的 switch/case 分支中比字符串比较快一个数量级——对于需要遍历数百万节点的大型项目，这种微优化至关重要。

Visitor 模式

Visitor 模式是遍历和分析 AST 的经典设计模式。它将"对节点做什么"与"如何遍历"分离，使新增分析 Pass 只需实现一个 Visitor，而无需修改节点类。

interface ASTVisitor<R = void> {
  visitProgram?(node: Program): R;
  visitVariableDeclaration?(node: VariableDeclaration): R;
  visitFunctionDeclaration?(node: FunctionDeclaration): R;
  visitBinaryExpression?(node: BinaryExpression): R;
  visitCallExpression?(node: CallExpression): R;
  visitIdentifier?(node: Identifier): R;
  visitNumberLiteral?(node: NumberLiteral): R;
}

const visit = <R>(node: BaseNode, visitor: ASTVisitor<R>): R | undefined => {
  switch (node.kind) {
    case 'Program':
      return visitor.visitProgram?.(node as Program);
    case 'VariableDeclaration':
      return visitor.visitVariableDeclaration?.(node as VariableDeclaration);
    case 'FunctionDeclaration':
      return visitor.visitFunctionDeclaration?.(node as FunctionDeclaration);
    case 'BinaryExpression':
      return visitor.visitBinaryExpression?.(node as BinaryExpression);
    case 'CallExpression':
      return visitor.visitCallExpression?.(node as CallExpression);
    case 'Identifier':
      return visitor.visitIdentifier?.(node as Identifier);
    case 'NumberLiteral':
      return visitor.visitNumberLiteral?.(node as NumberLiteral);
  }
  return undefined;
};

const walkChildren = (node: BaseNode, visitor: ASTVisitor): void => {
  switch (node.kind) {
    case 'Program':
      for (const stmt of (node as Program).body) visit(stmt, visitor);
      break;
    case 'FunctionDeclaration': {
      const fn = node as FunctionDeclaration;
      visit(fn.name, visitor);
      visit(fn.body, visitor);
      break;
    }
    case 'BinaryExpression': {
      const bin = node as BinaryExpression;
      visit(bin.left, visitor);
      visit(bin.right, visitor);
      break;
    }
    case 'CallExpression': {
      const call = node as CallExpression;
      visit(call.callee, visitor);
      for (const arg of call.arguments) visit(arg, visitor);
      break;
    }
  }
};

const collectIdentifiers = (root: BaseNode): string[] => {
  const names: string[] = [];
  const collector: ASTVisitor = {
    visitIdentifier(node: Identifier) {
      names.push(node.name);
      return undefined;
    },
  };

  const walk = (node: BaseNode): void => {
    visit(node, collector);
    walkChildren(node, {
      visitIdentifier: (n) => {
        collector.visitIdentifier!(n);
      },
    });
  };
  walk(root);
  return names;
};
遍历策略 方向 用途
前序遍历 根→子 符号收集、作用域分析
后序遍历 子→根 类型推断、求值
宽度优先 层级遍历 层级分析
反向遍历 根→子(逆序) 活跃性分析

Transformer 模式

Transformer 模式用于创建修改后的 AST。不同于 Visitor 的只读遍历，Transformer 返回新节点（或原节点的修改版本），用于代码转换和优化。

type TransformFn = (node: BaseNode) => BaseNode;

const transformNode = (node: BaseNode, transform: TransformFn): BaseNode => {
  const transformed = transform(node);

  switch (transformed.kind) {
    case 'Program': {
      const prog = transformed as Program;
      return {
        ...prog,
        body: prog.body.map((s) => transformNode(s, transform) as Statement),
      };
    }
    case 'BinaryExpression': {
      const bin = transformed as BinaryExpression;
      return {
        ...bin,
        left: transformNode(bin.left, transform) as Expression,
        right: transformNode(bin.right, transform) as Expression,
      };
    }
    case 'CallExpression': {
      const call = transformed as CallExpression;
      return {
        ...call,
        callee: transformNode(call.callee, transform) as Expression,
        arguments: call.arguments.map((a) => transformNode(a, transform) as Expression),
      };
    }
    default:
      return transformed;
  }
};

const doubleAllNumbers: TransformFn = (node) => {
  if (node.kind === 'NumberLiteral') {
    const num = node as NumberLiteral;
    return { ...num, value: num.value * 2 };
  }
  return node;
};

提示： 不可变 Transformer（返回新节点）vs 可变 Transformer（原地修改）是一个重要的架构决策。不可变方案更安全、更易于调试和测试，但在大型 AST 上可能有性能开销。TypeScript 编译器使用可变 AST 以获取最大性能。

源码位置追踪（Span）

每个 AST 节点必须携带源码位置信息（Span），用于错误报告、Source Map 生成和 IDE 功能。Span 的设计影响着编译器的内存占用和定位精度。

interface CompactSpan {
  start: number;
  end: number;
}

interface RichSpan {
  start: Position;
  end: Position;
  source: string;
}

interface Position {
  offset: number;
  line: number;
  column: number;
}

class SourceMap {
  private lineStarts: number[];

  constructor(source: string) {
    this.lineStarts = [0];
    for (let i = 0; i < source.length; i++) {
      if (source[i] === '\n') this.lineStarts.push(i + 1);
    }
  }

  offsetToPosition(offset: number): Position {
    let low = 0;
    let high = this.lineStarts.length - 1;
    while (low < high) {
      const mid = (low + high + 1) >> 1;
      if (this.lineStarts[mid] <= offset) low = mid;
      else high = mid - 1;
    }
    return { offset, line: low + 1, column: offset - this.lineStarts[low] + 1 };
  }

  spanToRange(span: CompactSpan): { start: Position; end: Position } {
    return {
      start: this.offsetToPosition(span.start),
      end: this.offsetToPosition(span.end),
    };
  }
}
Span 设计 存储 行列计算 内存开销
offset + len 2 × u32 需要 LineMap 最小(8字节)
start + end 2 × u32 需要 LineMap 8 字节
line+col+len 3 × u32 直接可用 12 字节
索引到表 1 × u32 查表 4 字节

小结

mindmap
  root((AST 设计))
    节点类型
      声明/语句/表达式
      字面量/类型/模式
      可辨识联合
    Visitor
      遍历与分析分离
      前序/后序遍历
      只读分析 Pass
    Transformer
      创建修改后的 AST
      不可变 vs 可变
      代码转换/优化
    Span
      源码位置追踪
      offset+length 最紧凑
      LineMap 行列转换
  • AST 节点通过可辨识联合（kind 字段）建模，每种语法构造对应一个类型。
  • Visitor 模式将遍历逻辑与分析逻辑分离，是 AST 分析 Pass 的标准范式。
  • Transformer 模式通过返回新/修改后的节点实现 AST 变换，是代码转换的基础。
  • 每个节点的 Span 记录源码位置，offset + length 是最紧凑的存储方案，配合 LineMap 按需计算行列号。
  • 工业级编译器（TypeScript、Rust）在 AST 设计中做了大量微优化，如数字枚举替代字符串、可变 AST 减少分配。
