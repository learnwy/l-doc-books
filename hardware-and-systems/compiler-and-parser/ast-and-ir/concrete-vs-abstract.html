CST 与 AST

具体语法树 vs 抽象语法树

具体语法树（Concrete Syntax Tree，CST）保留源代码的所有语法细节——包括空白、注释、括号和分隔符。抽象语法树（AST）则丢弃这些"噪音"，只保留语义相关的结构。这两种设计代表了编译器架构中的一个核心权衡。

// CST：保留所有 Token，包括空白和注释
interface CSTNode {
  kind: string;
  children: Array<CSTNode | CSTToken>;
  span: { start: number; end: number };
}

interface CSTToken {
  kind: string;
  text: string;
  leadingTrivia: Trivia[];
  trailingTrivia: Trivia[];
  span: { start: number; end: number };
}

interface Trivia {
  kind: 'whitespace' | 'newline' | 'comment' | 'blockComment';
  text: string;
}

// AST：只保留语义结构
interface ASTLetDecl {
  kind: 'LetDeclaration';
  name: string;
  init: ASTExpr;
  span: { start: number; end: number };
}
特性 CST（无损） AST（有损）
空白/注释 保留 丢弃
括号/分隔符 保留为节点 隐含在结构中
源码往返 可以精确重建源码 无法重建原始格式
内存占用 较大 较小
遍历复杂度 需要跳过 trivia 节点 直接访问语义节点
典型用途 格式化器、重构工具 编译器后端、代码生成
典型实现者 Roslyn, rust-analyzer GCC, V8 


提示： 选择 CST 还是 AST 取决于你的工具目标。如果你在构建格式化器（如 Prettier）、重构工具或 IDE 插件，CST 是必须的——因为你需要保留用户的代码格式。如果你只需要编译或分析语义，AST 更高效。






Red-Green 树
Red-Green 树是 Roslyn（C# 编译器）发明、后被 rust-analyzer 采纳的一种创新语法树设计。它将语法树分为两层：Green 树（不可变、无父指针、可共享）和 Red 树（按需创建、有父指针、有绝对位置）。


interface GreenNode {
  kind: string;
  width: number;
  children: GreenElement[];
}

type GreenElement = GreenNode | GreenToken;

interface GreenToken {
  kind: string;
  text: string;
  width: number;
}

interface RedNode {
  green: GreenNode;
  parent: RedNode | null;
  offsetInParent: number;
}

const createRedNode = (green: GreenNode, parent: RedNode | null, offset: number): RedNode => ({
  green,
  parent,
  offsetInParent: offset,
});

const getAbsoluteOffset = (red: RedNode): number => {
  let offset = 0;
  let current: RedNode | null = red;
  while (current !== null) {
    offset += current.offsetInParent;
    current = current.parent;
  }
  return offset;
};

const getChild = (red: RedNode, index: number): RedNode | null => {
  const greenChildren = red.green.children;
  if (index >= greenChildren.length) return null;

  let offset = 0;
  for (let i = 0; i < index; i++) {
    offset += greenChildren[i].width;
  }

  const child = greenChildren[index];
  if ('children' in child) {
    return createRedNode(child, red, offset);
  }
  return null;
};

提示： Red-Green 树的核心优势在于增量解析。当源码局部修改时，只需重建受影响的 Green 节点，未改变的子树可以直接复用。这使得 rust-analyzer 可以在毫秒级完成语法树更新，即使项目包含数十万行代码。






无损语法节点 API
基于 CST 或 Red-Green 树的语法节点 API 需要在保留所有源码细节的同时，提供方便的语义访问接口。关键挑战是如何让 API 既"无损"又"好用"。


class SyntaxNode {
  private green: GreenNode;
  private offset: number;
  private parentNode: SyntaxNode | null;

  constructor(green: GreenNode, parent: SyntaxNode | null, offset: number) {
    this.green = green;
    this.offset = offset;
    this.parentNode = parent;
  }

  kind(): string {
    return this.green.kind;
  }
  textRange(): { start: number; end: number } {
    return { start: this.offset, end: this.offset + this.green.width };
  }

  parent(): SyntaxNode | null {
    return this.parentNode;
  }

  children(): SyntaxNode[] {
    const result: SyntaxNode[] = [];
    let childOffset = this.offset;
    for (const child of this.green.children) {
      if ('children' in child) {
        result.push(new SyntaxNode(child, this, childOffset));
      }
      childOffset += child.width;
    }
    return result;
  }

  firstChildOfKind(kind: string): SyntaxNode | null {
    let childOffset = this.offset;
    for (const child of this.green.children) {
      if ('children' in child && child.kind === kind) {
        return new SyntaxNode(child, this, childOffset);
      }
      childOffset += child.width;
    }
    return null;
  }

  text(source: string): string {
    const range = this.textRange();
    return source.slice(range.start, range.end);
  }

  ancestors(): SyntaxNode[] {
    const result: SyntaxNode[] = [];
    let current = this.parentNode;
    while (current) {
      result.push(current);
      current = current.parentNode;
    }
    return result;
  }
}

class FunctionDeclSyntax {
  private node: SyntaxNode;

  constructor(node: SyntaxNode) {
    this.node = node;
  }

  nameToken(): SyntaxNode | null {
    return this.node.firstChildOfKind('Identifier');
  }

  parameterList(): SyntaxNode | null {
    return this.node.firstChildOfKind('ParameterList');
  }

  body(): SyntaxNode | null {
    return this.node.firstChildOfKind('Block');
  }

  returnTypeAnnotation(): SyntaxNode | null {
    return this.node.firstChildOfKind('TypeAnnotation');
  }
}

选择策略
interface TreeDesignDecision {
  scenario: string;
  recommendation: 'CST' | 'AST' | 'RedGreen';
  reason: string;
}

const designGuide: TreeDesignDecision[] = [
  {
    scenario: '传统编译器后端',
    recommendation: 'AST',
    reason: '只需要语义信息，AST 更紧凑高效',
  },
  {
    scenario: '代码格式化器',
    recommendation: 'CST',
    reason: '必须保留空白和注释以精确重建格式',
  },
  {
    scenario: 'IDE / Language Server',
    recommendation: 'RedGreen',
    reason: '需要增量更新、父节点遍历和无损信息',
  },
  {
    scenario: 'Linter / 静态分析',
    recommendation: 'AST',
    reason: '语义分析为主，偶尔需要注释信息可附加',
  },
  {
    scenario: '源码转换工具',
    recommendation: 'CST',
    reason: '转换后需要保留未修改部分的原始格式',
  },
];


小结
    

  • CST 保留所有源码细节（空白、注释、括号），支持无损源码往返。
    • 

  • AST 只保留语义相关结构，更紧凑高效，适合编译器后端。
    • 

  • Red-Green 树将语法树分为不可变的 Green 层和按需创建的 Red 层，完美支持增量解析。
    • 

  • 语法节点 API 应在通用遍历层之上提供类型化 Wrapper，兼顾灵活性和易用性。
    • 

  • 工具的目标决定了树设计的选择：编译→AST，格式化→CST，IDE→Red-Green。
