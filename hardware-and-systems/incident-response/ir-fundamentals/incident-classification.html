安全事件分类与分级体系

概述

安全事件分类与分级是事件响应流程的前置关键环节。准确的分类帮助响应团队快速理解事件性质、匹配正确的处置手册（Playbook）；合理的分级则确保资源投入与事件影响成正比，避免低级事件占用高级人力，也防止高危事件被低估延误。

本文系统介绍安全事件分类的标准方法、分级维度与判定标准，以及如何将分类分级体系与响应流程深度集成，形成可执行的运营制度。

事件分类标准

国际分类框架

业界已有多个成熟的事件分类标准，组织可直接采用或在此基础上定制：

NIST SP 800-61 分类

NIST 将安全事件按攻击向量分为以下类别：

类别 说明 典型事例
外部/可移动介质 通过 USB、光盘等外部设备发起的攻击 BadUSB 攻击、恶意固件植入
邮件（Email） 通过电子邮件传播的攻击 钓鱼邮件、BEC 诈骗、恶意附件
网络（Web） 通过 Web 应用或浏览器发起的攻击 SQL 注入、XSS、水坑攻击
暴力攻击（Attrition） 通过暴力手段突破防御 密码爆破、DDoS 攻击
冒充（Impersonation） 伪装合法实体实施欺骗 IP/MAC 伪装、域名仿冒
设备丢失/被窃 包含敏感数据的设备丢失或被盗 笔记本丢失、手机被窃
不当使用 违反可接受使用策略的行为 员工安装未授权软件、数据外传
其他 无法归入以上类别的事件 零日漏洞利用、供应链攻击

动态调级机制
事件的严重性可能在调查过程中发生变化，分级体系必须支持动态调整：


升级条件


    

  • 发现事件影响范围比初始评估更广
    • 

  • 检测到数据实际泄露（从"入侵"升级为"数据泄露"）
    • 

  • 攻击者仍在活跃活动中
    • 

  • 媒体曝光或外部报告增加了合规压力
    • 

  • 关联发现其他系统也已受影响
    • 



降级条件


    

  • 确认为误报或影响有限的安全事件
    • 

  • 初始影响评估过高，实际范围小于预期
    • 

  • 已完成遏制且无进一步扩散迹象
    • 



调级必须由事件指挥官（IC）或值班主管批准，并在事件工单中记录调级原因和时间。

组织内部的分级体系需要与国家标准形成映射关系，确保内部 P1/P2 事件能及时对接外部报告义务。


总结
安全事件分类与分级体系是事件响应效率的基础保障。分类回答"这是什么类型的事件"，分级回答"这个事件有多严重"。二者共同决定了响应手册的选择和资源的投入程度。一个好的分类分级体系应具备以下特征：分类覆盖全面但不过于细碎、分级标准可量化且易操作、支持动态调级、与 SLA 和升级机制深度集成、满足内外部合规要求。建议组织在 NIST/VERIS 等国际标准的基础上，结合自身业务特征和合规环境进行定制化适配。
