SIEM 与日志分析方法

概述

安全信息和事件管理（SIEM — Security Information and Event Management）是现代安全运营中心（SOC）的核心基础设施。SIEM 平台通过聚合来自网络设备、服务器、终端、应用和安全工具的日志数据，运用关联分析、行为基线和统计模型识别安全威胁。在事件响应的检测与分析阶段，SIEM 日志分析是确认事件、界定范围和追踪攻击路径的首要手段。

本文系统介绍 SIEM 平台的架构原理、日志采集策略、关联分析方法以及面向事件响应的高级分析技术，帮助安全分析师提升从海量日志中发现威胁的能力。

Sigma 规则标准


Sigma 是 SIEM 检测规则的开放标准，类似于 Snort 之于网络入侵检测。一条 Sigma 规则示例：


title: 可疑的 PowerShell 下载行为
status: stable
logsource:
  category: process_creation
  product: windows
detection:
  selection:
    CommandLine|contains|all:
      - 'powershell'
      - 'downloadstring'
  condition: selection
level: high
tags:
  - attack.execution
  - attack.t1059.001
Sigma 规则可以通过转换工具自动转化为 Splunk SPL、Elastic Query DSL、Microsoft KQL 等各平台原生查询语言。截至 2025 年，SigmaHQ 社区维护了超过 3000 条经过验证的检测规则。

事件响应中的日志分析实践
攻击链还原方法
在事件调查中，分析师需要从日志中还原完整的攻击链。推荐采用时间轴分析法：


    

  1. 锚定初始指标（Pivot Point）：从已知的 IoC（恶意 IP、恶意哈希、受害主机）出发
    2. 

  2. 时间窗口展开：以锚点时间为中心，向前后各扩展 24-72 小时
    3. 

  3. 跨源关联：在该时间窗口内关联所有相关数据源的日志
    4. 

  4. 攻击链映射：将发现的事件按 MITRE ATT&CK 战术阶段排列
    5. 

  5. 补充调查：对缺失的阶段进行针对性搜索
    6. 



Splunk SPL 攻击链查询示例


index=firewall OR index=proxy OR index=auth
earliest=-72h latest=+24h
(src_ip="192.168.1.100" OR dest_ip="192.168.1.100"
 OR user="compromised_user" OR dest_ip="203.0.113.50")
| eval event_type=case(
    index="firewall", "网络",
    index="proxy", "代理",
    index="auth", "认证")
| sort _time
| table _time event_type src_ip dest_ip user action url bytes

总结
SIEM 与日志分析是事件响应检测和分析阶段的核心能力。建设高效的 SIEM 运营体系需要关注三个层面：数据层确保关键日志源的完整采集和标准化；分析层通过规则关联、UEBA 和威胁情报集成实现多维度检测；运营层通过告警调优、威胁狩猎和自动化持续提升分析效率。在日志量持续增长的背景下，结合 AI/ML 能力的下一代 SIEM 正在成为趋势，但核心分析思维和方法论——时间轴分析、攻击链还原、跨源关联——仍然是安全分析师最重要的基本功。
