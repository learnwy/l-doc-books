通信协议实现

FPGA 在通信协议实现中扮演着不可替代的角色：从低速串行接口（UART/SPI/I2C）到高速 SerDes 协议（PCIe/以太网/光纤通道），FPGA 能够以硬件时序精度实现协议的每一层细节。本文从基础串行协议入手，逐步讲解到高速通信协议的 FPGA 实现方法。

UART 接收器设计
UART 接收的核心挑战是在没有时钟信号的情况下准确采样数据位。标准方法是使用 16 倍过采样：


关键设计要点：


    

  • 16 倍波特率的采样时钟：如 9600 baud 需要 153,600 Hz 采样时钟
    • 

  • 起始位中心对齐：检测到下降沿后等待 8 个采样时钟再确认
    • 

  • 数据位中心采样：每 16 个采样时钟取第 8 个点的值
    • 

  • 多数表决：对中心附近 3-5 个采样点取多数值，抗噪声
    • 



波特率生成
// 波特率分频器：从 100 MHz 生成 16× 采样时钟
// 9600 baud × 16 = 153600 Hz
// 100_000_000 / 153600 ≈ 651
localparam BAUD_DIV = 651;

reg [9:0] baud_cnt;
reg       baud_tick;

always @(posedge clk) begin
    if (rst || baud_cnt == BAUD_DIV - 1) begin
        baud_cnt  <= 0;
        baud_tick <= 1'b1;
    end else begin
        baud_cnt  <= baud_cnt + 1;
        baud_tick <= 1'b0;
    end
end

FPGA 实现 I2C 的挑战
    

  1. 开漏输出：SDA 和 SCL 都是开漏/开集电极，FPGA 需要通过三态缓冲器实现
    2. 

  2. 时钟拉伸：从设备可以拉低 SCL 暂停通信，主机必须检测
    3. 

  3. 仲裁：多主机环境下需要监听 SDA 确认自己是否丢失仲裁
    4. 

  4. 毛刺过滤：50 ns 以下的脉冲应被忽略（I2C 规范要求）
    5. 



// I2C 三态控制
assign sda = sda_oe ? 1'b0 : 1'bz;  // 开漏：只能拉低或释放
assign scl = scl_oe ? 1'b0 : 1'bz;

// 读取总线实际状态（含外部上拉后的电平）
wire sda_in = sda;
wire scl_in = scl;

编码的核心目的：


    

  • DC 平衡：确保传输信号没有直流分量，支持 AC 耦合
    • 

  • 跳变密度：保证足够的信号跳变以供接收端时钟恢复（CDR）
    • 

  • 帧定界：通过控制字符标识帧边界
    • 



以太网 MAC 层实现
MAC 层发送引擎的核心功能：


    

  • 插入 7 字节前导码（Preamble）和 1 字节帧起始定界符（SFD）
    • 

  • 附加源/目的 MAC 地址和以太类型/长度字段
    • 

  • 计算并附加 4 字节 CRC-32（FCS）
    • 

  • 维护最小帧长度（64 字节）：短帧自动填充
    • 

  • 帧间间隔（IFG）控制：最小 12 字节间隔
    •

通信协议的 FPGA 实现要求对协议规范的精确理解和对硬件时序的严格把控。现代 FPGA 厂商提供了丰富的协议 IP 核（如 Xilinx 的 AXI Ethernet、PCIe IP），工程实践中应优先使用验证过的 IP，仅在定制化需求时才从底层实现。
