仿真与时序分析

仿真和时序分析是验证 FPGA 设计正确性的两大核心手段。仿真验证逻辑功能是否符合预期（"做的对不对"），时序分析验证电路在目标频率下能否稳定工作（"跑得快不快"）。本文系统介绍功能仿真、时序仿真和静态时序分析（STA）的原理与实践方法。

功能仿真
Testbench 基本结构
`timescale 1ns / 1ps

module tb_counter;

// 信号声明
reg         clk;
reg         rst;
wire [7:0]  count;
wire        overflow;

// 被测模块例化
counter_8bit uut (
    .clk      (clk),
    .rst      (rst),
    .count    (count),
    .overflow (overflow)
);

// 时钟生成：100 MHz
initial clk = 0;
always #5 clk = ~clk;  // 周期 10 ns

// 激励序列
initial begin
    rst = 1;
    #100;           // 复位保持 100 ns
    rst = 0;
    #3000;          // 运行 3000 ns
    $finish;
end

// 结果检查
always @(posedge clk) begin
    if (!rst && count === 8'hFF && !overflow)
        $display("ERROR: overflow not asserted at count=0xFF, time=%0t", $time);
end

// 波形导出
initial begin
    $dumpfile("counter.vcd");
    $dumpvars(0, tb_counter);
end

endmodule

静态时序分析（STA）
STA 基本原理
STA 不需要测试激励，而是通过穷举所有时序路径来验证设计是否满足时序约束。它基于以下概念：


建立时间与保持时间




参数
定义
约束含义





建立时间 TsuT_{su}Tsu​
数据必须在时钟有效沿之前稳定的最小时间
限制最高工作频率




保持时间 ThT_hTh​
数据必须在时钟有效沿之后继续保持的最小时间
与频率无关，由最短路径决定





建立时间检查：


Tclk>Tcq+Tlogic+Trouting+Tsu−TskewT_{clk} > T_{cq} + T_{logic} + T_{routing} + T_{su} - T_{skew}Tclk​>Tcq​+Tlogic​+Trouting​+Tsu​−Tskew​
其中：


    

  • TclkT_{clk}Tclk​：时钟周期
    • 

  • TcqT_{cq}Tcq​：触发器时钟到输出延迟
    • 

  • TlogicT_{logic}Tlogic​：组合逻辑延迟
    • 

  • TroutingT_{routing}Trouting​：互联延迟
    • 

  • TsuT_{su}Tsu​：目标触发器建立时间
    • 

  • TskewT_{skew}Tskew​：时钟偏差（可正可负）
    • 



Slack（裕量）：


Slack=Tclk−(Tcq+Tlogic+Trouting+Tsu−Tskew)Slack = T_{clk} - (T_{cq} + T_{logic} + T_{routing} + T_{su} - T_{skew})Slack=Tclk​−(Tcq​+Tlogic​+Trouting​+Tsu​−Tskew​)
    

  • Slack > 0：满足时序
    • 

  • Slack = 0：临界
    • 

  • Slack < 0：时序违例
    •

完整的验证策略应当两者结合：先通过功能仿真确保逻辑正确，再通过 STA 确保在目标频率下可靠工作。对于关键路径，时序仿真（后仿）可以提供带有真实延迟的波形级验证，确认 STA 报告的违例是否真正影响功能。
