LSP 协议详解

核心概念

语言服务器协议（Language Server Protocol，LSP）是由微软提出的一种开放协议，用于将编程语言的智能特性（代码补全、跳转定义、错误诊断等）与编辑器解耦。在 LSP 出现之前，每个编辑器都需要为每种语言单独实现智能特性，形成 M×N 的组合爆炸。LSP 将问题简化为 M+N：语言实现方只需编写一个语言服务器，编辑器只需实现一个 LSP 客户端。

通信模型与消息格式
LSP 基于 JSON-RPC 2.0 协议进行通信。客户端（编辑器）和服务器之间通过标准输入/输出（stdio）、套接字（socket）或管道（pipe）传输 JSON 消息。


每条消息由 HTTP 风格的头部和 JSON 体组成：


Content-Length: 52\r\n
\r\n
{"jsonrpc":"2.0","method":"initialized","params":{}}
LSP 定义了三种消息类型：


interface RequestMessage {
  jsonrpc: '2.0';
  id: number | string;
  method: string;
  params?: unknown;
}

interface ResponseMessage {
  jsonrpc: '2.0';
  id: number | string;
  result?: unknown;
  error?: { code: number; message: string; data?: unknown };
}

interface NotificationMessage {
  jsonrpc: '2.0';
  method: string;
  params?: unknown;
}

生命周期与能力协商
LSP 连接的生命周期从 initialize 请求开始，到 exit 通知结束。能力协商（Capability Negotiation） 是初始化阶段的核心环节——客户端和服务器分别声明自己支持的特性，双方只使用对方也支持的特性。


interface InitializeParams {
  processId: number | null;
  rootUri: string | null;
  capabilities: ClientCapabilities;
  initializationOptions?: unknown;
  workspaceFolders?: WorkspaceFolder[] | null;
}

interface ClientCapabilities {
  textDocument?: {
    completion?: {
      completionItem?: {
        snippetSupport?: boolean;
        commitCharactersSupport?: boolean;
        documentationFormat?: MarkupKind[];
      };
    };
    hover?: { contentFormat?: MarkupKind[] };
    signatureHelp?: { signatureInformation?: { parameterInformation?: { labelOffsetSupport?: boolean } } };
    definition?: { linkSupport?: boolean };
    codeAction?: { codeActionLiteralSupport?: { codeActionKind?: { valueSet: string[] } } };
  };
  workspace?: {
    workspaceFolders?: boolean;
    configuration?: boolean;
    didChangeWatchedFiles?: { dynamicRegistration?: boolean };
  };
}
服务器返回自己的能力：


interface InitializeResult {
  capabilities: ServerCapabilities;
  serverInfo?: { name: string; version?: string };
}

interface ServerCapabilities {
  textDocumentSync?: TextDocumentSyncOptions | number;
  completionProvider?: CompletionOptions;
  hoverProvider?: boolean;
  definitionProvider?: boolean;
  referencesProvider?: boolean;
  documentFormattingProvider?: boolean;
  codeActionProvider?: boolean | CodeActionOptions;
  diagnosticProvider?: DiagnosticOptions;
}

文档同步模型
LSP 的文档同步确保服务器端始终持有最新的文件内容。同步有两种模式：


全量同步（Full Sync）：每次文件变更时发送完整文件内容。简单但带宽消耗大。


增量同步（Incremental Sync）：只发送变更的部分（插入/删除/替换的文本范围）。高效但实现复杂。


interface DidChangeTextDocumentParams {
  textDocument: VersionedTextDocumentIdentifier;
  contentChanges: TextDocumentContentChangeEvent[];
}

interface TextDocumentContentChangeEvent {
  range?: Range;
  rangeLength?: number;
  text: string;
}
核心请求类型
LSP 定义了数十种请求/通知类型，覆盖了现代 IDE 的所有智能特性：


interface CompletionItem {
  label: string;
  kind?: CompletionItemKind;
  detail?: string;
  documentation?: string | MarkupContent;
  insertText?: string;
  insertTextFormat?: InsertTextFormat;
  textEdit?: TextEdit;
  additionalTextEdits?: TextEdit[];
  filterText?: string;
  sortText?: string;
}

interface Hover {
  contents: MarkupContent | MarkedString;
  range?: Range;
}

interface Location {
  uri: string;
  range: Range;
}

interface Diagnostic {
  range: Range;
  severity?: DiagnosticSeverity;
  code?: number | string;
  source?: string;
  message: string;
  relatedInformation?: DiagnosticRelatedInformation[];
}

小结
    

  • LSP 通过标准化协议将 M×N 的语言-编辑器集成问题简化为 M+N
    • 

  • 基于 JSON-RPC 2.0 的消息格式支持 Request/Response 和 Notification 两种模式
    • 

  • 能力协商机制确保客户端和服务器只使用双方都支持的特性
    • 

  • 文档同步支持全量和增量两种模式，增量模式显著减少通信带宽
    • 

  • LSP 定义了数十种请求类型，覆盖从代码补全到重构的完整 IDE 智能特性
    •
