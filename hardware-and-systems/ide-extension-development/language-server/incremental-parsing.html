增量解析与性能优化

核心概念

语言服务器的性能瓶颈通常在解析和分析环节。每次用户敲击键盘都可能触发一次文档分析，如果每次都进行全量解析，大型文件的响应延迟将无法接受。增量解析（Incremental Parsing）通过只重新解析发生变化的部分来解决这一问题，是构建高性能语言服务器的关键技术。

Tree-sitter 增量解析
Tree-sitter 是 GitHub 开发的一个通用增量解析框架。它将解析过程分为两个阶段：首先用 LR 解析器生成具象语法树（CST），然后在文档变更时通过树差分（Tree Diffing）算法局部更新 CST。


import Parser from 'tree-sitter';
import TypeScript from 'tree-sitter-typescript';

const parser = new Parser();
parser.setLanguage(TypeScript.typescript);

let tree = parser.parse(sourceCode);

function handleEdit(
  startIndex: number,
  oldEndIndex: number,
  newEndIndex: number,
  startPosition: Point,
  oldEndPosition: Point,
  newEndPosition: Point,
  newSource: string,
): void {
  tree.edit({
    startIndex,
    oldEndIndex,
    newEndIndex,
    startPosition,
    oldEndPosition,
    newEndPosition,
  });

  tree = parser.parse(newSource, tree);
}

缓存与记忆化策略
除了增量解析，缓存和记忆化也是优化语言服务器性能的重要手段。


interface AnalysisCache {
  symbolTable: Map<string, SymbolInfo[]>;
  diagnostics: Map<string, Diagnostic[]>;
  completionItems: Map<string, CompletionItem[]>;
  documentVersions: Map<string, number>;
}

class CachedAnalyzer {
  private cache: AnalysisCache = {
    symbolTable: new Map(),
    diagnostics: new Map(),
    completionItems: new Map(),
    documentVersions: new Map(),
  };

  analyze(document: TextDocument): Diagnostic[] {
    const cachedVersion = this.cache.documentVersions.get(document.uri);
    if (cachedVersion === document.version) {
      return this.cache.diagnostics.get(document.uri) ?? [];
    }

    const diagnostics = this.performAnalysis(document);

    this.cache.diagnostics.set(document.uri, diagnostics);
    this.cache.documentVersions.set(document.uri, document.version);

    return diagnostics;
  }

  invalidate(uri: string): void {
    this.cache.symbolTable.delete(uri);
    this.cache.diagnostics.delete(uri);
    this.cache.completionItems.delete(uri);
    this.cache.documentVersions.delete(uri);
  }

  private performAnalysis(document: TextDocument): Diagnostic[] {
    const text = document.getText();
    return runAnalyzer(text);
  }
}

并发请求处理
语言服务器需要处理来自客户端的并发请求，尤其是在用户快速输入时。


class RequestQueue {
  private pending = new Map<
    string,
    {
      resolve: (value: unknown) => void;
      cancel: () => void;
    }
  >();

  async enqueue<T>(key: string, task: (token: CancellationToken) => Promise<T>): Promise<T> {
    const existing = this.pending.get(key);
    if (existing) {
      existing.cancel();
    }

    return new Promise((resolve, reject) => {
      let cancelled = false;
      const token: CancellationToken = {
        isCancellationRequested: false,
        onCancellationRequested: () => {},
      };

      this.pending.set(key, {
        resolve: resolve as (value: unknown) => void,
        cancel: () => {
          cancelled = true;
          token.isCancellationRequested = true;
        },
      });

      task(token)
        .then((result) => {
          if (!cancelled) {
            this.pending.delete(key);
            resolve(result);
          }
        })
        .catch(reject);
    });
  }
}
取消令牌（Cancellation Token） 是 LSP 的内置机制。当客户端发送新的补全请求时，之前的请求会被自动取消：


connection.onCompletion(async (params, token): Promise<CompletionList> => {

多线程与 Worker 策略
对于计算密集型的语言分析，可以使用 Worker 线程避免阻塞主 LSP 通信线程：


import { Worker } from 'worker_threads';

class AnalysisWorkerPool {
  private workers: Worker[] = [];
  private taskQueue: Array<{ data: unknown; resolve: (result: unknown) => void }> = [];
  private idleWorkers: Set<number> = new Set();

  constructor(workerCount: number, scriptPath: string) {
    for (let i = 0; i < workerCount; i++) {
      const worker = new Worker(scriptPath);
      this.workers.push(worker);
      this.idleWorkers.add(i);

      worker.on('message', (result) => {
        this.idleWorkers.add(i);
        this.processQueue();
      });
    }
  }

  async analyze(data: unknown): Promise<unknown> {
    return new Promise((resolve) => {
      this.taskQueue.push({ data, resolve });
      this.processQueue();
    });
  }

  private processQueue(): void {
    if (this.taskQueue.length === 0 || this.idleWorkers.size === 0) return;

    const workerIndex = this.idleWorkers.values().next().value;
    this.idleWorkers.delete(workerIndex);
    const task = this.taskQueue.shift()!;

    this.workers[workerIndex].postMessage(task.data);
  }
}
小结
    

  • 增量解析是大文件性能的关键，Tree-sitter 将每次编辑的解析开销从 O(n) 降至 O(log n)
    • 

  • 多层缓存策略（文档版本、符号表、解析树）减少重复计算
    • 

  • 取消令牌和请求队列确保快速输入时不会积压过期请求
    • 

  • Worker 线程池将计算密集型分析从 LSP 主通信线程分离，避免阻塞
    • 

  • 性能优化应以指标驱动：监控请求延迟、缓存命中率和内存占用
