IntelliJ Platform 基础

核心概念

IntelliJ Platform 是 JetBrains 全系列 IDE 的底层框架，包括 IntelliJ IDEA、WebStorm、PyCharm、GoLand 等产品都构建在这一平台之上。理解 IntelliJ Platform 的架构是开发高质量 JetBrains 插件的基础。

平台采用组件-服务-扩展点三层架构，通过声明式的 plugin.xml 配置文件将插件功能注入到 IDE 运行时。与 VS Code 的事件驱动激活不同，IntelliJ Platform 使用**扩展点（Extension Point）**机制实现插件与宿主之间的解耦。

plugin.xml 与声明式注册
plugin.xml 是 IntelliJ 插件的核心配置文件，等价于 VS Code 的 package.json。它定义了插件的元信息、依赖关系、扩展点注册以及所有声明式配置。


一个典型的 plugin.xml 结构如下：


<idea-plugin>
    <id>com.example.myplugin</id>
    <name>My Plugin</name>
    <version>1.0.0</version>
    <vendor email="dev@example.com" url="https://example.com">Example</vendor>

    <depends>com.intellij.modules.platform</depends>
    <depends>com.intellij.modules.lang</depends>

    <extensions defaultExtensionNs="com.intellij">
        <applicationService
            serviceInterface="com.example.MyService"
            serviceImplementation="com.example.MyServiceImpl"/>
        <projectService
            serviceInterface="com.example.ProjectService"
            serviceImplementation="com.example.ProjectServiceImpl"/>
        <localInspection
            language="JAVA"
            shortName="MyInspection"
            displayName="My Custom Inspection"
            groupName="My Plugin"
            implementationClass="com.example.MyInspection"/>
    </extensions>

    <actions>
        <action id="MyPlugin.Action"
                class="com.example.MyAction"
                text="My Action"
                description="Performs my action">
            <add-to-group group-id="EditorPopupMenu" anchor="last"/>
            <keyboard-shortcut keymap="$default" first-keystroke="ctrl alt M"/>
        </action>
    </actions>
</idea-plugin>
<depends> 标签声明插件对其他模块的依赖。com.intellij.modules.platform 是最基础的平台模块，几乎所有插件都需要依赖它。如果插件需要访问语言相关 API（如 PSI），还需依赖 com.intellij.modules.lang。


<extensions> 标签是核心区域，所有扩展点的注册都在此完成。defaultExtensionNs 指定默认命名空间，避免每个扩展都写完整路径。


Service 体系与作用域
IntelliJ Platform 的 Service 体系是插件状态管理的核心机制。Service 按作用域分为三个层级：Application 级、Project 级和 Module 级。


Application Service 在整个 IDE 生命周期内只有一个实例，适用于全局配置和跨项目共享状态：


@Service
class MyApplicationService {
    private val settings = mutableMapOf<String, String>()

    fun getSetting(key: String): String? = settings[key]
    fun setSetting(key: String, value: String) { settings[key] = value }

    companion object {
        fun getInstance(): MyApplicationService =
            ApplicationManager.getApplication().getService(MyApplicationService::class.java)
    }
}
Project Service 每个打开的项目各有一个实例，适用于项目相关的配置和缓存：


@Service(Service.Level.PROJECT)
class MyProjectService(private val project: Project) {
    private val cache = ConcurrentHashMap<String, Any>()

    fun getProjectName(): String = project.name
    fun getCachedData(key: String): Any? = cache[key]

    companion object {
        fun getInstance(project: Project): MyProjectService =
            project.getService(MyProjectService::class.java)
    }
}
三级 Service 的选择策略如下：


在现代 IntelliJ 插件开发中，轻量级 Service（Light Service）是推荐做法。使用 @Service 注解标记的类无需在 plugin.xml 中显式注册，平台会自动发现并管理其生命周期。


Action 系统与用户交互
Action 是 IntelliJ 插件与用户交互的主要方式。每个 Action 对应一个菜单项、工具栏按钮或键盘快捷键。Action 系统基于 AnAction 抽象类，包含两个核心方法：update() 控制可见性和启用状态，actionPerformed() 执行实际逻辑。


class MyAction : AnAction() {
    override fun update(e: AnActionEvent) {
        val project = e.project
        val editor = e.getData(CommonDataKeys.EDITOR)
        e.presentation.isEnabledAndVisible = project != null && editor != null
    }

    override fun actionPerformed(e: AnActionEvent) {
        val project = e.project ?: return
        val editor = e.getData(CommonDataKeys.EDITOR) ?: return
        val document = editor.document
        val selectionModel = editor.selectionModel

        if (selectionModel.hasSelection()) {
            val selectedText = selectionModel.selectedText ?: return
            WriteCommandAction.runWriteCommandAction(project) {
                document.replaceString(
                    selectionModel.selectionStart,
                    selectionModel.selectionEnd,
                    selectedText.uppercase()
                )
            }
        }
    }

    override fun getActionUpdateThread(): ActionUpdateThread =
        ActionUpdateThread.BGT
}
AnActionEvent 提供了丰富的上下文信息，通过 DataKey 机制可以获取当前编辑器、文件、项目等对象。getActionUpdateThread() 指定 update() 在哪个线程执行——BGT（Background Thread）用于不涉及 UI 的计算，EDT（Event Dispatch Thread）用于需要读取 UI 状态的场景。


Action 还支持分组（ActionGroup），可以创建动态子菜单：


class MyActionGroup : DefaultActionGroup() {
    override fun update(e: AnActionEvent) {
        e.presentation.isPopupGroup = true
    }

    override fun getChildren(e: AnActionEvent?): Array<AnAction> {
        return arrayOf(
            MyAction(),
            Separator(),
            AnotherAction()
        )
    }
}
线程模型与读写锁
IntelliJ Platform 的线程模型是插件开发中最关键的知识之一。平台使用读写锁（Read/Write Lock）保护内存中的数据模型：


    

  • 读操作（Read Action）：可以在任何线程执行，但必须在 ReadAction 上下文中
    • 

  • 写操作（Write Action）：必须在 EDT（Event Dispatch Thread）上执行
    • 

  • UI 操作：必须在 EDT 上执行
    • 



// 读操作 — 后台线程安全读取
ReadAction.run<Throwable> {
    val psiFile = PsiManager.getInstance(project).findFile(virtualFile)
    val classes = PsiTreeUtil.findChildrenOfType(psiFile, PsiClass::class.java)
}

// 非阻塞读操作 — 推荐方式
ReadAction.nonBlocking<List<PsiClass>> {
    val psiFile = PsiManager.getInstance(project).findFile(virtualFile)
    PsiTreeUtil.findChildrenOfType(psiFile, PsiClass::class.java).toList()
}
    .inSmartMode(project)
    .finishOnUiThread(ModalityState.defaultModalityState()) { classes ->
        updateUI(classes)
    }
    .submit(AppExecutorUtil.getAppExecutorService())

// 写操作 — 必须在 EDT
WriteCommandAction.runWriteCommandAction(project) {
    document.setText("new content")
}

ReadAction.nonBlocking 是现代 IntelliJ 插件开发的推荐模式，它允许读操作在后台线程执行，当写操作到来时自动取消并重试，避免了传统 ReadAction.run 可能导致的 UI 冻结问题。


Gradle 构建与项目配置
IntelliJ 插件使用 Gradle 构建系统，配合 gradle-intellij-plugin（现已升级为 IntelliJ Platform Gradle Plugin 2.x）管理依赖、沙箱测试和打包发布。


// build.gradle.kts
plugins {
    id("java")
    id("org.jetbrains.kotlin.jvm") version "1.9.24"
    id("org.jetbrains.intellij.platform") version "2.0.0"
}

repositories {
    mavenCentral()
    intellijPlatform {
        defaultRepositories()
    }
}

dependencies {
    intellijPlatform {
        intellijIdeaCommunity("2024.1")
        bundledPlugin("com.intellij.java")
        instrumentationTools()
    }
}

intellijPlatform {
    pluginConfiguration {
        id = "com.example.myplugin"
        name = "My Plugin"
        version = "1.0.0"
        ideaVersion {
            sinceBuild = "241"
            untilBuild = "242.*"
        }
    }
    sandboxContainer = layout.buildDirectory.dir("idea-sandbox")
}
sinceBuild 和 untilBuild 定义了插件的兼容性范围。241 表示 2024.1 版本，242.* 表示兼容 2024.2 的所有补丁版本。合理设置兼容范围可以避免用户升级 IDE 后插件无法使用。


Gradle 提供了以下关键任务：


./gradlew runIde          # 启动沙箱 IDE 实例进行调试
./gradlew buildPlugin     # 构建插件 ZIP 包
./gradlew verifyPlugin    # 验证插件兼容性
./gradlew publishPlugin   # 发布到 JetBrains Marketplace
./gradlew test            # 运行插件测试
小结
    

  • IntelliJ Platform 采用组件-服务-扩展点三层架构，plugin.xml 是插件的核心配置入口
    • 

  • Service 按作用域分为 Application、Project、Module 三级，轻量级 @Service 注解是推荐的注册方式
    • 

  • Action 系统通过 update() 控制可见性、actionPerformed() 执行逻辑，支持分组和动态子菜单
    • 

  • 线程模型基于读写锁，ReadAction.nonBlocking 是避免 UI 冻结的推荐模式
    • 

  • Gradle 构建系统管理依赖、沙箱测试和发布，sinceBuild/untilBuild 控制版本兼容性
    • 

  • 与 VS Code 相比，IntelliJ Platform 提供更深层的语言集成能力，但学习曲线也更陡峭
    •
