检查与快速修复

核心概念

Inspection（检查）和 QuickFix（快速修复）是 IntelliJ Platform 代码质量保障的核心机制。Inspection 负责发现代码中的潜在问题，QuickFix 提供一键修复方案。两者协同工作，构成了 IDE 实时代码分析的基础。

IntelliJ 的 Inspection 系统与 ESLint 的 Rule 概念类似，但运行在更深层的语义模型上。ESLint 基于 AST 模式匹配，而 IntelliJ Inspection 基于 PSI 树的完整语义信息，可以进行类型推断、控制流分析和跨文件引用检查。

LocalInspectionTool 实现
LocalInspectionTool 是最常用的 Inspection 类型，在用户编辑代码时实时运行。它通过 Visitor 模式遍历当前文件的 PSI 树，发现问题后注册 ProblemDescriptor。


class EmptyCatchBlockInspection : AbstractBaseJavaLocalInspectionTool() {

    override fun buildVisitor(
        holder: ProblemsHolder,
        isOnTheFly: Boolean
    ): PsiElementVisitor {
        return object : JavaElementVisitor() {
            override fun visitCatchSection(section: PsiCatchSection) {
                super.visitCatchSection(section)
                val catchBlock = section.catchBlock ?: return
                val statements = catchBlock.statements

                if (statements.isEmpty()) {
                    holder.registerProblem(
                        section.firstChild,
                        "空的 catch 块会吞掉异常，可能导致难以排查的问题",
                        ProblemHighlightType.WARNING,
                        AddLoggingQuickFix(),
                        RethrowExceptionQuickFix()
                    )
                }
            }
        }
    }
}
ProblemsHolder 是问题收集器，registerProblem() 接受以下参数：


holder.registerProblem(
    element,         // 标记问题的 PSI 元素
    description,     // 问题描述文本
    highlightType,   // 高亮类型（ERROR/WARNING/WEAK_WARNING/INFORMATION）
    *fixes           // 一个或多个 QuickFix
)
Inspection 需要在 plugin.xml 中注册：


<extensions defaultExtensionNs="com.intellij">
    <localInspection
        language="JAVA"
        shortName="EmptyCatchBlock"
        displayName="Empty catch block"
        groupPath="Java,Error handling"
        groupName="Probable bugs"
        enabledByDefault="true"
        level="WARNING"
        implementationClass="com.example.EmptyCatchBlockInspection"/>
</extensions>
groupPath 定义了 Inspection 在设置面板中的分类路径，enabledByDefault 控制是否默认启用，level 指定默认严重级别。


QuickFix 开发模式
QuickFix 继承自 LocalQuickFix 接口，在 applyFix() 方法中执行代码修改。一个好的 QuickFix 应该是幂等的、安全的，并且提供清晰的描述。


class AddLoggingQuickFix : LocalQuickFix {

    override fun getFamilyName(): String = "添加日志记录"

    override fun applyFix(project: Project, descriptor: ProblemDescriptor) {
        val catchSection = descriptor.psiElement.parent as? PsiCatchSection ?: return
        val catchBlock = catchSection.catchBlock ?: return
        val parameter = catchSection.parameter ?: return
        val paramName = parameter.name

        val factory = JavaPsiFacade.getElementFactory(project)
        val logStatement = factory.createStatementFromText(
            "java.util.logging.Logger.getLogger(getClass().getName()).log(" +
                "java.util.logging.Level.SEVERE, \"Caught exception\", $paramName);",
            catchBlock
        )

        WriteCommandAction.runWriteCommandAction(project) {
            catchBlock.add(logStatement)
            JavaCodeStyleManager.getInstance(project)
                .shortenClassReferences(catchBlock)
        }
    }
}

class RethrowExceptionQuickFix : LocalQuickFix {

    override fun getFamilyName(): String = "重新抛出异常"

    override fun applyFix(project: Project, descriptor: ProblemDescriptor) {
        val catchSection = descriptor.psiElement.parent as? PsiCatchSection ?: return
        val catchBlock = catchSection.catchBlock ?: return
        val parameter = catchSection.parameter ?: return

        val factory = JavaPsiFacade.getElementFactory(project)
        val throwStatement = factory.createStatementFromText(
            "throw new RuntimeException(${parameter.name});",
            catchBlock
        )

        WriteCommandAction.runWriteCommandAction(project) {
            catchBlock.add(throwStatement)
        }
    }
}
getFamilyName() 返回的文本显示在 Alt+Enter 意图列表中。当多个 QuickFix 注册在同一问题上时，用户可以选择最适合的修复方案。


高级 QuickFix 还可以使用 预览模式，在应用前显示修改的差异对比：


class MyQuickFix : LocalQuickFix {
    override fun getFamilyName(): String = "我的修复"

    override fun generatePreview(
        project: Project,
        previewDescriptor: ProblemDescriptor
    ): IntentionPreviewInfo {
        applyFix(project, previewDescriptor)
        return IntentionPreviewInfo.DIFF
    }

    override fun applyFix(project: Project, descriptor: ProblemDescriptor) {
        // 实际修改逻辑
    }
}
Intention Action 与对比
除了 Inspection + QuickFix，IntelliJ 还有 Intention Action 机制。两者的关键区别：Inspection 检测问题并提供修复，Intention 提供代码改进建议（代码本身没有问题）。


class ConvertToMultilineStringIntention : PsiElementBaseIntentionAction() {

    override fun getFamilyName(): String = "转换为多行字符串"

    override fun getText(): String = "将字符串拼接转换为文本块"

    override fun isAvailable(
        project: Project,
        editor: Editor?,
        element: PsiElement
    ): Boolean {
        val expression = PsiTreeUtil.getParentOfType(
            element, PsiPolyadicExpression::class.java
        ) ?: return false
        return expression.operationTokenType == JavaTokenType.PLUS &&
               expression.operands.all { it is PsiLiteralExpression }
    }

    override fun invoke(project: Project, editor: Editor?, element: PsiElement) {
        val expression = PsiTreeUtil.getParentOfType(
            element, PsiPolyadicExpression::class.java
        ) ?: return
        val parts = expression.operands
            .filterIsInstance<PsiLiteralExpression>()
            .mapNotNull { it.value as? String }

        val textBlock = "\"\"\"\n${parts.joinToString("\n")}\"\"\""
        val factory = JavaPsiFacade.getElementFactory(project)
        val newExpression = factory.createExpressionFromText(textBlock, expression)

        WriteCommandAction.runWriteCommandAction(project) {
            expression.replace(newExpression)
        }
    }
}

测试 Inspection 与 QuickFix
IntelliJ Platform 提供了完整的测试框架来验证 Inspection 和 QuickFix 的正确性。测试通过对比 测试数据文件 中标记的期望问题位置来验证。


class EmptyCatchBlockInspectionTest : LightJavaCodeInsightFixtureTestCase() {

    override fun getTestDataPath(): String = "src/test/testData/inspections"

    fun testEmptyCatchBlock() {
        myFixture.enableInspections(EmptyCatchBlockInspection::class.java)
        myFixture.configureByFile("EmptyCatchBlock.java")
        myFixture.checkHighlighting(true, false, true)
    }

    fun testQuickFix() {
        myFixture.enableInspections(EmptyCatchBlockInspection::class.java)
        myFixture.configureByFile("EmptyCatchBlockBefore.java")
        val intention = myFixture.findSingleIntention("添加日志记录")
        myFixture.launchAction(intention)
        myFixture.checkResultByFile("EmptyCatchBlockAfter.java")
    }

    fun testNoFalsePositive() {
        myFixture.enableInspections(EmptyCatchBlockInspection::class.java)
        myFixture.configureByFile("NonEmptyCatchBlock.java")
        myFixture.checkHighlighting(true, false, true)
    }
}
测试数据文件使用特殊的 XML 标记来标注期望的问题位置：


// EmptyCatchBlock.java
public class Example {
    public void method() {
        try {
            riskyOperation();
        } <warning descr="空的 catch 块会吞掉异常，可能导致难以排查的问题">catch</warning> (Exception e) {
        }
    }
}
LightJavaCodeInsightFixtureTestCase 提供了轻量级的测试环境，不需要启动完整的 IDE 实例。对于涉及跨文件分析的 Global Inspection 测试，需要使用 JavaCodeInsightFixtureTestCase 并配置多文件测试数据。


小结
    

  • Inspection 分为 Local（实时单文件）、Global（批量跨文件）和 External Annotator（外部工具集成）三种类型
    • 

  • LocalInspectionTool 通过 Visitor 模式遍历 PSI 树，使用 ProblemsHolder 注册发现的问题
    • 

  • QuickFix 在 applyFix() 中修改 PSI 树，支持多修复方案选择和预览模式
    • 

  • Intention Action 与 QuickFix 的区别：前者提供改进建议，后者修复实际问题
    • 

  • 测试框架基于测试数据文件的标记对比机制，支持高亮验证和 Before/After 修复验证
    • 

  • Inspection 的 groupPath 和 level 配置影响用户体验，应合理规划分类和默认严重级别
    •
