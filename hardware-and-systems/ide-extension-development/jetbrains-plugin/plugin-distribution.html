插件打包与分发

核心概念

JetBrains 插件的打包与分发涉及从源代码构建到最终用户安装的完整流程。JetBrains Marketplace 是官方的插件分发平台，为所有 JetBrains IDE（IntelliJ IDEA、WebStorm、PyCharm 等）提供统一的插件生态系统。

与 VS Code 的 vsce 打包工具不同，IntelliJ 插件使用 Gradle 构建系统完成打包，输出格式为包含 lib/ 目录的 ZIP 文件。插件的兼容性管理也更为复杂，需要声明支持的 IDE 产品和版本范围。

插件打包与版本管理
IntelliJ 插件的打包通过 Gradle 完成。IntelliJ Platform Gradle Plugin 2.x 提供了完整的构建生命周期管理：


// build.gradle.kts
plugins {
    id("org.jetbrains.intellij.platform") version "2.0.0"
}

intellijPlatform {
    pluginConfiguration {
        id = "com.example.awesome-plugin"
        name = "Awesome Plugin"
        version = "2.1.0"

        description = """
            <h2>Awesome Plugin for IntelliJ</h2>
            <p>This plugin provides amazing code analysis features.</p>
            <ul>
                <li>Smart code inspection</li>
                <li>One-click refactoring</li>
                <li>Performance profiling integration</li>
            </ul>
        """.trimIndent()

        changeNotes = """
            <h3>2.1.0</h3>
            <ul>
                <li>Added support for Kotlin 2.0</li>
                <li>Fixed false positive in empty catch inspection</li>
                <li>Improved performance for large projects</li>
            </ul>
        """.trimIndent()

        ideaVersion {
            sinceBuild = "241"
            untilBuild = "242.*"
        }

        vendor {
            name = "Example Inc."
            email = "plugins@example.com"
            url = "https://example.com/plugins"
        }
    }

    publishing {
        token = providers.environmentVariable("JETBRAINS_MARKETPLACE_TOKEN")
    }

    pluginVerification {
        ides {
            recommended()
        }
    }
}
版本兼容性是 IntelliJ 插件发布中最容易出错的环节。JetBrains IDE 使用构建号（Build Number）标识版本：

sinceBuild 指定最低兼容版本，untilBuild 指定最高兼容版本。推荐策略是设置 untilBuild 为当前主版本的通配符（如 242.*），在每个新 IDE 版本发布后测试并更新。

Plugin Verifier 与兼容性检查
verifyPlugin 任务使用 IntelliJ Plugin Verifier 工具检查插件的 API 兼容性。它会扫描插件字节码中对 IntelliJ Platform API 的引用，找出已废弃、已移除或不兼容的 API 调用。


pluginVerification {
    ides {
        recommended()
        ide(IntelliJPlatformType.IntellijIdeaCommunity, "2024.1")
        ide(IntelliJPlatformType.IntellijIdeaCommunity, "2024.2")
        ide(IntelliJPlatformType.IntellijIdeaCommunity, "2024.3")
    }

    failureLevel = listOf(
        FailureLevel.COMPATIBILITY_PROBLEMS,
        FailureLevel.MISSING_DEPENDENCIES
    )
}
./gradlew verifyPlugin

处理 API 迁移的常见策略：


// 使用反射兼容多版本
fun getEditorProject(editor: Editor): Project? {
    return try {
        editor.project
    } catch (e: NoSuchMethodError) {
        FileEditorManager.getInstance(editor.project!!).selectedEditor?.file?.let {
            ProjectLocator.getInstance().guessProjectForFile(it)
        }
    }
}

// 使用 @Suppress 标记已知废弃
@Suppress("DEPRECATION")
fun legacyMethod() {
    // 在迁移计划内的废弃 API 调用
}
Marketplace 发布流程
发布到 JetBrains Marketplace 需要完成以下步骤：创建开发者账号、获取 API Token、配置 Gradle 发布任务、提交审核。


首先在 Marketplace 网站获取发布 Token：


# 设置环境变量（CI/CD 中通常存储在 Secret 中）
export JETBRAINS_MARKETPLACE_TOKEN="perm:xxxx-xxxx-xxxx"

# 通过 Gradle 发布
./gradlew publishPlugin
对于 CI/CD 自动发布，推荐使用 GitHub Actions：


name: Publish Plugin

on:
  push:
    tags:
      - 'v*'

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup JDK
        uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '17'

      - name: Setup Gradle
        uses: gradle/actions/setup-gradle@v3

      - name: Build Plugin
        run: ./gradlew buildPlugin

      - name: Verify Plugin
        run: ./gradlew verifyPlugin

      - name: Run Tests
        run: ./gradlew test

      - name: Publish Plugin
        run: ./gradlew publishPlugin
        env:
          JETBRAINS_MARKETPLACE_TOKEN: ${{ secrets.JETBRAINS_MARKETPLACE_TOKEN }}

付费插件与许可证管理
JetBrains Marketplace 支持 Freemium 模式的付费插件。插件可以提供免费试用期，之后需要购买许可证才能继续使用。许可证验证通过 JetBrains 的 License API 实现。


class MyLicenseChecker {
    fun isLicensed(): Boolean {
        val licenseStatus = LicensingFacade.getInstance()
            ?.getConfirmationStamp("com.example.awesome-plugin")
        return licenseStatus != null
    }

    fun getLicenseExpirationDate(): Date? {
        return LicensingFacade.getInstance()
            ?.getLicenseExpirationDate("com.example.awesome-plugin")
    }

    fun showTrialExpiredDialog(project: Project) {
        Messages.showWarningDialog(
            project,
            "Your trial period has expired. Please purchase a license to continue using this plugin.",
            "License Required"
        )
    }
}
在 plugin.xml 中声明付费信息：


<idea-plugin>
    <product-descriptor code="AWESOMEPLUGIN" release-date="20240101" release-version="21"/>
    <!-- code: 产品代码，需在 Marketplace 注册 -->
    <!-- release-date: 首次发布日期 (YYYYMMDD) -->
    <!-- release-version: 主版本号 * 10 (2.1 → 21) -->
</idea-plugin>
付费插件的定价策略在 Marketplace 后台配置，支持年度订阅、月度订阅和永久许可证三种模式。JetBrains 从销售额中收取 5% 的平台费用。


企业内部分发与自定义仓库
对于不适合公开发布的企业内部插件，IntelliJ 支持配置自定义插件仓库（Custom Plugin Repository）。企业可以搭建私有仓库服务，统一管理和分发内部插件。


自定义仓库的最简实现是一个 HTTP 服务器，提供符合 IntelliJ 格式的 XML 插件列表：


<?xml version="1.0" encoding="UTF-8"?>
<plugins>
    <plugin
        id="com.company.internal-tool"
        url="https://plugins.company.com/files/internal-tool-1.2.0.zip"
        version="1.2.0">
        <idea-version since-build="241" until-build="242.*"/>
        <name>Internal Tool</name>
        <description>Company internal development tool</description>
        <vendor>Company Name</vendor>
    </plugin>
    <plugin
        id="com.company.code-standards"
        url="https://plugins.company.com/files/code-standards-3.0.1.zip"
        version="3.0.1">
        <idea-version since-build="241" until-build="243.*"/>
        <name>Code Standards</name>
        <description>Company coding standards enforcement</description>
        <vendor>Company Name</vendor>
    </plugin>
</plugins>
用户在 IDE 中添加自定义仓库：Settings → Plugins → ⚙ → Manage Plugin Repositories → 添加 URL。


对于大型组织，推荐使用 JetBrains Marketplace for Organizations（原 Private Marketplace）服务，提供更完善的访问控制、审计日志和自动更新功能。


企业内部分发的 CI/CD 流程：


name: Internal Plugin Release

on:
  push:
    tags:
      - 'v*'

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build Plugin
        run: ./gradlew buildPlugin

      - name: Verify Plugin
        run: ./gradlew verifyPlugin

      - name: Upload to Internal Repository
        run: |
          VERSION=$(./gradlew properties -q | grep "^version:" | awk '{print $2}')
          ARTIFACT="build/distributions/internal-tool-${VERSION}.zip"
          curl -X PUT \
            -H "Authorization: Bearer ${{ secrets.REPO_TOKEN }}" \
            -F "file=@${ARTIFACT}" \
            "https://plugins.company.com/api/upload"

      - name: Update Plugin Index
        run: |
          curl -X POST \
            -H "Authorization: Bearer ${{ secrets.REPO_TOKEN }}" \
            "https://plugins.company.com/api/reindex"
小结
    

  • IntelliJ 插件使用 Gradle 构建系统打包为 ZIP 格式，IntelliJ Platform Gradle Plugin 2.x 管理完整构建生命周期
    • 

  • 版本兼容性通过 sinceBuild/untilBuild 控制，Plugin Verifier 自动检测 API 兼容性问题
    • 

  • JetBrains Marketplace 提供完善的发布流程，包含安全、兼容性和质量审核
    • 

  • 付费插件通过 LicensingFacade API 验证许可证，支持年度/月度订阅和永久许可证模式
    • 

  • 企业内部分发可使用自定义插件仓库，通过 HTTP 服务器提供 XML 格式的插件列表
    • 

  • CI/CD 自动化是现代插件分发的最佳实践，确保每次发布都经过构建、验证和测试
