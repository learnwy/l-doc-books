PSI 与 AST 操作

核心概念

PSI（Program Structure Interface）是 IntelliJ Platform 的核心语言模型，为所有语言提供统一的程序结构表示。PSI 树建立在 AST（Abstract Syntax Tree）之上，但提供了更丰富的语义信息和更便捷的操作 API。

每个打开的文件在内存中都有对应的 PSI 树。PSI 树的根节点是 PsiFile，叶子节点是 PsiElement。与纯 AST 不同，PSI 树保留了所有源码信息（包括空白和注释），并提供了类型解析、引用查找等语义能力。

PSI 树的结构与遍历
PSI 树是一棵标准的树形结构，每个节点都是 PsiElement 的子类。不同语言有各自的 PSI 元素类型，例如 Java 有 PsiClass、PsiMethod、PsiField，Kotlin 有 KtClass、KtFunction。


遍历 PSI 树有多种方式，最常用的是 PsiTreeUtil 工具类：


val psiFile = PsiManager.getInstance(project).findFile(virtualFile)
    ?: return

val allClasses = PsiTreeUtil.findChildrenOfType(psiFile, PsiClass::class.java)

val parentMethod = PsiTreeUtil.getParentOfType(element, PsiMethod::class.java)

val nextSibling = PsiTreeUtil.skipWhitespacesAndCommentsForward(element)

PsiTreeUtil.processElements(psiFile, PsiMethod::class.java) { method ->
    processMethod(method)
    true
}
也可以使用 Visitor 模式 进行深度遍历，这在需要处理多种节点类型时更加优雅：


psiFile.accept(object : JavaRecursiveElementVisitor() {
    override fun visitMethod(method: PsiMethod) {
        super.visitMethod(method)
        val returnType = method.returnType
        val parameters = method.parameterList.parameters
        val body = method.body
        analyzeMethod(method.name, returnType, parameters, body)
    }

    override fun visitField(field: PsiField) {
        super.visitField(field)
        if (field.hasModifierProperty(PsiModifier.PUBLIC)) {
            reportPublicField(field)
        }
    }

    override fun visitReferenceExpression(expression: PsiReferenceExpression) {
        super.visitReferenceExpression(expression)
        val resolved = expression.resolve()
        if (resolved is PsiField) {
            trackFieldUsage(resolved)
        }
    }
})
PSI 树的一个重要特点是双向导航：每个节点既可以访问子节点，也可以访问父节点和兄弟节点。这使得从任意位置出发的上下文分析成为可能。


PsiReference 与符号解析
PsiReference 是 IntelliJ 实现代码导航、重命名和查找引用等功能的核心机制。一个引用（Reference）连接了使用处和声明处。


class MyReference(
    element: PsiElement,
    rangeInElement: TextRange
) : PsiReferenceBase<PsiElement>(element, rangeInElement) {

    override fun resolve(): PsiElement? {
        val name = element.text.substring(
            rangeInElement.startOffset,
            rangeInElement.endOffset
        )
        return findDeclaration(element.project, name)
    }

    override fun getVariants(): Array<Any> {
        val completionItems = mutableListOf<LookupElement>()
        findAllDeclarations(element.project).forEach { decl ->
            completionItems.add(
                LookupElementBuilder.create(decl.name)
                    .withIcon(decl.getIcon(0))
                    .withTypeText(decl.containingFile?.name)
            )
        }
        return completionItems.toTypedArray()
    }

    private fun findDeclaration(project: Project, name: String): PsiElement? {
        val scope = GlobalSearchScope.projectScope(project)
        return JavaPsiFacade.getInstance(project)
            .findClass(name, scope)
    }
}
resolve() 方法返回引用指向的声明元素，如果解析失败则返回 null（此时 IDE 会显示红色错误波浪线）。getVariants() 返回可能的补全候选项，与代码补全功能直接关联。


引用的注册通过 PsiReferenceContributor 完成：


class MyReferenceContributor : PsiReferenceContributor() {
    override fun registerReferenceProviders(registrar: PsiReferenceRegistrar) {
        registrar.registerReferenceProvider(
            PlatformPatterns.psiElement(PsiLiteralExpression::class.java),
            object : PsiReferenceProvider() {
                override fun getReferencesByElement(
                    element: PsiElement,
                    context: ProcessingContext
                ): Array<PsiReference> {
                    val literal = element as PsiLiteralExpression
                    val value = literal.value as? String ?: return PsiReference.EMPTY_ARRAY
                    if (isMyPattern(value)) {
                        return arrayOf(MyReference(element, TextRange(1, value.length + 1)))
                    }
                    return PsiReference.EMPTY_ARRAY
                }
            }
        )
    }
}
PSI 修改与 Write Action
修改 PSI 树是实现自动重构、代码生成等功能的基础。所有 PSI 修改都必须在 Write Action 中执行，并且应该使用 PsiElementFactory 创建新节点，而不是手动拼接文本。


fun addLogStatement(method: PsiMethod, project: Project) {
    val factory = JavaPsiFacade.getElementFactory(project)

    val logStatement = factory.createStatementFromText(
        "System.out.println(\"Entering ${method.name}\");",
        method
    )

    WriteCommandAction.runWriteCommandAction(project, "Add Log Statement", null, {
        val body = method.body ?: return@runWriteCommandAction
        val firstStatement = body.statements.firstOrNull()
        if (firstStatement != null) {
            body.addBefore(logStatement, firstStatement)
        } else {
            body.add(logStatement)
        }
    }, method.containingFile)
}
PsiElementFactory 可以创建各种语言构件：


val factory = JavaPsiFacade.getElementFactory(project)

val field = factory.createFieldFromText(
    "private final String name;", null
)

val method = factory.createMethodFromText("""
    public String getName() {
        return this.name;
    }
""".trimIndent(), null)

val annotation = factory.createAnnotationFromText(
    "@Override", null
)

val importStatement = factory.createImportStatement(
    JavaPsiFacade.getInstance(project).findClass(
        "java.util.List",
        GlobalSearchScope.allScope(project)
    )!!
)

Stub 索引与性能优化
当项目规模增大时，遍历所有文件的 PSI 树会导致严重的性能问题。IntelliJ 使用 Stub 索引 机制解决这一问题——Stub 是 PSI 树的轻量级序列化版本，只保留结构信息（类名、方法签名等），不保留方法体和注释。


class MyStubElementType(
    debugName: String
) : IStubElementType<MyStub, MyPsiElement>(debugName, MyLanguage) {

    override fun serialize(stub: MyStub, dataStream: StubOutputStream) {
        dataStream.writeName(stub.name)
        dataStream.writeBoolean(stub.isPublic)
    }

    override fun deserialize(dataStream: StubInputStream, parentStub: StubElement<*>): MyStub {
        val name = dataStream.readNameString()
        val isPublic = dataStream.readBoolean()
        return MyStub(parentStub, this, name, isPublic)
    }

    override fun createStub(psi: MyPsiElement, parentStub: StubElement<*>): MyStub {
        return MyStub(parentStub, this, psi.name, psi.isPublic)
    }

    override fun indexStub(stub: MyStub, sink: IndexSink) {
        stub.name?.let { name ->
            sink.occurrence(MyStubIndex.KEY, name)
        }
    }
}
Stub 索引的查询非常高效，因为它直接从序列化数据中读取，不需要解析源文件：


object MyStubIndex : StringStubIndexExtension<MyPsiElement>() {
    val KEY = StubIndexKey.createIndexKey<String, MyPsiElement>("my.stub.index")

    override fun getKey(): StubIndexKey<String, MyPsiElement> = KEY
}

fun findElementByName(project: Project, name: String): Collection<MyPsiElement> {
    return StubIndex.getElements(
        MyStubIndex.KEY,
        name,
        project,
        GlobalSearchScope.projectScope(project),
        MyPsiElement::class.java
    )
}
Stub 索引的核心优势在于延迟加载：只有当真正需要方法体、注释等完整信息时，才会触发文件解析和 PSI 树构建。这使得全项目范围的符号搜索可以在毫秒级完成。


小结
    

  • PSI 是 IntelliJ Platform 的核心语言模型，建立在 AST 之上但提供更丰富的语义信息
    • 

  • PSI 树支持双向导航和 Visitor 模式遍历，PsiTreeUtil 提供常用的查找工具方法
    • 

  • PsiReference 连接使用处与声明处，是代码导航、重命名和补全的基础
    • 

  • PSI 修改必须在 Write Action 中执行，使用 PsiElementFactory 创建新节点
    • 

  • Stub 索引是性能优化的关键，通过轻量级序列化实现全项目范围的快速搜索
    • 

  • 理解 Token → AST → PSI → Stub 的层次关系是掌握 IntelliJ 插件语言支持开发的前提
