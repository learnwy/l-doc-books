Debug Adapter Protocol 详解

核心概念

Debug Adapter Protocol（DAP）是微软提出的调试器标准化协议，设计理念与 LSP 如出一辙——通过在编辑器（前端）和调试器实现（后端）之间引入一层标准化协议，实现调试器的跨编辑器复用。一个实现了 DAP 的调试适配器可以同时被 VS Code、Neovim、Eclipse 等支持 DAP 的编辑器使用。

DAP 与 LSP 的设计对比：

语言智能特性的编辑器复用

自定义 JSON 协议




传输方式
stdio / socket / pipe
stdio / socket




生命周期
长连接（编辑器运行期间）
会话级（调试期间）




状态模型
无状态（文档为单位）
有状态（调试会话）

协议消息模型
DAP 使用与 LSP 类似但不完全相同的 JSON 消息格式。每条消息由 HTTP 风格的头部和 JSON 体组成：


interface ProtocolMessage {
  seq: number;
  type: 'request' | 'response' | 'event';
}

interface Request extends ProtocolMessage {
  type: 'request';
  command: string;
  arguments?: Record<string, unknown>;
}

interface Response extends ProtocolMessage {
  type: 'response';
  request_seq: number;
  success: boolean;
  command: string;
  message?: string;
  body?: Record<string, unknown>;
}

interface Event extends ProtocolMessage {
  type: 'event';
  event: string;
  body?: Record<string, unknown>;
}
DAP 定义了三种消息类型，与 LSP 的 Request/Response/Notification 类似：






类型
方向
说明
示例





Request
Client → Adapter
客户端发起请求
launch, setBreakpoints, continue




Response
Adapter → Client
适配器响应请求
每个 Request 对应一个 Response




Event
Adapter → Client
适配器主动通知
stopped, output, terminated

小结
    

  • DAP 通过标准化协议实现调试器的跨编辑器复用，设计理念与 LSP 一脉相承
    • 

  • 调试会话遵循 initialize → launch/attach → configurationDone → running → stopped → terminated 的状态流转
    • 

  • 客户端通过 threads → stackTrace → scopes → variables 的请求链获取程序停止时的完整状态
    • 

  • Event 机制使适配器能够主动推送程序状态变化，如断点命中、程序输出等
    • 

  • Launch 和 Attach 两种模式覆盖了本地调试和远程调试的需求
    •
