增量分析策略
语言服务器的核心挑战在于如何高效地更新分析结果。每次编辑后重新分析整个项目显然不可接受。


class IncrementalAnalyzer {
  private syntaxTrees: Map<string, SyntaxTree> = new Map();
  private semanticModels: Map<string, SemanticModel> = new Map();
  private dependencyGraph: DependencyGraph = new DependencyGraph();
  private dirtyFiles: Set<string> = new Set();

  onDocumentChange(uri: string, changes: TextDocumentContentChangeEvent[]): void {
    const tree = this.syntaxTrees.get(uri);
    if (tree) {
      this.syntaxTrees.set(uri, tree.applyEdits(changes));
    }

    this.dirtyFiles.add(uri);
    for (const dependent of this.dependencyGraph.getDependents(uri)) {
      this.dirtyFiles.add(dependent);
    }
  }

  getSemanticModel(uri: string): SemanticModel {
    if (this.dirtyFiles.has(uri)) {
      const tree = this.syntaxTrees.get(uri)!;
      const model = this.analyze(tree);
      this.semanticModels.set(uri, model);
      this.dirtyFiles.delete(uri);
    }
    return this.semanticModels.get(uri)!;
  }
}

工作区索引
工作区索引是语言服务器在项目打开时构建的全局知识库，支持跨文件的符号查找和引用。


class SymbolIndex {
  private byName: Map<string, SymbolEntry[]> = new Map();
  private byFile: Map<string, SymbolEntry[]> = new Map();

  addSymbol(entry: SymbolEntry): void {
    const nameEntries = this.byName.get(entry.name) ?? [];
    nameEntries.push(entry);
    this.byName.set(entry.name, nameEntries);
  }

  findByName(query: string): SymbolEntry[] {
    const results: SymbolEntry[] = [];
    for (const [name, entries] of this.byName) {
      if (fuzzyMatch(name, query)) results.push(...entries);
    }
    return results.sort((a, b) => relevanceScore(b, query) - relevanceScore(a, query));
  }

  removeFile(uri: string): void {
    const entries = this.byFile.get(uri) ?? [];
    for (const entry of entries) {
      const nameEntries = this.byName.get(entry.name);
      if (nameEntries) {
        const idx = nameEntries.indexOf(entry);
        if (idx >= 0) nameEntries.splice(idx, 1);
      }
    }
    this.byFile.delete(uri);
  }
}

提示： 索引构建可以分为两个阶段：快速的"骨架索引"（只扫描导出符号）和完整的"深度索引"（解析所有引用关系）。先完成骨架索引让服务器快速可用，后台继续深度索引。






项目模型
语言服务器需要理解项目的配置和结构，例如 TypeScript 的 tsconfig.json 或 Rust 的 Cargo.toml。


class ProjectManager {
  private projects: Map<string, ProjectModel> = new Map();

  async loadProject(rootUri: string): Promise<ProjectModel> {
    const configPath = await findProjectConfig(rootUri);
    const config = await readProjectConfig(configPath);
    const project: ProjectModel = {
      rootUri,
      configPath,
      sourceRoots: resolveSourceRoots(config),
      excludePatterns: config.exclude ?? ['node_modules', 'dist'],
      compilerOptions: config.compilerOptions ?? {},
      dependencies: await resolveDependencies(config),
    };
    this.projects.set(rootUri, project);
    return project;
  }

  getProjectForFile(uri: string): ProjectModel | undefined {
    for (const [root, project] of this.projects) {
      if (uri.startsWith(root)) return project;
    }
    return undefined;
  }
}

配置管理
语言服务器的配置来自多个来源，需要合并为最终的有效配置。


class ConfigManager {
  private defaults: ServerConfig;
  private global: Partial<ServerConfig> = {};
  private perFile: Map<string, Partial<ServerConfig>> = new Map();

  getConfig(uri?: string): ServerConfig {
    let config = deepMerge({ ...this.defaults }, this.global);
    if (uri) {
      const fileConfig = this.perFile.get(uri);
      if (fileConfig) config = deepMerge(config, fileConfig);
    }
    return config;
  }
}

小结
    

  • 语言服务器生命周期分为初始化、索引、就绪和关闭四个阶段，响应时间目标严格。
    • 

  • 增量分析通过脏文件标记和依赖图传播，避免每次编辑都重新分析整个项目。
    • 

  • 工作区索引分"骨架索引"和"深度索引"两阶段构建，让服务器快速可用。
    • 

  • 项目模型理解项目配置文件（tsconfig.json、Cargo.toml 等），提供正确的分析上下文。
    • 

  • 配置管理合并默认值、编辑器设置、项目配置和文件级配置，按优先级层级覆盖。
