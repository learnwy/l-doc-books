Rust Analyzer 模式

Salsa 增量计算框架

rust-analyzer 的核心是基于 Salsa 框架的需求驱动增量计算模型。与传统的"编辑 → 重新分析"模式不同，Salsa 将分析过程建模为一系列相互依赖的查询函数，只在输入变化时自动重新计算受影响的查询。

#[salsa::query_group(SourceDatabaseStorage)]
pub trait SourceDatabase {
    #[salsa::input]
    fn file_text(&self, file_id: FileId) -> Arc<String>;

    fn parse(&self, file_id: FileId) -> Parse<SourceFile>;
}

fn parse(db: &dyn SourceDatabase, file_id: FileId) -> Parse<SourceFile> {
    let text = db.file_text(file_id);
    SourceFile::parse(&text)
}

#[salsa::query_group(DefDatabaseStorage)]
pub trait DefDatabase: SourceDatabase {
    fn file_item_tree(&self, file_id: FileId) -> Arc<ItemTree>;
    fn crate_def_map(&self, krate: CrateId) -> Arc<CrateDefMap>;
}

#[salsa::query_group(HirDatabaseStorage)]
pub trait HirDatabase: DefDatabase {
    fn infer(&self, def: DefWithBodyId) -> Arc<InferenceResult>;
    fn ty(&self, def: TypeOwner) -> Ty;
}

虚拟文件系统（VFS）
rust-analyzer 使用虚拟文件系统（VFS）抽象文件访问，使分析逻辑与实际文件系统解耦。


pub struct Vfs {
  interner: PathInterner,
  data: Vec<Option<Vec<u8>>>,
  changes: Vec<ChangedFile>,
}

impl Vfs {
  pub fn set_file_contents(&mut self, path: VfsPath, contents: Option<Vec<u8>>) {
    let file_id = self.interner.intern(path);
    let change_kind = match (&self.data[file_id.0 as usize], &contents) {
      (None, Some(_)) => ChangeKind::Create,
      (Some(_), None) => ChangeKind::Delete,
      _ => ChangeKind::Modify,
    };
    self.data[file_id.0 as usize] = contents;
    self.changes.push(ChangedFile { file_id, change_kind });
  }
}

请求取消
在快速输入场景中，用户每次按键都会触发新的补全请求，之前的请求应被取消以节省计算资源。


pub struct GlobalState {
  req_queue: ReqQueue,
  task_pool: TaskPool,
}

impl GlobalState {
  fn on_request(&mut self, req: Request) {
    self.req_queue.incoming.register(req.id.clone(), ());
    let snap = self.snapshot();
    let sender = self.task_sender.clone();
    self.task_pool.spawn(move || {
      if snap.is_cancelled() { return Err(Cancelled); }
      let result = handle_request(&snap, &req);
      if snap.is_cancelled() { return Err(Cancelled); }
      sender.send(Task::Response(result))
    });
  }

  fn on_cancel(&mut self, id: RequestId) {
    if self.req_queue.incoming.cancel(&id) {
      self.send(Response::new_err(id, ErrorCode::RequestCancelled as i32, "cancelled".into()));
    }
  }
}

提示： rust-analyzer 的取消机制深度集成到 Salsa 框架中——每个 Salsa 查询都会在开始时自动检查取消标志。这意味着取消可以在任意查询边界生效，无需在业务代码中手动检查。






Chalk 类型推断
rust-analyzer 使用 Chalk 引擎进行类型推断和 trait 求解，Chalk 将 Rust 的类型系统建模为逻辑编程问题。


pub fn infer_body(db: &dyn HirDatabase, def: DefWithBodyId) -> InferenceResult {
  let mut ctx = InferenceContext::new(db, def);
  let body = db.body(def);
  for (pat, ty) in body.params.iter() { ctx.infer_pat(*pat, &ty); }
  let return_ty = ctx.infer_expr(body.body_expr);
  ctx.coerce(&return_ty, &ctx.return_ty());
  ctx.resolve_all()
}

小结
    

  • Salsa 框架将分析建模为需求驱动的查询图，自动追踪依赖并增量重算。
    • 

  • VFS 抽象文件系统访问，批量收集变更后统一应用到 Salsa 数据库。
    • 

  • 请求取消深度集成到 Salsa 中，每个查询边界自动检查取消标志。
    • 

  • Chalk 将 Rust 类型系统建模为逻辑编程问题，通过 Goal/Clause 求解 trait 约束。
    • 

  • 整体架构分为 LSP 前端、语法解析、HIR、名称解析、类型推断五层，Salsa 贯穿所有层。
