DAP 架构

调试适配器协议概述

Debug Adapter Protocol（DAP）是微软在 LSP 成功之后推出的另一个编辑器协议，专注于调试场景。DAP 的核心思想是将调试器（如 GDB、LLDB、Node.js Inspector）与编辑器之间的通信标准化。

interface ProtocolMessage {
  seq: number;
  type: 'request' | 'response' | 'event';
}

interface Request extends ProtocolMessage {
  type: 'request';
  command: string;
  arguments?: object;
}

interface Response extends ProtocolMessage {
  type: 'response';
  request_seq: number;
  success: boolean;
  command: string;
  message?: string;
  body?: object;
}

interface Event extends ProtocolMessage {
  type: 'event';
  event: string;
  body?: object;
}

调试适配器作为中间层
调试适配器（Debug Adapter）充当编辑器与底层调试器之间的翻译层。它将 DAP 请求转换为调试器的原生命令，并将调试器的输出转换为 DAP 事件。


class DebugAdapter {
  handleRequest(request: Request): Response {
    switch (request.command) {
      case 'setBreakpoints':
        return this.handleSetBreakpoints(request);
      case 'continue':
        return this.handleContinue(request);
      case 'next':
        return this.handleNext(request);
      case 'stackTrace':
        return this.handleStackTrace(request);
      case 'variables':
        return this.handleVariables(request);
      default:
        return this.errorResponse(request, `Unknown command: ${request.command}`);
    }
  }
}

Launch vs Attach
DAP 支持两种调试启动模式：launch（启动新进程）和 attach（附加到已有进程）。


interface LaunchRequestArguments {
  program: string;
  args?: string[];
  cwd?: string;
  env?: { [key: string]: string };
  stopOnEntry?: boolean;
  console?: 'internalConsole' | 'integratedTerminal' | 'externalTerminal';
}

interface AttachRequestArguments {
  processId?: number;
  port?: number;
  address?: string;
}

能力协商
DAP 的 initialize 请求类似 LSP，用于客户端和适配器之间交换能力。


interface InitializeRequestArguments {
  clientID?: string;
  clientName?: string;
  adapterID: string;
  locale?: string;
  linesStartAt1?: boolean;
  columnsStartAt1?: boolean;
  pathFormat?: 'path' | 'uri';
  supportsVariableType?: boolean;
  supportsRunInTerminalRequest?: boolean;
  supportsMemoryReferences?: boolean;
}

interface Capabilities {
  supportsConfigurationDoneRequest?: boolean;
  supportsConditionalBreakpoints?: boolean;
  supportsHitConditionalBreakpoints?: boolean;
  supportsLogPoints?: boolean;
  supportsDataBreakpoints?: boolean;
  supportsStepBack?: boolean;
  supportsReadMemoryRequest?: boolean;
  supportsDisassembleRequest?: boolean;
}

小结
    

  • DAP 将调试器实现从编辑器中解耦，调试适配器作为中间翻译层连接两者。
    • 

  • 协议消息分为请求、响应和事件三类，使用 seq/request_seq 进行消息关联。
    • 

  • Launch 模式启动新进程，Attach 模式附加到已有进程，配置通过 launch.json 管理。
    • 

  • 调试会话遵循 initialize → launch/attach → configurationDone → stopped/continued 循环 → terminated 生命周期。
    • 

  • 能力协商通过 initialize 请求完成，linesStartAt1 等参数确保客户端与适配器的坐标系一致。
