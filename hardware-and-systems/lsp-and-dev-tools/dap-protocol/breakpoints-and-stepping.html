断点与单步执行

源码断点

源码断点（Source Breakpoint）是最常用的断点类型，通过文件路径和行号定位暂停位置。

interface SetBreakpointsArguments {
  source: Source;
  breakpoints?: SourceBreakpoint[];
  lines?: number[];
  sourceModified?: boolean;
}

interface SourceBreakpoint {
  line: number;
  column?: number;
  condition?: string;
  hitCondition?: string;
  logMessage?: string;
}

interface Breakpoint {
  id?: number;
  verified: boolean;
  message?: string;
  source?: Source;
  line?: number;
  column?: number;
  endLine?: number;
  endColumn?: number;
}
断点验证状态：






verified
含义
编辑器显示





true
断点已成功设置在目标位置
实心红色圆点




false
断点无法设置（如空行、优化代码）
灰色空心圆点







提示： 设置断点时服务端返回的行号可能与请求的行号不同。例如请求在空行设置断点，运行时会自动调整到最近的可执行行。编辑器应按返回的实际位置显示断点。






函数断点与数据断点
除源码断点外，DAP 还支持函数断点（按函数名暂停）和数据断点（按变量值变化暂停）。


interface SetFunctionBreakpointsArguments {
  breakpoints: FunctionBreakpoint[];
}

interface FunctionBreakpoint {
  name: string;
  condition?: string;
  hitCondition?: string;
}

interface DataBreakpointInfoArguments {
  variablesReference: number;
  name: string;
  frameId?: number;
}

interface SetDataBreakpointsArguments {
  breakpoints: DataBreakpoint[];
}

interface DataBreakpoint {
  dataId: string;
  accessType?: 'read' | 'write' | 'readWrite';
  condition?: string;
  hitCondition?: string;
}

异常断点
异常断点在特定类型的异常抛出时暂停执行，是排查运行时错误的重要手段。


interface SetExceptionBreakpointsArguments {
  filters: string[];
  filterOptions?: ExceptionFilterOptions[];
  exceptionOptions?: ExceptionOptions[];
}

interface ExceptionFilterOptions {
  filterId: string;
  condition?: string;
}

interface ExceptionBreakpointsFilter {
  filter: string;
  label: string;
  description?: string;
  default?: boolean;
  supportsCondition?: boolean;
  conditionDescription?: string;
}

执行控制
当程序在断点处暂停后，用户通过执行控制命令逐步调试代码。


type StepCommand = 'continue' | 'next' | 'stepIn' | 'stepOut' | 'pause' | 'reverseContinue' | 'stepBack';

interface ContinueArguments {
  threadId: number;
  singleThread?: boolean;
}

interface NextArguments {
  threadId: number;
  singleThread?: boolean;
  granularity?: SteppingGranularity;
}

type SteppingGranularity = 'statement' | 'line' | 'instruction';

Stopped 事件
当程序暂停时，适配器发送 stopped 事件通知编辑器暂停原因。


interface StoppedEvent {
  reason: string;
  description?: string;
  threadId?: number;
  preserveFocusHint?: boolean;
  text?: string;
  allThreadsStopped?: boolean;
  hitBreakpointIds?: number[];
}

说明

提示： allThreadsStopped 表示所有线程都已暂停（全停模式），部分调试器支持仅暂停触发断点的线程而其他线程继续执行。






小结
    

  • DAP 支持源码断点、函数断点、数据断点、异常断点和指令断点五种断点类型。
    • 

  • 断点设置后服务端返回 verified 状态和实际行号，编辑器应按实际位置显示。
    • 

  • 执行控制包括 Continue/Step Over/Step Into/Step Out/Pause 五种基本操作。
    • 

  • Stopped 事件通过 reason 字段告知编辑器暂停原因，触发调用栈和变量面板的自动更新。
    • 

  • 步进粒度支持 statement（语句）、line（行）和 instruction（指令）三种级别。
    •
