Tree-sitter 架构

增量 GLR 解析器

Tree-sitter 的核心创新在于增量解析——当用户编辑代码时，解析器不需要重新解析整个文件，只需更新受影响的语法树部分。这使得即使在百万行的文件中，解析也能在毫秒级完成。

interface Parser {
  setLanguage(language: Language): void;
  parse(input: string | Input, oldTree?: Tree): Tree;
  reset(): void;
  getLanguage(): Language;
  setTimeoutMicros(timeout: number): void;
}

interface Input {
  (index: number, position: Point): string;
}

interface Point {
  row: number;
  column: number;
}
增量解析的关键步骤：






步骤
操作





编辑通知
调用 tree.edit() 告知语法树编辑位置和内容




失效标记
解析器标记受编辑影响的节点为"脏"节点




增量重解析
仅重新解析脏节点及其受影响的祖先节点




树复用
未受影响的节点直接从旧树复用







提示： GLR（Generalized LR）解析算法可以处理有歧义的语法，它维护多个并行的解析状态，在遇到歧义时同时探索所有可能的分支。






CST 表示
Tree-sitter 生成具体语法树（Concrete Syntax Tree），与 AST 不同，CST 保留了源代码的所有语法细节，包括注释、空白和标点符号。


interface SyntaxNode {
  type: string;
  text: string;
  startPosition: Point;
  endPosition: Point;
  startIndex: number;
  endIndex: number;
  parent: SyntaxNode | null;
  children: SyntaxNode[];
  namedChildren: SyntaxNode[];
  childCount: number;
  namedChildCount: number;
  isNamed: boolean;
  isMissing: boolean;
  hasError: boolean;
}

树查询（S 表达式模式）
Tree-sitter 提供了强大的查询语言，使用 S 表达式模式匹配语法树中的节点。


interface Query {
  captureNames: string[];
  matchLimit: number;
  matches(node: SyntaxNode, options?: QueryOptions): QueryMatch[];
  captures(node: SyntaxNode, options?: QueryOptions): QueryCapture[];
}

interface QueryMatch {
  pattern: number;
  captures: QueryCapture[];
}

interface QueryCapture {
  name: string;
  node: SyntaxNode;
}
查询语法示例：


; 匹配函数声明并捕获函数名
(function_declaration
  name: (identifier) @function.name
  body: (statement_block) @function.body)

; 匹配所有字符串字面量
(string) @string

; 匹配方法调用
(call_expression
  function: (member_expression
    object: (identifier) @object
    property: (property_identifier) @method))

; 匹配 if-else 语句
(if_statement
  condition: (_) @condition
  consequence: (_) @then
  alternative: (_)? @else)

提示： Tree-sitter 查询的性能非常好，因为它在编译查询时就优化了匹配路径。单个查询可以包含多个模式，一次遍历即可完成所有匹配。






语言绑定
Tree-sitter 的核心是 C 语言库，但提供了多种语言的绑定。


import Parser from 'tree-sitter';
import TypeScript from 'tree-sitter-typescript';

const parser = new Parser();
parser.setLanguage(TypeScript.typescript);
const tree = parser.parse('function greet(name: string): string { return "Hello, " + name; }');
console.log(tree.rootNode.toString());
use tree_sitter::{Parser, Language};
extern "C" { fn tree_sitter_typescript() -> Language; }

fn main() {
    let mut parser = Parser::new();
    parser.set_language(unsafe { tree_sitter_typescript() }).unwrap();
    let tree = parser.parse("function greet() { return 'hello'; }", None).unwrap();
    println!("{}", tree.root_node().to_sexp());
}

错误恢复
Tree-sitter 的一个核心特性是强大的错误恢复能力。即使源代码包含语法错误，解析器仍能生成有用的语法树。


const incompleteCode = `
function greet(name: string) {
  if (name) {
    console.log("Hello, " + name)

}
`;

const tree = parser.parse(incompleteCode);
const root = tree.rootNode;

function findErrors(node: SyntaxNode): void {
  if (node.hasError) {
    if (node.isMissing) {
      console.log(`Missing: ${node.type} at ${node.startPosition.row}:${node.startPosition.column}`);
    } else if (node.type === 'ERROR') {
      console.log(`Error: unexpected content at ${node.startPosition.row}:${node.startPosition.column}`);
    }
  }
  for (const child of node.children) {
    findErrors(child);
  }
}

提示： 错误恢复是编辑器场景的核心需求——用户在编辑过程中代码几乎总是处于"不完整"状态。Tree-sitter 在错误节点周围仍能提供准确的语法高亮和代码折叠。






小结
    

  • Tree-sitter 是增量 GLR 解析器，编辑后仅重新解析受影响的节点，实现毫秒级更新。
    • 

  • 生成 CST（具体语法树），保留标点、注释等所有语法细节，通过 isNamed 区分语义节点。
    • 

  • S 表达式查询语言支持模式匹配和捕获，配合谓词实现精确的节点过滤。
    • 

  • 核心库为 C 语言实现，提供 Node.js/Rust/WASM/Python/Go 等多语言绑定。
    • 

  • 错误恢复能力确保不完整代码仍能生成有用的语法树，这是编辑器场景的核心需求。
    •
