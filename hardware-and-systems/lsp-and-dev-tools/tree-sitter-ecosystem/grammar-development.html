语法开发

Tree-sitter CLI

Tree-sitter 提供了完整的命令行工具链，用于创建、测试和发布语法定义。

{
  "name": "tree-sitter-mylang",
  "version": "0.1.0",
  "main": "bindings/node",
  "types": "bindings/node/index.d.ts",
  "scripts": {
    "build": "tree-sitter generate && node-gyp build",
    "test": "tree-sitter test",
    "parse": "tree-sitter parse examples/sample.mylang"
  },
  "tree-sitter": [
    {
      "scope": "source.mylang",
      "file-types": ["mylang", "ml"],
      "highlights": "queries/highlights.scm",
      "injections": "queries/injections.scm"
    }
  ],
  "dependencies": {
    "nan": "^2.17.0"
  }
}

CLI 核心命令：

命令 功能
tree-sitter init 初始化新的语法项目骨架
tree-sitter generate 从 grammar.js 生成解析器 C 代码
tree-sitter test 运行测试用例（corpus 目录）
tree-sitter parse 解析文件并输出 S 表达式
tree-sitter highlight 使用 queries 高亮代码
tree-sitter playground 启动交互式 Web Playground
tree-sitter build-wasm 编译为 WASM 格式
tree-sitter query 在文件上执行查询 


提示： tree-sitter generate 从 grammar.js 生成约 10 万行的 C 代码。这个文件是自动生成的，不应手动编辑。






grammar.js DSL
语法定义使用 JavaScript DSL 编写，Tree-sitter 将其编译为 LR 解析表。


module.exports = grammar({
  name: 'mylang',
  extras: ($) => [/\s/, $.comment],
  rules: {
    program: ($) => repeat($._statement),
    _statement: ($) =>
      choice(
        $.variable_declaration,
        $.function_declaration,
        $.expression_statement,
        $.if_statement,
        $.return_statement,
      ),

    variable_declaration: ($) =>
      seq(
        choice('let', 'const', 'var'),
        field('name', $.identifier),
        optional(seq(':', field('type', $._type))),
        optional(seq('=', field('value', $._expression))),
        ';',
      ),

    function_declaration: ($) =>
      seq(
        'function',
        field('name', $.identifier),
        field('parameters', $.formal_parameters),
        optional(seq(':', field('return_type', $._type))),
        field('body', $.block),
      ),

    formal_parameters: ($) => seq('(', commaSep($.parameter), ')'),
    parameter: ($) => seq(field('name', $.identifier), optional(seq(':', field('type', $._type)))),

    if_statement: ($) =>
      prec.right(
        seq(
          'if',
          '(',
          field('condition', $._expression),
          ')',
          field('consequence', $._statement),
          optional(seq('else', field('alternative', $._statement))),
        ),
      ),

    return_statement: ($) => seq('return', optional($._expression), ';'),
    expression_statement: ($) => seq($._expression, ';'),
    block: ($) => seq('{', repeat($._statement), '}'),
    identifier: ($) => /[a-zA-Z_]\w*/,
    number: ($) => /\d+(\.\d+)?/,
    string: ($) => /"[^"]*"/,
    comment: ($) => token(choice(seq('//', /.*/), seq('/*', /[^*]*\*+([^/*][^*]*\*+)*/, '/'))),

    _type: ($) => choice($.identifier, $.generic_type),
    generic_type: ($) => seq($.identifier, '<', commaSep1($._type), '>'),

    _expression: ($) =>
      choice($.identifier, $.number, $.string, $.binary_expression, $.call_expression, $.parenthesized_expression),

    binary_expression: ($) =>
      choice(
        ...[
          ['+', 1],
          ['-', 1],
          ['*', 2],
          ['/', 2],
          ['==', 0],
          ['!=', 0],
        ].map(([op, p]) => prec.left(p as number, seq($._expression, op as string, $._expression))),
      ),

    call_expression: ($) => prec(3, seq(field('function', $._expression), '(', commaSep($._expression), ')')),
    parenthesized_expression: ($) => seq('(', $._expression, ')'),
  },
});

外部扫描器
某些语法结构（如 Python 缩进、字符串插值、heredoc）无法用上下文无关文法表达，需要外部扫描器处理。


module.exports = grammar({
  name: 'mylang',
  externals: ($) => [$.indent, $.dedent, $.newline, $.string_content, $.template_start, $.template_end],
  rules: {
    block: ($) => seq($.indent, repeat1($._statement), $.dedent),
  },
});
外部扫描器用 C 语言实现，需要提供 create、destroy、scan、serialize、deserialize 五个函数：


#include "tree_sitter/parser.h"

enum TokenType { INDENT, DEDENT, NEWLINE };

typedef struct { int indent_stack[100]; int indent_depth; } Scanner;

void *tree_sitter_mylang_external_scanner_create() {
  return calloc(1, sizeof(Scanner));
}

bool tree_sitter_mylang_external_scanner_scan(
  void *payload, TSLexer *lexer, const bool *valid_symbols
) {
  Scanner *scanner = (Scanner *)payload;
  if (valid_symbols[NEWLINE] && lexer->lookahead == '\n') {
    lexer->advance(lexer, false);
    lexer->result_symbol = NEWLINE;
    return true;
  }
  return false;
}

提示： 外部扫描器是 Tree-sitter 最复杂的部分。设计时应确保 serialize/deserialize 正确保存状态，否则增量解析会产生错误。






冲突解决
当语法存在歧义时，Tree-sitter 使用优先级和冲突声明来解决。


module.exports = grammar({
  name: 'mylang',

  conflicts: ($) => [
    [$._expression, $.type_identifier],
    [$.call_expression, $.generic_type],
  ],

  rules: {
    _expression: ($) =>
      prec(
        1,
        choice(
          $.identifier,
          prec.left(1, $.binary_expression),
          prec(2, $.call_expression),
          prec(3, $.member_expression),
        ),
      ),

    binary_expression: ($) =>
      choice(
        prec.left(1, seq($._expression, '+', $._expression)),
        prec.left(1, seq($._expression, '-', $._expression)),
        prec.left(2, seq($._expression, '*', $._expression)),
        prec.left(2, seq($._expression, '/', $._expression)),
      ),
  },
});




冲突解决机制
用法
说明





prec(n)
设置产生式优先级
数值越大优先级越高




prec.left(n)
左结合优先级
a + b + c → (a+b)+c




prec.right(n)
右结合优先级
a = b = c → a=(b=c)




prec.dynamic(n)
GLR 运行时优先级
延迟到解析时决定




conflicts
声明允许的冲突对
GLR 同时探索所有分支







测试
Tree-sitter 使用 corpus 目录中的测试文件验证语法正确性。每个测试由名称、源代码和期望的 S 表达式组成：


==================
Variable Declaration
==================

let x = 42;
const y: string = "hello";

---

(program
  (variable_declaration
    name: (identifier)
    value: (number))
  (variable_declaration
    name: (identifier)
    type: (identifier)
    value: (string)))


提示： 测试文件中的 S 表达式只需匹配命名节点（named nodes）。匿名节点如标点符号和关键字会被自动忽略，这使得测试更简洁。






小结
    

  • tree-sitter CLI 提供 generate、test、parse、build-wasm 等核心命令，覆盖语法开发全流程。
    • 

  • grammar.js DSL 使用 seq/choice/repeat/optional 组合子定义语法，field() 为节点命名。
    • 

  • 外部扫描器处理上下文无关文法无法表达的语法结构（缩进、插值等），用 C 语言实现。
    • 

  • 冲突解决通过 prec/prec.left/prec.right 设置优先级和结合性，conflicts 声明允许 GLR 探索歧义。
    • 

  • corpus 测试通过 S 表达式匹配验证语法正确性，只需匹配命名节点。
    •
