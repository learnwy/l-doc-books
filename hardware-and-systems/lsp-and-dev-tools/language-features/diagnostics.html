Part IV · 编辑器与编译器LSP 与开发工具协议 简介语言特性 简介诊断

诊断

推送模式（publishDiagnostics）

诊断是语言服务器向编辑器报告错误、警告和提示的核心机制。传统的推送模式中，服务端在分析完成后主动向客户端推送诊断结果。

interface PublishDiagnosticsParams {
  uri: string;
  version?: number;
  diagnostics: Diagnostic[];
}

interface Diagnostic {
  range: Range;
  severity?: DiagnosticSeverity;
  code?: number | string;
  codeDescription?: CodeDescription;
  source?: string;
  message: string;
  tags?: DiagnosticTag[];
  relatedInformation?: DiagnosticRelatedInformation[];
  data?: unknown;
}

enum DiagnosticSeverity {
  Error = 1,
  Warning = 2,
  Information = 3,
  Hint = 4,
}

提示： 推送模式下，发送空的 diagnostics: [] 数组即表示清除该文档的所有诊断。关闭文档时务必清除。






拉取模式（Diagnostic Pull Model）
LSP 3.17 引入了拉取模式，由客户端按需请求诊断，而非服务端主动推送。拉取模式更适合大型项目和计算密集的诊断。


interface DocumentDiagnosticParams {
  textDocument: TextDocumentIdentifier;
  identifier?: string;
  previousResultId?: string;
}

type DocumentDiagnosticReport = RelatedFullDocumentDiagnosticReport | RelatedUnchangedDocumentDiagnosticReport;

interface FullDocumentDiagnosticReport {
  kind: 'full';
  resultId?: string;
  items: Diagnostic[];
}

interface UnchangedDocumentDiagnosticReport {
  kind: 'unchanged';
  resultId: string;
}

提示： 拉取模式的 resultId 实现了高效的增量更新——如果诊断未变化，服务端只需返回一个字符串标识而非完整列表。






关联信息
复杂的诊断错误往往涉及多个代码位置。relatedInformation 允许诊断项引用其他位置来提供额外上下文。


interface DiagnosticRelatedInformation {
  location: Location;
  message: string;
}

const diagnostic: Diagnostic = {
  range: { start: { line: 10, character: 4 }, end: { line: 10, character: 8 } },
  severity: DiagnosticSeverity.Error,
  source: 'ts',
  message: "Type 'string' is not assignable to type 'number'.",
  relatedInformation: [
    {
      location: {
        uri: 'file:///src/types.ts',
        range: { start: { line: 5, character: 2 }, end: { line: 5, character: 12 } },
      },
      message: "The expected type comes from property 'count' declared here.",
    },
  ],
};

诊断标签
DiagnosticTag 为诊断提供语义化标记，编辑器据此调整渲染方式。


enum DiagnosticTag {
  Unnecessary = 1,
  Deprecated = 2,
}

const unusedImportDiag: Diagnostic = {
  range: { start: { line: 0, character: 0 }, end: { line: 0, character: 30 } },
  severity: DiagnosticSeverity.Hint,
  tags: [DiagnosticTag.Unnecessary],
  source: 'ts',
  message: "'React' is declared but its value is never read.",
};

const deprecatedUsageDiag: Diagnostic = {
  range: { start: { line: 15, character: 2 }, end: { line: 15, character: 12 } },
  severity: DiagnosticSeverity.Hint,
  tags: [DiagnosticTag.Deprecated],
  source: 'ts',
  message: "'oldMethod' is deprecated. Use 'newMethod' instead.",
};

提示： 诊断标签可以与任何严重程度组合使用。即使是 Error 级别的诊断也可以标记为 Deprecated，但实践中 Unnecessary 和 Deprecated 通常搭配 Hint 严重程度。






快速修复联动
诊断与 Code Actions 紧密关联。编辑器在诊断位置显示灯泡图标，点击后执行快速修复。


connection.onCodeAction((params): CodeAction[] => {
  const diagnostics = params.context.diagnostics;
  const actions: CodeAction[] = [];

  for (const diag of diagnostics) {
    if (diag.source === 'ts' && diag.code === 6133) {
      actions.push({
        title: `Remove unused import`,
        kind: CodeActionKind.QuickFix,
        diagnostics: [diag],
        isPreferred: true,
        edit: {
          changes: {
            [params.textDocument.uri]: [{ range: diag.range, newText: '' }],
          },
        },
      });
    }
  }

  return actions;
});




CodeAction 属性
说明





title
显示在菜单中的修复描述




kind
操作类型（quickfix / refactor / source）




diagnostics
此操作修复的诊断列表




isPreferred
是否为首选修复（支持批量应用）




edit
执行的 WorkspaceEdit




command
可选的后续命令







小结
    

  • 推送模式由服务端主动发送诊断，适合小项目和实时反馈场景。
    • 

  • 拉取模式由客户端按需请求，通过 resultId 实现增量更新，适合大型项目。
    • 

  • relatedInformation 为复杂错误提供多位置上下文，帮助开发者理解错误根因。
    • 

  • DiagnosticTag 的 Unnecessary 和 Deprecated 标签让编辑器对未使用代码和废弃 API 提供视觉反馈。
    • 

  • 诊断与 Code Actions 紧密联动，通过 isPreferred 标记支持一键修复和批量修复。
