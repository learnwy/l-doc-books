代码补全

补全触发机制

代码补全是编辑器中使用频率最高的语言特性。LSP 通过 textDocument/completion 请求实现，支持多种触发方式。

interface CompletionParams {
  textDocument: TextDocumentIdentifier;
  position: Position;
  context?: CompletionContext;
}

interface CompletionContext {
  triggerKind: CompletionTriggerKind;
  triggerCharacter?: string;
}

enum CompletionTriggerKind {
  Invoked = 1,
  TriggerCharacter = 2,
  TriggerForIncompleteCompletions = 3,
}




触发方式
triggerKind
说明





手动触发
1 (Invoked)
用户按 Ctrl+Space 等快捷键




触发字符
2
输入 .、/、< 等配置的触发字符




不完整补全续发
3
上次结果标记为 isIncomplete 时继续请求





服务端声明补全能力：


const capabilities: ServerCapabilities = {
  completionProvider: {
    triggerCharacters: ['.', '/', '<', '"', "'", '@'],
    resolveProvider: true,
    workDoneProgress: true,
  },
};


提示： triggerCharacters 应精简，过多的触发字符会导致用户输入时频繁弹出补全菜单，影响体验。






CompletionItem 结构
每个补全项包含丰富的元信息，用于呈现和应用补全。


interface CompletionItem {
  label: string;
  labelDetails?: CompletionItemLabelDetails;
  kind?: CompletionItemKind;
  detail?: string;
  documentation?: string | MarkupContent;
  preselect?: boolean;
  sortText?: string;
  filterText?: string;
  insertText?: string;
  insertTextFormat?: InsertTextFormat;
  textEdit?: TextEdit | InsertReplaceEdit;
  additionalTextEdits?: TextEdit[];
  commitCharacters?: string[];
  command?: Command;
  data?: unknown;
}
关键字段的作用：






字段
用途





label
补全菜单中显示的文本




kind
图标类型（函数、变量、类等）




sortText
排序键（不同于 label 的排序规则）




filterText
过滤键（用户继续输入时的匹配依据）




insertText
实际插入的文本（可与 label 不同）




textEdit
精确的编辑范围和文本




additionalTextEdits
附带的额外编辑（如自动导入语句）




data
服务端自定义数据，用于 resolve 阶段







Resolve 懒加载
计算所有补全项的完整信息（如文档注释、自动导入）成本很高。LSP 支持分两阶段返回补全项。


connection.onCompletion((params): CompletionItem[] => {
  return [
    {
      label: 'useState',
      kind: CompletionItemKind.Function,
      sortText: '0001',
      data: { source: 'react', exportName: 'useState' },
    },
    {
      label: 'useEffect',
      kind: CompletionItemKind.Function,
      sortText: '0002',
      data: { source: 'react', exportName: 'useEffect' },
    },
  ];
});

connection.onCompletionResolve((item): CompletionItem => {
  const { source, exportName } = item.data as { source: string; exportName: string };
  item.documentation = { kind: 'markdown', value: getDocumentation(source, exportName) };
  item.additionalTextEdits = [
    {
      range: { start: { line: 0, character: 0 }, end: { line: 0, character: 0 } },
      newText: `import { ${exportName} } from '${source}';\n`,
    },
  ];
  return item;
});




阶段
返回内容
时间要求





初始请求
label、kind、sortText、data
<100ms




resolve
documentation、additionalEdits
<200ms







Snippet 语法
LSP 的代码片段使用 VS Code snippet 语法，支持占位符、选择、变量等。


enum InsertTextFormat {
  PlainText = 1,
  Snippet = 2,
}
{
  "label": "for loop",
  "insertTextFormat": 2,
  "insertText": "for (let ${1:i} = 0; $1 < ${2:array}.length; $1++) {\n\t$0\n}"
}
Snippet 语法要素：


| 语法                                | 说明                 | 示例                 |
| ----------------------------------- | -------------------- | -------------------- | -------- | ---- | ------------- | --- |
| $1、$2                          | Tab stop（跳转顺序） | func($1, $2)       |
| $0                                | 最终光标位置         | if ($1) {\n\t$0\n} |
| ${1:placeholder}                  | 带默认值的占位符     | ${1:name}          |
| ${1                                | one,two,three        | }                   | 选择列表 | ${1 | const,let,var | }  |
| $TM_FILENAME                      | 内置变量             | 当前文件名           |
| ${TM_FILENAME/(.*)/${1:/upcase}/} | 变量变换             | 文件名转大写         |




提示： snippet 中的 $ 和 } 是特殊字符，如需插入字面量需要用 \$ 和 \} 转义。






排序与过滤
客户端根据 sortText 和 filterText 对补全项进行排序和过滤，服务端可以精确控制排序优先级。


function createCompletionItems(): CompletionItem[] {
  return [
    {
      label: 'console.log',
      sortText: '0000_console.log',
      filterText: 'console.log log cl',
      kind: CompletionItemKind.Method,
    },
    {
      label: 'console.error',
      sortText: '0001_console.error',
      filterText: 'console.error error ce',
      kind: CompletionItemKind.Method,
    },
    { label: 'const', sortText: '0010_const', kind: CompletionItemKind.Keyword },
  ];
}




字段
默认值
用途





sortText
= label
决定补全列表中的排序位置




filterText
= label
用户输入时用于模糊匹配的文本




preselect
false
是否默认选中此项





排序优先级策略：






优先级
sortText 前缀
适用场景





最高
0000_
最常用的 API、上下文相关推荐




高
0001_
当前作用域内的局部变量




中
0010_
导入的模块成员




低
0100_
关键字、全局对象




最低
1000_
不常用的补全项







自动导入与 Commit 字符
自动导入通过 additionalTextEdits 实现，在补全应用时自动插入 import 语句。Commit 字符允许用户通过特定字符一键确认补全。const completionItem: CompletionItem = { label: 'useState', kind: CompletionItemKind.Function, commitCharacters: ['(', '.'], additionalTextEdits: [ { range: { start: { line: 2, character: 0 }, end: { line: 2, character: 0 } }, newText: "import { useState } from 'react';\n" } ] };



```mermaid
sequenceDiagram
    participant U as 用户
    participant E as 编辑器

    U->>E: 输入 "useSt"
    E->>E: 显示补全：useState
    U->>E: 输入 "(" (commit 字符)
    E->>E: 确认 useState 补全
    E->>E: 插入 "useState("
    E->>E: 在文件顶部插入 import 语句




特性
说明





commitCharacters
输入这些字符时自动确认当前高亮的补全项




常用 commit 字符
(、.、;、,




additionalTextEdits
补全确认后执行的额外编辑（同步应用）




自动导入位置
通常在文件头部的 import 区域







提示： additionalTextEdits 应在 completionItem/resolve 阶段计算，避免为所有补全项预先计算导入路径。






小结
    

  • 补全触发支持手动调用、触发字符和不完整续发三种模式。
    • 

  • CompletionItem 包含丰富的元信息，通过 sortText/filterText 控制排序和过滤行为。
    • 

  • Resolve 懒加载将补全分为两阶段，初始请求快速返回列表，选中时按需加载文档和额外编辑。
    • 

  • LSP 的 snippet 语法支持 Tab stop、占位符、选择列表和变量变换。
    • 

  • 自动导入通过 additionalTextEdits 实现，commit 字符允许用户输入特定字符时一键确认补全。
    •
