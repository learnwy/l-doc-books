代码导航

跳转定义

跳转定义（Go to Definition）是开发者最常用的导航功能。LSP 通过 textDocument/definition 请求实现，返回符号的定义位置。

interface DefinitionParams {
  textDocument: TextDocumentIdentifier;
  position: Position;
}

type DefinitionResult = Location | Location[] | LocationLink[] | null;

interface Location {
  uri: string;
  range: Range;
}

interface LocationLink {
  originSelectionRange?: Range;
  targetUri: string;
  targetRange: Range;
  targetSelectionRange: Range;
}

提示： 优先返回 LocationLink，因为它提供了 targetSelectionRange 用于精确高亮定义的标识符，而非整个声明块。






类型定义与实现
除了基础的跳转定义，LSP 还提供类型定义和实现跳转，在面向对象和接口驱动的代码中尤为有用。


connection.onTypeDefinition((params): Location[] | null => {
  const symbol = findSymbolAt(params.textDocument.uri, params.position);
  if (!symbol) return null;
  const typeDecl = resolveTypeDeclaration(symbol);
  return typeDecl ? [typeDecl.location] : null;
});

connection.onImplementation((params): Location[] | null => {
  const symbol = findSymbolAt(params.textDocument.uri, params.position);
  if (!symbol || symbol.kind !== 'interface') return null;
  return findImplementations(symbol);
});

引用查找
查找引用（Find All References）返回符号在整个项目中被使用的所有位置。


interface ReferenceParams {
  textDocument: TextDocumentIdentifier;
  position: Position;
  context: ReferenceContext;
}

interface ReferenceContext {
  includeDeclaration: boolean;
}

connection.onReferences((params): Location[] => {
  const symbol = findSymbolAt(params.textDocument.uri, params.position);
  if (!symbol) return [];

  const refs = findAllReferences(symbol);
  if (!params.context.includeDeclaration) {
    return refs.filter((r) => !isDeclarationLocation(r, symbol));
  }
  return refs;
});




参数
说明





includeDeclaration
结果中是否包含定义/声明位置




true
返回定义位置 + 所有引用位置




false
仅返回引用位置（不含定义）







提示： 引用查找通常比其他导航请求更耗时，因为需要扫描整个项目。服务端应利用索引加速，并支持请求取消。






文档符号
文档符号提供当前文件的结构化大纲视图（Outline），支持扁平和层级两种格式。


type DocumentSymbolResult = SymbolInformation[] | DocumentSymbol[];

interface DocumentSymbol {

connection.onDocumentSymbol((params): DocumentSymbol[] => {
  const ast = parseDocument(params.textDocument.uri);

调用层级与类型层级
LSP 3.16 引入了调用层级（Call Hierarchy），3.17 引入了类型层级（Type Hierarchy），提供更深层的代码结构导航。


interface CallHierarchyItem {
  name: string;
  kind: SymbolKind;
  tags?: SymbolTag[];
  detail?: string;
  uri: string;
  range: Range;
  selectionRange: Range;
  data?: unknown;
}

connection.onPrepareCallHierarchy((params): CallHierarchyItem[] => {
  const symbol = findSymbolAt(params.textDocument.uri, params.position);
  if (!symbol) return [];
  return [toCallHierarchyItem(symbol)];
});

connection.onCallHierarchyIncomingCalls((params): CallHierarchyIncomingCall[] => {
  return findCallers(params.item);
});

connection.onCallHierarchyOutgoingCalls((params): CallHierarchyOutgoingCall[] => {
  return findCallees(params.item);
});

提示： 调用层级和类型层级都采用"准备 + 逐级展开"的懒加载模式，避免一次性计算整个层级树。






小结
    

  • LSP 提供 definition/typeDefinition/implementation/declaration 四种跳转导航。
    • 

  • LocationLink 比 Location 提供更精确的选择范围，支持更好的 Peek 预览体验。
    • 

  • 引用查找需要全项目扫描，通过 includeDeclaration 参数控制是否包含定义位置。
    • 

  • 文档符号提供文件级的结构化大纲，支持层级（DocumentSymbol）和扁平（SymbolInformation）两种格式。
    • 

  • 调用层级和类型层级采用"准备 + 逐级展开"的懒加载协议，避免一次性计算全部层级关系。
