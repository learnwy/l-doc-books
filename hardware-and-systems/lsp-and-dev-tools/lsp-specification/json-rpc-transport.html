JSON-RPC 传输层

JSON-RPC 2.0 基础

LSP 构建在 JSON-RPC 2.0 协议之上。JSON-RPC 定义了一种无状态、轻量级的远程过程调用协议，使用 JSON 作为数据编码格式。在 LSP 中，每条消息都是一个 JSON-RPC 请求、响应或通知。

interface RequestMessage {
  jsonrpc: '2.0';
  id: number | string;
  method: string;
  params?: object | unknown[];
}

interface ResponseMessage {
  jsonrpc: '2.0';
  id: number | string | null;
  result?: unknown;
  error?: ResponseError;
}

interface NotificationMessage {
  jsonrpc: '2.0';
  method: string;
  params?: object | unknown[];
}

三种消息类型的核心区别在于 id 字段的存在与否：

消息类型 id 字段 是否需要响应 典型用途
请求 必须存在 是 completion、hover
响应 对应请求 — 请求的返回结果
通知 不存在 否 didChange、didSave

提示： 通知不含 id 字段，服务端不应对通知发送响应。违反此约定可能导致协议级错误。

Content-Length 头与消息帧

LSP 在 JSON-RPC 之上定义了自己的消息帧格式。每条消息由头部（Header）和内容（Content）两部分组成，以 \r\n\r\n 分隔。

Content-Length: 52\r\n
\r\n
{"jsonrpc":"2.0","method":"initialized","params":{}}

头部格式遵循 HTTP 头的约定：

type HeaderField = {
  name: 'Content-Length' | 'Content-Type';
  value: string;
};
头字段 是否必须 默认值 说明
Content-Length 是 — 内容体的字节数（UTF-8）
Content-Type 否 application/vscode-jsonrpc; charset=utf-8 MIME 类型

传输通道
LSP 不绑定特定的传输层，支持多种通道实现。不同场景下的最优选择各不相同。


stdin/stdout 传输
最常见的传输方式，编辑器通过子进程的标准输入/输出与语言服务器通信。


import { createConnection, ProposedFeatures } from 'vscode-languageserver/node';

const connection = createConnection(ProposedFeatures.all);

connection.onInitialize((params) => {
  return {
    capabilities: {
      textDocumentSync: 1,
      completionProvider: { resolveProvider: true },
    },
  };
});

connection.listen();
TCP/Socket 传输
适用于远程开发场景或需要多个客户端连接同一语言服务器的情况。


import * as net from 'node:net';

const server = net.createServer((socket) => {
  const connection = createConnection(() => socket, socket);
  connection.listen();
});

server.listen(7000, '127.0.0.1');
WebSocket 传输
用于浏览器环境的语言服务器（如 Monaco Editor、vscode.dev）。


import { WebSocketServer } from 'ws';
import { WebSocketMessageReader, WebSocketMessageWriter } from 'vscode-ws-jsonrpc';

const wss = new WebSocketServer({ port: 3000 });

wss.on('connection', (ws) => {
  const reader = new WebSocketMessageReader(ws);
  const writer = new WebSocketMessageWriter(ws);
  const connection = createConnection(reader, writer);
  connection.listen();
});

消息批处理
JSON-RPC 2.0 支持批量请求，多个请求可以打包在一个 JSON 数组中发送。但 LSP 规范中不推荐使用批处理，主流实现也不支持。


[
  { "jsonrpc": "2.0", "id": 1, "method": "textDocument/completion", "params": {} },
  { "jsonrpc": "2.0", "id": 2, "method": "textDocument/hover", "params": {} }
]

错误处理
JSON-RPC 定义了标准错误码，LSP 在此基础上扩展了语言服务专用错误码。


interface ResponseError {
  code: number;
  message: string;
  data?: unknown;
}

namespace ErrorCodes {
  export const ParseError = -32700;
  export const InvalidRequest = -32600;
  export const MethodNotFound = -32601;
  export const InvalidParams = -32602;
  export const InternalError = -32603;

  export const ServerNotInitialized = -32002;
  export const UnknownErrorCode = -32001;
  export const RequestCancelled = -32800;
  export const ContentModified = -32801;
  export const ServerCancelled = -32802;
  export const RequestFailed = -32803;
}

提示： ContentModified 错误在编辑器快速输入时非常常见。客户端应静默处理此错误而非向用户报错。






小结
    

  • LSP 基于 JSON-RPC 2.0 协议，消息分为请求（含 id）、响应和通知（无 id）三类。
    • 

  • 消息帧由 Content-Length 头和 JSON 内容体组成，以 \r\n\r\n 分隔，Content-Length 计算 UTF-8 字节数。
    • 

  • stdin/stdout 是最常见的传输通道，TCP 和 WebSocket 分别适用于远程开发和浏览器 IDE 场景。
    • 

  • JSON-RPC 批处理在 LSP 中不推荐使用，主流实现均采用单条消息模式。
    • 

  • LSP 在标准 JSON-RPC 错误码基础上扩展了 RequestCancelled、ContentModified 等语言服务专用错误码。
    •
