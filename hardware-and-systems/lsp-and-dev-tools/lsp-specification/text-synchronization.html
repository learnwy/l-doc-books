文本同步

文档生命周期事件

LSP 中的文本同步是编辑器与语言服务器之间最频繁的交互。每当用户打开、编辑或关闭文件时，编辑器通过通知消息将文档状态同步给服务端。

interface DidOpenTextDocumentParams {
  textDocument: TextDocumentItem;
}

interface TextDocumentItem {
  uri: string;
  languageId: string;
  version: number;
  text: string;
}

interface DidCloseTextDocumentParams {
  textDocument: TextDocumentIdentifier;
}

提示： didOpen 发送完整文本内容，此后 didChange 只发送变更部分（增量模式）或完整文本（全量模式），取决于同步策略。






全量同步 vs 增量同步
LSP 定义了两种文本同步策略，通过 textDocumentSync 能力声明。


enum TextDocumentSyncKind {
  None = 0,
  Full = 1,
  Incremental = 2,
}

interface TextDocumentSyncOptions {
  openClose?: boolean;
  change?: TextDocumentSyncKind;
  willSave?: boolean;
  willSaveWaitUntil?: boolean;
  save?: boolean | SaveOptions;
}
全量同步
每次变更发送整个文档内容，实现简单但带宽消耗大。


interface FullDocumentChangeEvent {
  text: string;
}

connection.onDidChangeTextDocument((params) => {
  const fullText = params.contentChanges[0].text;
  documents.set(params.textDocument.uri, fullText);
  validateDocument(params.textDocument.uri);
});
增量同步
只发送变更的范围和新文本，带宽高效但实现复杂。


interface IncrementalChangeEvent {
  range: Range;
  rangeLength?: number;
  text: string;
}

interface Range {
  start: Position;
  end: Position;
}

interface Position {
  line: number;
  character: number;
}

版本号与一致性
每个文档携带单调递增的版本号 version，用于保证客户端与服务端的状态一致性。


interface VersionedTextDocumentIdentifier {
  uri: string;
  version: number;
}

function applyChanges(document: TextDocument, params: DidChangeTextDocumentParams): void {
  if (params.textDocument.version <= document.version) {
    return;
  }

  for (const change of params.contentChanges) {
    if ('range' in change) {
      applyIncrementalChange(document, change);
    } else {
      document.content = change.text;
    }
  }

  document.version = params.textDocument.version;
}
版本号管理规则：






规则
说明





初始值
didOpen 时由客户端设定（通常为 0 或 1）




递增策略
每次 didChange 版本号严格递增




乱序处理
服务端应丢弃版本号小于当前的变更




响应关联
diagnostics 等结果应标注对应的文档版本




过期检测
版本号不匹配时返回 ContentModified 错误







提示： 版本号是 LSP 解决并发编辑冲突的核心机制。服务端在返回诊断或补全结果时应附带文档版本，客户端可据此判断结果是否已过期。






内容变更事件详解
增量同步模式下的变更事件包含精确的编辑位置和替换文本。


interface TextDocumentContentChangeEvent {
  range: Range;
  rangeLength?: number;
  text: string;
}

function applyIncrementalChange(content: string, change: TextDocumentContentChangeEvent): string {
  const startOffset = positionToOffset(content, change.range.start);
  const endOffset = positionToOffset(content, change.range.end);

  return content.substring(0, startOffset) + change.text + content.substring(endOffset);
}

function positionToOffset(content: string, position: Position): number {
  const lines = content.split('\n');
  let offset = 0;
  for (let i = 0; i < position.line; i++) {
    offset += lines[i].length + 1;
  }
  return offset + position.character;
}

小结
    

  • 文本同步是 LSP 中最频繁的交互，涵盖 didOpen/didChange/didSave/didClose 四大事件。
    • 

  • 全量同步实现简单、天然容错；增量同步带宽高效，适合生产环境和大文件场景。
    • 

  • 版本号单调递增，是解决并发编辑冲突和检测结果过期的核心机制。
    • 

  • 增量变更事件通过 range + text 精确描述插入、删除和替换操作。
    • 

  • 位置编码协商（UTF-8/UTF-16/UTF-32）确保客户端和服务端对字符偏移量的计算一致。
