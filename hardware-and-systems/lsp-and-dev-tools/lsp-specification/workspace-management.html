工作区管理

workspaceFolders

现代开发常涉及多根目录工作区（multi-root workspace）。LSP 3.6 引入了 workspaceFolders 能力，允许客户端通知服务端工作区中的所有根文件夹及其变更。

interface WorkspaceFolder {
  uri: string;
  name: string;
}

interface WorkspaceFoldersChangeEvent {
  added: WorkspaceFolder[];
  removed: WorkspaceFolder[];
}
服务端声明对 workspaceFolders 的支持：


const capabilities: ServerCapabilities = {
  workspace: {
    workspaceFolders: {
      supported: true,
      changeNotifications: true,
    },
  },
};

connection.onDidChangeWorkspaceFolders((event) => {
  for (const added of event.added) {
    indexWorkspaceFolder(added.uri);
  }
  for (const removed of event.removed) {
    removeWorkspaceIndex(removed.uri);
  }
});

提示： 始终优先使用 workspaceFolders 而非已废弃的 rootPath。即使只有一个根目录，也应通过 workspaceFolders 传递以保持一致性。






配置管理
LSP 支持双向的配置管理：客户端可以通知服务端配置变更，服务端也可以主动拉取特定配置项。


connection.onDidChangeConfiguration((params) => {
  if (hasConfigurationCapability) {
    documentSettings.clear();
  } else {
    globalSettings = params.settings?.myLanguageServer ?? defaultSettings;
  }
  revalidateAllDocuments();
});

async function getDocumentSettings(resource: string): Promise<LanguageSettings> {
  if (!hasConfigurationCapability) {
    return globalSettings;
  }
  let result = documentSettings.get(resource);
  if (!result) {
    result = await connection.workspace.getConfiguration({
      scopeUri: resource,
      section: 'myLanguageServer',
    });
    documentSettings.set(resource, result);
  }
  return result;
}

按文档/作用域获取配置




混合模式
双向
推送触发 + 拉取获取
推荐的最佳实践







提示： 推荐使用"混合模式"：监听 didChangeConfiguration 通知清除缓存，然后在需要时通过 workspace/configuration 按需拉取。






文件监听
语言服务器经常需要监听工作区内文件系统的变化，例如 tsconfig.json 修改、package.json 依赖变更等。


connection.client.register(DidChangeWatchedFilesNotification.type, {
  watchers: [
    { globPattern: '**/tsconfig*.json' },
    { globPattern: '**/package.json' },
    { globPattern: '**/*.{ts,tsx}' },
  ],
});

connection.onDidChangeWatchedFiles((params) => {
  for (const change of params.changes) {
    switch (change.type) {
      case FileChangeType.Created:
        handleFileCreated(change.uri);
        break;
      case FileChangeType.Changed:
        handleFileChanged(change.uri);
        break;
      case FileChangeType.Deleted:
        handleFileDeleted(change.uri);
        break;
    }
  }
});

工作区编辑
服务端可以通过 workspace/applyEdit 请求让客户端执行跨文件的编辑操作，这是重构、自动修复等功能的基础。


interface WorkspaceEdit {
  changes?: { [uri: string]: TextEdit[] };
  documentChanges?: (TextDocumentEdit | CreateFile | RenameFile | DeleteFile)[];
  changeAnnotations?: { [id: string]: ChangeAnnotation };
}

interface TextEdit {
  range: Range;
  newText: string;
}
interface CreateFile {
  kind: 'create';
  uri: string;
  options?: { overwrite?: boolean };
}
interface RenameFile {
  kind: 'rename';
  oldUri: string;
  newUri: string;
}
interface DeleteFile {
  kind: 'delete';
  uri: string;
  options?: { recursive?: boolean };
}
一个典型的跨文件重命名编辑：


async function renameSymbol(oldName: string, newName: string, references: Location[]): Promise<void> {
  const editsByUri = new Map<string, TextEdit[]>();

  for (const ref of references) {
    const edits = editsByUri.get(ref.uri) ?? [];
    edits.push({ range: ref.range, newText: newName });
    editsByUri.set(ref.uri, edits);
  }

  const workspaceEdit: WorkspaceEdit = {
    changes: Object.fromEntries(editsByUri),
  };

  await connection.workspace.applyEdit({
    label: `Rename '${oldName}' to '${newName}'`,
    edit: workspaceEdit,
  });
}

提示： 使用 documentChanges 而非 changes 可以在同一个 WorkspaceEdit 中混合文本编辑和文件操作，并且支持编辑注解让用户逐个确认变更。






工作区符号

interface WorkspaceSymbol {

  location: Location | { uri: string };

小结
    

  • workspaceFolders 支持多根目录工作区，是 rootPath 的现代替代方案。
    • 

  • 配置管理推荐混合模式：监听推送通知清除缓存，按需拉取具体配置值。
    • 

  • 文件监听通过 glob 模式注册，服务端据此监控配置文件和源码变更。
    • 

  • WorkspaceEdit 支持文本编辑和文件操作的混合，是重构和自动修复的基础设施。
    • 

  • 工作区符号搜索提供全项目级别的符号导航，支持模糊匹配和延迟 resolve 优化。
