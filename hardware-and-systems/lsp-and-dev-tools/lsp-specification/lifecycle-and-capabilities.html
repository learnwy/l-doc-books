生命周期与能力协商

初始化握手

LSP 的生命周期始于一次严格的握手过程。客户端发送 initialize 请求，服务端返回其能力集合，然后客户端发送 initialized 通知确认握手完成。在此之前，服务端不应处理任何其他请求。

interface InitializeParams {
  processId: number | null;
  clientInfo?: { name: string; version?: string };
  rootUri: string | null;
  capabilities: ClientCapabilities;
  initializationOptions?: unknown;
  trace?: 'off' | 'messages' | 'verbose';
  workspaceFolders?: WorkspaceFolder[] | null;
}

interface InitializeResult {
  capabilities: ServerCapabilities;
  serverInfo?: { name: string; version?: string };
}


提示： processId 参数让服务端能监控父进程状态。如果编辑器进程崩溃退出，服务端可以通过检测父进程终止来自行清理退出。






客户端能力
ClientCapabilities 声明了编辑器支持的功能特性。服务端必须检查这些能力来决定自己的行为边界。


interface ClientCapabilities {
  workspace?: {
    applyEdit?: boolean;
    workspaceEdit?: {
      documentChanges?: boolean;
      resourceOperations?: ResourceOperationKind[];
      normalizesLineEndings?: boolean;
    };
    didChangeConfiguration?: { dynamicRegistration?: boolean };
    didChangeWatchedFiles?: { dynamicRegistration?: boolean };
    symbol?: { dynamicRegistration?: boolean };
    configuration?: boolean;
    workspaceFolders?: boolean;
  };
  textDocument?: {
    synchronization?: {
      dynamicRegistration?: boolean;
      willSave?: boolean;
      willSaveWaitUntil?: boolean;
      didSave?: boolean;
    };
    completion?: {
      dynamicRegistration?: boolean;
      completionItem?: {
        snippetSupport?: boolean;
        commitCharactersSupport?: boolean;
        insertReplaceSupport?: boolean;
        labelDetailsSupport?: boolean;
      };
    };
    hover?: { dynamicRegistration?: boolean; contentFormat?: MarkupKind[] };
    definition?: { dynamicRegistration?: boolean; linkSupport?: boolean };
  };
  general?: {
    staleRequestSupport?: { cancel: boolean; retryOnContentModified: string[] };
    positionEncodings?: PositionEncodingKind[];
  };
}

服务端能力
ServerCapabilities 是服务端在 initialize 响应中返回的能力声明，告知客户端哪些功能可用。


interface ServerCapabilities {
  positionEncoding?: PositionEncodingKind;
  textDocumentSync?: TextDocumentSyncOptions | TextDocumentSyncKind;
  completionProvider?: CompletionOptions;
  hoverProvider?: boolean | HoverOptions;
  signatureHelpProvider?: SignatureHelpOptions;
  definitionProvider?: boolean | DefinitionOptions;
  typeDefinitionProvider?: boolean | TypeDefinitionOptions;
  implementationProvider?: boolean | ImplementationOptions;
  referencesProvider?: boolean | ReferenceOptions;
  documentSymbolProvider?: boolean | DocumentSymbolOptions;
  codeActionProvider?: boolean | CodeActionOptions;
  codeLensProvider?: CodeLensOptions;
  documentFormattingProvider?: boolean | DocumentFormattingOptions;
  renameProvider?: boolean | RenameOptions;
  diagnosticProvider?: DiagnosticOptions;
  workspace?: {
    workspaceFolders?: { supported?: boolean; changeNotifications?: boolean | string };
    fileOperations?: FileOperationOptions;

}

动态注册
除了在 initialize 响应中静态声明能力，LSP 还支持运行时动态注册和取消注册能力。这允许服务端根据项目状态按需启用功能。


interface RegistrationParams {
  registrations: Registration[];
}

interface Registration {
  id: string;
  method: string;
  registerOptions?: unknown;
}

interface UnregistrationParams {
  unregisterations: Unregistration[];
}

关闭与退出
LSP 定义了优雅的关闭流程。客户端发送 shutdown 请求通知服务端准备退出，服务端完成清理后返回响应，最后客户端发送 exit 通知终止进程。


connection.onShutdown(() => {
  cleanupResources();
  cancelPendingOperations();
  flushDiagnostics();
});

connection.onExit(() => {
  process.exit(shutdownReceived ? 0 : 1);
});

提示： 如果客户端崩溃未发送 shutdown，服务端应设置超时机制（如监听 stdin 关闭）来检测并自行退出。






小结
    

  • LSP 生命周期遵循严格的 initialize → initialized → 正常通信 → shutdown → exit 流程。
    • 

  • ClientCapabilities 声明编辑器支持的功能边界，服务端必须据此调整自身行为。
    • 

  • ServerCapabilities 在初始化响应中静态声明，也可通过 client/registerCapability 动态注册。
    • 

  • 动态注册允许服务端根据项目状态按需启用功能，使用唯一 id 标识注册项。
    • 

  • 关闭流程需要 shutdown 请求 + exit 通知 两步完成，服务端应实现超时退出以应对客户端异常。
