补码与浮点数表示

核心概念

计算机中有符号整数和实数的表示是数字系统设计的基础问题。补码（Two's Complement）通过巧妙的编码方式统一了加减法运算，成为现代处理器中有符号整数的标准表示；IEEE 754 浮点标准则为实数运算提供了跨平台的一致表示方案。

原码与反码
原码（Sign-Magnitude）用最高位表示符号（0 正 1 负），其余位表示绝对值。例如 8 位原码中：


+5=0000_0101,−5=1000_0101+5 = 0000\_0101, \quad -5 = 1000\_0101+5=0000_0101,−5=1000_0101
原码的缺陷在于零有两种表示（0000_00000000\_00000000_0000 和 1000_00001000\_00001000_0000），且加减法需要额外的符号判断逻辑。


反码（One's Complement）对负数将原码除符号位外全部取反：


+5=0000_0101,−5=1111_1010+5 = 0000\_0101, \quad -5 = 1111\_1010+5=0000_0101,−5=1111_1010
反码解决了部分运算问题，但仍存在双零问题和循环进位（end-around carry）的复杂性。


补码原理与运算
补码的定义
nnn 位补码的数学定义为：


[X]补={X0≤X<2n−12n+X−2n−1≤X<0[X]_{补} = \begin{cases} X & 0 \leq X < 2^{n-1} \\ 2^n + X & -2^{n-1} \leq X < 0 \end{cases}[X]补​={X2n+X​0≤X<2n−1−2n−1≤X<0​
等价的快速求法：将原码取反加 1。例如 8 位系统中：


−5:0000_0101→取反1111_1010→+11111_1011-5: \quad 0000\_0101 \xrightarrow{\text{取反}} 1111\_1010 \xrightarrow{+1} 1111\_1011−5:0000_0101取反​1111_1010+1​1111_1011
补码加法的统一性
补码最大的优势是减法可以转化为加法：A−B=A+(−B)=A+[Bˉ+1]A - B = A + (-B) = A + [\bar{B} + 1]A−B=A+(−B)=A+[Bˉ+1]


示例：计算 7+(−3)7 + (-3)7+(−3) 在 8 位补码中的运算：


0000_0111+1111_1101=1_0000_01000000\_0111 + 1111\_1101 = 1\_0000\_01000000_0111+1111_1101=1_0000_0100
丢弃溢出的最高位，结果为 0000_0100=40000\_0100 = 40000_0100=4，正确。


溢出检测
当两个同号数相加结果变号时，发生溢出。硬件检测方法：


V=Cn−1⊕Cn−2V = C_{n-1} \oplus C_{n-2}V=Cn−1​⊕Cn−2​
其中 Cn−1C_{n-1}Cn−1​ 是最高位进位，Cn−2C_{n-2}Cn−2​ 是次高位进位。当两者不同时，V=1V=1V=1 表示溢出。

截断风险
将宽数据截断为窄位宽时可能丢失信息。例如 16 位的 0000_0001_0000_00000000\_0001\_0000\_00000000_0001_0000_0000（256）截断为 8 位得到 0000_00000000\_00000000_0000（0），产生错误。硬件设计中需要饱和逻辑（saturation）来防止截断溢出。

在 FPGA 和 ASIC 设计中，定点数因其硬件效率优势被广泛用于信号处理算法。设计者需要通过定点分析确定所需的整数位宽和小数位宽，在满足精度要求的前提下最小化资源消耗。


小结
补码通过模运算的数学性质将减法统一为加法，消除了双零问题，是现代数字系统中有符号整数的唯一实用表示方式。IEEE 754 浮点标准则解决了实数表示中动态范围与精度的平衡问题。理解这两种表示方法的编码规则、运算特性和硬件实现约束，是设计算术运算单元和数据通路的基础。选择定点还是浮点表示，取决于具体应用对精度、面积和功耗的综合需求。
