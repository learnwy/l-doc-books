模糊测试技术

什么是模糊测试

模糊测试（Fuzzing / Fuzz Testing）是一种自动化的安全测试技术，通过向目标程序输入大量随机或半随机的畸形数据，观察程序是否出现崩溃、内存泄漏、断言失败等异常行为，从而发现安全漏洞。模糊测试最擅长发现传统测试方法难以触及的边界条件和异常处理缺陷——这些缺陷通常是内存损坏漏洞、拒绝服务漏洞和逻辑错误的根源。

模糊测试的核心价值在于其发现未知漏洞的能力。与基于已知漏洞模式的 SAST/DAST 不同，模糊测试不预设要找什么——它通过暴力探索输入空间来发现开发者和安全人员都未预见到的缺陷。Google 的 OSS-Fuzz 项目自 2016 年启动以来，已在 1,000+ 个开源项目中发现了超过 10,000 个安全漏洞和 36,000 个功能 Bug。

模糊测试分类
按生成策略分类
基于变异的模糊测试（Mutation-based Fuzzing）以有效的种子输入为起点，通过随机或启发式变异（位翻转、字节替换、块插入/删除、整数边界值替换等）生成新的测试用例。这是当前最主流的模糊测试方法，AFL、libFuzzer、Honggfuzz 都属于此类。


优势：不需要了解输入格式的详细规范，只需提供一些有效的样本输入即可开始测试。 局限：对于结构复杂的输入格式（如 PDF、SQL），纯随机变异生成的大部分输入会在解析阶段就被拒绝，难以深入到程序的核心处理逻辑。


基于生成的模糊测试（Generation-based Fuzzing）根据输入格式的语法规范或协议定义来构造测试用例。测试者定义输入的结构模型（如 HTTP 请求的 Header、Body 格式），模糊测试器在模型约束下生成变异输入。


优势：生成的测试用例能通过语法校验层，更容易触及程序的深层逻辑。 局限：需要编写输入格式的模型，前期投入较大。


混合方法是 2025 年的主流趋势。现代模糊测试器结合了变异和生成的优势——使用覆盖率反馈引导变异方向，同时利用语法感知来生成结构有效的输入。


按覆盖率引导分类
覆盖率引导模糊测试（Coverage-Guided Fuzzing）是过去十年模糊测试领域最重要的技术突破。其核心思想是：如果某个变异输入触发了目标程序中之前未被执行的代码路径（新覆盖），就将该输入加入种子库供后续变异使用——通过这种方式，模糊测试器逐步探索越来越多的代码路径，更有可能发现深层漏洞。


AFL（American Fuzzy Lop）是覆盖率引导模糊测试的开创者。AFL 通过编译时插桩（在每个基本块入口插入覆盖率追踪代码）获取目标程序的执行路径信息，然后使用遗传算法选择和变异种子。AFL++ 是 AFL 的社区增强版，在变异策略、调度算法和性能方面都有显著提升。


libFuzzer 是 LLVM 项目内置的进程内（in-process）模糊测试引擎。与 AFL 的独立进程模式不同，libFuzzer 在同一进程内反复调用目标函数，避免了进程创建/销毁的开销，测试吞吐量可达每秒数万甚至数十万次。它使用 SanitizerCoverage 获取覆盖率反馈。


// libFuzzer 目标函数示例
extern "C" int LLVMFuzzerTestOneInput(const uint8_t *Data, size_t Size) {
    // 将模糊数据传递给待测函数
    ParseJSON(Data, Size);
    return 0;
}
Honggfuzz 是 Google 开发的另一个覆盖率引导模糊测试器，特色是支持多种反馈信号（代码覆盖、硬件性能计数器、内核信号）和强大的多进程并行能力。

高级模糊测试技术
结构感知模糊测试
对于接受结构化输入的程序（解析器、编译器、协议处理器），纯粹的字节级变异效率很低。结构感知模糊测试通过理解输入的语法结构来进行更智能的变异。


Protobuf Mutator：Google 的 libprotobuf-mutator 允许使用 Protocol Buffers 定义输入结构，然后在结构层面进行变异。这对于测试接受 Protobuf 序列化数据的服务特别有效。


语法引导模糊测试：对于编程语言解析器或 SQL 引擎，可以使用目标语言的语法规则（BNF/EBNF）来生成语法有效但语义异常的输入。例如，SQLancer 项目专门针对数据库管理系统进行语法引导的模糊测试，已在 SQLite、MySQL、PostgreSQL 中发现了数百个 Bug。


符号执行辅助
符号执行（Symbolic Execution）将程序输入表示为符号变量，沿着执行路径收集路径约束条件，然后使用 SMT 求解器生成满足特定路径条件的具体输入。纯符号执行面临路径爆炸问题，但与模糊测试结合时效果显著。


混合模糊测试（Hybrid Fuzzing）的典型方案是：模糊测试器在发现新覆盖遇到瓶颈时（如遇到复杂条件判断），将当前输入交给符号执行引擎分析，生成能穿越目标条件分支的输入，再将其返回给模糊测试器继续变异。


KLEE 是最知名的符号执行引擎，Driller 和 QSYM 是混合模糊测试的代表性工具。


持续模糊测试
Google OSS-Fuzz 是最大的持续模糊测试基础设施。开源项目集成到 OSS-Fuzz 后，Google 的分布式模糊测试集群会 7×24 小时持续运行模糊测试。发现的漏洞自动报告给项目维护者，修复后自动验证。


ClusterFuzzLite 是 OSS-Fuzz 的轻量级版本，可以在项目自己的 CI 环境中运行。它在 PR 级别提供快速的模糊测试反馈——在每次代码变更时运行短时间（如 10 分钟）的模糊测试，检查变更是否引入了新的崩溃。


# GitHub Actions 集成 ClusterFuzzLite
name: CIFuzz
on: [pull_request]
jobs:
  Fuzzing:
    runs-on: ubuntu-latest
    steps:
      - uses: google/clusterfuzzlite/actions/build_fuzzers@v1
        with:
          language: c++
      - uses: google/clusterfuzzlite/actions/run_fuzzers@v1
        with:
          fuzz-seconds: 600
          mode: 'code-change'
API 模糊测试
API 模糊测试是应用安全领域增长最快的模糊测试分支。传统的 DAST 工具使用预定义的攻击载荷列表，而 API 模糊测试使用模糊测试的变异策略来生成大量变异请求，发现 DAST 遗漏的边界条件漏洞。


RESTler
RESTler（Microsoft Research 开发）是第一个有状态的 REST API 模糊测试器。它从 OpenAPI 规范自动推断 API 操作之间的依赖关系（如"创建用户"的响应中的 user_id 用于"获取用户"的路径参数），然后按依赖顺序调用 API 并对每个参数进行模糊测试。


RESTler 的核心能力：


    

  1. 依赖推断：自动分析 API 规范，推断请求间的生产者-消费者关系
    2. 

  2. 有状态测试：按正确顺序调用 API，维护应用状态
    3. 

  3. 智能变异：根据参数类型选择变异策略（对字符串使用 SQL 注入载荷，对整数使用边界值）
    4. 

  4. 安全检查器：内置 Use-After-Free（资源删除后仍可访问）、资源泄漏等安全检查
    5. 



协议模糊测试
协议模糊测试针对网络协议实现进行测试，包括 HTTP/2、gRPC、WebSocket、MQTT 等。


boofuzz 是 Sulley 框架的继承者，是最流行的开源网络协议模糊测试框架。它允许定义协议的消息格式和状态机，然后对每个字段进行智能变异。


HTTP/2 模糊测试的特殊挑战在于 HTTP/2 是二进制协议（不像 HTTP/1.1 是文本协议），帧结构复杂（HEADERS、DATA、SETTINGS、GOAWAY 等），存在流多路复用和流控机制。Google 使用模糊测试发现了多个 HTTP/2 实现中的拒绝服务漏洞（如 CVE-2023-44487 "HTTP/2 Rapid Reset" 攻击）。


模糊测试实施最佳实践
种子选择
种子（Corpus）的质量直接影响模糊测试的效率。好的种子应该：


    

  1. 覆盖多样的代码路径：每个种子触发不同的处理逻辑
    2. 

  2. 尽量小：小种子变异后更容易产生有意义的变化
    3. 

  3. 格式有效：种子应该是目标程序能正常处理的有效输入
    4. 

  4. 定期精简：使用 afl-cmin 或 llvm-cov 精简种子库，删除覆盖率重复的种子
    5. 



崩溃分析与去重
模糊测试可能在短时间内产生数千个崩溃文件，其中大部分是同一个底层漏洞的不同触发路径。崩溃去重是将这些崩溃分组到唯一漏洞的过程。

与 Sanitizer 结合
模糊测试 + Sanitizer 是发现内存安全漏洞的"黄金组合"。Sanitizer 在运行时检测内存错误，模糊测试提供海量的输入来触发这些错误。

推荐实践：在模糊测试时同时启用 ASan 和 UBSan——ASan 检测内存损坏，UBSan 检测未定义行为。两者的组合能发现绝大多数安全相关的 C/C++ 缺陷。


总结
模糊测试是应用安全测试工具箱中发现未知漏洞能力最强的方法。覆盖率引导模糊测试（AFL++/libFuzzer）+ Sanitizer 的组合已成为 C/C++ 项目的安全测试标配。对于 Web 应用和 API，RESTler 等 API 模糊测试器正在填补 DAST 工具在边界条件检测上的空白。持续模糊测试（OSS-Fuzz/ClusterFuzzLite）将模糊测试从一次性活动转变为持续的安全保障机制。无论目标是系统级软件还是 Web API，模糊测试都应该成为安全测试策略的核心组成部分。
