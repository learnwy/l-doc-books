性能分析与功耗优化

性能分析方法论

嵌入式系统的性能分析不同于桌面软件——无法依赖功能丰富的 profiler 工具，需要利用硬件调试单元和轻量级仪器化手段获取运行时数据。核心目标是定位 CPU 瓶颈、优化关键路径延迟、确保实时性约束得到满足。

DWT 精确计时
CYCCNT 使用方法
DWT_CYCCNT 提供处理器级精度的时间测量：


执行周期数=DWT->CYCCNT∣after−DWT->CYCCNT∣before\text{执行周期数} = \text{DWT->CYCCNT}|_{\text{after}} - \text{DWT->CYCCNT}|_{\text{before}}执行周期数=DWT->CYCCNT∣after​−DWT->CYCCNT∣before​
执行时间（μs）=周期数fCPU/106\text{执行时间（μs）} = \frac{\text{周期数}}{f_{\text{CPU}} / 10^6}执行时间（μs）=fCPU​/106周期数​
启用 CYCCNT 的初始化步骤：


    

  1. 使能 DWT 单元：CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk
    2. 

  2. 复位计数器：DWT->CYCCNT = 0
    3. 

  3. 启动计数：DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk
    4. 



中断对测量的影响
测量期间若发生中断，CYCCNT 仍然递增（包括 ISR 执行时间）：


测量值=目标代码周期+∑中断执行周期\text{测量值} = \text{目标代码周期} + \sum \text{中断执行周期}测量值=目标代码周期+∑中断执行周期
精确测量需要：


    

  • 临时屏蔽中断（可能影响系统行为）
    • 

  • 多次测量取最小值（最小值≈无中断干扰时的真实值）
    • 

  • 使用 DWT 异常跟踪补偿 ISR 时间
    •

数据对齐与缓存优化
Cortex-M7 的 D-Cache 和 I-Cache 对数据布局敏感：


Cache Line=32 字节（M7典型值）\text{Cache Line} = 32 \text{ 字节}（M7 典型值）Cache Line=32 字节（M7典型值）
优化策略：


    

  • 频繁访问的数据结构按 32 字节对齐
    • 

  • 避免数据跨 Cache Line 边界（false sharing）
    • 

  • DMA 缓冲区标记为 Non-cacheable 或手动 Cache 维护
    •
