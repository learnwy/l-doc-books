RTOS 调度原理

为什么需要 RTOS

裸机编程中，应用逻辑通常以超级循环（Super Loop）模式运行：主函数中无限循环依次执行各任务，中断处理紧急事件。当系统复杂度增加时，超级循环面临根本性挑战：





维度
超级循环
RTOS 多任务





响应延迟
最差=循环总时长
确定性（最高优先级立即执行）




代码结构
所有任务紧耦合
各任务独立，关注点分离




时序确定性
随任务增加而恶化
由优先级和调度策略保证




阻塞等待
必须轮询或超时返回
原生支持挂起/唤醒




资源开销
极低（无调度器）
额外 RAM（每任务一个栈）+ ROM




适用场景
简单控制、极低资源
多任务、实时性要求高





调度算法
抢占式优先级调度
RTOS 中最常用的调度策略是基于优先级的抢占式调度：


运行任务=arg⁡max⁡就绪任务(优先级)\text{运行任务} = \arg\max_{\text{就绪任务}} (\text{优先级})运行任务=arg就绪任务max​(优先级)
核心规则：


    

  • 最高优先级的就绪任务始终获得 CPU
    • 

  • 更高优先级任务就绪时，低优先级任务被立即抢占
    • 

  • 相同优先级的任务按时间片轮转执行
    • 



时间片轮转
对于同优先级任务，调度器分配固定长度的时间片（Time Slice）：


时间片=N×TTick（N 为配置的 Tick 数）\text{时间片} = N \times T_{\text{Tick}} \quad \text{（N 为配置的 Tick 数）}时间片=N×TTick​（N 为配置的 Tick 数）
当任务消耗完时间片后，调度器切换到同优先级的下一个就绪任务。时间片的选择需要权衡：


    

  • 太短：上下文切换开销占比过高
    • 

  • 太长：同优先级任务响应延迟增大
    • 



协作式调度
协作式调度中，任务仅在主动让出 CPU 时（调用 yield 或进入阻塞状态）才发生切换：


切换条件=taskYIELD()∨进入阻塞 API\text{切换条件} = \text{taskYIELD()} \lor \text{进入阻塞 API}切换条件=taskYIELD()∨进入阻塞 API
优点是无需考虑抢占带来的数据竞争，缺点是一个任务长时间占用 CPU 会饿死其他任务。

PendSV 实现上下文切换
Cortex-M 使用 PendSV（可挂起系统调用）异常实现上下文切换：


PendSV 被配置为最低优先级异常，确保所有 ISR 完成后才执行上下文切换，避免在高优先级中断处理期间发生切换。

SysTick 定时器
角色与配置
SysTick 是 Cortex-M 内核自带的 24 位递减计数器，作为 RTOS 的心跳时钟（Tick）：


fTick=fHCLKLOAD+1f_{\text{Tick}} = \frac{f_{\text{HCLK}}}{\text{LOAD} + 1}fTick​=LOAD+1fHCLK​​
典型配置为 1 ms（1 kHz Tick 频率）：


LOAD=168,000,0001000−1=167999\text{LOAD} = \frac{168,000,000}{1000} - 1 = 167999LOAD=1000168,000,000​−1=167999
Tick 的作用
每次 SysTick 中断执行以下操作：


    

  1. 全局 Tick 计数器递增（用于 vTaskDelay 等时间 API）
    2. 

  2. 检查阻塞任务的超时条件
    3. 

  3. 更新时间片计数器
    4. 

  4. 若需要切换，挂起 PendSV
    5. 



Tickless 空闲模式
当系统无就绪任务时，Tickless 模式停止 SysTick 以降低功耗：


跳过 Tick 数=min⁡(最近唤醒时间,SysTick 最大计数)\text{跳过 Tick 数} = \min(\text{最近唤醒时间}, \text{SysTick 最大计数})跳过 Tick 数=min(最近唤醒时间,SysTick 最大计数)
唤醒后补偿跳过的 Tick 数，确保系统时间的正确性。

就绪列表
调度器通过就绪列表（按优先级索引的链表数组）在 O(1)O(1)O(1) 时间内找到最高优先级的就绪任务：


就绪列表=pxReadyTasksLists[configMAX_PRIORITIES]\text{就绪列表} = \text{pxReadyTasksLists}[\text{configMAX\_PRIORITIES}]就绪列表=pxReadyTasksLists[configMAX_PRIORITIES]
每次调度只需读取最高非空优先级索引即可，使用位图（bitmap）加速查找。

中断延迟边界
RTOS 引入的最坏中断延迟：


TIRQ_latency=Tlongest_critical_section+THW_entryT_{\text{IRQ\_latency}} = T_{\text{longest\_critical\_section}} + T_{\text{HW\_entry}}TIRQ_latency​=Tlongest_critical_section​+THW_entry​
FreeRTOS 通过 configMAX_SYSCALL_INTERRUPT_PRIORITY 将高于该优先级的中断完全不受 RTOS 临界区影响，确保关键中断的零抖动。
