栈大小估算
任务栈需容纳：函数调用深度 × 每帧局部变量 + 中断嵌套上下文 + 安全余量。


栈大小≥最大调用深度×平均帧大小+中断上下文+余量\text{栈大小} \geq \text{最大调用深度} \times \text{平均帧大小} + \text{中断上下文} + \text{余量}栈大小≥最大调用深度×平均帧大小+中断上下文+余量
实用估算策略：


    

  1. 初始分配较大栈（如 1024 字）
    2. 

  2. 使用 uxTaskGetStackHighWaterMark() 运行时检测实际最大使用量
    3. 

  3. 将栈大小设为实际使用量的 1.5-2 倍作为安全裕量
    4. 



栈溢出检测
FreeRTOS 提供两种运行时栈溢出检测方法：


    

  • 方法 1：每次上下文切换时检查 SP 是否越过栈底——检测速度快但可能遗漏瞬时溢出
    • 

  • 方法 2：在栈底填充已知模式（0xA5A5A5A5），切换时验证——可检测被覆盖的栈底区域
    •

计数信号量
计数信号量管理有限数量的资源：


计数值∈[0,最大计数]\text{计数值} \in [0, \text{最大计数}]计数值∈[0,最大计数]
应用场景：


    

  • 信号量初值=资源总数（如 DMA 通道数、缓冲池大小）
    • 

  • 每次获取资源 Take（计数-1），释放 Give（计数+1）
    • 

  • 计数为 0 时获取操作阻塞
    • 



互斥量
优先级继承
互斥量与二值信号量的关键区别在于优先级继承（Priority Inheritance）机制：


若高优先级任务等待低优先级任务持有的互斥量⇒临时提升持有者优先级\text{若高优先级任务等待低优先级任务持有的互斥量} \Rightarrow \text{临时提升持有者优先级}若高优先级任务等待低优先级任务持有的互斥量⇒临时提升持有者优先级
优先级反转问题
没有优先级继承时会发生优先级反转：


    

  1. 低优先级任务 L 获取互斥量
    2. 

  2. 高优先级任务 H 等待互斥量（被阻塞）
    3. 

  3. 中优先级任务 M 抢占 L 执行
    4. 

  4. H 的等待时间被 M 无限期延长
    5. 



最坏等待时间（无继承）=所有中优先级任务的总执行时间\text{最坏等待时间（无继承）} = \text{所有中优先级任务的总执行时间}最坏等待时间（无继承）=所有中优先级任务的总执行时间
最坏等待时间（有继承）=L 持有互斥量期间的执行时间\text{最坏等待时间（有继承）} = \text{L 持有互斥量期间的执行时间}最坏等待时间（有继承）=L 持有互斥量期间的执行时间
递归互斥量
同一任务可以多次获取同一递归互斥量（计数递增），但必须释放相同次数：


解锁条件：Give 次数=Take 次数\text{解锁条件：Give 次数} = \text{Take 次数}解锁条件：Give 次数=Take 次数
适用于嵌套调用中多个层级都需要访问相同受保护资源的场景。
