OXC 与 oxlint 概览

核心概念

OXC（The JavaScript Oxidation Compiler）是一个用 Rust 编写的高性能 JavaScript/TypeScript 工具集合，其核心组件包括解析器（oxc-parser）、lint 工具（oxlint）、转译器（oxc-transform）和解析器（oxc-resolver）。oxlint 是其中最成熟的面向用户的工具，它的定位是ESLint 的高性能替代品，专注于代码质量检查而非格式化。

oxlint 的核心策略是不求全面，但求极快。它将 ESLint 中最常用、最有价值的规则以 Rust 重新实现，作为 ESLint 的补充（而非完全替代）使用。


解析器架构与性能
OXC 的解析器（oxc-parser）是整个工具集的基础，也是目前已知最快的 JavaScript/TypeScript 解析器之一。

  performance: {
    speed: '比 Babel Parser 快约 3 倍';
    memory: '内存占用仅为 Babel 的 1/4';

  };
  compatibility: {
    estree: '可输出 ESTree 兼容 AST';

    jsx: '原生支持 JSX/TSX';
  };

解析器还支持输出 ESTree 兼容格式的 AST，这意味着理论上它可以作为 ESLint 的解析器后端使用，为现有 ESLint 规则提供更快的解析速度。


oxlint 规则与配置
oxlint 内置了数百条规则，这些规则从 ESLint 核心规则和流行的社区插件中移植而来。


{
  "$schema": "./node_modules/oxlint/configuration_schema.json",
  "rules": {
    "no-unused-vars": "error",
    "no-console": "warn",
    "eqeqeq": "error",
    "no-debugger": "error",
    "prefer-const": "error"
  },
  "plugins": ["typescript", "react", "react-hooks", "import", "jest", "unicorn", "jsx-a11y"],
  "ignorePatterns": ["dist/**", "node_modules/**"]
}
oxlint 的规则涵盖了多个 ESLint 插件的核心规则：


const oxlintRuleSources = {
  eslintCore: ['no-unused-vars', 'no-undef', 'eqeqeq', 'no-debugger'],
  typescriptEslint: ['no-explicit-any', 'no-non-null-assertion', 'consistent-type-imports'],
  reactPlugin: ['jsx-no-target-blank', 'no-direct-mutation-state'],
  reactHooksPlugin: ['rules-of-hooks', 'exhaustive-deps'],
  importPlugin: ['no-cycle', 'no-self-import', 'no-duplicates'],
  unicornPlugin: ['no-array-for-each', 'prefer-array-flat-map'],
  jestPlugin: ['no-identical-title', 'valid-expect'],
  jsxA11yPlugin: ['alt-text', 'aria-props'],
};
CLI 使用方式简洁直接：


oxlint .                          # 使用默认规则检查
oxlint --deny-warnings .         # 将 warning 视为 error
oxlint -c oxlintrc.json .        # 使用配置文件
oxlint --fix .                   # 自动修复
oxlint -D correctness -D perf .  # 启用特定类别

oxlint --ignore-pattern "dist/**" --ignore-pattern "*.test.ts" .
与 ESLint 的互补使用
oxlint 的官方推荐用法不是完全替代 ESLint，而是与 ESLint 互补——让 oxlint 处理那些不需要类型信息的高频规则，让 ESLint 处理需要类型信息和自定义插件的高级规则。

在 ESLint 配置中，使用 eslint-plugin-oxlint 自动关闭已由 oxlint 覆盖的规则：


import oxlint from 'eslint-plugin-oxlint';

export default [...tseslint.configs.recommendedTypeChecked, ...oxlint.configs['flat/recommended']];
这种分层策略在大型项目中效果显著：oxlint 在毫秒级完成基础检查，ESLint 只需处理剩余的高级规则，整体 lint 时间可缩短 60-80%。


OXC 生态与未来方向
OXC 项目的野心不止于 lint，它的目标是成为JavaScript 工具的基础设施层。


const oxcEcosystem = {
  released: {

OXC 与 Rolldown（Rust 实现的 Rollup 替代品，Vite 的未来打包器）紧密协作。Rolldown 使用 oxc-parser 作为其 JavaScript 解析器，这意味着 OXC 的解析器正在成为 Vite 生态的核心组件。

小结
    

  • OXC 是用 Rust 构建的 JavaScript 工具基础设施，oxlint 是其面向用户的 lint 工具
    • 

  • oxc-parser 通过 Arena 分配器和零拷贝策略实现了极高的解析性能
    • 

  • oxlint 的推荐用法是与 ESLint 互补，而非完全替代
    • 

  • 通过 eslint-plugin-oxlint 自动关闭 ESLint 中已被 oxlint 覆盖的规则
    • 

  • OXC 生态与 Rolldown/Vite 深度集成，正在成为 JavaScript 工具链的底层基础设施
    •
