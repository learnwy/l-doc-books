迁移指南：从 ESLint/Prettier 到新一代工具

核心概念

从 ESLint + Prettier 迁移到 Biome 或 oxlint 不是一个简单的工具替换，而是一个渐进式的工具链重构过程。成功的迁移需要评估现有配置的复杂度、识别不可迁移的规则、制定分阶段的切换计划，并在整个过程中保证代码质量不降级。

迁移的第一步是对现有工具链进行全面审计，明确哪些规则可以迁移、哪些需要保留。

npx @biomejs/biome migrate eslint --write
npx @biomejs/biome migrate prettier --write

迁移到 Biome
Biome 提供了自动化的迁移命令，可以从现有的 Prettier 和 ESLint 配置生成 biome.json。


npx @biomejs/biome init

npx @biomejs/biome migrate prettier --write

npx @biomejs/biome migrate eslint --write
迁移后需要手动调整的部分：


{
  "linter": {
    "rules": {
      "recommended": true,
      "correctness": {
        "noUnusedVariables": "error",
        "noUnusedImports": "error"
      },
      "suspicious": {
        "noExplicitAny": "warn"
      }
    }
  },
  "formatter": {
    "indentStyle": "space",
    "indentWidth": 2,
    "lineWidth": 80
  },
  "javascript": {
    "formatter": {
      "quoteStyle": "double",
      "semicolons": "always",
      "trailingCommas": "all"
    }
  },
  "files": {
    "ignore": ["dist/**", "node_modules/**", "coverage/**"]
  }
}

渐进引入 oxlint
对于配置复杂的大型项目，推荐先引入 oxlint 作为 ESLint 的加速层，然后逐步扩大 oxlint 的规则覆盖。


npm install -D oxlint eslint-plugin-oxlint
第一阶段：oxlint 处理基础规则，ESLint 自动跳过：


import oxlint from 'eslint-plugin-oxlint';

export default [...tseslint.configs.recommendedTypeChecked, ...oxlint.configs['flat/recommended']];
更新 lint-staged 配置，先运行 oxlint 再运行 ESLint：


{
  "lint-staged": {
    "*.{ts,tsx}": ["oxlint --fix", "eslint --fix"]
  }
}
更新 CI 脚本：


lint:
  script:
    - npx oxlint --deny-warnings .
    - npx eslint .

回归验证与质量保证
迁移过程中必须确保代码质量不降级。这需要一套系统化的验证流程。


eslint . 2>&1 | wc -l
biome check . 2>&1 | wc -l

prettier --check "src/**/*.{ts,tsx}" 2>&1 | tail -1
biome format --check "src/**/*.{ts,tsx}" 2>&1 | tail -1

小结
    

  • 迁移前必须审计现有 ESLint 规则的覆盖缺口，特别关注类型感知规则和自定义规则
    • 

  • Biome 提供了自动化的 migrate 命令，适合规则简单的项目快速迁移
    • 

  • 大型项目推荐渐进引入 oxlint + eslint-plugin-oxlint，分阶段扩大覆盖
    • 

  • 回归验证需覆盖规则覆盖率、格式化一致性、CI 性能和编辑器体验四个维度
    • 

  • 迁移的终极目标是性能提升和工具链简化，而非完全替代 ESLint 的所有能力
    •
