Biome 全面解析

核心概念

Biome 是一个用 Rust 编写的高性能 Web 工具链，目标是将格式化（Formatter）、静态分析（Linter）、导入排序（Import Organizer）统一到一个工具中。它继承了 Rome 项目的愿景，通过单一二进制文件替代 Prettier + ESLint 的组合方案，在保持高度兼容性的同时获得数量级的性能提升。

Biome 的核心优势不仅是性能，更是工具链简化——减少配置文件数量、消除工具间的版本冲突、统一诊断输出格式。


架构与解析器设计
Biome 的内部架构围绕 CST（Concrete Syntax Tree，具象语法树） 构建。与 ESLint 使用的 AST 不同，CST 保留了源代码中的所有信息，包括空白、注释、括号等。


interface BiomeArchitecture {
  parser: {
    type: 'CST-based';
    languages: ['JavaScript', 'TypeScript', 'JSX', 'TSX', 'JSON', 'CSS'];
    errorRecovery: '容错解析，语法错误不阻断';
    incrementalParsing: '支持增量更新';
  };
  formatter: {
    algorithm: 'IR-based (类似 Prettier Doc)';
    compatibility: '97% Prettier 输出兼容';
    performance: '并行文件处理';
  };
  linter: {
    rules: '300+ 内置规则';
    categories: ['correctness', 'suspicious', 'style', 'complexity', 'a11y'];
    autofix: '安全修复 + 不安全修复分离';
  };
}
CST 的优势在于它是可逆的——从 CST 可以精确重建原始源代码。这对格式化工具尤为重要，因为它需要在修改空白的同时保留注释等非语法信息。


Biome 的解析器支持容错解析——即使代码存在语法错误，解析器仍然会尽力构建部分 CST，使得 lint 和格式化可以在有语法错误的文件上工作。这在编辑器实时检查场景中尤为重要。


配置与规则体系
Biome 使用 biome.json 作为唯一的配置文件，结构清晰地分为格式化、lint、导入排序三个部分：


{
  "$schema": "https://biomejs.dev/schemas/1.9.0/schema.json",
  "organizeImports": {
    "enabled": true
  },
  "formatter": {
    "enabled": true,
    "indentStyle": "space",
    "indentWidth": 2,
    "lineWidth": 80,
    "lineEnding": "lf"
  },
  "linter": {
    "enabled": true,
    "rules": {
      "recommended": true,
      "correctness": {
        "noUnusedVariables": "error",
        "noUnusedImports": "error"
      },
      "suspicious": {
        "noExplicitAny": "warn",
        "noDoubleEquals": "error"
      },
      "style": {
        "useConst": "error",
        "noNonNullAssertion": "warn"
      },
      "complexity": {
        "noBannedTypes": "error"
      }
    }
  },
  "javascript": {
    "formatter": {
      "quoteStyle": "double",
      "trailingCommas": "all",
      "semicolons": "always",
      "arrowParentheses": "always"
    }
  }
}

Biome 支持文件级覆盖，类似 ESLint 的 files/ignores 模式：


{
  "overrides": [
    {
      "include": ["**/*.test.ts", "**/*.spec.ts"],
      "linter": {
        "rules": {
          "suspicious": {
            "noExplicitAny": "off"
          }
        }
      }
    },
    {
      "include": ["scripts/**"],
      "linter": {
        "rules": {
          "style": {
            "noConsole": "off"
          }
        }
      }
    }
  ]
}
与 Prettier 和 ESLint 的兼容策略
Biome 的采用策略是渐进式替代——先作为 Prettier 的替代品（格式化兼容度最高），再逐步替代 ESLint 的规则。


格式化兼容性方面，Biome 通过一个专门的兼容性测试套件追踪与 Prettier 的输出差异。少数已知差异是有意为之的改进：


const knownDifferences = {
  trailingCommaInArrowParams: 'Biome 在单参数箭头函数中不添加括号时更一致',
  htmlAttributeFormatting: 'HTML 属性换行策略有微小差异',
  markdownTableAlignment: 'Markdown 表格对齐策略不同',
  jsonTrailingComma: 'JSON 中永远不添加尾逗号（标准合规）',
};

Biome 提供了 biome migrate prettier 命令自动从 .prettierrc 生成 biome.json 的格式化配置。


编辑器集成与 CLI
Biome 提供了 VS Code 扩展和 CLI 两种使用方式。


biome check .                    # 格式化 + lint + 导入排序（仅检查）
biome check --write .            # 格式化 + lint + 导入排序（自动修复）
biome format --write .           # 仅格式化
biome lint .                     # 仅 lint
biome ci .                       # CI 模式（严格检查，不修复）
VS Code 集成配置：


{
  "editor.defaultFormatter": "biomejs.biome",
  "editor.formatOnSave": true,
  "editor.codeActionsOnSave": {
    "quickfix.biome": "explicit",
    "source.organizeImports.biome": "explicit"
  }
}
Biome 的 CLI 设计注重单命令覆盖所有功能。biome check 是最常用的命令，它同时执行格式化检查、lint、和导入排序，一次性报告所有问题。


小结
    

  • Biome 通过 Rust 实现将格式化 + lint + 导入排序统一为单一工具，性能提升 10-100 倍
    • 

  • CST 架构保留源代码所有信息，支持容错解析和精确的格式化/lint 分析
    • 

  • 规则分类为 correctness/suspicious/style/complexity/a11y/security 六大类别
    • 

  • 与 Prettier 保持 97% 的格式化输出兼容，提供自动迁移命令
    • 

  • biome check 单命令覆盖所有检查，--write 标志控制是否自动修复
    •
