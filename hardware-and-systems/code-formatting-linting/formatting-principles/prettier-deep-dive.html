Prettier 深度解析

核心概念

Prettier 是一个"有主见的"（opinionated）代码格式化工具，它的设计哲学是最小化可配置项，最大化一致性。与 ESLint 等高度可配置的工具不同，Prettier 刻意限制了用户可以调整的选项数量，从而确保任何使用 Prettier 的项目都能获得高度一致的代码风格。

Prettier 的核心价值在于终结代码风格争论。团队不再需要讨论"花括号是否换行""缩进用 2 还是 4 空格"等问题，因为 Prettier 已经做出了决定，而且这些决定不可更改（或只能在很小范围内调整）。


架构与执行流程
Prettier 的内部架构围绕管道模式组织，源代码经过一系列确定性变换最终输出格式化结果。


async function format(source: string, options: Options): Promise<string> {
  const resolvedOptions = await resolveOptions(options);
  const parser = getParser(resolvedOptions);
  const ast = parser.parse(source, resolvedOptions);
  const printer = getPrinter(resolvedOptions);
  const doc = printer.print(new AstPath(ast), resolvedOptions, (path) => printer.print(path, resolvedOptions, print));
  const formatted = printDocToString(doc, resolvedOptions);
  return formatted.formatted;
}
Prettier 的选项解析系统支持多层级配置合并：


interface OptionsResolution {
  editorConfig: Partial<Options>;
  configFile: Partial<Options>;
  cliFlags: Partial<Options>;
  perFileOverride: Partial<Options>;
}
配置优先级从低到高为：EditorConfig → .prettierrc → CLI 参数 → 文件级 override。这种层级设计使得项目可以设定基线配置，同时允许特定文件类型使用不同的格式化选项。

核心配置项深度解读
Prettier 的配置项虽少，但每一项都经过深思熟虑。理解这些选项背后的设计考量有助于做出合理选择。


printWidth（默认 80）：这不是一个硬性的行宽限制，而是格式化引擎的优化目标。Prettier 会尽量将代码控制在 printWidth 以内，但不会为此牺牲可读性。例如，一个很长的字符串字面量不会被截断。


tabWidth 与 useTabs：控制缩进的视觉宽度和物理字符。tabWidth: 2 + useTabs: false 是 JavaScript 社区最主流的选择，而 Go 社区倾向于使用 Tab。


trailingComma：从 v3 开始默认为 "all"，即在所有合法位置添加尾逗号。这一选择的理由是：尾逗号使得 git diff 更清晰，添加新元素时只需增加一行而不会修改前一行。


const config: PrettierConfig = {
  printWidth: 80,

插件系统与语言扩展
Prettier 的插件系统允许第三方为新语言添加格式化支持。每个插件本质上是一个实现了特定接口的 npm 包。


interface PrettierPlugin {
  languages: Array<{
    name: string;
    parsers: string[];
    extensions: string[];
    vscodeLanguageIds?: string[];
  }>;
  parsers: Record<
    string,
    {
      parse: (text: string, options: Options) => AST;
      astFormat: string;
      locStart: (node: ASTNode) => number;
      locEnd: (node: ASTNode) => number;
    }
  >;
  printers: Record<
    string,
    {
      print: (path: AstPath, options: Options, print: PrintFn) => Doc;
      embed?: EmbedFn;
      insertPragma?: (text: string) => string;
    }
  >;
  options?: Record<string, OptionDefinition>;
}
社区中重要的 Prettier 插件包括：


const plugins = [
  'prettier-plugin-tailwindcss',
  'prettier-plugin-organize-imports',
  'prettier-plugin-sql',
  'prettier-plugin-toml',
  '@prettier/plugin-xml',
  'prettier-plugin-astro',
  'prettier-plugin-svelte',
];
插件之间可能存在冲突，尤其是当多个插件处理同一语言时。Prettier 使用最后注册的插件优先的策略，因此插件的声明顺序很重要。prettier-plugin-tailwindcss 的文档明确要求它必须是插件列表中的最后一个。


与编辑器和工具链的集成
Prettier 的价值在格式化本身之外，更在于它与开发工具链的深度集成。


编辑器集成：VS Code 的 Prettier 扩展通过 editor.formatOnSave 实现保存时自动格式化。扩展内部调用 Prettier 的 Node.js API，并处理了配置解析、文件忽略等逻辑。


// VS Code settings.json 典型配置
const vscodeSettings = {
  'editor.defaultFormatter': 'esbenp.prettier-vscode',
  'editor.formatOnSave': true,
  '[javascript]': {
    'editor.defaultFormatter': 'esbenp.prettier-vscode',
  },
  '[typescript]': {
    'editor.defaultFormatter': 'esbenp.prettier-vscode',
  },
  'prettier.requireConfig': true,
};
与 ESLint 协作：Prettier 和 ESLint 的职责存在部分重叠（格式化规则）。推荐的做法是使用 eslint-config-prettier 关闭 ESLint 中与 Prettier 冲突的规则，让 Prettier 专注格式化，ESLint 专注代码质量。


import prettierConfig from 'eslint-config-prettier';

export default [...otherConfigs, prettierConfig];
Git Hooks 集成：通过 lint-staged 在提交前对暂存文件运行 Prettier，确保进入仓库的代码始终是格式化过的。


{
  "lint-staged": {
    "*.{js,ts,tsx,css,md,json}": "prettier --write"
  }
}
性能优化与缓存机制
Prettier 在大型项目中的性能是一个值得关注的话题。格式化单个文件通常在毫秒级，但当项目包含数千个文件时，全量格式化可能需要数十秒。


文件缓存：Prettier CLI 支持 --cache 标志，它会记录每个文件的内容哈希和格式化结果。当文件内容未变时跳过格式化，大幅提升增量格式化的速度。


prettier --write --cache "src/**/*.{ts,tsx}"
解析器性能：Babel Parser 的性能在大文件上可能成为瓶颈。对于纯 TypeScript 项目，使用 --parser typescript（基于 @typescript-eslint/typescript-estree）可能获得更好的性能。


并行处理：Prettier CLI 本身是单线程的，但可以通过 --concurrency 参数控制并发数。在 CI 环境中，结合文件分片和并行任务可以显著缩短格式化检查时间。

小结
    

  • Prettier 通过"有主见"的设计哲学终结代码风格争论，将格式化变为自动化基础设施
    • 

  • 内部架构基于 AST 解析 → Doc IR → 行宽求解的确定性管道
    • 

  • 配置项刻意精简，核心决策（如 trailingComma: all）背后有明确的工程理由
    • 

  • 插件系统通过 Parser + Printer 接口支持数十种语言
    • 

  • 与编辑器、ESLint、Git Hooks 的集成形成完整的格式化工具链
    • 

  • 性能优化的关键是缓存和增量策略，避免全量格式化
