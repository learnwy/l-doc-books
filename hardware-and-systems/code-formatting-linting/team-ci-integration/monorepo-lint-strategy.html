Monorepo 中的 Lint 策略

核心概念

Monorepo 中的 lint 策略面临独特的挑战：多个包可能使用不同的技术栈和编码规范，但需要共享基础配置并保持一致性。一个设计良好的 monorepo lint 架构需要在"统一管控"和"包级自治"之间取得平衡，同时解决性能问题——全量 lint 数千个文件在大型 monorepo 中可能耗时数分钟。

配置分层架构
Monorepo lint 配置通常采用根配置 + 包级覆盖的分层架构。


import eslint from '@eslint/js';
import tseslint from 'typescript-eslint';

const baseConfig = tseslint.config(eslint.configs.recommended, ...tseslint.configs.recommended, {
  rules: {
    '@typescript-eslint/no-unused-vars': [
      'error',
      {
        argsIgnorePattern: '^_',
        varsIgnorePattern: '^_',
      },
    ],
    '@typescript-eslint/consistent-type-imports': 'error',
  },
});

const reactConfig = {
  plugins: { react: reactPlugin, 'react-hooks': hooksPlugin },
  rules: {
    'react-hooks/rules-of-hooks': 'error',
    'react-hooks/exhaustive-deps': 'warn',
  },
};

const libraryConfig = {
  rules: {
    'no-console': 'error',
  },
};

const scriptConfig = {
  rules: {
    'no-console': 'off',
    '@typescript-eslint/no-explicit-any': 'off',
  },
};
根目录的 eslint.config.mjs 组合所有包的配置：


export default [
  ...baseConfig,

  {
    files: ['apps/**/*.{ts,tsx}'],
    ...reactConfig,
  },

  {
    files: ['packages/ui/**/*.{ts,tsx}'],
    ...reactConfig,
  },

  {
    files: ['packages/core/**/*.ts', 'packages/utils/**/*.ts'],
    ...libraryConfig,
  },

  {
    files: ['scripts/**/*.{ts,mjs}'],
    ...scriptConfig,
  },

  {
    files: ['**/*.test.{ts,tsx}'],
    rules: {
      '@typescript-eslint/no-explicit-any': 'off',
    },
  },

  {
    ignores: ['**/dist/**', '**/node_modules/**', '**/coverage/**'],
  },
];
TypeScript 项目引用与 Lint
在使用 TypeScript 项目引用（Project References）的 monorepo 中，每个包有自己的 tsconfig.json。ESLint 的类型感知规则需要正确配置 parserOptions.project 指向各包的 tsconfig。


export default [
  ...baseConfig,
  {
    files: ['apps/web/**/*.{ts,tsx}'],
    languageOptions: {
      parserOptions: {
        project: './apps/web/tsconfig.json',
        tsconfigRootDir: import.meta.dirname,
      },
    },
  },
  {
    files: ['packages/core/**/*.ts'],
    languageOptions: {
      parserOptions: {
        project: './packages/core/tsconfig.json',
        tsconfigRootDir: import.meta.dirname,
      },
    },
  },
];
对于包含大量子包的 monorepo，可以使用 glob 模式简化配置：


export default [
  ...baseConfig,
  {
    files: ['packages/*/src/**/*.{ts,tsx}', 'apps/*/src/**/*.{ts,tsx}'],
    languageOptions: {
      parserOptions: {
        project: true,
        tsconfigRootDir: import.meta.dirname,
      },
    },
  },
];

按变更包触发 Lint
大型 monorepo 中全量 lint 的成本过高。通过只 lint 受影响的包可以大幅缩短 CI 时间。


npx turbo lint --filter="...[origin/main]"

npx nx affected --target=lint --base=origin/main
手动实现基于 Git diff 的增量 lint：


#!/usr/bin/env bash
CHANGED_PACKAGES=$(git diff --name-only origin/main | \
  grep -E '^(packages|apps)/' | \
  cut -d'/' -f1-2 | \
  sort -u)

for pkg in $CHANGED_PACKAGES; do
  echo "Linting $pkg..."
  npx eslint "$pkg/src/**/*.{ts,tsx}" --max-warnings 0
done
Turborepo 的缓存机制可以跳过未变更包的 lint：


{
  "tasks": {
    "lint": {
      "inputs": ["src/**/*.ts", "src/**/*.tsx", "eslint.config.mjs"],
      "outputs": [],
      "cache": true
    }
  }
}
Biome 在 Monorepo 中的使用
Biome 对 monorepo 有良好的支持，通过根目录的 biome.json 配置统一管理：


{
  "files": {
    "include": ["apps/**", "packages/**"],
    "ignore": ["**/dist/**", "**/node_modules/**"]
  },
  "overrides": [
    {
      "include": ["apps/**/*.tsx"],
      "linter": {
        "rules": {
          "correctness": {
            "useExhaustiveDependencies": "warn"
          }
        }
      }
    },
    {
      "include": ["packages/core/**"],
      "linter": {
        "rules": {
          "style": {
            "noConsole": "error"
          }
        }
      }
    },
    {
      "include": ["scripts/**"],
      "linter": {
        "rules": {
          "style": {
            "noConsole": "off"
          }
        }
      }
    }
  ]
}
Biome 在 monorepo 中的性能优势尤其明显：得益于 Rust 的并行处理能力，全量扫描数千文件仍然可以在秒级完成，减少了对增量 lint 的依赖。

小结
    

  • Monorepo lint 采用根配置 + 包级覆盖的分层架构，在统一和自治之间取得平衡
    • 

  • TypeScript 类型感知规则需要正确配置每个包的 tsconfig.json 路径
    • 

  • 大型 monorepo 通过 Turborepo/Nx 的变更检测只 lint 受影响的包
    • 

  • Biome 的 Rust 并行处理使得全量扫描仍在秒级完成，减少了对增量策略的依赖
    • 

  • package.json 的 lint 脚本应同时支持全量和增量两种模式
