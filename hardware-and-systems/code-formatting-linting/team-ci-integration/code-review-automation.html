代码审查自动化

核心概念

代码审查自动化是将代码质量检查从人工评审中解放出来的实践——通过工具自动检测格式问题、潜在 bug、安全漏洞和编码规范违规，让人工审查聚焦于架构设计、业务逻辑和可维护性等只有人类才能判断的维度。自动化审查不是替代人工审查，而是通过消除低价值的机械检查来提升整体审查效率。

GitHub PR 自动化工具
GitHub 生态提供了丰富的自动化代码审查工具，它们通过 GitHub App 或 Actions 集成到 PR 工作流中。


Danger.js：一个可编程的 PR 审查自动化框架。它可以读取 PR 的文件变更、提交消息等信息，然后根据自定义规则在 PR 中留下评论。


import { danger, warn, fail, message } from 'danger';

const modifiedFiles = danger.git.modified_files;
const createdFiles = danger.git.created_files;

if (modifiedFiles.includes('package.json') && !modifiedFiles.includes('pnpm-lock.yaml')) {
  warn('package.json 已修改但 lockfile 未更新');
}

const bigPR = danger.github.pr.additions + danger.github.pr.deletions > 500;
if (bigPR) {
  warn('此 PR 变更超过 500 行，建议拆分为更小的 PR');
}

const hasTests = modifiedFiles.some((f) => f.includes('.test.') || f.includes('.spec.'));
const hasSrcChanges = modifiedFiles.some((f) => f.includes('/src/'));
if (hasSrcChanges && !hasTests) {
  warn('源码有变更但未添加或修改测试文件');
}

const newFiles = createdFiles.filter((f) => f.endsWith('.ts') || f.endsWith('.tsx'));
for (const file of newFiles) {
  const content = await danger.github.utils.fileContents(file);
  if (content.split('\n').length > 300) {
    fail(`${file} 超过 300 行，请拆分为更小的模块`);
  }
}
GitHub Actions Bot 评论：直接在 Actions 中生成 PR 评论：


- name: Comment PR with lint results
  if: failure()
  uses: actions/github-script@v7
  with:
    script: |
      const body = `### Lint Check Failed
      Please run \`npm run lint:fix\` to fix the issues.`;
      await github.rest.issues.createComment({
        owner: context.repo.owner,
        repo: context.repo.repo,
        issue_number: context.issue.number,
        body,
      });
自动修复与 Bot 提交
一种更激进的自动化策略是让 CI 自动修复格式问题并提交到 PR 分支。


name: Auto Fix
on:
  pull_request:
    types: [opened, synchronize]

permissions:
  contents: write

jobs:
  auto-fix:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.head_ref }}
          token: ${{ secrets.GITHUB_TOKEN }}

      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - run: pnpm biome check --write .

      - name: Commit fixes
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add -A
          git diff --staged --quiet || git commit -m "style: auto-fix formatting"
          git push

自动修复的风险控制：只让 Bot 处理确定安全的修复（格式化、导入排序），不处理可能改变语义的修复（ESLint autofix 中的 suggestion 类型）。


代码质量仪表盘
长期追踪代码质量趋势有助于发现退化和指导改进方向。


interface QualityMetrics {
  lintWarnings: number;
  lintErrors: number;
  typeErrors: number;
  testCoverage: number;
  codeComplexity: number;
  duplicateCode: number;
  techDebt: number;
}
通过 CI 收集指标并输出为结构化数据：


- name: Collect quality metrics
  run: |
    LINT_WARNINGS=$(eslint . --format json | jq '[.[].warningCount] | add')
    LINT_ERRORS=$(eslint . --format json | jq '[.[].errorCount] | add')
    COVERAGE=$(npx vitest --coverage --reporter=json | jq '.total.lines.pct')
    echo "lint_warnings=$LINT_WARNINGS" >> $GITHUB_OUTPUT
    echo "lint_errors=$LINT_ERRORS" >> $GITHUB_OUTPUT
    echo "coverage=$COVERAGE" >> $GITHUB_OUTPUT

审查流程最佳实践
一个高效的代码审查流程应该将自动化检查和人工审查有机结合。


Pre-merge 检查清单：


const preMergeChecklist = {
  automated: ['格式化检查通过', 'Lint 检查通过（zero warnings）', '类型检查通过', '单元测试通过', '覆盖率未下降'],
  manual: ['至少一位 reviewer approve', '架构变更经过设计讨论', '文档已更新（如需要）', '变更描述清晰'],
};
Branch Protection Rules：


required_status_checks:
  strict: true
  contexts:
    - 'lint'
    - 'typecheck'
    - 'test'
required_pull_request_reviews:
  required_approving_review_count: 1
  dismiss_stale_reviews: true

小结
    

  • 代码审查自动化的目标是消除低价值的机械检查，让人工审查聚焦于架构和业务逻辑
    • 

  • Danger.js 提供了可编程的 PR 审查框架，支持自定义检查规则和评论
    • 

  • 自动修复 + Bot 提交可以实现零摩擦的格式化，但需要限制为确定安全的修复
    • 

  • 代码质量指标的长期追踪有助于发现退化趋势和指导改进方向
    • 

  • Branch Protection Rules 确保自动化检查和人工审查都不可绕过
    •
