ESLint 架构与工作原理

核心概念

ESLint 是 JavaScript/TypeScript 生态中最广泛使用的静态代码分析工具。它的核心架构基于规则引擎模式——将代码解析为 AST，然后让每条规则独立地遍历 AST 节点，报告它发现的问题。这种架构使得 ESLint 具有极强的可扩展性，社区可以为任何编码规范编写自定义规则。

ESLint 的设计核心理念是一切皆可插拔：解析器、规则、格式化器、配置都可以由社区扩展。


解析器与 AST 标准
ESLint 的工作起点是将源代码解析为 AST。默认使用 Espree（基于 Acorn）解析器，但通过配置可以替换为其他兼容的解析器。


interface ParserInterface {
  parse(code: string, options: ParserOptions): AST.Program;
  parseForESLint?(
    code: string,
    options: ParserOptions,
  ): {
    ast: AST.Program;
    services?: Record<string, unknown>;
    scopeManager?: ScopeManager;
    visitorKeys?: VisitorKeys;
  };
}
ESLint 使用的 AST 遵循 ESTree 规范——一个由 Mozilla 发起的 JavaScript AST 标准。ESTree 定义了每种语法结构对应的节点类型和属性：


interface FunctionDeclaration extends Node {
  type: 'FunctionDeclaration';
  id: Identifier | null;
  params: Pattern[];
  body: BlockStatement;
  generator: boolean;
  async: boolean;
}

interface VariableDeclaration extends Node {
  type: 'VariableDeclaration';
  declarations: VariableDeclarator[];
  kind: 'var' | 'let' | 'const';
}
对于 TypeScript 代码，需要使用 @typescript-eslint/parser，它基于 TypeScript Compiler API 生成的 AST，并转换为 ESTree 兼容格式。这个解析器还可以提供类型信息服务，使得规则能够进行类型感知的分析：


const parserOptions = {
  parser: '@typescript-eslint/parser',
  parserOptions: {
    project: './tsconfig.json',
    tsconfigRootDir: __dirname,
    ecmaFeatures: { jsx: true },
  },
};
规则引擎与访问者模式
ESLint 规则引擎的核心是访问者模式（Visitor Pattern）。每条规则声明它感兴趣的 AST 节点类型，引擎在遍历 AST 时将匹配的节点分发给对应的规则。


interface RuleModule {
  meta: {
    type: 'problem' | 'suggestion' | 'layout';
    docs: { description: string; recommended: boolean };
    fixable?: 'code' | 'whitespace';
    hasSuggestions?: boolean;
    schema: JSONSchema[];
    messages: Record<string, string>;
  };
  create(context: RuleContext): RuleListeners;
}

type RuleListeners = {
  [nodeType: string]: (node: ASTNode) => void;
};
规则引擎的执行流程：


function runRules(ast: AST.Program, rules: Map<string, RuleModule>, config: Config): LintMessage[] {
  const messages: LintMessage[] = [];
  const visitors = new Map<string, Array<(node: ASTNode) => void>>();

  for (const [ruleId, ruleModule] of rules) {
    const context = createRuleContext(ruleId, config, messages);
    const listeners = ruleModule.create(context);

    for (const [selector, handler] of Object.entries(listeners)) {
      if (!visitors.has(selector)) visitors.set(selector, []);
      visitors.get(selector)!.push(handler);
    }
  }

  traverseAST(ast, (node, phase) => {
    const key = phase === 'enter' ? node.type : `${node.type}:exit`;
    for (const handler of visitors.get(key) ?? []) {
      handler(node);
    }
  });

  return messages;
}
ESLint 支持使用 ESQuery 选择器作为 visitor key，允许更精确的节点匹配：


const ruleListeners = {
  "CallExpression[callee.name='eval']"(node: ASTNode) {
    context.report({ node, messageId: 'noEval' });
  },
  "VariableDeclaration[kind='var']"(node: ASTNode) {
    context.report({ node, messageId: 'noVar' });
  },
  "MemberExpression[object.name='console']"(node: ASTNode) {
    context.report({ node, messageId: 'noConsole' });
  },
};
自动修复机制
ESLint 的自动修复（--fix）是通过文本级操作实现的，而非 AST 级变换。每个规则在报告问题时可以提供一个 fix 函数，该函数返回一组文本替换操作。


context.report({
  node,
  messageId: 'preferConst',
  fix(fixer: RuleFixer): Fix | Fix[] {
    return fixer.replaceTextRange([node.start, node.start + 3], 'const');
  },
});

interface RuleFixer {
  insertTextAfter(node: ASTNode, text: string): Fix;
  insertTextBefore(node: ASTNode, text: string): Fix;
  remove(node: ASTNode): Fix;
  removeRange(range: [number, number]): Fix;
  replaceText(node: ASTNode, text: string): Fix;
  replaceTextRange(range: [number, number], text: string): Fix;
}
修复操作的应用遵循严格的冲突检测规则：当两个修复操作涉及重叠的文本范围时，ESLint 只会应用其中一个，并在下一轮 --fix 中处理另一个。这也是为什么有时需要运行多次 --fix 才能修复所有问题。

作用域分析与变量追踪
ESLint 内置了作用域分析器（Scope Analyzer），它基于 eslint-scope 库构建变量的作用域链。这使得规则能够追踪变量的声明、引用和赋值情况。


interface Scope {
  type: 'global' | 'function' | 'block' | 'module' | 'class';
  variables: Variable[];
  references: Reference[];
  childScopes: Scope[];
  upper: Scope | null;
}

interface Variable {
  name: string;
  scope: Scope;
  defs: Definition[];
  references: Reference[];
  identifiers: Identifier[];
}
no-unused-vars 规则就是基于作用域分析实现的——它检查每个变量的 references 数组，如果只有声明（定义）而没有读取引用，则报告该变量未使用。


小结
    

  • ESLint 的核心架构基于"解析 → 遍历 → 规则匹配 → 问题报告"的管道模式
    • 

  • 访问者模式使每条规则独立运行，互不干扰，支持极高的可扩展性
    • 

  • 解析器可替换是关键设计，使得 ESLint 从 JavaScript 扩展到 TypeScript、Vue 等语言
    • 

  • 自动修复采用文本级操作而非 AST 变换，通过冲突检测保证安全性
    • 

  • 作用域分析器为变量追踪类规则（如 no-unused-vars）提供了基础设施
    •
