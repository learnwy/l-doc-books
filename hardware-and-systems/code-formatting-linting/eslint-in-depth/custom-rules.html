自定义 ESLint 规则开发

核心概念

自定义 ESLint 规则是将团队编码规范转化为自动化检查的核心手段。每条 ESLint 规则本质上是一个AST 访问者——它声明自己关心哪些类型的 AST 节点，然后在 ESLint 遍历 AST 时接收这些节点并执行检查逻辑。理解规则的结构和 API 是编写高质量自定义规则的基础。

规则结构与 Meta 信息
每条 ESLint 规则由两部分组成：meta 对象描述规则的元信息，create 函数返回 AST 访问者。


import type { Rule } from 'eslint';

const noMagicNumbers: Rule.RuleModule = {
  meta: {
    type: 'suggestion',
    docs: {
      description: '禁止使用未命名的数字字面量（魔法数字）',
      recommended: true,
    },
    fixable: 'code',
    hasSuggestions: true,
    schema: [
      {
        type: 'object',
        properties: {
          ignore: {
            type: 'array',
            items: { type: 'number' },
            uniqueItems: true,
          },
          ignoreArrayIndexes: { type: 'boolean' },
          enforceConst: { type: 'boolean' },
        },
        additionalProperties: false,
      },
    ],
    messages: {
      noMagic: "不允许使用魔法数字 '{{value}}'，请提取为命名常量",
      suggestConst: '提取为 const 常量',
    },
  },

  create(context) {
    const options = context.options[0] ?? {};
    const ignoredValues = new Set(options.ignore ?? [0, 1, -1]);

    return {
      Literal(node) {
        if (typeof node.value !== 'number') return;
        if (ignoredValues.has(node.value)) return;
        if (node.parent.type === 'VariableDeclarator') return;

        context.report({
          node,
          messageId: 'noMagic',
          data: { value: String(node.value) },
          suggest: [
            {
              messageId: 'suggestConst',
              fix(fixer) {
                const constName = `MAGIC_${node.value}`;
                return [
                  fixer.insertTextBefore(context.sourceCode.ast.body[0], `const ${constName} = ${node.value};\n`),
                  fixer.replaceText(node, constName),
                ];
              },
            },
          ],
        });
      },
    };
  },
};

RuleContext API 详解
create 函数接收的 context 对象提供了丰富的 API，是规则与 ESLint 引擎交互的唯一通道。


interface RuleContext {
  id: string;
  options: unknown[];
  settings: Record<string, unknown>;
  parserPath: string;
  languageOptions: LanguageOptions;
  sourceCode: SourceCode;
  filename: string;
  cwd: string;

  report(descriptor: ReportDescriptor): void;
  getScope(): Scope;
  getAncestors(): ASTNode[];
  getDeclaredVariables(node: ASTNode): Variable[];
  markVariableAsUsed(name: string): boolean;
}
SourceCode 是最常用的 API 之一，它提供了对源代码文本和 Token 序列的访问：


interface SourceCode {
  ast: AST.Program;
  text: string;
  lines: string[];

  getText(node?: ASTNode): string;
  getTokenBefore(node: ASTNode): Token | null;
  getTokenAfter(node: ASTNode): Token | null;
  getTokensBetween(left: ASTNode, right: ASTNode): Token[];
  getCommentsBefore(node: ASTNode): Comment[];
  getCommentsAfter(node: ASTNode): Comment[];
  getScope(node: ASTNode): Scope;

  isSpaceBetweenTokens(first: Token, second: Token): boolean;
}
实际开发中常用的 SourceCode 方法示例：


const enforceImportOrder: Rule.RuleModule = {
  meta: {
    type: 'suggestion',
    fixable: 'code',
    messages: {
      wrongOrder: "导入语句顺序不正确，'{{current}}' 应在 '{{expected}}' 之前",
    },
  },

  create(context) {
    const sourceCode = context.sourceCode;

    return {
      Program(node) {
        const importNodes = node.body.filter((n): n is ImportDeclaration => n.type === 'ImportDeclaration');

        for (let i = 1; i < importNodes.length; i++) {
          const prev = importNodes[i - 1];
          const curr = importNodes[i];
          const prevSource = prev.source.value as string;
          const currSource = curr.source.value as string;

          if (shouldComeBefore(currSource, prevSource)) {
            context.report({
              node: curr,
              messageId: 'wrongOrder',
              data: { current: currSource, expected: prevSource },
              fix(fixer) {
                const prevText = sourceCode.getText(prev);
                const currText = sourceCode.getText(curr);
                return [fixer.replaceText(prev, currText), fixer.replaceText(curr, prevText)];
              },
            });
          }
        }
      },
    };
  },
};
类型感知规则开发
当配置了 @typescript-eslint/parser 并提供 tsconfig.json 时，规则可以访问 TypeScript 的类型信息，编写更精确的检查。


import type { TSESTree } from '@typescript-eslint/utils';
import { ESLintUtils } from '@typescript-eslint/utils';

const createRule = ESLintUtils.RuleCreator((name) => `https://example.com/rules/${name}`);

const noFloatingPromises = createRule({
  name: 'no-floating-promises',
  meta: {
    type: 'problem',
    docs: { description: '要求处理 Promise 的返回值' },
    messages: {
      floating: 'Promise 必须被 await、return 或通过 .catch() 处理',
    },
    schema: [],
  },
  defaultOptions: [],

  create(context) {
    const services = ESLintUtils.getParserServices(context);
    const checker = services.program.getTypeChecker();

    return {
      ExpressionStatement(node: TSESTree.ExpressionStatement) {
        const tsNode = services.esTreeNodeToTSNodeMap.get(node.expression);
        const type = checker.getTypeAtLocation(tsNode);

        if (isPromiseLike(checker, type)) {
          context.report({
            node: node.expression,
            messageId: 'floating',
          });
        }
      },
    };
  },
});

测试与调试策略
ESLint 提供了 RuleTester 类用于规则的单元测试。每个测试用例由输入代码和期望的错误（或无错误）组成：


import { RuleTester } from 'eslint';

const ruleTester = new RuleTester({
  languageOptions: { ecmaVersion: 2022, sourceType: 'module' },
});

ruleTester.run('no-magic-numbers', noMagicNumbers, {
  valid: [
    'const MAX_RETRIES = 3;',
    'const arr = [0, 1];',
    'for (let i = 0; i < arr.length; i++) {}',
    { code: 'const x = 42;', options: [{ ignore: [42] }] },
  ],
  invalid: [
    {
      code: 'if (count > 5) {}',
      errors: [{ messageId: 'noMagic', data: { value: '5' } }],
    },
    {
      code: 'setTimeout(fn, 3000);',
      errors: [{ messageId: 'noMagic', data: { value: '3000' } }],
    },
    {
      code: 'const margin = width * 0.15;',
      errors: [
        {
          messageId: 'noMagic',
          data: { value: '0.15' },
          suggestions: [
            {
              messageId: 'suggestConst',
              output: 'const MAGIC_0.15 = 0.15;\nconst margin = width * MAGIC_0.15;',
            },
          ],
        },
      ],
    },
  ],
});

小结
    

  • 自定义 ESLint 规则的核心是实现 create 函数，返回 AST 节点的访问者处理器
    • 

  • meta 对象定义了规则的类型、可修复性、配置 schema 和错误消息模板
    • 

  • RuleContext 和 SourceCode 提供了丰富的 API 用于节点分析、文本操作和作用域查询
    • 

  • 类型感知规则通过 TypeScript 的 TypeChecker API 实现更精确的代码分析
    • 

  • RuleTester 提供了声明式的测试框架，确保规则在各种场景下正确工作
    •
