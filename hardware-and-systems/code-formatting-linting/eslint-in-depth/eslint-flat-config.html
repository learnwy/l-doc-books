ESLint Flat Config 迁移与实践

核心概念

ESLint 9.0 将 Flat Config 确立为默认配置格式，取代了沿用多年的 .eslintrc 级联配置系统。Flat Config 的核心变化是：配置文件从 JSON/YAML 的声明式格式变为纯 JavaScript/TypeScript 的编程式格式，配置不再通过目录层级级联，而是在一个数组中显式定义所有规则的应用范围。

Flat Config 的设计动机是消除配置的隐式行为——开发者不再需要理解 extends 链的合并规则、.eslintrc 的目录查找算法、以及 overrides 的优先级逻辑。


配置文件结构
Flat Config 使用 eslint.config.mjs（或 .js / .ts）作为配置文件，导出一个配置对象数组：


import eslint from '@eslint/js';
import tseslint from 'typescript-eslint';
import reactPlugin from 'eslint-plugin-react';
import reactHooks from 'eslint-plugin-react-hooks';

export default tseslint.config(
  eslint.configs.recommended,
  ...tseslint.configs.recommended,

  {
    files: ['**/*.{ts,tsx}'],
    plugins: {
      react: reactPlugin,
      'react-hooks': reactHooks,
    },
    languageOptions: {
      parser: tseslint.parser,
      parserOptions: {
        ecmaFeatures: { jsx: true },
        project: './tsconfig.json',
      },
    },
    settings: {
      react: { version: 'detect' },
    },
    rules: {
      'react/jsx-no-target-blank': 'error',
      'react-hooks/rules-of-hooks': 'error',
      'react-hooks/exhaustive-deps': 'warn',
    },
  },

  {
    files: ['**/*.test.{ts,tsx}'],
    rules: {
      '@typescript-eslint/no-explicit-any': 'off',
    },
  },

  {
    ignores: ['dist/**', 'node_modules/**', '*.config.{js,mjs}'],
  },
);
配置数组中每个对象的核心字段：


interface FlatConfig {
  name?: string;
  files?: string[];
  ignores?: string[];
  languageOptions?: {
    ecmaVersion?: number;
    sourceType?: 'module' | 'commonjs' | 'script';
    parser?: Parser;
    parserOptions?: Record<string, unknown>;
    globals?: Record<string, 'readonly' | 'writable' | 'off'>;
  };
  plugins?: Record<string, Plugin>;
  rules?: Record<string, RuleConfig>;
  settings?: Record<string, unknown>;
  linterOptions?: {
    noInlineConfig?: boolean;
    reportUnusedDisableDirectives?: Severity;
  };
  processor?: Processor;
}
从 .eslintrc 迁移
迁移的核心工作是将 .eslintrc 中的声明式配置转换为 Flat Config 的编程式表达。


extends → 数组展开：旧配置中的 extends 继承链变为配置数组中的展开：


// 旧配置
const legacy = {
  extends: ['eslint:recommended', 'plugin:@typescript-eslint/recommended', 'prettier'],
};

// Flat Config 等价
import eslint from '@eslint/js';
import tseslint from 'typescript-eslint';
import prettierConfig from 'eslint-config-prettier';

export default [eslint.configs.recommended, ...tseslint.configs.recommended, prettierConfig];
plugins 字符串 → import 对象：旧配置通过字符串名称引用插件，Flat Config 直接导入：


// 旧配置
const legacy = {
  plugins: ['@typescript-eslint', 'import'],
};

// Flat Config
import tseslint from 'typescript-eslint';
import importPlugin from 'eslint-plugin-import-x';

export default [
  {
    plugins: {
      '@typescript-eslint': tseslint.plugin,
      'import-x': importPlugin,
    },
  },
];
overrides → 独立配置对象：旧配置中的 overrides 数组变为顶层配置数组中的独立对象：


// 旧配置
const legacy = {
  overrides: [
    {
      files: ['*.test.ts'],
      env: { jest: true },
      rules: { 'no-console': 'off' },
    },
  ],
};

// Flat Config
import globals from 'globals';

export default [
  {
    files: ['**/*.test.ts'],
    languageOptions: {
      globals: { ...globals.jest },
    },
    rules: { 'no-console': 'off' },
  },
];
高级配置模式
Flat Config 的编程式特性使得一些高级配置模式成为可能。


条件配置：根据环境变量或项目特征动态生成配置：


const isCI = process.env.CI === 'true';

export default [
  eslint.configs.recommended,
  ...tseslint.configs.recommended,
  {
    rules: {
      'no-console': isCI ? 'error' : 'warn',
      'no-debugger': isCI ? 'error' : 'warn',
    },
  },
];
配置工厂函数：为组织内的多个项目提供统一的配置生成器：


interface ProjectConfig {
  type: 'app' | 'library' | 'script';
  framework?: 'react' | 'vue' | 'none';
  strictness: 'relaxed' | 'standard' | 'strict';
}

function createLintConfig(project: ProjectConfig): FlatConfig[] {
  const configs: FlatConfig[] = [eslint.configs.recommended, ...tseslint.configs.recommended];

  if (project.framework === 'react') {
    configs.push(...reactConfigs);
  }

  if (project.strictness === 'strict') {
    configs.push({
      rules: {
        '@typescript-eslint/no-explicit-any': 'error',
        '@typescript-eslint/strict-boolean-expressions': 'error',
        '@typescript-eslint/no-unsafe-assignment': 'error',
      },
    });
  }

  if (project.type === 'library') {
    configs.push({
      rules: {
        'no-console': 'error',
      },
    });
  }

  return configs;
}
命名配置：使用 name 字段为配置对象命名，方便调试：


export default [
  { name: 'base/recommended', ...eslint.configs.recommended },
  { name: 'typescript/recommended', ...tseslint.configs.recommended[0] },
  {
    name: 'project/test-overrides',
    files: ['**/*.test.ts'],
    rules: { '@typescript-eslint/no-explicit-any': 'off' },
  },
];

兼容性与生态适配
Flat Config 迁移过程中最大的挑战是插件生态的兼容性。并非所有 ESLint 插件都已适配 Flat Config 格式。


ESLint 提供了 @eslint/compat 包来桥接旧插件：


import { fixupPluginRules, fixupConfigRules } from '@eslint/compat';
import legacyPlugin from 'eslint-plugin-legacy';

export default [
  {
    plugins: {
      legacy: fixupPluginRules(legacyPlugin),
    },
  },
];

对于仍使用旧配置格式的项目，ESLint 9.x 提供了环境变量 ESLINT_USE_FLAT_CONFIG=false 来暂时使用旧配置，但这一选项将在未来版本中移除。


小结
    

  • Flat Config 用 JavaScript 数组替代 JSON 级联配置，消除了 extends 链的隐式合并逻辑
    • 

  • 迁移的核心步骤是将 extends → 数组展开、plugins 字符串 → import 对象、overrides → 带 files 的配置对象
    • 

  • 编程式配置支持条件逻辑、工厂函数、动态加载等旧格式无法实现的高级模式
    • 

  • @eslint/compat 包为尚未适配 Flat Config 的旧插件提供了桥接方案
    • 

  • 主流插件（typescript-eslint、react、prettier）已原生支持 Flat Config 格式
    •
