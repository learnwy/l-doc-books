NetFlow 与网络可观测性

网络流量遥测协议

网络流量遥测是网络可观测性的数据基础。通过在路由器、交换机和防火墙上启用流量遥测，可以获取网络中"谁在和谁通信、什么时候、传输了多少数据"的完整画面，而无需捕获和存储完整的数据包。

NetFlow 的演进

NetFlow 由 Cisco 在 1996 年引入，最初设计用于网络流量计费和规划。它的核心概念是"流"（Flow）——一组具有相同属性（源IP、目的IP、源端口、目的端口、协议、ToS、输入接口）的连续数据包构成一个流。路由器/交换机维护流缓存表，记录每个流的统计信息（数据包数、字节数、开始时间、结束时间），当流结束或超时后将流记录导出到收集器。

NetFlow v5 是使用最广泛的版本，使用固定的记录格式，包含约 20 个字段。v5 的局限是不支持 IPv6 和自定义字段。

NetFlow v9 引入了模板化架构——记录格式不再固定，而是通过模板定义。这使得 NetFlow v9 可以支持 IPv6、MPLS 标签、BGP AS 号等新信息，也允许厂商添加自定义字段。

IPFIX（IP Flow Information Export, RFC 7011）是 IETF 基于 NetFlow v9 标准化的流量导出协议。IPFIX 被视为 NetFlow v9 的"标准版本"，在协议层面几乎等价，但 IPFIX 支持可变长度字段和企业特定的信息元素（Enterprise-Specific Information Elements）。

其他遥测协议

sFlow（RFC 3176）采用与 NetFlow 不同的方式——不是追踪完整的流，而是按照设定的采样率（如每 1000 个数据包采样 1 个）对数据包头进行采样。sFlow 的优势是对网络设备的性能影响极小（因为只是采样，不需要维护流缓存表），劣势是采样可能遗漏低频但重要的通信。sFlow 在高速交换网络中特别流行，尤其是非 Cisco 厂商（Juniper、Arista、Dell）的设备。

流量日志：NGFW 和代理服务器生成的连接日志在功能上类似于 NetFlow，但通常包含更丰富的应用层信息——应用识别结果、URL 分类、用户身份、威胁判定等。Palo Alto 的 Traffic Log、Zscaler 的 Web Log 都是重要的网络遥测数据源。

协议 标准 采样/全流 特点 典型设备
NetFlow v5 Cisco 私有 全流 固定格式，成熟稳定 Cisco 路由器/交换机
NetFlow v9 Cisco 私有 全流 模板化，支持 IPv6 Cisco 设备
IPFIX RFC 7011 全流 标准化，可扩展 多厂商支持
sFlow RFC 3176 采样 低开销，适合高速网络 Juniper/Arista/Dell
VPC Flow Logs 云平台专有 全流/采样 云原生，包含 VPC 上下文 AWS/Azure/GCP

流量收集与存储架构

收集器架构

NetFlow/IPFIX 记录从网络设备导出后，需要由流量收集器接收、解析和存储。收集器的设计需要处理大规模数据吞入——一个大型企业网络每秒可能产生数万到数十万条流记录。

开源收集器：GoFlow2（Go 语言实现，高性能）、nfdump/nfsen（经典的 NetFlow 分析工具集）、pmacct（支持 NetFlow/IPFIX/sFlow 的多功能采集器）、Logstash（通过 netflow codec 接收 NetFlow 并输出到 Elasticsearch）。

存储后端选择：流记录的存储需要在查询性能和存储成本之间取得平衡。

时序数据库（ClickHouse、TimescaleDB）天然适合存储和查询带时间戳的流记录。ClickHouse 的列式存储和向量化执行引擎在流量分析的聚合查询中表现出色——"过去 7 天按目的端口统计连接数"这类查询可以在亚秒级完成。

Elasticsearch 提供了灵活的全文搜索和结构化查询能力，配合 Kibana 可以快速构建可视化仪表板。劣势是存储效率和大规模聚合查询性能不如专用时序数据库。

数据湖（AWS S3 + Athena、GCP BigQuery）适用于超大规模的长期存储和偶发的复杂分析查询。成本最低，但查询延迟较高。

数据保留策略

流记录的保留时间需要平衡存储成本和安全分析需求。建议的分层策略：

  • 高分辨率数据（完整流记录）保留 30-90 天——用于安全事件调查和威胁狩猎
  • 聚合数据（每小时/每天的统计汇总）保留 12-24 个月——用于趋势分析和基线比较
  • 告警和异常事件的原始数据永久保留——用于合规审计和事后取证

基于流量的安全分析

基线建模与异常检测

网络可观测性的安全价值始于基线建模——了解"正常是什么样的"才能发现"异常"。

基线建模的关键维度：

通信关系基线：哪些主机之间通常有通信？使用什么协议和端口？通信方向和频率如何？当一台从未与外部 IP 通信的内部服务器突然向境外 IP 发送 DNS 查询时，这就是偏离通信关系基线的异常。

流量体量基线：每个网段、每个应用的正常流量范围是什么？日间和夜间的差异有多大？工作日和周末的差异有多大？当夜间流量突然飙升到日间的 3 倍时，可能是 DDoS 攻击、数据外传或系统异常。

协议分布基线：正常情况下 DNS 流量占总流量的比例是多少？如果 DNS 流量占比突然从 2% 飙升到 15%，可能是 DNS 隧道数据外传。

威胁狩猎

网络遥测数据是威胁狩猎（Threat Hunting）的核心数据源之一。威胁狩猎是安全分析师主动搜索网络中可能存在的已入侵但未被自动检测发现的威胁。

常见的基于流量的狩猎查询：

内部扫描行为：查找在短时间内连接大量不同内部 IP 地址的主机——可能是攻击者在进行内网侦察。

查询示例（伪 SQL）：
SELECT src_ip, COUNT(DISTINCT dst_ip) as target_count
FROM flow_records
WHERE timestamp > NOW() - INTERVAL 1 HOUR
  AND src_ip IN (内网地址范围)
  AND dst_ip IN (内网地址范围)
GROUP BY src_ip
HAVING target_count > 50
ORDER BY target_count DESC

异常外联：查找与已知恶意 IP/域名通信的内部主机、与新注册域名通信的主机、以及使用非标准端口进行 HTTP/HTTPS 通信的主机。

数据外传嫌疑：查找上传数据量异常大的内部主机，特别是在非工作时间向外部 IP 传输大量数据的行为。

长连接检测：查找持续时间异常长的网络连接——可能是 C2 长连接、SSH 隧道或未关闭的异常会话。

安全事件响应辅助

当安全事件发生时，网络遥测数据为事件响应提供了关键的时间线重建能力：

攻击时间线重建：通过查询受感染主机在入侵时间窗口内的所有网络通信记录，重建攻击者的活动时间线——何时建立 C2 通信、何时开始横向移动、访问了哪些内部系统、是否有数据外传。

影响范围评估：通过查询与受感染主机有通信的所有内部主机，快速评估攻击的横向传播范围——哪些主机可能也已被入侵。

IoC 回溯搜索：当获取新的入侵指标（恶意 IP、恶意域名、C2 服务器地址）时，通过回溯搜索历史流量记录，检查组织内是否有主机在过去与这些指标有通信——这可能揭示已经存在但未被发现的入侵。

网络可观测性平台

从监控到可观测性

传统网络监控关注的是"设备是否在线、端口是否联通、带宽利用率是否正常"。网络可观测性（Network Observability）是更高层次的概念——它不仅关注"发生了什么"，还关注"为什么发生"和"会产生什么影响"。

可观测性的三大支柱在网络领域的映射：

指标（Metrics）：接口流量速率、CPU 利用率、丢包率、延迟、抖动等数值型时序数据。通过 SNMP polling、Streaming Telemetry 或 gNMI 收集。

日志（Logs）：设备日志（syslog）、安全事件日志、变更日志。结构化日志（如 JSON 格式的 syslog）便于自动化分析。

流量（Flows）：NetFlow/IPFIX/sFlow 记录提供了指标和日志之外的第三维度数据——网络通信的关系和内容特征。

Streaming Telemetry
传统的 SNMP polling（设备被动等待管理站查询）正在被 Streaming Telemetry（设备主动推送数据）替代。


Streaming Telemetry 使用 gRPC/gNMI 协议，设备按照订阅的数据路径和频率主动向收集器推送结构化数据（YANG 模型定义）。相比 SNMP 的优势：更高的数据粒度（可以做到秒级甚至亚秒级采集）、更低的设备 CPU 开销（推送而非轮询）、更丰富的数据模型（YANG 模型比 MIB 更灵活），以及更好的扩展性。


主流网络厂商（Cisco、Juniper、Arista、Nokia）在 2025 年的设备操作系统中都已原生支持 gNMI Streaming Telemetry。开源的遥测收集器包括 Telegraf（InfluxData 的数据采集代理）和 gnmic（专注于 gNMI 的采集工具）。


开源可观测性方案
构建开源网络可观测性平台的典型技术栈：


数据采集：Telegraf（SNMP + gNMI）+ GoFlow2（NetFlow/IPFIX/sFlow）+ Filebeat（设备日志）


存储与分析：ClickHouse（流记录和指标的高性能分析）或 Elasticsearch（全文搜索和灵活查询）+ Prometheus（时序指标）


可视化：Grafana 作为统一的仪表板层，通过数据源插件连接 ClickHouse、Elasticsearch、Prometheus 等后端。Grafana 的 FlowCharting 和 Network 面板可以构建网络拓扑图和流量热力图。


告警：Grafana Alerting 或 Prometheus Alertmanager 提供基于阈值和趋势的告警能力。


实践案例：构建安全导向的网络可观测性
一个面向安全用例的网络可观测性平台应该提供以下核心仪表板：


全局流量态势：实时显示南北向和东西向流量的总量、协议分布、Top N 源/目的 IP、Top N 应用。用于快速感知网络流量的整体健康状态和异常变化。


异常通信监控：高亮显示偏离基线的通信——新出现的内部到外部通信关系、异常的流量体量变化、非标准端口上的通信。这是安全分析师日常巡检的核心视图。


DNS 安全分析：DNS 查询量趋势、NXDOMAIN 比例、Top N 查询域名、DGA 域名检测结果、DNS 隧道可疑指标。DNS 是几乎所有网络攻击都会涉及的协议，DNS 分析是高效的威胁检测入口。


事件响应工作台：输入一个可疑 IP 或主机名，自动展示该目标的所有网络通信历史——通信对端、使用的协议和端口、传输的数据量、时间分布。为安全分析师的调查提供即时的网络上下文。
