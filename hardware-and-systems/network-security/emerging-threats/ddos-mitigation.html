DDoS 攻击防御体系

DDoS 攻击的演变与现状

分布式拒绝服务攻击（Distributed Denial of Service, DDoS）是通过大量分布式攻击源向目标发送海量流量或请求，耗尽目标的网络带宽、服务器资源或应用处理能力，导致合法用户无法正常访问服务。DDoS 是最古老也最持久的网络威胁之一——从 2000 年 MafiaBoy 对 Yahoo、eBay 的早期攻击，到 2025 年峰值超过 5 Tbps 的超大规模攻击，DDoS 的规模和复杂度在持续增长。

根据 Cloudflare 2025 年 DDoS 威胁报告的数据，DDoS 攻击呈现以下趋势：

规模持续扩大：物联网僵尸网络（Mirai 变种及其后继者）使得攻击者可以调动数十万甚至上百万的受感染设备发起攻击。2024 年 Q4 记录到的最大 DDoS 攻击峰值突破 5.6 Tbps。

攻击更加多向量：现代 DDoS 攻击不再使用单一的攻击技术，而是同时发起多个向量（TCP SYN Flood + UDP Amplification + HTTP Flood）的组合攻击，增加防御的复杂度。

应用层攻击增长：相比容量型攻击（Volumetric Attack），应用层 DDoS（L7 DDoS）的增长更为显著。HTTP/2 Rapid Reset 攻击（CVE-2023-44487）在 2023 年被发现后，成为 2024—2025 年最常见的应用层 DDoS 技术。

"DDoS 即服务"降低门槛：暗网市场上的 DDoS-as-a-Service（也称为 Booter/Stresser 服务）以每月几十美元的价格提供 DDoS 攻击能力，使得不具备技术能力的攻击者也能发起有效攻击。

DDoS 攻击分类

DDoS 攻击按 OSI 层次和攻击原理可以分为三大类：

容量型攻击（L3/L4）

容量型攻击的目标是用大量流量淹没目标的网络带宽或网络设备的处理能力。

UDP Flood：发送大量 UDP 数据包到目标的随机端口。目标系统检查每个端口是否有监听的应用，对于没有应用监听的端口返回 ICMP Port Unreachable——处理这些无效 UDP 包消耗系统资源。

反射放大攻击（Reflection/Amplification）利用开放的网络服务（DNS、NTP、Memcached、SSDP）作为"放大器"。攻击者向这些服务发送伪造源 IP（设为目标 IP）的小请求，服务返回大得多的响应到目标。放大倍数：DNS（28-54×）、NTP monlist（556×）、Memcached（10,000-51,000×）。

SYN Flood：发送大量 TCP SYN 包到目标，不完成三次握手。目标为每个半开连接分配资源（SYN 队列），当 SYN 队列被填满时，合法的 TCP 连接无法建立。

攻击类型 OSI 层 攻击原理 典型带宽 防御方法
UDP Flood L3/L4 大量 UDP 包耗尽带宽 100 Gbps - 5 Tbps 上游清洗/黑洞路由
反射放大 L3/L4 利用开放服务放大流量 500 Gbps - 2 Tbps BCP38 过滤/限速
SYN Flood L4 耗尽 TCP 连接表 10-200 Gbps SYN Cookie/SYN Proxy
ACK Flood L4 大量 ACK 包消耗状态表 10-100 Gbps 状态检测/限速

协议攻击

协议攻击利用网络协议的弱点或实现缺陷来消耗中间设备（防火墙、负载均衡器）的处理能力。

Ping of Death / ICMP Flood：早期经典攻击，通过发送超大或畸形的 ICMP 包导致系统崩溃。现代操作系统已修复相关漏洞，但大量 ICMP 流量仍可消耗带宽。

分片攻击（Fragmentation Attack）：发送大量 IP 分片包，目标系统尝试重组这些分片消耗 CPU 和内存。恶意的不完整分片（Teardrop Attack）可能导致某些系统崩溃。

应用层攻击（L7）

应用层 DDoS 是最难防御的类型，因为每个攻击请求在协议层面看起来都像合法的用户请求。

HTTP Flood：发送大量看似合法的 HTTP GET 或 POST 请求。攻击请求可能针对资源密集的页面（搜索功能、数据库查询页面）以最大化服务器端的处理开销。

HTTP/2 Rapid Reset：利用 HTTP/2 的流重置（RST_STREAM）机制，攻击者快速发送请求然后立即重置，服务器为每个请求分配了处理资源但还来不及完成就被取消。这个攻击在 2023 年 10 月被 Google、Cloudflare 和 AWS 联合披露，创造了当时的最高请求速率纪录（3.98 亿 RPS）。

Slowloris / Slow HTTP：建立大量 HTTP 连接但以极慢的速度发送请求头或请求体，保持连接长时间打开。目标服务器的连接池被慢速连接占满后，无法接受新的合法连接。

DNS 查询洪泛：向目标的 DNS 服务器发送大量查询请求，特别是查询不存在的域名（NXDOMAIN），迫使 DNS 服务器进行递归查询消耗资源。

多层防御架构

有效的 DDoS 防御需要在多个层面协同工作，没有单一的解决方案可以应对所有类型的 DDoS 攻击。

网络层防御（上游清洗）

ISP/上游清洗：当攻击流量超过组织自身网络带宽时，唯一有效的防御是在上游进行流量清洗。ISP 提供的 DDoS 防护服务（如 China Telecom 的云堤、AT&T DDoS Defense）在运营商网络中就过滤攻击流量，只将清洗后的合法流量发送到客户。

黑洞路由（Blackhole Routing / RTBH）：在紧急情况下，可以通过 BGP 向上游宣告将被攻击 IP 的流量路由到"黑洞"（丢弃）。这确实停止了攻击，但也完全中断了该 IP 的正常服务——属于"自杀式防御"。远程触发黑洞（RTBH）允许客户通过 BGP 社区属性触发上游路由器执行黑洞路由，无需联系 ISP 运维人员。

Anycast 分散：将服务部署在全球多个 PoP 节点上，使用 Anycast BGP 路由使每个地区的用户（和攻击者）被路由到最近的节点。攻击流量被分散到多个节点，每个节点只需处理一部分攻击流量。这是 Cloudflare、Akamai 等 CDN 厂商的核心 DDoS 防御原理。

边界防御

DDoS 专用设备：Arbor（Netscout）、Radware、A10 Networks 等厂商提供专用的 DDoS 缓解设备，部署在互联网边界。这些设备具备大容量的流量处理能力（数百 Gbps），使用多种检测和缓解技术：流量基线学习、协议合规检查、速率限制、行为分析。

防火墙/IPS 的 DDoS 功能：NGFW 通常内置基础的 DDoS 防护——SYN Cookie、连接限速、协议异常检测。但 NGFW 的 DDoS 防护能力有限——状态防火墙本身就是 DDoS 攻击的目标（攻击者可以耗尽其连接表）。

应用层防御

WAF 与速率限制：WAF 在应用层检测和阻断 HTTP Flood 攻击。基于 IP、Session 或 URL 的速率限制是最基本的应用层 DDoS 防御。

人机验证（CAPTCHA / Challenge）：在检测到异常流量时，向客户端发送 JavaScript 挑战或 CAPTCHA 验证，过滤掉不能执行 JavaScript 的简单机器人。Cloudflare 的 Managed Challenge 和 AWS WAF 的 Bot Control 是无感知的机器人检测方案——使用浏览器指纹、行为分析和 ML 模型区分人类和机器人，无需用户交互。

云原生 DDoS 防护
公有云平台提供了原生的 DDoS 防护服务：


AWS Shield：Standard 层免费提供基础的 L3/L4 DDoS 防护。Advanced 层（每月 $3,000）提供增强防护，包括 24/7 的 AWS DDoS 响应团队（DRT）支持、高级检测和缓解能力、以及 DDoS 导致的 AWS 费用减免。


Azure DDoS Protection：Standard 层提供自适应调优的 DDoS 防护，基于应用的正常流量模式自动调整检测阈值。集成 Azure Monitor 和 Azure Sentinel 提供可观测性和事件响应能力。


GCP Cloud Armor：与 Google 的全球负载均衡器集成，利用 Google 的全球网络基础设施（超过 200 个 PoP）分散和吸收 DDoS 流量。支持自适应保护（Adaptive Protection），使用 ML 模型自动检测和缓解 L7 DDoS。


AI 驱动的 DDoS 防御
传统 DDoS 防御依赖静态阈值和预定义规则——当流量超过阈值就触发缓解。但攻击者可以通过"低慢"攻击（Low and Slow）保持在阈值以下，或者通过快速变换攻击模式绕过静态规则。


AI/ML 驱动的 DDoS 防御通过学习网络流量的正常模式，自动检测偏离正常模式的攻击流量——即使攻击量低于传统的静态阈值。关键技术包括：时间序列异常检测（识别流量模式的非季节性突变）、流量特征聚类（将攻击流量与正常流量在特征空间中分离）、以及强化学习优化缓解策略（自动调整过滤规则的参数以最大化攻击流量过滤率同时最小化合法流量误伤）。


DDoS 防御运营
应急预案
每个组织都应该有 DDoS 应急预案，包括：


    

  • 检测机制和告警阈值配置
    • 

  • 升级流程（何时联系 ISP、何时启用云清洗、何时通知管理层）
    • 

  • 缓解操作的 SOP（Standard Operating Procedure）
    • 

  • 与 ISP、CDN 提供商、DDoS 防护服务商的紧急联系渠道
    • 

  • 沟通计划（向用户、客户和媒体的沟通模板）
    • 

  • 事后复盘流程
    • 



韧性设计
DDoS 防御不仅是安全问题，也是可用性和韧性设计问题。架构层面的韧性设计可以显著提高抗 DDoS 能力：多活数据中心架构、弹性自动扩展、CDN 缓存减少源站压力、Anycast 路由分散攻击流量、以及优雅降级策略（在攻击期间关闭非核心功能以保障核心服务）。


定期演练
至少每年进行一次 DDoS 防御演练——使用合法的 DDoS 模拟工具（如 Red Button、NimbusDDoS）对自身系统进行可控的 DDoS 测试，验证检测、告警和缓解流程的有效性。演练结果用于改进防御策略和应急预案。
