横向移动与权限提升

后渗透阶段的战略目标

横向移动（Lateral Movement）与权限提升（Privilege Escalation）是红队操作后渗透阶段的两大核心能力。在获得初始访问（Initial Access）之后，攻击者通常只获得了一个低权限的立足点——可能是一个普通用户的工作站会话。从这个起点到达最终目标（域控制器、核心数据库、高管邮箱）之间，需要通过反复的权限提升和横向移动来逐步扩大控制范围。

CrowdStrike 2025 年全球威胁报告的数据显示，攻击者从初始访问到横向移动的平均时间（Breakout Time）已缩短至 48 分钟，最快的案例仅需 51 秒。这意味着防御方的检测和响应窗口极为有限，理解横向移动的技术细节对于建设有效的检测能力至关重要。

Windows 本地权限提升
本地权限提升（Local Privilege Escalation, LPE）是将当前低权限会话提升为 SYSTEM 或 Administrator 权限的过程。


服务配置漏洞
Windows 服务是权限提升最常见的攻击面之一。以下是几种典型的服务配置漏洞：


不安全的服务路径（Unquoted Service Path）：当服务的可执行文件路径包含空格且未用引号包围时，Windows 会按照路径层级依次查找可执行文件。例如路径 C:\Program Files\Vulnerable App\service.exe 会依次尝试 C:\Program.exe、C:\Program Files\Vulnerable.exe。如果攻击者对这些中间路径有写权限，就可以植入恶意可执行文件。


弱服务权限：如果普通用户对某个以 SYSTEM 权限运行的服务有修改权限（SERVICE_CHANGE_CONFIG），就可以将服务的二进制路径修改为恶意程序。工具 accesschk（SysInternals）和 SharpUp 可以自动化扫描此类配置问题。


DLL 劫持：当服务加载 DLL 时，如果 DLL 搜索路径中存在攻击者可写的目录（且排在合法 DLL 所在目录之前），攻击者可以放置同名的恶意 DLL。Windows 的 DLL 搜索顺序依次为：应用程序目录 → 系统目录 → Windows 目录 → PATH 环境变量目录。


令牌操纵
Windows 使用访问令牌（Access Token）来控制进程的安全上下文。令牌操纵是一种不需要密码即可切换安全上下文的技术：


令牌模拟（Token Impersonation）：如果当前进程拥有 SeImpersonatePrivilege 或 SeAssignPrimaryTokenPrivilege 权限，就可以模拟其他用户的令牌。Windows 服务账户（如 IIS 的 IUSR、SQL Server 的服务账户）通常默认拥有这些权限。


Potato 系列攻击：这是利用 Windows COM 服务器和 NTLM 中继的权限提升技术族。从最初的 Hot Potato（2016）到 Sweet Potato、Rogue Potato，再到 2024—2025 年活跃的 GodPotato 和 CoercedPotato，每一代都在绕过微软的补丁。其核心原理是诱导 SYSTEM 权限的进程向攻击者控制的服务器进行 NTLM 认证，然后中继这个认证来获取 SYSTEM 令牌。


内核漏洞利用
Windows 内核漏洞是最直接但也最高风险的权限提升方式。成功利用内核漏洞可以直接获得 SYSTEM 权限，但失败可能导致蓝屏（BSOD）。


常见的内核攻击面包括：Win32k 子系统（图形内核）、NTFS 驱动、过滤驱动（杀毒软件的内核驱动常常引入新的攻击面）、以及打印机后台处理程序（Print Spooler，PrintNightmare CVE-2021-34527 的影响持续至今）。


工具 winPEAS（Windows Privilege Escalation Awesome Scripts）和 Seatbelt 可以自动化执行全面的本地权限提升检查，覆盖服务配置、计划任务、注册表权限、文件系统权限、已安装软件等数十个检查项。


Linux 权限提升
SUID/SGID 利用
设置了 SUID（Set User ID）位的可执行文件在运行时会以文件所有者的权限执行。如果 root 所有的 SUID 程序存在命令注入或文件操作漏洞，攻击者可以利用它获得 root 权限。


GTFOBins 项目维护了一个全面的列表，记录了可以被滥用来提权或逃逸受限环境的 Unix 二进制文件。例如 find 命令如果设置了 SUID 位，可以通过 find . -exec /bin/sh -p \; 直接获取 root shell。


Sudo 配置利用
sudoers 文件的配置错误是 Linux 环境中最常见的权限提升向量之一。常见的可利用配置包括：


    

  • 允许用户以 root 身份运行编辑器（vim、nano）—— 可以在编辑器中执行 shell 命令
    • 

  • 允许运行脚本语言解释器（python、perl）—— 直接执行任意代码
    • 

  • 允许运行特定程序但未限制参数 —— 通过参数注入执行额外命令
    • 

  • NOPASSWD 配置 —— 不需要密码即可执行 sudo 命令
    • 



容器逃逸
随着容器化部署的普及，从容器中逃逸到宿主机已成为重要的权限提升路径：


特权容器：以 --privileged 运行的容器拥有宿主机的所有设备访问权限，可以直接挂载宿主机文件系统。


Docker Socket 挂载：如果容器中挂载了 /var/run/docker.sock，攻击者可以通过 Docker API 创建新的特权容器来逃逸。


内核漏洞：容器与宿主机共享内核，内核漏洞（如 Dirty Pipe CVE-2022-0847）可以从容器内部直接获取宿主机 root 权限。


工具 linPEAS、LinEnum 和 linux-exploit-suggester 可以自动化扫描 Linux 环境中的权限提升路径。


Active Directory 凭据获取
在域环境中，获取凭据是横向移动的前提。Windows 和 Active Directory 的认证机制提供了多个凭据获取向量。


LSASS 内存提取
本地安全权限子系统服务（LSASS）进程缓存了当前登录用户的凭据材料。通过读取 LSASS 进程内存，可以获取明文密码（在 Windows 2012 R2 之前的系统上）、NTLM 哈希和 Kerberos 票据。


Mimikatz 是最经典的凭据提取工具，其 sekurlsa::logonpasswords 命令可以从 LSASS 中提取所有缓存的凭据。然而 Mimikatz 在 2025 年已经是所有安全产品的重点检测目标——它的二进制文件几乎不可能在有 EDR 的环境中直接运行。


替代方案包括：nanodump（使用 MiniDumpWriteDump API 的变体绕过 EDR hook）、PPLdump（绕过 PPL 保护提取 LSASS）、通过 comsvcs.dll 的 MiniDump 功能进行内存转储（rundll32 comsvcs.dll,MiniDump <lsass_pid> dump.dmp full）、以及使用 RPC 调用 MirrrorDump 等间接方法。


Kerberos 攻击
Kerberos 是 Active Directory 的核心认证协议，其设计中的若干特性可被红队利用：


Kerberoasting（T1558.003）：域中任何经过认证的用户都可以请求使用服务账号加密的 Kerberos Service Ticket（TGS）。由于 TGS 使用服务账号的密码哈希加密，攻击者可以离线暴力破解 TGS 来获取服务账号密码。工具 Rubeus kerberoast 和 Impacket GetUserSPNs.py 用于执行此攻击。


AS-REP Roasting：如果域用户账号配置了"不需要 Kerberos 预认证"（Do not require Kerberos preauthentication），攻击者无需该用户的密码即可请求其加密的 AS-REP 消息，然后离线破解。


Golden Ticket：获取 krbtgt 账号的密码哈希后，攻击者可以伪造任意用户的 TGT（Ticket Granting Ticket），获得对整个域的完全控制。Golden Ticket 的有效期默认为 10 年，即使重置了所有用户密码也不会失效——只有重置 krbtgt 密码两次才能使 Golden Ticket 失效。


Silver Ticket：使用服务账号的密码哈希伪造特定服务的 TGS。与 Golden Ticket 不同，Silver Ticket 不需要与域控制器通信，因此更难被检测。

横向移动技术
横向移动是利用已获得的凭据或权限访问网络中其他系统的过程。


基于凭据的横向移动
Pass-the-Hash（PtH）：使用 NTLM 哈希（而非明文密码）进行认证。这利用了 NTLM 认证协议的设计特性——认证过程中客户端使用密码的 NTLM 哈希计算响应，因此拥有哈希即可完成认证。工具 Impacket psexec.py、wmiexec.py、smbexec.py 和 evil-winrm 都支持 PtH。


Pass-the-Ticket（PtT）：使用窃取的 Kerberos 票据（TGT 或 TGS）进行认证。通过 Mimikatz 的 kerberos::ptt 命令或 Rubeus 的 ptt 功能将票据注入当前会话。


Overpass-the-Hash：使用 NTLM 哈希请求 Kerberos TGT，然后使用 TGT 进行 Kerberos 认证。这种方法结合了 PtH 和 PtT 的优势，可以在仅有 NTLM 哈希的情况下使用 Kerberos 认证（避免触发针对 NTLM 的检测规则）。

PsExec 风格攻击是最经典的横向移动方式：通过 SMB 将服务二进制文件复制到目标系统的 ADMIN$ 共享，然后通过 MSRPC 的 Service Control Manager 创建并启动服务来执行代码。这种方式功能强大但检测特征明显——会在目标系统上创建新服务并生成 Event ID 7045。


WMI 执行通过 Windows Management Instrumentation 在远程系统上创建进程。wmic /node:target process call create "cmd.exe /c payload"。WMI 的优势是不会在目标上创建服务或写入文件，但执行结果不会直接返回。


WinRM（Windows Remote Management）是 Windows 的合法远程管理协议，基于 WS-Management 标准。通过 evil-winrm 可以获得功能丰富的远程 PowerShell 会话。由于 WinRM 是合法的管理工具，其流量更难与正常管理活动区分。


内网代理与隧道
在复杂的网络环境中，红队需要建立代理和隧道来跨越网络边界：


SOCKS 代理：在已控制的跳板机上建立 SOCKS4/5 代理，将红队工具的流量通过跳板机路由到内部网络。Cobalt Strike 和 Sliver 都内置了 SOCKS 代理功能。


端口转发：将目标内网的端口映射到红队可达的地址。ssh -L（本地转发）、ssh -R（远程转发）和 chisel（HTTP 隧道端口转发）是常用工具。


DNS 隧道：在严格的出口过滤环境中，DNS 通常是少数被允许的协议之一。工具 dnscat2、iodine 可以将任意数据封装在 DNS 查询中传输。


C2 链式通信：在多层网络环境中，通过 SMB Beacon（Cobalt Strike）或 Peer-to-Peer 模式（Sliver）建立 Beacon 间的链式通信。只有第一层跳板机需要出网能力，深层内网的 Beacon 通过链式传递与 C2 服务器通信。
