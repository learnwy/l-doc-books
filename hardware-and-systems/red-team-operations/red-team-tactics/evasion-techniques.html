防御规避与反检测技术

现代防御体系的挑战

防御规避（Defense Evasion）是 MITRE ATT&CK 中技术数量最多的战术（TA0005，43 个技术），这反映了攻防对抗中"绕过检测"这个核心挑战的复杂性。现代企业安全防御已从传统杀毒软件演进到包含 EDR（Endpoint Detection and Response）、XDR（Extended Detection and Response）、SIEM（Security Information and Event Management）、SOAR（Security Orchestration, Automation and Response）和零信任架构在内的多层防御体系。

2025—2026 年的安全防御技术呈现几个关键趋势：EDR 产品全面采用内核级遥测（ETW、minifilter 驱动）；AI/ML 驱动的行为分析成为主流；云原生安全平台（CrowdStrike Falcon、Microsoft Defender for Endpoint、SentinelOne Singularity）提供跨端点、云和身份的统一检测；AMSI（Antimalware Scan Interface）覆盖范围从 PowerShell 扩展到 .NET、VBScript、JavaScript 和第三方应用。

面对这样的防御环境，红队需要深入理解每一层防御的检测原理，才能设计有效的规避策略。

端点检测规避

AMSI 绕过

AMSI 是 Windows 10 引入的反恶意软件扫描接口，允许应用程序将脚本内容提交给安装的安全产品进行扫描。PowerShell、VBScript、JScript、.NET 4.8+、Office VBA 宏都通过 AMSI 进行内容扫描。

AMSI 的工作流程：

AMSI 绕过的核心思路是在恶意内容被扫描之前破坏 AMSI 的工作链路：


内存补丁：修改 amsi.dll 中 AmsiScanBuffer 函数的入口指令，使其直接返回"未检测到威胁"的结果。经典方法是将函数开头的字节修改为 mov eax, 0x80070057; ret（返回 E_INVALIDARG 错误码，导致调用方跳过扫描）。


CLR Hooking：在 .NET CLR 层面拦截 AMSI 调用。通过修改 System.Management.Automation.AmsiUtils 类的 amsiInitFailed 字段为 true，使 PowerShell 认为 AMSI 初始化失败而跳过所有扫描。


反射加载：避免将恶意 .NET 程序集写入磁盘，直接在内存中通过 Assembly.Load(byte[]) 加载。配合 AMSI 绕过，可以在不触发文件扫描的情况下执行 .NET 工具（如 Rubeus、Seatbelt）。


ETW 绕过
ETW（Event Tracing for Windows）是 Windows 的核心遥测基础设施，EDR 产品严重依赖 ETW 来获取进程创建、线程注入、文件操作、网络连接等安全相关事件。


ETW Patching：与 AMSI 绕过类似，通过修改 ntdll.dll 中 EtwEventWrite 函数的入口指令使其直接返回，从而阻止当前进程产生 ETW 事件。这可以有效地对 EDR "隐身"——EDR 的用户态钩子看不到进程的行为。


ETW Threat Intelligence Provider 绕过：Windows 10 引入了 EtwTi（ETW Threat Intelligence）提供程序，这是一个内核级别的 ETW Provider，专门为安全产品提供高保真的安全事件。EtwTi 的数据来自内核，无法通过用户态的 ETW Patching 绕过。绕过 EtwTi 需要内核级别的操作（如加载恶意驱动或利用内核漏洞），这是 2025 年攻防对抗的前沿领域。


直接系统调用
现代 EDR 通过在用户态 DLL（ntdll.dll、kernel32.dll）的关键函数上安装钩子（Inline Hook 或 IAT Hook）来监控进程行为。直接系统调用（Direct Syscall）技术绕过了这些用户态钩子，直接通过 syscall 指令与内核通信。


传统直接系统调用：在代码中硬编码系统调用号（SSN），直接执行 syscall 指令。问题是 SSN 在不同 Windows 版本间可能不同，需要动态解析。


间接系统调用（Indirect Syscall）：不在自己的代码中执行 syscall 指令，而是跳转到 ntdll.dll 中合法的 syscall 指令地址执行。这样做的好处是调用栈看起来更"正常"——syscall 指令的返回地址指向 ntdll.dll 而非未知内存区域，可以绕过 EDR 的调用栈检测。


SysWhispers 项目提供了自动化生成系统调用存根代码的工具，SysWhispers3 支持间接系统调用和随机化系统调用号解析。HellsGate 和 HalosGate 则提供了运行时动态解析 SSN 的技术，即使 ntdll.dll 的导出表被 EDR 修改也能正确获取系统调用号。


进程注入技术
进程注入（Process Injection, T1055）是将代码注入到另一个进程的地址空间中执行的技术。它既是权限提升手段（注入到高权限进程），也是防御规避手段（在合法进程的上下文中执行恶意代码）。


经典注入技术
远程线程注入：在目标进程中分配内存（VirtualAllocEx）→ 写入 shellcode（WriteProcessMemory）→ 创建远程线程执行（CreateRemoteThread）。这是最基础的注入方式，也是 EDR 重点监控的行为——API 调用链非常明显。


APC 注入：使用异步过程调用（QueueUserAPC）将代码排队到目标线程的 APC 队列中。当目标线程进入可警告等待状态（alertable wait）时，APC 函数会被执行。比 CreateRemoteThread 更隐蔽，但需要目标线程处于特定状态。


进程镂空（Process Hollowing）：创建一个合法进程（如 svchost.exe）的挂起实例，清空其内存中的原始代码，注入恶意代码后恢复执行。从外部看，恶意代码运行在一个"合法"进程中。


高级注入技术
模块踩踏（Module Stomping / DLL Hollowing）：将合法 DLL 加载到目标进程中，然后用恶意代码覆盖 DLL 的 .text 段。由于恶意代码位于合法 DLL 的内存区域内，内存扫描更难检测。


线程执行劫持（Thread Execution Hijacking）：挂起目标进程的线程，修改其指令指针（RIP/EIP）指向注入的 shellcode，然后恢复线程。不需要创建新线程，减少了可检测的特征。


Phantom DLL Hollowing：将合法 DLL 映射为事务性文件（Transactional NTFS），在事务中修改 DLL 内容（注入恶意代码），将修改后的 DLL 映射到目标进程，然后回滚事务。磁盘上的文件保持不变，但内存中已经是恶意代码。


Early Bird 注入：在目标进程初始化完成之前（APC 在进程入口点执行之前就被调度）注入代码。由于此时 EDR 的用户态钩子可能尚未安装，Early Bird 注入可以在 EDR "看不到" 的时候完成注入。


C2 通信隐蔽
C2 通信的隐蔽性决定了红队操作的持久能力。如果 C2 流量被检测和阻断，红队将失去对已植入系统的控制。


流量伪装
域前置（Domain Fronting）：利用 CDN 的特性，将 C2 流量伪装成对合法域名的 HTTPS 请求。DNS 解析和 TLS SNI 指向合法的 CDN 域名（如 cdn.microsoft.com），但 HTTP Host 头指向红队控制的域名。从网络层看，流量目的地是合法的 CDN 服务器。2025 年部分 CDN 厂商（如 Cloudflare）已经开始检测和阻止域前置，但 Amazon CloudFront 和部分区域性 CDN 仍然可用。


C2 Profile 定制：Cobalt Strike 的 Malleable C2 Profile 和 Sliver 的 HTTP C2 配置都支持深度定制通信特征。最佳实践是将 C2 流量伪装成目标网络中已有的合法 Web 应用流量——使用相同的 URI 模式、请求频率和 HTTP 头。


合法服务作为 C2 通道：利用合法的云服务作为 C2 基础设施。常见的方案包括：使用 Slack/Teams Webhook 作为命令传递通道、使用 Google Sheets/OneDrive 存储任务和结果、使用 DNS over HTTPS（DoH）进行 DNS 隧道通信。这些流量混在大量合法的云服务流量中，极难区分。


Sleep 混淆
植入体在 Sleep 等待期间（两次 C2 通信之间的间隔）的内存状态是 EDR 内存扫描的重要检测窗口。


Sleep Obfuscation 技术在 Sleep 期间加密植入体的内存区域：Beacon 在进入 Sleep 前将自身代码段加密，修改内存保护属性为不可执行（PAGE_READWRITE），Sleep 结束后解密并恢复为可执行。Cobalt Strike 4.7+ 的 Sleep Mask Kit 提供了此功能。


Ekko / Foliage / Nighthawk Sleep：更高级的 Sleep 混淆技术，使用 APC 或回调函数在 Sleep 期间将加密和解密操作交给系统线程池执行，避免在 Sleep 恢复时出现明显的内存属性变更（RWX 切换）。


载荷加密与混淆
字符串加密：载荷中的硬编码字符串（如 API 函数名、C2 地址）是静态检测的主要特征。在编译时对所有字符串进行加密，运行时动态解密使用。


控制流混淆：通过插入不透明谓词（Opaque Predicate）、扁平化控制流（Control Flow Flattening）和虚假分支来增加逆向分析的难度。工具 LLVM-Obfuscator 和自定义的编译器 Pass 可以实现这些混淆。


多态与变形：每次生成的载荷在功能相同的情况下具有不同的二进制特征。通过随机化寄存器使用、指令替换（如 mov eax, 0 替换为 xor eax, eax）和垃圾代码插入来实现多态性。

WMI 事件订阅是最隐蔽的 Windows 持久化方式之一。通过创建 WMI 事件过滤器（Event Filter）、消费者（Event Consumer）和绑定（Filter-to-Consumer Binding），可以在满足特定条件时（如系统启动后 5 分钟）自动执行恶意命令。WMI 持久化不会在文件系统中留下明显痕迹，信息存储在 WMI 仓库（%SystemRoot%\System32\wbem\Repository）中。


COM 对象劫持通过在注册表中注册自定义的 COM 对象，覆盖系统或应用程序使用的合法 COM 对象。当应用程序加载被劫持的 COM 对象时，攻击者的代码会被执行。


高级持久化
Bootkit：修改系统引导过程中的组件（如 UEFI 固件、Windows Boot Manager），在操作系统加载之前执行恶意代码。2023 年发现的 BlackLotus 是首个已知的能绕过 Secure Boot 的 UEFI Bootkit，这类攻击即使重装操作系统也无法清除。


Active Directory 持久化：在域环境中，攻击者可以通过多种方式建立难以清除的持久化——Golden Ticket（伪造 krbtgt TGT）、Skeleton Key（在域控上安装万能密码）、DCSync 账号（通过赋予普通账号 DCSync 权限实现持续凭据获取）、AD CS 持久化（通过证书获得长期有效的认证能力）。


操作安全原则
红队操作中的操作安全（OPSEC）不仅是规避检测的技术问题，更是一套系统化的行为规范：


最小足迹原则：只执行完成任务必需的最少操作。避免不必要的端口扫描、文件写入和进程创建。每一个操作都可能产生日志和遥测事件。


时间控制：在目标组织的正常工作时间执行操作，将攻击流量混入正常的业务流量中。避免在深夜执行操作——这反而更容易被异常行为检测系统标记。


清理痕迹：操作结束后清理所有植入体、工具文件和日志条目。但要注意——清理日志本身可能触发安全告警（Event Log Cleared, Event ID 1102），因此需要在清理方式上也保持谨慎。


基础设施隔离：不同的红队评估使用不同的 C2 基础设施。一次评估中被发现的 C2 地址不应该影响其他评估。使用临时的 VPS、域名和证书，评估结束后销毁。
