Part III · 应用安全与对抗红队对抗与渗透测试 简介渗透测试方法论 简介信息收集与侦察技术

信息收集与侦察技术

侦察阶段的战略意义

信息收集与侦察（Reconnaissance）是渗透测试和红队评估中最关键的前期阶段——投入在侦察上的时间与最终测试成果的质量直接正相关。经验丰富的渗透测试人员通常会将 40%—60% 的时间花在信息收集上，因为充分的侦察能显著提高后续漏洞利用的成功率，同时减少不必要的噪声和误报。

侦察的核心目标是构建目标组织的完整画像：技术资产清单（IP、域名、应用）、组织结构（人员、部门、供应商）、技术栈（开发框架、中间件、云平台）以及安全防御态势（WAF、EDR、SIEM 部署情况）。

侦察技术按照与目标系统的交互程度分为两大类：被动侦察（Passive Reconnaissance）不直接与目标系统交互，通过公开信息源获取情报；主动侦察（Active Reconnaissance）直接与目标系统交互，通过扫描和探测获取技术细节。

被动侦察技术
被动侦察的核心优势在于隐蔽性——不会在目标系统的日志中留下任何痕迹，不会触发入侵检测系统（IDS）的告警。在红队评估中，被动侦察往往是唯一安全的起始步骤。


OSINT 开源情报收集
OSINT（Open Source Intelligence）是从公开可用的信息源中系统化收集和分析情报的方法。在渗透测试场景中，OSINT 能够揭示大量有价值的目标信息。


搜索引擎高级语法是最基础的 OSINT 手段。Google Dorking 使用搜索运算符定向查找敏感信息：


site:target.com filetype:pdf
site:target.com inurl:admin
site:target.com ext:sql | ext:bak | ext:log
"target.com" filetype:xlsx password
intitle:"index of" site:target.com
这些查询可以发现目标域名下的管理后台、泄露的数据库备份、含有凭据的电子表格等敏感资源。Google Hacking Database（GHDB）维护了数千条经过验证的 Dork 查询模板。


互联网资产搜索引擎是被动侦察的利器。Shodan、Censys、ZoomEye、FOFA 等搜索引擎持续扫描和索引全球互联网资产的端口、服务和证书信息，允许渗透测试者在不直接扫描目标的情况下获取其技术资产详情。

网络空间测绘示例：在 Shodan 中搜索 org:"Target Corp" port:443 可以列出目标组织名下所有 HTTPS 服务的 IP、证书、HTTP 头信息，无需直接向目标发送任何请求。


DNS 被动分析
DNS 记录是了解目标网络架构的重要窗口。被动 DNS 数据库（如 VirusTotal、SecurityTrails、PassiveDNS）记录了域名解析的历史变化，可以揭示：


历史解析记录——域名曾经指向哪些 IP，帮助发现已迁移但未完全下线的旧服务器。


子域名枚举——通过聚合被动 DNS 数据发现目标的子域名，往往比主域名更容易存在安全弱点。SecurityTrails 的数据显示，平均每个企业域名拥有超过 500 个子域名，其中许多是被遗忘的测试环境或内部系统。


邮件基础设施——MX 记录揭示邮件服务提供商（Google Workspace、Microsoft 365、自建邮件服务器），SPF/DKIM/DMARC 记录揭示邮件安全配置，这些对后续的社会工程攻击规划至关重要。


证书透明日志分析
证书透明（Certificate Transparency, CT）日志是一个公开的、仅追加的 TLS 证书日志系统。所有公开信任的 CA 在签发证书时都必须将证书记录到 CT 日志中。这意味着我们可以通过搜索 CT 日志来发现目标的所有 TLS 证书，进而发现子域名和服务。


工具 crt.sh 提供了 CT 日志的免费搜索接口。查询 %.target.com 可以列出所有包含 target.com 的证书记录，包括通配符证书和 SAN（Subject Alternative Name）中的多域名证书。这是子域名发现的高效且完全被动的方法。


代码仓库与泄露检测
GitHub、GitLab 等代码托管平台是意外信息泄露的重灾区。开发人员可能无意中将以下敏感信息提交到公开仓库：


    

  • API 密钥和访问令牌（AWS Access Key、Azure Service Principal）
    • 

  • 数据库连接字符串和凭据
    • 

  • 内部系统的 URL 和网络拓扑信息
    • 

  • 配置文件中的加密密钥和证书
    • 

  • CI/CD 流水线配置中的部署凭据
    • 



工具 trufflehog（TruffleHog）和 gitleaks 可以自动化扫描 Git 仓库的提交历史，检测高熵字符串和已知的密钥格式。GitHub 自 2024 年起强制启用 Secret Scanning，但历史提交中的泄露数据仍然大量存在。


主动侦察技术
主动侦察会直接与目标系统交互，因此存在被检测和记录的风险。在红队评估中，需要谨慎控制扫描的速率和方式以降低被发现的概率。


DNS 主动枚举
DNS 枚举是主动侦察的第一步，目标是建立尽可能完整的子域名清单。


字典爆破是最直接的方法。工具 gobuster dns、ffuf、massdns 使用字典对目标域名进行子域名暴力枚举。字典的质量直接决定发现率——SecLists 项目维护了多个高质量的子域名字典，从数万条到数百万条不等。


区域传送（Zone Transfer）是一种利用 DNS 服务器配置错误的技术。如果目标的 DNS 服务器允许未授权的 AXFR 请求，攻击者可以一次性获得该域名下的所有 DNS 记录。虽然现代 DNS 服务器默认禁止区域传送，但在内网环境和老旧系统中仍然经常存在这个配置问题。


DNS 记录深度分析——除了 A/AAAA 记录外，还应关注 CNAME 记录（可能存在子域名接管 / Subdomain Takeover 的风险）、TXT 记录（可能包含验证令牌和配置信息）、SRV 记录（揭示内部服务发现机制）。


端口扫描与服务发现
端口扫描是确定目标系统开放了哪些网络服务的核心手段。Nmap 是这个领域的事实标准工具，其扫描策略需要根据场景灵活调整：


快速发现扫描：nmap -sn 192.168.1.0/24 使用 ICMP/ARP 探测存活主机，不做端口扫描。适用于快速确定目标网段中有哪些活跃主机。


标准端口扫描：nmap -sS -sV -O -p- target.com 执行 SYN 半连接扫描（隐蔽性较好）、服务版本检测和操作系统指纹识别，扫描全部 65535 个端口。这是渗透测试中最常用的扫描模式。


隐蔽扫描：在红队评估中，需要使用更隐蔽的扫描方式来规避 IDS 检测。技术手段包括降低扫描速率（--scan-delay）、使用分片数据包（-f）、随机化扫描顺序（--randomize-hosts）、以及通过代理链路由扫描流量。


UDP 扫描：nmap -sU --top-ports 100 target.com 扫描 UDP 端口。UDP 扫描速度慢但不可忽视——SNMP（161）、DNS（53）、TFTP（69）、NTP（123）等重要服务使用 UDP 协议。


服务指纹识别与版本探测
发现开放端口后，需要确定运行在端口上的具体服务类型和版本。精确的版本信息对于漏洞匹配至关重要。


Nmap 的 -sV 参数通过发送特定的探测报文并分析响应来识别服务版本。对于 Web 服务，还需要使用专门的工具进行更深入的指纹识别：


Web 服务器指纹：whatweb、httpx 可以识别 Web 服务器类型（Nginx、Apache、IIS）、编程语言（PHP、Java、Node.js）、框架（WordPress、Django、Spring）和 WAF 类型。


CMS 识别：wpscan（WordPress）、droopescan（Drupal/Joomla）等专用工具可以深入分析特定 CMS 的版本、插件和主题，这些是 Web 应用渗透测试中最常见的攻击面。


API 发现：现代应用大量使用 API。通过分析 JavaScript 文件、OpenAPI/Swagger 文档端点（/swagger.json、/api-docs）、以及 GraphQL 内省查询（{ __schema { types { name } } }）来发现 API 端点和数据结构。


Web 应用深度探测
Web 应用侦察需要超越表面，深入理解应用的内部结构和逻辑：


目录和文件发现：feroxbuster、dirsearch、gobuster dir 使用字典暴力枚举 Web 应用的隐藏路径。重点关注管理后台（/admin、/wp-admin）、配置文件（/.env、/config.php）、备份文件（/.bak、/.old）和版本控制目录（/.git、/.svn）。


参数发现：arjun、param-miner（Burp 插件）用于发现隐藏的 HTTP 参数。许多应用存在未在前端使用但后端仍然处理的参数，这些"隐藏参数"可能存在注入点或权限绕过。


JavaScript 分析：现代 SPA 应用的大量逻辑在前端 JavaScript 中实现。使用 LinkFinder、JSParser 从 JS 文件中提取 API 端点、密钥和敏感路径。Webpack 打包的应用可以通过 Source Map 文件还原完整源代码。


侦察自动化与框架
大规模侦察需要自动化工具链来提高效率和覆盖面。


Recon-ng 是一个模块化的侦察框架，类似 Metasploit 的架构设计。它集成了数十个侦察模块，覆盖域名发现、IP 解析、联系人搜索、凭据检查等功能，并提供统一的数据存储和报告机制。


Amass（OWASP 项目）是目前最强大的子域名枚举工具，集成了被动收集、DNS 爆破、证书透明日志分析、Web 爬虫等多种发现技术。它的图数据库后端可以自动建立域名、IP 和 ASN 之间的关联关系。


SpiderFoot 是一个自动化 OSINT 平台，可以对目标的域名、IP、邮箱、人名进行全方位的情报收集，自动关联来自 100 多个数据源的信息。

侦察对抗与反侦察
了解侦察技术的同时，也需要理解防御方如何检测和阻止侦察活动：


网络层检测：IDS/IPS 系统通过检测异常的 DNS 查询频率、端口扫描模式和爬虫行为来识别侦察活动。红队需要通过速率控制、源 IP 分散和协议伪装来规避这些检测。


Web 层检测：WAF 和反爬虫系统通过分析请求的 User-Agent、请求频率、路径模式来识别自动化探测工具。使用真实浏览器指纹、随机化请求间隔和自定义 HTTP 头可以降低被检测的概率。


情报层面：目标组织可能订阅了数字风险防护（DRP）服务来监控对自身的侦察活动。在暗网论坛和 Pastebin 等平台上搜索目标信息时需要注意操作安全（OPSEC）。
