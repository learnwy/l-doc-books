Gazebo 仿真基础

核心概念

Gazebo 是 ROS 生态系统中最主流的机器人仿真器，提供物理引擎、传感器模拟和环境渲染能力。新一代 Gazebo（原 Ignition Gazebo）采用模块化架构，通过 ECS（Entity-Component-System）模式组织仿真世界中的所有实体。仿真是机器人开发的关键环节——在真实硬件部署之前验证算法、训练策略和测试安全边界。

SDF 世界文件
SDF（Simulation Description Format）是 Gazebo 描述仿真世界的标准格式，包含物理属性、几何形状、传感器配置和插件加载等所有仿真要素。


<?xml version="1.0"?>
<sdf version="1.9">
  <world name="warehouse">
    <physics name="1ms" type="dart">
      <max_step_size>0.001</max_step_size>
      <real_time_factor>1.0</real_time_factor>
    </physics>

    <light type="directional" name="sun">
      <cast_shadows>true</cast_shadows>
      <direction>-0.5 0.1 -0.9</direction>
    </light>

    <include>
      <uri>model://ground_plane</uri>
    </include>

    <model name="obstacle_box">
      <static>true</static>
      <pose>2.0 0 0.5 0 0 0</pose>
      <link name="link">
        <collision name="collision">
          <geometry><box><size>1 1 1</size></box></geometry>
        </collision>
        <visual name="visual">
          <geometry><box><size>1 1 1</size></box></geometry>
        </visual>
      </link>
    </model>
  </world>
</sdf>

max_step_size 控制物理仿真的时间步长——步长越小物理模拟越精确但越慢。对于快速运动或刚性碰撞场景，可能需要更小的步长（如 0.0005s）来保证数值稳定性。real_time_factor 控制仿真速度与真实时间的比率：1.0 表示实时仿真，大于 1.0 表示加速（用于快速训练），小于 1.0 表示慢动作。


SDF 与 URDF 的关系：URDF 是 ROS 生态中描述机器人模型的标准格式，SDF 是 Gazebo 的原生格式且功能更丰富（支持世界描述、传感器配置等）。Gazebo 可以直接加载 URDF 文件（内部自动转换为 SDF），但复杂的仿真场景通常需要直接编写 SDF。

传感器噪声模型是缩小仿真与现实差距（Sim-to-Real Gap）的关键。高斯噪声是最常用的模型，但真实传感器的噪声往往更复杂：激光雷达在玻璃和镜面上产生多路径反射导致虚假读数，深度相机在物体边缘有系统性的深度失真，IMU 存在随温度变化的零偏漂移。


为缩小 Sim-to-Real Gap，还需要考虑传感器的时序特性（采样率抖动、硬件延迟）和视场限制（盲区、最大探测距离）。domain randomization 技术通过在仿真中随机化传感器参数、光照条件和物体材质，使训练出的算法对噪声和不确定性更加鲁棒。


ROS 2 桥接
# ros_gz_bridge 配置
- ros_topic_name: '/scan'
  gz_topic_name: '/scan'
  ros_type_name: 'sensor_msgs/msg/LaserScan'
  gz_type_name: 'gz.msgs.LaserScan'
  direction: GZ_TO_ROS

- ros_topic_name: '/cmd_vel'
  gz_topic_name: '/cmd_vel'
  ros_type_name: 'geometry_msgs/msg/Twist'
  gz_type_name: 'gz.msgs.Twist'
  direction: ROS_TO_GZ
ros_gz_bridge 是 Gazebo 和 ROS 2 之间的消息转换层。它将 Gazebo 内部的 Protobuf 消息格式转换为 ROS 2 的消息类型，反之亦然。bridge 节点通过 YAML 配置文件声明需要桥接的话题、消息类型和方向。


桥接方向分为三种：GZ_TO_ROS（仿真数据发送到 ROS）、ROS_TO_GZ（ROS 控制命令发送到仿真）和 BIDIRECTIONAL（双向）。传感器数据通常是 GZ_TO_ROS，控制指令通常是 ROS_TO_GZ。


Launch 文件集成
在实际项目中，Gazebo 仿真通常通过 ROS 2 Launch 文件一键启动，同时加载世界文件、生成机器人模型和启动桥接节点。Launch 文件还可以通过参数切换仿真模式和真机模式——实现同一套代码在仿真和真机上运行（sim_mode 参数控制）。


小结
    

  • Gazebo 是 ROS 2 生态的标准仿真器，提供物理、传感器和渲染的完整仿真能力
    • 

  • SDF 格式描述仿真世界中的所有实体，包括物理属性、碰撞几何和传感器配置
    • 

  • 物理步长和实时因子需要根据仿真精度和速度需求平衡调整
    • 

  • 传感器仿真支持添加高斯噪声，使仿真数据更接近真实传感器输出
    • 

  • Domain randomization 技术通过随机化仿真参数来缩小 Sim-to-Real Gap
    • 

  • ros_gz_bridge 负责 Gazebo 话题和 ROS 2 话题之间的双向转换
    • 

  • 无头模式（headless）可关闭渲染引擎，用于 CI/CD 和大规模并行仿真
    •
