ros2_control 框架

核心概念

ros2_control 是 ROS2 中标准化的机器人硬件抽象和控制框架。它在硬件驱动和控制算法之间建立了清晰的分层架构，使得控制器可以独立于硬件开发和测试，硬件驱动可以被不同的控制器复用。这种解耦设计是工业级机器人软件的基础——更换硬件只需更换驱动插件，控制算法无需修改。

ros2_control 的架构由三层组成：Hardware Interface（硬件接口）层直接与物理硬件通信，Controller Manager（控制器管理器）负责加载和管理控制器插件，Controller（控制器）实现具体的控制算法。控制器通过标准的 Command Interface 和 State Interface 与硬件交互。

Hardware Interface 开发
Hardware Interface 是连接真实硬件的桥梁。每个硬件接口插件实现 on_init、configure、activate、deactivate、read 和 write 方法。read 在每个控制周期开始时从硬件读取状态，write 在控制周期结束时将命令发送到硬件。


import numpy as np

class HardwareInterface:
    def __init__(self):
        self.joint_names = []
        self.position_states = {}
        self.velocity_states = {}
        self.position_commands = {}
        self.velocity_commands = {}

    def on_init(self, info):
        for joint in info.get('joints', []):
            name = joint['name']
            self.joint_names.append(name)
            self.position_states[name] = 0.0
            self.velocity_states[name] = 0.0
            self.position_commands[name] = 0.0
            self.velocity_commands[name] = 0.0
        return True

    def configure(self):
        return True

    def activate(self):
        for name in self.joint_names:
            self.position_commands[name] = self.position_states[name]
        return True

    def deactivate(self):
        for name in self.joint_names:
            self.velocity_commands[name] = 0.0
        return True

    def read(self, time, period):
        raise NotImplementedError

    def write(self, time, period):
        raise NotImplementedError


class ServoHardwareInterface(HardwareInterface):
    def __init__(self):
        super().__init__()
        self.serial_port = None
        self.encoder_resolution = 4096

    def on_init(self, info):
        super().on_init(info)
        self.port_name = info.get('port', '/dev/ttyUSB0')
        self.baud_rate = info.get('baud_rate', 115200)
        return True

    def configure(self):
        self.serial_port = {
            'port': self.port_name,
            'baud': self.baud_rate,
            'connected': True
        }
        return True

    def read(self, time, period):
        for name in self.joint_names:
            encoder_count = self._read_encoder(name)
            self.position_states[name] = (
                encoder_count / self.encoder_resolution * 2 * np.pi
            )
            self.velocity_states[name] = self._estimate_velocity(
                name, self.position_states[name], period
            )

    def write(self, time, period):
        for name in self.joint_names:
            target_count = int(
                self.position_commands[name] / (2 * np.pi) * self.encoder_resolution
            )
            self._send_command(name, target_count)

    def _read_encoder(self, name):
        return 0

    def _estimate_velocity(self, name, position, period):
        return 0.0

    def _send_command(self, name, count):
        pass


class GazeboHardwareInterface(HardwareInterface):

硬件接口的关键设计是 State Interface 和 Command Interface 的分离。一个关节可以同时暴露多种状态（位置、速度、力矩）和多种命令接口（位置命令、速度命令），不同的控制器可以根据需要使用不同的接口组合。


控制器开发
ros2_control 提供了丰富的标准控制器：JointTrajectoryController（关节轨迹跟踪）、ForwardCommandController（直接转发命令）、DiffDriveController（差速驱动）、JointStateBroadcaster（关节状态广播）等。自定义控制器通过继承 controller_interface::ControllerInterface 实现。


import numpy as np

class PIDController:
    def __init__(self, kp, ki, kd, output_limit=None):
        self.kp = kp
        self.ki = ki
        self.kd = kd
        self.output_limit = output_limit
        self.integral = 0.0
        self.prev_error = 0.0

    def compute(self, error, dt):
        self.integral += error * dt
        derivative = (error - self.prev_error) / dt if dt > 0 else 0.0
        self.prev_error = error

        output = self.kp * error + self.ki * self.integral + self.kd * derivative

        if self.output_limit:
            output = np.clip(output, -self.output_limit, self.output_limit)
            if abs(output) >= self.output_limit:
                self.integral -= error * dt

        return output


class JointPositionController:
    def __init__(self, joint_names, pid_gains):
        self.joint_names = joint_names
        self.pids = {}
        for name in joint_names:
            gains = pid_gains.get(name, {'kp': 100, 'ki': 10, 'kd': 1})
            self.pids[name] = PIDController(
                gains['kp'], gains['ki'], gains['kd'],
                output_limit=gains.get('effort_limit', 100)
            )
        self.position_commands = {}
        self.state_positions = {}
        self.state_velocities = {}

    def configure(self):
        for name in self.joint_names:
            self.position_commands[name] = 0.0
        return True

    def update(self, time, period):
        dt = period
        effort_commands = {}

        for name in self.joint_names:
            target = self.position_commands[name]
            current = self.state_positions.get(name, 0.0)
            error = target - current
            effort = self.pids[name].compute(error, dt)
            effort_commands[name] = effort

        return effort_commands

    def set_target(self, joint_positions):
        for name, pos in joint_positions.items():
            if name in self.position_commands:
                self.position_commands[name] = pos


class DiffDriveController:
    def __init__(self, wheel_separation, wheel_radius):
        self.wheel_separation = wheel_separation
        self.wheel_radius = wheel_radius
        self.left_position = 0.0
        self.right_position = 0.0
        self.odom_x = 0.0
        self.odom_y = 0.0
        self.odom_theta = 0.0

    def cmd_vel_to_wheel_speed(self, linear_x, angular_z):
        left_speed = (linear_x - angular_z * self.wheel_separation / 2) / self.wheel_radius
        right_speed = (linear_x + angular_z * self.wheel_separation / 2) / self.wheel_radius
        return left_speed, right_speed

    def update_odometry(self, left_pos, right_pos, dt):
        dl = (left_pos - self.left_position) * self.wheel_radius
        dr = (right_pos - self.right_position) * self.wheel_radius

        self.left_position = left_pos
        self.right_position = right_pos

        ds = (dl + dr) / 2.0
        dtheta = (dr - dl) / self.wheel_separation

        self.odom_x += ds * np.cos(self.odom_theta + dtheta / 2)
        self.odom_y += ds * np.sin(self.odom_theta + dtheta / 2)
        self.odom_theta += dtheta

        return self.odom_x, self.odom_y, self.odom_theta
JointTrajectoryController 是机械臂控制中最常用的控制器。它接收关节轨迹（一系列时间标记的关节位置/速度/加速度），通过插值和 PID 控制跟踪轨迹。它与 MoveIt2 的轨迹执行模块直接对接，形成完整的运动规划-执行链路。


URDF 中的 ros2_control 配置
ros2_control 的硬件和控制器配置嵌入在 URDF 的 <ros2_control> 标签中。这使得机器人模型和控制配置保持在同一个文件中，简化了系统部署。


ROS2_CONTROL_URDF = """
<ros2_control name="RobotSystem" type="system">
  <hardware>
    <plugin>robot_hardware/ServoHardwareInterface</plugin>
    <param name="port">/dev/ttyUSB0</param>
    <param name="baud_rate">115200</param>
  </hardware>

  <joint name="joint_1">
    <command_interface name="position">
      <param name="min">-3.14</param>
      <param name="max">3.14</param>
    </command_interface>
    <state_interface name="position"/>
    <state_interface name="velocity"/>
  </joint>

  <joint name="joint_2">
    <command_interface name="position">
      <param name="min">-1.57</param>
      <param name="max">1.57</param>
    </command_interface>
    <command_interface name="velocity">
      <param name="min">-3.0</param>
      <param name="max">3.0</param>
    </command_interface>
    <state_interface name="position"/>
    <state_interface name="velocity"/>
    <state_interface name="effort"/>
  </joint>

  <sensor name="ft_sensor">
    <state_interface name="force.x"/>
    <state_interface name="force.y"/>
    <state_interface name="force.z"/>
    <state_interface name="torque.x"/>
    <state_interface name="torque.y"/>
    <state_interface name="torque.z"/>
    <param name="frame_id">tool0</param>
  </sensor>
</ros2_control>
"""

小结
    

  • ros2_control 提供了标准化的硬件抽象和控制框架，实现硬件与控制器的解耦
    • 

  • Hardware Interface 通过 read/write 方法封装硬件通信，支持真实硬件和仿真切换
    • 

  • Command Interface 和 State Interface 的分离使同一硬件可被不同类型控制器使用
    • 

  • 标准控制器涵盖轨迹跟踪、差速驱动、状态广播等常见需求
    • 

  • 配置通过 URDF 的 ros2_control 标签和 YAML 参数文件完成，部署方便
    • 

  • Controller Manager 管理控制器的生命周期，支持运行时切换控制模式
    • 

  • 该框架是 MoveIt2 轨迹执行和 Nav2 运动控制的底层基础
    •
