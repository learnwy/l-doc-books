ROS 2 QoS 策略

核心概念

ROS 2 的 QoS（Quality of Service）策略基于 DDS 标准，允许开发者对每个话题的通信行为进行细粒度控制。QoS 策略决定了消息的可靠性、持久性、历史深度和生命周期等关键属性，直接影响机器人系统的实时性和数据完整性。

预定义 QoS 配置
#include <rclcpp/rclcpp.hpp>

auto default_qos = rclcpp::QoS(10);

auto sensor_qos = rclcpp::SensorDataQoS();
// Best Effort + Volatile + Keep Last(5)

auto param_qos = rclcpp::ParametersQoS();
// Reliable + Transient Local + Keep Last(1000)

auto service_qos = rclcpp::ServicesQoS();
// Reliable + Volatile + Keep Last(10)

auto custom_qos = rclcpp::QoS(rclcpp::KeepLast(20))
    .reliability(rclcpp::ReliabilityPolicy::BestEffort)
    .durability(rclcpp::DurabilityPolicy::Volatile)
    .deadline(std::chrono::milliseconds(100))
    .liveliness(rclcpp::LivelinessPolicy::Automatic)
    .liveliness_lease_duration(std::chrono::seconds(5));

兼容性遵循"提供方至少满足请求方要求"的原则。发布者可以提供比订阅者要求更高的服务质量（如 Reliable 发布者 + Best Effort 订阅者），但不能反过来。在调试连接问题时，ros2 topic info -v 命令可以显示所有发布者和订阅者的 QoS 设置以及兼容性状态。


典型场景 QoS 配置
不同的机器人子系统对通信质量有不同的要求：


传感器数据流（激光雷达、摄像头）：使用 Best Effort + Volatile。传感器数据具有时效性——如果一帧数据丢失，等待重传没有意义，因为更新的数据已经到来。Keep Last(1) 或 Keep Last(5) 保证订阅者始终处理最新数据。


控制指令（cmd_vel、关节命令）：使用 Reliable + Volatile。控制指令不能丢失——一个丢失的速度指令可能导致机器人撞墙。但不需要 Transient Local，因为旧的控制指令对新连接者没有意义。


地图和参数：使用 Reliable + Transient Local。后连接的节点需要获取之前发布的地图或参数。Transient Local 确保迟到的订阅者也能收到最后一次发布的数据。


诊断和日志：使用 Best Effort + Volatile。诊断信息丢失不会影响系统安全，使用低开销的 QoS 避免占用通信带宽。

实时性配置
auto realtime_qos = rclcpp::QoS(rclcpp::KeepLast(1))
    .reliability(rclcpp::ReliabilityPolicy::BestEffort)
    .durability(rclcpp::DurabilityPolicy::Volatile)
    .deadline(std::chrono::milliseconds(10))
    .lifespan(std::chrono::milliseconds(50));

auto sub = create_subscription<Control>("cmd_vel", realtime_qos,
    [this](Control::UniquePtr msg) { execute_control(std::move(msg)); });

rclcpp::QoSEventCallbackGroup qos_events;
rclcpp::SubscriptionOptions sub_options;
sub_options.event_callbacks.deadline_callback =
    [](rclcpp::QOSDeadlineRequestedInfo &event) {
        RCLCPP_WARN(get_logger(), "Deadline missed: %d total",
                    event.total_count);
    };
Deadline 策略定义了消息必须到达的最大时间间隔。如果在 deadline 时间内没有收到新消息，DDS 触发 deadline missed 事件。配合回调函数可以实现看门狗机制——检测传感器掉线或通信中断。


Lifespan 策略定义消息的有效期限——超过 lifespan 的消息会被 DDS 自动丢弃，即使还在缓冲区中。这防止了订阅者处理过期数据，对安全关键系统尤为重要。


小结
    

  • ROS 2 QoS 基于 DDS 标准，提供可靠性、持久性、历史、截止时间等多维配置
    • 

  • 传感器数据使用 Best Effort 降低延迟，控制指令使用 Reliable 保证送达
    • 

  • 发布者和订阅者的 QoS 策略必须兼容，否则 DDS 拒绝建立连接
    • 

  • 不同子系统根据时效性、安全性和带宽需求选择不同的 QoS 组合
    • 

  • Deadline 和 Liveliness 策略是实时机器人系统的关键安全保障
    • 

  • Lifespan 策略防止订阅者处理过期数据，提升安全关键系统的可靠性
    • 

  • 合理的 QoS 配置需要在可靠性和实时性之间根据场景需求做出权衡
    •
