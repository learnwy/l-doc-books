Part IV · 编辑器与编译器编辑器架构与实现 简介语法与高亮 简介分词策略

分词策略

行级分词模型

代码编辑器的语法高亮通常基于行级分词（line-based tokenization）：逐行对文本进行词法分析，每一行产生一组 Token，每个 Token 描述一段文本的语法类型和对应的颜色。

interface Token {
  startIndex: number;
  type: string;
}

interface LineTokens {
  tokens: Token[];
  endState: TokenizerState;
}

interface TokenizerState {
  clone(): TokenizerState;
  equals(other: TokenizerState): boolean;
}

interface Tokenizer {
  getInitialState(): TokenizerState;
  tokenize(line: string, state: TokenizerState): LineTokens;
}
行级分词的核心设计特点：每一行的分词依赖于前一行的结束状态（end state），这使得多行字符串、注释块等跨行结构得以正确处理。

TextMate 语法
TextMate 语法是 VS Code 最主要的语法高亮引擎。它使用 Oniguruma 正则表达式引擎匹配文本模式，通过嵌套的 begin/end 规则描述跨行结构。


interface TextMateGrammar {
  scopeName: string;
  patterns: TextMatePattern[];
  repository: Record<string, TextMatePattern>;
}

interface TextMatePattern {
  match?: string;
  begin?: string;
  end?: string;
  name?: string;
  captures?: Record<number, { name: string }>;
  patterns?: TextMatePattern[];
  include?: string;
}

const typescriptGrammarExample: TextMatePattern[] = [
  {
    match: '\\b(const|let|var|function|class|interface|type)\\b',
    name: 'keyword.declaration.ts',

  },
  {
    begin: '"',
    end: '"',

    begin: '/\\*',
    end: '\\*/',

提示： TextMate 语法的 Oniguruma 正则引擎支持前瞻/后顾断言和反向引用，表达能力强于 JavaScript 原生正则。但这也意味着某些复杂语法规则可能导致灾难性回溯。VS Code 对每次正则匹配设有 5ms 超时限制，超时后该规则会被自动跳过。






Monarch：声明式分词
Monaco Editor 内置了一种名为 Monarch 的声明式分词引擎，相比 TextMate 语法更轻量、更易调试。


interface MonarchLanguage {
  defaultToken: string;
  tokenizer: Record<string, MonarchRule[]>;
}

type MonarchRule = [string | RegExp, string | MonarchAction];

interface MonarchAction {
  token: string;
  next?: string;
  bracket?: '@open' | '@close';
}

const monarchTypeScript: MonarchLanguage = {
  defaultToken: '',
  tokenizer: {
    root: [
      [/\b(const|let|var|function|class|return|if|else)\b/, 'keyword'],
      [/\b(true|false|null|undefined)\b/, 'constant'],
      [/\b\d+(\.\d+)?\b/, 'number'],
      [/"([^"\\]|\\.)*"/, 'string'],
      [/'([^'\\]|\\.)*'/, 'string'],
      [/\/\/.*$/, 'comment'],
      [/\/\*/, 'comment', '@comment'],
      [/[a-zA-Z_]\w*/, 'identifier'],
      [/[{}()\[\]]/, '@brackets'],
      [/[;,.]/, 'delimiter'],
    ],
    comment: [
      [/[^/*]+/, 'comment'],
      [/\*\//, 'comment', '@pop'],
      [/[/*]/, 'comment'],
    ],
  },
};

增量分词
编辑器不能在每次按键时都重新分词整个文件。增量分词（incremental tokenization）只重新处理受影响的行。


class IncrementalTokenizer {
  private states: TokenizerState[] = [];
  private lineTokens: LineTokens[] = [];
  private tokenizer: Tokenizer;

  constructor(tokenizer: Tokenizer) {
    this.tokenizer = tokenizer;
    this.states = [tokenizer.getInitialState()];
  }

  tokenizeLines(lines: string[]): void {
    for (let i = 0; i < lines.length; i++) {
      const result = this.tokenizer.tokenize(lines[i], this.states[i]);
      this.lineTokens[i] = result;
      this.states[i + 1] = result.endState;
    }
  }

  handleEdit(editStartLine: number, lines: string[]): number {
    let line = editStartLine;
    let changed = true;
    while (line < lines.length && changed) {
      const state = this.states[line] ?? this.tokenizer.getInitialState();
      const result = this.tokenizer.tokenize(lines[line], state);
      this.lineTokens[line] = result;
      const nextState = this.states[line + 1];
      changed = !(nextState && result.endState.equals(nextState));
      this.states[line + 1] = result.endState;
      line++;
    }
    return line - editStartLine;
  }

  getTokensForLine(lineNumber: number): LineTokens | undefined {
    return this.lineTokens[lineNumber];
  }
}

提示： VS Code 使用了异步分词策略：编辑后先用同步方式处理当前可见行（保证即时响应），然后在 idle 回调中逐步处理不可见行。如果在后续分词完成前用户又进行了编辑，之前的排队任务会被取消，重新从编辑点开始。






Token 缓存与存储
大文件中 Token 数量可能达到数十万个，高效的存储格式对内存和渲染性能至关重要。


class TokenStore {
  private tokenTypeMap: Map<string, number> = new Map();
  private tokenTypes: string[] = [];
  private lineData: Map<number, Uint32Array> = new Map();

  getTypeId(type: string): number {
    let id = this.tokenTypeMap.get(type);
    if (id === undefined) {
      id = this.tokenTypes.length;
      this.tokenTypes.push(type);
      this.tokenTypeMap.set(type, id);
    }
    return id;
  }

  storeLineTokens(lineNumber: number, tokens: Token[]): void {
    const packed = new Uint32Array(tokens.length);
    for (let i = 0; i < tokens.length; i++) {
      packed[i] = (tokens[i].startIndex << 16) | this.getTypeId(tokens[i].type);
    }
    this.lineData.set(lineNumber, packed);
  }

  getLineTokens(lineNumber: number): Token[] {
    const packed = this.lineData.get(lineNumber);
    if (!packed) return [];
    return Array.from(packed).map((val) => ({
      startIndex: val >> 16,
      type: this.tokenTypes[val & 0xffff],
    }));
  }
}

小结
    

  • 行级分词通过 endState 传递实现跨行结构（字符串、块注释）的正确处理。
    • 

  • TextMate 语法使用 Oniguruma 正则引擎，拥有最丰富的语法包生态。
    • 

  • Monarch 是 Monaco 内置的声明式分词引擎，使用 JavaScript 原生正则，性能更好。
    • 

  • 增量分词只重新处理受影响的行，通过 endState 比较判断是否继续级联。
    • 

  • Token 使用紧凑的 Uint32Array 编码存储，相比对象数组节省 95% 以上的内存。
