Gap Buffer 间隙缓冲区

Gap Buffer 的基本原理

Gap Buffer 是最简单也最古老的编辑器文本缓冲区实现之一，GNU Emacs 自 1985 年至今一直使用这种数据结构。其核心思想是在内存中维护一段连续的字符数组，并在光标位置保留一段"空隙"（gap），使得光标处的插入和删除操作为 O(1)。

TypeScript 实现
class GapBuffer {
  private buffer: string[];
  private gapStart: number;
  private gapEnd: number;

  constructor(initialText: string, gapSize = 256) {
    this.buffer = new Array(initialText.length + gapSize);
    this.gapStart = 0;
    this.gapEnd = gapSize;

    for (let i = 0; i < initialText.length; i++) {
      this.buffer[gapSize + i] = initialText[i];
    }
  }

  get length(): number {
    return this.buffer.length - (this.gapEnd - this.gapStart);
  }

  moveCursor(position: number): void {
    if (position < this.gapStart) {
      const moveCount = this.gapStart - position;
      for (let i = moveCount - 1; i >= 0; i--) {
        this.buffer[this.gapEnd - moveCount + i] = this.buffer[position + i];
      }
      this.gapEnd -= moveCount;
      this.gapStart = position;
    } else if (position > this.gapStart) {
      const moveCount = position - this.gapStart;
      for (let i = 0; i < moveCount; i++) {
        this.buffer[this.gapStart + i] = this.buffer[this.gapEnd + i];
      }
      this.gapStart += moveCount;
      this.gapEnd += moveCount;
    }
  }

  insert(position: number, text: string): void {
    this.moveCursor(position);
    this.ensureGap(text.length);
    for (let i = 0; i < text.length; i++) {
      this.buffer[this.gapStart + i] = text[i];
    }
    this.gapStart += text.length;
  }

  delete(position: number, count: number): void {
    this.moveCursor(position);
    this.gapEnd += count;
  }

  private ensureGap(needed: number): void {
    if (this.gapEnd - this.gapStart >= needed) return;
    const newGap = Math.max(needed, 256);
    const newBuffer = new Array(this.buffer.length + newGap);
    for (let i = 0; i < this.gapStart; i++) {
      newBuffer[i] = this.buffer[i];
    }
    const afterGap = this.buffer.length - this.gapEnd;
    for (let i = 0; i < afterGap; i++) {
      newBuffer[newBuffer.length - afterGap + i] = this.buffer[this.gapEnd + i];
    }
    this.gapEnd = this.gapStart + (this.gapEnd - this.gapStart) + newGap;
    this.buffer = newBuffer;
  }

  getText(): string {
    const before = this.buffer.slice(0, this.gapStart);
    const after = this.buffer.slice(this.gapEnd);
    return before.join('') + after.join('');
  }
}


光标局部性优化
Gap Buffer 的核心优势在于光标局部性：用户通常在当前光标位置附近进行连续编辑。当光标不移动时，插入和删除都是 O(1)。只有光标大幅跳转时才需要 O(n) 的 gap 搬移。

提示： Emacs 的 Gap Buffer 实现中，gap 的初始大小和扩容策略经过了数十年的调优。现代 Emacs 使用约 2KB 的初始 gap，并在需要扩容时按当前文件大小的一定比例增长，以减少 reallocation 次数。

提示： 如果你正在构建一个轻量级编辑器组件（例如单行输入框或小型代码块编辑器），Gap Buffer 的简单性是其最大优势。当文件不超过几千行时，Gap Buffer 的实际性能往往优于复杂的树结构，因为它具有更好的缓存局部性。






小结
    

  • Gap Buffer 在光标位置维护一段空隙，使局部编辑操作达到 O(1) 时间复杂度。
    • 

  • 光标局部性是 Gap Buffer 性能的关键假设，70% 以上的编辑操作发生在当前光标附近。
    • 

  • 对于多光标、协同编辑等需要任意位置 O(log n) 操作的场景，Gap Buffer 不是最佳选择。
    • 

  • 三种主流缓冲区数据结构各有适用场景：Gap Buffer 适合简单场景，Rope 适合多光标，Piece Table 综合最优。
    • 

  • 现代编辑器通常组合使用数据结构和索引策略，而非依赖单一方案。
