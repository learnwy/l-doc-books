Part IV · 编辑器与编译器编辑器架构与实现 简介文本缓冲区 简介行索引与编码

行索引与编码

行偏移索引的构建

代码编辑器中几乎所有操作都以"行号 + 列号"表示位置，但底层缓冲区存储的是字节或字符的线性序列。行偏移索引（Line Index）是连接这两种视图的桥梁——它记录每一行起始位置在缓冲区中的偏移量。

interface LineIndex {
  offsets: Uint32Array;
  lineCount: number;
}

function buildLineIndex(text: string): LineIndex {
  const offsets: number[] = [0];

  for (let i = 0; i < text.length; i++) {
    if (text[i] === '\n') {
      offsets.push(i + 1);
    } else if (text[i] === '\r') {
      if (i + 1 < text.length && text[i + 1] === '\n') {
        offsets.push(i + 2);
        i++;
      } else {
        offsets.push(i + 1);
      }
    }
  }

  return {
    offsets: new Uint32Array(offsets),
    lineCount: offsets.length,
  };
}

function getLineStartOffset(index: LineIndex, lineNumber: number): number {
  return index.offsets[lineNumber];
}

function getLineFromOffset(index: LineIndex, offset: number): number {
  let lo = 0;
  let hi = index.lineCount - 1;
  while (lo < hi) {
    const mid = (lo + hi + 1) >> 1;
    if (index.offsets[mid] <= offset) {
      lo = mid;
    } else {
      hi = mid - 1;
    }
  }
  return lo;
}
操作 时间复杂度 实现方式
行号 → 偏移量 O(1) 数组直接索引
偏移量 → 行号 O(log n) 二分搜索
构建完整索引 O(n) 单次遍历
增量更新（单行编辑） O(1) 调整后续偏移

function utf16OffsetToUtf8(text: string, utf16Offset: number): number {
  let utf8Offset = 0;
  for (let i = 0; i < utf16Offset; i++) {
    const code = text.charCodeAt(i);
    if (code <= 0x7f) {
      utf8Offset += 1;
    } else if (code <= 0x7ff) {
      utf8Offset += 2;
    } else if (code >= 0xd800 && code <= 0xdbff) {
      utf8Offset += 4;
      i++;
    } else {
      utf8Offset += 3;
    }
  }
  return utf8Offset;
}

function utf8OffsetToUtf16(text: string, targetUtf8: number): number {
  let utf8Offset = 0;
  let utf16Offset = 0;

  while (utf8Offset < targetUtf8 && utf16Offset < text.length) {
    const code = text.charCodeAt(utf16Offset);
    if (code <= 0x7f) {
      utf8Offset += 1;
    } else if (code <= 0x7ff) {
      utf8Offset += 2;
    } else if (code >= 0xd800 && code <= 0xdbff) {
      utf8Offset += 4;
      utf16Offset++;
    } else {
      utf8Offset += 3;
    }
    utf16Offset++;
  }
  return utf16Offset;
}


提示： LSP 3.17 引入了 positionEncoding 协商机制，客户端和服务器可以约定使用 UTF-8、UTF-16 或 UTF-32 偏移量。优先使用 UTF-32（码点偏移），可以避免绝大多数编码转换问题。

type EOLSequence = '\n' | '\r\n';

interface NormalizeResult {
  text: string;
  detectedEOL: EOLSequence;
  crlfCount: number;
  lfCount: number;
}

function normalizeEOL(raw: string): NormalizeResult {
  let crlfCount = 0,
    lfCount = 0;
  for (let i = 0; i < raw.length; i++) {
    if (raw[i] === '\r' && raw[i + 1] === '\n') {
      crlfCount++;
      i++;
    } else if (raw[i] === '\n') lfCount++;
  }
  const detectedEOL: EOLSequence = crlfCount > lfCount ? '\r\n' : '\n';
  const text = raw.replace(/\r\n/g, '\n').replace(/\r/g, '\n');
  return { text, detectedEOL, crlfCount, lfCount };
}
VS Code 的策略是在文件打开时检测并记录原始换行符类型，内部统一使用 LF，保存时恢复为原始格式。状态栏右下角显示当前文件的换行符类型。

function getCharWidth(codePoint: number): number {
  if (codePoint <= 0x7f) return 1;
  if (codePoint >= 0x1100 && codePoint <= 0x115f) return 2;
  if (codePoint >= 0x2e80 && codePoint <= 0x9fff) return 2;
  if (codePoint >= 0xac00 && codePoint <= 0xd7af) return 2;
  if (codePoint >= 0xf900 && codePoint <= 0xfaff) return 2;
  if (codePoint >= 0xfe30 && codePoint <= 0xfe6f) return 2;
  if (codePoint >= 0xff01 && codePoint <= 0xff60) return 2;
  if (codePoint >= 0xffe0 && codePoint <= 0xffe6) return 2;
  if (codePoint >= 0x20000 && codePoint <= 0x2ffff) return 2;
  return 1;
}

function getColumnFromOffset(line: string, charOffset: number): number {
  let column = 0;
  for (const ch of line.slice(0, charOffset)) column += getCharWidth(ch.codePointAt(0)!);
  return column;
}

function getOffsetFromColumn(line: string, targetColumn: number): number {
  let column = 0,
    offset = 0;
  for (const ch of line) {
    const w = getCharWidth(ch.codePointAt(0)!);
    if (column + w > targetColumn) break;
    column += w;
    offset += ch.length;
  }
  return offset;
}


提示： Tab 字符的列宽取决于当前列位置和 tabSize 设置。计算公式为 tabSize - (column % tabSize)，即 Tab 对齐到下一个 tabSize 的整数倍位置。这是光标定位中最容易忽略的边界情况之一。






增量索引更新
当用户进行编辑时，全量重建行索引代价过高。增量更新策略只修改受影响的区域：


function updateLineIndex(index: LineIndex, editOffset: number, deletedLength: number, insertedText: string): LineIndex {
  const editLine = getLineFromOffset(index, editOffset);
  let removedLines = 0;
  for (let i = editLine + 1; i < index.lineCount; i++) {
    if (index.offsets[i] <= editOffset + deletedLength) removedLines++;
    else break;
  }

  const newLineBreaks: number[] = [];
  for (let i = 0; i < insertedText.length; i++) {
    if (insertedText[i] === '\n') newLineBreaks.push(editOffset + i + 1);
  }

  const delta = insertedText.length - deletedLength;
  const newOffsets: number[] = [];
  for (let i = 0; i <= editLine; i++) newOffsets.push(index.offsets[i]);
  for (const lb of newLineBreaks) newOffsets.push(lb);
  for (let i = editLine + 1 + removedLines; i < index.lineCount; i++) {
    newOffsets.push(index.offsets[i] + delta);
  }

  return { offsets: new Uint32Array(newOffsets), lineCount: newOffsets.length };
}


小结
    

  • 行偏移索引是连接"行号 + 列号"位置表示与底层字节偏移量的桥梁。
    • 

  • UTF-8/UTF-16/UTF-32 编码差异是编辑器 bug 的高发区，LSP 3.17 的 positionEncoding 机制提供了标准解决方案。
    • 

  • 编辑器内部应统一使用 LF 换行符，在文件读写时进行归一化和恢复。
    • 

  • CJK 字符的双列宽度和 Tab 对齐是列计算中必须处理的特殊情况。
    • 

  • 增量行索引更新将编辑操作的索引维护成本从 O(n) 降低到 O(affected lines)。
