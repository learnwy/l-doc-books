Piece Table 片段表

什么是 Piece Table

Piece Table 是一种追加写入（append-only）的文本缓冲区数据结构，最早由 J Strother Moore 于 1983 年提出。VS Code 自 2018 年起采用 Piece Table 作为核心文本缓冲区实现，替代了此前基于行数组的方案。

Piece Table 的核心理念极其优雅：永远不修改原始文本，只记录"文本由哪些片段组成"。

组件 作用 可变性
Original Buffer 存储文件打开时的原始内容 只读
Add Buffer 存储所有后续新增的文本 追加写入
Piece 描述符表 有序列表，描述最终文本的片段组成 可修改 
上例表示将 "Hello World" 修改为 "Hello Beautiful World" 后的状态。




片段描述符设计
每个 Piece 描述符是一个轻量结构，指向某个缓冲区的一个区间：


type BufferKind = 'original' | 'add';

interface Piece {
  buffer: BufferKind;
  start: number;
  length: number;
}

interface PieceTable {
  original: string;
  add: string;
  pieces: Piece[];
}

function createPieceTable(content: string): PieceTable {
  return {
    original: content,
    add: '',
    pieces: [{ buffer: 'original', start: 0, length: content.length }],
  };
}

function getText(table: PieceTable): string {
  let result = '';
  for (const piece of table.pieces) {
    const buf = piece.buffer === 'original' ? table.original : table.add;
    result += buf.slice(piece.start, piece.start + piece.length);
  }
  return result;
}
关键特性：Piece 描述符只存储偏移量和长度，不复制任何文本内容，因此创建和拆分 Piece 的成本极低。

插入与删除操作
插入操作只需三步：将新文本追加到 Add Buffer，拆分受影响的 Piece，插入新的 Piece 描述符。


function insert(table: PieceTable, offset: number, text: string): void {
  const addStart = table.add.length;
  table.add += text;

  const newPiece: Piece = { buffer: 'add', start: addStart, length: text.length };

  let pos = 0;
  for (let i = 0; i < table.pieces.length; i++) {
    const piece = table.pieces[i];
    if (pos + piece.length >= offset) {
      const splitAt = offset - pos;
      if (splitAt === 0) {
        table.pieces.splice(i, 0, newPiece);
      } else if (splitAt === piece.length) {
        table.pieces.splice(i + 1, 0, newPiece);
      } else {
        const left: Piece = { buffer: piece.buffer, start: piece.start, length: splitAt };
        const right: Piece = {
          buffer: piece.buffer,
          start: piece.start + splitAt,
          length: piece.length - splitAt,
        };
        table.pieces.splice(i, 1, left, newPiece, right);
      }
      return;
    }
    pos += piece.length;
  }

  table.pieces.push(newPiece);
}

function remove(table: PieceTable, offset: number, length: number): void {
  let pos = 0;
  let remaining = length;

  for (let i = 0; i < table.pieces.length && remaining > 0; i++) {
    const piece = table.pieces[i];
    if (pos + piece.length <= offset) {
      pos += piece.length;
      continue;
    }

    const pieceOffset = Math.max(0, offset - pos);
    const removeLen = Math.min(remaining, piece.length - pieceOffset);

    if (pieceOffset === 0 && removeLen === piece.length) {
      table.pieces.splice(i, 1);
      i--;
    } else if (pieceOffset === 0) {
      piece.start += removeLen;
      piece.length -= removeLen;
    } else if (pieceOffset + removeLen === piece.length) {
      piece.length = pieceOffset;
    } else {
      const right: Piece = {
        buffer: piece.buffer,
        start: piece.start + pieceOffset + removeLen,
        length: piece.length - pieceOffset - removeLen,
      };
      piece.length = pieceOffset;
      table.pieces.splice(i + 1, 0, right);
    }

    remaining -= removeLen;
    pos += piece.length;
  }
}
删除操作同样不修改任何缓冲区内容，只调整或移除 Piece 描述符。




VS Code 的红黑树优化
VS Code 的 Piece Table 实现将 Piece 描述符组织为一棵红黑树（而非简单数组），以获得 O(log n) 的随机位置访问性能。


每个树节点额外维护两个聚合值：






字段
作用





leftLen
左子树的总字符数




leftLFCnt
左子树的总换行符数





通过这两个字段，可以在 O(log n) 时间内完成偏移量到 Piece 的定位，也能快速将行号映射为偏移量。




提示： 红黑树相比 AVL 树的优势在于插入/删除时的旋转次数更少（最多 2-3 次），对于编辑器这种写密集型场景更加友好。VS Code 源码中的 pieceTreeBase.ts 是学习这一实现的最佳参考。






追加写入的优势
Piece Table 的 append-only 设计带来了多项架构层面的优势：

说明

Add Buffer 记录了所有编辑的完整历史







小结
    

  • Piece Table 将文本表示为指向两个不可变缓冲区（Original + Add）的片段描述符序列。
    • 

  • 所有编辑操作只追加新文本到 Add Buffer 并调整 Piece 描述符，永不修改已有数据。
    • 

  • VS Code 使用红黑树组织 Piece 描述符，实现 O(log n) 的偏移量定位和行号映射。
    • 

  • append-only 设计天然支持低成本的撤销、快照和操作日志功能。
    • 

  • Piece Table 在编辑器场景中的综合表现优于 Rope 和 Gap Buffer，是现代编辑器的首选方案。
