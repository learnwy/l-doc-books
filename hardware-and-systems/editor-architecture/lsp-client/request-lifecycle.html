请求生命周期

请求的完整旅程

LSP 请求从用户操作触发到最终结果渲染，经历了多个阶段。理解这个生命周期对于构建响应迅速的编辑器至关重要。每个阶段都有优化空间，也有可能成为性能瓶颈。

interface RequestLifecycle<TParams, TResult> {
  readonly id: number;
  readonly method: string;
  readonly params: TParams;
  readonly timestamp: number;
  readonly cancellationToken: CancellationToken;
  readonly progress: ProgressReporter;
  result: Promise<TResult>;
}

interface CancellationToken {
  readonly isCancellationRequested: boolean;
  onCancellationRequested(listener: () => void): Disposable;
}

请求批处理与排序
当用户快速输入时，编辑器可能在短时间内生成大量请求。合理的批处理和排序策略可以显著减少服务器负载。


class RequestQueue {
  private queue: PendingRequest[] = [];
  private processing = false;

  enqueue(request: PendingRequest): void {
    const existing = this.queue.findIndex(
      (r) => r.method === request.method && r.textDocument === request.textDocument,
    );
    if (existing !== -1) {
      this.queue[existing].cancellationToken.cancel();
      this.queue[existing] = request;
    } else {
      this.queue.push(request);
    }
    this.queue.sort((a, b) => a.priority - b.priority);
    this.processNext();
  }

  private async processNext(): Promise<void> {
    if (this.processing || this.queue.length === 0) return;
    this.processing = true;
    const request = this.queue.shift()!;
    try {
      await this.send(request);
    } finally {
      this.processing = false;
      this.processNext();
    }
  }
}

取消令牌机制
取消是 LSP 高效运行的关键。当用户继续输入时，前一个尚未完成的补全请求应该被取消，释放服务器资源来处理最新请求。


class CancellationTokenSource {
  private _token: MutableCancellationToken;

  constructor() {
    this._token = new MutableCancellationToken();
  }

  get token(): CancellationToken {
    return this._token;
  }

  cancel(): void {
    this._token.cancel();
  }

  dispose(): void {
    this._token.dispose();
  }
}

class LspClient {
  private pendingRequests = new Map<number, CancellationTokenSource>();
  private nextId = 1;

  async sendRequest<T>(method: string, params: unknown): Promise<T> {
    const id = this.nextId++;
    const cts = new CancellationTokenSource();
    this.pendingRequests.set(id, cts);

    cts.token.onCancellationRequested(() => {
      this.connection.sendNotification('$/cancelRequest', { id });
    });

    try {
      return await this.connection.sendRequest<T>(method, params);
    } finally {
      this.pendingRequests.delete(id);
      cts.dispose();
    }
  }

  cancelRequest(id: number): void {
    this.pendingRequests.get(id)?.cancel();
  }
}


提示： 服务器收到取消通知后应尽快停止处理，但 LSP 规范允许服务器忽略取消通知并返回正常结果。客户端必须准备好处理已取消请求的延迟响应。






进度报告与部分结果
长时间运行的操作（如项目范围的符号搜索或大规模重构）需要向用户报告进度。LSP 3.15 引入了通用进度机制。


interface WorkDoneProgressParams {
  workDoneToken?: ProgressToken;
}

type ProgressToken = number | string;

interface WorkDoneProgressBegin {
  kind: 'begin';
  title: string;
  cancellable?: boolean;
  message?: string;
  percentage?: number;
}

interface WorkDoneProgressReport {
  kind: 'report';
  cancellable?: boolean;
  message?: string;
  percentage?: number;
}

interface WorkDoneProgressEnd {
  kind: 'end';
  message?: string;
}

class ProgressManager {
  private activeProgress = new Map<ProgressToken, ProgressUI>();

  handleProgress(
    token: ProgressToken,
    value: WorkDoneProgressBegin | WorkDoneProgressReport | WorkDoneProgressEnd,
  ): void {
    switch (value.kind) {
      case 'begin':
        this.activeProgress.set(token, this.createProgressUI(value));
        break;
      case 'report':
        this.activeProgress.get(token)?.update(value);
        break;
      case 'end':
        this.activeProgress.get(token)?.complete(value.message);
        this.activeProgress.delete(token);
        break;
    }
  }
}

防抖策略
防抖（Debouncing）是减少不必要请求的核心策略。不同类型的编辑操作需要不同的防抖参数。


class DebouncedRequestSender {
  private timers = new Map<string, ReturnType<typeof setTimeout>>();

  send<T>(key: string, delay: number, factory: () => Promise<T>): Promise<T> {
    return new Promise((resolve, reject) => {
      const existing = this.timers.get(key);
      if (existing) clearTimeout(existing);

      this.timers.set(
        key,
        setTimeout(async () => {
          this.timers.delete(key);
          try {
            resolve(await factory());
          } catch (e) {
            reject(e);
          }
        }, delay),
      );
    });
  }
}

const debouncer = new DebouncedRequestSender();

async function onTextChange(uri: string, changes: TextChange[]): Promise<void> {
  connection.sendNotification('textDocument/didChange', {
    textDocument: { uri, version: ++version },
    contentChanges: changes,
  });

  await debouncer.send(`diagnostics:${uri}`, 500, () =>
    connection.sendRequest('textDocument/diagnostic', {
      textDocument: { uri },
    }),
  );
}

小结
    

  • LSP 请求经历防抖、构建、传输、处理、渲染五个阶段，服务器处理占总耗时约 80%。
    • 

  • 请求队列通过合并同类请求和优先级排序减少服务器负载。
    • 

  • 取消令牌允许客户端中止未完成的请求，释放服务器资源处理最新操作。
    • 

  • 进度报告机制为长时间操作提供用户反馈，部分结果支持流式返回。
    • 

  • 不同操作类型的防抖延迟差异显著，从 0ms（签名帮助）到 500ms（语义高亮）。
