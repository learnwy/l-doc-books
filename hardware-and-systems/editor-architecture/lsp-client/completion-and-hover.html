补全与悬停

textDocument/completion 触发机制

代码补全是编辑器中使用频率最高的语言特性。LSP 的补全机制分为两种触发方式：用户主动调用（如 Ctrl+Space）和自动触发（输入特定字符如 . 或 /）。服务端通过能力声明告知客户端支持的触发字符。

interface CompletionOptions {
  triggerCharacters?: string[];
  allCommitCharacters?: string[];
  resolveProvider?: boolean;
  workDoneProgress?: boolean;
  completionItem?: {
    labelDetailsSupport?: boolean;
  };
}

interface CompletionParams {
  textDocument: TextDocumentIdentifier;
  position: Position;
  context?: CompletionContext;
}

interface CompletionContext {
  triggerKind: CompletionTriggerKind;
  triggerCharacter?: string;
}

enum CompletionTriggerKind {
  Invoked = 1,
  TriggerCharacter = 2,
  TriggerForIncompleteCompletions = 3,
}

提示： isIncomplete: true 表示服务器返回的是部分结果。TypeScript 语言服务器在返回超过 100 项时会设置此标志，要求客户端在用户继续输入时重新请求以获取精确结果。






补全项解析（Completion Resolve）
补全列表可能包含数百个项目，为每个项目计算完整文档和附加编辑代价很高。LSP 通过两阶段策略解决：先返回轻量列表，用户选中某项时再请求详细信息。


interface CompletionItem {
  label: string;
  labelDetails?: CompletionItemLabelDetails;
  kind?: CompletionItemKind;
  tags?: CompletionItemTag[];
  detail?: string;
  documentation?: string | MarkupContent;
  deprecated?: boolean;
  preselect?: boolean;
  sortText?: string;
  filterText?: string;
  insertText?: string;
  insertTextFormat?: InsertTextFormat;
  insertTextMode?: InsertTextMode;
  textEdit?: TextEdit | InsertReplaceEdit;
  textEditText?: string;
  additionalTextEdits?: TextEdit[];
  commitCharacters?: string[];
  data?: unknown;
}

  Class = 7,

代码片段语法（Snippet Grammar）
LSP 支持 TextMate 风格的代码片段语法，允许补全项插入包含占位符、选项和变量的模板文本。


enum InsertTextFormat {
  PlainText = 1,
  Snippet = 2,
}
片段语法规则：


tabstop      ::= '$' int | '${' int '}'
placeholder  ::= '${' int ':' any '}'
choice       ::= '${' int '|' text (',' text)* '|}'
variable     ::= '$' var | '${' var ':' any '}'
常见片段示例：


const snippetExamples: Record<string, string> = {
  forLoop: 'for (let ${1:i} = 0; $1 < ${2:array}.length; $1++) {\n\t$0\n}',
  arrowFunction: 'const ${1:name} = (${2:params}) => {\n\t$0\n};',
  tryCatch: 'try {\n\t$1\n} catch (${2:error}) {\n\t$0\n}',
  interfaceDecl: 'interface ${1:Name} {\n\t${2:property}: ${3:type};\n\t$0\n}',
  switchCase: 'switch (${1:key}) {\n\tcase ${2:value}:\n\t\t$0\n\t\tbreak;\n\tdefault:\n\t\tbreak;\n}',
};

提示： VS Code 和 Monaco Editor 共享同一套片段解析器。自定义语言服务器返回 Snippet 格式的补全项时，确保设置 insertTextFormat: 2，否则编辑器会将 $1 等语法视为纯文本。






悬停与签名帮助
悬停（Hover）在鼠标停留时显示类型信息和文档，签名帮助（Signature Help）在函数调用时显示参数提示。


interface HoverParams {
  textDocument: TextDocumentIdentifier;
  position: Position;
}

interface Hover {
  contents: MarkupContent | MarkedString | MarkedString[];
  range?: Range;
}

interface MarkupContent {
  kind: MarkupKind;
  value: string;
}

type MarkupKind = 'plaintext' | 'markdown';

interface SignatureHelpParams {
  textDocument: TextDocumentIdentifier;
  position: Position;
  context?: SignatureHelpContext;
}

interface SignatureHelp {
  signatures: SignatureInformation[];
  activeSignature?: number;
  activeParameter?: number;
}

interface SignatureInformation {
  label: string;
  documentation?: string | MarkupContent;
  parameters?: ParameterInformation[];
  activeParameter?: number;

跳转到定义与引用链
定义跳转和引用查找构成了代码导航的核心。LSP 定义了一组相关请求，支持从简单的单文件跳转到复杂的跨项目引用链。


type DefinitionResponse = Location | Location[] | LocationLink[] | null;

interface LocationLink {
  originSelectionRange?: Range;
  targetUri: string;
  targetRange: Range;
  targetSelectionRange: Range;
}

interface ReferenceParams {
  textDocument: TextDocumentIdentifier;
  position: Position;
  context: ReferenceContext;
}

interface ReferenceContext {
  includeDeclaration: boolean;
}

class NavigationService {
  async goToDefinition(uri: string, position: Position): Promise<Location[]> {
    const result = await this.client.sendRequest<DefinitionResponse>('textDocument/definition', {
      textDocument: { uri },
      position,
    });
    return this.normalizeLocations(result);
  }

  async findReferences(uri: string, position: Position): Promise<Location[]> {
    return this.client.sendRequest<Location[]>('textDocument/references', {
      textDocument: { uri },
      position,
      context: { includeDeclaration: false },
    });
  }

  async getTypeDefinition(uri: string, position: Position): Promise<Location[]> {
    const result = await this.client.sendRequest<DefinitionResponse>('textDocument/typeDefinition', {
      textDocument: { uri },
      position,
    });
    return this.normalizeLocations(result);
  }

  async getImplementation(uri: string, position: Position): Promise<Location[]> {
    const result = await this.client.sendRequest<DefinitionResponse>('textDocument/implementation', {
      textDocument: { uri },
      position,
    });
    return this.normalizeLocations(result);
  }
}

小结
    

  • 补全触发分三种：用户手动调用、触发字符和不完整补全的续请求。
    • 

  • 两阶段补全（列表 + Resolve）平衡了响应速度和信息完整性，初始列表目标 100ms 内返回。
    • 

  • TextMate 风格代码片段语法支持 Tab Stop、Placeholder、Choice 和 Variable 四种元素。
    • 

  • Hover 返回 Markdown 格式的类型和文档信息，SignatureHelp 在函数调用时提供参数级提示。
    • 

  • 五种导航请求（definition/typeDefinition/implementation/references/declaration）构成完整的代码导航链。
