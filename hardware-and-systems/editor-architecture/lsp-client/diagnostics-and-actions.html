诊断与代码操作

publishDiagnostics 推送流程

诊断是 LSP 中最常见的服务器到客户端通知。语言服务器在分析代码后，通过 textDocument/publishDiagnostics 将错误、警告等信息推送给编辑器。编辑器收到后在相应位置渲染波浪线、侧边栏图标等视觉提示。

interface PublishDiagnosticsParams {
  uri: string;
  version?: number;
  diagnostics: Diagnostic[];
}

interface Diagnostic {
  range: Range;
  severity?: DiagnosticSeverity;
  code?: number | string;
  codeDescription?: CodeDescription;
  source?: string;
  message: string;
  tags?: DiagnosticTag[];
  relatedInformation?: DiagnosticRelatedInformation[];
  data?: unknown;
}

interface DiagnosticRelatedInformation {
  location: Location;
  message: string;
}




字段
作用
示例值





range
诊断位置范围
{start: {line:5,char:10}, ...}




severity
严重级别
Error=1, Warning=2




code
错误代码
"TS2322", "E0308"

来源标识
"typescript", "eslint"

附加标签
Unnecessary=1, Deprecated=2

关联位置

提示： version 字段是 LSP 3.15 新增的关键特性。客户端可以用它判断诊断是否对应当前文档版本，避免因网络延迟显示过时的诊断信息。






诊断严重级别与标签
LSP 定义了四个严重级别和两个诊断标签，编辑器通常为每个级别分配不同的视觉样式。


enum DiagnosticSeverity {
  Error = 1,
  Warning = 2,
  Information = 3,
  Hint = 4,
}

enum DiagnosticTag {
  Unnecessary = 1,
  Deprecated = 2,
}

class DiagnosticRenderer {
  private decorationTypes = new Map<DiagnosticSeverity, TextEditorDecorationType>();

  render(uri: string, diagnostics: Diagnostic[]): void {
    const grouped = this.groupBySeverity(diagnostics);

    for (const [severity, items] of grouped) {
      const ranges = items.map((d) => d.range);
      this.applyDecoration(uri, severity, ranges);
    }

    this.updateProblemsPanel(uri, diagnostics);
    this.updateStatusBar(diagnostics);
  }

  private groupBySeverity(diagnostics: Diagnostic[]): Map<DiagnosticSeverity, Diagnostic[]> {
    const map = new Map<DiagnosticSeverity, Diagnostic[]>();
    for (const d of diagnostics) {
      const severity = d.severity ?? DiagnosticSeverity.Error;
      if (!map.has(severity)) map.set(severity, []);
      map.get(severity)!.push(d);
    }
    return map;
  }
}

代码操作（Code Actions）
代码操作是 LSP 最具生产力价值的特性之一。当光标位于诊断范围内时，编辑器请求服务器提供可用的修复或重构操作。


interface CodeActionParams {
  textDocument: TextDocumentIdentifier;
  range: Range;
  context: CodeActionContext;
}

interface CodeActionContext {
  diagnostics: Diagnostic[];
  only?: CodeActionKind[];
  triggerKind?: CodeActionTriggerKind;
}

type CodeActionKind =
  | 'quickfix'
  | 'refactor'
  | 'refactor.extract'
  | 'refactor.inline'
  | 'refactor.rewrite'
  | 'source'
  | 'source.organizeImports'
  | 'source.fixAll';

interface CodeAction {
  title: string;
  kind?: CodeActionKind;
  diagnostics?: Diagnostic[];
  isPreferred?: boolean;
  disabled?: { reason: string };
  edit?: WorkspaceEdit;
  command?: Command;
  data?: unknown;
}




操作类型
描述
示例





quickfix
快速修复
添加缺失导入、修复拼写




refactor.extract
提取重构
提取变量、提取函数




refactor.inline
内联重构
内联变量、内联函数




source.organizeImports
组织导入
排序和移除未使用的导入




source.fixAll
修复全部
应用所有自动修复







提示： isPreferred 标记为 true 的代码操作可以绑定到快捷键直接执行，无需弹出菜单。VS Code 的 "Auto Fix" 功能就依赖此字段。






WorkspaceEdit 编辑模型
代码操作最终通过 WorkspaceEdit 应用修改。这个数据结构支持跨文件编辑、文件创建/删除/重命名等复杂操作。


interface WorkspaceEdit {
  changes?: { [uri: string]: TextEdit[] };
  documentChanges?: (TextDocumentEdit | CreateFile | RenameFile | DeleteFile)[];
  changeAnnotations?: {
    [id: string]: ChangeAnnotation;
  };
}

interface TextEdit {
  range: Range;
  newText: string;
}

interface ChangeAnnotation {
  label: string;
  needsConfirmation?: boolean;
  description?: string;
}

class WorkspaceEditApplier {
  async apply(edit: WorkspaceEdit): Promise<boolean> {
    if (edit.documentChanges) {
      for (const change of edit.documentChanges) {
        if ('kind' in change) await this.applyResourceOperation(change);
        else await this.applyTextEdits(change.textDocument, change.edits);
      }
    } else if (edit.changes) {
      for (const [uri, edits] of Object.entries(edit.changes)) {
        await this.applyTextEdits({ uri }, edits);
      }
    }
    return true;
  }
}


工作区诊断拉取模型
LSP 3.17 引入了诊断拉取模型（Pull Diagnostics），与传统推送模型互补。拉取模型允许客户端主动请求诊断，适用于未打开文件的工作区级诊断。


interface DocumentDiagnosticParams {
  textDocument: TextDocumentIdentifier;
  identifier?: string;
  previousResultId?: string;
}

type DocumentDiagnosticReport = RelatedFullDocumentDiagnosticReport | RelatedUnchangedDocumentDiagnosticReport;

interface RelatedFullDocumentDiagnosticReport {
  kind: 'full';
  resultId?: string;
  items: Diagnostic[];
  relatedDocuments?: {
    [uri: string]: FullDocumentDiagnosticReport | UnchangedDocumentDiagnosticReport;
  };
}

interface RelatedUnchangedDocumentDiagnosticReport {
  kind: 'unchanged';
  resultId: string;
}

小结
    

  • publishDiagnostics 是服务器推送诊断的核心通知，支持版本匹配避免显示过时信息。
    • 

  • 四个严重级别（Error/Warning/Information/Hint）和两个标签（Unnecessary/Deprecated）提供丰富的视觉反馈。
    • 

  • 代码操作覆盖快速修复、重构和源代码操作三大类，isPreferred 标记支持快捷键直接执行。
    • 

  • WorkspaceEdit 支持跨文件文本编辑和资源操作（创建/重命名/删除），变更注解支持用户确认。
    • 

  • LSP 3.17 拉取模型与推送模型互补，客户端可按需请求诊断并通过 resultId 实现增量更新。
    •
