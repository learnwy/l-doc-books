LSP 协议概览

JSON-RPC 2.0 传输层

语言服务器协议（LSP）构建在 JSON-RPC 2.0 之上，这是一种无状态的轻量级远程调用协议。编辑器（客户端）与语言服务器通过 stdio、socket 或管道进行双向通信，每条消息由 HTTP 风格的头部和 JSON 主体组成。

interface JsonRpcMessage {
  jsonrpc: '2.0';
}

interface RequestMessage extends JsonRpcMessage {
  id: number | string;
  method: string;
  params?: unknown[] | object;
}

interface ResponseMessage extends JsonRpcMessage {
  id: number | string | null;
  result?: unknown;
  error?: ResponseError;
}

interface NotificationMessage extends JsonRpcMessage {
  method: string;
  params?: unknown[] | object;
}

interface ResponseError {
  code: number;
  message: string;
  data?: unknown;
}

传输帧格式示例：

Content-Length: 73\r\n
\r\n
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"capabilities":{}}}
传输方式 适用场景 特点
stdio 本地进程通信 最常用，VS Code 默认方式
TCP Socket 远程语言服务器 支持网络访问，需处理重连
Named Pipe Windows 本地 Windows 专有，高性能
WebSocket 浏览器环境 Monaco Editor 在线版常用方式

提示： JSON-RPC 消息中没有 method 字段的是响应消息，有 id 的是请求消息，既无 id 也无 result 的是通知消息。区分这三种类型是理解 LSP 的关键。

初始化握手流程
LSP 连接建立后的第一件事是执行初始化握手。这是一个严格的三步流程：客户端发送 initialize 请求，服务端返回能力声明，客户端发送 initialized 通知确认。


interface InitializeParams {
  processId: number | null;
  rootUri: string | null;
  capabilities: ClientCapabilities;
  initializationOptions?: unknown;
  workspaceFolders?: WorkspaceFolder[] | null;
}

interface InitializeResult {
  capabilities: ServerCapabilities;
  serverInfo?: {
    name: string;
    version?: string;
  };
}


提示： 在 initialized 通知发送之前，客户端不应发送任何其他请求或通知。违反此约定可能导致服务器忽略消息或返回错误。






能力协商机制
能力协商是 LSP 最精妙的设计之一。客户端和服务器各自声明支持的功能集，双方根据交集决定可用特性。这使得协议可以渐进演进而不破坏兼容性。

服务器生命周期
语言服务器的生命周期从进程启动到优雅关闭，编辑器需要管理整个过程，包括异常恢复。


interface LanguageServerManager {
  start(config: ServerConfig): Promise<void>;
  stop(): Promise<void>;
  restart(): Promise<void>;
  onCrash(handler: (error: Error) => void): void;
}

interface ServerConfig {
  command: string;
  args: string[];
  transport: 'stdio' | 'socket' | 'pipe';
  maxRestartCount: number;
  restartDelayMs: number;
  initializationOptions?: unknown;
}

class ServerLifecycle implements LanguageServerManager {
  private restartCount = 0;

  async start(config: ServerConfig): Promise<void> {
    const process = spawn(config.command, config.args);
    const connection = createConnection(process.stdin, process.stdout);

    const result = await connection.sendRequest<InitializeResult>('initialize', {
      capabilities: this.getClientCapabilities(),
    });

    this.negotiatedCapabilities = result.capabilities;
    connection.sendNotification('initialized', {});
  }

  async stop(): Promise<void> {
    await this.connection.sendRequest('shutdown');
    this.connection.sendNotification('exit');
  }

  async restart(): Promise<void> {
    if (this.restartCount >= this.config.maxRestartCount) {
      throw new Error('Max restart count exceeded');
    }
    this.restartCount++;
    await this.stop().catch(() => {});
    await delay(this.config.restartDelayMs);
    await this.start(this.config);
  }
}

小结
    

  • LSP 基于 JSON-RPC 2.0，通过 stdio/socket/pipe 传输带有 Content-Length 头的 JSON 消息。
    • 

  • 三种消息类型各司其职：Request 需要响应，Notification 单向通知，Response 承载结果。
    • 

  • 初始化握手是严格的三步流程：initialize → InitializeResult → initialized。
    • 

  • 能力协商让客户端和服务器各自声明功能集，根据交集决定可用特性。
    • 

  • 服务器生命周期包括启动、运行、关闭和崩溃恢复四个阶段，编辑器需管理全过程。
    •
