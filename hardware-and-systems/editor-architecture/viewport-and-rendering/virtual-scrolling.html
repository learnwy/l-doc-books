Part IV · 编辑器与编译器编辑器架构与实现 简介视口与渲染 简介虚拟滚动

虚拟滚动

为什么需要虚拟滚动

一个包含 100 万行的日志文件，如果为每一行都创建 DOM 元素，将产生超过 100 万个 DOM 节点。现代浏览器在 DOM 节点超过数千个时就会出现明显的性能下降。虚拟滚动的核心思想是：只为视口（viewport）内可见的行创建 DOM 元素，随着滚动动态回收和复用节点。

指标 全量渲染 (100K 行) 虚拟滚动 (100K 行)
DOM 节点数 ~100,000 ~60-80
首次渲染时间 > 5s < 50ms
内存占用 > 500MB < 20MB
滚动帧率 < 10fps 60fps

核心实现原理

虚拟滚动的基本模型：通过一个固定高度的容器和一个"撑高"元素来模拟完整的滚动区域，只在可见区域内渲染实际内容。

interface VirtualScrollState {
  scrollTop: number;
  containerHeight: number;
  lineHeight: number;
  totalLines: number;
  overscan: number;
}

interface VisibleRange {
  startLine: number;
  endLine: number;
  offsetY: number;
}

function computeVisibleRange(state: VirtualScrollState): VisibleRange {
  const { scrollTop, containerHeight, lineHeight, totalLines, overscan } = state;

  const rawStart = Math.floor(scrollTop / lineHeight);
  const rawEnd = Math.ceil((scrollTop + containerHeight) / lineHeight);

  const startLine = Math.max(0, rawStart - overscan);
  const endLine = Math.min(totalLines - 1, rawEnd + overscan);
  const offsetY = startLine * lineHeight;

  return { startLine, endLine, offsetY };
}

function getTotalHeight(state: VirtualScrollState): number {
  return state.totalLines * state.lineHeight;
}

预渲染缓冲区（Overscan）
滚动时如果只渲染精确可见的行，用户会看到短暂的白屏闪烁。Overscan 缓冲区在可见区域上下各多渲染若干行，为快速滚动提供缓冲。


interface OverscanConfig {
  top: number;
  bottom: number;
  dynamicMultiplier: number;
}

function computeDynamicOverscan(scrollVelocity: number, baseOverscan: OverscanConfig): OverscanConfig {
  const velocity = Math.abs(scrollVelocity);
  const multiplier = velocity > 1000 ? 3 : velocity > 500 ? 2 : 1;

  return {
    top: baseOverscan.top * multiplier,
    bottom: baseOverscan.bottom * multiplier,
    dynamicMultiplier: multiplier,
  };
}


提示： VS Code 使用了一种更激进的策略：将整个渲染区域分为"稳定区"和"快速滚动区"。快速滚动时（如拖动滚动条），暂时切换到简化渲染模式（只渲染行号和空白占位），待滚动停止后再渲染完整内容。这种策略显著提升了大文件的滚动流畅度。






滚动物理模拟
平滑的滚动体验依赖精确的滚动物理模拟。编辑器需要处理多种滚动输入源，并将它们转换为统一的滚动位置更新。

class SmoothScroller {
  private targetScrollTop = 0;
  private currentScrollTop = 0;
  private animationFrame: number | null = null;

  scrollTo(target: number, animated = true): void {
    this.targetScrollTop = Math.max(0, target);

    if (!animated) {
      this.currentScrollTop = this.targetScrollTop;
      this.render();
      return;
    }

    if (!this.animationFrame) {
      this.animate();
    }
  }

  scrollByDelta(delta: number): void {
    this.scrollTo(this.targetScrollTop + delta);
  }

  private animate(): void {
    const diff = this.targetScrollTop - this.currentScrollTop;
    if (Math.abs(diff) < 0.5) {
      this.currentScrollTop = this.targetScrollTop;
      this.render();
      this.animationFrame = null;
      return;
    }

    this.currentScrollTop += diff * 0.15;
    this.render();
    this.animationFrame = requestAnimationFrame(() => this.animate());
  }

  private render(): void {
    const range = computeVisibleRange({
      scrollTop: this.currentScrollTop,
      containerHeight: 800,
      lineHeight: 20,
      totalLines: 100000,
      overscan: 5,
    });
    this.updateDOM(range);
  }

  private updateDOM(_range: VisibleRange): void {}
}


Intersection Observer 模式
除了传统的 scroll 事件监听，现代浏览器的 Intersection Observer API 提供了一种高性能的可见性检测方案。


class IntersectionVirtualList {
  private observer: IntersectionObserver;
  private sentinels: Map<number, HTMLElement> = new Map();

  constructor(
    private container: HTMLElement,
    private renderLine: (line: number) => HTMLElement,
  ) {
    this.observer = new IntersectionObserver((entries) => this.handleIntersection(entries), {
      root: container,
      rootMargin: '100px 0px',
    });
  }

  private handleIntersection(entries: IntersectionObserverEntry[]): void {
    for (const entry of entries) {
      const lineNumber = parseInt(entry.target.getAttribute('data-line')!);
      if (entry.isIntersecting) {
        const content = this.renderLine(lineNumber);
        entry.target.replaceWith(content);
      }
    }
  }

  createSentinel(lineNumber: number): HTMLElement {
    const sentinel = document.createElement('div');
    sentinel.setAttribute('data-line', String(lineNumber));
    sentinel.style.height = '20px';
    this.observer.observe(sentinel);
    this.sentinels.set(lineNumber, sentinel);
    return sentinel;
  }

  dispose(): void {
    this.observer.disconnect();
    this.sentinels.clear();
  }
}

提示： 在实际的编辑器项目中，纯粹的 Intersection Observer 方案很少单独使用，因为编辑器需要精确控制每一行的渲染时机和顺序。更常见的做法是使用 scroll 事件 + requestAnimationFrame 的组合，在每一帧精确计算需要渲染的行范围。Monaco Editor 和 CodeMirror 6 都采用了这种方案。






小结
    

  • 虚拟滚动通过只渲染视口内的行将 DOM 节点数从数万降低到几十个，是大文件编辑的基础。
    • 

  • Overscan 缓冲区在可见区域上下多渲染若干行，消除快速滚动时的白屏闪烁。
    • 

  • 滚动物理模拟需要统一处理鼠标滚轮、触控板、键盘和程序化滚动等多种输入源。
    • 

  • scroll 事件 + requestAnimationFrame 是编辑器虚拟滚动的主流实现方案。
    • 

  • 快速滚动时可临时切换为简化渲染模式，滚动停止后再渲染完整内容。
