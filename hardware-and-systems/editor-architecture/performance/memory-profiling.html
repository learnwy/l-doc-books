内存分析

大文件的内存占用

编辑器处理大文件时，内存管理成为关键挑战。一个 100MB 的日志文件在内存中可能占用数倍于文件大小的空间，因为需要维护行索引、Token 缓存、语法树等辅助数据结构。

interface MemoryFootprint {
  textBuffer: number;
  lineIndex: number;
  tokenCache: number;
  syntaxTree: number;
  decorations: number;
  undoStack: number;
  total: number;
}

class MemoryEstimator {
  estimate(document: TextDocument): MemoryFootprint {
    const textSize = document.getText().length * 2;
    const lineCount = document.lineCount;

    return {
      textBuffer: textSize,
      lineIndex: lineCount * 12,
      tokenCache: lineCount * 200,
      syntaxTree: textSize * 0.5,
      decorations: lineCount * 50,
      undoStack: textSize * 0.1,
      total: textSize + lineCount * 262 + textSize * 0.6,
    };
  }
}

字符串驻留（String Interning）
编辑器中大量重复的字符串（如关键字、标识符、文件路径）可以通过字符串驻留共享内存。驻留池维护唯一字符串的引用，相同内容的字符串指向同一个内存地址。


class StringInterner {
  private pool = new Map<string, string>();
  private hits = 0;
  private misses = 0;

  intern(str: string): string {
    const existing = this.pool.get(str);
    if (existing !== undefined) {
      this.hits++;
      return existing;
    }
    this.misses++;
    this.pool.set(str, str);
    return str;
  }

  getStats(): { poolSize: number; hitRate: number } {
    const total = this.hits + this.misses;
    return {
      poolSize: this.pool.size,
      hitRate: total > 0 ? this.hits / total : 0,
    };
  }

  clear(): void {
    this.pool.clear();
    this.hits = 0;
    this.misses = 0;
  }
}

class TokenFactory {
  private interner = new StringInterner();

  createToken(type: string, value: string): Token {
    return {
      type: this.interner.intern(type),
      value: this.interner.intern(value),
    };
  }
}

缓冲区池化（Buffer Pooling）
频繁的内存分配和释放是性能杀手。缓冲区池（Buffer Pool）预分配固定大小的内存块，重用已释放的缓冲区。


class BufferPool {
  private pools = new Map<number, ArrayBuffer[]>();
  private readonly sizes = [256, 1024, 4096, 16384, 65536];

  acquire(requestedSize: number): ArrayBuffer {
    const size = this.findBestSize(requestedSize);
    const pool = this.pools.get(size);

    if (pool && pool.length > 0) {
      return pool.pop()!;
    }

    return new ArrayBuffer(size);
  }

  release(buffer: ArrayBuffer): void {
    const size = buffer.byteLength;
    if (!this.sizes.includes(size)) return;

    let pool = this.pools.get(size);
    if (!pool) {
      pool = [];
      this.pools.set(size, pool);
    }

    if (pool.length < 32) {
      pool.push(buffer);
    }
  }

  private findBestSize(requested: number): number {
    for (const size of this.sizes) {
      if (size >= requested) return size;
    }
    return requested;
  }

  getStats(): PoolStats {
    const stats: PoolStats = { totalPooled: 0, totalBytes: 0 };
    for (const [size, pool] of this.pools) {
      stats.totalPooled += pool.length;
      stats.totalBytes += pool.length * size;
    }
    return stats;
  }
}

WeakRef 缓存
WeakRef 允许缓存对象同时不阻止垃圾回收。当内存压力增大时，GC 可以自动释放 WeakRef 引用的对象。这对编辑器中的各种缓存（语法树、格式化结果、悬停信息）非常适合。


class WeakCache<K, V extends object> {
  private cache = new Map<K, WeakRef<V>>();
  private registry: FinalizationRegistry<K>;

  constructor() {
    this.registry = new FinalizationRegistry((key: K) => {
      const ref = this.cache.get(key);
      if (ref && ref.deref() === undefined) this.cache.delete(key);
    });
  }

  set(key: K, value: V): void {
    this.cache.set(key, new WeakRef(value));
    this.registry.register(value, key, value);
  }

  get(key: K): V | undefined {
    const ref = this.cache.get(key);
    if (!ref) return undefined;
    const value = ref.deref();
    if (!value) {
      this.cache.delete(key);
      return undefined;
    }
    return value;
  }
}

const syntaxTreeCache = new WeakCache<string, SyntaxTree>();
const hoverCache = new WeakCache<string, HoverResult>();
const formattingCache = new WeakCache<string, FormattingResult>();

Chrome DevTools 内存分析
Chrome DevTools 提供了强大的内存分析工具，对于基于 Electron 或 Web 的编辑器至关重要。


class MemoryProfiler {
  monitorMemoryUsage(intervalMs: number): Disposable {
    const timer = setInterval(() => {
      if ('memory' in performance) {
        const memory = (performance as PerformanceWithMemory).memory;
        const usage = {
          usedJSHeapSize: this.formatBytes(memory.usedJSHeapSize),
          totalJSHeapSize: this.formatBytes(memory.totalJSHeapSize),
          jsHeapSizeLimit: this.formatBytes(memory.jsHeapSizeLimit),
          utilization: ((memory.usedJSHeapSize / memory.jsHeapSizeLimit) * 100).toFixed(1) + '%',
        };
        this.reportToTelemetry(usage);
      }
    }, intervalMs);

    return { dispose: () => clearInterval(timer) };
  }

  private formatBytes(bytes: number): string {
    const units = ['B', 'KB', 'MB', 'GB'];
    let unitIndex = 0;
    let value = bytes;
    while (value >= 1024 && unitIndex < units.length - 1) {
      value /= 1024;
      unitIndex++;
    }
    return `${value.toFixed(1)} ${units[unitIndex]}`;
  }
}

小结
    

  • 大文件在内存中可能占用数倍于文件大小的空间，编辑器需要对超大文件采取降级策略。
    • 

  • 字符串驻留通过共享重复字符串的内存引用，对 Token 类型和关键字可节省 95%+ 的重复存储。
    • 

  • 缓冲区池化预分配固定大小的内存块并重用，减少 GC 压力和内存碎片。
    • 

  • WeakRef 缓存允许在内存充足时加速访问，在内存紧张时自动释放，适合语法树等大对象。
    • 

  • Chrome DevTools 的 Heap Snapshot 和 Allocation Timeline 是定位内存泄漏和优化内存使用的核心工具。
