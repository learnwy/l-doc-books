保存时格式化流水线

Format-on-Save 架构

保存时格式化（Format-on-Save）是开发者最常用的自动化格式化触发方式。编辑器在用户保存文件时拦截操作，先执行格式化再写入磁盘。这个流程需要精心设计以确保速度和可靠性。

interface SaveParticipant {
  waitUntil(promise: Thenable<TextEdit[]>): void;
}

class FormatOnSaveParticipant {
  private formatters = new Map<string, FormattingProvider>();

  async participate(document: TextDocument, reason: TextDocumentSaveReason): Promise<TextEdit[]> {
    if (reason === TextDocumentSaveReason.AfterDelay) {
      return [];
    }

    const config = this.getConfig(document.uri);
    if (!config.formatOnSave) return [];

    const formatter = await this.resolveFormatter(document);
    if (!formatter) return [];

    const timeout = config.formatOnSaveTimeout ?? 750;
    return Promise.race([formatter.format(document), this.createTimeout(timeout)]);
  }

  private createTimeout(ms: number): Promise<TextEdit[]> {
    return new Promise((resolve) => {
      setTimeout(() => resolve([]), ms);
    });
  }
}

Format-on-Type 机制
Format-on-Type 在用户输入时自动格式化，比 Format-on-Save 更即时。它通常只处理当前行或当前语句的缩进调整。


class FormatOnTypeHandler {
  private triggerCharacters: string[];
  private enabled: boolean;

  constructor(config: EditorConfig) {
    this.enabled = config.formatOnType;
    this.triggerCharacters = ['}', ';', '\n'];
  }

  async onCharacterTyped(document: TextDocument, position: Position, ch: string): Promise<TextEdit[]> {
    if (!this.enabled) return [];
    if (!this.triggerCharacters.includes(ch)) return [];

    const provider = this.getOnTypeProvider(document.languageId);
    if (!provider) return [];

    return provider.provideOnTypeFormattingEdits(document, position, ch, {
      tabSize: this.config.tabSize,
      insertSpaces: this.config.insertSpaces,
    });
  }
}

Pre-Commit Hooks 集成
格式化不仅发生在编辑器内，还应该在代码提交时作为最后的质量关卡。编辑器可以与 Git hooks 工具链集成。


interface PreCommitConfig {
  tool: 'husky' | 'lefthook' | 'lint-staged' | 'custom';
  formatCommand: string;
  stagedOnly: boolean;
}

const huskyConfig = {
  husky: {
    hooks: {
      'pre-commit': 'lint-staged',
    },
  },
};

const lintStagedConfig = {
  '*.{ts,tsx}': ['prettier --write', 'eslint --fix'],
  '*.{css,scss}': ['prettier --write'],
  '*.{json,md}': ['prettier --write'],
  '*.rs': ['rustfmt'],
  '*.py': ['ruff format'],
};

class PreCommitIntegration {
  async setupHooks(projectRoot: string): Promise<void> {
    const packageJson = await this.readPackageJson(projectRoot);

    const hooks = this.detectHookTool(projectRoot);
    switch (hooks) {
      case 'husky':
        await this.setupHusky(projectRoot);
        break;
      case 'lefthook':
        await this.setupLefthook(projectRoot);
        break;
    }
  }

  private async setupHusky(root: string): Promise<void> {
    const hookContent = ['#!/usr/bin/env sh', '. "$(dirname -- "$0")/_/husky.sh"', 'npx lint-staged'].join('\n');
    await this.writeFile(`${root}/.husky/pre-commit`, hookContent);
  }
}

提示： lint-staged 只对 git 暂存区（staged）的文件运行格式化，而不是整个项目。这确保了 pre-commit 钩子的执行速度，即使项目很大也只处理本次提交涉及的文件。






格式化器冲突处理
当项目中同时配置了多个格式化器时（如 Prettier + ESLint），可能产生冲突——一个格式化器的输出可能违反另一个的规则。


interface ConflictResolutionStrategy {
  name: string;
  resolve(formatters: FormatterChain[]): FormatterChain;
}

class SequentialStrategy implements ConflictResolutionStrategy {
  name = 'sequential';

  resolve(formatters: FormatterChain[]): FormatterChain {
    return {
      async format(source: string, options: FormatOptions): Promise<string> {
        let result = source;
        for (const formatter of formatters) result = await formatter.format(result, options);
        return result;
      },
    };
  }
}

class PrettierESLintIntegration {
  async format(source: string, filePath: string): Promise<string> {
    const prettierResult = await prettier.format(source, {
      filepath: filePath,
    });

    const eslintResult = await this.eslint.lintText(prettierResult, {
      filePath,
      fix: true,
    });

    return eslintResult[0].output ?? prettierResult;
  }
}

编辑器配置级联
编辑器的格式化设置支持多层级联：语言特定设置覆盖全局设置，工作区设置覆盖用户设置。


interface ConfigurationCascade {
  default: FormatConfig;
  user: Partial<FormatConfig>;
  workspace: Partial<FormatConfig>;
  workspaceFolder: Partial<FormatConfig>;
  languageSpecific: Record<string, Partial<FormatConfig>>;
}

class ConfigurationService {
  resolve(languageId: string, resource: Uri): FormatConfig {
    const base = { ...this.default };
    Object.assign(base, this.user);
    Object.assign(base, this.workspace);
    Object.assign(base, this.workspaceFolder);
    Object.assign(base, this.languageSpecific[languageId] ?? {});
    return base as FormatConfig;
  }
}

小结
    

  • Format-on-Save 在保存时触发格式化，支持全文件和仅修改行两种模式，超时保护避免阻塞保存。
    • 

  • Format-on-Type 在每次按键时触发，仅处理缩进等轻量级调整，延迟要求极低（<10ms）。
    • 

  • Pre-commit hooks 通过 husky + lint-staged 组合在提交时格式化暂存文件，作为最后的质量关卡。
    • 

  • 格式化器冲突通过 eslint-config-prettier 禁用冲突规则、串行执行链和统一配置源三种策略解决。
    • 

  • 编辑器配置按默认→用户→工作区→文件夹→语言特定的优先级级联，支持精细化的格式化控制。
    •
