格式化器架构

格式化器的核心抽象

代码格式化器的本质是一个转换函数：接收源代码文本，输出格式化后的文本。但不同格式化器的内部实现路径差异很大，从简单的正则替换到完整的 AST 重建，各有权衡。

interface Formatter {
  format(source: string, options: FormatOptions): string;
  formatRange(source: string, range: Range, options: FormatOptions): TextEdit[];
}

interface FormatOptions {
  tabSize: number;
  insertSpaces: boolean;
  trimTrailingWhitespace: boolean;
  insertFinalNewline: boolean;
  trimFinalNewlines: boolean;
  endOfLine: 'lf' | 'crlf' | 'auto';
}

interface TextEdit {
  range: Range;
  newText: string;
}

提示： Prettier 采用 "IR 重建" 策略——将 AST 转换为中间表示（Intermediate Representation），然后根据行宽约束重新排版。这解释了为什么 Prettier 的输出高度一致，但可能与程序员的手动格式化习惯不同。






CST 保留格式化
具体语法树（Concrete Syntax Tree, CST）保留了源代码中的所有信息，包括空白、注释和括号。CST 保留格式化只修改需要改变的部分，最大限度保留程序员的格式化意图。


interface CSTNode {
  type: string;
  value?: string;
  children: CSTNode[];
  leadingTrivia: Trivia[];
  trailingTrivia: Trivia[];
  range: Range;
}

interface Trivia {
  kind: 'whitespace' | 'newline' | 'comment' | 'blockComment';
  text: string;
  range: Range;
}

class CSTFormatter implements Formatter {
  format(source: string, options: FormatOptions): string {
    const cst = this.parser.parseCST(source);
    const edits = this.computeEdits(cst, options);
    return this.applyEdits(source, edits);
  }

  private computeEdits(node: CSTNode, options: FormatOptions): TextEdit[] {
    const edits: TextEdit[] = [];
    this.visitNode(node, 0, options, edits);
    return edits;
  }

  private visitNode(node: CSTNode, indent: number, options: FormatOptions, edits: TextEdit[]): void {
    for (const child of node.children) {
      const expectedIndent = this.computeIndent(child, indent, options);
      const actualIndent = this.getActualIndent(child);
      if (expectedIndent !== actualIndent) {
        edits.push({
          range: this.getIndentRange(child),
          newText: this.buildIndentString(expectedIndent, options),
        });
      }
      this.visitNode(child, indent + 1, options, edits);
    }
  }
}

范围格式化
范围格式化只对选定区域进行格式化，是编辑器中最常用的格式化方式之一。实现难点在于确定格式化边界——选区可能跨越不完整的语法结构。


class RangeFormatter {
  formatRange(source: string, selection: Range, options: FormatOptions): TextEdit[] {
    const expandedRange = this.expandToEnclosingStatement(source, selection);
    const regionText = this.extractRegion(source, expandedRange);
    const formatted = this.formatter.format(regionText, options);
    const edits = this.computeMinimalEdits(regionText, formatted);

    return edits.map((edit) => ({
      range: this.offsetRange(edit.range, expandedRange.start),
      newText: edit.newText,
    }));
  }

  private expandToEnclosingStatement(source: string, range: Range): Range {
    const tree = this.parser.parse(source);
    let node = tree.getNodeAtPosition(range.start);
    while (node && !this.isStatement(node)) {
      node = node.parent;
    }
    return node ? { start: node.range.start, end: node.range.end } : range;
  }

  private computeMinimalEdits(original: string, formatted: string): TextEdit[] {
    const diffs = myersDiff(original, formatted);
    return diffs.map((diff) => ({
      range: diff.range,
      newText: diff.newText,
    }));
  }
}

提示： VS Code 使用 Myers 差异算法计算最小编辑距离，只修改需要变更的部分。这避免了不必要的 git diff 噪音，也减少了撤销栈中的冗余条目。






格式化选项解析
格式化选项的来源是多层级的，编辑器需要按优先级合并来自不同配置源的选项。


interface ConfigSource {
  priority: number;
  resolve(uri: string): Promise<Partial<FormatOptions> | null>;
}

class EditorConfigSource implements ConfigSource {
  priority = 10;

  async resolve(uri: string): Promise<Partial<FormatOptions> | null> {
    const config = await parseEditorConfig(uri);
    if (!config) return null;
    return {
      tabSize: config.indent_size,
      insertSpaces: config.indent_style === 'space',
      trimTrailingWhitespace: config.trim_trailing_whitespace,
      insertFinalNewline: config.insert_final_newline,
      endOfLine: config.end_of_line as 'lf' | 'crlf',
    };
  }
}

class FormatOptionsResolver {
  private sources: ConfigSource[] = [];

  registerSource(source: ConfigSource): void {
    this.sources.push(source);
    this.sources.sort((a, b) => b.priority - a.priority);
  }

  async resolve(uri: string): Promise<FormatOptions> {
    const defaults: FormatOptions = {
      tabSize: 2,
      insertSpaces: true,
      trimTrailingWhitespace: true,
      insertFinalNewline: true,
      trimFinalNewlines: true,
      endOfLine: 'lf',
    };

    for (const source of this.sources) {
      const overrides = await source.resolve(uri);
      if (overrides) Object.assign(defaults, overrides);
    }
    return defaults;
  }
}

Prettier 的 IR 模型
Prettier 的核心创新是引入了中间表示层（IR），将格式化问题转化为行宽约束下的最优排版问题。


type Doc =
  | string
  | { type: 'concat'; parts: Doc[] }
  | { type: 'indent'; contents: Doc }
  | { type: 'group'; contents: Doc; break: boolean }
  | { type: 'line'; hard?: boolean; soft?: boolean }
  | { type: 'if-break'; breakContents: Doc; flatContents: Doc };

function printFunctionDeclaration(node: FunctionNode): Doc {
  return {
    type: 'group',
    contents: {
      type: 'concat',
      parts: [
        'function ',
        node.name,
        '(',
        { type: 'indent', contents: printParams(node.params) },
        ')',
        ' ',
        printBlock(node.body),
      ],
    },
    break: false,
  };
}

小结
    

  • 格式化器的核心策略分为 AST 重建、CST 保留、正则替换和 IR 中间表示四种。
    • 

  • CST 保留格式化通过保留 Trivia（空白和注释）实现最小修改，减少 git diff 噪音。
    • 

  • 范围格式化需要将选区扩展到完整语法结构，然后计算最小编辑差异。
    • 

  • 格式化选项按 .editorconfig > 工具配置 > 工作区设置 > 用户设置 > 内置默认的优先级合并。
    • 

  • Prettier 的 IR 模型将格式化问题转化为行宽约束下的排版优化，group/line/indent 是核心命令。
