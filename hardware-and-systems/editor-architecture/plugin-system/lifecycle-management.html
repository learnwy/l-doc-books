Part IV · 编辑器与编译器编辑器架构与实现 简介插件系统 简介生命周期管理

生命周期管理

核心概念

生命周期管理回答「扩展何时被加载、何时被卸载、出错怎么办」：

  • 激活与停用：扩展导出 activate / 可选 deactivate，宿主在合适时机调用；激活时注册的资源需可回收。
  • 依赖解析：扩展之间可声明依赖，宿主需按拓扑顺序激活并处理缺失依赖。
  • 懒加载策略：按激活事件推迟加载，把启动成本摊到真正需要时。
  • 崩溃恢复：扩展宿主崩溃后宿主需隔离故障、决定是否重启，避免牵连编辑器本体。
  • 优雅关闭：退出前让扩展有机会释放资源、落盘状态。

扩展激活与停用

扩展的生命周期由编辑器统一管理。每个扩展必须导出 activate 和可选的 deactivate 函数，编辑器在合适的时机调用它们。激活函数接收 ExtensionContext，用于注册订阅和访问存储。

interface ExtensionModule {
  activate(context: ExtensionContext): void | Thenable<void>;
  deactivate?(): void | Thenable<void>;
}

interface ExtensionContext {
  subscriptions: Disposable[];
  workspaceState: Memento;
  globalState: Memento;
  extensionUri: Uri;
  extensionPath: string;
  storageUri: Uri | undefined;
  extensionMode: ExtensionMode;
  secrets: SecretStorage;
}

enum ExtensionMode {
  Production = 1,
  Development = 2,
  Test = 3,
}

class ExtensionInstance {
  private module: ExtensionModule | null = null;
  private context: ExtensionContext;
  private status: ExtensionStatus = 'inactive';

  async activate(): Promise<void> {
    this.status = 'activating';
    try {
      this.module = await import(this.descriptor.main);
      await this.module.activate(this.context);
      this.status = 'active';
    } catch (error) {
      this.status = 'error';
      throw error;
    }
  }

  async deactivate(): Promise<void> {
    if (this.module?.deactivate) {
      await Promise.resolve(this.module.deactivate());
    }
    for (const sub of this.context.subscriptions) {
      sub.dispose();
    }
    this.status = 'inactive';
  }
}

    未激活 --> 激活中: 触发激活事件
    激活中 --> 已激活: activate() 成功
    激活中 --> 错误: activate() 异常

生命周期状态 说明 可用操作
未激活 已安装未加载 等待激活事件
激活中 正在执行 activate 等待完成
已激活 正常运行 接收事件，提供功能
停用中 正在执行 deactivate 清理资源
错误 activate 抛出异常 显示错误，自动禁用或重试
已禁用 用户或系统禁用 等待用户重新启用

提示： deactivate 函数的超时时间通常很短（VS Code 约 5 秒）。如果扩展需要执行耗时的清理操作（如保存缓存到磁盘），应在运行期间定期持久化，而不是依赖 deactivate。

依赖解析

扩展之间可以声明依赖关系，编辑器需要按拓扑顺序激活它们。循环依赖需要检测和处理。

interface DependencyGraph {
  nodes: Map<string, ExtensionDescriptor>;
  edges: Map<string, Set<string>>;
}

class DependencyResolver {
  resolve(extensions: ExtensionDescriptor[]): ExtensionDescriptor[] {
    const graph = this.buildGraph(extensions);
    return this.topologicalSort(graph);
  }

  private buildGraph(extensions: ExtensionDescriptor[]): DependencyGraph {
    const nodes = new Map<string, ExtensionDescriptor>();
    const edges = new Map<string, Set<string>>();

    for (const ext of extensions) {
      nodes.set(ext.id, ext);
      const deps = new Set(ext.extensionDependencies ?? []);
      edges.set(ext.id, deps);
    }
    return { nodes, edges };
  }

  private topologicalSort(graph: DependencyGraph): ExtensionDescriptor[] {
    const sorted: ExtensionDescriptor[] = [];
    const visited = new Set<string>();
    const visiting = new Set<string>();

    const visit = (id: string): void => {
      if (visited.has(id)) return;
      if (visiting.has(id)) throw new Error(`Circular dependency: ${id}`);
      visiting.add(id);
      for (const dep of graph.edges.get(id) ?? []) visit(dep);
      visiting.delete(id);
      visited.add(id);
      sorted.push(graph.nodes.get(id)!);
    };

    for (const id of graph.nodes.keys()) visit(id);
    return sorted;
  }
}

懒加载策略

懒加载是保证编辑器启动速度的核心策略。除了激活事件之外，扩展内部也应该采用懒加载。

class LazyExtensionLoader {
  private loadedModules = new Map<string, unknown>();

  async loadOnDemand<T>(moduleId: string, factory: () => Promise<T>): Promise<T> {
    if (!this.loadedModules.has(moduleId)) {
      this.loadedModules.set(moduleId, await factory());
    }
    return this.loadedModules.get(moduleId) as T;
  }
}

function activate(context: ExtensionContext): void {
  context.subscriptions.push(
    vscode.commands.registerCommand('myext.heavyFeature', async () => {
      const module = await import('./heavy-feature');
      module.execute();
    }),
  );

  context.subscriptions.push(
    vscode.languages.registerCompletionItemProvider(
      { language: 'typescript' },
      {
        async provideCompletionItems(document, position) {
          const engine = await import('./completion-engine');
          return engine.getCompletions(document, position);
        },
      },
    ),
  );
}

提示： VS Code 内置扩展（如 TypeScript 语言特性）也严格遵循懒加载策略。观察 "Developer: Show Running Extensions" 面板可以看到大多数扩展在启动后仍处于未激活状态。

崩溃恢复

扩展崩溃不应导致编辑器不可用。宿主进程监控机制需要检测崩溃并执行恢复策略。

interface CrashRecoveryPolicy {
  maxRestartsPerMinute: number;
  restartDelayMs: number;
  backoffMultiplier: number;
  maxBackoffMs: number;
  disableAfterMaxRestarts: boolean;
}

class ExtensionHostMonitor {
  private crashCount = 0;
  private lastCrashTime = 0;

  onHostCrash(hostId: string, exitCode: number): void {
    const now = Date.now();
    if (now - this.lastCrashTime < 60_000) {
      this.crashCount++;
    } else {
      this.crashCount = 1;
    }
    this.lastCrashTime = now;

    if (this.crashCount > this.policy.maxRestartsPerMinute) {
      this.disableProblematicExtensions(hostId);
      this.notifyUser(hostId);
      return;
    }

    const delay = Math.min(
      this.policy.restartDelayMs * Math.pow(this.policy.backoffMultiplier, this.crashCount - 1),
      this.policy.maxBackoffMs,
    );
    setTimeout(() => this.restartHost(hostId), delay);
  }

  private disableProblematicExtensions(hostId: string): void {
    const suspects = this.identifyCrashCauses(hostId);
    for (const ext of suspects) {
      this.extensionService.disable(ext.id);
    }
  }
}
恢复策略 触发条件 行为
立即重启 首次崩溃 延迟 1s 后重启宿主
指数退避 频繁崩溃 延迟翻倍（1s→2s→4s→8s）
禁用扩展 超过重启上限 禁用嫌疑扩展，通知用户
降级运行 宿主不可恢复 基本编辑功能仍可用

优雅关闭

编辑器关闭时需要给扩展足够的时间完成清理操作，同时设置超时防止无响应。

sequenceDiagram
    participant E as 编辑器
    participant H as 扩展宿主
    participant X as 扩展 A
    participant Y as 扩展 B

    E->>H: 请求关闭
    H->>X: deactivate()
    H->>Y: deactivate()
    X-->>H: 完成 (200ms)
    Y-->>H: 完成 (1s)
    H-->>E: 所有扩展已停用
    E->>H: 终止进程
    Note over E: 如果 5s 未完成,强制终止
class GracefulShutdown {
  async shutdownAll(extensions: ExtensionInstance[], timeoutMs: number): Promise<void> {
    const promises = extensions.map((ext) =>
      Promise.race([ext.deactivate(), new Promise<void>((resolve) => setTimeout(resolve, timeoutMs))]),
    );
    await Promise.allSettled(promises);
  }
}

  • 扩展生命周期包含未激活、激活中、已激活、停用中和错误五种状态，由编辑器统一管理。
  • 依赖解析通过拓扑排序确保扩展按正确顺序激活，循环依赖会被检测并报错。
  • 三级懒加载策略（扩展级、模块级、功能级）逐层减少不必要的资源消耗。
  • 崩溃恢复采用指数退避重启策略，超过重启上限后自动禁用问题扩展。
  • 优雅关闭并行调用所有扩展的 deactivate，设置超时防止无响应扩展阻塞退出。
