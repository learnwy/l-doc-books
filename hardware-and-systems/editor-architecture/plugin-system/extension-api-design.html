Part IV · 编辑器与编译器编辑器架构与实现 简介插件系统 简介扩展 API 设计

扩展 API 设计

扩展清单（Extension Manifest）

每个编辑器扩展都以 package.json 作为清单文件，声明扩展的元数据、入口点、激活条件和贡献点。VS Code 的扩展清单是目前最成熟的参考设计。

interface ExtensionManifest {
  name: string;
  displayName: string;
  version: string;
  publisher: string;
  engines: { vscode: string };
  categories: ExtensionCategory[];
  activationEvents: string[];
  main?: string;
  browser?: string;
  contributes?: ContributionPoints;
  extensionDependencies?: string[];
  extensionPack?: string[];
  extensionKind?: ('ui' | 'workspace')[];
}

type ExtensionCategory =
  | 'Programming Languages'
  | 'Snippets'
  | 'Linters'
  | 'Themes'
  | 'Debuggers'
  | 'Formatters'
  | 'Keymaps'
  | 'Other';
字段 作用 示例值
name 扩展唯一标识 "typescript-language-features"
main Node.js 入口 "./dist/extension.js"
browser Web 入口 "./dist/web/extension.js"
activationEvents 激活条件 ["onLanguage:typescript"]
contributes 贡献点声明 commands, menus, configuration
extensionKind 运行位置 ["workspace"] 在远程端运行
extensionDependencies 依赖的其他扩展 ["vscode.typescript-language-features"]

提示： main 和 browser 字段决定了扩展在不同环境中的入口。VS Code 的远程开发（Remote-SSH, Dev Containers）要求扩展声明 extensionKind 以确定在本地还是远程执行。

激活事件（Activation Events）

激活事件是扩展懒加载的核心机制。扩展不会在编辑器启动时全部加载，而是在满足特定条件时按需激活。

const activationEventTypes = [
  'onLanguage:${languageId}',
  'onCommand:${commandId}',
  'onDebug',
  'workspaceContains:${glob}',
  'onFileSystem:${scheme}',
  'onView:${viewId}',
  'onUri',
  'onWebviewPanel:${viewType}',
  'onCustomEditor:${viewType}',
  'onAuthenticationRequest:${providerId}',
  'onStartupFinished',
  '*',
] as const;

interface ActivationEventMatcher {
  match(event: string, context: ActivationContext): boolean;
}

class ExtensionActivationService {
  private pendingActivations = new Map<string, ExtensionDescriptor[]>();

  registerExtension(descriptor: ExtensionDescriptor): void {
    for (const event of descriptor.activationEvents) {
      const list = this.pendingActivations.get(event) ?? [];
      list.push(descriptor);
      this.pendingActivations.set(event, list);
    }
  }

  async fireActivationEvent(event: string): Promise<void> {
    const extensions = this.pendingActivations.get(event) ?? [];
    for (const ext of extensions) {
      await this.activateExtension(ext);
    }
    this.pendingActivations.delete(event);
  }
}

贡献点（Contribution Points）
贡献点是扩展向编辑器 UI 注入内容的声明式机制。扩展通过 contributes 字段声明命令、菜单、配置、语言、主题等。


interface ContributionPoints {
  commands?: CommandContribution[];
  menus?: Record<string, MenuContribution[]>;
  configuration?: ConfigurationContribution;
  languages?: LanguageContribution[];
  grammars?: GrammarContribution[];
  themes?: ThemeContribution[];
  iconThemes?: IconThemeContribution[];
  snippets?: SnippetContribution[];
  viewsContainers?: Record<string, ViewContainerContribution[]>;
  views?: Record<string, ViewContribution[]>;
  customEditors?: CustomEditorContribution[];
}

interface CommandContribution {
  command: string;
  title: string;
  category?: string;
  icon?: string | { light: string; dark: string };
  enablement?: string;
}

interface MenuContribution {
  command: string;
  when?: string;
  group?: string;
}

提示： 贡献点是纯声明式的，编辑器可以在不激活扩展的情况下读取和使用这些信息。这是实现快速启动的关键——命令面板可以显示所有扩展的命令，但只在用户执行时才激活对应扩展。






API 表面设计
扩展 API 定义了扩展可以访问的能力边界。VS Code 的 API 设计遵循几个核心原则：最小权限、事件驱动、Disposable 模式。


interface ExtensionContext {
  subscriptions: Disposable[];
  workspaceState: Memento;
  globalState: Memento & { setKeysForSync(keys: string[]): void };
  extensionUri: Uri;
  extensionPath: string;
  storageUri: Uri | undefined;
  globalStorageUri: Uri;
  logUri: Uri;
  extensionMode: ExtensionMode;
}

interface Disposable {
  dispose(): void;
}

function activate(context: ExtensionContext): void {
  const disposable = vscode.commands.registerCommand('extension.helloWorld', () =>
    vscode.window.showInformationMessage('Hello World!'),
  );
  context.subscriptions.push(disposable);

  const provider = vscode.languages.registerCompletionItemProvider(
    { scheme: 'file', language: 'typescript' },
    new MyCompletionProvider(),
    '.',
  );
  context.subscriptions.push(provider);
}

function deactivate(): void {}

版本与稳定性契约
扩展 API 的版本管理直接影响生态的健康程度。一个成熟的策略需要平衡创新速度和向后兼容。


interface ApiStabilityContract {
  stable: {
    breakingChanges: 'never within major version';
    deprecation: 'minimum 2 releases before removal';
    documentation: 'always public and versioned';
  };
  proposed: {
    availability: 'opt-in via enabledApiProposals';
    stability: 'may change or be removed without notice';
    publishing: 'cannot publish to marketplace';
  };
}

const engineConstraint = {
  engines: {
    vscode: '^1.80.0',
  },
};

小结
    

  • 扩展清单（package.json）声明了元数据、入口点、激活事件和贡献点，是扩展的身份证。
    • 

  • 激活事件实现按需加载，避免所有扩展在启动时同时激活拖慢编辑器。
    • 

  • 贡献点是声明式的 UI 注入机制，编辑器无需激活扩展即可读取其声明。
    • 

  • API 表面遵循最小权限、事件驱动和 Disposable 模式三大设计原则。
    • 

  • 版本契约将 API 分为 Proposed、Stable 和 Deprecated 三个阶段，平衡创新与稳定。
    •
