IPC 与沙箱

扩展宿主进程架构

现代编辑器将扩展运行在独立的宿主进程（Extension Host）中，与主进程（渲染进程）隔离。这种架构确保扩展代码的崩溃或卡顿不会影响编辑器的响应性。VS Code 采用多进程架构，每种宿主环境运行在独立进程中。

interface ExtensionHostDescriptor {
  kind: 'localProcess' | 'localWebWorker' | 'remoteProcess';
  entry: string;
  args: string[];
  env?: Record<string, string>;
}

interface ExtensionHostManager {
  start(descriptor: ExtensionHostDescriptor): Promise<ExtensionHostConnection>;
  terminate(hostId: string): Promise<void>;
  getRunningHosts(): ExtensionHostInfo[];
}

interface ExtensionHostConnection {
  hostId: string;
  protocol: MessageProtocol;
  onExit(handler: (code: number) => void): Disposable;
}

MessagePort/Worker 通信
主进程与扩展宿主之间的通信基于消息传递（Message Passing），具体实现因宿主类型而异。Node.js 宿主使用 IPC 管道，Web Worker 宿主使用 MessagePort。


interface MessageProtocol {
  send(message: ProtocolMessage): void;
  onMessage(handler: (message: ProtocolMessage) => void): Disposable;
  drain(): Promise<void>;
}

interface ProtocolMessage {
  type: MessageType;
  id?: number;
  data: VSBuffer;
}

enum MessageType {
  Request = 1,
  Reply = 2,
  ReplyError = 3,
  Cancel = 4,
}

class WebWorkerExtensionHost {
  private worker: Worker;
  private port: MessagePort;

  constructor(entry: string) {
    const channel = new MessageChannel();
    this.port = channel.port1;

    this.worker = new Worker(entry, { type: 'module' });
    this.worker.postMessage({ type: 'init', port: channel.port2 }, [channel.port2]);
  }

  createProtocol(): MessageProtocol {
    return {
      send: (msg) => this.port.postMessage(msg.data, [msg.data.buffer]),
      onMessage: (handler) => {
        const listener = (e: MessageEvent) => handler({ type: e.data.type, data: VSBuffer.wrap(e.data.buffer) });
        this.port.addEventListener('message', listener);
        this.port.start();
        return { dispose: () => this.port.removeEventListener('message', listener) };
      },
      drain: () => Promise.resolve(),
    };
  }
}

RPC 代理层
为了让扩展调用主进程的 API 像调用本地函数一样自然，编辑器在 IPC 之上构建了 RPC 代理层。每个 API 命名空间在宿主侧有一个代理（Proxy），在主进程侧有一个实现（Shape）。


interface IRPCProtocol {
  getProxy<T>(identifier: ProxyIdentifier<T>): T;
  set<T>(identifier: ProxyIdentifier<T>, instance: T): void;
}

class ProxyIdentifier<T> {
  constructor(
    public readonly isMain: boolean,
    public readonly sid: string,
  ) {}
}

const MainContext = {
  MainThreadCommands: new ProxyIdentifier<MainThreadCommandsShape>(true, 'MainThreadCommands'),
  MainThreadLanguages: new ProxyIdentifier<MainThreadLanguagesShape>(true, 'MainThreadLanguages'),
  MainThreadWindow: new ProxyIdentifier<MainThreadWindowShape>(true, 'MainThreadWindow'),
};

const ExtHostContext = {
  ExtHostCommands: new ProxyIdentifier<ExtHostCommandsShape>(false, 'ExtHostCommands'),
  ExtHostLanguages: new ProxyIdentifier<ExtHostLanguagesShape>(false, 'ExtHostLanguages'),
};

class RPCProtocolImpl implements IRPCProtocol {
  private proxies = new Map<string, unknown>();

  getProxy<T>(id: ProxyIdentifier<T>): T {
    if (!this.proxies.has(id.sid)) {
      this.proxies.set(id.sid, this.createProxy(id));
    }
    return this.proxies.get(id.sid) as T;
  }

  private createProxy<T>(id: ProxyIdentifier<T>): T {
    return new Proxy({} as T, {
      get: (_target, method: string) => {
        return (...args: unknown[]) => this.remoteCall(id.sid, method, args);
      },
    });
  }
}


提示： VS Code 的 RPC 层自动处理 Promise 序列化、Disposable 生命周期和事件订阅的跨进程传递。这意味着扩展调用 vscode.window.showQuickPick() 时，底层实际发生了跨进程 RPC 调用。






安全沙箱模型
扩展的安全隔离分为多个层次：进程隔离、API 权限控制和内容安全策略。


interface ExtensionPermissions {
  fileSystem: 'readOnly' | 'readWrite' | 'none';
  network: boolean;
  clipboard: boolean;
  shell: boolean;
  processExecution: boolean;
}

interface SandboxConfig {
  enableNodeIntegration: boolean;
  contextIsolation: boolean;
  sandbox: boolean;
  allowedModules: string[];
}

class ExtensionSandbox {
  private blockedAPIs = new Set<string>();

  validateAPIAccess(extensionId: string, apiName: string): boolean {
    if (this.blockedAPIs.has(apiName)) {
      throw new Error(`Extension ${extensionId} does not have permission to access ${apiName}`);
    }
    return true;
  }

  createRestrictedGlobals(): Record<string, unknown> {
    return {
      fetch: this.wrapFetchWithCORS(),
      setTimeout: globalThis.setTimeout.bind(globalThis),
      setInterval: globalThis.setInterval.bind(globalThis),
      console: this.createScopedConsole(),
    };
  }
}

小结
    

  • 扩展宿主进程与主进程隔离运行，支持 Local Process、Web Worker 和 Remote Process 三种模式。
    • 

  • 主进程与宿主之间通过 IPC 管道或 MessagePort 进行消息传递，Transferable 对象实现零拷贝传输。
    • 

  • RPC 代理层让扩展代码透明调用主进程 API，底层自动处理序列化和生命周期管理。
    • 

  • 安全沙箱通过进程隔离、API 权限控制、CSP 策略和资源限制四层防护确保系统安全。
    •
