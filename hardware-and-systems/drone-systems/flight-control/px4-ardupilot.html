PX4 与 ArduPilot

核心概念

PX4 和 ArduPilot 是全球最主流的两大开源无人机飞控软件栈，支持多旋翼、固定翼、垂直起降（VTOL）和无人车/船等多种平台。两者都提供了完整的飞行控制、导航、通信和任务管理功能，但在架构设计、开发理念和生态系统方面存在显著差异。

PX4 由苏黎世联邦理工学院（ETH Zürich）发起，采用模块化的 NuttX 实时操作系统架构，强调代码质量和工业级可靠性。ArduPilot 起源于 DIY 无人机社区，采用单线程协作调度架构，强调功能丰富度和社区驱动的开发。两者都通过 MAVLink 通信协议与地面站交互。

PX4 架构深入
PX4 的核心设计理念是"模块化和消息驱动"。每个功能模块（传感器驱动、估计器、控制器、通信）作为独立的 NuttX 任务运行，通过 uORB（微型对象请求代理）消息总线进行异步通信。


uORB 消息总线 是 PX4 架构的核心。每种消息类型定义为一个"主题"（Topic），模块通过发布（Publish）和订阅（Subscribe）主题进行解耦通信。典型的数据流：


    

  1. 传感器驱动发布 sensor_accel、sensor_gyro 主题
    2. 

  2. EKF2 估计器订阅传感器主题，发布 vehicle_attitude、vehicle_local_position 主题
    3. 

  3. 位置控制器订阅位置主题和任务命令，发布 vehicle_attitude_setpoint 主题
    4. 

  4. 姿态控制器订阅姿态设定点，发布 actuator_controls 主题
    5. 

  5. 混控器订阅执行器控制，发布 actuator_outputs（PWM 输出）
    6. 



EKF2 状态估计器 是 PX4 的导航核心，基于扩展卡尔曼滤波器融合 IMU、GPS、气压计、磁力计和可选的视觉/激光传感器数据。EKF2 的 24 状态向量包括：位置（3）、速度（3）、姿态四元数（4）、陀螺偏差（3）、加速度计偏差（3）、磁场（6）、风速（2）。


PX4 的参数系统允许在运行时调整 1000+ 个参数，涵盖控制器增益、传感器校准、安全限制和任务行为。参数通过 MAVLink 的 PARAM 协议远程读写，支持导出/导入方便批量配置。


ArduPilot 架构深入
ArduPilot 采用"车辆类型"分层架构：底层是通用的硬件抽象层（AP_HAL）和库函数集合，上层是针对不同车辆类型的应用（ArduCopter、ArduPlane、ArduSub、Rover）。


AP_HAL（硬件抽象层） 将硬件操作（GPIO、SPI、I2C、UART、定时器）抽象为统一接口，使 ArduPilot 可以在不同的硬件平台（Pixhawk、CubeOrange、Linux SBC）上运行相同的飞控代码。


调度系统：ArduPilot 使用协作式调度器（AP_Scheduler），主循环以固定频率（通常 400 Hz）运行，任务按照优先级和频率分组执行。与 PX4 的抢占式多任务不同，ArduPilot 的协作调度要求每个任务快速执行后让出 CPU，长时间任务需要分片处理。


飞行模式系统 是 ArduPilot 最灵活的特性之一。ArduCopter 提供了 20+ 种飞行模式，从基础的 Stabilize、AltHold 到高级的 Auto、Guided、Follow、ZigZag。每种模式定义了不同的控制权分配和自主水平。

地面站与 MAVLink 协议
MAVLink（Micro Air Vehicle Link）是无人机领域的标准通信协议，定义了飞控与地面站、伴飞电脑和云端之间的消息格式和传输规则。MAVLink v2 支持消息签名（安全认证）、消息扩展（向后兼容）和 256 种消息 ID（v1 为 256，v2 扩展到 16777215）。


MAVLink 消息分为三类：


心跳包（HEARTBEAT）：每秒发送一次，包含系统类型、自动驾驶类型和当前模式。用于连接检测和系统识别。


遥测数据：ATTITUDE（姿态欧拉角）、GLOBAL_POSITION_INT（GPS 位置）、SYS_STATUS（系统状态/电池）、VFR_HUD（飞行仪表显示数据）等。以 1-50 Hz 的频率流式发送。


命令/控制：SET_MODE（设置飞行模式）、COMMAND_LONG（执行特定命令）、MISSION_ITEM（航点定义）、SET_POSITION_TARGET_LOCAL_NED（位置控制目标）等。按需发送。


QGroundControl（QGC） 是 PX4 的默认地面站，也支持 ArduPilot。QGC 提供实时遥测显示、航点编辑、参数配置、固件更新和日志分析。基于 Qt/C++ 开发，支持 Windows、macOS、Linux、iOS 和 Android。


Mission Planner 是 ArduPilot 社区的主力地面站，Windows 平台开发（C#/.NET），功能极为丰富，包括高级校准工具、地形跟随配置、日志分析和 Python 脚本扩展。


二次开发与扩展
PX4 和 ArduPilot 都提供了丰富的二次开发接口，支持自定义任务逻辑、传感器集成和控制算法开发。


PX4 二次开发路径：


    

  • 外部模式（Offboard Mode）：通过 MAVSDK 或 MAVROS 从伴飞电脑发送位置/速度/姿态指令。适合需要 ROS 集成或视觉计算的场景
    • 

  • 自定义模块：在 PX4 源码中添加新的 uORB 模块，编译部署到飞控板。适合需要在飞控主频率运行的算法
    • 

  • 自定义混控器：修改电机分配和控制逻辑，支持非标准构型
    • 



ArduPilot 二次开发路径：


    

  • MAVProxy/DroneKit：Python 脚本通过 MAVLink 控制飞行器。DroneKit-Python 提供了高层 API
    • 

  • Companion Computer：伴飞电脑（Raspberry Pi/Jetson）通过串口/网络连接飞控，运行 ROS 节点或自定义程序
    • 

  • Lua 脚本：ArduPilot 内置 Lua 脚本引擎，可以在飞控板上运行自定义逻辑，无需重新编译固件
    •

小结
    

  • PX4 和 ArduPilot 是两大开源飞控平台，分别以模块化工业架构和功能丰富社区驱动为特色
    • 

  • PX4 通过 uORB 消息总线实现模块解耦，EKF2 融合多源传感器提供高精度状态估计
    • 

  • ArduPilot 提供 20+ 种飞行模式和广泛的硬件支持，AP_HAL 抽象层实现跨平台兼容
    • 

  • MAVLink 是无人机通信的标准协议，QGroundControl 和 Mission Planner 是两大地面站
    • 

  • 二次开发从脚本控制（DroneKit/MAVSDK）到 ROS 集成再到源码开发，满足不同深度的定制需求
    • 

  • 选择 PX4 还是 ArduPilot 取决于许可证需求（BSD vs GPL）、功能需求和团队技术栈
    •
