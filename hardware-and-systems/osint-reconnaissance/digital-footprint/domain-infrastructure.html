域名与基础设施侦察

概述

域名与基础设施侦察是 OSINT 中最基础也是最核心的技术方向。目标组织的互联网基础设施——域名、子域名、IP 地址、DNS 记录、SSL/TLS 证书、ASN、CDN 配置——构成了其在网络空间的「数字骨架」。通过系统化的基础设施侦察，安全团队能够绘制目标组织的完整网络拓扑，发现被遗忘的资产、影子 IT 和潜在的攻击入口。

在现代企业环境中，组织的基础设施版图往往远比管理层认为的更加庞大。子公司收购带来的遗留域名、开发测试环境的意外暴露、员工私自部署的云服务——这些「影子资产」是攻击者最喜欢的突破口，也是基础设施侦察需要发现的重点目标。

DNS 侦察

DNS 记录类型与情报价值

DNS 系统是互联网的「电话簿」，不同类型的 DNS 记录蕴含着丰富的情报价值：

记录类型 功能 情报价值
A/AAAA 域名到 IP 的映射 服务器位置、托管商识别
MX 邮件服务器 邮件基础设施、邮件安全配置
NS 权威名称服务器 DNS 托管商、域名管理结构
TXT 文本记录 SPF/DKIM/DMARC 配置、域名验证令牌
CNAME 别名记录 CDN 使用、子域名接管风险
SOA 起始授权记录 管理员邮箱、区域传输配置
SRV 服务记录 内部服务发现（如 SIP、XMPP）
PTR 反向解析 IP 到域名的关联
CAA 证书授权 允许的 CA 机构

DNS 枚举技术

被动 DNS 收集：

被动 DNS（Passive DNS, pDNS）是通过第三方数据源获取 DNS 历史解析记录的技术。其核心价值在于能够发现当前已不存在的 DNS 记录——已删除的子域名、曾经使用的 IP 地址、历史 CDN 配置等。

主要的被动 DNS 数据源：

数据源 特点 访问方式
SecurityTrails 最全面的 DNS 历史数据库 API（免费配额 + 商业）
PassiveTotal (RiskIQ) 微软旗下，与 Defender TI 集成 API
VirusTotal 域名解析历史、关联分析 API（免费配额）
DNSdumpster 免费的 DNS 侦察工具 Web 界面
Farsight DNSDB 全球最大的被动 DNS 数据库 商业 API
CirclPassiveDNS 安全社区共享 API

主动 DNS 枚举：

主动 DNS 枚举通过直接查询 DNS 服务器来发现子域名和记录。常用方法包括：

  1. 字典爆破：使用预定义的子域名字典（如 SecLists 的 DNS 子域名列表）逐一查询
  2. DNS 区域传输：尝试 AXFR 请求获取完整区域文件（大多数服务器已禁用）
  3. DNS 缓存探测：查询公共 DNS 递归服务器的缓存记录
  4. 证书透明度关联：从 CT 日志中提取域名后通过 DNS 验证
子域名发现实战
子域名发现是基础设施侦察中最关键的环节。一个综合的子域名发现流程通常组合多种技术：


使用 Subfinder 进行被动发现：


subfinder -d example.com -all -o subdomains.txt
Subfinder 集成了数十个被动数据源（SecurityTrails、Censys、Shodan、VirusTotal 等），通过并行查询快速聚合结果。


使用 Amass 进行深度枚举：


amass enum -d example.com -passive -o amass_passive.txt
amass enum -d example.com -active -brute -w /path/to/wordlist.txt -o amass_active.txt
OWASP Amass 是功能最全面的子域名枚举工具，支持被动收集、主动扫描、暴力枚举和排列组合生成四种模式。


使用 puredns 进行高效验证：


puredns resolve subdomains.txt -r resolvers.txt --write resolved.txt
在收集到大量候选子域名后，使用 puredns 通过可靠的 DNS 解析器列表进行批量验证，过滤失效的记录。


WHOIS 侦察
WHOIS 数据模型
WHOIS 是域名注册信息查询协议，提供域名的注册者、管理联系人、注册商、注册日期等信息。尽管 GDPR 的实施导致大量欧洲域名的 WHOIS 信息被隐私化（redacted），WHOIS 仍然是重要的情报来源。






WHOIS 字段
情报用途





Registrant Name/Org
识别域名所有者，关联同一实体的多个域名




Registrant Email
反向查找同一邮箱注册的所有域名




Name Servers
识别 DNS 基础设施提供商




Creation Date
判断域名年龄（新域名可能是钓鱼站）




Updated Date
跟踪域名配置变更




Registrar
注册商信息，辅助社工向量





WHOIS 历史数据
WHOIS 历史数据的价值在于记录了域名注册信息随时间的变化。即使当前 WHOIS 信息已被隐私保护服务遮蔽，历史记录中可能仍保留着原始注册人信息。

  • WhoisXMLAPI：提供 WHOIS 历史记录和反向查询 API
    • 

  • Whoxy：经济实惠的 WHOIS 历史数据 API

证书透明度侦察
CT 日志体系
证书透明度（Certificate Transparency, CT）是 Google 在 2013 年推出的公开审计框架。所有公开信任的 CA 机构在签发 SSL/TLS 证书时，必须将证书信息提交到公开的 CT 日志服务器。这意味着目标组织申请过的每一张证书（包括内部子域名的证书）都可以被检索到。


CT 日志对 OSINT 的核心价值：


    

  • 子域名发现：证书的 SAN（Subject Alternative Name）字段通常包含多个子域名
    • 

  • 历史证书追溯：即使证书已过期，CT 日志中仍保留记录
    • 

  • 组织关联：通过证书的 Organization 字段关联同一实体
    • 

  • 通配符证书识别：发现使用通配符证书的域名范围
    •

使用 crt.sh 进行证书搜索：


crt.sh 提供了 Web 界面和 JSON API 两种访问方式。通过搜索 %.example.com 可以获取包含该域名的所有证书记录，每条记录包含签发日期、有效期、签发 CA、SAN 列表等字段。

实践案例：完整基础设施侦察流程
以下是一个完整的基础设施侦察工作流示例：


阶段一：域名信息收集——WHOIS 查询 + 反向 WHOIS + CT 日志搜索，建立初始域名清单。


阶段二：子域名枚举——使用 Subfinder + Amass 被动收集，结合字典爆破进行主动枚举，puredns 验证存活。


阶段三：IP 基础设施映射——DNS 解析获取 IP，ASN 查询扩展 IP 范围，识别 CDN 和云服务。


阶段四：服务指纹识别——对发现的所有 IP 和域名进行服务识别和技术栈检测。


阶段五：报告输出——汇总所有发现，标注风险等级，输出结构化的基础设施侦察报告。


总结
域名与基础设施侦察是所有 OSINT 活动的起点和基础。通过综合运用 DNS 枚举、WHOIS 查询、CT 日志分析、ASN 映射等技术，安全团队能够构建目标组织的完整基础设施版图。在实际操作中，被动技术应优先于主动技术，多数据源交叉验证优于单一来源依赖，持续监控优于一次性扫描。随着组织的数字基础设施不断扩展，基础设施侦察已从一次性任务演变为持续的攻击面管理实践。
