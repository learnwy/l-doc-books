教程写作

核心概念

教程（tutorial）是技术写作中最有价值也最难写好的形式。教程的目标不是展示你知道什么，而是引导读者从零到一完成一个具体的任务。好的教程让读者在完成后获得 sense of accomplishment（成就感）和可复用的技能。

教程与其他技术内容形式的区别：

核心原则是 Test every step — 教程中的每一步都必须是你亲自验证过的。一个无法复现的教程比没有教程更糟糕。


教程的 SETUP-DO-VERIFY 结构
一个完整的教程遵循 SETUP → DO → VERIFY 循环，每个主要步骤都重复这个模式。


SETUP（准备）— 明确前置条件和环境要求：




Prerequisites
Before starting this tutorial, make sure you have:


    

  • Node.js 18+ installed (node --version)
    • 

  • Docker Desktop running (docker --version)
    • 

  • A GitHub account with SSH key configured
    • 

  • Basic familiarity with TypeScript (you don't need to be an expert)
    • 



Time estimate: 30-45 minutes


What you'll build: A real-time notification service using WebSocket and Redis Pub/Sub that can handle 10K concurrent connections.




前置条件必须具体到版本号，并提供验证命令。Time estimate 帮助读者决定是否现在开始。What you'll build 在开头就给出最终目标，让读者有全局画面。


DO（执行）— 每个步骤包含操作指令和预期结果：




Step 1: Initialize the Project
Create a new directory and initialize the project:


mkdir notification-service && cd notification-service
npm init -y
npm install ws redis typescript @types/ws
npx tsc --init
Your directory should now look like this:


notification-service/
├── node_modules/
├── package.json
├── package-lock.json
└── tsconfig.json


VERIFY（验证）— 每步之后告诉读者如何确认成功：




Run the following to verify your setup:


npx ts-node src/server.ts
You should see:


WebSocket server is running on ws://localhost:8080
Connected to Redis successfully
If you see a connection error, check that Docker is running and Redis is accessible on port 6379.




渐进式复杂度设计
教程的步骤应遵循 progressive complexity（渐进式复杂度）原则——每一步只在前一步的基础上添加一个新概念。


错误的做法是在第一步就展示最终的完整代码。正确的做法是：


Step 1 — 最简单的可工作版本：




Let's start with the simplest possible WebSocket server:


import { WebSocketServer } from 'ws';

const wss = new WebSocketServer({ port: 8080 });

wss.on('connection', (ws) => {
  ws.send('Welcome to the notification service!');
});
This is the "hello world" of WebSocket — it accepts connections and sends a greeting.

Troubleshooting 与常见问题
教程中最体现作者经验的部分是 Troubleshooting。预判读者可能遇到的问题并提前给出解决方案，能大幅提升教程的实用性。


在每个主要步骤后添加 troubleshooting 提示：




Troubleshooting:


If you see ECONNREFUSED 127.0.0.1:6379:


    

  • Make sure Redis is running: docker ps | grep redis
    • 

  • If not, start it: docker run -d -p 6379:6379 redis:7
    • 



If you see Cannot find module 'ws':


    

  • Make sure you ran npm install in the correct directory
    • 

  • Try deleting node_modules and running npm install again
    •

另一个最佳实践是提供一个 checkpoint 仓库——读者可以克隆某个 Git tag 来获得每一步完成后的代码状态：




Stuck? You can check out the completed code for this step:


git checkout step-3-redis-pubsub


教程的测试与维护
教程是有保质期的。依赖版本更新、API 变更、工具链演进都可能导致教程中的步骤无法复现。


教程测试的最佳实践：


    

  • 在发布前在一个全新的环境（clean machine / Docker container）中完整执行一遍
    • 

  • 让一个不了解该技术的同事跟着教程做，观察他们在哪里卡住
    • 

  • 建立 CI 自动化测试，定期验证教程中的代码仍然可以运行
    • 



教程维护的标准做法：


    

  • 在文章顶部标注 Last tested: March 2024 | Node.js 18.19 | Redis 7.2
    • 

  • 锁定依赖版本：npm install ws@8.16.0 redis@4.6.12 而非 npm install ws redis
    • 

  • 当主要依赖发生 breaking change 时，及时更新教程或添加版本兼容说明
    • 





⚠️ Version Note: This tutorial was written for Redis Client v4.x. If you're using v3.x, the connection syntax differs. See [migration guide] for details.
