清晰与简洁

核心概念

清晰与简洁是技术写作中最重要的两个品质。清晰意味着读者能够准确理解作者的意图，没有歧义；简洁意味着用最少的文字传达必要的信息，没有冗余。这两者相辅相成——简洁的文字通常更清晰，清晰的表达往往更简洁。

技术文档的读者通常在工作中阅读，时间有限、耐心有限。他们不是在欣赏文学作品，而是在寻找具体信息或跟随步骤完成任务。任何多余的文字都是障碍，任何模糊的表达都可能导致理解偏差甚至操作失误。

清晰与简洁的追求并不意味着内容要浅薄。深度和简洁并不矛盾——真正理解一个复杂概念的人，才能用简洁的语言解释它。正如 Einstein 所说："如果你不能简单地解释它，说明你还没有真正理解它。"

词汇精确与简化
技术写作中词汇选择的第一原则是：用最简单、最精确的词。不要用复杂的词来代替简单的词，也不要用模糊的词来代替精确的词。


简单词优于复杂词。技术文档不是展示词汇量的场所。当一个简单的词和一个复杂的词表达相同的意思时，始终选择简单的那个：

术语使用的一致性也是词汇选择的重要方面。在同一篇文档中，一个概念只能用一个术语。不要在一处说"服务器"，另一处说"主机"，还有一处说"节点"来指代同一个东西。第一次使用专业术语时，应该给出简明的定义或解释。


句式结构优化
句子是技术文档的基本单元。句式结构直接决定了信息传达的效率和准确性。技术写作中有几个核心的句式原则。


一句一义是最基本的句式原则。每个句子只传达一个信息点，避免在一个长句中堆砌多个概念：


不推荐：




系统在接收到请求后会先验证 Token 有效性，如果 Token 无效则返回 401 错误，同时记录日志并触发告警通知。




推荐：




系统接收到请求后，首先验证 Token 有效性。如果 Token 无效，系统返回 401 错误。同时，系统记录日志并触发告警通知。




拆分后的三个短句，每句传达一个独立的信息点，读者可以逐步理解整个流程。


主动语态优于被动语态。主动语态的句子结构是"主语 + 动词 + 宾语"，清楚地告诉读者"谁做了什么"。被动语态隐藏了动作执行者，在技术文档中容易导致歧义：






被动语态
主动语态
改进效果





配置文件被系统读取
系统读取配置文件
明确了动作执行者




错误信息会被写入日志
系统将错误信息写入日志
明确了谁在执行写入




请求被路由到后端服务
网关将请求路由到后端服务
明确了路由的执行者




数据被加密后发送
客户端加密数据后发送
明确了加密发生在哪一端





被动语态在少数场景下是合理的：当动作执行者不重要或不确定时（如"该协议于 2015 年发布"），以及在参考文档中保持客观语气时（如"该参数将被忽略"）。


正面表述优于否定表述。告诉读者"做什么"比告诉他们"不要做什么"更直接有效：


    

  • 不推荐："不要忘记在部署前运行测试" → 推荐："部署前请运行测试"
    • 

  • 不推荐："该参数不能为空" → 推荐："该参数必须有值"
    • 

  • 不推荐："不要使用 root 用户运行" → 推荐："使用非 root 用户运行"
    •

列表格式让读者可以快速扫描并逐项确认，远比在段落中搜索信息高效。


格式化提升可读性
格式化是清晰与简洁的视觉延伸。合理的格式化让文档在视觉上就传达出信息的层次和结构，降低读者的认知负担。


代码块必须始终标注语言标识。语言标识不仅启用语法高亮，还帮助读者在扫描页面时快速识别代码区域。内联代码使用反引号包裹（如 config.yaml），多行代码使用围栏代码块并标注语言。

段落长度控制直接影响文档的可读性。研究表明，超过 5 句话的段落会显著增加读者的跳读率。技术文档中的段落控制原则：


    

  • 每段聚焦一个主题，不超过 5 句话
    • 

  • 长流程使用编号步骤，而非段落叙述
    • 

  • 复杂概念配合图表说明，减少纯文字堆砌
    • 

  • 段落之间保持逻辑递进关系，避免跳跃
    • 

  • 在关键转折处使用过渡句，引导读者注意力
    • 



标题层级是文档结构的骨架。清晰的标题让读者在不阅读正文的情况下就能了解文档的内容范围和组织结构。标题应该具有描述性——"配置数据库连接"比"第三步"更有信息量。


小结
    

  • 清晰与简洁是技术写作最重要的两个品质，目标是让正确的信息以最低的认知成本到达读者
    • 

  • 词汇选择遵循"简单优于复杂、精确优于模糊"的原则，避免使用华丽但空洞的表达
    • 

  • 句式优化的三个核心原则：一句一义、主动语态优先、正面表述优先
    • 

  • 删减冗余包括消除冗余词、空洞描述，以及用列表替代并列信息的长段落
    • 

  • 格式化是可读性的视觉保障：代码块标注语言、告示框标记特殊信息、段落不超过 5 句
    • 

  • 简洁不等于简陋——目标是提升信息密度，而非降低内容深度
    •
