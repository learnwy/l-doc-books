贡献指南

为什么需要贡献指南

贡献指南（CONTRIBUTING.md）是开源项目不可或缺的文档，它明确告知潜在贡献者如何参与项目。一份清晰的贡献指南能降低参与门槛，提高协作效率，确保贡献质量。

贡献指南的核心目标

目标 说明
降低参与门槛 让新贡献者知道从何开始
统一流程 避免维护者反复解释相同流程
保证质量 确保提交的代码符合项目标准
营造氛围 传递开放友好的社区文化

行为准则 (Code of Conduct)

行为准则为社区互动设定基本规范，保护所有参与者。

常见行为准则模板

模板 适用场景 采用者
Contributor Covenant 大多数开源项目 Linux、Rails、Swift
Citizen Code of Conduct 社区驱动项目 强调公民责任意识
Mozilla 社区参与准则 大型开源组织 Mozilla 旗下项目

核心条款

  • 尊重不同背景和经验水平的参与者
  • 禁止骚扰、歧视和恶意攻击行为
  • 明确违规行为的处理流程和联系方式
  • 适用范围覆盖项目空间和公共场合的代表行为

开发环境搭建

清晰的环境搭建说明是吸引贡献者的关键。

标准模板

git clone https://github.com/your-org/your-project.git
cd your-project

nvm use

npm install

cp .env.example .env.local

npm run dev

npm test

环境要求说明

依赖 最低版本 说明
Node.js 18.0.0 推荐使用 nvm 管理版本
npm 9.0.0 随 Node.js 安装
Docker 24.0 用于本地数据库和中间件
Git 2.40 需支持 sparse-checkout

Pull Request 流程

标准 PR 流程

  1. Fork 项目仓库到个人账户
  2. 从 main 分支创建功能分支
  3. 在功能分支上进行开发和提交
  4. 确保所有测试通过且代码风格检查无误
  5. 提交 Pull Request 并填写 PR 模板
  6. 等待代码评审，根据反馈进行修改
  7. 维护者合并 PR

分支命名规范

前缀 用途 示例
feat/ 新功能开发 feat/dark-mode
fix/ Bug 修复 fix/login-timeout
docs/ 文档更新 docs/api-guide
refactor/ 代码重构 refactor/auth-module
chore/ 构建和工具 chore/upgrade-deps

PR 模板

## 变更说明

简要描述本次变更的内容和目的。

## 变更类型

- [ ] 新功能 (feat)
- [ ] Bug 修复 (fix)
- [ ] 文档更新 (docs)
- [ ] 代码重构 (refactor)
- [ ] 性能优化 (perf)

## 测试

- [ ] 已添加/更新相关测试
- [ ] 所有现有测试通过

## 关联 Issue

Closes #issue_number

工具 用途 配置文件

提交消息格式

遵循约定式提交（Conventional Commits）规范：

<type>(<scope>): <subject>

<body>

<footer>
类型 说明
feat 新功能
fix Bug 修复
docs 文档变更
style 代码格式调整（不影响逻辑）
refactor 重构（不是新功能也不是修复）
test 测试相关
chore 构建工具或辅助工具变更
