接口描述规范

HTTP 方法描述

每个接口描述应以 HTTP 方法 + 路径作为标题，紧跟一句话概要：

HTTP 方法 语义 描述模板 示例
GET 查询 获取 {资源} 的 {详情/列表} 获取用户详情
POST 创建 创建一个新的 {资源} 创建订单
PUT 全量更新 更新 {资源} 的全部字段 更新用户信息
PATCH 部分更新 更新 {资源} 的部分字段 修改订单状态
DELETE 删除 删除指定的 {资源} 删除收货地址

参数表规范

接口参数按位置分为四类，每类应使用独立的表格描述：

路径参数 (Path Parameters)

参数名 类型 必填 说明 示例
id string 是 用户唯一标识 usr_8a3b9c
orgId string 是 组织 ID org_12345

查询参数 (Query Parameters)

参数名 类型 必填 默认值 说明 示例
page integer 否 1 页码 3
pageSize integer 否 20 每页条数，最大 100 50
sort string 否 createdAt 排序字段 updatedAt
order string 否 desc 排序方向 asc

请求头参数 (Header Parameters)

参数名 类型 必填 说明
Authorization string 是 Bearer Token，格式：Bearer {token}
Content-Type string 是 请求体类型，固定为 application/json
X-Request-Id string 否 请求追踪 ID，用于日志关联

请求体参数 (Body Parameters)

参数名 类型 必填 说明 约束
name string 是 用户姓名 1-50 个字符
email string 是 邮箱地址 RFC 5322 格式
role string 否 角色 枚举：admin、member、viewer
tags string[] 否 标签列表 最多 10 个

请求与响应文档

请求体示例

{
  "name": "张三",
  "email": "zhangsan@example.com",
  "role": "member",
  "tags": ["开发", "后端"]
}

响应体结构

统一的响应格式有助于客户端解析：

{
  "code": 0,
  "message": "success",
  "data": {
    "id": "usr_8a3b9c",
    "name": "张三",
    "email": "zhangsan@example.com",
    "role": "member",
    "createdAt": "2025-03-15T10:30:00Z"
  }
}
字段 类型 说明
code integer 业务状态码，0 表示成功
message string 状态描述
data object 业务数据，失败时可为 null

接口调用示例

每个接口应提供至少两种语言的调用示例：

curl

curl -X POST https://api.example.com/v2/users \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "张三",
    "email": "zhangsan@example.com",
    "role": "member"
  }'

JavaScript (fetch)

const response = await fetch('https://api.example.com/v2/users', {
  method: 'POST',
  headers: {
    Authorization: 'Bearer eyJhbGciOiJIUzI1NiJ9...',
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    name: '张三',
    email: 'zhangsan@example.com',
    role: 'member',
  }),
});

const result = await response.json();
console.log(result.data.id);

分页文档

分页是列表类接口的核心要素，文档中必须详细说明分页机制。

偏移量分页 (Offset Pagination)

GET /v2/users?page=2&pageSize=20

响应中包含分页元数据：

{
  "code": 0,
  "data": {
    "items": [],
    "pagination": {
      "page": 2,
      "pageSize": 20,
      "total": 156,
      "totalPages": 8
    }
  }
}

游标分页 (Cursor Pagination)

GET /v2/events?cursor=evt_abc123&limit=50
{
  "code": 0,
  "data": {
    "items": [],
    "cursor": {
      "next": "evt_xyz789",
      "hasMore": true
    }
  }
}

分页方式对比

方式 优势 劣势 适用场景
偏移量分页 支持跳页，实现简单 深翻页性能差，数据偏移 后台管理列表
游标分页 性能稳定，无数据偏移 不支持跳页 动态数据流、时间线
Keyset 分页 高性能，适合大数据集 只能顺序翻页 日志查询、审计记录

最佳实践

  • 参数约束必须明确：类型、长度、枚举值、默认值缺一不可
  • 响应示例贴近真实：避免使用 string、xxx 等占位符
  • 标注幂等性：PUT 和 DELETE 通常是幂等的，POST 通常不是
  • 说明副作用：接口触发的异步操作（如发送邮件）应在文档中说明
  • 展示失败用例：除成功响应外，展示常见的失败响应样本
