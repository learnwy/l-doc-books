培训材料编写

培训材料类型

不同的培训场景需要不同类型的材料，合理搭配才能达到最佳学习效果。

材料类型 用途 特点
演示文稿 (Slides) 讲师主导的知识讲解 视觉化、信息密度低、引导节奏
学员手册 (Handouts) 培训后的参考资料 详细完整、可独立阅读
实操练习 (Labs) 动手实践巩固知识 任务驱动、有明确完成标准
速查卡片 (Cheat Sheet) 日常工作中快速查阅 单页、高密度、按场景组织
视频录屏 异步学习和回顾 可重复观看、覆盖操作细节

学习目标设计

使用 ABCD 模型定义学习目标

要素 说明 示例
A (Audience) 学习者是谁 初级后端开发工程师
B (Behavior) 学完后能做什么 独立完成 RESTful API 的设计与实现
C (Condition) 在什么条件下 使用 Express.js 框架
D (Degree) 达到什么程度 通过 API 设计评审并上线生产环境

学习目标层次（Bloom 分类法）

层次 动词 培训示例
记忆 列举、识别、定义 列举 HTTP 常用状态码及含义
理解 解释、区分、总结 解释 REST 与 RPC 的设计差异
应用 实现、使用、编写 使用 Express.js 编写 CRUD 接口
分析 对比、诊断、排查 分析 API 性能瓶颈并提出优化方案
评估 评审、选型、决策 评审同事的 API 设计并提出改进建议
创造 设计、架构、搭建 设计一套完整的微服务 API 体系

演示文稿编写

Slides 设计原则

原则 说明 反面示例
一页一主题 每页只传递一个核心信息 一页塞满 3 个概念
图多字少 关键词 + 图表，不是完整段落 把讲稿写在 Slide 上
渐进式展示 复杂内容分步呈现 一次性展示完整架构图
代码高亮 只展示关键代码片段 展示 200 行完整源码

Slide 结构模板

1. 封面（标题、讲师、日期）
2. 目录（本次培训覆盖内容）
3. 学习目标（学完后能做什么）
4. 核心概念讲解（每个概念 2-3 页）
5. 实操演示（Live Demo 步骤）
6. 练习环节（Lab 指引）
7. 总结与 Q&A
8. 参考资源

实操练习设计

Lab 练习模板

# Lab：实现用户认证模块

## 学习目标

完成本练习后，你将能够：

- 使用 JWT 实现 Token 签发和验证
- 编写登录和注册接口
- 实现中间件级别的权限校验

## 环境准备

- 已克隆练习仓库：`git clone <repo-url>`
- 已安装依赖：`npm install`
- 启动开发环境：`npm run dev`

## 任务说明

### 任务 1：实现 Token 签发（预计 15 分钟）

在 `src/auth/token.ts` 中实现 `generateToken` 函数。

**验收标准**：运行 `npm test -- --grep "token"` 全部通过。

### 任务 2：实现登录接口（预计 20 分钟）

在 `src/routes/auth.ts` 中实现 POST /login 接口。

**验收标准**：使用 curl 测试登录返回有效 Token。

练习难度分级

级别 说明 提示程度 适用场景
引导式 逐行指导，填空式练习 高 初学者入门培训
半开放式 给出框架和接口，自行实现 中 有基础的技能提升
开放式 只给需求描述，自行设计和实现 低 高级工程师实战演练

知识检验设计

检验形式对比

形式 适用场景 评估能力层次
选择题 概念理解、术语辨析 记忆、理解
代码填空 语法掌握、API 用法 记忆、应用
编程题 综合实现能力 应用、分析
设计题 架构思维、方案选型 分析、评估、创造
Code Review 代码质量意识 分析、评估

选择题示例

**Q1**：以下哪种 HTTP 方法是幂等的？

A. POST B. PATCH C. PUT ✅ D. CONNECT

**Q2**：JWT 的三部分用什么字符分隔？

A. 冒号 (:) B. 逗号 (,) C. 点号 (.) ✅ D. 斜杠 (/)

材料维护策略

版本与更新管理

策略 做法 频率
版本标注 每份材料标注适用版本和更新日期 每次修改
定期审查 检查技术内容是否过时 每季度
反馈收集 培训后收集学员反馈并改进 每次培训后
录屏更新 界面或流程变更后重新录制 按需
练习仓库 确保 Lab 依赖可安装、代码可运行 每月 CI 检查

层级 评估内容 方法

L3 行为 工作中的行为改变 3 个月后 Code Review 质量对比
