教程与操作指南

教程与操作指南的区别

技术文档中最常见的两种实践类型是教程 (Tutorial) 和操作指南 (How-to Guide)。两者目标不同，结构也有明显差异。

维度 教程 (Tutorial) 操作指南 (How-to)
目标 通过实践学习 完成特定任务
读者状态 初学者，不知道从哪开始 有基础，知道自己要做什么
结构 线性、从零到一 目标导向、可跳步
范围 覆盖完整流程 聚焦单个任务
解释量 较多，需要讲清"为什么" 较少，聚焦"怎么做"
示例 "从零搭建一个 React 项目" "如何在 React 中实现路由守卫"

前置条件写法

前置条件必须清晰具体，避免读者在半途卡住。

要素 好的写法 差的写法
工具版本 Node.js >= 18.0 安装 Node.js
知识储备 了解 HTTP 请求方法（GET/POST） 有后端经验
环境要求 macOS / Linux，4GB 以上内存 一台电脑
依赖服务 本地运行的 PostgreSQL 15 数据库

代码示例的写法

分步展示代码

每一步只展示新增或修改的代码，并用高亮标注变化部分：

// 第一步：定义接口
interface User {
  id: string;
  name: string;
  email: string;
}

// 第二步：创建服务
class UserService {
  private users: Map<string, User> = new Map();

  create(data: Omit<User, 'id'>): User {
    const id = crypto.randomUUID();
    const user = { id, ...data };
    this.users.set(id, user);
    return user;
  }
}

代码示例原则

原则 说明
可直接运行 复制粘贴即可执行，不缺依赖和上下文
渐进式复杂度 从最简版本开始，逐步添加功能
标注语言 代码块始终添加语言标签
完整导入 包含必要的 import 语句
预期输出 展示运行后的预期结果

验证步骤设计

每个关键步骤之后应设置验证点，让读者确认自己在正确的路径上。

# 验证步骤示例
$ npm run build
# 预期输出：
# ✓ Build completed successfully
# ✓ Output: dist/index.js (2.3 KB)

$ curl http://localhost:3000/health
# 预期输出：
# {"status":"ok","version":"1.0.0"}

验证检查点设计

阶段 验证方式 成功标志
环境准备 运行版本检查命令 版本号正确显示
安装依赖 运行构建命令 无报错退出
功能实现 运行测试用例 所有测试通过
最终集成 端到端操作 功能可正常使用

常见陷阱章节

在教程或指南末尾增加常见陷阱章节，帮助读者避免典型错误。

常见陷阱模板

## 常见陷阱

### ❌ 端口被占用

**现象**：启动服务时报错 `EADDRINUSE: address already in use :::3000`

**原因**：3000 端口已被其他进程占用。

**解决**：

​`bash lsof -i :3000 kill -9 <PID> ​`

### ❌ 依赖版本不兼容

**现象**：安装依赖后构建报类型错误。

**原因**：package.json 中未锁定主版本号。

**解决**：使用 `npm ci` 替代 `npm install`，确保使用 lock 文件。
