系统架构核心词汇

可扩展性与性能

系统架构讨论中，描述系统能力和性能特征的词汇是最基础的交流语言。这些术语在系统设计面试、架构评审和技术文档中无处不在。

核心性能指标术语

术语 发音 释义 例句
Latency /ˈleɪtənsi/ 单次请求从发出到收到响应的耗时 "The p99 latency for this endpoint is under 200ms."
Throughput /ˈθruːpʊt/ 系统单位时间内处理的请求量 "Our service handles 50,000 requests per second throughput."
Bandwidth /ˈbændwɪdθ/ 网络通道的最大数据传输速率 "The bandwidth between data centers is 10 Gbps."
Jitter /ˈdʒɪtər/ 延迟的波动幅度 "Network jitter causes inconsistent response times."
Saturation /ˌsætʃəˈreɪʃən/ 资源使用接近上限的程度 "CPU saturation is at 85% — we need to scale."

可扩展性术语

术语 释义 例句
Scalability 系统处理增长负载的能力 "The architecture was designed for horizontal scalability."
Horizontal Scaling (scale out) 增加更多机器来分担负载 "We scale horizontally by adding more pods to the cluster."
Vertical Scaling (scale up) 给单机增加更多资源 "Vertical scaling has limits — we can't add infinite RAM."
Elasticity 自动根据负载动态增减资源 "Cloud elasticity means we only pay for what we use."
Load Balancing 将请求分配到多个服务器 "The load balancer distributes traffic using round-robin."
Auto-scaling 根据指标自动调整实例数量 "Auto-scaling triggers when CPU exceeds 70%."
Sharding 将数据水平分割到多个数据库 "We shard the user table by geographic region."

易混辨析

Latency vs Response Time

  • Latency：纯网络传输延迟（数据在线路上花的时间）
  • Response Time：用户感知的总耗时（= 网络 latency + 服务器处理时间 + 排队时间）

Concurrency vs Parallelism

  • Concurrency（并发）：多个任务在重叠的时间段内推进，不一定同时执行
  • Parallelism（并行）：多个任务在同一时刻物理上同时执行

Throughput vs Bandwidth

  • Throughput：实际达到的数据传输速率
  • Bandwidth：理论上的最大传输能力

分布式系统理论

CAP 定理相关词汇

术语 释义 例句
Consistency 所有节点在同一时间看到相同的数据 "Strong consistency means reads always return the latest write."
Availability 系统对每个请求都能返回响应 "The system prioritizes availability over strict consistency."
Partition Tolerance 网络分区时系统仍能运行 "In a distributed system, partition tolerance is non-negotiable."
Eventual Consistency 数据最终会达成一致，但有延迟 "DynamoDB offers eventual consistency with lower latency."
Strong Consistency 每次读取都返回最新写入的值 "Banking transactions require strong consistency guarantees."
Linearizability 操作看起来像瞬间完成的全序 "Linearizability is the strongest form of consistency."

容错与可靠性

术语 释义 例句
Fault Tolerance 部分组件故障时系统仍能正常工作 "Our architecture is fault-tolerant with active-active replication."
Redundancy 通过冗余组件避免单点故障 "We maintain redundancy across three availability zones."
Failover 主系统故障时自动切换到备用系统 "Automatic failover happens within 30 seconds."
Circuit Breaker 检测到下游服务不健康时暂停调用 "The circuit breaker opens after 5 consecutive failures."
Graceful Degradation 系统在压力下优雅降级而非崩溃 "Under heavy load, we gracefully degrade to cached results."
Idempotency 多次执行同一操作结果相同 "All our API mutations are idempotent for safe retries."
Backpressure 下游慢时上游减速，防止过载 "We implement backpressure using a bounded queue."

架构风格与模式

核心架构术语

术语 释义 例句
Monolith 所有功能集中在一个可部署单元中 "We started as a monolith and later migrated to microservices."
Microservices 按业务能力拆分的独立服务集合 "Each microservice owns its database and can be deployed independently."
Service Mesh 处理服务间通信的基础设施层 "Istio provides our service mesh for traffic management."
API Gateway 统一的 API 入口，处理路由和认证 "The API gateway handles authentication before forwarding requests."
Event-Driven Architecture 通过事件异步通信的架构风格 "We use event-driven architecture with Kafka as the backbone."
CQRS 读写分离的架构模式 "CQRS lets us optimize read and write models independently."
Saga Pattern 跨服务事务的协调模式 "We use the saga pattern for distributed order processing."
Sidecar Pattern 辅助容器与主容器共同部署 "The logging sidecar collects metrics from all pods."

数据架构术语

术语 释义 例句
ACID 原子性、一致性、隔离性、持久性 "PostgreSQL provides full ACID compliance for transactions."
BASE 基本可用、软状态、最终一致 "NoSQL databases often trade ACID for BASE properties."
Write-Ahead Log (WAL) 先写日志再写数据的持久化策略 "The WAL ensures crash recovery without data loss."
Replication 将数据复制到多个节点 "We use leader-follower replication for read scaling."
Consensus 分布式节点就一个值达成一致 "Raft consensus ensures all nodes agree on the leader."
Tombstone 标记删除而非物理删除的记录 "Deleted records are marked with a tombstone for 7 days."

系统设计通用词汇

术语 释义 例句
SLA (Service Level Agreement) 服务水平协议 "Our SLA guarantees 99.9% uptime."
SLO (Service Level Objective) 内部服务水平目标 "The SLO for the search service is p99 < 100ms."
SLI (Service Level Indicator) 衡量 SLO 的具体指标 "Latency and error rate are our primary SLIs."
RPO (Recovery Point Objective) 可接受的数据丢失时间窗口 "RPO of 5 minutes means we can lose at most 5 minutes of data."
RTO (Recovery Time Objective) 系统恢复所需最大时间 "Our RTO is 15 minutes for critical services."
MTTR (Mean Time To Recovery) 平均恢复时间 "We've reduced MTTR from 2 hours to 20 minutes."
MTBF (Mean Time Between Failures) 平均故障间隔 "The MTBF for this component is approximately 6 months."

常用搭配与表达

描述系统能力

"The system is designed to handle..."
"This component is responsible for..."
"The architecture supports up to..."
"This layer abstracts away the complexity of..."
"The service guarantees at-least-once delivery."
"We achieve high availability through..."

讨论权衡取舍

"The trade-off here is between consistency and availability."
"We're optimizing for read performance at the cost of write latency."
"This introduces additional complexity but provides..."
"The overhead is acceptable given the reliability gains."
"We chose eventual consistency because our use case tolerates..."

这些架构词汇构成了系统设计讨论的基础语言。在架构评审、系统设计面试和技术文档中，精准使用这些术语不仅能展示专业深度，更能确保所有参与者对讨论内容有一致的理解。
