简历写作

核心概念

英文简历（resume）是程序员求职的第一张名片。招聘经理平均只花 6-7 秒扫描一份简历，因此每一行都必须传递高密度的价值信息。英文简历与中文简历在格式、内容和写作风格上有根本性差异——英文简历强调 impact over responsibilities（影响力大于职责描述）。

英文简历与中文简历的关键差异：

核心原则是 Show, don't tell — 用数据和成果证明你的能力，而不是空洞地自我标榜。


成就导向的 STAR-R 写法
简历中的工作经历部分是最重要的，应使用 STAR-R 框架：Situation（背景）、Task（任务）、Action（行动）、Result（结果）、Relevance（关联性）。


在简历中，STAR-R 被浓缩为一个 bullet point，格式为 Action verb + What you did + Quantified result：


坏的写法（职责描述）：




    

  • Responsible for maintaining the backend services
    • 

  • Worked on database optimization
    • 

  • Helped with code reviews
    • 





好的写法（成就导向）：




    

  • Redesigned the caching layer for user authentication, reducing API response time by 40% (from 500ms to 300ms) and saving $15K/month in infrastructure costs
    • 

  • Led the migration from monolith to microservices architecture, enabling the team to deploy independently and reducing release cycle from 2 weeks to 2 days
    • 

  • Established code review standards and mentored 3 junior engineers, improving team code quality (defect rate decreased by 30%)
    • 





每个 bullet point 的黄金公式：




[Strong Action Verb] + [What you did specifically] + [Quantified impact]




常用的强动词（按类别）：






类别
动词





领导
Led, Spearheaded, Directed, Orchestrated




构建
Built, Architected, Designed, Implemented




改进
Optimized, Streamlined, Reduced, Improved




影响
Increased, Drove, Delivered, Achieved




创新
Pioneered, Introduced, Launched, Initiated





避免使用弱动词如 Helped、Assisted、Participated in、Was responsible for。


Summary 与技能区的写法
简历顶部的 Summary 或 Professional Summary 是可选的，但对有 5+ 年经验的候选人推荐使用。好的 Summary 在 2-3 句话内传达你的核心价值主张。


坏的 Summary：




Experienced software engineer with strong skills in various technologies. Team player who is passionate about coding and solving problems.




好的 Summary：




Senior Software Engineer with 7 years of experience building high-traffic distributed systems. Led a team of 5 engineers at TechCorp to redesign the payment processing platform, handling 10M+ transactions daily with 99.99% uptime. Specialized in Go, Kubernetes, and event-driven architectures.




Summary 的公式：[Title] with [X years] experience in [domain]. [Top achievement with numbers]. Specialized in [key technologies/skills].


技能区（Skills section）的写法：




Languages: TypeScript, Go, Python, SQL Frameworks: React, Node.js, Express, gRPC Infrastructure: AWS (EC2, Lambda, DynamoDB), Kubernetes, Docker, Terraform Tools: Git, GitHub Actions, Datadog, PagerDuty




技能区的注意事项：


    

  • 按 JD 要求的优先级排序
    • 

  • 只列举真正熟练的技能，不要为了充数列举只用过一次的技术
    • 

  • 使用行业标准名称：TypeScript 而非 TS，Kubernetes 而非 K8s（除非 JD 中使用缩写）
    • 

  • 不要列 Git、VS Code 等基础工具——这是默认技能
    • 



ATS 友好与格式规范
现代招聘流程中，简历首先被 ATS（Applicant Tracking System）机器解析，然后才到达人类招聘经理。ATS 不友好的简历会直接被过滤。


ATS 友好的格式要求：


    

  • 使用标准字体（Arial、Calibri、Times New Roman）
    • 

  • 不使用表格、多列布局、文本框
    • 

  • 标题使用标准命名：Experience、Education、Skills
    • 

  • 文件格式：PDF（除非 JD 特别要求 .docx）
    • 

  • 不使用 header/footer 放置关键信息（ATS 可能忽略）
    •

关键词优化策略：仔细阅读 JD，将其中的关键技术词和短语自然地融入你的简历。如果 JD 写 React ecosystem，你的简历也应该使用这个短语而非只写 React。


简历的版面标准：


    

  • 边距：0.5-1 英寸
    • 

  • 字号：正文 10-12pt，标题 14-16pt
    • 

  • 行距：1.0-1.15
    • 

  • 一页纸（除非 10+ 年经验）
    •

教育与其他板块的写法
教育板块（Education）对不同阶段的候选人重要性不同。对于有 5+ 年工作经验的人，教育背景放在最底部即可，只需一行：




M.S. Computer Science — University of California, Berkeley, 2018




对于应届生或经验较少的候选人，可以加入相关课程和 GPA（如果优秀）：




B.S. Computer Science — Tsinghua University, 2020 (GPA: 3.8/4.0) Relevant Coursework: Distributed Systems, Database Design, Machine Learning




Open Source / Side Projects 板块对初中级工程师特别有价值：




FastCache — Open-source in-memory cache for Node.js (GitHub: 500+ ⭐) Built with zero dependencies. Features: TTL support, LRU eviction, cluster mode. Adopted by 3 production applications including a Y Combinator startup.




Certifications 板块在特定领域有加分效果：




    

  • AWS Solutions Architect Professional (2024)
    • 

  • Certified Kubernetes Administrator (CKA, 2023)
    •

小结
    

  • 简历使用 Action Verb + What + Quantified Result 公式描述成就
    • 

  • 避免弱动词（Helped、Responsible for），使用强动词（Led、Architected、Optimized）
    • 

  • Summary 用 2-3 句话传达 Title + Experience + Top Achievement + Specialization
    • 

  • 技能区按 JD 优先级排序，只列真正熟练的技能
    • 

  • 简历格式需 ATS 友好：标准字体、标准标题、PDF 格式
    • 

  • 关键词策略：将 JD 中的技术词和短语自然融入简历
    • 

  • 一页纸原则，除非 10+ 年经验
    • 

  • 不同阶段侧重不同：初级重项目，中级重成就，高级重领导力
    •
