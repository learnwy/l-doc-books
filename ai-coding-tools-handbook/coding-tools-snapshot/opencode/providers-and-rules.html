Providers 与 Rules：75+ 家 + 四层加载 + URL 远程注入

核心概念

OpenCode 把"用哪家 LLM"和"agent 默认带什么背景上下文"切成两条正交的配置面：providers（model 注册 + endpoint + 鉴权）落在 opencode.json 的 providers 字段；rules / instructions（agent 提示工程）走四层加载——全局 ~/.config/opencode/AGENTS.md → CLAUDE.md fallback → 项目 AGENTS.md → opencode.json instructions 字段。后者支持 paths / globs / URLs 三种来源，URL 远程注入是 OpenCode 在 2026 年同类工具里的独家能力。

本文只展开这两块。MCP / Skills / 自定义 slash 在 2_mcp-and-skills.md 单写。

providers：把 75+ 家接进同一份 opencode.json
OpenCode 通过 Models.dev 接入主流 provider，opencode.json 的 providers 字段允许混合声明云端 API、自家 OpenCode Zen gateway 与本地 Ollama / LM Studio。下面是覆盖三类来源的最小示例。


{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "name": "Anthropic",
      "models": ["claude-opus-4-7", "claude-sonnet-4-6", "claude-haiku-4-5"],
    },
    "zen": {
      "name": "OpenCode Zen",
      "apiBase": "https://gateway.opencode.ai/v1",
      "models": ["zen-default", "zen-fast"],
    },
    "ollama-local": {
      "name": "Local Ollama",
      "apiBase": "http://localhost:11434/v1",
      "auth": "none",
      "models": ["qwen3-coder:30b", "deepseek-coder-v3:33b"],
    },
  },
  "defaultModel": "anthropic/claude-sonnet-4-6",
}

Rules / Instructions：四层加载 + URL 是杀手锏
OpenCode 的"提示工程"分两条独立通道：声明式的 AGENTS.md / CLAUDE.md 文件，以及 opencode.json 的 instructions 字段。前者是同类工具的标准做法，后者是 OpenCode 在 2026 年同类中独家支持 URL 远程加载的差异化能力。


加载顺序（按"加载先 → 优先级低"，后加载覆盖前面）：


    

  1. ~/.config/opencode/AGENTS.md（全局）
    2. 

  2. ~/.claude/CLAUDE.md（fallback，兼容 Claude Code 用户的全局规则）
    3. 

  3. 项目根 AGENTS.md
    4. 

  4. 项目根 CLAUDE.md（仅当 AGENTS.md 不存在时 fallback）
    5. 

  5. 嵌套目录的 AGENTS.md（按 cwd 向下走，最近的优先）
    6. 

  6. opencode.json 的 instructions（最后注入，可覆盖一切）
    7. 



instructions 字段：path / glob / URL 三种来源
{
  "instructions": [
    "./docs/api-guidelines.md", // path
    "./packages/*/AGENTS.md", // glob
    "https://team.example.com/style", // URL（5 秒超时，失败降级跳过）
  ],
}
URL 来源的设计意图是让团队规范跟随 wiki / 知识库实时演进，不必每次更新都 PR 一次 AGENTS.md。但要注意三条约束：


    

  • 5 秒超时静默跳过：URL 不可达时 agent 不报错、不停下、不重试，下游可能误以为规范被加载。
    • 

  • 不 cache：每次 session 重新拉，wiki 后端建议加 ETag / Last-Modified 加速。
    • 

  • 生产环境建议 HTTPS + 内网鉴权：URL 暴露在 opencode.json 里，会随 commit 进 git。
    •

这是 OpenCode 在提示工程层独家、且在企业内"动态规范分发"场景下最有用的一个差异化点。


一份能直接用的最小可工作配置
下面这份 opencode.json 把 provider + rules 两条配置面合在一起，可作为新项目的起点。


{
  "$schema": "https://opencode.ai/config.json",

  // —— provider 与 model
  "providers": {
    "anthropic": {
      "name": "Anthropic",
      "models": ["claude-opus-4-7", "claude-sonnet-4-6"],
    },
    "ollama": {
      "name": "Local Ollama",
      "apiBase": "http://localhost:11434/v1",
      "auth": "none",
      "models": ["qwen3-coder:30b"],
    },
  },
  "defaultModel": "anthropic/claude-sonnet-4-6",

  // —— Rules 远程注入（动态团队规范）
  "instructions": ["./docs/coding-style.md", "./packages/*/AGENTS.md", "https://team.example.com/ai-guidelines"],
}
配合项目根的 AGENTS.md 写"业务目标 / 团队约定 / 禁区目录"三段，agent 就有了稳定且可演进的项目背景。

小结
    

  • providers 字段一份 opencode.json 同时管 75+ 公有云 + Zen + 本地 Ollama / LM Studio / vLLM，混合声明无冲突。
    • 

  • model 切换优先级 CLI flag > 当前 session /model > 项目 defaultModel > 全局 defaultModel > 工具内置 fallback。
    • 

  • Rules 四层加载：全局 → CLAUDE fallback → 项目 → 嵌套 → instructions，后者最晚注入、可覆盖一切。
    • 

  • instructions 支持 paths / globs / URLs，URL 远程注入是同类独家（5 秒超时静默跳过、不 cache）。
    • 

  • 想把团队规范"动态化"、不强制每次改提示都 PR AGENTS.md，URL 注入是 OpenCode 的关键卖点；MCP / Skills 的配置在下一篇 2_mcp-and-skills.md 展开。
    •
