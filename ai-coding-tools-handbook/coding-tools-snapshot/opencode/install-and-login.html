安装方式与 provider 登录

核心概念

OpenCode 提供五条平行的安装路径与两套登录机制。读者拿到一台干净的 Mac / Linux 终端、希望"从 0 到 opencode --version 输出版本号"，只需要做两个决定：装在哪里（个人开发机 / 远端 VPS / CI / 离线机器）与 凭据怎么拿（OAuth 浏览器跳转 / 直接贴 API key）。本文只覆盖到"凭据就绪、TUI 第一次能打开"这一步；进入 TUI 之后的导航、/init、/share 留给 2_first-session-and-share.md。

挑选时按"装哪台机 × 是否需要可复现部署"两个维度即可。


    

  • 个人开发机日常用：一键脚本最快，5 秒拿到二进制；担心 PATH 干净的话改 npm 全局。
    • 

  • 远端 server（OpenCode client/server 架构的典型部署）：Docker 镜像最干净，可与 docker compose / systemd 自然集成。
    • 

  • CI 跑批：npm 全局或 Docker，cache 友好。
    • 

  • 离线 / 内网：Release 二进制；下载后校验 SHA256 再 tar xf 到 PATH 目录。
    • 

  • 混合管理：Homebrew tap 在 macOS 上能跟 brew bundle 协作，团队成员 Brewfile 一致。
    • 



# 一键脚本路径示例 + 添加 PATH
curl -fsSL https://opencode.ai/install | bash
echo 'export PATH="$HOME/.opencode/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
opencode --version
Bun 依赖：OpenCode 截至 2026-05 需要 Bun 1.x；npm 全局路径下 Node 是入口 shim，runtime 仍切到 Bun。若 bun --version 失败，安装 Bun：curl -fsSL https://bun.sh/install | bash。


OAuth vs API key 两套登录机制
OpenCode 必须有一个能用的 LLM provider 凭据，否则 TUI 第一次启动会强制弹 DialogProvider 引导，不完成走不到主界面。两套登录机制各有适用：






维度
OAuth（推荐）
API key





触发命令
opencode auth login [provider]
同左，子选项里选 "API key"




凭据来源
浏览器跳转 provider 控制台授权
用户从 provider 控制台复制




适用
公网可达、个人开发
内网 / 受限网络 / CI




安全
scope 可精确控制，过期可吊销
全权 key，泄露代价高




失败常见原因
localhost 回调端口被防火墙拦
复制时漏掉前缀 / 末尾换行





# 交互式选 provider，按提示走 OAuth 浏览器跳转
opencode auth login

# 已知要登哪一家时可以指定
opencode auth login anthropic
opencode auth login openai
opencode auth login zen          # OpenCode 自家 gateway

# bypass 交互：把 API key 写进环境变量
export ANTHROPIC_API_KEY=sk-ant-xxxxxxxx
export OPENAI_API_KEY=sk-xxxxxxxx
opencode                          # 启动时会自动检测
首次运行 DialogProvider 引导
第一次运行 opencode（无任何凭据），TUI 会先弹 DialogProvider，逐步问：


    

  1. 选 provider：从列表里选一家或多家（可同时配 Anthropic 与本地 Ollama）。
    2. 

  2. 选登录方式：每家 provider 都给两个选项—— OAuth 或粘 API key。
    3. 

  3. 选 default model：例如 anthropic/claude-sonnet-4-6 / openai/gpt-5.5。
    4. 

  4. 确认 opencode.json 写入位置：项目根（commit 给团队）或 ~/.config/opencode/opencode.json（个人私有）。
    5. 



完成后所有凭据加密落地到 ~/.local/share/opencode/auth.json（macOS 是 ~/Library/Application Support/opencode/auth.json），后续 MCP OAuth token 落 mcp-auth.json。


~/.local/share/opencode/           # Linux / WSL
├── auth.json                       # 加密 provider 凭据
├── mcp-auth.json                   # MCP server token
└── sessions/                       # 会话历史

~/Library/Application Support/opencode/    # macOS 同上

陷阱与常见故障




现象
可能原因
处理





opencode: command not found
PATH 没包含 ~/.opencode/bin/ 或全局 npm 路径
echo $PATH 验证；把 bin 路径加进 shell rc




bun: not found 报错
npm 全局安装但未装 Bun runtime
curl -fsSL https://bun.sh/install | bash




OAuth 浏览器回调超时
公司网络拦截 localhost 回调端口
用 opencode auth login <provider> 切到 API key 模式




opencode --version 在 Docker 内为空
镜像未挂卷或 entrypoint 被覆盖
用 docker run -it --entrypoint opencode anomalyco/opencode --version 验证




OAuth 完成但仍报 "no provider"
auth.json 路径权限不可写
ls -la ~/.local/share/opencode/ 确认目录可写




API key 粘贴后第一次调用 401
复制时漏掉前缀 sk-ant- 或粘到换行
cat ~/.local/share/opencode/auth.json 检查首尾





小结
    

  • 五种安装路径按"装哪台机 × 是否需可复现"挑：curl 最快、npm 友好、brew 团队可锁、Docker 适合远端、Release 留给 air-gap。
    • 

  • Bun 1.x 是 runtime 硬依赖；npm 全局路径下 Node 只是入口 shim。
    • 

  • 登录优先 OAuth（opencode auth login），端口受限时 fallback API key 或环境变量。
    • 

  • 首次启动 TUI 会强制走 DialogProvider 引导，完成后凭据落 auth.json。
    • 

  • 跑通 opencode --version 输出版本号即可进入下一篇 2_first-session-and-share.md，开始第一次会话。
    •
