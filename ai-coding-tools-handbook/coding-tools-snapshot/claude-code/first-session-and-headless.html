Tier 1 · Coding Tools 工具栈三款 Coding Tools 速览 简介Claude Code 速览 简介首次会话 · TUI 巡视 · `/memory` · headless 接 CI

首次会话 · TUI 巡视 · /memory · headless 接 CI

核心概念

装登录完成后的下一步是"首次会话 + headless 接 CI"。TUI 进去后先做四件事：核对 /model 与 /permissions、用 /agents /skills 看可用资产、用 /plan 演练大改、用 /memory 让 Claude 自己生成首份 CLAUDE.md。沉淀完资产再切到 claude -p headless 形态接 CI——--continue 与 --resume 让 session 可序列化、跨会话续接。

这一节聚焦"会话内体验 + 自动化接入"，安装与登录已在上一节解决。整个 TUI 巡视用不到 5 分钟，但能把后续几十小时的会话效率定下来——尤其是 /permissions 默认值与 CLAUDE.md 是否生成两件事，几乎决定了上手体验。

TUI 巡视：四件套先看完
不带参数运行 claude 即进入 TUI，落在默认 build agent。进去后立刻核对四件套：模型、权限、Skills、Subagents——先把 baseline 看清，后面排错会快很多。


┌─ Claude Code · build agent ───────────────────────────┐
│ > 你想做什么?                       [/help 看全部命令] │
├───────────────────────────────────────────────────────┤
│ /model        当前 Sonnet 4.6 (1M ctx) — 切到 opus     │
│ /permissions  当前 default — 改 acceptEdits / plan     │
│ /agents       看可用 sub-agent（Explore/Plan 等）     │
│ /skills       看已加载 Skills（含 bundled + user）    │
│ /plan         进入 plan mode（只读分析，不改文件）    │
│ /memory       触发自动生成 CLAUDE.md + MEMORY.md       │
│ /context      看当前会话 token 占用                   │
└───────────────────────────────────────────────────────┘

/permissions default 是新手第一坑：每次 edit 都会问"yes/no"，跑十几个文件的 refactor 会被打断到怀疑人生。Pro 个人开发推荐 acceptEdits（编辑无需确认、shell 命令仍问）；Team / Enterprise 可在 .claude/settings.json 走 managed settings 把策略固化。


/plan 模式：大改前先演练
任何一次"跨多文件 / 改公共契约 / 影响 CI" 的改动，建议先在 plan mode 演练一遍。plan mode 让 Claude 只读分析、不动文件——产出方案、列风险点、给出步骤拆解——确认后再切回 build agent 执行。


> /plan
进入 plan mode（只读，不会编辑文件）

> 把所有 callback-based 的 fs 调用改为 async/await，影响范围？
[Plan Agent · Haiku 4.5 · read-only]
  扫描 src/**/*.ts ...
  发现 23 处 fs.readFile callback 调用，14 个文件
  建议步骤：
    1. 引入 fs/promises ...
    2. 逐文件改写，从 utils/ 开始 ...
    3. 跑 npm test 验证 ...
  风险：3 处 callback 内部用到 this 绑定，需要保留 ...
plan agent 默认走 Haiku 4.5 只读，省 token 又快；满意后回 build agent 真改。Plan agent 不能再 spawn subagent，是 Claude Code 防嵌套保护的体现。


/memory 生成 CLAUDE.md 与 auto-memory
首次进入一个仓库时，让 Claude 自己读项目结构、构建系统、README 生成首份 CLAUDE.md，比手写更省力且更准。


> /memory
扫描 README、package.json、Cargo.toml、pyproject.toml、CI 配置、docs/...

生成建议：
  ./CLAUDE.md  (项目协议，commit 进仓库)
  ~/.claude/memory/<project>/MEMORY.md  (auto-memory，用户级)

接受? [y/N/edit]
/memory 同时维护两份资产：


    

  • CLAUDE.md：项目协议（业务目标、不要碰的目录、约定）；落项目根并 commit，团队共享。
    • 

  • MEMORY.md（auto-memory）：Claude 自己 curate 的"长期事实"笔记；落 ~/.claude/memory/<project>/，头 200 行 / 25KB 截断，超出部分 Claude 会主动压缩或丢弃旧条目。
    • 



建议第一次跑完不要直接 accept，先 review 把空话删掉，留下"业务目标 / 团队约定 / agent 不要碰的目录"三段就够。@path import 与多层加载顺序的细节在 ./5_claude-md-and-skills.md 展开。


Headless：claude -p 与 session 续接
跑完一次 TUI session 后，CI 接续才是 Claude Code 的另一半价值。claude -p 让你把 agent 当 shell 命令用，--continue 与 --resume 让会话状态可序列化。


# 单次 prompt，输出 JSON 给后续脚本 parse
claude -p "review the diff at HEAD~1..HEAD and list breaking changes" \
       --output-format json

# 继续上一次 TUI session（自动识别 cwd 最近的 session）
claude --continue

# 指定恢复某个 session id（在 ~/.claude/sessions/ 列出）
claude --resume <session-id>

# CI 场景：把仓库扫描 + 自动生成 PR comment 串到一条管道
claude -p "$(cat .github/prompts/pr-review.md)" \
       --output-format stream-json \
       | jq '.events[] | select(.type=="message")'




选项
作用
何时用





--output-format json
一锅 JSON 在结束时返回
后续脚本 parse 的"单步"场景




--output-format stream-json
事件流，每行一个 NDJSON 事件
CI 实时滚日志、长跑任务




--output-format text
默认人类可读
调试时手动看




--continue
续接 cwd 最近 session
本地工作切回上次状态




--resume <id>
恢复指定 session（~/.claude/sessions/）
跨机器 / 跨 cwd 续接





stream-json 让 long-running 任务的进度可以在 CI 日志里实时滚出来，比一锅 JSON 最后才返回更友好。Session 与 sub-agent 隔离的细节（isolation: worktree 等）见 module-deep agents hub。

现象

TUI 起来 prompt 偏题

plan mode 本就只读；满意后退出 plan mode 让 build agent 执行




/memory 生成的 CLAUDE.md 太长
Claude 把 README 全 paraphrase 进去了
review 时只留三段：业务目标 / 团队约定 / agent 不要碰的目录




stream-json 在 CI 里没有滚
输出被 buffer

/memory 不是"一次性"的，仓库结构有大变（迁移构建系统、新增子模块）后再跑一次会让 CLAUDE.md 重新对齐当前状态。


小结
    

  • TUI 巡视先看四件套：/model 切档、/permissions 改 acceptEdits、/agents /skills 列资产、/plan 演练大改。
    • 

  • /permissions default 是新手第一坑——每个 edit 都问 y/n；个人改 acceptEdits、团队走 managed settings。
    • 

  • /memory 生成两份资产：CLAUDE.md（commit、团队共享）+ MEMORY.md（auto-memory，头 200 行 / 25KB 截断）。
    • 

  • Headless 三件套：claude -p 单次、--continue 续 cwd 最近、--resume <id> 跨机器跨 cwd；输出格式 json / stream-json / text 按 CI 形态选。
    • 

  • 首次失败三大根因：plan-模型不匹配、/permissions default 太严、缺 CLAUDE.md——分别用 /model、/permissions、/memory 解决。
    •
