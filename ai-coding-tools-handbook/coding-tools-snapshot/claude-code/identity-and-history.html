Claude Code 身份 · 模型阵列 · 多 surface · 2026 时间线

核心概念

Claude Code 是 Anthropic 官方维护的终端原生 AI 编程代理，仓库 anthropics/claude-code 公开可读，但许可证走 Anthropic Commercial ToS 而非 OSI 开源协议——业内称作 source-available。这种身份决定了它与 OpenCode（MIT）/ Codex CLI（Apache-2.0）的根本差异：你可以读源码、提 Issue、给 PR，但不能 fork 自部署、也不能把它打包进商业衍生产品。模型侧也只接 Anthropic 一家，未付费订阅或未持有 API key 时整个客户端不会调起任何模型。

它在 5 款工具里最显著的产品形态差异是"多 surface 同引擎"——同一份 agent loop 同时跑在终端 CLI、VS Code 扩展、JetBrains 插件、桌面端（macOS/Win/Linux ARM64）、Web 端 claude.ai/code、iOS App 六处入口，所有 surface 共享同一份 CLAUDE.md / Skills / MCP / Hooks 配置。这种统一性是其它工具花很大精力都未必能复现的。

多 surface 与统一配置
六个入口共享 ~/.claude/ 这套用户全局配置，外加项目根的 ./CLAUDE.md / .mcp.json / .claude/settings.json。意味着——


    

  • 在一台机器上装 CLI + IDE 扩展，CLAUDE.md / Skills / MCP / Hooks 改一处即可生效，不必维护两份。
    • 

  • 同账号下的 Web claude.ai/code 与 iOS App 也读云端同步的用户级配置，远程协作时仓库 commit 进 .mcp.json 就能让团队 Web 端一致。
    • 

  • 桌面 Claude Desktop（claude.ai/download）与 Claude Code 是不同产品：前者是面向普通用户的 LLM 对话客户端，不内置 agentic coding，二者只共用 Claude 账号体系，不要混淆。

2026 时间线
2026 年 Claude Code 的关键节点排成一条线，方便对照"我手上版本"。


    

  • 2026-04-23 · Enterprise 与 Anthropic API 默认模型切到 Opus 4.7。Pro / Team Standard 仍 Sonnet 4.6；Bedrock / Vertex / Foundry 三方分发停留 Sonnet 4.5，需要 ANTHROPIC_DEFAULT_OPUS_MODEL=claude-opus-4-7 显式 pin。
    • 

  • 2026-05-06 · 全部 plan 5 小时窗速率全面翻倍。免费版与 Pro 同时上调，CLI 配 Pro 已经能跑相当密集的会话。
    • 

  • v2.1.32+ · Agent Teams 进入正式。顶层 Opus 4.7 coordinator 拉起最多 10 个并行 subagent，每个独立 isolation（isolation: worktree）、独立 model / effort、独立预载 skills；subagent 不能再 spawn subagent，Plan agent 内部专门做了防嵌套保护。
    • 

  • 2026 起 · Skills 已并入 commands。老式 .claude/commands/*.md 仍兼容，但同名 Skill 优先级更高；官方推荐只写 Skills，custom commands 视为 Skill 的 user-invocable 子形态。
    • 

  • Hooks 事件数 29。覆盖 session 生命周期、prompt/tool 调用、agent 状态、环境变化四大组；handler 5 种（command / http / mcp_tool / prompt / agent），是 5 家工具里事件最多的一项（OpenCode ~25、OpenClaw 14、Hermes 12+、Codex CLI 仅 6）。
    • 



陷阱与常见误解




误解
实际情况





"Claude Code 是开源的"
仓库公开，但许可证是 Anthropic Commercial ToS（source-available），不允许 fork 自部署 / 商业衍生。




"全系模型都是 200K 上下文"
Opus 4.7 与 Sonnet 4.6 是 1M context，仅 Haiku 4.5 是 200K。




"Pro / Team 默认是 Opus"
Pro 与 Team Standard 默认 Sonnet 4.6；Enterprise + API 自 2026-04-23 默认 Opus 4.7；Bedrock/Vertex/Foundry 停 Sonnet 4.5，需显式 pin。




"桌面 Claude Desktop = Claude Code"
二者共用账号但是不同产品；Claude Desktop 是 LLM 对话客户端，不内置 agentic coding。




"subagent 可以再 spawn subagent"
不可以，显式禁止递归；多 agent 协作走 Agent Teams 的"扁平 + coordinator"模型。




"Hooks 数量是 25 个"
截至 2026-05-14 v2.1.x 是 29 个事件，5 家里最多。





小结
    

  • 仓库 anthropics/claude-code、Anthropic 维护、source-available（非 OSI） 走 Anthropic Commercial ToS。
    • 

  • 三档模型：Opus 4.7（1M）/ Sonnet 4.6（1M）/ Haiku 4.5（200K）；subagent 别名 opus/sonnet/haiku/inherit。
    • 

  • 多 surface 同引擎：CLI / VS Code / JetBrains / 桌面 / Web claude.ai/code / iOS 共享同一份 ~/.claude/ 与项目 .claude/ 配置；与 Claude Desktop 是不同产品。
    • 

  • 2026 时间线：04-23 Enterprise+API 默认 Opus 4.7、05-06 速率翻倍、v2.1.32+ Agent Teams 正式（最多 10 并行 subagent）、Skills 并入 commands、Hooks 29 事件 × 5 handler。
    •
