CLAUDE.md 多层加载 · Skills 14+ frontmatter 字段

核心概念

Claude Code 的"prompt + 可复用工序"两层配置在 5 款工具里最分散但表达力最强。本节专注前两层：CLAUDE.md 管 prompt（项目协议与全局事实）、SKILL.md 管可复用工序（含已并入的老式 commands）——MCP 与 Hooks 在下一节展开。

两层各管一摊：CLAUDE.md 把"该怎么做事"以自然语言写给 agent；SKILL.md 把"具体怎么做事"以 frontmatter + markdown 步骤固化，可被 LLM 自动选用或显式 /skill-name 触发。把"哪个文件管哪件事 / 加载顺序如何"想清楚之后，80% 的新手配置错觉会自动消失。

CLAUDE.md 多层加载与 path-scoped rules
CLAUDE.md 不是单文件——是一组按"作用域 + 层级"叠加的 markdown，加载顺序固定为 managed → user → project → local。@path import 在任意文件内可用，最多 5 跳。

.claude/rules/ 是 2026 年的新设计：每个规则文件 frontmatter 写 globs: ["src/api/**/*.ts"]，只有当 agent 操作匹配的路径时才注入对应规则——既能避免把"前端规则 + 后端规则"全塞进根 CLAUDE.md，又能在 monorepo 里给不同子工程下不同提示。@path import 让多个文件能像 markdown include 一样拼装（如根 CLAUDE.md 写 @.claude/rules/typescript.md），最多 5 跳避免循环。


CLAUDE.md 范例
# 项目协议

业务目标：l-doc-hub 是一个 AI handbook，重点是"事实溯源 + 工具横向对比"。

## Agent 不要碰

- `_research/` 是 W1 永久产物，不要改
- `ai-handbook/INDEX.md` 由脚本生成，不要手动改
- `feedback_*.md` 是 reviewer feedback 归档，不要 paraphrase

## 团队约定

- 中文为正文、英文用于专有名词与 CLI flags
- 不写 emoji，不写 Co-Authored-By trailer

## 运行命令

- 验证：`node scripts/doc-hub/doc-hub.mjs analyze --issues`
- 关键路径：`ai-handbook/` 是新生根，与 `docs/02_ai-llm/` 零交叉

@.claude/rules/markdown-style.md
@.claude/rules/mermaid-style.md
MEMORY.md auto-memory 的边界
MEMORY.md auto-memory 由 Claude 自己写：每次 session 结束时 agent 把"值得记的长期事实"写进去，下次启动会自动加载头 200 行 / 25KB。超出部分 Claude 会主动压缩或丢弃旧条目——这与 OpenClaw 的 SOUL.md（人格分离）、Hermes 的 char-cap + curator 是不同的设计取向，Claude Code 保留"自由形态"，靠截断 + 主动压缩控制规模。


想固化某条 auto-memory 不被压缩，把它从 MEMORY.md 复制进 CLAUDE.md 即可。


Skills：路径优先 + frontmatter 14+ 字段
Skills 是 Claude Code 把"可复用工序"固化的核心载体。从 2026 年起，custom commands 已并入 Skills——老式 .claude/commands/*.md 仍兼容，但同名 Skill 优先级更高，新写法推荐只写 Skills。

SKILL.md frontmatter 字段
frontmatter 字段是 5 家工具里最丰富的——14+ 个键覆盖 context、模型、effort、工具白名单、path scope、hook 内嵌、user invocation 控制。


# .claude/skills/pr-review/SKILL.md
---
name: pr-review
description: 审查当前 PR 的 diff、列 breaking changes、建议测试补充
context: fork # 是否复制主 context（默认 true）
disable-model-invocation: false # 禁止 LLM 自动选用（仅 user-invocable）
user-invocable: true # 允许用户用 /pr-review 触发
agent: build # 限定可用此 skill 的 agent
paths: # path-scope，仅在匹配路径下生效
  - '**/*.ts'
  - '**/*.tsx'
allowed-tools: # 收紧此 skill 可用的工具
  - Read
  - 'Bash(git diff:*)'
model: opus # 此 skill 强制走 Opus
effort: high # reasoning effort
hooks: # 把 hook 内嵌进 skill
  PostToolUse:
    - command: 'bun run lint'
shell: bash # 限定 shell handler
---
# PR Review 工序

1. 跑 `git diff HEAD~1..HEAD` 拿 diff
2. 列每个变更的 risk level、breaking changes、测试覆盖
3. 输出 markdown PR comment

陷阱与常见配置错觉




误解
实际情况





"CLAUDE.md 只能写在仓库根"
至少 5 个位置可生效（user / project 主 / .claude/CLAUDE.md / .local / .claude/rules/*.md）+ @path 5 跳 import。




"MEMORY.md 是手写的"
由 Claude 自己 curate；头 200 行 / 25KB 截断；想固化条目就把它复制进 CLAUDE.md。




"自定义命令必须写 .claude/commands/"
已并入 Skills；新写法 .claude/skills/<name>/SKILL.md + user-invocable: true；老路径兼容但同名 Skill 优先。




"Skills 只能 LLM 自动调用"
加 user-invocable: true 暴露为 slash；加 disable-model-invocation: true 仅允许用户触发；二者可组合。




"Skills 默认共享主 context"
默认 context: fork，子 context 独立；想读父 context 设 context: shared（注意污染风险）。




"Skills 没有 path scope"
frontmatter paths: 字段是 glob 数组，类似 .claude/rules/ 的 path-scope。




"@path 不存在会报错"
静默跳过——配置完后用 TUI 内 /context 看实际加载的文件清单是最稳的验证方式。





加载顺序排查思路：怀疑某条规则没生效时，按"managed → user → project → local，rules glob 是否匹配"逐层查；/context 看实际加载的 token 数与文件清单。


小结
    

  • 两层各管一摊：CLAUDE.md 管 prompt（项目协议）、SKILL.md 管可复用工序（含已并入的 commands）。
    • 

  • CLAUDE.md 多层加载 managed → user → project → local；@path 5 跳 import；.claude/rules/*.md 按 globs path-scope；MEMORY.md 由 Claude 自己写，头 200 行 / 25KB 截断。
    • 

  • Skills 路径三层：user ~/.claude/skills/ < project .claude/skills/ < plugin bundled；项目级覆盖用户级。
    • 

  • frontmatter 14+ 字段：context: fork / disable-model-invocation / user-invocable / paths / allowed-tools / model / effort / hooks / agent / shell 等。
    • 

  • custom commands 已并入 Skills——.claude/commands/*.md 兼容但同名 Skill 优先；新写法用 user-invocable: true，同一工序兼容 LLM 自动调用与用户显式触发。
    • 

  • 排查时按"加载顺序逐层 + /context 看实际加载"组合，比单看单文件更稳。
