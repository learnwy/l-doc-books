Providers 与 AGENTS.md · 两块"必先配齐"的基础配置

核心概念

Codex CLI 配置面收敛在 ~/.codex/config.toml（用户层）+ ~/.codex/AGENTS.md（提示协议层），加上项目级 .codex/config.toml 与项目 AGENTS.md，仅四个文件。本节聚焦其中两块——Providers / Models（决定走哪家模型） 与 AGENTS.md walk-up（决定 system prompt 怎么拼）。这两块不配好，后续的 Hooks / MCP 配置都无意义；它们也是 Codex CLI 与 OpenCode / Claude Code 差异最大的两个面。

Providers · [models] 段四选一
[models] 段决定走哪家 provider 与默认模型。Codex CLI 内置四个 provider 名，开箱即用。






Provider
适用场景
关键配置项





openai（默认）
ChatGPT 订阅 / API key 用户
无需额外配置




amazon-bedrock
企业 Bedrock 部署
aws_region + inference_profile_arn（2026-04 起取代旧 endpoint_url）




ollama
本地推理
base_url（默认 http://localhost:11434/v1）




lmstudio
本地推理 / GUI 调参
base_url（默认 http://localhost:1234/v1）





完整 ~/.codex/config.toml 示例（同时声明多个 provider、按需切换）：


[models]
default = "openai"
fallback = "ollama"   # 走 default 失败时切到 fallback

[models.openai]
model = "gpt-5.5"
# 走 ChatGPT 订阅时不需要 api_key
# 走 API 时由 OPENAI_API_KEY 环境变量提供（或 api_key = "sk-..." 写死）

[models.amazon-bedrock]
model = "anthropic.claude-sonnet-4-6-v1:0"
aws_region = "us-west-2"
# 2026-04 起的新字段；沿用旧 endpoint_url 会收到 deprecation warning
inference_profile_arn = "arn:aws:bedrock:us-west-2:123456789012:inference-profile/us.anthropic.claude-sonnet-4-6-v1:0"

[models.ollama]
model = "qwen2.5-coder:32b"
base_url = "http://localhost:11434/v1"

[models.lmstudio]
model = "qwen2.5-coder-32b-instruct"
base_url = "http://localhost:1234/v1"
切换走 TUI 内 /model 命令、或 codex exec --model amazon-bedrock 命令行临时覆盖；fallback 仅在 default provider 网络层失败时触发。


Bedrock 2026-04 迁移要点
Bedrock 从 2026-04 升级为"一等" provider，伴随一个 breaking change：runtime endpoint 报告改用 inference_profile_arn，旧 endpoint_url 字段标记为 deprecated。






旧（2026-03 及之前）
新（2026-04 起）





endpoint_url = "bedrock-runtime.us-west-2.amazonaws.com"
inference_profile_arn = "arn:aws:bedrock:us-west-2:.../us.anthropic..."




模型直接写 model id
模型 id 写 cross-region inference profile id




不支持跨区故障转移
inference profile 内置跨区路由





继续用旧字段会启动时打 warning、但仍能跑；下一个 major release 移除支持。


AGENTS.md Walk-up · 沿目录拼提示
AGENTS.md 是 Codex CLI 与 OpenCode / OpenClaw / Hermes 共识的"项目提示协议文件"，由 OpenAI 在 2025-09 推动成跨工具协议。加载算法分四层。


加载层级（优先级 L1 < L2 < L3 < L4）：


    

  1. 全局层 ~/.codex/AGENTS.md —— 跨项目通用规则（个人偏好、shell 别名约定）。
    2. 

  2. 项目根层 —— 从 cwd 向上 walk，遇到 project_root_markers（默认 [".git"]）停在那一层；该层 AGENTS.md 加载。
    3. 

  3. walk 沿途层 —— walk 经过的每个目录里如果有 AGENTS.md 都加载，cwd-most 优先级最高。
    4. 

  4. 临时覆盖 AGENTS.override.md —— 与同目录 AGENTS.md 并存时，override 内容追加在最后（最高优先级），用于"我想临时让 Codex 不要做 X"这种场景，commit 进仓库前删掉。
    5. 



project_root_markers 与 fallback 文件名
# ~/.codex/config.toml 顶层
project_root_markers = [".git", "package.json", "Cargo.toml", "pyproject.toml", "go.mod"]

# 找不到 AGENTS.md 时退而读 CLAUDE.md（兼容已有 Claude Code 项目）
project_doc_fallback_filenames = ["AGENTS.md", "CLAUDE.md"]
project_root_markers 默认仅 [".git"]，对 monorepo / 非 Git 仓库不友好；自定义后能让 walk 在第一层 package boundary 就停下。


Untrusted Projects · 项目层 config 被跳过、AGENTS.md 仍读
当项目未被加进 ~/.codex/trusted-projects 时：


    

  • 项目级 .codex/config.toml 与 .codex/agents/ / .codex/hooks.json / .codex/mcp_servers 被跳过；
    • 

  • 项目级 AGENTS.md 仍然加载（提示协议层无危险）。
    • 



这是 Codex CLI 与 OpenCode / Claude Code 最显著的安全模型差异——后两者默认信任所有项目目录配置。设计意图是：恶意项目可能在 .codex/config.toml 里设危险 sandbox / 改 inference_profile_arn 偷流量，但 AGENTS.md 只是文本提示，影响范围有限。


codex trust 命令把当前项目加入 trusted；codex trust list 看清单。


Admin 控制面 · ~/.codex/requirements.toml
requirements.toml 是 enterprise 控制面，作用是让 IT 强制全局策略、覆盖用户层任何冲突配置。位置两选一：~/.codex/requirements.toml（个人 admin override，少见）或 /etc/codex/requirements.toml（系统级，企业管控常见）。它正交于 providers / AGENTS.md，所以放在本节收尾。


# /etc/codex/requirements.toml
[require]
sandbox_mode = "workspace-write"          # 用户不能切到 danger-full-access
approval_policy = "on-request"            # 强制最低审批等级

[require.models]
allowed = ["openai", "amazon-bedrock"]    # 禁用 ollama / lmstudio 本地

[require.mcp_servers]
allowlist = ["github", "internal-search"] # 用户配的其它 mcp_servers 被静默忽略
用户的 config.toml 与 requirements.toml 冲突时，CLI 启动打 warning 并使用 admin 值。这也是 untrusted projects 跳过项目层的根本原因——避免恶意项目通过 .codex/config.toml 绕开企业策略。Hooks / MCP 配置中 admin override 的更多细节见 2_hooks-and-mcp.md。

小结
    

  • Codex 配置面收敛在 ~/.codex/config.toml + ~/.codex/AGENTS.md，加上项目层两个文件，总共四份。
    • 

  • Providers：[models] 段四选一（openai / amazon-bedrock / ollama / lmstudio），Bedrock 2026-04 后用 inference_profile_arn 取代旧 endpoint_url。
    • 

  • AGENTS.md walk-up：四层加载（全局 → 项目根 → 沿途子目录 cwd-most 优先 → AGENTS.override.md 临时覆盖）；project_root_markers 决定 walk 停点。
    • 

  • Untrusted projects：项目层 .codex/ 配置被跳过、AGENTS.md 仍读；codex trust 加入信任清单是安全模型的核心 anchor。
    • 

  • Admin override：~/.codex/requirements.toml 或 /etc/codex/requirements.toml 强制企业策略，与 untrusted projects 设计联动。
    •
