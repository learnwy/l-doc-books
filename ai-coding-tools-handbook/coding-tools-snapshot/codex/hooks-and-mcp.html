Hooks 与 MCP · 6 个 event + 三种 MCP 传输

核心概念

Providers / AGENTS.md 配齐之后，剩下的两块"自动化与扩展面"是 Hooks（自动化锚点） 与 MCP（外部工具协议）。它们都在 ~/.codex/config.toml 里以 section 形式出现，也都被 requirements.toml 的 admin allowlist 管辖。本节聚焦两块，并给出企业 lockdown 的最小可行配置。

Hooks · 6 个 stable event
2026 年 Codex CLI 的 hooks 覆盖 6 个 event，全部 stable——早期 plan 误写 "25+" 是把 Hermes 的 transform 系列 + Claude Code 的 29 个混进来了。设计原则是"每事件做正确"优于"事件数量多"。






Event
触发时机
典型用途





SessionStart
TUI / codex exec 启动
加载团队约定、设置环境变量




UserPromptSubmit
用户每次 enter、发送 model 前
注入额外上下文、敏感词过滤




PreToolUse
model 决定调 tool、实际执行前
拦截危险 shell、注入 audit log




PermissionRequest
sandbox 触发 approval prompt 时
自动审批白名单内的操作




PostToolUse
tool 执行完成后
录制结果、转化输出




Stop
session 退出前
上传日志、清理临时文件





PermissionRequest 是独立成 event 的细致设计——Claude Code 把这步合并在 PreToolUse 内，Codex 拆开后能精确实现"白名单自动批准"而不影响 PreToolUse 的 audit。


两种配置面 · inline vs 独立文件
# 方案 A · config.toml 内 [hooks] inline 块（小型 hook 友好）
[[hooks.PreToolUse]]
matcher = "Bash"
command = "echo \"$CODEX_TOOL_INPUT\" >> ~/.codex/audit.log"

[[hooks.Stop]]
matcher = "*"
command = "codex-upload-log"
// 方案 B · 独立 ~/.codex/hooks.json（复杂 hook、便于版本管理）
{
  "PreToolUse": [
    {
      "matcher": "Bash",
      "handler": "command",
      "command": "/usr/local/bin/codex-bash-audit.sh"
    },
    {
      "matcher": "Edit",
      "handler": "command",
      "command": "/usr/local/bin/codex-edit-policy.py"
    }
  ],
  "Stop": [{ "matcher": "*", "handler": "command", "command": "codex-upload-log" }]
}
两种面读同一份内部 schema，可以并存（按 inline 先、独立文件后顺序合并）。

handler 类型：当前 stable 仅 command；schema 中保留 prompt / agent handler 字段（与 Claude Code 对齐），运行时解析但跳过，未来版本启用。同 event 多 handler 并发触发，全部退出后聚合决策；任一返回阻塞即整体阻塞。


MCP Servers · [mcp_servers.<id>] 三种传输
MCP（Model Context Protocol）让 model 调外部 tool / 数据源。Codex CLI 是 MCP client（一等），2026-04 PR #17210 加入 outputSchema 推断——把 server 端结构化输出 schema 反塞进 code-mode tool decl，model 知道字段类型与约束。


配置走 [mcp_servers.<id>]，传输三选一
# stdio · 本地进程，最常见
[mcp_servers.filesystem]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
env = { LOG_LEVEL = "info" }

# Streamable HTTP · 远端服务 + OAuth
[mcp_servers.github]
url = "https://mcp.github.com"
oauth = true   # 触发 OAuth flow，回调端口由 mcp_oauth_callback_port 控制

# Streamable HTTP + 自定义 header（API key 等）
[mcp_servers.internal-search]
url = "https://search.example.com/mcp"
headers = { Authorization = "Bearer ${INTERNAL_TOKEN}" }

codex mcp CLI · 与 TOML 等价的脚本化入口
# CLI 等价配置 stdio server
codex mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem /tmp

# 列出当前已配 server 与状态
codex mcp list

# 管理 OAuth token
codex mcp login github
codex mcp logout github
codex mcp add 写到 ~/.codex/config.toml（或 --project 写到 .codex/config.toml）；CLI 适合脚本化、TOML 适合 commit 进仓库。


OAuth 回调端口与 token 存放
# 多用户 / 容器环境推荐固定回调端口
mcp_oauth_callback_port = 47282   # 任意未占用端口
OAuth token 写在 ~/.codex/mcp-tokens/<id>.json（chmod 600）；token 过期时下次调用自动 refresh，refresh 失败提示 codex mcp login <id> 重新授权。


outputSchema 推断 · 2026-04 新增
PR #17210 之前，MCP server 返回结构化数据时 model 只看到 JSON 字符串、不知字段类型。之后 client 会把 server 声明的 outputSchema 反塞进 tool decl，使得 model 在生成调用代码时知道：返回的对象有 id: string、status: "pending" | "done" 这种约束，code-mode 调用准确率显著提升。


启用条件：server 端 tools/list 响应里给出 outputSchema；client 端 Codex CLI 版本 ≥ v0.124（含 PR #17210）。


Admin Override · requirements.toml 限制 Hooks 与 MCP
requirements.toml 给企业 IT 一个 lockdown 面，覆盖用户层 / 项目层任何冲突配置。在 Hooks / MCP 场景下两个最常用约束：


# /etc/codex/requirements.toml
[require.mcp_servers]
allowlist = ["github", "internal-search"]   # 用户配的其它 mcp_servers 被静默忽略

[require.hooks]
require_audit_log = true                     # 强制 PreToolUse 中必须有 audit 类 hook
forbidden_commands = ["curl http://*"]      # 静默剔除发到非 HTTPS 的 hook handler
启动时若用户的 mcp_servers 不在 allowlist，CLI 在 codex status 输出 MCP servers (admin-filtered): foo, bar 提示。这是 Codex CLI 在企业市场比 Claude Code managed settings 更适配的关键——admin 值是静默覆盖、不是合并，恶意配置进不来。

小结
    

  • Hooks：6 个 stable event（SessionStart / UserPromptSubmit / PreToolUse / PermissionRequest / PostToolUse / Stop）；PermissionRequest 独立成 event 是企业 audit 友好的细化。
    • 

  • Hooks 配置面：config.toml inline [hooks] 与 ~/.codex/hooks.json 两种并存；同 event 多 handler 并发；exit-code 2 + stderr 阻塞、JSON stdout 决策。
    • 

  • MCP 三种传输：stdio（本地进程）、Streamable HTTP（远端 + header）、Streamable HTTP + OAuth（SaaS）；codex mcp CLI 与 [mcp_servers.<id>] TOML 等价。
    • 

  • 2026-04 关键变化：MCP outputSchema 推断（PR #17210）让 code-mode 调用拿到 server 端字段类型；client 版本 ≥ v0.124 才生效。
    • 

  • Admin lockdown：requirements.toml 提供 allowlist / forbidden_commands 等约束，静默覆盖用户配置，是 Codex CLI 在企业市场比 Claude managed settings 更强约束的关键设计。
    •
