Tier 1 · Coding Tools 工具栈三款 Coding Tools 速览 简介OpenAI Codex CLI 速览 简介首次会话与 Headless · TUI 三开关、`/init`、`codex exec --json`

首次会话与 Headless · TUI 三开关、/init、codex exec --json

核心概念

装好 + 登好之后，"跑通一次会话"的路径分两条，最好都走一遍。TUI 路径关心可视交互——/permissions / /model / approval_policy 三个关键开关、/init 生成 AGENTS.md；Headless 路径关心可被 CI / git hook / 流水线消费——codex exec --json 单次会话、跑完即退、读同一份配置。

TUI 三开关 · sandbox / model / approval
终端打 codex 进 TUI，默认 build agent（edit / bash / task 权限）。首次启动会引导填三个开关，对应三类风险面，组合起来决定"Codex 能动多大、模型怎么贵、什么时候停下来问你"。


/permissions 切 sandbox_mode




取值
行为
推荐用途





read-only
只读文件、不写、不跑 shell
首次试用、review 他人代码




workspace-write
写当前工作区，不动 ~ 与系统目录
日常开发（推荐起点）




danger-full-access
全机器无限制
仅在 Docker / 隔离 VM 内





/model 切模型
默认 gpt-5.5；gpt-5.4 省 token、gpt-5.4-mini 极快、gpt-5.3-codex 是上一代 code-fine-tune。切换在 TUI 即时生效，不影响下次启动默认值。


approval_policy 首次启动一次性问
# ~/.codex/config.toml 的对应段
approval_policy = "on-request"   # 推荐起点：模型主动求批准时才弹
# approval_policy = "untrusted"  # 任何写盘 / shell 都弹
# approval_policy = "never"      # 永不打断（仅配合 read-only sandbox）
# approval_policy = "granular"   # 按 tool 分组细化
推荐起点组合：workspace-write + on-request + gpt-5.5。既能改代码、又给两道审核（sandbox 限定写在工作区 + 关键操作弹确认）。


/init · 生成 AGENTS.md 并理解 walk-up
在仓库根目录的 TUI 里输入 /init，Codex 做四步。


    

  1. 从 cwd 向上 walk 直到遇到 project_root_markers（默认 [".git"]）；
    2. 

  2. 读项目结构（package.json / pyproject.toml / Cargo.toml / go.mod 等指纹文件）；
    3. 

  3. 调用 model 生成首份 AGENTS.md 写在仓库根；
    4. 

  4. 提示是否同时生成 .codex/config.toml 项目级配置。
    5. 



AGENTS.md 是"项目背景注入文件"——之后每次会话都把它与全局 ~/.codex/AGENTS.md、子目录的 AGENTS.md 一起拼到 system prompt 顶部，cwd-most 优先级最高。结构通常是：项目简介 / 技术栈 / 关键命令（test / build / lint）/ 风格约定 / 勿动清单。


为什么不能跳过这一步：没有 AGENTS.md 时，每条 prompt 都要重复交代项目背景，token 消耗与回答质量都会变差。具体 walk-up 算法、AGENTS.override.md 临时覆盖、untrusted projects 行为见 ./5_providers-and-agents-md.md。


Headless 模式 · codex exec 接 CI / git hook
TUI 跑通后试一次 headless 模式——这是把 Codex 接入 git hook / CI 流水线的入口。


# 基本调用：传一句话、拿一段文本回复
codex exec "review the staged diff for security issues"

# JSON 输出，便于 jq 解析
codex exec --json "summarize the changes in the last 3 commits" | jq

# 接 git pre-commit hook 示意：staged diff 是否安全
codex exec --json --sandbox read-only \
  "is the staged diff safe to commit? respond with JSON {verdict: safe|unsafe, reason}" \
  | jq -e '.verdict == "safe"'

# CI 友好：超时 + 限定 model + 限定 sandbox
codex exec --json --timeout 120s --model gpt-5.4-mini --sandbox read-only \
  "lint review for $CI_COMMIT_SHA"
codex exec 单次会话，跑完即退；它与 TUI 共享同一份 ~/.codex/config.toml 与 AGENTS.md。这意味着"在 TUI 里调好的配置 = 在 CI 里也是同一套行为"——这一致性是 Codex CLI 比裸 OpenAI API 调用顺手的核心原因。

根因
解法

联系 IT；或切个人账号 + 个人目录

cwd 不在 .git 仓库 / .git 离 cwd 太远
在仓库根重跑；或配 project_root_markers = [".git", "package.json"]




codex exec --json 输出非 JSON
命令后接了 > file.txt 与 stderr 混了
加 2>/dev/null 隔 stderr 或 codex exec --json ... 1>out.json




TUI 改了配置但 headless 不生效
改的是 .codex/config.toml，但项目未 trusted
把项目加进 ~/.codex/trusted-projects，或挪到 ~/.codex/config.toml 用户层





最后一个值得强调的是 requirements.toml 的存在感：企业部署中 IT 经常把它放在 ~/.codex/ 或系统级 /etc/codex/，作用是 admin override —— 用户的 config.toml 选项如果违反它会被静默忽略。详见 ./6_hooks-and-mcp.md 收尾段。


小结
    

  • 首次会话走两条路径：TUI（日常）与 Headless（CI / git hook），二者共享同一份 config.toml + AGENTS.md。
    • 

  • TUI 三开关：/permissions 切 sandbox_mode、/model 切模型、approval_policy 首次启动定调；推荐起点 workspace-write + on-request + gpt-5.5。
    • 

  • /init 生成 AGENTS.md：四步（向上 walk → 读指纹 → model 生成 → 提示项目级 config），cwd-most 优先级最高、不可跳过。
    • 

  • Headless 关键：codex exec --json 单次会话、跑完即退、读同一份配置；--timeout + --sandbox read-only 是 CI 标配。
    • 

  • 五大常见跑不通：缺鉴权、Fast 档不在、admin 锁了选项、cwd 远离 .git、stderr 与 JSON 混流——每条都有可执行的回退路径。
    •
