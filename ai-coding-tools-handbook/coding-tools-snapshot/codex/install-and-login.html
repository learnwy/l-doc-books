安装与登录 · 装上 Codex CLI 并看到 Fast 档

核心概念

Codex CLI 的"上手第一步"分得很清：装二进制 → 选鉴权路径 → 用 codex status 验"plan 档位"。这三步串起来才是"装上"的完整意义——只完成前两步，仍然可能在 Free / Go 档跑 Codex，响应慢到误以为工具有 bug。本节按这三步铺开，每步明确"该选哪种、踩到什么坑、回退到哪里"。

四种官方支持方式按"日常 → 隔离"递进列出，再加 winget 给 Windows 用户。

多源装重了怎么办：常见情况是先装了 npm 又装了 brew，PATH 顺序导致旧版优先；which -a codex 看完整列表，把不想要的那条手动 unlink（npm: npm rm -g @openai/codex，brew: brew unlink openai-codex）。


鉴权路径二选一 · OAuth vs API Key
两条路径互斥（同时设了以 OAuth 为准），按"是否有 ChatGPT 订阅"分流。


OAuth 路径（推荐 ChatGPT 订阅用户）
执行 codex login 弹浏览器到 OpenAI 登录页，授权后 CLI 拿到 refresh token 写在 ~/.codex/auth.json（chmod 600，团队共享机器需注意权限）。


    

  • 优势：消化 ChatGPT plan 的额度、合格 plan 自动开启 Fast 档、无需管理 API key 轮转。
    • 

  • 限制：每 30 天若 CLI 完全静默会触发 refresh 失败，需重新 codex login。
    • 

  • 远程机器友好：codex login --device-code 用 6 位数字 + 任意浏览器完成授权，专为 ssh / tmux 跑 CLI 的场景。
    • 



API Key 路径（推荐企业 / 不想登 ChatGPT / CI）
export OPENAI_API_KEY=sk-...
# 写入 shell profile（zsh）
echo 'export OPENAI_API_KEY=sk-...' >> ~/.zshrc
    

  • 优势：跳过 OAuth、token 不过期、按 API 计费透明；CI 环境必选这条。
    • 

  • 限制：失去 Fast 档（按 API 默认速度走，对短任务通常足够）、失去订阅包内额度。
    • 

  • 企业附加 base_url：通过 OpenAI 兼容代理时设 OPENAI_BASE_URL，例如 https://gateway.internal.example.com/v1。
    • 



codex status · 必跑的第一条命令
装完 + 登完后第一条命令永远是 codex status，它是判断"是否真的装好了"的唯一权威输出。


codex status

# 输出示例（OAuth + ChatGPT Pro）
# Account:       name@example.com
# Plan:          ChatGPT Pro
# Fast tier:     enabled (default since 2026-05)
# Default model: gpt-5.5
# Auth source:   ~/.codex/auth.json (OAuth, refreshed 2h ago)
# Config:        ~/.codex/config.toml (5 sections loaded)
# Requirements:  not present
Fast tier 三种取值含义不同。






Fast tier 值
含义
处理动作





enabled (default since X)
Plus / Pro / Business / Enterprise 默认开
无须任何动作




not eligible
plan 在 Free / Go 档
升 plan 或改 API key 路径




disabled by admin
requirements.toml 强制关
联系 IT；个人无法绕过





Auth source 一行帮你排查"同时设了 OAuth 与 API key 时 CLI 选了哪条"，优先级是 OAuth > API key（除非显式 --api-key 或 OPENAI_API_KEY_FORCE=1）。


陷阱与首次安装的五大坑




现象
根因
解法





codex --version 报 command not found
PATH 没生效（macOS 新 zsh 用户尤其常见）
eval "$(/opt/homebrew/bin/brew shellenv)" 写入 ~/.zprofile




codex login 浏览器打开但回调 404
防火墙拦了 localhost:<random> 回调端口
用 codex login --device-code 走纯数字流程




codex status 显示 Fast tier: not eligible
plan 在 Free / Go；或登错账号（多个 OpenAI 邮箱）
升 plan；或 codex logout && codex login 选正确账号




codex status 显示 Auth source: API key (env)，却想用订阅
同时设了 OPENAI_API_KEY 和 OAuth，CLI 走了环境变量
unset OPENAI_API_KEY 或在 shell profile 注释掉那一行




Docker 容器内 codex login 弹不出来
container 内没 X / 默认 browser
走 codex login --device-code；或 host 完成登录后 mount ~/.codex/ 进容器




安装多份 codex（npm + brew + Cargo cargo install）
PATH 顺序冲突
which -a codex 列全，手动 unlink 不要的那条





小结
    

  • 三步顺序：安装 → 鉴权 → codex status 验档位——只完成前两步会误以为"装好了"。
    • 

  • 五种安装方式：brew install openai-codex 是首选；npm 装的也是 Rust 二进制；Docker 适合 CI；winget / Releases 给 Windows / 离线环境。
    • 

  • 鉴权二选一：OAuth codex login（拿 ChatGPT plan 包 + Fast 档）vs OPENAI_API_KEY（企业 / CI / 按 API 计费）；二者同时存在以 OAuth 为准。
    • 

  • codex status 是装好后第一条命令，三个关键字段：Plan / Fast tier / Auth source，逐一对照表上即可定位"是否符合预期"。
    • 

  • 五大常见坑：PATH 未生效、OAuth 回调被拦、Fast 档不在名单、环境变量与 OAuth 同时存在、多源装重——每一条都有可直接执行的解法。
    •
