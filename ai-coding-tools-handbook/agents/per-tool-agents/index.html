三款工具的 Agent 实现 简介

读完 subagent 基础之后，本章把三款工具的 agent 实现拉平。Claude Code 是 Agent Teams 的发起者——Opus 4.6 release（2026-02）随 v2.1.32+ 引入、experimental flag 启用、shared task list + peer-to-peer messaging；Codex App 走桌面 supervisor 路线、把 multi-agent 做成视觉 operations console + built-in worktree per agent + cloud execution；OpenCode 在 2026 上半年 port 自己的 Agent Teams 实现、与 Claude 哲学接近但实现细节不同（cross-provider model mix、single-process 限制、event-driven messaging）。三家都在解决"agent 并行 + 协调 + 隔离"问题，但偏好不同 trade-off。

本章包含三篇 L4 文档。

1_claude-code-subagents-and-teams.md —— Claude Code 完整 agent 体系。第一块讲 subagent 定义文件——.claude/agents/<name>.md 含 frontmatter（name、description、tools:、isolation: worktree、model:）+ body 作 system prompt；主 agent 通过 description 自动匹配派生。第二块讲 Agent Teams（Opus 4.6 release 2026-02 experimental）——启用 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 或 settings.json 开关；lead AI spawn teammates、各自 context window、shared task list 是 source of truth、三态 pending / in_progress / completed + dependencies、阻塞 task 在依赖完成时自动 unblock。第三块讲 peer-to-peer messaging——teammates 互相发消息、claim task、mid-task 分享发现、不必经主 agent 转交；user 可直接对单个 teammate 发指令。第四块讲与 subagent 的边界——subagent 是 single session 内 fire-and-forget 子任务（return 一次 result），Agent Teams 是长期协作的多个 peer agent。

2_codex-agents-supervisor.md —— Codex App 桌面 supervisor 模型。第一块讲 App 定位——developers.openai.com/codex/app 桌面端是 "command center for multi-agent workflows"，built-in worktree support、isolated copies per agent；与 CLI / IDE 扩展 / Web / iOS 共享 unified state（同一份 session 跨 surface 可继续）。第二块讲 GPT-5.3-Codex（2026-02-05 release）作为 most capable agentic coding 模型、Cloud execution 不占 user 本地 CPU。第三块讲 agent supervisor UI——视觉 console 看每个 agent 的 plan / current step / file changes / token usage，相比 Claude Code 的对话式 orchestration 更适合"agent 跑 30 分钟以上长任务"的场景。第四块讲 Codex 与 Claude 在多 agent 哲学上的差异——Codex 偏 supervisor + 长任务、Claude 偏 conversational + 紧反馈循环；选择上往往由 team 工作节奏决定，而非工具能力差异。

3_opencode-agent-teams-port.md —— OpenCode Agent Teams port。第一块讲 port 动机与时间线——dev.to/uenyioha/porting-claude-codes-agent-teams-to-opencode-4hol 文章详述、OpenCode 团队 2026 上半年完成 port、保持架构与 Claude 类似（fire-and-forget spawn、file-based inbox、explicit sub-agent isolation）。第二块讲 OpenCode 独有的 cross-provider model mix——同一个 agent team 内 teammate 可来自不同 provider（Anthropic Claude + OpenAI GPT + Google Gemini + 本地 Ollama），Claude Code 因绑 Anthropic 模型做不到。第三块讲 architectural divergence——event-driven messaging、append-only JSONL writes（持久化任务流）、peer-to-peer 通信、两级 state machine、single-process only（所有 lock 在内存，多 server instance 不能共享 storage）。第四块讲 trade-off 总结——OpenCode 灵活性高（model mix + provider 中立），Claude Code 工业级（file-based locking 跨进程、Anthropic 直接维护）；选 OpenCode 还是 Claude Code 取决于团队是否需要 model mix 与跨 provider portability。

学习建议是先读 1_ 把 Claude Agent Teams 心智建好（reference implementation），再读 2_ 看 Codex 的不同哲学，最后读 3_ 看 OpenCode 的 cross-provider 价值；选型阶段三节都要读。
