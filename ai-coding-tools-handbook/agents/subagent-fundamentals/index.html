Subagent 基础机制 简介

Subagent 不是简单的"主 agent 调一个子函数"——它有自己的 context window、自己的 system prompt、独立的 tool access 与 permission 集，是一个完整的迷你 agent 实例。这个 isolated 设计解决了主 agent 在长会话里 context 被 search result / log / file content 撑爆的问题：让 subagent 在自己的 context 里干完脏活、只把 summary 回报主 agent。但 isolation 之上还有两个关键机制需要理解清楚——isolation: worktree 让 subagent 在 fresh git worktree 跑，文件改动写隔离的工作树而非主 checkout；fork mode 复用 parent 的 prompt cache 让派生成本接近"零"。这两块是 2026 多 agent 编排能 cost-effective 跑起来的底层支撑。

本章包含两篇 L4 文档。

1_subagent-isolation-and-context.md —— subagent 隔离与 context 模型。第一块讲基础隔离——subagent 自己的 context window（不与主对话共享）、自己的 system prompt（在 .claude/agents/<name>.md 定义）、自己的 tool 集（frontmatter tools: 列）、自己的 permission（独立 --permission-mode）；主 agent 通过 description 匹配派生 subagent、subagent 跑完只返回 summary 而非全 transcript。第二块讲 isolation: worktree 机制——agent 设置该字段后，Claude 自动 spin up fresh worktree、给它命名、在那里跑工作、收尾如无 changes 自动 cleanup；per-worktree state（plan mode / memory / hooks / permissions / transcript）都附着到 worktree、原仓库 checkout 不受影响。第三块讲 两 agent 互不见对方的 edits——这是 worktree 模式的核心价值，两个 subagent 各自的 plan 不冲突、文件改动隔离。第四块讲收尾——worktree 自动 cleanup 还是保留？有 unmerged commits 时拒绝 cleanup 防数据丢失。

2_fork-mode-and-prompt-cache.md —— fork mode 与 prompt cache 经济学。第一块讲 fork vs spawn——fork 复用 parent 的 system prompt 与 tool definitions、首次 request reuse parent prompt cache、远比 spawn fresh subagent 便宜（spawn fresh 要重 boot system prompt + tools，token 开销大）。第二块讲启用方式——CLAUDE_CODE_FORK_SUBAGENT=1 env var 启用（interactive / non-interactive / Agent SDK 都生效）；Agent tool 调用时显式 isolation: "worktree" 让 fork 的文件 edits 写隔离 worktree。第三块讲 fork-can't-fork 规则——fork 不能再 fork（一层 fork 深度限制），这是防递归无限派生的硬规则；需要更深嵌套时 spawn fresh subagent 而非 fork。第四块讲选型——同 context 重活（同样的 system prompt + tools，只换 task）用 fork；不同领域任务（如主 agent 改代码 / subagent 跑 web search）用 spawn fresh；多 worker 并行（agent teams 场景）用 fresh subagent + worktree。

学习建议是 1_ 先把 isolation 模型刻进脑里再读 2_；后续每次"想派生一个 subagent"时按"重活同 context vs 异领域 vs 并行"三问决定 fork / spawn / Agent Teams。
