Claude Code 的 MCP 配置：四级 scope、.mcp.json 与 ${VAR}

Claude Code 是三款工具里配置面最复杂的一家——同时维护两份配置文件、四种 scope、type 字段命名上把 spec 的 streamable-http 简写成 http、提供 claude mcp add CLI 屏蔽手写 JSON、还内置与 Claude Desktop 的双向迁移。这套设计的优点是 enterprise / team / personal 边界清晰，缺点是第一次接入需要理解 scope 优先级、文件命名、CLI 与手写的关系四件事。本节按"两份文件 → CLI + 四级 scope → 命名差异 → 运行时与 Desktop 互通"四块讲清。

personal 与 user 都存到 ~/.claude.json 但语义不同：personal 是"跨项目用户级"、user 是"项目级用户私有覆盖"（在某项目里我额外加一个个人 server，但不写进 commit 的 .mcp.json）。


.mcp.json 与 claude mcp add CLI
新手 onboarding 不建议手写 JSON，用 claude mcp add CLI 引导：


# 添加 stdio server 到项目 scope（写到 .mcp.json）
claude mcp add github --scope project --transport stdio \
  -- npx -y @modelcontextprotocol/server-github

# 添加 HTTP server 到 personal scope（写到 ~/.claude.json）
claude mcp add notion --scope personal --transport http \
  --url https://mcp.notion.com/mcp

# 列出当前 session 里所有 server
claude mcp list

# 移除某个 server
claude mcp remove github --scope project
CLI 干的事情等价于手写 JSON 并放到对应文件——区别只是 CLI 会校验字段、自动选择文件路径、运行时立刻 reload。手写 JSON 是完全支持的备份姿势。


一份典型 .mcp.json 长这样：


{
  "mcpServers": {
    "github": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" },
    },
    "linear": {
      "type": "http",
      "url": "https://mcp.linear.app/mcp",
    },
  },
}
${GITHUB_TOKEN} env 引用语法与 OpenCode 一致——Claude Code 启动时从自己进程的 env 展开，避免 token 字面值进 git。这是 .mcp.json 能安全 commit 的关键。


四级 scope 的合并语义
--scope 四个值对应四类配置来源，加载顺序明确：






优先级
scope
文件
覆盖语义





1（最低）
managed
enterprise 平台特定
企业强制，admin 推送




2
user
~/.claude.json 内 user-scope 段
用户全局共享




3
personal
~/.claude.json 内 personal-scope 段
跨项目个人配置




4（最高）
project
<repo>/.mcp.json
项目级，commit 进 git





合并规则是按 server 名深合并、同名后加载者整体替换前者；不同 server 名累加；managed scope 内被 admin 标记 lock: true 的 server 例外——project / user 同名 server 会被忽略，相当于 OpenCode 的 admin managed 与 Codex 的 requirements.toml。


实务用法：


    

  • 项目内共享 server（团队都需要的项目 wiki / 项目数据库）→ --scope project，commit .mcp.json。
    • 

  • 跨项目个人偏好（个人 GitHub / Notion / 待办工具）→ --scope personal，不 commit。
    • 

  • 某项目里我个人临时加一个 server 但不污染项目 .mcp.json → --scope user，写到 ~/.claude.json。
    • 

  • 企业强制（审计 / 合规）→ --scope managed，由 admin 部署。
    • 



type: http 与 type: streamable-http 的命名差异
这是 Claude Code 配置里最容易引起混淆的点。MCP spec 里 HTTP transport 的正式名字是 streamable-http（区别于已 deprecated 的 sse）；Claude Code 简写成 http：


{
  "mcpServers": {
    "linear-a": { "type": "http", "url": "https://..." },
    "linear-b": { "type": "streamable-http", "url": "https://..." },
  },
}
两种写法 Claude Code 都接受、语义完全一致——type: streamable-http 在 Claude Code 实现里被识别为 type: http 的别名。从 OpenCode（type: remote）或 Codex（type: streamable-http）迁移配置时，把字段值替换成 http 即可。OAuth 触发方式：HTTP server 请求 401 时 Claude Code 自动进入 OAuth flow，token 持久化到 ~/.claude/auth/，无需手动跑 auth 子命令——这点与 OpenCode 的 opencode mcp auth 不同。


运行时 /mcp 命令与 Claude Desktop 互通
Claude Code 在会话中提供 /mcp 命令查看 / 管理运行时 server 状态：






命令
作用





/mcp
列出当前会话所有 server + 连接状态 + tool 数量




/mcp <name> disconnect
临时断开某个 server（context 立刻释放）




/mcp <name> reconnect
重连某个 server（用于改配置后不重启 Claude Code）




/mcp <name> info
看 server 暴露的 tool 列表 + 当前会话调用统计





/mcp reconnect 在改 .mcp.json 不想重启整个会话时很有用——但注意：只有 stdio 子进程模型能完整 reload；HTTP server 重连只重置 session、连接配置本身（URL 改了）仍然按旧配置。


与 Claude Desktop 的配置互通：


# 一键把 Claude Desktop 配置导入到 Claude Code
claude mcp add-from-claude-desktop
Claude Desktop 的 claude_desktop_config.json 也用 mcpServers 顶层 key、字段命名（command、args、env、type 等）与 Claude Code 完全一致——这个一键导入命令就是把 claude_desktop_config.json 整段拷贝到 personal scope 的 ~/.claude.json。反向迁移（Claude Code → Desktop）目前需要手动复制片段，没有官方一键命令。


最小可运行配置
// .mcp.json (项目根，commit 进 git)
{
  "mcpServers": {
    "github": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" },
    },
    "notion": {
      "type": "http",
      "url": "https://mcp.notion.com/mcp",
    },
  },
}
跑通顺序：


    

  1. shell 里 export GITHUB_TOKEN=ghp_... 提供 env 变量。
    2. 

  2. 启动 Claude Code 会话，github server 立刻可用、notion 首次调用时弹浏览器走 OAuth。
    3. 

  3. 用 /mcp 验证 server 状态、/mcp notion info 看暴露的 tool 列表。
    4. 



陷阱与常见问题
    

  • .mcp.json env 写字面 token：忘记用 ${VAR} 直接把 token 写进 JSON、commit 进 git 泄漏。强制规则是任何敏感字段必须 ${VAR} 引用。
    • 

  • /mcp reconnect 不重读 .mcp.json：reconnect 重置 session 但不重读文件；改了配置仍需要重启 Claude Code（详见 ../3_reverse-mcp-and-pitfalls/2_pitfalls-and-tool-budget.md 第一类陷阱）。
    • 

  • personal 与 user scope 混淆：选错 scope 导致项目里看不见 server。用 claude mcp list 看每个 server 标的 scope 一目了然。
    • 

  • type: sse 旧配置无效：Claude Code 2026 已不再接受 type: sse，旧 server 通过 type: http 加 4xx 回退 兼容。
    • 

  • claude mcp add-from-claude-desktop 覆盖现有 personal server：导入是合并不是覆盖，但相同 server 名会被新版本覆盖。导入前 claude mcp list 确认无冲突。
    • 



小结
    

  • Claude Code 用 .mcp.json（项目 commit）+ ~/.claude.json（用户）两份文件，claude mcp add CLI 引导写入避免手动改 JSON。
    • 

  • 四级 scope（managed / user / personal / project）覆盖语义 project > personal > user > managed，managed 锁定除外。
    • 

  • type: streamable-http 在 Claude Code 是 type: http 的别名，两种写法等价；从其他工具迁移直接替换字段值即可。
    • 

  • ${VAR} env 引用让 .mcp.json 能安全 commit；HTTP server OAuth 自动触发，token 存 ~/.claude/auth/。
    • 

  • 运行时 /mcp 命令查 server 状态 + reconnect；claude mcp add-from-claude-desktop 一键从 Desktop 配置导入。
    •
