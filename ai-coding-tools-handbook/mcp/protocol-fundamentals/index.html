MCP 协议本体：传输、授权与 outputSchema 简介

2024-11 Anthropic 开源 MCP 时，协议只有 stdio 一种 transport、没有正式的授权层、tool 返回值是 free-form text。到 2026-05-14，最新 spec（modelcontextprotocol.io 2025-11 版）已经把 transport 收敛为 stdio + Streamable HTTP 两种、把 HTTP 授权强制为 OAuth 2.1 + PKCE、把 tool 返回值升级为 outputSchema-typed structuredContent——三项改动都不是渐进优化，而是 breaking change。本章不重复讲"MCP 是什么"，目标是把这些 2025-2026 才稳定下来的协议要点压成两篇可读的 L4。

读完本章，读者应能：判断一个 MCP server 实现是否合规（transport 选对了吗、OAuth 流走对了吗、outputSchema 提供了吗）；理解为什么 2025 年的旧教程在 2026 年用不了；以及给自己的 server / client 选对 spec 版本 pin。

本章包含两篇 L4 文档。

1_transports-stdio-and-streamable-http.md —— 两种 transport 与三类 primitive。第一块讲 JSON-RPC 2.0 基础与三类 primitive（Tools / Resources / Prompts）的语义边界——常见混淆是把 Resource 当成 Tool 调用，或把 Prompt 当成 system message 注入；第二块讲 stdio transport：subprocess 模型、stdin/stdout JSON-RPC 帧、stderr-as-log、newline 分隔禁内嵌、no-auth-needed；第三块讲 Streamable HTTP transport：单一 endpoint 同时支持 POST 与 GET、可选 SSE 流式服务端通知、Mcp-Session-Id header（UUID/JWT/hash，仅可见 ASCII）、Origin header 必须验证防 DNS rebinding、HTTP 4xx 回退到旧 SSE+POST 双 endpoint 的 backwards-compat 算法；最后讲 2025-06-18 SSE 弃用与旧 server / client 互通建议。

2_oauth-and-output-schema.md —— OAuth 2.1 授权与 typed tool 返回。第一块讲 HTTP transport 上的 OAuth 2.1 + PKCE：MCP server 是 OAuth Resource Server、MCP client 是 OAuth Client、第一次受保护请求返回 401 + WWW-Authenticate header 引用 protected resource metadata、metadata 指 authorization server、client 可选 RFC 7591 Dynamic Client Registration 自动注册、RFC 8707 Resource Indicators 防 token 跨 server 滥用；第二块讲 stdio 的等价方案——子进程继承 env，不需要 HTTP 级别授权；第三块讲 outputSchema 与 structuredContent：tool 声明 outputSchema 后，client 拿到的是 typed object（带 JSON Schema 校验），fallback 是从 text content 解析 JSON，最差 fallback 是 raw CallToolResult { content, isError }；最后讲 production 部署建议——固定 spec 版本（不要追 latest）、HTTP 强制 PKCE、outputSchema 必填以便客户端做 zod / valibot 校验。

学习建议是 1_ 先读完把"协议形态"内化（stdio vs HTTP 是日常选型的第一刀），再读 2_ 把安全 / 类型化的硬要求记牢——这两块是 2025-2026 与 2024 协议最大的差异源。
