反向 MCP 与配置陷阱 简介

前两章的视角都是"编程代理（Claude Code / Codex / OpenCode）作为 MCP client、调用外部 server"——这是 95% 用户的入门姿势。但 MCP 的协议本身是对称的：任何应用都可以同时作为 client 和 server，这是 2026 年跨 tier 编排（personal-agent 工具暴露 MCP server 给 coding 工具反向调用）的协议基础。本章一篇讲清"反向"模式的架构意义与 tier 2 工具 hermes / openclaw 的 mcp serve 实现入口；另一篇收尾五类跨工具配置陷阱——这些陷阱在第 2 章每个 per-tool 节都会零散提到，本章把它们汇总成一份 checklist。

本章包含两篇 L4 文档。

1_reverse-mcp-tier-2-as-server.md —— 反向 MCP：Tier 2 工具作 server 被 Tier 1 反向调用。第一块讲架构动机——为什么不直接让 coding 代理调外部 API 就好？因为 personal-agent 工具（Hermes / OpenClaw）持久化了用户的 memory / persona / skills 这些"软上下文"，让 coding 代理通过 MCP 调用它们等于把"角色化的世界知识"注入到编程会话；第二块讲 Hermes hermes mcp serve 暴露的 tool 列表（memory query / curator scheduling / persona pick / skill 调度）；第三块讲 OpenClaw mcp serve 暴露的 tool（multi-tenant persona switch / chat-platform message router）；第四块讲 client 端如何接——Claude Code .mcp.json 加一行 stdio 配置即可、Codex 同理；深入选型 / 编排 / 防递归请转 03_bridges/1_cross-tier-orchestration/。

2_pitfalls-and-tool-budget.md —— 跨工具配置的五类陷阱。第一块讲 restart-after-change：编辑 .mcp.json / opencode.json / config.toml 直接修改文件不会影响正在运行的会话，必须 restart 或用 /mcp reconnect；第二块讲 绝对路径：filesystem-server 的 path 参数不展开 ~/，必须写 /Users/<name>/...，2026 上半年依然是最常见的"我配了为什么不工作"原因；第三块讲 tool 名冲突：两个 server 暴露同名 tool 时 client 行为不定（Claude Code 取一个忽略另一个、Codex 走 alphabetical），解法是 tools 字段 rename 或 filter；第四块讲 prompt-injection 风险：fetch-external-content 类 server（web fetch、wiki reader）可被外部内容操纵 agent 行为——配置前 review server 源码、按需用 server allowlist、关键路径加 hook 二次确认；第五块讲 tool budget < 10：研究与社区共识——超过 10 个并发 server 会让 agent context 被 tool description 占满、降低任务质量，主流建议保留 5-6 个常用 server，剩余按需 enable/disable。

学习建议是先读 1_ 把"反向"的概念建立，再读 2_ 把五类陷阱印到肌肉记忆里——任何一条踩中都会浪费半天 debug 时间。
