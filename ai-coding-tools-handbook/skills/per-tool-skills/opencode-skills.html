OpenCode Skills 多路径互通实现

OpenCode（Anomalyco 维护的开源 agent 编辑器）2026 年把 Skills 实现得最"互通主义"——同时扫 .opencode/skills/ + .claude/skills/ + .agents/skills/ 三路径合并去重，加上 plugin-bundled 这一档形成四档发现。OpenCode 私有的 skill instructions provider plugin 进一步让 plugin 在 build/plan agent 切换时动态变更可用 skill 列表，是它 "plugin = hook" 哲学的具体落地。本文讲多路径互通、plugin 触发器、commands 兼容、provider plugin 模式。

核心概念

OpenCode 不追求把所有字段都自己实现，而是追求"读得了别人的 skill"——同一份 base SKILL.md 在 Claude、Codex 写、在 OpenCode 直接复用。这种"互通优先"的设计选择把 OpenCode 变成跨工具迁移成本最低的工具。

三路径并存与去重合并
OpenCode 启动时按顺序扫描三类 user-written 路径：


    

  • .opencode/skills/<name>/SKILL.md——OpenCode 原生路径，纯 OpenCode 项目首选。
    • 

  • .claude/skills/<name>/SKILL.md——兼容 Claude Code 项目，无需迁移即用。
    • 

  • .agents/skills/<name>/SKILL.md——agentskills.io 推荐的中性路径（2026 起社区事实标准），跨工具共享 skill 的最佳位置。
    • 



扫描结果按"先发现的留下、后发现的同名被去重"合并——具体顺序由 OpenCode 配置决定，默认 .opencode > .claude > .agents。这意味着把同一个 skill 同时放在 .agents/skills/deploy/ 与 .opencode/skills/deploy/ 时，OpenCode 用前者还是后者取决于扫描顺序，建议团队选一个路径放、避免多份副本。


中性路径 .agents/skills/ 是这套机制最大的实用价值：mono-repo 里多人各用 Claude / Codex / OpenCode，把 skill 都 commit 到 .agents/skills/ 一份，三家都能读到（Claude / Codex 通过 symlink 或 alias 配置、OpenCode 原生支持）。详见 ../3_cross-tool-interop/1_path-interop-and-discovery-order.md。


Plugin-bundled Skills 与触发器
OpenCode 的 plugin 系统支持把 skill 打包到 plugin 一起分发。plugin 维护者在 plugin manifest 声明 skills_dir，OpenCode 启动时把对应目录纳入扫描。plugin-bundled skill 与 user skill 同名时 plugin 优先（与 Claude Code 一致）。


OpenCode 独有的是 plugin 触发器：plugin 可以根据 agent mode（如切到 build agent 还是 plan agent）动态启用/禁用 skill 列表。例如：






Agent Mode
Plugin 启用的 Skills





plan
research-helper, task-decomposer




build
code-reviewer, test-runner, deploy-checker




debug
log-collector, trace-analyzer





这与 Claude Code 的"所有 skill 全部进 inventory、模型自己选"不同——OpenCode 让 plugin 提前根据上下文裁剪 inventory，减少 token、减少模型误触。代价是 plugin 维护者需要自己写 mode → skill 映射逻辑。


Commands 兼容
OpenCode 早期与 Claude Code 一样把 slash 命令存在 .opencode/commands/*.md。2026 起 Skills 成为新标准、但旧 commands 路径仍兼容：


    

  • .opencode/commands/*.md 自动按"无 frontmatter 的简单 skill"加载。
    • 

  • 与 .opencode/skills/<name>/SKILL.md 同名时 skill 优先。
    • 

  • 推荐迁移：把 .opencode/commands/foo.md 改写成 .opencode/skills/foo/SKILL.md，加 frontmatter 后获得调用控制能力。
    • 



兼容期不强制迁移，但新写的 slash 都建议直接走 Skills。


Skill Instructions Provider Plugin
OpenCode 的 plugin 系统把"提供 skill"也视为一种 hook：plugin 实现 getSkills(context) 函数、OpenCode 在每次 turn 前调用、plugin 返回当前应启用的 skill 数组。这把 skill 列表从"静态磁盘扫描"变成"动态 context-aware"。


典型用法：


    

  • 基于文件类型动态启用：编辑 .tsx 时启用 React skill 集合、编辑 .rs 时启用 Rust skill 集合。
    • 

  • 基于 git 状态动态启用：dirty working tree 时启用 commit-helper、clean 时禁用。
    • 

  • 基于团队角色动态启用：根据用户 git config 邮箱判断是 frontend / backend / devops，对应不同 skill 包。
    • 



provider plugin 是 OpenCode "plugin = hook" 哲学的体现——把工具核心能力暴露为 plugin 可重写的扩展点。Claude Code 与 Codex 目前没有等价机制。


跨工具互通性
OpenCode 对 base SKILL.md 的支持：


    

  • name / description / argument-hint / version / $ARGUMENTS：全识别。
    • 

  • disable-model-invocation / user-invocable / mode：静默忽略——OpenCode 让 plugin provider 控制可见性，frontmatter 字段无能为力。
    • 

  • allowed-tools：部分识别（plugin-bundled 内强制、user-written 暂未启用）。
    • 

  • !command 预加载：plugin-bundled 内支持、user-written 不支持。
    • 

  • model / effort / context / agent：静默忽略，OpenCode 走会话级配置而非 skill 级。
    • 



这意味着 OpenCode 是跨工具 skill 的"低门槛接收方"——base 字段够用、私有字段不会报错、加 provider plugin 后还能动态裁剪。


陷阱与常见问题
    

  • 三路径同名 skill 副本：把同一个 skill copy 到 .agents/skills/ 与 .opencode/skills/ 都各放一份，OpenCode 默认用前者会让团队困惑改后者没生效；建议团队只选一个路径放。
    • 

  • plugin provider 在 plan/build 模式切换时丢 skill：模型在 plan 阶段记住的 skill 切到 build 后不在 inventory 了，触发失败；plugin 应当在两个 mode 都启用关键 skill 或在 prompt 里说明。
    • 

  • 依赖 disable-model-invocation 防止误触：OpenCode 静默忽略该字段——想让 skill 只 user 触发，要么不写进 inventory（provider 控制）、要么靠命名前缀让 description 不像 use-case。
    • 

  • !command 在 user-written skill 不生效：以为预加载了实则原文注入 body——agent 会按字面执行；如需预加载请打成 plugin-bundled。
    • 

  • .agents/skills/ 与 .opencode/skills/ 优先级误解：默认前者后扫到、被去重——想让中性路径优先要在配置里调整扫描顺序。
    • 



小结
    

  • OpenCode 主打"互通优先"：三路径并存 + 去重合并 + plugin-bundled
    • 

  • .agents/skills/ 是 2026 跨工具共享事实标准、OpenCode 原生支持
    • 

  • plugin-bundled skill 可根据 agent mode 动态启用/禁用，是 OpenCode 独有能力
    • 

  • commands 旧路径仍兼容，新写一律走 skills
    • 

  • skill instructions provider plugin 把 skill 列表变成 context-aware，是 "plugin = hook" 落地
    • 

  • 私有调用控制字段静默忽略，可见性由 provider plugin 接手
    •
