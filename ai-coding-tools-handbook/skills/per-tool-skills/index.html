三款工具的 Skills 实现 简介

读完第 1 章的 spec 参考之后，本章把三款主流编程工具的 Skills 具体实现拉平。Claude Code 是 Skills 的 reference implementation——14+ frontmatter 字段最完整、commands 已并入 Skills、/skills 运行时命令；Codex 通过 openai.yaml 元数据扩展、按 OpenAI 内部安全策略实施权限模型；OpenCode 走多路径互通——.opencode/skills/ + .claude/skills/ + .agents/skills/ 三路径并存扫描、plugin-bundled、commands 仍兼容旧 .opencode/commands/。同一份 base SKILL.md 在三家可以直接复用，但要利用各家独有能力（如 Claude context: fork / Codex openai.yaml / OpenCode 跨路径 fallback），需要分别理解差异。

本章包含三篇 L4 文档。

1_claude-code-skills.md —— Claude Code Skills（reference implementation）。第一块讲两个发现路径 ~/.claude/skills/<name>/SKILL.md（用户全局）+ .claude/skills/<name>/SKILL.md（项目本地）+ plugin-bundled <plugin>/skills/<name>/SKILL.md；第二块讲 commands → Skills 的合并历史（2026 Q1 完成，老的 .claude/commands/*.md 仍兼容、同名 skill 优先）；第三块讲调用控制三件套——disable-model-invocation: true（user-only 触发，省 context）/ user-invocable: false（Claude-only 触发，不出现在 /skill-name 列表）/ mode: true（UI grouping 到顶部）；第四块讲运行环境字段——allowed-tools 限权、model 覆盖默认、effort: low|medium|high 推理深度、context: fork 隔离 subagent、agent: Explore|Plan|general-purpose 选 subagent 类型；第五块讲 !command 动态预加载（如 !git status 嵌入当前 git 状态）+ $ARGUMENTS 参数替换；第六块讲 issue #17283 已知 bug + workaround。

2_codex-skills.md —— Codex Skills。第一块讲基础发现路径 .codex/skills/<name>/SKILL.md（项目）+ ~/.codex/skills/<name>/SKILL.md（用户）；第二块讲 openai.yaml 元数据 vendor extension——在 SKILL.md 同目录可放 openai.yaml 声明额外 OpenAI 特有元数据（model_pin、approval_policy、sandbox_mode），与 frontmatter 互补；第三块讲与 AGENTS.md 的协作——skill 是过程性知识、AGENTS.md 是项目协议，两者通过 prompt 拼接同时进入 context；第四块讲 untrusted-projects 安全模型——默认不读 .codex/，skill 执行 scripts 需 explicit user approval。

3_opencode-skills.md —— OpenCode Skills 的多路径互通设计。第一块讲三路径并存：.opencode/skills/（OpenCode 项目原生）+ .claude/skills/（兼容 Claude 项目）+ .agents/skills/（agentskills.io 推荐的中性路径，跨工具共享）；扫描合并去重、同名按路径优先级。第二块讲 plugin-bundled skills——通过 plugin 系统打包 + 触发器机制（plugin 决定 skill 启用/禁用）；第三块讲 commands 兼容——.opencode/commands/*.md 旧路径仍读、与 Skills 同名按 skill 优先；第四块讲 OpenCode 独有的 skill instructions provider plugin 模式——允许 plugin 在 build/plan agent 切换时动态变更 skill 列表，是 OpenCode "plugin = hook" 哲学的具体落地。

学习建议是只用一款工具的读者只看对应一节；同时用多款工具的工程师建议三节都读——重点对比"路径布局 + 调用控制字段支持度"两条线。
