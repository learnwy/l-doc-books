Claude Code Skills 参考实现详解

Skills 的规范虽然由 agentskills.io 用 Apache-2.0 协议公开维护，但 Claude Code 才是把 14+ frontmatter 字段全实现的 reference impl。2026 Q1 Claude Code 完成"commands → Skills"的合并、/skills 运行时命令、context: fork 与 agent: 字段、!command 预加载、$ARGUMENTS 参数替换一应俱全。同时 issue #17283 又揭示了 Skill tool 调用路径的一处隐性 bug——本文把这些实现细节、合并历史、调用控制三件套、运行环境字段、动态注入与 workaround 一次讲清。

核心概念

Claude Code 把 skill 当作"模型可决定是否触发的 prompt 片段 + 可选的 subagent 隔离运行环境"。/skills 命令打开列表，斜杠触发或模型自动触发都可，frontmatter 字段控制可见性、权限、运行环境。

三类发现路径
Claude Code 启动时按 plugin > project > user 顺序扫描三类路径：


    

  • ~/.claude/skills/<name>/SKILL.md——用户全局，跨项目共享，常放个人偏好型 skill（如 personal-pr-template、my-coding-style）。
    • 

  • .claude/skills/<name>/SKILL.md——项目本地，commit 进 git 与团队共享；通常 commit、放团队约定型 skill。
    • 

  • <plugin-dir>/skills/<name>/SKILL.md——plugin 打包，通过 marketplace 或 npm 分发；plugin 维护者负责升级。
    • 



同名时高优先级覆盖低优先级。例如 plugin 与 project 都有 deploy skill，模型只看到 plugin 版；user 想覆盖必须改 name。这种"plugin 总赢"的策略避免了 plugin 升级被 user 偶然 shadowing，但要求 plugin 用前缀（acme-deploy、stripe-checkout-tester）避免与常用 user skill 重名。


commands → Skills 的合并历史
Claude Code 早期把 .claude/commands/*.md 作为 slash 命令的存储位置——简单 prompt 拼接、没有 frontmatter、不支持 description discovery。2026 Q1 之前的 release 同时存在两套系统：commands 走 .claude/commands/、skills 走 .claude/skills/。2026 Q1 起官方完成合并：


    

  • 旧 .claude/commands/*.md 仍兼容、自动按"无 frontmatter 的简单 skill"加载。
    • 

  • 同名时 skill 优先（.claude/skills/deploy/SKILL.md 覆盖 .claude/commands/deploy.md）。
    • 

  • 推荐迁移路径是把 .claude/commands/foo.md 改写成 .claude/skills/foo/SKILL.md、补 frontmatter——/skills 列表更清晰、可以加调用控制、未来不被 deprecate。
    • 



迁移期间最常见踩坑是 /foo 触发到底打到 commands 还是 skill：用 /skills 命令查看 inventory 即可确认。


调用控制三件套
disable-model-invocation、user-invocable、mode 是 Claude Code 私有的可见性字段，详见 ../1_skill-md-reference/2_frontmatter-fields-complete-reference.md。三个字段组合后构成五种典型场景：






场景
字段配置
用法





自动 + 手动均可
全默认
普通 skill




仅 user 手动
disable-model-invocation: true
高代价或破坏性操作（如 deploy）




仅 model 自动
user-invocable: false
内部辅助 skill，不希望出现在 slash 列表

mode: true
模式切换型 skill 放列表顶部

disable-model-invocation: true + user-invocable: false
配置错误，谁都触发不了





实际工作流里 disable-model-invocation 用得最多——典型例子是"调用费时长 + 副作用大"的 skill（如生产部署、删数据），明示 user-only 触发能避免模型在多 turn 里误调。


运行环境字段
Claude Code 完整实现 allowed-tools / model / effort / context: fork / agent：


    

  • allowed-tools 是 harness-enforced 白名单。skill 内 agent 尝试调用未列出 tool 时 harness 直接拒绝、返回错误给模型自己处理。常见组合 [Read, Grep, Glob, Bash]（只读型 skill）、[Read, Edit, Write]（改文件型）。
    • 

  • model 覆盖会话默认（如把单个长 skill 切到 claude-opus-4-7、便宜 skill 用 sonnet-4-7）。
    • 

  • effort: low|medium|high 控制本次推理深度——high 启用更长 thinking、约相当于 OpenAI o-series 的 reasoning effort 旋钮。
    • 

  • context: fork 开 subagent 隔离 context——主会话不受 skill 长输出污染。
    • 

  • agent: Explore|Plan|general-purpose 显式选 subagent 类型，仅在 context: fork 生效时有意义。
    • 



动态注入：!command 与 $ARGUMENTS
!command 是 body 内的行首预加载语法。例如 PR review skill 的 body 头部：


---
name: pr-review
description: Review the current PR for security and style issues.
---

!git diff main...HEAD
!gh pr view --json title,body,author

Review the diff above for: security issues, breaking changes, style violations.
$ARGUMENTS
skill 触发时 Claude Code 先在 shell 跑 git diff 与 gh pr view，把 stdout 注入到 body 对应位置（替换那一行），用户 /pr-review --strict 调用时 $ARGUMENTS 替换为 --strict。最终模型看到的是已经填好的具体上下文，省了一轮 Bash 工具调用。


注意 !command 的预执行是 skill 触发时立刻跑、跑完才进 turn——意味着命令必须够快（< 数秒），慢命令会让 skill 触发体感卡顿。


issue #17283 与 workaround
Anthropic 公开 issue #17283（2026-01 报告，截至 2026-05 仍未完全修复）描述：通过 Skill tool 调用时（如另一个 agent 内部调用 Skill(name=foo)），context: fork 与 agent: 字段被静默忽略——skill 仍在主会话 context 里跑、subagent 隔离失败、原本期望的"长输出不污染主 context"被打破。


workaround 有两条：


    

  1. 把 skill 重写成 custom agent（在 .claude/agents/<name>.md）——agent 路径下 fork 与 subagent 类型字段都按预期工作。
    2. 

  2. 仍保留 skill 形式、但把 body 写成"只给 agent 读、不实际执行长任务"的 prompt 片段，把长任务挪进 agent。
    3. 



迁移成本视 skill 大小：调研型、长输出型 skill 建议改 agent；轻量 prompt 型 skill 保留即可。


陷阱与常见问题
    

  • commands 与 skill 同名混淆：迁移期 /foo 触发到底打哪个，靠 /skills 列表与 /help foo 确认；推荐尽快把 commands 全迁到 skills。
    • 

  • mode: true 误以为限制行为：只是 UI 提示，不限制谁能触发——别拿它做安全控制。
    • 

  • context: fork 通过 Skill tool 调用失效：踩 #17283，要么改 agent、要么改 prompt 不依赖隔离。
    • 

  • !command 命令慢导致 skill 卡顿：把慢命令挪到 body 里让 agent 自己决定何时跑、或者改用 scripts/ 异步处理。
    • 

  • plugin skill 默默覆盖 project skill：装新 plugin 前用 /skills 列表 diff 一遍，提前发现同名冲突。
    • 



小结
    

  • Claude Code 是 14+ 字段全实现的 reference impl
    • 

  • 三类路径 user / project / plugin，plugin > project > user 优先级
    • 

  • commands 已并入 Skills（2026 Q1），旧 .claude/commands/*.md 兼容但同名 skill 优先
    • 

  • 调用控制三件套 + 运行环境五字段 + 动态注入两机制 = 完整字段集
    • 

  • issue #17283：Skill tool 路径 fork/agent 字段被忽略，workaround 是改 custom agent
    • 

  • !command 预加载省 turn 但要求命令够快；$ARGUMENTS 参数替换让 slash 调用更灵活
    •
