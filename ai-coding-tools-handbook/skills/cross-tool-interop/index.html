跨工具协作与生命周期 简介

Skills 的核心承诺是"一次写好、所有兼容工具直读"——但落到团队规模化实践时，跨工具协作与 skill 生命周期管理会暴露很多 spec 没回答的问题：如果同一份 skill 在 Claude Code 写时用了 context: fork，搬到 Codex 后会怎样（spec 允许静默忽略）？plugin 提供的 skill 与 user 自写的 skill 同名时谁优先？要 retire 一个用了 6 个月、跨 4 个项目的 skill 时怎样不破坏依赖它的工作流？本章把这些 spec 之外的实战问题汇总成两篇 L4。

本章包含两篇 L4 文档。

1_path-interop-and-discovery-order.md —— 跨工具路径互通与发现顺序。第一块讲 agentskills.io 推荐的 中性路径 .agents/skills/——把 skill 放这里、Claude Code / Codex / OpenCode 都能扫到（OpenCode 原生支持；Claude Code / Codex 通过 symlink 或 alias 配置），这是团队 mono-repo 共享 skill 的事实最佳实践。第二块讲 plugin-bundled vs user-written 优先级——多数工具 plugin > project > user > built-in，但 OpenCode 按 plugin lifecycle 触发；同名冲突时建议 plugin 用前缀（如 acme-deploy）避免与 user skill 重名。第三块讲团队 commit 策略——.agents/skills/（团队共享）commit、~/.config/<tool>/skills/（个人）不 commit、.<tool>/skills/（项目级 tool-specific）按团队约定（一般 commit）。第四块讲 IDE 与终端协同——VS Code Copilot 在 2026 Q1 加入 SKILL.md 支持后，同一 skill 在 IDE 与 CLI 间共享，体验已经统一。

2_skill-lifecycle-and-pitfalls.md —— 生命周期与陷阱。第一块讲 lifecycle 阶段——write（命名 + frontmatter 设计 + body）→ test（dry-run + edge case）→ ship（commit + tag）→ adopt（团队培训 + adoption metric）→ retire（标记 deprecation + 给迁移指引 + 删除）。第二块讲 版本管理——version 字段 + git tag 双轨；breaking change 时改 skill name 而不只是 bump version，避免 in-flight 任务半途中断。第三块讲 prompt-injection 安全审计 checklist——SKILL.md 内容是 agent 看见的 prompt、!command 与 scripts/ 可被恶意 skill 用来执行任意代码、第三方公开 skill 安装前必须 review；附 2026 已发现的几起公开 skill 投毒案例（agentskills.io 维护 advisory）。第四块讲常见陷阱——同名 skill 冲突静默选错、disable-model-invocation 拼错（hyphen vs underscore）导致 spec 字段静默忽略、allowed-tools 在不支持的工具被忽略给安全错觉。

学习建议是按章节顺序读完即可；运行中的团队建议把第 2 篇的 lifecycle 与 audit checklist 直接搬到内部 wiki 作为 skill 维护规范。
