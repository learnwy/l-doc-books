Frontmatter 字段完整参考

SKILL.md 顶部的 YAML frontmatter 是 skill 唯一的结构化声明区，14+ 字段里只有两个是 spec 必填（name、description），其它都是元数据、调用控制、运行环境或动态注入。不同工具对字段的识别程度差异极大——同一个 context: fork Claude 认、Codex 静默忽略、OpenCode 不实现。本文按字段大表 + 跨工具支持矩阵 + 已知 bug 三块铺开，写完后建议作为工具书反复查询。

Base 与元数据字段细节
name 是 spec 唯一的全局标识。改名等同于发布一个全新 skill——已经引用 old-name 的工作流会立刻"找不到 skill"。这是为什么 ../3_cross-tool-interop/2_skill-lifecycle-and-pitfalls.md 建议 breaking change 时改名而非 bump version——让旧引用显式失败、而不是隐性挂在过期行为。


description 是 progressive disclosure 的核心。session start 时它进入模型的 inventory，模型据此判断"这个 skill 是不是匹配当前任务"。description 写法对 skill 触发命中率影响极大：必须前置动词、覆盖典型触发场景、给出 use-when 例子。Anthropic 公开文档建议 30-80 token，agentskills.io 推荐 60 token 上下。


version 是软约定。Claude Code 在 /skills 列表展示但不做 semver 比对、不限制并存版本；team 通常配合 git tag 做版本管理。argument-hint 在 /skill-name <arg> 这种 slash 触发时显示参数提示，对 user-invocable skill 很有用。

mode: true 是纯 UI 提示：把 skill 放到 slash 列表顶部分组（典型用法是给"模式切换型"skill 用，如 /research-mode、/strict-mode）。这三个字段 Codex 与 OpenCode 都静默忽略——同一份 skill 搬过去后模型可以无限制触发，团队迁移时需要重新评估安全模型。


运行环境与权限字段
allowed-tools 是少数有跨工具 partial 实现的安全字段——Claude Code 严格执行（agent 试图调用未列出的 tool 会被 harness 拒）、OpenCode 在 plugin-bundled skill 里执行、Codex 仅 vendor extension 在 openai.yaml 里有等价物。model、effort、context: fork、agent 都是 Claude Code 私有——在其他工具完全静默忽略。


context: fork 是性价比最高的字段：让 skill 在独立 subagent 里跑，主会话 context 不被污染。例如一个深度调研型 skill 跑完会注入 5k token 文档，不 fork 直接污染主会话；fork 后主 agent 只收到最终的 summary 输出。但请注意 Anthropic issue #17283（2026-01）：通过 Skill tool 调用时 context: fork 与 agent: 被静默忽略，skill 仍在主会话 context 里跑。workaround 是改写成 custom agent，详见 ../2_per-tool-skills/1_claude-code-skills.md。


动态注入：!command 与 $ARGUMENTS
!command 是 Claude Code 独有的预加载机制——body 里行首写 !git status 或 !cat README.md，skill 触发时这些命令先在 shell 跑、stdout 替换到 body 对应位置后再注入 context。这避免 agent 在 turn 里多走一步 Bash 调用、降低 token 消耗。OpenCode 在 plugin-bundled skill 里已经支持类似机制；Codex 没有等价语法。


$ARGUMENTS / $1 / $2 是参数占位符。user 在 /skill-name foo bar 这种 slash 调用时，body 里的 $1 替换为 foo、$2 为 bar、$ARGUMENTS 为全部参数。Claude / Codex / OpenCode 都识别。


陷阱与常见问题
    

  • 字段名拼错（hyphen vs underscore）：disable_model_invocation 不是合法 spec 字段、被静默忽略——skill 表面看正常实则模型还能自动调。检查办法：触发后看 /skills 列表里这个 skill 是不是带 user-only 标记。
    • 

  • 未识别字段误以为生效：把 Claude 私有的 context: fork 写在 Codex skill 里、以为隔离了，实际上 Codex 一律在主会话跑——隔离假象是高危错误，团队迁移时务必查表。
    • 

  • allowed-tools 在不支持工具被忽略：以为限了权，agent 实际全权限——agentskills.io 推荐配套外层沙箱（Codex sandbox_mode、OpenCode plugin 钩子）补强。
    • 

  • version 误以为是依赖管理：当前所有工具都不做 semver 比对，仅做版本号展示——版本管理请走 git tag 双轨。
    • 

  • !command 在恶意 skill 里是 RCE：第三方 skill 安装前必须 grep ^!、确认所有预加载命令安全。agentskills.io 维护 advisory，详见 ../3_cross-tool-interop/2_skill-lifecycle-and-pitfalls.md。
    • 



小结
    

  • 14+ 字段按 base / metadata / invocation / runtime / dynamic 五组分类
    • 

  • 仅 name 与 description 是 spec 必填，其它都是 vendor extension
    • 

  • 跨工具兼容靠 spec 的"未识别字段静默忽略"约定——同一份 skill 多工具可读
    • 

  • Claude Code 是 reference impl，14+ 字段最全；Codex / OpenCode 仅识别 base + 部分 metadata
    • 

  • Anthropic issue #17283 已知：Skill tool 调用时 context: fork、agent: 被忽略
    • 

  • 拼写、未支持字段误用是最常见踩坑——迁移前必查字段大表
    •
