SKILL.md 规范深度参考 简介

读完本章，读者拿到一个新工具的 Skills 文档时，能立刻判断它对 SKILL.md spec 的实现程度——是不是合规、用了哪些 vendor extension、字段被静默忽略时该怎么处理。这一章不重复"Skills 是什么、为什么 progressive disclosure"——那些在 ../../1_prompt-engineering/1_agents-md-and-skills-standards/2_skills-progressive-disclosure.md 已展开；本章只做实现细节的深度 reference。

本章包含两篇 L4 文档。

1_skill-md-file-layout-and-discovery.md —— 文件布局与发现机制。第一块讲 SKILL.md 最小目录结构：skill-name/SKILL.md（必备）+ scripts/（可选，executables，agent 在需要时 spawn 子进程调用）+ 资源文件（如 templates / examples，被 SKILL.md body 用 relative path 引用）。第二块讲命名规则：skill-name 必须 kebab-case、对应 frontmatter name 字段（必填）、跨 skill 全局唯一（同名后加载者覆盖先加载者）。第三块讲 discovery 四类来源——以 Claude Code 为例：user ~/.config/claude/skills/、project .claude/skills/、plugin-bundled（<plugin>/skills/）、built-in；扫描顺序与冲突处理（同名 skill plugin > project > user > built-in 还是反向，取决于具体实现）。第四块讲 SKILL.md 加载语义：session start 只扫 name + description 进入 context（progressive disclosure），匹配触发后才注入 body；body <500 行最佳实践。

2_frontmatter-fields-complete-reference.md —— 14+ 字段完整参考表。第一块是字段大表，含每字段的 spec/Claude/Codex/OpenCode 支持矩阵、默认值、语义说明。覆盖：base spec 必填 name / description；元数据 version / argument-hint；调用控制 disable-model-invocation（user-only trigger）/ user-invocable: false（hidden from slash menu）/ mode（UI grouping）；权限与运行环境 allowed-tools / model / effort / context: fork / agent；动态注入 !command（pre-load shell）/ $ARGUMENTS $1 $2（参数替换）。第二块讲 vendor extension 模式与跨工具兼容——agentskills.io spec 明确允许 vendor 加字段，未识别字段必须静默忽略不报错；这一约定让 skill 可在多工具间复用。第三块讲已知 bug 与边界——Claude Code 2026-01 issue #17283：通过 Skill tool 调用时 context: fork 与 agent: 被忽略、skill 在主会话 context 跑（workaround 是把 skill 改成 custom agent）。

学习建议是先读 1_ 把"目录结构 + 发现机制"建好心智模型，再读 2_ 把字段表当工具书查——后续每次写新 skill 都回来查一次字段是否被目标工具支持。
