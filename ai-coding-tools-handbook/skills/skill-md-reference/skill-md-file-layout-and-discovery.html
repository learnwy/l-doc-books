SKILL.md 文件布局与发现机制

一条 skill 在磁盘上的物理形态是约定俗成的：固定名为 SKILL.md 的 Markdown 文件、放在以 skill 名命名的目录里、可选 scripts/ 和资源子目录。Anthropic 在 code.claude.com/docs/en/skills 与 agentskills.io 的开放规范都遵守这一布局，使得"agent 在 session start 只扫名字与描述、命中后再载入正文"的 progressive disclosure 才有物理基础。本文把布局规则、命名约束、四类 discovery 来源与加载语义讲透。

核心概念

最小可用 skill 是一个 SKILL.md 文件加一个外层目录。SKILL.md 顶部是 YAML frontmatter（至少 name + description），下面是 Markdown 正文（即 skill 触发后注入的 prompt）。规模化时常加 scripts/ 子目录（agent 可 spawn 子进程执行的脚本）与资源文件（如 templates/、examples/），由正文用 relative path 引用。

目录布局与命名规则
外层目录名必须等于 name frontmatter 字段（spec 约束），且采用 kebab-case：pr-review-helper、db-migration-runner。下划线、CamelCase、首字母大写均不合规——Claude Code 在 2026 Q1 起对不合规 name 会在 /skills 列表打 warning，OpenCode 直接跳过加载。


name 字段是全局唯一标识——同名 skill 来自不同来源（user / project / plugin）时，工具按"discovery 顺序后扫者覆盖先扫者"或反向（取决于实现），不会同时生效。这是同名冲突最常见的隐性故障来源，下面 discovery 一节展开。


scripts/ 子目录里的脚本通常带 shebang（#!/usr/bin/env bash、#!/usr/bin/env python），权限位 +x。SKILL.md 正文里用 scripts/run.sh 这种相对路径引用，agent 在执行时把它解析成绝对路径再 spawn。资源文件（如 templates/email.md）同理。

session 启动时，Claude Code 顺序扫描这四档目录，把所有 SKILL.md 的 name + description 抽取到内存表；同名 skill 按"高优先级覆盖低优先级"或"先发现优先"由工具决定——Claude Code 选 plugin > project > user，OpenCode 在多路径互通时按数组顺序去重保留前者。这一差异是迁移 skill 时最容易踩坑的点，详见 ../3_cross-tool-interop/1_path-interop-and-discovery-order.md。


SKILL.md 的加载语义
skill 的 progressive disclosure 由两阶段加载实现：


    

  1. session start：工具递归扫描四类来源，仅读取每个 SKILL.md 的 frontmatter 与首段 description（典型 30-80 token），把所有 skill 的 name + description 拼成一个 inventory 注入 system prompt。Mahesh Murag 在 Anthropic 内部分享里给的经验数字是 50 个 skill 大约 1500-2500 token，远小于把所有 body 都常驻的成本（前置 hub ../../1_prompt-engineering/1_agents-md-and-skills-standards/2_skills-progressive-disclosure.md 已展开）。
    2. 

  2. trigger 后：当模型决定调用某 skill（model-invoked）或用户输入 /skill-name（user-invoked），工具把对应 SKILL.md 的完整 body 读出来注入 turn 的 context；引用的 scripts/ 或资源文件按需在 agent 行为里再读。
    3. 



body 的最佳实践长度是 < 500 行（Anthropic 在 code.claude.com/docs/en/skills 给的软上限）。超过 500 行的 skill 容易把 turn context 撑爆，更好的做法是拆 skill、或者把详细步骤挪到 references/long-procedure.md 由 body 在需要时引用。


陷阱与常见问题
实践中最常见的几类陷阱：


    

  • 外层目录名与 name 字段不一致：写了 name: pr-review 但目录叫 pr_review——Claude Code 静默跳过、OpenCode 报 warning。修复办法是统一 kebab-case 且全等。
    • 

  • 同名 skill 覆盖：user 全局有一个 deploy skill、project 里又写一个 deploy，agent 看到的只有项目里那份；plugin 提供的 deploy 又会覆盖前两者。建议 plugin 用前缀（如 acme-deploy）规避。
    • 

  • scripts/ 权限缺失：脚本没加 +x，agent spawn 时静默失败、body 里的引用看似生效但执行无效。修复：写完脚本立刻 chmod +x。
    • 

  • resource 路径写成绝对：body 引用 /Users/foo/templates/email.md，迁移到他人机器后整个 skill 失效。spec 要求只用 relative path。
    • 

  • frontmatter 缺失 name 或 description：Claude Code 把这种 skill 当损坏跳过，但不会显式报错——用户以为加载成功实则没在 inventory 里。
    • 



小结
    

  • skill 物理形态：<kebab-case-name>/SKILL.md 必备 + scripts/、资源文件可选，body 用 relative path 引用
    • 

  • name 字段全局唯一、必须等于外层目录名、kebab-case
    • 

  • 四类 discovery 来源 user / project / plugin-bundled / built-in，优先级因工具而异
    • 

  • 加载分两阶段：session start 仅 name+description 进 inventory（progressive disclosure），命中后 body 注入
    • 

  • body 最佳长度 < 500 行，超出请拆 skill 或外挂 references
    • 

  • 同名覆盖、绝对路径、脚本权限缺失是高频踩坑点
    •
