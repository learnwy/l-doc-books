合并后的命令架构 简介

2026 年三款编程工具的命令体系都在向 SKILL.md 收敛。这一收敛带来的不只是文件格式统一，更重要的是命令获得了"声明式声明 + 渐进披露 + 跨工具 portability"三项能力——这是过去各家命令文件 .claude/commands/*.md / .codex/commands/ 私有格式做不到的。本章用两篇讲清架构演化的脉络与发现/调用机制，是后续读者理解每款工具具体实现的前提。

本章包含两篇 L4 文档。

1_slash-commands-history-and-skills-merger.md —— 历史脉络与合并里程碑。第一块讲 2025 年三家私有命令格式各自存在的问题——Claude .claude/commands/*.md 没有 progressive disclosure，所有命令的 prompt body 在 session start 全装入 context；Codex .codex/commands/ 与 OpenCode .opencode/commands/ 类似。第二块讲 Claude Code v2.1.101（2026-04-11 changelog）的合并方案——同名时 skill 优先、老格式仍能加载（不立即破坏老工作流）。第三块讲为什么合并而不是新加格式：核心动机是把命令也放进 progressive disclosure 经济模型、把 description budget（1% context / 8000 char fallback）扩展到命令。第四块讲 Codex 与 OpenCode 2026 上半年的对齐——同样以 SKILL.md 为新标准、保留 commands/ 兼容路径。

2_command-discovery-and-invocation.md —— 发现与调用机制。第一块讲跨工具发现路径——Claude .claude/commands/ + .claude/skills/ 合并扫描；Codex 从 cwd walk-up 到 repo root 找 .agents/skills/，monorepo 里 root + sub-project 嵌套都能发现；OpenCode 三路径并存 .opencode/skills/ + .claude/skills/ + .agents/skills/。第二块讲两种调用模式——implicit（description 匹配 auto-load，Codex 在 prompt 包含相关关键词时自动激活）vs explicit（/cmd-name Claude/OpenCode 或 $skill-name Codex 强制激活）。第三块讲 description budget 机制：所有 skill 的 name 始终入 context，description 按 1% context window 动态扩容，超出 fallback 8000 char 后开始截断（截掉关键词 = skill 永远不被 model 匹配，常见调试痛点）。

学习建议是 1_ 先读把"为什么合并"想清楚，再读 2_ 把"怎么被发现 / 怎么被调用"建好心智，第 2 章 per-tool 实现里很多细节都基于这两块基础。
