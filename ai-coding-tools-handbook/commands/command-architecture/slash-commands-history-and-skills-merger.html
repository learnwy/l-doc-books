Slash Commands 历史脉络与 Skills 合并里程碑

把命令文件升级成 SKILL.md 不是 Anthropic 的"突发奇想"，而是 2025 年三款工具私有命令格式集体撞墙的必然结果。Claude Code v2.1.101（2026-04-11 changelog）正式宣布同名时 skill 优先、.claude/commands/*.md 作为兼容路径继续工作；Codex 与 OpenCode 在 2026 上半年完成对齐。理解这次合并的脉络比记住具体语法更重要——它决定了团队在未来 1 ~ 2 年里命令体系的演化方向。

核心概念

2025 年三款工具的私有命令格式之间没有任何共享标准，命令是工具的"原子单位"但又是"封闭实现"。下表把三家命令体系在 2025Q4 与 2026Q2 的状态拉平做对比。

维度 2025Q4 私有格式 2026Q2 SKILL.md 合并
文件路径 .claude/commands/*.md / .codex/commands/*.md / .opencode/commands/*.md 统一 .claude/skills/<name>/SKILL.md，中性路径 .agents/skills/
上下文加载 所有命令 body 在 session start 全装入 context 仅 name + description 入 context，匹配后才注入 body
frontmatter 表达力 description / arguments 等少量字段，私有 schema 14+ 字段（model / tools / allowed-tools / disable-model-invocation / context: fork / argument-hint 等）
跨工具 portability 不可移植，复制改文件名都不够 同一份 SKILL.md 在三家工具直接工作
参数捕获 Claude $ARGUMENTS 单变量 $1 $2 多参数 + argument-hint 自动补全
调用方式 仅 explicit /cmd-name implicit（description 匹配 auto-load）+ explicit 双轨

2025 年三家私有命令格式各自的问题
最早被吐槽的不是 frontmatter 字段少，而是上下文加载方式。.claude/commands/*.md 在 session start 时所有文件全部读入，每个文件的完整 body（含 prompt template + 示例 + 注释）都进 system prompt。一个项目积累 20 个命令、平均每个 1500 token，session 还没开始就先付掉 30 K token 沉没成本。这一成本对偶尔使用的命令尤其不划算——/changelog-bump 一个季度才用一次，却天天占 context。


Codex 的 .codex/commands/*.md 走类似策略，OpenCode 的 .opencode/commands/*.md 也是。三家在 2025 年都没把命令纳入 progressive disclosure 经济模型——这个模型当时只用在 Anthropic 系统提示的某些动态段落里，没下沉到用户自定义命令。


第二个问题是字段表达力不够。私有命令格式只能声明 description 与可选 argument-hint，无法表达：


    

  • 这条命令该用哪个 model（critical 工作流需要 pin Opus）
    • 

  • 这条命令只能调哪些工具（安全敏感命令应该禁掉 Bash）
    • 

  • 这条命令是否允许 model 自动激活（敏感命令必须显式 explicit）
    • 

  • 这条命令是否在独立 context fork 里运行（隔离失败）
    • 



第三个问题是跨工具不可移植。同一个团队同时用 Claude Code 与 Codex 时，写好的 /review 命令在两边要维护两份，frontmatter schema 不同、参数语法不同、调用前缀不同。这种重复劳动在 2025 末越来越难接受。


Claude Code v2.1.101 的合并方案
Anthropic 在 2026-04-11 发布的 v2.1.101 changelog 给出三条核心规则。第一是同名优先：项目同时存在 .claude/commands/foo.md 与 .claude/skills/foo/SKILL.md 时，skill 优先生效，/foo 命令被路由到 skill；旧 commands 路径仍能加载未冲突的命令。第二是渐进披露下沉：commands 路径也开始按 progressive disclosure 处理，仅 description 入 context，body 在匹配后才注入；这让老 commands 文件零修改就获得了 token 经济收益。第三是双源 /help 列表：/help 输出区分"Commands"与"Skills"两个分组，但命令本身可以混用。


合并不是破坏式变更。社区里实际跑了几个月发现两个意外好处：一是老 commands 文件不需要立即迁移，团队可以按 frequency 排序逐个搬；二是 skill 形态的命令在跨工具复制时不再需要改路径——.claude/skills/refactor-extract/SKILL.md 直接复制到 Codex 项目下的 .agents/skills/refactor-extract/SKILL.md 就能工作。


为什么合并而不是新加一个 commands v2 格式
外部经常被问的一个问题：既然要解决 token 与表达力，为什么不直接给 commands 格式加 v2 schema？官方与社区讨论给出三条原因。


第一是减少标准数。Anthropic 团队明确表态过"agentic system 已经有太多概念"，再多一个 commands v2 会让用户在 skills / commands / agents / hooks / MCP 之间继续混淆。合并到 SKILL.md 让"过程性知识载体"只剩一个标准。


第二是跨工具压力。如果 Claude Code 独自演化 commands v2，Codex 与 OpenCode 不会跟，跨工具复用诉求永远落空。而 SKILL.md 已经在 2026 Q1 由 agentskills.io 推动成为开放规范（详见 ../../3_skills/3_cross-tool-interop/），三家都有动力对齐。


第三是功能完备。SKILL.md 在 frontmatter 已经支持 14+ 字段，commands v2 即便重设计也很可能收敛到同样的字段集；既然终点一样，不如直接复用。


Codex 与 OpenCode 的 2026 上半年对齐
Claude Code 合并后两个月内，Codex 与 OpenCode 也完成了类似演化，但合并程度与遗留路径策略各有不同。


Codex 在 2026Q2 引入 .agents/skills/ 中性路径与 walk-up 扫描机制。.codex/commands/*.md legacy 路径继续工作但 Codex 文档已经把它标记为 deprecated；新写命令一律走 .agents/skills/<name>/SKILL.md，配 agents/openai.yaml sidecar 表达 OpenAI 专属字段（具体见 ../2_per-tool-commands/2_codex-commands.md）。Codex 的特色是引入 implicit 调用——model 读 description 匹配 user prompt 自动激活，不需要打 / 前缀。


OpenCode 走多路径合并：.opencode/commands/ legacy + .opencode/skills/ 项目级 + .agents/skills/ 中性 + .claude/skills/ 兼容路径，四路径扫描去重；同名按 plugin > project > user > legacy 优先。OpenCode 的特色是 plugin-bundled commands——一个 plugin 可以一次注册多个 skill 并随 plugin 安装/更新（具体见 ../2_per-tool-commands/3_opencode-commands.md）。


陷阱与常见问题
合并落地过程社区遇到的高频坑有四个。


第一是双源命令同名冲突没意识到：.claude/commands/test.md 与 .claude/skills/test/SKILL.md 共存时 skill 优先，但 SKILL.md 内容如果不完整（比如 description 关键词与原命令对不上），用户输入 /test 会触发"错误的"那一个，看起来"命令逻辑变了"。修复方式是迁移时把旧 commands 内容彻底合到新 SKILL.md，旧文件删掉或重命名加 .bak 后缀。


第二是误以为 legacy commands 不再 progressive disclosure：v2.1.101 之后 commands 路径也按 description-first 加载，团队仍可继续用 .claude/commands/*.md，不必立刻迁。


第三是参数语法差异：legacy $ARGUMENTS 是单变量，新 Skill 用 $1 $2 多参数。迁移老命令时如果 body 里有 git log $ARGUMENTS 这种用法直接复制到 SKILL.md 不会报错但语义变了——需要改成 $1 或 $@（全部位置参数）。


第四是跨工具 frontmatter 字段不全兼容：Claude 独有的 context: fork、Codex 独有的 invocation_policy、OpenCode 独有的 instructions_provider 不通用；写一份 SKILL.md 想三家都跑通时，把工具专属字段放进 sidecar（Codex 的 agents/openai.yaml），保留 base SKILL.md 干净。


小结
    

  • Claude Code v2.1.101（2026-04-11）正式合并 .claude/commands/*.md 到 .claude/skills/，同名 skill 优先、老路径作为兼容保留
    • 

  • 合并核心动机是 progressive disclosure 下沉、frontmatter 表达力升级、跨工具 portability
    • 

  • Codex 在 2026Q2 走 .agents/skills/ walk-up 扫描，OpenCode 走四路径合并去重，两家都对齐 SKILL.md 标准
    • 

  • 老 commands 文件不必立刻迁移，可按 frequency 排序逐步走；迁移时注意 $ARGUMENTS 与 $1 的语义差异
    • 

  • 跨工具复用时把厂商专属字段放进 sidecar 而非 base SKILL.md，保 spec 干净
    • 

  • 下一篇 ./2_command-discovery-and-invocation.md 把"命令怎么被发现 / 怎么被调用"讲透
