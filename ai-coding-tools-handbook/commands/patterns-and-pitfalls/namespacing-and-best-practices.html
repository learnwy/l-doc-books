命名空间、版本 pin 与规模化最佳实践

团队命令到 20 + 数量后，扁平 /cmd-name 列表会变得难以发现、容易冲突、调试痛苦。本篇收尾两类规模化经验：先讲 namespacing 模式怎么按动作分组，再讲 model 版本 pin 避免 silent drift，最后把"slash command 是会花钱的 context 资源、不是免费 hotkey"这条经济学认知与 2026 实际发生的安全事件结合。所有建议对应三家工具 2026 Q2 主流行为。

核心概念

下表把规模化阶段的四个维度做对照——单人 / 团队（10 ~ 20 命令）/ 大规模（50 + 命令）。

维度 单人 团队 10 ~ 20 命令 大规模 50 + 命令
namespacing 不需要 推荐 <group>-<verb> 前缀 必须，配 plugin 分组分发
model pin 可选 推荐 critical 命令 pin 全部命令 pin 完整版本号
description budget 一般够 注意控制总长 强制按 1% context 预算管
review 流程 个人开发 PR + 字段 checklist CI 校验 + 安全扫描
第三方 plugin 自由用 团队 allowlist 必走内部 registry + advisory 订阅

下图按命令规模演化时的瓶颈与对应实践对应起来。

namespacing 模式：按动作分组
扁平 /cmd-name 在 20 + 命令时找命令变得困难——/help 列表一屏装不下、user 记不清是 /review 还是 /code-review 还是 /pr-review。社区惯例是按动作分组：


/refactor-rename-pattern        # 重构类
/refactor-extract-component
/refactor-inline-helper

/test-add-edge-cases            # 测试类
/test-gen-property-based
/test-coverage-gap

/db-migration-draft             # 数据库类
/db-query-optimize
/db-schema-diff

/pr-review-security             # PR 审阅类
/pr-review-perf
/pr-review-style
Claude Code 不支持目录嵌套 namespace——.claude/skills/refactor/rename/SKILL.md 不识别，必须用 - 分隔扁平表达：目录 .claude/skills/refactor-rename-pattern/，name 字段 refactor-rename-pattern，user 调用 /refactor-rename-pattern。Codex 支持目录嵌套（.agents/skills/refactor/rename-pattern/SKILL.md），OpenCode 必须 plugin manifest 显式声明 namespace。


跨工具复用建议用扁平 - 前缀，三家都识别。命名时第一个 - 前的 token 是 group（refactor / test / db / pr），剩下表达 verb + object。这种命名风格跟 npm 包 @scope/<group>-<verb> 类似，user /help 列表按字母序排时同 group 命令自动聚在一起，发现性立刻提升。


team-x 的内部规范可以更进一步——所有 team 内部命令前缀 tx-，避免与第三方插件命令冲突：/tx-refactor-rename / /tx-test-add-edge。


model 版本 pin：避免 silent drift
frontmatter 写 model: claude-opus 是 alias，2025 指向 v4.5、2026 指向 v4.7、未来某天 v5 发布后再次漂移。critical 命令（影响代码安全、写 production 配置、操作 git 历史）应该 pin 完整版本号：


# Claude Code 写完整版本
model: claude-opus-4-7-20260423

# Codex 在 openai.yaml 写完整版本
model_pin: gpt-5.5-20260205
完整版本号意味着 Anthropic 发布 v4.8 后该命令仍跑在 v4.7 上，行为绝对一致。代价是手动升级——团队定期（季度）评估是否升 pin 版本。


升级流程建议：


    

  • 新 model 发布后开 staging 项目，复制一份 critical 命令把 pin 改成新版本
    • 

  • 跑核心场景对比新旧 model 输出差异（diff 显著性、错误率、token 消耗）
    • 

  • 差异可接受时 batch 改所有 critical 命令的 pin、走 PR review
    • 

  • 上线后观察一周，确认无回退再删 staging 实验
    • 



非 critical 命令（一次性脚手架、低频探索类）保持 alias 没问题，alias 漂移带来的 quality 提升通常正向。


计费认知：slash command 不是免费快捷键
最常见的认知误区是把 slash command 当成 Unix shell alias——"打 /foo 就是 foo 的快捷写法，不付额外成本"。实际上 slash command 在三家工具里都有 context 成本：


    

  • session start 成本：description 始终入 system prompt，每个 skill 平均 100 token 在 1% context budget 里
    • 

  • 每轮 chat 成本：description 留在每轮 system prompt 里，每轮都重新计入 token 计费
    • 

  • 激活成本：命令 body 在匹配后注入 chat，body 越长每次调用付的 token 越多
    • 



20 个 skill 的 description budget 大约 2K token，按 sonnet $3/MTok 算每 session 0.6 美分——单看不贵，但 1000 个 active session 就是 6 美元。50 个 skill 时 description budget 接近 budget 上限，超出后按字母序截尾——尾部 skill 在 implicit 路径完全失效。


控制成本的实战做法：


    

  • 定期审计 active skill：每月清查一次半年没用过的 skill，加 disable-model-invocation: true 或挪到 archived 目录
    • 

  • description 控长：单个 description 控制在 80 ~ 120 token，过长会挤占其它 skill 预算
    • 

  • body 拆 references：长 prompt body 抽到 references/ 按需读，主 SKILL.md 控在 200 行内
    • 

  • measure first：跑 claude code --token-stats 看 session 实际消耗，按数据决定剪哪些 skill
    • 



安全审计：2026 已发生事件与防护
2026 已经发生两起公开 skill registry 投毒事件值得团队警惕。


事件一（2026-03）：公开 skill registry ClawHub 上一个 git-cleanup skill 被植入恶意 !command——执行时偷偷把 ~/.ssh/id_rsa 通过 curl 上传到攻击者服务器。下载量过百时被发现，registry 紧急下架并发 advisory。


事件二（2026-04）：OpenCode plugin @some-team/dev-tools 在 v1.4.2 版本 instructions_provider.js 加入隐蔽数据回传——所有 user prompt 被复制一份发送到第三方分析服务。


这两起事件揭示 SKILL.md 范式的核心风险：skill body 内 !command 与 scripts/ 可执行任意代码，公开 skill 安装前必走 review。落地建议：


    

  • 公开 skill 走 allowlist：团队维护一份 trusted source 列表（agentskills.io 官方 + 已审计 vendor），不在 list 上的 plugin 不允许安装到团队项目
    • 

  • 第三方 plugin 按 npm 风险等级处理：subscribe agentskills.io/advisory RSS、定期跑 opencode plugin audit 类工具扫已知漏洞
    • 

  • CI 校验 frontmatter：team 内部 CI 拒绝包含 !command 且非 trusted source 的 skill 进入主分支
    • 

  • 生产命令开 disable-model-invocation：production 关键命令禁 implicit 调用，user 必须显式 explicit——避免恶意 description 关键词诱导 model 自动激活
    • 



agentskills.io 在 2026 上线 advisory 入口 agentskills.io/advisory，类似 npm audit + CVE database，团队应订阅。


陷阱与常见问题
第一是 namespace 前缀不一致：团队约定 tx- 前缀但有人写 team-x- 有人写 tx_，namespace 失去意义；CI 加 lint 规则强制 ^tx-[a-z-]+$ 命名。


第二是 model pin 过细导致 cascade 升级：100 个 skill 全部 pin 同一 model 版本，升级时一次性改 100 个文件 PR 极其臃肿；分批升、按 priority 排序，high-priority 命令先升、low-priority 跟随。


第三是 description budget 撑爆但无报错：超 budget 的 skill 按字母序砍尾，被砍的 skill /skills 列表仍显示但 implicit 不工作；调试用 --debug-skills 看实际入 context 的 skill 列表。


第四是 第三方 advisory 订阅忘了关注：installed plugin 发布安全更新后团队没及时升级，漏洞窗口持续数周；CI 加自动化检查 outdated-plugins 周报。


小结
    

  • namespacing 用扁平 - 前缀按动作分组（/refactor- / /test- / /db- / /pr-），团队内部前缀避免与第三方冲突
    • 

  • critical 命令 pin 完整 model 版本号（claude-opus-4-7-20260423 / gpt-5.5-20260205），定期 staging 验证升级
    • 

  • slash command 不是免费 hotkey：description 占 1% context budget，每月清查闲置 skill 保 budget 不撑爆
    • 

  • 2026 已发生 ClawHub + OpenCode plugin 两起投毒事件，公开 skill 走 allowlist、订阅 agentskills.io/advisory、CI 校验 frontmatter
    • 

  • 与范式决策框架结合见上一篇 ./1_skill-vs-command-paradigm.md
    • 

  • 跨工具 portable 实现细节回到 ../../3_skills/3_cross-tool-interop/
    •
