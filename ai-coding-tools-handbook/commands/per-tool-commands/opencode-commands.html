OpenCode 命令体系：多路径互通与 plugin-bundled

OpenCode 作为开源工具，命令体系设计上比 Claude 与 Codex 都更"杂食"——同时扫描四条发现路径、与 Claude Code skill 二进制兼容、支持 plugin-bundled 一次注册多个 skill、独有 instructions provider plugin 让命令随 agent 模式动态切换。理解这套灵活性能直接解释为什么 OpenCode 在多工具混合团队里常被当作"中性 hub"——别人写好的 skill 它都能跑。

核心概念

下表把 OpenCode 与 Claude / Codex 在路径策略、bundled、热加载维度做对比。

维度 Claude Code Codex OpenCode
主路径 .claude/skills/ .agents/skills/（walk-up） .opencode/skills/
兼容路径数 1（legacy commands） 1（.codex/commands/） 3（.agents/skills/ + .claude/skills/ + .opencode/commands/）
plugin 注册 skill 不支持 不支持 支持（plugin.json 声明）
热加载 重启 session 重启 session plugin 文件 touch 即生效
instructions provider 不支持 不支持 支持（agent 切换动态变 skill 列表）
与 Claude skill 兼容 自身实现 通过 .agents/skills/ 中性路径 直接读 .claude/skills/ 二进制兼容

下图展示 OpenCode session start 时四条发现路径如何合并去重。

四条发现路径并存
OpenCode 同时扫描以下四条路径（按优先级从高到低）：


    

  • plugin-bundled：通过 plugin.json 声明的 skill 列表，由 plugin 注册流程注入
    • 

  • .opencode/skills/<name>/SKILL.md：项目级专属 skill
    • 

  • .agents/skills/<name>/SKILL.md：中性路径，跨工具共享
    • 

  • .claude/skills/<name>/SKILL.md：兼容路径，直接复用 Claude 项目
    • 

  • .opencode/commands/<name>.md：legacy 格式，仍工作但 deprecated
    • 



合并去重逻辑是同名 skill 按优先级取高的版本。例如 plugin 注册了 pr-review 且 .opencode/skills/pr-review/SKILL.md 也存在时，plugin 版本生效，项目级被忽略。这种设计避免用户随便复制覆盖团队 plugin 基建，但也意味着想 override plugin 必须改名（比如 pr-review-local）。


OpenCode 跟 Claude skill 是二进制兼容——.claude/skills/<name>/SKILL.md 直接放进 OpenCode 项目可工作，无需任何转换。这种兼容是策略层选择：OpenCode 文档明确写"if it works in Claude Code, paste it here unchanged"，目标是降低多工具团队的迁移成本。代价是 Claude 专属 frontmatter 字段（如 context: fork）OpenCode 可能不实现但也不报错——静默忽略。


plugin-bundled commands
OpenCode 独有的 plugin 体系让一个 plugin 可以一次注册多个 skill。plugin.json 示例：


{
  "name": "@team-x/coding-skills",
  "version": "1.2.3",
  "skills": [
    {
      "name": "pr-review",
      "path": "skills/pr-review/SKILL.md"
    },
    {
      "name": "refactor-extract",
      "path": "skills/refactor-extract/SKILL.md"
    },
    {
      "name": "test-gen-edge",
      "path": "skills/test-gen-edge/SKILL.md"
    }
  ],
  "instructions_provider": "./providers/agent-aware.js"
}
plugin 安装后 OpenCode 自动注册这三个 skill。plugin 文件 touch（修改时间戳更新）即触发重新加载——不需要重启 OpenCode session。这对开发 skill 时反复调试很友好：改完 SKILL.md 文件保存，下一轮 chat 立刻用上新版本。


plugin 也是团队批量分发命令的主要途径。team-x 维护 @team-x/coding-skills 包，所有团队成员 opencode plugin add @team-x/coding-skills 后自动获得统一命令集；version bump 后 opencode plugin update 同步。这比 git submodule 共享 .claude/skills/ 体验好很多——后者每次更新都得 git pull 还得手动 reload。


instructions provider 与 agent-aware skill 列表
OpenCode 还有个"plugin = hook 实现方式"哲学的具体落地：instructions provider plugin。


instructions provider 是一个 JS 文件，OpenCode 在 agent 切换时调用它返回当前应该激活的 skill 列表。典型用法：plan agent 模式下只激活规划类 skill（scope-decompose / risk-assess / acceptance-criteria-draft），build agent 模式下只激活实现类 skill（refactor-extract / test-gen-edge / pr-review）。这样 description budget 在每个 agent 模式下都只装当下相关的 skill，不浪费 token 在不相关的命令上。


这套机制是 OpenCode 的差异化能力——Claude / Codex 都是"一次加载全部 skill 直到 session 结束"，OpenCode 让 skill 列表跟随 agent 模式动态变化。对大型团队 30+ skill 的场景特别有价值。


与 Claude Code skill 的二进制兼容验证
社区做过对比实验：把 Claude .claude/skills/test-suite/SKILL.md 整目录复制到 OpenCode 项目下相同路径，运行 opencode /test-suite 触发命令，行为与 Claude Code 完全一致。frontmatter 中的 description / model / tools / argument-hint / allowed-tools 均生效；context: fork 等 Claude 独有字段被静默忽略但不报错。


兼容性的反方向也工作：OpenCode .opencode/skills/foo/SKILL.md 复制到 Claude .claude/skills/foo/SKILL.md 也能跑，前提是 frontmatter 不依赖 OpenCode 独有字段（instructions provider 函数引用等）。


跨三家 portable 的最干净写法见 ../../3_skills/3_cross-tool-interop/：base SKILL.md 只用三家共有字段，厂商专属字段放 sidecar。


陷阱与常见问题
第一是同名 skill 优先级颠倒：用户在 .opencode/skills/pr-review/SKILL.md 写了"个人定制版"，却被 plugin 注册的同名 skill 覆盖；调试时 opencode skills list --source 显示每条 skill 来源；想 override plugin 必须改名。


第二是 .claude/skills/ 兼容路径默认开启：克隆别人的 Claude Code 项目跑 OpenCode 时，Claude 项目的所有 skill 都自动加载——可能装入大量不相关命令撑爆 description budget。配置文件里设 discovery.claude_compat: false 关掉这条路径。


第三是 plugin 热加载不覆盖配置文件：touch SKILL.md 自动重载，但 plugin.json 或 instructions_provider.js 改动需要 opencode plugin reload 显式触发。


第四是 instructions provider 抛异常：provider JS 报错时 OpenCode 不显示错误信息只静默 fallback 到全量 skill；调试用 opencode --debug-provider 看异常堆栈。


小结
    

  • OpenCode 四路径并存：.opencode/skills/ + .agents/skills/ + .claude/skills/ + .opencode/commands/，按 plugin > project > user > legacy 优先
    • 

  • 与 Claude Code skill 二进制兼容，复制粘贴即用；跨工具 portable 写法见 ../../3_skills/3_cross-tool-interop/
    • 

  • plugin-bundled 通过 plugin.json 一次注册多个 skill，touch 文件即热加载、不需重启
    • 

  • instructions provider plugin 让 skill 列表随 agent 模式（plan/build）动态变化，节省 description budget
    • 

  • 调试用 opencode skills list --source 看每条 skill 来源，关闭 .claude/skills/ 兼容路径用 discovery.claude_compat: false
    •
