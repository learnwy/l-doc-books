Codex 命令体系：implicit 双轨调用与 openai.yaml sidecar

Codex 在 2026 上半年完成 commands→Skills 对齐，但走的路径与 Claude 不同。它把命令文件放在中性目录 .agents/skills/、走 walk-up 扫描、引入 implicit/explicit 双轨调用、用 agents/openai.yaml sidecar 表达 OpenAI 专属字段。理解这套设计能解释为什么 Codex 命令"看起来很像 Claude skill 但又不完全一样"——base SKILL.md 跨工具可移植，sidecar 装厂商专属。

核心概念

下表把 Codex 与 Claude 命令体系在四个关键维度做对比。

维度 Claude Code Codex
主路径 .claude/skills/<name>/SKILL.md .agents/skills/<name>/SKILL.md
扫描策略 严格 cwd walk-up 到 git repo root
调用模式 explicit /name 为主 implicit + explicit + hybrid
厂商扩展位置 frontmatter 字段（context: fork 等） agents/openai.yaml sidecar
安全模型 allowed-tools approval_policy + sandbox_mode
project .codex/ 不适用 默认不读（untrusted-projects 策略）

发现路径与 walk-up 扫描
Codex 主路径是 .agents/skills/<name>/SKILL.md，使用 agentskills.io 推动的中性目录，目标是同一份命令文件能直接在 OpenCode 与 Claude Code 复用（详见 ../../3_skills/3_cross-tool-interop/）。.codex/commands/<name>.md 作为 legacy 路径继续工作但官方文档已标记 deprecated，新写命令一律去 .agents/skills/。


walk-up 扫描从 cwd 一路向上找直到 git repo root（或文件系统根），途中每一层只要存在 .agents/skills/ 就纳入扫描合并。monorepo 里 packages/foo/ 子项目运行 codex 时，根目录 .agents/skills/ 与子项目本地 .agents/skills/ 都会被发现，子项目级同名覆盖根级。


walk-up 有个安全约束：Codex 默认不读 project 级 .codex/ 目录——untrusted-projects 策略假设父目录可能藏恶意命令文件。要让 project 级 .codex/ 生效需要 codex trust-project 把当前 cwd 加入信任列表。.agents/skills/ 不受这个约束（设计哲学上是"中性 portable 路径，团队 review 过的"）。


implicit / explicit / hybrid 三种调用
Codex 是三家工具里 implicit 机制最完整的。openai.yaml 的 invocation_policy 字段控制每个 skill 的调用模式。


# agents/openai.yaml (与 .agents/skills/pr-review/SKILL.md 配套)
skills:
  pr-review:
    invocation_policy: auto # auto / manual / hybrid
    display_name: PR Reviewer
    approval_policy: read-only # read-only / read-write / full-access
    sandbox_mode: workspace # workspace / network / unrestricted
    mcp_servers: [github]
    model_pin: gpt-5.5-20260205
    

  • auto：model 读 description 匹配 user prompt 关键词自动激活，无需 user 输入命令名
    • 

  • manual：必须 user 输入 $pr-review 显式触发，model implicit 触发被禁
    • 

  • hybrid：默认允许 implicit，但激活前提示 user 确认（适合 sensitive 命令）
    • 



切到 hybrid 的典型场景是"频繁但敏感"——比如 db-migration-generate 想被关键词激活方便使用，又不想 model 在没确认时直接生成迁移脚本。


openai.yaml sidecar 设计哲学
为什么不把 invocation_policy、approval_policy、sandbox_mode 这些字段直接放进 SKILL.md frontmatter？原因是这些字段是 OpenAI 专属语义，把它们放进 base spec 会让跨工具复用变难——Claude / OpenCode 看到这些字段必须忽略或报错，造成 spec 污染。


sidecar 方案让 base SKILL.md 保持干净跨工具 portable，OpenAI 专属配置另放一个文件。Codex 加载顺序是先读 .agents/skills/<name>/SKILL.md 拿 description / model / tools 等通用字段，再合并读 agents/openai.yaml 拿专属字段，两者拼成最终 skill metadata。


这套设计的代价是团队需要维护两个文件、读 SKILL.md 时还得跟 sidecar 对照。社区有声音建议未来把 sidecar 改成 frontmatter 下的 vendor.openai: 命名空间块，但 2026Q2 主流仍是分文件。


安全模型：approval_policy 与 sandbox_mode
Codex 的两个安全字段在 openai.yaml 表达。


approval_policy 控制命令对文件系统的写权限：


    

  • read-only：只允许 Read / Bash 只读命令，写操作触发 user approval
    • 

  • read-write：允许 Edit / Write 工作区文件，工作区外写触发 approval
    • 

  • full-access：所有写操作不需 approval（仅 trusted 项目用）
    • 



sandbox_mode 控制命令的执行隔离：


    

  • workspace：限制在当前 cwd 子树，禁网络（除显式 MCP server）
    • 

  • network：允许网络但禁工作区外文件
    • 

  • unrestricted：全访问（仅 trusted）
    • 



两个字段独立组合表达 9 种安全姿态。绝大多数命令应该 read-only + workspace，需要写代码的命令 read-write + workspace，需要 npm install 等网络访问的命令 read-write + network。unrestricted 应该极少用——审计日志会持久记录每次启用。


触发命令时如果实际操作超过 approval_policy 允许的级别，Codex 会暂停执行弹出 user approval prompt（CLI 显示，user 输入 yes/no）。这跟 Claude Code 的 hook 机制不同——hook 是事件回调，approval 是阻塞式 prompt。


陷阱与常见问题
第一是 untrusted-projects 阻止 .codex/ 不易察觉：克隆别人的项目运行 codex 时 .codex/commands/ 完全静默不加载，user 调用 /foo 报 unknown command；解决方案是 codex trust-project 或把命令移到 .agents/skills/（中性路径不受信任约束）。


第二是 walk-up 扫描"找错父目录"：在非 git 仓库目录运行时 walk-up 会一直走到 /，可能扫到 ~/.agents/skills/ 等共享目录里的命令；调试时跑 codex skills --list-paths 查看实际扫描到的所有目录。


第三是 sidecar 与 SKILL.md name 不一致：agents/openai.yaml 用 skills.pr-review key 但 SKILL.md 的 name: 写成 pr-reviewer 时 sidecar 不生效——必须 key 与 name 完全一致。


第四是 model_pin 写错版本字符串：gpt-5.5-20260205 是合法的版本 pin，写成 gpt-5.5 会被解析为 alias 漂移；critical 命令应该用完整版本号。


小结
    

  • Codex 主路径 .agents/skills/<name>/SKILL.md，walk-up 到 git repo root，legacy .codex/commands/ 仍可用但 deprecated
    • 

  • agents/openai.yaml sidecar 装 OpenAI 专属字段（invocation_policy / approval_policy / sandbox_mode / mcp_servers / model_pin），保 base SKILL.md 干净跨工具 portable
    • 

  • 调用模式有 auto / manual / hybrid 三种，安全敏感命令用 hybrid 在 implicit 与 user 确认之间平衡
    • 

  • approval_policy（写权限）与 sandbox_mode（隔离）正交组合 9 种安全姿态，工作区写代码常用 read-write + workspace
    • 

  • 跨项目调试用 codex skills --list-paths 看扫描了哪些目录，codex trust-project 解除 untrusted-projects 限制
    • 

  • 下一篇 ./3_opencode-commands.md 讲 OpenCode 的多路径互通与 plugin-bundled 模式
    •
