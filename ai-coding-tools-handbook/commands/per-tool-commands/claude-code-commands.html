Claude Code 命令体系：legacy commands 与 Skills 合并实现

Claude Code 是 commands→Skills 合并的发起者，也是 reference implementation。v2.1.101（2026-04-11）之后，.claude/commands/ 与 .claude/skills/ 两个目录并存、同名时 skill 优先、/help 显示双源列表。理解这套兼容性设计有两个收益：旧团队的命令文件不必立即迁移就能享受 progressive disclosure；想充分利用 frontmatter 14+ 字段的团队可以把新命令直接以 Skill 形态写。

核心概念

下表把 Claude Code 的两种命令形态做正交对比。

维度 legacy .claude/commands/<name>.md 新形态 .claude/skills/<name>/SKILL.md
文件布局 单个 .md 文件 目录 + SKILL.md + 可选 references/ scripts/
参数捕获 $ARGUMENTS（单变量，整串注入） $1 $2 $@（多参数 + 全量）
frontmatter 字段 description / arguments / model / tools description / model / tools / allowed-tools / disable-model-invocation / user-invocable / context: fork / argument-hint
progressive disclosure v2.1.101 后也支持（description-first） 原生支持
运行时显示 /help Commands 分组 /help Commands 分组 + /skills 列表
跨工具复用 不可移植 可直接复制到 .agents/skills/ 给 Codex / OpenCode 用

legacy commands 的 $ARGUMENTS 参数捕获
legacy 格式只有一个参数变量：$ARGUMENTS。它把 user 在命令名后输入的整串文字（含空格）原样注入到命令 body 的 $ARGUMENTS 占位符。例如 .claude/commands/review.md 内容：


---
description: 审阅指定 git ref 的所有 diff
arguments: <git-ref>
---

请审阅以下 git ref 的所有 diff 并给出改进建议：$ARGUMENTS

重点检查：

1. 命名清晰度
2. 错误处理完备性
3. 测试覆盖
user 输入 /review feature/auth-rework 后，$ARGUMENTS 被替换成 feature/auth-rework，整段 prompt 加完整 body 送给 model。这种单变量设计简单但有两个限制：一是无法区分多个参数（"审 PR + 重点关注 security" 必须 user 自己在 prompt 里组织），二是没有 type/hint 帮 user 写对参数。


Skill 形态的多参数与 argument-hint
新 Skill 形态支持 $1 $2 等位置参数与 $@ 全部参数，配 frontmatter 的 argument-hint 字段做自动补全提示。


---
name: review
description: 审阅指定 git ref 的 diff，可选 focus 维度（security/perf/style）
argument-hint: <git-ref> [focus]
allowed-tools: [Read, Bash(git diff:*), Bash(git log:*)]
model: claude-opus-4-7-20260423
---

请审阅 `$1` 的所有 diff。

$2 关键词存在时按这个维度重点检查：
- security: 鉴权 / 输入校验 / 注入风险
- perf: 复杂度 / 缓存 / IO
- style: 命名 / 注释 / 一致性

默认（$2 为空）覆盖全部维度。
user 输入 /review feature/auth-rework security 后，$1 = feature/auth-rework、$2 = security、$@ = feature/auth-rework security。argument-hint 在 user 输入 /review 后按 Tab 触发补全提示语 " [focus]"，帮助记住参数顺序。


$1 与 $ARGUMENTS 的语义差异是迁移老命令时最容易踩的坑：直接把 git log $ARGUMENTS 复制到新 SKILL.md 里，user 输入 /review feature/auth-rework security 时 $ARGUMENTS 不再是单变量、整段 prompt 内不会自动展开；需要改成 git log $1 或 git log $@（取决于到底想要单参数还是全部参数）。

legacy 单字段语义





context: fork 是 Skill 独有的能力。普通调用共享主 chat 的 context（命令执行完成后产生的输出留在历史里）；fork context 让命令在隔离副本里运行，结果通过主进程拿回但不污染 chat 历史。这对"产生大量中间输出但只想要最终结果"的命令很有用，比如 /run-benchmark 跑完只保留最终数字。


运行时：/help 与 /skills 命令的关系
session 中两个内置 slash command 用来查看可用命令列表：


    

  • /help 列出所有可用命令，按 "Commands"（来自 .claude/commands/ 或同名优先后被路由的 skill）、"Built-in Slash Commands"（/clear / /compact / /skills 等）两组显示
    • 

  • /skills 只列 .claude/skills/ 下的 Skill 类命令，显示 name + description + allowed-tools 摘要
    • 



两个命令信息有重叠但不等价——一个 Skill 会同时出现在 /help 与 /skills 里；一个 legacy commands 只出现在 /help。这种双重显示是过渡期产物，未来 Anthropic 可能简化为单一列表。


/clear 重置 chat context，但不重置 skill 加载状态——已加载的 skill 还在 description budget 里。想真正重置 skill 状态需要 /clear --hard 或重启 session。


陷阱与常见问题
第一是 $ARGUMENTS 复制粘贴语义变了：迁移老命令时 body 内的 $ARGUMENTS 直接复制到 SKILL.md 不会报错但行为变——$ARGUMENTS 在 Skill 形态不被识别为变量，会被当成字面字符串。修复是迁移时一律改成 $@ 或 $1。


第二是 allowed-tools glob 写错：allowed-tools: [Bash(git)] 不是合法 glob，正确写法 Bash(git:*) 或 Bash(git diff:*)；写错时 user 调用会报"tool not in allowlist"。


第三是 model 字段写 alias 而非具体版本：model: claude-opus 在 2026 上半年默认指向 v4.6，但 v4.7 发布后可能漂移到 v4.7；critical 命令应该 pin claude-opus-4-7-20260423 这种完整版本号防 silent drift。详细见 ../3_patterns-and-pitfalls/2_namespacing-and-best-practices.md。


第四是 disable-model-invocation: true 后忘记 /cmd-name 仍可用：该字段只禁 implicit，不禁 explicit；想完全禁需要 user-invocable: false。


小结
    

  • Claude Code v2.1.101 后 .claude/commands/ 与 .claude/skills/ 双路径并存，同名 skill 优先
    • 

  • legacy $ARGUMENTS 是单变量，Skill 形态用 $1 $2 $@ 多参数 + argument-hint 补全
    • 

  • frontmatter 共有 description / model / tools；Skill 独有 allowed-tools / disable-model-invocation / user-invocable / context: fork / argument-hint
    • 

  • /help 列双源命令，/skills 只列 Skill；/clear 不重置 description budget
    • 

  • 迁移老命令最大坑在参数语法差异与 model 版本 pin，详细策略见 ../3_patterns-and-pitfalls/1_skill-vs-command-paradigm.md
    • 

  • 下一篇 ./2_codex-commands.md 讲 Codex 的 implicit/explicit 双轨与 openai.yaml sidecar
