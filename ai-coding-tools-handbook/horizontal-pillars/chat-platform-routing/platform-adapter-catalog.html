主流 chat platform 适配清单

核心概念

OpenClaw 把"多个 chat platform 当成统一 agent 工作台"的前提是：在 inbound / outbound 两个方向上，五种主流 chat platform 的 API 形态有大量差异——OAuth 流程、webhook vs long-poll、message schema 字段命名、rate limit 颗粒度。这些差异不能在路由层抹掉，必须先在 adapter 层抽象出一个统一的 Message / Event / Action 模型。本篇按"五个平台横向对照 + adapter 抽象 + rate limit 对比"三块讲清，路由 DSL 走 ./2_routing-rules-syntax.md。

飞书 Open API：bot 与 user 双身份
飞书 Open API 是国内 personal-agent 工具栈最常 anchor 的平台。它把"应用"分两种 token：tenant_access_token（bot 身份，按租户授权）与 user_access_token（user 身份，OAuth code 兑换）。OpenClaw 同时使用两种——bot 用于自动回复 / webhook 接收，user 用于代用户读消息历史 / 发送以用户身份的回复。


lark_adapter:
  app_id: 'cli_xxx'
  app_secret: '****'
  tenant_token_endpoint: '/open-apis/auth/v3/tenant_access_token/internal'
  user_oauth_endpoint: '/open-apis/authen/v1/access_token'
  webhook_path: '/lark/webhook'
  events:
    - 'im.message.receive_v1'
    - 'im.chat.member.user.added_v1'
飞书 webhook 签名采用 X-Lark-Signature HMAC-SHA256 校验，payload 包含 header.event_type 与 event.message 两层；adapter 把 message.message_id 映射到统一 Message.id，把 chat_id 映射到 Message.channel_id。


Slack Bolt SDK：events API + 双 socket
Slack 官方推荐 Bolt SDK（Node / Python / Java 三种 binding）。它统一了 events API（HTTP webhook）与 socket mode（WebSocket，避免开放公网入口）。OpenClaw 默认采用 socket mode——personal-agent 通常运行在本地或 NAT 后的机器上，没有稳定公网 HTTPS。


const app = new App({
  token: process.env.SLACK_BOT_TOKEN,
  appToken: process.env.SLACK_APP_TOKEN,
  socketMode: true,
});

app.message(async ({ message, say }) => {
  const unified = adapter.toMessage(message, 'slack');
  const persona = await router.resolve(unified);
  await persona.handle(unified, say);
});
Slack 把 channel 分为 public_channel / private_channel / mpim / im 四种，schema 在 channel_type 字段反映；DM 走 im，私聊群走 mpim——adapter 把这四种归并到统一 Message.channel.kind。


Telegram Bot API：long-poll 优先
Telegram Bot API 是最轻量的一档：单一 token、单向 API、文档极简。两种实时模式：getUpdates long-poll（默认）或 setWebhook（需要 HTTPS 公网）。OpenClaw 选 long-poll 路径——personal-agent 部署门槛低，long-poll 在 chat 体量小时延迟可控（< 1 秒）。


def poll_loop():
    offset = 0
    while True:
        resp = requests.get(
            f"https://api.telegram.org/bot{TOKEN}/getUpdates",
            params={"offset": offset, "timeout": 30},
            timeout=35,
        )
        for upd in resp.json()["result"]:
            offset = upd["update_id"] + 1
            adapter.dispatch(upd)
Telegram 的 message schema 在 update.message 里：chat.id 是负数表示群、正数表示 1:1；adapter 用符号位推断 channel kind。它不支持 user 身份——所有发送都是 bot。这是 personal-agent 在 Telegram 上的硬限制：用户无法以"自己的身份"发消息，只能用 bot 代理。


Discord.js gateway：interaction-based
Discord 的 API 范式与前三家不同——以 gateway WebSocket 推送事件为主，HTTP 仅用于 reply / fetch。Discord.js 是 Node 上事实标准 SDK。OpenClaw 适配 Discord 时关注三件事：guild（服务器）层级权限、slash command interaction、ephemeral reply（只发送者可见）。


const { Client, GatewayIntentBits } = require('discord.js');
const client = new Client({
  intents: [
    GatewayIntentBits.Guilds,
    GatewayIntentBits.GuildMessages,
    GatewayIntentBits.MessageContent,
    GatewayIntentBits.DirectMessages,
  ],
});

client.on('messageCreate', async (msg) => {
  if (msg.author.bot) return;
  const unified = adapter.toMessage(msg, 'discord');
  await router.dispatch(unified);
});
Discord 的 guild_id + channel_id 形成两级嵌套，adapter 把 guild_id 映射到统一 Message.parent_id（对应路由 lookup 第 2 级 parent rule）。


Matrix protocol：联邦 + E2E 加密
Matrix 是五者中唯一联邦协议——没有单一中央服务器，每个 homeserver 独立运营，房间在多个 homeserver 间同步。它支持 end-to-end 加密（Olm/Megolm），personal-agent 接入时必须维护 device key 与 session key 储存。

OpenClaw 的 outbound queue 在 adapter 层做 token-bucket，按平台不同配置。Discord 的 per-bucket rate limit 由 X-RateLimit-Bucket header 标识，比其他平台复杂——adapter 需要解析 header 并动态调整 bucket 计数。


陷阱与常见问题
    

  • 以为 Telegram 支持 user 身份：Bot API 不支持。需要 user 身份的场景必须改用 MTProto（telethon / Pyrogram），但风险更大且违反 ToS。
    • 

  • 飞书 webhook 签名忘记校验：直接信任 payload 会被伪造请求触发 persona action。X-Lark-Signature 必须校验。
    • 

  • Slack socket mode 与 events API 同时启用：会导致双重投递。生产二选一。
    • 

  • Discord intents 漏开 MessageContent：Discord 2022 后默认不发送 message content，必须 verified bot 申请 intent；adapter 启动检查必须读取 intents 配置。
    • 

  • Matrix E2E key 丢失：device key 储存损坏后历史消息永远无法解密。adapter 应定期备份 session keys 到加密文件。
    • 

  • Rate limit 未做 retry：直接报错会让 OpenClaw 漏消息。adapter 必须对 429 + retry-after 做指数回退。
    • 



小结
五种主流 chat platform——飞书 / Slack / Telegram / Discord / Matrix——在 OAuth 流、实时通道、message schema、rate limit 四个维度都有差异。OpenClaw 用 adapter 层把这些差异收敛到统一 Message / Action 模型，router 与 personas runtime 才能跨平台工作。adapter 的核心责任是 schema 翻译 + 实时通道维护 + rate limit 队列；身份模型差异（飞书 / Slack 支持双身份、Telegram bot-only、Discord bot-only、Matrix user-only）反过来影响 personal-agent 在该平台能做什么。下一篇讲路由规则 DSL 如何把统一 Message 映射到正确 persona。
