七后端横向对比

核心概念

Hermes 与 OpenClaw 都把"用什么 terminal 跑 agent"作为一个显式选项——七种主流终端（macOS Terminal / iTerm2 / Ghostty / kitty / wezterm / tmux / WSL）在 TUI 能力、键位、性能、平台覆盖上有显著差异。这些差异直接决定 agent UX：Kitty keyboard protocol 不支持就用不了 Shift+Enter 多行输入、truecolor 不支持就显示成模糊的 256 色、cold start 慢就让"开新 session"变成痛点。本篇按"四轴评估 + 平台覆盖 + 性能基准 + 推荐场景"四块讲清，安全模型走 ./2_security-and-isolation-model.md。

tmux 的特殊地位
tmux 不是终端 emulator——它是 multiplexer，跑在某个 emulator 之内。它的价值是"在远端持久化 session"——SSH 断了 session 不丢。Personal-agent 常用 agent + tmux 模式：tmux 提供 detach/attach，agent 在 tmux session 内跑长期任务。


tmux 在 TUI / 颜色支持上是"透传"——它本身不渲染，把 host 的能力透传给应用，需要正确配置 terminal-overrides：


# ~/.tmux.conf
set -g default-terminal "tmux-256color"
set -ga terminal-overrides ",*256col*:Tc"        # truecolor 透传
set -ga terminal-overrides ",*:Smol=\\E[53m"     # csi-u 透传
这套配置缺一项就让 host 的能力被 tmux "降级"——常见症状是 truecolor 配色突然变成 256 量化。


WSL 与 host 的关系
WSL 是 Windows 上的 Linux 子系统，agent 跑在 WSL 里时其终端体验完全取决于 host：Windows Terminal（微软默认）、wezterm、Alacritty 等。WSL 自己无 GUI——它把 stdio 接到 host 的 pty。所以"WSL 后端"严格说是"host + WSL"的组合：

要在 WSL 上获得最佳 personal-agent 体验，host 应选 wezterm 或 Windows Terminal 1.18+。


陷阱与常见问题
    

  • macOS Terminal 配置不全：默认无 truecolor、无 Kitty protocol——personal-agent 在此运行 UX 多处降级。除非有强约束（如公司管控只允许系统应用）应避免。
    • 

  • iTerm2 Shift+Enter 默认未配：必须手动到 Profile Keys 添加 Send Escape Sequence: \r——新用户常踩。
    • 

  • tmux terminal-overrides 漏 :Tc：truecolor 配色被 quantize 成 256 色——agent 输出明显失真。
    • 

  • WSL 用 cmd.exe 当 host：Windows 默认 cmd.exe 几乎无 modern 能力——必须迁到 Windows Terminal 或 wezterm。
    • 

  • Ghostty 配置只能在 macOS / Linux 测试：Windows 支持还在计划中，跨平台需求当前选 wezterm。
    • 

  • 远程 SSH 直接 ssh 不开 tmux：网络抖动断 session 丢上下文。SSH 内开 tmux 几乎是 personal-agent 远程使用的硬要求。
    • 



小结
7 种终端在 TUI / 颜色 / 键位 / 平台四轴上呈"两个时代分布"：旧时代（macOS Terminal）只满足基本需要；新时代（Ghostty / kitty / wezterm / iTerm2）支持 Kitty keyboard protocol + truecolor + GPU 加速。tmux 是 multiplexer 不是 emulator，价值在 session 持久化；WSL 不是终端，是 Windows 上的 Linux 子系统。推荐：日常 macOS 选 Ghostty、需重度自定义选 iTerm2、跨平台选 wezterm、远程 SSH 必配 tmux。下一篇深入各后端的安全模型与进程隔离差异。
