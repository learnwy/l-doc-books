大小纪律与 lazy-load 陷阱

写得多 ≠ 模型遵守得多。提示文件最反直觉的两个失败模式：装太多 和 写了不加载——前者超出 LLM 可靠遵循的 instruction 上限，后者把规则放进 subdir 却从未触发 lazy-load。

提示文件落地中最常被忽略的两个事实：（一）前沿 LLM 在 prompt 长度上有 可靠遵循的天花板——研究与实证显示约 150-200 条 instruction 之后开始系统性遗漏；（二）Claude Code / Codex / OpenCode 各自的"按需加载"策略带来不同的失败模式，特别是 Claude Code subdir CLAUDE.md 的 lazy-load 与 path-scoped rules 的 globs 校验。本文把这两类陷阱讲透并给出可验证的规避方案。

Size Discipline：150-200 Instruction 上限
业界对 LLM "可靠遵循 instruction 数量"做过多次实证：Anthropic、OpenAI、Google DeepMind 在 2024-2025 各自发布的 instruction-following benchmark 都指向同一区间——约 150-200 条之后开始系统性遗漏，越靠近末段越严重。Claude Code 自家 system prompt 已占用约 50 条 instruction（工具说明、安全约束、输出格式），留给 CLAUDE.md / AGENTS.md 的实际可用预算约 100-150 条。


经验法则：


    

  • 单份 CLAUDE.md / AGENTS.md 行数 建议 < 300 行，硬上限 500 行
    • 

  • 行数与 instruction 数不完全等同（一行可能是一条 instruction 也可能是支撑性说明），但行数是粗略代理
    • 

  • 同一 instruction 多次重复无效——模型按"已说过"折算
    • 

  • 列表项 > 散文段落——结构化指令的遵循率比段落散落的高
    • 



数学化一点：若 nnn 是当前提示文件的 instruction 数、TTT 是 LLM 的可靠遵循上限（约 150-200），则有效遵循率近似：


follow_rate(n)≈min⁡(1,Tn)\text{follow\_rate}(n) \approx \min\left(1, \frac{T}{n}\right)follow_rate(n)≈min(1,nT​)
写 400 条 instruction 时，理论上只有 200/400=50%200/400 = 50\%200/400=50% 会被可靠遵循——而被遗漏的往往是文档末段（不是随机分布）。


实战规避：


    

  • 把"常驻规则"（每次会话必需）放主 CLAUDE.md，控制在 100-150 行
    • 

  • 把"按需规则"（编辑某类文件时才需要）放 .claude/rules/*.md 切片，用 globs: 限定激活
    • 

  • 用 @imports 把长文档拆成多份 < 100 行的子文件、主文件聚合——更易维护，但注意 5 跳上限
    • 

  • 定期审计：wc -l CLAUDE.md 超过 300 时强制拆分
    • 



Subdir Lazy-load 陷阱
这是 Claude Code monorepo 用户最常踩的坑。场景：


my-monorepo/
  CLAUDE.md                  # 项目根
  frontend/
    CLAUDE.md                # 写了 "前端用 React 18 + TS strict"
  backend/
    CLAUDE.md                # 写了 "后端用 Go 1.22 + zerolog"
用户说："修复 login bug，看下 frontend 里的接口，然后改 backend/auth/login.go"。


Claude 实际执行路径：


    

  1. 读取项目根 CLAUDE.md——OK
    2. 

  2. 决定先看 frontend/api/login.ts 了解接口签名——访问 frontend/，lazy-load frontend/CLAUDE.md 进入 context
    3. 

  3. 切到 backend/auth/login.go 修复——访问 backend/，lazy-load backend/CLAUDE.md
    4. 



这是预期行为。但反例：用户只说"修复 backend/auth/login.go"，Claude 没必要访问 frontend，frontend/CLAUDE.md 永远不会进入 context——里面写的"前端必须用 strict mode"在这次会话里根本不存在。


这条规则文件写了等于没写——除非"修复的事情"真的让 Claude 访问到该目录。


规避：


    

  • 关键规则放项目根：跨模块都必须遵守的（commit 风格、PR 模板、安全约束）放项目根 CLAUDE.md
    • 

  • subdir 只放该目录特有规则：仅在该目录工作时才有意义的（前端组件命名、后端 logger 选型）放 subdir
    • 

  • 不要把 admin / 安全策略放 subdir：依赖 lazy-load 触发是危险的，admin 规则用 Codex requirements.toml 或 managed settings
    • 

  • 测试方式：claude --print-context 可打印当前会话已加载的提示文件列表
    • 



Codex walk-up 与 OpenCode instructions.paths 的差异：


    

  • Codex walk-up 仅向上、不向下 lazy：从 cwd 向上走，途中所有 AGENTS.md 都在启动时加载，不存在"事后触发"。但这也意味着子目录的特定规则必须在 walk-up 路径上，否则不会被发现。
    • 

  • OpenCode 显式 paths：所有要加载的文件必须在 instructions.paths 或 globs 显式列出——没有 lazy，也没有 walk-up，是最 predictable 的实现。
    •

Path-scoped Globs 校验
Claude Code .claude/rules/*.md 的 frontmatter 是落地 path-scoped 规则的关键，但最常见的失败是静默失败——拼写错 frontmatter 字段名或 glob 模式，没有运行时报错。


错误示例：


---
description: TypeScript 规则
glob: # 错: 字段名应该是 globs（复数）
  - '**/*.ts'
path: # 错: 字段名应该是 paths（复数）
  - 'src/'
---
或：


---
globs:
  - '*.ts' # 错: 单星号不递归，src/foo.ts 不命中
  - '**/.*ts' # 错: 转义错误，匹配不到任何文件
---
校验手段：


    

  • claude --check-rules 命令（Claude Code 1.2+）会列出所有 .claude/rules/*.md、校验 frontmatter 字段名、试运行 glob 看是否匹配到任何文件
    • 

  • pre-commit hook 加 claude rules lint 阻止错误规则进 git
    • 

  • 命名约定：rule 文件名与主 glob 对应（typescript.md 主管 **/*.ts，避免文件名与内容脱节）
    • 



正确写法：


---
description: TypeScript / TSX 编辑时激活
globs:
  - '**/*.ts'
  - '**/*.tsx'
paths:
  - 'src/'
  - 'packages/web/src/'
---

陷阱与常见问题
    

  • 过度自信"规则我写了"：写完 CLAUDE.md 没验证 Claude 是否真按规则做，事后才发现 lazy-load 未触发。规避：每次提示文件改完，用一个 dummy task 测一遍。
    • 

  • 拆分过细导致 imports 跳数爆：把单份 CLAUDE.md 拆成 10 个 @import 子文件，嵌套链超过 5 跳被静默截断。规避：嵌套层级 ≤ 3。
    • 

  • 把 size discipline 当成"删内容"：以为只能砍指令，其实更好的做法是切片到 .claude/rules/——总 token 不变、常驻 context 大幅缩减。
    • 

  • OpenCode globs 匹配 node_modules：globs: ["**/*.md"] 把依赖 README 全抓进来，瞬间撑爆。规避：用更精确的 glob 或 paths 限定。
    • 

  • 跨工具迁移忘了 lazy-load 语义：从 Claude Code 迁到 Codex，subdir CLAUDE.md 被 Codex walk-up 当作启动时加载（与原本 lazy 行为不同），导致 context 超预算。规避：迁移前审 subdir 规则、把真正"按需"的搬到 path-scoped 切片或 OpenCode plugin provider。
    • 



小结
    

  • LLM 可靠遵循的 instruction 数约 150-200 条，Claude Code system prompt 已占 ~50 条，CLAUDE.md / AGENTS.md 建议 < 300 行
    • 

  • 数学上有效遵循率 ≈ min⁡(1,T/n)\min(1, T/n)min(1,T/n)，超过上限时末段优先被遗漏
    • 

  • Claude Code subdir CLAUDE.md 是 lazy-load——未访问该目录则规则不加载，是 monorepo 最常见的"我明明写了"陷阱
    • 

  • 关键规则放项目根、subdir 只放该目录特有规则；admin / 安全策略不能依赖 lazy-load 触发
    • 

  • Codex walk-up 仅向上不向下、OpenCode 完全 explicit——三种语义在 monorepo 场景下行为各异
    • 

  • Path-scoped rules 的 globs: / paths: 拼写错误静默失败，必须用 claude --check-rules 校验
    • 

  • 跨工具迁移要审 lazy-load 行为差异，避免 token 预算意外超出
    •
