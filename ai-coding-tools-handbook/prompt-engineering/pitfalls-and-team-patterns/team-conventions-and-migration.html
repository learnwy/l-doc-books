团队协议、symlink 模式与跨工具迁移

2026 年团队级 AI 编程协议的事实标准已清晰：AGENTS.md 主写、CLAUDE.md symlink、admin 走 requirements.toml / managed settings——但落地仍有 mono-repo 切片、admin override 穿透、跨工具迁移三大决策点。

当一家工程团队从"每人随意用 AI 工具"演进到"统一协议、可审计、可回收"时，提示文件就从个人偏好变成基础设施。本文按团队规模升级路径展开：mono-repo 多文件如何切片、AGENTS.md 主写 + symlink 模式如何落地、admin 如何强制安全策略、从 Cursor / Copilot / Aider 迁过来的字段对照。

Mono-repo 模式：多文件 + 显式聚合
mono-repo 是团队规范最复杂的场景。典型布局：


my-monorepo/
  AGENTS.md                        # 仓库根：跨 package 共同约束
  CLAUDE.md -> AGENTS.md           # symlink
  .agents/rules/                   # 切片规则（按文件类型）
    typescript.md
    python.md
    security.md
  packages/
    web/
      AGENTS.md                    # 前端特定：React 18 + TS strict
    api/
      AGENTS.md                    # 后端特定：Go 1.22 + zerolog
    cli/
      AGENTS.md                    # CLI 特定：cobra + viper
三款工具的对应配置：


OpenCode——opencode.json 显式列出所有可能加载的 AGENTS.md：


{
  "instructions": {
    "paths": ["AGENTS.md"],
    "globs": ["packages/*/AGENTS.md", ".agents/rules/*.md"]
  }
}
OpenCode 在启动时把所有 glob 匹配到的文件都装入（不是 lazy）；如果想让 build agent 不加载前端规则，可以在 agent.build.instructions 字段覆盖。


Codex——配 project_root_markers 让 walk-up 在 package 边界停止：


# ~/.codex/config.toml
project_root_markers = [".git", "package.json", "Cargo.toml", "go.mod"]
cwd 在 packages/web/src/ 时，walk-up 走到 packages/web/（命中 package.json 停止），加载 packages/web/AGENTS.md + 沿途其它——但不会走到仓库根（除非主动配置 walk_beyond_root）。所以仓库根 AGENTS.md 在 mono-repo 里需要额外设置 include_repo_root: true。


Claude Code——依赖 subdir lazy-load，关键规则放项目根 + .claude/rules/ path-scoped 切片：


.claude/rules/typescript.md       # globs: ["**/*.ts", "**/*.tsx"]
.claude/rules/golang.md           # globs: ["**/*.go"]
.claude/rules/python.md           # globs: ["**/*.py"]
subdir CLAUDE.md（即 AGENTS.md symlink）作为 package-specific 增量、按需 lazy-load。


AGENTS.md 主写 + CLAUDE.md Symlink
这是 2026 年的事实标准，Anthropic 在 2026-04 docs 已明确推荐：


# 在仓库根
ln -s AGENTS.md CLAUDE.md

# pre-commit hook 校验 symlink 仍然有效
[ -L CLAUDE.md ] && [ "$(readlink CLAUDE.md)" = "AGENTS.md" ] || (echo "CLAUDE.md symlink 失效"; exit 1)
优点：


    

  • 一份内容喂所有 16+ 工具
    • 

  • 团队成员无论用什么工具都看到相同规则
    • 

  • 修改一处所有工具同步生效
    • 

  • 不增加 git 仓库体积（symlink 本身仅 ~50 字节）
    • 



注意事项：


    

  • Windows / WSL：Windows 创建 symlink 需要管理员权限或开启开发者模式；WSL2 跨文件系统（/mnt/c/）的 symlink 不一定被 Git for Windows 正确处理
    • 

  • core.symlinks 配置：某些团队的 Git 全局配置禁用了 symlink，需要在仓库级 .git/config 显式 [core] symlinks = true
    • 

  • 替代方案：不支持 symlink 的环境可用 pre-commit hook 自动同步内容（cp AGENTS.md CLAUDE.md && git add CLAUDE.md），稍逊但可用
    • 

  • CI 检测：CI 加一条 diff -q AGENTS.md CLAUDE.md（symlink 时 diff 显示空），偏离时硬失败
    • 



Admin Override 与 Untrusted Projects
企业 IT 推 admin 规则时，三款工具的机制不同：






工具
Admin 路径
覆盖语义





Codex
/etc/codex/requirements.toml
与 user ~/.codex/config.toml 冲突时静默忽略 user 字段 + warning 日志




Claude Code
macOS /Library/Application Support/Claude/managed-settings.json 或 Linux /etc/claude-code/managed.json
managed settings 优先于 user settings，部分字段允许 user 增量




OpenCode
opencode.json 中 system_instructions 字段
通过 MDM 推送至 ~/.opencode/opencode.json 受保护位置





实战部署：


    

  • MDM 推送：macOS Jamf / Intune / Munki 把 admin 文件推到受保护目录，chown root:wheel + chmod 0644 防 user 篡改
    • 

  • 检测违规：admin 文件命中后在工具日志打"received managed config from /etc/..."，便于审计
    • 

  • 冲突处理：user 写的"允许 rm -rf"被 admin 否决时，日志 warning 但不中断启动——dev 仍能干活，只是禁用项不生效
    • 

  • untrusted-projects：Codex 独有，把高风险路径（外部承包商目录、临时下载代码）列入 admin glob，命中后 user 的 auto_approve_patterns 全部失效，每个 shell 命令要 human approval
    •

迁移完成后的清理步骤：


    

  1. 仓库根创建 AGENTS.md 与 ln -s AGENTS.md CLAUDE.md
    2. 

  2. 把上表字段并入 AGENTS.md，去重重复条目（cursor 与 copilot 规则常有交叉）
    3. 

  3. 控制 AGENTS.md 行数 < 300，超出的切到 .claude/rules/
    4. 

  4. 旧工具的私有文件保留还是删除？
      

    • 如果团队仍有人在用：保留（如 .cursorrules、.github/copilot-instructions.md）
      • 

    • 完全迁出：删除并加到 .gitignore 防止误重建
      • 

    

    5. 

  5. CI 加 diff -q AGENTS.md CLAUDE.md + claude --check-rules 校验
    6. 



陷阱与常见问题
    

  • symlink 在 Windows 失效：团队 50% Windows 用户、symlink 创建失败回退为普通文件，半个月后两份内容已经分叉。规避：CI 强校验 + pre-commit hook 双保险，或换 pre-commit cp 方案。
    • 

  • admin override 没说明被忽略：dev 写 user 配置不生效但工具没明显报错，半天才发现是 admin 在压制。规避：admin 配置文件第一行写注释 "managed by IT / questions: it-help@..."；工具启动日志显式标"managed config active"。
    • 

  • 迁移漏抓 rules 子目录：Cursor 用户从 .cursorrules 升级到 .cursor/rules/*.md 后只迁了根文件、漏了切片。规避：迁移脚本 find .cursor/rules .github .aider* .cline* .windsurf* -type f 全量列出。
    • 

  • mono-repo 重复规则：根 AGENTS.md 写"用 conventional commits"、每个 package AGENTS.md 又抄一遍——冗余 + 不一致风险。规避：根写共性、subdir 只写 differential。
    • 

  • 跨工具混用导致规则碰撞：团队一半用 Codex（walk-up 拿到仓库根 AGENTS.md）、一半用 Claude Code（subdir lazy-load 没拿到仓库根之外的规则），结果同一个 PR 两个 reviewer 提示不同。规避：把"全 hands"规则放仓库根，确保所有工具都能拿到。
    • 



小结
    

  • 团队级 AI 编程协议事实标准：AGENTS.md 主写 + ln -s AGENTS.md CLAUDE.md symlink，一份文件喂 16+ 工具
    • 

  • mono-repo 模式：根 AGENTS.md 写共性、.claude/rules/ 放 path-scoped 切片、package subdir AGENTS.md 写 differential
    • 

  • 三款工具的 mono-repo 配合各异：OpenCode 显式 paths/globs、Codex 用 project_root_markers 控制 walk-up、Claude Code 用 subdir lazy-load
    • 

  • Admin override 三机制：Codex requirements.toml（user 冲突静默忽略）、Claude managed settings（优先 user settings）、OpenCode system_instructions（MDM 推送）
    • 

  • Codex 独有 untrusted-projects 名单，命中项目 user 的 auto_approve 失效，所有 shell 命令要 human approval
    • 

  • 迁移路径覆盖 Cursor / Copilot / Aider / Windsurf / Continue / Cline 字段对照，cat + grep + jq 即可大半完成
    • 

  • 实战陷阱：symlink Windows 失效、admin 静默压制难察觉、迁移漏抓子目录、mono-repo 重复规则、跨工具规则碰撞
    •
