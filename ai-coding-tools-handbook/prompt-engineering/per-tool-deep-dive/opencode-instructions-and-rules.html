OpenCode：instructions 字段与 AGENTS.md 早期采纳

OpenCode 把"提示文件去哪儿找"这件事从约定升级为配置项——opencode.json 的 instructions 字段支持 paths / globs / URLs 三源聚合，是 2026 上半年最灵活的实现。

OpenCode 在 2025-10 就成为 AGENTS.md 的 first-mover 之一（早于 Codex CLI 公开开源、与 Cursor 同期），但它对"提示文件"的处理路径与其它工具有本质不同：不依赖 walk-up 算法，而是要求用户在 opencode.json 显式列出要加载的源。这种"显式 > 隐式"的设计哲学让 mono-repo 与跨仓库引用变得容易，也避免了 walk-up 在深层目录里抓到全公司根 AGENTS.md 的灾难。

核心概念

OpenCode 的加载流程围绕 opencode.json 一个文件展开，agent 启动时读取 instructions 字段、按顺序聚合所有源：





配置项
类型
行为





instructions.paths
string[]
字面量路径数组，相对 opencode.json 所在目录




instructions.globs
string[]
glob 模式，匹配多份文件后合并




instructions.urls
string[]
远程 URL，启动时拉取（支持 GitHub Raw / GitLab / 内网 wiki）




instructions.providers
object[]
plugin 实现，可基于 agent 类型动态生成 instructions




system_instructions
string
管理员预设、用户不可覆盖（admin override）




AGENTS.md 自动发现
默认
仓库根 + ~/.opencode/AGENTS.md 隐式加载，无需声明





最小可用 opencode.json 示例
下面是一份覆盖三种源的实战配置：


{
  "$schema": "https://opencode.ai/config.schema.json",
  "instructions": {
    "paths": ["docs/AGENTS.md", "AGENTS.md", "packages/web/AGENTS.md"],
    "globs": [".agents/rules/*.md"],
    "urls": ["https://raw.githubusercontent.com/myorg/style-guide/main/typescript.md"]
  },
  "model": "anthropic/claude-opus-4-7",
  "agent": {
    "build": {
      "instructions": {
        "paths": ["docs/AGENTS.build.md"]
      }
    },
    "plan": {
      "instructions": {
        "paths": ["docs/AGENTS.plan.md"]
      }
    }
  }
}
要点解释：


    

  • instructions.paths 是顺序敏感的——前面的源出现在更靠近 system prompt 起始的位置，后面的源在后；当指令冲突时，后载入者覆盖前载入者（与 AGENTS.md 规范"最近-胜"语义对齐）。
    • 

  • globs 用于把整个目录的规则文件全量装入，常见做法是把 .agents/rules/typescript.md、.agents/rules/python.md 等切片放进去。
    • 

  • urls 在 CI 环境最有用——把团队公共规范放到 GitLab Raw URL，所有项目共享一份；离线启动时 OpenCode 会用本地缓存，缓存过期默认 24h。
    • 

  • agent.{name}.instructions 是 OpenCode 独有的"按 agent 切换 instructions"机制——切到 plan agent 时自动用 AGENTS.plan.md，避免在 build agent 上下文里塞计划相关的废话。
    • 



AGENTS.md 早期采纳与 /init 模板
OpenCode 与 OpenAI 在 2025-09 联名签署 v1.0 规范时是签署方之一，2025-10 发布的 0.3.x 已默认支持 AGENTS.md 自动发现：仓库根存在 AGENTS.md 时无需声明、隐式追加到 instructions 列表末尾。


opencode /init 命令会扫描仓库结构并生成一份初始 AGENTS.md 模板，约 70-90 行，包括：


    

  • 项目简介（从 package.json description 或 README.md 第一段提取）
    • 

  • 常用命令（自动嗅探 pnpm test / cargo build / pytest 等）
    • 

  • 代码风格（基于检测到的 linter 配置自动写入）
    • 

  • 待办占位（让用户填团队偏好）
    • 



模板是起点而非终点，团队应当根据自身约定改写。/init 不会覆盖已有 AGENTS.md（追加 .bak 备份提示用户合并）。


Plugin-based Instructions Provider
OpenCode 0.4.x 开始支持 plugin 形式的 instructions provider，这是它与 Codex / Claude Code 最大的差异点。一个 provider 是 hook 实现，会在 agent 启动或切换时被调用、返回一段动态 instructions。典型用法：


// .opencode/plugins/git-status-instructions.js
export default {
  name: 'git-status-instructions',
  hooks: {
    onAgentStart: async ({ agentName, cwd }) => {
      const branch = await runGit(['rev-parse', '--abbrev-ref', 'HEAD'], cwd);
      const status = await runGit(['status', '--short'], cwd);
      if (status.length > 30) {
        return `## 仓库状态提醒\n当前分支 ${branch}，有 ${status.split('\n').length} 个未提交改动，建议先 stash 再开始任务。`;
      }
      return null;
    },
  },
};
注册到 opencode.json：


{
  "instructions": {
    "providers": [{ "path": ".opencode/plugins/git-status-instructions.js" }]
  }
}
应用场景：


    

  • 基于环境变量切换：CI 环境追加 "禁止修改 .env.example"；开发环境不追加
    • 

  • 跨 agent 共享上下文：plan agent 产出的"本次重构计划"自动喂给 build agent
    • 

  • 拉取远端动态规则：从内网风控系统拉当日"高风险包列表"作为 instructions
    • 



注意 provider 在每次 agent 启动都会被调用，要保证幂等且快速（< 200ms），否则启动延迟感知明显。


跨工具协作的桥接策略
OpenCode 与其它工具混用的常见组合：






场景
OpenCode 配置
配合工具

instructions.paths: ["CLAUDE.md"]
Claude Code 仍读 CLAUDE.md，OpenCode 借道复用




Codex CLI / OpenCode 混用
在仓库根放 AGENTS.md，两边自动发现
Codex walk-up + OpenCode 隐式加载

instructions.paths: [".cursor/rules.md", "AGENTS.md"]
保留 Cursor 用户的 .cursor/rules.md




全 hands-off agent（Devin / Jules）
OpenCode 与它们共用同一份 AGENTS.md
所有签署方都走 v1.0 规范





跨工具一致性的核心是：把团队级规则只写在 AGENTS.md，工具特定的扩展（OpenCode plugin / Claude Code path-scoped rules）作为本地增量、不进 git 或在独立目录。


陷阱与常见问题
    

  • paths 顺序写反：把"项目级"放在"用户级"之前，导致用户级覆盖项目级（与"最近-胜"语义违背用户期望）。规则是越具体越靠后。
    • 

  • globs 误吸收 node_modules：写 **/*.md 会把 node_modules 下的依赖 README 全吸进来。务必用更精确的 .agents/rules/*.md 或 docs/policies/*.md。
    • 

  • URLs 离线失败：CI 环境无外网时 urls 拉取失败，OpenCode 默认 warning 但继续启动；如果团队规范包含 URL-only 的关键规则，需要在 CI 加 instructions.allow_offline: false 让缺失变 hard fail。
    • 

  • plugin provider 阻塞启动：provider 同步等待网络请求会让 opencode 启动时间从 200ms 飙到 5s+，应当在 provider 内部做 timeout + fallback。
    • 

  • system_instructions 与 user 冲突：admin 通过 system_instructions 强制安全策略时，用户在 instructions.paths 写的相反规则被静默覆盖——日志里会有 warning，但不影响启动；落地团队规范时应当先与 admin 对齐。
    • 



小结
    

  • OpenCode 是 AGENTS.md v1.0 早期签署方与采纳者之一，opencode.json 的 instructions 字段支持 paths / globs / URLs 三源聚合
    • 

  • 默认仍隐式加载仓库根与 ~/.opencode/AGENTS.md，与签署的开放规范保持兼容
    • 

  • agent.{name}.instructions 支持按 agent 切换 instructions，build / plan 模式可载入不同提示文件
    • 

  • Plugin-based instructions provider 是独有扩展，允许 hook 在 agent 启动时动态生成 instructions——适合环境感知、跨 agent 上下文桥接、动态规则拉取
    • 

  • /init 生成初始模板但不覆盖已有文件，跨工具协作推荐"团队级写 AGENTS.md、工具扩展放独立目录"
    • 

  • 实战陷阱：paths 顺序、globs 吸收 node_modules、URLs 离线失败、plugin 阻塞启动、admin 与 user 静默冲突
    •
