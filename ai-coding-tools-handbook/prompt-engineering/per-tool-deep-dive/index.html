三款工具的提示文件实现 简介

读完第 1 章对开放标准的总览之后，本章把三款主流工具的具体实现拉平比较。同一份 AGENTS.md 在 OpenCode、Codex CLI、Claude Code 三家眼里的解析路径并不一样：OpenCode 走 opencode.json instructions 字段聚合（接 paths / globs / URLs 三种源）；Codex CLI 走 walk-up 算法（从 cwd 向上找 AGENTS.md 直到 project_root_markers 命中）+ AGENTS.override.md 临时覆盖 + requirements.toml 管控；Claude Code 走 CLAUDE.md 5 层加载（global / project / local / subdir lazy-load / path-scoped .claude/rules/）+ @imports 5 跳 + 一个仍未盖棺的 AGENTS.md fallback 之争。三家实现都"声称兼容 AGENTS.md"，但在 monorepo、企业管控、个人 override 三个场景下行为差异显著。

本章不重复第 1 章的规范本体讨论，目标是让读者拿到这一章，能在 5 分钟内为某款工具写出一份生产可用的提示文件、并且知道为什么这样写。

本章包含三篇 L4 文档。

1_opencode-instructions-and-rules.md —— OpenCode 实现。第一块讲 opencode.json instructions 字段：三种源 paths / globs / URLs；如何把团队约定、规范文档、外部 wiki 合成同一个工具可见的 context。第二块讲 OpenCode 的 AGENTS.md 早期采纳者身份与 /init 命令生成模板。第三块讲 OpenCode 独有的 plugin-based "instructions provider" 扩展（plugin = hook 实现方式）——允许在 build / plan agent 切换时动态变更 instructions 内容。

2_codex-agents-md-walkup-and-override.md —— Codex CLI 实现。第一块讲 walk-up 算法与 project_root_markers（默认 .git，可在 ~/.codex/config.toml 自定义为 [".git", "package.json", "Cargo.toml"]）；如何避免"cwd 离 .git 太远导致 AGENTS.md 抓全公司根"的灾难。第二块讲 AGENTS.override.md——临时实验性 prompt（本地不 commit、override 上层 AGENTS.md），实战中是 A/B 提示文件的最佳实践。第三块讲 admin requirements.toml（~/.codex/ 或 /etc/codex/）+ untrusted-projects 名单——企业管控场景下用户的 config.toml 与 admin 值冲突会被静默忽略。

3_claude-md-imports-and-path-scoped-rules.md —— Claude Code 实现。第一块讲 5 层加载：~/.claude/CLAUDE.md（global）+ 项目根 ./CLAUDE.md + CLAUDE.local.md（personal override / gitignored）+ subdir CLAUDE.md（lazy-load —— 只有 Claude 真访问该目录内文件才进入 context）+ .claude/rules/*.md（path-scoped 通过 frontmatter globs: / paths: 限定）；附 @path 5 跳 @imports 机制。第二块讲 AGENTS.md fallback 之争（GitHub issue #6235 状态、官方 docs 矛盾、HiveTrail 2026-04 实测）与行业事实标准：ln -s AGENTS.md CLAUDE.md。第三块讲 path-scoped rules 的实战用法——.claude/rules/typescript.md frontmatter globs: ["**/*.tsx", "**/*.ts"] 只在编辑 TS 时激活，避免常驻 context。

学习建议是按章节顺序读；如果只用某一款工具，可只读对应一节；如果在评估"团队主用哪款"，三节都看再读第 3 章团队模式。
