Codex CLI：walk-up 算法、override 与 admin 管控

Codex 是 AGENTS.md 协议的发源地，walk-up 算法、AGENTS.override.md、requirements.toml 三件套构成了 2026 年最严密的 admin / user 双层提示文件治理体系。

Codex CLI 把 AGENTS.md 当作"项目协议的唯一真理来源"，但它的加载机制比 OpenCode 隐晦得多：不要求用户在配置里显式列出路径，而是从 cwd 开始向上 walk-up、把途中遇到的所有 AGENTS.md 都按"最近-胜"原则合并。这种隐式行为带来便利的同时也带来三个新问题——走到哪里停（project_root_markers）、怎么临时实验（AGENTS.override.md）、admin 如何强制策略（requirements.toml）。本文按这三层展开。

Walk-up 算法与 project_root_markers
默认情况下 Codex 从 cwd 向上 walk-up 直到遇到包含 .git 的目录，把这一级作为 project root。问题是大型 monorepo 里 .git 可能在很高层（比如全公司只有一个 git 仓库、内部按 companies/myorg/products/web/ 分层），结果是 Codex 把整个公司根 AGENTS.md 都抓进来。


解决办法是在 ~/.codex/config.toml 显式定义 project_root_markers：


# ~/.codex/config.toml
project_root_markers = [".git", "package.json", "Cargo.toml", "pyproject.toml", "go.mod"]
含义是：walk-up 时只要看到上述任一标记文件就停下。这样在 companies/myorg/products/web/ 下启动 Codex，walk-up 在 web/package.json 这一级就停了，不会再往上抓 myorg/AGENTS.md。


实战建议：


    

  • monorepo（pnpm workspace / cargo workspace）里把根 package.json / Cargo.toml 作为 marker
    • 

  • 多语言混合项目把所有语言的 manifest 都列入
    • 

  • 不要把 README.md 列为 marker——几乎所有目录都有，walk-up 会过早停止
    • 



walk-up 路径上的所有 AGENTS.md 都加入候选，离 cwd 更近者优先级更高（与规范"最近-胜"一致）。


AGENTS.override.md：临时实验最佳实践
AGENTS.override.md 是 Codex 独有扩展（不在 AGENTS.md v1.0 规范里），用途是让开发者临时改提示文件而不污染团队共享的 AGENTS.md。典型场景：


    

  • A/B 测试不同提示——团队 AGENTS.md 写"用 TDD 写测试"，本机 override 改成"先写实现再写测试"，对比 agent 行为差异
    • 

  • 紧急修复时临时降低规范——AGENTS.md 写"必须有 unit test"，本周末紧急 hotfix 时 override 加"prod 紧急修复可跳过 unit test 直接 commit"
    • 

  • 个人偏好微调——AGENTS.md 写"用 4 空格缩进"，本机 override 改 2 空格做 PoC
    • 



使用方法极简，仓库根 touch AGENTS.override.md，写入差异化内容即可。Codex 会在合并时完全覆盖上层 AGENTS.md（不是追加），所以 override 内容应当是"完整可用的项目协议"——既保留 AGENTS.md 想保留的部分，又改写要 A/B 的部分。


关键约束：


    

  • 必须在 .gitignore 加 AGENTS.override.md——codex /init 默认会加，但手动新建仓库时需要确认
    • 

  • CI 检测：很多团队在 pre-commit hook 加 [ ! -f AGENTS.override.md ] || (echo "提交前请删除 override"; exit 1)，避免无意中带进 git
    • 

  • 优先级：AGENTS.override.md > 仓库根 AGENTS.md > 上层 AGENTS.md > 用户级 AGENTS.md > admin requirements
    • 



Admin 层：requirements.toml 与 untrusted-projects
企业部署 Codex 时常需要"无论 user 怎么改 AGENTS.md，agent 都必须遵守的安全策略"——比如禁止访问 prod 数据库、禁止 commit 包含 API key 的代码、禁用某些破坏性 shell 命令。Codex 通过 requirements.toml 满足这个需求，路径有两处：


    

  • 用户级 ~/.codex/requirements.toml：user 自己写的预设，可覆盖
    • 

  • 系统级 /etc/codex/requirements.toml：admin 推送，user 不可覆盖
    • 



一份典型的 admin requirements.toml：


# /etc/codex/requirements.toml
[security]
forbid_shell_patterns = ["rm -rf /", "dd if=/dev/zero"]
require_human_approval_for = ["git push --force", "DROP TABLE"]

[untrusted-projects]
paths = ["/work/external-contractors/*"]
# 命中此 glob 的项目，user config.toml 中的某些字段被静默忽略
ignore_user_config = ["allowed_commands", "auto_approve_patterns"]

[network]
allow_egress_domains = ["github.com", "registry.npmjs.org"]
冲突处理规则：


    

  • 用户在 ~/.codex/config.toml 里写 allowed_commands = ["rm -rf /"]，但 admin requirements.toml 把 rm -rf / 列入 forbid_shell_patterns——user 静默被忽略，启动时只有一条 warning 日志，不阻塞启动（避免 dev 没法干活）
    • 

  • 项目在 untrusted-projects.paths 命中时，user 的 auto_approve_patterns 被禁用，每个 shell 命令都要 human approval
    • 

  • admin 与 user requirements.toml 字段冲突——admin 胜
    • 



这套机制让 admin 可以在不打扰 dev 日常的前提下推规则，dev 只在尝试做被禁止的操作时才察觉到。


与 Codex CLI 安装路径的互动
Codex CLI 的安装路径影响 requirements.toml 的搜索顺序：

npm install -g @openai/codex

企业 MDM 推送

企业部署通常通过 MDM / Ansible 把 admin requirements 推到 /etc/codex/，并用文件权限 0644 + owner root 防止 user 篡改。


陷阱与常见问题
    

  • walk-up 抓到全公司根：没配 project_root_markers、cwd 在深层目录、.git 在很高层，结果 AGENTS.md 总和远超 system prompt 预算。规避方式见上文配置示例。
    • 

  • override 进了 git：仓库根没把 AGENTS.override.md 加入 .gitignore，一次粗心 git add . 把 override 推到团队仓库，下次 CI 跑全部踩坑。务必走 pre-commit hook 拦截。
    • 

  • admin 静默忽略难调试：user 写的 config 不生效但 Codex 没报硬错误，只在日志里 warning。排查方式：codex doctor 命令会打印最终生效的 config + 被忽略的字段及原因。
    • 

  • untrusted-projects glob 匹配不到：admin 把 paths = ["/work/external-contractors/*"]，但 dev 通过 symlink 把项目链到 ~/code/proj-x，glob 不命中——admin 规则形同虚设。建议在 admin 端加多种路径变体，并配合 cwd_real_path 解析（Codex 0.5+ 支持）。
    • 

  • AGENTS.override.md 不退出：跨项目共用一个 shell session，cd 切到另一项目时 override 仍在生效（因 cwd-based 解析）——这是正常行为，但容易忘。建议 override 文件第一行写 <!-- ACTIVE: $PROJECT_NAME --> 提醒自己。
    • 



小结
    

  • Codex CLI 是 AGENTS.md 协议起源，walk-up 算法从 cwd 向上找直到 project_root_markers 命中
    • 

  • 默认 marker 仅 .git，monorepo / 深层目录场景必须自定义，常见加 package.json / Cargo.toml / pyproject.toml / go.mod
    • 

  • AGENTS.override.md 是 Codex 独有扩展，仓库本地 / 不进 git / 完全覆盖上层，适合 A/B 实验与紧急情境
    • 

  • admin 层 requirements.toml（/etc/codex/ 或 MDM 推送）强制安全策略，user 冲突项静默忽略 + warning
    • 

  • untrusted-projects 名单让特定项目下 user 的 allowed_commands / auto_approve_patterns 失效，配合 human approval
    • 

  • 实战陷阱：walk-up 抓全公司根、override 进 git、admin 静默忽略难调试、untrusted-projects glob symlink 失配
    •
