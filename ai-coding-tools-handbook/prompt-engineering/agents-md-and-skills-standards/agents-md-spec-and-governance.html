AGENTS.md 规范本体与治理

2026 年 AI 编程代理生态出现的第一份"跨厂商、跨工具、不与任何单家产品绑定"的提示文件开放规范。

AGENTS.md 不是又一个 .cursorrules 或 .aider.conf——后者是单一工具的私有协议，前者是被 OpenAI、Anthropic、Google、Sourcegraph 等八家公司联名背书、并在 2025-12 转入 Linux Foundation 子基金会治理的标准。理解这份规范的最快方式是把它拆成三层：格式约定（如何写）、加载语义（工具如何发现并解析）、治理与生态（谁在维护、有多少工具实现）。

核心概念

AGENTS.md 的核心是"一份 Markdown 文件、放在任何层级、最近-胜规则、可被 chat prompt 覆盖"。下图把发现路径与优先级落到一张时序图上：

格式约定与最近-胜规则
规范本体非常克制：除了"必须是 UTF-8 Markdown、文件名 AGENTS.md"以外，几乎不限制内容。这意味着团队完全可以把 AGENTS.md 写成"任务清单 + 代码规范 + 测试命令 + 偏好"的混合体。但加载语义有强约束，工具不得自行变通：


    

  • 最近-胜：当 repo/AGENTS.md 与 repo/packages/web/AGENTS.md 同时存在、Claude 正在编辑 packages/web/src/App.tsx 时，web/ 那份必须完全覆盖（而非追加）根目录那份的冲突条目。
    • 

  • 不向下递归：工具不能在用户没主动访问子目录时就把所有 AGENTS.md 全量装入 context——这是 chapter 3 lazy-load 陷阱的源头。
    • 

  • chat prompt 终极优先：用户在对话里临时说"忽略 AGENTS.md 里的 lint 规则、本次直接 commit"，工具必须遵守，不能以"规范文件没允许"为由拒绝。
    • 



治理脉络：从 OpenAI 早期协议到 AAIF
AGENTS.md 的演化分四个明确节点：


    

  • 2024-末 ~ 2025-08：OpenAI 内部 Codex 项目使用一份名为 AGENTS.md 的协议文件，作为 Codex CLI 的 walk-up 解析目标。当时还是 OpenAI 单家约定。
    • 

  • 2025-09：OpenAI、Anthropic、Google、Sourcegraph、Cursor、Factory、Amp、Jules 八家联名签署 v1.0 规范，移交到独立的 agents.md 站点维护，GitHub 仓库 openai/agents.md 作为参考实现。这一刻起 AGENTS.md 不再是 OpenAI 私有。
    • 

  • 2025-12：规范连同 SKILL.md、Agent Skill SDK 等一同归入新成立的 Agentic AI Foundation（AAIF），AAIF 作为 Linux Foundation 子基金会运作，治理结构与 OpenJS Foundation 类似——TSC 由签署厂商提名、规范变更走 RFC 流程。
    • 

  • 2026 年至今：v1.1 草案进入公开评审，主要修订是把"用户级 ~/.agents/AGENTS.md"从隐式约定升级为规范明文，并新增"工具可选支持 .toml 元数据 sidecar"。
    • 



治理结构落地之后的实际影响是：任何工具厂商都可以提 RFC 扩展规范（比如加新 frontmatter 字段），但核心三条规则（文件名 / 最近-胜 / chat prompt 优先级）必须保持向后兼容。

陷阱与常见问题
实践中最常踩三个坑：


    

  • 大小写错误：文件名必须严格是 AGENTS.md，Agents.md / agents.md 在 case-sensitive 文件系统（macOS APFS 默认 case-insensitive、Linux ext4 case-sensitive）上行为不一致——团队 CI 在 Linux 跑、本地 macOS 开发，可能 dev 看到加载、CI 看到没加载。规避方式是在 CI 加 [ -f AGENTS.md ] && grep -l ... 形式的硬校验。
    • 

  • 试图用 frontmatter 强制加载：v1.0 规范没有 frontmatter 字段控制加载，写了 frontmatter: { priority: high } 之类没有任何作用——工具会原样保留作为内容传给模型，反而稀释了真正的指令。
    • 

  • 混淆 chat prompt 优先级：以为"AGENTS.md 里写了'禁止删除 prod table'就万无一失"。事实是用户当次 chat prompt 永远可以覆盖——真正的安全护栏要走 admin requirements.toml（Codex）或 managed settings（Claude Code），不是 AGENTS.md。
    • 



另一个常被问到的问题是"AGENTS.md 与 .gitignore 怎么配合"。规范无要求，但事实做法是：AGENTS.md 进 git（团队共享）、AGENTS.local.md / AGENTS.override.md 不进 git（个人临时实验）——后者由各工具自行扩展（Codex 用 override、OpenCode 用 local），见 ../2_per-tool-deep-dive/2_codex-agents-md-walkup-and-override.md。


小结
    

  • AGENTS.md 是 2025-09 由 8 家厂商签署、2025-12 归入 Linux Foundation 子基金会 AAIF 治理的开放规范，2026 年是工具栈第一份不被单家绑定的标准
    • 

  • 规范核心三条：标准 Markdown / 任意层级放置 / 最近-胜规则，加上"chat prompt > 文件"的优先级
    • 

  • 2026 上半年 16+ 工具实现，按"原生 / fallback / 不支持"三档划分，Claude Code 与 Gemini CLI 是 fallback、Copilot 暂未支持
    • 

  • 治理走 RFC 流程，核心规则保持向后兼容，工具可在扩展层加入 frontmatter / sidecar
    • 

  • 落地三大陷阱：文件名大小写、frontmatter 误用、混淆 chat prompt 优先级与安全护栏
    •
