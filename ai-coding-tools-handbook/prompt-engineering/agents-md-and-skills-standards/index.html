开放标准：AGENTS.md 与 SKILL.md 简介

2026 年 AI 编程代理生态里有两条相辅相成的开放规范同时进入"行业默认"：AGENTS.md 解决"项目级提示语怎么写、工具如何发现并加载"的问题；SKILL.md 解决"可复用的过程性知识如何以 token-cheap 的方式装上"的问题。前者从 OpenAI Codex 早期协议起步、2025 年 9 月由 8 家厂商联名扩展成跨工具开放规范；后者从 Anthropic Claude Code 的 Skills 概念演化、2026 年 1 月以 Apache-2.0 协议发布在 agentskills.io。两条标准都通过 Agentic AI Foundation（AAIF / Linux Foundation 旗下，2025 年 12 月成立） 治理，这是 AI 编程工具栈第一次有共同的标准组织背书。

本章的目的，是让读者无论用哪款工具，都能站在标准本身的角度判断"这个实现是否合规 / 扩展到哪一层"。这一视角对评估新出工具、判断厂商承诺的真假、规划长期团队协议都至关重要。

本章包含两篇 L4 文档。

1_agents-md-spec-and-governance.md —— 标准本体与治理。第一块讲格式约定：标准 Markdown、可在任意层级放置（仓库根 / ~/ 用户级 / subdir）、与最近编辑文件距离最近者优先；明确"chat prompt > AGENTS.md"的优先级。第二块讲治理与历史：2025-09 由 OpenAI 牵头与 Anthropic / Google / Sourcegraph / Cursor / Factory / Amp / Jules 等签署、2025-12 归入 AAIF / Linux Foundation；GitHub openai/agents.md 为参考实现仓库。第三块讲 2026 上半年的 16+ 工具适配矩阵：Claude Code / Codex CLI / OpenCode / Cursor / Aider / Devin / Amp / Jules / Zed / Continue / Roo / Factory / Copilot / Gemini CLI / Windsurf / Amazon Q——附"原生 vs fallback vs 不支持"分级表。

2_skills-progressive-disclosure.md —— SKILL.md 与渐进披露。第一块讲格式：skill-name/SKILL.md 必备 + 可选 scripts/ 子目录；frontmatter 必填 name / description + 可选 14+ 字段（按 spec 与 tool extension 分类）。第二块讲核心设计原则 progressive disclosure：会话启动只载入所有 skill 的 name + description（约 50 个 skill ≈ 1500-2500 token），匹配任务时才注入 SKILL.md body——这是 Anthropic PM Mahesh Murag 提出的、解决 prompt bloat 的关键机制。第三块讲 2026 工具适配：16+ 工具支持，每家可叠加扩展（Claude Code 加 context: fork、Codex 加 openai.yaml），但 base SKILL.md 跨工具直读。

学习建议是 1_ 先读一遍把"标准 + 治理 + 适配矩阵"刻进脑里，再读 2_ 体会 Skills 与 AGENTS.md 的角色分工——AGENTS.md 是项目协议的静态层，SKILL.md 是过程性知识的动态层，两者在 token 经济学上互补而不重叠。
