Hermes Agent 身份与定位

核心概念

Hermes Agent 在 Tier 2 personal-agent 阵营里的身份与 OpenClaw 完全正交：persistent memory + 自创 skills + 7 种 terminal 后端 + curator 后台维护。它不路由 chat 消息、不切 persona、不接 webhook；它专心做一件 OpenClaw 与 coding agent 都不擅长的事——把"我历史上偏好什么、做过什么、固化成什么 skill"沉淀为可跨 session 复用的长期资产。

图里的 curator 是 Hermes 的"看门人"——每天定时跑一遍，按 importance 重排 memory、去重、退役 stale 条目、并用 GEPA 机制让 skill 自我精炼。它是 Hermes 区别于"无脑日志"型记忆工具的关键。

两者经常一起部署：OpenClaw 维护"现在以谁的身份在哪聊"，Hermes 维护"这个 persona 过去做过哪些决策"。coding agent 通过反向 MCP 同时拿到两边的 tool——openclaw.message.send 用于发消息，hermes.memory.query 用于取上下文。


与 Claude Code memory 的差异
读者第二个常见问题是："Claude Code 自己也有 memory，为什么还需要 Hermes？" 答案在时间尺度：


    

  • Claude Code working memory = 单次 session 内的短期上下文，session 结束就丢；它擅长"在同一个会话里记住我刚才说过什么"。
    • 

  • Hermes persistent memory = 跨 session、跨工具、跨设备的长期资产；它擅长"上周我们讨论过的那个 X 决策，把当时的 reasoning 拉回来"。
    • 



二者互补不替代。实际工作流是 Claude Code 起 session 时通过反向 MCP 调 hermes.memory.query 把昨天的相关 memory 拉到 working memory；session 结束时把今天的关键决策回写 Hermes：


这种模式让 Claude Code 每次起 session 都有"上下文连续性"，而不是每次从零开始解释。

Hermes 选"本地 + 显式管理"路线，核心动机是数据所有权——personal-agent 类工具维护的是用户最敏感的长期偏好与决策历史，不该绑死在某家 SaaS 上。


与 Anthropic API memory 的差异
Anthropic API 也提供了 session-level memory feature，但定位是单 API session 内的对话状态——它对标的是 OpenAI 的 thread API、不是 Hermes 的跨 session 资产。


可以这样记：


    

  • Anthropic API memory = 一次 API 调用链里的 turn-to-turn 记忆。
    • 

  • Claude Code working memory = 一次本地 session 里的多 turn 记忆（建立在 API memory 之上加 local cache）。
    • 

  • Hermes persistent memory = 跨 session / 跨 coding agent / 跨设备 / 跨年份的长期资产。
    • 



三层是 nesting 关系，不是替代关系。


官方 bundled claude-code skill：协同入口
Hermes 官方在二进制内置了一个 bundled skill 叫 claude-code——这是 Hermes 在协议层主动承认 Claude Code 在 coding 领域的强势、并提供官方 delegate 路径的体现。


工作机制：当用户在 Hermes 里说"帮我写一段代码 X"时，bundled claude-code skill 的 trigger 命中，Hermes 不自己处理，而是：


    

  1. 把上下文 + 任务通过 stdio 启动 claude CLI 子进程；
    2. 

  2. 等 Claude Code 完成后接 stdout 结果；
    3. 

  3. 把结果 + 关键决策回写 Hermes memory，便于下次复用。
    4. 



这个设计的关键含义：Hermes 不试图成为 coding agent，它把编程交给最专业的工具，自己专心做 memory + skill。这是 Tier 2 工具与 Tier 1 工具协同的范式样板。


第三方 blog 把这种关系总结为 "Claude Code for software engineering, Hermes for everything else"，但这是外部 framing 而非 Hermes 官方表述——本 hub 改为复述可验证的协议事实（bundled skill + stdio delegate），不复用未验证的 marketing 措辞。


陷阱与常见问题
    

  • 把 Hermes 当 coding agent：它没有 file-edit / shell-exec 能力，写代码请用 Claude Code（通过 bundled skill）。
    • 

  • 把 Hermes memory 与 vector DB 等同：Hermes 内部 SQLite + FTS5 是关键词 + 全文检索为主，可加 vector 但不是核心；与 LangChain 类 RAG 不同。
    • 

  • 以为 skill 是 OpenAI function：Hermes skill 是 frontmatter + markdown 的本地文件，触发由 trigger phrase 命中而非 model 自主决定。
    • 

  • 以为 curator 会主动学习新偏好：curator 只 review 已有 memory，不主动从外部源拉数据；新偏好仍需用户写入。
    • 



小结
    

  • Hermes 身份：persistent memory + 自创 skills + 7 terminal 后端 + curator。
    • 

  • 与 OpenClaw 正交：OpenClaw 管"现在"，Hermes 管"历史 + 复用"。
    • 

  • 与 Claude Code memory 互补：Claude 短期 working，Hermes 跨 session 长期。
    • 

  • 与 ChatGPT memory 差异：本地 SQLite + 显式 curator + 可审计 NDJSON。
    • 

  • 官方 bundled claude-code skill 是协同入口，编程任务 delegate 给 Claude CLI。
    •
