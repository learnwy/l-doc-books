Hermes Agent 速览 简介

Hermes Agent 是 Tier 2 personal-agent 阵营里"持久记忆 + 自创 skills"方向的代表工具，定位是把"用户的长期 memory（偏好、决策、项目背景）"与"自我维护的 skills（curator 后台 review / GEPA self-improvement）"沉淀成长期资产；coding agent 通过反向 MCP 拉取 memory query / persona active / skill dispatch / curator schedule 等 tool，让每次编程会话起手就有"角色化世界知识"。Hermes 的另一关键特性是 7 种 terminal 后端——同一 Hermes 实例可在 macOS Terminal / iTerm2 / Ghostty / kitty / wezterm / tmux / WSL 上保持一致体验，是跨设备工作流的协议层基础。

适合读者主要有三类：每次新会话都重新解释 context 觉得浪费的开发者；想把过往 decision / learning 沉淀成可查询长期记忆的工程师；以及对 GEPA-style skill self-improvement（ICLR-2026 paper 在 Hermes 落地）感兴趣的工具研究者。读者只需用过任一款 coding agent；对反向 MCP 还不熟请先回 ../../../01_coding-tools/3_mcp/3_reverse-mcp-and-pitfalls/。

本章六篇 L4 按"先理解、再上手、最后配置"三对递进。

定位对（1-2）：1_identity-and-positioning.md 讲 Hermes 的身份与定位——persistent memory + 自创 skills + 7 terminal 后端、与 OpenClaw 的角色分工；2_use-cases-and-comparison.md 讲使用场景与对比定位——与 Claude Code（短期 working memory）/ ChatGPT memory（私有 SaaS）的差异。

上手对（3-4）：3_install-and-memory-init.md 讲安装（CLI binary / Homebrew）+ 首次 memory 初始化 + 第一次 curator 周期；4_first-skill-and-claude-code-bundle.md 讲第一次自创 skill + 启用 bundled claude-code skill（Hermes 官方提供的协同入口）。

配置对（5-6）：5_seven-terminal-backends.md 横向对比 7 种 terminal 后端（macOS Terminal / iTerm2 / Ghostty / kitty / wezterm / tmux / WSL），每种的兼容性与体验差异；6_curator-and-skill-self-improvement.md 讲 curator 后台周期维护 memory + ICLR-2026 GEPA self-improvement 机制如何让 skills 自动 refine。

推荐学习路径是按 1→2→3→4→5→6 顺序走一遍；只关心 Claude Code 协同的开发者优先看第 2-4 篇；对 GEPA 感兴趣直接读第 6 篇。深入 persistent memory 的 FTS5 索引与 char-cap + curator、skills self-creation 的触发条件请转 ../../../02_personal-agents/2_persistent-memory/ 与 ../../../02_personal-agents/3_skills-self-creation/。

本节内容定位：第三方 blog 措辞 "Claude Code for software engineering, Hermes for everything else" 是外部 framing 而非 Hermes 官方定位，本章改为复述可验证协议事实——Hermes 提供官方 bundled claude-code skill 作为协同入口，承认 Claude Code 在 coding 领域的强势。
