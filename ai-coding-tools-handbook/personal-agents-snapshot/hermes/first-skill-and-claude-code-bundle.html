Hermes 第一个 skill 与 claude-code bundle

核心概念

Hermes 的 skill 是 frontmatter + markdown 的本地文件，写起来比 OpenAI function 简单一个量级。本节按"自创第一个 skill → 测试触发 → 启用 bundled claude-code skill → 验证 delegate 链路"四步走完，目标是让读者拿到两个能跑的 skill：一个完全自己写、一个用官方 bundle。两个 skill 一起跑通后，Hermes 与 Claude Code 的协同范式就建立了。

自创第一个 skill：起脚手架
hermes skill new my-style-guide
命令会生成一份脚手架文件：


~/.learnwy/hermes/skills/my-style-guide/
  SKILL.md
脚手架内容大致：


---
name: my-style-guide
description: <一句话描述 skill 用途>
trigger:
  - <触发词或短语 1>
  - <触发词或短语 2>
version: 0.1.0
author: <你>
---

# <skill 名>

<在这里写 skill body：规范 / 步骤 / 示例 / 反例>
frontmatter 三个字段是关键：






字段
含义
写法建议





name
skill 唯一 ID
全小写连字符，如 my-style-guide




description
一句话用途
让 agent 读了能判断"该不该用"




trigger
触发短语列表
具体到项目 / 工具 / 文件类型，避免太通用





一个具体 skill 的完整例子
把脚手架补成"项目 X 的 coding style guide"：


---
name: project-x-style
description: Project X 内部 coding style 规范，用于代码生成与 review
trigger:
  - 'project-x'
  - '项目 X'
  - 'X 项目'
  - '/path/to/repo/project-x'
version: 0.1.0
author: wangyang
---

# Project X Coding Style

## 缩进与命名

- 缩进：4 空格，禁 tab
- 文件名：snake_case
- 变量名：camelCase
- 常量：UPPER_SNAKE
- React 组件：PascalCase

## Commit message

强制 Conventional Commits 格式：

type(scope): subject

body

footer

`type` 限定枚举：feat / fix / refactor / docs / test / chore。

## PR description

必含三段：Summary / Test plan / Risk。test plan 必含至少一项 manual 验证。

## 反例

- 不要 `git add -A`，永远用具体路径
- 不要 commit `.env`
- 不要在 PR 里写 `@here` style mention
写完后让 Hermes 重新扫描 skill 目录：


hermes skill reload
hermes skill list
输出能看到 project-x-style 在列表里。


测试触发
不真启 coding agent，先用 dry-run / mock fire 验证 skill 触发：


hermes skill test --skill project-x-style --prompt "帮我写一个 project-x 的新组件"
输出大致：


trigger-match: "project-x"
matched-position: prompt[6:15]
would-inject: ~/.learnwy/hermes/skills/project-x-style/SKILL.md
estimated-tokens: 312
would-inject 表示该 skill 会被注入到 coding agent 的上下文；estimated-tokens 帮助评估 prompt budget。


live 触发验证
启动 mcp-serve（如未启动），然后在 Claude Code 里说一句包含 trigger 的话：


hermes mcp-serve &
在 Claude Code 里：


> 帮我写一个 project-x 的新组件
Claude Code 通过反向 MCP 调 hermes.skill.list 拿到 project-x-style 后，因 trigger 命中自动调 hermes.skill.dispatch(skill='project-x-style') 拉 body 注入上下文，再生成代码时遵循该 style guide。


启用 bundled claude-code skill
Hermes 二进制内置的 bundled skill 在 init 时已经放到 ~/.learnwy/hermes/skills/claude-code/，但默认 enabled: false——避免在用户没装 Claude CLI 时无声失败。手动启用：


hermes skill enable claude-code
启用后看一眼 ~/.learnwy/hermes/skills/claude-code/SKILL.md 的关键 frontmatter：


---
name: claude-code
description: Delegate coding tasks to Claude Code CLI
trigger:
  - '写代码'
  - 'implement'
  - '重构'
  - '调试'
  - 'write code'
  - 'refactor'
  - 'debug'
bundled: true
enabled: true
delegate:
  command: claude
  args: ['-p']
  io: stdio
---
delegate 段是 bundled skill 特有字段——告诉 Hermes 命中时不要把 body 注入上下文，而是 fork 一个子进程跑 Claude Code CLI。


bundled skill 的 delegate 工作机制
完整的 delegate 链路：


具体到代码层面：Hermes 用 child_process.spawn('claude', ['-p'])、把整理好的 prompt 通过 stdin 喂入、收 stdout 作为 Claude 的回答、解析其中的关键 decision 段并调 memory.write 写回 Hermes。


这套机制让 Hermes 不必自己做编程任务——它把 coding 交给最专业的工具，自己专心做 memory + skill 的长期资产维护。这是 Tier 2 工具与 Tier 1 工具的范式样板。


bundled vs 自创 skill 的差异
写完两个 skill 后，可以横向对比看清边界：

验证两个 skill 一起工作
写完两个 skill 后做一次组合验证：


> 帮我用 project-x 的 style 写一个组件
期望行为：


    

  1. Hermes 检测 prompt 命中 project-x-style（trigger "project-x"）和 claude-code（trigger "写"）。
    2. 

  2. 优先级处理：project-x-style 是上下文注入型、claude-code 是 delegate 型——Hermes 先把 project-x-style body 注入到 delegate prompt 里。
    3. 

  3. fork claude -p，子进程拿到带 style guide 的 prompt，生成符合规范的代码。
    4. 

  4. 结果回到 Hermes，关键决策写 memory。
    5. 



这种"上下文注入 skill + delegate skill"的组合范式可复用到所有协同场景。


陷阱与常见问题
    

  • trigger 写得太通用：写"code" / "function" 这种词，每次都激活，agent 上下文被无关 skill 撑爆；trigger 要具体到项目名 / 工具名 / 文件路径。
    • 

  • skill body 写太长：单 SKILL.md 建议 < 2000 tokens；超过的拆 reference 文件，body 里只放索引。
    • 

  • bundled claude-code 启用前没装 claude CLI：trigger 命中后 fork 失败，错误日志写在 audit/；先 which claude 确认。
    • 

  • delegate 时未限制 PATH / cwd：子进程继承环境会引入意外副作用；生产建议用 delegate.env / delegate.cwd 显式限制。
    • 

  • 以为 enable 后立刻生效：trigger 列表是 mcp-serve 启动时加载的；改 SKILL.md 后要 hermes skill reload。
    • 



小结
    

  • 自创 skill：frontmatter (name/description/trigger) + markdown body，放 ~/.learnwy/hermes/skills/<name>/SKILL.md。
    • 

  • 测试用 hermes skill test，live 用 mcp-serve 跑通后在 Claude Code 里输 trigger phrase。
    • 

  • bundled claude-code skill 是官方 delegate 入口，承认 Claude Code 在 coding 领域专业性。
    • 

  • delegate 机制：fork claude -p、stdio 传上下文、回写关键决策到 memory。
    • 

  • 自创 + bundled 组合：上下文注入型 skill 与 delegate 型 skill 可叠加使用。
    • 

  • 下一篇 5_seven-terminal-backends.md 看 7 种 terminal 后端横向对比。
