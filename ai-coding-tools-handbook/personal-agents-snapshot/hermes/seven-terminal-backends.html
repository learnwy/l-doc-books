Hermes 7 种 terminal 后端

核心概念

Hermes 在协议层面对 7 种主流 terminal 做了官方适配——macOS Terminal / iTerm2 / Ghostty / kitty / wezterm / tmux / WSL。这不是简单"能跑就行"，而是覆盖三类兼容性维度：TUI 渲染（box-drawing 字符 / Unicode 宽字符）、键位协议（Kitty keyboard protocol / legacy CSI）、颜色支持（256-color / truecolor / OSC 52 剪贴板）。本节横向对比这 7 种后端的能力矩阵，并给出"什么场景选哪种"的决策树。

七种后端共享同一 storage——切 terminal 不丢 memory / skill / audit log。

后三行特意标注"取决宿主"——tmux 和 WSL 不是独立 terminal emulator，而是嵌套层；它们的能力上限由外层 terminal 决定。


单个 terminal 的特性细节
macOS Terminal
系统自带、零安装。Hermes 在它上面能跑，但有三个已知限制：


    

  • 不支持 truecolor，diff / syntax highlight 颜色被自动降级为 256 色近似值。
    • 

  • 不支持 Kitty keyboard protocol，Hermes 一些键位（如 Ctrl+Shift+P）会 fallback 到普通 P。
    • 

  • OSC 52 剪贴板仅在新版本（Sonoma+）部分支持。
    • 



适用场景：临时上去看一眼 / 远程 SSH 跳板机；不推荐做主力。


iTerm2
macOS 老牌强力 terminal。Hermes 在 iTerm2 上几乎全能力可用：


    

  • truecolor 支持完整。
    • 

  • OSC 52 完整支持，Hermes 可直接复制 memory 条目到系统剪贴板。
    • 

  • 键位协议是 legacy CSI + iTerm2 私有扩展，多数 Hermes 键位可用，但 Kitty keyboard 不原生（可通过 profile 模拟）。
    • 

  • 内置 split / hotkey window 与 Hermes 多 session 配合好。
    • 



适用场景：macOS 日常通用首选；尤其多 split 场景。


Ghostty
Mitchell Hashimoto 主导的新 terminal，2024 年发布。Hermes 在 Ghostty 上是"原生路线"：


    

  • Kitty keyboard protocol 原生支持，Hermes 复杂键位（如 Shift+Enter 多行 / Ctrl+P 历史）100% 可用。
    • 

  • truecolor + OSC 52 + Sixel 等现代特性完整。
    • 

  • 启动速度与渲染性能优秀。
    • 



适用场景：macOS / Linux 上希望走"现代 terminal 协议"路线的开发者。


kitty
Linux/macOS 性能党的选择，Kitty keyboard protocol 由它发明。Hermes 在 kitty 上能力对齐 Ghostty：


    

  • GPU 加速渲染，长输出 scroll 极顺。
    • 

  • Kitty graphics protocol（可直接显示图片）—— Hermes 暂未深度集成，但不冲突。
    • 

  • 配置文件文本格式，易于版本控。
    • 



适用场景：Linux 桌面 / 性能敏感场景；macOS 上也可作为 Ghostty 替代。


wezterm
Wez Furlong 主导的跨平台 terminal（Lua 配置）。Hermes 在 wezterm 上是"跨平台一致"路线：


    

  • 同一配置在 macOS / Linux / Windows 三平台行为一致。
    • 

  • 完整 Kitty keyboard / truecolor / OSC 52。
    • 

  • Lua 配置可程序化生成，便于 dotfiles 管理。
    • 



适用场景：多平台轮换工作；需要 dotfiles 跨 OS 复用的开发者。


tmux 嵌套
tmux 不是独立 terminal emulator，是 terminal multiplexer——在某外层 terminal 内跑多个 window/pane。Hermes 在 tmux 内的关键 quirk：


    

  • truecolor 透传：需要外层 terminal + tmux 都开启 truecolor 透传（set -ga terminal-overrides ",*256col*:Tc"），否则颜色降级。
    • 

  • 键位透传：tmux 默认会拦截一些 prefix；Hermes 用的复杂键位（如 Kitty keyboard）需配 extended-keys on。
    • 

  • OSC 52 透传：tmux 3.3+ 默认支持，老版本要 set -g set-clipboard on。
    • 



适用场景：多窗口工作流 / 远程 SSH 长会话（断线重连）；嵌套时务必配齐 quirk 选项。


WSL（Windows Subsystem for Linux）
WSL 不是 terminal，是 Linux subsystem——通常配合 Windows Terminal 或 wezterm 使用。Hermes 在 WSL 上是 Linux binary，能力上限由外层 terminal 决定：


    

  • 外层用 Windows Terminal：truecolor / OSC 52 OK；键位协议有限。
    • 

  • 外层用 wezterm Windows 版：Kitty keyboard 可用，体验对齐原生 Linux。
    • 

  • 文件系统注意：~/.learnwy/hermes/ 放 WSL 内置 ext4（/home/<user>/），不要放 /mnt/c/ 否则 SQLite 性能崩溃。
    • 



适用场景：Windows 主力机想跑 Hermes；推荐外层 wezterm + WSL 内 binary。


选型决策树
经验法则：


    

  • macOS 默认推 Ghostty 或 iTerm2：前者代表"未来"，后者代表"稳定"。
    • 

  • Linux 推 kitty 或 wezterm：性能党选 kitty，跨平台党选 wezterm。
    • 

  • 多窗口工作流：在上述选好的 terminal 上嵌 tmux。
    • 

  • 远程 SSH 注意 keyboard protocol fallback：SSH 隧道偶尔不透传 Kitty keyboard，复杂键位失效；Hermes 内置 fallback 到 legacy CSI。
    • 

  • Windows：wezterm Windows 版 + WSL Linux binary 是最一致体验。
    • 



Hermes 数据跨 terminal 共享机制
七种后端共享同一 ~/.learnwy/hermes/ 目录，但 SQLite 默认 WAL 模式下不支持多 host 并发。两种典型部署：


    

  • 单设备多 terminal：完全 OK——OS 层文件锁会串行化写。
    • 

  • 多设备 mesh：需要走 Hermes 自带的 sync 协议（不是直接共享磁盘）；这部分进阶用法在 ../../../02_personal-agents/2_persistent-memory/ 详述。
    • 



陷阱与常见问题
    

  • WSL 把 storage 放 /mnt/c/：跨文件系统访问 SQLite 性能崩；务必放 WSL 内的 ext4 路径。
    • 

  • tmux 没开 truecolor 透传：颜色降级到 8 / 256；diff highlight 难看。
    • 

  • 远程 SSH 用 Kitty keyboard：复杂键位偶发失效；Hermes 会日志 warn 并 fallback。
    • 

  • 以为换 terminal 要重 init：切 terminal 完全无需重 init，数据在同一 storage。
    • 

  • 同时跑多 mcp-serve：一个 storage 只能一个 mcp-serve 进程；多个会写 lock-conflict。
    • 



小结
    

  • 7 后端：macOS Terminal / iTerm2 / Ghostty / kitty / wezterm / tmux / WSL。
    • 

  • 关键差异：TUI / 颜色 / 键位协议 / OSC 52 / 嵌套兼容性。
    • 

  • 决策树：macOS 推 Ghostty/iTerm2、Linux 推 kitty/wezterm、Windows 走 wezterm+WSL。
    • 

  • 多窗口加 tmux 嵌套，远程 SSH 注意 keyboard protocol fallback。
    • 

  • 数据共享：单设备多 terminal OK，多设备 mesh 走 Hermes sync 协议。
    •
