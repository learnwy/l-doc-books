OpenClaw 安装与首次 tenant 创建

核心概念

OpenClaw 的上手路径分两步：先把二进制装好（npm / Homebrew / Docker 三选一），再用 openclaw init 创建第一个 tenant、注册第一个 persona、配置个人 email 与 identity。本节按"安装 → init → status 健康检查"线性走一遍，目标是让读者在 15 分钟内拿到一个能跑的 OpenClaw 实例。

三种安装路径
OpenClaw 官方提供三种安装路径，对应不同的运维偏好。






安装方式
适合场景
优势
劣势





npm npm i -g openclaw
Node 生态熟悉的开发者
一键升级 / 与 Node 项目共存
依赖系统 Node 版本




Homebrew brew install openclaw
macOS 桌面开发者
与系统包管理一致
Linux 不支持




Docker docker pull openclaw:latest
服务器 / 隔离环境
环境完全隔离 / 易于回滚
端口映射 / 文件挂载





三种方式装出来的二进制行为完全一致；选择只是部署环境差异。本节示例以 npm 路径为主，其它两种在 5_deployment-modes.md 详细展开。


npm 安装步骤
node --version          # 验证 Node >=18
npm i -g openclaw       # 全局安装
openclaw --version      # 验证安装成功
如果遇到 EACCES 权限错误，建议用 nvm 管理 Node 而不是 sudo——sudo 装 global package 会污染系统目录，后续升级与回滚都很痛苦。


Homebrew 安装步骤
brew tap openclaw/tap    # 一次性 tap 官方仓库
brew install openclaw    # 安装
openclaw --version       # 验证
brew upgrade openclaw    # 后续升级
Homebrew 路径会自动管理依赖（如 sqlite、libssl），不需要单独装。


Docker 安装步骤
docker pull openclaw/openclaw:latest
docker run -d \
  --name openclaw \
  -v $HOME/.openclaw:/root/.openclaw \
  -p 8080:8080 \
  openclaw/openclaw:latest
docker exec openclaw openclaw --version
Docker 路径要把 $HOME/.openclaw 挂出来——这是配置 / persona / audit log 的家目录，没挂出来下次启动数据就丢了。


首次 init：创建 tenant + persona
二进制装好后，第一步永远是 openclaw init。本节按交互流程拆开。


openclaw init
init 会依次问几件事：


    

  1. tenant name：建议用"组织 / 个人"语义命名，如 personal / acme-corp；后续 audit log 与 key 都按 tenant 隔离。
    2. 

  2. first persona name：建议从最常用的 hat 开始，如 dev；persona 的命名空间是后续切换的依据。
    3. 

  3. persona identity：填 email 与 display name，会作为 chat platform onboarding 时的默认 identity。
    4. 

  4. storage path：默认 ~/.openclaw，可改；Docker 用户记得这个路径要与 -v 挂载点匹配。
    5. 



完成后会生成两份文件：


    

  • ~/.openclaw/config.yaml：tenant + persona 元配置。
    • 

  • ~/.openclaw/personas/dev/credentials.yaml：persona 级 key/secret 占位（首次为空，下一节填）。
    • 



配置 persona 的 personal email 与 identity
identity 是 persona 的"对外身份"，影响后续两件事：


    

  • chat platform onboarding 时，OAuth 回调与 identity 绑定，错配会导致 webhook 路由不到。
    • 

  • coding agent 通过反向 MCP 拿到 persona.active tool 时，返回值里包含 identity 信息，被 agent 用于生成"以谁的口吻"的 message。
    • 



编辑 ~/.openclaw/personas/dev/identity.yaml：


persona: dev
display_name: 'Wang Yang (dev)'
email: dev@example.com
signature: '— sent via OpenClaw / dev'
languages: [zh-CN, en]
default_chat_platform: feishu
signature 会在每条 outbound message 末尾自动追加（可关），便于接收方识别"这是 agent 发的，不是人工"。


openclaw status：健康检查
init 完成后，跑一遍 status 看健康：


openclaw status
输出大致结构：


tenant: personal
  state: active
  personas: 1
    - dev (state=active, chat-platforms=0, last-message=never)
  audit-log: enabled (retention=30d, exported=false)
  reverse-mcp: not-listening (run `openclaw mcp-serve` to start)
  storage: ~/.openclaw (free=120GB)
每行的含义：


    

  • state: active 表示 tenant 已就绪；若是 pending 说明 init 中途中断，重跑 init 即可。
    • 

  • personas 行列出当前 tenant 下所有 persona，逗号后的字段是该 persona 的健康摘要。
    • 

  • audit-log 行确认审计开启状态；生产建议 exported=true（导出到 SIEM）。
    • 

  • reverse-mcp 行表示是否在监听反向 MCP 端口；要让 coding agent 调用 OpenClaw 必须先 openclaw mcp-serve 起来。
    • 

  • storage 行确认数据目录与可用空间。
    • 



启动反向 MCP server
到这一步 OpenClaw 本体已就绪，但 coding agent 还连不进来。最后一步是启动反向 MCP server：


openclaw mcp-serve --port 8765 &
启动后，在 Claude Code / Codex 的 MCP 配置里加：


{
  "mcpServers": {
    "openclaw": {
      "command": "openclaw",
      "args": ["mcp-stdio"]
    }
  }
}
下次 coding agent 起 session 就能看到 persona.switch / message.send / route.list 等 tool 可用。


陷阱与常见问题
    

  • init 跑两次：第二次 init 不会清旧数据但会改 config.yaml；建议先 backup ~/.openclaw。
    • 

  • persona name 用空格 / 中文：路由规则与文件路径用 persona name 拼接，建议只用 [a-z0-9-]。
    • 

  • email 与 chat-platform OAuth 不一致：下一节 chat-platform onboarding 时 OAuth 回调会比对 email；不一致就会报 identity mismatch。
    • 

  • 忘记跑 openclaw mcp-serve：coding agent 看不到 tool 时第一件事就是 status 看 reverse-mcp 行。
    • 

  • Docker 没挂存储：容器重启数据丢失；务必 -v 挂卷。
    • 



小结
    

  • 三种安装路径：npm（开发者）/ Homebrew（macOS 桌面）/ Docker（隔离环境）。
    • 

  • 首次 init 创建 tenant + persona + identity，生成 ~/.openclaw/config.yaml。
    • 

  • openclaw status 是健康检查入口，逐行确认 tenant / persona / audit / mcp / storage 状态。
    • 

  • 最后 openclaw mcp-serve 启动反向 MCP server，coding agent 才能调用。
    • 

  • 下一篇 4_chat-platform-onboarding.md 接入第一个 chat platform。
    •
