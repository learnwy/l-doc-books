OpenClaw 速览 简介

OpenClaw 是 Tier 2 personal-agent 阵营里"多租户 chat-platform 编排"方向的代表工具，定位是把"一个用户的多个 persona（dev / OSS contributor / personal projects）"与"多个 chat platform（飞书 / Slack / Telegram / Discord）"通过显式路由规则连成同一个 agent 资产；coding 工具（Claude Code / Codex）通过反向 MCP 拿到 persona switch / message route / channel send / tenant list 等 tool，把"角色化沟通能力"接入编程会话。

适合读者主要有三类：单个开发者扮演多个角色（白天工作 persona / 晚上 OSS persona / 周末 hobby persona）需要严格隔离的多 hat 用户；想把团队 chat-platform 内的 agent 调度集中起来的技术负责人；以及对 multi-tenant 安全模型（per-tenant key、isolated workspace、audit log）感兴趣的工程师。读者只需会跑过一次 coding agent；如对反向 MCP 还不熟，请回 ../../../01_coding-tools/3_mcp/3_reverse-mcp-and-pitfalls/。

本章六篇 L4 按"先理解、再上手、最后配置"三对递进。

定位对（1-2）：1_identity-and-positioning.md 讲 OpenClaw 的身份与定位——multi-tenant chat-platform router + 多 persona 隔离设计哲学、与 Claude Code / Hermes 的角色分工；2_use-cases-and-target-users.md 讲适用场景与目标用户——多 hat 个人开发、团队内多 agent 编排、安全要求高的企业场景。

上手对（3-4）：3_install-and-first-tenant.md 讲安装路径（npm / Homebrew / Docker）+ 首次创建 tenant + 注册第一个 persona；4_chat-platform-onboarding.md 讲接入第一个 chat platform（OAuth 授权 / webhook 配置 / 路由规则起步）。

配置对（5-6）：5_deployment-modes.md 讲四种部署形态（launchd macOS / systemd Linux / Docker 容器 / iOS node 本地节点），每种的 trade-off 与生产 vs 本地差异；6_security-and-audit.md 讲 per-tenant key 隔离、audit log 设计、与企业 Compliance 接入点。

推荐学习路径是按 1→2→3→4→5→6 顺序走一遍；只关心安全 / 部署的运维直接看第 5-6 篇；多 hat 用户优先看第 1-3 篇。深入 multi-tenant personas 路由算法、persona switch tool 的反向 MCP 调用请转 ../../../02_personal-agents/6_multi-tenant-personas/。

本节内容定位：因 OpenClaw 的部分对外 framing（如 "破 React 十年纪录"）未在 Wikipedia / 官方 about 找到独立佐证，本章只保留可验证事实（如 350k+ stars 数字），不复述未经证实的 marketing 表述。
