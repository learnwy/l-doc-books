reverse-MCP：Tier 1 工具反向调用 Tier 2 server

核心概念

Tier 1 coding-tools（Claude Code、Codex CLI）2026 年起把 Tier 2 personal-agent 工具（Hermes、OpenClaw）当作 MCP server 反向调用。这是与 bundled skill 委派（./1_hermes-bundled-claude-code-skill.md）完全相反的方向：bundled 是 Tier 2 主动调 Tier 1，reverse-MCP 是 Tier 1 主动调 Tier 2。Claude Code 在 .mcp.json 里注册一行 hermes mcp serve，启动会话时通过 stdio JSON-RPC 拉 memory / persona / curator schedule 当作"软上下文"注入到当前 prompt，写完代码后再 memory_write 回写关键决策。这种"动态 context 注入"模式让长会话拥有跨会话连续记忆，是 ../../../02_personal-agents/2_modules-deep/3_mcp-bidirectional/ "双向 MCP"视角的 client 端落地。

协议层：.mcp.json 与 mcp_servers 配置
Claude Code 通过 .mcp.json 注册：


{
  "mcpServers": {
    "hermes": {
      "command": "hermes",
      "args": ["mcp", "serve"],
      "env": {
        "HERMES_HOME": "/Users/me/.local/share/hermes"
      }
    },
    "openclaw": {
      "command": "openclaw",
      "args": ["mcp", "serve", "--tenant", "engineering"]
    }
  }
}
Codex CLI 等价的 ~/.codex/config.toml：


[mcp_servers.hermes]
command = "hermes"
args = ["mcp", "serve"]

[mcp_servers.openclaw]
command = "openclaw"
args = ["mcp", "serve", "--tenant", "engineering"]
启动 Claude Code 后，stdio JSON-RPC 立刻握手：client 发 initialize → server 回 tools/list 告知有哪些 tool 可调 → client 把 tool 列表交给 LLM 作 system prompt 一部分。整个生命周期跟普通 MCP server 完全一致，只是这里 server 是 personal-agent 工具而不是外部 SaaS。


Tier 2 暴露的"软上下文 tool" 类别
reverse-MCP 实际可用的 5 类 tool（详细 schema 见 ../../../02_personal-agents/2_modules-deep/3_mcp-bidirectional/1_server-side-impl-hermes.md）：

"软上下文"指这些 tool 不直接改 user 文件系统、不直接调外部 API，只读写 personal-agent 内部 state（memory DB、persona registry、curator schedule）。这一约束让 reverse-MCP 安全边界清晰：Tier 1 拉的都是 user 自己积累的私有上下文，不会触发不可预期的外部副作用。


典型工作流：会话启动 → 写代码 → 回写
完整 sequence：


这个工作流体现 reverse-MCP 的双向价值：拉历史决策让当前 prompt 更具上下文一致性、写新决策让未来会话不重复同一讨论。整个过程对 user 透明——user 只看到 Claude Code 在用"看起来很对"的方式回答，并不需要知道 Hermes 在背后参与。


reentry-guard 与环检测
reverse-MCP 与 bundled skill 配合在 design 上可能形成环：Claude Code 调 hermes（拉 memory）→ hermes curator 检测到需要写代码 → bundled skill 启动新 Claude Code subprocess → 新 subprocess 再调 hermes → ...无限增长。reentry-guard 是必须设计：


具体规则：每次 MCP 调用在 X-Call-Chain header（自定义 metadata 字段）维护一个 path 列表，记录已访问的 tier-工具对（如 ["tier1:claude-code", "tier2:hermes"]）。任何节点检测到自己即将再次出现在 path 里 → 抛 reentry_blocked error 上层。


    

  • depth 上限 = 1：同 call chain 最多 1 层跨 tier 调用（Tier 1 → Tier 2 = 1 层；再 Tier 2 → Tier 1 就是第 2 层，触发 guard）。这与双向 MCP 通用 depth=2 是同一框架的更严格 client 侧配置。
    • 

  • timeout = 10 秒：单次 MCP call 超过 10 秒 fallback 到不拉 context、走纯 LLM 模式。防止 Hermes server hang 卡住整个会话。
    • 

  • 环检测：path 包含同一节点 → 即刻 reject，不等 depth 上限。
    •

超限后 Claude Code 不 hard-error，而是 graceful degrade："本会话已耗尽 hermes budget，后续不再注入 memory context，需要时请手动重启会话"——user 仍然能正常用 Claude Code，只是失去 reverse-MCP 增益。


与 Tier 2 server-side 视角的对应
../../../02_personal-agents/2_modules-deep/3_mcp-bidirectional/ 整章从 Tier 2 server 角度讲"Hermes / OpenClaw 如何把自己实现成 MCP server"，包括 mcp serve subcommand 设计、tool schema、reentry-guard server 侧实现等。本篇是 client 侧——从 Claude Code / Codex 的角度看"如何接入这个 server、什么时候触发哪个 tool、超出 budget 如何降级"。两边视角合在一起才是完整的双向 MCP 图景。


server 侧关心：tool schema 如何让 client 容易消费、并发请求如何串行化、reentry-guard 拒绝时返回什么 error code。client 侧关心：会话生命周期里何时拉 context、tool 失败时如何 fallback、budget 用尽时如何对 user 解释。两边的协议契约在 MCP spec 2025-11 Streamable HTTP + OAuth 2.1（见 ../../../01_coding-tools/3_mcp/）里规定。


陷阱与常见问题
    

  • Hermes server 启动慢 → 会话冷启延迟：hermes mcp serve 启动 cold 可能 2-3 秒（要加载 SQLite + memory index）。修复：用 hermes mcp serve --warm 后台预热；或在 .mcp.json 加 timeout_initialize: 5000 容忍冷启。
    • 

  • memory_query 返回噪声 entry：query 太宽（如 "code"）→ 检索回 30 条不相关的，污染 prompt。修复：query 加 tag filter，或要求 min_importance: 0.5。
    • 

  • memory_write 副作用未隔离：Claude Code 写错代码后 memory_write 也把错误经验落进 memory。修复：curator 通过 candidate → promote 通道延迟 ingestion；user 可在 Hermes UI 手动 reject。
    • 

  • 同一进程多 Claude Code instance 共享 hermes：两个 Claude Code 标签页 + 同一 hermes server → memory_write 竞争。修复：hermes server 内部把 write 串行化（详见 ../../../02_personal-agents/2_modules-deep/3_mcp-bidirectional/3_dual-role-process-architecture.md）。
    • 

  • budget 用尽用户无感：fallback 后 Claude Code 行为"看起来一样但失去 memory 增益"。修复：在 status bar 显式提示 "hermes budget exceeded, restart to reset"。
    • 



小结
    

  • reverse-MCP 是 Tier 1 工具反向把 Tier 2 当 MCP server 用的模式，.mcp.json / mcp_servers 配置一行接入，stdio JSON-RPC 通讯。
    • 

  • Tier 2 暴露的 5 类"软上下文 tool"（memory_query/write、persona_active、skill_dispatch、curator_schedule）只读写 personal-agent 内部 state，不触发外部副作用，安全边界清晰。
    • 

  • 典型工作流"拉历史决策 → 写代码 → 回写新决策"提供跨会话连续记忆，user 无感。
    • 

  • reentry-guard depth=1、timeout=10s、call-chain path 环检测三重防御，与 bundled skill 配合时务必启用避免无限递归。
    • 

  • Budget 管理 10 call / session、$0.5 cost 上限、graceful degrade 不 hard-error，超限后用 status 提示 user 重启 session 重置。
    • 

  • 与 ../../../02_personal-agents/2_modules-deep/3_mcp-bidirectional/ 的 server 侧视角互为镜像；选型决策见 ./4_selection-decision-framework.md。
    •
