.agents/skills/ 中性路径跨工具互通

核心概念

agentskills.io 在 2026 年的 spec 把 .agents/skills/<name>/SKILL.md 立为"跨 agent 工具中性路径"约定——它不绑特定 vendor、不属于任何 IDE 私域目录、commit 进 git 后所有兼容的 AI agent 工具都会自动扫描到。一份 SKILL.md 同时被 Claude Code / Codex / OpenCode / Cursor / Hermes / Aider 等十余款工具读取，是当下"一份源代码喂多 tier"的事实标准。这跟 Tier 1 的 .claude/skills/、Tier 2 的 ~/.config/hermes/skills/ 等 vendor-specific 路径互相补充：vendor 路径放只对那个工具有意义的 skill，中性路径放跨工具都能跑的通用能力。

"扫描 .agents/skills/"是 2026 年新加入工具的入门门槛——agentskills.io 没明文强制，但生态压力让 vendor 都加上了。Aider / Devin / Amp 这种"没自家目录"的工具直接把 .agents/ 当唯一来源，反而是路径互通最纯粹的实现。


mono-repo 共享：commit .agents/ 进 git
最大价值在团队层面。考虑一个典型 mono-repo：


my-monorepo/
├── .agents/
│   └── skills/
│       ├── review-pr/SKILL.md
│       ├── run-tests/SKILL.md
│       └── deploy-staging/SKILL.md
├── packages/
└── README.md
.agents/skills/ 进 git 提交后，所有团队成员、所有 AI 工具立刻共享：


    

  • 用 Claude Code 的同事拉代码 → .agents/skills/review-pr 自动可用
    • 

  • 用 Codex 的同事拉代码 → 同一份 skill 也可用，行为一致
    • 

  • 切到 Cursor 评审分支时 → 还是同一份 skill
    • 

  • 新人入职 clone 仓库 → 不需要任何额外配置就拿到团队所有自动化能力
    • 



对比 .<tool>/skills/ 的局限：


my-monorepo/
├── .claude/skills/review-pr/   # 只 Claude Code 看到
├── .codex/skills/review-pr/    # 必须 fork 给 Codex
└── .cursor/skills/review-pr/   # 又得复制一份
这种重复维护模式在团队规模超过 5 人或工具栈超过 2 个时迅速失控——bug 修一处其他三处忘了改、prompt 调优各家分叉。把通用能力收敛到 .agents/ 是 single source of truth。


路径优先级与跨 tier 触发先后
同名 skill 出现在多个路径时谁先生效？以 Claude Code 为例的实际优先级：


实际效果是"越靠近代码越优先"——plugin 厂商可以 ship default，project 可以覆盖、user 可以再覆盖。在跨 tier 工作流里，这条优先级链解释了一类常见现象：user 在 Hermes 里写了 ~/.config/hermes/skills/review-pr，但 Claude Code 触发同名 skill 时用的是 .agents/skills/review-pr 那份——两个工具看到的不是同一文件，因为各自的扫描根集不一样。Hermes 看 ~/.config/hermes/skills/ + .agents/，Claude Code 看 .claude/ + .agents/，交集只有 .agents/。


一份源代码喂多 tier 的实际优势
中性路径在工程实践层面有四项可量化收益：


    

  • 维护成本下降到 1/N：N 是工具数。10 人团队 + 3 个工具 = 之前 30 处维护点，现在 10 处。
    • 

  • 跨工具能力对称：用 Claude Code 跑出来的结果，换 Codex 跑应该一致（同一 prompt 同一 allowed-tools）。"换工具丢能力"这个用户痛点被解决。
    • 

  • skill 升级一次全 propagate：修一处 prompt typo，所有人所有工具下次启动自动拿到新版。
    • 

  • 新人 onboarding 接近零：clone 仓库 + 选任一兼容工具 → 立刻拿到全部团队 skill。前 agentskills.io 时代新人需要为每个工具配私域目录，至少 1-2 小时。
    • 



反例：tier-specific 功能不应放 .agents/
中性路径不是万能的——有些 skill 必须留在 vendor 目录：


    

  • Hermes GEPA evolution hook：依赖 hermes.curator.memory_evolved event，其他工具没有这个 event 源。放 .agents/ 让 Claude Code 看到只会触发"无效 skill"的困惑。
    • 

  • OpenCode plugin hook：OpenCode 的 onPromptSubmit extension hook 在其他工具里没有对应 lifecycle。
    • 

  • Claude Code /loop、/schedule 系统命令封装：用到 Claude Code 私有 CLI 子命令。
    • 

  • Cursor 多文件 apply：依赖 Cursor 的 inline diff UI。
    • 

  • OpenClaw tenant 数据回写：依赖 OpenClaw 的 multi-tenant 上下文。
    • 



判断准则：skill 若依赖某 vendor 的 hook、lifecycle、UI、内部 state，应放 vendor 私域目录；放 .agents/ 后非支持工具会静默忽略 vendor extension 字段——表面看 skill "存在"，运行时却找不到 hook、出错信息 cryptic、user 困惑度高。明确划界后排查路径很短。


陷阱与常见问题
    

  • .agents/ 提交到 git 但 .gitignore 漏配：常见误删——某 IDE 的 "smart cleanup" 把没用到的 .agents/ 当垃圾清。修复：在仓库根 .gitattributes 加 *.md linguist-documentation=false，或在 README 明示该目录是 source of truth。
    • 

  • 同名 skill 多路径不一致：plugin 提供 review-pr v1.0，user 又在 .agents/ 写了自己的 v0.9 fork，结果触发 plugin 版本（因为优先级更高）。修复：检查实际生效路径用 claude --list-skills / codex skill ls --resolved 等命令。
    • 

  • vendor 字段静默忽略导致 cryptic 失败：在 .agents/ 放了一个含 cursor.applyToWorkspace: true 字段的 SKILL.md，Cursor 解析了，但 Claude Code 静默 ignore 该字段，运行时行为不一致。修复：vendor-only 字段一律放 vendor 私域目录或加显式注释。
    • 

  • user 全局 vs project 优先级混淆：~/.agents/skills/foo 与 .agents/skills/foo 同时存在，多数工具的默认 project > user，但有的工具反过来（Cursor 实测 workspace > project > user）。修复：跨工具协作前在团队 wiki 明确每个工具的 resolution rule。
    • 



小结
    

  • .agents/skills/<name>/SKILL.md 是 2026 跨工具中性路径事实标准，agentskills.io spec 推荐、12 款主流 AI agent 工具已适配。
    • 

  • mono-repo commit .agents/ 进 git 是 single source of truth：维护一份、跨工具对称、升级一次 propagate、新人零成本 onboarding。
    • 

  • 路径优先级 plugin > project .agents/ > project .<tool>/ > user ~/.agents/ > user ~/.<tool>/ > builtin；跨 tier 时各工具扫描根集不同，交集只有 .agents/。
    • 

  • 反例：依赖 vendor hook / UI / lifecycle 的 skill 必须留 vendor 私域；放 .agents/ 在非支持工具中静默失败、cryptic 难排查。
    • 

  • 选型层面：纯静态 prompt 共享走本路径；需要 runtime 跨 tier 调用走 ./1_hermes-bundled-claude-code-skill.md / ./3_reverse-mcp-tier-2-as-server.md；总决策框架见 ./4_selection-decision-framework.md。
    •
