跨 Tier 编排核心范式 简介

本章把跨 Tier 协作的四个核心范式集中讲清：bundled skill 委派、Skills 路径互通、reverse-MCP、选型决策框架。每个范式给出"协议层契约 + 典型工作流 + 安全 / budget 约束 + 反例"，让读者建立完整的"什么场景该用哪一个"决策模型。

本章包含四篇 L4 文档。

1_hermes-bundled-claude-code-skill.md —— Hermes 官方 bundled claude-code skill。一种 Tier 2 → Tier 1 单向委派模式：Hermes 在合适时序（用户请求编程任务 / curator 检测代码相关 memory 需要更新）触发 Claude Code 子进程跑 coding 任务、把 stdout 与 final result 回收到 Hermes memory。bundled skill 的 SKILL.md frontmatter、调用协议（stdio invoke claude -p headless 模式 / 传 context / 接 stdout）、错误处理（subprocess crash / timeout / cost budget exceeded）、与 Hermes curator 的协同。

2_skills-path-interop.md —— .agents/skills/ 中性路径的事实标准。agentskills.io spec 推荐的跨工具中性目录，让 Claude Code / Codex / OpenCode / Hermes / VSCode Copilot 都能扫到同一份 SKILL.md。Mono-repo 共享模式（commit .agents/skills/ 进 git，所有团队成员的所有工具自动可用）。路径优先级 (plugin > project > user) 与跨 tier 触发先后。一份源代码喂多 tier 的实际优势：维护一份不维护四份、跨工具能力对称。

3_reverse-mcp-tier-2-as-server.md —— Tier 1 工具反向调用 Tier 2 server。Claude Code 通过 .mcp.json 接 hermes mcp serve / openclaw mcp serve，把 Tier 2 当作 "软上下文 server"（memory / persona / skill 等）。协议层是 MCP stdio + reentry-guard。典型工作流：Claude Code 启动会话 → MCP 拉 hermes memory 作 context 注入 → 写代码 → memory_write 回写决策；与 ../../../02_personal-agents/2_modules-deep/3_mcp-bidirectional/ 的"双向"视角对应。

4_selection-decision-framework.md —— 跨 tier 编排选型决策树。四个 pattern 的适用 conditions: bundled skill（Tier 2 主导 + 单向 + 需要返回结果到 memory）/ Skills 路径互通（无 runtime cross-call，纯静态共享 prompt）/ reverse-MCP（Tier 1 主导 + 长会话 + 需要 dynamic context 注入）/ 纯独立运行（两 tier 完全 decouple，互不调用）。决策树（场景：需要 cross-tier state share？→ 是 → 单/双向？→ Tier 2 主调用 → bundled skill；Tier 1 主调用 → reverse-MCP；否则 → Skills 互通 / 完全 decouple）。anti-pattern 警示：递归调用（A→B→A）必须严防，每条 pattern 都有 reentry-guard。

学习建议按章节顺序读完即可；选型阶段先看 4_ 决策框架，再回查具体 pattern 细节。
