跨 Tier 编排与委派 简介

Tier 1 coding-tools 与 Tier 2 personal-agents 在 2026 年完成了从"两条独立工具栈"到"协议层互通"的演进——这里"协议层"指 MCP 反向调用、Skills 路径互通（.agents/skills/ 中性目录）、官方 bundled claude-code skill 委派模式三条具体通道。本 hub 不重新讲 MCP / Skills 基础协议（那些在 Tier 1 / Tier 2 的 module-deep 章节展开），只把"跨 tier 协作"作为独立设计问题分析：什么时候让 Tier 2 工具调 Tier 1、什么时候反向、什么时候让 Skills 在两 tier 间复用一份源代码、选型决策的判断框架。

适合读者主要有三类：同时使用 coding agent 与 personal-agent 工具的开发者（如用 Claude Code 写代码 + 用 Hermes 管 memory）；想搭建 multi-tier agent 工作流但担心递归调用与 budget 失控的架构师；以及做工具生态研究、关心 2026 跨 vendor 协作模式如何演化的研究者。读者需先熟悉 Tier 1 MCP 与 Tier 2 reverse-MCP 概念——分别在 ../../01_coding-tools/3_mcp/ 与 ../../02_personal-agents/2_modules-deep/3_mcp-bidirectional/ 展开。

本 hub 一章包含四篇 L4 文档，按"先看两种委派模式 → 再看路径互通 → 最后看选型"递进。

第 1 章 1_orchestration-patterns/ 把跨 tier 协作的四个核心范式集中讲清：第一篇 1_hermes-bundled-claude-code-skill.md 讲 Hermes 官方 bundled claude-code skill 的委派模式（Tier 2 → Tier 1 单向，Hermes 在合适时序触发 Claude Code 子进程跑编程任务、把结果回收到 memory）；第二篇 2_skills-path-interop.md 讲 .agents/skills/ 中性路径作为团队共享 skill 的事实标准——Claude Code / Codex / OpenCode / Hermes 都扫描该目录、一份源代码喂多 tier；第三篇 3_reverse-mcp-tier-2-as-server.md 讲 Tier 1 工具反向调用 Tier 2 server（Claude Code 调 hermes mcp serve 拉 memory / persona），把 Tier 2 当 "软上下文 server" 用；第四篇 4_selection-decision-framework.md 给跨 tier 编排的选型决策树（什么场景用 bundled skill / 什么用 reverse-MCP / 什么用纯 Skills 互通 / 什么不必跨 tier）。

推荐学习路径是按 1→2→3→4 顺序读，前三篇是三种独立 pattern，第四篇综合给决策框架。如果只关心其中一个 pattern，直接进对应 L4 即可。MCP 协议本体请回 ../../01_coding-tools/3_mcp/；Skills 实现细节请回 ../../01_coding-tools/4_skills/。

版本冻结：本 hub 内容基于 Hermes Agent（NousResearch）/ OpenClaw / Claude Code / Codex CLI 截至 2026-05-14 的公开材料、agentskills.io spec、MCP spec 2025-11；事实主张优先 anchor 到可验证协议或官方 bundled skill 元数据，未独立验证的 framing 表述明确标注。
