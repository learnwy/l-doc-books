行业场景外部 source 链接索引

把"AI 编程代理在某行业是否值得引入"的问题拆成八个垂直领域，每个领域列 3-6 条外部 source（官方 case / 第三方博客 / 开源仓库示例）并标注"为什么值得读"。所有 link 都用描述性占位——具体 URL 请按描述自行 WebSearch 定位，避免引用过时或失效链接。本文 2026-05 锚定，行业划分参考 Anthropic Customers 与 OpenAI 官方 case study 页面的 industry tag、以及主流 engineering blog 的标签云。

核心概念

阅读本索引前先理解三件事。

第一，这是参考资料库而非综述——所有 claim 都需要按 link 追溯回原始 source 才能 cite。本 hub 不替读者背书具体行业的 ROI 数字，因为这些数字往往依赖具体团队规模、code base 复杂度、工具使用熟练度，无法外推。

第二，link 价值判断维度优先级是「官方 case > 公司 engineering blog > 个人长文博客 > HN 讨论 > GitHub 示例 repo」。官方 case 通常有数据但缺细节，engineering blog 有细节但常有 marketing 倾向，个人博客最真实但样本量小，HN 讨论补充失败案例，GitHub repo 给具体配置参考。

第三，领域间相互渗透——比如金融领域很多 AI coding 实践其实是从 Web 后端 + 安全这两个领域同时借鉴的。读完本索引后建议交叉对照 2_use-case-overview-synthesis.md 看跨行业 pattern。

Web 后端
Web 后端是 AI coding 工具最成熟的领域：SaaS / 电商 / 内容平台都有大量公开实战。看这个领域时重点关注「monorepo 重构、API 接口生成、framework 升级（如 Next.js / Rails major version）」这三类 use case，以及团队 size 与工具选型的相关性——小团队偏爱 Cursor / Codex Cloud 的 batch 模式，大团队偏爱 Claude Code 配合 Skills + Subagents 的可定制化。

Mobile（iOS + Android + 跨平台）
Mobile 的特殊性是 build 时间长、模拟器交互成本高，所以 AI 工具的价值更多在「UI 代码生成 + state 管理重构 + 跨平台 bridge 编写」而非端到端自动化。Native iOS（Swift）/ Android（Kotlin）/ 跨平台（React Native / Flutter / Lynx）三条线对工具的需求略有不同，建议分别看。

安全（security review / 渗透测试）
安全领域的 AI coding 应用主要分两线：防御端（自动 code review、SAST 集成、secret 扫描）与进攻端（自动化渗透测试脚本、漏洞 PoC 生成）。防御端实践更成熟、source 多；进攻端因合规与 dual-use 风险，公开 source 较少且多为 ethical hackers 个人分享。

元提示：跨领域读 source 的判断准则
读上面每个领域的 source 前先校准三件事：第一，区分 marketing 与实战——多数 engineering blog 包含 marketing 倾向，看到「提升 X% 效率」的数字优先怀疑统计口径；第二，关注团队 size 与 code base 复杂度——一个 5 人初创的实践不能外推到 500 人企业；第三，留意时间锚点——AI 工具 6 个月就一次大版本，2025 年初的 case 可能已与 2026 年实际能力差距很大。


更细的领域级元提示有五段。


Web 后端：重点看「framework 升级 + monorepo refactor」case，因为这两类最能体现 AI 工具相对人工的 ROI。SaaS 后端 API 生成 case 看得多了会麻木，价值低。


Data engineering：优先看含 benchmark 数据的 case——AI 写 SQL 容易出幻觉，没 benchmark 的 case 不可信。dbt / Airflow 领域 case 比 ML 训练脚本更可参考，因为变量更少。


DevOps & SRE：看 case 时区分「agent 只读 advisory」vs「agent 写 apply」。前者门槛低、ROI 中等；后者门槛高、ROI 高但风险也高。


安全：防御端 case 看 false positive rate（误报率）是关键指标；进攻端 case 看 ethical & legal disclaimer 是否清晰。


金融 / 医疗 / 游戏与嵌入式：这三个 niche 领域 case 少，但每一个都值得深读——尤其留意合规 / 性能 / 工具链约束如何与 AI agent 的"自动化"诉求冲突。
