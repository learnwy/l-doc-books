Managed settings 与 admin override 强制策略

写好 AGENTS.md baseline 之后，下一道防线是把"用户不能改的策略"硬编码到 OS 级配置里——这就是 managed settings 要解决的问题。2026-04 之后 Anthropic、OpenAI Codex、OpenCode 三家都补齐了对应机制，本篇按文件路径、字段含义、推荐 baseline、三家对照展开。

核心概念

managed settings 的核心特征是 OS 级路径 + tamper-resistant + admin-only writable。它通过企业 MDM（Jamf 在 macOS、Intune 在 Windows、Kandji 跨平台）下发到设备指定路径，agent 启动时按 managed > user > project 优先级合并，managed 字段一旦设置，user / project 同名字段静默失效。

managed 字段被覆盖时 agent 不会报错——只会在 startup 日志打 info 行，这是有意设计：让企业策略 silent enforce 而不打扰 dev。


Claude Code managed-settings.json 路径
Anthropic 2026-04 admin controls release 之后，managed-settings.json 在三个平台有固定路径：


    

  • macOS：/Library/Application Support/ClaudeCode/managed-settings.json
    • 

  • Linux：/etc/claude-code/managed-settings.json
    • 

  • Windows：C:\ProgramData\ClaudeCode\managed-settings.json
    • 



这三个路径都需要 root / admin 权限写入，普通 user 即便 chmod 也改不了——这是 OS 级文件权限，不是 Claude Code 进程内 check，所以 tamper-resistant。如果 MDM 下发失败（如 endpoint 离线 24h），agent 会按 user / project settings 退化，但 不会 把 managed deny rule 当成 allow——deny 规则只要 managed 文件存在就生效。


推荐 baseline managed-settings.json
下方是一份在企业部署中验证过的最小 baseline，专门 enforce 那些 "用户绝对不该绕过" 的安全字段。


{
  "$schema": "https://anthropic.com/schemas/claude-code/managed-settings/v1.json",
  "permissions": {
    "deny": [
      "Bash(rm -rf *)",
      "Bash(sudo *)",
      "Bash(curl * | bash)",
      "Bash(*production* mysql *)",
      "WebFetch(*://internal.acme.com/*)"
    ],
    "ask": ["Bash(git push *)", "Bash(npm publish *)"]
  },
  "allowManagedMcpServersOnly": true,
  "managedMcpServers": {
    "sentry": { "command": "/opt/acme/mcp/sentry-readonly" },
    "datadog": { "command": "/opt/acme/mcp/datadog-readonly" }
  },
  "disableBypassPermissionsMode": true,
  "telemetry": {
    "endpoint": "https://otel.acme.com/v1/traces",
    "required": true
  }
}
关键字段含义：


    

  • disableBypassPermissionsMode: true 关闭 claude --dangerously-skip-permissions 命令行 flag——这是 Claude Code 让 dev 一键绕过所有 permission 的开关，企业部署必须关
    • 

  • allowManagedMcpServersOnly: true 与 enableAllProjectMcpServers 互斥；开启后 dev 仓库内的 .mcp.json 任何 server 都不加载，只跑 managed 列表
    • 

  • permissions.deny 用 first-match wins，写在 managed 里之后 user / project 同名 allow 无效
    • 

  • telemetry.required: true 强制 OTel export，dev 不能本地关
    • 



Codex requirements.toml
OpenAI Codex 的 admin override 文件叫 requirements.toml（不是 config.toml，这俩并列存在），位置：


    

  • 用户级：~/.codex/requirements.toml（仅作为 fallback，admin 一般用下方）
    • 

  • 系统级：/etc/codex/requirements.toml（Linux / macOS）或 C:\ProgramData\codex\requirements.toml（Windows）
    • 



合并规则与 Claude Code 类似——系统级 requirements 覆盖 user config.toml，冲突字段 静默忽略 user 值，但 Codex 会在启动时打 warning（不是 info），明确告诉 dev "某字段被企业策略覆盖"。


# /etc/codex/requirements.toml
[permissions]
# 这些 tool call 永远不允许，user config.toml 无法覆盖
deny = [
  "shell:rm -rf",
  "shell:sudo",
  "network:internal.acme.com"
]

[model]
# 强制只能用 GPT-5（成本与合规考虑）
allowed = ["gpt-5", "gpt-5-mini"]

[telemetry]
required = true
endpoint = "https://otel.acme.com/v1/traces"
OpenCode managed settings + 远程配置
OpenCode 的 admin 机制最特殊：除了本地 managed settings，还支持 远程 .well-known/opencode 配置——agent 启动时按公司域名拉取，类似 OIDC discovery 文档的玩法。


.well-known/opencode 的好处是企业不需要 MDM 就能下发——只要员工设备能访问公司域名就生效；缺点是依赖网络，离线开发场景需要本地 managed settings 兜底。OpenCode 在 2026-Q1 加了 RBAC 协同——远程配置可声明 "field X 仅 role admin 可改"，agent 启动时拿 SSO token 找 RBAC server 验权后才决定是否 apply。

选型上：纯 Anthropic 栈的团队用 Claude Code managed-settings；多模型混合栈用 Codex requirements.toml（OpenAI 与 Anthropic 都能用）；强合规 + SSO 强制的金融 / 医疗团队优先 OpenCode 的 RBAC 协同。


陷阱与常见问题
    

  • 陷阱 1：endpoint 缓存导致 24h 才生效。MDM 下发后 agent 可能仍按旧 managed settings 跑；先在 staging endpoint 验证，再推 production。
    • 

  • 陷阱 2：把 user 该改的字段也 managed。比如 editor 主题、键位偏好——这种字段 managed 会让 dev 觉得"被绑架"，只 managed 安全相关 字段。
    • 

  • 陷阱 3：忘记 disableBypassPermissionsMode。漏这一条等于 deny rules 全形同虚设，dev 一个 --dangerously-skip-permissions 就绕过。
    • 

  • 陷阱 4：managed deny 与 project allow 冲突预期错。开发者常以为 project allow 能覆盖 managed deny——不能；managed deny first-match wins 是硬规则。
    • 

  • 陷阱 5：OpenCode 远程配置故障导致开发卡死。.well-known/opencode 拉取超时时默认 fail-closed；高可用部署要么开 fail-open + 本地 managed 兜底，要么 endpoint 部署在 CDN。
    • 



小结
    

  • managed settings 是 admin 不可绕过的 OS 级配置，按 managed > user > project 优先级合并。
    • 

  • Claude Code 的 managed-settings.json 在 macOS /Library/Application Support/ClaudeCode/、Linux /etc/claude-code/、Windows ProgramData\ClaudeCode\。
    • 

  • 推荐 baseline 必含三条：disableBypassPermissionsMode: true / allowManagedMcpServersOnly: true / OTel telemetry required。
    • 

  • Codex 用 requirements.toml，冲突时 warning + 静默；OpenCode 多一层远程 .well-known/opencode + RBAC 验权。
    • 

  • 重大变更前先 staging endpoint 验证，避免 24h endpoint 缓存导致回滚困难。
    •
