团队 AGENTS.md 六段式模板与 monorepo 多层加载

团队把 AI 编程代理推到 20 人以上时，第一件踩坑的事不是工具选型，而是每个开发者都按自己习惯写 AGENTS.md / CLAUDE.md，三周后规范分裂成五种方言。本篇给一份在 2026 多家中型团队验证过的六段式 baseline，外加 monorepo 多层加载方案，目标是读完直接 fork 到自己 agents/AGENTS.md.template。

核心概念

AGENTS.md / CLAUDE.md 是 agent 在每次会话启动时强制加载的"项目说明书"，它告诉 agent 三件事：项目是什么、能做什么操作、什么操作绝对不允许。Anthropic 与 OpenCode 在 2026-Q1 的官方建议是把它拆成 六段——项目背景 / 构建命令 / 测试规约 / 编码风格 / 禁区目录 / 安全约束——每段一到两段中文 + 必要的命令 / 路径，整文件控制在 200 行以内。

六段式 baseline 模板
下方是 2026 中型团队（Python + TypeScript 混合栈）通用 baseline，按段落注释了为什么这样写。


# AGENTS.md

## 项目背景

本仓库是 acme-platform，TypeScript + Node 20 + Postgres 的多租户 SaaS 后端。
主入口 `apps/api/`，共享代码在 `packages/`。读者可假设你已熟悉 NestJS。

## 构建命令

- 安装依赖：`pnpm install --frozen-lockfile`
- 开发服务：`pnpm dev`（自动起 :3000 与 :3001 调试端口）
- 生产构建：`pnpm build && pnpm start:prod`
- 数据库迁移：`pnpm db:migrate` —— 仅在 `apps/api/` 目录下运行

## 测试规约

- 改动 `packages/` 任何文件后必须跑 `pnpm test:unit`
- 改动 `apps/api/src/controllers/` 后必须跑 `pnpm test:e2e`
- 仅文档 / 注释改动可跳过测试，需在 commit message 注明 `[docs-only]`

## 编码风格

- ESLint 8.57 + Prettier 3.2（版本由 `.tool-versions` pin）
- 提交前自动跑 `pnpm lint:fix` —— 不要手动修复 lint
- TypeScript strict mode 已开，禁止新增 `any`，必须用 `unknown` + type guard

## 禁区目录

- `migrations/`：数据库迁移文件由 DBA 审核，agent 一律不写
- `vendor/`：第三方代码拷贝，禁止编辑
- `infra/terraform/`：基础设施代码，agent 仅可读不可写

## 安全约束

- 禁止 hardcode API key / DB 密码 —— 使用 `process.env.X` 并在 `.env.example` 注册
- 禁止新增对外 HTTP 调用，必须走 `packages/http-client/` 已审 outbound list
- 禁止把日志写到 `console.log` —— 用 `packages/logger/`，PII 字段会自动脱敏
这份模板的关键在 简短 与 可执行：每条规则都能被 agent 单步遵守，没有任何"推荐 / 最好 / 尽量"等模糊语。


monorepo 多层加载
monorepo 有 30+ 个 package 时，把所有规则塞进根 AGENTS.md 会把上下文撑爆。Claude Code / OpenCode / Codex 都支持多层加载，差别在于 加载顺序 与 边界控制：


    

  • Claude Code 从当前工作目录 walk-up 到 git root，沿途每个 CLAUDE.md / AGENTS.md 都加载，子目录覆盖父目录的同名段
    • 

  • OpenCode 用 instructions paths 在 opencode.json 显式拼装加载列表，顺序写死，最适合架构稳定的 monorepo
    • 

  • Codex 用 project_root_markers 限定 walk-up 边界（默认认 .git、pyproject.toml），防止误加载到 home 目录的祖先 AGENTS.md
    • 



实操原则：根 AGENTS.md 写跨子项目都成立的事（禁区、安全、提交规范），package 子目录的 AGENTS.md 只写该 package 独有的事（如 apps/api/ 写 NestJS module 拆分约定）。共享 skills（.agents/skills/<name>/SKILL.md）放在 root .agents/ 中性路径，三个 IDE 都能识别。


path-scoped 规则切片
整本 AGENTS.md 常驻 context 浪费 token，而 .claude/rules/*.md 支持 frontmatter globs: 按文件路径条件加载，让"TS 编码规则"只在你编 TS 时上场，编 SQL 时不污染。


---
description: TypeScript strict mode rules
globs:
  - '**/*.ts'
  - '**/*.tsx'
alwaysApply: false
---
# TypeScript 规则
- 禁用 any，用 unknown + 类型守卫
- 异步函数返回值必须显式标注 Promise<T>
- public API 必须有 JSDoc，agent 写代码时同步补
这种切片在 200 文件以上的项目里能把 baseline context 砍掉 40%，按 2026 多个 case study 的实测，agent 在 long-session 中的"漂忘规则"概率也明显下降。配套写法是把规则按主题拆——TS / Python / SQL / docs / migrations 各一个文件——而不是塞进单一 AGENTS.md。

OpenCode 的显式 paths 写法在 100+ package 的 monorepo 里反而是优势——新人改子项目时不会被无关父项目规则干扰。Codex 的 marker 机制最适合根目录与 home 目录之间 AGENTS.md 容易冲突的情况（个人 ~/AGENTS.md 别让它泄漏到企业项目）。


陷阱与常见问题
    

  • 陷阱 1：把"项目方法论"塞进 AGENTS.md。常见反例是 1500 行的 AGENTS.md 写满架构哲学，agent 反而抓不到 actionable 命令；保持 200 行硬上限。
    • 

  • 陷阱 2：子目录 AGENTS.md 重写父目录段。Claude Code 的覆盖是按段名 fuzzy match，不可靠；推荐子目录只 补充（写父目录没写的事），不 覆盖。
    • 

  • 陷阱 3：把 secret / token 写进示例。即便注释为示例，agent 也可能 quote 出来；用 <REDACTED> 占位。
    • 

  • 陷阱 4：rules 文件 frontmatter globs 写漏。漏 alwaysApply: false 会让规则常驻，等同于直接写进 AGENTS.md，达不到切片目的。
    • 

  • 陷阱 5：忽略提交规范段。不写就意味着 agent 按自己习惯起 commit message，跨人协作时 message 风格五花八门，CI 难以 lint。
    • 



小结
    

  • 团队 AGENTS.md 用六段式 baseline：项目背景 / 构建命令 / 测试规约 / 编码风格 / 禁区目录 / 安全约束，整文件不超 200 行。
    • 

  • monorepo 用多层加载：根写跨项目规则，package 子目录只写该包独有约定，三家工具的边界控制方式不同——Claude Code 自动 walk-up、OpenCode 显式列表、Codex 用 marker。
    • 

  • 共享 skills 放 .agents/skills/ 中性路径，三个 IDE 都能识别。
    • 

  • 用 .claude/rules/*.md + frontmatter globs: 按路径切片规则，避免常驻 context 浪费 token。
    • 

  • 写完模板先在 pilot 5 人组跑一周，再批量推到全团队；首版要短、要 actionable，比"全面"重要。
    •
