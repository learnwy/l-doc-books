团队 AGENTS.md 模板与 admin override 简介

团队规模化使用 AI 编程代理的两个最基础问题：规范怎么写、admin 策略怎么强制。本章用两篇 L4 直接给答案。第一篇是一份可直接落地的团队 AGENTS.md baseline 与 monorepo 模式；第二篇覆盖三款工具的 admin override 机制，让 ops / security 团队能把"不允许用户改的策略"硬编码进部署。

本章包含两篇 L4 文档。

1_team-agents-md-template-and-monorepo.md —— 团队 baseline 模板。第一块给出六段式 baseline：项目背景（一句话定位 + tech stack）/ 构建命令（npm run dev 等）/ 测试规约（哪些测试必须跑、什么时候跳过）/ 编码风格（lint、format 工具 pin）/ 禁区目录（agent 不可写的目录如 migrations/、vendor/）/ 安全约束（不允许 hardcode secret、不允许调外网 API 类）。第二块讲 monorepo 模式——根目录顶层 AGENTS.md + 每 package 的 subdir AGENTS.md（lazy-load）+ .agents/skills/ 中性路径共享团队 skills；OpenCode 用 instructions paths 显式拼装、Codex 用 project_root_markers 限定 walk-up 边界。第三块讲 .claude/rules/*.md path-scoped 切片——按 frontmatter globs: 让 TS 规则只在编 TS 时激活，避免常驻 context。

2_managed-settings-and-admin-override.md —— 三家 admin override 机制。第一块讲 Claude Code managed-settings.json —— 通过 MDM（Jamf / Kandji / Intune）推到 OS 级路径：macOS /Library/Application Support/ClaudeCode/managed-settings.json、Linux /etc/claude-code/managed-settings.json、Windows 对应 ProgramData 路径；这些路径的字段不能被 user 或 project settings 覆盖，且 OS-level tamper-resistant。第二块讲推荐 baseline managed-settings.json 字段——allowManagedMcpServersOnly: true 锁 MCP server 列表、disableBypassPermissionsMode: true 防 user 强行绕过 permission、organizational MCP allowlist。第三块讲 Codex requirements.toml——位置 ~/.codex/ 或 /etc/codex/、admin 字段与 user config.toml 冲突时静默忽略、启动打 warning。第四块讲 OpenCode managed settings——远程 .well-known/opencode 配置 + 本地 managed settings 覆盖逻辑、与 RBAC 协同。

学习建议是先读 1_ 拿到模板直接 fork、再读 2_ 决定推哪些字段进 managed settings；首次部署的 ops 团队可以把第 2 篇当 deployment checklist 用。
