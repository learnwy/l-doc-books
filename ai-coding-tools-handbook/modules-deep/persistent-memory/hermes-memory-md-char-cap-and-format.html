Hermes MEMORY.md 字符上限与格式

核心概念

Hermes 把"跨会话长期记忆"实现为单一可读文件 ~/.learnwy/hermes/MEMORY.md，而非数据库 dump。文件本身是 Markdown，但 Hermes runtime 严格执行头部 200 行 / 25KB 的硬截断：每次会话启动时只把头部装进 system prompt，剩余条目通过 FTS5 检索按需召回。这套设计来自 Claude Code auto-memory 的工程经验，但比 Tier 1 多两层：importance-score 排序的可维护性结构，以及由 curator 进程自动重写头部的演进闭环。

四个区块构成 MEMORY.md 的物理结构：frontmatter 元数据 / body 条目正文 / importance 评分边带 / tags 索引侧栏。Hermes runtime 按这个固定布局解析，curator 按这个布局回写。

200 行 / 25KB 双重截断
为什么是 200 行同时 25KB 而不是单维度限制？因为 Markdown 单行可以长达数 KB（粘贴的 JSON 或 stack trace），单一行数限制会让一条 dump 占满预算；反过来单一 byte 限制对于密集要点排版又太松。Hermes 取 min(行数 <= 200, byte <= 25KB) 两个条件，谁先触达谁截断。


实现层面，截断不是"把后续条目删掉"，而是保留 importance score 最高的 K 条，剩余条目挪到文件尾的"cold storage"段。Cold storage 段不进 system prompt，但仍被 FTS5 索引，memory_query 工具可以访问。这意味着低 importance 不等于丢失，只是不再"白嫖"上下文预算。


---
version: 2.4
last_curator_run: 2026-05-13T03:00:00Z
entry_count: 187
hot_byte_size: 24317
cold_byte_size: 86419
---

importance score 计算
每条条目的 importance 不是固定值，curator 周期重算。三个因子加权：






因子
权重
信号来源





recency
0.3
最近被 memory_query 命中或被用户引用的天数




relevance
0.4
与活跃 persona / project 标签的 cosine similarity




user_signal
0.3
显式 pin / explicit /memorize / 用户更正频次





公式：


importance=0.3⋅σ(recency_days−1)+0.4⋅cos⁡(ventry,vpersona)+0.3⋅user_signal\text{importance} = 0.3 \cdot \sigma(\text{recency\_days}^{-1}) + 0.4 \cdot \cos(v_{\text{entry}}, v_{\text{persona}}) + 0.3 \cdot \text{user\_signal}importance=0.3⋅σ(recency_days−1)+0.4⋅cos(ventry​,vpersona​)+0.3⋅user_signal
其中 σ\sigmaσ 是 sigmoid，vvv 是 embedding。新条目默认 importance=0.5，第一次 curator 跑过后才有 reasoned 分数。


与 Claude Code auto-memory 对照
Tier 1 的 Claude Code 也有 auto-memory（~/.claude/projects/<slug>/memory/MEMORY.md），但是 session 级——每个 working directory 起一个独立文件，跨工程不共享。Hermes MEMORY.md 是 全局单实例，所有 persona / project 都从同一份长期记忆抽取。

## 飞书 lark-cli auth login 一年 expires 一次

<!-- importance: 0.78, tags: lark,workflow -->

每年 5 月需要重新 `lark-cli auth login`,token 自动失效。提示用户而非
自行尝试 reset secret。
陷阱与常见问题
    

  • 以为编辑 MEMORY.md 立刻生效：runtime 在 session 启动时一次性读入头部，session 内不重读。改完需要重启 shell 或调 hermes memory reload。
    • 

  • 手写超长行触发硬截断：单行 5KB 的 JSON dump 会把后面 5-10 条都挤进 cold storage。建议长 dump 用 link 引用而非内联粘贴。
    • 

  • 绕过 curator 直接改 importance：手动编辑 <!-- importance: 0.99 --> 在下次 curator 跑时会被覆盖。要"钉"一条目用 frontmatter pinned: [entry_id] 字段。
    • 

  • 混用 Claude Code 与 Hermes 心智模型：两边截断策略不同，写 prompt 时不要假设它们一致。
    • 



小结
Hermes MEMORY.md 在"单文件 Markdown + 严格头部预算 + cold storage 兜底 + importance 自维护"四点上凝聚了 2026 personal-agent 工具栈对长期记忆的工程共识——不依赖向量数据库、不靠 RAG 重建上下文，靠 200 行硬约束逼用户和 curator 共同保持 signal-to-noise。Importance score 把"哪些信息值得占预算"的决策外化为可观测的浮点，curator 周期重排让记忆系统自身演进。下一篇看 OpenClaw 的"三件套"方案如何用三个独立文件分层取代 Hermes 的"单文件四区块"。
