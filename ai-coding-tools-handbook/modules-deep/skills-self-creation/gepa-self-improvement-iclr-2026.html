GEPA 反思式 prompt 演化（Genetic-Pareto）

核心概念

GEPA 是 ICLR 2026 Oral 论文 Genetic-Pareto: Reflective Prompt Evolution（arXiv:2507.19457）提出的算法，把"用强化学习对 LLM 后训练"那套思路替换为"对 prompt 本身做演化"。三个组件构成 GEPA 名字：Genetic 借遗传算法的 candidate population / mutation / selection 框架；Pareto 用多目标 Pareto 前沿替代单一适应度，避免局部最优；Reflective 突破点——mutation 不是随机扰动，而是用 LLM 反思 trajectory 后写出的自然语言诊断。论文结果：比 GRPO 平均高 6pp、最高 19pp，所需 rollout 数量少 35×。NousResearch 的 hermes-agent-self-evolution 项目把它工程落地为 DSPy + GEPA pipeline。

三个核心组件
Genetic：候选 population 与变异
GEPA 维护一个 prompt 候选 population P={c1,c2,...,ck}P = \{c_1, c_2, ..., c_k\}P={c1​,c2​,...,ck​}。每个 candidate 是一个 prompt 文本（或更通用地，一组 prompt 文本组成的 DSPy program）。每轮迭代选 candidate 做评估，根据评估结果生成新 candidate，新旧合并形成下一代 population。


变异 (mutation) 不是字符级随机扰动——那对 prompt 几乎必然产生无意义文本。GEPA 的变异是语义级：把当前 candidate 与失败 trajectory 一起喂给 mutation LLM，让它产出"针对这类失败修改后的 prompt"。


Pareto：多目标前沿选择
单一适应度函数（"平均 success rate"）会引导 population 收敛到对所有 task 都"还行"的中庸 prompt，错过对特定 task 出色的 specialist candidate。GEPA 把每个 task 当成独立目标，maintain 一个 Pareto 前沿：


c1≻c2  ⟺  ∀t∈T:r(c1,t)≥r(c2,t)∧∃t′:r(c1,t′)>r(c2,t′)c_1 \succ c_2 \iff \forall t \in T: r(c_1, t) \geq r(c_2, t) \land \exists t': r(c_1, t') > r(c_2, t')c1​≻c2​⟺∀t∈T:r(c1​,t)≥r(c2​,t)∧∃t′:r(c1​,t′)>r(c2​,t′)
即 c1c_1c1​ dominates c2c_2c2​ 当且仅当 c1c_1c1​ 在所有 task 上不差且至少一项严格更好。Pareto 前沿是不被任何其他 candidate dominate 的 candidate 集合。新 candidate 只要进 Pareto 前沿就保留，即便平均分不及最强者——这给"在 niche task 上出色"的 candidate 保留空间。


Reflective：基于 trajectory 的自然语言诊断
这是 GEPA 区别于传统 evolutionary search 的关键。失败 trajectory 不止给一个"failed=true"标签，而是被一个evaluator LLM反思后生成 Actionable Side Information (ASI)：


Task: 从 lark-base 表生成周报
Candidate v3 fail on trajectory #87:
Trajectory:
  step1 lark-base +search "周会议程" → 返回 12 个候选
  step2 candidate 直接取 results[0] → 取到了已废弃的"周会议程_old"
  step3 后续步骤基于错误 base 拼接,产出空周报

ASI:
  Candidate v3 缺少"多候选时按 modified_at 排序取最新"的步骤。
  prompt 应在 search 后插入显式 sort 子步骤,或要求 LLM 主动询问
  用户确认 base 选择。
ASI 是论文里被命名为"text-optimization analogue of a gradient"的概念——它告诉 mutation LLM 不只是"失败了"，更告诉它"为什么失败、在哪里改"。


ASI 驱动的变异 prompt
Mutation 步骤的 prompt 模板（简化）：


你正在演进一个 LLM agent 的 prompt。

当前 candidate（version v3）：
<prompt text>

最近 5 条失败 trajectory 与对应 ASI：
1. <traj_1> | ASI: <text_1>
2. <traj_2> | ASI: <text_2>
...

任务：基于上述 ASI，提议一个 mutated prompt（version v4）。
要求：
- 不要重写整个 prompt,只改最相关部分
- 解释你的修改逻辑
- 不破坏当前在 Pareto 前沿的 task 的成功路径
Mutation LLM 输出新 prompt + change log。新 prompt 作为 candidate 进入下一轮评估。


System-aware merge
Pareto 前沿可能有多个 candidate 各自 specialize 不同 task。GEPA 的 system-aware merge 把多个 Pareto-optimal candidate 合并成一个更通用的 candidate：


Merge LLM 看见每个 ancestor 的"在哪些 task 上出色 + 为什么"，尝试合成一个继承所有 strength 的新 prompt。论文实验显示 merge 步骤是 GEPA 相比 single-line mutation 的关键增益来源。

陷阱与常见问题
    

  • ASI 太长导致 mutation prompt 爆 context：5 条 trajectory + ASI 累积容易破 32K。GEPA 配置项 asi_max_chars 限制单条 ASI 长度，默认 1500。
    • 

  • Pareto front 膨胀：task 维度多时 Pareto 前沿可能很大，merge 阶段成本陡升。论文建议 task 维度按 cluster 降到 5-10 个聚合维度。
    • 

  • Mutation LLM 用得过小：用 Haiku 做 mutation 容易产出"我不该改任何东西"的保守输出。建议 mutation LLM 用 Sonnet 量级以上。
    • 

  • Evaluator 不诚实：让 Sonnet 评估自己写的 trajectory，乐观偏置。GEPA 建议 evaluator 用与 actor 不同的 model family。
    • 

  • "Genetic-Pareto" 写成 "Genetic-Programming" 或 "Generic-Pareto"：算法名固定是 Genetic-Pareto，论文 abstract 第一句明确这是缩写来源。
    • 



小结
GEPA 把"prompt 演化"从启发式 prompt engineering 升级为 reproducible 算法，三个组件（Genetic population / Pareto front / Reflective ASI）各司其职。Reflective 部分通过把 trajectory 反思成自然语言诊断信息，让单次 rollout 信息量比 scalar reward 高一两个数量级，因此能用 10^2-10^3 而非 10^5 量级的 rollout 完成有效优化。Hermes 把这套机制 plug 进 curator + skill_manage，得到一个不需要 model fine-tuning 就能持续演进的 personal-agent 工具栈。下一篇看在演进过程中 skill 版本与 rollback 如何管理。
