hermes mcp serve：server 端实现

核心概念

hermes mcp serve 把 Hermes 的核心能力——长期记忆、curator 状态、persona、skill dispatch——封装成 MCP server 暴露出去。这是 Tier 2 personal-agent 工具栈区别于 Tier 1 coding-tools 的关键设计：Tier 1 工具用 MCP 作 client 调用外部 server，Tier 2 用 MCP 作 server 把自己的"软上下文"暴露给 Tier 1 反向调用。stdio-first 设计保证数据不出本机，5 个核心 tool 各有 input/output schema，让 Claude Code / Codex 等 client 能用 structured tool result 直接消费。





设计选择
理由





stdio over HTTP
本地优先，数据不出本机，无 audience 校验复杂度




5 个 tool 而非更多
控制 client 端 schema 复杂度，避免选择疲劳




全部带 outputSchema
client 可解析 typed 字段而非裸字符串




默认 read-heavy
memory_write 是唯一写操作，其余 read-only





tool 列表与职责
memory_query
按 FTS5 检索 Hermes 长期记忆。Input：


{
  "query": "rpc OR kitex NOT deprecated",
  "top_k": 10,
  "filters": {
    "tags": ["bytedance", "rpc"],
    "min_importance": 0.5,
    "since": "2026-04-01"
  },
  "rank_mode": "bm25_importance"
}
Output（structured 字段）：


{
  "entries": [
    {
      "entry_id": "mem_8a3f",
      "title": "字节内部 RPC 服务必须用 bytedance-golang-expert",
      "body_excerpt": "处理任何...",
      "score": 0.87,
      "importance": 0.91,
      "tags": ["workflow", "bytedance", "rpc"],
      "last_hit_at": "2026-05-10T09:42:00Z"
    }
  ],
  "total_matched": 23,
  "query_ms": 4.7
}
详细 FTS5 语法见 ../1_persistent-memory/3_fts5-search-and-retrieval.md。


memory_write
把一条新记忆写进 MEMORY.md（cold storage 区，后续 curator 决定是否升 hot）。Input：


{
  "title": "lark-cli token 一年过期一次",
  "body": "每年 5 月需要重新 lark-cli auth login...",
  "tags": ["lark", "workflow"],
  "source": "claude_code_session",
  "initial_importance": 0.6
}
Output：


{
  "entry_id": "mem_9b21",
  "status": "written",
  "location": "cold_storage",
  "curator_eta": "2026-05-15T03:00:00Z"
}
是唯一一个修改 state 的 tool。Hermes 在 server 端做 dedup pre-check：如果新条目与已有 entry embedding similarity > 0.92，返回 status: "deduplicated" 并附 existing entry_id，避免 client 反复写入同一事实。


curator_schedule_list
返回最近 N 次 curator run 的状态与 metric snapshot。Input：


{ "limit": 10, "since": "2026-04-01" }
Output：


{
  "runs": [
    {
      "run_id": "cur_2026-05-13",
      "started_at": "2026-05-13T03:00:00Z",
      "duration_ms": 1830,
      "reranks": 142,
      "dedupes": 4,
      "retires": 2,
      "next_scheduled": "2026-05-14T03:00:00Z"
    }
  ]
}
提供给 client 的目的是让 client "知道记忆系统什么状态"——例如 Claude Code 在做关键操作前可以先 curator_schedule_list，发现 next_scheduled 在 5 分钟内，决定推迟写入避免 race。


persona_active
返回当前 active persona 元数据。Output：


{
  "persona_id": "tech-lead",
  "soul_excerpt": "简短直接,决策给 2-3 个 trade-off...",
  "user_excerpt": "时区 Asia/Shanghai,母语中文...",
  "tool_whitelist": ["bytedance-golang-expert", "lark-cli"],
  "activated_at": "2026-05-14T08:00:00Z"
}
让 Tier 1 client 知道"用户当前正在以哪个角色工作"，从而对齐自己的输出风格与工具选择。


skill_dispatch
让 client 触发 Hermes 已注册的某个 skill。Input：


{
  "skill_name": "weekly-report-base-to-doc",
  "context": {
    "base_id": "bascn123",
    "week_start": "2026-05-10"
  }
}
Output：


{
  "invocation_id": "inv_3c8f",
  "status": "started",
  "skill_version": "1.1.0",
  "estimated_steps": 4
}
注意：这是异步 dispatch，不阻塞 client。Skill 执行进度可通过 inv_3c8f 查 Hermes status endpoint，或订阅 hermes outbound webhook 接收完成事件。


stdio-first 设计原因




维度
stdio
HTTP





部署
子进程直接启动
需起 daemon + 监听 port




鉴权
进程父子关系隐含信任
必须 token + audience 校验




数据流向
本地 unix domain
可能走网络




调试
tcpdump 不可见
易抓包泄露




多 client
每个 client 自己启子进程
单 daemon 多 client





Tier 2 选 stdio 是因为 memory / persona 包含用户最敏感的"软资产"——把这些通过 HTTP 暴露需要严格 audience / token 管理才安全，反而比 stdio 更复杂。代价是不能跨主机：Claude Code 在另一台机器要用 Hermes memory，必须 SSH tunnel 或显式 HTTP 模式（hermes mcp serve --http，需要额外配置 token）。


Tier 1 client 接入示例
Claude Code
// ~/.claude/mcp-servers/hermes.json
{
  "command": "hermes",
  "args": ["mcp", "serve"],
  "env": {
    "HERMES_HOME": "~/.learnwy/hermes"
  }
}
启动 Claude Code 后 claude mcp list 应看到 hermes 在列。


Codex CLI
# ~/.codex/config.toml
[[mcp_servers]]
name = "hermes"
command = "hermes"
args = ["mcp", "serve"]
两者都用 stdio，配置 schema 略有差异但语义一致。


input/output schema 完整声明
每个 tool 都按 MCP spec 声明 inputSchema 与 outputSchema，让 client 能在 IDE / runtime 做静态校验：


{
  "name": "memory_query",
  "description": "Search Hermes long-term memory via FTS5",
  "inputSchema": {
    "type": "object",
    "required": ["query"],
    "properties": {
      "query": { "type": "string" },
      "top_k": { "type": "integer", "default": 10, "maximum": 100 },
      "filters": { "type": "object" },
      "rank_mode": { "type": "string", "enum": ["bm25", "bm25_importance", "recency"] }
    }
  },
  "outputSchema": {
    "type": "object",
    "required": ["entries"],
    "properties": {
      "entries": { "type": "array", "items": { "$ref": "#/$defs/Entry" } },
      "total_matched": { "type": "integer" },
      "query_ms": { "type": "number" }
    }
  }
}
outputSchema 是 MCP 2025 spec 引入的可选字段——Hermes 全部 tool 都声明它，让 client 不必把 result 当字符串 parse。


陷阱与常见问题
    

  • client 配置写错命令路径：hermes 不在 PATH 时启动失败，错误隐藏在 client log。先 which hermes 确认。
    • 

  • stdio 模式下 stderr 也走 transport：Hermes 把 log 默认写 ~/.learnwy/hermes/logs/serve.log 而非 stderr，避免污染 JSON-RPC stream。如果日志看不到检查这个文件。
    • 

  • memory_write 写不进：可能 dedup 命中，看 output.status 字段。或 hermes 的 SQLite 锁住（同一时刻 curator 在跑），重试一次即可。
    • 

  • persona_active 返回 null：用户没切过 persona，没有 default。建议 client 收到 null 时不要直接报错，而是 fallback 到 USER.md 内容。
    • 

  • 跨机器接入：默认 stdio 不可跨机，需要 --http 模式 + token。详见 hermes 文档 mcp/http 章节。
    • 



小结
hermes mcp serve 用 5 个 tool 把 Hermes 的长期记忆 / curator / persona / skill 能力一一暴露给 Tier 1 client。stdio-first 设计保证数据本地，outputSchema 让 client 解析无歧义，read-heavy + 单一 write tool 的设计让 server 端复杂度可控。这是 Tier 2 personal-agent 工具栈区别于 Tier 1 coding-tools 的"反向 MCP" 关键步骤——下一篇看 OpenClaw 的 MCP server 实现，看它如何在 multi-tenant 隔离要求下做同样的事。
