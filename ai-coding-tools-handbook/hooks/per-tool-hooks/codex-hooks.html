Codex hooks 与 admin override

Codex 在 2026 年的 hook 体系走精简路线——6 个 stable 事件覆盖 agent 主要决策路径，配置位置在 ~/.codex/config.toml，运行环境与 sandbox / approval policy 紧密耦合。最具特色的是 admin override 机制：企业可以通过 requirements.toml 强制 hook 不允许 user 关闭，用户的 config.toml 设置如与 admin 冲突静默忽略——这把"安全策略不可绕过"做到了 user-tool 层级。本文把 Codex hook 的事件清单、配置语法、admin override、与 sandbox / approval 的协同讲清。

核心概念

Codex 把 hook 与企业安全策略深度绑定：admin 通过 requirements.toml 写"强制"hook，user 的 config.toml 设置和 admin 冲突时静默忽略——意味着安全审计、合规检查等不可绕过的 hook 可以由 IT 部门统一下发。

按 2026-05 文档，Codex 提供 6 个稳定事件：

与 Claude Code 20+ 事件相比，Codex 砍掉了 SubagentStart / FileChanged / CwdChanged / TaskCreated / PermissionRequest / Notification 等更细粒度的事件——选择"覆盖核心决策路径"而非"全部 lifecycle 节点"。事件名也走 snake_case 而非 PascalCase，更贴近 Unix 命令行风格。


事件较少不等于能力弱：日常 policy enforcement（拦命令、审 prompt、强制 SOP）所需的 hook 点 6 个事件全覆盖。要做"文件变更后自动 lint"这种细粒度自动化，Codex 推荐用 post_tool + 检查工具名是 Edit/Write 来实现，而不是引入专门事件。


config.toml 配置语法
~/.codex/config.toml 是 user 级配置，/etc/codex/requirements.toml（macOS 上 /Library/Application Support/codex/requirements.toml）是 admin 级配置。语法走 TOML：


# ~/.codex/config.toml

[hooks.session_start]
command = "/usr/local/bin/codex-inject-env.sh"
timeout_ms = 1000

[hooks.pre_tool]
command = "/usr/local/bin/check-bash.sh"
matcher = "bash"   # 工具名匹配；可选

[[hooks.pre_tool]]
command = "/usr/local/bin/check-edit.sh"
matcher = "edit"

[hooks.stop]
command = "/usr/local/bin/check-sop.sh"
字段约定：command 是脚本路径或 shell 命令；matcher 是工具名 / prompt 正则；timeout_ms 超时；多条 hook 用 TOML 数组 [[hooks.<event>]] 重复声明。Codex 当前不支持 handler: "http" / mcp_tool / prompt / agent 这些 Claude Code 的非 command handler——所有 hook 都是 shell 子进程形态。


退出码语义与 Claude Code 一致：exit 0 放行、exit 2 阻塞 + stderr 反馈、其它非 0 是 warning。stdin 传 JSON、stdout 用法见上一章。差异主要在事件粒度和配置位置。


admin override 与 requirements.toml
企业部署场景里，Codex 提供 requirements.toml 让 admin 写"不可绕过"的 hook 配置：


# /etc/codex/requirements.toml （admin 强制）

[hooks.pre_tool]
command = "/opt/security/audit-tool-call.sh"
matcher = ".*"
mandatory = true

[hooks.session_start]
command = "/opt/compliance/load-policy.sh"
mandatory = true
allow_user_extend = true

[hooks.prompt_submit]
command = "/opt/security/scan-prompt.sh"
matcher = ".*"
mandatory = true
mandatory = true 标记的 hook 不可被 user 关闭——user 在自己的 config.toml 里写同名 hook 会被静默忽略；allow_user_extend = true 允许 user 在同事件追加 hook（追加的 hook 与 admin 强制 hook 并列执行）。


合并规则：






admin 设置
user 设置
实际行为





mandatory=true
同事件配置
user 配置忽略，仅 admin 执行




mandatory=true, allow_user_extend=true
同事件追加
admin + user 都执行




mandatory=false 或未设
user 同事件覆盖
user 配置生效，admin 不执行




未配置
user 配置
user 配置生效





这套机制让 IT 部门可以下发"所有 Codex 用户的 pre_tool 都先走一道安全审计"——user 无法在自己机器上关掉。下发方式可以是配置管理工具（Ansible / Chef / Jamf）写文件、或 Codex 企业版的中心化下发。


hook 与 sandbox / approval policy 协同
Codex 的工具调用受两条额外管控：sandbox 模式（命令在受限环境运行）、approval policy（高风险命令要求用户批准）。hook 在这套体系里的位置是"最先执行的检查点"：


执行顺序是 hook → approval policy → sandbox。hook 是第一道关，exit 2 直接阻塞、approval policy 都不会被调用。approval policy 是第二道关，user 批准后才走 sandbox。三者解决不同问题：hook 是"程序化策略"（写脚本判定），approval policy 是"用户交互"（人在环），sandbox 是"运行时围栏"（限制副作用）。


hook 的运行环境是另一个细节——pre_tool hook 在 main process 跑，能访问完整环境变量与文件系统；post_tool hook 默认也在 main process，但企业版可以配置成 sandbox 内运行（限制 hook 自己写文件 / 网络访问的能力）。后者用于"hook 不能信任 LLM 工具输出"的高安全场景——hook 读到污染数据时无法横向移动。


陷阱与常见问题
    

  • admin override 写错路径：requirements.toml 在 macOS 走 /Library/Application Support/codex/、Linux 走 /etc/codex/、Windows 走 %ProgramData%\codex\；路径错会被当不存在。
    • 

  • TOML 数组语法：多条同事件 hook 必须用 [[hooks.pre_tool]] 而非 [hooks.pre_tool] 重复——后者按 TOML 规范是"重复 table"会报错。
    • 

  • 以为有 handler 字段：Codex 当前只支持 command handler；写 handler = "http" 被忽略，hook 不生效。
    • 

  • mandatory 与 allow_user_extend 同时不设：默认行为是 mandatory=false，user 覆盖会顶替 admin；安全策略必须显式 mandatory = true。
    • 

  • matcher 大小写：Codex 工具名走 lowercase（bash / edit），matcher 写 Bash 匹配失败；与 Claude Code 的 PascalCase 反向。
    • 

  • hook 内调用 codex CLI：可能形成无限循环（hook 触发 hook）；与 SessionStart 这种事件一起出现时尤其危险。
    • 



小结
    

  • Codex 提供 6 个 stable 事件（session_start / prompt_submit / pre_tool / post_tool / command_complete / stop），覆盖核心决策路径而非全 lifecycle。
    • 

  • ~/.codex/config.toml user 级配置；TOML 语法、command handler 唯一形态、退出码语义与 Claude Code 一致。
    • 

  • requirements.toml admin 级配置 + mandatory = true 实现"不可绕过"hook，企业部署的安全审计 hook 走这条。
    • 

  • hook → approval policy → sandbox 三道关解决"程序化策略 / 用户交互 / 运行时围栏"三类不同问题。
    •
