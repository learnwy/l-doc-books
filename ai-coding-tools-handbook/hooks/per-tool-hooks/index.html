三款工具的 Hooks 实现 简介

读完触发模型之后，本章把三家具体实现拉平。Claude Code 是 hook 体系最完整的实现——20+ 事件 / 5 类 handler / 最丰富的 JSON 控制 schema；Codex 6 个 stable 事件、走 OpenAI 内部安全策略 + admin override；OpenCode 选择了不一样的设计哲学——不原生兼容 Claude hooks、把 hook 抽象成 plugin 系统（tool.execute.before/after / session.idle），plugin = hook 实现方式。三家在事件覆盖、配置位置、handler 类型上差异显著，跨工具迁移 hook 需要逐项映射。

本章包含三篇 L4 文档。

1_claude-code-hooks-events.md —— Claude Code 20+ 事件 + 5 handler。第一块列事件清单——PreToolUse / PostToolUse / UserPromptSubmit / UserPromptExpansion / SessionStart / Stop / SubagentStart / SubagentStop / PreCompact / PostCompact / WorktreeCreate / FileChanged / CwdChanged / TaskCreated / TaskCompleted / PermissionRequest / PermissionDenied / Notification 等 18-29 个事件（不同 minor version 数量略不同）。第二块讲 5 类 handler——command（shell 子进程）/ http（HTTP endpoint）/ mcp_tool（调用 MCP server tool）/ prompt（发新 prompt）/ agent（spawn sub-agent）；handler 类型决定 hook 的运行环境与 latency 预算。第三块讲 settings.json 配置——hooks.<event>.[*] 数组 + matcher（tool name pattern、prompt regex）+ command 或对应 handler 字段。第四块讲 skill / subagent frontmatter hooks: 内嵌——hook 不一定在 settings.json 全局生效，可在 skill 或 subagent 内嵌只对该 skill/subagent 有效。

2_codex-hooks.md —— Codex 6 stable 事件 + config.toml。第一块讲 6 stable 事件（具体清单按 2026-05 文档：会话启动、prompt 提交、工具前、工具后、命令完成、停止），相比 Claude Code 数量精简但覆盖核心路径。第二块讲 [hooks] 在 ~/.codex/config.toml 配置——格式 [hooks.<event>] + command = "..." + 可选 matcher。第三块讲 admin override 与 requirements.toml——企业可强制特定 hook（如安全审计 hook）不允许 user 关闭；user 的 config.toml 设置如与 admin 冲突静默忽略。第四块讲 Codex hooks 与 sandbox / approval policy 的协同——hook 在 sandbox 环境运行 vs 主进程；exit 2 阻塞行为与 approval policy 的优先级（hook deny 优先）。

3_opencode-plugin-as-hook.md —— OpenCode "plugin = hook" 设计哲学。第一块讲为什么 OpenCode 不直接复制 Claude Code 的 hook 模型——issue #12472 讨论显示官方立场是 plugin 系统更通用、可以同时实现 hook + tool 扩展 + UI 注入。第二块讲 plugin 事件——tool.execute.before（对应 PreToolUse）/ tool.execute.after（对应 PostToolUse）/ session.idle（部分对应 Stop）+ plugin lifecycle 事件（install / uninstall / enable / disable）。第三块讲 plugin 写法——JavaScript / TypeScript module export 注册函数；Bun runtime 加载；compared to bash hook 的写法更"应用化"。第四块讲 OpenCode 不支持 Claude Code 原生 hook 的事实与 user 维护双份 hook（一份 ~/.claude/settings.json、一份 OpenCode plugin）的痛点；引出第 3 章的 bridge 范式。

学习建议是只用一款的读者只看对应一节；同时用两款以上的工程师建议三节都读——重点对比"事件覆盖度"与"配置位置"两条线，跨工具迁移的 80% 工作量在这两块。
