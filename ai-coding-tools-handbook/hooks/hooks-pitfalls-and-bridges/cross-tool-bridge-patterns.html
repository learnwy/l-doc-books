跨工具 bridge 模式

团队同时使用 Claude Code、Codex、OpenCode 三家工具时，hook 规则的维护成本以"工具数量 × 规则数量"线性增长——同一条"拒绝 force-push 到 main"的策略要在 Claude settings.json 写一份 bash 脚本、在 Codex config.toml 写一份、在 OpenCode 里写一份 TS plugin。社区 issue #12472 的讨论沉淀出"OpenCode plugin 桥接 Claude Code hook"这一事实标准方案，加上工具名映射、exit code 2 re-injection、共享 hook 仓库三种范式，可以把团队 hook 维护收敛到单一信源。本文给出可照搬的 bridge plugin 与 monorepo template。

核心概念

bridge 的核心思路：把 hook 脚本仍然按 Claude Code 的协议（stdin JSON、exit code）写，存到一个共享仓库；Claude Code 通过 settings.json 直接引用；Codex 通过 config.toml 引用同一份脚本（协议兼容）；OpenCode 写一个 bridge plugin，启动时扫 ~/.claude/settings.json 把 hooks 数组 map 到 OpenCode 三类 plugin event、动态调脚本。

OpenCode bridge plugin：从 settings.json 到 plugin event
bridge plugin 启动时读 ~/.claude/settings.json，把 hooks 字段 map 到 OpenCode 的三个 plugin event。下面是简化版本：


// opencode-plugin-claude-hooks-bridge/index.ts
import { readFileSync } from 'fs';
import { homedir } from 'os';
import { join } from 'path';
import { spawnSync } from 'child_process';
import type { Plugin } from 'opencode-plugin-types';

type ClaudeHook = {
  matcher?: string;
  command?: string;
  timeout_ms?: number;
};

type Settings = { hooks?: Record<string, ClaudeHook[]> };

const EVENT_MAP: Record<string, 'tool.execute.before' | 'tool.execute.after' | 'session.idle'> = {
  PreToolUse: 'tool.execute.before',
  PostToolUse: 'tool.execute.after',
  Stop: 'session.idle',
};

const TOOL_NAME_MAP: Record<string, string> = {
  bash: 'Bash',
  edit: 'Edit',
  read: 'Read',
  write: 'Write',
  grep: 'Grep',
  glob: 'Glob',
};

function normalizeToolName(name: string) {
  return TOOL_NAME_MAP[name.toLowerCase()] ?? name;
}

function loadSettings(): Settings {
  try {
    return JSON.parse(readFileSync(join(homedir(), '.claude/settings.json'), 'utf8'));
  } catch {
    return {};
  }
}

function runHook(hook: ClaudeHook, eventPayload: object) {
  const result = spawnSync(hook.command!, [], {
    input: JSON.stringify(eventPayload),
    encoding: 'utf8',
    timeout: hook.timeout_ms ?? 2000,
    shell: true,
  });
  return {
    exitCode: result.status ?? 0,
    stdout: result.stdout ?? '',
    stderr: result.stderr ?? '',
  };
}

const plugin: Plugin = {
  name: 'claude-hooks-bridge',
  version: '1.0.0',

  async onEnable(ctx) {
    const settings = loadSettings();
    ctx.log.info(`bridge: 加载 ${Object.keys(settings.hooks ?? {}).length} 个事件 hook`);
  },

  hooks: {
    'tool.execute.before': async (event, ctx) => {
      const hooks = loadSettings().hooks?.PreToolUse ?? [];
      const toolName = normalizeToolName(event.tool);
      for (const h of hooks) {
        if (h.matcher && !new RegExp(h.matcher).test(toolName)) continue;
        const r = runHook(h, { tool_name: toolName, tool_input: event.input });
        if (r.exitCode === 2) {
          return { decision: 'deny', reason: r.stderr.trim() };
        }
      }
    },

    'tool.execute.after': async (event, ctx) => {
      const hooks = loadSettings().hooks?.PostToolUse ?? [];
      const toolName = normalizeToolName(event.tool);
      for (const h of hooks) {
        if (h.matcher && !new RegExp(h.matcher).test(toolName)) continue;
        runHook(h, { tool_name: toolName, tool_output: event.output });
      }
    },

    'session.idle': async (event, ctx) => {
      if (event.cause !== 'agent_stop') return;
      const hooks = loadSettings().hooks?.Stop ?? [];
      for (const h of hooks) {
        const r = runHook(h, { cause: event.cause });
        if (r.exitCode === 2) {
          return { decision: 'continue', message: r.stderr.trim() };
        }
      }
    },
  },
};

export default plugin;
这份 plugin 干了三件事：第一，启动时读 ~/.claude/settings.json 把 hooks 数组缓存到内存；第二，三个 plugin event 触发时分别 lookup PreToolUse / PostToolUse / Stop 对应配置、调 shell 脚本；第三，转换工具名、把 shell 脚本的 exit 2 + stderr 翻译成 OpenCode plugin 的 {decision: "deny", reason} 或 session.continue。


工具名转换：PascalCase ↔ lowercase
Claude Code 工具名用 PascalCase（Bash、Edit、Read、Write、Grep、Glob、Task、WebFetch），早期 OpenCode 用 lowercase（bash、edit、read），2026 版已逐步对齐到 PascalCase 但仍有些版本走 lowercase。bridge plugin 必须维护一张双向 lookup table：

实现时建议双向 normalizer：把任何输入先全转成 PascalCase 再做 matcher 匹配，避免 hook 脚本里写两套 case。


exit code 2 re-injection 模拟 Stop hook
Claude Code Stop hook 最典型用法是 SOP enforcement——agent 试图 stop 时 hook 检查"checklist 是否完成"，没完成就 exit 2 + stderr 写"还需要做 X"，agent 把 stderr 喂回 LLM 强制继续工作。这一模式在 OpenCode 里要在 plugin 内主动调用 session.continue API 模拟：


"session.idle": async (event, ctx) => {
  if (event.cause !== "agent_stop") return;
  const sopDone = await ctx.storage.get("sop_done");
  if (!sopDone) {
    return {
      decision: "continue",
      message: "SOP checklist 未完成，请继续执行：1. 跑 lint 2. 跑 test 3. 写 PR 描述"
    };
  }
},
返回 {decision: "continue", message: "..."} 让 OpenCode 把 message 作为 system context 注入下一轮 LLM 调用，强制 agent 继续工作。bridge plugin 里这部分由 shell hook 的 exit 2 + stderr 转译——shell 脚本退出 2、stderr 写"还需要做 X"，plugin 把它打包成 OpenCode 的 decision: "continue"。


共享 hook 仓库：team-hooks/ monorepo template
把所有 hook 脚本集中到一个 git 仓库，各工具引用同一份。最小 monorepo 结构：


team-hooks/
├── README.md
├── pretooluse/
│   ├── check-bash.sh
│   ├── check-edit.sh
│   └── check-write.sh
├── posttooluse/
│   └── audit-log.sh
├── stop/
│   └── check-sop.sh
├── sessionstart/
│   └── inject-git-status.sh
├── config-templates/
│   ├── claude-settings.json
│   ├── codex-config.toml
│   └── opencode-plugins.json
└── tests/
    └── test-pretooluse.sh
每个工具的引用方式：


// ~/.claude/settings.json （直接引用绝对路径）
{
  "hooks": {
    "PreToolUse": [{ "matcher": "Bash", "command": "~/team-hooks/pretooluse/check-bash.sh" }],
    "Stop": [{ "command": "~/team-hooks/stop/check-sop.sh" }],
  },
}
# ~/.codex/config.toml
[hooks.pre_tool]
command = "~/team-hooks/pretooluse/check-bash.sh"
matcher = "bash"

[hooks.stop]
command = "~/team-hooks/stop/check-sop.sh"
// ~/.config/opencode/config.json
{
  "plugins": ["opencode-plugin-claude-hooks-bridge"],
}
OpenCode 端只装 bridge plugin、bridge plugin 自动读 ~/.claude/settings.json 引用同一份 hook 脚本。新成员入职跑一遍 git clone team-hooks ~ && bash team-hooks/setup.sh 就完成三个工具的全部配置。


更新流程：仓库 push → 团队成员 pull → hook 立刻生效（脚本即文件，无需 reload）。OpenCode bridge plugin 也无须重启——每次事件触发都重新读 settings.json（生产环境可以加 30 秒缓存）。


陷阱与常见问题
    

  • bridge plugin 不读最新 settings.json：缓存 settings 到内存后忘记 invalidate；建议每次事件都 stat 文件 mtime，变了重新加载。
    • 

  • 工具名转换漏边缘 case：Claude 新增 Notebook / BashOutput 等工具时，lookup table 不更新就 silent 不生效；建议无匹配时 fallback 用原名 + 日志告警。
    • 

  • session.idle 当 Stop 用没区分 cause：用户输入回合也会触发 idle，没判定 cause === "agent_stop" 会在用户问问题时也跑 SOP 检查。
    • 

  • 同一脚本在三家工具行为不同：Codex 工具名小写、Claude PascalCase——hook 脚本 matcher 写 if [ "$TOOL" = "Bash" ] 在 Codex 端失败；脚本里统一用 normalizer。
    • 

  • 共享仓库权限混乱：脚本带 sudo 或写敏感路径，团队成员 clone 后被恶意修改可能引发安全事故；用 git tag 锁版本 + signed commit。
    • 

  • bridge plugin 性能瓶颈：每次工具调用都 spawnSync shell 脚本，在 OpenCode in-process 优势丧失；高频路径建议 plugin 内做轻量过滤再调脚本。
    • 



小结
    

  • 三家工具的 hook 协议（stdin JSON、exit code、stderr 反馈）在 2026 已收敛到兼容程度——同一份 shell 脚本可以同时被 Claude Code 与 Codex 直接调用、被 OpenCode 通过 bridge plugin 调用。
    • 

  • OpenCode bridge plugin 读 ~/.claude/settings.json 把 hooks 数组 map 到三个 plugin event，工具名 normalize + exit 2 翻译成 plugin 返回值。
    • 

  • exit 2 re-injection 模拟 Stop hook 的 SOP enforcement：shell 脚本 exit 2 + stderr，plugin 翻译成 decision: "continue" + message 强制 agent 继续。
    • 

  • 共享 hook 仓库（team-hooks/）作为单一信源，三家工具按各自方式引用同一份脚本；新成员入职跑一次 setup 完成全部配置。
    • 

  • 整套 hub 在 ../_INTRODUCTION.md 给出全局导引；上层模块 commands / agents / skills / mcp 见 ../../。
