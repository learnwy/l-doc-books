可观测：OTel 与 Session 检索 简介

AI 编程代理在 2026 年完成了从"黑箱"到"OpenTelemetry-native 可观测"的关键演化。Claude Code / Codex CLI / Gemini CLI 都内置 OTel instrumentation——session、token、tool call、cost、error、performance 都通过标准 OTLP 协议导出；下游 backend 选 SigNoz / Dynatrace / Elastic / OpenObserve / Grafana+Loki/Prometheus / Logfire / Honeycomb 都可。但"装上 OTel exporter"只是开始——内容审计（content vs structural）、session 检索（FTS5、stream-json 抓取）、agent 自己查 telemetry 闭环这三层是 2026 真正的实战分水岭。本 hub 把 OTel 协议本体、三家工具的 export 配置、backend 对比、session 检索机制讲清，让 platform / SRE / security 团队能起一份 production-ready 的 observability stack。

适合读者主要有三类：在团队里推 AI coding 代理需要 metrics + cost 看板的 platform 工程师；做安全审计 / Compliance 需要 audit log 的 security 工程师；以及对"agent 自己查 telemetry → 修 production bug"这种 closed-loop 模式感兴趣的工具开发者。读者只需了解 OpenTelemetry 基本概念（trace / metric / log），不熟可先读 OTel 官方 quickstart。

本 hub 两章按"先理解协议、再选 backend"递进。

第 1 章 1_otel-fundamentals/ 讲 OTel 协议本体与三家 export 配置：第一篇 1_otel-and-stream-json-protocols.md 讲 Claude / Codex / Gemini CLI 的 OTel instrumentation 设计——span 包 model request 与 tool execution、metric 包 token + cost counter、log event 包 prompt 与 tool result；五类标准 event（api_request / tool_result / session / prompt / event.sequence）跨三家一致；content vs structural 隐私默认（默认不记 prompt 内容，opt-in OTEL_LOG_USER_PROMPTS=1 / OTEL_LOG_TOOL_DETAILS=1）；stream-json wrapper 模式（claudia 类工具替代 claude 二进制做 wrapper-level 抓取）。第二篇 2_per-tool-otel-export-config.md 三家具体 export 配置——Claude CLAUDE_CODE_ENABLE_TELEMETRY=1 + OTLP HTTP exporter + 通过 managed-settings 中央化；Codex opt-in OTel + cloud 跨 surface unified；Gemini 内置 OTel + 预配 dashboard。

第 2 章 2_backends-and-session-search/ 讲 backend 选型与 session 检索：第一篇 1_backend-comparison.md 横向对比 SigNoz / Dynatrace / Elastic / OpenObserve / Grafana+Prometheus+Loki / Logfire+Honeycomb+Sentry——按 self-hosted vs SaaS、cost、metric+log+trace 三合一支持度、AI 行业插件成熟度四轴评估；附 2026 最常见三套部署组合的 trade-off。第二篇 2_session-search-and-agent-loop.md 讲 session 检索机制（Hermes 用 FTS5 全文索引 session transcript，留作 Tier 2 引用）+ closed-loop agent observation（OpenObserve 让 agent 通过 MCP server 查自己的 telemetry，看 production 错误 → 自动 file PR）。

推荐学习路径是按章节顺序走一遍；只关心 export 配置的运维直接看第 1 章 2 节，关心 backend 选型的 platform 团队两章都读。Team-specs 的 admin override 与本 hub 的中央化 telemetry 是 ops 视角两条线，请同时读 ../1_team-specs/。

版本冻结：本 hub 内容基于 Claude Code code.claude.com/docs/en/agent-sdk/observability + Codex / Gemini CLI OTel docs + Dynatrace / Elastic / SigNoz 2026 blog 系列；事实主张全部可在 _research/doc-sources.md 与 OTel 官方 spec 中追溯。
