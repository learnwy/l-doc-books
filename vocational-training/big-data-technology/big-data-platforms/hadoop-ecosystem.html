Hadoop 生态

知识要点

Hadoop 是大数据技术的奠基平台，其"分而治之"的设计哲学深刻影响了所有后续分布式系统的架构思路。理解 Hadoop 生态不仅是操作集群的技能需求，更是建立分布式思维的必经之路。

HDFS 分布式文件系统

HDFS（Hadoop Distributed File System）是为大规模数据存储设计的分布式文件系统，核心设计决策是"写一次、读多次"：

关键参数与操作：


# HDFS 基本操作
hdfs dfs -mkdir -p /user/etl/input
hdfs dfs -put local_data.csv /user/etl/input/
hdfs dfs -ls -R /user/etl/
hdfs dfs -du -s -h /user/etl/        # 查看目录大小

# 关键配置参数
# dfs.blocksize=128MB（默认），大文件可设为 256MB 减少 NameNode 内存压力
# dfs.replication=3（默认副本因子）
HDFS 的块大小设计遵循一个简单原则：寻址时间应为传输时间的 1% 以下。假设磁盘寻址 10ms，传输速率 100MB/s，则块大小应 ≥ 100MB，因此默认 128MB。


MapReduce 编程模型
MapReduce 将计算抽象为 Map（映射）和 Reduce（归约）两个阶段，实现"移动计算而非移动数据"：


# Python Hadoop Streaming 示例：WordCount
# mapper.py
import sys
for line in sys.stdin:
    for word in line.strip().split():
        print(f"{word}\t1")

# reducer.py
import sys
current_word = None
count = 0
for line in sys.stdin:
    word, val = line.strip().split('\t')
    if word == current_word:
        count += int(val)
    else:
        if current_word:
            print(f"{current_word}\t{count}")
        current_word = word
        count = int(val)
if current_word:
    print(f"{current_word}\t{count}")
MapReduce 的执行流程：Input → Split → Map → Shuffle & Sort → Reduce → Output。其中 Shuffle 阶段是性能瓶颈所在——涉及网络传输和磁盘 I/O。


YARN 资源管理
YARN（Yet Another Resource Negotiator）将资源管理从计算框架中解耦，使 Hadoop 集群能同时运行 MapReduce、Spark、Flink 等多种引擎：


YARN 的资源单位是 Container，每个 Container 包含固定的 CPU 和内存配额。ApplicationMaster 负责向 ResourceManager 申请资源并协调任务执行。


Hive 数据仓库
Hive 将 SQL 翻译为 MapReduce/Spark 作业，让熟悉 SQL 的分析师能直接查询 HDFS 上的海量数据：


-- 创建外部表（数据存储在 HDFS，删表不删数据）
CREATE EXTERNAL TABLE user_events (
    user_id     STRING,
    event_type  STRING,
    event_time  TIMESTAMP,
    properties  MAP<STRING, STRING>
)
PARTITIONED BY (dt STRING)
STORED AS PARQUET
LOCATION '/dw/ods/user_events';

-- 分区加载
ALTER TABLE user_events ADD PARTITION (dt='2026-05-07')
LOCATION '/dw/ods/user_events/dt=2026-05-07';

-- 分析查询
SELECT event_type,
       COUNT(*) AS cnt,
       COUNT(DISTINCT user_id) AS uv
FROM user_events
WHERE dt BETWEEN '2026-05-01' AND '2026-05-07'
GROUP BY event_type
ORDER BY cnt DESC;
分区（Partition） 和 分桶（Bucket） 是 Hive 性能优化的两大核心手段。分区按业务维度（如日期）物理隔离数据，分桶按哈希值将数据均匀分布，加速 JOIN 和采样。


HBase 列式存储
HBase 是基于 HDFS 的分布式列族数据库，适合海量数据的随机实时读写：


// HBase Java API 示例
Put put = new Put(Bytes.toBytes("user_1001"));
put.addColumn(
    Bytes.toBytes("profile"),          // 列族
    Bytes.toBytes("name"),             // 列限定符
    Bytes.toBytes("张三")              // 值
);
table.put(put);

// Scan 范围查询
Scan scan = new Scan();
scan.setStartRow(Bytes.toBytes("user_1000"));
scan.setStopRow(Bytes.toBytes("user_2000"));
scan.addColumn(Bytes.toBytes("profile"), Bytes.toBytes("name"));
HBase 的 RowKey 设计直接决定查询性能：避免热点（加盐/反转）、支持范围扫描（时间戳前缀）、控制长度（通常 < 100 字节）。


数据仓库分层架构
企业级数据仓库通常采用经典的分层设计：


    

  • ODS：原始数据落地，不做清洗
    • 

  • DWD：数据清洗、去重、维度关联
    • 

  • DWS：按主题域汇总（用户、商品、交易）
    • 

  • ADS：面向具体业务场景的指标表
    • 



前沿动态
    

  • Hadoop 云原生化：Ozone 取代 HDFS 支持对象存储语义，适配 K8s 部署
    • 

  • Hive on Tez/LLAP：Hive 4.x 通过 LLAP 缓存层实现亚秒级交互查询
    • 

  • 数据湖仓一体：Apache Iceberg/Delta Lake 在 HDFS/对象存储上提供 ACID 事务和时间旅行
    • 

  • NameNode 联邦：解决单点元数据瓶颈，支持百亿级文件数
    •

小结
Hadoop 生态奠定了大数据技术的基础设施层：HDFS 提供可靠的分布式存储，YARN 实现弹性资源管理，MapReduce 定义了分布式计算的基本范式，Hive 桥接了 SQL 分析与分布式存储，HBase 补充了实时随机访问能力。虽然新一代引擎在性能上全面超越了原生 MapReduce，但 Hadoop 的架构思想——数据本地性、容错设计、水平扩展——仍然是理解所有分布式系统的思维基础。
