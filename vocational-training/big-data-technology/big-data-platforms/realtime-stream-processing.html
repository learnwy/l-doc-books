实时流处理

知识要点

实时流处理解决的核心问题是：如何对持续到达的无界数据流进行低延迟计算。随着业务对时效性要求从"T+1 天"缩短到"秒级"，实时流处理已成为大数据岗位的核心必备技能。2026 年的流处理技术栈以 Kafka + Flink 为主导。

Kafka 消息队列

Apache Kafka 是分布式流数据平台，充当数据生产者与消费者之间的高吞吐缓冲层：

核心概念与配置：


# Kafka Producer 配置
bootstrap.servers=kafka1:9092,kafka2:9092,kafka3:9092
acks=all                          # 所有 ISR 副本确认才算成功
compression.type=lz4              # 压缩减少网络 IO
batch.size=65536                  # 批量发送提升吞吐
linger.ms=5                       # 等待 5ms 凑批

# Topic 设计原则
# - 分区数 = 消费者并行度上限
# - 副本因子 >= 3 保证高可用
# - 保留时间根据重放需求设定（通常 7 天）
# Python Kafka 生产者
from confluent_kafka import Producer
import json

producer = Producer({'bootstrap.servers': 'kafka:9092'})

def send_event(user_id, event_type, properties):
    message = json.dumps({
        'user_id': user_id,
        'event': event_type,
        'properties': properties,
        'timestamp': int(time.time() * 1000)
    })
    producer.produce(
        topic='user_events',
        key=user_id,          # 相同 user 路由到同一分区，保证顺序
        value=message
    )
    producer.flush()
Flink 流计算框架
Apache Flink 是当前最成熟的分布式流处理引擎，以"事件时间处理"和"精确一次语义"为核心优势：


// Flink Java API：实时订单金额统计
StreamExecutionEnvironment env = StreamExecutionEnvironment.getExecutionEnvironment();
env.setParallelism(4);

DataStream<String> source = env.addSource(
    new FlinkKafkaConsumer<>("orders", new SimpleStringSchema(), kafkaProps)
);

DataStream<OrderEvent> orders = source
    .map(json -> parseOrder(json))
    .assignTimestampsAndWatermarks(
        WatermarkStrategy.<OrderEvent>forBoundedOutOfOrderness(Duration.ofSeconds(5))
            .withTimestampAssigner((event, ts) -> event.getEventTime())
    );

// 5 分钟滚动窗口统计
DataStream<WindowResult> result = orders
    .keyBy(OrderEvent::getCategory)
    .window(TumblingEventTimeWindows.of(Time.minutes(5)))
    .aggregate(new OrderAggregator(), new WindowResultFunction());

result.addSink(new FlinkKafkaProducer<>("order_stats", ...));
env.execute("Real-time Order Stats");
Flink 的 Python API（PyFlink）在 2026 年已相当成熟：


from pyflink.datastream import StreamExecutionEnvironment
from pyflink.table import StreamTableEnvironment

env = StreamExecutionEnvironment.get_execution_environment()
t_env = StreamTableEnvironment.create(env)

# SQL 方式定义流处理
t_env.execute_sql("""
    CREATE TABLE user_events (
        user_id STRING,
        event_type STRING,
        event_time TIMESTAMP(3),
        WATERMARK FOR event_time AS event_time - INTERVAL '5' SECOND
    ) WITH (
        'connector' = 'kafka',
        'topic' = 'user_events',
        'properties.bootstrap.servers' = 'kafka:9092',
        'format' = 'json'
    )
""")

# 实时 PV/UV 统计
t_env.execute_sql("""
    SELECT 
        TUMBLE_START(event_time, INTERVAL '1' MINUTE) AS window_start,
        event_type,
        COUNT(*) AS pv,
        COUNT(DISTINCT user_id) AS uv
    FROM user_events
    GROUP BY TUMBLE(event_time, INTERVAL '1' MINUTE), event_type
""")
窗口函数设计
窗口是流处理的核心抽象，将无界流切分为有界计算片段：






窗口类型
特点
适用场景





滚动窗口（Tumbling）
固定大小，不重叠
每分钟 PV 统计




滑动窗口（Sliding）
固定大小，可重叠
最近 5 分钟均值，每 1 分钟更新




会话窗口（Session）
按活动间隔动态划分
用户会话分析




全局窗口（Global）
需自定义 Trigger
自定义聚合逻辑





窗口大小的选择涉及延迟与精度的权衡：窗口越小延迟越低但统计波动越大，窗口越大结果越稳定但延迟越高。


状态管理
有状态的流处理是 Flink 区别于简单消息处理的核心能力：


// 实时去重：利用 ValueState 记录已见用户
public class DeduplicateFunction extends KeyedProcessFunction<String, Event, Event> {
    private ValueState<Boolean> seenState;
    
    @Override
    public void open(Configuration params) {
        seenState = getRuntimeContext().getState(
            new ValueStateDescriptor<>("seen", Boolean.class)
        );
    }
    
    @Override
    public void processElement(Event event, Context ctx, Collector<Event> out) throws Exception {
        if (seenState.value() == null) {
            seenState.update(true);
            out.collect(event);
            // 24 小时后清除状态
            ctx.timerService().registerEventTimeTimer(
                ctx.timestamp() + 24 * 3600 * 1000L
            );
        }
    }
    
    @Override
    public void onTimer(long timestamp, OnTimerContext ctx, Collector<Event> out) {
        seenState.clear();
    }
}
Flink 的状态后端（State Backend）决定了状态的存储位置：


    

  • HashMapStateBackend：状态存内存，速度快，容量受限于 JVM 堆
    • 

  • EmbeddedRocksDBStateBackend：状态存本地磁盘（RocksDB），支持超大状态
    • 



Exactly-Once 语义
精确一次（Exactly-Once）是流处理最强的一致性保证，意味着即使发生故障，每条数据也只被处理一次：


Flink 通过 Checkpoint 机制实现 Exactly-Once：


    

  1. JobManager 定期向所有 Source 注入 Barrier（屏障）
    2. 

  2. 各 Operator 收到 Barrier 后将本地状态快照到持久存储
    3. 

  3. 所有 Operator 完成快照后，该 Checkpoint 标记为 Completed
    4. 

  4. 故障恢复时从最近 Completed Checkpoint 恢复状态
    5. 



端到端 Exactly-Once 还需要 Sink 端支持事务（如 Kafka 事务、两阶段提交）。


前沿动态
    

  • Flink 2.x 统一批流：消除批处理和流处理的 API 差异，一套代码同时支持两种模式
    • 

  • Kafka 去 ZooKeeper：KRaft 模式简化运维，Kafka 4.0 完全移除 ZooKeeper 依赖
    • 

  • 流式数据湖：Paimon（原 Flink Table Store）实现流式写入 + 实时查询的湖仓一体
    • 

  • LLM 实时推理：将 LLM 嵌入 Flink 算子，对流数据进行实时文本分析和内容审核

小结
实时流处理技术栈以 Kafka（数据总线）+ Flink（计算引擎）为核心。Kafka 提供高吞吐、持久化的消息队列能力，Flink 提供事件时间处理、精确状态管理和多种窗口语义。掌握窗口设计、状态管理和 Exactly-Once 机制，你将具备构建企业级实时数据管道的核心能力——这也是 2026 年大数据岗位薪资溢价最高的技能方向。
