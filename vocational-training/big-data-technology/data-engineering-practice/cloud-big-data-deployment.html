云上大数据部署

知识要点

2026 年的大数据基础设施已全面云化——超过 80% 的企业选择在公有云上运行大数据工作负载。云平台提供弹性伸缩、免运维、按需付费的优势，大数据工程师需要掌握主流云平台的数据服务和 DataOps 实践。

阿里云 MaxCompute

MaxCompute（原 ODPS）是阿里云的 Serverless 大数据计算平台，支持 PB 级数据的 SQL 分析和机器学习：

-- MaxCompute SQL：与 Hive SQL 高度兼容
-- 创建分区表
CREATE TABLE IF NOT EXISTS dws_order_stats (
    user_id         STRING,
    order_count     BIGINT,
    total_amount    DECIMAL(12, 2),
    avg_amount      DECIMAL(10, 2)
)
PARTITIONED BY (dt STRING)
LIFECYCLE 365;               -- 365 天自动过期删除

-- 数据写入
INSERT OVERWRITE TABLE dws_order_stats PARTITION (dt='2026-05-07')
SELECT 
    user_id,
    COUNT(*) AS order_count,
    SUM(amount) AS total_amount,
    AVG(amount) AS avg_amount
FROM dwd_order_detail
WHERE dt = '2026-05-07'
GROUP BY user_id;

-- 窗口函数 + 数据分层
SELECT user_id, total_amount,
       NTILE(10) OVER (ORDER BY total_amount DESC) AS decile
FROM dws_order_stats
WHERE dt = '2026-05-07';

MaxCompute 成本模型：

  • 按量付费：每扫描 1TB 数据收费约 ¥150（适合临时查询）
  • 包年包月：购买固定 CU（计算单元），适合稳定负载
  • 优化策略：分区裁剪、列裁剪、小文件合并

AWS EMR（Elastic MapReduce）

AWS EMR 是全托管的 Hadoop/Spark 集群服务：

# 使用 boto3 创建 EMR 集群
import boto3

emr = boto3.client('emr', region_name='us-east-1')

cluster_id = emr.run_job_flow(
    Name='daily-etl-cluster',
    ReleaseLabel='emr-7.0.0',
    Applications=[
        {'Name': 'Spark'},
        {'Name': 'Hive'},
        {'Name': 'Presto'}
    ],
    Instances={
        'MasterInstanceType': 'm6g.2xlarge',
        'SlaveInstanceType': 'r6g.4xlarge',
        'InstanceCount': 5,
        'Ec2SubnetId': 'subnet-xxx',
        'KeepJobFlowAliveWhenNoSteps': False,  # 作业完成后自动销毁
    },
    Steps=[{
        'Name': 'Spark ETL Job',
        'ActionOnFailure': 'TERMINATE_CLUSTER',
        'HadoopJarStep': {
            'Jar': 'command-runner.jar',
            'Args': [
                'spark-submit',
                '--deploy-mode', 'cluster',
                '--class', 'com.company.DailyETL',
                's3://my-bucket/jars/etl.jar',
                '--date', '2026-05-07'
            ]
        }
    }],
    LogUri='s3://my-bucket/emr-logs/',
    JobFlowRole='EMR_EC2_DefaultRole',
    ServiceRole='EMR_DefaultRole',
)['JobFlowId']

EMR 架构选择：

  • EC2 模式：传统虚拟机集群，适合长期运行的数据仓库
  • EKS 模式：基于 Kubernetes，适合多租户和资源共享
  • Serverless：无需管理集群，按作业计费，适合间歇性负载

数据湖架构

数据湖将所有原始数据统一存储在对象存储（S3/OSS）上，通过元数据层提供结构化访问：

Apache Iceberg 表格式（2026 年数据湖事实标准）：


-- 创建 Iceberg 表（支持 ACID 事务）
CREATE TABLE catalog.db.orders (
    order_id    BIGINT,
    user_id     STRING,
    amount      DECIMAL(10, 2),
    status      STRING,
    created_at  TIMESTAMP
)
USING iceberg
PARTITIONED BY (days(created_at))
TBLPROPERTIES (
    'write.format.default' = 'parquet',
    'write.parquet.compression-codec' = 'zstd'
);

-- 时间旅行：查看历史版本
SELECT * FROM catalog.db.orders FOR SYSTEM_TIME AS OF '2026-05-01 00:00:00';

-- Schema Evolution（无需重写数据）
ALTER TABLE catalog.db.orders ADD COLUMN discount DECIMAL(5, 2);

-- 合并小文件（维护操作）
CALL catalog.system.rewrite_data_files(table => 'db.orders', strategy => 'binpack');
DataOps 实践
DataOps 将 DevOps 理念应用到数据工程，实现数据管道的持续集成和持续交付：


# dbt 项目配置示例（数据转换的 CI/CD）
# dbt_project.yml
name: 'ecommerce_analytics'
version: '1.0.0'
profile: 'production'

models:
  ecommerce_analytics:
    staging:
      +materialized: view
      +schema: staging
    marts:
      +materialized: table
      +schema: analytics
    
# models/marts/user_lifetime_value.sql
{{ config(materialized='incremental', unique_key='user_id') }}

WITH user_orders AS (
    SELECT
        user_id,
        COUNT(*) AS lifetime_orders,
        SUM(amount) AS lifetime_revenue,
        MIN(created_at) AS first_order_at,
        MAX(created_at) AS last_order_at
    FROM {{ ref('stg_orders') }}
    {% if is_incremental() %}
    WHERE created_at > (SELECT MAX(last_order_at) FROM {{ this }})
    {% endif %}
    GROUP BY user_id
)
SELECT
    user_id,
    lifetime_orders,
    lifetime_revenue,
    lifetime_revenue / NULLIF(lifetime_orders, 0) AS avg_order_value,
    DATEDIFF(day, first_order_at, last_order_at) AS active_days
FROM user_orders

# 自动化成本监控脚本
def analyze_daily_cost(date):
    """分析每日大数据成本并生成优化建议"""
    costs = get_cost_by_service(date)
    
    recommendations = []
    
    # 检查空闲集群
    idle_clusters = [c for c in get_clusters() if c['utilization'] < 0.1]
    if idle_clusters:
        savings = sum(c['hourly_cost'] * 24 for c in idle_clusters)
        recommendations.append(f"关闭 {len(idle_clusters)} 个空闲集群，日省 ¥{savings:.0f}")
    
    # 检查大表无分区裁剪的查询
    expensive_queries = get_queries_without_partition_filter(date)
    if expensive_queries:
        recommendations.append(
            f"{len(expensive_queries)} 个查询未使用分区过滤，建议添加 WHERE dt = 条件"
        )
    
    return {'date': date, 'total_cost': sum(costs.values()), 'recommendations': recommendations}

  • Serverless 数据仓库：Snowflake、BigQuery、MaxCompute 完全无需管理基础设施
    • 

  • 数据湖仓一体：Iceberg + Spark/Flink/Trino 在一套存储上同时支持流式写入和交互查询
    • 

  • FinOps 成熟化：企业设立专门的云成本优化团队，大数据成本优化成为独立岗位
    • 

  • 多云架构：企业为避免厂商锁定，采用 Iceberg + Trino 实现跨云数据访问

小结
云上大数据部署是 2026 年大数据工程师的标配技能。阿里云 MaxCompute 和 AWS EMR 代表了两种典型的云上计算模式（Serverless vs 托管集群），数据湖架构以 Iceberg 为核心实现了存储与计算解耦，DataOps 将工程最佳实践引入数据管道，成本优化确保技术投入的 ROI。掌握这些能力，你将能在入职第一天就上手企业的云上数据基础设施。
