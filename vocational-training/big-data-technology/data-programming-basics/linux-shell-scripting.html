Linux 与 Shell 脚本

知识要点

大数据基础设施几乎全部运行在 Linux 操作系统上。从 Hadoop 集群的日常运维到 ETL 脚本的自动化调度，Linux 命令行操作能力和 Shell 编程技能是大数据工程师的基本功。掌握这些技能意味着你能高效地管理服务器、处理日志、调度任务。

文件系统与权限管理

Linux 文件系统的层级结构和权限模型是系统操作的基础：

# 目录结构认知
/etc/hadoop/conf/       # Hadoop 配置文件
/var/log/               # 系统与应用日志
/opt/spark/             # Spark 安装目录
/data/hdfs/             # HDFS 本地存储路径

# 权限管理（大数据服务通常用专用用户运行）
chmod 750 /opt/hadoop/bin/    # owner=rwx, group=rx, other=无
chown -R hdfs:hadoop /data/hdfs/
# 数字权限：r=4, w=2, x=1，所以 750 = rwxr-x---

# 磁盘与空间监控
df -h                   # 文件系统使用率
du -sh /data/hdfs/*     # 各目录大小
lsblk                   # 块设备信息

Cron 定时调度

Cron 是 Linux 内置的任务调度器，在轻量级 ETL 场景中广泛使用：

# crontab 格式：分 时 日 月 周 命令
# ┌─── 分钟 (0-59)
# │ ┌─── 小时 (0-23)
# │ │ ┌─── 日 (1-31)
# │ │ │ ┌─── 月 (1-12)
# │ │ │ │ ┌─── 周几 (0-7, 0和7都是周日)
# │ │ │ │ │
  0 2 * * * /opt/scripts/daily_etl.sh >> /var/log/etl.log 2>&1
 30 * * * * /opt/scripts/hourly_sync.sh
  0 0 1 * * /opt/scripts/monthly_report.sh

# 常用操作
crontab -e              # 编辑当前用户的调度表
crontab -l              # 查看已有任务

关键注意事项：Cron 环境变量与交互式 Shell 不同，需要在脚本中显式设置 PATH 或使用绝对路径。

AWK 文本处理

AWK 是面向列的流式文本处理语言，特别适合处理日志和 CSV 数据：

# 基础：打印特定列
awk '{print $1, $4}' access.log       # IP 和时间戳

# 条件过滤 + 计算
awk '$9 >= 500 {count++} END {print "5xx errors:", count}' access.log

# 分组统计：按状态码统计请求数
awk '{status[$9]++} END {for (s in status) print s, status[s]}' access.log

# 复杂示例：计算每小时平均响应时间
awk -F'[[ :]' '{
    hour = $5
    time_ms = $NF
    sum[hour] += time_ms
    count[hour]++
}
END {
    for (h in sum) printf "Hour %s: avg %.2f ms\n", h, sum[h]/count[h]
}' access.log

SED 流编辑器

SED 擅长对文本进行行级别的查找替换和变换：

# 替换配置文件中的参数
sed -i 's/dfs.replication=2/dfs.replication=3/g' hdfs-site.xml

# 删除空行和注释行
sed '/^$/d; /^#/d' config.properties > config_clean.properties

# 在特定行后插入内容
sed '/\[core-site\]/a\    fs.defaultFS=hdfs://namenode:9000' hadoop.conf

# 提取特定范围的行
sed -n '100,200p' huge_log.txt

日志处理实战

大数据集群会产生海量日志，高效的日志分析是运维的核心技能：

#!/bin/bash
# 日志分析脚本：统计 Spark 作业失败原因

LOG_DIR="/var/log/spark"
DATE=$(date -d "yesterday" +%Y-%m-%d)
REPORT="/tmp/spark_daily_report_${DATE}.txt"

echo "=== Spark 作业日报 ${DATE} ===" > "$REPORT"

# 统计各级别日志数量
echo -e "\n[日志级别分布]" >> "$REPORT"
for level in INFO WARN ERROR FATAL; do
    count=$(grep -c "^${DATE}.*${level}" "${LOG_DIR}/spark.log")
    echo "  ${level}: ${count}" >> "$REPORT"
done

# 提取 ERROR 的 Top 5 异常类型
echo -e "\n[Top 5 异常类型]" >> "$REPORT"
grep "^${DATE}.*ERROR" "${LOG_DIR}/spark.log" \
    | grep -oP '(?<=Exception: ).*' \
    | sort | uniq -c | sort -rn | head -5 >> "$REPORT"

# OOM 检测
oom_count=$(grep -c "OutOfMemoryError" "${LOG_DIR}/spark.log")
if [ "$oom_count" -gt 0 ]; then
    echo -e "\n⚠️ 检测到 ${oom_count} 次 OOM，建议增加 executor 内存" >> "$REPORT"
fi

cat "$REPORT"

自动化运维脚本

将重复操作封装为脚本，是提升运维效率的关键：

#!/bin/bash
# 集群健康检查脚本

NODES=("node1" "node2" "node3" "node4")
ALERT_THRESHOLD=90

for node in "${NODES[@]}"; do
    # 检查 SSH 连通性
    if ! ssh -o ConnectTimeout=5 "$node" "echo ok" &>/dev/null; then
        echo "[ALERT] ${node} 无法连接"
        continue
    fi
    
    # 检查磁盘使用率
    disk_usage=$(ssh "$node" "df / | tail -1 | awk '{print \$5}' | tr -d '%'")
    if [ "$disk_usage" -ge "$ALERT_THRESHOLD" ]; then
        echo "[WARN] ${node} 磁盘使用率 ${disk_usage}%"
    fi
    
    # 检查关键进程
    for proc in "DataNode" "NodeManager"; do
        if ! ssh "$node" "pgrep -f $proc" &>/dev/null; then
            echo "[ALERT] ${node} 进程 ${proc} 未运行"
        fi
    done
done

前沿动态

  • Infrastructure as Code：Ansible/Terraform 取代手工 Shell 脚本管理集群，但 Shell 仍是 IaC 工具的底层执行引擎
  • 容器化运维：Docker/K8s 环境下，Shell 脚本用于健康检查（liveness/readiness probe）和初始化容器
  • AI 运维助手：自然语言转 Shell 命令工具（如 ai-shell）降低了命令行学习门槛，但理解底层原理仍不可替代
  • eBPF 观测：新一代 Linux 可观测性工具（bpftrace）使性能诊断从"猜测"变为"精确度量"

练习与思考

  1. 编写一个 Shell 脚本，扫描 /var/log/ 下所有 .log 文件，找出 24 小时内修改过的文件，统计其行数并按大小降序输出
  2. 用 AWK 处理一个 CSV 格式的销售数据（字段：日期、产品、地区、金额），按地区分组计算月度总销售额
  3. 设置 Cron 任务：每天凌晨 3 点压缩 7 天前的日志文件（gzip），每月 1 日删除 90 天前的压缩日志
  4. 思考：在什么场景下应该用 Shell 脚本，什么场景下应该用 Python？两者的边界在哪里？

小结

Linux 与 Shell 脚本是大数据工程师的"瑞士军刀"——文件操作、进程管理、日志分析、定时调度、集群运维都离不开它。AWK 和 SED 提供了轻量高效的文本处理能力，Cron 实现基础的任务调度，而结构化的 Shell 脚本将这些单个命令编排为可靠的自动化工作流。这些技能在后续操作 Hadoop/Spark 集群时将每天使用。
