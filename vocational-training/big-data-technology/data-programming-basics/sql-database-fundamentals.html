SQL 与数据库基础

知识要点

SQL 是数据工程师与分析师的通用语言——无论底层是 MySQL、PostgreSQL，还是 Hive、Spark SQL、ClickHouse，SQL 语法都是访问数据的第一接口。扎实的 SQL 能力和关系数据库理论直接决定了数据处理的效率和数据模型的质量。

MySQL 实操基础

MySQL 是高职大数据教学和中小企业最常用的关系数据库：

-- 建表与约束
CREATE TABLE user_orders (
    order_id    BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id     INT NOT NULL,
    product_id  INT NOT NULL,
    amount      DECIMAL(10, 2) NOT NULL,
    status      ENUM('pending', 'paid', 'shipped', 'completed', 'cancelled'),
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_created (user_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 批量插入与性能对比
INSERT INTO user_orders (user_id, product_id, amount, status)
VALUES (1001, 50, 299.00, 'paid'),
       (1002, 32, 159.00, 'pending'),
       (1001, 78, 499.00, 'completed');

索引设计的核心原则：高选择性列优先，复合索引遵循最左前缀匹配。一个合理的索引可以将查询时间从秒级降到毫秒级。

关系设计与范式理论

关系模型设计需要在规范化与查询性能之间取得平衡：

  • 第一范式（1NF）：每列原子值，不可再分
  • 第二范式（2NF）：消除部分依赖（非主属性完全依赖于主键）
  • 第三范式（3NF）：消除传递依赖
实践中，OLTP 系统倾向 3NF（减少冗余、保证一致性），而数据仓库倾向反范式（宽表、预计算，减少 JOIN 提升查询速度）。


复杂查询技巧
大数据分析中常用的高级 SQL 模式：


-- 窗口函数：用户最近 3 笔订单的累计金额
SELECT user_id, order_id, amount,
       SUM(amount) OVER (
           PARTITION BY user_id 
           ORDER BY created_at 
           ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
       ) AS rolling_3_sum
FROM user_orders
WHERE status = 'completed';

-- CTE + 递归：组织架构层级展开
WITH RECURSIVE org_tree AS (
    SELECT id, name, parent_id, 1 AS depth
    FROM departments WHERE parent_id IS NULL
    UNION ALL
    SELECT d.id, d.name, d.parent_id, ot.depth + 1
    FROM departments d
    JOIN org_tree ot ON d.parent_id = ot.id
)
SELECT * FROM org_tree ORDER BY depth, name;

-- 行列转换（PIVOT）
SELECT user_id,
       SUM(CASE WHEN MONTH(created_at) = 1 THEN amount ELSE 0 END) AS jan,
       SUM(CASE WHEN MONTH(created_at) = 2 THEN amount ELSE 0 END) AS feb,
       SUM(CASE WHEN MONTH(created_at) = 3 THEN amount ELSE 0 END) AS mar
FROM user_orders
WHERE YEAR(created_at) = 2026
GROUP BY user_id;
存储过程与事务
存储过程封装复杂业务逻辑，减少网络往返，适用于批量数据处理场景：


DELIMITER //
CREATE PROCEDURE settle_daily_orders(IN settle_date DATE)
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION ROLLBACK;
    
    START TRANSACTION;
    
    UPDATE user_orders
    SET status = 'completed'
    WHERE status = 'shipped'
      AND created_at < settle_date - INTERVAL 7 DAY;
    
    INSERT INTO daily_settlement (settle_date, total_amount, order_count)
    SELECT settle_date, SUM(amount), COUNT(*)
    FROM user_orders
    WHERE status = 'completed'
      AND DATE(created_at) = settle_date;
    
    COMMIT;
END //
DELIMITER ;
事务的 ACID 特性保证了数据一致性：原子性（Atomicity）、一致性（Consistency）、隔离性（Isolation）、持久性（Durability）。


数据建模方法论
面向分析的数据建模通常采用维度建模（Kimball 方法）：


    

  • 事实表：记录业务事件的度量值（金额、数量、时长）
    • 

  • 维度表：描述事件的上下文（时间、地区、产品、用户）
    • 

  • 星型模型：事实表在中心，维度表围绕辐射
    • 

  • 雪花模型：维度表进一步规范化拆分
    • 



维度建模的核心思想是"以业务过程为中心"，每个事实表对应一个可度量的业务事件。


前沿动态
    

  • HTAP 数据库：TiDB、PolarDB 等支持事务与分析混合负载，减少 ETL 延迟
    • 

  • SQL on Everything：DuckDB（嵌入式 OLAP）让开发者在笔记本上直接对 Parquet/CSV 运行分析 SQL，无需搭建集群
    • 

  • AI 生成 SQL：Text-to-SQL 模型（如 BIRD-SQL 基准测试达到 85%+ 准确率）正在重塑数据分析工作流
    • 

  • 向量搜索扩展：pgvector、MySQL HeatWave 将向量相似度搜索内嵌到传统关系数据库
    •

    5. 



小结
SQL 是大数据生态中贯穿始终的技能——从 MySQL 的 OLTP 场景到 Hive/Spark SQL 的 OLAP 分析，语法一脉相承。掌握关系设计理论确保数据模型的合理性，熟练运用窗口函数和 CTE 解决复杂分析问题，理解事务机制保障数据一致性。这些能力在后续学习 Hive 数据仓库和 Spark SQL 时将直接迁移复用。
