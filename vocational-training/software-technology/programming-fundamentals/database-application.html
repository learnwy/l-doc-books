数据库应用开发

知识要点

数据库是几乎所有软件系统的数据存储核心。高职软件技术专业的数据库课程以 MySQL 关系型数据库为主线，覆盖库表设计、SQL 编写与调优、Java 持久层框架（JDBC/MyBatis）以及 Redis 缓存技术，让学生具备从数据建模到高性能数据访问的完整能力。

MySQL 数据库设计

良好的库表设计从需求分析开始，经过概念模型（ER 图）到逻辑模型（范式化）再到物理模型（建表语句）：

-- 订单系统核心表设计
CREATE TABLE orders (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    total_amount DECIMAL(10, 2) NOT NULL DEFAULT 0.00,
    status TINYINT NOT NULL DEFAULT 0 COMMENT '0待付款 1已付款 2已发货 3已完成',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_id (user_id),
    INDEX idx_status_created (status, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

三大范式指导表结构规范化：第一范式要求字段原子性，第二范式消除部分依赖，第三范式消除传递依赖。实际项目中常在第三范式基础上适度反范式化以提升查询性能。

SQL 优化

SQL 性能调优的核心工具是 EXPLAIN，它揭示了查询执行计划：

EXPLAIN SELECT o.id, u.name, o.total_amount
FROM orders o
JOIN users u ON o.user_id = u.id
WHERE o.status = 1 AND o.created_at > '2026-01-01'
ORDER BY o.created_at DESC
LIMIT 20;

关键优化策略：

策略 说明 效果
索引覆盖 查询字段全部在索引中 避免回表
最左前缀 复合索引按声明顺序匹配 索引生效
避免 SELECT * 只查需要的列 减少 IO
分页优化 用 WHERE id > last_id 替代 OFFSET 深分页不退化

慢查询日志（slow_query_log）配合 pt-query-digest 可定位线上性能瓶颈。

JDBC 与 MyBatis

JDBC 是 Java 访问数据库的标准 API，MyBatis 在其上提供了 SQL 映射和对象关系映射能力：

// MyBatis Mapper 接口
@Mapper
public interface OrderMapper {
    
    @Select("SELECT * FROM orders WHERE user_id = #{userId} AND status = #{status}")
    List<Order> findByUserAndStatus(@Param("userId") Long userId, 
                                     @Param("status") Integer status);
    
    @Insert("INSERT INTO orders(user_id, total_amount, status) VALUES(#{userId}, #{totalAmount}, #{status})")
    @Options(useGeneratedKeys = true, keyProperty = "id")
    int insert(Order order);
}

MyBatis 的动态 SQL（<if>、<foreach>、<choose>）解决了复杂查询的 SQL 拼接问题，避免了字符串拼接带来的 SQL 注入风险。

MyBatis-Plus 进一步简化了单表 CRUD，通过条件构造器实现零 SQL 编码：

List<Order> orders = orderMapper.selectList(
    new LambdaQueryWrapper<Order>()
        .eq(Order::getStatus, 1)
        .gt(Order::getCreatedAt, LocalDateTime.of(2026, 1, 1, 0, 0))
        .orderByDesc(Order::getCreatedAt)
);

Redis 缓存技术

Redis 作为内存数据库，读写性能达到 10510^5105 QPS 级别，常用于缓存热点数据、会话存储和分布式锁：

@Service
public class UserService {
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    public User getUserById(Long id) {
        String key = "user:" + id;
        String cached = redisTemplate.opsForValue().get(key);
        if (cached != null) {
            return JSON.parseObject(cached, User.class);
        }
        User user = userMapper.selectById(id);
        if (user != null) {
            redisTemplate.opsForValue().set(key, JSON.toJSONString(user), 
                Duration.ofMinutes(30));
        }
        return user;
    }
}

缓存三大问题及应对：

  • 缓存穿透：查询不存在的数据 → 布隆过滤器或缓存空值
  • 缓存击穿：热点 key 过期 → 互斥锁或逻辑过期
  • 缓存雪崩：大量 key 同时过期 → 过期时间加随机偏移

前沿动态

  • MySQL 9.x 与 HeatWave：Oracle 推出的 HeatWave 引擎让 MySQL 在不导出数据的情况下执行实时分析查询，OLTP + OLAP 一体化趋势明显
  • 分布式数据库普及：TiDB、OceanBase 在国内企业广泛落地，兼容 MySQL 协议但支持水平扩展，高职学生了解分布式概念有利于职业发展
  • AI 辅助 SQL 优化：2026 年 ChatGPT/Copilot 可直接分析慢查询并建议索引策略，但理解 EXPLAIN 输出仍是 DBA 和后端开发者的核心能力

练习与思考

  1. 设计一个博客系统的数据库表结构（用户、文章、评论、标签），要求满足第三范式，并设计合适的索引支撑"按标签查文章"和"按时间倒序分页"两种查询场景。

  2. 编写一段 MyBatis 动态 SQL，实现"多条件组合查询订单"功能：可选条件包括用户 ID、订单状态、金额范围、时间范围，任意组合均需正常工作。

  3. 实现一个带有 Redis 缓存的用户查询服务，要求：a) 缓存命中直接返回；b) 缓存未命中查数据库并写缓存；c) 用户信息更新时主动删除缓存（Cache Aside 模式）。编写测试验证缓存一致性。

小结

数据库应用开发贯穿软件系统的整个生命周期：设计阶段通过 ER 建模和范式化保证数据完整性；开发阶段通过 MyBatis 等框架高效操作数据；运行阶段通过 SQL 优化和 Redis 缓存保障系统性能。从单表 CRUD 到缓存策略，数据层能力的深度直接决定了应用系统的上限。
