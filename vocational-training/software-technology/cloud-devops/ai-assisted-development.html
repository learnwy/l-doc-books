AI 辅助开发

知识要点

AI 辅助开发已从"实验性工具"转变为 2026 年软件工程师的标准生产力工具。GitHub Copilot 和 Cursor 等 AI 编程助手通过大语言模型（LLM）理解代码上下文，实时提供补全建议、生成函数实现、编写测试用例，甚至重构代码结构。掌握 AI 工具的高效使用方法，是新一代开发者的核心竞争力。

AI 编程工具生态

2026 年主流的 AI 编程工具对比：

工具 定位 核心能力 适用场景
GitHub Copilot IDE 插件 行级/块级补全，Chat 对话 日常编码辅助
Cursor AI-native IDE 全文件编辑，多文件重构 深度代码变更
Claude Code 终端 Agent 自主完成复杂任务 多步骤工程任务
Codeium 免费替代方案 补全 + Chat 个人/学生开发

这些工具的底层都是大语言模型（GPT-4o、Claude、Codestral 等），但在交互方式和工作流整合上各有特色。

Copilot 高效使用技巧

Copilot 的补全质量高度依赖上下文质量——好的注释和函数签名能引导出更精准的代码建议：

// 方式1: 写好注释再让 Copilot 生成实现
/**
 * 计算两个日期之间的工作日天数（排除周末和法定节假日）
 * @param start 开始日期
 * @param end 结束日期
 * @param holidays 法定节假日列表
 * @return 工作日天数
 */
public int calculateWorkingDays(LocalDate start, LocalDate end, 
                                 List<LocalDate> holidays) {
    // Copilot 基于注释上下文生成实现...
    int workingDays = 0;
    LocalDate current = start;
    while (!current.isAfter(end)) {
        DayOfWeek day = current.getDayOfWeek();
        if (day != DayOfWeek.SATURDAY && day != DayOfWeek.SUNDAY 
            && !holidays.contains(current)) {
            workingDays++;
        }
        current = current.plusDays(1);
    }
    return workingDays;
}

提升 Copilot 补全质量的实践：

  1. 命名即文档：calculateMonthlyRevenue 比 calc 能触发更好的补全
  2. 类型签名先行：先写好参数和返回类型，再让 AI 填充实现
  3. 提供示例：在注释中给出输入输出示例，AI 会遵循模式
  4. 相关文件打开：Copilot 会参考当前打开的相关文件作为上下文

Cursor 多文件编辑

Cursor 的 Composer 功能可以同时编辑多个文件，适合重构和新功能开发：

用户指令（自然语言）:
"为 UserService 添加邮件验证功能：
1. 新增 EmailService 接口和实现
2. 在用户注册时发送验证邮件
3. 添加 /api/verify-email 接口
4. 编写对应的单元测试"

Cursor 会同时创建/修改:
- src/service/EmailService.java (新建)
- src/service/impl/EmailServiceImpl.java (新建)
- src/service/UserService.java (修改)
- src/controller/AuthController.java (修改)
- test/service/EmailServiceTest.java (新建)

Cursor 的 @ 引用机制让上下文更精确：

  • @file 引用特定文件
  • @codebase 搜索整个项目
  • @docs 引用官方文档
  • @web 搜索最新信息

Prompt Engineering 实践

与 AI 编程工具交互的核心是 Prompt 质量。结构化 Prompt 公式：

角色 + 上下文 + 任务 + 约束 + 输出格式

示例:
"你是一个 Java 后端开发专家。当前项目使用 Spring Boot 3 + MyBatis-Plus + MySQL 8。
请为订单模块实现以下功能：
- 创建订单（校验库存、计算金额、扣减库存）
- 使用乐观锁防止超卖
- 事务回滚保证一致性
约束：
- 遵循当前项目的分层架构（Controller → Service → Mapper）
- 使用 LambdaQueryWrapper 而非字符串 SQL
- 异常使用自定义 BusinessException"

Prompt 优化技巧：

技巧 说明 效果
指定技术栈 "使用 Spring Boot 3 + JDK 21" 避免过时 API
给出约束 "不使用 Lombok" 符合项目规范
分步执行 "先设计接口，再实现" 降低出错率
提供示例 "参考 UserController 的风格" 风格一致
要求解释 "解释关键设计决策" 便于审查

AI 辅助测试生成
AI 在测试领域的应用已非常成熟：


// 提示: "为 OrderService.createOrder 生成单元测试，覆盖：
// 正常下单、库存不足、金额计算、并发下单"

@ExtendWith(MockitoExtension.class)
class OrderServiceTest {
    
    @Mock private OrderMapper orderMapper;
    @Mock private ProductMapper productMapper;
    @InjectMocks private OrderServiceImpl orderService;
    
    @Test
    void createOrder_success() {
        // Given
        Product product = new Product(1L, "键盘", new BigDecimal("299.00"), 100);
        when(productMapper.selectById(1L)).thenReturn(product);
        when(productMapper.deductStock(1L, 2)).thenReturn(1); // 扣减成功
        
        CreateOrderDTO dto = new CreateOrderDTO(1L, 1L, 2);
        
        // When
        Order order = orderService.createOrder(dto);
        
        // Then
        assertNotNull(order);
        assertEquals(new BigDecimal("598.00"), order.getTotalAmount());
        verify(orderMapper).insert(any(Order.class));
    }
    
    @Test
    void createOrder_insufficientStock_throwsException() {
        Product product = new Product(1L, "键盘", new BigDecimal("299.00"), 1);
        when(productMapper.selectById(1L)).thenReturn(product);
        
        CreateOrderDTO dto = new CreateOrderDTO(1L, 1L, 5); // 库存不足
        
        assertThrows(BusinessException.class, () -> orderService.createOrder(dto));
        verify(orderMapper, never()).insert(any());
    }
}
前沿动态
    

  • Agentic Coding：2026 年 AI Agent（如 Claude Code、Devin）可自主完成从 Issue 到 PR 的完整开发闭环，开发者角色从"写代码"转向"定义需求和审查结果"
    • 

  • AI 代码审查：CodeRabbit、Copilot for PRs 自动识别潜在 Bug、性能问题和安全漏洞
    • 

  • 上下文工程：AI 编程的核心瓶颈从模型能力转向上下文管理——如何让 AI 理解整个项目的架构和约定
    • 

  • AI 安全编码：专用安全模型可识别 AI 生成代码中的漏洞，形成"AI 生成 → AI 审计"的闭环
    • 

  • 模型本地化：Ollama 等工具让开发者在本地运行代码模型（DeepSeek Coder、CodeLlama），适用于涉密项目

练习与思考
    

  1. 使用 Copilot 或 Cursor 完成一个完整的 CRUD 模块开发（从 Controller 到 Mapper），记录 AI 生成代码中你发现并修正的问题（至少找出 3 处），分析 AI 容易出错的模式。
    

    2. 

  2. 设计一组 Prompt，让 AI 为一个复杂业务逻辑（如"秒杀下单"）生成实现代码。对比不同 Prompt 写法（模糊 vs 精确、无约束 vs 有约束）的输出质量差异。
    

    3. 

  3. 选择一个开源项目的 Issue，尝试仅通过与 AI 对话（不手动写代码）来完成 Bug 修复或功能实现。记录交互轮次、总耗时、以及最终代码的质量评估。
    

    4. 



小结
AI 辅助开发正在重新定义"编程"的含义——从逐行编码转向定义意图、审查结果和把控质量。高效使用 AI 工具需要掌握三项能力：Prompt Engineering（精确表达需求）、上下文管理（给 AI 足够的背景信息）和批判性审查（识别 AI 输出的问题）。AI 是强大的生产力倍增器，但理解底层原理和具备判断力的开发者才能真正驾驭它。
