Linux 运维

知识要点

Linux 是全球超过 96% 服务器的操作系统，从云服务器到容器运行时都构建在 Linux 之上。高职软件技术专业的 Linux 课程以 CentOS/Ubuntu 为实践环境，培养学生独立完成服务器部署、故障排查和安全加固的运维能力。

文件系统与目录结构

Linux 采用树形文件系统，一切皆文件：

/
├── bin/         # 基本命令（ls, cp, mv）
├── etc/         # 系统配置文件
├── home/        # 用户主目录
├── var/         # 可变数据（日志、缓存）
│   └── log/     # 系统和应用日志
├── opt/         # 第三方软件安装
├── tmp/         # 临时文件
└── usr/         # 用户程序
    ├── local/   # 手动安装的软件
    └── bin/     # 用户命令

文件操作核心命令：

# 查找文件
find /var/log -name "*.log" -mtime -7      # 最近7天修改的日志

# 文本处理三剑客
grep -r "ERROR" /var/log/app/ --include="*.log"   # 递归搜索错误
awk '{print $1, $4}' access.log | sort | uniq -c  # 统计 IP 访问量
sed -i 's/8080/9090/g' application.yml             # 批量替换端口号

# 磁盘管理
df -h                    # 查看磁盘使用率
du -sh /var/log/*       # 各目录占用空间

用户与权限管理

Linux 权限模型由用户（User）、组（Group）和其他（Other）三部分构成，每部分拥有读（r=4）、写（w=2）、执行（x=1）三种权限：

# 权限示例
-rwxr-xr--  1 deploy appgroup  4096 May 01 10:00 app.jar
# 所有者: rwx(7) | 同组: r-x(5) | 其他: r--(4) → 754

# 用户管理
useradd -m -s /bin/bash deploy         # 创建部署专用用户
usermod -aG docker deploy              # 加入 docker 组
chmod 750 /opt/app                     # 设置目录权限
chown -R deploy:appgroup /opt/app      # 更改所有权

最小权限原则：应用进程以非 root 用户运行，数据库端口不对外暴露，SSH 禁止 root 直接登录。

Shell 脚本编程

Shell 脚本将重复性运维操作自动化：

#!/bin/bash
# 应用部署脚本

APP_NAME="myapp"
JAR_FILE="/opt/app/${APP_NAME}.jar"
LOG_FILE="/var/log/${APP_NAME}/app.log"
PID_FILE="/var/run/${APP_NAME}.pid"

start() {
    if [ -f "$PID_FILE" ] && kill -0 $(cat "$PID_FILE") 2>/dev/null; then
        echo "${APP_NAME} 已在运行中 (PID: $(cat $PID_FILE))"
        return 1
    fi
    
    echo "启动 ${APP_NAME}..."
    nohup java -Xmx512m -jar "$JAR_FILE" \
        --spring.profiles.active=prod \
        > "$LOG_FILE" 2>&1 &
    
    echo $! > "$PID_FILE"
    echo "${APP_NAME} 启动成功 (PID: $!)"
}

stop() {
    if [ ! -f "$PID_FILE" ]; then
        echo "${APP_NAME} 未在运行"
        return 1
    fi
    
    local pid=$(cat "$PID_FILE")
    echo "停止 ${APP_NAME} (PID: ${pid})..."
    kill "$pid"
    
    # 等待进程退出，最多30秒
    for i in $(seq 1 30); do
        if ! kill -0 "$pid" 2>/dev/null; then
            rm -f "$PID_FILE"
            echo "${APP_NAME} 已停止"
            return 0
        fi
        sleep 1
    done
    
    kill -9 "$pid"
    rm -f "$PID_FILE"
    echo "${APP_NAME} 强制终止"
}

case "$1" in
    start)  start ;;
    stop)   stop ;;
    restart) stop && sleep 2 && start ;;
    *) echo "用法: $0 {start|stop|restart}" ;;
esac

服务部署与进程管理

systemd 是现代 Linux 的服务管理器：

# /etc/systemd/system/myapp.service
[Unit]
Description=My Spring Boot Application
After=network.target

[Service]
Type=simple
User=deploy
ExecStart=/usr/bin/java -Xmx512m -jar /opt/app/myapp.jar
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
systemctl daemon-reload
systemctl enable myapp       # 开机自启
systemctl start myapp        # 启动
systemctl status myapp       # 查看状态
journalctl -u myapp -f       # 实时查看日志

日志分析

日志是故障排查的第一手资料：

# 实时追踪错误日志
tail -f /var/log/app/error.log | grep --line-buffered "Exception"

# 统计最近1小时 5xx 错误数
awk -v start="$(date -d '1 hour ago' '+%d/%b/%Y:%H:%M')" \
    '$4 > "["start && $9 ~ /^5/' access.log | wc -l

# 按分钟统计请求量（发现流量突增）
awk '{print substr($4, 2, 17)}' access.log | sort | uniq -c | tail -20

ELK Stack（Elasticsearch + Logstash + Kibana）是企业级日志平台的标准方案。

安全加固

# SSH 安全配置 (/etc/ssh/sshd_config)
PermitRootLogin no           # 禁止 root SSH
PasswordAuthentication no    # 仅密钥认证
Port 2222                    # 修改默认端口

# 防火墙 (firewalld)
firewall-cmd --permanent --add-port=80/tcp
firewall-cmd --permanent --add-port=443/tcp
firewall-cmd --reload

# fail2ban 防暴力破解
apt install fail2ban
systemctl enable fail2ban

前沿动态

  • 不可变基础设施：2026 年服务器不再"维护"而是"替换"——出问题直接销毁重建新实例，配合 Terraform + Ansible 实现
  • eBPF 可观测性：Linux 内核级别的观测能力，无需修改应用代码即可获取网络流量、系统调用等详细信息
  • AI 辅助运维：AIOps 工具可自动识别日志中的异常模式、预测故障、生成排查建议
  • 安全左移：DevSecOps 将安全检查嵌入 CI 流水线，容器镜像扫描、依赖漏洞检测在部署前自动完成

练习与思考

  1. 在云服务器（或虚拟机）上完成以下操作：创建 deploy 用户、配置 SSH 密钥登录并禁止密码登录、安装 JDK 17、部署一个 Spring Boot 应用并配置为 systemd 服务。

  2. 编写一个 Shell 脚本实现日志轮转：当 /var/log/app/app.log 超过 100MB 时，将其压缩归档为 app.log.{date}.gz，保留最近 7 天的归档，自动清理更早的文件。配置 crontab 每小时执行一次。

  3. 模拟线上故障排查：在应用日志中注入大量 ERROR 信息，使用 grep + awk 组合定位错误集中的时间段和错误类型，编写排查报告说明根因和修复方案。

小结

Linux 运维能力是后端开发者和运维工程师的必备技能。文件系统操作和权限管理保障了系统安全；Shell 脚本将重复操作自动化；systemd 和日志分析支撑了应用的稳定运行。掌握这些基础后，进阶的容器化和 Kubernetes 编排才有坚实的操作系统层支撑。
