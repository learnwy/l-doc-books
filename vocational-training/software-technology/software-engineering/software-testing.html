软件测试

知识要点

软件测试是保障产品质量的最后一道防线，也是贯穿开发全流程的质量工程活动。高职软件技术专业的测试课程从测试理论出发，经过用例设计方法，到自动化测试工具实战，让学生具备独立承担测试工程师岗位的能力。

测试基础理论

软件测试的本质是通过有限的测试用例发现尽可能多的缺陷。测试金字塔模型描述了各层测试的比例关系：

测试分类维度：


    

  • 按阶段：单元测试 → 集成测试 → 系统测试 → 验收测试
    • 

  • 按方法：黑盒测试（关注输入输出）、白盒测试（关注内部逻辑）
    • 

  • 按目的：功能测试、性能测试、安全测试、兼容性测试
    •

黑盒与白盒测试
黑盒测试不关心内部实现，只验证输入对应的输出是否符合预期。白盒测试关注代码覆盖率：


    

  • 语句覆盖：每条可执行语句至少执行一次
    • 

  • 分支覆盖：每个判断的真/假分支至少执行一次
    • 

  • 路径覆盖：所有可能的执行路径至少走一次
    • 



// 白盒测试示例 — 分支覆盖
public String classify(int score) {
    if (score >= 90) return "优秀";      // 分支1-T
    else if (score >= 60) return "及格";  // 分支2-T
    else return "不及格";                 // 分支2-F
}

// 测试用例：score=95(分支1-T), score=75(分支1-F,2-T), score=40(分支1-F,2-F)
Selenium Web 自动化测试
Selenium WebDriver 模拟用户操作浏览器，实现 UI 层的回归测试自动化：


public class LoginTest {
    private WebDriver driver;
    
    @BeforeEach
    void setup() {
        driver = new ChromeDriver();
        driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));
    }
    
    @Test
    void testLoginSuccess() {
        driver.get("http://localhost:8080/login");
        
        driver.findElement(By.id("username")).sendKeys("admin");
        driver.findElement(By.id("password")).sendKeys("Admin@123");
        driver.findElement(By.id("login-btn")).click();
        
        WebElement welcome = driver.findElement(By.className("welcome-msg"));
        assertTrue(welcome.getText().contains("欢迎"));
    }
    
    @AfterEach
    void teardown() {
        driver.quit();
    }
}
Page Object 模式将页面元素封装为对象，提升自动化脚本的可维护性：


public class LoginPage {
    private WebDriver driver;
    
    @FindBy(id = "username") private WebElement usernameInput;
    @FindBy(id = "password") private WebElement passwordInput;
    @FindBy(id = "login-btn") private WebElement loginButton;
    
    public LoginPage(WebDriver driver) {
        this.driver = driver;
        PageFactory.initElements(driver, this);
    }
    
    public DashboardPage login(String user, String pass) {
        usernameInput.sendKeys(user);
        passwordInput.sendKeys(pass);
        loginButton.click();
        return new DashboardPage(driver);
    }
}

JMeter 测试计划的核心组件：线程组（模拟用户数）→ HTTP 请求采样器 → 断言 → 监听器（聚合报告）。压测时逐步加压观察系统拐点。


前沿动态
    

  • AI 生成测试用例：2026 年 Copilot 和专用测试 AI 可根据代码逻辑自动生成单元测试和边界条件，测试工程师角色从"编写用例"转向"设计策略和验证 AI 输出"
    • 

  • Playwright 替代 Selenium：微软的 Playwright 在跨浏览器自动化、录制回放、网络模拟方面表现更优，逐渐成为新项目首选
    • 

  • 混沌工程：通过注入故障（网络延迟、服务宕机）验证系统韧性，从测试"功能正确"扩展到测试"故障容忍"
    • 

  • Shift-Left Testing：测试左移至开发阶段，TDD/BDD 在敏捷团队中更加普及
    • 



练习与思考
    

  1. 为一个"用户注册"功能设计完整的测试用例集：使用等价类划分和边界值分析方法，覆盖用户名、密码、邮箱、手机号四个输入字段。要求用例数不超过 25 条但覆盖所有关键场景。
    

    2. 

  2. 使用 Selenium (或 Playwright) 为一个登录页面编写自动化测试脚本，采用 Page Object 模式，覆盖：正常登录、密码错误、账号锁定三个场景。
    

    3. 

  3. 使用 JMeter 对你的 Spring Boot 项目 API 进行压力测试：分别在 50、100、200 并发用户下测试登录接口的 TPS 和响应时间，画出负载-性能曲线，找出系统瓶颈。
    

    4. 



小结
软件测试是工程质量保障的核心手段。测试用例设计方法（等价类、边界值、判定表）提供了系统化发现缺陷的思路；自动化测试工具（Selenium/Playwright）将重复性验证从人力中解放出来；性能测试（JMeter）确保系统在真实负载下仍能稳定运行。"测试思维"不只是测试工程师的专属能力——优秀的开发者同样需要具备质量意识和测试习惯。
