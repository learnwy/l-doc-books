后端 API 开发

知识要点

后端 API 是前端应用与数据层之间的桥梁，它定义了数据的流转规则和业务逻辑的执行方式。Spring Boot 凭借"约定优于配置"的理念成为 Java 后端开发的事实标准，本节围绕 RESTful API 设计、JWT 无状态认证、Swagger 文档自动化和接口安全展开。

RESTful API 设计原则

REST 将服务端资源映射为 URL，通过 HTTP 方法表达操作语义：

HTTP 方法 语义 示例 幂等性
GET 查询资源 GET /api/users/1 是
POST 创建资源 POST /api/users 否
PUT 全量更新 PUT /api/users/1 是
PATCH 部分更新 PATCH /api/users/1 是
DELETE 删除资源 DELETE /api/users/1 是

统一响应格式提升 API 的可消费性：

@Data
@AllArgsConstructor
public class ApiResponse<T> {
    private int code;
    private String message;
    private T data;
    
    public static <T> ApiResponse<T> success(T data) {
        return new ApiResponse<>(200, "success", data);
    }
    
    public static ApiResponse<?> error(int code, String msg) {
        return new ApiResponse<>(code, msg, null);
    }
}

Spring Boot 控制器与参数校验

使用 @Validated 配合 JSR 380 注解实现声明式参数校验：

@RestController
@RequestMapping("/api/users")
public class UserController {
    
    @Autowired
    private UserService userService;
    
    @PostMapping
    public ApiResponse<UserVO> createUser(@RequestBody @Validated CreateUserDTO dto) {
        UserVO user = userService.create(dto);
        return ApiResponse.success(user);
    }
    
    @GetMapping
    public ApiResponse<PageResult<UserVO>> listUsers(
            @RequestParam(defaultValue = "1") int page,
            @RequestParam(defaultValue = "20") int size) {
        return ApiResponse.success(userService.list(page, size));
    }
}

@Data
public class CreateUserDTO {
    @NotBlank(message = "用户名不能为空")
    @Size(min = 2, max = 20)
    private String username;
    
    @Email(message = "邮箱格式不正确")
    private String email;
    
    @NotBlank
    @Pattern(regexp = "^(?=.*[a-z])(?=.*[A-Z])(?=.*\\d).{8,}$",
             message = "密码需包含大小写字母和数字，至少8位")
    private String password;
}

全局异常处理器统一拦截校验失败和业务异常：

@RestControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ApiResponse<?> handleValidation(MethodArgumentNotValidException ex) {
        String msg = ex.getBindingResult().getFieldErrors().stream()
            .map(e -> e.getField() + ": " + e.getDefaultMessage())
            .collect(Collectors.joining("; "));
        return ApiResponse.error(400, msg);
    }
    
    @ExceptionHandler(BusinessException.class)
    public ApiResponse<?> handleBusiness(BusinessException ex) {
        return ApiResponse.error(ex.getCode(), ex.getMessage());
    }
}

JWT 无状态认证

JSON Web Token 将用户身份信息编码在 Token 中，服务端无需维护 Session：

JWT 结构分为三部分：Header（算法声明）、Payload（用户信息和过期时间）、Signature（防篡改签名）。Token 有效期一般设为 2h2h2h，配合 Refresh Token 机制实现无感续期。


public String generateToken(UserDetails user) {
    return Jwts.builder()
        .setSubject(user.getUsername())
        .claim("roles", user.getAuthorities())
        .setIssuedAt(new Date())
        .setExpiration(new Date(System.currentTimeMillis() + 7200000))
        .signWith(secretKey, SignatureAlgorithm.HS256)
        .compact();
}

接口安全
除 JWT 认证外，API 安全还需关注：


    

  • CORS 配置：限制允许的 Origin，避免跨域攻击
    • 

  • 限流（Rate Limiting）：使用令牌桶或滑动窗口算法，防止接口被刷
    • 

  • SQL 注入防护：始终使用参数化查询（MyBatis #{} 而非 ${}）
    • 

  • XSS 防护：对用户输入的 HTML 内容进行转义
    • 

  • HTTPS：生产环境强制 TLS 加密传输
    • 



前沿动态
    

  • Spring Boot 3.3+：基于 GraalVM 的 AOT 编译让启动时间从秒级降至毫秒级，适配 Serverless 部署场景
    • 

  • GraphQL 与 BFF：部分场景中 GraphQL 替代 REST 实现更灵活的数据查询，但 REST 仍是主流
    • 

  • API Gateway：Spring Cloud Gateway 或 APISIX 在微服务架构中统一处理认证、限流、灰度等横切关注点
    • 

  • AI 辅助 API 开发：Copilot 可根据 OpenAPI spec 自动生成 Controller/Service/DTO 代码骨架
    •

小结
后端 API 开发是全栈能力的核心环节，它将业务逻辑暴露为标准化的 HTTP 接口供前端和移动端消费。RESTful 设计保证接口的一致性和可理解性，JWT 实现轻量级安全认证，Swagger 自动化文档桥接前后端协作，参数校验和异常处理则筑牢了系统的健壮性防线。这些规范和实践在企业级项目中每天都在使用。
