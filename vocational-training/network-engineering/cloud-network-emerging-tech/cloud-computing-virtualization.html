          云计算与虚拟化

          知识要点

          云计算从根本上改变了企业IT基础设施的供给模式——从自建机房采购物理服务器转变为按需租用弹性计算资源。虚拟化技术是云计算的底层支撑，通过软件抽象将物理硬件资源转化为多个隔离的虚拟环境。对于网络工程师而言，理解虚拟化环境中的网络实现机制和云平台的网络服务架构，是在云化时代保持核心竞争力的关键。

          虚拟化技术原理

          虚拟化通过Hypervisor（虚拟机监控程序）在物理硬件之上创建多个隔离的虚拟机（VM），每个VM拥有独立的操作系统和应用环境。

          Hypervisor分类：

          • Type 1（裸金属）：直接运行在物理硬件上，如VMware ESXi、KVM、Microsoft Hyper-V
          • Type 2（宿主型）：运行在宿主操作系统之上，如VMware Workstation、VirtualBox
          虚拟网络实现：
          

          Hypervisor内部通过虚拟交换机（vSwitch）实现VM之间和VM到外部网络的通信：
          

            

          • VMware vSphere分布式交换机（VDS）：跨多台ESXi主机的逻辑交换机，支持VLAN、流量监控、端口镜像
            • 

          • Linux Bridge：KVM环境的默认虚拟交换方案
            • 

          • Open vSwitch（OVS）：支持OpenFlow协议的软件交换机，是SDN和云平台（OpenStack）的网络基础组件
            • 

          

          SR-IOV（Single Root I/O Virtualization）：绕过Hypervisor的虚拟化层，让VM直接访问物理网卡的虚拟功能（VF），实现接近物理网卡的转发性能：
          

          SR-IOV延迟≈3μsvsvSwitch延迟≈50μs\text{SR-IOV延迟} \approx 3\mu s \quad vs \quad \text{vSwitch延迟} \approx 50\mu sSR-IOV延迟≈3μsvsvSwitch延迟≈50μs

          IaaS网络服务（以主流公有云为例）：
          

            

          • VPC（虚拟私有云）：逻辑隔离的虚拟网络空间，用户自定义CIDR地址块
            • 

          • 子网（Subnet）：VPC内的IP地址范围，绑定可用区（AZ）
            • 

          • 安全组（Security Group）：实例级别的有状态防火墙规则
            • 

          • 网络ACL：子网级别的无状态流量过滤
            • 

          • NAT网关：为私有子网实例提供出站互联网访问
            • 

          • 负载均衡器（ELB/ALB/NLB）：将流量分发到多个后端实例
            • 

          

          VPC网络地址规划建议预留充足的地址空间：
          

          VPC CIDR建议≥/16（65534个可用IP）\text{VPC CIDR建议} \geq /16 \text{（65534个可用IP）}VPC CIDR建议≥/16（65534个可用IP）
          子网按照功能分层划分：公有子网（放置NAT/LB）+ 私有子网（放置应用服务器）+ 数据子网（放置数据库）。
          

          容器与Kubernetes网络
          容器是比VM更轻量的虚拟化技术，共享宿主机内核但具有独立的文件系统和网络命名空间。
          

          Docker网络模式：
          

            

          • Bridge模式（默认）：容器通过docker0虚拟网桥互通
            • 

          • Host模式：容器直接使用宿主机网络栈
            • 

          • None模式：无网络（需手动配置）
            • 

          • Overlay模式：跨主机容器通信（Docker Swarm）
            • 

          

          Kubernetes网络模型核心要求：
          

            

          • Pod内所有容器共享网络命名空间（localhost通信）
            • 

          • 所有Pod之间可直接通信（无需NAT）
            • 

          • 所有Node与所有Pod之间可直接通信
            •

          Kubernetes Service网络：
          

            

          • ClusterIP：集群内部虚拟IP，通过kube-proxy实现负载均衡
            • 

          • NodePort：在每个节点暴露固定端口（30000-32767）
            • 

          • LoadBalancer：对接云厂商LB实现外部流量接入
            • 

          • Ingress：HTTP/HTTPS层的路由规则（域名/路径→Service映射）
            • 

          

          混合云网络连接方案
          企业通常需要将本地数据中心与公有云VPC安全互联：
          

            

          • VPN连接：通过IPSec VPN隧道实现加密互联（带宽有限，适合小流量场景）
            • 

          • 专线连接（Direct Connect/Express Route）：物理专线或MPLS直连，提供稳定低延迟的大带宽通道
            • 

          • 云企业网（CEN/Transit Gateway）：多VPC和多数据中心通过中心枢纽互联互通
            • 

          

          专线带宽与成本的权衡计算：
          

          每月专线成本=端口月租+流量费×月均流量(TB)\text{每月专线成本} = \text{端口月租} + \text{流量费} \times \text{月均流量(TB)}每月专线成本=端口月租+流量费×月均流量(TB)
          当月均流量超过阈值时，专线比VPN over Internet更经济（需具体计算Break-even Point）。
          

          前沿动态
          eBPF（extended Berkeley Packet Filter）正在革新云原生网络的数据面——Cilium CNI通过eBPF直接在Linux内核中执行网络策略和负载均衡，避免了iptables的性能瓶颈，在大规模Kubernetes集群中实现万级Service的高性能转发。
          

          Serverless容器（如AWS Fargate、阿里云ECI）进一步简化了网络管理——用户无需管理Node层面的网络配置，容器直接运行在云商管理的弹性计算节点上，通过VPC ENI直接获得VPC内IP地址。
          

          练习与思考
            

          1. 在云平台上创建一个VPC，包含公有子网和私有子网，配置NAT网关使私有子网实例可以访问互联网但不可被互联网直接访问
            2. 

          2. 使用Minikube或Kind搭建本地Kubernetes集群，部署一个多副本的Nginx应用，通过Service和Ingress实现外部访问
            3. 

          3. 对比VMware ESXi虚拟网络和Kubernetes CNI网络在隔离机制、性能和灵活性方面的差异
            4. 

          4. 某企业需要将本地Oracle数据库与云上应用连接，日均数据同步量约500GB，请对比VPN和专线两种方案的成本和性能
            5. 

          

          小结
          云计算和虚拟化重塑了网络工程的技术栈和工作方式。虚拟化在物理设备之上创建了软件定义的网络层，云服务模型将网络功能转化为可编程的API服务，容器和Kubernetes带来了更细粒度的网络抽象和自动化能力。网络工程师需要从传统的"配置物理设备"思维转向"编排虚拟网络服务"的云原生视角，同时理解混合云场景下本地与云端网络的互联架构，才能在云化浪潮中持续创造价值。
