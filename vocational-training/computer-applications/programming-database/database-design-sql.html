数据库设计与 SQL

知识要点

几乎所有信息系统的背后都有一个数据库在运转——网上购物的订单记录、学校的学生信息、医院的就诊档案、企业的财务数据，都存储在数据库中。掌握关系数据库的设计方法和 SQL 查询语言，是从"数据使用者"进阶为"系统搭建者"的关键一步。

关系数据库核心概念

数据库（Database）：有组织地存储和管理数据的仓库。

表（Table）：数据库中的核心对象，以行和列的二维结构存储数据。每行是一条记录（Record），每列是一个字段（Field）。

关键术语：

概念 说明 示例
主键（Primary Key） 唯一标识一条记录的字段 学号、身份证号
外键（Foreign Key） 指向另一张表主键的引用 选课表中的学号引用学生表
索引（Index） 加速查询的数据结构 给"姓名"字段建索引
约束（Constraint） 保证数据完整性的规则 NOT NULL, UNIQUE, CHECK

SQL 增删改查（CRUD）
创建数据库和表：


CREATE DATABASE school_db CHARACTER SET utf8mb4;
USE school_db;

CREATE TABLE students (
    student_id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    gender ENUM('男', '女') NOT NULL,
    class VARCHAR(30),
    enrollment_date DATE,
    phone VARCHAR(11)
);
插入数据（INSERT）：


INSERT INTO students (name, gender, class, enrollment_date, phone)
VALUES ('张三', '男', '计算机1班', '2024-09-01', '13800138001');

-- 批量插入
INSERT INTO students (name, gender, class, enrollment_date, phone) VALUES
('李四', '女', '计算机1班', '2024-09-01', '13800138002'),
('王五', '男', '计算机2班', '2024-09-01', '13800138003'),
('赵六', '女', '计算机2班', '2024-09-01', '13800138004');
查询数据（SELECT）：


-- 查询所有学生
SELECT * FROM students;

-- 条件查询
SELECT name, class FROM students WHERE gender = '女';

-- 模糊查询
SELECT * FROM students WHERE name LIKE '张%';

-- 排序
SELECT * FROM students ORDER BY enrollment_date DESC;

-- 聚合函数
SELECT class, COUNT(*) AS 人数 FROM students GROUP BY class;

-- 多表联查（查询学生选课及成绩）
SELECT s.name, c.course_name, e.score
FROM students s
JOIN enrollment e ON s.student_id = e.student_id
JOIN courses c ON e.course_id = c.course_id
WHERE e.score >= 60
ORDER BY e.score DESC;
更新数据（UPDATE）：


-- 修改单条记录
UPDATE students SET phone = '13900139001' WHERE student_id = 1;

-- 批量更新
UPDATE students SET class = '计算机3班' WHERE class = '计算机2班';
删除数据（DELETE）：


-- 删除特定记录（务必带 WHERE 条件！）
DELETE FROM students WHERE student_id = 4;

-- 清空表（保留表结构）
TRUNCATE TABLE temp_data;
表设计与规范化
数据库设计三范式：


    

  • 第一范式（1NF）：每个字段不可再分。如"地址"不应存储"省+市+区"的合并文本，应拆分为三个字段。
    • 

  • 第二范式（2NF）：非主键字段完全依赖于主键（消除部分依赖）。
    • 

  • 第三范式（3NF）：非主键字段不依赖于其他非主键字段（消除传递依赖）。
    • 



实际设计建议：


    

  • 主键统一使用自增 INT（或 BIGINT）
    • 

  • 字段命名用小写下划线风格（student_name 而非 StudentName）
    • 

  • 日期字段用 DATE/DATETIME 类型，不用字符串存储
    • 

  • 金额字段用 DECIMAL(10,2)，不用 FLOAT（浮点精度问题）
    • 

  • 每张表添加 created_at 和 updated_at 时间戳字段
    • 



索引优化
索引大幅提升查询速度，但也增加写入开销和存储空间。


索引使用原则：


    

  • WHERE 子句中频繁出现的字段建索引
    • 

  • 作为 JOIN 条件的外键字段建索引
    • 

  • 数据量小的表（< 1000 行）不需要索引
    • 

  • 频繁更新的字段避免建索引
    • 



-- 创建索引
CREATE INDEX idx_student_name ON students(name);

-- 查看执行计划（判断是否使用了索引）
EXPLAIN SELECT * FROM students WHERE name = '张三';
查询性能的经验公式：无索引的全表扫描时间复杂度为 O(n)O(n)O(n)，B+Tree 索引查询为 O(log⁡n)O(\log n)O(logn)——当表有 100 万行数据时，差距从遍历 100 万次缩减到约 20 次磁盘读取。


前沿动态
2026 年数据库领域的新趋势：云原生数据库（如阿里云 PolarDB、AWS Aurora）让中小企业无需自建服务器即可使用高性能数据库；AI 数据库助手可通过自然语言生成 SQL（如"查询上月销售额前十的产品"自动转为 SQL 语句）；NewSQL 数据库（TiDB、CockroachDB）兼顾了关系型的一致性和 NoSQL 的水平扩展能力；低代码平台让非开发人员也能通过拖拽创建数据库应用；向量数据库（Milvus、Pinecone）成为 AI 应用的标配存储。

小结
数据库是信息系统的数据基石。本节从概念模型（实体关系）到物理实现（建表语句），从基础 CRUD 到多表关联查询，从规范化设计到索引优化，构建了完整的数据库应用能力。SQL 语言的核心就是"描述你想要什么数据"——思路清晰比记住语法更重要。在实际工作中，大多数业务需求都可以通过灵活组合 SELECT + JOIN + WHERE + GROUP BY 来满足。
