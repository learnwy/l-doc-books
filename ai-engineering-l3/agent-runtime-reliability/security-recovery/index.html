安全边界与恢复语义简介

Agent 运行时既执行不完全可预测的模型决策，又触达文件、网络、凭据和业务系统，因此可靠性与安全性不能拆开设计。一次“成功”的越权工具调用仍然是系统失败。

工具沙箱与安全边界从能力授予而非工具名称建模权限，讨论文件系统、网络出口、凭据、进程和租户隔离。沙箱降低宿主暴露面，但它不能替代工具级授权和资源限制。

恢复、补偿与状态对账区分瞬时失败、已知失败和结果未知，给出前向重试、补偿动作、外部查询与人工修复的选择顺序。补偿不是数据库回滚，而是新的、同样可能失败的业务动作。

运行时边界与系统集成明确运行时与规划器、模型网关、工具适配器及工作流引擎的所有权。边界清晰后，重试策略、身份信息和追踪上下文才不会在多个层次重复实现。

建议先从沙箱建立最坏情况思维，再学习恢复语义，最后用系统集成篇检查架构。这样可以避免先选框架，再让框架默认值替你决定安全和一致性。

实践时选一个高风险动作，列出它所需的最小能力、执行前验证、执行后回执、补偿动作和不可补偿的转折点。若无法描述转折点，就不应允许 agent 无监督执行。

完成本章后，你应能为工具执行绘制信任边界，处理一次“请求超时但外部状态未知”的事故，并为四类相邻系统写出不重叠的接口责任。
