Part II · Agent Construction工具调用与函数调用编排并行工具调用

并行工具调用

用户问「上海和东京现在分别几点、各自天气如何」，最笨的做法是查上海时间、等结果、查东京时间、等结果、查上海天气……四次串行往返，延迟相加。但这四件事彼此毫无依赖，完全可以在一轮里同时发出、并发执行。这就是并行工具调用要榨取的延迟红利，也是工具编排里最容易拿到的一笔收益。

核心概念：何时能并行，何时不能

并行的唯一前提是调用之间没有数据依赖——后一个的参数不依赖前一个的结果。下表区分两种典型形态。

形态 例子 能否并行 归属
扇出（无依赖） 同时查三城天气 能，本篇主题 并行
流水线（有依赖） 先搜 ID 再用 ID 查详情 不能，必须串行 多步工具链
混合 先搜 ID（串），再并发查多个 ID 详情（并） 分段：段内并、段间串 两者结合

模型会自己判断该不该并行：当它在函数调用循环的某一帧里发现几件事互不依赖，就会在同一个 assistant 帧里输出多个 tool_calls（Anthropic 是多个 tool_use 块），每个带各自的 call_id。这正是当初强调 call_id 重要性的兑现场景——三个结果并发返回时，全靠 ID 各自归位。

flowchart TD
  A[模型: 一帧内输出 3 个 tool_calls<br/>各带独立 call_id] --> B[宿主: 并发派发]
  B --> C1[查上海天气]
  B --> C2[查东京天气]
  B --> C3[查纽约天气]
  C1 --> D[按 call_id 收集全部结果]
  C2 --> D
  C3 --> D
  D --> E[同一轮回灌全部 tool_result]
  E --> F[模型据三者综合作答]

延迟模型：从相加到取最大

并行的价值可以量化。设单次工具调用耗时为 tit_iti​，串行总延迟是 ∑i=1nti\sum_{i=1}^{n} t_i∑i=1n​ti​，并行总延迟则是 max⁡iti\max_i t_imaxi​ti​（加上一点固定调度开销）。当 nnn 个调用耗时相近、都约为 ttt 时，串行是 n⋅tn \cdot tn⋅t，并行是 ttt，理论加速比接近 nnn 倍。

实践中加速比拿不满，受限于三点：模型不一定识别出可并行（描述含糊时它会保守串行）、宿主的并发度上限、以及共享下游（三个调用打同一个限流的 API）。但即便只是把三个独立的网络往返从相加压成取最大，对交互式应用的体感提升也极明显。

宿主侧：并发执行与结果归集

模型只负责「在一帧里提议多个调用」，真正的并发执行是宿主的活。两条工程要点：

其一，用语言原生的并发原语并发派发——Python 的 asyncio.gather、JS 的 Promise.all、Go 的 goroutine——别傻乎乎地 for 循环逐个 await，那等于把模型的并行意图又拍回串行。

其二，全部结果到齐后在同一轮一次性回灌。协议要求：assistant 帧里有几个 tool_calls，紧接着就必须有对应数量、ID 一一匹配的 tool 结果帧，缺一个模型就会报错。所以即使某个调用失败，也要回灌它的错误结果（按工具错误处理的写法），而不能直接丢弃——丢弃会破坏 ID 配对，导致整轮失败。

什么时候要主动关掉并行

并行不总是好事，有三种情况要主动关闭（OpenAI 设 parallel_tool_calls:false，Anthropic 设 disable_parallel_tool_use:true，此时模型每轮至多一个工具）：

  • 有副作用且需顺序保证：先扣库存再创建订单，并发执行可能产生竞态，必须串行。
  • 下游强限流：并发只会更快撞限流，串行反而更稳。
  • 要强约束模型只走单工具：某些评测或审计场景需要每步可追溯，单工具更清晰。

需要提醒一个 2025–2026 年的兼容性细节：据 OpenAI 文档，非微调模型的 strict 模式已与并行调用兼容，但微调模型在一轮调多个函数时 strict 可能被降级——若你既用微调模型又强依赖 schema 可靠性，宁可关掉并行换取 strict。这条取舍把本篇与工具模式定义的 strict 讨论接上了。

小结

  • 并行的唯一前提是调用间无数据依赖；有依赖的必须串行，属于多步工具链。
  • 模型在一帧内输出多个带独立 call_id 的调用，结果靠 ID 各自归位。
  • 延迟从串行的 ∑ti\sum t_i∑ti​ 降到并行的 max⁡ti\max t_imaxti​，理论加速比接近调用数，实际受模型识别、并发上限、共享下游限制。
  • 宿主用原生并发原语派发，全部结果（含失败结果）必须在同一轮一一对应回灌，丢弃任一结果会破坏 ID 配对致整轮失败。
  • 有副作用需顺序、下游强限流、需单工具可追溯时主动关闭并行；微调模型并行与 strict 可能冲突，需取舍。
