审计证据与数据治理

模型网关位于所有请求的汇聚点，很容易滑向“把 Prompt 和响应全存下来以后再分析”。这种做法既扩大隐私与商业秘密风险，也让真正需要的决策证据淹没在内容湖中。审计的目标是证明谁依据哪个版本的策略做了什么，而不是默认复制一切。

核心概念

证据链围绕逻辑请求、策略决策和供应商尝试建立。内容与元数据分级处理：默认元数据审计可以解释路由、授权、用量和失败；只有在明示目的、权限、保留期和脱敏条件下，才采样必要内容用于安全调查或评测。

flowchart LR
    Request[逻辑请求] --> Decision[策略与路由决策]
    Decision --> Attempt[供应商尝试]
    Attempt --> Usage[用量与成本]
    Attempt --> Outcome[完成或错误]
    Request --> Classify[数据分类]
    Classify --> Redact[脱敏与最小化]
    Redact --> Audit[审计事件]
    Audit --> Retention[分级保留与删除]
证据层 默认记录 默认不记录 主要用途
请求 标识、租户、意图、尺寸、分类 原始 Prompt 归因与容量分析
决策 策略版本、候选、拒绝原因 敏感策略数据全文 解释与合规证明
尝试 部署、时序、状态、供应商请求标识 认证头 故障调查
用量 Token 分项、价格版本、估算标志 无关业务内容 对账与预算
内容样本 受控脱敏片段或哈希 全量默认留存 获批评测与事件调查

审计事件模型

事件采用追加写入并带稳定 Schema 版本。公共字段包括 event_id、occurred_at、request_id、decision_id、attempt_id、可信 tenant_id、工作负载主体、事件类型、策略版本和数据分类。金额使用整数最小货币单位并带币种，时间使用统一 UTC 时间戳。

决策事件保存合格候选、被排除候选的原因码、最终选择和健康快照版本。它不必复制整个策略包；保存内容寻址哈希与不可变版本即可。供应商尝试事件保存端点类别、区域、实际模型版本、开始和结束时间、终止原因，以及受限的供应商请求标识。

export type AuditEvent = {
  schemaVersion: string;
  eventId: string;
  eventType: string;
  occurredAt: string;
  requestId: string;
  decisionId?: string;
  attemptId?: string;
  tenantId: string;
  actorId: string;
  policyVersion: string;
  dataClass: 'public' | 'internal' | 'confidential' | 'restricted';
  payload: Record<string, unknown>;
};

事件生产要与请求结果解耦，但不能无限丢失。普通性能指标可以在拥塞时采样，授权拒绝、凭证使用和高风险策略旁路则属于关键事件：本地有界持久缓冲满时，受监管请求应失败关闭。不同数据等级需要明确的失败策略。

内容最小化与脱敏

不记录内容并不等于不可调试。可以记录输入块数量、媒体类型、字节数、Token 数、Schema 哈希、工具名称、参数 Schema 验证结果和输出分类。需要比较重复内容时，使用租户作用域带密钥哈希，避免全局哈希成为跨租户关联标识。

内容采样必须在进入日志管道前脱敏，而不是先写入再异步清理。采样策略包含目的、比例、适用租户、字段、保留期和审批引用；用户或租户选择退出时覆盖全局采样。工具参数和结果通常比对话文本更敏感，因为它们可能含数据库主键、访问令牌或内部文档。

OpenTelemetry 的生成式 AI 语义约定对工具参数、结果和定义给出敏感信息警告，官方属性注册表支持“默认只记元数据、内容显式开启”的设计。遥测标准定义字段名，不替组织决定哪些内容可以被收集。

保留、删除与供应商数据边界

保留期按目的和数据分类定义，而非整个审计库一个数字。高粒度调试内容可能只保留数天，聚合成本保留更久，安全与合规事件依据法律和合同处理。删除工作流要覆盖主存储、搜索索引、备份生命周期和下游导出，并保存不含被删内容的删除证明。

供应商侧数据处理必须进入部署目录：是否默认存储响应、零数据保留条件、区域、滥用监控例外、服务器工具额外数据流和后台任务保留。策略根据请求分类筛选部署，不能假设所有端点条款相同。OpenAI 的平台数据控制文档就区分不同端点和功能的应用状态保留条件，说明部署能力目录必须包含数据治理属性。

数据类别 示例 推荐处理
操作元数据 延迟、状态、Token 默认收集，限制租户可见性
决策证据 策略版本、原因码 追加写，较长保留
内容指纹 租户作用域哈希 轮换密钥，限制关联范围
脱敏样本 获批评测片段 短期、访问审批
原始受限内容 医疗、密钥、源码 默认不采集，特殊事件单独隔离

完整性、访问与可追责性

追加写并不自动防篡改。事件批次可以建立哈希链或签名清单，存入具有保留锁的对象存储；密钥轮换和验证工具需要独立权限。时钟偏差会破坏事件顺序，因此使用单调序号和接收时间辅助分析，不能只依赖供应商时间戳。

审计查询本身也要审计。平台运维可看性能元数据，财务可看聚合成本，安全调查员在工单授权后看受控样本，产品团队只能看本租户汇总。导出带水印、目的与到期时间，防止“为了排障”成为永久复制通道。

一次可追责调查应从 request_id 找到策略与路由决策，再展开所有尝试、取消、用量和最终输出状态；从某个策略版本也能反向找出受影响请求。双向索引只包含标识与元数据，敏感内容仍留在隔离存储。

评测、事件响应与风险框架

审计证据可以生成评测样本，但两者目的不同。先按事件或质量信号筛选请求，再经过权限与脱敏进入独立评测数据集；评测标签与结果不能回写原始审计事件。这样保留不可变事实，同时允许评测集修订。

NIST 的生成式 AI 风险管理框架将治理、内容来源、部署前测试和事件披露列为重要考虑，并强调风险贯穿设计、部署、运行与退役；可参考NIST AI 600-1。网关证据链正好把这些生命周期动作连接起来，但它不能替代组织对风险容忍度和法律义务的判断。

事件响应预先定义封存范围：相关策略快照、适配器版本、部署能力、尝试元数据和获批内容样本。供应商请求标识方便与外部支持协查，内部 attempt_id 保持跨供应商统一。调查结束后恢复正常保留策略，避免临时扩大采集成为永久默认。

审计事件关联身份与策略决策以及配额结算，随后为运营章的可观测性与成本归因提供可信事实。若遥测管道可以修改租户或价格版本，成本和合规报告都不再可靠，因此这些字段必须在数据面从可信上下文生成。

小结

  • 审计证明主体、策略、决策、尝试和结果，不等于默认保存全部内容。
  • 元数据默认记录，内容采样需要目的、授权、脱敏、比例和保留期。
  • 供应商数据条款属于部署能力，必须参与路由硬约束。
  • 关键审计事件使用追加写、完整性验证和受控失败策略。
  • 审计查询与导出本身也要留痕，并按角色和租户隔离。
  • 评测从审计证据受控派生，但不能改写原始事实。
