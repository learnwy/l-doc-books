网关迁移、升级与供应商故障演练

把现有系统迁入模型网关，最大的风险不是代码编译失败，而是隐藏语义被重写：默认超时、消息排序、工具结果、内容过滤、Token 统计和重试行为都可能改变。安全迁移先建立事实与对照，再移动流量；供应商故障演练则证明这些备选路径在真正事故前已经工作过。

核心概念

迁移采用绞杀式路径：盘点直接调用，包住现有行为，建立规范契约，影子比较，按切片切流，最后撤销旧凭证。升级同样走新旧适配器并存。故障演练在每个阶段注入可控制的失败，验证回退不会越过质量、预算和数据边界。

flowchart LR
    Inventory[调用与语义盘点] --> Wrap[旧路径适配封装]
    Wrap --> Observe[统一标识与证据]
    Observe --> Shadow[候选网关影子]
    Shadow --> Canary[按意图与租户切流]
    Canary --> Ramp[渐进放量]
    Ramp --> Revoke[撤销旧凭证与入口]
    Drill[故障注入] --> Shadow
    Drill --> Canary
    Drill --> Ramp

现状盘点与契约抽取

盘点不仅搜索 SDK 包。还要查找 HTTP 直连、云平台代理、后台任务、边缘函数、测试工具和临时脚本中的供应商端点；从账单与出口日志反向核对，发现代码搜索遗漏的调用。每个调用记录所有者、租户、意图、模型、区域、数据分类、工具、副作用、重试、超时、预期用量和服务目标。

现有默认值就是迁移契约的一部分，即使它们从未被写下来。用脱敏录制或合成等价样本捕获请求、流事件、终止原因与错误；把依赖供应商专有字段的调用明确标为扩展或独立通道。不要为了追求统一而在第一步改掉产品行为。

先让旧路径通过网关的“直通适配器”，只增加身份、标识、审计与成本事实，不改变路由。这样团队获得观测基线，并能将凭证逐步收回平台。随后才把稳定模型名替换为意图与能力需求。

影子、双轨与切流

影子比较之前要确定输出如何评估。确定性抽取可以使用 Schema 与黄金标签，开放生成使用按意图校准的判定器和人工抽样，工具任务比较调用名称、参数和最终状态。所有失败与超时保留在配对数据中。

双轨不是把两个结果都发给用户。稳定路径继续承载用户，候选路径在独立低优先级容量池执行；有副作用的服务器工具被禁用或替换为沙箱。影子成本有单独预算，避免迁移项目意外挤占生产额度。

切流按“低风险意图内部租户—代表性租户—高风险意图”的顺序，不按随机全局比例一刀切。每一步冻结其他重大配置变更，观察完整业务周期，并保留一键回滚指针。数据库或事件 Schema 必须先向后兼容，确保回滚后的旧数据面仍能读取。

适配器与供应商升级

供应商 SDK 或 API 升级先在新适配器版本中实现，旧版本继续可用。黄金轨迹验证编码与解码，在线合成探针验证鉴权和真实端点，影子流量验证未覆盖的事件组合。只看 SDK 变更日志不足以证明语义兼容。

模型版本升级单独评估质量、延迟、成本、安全与工具行为。供应商可能在同一别名后更新模型，因此生产目录优先使用可审计版本；无法固定时，合成探针与持续评测必须检测漂移。别名解析结果写入每次尝试证据。

价格、配额和数据条款也是升级。价格表设置生效时间，旧用量仍按旧版本结算；配额变化先做容量模拟；数据处理条款改变则重新评估允许租户，不能作为普通文档更新跳过发布门。

  trafficPercent: number;

供应商故障演练矩阵

演练覆盖失败位置与持续时间，而非只有“返回 500”。连接层包括 DNS、TLS、连接重置和区域不可达；认证层包括密钥撤销、权限缩小和凭证服务失联；容量层包括 429、首 Token 变慢和配额突然下降；协议层包括事件乱序、工具参数截断、尾用量缺失和模型版本异常；业务层包括质量切片退化和安全策略变化。

单区域不可达 熔断该部署，选独立区域 熔断整个供应商 决策与熔断事件
凭证被撤销 隔离凭证引用并告警 无限重试认证失败 尝试数与撤销审计

注入位置优先在适配器测试代理或沙箱账户，避免依赖真实供应商事故。生产 Game Day 只对已授权租户与小流量执行，并设置全局停止开关。故障注入本身带审计标记，告警系统能区分演练与真实事故，但服务处理路径保持一致。

运行手册与恢复目标

运行手册从症状到边界：逻辑成功率下降先区分网关拒绝、供应商尝试失败与质量门失败；供应商故障再按部署、区域、账户和协议分类。每步写明查询、期望证据、操作权限、风险和回退，避免事故中临时发明命令。

恢复目标不能只写服务 RTO。还要定义可接受的降级等级、最大额外成本、允许积压的后台任务、数据区域和恢复后对账时间。若业务宁愿失败也不接受低质量结果，运行手册必须尊重这个选择。

演练通过标准包括：故障在目标检测时间内出现；熔断只影响预期边界；健康租户服务目标保持；额外尝试与成本在预算内；客户端看到明确降级或终止；恢复后半开流量逐步增加；审计链能重建全过程。只验证“最后成功了”远远不够。

退役、回滚与持续演练

旧路径退役先把调用流量降为零并持续观察，再撤销供应商凭证、删除网络允许规则、关闭部署和归档契约样本。只删除代码但保留长期密钥，会留下无法观测的旁路。退役清单需要所有者签字与账单归零证据。

回滚要定期演练。候选全量后仍保留上一稳定快照一个约定窗口，并验证数据向后兼容；窗口结束才清理旧适配器。紧急回滚如果依赖已经删除的凭证或不兼容数据，就只是文档里的愿望。

持续演练按风险轮换：每周合成探针，每月单部署与凭证故障，每季度跨区域或全供应商 Game Day，重大供应商与策略变更后追加针对性演练。频率应结合真实变更率，而非机械日历。

迁移的放量和停止条件来自评测门与灰度发布，全过程证据由可观测性与成本归因提供。两者若尚未完成，就先建设证据和回滚快照，不应直接切换生产主路径。

微软在 2026 年的模型端点文档明确给出旧推理 SDK 的退役时间并建议迁往 OpenAI v1 接口，说明接口迁移本身就是持续运营事项；OpenAI 的生产最佳实践建议隔离测试与生产项目并分别设置访问、速率和支出限制。这些官方建议都支持“先隔离、再比较、后切流”的路径。

小结

  • 迁移先盘点隐藏语义与旁路调用，再封装旧行为和建立证据。
  • 影子与双轨保持用户稳定路径，不执行真实副作用，并有独立成本预算。
  • 适配器、模型、价格、配额和数据条款都按版本化发布管理。
  • 故障演练覆盖连接、认证、容量、协议和质量，验证禁止行为而非只看恢复。
  • 运行手册包含降级等级、成本与数据边界，恢复目标不只是服务在线。
  • 退役必须撤销凭证和网络旁路，回滚与演练要在真正事故前反复证明。
