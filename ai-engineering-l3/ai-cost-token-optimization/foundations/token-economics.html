Token 经济学

核心概念

Token 是 LLM 推理的最小计费单位，但 2026 年的定价维度已远超简单的"输入/输出"二分法。四种 Token 类型（输入、输出、缓存、思考）各有独立定价，有效成本公式将标价、缓存命中率、输出比例统一为可计算的实际费用。核心定律：输出比输入贵 3-8 倍；缓存降 90% 输入成本；思考 Token 是隐藏账单；多轮对话成本接近二次增长。

Token 作为计费原子

Token 是 LLM 推理的最小计费单位。一个 token 大约对应 4 个英文字符或 1-2 个中文字符，但实际切分由每个模型的 tokenizer 决定。理解 token 经济学的核心不是"一个 token 多少钱"——而是不同类型的 token 定价差异巨大，且这些差异直接指导优化方向。

2026 年的 token 定价维度已经从简单的"输入/输出"二分法，扩展为四维度定价体系：

graph LR
    A[Token 类型] --> B[输入 Token<br/>Input Tokens]
    A --> C[输出 Token<br/>Output Tokens]
    A --> D[缓存 Token<br/>Cached Tokens]
    A --> E[思考 Token<br/>Thinking Tokens]

    B --> F[标价基准<br/>$0.05-$21/M]
    C --> G[3-8x 输入价<br/>$0.4-$168/M]
    D --> H[10-25% 输入价<br/>自动/手动触发]
    E --> I[按输出价计费<br/>仅 reasoning 模型]

四种 Token 的定价机制

输入 Token（Prompt Tokens）

输入 token 包含系统 Prompt、用户消息、对话历史和注入的上下文（RAG 结果、文档片段等）。它们是成本方程中量最大但单价最低的部分。

关键特性：

  • 可并行处理（GPU 利用率高），因此厂商可以以较低价格提供
  • 在多轮对话中线性累积——第 N 轮的输入包含前 N-1 轮的全部历史
  • 是缓存机制的主要优化目标

输出 Token（Completion Tokens）

输出 token 是模型生成的响应内容。它们是成本方程中单价最高的部分——通常是输入价格的 3-8 倍。

厂商/模型 输入价 输出价 输出/输入比
GPT-5.2 Pro $21.00/M $168.00/M 8.0x
GPT-5.2 $1.75/M $14.00/M 8.0x
Claude Sonnet 4.6 $3.00/M $15.00/M 5.0x
Claude Haiku 4.5 $1.00/M $5.00/M 5.0x
DeepSeek-V3 ¥1/M ¥2/M 2.0x
Qwen-Max ¥20/M ¥60/M 3.0x

输出定价高昂的物理原因：每生成一个 token 需要一次完整的自回归前向传播，无法并行。100 个输出 token 就是 100 次串行计算。这决定了控制输出长度永远比压缩输入更有成本杠杆。

缓存 Token（Cached Input Tokens）

2025-2026 年最重要的定价创新是 Prompt Caching——重复发送的输入前缀仅需支付标价的 10-25%：

厂商 缓存折扣 触发条件 TTL 额外费用
OpenAI 90%（仅付 10%） 自动，前缀 > 1024 token 约 5-10 分钟 无
Anthropic 90%（仅付 10%） 手动标记 cache_control 5min / 1h 写入费 125%
Google 75%（仅付 25%） 手动 context cache API 按小时计存储费 存储费 + 读取费

OpenAI 的方案最简单——超过 1024 token 的公共前缀自动缓存，无需任何代码改动。Anthropic 需要显式标记但提供更精细的控制。

经济学关键点：对于携带 4000+ token 系统 Prompt 的高频调用（如 Agent 系统），Prompt Cache 可以将输入成本降低 80-90%。在一个日均 10 万次调用的客服系统中，仅此一项就可节省数千美元/月。

思考 Token（Thinking Tokens）

Reasoning 模型（o3、o4-mini、Claude with extended thinking、DeepSeek-R1）引入了第四种 token 类型：模型的"内部推理"过程产生的 token，按输出价格计费但不显示在最终响应中。

Thinking Cost=thinking_tokens×output_rate\text{Thinking Cost} = \text{thinking\_tokens} \times \text{output\_rate}Thinking Cost=thinking_tokens×output_rate

这是一个容易被忽视的成本陷阱。一个 reasoning 请求可能输出 200 个最终 token，但内部产生 2000 个思考 token——实际账单是你以为的 10 倍。

有效成本公式

标价（sticker price）不等于实际成本。2026 年比较模型成本的正确方式是计算有效成本（effective cost）：

effective_cost=Tinput×Pinput×(1−rcache)×dcache⏟缓存后的输入成本+Tcached×Pinput×dcache⏟缓存命中部分+Toutput×Poutput⏟输出成本+Tthinking×Poutput⏟思考成本\text{effective\_cost} = \underbrace{T_{input} \times P_{input} \times (1 - r_{cache}) \times d_{cache}}_{\text{缓存后的输入成本}} + \underbrace{T_{cached} \times P_{input} \times d_{cache}}_{\text{缓存命中部分}} + \underbrace{T_{output} \times P_{output}}_{\text{输出成本}} + \underbrace{T_{thinking} \times P_{output}}_{\text{思考成本}}effective_cost=缓存后的输入成本Tinput​×Pinput​×(1−rcache​)×dcache​​​+缓存命中部分Tcached​×Pinput​×dcache​​​+输出成本Toutput​×Poutput​​​+思考成本Tthinking​×Poutput​​​

其中：

  • TTT 表示各类型 token 数量
  • PPP 表示标价（per token）
  • rcacher_{cache}rcache​ 表示缓存命中率
  • dcached_{cache}dcache​ 表示缓存折扣系数（OpenAI = 0.1，Anthropic = 0.1）

实际案例：标价对比 vs 有效成本对比

考虑一个代码 Agent 的实际工作负载：8K token 系统 Prompt、400 token 用户输入、600 token 输出、每小时 100 次调用。

Model A（轻量模型）：输入 0.20/M，输出0.20/M，输出0.20/M，输出0.80/M，无缓存支持

  • 每次成本 = 8400 × 0.20/M+600×0.20/M + 600 ×0.20/M+600×0.80/M = 0.00168+0.00168 +0.00168+0.00048 = $0.00216

Model B（中端模型）：输入 3.00/M，输出3.00/M，输出3.00/M，输出15.00/M，缓存命中率 85%

  • 每次成本 = 8000 × 3.00/M×0.10（缓存）+400×3.00/M × 0.10（缓存）+ 400 ×3.00/M×0.10（缓存）+400×3.00/M + 600 × $15.00/M
  • = 0.0024+0.0024 +0.0024+0.0012 + 0.009=∗∗0.009 = **0.009=∗∗0.0126**

Model B with Batch（50% 折扣）：= 0.0126×0.5=∗∗0.0126 × 0.5 = **0.0126×0.5=∗∗0.0063**

标价上 Model B 是 Model A 的 15 倍，但有效成本差距仅约 3-6 倍——而 Model B 的质量显著更高。加上 Model A 更高的重试率（指令遵循能力弱），实际差距进一步缩小。

成本累积的时间维度

多轮对话的成本不是线性增长，而是接近二次增长——因为每轮都重新发送全部历史：

对话轮数 累计输入 token（假设每轮用户 100 + 模型 200） 相对首轮成本
1 8,100 (sys + user) 1x
5 9,500 1.17x
10 11,000 1.36x
50 23,000 2.84x
100 38,000 4.69x
260 86,000 10.6x

一项实测数据显示：Claude 会话中一个三词用户输入在第 1 条消息花费 0.0018，到第260条消息时花费0.0018，到第 260 条消息时花费0.0018，到第260条消息时花费2.41——膨胀 1339 倍。这是上下文重发机制的直接后果。

五条 Token 经济学定律

  1. 输出比输入贵 3-8 倍 → 控制输出长度是最高杠杆
  2. 缓存把重复输入成本降 90% → 长系统 Prompt 的高频场景必开缓存
  3. 思考 token 是隐藏账单 → Reasoning 模型的实际成本 = 显示输出 × 5-15
  4. 上下文重发让多轮对话成本接近二次增长 → 滑动窗口/摘要压缩是刚需
  5. 标价排名 ≠ 有效成本排名 → 必须用真实流量回放测有效成本

小结

Token 经济学的五条定律构成成本优化的理论基础：输出控制 > 输入压缩（因为输出单价 3-8 倍）；Prompt Cache 是长前缀场景的首选手段（降 90%）；Reasoning 模型的思考 token 让实际账单远超预期；多轮对话的二次增长需要主动管理上下文；标价排名不等于有效成本排名——必须用真实流量回放。这五条定律直接指导下一步的成本架构设计。
