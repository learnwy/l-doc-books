量化与蒸馏的成本收益

核心概念

量化和蒸馏在模型层面降低推理成本——量化降低精度位数（FP16→INT4，吞吐提升 3-4x），蒸馏降低参数量（70B→7B，吞吐提升 10x）。INT8 量化几乎是"免费午餐"（质量损失 <1%）。针对性蒸馏（RouteNLP 验证：对路由升级失败案例定向蒸馏）比无差别蒸馏的成本收益高 2 倍以上。与路由系统形成正向闭环：蒸馏增强小模型 → 升级率降低 → 成本持续下降。

模型压缩的经济学逻辑

量化和蒸馏是模型层面的成本优化——通过降低模型的计算需求来降低单次推理成本。与路由（选便宜模型）和缓存（复用结果）不同，这两种技术直接改变模型本身的推理效率。

核心经济逻辑：

推理成本∝模型参数量×精度位数硬件吞吐量\text{推理成本} \propto \frac{\text{模型参数量} \times \text{精度位数}}{\text{硬件吞吐量}}推理成本∝硬件吞吐量模型参数量×精度位数​

量化降低精度位数（FP16→INT8→INT4），蒸馏降低参数量（70B→7B）。两者都直接减小分子，让同一硬件承载更多推理请求。

    A --> C[蒸馏<br/>7B FP16]
    A --> D[量化+蒸馏<br/>7B INT4]

    B --> E[吞吐 3-4x↑<br/>质量损失 1-3%]

量化技术与成本收益

量化级别对比

量化将模型权重从高精度浮点数（FP16/BF16）压缩到低精度整数（INT8/INT4），直接减少内存占用和计算量。

量化级别 位数 内存占用（70B 模型） 吞吐提升 质量损失
FP16（基线） 16 bit ~140 GB 1x 0%
INT8 8 bit ~70 GB 1.8-2.2x 0.5-1%
INT4（GPTQ） 4 bit ~35 GB 3-4x 1-3%
INT4（AWQ） 4 bit ~35 GB 3-4x 1-2%
GGUF Q4_K_M 4.5 bit ~40 GB 2.5-3x 1-2.5%
INT3/INT2 2-3 bit ~20-25 GB 5-6x 5-10%

2026 年的新范式：原生低精度发布。量化正从「部署时的后处理」前移到「训练/发布阶段」：DeepSeek-V3 直接以 FP8 混合精度框架训练并发布 FP8 权重（技术报告 arXiv:2412.19437，2024-12）；OpenAI gpt-oss 系列（2025-08-05 发布，Apache 2.0）原生以 MXFP4 精度发布，官方模型卡注明 120b 版本可在单张 80GB GPU 上运行；Blackwell 代际硬件进一步将 FP4 作为一等计算精度。实践含义：优先选用官方原生低精度 checkpoint——其质量损失通常小于社区后量化方案，还省去自行校准的成本。

量化的成本收益计算

以 2026 年开源中坚 dense 模型 Qwen3-32B（Apache 2.0，2025-04 发布）的租用部署为例：

配置 可部署性 月吞吐量 等效月成本 单 token 成本
BF16 需要 1×H100 80GB ~2亿 tokens $3,000 $15/M
INT8 需要 1×L40S 48GB ~2亿 tokens $1,000 $5/M
INT4 (AWQ) 需要 1×24GB 卡（4090/L4） ~2亿 tokens $400 $2/M

关键洞察（2026 版）：对中坚 dense 模型，INT4 量化意味着「一张消费级/入门卡跑生产负载」——硬件门槛从数据中心级降到工作站级。对前沿 MoE（DeepSeek-V3 级，671B 总参/~37B 激活），量化决定的不是「省几张卡」而是「用什么代际的硬件」：BF16/FP16 权重需多机互联，原生 FP8 或动态低比特量化（权重 ~130-340 GB）可压进单个 8 卡节点。

量化质量损失的实际影响

量化的质量损失不是均匀分布的——某些任务几乎不受影响，某些任务显著退化：

任务类型 INT8 质量保持 INT4 质量保持 敏感性
文本分类 99.5% 98% 极低
信息抽取 99% 97% 低
摘要生成 98.5% 96% 中低
代码生成 98% 94% 中
数学推理 97% 91% 高
多步逻辑推理 96% 88% 很高

实践建议：INT8 量化几乎是"免费午餐"（质量损失 <1%），应该作为自建部署的默认配置。INT4 量化需要在目标任务上做评估验证。

知识蒸馏与成本优化

蒸馏的经济学

蒸馏将大模型的"知识"压缩到小模型中——用大模型的输出作为训练数据，训练一个参数量小得多的学生模型。

蒸馏 ROI=节省的推理成本（长期）蒸馏训练成本（一次性）+质量损失的业务代价\text{蒸馏 ROI} = \frac{\text{节省的推理成本（长期）}}{\text{蒸馏训练成本（一次性）} + \text{质量损失的业务代价}}蒸馏 ROI=蒸馏训练成本（一次性）+质量损失的业务代价节省的推理成本（长期）​

针对性蒸馏 vs 通用蒸馏

RouteNLP（2026）的研究揭示了一个关键发现：针对路由升级失败案例的定向蒸馏，比无差别蒸馏的成本收益高 2 倍以上（21.7% vs 9.4% 成本改进）。

工作流程：

  1. 部署路由系统，记录从低级模型升级到高级模型的所有 case
  2. 聚类分析升级原因——哪些类型的请求小模型处理不了
  3. 用大模型为这些特定类型生成高质量训练数据
  4. 针对性地微调/蒸馏小模型，增强其在这些类型上的能力
  5. 重新训练路由器，将更多请求留在小模型层
# 针对性蒸馏的数据收集
escalation_logs = get_escalation_logs(last_30_days)
clusters = cluster_escalations(escalation_logs)  # 聚类升级原因

for cluster in clusters:
    # 用旗舰模型为每个聚类生成训练数据
    training_data = generate_training_data(
        model="claude-opus-4-6",
        examples=cluster.examples,
        n_samples=1000
    )

    # 蒸馏到小模型
    fine_tune(
        base_model="qwen3-8b",
        training_data=training_data,
        task_type=cluster.task_type
    )

量化+蒸馏的组合策略

最具成本效益的自建推理方案通常是组合使用：

策略层 技术 效果
模型选择 用蒸馏后的小模型替代大模型 参数量降 10x
精度压缩 INT4 量化 内存降 4x
推理优化 vLLM / TensorRT-LLM 吞吐提升 2-3x
请求优化 Continuous batching 吞吐提升 1.5-2x
综合 成本降 30-50x

框架 特点 适用场景

与路由系统的协同

量化/蒸馏不应该独立运行——它们与模型路由系统形成正向循环：

  1. 路由系统发现：哪些请求小模型处理不了（升级率数据）
  2. 针对性蒸馏：增强小模型在这些请求上的能力
  3. 路由器重训练：更多请求可以留在小模型层
  4. 成本持续下降：升级率降低 → 整体成本降低
  5. 循环重复：新的升级模式出现 → 再次蒸馏

RouteNLP 在 8 周部署中验证了这个闭环：每 2 周一轮"分析升级 → 蒸馏 → 重路由"循环，成本持续下降。

实施决策矩阵

场景 推荐方案 理由
月支出 < $5K 不建议自建量化/蒸馏 ROI 不足以覆盖人力
月支出 5K−5K-5K−50K INT8 量化 + 开源模型 低投入、快见效
月支出 > $50K 全栈（量化+蒸馏+路由闭环） 投入合理、回报巨大
高度定制需求 蒸馏定制模型 开源基座 + 业务数据
边缘/离线场景 INT4 量化 + 小模型 硬件约束下的唯一选择

小结

量化和蒸馏是自建推理场景的核心成本杠杆。INT8 量化作为默认配置（质量损失 <1%、吞吐 2x），INT4 量化需要在目标任务上验证；模型有官方原生低精度版本（如 FP8、MXFP4）时应优先选用原生 checkpoint，而非社区后量化。蒸馏的最大价值在于与路由系统形成闭环——分析升级失败 → 针对性蒸馏 → 路由器重训 → 成本持续下降。月支出 < 5K时不建议投入；>5K 时不建议投入；>5K时不建议投入；>50K 且有 ML 团队时应建立完整的量化+蒸馏+路由闭环。
