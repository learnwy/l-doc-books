预算分配与熔断机制

核心概念

预算治理把成本上限作为系统设计约束前置——像内存限制和延迟 SLA 一样对待。多层级配额（组织/团队/项目/用户/会话）配合渐进式降级策略（旗舰→中端→轻量→缓存→静态），确保预算耗尽时服务可用性优雅退化而非硬切断。会话级熔断器是 Agent 系统的必备防线——防止单个失控任务吞噬整体预算。

预算是设计约束，不是事后审计

预算管理的传统做法是月底看账单、季度做复盘。这对 LLM 支出不够——因为 LLM 成本可以在几小时内失控（Agent 循环、流量突增、配置错误）。正确的做法是把预算作为系统设计约束前置，像对待内存限制和延迟 SLA 一样对待成本上限。

2025 年底 LangChain Agent 无限循环 11 天产生 $47,000 账单的事件，2026 年某团队月支出从 ¥5,600 飙升至 ¥84,000 的案例——都说明没有预算熔断的 LLM 系统是一颗定时炸弹。

多层级配额体系

层级设计

层级 控制对象 典型预算 周期 超限处理
组织级 整个公司 $50,000/月 月 硬断 + CEO 告警
团队级 业务团队 $10,000/月 月 降级 + TL 告警
项目级 单个产品/功能 $3,000/月 月/周 降级 + PM 告警
用户级 单个终端用户 $0.50/天 日 限流 + 用户提示
会话级 单次 Agent 任务 $5.00/session 任务 终止任务

配额分配策略

固定配额：每个层级分配固定额度。简单但僵化——月中用完就停。

弹性配额：允许短期超支（借用下月额度），但触发告警和审批。

按比例分配：按历史用量 + 增长系数自动调整。适合快速增长期。

interface BudgetConfig {
  entity_id: string; // 团队/项目/用户 ID
  entity_type: 'org' | 'team' | 'project' | 'user' | 'session';
  budget_usd: number; // 预算额度
  period: 'monthly' | 'weekly' | 'daily' | 'per_session';
  soft_limit_pct: number; // 软限制百分比（如 80%）
  hard_limit_pct: number; // 硬限制百分比（如 100%）
  overflow_allowed: boolean; // 是否允许弹性超支
  overflow_max_pct: number; // 最大超支比例（如 120%）
  on_soft_limit: 'alert' | 'degrade' | 'throttle';
  on_hard_limit: 'alert' | 'degrade' | 'block';
}

熔断策略设计

渐进式降级（优于硬切）

预算接近上限时，不是直接拒绝请求，而是渐进降级——保证服务可用性的同时控制成本：

预算消耗 状态 策略
0-70% 正常 全模型可用，无限制
70-85% 预警 告警 + 推荐使用更便宜模型
85-95% 降级 强制路由到轻量模型
95-100% 限流 限制请求频率 + 轻量模型
>100% 熔断 仅允许关键路径，其余队列化 
class BudgetCircuitBreaker:
    def __init__(self, config: BudgetConfig):
        self.config = config
        self.spent = 0.0

    def get_allowed_model(self, requested_model: str) -> str:
        usage_pct = self.spent / self.config.budget_usd

        if usage_pct < 0.70:
            return requested_model  # 正常使用

        if usage_pct < 0.85:
            # 预警：允许使用但记录
            self.alert("approaching_limit", usage_pct)
            return requested_model

        if usage_pct < 0.95:
            # 降级：强制使用便宜模型
            return self.downgrade_model(requested_model)

        if usage_pct < 1.0:
            # 限流：便宜模型 + 速率限制
            self.throttle()
            return self.cheapest_model()

        # 熔断：仅关键路径通过
        if not self.is_critical_path():
            raise BudgetExhaustedError()
        return self.cheapest_model()

    def downgrade_model(self, model: str) -> str:
        DOWNGRADE_MAP = {
            "claude-opus-4-6": "claude-sonnet-4-6",
            "claude-sonnet-4-6": "claude-haiku-4-5",
            "gpt-5.2": "gpt-5-mini",
            "gpt-5-mini": "gpt-5-nano",
        }
        return DOWNGRADE_MAP.get(model, model)

会话级熔断（Agent 防护）

Agent 系统需要额外的会话级熔断，防止单个任务失控：

MAX_STEPS_PER_SESSION = 30
MAX_COST_PER_SESSION = 5.0      # $5
MAX_TOKENS_PER_SESSION = 500000  # 50万 token

class AgentBudgetGuard:
    def check_session_budget(self, session: AgentSession) -> Action:
        if session.total_cost > MAX_COST_PER_SESSION:
            return Action.TERMINATE

        if session.step_count > MAX_STEPS_PER_SESSION:
            return Action.TERMINATE

        if session.total_tokens > MAX_TOKENS_PER_SESSION:
            return Action.FORCE_SUMMARIZE  # 强制压缩上下文

        if session.step_count > MAX_STEPS_PER_SESSION * 0.8:
            return Action.WARN_AND_SIMPLIFY  # 提示简化

        return Action.CONTINUE

速率限制与配额 API

Token 速率限制

除了总预算，还需要速率限制防止突发消耗：

维度 限制方式 目的
每分钟 token 数 滑动窗口 防止突发流量
每小时请求数 令牌桶 平滑调用模式
每日总成本 累积计数 日预算控制
并发请求数 信号量 防止资源耗尽

配额 API 设计

向业务系统暴露配额查询和消费接口：

interface QuotaAPI {
  // 查询剩余配额
  getRemaining(entityId: string): Promise<{
    budget_usd: number;
    spent_usd: number;
    remaining_usd: number;
    remaining_pct: number;
    resets_at: Date;
  }>;

  // 预扣配额（调用前）
  reserve(
    entityId: string,
    estimated_cost: number,
  ): Promise<{
    approved: boolean;
    reservation_id: string;
    degraded_model?: string; // 如果降级
  }>;

  // 确认消费（调用后）
  confirm(reservationId: string, actual_cost: number): Promise<void>;

  // 释放未用配额（调用失败时）
  release(reservationId: string): Promise<void>;
}

预算分配的组织实践

按价值分配

不是平均分配预算，而是按业务价值排优先级：

功能 业务价值 预算占比 降级优先级
核心付费功能 直接营收 40% 最后降级
用户留存功能 间接营收 25% 中等
内部工具 效率提升 20% 优先降级
实验功能 未验证 10% 首先降级
安全/合规 风险管控 5% 不降级

预算审批流程

  • < $1,000/月增量：团队 lead 审批
  • 1,000−1,000-1,000−5,000/月增量：部门负责人审批 + ROI 估算
  • > $5,000/月增量：VP 审批 + 详细 TCO 分析

月度成本复盘

每月固定时间进行成本复盘：

  1. 总成本 vs 预算：是否超支
  2. 各团队/项目消耗排名：谁花最多
  3. 单位成本趋势：效率是否在改善
  4. 异常事件回顾：本月发生了什么突增
  5. 下月预算调整建议

与 FinOps 实践的对齐

LLM 成本管理本质上是 FinOps 的一个子领域。核心原则一致：

FinOps 原则 LLM 成本应用
每个人都对成本负责 开发者可以看到自己代码的 LLM 成本
集中管理分散消费 统一计量 + 分布式消费 + 集中可视
及时决策 实时仪表板而非月底账单
按业务价值优化 优先优化低 ROI 的 LLM 调用
持续改进 月度复盘 + 季度策略调整

小结

预算治理的三层防线：配额分配决定"谁能花多少"（按业务价值而非平均分配）；实时追踪回答"已经花了多少"（速率限制防突发）；熔断策略决定"超限怎么办"（渐进降级优于硬切断）。会话级熔断是 Agent 系统的必备安全网。月度复盘将预算治理从被动审计转为主动优化——对齐 FinOps 的"持续改进"原则。
