Prompt 压缩与 Token 工程

核心概念

Prompt 压缩通过减少每次 API 调用携带的无效 token 来降低成本——不改模型、不改架构，只让输入更精炼、输出更简洁。三个维度：输入压缩（系统 Prompt 瘦身、Few-shot 精简）、输出控制（max_tokens、结构化格式）、上下文管理（滑动窗口、摘要替换、RAG 精选）。风险最低、见效最快，单独可节省 30-50%。

为什么 Prompt 压缩是最安全的第一步

在所有成本优化策略中，Prompt 压缩的风险最低、实施门槛最低、效果最可预测。它不改变模型选择（不影响质量上限），不改变系统架构（不增加复杂度），只是让每次调用携带更少的无效 token。

实测数据表明，多数生产系统的 Prompt 存在 30-50% 的冗余——冗余的指令、重复的示例、过度详细的格式说明、以及历史累积的"保险性"描述。这些冗余直接转化为每次调用的额外费用。

系统 Prompt 瘦身

审计现有系统 Prompt

生产系统的 system prompt 往往经历了多轮迭代累积，每次加一条规则但从不删旧规则。审计步骤：

  1. 统计 token 数：用 tiktoken 计算当前 system prompt 的精确 token 数
  2. 分类标注：将每段内容标注为 Role / Constraint / Format / Example / Safety
  3. 测试删除：逐段移除，在评估集上测试输出质量是否下降
  4. 合并同类：将散落在多处的同类约束合并为一条

压缩技术

技术 压缩率 质量风险 适用场景
删除显而易见的指令 10-20% 极低 "请用中文回答"（模型已默认）
合并重复约束 15-30% 低 多处强调同一规则
缩写格式规范 20-40% 中低 详细 JSON schema → 简明示例
减少 Few-shot 数量 30-60% 中 5 个示例 → 2 个核心示例
用结构化标签替代散文 20-35% 低 XML tags 替代自然语言描述

实例对比：

压缩前（847 tokens）：

你是一个专业的客户支持助手。你的任务是帮助用户解决产品相关的问题。
请注意以下重要规则：
1. 永远保持礼貌和专业的态度
2. 如果你不确定答案，请告诉用户你需要查询更多信息
3. 不要提供医疗、法律或财务方面的建议
4. 如果用户表示不满，请表达理解并提供升级到人工客服的选项
5. 回答应该简洁明了，不要过于冗长
6. 使用用户的语言来回答问题
...（还有 20 条类似规则）

压缩后（312 tokens）：

<role>产品支持助手</role>
<rules>
- 不确定时说明需查询，不编造
- 禁止医疗/法律/财务建议
- 不满用户→表达理解+提供人工升级
- 简洁回答，跟随用户语言
</rules>

压缩率 63%，经评估集验证回答质量无显著下降。

Few-shot 示例优化

Few-shot 示例是 system prompt 中 token 消耗的大户。优化原则：

  • 最小 k 值：从 1 个示例开始测试，仅在质量不足时增加。研究表明多数分类任务 2-3 个示例就达到收益饱和
  • 多样性优先于数量：3 个覆盖不同边界 case 的示例 > 5 个相似的示例
  • 动态检索：不在 system prompt 固定示例，而是根据当前输入动态检索最相关的 1-2 个

输出长度控制

输出 token 单价是输入的 3-8 倍，控制输出长度的 ROI 最高。

max_tokens 参数

最直接的控制手段。但要注意：设置过低会导致输出被截断（不完整），设置过高则失去约束意义。

response = client.chat.completions.create(
    model="gpt-5-mini",
    messages=messages,
    max_tokens=500,           # 硬上限
    temperature=0.3,          # 低温度减少冗余
)

按场景设置合理的 max_tokens：

场景 推荐 max_tokens 原因
分类/抽取 50-100 输出是标签或短文本
摘要 200-500 控制摘要长度
代码生成 500-2000 需要完整函数体
长文写作 2000-4000 允许展开但仍有上限

结构化输出约束

让模型输出 JSON/XML 而非自然语言散文，天然地限制了输出长度并消除了"客套话"开销：

response = client.chat.completions.create(
    model="gpt-5-mini",
    messages=[{
        "role": "user",
        "content": "分析这段文本的情感"
    }],
    response_format={"type": "json_schema", "json_schema": {
        "name": "sentiment",
        "schema": {
            "type": "object",
            "properties": {
                "sentiment": {"enum": ["positive", "negative", "neutral"]},
                "confidence": {"type": "number"},
                "key_phrases": {"type": "array", "items": {"type": "string"}, "maxItems": 3}
            }
        }
    }}
)

结构化输出 vs 自然语言输出的 token 对比：

  • 自然语言："这段文本的整体情感倾向是积极的，置信度较高约为 0.85。主要的积极关键词包括..." → 约 80 tokens
  • JSON：{"sentiment":"positive","confidence":0.85,"key_phrases":["excellent","recommended"]} → 约 25 tokens

节省 70% 的输出 token，且更容易程序化处理。

指令层面的简洁约束

在 system prompt 中显式要求简洁：

回答格式要求：
- 直接给结论，不要铺垫
- 列表优于段落
- 不超过 3 句话除非用户要求详细展开

这种指令对 Claude 和 GPT 系列都有效，可减少 30-50% 的输出 token。

对话历史管理

滑动窗口策略

保留最近 N 轮对话，丢弃更早的历史。适用于上下文依赖性弱的场景（如客服问答）：

MAX_HISTORY_TURNS = 10

def trim_history(messages: list, max_turns: int = MAX_HISTORY_TURNS) -> list:
    system = [m for m in messages if m["role"] == "system"]
    history = [m for m in messages if m["role"] != "system"]
    return system + history[-(max_turns * 2):]  # user+assistant 成对

摘要压缩策略

周期性将旧历史压缩为摘要，保留关键信息但大幅减少 token 数：

SUMMARY_THRESHOLD = 20  # 超过 20 轮时触发压缩

def compress_history(messages: list) -> list:
    if len(messages) <= SUMMARY_THRESHOLD * 2:
        return messages

    old_messages = messages[1:-10]  # 保留 system + 最近 5 轮
    summary = summarize(old_messages)  # 用轻量模型生成摘要

    return [
        messages[0],  # system prompt
        {"role": "system", "content": f"对话摘要：{summary}"},
        *messages[-10:]  # 最近 5 轮
    ]

RAG 上下文精选

RAG 注入的 chunks 并非越多越好。研究表明 top-3 精选优于 top-10 全量注入：

  • 减少 chunk 数量：从 top-5 降到 top-2-3，Token 减少 40-60%
  • 缩短 chunk 长度：从 1000 token chunks 改为 300-500 token chunks
  • 提高相关性阈值：只注入相似度 > 0.85 的 chunks，丢弃勉强相关的

量化收益估算

一个典型的 AI 客服系统（月 10 万次调用、平均 6000 input tokens + 400 output tokens、使用 Claude Sonnet）：

优化项 Token 节省 月度成本节省
System prompt 压缩 50% -2000 input/次 $600
对话历史滑动窗口 -1500 input/次 $450
输出结构化约束 -150 output/次 $225
RAG chunks top-5→top-2 -1000 input/次 $300
合计 $1,575/月（~33%）

小结

Prompt 压缩是成本优化的最安全起步：系统 Prompt 瘦身（去冗余指令、压缩格式规范、精简 Few-shot）降低固定输入开销；输出结构化约束和 max_tokens 控制降低昂贵的输出 token；对话历史的滑动窗口与摘要压缩遏制多轮对话的二次增长。这些技术互不冲突，可以与后续的模型路由和缓存策略叠加使用。
