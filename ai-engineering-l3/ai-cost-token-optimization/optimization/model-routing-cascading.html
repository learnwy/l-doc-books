模型路由与级联

核心概念

模型路由根据请求复杂度动态选择最具成本效益的模型，是成本优化的单一最大杠杆（40-70% 节省）。三种模式：静态规则路由（按任务类型确定性分派）、Cascade 级联（从最便宜开始，不达标才升级）、分类器路由（训练轻量模型预判所需级别）。Anthropic 的 Advisor 策略代表了 2026 年的新范式——小模型驱动执行、大模型按需咨询。

模型路由是单一最大杠杆

模型路由——根据请求复杂度动态选择最具成本效益的模型——是 2025-2026 年成本优化实践中公认的单一最大杠杆。原理朴素：70% 以上的生产请求在轻量模型上的表现与旗舰模型无异，但按旗舰价格计费。系统性路由可实现 40-70% 的成本削减。

RouteNLP（2026，港大）在企业金融客服场景部署 8 周的实测结果：推理成本降低 58%，响应接受率维持 91%，p99 延迟从 1847ms 降至 387ms。AWS 的 IPR（Intelligent Prompt Routing）在 Claude 系列内部路由实现 43.9% 成本降低且保持质量等价。

三种路由模式

模式一：静态规则路由

基于任务类型的确定性路由——简单、可审计、零延迟开销。适合任务边界清晰的系统。

任务类型 路由目标 理由
意图分类 Nano/Haiku 固定标签集，小模型准确率 >95%
实体抽取 Nano/Haiku 结构化输出，pattern matching 类
情感分析 Nano/Haiku 二分类/三分类任务
内容生成 Mini/Sonnet 需要流畅性和创造力
代码审查 Sonnet 需要理解复杂逻辑
架构设计 Opus 需要多步推理和全局视野
法律/医疗分析 Opus 准确率要求极高

实现极其简单——本质是一个 switch/map：

const MODEL_MAP = {
  classification: 'gpt-5-nano',
  extraction: 'gpt-5-nano',
  sentiment: 'gpt-5-nano',
  summarization: 'gpt-5-mini',
  generation: 'gpt-5-mini',
  code_review: 'claude-sonnet-4-6',
  architecture: 'claude-opus-4-6',
} as const;

function routeByTaskType(taskType: keyof typeof MODEL_MAP): string {
  return MODEL_MAP[taskType];
}

优势：零额外成本、完全确定性、易调试。劣势：粒度粗，同一任务类型内的复杂度差异被忽略。

模式二：Cascade 级联

从最便宜的模型开始尝试，仅在输出不达标时升级到更贵的模型。兼顾成本最小化和质量保底。

级联的核心设计决策是升级判据——什么条件触发升级：

  • 置信度阈值：模型输出附带置信度分数，低于阈值则升级
  • 格式验证：输出无法通过 schema 验证则升级
  • 自我验证：让模型自评回答质量，不满意则升级
  • Conformal Prediction：RouteNLP 使用的分布无关阈值初始化方法
MODELS_CASCADE = [
    {"model": "gpt-5-nano", "max_cost": 0.0001},
    {"model": "gpt-5-mini", "max_cost": 0.001},
    {"model": "gpt-5.2", "max_cost": 0.01},
]

async def cascade_call(prompt: str, quality_threshold: float = 0.8):
    for tier in MODELS_CASCADE:
        response = await call_model(tier["model"], prompt)
        quality_score = evaluate_response(response)

        if quality_score >= quality_threshold:
            return response  # 够好就停

    return response  # 最后一级无论如何返回

成本分析：假设 85% 请求在 Nano 层通过、12% 在 Mini 层通过、3% 升级到旗舰：

平均成本=0.85×Cnano+0.12×(Cnano+Cmini)+0.03×(Cnano+Cmini+Cflagship)\text{平均成本} = 0.85 \times C_{nano} + 0.12 \times (C_{nano} + C_{mini}) + 0.03 \times (C_{nano} + C_{mini} + C_{flagship})平均成本=0.85×Cnano​+0.12×(Cnano​+Cmini​)+0.03×(Cnano​+Cmini​+Cflagship​)

对比全量旗舰，cascade 的平均成本通常仅为其 15-30%。

权衡：cascade 在升级时会产生额外延迟（重新调用更强模型）和额外成本（低级模型的调用费用虽小但非零）。对延迟敏感的场景需要权衡升级率与 p99 延迟。

模式三：分类器路由

训练一个轻量分类器预测请求所需的模型级别，一次性路由到正确级别——避免 cascade 的多次调用开销。

分类器的训练数据来源：

  1. 用旗舰模型处理一批请求，记录输出质量
  2. 用低级模型处理相同请求，记录输出质量
  3. 标注"这个请求用低级模型就够了"或"需要高级模型"
  4. 训练轻量 BERT/distilBERT 分类器

AWS IPR 使用 Qwen3-0.6B 作为路由分类器，在保持 100% 质量等价的前提下，将 59.9% 的请求路由到 Haiku（便宜 12 倍），实现 48.7% 成本节省。

Anthropic Advisor 策略

2026 年 4 月，Anthropic 推出了一种创新的路由模式：Advisor Strategy——Opus 作为顾问、Sonnet/Haiku 作为执行者。

传统模式：大模型编排，小模型执行（top-down） Advisor 模式：小模型驱动，大模型按需咨询（bottom-up）

response = client.messages.create(
    model="claude-sonnet-4-6",  # executor
    tools=[
        {
            "type": "advisor_20260301",
            "name": "advisor",
            "model": "claude-opus-4-6",
            "max_uses": 3,  # 成本控制：最多咨询 3 次
        },
    ],
    messages=[...]
)

实测效果：

  • Sonnet + Opus advisor：SWE-bench Multilingual 提升 2.7 百分点，同时单任务成本降低 11.9%
  • Haiku + Opus advisor：BrowseComp 得分 41.2%（Haiku 单独 19.7%），成本仅为 Sonnet 单独的 15%

为什么 Advisor 比传统路由更好：

  • 不需要预判复杂度——执行者自己知道何时需要帮助
  • Opus 只生成短计划（400-700 tokens），不执行工具调用——成本可控
  • 单次 API 请求完成，无需外部编排逻辑

构建路由评估数据集

在部署路由之前，需要构建评估集来验证路由决策的质量-成本权衡：

  1. 采样 200-500 个生产请求
  2. 在所有候选模型上运行
  3. 收集质量评分（自动指标 + 人工抽检）
  4. 绘制质量-成本帕累托前沿
  5. 确定各任务类型的"足够好"模型

路由系统的常见陷阱

陷阱一：静默质量退化

路由到低级模型后，输出质量可能在特定 case 上显著下降，但如果没有持续的质量监控，这种退化会被用户投诉而非系统指标发现。

解决：对路由到低级模型的请求做持续采样评估（如每 100 次抽 1 次用旗舰模型对照）。

陷阱二：升级率失控

Cascade 系统如果升级判据过于敏感，可能导致 80% 请求都升级到旗舰——实际成本反而高于全量使用中端模型（因为多了低级模型的"浪费"调用）。

解决：监控升级率，保持在 15-30% 以下。超过则调整判据或扩大低级模型的能力覆盖。

陷阱三：路由器本身的代价

分类器路由为每个请求增加一次轻量模型调用。如果请求量极大（百万级/天），路由器本身的成本也需计入：

小结

模型路由的核心洞察：70% 以上的生产请求不需要旗舰模型，但组织惯性导致全量使用旗舰。三种路由模式适用不同成熟度——静态规则即刻上线、Cascade 在 2-3 周内部署、分类器路由需要更多数据积累。Anthropic 的 Advisor 策略代表了"小模型驱动、大模型按需"的新范式。关键是持续监控路由质量，防止静默退化。
