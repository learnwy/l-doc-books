Part IV · Control Plane模型路由与级联

模型路由与级联

一个产品里很少只用一个模型。简单的分类、改写、抽取任务，便宜的小模型可能已经够用；多步推理、长链代码、严谨论证等请求，则可能需要更强模型或更高推理强度。模型路由（routing）与级联（cascade）把「按能力、成本与风险分配推理资源」工程化：可以在请求进入模型前选择模型，也可以先运行低成本路径、证据不足时再升级。收益不是固定百分比，它取决于候选模型、推理强度、真实流量分布、质量门和完整成本口径，必须用自己的评测验证。

本 hub 把这条主线拆成四章，层层递进。基础回答「为什么要路由、省的是什么、有哪些大类方法」——它建立成本-质量前沿这个贯穿全书的坐标系，并给出一张方法谱系图，后面每一种具体方法都挂在这张图上。方法深入三种核心机制：请求进来前就决策的分类器路由、请求跑起来后按结果回退的模型级联、以及给两者供给信号的难度估计。训练讲怎么把一个路由器真正训出来——损失与架构、偏好数据与标注、以及上线后用赌博机持续学习。实践落到工程：用哪种网关中间件接住多模型、怎么离线加在线地评测一个路由策略、以及真实系统里绕不开的漂移、冷启动与回退权衡。

读者路径建议：做应用、想立刻省钱的工程师，可以从 为何模型路由 直接跳到 路由网关与中间件，先用现成网关搭一个规则路由跑起来，再回头补 成本-质量前沿 与 路由评测 把策略量化。想训练自己路由器的研究型读者，建议顺序读完基础与方法两章后，重点啃训练章。前置知识只需要：知道 LLM 推理大致怎么计费（按 token）、读得懂简单的分类与回归概念。

与兄弟 hub 的分工要划清楚，避免重复也方便交叉取用。本 hub 只管「在多个已有模型之间做选择与回退」这一层决策逻辑。省钱的全景——缓存、压缩、批处理这些与「选哪个模型」并列的省钱手段——属于 AI 成本与延迟优化，那里也有一节模型分级，本 hub 是它的深化与展开。模型本身怎么跑得快——KV cache、连续批处理、推测解码、量化——是 LLM 服务与推理系统 的范围；注意「推测解码」是单模型内部的 token 级加速，而本 hub 讲的「推测级联」是它与多模型级联的杂交，二者别混。怎么判断一个回答好不好——评测方法学、benchmark、judge 模型——是 AI 评测与基准 的地盘，本 hub 只在「如何评一个路由策略」这一窄口径上用到它。最后，**混合专家（MoE）**很容易和路由混淆：MoE 是模型内部把 token 路由给不同 FFN 专家，是架构层；本 hub 的路由是模型外部、请求级、跨独立模型的，二者机制相似但层次完全不同，详见 混合专家。

四章读完，你应该能回答三个问题：给定我的流量分布，路由能省多少、风险在哪；该用规则、训练分类器还是级联；以及上线后怎么持续验证它没有悄悄退化。
