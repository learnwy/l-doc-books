Part IV · Control Plane模型路由与级联方法难度估计

难度估计

把前两节连起来看会发现一个共同的瓶颈：分类器路由要预测「该上强模型」的分（分类器路由），级联要判断「这版答案够不够好」（模型级联与回退），它们表面上是两件事，骨子里都在问同一个问题——这个请求/这个回答有多难、有多可信。决策器的算法再精巧，喂进去的难度信号不准，整套路由就垮。所以难度估计不是路由的一个配件，而是它的真正瓶颈。这一节把「难度」这个概念拆开，讲清楚它有哪几种形态、用什么信号去估、以及为什么它本质上很难。

核心概念：三种难度，别混为一谈

「难」是个含糊的词，路由里至少要区分三种，它们用不同信号、服务不同决策。

flowchart TD
  Root[请求的'难度'] --> A[内在难度<br/>请求本身有多难]
  Root --> B[相对难度<br/>小模型相对大模型差多少]
  Root --> C[回答可信度<br/>这版答案靠不靠谱]
  A --> A1[请求前可估·喂给分类器路由]
  B --> B1[路由真正关心的量]
  C --> C1[答案后才有·喂给级联回退]

内在难度是请求本身的属性——一道竞赛数学题客观上比一句问候难。但路由其实不直接关心它：哪怕一个请求很难，只要小模型也能答对，就没必要升级。相对难度才是路由真正要的量：小模型在这个请求上相对强模型差多少？差得多才值得升级，差不多就别浪费钱。回答可信度是级联用的事后信号——答案已经生成，问它有多大概率是对的。三者关系是：分类器路由想在请求前估出相对难度（最难），级联退而求其次、用事后的回答可信度近似它（更容易但要白跑一趟）。

估计内在/相对难度的信号

请求前能用的信号都是「表面线索」，因为还没有任何答案。下表列出常用信号及其可靠性。

信号 怎么用 反映哪种难度 可靠性
请求长度 / token 数 长请求倾向更难 内在（弱代理） 低，只在极端值有用
任务类型标签 代码/推理/数学标记为难 内在 中，领域相关
嵌入空间位置 离「历史难样本」近则难 相对 中高，依赖编码器
小模型自评不确定性 让小模型预估自己能否答好 相对 中，受过度自信污染
历史同类请求胜负 查相似请求里小模型赢没赢 相对 高，但要积累数据

关键教训是：单一表面信号（尤其是长度）几乎从不够用，必须组合。真正强的相对难度估计来自「历史同类请求里小模型 vs 强模型谁赢」这种监督信号——它直接对准路由要的量，但要靠数据积累，这正是 路由数据与标注 的主题，也是矩阵分解路由能 work 的根基。

回答可信度：把不确定性量化

级联走的是另一条路——先生成答案，再估它可信不可信。这里的核心是不确定性量化，把「模型有多确定」变成一个可比的数。

一个朴素做法是用生成序列的平均对数概率（等价于困惑度的负向量）。设回答有 nnn 个 token，第 ttt 个 token 概率为 ptp_tpt​，置信度可取

c(x)=exp⁡ ⁣(1n∑t=1nlog⁡pt)c(x) = \exp\!\left(\frac{1}{n}\sum_{t=1}^{n}\log p_t\right)c(x)=exp(n1​t=1∑n​logpt​)

但这个信号有个出名的毛病：它衡量的是「流畅度」而非「正确性」。模型可以非常流畅、非常自信地胡说八道（幻觉），此时 c(x)c(x)c(x) 很高却完全错。所以更可靠的可信度估计往往要额外手段：让模型对同一请求采样多次看答案一致性、单独训一个判正确性的小模型，或用一个更强的 judge 模型打分。judge 必须在盲测中交换回答位置、控制长度并按独立人工样本校准，否则位置偏差和风格偏好会直接污染升级决策。

为什么难度估计本质上很难

值得花一段讲清楚难度估计的根本困难，免得对它期望过高。第一，难度是相对于模型的，不是绝对的——同一个请求，小模型升级一代后可能从「难」变「简单」，于是所有难度标签都过期了。这意味着难度估计器和模型版本强绑定，模型一换就要重估，是 落地与权衡 里漂移问题的直接来源。

第二，最有价值的判断恰好最难做——那些「小模型差一点点就能答对」的边界请求，正是路由收益最大的地方，也正是难度信号最模糊、最容易判错的地方。容易判的请求（明显简单或明显难）路由收益本来就小。所以难度估计的提升空间集中在中间那条模糊地带，而那里偏偏最难提升。

第三，估计本身有成本。最准的相对难度估计往往要真跑小模型甚至采样多次，但那就退化成级联、丧失了「请求前一次决策」的省。难度估计永远在「估得准」和「估得省」之间走钢丝。认清这三点，就不会指望一个完美的难度预言机，而会务实地在准确和成本间找平衡——这也是为什么实践中规则、分类器、级联常常混用。

小结

  • 难度估计是路由的真正瓶颈：分类器路由和级联本质都在估难度，信号不准则整套路由垮。
  • 区分三种难度：内在难度（请求本身）、相对难度（小模型相对强模型差多少，路由真正要的量）、回答可信度（事后信号，级联用）。
  • 请求前只能用表面信号（长度、任务类型、嵌入位置、自评、历史胜负），单一信号几乎不够，最强的是「历史同类请求小模型胜负」这种监督信号。
  • 回答可信度常用平均对数概率，但它衡量流畅而非正确，幻觉会让它失效；更可靠的是采样一致性、训练的正确性判别器或 judge 打分。
  • 难度本质上难估：它相对模型版本会过期、最有价值的边界请求最难判、且越准的估计越贵——务实地在准与省之间平衡。
