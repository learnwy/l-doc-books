Part IV · Control Plane模型路由与级联基础成本-质量前沿

成本-质量前沿

上一节用一张三行表说明了路由能把强模型调用占比压到二三成。但「压到二三成」只是一个点，真正决定一个路由器好坏的，是它在所有可能的占比下表现出的整条曲线。把横轴设为成本（或等价地，送给强模型的请求比例），纵轴设为质量，每一个路由策略都会画出一条从「全用小模型」到「全用强模型」的曲线。这条曲线就是成本-质量前沿（cost-quality frontier），它是评判路由器的标准坐标系，也是这一节要精确定义的对象。理解它之后，「这个路由器好不好」就从一句感觉变成了一个可以测量、可以比较的几何问题。

核心概念：把策略画成前沿上的点

设小模型质量为 qsq_sqs​、成本为 csc_scs​，强模型为 qlq_lql​、成本为 clc_lcl​，且 ql>qsq_l > q_sql​>qs​、cl>csc_l > c_scl​>cs​。一个路由器把比例 ppp 的请求送给强模型，剩下 1−p1-p1−p 送给小模型。最朴素的「随机路由」基线下，整体期望成本与质量都是线性插值：

C(p)=(1−p) cs+p cl,Qrand(p)=(1−p) qs+p qlC(p) = (1-p)\,c_s + p\,c_l, \qquad Q_{\text{rand}}(p) = (1-p)\,q_s + p\,q_lC(p)=(1−p)cs​+pcl​,Qrand​(p)=(1−p)qs​+pql​

随着 ppp 从 0 到 1，随机基线在成本-质量平面上走出一条直线，连接 (cs,qs)(c_s, q_s)(cs​,qs​) 和 (cl,ql)(c_l, q_l)(cl​,ql​) 两端。一个有用的路由器必须做得比这条直线好：它应该优先把强模型的额度花在「小模型答不好、但强模型能答好」的那批请求上，于是在同样的成本下质量更高，曲线凸出在随机直线之上。

flowchart TD
  A[全小模型<br/>低成本·低质量] --> B[好路由器:<br/>凸出在随机线上方]
  A --> C[随机路由:<br/>对角直线基线]
  B --> D[全强模型<br/>高成本·高质量]
  C --> D
  E[路由器好坏] --> F[看曲线离随机线<br/>上方有多远]

判断一个路由器，看的就是它的曲线在多大范围内、离随机基线上方有多远。完全没用的路由器贴着随机线；理论最优的路由器（拥有完美的难度先知）则贴着左上角的「先答对难题再答简单题」的理想折线。

APGR：把整条曲线压成一个数

逐点比较曲线不方便，业界用一个汇总指标——APGR（Average Performance Gap Recovered，平均性能差恢复率）。直觉是：随机基线和理论上界（同成本下质量的最大可能）之间有一个差距，路由器把这个差距填回了多少比例。形式上，对每个成本预算 ccc，记随机基线质量 Qrand(c)Q_{\text{rand}}(c)Qrand​(c)、最优可达质量 Qopt(c)Q_{\text{opt}}(c)Qopt​(c)、被评路由器质量 Qrouter(c)Q_{\text{router}}(c)Qrouter​(c)，单点的差距恢复率为

PGR(c)=Qrouter(c)−Qrand(c)Qopt(c)−Qrand(c)\mathrm{PGR}(c) = \frac{Q_{\text{router}}(c) - Q_{\text{rand}}(c)}{Q_{\text{opt}}(c) - Q_{\text{rand}}(c)}PGR(c)=Qopt​(c)−Qrand​(c)Qrouter​(c)−Qrand​(c)​

再对成本区间求平均（积分归一化）得到 APGR。APGR 等于 0 表示路由器和瞎猜一样，等于 1 表示达到先知上界。RouteLLM 正是用这套指标报告其结果的（RouteLLM, ICLR 2025）。这个指标在第四章 路由评测 会被当成主指标展开，这里先把它的定义钉死，作为全 hub 的公共度量。

下面把几个常见汇总指标列清楚，避免后文混用。

指标 含义 越大/越小越好 主要用途
APGR 平均填回了多少「随机→先知」的差距 越大越好（上限 1） 比较两个路由器整条曲线
CPT(x%) 达到强模型 x% 质量所需的最低成本 越小越好 给定质量目标算预算
强模型调用占比 实际送给强模型的请求比例 视质量目标而定 直接预估账单
误路由率 难题被送给小模型的比例 越小越好 质量风险监控

边际思维：下一块钱该花在谁身上

前沿曲线背后有一个更锋利的视角——边际分析。把请求按「升级到强模型能带来多少质量提升」排序，提升最大的请求排在最前。一个最优路由器应当严格按这个顺序、从提升最大的请求开始往强模型放，直到预算耗尽。这等价于说：在最优策略下，被送给强模型的最后一个请求，其边际质量提升应当恰好等于「每多花一块钱买到的质量」这个统一的兑换率 λ\lambdaλ。

送给强模型  ⟺  ql(x)−qs(x)cl−cs≥λ\text{送给强模型} \iff \frac{q_l(x) - q_s(x)}{c_l - c_s} \ge \lambda送给强模型⟺cl​−cs​ql​(x)−qs​(x)​≥λ

这里 ql(x)−qs(x)q_l(x)-q_s(x)ql​(x)−qs​(x) 是请求 xxx 在强模型上相对小模型的质量增益，λ\lambdaλ 是你愿意为单位质量支付的价格（willingness-to-pay）。调高 λ\lambdaλ 表示你更舍得花钱买质量，更多请求被送上强模型，前沿上的工作点右移；调低则左移。整条前沿曲线，本质就是 λ\lambdaλ 从 0 扫到无穷大时工作点的轨迹。

这个 λ\lambdaλ 在工程上往往落地成一个置信度阈值或分数阈值：路由器给每个请求打一个「该上强模型」的分，超过阈值就升级。阈值就是 λ\lambdaλ 的代理。怎么打这个分，是 难度估计 的核心；级联里怎么用这个阈值决定要不要回退，是 模型级联与回退 的核心。本节只确立一件事：阈值不是拍脑袋设的，它对应着前沿上一个明确的成本-质量工作点。

前沿会移动，也会作弊

两个容易踩的坑。第一，前沿不是固定的：模型版本一更新、单价一调整，整条曲线就平移甚至变形，原来调好的阈值可能瞬间偏离最优。这是 落地与权衡 里漂移问题的根源——上线那天最优的工作点，三个月后可能既不省钱也不保质。

第二，前沿会被「作弊」式地刷高。如果用来画前沿的评测集和训练路由器的数据同源、甚至重叠，APGR 会虚高，一到真实流量就垮。所以前沿必须在独立、贴近线上分布的数据上测，且小模型与强模型的质量评估要用同一把尺子：同一个 rubric、同一个 judge 协议、相同的位置随机化与盲测流程。前沿是个好工具，但只在诚实测量下才有意义。

小结

  • 每个路由策略在成本-质量平面上画出一条曲线，随机路由是连接两端的对角直线，有用的路由器凸出在它上方。
  • APGR 把整条曲线压成一个数：填回了多少「随机基线到先知上界」的差距，0 等于瞎猜、1 等于先知；CPT、调用占比、误路由率是补充视角。
  • 边际思维给出最优策略：按「升级带来的质量增益」排序优先送强模型，工作点由 willingness-to-pay λ\lambdaλ 决定，工程上落地为置信度/分数阈值。
  • 前沿随模型版本与定价漂移，且会因评测数据泄漏而虚高；必须在独立、同分布、同评估协议下诚实测量。
