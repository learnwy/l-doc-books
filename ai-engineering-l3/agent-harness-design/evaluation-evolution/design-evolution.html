设计演进的驱动力

harness 设计最反直觉的地方在于：你精心搭建的东西，有一部分注定要被拆掉。两年前的最佳实践是手写解析器把模型输出变成函数调用，今天原生 function calling 让那层代码成了负资产；曾经必要的长篇行为规范提示词，正被训练进权重里的默认行为取代。这不是设计失误，而是这个领域的结构性特征——模型在快速吸收脚手架的功能。理解推动这场演进的力量，才能设计出「知道自己哪天该被删除」的模块。

核心概念：五股力量的方向表

力量 作用方向 近年实例
模型能力 自下而上吸收脚手架层 原生工具调用、长上下文、推理模型
经济学 改写成本结构从而改写架构取舍 提示缓存、批量推理、单价下行
标准化 私有格式被协议收编 function calling、MCP、说明文件格式
安全压力 给自治度加上可审计的缰绳 审批模式、沙箱档位成为标配
研究回流 论文机制沉降为产品默认 反思循环、计划执行模式进入主流外壳

五股力量的合力决定了每个组件的生命周期曲线。下面逐一展开，重点回答那个实操问题：今天的哪些设计决策，会在什么信号出现时需要重审。

模型能力：吸收与释放的循环

Rich Sutton 在《The Bitter Lesson》里给出的判断——依赖算力泛化的方法终将胜过人工编码的知识——在过去几年以更快的节奏应验到 agent 层（Sutton，2019 年短文）。DeepSeek-R1 展示了纯强化学习可以自发激发出长程推理与反思行为，无需手工的过程奖励脚手架（arXiv 2501.12948）；工具调用从「解析器工程」变成 API 参数；百万级窗口让许多检索中间层失去存在理由。METR 的测量给这股力量定了速：模型能完成的任务时长地平线约每七个月翻一番，即

T(t)=T0⋅2 t/7 月T(t) = T_0 \cdot 2^{\,t/7\text{ 月}}T(t)=T0​⋅2t/7 月

按此速率外推，今天地平线一小时的任务约两年后到达半日量级——置信区间虽宽，方向却稳定。对 harness 的含义不是「不用设计了」，而是每一层都要标定它假设的模型水位线：这层逻辑补偿的是模型的哪个具体弱点？下次模型升级时，跑一次消融实验验证它是否仍有净贡献。

flowchart LR
    A[外部脚手架功能] --> B[验证价值 成为事实标准]
    B --> C[被模型或 API 原生吸收]
    C --> D[harness 删去该层变薄]
    D --> E[新缺口暴露]
    E --> A

这个循环解释了为什么成熟的 harness 反而越来越薄：mini-swe-agent 用约百行代码逼近重型框架的成绩，正是踩在了模型已原生具备的能力上，只保留真正的编排最小集（SWE-agent/mini-swe-agent）。

经济学：价格信号重塑架构

推理成本结构的变化直接改写最优架构。Manus 团队复盘的核心教训之一是：KV 缓存命中率决定 agent 的单位经济性，因此「追加式上下文、稳定前缀」压倒了「聪明但破坏缓存的重排策略」（Manus 博客）。这类约束十年前不存在，如今却排在架构决策表的第一行——当缓存读取的单价与全价相差一个数量级，为命中缓存而牺牲一点局部优雅是完全理性的。

反方向的信号同样有效：单价整体下行与吞吐上升，会让「多跑几轮」相对「精心单发」变得更划算——重复采样、集成表决这类用计算换可靠度的模式（见编排多个 harness）的经济可行域正在扩大。设计时值得为每个重负载组件写下它的价格敏感度：如果 token 单价再降十倍，这个设计还会是最优吗？

标准化：协议收编私有格式

标准化是缓慢但不可逆的力量。工具调用经历了从各家私有的输出约定到统一 JSON schema 规范的转变；MCP 于 2024 年底发布后在一年内获得主要厂商跟进，工具供给端开始跨外壳复用（MCP 发布公告）；仓库级说明文件以 AGENTS.md 的形状成为跨工具契约，被数万个项目采纳（agents.md）。标准化的受害者永远是中间层的私有胶水——如果你的某个模块唯一的存在意义是适配某家厂商的非标接口，它就是下一个被协议拆除的对象。产品侧同样在收敛：Claude Code 的外壳能力被抽取为官方 SDK 对外开放，产品壳与自研壳的边界正在模糊（building-agents-with-the-claude-agent-sdk）。

安全压力与研究回流

另外两股力量的方向恰好相反。安全压力持续做加法：提示注入的现实威胁（OWASP 清单首位的风险，见权限与安全分层）让审批模式与沙箱档位从可选配件变成出厂标配，且随自治度提升只会收紧不会放松。研究回流则负责供给新模式：ReAct 式交错推理从论文走到几乎所有产品的骨架里，反思与计划执行模式也完成了同样的旅程（arXiv 2210.03629）。跟踪这两股力的方法不同——前者盯威胁情报与事故报告，后者盯消融文献里的「哪个机制在什么条件下有净收益」。

案例年表：三次重心迁移

把五股力量放进时间轴，能看到 harness 架构的重心已经迁移了三次。2023 年：循环即产品。 模型原生工具能力薄弱，harness 的价值集中在输出解析、重试与状态管理上，自建的提示词状态机是核心竞争力。2024 年：接口与协议年。 function calling 逐渐普及让解析层贬值， Devin 与 OpenHands 把「环境」变成卖点，年底 MCP 发布则预告了工具供给的标准化（MCP 公告）。2025 年：薄壳与 SDK 化。 长上下文与推理模型吸收了大量过程性脚手架，百行最小外壳成为可行选项，厂商把产品级壳开放成 SDK，竞争焦点从「有没有循环」转向「权限、恢复与呈现的成色」（Claude Agent SDK）。

三次迁移的共同教训：每个时代的核心竞争力都是下一个时代的默认配置。这为「升级日流程」提供了清单——模型大版本发布后依次执行：读官方的能力变更说明，标记哪些变化触及本 harness 的补偿层；跑一次消融对照确认各模块净贡献；按结果拆层或保留；最后把结论写进架构决策记录。整个流程半天以内，换来的是外壳不会随时间腐化成历史包袱。

面向演化的设计姿态

把这些力量翻译成四条可持续的设计纪律。第一，为删除而写：每个模块带一行注释说明它补偿的模型缺陷，缺陷消失之日就是它的退役之时；适配层一律做薄，标准接口直达业务。第二，定期复测归因：把消融实验设为季度体检而不是上线前的一次性审计，模型每次升级后重跑关键对照。第三，押注协议而非实现：工具面走 MCP，指令面走通用说明文件，评测面走开放基准加自有任务套件，让任何一层都能独立替换。第四，保持最小内核的可行性证明：像 mini-swe-agent 那样维护一个百行级的最小版本作为对照组，它既是复杂度的试金石，也是大重构时的退路。做到这四条，下一次模型发布时你的反应将是「拆东西」而非「救火」。

小结

  • 五股力量中，模型能力自下而上吸收脚手架，安全压力自上而下加缰绳。
  • 为每层标注其假设的模型水位线，升级后用消融复测净贡献。
  • 价格结构参与架构决策：缓存经济学已重排优先级。
  • 押注协议、保持薄适配、维护百行最小对照，是穿越演进的四条纪律。
