Agent 循环设计：步进、中断与恢复

循环是 harness 里最先被写下、却最不该被随手写的部分。它的三个语义——一步算什么、用户何时能插手、断电之后从哪继续——会渗进上层所有功能：UI 的每个交互、计费的每次结算、评测的每条轨迹都建立在这套语义之上。上线后再改步进粒度或中断行为，等于给行驶中的车换轮轴。本篇把这三组语义当作正式的 API 来设计。

核心概念：一步是什么

Anthropic 把 agent 定义为「模型在循环中使用工具」：收集上下文、采取行动、核验结果、再循环，直到任务完成（building-effective-agents）。这个朴素描述落到工程上，需要先把「一步」的状态机画出来——每条边都是你将来要测试的分支：

stateDiagram-v2
    [*] --> 思考中
    思考中 --> 待审批: 工具需权限
    待审批 --> 执行中: 获批
    待审批 --> 已终止: 用户拒绝
    思考中 --> 执行中: 免审工具
    执行中 --> 观察中: 结果返回
    观察中 --> 思考中: 目标未达
    观察中 --> 已完成: 结束信号
    思考中 --> 已暂停: 用户打断
    执行中 --> 已暂停: 安全点生效
    已暂停 --> 思考中: 注入新指令

「一步 = 一次模型推理加其触发的全部工具执行」是多数终端 harness 的粒度。粒度选择是第一个权衡：粒度太细（单工具即停）让强模型窒息于等待审批；太粗（整任务一档）则中间无法纠偏。实践中常见的折中是按风险分级——只读工具连续执行不落闸，写操作前停下等批。

设计量 可选值 影响
步进粒度 单工具 / 单回合 / 多回合批次 审批频率与纠偏时机
决策主体 模型自主 / 计划驱动 / 人每步确认 自治度与可控度
停止权 仅模型 / harness 强制 / 用户 防失控与防早退

步进策略：三种谱系

反应式由 ReAct 确立：推理轨迹与动作交错生成，思考为下一步动作提供依据，动作的观测又反过来修正思考，这种接地显著降低了纯思维链的幻觉漂移（arXiv 2210.03629）。它至今仍是绝大多数产品 harness 的骨架，因为实现简单且对模型能力要求最低。

计划式在循环外套一层显式计划维护：先产出任务分解，执行中对计划增量修订。它的价值在长程任务上——计划充当防止目标漂移的外部锚点。代价是多一次结构化输出与一致性维护，且计划本身可能过时，何时重算是新增的设计点。

搜索式把循环升级为树探索：ToT 类方法在每个决策点展开多个候选并回溯（arXiv 2305.10601）；Reflexion 则在失败后生成语言化的自我反馈存入情景记忆，下一轮携带教训重试，HumanEval 上将 pass@1 提到 91%（arXiv 2303.11366）。搜索式的成本以倍数计，产品化 harness 很少全盘采用，但「失败后带反馈重试」作为局部模式已被广泛内化——错误恢复一章会回到它（见错误恢复与重试模式）。

预算与停止条件：防失控也防早退

没有外部停止权的循环迟早出事。停止条件通常三层叠加：

  • 信号停止：模型发出结构化的完成声明，这是唯一正常出口；
  • 预算停止：token 或费用超限强制收尾。设每轮平均消耗 cˉ\bar{c}cˉ 个 token、预算为 BBB，则硬上限轮数为 nmax⁡=⌊B/cˉ⌋n_{\max} = \lfloor B/\bar{c} \rfloornmax​=⌊B/cˉ⌋，注意末轮应留给「总结已做工作」，否则用户拿到的是静默截断。预算的分区方法见Harness 内的上下文管理；
  • 卡死停止：检测到无进展时熔断。最实用的信号是动作签名重复——对「工具 + 关键参数」做哈希，若同一签名在滑动窗口内出现 kkk 次，判定打转。确定性环境下同签名重复的概率随 kkk 指数衰减（pkp^kpk，p<1p<1p<1），因此取很小的 kkk（如 3）误报率即可忽略，而真打转几乎必然命中。

比停止更难的是止损后的姿态：预算耗尽时应让模型用最后一轮产出移交文档（做了什么、卡在哪、下一步建议），而不是直接掐断进程。这个细节决定了用户把 harness 判定为「可靠的同事」还是「会猝死的实习生」。

中断语义：把打断设计成常态操作

人在环路的系统里，打断频率远高于设计者的直觉。Claude Code 的处理已成事实范本：运行中按键即刻打断当前回合，正在执行的命令跑完即止而非硬杀；打断期间键入的新消息进入队列，在下个安全点注入上下文，而不是丢弃（interactive-mode 文档）。这组语义回答了两个关键问题：打断的原子单位是什么（当前工具调用，而非整个任务）、排队消息何时可见（下一轮装配时）。

中断还有一层容易被忽略的经济学。设打断发生在工具边界时的废弃工作期望为 wbw_bwb​、硬杀进程为 wkw_kwk​，正在执行的工具剩余时长分布决定两者差距——对秒级命令二者接近，对十分钟测试套件，边界等待远优于硬杀。所以成熟 harness 都实现协作式中断：先发取消信号，给工具一个宽限期，超时才升级为强杀。OpenHands 的事件流架构里，暂停与恢复同样是事件流上的普通条目，这让打断本身可审计、可回放（arXiv 2407.16741）。

恢复与续跑：会话是一等资产

长任务的会话价值常常超过进程价值——跑了四十分钟的调试轨迹不该随终端关闭蒸发。恢复设计要回答三问。第一，序列化什么：完整消息历史、工具结果原文、待办清单、权限授予状态都要进盘；只存摘要的方案会让恢复后的模型失去关键细节。第二，在哪重放：恢复既可以从头重放事件重建环境，也可以快照环境状态只续尾部；前者正确性易保证但慢，后者依赖环境可快照。Codex CLI 提供 resume 子命令按历史会话续跑，Claude Code 的 --continue 与 --resume 同理（developers.openai.com/codex/cli、cli-reference）。第三，恢复后第一轮喂什么：实践上应在历史之后附加一条系统级的「你刚从中断恢复」锚点，否则模型常把恢复当成全新开始，重复已完成的工作。

恢复设计与持久化格式互相绑定：事件流式的历史天然支持重放，而自由文本日志只能支持「带着日志重新开始」。这也是第一章参照系里 OpenHands 与 Aider 分野的根源之一。

循环语义的测试策略

状态机一旦画出来，就该像对待支付流程一样给它配测试。难点在于循环的驱动源是概率性的模型输出，直接调真实模型既贵又不稳定——解法是假模型：用一个可编程的桩替换模型接口，按脚本吐出预设的工具调用序列，从而把「模型聪明与否」从被测对象里剥离，只测 harness 的机械语义。

三类测试覆盖三种信心。黄金轨迹回放：录制真实会话的事件流，断言恢复函数能从任意事件截断点重建出等价会话状态——这直接验证持久化与重放逻辑，是恢复语义的回归网。状态机性质测试：不写具体脚本，而是声明不变量——「结束信号之后不得再有任何工具执行」「副作用工具被执行则此前必存在对应审批事件」「暂停状态下收到新指令最终必然回到思考态」——用随机化的桩序列穷举路径，让性质检查器抓违例。中断时序测试：在工具执行的不同相位注入打断信号（已发出未开始、执行中、宽限期内），断言取消语义、队列消息注入点与资源清理全部符合设计。

这套测试的隐藏收益是文档性的：性质清单就是循环语义的 executable spec，新成员读完测试文件比读完设计文档更清楚系统承诺了什么。当后续章节讨论到权限与恢复策略的调整时，这些性质测试是唯一能防止「顺手改坏」的安全网。

小结

  • 先画状态机再写代码：每条边都是未来的测试用例与 UI 分支。
  • 三层停止叠加：模型信号、预算熔断、卡死检测（动作签名去重）。
  • 中断用协作式语义：工具边界生效、消息排队注入、宽限期后才强杀。
  • 会话持久化要含权限状态与原始观测，恢复首轮必须带「已恢复」锚点。
