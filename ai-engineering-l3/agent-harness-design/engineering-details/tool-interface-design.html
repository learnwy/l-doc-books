工具接口在 harness 中的设计

给模型设计工具和给同事写 API 是两份不同的工作：人类工程师会读文档、试调用、翻源码，模型只拥有你塞进上下文的名称、描述与参数 schema——描述之外的世界对它不存在。SWE-agent 把这层界面命名为 ACI（agent-computer interface），并用消融实验证明：同样的任务与模型，仅改变接口的形状就能显著改变解决率，正如人机交互里键盘布局决定打字速度（arXiv 2405.15793）。本篇讨论这层界面的四个设计面：签名、描述、返回值与错误。

核心概念：ACI 与传统 API 设计的分岔

设计维度 传统 API 面向人 ACI 面向模型
文档 独立文档站，可检索 描述字段本身，随每轮请求计费
容错 客户端读文档修正 错误消息就是唯一的纠正教材
返回体积 富余即可，带宽便宜 每个 token 都挤占注意力与窗口
探索成本 人可以试错几次 每次试错是一整轮推理的开销
演进约束 可发废弃通知 改名即「失忆」，旧用法瞬间失效

分岔的根源是调用者没有先验知识且每次探索极贵。人调用陌生 API 失败三次会去搜 Stack Overflow；模型失败三次意味着三轮推理延迟与三倍 token 成本，还可能陷入重复同一错误的循环。因此 ACI 设计的第一原则是把「人靠经验补齐的信息」全部前置进接口本身。

flowchart LR
    M[模型生成调用] --> V[harness 校验器]
    V -->|schema 不合| E1[结构化纠错信息]
    V -->|通过| X[工具执行]
    X --> R[原始结果]
    R --> C[裁剪与格式化]
    C --> O[作为观测返回]
    E1 --> O

签名设计：让正确用法成为唯一用法

参数表的第一原则是用类型系统替模型省心。能枚举就不自由字符串，能布尔就不枚举两个值的场景；路径拼接这类易错操作宁可拆成结构化字段也不要让模型手拼。Anthropic 的工具写作指南给出的反面案例极具代表性：一个需要模型自行猜测目录名的接口，远不如显式提供列举目录的配套接口——与其让模型猜，不如给它问的手段（writing-tools-for-agents）。

大结果集一律配分页参数，这是 Claude Code 读文件接口的经典形状：偏移量加行数上限，配合返回值里的总行数提示，模型可以像翻书一样按需读取而不是一口吞下整个仓库。默认值同样重要：把最常用的安全默认写死在 schema 里（如「不传即读前 2000 行」），模型的常见路径就少一次决策。最后是命名空间：当工具超过一二十个，read_file 与 read_messages 这类前缀分组能显著降低选错工具的概率——名字是模型路由决策的唯一线索。

描述即提示词：被低估的正文

工具描述不是注释而是真正的提示词，它参与每一轮的推理。写它的正确姿势与写 prompt 一致：说清何时该用、何时不该用、单位与边界条件、以及与相邻工具的分工。「搜索邮件」不如「按关键词搜索收件箱，返回摘要列表；需要完整正文时再用 get_message」。Anthropic 的指南特别强调合并高价值工作流：与其暴露三个原子接口让模型自己组合出「给 Jira 票加评论并修改状态」，不如提供一个完成整条流程的复合工具——组合逻辑在代码里做一次，好过让模型每轮都重新发明一遍（writing-tools-for-agents）。

但合并要克制：过度复合会让接口数量膨胀、单个描述变长，而 schema 本身是有租金的。设 NNN 个工具平均每个占用 sˉ\bar{s}sˉ 个 token 的 schema，则每轮固定开销为

S=N⋅sˉ,ρ=SWS = N \cdot \bar{s}, \qquad \rho = \frac{S}{W}S=N⋅sˉ,ρ=WS​

以 N=30N = 30N=30、sˉ=150\bar{s} = 150sˉ=150 计，S=4500S = 4500S=4500 个 token；在 200K 窗口上占比约 2%2\%2%，尚可接受，但在 32K 窗口的本地小模型上就到了必须精简的程度。工具集不是免费的，按真实使用频率裁剪是持续工作。

返回值经济学：每个 token 都有价格

工具结果直接进入下一轮上下文，因此返回值设计的核心是信噪比而非完整性。可操作的规则：结构化数据优先于序列化日志；命中十条精确结果优于倾倒一千条原始记录；超长输出截断时必须携带「已截断，共 N 行」的标记，否则模型会把局部当成全貌做推理。图片等高成本载荷要有显式的尺寸控制开关。这些规则的共同动机是保护两种稀缺资源：窗口容量与注意力质量——中段的大段噪声正是上下文腐烂的重灾区（arXiv 2507.13333）。

返回格式的选择还有一层交互考量：面向人的 CLI 会把 diff 渲染成彩色行级视图，而喂给模型的观测应是带明确锚点的纯文本。同一个工具执行器服务两类消费者时，格式化的职责应放在呈现层而不是工具层——这正是事件流架构要解决的问题（见事件流与可观测 UI）。

一份签名的设计走查

把上述原则压缩成一次真实的走查。任务：让 agent 能在大型仓库里定位代码。初稿接口是 grep(pattern)——问题立刻显形：正则方言未定义（模型会混用不同工具的语法）、无范围控制（大仓库全量扫描既慢又倾倒海量结果）、无结构化输出（匹配行与文件路径混在纯文本里）。

逐项修正后得到 search_code：参数 query 用字面量字符串加独立的 is_regex 布尔开关，消除方言歧义；scope 接受目录或 glob 模式并给默认值（当前工作区），常见路径零决策；max_results 默认 30 且返回体携带 total_matches 计数——模型看到「共 412 处命中，已显示前 30」就知道该收窄而不是以为只有 30 处；每条结果带文件、行号与前后各一行的上下文窗口，直接可供后续编辑工具引用。描述字段三句话：何时用它（知道符号名或字符串时）、何时不用（探索性浏览请先调目录列举）、结果如何衔接（行号可直接喂给编辑接口）。整个走查没有一行炫技，全部决策都在回答同一个问题：模型最可能以哪种错误方式调用它，如何在接口层让那种方式不可能或不昂贵。

错误消息：恢复流程的第一块踏板

模型遇到报错时没有别的求助渠道，错误文本就是它重试策略的全部依据。高质量错误消息的三要素：发生了什么（具体到字段与约束）、为什么被拒（指向可执行的修正）、下一步建议（给出可行方向而非只有否定）。比较两种写法：「Error: invalid input」与「参数 since 不接受相对时间，请传 ISO 8601 日期，例如 2026-08-01；如需『最近一周』请改用 range 参数」。后者让模型一轮自愈，前者诱发数轮盲试。完整的错误分类与重试语义在错误恢复与重试模式展开，这里只需确立原则：错误消息是接口的一部分，按提示词的标准来评审它。

工具调用的可靠性本身也有研究脉络支撑：Gorilla 的实验表明微调后的模型调用 API 时能显著降低幻觉参数率，说明「模型会用错工具」不是道德缺陷而是可优化的接口问题（arXiv 2305.15334）；更早的 Toolformer 则证明了工具使用的模式可以从语料中自监督学出，为「原生工具能力」提供了概念起点（arXiv 2302.04761）。harness 侧的对策是把这两类改进都当作接口设计的红利：模型越强，schema 可以越简洁；模型越弱，越要在描述里补足引导。

生态协议：从私有函数到 MCP

工具接口正在经历从「各 harness 私有函数集」到「跨 harness 协议」的转变。MCP 用统一的 JSON-RPC 形状定义了 server 暴露工具、资源与提示的方式，2024 年底由 Anthropic 发布后迅速被主流厂商跟进支持，一个 server 写一次可以被多个 harness 复用（modelcontextprotocol.io、发布公告）。对接口设计者的直接影响有二：其一，描述字段的写作规范开始跨产品通用，「描述即提示词」从经验升级为生态契约；其二，第三方来源的工具进入信任评估范围，来源分级与默认降级审批成为 harness 的新职责（威胁模型见权限与安全分层）。

小结

  • ACI 与 API 的分岔在于调用者零先验、试错昂贵，一切引导必须前置。
  • 签名用类型与枚举封死歧义，分页与默认值铺平常见路径。
  • 描述按提示词标准写作，schema 有 token 租金，工具集需持续裁剪。
  • 返回值追求信噪比，错误消息按「能让模型一轮自愈」来评审。
