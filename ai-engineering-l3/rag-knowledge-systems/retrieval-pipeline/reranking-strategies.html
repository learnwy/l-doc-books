Part III · RetrievalRAG 与知识系统 简介检索管线 简介重排序策略

重排序策略

核心概念

重排序（Reranking）是 RAG 检索管道中的精排阶段：在初步向量检索返回 Top-N 候选后，用更精确但计算成本更高的模型对这些候选重新排序。重排序是提升 RAG 回答质量最高效的手段之一——通常可以在不修改索引、不重新嵌入的情况下，将检索精度提升 10-30%。

为什么需要重排序

向量检索（一阶段）使用双编码器（Bi-Encoder）分别编码查询和文档，然后用向量相似度排序。这种方式速度极快（毫秒级搜索百万级文档），但精度有限——因为查询和文档之间没有交互信息。

Python Cross-Encoder 实现
from sentence_transformers import CrossEncoder
import numpy as np
from dataclasses import dataclass

@dataclass
class RerankResult:
    index: int
    text: str
    score: float
    original_rank: int

class CrossEncoderReranker:
    def __init__(self, model_name: str = "BAAI/bge-reranker-v2-m3"):
        self.model = CrossEncoder(model_name, max_length=512)

    def rerank(
        self,
        query: str,
        documents: list[str],
        top_k: int = 5,
    ) -> list[RerankResult]:
        pairs = [[query, doc] for doc in documents]

        scores = self.model.predict(pairs, show_progress_bar=False)

        ranked_indices = np.argsort(scores)[::-1][:top_k]

        return [
            RerankResult(
                index=int(idx),
                text=documents[idx],
                score=float(scores[idx]),
                original_rank=i,
            )
            for i, idx in enumerate(ranked_indices)
        ]

reranker = CrossEncoderReranker()

query = "RAG 系统如何处理长文档"
candidates = [
    "向量数据库支持高效的相似度搜索",
    "长文档需要分块后才能被 RAG 系统有效处理，常见策略包括固定长度分块和语义分块",
    "GPT-4 的上下文窗口可以支持 128K token",
    "递归分块按层级分隔符逐步分割文档，适合处理结构化长文档",
    "机器学习模型需要大量训练数据",
]

results = reranker.rerank(query, candidates, top_k=3)
for r in results:
    print(f"[{r.score:.4f}] (原排名 {r.original_rank}) {r.text[:50]}...")
TypeScript Cross-Encoder 调用
import Cohere from 'cohere-ai';

interface RerankInput {
  query: string;
  documents: string[];
  topK: number;
  model?: string;
}

interface RerankOutput {
  index: number;
  text: string;
  relevanceScore: number;
}

class CohereReranker {
  private client: Cohere;

  constructor() {
    this.client = new Cohere({});
  }

  async rerank(input: RerankInput): Promise<RerankOutput[]> {
    const response = await this.client.rerank({
      model: input.model || 'rerank-multilingual-v3.0',
      query: input.query,
      documents: input.documents,
      topN: input.topK,
      returnDocuments: true,
    });

    return response.results.map((r) => ({
      index: r.index,
      text: input.documents[r.index],
      relevanceScore: r.relevanceScore,
    }));
  }
}

class SelfHostedReranker {
  private endpoint: string;

  constructor(endpoint: string) {
    this.endpoint = endpoint;
  }

  async rerank(input: RerankInput): Promise<RerankOutput[]> {
    const pairs = input.documents.map((doc) => [input.query, doc]);

    const response = await fetch(`${this.endpoint}/predict`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ pairs }),
    });

    const scores: number[] = await response.json();

    return scores
      .map((score, idx) => ({
        index: idx,
        text: input.documents[idx],
        relevanceScore: score,
      }))
      .sort((a, b) => b.relevanceScore - a.relevanceScore)
      .slice(0, input.topK);
  }
}
方法 2：LLM 重排序
用大语言模型评估每个文档与查询的相关性。精度最高但成本也最高。


from openai import OpenAI

client = OpenAI()

def llm_rerank(
    query: str,
    documents: list[str],
    top_k: int = 5,
) -> list[tuple[int, float, str]]:
    scored_docs = []

    for i, doc in enumerate(documents):
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {
                    "role": "system",
                    "content": (
                        "评估文档与查询的相关性。只输出一个 0-10 的整数分数。\n"
                        "0=完全不相关，10=完全相关。"
                    ),
                },
                {
                    "role": "user",
                    "content": f"查询: {query}\n\n文档: {doc}",
                },
            ],
            temperature=0,
            max_tokens=5,
        )
        score_text = response.choices[0].message.content or "0"
        score = int("".join(c for c in score_text if c.isdigit()) or "0")
        scored_docs.append((i, score / 10.0, doc))

    scored_docs.sort(key=lambda x: x[1], reverse=True)
    return scored_docs[:top_k]

Lost in the Middle 问题
研究发现，LLM 对上下文中间位置的信息关注度较低——即使相关文档排在中间，LLM 也倾向于更多利用首尾位置的信息。这被称为"Lost in the Middle"现象。

Python 交错排列实现
def interleave_by_relevance(
    documents: list[str],
    scores: list[float],
) -> list[str]:
    paired = sorted(zip(scores, documents), reverse=True)

    result = [None] * len(paired)

    head = 0
    tail = len(paired) - 1

    for i, (score, doc) in enumerate(paired):
        if i % 2 == 0:
            result[head] = doc
            head += 1
        else:
            result[tail] = doc
            tail -= 1

    return [doc for doc in result if doc is not None]
MMR 多样性重排
除了相关性排序，还需要考虑结果的多样性——避免返回内容高度相似的多个文档块。


interface DiversityConfig {
  lambda: number;
  topK: number;
}

function mmrRerank(
  query: number[],
  candidateVectors: number[][],
  candidateScores: number[],
  config: DiversityConfig,
): number[] {
  const selected: number[] = [];
  const remaining = new Set(candidateVectors.map((_, i) => i));

  const firstIdx = candidateScores.indexOf(Math.max(...candidateScores));
  selected.push(firstIdx);
  remaining.delete(firstIdx);

  while (selected.length < config.topK && remaining.size > 0) {
    let bestScore = -Infinity;
    let bestIdx = -1;

    for (const idx of remaining) {
      const relevance = candidateScores[idx];

      let maxSim = -Infinity;
      for (const selIdx of selected) {
        const sim = cosineSimilarity(candidateVectors[idx], candidateVectors[selIdx]);
        maxSim = Math.max(maxSim, sim);
      }

      const mmrScore = config.lambda * relevance - (1 - config.lambda) * maxSim;

      if (mmrScore > bestScore) {
        bestScore = mmrScore;
        bestIdx = idx;
      }
    }

    selected.push(bestIdx);
    remaining.delete(bestIdx);
  }

  return selected;
}

function cosineSimilarity(a: number[], b: number[]): number {
  let dot = 0,
    normA = 0,
    normB = 0;
  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
  }
  return dot / (Math.sqrt(normA) * Math.sqrt(normB));
}

常见误区
❌ 误区 1：所有查询都需要重排
重排增加延迟和成本。对于简单查询（如精确关键词匹配），向量检索的结果已经足够好。建议用查询分类器判断是否需要重排。


❌ 误区 2：重排候选越多越好
候选太多（>100 条），Cross-Encoder 的延迟会非常高。经验法则：初步检索返回 20-50 条即可，更多的候选对最终 Top-5 的影响微乎其微。


❌ 误区 3：忽视 Lost in the Middle
即使重排序做得很好，如果直接按分数从高到低排列文档送入 LLM，中间位置的文档可能被忽略。对最终结果做位置优化（交错排列）是低成本高回报的优化。


❌ 误区 4：Cross-Encoder 和 Bi-Encoder 可以互换
两者架构不同、能力不同、用途不同：


    

  • Bi-Encoder 用于大规模一阶段检索（可预计算、可索引）
    • 

  • Cross-Encoder 用于小规模二阶段精排（需实时计算、不可索引）
    • 

  • 不能用 Cross-Encoder 做一阶段检索，也不应该用 Bi-Encoder 做精排
    • 



小结
重排序是 RAG 系统中投入产出比最高的优化手段之一，能够在不改变索引和嵌入的前提下显著提升检索精度。


核心要点回顾：


    

  • Cross-Encoder 是最主流的重排方法，BGE-reranker-v2-m3 是中文场景首选
    • 

  • 多阶段级联重排（粗排→精排→深排）是生产级系统的最佳实践
    • 

  • 重排候选数 20-50 是合理范围，不需要也不应该太多
    • 

  • Lost in the Middle 问题需要用交错排列等策略缓解
    • 

  • MMR 多样性重排避免返回重复内容
    • 

  • 选择性重排（只对重要查询重排）和结果缓存是关键的成本优化策略
    • 

  • 用 NDCG、MRR、Hit Rate 评估重排效果，关注提升幅度而非绝对值
    •
