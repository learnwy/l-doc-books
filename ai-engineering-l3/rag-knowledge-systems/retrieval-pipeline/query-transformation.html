查询变换

核心概念

查询变换是将用户的原始查询转换为更适合检索的形式的过程。在 RAG 系统中，用户的自然语言查询往往含糊、口语化、缺乏背景信息，直接用于向量检索会导致召回率低下。查询变换通过重写、扩展、分解等手段弥合用户意图与检索表达之间的鸿沟。

为什么需要查询变换

原始查询的问题 查询变换的好处
表达不清晰 更明确的查询
口语化 更正式/准确
信息不全 补充上下文
歧义 消除歧义

常见查询变换方法

1. 查询重写 (Query Rewriting)

核心思想: 让 LLM 将原始查询改写成更好的查询。

示例提示词:


请将以下用户查询改写成更适合向量检索的形式：
- 更具体明确
- 补充必要的上下文
- 保持原意
- 3句话以内

原始查询：什么是 RAG？
示例输出:


RAG (Retrieval-Augmented Generation) 的定义、工作原理和应用场景是什么？




优点
缺点





提升检索质量
增加成本




处理口语化查询
增加延迟




灵活
需要调优提示词





适用场景: 用户查询口语化、表达不清晰、需要更好效果。


2. 查询扩展 (Query Expansion)
核心思想: 用同义词、相关词扩展原始查询。


示例:


原始查询: "如何学习 Python"
扩展后: "如何学习 Python, Python 教程, Python 入门, 编程学习"
扩展来源:


    

  • WordNet、同义词词典
    • 

  • LLM 生成
    • 

  • 历史查询日志
    • 

  • 领域知识
    • 







优点
缺点





提升召回率
可能引入噪声




简单
需要扩展源




无额外成本
可能降低精度





适用场景: 召回率低、需要找到更多相关内容。


3. 查询分解 (Query Decomposition)
核心思想: 将复杂查询分解成多个简单子查询。


示例:


复杂查询: "2023年最好用的 RAG 框架是什么？它们的优缺点对比如何？"
分解为:
1. 2023年有哪些流行的 RAG 框架？
2. LangChain 的优缺点是什么？
3. LlamaIndex 的优缺点是什么？




优点
缺点





处理复杂查询
需要多次检索




更全面的结果
增加复杂度




召回率更高
成本增加





适用场景: 多步骤问题、比较类问题、需要全面信息。


4. 查询回溯 (Step-back Prompting)
核心思想: 先问一个更基础的问题，用答案帮助回答原问题。


示例:


原始查询: "Python 3.11 的 asyncio 有什么改进？"
Step-back 查询: "Python 的 asyncio 是什么？它的主要功能有哪些？"
先用 Step-back 查询的结果补充上下文，再回答原问题。




优点
缺点





补充背景知识
增加步骤




提升理解
增加延迟




适合复杂概念
需要判断何时使用





适用场景: 需要背景知识、专业领域问题。


5. 多查询生成 (Multi-Query Generation)
核心思想: 生成多个不同的查询，分别检索，合并结果。


示例提示词:


请为以下查询生成 3 个不同但意思相近的查询，用于向量检索：

原始查询：如何优化 RAG 系统的性能？
示例输出:


1. RAG 系统性能优化的方法有哪些？
2. 提升 RAG 检索和生成效果的技巧是什么？
3. 如何改进 RAG 系统的响应速度和准确率？




优点
缺点





召回率大幅提升
成本高（多次检索）




覆盖更多角度
延迟增加




效果通常很好
结果需要去重





适用场景: 追求高召回率、重要查询、预算充足。
