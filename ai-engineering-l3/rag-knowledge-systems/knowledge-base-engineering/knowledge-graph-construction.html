知识图谱构建

核心概念

知识图谱是结构化的知识表示形式，由实体、关系和属性组成，可以增强 RAG 系统的推理和检索能力。与纯向量检索只能找到"语义相似"的文档不同，知识图谱能表达精确的实体关系，支持多跳推理——例如从"Python"出发，经"发明者"关系到"Guido van Rossum"，再经"贡献"关系找到相关项目。这种结构化推理能力是纯向量检索无法实现的。

知识图谱的基本元素

元素 说明 示例
实体 (Entity) 现实世界中的事物 "Python", "Guido van Rossum"
关系 (Relation) 实体之间的联系 "发明者", "发布于"
属性 (Attribute) 实体的特征 "版本: 3.11", "发布时间: 2022"

知识图谱在 RAG 中的作用

能力 说明
结构化检索 可以按关系和属性查询
多跳推理 可以通过关系链推理
知识补全 可以推断缺失的知识
可解释性 答案来源更清晰

知识图谱构建方法

1. 手动构建

核心思想: 人工定义实体、关系和属性。

适用场景:

  • 领域知识明确
  • 数据量较小
  • 需要高质量控制
  • 概念不常变化

优点:

  • 质量高
  • 可控性强
  • 无错误

缺点:

  • 成本高
  • 速度慢
  • 难以扩展

2. 从结构化数据转换

核心思想: 将数据库、CSV、JSON 等结构化数据转换成知识图谱。

示例:

CSV 数据:
语言,发明者,发布年份
Python,Guido van Rossum,1991
Java,James Gosling,1995

转换成图谱:
(Python) -[发明者]-> (Guido van Rossum)
(Python) -[发布年份]-> (1991)

适用场景:

  • 已有结构化数据
  • 数据格式规范
  • 关系明确

优点:

  • 自动化程度高
  • 质量有保证
  • 易于更新

缺点:

  • 受限于原始数据结构
  • 需要数据清洗

3. 从非结构化文本提取

核心思想: 用 NLP 或 LLM 从自由文本中提取实体和关系。

常用方法:


    

  • NER (Named Entity Recognition): 识别实体
    • 

  • RE (Relation Extraction): 抽取关系
    • 

  • LLM: 直接让 LLM 提取（提示词工程）
    • 



LLM 提示词示例:


请从以下文本中提取实体、关系和属性，用 JSON 格式输出：

格式：
{
  "entities": [{"id": "1", "name": "实体名", "type": "类型"}],
  "relations": [{"from": "1", "to": "2", "type": "关系类型"}],
  "attributes": [{"entity": "1", "key": "属性名", "value": "属性值"}]
}

文本：{text}
适用场景:


    

  • 大量非结构化文本
    • 

  • 需要自动化构建
    • 

  • 领域知识分散
    • 



优点:


    

  • 可以处理大量数据
    • 

  • 自动化程度高
    • 

  • 发现隐含知识
    • 



缺点:


    

  • 可能有错误
    • 

  • 需要质量校验
    • 

  • 成本较高
    • 



4. 混合方法
核心思想: 结合多种方法，互补长短。


常见组合:


    

  • 手动定义核心概念
    • 

  • 从结构化数据导入基础数据
    • 

  • 用 LLM 补充从非结构化文本提取的知识
    • 

  • 人工校验和修正
    • 



优点:


    

  • 质量和效率平衡
    • 

  • 灵活可控
    • 

  • 适合大多数场景
    •

知识图谱与 RAG 结合
1. 图谱增强检索
方法:


    

  • 先在图谱中查询相关实体和关系
    • 

  • 再用这些信息增强向量检索
    • 

  • 或者混合两种检索结果
    • 



示例:


查询: "Python 的发明者还发明了什么？"

图谱查询:
- 找到 (Python) -[发明者]-> (Guido)
- 找到 (Guido) -[发明]-> (其他实体)

结合 RAG:
- 用图谱结果补充检索
- 生成更完整的答案
2. 图谱作为知识源
方法:


    

  • 将图谱中的三元组转换成文本
    • 

  • 作为 RAG 的知识库一部分
    • 

  • 或者直接用图检索
    • 



示例转换:


三元组: (Python) -[发明者]-> (Guido van Rossum)
转换成文本: "Python 的发明者是 Guido van Rossum"
3. 可解释性增强
方法:


    

  • 用图谱路径展示推理过程
    • 

  • 让答案更可追溯
    • 

  • 提升用户信任
    • 



实际应用
什么时候用知识图谱增强 RAG
✅ 适合场景:


    

  • 需要复杂推理
    • 

  • 实体和关系很重要
    • 

  • 需要可解释性
    • 

  • 领域知识复杂
    • 



❌ 不适合场景:


    

  • 简单问答
    • 

  • 快速原型
    • 

  • 数据量很小
    • 

  • 成本敏感
    •

  • 知识图谱由实体、关系、属性组成
    • 

  • 构建方法：手动、结构化转换、文本提取、混合

  • 选择支持向量的图数据库便于 RAG 集成
