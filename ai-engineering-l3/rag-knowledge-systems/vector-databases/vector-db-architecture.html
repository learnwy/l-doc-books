向量数据库架构

核心概念

向量数据库（Vector Database）是专门设计用于存储、索引和高效查询高维向量数据的数据库系统。与传统关系型数据库围绕事务处理和 SQL 查询优化不同，向量数据库围绕近似最近邻搜索（ANN）这一核心操作进行全栈优化——从存储引擎到索引结构到查询处理器。

2. 索引层
索引是向量数据库性能的核心。不同的索引类型适用于不同的规模和需求场景。


TypeScript 向量数据库客户端封装
import { QdrantClient } from '@qdrant/js-client-rest';

interface VectorDBConfig {
  url: string;
  collectionName: string;
  vectorSize: number;
  distanceMetric: 'Cosine' | 'Euclid' | 'Dot';
}

interface UpsertPayload {
  id: string;
  vector: number[];
  metadata: Record<string, unknown>;
}

interface SearchOptions {
  vector: number[];
  topK: number;
  scoreThreshold?: number;
  filter?: Record<string, unknown>;
}

class VectorDB {
  private client: QdrantClient;
  private config: VectorDBConfig;

  constructor(config: VectorDBConfig) {
    this.config = config;
    this.client = new QdrantClient({ url: config.url });
  }

  async ensureCollection(): Promise<void> {
    const collections = await this.client.getCollections();
    const exists = collections.collections.some((c) => c.name === this.config.collectionName);

    if (!exists) {
      await this.client.createCollection(this.config.collectionName, {
        vectors: {
          size: this.config.vectorSize,
          distance: this.config.distanceMetric,
        },
        optimizers_config: {
          default_segment_number: 2,
          indexing_threshold: 20000,
        },
        hnsw_config: {
          m: 16,
          ef_construct: 128,
          full_scan_threshold: 10000,
        },
      });
    }
  }

  async upsert(points: UpsertPayload[]): Promise<void> {
    const batchSize = 100;
    for (let i = 0; i < points.length; i += batchSize) {
      const batch = points.slice(i, i + batchSize);
      await this.client.upsert(this.config.collectionName, {
        wait: true,
        points: batch.map((p) => ({
          id: p.id,
          vector: p.vector,
          payload: p.metadata,
        })),
      });
    }
  }

  async search(options: SearchOptions): Promise<
    Array<{
      id: string;
      score: number;
      metadata: Record<string, unknown>;
    }>
  > {
    const results = await this.client.search(this.config.collectionName, {
      vector: options.vector,
      limit: options.topK,
      score_threshold: options.scoreThreshold,
      filter: options.filter,
      with_payload: true,
    });

    return results.map((r) => ({
      id: String(r.id),
      score: r.score,
      metadata: r.payload as Record<string, unknown>,
    }));
  }
}

from qdrant_client import QdrantClient
from qdrant_client.models import (
    Filter,
    FieldCondition,
    MatchValue,
    Range,
    PointStruct,
)

client = QdrantClient(url="http://localhost:6333")

client.upsert(
    collection_name="rag_chunks",
    points=[
        PointStruct(
            id=1,
            vector=[0.1] * 768,
            payload={
                "text": "RAG 系统的核心是检索增强生成",
                "source": "docs/rag-intro.md",
                "category": "architecture",
                "created_at": "2024-01-15",
                "language": "zh",
                "token_count": 256,
            },
        ),
    ],
)

results = client.search(
    collection_name="rag_chunks",
    query_vector=[0.2] * 768,
    query_filter=Filter(
        must=[
            FieldCondition(
                key="category",
                match=MatchValue(value="architecture"),
            ),
            FieldCondition(
                key="language",
                match=MatchValue(value="zh"),
            ),
            FieldCondition(
                key="token_count",
                range=Range(gte=100, lte=1000),
            ),
        ],
    ),
    limit=10,
    with_payload=True,
)

常见误区
❌ 误区 1：向量数据库可以完全替代传统数据库
向量数据库擅长相似度搜索，但不擅长复杂的关系查询、事务处理、聚合分析。生产系统通常需要向量数据库 + 传统数据库协同工作。


❌ 误区 2：所有场景都需要专用向量数据库
小规模场景（<100K 向量）使用 pgvector 或内存中的 FAISS 就足够了。引入专用向量数据库会增加不必要的运维复杂度。


❌ 误区 3：忽视容量规划
向量数据库的内存占用与向量数量和维度成正比。100 万条 768 维 float32 向量就需要 ~3GB 纯向量存储，加上 HNSW 索引可能需要 5-8GB 内存。必须提前做容量规划。


❌ 误区 4：不监控索引健康状况
索引随着数据增长可能退化。需要监控：


    

  • 查询延迟的 P99 趋势
    • 

  • 召回率是否下降
    • 

  • 内存使用率
    • 

  • 索引碎片化程度
    • 



小结
向量数据库的架构设计围绕高性能相似度搜索展开，从存储引擎到索引结构到查询处理器都针对 ANN 操作深度优化。


核心要点回顾：


    

  • 四大核心组件：存储引擎、索引层、查询引擎、元数据过滤
    • 

  • HNSW 是最常用的索引类型，适合大多数场景
    • 

  • 预过滤 vs 后过滤的选择影响查询结果和性能
    • 

  • 分布式架构需要考虑分片策略和一致性模型
    • 

  • 选型要考虑规模、部署方式、混合搜索需求、运维能力
    • 

  • 小规模用 pgvector/FAISS，中大规模用 Qdrant/Weaviate/Milvus
    • 

  • 量化技术（SQ/PQ）可以在牺牲少量精度的前提下大幅降低内存需求
    • 

  • 必须做容量规划和持续的性能监控
