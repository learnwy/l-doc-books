文本分割方法

核心概念

文本分割是将长文档切分成多个短块的过程，是 RAG 系统的关键预处理步骤。

为什么需要文本分割

问题 分割带来的好处
文档太长，超过嵌入模型窗口 每个块在模型窗口内
向量语义不够聚焦 每个块有明确的主题
检索返回整段不相关内容 可以返回精确相关的块
上下文太长，LLM 无法处理 只给 LLM 最相关的几个块

基础分割方法

1. 按字符数分割

核心思想：固定每个块的字符数，最简单的方法。

原始文档: "这是一段很长的文本，我们需要将它切分成多个块..."
分割结果:
  块 1: "这是一段很长的文本，我们需要将它切..."
  块 2: "分成多个块..."
优点 缺点
实现简单 容易切断句子
块大小可控 语义可能不完整
速度极快 检索效果差

适用场景：快速原型、对效果要求不高。

2. 按换行符分割

核心思想：利用文档的自然换行结构。

原始文档:
第一段文本。
第二段文本。
第三段文本。

分割结果:
  块 1: "第一段文本。"
  块 2: "第二段文本。"
  块 3: "第三段文本。"
优点 缺点
保持句子完整 块大小差异大
语义相对完整 可能块太小或太大
实现简单 对无格式文档效果差

适用场景：格式化良好的文档、段落清晰。

3. 按句子分割

核心思想：利用标点符号（。！？.!?）找到句子边界。





优点
缺点





保持语义单元
引号、缩写可能误判




块更有意义
需要语言知识




效果通常不错
实现稍复杂





适用场景：通用场景、大多数 RAG 应用的起点。


4. 按段落分割
核心思想：利用空行、标题等结构识别段落。


原始文档:
## 第一章
这是第一章的内容。

## 第二章
这是第二章的内容。

分割结果:
  块 1: "## 第一章\n这是第一章的内容。"
  块 2: "## 第二章\n这是第二章的内容。"




优点
缺点





保持文档结构
需要格式化文档




语义最完整
可能块太大




结合标题，检索效果好
对纯文本效果差





适用场景：Markdown、HTML 等结构化文档。


高级分割方法
1. 递归字符分割 (Recursive Character Splitting)
核心思想：按优先级尝试不同的分隔符，直到块大小合适。


分隔符优先级: ["\n\n", "\n", "。", "！", "？", " "]
工作流程:


    

  1. 先用双换行分割

  2. 如果块太大，用单换行分割
    3. 

  3. 如果还太大，用句号分割
    4. 

  4. 继续直到所有块在目标大小范围内
    5. 







优点
缺点





结合了多种方法
需要调优分隔符顺序




灵活性高
实现较复杂




效果通常很好
速度稍慢





适用场景：生产级应用、LangChain 等框架的默认方法。


2. 重叠窗口 (Sliding Window)
核心思想：块之间有重叠，避免重要信息被切断。


原始文本: [A B C D E F G H]
窗口大小=4, 重叠=2:
  块 1: [A B C D]
  块 2: [C D E F]
  块 3: [E F G H]




优点
缺点





避免信息丢失
增加存储成本




提升召回率
增加计算成本




边界处效果好
可能有重复内容





适用场景：对召回率要求高、不介意一些重复。


3. 内容感知分割
核心思想：结合文档类型的特定知识。






文档类型
分割策略





代码
按函数、类、文件




论文
按摘要、引言、方法、结果




对话
按轮次、按主题




表格
按行、按相关行组





适用场景：特定类型的文档、领域专业应用。

常见误区
❌ 误区 1：块越小越好
块太小反而效果差:


    

  • 上下文不完整
    • 

  • 语义不连贯
    • 

  • LLM 难以理解
    • 



❌ 误区 2：块越大越好
块太大也有问题:


    

  • 超过嵌入窗口
    • 

  • 向量语义不聚焦
    • 

  • 给 LLM 的上下文太多
    • 



❌ 误区 3：从不调优分割策略
默认配置不是万能的:


    

  • 不同文档需要不同策略
    • 

  • 先做 A/B 测试
    • 

  • 定期评估效果
    • 



小结
    

  • 递归字符分割是通用起点
    • 

  • 重叠窗口提升召回率
    • 

  • 不同文档用不同策略
    • 

  • 先做 A/B 测试
    • 

  • 平衡块大小和语义完整性
    •
