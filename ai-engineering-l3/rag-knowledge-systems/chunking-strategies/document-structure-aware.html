文档结构感知

核心概念

文档结构感知分块是利用文档的固有结构（标题、章节、列表、表格等）来指导分割的方法。与纯文本分割不同，结构感知方法能保持语义完整性，因为文档的结构本身就编码了内容的组织逻辑——标题划定了主题边界，列表和表格是不可拆分的信息单元。

为什么文档结构重要

无结构分块 结构感知分块
可能切断章节 在章节边界分割
忽略标题信息 标题作为元数据
无法利用层次 保持文档层次
效果不稳定 效果通常更好
上下文碎片化 语义完整性高

常见文档结构

1. Markdown 结构

# 一级标题

## 二级标题

### 三级标题

正文内容

- 列表项 1
- 列表项 2

分割策略:

  • 在标题级别变化处分割
  • 标题作为块的一部分
  • 同一标题下的内容合并
  • 列表保持完整

适用场景: 绝大多数技术文档、笔记。

2. HTML 结构

<h1>一级标题</h1>
<h2>二级标题</h2>
<p>段落</p>
<ul>
  <li>列表项</li>
</ul>

分割策略:

  • 利用 <h1>-<h6> 标签
  • 利用 <article>、<section> 语义标签
  • 保持表格、代码块完整
  • 提取元数据（作者、日期等）

适用场景: 网页内容、HTML 文档。

3. 代码文件结构

class MyClass:
    def method1(self):
        pass

def function1():
    pass

分割策略:

  • 按函数、类分割
  • 保持函数/类完整
  • 相关函数可以合并
  • 保留导入语句

适用场景: 代码文档、代码库知识库。

4. PDF 文档结构

挑战:

  • PDF 本质是渲染格式，不是结构化格式
  • 需要先提取文本和结构
  • 表格、图片处理复杂

分割策略:

  • 用工具（PyMuPDF、pdfplumber）提取结构
  • 识别标题（字体大小、样式）
  • 处理页眉页脚
  • 保持表格完整性

适用场景: PDF 格式的白皮书、论文。

常见误区
❌ 误区 1：忽略文档结构
有结构不用是浪费:


    

  • 效果变差
    • 

  • 错过元数据
    • 

  • 检索质量下降
    • 



❌ 误区 2：过度依赖自动解析
自动解析不完美:


    

  • 可能解析错误
    • 

  • 需要人工校验
    • 

  • 混合文档需要特殊处理
    • 



❌ 误区 3：所有文档用同一策略
不同文档不同策略:


    

  • 技术文档 vs 小说（结构化程度差异大）
    • 

  • Markdown vs PDF（解析难度不同）
    • 

  • 代码 vs 散文（语义单元粒度不同）
    • 

  • 表格密集文档需要特殊处理，保持行列完整性
    • 

  • 混合文档（图文、代码 + 文字）需要多策略协同
    •
