高级 RAG 模式

核心概念

高级 RAG 模式是在 Naive RAG 基础上添加各种优化技术，提升效果和可靠性。Naive RAG 的"检索-拼接-生成"流程简单但粗糙，面对真实场景中的模糊查询、噪声文档和长上下文问题往往力不从心。高级 RAG 通过在检索前（查询变换）、检索中（重排序）和检索后（上下文压缩、引用、自校验）三个环节引入优化策略，系统性地提升端到端答案质量。

为什么需要高级 RAG

Naive RAG 的局限 高级 RAG 的优化
检索可能不准确 查询变换、重排
容易产生幻觉 检索校验、引用
上下文有限 压缩、选择性使用
无法处理复杂查询 查询分解、多步检索

常见高级 RAG 技术

1. 查询变换 (Query Transformation)

详见 Chapter 04，常见方法：

  • 查询重写
  • 查询扩展
  • 查询分解
  • 多查询生成

收益:

  • 提升召回率
  • 处理口语化查询
  • 覆盖更多角度

2. 重排 (Reranking)

详见 Chapter 04，常见方法：

  • Cross-Encoder
  • LLM 重排
  • 混合重排

收益:

  • 提升检索精度
  • 更好的排序
  • 更相关的上下文

3. 上下文压缩 (Context Compression)

核心思想: 压缩检索到的文档，只保留最相关的部分。

常见方法:


    

  • LLM 提取关键信息：使用小模型从每个文档块中抽取与查询最相关的句子
    • 

  • Embedding 过滤句子：计算每个句子与查询的相似度，过滤掉低相关的句子
    • 

  • 摘要：对长文档生成查询导向的摘要
    • 



收益:


    

  • 节省 LLM 上下文窗口，允许使用更多检索结果
    • 

  • 去除无关噪声信息，提升答案聚焦度
    • 

  • 降低 Token 消耗，节约成本
    • 



4. 引用与溯源 (Citations)
核心思想: 让 LLM 在答案中标注信息来源。


提示词示例:


请根据以下上下文回答问题，并在答案中标注引用来源（如 [1]、[2]）。

上下文：
[1] {doc1}
[2] {doc2}

问题：{query}

答案（带引用）：
收益:


    

  • 减少幻觉
    • 

  • 可验证答案
    • 

  • 提升可信度
    • 



5. 自我校验 (Self-Correction)
核心思想: LLM 生成答案后，自己检查是否正确。


收益:


    

  • 减少错误答案
    • 

  • 提升可靠性
    • 

  • 自动修复
    • 



6. 多步检索 (Multi-Step Retrieval)
核心思想: 第一次检索的结果作为第二次检索的输入，逐步缩小范围、提升精度。


示例:


    

  1. 查询: "Python 3.11 的新特性"
    2. 

  2. 第一次检索: 找到 Python 3.11 相关文档
    3. 

  3. 从文档中提取关键词: "asyncio", "typing", "performance"
    4. 

  4. 第二次检索: 用这些关键词更精确地检索
    5. 

  5. 合并结果，生成答案
    6. 



多步检索在处理模糊查询或需要多维度信息的场景中特别有效。每一步检索都会收窄搜索范围，使最终的上下文更加精准。典型的实现方式是将 LLM 作为中间协调器，由它决定是否需要进一步检索以及使用什么查询。


收益:


    

  • 更精确的检索
    • 

  • 可以探索相关主题
    • 

  • 处理复杂查询
    •

监控高级 RAG
监控是高级 RAG 运维的基础，需要关注以下关键指标：


    

  • 检索准确率（Recall@k 和 Precision@k 的变化趋势）
    • 

  • 答案满意度（用户反馈评分或隐式信号）
    • 

  • 引用准确率（引用的文档是否确实支持答案中的论断）
    • 

  • 幻觉率（答案中无法追溯到检索文档的内容占比）
    • 

  • 成本变化（每次查询消耗的 Token 数和 API 调用次数）
    • 

  • 延迟变化（端到端响应时间的 P50、P95 和 P99）
    • 



小结
    

  • 从 Naive RAG 开始，逐步升级
    • 

  • 查询变换和重排是最常用的优化
    • 

  • 引用和自我校验提升可信度
    • 

  • 根据问题选择合适的技术
    • 

  • 权衡效果、成本、实现难度
