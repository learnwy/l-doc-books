相似度搜索

核心概念

相似度搜索（Similarity Search）是向量检索的核心操作：给定一个查询向量，在向量数据库中找到与其最相似的 K 个向量。在 RAG 系统中，相似度搜索的质量直接决定了哪些文档块会被送入 LLM——这是整个管道中信息损失最大的一个环节。

相似度的数学本质

在向量空间中，"语义相似"被转化为"几何距离近"。相似度度量定义了向量空间的拓扑结构，不同的度量方式会产生不同的搜索结果。

相似度计算方法深度解析
余弦相似度（Cosine Similarity）
余弦相似度衡量的是两个向量之间夹角的余弦值，只关注方向不关注长度。这使得它天然具备长度不变性——一段话说得长和说得短，只要语义方向一致，相似度就高。


数学定义：


cos(θ) = (A · B) / (||A|| × ||B||)

欧氏距离（Euclidean Distance）
欧氏距离衡量的是两个向量在空间中的绝对距离。与余弦相似度不同，它对向量的长度（模）敏感。


数学定义：


d(A, B) = sqrt(Σ(Ai - Bi)²)
内积 / 点积（Dot Product / Inner Product）
内积同时考虑了方向和长度。当向量已经归一化（L2 范数为 1）后，内积等价于余弦相似度。


数学定义：


A · B = Σ(Ai × Bi)

TypeScript 实现三种度量
interface SimilarityMetrics {
  cosine: number;
  euclidean: number;
  dotProduct: number;
}

function computeAllMetrics(a: number[], b: number[]): SimilarityMetrics {
  let dot = 0;
  let normA = 0;
  let normB = 0;
  let eucSq = 0;

  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
    eucSq += (a[i] - b[i]) ** 2;
  }

  return {
    cosine: dot / (Math.sqrt(normA) * Math.sqrt(normB)),
    euclidean: Math.sqrt(eucSq),
    dotProduct: dot,
  };
}

function findTopK(
  query: number[],
  vectors: number[][],
  k: number,
  metric: 'cosine' | 'euclidean' | 'dotProduct' = 'cosine',
): Array<{ index: number; score: number }> {
  const scores = vectors.map((vec, idx) => {
    const metrics = computeAllMetrics(query, vec);
    return { index: idx, score: metrics[metric] };
  });

  if (metric === 'euclidean') {
    scores.sort((a, b) => a.score - b.score);
  } else {
    scores.sort((a, b) => b.score - a.score);
  }

  return scores.slice(0, k);
}
Python SIMD 优化实现
import numpy as np
from typing import Literal

def batch_similarity(
    query: np.ndarray,
    corpus: np.ndarray,
    metric: Literal["cosine", "euclidean", "dot"] = "cosine",
) -> np.ndarray:
    if metric == "dot":
        return corpus @ query

    if metric == "cosine":
        query_norm = query / np.linalg.norm(query)
        corpus_norms = corpus / np.linalg.norm(corpus, axis=1, keepdims=True)
        return corpus_norms @ query_norm

    if metric == "euclidean":
        diff = corpus - query[np.newaxis, :]
        return -np.sqrt(np.sum(diff ** 2, axis=1))

    raise ValueError(f"Unknown metric: {metric}")

def search_with_threshold(
    query: np.ndarray,
    corpus: np.ndarray,
    top_k: int = 10,
    threshold: float = 0.7,
    metric: Literal["cosine", "euclidean", "dot"] = "cosine",
) -> list[tuple[int, float]]:
    scores = batch_similarity(query, corpus, metric)
    top_indices = np.argsort(scores)[::-1]

    results = []
    for idx in top_indices:
        score = float(scores[idx])
        if metric == "euclidean" and score < -threshold:
            break
        if metric != "euclidean" and score < threshold:
            break
        results.append((int(idx), score))
        if len(results) >= top_k:
            break

    return results

检索质量优化
影响检索质量的因素矩阵
混合检索策略
单一的向量检索可能遗漏关键词精确匹配的结果。混合检索结合稠密向量搜索和稀疏词汇搜索的优势：


interface SearchResult {
  id: string;
  text: string;
  denseScore: number;
  sparseScore: number;
  hybridScore: number;
}

function hybridSearch(
  denseResults: Array<{ id: string; score: number }>,
  sparseResults: Array<{ id: string; score: number }>,
  alpha: number = 0.7,
  topK: number = 10,
): SearchResult[] {
  const scoreMap = new Map<string, { dense: number; sparse: number }>();

  for (const r of denseResults) {
    scoreMap.set(r.id, { dense: r.score, sparse: 0 });
  }

  for (const r of sparseResults) {
    const existing = scoreMap.get(r.id) || { dense: 0, sparse: 0 };
    existing.sparse = r.score;
    scoreMap.set(r.id, existing);
  }

  const results: SearchResult[] = [];
  for (const [id, scores] of scoreMap) {
    results.push({
      id,
      text: '',
      denseScore: scores.dense,
      sparseScore: scores.sparse,
      hybridScore: alpha * scores.dense + (1 - alpha) * scores.sparse,
    });
  }

  results.sort((a, b) => b.hybridScore - a.hybridScore);
  return results.slice(0, topK);
}
Python 完整检索管道
import numpy as np
from dataclasses import dataclass, field

@dataclass
class RetrievalConfig:
    top_k: int = 20
    similarity_threshold: float = 0.7
    use_mmr: bool = True
    mmr_lambda: float = 0.7
    rerank: bool = True

@dataclass
class RetrievalResult:
    chunk_id: str
    text: str
    score: float
    metadata: dict = field(default_factory=dict)

def maximal_marginal_relevance(
    query_embedding: np.ndarray,
    candidate_embeddings: np.ndarray,
    candidate_ids: list[str],
    k: int = 10,
    lambda_param: float = 0.7,
) -> list[int]:
    query_sim = np.dot(candidate_embeddings, query_embedding)

    selected = []
    remaining = list(range(len(candidate_ids)))

    first = int(np.argmax(query_sim))
    selected.append(first)
    remaining.remove(first)

    while len(selected) < k and remaining:
        best_score = -np.inf
        best_idx = -1

        for idx in remaining:
            relevance = query_sim[idx]

            max_sim_to_selected = max(
                np.dot(candidate_embeddings[idx], candidate_embeddings[s])
                for s in selected
            )

            mmr_score = lambda_param * relevance - (1 - lambda_param) * max_sim_to_selected

            if mmr_score > best_score:
                best_score = mmr_score
                best_idx = idx

        selected.append(best_idx)
        remaining.remove(best_idx)

    return selected

def retrieve(
    query_vec: np.ndarray,
    corpus_vecs: np.ndarray,
    corpus_texts: list[str],
    config: RetrievalConfig,
) -> list[RetrievalResult]:
    similarities = np.dot(corpus_vecs, query_vec)

    above_threshold = np.where(similarities >= config.similarity_threshold)[0]

    top_indices = np.argsort(similarities[above_threshold])[::-1][:config.top_k * 2]
    candidate_indices = above_threshold[top_indices]

    if config.use_mmr:
        mmr_indices = maximal_marginal_relevance(
            query_vec,
            corpus_vecs[candidate_indices],
            [str(i) for i in candidate_indices],
            k=config.top_k,
            lambda_param=config.mmr_lambda,
        )
        final_indices = candidate_indices[mmr_indices]
    else:
        final_indices = candidate_indices[:config.top_k]

    return [
        RetrievalResult(
            chunk_id=str(idx),
            text=corpus_texts[idx],
            score=float(similarities[idx]),
        )
        for idx in final_indices
    ]

调优方法论
常见误区
❌ 误区 1：只看 Top-1 结果
RAG 需要多个文档块交叉验证，Top-1 可能恰好不是最佳答案：


    

  • 通常返回 Top-5~20，让重排器和 LLM 综合判断
    • 

  • 不同查询的最佳 K 值不同，可以用动态 K 策略
    • 

  • 结合 MMR 增加多样性，避免返回重复内容
    • 



❌ 误区 2：不设置相似度阈值
没有阈值会返回完全不相关的低分文档，污染 LLM 上下文：


    

  • 余弦相似度 0.7 是通用的保守起点
    • 

  • 不同嵌入模型的分数分布不同，必须针对具体模型调整
    • 

  • 可以用动态阈值：根据 Top-1 分数按比例设定（如 Top-1 × 0.8）
    • 



❌ 误区 3：认为 ANN 不够准确
现代 ANN 算法（尤其 HNSW）的召回率非常接近精确搜索：


    

  • 合理配置的 HNSW 召回率 >99%，几乎无感知精度损失
    • 

  • 对 RAG 来说，5% 的精度损失远不如 100 倍的速度提升重要
    • 

  • 真正影响检索质量的是嵌入模型和分块策略，而非 ANN 算法
    • 



❌ 误区 4：忽视预过滤和后过滤的区别
元数据过滤有两种模式，效果截然不同：


    

  • 预过滤（Pre-filtering）：先按元数据过滤，再在子集中向量搜索。保证结果都满足过滤条件，但可能候选太少影响质量
    • 

  • 后过滤（Post-filtering）：先向量搜索 Top-K，再过滤不满足条件的。可能返回不足 K 条结果
    • 

  • 推荐策略：预过滤 + 适当扩大 K 值
    • 



小结
相似度搜索是 RAG 检索管道的核心引擎，理解不同的距离度量、ANN 算法和优化策略是构建高质量检索系统的基础。


核心要点回顾：


    

  • 余弦相似度是 RAG 场景的默认选择，归一化后等价于内积
    • 

  • HNSW 是当前最推荐的 ANN 算法，适用于绝大多数 RAG 场景
    • 

  • 混合检索（稠密 + 稀疏）能有效弥补纯向量搜索的不足
    • 

  • MMR 算法在保持相关性的同时增加结果多样性
    • 

  • 索引参数（M、ef_construction、ef_search）需要基于评估数据集调优
    • 

  • 设置合理的相似度阈值，避免低质量结果污染 LLM 上下文
    • 

  • 预过滤 vs 后过滤的选择影响检索结果的完整性
    •
