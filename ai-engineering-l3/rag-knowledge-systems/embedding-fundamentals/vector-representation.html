向量表示

核心概念

向量表示（Vector Representation）是将非结构化数据——文本、图像、音频、视频——映射到高维数值向量空间的技术。它是整个 RAG 系统的数学基石，没有高质量的向量表示，后续的检索、排序、生成都无从谈起。

向量表示的核心假设源自分布式语义假说（Distributional Hypothesis）：在相似上下文中出现的词具有相似的含义。这一假设延伸到句子和文档级别后，就成为了现代语义搜索的理论基础——语义相似的内容在向量空间中距离更近。

为什么向量表示对 RAG 至关重要
传统关键词搜索（如 BM25）依赖词面匹配，存在"词汇鸿沟"（Lexical Gap）问题。向量表示从根本上解决了这个问题：


    

  • 同义词理解："猫咪"和"猫科动物"在向量空间中高度接近
    • 

  • 语义泛化：查询"如何提升系统性能"能匹配到"优化服务响应速度"
    • 

  • 跨语言检索：中文查询可以检索到语义相关的英文文档
    • 

  • 零样本迁移：对从未见过的领域概念，依然能产生合理的向量表示
    • 

  • 统一表示：文本、代码、表格等不同形态的数据共享同一个向量空间
    •

TypeScript 实现示例
import { pipeline } from '@xenova/transformers';

interface EmbeddingResult {
  text: string;
  vector: number[];
  dimension: number;
  norm: number;
}

async function createEmbedding(text: string): Promise<EmbeddingResult> {
  const extractor = await pipeline('feature-extraction', 'Xenova/all-MiniLM-L6-v2');

  const output = await extractor(text, {
    pooling: 'mean',
    normalize: true,
  });

  const vector = Array.from(output.data as Float32Array);
  const norm = Math.sqrt(vector.reduce((sum, v) => sum + v * v, 0));

  return {
    text,
    vector,
    dimension: vector.length,
    norm,
  };
}

function cosineSimilarity(a: number[], b: number[]): number {
  let dotProduct = 0;
  let normA = 0;
  let normB = 0;
  for (let i = 0; i < a.length; i++) {
    dotProduct += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
  }
  return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB));
}

async function demonstrateSemanticSimilarity() {
  const sentences = ['机器学习是人工智能的核心分支', '深度学习推动了 AI 技术的突破', '今天天气真不错'];

  const embeddings = await Promise.all(sentences.map(createEmbedding));

  for (let i = 0; i < embeddings.length; i++) {
    for (let j = i + 1; j < embeddings.length; j++) {
      const sim = cosineSimilarity(embeddings[i].vector, embeddings[j].vector);
      console.log(`"${sentences[i]}" vs "${sentences[j]}": ${sim.toFixed(4)}`);
    }
  }
}
Python 实现示例
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("BAAI/bge-base-zh-v1.5")

def embed_texts(texts: list[str]) -> np.ndarray:
    embeddings = model.encode(
        texts,
        normalize_embeddings=True,
        show_progress_bar=False,
        batch_size=32,
    )
    return embeddings

def find_most_similar(
    query: str,
    corpus: list[str],
    top_k: int = 5,
) -> list[tuple[int, float, str]]:
    query_vec = embed_texts([query])
    corpus_vecs = embed_texts(corpus)

    similarities = np.dot(corpus_vecs, query_vec.T).flatten()
    top_indices = np.argsort(similarities)[::-1][:top_k]

    return [
        (int(idx), float(similarities[idx]), corpus[idx])
        for idx in top_indices
    ]

corpus = [
    "向量数据库是存储和检索高维向量的专用系统",
    "RAG 通过检索外部知识来增强大语言模型的回答",
    "Transformer 架构引入了自注意力机制",
    "分布式系统需要处理网络分区和一致性问题",
    "嵌入模型将文本映射到连续向量空间",
]

results = find_most_similar("如何存储文本的语义表示", corpus, top_k=3)
for idx, score, text in results:
    print(f"[{score:.4f}] {text}")

Matryoshka 表示学习
Matryoshka Representation Learning（MRL）是一种新的训练方式，允许一个模型输出多种维度的有效向量。核心思想是让向量的前 k 维就包含足够的语义信息：


这种方式的实际优势在于：可以用同一模型灵活适配不同场景的精度-成本需求，无需重新训练多个模型。

向量归一化的数学意义
function l2Normalize(vector: number[]): number[] {
  const norm = Math.sqrt(vector.reduce((sum, v) => sum + v * v, 0));
  if (norm === 0) return vector;
  return vector.map((v) => v / norm);
}

function demonstrateNormalization() {
  const raw = [3.0, 4.0];
  const normalized = l2Normalize(raw);

  const normBefore = Math.sqrt(raw.reduce((s, v) => s + v * v, 0));
  const normAfter = Math.sqrt(normalized.reduce((s, v) => s + v * v, 0));

  console.log(`归一化前范数: ${normBefore}`);
  console.log(`归一化后范数: ${normAfter}`);
  console.log(`方向不变: ${raw[0] / raw[1] === normalized[0] / normalized[1]}`);
}
归一化后，余弦相似度退化为向量点积，计算速度大幅提升。大多数向量数据库在入库时自动执行 L2 归一化。

元数据与向量的协同
向量不是孤立存储的，与元数据的结合是生产级 RAG 系统的标配：


interface VectorRecord {
  id: string;
  vector: number[];
  metadata: {
    text: string;
    source: string;
    chunkIndex: number;
    totalChunks: number;
    createdAt: string;
    language: string;
    category: string;
    tokenCount: number;
  };
}

function createVectorRecord(
  text: string,
  vector: number[],
  source: string,
  chunkIndex: number,
  totalChunks: number,
): VectorRecord {
  return {
    id: `${source}_chunk_${chunkIndex}`,
    vector,
    metadata: {
      text,
      source,
      chunkIndex,
      totalChunks,
      createdAt: new Date().toISOString(),
      language: detectLanguage(text),
      category: classifyContent(text),
      tokenCount: estimateTokens(text),
    },
  };
}
元数据的价值在于支持混合检索——先用元数据过滤缩小搜索范围，再用向量相似度精确匹配，这比纯向量检索效率高数倍。

常见误区
❌ 误区 1：向量维度越高越好
维度翻倍并不意味着效果翻倍。实际上存在边际递减效应：


    

  • 从 384→768 维：精度提升 ~8-12%
    • 

  • 从 768→1536 维：精度提升 ~3-5%
    • 

  • 从 1536→3072 维：精度提升 ~1-2%
    • 



但存储、计算、索引构建时间都是线性增长的。在 768-1024 维度区间内选择是大多数 RAG 应用的最优策略。


❌ 误区 2：所有数据用同一个嵌入模型
不同类型的数据适合不同的嵌入模型：


    

  • 代码 → CodeBERT、StarCoder Embeddings
    • 

  • 多语言文本 → multilingual-e5-large、BGE-M3
    • 

  • 结构化表格 → 先转换为自然语言描述再嵌入
    • 

  • 医学/法律文本 → 领域微调后的嵌入模型
    • 



混用不匹配的模型会导致跨类型检索效果急剧下降。


❌ 误区 3：嵌入一次就不再更新
知识库内容在变化，嵌入模型在进步，嵌入需要持续维护：


    

  • 文档内容修改时，对应向量必须重新生成
    • 

  • 模型升级时，全量重嵌入（注意新旧模型向量空间不兼容）
    • 

  • 定期用评估集检查检索质量是否衰退
    • 



❌ 误区 4：忽视查询与文档的不对称性
用户查询通常是短文本，而文档块是长文本。某些嵌入模型（如 E5、BGE）要求对查询和文档使用不同的指令前缀。忽视这一点会导致显著的精度下降。


小结
向量表示是 RAG 系统的数学基石，将语义信息编码为可计算的数值形式。从词嵌入到上下文嵌入再到专用嵌入模型，向量表示技术经历了三代演进，能力持续增强。


核心要点回顾：


    

  • 向量表示的本质是语义的几何化——将"意思相近"转化为"距离相近"
    • 

  • 维度选择需要权衡精度、成本和速度，768-1024 是大多数场景的甜区
    • 

  • 池化策略（Mean Pooling 为主流）和归一化是从 Transformer 输出到最终向量的关键步骤
    • 

  • 元数据与向量协同使用，支持高效的混合过滤检索
    • 

  • 大规模场景需关注量化压缩（FP16、INT8、PQ）
    • 

  • 不同数据类型、不同语言应选择对应的专用嵌入模型
    •
