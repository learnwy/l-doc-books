嵌入模型

核心概念

嵌入模型（Embedding Model）是将文本转换为稠密向量表示的神经网络，是 RAG 系统的"语义引擎"。嵌入模型的质量直接决定了检索精度的上限——即使后续的重排序、提示工程再精妙，如果嵌入模型在第一步就漏掉了相关文档，整个管道的效果都会受限。

模型架构原理

现代嵌入模型基于 Transformer 编码器架构，通过对比学习（Contrastive Learning）训练。训练目标是让语义相似的文本对在向量空间中距离更近，不相似的更远。

TypeScript 模型调用示例
import OpenAI from 'openai';

interface EmbeddingConfig {
  model: string;
  dimensions?: number;
  batchSize: number;
}

const CONFIGS: Record<string, EmbeddingConfig> = {
  highPrecision: {
    model: 'text-embedding-3-large',
    dimensions: 1536,
    batchSize: 100,
  },
  balanced: {
    model: 'text-embedding-3-small',
    batchSize: 200,
  },
  costEffective: {
    model: 'text-embedding-3-small',
    dimensions: 512,
    batchSize: 500,
  },
};

class EmbeddingService {
  private client: OpenAI;
  private config: EmbeddingConfig;
  private cache: Map<string, number[]> = new Map();

  constructor(config: EmbeddingConfig) {
    this.client = new OpenAI();
    this.config = config;
  }

  async embedBatch(texts: string[]): Promise<number[][]> {
    const uncached: string[] = [];
    const results: Map<string, number[]> = new Map();

    for (const text of texts) {
      const cached = this.cache.get(text);
      if (cached) {
        results.set(text, cached);
      } else {
        uncached.push(text);
      }
    }

    for (let i = 0; i < uncached.length; i += this.config.batchSize) {
      const batch = uncached.slice(i, i + this.config.batchSize);
      const response = await this.client.embeddings.create({
        model: this.config.model,
        input: batch,
        dimensions: this.config.dimensions,
      });

      for (let j = 0; j < batch.length; j++) {
        const vec = response.data[j].embedding;
        this.cache.set(batch[j], vec);
        results.set(batch[j], vec);
      }
    }

    return texts.map((t) => results.get(t)!);
  }
}
Python 多模型对比评估
from sentence_transformers import SentenceTransformer
import numpy as np
from dataclasses import dataclass

@dataclass
class EvalResult:
    model_name: str
    hit_rate_at_5: float
    mrr_at_10: float
    avg_latency_ms: float
    dimension: int

def evaluate_model(
    model_name: str,
    queries: list[str],
    corpus: list[str],
    relevant_ids: dict[int, list[int]],
) -> EvalResult:
    model = SentenceTransformer(model_name)

    import time
    start = time.time()
    corpus_embeddings = model.encode(corpus, normalize_embeddings=True, batch_size=64)
    query_embeddings = model.encode(queries, normalize_embeddings=True, batch_size=64)
    latency = (time.time() - start) / len(queries) * 1000

    similarities = np.dot(query_embeddings, corpus_embeddings.T)

    hit_count = 0
    mrr_sum = 0.0

    for i, query_sims in enumerate(similarities):
        top_indices = np.argsort(query_sims)[::-1][:10]
        top5 = set(top_indices[:5].tolist())
        relevant = set(relevant_ids[i])

        if top5 & relevant:
            hit_count += 1

        for rank, idx in enumerate(top_indices, 1):
            if idx in relevant:
                mrr_sum += 1.0 / rank
                break

    return EvalResult(
        model_name=model_name,
        hit_rate_at_5=hit_count / len(queries),
        mrr_at_10=mrr_sum / len(queries),
        avg_latency_ms=latency,
        dimension=corpus_embeddings.shape[1],
    )

models_to_compare = [
    "BAAI/bge-small-zh-v1.5",
    "BAAI/bge-base-zh-v1.5",
    "BAAI/bge-large-zh-v1.5",
]

for model_name in models_to_compare:
    result = evaluate_model(model_name, queries, corpus, relevant_ids)
    print(f"{result.model_name}: HR@5={result.hit_rate_at_5:.3f} "
          f"MRR@10={result.mrr_at_10:.3f} "
          f"Latency={result.avg_latency_ms:.1f}ms "
          f"Dim={result.dimension}")

Python 微调示例
from sentence_transformers import (
    SentenceTransformer,
    InputExample,
    losses,
)
from torch.utils.data import DataLoader

base_model = SentenceTransformer("BAAI/bge-base-zh-v1.5")

train_examples = [
    InputExample(
        texts=[
            "RAG 系统如何选择分块大小",
            "分块大小优化需要考虑嵌入模型的最大窗口和文档类型",
            "数据库索引可以提升查询性能",
        ]
    ),
    InputExample(
        texts=[
            "向量数据库的分布式架构",
            "Milvus 支持分片和副本的分布式部署模式",
            "Python 是一种编程语言",
        ]
    ),
]

train_dataloader = DataLoader(train_examples, shuffle=True, batch_size=16)

train_loss = losses.TripletLoss(
    model=base_model,
    distance_metric=losses.TripletDistanceMetric.COSINE,
    triplet_margin=0.2,
)

base_model.fit(
    train_objectives=[(train_dataloader, train_loss)],
    epochs=3,
    warmup_steps=100,
    output_path="./finetuned-bge-rag",
    show_progress_bar=True,
)

finetuned = SentenceTransformer("./finetuned-bge-rag")

常见误区
❌ 误区 1：盲目追求 MTEB 排行榜第一
MTEB 是综合评测，排名高不等于在你的场景下效果好：


    

  • 不同任务权重不同，你的场景可能只关心 Retrieval
    • 

  • 测试数据分布与你的业务数据可能差异很大
    • 

  • 必须用自己的数据做 A/B 测试，至少准备 100-200 条标注数据
    • 



❌ 误区 2：忽视指令前缀
BGE 和 E5 系列模型要求对查询添加特定前缀：


    

  • BGE: 查询添加 "Represent this sentence: "
    • 

  • E5: 查询添加 "query: "，文档添加 "passage: "
    • 

  • 不添加前缀可能导致 5-15% 的精度下降
    • 



❌ 误区 3：模型选定后不再评估
嵌入模型领域进步很快，每季度都有新模型发布：


    

  • 每季度用评估集重新对比一次
    • 

  • 关注 BGE、E5 等系列的版本更新
    • 

  • 模型切换时需要全量重嵌入，提前规划迁移方案
    • 



❌ 误区 4：忽视嵌入模型与分块策略的耦合
嵌入模型的最大 Token 窗口直接约束分块大小：


    

  • BGE-base（512 Token 窗口）→ 分块不超过 400 Token
    • 

  • OpenAI 3-small（8191 Token 窗口）→ 分块可以更大
    • 

  • 换模型时必须重新评估分块策略
    • 



小结
嵌入模型是 RAG 系统检索精度的关键决定因素。模型选择不是看排行榜，而是看你的实际场景——语言分布、部署约束、成本预算、精度需求、文本长度。


核心要点回顾：


    

  • 商用 API（OpenAI 3-small/large）精度高、使用简单，但有隐私和成本考量
    • 

  • 开源模型（BGE、E5、GTE）免费自建，中文场景 BGE-large-zh 是标杆
    • 

  • BGE-M3 是目前最全面的开源模型，支持稠密/稀疏/多向量三种检索
    • 

  • 微调能显著提升领域效果，LoRA 是大模型微调的高效选择
    • 

  • 必须用自己的数据做 A/B 测试，不要盲目跟风排行榜
    • 

  • 注意指令前缀、模型窗口大小、分块策略的耦合关系
    • 

  • 部署时考虑缓存、批量、分层路由等成本优化策略
    •
