权益模型与策略决策

核心概念

权益不是“用户订阅是否 active”的别名，而是某个主体在特定上下文中能否使用某项功能以及可使用多少的可解释契约。订阅、企业合同、试用、人工赠送和风险封禁都可能影响最终决定，因此应用代码不应散落读取计费表后自行拼条件。

Stripe Entitlements 文档把产品功能映射为 active entitlements，并建议把权益持久化到内部系统以加快决策。OpenMeter 的权益说明进一步区分布尔、静态和计量权益。供应商对象可以作为输入，但内部策略决策仍需拥有自己的版本、失败偏好和审计记录。

flowchart LR
    R[访问请求] --> C[决策上下文]
    S[权益快照] --> P[策略引擎]
    U[已用量与预留] --> P
    C --> P
    P --> D{决策}
    D -->|allow| A[执行功能]
    D -->|deny| N[拒绝与原因]
    D -->|degrade| G[降级能力]
    P --> L[决策审计]
权益类型 例子 决策输入
布尔权益 可访问高级模型 功能键与有效区间
静态数量权益 最多 20 个成员 配置上限与当前资源数
计量权益 每月 100 万 token 周期额度、已用量、预留量
分层能力 高峰期只允许基础模型 资源状态与降级策略
合同例外 企业客户超额仍可用 客户覆盖规则与审批版本

同章的配额与预留处理并发数量，本节专注如何表达和执行政策。

领域对象与所有权边界

Feature 是稳定业务能力键，例如 agent.execute；EntitlementGrant 表示来源、数量或布尔值、有效区间和优先级；EntitlementSnapshot 是某主体在一个修订上的已解析结果；PolicyDecision 是一次请求的输出。产品目录拥有功能与套餐映射，合同系统拥有例外，计量系统提供用量，策略服务负责合并并决策。

供应商的 product、subscription 或 active entitlement 通过反腐层转换成内部 EntitlementGrant，不直接泄漏到业务服务。这样更换计费供应商或同时服务企业合同不会迫使每个调用方理解外部生命周期。

每个 grant 都有不可变来源和版本。撤销通过结束有效区间或追加撤销记录，不删除历史。Snapshot 记录所含 grant ID、策略包版本和生成高水位，便于重放过去决定。

决策接口与解释

决策请求包含主体、功能、操作、资源、请求数量、环境、时间和稳定 request_id。可借鉴 OpenFeature 的 evaluation context 规范：上下文字段拥有唯一键，按明确优先级合并。计量权益还要读取当前窗口的 committed 和 reserved 数量。

返回值不只是布尔值：

{
  "decision": "allow",
  "reason": "within_metered_allowance",
  "feature_key": "agent.execute",
  "policy_version": "policy_2026_08_31_3",
  "snapshot_revision": "ent_rev_1842",
  "remaining": "23750",
  "reservation_required": true,
  "expires_at": "2026-08-31T06:00:00Z"
}

调用方只依赖意图级接口，如 authorize(feature, subject, request)，不能沿对象链读取订阅、产品、价格和用量。原因码稳定且可观测，面向客户的文案由上层本地化。

缓存、一致性与失败偏好

权益读取路径需要低延迟，可缓存主体快照，但缓存键必须包含或返回 revision，并通过事件失效加短 TTL 双重保护。升级通常可容忍秒级生效，风险封禁和退款撤销可能要求更快；不同变更类型定义自己的传播 SLO。

功能风险 服务不可用时 示例
低成本可逆 短期使用最近快照 查看历史结果
中成本可限速 降级或较小本地额度 基础模型调用
高成本或不可逆 失败关闭 大规模 Agent 执行
安全与合规封禁 失败关闭 导出敏感数据

失败开放不是“任何错误都允许”。只有快照未过期、请求风险等级允许且本地应急预算未耗尽时才能放行，并写 degraded_allow 审计事件。恢复后这些请求仍需进入计量与对账。

变更、测试与审计

策略版本以不可变包发布，影子模式对真实请求同时计算旧新决策但只执行旧结果，比较允许转拒绝、拒绝转允许和剩余额度差异。大规模变更按租户分批，保留快速切回旧策略的能力。

测试矩阵覆盖有效区间边界、多个 grant 优先级、订阅取消、人工覆盖、缓存陈旧、用量恰好到限额和供应商 Webhook 乱序。属性测试可验证：硬限额下任何允许决策都不应让 confirmed consumption 超过 limit 与明确 overage 之和。

审计记录保存请求摘要、决策、原因、策略版本、快照 revision、用量高水位和预留 ID。敏感上下文只保留经批准字段或哈希，不复制完整用户内容。

小结

  • 权益是版本化业务契约，不等同于订阅状态。
  • 布尔、静态数量和计量权益统一进入策略决策，但保持各自语义。
  • 外部供应商对象经反腐层转换，内部策略服务拥有最终决定。
  • 决策返回结果、原因、版本、快照和剩余额度，而不是裸布尔值。
  • 缓存与失败偏好按功能风险分级，降级放行也必须审计和补计量。
  • 需要占用未来额度的允许决定继续进入配额预留状态机。
