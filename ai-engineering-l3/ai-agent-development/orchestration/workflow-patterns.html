工作流模式

Agent 工作流概述

Agent 工作流定义了任务执行的结构化路径。不同于简单的循环执行，工作流模式为 Agent 提供了顺序、并行、条件分支等丰富的编排能力，使复杂任务的执行更加可控和高效。



顺序工作流
顺序（Sequential）工作流是最简单的模式——步骤按固定顺序逐一执行，前一步的输出作为后一步的输入：


from dataclasses import dataclass
from typing import Any, Callable

@dataclass
class WorkflowStep:
    name: str
    handler: Callable
    description: str

class SequentialWorkflow:
    def __init__(self, steps: list[WorkflowStep]):
        self.steps = steps

    def run(self, initial_input: Any) -> Any:
        current = initial_input
        for step in self.steps:
            print(f"执行步骤: {step.name}")
            current = step.handler(current)
        return current

workflow = SequentialWorkflow([
    WorkflowStep("收集需求", gather_requirements, "从用户输入中提取需求"),
    WorkflowStep("生成代码", generate_code, "根据需求生成代码"),
    WorkflowStep("运行测试", run_tests, "执行测试验证代码"),
    WorkflowStep("代码审查", review_code, "审查代码质量")
])

result = workflow.run(user_request)


并行工作流
并行（Parallel）工作流允许多个无依赖的步骤同时执行，大幅缩短总执行时间：


interface ParallelTask<T> {
  name: string;
  execute: () => Promise<T>;
}

async function parallelWorkflow<T>(tasks: ParallelTask<T>[]): Promise<Map<string, T>> {
  const results = new Map<string, T>();

  const promises = tasks.map(async (task) => {
    const result = await task.execute();
    results.set(task.name, result);
  });

  await Promise.allSettled(promises);
  return results;
}

const searchResults = await parallelWorkflow([
  { name: 'academic', execute: () => searchAcademic(query) },
  { name: 'blogs', execute: () => searchBlogs(query) },
  { name: 'docs', execute: () => searchDocs(query) },
]);


条件工作流
条件（Conditional）工作流根据中间结果动态选择执行路径：


class ConditionalWorkflow:
    def __init__(self):
        self.routes: dict[str, Callable] = {}
        self.classifier: Callable | None = None

    def set_classifier(self, classifier: Callable):
        self.classifier = classifier

    def add_route(self, category: str, handler: Callable):
        self.routes[category] = handler

    def run(self, input_data: Any) -> Any:
        category = self.classifier(input_data)
        handler = self.routes.get(category)
        if not handler:
            raise ValueError(f"未知分类: {category}")
        return handler(input_data)

workflow = ConditionalWorkflow()
workflow.set_classifier(lambda x: classify_request(x))
workflow.add_route("code", handle_code_request)
workflow.add_route("search", handle_search_request)
workflow.add_route("write", handle_write_request)

Map-Reduce 工作流
Map-Reduce 模式将大任务拆分为多个小任务并行处理（Map），然后将结果合并（Reduce）：


import asyncio

class MapReduceWorkflow:
    def __init__(self, mapper: Callable, reducer: Callable, max_concurrency: int = 5):
        self.mapper = mapper
        self.reducer = reducer
        self.semaphore = asyncio.Semaphore(max_concurrency)

    async def run(self, items: list[Any]) -> Any:
        async def map_with_limit(item):
            async with self.semaphore:
                return await self.mapper(item)

        mapped = await asyncio.gather(*[map_with_limit(item) for item in items])
        return await self.reducer(mapped)

async def summarize_document(chunk: str) -> str:
    return await call_llm_async(f"摘要以下内容:\n{chunk}")

async def merge_summaries(summaries: list[str]) -> str:
    combined = "\n---\n".join(summaries)
    return await call_llm_async(f"将以下摘要合并为一篇连贯的总结:\n{combined}")

workflow = MapReduceWorkflow(mapper=summarize_document, reducer=merge_summaries)
result = await workflow.run(document_chunks)


Human-in-the-Loop
Human-in-the-Loop（人机协作）模式在关键决策点暂停执行，等待人类确认后再继续：


class HumanInTheLoopWorkflow:
    def __init__(self, approval_required: list[str]):
        self.approval_required = approval_required

    async def run(self, task: str, steps: list[WorkflowStep]) -> str:
        results = []
        for step in steps:
            result = step.handler(task)

            if step.name in self.approval_required:
                approval = await self._request_approval(step.name, result)
                if not approval["approved"]:
                    if approval.get("feedback"):
                        result = self._revise(result, approval["feedback"])
                    else:
                        return "任务被人工终止"

            results.append(result)
        return results[-1]

    async def _request_approval(self, step_name: str, result: str) -> dict:
        print(f"\n=== 需要人工确认: {step_name} ===")
        print(f"结果:\n{result}")
        response = input("批准 (y) / 修改 (f) / 拒绝 (n): ")
        if response == "y":
            return {"approved": True}
        elif response == "f":
            feedback = input("请提供修改意见: ")
            return {"approved": False, "feedback": feedback}
        return {"approved": False}


提示： Human-in-the-Loop 是生产环境中 Agent 系统的安全保障。对于涉及数据修改、资金操作、外部通信等高风险行为，务必设置人工审批节点。






小结
    

  • 工作流模式为 Agent 提供了结构化的任务编排能力，超越简单的循环执行。
    • 

  • 顺序、并行、条件是三种基础工作流模式，可以组合构建复杂流程。
    • 

  • Map-Reduce 模式适合大规模批量处理任务，通过并行 Map 和集中 Reduce 提升效率。
    • 

  • Human-in-the-Loop 在关键节点引入人工确认，是生产环境中不可或缺的安全机制。
    • 

  • 工作流模式的选择应根据任务特性——步骤依赖关系、并行可能性、风险等级来决定。
