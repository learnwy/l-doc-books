错误恢复

Agent 错误的特殊性

Agent 系统的错误恢复比传统软件更复杂——除了常规的技术错误（网络超时、API 故障），还有 LLM 特有的推理错误（幻觉、逻辑矛盾、工具误用）。有效的错误恢复策略是 Agent 在生产环境中可靠运行的基础。



重试策略
重试是应对瞬态错误的第一道防线。不同类型的错误需要不同的重试策略：

import asyncio
from enum import Enum, auto

class RetryPolicy(Enum):
    NONE = auto()
    IMMEDIATE = auto()
    EXPONENTIAL_BACKOFF = auto()
    FIXED_DELAY = auto()

class RetryConfig:
    def __init__(
        self,
        policy: RetryPolicy = RetryPolicy.EXPONENTIAL_BACKOFF,
        max_retries: int = 3,
        base_delay: float = 1.0,
        max_delay: float = 30.0
    ):
        self.policy = policy
        self.max_retries = max_retries
        self.base_delay = base_delay
        self.max_delay = max_delay

    def get_delay(self, attempt: int) -> float:
        if self.policy == RetryPolicy.IMMEDIATE:
            return 0
        if self.policy == RetryPolicy.FIXED_DELAY:
            return self.base_delay
        if self.policy == RetryPolicy.EXPONENTIAL_BACKOFF:
            return min(self.base_delay * (2 ** attempt), self.max_delay)
        return 0

async def retry_with_policy(func, config: RetryConfig, *args, **kwargs):
    last_error = None
    for attempt in range(config.max_retries + 1):
        try:
            return await func(*args, **kwargs)
        except Exception as e:
            last_error = e
            if attempt < config.max_retries:
                delay = config.get_delay(attempt)
                await asyncio.sleep(delay)
    raise last_error


自我修正
LLM 特有的错误——如生成了无效的 JSON、调用了不存在的工具、产生了逻辑矛盾——不能简单地重试，而需要让 Agent 理解错误并修正：


class SelfCorrectingAgent:
    def __init__(self, max_corrections: int = 3):
        self.max_corrections = max_corrections

    def execute_with_correction(self, task: str, validator: callable) -> str:
        result = call_llm(f"完成以下任务:\n{task}")

        for attempt in range(self.max_corrections):
            validation = validator(result)
            if validation["valid"]:
                return result

            correction_prompt = (
                f"你之前的输出存在以下问题:\n"
                f"{validation['errors']}\n\n"
                f"原始任务: {task}\n"
                f"你的输出: {result}\n\n"
                f"请修正以上问题，重新输出正确的结果。"
            )
            result = call_llm(correction_prompt)

        return result

def json_validator(output: str) -> dict:
    try:
        import json
        json.loads(output)
        return {"valid": True}
    except json.JSONDecodeError as e:
        return {"valid": False, "errors": f"JSON 格式错误: {e}"}

def code_validator(output: str) -> dict:
    try:
        compile(output, "<string>", "exec")
        return {"valid": True}
    except SyntaxError as e:
        return {"valid": False, "errors": f"语法错误: {e}"}


降级策略
当主要路径完全失败时，降级（Fallback）策略提供替代方案，确保系统仍能提供部分价值：


interface FallbackLevel {
  name: string;
  model: string;
  tools: string[];
  maxRetries: number;
}

class FallbackChain {
  private levels: FallbackLevel[];

  constructor(levels: FallbackLevel[]) {
    this.levels = levels;
  }

  async execute(task: string): Promise<{ result: string; level: string }> {
    for (const level of this.levels) {
      try {
        const result = await this.runAtLevel(task, level);
        return { result, level: level.name };
      } catch (error) {
        console.error(`${level.name} 失败: ${error}`);
        continue;
      }
    }
    return {
      result: '抱歉，系统暂时无法处理您的请求，请稍后再试。',
      level: 'fallback_message',
    };
  }

  private async runAtLevel(task: string, level: FallbackLevel): Promise<string> {
    return callLLM(task, { model: level.model, tools: level.tools });
  }
}

const chain = new FallbackChain([
  { name: 'primary', model: 'gpt-4o', tools: ['search', 'code', 'file'], maxRetries: 2 },
  { name: 'secondary', model: 'gpt-4o-mini', tools: ['search'], maxRetries: 1 },
  { name: 'basic', model: 'gpt-3.5-turbo', tools: [], maxRetries: 1 },
]);


优雅降级
优雅降级（Graceful Degradation）意味着即使部分能力不可用，系统仍尽最大努力提供有价值的输出：






降级场景
正常能力
降级后表现

代码执行不可用
运行并验证代码

高级模型不可用

class GracefulAgent:
    def __init__(self):
        self.available_capabilities: set[str] = set()
        self.all_capabilities: set[str] = {"search", "code_exec", "memory", "file_io"}

    async def check_capabilities(self):
        for cap in self.all_capabilities:
            try:
                await self._ping_capability(cap)
                self.available_capabilities.add(cap)
            except Exception:
                pass

    def build_system_prompt(self) -> str:
        unavailable = self.all_capabilities - self.available_capabilities
        prompt = "你是一个智能助手。"
        if unavailable:
            limitations = ", ".join(unavailable)
            prompt += f"\n注意: 以下能力当前不可用: {limitations}。请在回答中考虑这些限制。"
        return prompt

    async def run(self, task: str) -> str:
        await self.check_capabilities()
        available_tools = [
            t for t in self.all_tools
            if t["function"]["name"] in self.available_capabilities
        ]
        return await self._execute(task, available_tools)


提示： 生产环境中的 Agent 应该假设任何外部依赖都可能失败。设计时遵循「部分可用优于完全不可用」的原则，在关键路径上都准备好降级方案。






小结
    

  • Agent 系统面临技术错误、LLM 错误和工作流错误三类挑战，需要分别应对。
    • 

  • 重试策略是应对瞬态技术错误的第一道防线，指数退避+抖动是推荐的退避方式。
    • 

  • 自我修正通过将错误信息反馈给 LLM 来修复推理和格式错误。
    • 

  • 降级链按优先级尝试不同的执行方案，确保系统在异常情况下仍能提供价值。
    • 

  • 优雅降级让 Agent 在部分能力不可用时仍能以降低质量但不中断的方式继续服务。
    •
