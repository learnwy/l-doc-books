函数调用

从文本生成到工具使用

LLM 的函数调用（Function Calling）能力是 Agent 与外部世界交互的桥梁。通过函数调用，LLM 不再仅仅生成文本，而是能够输出结构化的工具调用指令，由外部系统执行后将结果返回给模型。



OpenAI Function Calling 机制
OpenAI 的 Function Calling 是目前最广泛使用的工具调用协议。开发者定义工具的 JSON Schema，LLM 根据用户请求自主决定是否调用以及如何传参。


from openai import OpenAI

client = OpenAI()

tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "获取指定城市的当前天气信息",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {
                        "type": "string",
                        "description": "城市名称，如「北京」「上海」"
                    },
                    "unit": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                        "description": "温度单位"
                    }
                },
                "required": ["city"]
            }
        }
    }
]

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "北京今天天气怎么样？"}],
    tools=tools
)

message = response.choices[0].message
if message.tool_calls:
    for call in message.tool_calls:
        print(f"调用函数: {call.function.name}")
        print(f"参数: {call.function.arguments}")


工具定义与参数 Schema
良好的工具定义是函数调用成功率的关键。工具描述需要清晰、准确，参数 Schema 需要完备且有约束：






Schema 要素
作用
最佳实践





name
工具的唯一标识
使用动词+名词，如 search_documents




description
告诉 LLM 何时使用此工具
描述功能、适用场景和限制




parameters
定义输入参数结构
使用 JSON Schema，包含类型和描述




required
必填参数列表
只将真正必需的参数列为 required




enum
限定参数取值范围
避免 LLM 生成无效值





interface ToolDefinition {
  type: 'function';
  function: {
    name: string;
    description: string;
    parameters: {
      type: 'object';
      properties: Record<
        string,
        {
          type: string;
          description: string;
          enum?: string[];
          items?: object;
        }
      >;
      required: string[];
    };
  };
}

const searchTool: ToolDefinition = {
  type: 'function',
  function: {
    name: 'search_knowledge_base',
    description: '在知识库中搜索与查询相关的文档。当用户提问涉及特定领域知识时使用此工具。',
    parameters: {
      type: 'object',
      properties: {
        query: {
          type: 'string',
          description: '搜索查询文本',
        },
        top_k: {
          type: 'number',
          description: '返回结果数量，默认为 5',
        },
        filters: {
          type: 'object',
          description: "过滤条件，如 {category: 'tech', date_from: '2024-01-01'}",
        },
      },
      required: ['query'],
    },
  },
};


提示： 工具的 description 字段是影响 LLM 选择正确工具的最重要因素。描述应该说明「什么时候用」而不仅仅是「做什么」。例如，「当用户需要查询实时天气信息时使用此工具」优于「获取天气数据」。






并行函数调用
现代 LLM 支持在一次响应中同时发起多个工具调用，大幅提升执行效率。当多个工具调用之间没有依赖关系时，应该鼓励并行调用。


import json
import asyncio
from openai import OpenAI

client = OpenAI()

def handle_tool_calls(message) -> list[dict]:
    results = []
    for tool_call in message.tool_calls:
        name = tool_call.function.name
        args = json.loads(tool_call.function.arguments)

        result = dispatch_tool(name, args)

        results.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": json.dumps(result, ensure_ascii=False)
        })
    return results

def dispatch_tool(name: str, args: dict) -> dict:
    tool_registry = {
        "get_weather": get_weather,
        "search_knowledge_base": search_knowledge_base,
        "run_code": run_code
    }
    if name not in tool_registry:
        return {"error": f"未知工具: {name}"}
    return tool_registry[name](**args)

def agent_with_tools(user_message: str, tools: list) -> str:
    messages = [{"role": "user", "content": user_message}]

    while True:
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools,
            parallel_tool_calls=True
        )

        choice = response.choices[0]
        messages.append(choice.message)

        if choice.finish_reason == "stop":
            return choice.message.content

        if choice.message.tool_calls:
            tool_results = handle_tool_calls(choice.message)
            messages.extend(tool_results)


函数调用的常见陷阱




陷阱
描述
解决方案





参数幻觉
LLM 编造不存在的参数值
使用 enum 约束、添加参数校验




工具混淆
多个工具功能相似导致选择错误
让工具名称和描述有明确区分度




无限循环
Agent 反复调用同一工具
设置最大调用次数，检测重复




JSON 格式错误
LLM 输出的 JSON 不合法
使用 Structured Output 模式





from pydantic import BaseModel, Field

class WeatherParams(BaseModel):
    city: str = Field(description="城市名称")
    unit: str = Field(default="celsius", description="温度单位")

def safe_parse_tool_call(arguments: str, schema: type[BaseModel]) -> BaseModel:
    try:
        return schema.model_validate_json(arguments)
    except Exception as e:
        return schema(city="unknown")


小结
    

  • 函数调用是 LLM 从纯文本生成跨越到工具使用的关键能力，是 Agent 与外部世界交互的桥梁。
    • 

  • 工具定义的 description 字段是决定 LLM 正确选择工具的最重要因素。
    • 

  • 并行函数调用支持同时执行多个无依赖的工具调用，大幅提升效率。
    • 

  • 参数幻觉、工具混淆、无限循环是函数调用中最常见的陷阱，需要通过 Schema 约束和调用限制来防范。
    • 

  • 使用 Pydantic 等工具进行参数校验可以有效提升函数调用的健壮性。
    •
