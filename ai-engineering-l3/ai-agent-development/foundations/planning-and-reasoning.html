Part II · Agent EngineeringAI Agent 开发 简介基础 简介规划与推理

规划与推理

任务分解

复杂任务很少能一步完成。Agent 的规划能力——将高层目标拆解为可执行的子任务序列——是其区别于简单 Chatbot 的核心能力。任务分解（Task Decomposition）是规划的第一步。

任务分解有两种主要策略：






策略
描述
适用场景





自顶向下
先生成完整计划，再逐步执行
目标明确、步骤可预见的任务




逐步展开
每完成一步再规划下一步
依赖中间结果、不确定性高的任务





from openai import OpenAI

client = OpenAI()

def decompose_task(goal: str) -> list[str]:
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {
                "role": "system",
                "content": "将用户的目标分解为 3-7 个具体的子任务。每个子任务应该是独立可执行的。以 JSON 数组格式返回。"
            },
            {"role": "user", "content": goal}
        ],
        response_format={"type": "json_object"}
    )
    import json
    result = json.loads(response.choices[0].message.content)
    return result["tasks"]

tasks = decompose_task("为电商网站构建一个商品推荐系统")
for i, task in enumerate(tasks, 1):
    print(f"{i}. {task}")


Plan-and-Execute 模式
Plan-and-Execute 是一种将规划与执行分离的 Agent 架构。它先由一个「规划者」生成完整计划，再由一个「执行者」逐步执行每个步骤。


这种架构的优势在于规划者可以使用更强大的模型（如 GPT-4o），而执行者可以使用更快更便宜的模型：


interface PlanStep {
  id: number;
  description: string;
  dependencies: number[];
  status: 'pending' | 'in_progress' | 'completed' | 'failed';
  result?: string;
}

interface Plan {
  goal: string;
  steps: PlanStep[];
  currentStep: number;
}

async function planAndExecute(goal: string): Promise<string> {
  const plan: Plan = await generatePlan(goal);

  for (const step of plan.steps) {
    step.status = 'in_progress';
    try {
      step.result = await executeStep(step, plan);
      step.status = 'completed';
    } catch (error) {
      step.status = 'failed';
      const revisedPlan = await replan(plan, error);
      plan.steps = revisedPlan.steps;
    }
  }

  return synthesizeResults(plan);
}


反思机制
反思（Reflection）是 Agent 在执行过程中回顾自身表现并进行改进的能力。它可以在行动后立即触发，也可以在完成一轮任务后进行全局反思。


Reflexion 框架是反思机制的代表性实现，它维护一个反思记忆，让 Agent 从过去的失败中学习：


class ReflexionAgent:
    def __init__(self):
        self.reflections: list[str] = []

    def act(self, task: str) -> str:
        context = self._build_context(task)
        result = self._execute(context)

        if not self._evaluate(result, task):
            reflection = self._reflect(task, result)
            self.reflections.append(reflection)
            return self.act(task)

        return result

    def _build_context(self, task: str) -> str:
        reflection_text = "\n".join(
            f"- 经验 {i+1}: {r}" for i, r in enumerate(self.reflections)
        )
        return f"任务: {task}\n\n过去的经验教训:\n{reflection_text}"

    def _reflect(self, task: str, failed_result: str) -> str:
        prompt = f"""
任务: {task}
失败的尝试结果: {failed_result}

请分析失败原因，总结一条简洁的经验教训，以便下次避免同样的错误。
"""
        return call_llm(prompt)

    def _evaluate(self, result: str, task: str) -> bool:
        return call_llm(f"结果 '{result}' 是否正确完成了任务 '{task}'？回答 yes 或 no") == "yes"

    def _execute(self, context: str) -> str:
        return call_llm(context)


自我批评
自我批评（Self-Critique）是反思的一种特殊形式，Agent 在生成输出后立即评审自己的工作，发现并修正错误。






自我批评维度
检查内容
示例问题





准确性
事实是否正确
引用的数据是否真实？




完整性
是否遗漏关键信息
是否覆盖了所有子任务？




一致性
前后逻辑是否矛盾
结论是否与分析一致？




可行性
方案是否可执行
代码能否通过编译？





def generate_with_critique(task: str, max_revisions: int = 3) -> str:
    draft = call_llm(f"完成以下任务:\n{task}")

    for _ in range(max_revisions):
        critique = call_llm(
            f"请严格审查以下内容，指出所有问题:\n\n{draft}\n\n"
            f"如果没有问题，回答「无问题」。否则列出具体问题。"
        )

        if "无问题" in critique:
            break

        draft = call_llm(
            f"原始内容:\n{draft}\n\n批评意见:\n{critique}\n\n"
            f"请根据批评意见修正内容。"
        )

    return draft


提示： 自我批评策略能显著提升 Agent 输出质量，但也会增加 LLM 调用次数和延迟。在生产环境中需要在质量和成本之间找到平衡，通常设置 2-3 轮修订上限。






小结
    

  • 任务分解是 Agent 规划的基础，分为自顶向下和逐步展开两种策略。
    • 

  • Plan-and-Execute 架构将规划与执行分离，支持更灵活的模型选择和动态重新规划。
    • 

  • 反思机制让 Agent 能从失败中学习，Reflexion 框架维护反思记忆实现持续改进。
    • 

  • 自我批评通过生成-审查-修订循环提升输出质量，通常限制 2-3 轮迭代。
    • 

  • 规划与推理能力是将简单 LLM 应用升级为真正 Agent 系统的关键。
