Agent 评估

为什么评估 Agent 很困难

Agent 评估比传统 ML 模型评估更复杂——Agent 的输出不是简单的分类或数值，而是多步骤的交互过程。同一个任务可能有多种正确的完成路径，工具调用的顺序和选择都可能不同但同样有效。



任务完成率
任务完成率（Task Completion Rate）是最直接的评估指标——Agent 是否成功完成了给定任务：


from dataclasses import dataclass
from enum import Enum

class TaskResult(Enum):
    SUCCESS = "success"
    PARTIAL = "partial"
    FAILURE = "failure"
    TIMEOUT = "timeout"

@dataclass
class EvalCase:
    task: str
    expected_output: str | None
    validation_fn: callable
    max_steps: int = 15
    timeout_seconds: float = 60.0

@dataclass
class EvalResult:
    case: EvalCase
    result: TaskResult
    actual_output: str
    steps_taken: int
    total_tokens: int
    latency_ms: float
    tool_calls: list[dict]

class AgentEvaluator:
    def __init__(self, agent):
        self.agent = agent

    def evaluate(self, cases: list[EvalCase]) -> dict:
        results = []
        for case in cases:
            result = self._run_case(case)
            results.append(result)

        success_count = sum(1 for r in results if r.result == TaskResult.SUCCESS)
        partial_count = sum(1 for r in results if r.result == TaskResult.PARTIAL)

        return {
            "total_cases": len(cases),
            "success_rate": success_count / len(cases),
            "partial_rate": partial_count / len(cases),
            "avg_steps": sum(r.steps_taken for r in results) / len(results),
            "avg_tokens": sum(r.total_tokens for r in results) / len(results),
            "avg_latency_ms": sum(r.latency_ms for r in results) / len(results),
            "results": results
        }

    def _run_case(self, case: EvalCase) -> EvalResult:
        import time
        start = time.time()
        output = self.agent.run(case.task)
        latency = (time.time() - start) * 1000

        task_result = case.validation_fn(output, case.expected_output)

        return EvalResult(
            case=case,
            result=task_result,
            actual_output=output,
            steps_taken=0,
            total_tokens=0,
            latency_ms=latency,
            tool_calls=[]
        )

interface ToolCallEval {
  expectedTool: string;
  expectedArgs: Record<string, unknown>;
  actualTool: string;
  actualArgs: Record<string, unknown>;
}

interface ToolAccuracyMetrics {
  selectionPrecision: number;
  selectionRecall: number;
  parameterAccuracy: number;
  redundancyRate: number;
}

function evaluateToolAccuracy(expected: ToolCallEval[], actual: ToolCallEval[]): ToolAccuracyMetrics {
  let correctSelections = 0;
  let correctParams = 0;

  for (const exp of expected) {
    const match = actual.find((a) => a.actualTool === exp.expectedTool);
    if (match) {
      correctSelections++;
      if (JSON.stringify(match.actualArgs) === JSON.stringify(exp.expectedArgs)) {
        correctParams++;
      }
    }
  }

  const redundant = actual.filter((a) => !expected.find((e) => e.expectedTool === a.actualTool)).length;

  return {
    selectionPrecision: actual.length > 0 ? correctSelections / actual.length : 0,
    selectionRecall: expected.length > 0 ? correctSelections / expected.length : 0,
    parameterAccuracy: expected.length > 0 ? correctParams / expected.length : 0,
    redundancyRate: actual.length > 0 ? redundant / actual.length : 0,
  };
}


轨迹分析
轨迹分析（Trajectory Analysis）关注 Agent 的整个执行路径，评估推理过程的质量：


class TrajectoryAnalyzer:
    def analyze(self, trajectory: list[dict]) -> dict:
        return {
            "total_steps": len(trajectory),
            "tool_calls": self._count_tool_calls(trajectory),
            "unique_tools": self._count_unique_tools(trajectory),
            "backtrack_count": self._detect_backtracks(trajectory),
            "loop_detected": self._detect_loops(trajectory),
            "reasoning_quality": self._evaluate_reasoning(trajectory)
        }

    def _detect_loops(self, trajectory: list[dict]) -> bool:
        tool_sequences = []
        for step in trajectory:
            if step.get("type") == "tool_call":
                tool_sequences.append(step["tool_name"])
        for i in range(len(tool_sequences) - 2):
            if tool_sequences[i] == tool_sequences[i+1] == tool_sequences[i+2]:
                return True
        return False

提示： Agent 评估的黄金标准是「LLM-as-Judge」——使用另一个 LLM 来评判 Agent 的输出质量。这比基于规则的验证更灵活，能处理「答案正确但表述不同」的情况。但要注意评判 LLM 的偏见问题。






小结
    

  • Agent 评估比传统 ML 更复杂，需要评估任务完成率、工具准确性、轨迹质量等多个维度。
    • 

  • 任务完成率是最直接的指标，通过验证函数判断是否成功、部分成功或失败。
    • 

  • 工具准确性从选择精确率、召回率、参数准确率和冗余调用率四个角度评估。
    • 

  • 轨迹分析关注执行路径的合理性、效率和推理连贯性。
    • 

  • 评估基准应覆盖单工具、多工具、多步推理、错误恢复等不同难度场景。
