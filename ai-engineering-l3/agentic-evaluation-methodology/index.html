Agentic 评估方法论

当系统从「一次问答」变成「连续做几十个决定」，评测的对象就从答案变成了轨迹：状态会累积、误差会级联、同一任务跑两次结果不同。

这套变化把传统 LLM 评测的整套假设连根拔起，也催生了一批全新的工程问题——任务怎么选才分得开好坏、环境怎么造才能复位、过程怎么评才不引入新偏差、分数怎么算才不自欺、以及这一切如何塞进 CI 和生产流量里持续运转。

本 hub 专门回答这批问题。它讨论的不是「某个基准上谁的分高」，而是「你自己怎么造一套能信的 agentic 评测」。

先划清与兄弟 hub 的边界。31_llm-evaluation-benchmarks 是基准地图集——盘点世界上有哪些榜单、分数怎么读、各自测什么，读完你知道「去哪看别人的成绩」；本 hub 是施工图——读完你能动手造自己的评测设施。

20_eval-driven-ai-engineering 讲评测驱动的 AI 工程总纲，其重心在单轮 LLM 应用：数据集怎么做、指标怎么配、LLM judge 怎么校准；本 hub 只在过程级评判一篇里借用它的裁判思想，讲的是 agent 特有的轨迹评判与编排位置。

33_agent-harness-design 研究怎么把 agent 本体和 harness 造好，是「被测对象」的设计学；本 hub 是「测量系统」的设计学，两者互为镜像。29_ai-native-testing 关注 AI 原生软件的测试工程全貌，agentic 评测只是其中一隅，本 hub 把这一隅展开到可落地的深度。

内容沿四条主线递进。「为何不同」先把单轮与 agentic 评测之间的鸿沟拆解清楚——误差级联的数学、成功率之外该测的成本与效率、评估栈的六层解剖，这三篇给你完整的概念坐标系。

「方法体系」进入施工层：任务套件怎么设计才有分辨力、环境沙箱怎么建才能复位且安全、LLM judge 用在 agent 上有哪些正确姿势。

「统计与陷阱」处理最容易翻车的暗面：方差与功效决定你需要多少次运行、污染与过拟合会让数字虚假繁荣、成本管理决定这套体系能否活过第一个季度。

「生产化」收束到真实战场：门禁怎么进 CI 而不失去公信力、线上影子评估怎么补离线的盲区、公开案例里反复验证过的设计模式有哪些。

不同读者有不同的入口。刚接手 agent 评测的新人请从第一章顺读，概念坐标系没立起来之前动手只会复刻别人的坑。

已有单轮 LLM 评测经验的工程师可以直接跳到第二章，第一章只补读误差级联那一篇；平台工程视角、关心落地多过原理的读者，可以第三章第四章对读着走，遇到概念空洞再回前两章查。

前置要求不高但不可无：用过 LLM API、见过 agent 至少卡住一次的真实经历、懂基本的软件测试概念和比例与置信区间的统计常识即可，不要求机器学习背景。

全部读完后，你应当能把「给我们的 agent 建套评测吧」这句模糊的需求，拆成一串有明确顺序、明确预算、明确验收标准的工程项目。

延伸阅读（可选的跨 hub 探索，不影响本 hub 自足性）：想先浏览现有公开基准的全景再去造轮子，见31 · LLM 评估基准；想要单轮应用评测基建（数据集、指标、裁判校准）的总纲，见20 · 评测驱动的 AI 工程；想知道被测对象本身怎么设计，见33 · Agent Harness 设计。
