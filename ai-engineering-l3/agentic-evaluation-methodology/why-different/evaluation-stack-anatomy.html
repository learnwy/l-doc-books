Part III · EvaluationAgentic 评估方法论为何不同评估栈解剖

评估栈解剖

一次评测跑完，分数从 62% 跌到 55%，此刻你手里只有一个数字和至少六种解释：任务被改坏了、环境复位失败、harness 升级改了工具行为、日志丢了关键字段、裁判提示词漂了、或者纯粹是采样噪声。没有分层的评测系统里，这六种原因搅成一锅粥，团队只能靠猜。评估栈解剖的目的就是把这套基础设施拆成职责单一的层，让每一次异常都有明确的归属地。

核心概念：六层参考架构

把任何一套像样的 agentic 评测设施横切开，都能看到大致相同的六个层次。层次之间只通过明确定义的接口交换数据：任务层向下投递任务规格，环境层返回观测，记录层把一切落盘，评判层消费记录产出判定，统计层把判定汇总成可比较的数字。

层 职责 输入 → 输出 该层特有的故障
任务层 定义做什么、怎么算成 任务规格 → 可执行任务实例 题目歧义、判定标准含糊
环境层 提供可复位的执行世界 容器镜像、初始快照 → 活的沙箱 复位不干净、依赖漂移
Harness 驱动 agent 与环境交互 agent + 工具接口 → 完整轨迹 接口设计改变 agent 行为
记录层 无损捕获过程数据 事件流 → trace 存储 截断丢字段、时间戳乱序
评判层 从 trace 产出判定 trace + 量规 → 分数 裁判偏差、量规漂移
统计层 判定的聚合与推断 分数列表 → 区间与结论 方差低估、多重比较

排障路由

这张表同时是一张排障路由表：分数异常时自下而上排查往往最快——统计层的噪声最便宜（多跑几次就能排除），环境层的复位问题次之（冒烟测试可查），而任务层和量规层的问题最隐蔽也最致命，因为它们悄悄改变了所有历史分数的可比性。

Harness 是被低估的行为变量

多数团队第一次踩坑都会在同一个地方：换了一个 agent 运行框架，模型没变，分数却动了十几个点。原因在于 harness 不是中立的管道——暴露给模型的工具形态直接改变它的行为。SWE-agent 的研究者把这层接口称为 agent-computer interface 并专门做了消融实验：同样的底层模型，搜索文件用简洁紧凑的接口还是冗长交互式的接口，完成任务的表现差异显著，好的接口设计本身就是性能来源（arXiv 2405.15793）。推论对评测而言是硬性的：harness 变更等同于被测系统变更，必须触发一轮完整的回归评测，且 harness 的版本要和分数一起进版本控制。

超时与资源策略

harness 还有一个常被忽略的义务：超时与资源策略本身是被评对象的一部分。给 agent 十分钟还是一小时、允许并行开三个终端还是一个，这些配置直接改变成功率分布，必须作为显式参数记录在每次运行报告中，否则跨团队的数字永远对不上。

Trace：让事后重判成为可能

评判层和诊断层的全部能力都以记录层的数据完整性为前提。一条够用的轨迹记录至少要包含四类信息：结构化的交互事件序列（观测、思考、动作、工具返回，各自带序号与时间戳）、环境的终态快照（用于确定性复核）、运行配置（模型版本、harness 版本、温度、预算上限）、以及成本流水（每次调用的 token 数）。缺了终态快照，你就只能相信 harness 自己报的成功标志；缺了成本流水，测量什么里那套效率指标全部无从计算。

写入即冻结

trace 设计的核心纪律是写入即冻结：记录层只追加不改写，任何后见之明的修正都作为新的注释事件叠加。这条纪律换来的是一项关键能力——同一份 trace 可以反复送回评判层重新打分（换量规、换裁判模型、换判定阈值），而不需要重新烧钱跑环境。过程级评判的迭代因此从「小时级的环境重跑」降为「分钟级的重放打分」，这是评估系统能快速迭代量规的前提，具体机制在过程级评判中展开。

分层健康检查

成熟的评测设施给每一层都配了廉价的自检手段。

环境层的冒烟测试

环境层做冒烟测试：每次批量评测前先跑一组已知解法的黄金任务，环境没复位好立刻暴露，不至于污染几百个昂贵任务的结果。OSWorld 这类真实操作系统环境甚至把「任务设置、执行式评测」做成环境平台的一等公民，正是为了把环境正确性从祈祷变成断言（arXiv 2404.07972）。WebArena 则走另一条路：自托管整套网站来保证环境完全可控可复现（arXiv 2307.13854）——两条路线的取舍在评估环境与沙箱构建里细讲。

评判与统计的自检

评判层配金标准轨迹集：几十条人工确认过应得高分的轨迹和应得低分的失败轨迹，每次量规或裁判模型变动后先过这一小撮，一致性掉了就说明评判层自己退化了。统计层最简单的自检是负对照：拿同一系统跑两次假装是两个系统，任何「显著差异」都是检验程序本身的 bug。这些检查单条成本极低，合起来却能把「分数异常」的平均定位时间从几天压到几分钟——这正是把栈分层的最大回报：不是让每一层都完美，而是让任何一层的坏都看得见、修得起。

小结

  • 评估栈分六层：任务、环境、harness、记录、评判、统计，每层有专属故障域。
  • harness 的接口设计会实质改变 agent 行为，其变更必须视同被测系统的变更。
  • trace 要含交互事件、终态快照、运行配置、成本流水，写入即冻结支撑事后重判。
  • 每层配廉价自检：环境冒烟、评判金轨迹、统计负对照，让异常定位以分钟计。
