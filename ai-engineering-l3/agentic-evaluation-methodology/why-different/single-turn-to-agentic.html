从单轮评测到 agentic 评测的转变

一个函数的单元测试写完可以躺半年，因为输入相同则输出必然相同；一个 agent 的评测跑完当晚就可能失效，因为它要连续做十几个决定、每个决定都改变世界状态，而其中任何一步走偏都会把后面的所有步骤带进沟里。这不是量变而是质变：单轮评测回答「这个模型对这句话怎么答」，agentic 评测回答「这个系统能不能在一片会动的环境里把一件事从头做到尾」。两句话背后是完全不同的评测本体论，本篇先把这道鸿沟拆开看清楚。

核心概念：单轮假设在哪里断裂

传统 LLM 评测建立在三条隐含假设上：输入是静态给定的、输出是一次性的、评分只看最终产物。SWE-bench 之前的代码评测就是典型——HumanEval 给一段函数签名和 docstring，模型吐一段代码，测试用例一跑即见分晓（arXiv 2107.03374）。这套范式在 agent 场景下三条假设同时断裂。

维度 单轮评测 agentic 评测
输入 静态 prompt，一次性给定 动态环境，观测随动作变化
输出 一段文本，一次成型 数十次工具调用的序列
正确性 与参考答案比对 终态满足目标且过程可接受
时间 一次前向传播 分钟到小时级的交互
失败模式 答错 答错、卡死、死循环、破坏环境、提前放弃
评分语义 点值 多次运行的分布

断裂的核心是状态性：agent 的每个动作都写入环境状态，后续观测依赖历史动作序列。同一个任务，「先读文件再改代码」和「先改代码再读文件」走出的轨迹完全不同，而单轮评测里根本不存在「顺序」这个变量。多步依赖还带来部分信用问题——一条轨迹里九步正确、一步删错了数据库，结果判定为失败，但失败原因和九步全错的失败完全是两种病，需要不同的药。

误差级联的数学现实

多步任务最残酷的性质是误差按乘法累积而非加法。设每一步决策的可靠率为 ppp，一条 nnn 步的轨迹全程无错的条件概率是

Pclean=pnP_{\text{clean}} = p^nPclean​=pn

当 p=0.95p = 0.95p=0.95 时，10 步任务的全程无错率跌到 0.9510≈0.600.95^{10} \approx 0.600.9510≈0.60，30 步只剩 0.9530≈0.210.95^{30} \approx 0.210.9530≈0.21。这解释了一个反复被实测验证的现象：单步能力看起来不错的模型，在长程任务上的表现远低于直觉预期。GAIA 的设计者对此有过精确测量——人类受访者拿到 92% 的正确率，而装备了插件的 GPT-4 只有 15%，差距恰恰集中在需要多环节配合的复合任务上（arXiv 2311.12983）。

flowchart TD
    S[任务开始] --> A[步骤 1 可靠率 p]
    A --> B[步骤 2 可靠率 p]
    B --> C{中途出错?}
    C -->|是| D[错误写入环境状态]
    D --> E[后续步骤基于错误观测]
    E --> F[整条轨迹报废<br/>或付出高昂恢复成本]
    C -->|否| G[继续下一步]
    G --> H{到达最后一步?}
    H -->|否| B
    H -->|是| I[任务成功]

级联还有一个隐蔽推论：恢复能力成为独立于单步能力的第二能力维度。好的 agent 能从报错里爬出来重试另一条路径，差的 agent 一个报错就原地打转。这意味着评测必须覆盖「出错之后的轨迹」，而不只是「一切顺利的轨迹」——刻意注入故障的任务因此成为 agentic 套件的标配题型。

轨迹与结果是两个被评对象

单轮评测只有一个被评对象：答案。agentic 评测天然有两个：终态结果（数据库里的订单改对了吗、测试套件绿了吗）和走向终态的轨迹（调用了哪些工具、参数是否合理、有没有绕远路、有没有越权操作）。两者可能背离出四种组合：结果对且过程干净、结果对但过程危险（碰巧蒙对了测试用例）、结果错但过程有亮点（差一步就成）、结果错且过程灾难。

只看结果会让「幸运的错误」混进成功样本，只看过程会把高效直接的暴力解法误判为低分。正确的做法是把两者当作互补信号分别采集：结果判定负责「能不能」，轨迹评判负责「稳不稳、贵不贵、安不安全」。轨迹怎么评、量规怎么写、judge 放在哪一层，是方法体系一章中过程级评判的主题，这里只需要记住结论：从单轮到 agentic 的转变，本质是被评对象从一个变成了两个。

非确定性迫使评测改说分布语言

单轮评测里，同一道题跑两次得到同一个分数是理所当然；agent 评测里这是奢望。模型解码有随机性，环境的响应时间有抖动，工具调用可能超时，模拟用户（如 τ-bench 里由 LLM 扮演的用户）本身就有情绪波动。于是「这个 agent 的成功率是多少」这个问题失去了良定义——你必须先问「跑多少次、取什么统计量」。τ-bench 的作者为此专门提出了 passk^kk 指标：同一任务连跑 kkk 次，只有 kkk 次全部成功才算通过，用它衡量的是可靠性而非运气（arXiv 2406.12045）。他们测出一个当时令人不安的结果：即便是最强的函数调用 agent，任务成功率也不到一半，而 retail 场景下 pass8^88 掉到四分之一以下——单次的亮眼成绩里藏着大量运气成分。

一旦评测的对象从点值变成分布，整套统计推断工具就要跟上：置信区间、效应量检验、所需样本量计算。这些内容在统计一章的方差与功效分析里有完整的数学处理；这里只需确立观念转变——agentic 评测报告的最小单位不是分数，而是「多少次运行下的什么统计量」。METR 用 50% 任务完成时间地平线来刻画模型能力随时间的演进，其报告同样建立在大量重复运行的分布估计之上，而不是任何单次运行的成绩（METR，2025 年 3 月，metr.org）。

转变落到的工程实体

鸿沟认清之后，跨越它的办法是搭一套新的评测基础设施，它至少包含四类构件：可判定的任务集、可复位的执行环境、驱动 agent 跑完任务的 harness、以及产出可比数字的评判与统计层。这四件套各自都有深水区：任务怎么选才不偏科、环境怎么造才能复位、harness 怎么记录才够裁判吃、统计怎么做才不自欺。本 hub 后续章节正是沿这条线逐层展开——下一节先讲清楚除了成功率之外还该测什么，再给出整个评估栈的分层解剖。

值得强调的是，转变并不意味着抛弃单轮时代的全部遗产。确定性断言（文件存在、测试通过、返回码为零）依然是结果判定的首选，能用正则解决的就不用 judge；单轮评测积累的统计纪律同样适用于新范式。真正的分界在于承认：agent 评测评的是一个动态系统在噪声环境下的行为分布，而不是一个静态函数在固定输入下的输出值。守住这条界线，后面所有的技术选择都有了锚点。

小结

  • 单轮评测的三条静态假设（输入给定、输出一次、只看产物）在 agent 场景同时失效。
  • 误差按 pnp^npn 级联，长程任务的成功率由最薄弱环节支配，恢复能力是需要单独覆盖的能力维度。
  • 轨迹与结果是两个互补的被评对象，只看任何一个都会系统性误判。
  • 非确定性迫使评测从点值转向分布语言，passk^kk 这类多次运行指标由此而生。
  • 跨越鸿沟靠的是任务、环境、harness、评判四件套基础设施，这正是本 hub 其余篇章的路线图。
