评估环境与沙箱构建

任务集再精良，没有一套跑得起、停得下、复得位的执行环境，评测就只是纸面设计。环境工程在 agentic 评测里的地位相当于风洞在空气动力学里的地位：被测对象的一切行为都要在这个受控空间里发生、被观测、可重现。它也是整个评估栈中最容易烂尾的一层——环境问题往往不报错，只安静地把噪声和偏差灌进你的分数里。

核心概念：复位是头等公民

评测环境和开发环境最本质的区别只有一个词：复位。每个任务实例都必须从一个已知的、干净的初始状态开始，上一轮轨迹留下的任何痕迹——半改的文件、残留的进程、被污染的缓存——都是对下一轮测量的投毒。复位的实现有两条路线，各有适用域。快照路线把环境做成镜像加快照：容器从基础镜像拉起，初始化脚本执行完毕后提交成基线快照，之后每次运行都从快照瞬时恢复，用完即弃。重建路线则每次从零执行完整的初始化流程，慢但不会积累快照本身的隐性状态。

初始断言

复位质量必须被显式验证而不是被假设。做法是把「初始断言」做进环境：一组检查初始状态是否符合预期的机判谓词，任何一个不过就中止该轮并标记环境故障，绝不让脏环境产生的数据流进统计层。这是评估栈解剖里冒烟测试的环境层实现。经验法则是：环境类故障一旦混入结果，事后几乎无法与 agent 故障区分，所以宁可错杀一轮也不放行一轮。

在真实性谱系上选点

环境不是越真越好，而是在一条「可控性 ↔ 真实性」的谱系上选一个和决策匹配的点。三个公开基准恰好标出了三个典型位置。WebArena 选择自托管仿真：把电商、论坛、协作开发、内容管理四类网站整套架设在自己的基础设施里，环境完全可控、完全可复现，代价是搭建和维护成本高，且仿真的真实感有上限（arXiv 2307.13854）。OSWorld 选择真实操作系统：直接在 Ubuntu、Windows、macOS 的真实虚拟机里布置任务，以执行式评测检验终态，真实感拉满，但环境变量更多、噪声更大（arXiv 2404.07972）。Terminal-Bench 选择终端环境这一中间形态：任务在容器化的命令行世界里完成，从编译内核、配置 git 服务器到破解压缩包哈希，由 Stanford 与 Laude Institute 合作运营公开榜单（tbench.ai）。

形态 代表 可控性 真实感 单任务成本 适用
自托管 Web 仿真 WebArena 最高 中 中 交互协议研究
容器化终端 Terminal-Bench 高 中高 低-中 工程能力回归
真实操作系统 OSWorld 中 最高 高 部署前体检

选点的判据

选点的判据是评测要支撑什么决策。日常回归要的是高频、便宜、低噪，容器化终端形态最合适；发布前的最终验证要的是高保真，值得为真实操作系统的单次运行付出十倍成本。多数成熟团队的答案是分层组合：内层便宜环境守门，外层昂贵环境季度体检。

并行调度与抖动的治理

agentic 评测的算力画像很特殊：单个任务是分钟级的长时间交互，而统计功效又要求大量重复运行，唯一出路是大规模并行。

资源竞争与限额

容器并行带来的新问题是资源竞争成为隐藏变量——八十个容器抢同一台宿主机的 CPU 和磁盘 IO，任务墙钟时间被拉长、依赖外部服务的步骤超时率上升，这些都会转化为伪失败。治理手段是把资源限额写进调度配置：每容器的 CPU、内存上限明确分配，对外部服务的访问尽量 mock 或限流，并把宿主机负载作为运行元数据一并记录。

抖动的归因

抖动治理的核心难题是归因：一个任务这次失败下次成功，到底是环境抖了还是 agent 本来就不稳？机械地区分做不到，但可以量化地分。给已知确定解的黄金任务定期重跑，其失败率就是环境抖动的本底估计；agent 的原始波动率减去本底，才是真正的行为方差。这个分解直接影响统计层需要的重复次数计算，详见方差与功效分析。工程上还要配一层廉价的失败重试预算：环境级错误码触发的自动重试不计入 agent 成绩，agent 行为导致的失败绝不重试——混淆这两类重试是新手最常见的自欺。

沙箱的安全边界

评估环境里跑的代码来自一个不完全可信的来源：被测模型的输出。模型可能生成删除文件的命令、向任意外网发包的脚本、或者在你没注意的地方读取凭据。因此沙箱的第一原则是默认拒绝：网络出口走白名单代理，文件系统按任务需要最小挂载，进程权限降到非特权用户，云凭据、内部密钥永远不注入沙箱环境变量。SWE-Lancer 的开源方案提供了一个可参照的底线实践——官方分发统一的 Docker 镜像作为评测运行环境，让「在什么隔离边界里跑」本身成为基准定义的一部分（arXiv 2502.12115）。

安全边界的另一半是逃逸后的爆炸半径控制：沙箱跑在独立的子网和账号体系下，即使被攻破也摸不到生产资产。这听起来偏执，但在把 agent 接上 shell 和浏览器的第一天就该到位——评测基础设施的安全事故比评测分数的错误难看得多。环境的最后一项成本属性也别忘了：并行规模乘以单任务时长就是账单，容量规划和省钱手段在评估成本管理里有专门的展开。环境造好的标志不是功能齐全，而是你敢在任何时候按下「全量重跑」并且知道会得到同样的数字。

小结

  • 复位是评测环境的头等公民，初始断言把环境故障拦在测量之前。
  • 环境在可控性-真实性谱系上选点：仿真最高控、真机最高保、终端居中性价比好。
  • 资源限额写进调度，黄金任务测出抖动本底，两类失败的自动重试政策必须分开。
  • 沙箱默认拒绝出网、最小挂载、无密钥注入，并为逃逸预留爆炸半径隔离。
