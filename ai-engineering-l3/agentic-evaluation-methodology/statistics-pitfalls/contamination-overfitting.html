Part III · EvaluationAgentic 评估方法论统计与陷阱污染与过拟合基准

污染与过拟合基准

评测分数的两大暗病症状相同——数字在涨，能力没涨——病根却分别在数据链的两端。污染是考卷提前泄进了教材：基准任务混进了模型的预训练语料，模型背过答案。过拟合是考生研究透了考官：团队对着固定套件反复调优，分数成为优化目标本身而不再是能力的代理变量。两者都让评测失去效度，且都会伪装成进步，必须分开诊断、分开用药。

核心概念：污染与过拟合的病根

污染的经典形态是公开基准的题目原文或近义变体被爬进预训练语料。agentic 领域还多一层结构性风险：主流软件工程基准的任务素材就是公开仓库的真实 issue 和 PR——SWE-bench 直接取材于 GitHub 上人人可访问的问题与修复（arXiv 2310.06770）。这意味着「题目 + 标准答案 + 解题过程」三件套天然躺在互联网上，任何在此之后训练的模型都无法自证清白。这不是假设性担忧：MLE-bench 的作者在发布基准时专门研究了来自预训练的各种污染形式的影响，把污染检查当作基准发布的标准工序（arXiv 2410.07095）。

时间窗对照

时间窗对照是目前最干净的实证手法。LiveCodeBench 持续从竞赛平台收录新题，并按「模型训练截止日期之前/之后」切分题目分别评估：同一批模型在后窗题目上的分数系统性低于前窗，差值就是污染贡献的虚高成分的直接估计（arXiv 2403.07974）。这个设计的精髓在于它不需要窥探任何模型的训练数据，只用发布时间做自然实验。

检测工具箱

没有单一检测器能抓住所有污染形态，实用方案是多层探测的组合：

检测方法 原理 能抓住 盲区
n-gram / 嵌入重叠 任务文本与已知语料比对 原文级泄漏 改写与翻译式泄漏
时间窗对照 训练截止前后分数差 一切形式的净效应 需要知道截止日期
canary 字符串 语料中埋唯一标识串 自家数据的定向取证 只护得住自己的语料
行为学探针 要求逐字补全题目 强记忆化 弱泛化偏置抓不到

Canary 与行为探针

canary 值得一提：大型模型实验室在发布自有评测集时会在文档中嵌入唯一的随机标识串并声明勿训，一旦后续模型出现对该串的记忆即可实锤定向污染。行为学探针则是反向利用记忆——如果模型能一字不差地续写某道题目的长尾段落，「没见过」的辩解很难成立。

间接污染的侧翼

agentic 场景还要多防一条侧翼：间接污染。你的任务素材未必直接泄题，但解题所需的教程、踩坑笔记、stack overflow 问答可能早已在语料里——模型没背答案，却背熟了套路，效果上等价于缩小了任务对泛化能力的考察范围。这类污染无法靠文本比对检测，只能靠行为学信号侧面估计：如果某类任务的分数随模型代际跳跃式上升而其他指标平稳，就值得怀疑。对内部团队而言最经济的组合是时间窗思想加私有保留集：新任务只对训练截止日期之后的系统完全可信。

Goodhart 之刃：评测侧的过拟合

即使毫无污染，固定套件也会随使用而贬值。古德哈特定律的评测版表述：当测量成为目标，它就不再是一个好的测量。具体机制有三层：提示词层面的针对性修补（发现第 47 号题总挂就为这类措辞打补丁）、策略层面对判定器的钻营（发现测试断言不检查副作用就用危险捷径通过）、以及组织层面把刷分当 KPI。SWE-bench 社区对此的一个制度化回应值得注意：OpenAI 与原班作者合作推出人工校验的 Verified 子集，剔除判定不可靠的任务样本，压缩了「钻判定空子」的空间（OpenAI，2024 年）。

对抗过拟合的核心武器是任务套件设计中预留的私有保留集，它的使用纪律比划分方法更关键。三条铁律：日常回归永远不碰保留集，任何针对保留集分数的迭代调优行为都在腐蚀它；解封频率压到季度级甚至半年级，且只在重大决策点启用；解封即退役——保留集一旦用于正式评估，其中暴露过的任务应轮换出池子，由新储备补位。保留集的价值和核弹头一样：威慑力在于存在，而不在于频繁使用。

把防御做成流程

零散的警惕挡不住系统的漏，防污染与防过拟合最终要固化成任务入库和版本管理的流程纪律：

flowchart TD
    A[候选新任务] --> B{来源可追溯?}
    B -->|否| X[拒收]
    B -->|是| C[查重: 与公开语料<br/>n-gram 及嵌入比对]
    C -->|疑似泄漏| X
    C -->|干净| D[标注创建时间与来源]
    D --> E{进入哪层}
    E -->|日常回归池| F[全量可见 定期轮换]
    E -->|私有保留池| G[加密隔离 季度解封]
    F --> H[每次套件发版记录哈希<br/>保证分数-版本可对账]
    G --> H

版本对账

版本对账是最后一道保险：每份评测报告都必须能回答「这组分数是用哪个哈希的任务集、哪一版量规、哪个 harness 跑出来的」。少了这道对账，几个月后你将无法区分「能力提升」「任务变简单」和「量规放宽」。还有一个容易被忽略的时效维度：agent 生态本身在漂移，依赖库升级、API 变更会让旧任务的难度无声地变化，所以套件需要定期用黄金系统重标定难度档位。当这套流程与线上监控衔接——生产环境里新出现的失败模式持续补充进任务池——评测就获得了对抗陈旧化的自我更新能力，那个闭环的设计在线上影子评估。统计上如何识别「可疑的异常高分」同样有章可循，见方差与功效分析中的区间逻辑：一个宣称涨了二十个点的结果，若区间根本容不下噪声解释，才配得上进一步归因。

小结

  • 污染在数据链上游（考卷泄入训练语料），过拟合在下游（考生研究透考官），症状同为虚假进步。
  • 时间窗对照是最干净的实证检测，n-gram 重叠、canary、行为探针各有盲区需组合。
  • 私有保留集是对抗 Goodhart 的终审武器，纪律三条：日常不碰、低频解封、解封即退役。
  • 任务入库走查重-标注-分池-对账流水线，每份报告必须能与套件哈希对账。
