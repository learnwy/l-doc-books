公开案例的模式提炼

单个基准的发布博客讲的是它自己的故事，直接照搬某个榜单的做法大概率水土不服——真正可迁移的是散落在十几个公开评测项目里的设计模式。本篇把 2024 到 2026 年间最具影响力的 agentic 评测工程当作田野调查的样本，提炼出四组反复出现、被不同团队独立验证过的模式，并给出把它们搬进自建套件时的适配清单。

核心概念：案例全景

先铺开地图。下表每个条目的事实都来自其原始发布物，读者可循链接自行核验：

模式一：真实工件加执行式判定

被验证次数最多的模式是「任务取自真实世界，判定交给机器执行」。SWE-bench 把真实 GitHub issue 连同对应 PR 变成任务、用仓库自己的测试套件判分；MLE-bench 用 Kaggle 竞赛的官方评分流程判分；Terminal-Bench 的每道终端任务都自带验收脚本。这个模式的威力在于判定成本随任务数量摊薄为零——造一套判定脚本的投入换来无限次免费复跑，这是测量什么里「能确定就别用裁判」原则的集体背书。

但这条模式有一个常被忽略的补丁：判定器本身需要质检。OpenAI 与 SWE-bench 原作者合作推出人工校验的 Verified 子集，剔除了判定不可靠的任务样本（OpenAI，2024 年）；SWE-Lancer 走得更远，其端到端测试由资深工程师三重核验，管理类任务的答案则对照原始雇佣经理的真实决策（arXiv 2502.12115）。教训很清晰：「机器判定」不等于「判定正确」，判定工件的缺陷会静默地扭曲整个榜单。

模式二：可靠性与人类锚定写进指标定义

第二组模式关于指标本身的设计勇气。当所有榜单都在报单次成功率时，τ-bench 提出连跑 kkk 次全对才算过的 passk^kk，并实测出当时最强的函数调用 agent 成功率不足一半、retail 场景 pass8^88 掉破四分之一的结果（arXiv 2406.12045）——一个指标的定义变更，暴露了整个行业数字里水分的存在。METR 则干脆绕开百分比，用「人类完成同类任务所需时长」给能力定标，测得前沿模型的 50% 完成时间地平线约五十分钟且自 2019 年以来约每七个月翻倍（arXiv 2503.14499；metr.org）。

人类锚定是这组模式的另一半。GAIA 用人类 92% 对照当时 GPT-4 加插件的 15%，让「通用助手还有多远」第一次有了直观刻度（arXiv 2311.12983）；MLE-bench 直接借 Kaggle 公开排行榜的奖牌线做人类基线（arXiv 2410.07095）。共同思想是：百分比只有对着一个人类参照系才有意义，这正是本 hub 反复强调的校准砝码思路在公开实践中的样子。

模式三：环境谱系上的自觉站位

第三组模式关于环境的自觉选择。把环境类案例排在光谱上：WebArena 为极致可控而自托管全部网站（arXiv 2307.13854），OSWorld 为极致保真而直接开真虚拟机（arXiv 2404.07972），Terminal-Bench 和 TheAgentCompany 占据中间地带——前者以容器终端兼顾便宜与真实，后者干脆搭了一整家模拟公司来测「数字员工」的全栈行为，并测出最强 agent 也只能自主完成三成任务的现实读数（arXiv 2412.14161）。没有谁试图在一份环境上同时满足所有诉求，各自明确定位并接受代价，这个「自觉站位」的姿态本身就是模式，其工程细节在评估环境与沙箱构建已系统展开。

同组还有一个防退化的分支模式：把防污染做成机制而非声明。LiveCodeBench 用持续收录新题加训练截止时间窗对照，让污染效应变成可测量的差值（arXiv 2403.07974）；MLE-bench 在发布时同步研究预训练污染的影响（arXiv 2410.07095）。公开基准尚且如此，内部套件更没有理由裸奔，对应的入库流水线见污染与过拟合基准。

模式四：统计与偏差纪律的一等公民化

最后一组模式最不起眼却最能区分业余与专业：把统计纪律当作评测产品的一部分来交付。Anthropic 的统计分析把语言模型评测明确为实验科学问题，给出区间估计与实验规划的成套方法（arXiv 2411.00640）；LLM-as-judge 的奠基研究在推广裁判范式的同一篇论文里就系统列出了位置、冗长、自我增强三类偏差及其缓解方案（arXiv 2306.05685）。注意这两个案例的共同点：缺陷披露发生在方法论主张的同时，而不是等社区打脸后再补救。这套纪律的完整展开在本 hub 的方差与功效分析与过程级评判，此处只提炼姿态：可信度不是测出来的，是设计出来的。

四组模式的适配顺序建议自上而下：先把判定做实（模式一），再选指标（模式二），然后按预算站环境位（模式三），全程带着统计纪律（模式四）。照抄任何一个榜单的具体题目毫无意义，因为你的任务分布只属于你的业务——这也是本 hub 与兄弟主题的根本分野：别人发布的分数不可比，可迁移的只有设计决策。把这些决策组合进自己的评估栈之后，别忘了最后一步是把整套设施接入日常开发节奏，那正是Agent 进 CI 门禁与线上影子评估已经铺好的路。

小结

  • 真实工件加执行式判定是被验证最多的模式，但判定工件本身必须质检。
  • 指标设计的勇气体现在 passk^kk 与时间地平线这类新定义，以及人类参照系的锚定。
  • 环境要在可控-保真光谱上自觉站位，防污染要做成机制而非口头声明。
  • 统计与偏差纪律应当与方法论同时出厂，可信度是设计出来的不是测出来的。
