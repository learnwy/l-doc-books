Part IV · Control PlaneAI 护栏与内容安全·总览输入防御PII 识别与脱敏

PII 识别与脱敏

不是所有输入护栏都在防攻击。用户在客服对话里随手打出自己的手机号、身份证、银行卡，没有任何恶意，但这些个人身份信息（PII）一旦进入模型上下文，就会顺着链路扩散：被写进调试日志、被发往第三方模型 API、被模型在后续回答里复述、被存进对话历史长期留存。在 GDPR、《个人信息保护法》等法规下，每一处扩散都是合规风险。OWASP 把敏感信息泄露列为 LLM02。这一篇讲 PII 的识别—脱敏—还原管线，以及为什么它在入口和出口都要做。

核心概念：识别—脱敏—还原三段管线

PII 处理不是简单地「检测到就删掉」。很多场景下你还需要模型基于这些信息工作——比如「帮我查订单 138xxxx 的物流」，你不能把手机号删了让模型无从查起。所以标准管线是三段：识别、脱敏（用占位符替换）、把模型回答里的占位符还原回真实值。

flowchart TD
  IN[用户输入<br/>含真实 PII] --> DET[识别<br/>NER+正则+校验]
  DET --> MAP[建立映射<br/>真实值 ↔ 占位符]
  MAP --> RED[脱敏文本<br/>用占位符替换]
  RED --> M[LLM 推理]
  M --> RESP[含占位符的回答]
  RESP --> RESTORE[按映射还原]
  RESTORE --> OUT[返回用户<br/>真实值]

关键设计是那张映射表：识别阶段把每个 PII 实体替换成稳定的占位符（如 <PHONE_1>），并记下 <PHONE_1> ↔ 真实手机号 的对应；模型在脱敏文本上推理，它看到的是占位符；模型回答里若引用了 <PHONE_1>，在返回用户前按映射还原。这样模型上下文、日志、第三方 API 里全程不出现真实 PII，但功能不受影响。映射表本身是敏感数据，须短生命周期、加密、用完即弃。

三类检测器：NER、正则、校验和

PII 识别的难点在于不同类型的 PII 适合不同检测器，单靠一种都不够。Microsoft Presidio——2026 年最主流的开源 PII 工具，NeMo Guardrails 和 Guardrails AI 都内置了它——的设计就是把三类检测器组合起来。

命名实体识别（NER）：用 NLP 模型识别姓名、地址、组织等没有固定格式的 PII。姓名没法用正则匹配，只能靠模型从上下文判断「张伟」是个人名。

正则：匹配有固定格式的 PII——手机号、邮箱、身份证号、IP 地址、信用卡号。这类格式规整，正则又快又准。

校验和 / 上下文增强：对有内部校验规则的 PII（如信用卡的 Luhn 校验、身份证的校验位），用算法确认它真的是有效号码而非碰巧匹配格式的数字，降低误报；再结合上下文词（号码前面有「卡号」二字）提升置信度。

下表对比三类检测器的适用范围。

检测器 擅长的 PII 速度 局限
NER 模型 姓名、地址、机构 慢 依赖语言模型质量，可能漏报
正则 手机/邮箱/卡号/IP 极快 只能抓固定格式，易误报
校验和 身份证、信用卡 快 仅适用于有校验规则的类型

Presidio 把三者的输出按置信度融合，每个识别结果带一个分数，应用按阈值决定是否脱敏。这个阈值同样是召回与误报的权衡——阈值低则多脱敏（可能误伤正常数字），阈值高则可能漏掉真实 PII。

入口与出口都要扫

PII 检查是 护栏架构 里讲的「两头都做」的典型。入口扫描挡住用户输入里的 PII，防止它进入模型上下文和日志。但出口也必须扫，原因有二：一是模型可能从 RAG 检索的文档里读到 PII 并复述出来——这 PII 不来自当前用户输入，入口扫描扫不到；二是模型可能把入口脱敏时遗漏的、或它自己推断出的 PII 写进回答。所以出口 rail 要再独立扫一遍生成文本，作为最后一道防线。入口脱敏的占位符还原和出口的 PII 扫描，是同一段出口处理里的两件事——先还原本次对话该还原的占位符，再扫描整段回答确认没有意料外的 PII 泄露。

一段最小实现

用 Presidio 风格的 API 把识别与脱敏串起来，体现「保留映射以便还原」的关键：

from presidio_analyzer import AnalyzerEngine
from presidio_anonymizer import AnonymizerEngine

analyzer, anonymizer = AnalyzerEngine(), AnonymizerEngine()

def redact(text: str, threshold: float = 0.5):
    results = [r for r in analyzer.analyze(text=text, language="zh")
               if r.score >= threshold]
    # 用稳定占位符替换，并保留映射用于还原
    anonymized = anonymizer.anonymize(text=text, analyzer_results=results)
    mapping = build_mapping(text, results)   # <PHONE_1> -> 真实值
    return anonymized.text, mapping

注意 threshold 把低置信度的识别结果挡在脱敏之外——这是控制误报的旋钮，要靠评测校准。

不止 PII：密钥与机密

同一套管线还该扫机密信息——API key、密码、token、内部 URL。这类内容若被模型复述或写进日志，等于凭证泄露。检测手段类似（密钥多有固定前缀和长度特征，适合正则），但处置更激进：检测到机密通常直接拦截整条请求并告警，而不是脱敏后放行，因为机密出现在用户输入里本身就是异常信号。这一类也与 策略强制 在出口侧的机密扫描呼应。

小结

  • PII 处理是识别—脱敏—还原三段管线，不是简单删除；用稳定占位符替换并保留映射表，让模型在脱敏文本上工作而功能不受损。
  • 识别要组合三类检测器：NER 抓无固定格式的姓名地址，正则抓格式规整的手机邮箱卡号，校验和确认有内部校验规则的号码；Presidio 是 2026 主流开源实现。
  • 入口与出口都要扫：入口挡用户输入的 PII，出口挡模型从 RAG 复述或自行推断出的 PII；阈值是召回—误报的旋钮，靠评测校准。
  • 同一管线扩展到密钥与机密检测，但处置更激进——通常直接拦截而非脱敏。
