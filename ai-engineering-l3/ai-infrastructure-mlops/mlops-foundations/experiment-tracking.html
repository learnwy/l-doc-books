实验追踪

核心概念

实验追踪（Experiment Tracking）是 ML 开发过程中记录、比较和管理模型实验的系统化方法。在模型开发的探索阶段，团队通常会运行数百甚至数千次实验，每次实验涉及不同的数据子集、超参数配置、模型架构和训练策略。没有系统化的追踪机制，团队将陷入"哪次实验用了什么参数、得到了什么结果"的混乱之中。

实验追踪系统的核心价值在于将隐式的、存在于数据科学家脑中的实验知识转化为显式的、可查询的结构化数据。

MLflow 追踪体系
MLflow 是最广泛使用的开源实验追踪工具，其 Tracking 组件提供了四层数据模型：Experiment（实验）→ Run（运行）→ Params/Metrics/Artifacts。每个 Experiment 代表一个研究课题（如"图像分类模型优化"），其中包含多个 Run，每个 Run 记录了一次具体的训练过程。


MLflow 的核心 API 设计非常简洁。通过 mlflow.log_param() 记录超参数，mlflow.log_metric() 记录评估指标，mlflow.log_artifact() 保存模型文件和其他产物。MLflow 还支持自动日志（Autolog），对 PyTorch、TensorFlow、Scikit-learn 等主流框架可以零代码侵入地自动记录所有训练参数和指标。


import mlflow

mlflow.set_experiment("text-classification-v2")

with mlflow.start_run(run_name="bert-base-lr3e5"):
    mlflow.log_params({
        "model": "bert-base-uncased",
        "learning_rate": 3e-5,
        "batch_size": 32,
        "epochs": 10,
        "warmup_ratio": 0.1,
    })

    for epoch in range(10):
        train_loss = train_one_epoch(model, train_loader)
        val_metrics = evaluate(model, val_loader)

        mlflow.log_metrics({
            "train_loss": train_loss,
            "val_accuracy": val_metrics["accuracy"],
            "val_f1": val_metrics["f1"],
        }, step=epoch)

    mlflow.pytorch.log_model(model, "model")
    mlflow.log_artifact("confusion_matrix.png")
MLflow Tracking Server 支持多种后端存储方案。元数据（参数、指标）可以存储在 SQLite、PostgreSQL 或 MySQL 中，Artifact 可以存储在本地文件系统、S3、GCS 或 Azure Blob 中。生产环境建议使用 PostgreSQL 作为元数据存储、S3/GCS 作为 Artifact 存储，并通过负载均衡部署多个 Tracking Server 实例以支持团队规模扩展。


Weights & Biases 深度集成
Weights & Biases（W&B）是功能最丰富的商业实验追踪平台，它在基础的参数-指标记录之上，提供了实时训练可视化、超参数搜索（Sweeps）、模型版本管理（Model Registry）和协作报告（Reports）等高级功能。


W&B 的独特价值在于其实时可视化能力。训练过程中的损失曲线、梯度分布、注意力热图等可以实时在 Web 仪表盘上更新，团队成员可以在任何设备上实时观察训练进展。这对于长时间训练（如大模型预训练）尤为重要，可以在早期发现训练异常并及时调整。

for step, batch in enumerate(dataloader):

W&B Sweeps 提供了自动化超参数搜索能力，支持网格搜索、随机搜索和贝叶斯优化三种策略。Sweep Controller 根据历史实验结果动态调整搜索方向，可以在有限的计算预算内找到更优的超参数组合。


实验对比与模型选择
实验追踪的终极目标是帮助团队做出更好的模型选择决策。有效的实验对比需要多维度、多粒度的分析能力。


基础对比是在相同评估集上比较不同实验的核心指标（准确率、F1、AUC 等）。但仅看聚合指标往往不够，还需要分析模型在不同数据子集上的表现差异。例如，一个整体准确率更高的模型可能在某些边缘案例上表现很差，这在安全敏感的应用中是不可接受的。


MLflow 和 W&B 都提供了实验对比仪表盘，支持按指标排序、筛选和分组。进阶用法包括并行坐标图（Parallel Coordinates Plot）——将每个超参数作为一个轴，每次实验作为一条线，通过线条的颜色编码目标指标值，可以直观地发现超参数与性能的相关关系。

模型注册与晋级流程
实验追踪的下游是模型注册表（Model Registry），它管理着从实验阶段到生产部署的模型晋级流程。MLflow Model Registry 定义了四个标准阶段：None → Staging → Production → Archived。


模型注册时，不仅要保存模型权重，还要记录完整的元数据：训练数据的版本指纹、超参数快照、评估指标、依赖环境（conda.yaml / requirements.txt）和模型签名（输入输出的 Schema）。这些元数据是模型复现和问题排查的基础。


晋级流程通常需要人工审批结合自动化检查。从 Staging 到 Production 的晋级至少应该通过以下自动化门控：性能指标不低于当前生产模型、推理延迟在 SLA 范围内、模型大小在部署限制内、安全性测试通过。人工审批环节则评估业务影响、合规要求和发布时机。


from mlflow import MlflowClient

client = MlflowClient()

model_version = client.create_model_version(
    name="text-classifier",
    source="runs:/abc123/model",
    run_id="abc123",
    description="BERT fine-tuned on v2 dataset",
)

client.set_model_version_tag(
    name="text-classifier",
    version=model_version.version,
    key="validation_accuracy",
    value="0.94",
)

client.transition_model_version_stage(
    name="text-classifier",
    version=model_version.version,
    stage="Staging",
)
小结
    

  • 实验追踪将隐式的实验知识转化为可查询的结构化数据，是 ML 团队协作和模型复现的基础
    • 

  • MLflow 是开源标准方案，适合自建基础设施的团队；W&B 提供更丰富的可视化和协作功能
    • 

  • 有效的实验对比需要多维度分析，不能仅依赖聚合指标，还需要关注子集性能和资源效率
    • 

  • 模型注册与晋级流程是连接实验追踪和生产部署的桥梁，需要自动化检查与人工审批相结合
    • 

  • 实验追踪系统的投入产出比极高，建议在项目初期就建立规范化的追踪实践
