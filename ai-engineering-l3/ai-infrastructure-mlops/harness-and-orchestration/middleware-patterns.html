中间件模式

核心概念

中间件（Middleware）是处理 ML 服务请求-响应链路中横切关注点的软件组件。在 ML 系统中，模型推理只是请求处理的核心一环，围绕它还有认证鉴权、速率限制、请求转换、缓存、日志记录、熔断降级等一系列基础设施需求。中间件模式将这些关注点封装为可组合的独立组件，形成清晰的责任链。

中间件的核心价值是关注点分离——每个中间件只负责一项职责，通过组合形成完整的处理链路。

认证鉴权与访问控制
ML API 的认证鉴权需要处理两类场景：外部客户端访问（通过 API Key 或 OAuth 2.0 Token）和内部服务间调用（通过 mTLS 或 Service Account）。认证解决"你是谁"的问题，鉴权解决"你能做什么"的问题。


对于 ML 服务，鉴权的粒度通常包括：模型级别（是否有权访问特定模型）、版本级别（是否有权访问生产版本或实验版本）和操作级别（是否有权执行推理、查询元数据或修改模型配置）。基于角色的访问控制（RBAC）将权限打包为角色，再将角色分配给用户或服务。


from functools import wraps

class AuthMiddleware:
    def __init__(self, auth_service):
        self.auth_service = auth_service

    async def __call__(self, request, next_handler):
        token = request.headers.get("Authorization", "").replace("Bearer ", "")
        if not token:
            return Response(status=401, body={"error": "Missing authentication"})

        identity = await self.auth_service.verify_token(token)
        if not identity:
            return Response(status=401, body={"error": "Invalid token"})

        model_name = request.path_params.get("model_name")
        if not self.auth_service.check_permission(identity, model_name, "predict"):
            return Response(status=403, body={"error": "Permission denied"})

        request.identity = identity
        return await next_handler(request)
API Key 轮转和审计日志是安全运维的重要组成部分。API Key 应设置有效期并支持自动轮转，所有认证事件（成功和失败）都应记录到审计日志中，用于安全审计和异常检测。


速率限制与请求队列
速率限制（Rate Limiting）保护 ML 服务免受流量突增的冲击。ML 推理通常是计算密集型操作，GPU 资源有限，不受控的请求涌入会导致推理延迟飙升甚至服务崩溃。


令牌桶算法（Token Bucket）是最常用的速率限制策略。它为每个客户端维护一个令牌桶，桶按固定速率补充令牌，每个请求消耗一个令牌。当桶中没有令牌时，新请求被拒绝或排队。令牌桶的两个参数——桶容量（Burst Size）和补充速率（Rate）——控制了短时间突发流量和持续流量的上限。


import time
from collections import defaultdict

class TokenBucketRateLimiter:
    def __init__(self, rate, burst):
        self.rate = rate
        self.burst = burst
        self.buckets = defaultdict(lambda: {"tokens": burst, "last_time": time.time()})

    def allow(self, client_id):
        bucket = self.buckets[client_id]
        now = time.time()
        elapsed = now - bucket["last_time"]
        bucket["tokens"] = min(self.burst, bucket["tokens"] + elapsed * self.rate)
        bucket["last_time"] = now

        if bucket["tokens"] >= 1:
            bucket["tokens"] -= 1
            return True
        return False

class RateLimitMiddleware:
    def __init__(self, limiter):
        self.limiter = limiter

    async def __call__(self, request, next_handler):
        client_id = request.identity.client_id
        if not self.limiter.allow(client_id):
            return Response(
                status=429,
                body={"error": "Rate limit exceeded"},
                headers={"Retry-After": "1"},
            )
        return await next_handler(request)
对于多模型服务，速率限制需要按模型维度设置不同的限额。大模型的推理成本远高于小模型，应该设置更低的速率限制。优先级队列可以让高优先级请求在限流条件下仍能获得服务。


缓存策略与结果复用
推理结果缓存是降低 ML 服务成本和延迟的高效手段。当相同的输入产生确定性的输出时（如文本分类、图像识别），缓存可以完全避免重复推理。即使模型输出不完全确定性（如含采样的生成模型），近似缓存也能减少大部分重复计算。


缓存键的设计是核心挑战。最简单的方案是将输入数据的哈希值作为缓存键，但对于复杂输入（如图像），计算完整哈希的成本不低。实践中常用的策略是多级缓存键：先用轻量级特征（如文本长度 + 前 N 个字符的哈希）快速匹配，命中后再验证完整输入的一致性。


import hashlib
import json

class InferenceCacheMiddleware:
    def __init__(self, cache_backend, ttl_seconds=3600):
        self.cache = cache_backend
        self.ttl = ttl_seconds

    def _compute_cache_key(self, model_name, model_version, input_data):
        payload = json.dumps({
            "model": f"{model_name}:{model_version}",
            "input": input_data,
        }, sort_keys=True)
        return hashlib.sha256(payload.encode()).hexdigest()

    async def __call__(self, request, next_handler):
        cache_key = self._compute_cache_key(
            request.model_name, request.model_version, request.input_data
        )

        cached = await self.cache.get(cache_key)
        if cached:
            return Response(body=cached, headers={"X-Cache": "HIT"})

        response = await next_handler(request)
        await self.cache.set(cache_key, response.body, ttl=self.ttl)
        return response
缓存失效策略需要考虑模型更新。当模型版本升级时，旧版本的缓存应该失效。通过将模型版本纳入缓存键的计算，可以自然地实现版本感知的缓存失效。

熔断降级与容错
熔断器（Circuit Breaker）模式防止 ML 服务在依赖的下游服务故障时级联崩溃。当模型推理或特征服务的错误率超过阈值时，熔断器"断开"，后续请求直接返回降级结果而不实际调用故障服务，避免无用的重试和资源浪费。


熔断器有三个状态：关闭（正常通过请求）、打开（直接返回降级结果）和半开（允许少量探测请求验证服务是否恢复）。状态转换由错误率和超时时间控制。


降级策略是熔断器的配套设计。对于 ML 服务，常见的降级方案包括：返回缓存的最近结果、使用更简单的备用模型（如规则引擎或小模型）、返回默认值（如推荐系统返回热门商品列表）。


class CircuitBreaker:
    def __init__(self, failure_threshold=5, recovery_timeout=30):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.failure_count = 0
        self.state = "closed"
        self.last_failure_time = 0

    async def call(self, func, fallback, *args, **kwargs):
        if self.state == "open":
            if time.time() - self.last_failure_time > self.recovery_timeout:
                self.state = "half_open"
            else:
                return await fallback(*args, **kwargs)

        try:
            result = await func(*args, **kwargs)
            if self.state == "half_open":
                self.state = "closed"
                self.failure_count = 0
            return result
        except Exception:
            self.failure_count += 1
            self.last_failure_time = time.time()
            if self.failure_count >= self.failure_threshold:
                self.state = "open"
            return await fallback(*args, **kwargs)
