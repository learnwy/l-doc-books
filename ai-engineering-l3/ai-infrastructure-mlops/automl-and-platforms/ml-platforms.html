ML 平台

核心概念

ML 平台（Machine Learning Platform）是为组织中的数据科学家、ML 工程师和业务分析师提供统一的模型开发、训练、部署和管理能力的基础设施系统。它将分散的 ML 工具链整合为一站式的工程平台，降低 ML 落地的工程复杂度，提升团队的整体效率。

ML 平台的设计需要在标准化与灵活性之间找到平衡——过度标准化限制了创新，过度灵活则增加了维护成本。

开源 ML 平台方案
Kubeflow 是 Google 主导的开源 ML 平台，运行在 Kubernetes 之上。它由多个松耦合的组件组成：Kubeflow Pipelines（工作流编排）、Katib（超参搜索）、KServe（模型服务）、Notebooks（Jupyter 环境）和 Training Operator（分布式训练）。Kubeflow 的优势是与 Kubernetes 生态深度集成，适合已有 K8s 基础设施的团队。


MLflow 是 Databricks 开源的 ML 平台框架，以简洁和易用著称。它包含四个核心组件：Tracking（实验追踪）、Projects（可复现打包）、Models（模型管理）和 Model Registry（模型注册）。MLflow 可以独立部署，也可以作为更大平台的子组件使用。


import mlflow

mlflow.set_tracking_uri("http://mlflow-server:5000")
mlflow.set_experiment("recommendation-model-v3")

with mlflow.start_run():
    mlflow.log_params({"model_type": "two_tower", "embedding_dim": 128})

    model = train_recommendation_model(config)

    mlflow.log_metrics({"ndcg@10": 0.48, "recall@50": 0.72})
    mlflow.pytorch.log_model(model, "model", registered_model_name="rec-model")
Metaflow 是 Netflix 开源的人机交互式 ML 平台框架。它的独特设计是将 ML 工作流定义为 Python 类中的方法链，通过装饰器控制执行环境（本地 → AWS Batch → Kubernetes）。Metaflow 的版本快照机制可以自动保存每次运行的代码、数据和结果，实现任意历史运行的完整复现。


云厂商 ML 平台
AWS SageMaker、Google Vertex AI 和 Azure Machine Learning 是三大云厂商的 ML 平台，它们提供了开箱即用的全托管服务，覆盖 ML 全生命周期。


SageMaker 的核心优势是与 AWS 生态的深度集成。SageMaker Studio 提供了统一的 IDE 环境，SageMaker Training 支持分布式训练的一键启动，SageMaker Endpoints 提供了自动扩缩容的模型服务。SageMaker JumpStart 内置了数百个预训练模型的一键部署能力。


Vertex AI 是 Google Cloud 的 ML 平台，将 AutoML 和自定义模型训练统一为一个平台。Vertex AI Pipelines 基于 Kubeflow Pipelines 构建，提供了托管的流水线编排能力。Vertex AI Feature Store 提供了托管的特征存储服务。

多租户架构设计
企业级 ML 平台需要支持多个团队共享资源，同时保证资源隔离和公平分配。多租户架构的设计需要在共享效率和隔离安全之间找到平衡。


命名空间隔离是 Kubernetes 上多租户的基础方案。每个团队分配独立的 Namespace，通过 ResourceQuota 限制资源使用量，通过 NetworkPolicy 限制网络访问。但 Namespace 隔离是软隔离，无法完全防止侧信道攻击，对于高安全要求的场景需要使用虚拟集群或独立集群。


资源配额管理需要设计灵活的配额模型。固定配额简单但利用率低——团队未使用的配额浪费了。弹性配额允许团队在其他团队空闲时临时借用资源，但保证核心配额在需要时可以回收。优先级抢占机制确保高优先级任务在资源紧张时可以抢占低优先级任务。


class TenantResourceManager:
    def __init__(self):
        self.tenants = {}

    def register_tenant(self, tenant_id, config):
        self.tenants[tenant_id] = {
            "guaranteed_gpu": config["guaranteed_gpu"],
            "max_gpu": config["max_gpu"],
            "priority": config["priority"],
            "current_usage": 0,
        }

    def request_resources(self, tenant_id, gpu_count):
        tenant = self.tenants[tenant_id]
        total_available = self._get_available_gpus()

        if tenant["current_usage"] + gpu_count <= tenant["guaranteed_gpu"]:
            return self._allocate(tenant_id, gpu_count)

        if tenant["current_usage"] + gpu_count <= tenant["max_gpu"]:
            if total_available >= gpu_count:
                return self._allocate(tenant_id, gpu_count)
            return self._try_preempt(tenant_id, gpu_count)

        return None
平台成熟度演进
ML 平台的建设不是一次性工程，而是随组织 ML 成熟度逐步演进的过程。过早建设复杂平台会导致投入产出不成比例，过晚建设则会阻碍 ML 规模化。


第一阶段（0-6 个月）聚焦基础能力：统一的 Notebook 环境、基本的实验追踪（MLflow）和简单的模型部署流程。这个阶段的目标是让数据科学家能够高效地开发和迭代模型。


第二阶段（6-18 个月）建设自动化能力：ML 流水线编排、自动化训练和评估、模型注册和版本管理。这个阶段的目标是实现模型的持续交付。


第三阶段（18-36 个月）强化治理和规模化：多租户资源管理、模型监控和漂移检测、合规审计和权限控制、成本分析和优化。这个阶段的目标是支撑组织级的 ML 规模化运营。

小结
    

  • ML 平台将分散的 ML 工具链整合为一站式工程平台，是 ML 规模化的基础设施
    • 

  • Kubeflow 适合 K8s 原生团队，MLflow 适合快速起步，云厂商方案适合已锁定云平台的组织
    • 

  • 多租户架构需要在共享效率和隔离安全之间平衡，弹性配额是资源管理的最佳实践
    • 

  • 平台建设应随组织 ML 成熟度渐进演进，避免过早投入复杂平台建设
    • 

  • 成功的 ML 平台是技术和组织的结合体，需要平台团队与用户团队紧密协作
