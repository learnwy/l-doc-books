成本优化

核心概念

ML 工作负载是组织中最昂贵的云计算支出之一。GPU 实例的小时成本是 CPU 实例的 10-50 倍，大模型训练可能消耗数百万美元的计算资源，推理服务的 GPU 成本随流量线性增长。成本优化不是简单地减少资源使用，而是在保障 ML 系统性能和可靠性的前提下，最大化每单位投入的产出价值。

ML 成本优化的核心思路是从训练、推理和存储三个维度系统化地寻找优化空间。

训练成本优化
训练成本优化的核心策略是提升 GPU 利用率和缩短训练时间。GPU 利用率低是训练成本浪费的最大根因——调研显示，大多数组织的 GPU 训练集群平均利用率不足 30%。


竞价实例（Spot/Preemptible Instances）是降低训练成本的最直接手段。AWS Spot Instances 的价格通常是按需实例的 30-40%，但可能被随时回收。对于可容忍中断的训练任务，配合检查点恢复机制，竞价实例可以将训练成本降低 60-70%。


class SpotAwareTrainer:
    def __init__(self, config):
        self.config = config
        self.checkpoint_interval = config.get("checkpoint_minutes", 30)

    def train(self):
        start_step = self.load_checkpoint_if_exists()

        for step in range(start_step, self.config["total_steps"]):
            loss = self.train_step(step)

            if self.should_checkpoint(step):
                self.save_checkpoint(step)

            if self.spot_termination_notice():
                self.save_checkpoint(step, urgent=True)
                self.request_new_instance()
                break

    def spot_termination_notice(self):
        try:
            resp = requests.get(
                "http://169.254.169.254/latest/meta-data/spot/instance-action",
                timeout=1,
            )
            return resp.status_code == 200
        except Exception:
            return False
混合精度训练（Mixed Precision Training）通过使用 FP16/BF16 进行前向和反向传播，将训练速度提升 1.5-2 倍，同时减少显存占用使得可以使用更大的 batch size。梯度累积允许在小 batch size 下模拟大 batch size 的训练效果，使得较便宜的 GPU（如 A10G 替代 A100）也能训练大模型。


训练任务调度的优化也不可忽视。通过分析训练任务的资源使用模式，将互补的任务混合调度到同一组 GPU 上（如一个 GPU 密集型任务和一个 CPU 密集型任务共享节点），可以提升整体资源利用率。


推理成本优化
推理成本在模型上线后会持续增长，通常成为 ML 系统中占比最大的支出项。推理成本优化需要从模型优化、服务优化和资源优化三个层面入手。


模型级优化包括量化（INT8/INT4 降低每次推理的计算成本）、剪枝（减少模型参数量）和蒸馏（用小模型替代大模型）。这些技术在前面的章节已经详细介绍。在成本视角下，关键是量化模型的精度损失与成本节约之间的 ROI 计算。


服务级优化的核心是提升 GPU 利用率。动态批处理将多个请求合并为一个 batch 执行，使 GPU 的并行计算能力得到充分利用。模型共置（Model Co-location）将多个低流量模型部署到同一块 GPU 上，避免每个模型独占一块 GPU 导致的资源浪费。


class CostAnalyzer:
    def __init__(self, gpu_cost_per_hour, model_configs):
        self.gpu_cost = gpu_cost_per_hour
        self.configs = model_configs

    def analyze_inference_cost(self, model_name, daily_requests):
        config = self.configs[model_name]
        latency_ms = config["avg_latency_ms"]
        gpu_count = config["gpu_count"]

        requests_per_second = daily_requests / 86400
        gpu_utilization = (requests_per_second * latency_ms / 1000) / gpu_count

        daily_cost = gpu_count * self.gpu_cost * 24
        cost_per_request = daily_cost / daily_requests

        return {
            "daily_cost": daily_cost,
            "cost_per_request": cost_per_request,
            "gpu_utilization": gpu_utilization,
            "monthly_cost": daily_cost * 30,
        }

    def optimize_recommendation(self, analysis):
        recommendations = []
        if analysis["gpu_utilization"] < 0.3:
            recommendations.append("考虑模型共置或缩小实例规格")
        if analysis["cost_per_request"] > 0.01:
            recommendations.append("考虑模型量化降低单次推理成本")
        return recommendations
资源级优化包括自动扩缩容（根据流量动态调整实例数量）、预留实例和储蓄计划（对稳定的基线负载使用预留实例降低成本）、以及区域选择（选择 GPU 价格更低的云区域）。

FinOps 实践
FinOps（Financial Operations）是将财务管理实践引入云计算运营的方法论。在 ML 场景中，FinOps 的核心目标是建立成本透明度、成本问责制和成本优化的持续循环。


成本透明度要求将云计算账单拆分到每个团队、每个项目和每个模型级别。通过资源标签（Tag）标记每个 GPU 实例、存储桶和网络资源的归属，结合云厂商的成本报告工具（AWS Cost Explorer、GCP Billing），生成多维度的成本仪表盘。


成本问责制要求每个团队对自己的 ML 资源支出负责。设定团队级的成本预算和告警，当某个团队的 GPU 支出超过预算时自动通知团队负责人。定期进行成本审计，识别和清理闲置资源（如长时间未使用的模型端点、过期的训练数据备份）。


单位经济学（Unit Economics）分析是 ML FinOps 的高级实践。它将成本归因到业务指标上——每次模型预测的成本、每个活跃用户的 ML 成本、每增加 1% 准确率的边际成本。这些指标帮助决策者评估 ML 投入的商业回报。


GPU 资源利用率优化
GPU 利用率是 ML 成本优化的核心指标。低利用率意味着昂贵的 GPU 资源在空转。提升 GPU 利用率需要从任务调度、资源分配和工作负载优化三个维度入手。


GPU 分时复用（Time-Slicing）允许多个推理任务共享同一块 GPU 的计算时间。NVIDIA MPS（Multi-Process Service）提供了更细粒度的 GPU 共享能力，允许多个进程同时访问 GPU，减少上下文切换开销。对于小模型推理，GPU 分时复用可以将单 GPU 的利用率从 10-20% 提升到 60-80%。


GPU 显存超售（Memory Oversubscription）在推理场景下是一种激进但有效的策略。如果多个模型的显存占用总和超过 GPU 物理显存，但它们不会同时被密集访问，可以通过显存交换（GPU Memory Swap）到主机内存来实现超售。这种策略适用于多模型低流量的场景。


class GPUUtilizationOptimizer:
    def __init__(self, gpu_inventory):
        self.gpus = gpu_inventory

    def analyze_utilization(self):
        report = []
        for gpu in self.gpus:
            util = gpu.get_utilization()
            memory_util = gpu.get_memory_utilization()
            report.append({
                "gpu_id": gpu.id,
                "compute_util": util,
                "memory_util": memory_util,
                "status": self._classify(util, memory_util),
            })
        return report

    def _classify(self, compute, memory):
        if compute < 0.2 and memory < 0.3:
            return "idle"
        if compute < 0.5:
            return "underutilized"
        return "healthy"

    def recommend_actions(self, report):
        actions = []
        idle_gpus = [r for r in report if r["status"] == "idle"]
        if idle_gpus:
            actions.append(f"发现 {len(idle_gpus)} 块空闲 GPU，建议释放或合并工作负载")
        return actions
小结
    

  • ML 成本优化需要从训练、推理和存储三个维度系统化推进
    • 

  • 竞价实例 + 检查点恢复是训练成本优化的最直接手段，可降低 60-70% 成本
    • 

  • 推理成本优化需要模型级（量化/蒸馏）、服务级（批处理/共置）和资源级（扩缩容/预留）三层协同
    • 

  • FinOps 实践建立成本透明度和问责制，单位经济学分析帮助评估 ML 投入的商业回报
    • 

  • GPU 利用率是成本优化的核心指标，分时复用和模型共置是提升利用率的有效手段
