推理引擎

核心概念

推理引擎（Inference Engine）是将训练好的模型转化为高性能推理服务的核心软件层。它负责模型加载、计算图优化、内存管理和请求调度，目标是在满足延迟 SLA 的前提下最大化推理吞吐量。不同类型的模型（CNN、Transformer、LLM）和不同的硬件平台（GPU、CPU、NPU）需要选择不同的推理引擎。

推理引擎的选择取决于模型类型、目标硬件和性能要求的综合考量。

TensorRT 计算图优化
TensorRT 是 NVIDIA 推出的高性能深度学习推理优化器和运行时。它通过一系列计算图级别的优化将模型推理性能提升到硬件极限。


算子融合（Operator Fusion）是 TensorRT 最核心的优化手段。它将计算图中多个连续的算子合并为单个融合算子，减少 Kernel Launch 开销和中间结果的显存读写。常见的融合模式包括 Conv+BN+ReLU 融合、Linear+GeLU 融合和 Multi-Head Attention 融合。


import tensorrt as trt

logger = trt.Logger(trt.Logger.WARNING)
builder = trt.Builder(logger)
network = builder.create_network(
    1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH)
)

parser = trt.OnnxParser(network, logger)
with open("model.onnx", "rb") as f:
    parser.parse(f.read())

config = builder.create_builder_config()
config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, 1 << 30)
config.set_flag(trt.BuilderFlag.FP16)

profile = builder.create_optimization_profile()
profile.set_shape("input", min=(1, 3, 224, 224), opt=(8, 3, 224, 224), max=(32, 3, 224, 224))
config.add_optimization_profile(profile)

engine = builder.build_serialized_network(network, config)
TensorRT 还支持动态形状推理，允许同一个引擎处理不同 batch size 和序列长度的输入。构建时指定最小、最优和最大形状，运行时引擎自动选择最匹配的执行策略。


vLLM 与 PagedAttention
vLLM 是专为大语言模型设计的高吞吐推理引擎。LLM 推理的核心瓶颈不是计算，而是内存——KV Cache 的管理。在自回归生成过程中，每个 Token 都需要访问之前所有 Token 的 Key-Value 对，这些 KV Cache 随序列长度线性增长，很快耗尽 GPU 显存。


PagedAttention 是 vLLM 的核心创新，它借鉴了操作系统虚拟内存的分页机制来管理 KV Cache。传统实现为每个请求预分配最大序列长度的连续显存，造成大量浪费（实际生成长度往往远小于最大长度）。PagedAttention 将 KV Cache 分割为固定大小的 Block（类似内存页），按需分配和回收，通过页表维护逻辑序列到物理 Block 的映射。


vLLM 还实现了连续批处理（Continuous Batching），不同于传统的静态批处理需要等待一批请求全部完成。连续批处理在每个解码步都可以加入新请求或移除已完成的请求，大幅提升 GPU 利用率。结合 PagedAttention 和连续批处理，vLLM 可以将 LLM 推理吞吐量提升 2-24 倍。


from vllm import LLM, SamplingParams

llm = LLM(
    model="meta-llama/Llama-3-8B-Instruct",
    tensor_parallel_size=2,
    gpu_memory_utilization=0.9,
    max_model_len=4096,
)

sampling_params = SamplingParams(
    temperature=0.7,
    top_p=0.9,
    max_tokens=512,
)

outputs = llm.generate(["What is MLOps?", "Explain PagedAttention."], sampling_params)
ONNX Runtime 跨平台推理
ONNX Runtime 是微软开发的跨平台推理引擎，支持 ONNX 格式的模型在 CPU、GPU、NPU 等多种硬件上运行。它的核心优势是"一次导出，到处运行"的跨平台能力。


ONNX Runtime 通过 Execution Provider 抽象不同的硬件后端。CUDAExecutionProvider 利用 NVIDIA GPU 加速，TensorRTExecutionProvider 集成 TensorRT 优化，OpenVINOExecutionProvider 支持 Intel 硬件，CoreMLExecutionProvider 支持 Apple 设备。开发者可以用统一的 API 在不同硬件上运行同一个模型。


import onnxruntime as ort
import numpy as np

providers = [
    ("TensorrtExecutionProvider", {"trt_fp16_enable": True}),
    ("CUDAExecutionProvider", {"device_id": 0}),
    "CPUExecutionProvider",
]

session = ort.InferenceSession("model.onnx", providers=providers)

inputs = {"input_ids": np.array([[101, 2023, 2003]], dtype=np.int64)}
outputs = session.run(None, inputs)
ONNX Runtime 的图优化包括常量折叠、冗余节点消除、算子融合和内存规划。对于 Transformer 模型，它提供了专门的 Attention 融合优化，将 Q/K/V 投影、缩放点积注意力和输出投影合并为单个高效算子。

推理引擎性能调优
推理引擎的性能调优需要从多个维度入手：计算优化、内存优化和调度优化。


计算优化的核心是选择最优的 CUDA Kernel 实现。TensorRT 的 Auto-Tuning 功能在构建时针对目标 GPU 尝试多种 Kernel 实现，选择耗时最短的方案。FlashAttention 通过优化 SRAM 的访问模式，将 Attention 计算的显存访问量降低到 O(N) 级别，同时减少了 HBM 读写次数。


内存优化关注推理过程中显存的分配和复用。算子间的中间张量（Activation）可以通过内存规划实现复用——如果两个张量的生命周期不重叠，它们可以共享同一块显存。TensorRT 的内存规划器通过分析计算图的数据流来最小化显存峰值占用。


调度优化包括动态批处理（将多个请求合并为一个 batch 执行）和请求优先级管理。对于 LLM 推理，Speculative Decoding（推测解码）使用小模型快速生成候选 Token 序列，再用大模型一次性验证，可以在不降低输出质量的情况下提升生成速度 2-3 倍。


小结
    

  • 推理引擎的选择取决于模型类型和目标硬件，没有万能方案
    • 

  • TensorRT 通过算子融合和 Auto-Tuning 实现 GPU 推理的极致性能
    • 

  • vLLM 的 PagedAttention 和连续批处理是 LLM 高吞吐推理的关键技术
    • 

  • ONNX Runtime 通过 Execution Provider 抽象实现跨平台推理的统一体验
    • 

  • 性能调优需要从计算、内存和调度三个维度综合优化
