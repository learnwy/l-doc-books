模型压缩

核心概念

模型压缩（Model Compression）是一系列旨在减小模型规模、降低计算成本和内存占用的技术的总称。随着模型参数量从百万级增长到千亿级，模型压缩已成为连接研究成果与生产部署之间不可或缺的桥梁。压缩的核心假设是深度神经网络存在大量冗余——并非所有参数都对模型性能做出同等贡献。

不同压缩技术在压缩比、精度损失、实现复杂度和硬件依赖等维度上各有取舍。

低秩分解
低秩分解（Low-Rank Factorization）的核心思想是将大权重矩阵分解为两个较小矩阵的乘积。对于一个形状为 m×n 的权重矩阵 W，将其分解为 W ≈ AB，其中 A 的形状为 m×r，B 的形状为 r×n，r 远小于 min(m, n)。这样，原本需要 m×n 个参数，现在只需要 r×(m+n) 个参数。


SVD（奇异值分解）是最经典的低秩分解方法。对权重矩阵做 SVD 分解 W = UΣV^T，保留最大的 r 个奇异值及对应的奇异向量，即可得到秩为 r 的近似。保留的奇异值数量 r 决定了压缩比和近似精度之间的权衡。


import torch

def svd_compress(weight, rank):
    U, S, Vt = torch.linalg.svd(weight, full_matrices=False)
    U_r = U[:, :rank]
    S_r = S[:rank]
    Vt_r = Vt[:rank, :]
    A = U_r @ torch.diag(S_r)
    B = Vt_r
    return A, B

original = torch.randn(4096, 4096)
A, B = svd_compress(original, rank=256)

original_params = 4096 * 4096
compressed_params = 4096 * 256 + 256 * 4096
compression_ratio = original_params / compressed_params
LoRA（Low-Rank Adaptation）是低秩分解在大模型微调中的成功应用。LoRA 不直接分解原始权重，而是冻结原权重 W₀，只训练一对低秩矩阵 ΔW = AB。推理时将 W₀ + AB 合并为单个矩阵，不增加推理延迟。这个方法将微调所需的可训练参数从数十亿降低到数百万，同时保持了与全量微调相当的效果。


权重共享与聚类
权重共享（Weight Sharing）通过让多个连接共享同一个权重值来减少模型的有效参数量。最典型的实现是 k-means 权重聚类：将权重值聚为 k 个簇，同一簇内的所有权重用簇中心值替代。存储时只需保存 k 个中心值和每个权重的簇索引。


当 k=256 时，每个权重的簇索引只需 8 位（1 字节）存储，加上 256 个 FP32 中心值（1KB），相比原始的 FP32 权重（4 字节/权重），可以实现约 4 倍压缩。更激进的配置使用 k=16（4 位索引），压缩比可达 8 倍。


Transformer 架构中的跨层权重共享是另一种有效策略。ALBERT 模型通过让所有 Transformer 层共享相同的参数，将 BERT-Large 的参数量从 334M 降至 12M（压缩 28 倍），同时在多数 NLP 任务上保持了有竞争力的性能。这表明 Transformer 的不同层在学习相似的表示变换。


紧凑架构设计
紧凑架构设计（Compact Architecture Design）从模型结构层面减少冗余，通过设计更高效的网络模块实现更优的精度-效率平衡。这种方法不是压缩已有模型，而是从一开始就设计更高效的模型。


深度可分离卷积（Depthwise Separable Convolution）是 MobileNet 的核心创新。它将标准卷积分解为逐通道的深度卷积和 1×1 的逐点卷积，计算量降至标准卷积的 1/k²（k 为卷积核大小）。MobileNetV2 进一步引入了倒残差结构和线性瓶颈，在移动端推理中达到了精度与效率的最佳平衡。


对于 Transformer 模型，MoE（Mixture of Experts）架构通过稀疏激活实现了参数量与计算量的解耦。一个包含 64 个专家的 MoE 层，每次推理只激活 2 个专家，实际计算量只有密集模型的 1/32，但模型容量远大于同等计算量的密集模型。

组合压缩策略
实际生产中，单一压缩技术往往不能满足部署要求，需要组合多种压缩方法。组合策略的设计需要考虑技术之间的兼容性和压缩效果的叠加性。


常见的组合路径是"蒸馏 + 量化"：先用大模型蒸馏出小模型（缩小架构），再对小模型做量化（降低精度）。另一条路径是"剪枝 + 量化"：先剪枝去除冗余通道/层（减少计算量），再量化剩余参数（减少内存占用）。这两条路径可以进一步组合为"蒸馏 + 剪枝 + 量化"的三段式压缩。


压缩效果并非简单叠加。例如，已经蒸馏过的小模型对量化的鲁棒性可能不如原始大模型，因为蒸馏已经移除了部分冗余，剩余参数的精度更加敏感。因此，量化感知蒸馏（Quantization-Aware Distillation）将蒸馏和量化统一到一个训练过程中，让学生模型在量化约束下学习教师模型的知识。


class CompressionPipeline:
    def __init__(self, teacher_model, target_model):
        self.teacher = teacher_model
        self.target = target_model

    def run(self):
        pruned = self.structural_prune(self.target, sparsity=0.5)
        distilled = self.distill(self.teacher, pruned, epochs=10)
        quantized = self.quantize(distilled, bits=8)
        return quantized

    def evaluate(self, model, test_data):
        metrics = {
            "accuracy": compute_accuracy(model, test_data),
            "latency_ms": measure_latency(model),
            "model_size_mb": get_model_size(model),
            "memory_mb": measure_memory(model),
        }
        return metrics
小结
    

  • 模型压缩的核心假设是深度网络存在大量冗余，不同技术从不同维度消除冗余
    • 

  • 低秩分解和权重共享是最轻量的压缩手段，LoRA 是大模型微调的事实标准
    • 

  • 紧凑架构设计从根本上提高模型效率，MoE 通过稀疏激活实现了参数量与计算量的解耦
    • 

  • 生产部署通常需要组合多种压缩技术，组合顺序和方法的兼容性是设计的关键
    • 

  • 选择压缩策略时需要综合考虑目标精度、延迟要求、内存限制和目标硬件平台
