数据管道

核心概念

训练数据管道（Data Pipeline）是连接原始数据存储与 GPU 计算的关键基础设施。它负责数据的加载、解码、预处理、增强和批处理，最终将张量送入 GPU 显存。在大规模训练中，数据管道的吞吐量必须匹配 GPU 的计算速度，否则 GPU 将陷入等待数据的空闲状态，造成昂贵计算资源的浪费。

高效的数据管道需要在存储 I/O、CPU 预处理和 GPU 传输三个环节之间建立流水线，使它们可以并行执行。

数据格式与存储优化
数据格式的选择直接影响数据管道的 I/O 吞吐量。训练数据应使用列式二进制格式（如 Apache Parquet、TFRecord、WebDataset），而非行式文本格式（CSV、JSON）。二进制格式的优势在于紧凑的编码减少了存储和传输量，列式布局支持按需读取特定字段，内置的压缩（Snappy、Zstd）进一步降低 I/O。


对于大规模非结构化数据（图像、音频、视频），WebDataset 是一种高效的数据打包格式。它将多个样本打包为 TAR 归档文件，每个 TAR 文件包含数百到数千个样本。这种设计避免了海量小文件带来的文件系统元数据开销，支持顺序读取以最大化磁盘吞吐量。


import webdataset as wds

dataset = (
    wds.WebDataset("s3://bucket/train-{000..999}.tar")
    .shuffle(10000)
    .decode("pil")
    .to_tuple("image.jpg", "label.txt")
    .map_tuple(transform_image, int)
    .batched(32)
)

dataloader = wds.WebLoader(dataset, num_workers=8, batch_size=None)
数据存储的分层架构是大规模训练的标准实践。冷数据存储在低成本的对象存储（S3、GCS）中，作为数据的持久副本。热数据缓存在高速的本地 NVMe SSD 或分布式文件系统（Lustre、GPFS）中，提供训练所需的高吞吐量读取。数据预取（Prefetch）策略在训练开始前将即将使用的数据从冷存储拉取到热缓存。


多进程数据加载
PyTorch DataLoader 的多进程加载是提升 CPU 预处理吞吐量的标准手段。通过 num_workers 参数指定子进程数量，每个子进程独立执行数据加载和预处理，主进程只负责消费处理好的批次。


num_workers 的最优值取决于 CPU 核心数、预处理复杂度和 GPU 数量。经验规则是每块 GPU 配置 4-8 个 Worker。设置过多的 Worker 会导致进程间的内存竞争和上下文切换开销超过并行收益。


from torch.utils.data import DataLoader, DistributedSampler

sampler = DistributedSampler(
    dataset,
    num_replicas=world_size,
    rank=rank,
    shuffle=True,
    seed=42,
)

dataloader = DataLoader(
    dataset,
    batch_size=32,
    sampler=sampler,
    num_workers=8,
    pin_memory=True,
    prefetch_factor=4,
    persistent_workers=True,
    drop_last=True,
)
pin_memory=True 将数据加载到页锁定内存（Pinned Memory）中，避免了 Host-to-Device 传输时的内存拷贝，显著提升 PCIe 传输速度。prefetch_factor 控制每个 Worker 预加载的批次数量，值越大预取越激进，但消耗更多 CPU 内存。persistent_workers=True 避免每个 epoch 重新创建 Worker 进程，减少初始化开销。


对于超大规模数据集，可以使用流式数据加载（Streaming DataLoader）避免将整个数据集索引加载到内存。MosaicML 的 StreamingDataset 和 Hugging Face 的 Datasets 库都支持从远程存储流式读取数据，每次只在内存中保留当前批次的数据。


数据增强与预处理加速
数据增强（Data Augmentation）是提升模型泛化能力的关键技术，但复杂的增强操作可能成为数据管道的 CPU 瓶颈。解决方案是将部分预处理操作迁移到 GPU 上执行。


NVIDIA DALI（Data Loading Library）是 GPU 加速数据预处理的专用库。它将图像解码、缩放、裁剪、颜色变换等操作移到 GPU 上执行，通过流水线化实现与训练计算的并行。在图像训练场景中，DALI 可以将数据管道吞吐量提升 2-5 倍。


from nvidia.dali import pipeline_def, fn, types

@pipeline_def(batch_size=64, num_threads=4, device_id=0)
def training_pipeline():
    jpegs, labels = fn.readers.file(
        file_root="/data/imagenet/train",
        random_shuffle=True,
    )
    images = fn.decoders.image(jpegs, device="mixed")
    images = fn.resize(images, resize_x=256, resize_y=256)
    images = fn.crop_mirror_normalize(
        images,
        crop=(224, 224),
        mean=[0.485, 0.456, 0.406],
        std=[0.229, 0.224, 0.225],
        mirror=fn.random.coin_flip(),
    )
    return images, labels
对于 NLP 任务，Tokenization 通常是预处理的瓶颈。HuggingFace Tokenizers 库使用 Rust 实现的高性能 Tokenizer，支持批量并行分词。对于超大规模语料，建议将 Tokenization 作为离线预处理步骤，将分词结果保存为二进制格式，训练时直接加载 Token ID 序列。

分布式数据管道与数据分片
在分布式训练中，每块 GPU 需要处理不同的数据子集，这要求数据管道具备高效的分片和去重能力。DistributedSampler 是 PyTorch 中最基础的分片方案，它将数据集的索引按 GPU 数量均匀切分，确保每块 GPU 看到不同的数据。


对于流式数据集，分片策略需要更精细的设计。一种常见模式是将数据预先切分为多个物理分片文件（Shard），每块 GPU 负责读取特定的分片集合。这避免了在运行时动态计算分片索引的开销，也简化了 Worker 之间的协调。


数据去重和采样策略也是分布式数据管道的重要组成部分。课程学习（Curriculum Learning）按样本难度渐进式地调整采样概率，先训练简单样本再逐步增加难样本。数据混合（Data Mixing）在多任务学习中按预定比例从不同数据源采样，确保各任务的训练数据量符合设计预期。


小结
    

  • 数据管道的吞吐量必须匹配 GPU 计算速度，否则 GPU 空闲即资源浪费
    • 

  • 使用二进制格式（Parquet、WebDataset）和分层存储架构优化 I/O 吞吐量
    • 

  • 多进程加载配合 Pinned Memory 和预取是 PyTorch 数据管道的标准优化组合
    • 

  • GPU 预处理（DALI）和离线预处理是突破 CPU 瓶颈的两种互补策略
    • 

  • 分布式场景下的数据分片和采样策略直接影响训练效率和模型质量
