训练编排

核心概念

训练编排（Training Orchestration）是管理复杂训练工作流的系统化方法，涵盖超参数搜索调度、多阶段训练流程管理、检查点策略和故障自动恢复。大规模训练任务通常持续数天甚至数周，涉及多次重试、恢复和调参迭代，没有系统化的编排能力，训练过程将充满不确定性和资源浪费。

训练编排的核心价值是将"人盯训练"的手动模式升级为"配置驱动"的自动化模式。

超参数搜索调度
超参数搜索是模型开发中最耗费计算资源的环节。一次完整的超参数搜索可能需要运行数百次训练实验，每次实验消耗数小时的 GPU 时间。高效的搜索调度策略可以在有限的计算预算内找到更优的超参数配置。


网格搜索（Grid Search）穷举所有超参数组合，简单但计算量随维度指数增长。随机搜索（Random Search）在超参数空间中随机采样，研究表明在大多数场景下效率优于网格搜索，因为它可以在高维空间中更均匀地探索。


贝叶斯优化（Bayesian Optimization）是最先进的超参数搜索策略。它使用高斯过程或树结构模型（TPE）建立超参数到性能指标的代理模型，根据代理模型预测的期望提升（Expected Improvement）选择下一组候选超参数。每次实验结果都用于更新代理模型，使搜索越来越精准。


import optuna

def objective(trial):
    lr = trial.suggest_float("learning_rate", 1e-5, 1e-3, log=True)
    batch_size = trial.suggest_categorical("batch_size", [16, 32, 64])
    warmup_ratio = trial.suggest_float("warmup_ratio", 0.0, 0.2)
    weight_decay = trial.suggest_float("weight_decay", 1e-4, 0.1, log=True)

    model = create_model()
    accuracy = train_and_evaluate(model, lr, batch_size, warmup_ratio, weight_decay)

    return accuracy

study = optuna.create_study(
    direction="maximize",
    sampler=optuna.samplers.TPESampler(seed=42),
    pruner=optuna.pruners.HyperbandPruner(),
)
study.optimize(objective, n_trials=100, n_jobs=4)
早停剪枝（Early Stopping Pruning）是加速超参搜索的关键技术。Hyperband 算法将计算预算分为多轮（Bracket），每轮启动大量实验但只分配少量训练轮次，根据中间结果淘汰表现差的实验，将资源集中到有潜力的配置上。这种"赛马"机制可以将搜索效率提升 10-50 倍。


检查点策略与断点续训
检查点（Checkpoint）是训练编排中最关键的容错机制。训练过程定期保存模型状态快照，当训练中断时可以从最近的检查点恢复，避免从头开始。


检查点的保存频率需要权衡 I/O 开销和恢复损失。保存过频繁会拖慢训练速度（大模型的检查点可能超过 100GB），保存过稀疏则在故障时丢失较多训练进度。经验规则是每 1-2 小时保存一次，或每 500-2000 个训练步保存一次。


class CheckpointManager:
    def __init__(self, save_dir, max_keep=5):
        self.save_dir = save_dir
        self.max_keep = max_keep

    def save(self, model, optimizer, scheduler, step, metrics):
        state = {
            "model": model.state_dict(),
            "optimizer": optimizer.state_dict(),
            "scheduler": scheduler.state_dict(),
            "step": step,
            "metrics": metrics,
            "rng_states": {
                "python": random.getstate(),
                "numpy": np.random.get_state(),
                "torch": torch.random.get_rng_state(),
                "cuda": torch.cuda.get_rng_state_all(),
            },
        }
        path = os.path.join(self.save_dir, f"checkpoint-{step}")
        torch.save(state, path)
        self._cleanup_old_checkpoints()

    def load_latest(self, model, optimizer, scheduler):
        latest = self._find_latest_checkpoint()
        if latest is None:
            return 0
        state = torch.load(latest)
        model.load_state_dict(state["model"])
        optimizer.load_state_dict(state["optimizer"])
        scheduler.load_state_dict(state["scheduler"])
        self._restore_rng_states(state["rng_states"])
        return state["step"]
异步检查点保存是减少 I/O 对训练影响的重要优化。DeepSpeed 和 FSDP 都支持将检查点保存操作放到后台线程执行，训练主循环在发起保存后立即继续下一个训练步。分布式检查点中，每块 GPU 只保存自己负责的参数分片，避免在单节点上汇聚全量模型。


多阶段训练流程
现代大模型训练通常包含多个阶段：预训练（Pre-training）、继续预训练（Continued Pre-training）、有监督微调（SFT）和对齐训练（RLHF/DPO）。每个阶段有不同的数据、超参数和训练策略，需要编排系统将它们有序衔接。


多阶段训练的编排挑战在于阶段之间的依赖管理。后续阶段依赖前序阶段产出的模型检查点，且不同阶段可能需要不同的计算资源配置。例如，预训练需要大量 GPU 进行分布式训练，而 SFT 可能只需要少量 GPU 进行 LoRA 微调。

Kubernetes Job 和 Argo Workflows 是多阶段训练编排的常用工具。通过 DAG 定义阶段间的依赖关系，每个阶段作为独立的 Job 运行，后续阶段在前序阶段成功完成后自动启动。


训练监控与告警
训练编排系统需要实时监控训练任务的健康状态，及时发现异常并触发告警或自动干预。监控指标分为三类：系统指标、训练指标和数据指标。


系统指标包括 GPU 利用率、显存使用率、CPU/内存使用率、磁盘 I/O 和网络带宽。训练指标包括训练 Loss、学习率、梯度范数、训练吞吐量（Tokens/sec 或 Samples/sec）。数据指标包括数据加载延迟、数据管道吞吐量和数据质量异常计数。


常见的训练异常模式包括：Loss 突然飙升（可能是数据异常或学习率过大）、Loss 长时间不下降（可能是学习率过小或数据不足）、GPU 利用率骤降（可能是数据管道瓶颈或通信阻塞）、梯度范数异常（可能是数值不稳定）。


梯度范数监控是早期发现训练不稳定的关键手段。正常训练中，梯度范数应在相对稳定的范围内波动。如果梯度范数持续增大，可能预示着即将出现 Loss 爆炸，此时应触发梯度裁剪或自动降低学习率。


小结
    

  • 训练编排将手动的训练管理升级为配置驱动的自动化系统，是大规模训练的必备能力
    • 

  • 贝叶斯优化 + Hyperband 剪枝是当前最高效的超参数搜索策略组合
    • 

  • 检查点是训练容错的核心机制，需要在保存频率和 I/O 开销之间找到平衡
    • 

  • 多阶段训练需要编排系统管理阶段间的模型依赖和资源差异
    • 

  • 完善的训练监控体系应覆盖系统、训练和数据三个层面的指标，支持自动化告警和干预
