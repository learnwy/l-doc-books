分布式训练框架

核心概念

当模型规模超出单块 GPU 的显存容量，或训练数据量庞大需要加速训练时，分布式训练成为必然选择。分布式训练的核心思想是将训练工作负载分散到多块 GPU 上并行执行，通过高效的通信协议同步梯度或中间结果。

分布式训练的并行策略是整个领域的核心知识框架。不同的并行策略适用于不同的模型规模和硬件配置。

数据并行与梯度同步
数据并行（Data Parallelism, DP）是最基础也是最常用的并行策略。每块 GPU 持有完整的模型副本，但只处理全局 batch 的一个子集。每个前向-反向传播周期结束后，所有 GPU 通过 AllReduce 操作聚合梯度，然后各自用相同的聚合梯度更新参数，保证所有副本的参数始终一致。


PyTorch DistributedDataParallel（DDP）是数据并行的标准实现。DDP 通过梯度桶化（Gradient Bucketing）优化通信效率——将多个小张量的梯度打包成大桶，减少 AllReduce 的调用次数。DDP 还支持梯度计算与通信的重叠（Overlap），在反向传播的同时开始同步已计算完成的梯度桶，隐藏通信延迟。


import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP

dist.init_process_group(backend="nccl")
local_rank = int(os.environ["LOCAL_RANK"])
torch.cuda.set_device(local_rank)

model = LargeModel().cuda(local_rank)
model = DDP(model, device_ids=[local_rank], find_unused_parameters=False)

optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)

for batch in dataloader:
    loss = model(batch)
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
ZeRO（Zero Redundancy Optimizer）是 DeepSpeed 提出的革命性优化，它将 DP 中每块 GPU 冗余存储的优化器状态、梯度和参数分散到所有 GPU 上。ZeRO Stage 1 分片优化器状态（节省 4x 显存），Stage 2 额外分片梯度（节省 8x），Stage 3 连参数也分片（理论上每卡只需 1/N 的显存）。PyTorch FSDP（Fully Sharded Data Parallel）是 ZeRO Stage 3 的原生 PyTorch 实现。


模型并行与张量并行
当单层的参数量超出单卡显存（如大模型的 Embedding 层或 LM Head），需要使用模型并行将层内权重切分到多块 GPU 上。张量并行（Tensor Parallelism, TP）是模型并行的主要实现方式，它将矩阵运算沿特定维度切分。


Megatron-LM 定义了 Transformer 中张量并行的标准切分方式。对于 MLP 层中的两个线性变换 Y = GeLU(XA)B，第一个矩阵 A 按列切分，第二个矩阵 B 按行切分。这种切分方式的妙处在于中间结果不需要通信，只在最终输出时执行一次 AllReduce。对于自注意力层，Q/K/V 投影按注意力头切分，每块 GPU 处理一部分注意力头。


流水线并行（Pipeline Parallelism, PP）将模型的层按顺序分组，每组放在一块 GPU 上。前向传播时，第一组计算完激活值后传递给第二组，依此类推。朴素的流水线并行会导致严重的气泡（Bubble）——大部分时间只有一块 GPU 在工作。GPipe 和 PipeDream 通过微批次（Micro-batch）流水线技术显著减少气泡，将全局 batch 切分为多个微批次，让多块 GPU 可以同时处理不同微批次的不同阶段。


from torch.distributed.pipelining import SplitPoint, pipeline

pipe = pipeline(
    module=model,
    mb_args=(micro_batch,),
    split_spec={
        "layers.12": SplitPoint.BEGINNING,
        "layers.24": SplitPoint.BEGINNING,
        "layers.36": SplitPoint.BEGINNING,
    },
)

pipe.step(micro_batches=8)
实际的大模型训练通常采用 3D 并行——同时使用数据并行、张量并行和流水线并行。例如，在 64 块 GPU 上训练 175B 模型，可以配置 TP=8（8 块 GPU 做张量并行）、PP=4（4 组流水线）、DP=2（2 路数据并行），总共 8×4×2=64 块 GPU。


DeepSpeed 与 Megatron-LM
DeepSpeed 是微软开发的深度学习优化库，以 ZeRO 系列技术为核心。除了 ZeRO 数据并行优化，DeepSpeed 还提供了 ZeRO-Offload（将优化器状态卸载到 CPU 内存或 NVMe）、ZeRO-Infinity（利用 NVMe 扩展"显存"容量）、混合精度训练和稀疏注意力等优化技术。


import deepspeed

model, optimizer, _, _ = deepspeed.initialize(
    model=model,
    config={
        "train_batch_size": 256,
        "gradient_accumulation_steps": 8,
        "fp16": {"enabled": True},
        "zero_optimization": {
            "stage": 3,
            "offload_optimizer": {"device": "cpu"},
            "offload_param": {"device": "cpu"},
            "overlap_comm": True,
            "contiguous_gradients": True,
        },
    },
)
Megatron-LM 是 NVIDIA 开发的大模型训练框架，专注于 Transformer 架构的极致优化。它提供了高效的张量并行和流水线并行实现，以及针对 Transformer 的 Fused Kernel（融合算子，如 Fused Softmax、Fused LayerNorm）。Megatron-LM 通常与 DeepSpeed 结合使用，形成 Megatron-DeepSpeed 方案，兼顾两者的优势。

通信后端与拓扑优化
分布式训练的通信效率直接决定了训练的扩展效率（Scaling Efficiency）。NCCL（NVIDIA Collective Communications Library）是 GPU 间集合通信的标准后端，支持 AllReduce、AllGather、ReduceScatter 等集合操作，并能自动感知 NVLink、NVSwitch 和 InfiniBand 的拓扑结构选择最优通信路径。


通信优化的核心策略包括梯度压缩（Gradient Compression）和通信-计算重叠（Communication-Computation Overlap）。梯度压缩通过 Top-K 稀疏化或低精度量化减少通信数据量。通信-计算重叠在反向传播的同时启动梯度同步，使通信延迟被计算时间隐藏。


InfiniBand 网络在大规模集群中至关重要。相比以太网，InfiniBand 提供了更高的带宽（400Gbps HDR）、更低的延迟（<1μs）和 RDMA（Remote Direct Memory Access）能力。GPUDirect RDMA 允许 GPU 直接读写远端 GPU 的显存，跳过 CPU 和系统内存的拷贝，进一步降低通信延迟。


小结
    

  • 分布式训练的并行策略按切分维度分为数据、张量、流水线、序列和专家并行，大模型通常采用 3D 并行组合
    • 

  • ZeRO 通过分片优化器状态、梯度和参数，在数据并行的简洁性基础上实现了显存线性扩展
    • 

  • PyTorch FSDP 适合中等规模模型的快速上手，DeepSpeed + Megatron-LM 组合适合超大规模训练
    • 

  • 通信效率是分布式训练扩展性的关键瓶颈，NVLink + InfiniBand + RDMA 是高性能通信的硬件基础
    • 

  • 选择框架时需要综合考虑模型规模、团队技术栈和可用硬件配置
    •
