Memory 记忆系统

核心概念

在 AI 编程中，记忆（Memory）是指 AI 在对话之间以及跨会话中持久化和检索信息的能力。如果上下文决定了"AI 这一轮能看到什么"，那么记忆决定的是"AI 在全新对话中还能记住什么"。

人类开发者在长期合作中会积累对项目的深层理解——编码风格偏好、架构约定、曾经踩过的坑、团队的技术选型原则。AI 的记忆系统试图模拟这种能力，让 AI 不仅是一个无状态的代码生成器，而是一个能够逐渐"了解"你和你项目的编程伙伴。

短期记忆 vs 长期记忆
短期记忆本质上就是当前对话的上下文窗口内容。它的特点是：


    

  • 容量受上下文窗口限制
    • 

  • 会话结束后自动丢失
    • 

  • 随对话推进不断更新
    • 



长期记忆则通过外部存储机制实现跨会话的信息持久化：


    

  • 存储在文件系统、数据库或云端
    • 

  • 新会话开始时自动或按需加载
    • 

  • 需要主动管理（写入、更新、清理）
    • 



记忆的生命周期
interface MemorySystem {
  encode(interaction: Interaction): MemoryEntry;
  store(entry: MemoryEntry): void;
  retrieve(query: string): MemoryEntry[];
  consolidate(): void;
  forget(criteria: ForgetCriteria): void;
}

interface MemoryEntry {
  id: string;
  type: 'episodic' | 'semantic' | 'procedural';
  content: string;
  timestamp: number;
  relevance: number;
  source: string;
}
记忆的生命周期包含五个阶段：


    

  1. 编码：将交互信息转化为可存储的记忆条目
    2. 

  2. 存储：将记忆条目写入持久化存储
    3. 

  3. 检索：根据当前上下文查找相关的历史记忆
    4. 

  4. 巩固：合并冗余记忆、提炼关键信息
    5. 

  5. 遗忘：清理过时或不再相关的记忆
    6. 





关键要素
情景记忆：对话历史
情景记忆记录的是"发生了什么"——具体的对话内容、AI 执行的操作、产生的结果。它是最直观的记忆形式：


episodic_memory:
  - session: '2026-03-28T10:30:00Z'
    summary: '重构了用户认证模块，将 JWT 刷新逻辑抽取为独立服务'
    files_modified:
      - src/auth/token-service.ts
      - src/auth/middleware.ts
    outcome: '成功，所有测试通过'

  - session: '2026-03-27T14:00:00Z'
    summary: '排查了数据库连接池泄漏问题'
    root_cause: '事务未在 finally 中释放连接'
    files_modified:
      - src/db/connection-pool.ts
    outcome: '修复成功'
语义记忆：事实与偏好
语义记忆存储的是脱离了具体事件的通用知识——项目规则、用户偏好、技术栈信息：


{
  "project_facts": {
    "language": "TypeScript 5.x",
    "runtime": "Node.js 22",
    "package_manager": "pnpm",
    "test_framework": "Vitest",
    "style": "ESLint + Prettier",
    "architecture": "模块化单体，按功能划分目录"
  },
  "user_preferences": {
    "code_style": "函数式优先，避免 class",
    "naming": "camelCase for variables, PascalCase for types",
    "error_handling": "偏好 Result 模式而非 try-catch",
    "comments": "代码应自解释，仅在复杂逻辑处添加注释"
  }
}
程序性记忆：学到的模式
程序性记忆是 AI 从反复交互中"学到"的行为模式，类似于肌肉记忆：


模式 1：用户提交代码前总是要求先运行 lint 和 typecheck
模式 2：用户偏好在修改代码后立即查看 diff
模式 3：用户习惯用 @codebase 搜索后再精确引用文件
模式 4：错误修复时，用户总是要求同时补充测试用例


实际应用
Trae 的 ai-brain 系统
Trae 通过 ai-brain 技能实现了一套完整的记忆管理系统：


~/.learnwy/ai/memory/
├── identity/
│   ├── AI.md           ← AI 的身份定义
│   └── you.md          ← 用户画像
├── conversation/
│   └── history/        ← 近期对话记录
└── deeper/             ← 深层长期知识
其核心工作流程：


# 会话开始 → 加载身份和历史记忆
bash ~/.trae-cn/skills/ai-brain/scripts/session.sh start

# 会话中 → 追加重要信息到历史
bash ~/.trae-cn/skills/ai-brain/scripts/append-history.sh "完成认证模块重构"

# 会话结束 → 反思并巩固记忆
bash ~/.trae-cn/skills/ai-brain/scripts/session.sh end
这种基于文件系统的方案简单透明——用户可以直接查看和编辑 AI 的记忆内容。


Claude 的记忆文件
Claude Code 通过 CLAUDE.md 文件实现项目级记忆：


<!-- CLAUDE.md — 放置在项目根目录 -->

## 项目概述

这是一个电商平台的后端服务，使用 TypeScript + Fastify。

## 编码规范

- 所有 API 返回统一的 Result 类型
- 数据库操作必须在 Service 层，Controller 不直接访问数据库
- 使用 Zod 进行请求参数校验

## 注意事项

- 不要修改 src/legacy/ 目录下的代码
- 支付模块的测试需要 mock 第三方 API
Claude 在每次会话开始时自动读取该文件，将其中的信息注入系统提示词。这种方式的优势在于版本控制友好——CLAUDE.md 可以随代码一起提交到 Git 仓库。

常见误区
误区一：AI 自动记住一切
当前的 AI 编程工具不会自动记住所有交互细节。除非通过专门的记忆机制（如 ai-brain 脚本或 CLAUDE.md 文件），否则每次新对话都是从零开始。


误区二：记忆文件越详细越好
过长的记忆文件会占用宝贵的上下文窗口空间。记忆应该是精炼的、高信号密度的——记录"什么该做、什么不该做"，而不是完整的历史叙述。


误区三：忽视记忆的维护
记忆需要定期更新和清理。过时的记忆（如已弃用的架构决策、已删除的模块信息）不仅浪费上下文空间，还可能误导 AI 做出错误判断。


误区四：将所有信息放在同一层
不同类型的记忆应该分层管理。项目级规则放在 .cursorrules 或 CLAUDE.md 中，个人偏好放在全局配置中，临时上下文留在对话中。混合存放会导致信息冲突和管理混乱。




小结
    

  • AI 的记忆分为情景记忆（对话历史）、语义记忆（事实和偏好）和程序性记忆（行为模式）三种类型。
    • 

  • 短期记忆即当前对话的上下文，会话结束后消失；长期记忆通过外部存储实现跨会话持久化。
    • 

  • 记忆的生命周期包括编码、存储、检索、巩固和遗忘五个阶段。
    • 

  • 主流 AI 编程工具通过不同机制实现记忆：Trae 的 ai-brain（全局文件系统）、Claude 的 CLAUDE.md（项目级文件）、Cursor 的 .cursorrules（项目规则文件）。
    • 

  • 有效的记忆管理需要精炼、分层、定期维护，避免信息过时或冲突。
    • 

  • 记忆与上下文互补：记忆提供跨会话的持久知识，上下文提供单次会话的实时信息。
    •
