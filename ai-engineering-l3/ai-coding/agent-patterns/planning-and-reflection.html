Part I · FoundationsAI 编程 简介Agent 架构 简介规划与反思

规划与反思

问题背景

ReAct 模式让 Agent 具备了"边想边做"的能力，但它本质上是一种反应式（reactive）的策略——Agent 在每一步只考虑当前状态和下一步行动，缺乏对整体任务的全局视角。当面对复杂的多步任务时，这种逐步摸索的方式可能导致方向偏移、重复劳动或遗漏关键步骤。

我们需要让 Agent 具备两种更高层的认知能力：先想后做（规划）和做完回头看（反思）。




模式定义
Plan-Execute 模式
Plan-Execute（规划-执行）模式将 Agent 的工作分为两个明确的阶段：先由 Planner 生成一个完整的任务计划，再由 Executor 逐步执行。两个阶段可以由同一个 LLM 驱动，也可以使用不同的模型。


Reflection（反思）模式
反思模式是指 Agent 在执行完一个步骤或整个任务后，对自身的输出进行自我批判和评估，从而发现错误并改进。

提示： 规划和反思并非互斥——最强大的 Agent 同时具备这两种能力，形成"规划 → 执行 → 反思 → 重规划"的完整循环。






工作流程
任务分解（Task Decomposition）
规划的第一步是将大任务分解为小的、可执行的子任务。分解策略直接影响执行效率：


interface TaskDecomposition {
  originalTask: string;
  steps: PlannedStep[];
  dependencies: DependencyGraph;
  estimatedComplexity: 'low' | 'medium' | 'high';
}

interface PlannedStep {
  id: string;
  description: string;
  rationale: string;
  dependencies: string[];
  estimatedTools: string[];
  acceptanceCriteria: string;
}

interface DependencyGraph {
  nodes: string[];
  edges: Array<{ from: string; to: string }>;
  parallelGroups: string[][];
}

自适应重规划（Adaptive Replanning）
执行过程中，原始计划可能因为意外发现而需要调整。自适应重规划在每个步骤执行后评估是否需要修改后续计划：


async function adaptiveExecute(plan: TaskDecomposition, context: AgentContext): Promise<ExecutionResult> {
  const results: StepResult[] = [];

  for (let i = 0; i < plan.steps.length; i++) {
    const step = plan.steps[i];
    const result = await executeStep(step, context);
    results.push(result);

    const assessment = await assessProgress({
      originalPlan: plan,
      completedSteps: results,
      remainingSteps: plan.steps.slice(i + 1),
      currentContext: context,
    });

    if (assessment.needsReplan) {
      const updatedPlan = await replan({
        originalGoal: plan.originalTask,
        completedWork: results,
        newInformation: assessment.newFindings,
        remainingGoals: assessment.unmetGoals,
      });

      plan.steps = [...plan.steps.slice(0, i + 1), ...updatedPlan.steps];
    }
  }

  return aggregateResults(results);
}
反思与自我批判（Reflection / Self-Critique）
反思机制让 Agent 在输出结果后进行自我检查，发现潜在问题：


interface ReflectionResult {
  isAcceptable: boolean;
  issues: ReflectionIssue[];
  suggestions: string[];
  confidence: number;
}

interface ReflectionIssue {
  severity: 'critical' | 'warning' | 'suggestion';
  description: string;
  location?: string;
  suggestedFix?: string;
}

async function reflectOnOutput(task: string, output: string, context: AgentContext): Promise<ReflectionResult> {
  const reflectionPrompt = `
你刚刚为以下任务生成了输出：
任务：${task}
输出：${output}

请严格审视你的输出，回答以下问题：
1. 输出是否完整且正确地解决了任务？
2. 是否有潜在的 bug 或边界情况未处理？
3. 代码是否符合项目的编码规范？
4. 是否有更好的实现方式？
`;

  return await callLLM(reflectionPrompt);
}
验证链（Chain of Verification）
验证链是一种结构化的反思策略，Agent 先生成一系列验证问题，然后逐一回答这些问题来检验自己的输出：


原始输出：为 UserService 添加了缓存功能

验证问题生成：
Q1: 缓存的 key 是否唯一且不会冲突？
Q2: 缓存的过期策略是否合理？
Q3: 缓存失效时是否会正确回退到数据库查询？
Q4: 并发场景下是否存在缓存击穿问题？
Q5: 是否有对应的单元测试覆盖新增逻辑？

逐一验证：
A1: 使用了 userId 作为 key，在当前场景下是唯一的 ✅
A2: 设置了 5 分钟过期，对于用户数据来说合理 ✅
A3: 检查代码...发现缓存 miss 时没有 try-catch，数据库查询失败会抛异常 ❌
A4: 没有使用 singleflight 或锁机制，高并发时可能击穿 ⚠️
A5: 没有编写测试 ❌

改进行动：
- 修复 A3：添加 try-catch 和降级逻辑
- 修复 A4：添加 singleflight 机制
- 修复 A5：编写缓存相关的单元测试

变体与演进
AI 编程工具中的规划实践
Trae Plan 模式
Trae IDE 提供了显式的 Plan 模式，用户可以选择让 Agent 先制定计划再执行：


# Trae Plan 模式的工作流
trigger: 用户选择 "Plan" 模式并提交任务

phase_1_plan:
  - Agent 分析任务需求
  - 生成结构化的执行计划（步骤列表 + 文件变更预览）
  - 展示计划给用户确认
  - 用户可以修改、批准或拒绝计划

phase_2_execute:
  - 按照确认后的计划逐步执行
  - 每个步骤执行后更新进度
  - 遇到问题时可以调整后续步骤

phase_3_verify:
  - 运行相关测试
  - 检查类型错误
  - 汇总变更摘要

小结
规划与反思是 Agent 从"反应式执行"走向"主动式认知"的关键能力。Plan-Execute 模式通过预先规划给 Agent 全局视角和执行方向；任务分解将大问题化解为可管理的小步骤；自适应重规划让 Agent 能够在执行过程中灵活应对变化；反思和自我批判机制确保输出质量；验证链提供了结构化的自检流程。Trae 的 Plan 模式和 Claude Code 的 Spec 模式展示了这些理念在实际产品中的落地方式。结合上一节的 ReAct 模式，Agent 具备了"想-做-看-反思-调整"的完整认知循环，这正是当前最先进 AI 编程工具的核心架构。
