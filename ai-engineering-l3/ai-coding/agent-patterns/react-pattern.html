ReAct 模式

问题背景

让 LLM 直接生成最终答案（Direct Prompting）在简单任务中效果不错，但面对需要多步推理和外部信息获取的复杂任务时，模型容易产生幻觉或遗漏关键步骤。另一方面，纯粹的"思维链"（Chain of Thought）推理虽然改善了推理质量，但模型仍然只能依赖自身的知识，无法与外部世界交互来获取实时信息或验证推理结果。

我们需要一种将推理（Reasoning）和行动（Acting）结合起来的模式，让模型既能"想清楚"，又能"做实验"——这就是 ReAct。




模式定义
ReAct（Reasoning + Acting）是由 Yao et al. (2022) 提出的一种让语言模型交替进行推理和行动的框架。它的核心思想是：在每一步中，模型先进行思考（Thought），然后决定一个行动（Action），执行后得到观察结果（Observation），再基于观察继续思考——形成一个不断迭代的循环。






组成部分
角色
来源





Thought（思考）
分析当前状态，推理下一步应该做什么
LLM 生成




Action（行动）
调用外部工具获取信息或执行操作
LLM 选择，系统执行




Observation（观察）
行动返回的结果，作为下一轮推理的输入
工具返回







提示： ReAct 的关键创新在于让推理过程"可见"且"可交互"——Thought 让我们看到模型在想什么，Action 让模型能做什么，Observation 让模型知道发生了什么。

ReAct 与函数调用（Function Calling）的结合
在现代 AI 编程工具中，ReAct 模式通过 LLM 的函数调用机制来实现：


实现伪代码
interface ReActStep {
  thought: string;
  action: ToolCall | null;
  observation: string | null;
}

async function reactLoop(task: string, tools: ToolDefinition[], maxSteps: number = 20): Promise<string> {
  const history: ReActStep[] = [];
  let currentContext = buildInitialContext(task, tools);

  for (let step = 0; step < maxSteps; step++) {
    const llmResponse = await callLLM(currentContext);

    if (llmResponse.type === 'final_answer') {
      return llmResponse.content;
    }

    if (llmResponse.type === 'function_call') {
      const tool = tools.find((t) => t.name === llmResponse.functionName);
      const observation = await tool.execute(llmResponse.arguments);

      history.push({
        thought: llmResponse.reasoning,
        action: llmResponse.functionCall,
        observation: observation.output,
      });

      currentContext = updateContext(currentContext, history);
    }
  }

  return '达到最大步数限制，返回当前最佳结果';
}

上下文管理策略
随着 ReAct 循环的进行，上下文会不断增长，需要策略来管理：


interface ContextManager {
  addStep(step: ReActStep): void;
  getContext(maxTokens: number): string;
  summarizeOldSteps(): void;
  getStepCount(): number;
}

function buildContext(history: ReActStep[], maxTokens: number): string {
  if (estimateTokens(history) <= maxTokens) {
    return formatAllSteps(history);
  }

  const recentSteps = history.slice(-5);
  const oldSteps = history.slice(0, -5);
  const summary = summarize(oldSteps);

  return `${summary}\n\n--- 最近步骤 ---\n\n${formatAllSteps(recentSteps)}`;
}

优势详解
    

  • 透明可审计：每一步的 Thought 让人类可以理解 Agent 在做什么以及为什么
    • 

  • 动态错误恢复：如果某个工具调用失败或返回了意料之外的结果，下一个 Thought 可以分析原因并调整策略
    • 

  • 事实锚定：Observation 提供了来自真实世界的反馈，有效减少幻觉
    • 

  • 灵活适应：不需要预先定义完整计划，可以根据实际情况动态调整
    • 



局限性详解
    

  • 延迟累积：每一步都需要一次 LLM 调用 + 一次工具调用，多步循环导致显著延迟
    • 

  • Token 成本：上下文随循环不断增长，后期每次 LLM 调用的 Token 消耗越来越大
    • 

  • 循环风险：模型可能陷入无效循环，反复执行相似的操作而无实质进展
    • 

  • 过度思考：某些简单任务不需要 ReAct 循环，直接执行反而更高效
    •

在 AI 编程工具中的实现
几乎所有现代 AI 编程 Agent 的核心循环都是 ReAct 模式的变体：


# Trae Agent 的核心循环（概念描述）
loop:
  step_1: 接收上下文（系统提示 + 对话历史 + 工具结果）
  step_2: LLM 推理（隐含 Thought + 输出 Action 或 Answer）
  step_3: 如果输出包含 tool_call → 执行工具 → 将结果作为 Observation 追加到上下文
  step_4: 如果输出是文本回答 → 循环结束
  step_5: 回到 step_1
# Claude Code 的核心循环（概念描述）
loop:
  step_1: 构建 messages 数组（system + user + assistant + tool_result...）
  step_2: 调用 API，获取 assistant 响应
  step_3: 解析响应中的 tool_use blocks
  step_4: 并行执行所有 tool_use → 生成 tool_result
  step_5: 将 assistant message 和 tool_result 追加到 messages
  step_6: 如果有 tool_use → 继续循环；否则 → 结束


提示： 在实际实现中，Thought 通常不会作为单独的文本段落出现，而是隐含在 LLM 生成 function_call 之前的推理中。一些工具（如 Claude）使用 <thinking> 标签或 extended thinking 功能让 Thought 显式可见。






小结
ReAct 模式通过交替执行 Thought（思考）、Action（行动）和 Observation（观察）三个步骤，将 LLM 的推理能力与工具调用能力有机结合。相比直接提示和纯思维链，ReAct 能够获取外部信息、动态纠错、并保持推理过程的透明性。虽然它带来了延迟和 Token 成本的增加，但对于需要多步推理和工具交互的复杂编程任务来说，ReAct 几乎是当前所有 AI 编程 Agent 的核心架构模式。理解 ReAct 的工作机制，是理解 Trae、Claude Code 等工具如何运作的关键。
