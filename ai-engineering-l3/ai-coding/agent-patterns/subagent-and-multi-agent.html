SubAgent 与多智能体

问题背景

单个 Agent 在面对大型、跨领域的复杂任务时，往往会遇到上下文窗口溢出、推理链过长导致质量下降、以及缺乏专业化能力等问题。例如，一个"从零搭建全栈应用"的任务可能涉及前端 UI 构建、后端 API 设计、数据库建模、测试编写等多个专业领域——单个 Agent 很难在一次连续推理中同时胜任所有这些角色。



模式定义
SubAgent（子智能体）是指在一个主 Agent（编排器）的协调下，负责完成特定子任务的专业化 Agent。多智能体系统（Multi-Agent System）则是多个 Agent 通过协作协议共同完成一个大型目标的架构模式。


核心概念关系如下：

提示： 拆分子 Agent 并非总是最优选择。任务简单时，引入多 Agent 的开销（通信、同步、上下文传递）反而会降低效率。






工作流程
编排器模式（Orchestrator Pattern）
编排器是多智能体系统中最常见的协调模式。主 Agent 承担"指挥官"角色，负责任务拆解和结果整合：


委派模式（Delegation Pattern）
委派模式中，主 Agent 将整个子任务完整地委托给子 Agent，不干预子 Agent 的内部执行过程：


interface DelegationRequest {
  taskId: string;
  description: string;
  context: string;
  constraints: string[];
  expectedOutput: OutputFormat;
}

interface SubAgentConfig {
  name: string;
  systemPrompt: string;
  tools: ToolDefinition[];
  model: string;
  maxSteps: number;
}

async function delegateToSubAgent(request: DelegationRequest, config: SubAgentConfig): Promise<SubAgentResult> {
  const subAgent = createAgent(config);

  const result = await subAgent.execute({
    instruction: request.description,
    context: request.context,
    constraints: request.constraints,
  });

  return {
    taskId: request.taskId,
    output: result.output,
    steps: result.executionTrace,
    tokenUsage: result.totalTokens,
  };
}
扇出/扇入模式（Fan-Out / Fan-In）
当多个子任务彼此独立时，可以并行分发（Fan-Out），等所有结果返回后统一汇总（Fan-In）：


async function fanOutFanIn(subtasks: DelegationRequest[], configs: SubAgentConfig[]): Promise<AggregatedResult> {
  const promises = subtasks.map((task, index) => delegateToSubAgent(task, configs[index]));

  const results = await Promise.allSettled(promises);

  const succeeded = results
    .filter((r): r is PromiseFulfilledResult<SubAgentResult> => r.status === 'fulfilled')
    .map((r) => r.value);

  const failed = results.filter((r): r is PromiseRejectedResult => r.status === 'rejected').map((r) => r.reason);

  return { succeeded, failed, totalTasks: subtasks.length };
}

type MessageChannel = 'direct' | 'broadcast' | 'event_bus';

interface AgentMessage {
  from: string;

interface MessageBus {

小结
当单个 Agent 面对复杂、跨领域的任务时，拆分为多个专业化的子 Agent 是提升能力和效率的自然选择。编排器模式提供了集中式的任务协调，委派机制确保子任务的完整移交，扇出/扇入策略实现了并行加速。顺序、并行和层级三种协作范式适应不同的任务结构。Trae 和 Claude Code 等现代 AI 编程工具已经在实践中广泛使用子 Agent 架构来应对真实场景中的复杂编程任务。理解这些模式，将帮助你更好地使用和评估 AI 编程工具的能力。
