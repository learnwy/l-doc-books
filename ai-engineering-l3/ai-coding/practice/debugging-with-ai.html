调试与排错

场景描述

调试是开发中最耗时的活动之一。传统调试依赖开发者的经验和直觉——逐行阅读代码、设置断点、分析日志。AI 的加入改变了这一流程：它可以快速理解错误信息、提出假设、建议修复方案，并帮助你分析大量日志数据。关键在于掌握如何有效地将调试问题传递给 AI，以及何时该信任 AI 的诊断结果。



核心原则
复现→定位→修复→验证
AI 辅助调试同样遵循经典的四步闭环，但每一步都可以借助 AI 加速：


错误信息是最重要的上下文
AI 诊断问题的质量直接取决于你提供的错误信息的完整性和准确性：






信息质量
示例
AI 诊断效果





❌ 极差
"代码报错了"
无法定位，只能猜测




⚠️ 一般

✅ 优秀

能直接给出修复方案







提示： 永远复制粘贴完整的错误信息文本，而不是截图或口头描述。AI 需要精确的错误代码和堆栈信息来定位问题。






操作步骤
步骤一：收集并整理错误信息
在向 AI 求助之前，先系统化地收集所有相关信息：


# 收集编译错误
npm run build 2>&1 | tee build-error.log

# 收集运行时错误和堆栈跟踪
node dist/index.js 2>&1 | tee runtime-error.log

# 收集测试失败信息
npm test -- --verbose 2>&1 | tee test-error.log

# 收集最近的 git 变更（定位引入 Bug 的提交）
git log --oneline -10
git diff HEAD~3 -- src/
步骤二：构建调试请求
使用结构化的格式向 AI 描述问题：


## 问题描述

在执行用户注册流程时，提交表单后返回 500 错误。

## 错误信息

```
TypeError: Cannot read properties of undefined (reading 'email') at validateUser (src/validators/user.ts:23:18) at registerHandler (src/routes/auth.ts:45:12) at Layer.handle (node_modules/express/lib/router/layer.js:95:5)
```

## 相关代码

```typescript
// src/validators/user.ts:20-30
function validateUser(body: unknown): ValidationResult {
  const { email, password, name } = body as UserInput;
  if (!email.includes('@')) {
    // 第 23 行
    return { valid: false, error: '邮箱格式不正确' };
  }
  return { valid: true };
}
```

## 复现步骤

1. POST /api/auth/register
2. Body: { "password": "123456" }（缺少 email 字段）
3. 返回 500 而非预期的 400 验证错误

## 期望行为

缺少必填字段时应返回 400 状态码和具体的错误提示。

步骤四：验证修复方案
AI 给出修复方案后，务必系统化验证：


// AI 建议的修复：添加输入验证
function validateUser(body: unknown): ValidationResult {
  if (!body || typeof body !== 'object') {
    return { valid: false, error: '请求体不能为空' };
  }

  const input = body as Record<string, unknown>;

  if (typeof input.email !== 'string' || !input.email.includes('@')) {
    return { valid: false, error: '请提供有效的邮箱地址' };
  }

  if (typeof input.password !== 'string' || input.password.length < 6) {
    return { valid: false, error: '密码长度至少为 6 位' };
  }

  return { valid: true };
}
验证清单：


verification_checklist:
  compile_check:
    - 修改后能否通过 TypeScript 编译
    - 是否引入新的类型错误
  unit_test:
    - 原有测试是否全部通过
    - 是否为修复添加了回归测试
  integration:
    - 在开发环境中复现原始问题
    - 确认修复后问题不再出现
  edge_cases:
    - 空值输入
    - 异常格式输入
    - 并发请求场景

常见问题
AI 无法理解我的错误上下文怎么办？
当项目过大、AI 无法获取完整上下文时：


策略 1：逐步缩小范围
  - 先提供模块级别的描述
  - 再提供具体文件和函数
  - 最后聚焦到出错的那几行

策略 2：创建独立复现脚本
  - 将问题从项目中剥离
  - 用最少的代码复现问题
  - 这本身就是定位问题的有效手段

策略 3：分层排查
  - 网络层：API 请求/响应是否正确
  - 数据层：数据库查询结果是否符合预期
  - 逻辑层：业务逻辑处理是否正确
  - 表现层：UI 渲染是否正确

如何利用 AI 编写回归测试？
修复 Bug 后，让 AI 帮你生成回归测试以防止问题再次出现：


// 向 AI 描述：
// "为以下修复生成回归测试：validateUser 函数之前在 body 为 undefined 时崩溃，
//  现在已添加空值检查。请用 Jest 编写测试。"

// AI 生成的回归测试
describe('validateUser', () => {
  it('应该处理 undefined 输入', () => {
    const result = validateUser(undefined);
    expect(result.valid).toBe(false);
    expect(result.error).toBe('请求体不能为空');
  });

  it('应该处理 null 输入', () => {
    const result = validateUser(null);
    expect(result.valid).toBe(false);
  });

  it('应该处理空对象', () => {
    const result = validateUser({});
    expect(result.valid).toBe(false);
    expect(result.error).toContain('邮箱');
  });

  it('应该处理缺少 email 字段的输入', () => {
    const result = validateUser({ password: '123456' });
    expect(result.valid).toBe(false);
  });

  it('应该接受有效输入', () => {
    const result = validateUser({
      email: 'test@example.com',
      password: '123456',
    });
    expect(result.valid).toBe(true);
  });
});


小结
    

  • 复现→定位→修复→验证是 AI 辅助调试的核心闭环，AI 在每个阶段都能提供有价值的协助。
    • 

  • 完整的错误信息是 AI 诊断的基础——粘贴完整的错误堆栈、提供相关代码、描述复现步骤，三者缺一不可。
    • 

  • 结构化的调试请求（问题描述 + 错误信息 + 相关代码 + 复现步骤 + 期望行为）可以显著提升 AI 的诊断质量。
    • 

  • 日志分析是 AI 的强项，面对大量日志数据时，AI 可以快速识别模式、关联错误、按优先级排列问题。
    • 

  • AI 调试有明确的局限性：并发竞态、环境特定问题、内存泄漏等场景需要回归传统调试手段。
    • 

  • 每次修复后都应编写回归测试，AI 可以根据修复内容快速生成对应的测试用例。
    •
