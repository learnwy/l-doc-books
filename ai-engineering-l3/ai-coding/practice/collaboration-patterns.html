高效协作模式

场景描述

AI 辅助编程的核心不在于"让 AI 写所有代码"，而在于建立一种高效的 Human-AI 协作关系。就像与一位技术能力强但缺乏项目背景的新同事合作，你需要掌握正确的沟通方式、任务分配策略和质量把控方法，才能让协作效率最大化。



核心原则
AI 结对编程模型
将 AI 视为结对编程中的"领航员"（Navigator）或"驾驶员"（Driver），根据任务性质灵活切换角色：


委托决策框架
不是所有任务都适合交给 AI。以下矩阵帮助你快速决策：

提示： 一个简单的判断标准——如果你能在 30 秒内向 AI 清晰描述期望的输入和输出，这个任务就适合委托。




Trust but Verify（信任但验证）
AI 生成的代码可能看起来完全正确，但隐藏着微妙的问题。建立系统化的验证习惯：


// ❌ 盲目信任 AI 生成的代码
const result = aiGeneratedFunction(input);
// 直接部署上线

// ✅ 信任但验证的流程
// 1. 阅读并理解 AI 生成的代码逻辑
// 2. 检查边界条件和错误处理
// 3. 运行现有测试套件
// 4. 针对 AI 代码补充测试用例
// 5. 通过代码审查后再合并


操作步骤
步骤一：构建有效的任务描述
好的任务描述是高效协作的基础。遵循 C-S-E 框架：


    

  • Context（上下文）：项目背景、技术栈、约束条件
    • 

  • Specific（具体）：明确的输入输出、预期行为
    • 

  • Example（示例）：提供参考代码或期望的输出格式
    • 



<!-- ❌ 模糊的任务描述 -->

帮我写一个用户验证功能

<!-- ✅ 清晰的任务描述（C-S-E 框架）-->

【上下文】

- 项目使用 Express + TypeScript，认证方案是 JWT
- 用户模型已定义在 src/models/user.ts
- 现有中间件风格参考 src/middleware/auth.ts

【具体需求】

- 实现邮箱+密码的注册接口 POST /api/auth/register
- 密码需要 bcrypt 加密，salt rounds = 10
- 注册成功返回 JWT token，有效期 7 天
- 邮箱已存在时返回 409 状态码

【参考格式】返回结构：{ success: boolean, token?: string, error?: string }
步骤二：提供充足的上下文
AI 无法自动理解你的项目全貌。主动提供关键上下文：


# 在对话开始时，提供项目结构概览
tree src/ -L 2 --dirsfirst

# 提供相关文件内容
cat src/models/user.ts
cat src/middleware/auth.ts

# 提供当前的错误信息或日志
npm run build 2>&1 | tail -20
步骤三：迭代式对话
不要期望一次对话就得到完美结果。采用渐进式细化策略：


第 1 轮：先让 AI 实现核心功能
  → 审查：逻辑正确，但缺少输入验证

第 2 轮：要求添加输入验证和错误处理
  → 审查：验证逻辑完善，但错误消息不够友好

第 3 轮：优化错误消息，添加国际化支持
  → 审查：满足要求，准备合并
步骤四：管理 AI 的不确定性
当 AI 对某个问题不确定时，它可能会"自信地给出错误答案"。识别这些信号：

    - 在模糊描述后期望精确结果
高效协作的对话模板
## 功能实现模板

我需要在 [模块名] 中实现 [功能描述]。

- 技术栈：[框架/语言/版本]
- 相关文件：[文件列表]
- 约束条件：[性能要求/兼容性/风格]
- 期望行为：[输入→输出示例]

## Bug 修复模板

[文件路径] 中的 [函数名] 出现了以下问题：

- 期望行为：[描述]
- 实际行为：[描述]
- 错误信息：[完整的错误输出]
- 复现步骤：[1. 2. 3.]

## 代码优化模板

以下代码可以工作，但我希望在 [方面] 进行优化：

- 当前实现：[代码片段]
- 优化目标：[性能/可读性/可维护性]
- 约束：[不能改变公共 API/需要向后兼容]
建立个人协作工作流


常见问题
AI 生成的代码总是不符合项目风格怎么办？
在项目根目录创建 .trae/rules/ 或类似的规则文件，定义代码风格约束。大多数 AI 编程工具支持读取项目级规则：


<!-- .trae/rules/code-style.md -->

# 代码风格规则

- 使用函数式组件，不使用 class 组件
- 所有异步操作使用 async/await，不使用 .then() 链
- 错误处理统一使用 Result 模式
- 命名规范：camelCase 用于变量和函数，PascalCase 用于类型
AI 总是给出过于复杂的方案怎么办？
明确告诉 AI 你期望的复杂度级别：


✅ "请用最简单的方式实现，不需要考虑扩展性"
✅ "请给出一个 MVP 版本，后续我再逐步完善"
✅ "实现应该控制在 50 行以内"
如何处理 AI 上下文窗口不够用的情况？
策略 1：分而治之 — 将大任务拆分为独立的小任务
策略 2：摘要式上下文 — 用简短描述代替完整代码
策略 3：渐进式构建 — 先实现骨架，再逐步填充细节
策略 4：利用文件引用 — 让 AI 工具直接读取文件而非粘贴


小结
    

  • AI 结对编程模型将 AI 定位为协作伙伴而非替代者，根据任务性质灵活切换主导角色。
    • 

  • 委托决策框架帮助你快速判断任务是否适合交给 AI：模板化、重复性任务优先委托，架构决策和安全关键代码保留人工主导。
    • 

  • C-S-E 框架（Context-Specific-Example）是编写有效任务描述的实用方法，充足的上下文是高质量输出的前提。
    • 

  • 迭代式对话是常态，不要期望一次得到完美结果，通过渐进式细化逐步逼近目标。
    • 

  • Trust but Verify 是与 AI 协作的核心心态——信任其能力，但始终保持系统化的验证习惯。
    • 

  • 建立个人化的协作工作流和对话模板，可以显著提升日常开发中的 AI 协作效率。
    •
