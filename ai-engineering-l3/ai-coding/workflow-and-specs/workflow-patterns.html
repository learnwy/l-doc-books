工作流模式

核心概念

在 AI 辅助编程中，工作流模式（Workflow Pattern）定义了人类与 AI 之间的协作方式——谁来做决策、何时做决策、以什么粒度做决策。当前主流的 AI 编程工具普遍支持三种工作流模式：





模式
一句话描述
人类参与度
适合任务





Agent 模式
AI 自主分析、决策并执行
低
简单明确的任务




Plan 模式
AI 先生成计划，确认后执行
中
中等复杂度的任务




Spec 模式
基于完整规范文档驱动执行
高
大型或高风险的任务





三种模式并非互斥，而是一个控制力谱系——从左到右，人类对 AI 行为的控制力逐渐增强，AI 的自主性逐渐降低。选择哪种模式取决于任务的复杂度、风险等级和你对 AI 的信任度。




提示： 没有"最好的"模式，只有"最合适的"模式。在同一个项目中，你完全可以对不同任务使用不同的模式。






工作原理
Agent 模式（自主执行）
Agent 模式是最"自动化"的工作方式。用户发出请求后，AI 自主决定如何完成任务，包括搜索代码、阅读文件、编写代码、运行测试等。


特征：


    

  • AI 自主决定执行步骤，无需人类逐步确认
    • 

  • 使用 ReAct（Reasoning + Acting）循环：思考 → 行动 → 观察 → 思考
    • 

  • 适合目标清晰、风险可控的任务
    • 



典型场景：


用户: "修复 TypeScript 编译错误"
AI:   [搜索错误] → [定位问题] → [修改代码] → [运行编译] → [确认修复]
      整个过程无需人类介入
Plan 模式（先规划后执行）
Plan 模式在 Agent 模式的基础上增加了一个计划审批环节。AI 先生成执行计划，等待用户确认后才开始执行。


特征：


    

  • 执行前有明确的计划审批步骤
    • 

  • 用户可以在执行前修改、增删计划中的步骤
    • 

  • 执行过程中 AI 仍有一定自主性
    • 



典型场景：


用户: "为项目添加单元测试框架"
AI:   [生成计划]
      1. 安装 vitest 和相关依赖
      2. 创建 vitest.config.ts
      3. 编写 src/utils/ 下的测试文件
      4. 配置 package.json 的 test 脚本
      5. 运行测试验证
      → 等待用户确认 →
      [按计划执行]
Spec 模式（先规范后执行）
Spec 模式是控制力最强的模式。它要求在编码之前准备好完整的规范文档（spec.md），AI 严格按照规范执行。


特征：


    

  • 以结构化的规范文档作为输入
    • 

  • 执行过程可追溯到规范中的具体条目
    • 

  • 验证标准预先定义，不存在模糊空间
    • 





关键要素
审查循环（Review Cycle）
无论使用哪种模式，AI 编程都遵循一个核心的迭代循环：


这个循环在实际执行中的表现：


# 典型的 AI 编程迭代循环
# 步骤 1: 编写代码
# 步骤 2: 运行测试
npm run test

# 步骤 3: 运行类型检查和代码检查
npm run typecheck
npm run lint

# 步骤 4: 如果有错误，修复后重复
# AI 自动分析错误输出，定位问题，修改代码，再次验证
好的 AI 编程工具会自动执行这个循环——写完代码后主动运行测试和 lint，发现错误后自动修复，直到所有检查通过。


迭代精炼（Iterative Refinement）
AI 的首次输出很少是完美的。迭代精炼是通过多轮人机交互逐步改进产出质量的过程：






迭代轮次
人类动作
AI 动作

第 2 轮

第 4 轮

调整为项目规范风格

完成并标记为已完成

混合使用示例
在实际项目中，你可能在同一个开发周期内混合使用多种模式：


项目：电商平台重构

Sprint 1 - 架构设计
└── [Spec 模式] 编写技术规范，定义模块边界和接口

Sprint 2 - 核心模块开发
├── [Plan 模式] 实现商品管理模块（中等复杂度）
├── [Plan 模式] 实现订单处理模块（中等复杂度）
└── [Spec 模式] 实现支付集成模块（高风险）

Sprint 3 - 细节完善
├── [Agent 模式] 修复 Bug 列表中的 15 个 Bug
├── [Agent 模式] 添加缺失的类型定义
└── [Plan 模式] 添加监控和日志模块

Sprint 4 - 测试与部署
├── [Plan 模式] 编写端到端测试
└── [Agent 模式] 修复测试中发现的问题


常见误区




误区
问题
正确做法





所有任务都用 Agent 模式
复杂任务缺乏规划，容易出错
根据复杂度选择合适的模式




所有任务都用 Spec 模式
简单任务流程过重，效率低下
简单任务直接用 Agent 模式




审批计划时不仔细看
计划中的问题在执行时才暴露，导致返工
认真审阅计划，提前发现潜在问题




不信任 AI，每一步都要手动确认
失去了 AI 辅助编程的效率优势
对低风险操作给予信任，只对关键节点把关




从不回顾和改进工作流
一直用低效的方式工作
定期回顾哪种模式效果好，持续优化工作流




认为 AI 的执行结果一定正确
跳过验证环节，bug 流入生产
无论哪种模式，验证环节都不可省略







小结
    

  • AI 编程有三种核心工作流模式：Agent 模式（自主执行）、Plan 模式（先规划后执行）、Spec 模式（先规范后执行）。
    • 

  • 三种模式构成一个控制力谱系——从 Agent 到 Spec，人类控制力递增，AI 自主性递减。
    • 

  • 审查循环（编写 → 测试 → 检查 → 修复）是所有模式共有的质量保障机制。
    • 

  • 迭代精炼通过多轮人机交互逐步提升产出质量，AI 的首次输出很少是最终版本。
    • 

  • 模式选择取决于任务的复杂度、风险等级和不确定性——简单任务用 Agent，中等用 Plan，复杂/高风险用 Spec。
    • 

  • 在实际项目中，应混合使用不同模式，对不同任务采用最合适的协作方式。
    •
