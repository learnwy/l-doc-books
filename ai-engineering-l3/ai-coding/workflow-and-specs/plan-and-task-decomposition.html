Plan 计划与任务分解

核心概念

在 AI 编程中，**计划（Planning）**是指在执行编码之前，先对任务进行分析、拆解和排序的过程。任务分解（Task Decomposition）则是将一个复杂的、模糊的需求拆解为一系列具体的、可执行的子任务。

为什么计划如此重要？因为 AI Agent 的能力本质上是逐步执行的——它在单次操作中只能完成一个有限范围的动作（读文件、写代码、运行命令）。如果没有计划，Agent 很容易陷入"走一步看一步"的状态，遗漏关键步骤或做出不一致的决策。


计划之于 AI，就像大纲之于写作——它不保证最终产出完美，但它显著降低了迷失方向的概率。




提示： 好的计划不是一成不变的。最有效的计划是"活计划"——在执行过程中根据实际情况动态调整。

关键要素
计划文件的格式
一个结构良好的计划文件（plan.md）通常包含以下要素：


# 计划：实现用户通知系统

## 目标

为应用添加实时通知功能，支持站内消息和邮件通知。

## 范围分析

- 涉及文件：src/services/, src/api/, src/models/
- 新增模块：notification service, email adapter
- 修改模块：user service (添加通知偏好)

## 任务列表

### 阶段一：数据模型（预计 30 分钟）

- [ ] 1.1 定义 Notification 接口
- [ ] 1.2 创建数据库迁移脚本
- [ ] 1.3 实现 NotificationRepository

### 阶段二：核心服务（预计 1 小时）

- [ ] 2.1 实现 NotificationService
- [ ] 2.2 实现 EmailAdapter
- [ ] 2.3 编写单元测试

### 阶段三：API 层（预计 45 分钟）

- [ ] 3.1 添加通知相关的 API 路由
- [ ] 3.2 实现 WebSocket 推送
- [ ] 3.3 编写集成测试

## 风险与注意事项

- WebSocket 连接管理需要处理断线重连
- 邮件发送应使用异步队列，避免阻塞主线程
Todo 列表管理
在 AI 编程工具中，Todo 列表是计划的运行时表现形式。它跟踪每个子任务的状态：


interface TodoItem {
  id: string;
  content: string;
  status: 'pending' | 'in_progress' | 'completed';
  priority: 'high' | 'medium' | 'low';
}
Todo 列表的管理遵循以下原则：


    

  1. 同一时间只有一个任务处于 in_progress 状态——保持专注，避免并行混乱。
    2. 

  2. 完成即标记——一个任务做完后立刻标记为 completed，不要攒着批量标记。
    3. 

  3. 动态增删——执行过程中发现新的子任务，立即添加；发现不再需要的任务，立即移除。
    4. 

  4. 优先级调整——根据实际情况调整任务的执行顺序。
    5. 



计划审批流程
在 Plan 模式下，AI 生成的计划需要人类确认后才能执行：


这个流程确保了人类始终掌握控制权——AI 负责生成计划，人类负责审批和决策。




实际应用
示例一：Trae Plan 模式
在 Trae 中，Plan 模式的工作方式如下：


用户: "给项目添加国际化支持"

Trae (Plan 模式):
━━━━━━━━━━━━━━━━━━━━━━
📋 计划
1. 安装 i18next 和 react-i18next 依赖
2. 创建 src/i18n/ 目录结构
3. 编写中文和英文语言包
4. 初始化 i18n 配置
5. 修改 App.tsx 包裹 I18nextProvider
6. 将现有硬编码文本替换为 t() 调用
7. 添加语言切换组件
8. 运行测试验证
━━━━━━━━━━━━━━━━━━━━━━
是否按此计划执行？[确认 / 修改 / 拒绝]
用户可以在确认前修改计划——比如删除不需要的步骤，或者添加遗漏的步骤。


示例二：Claude Code 的迭代式方法
Claude Code 采用更细粒度的迭代方式。它不会一次性生成完整计划，而是通过 TodoWrite 工具动态管理任务列表：


用户: "重构 auth 模块，将 JWT 逻辑抽离为独立服务"

Claude Code:
1. [搜索代码] 查找所有 JWT 相关代码
   → 发现 3 个文件涉及 JWT 逻辑
2. [创建 Todo] 添加 5 个重构任务
3. [执行任务 1] 创建 JwtService 类
   → 完成 ✅，标记任务 1 为 completed
4. [执行任务 2] 迁移 token 生成逻辑
   → 发现额外依赖，添加新任务
5. [继续执行] ...

自适应计划
真正高效的 AI 编程工作流不是严格按计划执行，而是在执行过程中持续调整：


自适应计划的关键行为：


    

  1. 发现新依赖时——将新的前置任务插入计划。
    2. 

  2. 任务比预期简单时——合并后续相关任务，加速推进。
    3. 

  3. 任务比预期复杂时——将当前任务进一步拆分为更小的子任务。
    4. 

  4. 遇到阻碍时——跳过被阻塞的任务，先处理其他独立任务。
    5. 





常见误区




误区
问题
正确做法





计划过于粗略
"实现功能"这样的任务无法指导执行
每个任务应具体到可以独立验证的粒度




计划过于细碎
把每一行代码都列为一个任务，失去计划的意义
任务粒度应在"一个逻辑单元"级别




不允许计划变更
僵化执行导致在错误方向上越走越远
把计划当作指南而非铁律，随时调整




忽视任务依赖关系
先做了依赖后续模块的任务，导致返工
明确标注任务间的依赖，按依赖顺序执行




计划只在脑中，不写下来
AI 无法感知你脑中的计划
用文件或 Todo 工具将计划外化




跳过计划直接让 AI 开干
对复杂任务来说，AI 容易遗漏步骤或走弯路
任务越复杂，越值得先花时间做计划







提示： 判断一个任务是否需要计划的简单规则——如果你能用一句话描述清楚要做什么，且 AI 一次操作就能完成，那不需要计划。否则，先做计划。






小结
    

  • 计划是 AI 编程中控制复杂度的核心手段，它将模糊的需求转化为有序的执行路径。
    • 

  • 任务分解有多种策略（功能分解、层次分解、依赖分解等），应根据任务特征灵活选择。
    • 

  • 计划文件（plan.md）应包含目标、范围、任务列表和风险提示，格式清晰、粒度适中。
    • 

  • Todo 列表是计划的运行时表现，遵循"单一进行中任务、完成即标记、动态增删"的管理原则。
    • 

  • 计划审批流程确保人类始终掌握控制权——AI 提案，人类决策。
    • 

  • 自适应计划是最佳实践：在执行过程中根据实际情况持续调整计划，而非僵化执行。
    •
