Zero-Shot 与 Few-Shot

核心概念

Zero-Shot 和 Few-Shot 是提示工程中最基础也最常用的两种技术。它们的核心区别在于是否在提示中提供示例：Zero-Shot 直接给出任务描述，依赖模型的预训练知识完成推理；Few-Shot 则通过在提示中嵌入少量输入-输出示例对，引导模型理解任务模式并进行模仿。

这两种技术源自 GPT-3 论文中的核心发现：大语言模型具备 In-Context Learning 能力，即无需微调参数，仅通过调整输入上下文就能适配新任务。理解并掌握 Zero-Shot 与 Few-Shot 的设计原则，是提示工程的第一步。


Zero-Shot 提示设计
Zero-Shot 的核心在于用清晰、无歧义的指令描述任务。由于没有示例作为参照，指令的精确度直接决定输出质量。


一个良好的 Zero-Shot 提示通常包含三个要素：任务定义、输入数据、输出要求。

The garbage collector in V8 uses a generational approach,

V8 中的垃圾回收器（garbage collector）采用分代策略（generational approach），

Zero-Shot 的有效策略包括：


    

  • 动词前置：以明确的动作动词开头（分析、总结、翻译、分类），让模型立即知道要做什么
    • 

  • 约束条件明确化：直接说明长度、格式、语言、风格等约束
    • 

  • 负面指令：明确告知不要做什么，比"请注意"更有效
    • 



分类以下用户反馈的情感倾向。只输出"正面"、"负面"或"中性"，不要输出任何解释。

反馈：这个 API 接口设计得很优雅，但文档太少了，调试花了很长时间。
Zero-Shot 在以下场景表现优异：任务定义清晰且常见（如翻译、摘要）、模型参数量足够大（GPT-4 级别）、以及对输出格式要求不严格的情况。


Few-Shot 示例设计原则
Few-Shot 的核心挑战不在于"给几个示例"，而在于给什么样的示例。示例的质量、多样性和排列顺序对模型输出有决定性影响。


示例选择的三大原则：


原则一：代表性覆盖。示例应覆盖任务的主要类别和边界情况，而非重复同一类型。

原则二：格式一致性。所有示例必须使用完全相同的格式模板，包括分隔符、标签位置和换行方式。模型对格式模式极其敏感，一个不一致的示例可能破坏整体效果。


原则三：近因效应。模型对最后一个示例赋予最高权重。将最能代表目标输出的示例放在最后位置，紧邻实际输入。

动态示例选择策略
在生产环境中，静态的 Few-Shot 示例往往无法应对多样化的输入。动态示例选择（Dynamic Few-Shot Selection）根据每次输入的特征，从示例库中检索最相关的示例，动态构建提示。


interface Example {
  input: string;
  output: string;
  embedding: number[];
  category: string;
}

interface DynamicFewShotConfig {
  maxExamples: number;
  similarityThreshold: number;
  diversityWeight: number;
}

const selectExamples = (
  query: string,
  queryEmbedding: number[],
  examplePool: Example[],
  config: DynamicFewShotConfig,
): Example[] => {
  const scored = examplePool.map((ex) => ({
    example: ex,
    similarity: cosineSimilarity(queryEmbedding, ex.embedding),
  }));

  const filtered = scored.filter((s) => s.similarity >= config.similarityThreshold);

  filtered.sort((a, b) => b.similarity - a.similarity);

  const selected: Example[] = [];
  const seenCategories = new Set<string>();

  for (const { example } of filtered) {
    if (selected.length >= config.maxExamples) break;
    const diversityBonus = seenCategories.has(example.category) ? 0 : config.diversityWeight;
    if (selected.length === 0 || diversityBonus > 0 || selected.length < config.maxExamples) {
      selected.push(example);
      seenCategories.add(example.category);
    }
  }

  return selected;
};
动态选择的核心思路是将示例向量化后存入检索库（如向量数据库），每次请求时以用户输入为查询，检索语义最相似的 K 个示例。同时加入多样性约束，避免检索到 K 个高度相似但类别单一的示例。


这种策略在客服分类、代码审查、文档标注等需要处理大量不同类型输入的场景中尤为有效。

小结
    

  • Zero-Shot 和 Few-Shot 是提示工程的两大基石，分别适用于不同复杂度的任务场景
    • 

  • Zero-Shot 的关键在于指令精确度：动词前置、约束明确、负面指令
    • 

  • Few-Shot 的核心在于示例质量：代表性覆盖、格式一致、利用近因效应
    • 

  • 动态示例选择通过语义检索实现 Few-Shot 的规模化应用
    • 

  • 实践中应采用渐进增强策略，从 Zero-Shot 出发，按需添加示例
    • 

  • 两种技术可以与 Chain-of-Thought 等其他技术组合，产生更强效果
