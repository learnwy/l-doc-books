任务分解与规划

核心概念

任务分解与规划（Decomposition & Planning）是一种将复杂问题拆分为可管理子任务，并按照逻辑顺序编排执行的提示模式。这一模式的核心洞察是：LLM 处理单个简单任务的能力远优于直接处理复杂任务。通过显式的分解和规划步骤，可以将 LLM 的单步推理能力聚合为多步复杂推理能力。

任务分解模式源自软件工程中的分治思想（Divide and Conquer），也是 AI Agent 架构中 Plan-Execute-Observe 循环的核心环节。


分解策略与方法
有效的任务分解需要选择合适的分解策略。不同类型的任务适合不同的分解方式。


目标驱动分解：从最终目标出发，逆向推导需要完成的子任务。


最终目标：将一个 Express.js 单体应用迁移到 Fastify 微服务架构

请从目标出发，逆向分解为可执行的子任务：

1. 识别当前单体应用的所有功能模块
2. 分析模块间的依赖关系，确定服务边界
3. 设计微服务间的通信协议（REST/gRPC/消息队列）
4. 为每个服务设计 API 契约
5. 逐个服务实现迁移（按依赖顺序：基础服务优先）
6. 实现服务发现和负载均衡
7. 建立统一的日志和监控体系
8. 灰度发布和流量切换

每个子任务完成后，输出其结果摘要，作为下一个子任务的输入上下文。
模式匹配分解：识别任务中的已知模式，用对应的解决方案模板展开。


任务：优化一个电商平台的首屏加载速度

这是一个"性能优化"类任务，按照标准优化框架分解：

第一步：测量（Measure）
- 当前首屏加载时间
- Lighthouse 评分
- 关键指标：LCP、FID、CLS

第二步：分析（Analyze）
- 识别性能瓶颈（网络/渲染/资源）
- 分析资源加载瀑布图
- 识别阻塞渲染的资源

第三步：优化（Optimize）
- 针对每个瓶颈的具体优化方案

第四步：验证（Verify）
- 优化前后指标对比
递归分解：对每个子任务递归应用分解，直到达到可直接执行的粒度。


执行计划编排
分解产生的子任务需要按照正确的顺序和依赖关系编排为执行计划。


请为以下子任务制定执行计划，考虑依赖关系和并行可能性：

子任务列表：
A. 数据库 Schema 设计
B. API 接口设计
C. 前端页面开发
D. 单元测试编写
E. 集成测试编写
F. 部署配置

执行计划：
阶段 1（并行）：A + B（无相互依赖）
阶段 2（并行）：C + D（依赖 A 和 B 的输出）
阶段 3（顺序）：E（依赖 C 和 D）
阶段 4（顺序）：F（依赖 E 通过）

每个阶段的输入：上一阶段的输出摘要
每个阶段的输出：执行结果 + 下一阶段需要的上下文

动态重规划机制
真实任务执行中，子任务的结果可能偏离预期，需要动态调整计划。


你正在执行一个多步任务。在每一步完成后，评估以下问题：

1. 当前步骤的输出是否符合预期？
2. 是否发现了新的信息，需要调整后续计划？
3. 是否需要回溯到之前的步骤重新执行？

如果需要重规划，按以下格式输出：

[重规划触发]
原因：{发现了什么导致需要调整}
影响范围：{哪些后续步骤受影响}
新计划：{调整后的执行计划}
interface TaskPlan {
  tasks: TaskNode[];
  dependencies: Map<string, string[]>;
  status: Map<string, 'pending' | 'running' | 'done' | 'failed'>;
}

interface TaskNode {
  id: string;
  description: string;
  expectedOutput: string;
  actualOutput?: string;
}

const shouldReplan = (plan: TaskPlan, completedTask: TaskNode): boolean => {
  if (!completedTask.actualOutput) return false;

  const divergence = assessDivergence(completedTask.expectedOutput, completedTask.actualOutput);

  return divergence > 0.3;
};

const replan = (currentPlan: TaskPlan, divergenceInfo: string): TaskPlan => {
  const remainingTasks = currentPlan.tasks.filter((t) => currentPlan.status.get(t.id) === 'pending');

  return generateNewPlan(remainingTasks, divergenceInfo);
};
实际应用：代码重构的分解规划
以一个真实的代码重构场景展示完整的分解与规划过程。


任务：将一个 500 行的 React 类组件重构为函数式组件 + Hooks

请按以下步骤分解并执行：

步骤 1：分析当前组件
- 识别所有 state 变量
- 识别所有生命周期方法及其用途
- 识别所有类方法和事件处理器
- 列出外部依赖（HOC、context、refs）

步骤 2：设计重构方案
- 将每个 state 映射为 useState 或 useReducer
- 将每个生命周期映射为对应的 useEffect
- 设计自定义 Hook 提取可复用逻辑
- 确定是否需要 useRef、useMemo、useCallback

步骤 3：制定迁移顺序
1. 创建函数式组件骨架
2. 迁移 state（先简单 state，后复杂 state）
3. 迁移生命周期（componentDidMount → useEffect）
4. 迁移事件处理器
5. 提取自定义 Hook
6. 删除旧类组件

步骤 4：验证
- 每迁移一个部分，立即运行测试
- 对比重构前后的渲染输出
- 检查性能是否有回退

在步骤 1 完成后暂停，等我确认分析结果是否准确。
小结
    

  • 任务分解将复杂问题转化为可管理的子任务序列，显著提升 LLM 处理复杂任务的能力
    • 

  • 三种分解策略（目标驱动、模式匹配、递归）适用于不同类型的任务
    • 

  • 执行计划编排需要考虑依赖关系和并行可能性
    • 

  • 动态重规划机制是处理不确定性的关键，应在每一步进行偏离评估
    • 

  • 中间结果作为下一步的输入上下文，是保持任务连贯性的核心机制
    • 

  • 在关键步骤设置暂停点，让人类确认方向正确后再继续
    •
