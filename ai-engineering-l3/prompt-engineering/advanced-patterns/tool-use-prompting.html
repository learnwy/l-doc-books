工具调用提示

核心概念

工具调用提示（Tool-Use Prompting）是指导 LLM 正确选择和使用外部工具（函数、API、数据库查询等）的提示技术。在 Agent 架构中，LLM 作为"大脑"需要决定何时调用哪个工具、传递什么参数、以及如何处理工具返回结果。工具调用能力是 LLM 从"文本生成器"进化为"行动执行者"的关键跨越。

工具调用的核心挑战在于三个决策：何时调用（识别需要工具辅助的场景）、调用哪个（从工具集中选择最合适的工具）、怎么调（构造正确的参数）。


工具定义与描述

工具选择与编排
当工具集中有多个工具时，LLM 需要准确地选择合适的工具，有时还需要编排多个工具的调用顺序。


你有以下工具可用：

1. search_docs: 搜索项目文档
2. search_code: 搜索源代码
3. read_file: 读取文件全文
4. run_command: 执行终端命令
5. write_file: 写入文件

工具选择规则：
- 了解功能如何实现 → search_code → read_file（查看完整实现）
- 了解项目配置 → search_docs 或 read_file
- 验证代码修改 → write_file → run_command（执行测试）
- 分析项目结构 → run_command（ls/tree）→ search_code
- 修复 bug → search_code（定位）→ read_file（理解）→ write_file（修复）→ run_command（验证）

注意：
- 优先使用 search 工具缩小范围，再用 read_file 获取详情
- write_file 之后必须跟 run_command 验证
- 如果第一次搜索没有结果，换一个查询词重试
ReAct 模式的工具调用
ReAct（Reasoning + Acting）是工具调用的经典模式，将推理和行动交替进行，每次行动后观察结果并决定下一步。


使用 Thought/Action/Observation 循环解决问题。

Thought: 分析当前情况和下一步计划
Action: 选择一个工具并指定参数
Observation: 工具返回的结果（系统自动填入）

重复上述循环，直到可以给出最终答案。

示例：

用户：项目中的用户认证是如何实现的？

Thought: 我需要找到认证相关的代码。先搜索 "auth" 或 "authentication" 关键词。
Action: search_code(query="authentication", file_pattern="*.ts")
Observation:
  - src/middleware/auth.ts (line 15-45)
  - src/routes/login.ts (line 1-80)
  - src/utils/jwt.ts (line 1-30)

Thought: 找到了三个相关文件。核心认证逻辑应该在 middleware/auth.ts 中，让我读取它的内容。
Action: read_file(path="src/middleware/auth.ts")
Observation: [文件内容...]

Thought: 现在我理解了认证实现。使用 JWT token，通过中间件验证。
让我也确认一下 JWT 的配置。
Action: read_file(path="src/utils/jwt.ts")
Observation: [文件内容...]

Thought: 我现在有足够的信息来回答用户的问题了。

最终回答：项目使用 JWT（JSON Web Token）实现用户认证...
工具调用的错误处理
工具调用可能失败，优秀的提示设计需要预设错误处理策略。


工具调用错误处理规则：

1. 工具超时：等待最多 30 秒，超时后告知用户并建议替代方案
2. 参数错误：检查参数格式，修正后重试（最多重试 2 次）
3. 权限不足：告知用户需要的权限，不尝试绕过
4. 结果为空：换一种查询方式重试，或告知用户未找到
5. 结果过大：请求分页或缩小查询范围

错误恢复示例：
Thought: search_code 返回空结果，可能关键词不精确。
尝试用更通用的关键词 "login" 替代 "authenticate"。
Action: search_code(query="login")

interface ToolCallResult {
  success: boolean;
  data?: unknown;
  error?: string;
  errorType?: 'timeout' | 'invalid_params' | 'empty' | 'permission' | 'unavailable';
}

const handleToolError = (result: ToolCallResult, retryCount: number): 'retry' | 'fallback' | 'abort' => {
  if (result.success) return 'abort';

  switch (result.errorType) {
    case 'timeout':
      return retryCount < 3 ? 'retry' : 'fallback';
    case 'invalid_params':
      return retryCount < 2 ? 'retry' : 'abort';
    case 'empty':
      return retryCount < 2 ? 'retry' : 'fallback';
    case 'permission':
      return 'abort';
    case 'unavailable':
      return 'fallback';
    default:
      return 'abort';
  }
};

  • 工具调用是 LLM 从文本生成器进化为行动执行者的关键能力
    • 

  • 工具定义的质量决定选择准确率，必须包含使用场景和限制说明
    • 

  • 多工具编排需要明确的选择规则和执行顺序
    • 

  • ReAct 模式通过推理-行动-观察循环实现灵活的工具使用
    • 

  • 错误处理是生产级工具调用的必备组件，需要重试、降级和通知策略
    • 

  • 核心原则：先搜索缩小范围，再读取获取详情，修改后必须验证
