自我反思与批判

核心概念

自我反思与批判（Self-Reflection & Critique）是一种让 LLM 审视并改进自身输出的提示模式。其核心思想是将"生成"和"评估"分离为两个独立阶段：模型首先生成初始回答，然后以批判者的视角审视这个回答，找出问题并产出改进版本。这种模式模拟了人类写作中"初稿→审稿→修改"的工作流程。

自我反思之所以有效，是因为 LLM 在评估模式（"这个回答好不好"）下的判断力通常优于生成模式（"直接生成最好的回答"）。批判性思维作为一种更简单的认知任务，模型在这一模式下能发现自己在生成模式中犯的错误。


反思框架设计
一个结构化的反思框架确保模型从多个维度审视自己的输出，而非泛泛地说"这个回答不错"。


请先回答用户的问题，然后按照以下框架对自己的回答进行反思：

[回答]
{你的初始回答}

[反思]
1. 正确性检查：回答中是否有事实错误或逻辑漏洞？
2. 完整性检查：是否遗漏了用户问题的某些方面？
3. 深度检查：解释是否足够深入，还是停留在表面？
4. 实用性检查：给出的建议是否可直接执行？是否考虑了实际约束？
5. 安全性检查：是否有潜在的安全风险或不当建议？

[修改]
基于反思发现的问题，输出改进后的最终版本。

用户问题：解释 React 中 useEffect 的闭包陷阱及解决方案。
领域特定的反思框架更能发现深层问题：


[代码审查反思框架]
对你给出的代码方案进行自我审查：

□ 类型安全：是否所有变量都有正确的类型？是否有隐式 any？
□ 边界条件：空数组、null、undefined、超长字符串是否处理？
□ 并发安全：是否有竞态条件？异步操作是否正确处理？
□ 性能影响：时间复杂度是否最优？是否有不必要的重渲染？
□ 错误处理：异常是否被捕获并有意义地处理？
□ 可维护性：代码是否易于理解和修改？命名是否清晰？

对每个检查项给出"通过/未通过"及具体说明。
Reflexion 模式
Reflexion 是一种多轮自我反思的系统化实现，每一轮反思产生的"经验"会被显式地传递给下一轮。


# Reflexion 执行模板

## 第 1 轮：初始尝试
[任务] 编写一个高效的 LRU Cache 实现
[输出] {初始代码}
[自评分] 7/10

## 反思
- 基本功能正确，但缺少并发安全机制
- get 操作的时间复杂度为 O(1)，符合要求
- 缺少容量满时的淘汰策略日志
- 未处理 key 类型的边界情况

## 经验总结
1. 缓存实现必须考虑线程安全
2. 需要添加操作日志以便调试
3. key 应支持泛型，不应硬编码为 string

## 第 2 轮：改进尝试
[携带经验] 上述 3 条经验
[输出] {改进后的代码}
[自评分] 9/10
批判性对话模式
将反思过程显式化为两个角色之间的对话：一个"创作者"和一个"批判者"。批判者的专业视角可以发现创作者盲区中的问题。


以下是一个双角色批判对话：

[创作者] 我建议使用 Redis 作为这个实时排行榜系统的主存储。

[批判者] 请回答以下问题：
1. Redis 的持久化策略（RDB/AOF）是否满足数据安全要求？如果 Redis 宕机，排行榜数据是否可恢复？
2. 当排行榜数据量超过 Redis 单实例内存限制时，你的扩展方案是什么？
3. 你是否考虑过 Redis Sorted Set 在极端并发下的性能特征？

[创作者]
1. 对于排行榜场景，使用 AOF + 每秒同步可以将数据丢失控制在 1 秒内。但确实需要一个备份方案——建议 MySQL 作为持久化备份，Redis 作为读取热路径。
2. Redis Cluster 可以分片扩展。排行榜可以按时间维度（日榜/周榜/月榜）分散到不同分片。
3. ZADD 和 ZRANGEBYSCORE 在百万级数据量下延迟约 0.1ms，满足需求。但需要注意 ZRANGEBYSCORE 的大范围查询可能引发慢查询。

[批判者] 改进建议：
- 方案基本合理，但建议补充 Redis 与 MySQL 之间的数据同步策略
- 需要明确"慢查询"的阈值和处理方案（如分页、缓存热区间）
- 建议增加降级方案：Redis 不可用时，直接读 MySQL

[最终方案] 综合以上讨论...

反思的局限与补偿策略
自我反思存在固有局限性，了解这些局限才能正确使用这一技术。


[反思局限性 1：确认偏误]
模型倾向于确认自己的初始输出，而非真正找出问题。
补偿策略：使用强制否定提示——"假设你的回答中至少有 2 个错误，找出它们。"

[反思局限性 2：知识盲区]
模型无法发现自己知识之外的错误。
补偿策略：将反思限定在可验证的维度（逻辑一致性、代码语法、格式规范）。

[反思局限性 3：反思深度递减]
第 3 轮之后的反思通常收益递减，甚至可能引入新错误。
补偿策略：限制反思轮数（通常 2 轮最优），设置停止条件。

小结
    

  • 自我反思将"生成"和"评估"分离，利用模型在评估模式下更强的判断力
    • 

  • 结构化反思框架（正确性、完整性、深度、实用性、安全性）避免泛泛之谈
    • 

  • Reflexion 模式通过显式经验传递实现多轮持续改进
    • 

  • 批判性对话模式通过角色分离提供更客观的评估视角
    • 

  • 反思存在确认偏误和深度递减等固有局限，需要补偿策略
    • 

  • 实践中 2 轮反思通常是最优选择，超过 3 轮收益递减
    •
