A/B 测试与对比

核心概念

A/B 测试是 Prompt 优化中用于受控对比实验的标准方法论。其核心思想是在相同条件下，将流量分配到不同的 Prompt 版本，通过统计方法判断哪个版本更优。与传统 Web A/B 测试不同，Prompt A/B 测试需要应对输出不确定性、评估主观性和 API 成本约束等独特挑战。

A/B 测试在 Prompt 工程中的意义
Prompt 优化不应依赖直觉。当你修改了 Prompt 中的一个词、调整了示例顺序、或重写了系统指令，唯一能证明"变好了"的方式就是在相同条件下，用相同数据，做受控对比实验。A/B 测试是实现这一目标的标准方法论。


与传统 Web A/B 测试不同，Prompt A/B 测试面临独特挑战：


    

  • 输出不确定性：相同输入、相同 Prompt，LLM 可能产生不同输出（除非 temperature=0）
    • 

  • 评估主观性：很多场景没有唯一正确答案，需要多维度评判
    • 

  • 成本约束：每次调用都有 API 费用，不能像 Web 测试那样跑百万级流量
    • 

  • 因果模糊：模型行为本身在更新，环境因素（API 延迟、版本变化）可能干扰结果
    • 



受控实验设计
单变量原则
每次实验只改变一个变量，才能归因改进来源。


错误做法 —— 同时改变多个变量：

Prompt A（基线）：
  你是一个客服助手。请回答用户的问题。

Prompt B（同时改了角色 + 格式 + 约束）：
  你是一位拥有 5 年经验的高级技术支持工程师。
  请用以下格式回答：
  1. 问题诊断
  2. 解决方案
  如果不确定，请说"我需要进一步了解"。

问题：如果 B 更好，是因为角色更具体？格式更清晰？还是加了不确定性处理？
正确做法 —— 逐一隔离变量：

实验 1：角色变更
  A: 你是一个客服助手。
  B: 你是一位拥有 5 年经验的高级技术支持工程师。

实验 2：输出格式（在实验 1 的胜者基础上）
  A: 请回答用户的问题。
  B: 请用以下格式回答：1. 问题诊断 2. 解决方案

实验 3：不确定性处理（在实验 2 的胜者基础上）
  A: （无此约束）
  B: 如果不确定，请说"我需要进一步了解"。

最小样本量计算
from scipy.stats import norm
import math

def min_sample_size(effect_size, alpha=0.05, power=0.80):
    z_alpha = norm.ppf(1 - alpha / 2)
    z_beta = norm.ppf(power)
    n = ((z_alpha + z_beta) / effect_size) ** 2
    return math.ceil(n)

import json
from scipy import stats

def analyze_ab_test(scores_a, scores_b, alpha=0.05):
    mean_a = sum(scores_a) / len(scores_a)
    mean_b = sum(scores_b) / len(scores_b)

    t_stat, p_value = stats.ttest_rel(scores_a, scores_b)

    diff = mean_b - mean_a
    pooled_std = ((sum((s - mean_a)**2 for s in scores_a) +
                   sum((s - mean_b)**2 for s in scores_b)) /
                  (2 * len(scores_a) - 2)) ** 0.5
    cohens_d = diff / pooled_std if pooled_std > 0 else 0

    win_b = sum(1 for a, s in zip(scores_a, scores_b) if s > a)
    tie = sum(1 for a, s in zip(scores_a, scores_b) if s == a)
    win_a = sum(1 for a, s in zip(scores_a, scores_b) if s < a)

    return {
        "mean_a": round(mean_a, 3),
        "mean_b": round(mean_b, 3),
        "improvement": f"{(diff/mean_a*100):.1f}%",
        "p_value": round(p_value, 4),
        "significant": p_value < alpha,
        "cohens_d": round(cohens_d, 3),
        "win_rate": f"B胜{win_b} / 平{tie} / A胜{win_a}"
    }

Multi-Armed Bandit 方法
传统 A/B 测试需要等实验结束才能做决策，MAB（多臂老虎机）方法可以在实验过程中动态分配流量，减少"探索劣质方案"的损失。


Thompson Sampling 策略
import numpy as np

class PromptBandit:
    def __init__(self, prompt_variants):
        self.variants = prompt_variants
        self.successes = {v: 1 for v in prompt_variants}
        self.failures = {v: 1 for v in prompt_variants}

    def select(self):
        samples = {}
        for v in self.variants:
            samples[v] = np.random.beta(
                self.successes[v],
                self.failures[v]
            )
        return max(samples, key=samples.get)

    def update(self, variant, reward):
        if reward:
            self.successes[variant] += 1
        else:
            self.failures[variant] += 1

    def stats(self):
        for v in self.variants:
            total = self.successes[v] + self.failures[v] - 2
            rate = (self.successes[v] - 1) / total if total > 0 else 0
            print(f"  {v}: {total}次试验, 成功率={rate:.2%}")

bandit = PromptBandit(["prompt_v1", "prompt_v2", "prompt_v3"])

np.random.seed(42)
true_rates = {"prompt_v1": 0.6, "prompt_v2": 0.75, "prompt_v3": 0.65}

for i in range(500):
    chosen = bandit.select()
    reward = np.random.random() < true_rates[chosen]
    bandit.update(chosen, reward)

print("500 轮后的流量分配结果：")
bandit.stats()

ELO 评分系统
当需要在多个 Prompt 版本间建立全局排名时，ELO 评分系统（源自国际象棋排名）是一个优雅的方案。


class PromptELO:
    def __init__(self, k=32, initial_rating=1500):
        self.ratings = {}
        self.k = k
        self.initial = initial_rating
        self.history = []

    def get_rating(self, prompt_id):
        if prompt_id not in self.ratings:
            self.ratings[prompt_id] = self.initial
        return self.ratings[prompt_id]

    def expected_score(self, ra, rb):
        return 1 / (1 + 10 ** ((rb - ra) / 400))

    def record_match(self, winner, loser, draw=False):
        ra = self.get_rating(winner)
        rb = self.get_rating(loser)

        ea = self.expected_score(ra, rb)
        eb = self.expected_score(rb, ra)

        if draw:
            sa, sb = 0.5, 0.5
        else:
            sa, sb = 1, 0

        self.ratings[winner] = ra + self.k * (sa - ea)
        self.ratings[loser] = rb + self.k * (sb - eb)

        self.history.append({
            "winner": winner,
            "loser": loser,
            "draw": draw
        })

    def leaderboard(self):
        sorted_prompts = sorted(
            self.ratings.items(),
            key=lambda x: x[1],
            reverse=True
        )
        print("Prompt ELO 排行榜：")
        for rank, (pid, rating) in enumerate(sorted_prompts, 1):
            print(f"  #{rank} {pid}: {rating:.0f}")

elo = PromptELO()

matches = [
    ("v3_structured", "v1_basic"),
    ("v3_structured", "v2_cot"),
    ("v2_cot", "v1_basic"),
    ("v3_structured", "v1_basic"),
    ("v2_cot", "v1_basic"),
    ("v3_structured", "v2_cot"),
    ("v2_cot", "v3_structured"),
    ("v3_structured", "v2_cot"),
]

for winner, loser in matches:
    elo.record_match(winner, loser)

elo.leaderboard()
盲对比协议
为确保评估公正性，应建立标准化的盲对比流程。


盲对比协议（Blind Comparison Protocol）

准备阶段：
1. 实验管理员准备 Prompt A 和 Prompt B（评估者不知道版本信息）
2. 使用相同测试集生成两组输出
3. 每对输出随机标记为"左"和"右"（打乱 A/B 对应关系）
4. 生成评估工单，分配给 3 名独立评估者

评估阶段：
5. 评估者独立完成所有工单，不互相讨论
6. 每个工单记录：偏好选择 + 置信度 + 理由
7. 评估者不知道哪个版本是新版本

汇总阶段：
8. 统计每条用例的多数投票结果
9. 计算评估者间一致性（Fleiss' Kappa）
10. Kappa < 0.4 的用例标记为"有争议"，单独复审
11. 揭盲：公布 A/B 对应关系，生成最终报告

实战案例：客服 Prompt 五轮迭代
以下是一个真实的客服场景 Prompt 通过 5 个版本迭代实现可衡量改进的完整过程。


测试场景：电商退货咨询
评估集：80 条真实客服对话
评估方式：LLM-as-Judge (GPT-4o) + 3 名人工评估者
评分维度：准确性(0-3) + 共情(0-2) + 可操作性(0-2) = 总分 0-7

版本 1（基线）：
  "你是客服助手。回答用户关于退货的问题。"
  结果：平均 3.2/7 | 准确性 1.8 | 共情 0.5 | 可操作性 0.9

版本 2（+角色定义）：
  "你是一名经验丰富的电商客服专员，专注于退货和售后服务。
   请耐心、专业地回答用户的问题。"
  结果：平均 4.1/7 (+28%) | 准确性 2.1 | 共情 1.0 | 可操作性 1.0
  p值：0.003 ✓ 显著

版本 3（+结构化输出）：
  "...（版本2的角色定义）
   请按以下格式回答：
   【问题确认】简要复述用户的问题
   【解决方案】具体的操作步骤
   【温馨提示】相关注意事项"
  结果：平均 5.0/7 (+22%) | 准确性 2.4 | 共情 1.1 | 可操作性 1.5
  p值：0.008 ✓ 显著

版本 4（+边界处理）：
  "...（版本3的全部内容）
   特别注意：
   - 如果用户的退货已超过7天期限，请先表达理解，再说明政策
   - 如果信息不足以判断，请礼貌地询问订单号
   - 不要承诺你不确定的结果"
  结果：平均 5.6/7 (+12%) | 准确性 2.7 | 共情 1.3 | 可操作性 1.6
  p值：0.021 ✓ 显著

版本 5（+少样本示例）：
  "...（版本4的全部内容）

   参考以下优秀回复示例：

   用户：我买的衣服收到后发现尺码不对，想退货。
   回复：
   【问题确认】您收到的衣服尺码与预期不符，希望办理退货。
   【解决方案】
   1. 请保持商品吊牌完整，不影响二次销售
   2. 在APP中进入「我的订单」→ 找到该订单 → 点击「申请退货」
   3. 选择退货原因「尺码不合适」，提交申请
   4. 审核通过后，按提示寄回商品，运费由平台承担
   【温馨提示】退货申请需在收货后7天内提交，退款将在收到退货后3个工作日内原路返回。"
  结果：平均 6.1/7 (+9%) | 准确性 2.8 | 共情 1.5 | 可操作性 1.8
  p值：0.034 ✓ 显著
迭代分析
五轮迭代的累计提升：

版本    平均分   累计提升   关键改变点
v1      3.2/7   基线      —
v2      4.1/7   +28%     角色定义是最大的单次提升
v3      5.0/7   +56%     结构化显著提升可操作性

核心发现：
1. 前 3 轮改进（角色+结构+边界）贡献了 85% 的总提升
2. 少样本示例的边际收益递减，但仍然显著
3. 共情维度提升最慢，说明情感表达需要更精细的调优
4. 每轮改进都通过了统计显著性检验（p < 0.05）

小结
    

  • 单变量原则是实验设计的基石：每次只改一个变量，才能准确归因改进来源。
    • 

  • 最小样本量取决于期望的效应量：小效应需约 400 条，中等效应约 65 条，大效应约 26 条。
    • 

  • Multi-Armed Bandit 方法通过动态流量分配减少了传统 A/B 测试的机会成本，适合在线快速筛选。
    • 

  • ELO 评分系统为多个 Prompt 版本建立全局排名，支持持续加入新候选。
    • 

  • 盲对比协议通过随机标记和独立评估消除了评估者偏见，是人工终审的标准流程。
    • 

  • 实战迭代显示：角色定义 + 结构化 + 边界处理贡献了 85% 的总提升，少样本示例的边际收益递减。
    •
