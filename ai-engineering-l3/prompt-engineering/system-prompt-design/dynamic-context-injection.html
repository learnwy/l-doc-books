动态上下文注入

核心概念

动态上下文注入（Dynamic Context Injection）是在运行时将外部信息动态插入到提示词中的技术。与静态系统提示词不同，动态上下文根据每次请求的具体条件实时构建，使模型能够基于最新、最相关的信息进行推理。这是 RAG（检索增强生成）和 Agent 系统的核心基础设施。

动态上下文注入的核心挑战是在有限的 Token 窗口中最大化信息价值——选择最相关的信息、去除冗余、保持上下文连贯性。


检索上下文注入
检索上下文是 RAG 系统的核心组件。通过语义检索找到与用户问题最相关的文档片段，注入到提示中供模型参考。


interface RetrievedChunk {
  content: string;
  source: string;
  score: number;
  metadata: Record<string, unknown>;
}

interface ContextInjectionConfig {
  maxTokens: number;
  maxChunks: number;
  minScore: number;
  deduplicationThreshold: number;
}

const buildRetrievalContext = (chunks: RetrievedChunk[], config: ContextInjectionConfig): string => {
  const filtered = chunks.filter((c) => c.score >= config.minScore).slice(0, config.maxChunks);

  const deduplicated = deduplicateChunks(filtered, config.deduplicationThreshold);

  let totalTokens = 0;
  const selected: RetrievedChunk[] = [];

  for (const chunk of deduplicated) {
    const chunkTokens = estimateTokens(chunk.content);
    if (totalTokens + chunkTokens > config.maxTokens) break;
    selected.push(chunk);
    totalTokens += chunkTokens;
  }

  return selected.map((c, i) => `[参考文档 ${i + 1}] (来源: ${c.source})\n${c.content}`).join('\n\n');
};
注入检索上下文的提示模板：


基于以下参考文档回答用户问题。如果参考文档中没有相关信息，请明确说明。

{检索到的文档片段}

规则：
1. 优先使用参考文档中的信息
2. 引用信息时标注来源编号，如 [参考文档 1]
3. 如果多个文档信息矛盾，指出差异并给出综合判断
4. 不要编造参考文档中没有的事实

用户问题：{用户输入}
对话历史管理
对话历史是多轮对话中最关键的动态上下文。有效的历史管理策略需要在保留必要信息和控制 Token 消耗之间取得平衡。


三种对话历史管理策略：


滑动窗口法：保留最近 N 轮对话，丢弃更早的历史。简单高效，但可能丢失早期重要信息。


摘要压缩法：当历史超过阈值时，用模型将早期历史压缩为摘要。


请将以下对话历史压缩为一段 100 字以内的摘要，保留关键决策和结论：

[第 1-5 轮对话内容]

摘要要求：
- 保留所有技术决策及其理由
- 保留用户的核心需求
- 省略寒暄和重复确认
- 保留代码方案的关键选择
选择性保留法：为每轮对话标记重要性，只保留重要对话轮次。


interface ConversationTurn {
  role: 'user' | 'assistant';
  content: string;
  importance: 'critical' | 'normal' | 'trivial';
  tokens: number;
}

const selectHistory = (turns: ConversationTurn[], tokenBudget: number): ConversationTurn[] => {
  const critical = turns.filter((t) => t.importance === 'critical');
  const normal = turns.filter((t) => t.importance === 'normal');

  let remaining = tokenBudget;
  const selected: ConversationTurn[] = [];

  for (const turn of critical) {
    if (remaining >= turn.tokens) {
      selected.push(turn);
      remaining -= turn.tokens;
    }
  }

  const recentNormal = normal.slice(-6);
  for (const turn of recentNormal) {
    if (remaining >= turn.tokens) {
      selected.push(turn);
      remaining -= turn.tokens;
    }
  }

  return selected.sort((a, b) => turns.indexOf(a) - turns.indexOf(b));
};

Token 预算分配
在有限的上下文窗口中，合理分配 Token 预算是动态上下文注入的核心工程问题。


总上下文窗口：128K tokens（以 Claude 3.5 为例）
推荐预算分配：

系统提示词：1,000-2,000 tokens（1.5%）
检索文档：  30,000-60,000 tokens（45%）
对话历史：  15,000-30,000 tokens（22%）
用户输入：  1,000-5,000 tokens（4%）
输出预留：  4,000-8,000 tokens（6%）
安全缓冲：  25,000+ tokens（20%）
interface TokenBudget {
  systemPrompt: number;
  retrievalContext: number;
  conversationHistory: number;
  userInput: number;
  outputReserve: number;
  safetyBuffer: number;
}

const allocateBudget = (totalWindow: number, userInputTokens: number): TokenBudget => {
  const systemPrompt = Math.min(2000, totalWindow * 0.015);
  const outputReserve = Math.min(8000, totalWindow * 0.06);
  const safetyBuffer = totalWindow * 0.2;
  const userInput = userInputTokens;

  const available = totalWindow - systemPrompt - outputReserve - safetyBuffer - userInput;
  const retrievalContext = Math.floor(available * 0.65);
  const conversationHistory = available - retrievalContext;

  return {
    systemPrompt,
    retrievalContext,
    conversationHistory,
    userInput,
    outputReserve,
    safetyBuffer,
  };
};
上下文质量优化
注入的上下文质量直接决定模型输出质量。低质量上下文（噪声多、相关性低、信息过时）会导致模型输出幻觉或不准确的内容。

# 上下文注入格式规范

每个注入的文档片段使用以下格式：

---
[文档 {序号}]
来源：{来源名称}
更新时间：{日期}
相关度：{高/中}

{文档内容}
---

注意事项：
- 文档内容已根据相关性排序，优先参考前面的文档
- 标注"相关度：中"的文档可能仅部分相关
- 如果文档之间信息矛盾，以更新时间较新的为准
