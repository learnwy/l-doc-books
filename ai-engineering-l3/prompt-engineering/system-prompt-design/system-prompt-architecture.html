系统提示词架构

核心概念

系统提示词（System Prompt）是定义 AI 应用行为的"宪法"级别配置。它在整个对话生命周期中持续生效，决定了模型的身份、能力边界、输出风格和行为规范。一个精心设计的系统提示词架构是构建可靠 AI 产品的基础。

系统提示词与用户消息（User Prompt）的本质区别在于：系统提示词设定全局上下文和规则，用户消息提供具体任务和输入。优秀的系统提示词能让模型在处理任何用户输入时都保持一致的行为模式。


分层架构设计
生产级系统提示词需要清晰的分层结构，每一层解决特定问题，各层之间既独立又协同。


# 身份定义
你是 CodePilot，一个为中高级开发者设计的编程助手。
你的专长是 TypeScript 全栈开发，对 React、Node.js、PostgreSQL 有深入理解。

# 核心能力
你可以完成以下任务：
1. 代码审查：分析代码质量，指出潜在问题
2. 架构建议：基于项目规模和团队情况提供架构方案
3. 调试协助：根据错误信息和代码片段定位问题根因
4. 重构指导：提供安全的重构步骤和最佳实践

# 行为规范
- 默认使用 TypeScript，除非用户明确要求其他语言
- 代码示例必须包含类型注解
- 先给出简短答案，用户追问时再展开细节
- 对于性能敏感的建议，给出时间/空间复杂度分析
- 不确定的内容明确标注"不确定"，而非猜测

# 输出格式
- 代码块使用 typescript 语言标记
- 多方案对比使用表格
- 复杂流程使用有序列表
- 关键概念首次出现时加粗

# 安全约束
- 不生成包含明文密码、密钥或 token 的代码示例
- 不建议禁用安全特性（如 CORS、CSRF 防护）
- 涉及数据库操作时，始终使用参数化查询
- 不提供绕过认证/授权机制的方法
每一层都有明确的职责边界，使得维护和迭代更加高效。当需要调整输出风格时，只需修改行为规范层；当发现新的安全风险时，只需更新安全约束层。


模块化提示词组装
大型 AI 应用通常需要根据不同场景动态组装系统提示词。模块化设计允许将提示词拆分为可复用的组件，按需组合。


interface PromptModule {
  id: string;
  category: 'identity' | 'capability' | 'behavior' | 'constraint';
  content: string;
  priority: number;
  conditions?: Record<string, unknown>;
}

const assembleSystemPrompt = (modules: PromptModule[], context: Record<string, unknown>): string => {
  const activeModules = modules
    .filter((m) => !m.conditions || matchConditions(m.conditions, context))
    .sort((a, b) => a.priority - b.priority);

  const grouped = new Map<string, string[]>();
  for (const mod of activeModules) {
    const existing = grouped.get(mod.category) ?? [];
    existing.push(mod.content);
    grouped.set(mod.category, existing);
  }

  const sections = ['identity', 'capability', 'behavior', 'constraint'];
  return sections
    .map((s) => grouped.get(s)?.join('\n') ?? '')
    .filter(Boolean)
    .join('\n\n');
};

版本管理与迭代策略
系统提示词应像代码一样进行版本管理，每次修改都可追溯和回滚。

迭代策略的关键原则：


    

  • 渐进修改：每次只修改一个层级，观察效果后再修改下一层
    • 

  • A/B 对比：重大调整前先在小流量上测试新版本
    • 

  • 回归测试：维护一组标准测试用例，每次修改后验证输出是否符合预期
    • 

  • Token 预算监控：系统提示词通常占用 500-2000 tokens，需要在信息密度和 Token 消耗之间平衡
    •

# 系统提示词评估检查清单

□ 身份层：模型能否在第 1 轮对话中准确描述自己的身份？
□ 身份层：第 10 轮对话后，角色是否发生漂移？
□ 能力层：对超出能力范围的请求，是否正确拒绝？
□ 行为层：输出格式是否在 95% 以上的情况下符合规范？
□ 约束层：对 20 种常见越界攻击，拦截率是否 ≥ 90%？
□ 整体：系统提示词 Token 数是否在预算范围内？
□ 整体：是否所有层级都有清晰的分隔标记？
小结
    

  • 系统提示词是 AI 应用的行为基石，需要架构级别的设计思维
    • 

  • 分层架构（身份、能力、行为、约束）使提示词维护更加高效
    • 

  • 模块化设计支持动态组装，适应多场景、多用户群体的需求
    • 

  • 版本管理和回归测试是生产级系统提示词的必备实践
    • 

  • Token 预算和信息密度需要持续平衡优化
    • 

  • 评估体系应覆盖一致性、安全性、格式遵循率和用户满意度
    •
