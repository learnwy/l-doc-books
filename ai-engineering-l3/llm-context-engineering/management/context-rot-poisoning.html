上下文腐烂与污染

一个智能体跑着跑着突然变笨：开始重复无效动作、坚持一个明显错误的前提、或在两个矛盾的指令间反复横跳。这通常不是模型「能力下降」，而是它的上下文病了。为何上下文工程 里命名过四种失败模式，本篇把它们展开成可判别、可防治的诊断手册——这是排查「越跑越笨」类故障的主要工具。

核心概念

上下文病害指上下文窗口随长度和轮次累积而发生的质量退化，导致模型行为偏离预期。它的共同根源是窗口里混入了稀释、误导或矛盾的内容，而模型缺乏自动甄别能力——它默认窗口里的一切都是该信任的输入。四种病害按机理分类，下表给出判别与对策的总览。

病害 机理 典型症状 主要对策
腐烂 rot 长度增长致整体注意力稀释 越往后越忽略信息、重复早期动作 压缩、卸载、缩短有效窗口
污染 poisoning 错误/无关内容进入并自我放大 坚持一个错误前提推下去 隔离、来源校验、剪枝
分心 distraction 次要信息过多牵走注意力 偏离主任务、纠缠细枝末节 选择更严、工具收敛
冲突 clash 上下文含矛盾指令/事实 在两种行为间摇摆、自相矛盾 去重、约束分层、清理矛盾

腐烂：长度本身就是病因

腐烂是最隐蔽的一种，因为没有单一的「坏内容」可指——是窗口太长这件事本身导致整体注意力被稀释。2026 年多个智能体基准观察到，模型正确率在上下文超过约 32K token 后系统性下滑，且智能体越来越倾向重复历史里出现过的动作，而非根据当前状态决策（来源：Agentic Context Engineering）。

腐烂的对策不是「让模型更强」，而是「让有效窗口更短」：及时压缩历史、把冷数据卸载到外存、在子任务边界重置上下文。这正是 上下文压缩 与 记忆卸载与外存 存在的根本理由。长上下文 hub 从架构角度记录了同类失败，见 上下文腐烂的失败。

污染：错误会自我放大

污染指一段错误或无关的内容进入上下文后，把后续推理带偏，而且——这是它最危险的地方——会沿轮次自我放大。模型基于被污染的前提生成新内容，新内容又进入历史成为下一轮的「事实」，错误像滚雪球一样固化。一个被幻觉出来的 API 名字，可能让智能体接下来十轮都围着这个不存在的 API 打转。

污染的对策有三层：一是隔离（把可疑信息段放进独立的子上下文，不让它污染主线，见 智能体上下文工程 的多智能体隔离）；二是来源校验（写入长期记忆前做跨源验证，别把单次输出当成事实固化）；三是剪枝（一旦识别出污染源，直接从上下文删除）。来源校验的把关与护栏机制相通，见 约束与护栏。

分心与冲突：选择和去重的失职

分心和冲突往往是组装阶段没做好的后果，在管理阶段才暴露。

分心是窗口塞了太多次要信息，把模型的注意力从主任务牵走。症状是智能体纠缠细枝末节、在无关分支上花大量轮次。它本质是 上下文选择 太松——选进来太多边缘内容。对策是收紧选择、收敛工具集，让窗口只留与主任务强相关的内容。

冲突是上下文里并存矛盾的指令或事实：系统提示说「永远用中文」，某段历史又有「请用英文回答」；检索回两段互相打架的政策。模型会在矛盾间摇摆，输出自相矛盾。对策是去重与约束分层——给指令明确优先级（见提示工程的 指令层级），并在装配时主动清理已知矛盾的片段。

一套防治流程

把四种病害的防治串成一条可执行的循环：

  • 预防：组装阶段严格选择（防分心）、去重清矛盾（防冲突）。
  • 监控：跟踪窗口占用与轮次，临近腐烂阈值就压缩/卸载。
  • 隔离：高风险或不可信内容放子上下文，防污染扩散。
  • 校验：写入长期记忆前跨源验证，防污染固化。
  • 复位：子任务边界重置上下文，把累积的腐烂一次性清掉。

这套流程不是一次性的，而是贯穿智能体整个生命周期的常驻机制。它的有效性需要被度量，那是 上下文评测 的任务。

小结

  • 智能体「变笨」多是上下文病了而非模型弱；四种病害——腐烂、污染、分心、冲突——按机理可判别。
  • 腐烂是长度本身致注意力稀释（约 32K 后显著），对策是缩短有效窗口：压缩、卸载、复位。
  • 污染最危险因其沿轮次自我放大，对策是隔离、来源校验、剪枝。
  • 分心是选择太松、冲突是去重失职，二者根在组装阶段，对策回到选择与去重。
  • 防治是常驻循环：预防—监控—隔离—校验—复位，且需被评测度量。
