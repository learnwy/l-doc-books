状态与草稿板

让一个智能体跑五十轮而不「失忆」，靠的不是更大的窗口，而是一块显式的草稿板——它在上下文里维护一份当前任务的活状态：做到第几步、确认了哪些事实、下一步要干啥。没有草稿板的智能体会在长任务里反复忘记自己已经做过的事，重复调同一个工具、绕回已经否决过的方案。本篇讲草稿板的形态、它和外存记忆的分工，以及如何用它让长任务保持连贯。

核心概念

草稿板（scratchpad）是上下文窗口里一段被持续读写的结构化状态，承载智能体在「当前任务进行期间」需要随时取用的工作记忆。它的关键特征是「活」——每一轮都可能被更新，且就在窗内、无需取回。这区别于卸载到外存的冷数据：草稿板是热的、轻的、随手可改的；外存是冷的、重的、按需取回的（见 记忆卸载与外存）。

下图把一轮智能体循环里草稿板的读写位置画出来：它在每轮被读取以决策、被更新以记录进展。

flowchart TD
  S[草稿板状态<br/>待办/已确认/当前步] --> R[读取: 决定下一步]
  R --> A[执行动作<br/>工具调用/推理]
  A --> O[观察结果]
  O --> U[更新草稿板<br/>勾掉完成项/记录新事实]
  U --> S
  U --> C{任务完成?}
  C -->|否| R
  C -->|是| E[结束]

草稿板里常放四类状态，下表说明各自作用与更新时机。

状态项 作用 更新时机
待办清单 把大任务拆成可勾选的步骤 完成一步即勾掉
已确认事实 沉淀不再变的结论，防重复求证 每次确认新事实时追加
当前焦点 标记此刻在做哪一步 切换子任务时更新
待解问题 记录卡住的点，避免遗漏 遇阻时记、解决后清

待办清单的设计与提示工程里的任务分解相通，见 分解与规划。

待办清单：对抗长任务失忆

最有效的草稿板形态是一份显式待办清单。把「实现一个登录功能」拆成「1. 设计接口 2. 写后端 3. 写前端 4. 加测试」，让智能体每完成一步就在上下文里把它勾掉。这有两个作用：一是防止智能体忘记还有哪些步没做（长任务里这是真实问题），二是给它一个稳定的进度锚点，每轮都能从「我做到第几步」重新定位，而不是从头重读全部历史。

LangChain 把这种「让 agent 在任务进行中写下中间结论和已完成步骤」的做法归为 Write 策略里的短期草稿板，明确区别于跨会话的长期记忆（来源：Context Engineering for agents）。短期草稿板防的是「任务内失忆」，长期记忆管的是「跨会话复用」——两者别混用。

结构化笔记：让状态可被压缩

草稿板还有一个常被忽略的价值：它让压缩有据可依。当窗口要压缩历史时（见 上下文压缩），有了显式的「已确认事实」清单，就能放心丢掉那些事实的推导过程——因为结论已经被结构化地记下了。没有草稿板时，压缩只能盲目摘要，容易把还没沉淀的关键结论一起丢掉。

因此一个好习惯是：智能体每确认一个不会再变的结论，就立即写进草稿板的「已确认事实」，而不是任由它散落在对话历史里。这相当于主动把关键信息从「易失的历史」搬进「稳定的状态」，为后续压缩兜底。

草稿板与外存的分工

草稿板和外存记忆是一对，分工清晰：

  • 草稿板（窗内）：当前任务的活状态，小、热、每轮可改。例如「第 2 步进行中，已确认用户要 OAuth 登录」。
  • 外存（窗外）：体量大或暂时用不上的内容，冷、重、按需取回。例如第 2 步产出的那份完整设计文档。

一个长任务的典型流程是：草稿板记进度与关键事实 → 大产出卸载到文件系统 → 草稿板里只留「设计见 design.md」这样的指针。这样窗口始终保持轻量，又不丢任何东西。把本该卸载的大块内容硬塞进草稿板，会让草稿板膨胀、反噬窗口预算，是常见反模式。

多智能体里的状态传递

在多智能体系统里，草稿板还承担子任务间的状态传递：主智能体把子任务的目标与约束写成一份精简状态交给子智能体，子智能体完成后把结果状态回传。这里的关键是「传递恰好够用的状态」——既不让子智能体缺信息，也不把主智能体的全部上下文倒给它（那会污染子智能体、抬高成本）。这套隔离式状态传递是 智能体上下文工程 的核心议题。

小结

  • 草稿板是窗内持续读写的活状态，让长任务智能体不失忆、有稳定进度锚点。
  • 显式待办清单是最有效形态，每步勾掉，防遗漏、防重复劳动。
  • 把已确认结论结构化记下，能为压缩兜底——丢推导过程而不丢结论。
  • 草稿板（热、轻、窗内）与外存（冷、重、窗外）分工：大产出卸载、草稿板只留指针。
  • 多智能体里草稿板还传递子任务状态，原则是「恰好够用」。
