上下文评测

「我加了记忆、上了压缩、改了排序——智能体真的变好了吗？」如果回答不上来，你的上下文策略就是在凭直觉调参。上下文评测把上下文当成一个可度量的工程变量：用消融定位哪段内容真有用、用对照基准量化长上下文下的退化、用面向上下文（而非只看最终答案）的指标。本篇讲怎么测、测什么、以及 2026 年的基准现状。

核心概念

上下文评测的对象不是模型本身，而是「上下文策略」这个变量：给定同一个模型和任务，不同的选择/排序/压缩/卸载策略，效果差多少。它的核心方法论是控制变量——固定模型与任务，只改上下文策略，观测输出质量与成本的变化。这要求评测能把「上下文这一变量」从「模型能力」里剥离出来。

下图把一次上下文评测的闭环画出来：从构造对照、跑变体、到归因与迭代。

flowchart TD
  D[黄金数据集<br/>任务+期望输出] --> V[策略变体<br/>A: 全塞 / B: 精选 / C: 压缩]
  V --> RUN[固定模型逐变体跑]
  RUN --> M[多维指标<br/>正确率/成本/延迟]
  M --> ABL[消融归因<br/>哪段内容贡献了正确率]
  ABL --> DEC{某策略更优?}
  DEC -->|是| ADOPT[采纳并回归]
  DEC -->|否| V

上下文评测看的指标比「答对没」更宽，下表列出关键维度。

指标维度 衡量什么 为何重要
任务正确率 最终输出是否达标 底线，但不解释原因
上下文利用率 入窗内容有多少真被用到 暴露「塞了没用」的浪费
token 成本 每次/每任务的 token 量 直接关联预算与延迟
位置敏感度 关键信息移位后准确率变化 检测 lost in the middle
退化曲线 正确率随上下文长度的变化 定位腐烂阈值

任务正确率的通用评测方法论属于评测 hub，见 评测原则；本篇聚焦「上下文这一变量」的专门测法。

消融：定位哪段内容真有用

最有诊断力的方法是消融实验：把入窗内容分成若干段（系统指令、检索片段、记忆、历史），逐段移除或替换，看正确率掉多少。掉得多的段就是真贡献，掉不动的段就是可疑的占位浪费。

消融能直接回答两个高价值问题。其一，「我检索的 8 段，哪几段真在被用」——往往发现只有 2–3 段贡献了几乎全部正确率，其余在白占预算（印证 上下文选择 的「召回宽、入窗窄」）。其二，「我加的记忆有没有用」——把记忆段移除后正确率不变，说明记忆策略没真正命中相关条目。消融把「凭感觉觉得有用」变成「数据证明有用」。

位置探针：量化 lost in the middle

要验证 排序与位置效应 在你的场景成立到什么程度，用位置探针：把同一段关键证据分别放在窗口开头、中段、结尾，其余内容不变，测三种摆法的准确率。如果中段明显低于头尾，就证实了 lost in the middle 在你这里成立，且量化了它的幅度——这直接指导你把关键证据往结尾排。

把这个测法系统化，就是「大海捞针」式探针：在长上下文里埋一条特定事实，移动它的位置，看模型能否捞出来。长上下文 hub 有专门的评测方法论，见 长上下文评测。

退化曲线与 2026 基准

要定位你的腐烂阈值，画退化曲线：固定任务，逐步加长上下文（多塞无关内容或多轮历史），记录正确率随长度的变化。曲线开始明显下行的点，就是你这个模型 + 任务的有效上下文上限——超过它再塞就是负收益。

2026 年出现了专门压测这件事的基准。LOCA-bench 在「可控且极端的上下文增长」下评测语言智能体，AgentSwing 关注长程网页智能体的并行上下文管理路由（来源：LOCA-bench, arXiv 2602.07962；AgentSwing, arXiv 2603.27490）。这些基准的共同信号是：上下文增长本身是一个独立的、可被系统性度量的失效维度，而不是模型能力的附属。退化曲线对应的失效，正是 上下文腐烂与污染 里的腐烂。

把评测接进迭代

评测不是一次性验收，而要接进上下文策略的迭代回路。实践建议：

  • 维护一个小而稳定的黄金数据集（覆盖典型与边界任务），每次改上下文策略都跑一遍回归。
  • 把 token 成本和正确率一起看——一个把成本翻倍只换来一个百分点正确率的策略不值得采纳。
  • 对关键策略做消融，确保每段入窗内容都「赚回了它的 token」。

这套「golden 集 + 回归 + 多维指标」的纪律，和通用 LLM 评测一脉相承，见 自动化评测。没有评测，上下文工程陷阱 里的反模式你将无从察觉。

小结

  • 上下文评测度量的是「上下文策略」这个变量，方法核心是控制变量：固定模型与任务，只改策略。
  • 消融逐段移除入窗内容，定位真贡献的段——常发现多数检索片段在白占预算。
  • 位置探针量化 lost in the middle，退化曲线定位腐烂阈值；2026 有 LOCA-bench 等专门基准。
  • 看多维指标而非只看正确率，尤其把 token 成本和正确率一起权衡。
  • 评测要接进迭代回路：稳定黄金集 + 每次改策略跑回归。
