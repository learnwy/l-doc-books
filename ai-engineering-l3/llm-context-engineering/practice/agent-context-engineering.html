智能体上下文工程

前面所有工序——选择、排序、压缩、卸载、草稿板、病害防治——在一个真实智能体里是同时运转、互相耦合的。本篇把它们焊成一个完整的智能体循环，并回答规模化的关键问题：当单个智能体的上下文撑不住一个复杂任务时，如何用多智能体的上下文隔离把它拆开并行。2026 年的生产数据显示，隔离式多智能体能在显著降低单体负担的同时大幅提升表现。

核心概念

智能体上下文工程是把上下文的「组装」与「管理」整合进智能体每一轮决策循环的工程实践。它的核心约束是：智能体每轮看到的窗口都是程序动态拼装的，而拼装质量直接决定这一轮的决策质量。单体智能体把所有上下文压在一个窗口里，随任务复杂度上升必然撞上腐烂与预算上限；多智能体则通过把上下文切分到多个隔离窗口来突破这个上限。

下图把一个真实智能体的单轮循环画出来，标出每个工序在循环中的位置。

flowchart TD
  T[到达新一轮] --> SEL[选择: 历史/检索/记忆/工具]
  SEL --> CMP[压缩: 裁工具结果/摘要历史]
  CMP --> ORD[排序: 指令前置/关键证据后置]
  ORD --> W[装配窗口快照]
  W --> LLM[LLM 决策]
  LLM --> ACT[执行: 工具调用或回答]
  ACT --> SP[更新草稿板状态]
  SP --> OFF[卸载大产出到外存]
  OFF --> T

单体与多智能体在上下文上的取舍，下表对照。

维度 单体智能体 多智能体（隔离）
上下文窗口 一个，承载全部 多个，各管子任务
腐烂风险 随任务复杂度急升 每个子窗口短、风险低
token 成本 单窗口可能撑爆预算 总量可控、可并行
协调开销 无 主从通信、状态传递
适合任务 简单、线性 复杂、可分解、需并行

任务的分解策略与规划相关，见 分解与规划。

单轮循环：所有工序的协同

先看单体智能体一轮里各工序如何协同。到达新一轮时，先做 选择——从历史、检索、记忆、工具池里挑出本轮相关的候选；选中的工具结果若冗长，立即 压缩；然后 排序，把系统指令前置、当前最关键证据和用户问题后置；装配出窗口快照交给模型决策；模型给出动作后，把进展写进 草稿板、把大产出 卸载 到外存；进入下一轮时再重做选择。

关键在于这些工序不是一次性配置，而是每轮重算。一个把选择写死在会话开头的智能体，跑到中段窗口必然偏离当前子任务——这是单体智能体最常见的退化。

多智能体隔离：突破单窗口上限

当任务复杂到单窗口装不下、或腐烂无法靠压缩压住时，就该上多智能体。核心思想是上下文隔离：把任务拆成子任务，每个子任务交给一个拥有独立、干净窗口的子智能体，主智能体只负责分派与汇总。

这样做的收益是双重的。其一，每个子窗口只承载自己子任务的上下文，短而干净，腐烂与分心风险大降。其二，可疑或高风险内容被关在子上下文里，不会污染主线——这正是 上下文腐烂与污染 里污染防治的隔离手段。Anthropic 报告其多智能体架构相比单智能体取得了 90.2% 的表现提升，并在生产评测中实现 84% 的 token 削减（来源：Effective context engineering for AI agents）。多智能体的协调本身是独立学科，见多智能体系统 hub 的 多智能体记忆。

主从之间：传递恰好够用的上下文

多智能体的成败系于一个细节：主智能体给子智能体多少上下文。两个极端都错——给太少，子智能体缺信息、做错方向；把主智能体的全部历史倒给它，则既污染了子窗口、又抬高成本、还可能引入与子任务无关的腐烂。

正确做法是传递「恰好够用」的状态：子任务的目标、必要的约束、相关的少量事实，外加一个可按需取回更多的引用（比如「详情见 spec.md」）。子智能体完成后，也只回传精简的结果状态，而非它整个工作过程。这种最小化的状态传递，是 状态与草稿板 在多智能体场景的直接应用。

一个端到端的例子

设想一个「调研三家竞品并写对比报告」的智能体。单体做法会把三家的全部抓取内容堆进一个窗口，很快腐烂。隔离做法是：主智能体拆出三个子任务，各派一个子智能体调研一家——每个子智能体的窗口只装自己那家的资料，调研完把一份结构化摘要回传；主智能体收齐三份摘要，在一个干净的窗口里完成对比写作。全程主窗口从不承载原始抓取内容（那些被卸载到文件系统），每个子窗口都短而专注。这个例子把本 hub 的几乎所有工序串了起来——它的效果好不好，要靠下一篇的评测来度量。

小结

  • 智能体上下文工程是把选择、压缩、排序、草稿板、卸载整合进每轮循环，且每轮重算而非一次性配置。
  • 单体智能体随复杂度上升必撞腐烂与预算墙；多智能体用上下文隔离突破单窗口上限。
  • 隔离收益双重：子窗口短而干净（降腐烂分心）、风险内容被关在子上下文（防污染扩散）；生产数据显示大幅提升与显著 token 削减。
  • 多智能体成败在「传递恰好够用的上下文」：目标 + 必要约束 + 少量事实 + 可取回引用。
