上下文窗口预算

「我的模型有 100 万 token 窗口，所以容量不是问题」——这句话在 2026 年同时是对的和危险的。对，是因为 13 个主流前沿模型确实都已提供 1M 以上的窗口；危险，是因为窗口大小是上限，不是预算，而真正约束你的是预算：每段内容的 token 成本、注意力随长度膨胀的算力代价、以及质量随占用率下降的隐性税。本篇把窗口从一个数字变成一张可核算的预算表。

核心概念

预算思维的起点，是承认窗口里的每一段内容都在竞争同一份稀缺额度，而这份额度有三重代价：占位代价（挤掉别的内容）、算力代价（注意力计算变贵）、质量代价（占用越满，有效注意力越稀）。把这三重代价显式记账，就是上下文预算。

下图把一份典型的智能体窗口拆成预算条目，每一条都该被单独审视「值不值这些 token」。

flowchart TD
  W[窗口总额度<br/>如 200K token] --> F[固定开销]
  W --> V[可变内容]
  F --> F1[系统指令]
  F --> F2[工具定义<br/>常被低估]
  V --> V1[历史消息<br/>随轮次线性增长]
  V --> V2[检索片段<br/>选择策略决定]
  V --> V3[记忆条目<br/>卸载策略决定]
  V --> V4[草稿板状态]
  V1 --> R[剩余可用额度<br/>= 总额 − 已占用]
  R --> Q[有效注意力质量<br/>随占用率下降]

不同前沿模型的窗口与「装满它」的成本差异极大，这直接决定你的预算松紧。下表为 2026 年 6 月的公开数据。

token 不是字符：内容的真实计价

预算的最小单位是 token，而不同内容的 token 密度差异很大，估错会让预算全盘失真。粗略经验：英文约 4 字符/token，中文约 1.5 字符/token，代码因符号密集而 token 更碎。一个被严重低估的条目是工具定义——一个把 2500 多个 API 端点平铺成工具的传统 MCP 服务，光工具 schema 就能吃掉约 117 万 token；而 Cloudflare 在 2026 年 2 月的 Code Mode 架构把它们收敛成两个工具，仅约 1000 token（来源：Context Engineering Agent Reliability Playbook 2026）。这说明工具定义常常是预算里最大的隐形开销，而它属于「固定开销」、每一轮都在付费。

工具定义的精简策略属于 上下文选择 的范畴；如何让历史消息不无限增长，则见 上下文压缩。

注意力的算力代价：为什么长不只是慢

标准自注意力的计算量随序列长度平方增长。若序列长度为 nnn、隐藏维度为 ddd，注意力的计算复杂度约为 O(n2d)O(n^2 d)O(n2d)，KV 缓存的显存占用则随 nnn 线性增长，约为 2⋅n⋅L⋅d2 \cdot n \cdot L \cdot d2⋅n⋅L⋅d（LLL 为层数，系数 2 对应 K 和 V）。这意味着把上下文从 50K 翻倍到 100K，注意力计算量约变为 4 倍，而显存约变为 2 倍。

预算因此不只是「花多少钱」，还包括「跑多慢、占多少显存」。这也是为什么即便模型「装得下」，把窗口塞满在生产上往往不划算。注意力平方代价的缓解（稀疏化、分页）属于供给侧，见 注意力复杂度；KV 缓存的显存账见 KV 缓存的显存核算。

质量税：占用率与有效注意力

预算里最容易被忽略的是质量税。多项 2026 年评测显示，模型在窗口占用超过约 32K token 后正确率开始下滑，且呈现强烈的位置偏好——头尾内容被充分关注，中段近乎被忽略（即 lost in the middle）。换句话说，剩余额度并非「免费可用」：你用得越满，每一段内容分到的有效注意力越少。

把这一点写进预算，意味着应当为「质量」预留余量，而不是把窗口塞到物理上限。位置偏好的成因与利用见 排序与位置效应，质量退化的全貌见 上下文腐烂与污染。

一个可操作的预算公式

把上面三重代价合成一个简单的决策准则：对每个候选内容片段 ccc，估计它的边际效用 u(c)u(c)u(c) 与边际代价 cost(c)\text{cost}(c)cost(c)，仅当 u(c)>λ⋅cost(c)u(c) > \lambda \cdot \text{cost}(c)u(c)>λ⋅cost(c) 时纳入窗口，其中 λ\lambdaλ 是随当前占用率上升而增大的稀缺乘子。占用率越高，门槛越严——这正是把「窗口越满越该挑剔」编码进了公式。实践中 u(c)u(c)u(c) 常用检索相关性分数近似，cost(c)\text{cost}(c)cost(c) 用 token 数近似，λ\lambdaλ 用一条随占用率上升的简单曲线。

小结

  • 窗口大小是上限，预算才是约束；每段内容承担占位、算力、质量三重代价。
  • 2026 年 1M 窗口已普及，但装满成本在不同模型间差达 71 倍，且部分模型越过阈值会整段加价。
  • 工具定义是最常被低估的固定开销，可达百万 token 级，精简它收益巨大。
  • 注意力按 O(n2d)O(n^2 d)O(n2d) 增长、KV 缓存线性增长、质量在约 32K 后下滑——三者共同要求为质量预留余量，而非塞满。
