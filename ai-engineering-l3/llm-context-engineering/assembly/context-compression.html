上下文压缩

选好、排好之后，内容仍常常放不下，或者放得下但太贵、太稀。压缩就是在尽量不丢关键事实的前提下，把信息密度提上去。它是上下文工程里收益最直接、也最容易做坏的一道工序——压过头会丢掉后续推理依赖的事实，压不够则白白付费。本篇讲三类压缩手段、压缩的时机，以及如何避免把它做成「有损得失控」。

核心概念

压缩是一个有损编码问题：把一段上下文 xxx 映射成更短的 x′x'x′，目标是在 token 数大幅下降的同时，保留对下游任务有用的信息。关键不是「缩多少」，而是「缩掉的是不是冗余」。好的压缩缩掉的是寒暄、重复、过程性废话；坏的压缩缩掉的是某个 ID、某条约束、某个已确认的事实。

下图把一次智能体循环里的压缩触发与三条压缩路径画出来。

flowchart TD
  A[轮次累积<br/>窗口占用上升] --> B{超过压缩阈值?}
  B -->|否| C[原样保留]
  B -->|是| D[压缩选路]
  D --> E[摘要<br/>多轮历史压成结论]
  D --> F[压实 compaction<br/>工具结果裁剪/合并]
  D --> G[剪枝<br/>丢弃低价值片段]
  E --> H[压缩后窗口]
  F --> H
  G --> H
  H --> I[继续循环]

三类手段的适用对象与风险各不相同，下表对照。

手段 压缩对象 典型做法 主要风险
摘要 summarization 多轮对话历史 调模型把 N 轮压成一段结论 丢失后续要引用的细节
压实 compaction 冗长工具结果 裁剪字段、合并重复、保留关键 裁掉了下游需要的字段
剪枝 pruning 低价值片段 按分数直接丢弃整段 误删真正相关的片段

摘要与剪枝的判分逻辑和 上下文选择 同源——本质都是「什么有用」的判定，区别只在选择是入窗前、压缩是入窗后。

摘要：把历史压成结论

最常见的压缩是历史摘要。当对话或智能体循环跑了很多轮，前面的大段过程往往可以压成几句结论：用户想要什么、已经确认了哪些事实、当前进行到哪一步。Anthropic 把这套在长程智能体里的做法称为 compaction 与结构化笔记，配合多智能体架构来对抗上下文污染（来源：Effective context engineering for AI agents）。

摘要的危险在于「丢了之后才需要」。一个稳妥的模式是分层保留：把原始历史卸载到窗外（见 记忆卸载与外存），窗内只留摘要，一旦后续需要细节再按需选回。这样摘要不是不可逆的删除，而是「热数据降级为冷数据」。

压实：工具结果是压缩的主战场

智能体里最肥的 token 来源往往是工具结果——一次数据库查询可能返回几 KB 的 JSON，一次网页抓取可能是上万 token 的 HTML。把它们原样塞回窗口是巨大的浪费。压实就是在工具结果回流到上下文前做一道裁剪：只留模型决策真正需要的字段、合并重复行、把长文本截断到关键段。

压实的收益有真实量化：Cloudflare 的 Code Mode 报告显示，把工具调用方式改造后，简单任务省 32% token、复杂批量任务省 81%（来源：Context Engineering Agent Reliability Playbook 2026）。压实和压缩在底层与长上下文的 KV 压缩是不同层面的事——前者压「放进窗口的内容」，后者压「已在窗口里的注意力缓存」，见 KV 缓存压缩。

压缩的时机：阈值与节奏

什么时候触发压缩，本身是个工程决策。两种常见策略：

  • 阈值触发：窗口占用超过某个比例（如 70%）就压一次。简单、可预测，但可能在任务关键时刻打断。
  • 边界触发：在子任务自然边界（一个工具调用链结束、一个子目标达成）压一次。语义更干净，但需要任务结构可识别。

实践中常二者结合：边界优先，阈值兜底。无论哪种，都要避免「每轮都压」——频繁摘要会累积有损误差，把第 1 轮的事实经过五次转述压成面目全非。这种「转述漂移」是压缩做坏的典型，也是 上下文腐烂与污染 里腐烂的一个来源。

一个最小压缩公式

把压缩的取舍写成一个保真度约束下的最小化目标：在保证保真度 fidelity(x′)≥τ\text{fidelity}(x') \ge \taufidelity(x′)≥τ 的前提下，最小化 ∣x′∣|x'|∣x′∣（压缩后 token 数）。其中 τ\tauτ 是任务能容忍的最低保真度——客服结算这类强依赖事实的任务 τ\tauτ 要高、压得保守；闲聊摘要 τ\tauτ 可低、压得激进。把 τ\tauτ 显式化，能防止「一刀切压 50%」这种不分任务的粗暴压缩。

小结

  • 压缩是有损编码，关键是「缩掉的是冗余还是事实」；缩对了省钱提质，缩错了丢失下游依赖。
  • 三类手段：摘要压历史、压实裁工具结果、剪枝丢低价值片段，对象与风险各异。
  • 工具结果是压实主战场，真实可省 32%–81% token；与 KV 缓存压缩是不同层面。
  • 时机用「边界优先、阈值兜底」，避免每轮压造成转述漂移；用保真度阈值 τ\tauτ 按任务调激进程度。
