部署与监控

从开发到生产

本地 tsx watch 足以支撑开发调试，但生产环境需要容器化部署、环境隔离、健康检查、优雅关闭和全链路监控。本节以 Docker 容器化 Hono Agent 服务为主线，覆盖从镜像构建到 Prometheus 指标采集的完整流程。



Dockerfile
多阶段构建减小镜像体积，生产阶段只包含运行时依赖：


# Dockerfile
FROM node:20-alpine AS builder

WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile

COPY . .
RUN pnpm run build

FROM node:20-alpine AS runner

WORKDIR /app
ENV NODE_ENV=production

COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./

EXPOSE 3000

HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
  CMD wget -qO- http://localhost:3000/health || exit 1

CMD ["node", "dist/index.js"]


环境变量配置
生产环境通过环境变量注入敏感配置，绝不硬编码：


interface EnvConfig {
  port: number;
  nodeEnv: string;
  openaiApiKey: string;
  anthropicApiKey: string;
  logLevel: string;
  corsOrigin: string;
}

function loadEnvConfig(): EnvConfig {
  const required = (key: string): string => {
    const value = process.env[key];
    if (!value) throw new Error(`缺少环境变量: ${key}`);
    return value;
  };

  return {
    port: parseInt(process.env.PORT ?? '3000', 10),
    nodeEnv: process.env.NODE_ENV ?? 'development',
    openaiApiKey: required('OPENAI_API_KEY'),
    anthropicApiKey: required('ANTHROPIC_API_KEY'),
    logLevel: process.env.LOG_LEVEL ?? 'info',
    corsOrigin: process.env.CORS_ORIGIN ?? '*',
  };
}


健康检查端点
健康检查分为存活探针（liveness）和就绪探针（readiness）。存活探针验证进程是否运行，就绪探针验证依赖服务是否可用：


import { Hono } from 'hono';

const app = new Hono();
let isReady = false;

app.get('/health', (c) => {
  return c.json({ status: 'ok', uptime: process.uptime() });
});

app.get('/ready', async (c) => {
  if (!isReady) {
    return c.json({ status: 'not_ready' }, 503);
  }
  return c.json({ status: 'ready' });
});

async function startServer(): Promise<void> {
  const config = loadEnvConfig();
  isReady = true;

  const { serve } = await import('@hono/node-server');
  serve({ fetch: app.fetch, port: config.port }, (info) => {
    console.log(`Agent 服务启动: http://localhost:${info.port}`);
  });
}


优雅关闭
收到 SIGTERM 信号后，停止接受新请求，等待进行中的请求完成，再退出进程：


function setupGracefulShutdown(server: { close: (cb: () => void) => void }): void {
  let isShuttingDown = false;

  const shutdown = (signal: string) => {
    if (isShuttingDown) return;
    isShuttingDown = true;

    console.log(`[Shutdown] 收到 ${signal}，开始优雅关闭...`);

    server.close(() => {
      console.log('[Shutdown] 所有连接已关闭，进程退出');
      process.exit(0);
    });

    setTimeout(() => {
      console.error('[Shutdown] 超时强制退出');
      process.exit(1);
    }, 10_000);
  };

  process.on('SIGTERM', () => shutdown('SIGTERM'));
  process.on('SIGINT', () => shutdown('SIGINT'));
}

Prometheus 指标
在 Agent 服务中暴露关键指标，供 Prometheus 拉取：


class MetricsCollector {
  private requestCount = 0;
  private requestDurations: number[] = [];
  private tokenCounts: { prompt: number; completion: number }[] = [];
  private errorCount = 0;

  recordRequest(durationMs: number): void {
    this.requestCount++;
    this.requestDurations.push(durationMs);
  }

  recordTokens(prompt: number, completion: number): void {
    this.tokenCounts.push({ prompt, completion });
  }

  recordError(): void {
    this.errorCount++;
  }

  toPrometheus(): string {
    const avgDuration =
      this.requestDurations.length > 0
        ? this.requestDurations.reduce((a, b) => a + b, 0) / this.requestDurations.length
        : 0;

    const totalPromptTokens = this.tokenCounts.reduce((s, t) => s + t.prompt, 0);
    const totalCompletionTokens = this.tokenCounts.reduce((s, t) => s + t.completion, 0);

    return [
      `agent_requests_total ${this.requestCount}`,
      `agent_request_duration_avg_ms ${avgDuration.toFixed(2)}`,
      `agent_errors_total ${this.errorCount}`,
      `agent_prompt_tokens_total ${totalPromptTokens}`,
      `agent_completion_tokens_total ${totalCompletionTokens}`,
    ].join('\n');
  }
}

const metrics = new MetricsCollector();

app.get('/metrics', (c) => {
  c.header('Content-Type', 'text/plain');
  return c.text(metrics.toPrometheus());
});


告警规则
Prometheus 告警规则示例，当错误率或延迟超过阈值时触发通知：


{
  "groups": [
    {
      "name": "agent-alerts",
      "rules": [
        {
          "alert": "HighErrorRate",
          "expr": "rate(agent_errors_total[5m]) > 0.1",
          "for": "2m",
          "labels": { "severity": "critical" },
          "annotations": {
            "summary": "Agent 错误率过高",
            "description": "5 分钟内错误率超过 10%"
          }
        },
        {
          "alert": "HighLatency",
          "expr": "agent_request_duration_avg_ms > 5000",
          "for": "5m",
          "labels": { "severity": "warning" },
          "annotations": {
            "summary": "Agent 响应延迟过高",
            "description": "平均响应时间超过 5 秒"
          }
        }
      ]
    }
  ]
}


小结
    

  • 多阶段 Docker 构建将镜像体积降到最低，HEALTHCHECK 指令让容器编排器自动检测服务健康。
    • 

  • 环境变量管理敏感配置，loadEnvConfig 在启动时校验必需变量，缺失则立即报错。
    • 

  • 存活探针和就绪探针分别回答"进程是否存活"和"服务是否可接受请求"两个问题。
    • 

  • 优雅关闭在 SIGTERM 后先停止接入新请求，等待存量请求完成，超时后强制退出。
    • 

  • Prometheus 指标覆盖请求量、延迟、错误率和 token 消耗，告警规则在异常时自动通知。
    •
