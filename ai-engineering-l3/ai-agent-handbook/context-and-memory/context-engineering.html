上下文工程

什么是上下文工程

上下文工程（Context Engineering）是为 LLM 构建恰当输入信息的技术。模型的输出质量直接取决于输入上下文的质量——正确的信息、正确的格式、正确的顺序。上下文工程不仅仅是写好 prompt，而是系统性地从多个来源收集、筛选、排序并组装信息，使模型在有限的上下文窗口内获得最佳推理材料。



消息角色与注入顺序
LLM 的输入由不同角色的消息组成，每种角色承担特定职责。注入顺序直接影响模型的行为模式：

上下文来源
一个完整的 Agent 上下文由五大来源构成：


用户输入：当前轮次的用户消息，是最高优先级的上下文。


工具结果：上一轮工具调用的返回值，提供外部世界的实时数据。


记忆系统：从短期记忆（会话历史）和长期记忆（向量检索）中提取的相关信息。


技能指令：匹配到的 SKILL.md 内容，指导 Agent 如何执行特定任务。


规则约束：全局规则和项目规则，定义行为边界和安全策略。




Token 预算分配
上下文窗口的容量有限，需要为不同来源分配 Token 预算：


interface TokenBudget {
  total: number;
  system: number;
  memory: number;
  tools: number;
  conversation: number;
  reserved: number;
}

function allocateTokenBudget(windowSize: number): TokenBudget {
  return {
    total: windowSize,
    system: Math.floor(windowSize * 0.15),
    memory: Math.floor(windowSize * 0.1),
    tools: Math.floor(windowSize * 0.2),
    conversation: Math.floor(windowSize * 0.45),
    reserved: Math.floor(windowSize * 0.1),
  };
}


ContextBuilder 实现
ContextBuilder 是上下文组装的核心类，负责从多个来源收集信息并按优先级组装为最终的消息数组：


import type { CoreMessage } from 'ai';

interface ContextSource {
  name: string;
  priority: number;
  messages: CoreMessage[];
  tokenCount: number;
}

class ContextBuilder {
  private sources: ContextSource[] = [];
  private budget: TokenBudget;

  constructor(windowSize: number) {
    this.budget = allocateTokenBudget(windowSize);
  }

  addSystemPrompt(content: string, tokenCount: number): this {
    this.sources.push({
      name: 'system',
      priority: 100,
      messages: [{ role: 'system', content }],
      tokenCount,
    });
    return this;
  }

  addSkillInstructions(instructions: string, tokenCount: number): this {
    this.sources.push({
      name: 'skills',
      priority: 90,
      messages: [{ role: 'system', content: instructions }],
      tokenCount,
    });
    return this;
  }

  addMemoryContext(memories: string[], tokenCount: number): this {
    if (memories.length === 0) return this;
    const content = memories.join('\n\n');
    this.sources.push({
      name: 'memory',
      priority: 70,
      messages: [{ role: 'system', content: `相关记忆:\n${content}` }],
      tokenCount,
    });
    return this;
  }

  addConversationHistory(messages: CoreMessage[], tokenCount: number): this {
    this.sources.push({
      name: 'conversation',
      priority: 60,
      messages,
      tokenCount,
    });
    return this;
  }

  addToolResults(messages: CoreMessage[], tokenCount: number): this {
    this.sources.push({
      name: 'tools',
      priority: 80,
      messages,
      tokenCount,
    });
    return this;
  }

  build(): CoreMessage[] {
    const sorted = [...this.sources].sort((a, b) => b.priority - a.priority);

    let usedTokens = 0;
    const selected: ContextSource[] = [];

    for (const source of sorted) {
      if (usedTokens + source.tokenCount <= this.budget.total - this.budget.reserved) {
        selected.push(source);
        usedTokens += source.tokenCount;
      }
    }

    const systemMessages: CoreMessage[] = [];
    const conversationMessages: CoreMessage[] = [];

    for (const source of selected) {
      if (source.messages[0]?.role === 'system') {
        systemMessages.push(...source.messages);
      } else {
        conversationMessages.push(...source.messages);
      }
    }

    return [...systemMessages, ...conversationMessages];
  }
}


在路由中使用 ContextBuilder
import { generateText } from 'ai';
import { openai } from '@ai-sdk/openai';

async function handleChat(userMessage: string, sessionId: string) {
  const builder = new ContextBuilder(128000);

  const systemPrompt = '你是一个专业的编程助手，擅长 TypeScript 开发。';
  const history = await loadConversationHistory(sessionId);
  const memories = await searchRelevantMemories(userMessage);
  const skills = await matchSkills(userMessage);

  const messages = builder
    .addSystemPrompt(systemPrompt, 50)
    .addSkillInstructions(skills, 200)
    .addMemoryContext(memories, 300)
    .addConversationHistory(history, 2000)
    .build();

  messages.push({ role: 'user', content: userMessage });

  const result = await generateText({
    model: openai('gpt-4o'),
    messages,
  });

  return result.text;
}

小结
    

  • 上下文工程是系统性地为 LLM 构建输入信息的技术，决定了模型输出的质量上限。
    • 

  • 上下文来源包括用户输入、工具结果、记忆系统、技能指令和规则约束五大类别。
    • 

  • 消息角色（system / user / assistant / tool）各有职责，注入顺序影响模型行为。
    • 

  • Token 预算分配确保有限的上下文窗口被合理利用，避免关键信息被截断。
    • 

  • ContextBuilder 模式将上下文组装抽象为链式 API，支持按优先级动态裁剪。
    • 

  • 上下文组装流水线从技能匹配到最终注入，形成可复用的标准化流程。
