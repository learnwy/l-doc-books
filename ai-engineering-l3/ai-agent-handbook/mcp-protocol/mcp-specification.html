MCP 规范解读

什么是 MCP

Model Context Protocol（MCP）是由 Anthropic 提出的开放协议，用于标准化 AI 应用与外部数据源、工具之间的通信方式。在没有 MCP 之前，每个 Agent 需要为每个工具编写专用的集成代码；MCP 提供了统一的协议层，让任意 AI 客户端可以连接任意 MCP 服务器，实现工具和资源的即插即用。

MCP 采用客户端-服务器架构：Host（宿主应用）内嵌多个 MCP Client，每个 Client 与一个 MCP Server 建立一对一连接。Server 暴露工具、资源和提示模板，Client 负责发现和调用它们。




协议传输层
MCP 基于 JSON-RPC 2.0 协议进行通信。每条消息都是一个标准的 JSON-RPC 请求或响应：


{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "readFile",
    "arguments": {
      "path": "/src/index.ts"
    }
  }
}
MCP 支持两种传输方式：






传输方式
协议
适用场景
特点





stdio
标准输入/输出
本地进程通信
低延迟、无需网络




SSE
HTTP Server-Sent Events
远程服务通信
支持跨网络、可鉴权





stdio 模式下，Host 启动 Server 子进程，通过 stdin/stdout 交换 JSON-RPC 消息。SSE 模式下，Client 通过 HTTP POST 发送请求，通过 SSE 流接收响应。




生命周期
MCP 连接遵循严格的生命周期管理。Client 和 Server 之间的交互从初始化开始，经过能力协商，进入正常运行阶段，最终通过关闭流程断开连接。

能力协商
在 initialize 阶段，Client 和 Server 交换各自支持的能力（capabilities）。只有双方都声明支持的功能才能在运行阶段使用：


interface ClientCapabilities {
  roots?: { listChanged?: boolean };
  sampling?: Record<string, never>;
}

interface ServerCapabilities {
  tools?: { listChanged?: boolean };
  resources?: { subscribe?: boolean; listChanged?: boolean };
  prompts?: { listChanged?: boolean };
  logging?: Record<string, never>;
}
协商结果决定了可用的协议特性。例如，只有 Server 声明 tools 能力时，Client 才能调用 tools/list 和 tools/call 方法。

在实践中，两者通常组合使用：核心业务工具直接定义在应用中以获得最佳性能，通用能力（文件系统、数据库、搜索）通过 MCP Server 提供以实现跨项目复用。


import { generateText, tool } from 'ai';
import { openai } from '@ai-sdk/openai';

const result = await generateText({
  model: openai('gpt-4o'),
  tools: {
    calculatePrice: tool({
      description: '计算商品价格（核心业务，直接定义）',
      parameters: z.object({ productId: z.string(), quantity: z.number() }),
      execute: async ({ productId, quantity }) => {
        return { total: quantity * 99.9 };
      },
    }),
    ...mcpTools,
  },
});


小结
    

  • MCP 是标准化 AI 应用与外部工具通信的开放协议，基于 JSON-RPC 2.0，支持 stdio 和 SSE 两种传输方式。
    • 

  • 连接生命周期为 initialize → initialized → running → shutdown，Client 和 Server 在初始化时协商各自支持的能力。
    • 

  • 协议定义三大核心原语：Tools（模型调用的操作）、Resources（应用控制的上下文数据）、Prompts（用户选择的交互模板）。
    • 

  • MCP 与直接函数调用互补：核心业务工具直接定义，通用工具通过 MCP 动态发现和调用，兼顾性能与复用性。
    •
