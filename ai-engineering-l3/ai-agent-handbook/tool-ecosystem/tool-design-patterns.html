工具设计模式

为什么需要设计原则

Agent 的能力上限取决于工具的质量。一个设计粗糙的工具会导致模型调用失败、参数传递错误、执行超时或产生不可预测的副作用。好的工具设计遵循五项核心原则：单一职责、Schema 明确、错误友好、幂等安全、超时可控。



单一职责原则
每个工具只做一件事。不要把"读取文件 + 解析内容 + 写入结果"塞进一个工具，而是拆分为三个独立工具。模型更容易理解职责单一的工具描述，调用准确率更高。

❌ 不良设计
✅ 良好设计

工具接口类型定义
使用 TypeScript 类型约束工具的完整结构，确保每个工具都满足统一的接口规范：


import { z, ZodSchema } from 'zod';

interface ToolDefinition<TParams = unknown, TResult = unknown> {
  name: string;
  description: string;
  parameters: ZodSchema<TParams>;
  execute: (params: TParams) => Promise<ToolResult<TResult>>;
  timeout?: number;
  idempotent?: boolean;
}

interface ToolResult<T = unknown> {
  success: boolean;
  data?: T;
  error?: string;
  metadata?: {
    duration: number;
    retryable: boolean;
  };
}


参数校验与 Zod Schema
参数设计是工具质量的核心。每个参数都必须有 .describe() 说明，让模型理解参数含义。使用 .default() 减少必填参数数量，降低模型出错概率：


import { tool } from 'ai';
import { z } from 'zod';

const readFileTool = tool({
  description: '读取指定路径文件的文本内容，返回文件内容字符串',
  parameters: z.object({
    path: z.string().describe('文件的绝对路径或相对于项目根目录的路径'),
    encoding: z.enum(['utf-8', 'ascii', 'base64']).default('utf-8').describe('文件编码格式'),
    maxLines: z.number().min(1).max(5000).default(500).describe('最多读取的行数'),
  }),
  execute: async ({ path, encoding, maxLines }) => {
    const content = await readFileContent(path, encoding, maxLines);
    return content;
  },
});

错误处理策略
工具执行失败时，应返回结构化错误信息而非抛出异常。这让模型能理解失败原因并调整策略：


const safeExecute = tool({
  description: '查询指定关键词的搜索结果',
  parameters: z.object({
    query: z.string().min(1).describe('搜索关键词'),
  }),
  execute: async ({ query }) => {
    try {
      const response = await fetch(`https://api.search.example/v1?q=${encodeURIComponent(query)}`);
      if (!response.ok) {
        return {
          success: false,
          error: `HTTP ${response.status}: ${response.statusText}`,
          retryable: response.status >= 500,
        };
      }
      const data = await response.json();
      return { success: true, results: data.items };
    } catch (err) {
      return { success: false, error: err instanceof Error ? err.message : '网络请求失败', retryable: true };
    }
  },
});


幂等性设计
幂等工具意味着多次调用产生相同结果。读取操作天然幂等，写入操作需要额外设计：


const writeFileTool = tool({
  description: '将内容写入指定路径的文件，如果文件已存在则覆盖',
  parameters: z.object({
    path: z.string().describe('目标文件路径'),
    content: z.string().describe('要写入的文件内容'),
    checksum: z.string().optional().describe('内容校验和，用于避免重复写入相同内容'),
  }),
  execute: async ({ path, content, checksum }) => {
    if (checksum) {
      const existing = await getFileChecksum(path).catch(() => null);
      if (existing === checksum) {
        return { success: true, skipped: true, message: '文件内容未变化，跳过写入' };
      }
    }
    await writeFileContent(path, content);
    return { success: true, skipped: false, path };
  },
});


超时控制
所有工具必须有超时保护，防止单个工具阻塞整个 Agent 循环：


function withTimeout<T>(promise: Promise<T>, ms: number, toolName: string): Promise<T> {
  return Promise.race([
    promise,
    new Promise<never>((_, reject) => setTimeout(() => reject(new Error(`工具 ${toolName} 执行超时 (${ms}ms)`)), ms)),
  ]);
}

function createTool<TParams, TResult>(def: ToolDefinition<TParams, TResult>) {
  const timeout = def.timeout ?? 30_000;
  return tool({
    description: def.description,
    parameters: def.parameters,
    execute: async (params: TParams) => {
      return withTimeout(def.execute(params), timeout, def.name);
    },
  });
}

小结
工具设计的核心是"对模型友好"与"对系统安全"的平衡。单一职责让模型精准选择，精确的 Zod Schema 防止参数错误，结构化错误返回给模型恢复机会，幂等设计保证重复调用安全，超时控制防止 Agent 循环卡死。遵循统一的 ToolDefinition 接口和生命周期管理，工具生态才能在规模增长时保持可靠。
