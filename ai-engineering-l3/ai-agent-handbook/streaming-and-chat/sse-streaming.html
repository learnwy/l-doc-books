SSE 流式响应

为什么需要流式响应

大语言模型生成一段完整回复可能需要数秒甚至更长时间。如果等待全部生成完毕再返回，用户会面对一段漫长的空白等待。流式响应让 token 一边生成一边推送到客户端，用户能实时看到文字逐步出现，体验上接近"AI 正在思考并打字"的效果。

Server-Sent Events（SSE）是实现流式响应的标准协议。与 WebSocket 的双向通信不同，SSE 是服务端到客户端的单向推送，天然适合"模型生成、客户端消费"的场景。



SSE 协议基础
SSE 使用 text/event-stream 内容类型，通过 HTTP 长连接推送事件。每个事件由 data: 字段和两个换行符分隔：


data: {"text": "你"}

data: {"text": "好"}

data: {"text": "！"}

data: [DONE]

Hono 流式路由
使用 AI SDK 6 的 streamText 配合 Hono 实现流式端点：


import { Hono } from 'hono';
import { streamText } from 'ai';
import { openai } from '@ai-sdk/openai';

const app = new Hono();

app.post('/api/chat', async (c) => {
  const { messages } = await c.req.json();

  const result = streamText({
    model: openai('gpt-4o'),
    messages,
  });

  return result.toDataStreamResponse();
});

export default app;
toDataStreamResponse() 自动设置正确的 SSE 头并将 token 流转换为符合 AI SDK Data Stream Protocol 的事件格式。




自定义流式响应
当需要更细粒度的控制时，可以手动构造 SSE 流：


import { Hono } from 'hono';
import { streamText } from 'ai';
import { openai } from '@ai-sdk/openai';
import { stream } from 'hono/streaming';

const app = new Hono();

app.post('/api/chat/custom', async (c) => {
  const { messages } = await c.req.json();

  const result = streamText({
    model: openai('gpt-4o'),
    messages,
  });

  return stream(
    c,
    async (s) => {
      for await (const chunk of result.textStream) {
        await s.write(`data: ${JSON.stringify({ text: chunk })}\n\n`);
      }
      await s.write('data: [DONE]\n\n');
    },
    {
      headers: {
        'Content-Type': 'text/event-stream',
        'Cache-Control': 'no-cache',
        Connection: 'keep-alive',
      },
    },
  );
});


客户端消费
在浏览器端使用 fetch 读取流式响应：


async function consumeStream(messages: Array<{ role: string; content: string }>) {
  const response = await fetch('/api/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ messages }),
  });

  const reader = response.body!.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n\n');
    buffer = lines.pop() ?? '';

    for (const line of lines) {
      const data = line.replace(/^data: /, '');
      if (data === '[DONE]') return;
      const parsed = JSON.parse(data);
      process.stdout.write(parsed.text);
    }
  }
}
如果使用 AI SDK 的 useChat hook，上述解析逻辑已被完全封装，只需一行即可接入流式端点（详见第四节 React Chat 组件）。

错误处理与中断
流式传输中需要处理两类异常：服务端生成错误和客户端主动断开。


import { Hono } from 'hono';
import { streamText } from 'ai';
import { openai } from '@ai-sdk/openai';

const app = new Hono();

app.post('/api/chat/safe', async (c) => {
  const { messages } = await c.req.json();

  try {
    const result = streamText({
      model: openai('gpt-4o'),
      messages,
      abortSignal: c.req.raw.signal,
      onError: ({ error }) => {
        console.error('Stream error:', error);
      },
    });

    return result.toDataStreamResponse();
  } catch (error) {
    return c.json({ error: 'Failed to start stream' }, 500);
  }
});
abortSignal 绑定到请求的 signal，当客户端关闭连接时自动取消 LLM 调用，避免无用的 token 消耗和费用浪费。




小结
    

  • SSE 是 AI 流式响应的标准协议，基于 HTTP 长连接实现服务端到客户端的单向推送。
    • 

  • AI SDK 6 的 streamText 和 toDataStreamResponse() 封装了完整的流式链路，一行代码即可在 Hono 中开启流式端点。
    • 

  • 客户端通过 ReadableStream 或 AI SDK 的 useChat hook 消费流式数据。
    • 

  • 生产环境中必须处理 abortSignal 中断和错误回退，避免无用的 token 消耗。
