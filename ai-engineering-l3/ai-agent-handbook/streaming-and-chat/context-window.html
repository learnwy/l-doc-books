上下文窗口

什么是上下文窗口

每个大语言模型都有一个固定的上下文窗口大小，以 token 为单位。发送给模型的所有内容（system prompt + 对话历史 + 当前请求）和模型生成的回复，都必须在这个窗口内。超出窗口限制的消息会被截断或直接报错。

上下文管理的核心挑战：在有限的窗口内，放入最有价值的信息，同时为模型回复保留足够空间。

窗口大≠效果好。在超长上下文中，模型对中间部分信息的"注意力"会下降（Lost in the Middle 效应）。精准的上下文裁剪往往比塞满窗口更有效。






Token 计数
精确管理上下文需要知道每条消息占用多少 token。使用 js-tiktoken 对 OpenAI 系列模型进行 token 计数：


npm install js-tiktoken
import { encodingForModel } from 'js-tiktoken';

const encoder = encodingForModel('gpt-4o');

function countTokens(text: string): number {
  return encoder.encode(text).length;
}

function countMessageTokens(messages: Array<{ role: string; content: string }>): number {
  let total = 0;
  for (const msg of messages) {
    total += 4;
    total += countTokens(msg.role);
    total += countTokens(msg.content);
  }
  total += 2;
  return total;
}

console.log(countTokens('Hello, world!'));
console.log(
  countMessageTokens([
    { role: 'system', content: '你是一个助手。' },
    { role: 'user', content: '你好' },
  ]),
);
每条消息额外消耗约 4 个 token 用于格式标记（<|im_start|>role\ncontent<|im_end|>），整个对话末尾还有 2 个 token 的开销。




上下文预算分配
一个合理的上下文预算分配策略：


interface ContextBudget {
  modelLimit: number;
  systemReserved: number;
  replyReserved: number;
  historyBudget: number;
}

function calculateBudget(modelLimit: number, systemTokens: number): ContextBudget {
  const replyReserved = Math.min(4096, Math.floor(modelLimit * 0.1));
  const systemReserved = systemTokens;
  const historyBudget = modelLimit - systemReserved - replyReserved;

  return {
    modelLimit,
    systemReserved,
    replyReserved,
    historyBudget,
  };
}

const budget = calculateBudget(128000, 500);
console.log(budget);


滑动窗口截断
当对话历史超出预算时，最常用的策略是滑动窗口——保留最近的消息，丢弃最早的消息：


import type { CoreMessage } from 'ai';

function truncateMessages(
  messages: CoreMessage[],
  maxTokens: number,
  countFn: (messages: CoreMessage[]) => number,
): CoreMessage[] {
  const systemMessages = messages.filter((m) => m.role === 'system');
  const nonSystemMessages = messages.filter((m) => m.role !== 'system');

  const systemTokens = countFn(systemMessages);
  let availableTokens = maxTokens - systemTokens;

  const kept: CoreMessage[] = [];

  for (let i = nonSystemMessages.length - 1; i >= 0; i--) {
    const msgTokens = countFn([nonSystemMessages[i]]);
    if (availableTokens - msgTokens < 0) break;
    availableTokens -= msgTokens;
    kept.unshift(nonSystemMessages[i]);
  }

  return [...systemMessages, ...kept];
}
这个实现的关键设计：


    

  • System prompt 始终保留，它定义了 AI 的行为规则，丢失会导致行为异常
    • 

  • 从最新消息向前遍历，确保最近的对话上下文不会丢失
    • 

  • 超出预算时立即停止，不会部分截断单条消息
    • 





消息优先级策略
简单的滑动窗口可能丢失重要的早期信息。引入优先级可以更智能地选择保留哪些消息：


type Priority = 'critical' | 'high' | 'normal' | 'low';

interface PrioritizedMessage {
  message: CoreMessage;
  priority: Priority;
  tokens: number;
}

const PRIORITY_ORDER: Record<Priority, number> = {
  critical: 0,
  high: 1,
  normal: 2,
  low: 3,
};

function selectByPriority(items: PrioritizedMessage[], budget: number): CoreMessage[] {
  const sorted = [...items].sort((a, b) => {
    const priorityDiff = PRIORITY_ORDER[a.priority] - PRIORITY_ORDER[b.priority];
    if (priorityDiff !== 0) return priorityDiff;
    return items.indexOf(a) - items.indexOf(b);
  });

  const selected: PrioritizedMessage[] = [];
  let used = 0;

  for (const item of sorted) {
    if (used + item.tokens > budget) continue;
    used += item.tokens;
    selected.push(item);
  }

  return selected.sort((a, b) => items.indexOf(a) - items.indexOf(b)).map((s) => s.message);
}

集成到聊天路由
将上下文管理集成到 Hono API 中：


import { Hono } from 'hono';
import { streamText } from 'ai';
import { openai } from '@ai-sdk/openai';

const MODEL_LIMIT = 128000;
const REPLY_RESERVED = 4096;

const app = new Hono();

app.post('/api/chat', async (c) => {
  const { messages } = await c.req.json();

  const systemPrompt: CoreMessage = {
    role: 'system',
    content: '你是一个 AI 编程助手。',
  };

  const allMessages = [systemPrompt, ...messages];
  const budget = MODEL_LIMIT - REPLY_RESERVED;
  const truncated = truncateMessages(allMessages, budget, countMessageTokens);

  const result = streamText({
    model: openai('gpt-4o'),
    messages: truncated,
  });

  return result.toDataStreamResponse();
});


小结
    

  • 上下文窗口是模型的硬性限制，所有输入和输出共享这个空间。
    • 

  • 使用 js-tiktoken 进行精确的 token 计数，避免因估算偏差导致请求失败。
    • 

  • 滑动窗口是最基础的截断策略，优先保留 system prompt 和最近的对话。
    • 

  • 通过优先级机制可以实现更智能的上下文选择，在有限空间中放入最有价值的信息。
