对话历史管理

消息的数据结构

AI SDK 6 中的对话由消息数组驱动。每条消息包含角色和内容，四种角色各有明确职责：

角色 用途 由谁产生
system 设定 AI 的行为规则和人格 开发者
user 用户输入的自然语言请求 终端用户
assistant 模型的回复文本或工具调用请求 LLM
tool 工具执行的返回结果 工具执行引擎

对应的 TypeScript 类型定义：

import type { CoreMessage } from 'ai';

type MessageRole = 'system' | 'user' | 'assistant' | 'tool';

interface ChatMessage {
  role: MessageRole;
  content: string;
  id?: string;
  createdAt?: Date;
}

const exampleConversation: CoreMessage[] = [
  { role: 'system', content: '你是一个 TypeScript 专家，回答简洁准确。' },
  { role: 'user', content: '如何定义一个泛型函数？' },
  { role: 'assistant', content: '使用尖括号语法：function identity<T>(arg: T): T { return arg; }' },
  { role: 'user', content: '能给一个更实际的例子吗？' },
];

对话流转过程

每轮对话都将完整的消息历史发送给模型，模型没有内置记忆，它的"记忆"完全来自你传入的 messages 数组。




内存存储
最简单的对话存储方案是基于 Map 的内存存储，适合开发调试和单实例部署：


import type { CoreMessage } from 'ai';

interface Conversation {
  id: string;
  messages: CoreMessage[];
  createdAt: Date;
  updatedAt: Date;
}

class InMemoryChatStore {
  private conversations = new Map<string, Conversation>();

  create(id: string): Conversation {
    const conversation: Conversation = {
      id,
      messages: [],
      createdAt: new Date(),
      updatedAt: new Date(),
    };
    this.conversations.set(id, conversation);
    return conversation;
  }

  get(id: string): Conversation | undefined {
    return this.conversations.get(id);
  }

  append(id: string, message: CoreMessage): void {
    const conversation = this.conversations.get(id);
    if (!conversation) throw new Error(`Conversation ${id} not found`);
    conversation.messages.push(message);
    conversation.updatedAt = new Date();
  }

  getMessages(id: string): CoreMessage[] {
    return this.conversations.get(id)?.messages ?? [];
  }

  delete(id: string): boolean {
    return this.conversations.delete(id);
  }

  list(): Conversation[] {
    return Array.from(this.conversations.values());
  }
}

const store = new InMemoryChatStore();


集成到 Hono 路由
将消息存储接入 API 端点，使用 thread ID 区分不同对话：


import { Hono } from 'hono';
import { streamText } from 'ai';
import { openai } from '@ai-sdk/openai';
import { randomUUID } from 'node:crypto';

const app = new Hono();
const store = new InMemoryChatStore();

app.post('/api/threads', async (c) => {
  const id = randomUUID();
  const thread = store.create(id);
  return c.json({ threadId: thread.id });
});

app.post('/api/threads/:threadId/chat', async (c) => {
  const { threadId } = c.req.param();
  const { content } = await c.req.json();

  store.append(threadId, { role: 'user', content });
  const messages = store.getMessages(threadId);

  const result = streamText({
    model: openai('gpt-4o'),
    messages,
    onFinish: ({ text }) => {
      store.append(threadId, { role: 'assistant', content: text });
    },
  });

  return result.toDataStreamResponse();
});

app.get('/api/threads/:threadId/messages', async (c) => {
  const { threadId } = c.req.param();
  const messages = store.getMessages(threadId);
  return c.json({ messages });
});


文件持久化
内存存储在进程重启后丢失。使用 JSON 文件实现简单的持久化：


import { readFile, writeFile, mkdir } from 'node:fs/promises';
import { join } from 'node:path';
import type { CoreMessage } from 'ai';

class FileChatStore {
  constructor(private dir: string) {}

  private path(id: string): string {
    return join(this.dir, `${id}.json`);
  }

  async init(): Promise<void> {
    await mkdir(this.dir, { recursive: true });
  }

  async save(id: string, messages: CoreMessage[]): Promise<void> {
    const data = JSON.stringify({ id, messages, updatedAt: new Date() }, null, 2);
    await writeFile(this.path(id), data, 'utf-8');
  }

  async load(id: string): Promise<CoreMessage[]> {
    try {
      const raw = await readFile(this.path(id), 'utf-8');
      const data = JSON.parse(raw);
      return data.messages;
    } catch {
      return [];
    }
  }
}

const fileStore = new FileChatStore('./data/conversations');


数据库持久化
生产环境通常使用数据库存储对话。以下是典型的表结构设计：


{
  "tables": {
    "threads": {
      "columns": {
        "id": "TEXT PRIMARY KEY",
        "title": "TEXT",
        "created_at": "TIMESTAMP DEFAULT NOW()",
        "updated_at": "TIMESTAMP DEFAULT NOW()"
      }
    },
    "messages": {
      "columns": {
        "id": "TEXT PRIMARY KEY",
        "thread_id": "TEXT REFERENCES threads(id)",
        "role": "TEXT NOT NULL",
        "content": "TEXT NOT NULL",
        "created_at": "TIMESTAMP DEFAULT NOW()"
      },
      "indexes": ["thread_id", "created_at"]
    }
  }
}

小结
    

  • 对话历史是消息数组，模型的"记忆"完全来自你传入的 messages[]。
    • 

  • 四种消息角色（system/user/assistant/tool）各有明确职责，共同构成完整的对话上下文。
    • 

  • 使用 thread ID 管理多个独立对话，通过 onFinish 回调将 assistant 回复写入存储。
    • 

  • 根据场景选择存储策略：内存适合开发、文件适合原型、数据库适合生产。
