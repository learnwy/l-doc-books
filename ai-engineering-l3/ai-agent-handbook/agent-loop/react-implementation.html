ReAct 实现

从零构建 Agent Loop

上一节理解了 ReAct 的理论框架，现在从零实现一个完整的 ReAct 循环。不依赖 AI SDK 的 Agent 抽象，仅使用 generateText 的单次调用能力，手动管理 Thought-Action-Observation 的每一步。



ReActAgent 完整实现
核心实现封装在 ReActAgent 类中，包含 think、act、observe 三个方法：


import { generateText, type CoreMessage, type CoreTool } from 'ai';

interface ReActConfig {
  model: Parameters<typeof generateText>[0]['model'];
  tools: Record<string, CoreTool>;
  systemPrompt: string;
  maxSteps: number;
}

class ReActAgent {
  private config: ReActConfig;
  private messages: CoreMessage[] = [];
  private stepCount = 0;

  constructor(config: ReActConfig) {
    this.config = config;
  }

  async run(userMessage: string): Promise<string> {
    this.messages = [
      { role: 'system', content: this.config.systemPrompt },
      { role: 'user', content: userMessage },
    ];
    this.stepCount = 0;

    while (this.stepCount < this.config.maxSteps) {
      const { text, toolCalls } = await this.think();

      if (!toolCalls || toolCalls.length === 0) return text;

      const results = await this.act(toolCalls);
      this.observe(toolCalls, results);
      this.stepCount++;
    }

    return this.forceFinish();
  }

  private async think() {
    const result = await generateText({
      model: this.config.model,
      messages: this.messages,
      tools: this.config.tools,
    });
    return { text: result.text, toolCalls: result.toolCalls };
  }

  private async act(toolCalls: { toolName: string; args: Record<string, unknown>; toolCallId: string }[]) {
    return Promise.all(
      toolCalls.map(async (call) => {
        const toolDef = this.config.tools[call.toolName];
        if (!toolDef || !('execute' in toolDef) || !toolDef.execute) {
          return { error: `工具 ${call.toolName} 不存在` };
        }
        try {
          return await toolDef.execute(call.args, {
            toolCallId: call.toolCallId,
            messages: this.messages,
            abortSignal: undefined as never,
          });
        } catch (err) {
          return { error: err instanceof Error ? err.message : String(err) };
        }
      }),
    );
  }

  private observe(
    toolCalls: { toolName: string; args: Record<string, unknown>; toolCallId: string }[],
    results: unknown[],
  ) {
    this.messages.push({
      role: 'assistant',
      content: toolCalls.map((call) => ({
        type: 'tool-call' as const,
        toolCallId: call.toolCallId,
        toolName: call.toolName,
        args: call.args,
      })),
    });

    this.messages.push({
      role: 'tool',
      content: toolCalls.map((call, i) => ({
        type: 'tool-result' as const,
        toolCallId: call.toolCallId,
        toolName: call.toolName,
        result: results[i],
      })),
    });
  }

  private async forceFinish(): Promise<string> {
    this.messages.push({
      role: 'user',
      content: '你已达到最大执行步数限制，请根据已有信息给出最终回答。',
    });
    const result = await generateText({ model: this.config.model, messages: this.messages });
    return result.text;
  }
}
三个方法的职责清晰分离：think 调用模型但不设 maxSteps，只执行一步；act 并发执行工具并在内部捕获异常，将错误作为 Observation 返回给模型；observe 按 CoreMessage 格式将 tool-call 和 tool-result 追加到消息列表，通过 toolCallId 关联。




运行与执行轨迹
import { openai } from '@ai-sdk/openai';
import { tool } from 'ai';
import { z } from 'zod';

const agent = new ReActAgent({
  model: openai('gpt-4o'),
  tools: {
    weather: tool({
      description: '获取城市天气',
      parameters: z.object({ city: z.string() }),
      execute: async ({ city }) => {
        const db: Record<string, number> = { 北京: 28, 东京: 32 };
        return { city, temp: db[city] ?? 20 };
      },
    }),
    calculator: tool({
      description: '数学计算',
      parameters: z.object({ expression: z.string() }),
      execute: async ({ expression }) => ({
        result: new Function(`return ${expression}`)(),
      }),
    }),
  },
  systemPrompt: '你是一个有用的助手，可以查询天气和进行数学计算。',
  maxSteps: 10,
});

const answer = await agent.run('北京和东京的温差是多少度？');
执行轨迹：


Step 1 — think: tool_call: weather({ city: "北京" })
       — act:   { city: "北京", temp: 28 }
Step 2 — think: tool_call: weather({ city: "东京" })
       — act:   { city: "东京", temp: 32 }
Step 3 — think: tool_call: calculator({ expression: "32 - 28" })
       — act:   { result: 4 }
Step 4 — think: "东京 32°C 比北京 28°C 高 4 度" → 无 toolCalls，循环终止

处理策略

返回错误 Observation，模型可据此修正

使用 AbortController 设置超时，返回超时错误




工具返回巨大结果
截断结果，避免上下文窗口溢出

检测重复的 toolCall 模式，强制终止




并行工具调用
Promise.all 并发执行同一步的多个调用







小结
从零实现 ReAct 循环的核心在于三个方法：think 调用模型获取推理和工具请求，act 执行工具并收集结果（含错误处理），observe 将调用和结果按 CoreMessage 格式回填到消息历史。循环控制通过检查 toolCalls 是否为空来判断终止，通过 maxSteps 计数器来防止无限循环。手动构建这个循环让你理解了消息格式、工具执行、错误恢复和强制终止的每一个细节——这正是下一节迁移到 AI SDK Agent 抽象时需要的底层认知。
