Supervisor 模式

从单 Agent 到多 Agent

单个 Agent 在面对复杂任务时会遇到两个瓶颈：上下文窗口溢出和能力边界模糊。一个 Agent 同时承担调研、编码、审查三项工作，系统提示膨胀、工具集过载，每一步的推理质量都在下降。Supervisor 模式引入了一个中心调度角色——Lead Agent，它不直接执行具体工作，而是负责理解任务、制定计划、委派给专业子 Agent，并汇总最终结果。

Supervisor 核心数据结构
Supervisor 的调度基于两个核心概念：子 Agent 注册表和任务计划：


import { generateText, generateObject, tool } from 'ai';
import { openai } from '@ai-sdk/openai';
import { z } from 'zod';

interface AgentDescriptor {
  name: string;
  description: string;
  capabilities: string[];
}

interface SubTask {
  id: string;
  description: string;
  assignee: string;
  dependencies: string[];
  status: 'pending' | 'running' | 'completed' | 'failed';
  result?: string;
}

interface TaskPlan {
  goal: string;
  subtasks: SubTask[];
}


任务规划：从用户请求到执行计划
Supervisor 拿到用户请求后，第一步是通过 LLM 生成结构化的执行计划。计划包含子任务列表、每个子任务的执行者和依赖关系：


const planSchema = z.object({
  goal: z.string().describe('任务总目标'),
  subtasks: z.array(
    z.object({
      id: z.string(),
      description: z.string().describe('子任务描述'),
      assignee: z.string().describe('负责执行的 Agent 名称'),
      dependencies: z.array(z.string()).describe('依赖的子任务 ID'),
    }),
  ),
});

async function planTask(request: string, agents: AgentDescriptor[]): Promise<TaskPlan> {
  const agentList = agents.map((a) => `- ${a.name}: ${a.description} (${a.capabilities.join(', ')})`).join('\n');

  const { object } = await generateObject({
    model: openai('gpt-4o'),
    schema: planSchema,
    prompt: `你是一个任务规划器。根据用户请求和可用 Agent 列表，生成执行计划。

可用 Agent:
${agentList}

用户请求: ${request}`,
  });

  return {
    goal: object.goal,
    subtasks: object.subtasks.map((st) => ({
      ...st,
      status: 'pending' as const,
    })),
  };
}


Supervisor 调度循环
Supervisor 按照依赖关系逐步执行子任务，每完成一个子任务就更新状态，直到所有子任务完成后汇总输出：


type AgentExecutor = (task: string, context: string) => Promise<string>;

class Supervisor {
  private agents: Map<string, AgentDescriptor> = new Map();
  private executors: Map<string, AgentExecutor> = new Map();

  register(descriptor: AgentDescriptor, executor: AgentExecutor) {
    this.agents.set(descriptor.name, descriptor);
    this.executors.set(descriptor.name, executor);
  }

  async run(request: string): Promise<string> {
    const descriptors = Array.from(this.agents.values());
    const plan = await planTask(request, descriptors);

    while (plan.subtasks.some((st) => st.status === 'pending')) {
      const ready = plan.subtasks.filter(
        (st) =>
          st.status === 'pending' &&
          st.dependencies.every((dep) => plan.subtasks.find((d) => d.id === dep)?.status === 'completed'),
      );

      for (const task of ready) {
        task.status = 'running';
        const executor = this.executors.get(task.assignee);
        if (!executor) {
          task.status = 'failed';
          task.result = `未找到 Agent: ${task.assignee}`;
          continue;
        }

        const depContext = task.dependencies
          .map((dep) => plan.subtasks.find((d) => d.id === dep))
          .filter(Boolean)
          .map((d) => `[${d!.id}] ${d!.result}`)
          .join('\n');

        try {
          task.result = await executor(task.description, depContext);
          task.status = 'completed';
        } catch (err) {
          task.status = 'failed';
          task.result = err instanceof Error ? err.message : '执行失败';
        }
      }
    }

    return this.synthesize(plan);
  }

  private async synthesize(plan: TaskPlan): Promise<string> {
    const results = plan.subtasks
      .map((st) => `## ${st.description}\n状态: ${st.status}\n${st.result ?? '无结果'}`)
      .join('\n\n');

    const { text } = await generateText({
      model: openai('gpt-4o'),
      prompt: `根据以下子任务执行结果，生成最终回复:

目标: ${plan.goal}

${results}`,
    });

    return text;
  }
}


DeerFlow 风格：Supervisor 作为 ReAct Agent
更强大的模式是让 Supervisor 本身也是一个 ReAct Agent，将「委派子任务」作为 Supervisor 的工具。这样 Supervisor 可以动态决定何时规划、何时委派、何时自己处理：


const supervisor = await generateText({
  model: openai('gpt-4o'),
  system: `你是一个 Supervisor Agent。你可以将任务委派给专业 Agent，也可以自己回答简单问题。

可用 Agent:
- research: 擅长信息检索和调研
- coding: 擅长代码编写和调试
- review: 擅长代码审查和质量分析`,
  prompt: userRequest,
  tools: {
    delegate: tool({
      description: '将子任务委派给指定 Agent',
      parameters: z.object({
        agent: z.enum(['research', 'coding', 'review']),
        task: z.string().describe('子任务描述'),
        context: z.string().describe('相关上下文').optional(),
      }),
      execute: async ({ agent, task, context }) => {
        const executor = executors.get(agent);
        if (!executor) return { error: `Agent ${agent} 不存在` };
        const result = await executor(task, context ?? '');
        return { agent, task, result };
      },
    }),
  },
  maxSteps: 15,
});

小结
Supervisor 模式通过引入中心调度 Agent 解决了单 Agent 的上下文膨胀和能力模糊问题。核心流程是：接收请求 → 规划子任务 → 按依赖关系委派执行 → 汇总结果。planTask 使用 generateObject 生成结构化执行计划，Supervisor.run 按依赖拓扑顺序调度子 Agent。DeerFlow 风格进一步将 Supervisor 自身作为 ReAct Agent，用 delegate 工具动态委派，兼顾灵活性与可控性。选择预先规划还是动态规划取决于任务的确定性——确定性高用前者，探索性强用后者。
