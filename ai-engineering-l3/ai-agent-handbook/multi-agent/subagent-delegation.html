Subagent 委派

从调度到执行

Supervisor 负责规划和调度，但真正干活的是 Subagent。每个 Subagent 拥有独立的系统提示、工具集和上下文窗口，专注于单一领域的任务。委派机制定义了 Supervisor 如何创建 Subagent、传递上下文、收集结果，以及如何在主 Agent 和子 Agent 之间平滑交接控制权。



SubAgent 定义
每个 SubAgent 封装了完整的 Agent 能力：专属模型、系统提示和工具集。执行时通过 AI SDK 的 generateText 在独立上下文中运行：


import { generateText, tool } from 'ai';
import { openai } from '@ai-sdk/openai';
import type { CoreMessage, Tool } from 'ai';
import { z } from 'zod';

interface SubAgentConfig {
  name: string;
  description: string;
  systemPrompt: string;
  model?: Parameters<typeof openai>[0];
  tools?: Record<string, Tool>;
  maxSteps?: number;
}

class SubAgent {
  private config: SubAgentConfig;

  constructor(config: SubAgentConfig) {
    this.config = config;
  }

  async execute(task: string, context?: string): Promise<string> {
    const prompt = context ? `上下文信息:\n${context}\n\n任务:\n${task}` : task;

    const result = await generateText({
      model: openai(this.config.model ?? 'gpt-4o'),
      system: this.config.systemPrompt,
      prompt,
      tools: this.config.tools ?? {},
      maxSteps: this.config.maxSteps ?? 10,
    });

    return result.text;
  }

  get descriptor() {
    return {
      name: this.config.name,
      description: this.config.description,
    };
  }
}


AgentFactory：按需创建专业 Agent
AgentFactory 维护一组 Agent 模板，根据任务类型动态实例化对应的 SubAgent：


interface AgentTemplate {
  config: SubAgentConfig;
  toolFactory?: () => Record<string, Tool>;
}

class AgentFactory {
  private templates: Map<string, AgentTemplate> = new Map();

  registerTemplate(name: string, template: AgentTemplate) {
    this.templates.set(name, template);
  }

  create(name: string): SubAgent {
    const template = this.templates.get(name);
    if (!template) throw new Error(`未注册的 Agent 模板: ${name}`);

    const tools = template.toolFactory?.() ?? template.config.tools;
    return new SubAgent({ ...template.config, tools });
  }

  list(): Array<{ name: string; description: string }> {
    return Array.from(this.templates.entries()).map(([name, t]) => ({
      name,
      description: t.config.description,
    }));
  }
}
注册三种典型的 Agent 模板：


const factory = new AgentFactory();

factory.registerTemplate('research', {
  config: {
    name: 'research',
    description: '信息检索与调研，擅长总结和分析',
    systemPrompt: '你是一个专业的调研助手。搜集信息后给出结构化的分析报告。',
    model: 'gpt-4o',
  },
  toolFactory: () => ({
    webSearch: tool({
      description: '搜索网络信息',
      parameters: z.object({ query: z.string() }),
      execute: async ({ query }) => ({ results: `搜索结果: ${query}` }),
    }),
  }),
});

factory.registerTemplate('coding', {
  config: {
    name: 'coding',
    description: '代码编写与调试，擅长 TypeScript',
    systemPrompt: '你是一个 TypeScript 专家。编写高质量、类型安全的代码。',
    model: 'gpt-4o',
  },
  toolFactory: () => ({
    executeCode: tool({
      description: '执行 TypeScript 代码片段',
      parameters: z.object({ code: z.string() }),
      execute: async ({ code }) => ({ output: `执行结果: ${code}` }),
    }),
  }),
});

factory.registerTemplate('review', {
  config: {
    name: 'review',
    description: '代码审查与质量分析',
    systemPrompt: '你是一个代码审查专家。识别潜在问题并给出改进建议。',
    model: 'gpt-4o',
  },
});


Handoff 协议
Handoff 定义了任务交接的标准格式。每次委派都包含任务描述、上下文数据和期望输出格式，确保子 Agent 有足够的信息独立完成工作：


interface HandoffPayload {
  taskId: string;
  from: string;
  to: string;
  task: string;
  context: Record<string, unknown>;
  expectedOutput: string;
}

interface HandoffResult {
  taskId: string;
  agent: string;
  status: 'success' | 'failure';
  output: string;
  metadata: {
    duration: number;
    tokensUsed: number;
  };
}

async function handoff(factory: AgentFactory, payload: HandoffPayload): Promise<HandoffResult> {
  const agent = factory.create(payload.to);
  const start = Date.now();

  const contextStr = Object.entries(payload.context)
    .map(([k, v]) => `${k}: ${JSON.stringify(v)}`)
    .join('\n');

  try {
    const output = await agent.execute(payload.task, contextStr);
    return {
      taskId: payload.taskId,
      agent: payload.to,
      status: 'success',
      output,
      metadata: { duration: Date.now() - start, tokensUsed: 0 },
    };
  } catch (err) {
    return {
      taskId: payload.taskId,
      agent: payload.to,
      status: 'failure',
      output: err instanceof Error ? err.message : '执行失败',
      metadata: { duration: Date.now() - start, tokensUsed: 0 },
    };
  }
}


委派流程时序


上下文隔离与传递策略
子 Agent 的上下文窗口与 Supervisor 完全隔离，这是 Supervisor 模式的核心优势。但如何传递恰当的上下文需要权衡：






策略
传递内容
优势
风险





最小上下文
仅任务描述
不会干扰子 Agent 推理
缺少必要背景信息




摘要上下文
前置任务结果摘要
平衡信息量和噪声
摘要可能丢失细节




完整上下文
所有前置任务原始输出
信息最完整
可能超出上下文窗口




结构化上下文
提取的键值对
精准、紧凑
需要额外提取步骤





推荐做法是根据子任务的依赖深度选择策略：直接依赖使用完整上下文，间接依赖使用摘要上下文。




完整委派示例
const factory = new AgentFactory();

const result = await handoff(factory, {
  taskId: 'task-001',
  from: 'supervisor',
  to: 'research',
  task: '调研 AI SDK 6 的多 Agent 编排最佳实践',
  context: {
    userGoal: '构建一个多 Agent 代码助手',
    techStack: 'TypeScript + Hono + AI SDK 6',
  },
  expectedOutput: '结构化调研报告',
});

if (result.status === 'success') {
  const codeResult = await handoff(factory, {
    taskId: 'task-002',
    from: 'supervisor',
    to: 'coding',
    task: '根据调研结果实现 Supervisor 类',
    context: {
      researchReport: result.output,
    },
    expectedOutput: 'TypeScript 代码实现',
  });
}


小结
Subagent 委派机制是 Supervisor 模式的执行层。SubAgent 类封装了独立的模型、系统提示和工具集，通过 generateText + maxSteps 在隔离的上下文中执行任务。AgentFactory 基于模板按需创建 SubAgent 实例，支持不同类型的专业 Agent（调研、编码、审查）。Handoff 协议标准化了任务交接流程，包含任务描述、上下文和结果元数据。上下文隔离是多 Agent 架构的核心优势——每个子 Agent 只看到与自己任务相关的信息，避免无关噪声干扰推理。选择上下文传递策略时，直接依赖用完整上下文，间接依赖用摘要，在信息充分性和窗口利用率之间取得平衡。
