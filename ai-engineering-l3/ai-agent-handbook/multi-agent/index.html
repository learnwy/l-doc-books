多 Agent 系统 简介

单个 Agent 的能力终有上限。当任务复杂度超越单一模型的上下文容量或专业范围时，将工作分配给多个专注于不同领域的 Agent 协同完成，往往能够取得远超单体架构的效果。多 Agent 系统借鉴了人类团队协作的模式：有人负责决策与分配，有人负责执行具体工作，有人负责汇总与审查。这种分工协作的架构为构建复杂的 AI 应用提供了强大的组织范式。

Supervisor 模式是多 Agent 系统中最常见的协调架构。一个主 Agent（Supervisor 或 Lead Agent）负责理解用户的整体意图，将任务分解为子任务，并决定将每个子任务委派给哪个专业 Agent 执行。Supervisor 还负责汇总各子 Agent 的输出，进行质量审查，并在必要时发起重试或修正。

这种中心化的调度方式提供了清晰的控制流和可预测的执行路径，适合大多数需要多步协调的应用场景。Supervisor 本身也是一个 Agent，它的系统提示中包含了对所有可用子 Agent 能力的描述，使其能够根据任务特性做出合理的调度决策。

Subagent 委派机制定义了 Supervisor 如何创建和管理子 Agent。每个子 Agent 拥有独立的系统提示、工具集和上下文窗口，专注于完成被委派的特定子任务。委派过程涉及任务描述的传递、执行环境的隔离以及结果的回传。Handoff 协议确保了控制权在主 Agent 与子 Agent 之间的平滑交接，让整个系统像一个配合默契的团队一样运转。

子 Agent 的独立上下文意味着它们不会被其他子任务的无关信息干扰，从而能够在各自的领域内发挥最大效能。

并行执行是提升多 Agent 系统效率的关键手段。当多个子任务之间不存在依赖关系时，可以采用扇出（Fan-out）策略将它们同时分发给不同的子 Agent 并行处理，然后通过扇入（Fan-in）将各自的结果收集汇总。这种并行化不仅大幅缩短了端到端的响应时间，还能充分利用模型推理的并发能力。

设计并行执行策略时，需要仔细分析任务之间的依赖图谱，确保并行任务之间不会产生冲突或数据竞争。错误处理在并行场景下尤为关键——当某个并行分支失败时，系统需要决定是等待重试、跳过该分支，还是终止整个任务。

消息网关是多 Agent 系统的通信基础设施。当系统中的 Agent 数量增多、交互模式变得复杂时，需要一个统一的消息路由层来管理 Agent 之间的通信。消息网关负责消息的序列化、路由、过滤和持久化，确保每个 Agent 都能及时接收到与自己相关的信息，同时屏蔽掉无关的干扰。

良好的消息网关设计还为系统的可观测性和故障排查提供了天然的支撑点——通过记录所有经过网关的消息，开发者可以完整回溯多 Agent 协作的全过程，快速定位通信链路中的问题所在。

多 Agent 系统代表着 AI 应用架构从单体走向分布式协作的演进方向。本章将帮助你掌握从 Supervisor 调度到消息通信的完整技术栈，理解多 Agent 协作中的设计权衡与工程实践，为构建规模化的智能系统奠定坚实基础。
