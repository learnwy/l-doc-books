中间件编排

超越 LLM 层的中间件

前面章节介绍的 LanguageModelMiddleware 作用在模型调用层——拦截 wrapGenerate 和 wrapStream。但 Harness 层面的中间件覆盖范围更广：它拦截整个任务执行流程，包括请求预处理、工具调用、子 Agent 派发、错误处理和响应后处理。Harness 中间件是洋葱模型的全链路版本，每个中间件同时处理入站和出站逻辑。



HarnessMiddleware 接口
与 AI SDK 的 LanguageModelMiddleware 不同，Harness 中间件采用 next 函数传递控制权，支持全链路拦截：


interface ExecutionContext {
  task: AgentTask;
  harness: AgentHarness;
  tools: Record<string, import('ai').CoreTool>;
  traceId: string;
  startTime: number;
  metadata: Record<string, unknown>;
}

interface AgentResult {
  text: string;
  messages: import('ai').CoreMessage[];
  usage: { totalTokens: number; promptTokens: number; completionTokens: number };
  duration: number;
}

interface HarnessMiddleware {
  name: string;
  priority: number;
  execute(ctx: ExecutionContext, next: () => Promise<AgentResult>): Promise<AgentResult>;
}




属性
说明





name
中间件标识，用于日志和调试




priority
数值越小越在外层，越先执行




execute
洋葱模型核心：next() 调用前是入站逻辑，调用后是出站逻辑







中间件链构建
class MiddlewareChain {
  private middlewares: HarnessMiddleware[] = [];

  use(middleware: HarnessMiddleware): void {
    this.middlewares.push(middleware);
    this.middlewares.sort((a, b) => a.priority - b.priority);
  }

  build(ctx: ExecutionContext, coreHandler: () => Promise<AgentResult>): () => Promise<AgentResult> {
    let handler = coreHandler;

    for (const mw of [...this.middlewares].reverse()) {
      const next = handler;
      handler = () => mw.execute(ctx, next);
    }

    return handler;
  }
}

生命周期钩子中间件
Harness 中间件不仅拦截请求响应，还能挂载到 Agent 执行过程的关键节点：


interface LifecycleHooks {
  onTaskStart?(ctx: ExecutionContext): Promise<void>;
  onToolCall?(ctx: ExecutionContext, toolName: string, args: unknown): Promise<void>;
  onToolResult?(ctx: ExecutionContext, toolName: string, result: unknown): Promise<void>;
  onAgentSpawn?(ctx: ExecutionContext, agentId: string): Promise<void>;
  onError?(ctx: ExecutionContext, error: Error): Promise<void>;
  onTaskEnd?(ctx: ExecutionContext, result: AgentResult): Promise<void>;
}

function createHookMiddleware(hooks: LifecycleHooks): HarnessMiddleware {
  return {
    name: 'lifecycle-hooks',
    priority: 5,
    execute: async (ctx, next) => {
      await hooks.onTaskStart?.(ctx);

      const originalTools = { ...ctx.tools };
      for (const [name, tool] of Object.entries(ctx.tools)) {
        if ('execute' in tool && tool.execute) {
          const originalExecute = tool.execute;
          (tool as { execute: typeof originalExecute }).execute = async (args, options) => {
            await hooks.onToolCall?.(ctx, name, args);
            const result = await originalExecute(args, options);
            await hooks.onToolResult?.(ctx, name, result);
            return result;
          };
        }
      }

      try {
        const result = await next();
        await hooks.onTaskEnd?.(ctx, result);
        return result;
      } catch (err) {
        await hooks.onError?.(ctx, err instanceof Error ? err : new Error(String(err)));
        throw err;
      }
    },
  };
}


常用 Harness 中间件
认证中间件
const authMiddleware: HarnessMiddleware = {
  name: 'auth',
  priority: 10,
  execute: async (ctx, next) => {
    const apiKey = ctx.metadata.apiKey as string | undefined;
    if (!apiKey || !isValidApiKey(apiKey)) {
      throw new Error('认证失败：无效的 API Key');
    }
    ctx.metadata.userId = await resolveUserId(apiKey);
    return next();
  },
};
超时控制中间件
const timeoutMiddleware: HarnessMiddleware = {
  name: 'timeout',
  priority: 15,
  execute: async (ctx, next) => {
    const controller = new AbortController();
    const timeoutId = setTimeout(() => controller.abort(), 60_000);

    try {
      ctx.metadata.abortSignal = controller.signal;
      return await next();
    } finally {
      clearTimeout(timeoutId);
    }
  },
};
错误恢复中间件
const errorRecoveryMiddleware: HarnessMiddleware = {
  name: 'error-recovery',
  priority: 90,
  execute: async (ctx, next) => {
    const maxRetries = 3;
    let lastError: Error | undefined;

    for (let attempt = 0; attempt < maxRetries; attempt++) {
      try {
        return await next();
      } catch (err) {
        lastError = err instanceof Error ? err : new Error(String(err));
        const isRetryable = lastError.message.includes('rate limit') || lastError.message.includes('timeout');
        if (!isRetryable) throw lastError;
        await new Promise((r) => setTimeout(r, 1000 * 2 ** attempt));
      }
    }
    throw lastError;
  },
};


中间件注册与执行
const chain = new MiddlewareChain();
chain.use(authMiddleware);
chain.use(timeoutMiddleware);
chain.use(errorRecoveryMiddleware);
chain.use(
  createHookMiddleware({
    onTaskStart: async (ctx) => console.log(`[Task] 开始: ${ctx.traceId}`),
    onToolCall: async (ctx, name) => console.log(`[Tool] 调用: ${name}`),
    onError: async (ctx, err) => console.error(`[Error] ${err.message}`),
  }),
);

const coreHandler = async (): Promise<AgentResult> => {
  const result = await generateText({
    model: harness.getModel('openai', 'gpt-4o'),
    tools: ctx.tools,
    prompt: ctx.task.prompt,
    maxSteps: 10,
  });
  return {
    text: result.text,
    messages: result.response.messages,
    usage: result.usage,
    duration: Date.now() - ctx.startTime,
  };
};

const handler = chain.build(ctx, coreHandler);
const result = await handler();


小结
Harness 中间件将洋葱模型从 LLM 调用层扩展到整个任务执行链路。HarnessMiddleware 通过 execute(ctx, next) 实现入站和出站双向拦截，priority 字段控制执行顺序——数值越小越在外层。MiddlewareChain 通过逆序嵌套构建完整调用链。在请求-响应拦截之上，生命周期钩子中间件通过包装 tool.execute 实现工具调用级别的 onToolCall、onToolResult 事件。认证、超时、错误恢复等横切关注点各自实现为独立中间件，通过 chain.use() 按需组合。这种架构确保核心 Agent 逻辑保持纯净，所有横切关注点通过中间件链无侵入式地叠加。
