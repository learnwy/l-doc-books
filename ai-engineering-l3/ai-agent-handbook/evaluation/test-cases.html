测试用例与基准

测试用例的作用

评估 Agent 的质量需要结构化的测试用例。每个用例定义一个场景：给定输入、可用工具和约束条件，期望 Agent 产出什么结果。好的测试套件覆盖四个维度——准确性、安全性、鲁棒性、工具使用——确保 Agent 在各种场景下都能正确运作。



TestCase 格式定义
每个测试用例包含输入、期望输出、可用工具集、最大步数和超时时间：


interface TestCase {
  id: string;
  name: string;
  category: 'accuracy' | 'safety' | 'robustness' | 'tool-usage';
  input: string;
  expectedOutput: string;
  matchStrategy: 'exact' | 'contains' | 'semantic' | 'regex';
  tools: string[];
  maxSteps: number;
  timeout: number;
  tags: string[];
  metadata?: Record<string, unknown>;
}
matchStrategy 决定如何对比实际输出和期望输出：exact 要求完全匹配，contains 要求包含关键片段，semantic 使用嵌入向量计算相似度，regex 使用正则表达式匹配。

测试套件加载器
从 JSON 文件加载测试套件，并校验每个用例的格式：


import { readFile } from 'node:fs/promises';

interface TestSuite {
  suite: string;
  description: string;
  cases: TestCase[];
}

async function loadTestSuite(filePath: string): Promise<TestSuite> {
  const raw = await readFile(filePath, 'utf-8');
  const data = JSON.parse(raw) as TestSuite;

  for (const tc of data.cases) {
    if (!tc.id || !tc.input || !tc.category) {
      throw new Error(`测试用例格式错误: ${JSON.stringify(tc)}`);
    }
    if (!['accuracy', 'safety', 'robustness', 'tool-usage'].includes(tc.category)) {
      throw new Error(`未知类别: ${tc.category} (用例 ${tc.id})`);
    }
  }

  return data;
}

function filterByCategory(suite: TestSuite, category: string): TestCase[] {
  return suite.cases.filter((tc) => tc.category === category);
}

function filterByTags(suite: TestSuite, tags: string[]): TestCase[] {
  return suite.cases.filter((tc) => tags.some((tag) => tc.tags.includes(tag)));
}


匹配策略实现
不同的测试场景需要不同的匹配策略：


import { embed, cosineSimilarity } from 'ai';
import { openai } from '@ai-sdk/openai';

type MatchStrategy = 'exact' | 'contains' | 'semantic' | 'regex';

async function matchOutput(
  actual: string,
  expected: string,
  strategy: MatchStrategy,
): Promise<{ passed: boolean; score: number }> {
  const normalize = (s: string) => s.trim().toLowerCase();

  switch (strategy) {
    case 'exact':
      return {
        passed: normalize(actual) === normalize(expected),
        score: normalize(actual) === normalize(expected) ? 1.0 : 0.0,
      };

    case 'contains':
      return {
        passed: normalize(actual).includes(normalize(expected)),
        score: normalize(actual).includes(normalize(expected)) ? 1.0 : 0.0,
      };

    case 'regex': {
      const pattern = new RegExp(expected, 'i');
      const matched = pattern.test(actual);
      return { passed: matched, score: matched ? 1.0 : 0.0 };
    }

    case 'semantic': {
      const { embedding: embA } = await embed({
        model: openai.embedding('text-embedding-3-small'),
        value: actual,
      });
      const { embedding: embB } = await embed({
        model: openai.embedding('text-embedding-3-small'),
        value: expected,
      });
      const score = cosineSimilarity(embA, embB);
      return { passed: score >= 0.85, score };
    }
  }
}

Golden Answer 与评判标准
Golden Answer（标准答案）是测试用例的核心。对于确定性任务（如数学计算），使用精确匹配或包含匹配；对于开放性任务（如文本摘要），使用语义相似度。正则匹配适合验证输出格式或关键词存在。




小结
测试用例是 Agent 评估的数据基础。每个用例通过 id、category、input、expectedOutput、matchStrategy 等字段定义一个完整的测试场景。测试套件以 JSON 格式存储，支持按类别和标签过滤。四种匹配策略——精确匹配、包含匹配、正则匹配、语义相似度——覆盖了从确定性验证到模糊评估的全谱段。设计用例时遵循覆盖正常路径、边界情况、错误路径、安全场景和多步推理的原则，确保 Agent 在各种条件下都经过充分验证。
