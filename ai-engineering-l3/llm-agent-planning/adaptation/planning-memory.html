Part II · Agent Construction智能体规划与任务分解自适应规划与记忆

规划与记忆

反思和重规划让智能体在一次任务内变聪明，但任务一结束，所有教训随上下文清空——下次遇到同样的坑，它还会一脚踩进去。把"这次学到的"留到"下次用得上"，需要让规划接上记忆。这一篇只讲一件事：记忆如何反哺规划这个接口，不展开通用存储引擎的实现。

核心概念

规划相关的记忆要回答三个问题：记什么、何时记、何时取。按内容，与规划最相关的有三类记忆：

  • 情景记忆（episodic）：具体的过往轨迹——"上次办上海出差，我是先订票拿到行程号再写日历的"。Reflexion 的失败反思就存在这里。
  • 过程记忆 / 技能库（procedural / skill library）：把成功的子计划提炼成可复用的"技能"——"订机票"这个动作序列固化成一个可调用的高层动作。
  • 语义记忆（semantic）：关于世界的事实——"周二的航班通常更便宜"。
flowchart TD
    PLAN[规划器] -->|规划前| RET[检索相关记忆<br/>类似任务怎么做的]
    RET --> PLAN
    PLAN --> EXEC[执行]
    EXEC --> REF[反思: 成功? 失败?]
    REF -->|成功| SKILL[提炼为技能<br/>存入技能库]
    REF -->|失败| LESSON[失败教训<br/>存入情景记忆]
    SKILL --> STORE[(长期记忆)]
    LESSON --> STORE
    STORE -.下次任务.-> RET

下表对照三类记忆如何反哺规划：

记忆类型 内容 反哺规划的方式 典型代表
情景记忆 过往轨迹/失败教训 规划前检索相似案例避坑 Reflexion
过程记忆/技能库 固化的成功子计划 当高层动作直接复用 Voyager

技能库：让规划越做越省

最能体现"记忆反哺规划"的是技能库（skill library）。它的思路是：每当智能体成功完成一个子任务，就把那串动作序列封装成一个带名字、带说明的可复用"技能"，存进库里；下次规划时，这个技能就成了一个高层动作，规划器可以直接调用它，而不必从原子动作重新拼。

这条路线的标志性工作是 Voyager——一个在 Minecraft 里自主探索的智能体，它把习得的技能（"造一把石镐"）持续写入技能库并组合复用，从而越玩越会、能力随时间单调增长。技能库的妙处在于它把规划的抽象层级抬高了：当"造石镐"是一个现成技能时，"造铁镐"的规划就只需在更高层组合技能，搜索空间骤减——这正好接上任务分解里 HTN 的"方法"概念，技能库本质是自动习得的 HTN 方法集。

# 技能库反哺规划的最小骨架
def plan_with_skills(task, skill_lib):
    relevant = skill_lib.retrieve(task)        # 检索可复用技能
    plan = planner(task, available=relevant)   # 规划器把技能当高层动作
    result, trace = execute(plan)
    if result.success and is_novel(trace):     # 新的成功模式
        skill = distill(trace)                 # 提炼成技能
        skill_lib.add(skill)                   # 写回库, 下次可用
    return result

记忆反哺规划的两大陷阱

记忆不是越多越好，用不好反而是负担。两个陷阱尤其常见。

第一，检索噪声把规划带偏。如果规划前检索到的是表面相似实则不适用的旧案例，智能体会照搬错误模式——这比没有记忆更糟。从规划侧应把检索到的记忆当"建议"而非"指令"，同时保留来源、适用条件和历史成功率，让规划器在当前约束下重新判断。

第二，陈旧记忆固化错误。世界变了（API 改版、价格规律变化），但技能库里的旧技能还在，照用就出错。这要求记忆带"时效"、适用版本与成功率元数据，并在反复失败时让重规划废弃或更新对应技能。

陷阱 表现 规划侧的缓解
检索噪声 照搬不适用的旧案例 记忆当建议非指令，规划器复核
陈旧固化 用过时技能反复出错 给技能加时效/成功率，失败即废弃
记忆膨胀 库太大检索变慢变噪 定期巩固、去重、淘汰低价值技能

与多智能体记忆的边界

当规划跨越多个智能体时，记忆还要解决"谁记、谁看、谁能改"的问题。本 hub 默认单智能体规划，只需记住一个原则：在单体场景里，规划与记忆是一条"规划前检索、执行后沉淀"的闭环；多体场景要额外处理共享权限、并发写入与一致性。

小结

  • 本篇只讲"记忆反哺规划"这一接口；记忆系统本身属 51 hub。
  • 与规划最相关的三类记忆：情景（过往轨迹/教训）、过程/技能库（固化的成功子计划）、语义（世界事实）。
  • 技能库（Voyager）让规划越做越省：成功子计划封装为高层动作，抬高规划抽象层级、压缩搜索空间，本质是自动习得的 HTN 方法集。
  • 两大陷阱：检索噪声（照搬不适用旧案例）与陈旧固化（用过时技能出错）；缓解靠"记忆当建议非指令"与"给技能加时效/成功率元数据"。
  • 单体场景下规划与记忆是"规划前检索、执行后沉淀"的闭环；多体共享一致性属其他 hub。
