Part II · Agent Construction智能体规划与任务分解基础规划问题形式化

规划问题形式化

"订机票并加日历"这句自然语言指令，在规划器眼里必须先变成可计算的对象，才能谈得上求解。经典 AI 在六十年里积累了一整套描述规划问题的数学语言——状态、动作、目标、转移。LLM 智能体并没有抛弃这套语言，而是把它"软化"了：状态可能是一段自然语言上下文而非逻辑命题，动作可能是一次工具调用而非形式化算子。理解这套形式化，能让你在后文比较各范式时说清它们到底在优化什么、又偷偷放弃了什么保证。

核心概念

一个规划问题最小可由四元组 ⟨S,A,T,G⟩\langle S, A, T, G \rangle⟨S,A,T,G⟩ 刻画：

  • SSS：状态空间，所有可能的世界配置。对智能体，一个状态可能是"当前已查到的航班列表 + 日历内容 + 对话历史"。
  • AAA：动作空间，智能体可执行的全部动作（每个工具调用是一个带参动作）。
  • T:S×A→ST: S \times A \to ST:S×A→S：转移函数，执行动作后世界如何变化。
  • G⊆SG \subseteq SG⊆S：目标状态集合，满足任务要求的那些状态。

规划即在此四元组上寻找一个动作序列 π=(a1,a2,…,an)\pi = (a_1, a_2, \dots, a_n)π=(a1​,a2​,…,an​)，使得从初始状态 s0s_0s0​ 出发，依次施加这些动作后到达某个 sn∈Gs_n \in Gsn​∈G。

flowchart TD
    S0[初始状态 s0<br/>目标 + 空行程] -->|a1 查航班| S1[s1<br/>得到航班列表]
    S1 -->|a2 选最便宜| S2[s2<br/>锁定候选]
    S2 -->|a3 下单| S3[s3<br/>拿到行程号]
    S3 -->|a4 写日历| SG[sG 属于 G<br/>目标达成]
    S2 -.售罄.-> X[转移失败<br/>触发重规划]
    X -.-> S1

经典规划与 LLM 智能体规划的核心差异，集中在这四个要素的"可知性"上，下表对照：

要素 经典 AI 规划（STRIPS/PDDL） LLM 智能体规划
状态 SSS 离散逻辑命题集合，完全可观测 自然语言上下文，部分可观测
动作 AAA 有精确前置/效果的算子 工具调用，效果常不确定
转移 TTT 确定、已知 随机、需执行后才知
目标 GGG 形式化命题 自然语言意图，可能模糊
求解 符号搜索，保证最优/完备 LLM 生成，启发式、无保证

这张表解释了一个关键事实：LLM 智能体规划牺牲了经典规划的完备性与最优性保证，换取了对开放、模糊、动态环境的适应力。第二章的各范式本质上是在这条取舍线上的不同站位。

确定性、马尔可夫与部分可观测

当转移 TTT 是确定的、状态完全可观测时，规划退化为在状态图上找路径，BFS/DFS/A* 即可。但智能体的真实处境几乎从不如此理想。

引入随机性后，转移变为概率分布 T(s′∣s,a)T(s' \mid s, a)T(s′∣s,a)，问题升级为马尔可夫决策过程（MDP），目标从"找一条路径"变成"找一个策略 π:S→A\pi: S \to Aπ:S→A"，最大化期望累积回报：

Vπ(s)=E[∑t=0∞γtr(st,at) | s0=s]V^\pi(s) = \mathbb{E}\left[\sum_{t=0}^{\infty} \gamma^t r(s_t, a_t) \,\middle|\, s_0 = s\right]Vπ(s)=E[t=0∑∞​γtr(st​,at​)​s0​=s]

其中 γ∈[0,1)\gamma \in [0,1)γ∈[0,1) 是折扣因子。本篇只借用 MDP 的语言来说明状态、动作与长期回报，不展开策略学习算法。

再放松"完全可观测"假设——智能体看不到完整世界，只能通过工具返回观察到局部信息——问题进一步升级为部分可观测马尔可夫决策过程（POMDP）。这正是网页智能体的真实处境：它不知道下一页长什么样，只能点进去才知道。POMDP 求解需要维护对隐藏状态的信念（belief） b(s)b(s)b(s)，这一点直接启发了第三章反思与自我批评中 ReflAct 维护并反思"信念—目标"对齐的设计。

实践含义很直接：环境越接近 POMDP，越不该把整条计划提前定死，越应依赖ReAct 交错推理那样的走一步看一步。

世界模型：先预测后承诺

四元组里的转移函数 TTT 往往未知，但规划仍需要回答「做了这个动作，接下来大概会怎样」。世界模型就是一个预测器 T^(s,a)\hat{T}(s,a)T^(s,a)：它根据历史转移、环境规则或检索到的相似经验，预测候选动作的后果，让规划器在真正产生副作用前做有限前瞻。

flowchart LR
  S[当前状态] --> A1[候选动作 A]
  S --> A2[候选动作 B]
  A1 --> W[世界模型预测]
  A2 --> W
  W --> O1[预测后果与置信度]
  O1 --> V[约束与价值评估]
  V --> C[只执行获选动作]
  C --> R[真实观察]
  R --> U[比较预测误差并更新记忆]

世界模型不一定是单独训练的神经网络，也可以是符号模拟器、API 沙箱、检索到的转移案例，或让 LLM 生成结构化后果预测。它的价值在于把不可逆动作变成「先模拟、再承诺」；它的危险则是错误前瞻会系统性误导计划。2026 年 WorldEvolver 的实验强调了三个实用构件：用真实转移形成情节记忆，从预测—观察偏差提炼规则，并只在预测置信度足够时向下游规划器提供前瞻（WorldEvolver, arXiv 2606.30639）。

因此世界模型必须输出置信度和可追溯依据，不能把预测伪装成事实。低置信度时退回交错执行，通过真实观察缩小不确定性；高风险动作即使预测乐观，也要经过确定性约束或人工审批。评测时应同时测转移预测准确率与最终任务成功率，因为更像真的预测不一定被规划器正确使用。

分层与层级任务网络（HTN）

直接在原子动作空间里搜索长程任务会爆炸——这就是为什么人类规划出差时不会一上来就想"先迈左脚还是右脚"，而是先想"订票、订酒店、报备"这些高层任务，再逐层细化。层级任务网络（HTN, Hierarchical Task Network） 把这种直觉形式化：定义一组方法（method），每个方法把一个抽象任务分解为更细的子任务，直到全是可直接执行的原始任务（primitive task）。

HTN 在 LLM 时代获得了新生。2025 年的 ChatHTN 用 LLM 在"没有现成方法可用"时即兴生成一个任务分解，再交还给 HTN 引擎继续推进，且被证明是可靠的（sound）——任何它产出的解都保证正确求解原问题（ChatHTN / Online HTN, arXiv 2511.12901）。这是"LLM 的灵活分解"与"符号规划的正确性保证"罕见的结合范例。HTN 作为一种具体的分解策略，详细机制留给任务分解展开；这里只确立它在形式化谱系中的位置：HTN 是在抽象层级上做的分层规划。

PDDL 与"让 LLM 写规划模型"

另一条把 LLM 与经典规划缝合的路线是：不让 LLM 直接输出动作序列，而让它把自然语言任务翻译成 PDDL（Planning Domain Definition Language，经典规划的标准描述语言），再交给久经考验的符号规划器（如 Fast Downward）求解。这样 LLM 只负责它擅长的"语言到形式化"映射，搜索的完备性由符号求解器兜底。2025 年一项综述系统梳理了这条"LLM 作为规划形式化器"的路线及其在可靠性上的优势（LLMs as Planning Formalizers, arXiv 2503.18971）。

路线 LLM 负责 求解器负责 优点 短板
LLM 直接规划 全部（分解+排序） 无 灵活、零形式化成本 无完备性保证
LLM → PDDL → 符号求解 翻译为形式化 搜索求解 完备、可验证 需可形式化的封闭域
LLM-HTN（如 ChatHTN） 即兴分解 层级展开+校验 灵活且可靠 工程复杂

选哪条，取决于你的域能否被形式化：封闭、规则明确的域（如物流调度）适合走 PDDL 路线；开放、语义模糊的域（如网页操作）只能靠 LLM 直接规划加重规划兜底。

小结

  • 规划问题最小可形式化为四元组 ⟨S,A,T,G⟩\langle S, A, T, G \rangle⟨S,A,T,G⟩，求解即找一条从 s0s_0s0​ 到目标集 GGG 的动作序列。
  • LLM 智能体规划牺牲经典规划的完备性/最优性保证，换取对开放、模糊、动态环境的适应力。
  • 按转移与可观测性，问题从确定性路径搜索升级到 MDP，再到 POMDP；环境越接近 POMDP，越该走一步看一步而非预定全程。
  • 世界模型用预测转移 T^\hat{T}T^ 支持「先模拟、再承诺」，但错误前瞻会放大偏航，必须带置信度、预测误差反馈与选择性使用。
  • HTN 在抽象层级上分解任务，ChatHTN 用 LLM 即兴生成方法且保持可靠性。
  • "LLM → PDDL → 符号求解器"路线把灵活性与完备性缝合，但只适用于可形式化的封闭域。
