规划范式谱系

一个新手最容易犯的错，是把 ReAct、Plan-and-Execute、ReWOO、思维树当成四个互相竞争、必须二选一的"框架"，然后凭一句"哪个更先进"做选型。它们其实是同一张设计空间里的不同坐标点——理解坐标轴，比记住名字重要得多。这一篇就是那张地图：把后两章将逐篇深讲的所有范式摆进统一坐标系，让你读每一篇时都知道"它在地图的哪个位置、放弃了什么换取了什么"。

核心概念

刻画规划范式，最有解释力的是两根轴。

轴一：何时规划（when to plan）。 一个极端是决策前置（decompose-first / plan-then-execute）：先一次性把整条计划想清楚，再执行。另一极端是交错（interleaved）：想一步、做一步、看一步，根据观察再想下一步。中间地带是"先出粗计划，执行中按需细化/修补"。

轴二：是否搜索（whether to search）。 一个极端是单轨（single-trajectory）：只生成并沿一条路径走。另一极端是多轨搜索（multi-trajectory search）：同时维护多条候选路径，比较、回溯、剪枝——这就把规划显式变成搜索问题，代价是计算量陡增。

这两根轴源自规划问题形式化：何时规划对应"环境是否接近 POMDP（越不可观测越该交错）"，是否搜索对应"是否愿意为完备性付出测试时计算"。

flowchart TD
    Q1{何时规划?} -->|决策前置| D[先想清整条计划]
    Q1 -->|交错| I[想一步做一步看一步]
    Q1 -->|混合| H[粗计划+按需细化]
    D --> Q2{是否搜索?}
    I --> Q2
    H --> Q2
    Q2 -->|单轨| ST[沿一条路径]
    Q2 -->|多轨搜索| MT[维护多条候选+回溯]
    ST --> R1[ReAct / Plan-Execute / ReWOO]
    MT --> R2[思维树 ToT / MCTS / LATS]

谱系全图：六种主流范式定位

把上面两根轴交叉，再叠加"LLM 调用次数 / token 效率"这个工程维度，就能给六种最常见的范式各安一个位置。下表是全 hub 的导航表，后两章每一篇都对应其中一行或几行。

范式 何时规划 是否搜索 LLM 调用 适用地形 主讲篇
ReAct 交错 单轨 每步一次（多） 反馈密集、不可预测 ReAct 交错推理
Plan-and-Execute 决策前置 单轨 计划1次+执行 长程、步骤可预判 任务分解
ReWOO 决策前置 单轨 仅约2次 token 敏感、工具可并行 任务分解
least-to-most 决策前置 单轨 中 子问题有依赖链 任务分解
思维树（ToT） 交错/混合 多轨搜索 多（指数） 需探索回溯的难题 思维树与搜索
LATS / MCTS 混合 多轨搜索 最多 高价值、可重试 思维树与搜索

几个值得记住的对照：ReAct 与 Plan-and-Execute 在"何时规划"轴上正对立，前者响应性强但缺全局视野、token 贵，后者全局且高效但计划僵化。ReWOO 是 Plan-and-Execute 的 token 优化版——它一次规划出带占位符的全流程、并行跑完所有工具、最后一次合成，总共约两次 LLM 调用，token 效率约为 ReAct 的五倍（The 4 Single-Agent Patterns）。思维树则在另一根轴上独树一帜：它不满足于一条路径，而是在计划空间里做真正的搜索。

第三根隐轴：是否自适应

前两根轴刻画"如何生成计划"，但 2026 年真正区分玩具与产品的，是第三根隐藏轴——是否具备自适应能力：计划出错后能不能反思、能不能重规划、能不能记住教训。

这根轴正交于前两根：ReAct 自带轻量自适应（每步看观察即调整），但缺乏对"整体策略错了"的反思；Plan-and-Execute 默认计划僵化，必须外挂重规划才不脆。2026 年的主流趋势正是给所有范式加装这层自适应——Plan-Execute-Verify-Replan 框架在执行后增加"验证"环节，发现集体结果未满足原始查询时触发定向重规划（Verified Multi-Agent Orchestration, arXiv 2603.11445）。

范式 自带反思 自带重规划 自带记忆
朴素 ReAct 弱（仅局部） 无 无
Plan-and-Execute 无 可外挂 无
Reflexion 系 强 强 跨会话
LATS（搜索+反思） 强 内生于回溯 可选

这根轴正是第三章自适应整章的主题：反思、重规划、记忆三篇分别对应表中三列。

如何用这张地图做选型

地图的用处是选型。给定一个任务，按三问定位：

  1. 环境可预测吗？ 不可预测（开放网页、强反馈依赖）→ 偏交错（ReAct）；可预判（固定流程、API 编排）→ 偏决策前置（Plan-and-Execute / ReWOO）。判据细节见为何需要规划末尾的取舍表。
  2. 任务难到需要探索回溯吗？ 一般任务单轨足够；存在多个看似可行实则死胡同的分支、且值得为正确性付算力 → 上多轨搜索（ToT/LATS）。
  3. 任务长且高风险吗？ 是 → 必须叠加自适应层（反思+重规划），并考虑人在回路审批。

值得强调：这些范式可组合而非互斥。一个成熟系统常是"Plan-and-Execute 出粗计划 + ReAct 执行每个子步 + 失败时局部重规划 + 关键节点 ToT 探索"的混合体。地图的价值不在于让你挑一个赢家，而在于让你为系统的每一层选对工具。

小结

  • 规划范式由两根主轴刻画：何时规划（决策前置↔交错）与是否搜索（单轨↔多轨），二者对应形式化中的"可观测性"与"测试时计算"取舍。
  • 六种主流范式（ReAct、Plan-and-Execute、ReWOO、least-to-most、ToT、LATS）可在这张坐标系里各安其位，本表是后两章的导航。
  • ReWOO 是 Plan-and-Execute 的 token 优化版，约两次调用、五倍效率。
  • 存在正交的第三根隐轴——是否自适应（反思/重规划/记忆），它是 2026 年区分玩具与产品的关键，对应第三章整章。
  • 范式可组合：成熟系统是多范式的混合体，地图用于为每一层选对工具而非挑唯一赢家。
