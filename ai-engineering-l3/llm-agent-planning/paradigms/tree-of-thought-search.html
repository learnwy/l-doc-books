思维树与搜索

ReAct 和任务分解都只沿一条路径前进——选定一步就走下去，错了再说。但有些问题里，"哪一步对"本身就需要试探：填字游戏、24 点、需要回溯的多步推理，往往得同时押注几条候选路、走不通就退回换一条。把规划显式地当成在"思路空间"里的搜索，正是思维树（Tree of Thoughts, ToT）这一族方法的出发点。它在范式谱系的"是否搜索"轴上站到了多轨搜索这一极，代价是算力陡增。

核心概念

思维树把规划建模成一棵搜索树：节点是一个"思路状态"（已走过的部分推理/计划），边是"再走一步思路"。在每个节点，LLM 既当生成器（提出若干候选下一步），又当评估器（给每个候选打分，判断它有多可能通向解）。然后用经典搜索策略决定扩展哪些节点、剪掉哪些。

它与单轨范式的根本区别在于回溯（backtracking）：走进死胡同时，ToT 能退回上层换一条分支，而 ReAct/分解只能硬着头皮往下或整体重来。

flowchart TD
    Root[初始问题] --> N1[思路A]
    Root --> N2[思路B]
    Root --> N3[思路C]
    N1 --> N1a[A1 评分0.8]
    N1 --> N1b[A2 评分0.3 剪枝]
    N2 --> N2a[B1 评分0.2 剪枝]
    N3 --> N3a[C1 评分0.7]
    N1a --> Goal[到达解]
    N3a -.回溯.-> N3

下表把单轨范式与多轨搜索的取舍摆清楚：

维度 单轨（ReAct/分解） 多轨搜索（ToT/MCTS）
同时维护路径数 1 多（束宽/采样数）
回溯能力 无（只能整体重来） 有
解难题能力 弱 强
LLM 调用量 线性 接近指数
适用任务 一般任务 高价值、可付算力的难题

从 ToT 到搜索算法谱系

ToT 是一个框架，具体"怎么搜"可套不同经典搜索算法，构成一个谱系。下表按"探索充分性 vs 算力"排列：

搜索策略 在 ToT 中如何用 特点
广度优先（BFS） 每层保留全部/前 k 个节点逐层扩展 不漏解，算力高
束搜索（Beam） 每层只留评分最高的 b 个 算力可控，可能漏最优
深度优先（DFS） 沿一条分支走到底，失败再回溯 省内存，可能久陷死胡同
蒙特卡洛树搜索（MCTS） 选择—扩展—模拟—回传四步循环 用采样平衡探索与利用

束搜索是工程上最常见的折中：维护固定束宽 bbb，每层只保留评分最高的 bbb 个节点，把指数爆炸压成 O(b⋅d)O(b \cdot d)O(b⋅d)（ddd 为深度）。

蒙特卡洛树搜索（MCTS） 更精巧，它用上置信界（UCB）公式在"利用已知好节点"与"探索未知节点"间权衡：

UCB(n)=Q(n)N(n)⏟利用+cln⁡N(parent)N(n)⏟探索\text{UCB}(n) = \underbrace{\frac{Q(n)}{N(n)}}_{\text{利用}} + \underbrace{c\sqrt{\frac{\ln N(\text{parent})}{N(n)}}}_{\text{探索}}UCB(n)=利用N(n)Q(n)​​​+探索cN(n)lnN(parent)​​​​

其中 Q(n)Q(n)Q(n) 是节点累积价值，N(n)N(n)N(n) 是访问次数，ccc 调节探索强度。把 MCTS 与 LLM 反思结合的代表是 LATS（Language Agent Tree Search），它在树搜索的每个节点引入反思信号来评估与改进——这是搜索与自适应的交汇点。

评估函数：搜索的灵魂

搜索的成败，七成在评估函数——它决定扩展谁、剪掉谁。ToT 里 LLM 自评有三种常见形式：

# 形式1：数值打分——让模型给每个候选思路打 0-1 的"通向解"概率
score = llm(f"这条思路解决问题的可能性(0-1)：{thought}")

# 形式2：投票——多个候选两两比较，胜出者晋级
winner = llm(f"以下哪条思路更可能正确？{candidates}")

# 形式3：可行性分类——sure / maybe / impossible 三档，直接剪掉 impossible
verdict = llm(f"这条思路可行吗(sure/maybe/impossible)：{thought}")

评估函数的可靠性是 ToT 的阿喀琉斯之踵：如果 LLM 自评不准，搜索就在错误的引导下浪费算力，甚至剪掉正确分支。这与规划评测里"过程评估难于结果评估"是同一个困难的两面——一个不可靠的验证器既毁搜索也毁纠错。

算力账：什么时候值得上搜索

多轨搜索本质是用测试时计算换正确率。问题是：值不值？

设束宽 bbb、深度 ddd、每节点评估调用 eee 次，则总 LLM 调用约 b⋅d⋅(1+e)b \cdot d \cdot (1+e)b⋅d⋅(1+e) ——相比 ReAct 的 ddd 次，开销放大 b(1+e)b(1+e)b(1+e) 倍。一个 b=5b=5b=5、e=1e=1e=1 的中等配置就是十倍调用量。因此搜索只在三个条件同时满足时划算：

  1. 任务确实难到单轨解不了（存在大量看似可行的死胡同）；
  2. 正确性价值高（一次错误的代价远超额外算力成本）；
  3. 有可靠的评估信号（自评或外部校验器靠谱，否则搜索是盲搜）。

反过来，对简单任务或评估信号不可靠的开放任务，搜索往往是负收益——多花十倍算力却被坏评估带偏。这条判据把思维树牢牢钉在范式谱系的"高价值难题"角落，而非通用默认。

小结

  • 思维树把规划显式建模为搜索树：LLM 兼任生成器与评估器，配合经典搜索策略扩展/剪枝，核心能力是单轨范式没有的回溯。
  • 搜索策略构成谱系：BFS 不漏解但贵、束搜索压成 O(b⋅d)O(b\cdot d)O(b⋅d)、DFS 省内存、MCTS 用 UCB 平衡探索与利用；LATS 把 MCTS 与反思结合。
  • 评估函数是搜索的灵魂，其可靠性是阿喀琉斯之踵——坏评估会剪掉正解、浪费算力。
  • 搜索是"用测试时计算换正确率"，开销约放大 b(1+e)b(1+e)b(1+e) 倍，仅在任务难、价值高、评估可靠三条件同时满足时划算。
  • 它在范式谱系里属"高价值难题"专用，而非通用默认。
