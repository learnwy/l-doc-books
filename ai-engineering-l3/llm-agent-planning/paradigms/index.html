Part II · Agent Construction智能体规划与任务分解范式

范式

这一章是 hub 的技术主体。三种主流规划范式在此各占一篇，逐一讲透其机制、适用边界与失败模式。它们不是互斥的竞品，而是处在范式谱系不同坐标上的工具——理解它们的取舍，才能为手头任务选对打法。

第一篇ReAct 交错推理讲最广为采用的范式：把"想—做—看"拧成一个循环，每一步都根据最新观察重新决策。它响应性强，但每步一次 LLM 调用、缺乏全局视野，长链上容易迷失。

第二篇任务分解走相反路线：先把大任务拆成子任务的结构（least-to-most、Plan-and-Solve、HTN、Plan-and-Execute），再分别求解。它视野全局、token 高效，代价是计划僵化、对意外不敏感——这正是第三章重规划与恢复要补的洞。

第三篇思维树与搜索把规划显式地变成搜索问题：用思维树、束搜索、蒙特卡洛树搜索在多条候选路径间权衡回溯。它能解前两者解不了的难题，但计算开销陡增，与兄弟 hub 55_llm-reasoning-test-time-compute 讲的测试时计算扩展同源。

读法建议：先读 ReAct 建立"交错"的基线直觉，再读分解理解"先谋后动"的另一极，最后用搜索把两者统一到"在计划空间里探索"的视角。三篇之间有密集交叉引用，可来回对照。
