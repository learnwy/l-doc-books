智能体规划与任务分解

当一个 LLM 智能体被要求"订一张明天去上海的最便宜机票并加进日历"时，它面对的不是单次问答，而是一连串相互依赖的决策：先查航班、再比价、然后调用日历、最后确认无冲突。把一个高层目标拆成可执行的子步骤、对子步骤排序、在执行偏离预期时调整路线——这套能力就是规划（planning）。本 hub 专讲规划这一件事：智能体如何从目标推导出行动序列，以及当世界不按剧本走时如何重来。

规划是智能体从"会说"走向"会做"的分水岭。τ-bench 原始论文报告，当时最强的函数调用智能体在整体任务上的成功率仍低于 50%，零售域的八次一致成功率 pass^8 低于 25%（τ-bench, arXiv 2406.12045）。这不是一个可永久沿用的模型排行榜，而是一个更稳定的工程警告：单次成功掩盖不了跨步骤、跨运行的不一致，规划与恢复必须单独度量。

全 hub 沿四条主线递进。第一条基础回答"为什么需要显式规划、规划问题在数学上是什么、有哪些范式谱系"，给后文搭好坐标系。第二条范式深入三种主流打法：ReAct 式交错推理、任务分解（least-to-most / Plan-and-Execute / HTN）、思维树与搜索（ToT / MCTS）——这是 hub 的技术主体。第三条自适应处理"计划注定会错"之后的事：反思与自我批评、失败检测与重规划、用记忆让规划越做越好。第四条实践落到工程地面：如何评测规划能力、如何在长程任务上守住可靠性、如何让人在关键节点介入。四线层层递进——先懂问题，再学方法，再学纠错，最后学怎么把它做扎实并安全上线。

本 hub 与若干兄弟 hub 边界相邻，分工务必清楚。工具调用的机制（函数调用协议、并行调用、JSON 语法约束）属于 74_llm-tool-use-function-calling；本 hub 只关心"规划决定调哪个工具、按什么顺序"，不重复讲调用本身。通用推理与测试时计算（思维链、自洽、推理模型 RL）属于 55_llm-reasoning-test-time-compute；本 hub 把推理当作规划的底层燃料，只在它服务于"行动序列生成"时展开。智能体工程脚手架（框架选型、LangGraph、生产部署）属于 03_ai-agent-development 与 26_ai-agent-frameworks；本 hub 讲规划算法本身，不讲框架 API。多智能体协作（角色分工、协商、编排）属于 52_multi-agent-systems；本 hub 默认单智能体规划，多体编排只点到为止。记忆系统的存储与检索机制属于 51_ai-agent-memory-systems；本 hub 的"规划与记忆"只讲记忆如何反哺规划这一接口。

推荐学习路径分三类读者。初学者按目录顺序读完整四章，先建立"规划是什么、为什么难"的直觉，再逐个吃透范式。已有智能体开发经验、想升级规划质量的工程师可直接跳到第二章对比三种范式，再读第三章的反思与重规划——这是把 demo 变产品的关键。做评测与上线的人重点读第四章，配合兄弟 hub 33_ai-evaluation-redteam 的评测方法学。

前置知识方面：读者应已熟悉 LLM 的基本调用方式与提示工程，理解"上下文窗口"和"工具调用"的大致概念。不需要经典 AI 规划（STRIPS/PDDL）背景——本 hub 会在用到时自带最小够用的形式化。具备搜索算法（BFS/DFS/启发式搜索）的直觉会让第二章的思维树一节读起来更轻松，但并非硬要求。
