Part II · Agent Construction智能体规划与任务分解实践人在回路规划

人在回路规划

一个智能体即将执行"删除生产数据库的旧表"或"给供应商打款 50 万"时，再可靠的自动重规划也不该是最后一道闸——这种动作出错的代价，远超让一个人花十秒点一下"确认"的成本。人在回路（human-in-the-loop, HITL）规划，就是把人的判断有结构地嵌进智能体的规划与执行流程，在恰当的节点、以恰当的方式让人介入。它与反思互补：一个是机器自审，一个是人审；也是重规划护栏"超限升级"和长程可靠性"幂等不可保证时升级"最终交付的去处。

核心概念

HITL 规划的设计核心是回答三个问题：在哪个阶段介入、对什么介入、以什么形式介入。

按阶段，介入点分两类——这是 HITL 最关键的设计选择：

  • 计划阶段介入（plan-time）：智能体先产出完整计划，人审查计划的可行性后再授权执行。适合涉及多部门、大预算的复杂工作流——在规划阶段就把关，比放任执行到一半才发现方向错了代价低得多（Human-in-the-Loop Oversight, Galileo）。
  • 执行阶段介入（execution-time）：计划自动跑，只在触及高风险动作时暂停请求批准（如真正打款那一步）。适合大部分步骤安全、仅个别动作危险的场景。
flowchart TD
    GOAL[用户目标] --> PLAN[智能体生成计划]
    PLAN --> PG{计划阶段审查?}
    PG -->|高复杂/大预算| HR1[人审计划可行性]
    PG -->|常规| EXEC[执行]
    HR1 -->|批准| EXEC
    HR1 -->|驳回+反馈| PLAN
    EXEC --> RISK{触及高风险动作?}
    RISK -->|是| HR2[人批准该动作]
    RISK -->|否| CONT[继续]
    HR2 -->|批准| CONT
    HR2 -->|拒绝| PLAN
    CONT --> DONE[完成]

按风险分级：不是所有动作都该打扰人

HITL 用得过密，人会被审批疲劳淹没，最终变成无脑点"同意"，监督形同虚设；用得过疏，危险动作溜过去。关键是按风险给动作分级，只在该停的地方停。一套常见的三级策略：

风险级别 动作例子 自动化程度 介入形式
低（可逆、无副作用） 查询、读取、搜索 全自动 无
中（有副作用、可补救） 发草稿、改非关键配置 自动+事后可审计 异步通知/抽审
高（不可逆、高代价） 打款、删数据、外发邮件 必须批准 同步阻塞审批

判级的依据主要是可逆性与代价：可逆且低代价的放行，不可逆或高代价的必停。这条原则和长程可靠性里"幂等动作可自动重试、非幂等动作须升级"是同一套逻辑的两面——不可逆性既挡住自动重试，也触发人工审批。

2026 年企业实践把这套做成了多层监督（multi-tier oversight）：策略规划与执行分离，LLM 产出高层行动计划，由操作员审查可行性后再授权（Galileo HITL Oversight）。混合工作流成为安全关键、强监管、信任敏感领域的标配——智能体增强而非取代人的专业判断（LLM agents guide 2026, SuperAnnotate）。

让人的反馈反哺规划，而非一次性丢弃

朴素 HITL 有个浪费：人驳回了一个计划、改了一个参数，这些宝贵反馈用完即扔，下次智能体还会犯同样的错。成熟做法是把人的介入当作高质量训练信号沉淀下来。

def plan_with_hitl(task, policy):
    plan = planner(task)
    if policy.needs_plan_review(plan):       # 计划阶段按策略判是否要审
        decision = ask_human(plan)           # 阻塞等人
        if decision.rejected:
            memory.add_lesson(decision.feedback)  # 反馈沉淀进记忆
            return plan_with_hitl(task, policy)   # 带教训重规划
    for step in plan:
        if policy.risk(step) == "high":      # 高风险动作执行前阻塞审批
            if not ask_human(step).approved:
                memory.add_lesson(...)        # 拒绝也是信号
                return replan_from(step)
        execute(step)
    return done

两个去向值得注意。其一，人的反馈写入规划与记忆，让智能体在后续任务里规避同类问题——这是 HITL 与记忆的接口。其二，积累的人工决策是最高质量的规划评测金标准与对齐数据，可用于改进策略本身。把"人在回路"从成本中心变成数据飞轮，是 HITL 工程化的关键一跃。

与可扩展监督的边界

HITL 有个内生张力：人的带宽有限，而智能体越强、越自主，需要审查的内容可能超出人类能逐条核查的范围——这就是可扩展监督（scalable oversight）问题。当智能体的计划复杂到人类难以独立判对错时，单纯"让人审"就不够了，可以用独立检查器帮人定位高风险步骤，但最终审批界面仍应展示证据、差异和不可逆后果，而不是只展示另一个模型的结论。

本 hub 的立场是务实的：按风险分级的 HITL 是高风险智能体上线的必备护栏；它与机器自审（反思）、自动恢复（重规划）一起，构成"机器尽量自己扛、扛不住或太危险就交给人"的完整安全网。无论单体还是多体，审批都必须绑定明确主体、权限范围、计划版本和过期时间。

小结

  • HITL 规划把人的判断有结构地嵌进流程，与机器自审（反思）、自动恢复（重规划）互补，是重规划"超限升级"和不可逆动作的最终去处。
  • 两类介入点：计划阶段（审查整体可行性，适合复杂大预算）与执行阶段（仅高风险动作阻塞审批）。
  • 按风险三级分流，判据是可逆性与代价：可逆低代价放行、不可逆高代价必停；这与"幂等可重试、非幂等须升级"同源，避免审批疲劳。
  • 人的反馈应反哺规划：写入记忆规避同类错、积累为评测金标准与对齐数据，把 HITL 从成本中心变数据飞轮。
  • 当计划复杂到超出人类审查范围时进入可扩展监督，属对齐 hub；务实立场是当下按风险分级的 HITL 仍是高风险上线必备护栏。
