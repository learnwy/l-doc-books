自定义工具开发

核心概念

自定义工具是将领域特定能力封装为 Agent 可调用组件的过程。一个好的工具不仅仅是对 API 的简单包装，它需要处理输入验证、错误恢复、结果格式化和安全控制。自定义工具的质量直接决定了 Agent 系统在特定领域的表现上限。





工具设计原则
说明
常见反模式





单一职责
每个工具只做一件事
一个工具包含多种操作




明确边界
清晰定义输入输出
接受自由文本输入




安全优先
验证所有输入
直接透传用户输入




幂等设计
重复调用无副作用
无法安全重试




信息充分
返回足够上下文
只返回 success/fail




快速失败
尽早检测错误
超时后才报错





数据库查询工具
构建一个安全的数据库查询工具需要处理 SQL 注入防护、查询超时、结果格式化等多个关注点：


import { DynamicStructuredTool } from '@langchain/core/tools';
import { z } from 'zod';

interface QueryResult {
  columns: string[];
  rows: Record<string, unknown>[];
  rowCount: number;
  executionTime: number;
}

const createDatabaseTool = (config: {
  connectionString: string;
  allowedTables: string[];
  maxRows: number;
  timeoutMs: number;
}) => {
  const validateQuery = (sql: string): { valid: boolean; reason?: string } => {
    const upper = sql.toUpperCase().trim();
    if (!upper.startsWith('SELECT')) {
      return { valid: false, reason: '只允许 SELECT 查询' };
    }

    const dangerous = ['DROP', 'DELETE', 'UPDATE', 'INSERT', 'ALTER', 'TRUNCATE', 'EXEC'];
    for (const keyword of dangerous) {
      if (upper.includes(keyword)) {
        return { valid: false, reason: `包含禁止关键字: ${keyword}` };
      }
    }

    const tableRefs = sql.match(/(?:FROM|JOIN)\s+(\w+)/gi) || [];
    for (const ref of tableRefs) {
      const tableName = ref.split(/\s+/)[1];
      if (!config.allowedTables.includes(tableName)) {
        return { valid: false, reason: `不允许访问表: ${tableName}` };
      }
    }

    return { valid: true };
  };

  return new DynamicStructuredTool({
    name: 'query_database',
    description: `查询数据库，获取业务数据。可访问的表：${config.allowedTables.join('、')}。
      仅支持 SELECT 查询，最多返回 ${config.maxRows} 行。
      返回格式：列名列表 + 数据行数组 + 行数统计。`,
    schema: z.object({
      sql: z.string().describe('SQL SELECT 查询语句'),
      explain: z.boolean().optional().default(false).describe('是否返回执行计划'),
    }),
    func: async ({ sql, explain }) => {
      const validation = validateQuery(sql);
      if (!validation.valid) {
        return JSON.stringify({ error: validation.reason, suggestion: '请修改查询后重试' });
      }

      const limitedSql = sql.includes('LIMIT') ? sql : `${sql} LIMIT ${config.maxRows}`;

      try {
        const start = Date.now();
        const result: QueryResult = {
          columns: ['id', 'name', 'value'],
          rows: [],
          rowCount: 0,
          executionTime: Date.now() - start,
        };

        return JSON.stringify({
          ...result,
          hint:
            result.rowCount === config.maxRows
              ? `结果已截断到 ${config.maxRows} 行，如需更多数据请添加更精确的 WHERE 条件`
              : undefined,
        });
      } catch (error) {
        return JSON.stringify({
          error: `查询执行失败: ${(error as Error).message}`,
          suggestion: '请检查 SQL 语法或简化查询',
        });
      }
    },
  });
};
数据库工具的关键设计是多层防御：Schema 层验证参数类型，业务层验证 SQL 安全性，执行层控制超时和结果大小。


API 集成工具
将外部 API 封装为 Agent 工具时，需要处理认证、速率限制和响应格式化：


const createApiTool = (config: {
  name: string;
  description: string;
  baseUrl: string;
  headers: Record<string, string>;
  rateLimit: { maxCalls: number; windowMs: number };
}) => {
  let callTimestamps: number[] = [];

  const checkRateLimit = (): boolean => {
    const now = Date.now();
    callTimestamps = callTimestamps.filter((t) => now - t < config.rateLimit.windowMs);
    if (callTimestamps.length >= config.rateLimit.maxCalls) return false;
    callTimestamps.push(now);
    return true;
  };

  return new DynamicStructuredTool({
    name: config.name,
    description: config.description,
    schema: z.object({
      endpoint: z.string().describe('API 端点路径'),
      method: z.enum(['GET', 'POST']).default('GET'),
      params: z.record(z.string()).optional().describe('查询参数'),
      body: z.string().optional().describe('POST 请求体（JSON 字符串）'),
    }),
    func: async ({ endpoint, method, params, body }) => {
      if (!checkRateLimit()) {
        return JSON.stringify({
          error: '速率限制',
          retryAfter: `${config.rateLimit.windowMs / 1000} 秒后重试`,
        });
      }

      const url = new URL(endpoint, config.baseUrl);
      if (params) {
        for (const [key, value] of Object.entries(params)) {
          url.searchParams.set(key, value);
        }
      }

      try {
        const response = await fetch(url.toString(), {
          method,
          headers: { ...config.headers, 'Content-Type': 'application/json' },
          body: method === 'POST' ? body : undefined,
          signal: AbortSignal.timeout(10000),
        });

        if (!response.ok) {
          return JSON.stringify({
            error: `API 返回 ${response.status}`,
            statusText: response.statusText,
          });
        }

        const data = await response.json();
        return JSON.stringify(data, null, 2).slice(0, 5000);
      } catch (error) {
        return JSON.stringify({ error: (error as Error).message });
      }
    },
  });
};
API 工具的响应应该被截断到合理的长度（如 5000 字符），避免过大的返回值占用 LLM 的上下文窗口。


文件系统工具
文件系统工具允许 Agent 读写文件，但必须严格限制访问范围以防止安全问题：


import { resolve, relative } from 'node:path';
import { readFile, writeFile, readdir, stat } from 'node:fs/promises';

const createFileSystemTool = (config: {
  rootDir: string;
  allowedExtensions: string[];
  maxFileSize: number;
  readOnly: boolean;
}) => {
  const isPathSafe = (filePath: string): boolean => {
    const resolved = resolve(config.rootDir, filePath);
    const rel = relative(config.rootDir, resolved);
    return !rel.startsWith('..') && !resolve(resolved).includes('node_modules');
  };

  const readTool = new DynamicStructuredTool({
    name: 'read_file',
    description: `读取项目文件内容。允许的文件类型：${config.allowedExtensions.join('、')}。
      文件路径相对于项目根目录。超过 ${config.maxFileSize / 1024}KB 的文件将被截断。`,
    schema: z.object({
      path: z.string().describe('相对于项目根目录的文件路径'),
      startLine: z.number().optional().describe('起始行号（从 1 开始）'),
      endLine: z.number().optional().describe('结束行号'),
    }),
    func: async ({ path: filePath, startLine, endLine }) => {
      if (!isPathSafe(filePath)) {
        return JSON.stringify({ error: '路径不在允许范围内' });
      }

      const ext = filePath.split('.').pop() ?? '';
      if (!config.allowedExtensions.includes(`.${ext}`)) {
        return JSON.stringify({ error: `不允许读取 .${ext} 文件` });
      }

      try {
        const fullPath = resolve(config.rootDir, filePath);
        const fileStat = await stat(fullPath);

        if (fileStat.size > config.maxFileSize) {
          return JSON.stringify({ error: '文件过大，请指定行号范围' });
        }

        let content = await readFile(fullPath, 'utf-8');
        if (startLine || endLine) {
          const lines = content.split('\n');
          const start = (startLine ?? 1) - 1;
          const end = endLine ?? lines.length;
          content = lines.slice(start, end).join('\n');
        }

        return content;
      } catch (error) {
        return JSON.stringify({ error: (error as Error).message });
      }
    },
  });

  const listTool = new DynamicStructuredTool({
    name: 'list_directory',
    description: '列出目录中的文件和子目录',
    schema: z.object({
      path: z.string().default('.').describe('相对于项目根目录的目录路径'),
      recursive: z.boolean().optional().default(false),
    }),
    func: async ({ path: dirPath, recursive }) => {
      if (!isPathSafe(dirPath)) {
        return JSON.stringify({ error: '路径不在允许范围内' });
      }
      try {
        const entries = await readdir(resolve(config.rootDir, dirPath), {
          withFileTypes: true,
          recursive,
        });
        return JSON.stringify(
          entries.slice(0, 100).map((e) => ({
            name: e.name,
            type: e.isDirectory() ? 'dir' : 'file',
          })),
        );
      } catch (error) {
        return JSON.stringify({ error: (error as Error).message });
      }
    },
  });

  return [readTool, listTool];
};
文件系统工具的安全核心是路径遍历防护——通过 resolve 和 relative 确保所有访问都限制在配置的根目录内。


工具测试策略
自定义工具需要在三个维度进行测试：功能正确性、安全性和 LLM 兼容性：


const testSuite = {
  functional: async (tool: DynamicStructuredTool) => {
    const cases = [
      { input: { sql: 'SELECT * FROM products' }, expectContains: 'columns' },
      { input: { sql: 'DROP TABLE products' }, expectContains: 'error' },
      { input: { sql: 'SELECT * FROM secrets' }, expectContains: '不允许' },
    ];

    for (const { input, expectContains } of cases) {
      const result = await tool.invoke(input);
      const passed = result.includes(expectContains);
      console.log(`${passed ? '✅' : '❌'} ${JSON.stringify(input)} → ${expectContains}`);
    }
  },

  security: async (tool: DynamicStructuredTool) => {
    const attacks = [
      'SELECT * FROM products; DROP TABLE users',
      'SELECT * FROM products UNION SELECT password FROM users',
      'SELECT * FROM ../../etc/passwd',
    ];

    for (const attack of attacks) {
      const result = await tool.invoke({ sql: attack });
      const blocked = result.includes('error') || result.includes('禁止') || result.includes('不允许');
      console.log(`${blocked ? '✅ 已拦截' : '❌ 未拦截'}: ${attack.slice(0, 50)}`);
    }
  },
};
小结
    

  • 自定义工具开发遵循单一职责、安全优先、幂等设计、信息充分四大原则
    • 

  • 数据库工具需要多层防御：Schema 验证、SQL 安全检查、执行超时和结果截断
    • 

  • API 工具必须实现速率限制和响应截断，防止影响 LLM 上下文窗口
    • 

  • 文件系统工具通过路径遍历防护确保访问范围受控
    • 

  • 工具测试应覆盖功能、安全和 LLM 兼容性三个维度
