工具编排与调度

核心概念

工具编排是 Agent 系统中连接 LLM 推理能力与外部工具执行的中间层。当 Agent 需要调用多个工具、处理工具间依赖关系、管理并发执行和故障恢复时，简单的工具调用已不能满足需求。工具编排器负责将 LLM 的工具调用意图转化为高效、可靠的执行计划。

并行执行引擎
当多个工具调用之间没有数据依赖时，并行执行可以大幅减少总延迟。编排器需要识别独立的工具调用并管理并发：


interface ToolCall {
  id: string;
  name: string;
  args: Record<string, unknown>;
  dependencies: string[];
}

interface ToolResult {
  id: string;
  success: boolean;
  data: unknown;
  duration: number;
}

const createParallelExecutor = (
  toolRegistry: Map<string, (args: Record<string, unknown>) => Promise<unknown>>,
  config: { maxConcurrency: number; timeout: number },
) => {
  return async (calls: ToolCall[]): Promise<ToolResult[]> => {
    const results = new Map<string, ToolResult>();
    const pending = new Set(calls.map((c) => c.id));

    const executeOne = async (call: ToolCall): Promise<ToolResult> => {
      const start = Date.now();
      const handler = toolRegistry.get(call.name);
      if (!handler) {
        return { id: call.id, success: false, data: `未知工具: ${call.name}`, duration: 0 };
      }

      try {
        const result = await Promise.race([
          handler(call.args),
          new Promise((_, reject) => setTimeout(() => reject(new Error('超时')), config.timeout)),
        ]);
        return { id: call.id, success: true, data: result, duration: Date.now() - start };
      } catch (error) {
        return {
          id: call.id,
          success: false,
          data: (error as Error).message,
          duration: Date.now() - start,
        };
      }
    };

    const ready = calls.filter((c) => c.dependencies.length === 0);
    const waiting = calls.filter((c) => c.dependencies.length > 0);

    const batchExecute = async (batch: ToolCall[]) => {
      const chunks: ToolCall[][] = [];
      for (let i = 0; i < batch.length; i += config.maxConcurrency) {
        chunks.push(batch.slice(i, i + config.maxConcurrency));
      }

      for (const chunk of chunks) {
        const chunkResults = await Promise.all(chunk.map(executeOne));
        for (const r of chunkResults) {
          results.set(r.id, r);
          pending.delete(r.id);
        }
      }
    };

    await batchExecute(ready);

    while (pending.size > 0) {
      const nowReady = waiting.filter((c) => c.dependencies.every((dep) => results.has(dep)) && pending.has(c.id));
      if (nowReady.length === 0) break;
      await batchExecute(nowReady);
    }

    return calls.map((c) => results.get(c.id)!);
  };
};
并行执行的关键约束是最大并发数控制。过高的并发可能触发外部 API 的速率限制或导致资源争用，通常建议设置为 5-10 个并行任务。


依赖图与 DAG 调度
当工具调用之间存在数据依赖时，需要构建有向无环图（DAG）并按拓扑顺序执行。这确保每个工具在其依赖完成后才执行：


const buildExecutionDAG = (calls: ToolCall[]): Map<number, ToolCall[]> => {
  const inDegree = new Map<string, number>();
  const adjList = new Map<string, string[]>();

  for (const call of calls) {
    inDegree.set(call.id, call.dependencies.length);
    for (const dep of call.dependencies) {
      const existing = adjList.get(dep) || [];
      existing.push(call.id);
      adjList.set(dep, existing);
    }
  }

  const levels = new Map<number, ToolCall[]>();
  let level = 0;
  const queue = calls.filter((c) => (inDegree.get(c.id) ?? 0) === 0);
  const visited = new Set<string>();

  while (queue.length > 0) {
    levels.set(level, [...queue]);
    const nextQueue: ToolCall[] = [];

    for (const call of queue) {
      visited.add(call.id);
      const dependents = adjList.get(call.id) || [];
      for (const depId of dependents) {
        const newDegree = (inDegree.get(depId) ?? 1) - 1;
        inDegree.set(depId, newDegree);
        if (newDegree === 0) {
          nextQueue.push(calls.find((c) => c.id === depId)!);
        }
      }
    }

    queue.length = 0;
    queue.push(...nextQueue);
    level++;
  }

  return levels;
};
DAG 调度的优势在于最大化并行度——同一层级的工具可以并行执行，只有跨层级的依赖才需要等待。


重试与降级策略
生产环境中工具调用可能因网络、超时或服务端错误而失败。编排器需要实现智能的重试和降级策略：


interface RetryConfig {
  maxAttempts: number;
  baseDelay: number;
  maxDelay: number;
  backoffMultiplier: number;
  retryableErrors: string[];
}

const createRetryableExecutor = (config: RetryConfig) => {
  const shouldRetry = (error: Error, attempt: number): boolean => {
    if (attempt >= config.maxAttempts) return false;
    return config.retryableErrors.some((pattern) => error.message.includes(pattern));
  };

  const getDelay = (attempt: number): number => {
    const delay = config.baseDelay * Math.pow(config.backoffMultiplier, attempt);
    const jitter = Math.random() * delay * 0.1;
    return Math.min(delay + jitter, config.maxDelay);
  };

  return async <T>(fn: () => Promise<T>, fallback?: () => Promise<T>): Promise<T> => {
    let lastError: Error | undefined;

    for (let attempt = 0; attempt < config.maxAttempts; attempt++) {
      try {
        return await fn();
      } catch (error) {
        lastError = error as Error;
        if (!shouldRetry(lastError, attempt + 1)) break;
        await new Promise((r) => setTimeout(r, getDelay(attempt)));
      }
    }

    if (fallback) {
      return fallback();
    }

    throw lastError;
  };
};

const retryExecutor = createRetryableExecutor({
  maxAttempts: 3,
  baseDelay: 1000,
  maxDelay: 10000,
  backoffMultiplier: 2,
  retryableErrors: ['TIMEOUT', 'RATE_LIMIT', 'SERVICE_UNAVAILABLE'],
});

结果聚合与缓存
多工具执行的结果需要聚合为 LLM 可消费的格式，同时通过缓存避免重复执行：


const createToolCache = (config: { ttlMs: number; maxSize: number }) => {
  const cache = new Map<string, { result: unknown; expiry: number }>();

  const getCacheKey = (name: string, args: Record<string, unknown>): string => {
    return `${name}:${JSON.stringify(args, Object.keys(args).sort())}`;
  };

  return {
    get: (name: string, args: Record<string, unknown>): unknown | undefined => {
      const key = getCacheKey(name, args);
      const entry = cache.get(key);
      if (!entry || Date.now() > entry.expiry) {
        cache.delete(key);
        return undefined;
      }
      return entry.result;
    },
    set: (name: string, args: Record<string, unknown>, result: unknown) => {
      if (cache.size >= config.maxSize) {
        const firstKey = cache.keys().next().value;
        if (firstKey) cache.delete(firstKey);
      }
      cache.set(getCacheKey(name, args), { result, expiry: Date.now() + config.ttlMs });
    },
  };
};
缓存策略需要根据工具的特性来决定——实时数据查询（如股价）不应缓存，而静态信息查询（如文档搜索）可以设置较长的 TTL。


小结
    

  • 工具编排器是 LLM 意图与工具执行之间的中间层，负责依赖分析、并发控制和故障恢复
    • 

  • 无依赖的工具调用应并行执行，并发数控制在 5-10 以避免触发速率限制
    • 

  • DAG 调度通过拓扑排序最大化并行度，确保依赖顺序正确
    • 

  • 重试策略应使用指数退避加抖动，结合断路器模式防止雪崩
    • 

  • 工具结果缓存可避免重复执行，但需根据数据时效性设置合理的 TTL
    •
