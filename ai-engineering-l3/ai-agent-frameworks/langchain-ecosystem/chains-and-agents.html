链与代理模式

核心概念

在 LangChain 中，Chain（链）和 Agent（代理）代表了两种截然不同的 LLM 应用构建范式。Chain 是预定义的执行路径，每个步骤在编码时就已确定；Agent 则由 LLM 动态决定下一步操作，具备自主推理和工具调用能力。理解两者的边界和适用场景是构建可靠 AI 应用的关键。

链的构建模式
LangChain 的链从简单的顺序调用发展到支持并行、分支和条件逻辑的复杂工作流。LCEL 提供了声明式的链构建能力：


import { ChatOpenAI } from '@langchain/openai';
import { ChatPromptTemplate } from '@langchain/core/prompts';
import { StringOutputParser } from '@langchain/core/output_parsers';
import { RunnableSequence, RunnableParallel, RunnablePassthrough, RunnableBranch } from '@langchain/core/runnables';

const model = new ChatOpenAI({ modelName: 'gpt-4' });

const analyzeChain = ChatPromptTemplate.fromTemplate('分析以下文本的主题和情感：{text}')
  .pipe(model)
  .pipe(new StringOutputParser());

const summarizeChain = ChatPromptTemplate.fromTemplate('用三句话总结以下文本：{text}')
  .pipe(model)
  .pipe(new StringOutputParser());

const parallelChain = RunnableParallel.from({
  analysis: analyzeChain,
  summary: summarizeChain,
  original: new RunnablePassthrough(),
});

const classifyChain = ChatPromptTemplate.fromTemplate(
  "判断以下文本是技术文档还是商业报告，只回答'技术'或'商业'：{text}",
)
  .pipe(model)
  .pipe(new StringOutputParser());

const techChain = ChatPromptTemplate.fromTemplate('提取以下技术文档的关键 API 和代码示例：{text}')
  .pipe(model)
  .pipe(new StringOutputParser());

const bizChain = ChatPromptTemplate.fromTemplate('提取以下商业报告的关键数据和结论：{text}')
  .pipe(model)
  .pipe(new StringOutputParser());

const branchChain = RunnableSequence.from([
  { text: new RunnablePassthrough(), category: classifyChain },
  new RunnableBranch([(input) => input.category.includes('技术'), techChain], bizChain),
]);
链的设计原则是最小化 LLM 调用次数。每次调用都有延迟和成本，因此应尽量在单次 prompt 中完成更多工作，只在确实需要不同推理逻辑时才拆分为多步。


ReAct 代理架构
ReAct（Reasoning + Acting）是 LangChain Agent 的经典实现模式。LLM 交替进行推理（Thought）和行动（Action），通过观察行动结果（Observation）迭代直到得出最终答案。


import { ChatOpenAI } from '@langchain/openai';
import { createReactAgent } from '@langchain/langgraph/prebuilt';
import { TavilySearchResults } from '@langchain/community/tools/tavily_search';
import { Calculator } from '@langchain/community/tools/calculator';
import { DynamicStructuredTool } from '@langchain/core/tools';
import { z } from 'zod';

const searchTool = new TavilySearchResults({ maxResults: 3 });
const calculator = new Calculator();

const codeAnalyzer = new DynamicStructuredTool({
  name: 'analyze_code',
  description: '分析代码片段的复杂度和潜在问题',
  schema: z.object({
    code: z.string().describe('要分析的代码'),
    language: z.string().describe('编程语言'),
  }),
  func: async ({ code, language }) => {
    const lines = code.split('\n').length;
    return `代码分析结果：${language} 代码共 ${lines} 行，复杂度中等`;
  },
});

const model = new ChatOpenAI({ modelName: 'gpt-4-turbo' });

const agent = createReactAgent({
  llm: model,
  tools: [searchTool, calculator, codeAnalyzer],
});

const result = await agent.invoke({
  messages: [{ role: 'user', content: '搜索 React 19 的新特性，计算如果团队有 5 人需要多少天完成迁移' }],
});
ReAct 代理的执行过程遵循 Thought → Action → Observation 循环，LLM 在每一轮根据历史上下文决定是继续调用工具还是直接给出答案。这种模式的优势是通用性强，但缺点是推理步骤不可控，可能出现无限循环或偏离主题。


记忆系统设计
Agent 和 Chain 都需要记忆系统来维持上下文连续性。LangChain 提供了多种记忆策略，从简单的对话缓冲到复杂的摘要记忆：


import { BufferMemory, ConversationSummaryMemory } from 'langchain/memory';
import { ChatOpenAI } from '@langchain/openai';
import { ChatMessageHistory } from 'langchain/stores/message/in_memory';

const bufferMemory = new BufferMemory({
  memoryKey: 'chat_history',
  returnMessages: true,
  chatHistory: new ChatMessageHistory(),
});

const summaryMemory = new ConversationSummaryMemory({
  llm: new ChatOpenAI({ modelName: 'gpt-3.5-turbo' }),
  memoryKey: 'chat_history',
  returnMessages: true,
});

在生产环境中，记忆系统通常需要持久化到外部存储（Redis、PostgreSQL 等），LangChain 通过 ChatMessageHistory 的多种后端实现来支持这一需求。


错误处理与可靠性
生产级 Agent 必须具备完善的错误处理机制。LLM 输出的不确定性、工具调用的失败、上下文窗口溢出等问题都需要在框架层面系统性地解决：


import { ChatOpenAI } from '@langchain/openai';
import { RunnableSequence } from '@langchain/core/runnables';

const reliableModel = new ChatOpenAI({
  modelName: 'gpt-4-turbo',
  maxRetries: 3,
  timeout: 30000,
}).withFallbacks({
  fallbacks: [new ChatOpenAI({ modelName: 'gpt-3.5-turbo', maxRetries: 2 })],
});

const chainWithRetry = RunnableSequence.from([prompt, reliableModel, outputParser]).withRetry({
  stopAfterAttempt: 3,
  onFailedAttempt: (error, attempt) => {
    console.error(`第 ${attempt} 次尝试失败：${error.message}`);
  },
});
关键的可靠性策略包括：为每个链设置超时时间防止无限等待，使用 withFallbacks 配置模型降级路径，在 Agent 循环中设置最大迭代次数防止无限循环，以及通过 LangSmith 追踪每次调用的输入输出用于事后分析。


小结
    

  • Chain 适合确定性流程，Agent 适合需要动态推理的场景，选择取决于任务的结构化程度
    • 

  • LCEL 支持顺序、并行、分支三种链组合模式，应最小化 LLM 调用次数以控制延迟和成本
    • 

  • ReAct 是最通用的 Agent 架构，通过 Thought-Action-Observation 循环实现自主推理
    • 

  • 记忆系统的选择需要在 Token 消耗和信息完整性之间权衡，生产环境需持久化
    • 

  • 错误处理是生产级应用的必要环节，需要在模型层和链层都配置重试与降级策略
    •
