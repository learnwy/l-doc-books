LangChain 工具系统

核心概念

工具（Tool）是 Agent 与外部世界交互的接口。在 LangChain 中，工具将外部能力（搜索引擎、数据库、API、文件系统等）封装为 LLM 可理解、可调用的标准化组件。LLM 通过工具的名称和描述来决定何时以及如何调用它们，因此工具的描述质量直接决定了 Agent 的行为准确性。

自定义工具开发
LangChain 提供了三种创建自定义工具的方式：tool 装饰器适合简单场景，DynamicStructuredTool 适合需要复杂输入的场景，继承 StructuredTool 则提供最大的灵活性。


import { DynamicStructuredTool, StructuredTool } from '@langchain/core/tools';
import { z } from 'zod';
import { tool } from '@langchain/core/tools';

const weatherTool = tool(
  async (input: string) => {
    return `${input} 当前温度 25°C，晴天`;
  },
  {
    name: 'get_weather',
    description: '获取指定城市的天气信息',
    schema: z.object({
      city: z.string().describe('城市名称'),
    }),
  },
);

const databaseQuery = new DynamicStructuredTool({
  name: 'query_database',
  description: '在产品数据库中执行 SQL 查询，返回结构化结果',
  schema: z.object({
    query: z.string().describe('SQL SELECT 查询语句'),
    limit: z.number().optional().default(10).describe('返回结果数量上限'),
  }),
  func: async ({ query, limit }) => {
    const sanitized = query.replace(/;.*$/, '').trim();
    if (!/^SELECT/i.test(sanitized)) {
      return '错误：只允许 SELECT 查询';
    }
    return JSON.stringify({ rows: [], count: 0, query: sanitized });
  },
});

class GitHubTool extends StructuredTool {
  name = 'github_search';
  description = '搜索 GitHub 仓库，返回仓库名、星数和描述';
  schema = z.object({
    query: z.string().describe('搜索关键词'),
    language: z.string().optional().describe('编程语言过滤'),
  });

  async _call({ query, language }: z.infer<typeof this.schema>) {
    const params = new URLSearchParams({ q: query });
    if (language) params.set('q', `${query} language:${language}`);
    const response = await fetch(`https://api.github.com/search/repositories?${params}`);
    const data = await response.json();
    return JSON.stringify(
      data.items?.slice(0, 5).map((r: Record<string, unknown>) => ({
        name: r.full_name,
        stars: r.stargazers_count,
        description: r.description,
      })),
    );
  }
}
工具描述的编写是一门艺术。描述应该清晰说明工具的用途（做什么）、输入要求（接受什么）和输出格式（返回什么）。模糊的描述会导致 LLM 在错误的时机调用工具。


工具组合与路由
复杂的 Agent 通常拥有多个工具，需要设计合理的路由策略来确保 LLM 选择正确的工具。工具组可以按领域分组，通过工具包（Toolkit）模式管理：


import { DynamicStructuredTool } from '@langchain/core/tools';
import { z } from 'zod';

const createCRUDToolkit = (entityName: string) => {
  const listTool = new DynamicStructuredTool({
    name: `list_${entityName}`,
    description: `列出所有 ${entityName}，支持分页和过滤`,
    schema: z.object({
      page: z.number().optional().default(1),
      filter: z.string().optional().describe('过滤条件'),
    }),
    func: async ({ page, filter }) => JSON.stringify({ entity: entityName, page, filter, results: [] }),
  });

  const getTool = new DynamicStructuredTool({
    name: `get_${entityName}`,
    description: `根据 ID 获取单个 ${entityName} 的详细信息`,
    schema: z.object({ id: z.string().describe('实体 ID') }),
    func: async ({ id }) => JSON.stringify({ entity: entityName, id, data: {} }),
  });

  const createTool = new DynamicStructuredTool({
    name: `create_${entityName}`,
    description: `创建新的 ${entityName}`,
    schema: z.object({ data: z.string().describe('JSON 格式的创建数据') }),
    func: async ({ data }) => JSON.stringify({ entity: entityName, created: true, data }),
  });

  return [listTool, getTool, createTool];
};

const productTools = createCRUDToolkit('product');
const orderTools = createCRUDToolkit('order');
const allTools = [...productTools, ...orderTools];
工具数量的最佳实践是控制在 5-15 个之间。工具过少会限制 Agent 能力，过多则会增加 LLM 的选择难度和 Token 消耗。当工具超过 15 个时，应考虑分层路由——先选择工具类别，再在类别内选择具体工具。


工具安全与验证
工具是 Agent 与外部系统的边界，安全性至关重要。必须在工具层面实现输入验证、权限控制和操作审计：


import { DynamicStructuredTool } from '@langchain/core/tools';
import { z } from 'zod';

const createSafeDbTool = (allowedTables: string[]) =>
  new DynamicStructuredTool({
    name: 'safe_db_query',
    description: `安全数据库查询工具，仅允许查询 ${allowedTables.join('、')} 表`,
    schema: z.object({
      query: z.string().describe('SQL SELECT 查询'),
    }),
    func: async ({ query }) => {
      const upperQuery = query.toUpperCase().trim();

      if (!upperQuery.startsWith('SELECT')) {
        return '安全拒绝：只允许 SELECT 查询';
      }

      const forbidden = ['DROP', 'DELETE', 'UPDATE', 'INSERT', 'ALTER'];
      if (forbidden.some((kw) => upperQuery.includes(kw))) {
        return '安全拒绝：检测到危险操作关键字';
      }

      const tableMatch = query.match(/FROM\s+(\w+)/i);
      if (tableMatch && !allowedTables.includes(tableMatch[1])) {
        return `安全拒绝：不允许访问表 ${tableMatch[1]}`;
      }

      return JSON.stringify({ status: 'ok', rows: [] });
    },
  });

const safeDbTool = createSafeDbTool(['products', 'categories', 'reviews']);

工具测试与调试
工具的可靠性直接决定了 Agent 的整体表现。系统的测试策略应覆盖工具本身的功能正确性和 LLM 调用工具时的行为正确性：


import { DynamicStructuredTool } from '@langchain/core/tools';
import { z } from 'zod';

const testToolDirectly = async (tool: DynamicStructuredTool, input: Record<string, unknown>, expected: string) => {
  const result = await tool.invoke(input);
  const pass = result.includes(expected);
  console.log(`${pass ? '✅' : '❌'} ${tool.name}: ${pass ? '通过' : '失败'}`);
  return pass;
};

const testToolSelection = async (
  agent: { invoke: (input: Record<string, unknown>) => Promise<Record<string, unknown>> },
  userQuery: string,
  expectedTool: string,
) => {
  const result = await agent.invoke({
    messages: [{ role: 'user', content: userQuery }],
  });
  const steps = (result as Record<string, unknown[]>).intermediateSteps || [];
  const usedTool = steps.some(
    (s: unknown) => (s as Record<string, Record<string, string>>).action?.tool === expectedTool,
  );
  console.log(`${usedTool ? '✅' : '❌'} 查询 "${userQuery}" → 期望工具 ${expectedTool}`);
  return usedTool;
};
调试工具调用时，LangSmith 的追踪功能是最有价值的手段。它能展示 LLM 在每一步的完整推理过程，包括为什么选择了某个工具、传入了什么参数、得到了什么结果。


小结
    

  • 工具是 Agent 连接外部世界的桥梁，工具描述的质量直接影响 Agent 的行为准确性
    • 

  • 三种创建方式适用于不同复杂度：tool 函数、DynamicStructuredTool、StructuredTool 类
    • 

  • 工具数量建议控制在 5-15 个，超过时应采用分层路由策略
    • 

  • 安全设计是生产工具的必备要素，需要在输入验证、权限控制和审计三个层面综合防护
    • 

  • 工具测试需要覆盖两个维度：工具自身的功能正确性和 LLM 对工具的选择正确性
