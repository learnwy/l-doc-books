LangGraph 状态化工作流

核心概念

LangGraph 是 LangChain 生态中用于构建有状态、多步骤 AI 应用的框架。它以有向图（Directed Graph）为核心抽象，每个节点是一个计算步骤，边定义了控制流。与传统 Chain 的线性执行不同，LangGraph 支持循环、条件分支和并行执行，能够表达复杂的 Agent 工作流，同时保持可控性和可观测性。

图的构建与状态设计
LangGraph 的核心是 StateGraph，它定义了状态的结构和图的拓扑。状态通过 TypeScript 类型或 Zod Schema 定义，在节点间自动传递和更新：


import { StateGraph, Annotation, END, START } from '@langchain/langgraph';
import { ChatOpenAI } from '@langchain/openai';
import { BaseMessage, HumanMessage } from '@langchain/core/messages';

const AgentState = Annotation.Root({
  messages: Annotation<BaseMessage[]>({
    reducer: (a, b) => [...a, ...b],
    default: () => [],
  }),
  currentStep: Annotation<string>({
    reducer: (_, b) => b,
    default: () => 'start',
  }),
  searchResults: Annotation<string[]>({
    reducer: (a, b) => [...a, ...b],
    default: () => [],
  }),
  iterationCount: Annotation<number>({
    reducer: (_, b) => b,
    default: () => 0,
  }),
});

const model = new ChatOpenAI({ modelName: 'gpt-4-turbo' });

const routeNode = async (state: typeof AgentState.State) => {
  const lastMessage = state.messages[state.messages.length - 1];
  const response = await model.invoke([
    {
      role: 'system',
      content: '判断用户请求需要搜索、计算还是直接回答。只回答一个词。',
    },
    lastMessage,
  ]);
  return { currentStep: response.content as string };
};

const searchNode = async (state: typeof AgentState.State) => {
  const query = state.messages[state.messages.length - 1].content;
  const results = [`搜索结果: ${query} 相关信息`];
  return { searchResults: results };
};

const answerNode = async (state: typeof AgentState.State) => {
  const context = state.searchResults.join('\n');
  const response = await model.invoke([{ role: 'system', content: `基于以下信息回答：${context}` }, ...state.messages]);
  return { messages: [response] };
};

const graph = new StateGraph(AgentState)
  .addNode('route', routeNode)
  .addNode('search', searchNode)
  .addNode('answer', answerNode)
  .addEdge(START, 'route')
  .addConditionalEdges('route', (state) => {
    if (state.currentStep.includes('搜索')) return 'search';
    return 'answer';
  })
  .addEdge('search', 'answer')
  .addEdge('answer', END)
  .compile();

const result = await graph.invoke({
  messages: [new HumanMessage('LangGraph 和 LangChain 有什么区别？')],
});
状态设计的关键原则是最小化状态——只在状态中保留节点间需要共享的数据。状态的 reducer 函数定义了如何合并更新，messages 通常使用追加策略，而标量值使用覆盖策略。


检查点与持久化
LangGraph 的检查点机制允许在任意节点保存完整的图状态，支持暂停/恢复、时间回溯和故障恢复。这是构建长时间运行 Agent 的关键能力：


import { MemorySaver } from '@langchain/langgraph';

const checkpointer = new MemorySaver();

const persistentGraph = new StateGraph(AgentState)
  .addNode('route', routeNode)
  .addNode('search', searchNode)
  .addNode('answer', answerNode)
  .addEdge(START, 'route')
  .addConditionalEdges('route', (state) => {
    if (state.currentStep.includes('搜索')) return 'search';
    return 'answer';
  })
  .addEdge('search', 'answer')
  .addEdge('answer', END)
  .compile({ checkpointer });

const config = { configurable: { thread_id: 'user-session-123' } };

const firstResult = await persistentGraph.invoke({ messages: [new HumanMessage('什么是向量数据库？')] }, config);

const secondResult = await persistentGraph.invoke(
  { messages: [new HumanMessage('它和传统数据库有什么区别？')] },
  config,
);

const history = await persistentGraph.getStateHistory(config);
for await (const snapshot of history) {
  console.log(`步骤: ${snapshot.metadata?.step}, 节点: ${snapshot.next}`);
}

人工介入与中断
LangGraph 原生支持人工介入（Human-in-the-Loop），允许在指定节点暂停执行，等待人工审批或修改后继续。这对于高风险操作（如支付、数据删除）至关重要：


const graphWithInterrupt = new StateGraph(AgentState)
  .addNode('analyze', async (state) => {
    const response = await model.invoke(state.messages);
    return { messages: [response], currentStep: 'analyzed' };
  })
  .addNode('execute', async (state) => {
    return { currentStep: 'executed' };
  })
  .addNode('report', async (state) => {
    return { currentStep: 'reported' };
  })
  .addEdge(START, 'analyze')
  .addEdge('analyze', 'execute')
  .addEdge('execute', 'report')
  .addEdge('report', END)
  .compile({
    checkpointer: new MemorySaver(),
    interruptBefore: ['execute'],
  });

const config = { configurable: { thread_id: 'approval-flow-1' } };

const partialResult = await graphWithInterrupt.invoke({ messages: [new HumanMessage('删除所有过期订单')] }, config);

const currentState = await graphWithInterrupt.getState(config);
console.log('等待审批，下一步:', currentState.next);

await graphWithInterrupt.updateState(config, {
  messages: [new HumanMessage('已审批，继续执行')],
});

const finalResult = await graphWithInterrupt.invoke(null, config);
中断机制与检查点协同工作——中断时自动保存状态，恢复时从检查点加载。这使得即使在进程重启后，也能继续执行被中断的工作流。


子图与模块化
复杂的 Agent 系统通常由多个子图组成。LangGraph 支持将子图作为节点嵌入到父图中，实现关注点分离和复用：


const researchSubgraph = new StateGraph(AgentState)
  .addNode('search', searchNode)
  .addNode('summarize', async (state) => {
    const summary = await model.invoke([
      { role: 'system', content: '总结以下搜索结果' },
      { role: 'user', content: state.searchResults.join('\n') },
    ]);
    return { messages: [summary] };
  })
  .addEdge(START, 'search')
  .addEdge('search', 'summarize')
  .addEdge('summarize', END)
  .compile();

const parentGraph = new StateGraph(AgentState)
  .addNode('route', routeNode)
  .addNode('research', researchSubgraph)
  .addNode('answer', answerNode)
  .addEdge(START, 'route')
  .addConditionalEdges('route', (state) => {
    if (state.currentStep.includes('研究')) return 'research';
    return 'answer';
  })
  .addEdge('research', 'answer')
  .addEdge('answer', END)
  .compile();
子图的设计原则是单一职责——每个子图完成一个独立的功能单元（如研究、写作、审核），通过统一的状态接口与父图通信。


小结
    

  • LangGraph 以有向图为核心抽象，支持循环、条件分支和并行，适合复杂的多步骤 Agent 工作流
    • 

  • 状态设计遵循最小化原则，reducer 函数定义更新策略，消息追加、标量覆盖
    • 

  • 检查点机制实现了持久化状态，支持暂停/恢复、时间回溯和故障恢复
    • 

  • 人工介入通过 interruptBefore/interruptAfter 实现，与检查点协同保证流程可靠性
    • 

  • 子图模式实现了关注点分离，每个子图完成独立功能单元，通过状态接口通信
    •
