CrewAI 多代理协作

核心概念

CrewAI 是一个面向多代理协作的框架，它的核心理念是将 AI 应用类比为一个团队（Crew）——每个 Agent 扮演特定角色（Role），拥有明确的目标（Goal）和背景故事（Backstory），通过协作完成复杂任务。这种角色驱动的设计使得非技术人员也能理解和设计 Agent 系统。

Agent 角色定义
CrewAI 的 Agent 由三个核心属性定义：Role 决定了 Agent 的专业身份，Goal 描述了它要达成的目标，Backstory 提供了行为上下文。这种设计让 LLM 能够更好地进入角色：


import { Agent, Task, Crew, Process } from 'crewai';

const researcher = new Agent({
  role: '高级技术研究员',
  goal: '深入研究指定技术主题，产出全面准确的研究报告',
  backstory: `你是一位拥有 10 年经验的技术研究员，擅长从海量信息中
    提取关键洞察。你的研究报告以深度和准确性著称，经常被团队作为
    决策依据。你特别擅长发现技术趋势和潜在风险。`,
  verbose: true,
  allowDelegation: true,
  tools: [searchTool, webScraperTool],
  llm: 'gpt-4-turbo',
  maxIterations: 15,
  memory: true,
});

const dataAnalyst = new Agent({
  role: '数据分析专家',
  goal: '分析研究数据，提供可量化的洞察和可视化建议',
  backstory: `你是一位资深数据分析师，擅长将复杂数据转化为清晰的
    商业洞察。你重视数据的准确性和可复现性，总是附上数据来源和
    分析方法论。`,
  verbose: true,
  tools: [calculatorTool, chartTool],
  llm: 'gpt-4-turbo',
});

const technicalWriter = new Agent({
  role: '技术文档撰写者',
  goal: '将研究成果和分析数据整合为高质量的技术文档',
  backstory: `你是一位经验丰富的技术写作专家，擅长将复杂的技术概念
    转化为清晰易懂的文档。你注重文档的结构性、可读性和实用性。`,
  verbose: true,
  tools: [markdownTool],
  llm: 'gpt-4-turbo',
});
角色设计的关键是职责单一——每个 Agent 只负责一个明确的功能领域。当一个 Agent 的职责过于宽泛时，LLM 的表现往往不如多个专注的 Agent 协作。


任务编排与流程
Task 是 CrewAI 中工作的基本单位。每个 Task 描述了要完成的具体工作、期望输出和分配的 Agent。Crew 则定义了任务的执行流程：


const researchTask = new Task({
  description: `研究 {topic} 的最新发展，包括：
    1. 核心技术原理和最新进展
    2. 主要竞争方案对比
    3. 行业应用案例
    4. 未来发展趋势预测`,
  expectedOutput: '一份结构化的研究报告，包含以上四个维度的详细分析',
  agent: researcher,
  outputFile: 'research-report.md',
});

const analysisTask = new Task({
  description: `基于研究报告，进行深入的数据分析：
    1. 提取关键量化指标
    2. 进行竞品对比矩阵分析
    3. 评估技术成熟度
    4. 风险评估与建议`,
  expectedOutput: '包含数据表格和分析结论的分析报告',
  agent: dataAnalyst,
  context: [researchTask],
});

const writingTask = new Task({
  description: '整合研究和分析成果，产出一份面向技术决策者的综合报告',
  expectedOutput: '一份 3000 字以上的技术评估文档',
  agent: technicalWriter,
  context: [researchTask, analysisTask],
});

const crew = new Crew({
  agents: [researcher, dataAnalyst, technicalWriter],
  tasks: [researchTask, analysisTask, writingTask],
  process: Process.Sequential,
  verbose: true,
  memory: true,
  planning: true,
});

const result = await crew.kickoff({ inputs: { topic: 'RAG 技术' } });

记忆与学习机制
CrewAI 的记忆系统支持短期记忆（当前任务上下文）、长期记忆（跨次运行的经验）和实体记忆（关键信息索引），使 Agent 能够从历史执行中学习和改进：


const crewWithMemory = new Crew({
  agents: [researcher, dataAnalyst],
  tasks: [researchTask, analysisTask],
  process: Process.Sequential,
  memory: true,
  embeddingModel: {
    provider: 'openai',
    config: { model: 'text-embedding-3-small' },
  },
});

const firstRun = await crewWithMemory.kickoff({
  inputs: { topic: 'LLM 微调技术' },
});

const secondRun = await crewWithMemory.kickoff({
  inputs: { topic: 'LLM 推理优化' },
});
长期记忆通过向量数据库存储，Agent 在执行新任务时会自动检索相关的历史经验。这种机制使得 Agent 团队随着使用次数增加而变得更加高效和准确。


生产化与监控
将 CrewAI 部署到生产环境需要关注异步执行、错误恢复和性能监控：


const productionCrew = new Crew({
  agents: [researcher, dataAnalyst, technicalWriter],
  tasks: [researchTask, analysisTask, writingTask],
  process: Process.Hierarchical,
  managerLlm: 'gpt-4-turbo',
  verbose: false,
  maxRpm: 10,
  stepCallback: (step) => {
    console.log(`[${new Date().toISOString()}] Agent: ${step.agent}, 状态: ${step.status}`);
  },
  taskCallback: (task) => {
    console.log(`任务完成: ${task.description.slice(0, 50)}...`);
    console.log(`输出质量评分: ${task.qualityScore || 'N/A'}`);
  },
});

const runWithTimeout = async (crew: Crew, inputs: Record<string, string>, timeoutMs: number) => {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeoutMs);
  try {
    const result = await crew.kickoff({ inputs });
    return { success: true, result };
  } catch (error) {
    return { success: false, error: (error as Error).message };
  } finally {
    clearTimeout(timer);
  }
};
小结
    

  • CrewAI 以角色驱动的方式定义 Agent，通过 Role、Goal、Backstory 三元组实现角色化
    • 

  • 任务编排支持顺序、层级和协商三种流程，通过 context 属性建立任务间依赖
    • 

  • 记忆系统包含短期、长期和实体三个层次，使 Agent 能从历史执行中学习
    • 

  • 生产部署需要关注超时控制、速率限制、回调监控和错误恢复机制
    • 

  • 适合结构化的多步骤任务（如研究报告、内容生产），不适合需要高度灵活性的实时交互场景
    •
