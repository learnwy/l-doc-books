多代理协作模式

核心概念

多代理协作是 AI Agent 系统的核心设计范式，它将复杂任务分解为多个专业化的 Agent 之间的协作。不同的协作模式适用于不同类型的任务，选择正确的模式直接影响系统的效率、质量和可靠性。理解这些模式的本质区别和适用边界是构建高效多代理系统的前提。

管道与流水线模式
管道模式是最直观的多代理协作方式——每个 Agent 处理任务的一个阶段，将结果传递给下一个 Agent。这种模式的优势在于职责清晰、调试简单，缺点是无法回溯和并行：


interface PipelineResult {
  stage: string;
  output: string;
  metadata: Record<string, unknown>;
}

const createPipeline = (
  stages: Array<{
    name: string;
    agent: { invoke: (input: string) => Promise<string> };
    validate?: (output: string) => boolean;
  }>,
) => {
  return async (input: string): Promise<PipelineResult[]> => {
    const results: PipelineResult[] = [];
    let currentInput = input;

    for (const stage of stages) {
      const output = await stage.agent.invoke(currentInput);

      if (stage.validate && !stage.validate(output)) {
        throw new Error(`阶段 ${stage.name} 验证失败`);
      }

      results.push({
        stage: stage.name,
        output,
        metadata: { timestamp: Date.now(), inputLength: currentInput.length },
      });

      currentInput = output;
    }

    return results;
  };
};

const contentPipeline = createPipeline([
  { name: '研究', agent: researchAgent },
  { name: '大纲', agent: outlineAgent },
  { name: '写作', agent: writingAgent },
  {
    name: '审核',
    agent: reviewAgent,
    validate: (output) => output.includes('通过'),
  },
]);
管道模式的一个常见变体是带反馈的管道——当某个阶段的输出不满足质量要求时，回退到上一个阶段重新处理。这需要在管道中引入循环逻辑。


辩论与对抗模式
辩论模式让多个 Agent 从不同角度分析同一个问题，通过论点交锋来提高决策质量。这种模式特别适合需要权衡利弊的技术决策场景：


interface DebateRound {
  proArgument: string;
  conArgument: string;
  round: number;
}

const createDebate = (config: {
  proAgent: { invoke: (input: string) => Promise<string> };
  conAgent: { invoke: (input: string) => Promise<string> };
  judgeAgent: { invoke: (input: string) => Promise<string> };
  maxRounds: number;
}) => {
  return async (topic: string): Promise<string> => {
    const rounds: DebateRound[] = [];
    let context = `辩题：${topic}\n\n`;

    for (let i = 0; i < config.maxRounds; i++) {
      const proPrompt = `${context}作为正方，请提出你的论点（第 ${i + 1} 轮）：`;
      const proArg = await config.proAgent.invoke(proPrompt);
      context += `正方第 ${i + 1} 轮：${proArg}\n\n`;

      const conPrompt = `${context}作为反方，请反驳正方观点并提出你的论点：`;
      const conArg = await config.conAgent.invoke(conPrompt);
      context += `反方第 ${i + 1} 轮：${conArg}\n\n`;

      rounds.push({ proArgument: proArg, conArgument: conArg, round: i + 1 });
    }

    const judgePrompt = `${context}作为裁判，综合双方论点，给出最终判断和建议：`;
    return config.judgeAgent.invoke(judgePrompt);
  };
};

const techDecision = createDebate({
  proAgent: microservicesAdvocate,
  conAgent: monolithAdvocate,
  judgeAgent: architectJudge,
  maxRounds: 3,
});

const verdict = await techDecision('新项目应该使用微服务架构还是单体架构？');
辩论模式的核心价值在于减少单一 Agent 的偏见。单个 LLM 可能倾向于某种观点，而对抗式对话迫使系统考虑多个视角。


层级管理模式
层级模式引入了一个管理者 Agent，负责任务分解、工作分配和质量控制。这种模式模拟了现实中的项目管理结构：


interface SubTask {
  id: string;
  description: string;
  assignee: string;
  priority: 'high' | 'medium' | 'low';
  dependencies: string[];
}

const createHierarchicalSystem = (config: {
  manager: { invoke: (input: string) => Promise<string> };
  workers: Map<string, { invoke: (input: string) => Promise<string> }>;
}) => {
  return async (task: string): Promise<Map<string, string>> => {
    const planPrompt = `将以下任务分解为子任务，为每个子任务指定执行者。
      可用执行者：${[...config.workers.keys()].join('、')}
      任务：${task}
      以 JSON 数组格式输出子任务列表。`;

    const planResult = await config.manager.invoke(planPrompt);
    const subTasks: SubTask[] = JSON.parse(planResult);

    const results = new Map<string, string>();
    const completed = new Set<string>();

    const executeTask = async (subTask: SubTask): Promise<void> => {
      for (const dep of subTask.dependencies) {
        while (!completed.has(dep)) {
          await new Promise((resolve) => setTimeout(resolve, 100));
        }
      }

      const worker = config.workers.get(subTask.assignee);
      if (!worker) throw new Error(`未找到执行者: ${subTask.assignee}`);

      const context = subTask.dependencies.map((dep) => `[${dep}的结果]: ${results.get(dep)}`).join('\n');

      const result = await worker.invoke(`${subTask.description}\n上游依赖结果：\n${context}`);

      results.set(subTask.id, result);
      completed.add(subTask.id);
    };

    const independent = subTasks.filter((t) => t.dependencies.length === 0);
    await Promise.all(independent.map(executeTask));

    const dependent = subTasks.filter((t) => t.dependencies.length > 0);
    await Promise.all(dependent.map(executeTask));

    return results;
  };
};
层级模式的挑战在于管理者 Agent 的质量——如果任务分解不合理或工作分配不当，整个系统的效率会大幅下降。实践中建议为管理者 Agent 提供详细的团队能力描述和历史任务数据。


共识与投票模式
投票模式让多个 Agent 独立处理同一任务，通过投票或加权聚合得出最终结果。这种模式可以显著提高结果的可靠性：


interface VoteResult {
  agent: string;
  answer: string;
  confidence: number;
}

const createVotingSystem = (
  agents: Array<{
    name: string;
    agent: { invoke: (input: string) => Promise<string> };
    weight: number;
  }>,
) => {
  return async (question: string): Promise<string> => {
    const votes: VoteResult[] = await Promise.all(
      agents.map(async ({ name, agent, weight }) => {
        const response = await agent.invoke(`${question}\n请在回答末尾用 [confidence: 0-100] 标注你的信心度。`);
        const confidenceMatch = response.match(/\[confidence:\s*(\d+)\]/);
        return {
          agent: name,
          answer: response.replace(/\[confidence:\s*\d+\]/, '').trim(),
          confidence: (confidenceMatch ? parseInt(confidenceMatch[1]) : 50) * weight,
        };
      }),
    );

    votes.sort((a, b) => b.confidence - a.confidence);

    const synthesisPrompt = `以下是多位专家对问题"${question}"的回答：
      ${votes.map((v) => `${v.agent}（权重分 ${v.confidence}）：${v.answer}`).join('\n\n')}
      请综合以上观点，给出最终答案。优先采纳高权重专家的意见。`;

    return agents[0].agent.invoke(synthesisPrompt);
  };
};
投票模式的效果取决于 Agent 之间的多样性——如果所有 Agent 使用相同的模型和提示，投票结果与单个 Agent 无异。应通过不同的模型、温度参数或提示策略来增加多样性。


小结
    

  • 管道模式适合有明确阶段的任务流，职责清晰但缺乏灵活性
    • 

  • 辩论模式通过对抗性对话减少单一 Agent 偏见，适合技术决策场景
    • 

  • 层级模式模拟项目管理结构，管理者 Agent 的质量决定系统上限
    • 

  • 投票模式通过多样性提高可靠性，关键是确保 Agent 间的差异化
    • 

  • 实际系统往往组合多种模式——如先层级分解再管道执行，辅以投票验证
    • 

  • 选择协作模式时应考虑任务结构、时间约束、质量要求和成本预算
