AutoGen 对话式多代理

核心概念

AutoGen 是微软推出的多代理对话框架，其核心理念是将 Agent 之间的协作建模为多方对话。每个 Agent 既是消息的发送者也是接收者，通过结构化的对话协议完成复杂任务。与 CrewAI 的角色驱动模式不同，AutoGen 更加强调 Agent 之间的动态交互和代码执行能力。

Agent 类型与配置
AutoGen 提供了多种预建 Agent 类型，每种都针对特定的协作场景进行了优化：


import { AssistantAgent, UserProxyAgent, ConversableAgent, GroupChat, GroupChatManager } from 'autogen';

const assistant = new AssistantAgent({
  name: 'tech_expert',
  systemMessage: `你是一位资深全栈工程师，擅长系统设计和代码实现。
    你的回答应该包含具体的代码示例和架构建议。
    当需要验证方案时，主动编写可执行的代码片段。`,
  llmConfig: {
    model: 'gpt-4-turbo',
    temperature: 0.1,
  },
});

const userProxy = new UserProxyAgent({
  name: 'user',
  humanInputMode: 'TERMINATE',
  maxConsecutiveAutoReply: 10,
  codeExecutionConfig: {
    workDir: './workspace',
    useDocker: true,
    timeout: 60,
  },
  isTerminationMsg: (msg) => msg.content?.includes('TERMINATE') ?? false,
});

const codeReviewer = new ConversableAgent({
  name: 'code_reviewer',
  systemMessage: `你是一位严格的代码评审专家。你需要：
    1. 检查代码的正确性和安全性
    2. 评估代码的可维护性和性能
    3. 给出具体的改进建议
    在代码质量达标时回复 "APPROVED"。`,
  llmConfig: { model: 'gpt-4-turbo', temperature: 0 },
});
UserProxyAgent 是 AutoGen 的独特设计——它代表人类用户参与 Agent 对话，可以在需要时请求人工输入，也可以自动代理执行代码。humanInputMode 控制了人工介入的策略：ALWAYS（每轮请求）、TERMINATE（结束时确认）、NEVER（完全自动）。


对话编排与群聊
AutoGen 的群聊（GroupChat）允许多个 Agent 在一个共享对话空间中协作。GroupChatManager 负责决定每轮由哪个 Agent 发言：


const researcher = new AssistantAgent({
  name: 'researcher',
  systemMessage: '你是研究员，负责收集和整理技术资料。搜索完成后总结关键发现。',
  llmConfig: { model: 'gpt-4-turbo' },
});

const architect = new AssistantAgent({
  name: 'architect',
  systemMessage: '你是架构师，负责根据研究结果设计系统方案。产出架构图和技术选型。',
  llmConfig: { model: 'gpt-4-turbo' },
});

const developer = new AssistantAgent({
  name: 'developer',
  systemMessage: '你是开发者，负责将架构方案转化为可执行的代码实现。',
  llmConfig: { model: 'gpt-4-turbo' },
});

const groupChat = new GroupChat({
  agents: [userProxy, researcher, architect, developer, codeReviewer],
  messages: [],
  maxRound: 20,
  speakerSelectionMethod: 'auto',
  allowRepeatSpeaker: false,
});

const manager = new GroupChatManager({
  groupchat: groupChat,
  llmConfig: { model: 'gpt-4-turbo' },
});

await userProxy.initiateChat(manager, {
  message: '设计一个高并发的消息队列系统，支持 100 万 QPS',
});
群聊的发言人选择策略是系统的关键设计点。auto 模式由 LLM 根据对话上下文选择最合适的下一位发言者，round_robin 按顺序轮流，manual 由人工指定。


代码执行沙箱
AutoGen 的代码执行能力是其最显著的差异化特性。Agent 生成的代码可以在安全的沙箱中执行，执行结果作为对话消息反馈给 Agent：


const codingAssistant = new AssistantAgent({
  name: 'coder',
  systemMessage: `你是一位编程专家。遇到需要验证的问题时，
    直接编写代码并请求执行。代码块使用 \`\`\`python 标记。`,
  llmConfig: { model: 'gpt-4-turbo' },
});

const executor = new UserProxyAgent({
  name: 'executor',
  humanInputMode: 'NEVER',
  codeExecutionConfig: {
    workDir: './sandbox',
    useDocker: true,
    timeout: 120,
    lastNMessages: 3,
  },
  defaultAutoReply: '继续执行下一步。如果任务完成，回复 TERMINATE。',
});

await executor.initiateChat(codingAssistant, {
  message: `分析 GitHub API 返回的仓库数据：
    1. 获取 stars 数排名前 10 的 TypeScript 仓库
    2. 计算平均 star 数和中位数
    3. 生成趋势图表并保存为 PNG`,
});

嵌套对话与复杂工作流
AutoGen 支持嵌套对话，一个 Agent 可以在处理消息时发起与其他 Agent 的子对话。这种模式使得构建层次化的多代理系统成为可能：


const plannerAgent = new AssistantAgent({
  name: 'planner',
  systemMessage: '你是项目规划者，将大任务分解为子任务并分配给合适的 Agent。',
  llmConfig: { model: 'gpt-4-turbo' },
});

const registerNestedChats = (agent: ConversableAgent) => {
  agent.registerNestedChat({
    trigger: (msg) => msg.content?.includes('需要研究') ?? false,
    chatConfig: {
      recipient: researcher,
      maxTurns: 5,
      summary: 'last_msg',
    },
  });

  agent.registerNestedChat({
    trigger: (msg) => msg.content?.includes('需要编码') ?? false,
    chatConfig: {
      recipient: developer,
      maxTurns: 10,
      summary: 'reflection_with_llm',
    },
  });
};

registerNestedChats(plannerAgent);

await userProxy.initiateChat(plannerAgent, {
  message: '构建一个 RAG 系统：需要研究最佳实践，然后需要编码实现原型',
});
嵌套对话的设计使得每个子任务都在独立的对话上下文中处理，避免了群聊中上下文过长导致的质量下降。子对话完成后，摘要结果会自动返回到父对话。


小结
    

  • AutoGen 以多方对话为核心模型，Agent 通过消息交互协作，自然支持动态协商
    • 

  • UserProxyAgent 是人机协作的桥梁，支持三种人工介入模式满足不同自动化需求
    • 

  • 群聊机制允许多个专业 Agent 在共享空间中协作，发言人选择策略影响协作质量
    • 

  • 原生代码执行沙箱是 AutoGen 的核心差异化能力，支持生成-执行-反馈的迭代循环
    • 

  • 嵌套对话模式实现了层次化的任务分解，每个子任务在独立上下文中处理避免信息过载
    •
