Agent 扩展与性能优化

核心概念

Agent 系统的扩展面临独特的挑战——LLM 调用的高延迟、不确定的执行时间和高昂的 Token 成本使得传统的 Web 扩展策略不能直接照搬。Agent 扩展需要在三个层面同时优化：推理层（减少 LLM 调用次数和 Token 消耗）、编排层（并行化和缓存）和基础设施层（负载均衡和弹性伸缩）。

语义缓存
语义缓存通过向量相似度判断查询是否可以复用历史结果，避免重复的 LLM 调用。与精确匹配缓存不同，语义缓存能够处理措辞不同但含义相同的查询：


interface CacheEntry {
  query: string;
  embedding: number[];
  response: string;
  timestamp: number;
  hitCount: number;
}

const createSemanticCache = (config: {
  embedModel: { embed: (text: string) => Promise<number[]> };
  similarityThreshold: number;
  maxEntries: number;
  ttlMs: number;
}) => {
  const entries: CacheEntry[] = [];

  const cosineSimilarity = (a: number[], b: number[]): number => {
    let dotProduct = 0;
    let normA = 0;
    let normB = 0;
    for (let i = 0; i < a.length; i++) {
      dotProduct += a[i] * b[i];
      normA += a[i] * a[i];
      normB += b[i] * b[i];
    }
    return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB));
  };

  return {
    get: async (query: string): Promise<string | null> => {
      const queryEmbed = await config.embedModel.embed(query);
      const now = Date.now();

      let bestMatch: CacheEntry | null = null;
      let bestScore = 0;

      for (const entry of entries) {
        if (now - entry.timestamp > config.ttlMs) continue;
        const score = cosineSimilarity(queryEmbed, entry.embedding);
        if (score > config.similarityThreshold && score > bestScore) {
          bestMatch = entry;
          bestScore = score;
        }
      }

      if (bestMatch) {
        bestMatch.hitCount++;
        return bestMatch.response;
      }
      return null;
    },

    set: async (query: string, response: string) => {
      const embedding = await config.embedModel.embed(query);
      if (entries.length >= config.maxEntries) {
        entries.sort((a, b) => a.hitCount - b.hitCount);
        entries.shift();
      }
      entries.push({
        query,
        embedding,
        response,
        timestamp: Date.now(),
        hitCount: 0,
      });
    },
  };
};
语义缓存的关键参数是相似度阈值——设置过低会导致错误命中（返回不相关的缓存结果），设置过高则降低缓存命中率。通常建议从 0.95 开始，根据实际效果逐步调整。


模型路由与降级
模型路由根据查询复杂度自动选择合适的模型，简单查询使用快速便宜的小模型，复杂查询使用能力强但昂贵的大模型：


interface ModelConfig {
  name: string;
  costPerToken: number;
  maxTokens: number;
  avgLatency: number;
  invoke: (messages: Array<{ role: string; content: string }>) => Promise<{ content: string }>;
}

const createModelRouter = (models: { fast: ModelConfig; balanced: ModelConfig; powerful: ModelConfig }) => {
  const classifyComplexity = (query: string): 'simple' | 'medium' | 'complex' => {
    const length = query.length;
    const hasCode = /```/.test(query);
    const hasMultipleQuestions = (query.match(/[？?]/g) ?? []).length > 2;
    const requiresReasoning = /为什么|分析|比较|设计|评估/.test(query);

    if (hasCode || hasMultipleQuestions || (requiresReasoning && length > 200)) {
      return 'complex';
    }
    if (requiresReasoning || length > 100) {
      return 'medium';
    }
    return 'simple';
  };

  return {
    route: async (messages: Array<{ role: string; content: string }>) => {
      const lastMessage = messages[messages.length - 1].content;
      const complexity = classifyComplexity(lastMessage);

      const modelMap = {
        simple: models.fast,
        medium: models.balanced,
        complex: models.powerful,
      };

      const selected = modelMap[complexity];

      try {
        return await selected.invoke(messages);
      } catch {
        if (selected !== models.powerful) {
          return models.powerful.invoke(messages);
        }
        throw new Error('所有模型都不可用');
      }
    },
  };
};
模型路由的核心挑战是复杂度分类的准确性。基于规则的分类器简单但不够准确，可以训练一个轻量级分类模型来提高路由精度。


异步处理与队列
对于耗时较长的 Agent 任务，同步等待会导致连接超时和资源浪费。异步队列模式将任务提交和结果获取分离：


interface AgentJob {
  id: string;
  input: string;
  status: 'pending' | 'processing' | 'completed' | 'failed';
  result?: string;
  error?: string;
  createdAt: number;
  completedAt?: number;
}

const createAgentQueue = (config: { maxConcurrent: number; agent: { invoke: (input: string) => Promise<string> } }) => {
  const jobs = new Map<string, AgentJob>();
  let activeCount = 0;
  const pending: string[] = [];

  const processNext = async () => {
    if (activeCount >= config.maxConcurrent || pending.length === 0) return;

    const jobId = pending.shift()!;
    const job = jobs.get(jobId)!;
    activeCount++;
    job.status = 'processing';

    try {
      job.result = await config.agent.invoke(job.input);
      job.status = 'completed';
    } catch (error) {
      job.error = (error as Error).message;
      job.status = 'failed';
    } finally {
      job.completedAt = Date.now();
      activeCount--;
      processNext();
    }
  };

  return {
    submit: (input: string): string => {
      const id = `job_${Date.now()}_${Math.random().toString(36).slice(2, 8)}`;
      jobs.set(id, { id, input, status: 'pending', createdAt: Date.now() });
      pending.push(id);
      processNext();
      return id;
    },

    getStatus: (id: string): AgentJob | undefined => jobs.get(id),

    getQueueStats: () => ({
      pending: pending.length,
      processing: activeCount,
      total: jobs.size,
    }),
  };
};
流式输出优化
流式输出让用户在 Agent 推理过程中就能看到部分结果，显著改善感知延迟：


const createStreamingAgent = (model: {
  stream: (messages: Array<{ role: string; content: string }>) => AsyncIterable<{ content: string }>;
}) => {
  return async function* (input: string) {
    const messages = [
      { role: 'system' as const, content: '你是一位技术专家' },
      { role: 'user' as const, content: input },
    ];

    let fullResponse = '';
    for await (const chunk of model.stream(messages)) {
      fullResponse += chunk.content;
      yield { type: 'token' as const, content: chunk.content };
    }

    yield { type: 'complete' as const, content: fullResponse };
  };
};

小结
    

  • Agent 扩展需要在推理层、编排层和基础设施层三个层面协同优化
    • 

  • 语义缓存通过向量相似度避免重复 LLM 调用，阈值设置影响准确性和命中率的平衡
    • 

  • 模型路由根据查询复杂度自动选择模型，在成本和质量之间取得平衡
    • 

  • 异步队列将任务提交和结果获取分离，适合处理耗时 Agent 任务
    • 

  • 流式输出是改善用户体验最直接的手段，应在所有对话场景中默认启用
