分块对检索的影响

一个被切坏的边界，不会在切块那一刻报错。它静静潜伏，直到某个用户提问时，检索器召回了半句话、模型据此编出一个听起来合理却错误的答案——这时你才发现问题，却很难一眼看出根源在分块。这一篇把「一次切块」到「最终答案」之间的因果链拆开，让你看清：在分块这一步埋下的隐患，究竟会在流水线的哪一环爆发。它不讲怎么切，只讲切的后果如何传导。

核心概念

分块的影响是沿流水线逐级传导的，每一环都把上一环的缺陷放大或暴露。块边界先决定嵌入向量的质量，嵌入质量决定召回与精确率，召回回来的块是否完整决定模型能否拿到足够上下文，最终决定答案是否正确、是否产生幻觉。这条链是单向的：上游的分块错误，下游任何环节都无法完全弥补。

flowchart TD
  A[块边界划定] --> B[嵌入向量质量<br/>主题纯净度]
  B --> C[召回 Recall<br/>相关块是否被检出]
  B --> D[精确率 Precision<br/>无关块是否混入]
  C --> E[上下文完整性<br/>命中块是否自足]
  D --> E
  E --> F[答案正确性 / 幻觉率]
  F -.切坏的边界在此爆发.-> A

下表把常见的分块缺陷映射到它在哪一环爆发、表现为什么症状。

分块缺陷 爆发环节 可观测症状
块过大、主题混杂 嵌入 → 精确率 召回里混入大量无关内容，精确率低
块过小、上下文不足 上下文完整性 召回率高但答案残缺/答非所问
答案跨边界被腰斩 召回 关键查询召回率骤降，时灵时不灵
重叠过大 精确率 → 上下文 召回多个重复块，挤占名额
边界切断指代/上下文 答案正确性 模型据残缺片段编造，幻觉上升

从块边界到嵌入质量

链条的第一环，是块边界决定嵌入向量「指向哪里」。一个边界若把两个无关主题圈进同一块，嵌入模型只能输出二者的语义平均，向量既不靠近主题 A 也不靠近主题 B；一个边界若把单一主题完整圈住，向量就锐利地落在该主题附近。这一环的质量完全由切块决定，嵌入模型本身无能为力——它只能忠实地编码你交给它的文本，垃圾进则垃圾出。

这里有个容易被忽略的细节：边界还会切断指代与上下文依赖。「它的保修期是两年」这句话，若「它」指代的主语被切到了上一个块，那么这一块的嵌入就丢失了关键语义，向量会落在一个含糊的位置。这正是 元数据与上下文增强 要解决的问题——给每块补回它丢失的文档级上下文。

召回与精确率的此消彼长

嵌入质量定下后，影响传导到检索的两个核心指标。召回率衡量「相关的块有没有被检出」，精确率衡量「检出的块里有多少真相关」。块大小在这两者间制造了一个跷跷板：块越大，单块覆盖的内容越多，相关信息更可能落在某个被召回的块里（召回率升），但每个块也夹带更多无关内容（精确率降）；块越小则相反。

这条规律解释了一个常见的困惑：「我把块调小后召回的命中看起来更准了，但答案反而更差」。原因是小块虽然精确率高，却牺牲了单块的上下文完整性——这是下一环的事。本 hub 在 分块评测 里定义 Recall@k、MRR、nDCG 与端到端正确率如何共同衡量分块，避免只盯一个检索数字。

从上下文完整性到答案正确性

链条的最后两环，是召回回来的块能否让模型答对。即便召回率和精确率都不错，若每个命中块本身上下文残缺——答案的前半句在别的块、关键定义在上一段——模型拿到的就是一堆碎片。此时模型有两种坏结局：要么直说「上下文不足」（好的情况），要么用残缺片段强行补全，编出一个听起来合理的幻觉答案（坏的情况）。

这就是为什么「召回率高」不等于「答案好」。NAACL 2025 对文档检索、证据检索与检索式问答的联合实验显示，语义边界并没有带来一致的下游收益（Qu 等，2025）。这条因果链的实践含义是：评测分块绝不能只看检索指标，必须一路看到端到端的答案质量——这正是 分块评测 强调的原则。而把命中小块替换成其所属大块、从根上解开「召回准但上下文不足」死结的办法，是 父子与窗口检索。

用检索轨迹定位缺陷传播

线上只记录最终答案，会把所有失败都压成一句「模型答错了」。要把根因追到分块，至少要为每次查询保存候选块、排名、分数、原文区间和实际送入模型的上下文。下面的结构把分块边界、检索排序与生成输入串在同一条轨迹里。

type RetrievedChunk = {
  chunkId: string;
  sourceId: string;
  start: number;
  end: number;
  rank: number;
  score: number;
  includedInPrompt: boolean;
};

type RetrievalTrace = {
  queryId: string;
  indexVersion: string;
  chunkerVersion: string;
  candidates: RetrievedChunk[];
  answerSupported: boolean;
};

诊断时按顺序问四个问题：相关证据是否存在于索引；存在的话是否进入候选集；进入候选集后是否排进上下文预算；进入上下文后答案是否仍不受证据支持。第一类通常是摄入或切块遗漏，第二类偏向表示与检索，第三类偏向排序和重复块挤占，第四类才主要指向生成。这个顺序能阻止团队用换模型掩盖上游边界错误。

小结

  • 分块的影响沿单向因果链传导：块边界 → 嵌入质量 → 召回/精确率 → 上下文完整性 → 答案正确性，上游错误下游无法弥补。
  • 块边界决定嵌入指向哪里，还会切断指代与上下文依赖，让向量落在含糊位置。
  • 召回与精确率随块大小此消彼长：大块召回升而精确降，小块相反。
  • 「召回率高」不等于「答案好」——上下文残缺会逼模型产生幻觉，所以评测必须看到端到端答案质量。
