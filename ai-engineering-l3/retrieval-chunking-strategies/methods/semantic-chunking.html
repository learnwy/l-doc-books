语义分块

递归切分在句号处断开，却不知道断开的两句其实在讲同一件事。语义分块（semantic chunking）想修正这一点：它不靠标点，而靠嵌入向量——当相邻句子的语义相似度骤然下降，就认定话题切换、在此划下边界。直觉上这显然更优。但 NAACL 2025 在三类任务上的系统实验给出反直觉结论：额外计算并未换来一致性能收益（Qu 等，2025）。这一篇讲清它的原理、适用边界，以及如何把它扩展到 proposition 与 LLM 引导切分。

核心概念

语义分块把文档先拆成句子，给每句算嵌入向量，再沿文本顺序比较相邻句（或相邻句组）的相似度。相似度高说明仍在同一话题、应留在同一块；相似度低于某阈值说明话题跳转、应在此断开。判定断点的相似度可用余弦相似度 sim(a,b)=a⋅b∥a∥∥b∥\text{sim}(a,b) = \frac{a \cdot b}{\|a\| \|b\|}sim(a,b)=∥a∥∥b∥a⋅b​，断点条件常写成相似度低于某分位数阈值 θ\thetaθ，即 sim(si,si+1)<θ\text{sim}(s_i, s_{i+1}) < \thetasim(si​,si+1​)<θ 时切分。

  A[文档拆成句子] --> B[每句算嵌入向量]
  B --> C[计算相邻句余弦相似度]
  C --> D{相似度 < 阈值?}
  D -->|否, 同话题| E[并入当前块]
  D -->|是, 话题跳转| F[在此切断, 开新块]
  E --> C
  F --> C
  F --> G[语义块输出]
  E --> G

嵌入相似度如何定边界

语义分块的实现有几个关键参数，决定了它切得好不好。第一是比较单位：逐句比较太敏感、噪声大，实践中常把连续 1–3 句作为一个比较窗口（buffer），用窗口的平均向量比相似度，平滑掉单句波动。第二是断点阈值：用绝对阈值难以跨文档通用，更稳的做法是用相似度的百分位数——把全文相邻相似度排序，取低端的某个分位（如第 5 百分位）作为断点，这样阈值自适应每篇文档的相似度分布。

这套机制依赖一个前提：嵌入模型必须能可靠地把「同话题」与「换话题」在向量空间里区分开。这把语义分块的成败直接绑在了嵌入模型质量上——用一个语义分辨力弱的嵌入模型做语义分块，等于用钝刀切边界。阈值还会受到文档体裁影响，同一个绝对值很难同时适合法律条款、聊天记录和技术论文，因此应在每篇文档内使用分位数或经过标注集校准的阈值。

为什么它常常不如想象中好

这是本篇最重要的部分。NAACL 2025 的研究没有得出「语义分块永远更差」，而是更谨慎也更有用的结论：在文档检索、证据检索与检索式答案生成上，语义分块没有提供足够一致的增益来证明其额外成本合理。2026 年复现研究还发现，任务定义会改变赢家：简单结构方法更适合跨语料检索，而 LLM 引导方法可能在文档内定位占优（Beyond Chunk-Then-Embed）。

成本上的代价同样真实：每个句子或句组都要先算嵌入，索引构建时延与调用量都会放大；阈值、缓冲窗口与最小块长又增加了配置面。这意味着它在「质量没有稳定赢、成本确定增加」时不划算。回到 分块对检索的影响 的因果链，语义分块最典型的失败是优化了边界纯净度，却让单块不再自足。

Proposition、LLM 引导与自适应切分

语义分块只决定「在哪里断」，更细粒度的方法会重新定义「什么可以成为检索单位」。Dense X Retrieval 把 proposition 定义为简洁、自足、只表达一个事实的自然语言单元，并展示了它在细粒度检索和给定计算预算的问答中相对 passage 的优势（Chen 等，2024）。代价是必须由生成模型抽取和去指代，索引条目数量也显著上升；因此 proposition 适合事实密集型语料，不适合需要保留论证链或程序结构的内容。

LLM 引导切分则让模型判断逻辑边界。ACL 2025 的 MoC 没有让模型重写整篇文本，而是路由到不同粒度的轻量 chunker，并生成结构化切分规则，试图平衡精度与成本（MoC）。LREC 2026 的 Adaptive Chunking 更进一步：根据引用完整性、块内凝聚度、文档上下文连贯性、区块完整性与大小合规五类文档指标，逐文档选择切法（Adaptive Chunking）。这类方法常被口语化地叫作 agentic chunking，但工程上应拆成三个可观测步骤：分析文档、选择策略、产出边界，而不是把整条摄入链交给一个黑盒代理。

type ChunkStrategy = 'recursive' | 'semantic' | 'proposition' | 'structure';

type DocumentSignals = {
  hasStableHeadings: boolean;
  factDensity: number;
  topicShiftRate: number;
};

function chooseStrategy(signals: DocumentSignals): ChunkStrategy {
  if (signals.hasStableHeadings) return 'structure';
  if (signals.factDensity >= 0.8) return 'proposition';
  if (signals.topicShiftRate >= 0.5) return 'semantic';
  return 'recursive';
}

这段路由不是研究论文的复刻，而是可执行的架构边界：信号计算、策略决策和切分实现可以分别记录版本、分别回放。生产系统还应保留递归基线，并按文档类型分层比较增益；若 proposition 或 LLM 引导切分只提高内在边界分数、却没有提高端到端答案质量，就不应上线。

什么时候语义分块才值得用

语义分块不是没有用武之地，只是用武之地比想象中窄。它适合话题密集交叉、缺乏可靠结构信号的内容：比如一篇在多个主题间频繁跳转、又没有清晰段落或标题结构的长文。即使采用，也应设置最小块长与最大块长，把过短相邻块重新合并，并记录因阈值而产生的边界，避免无法解释。

决策原则很明确：默认保留递归基线，只有当端到端评测显示语义分块的增益确实盖过嵌入调用、索引规模与运维复杂度时，才采用它。怎么做这个评测对比，见 分块评测 与 分块调优。若文档有清晰结构，更该先试成本低得多的 结构感知分块。

小结

  • 语义分块靠嵌入相似度找话题切换点（相邻句相似度 <θ< \theta<θ 即断），用窗口缓冲 + 百分位阈值更稳。
  • 它的成败绑死在嵌入模型的语义分辨力上，是把双刃剑。
  • 同行评审实验显示它没有稳定覆盖额外计算成本；任务类型与文档结构都会改变结论。
  • Proposition、LLM 引导与自适应切分扩展了策略空间，但都必须保留可观测步骤和递归基线。
