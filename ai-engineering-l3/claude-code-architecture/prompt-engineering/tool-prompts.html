工具提示词

工具提示词机制

Claude Code 中的每个工具都可以通过 prompt.ts 文件提供动态系统提示词。这些提示词在每次 API 调用前汇集到系统提示词的末尾，为模型提供工具专属的使用指南。

// src/tools/types.ts — 工具提示词接口（简化）
interface Tool {
  name: string;
  description: string;
  inputSchema: ZodSchema;
  execute: (input: unknown) => Promise<ToolResult>;
  getSystemPrompt?: (ctx: ToolPromptContext) => string;
}

interface ToolPromptContext {
  cwd: string;
  model: string;
  contextWindowSize: number;
  currentTokenUsage: number;
  isCoordinator: boolean;
  agentMode: 'coordinator' | 'specialist' | 'standalone';
  availableTools: string[];
  mcpServers: McpServerInfo[];
}

BashTool 提示词
BashTool 的提示词是最复杂的工具提示词之一，包含工具优先级层次、超时配置、后台任务管理和 git 安全协议。


// src/tools/bash/prompt.ts — BashTool 提示词（简化）
function getBashPrompt(ctx: ToolPromptContext): string {
  const timeoutConfig = getTimeoutConfig(ctx);

  return `## Bash Tool Usage

### Tool Preference Hierarchy
Before using Bash, check if a dedicated tool exists:
- File reading → ReadFileTool
- File editing → FileEditTool
- Code search → GrepTool
- File finding → GlobTool

Only use Bash for operations not covered by dedicated tools.

### Timeout Configuration
- Default timeout: ${timeoutConfig.default}s
- Long-running commands: use \`timeout ${timeoutConfig.long}s\`
- Background tasks: append \`&\` and use \`disown\`

### Background Tasks
\`\`\`bash
# Correct: background task with disown
long_running_command &
disown

# Incorrect: will block the tool
long_running_command
\`\`\`

### Git Safety Protocol
- Always check current branch before operations: \`git branch --show-current\`
- Use \`git stash\` before switching branches
- Prefer \`git diff --stat\` for overview before detailed diffs
- Never force push without explicit user confirmation
- Always use \`--no-edit\` for merge commits in automated flows

### Environment Variables
Available in this session:
- CWD: ${ctx.cwd}
- HOME: \${HOME}
- SHELL: \${SHELL}`;
}


提示： Git 安全协议是 BashTool 提示词的重要组成。Claude Code 曾因为模型在错误分支上执行 git push --force 导致数据丢失，此后添加了完整的 git 操作安全指引。






SkillTool 提示词
SkillTool 的提示词具有独特的预算感知机制——技能列表的长度根据当前 context window 使用情况动态调整。


// src/tools/skill/prompt.ts — SkillTool 提示词（简化）
function getSkillPrompt(ctx: ToolPromptContext): string {
  const skills = discoverAvailableSkills(ctx.cwd);

  const budgetForSkills = Math.floor(ctx.contextWindowSize * 0.01);
  const maxCharsPerEntry = 250;

  const truncatedSkills = skills.map((skill) => ({
    name: skill.name,
    description: truncate(skill.description, maxCharsPerEntry),
    commands: skill.commands?.map((c) => c.name),
  }));

  const skillList = truncatedSkills.map((s) => `- **${s.name}**: ${s.description}`).join('\n');

  const totalChars = skillList.length;
  const truncated = totalChars > budgetForSkills;

  return `## Available Skills
${truncated ? `(Showing top skills, ${skills.length} total)` : ''}

${truncated ? skillList.slice(0, budgetForSkills) + '\n...' : skillList}

### Usage
Use the Skill tool to invoke a skill by name. Skills are pre-built workflows
that can execute multi-step tasks like code review, testing, and deployment.

### Budget Note
Skill listing uses ~1% of context window. Each entry capped at ${maxCharsPerEntry} chars.`;
}

ConfigTool 提示词
ConfigTool 的提示词从 Settings Registry 动态生成，确保模型始终知道当前所有可配置项：


// src/tools/config/prompt.ts — ConfigTool 提示词（简化）
function getConfigPrompt(ctx: ToolPromptContext): string {
  const registry = getSettingsRegistry();
  const settingsDoc = registry.toPrompt();

  return `## Configuration Tool

### Available Settings
${settingsDoc}

### Usage
Use the Config tool to read or modify settings.

\`\`\`
config get <key>      # Read a setting
config set <key> <value>  # Modify a setting
config list           # List all settings
config reset <key>    # Reset to default
\`\`\`

### Scope
Settings have different scopes:
- **global**: Affects all projects (~/.claude/config.json)
- **project**: Affects current project (.claude/config.json)
- **session**: Only affects current session (not persisted)`;
}


提示： ConfigTool 提示词的动态生成确保了 Settings Registry 中新增的配置项自动出现在模型的知识范围内，无需手动更新提示词。






AgentTool 提示词
AgentTool 的提示词最具动态性——它根据当前的 agent 模式（coordinator/specialist/standalone）生成完全不同的内容。


// src/tools/agent/prompt.ts — AgentTool 提示词（简化）
function getAgentPrompt(ctx: ToolPromptContext): string {
  if (ctx.agentMode === 'coordinator') {
    return buildCoordinatorPrompt(ctx);
  } else if (ctx.agentMode === 'specialist') {
    return buildSpecialistPrompt(ctx);
  }
  return buildStandalonePrompt(ctx);
}

function buildCoordinatorPrompt(ctx: ToolPromptContext): string {
  return `## Agent Tool (Coordinator Mode)

You are operating as a **coordinator**. You can fork specialist agents to handle subtasks.

### Fork Capability
- Use Agent tool to create specialist agents for focused subtasks
- Each specialist has its own context window and tool access
- Specialists report back results to you

### Agent Definitions
Available agent types:
- **code-writer**: Focused on code generation and editing
- **researcher**: Focused on reading and analyzing code
- **tester**: Focused on running and analyzing tests
- **reviewer**: Focused on code review and quality

### Coordination Strategy
1. Break complex tasks into focused subtasks
2. Assign each subtask to the appropriate specialist
3. Synthesize results from all specialists
4. Make final decisions based on specialist reports`;
}

function buildSpecialistPrompt(ctx: ToolPromptContext): string {
  return `## Agent Tool (Specialist Mode)

You are operating as a **specialist** agent. Focus on your assigned task.

### Constraints
- Complete your assigned task and report results
- Do not fork additional agents
- Stay focused on the specific subtask
- Report blockers clearly if encountered`;
}

function buildStandalonePrompt(ctx: ToolPromptContext): string {
  return `## Agent Tool (Standalone Mode)

Use the Agent tool to delegate complex subtasks to a separate agent instance.

### When to Use
- Task requires isolated context (won't pollute main conversation)
- Task is well-defined and can run independently
- You need to parallelize multiple independent subtasks

### How It Works
- Each agent gets its own context window
- Agent inherits your tools and permissions
- Results are returned as a summary`;
}

FileEditTool 与提示词组装
FileEditTool 的提示词较为简短，主要强调三条编辑最佳实践：编辑前先读取文件、做最小化修改、使用 SEARCH/REPLACE 模式精确定位。


当多个工具提供提示词时，按注册优先级排序后组装。优先级排列：BashTool (100) > AgentTool (90) > SkillTool (80) > ConfigTool (70) > FileEditTool (60)。其余工具默认优先级 50。assembleToolPrompts() 函数收集所有工具的 getSystemPrompt() 输出，排序后 join 到系统提示词末尾。




小结
    

  • 每个工具通过 prompt.ts 提供动态系统提示词，接收 ToolPromptContext 获取运行时上下文。
    • 

  • BashTool 提示词最复杂，包含工具优先级层次、超时配置、后台任务规则和 Git 安全协议。
    • 

  • SkillTool 的预算感知机制将技能列表限制在 context window 的 1%，每条目最多 250 字符。
    • 

  • ConfigTool 从 Settings Registry 动态生成配置项列表，确保模型始终知道最新可配置项。
    • 

  • AgentTool 根据 agent 模式（coordinator/specialist/standalone）生成完全不同的提示词。
    • 

  • 工具提示词按注册优先级排序后合并到系统提示词末尾，BashTool 优先级最高。
