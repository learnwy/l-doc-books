系统提示词架构

提示词总览

src/constants/prompts.ts（914 行）是 Claude Code 系统提示词的核心定义文件。系统提示词由 9 个以上的段落组成，每个段落承担特定的指令职责。段落的排列顺序经过精心设计，确保模型能正确理解指令优先级。

// src/constants/prompts.ts — 系统提示词构建（简化）
function buildSystemPrompt(config: PromptConfig): string {
  const sections: PromptSection[] = [
    { id: 'intro', content: buildIntroSection() },
    { id: 'identity', content: buildIdentitySection() },
    { id: 'owasp', content: buildOWASPSection() },
    { id: 'system', content: buildSystemSection(config) },
    { id: 'tools', content: buildToolsSection(config) },
    { id: 'permissions', content: buildPermissionsSection(config) },
    { id: 'doing-tasks', content: buildDoingTasksSection() },
    { id: 'actions', content: buildActionsSection() },
    { id: 'using-tools', content: buildUsingToolsSection() },
    { id: 'tone-and-style', content: buildToneSection() },
    { id: 'output-efficiency', content: buildOutputEfficiencySection() },
  ];

  const staticContent = sections.map((s) => s.content).join('\n\n');

  return staticContent + '\n\n' + SYSTEM_PROMPT_DYNAMIC_BOUNDARY;
}

function buildOWASPSection(): string {
  return `# Security Guidelines (OWASP-aligned)

## Injection Prevention
- Never execute user-provided strings directly as code without validation
- Sanitize file paths to prevent directory traversal
- Validate tool inputs against expected schemas

## Data Protection
- Never log, display, or transmit API keys, tokens, or credentials
- When reading files, check for sensitive patterns before displaying
- Redact secrets from command outputs

## Output Validation
- Verify generated code doesn't introduce known vulnerability patterns
- Check for hardcoded credentials in generated code
- Validate URLs and file paths before use`;
}

软件工程指导段落
doing-tasks 是系统提示词中最长的段落（约 150 行），包含了 Claude Code 作为编程助手的核心行为指南：


// src/constants/prompts.ts — doing-tasks 段落（简化）
function buildDoingTasksSection(): string {
  return `# Doing Tasks

## Software Engineering Best Practices
- Always read existing code before making changes to understand conventions
- Follow the existing code style: indentation, naming, imports, patterns
- Never assume a library is available — check package.json/Cargo.toml first
- Write code that handles errors properly
- Add appropriate type annotations in TypeScript projects
- Use existing utilities and helpers when available

## File Operations
- Read files before editing them
- Make minimal, focused changes
- Preserve existing formatting and style
- When creating new files, match patterns from similar existing files

## Testing
- Never assume specific test framework — check project configuration
- Run tests after making changes when possible
- Verify builds succeed after code changes

## Version Control
- Make atomic, focused changes
- Don't modify unrelated files
- Respect .gitignore patterns`;
}


工具使用优先级段落
// src/constants/prompts.ts — using-tools 段落（简化）
function buildUsingToolsSection(): string {
  return `# Using Tools

## Tool Selection Priority
When multiple tools could accomplish a task, prefer dedicated tools over Bash:

1. **FileEditTool** over sed/awk/perl for file editing
2. **ReadFileTool** over cat/head/tail for file reading
3. **GrepTool** over grep/rg for searching
4. **GlobTool** over find/ls for file finding
5. **AgentTool** for complex multi-step subtasks
6. **BashTool** as last resort for operations not covered by dedicated tools

## Bash Safety
- Always use absolute paths or verify CWD
- Quote variables and filenames
- Prefer non-destructive operations
- Use git for version control before destructive changes`;
}


提示： 工具优先级设计的核心目的是安全性和可控性。专用工具有更严格的输入验证和更精确的权限控制，而 BashTool 的攻击面最大。






静态/动态分界线
SYSTEM_PROMPT_DYNAMIC_BOUNDARY 是一个关键的分隔标记，将系统提示词分为可缓存的静态部分和每轮变化的动态部分。


// src/constants/prompts.ts — 分界线设计（简化）
const SYSTEM_PROMPT_DYNAMIC_BOUNDARY =
  '\n═══════════════════════════════════════\n' +
  'DYNAMIC CONTEXT (changes per turn)\n' +
  '═══════════════════════════════════════\n';

function buildDynamicSections(config: DynamicPromptConfig): string {
  const parts: string[] = [];

  if (config.sessionGuidance) {
    parts.push(`## Session Guidance\n${config.sessionGuidance}`);
  }

  if (config.memoryContent) {
    parts.push(`## Memory\n${config.memoryContent}`);
  }

  parts.push(`## Environment\n${buildEnvInfo(config)}`);

  if (config.language) {
    parts.push(`## Language\nRespond in: ${config.language}`);
  }

  if (config.mcpInstructions) {
    parts.push(`## MCP Servers\n${config.mcpInstructions}`);
  }

  if (config.tokenBudget) {
    parts.push(`## Token Budget\nRemaining budget: ~${config.tokenBudget} tokens. Be concise.`);
  }

  if (config.briefMode) {
    parts.push(`## Brief Mode\nProvide shorter responses. Skip explanations unless asked.`);
  }

  return parts.join('\n\n');
}

完整提示词组装
将静态和动态部分组合，一个完整的系统提示词结构如下：


// src/query/QueryEngine.ts — 提示词组装（简化）
class QueryEngine {
  private buildFullSystemPrompt(): SystemPrompt {
    const staticPrompt = buildSystemPrompt(this.config);

    const dynamicConfig: DynamicPromptConfig = {
      sessionGuidance: this.config.sessionGuidance,
      memoryContent: this.memoryContent,
      language: this.config.responseLanguage,
      mcpInstructions: this.mcpManager?.getInstructions(),
      tokenBudget: this.getRemainingBudget(),
      briefMode: this.config.briefMode,
    };
    const dynamicPrompt = buildDynamicSections(dynamicConfig);

    const toolPrompts = this.tools
      .filter((t) => t.getSystemPrompt)
      .map((t) => t.getSystemPrompt!(this.createToolPromptContext()));

    return {
      content: [staticPrompt, dynamicPrompt, ...toolPrompts].join('\n\n'),
      cacheBreakpoints: this.calculateCacheBreakpoints(),
    };
  }
}


小结
    

  • 系统提示词由 9+ 段落组成（914 行），按指令优先级精确排列：身份 → 安全 → 框架 → 工程 → 工具 → 风格。
    • 

  • OWASP 安全指令覆盖注入防御、数据保护和输出验证三大安全领域。
    • 

  • doing-tasks 段落（~150 行）包含完整的软件工程最佳实践指导。
    • 

  • 工具使用优先级明确：专用工具 > BashTool，核心目的是安全性和可控性。
    • 

  • SYSTEM_PROMPT_DYNAMIC_BOUNDARY 将提示词分为**静态（~80%）和动态（~20%）**两部分，静态部分可被 API 缓存。
    • 

  • 完整提示词 = 静态段落 + 动态段落 + 工具提示词，总量约 3500+ tokens。
