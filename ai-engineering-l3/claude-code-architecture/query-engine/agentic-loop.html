Agentic Loop 智能体循环

queryLoop 概览

src/query/query.ts（1728 行）包含 Claude Code 最核心的函数 queryLoop()。它实现了一个 while(true) 循环，每次迭代执行一次 API 调用和后续的工具执行。循环直到模型返回 end_turn（无工具调用）或触发停止条件时才终止。

// src/query/query.ts — queryLoop 主结构（简化）
async function* queryLoop(params: QueryLoopParams): AsyncGenerator<SDKMessage> {
  const { messages, config, usage, stopHooks } = params;

  while (true) {
    await preCallCompaction(messages, config);

    const response = yield* callAPI(messages, config);

    updateUsage(usage, response.usage);

    yield* processAssistantResponse(response, messages);

    if (response.stop_reason === 'end_turn') {
      const shouldContinue = await runStopHooks(stopHooks, messages);
      if (!shouldContinue) break;
    }

    if (response.stop_reason === 'tool_use') {
      yield* executeTools(response.tool_calls, messages, config);
      continue;
    }

    if (response.stop_reason === 'max_tokens') {
      yield* handleMaxTokens(messages, config);
      continue;
    }
  }
}

状态转换与 Reason Code
每次循环迭代都伴随状态转换，通过 reason code 追踪转换原因：


// src/query/query.ts — 状态转换跟踪（简化）
type TransitionReason =
  | 'tool_execution'
  | 'max_tokens_escalation'
  | 'max_tokens_recovery'
  | 'reactive_compact'
  | 'stop_hook_continue'
  | 'budget_exceeded'
  | 'max_turns_reached'
  | 'error_recovery';

interface LoopState {
  iteration: number;
  lastReason: TransitionReason | null;
  consecutiveMaxTokens: number;
  compactCount: number;
  errorCount: number;
  startTime: number;
}

function trackTransition(state: LoopState, reason: TransitionReason): void {
  state.iteration++;
  state.lastReason = reason;

  if (reason === 'max_tokens_escalation') {
    state.consecutiveMaxTokens++;
  } else {
    state.consecutiveMaxTokens = 0;
  }

  if (reason === 'reactive_compact') {
    state.compactCount++;
  }
}

预调用压缩
每次 API 调用前，preCallCompaction() 执行三层渐进式压缩：


// src/query/query.ts — 预调用压缩（简化）
async function preCallCompaction(messages: SDKMessage[], config: QueryConfig): Promise<void> {
  snipCompact(messages);

  applyCachedMicrocompaction(messages);

  if (feature('CONTEXT_COLLAPSE')) {
    const tokenCount = estimateTokens(messages);
    const threshold = config.contextWindow * 0.7;

    if (tokenCount > threshold) {
      projectedCollapseView(messages, {
        recentWindowSize: config.recentWindowSize,
        drainTracking: config.drainTracking,
      });
    }
  }
}

工具执行引擎
当模型返回 tool_use 类型的 content blocks 时，executeTools() 负责并行执行这些工具。


// src/query/query.ts — 工具执行（简化）
async function* executeTools(
  toolCalls: ToolUseBlock[],
  messages: SDKMessage[],
  config: QueryConfig,
): AsyncGenerator<SDKMessage> {
  const executor = new StreamingToolExecutor({
    tools: config.tools,
    permissionManager: config.permissionManager,
    maxConcurrency: config.maxToolConcurrency,
  });

  const results = executor.executeAll(toolCalls);

  for await (const result of results) {
    const toolResultMessage: SDKMessage = {
      type: 'tool_result',
      tool_use_id: result.toolUseId,
      content: result.output,
      is_error: result.isError,
      timestamp: Date.now(),
    };

    messages.push(toolResultMessage);
    yield toolResultMessage;
  }
}
StreamingToolExecutor
// src/streaming/StreamingToolExecutor.ts — 并行执行器（简化）
class StreamingToolExecutor {
  private concurrencyLimiter: Semaphore;

  constructor(private config: ExecutorConfig) {
    this.concurrencyLimiter = new Semaphore(config.maxConcurrency);
  }

  async *executeAll(toolCalls: ToolUseBlock[]): AsyncGenerator<ToolResult> {
    const promises = toolCalls.map((call) =>
      this.concurrencyLimiter.acquire().then(async (release) => {
        try {
          const result = await this.executeSingle(call);
          return result;
        } finally {
          release();
        }
      }),
    );

    for (const promise of promises) {
      yield await promise;
    }
  }

  private async executeSingle(call: ToolUseBlock): Promise<ToolResult> {
    const tool = this.config.tools.get(call.name);
    if (!tool) {
      return { toolUseId: call.id, output: `Unknown tool: ${call.name}`, isError: true };
    }

    const permitted = await this.config.permissionManager.check(call);
    if (!permitted) {
      return { toolUseId: call.id, output: 'Permission denied', isError: true };
    }

    return tool.execute(call.input);
  }
}


提示： StreamingToolExecutor 使用信号量（Semaphore）控制并发度。默认 maxConcurrency 为 4，防止同时执行过多工具（特别是 BashTool）导致系统资源耗尽。






错误恢复与 Stop Hooks
queryLoop 内置了多种错误恢复机制。prompt-too-long (413) 触发 reactiveCompact()——紧急压缩消息列表后继续循环。max_tokens 触发升级策略——首次翻倍 maxOutputTokens，连续 2 次后切换到多轮恢复模式。

Stop Hooks 在模型返回 end_turn 时执行，决定是否真正停止循环。每个 StopHook 的 check() 方法返回 { shouldContinue, appendMessage? }。如果 shouldContinue 为 true，可选地追加一条 user 消息（如"请修复测试失败"）并继续循环。




提示： Stop hooks 常用于自动化场景。例如，一个 hook 可以检查测试是否通过，如果没有则追加"请修复测试失败"的消息并继续循环。






小结
    

  • queryLoop() 是 1728 行的 while(true) 循环，每次迭代执行一次 API 调用 + 工具执行。
    • 

  • 通过 8 种 reason code 追踪状态转换，支持连续错误计数和自动恢复策略。
    • 

  • 预调用压缩在每次 API 调用前执行 snip → micro → collapse 三层渐进式压缩，无需额外 API 调用。
    • 

  • StreamingToolExecutor 使用信号量控制工具并发执行，默认最多 4 个工具并行。
    • 

  • 内置 prompt-too-long 紧急压缩和 max_tokens 升级两种关键错误恢复策略。
    • 

  • Stop hooks 在 end_turn 时验证是否应真正停止，支持自动化场景的条件继续。
