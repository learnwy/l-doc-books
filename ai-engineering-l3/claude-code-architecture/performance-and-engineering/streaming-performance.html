流式性能

AsyncGenerator 驱动的流式架构

Claude Code 的核心数据流全部基于 AsyncGenerator 模式，从 API 查询到消息提交、从重试逻辑到工具执行，AsyncGenerator 是统一的流式原语。

async function* query(messages: Message[], options: QueryOptions): AsyncGenerator<SDKMessage> {
  const stream = await apiClient.messages.create({
    model: options.model,
    messages,
    stream: true,
    max_tokens: options.maxTokens,
  });

  for await (const event of stream) {
    yield event;
  }
}

async function* submitMessage(userMessage: string, conversation: Conversation): AsyncGenerator<SDKMessage> {
  const messages = [...conversation.messages, { role: 'user', content: userMessage }];

  yield* withRetry(function* () {
    yield* query(messages, conversation.options);
  });
}

async function* withRetry<T>(fn: () => AsyncGenerator<T>, maxRetries = 3): AsyncGenerator<T | RetryEvent> {
  let attempt = 0;

  while (attempt <= maxRetries) {
    try {
      yield* fn();
      return;
    } catch (error) {
      attempt++;
      if (attempt > maxRetries) throw error;
      yield { type: 'retry', attempt, error } as RetryEvent;
      await sleep(Math.pow(2, attempt) * 1000);
    }
  }
}

提示： AsyncGenerator 的关键优势是组合性。withRetry 可以包装任何 AsyncGenerator，submitMessage 可以 yield* 任何子生成器。这种模式避免了回调地狱和 Promise 链的复杂性。






StreamingToolExecutor
StreamingToolExecutor 在 API 流式响应还未完成时就开始执行工具调用，实现流与执行的重叠。


class StreamingToolExecutor {
  private pendingTools: Map<string, ToolCall> = new Map();
  private executing: Map<string, Promise<ToolResult>> = new Map();

  processStreamEvent(event: SDKMessage): void {
    if (event.type === 'content_block_start' && event.content_block.type === 'tool_use') {
      this.pendingTools.set(event.content_block.id, {
        id: event.content_block.id,
        name: event.content_block.name,
        input: '',
      });
    }

    if (event.type === 'content_block_delta' && event.delta.type === 'input_json_delta') {
      const tool = this.pendingTools.get(event.index_id);
      if (tool) tool.input += event.delta.partial_json;
    }

    if (event.type === 'content_block_stop') {
      const tool = this.pendingTools.get(event.content_block_id);
      if (tool) {
        this.startExecution(tool);
        this.pendingTools.delete(tool.id);
      }
    }
  }

  private startExecution(tool: ToolCall): void {
    const parsedInput = JSON.parse(tool.input);
    const promise = executeTool(tool.name, parsedInput);
    this.executing.set(tool.id, promise);
  }

  async collectResults(): Promise<Map<string, ToolResult>> {
    const results = new Map<string, ToolResult>();
    for (const [id, promise] of this.executing) {
      results.set(id, await promise);
    }
    return results;
  }
}

空闲看门狗
流式传输可能因网络问题而停滞，空闲看门狗检测并处理这种情况。


interface IdleWatchdog {
  reset(): void;
  stop(): void;
}

function createIdleWatchdog(timeout: number, onIdle: () => void): IdleWatchdog {
  let timer: ReturnType<typeof setTimeout> | null = null;

  function reset(): void {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      onIdle();
    }, timeout);
  }

  function stop(): void {
    if (timer) {
      clearTimeout(timer);
      timer = null;
    }
  }

  reset();
  return { reset, stop };
}

async function* queryWithWatchdog(messages: Message[], options: QueryOptions): AsyncGenerator<SDKMessage> {
  const watchdog = createIdleWatchdog(options.idleTimeout ?? 30_000, () => {
    throw new Error('Stream idle timeout');
  });

  try {
    for await (const event of query(messages, options)) {
      watchdog.reset();
      yield event;
    }
  } finally {
    watchdog.stop();
  }
}

默认值
说明





idleTimeout

throw

提示： 空闲看门狗每收到一个流事件就重置定时器。如果在超时时间内没有收到任何事件，则认为流已停滞并触发错误，由上层 withRetry 处理重试。






非流式降级
当流式传输遇到不可恢复的错误时，自动降级为非流式请求。


async function* queryWithFallback(messages: Message[], options: QueryOptions): AsyncGenerator<SDKMessage> {
  try {
    yield* queryWithWatchdog(messages, options);
  } catch (error) {
    if (isStreamError(error)) {
      const response = await apiClient.messages.create({
        model: options.model,
        messages,
        stream: false,
        max_tokens: options.maxTokens,
      });

      yield { type: 'message_start', message: response };
      for (const block of response.content) {
        yield { type: 'content_block_start', content_block: block };
        yield { type: 'content_block_stop' };
      }
      yield { type: 'message_stop' };
    } else {
      throw error;
    }
  }
}


分块响应解析
工具结果采用渐进式解析，在数据到达时逐步渲染。


async function* parseToolResultChunked(result: ToolResult): AsyncGenerator<RenderedChunk> {
  if (result.content.length === 0) {
    yield { type: 'empty', text: '(no output)' };
    return;
  }

  for (const item of result.content) {
    if (item.type === 'text') {
      const lines = item.text.split('\n');
      const CHUNK_SIZE = 50;

      for (let i = 0; i < lines.length; i += CHUNK_SIZE) {
        const chunk = lines.slice(i, i + CHUNK_SIZE).join('\n');
        yield { type: 'text-chunk', text: chunk, progress: (i + CHUNK_SIZE) / lines.length };
      }
    } else if (item.type === 'image') {
      yield { type: 'image', data: item.data, mimeType: item.mimeType };
    }
  }
}

帧率调度与流式渲染
终端 UI 在流式场景下的帧率控制尤为重要，避免每个 stream event 都触发渲染。


function createStreamRenderer(screen: Screen): StreamRenderer {
  let pendingContent = '';
  let frameRequested = false;

  function appendContent(text: string): void {
    pendingContent += text;

    if (!frameRequested) {
      frameRequested = true;
      requestAnimationFrame(() => {
        frameRequested = false;
        flushContent();
      });
    }
  }

  function flushContent(): void {
    if (pendingContent) {
      screen.write(pendingContent);
      pendingContent = '';
    }
  }

  return { appendContent, flush: flushContent };
}


提示： 在 API 流式响应的高频场景下（每秒数十个事件），不合并渲染会导致终端频繁刷新。帧率调度将多次 append 合并为单次 write，大幅减少终端 I/O 开销。






FPS 指标追踪
context/fpsMetrics.tsx 在流式场景下持续追踪帧率，用于检测和诊断性能问题。


function useFPSMonitor(): FPSReport {
  const { metrics, recordFrame } = useFPSMetrics();

  useEffect(() => {
    const interval = setInterval(() => {
      recordFrame();
    }, 33);

    return () => clearInterval(interval);
  }, [recordFrame]);

  return {
    fps: metrics.currentFPS,
    dropped: metrics.droppedFrames,
    isHealthy: metrics.currentFPS >= 20,
  };
}

小结
    

  • AsyncGenerator 是 Claude Code 的统一流式原语，query、submitMessage、withRetry 都基于此模式。
    • 

  • StreamingToolExecutor 在 API 流式响应未完成时就开始执行工具，实现流与执行的并行重叠。
    • 

  • 空闲看门狗检测流式传输停滞，30 秒无新事件即触发错误，由 withRetry 处理重试。
    • 

  • 流错误时自动降级为非流式请求，将非流式结果模拟为流式事件保持上层逻辑一致。
    • 

  • 帧率调度将高频 stream 事件合并为单次终端写入，FPS 监控持续追踪渲染健康度。
