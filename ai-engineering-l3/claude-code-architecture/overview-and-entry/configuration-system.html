配置系统

配置优先级链

Claude Code 采用多层配置源设计，每一层可以覆盖更低优先级层的值。优先级从高到低依次为：环境变量 > CLI 参数 > 项目配置 > 用户配置 > MDM 托管配置 > 默认值。

// src/state/config.ts — 配置加载（简化）
interface ConfigSource {
  name: string;
  priority: number;
  load: () => Promise<Record<string, unknown>>;
}

const configSources: ConfigSource[] = [
  { name: 'env', priority: 100, load: loadEnvConfig },
  { name: 'cli', priority: 90, load: loadCLIConfig },
  { name: 'project', priority: 70, load: loadProjectConfig },
  { name: 'user', priority: 50, load: loadUserConfig },
  { name: 'mdm', priority: 30, load: loadMDMConfig },
  { name: 'defaults', priority: 0, load: loadDefaults },
];

async function resolveConfig(): Promise<AppConfig> {
  const layers: Record<string, unknown>[] = [];

  const sorted = configSources.sort((a, b) => a.priority - b.priority);
  for (const source of sorted) {
    layers.push(await source.load());
  }

  return mergeConfigs(layers);
}

环境变量配置
Claude Code 支持大量环境变量来覆盖默认行为：


// src/state/env-config.ts — 环境变量映射（简化）
interface EnvMapping {
  envKey: string;
  configKey: string;
  type: 'string' | 'number' | 'boolean' | 'json';
  sensitive?: boolean;
}

const ENV_MAPPINGS: EnvMapping[] = [
  { envKey: 'ANTHROPIC_API_KEY', configKey: 'apiKey', type: 'string', sensitive: true },
  { envKey: 'CLAUDE_MODEL', configKey: 'model', type: 'string' },
  { envKey: 'CLAUDE_MAX_TURNS', configKey: 'maxTurns', type: 'number' },
  { envKey: 'CLAUDE_BUDGET', configKey: 'budget', type: 'number' },
  { envKey: 'CLAUDE_PERMISSION_MODE', configKey: 'permissionMode', type: 'string' },
  { envKey: 'CLAUDE_VERBOSE', configKey: 'verbose', type: 'boolean' },
  { envKey: 'CLAUDE_MCP_CONFIG', configKey: 'mcpConfig', type: 'json' },
  { envKey: 'AWS_REGION', configKey: 'awsRegion', type: 'string' },
  { envKey: 'AWS_PROFILE', configKey: 'awsProfile', type: 'string' },
  { envKey: 'GCP_PROJECT', configKey: 'gcpProject', type: 'string' },
  { envKey: 'ANTHROPIC_BASE_URL', configKey: 'baseUrl', type: 'string' },
];

function loadEnvConfig(): Record<string, unknown> {
  const config: Record<string, unknown> = {};
  for (const mapping of ENV_MAPPINGS) {
    const value = process.env[mapping.envKey];
    if (value !== undefined) {
      config[mapping.configKey] = coerce(value, mapping.type);
    }
  }
  return config;
}

项目配置与用户配置
项目配置存储在项目根目录的 .claude/config.json 中，用户配置存储在 ~/.claude/config.json。


// src/state/project-config.ts — 项目配置（简化）
import { z } from 'zod';

const ProjectConfigSchema = z.object({
  model: z.string().optional(),
  maxTurns: z.number().optional(),
  permissions: z
    .object({
      allowedTools: z.array(z.string()).optional(),
      deniedTools: z.array(z.string()).optional(),
      mode: z.enum(['default', 'plan', 'bypassPermissions']).optional(),
    })
    .optional(),
  mcp: z
    .object({
      servers: z
        .record(
          z.object({
            command: z.string(),
            args: z.array(z.string()).optional(),
            env: z.record(z.string()).optional(),
          }),
        )
        .optional(),
    })
    .optional(),
  hooks: z
    .object({
      preToolExecution: z.array(z.string()).optional(),
      postToolExecution: z.array(z.string()).optional(),
      preApiCall: z.array(z.string()).optional(),
    })
    .optional(),
});

type ProjectConfig = z.infer<typeof ProjectConfigSchema>;

async function loadProjectConfig(): Promise<ProjectConfig> {
  const configPath = path.join(process.cwd(), '.claude', 'config.json');
  if (!(await exists(configPath))) return {};

  const raw = JSON.parse(await readFile(configPath, 'utf-8'));
  return ProjectConfigSchema.parse(raw);
}


提示： .claude/config.json 适合提交到版本控制中，供团队共享。而 ~/.claude/config.json 是个人配置，不应提交。






Feature Flag 双轨机制
Claude Code 的 feature flag 系统由构建时和运行时两个层面组成。


构建时：feature() 宏
// 构建时 feature — 由 Bun define 替换
if (feature('CONTEXT_COLLAPSE')) {
  await enableContextCollapse();
}
// 若 CONTEXT_COLLAPSE = false，整块代码在构建时被消除
运行时：GrowthBook
// src/state/feature-flags.ts — 运行时 feature flag（简化）
import { GrowthBook } from '@growthbook/growthbook';

let gb: GrowthBook;

async function initFeatureFlags(config: AppConfig): Promise<void> {
  gb = new GrowthBook({
    apiHost: 'https://cdn.growthbook.io',
    clientKey: config.growthbookKey,
    attributes: {
      userId: config.userId,
      version: VERSION,
      os: process.platform,
      provider: config.provider,
    },
  });

  await gb.init({ timeout: 3000 });
}

function isFeatureEnabled(key: string): boolean {
  return gb.isOn(key);
}

function getFeatureValue<T>(key: string, fallback: T): T {
  return gb.getFeatureValue(key, fallback);
}

globalConfig 持久化
全局配置通过 globalConfig 模块管理，持久化到 ~/.claude.json。


// src/state/global-config.ts — 全局配置管理（简化）
import { readFileSync, writeFileSync } from 'node:fs';

interface GlobalConfig {
  userId: string;
  analyticsConsent: boolean;
  preferredModel: string;
  theme: 'auto' | 'light' | 'dark';
  sessions: SessionRecord[];
  costs: CostRecord[];
  oauthTokens: Record<string, OAuthToken>;
  migrationState: Record<string, boolean>;
  mcpServers: Record<string, McpServerConfig>;
}

const CONFIG_PATH = path.join(os.homedir(), '.claude.json');

function readGlobalConfig(): GlobalConfig {
  try {
    return JSON.parse(readFileSync(CONFIG_PATH, 'utf-8'));
  } catch {
    return createDefaultGlobalConfig();
  }
}

function writeGlobalConfig(config: GlobalConfig): void {
  writeFileSync(CONFIG_PATH, JSON.stringify(config, null, 2));
}

function updateGlobalConfig(updater: (config: GlobalConfig) => GlobalConfig): void {
  const current = readGlobalConfig();
  const updated = updater(current);
  writeGlobalConfig(updated);
}

Settings Registry 与配置验证
Claude Code 使用 SettingsRegistry 集中管理所有可配置项。每个 SettingDefinition 声明 key、类型、默认值、作用域（global/project/session）以及可选的 envKey 和 cliFlag 映射。registry.get(key) 按优先级链自动解析值。


toPrompt() 方法为 ConfigTool 动态生成配置列表提示词，确保模型始终知道最新可配置项。


所有配置在合并后通过 Zod schema 验证，AppConfigSchema.safeParse() 返回详细的字段级错误信息。




提示： Settings Registry 的 toPrompt() 和 Zod 验证形成闭环——Registry 定义配置项 → Zod 验证配置值 → toPrompt() 将可配置项暴露给模型。






小结
    

  • 配置系统采用 六层优先级链：环境变量 > CLI > 项目配置 > 用户配置 > MDM > 默认值，高优先级覆盖低优先级。
    • 

  • Feature flag 采用双轨机制：构建时 feature() 宏实现死代码消除，运行时 GrowthBook 支持灰度发布和 A/B 测试。
    • 

  • 持久化分三层：全局（~/.claude.json）、项目级（~/.claude/projects/<hash>/）和项目共享（.claude/config.json）。
    • 

  • 所有配置通过 Zod schema 验证，确保类型安全和完整的错误提示。
    • 

  • Settings Registry 集中管理所有可配置项，支持动态生成提示词和多来源解析。
