Part II · Agent EngineeringClaude Code 架构解析 简介总览与启动流程 简介项目结构

项目结构

Monorepo 目录布局

Claude Code 采用典型的 TypeScript Monorepo 结构，核心代码集中在 src/ 目录下。整个项目由 30 多个子目录组成，每个子目录对应一个功能域。以下是完整的目录地图：

src/
├── main.tsx              # 入口文件（4684 行）
├── constants/            # 常量定义（提示词、模型、限制）
├── tools/                # 工具注册与实现（Bash/FileEdit/Agent 等）
├── services/             # 核心服务（API 调用、认证、成本追踪）
├── state/                # 状态管理（会话、配置、权限）
├── memdir/               # 记忆目录系统（CLAUDE.md 管理）
├── ink/                  # 终端 UI 组件（React + Ink）
├── skills/               # 技能系统（捆绑技能 + 自定义技能）
├── plugins/              # 插件体系（内置插件 + 外部插件）
├── bridge/               # 远程桥接（SSH/WebSocket 通信）
├── query/                # 查询引擎与对话循环
├── commands/             # 斜杠命令注册
├── entrypoints/          # 多入口（CLI/REPL/headless/assistant）
├── hooks/                # 生命周期钩子
├── permissions/          # 权限管控体系
├── utils/                # 工具函数
├── mcp/                  # MCP 客户端与服务端
├── analytics/            # 分析与遥测
├── auth/                 # OAuth 认证
├── compact/              # 上下文压缩
├── context/              # 上下文注入
├── diff/                 # 文件差异处理
├── file-edit/            # 文件编辑引擎
├── git/                  # Git 操作封装
├── markdown/             # Markdown 渲染
├── messages/             # 消息类型定义
├── prompt-cache/         # 提示词缓存检测
├── streaming/            # 流式处理
├── telemetry/            # OpenTelemetry 集成
└── terminal/             # 终端管理
目录 文件数量级 核心职责 关键文件
tools/ 30+ 所有工具实现 BashTool.ts, FileEditTool.ts, AgentTool.ts
services/ 15+ API 客户端、成本追踪 claude.ts, cost-tracker.ts
query/ 10+ 对话循环核心 QueryEngine.ts, query.ts
ink/ 40+ 终端 UI 组件 App.tsx, REPL.tsx, Message.tsx
constants/ 10+ 提示词与配置 prompts.ts, models.ts
compact/ 8+ 上下文压缩 compact.ts, snip.ts, microcompact.ts
mcp/ 10+ MCP 协议集成 McpClient.ts, McpToolAdapter.ts

提示： src/main.tsx 单文件超过 4600 行，是整个项目最大的文件。它不仅是入口点，还包含了大量启动逻辑、迁移代码和 feature-gated 分支。

构建系统

Claude Code 使用 Bun 作为构建工具和运行时，替代了传统的 tsc + webpack/esbuild 方案。

// build.ts — 构建配置（简化）
import { build } from 'bun';

await build({
  entrypoints: ['src/main.tsx'],
  outdir: './dist',
  target: 'node',
  define: {
    'feature("CONTEXT_COLLAPSE")': 'true',
    'feature("MCP_V2")': 'true',
    'feature("DEEP_LINK")': 'false',
  },
  minify: true,
  sourcemap: 'external',
});

feature() 宏与死代码消除

Claude Code 使用自定义的 feature() 宏实现构建时的条件编译。Bun 的 define 选项将 feature() 调用替换为布尔字面量，随后的 tree-shaking 阶段自动消除不可达代码。

// src/utils/feature.ts
declare function feature(name: string): boolean;

// 使用方式 — 构建时解析
if (feature('CONTEXT_COLLAPSE')) {
  const { collapseContext } = await import('./compact/collapse');
  await collapseContext(messages);
}

// 构建后（feature 为 false 时）—— 整块 if 被消除
// （空）
机制 触发时机 粒度 典型用途
feature() 宏 构建时 代码块级 实验性功能开关
define 替换 Bun build 表达式级 环境常量注入
tree-shaking 构建时 模块/函数级 未使用代码消除
GrowthBook 运行时 请求级 A/B 测试、灰度发布 


提示： feature() 宏只在构建时生效，不会出现在运行时代码中。如果你在源码中搜索 feature( 调用，可以追踪所有实验性功能的入口。

API 客户端：Anthropic SDK
// src/services/claude.ts — API 客户端工厂（简化）
import Anthropic from '@anthropic-ai/sdk';
import { AnthropicBedrock } from '@anthropic-ai/bedrock-sdk';
import { AnthropicVertex } from '@anthropic-ai/vertex-sdk';

type ClientProvider = 'direct' | 'bedrock' | 'vertex' | 'foundry';

function createClient(provider: ClientProvider): Anthropic {
  switch (provider) {
    case 'direct':
      return new Anthropic({ apiKey: getApiKey() });
    case 'bedrock':
      return new AnthropicBedrock({ region: getAwsRegion() });
    case 'vertex':
      return new AnthropicVertex({ projectId: getGcpProject() });
    case 'foundry':
      return createFoundryClient();
  }
}

构建产物与分发
Claude Code 的构建产物是单个 JavaScript bundle 文件，通过 npm 分发。


// package.json（关键字段简化）
{
  "name": "@anthropic-ai/claude-code",
  "bin": { "claude": "./dist/cli.js" },
  "files": ["dist/"],
  "engines": { "node": ">=18.0.0" },
  "scripts": {
    "build": "bun run build.ts",
    "typecheck": "tsc --noEmit",
    "lint": "eslint src/"
  }
}

小结
    

  • Claude Code 采用 Monorepo 结构，src/ 下 30+ 子目录按功能域划分，main.tsx 是 4684 行的超大入口文件。
    • 

  • 构建系统基于 Bun，通过自定义 feature() 宏实现构建时条件编译，配合 tree-shaking 实现死代码消除。
    • 

  • Commander.js 提供类型安全的 CLI 框架，React + Ink 实现终端 UI，Anthropic SDK 支持四种 API 提供商。
    • 

  • 最终构建产物为单 bundle 文件，通过 npm 分发，支持 Node.js 18+ 运行时。
