CLI 参数解析
启动的第一步是通过 Commander.js 解析命令行参数。Claude Code 支持丰富的 CLI 选项：


// src/main.tsx — CLI 定义（简化）
import { Command } from 'commander';

const program = new Command()
  .name('claude')
  .argument('[prompt...]', '初始提示词')
  .option('-p, --print', '非交互模式')
  .option('--model <model>', '模型名称')
  .option('--max-turns <n>', '最大轮次', parseInt)
  .option('--output-format <format>', '输出格式: text|json|stream-json')
  .option('--allowedTools <tools...>', '允许的工具列表')
  .option('--permission-mode <mode>', '权限模式: default|plan|bypassPermissions')
  .option('--resume <id>', '恢复会话 ID')
  .option('--continue', '继续上次会话')
  .option('--verbose', '详细日志')
  .option('--dangerously-skip-permissions', '跳过所有权限检查');

const options = program.parse().opts();


提示： --dangerously-skip-permissions 是一个危险选项，仅用于 CI/CD 环境。在交互模式下使用会弹出明确的警告提示。






同步迁移
CLI 解析完成后，Claude Code 会执行 11 个同步迁移任务，确保本地数据结构与当前版本兼容。


// src/main.tsx — 迁移执行（简化）
interface Migration {
  id: string;
  description: string;
  run: () => Promise<void>;
}

const migrations: Migration[] = [
  { id: 'v1_config_location', description: '迁移配置文件位置', run: migrateConfigLocation },
  { id: 'v2_memory_format', description: '升级记忆文件格式', run: migrateMemoryFormat },
  { id: 'v3_permission_schema', description: '权限 schema 升级', run: migratePermissions },
  { id: 'v4_cost_tracking', description: '成本追踪字段添加', run: migrateCostTracking },
  { id: 'v5_session_format', description: '会话格式标准化', run: migrateSessionFormat },
  { id: 'v6_tool_permissions', description: '工具权限细化', run: migrateToolPermissions },
  { id: 'v7_mcp_config', description: 'MCP 配置结构更新', run: migrateMcpConfig },
  { id: 'v8_worktree_paths', description: '工作树路径规范化', run: migrateWorktreePaths },
  { id: 'v9_analytics_consent', description: '分析同意字段', run: migrateAnalyticsConsent },
  { id: 'v10_skill_discovery', description: '技能发现格式', run: migrateSkillDiscovery },
  { id: 'v11_global_config_keys', description: '全局配置键重命名', run: migrateGlobalConfigKeys },
];

async function runMigrations(): Promise<void> {
  const completed = readMigrationState();
  for (const migration of migrations) {
    if (!completed.has(migration.id)) {
      await migration.run();
      markMigrationComplete(migration.id);
    }
  }
}
迁移状态持久化到 ~/.claude/migrations.json，确保每个迁移只执行一次。




Feature-Gated 重写
迁移完成后，Claude Code 检查 feature flag 来决定是否将控制流重写到特殊入口点。


// src/main.tsx — Feature-gated 重写（简化）
if (feature('SSH_BRIDGE') && isSSHSession()) {
  const { runBridge } = await import('./bridge/ssh-bridge');
  await runBridge(options);
  process.exit(0);
}

if (feature('ASSISTANT_MODE') && options.assistant) {
  const { runAssistant } = await import('./entrypoints/assistant');
  await runAssistant(options);
  process.exit(0);
}

if (feature('DEEP_LINK') && hasDeepLinkArgs()) {
  const { handleDeepLink } = await import('./entrypoints/deep-link');
  await handleDeepLink(options);
  process.exit(0);
}

init() 阶段
init() 是核心初始化函数，负责构建运行时所需的所有服务实例。


// src/main.tsx — init()（简化）
async function init(options: CLIOptions): Promise<AppContext> {
  const config = await loadConfig(options);

  const apiClient = createClient(config.provider);

  const queryEngine = new QueryEngine({
    client: apiClient,
    model: config.model,
    maxTokens: config.maxTokens,
    tools: await discoverTools(config),
    systemPrompt: await buildSystemPrompt(config),
  });

  const permissionManager = new PermissionManager({
    mode: config.permissionMode,
    allowedTools: config.allowedTools,
    deniedTools: config.deniedTools,
  });

  const costTracker = new CostTracker({
    budget: config.budget,
    sessionId: config.sessionId,
  });

  return {
    config,
    queryEngine,
    permissionManager,
    costTracker,
    apiClient,
  };
}

setup() 阶段
setup() 在 init() 返回的 AppContext 基础上完成运行时环境准备。


// src/main.tsx — setup()（简化）
async function setup(ctx: AppContext): Promise<void> {
  assertNodeVersion('>=18.0.0');

  process.chdir(ctx.config.cwd || process.cwd());

  if (ctx.config.useWorktree) {
    await createWorktree(ctx);
  }

  ctx.fileWatcher = new FileWatcher({
    root: process.cwd(),
    ignore: ctx.config.watchIgnore,
  });
  ctx.fileWatcher.start();

  await initAnalytics(ctx.config);

  await prefetchApiKey(ctx.apiClient);

  await validatePermissions(ctx.permissionManager);

  await discoverMcpServers(ctx);

  await loadMemoryFiles(ctx);
}


提示： prefetchApiKey() 会在后台异步验证 API Key 的有效性。如果 Key 无效，不会在 setup 阶段报错，而是在第一次 API 调用时抛出认证错误。






运行模式分支
setup() 完成后，根据 CLI 参数决定进入哪种运行模式：


// src/main.tsx — 模式分支（简化）
async function start(ctx: AppContext, options: CLIOptions): Promise<void> {
  if (options.print || options.outputFormat) {
    await runHeadless(ctx, options);
    return;
  }

  if (options.resume) {
    await resumeSession(ctx, options.resume);
  } else if (options.continue) {
    await continueLastSession(ctx);
  }

  await runREPL(ctx, options);
}

小结
    

  • main.tsx 是 4684 行的超大入口文件，包含六个启动阶段：CLI 解析 → 同步迁移 → feature-gated 重写 → init → setup → 模式启动。
    • 

  • 11 个同步迁移确保本地数据与当前版本兼容，迁移状态持久化到 ~/.claude/migrations.json。
    • 

  • Feature-gated 重写在正常初始化前检查 SSH/Assistant/Deep-Link 三种特殊入口，命中则直接转入对应模块。
    • 

  • init() 构建核心服务实例（QueryEngine、PermissionManager、CostTracker），setup() 完成运行时环境准备（Node 检查、文件监听、MCP 发现、记忆加载）。
    • 

  • 支持四种运行模式：REPL（默认交互）、Headless（CI/CD）、Resume（恢复会话）和 Continue（继续上次）。
