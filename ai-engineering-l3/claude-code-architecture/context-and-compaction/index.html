上下文管理与压缩 简介

上下文管理是 Claude Code 能够处理长时间复杂对话的关键。随着对话推进，消息列表不断增长，最终会逼近甚至超出模型的上下文窗口限制。Claude Code 设计了一套四层渐进式压缩架构来应对这一挑战，每一层在压缩力度、计算成本和信息保真度之间取得不同的平衡。

本章将逐层剖析这套压缩系统的设计：

上下文窗口策略首先建立全局视角，解析四层压缩架构（snip → microcompact → context collapse → auto-compact）的触发条件、执行时机和相互关系。

Snip 与 Microcompact深入两种无 API 调用开销的轻量级压缩——snip compact 移除旧 tool_result 内容，microcompact 应用缓存的字段级压缩。两者在每次 API 调用前自动执行。

Auto Compact分析 LLM 驱动的完整对话摘要——触发条件（阈值或 413 错误）、摘要生成流程、原始消息替换策略，以及 reactive compact 的紧急压缩机制。

Context Collapse讲解 feature-gated 的投影式折叠——如何在不调用 LLM 的情况下将旧消息折叠为最小存根，以及 drain 策略如何在模型需要时逐步展开折叠内容。

建议按顺序阅读，从全局策略概览开始，逐步深入每种压缩机制的实现细节。
