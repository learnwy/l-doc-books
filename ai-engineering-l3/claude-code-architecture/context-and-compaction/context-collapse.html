Context Collapse 上下文坍缩

Feature-Gated 设计

Context Collapse 是四层压缩架构的第三层，位于 microcompact 和 auto compact 之间。它通过 feature("CONTEXT_COLLAPSE") 宏控制，在构建时决定是否编入产物。这一设计反映了它的实验性质——Context Collapse 是一种创新但尚在验证的压缩策略。

// src/query/query.ts — Feature gate 检查（简化）
async function preCallCompaction(messages: SDKMessage[], config: QueryConfig): Promise<void> {
  snipCompact(messages);
  applyCachedMicrocompaction(messages);

  if (feature('CONTEXT_COLLAPSE')) {
    const tokenCount = estimateTokens(messages);
    if (tokenCount > config.contextWindow * config.collapseThreshold) {
      projectedCollapseView(messages, config.collapseConfig);
    }
  }
}

提示： Context Collapse 的核心价值是"在不调用 LLM 的前提下实现显著的上下文缩减"。它填补了 microcompact（低力度）和 auto compact（高成本）之间的空白。






投影式折叠
Context Collapse 的核心机制是投影式折叠（projected collapse）。它不修改消息的实际内容，而是创建一个"折叠视图"——旧消息只保留最小化的元数据存根，最近的消息保持完整。


// src/compact/collapse.ts — 投影式折叠（简化）
interface CollapseConfig {
  recentWindowSize: number;
  minStubSize: number;
  drainTracking: DrainTracker;
}

interface CollapsedView {
  stubs: MessageStub[];
  fullMessages: SDKMessage[];
  totalTokensSaved: number;
}

function projectedCollapseView(messages: SDKMessage[], config: CollapseConfig): void {
  const splitPoint = messages.length - config.recentWindowSize;
  if (splitPoint <= 0) return;

  for (let i = 0; i < splitPoint; i++) {
    if (isAlreadyCollapsed(messages[i])) continue;

    const stub = collapseToStub(messages[i], config.minStubSize);
    const originalContent = messages[i].content;

    messages[i] = {
      ...messages[i],
      content: stub.content,
      metadata: {
        ...messages[i].metadata,
        collapsed: true,
        originalContentHash: hashContent(originalContent),
        originalTokenCount: estimateTokens(originalContent),
        stubTokenCount: estimateTokens(stub.content),
      },
    };
  }
}
消息折叠规则
不同类型的消息有不同的折叠策略：


// src/compact/collapse.ts — 折叠规则（简化）
function collapseToStub(message: SDKMessage, minSize: number): MessageStub {
  switch (message.type) {
    case 'assistant':
      return {
        content: collapseAssistant(message),
        type: 'assistant_stub',
      };

    case 'tool_use':
      return {
        content: `[Tool: ${message.tool_name}(${summarizeInput(message.tool_input)})]`,
        type: 'tool_use_stub',
      };

    case 'tool_result':
      const status = message.is_error ? 'error' : 'success';
      return {
        content: `[Result: ${status}]`,
        type: 'tool_result_stub',
      };

    case 'user':
      return {
        content: `[User: ${truncate(extractText(message.content), 100)}]`,
        type: 'user_stub',
      };

    default:
      return {
        content: `[${message.type}]`,
        type: 'generic_stub',
      };
  }
}

function collapseAssistant(message: SDKMessage): string {
  const textBlocks = extractTextBlocks(message.content);
  const toolUseBlocks = extractToolUseBlocks(message.content);

  const parts: string[] = [];

  if (textBlocks.length > 0) {
    parts.push(`[说明: ${truncate(textBlocks[0].text, 80)}]`);
  }

  if (toolUseBlocks.length > 0) {
    const toolNames = toolUseBlocks.map((b) => b.name).join(', ');
    parts.push(`[调用: ${toolNames}]`);
  }

  return parts.join(' ');
}

Drain 策略
Context Collapse 的一个关键创新是 drain 策略——当模型在后续对话中需要更多上下文时，可以逐步"排水"（展开）折叠的消息。


// src/compact/collapse.ts — Drain 策略（简化）
interface DrainTracker {
  drainRequests: DrainRequest[];
  maxDrainPerTurn: number;
  totalDrained: number;
}

interface DrainRequest {
  messageIndex: number;
  reason: string;
  requestedAt: number;
}

function processDrainRequests(messages: SDKMessage[], tracker: DrainTracker): number {
  const toProcess = tracker.drainRequests.slice(0, tracker.maxDrainPerTurn);

  let drainedCount = 0;

  for (const request of toProcess) {
    const msg = messages[request.messageIndex];
    if (!msg?.metadata?.collapsed) continue;

    const originalHash = msg.metadata.originalContentHash;
    const original = retrieveOriginalContent(originalHash);

    if (original) {
      messages[request.messageIndex] = {
        ...msg,
        content: original,
        metadata: {
          ...msg.metadata,
          collapsed: false,
          drainedAt: Date.now(),
        },
      };
      drainedCount++;
    }
  }

  tracker.totalDrained += drainedCount;
  tracker.drainRequests = tracker.drainRequests.slice(toProcess.length);

  return drainedCount;
}
Drain 触发检测
// src/compact/collapse.ts — Drain 触发检测（简化）
function detectDrainTriggers(assistantResponse: SDKMessage, messages: SDKMessage[]): DrainRequest[] {
  const requests: DrainRequest[] = [];
  const responseText = extractText(assistantResponse.content);

  const referencePatterns = [
    /之前(的|提到的|看过的)(.{0,20})(文件|代码|输出)/g,
    /earlier (file|code|output|result)/gi,
    /refer back to/gi,
    /as (mentioned|shown|discussed) (earlier|before|above)/gi,
  ];

  for (const pattern of referencePatterns) {
    if (pattern.test(responseText)) {
      const candidates = findCollapsedCandidates(messages, responseText);
      requests.push(
        ...candidates.map((idx) => ({
          messageIndex: idx,
          reason: 'model_reference',
          requestedAt: Date.now(),
        })),
      );
    }
  }

  return requests;
}

折叠 vs 压缩 的权衡
Context Collapse 和 Auto Compact 代表了两种不同的信息处理哲学：


// 折叠：保留原始内容的引用，可逆
const collapsed = {
  content: '[说明: 分析了项目结构] [调用: ReadFileTool]',
  metadata: {
    collapsed: true,
    originalContentHash: 'abc123', // 可以恢复
  },
};

// 压缩：生成摘要，不可逆
const compacted = {
  content: '[Conversation Summary]\n分析了项目的目录结构...',
  metadata: {
    compacted: true,
    removedCount: 50, // 原始消息已丢失
  },
};

原始内容存储与控制流
折叠消息的原始内容存储在 CollapseContentStore 中——一个 FIFO Map，默认最多缓存 50 条。当存储满时，最早折叠的消息原始内容被淘汰，drain 将无法恢复这些消息。这是折叠策略"逐渐退化为不可逆"的设计。

完整控制流：Token 估算 → 超过 70% 则分割消息 → 折叠旧消息为存根 → 保存原始到 Store → API 调用 → 检测 drain 触发 → 展开指定消息 → 下一轮。




提示： 原始内容存储有大小限制。当存储满时，最早折叠的消息无法通过 drain 恢复。在超长对话中，早期的折叠消息实质上已变为不可逆压缩。






小结
    

  • Context Collapse 通过 feature("CONTEXT_COLLAPSE") 构建时门控，反映其实验性质。
    • 

  • 核心机制是投影式折叠——不修改原始内容，而是将旧消息替换为最小化存根。
    • 

  • 不同消息类型有不同的折叠策略：assistant 保留意图摘要，tool_result 仅保留成功/失败状态。
    • 

  • Drain 策略是关键创新——通过检测模型引用旧内容的模式，逐步展开折叠消息。
    • 

  • 原始内容存储在 FIFO 缓存（默认 50 条）中，超出后逐渐退化为不可逆折叠。
    • 

  • 执行速度 <5ms、零 API 成本，填补了 microcompact 和 auto compact 之间的空白。
