Snip 与 Microcompact

Snip Compact

Snip compact 是四层压缩架构的第一层，也是最轻量的压缩操作。它通过移除旧的 tool_result 消息中的具体输出内容，替换为简短的存根（stub），来释放 token 空间。

// src/compact/snip.ts — Snip Compact 实现（简化）
interface SnipConfig {
  keepRecentResults: number;
  stubTemplate: string;
}

function snipCompact(
  messages: SDKMessage[],
  config: SnipConfig = { keepRecentResults: 3, stubTemplate: '[output snipped]' },
): void {
  const toolResults = messages.map((msg, index) => ({ msg, index })).filter(({ msg }) => msg.type === 'tool_result');

  if (toolResults.length <= config.keepRecentResults) return;

  const toSnip = toolResults.slice(0, -config.keepRecentResults);

  for (const { msg, index } of toSnip) {
    if (isAlreadySnipped(msg)) continue;

    const originalSize = getContentSize(msg.content);
    messages[index] = {
      ...msg,
      content: config.stubTemplate,
      metadata: {
        ...msg.metadata,
        snipped: true,
        originalSize,
        snippedAt: Date.now(),
      },
    };
  }
}

提示： Snip compact 只影响 tool_result 类型的消息，不会修改 assistant 或 user 消息。这确保了对话的语义结构完整——模型仍然知道工具被调用过，只是看不到具体输出了。






就地修改策略
Snip compact 直接修改 messages 数组中的元素（就地修改），而不是创建新数组：


// src/compact/snip.ts — 就地修改（简化）
function snipCompact(messages: SDKMessage[]): void {
  // 直接修改 messages[index]，不创建新数组
  for (const { index } of toSnip) {
    messages[index] = { ...messages[index], content: '[output snipped]' };
    // messages 数组引用不变，外部持有者自动看到变更
  }
}

Microcompact
Microcompact 是第二层压缩，使用预先缓存的压缩规则对消息的特定字段进行压缩。与 snip 不同，microcompact 保留消息的结构，只压缩冗余字段。


// src/compact/microcompact.ts — Microcompact 实现（简化）
interface MicrocompactRule {
  messageType: SDKMessageType;
  field: string;
  condition: (value: unknown) => boolean;
  compress: (value: unknown) => unknown;
}

const RULES: MicrocompactRule[] = [
  {
    messageType: 'tool_result',
    field: 'content',
    condition: (v) => typeof v === 'string' && v.length > 1000,
    compress: (v) => truncateMiddle(v as string, 500, '[...truncated...]'),
  },
  {
    messageType: 'assistant',
    field: 'content',
    condition: (v) => Array.isArray(v) && hasLargeTextBlock(v),
    compress: (v) => compressTextBlocks(v as ContentBlock[]),
  },
  {
    messageType: 'tool_result',
    field: 'content',
    condition: (v) => typeof v === 'string' && isRepeatedPattern(v),
    compress: (v) => deduplicateLines(v as string),
  },
];

function applyCachedMicrocompaction(messages: SDKMessage[]): void {
  for (let i = 0; i < messages.length; i++) {
    const msg = messages[i];
    if (msg.metadata?.microcompacted) continue;

    for (const rule of RULES) {
      if (msg.type !== rule.messageType) continue;
      const value = getField(msg, rule.field);
      if (rule.condition(value)) {
        setField(messages[i], rule.field, rule.compress(value));
        messages[i] = {
          ...messages[i],
          metadata: { ...messages[i].metadata, microcompacted: true },
        };
      }
    }
  }
}
压缩规则详解
// src/compact/microcompact.ts — 中间截断（简化）
function truncateMiddle(text: string, maxLength: number, placeholder: string): string {
  if (text.length <= maxLength) return text;
  const halfLength = Math.floor((maxLength - placeholder.length) / 2);
  return text.slice(0, halfLength) + placeholder + text.slice(-halfLength);
}

// 重复行去重
function deduplicateLines(text: string): string {
  const lines = text.split('\n');
  const seen = new Set<string>();
  const result: string[] = [];
  let duplicateCount = 0;

  for (const line of lines) {
    if (seen.has(line.trim()) && line.trim().length > 0) {
      duplicateCount++;
      continue;
    }
    seen.add(line.trim());
    result.push(line);
  }

  if (duplicateCount > 0) {
    result.push(`[${duplicateCount} duplicate lines removed]`);
  }

  return result.join('\n');
}

缓存机制
Microcompact 的"缓存"体现在 metadata.microcompacted 标记——一旦消息被压缩，后续循环迭代不会重复处理。


// src/compact/microcompact.ts — 缓存检查（简化）
function applyCachedMicrocompaction(messages: SDKMessage[]): void {
  for (let i = 0; i < messages.length; i++) {
    // 缓存命中：已经压缩过的消息直接跳过
    if (messages[i].metadata?.microcompacted) continue;

    // 缓存未命中：执行压缩规则
    applyRules(messages, i);
  }
}


Snip + Micro 的协同
Snip 和 Microcompact 在 preCallCompaction() 中按顺序执行，形成互补：


// src/query/query.ts — 协同执行（简化）
async function preCallCompaction(messages: SDKMessage[], config: QueryConfig): Promise<void> {
  // 第一步：Snip 移除完全不需要的旧输出
  snipCompact(messages, {
    keepRecentResults: config.snipKeepRecent ?? 3,
  });

  // 第二步：Micro 压缩剩余的可压缩内容
  applyCachedMicrocompaction(messages);
}

提示： Snip 和 Microcompact 的总耗时通常不超过 10ms，即使在千条消息的长对话中。相比之下，一次 API 调用的延迟通常在 1-10 秒。这就是"能不调 API 就不调"原则的性能基础。






小结
    

  • Snip compact 移除旧 tool_result 的完整内容，替换为 [output snipped] 存根，保留最近 3 条。
    • 

  • Microcompact 在字段级别压缩：超过 1000 字符的内容中间截断，重复行去重，大文本块压缩。
    • 

  • 两者按顺序执行：Snip 先删除不需要的旧输出，Micro 再压缩剩余的冗余内容。
    • 

  • 都采用就地修改策略，O(1) 额外内存，通过 metadata 标记避免重复处理。
    • 

  • 总耗时通常 <10ms，与 API 调用的 1-10 秒延迟相比可忽略不计。
