Auto Compact 自动压缩

触发条件

Auto Compact 是四层压缩架构的第四层，也是唯一需要调用 LLM 的压缩操作。它有两种触发方式：主动触发（上下文使用超过 90%）和被动触发（API 返回 413 prompt-too-long 错误）。

// src/compact/compact.ts — 触发逻辑（简化）
interface CompactTrigger {
  type: 'threshold' | 'reactive' | 'manual';
  tokenCount: number;
  contextWindow: number;
  error?: Error;
}

function shouldAutoCompact(messages: SDKMessage[], config: CompactConfig): CompactTrigger | null {
  const tokenCount = estimateTokens(messages);
  const ratio = tokenCount / config.contextWindow;

  if (ratio >= config.compactThreshold) {
    return {
      type: 'threshold',
      tokenCount,
      contextWindow: config.contextWindow,
    };
  }

  return null;
}

function createReactiveTrigger(error: Error): CompactTrigger {
  return {
    type: 'reactive',
    tokenCount: -1,
    contextWindow: -1,
    error,
  };
}

提示： Reactive compact 是一种"保险机制"。由于 token 估算有 ±15% 的误差，有时候预估没超过阈值但实际已经超了。413 错误触发 reactive compact 后，系统会立即压缩并重试 API 调用。






摘要生成流程
Auto compact 的核心是调用 LLM 对完整对话生成摘要：


// src/compact/compact.ts — 摘要生成（简化）
interface CompactResult {
  summary: string;
  preservedMessages: SDKMessage[];
  removedCount: number;
  tokensSaved: number;
}

async function generateCompactSummary(messages: SDKMessage[], config: CompactConfig): Promise<CompactResult> {
  const recentCount = config.keepRecentMessages ?? 5;
  const oldMessages = messages.slice(0, -recentCount);
  const recentMessages = messages.slice(-recentCount);

  const summaryPrompt = buildSummaryPrompt(oldMessages, config.customPrompt);

  const response = await config.client.messages.create({
    model: config.compactModel ?? config.model,
    max_tokens: 4096,
    system: COMPACT_SYSTEM_PROMPT,
    messages: [{ role: 'user', content: summaryPrompt }],
  });

  const summary = extractTextContent(response.content);

  return {
    summary,
    preservedMessages: recentMessages,
    removedCount: oldMessages.length,
    tokensSaved: estimateTokens(oldMessages) - estimateTokens(summary),
  };
}

消息替换策略
摘要生成后，原始消息被替换为压缩摘要 + 最近消息：


// src/compact/compact.ts — 消息替换（简化）
function applyCompactResult(messages: SDKMessage[], result: CompactResult): void {
  const compactMessage: SDKMessage = {
    type: 'assistant',
    content: [
      {
        type: 'text',
        text: `[Conversation Summary]\n\n${result.summary}`,
      },
    ],
    timestamp: Date.now(),
    metadata: {
      compacted: true,
      removedCount: result.removedCount,
      tokensSaved: result.tokensSaved,
    },
  };

  messages.length = 0;

  messages.push(compactMessage);

  for (const msg of result.preservedMessages) {
    messages.push(msg);
  }
}

提示： 保留最近 5 条消息是因为模型需要知道"刚才在做什么"。如果全部替换为摘要，模型会丢失当前任务的上下文。






Reactive Compact
Reactive compact 是 413 错误的紧急响应机制。它与常规 auto compact 的区别在于：更积极的压缩策略和更少的保留消息。


// src/compact/compact.ts — Reactive Compact（简化）
async function* reactiveCompact(messages: SDKMessage[], config: CompactConfig): AsyncGenerator<SDKMessage> {
  yield {
    type: 'system',
    content: '⚠️ 上下文超出限制，正在执行紧急压缩...',
    timestamp: Date.now(),
  };

  const result = await generateCompactSummary(messages, {
    ...config,
    keepRecentMessages: 3,
    compactModel: config.compactModel ?? 'claude-haiku-3-20241022',
    maxSummaryTokens: 2048,
  });

  applyCompactResult(messages, result);

  yield {
    type: 'system',
    content: `紧急压缩完成。移除 ${result.removedCount} 条消息，节省约 ${formatTokenCount(result.tokensSaved)} tokens。`,
    timestamp: Date.now(),
  };
}

可配置模型
Auto compact 可以使用与主对话不同的模型来生成摘要：


// src/compact/compact.ts — 模型选择（简化）
function selectCompactModel(config: CompactConfig): string {
  if (config.compactModel) return config.compactModel;

  const modelCostMap: Record<string, string> = {
    'claude-opus-4-20250514': 'claude-sonnet-4-20250514',
    'claude-sonnet-4-20250514': 'claude-haiku-3-20241022',
    'claude-haiku-3-20241022': 'claude-haiku-3-20241022',
  };

  return modelCostMap[config.model] ?? config.model;
}

提示： 使用更便宜的模型做摘要是一个重要的成本优化。Haiku 的摘要能力对于压缩对话已经足够好，而其价格仅为 Sonnet 的 1/4。






压缩历史追踪
每次 auto compact 都会记录在项目状态中，用于分析和调试：


// src/compact/compact.ts — 历史追踪（简化）
interface CompactRecord {
  timestamp: number;
  trigger: 'threshold' | 'reactive' | 'manual';
  removedCount: number;
  tokensBefore: number;
  tokensAfter: number;
  summaryModel: string;
  summaryTokens: number;
  summaryCost: number;
}

async function recordCompaction(record: CompactRecord, cwd: string): Promise<void> {
  const projectState = await readProjectState(getProjectStatePath(cwd));
  projectState.compactHistory = projectState.compactHistory ?? [];
  projectState.compactHistory.push(record);
  await writeProjectState(getProjectStatePath(cwd), projectState);
}


小结
    

  • Auto compact 有三种触发方式：threshold（90% 窗口）、reactive（413 错误）和 manual（/compact 命令）。
    • 

  • 摘要通过 LLM 调用生成，使用结构化提示词要求输出 Context/Actions/Files/Issues 四个段落。
    • 

  • 消息替换策略：清空原数组 → 插入摘要消息 → 恢复最近 5 条（reactive 为 3 条）消息。
    • 

  • Reactive compact 使用更快更便宜的 Haiku 模型，是 413 错误的紧急恢复机制。
    • 

  • 默认摘要模型自动降一级（Opus→Sonnet, Sonnet→Haiku），优化压缩操作本身的成本。
    • 

  • 每次压缩都记录为 CompactRecord，持久化到项目状态中用于分析。
