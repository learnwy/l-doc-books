上下文窗口策略

四层压缩架构

Claude Code 的上下文管理核心是一套四层渐进式压缩架构。每一层在三个维度上取得不同的平衡：压缩力度（释放多少 token）、计算成本（是否需要 API 调用）和信息保真度（保留多少原始信息）。

提示： 四层架构的设计哲学是"能不调 API 就不调"。前三层都是纯本地操作，只有在上下文真正不够用时才启用第四层的 LLM 摘要。






触发条件与时机
每一层压缩在查询循环中的不同位置触发：


// src/query/query.ts — 压缩触发时机（简化）
async function* queryLoop(params: QueryLoopParams): AsyncGenerator<SDKMessage> {
  while (true) {
    // 第一层 + 第二层：每轮自动执行
    snipCompact(params.messages);
    applyCachedMicrocompaction(params.messages);

    // 第三层：超过阈值时执行
    const tokenEstimate = estimateTokens(params.messages);
    if (feature('CONTEXT_COLLAPSE') && tokenEstimate > params.contextWindow * 0.7) {
      projectedCollapseView(params.messages, params.collapseConfig);
    }

    // 第四层：超过更高阈值时执行
    if (tokenEstimate > params.contextWindow * 0.9) {
      yield* autoCompact(params.messages, params.config);
    }

    try {
      const response = yield* callAPI(params);
      // ... 正常处理
    } catch (error) {
      if (isPromptTooLong(error)) {
        // 第四层（reactive）：413 错误触发
        yield* reactiveCompact(params.messages, params.config);
        continue;
      }
      throw error;
    }
  }
}


Token 估算
所有压缩决策都依赖 token 估算。Claude Code 使用快速的字符级估算而非精确的分词器：


// src/utils/token-estimate.ts — Token 估算（简化）
function estimateTokens(input: string | SDKMessage[]): number {
  if (typeof input === 'string') {
    return Math.ceil(input.length / 3.5);
  }

  let total = 0;
  for (const msg of input) {
    const content = typeof msg.content === 'string' ? msg.content : JSON.stringify(msg.content);
    total += Math.ceil(content.length / 3.5);
    total += 4; // message overhead
  }
  return total;
}

小结
    

  • Claude Code 采用四层渐进式压缩架构：snip → microcompact → context collapse → auto compact，力度依次递增。
    • 

  • 前三层是纯本地操作（无 API 调用），只有第四层 auto compact 需要调用 LLM。
    • 

  • Token 估算使用字符/3.5 快速算法，精度 ±15%，对阈值判断足够。
    • 

  • 上下文窗口分为五个区间，每个区间触发不同级别的压缩策略。
    • 

  • 在典型的 100 轮对话中，四层压缩累积可压缩 80%（250k → 50k tokens）。
    • 

  • 设计哲学：能不调 API 就不调，最大化利用本地快速压缩。
