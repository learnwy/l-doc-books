协议模式

能力协商

MCP 和 LSP 都采用客户端-服务端能力协商模式，在连接建立时交换各自支持的功能集合。

interface ServerCapabilities {
  tools?: { listChanged?: boolean };
  resources?: { subscribe?: boolean; listChanged?: boolean };
  prompts?: { listChanged?: boolean };
  logging?: {};
}

interface ClientCapabilities {
  roots?: { listChanged?: boolean };
  sampling?: {};
  experimental?: Record<string, unknown>;
}

interface NegotiatedCapabilities {
  server: ServerCapabilities;
  client: ClientCapabilities;
  protocolVersion: string;
}

async function negotiateCapabilities(
  client: McpClient,
  requestedCapabilities: ClientCapabilities,
): Promise<NegotiatedCapabilities> {
  const result = await client.initialize({
    protocolVersion: LATEST_PROTOCOL_VERSION,
    capabilities: requestedCapabilities,
    clientInfo: { name: 'claude-code', version: VERSION },
  });

  return {
    server: result.capabilities,
    client: requestedCapabilities,
    protocolVersion: result.protocolVersion,
  };
}

提示： 能力协商是协议的第一步，后续的所有交互都基于协商结果进行。如果服务端不声明 tools 能力，客户端就不应该发送 tools/list 请求。






进度报告
两种协议都支持进度报告，让长时间运行的操作能够向客户端反馈进度。


interface ProgressParams {
  token: string | number;
  value: {
    kind?: 'begin' | 'report' | 'end';
    title?: string;
    message?: string;
    percentage?: number;
  };
}

function handleProgress(params: ProgressParams): void {
  const { token, value } = params;

  switch (value.kind) {
    case 'begin':
      startProgressBar(token, value.title ?? 'Working...');
      break;
    case 'report':
      updateProgressBar(token, value.message, value.percentage);
      break;
    case 'end':
      completeProgressBar(token, value.message);
      break;
  }
}

async function callToolWithProgress(
  serverName: string,
  toolName: string,
  args: Record<string, unknown>,
): Promise<McpResult> {
  const progressToken = generateToken();

  return callMCPTool(serverName, toolName, args, (progress) => {
    handleProgress({
      token: progressToken,
      value: { kind: 'report', ...progress },
    });
  });
}

流式结果
Claude Code 大量使用 AsyncGenerator 模式处理流式结果，MCP 工具调用也遵循这一模式。


async function* streamToolResults(
  serverName: string,
  toolName: string,
  args: Record<string, unknown>,
): AsyncGenerator<ToolResultChunk> {
  const session = await connectToServer(serverName);

  yield { type: 'status', message: `Calling ${toolName}...` };

  const result = await session.client.callTool({
    name: toolName,
    arguments: args,
  });

  const processed = processMCPResult(result, serverName);

  for (const content of processed.content) {
    yield { type: 'content', data: content };
  }

  yield { type: 'complete', isError: processed.isError };
}

type ToolResultChunk =
  | { type: 'status'; message: string }
  | { type: 'content'; data: ProcessedContent }
  | { type: 'complete'; isError: boolean };


提示： AsyncGenerator 是 Claude Code 的通用组合原语。通过 yield 中间状态，调用方可以在工具执行过程中实时更新 UI，而不必等待完整结果返回。






MCP 资源系统
MCP 协议定义了资源系统，允许服务器向客户端暴露可读取的数据资源。


interface McpResource {
  uri: string;
  name: string;
  description?: string;
  mimeType?: string;
}

class ReadMcpResourceTool {
  name = 'mcp__read_resource';

  async execute(params: { serverName: string; uri: string }): Promise<ToolResult> {
    const session = await connectToServer(params.serverName);
    const response = await session.client.readResource({ uri: params.uri });

    return {
      content: response.contents.map((item) => ({
        type: item.mimeType?.startsWith('image/') ? 'image' : 'text',
        data: item.text ?? item.blob,
      })),
    };
  }
}

class ListMcpResourcesTool {
  name = 'mcp__list_resources';

  async execute(params: { serverName: string }): Promise<ToolResult> {
    const session = await connectToServer(params.serverName);
    const response = await session.client.listResources();

    const table = response.resources.map((r) => ({
      uri: r.uri,
      name: r.name,
      type: r.mimeType ?? 'unknown',
    }));

    return { content: [{ type: 'text', text: formatTable(table) }] };
  }
}

MCPTool 运行时模板
MCPTool 是所有 MCP 工具的基础模板类，其方法在运行时由 client.ts 动态覆盖。


class MCPTool {
  name: string;
  description: string;
  inputSchema: JSONSchema;
  serverName: string;

  async isEnabled(): Promise<boolean> {
    return false;
  }

  async validateInput(input: unknown): Promise<ValidationResult> {
    return { valid: true };
  }

  async execute(input: Record<string, unknown>): Promise<ToolResult> {
    throw new Error('Not implemented');
  }

  getPermissionDescription(): string {
    return `MCP tool: ${this.name}`;
  }
}

function createMCPToolInstance(mcpTool: McpToolDefinition, serverName: string): MCPTool {
  const tool = new MCPTool();
  tool.name = `mcp__${serverName}__${mcpTool.name}`;
  tool.description = mcpTool.description;
  tool.inputSchema = mcpTool.inputSchema;
  tool.serverName = serverName;

  tool.isEnabled = async () => {
    const state = getConnectionState(serverName);
    return state === McpConnectionState.Connected;
  };

  tool.execute = async (input) => {
    return callMCPTool(serverName, mcpTool.name, input);
  };

  return tool;
}

错误恢复模式
MCP 定义了多种错误恢复机制，包括会话过期重试和 URL 引导重试。


const URL_ELICITATION_ERROR = -32042;
const MAX_URL_RETRIES = 3;

async function callWithErrorRecovery(serverName: string, request: McpRequest): Promise<McpResponse> {
  let retries = 0;

  while (retries < MAX_URL_RETRIES) {
    try {
      return await sendRequest(serverName, request);
    } catch (error) {
      if (isSessionExpired(error)) {
        invalidateConnection(serverName);
        return await sendRequest(serverName, request);
      }

      if (isUrlElicitationError(error) && retries < MAX_URL_RETRIES) {
        const newUrl = await promptUserForUrl(error.data?.url);
        if (newUrl) {
          updateServerUrl(serverName, newUrl);
          retries++;
          continue;
        }
      }

      throw error;
    }
  }

  throw new Error('Max retries exceeded');
}

function isUrlElicitationError(error: unknown): boolean {
  return isJsonRpcError(error) && error.code === URL_ELICITATION_ERROR;
}

小结
    

  • 能力协商是协议交互的第一步，客户端和服务端交换各自支持的功能集合。
    • 

  • 进度报告通过 begin/report/end 三阶段模型，让长时间操作能实时反馈进度。
    • 

  • AsyncGenerator 是流式结果的核心模式，通过 yield 中间状态实现实时 UI 更新。
    • 

  • MCP 资源系统通过 URI 寻址暴露服务器数据，支持文本和二进制内容。
    • 

  • 错误恢复覆盖会话过期、URL 引导和认证失败三类场景，各有独立的重试策略。
    • 

  • MCP 与 LSP 共享 initialize → discover → operate → shutdown 的四阶段生命周期模型。
