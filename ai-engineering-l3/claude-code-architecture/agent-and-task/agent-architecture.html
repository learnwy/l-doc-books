AgentTool 核心设计

AgentTool 是 Claude Code 中创建子 agent 的核心工具，它将子 agent 作为独立的执行单元（通常是 fork 进程）来运行。每个子 agent 拥有独立的对话上下文和工具集，但可以通过多种隔离模式共享父 agent 的资源。

interface AgentToolInput {
  description: string;
  prompt: string;
  subagent_type: SubagentType;
  model?: 'sonnet' | 'opus' | 'haiku';
  run_in_background?: boolean;
  isolation?: IsolationMode;
}

type SubagentType = 'general' | 'explore' | 'plan' | 'verify' | 'guide';
type IsolationMode = 'fork' | 'worktree' | 'remote' | 'in-process' | 'background';

提示： fork 模式是最常用的隔离模式，它通过继承父 agent 的对话上下文实现 prompt cache 共享，避免了重复的 cache_creation token 消耗。






五种隔离模式详解
每种隔离模式在进程边界、文件系统访问和缓存策略上有不同的取舍。


function createSubagent(input: AgentToolInput, parentContext: ToolUseContext): SubagentHandle {
  switch (input.isolation) {
    case 'fork':
      return forkSubagent(input, parentContext);
    case 'worktree':
      return worktreeSubagent(input, parentContext);
    case 'remote':
      return remoteSubagent(input, parentContext);
    case 'in-process':
      return inProcessSubagent(input, parentContext);
    case 'background':
      return backgroundSubagent(input, parentContext);
  }
}

function forkSubagent(input: AgentToolInput, parentContext: ToolUseContext): SubagentHandle {
  const childContext = {
    ...parentContext,
    conversationHistory: [...parentContext.conversationHistory],
    promptCachePrefix: parentContext.promptCachePrefix,
  };

  return spawnChildProcess(input.prompt, childContext);
}

fork 模式继承父 agent 的 conversationHistory，这意味着子 agent 的 API 请求可以命中父 agent 已建立的 prompt cache，显著减少重复的 cache_creation 开销。




提示： worktree 模式通过 git worktree add 创建独立的工作目录，适合需要在不同分支上并行修改代码的场景，如同时修复多个 bug。

EXPLORE 和 PLAN 使用较低成本的 Haiku/Sonnet 模型且只赋予只读工具，体现了"最小权限"原则——探索和规划不需要修改文件的能力。




提示： 自定义 agent 可以通过 agentDefinitions 配置扩展，它们与内置 agent 使用相同的定义格式，并在运行时合并到可用 agent 列表中。






自动后台阈值
当子 agent 执行时间超过阈值（120 秒）时，系统会自动将其转为后台任务，避免阻塞父 agent 的对话流。


const AUTO_BACKGROUND_THRESHOLD_MS = 120 * 1000;

async function executeSubagent(input: AgentToolInput, context: ToolUseContext): Promise<ToolResult<AgentOutput>> {
  const startTime = Date.now();

  const handle = createSubagent(input, context);

  const result = await Promise.race([
    handle.waitForCompletion(),
    sleep(AUTO_BACKGROUND_THRESHOLD_MS).then(() => 'timeout' as const),
  ]);

  if (result === 'timeout' || input.run_in_background) {
    handle.moveToBackground();
    return successResult({
      status: 'backgrounded',
      taskId: handle.taskId,
      message: `Agent moved to background after ${AUTO_BACKGROUND_THRESHOLD_MS / 1000}s`,
    });
  }

  return successResult({ status: 'completed', output: result });
}

Fork 子 Agent 的缓存共享
fork 模式最重要的优化是 prompt cache 共享。子 agent 继承父 agent 的对话历史作为 prompt 前缀，API 请求可以直接命中已有的缓存。


interface ForkContext {
  conversationHistory: Message[];
  promptCachePrefix: string;
  systemPrompt: string;
}

function buildForkApiRequest(childPrompt: string, forkContext: ForkContext): ApiRequest {
  return {
    system: forkContext.systemPrompt,
    messages: [...forkContext.conversationHistory, { role: 'user', content: childPrompt }],
    cacheControl: {
      prefixLength: forkContext.conversationHistory.length,
    },
  };
}

提示： prompt cache 共享是 fork 模式成为默认隔离模式的主要原因——在 API 成本结构中，cache_creation 的价格是 cache_read 的 4 倍。






小结
    

  • AgentTool 支持 5 种隔离模式（fork/worktree/remote/in-process/background），fork 为默认且最常用。
    • 

  • fork 模式继承父 agent 的对话上下文，实现 prompt cache 共享，cache_read 比 cache_creation 便宜 4 倍。
    • 

  • 6 个内置 Agent 遵循最小权限原则——探索和规划只赋予只读工具，通用和验证赋予全部工具。
    • 

  • 子 agent 执行超过 120 秒自动转为后台任务，通过 taskId 异步查询结果。
    • 

  • 自定义 agent 通过 agentDefinitions 配置扩展，与内置 agent 使用相同的定义格式。
