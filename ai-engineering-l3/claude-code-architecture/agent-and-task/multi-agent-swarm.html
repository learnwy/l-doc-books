多智能体协同

Coordinator 模式架构

Coordinator 模式是 Claude Code 多 agent 协同的核心模式：一个 leader agent 负责任务规划和分发，多个 worker agent 并行执行具体任务。Leader 只保留最小工具集，worker 获得完整工具访问权限。

const COORDINATOR_MODE_ALLOWED_TOOLS = ['Agent', 'TaskStop', 'SendMessage', 'SyntheticOutput'];

interface CoordinatorConfig {
  leaderTools: string[];
  workerTools: string[];
  maxConcurrentWorkers: number;
}

function buildCoordinatorConfig(): CoordinatorConfig {
  return {
    leaderTools: COORDINATOR_MODE_ALLOWED_TOOLS,
    workerTools: getAllTools().filter((t) => !COORDINATOR_MODE_ALLOWED_TOOLS.includes(t)),
    maxConcurrentWorkers: 5,
  };
}

Leader 被限制为只能使用协调类工具，这防止了 leader 越过 worker 直接修改代码——保持了职责分离的架构原则。




提示： SyntheticOutput 工具让 leader 能够合成最终输出而不需要实际执行任何操作，适合 leader 根据 worker 结果组装回答的场景。






Teammate 任务状态
InProcessTeammateTaskState 扩展了基础任务状态，增加了消息队列、abort 控制器和阶段追踪，专门用于同进程内的 teammate 协作。


interface InProcessTeammateTaskState extends TaskStateBase {
  type: 'in_process_teammate';
  messages: Message[];
  abortController: AbortController;
  phase: TeammatePhase;
  retainTranscript: boolean;
  evictAfter?: number;
}

type TeammatePhase = 'initializing' | 'working' | 'waiting' | 'done';

Retain/Evict 内存管理
Teammate 的对话记录采用 retain/evict 模式管理内存——查看 teammate 时保留完整对话（retain），离开视图后延迟淘汰（evict）以释放内存。


function retainTeammateTranscript(task: InProcessTeammateTaskState): void {
  task.retainTranscript = true;
  task.evictAfter = undefined;
}

function releaseTeammateTranscript(task: InProcessTeammateTaskState, gracePeriodMs: number = 30000): void {
  task.retainTranscript = false;
  task.evictAfter = Date.now() + gracePeriodMs;
}

function evictIfExpired(task: InProcessTeammateTaskState): void {
  if (!task.retainTranscript && task.evictAfter && Date.now() >= task.evictAfter) {
    task.messages = [createStubMessage(task)];
    task.evictAfter = undefined;
  }
}

function createStubMessage(task: InProcessTeammateTaskState): Message {
  return {
    role: 'system',
    content: `[Transcript evicted. ${task.messages.length} messages were exchanged.]`,
  };
}

30 秒宽限期的设计考虑：用户可能短暂切出后立即切回查看 teammate 状态，宽限期避免了不必要的淘汰和重建。




提示： 存根消息保留了对话的元信息（消息数量），让 leader 知道这个 teammate 曾经有过多少交互，有助于后续任务分配决策。






Inbox 消息传递
Leader 和 teammate 之间通过 SendMessageTool 实现双向消息传递，形成了一个简单的 inbox 通信模式。


interface SendMessageInput {
  targetTaskId: string;
  message: string;
}

async function sendMessageCall(input: SendMessageInput, context: ToolUseContext): Promise<ToolResult<void>> {
  const task = context.appState.tasks.get(input.targetTaskId);

  if (!task || task.type !== 'in_process_teammate') {
    return errorResult(undefined, 'Target task not found or not a teammate');
  }

  const teammateTask = task as InProcessTeammateTaskState;
  teammateTask.messages.push({
    role: 'user',
    content: input.message,
  });

  if (teammateTask.phase === 'waiting') {
    teammateTask.phase = 'working';
  }

  return successResult(undefined);
}

消息传递是异步的——leader 发送消息后不需要等待 teammate 处理完成，可以继续分发任务给其他 teammate。




视图管理
teammateViewHelpers.ts 提供了 teammate 视图的进入和退出管理，确保同一时间只有一个 teammate 的对话处于"被查看"状态。


interface TeammateViewState {
  activeTeammateId: string | null;
}

function enterTeammateView(viewState: TeammateViewState, task: InProcessTeammateTaskState): void {
  if (viewState.activeTeammateId) {
    const current = getTask(viewState.activeTeammateId);
    if (current) releaseTeammateTranscript(current);
  }

  viewState.activeTeammateId = task.id;
  retainTeammateTranscript(task);
}

function exitTeammateView(viewState: TeammateViewState): void {
  if (viewState.activeTeammateId) {
    const task = getTask(viewState.activeTeammateId);
    if (task) releaseTeammateTranscript(task);
    viewState.activeTeammateId = null;
  }
}

切换视图时自动 release 前一个 teammate 的设计避免了内存泄漏——如果用户频繁在不同 teammate 间切换而不显式退出，所有 teammate 的对话都会驻留内存。




提示： 视图管理的互斥设计（同一时间只有一个活跃 teammate）简化了 UI 渲染逻辑，但也意味着无法同时查看两个 teammate 的对话。






小结
    

  • Coordinator 模式中 leader 仅拥有 4 个协调工具（Agent/TaskStop/SendMessage/SyntheticOutput），worker 获得全部非协调工具。
    • 

  • Teammate 任务通过 InProcessTeammateTaskState 管理，包含消息队列、abort 控制器和阶段追踪。
    • 

  • Retain/evict 模式在查看 teammate 时保留完整对话，退出后 30 秒宽限期后淘汰为存根消息。
    • 

  • Leader 与 teammate 通过 SendMessageTool 异步通信，消息推送可唤醒处于 waiting 状态的 teammate。
    • 

  • 视图管理确保同一时间只有一个活跃 teammate，切换视图时自动 release 前一个以防内存泄漏。
