技能与插件

技能系统概述

Claude Code 的技能系统让用户可以通过声明式的 SKILL.md 文件扩展 AI 助手的能力。每个技能定义了触发条件、可用工具和执行逻辑，系统从 5 个不同来源加载技能。

interface BundledSkillDefinition {
  name: string;
  description: string;
  whenToUse: string;
  allowedTools: string[];
  files: SkillFile[];
}

interface SkillFile {
  path: string;
  content: string;
  nonce: string;
}

BundledSkillDefinition 中的 nonce 字段用于安全校验——文件内容通过进程级 nonce 加密后提取，防止技能文件在运行时被篡改。




提示： 技能与工具的区别在于抽象层次——工具是底层操作（读文件、执行命令），技能是高层行为模式（"当用户请求代码审查时，按以下步骤执行"）。






SKILL.md 文件格式
SKILL.md 使用 YAML frontmatter 定义技能元数据，正文为 Markdown 格式的执行指令。


---
description: Generate unit tests for TypeScript files
allowed-tools:
  - FileRead
  - FileEdit
  - Bash
  - Grep
argument-hint: '<file-path> [--coverage]'
when_to_use: 'When the user asks to generate or write tests'
model: sonnet
hooks:
  pre: "echo 'Starting test generation...'"
  post: 'npm test'
context:
  - 'tsconfig.json'
  - 'jest.config.ts'
agent: general
paths:
  - 'src/**/*.ts'
  - '!src/**/*.test.ts'
---
# 测试生成技能

1. 读取目标文件，理解其导出的函数和类 2. 检查现有测试文件（如果有） 3. 生成覆盖主要分支的单元测试 4. 使用 jest 运行测试确认通过

五来源加载策略
技能从 5 个来源按优先级加载，同名技能以高优先级来源为准。


type SkillSource = 'managed' | 'user' | 'project' | 'additional' | 'legacy';

interface SkillSourceConfig {
  source: SkillSource;
  path: string;
  priority: number;
}

function getSkillSources(projectDir: string): SkillSourceConfig[] {
  return [
    { source: 'managed', path: getManagedSkillsDir(), priority: 1 },
    { source: 'user', path: path.join(homedir(), '.claude', 'skills'), priority: 2 },
    { source: 'project', path: path.join(projectDir, '.claude', 'skills'), priority: 3 },
    { source: 'additional', path: getAdditionalSkillsDir(), priority: 4 },
    { source: 'legacy', path: path.join(projectDir, '.claude', 'commands'), priority: 5 },
  ];
}

async function loadAllSkills(projectDir: string): Promise<Skill[]> {
  const sources = getSkillSources(projectDir);
  const skillMap = new Map<string, Skill>();

  for (const source of sources) {
    const skills = await loadSkillsFromDir(source.path);
    for (const skill of skills) {
      if (!skillMap.has(skill.name)) {
        skillMap.set(skill.name, { ...skill, source: source.source });
      }
    }
  }

  return Array.from(skillMap.values());
}

加载策略采用"先到先得"——同名技能以最先加载的来源为准。这意味着 managed 技能可以覆盖所有其他来源的同名技能。




提示： legacy 来源 .claude/commands/ 保持了对旧版命令系统的向后兼容。新项目应使用 .claude/skills/ 目录。






条件激活与路径匹配
技能可以通过 paths 字段实现条件激活——只有当用户操作的文件匹配指定路径模式时，技能才会被激活。


function isSkillActiveForFile(skill: Skill, filePath: string, projectDir: string): boolean {
  if (!skill.paths || skill.paths.length === 0) return true;

  const relativePath = path.relative(projectDir, filePath);

  for (const pattern of skill.paths) {
    if (pattern.startsWith('!')) {
      if (minimatch(relativePath, pattern.slice(1))) return false;
    }
  }

  for (const pattern of skill.paths) {
    if (!pattern.startsWith('!')) {
      if (minimatch(relativePath, pattern)) return true;
    }
  }

  return false;
}

模板变量
SKILL.md 中支持模板变量替换，提供了技能执行时的动态上下文。


function expandTemplateVariables(content: string, skillDir: string, sessionId: string): string {
  return content.replace(/\$\{CLAUDE_SKILL_DIR\}/g, skillDir).replace(/\$\{CLAUDE_SESSION_ID\}/g, sessionId);
}

插件系统
插件（Plugin）是比技能更高一层的扩展机制，它可以同时提供技能、钩子和 MCP 服务器。


interface BuiltinPluginDefinition {
  id: string;
  name: string;
  isAvailable: () => boolean;
  defaultEnabled: boolean;
  skills: BundledSkillDefinition[];
  hooks: PluginHooks;
  mcpServers: McpServerDefinition[];
}

interface PluginHooks {
  onToolCall?: (tool: string, input: unknown) => Promise<void>;
  onResponse?: (response: string) => Promise<void>;
  onSessionStart?: () => Promise<void>;
  onSessionEnd?: () => Promise<void>;
}

interface McpServerDefinition {
  name: string;
  command: string;
  args: string[];
  env?: Record<string, string>;
}

插件提供的 MCP 服务器可以集成 LSP（Language Server Protocol）能力，为技能提供代码智能分析支持：


const typescriptPlugin: BuiltinPluginDefinition = {
  id: 'typescript',
  name: 'TypeScript Support',
  isAvailable: () => existsSync('tsconfig.json'),
  defaultEnabled: true,
  skills: [typescriptRefactorSkill, typescriptTestSkill],
  hooks: {
    onToolCall: async (tool) => {
      if (tool === 'FileEdit') await runTypeCheck();
    },
  },
  mcpServers: [
    {
      name: 'typescript-lsp',
      command: 'typescript-language-server',
      args: ['--stdio'],
    },
  ],
};


提示： isAvailable() 函数在项目级别检测插件是否适用——例如 TypeScript 插件只在存在 tsconfig.json 的项目中激活，避免在纯 JavaScript 项目中加载不必要的 LSP 服务器。






小结
    

  • 技能通过 SKILL.md 文件声明式定义，YAML frontmatter 包含描述、工具白名单、触发条件和执行钩子。
    • 

  • 技能从 5 个来源加载（managed/user/project/additional/legacy），同名技能以高优先级来源为准。
    • 

  • paths 字段实现条件激活，使用 gitignore 风格模式匹配，! 排除模式优先于包含模式。
    • 

  • 模板变量 ${CLAUDE_SKILL_DIR} 和 ${CLAUDE_SESSION_ID} 提供运行时动态上下文。
    • 

  • 插件系统将技能、钩子和 MCP 服务器打包为一个扩展单元，支持 LSP 集成和生命周期回调。
