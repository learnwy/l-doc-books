权限与安全

三层权限模型

Claude Code 的权限系统采用纵深防御架构，每次工具调用必须通过三层独立的安全检查：输入验证、权限检查和安全守卫。

async function securityPipeline(
  tool: Tool<unknown, unknown>,
  input: unknown,
  context: ToolUseContext,
): Promise<ToolResult<unknown> | null> {
  const validationResult = await tool.validateInput(input, context);
  if (!validationResult.valid) return errorResult(null, validationResult.reason);

  const permissionResult = await tool.checkPermissions(input, context);
  if (permissionResult.result === 'deny') return errorResult(null, permissionResult.reason);

  const guardResult = applySecurityGuards(tool, input);
  if (!guardResult.passed) return errorResult(null, guardResult.reason);

  return null;
}
层级 函数 检查内容 失败行为
第 1 层 validateInput() 结构、格式、deny 规则 静默拒绝
第 2 层 checkPermissions() allow/deny 规则匹配 拒绝或询问
第 3 层 安全守卫 UNC、路径遍历、设备文件 静默拒绝

三层设计确保了即使一层被绕过，后续层仍能提供保护。

提示： 第 1 层和第 3 层的失败都是"静默拒绝"——不需要用户交互，直接返回错误。只有第 2 层的 ask 结果需要用户参与。

输入验证层

输入验证（validateInput）执行结构性检查和显式 deny 规则匹配。它是最廉价的安全层，不涉及文件系统或网络访问。

interface ValidationResult {
  valid: boolean;
  reason?: string;
}

async function validateBashInput(input: { command: string }, context: ToolUseContext): Promise<ValidationResult> {
  if (!input.command || input.command.trim().length === 0) {
    return { valid: false, reason: 'Empty command' };
  }

  if (input.command.length > 100000) {
    return { valid: false, reason: 'Command too long' };
  }

  const denyRules = context.appState.permissions.deny;
  for (const rule of denyRules) {
    if (matchesDenyRule(input.command, rule)) {
      return { valid: false, reason: `Command matches deny rule: ${rule.pattern}` };
    }
  }

  return { valid: true };
}

async function validateFileInput(input: { path: string }, context: ToolUseContext): Promise<ValidationResult> {
  if (path.isAbsolute(input.path) && !existsSync(input.path)) {
    return { valid: false, reason: 'File does not exist' };
  }

  return { valid: true };
}
验证项 工具 检查逻辑 拒绝原因
空输入 BashTool 命令为空或纯空白 Empty command
长度限制 BashTool 超过 100K 字符 Command too long
deny 规则 所有工具 匹配 deny 模式列表 规则描述
路径存在性 FileReadTool 绝对路径文件不存在 File not exist

权限检查层

checkPermissions() 是权限系统的核心，它基于 allow/deny 规则和通配符匹配来做出 allow/deny/ask 决策。

interface PermissionRule {
  tool: string;
  pattern: string;
  action: 'allow' | 'deny';
}

function checkPermissionsWithRules(toolName: string, input: unknown, rules: PermissionRule[]): PermissionResult {
  for (const rule of rules) {
    if (rule.tool !== toolName && rule.tool !== '*') continue;

    if (matchesPattern(input, rule.pattern)) {
      if (rule.action === 'deny') {
        return { result: 'deny', reason: `Matches deny rule: ${rule.pattern}` };
      }
      if (rule.action === 'allow') {
        return { result: 'allow', reason: `Matches allow rule: ${rule.pattern}` };
      }
    }
  }

  return { result: 'ask', message: `${toolName} requires approval` };
}

function matchesPattern(input: unknown, pattern: string): boolean {
  const inputStr = JSON.stringify(input);
  const regex = new RegExp(pattern.replace(/\*/g, '.*').replace(/\?/g, '.'));
  return regex.test(inputStr);
}

规则求值顺序遵循"先匹配先生效"原则——规则列表从上到下扫描，第一条匹配的规则决定最终结果。




提示： 当没有任何规则匹配时，默认返回 ask，这再次体现了 fail-closed 设计——宁可多问用户一次，也不自动放行未知操作。






安全守卫层
安全守卫是最底层的硬编码保护，它们不受规则配置影响，直接拦截已知的危险操作。


function applySecurityGuards(tool: Tool<unknown, unknown>, input: unknown): { passed: boolean; reason?: string } {
  if (hasUNCPath(input)) return { passed: false, reason: 'UNC paths are blocked' };
  if (hasPathTraversal(input)) return { passed: false, reason: 'Path traversal detected' };
  if (accessesBlockedDevice(input)) return { passed: false, reason: 'Blocked device path' };
  return { passed: true };
}

const BLOCKED_DEVICES = [
  '/dev/zero',
  '/dev/null',
  '/dev/stdin',
  '/dev/stdout',
  '/dev/stderr',
  '/dev/random',
  '/dev/urandom',
];

function accessesBlockedDevice(input: unknown): boolean {
  const inputStr = JSON.stringify(input);
  return BLOCKED_DEVICES.some((device) => inputStr.includes(device));
}

自动模式分类器
自动模式（auto mode）下，系统使用 ML 分类器判断工具调用是否安全，替代用户的手动确认。


type SafetyClassification = 'safe' | 'unsafe' | 'unknown';

async function autoModeDecision(
  tool: Tool<unknown, unknown>,
  input: unknown,
  context: ToolUseContext,
  classifier: AutoModeClassifier,
): Promise<PermissionResult> {
  const classification = await classifier.classify(tool, input, context);

  switch (classification) {
    case 'safe':
      return { result: 'allow', reason: 'Auto-mode: classified as safe' };
    case 'unsafe':
      return { result: 'ask', message: 'Auto-mode: classified as unsafe' };
    case 'unknown':
      return { result: 'ask', message: 'Auto-mode: unable to classify' };
  }
}

BashTool 沙箱机制
BashTool 的沙箱基于文件系统 allow/deny 列表和网络主机限制，提供操作系统级别的隔离。


interface BashSandboxPolicy {
  filesystem: {
    allow: string[];
    deny: string[];
  };
  network: {
    allowedHosts: string[];
    denyAll: boolean;
  };
}

function buildDefaultSandboxPolicy(projectDir: string): BashSandboxPolicy {
  return {
    filesystem: {
      allow: [projectDir, path.join(homedir(), '.claude'), '/tmp'],
      deny: ['/etc/shadow', '/etc/passwd', homedir() + '/.ssh', homedir() + '/.aws'],
    },
    network: {
      allowedHosts: ['registry.npmjs.org', 'github.com'],
      denyAll: false,
    },
  };
}

小结
    

  • Claude Code 采用三层纵深防御：输入验证（结构检查）→ 权限检查（规则匹配）→ 安全守卫（硬编码保护）。
    • 

  • 权限规则支持 通配符匹配（* 和 ?），按"先匹配先生效"顺序求值，无匹配时默认 ask。
    • 

  • 安全守卫硬编码拦截 UNC 路径、路径遍历和 /dev/ 设备文件访问。
    • 

  • 自动模式使用 ML 分类器将工具调用分为 safe/unsafe/unknown，只有 safe 才自动放行。
    • 

  • BashTool 沙箱基于文件系统 allow/deny 列表和网络 host 白名单，deny 优先于 allow。
