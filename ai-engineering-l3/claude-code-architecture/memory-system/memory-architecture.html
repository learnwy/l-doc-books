记忆架构

文件系统存储模型

Claude Code 的记忆系统采用纯文件方案，所有记忆持久化为 Markdown 文件，存储在项目级目录 ~/.claude/projects/<project>/memory/ 下。这种设计避免了数据库依赖，用户可以直接用任意文本编辑器查看和修改记忆内容。

interface MemoryFileMetadata {
  name: string;
  description: string;
  type: MemoryType;
}

type MemoryType = 'user' | 'feedback' | 'project' | 'reference';

interface MemoryFile {
  frontmatter: MemoryFileMetadata;
  content: string;
  filePath: string;
}

目录结构遵循约定优于配置的原则：

~/.claude/
├── projects/
│   └── <project-hash>/
│       └── memory/
│           ├── MEMORY.md          # 入口点文件
│           ├── preferences.md     # 用户偏好
│           ├── corrections.md     # 反馈修正
│           └── team/              # 团队共享记忆
│               └── conventions.md
路径组成部分 来源 说明
~/.claude/ 全局配置目录 所有项目共享的根目录
projects/ 固定目录名 项目级记忆隔离
<project-hash> 项目路径哈希 避免路径冲突和特殊字符问题
memory/ 固定目录名 记忆文件存放位置
team/ 可选子目录 团队共享记忆，受额外安全限制

提示： 项目哈希基于项目根路径生成，因此同一项目在不同机器上可能有不同的哈希值。迁移记忆时需要注意路径映射。

四类记忆分类法

每个记忆文件通过 YAML frontmatter 中的 type 字段标识其分类。四种类型覆盖了 AI 编码助手在长期交互中需要记住的所有知识维度。

---
name: coding-style
description: User's preferred coding conventions
type: user
---
# 编码风格偏好

- 使用函数式风格，避免 class
- 优先使用 const 声明
- 缩进使用 2 空格

每种类型在 prompt 构建时有不同的权重和呈现方式。user 类型的记忆会被优先注入到系统 prompt 中，因为用户偏好直接影响输出质量。




YAML Frontmatter 元数据
每个记忆文件以标准 YAML frontmatter 开头，包含三个必需字段。解析器在加载时会验证这些字段的存在性和类型正确性。


function parseMemoryFile(filePath: string): MemoryFile | null {
  const content = readFileSync(filePath, 'utf-8');
  const match = content.match(/^---\n([\s\S]*?)\n---\n([\s\S]*)$/);

  if (!match) return null;

  const frontmatter = parseYaml(match[1]) as MemoryFileMetadata;

  if (!frontmatter.name || !frontmatter.type) return null;

  const validTypes: MemoryType[] = ['user', 'feedback', 'project', 'reference'];
  if (!validTypes.includes(frontmatter.type)) return null;

  return {
    frontmatter,
    content: match[2].trim(),
    filePath,
  };
}

frontmatter 的设计遵循了"机器可读 + 人类可编辑"的双重目标。用户可以手动创建记忆文件，只要遵循 frontmatter 格式即可被系统识别。




提示： description 字段在 AI 驱动的记忆召回中扮演关键角色——Sonnet 模型会基于 description 来判断记忆文件与当前查询的相关性。






MEMORY.md 入口点
MEMORY.md 是记忆系统的入口文件，充当整个记忆目录的索引和摘要。系统对其有明确的大小限制：最大 200 行、25KB。


const MEMORY_MAX_LINES = 200;
const MEMORY_MAX_BYTES = 25 * 1024;

function loadMemoryEntrypoint(projectDir: string): string | null {
  const memoryPath = path.join(projectDir, 'memory', 'MEMORY.md');

  if (!existsSync(memoryPath)) return null;

  const content = readFileSync(memoryPath, 'utf-8');
  const lines = content.split('\n');

  if (lines.length > MEMORY_MAX_LINES) {
    return lines.slice(0, MEMORY_MAX_LINES).join('\n');
  }

  if (Buffer.byteLength(content, 'utf-8') > MEMORY_MAX_BYTES) {
    return content.slice(0, MEMORY_MAX_BYTES);
  }

  return content;
}
MEMORY.md 的内容会被无条件注入到每次对话的 system prompt 中，因此体积控制至关重要。

buildMemoryPrompt 构建流程
memdir.ts 中的 buildMemoryPrompt() 是记忆系统的核心函数，负责将文件系统中的记忆转化为可注入 prompt 的文本。它不仅加载记忆内容，还会添加行为指令，教会模型如何操作记忆。


function buildMemoryPrompt(memoryDir: string): string {
  const sections: string[] = [];

  sections.push(buildBehavioralInstructions());

  const entrypoint = loadMemoryEntrypoint(memoryDir);
  if (entrypoint) {
    sections.push(`<memory-entrypoint>\n${entrypoint}\n</memory-entrypoint>`);
  }

  const files = scanMemoryDirectory(memoryDir);
  if (files.length > 0) {
    const manifest = files.map((f) => `- ${f.name}: ${f.description}`).join('\n');
    sections.push(`<memory-manifest>\n${manifest}\n</memory-manifest>`);
  }

  return sections.join('\n\n');
}

function buildBehavioralInstructions(): string {
  return [
    'You have access to a persistent memory system.',
    'Use memory to store important context across conversations.',
    'When the user corrects you, save the correction as a feedback memory.',
    'Read relevant memories before answering domain-specific questions.',
  ].join('\n');
}
行为指令的设计体现了"自我教学"模式——通过 prompt 指令让模型学会何时读取、何时写入记忆。




loadMemoryPrompt 分发策略
loadMemoryPrompt() 是记忆加载的入口分发器，根据不同的记忆模式选择对应的加载策略。


type MemoryMode = 'kairos' | 'team' | 'auto' | string;

function loadMemoryPrompt(mode: MemoryMode, projectDir: string): string | null {
  switch (mode) {
    case 'kairos':
      return loadKairosDailyLog(projectDir);
    case 'team':
      return buildCombinedMemoryPrompt(projectDir);
    case 'auto':
      return buildMemoryPrompt(path.join(projectDir, 'memory'));
    default:
      return null;
  }
}

分发策略的"安全降级"设计值得注意——当遇到未知模式时返回 null 而非抛错，确保记忆系统的故障不会影响核心对话功能。




提示： kairos 模式以希腊语"恰当的时机"命名，它将记忆按时间维度组织为每日日志，特别适合需要追踪项目演进的长期开发任务。






小结
    

  • Claude Code 记忆系统采用纯文件方案，所有记忆以 Markdown 存储在 ~/.claude/projects/<project>/memory/ 目录下。
    • 

  • 四类记忆分类（user/feedback/project/reference）通过 YAML frontmatter 的 type 字段区分，覆盖偏好、修正、上下文和参考知识。
    • 

  • MEMORY.md 作为入口点受 200 行/25KB 限制，其内容无条件注入 system prompt。
    • 

  • buildMemoryPrompt() 不仅加载记忆内容，还注入行为指令教会模型自主操作记忆系统。
    • 

  • loadMemoryPrompt() 通过模式分发（kairos/team/auto）选择加载策略，未知模式安全降级为 null。
