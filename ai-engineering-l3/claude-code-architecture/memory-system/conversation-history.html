对话历史

history.ts 存储架构

history.ts（464 行）管理着 Claude Code 的对话历史系统。所有历史记录存储在 ~/.claude/history.jsonl 文件中，采用 JSONL（JSON Lines）格式——每行一条独立的 JSON 记录。

const HISTORY_FILE = path.join(homedir(), '.claude', 'history.jsonl');
const MAX_HISTORY_ITEMS = 100;

interface LogEntry {
  display: string;
  pastedContents: StoredPastedContent[];
  timestamp: number;
  project: string;
  sessionId: string;
}

JSONL 格式的选择体现了"追加友好"的设计理念：

{"display":"fix auth bug","pastedContents":[],"timestamp":1709000000,"project":"/app","sessionId":"abc123"}
{"display":"add dark mode","pastedContents":[],"timestamp":1709003600,"project":"/app","sessionId":"def456"}
{"display":"refactor api","pastedContents":[],"timestamp":1709007200,"project":"/web","sessionId":"ghi789"}

文件位置 全局 项目级 历史记录跨项目统一管理
条目上限 100 无限制 控制文件大小和加载时间
时间戳格式 Unix ms ISO 8601 排序和比较更高效 


提示： MAX_HISTORY_ITEMS = 100 意味着系统只保留最近的 100 条历史。当超过此限制时，最旧的条目会在下次写入时被淘汰。

display 和 pastedContents 的分离是一个精巧的设计——用户在命令行输入的短文本直接存储在 display 中，而可能很长的粘贴内容通过哈希引用存储在独立文件中。




大文本内容寻址哈希
当用户粘贴的内容超过 1024 字符时，系统不会将其内联存储在 JSONL 中，而是采用内容寻址（content-addressed）哈希策略存储到独立文件。


const PASTE_THRESHOLD = 1024;
const PASTED_TEXTS_DIR = path.join(homedir(), '.claude', 'pastedTexts');

interface StoredPastedContent {
  hash: string;
  length: number;
}

function storePastedContent(content: string): StoredPastedContent | null {
  if (content.length < PASTE_THRESHOLD) return null;

  const hash = createHash('sha256').update(content).digest('hex');
  const filePath = path.join(PASTED_TEXTS_DIR, hash);

  if (!existsSync(filePath)) {
    mkdirSync(PASTED_TEXTS_DIR, { recursive: true });
    writeFileSync(filePath, content, 'utf-8');
  }

  return { hash, length: content.length };
}

function loadPastedContent(stored: StoredPastedContent): string | null {
  const filePath = path.join(PASTED_TEXTS_DIR, stored.hash);
  if (!existsSync(filePath)) return null;
  return readFileSync(filePath, 'utf-8');
}

提示： 1024 字符的阈值经过权衡——太小会导致大量小文件 I/O 开销，太大则让 JSONL 膨胀。典型的代码片段粘贴在 1-5 KB 范围内，1024 是一个合理的切分点。






缓冲写入与文件锁
对话历史的写入采用缓冲策略（buffered write），不是每条记录立即写入，而是在退出时统一刷新（flush-on-exit）。同时使用文件级锁（file-level locking）防止多实例并发写入冲突。


class HistoryWriter {
  private buffer: LogEntry[] = [];
  private lockHandle: FileHandle | null = null;

  append(entry: LogEntry): void {
    this.buffer.push(entry);
  }

  async flush(): Promise<void> {
    if (this.buffer.length === 0) return;

    await this.lock();

    try {
      const lines = this.buffer.map((entry) => JSON.stringify(entry)).join('\n');

      await appendFile(HISTORY_FILE, lines + '\n', 'utf-8');
      this.buffer = [];
    } finally {
      await this.unlock();
    }
  }

  private async lock(): Promise<void> {
    const lockPath = HISTORY_FILE + '.lock';
    this.lockHandle = await open(lockPath, 'wx');
  }

  private async unlock(): Promise<void> {
    if (this.lockHandle) {
      await this.lockHandle.close();
      await unlink(HISTORY_FILE + '.lock');
      this.lockHandle = null;
    }
  }
}

提示： 缓冲写入的一个风险是进程异常退出时丢失未刷新的历史。Claude Code 通过注册 process.on('exit') 和 SIGINT 处理器来最大程度减少数据丢失。






读取路径：上方向键与 Ctrl+R
历史记录提供两种读取模式：getHistory() 支持上方向键的最近命令浏览，getTimestampedHistory() 支持 Ctrl+R 的时间戳搜索。


function getHistory(limit: number = MAX_HISTORY_ITEMS): LogEntry[] {
  if (!existsSync(HISTORY_FILE)) return [];

  const content = readFileSync(HISTORY_FILE, 'utf-8').trim();
  if (!content) return [];

  const lines = content.split('\n');
  const entries = lines
    .map((line) => {
      try {
        return JSON.parse(line) as LogEntry;
      } catch {
        return null;
      }
    })
    .filter(Boolean) as LogEntry[];

  return entries.slice(-limit).reverse();
}

function getTimestampedHistory(query: string, project?: string): LogEntry[] {
  const all = getHistory(MAX_HISTORY_ITEMS);

  return all.filter((entry) => {
    const matchesQuery = entry.display.toLowerCase().includes(query.toLowerCase());
    const matchesProject = !project || entry.project === project;
    return matchesQuery && matchesProject;
  });
}

getHistory() 的"反向读取"策略值得注意——JSONL 文件是追加写入的，所以最新的条目在文件末尾。通过 slice(-limit).reverse() 取最后 N 条并反序，实现高效的"最近优先"访问。




removeLastFromHistory 撤销机制
当用户按 Ctrl+C 取消输入时，removeLastFromHistory() 会移除最近添加的历史记录，避免保留未完成的输入。


function removeLastFromHistory(): void {
  if (!existsSync(HISTORY_FILE)) return;

  const content = readFileSync(HISTORY_FILE, 'utf-8').trim();
  if (!content) return;

  const lines = content.split('\n');
  lines.pop();
  writeFileSync(HISTORY_FILE, lines.join('\n') + '\n', 'utf-8');
}

这是一个面向用户体验的微优化——在命令行工具中，用户经常输入一半后按 Ctrl+C 取消，保留这些片段到历史记录中会让上方向键的导航体验变差。




提示： removeLastFromHistory() 需要读取并重写整个文件，因此不适合频繁调用。在实际实现中，它只在 Ctrl+C 信号处理器中被调用一次。
