AI 驱动的记忆召回

findRelevantMemories 核心流程

findRelevantMemories.ts（141 行）实现了 Claude Code 记忆系统中最精巧的部分——利用 Sonnet 模型作为旁路查询（side-query），从大量记忆文件中智能筛选与当前用户查询最相关的记忆。

interface MemorySearchResult {
  paths: string[];
  reasoning: string;
}

async function findRelevantMemories(
  userQuery: string,
  recentTools: ToolResult[],
  memoryDir: string,
  alreadySurfaced: Set<string>,
): Promise<MemorySearchResult> {
  const manifest = await scanMemoryFiles(memoryDir);
  const formatted = formatMemoryManifest(manifest);

  const result = await sideQuery({
    model: 'sonnet',
    systemPrompt: buildMemorySearchPrompt(),
    userMessage: buildSearchInput(userQuery, recentTools, formatted),
    outputSchema: memorySearchSchema,
  });

  const filtered = result.paths.filter((p) => !alreadySurfaced.has(p));
  return { paths: filtered.slice(0, 5), reasoning: result.reasoning };
}

提示： 使用 Sonnet 而非 Opus 进行旁路查询是性能与成本的权衡——记忆检索需要快速响应，而 Sonnet 在分类和检索任务上已经足够准确。






scanMemoryFiles 扫描策略
扫描阶段的设计体现了对大规模记忆库的务实处理：只读取每个文件的前 30 行作为摘要，最多处理 200 个文件，按修改时间倒序排列以优先考虑最新记忆。


const MAX_SCAN_FILES = 200;
const PREVIEW_LINES = 30;

interface MemoryFileSummary {
  path: string;
  preview: string;
  mtime: number;
}

async function scanMemoryFiles(memoryDir: string): Promise<MemoryFileSummary[]> {
  const files = await glob('**/*.md', { cwd: memoryDir });

  const withStats = await Promise.all(
    files.map(async (file) => {
      const fullPath = path.join(memoryDir, file);
      const stat = await fsStat(fullPath);
      return { path: file, fullPath, mtime: stat.mtimeMs };
    }),
  );

  const sorted = withStats.sort((a, b) => b.mtime - a.mtime).slice(0, MAX_SCAN_FILES);

  return Promise.all(
    sorted.map(async (entry) => {
      const content = await readFile(entry.fullPath, 'utf-8');
      const lines = content.split('\n').slice(0, PREVIEW_LINES);
      return {
        path: entry.path,
        preview: lines.join('\n'),
        mtime: entry.mtime,
      };
    }),
  );
}

"前 30 行"的设计有其巧妙之处：标准的 YAML frontmatter 约占 5-6 行，剩余 24-25 行足以捕获文件的标题和第一个段落，为 Sonnet 提供足够的语义信息进行相关性判断。




提示： 当记忆文件超过 200 个时，旧文件（按 mtime）会被自动排除在扫描范围之外。定期清理过时记忆有助于保持检索质量。






formatMemoryManifest 清单构建
扫描结果需要被格式化为 Sonnet 模型能高效处理的结构化文本。formatMemoryManifest() 将每个文件的路径和预览组装为编号清单。


function formatMemoryManifest(summaries: MemoryFileSummary[]): string {
  return summaries
    .map((s, i) => {
      const header = `[${i + 1}] ${s.path}`;
      const separator = '-'.repeat(40);
      return `${header}\n${separator}\n${s.preview}\n`;
    })
    .join('\n');
}

sideQuery 旁路查询机制
sideQuery() 是记忆检索的核心：它向 Sonnet 模型发送一个独立的、不影响主对话流的查询请求，要求模型以 JSON Schema 格式返回结构化结果。


const memorySearchSchema = z.object({
  paths: z.array(z.string()).max(5).describe('Most relevant memory file paths'),
  reasoning: z.string().describe('Brief explanation of selection rationale'),
});

type MemorySearchOutput = z.infer<typeof memorySearchSchema>;

async function sideQuery(options: {
  model: string;
  systemPrompt: string;
  userMessage: string;
  outputSchema: z.ZodType<MemorySearchOutput>;
}): Promise<MemorySearchOutput> {
  const response = await callModel({
    model: options.model,
    system: options.systemPrompt,
    messages: [{ role: 'user', content: options.userMessage }],
    responseFormat: { type: 'json_schema', schema: options.outputSchema },
  });

  return options.outputSchema.parse(JSON.parse(response.content));
}

searchInput 的构建将用户查询和最近工具执行结果一起传给 Sonnet，让模型能够根据当前任务上下文（而非仅查询文本）来判断记忆相关性。




提示： 旁路查询的 reasoning 字段虽然不直接展示给用户，但对调试记忆检索质量非常有价值。可通过日志查看 Sonnet 为什么选择了特定记忆。






已展示路径过滤
为避免重复向主对话注入相同的记忆内容，系统维护了一个 alreadySurfaced 集合，记录当前会话中已经加载过的记忆路径。


function filterAlreadySurfaced(candidates: string[], alreadySurfaced: Set<string>, maxResults: number = 5): string[] {
  return candidates.filter((path) => !alreadySurfaced.has(path)).slice(0, maxResults);
}
这个看似简单的过滤逻辑解决了一个重要的 UX 问题：如果同一份记忆在每次查询中都被重复注入，不仅浪费 token，还会在 prompt 中产生冗余信息干扰模型判断。

memoryAge 新鲜度追踪
memoryAge.ts 实现了记忆的新鲜度检测机制，用于识别可能已过时的记忆内容。核心阈值为 1 天——超过 24 小时未更新的记忆被标记为"陈旧"。


const STALENESS_THRESHOLD_MS = 24 * 60 * 60 * 1000;

interface MemoryFreshness {
  path: string;
  isStale: boolean;
  ageMs: number;
  lastModified: Date;
}

function checkMemoryFreshness(filePath: string, now: number = Date.now()): MemoryFreshness {
  const stat = statSync(filePath);
  const ageMs = now - stat.mtimeMs;

  return {
    path: filePath,
    isStale: ageMs > STALENESS_THRESHOLD_MS,
    ageMs,
    lastModified: stat.mtime,
  };
}

buildSearchingPastContextSection
当记忆文件检索不足以回答用户问题时，系统会引导模型使用 grep 搜索过去的对话上下文。


function buildSearchingPastContextSection(): string {
  return [
    '<searching-past-context>',
    'If relevant memories are insufficient, search past conversation context.',
    'Use grep to search through conversation history files.',
    'Focus on recent conversations first (sorted by timestamp).',
    '</searching-past-context>',
  ].join('\n');
}
这形成了记忆系统的两级回退策略：先查结构化记忆文件，不够时再 grep 非结构化的对话历史。




提示： grep 搜索过去对话是一个高 token 消耗操作，系统仅在结构化记忆检索结果不足时才触发，体现了"渐进式信息获取"的设计理念。

  • findRelevantMemories() 使用 Sonnet 旁路查询从记忆清单中智能检索最相关的记忆，返回最多 5 条路径。

  • scanMemoryFiles() 对每个 .md 文件只读前 30 行作为摘要，最多处理 200 个文件，按 mtime 降序排列。
    • 

  • 旁路查询通过 JSON Schema 约束输出格式，确保结构化的路径列表和推理依据。
