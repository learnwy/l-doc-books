在线评估

核心概念

在线评估（Online Evaluation）通过真实用户的行为数据来衡量搜索系统的效果，是搜索优化的最终判断标准。与离线评估基于标注数据不同，在线评估直接反映用户在真实场景下与搜索系统的交互质量，能够捕获离线评估无法覆盖的用户体验维度。

A/B 测试框架
A/B 测试是搜索系统在线评估的金标准。将用户随机分为实验组（使用新模型）和对照组（使用当前模型），比较两组的在线指标差异来判断新模型的效果。


interface ABTestConfig {
  experimentId: string;
  trafficSplit: number;
  minSampleSize: number;
  testDuration: number;
  primaryMetric: string;
  guardrailMetrics: string[];
  significanceLevel: number;
}

interface ABTestResult {
  experimentId: string;
  controlGroup: MetricSummary;
  treatmentGroup: MetricSummary;
  uplift: number;
  pValue: number;
  confidenceInterval: [number, number];
  isSignificant: boolean;
  sampleSize: number;
}

interface MetricSummary {
  mean: number;
  standardDeviation: number;
  sampleSize: number;
  percentiles: Record<string, number>;
}

function calculateUplift(control: number, treatment: number): number {
  return (treatment - control) / control;
}

function calculateMinSampleSize(
  baselineRate: number,
  minimumDetectableEffect: number,
  significanceLevel: number = 0.05,
  power: number = 0.8,
): number {
  const zAlpha = 1.96;
  const zBeta = 0.84;
  const pooledVariance = 2 * baselineRate * (1 - baselineRate);
  const effectSize = baselineRate * minimumDetectableEffect;
  return Math.ceil((pooledVariance * (zAlpha + zBeta) ** 2) / effectSize ** 2);
}

interface TrafficRouter {
  route(userId: string, experimentId: string): 'control' | 'treatment';
  getActiveExperiments(): ABTestConfig[];
}

function hashBasedRouting(userId: string, experimentId: string, split: number): 'control' | 'treatment' {
  const hash = hashFnv1a(`${userId}:${experimentId}`);
  return hash % 100 < split * 100 ? 'treatment' : 'control';
}
A/B 测试的关键设计要点包括：足够大的样本量（确保统计功效）、足够长的实验时间（覆盖工作日和周末的流量差异）、护栏指标（Guardrail Metrics，确保关键业务指标不下降）以及避免窥探效应（不要在实验未结束时频繁查看结果并做决策）。


Interleaving 评估
Interleaving 是一种比 A/B 测试更灵敏的在线评估方法。它将两个排序系统的结果交错合并为一个排序列表展示给用户，通过用户的点击行为推断哪个系统更好。


type InterleavingMethod = 'team_draft' | 'balanced' | 'probabilistic';

interface InterleavedResult {
  docId: string;
  rank: number;
  source: 'A' | 'B';
}

function teamDraftInterleaving(listA: string[], listB: string[], k: number): InterleavedResult[] {
  const result: InterleavedResult[] = [];
  const used = new Set<string>();
  let ptrA = 0;
  let ptrB = 0;
  let teamASize = 0;
  let teamBSize = 0;

  while (result.length < k && (ptrA < listA.length || ptrB < listB.length)) {
    const pickA = teamASize <= teamBSize;

    if (pickA && ptrA < listA.length) {
      while (ptrA < listA.length && used.has(listA[ptrA])) ptrA++;
      if (ptrA < listA.length) {
        result.push({ docId: listA[ptrA], rank: result.length + 1, source: 'A' });
        used.add(listA[ptrA]);
        teamASize++;
        ptrA++;
      }
    } else if (ptrB < listB.length) {
      while (ptrB < listB.length && used.has(listB[ptrB])) ptrB++;
      if (ptrB < listB.length) {
        result.push({ docId: listB[ptrB], rank: result.length + 1, source: 'B' });
        used.add(listB[ptrB]);
        teamBSize++;
        ptrB++;
      }
    }
  }

  return result;
}

function evaluateInterleaving(
  interleavedResults: InterleavedResult[],
  clickedDocIds: Set<string>,
): { winsA: number; winsB: number; ties: number } {
  let clicksA = 0;
  let clicksB = 0;

  for (const result of interleavedResults) {
    if (clickedDocIds.has(result.docId)) {
      if (result.source === 'A') clicksA++;
      else clicksB++;
    }
  }

  return {
    winsA: clicksA > clicksB ? 1 : 0,
    winsB: clicksB > clicksA ? 1 : 0,
    ties: clicksA === clicksB ? 1 : 0,
  };
}
Interleaving 相比 A/B 测试的优势是灵敏度更高——在相同流量下，Interleaving 能更快地检测到系统间的微小差异。缺点是只能比较排序质量，无法评估其他变更（如 UI 改动、延迟优化）。

位置偏差是搜索日志中最严重的偏差。用户倾向于点击排名靠前的结果，即使它们不一定比后面的更相关。IPW（Inverse Propensity Weighting）通过估计每个位置的点击倾向性来校正这种偏差。


小结
    

  • 在线评估是搜索优化的最终判断标准，直接反映真实用户体验
    • 

  • A/B 测试是在线评估的金标准，需要足够的样本量、实验时长和护栏指标
    • 

  • Interleaving 灵敏度更高，能在较小流量下检测排序差异，但仅适用于排序比较
    • 

  • 点击率、满意度、停留时长和查询改写率是核心在线指标，需要综合分析
    • 

  • 用户行为日志存在位置偏差等系统性偏差，需要通过 IPW 等方法校正后才能用于模型训练
