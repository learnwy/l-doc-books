交叉编码器重排序

核心概念

交叉编码器重排序（Cross-Encoder Reranking）是在初始检索阶段之后，使用高精度的交叉编码器模型对候选文档进行精细排序的技术。Cross-Encoder 将查询和文档联合编码，通过 Transformer 的全注意力机制捕获查询-文档之间的深层语义交互，排序质量远超 Bi-Encoder。

Cross-Encoder 架构与训练
Cross-Encoder 的训练通常采用二元分类或回归框架。给定查询-文档对 (q, d)，模型输出一个相关性分数。训练数据可以来自人工标注（如 MS MARCO 的稀疏标注）或搜索日志（点击/未点击）。

interface MarginMSEBatch {
  query: string;
  docPos: string;
  docNeg: string;
  teacherPosScore: number;
  teacherNegScore: number;
}

function marginMSELoss(
  studentPosScore: number,
  studentNegScore: number,
  teacherPosScore: number,
  teacherNegScore: number,
): number {
  const studentMargin = studentPosScore - studentNegScore;
  const teacherMargin = teacherPosScore - teacherNegScore;
  return (studentMargin - teacherMargin) ** 2;
}

interface RerankPipeline {
  retriever: Retriever;
  reranker: CrossEncoder;
  retrieveTopK: number;
  rerankTopK: number;
}

async function rerankPipeline(
  query: string,
  pipeline: RerankPipeline,
): Promise<Array<{ docId: string; score: number }>> {
  const candidates = await pipeline.retriever.search(query, pipeline.retrieveTopK);

  const pairs = candidates.map((c) => ({
    query,
    document: c.content,
    docId: c.id,
  }));

  const scores = await pipeline.reranker.scoreBatch(pairs.map((p) => [p.query, p.document]));

  return pairs
    .map((p, i) => ({ docId: p.docId, score: scores[i] }))
    .sort((a, b) => b.score - a.score)
    .slice(0, pipeline.rerankTopK);
}
MonoT5 是一种基于生成模型的重排序方法，它将相关性判断建模为 "true"/"false" 的文本生成任务。RankGPT 则利用 LLM 的推理能力直接对候选文档列表进行排序。


多阶段级联重排序
在大规模搜索系统中，单一的 Cross-Encoder 重排序往往不够。需要设计多阶段级联排序架构，每一阶段使用更复杂的模型处理更少的候选文档，逐级精炼排序结果。

每个阶段的设计需要考虑两个核心指标：上一阶段的召回率（确保相关文档不被过早淘汰）和本阶段的排序精度（在允许的延迟内尽可能提升排序质量）。


阶段之间的文档截断数量（Top-K 设置）需要仔细调优。过大的 K 值增加下游计算成本，过小的 K 值可能丢失相关文档。理想的策略是通过离线评估确定每个阶段的最小 K 值，使得目标文档的漏失率低于某个阈值。


在线推理优化
Cross-Encoder 的在线推理是重排序系统的性能瓶颈。针对这一问题，有多种优化策略。

function queryDocHash(query: string, docId: string): string {
  return `${hashFnv1a(query)}_${docId}`;
}

interface EarlyExitConfig {
  confidenceThreshold: number;
  minLayers: number;
  maxLayers: number;
}

function shouldEarlyExit(layerOutput: Float32Array, config: EarlyExitConfig, currentLayer: number): boolean {
  if (currentLayer < config.minLayers) return false;
  const confidence = Math.abs(sigmoid(layerOutput[0]) - 0.5) * 2;
  return confidence >= config.confidenceThreshold;
}

interface DynamicBatchConfig {
  maxBatchSize: number;
  maxWaitMs: number;
  padToMultipleOf: number;
}

async function dynamicBatch(
  requests: Array<{ query: string; document: string }>,
  config: DynamicBatchConfig,
): Promise<number[]> {
  const sorted = [...requests].sort(
    (a, b) => a.query.length + a.document.length - (b.query.length + b.document.length),
  );

  const padded = sorted.map((r) => {
    const totalLen = r.query.length + r.document.length;
    const paddedLen = Math.ceil(totalLen / config.padToMultipleOf) * config.padToMultipleOf;
    return { ...r, paddedLen };
  });

  return forwardBatch(padded);
}
关键优化手段包括：INT8/INT4 量化降低计算量和内存带宽需求；动态批处理将多个请求合并为一个 GPU batch；早退机制（Early Exit）在模型中间层就输出高置信度的结果；结果缓存避免重复计算热门查询。


小结
    

  • Cross-Encoder 通过查询-文档联合编码实现最高质量的语义匹配，是重排序的核心模型
    • 

  • 多阶段级联排序（召回 → 粗排 → 精排 → 重排）是大规模搜索系统的标准架构
    • 

  • MarginMSE 是训练 Cross-Encoder 的有效损失函数，利用教师模型的分数差作为监督信号
    • 

  • 在线推理优化（量化、动态批处理、早退、缓存）是 Cross-Encoder 落地的关键工程技术
    • 

  • MonoT5 和 RankGPT 代表了基于生成模型重排序的新方向，利用 LLM 的推理能力提升排序质量
    •
