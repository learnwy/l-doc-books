多阶段排序

核心概念

多阶段排序（Multi-Stage Ranking）是将搜索排序过程分解为多个级联阶段的系统架构，每个阶段使用复杂度递增的模型处理逐渐减少的候选文档集。这种设计在海量文档规模下实现了排序质量与计算效率的最优平衡。

召回层设计
召回层是排序漏斗的入口，目标是在极低延迟内从全量索引中检索出尽可能多的相关文档。召回率是此阶段的核心指标，宁可多召回无关文档也不能遗漏相关文档。


interface RecallStrategy {
  name: string;
  quota: number;
  retriever: Retriever;
  priority: number;
}

interface MultiChannelRecall {
  channels: RecallStrategy[];
  deduplication: 'union' | 'weighted';
  totalQuota: number;
}

async function multiChannelRecall(query: string, config: MultiChannelRecall): Promise<Map<string, RecallResult>> {
  const channelResults = await Promise.all(
    config.channels.map(async (ch) => ({
      name: ch.name,
      results: await ch.retriever.search(query, ch.quota),
    })),
  );

  const merged = new Map<string, RecallResult>();
  for (const { name, results } of channelResults) {
    for (const result of results) {
      const existing = merged.get(result.docId);
      if (!existing) {
        merged.set(result.docId, { ...result, sources: [name] });
      } else {
        existing.sources.push(name);
        existing.score = Math.max(existing.score, result.score);
      }
    }
  }

  return merged;
}

interface RecallChannelConfig {
  bm25: { enabled: boolean; quota: number };
  dense: { enabled: boolean; quota: number; model: string };
  collaborative: { enabled: boolean; quota: number };
  personalized: { enabled: boolean; quota: number };
  realtime: { enabled: boolean; quota: number };
}
多路召回（Multi-Channel Recall）是工业界的标准做法。每路召回针对不同的匹配维度（词汇匹配、语义匹配、协同过滤、个性化等），最终合并去重。多路召回的配额分配需要通过 A/B 测试持续优化。


预排序与粗排
预排序层（Pre-Ranking）在召回结果的基础上进行第一轮筛选，将候选从万级压缩到千级。此阶段需要在极低延迟（通常 5ms 以内）下完成，因此模型必须足够轻量。


interface PreRankModel {
  type: 'two_tower' | 'light_mlp' | 'feature_cross';
  inputDim: number;
  hiddenDims: number[];
  outputDim: number;
}

interface PreRankFeatures {
  queryEmbedding: Float32Array;
  docEmbedding: Float32Array;
  staticFeatures: number[];
}

function twoTowerPreRank(queryEmb: Float32Array, docEmbs: Float32Array[]): number[] {
  return docEmbs.map((docEmb) => dotProduct(queryEmb, docEmb));
}

interface PreRankConfig {
  model: PreRankModel;
  topK: number;
  batchSize: number;
  useCache: boolean;
  cacheKeyFn: (query: string) => string;
}

function lightMLPPreRank(features: PreRankFeatures[], weights: MLPWeights): number[] {
  return features.map((f) => {
    const input = Float32Array.from([
      ...f.queryEmbedding.slice(0, 64),
      ...f.docEmbedding.slice(0, 64),
      ...f.staticFeatures,
    ]);
    return mlpForward(input, weights);
  });
}
预排序模型的设计原则是用最少的计算量筛选出最有可能相关的文档。双塔模型通过预计算文档向量将在线计算简化为向量点积；轻量 MLP 使用少量统计特征（如 BM25 分数、文档质量分、点击率）进行快速评分。


精排与深度排序模型
精排层（Ranking）是排序系统的核心阶段，使用最丰富的特征和最复杂的模型进行精确排序。此阶段的候选量已经降至千级，允许使用更重的模型和更多的特征。

  wideFeatures: string[];
  deepFeatures: string[];
  embeddingDim: number;
  crossLayers: number;
  deepLayers: number[];
}

interface DCNv2Config {
  inputDim: number;
  crossLayers: number;
  deepLayers: number[];
  expertNum: number;
  mixtureLayers: number;
}

function crossLayer(x0: Float32Array, xi: Float32Array, weight: Float32Array[], bias: Float32Array): Float32Array {
  const dim = x0.length;
  const result = new Float32Array(dim);

  const projected = matMul(xi, weight);
  for (let j = 0; j < dim; j++) {
    result[j] = x0[j] * projected[j] + bias[j] + xi[j];
  }

  return result;
}
在实际系统中，精排模型通常采用 GBDT 和深度模型的融合方案。GBDT 处理结构化特征（数值统计、类别标签），深度模型处理非结构化特征（文本嵌入、图像特征），最终通过加权融合或 stacking 得到最终排序分数。


策略层与业务调控
策略层（Policy Layer）是排序漏斗的最后一个环节，基于业务规则和多目标优化对精排结果进行最终调整。策略层不以单纯的相关性最优为目标，而是需要平衡相关性、多样性、新鲜度、商业价值等多个维度。


interface PolicyConfig {
  diversityWeight: number;
  freshnessBoost: number;
  qualityThreshold: number;
  maxSameSource: number;
  businessRules: BusinessRule[];
}

interface BusinessRule {
  condition: (doc: RankedDoc) => boolean;
  action: 'boost' | 'demote' | 'pin' | 'remove';
  value: number;
}

function applyDiversityReranking(rankedDocs: RankedDoc[], config: PolicyConfig): RankedDoc[] {
  const result: RankedDoc[] = [];
  const sourceCount = new Map<string, number>();

  for (const doc of rankedDocs) {
    const count = sourceCount.get(doc.source) ?? 0;
    if (count >= config.maxSameSource) continue;

    sourceCount.set(doc.source, count + 1);
    result.push(doc);
  }

  return result;
}

function mmrReranking(docs: RankedDoc[], lambda: number, topK: number): RankedDoc[] {
  const selected: RankedDoc[] = [];
  const remaining = [...docs];

  while (selected.length < topK && remaining.length > 0) {
    let bestIdx = 0;
    let bestScore = -Infinity;

    for (let i = 0; i < remaining.length; i++) {
      const relevance = remaining[i].score;
      const maxSim = selected.length === 0 ? 0 : Math.max(...selected.map((s) => similarity(remaining[i], s)));
      const mmrScore = lambda * relevance - (1 - lambda) * maxSim;

      if (mmrScore > bestScore) {
        bestScore = mmrScore;
        bestIdx = i;
      }
    }

    selected.push(remaining[bestIdx]);
    remaining.splice(bestIdx, 1);
  }

  return selected;
}
MMR（Maximal Marginal Relevance）是最常用的多样性算法，它在每一步选择与已选文档最不相似但与查询最相关的文档。


小结
    

  • 多阶段排序通过漏斗架构实现了排序质量与计算效率的最优平衡，是大规模搜索系统的标准设计
    • 

  • 召回层追求高召回率，多路召回是工业标准；预排序层用轻量模型快速筛选
    • 

  • 精排层是排序核心，GBDT 和深度模型融合方案效果最优，DCN-V2 等模型擅长特征交叉
    • 

  • 策略层平衡多目标（相关性、多样性、新鲜度），MMR 是经典的多样性重排序算法
    • 

  • 各阶段的候选截断数量和延迟预算需要通过离线评估和在线 A/B 测试持续优化
    •
