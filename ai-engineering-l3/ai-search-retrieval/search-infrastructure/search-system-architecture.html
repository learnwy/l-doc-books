搜索系统架构

核心概念

搜索系统架构（Search System Architecture）是支撑端到端搜索体验的分布式系统设计，涵盖从用户查询输入到结果展示的完整数据流。现代搜索架构需要同时满足低延迟（P99 < 200ms）、高吞吐（万级 QPS）、高可用（99.99%）和数据新鲜度等多维度要求。

微服务拆分与服务治理
搜索系统通常采用微服务架构，将不同功能拆分为独立的服务。每个服务可以独立开发、部署和扩缩容。


interface SearchService {
  name: string;
  endpoints: Endpoint[];
  dependencies: string[];
  sla: SLAConfig;
  scaling: ScalingConfig;
}

interface SLAConfig {
  p50LatencyMs: number;
  p99LatencyMs: number;
  availabilityTarget: number;
  errorBudget: number;
}

interface ScalingConfig {
  minInstances: number;
  maxInstances: number;
  targetCPU: number;
  targetQPS: number;
  scaleUpCooldown: number;
  scaleDownCooldown: number;
}

服务间通信通常采用 gRPC（低延迟、强类型）或 HTTP/JSON（通用性好）。在搜索系统中，内部服务间优先使用 gRPC，对外 API 使用 REST。服务发现、熔断降级和分布式追踪是服务治理的三大支柱。


特征服务与模型服务
特征服务（Feature Store）为排序模型提供实时和离线特征。模型服务（Model Serving）托管各类机器学习模型，提供低延迟的在线推理。


interface FeatureStore {
  getOnlineFeatures(keys: FeatureKey[]): Promise<FeatureVector[]>;
  getBatchFeatures(keys: FeatureKey[]): Promise<FeatureVector[]>;
  registerFeatureView(view: FeatureView): Promise<void>;
}

interface FeatureKey {
  entityType: 'user' | 'item' | 'query';
  entityId: string;
  featureNames: string[];
}

interface FeatureView {
  name: string;
  entities: string[];
  features: FeatureDefinition[];
  source: DataSource;
  ttl: number;
}

interface ModelServingConfig {
  modelName: string;
  version: string;
  runtime: 'onnx' | 'tensorrt' | 'triton' | 'torchserve';
  batchSize: number;
  maxLatencyMs: number;
  gpuMemoryMb: number;
  instances: number;
}

interface ModelServingRequest {
  modelName: string;
  inputs: Record<string, Float32Array | string[]>;
  outputNames: string[];
}

async function modelInference(
  request: ModelServingRequest,
  config: ModelServingConfig,
): Promise<Record<string, Float32Array>> {
  const client = getModelClient(config.modelName, config.runtime);
  const response = await client.predict(request.inputs, {
    timeout: config.maxLatencyMs,
    batchSize: config.batchSize,
  });
  return response;
}

可观测性与故障处理
搜索系统的可观测性（Observability）包括指标监控（Metrics）、日志（Logging）和分布式追踪（Tracing）三大支柱，是快速发现和定位问题的基础。


interface SearchMetrics {
  latency: HistogramMetric;
  qps: CounterMetric;
  errorRate: GaugeMetric;
  cacheHitRate: GaugeMetric;
  indexFreshness: GaugeMetric;
  recallRate: GaugeMetric;
  rankingModelVersion: LabelMetric;
}

interface AlertRule {
  metric: string;
  condition: 'gt' | 'lt' | 'rate_change';
  threshold: number;
  duration: number;
  severity: 'warning' | 'critical';
  action: 'notify' | 'auto_rollback' | 'circuit_break';
}

故障处理的核心原则是 "优雅降级"：当某个组件出现故障时，系统应该返回质量稍低但仍可用的结果，而不是直接报错。降级策略需要预先定义并定期演练。


小结
    

  • 现代搜索架构采用微服务设计，将查询理解、召回、排序和展示拆分为独立服务
    • 

  • 每个服务有明确的 SLA 和延迟预算，端到端延迟通过级联优化控制在 200ms 以内
    • 

  • 特征服务和模型服务是排序系统的核心支撑，需要低延迟的在线推理和实时特征获取
    • 

  • 可观测性（指标、日志、追踪）和告警是快速发现和定位搜索质量问题的基础
    • 

  • 优雅降级策略确保在组件故障时系统仍能返回可用结果，保障用户体验
    •
