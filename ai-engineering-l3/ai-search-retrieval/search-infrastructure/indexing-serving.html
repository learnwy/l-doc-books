索引构建与在线服务

核心概念

索引构建与在线服务（Indexing and Serving）是搜索系统从离线数据处理到在线查询响应的完整工程管线。索引构建将原始文档转换为高效检索的数据结构，在线服务基于这些索引响应用户的实时查询请求。两者的设计直接决定了搜索系统的数据新鲜度、查询延迟和系统可用性。

文档处理管线
文档处理管线将原始内容转换为可索引的结构化数据。这个过程包括文档获取、内容提取、文本清洗、特征计算和向量编码等步骤。


interface DocumentPipeline {
  crawler: DocumentCrawler;
  parser: DocumentParser;
  enricher: DocumentEnricher;
  encoder: DocumentEncoder;
  indexer: DocumentIndexer;
}

interface ProcessedDocument {
  id: string;
  url: string;
  title: string;
  content: string;
  cleanText: string;
  tokens: string[];
  embedding: Float32Array;
  metadata: DocumentMetadata;
  features: DocumentFeatures;
}

interface DocumentMetadata {
  language: string;
  contentType: string;
  publishDate: Date;
  lastModified: Date;
  author: string;
  domain: string;
}

interface DocumentFeatures {
  wordCount: number;
  pageRank: number;
  domainAuthority: number;
  qualityScore: number;
  spamScore: number;
  readabilityScore: number;
}

async function processDocument(raw: RawDocument, pipeline: DocumentPipeline): Promise<ProcessedDocument> {
  const parsed = await pipeline.parser.parse(raw);
  const enriched = await pipeline.enricher.enrich(parsed);
  const embedding = await pipeline.encoder.encode(enriched.cleanText);

  return {
    id: raw.id,
    url: raw.url,
    title: parsed.title,
    content: parsed.content,
    cleanText: enriched.cleanText,
    tokens: enriched.tokens,
    embedding,
    metadata: enriched.metadata,
    features: enriched.features,
  };
}

interface BatchProcessor {
  batchSize: number;
  concurrency: number;
  retryPolicy: RetryPolicy;
  deadLetterQueue: string;
}

async function batchProcess(
  documents: RawDocument[],
  pipeline: DocumentPipeline,
  config: BatchProcessor,
): Promise<ProcessingResult> {
  const batches = chunk(documents, config.batchSize);
  let successCount = 0;
  let failCount = 0;

  for (const batch of batches) {
    const results = await Promise.allSettled(batch.map((doc) => processDocument(doc, pipeline)));

    for (const result of results) {
      if (result.status === 'fulfilled') {
        await pipeline.indexer.index(result.value);
        successCount++;
      } else {
        failCount++;
      }
    }
  }

  return { successCount, failCount, total: documents.length };
}
大规模文档处理需要考虑幂等性（同一文档重复处理不产生副作用）、容错性（单文档失败不影响整体流程）和可追溯性（每个文档的处理状态可查询）。


增量索引与近实时更新
全量重建索引的成本随数据规模线性增长，对于频繁更新的数据源（如新闻、社交媒体），需要支持增量索引更新。


interface IncrementalIndexer {
  memoryBuffer: MemoryIndex;
  diskSegments: DiskSegment[];
  mergePolicy: MergePolicy;
}

interface MemoryIndex {
  maxSize: number;
  currentSize: number;
  documents: Map<string, IndexedDocument>;
  invertedIndex: Map<string, PostingList>;
  vectorIndex: HNSWIndex;
}

interface DiskSegment {
  id: string;
  docCount: number;
  byteSize: number;
  createdAt: Date;
  level: number;
}

interface MergePolicy {
  maxSegments: number;
  maxSegmentSize: number;
  mergeFactor: number;
  flushThreshold: number;
}

async function handleDocumentUpdate(indexer: IncrementalIndexer, doc: ProcessedDocument): Promise<void> {
  indexer.memoryBuffer.documents.set(doc.id, toIndexedDoc(doc));
  updateInvertedIndex(indexer.memoryBuffer.invertedIndex, doc);
  indexer.memoryBuffer.vectorIndex.add(doc.id, doc.embedding);
  indexer.memoryBuffer.currentSize++;

  if (indexer.memoryBuffer.currentSize >= indexer.mergePolicy.flushThreshold) {
    const segment = await flushToDisk(indexer.memoryBuffer);
    indexer.diskSegments.push(segment);
    clearMemoryBuffer(indexer.memoryBuffer);

    if (shouldMerge(indexer.diskSegments, indexer.mergePolicy)) {
      await mergeSegments(indexer.diskSegments, indexer.mergePolicy);
    }
  }
}
LSM（Log-Structured Merge-tree）风格的索引管理是近实时搜索引擎（如 Elasticsearch）的核心设计。新文档首先写入内存缓冲区，当缓冲区达到阈值时刷盘为一个不可变的段（Segment），后台持续合并小段为大段以提高检索效率。

小结
    

  • 索引构建与在线服务是搜索系统的两大核心工程支柱，决定了数据新鲜度和查询性能
    • 

  • 文档处理管线需要保证幂等性、容错性和可追溯性，支持大规模并行处理
    • 

  • 增量索引通过 LSM 风格的内存缓冲+段合并实现近实时更新，是动态数据源的标准方案
    • 

  • 在线服务通过缓存、并行检索、降级策略和限流熔断保障延迟和可用性
    • 

  • 索引部署需要支持蓝绿发布或灰度切换，确保索引更新不影响在线服务
    •
