稀疏与稠密混合检索

核心概念

混合检索（Hybrid Retrieval）将稀疏检索（BM25、SPLADE）与稠密检索（Dense Retrieval）的结果进行融合，利用两种检索范式的互补优势来提升整体检索质量。稀疏检索擅长精确的词汇匹配，稠密检索擅长语义理解，两者融合能够覆盖更广泛的相关文档。

学习型稀疏检索
传统 BM25 使用固定的 TF-IDF 权重计算词项重要性，而学习型稀疏检索（Learned Sparse Retrieval）通过神经网络学习更优的词项权重，同时保持稀疏表示的可解释性和检索效率。


SPLADE（SParse Lexical AnD Expansion model）是学习型稀疏检索的代表模型。它利用 BERT 的 MLM 头部为每个查询/文档生成一个词表大小的稀疏向量，其中每个维度对应词表中的一个词项，权重表示该词项的重要性。SPLADE 的关键创新在于它不仅保留了原始文档中的词项，还能通过 MLM 预测扩展出语义相关的新词项。


interface SpladeOutput {
  indices: number[];
  values: number[];
  expandedTerms: Map<string, number>;
}

interface SpladeConfig {
  model: string;
  regLambda: number;
  flopsRegLambda: number;
  topK: number;
}

function spladeForward(tokenLogits: Float32Array[], attentionMask: boolean[]): SpladeOutput {
  const vocabSize = tokenLogits[0].length;
  const aggregated = new Float32Array(vocabSize);

  for (let i = 0; i < tokenLogits.length; i++) {
    if (!attentionMask[i]) continue;
    for (let j = 0; j < vocabSize; j++) {
      const activated = Math.log(1 + Math.exp(tokenLogits[i][j]));
      aggregated[j] = Math.max(aggregated[j], activated);
    }
  }

  const indices: number[] = [];
  const values: number[] = [];
  for (let j = 0; j < vocabSize; j++) {
    if (aggregated[j] > 0) {
      indices.push(j);
      values.push(aggregated[j]);
    }
  }
  return { indices, values, expandedTerms: new Map() };
}
DeepImpact 和 uniCOIL 是另外两种重要的学习型稀疏方法。DeepImpact 为文档中每个唯一词项学习一个标量权重，uniCOIL 则为每个 token 学习上下文感知的权重。与 SPLADE 相比，这两种方法不进行词项扩展，但计算效率更高。


分数融合策略
混合检索的关键技术挑战是如何有效融合来自不同检索器的分数。由于稀疏和稠密检索器的分数分布差异很大（BM25 分数通常在 0-30 之间，而余弦相似度在 -1 到 1 之间），直接相加会导致某一方的贡献被淹没。

RRF（Reciprocal Rank Fusion）是最广泛使用的无参数融合方法，它只依赖排名位置而不依赖原始分数：


interface RankResult {
  docId: string;
  rank: number;
  score: number;
}

function reciprocalRankFusion(rankings: RankResult[][], k: number = 60): Map<string, number> {
  const fusedScores = new Map<string, number>();

  for (const ranking of rankings) {
    for (const result of ranking) {
      const current = fusedScores.get(result.docId) ?? 0;
      fusedScores.set(result.docId, current + 1 / (k + result.rank));
    }
  }

  return fusedScores;
}

function normalizedLinearFusion(
  sparseResults: RankResult[],
  denseResults: RankResult[],
  alpha: number = 0.5,
): Map<string, number> {
  const sparseMax = Math.max(...sparseResults.map((r) => r.score));
  const sparseMin = Math.min(...sparseResults.map((r) => r.score));
  const denseMax = Math.max(...denseResults.map((r) => r.score));
  const denseMin = Math.min(...denseResults.map((r) => r.score));

  const fused = new Map<string, number>();

  for (const r of sparseResults) {
    const norm = (r.score - sparseMin) / (sparseMax - sparseMin + 1e-8);
    fused.set(r.docId, (fused.get(r.docId) ?? 0) + alpha * norm);
  }

  for (const r of denseResults) {
    const norm = (r.score - denseMin) / (denseMax - denseMin + 1e-8);
    fused.set(r.docId, (fused.get(r.docId) ?? 0) + (1 - alpha) * norm);
  }

  return fused;
}
融合权重 α 的选择对最终效果影响显著。经验表明，在精确匹配需求强的场景（如实体搜索、代码搜索），应增大稀疏检索的权重；在语义理解需求强的场景（如问答、对话），应增大稠密检索的权重。


端到端混合检索系统
在生产环境中部署混合检索系统需要考虑架构设计、延迟优化和资源调度等工程问题。核心架构通常包括并行的稀疏和稠密检索管线，以及一个融合层和可选的重排序层。


延迟优化的关键在于稀疏和稠密检索的并行执行。由于两个检索器完全独立，可以并行发起请求，总延迟取决于较慢的那一方。在实际系统中，稠密检索（GPU 编码 + ANN 搜索）通常是瓶颈。


索引同步是另一个重要的工程问题。文档更新需要同时更新稀疏索引（倒排索引）和稠密索引（向量索引），两者的更新延迟和一致性保证需要仔细设计。常见的做法是采用双写策略（同时写入两个索引），并通过版本号确保一致性。


查询自适应路由
并非所有查询都需要混合检索。某些查询（如精确的实体名称搜索）用稀疏检索就够了，某些查询（如语义模糊的自然语言问题）更适合稠密检索。查询自适应路由（Query-Adaptive Routing）根据查询特征动态选择检索策略，在保证质量的同时降低计算成本。


type RetrievalMode = 'sparse_only' | 'dense_only' | 'hybrid';

interface QueryFeatures {
  length: number;
  entityCount: number;
  avgTermIdf: number;
  isQuestion: boolean;
  domainSpecific: boolean;
}

function routeQuery(features: QueryFeatures): RetrievalMode {
  if (features.entityCount > 0 && features.length <= 3) {
    return 'sparse_only';
  }

  if (features.isQuestion && features.avgTermIdf < 3.0) {
    return 'dense_only';
  }

  return 'hybrid';
}

interface AdaptiveHybridConfig {
  router: (features: QueryFeatures) => RetrievalMode;
  sparseWeight: number;
  denseWeight: number;
  fallbackMode: RetrievalMode;
}
学习型路由器可以通过一个轻量级分类器实现，输入查询的特征向量（词长、IDF 统计、是否包含实体、句法结构等），输出最优的检索模式。训练数据可以通过对比三种模式在验证集上的效果自动生成。


小结
    

  • 混合检索融合稀疏（词汇匹配）和稠密（语义匹配）两种范式的互补优势，在大多数检索任务上优于单一检索器
    • 

  • 学习型稀疏检索（SPLADE、uniCOIL）通过神经网络学习词项权重和扩展，弥合了传统稀疏检索和稠密检索的差距
    • 

  • RRF 是最稳健的无参数融合方法，不依赖分数归一化；线性加权融合简单但需要调优权重参数
    • 

  • 生产系统需要并行执行两路检索、同步维护双索引、优化端到端延迟
    • 

  • 查询自适应路由可以根据查询特征动态选择检索策略，在质量和效率之间取得更好的平衡
    •
