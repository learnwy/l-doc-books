稠密检索

核心概念

稠密检索（Dense Retrieval）是利用深度学习模型将查询和文档映射到连续向量空间，通过向量相似度计算实现语义级别匹配的检索范式。与传统基于词频的稀疏检索不同，稠密检索能够捕捉深层语义关系，解决词汇不匹配（Vocabulary Mismatch）问题。

稠密检索的核心思想是在向量空间中，语义相近的文本被映射到相近的位置，从而通过最近邻搜索实现高效的语义检索。

双塔编码架构
双塔模型（Bi-Encoder）是稠密检索最核心的架构设计。查询和文档分别通过独立的编码器生成向量表示，在推理时文档向量可以离线预计算并建立索引，查询时只需在线编码查询向量并执行近似最近邻（ANN）搜索。


Bi-Encoder 的训练目标通常采用对比学习框架。给定查询 q、正样本文档 d⁺ 和负样本文档 d⁻，优化以下损失函数：


interface DenseRetrievalConfig {
  queryEncoder: TransformerModel;
  docEncoder: TransformerModel;
  similarityFn: 'dot_product' | 'cosine' | 'l2_distance';
  poolingStrategy: 'cls' | 'mean' | 'max';
  embeddingDim: number;
}

interface TrainingBatch {
  queries: string[];
  positives: string[];
  negatives: string[][];
}

function inBatchNegativeLoss(
  queryEmbeds: Float32Array[],
  docEmbeds: Float32Array[],
  temperature: number = 0.05,
): number {
  const batchSize = queryEmbeds.length;
  const scores: number[][] = [];
  for (let i = 0; i < batchSize; i++) {
    const row: number[] = [];
    for (let j = 0; j < batchSize; j++) {
      row.push(dotProduct(queryEmbeds[i], docEmbeds[j]) / temperature);
    }
    scores.push(row);
  }
  return crossEntropyLoss(
    scores,
    Array.from({ length: batchSize }, (_, i) => i),
  );
}
双塔架构的关键设计选择包括参数共享策略、池化方法和向量维度。参数共享（Shared Encoder）在数据量有限时表现更好，而独立参数（Asymmetric Encoder）在大规模数据上可以更好地适配查询和文档的不同特征分布。


CLS 池化直接取 [CLS] token 的隐藏状态作为句子表示，而均值池化（Mean Pooling）对所有 token 的隐藏状态取平均。实践中，均值池化通常能获得更稳定的表示。

ANCE（Approximate Nearest Neighbor Negative Contrastive Estimation）是一种经典的硬负样本挖掘方法，它周期性地使用当前训练中的模型刷新 ANN 索引，从索引中检索最相似但非正例的文档作为负样本：


interface HardNegativeMining {
  model: DenseRetriever;
  index: ANNIndex;
  refreshInterval: number;
  topK: number;
  filterPositives: boolean;
}

async function mineHardNegatives(
  queries: string[],
  positiveIds: Set<string>,
  config: HardNegativeMining,
): Promise<Map<string, string[]>> {
  const queryEmbeds = await config.model.encodeQueries(queries);
  const results = new Map<string, string[]>();
  for (let i = 0; i < queries.length; i++) {
    const candidates = await config.index.search(queryEmbeds[i], config.topK * 2);
    const negatives = candidates
      .filter((c) => !positiveIds.has(c.id))
      .slice(0, config.topK)
      .map((c) => c.id);
    results.set(queries[i], negatives);
  }
  return results;
}
实践中常采用混合负采样策略：一部分来自 BM25 负样本，一部分来自硬负样本挖掘，再加上 In-Batch Negatives，形成多梯度难度的训练信号。


向量索引与近似最近邻
稠密检索在推理阶段的核心挑战是如何在数十亿级文档向量中高效找到最相似的向量。精确最近邻搜索的时间复杂度为 O(n)，在实际系统中不可接受，因此需要近似最近邻（ANN）算法。


HNSW（Hierarchical Navigable Small World）是目前工业界最广泛使用的 ANN 算法。它构建一个多层图结构，底层包含所有节点，上层逐渐稀疏。检索时从顶层的入口节点开始，贪心搜索到每层的最近邻，然后下降到下一层继续搜索，最终在底层获得精确的近似最近邻。


IVF（Inverted File Index）将向量空间划分为多个 Voronoi 区域，每个区域由一个聚类中心表示。检索时先找到最近的几个聚类中心，然后只在这些聚类内部进行精确搜索。IVF 通常与 PQ（Product Quantization）结合使用，通过将高维向量压缩为短编码来大幅减少内存占用。


interface IndexConfig {
  type: 'hnsw' | 'ivf_pq' | 'ivf_flat' | 'flat';
  dimension: number;
  metric: 'ip' | 'l2' | 'cosine';
  hnswM?: number;
  hnswEfConstruction?: number;
  hnswEfSearch?: number;
  ivfNlist?: number;
  ivfNprobe?: number;
  pqM?: number;
  pqNbits?: number;
}

function chooseIndex(corpusSize: number, memoryBudget: number): IndexConfig {
  if (corpusSize < 100_000) {
    return { type: 'flat', dimension: 768, metric: 'ip' };
  }
  if (corpusSize < 10_000_000) {
    return {
      type: 'hnsw',
      dimension: 768,
      metric: 'ip',
      hnswM: 32,
      hnswEfConstruction: 200,
      hnswEfSearch: 128,
    };
  }
  return {
    type: 'ivf_pq',
    dimension: 768,
    metric: 'ip',
    ivfNlist: Math.round(Math.sqrt(corpusSize)),
    ivfNprobe: 64,
    pqM: 96,
    pqNbits: 8,
  };
}
预训练与微调范式
稠密检索模型的训练通常分为预训练和微调两个阶段。预训练阶段在大规模无标注语料上学习通用的文本表示能力，微调阶段在特定检索任务的标注数据上优化检索性能。


预训练方法的演进路线清晰：从 BERT 直接微调到 ICT（Inverse Cloze Task）预训练，再到 Condenser/coCondenser 的结构化预训练，以及 RetroMAE 的掩码自编码预训练。

微调阶段的核心策略包括知识蒸馏（从 Cross-Encoder 到 Bi-Encoder）、多任务学习（检索 + 分类 + 聚类联合训练）以及课程学习（从简单负样本逐渐过渡到困难负样本）。


小结
    

  • 稠密检索通过双塔编码架构将查询和文档映射到连续向量空间，实现语义级别的检索匹配
    • 

  • 负样本质量是训练效果的关键因素，混合策略（BM25 + 硬负样本 + In-Batch）效果最佳
    • 

  • ANN 索引（HNSW、IVF-PQ）解决了大规模向量检索的效率问题，需要在速度、召回率和内存之间权衡
    • 

  • 预训练范式从通用语言模型微调演进到检索专用预训练（coCondenser、RetroMAE），显著提升了零样本和小样本场景的表现
    • 

  • 实际部署中需要综合考虑编码延迟、索引构建时间、内存占用和召回质量等工程因素
    •
