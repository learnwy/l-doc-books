查询改写

核心概念

查询改写（Query Rewriting）是在保持用户检索意图不变的前提下，将原始查询转换为更有利于检索系统理解和匹配的形式。它是弥合用户表达与文档内容之间语义鸿沟的关键技术，直接影响召回率和检索质量。

基于词典与规则的改写
基于词典的改写是最传统也最可控的方法，通过维护同义词词典、缩写词典、上下位词关系等资源来扩展或替换查询词项。


interface SynonymDict {
  synonyms: Map<string, string[]>;
  hypernyms: Map<string, string[]>;
  hyponyms: Map<string, string[]>;
  abbreviations: Map<string, string>;
}

interface RewriteCandidate {
  query: string;
  source: 'synonym' | 'hypernym' | 'abbreviation' | 'correction';
  confidence: number;
  originalTerms: string[];
  replacedTerms: string[];
}

function dictionaryRewrite(query: string, dict: SynonymDict, maxExpansions: number = 3): RewriteCandidate[] {
  const tokens = tokenize(query);
  const candidates: RewriteCandidate[] = [];

  for (let i = 0; i < tokens.length; i++) {
    const token = tokens[i];

    const abbreviation = dict.abbreviations.get(token.toLowerCase());
    if (abbreviation) {
      const newTokens = [...tokens];
      newTokens[i] = abbreviation;
      candidates.push({
        query: newTokens.join(' '),
        source: 'abbreviation',
        confidence: 0.95,
        originalTerms: [token],
        replacedTerms: [abbreviation],
      });
    }

    const syns = dict.synonyms.get(token) ?? [];
    for (const syn of syns.slice(0, maxExpansions)) {
      const newTokens = [...tokens];
      newTokens[i] = syn;
      candidates.push({
        query: newTokens.join(' '),
        source: 'synonym',
        confidence: 0.8,
        originalTerms: [token],
        replacedTerms: [syn],
      });
    }
  }

  return candidates;
}
词典方法的优势是确定性强、可解释、延迟低，但维护成本高，且无法处理词典外的表达。在实际系统中，通常将词典方法作为 fallback，确保核心场景的稳定性。


基于嵌入的语义扩展
利用词嵌入或句子嵌入模型进行语义级别的查询扩展。核心思想是在嵌入空间中找到与查询词语义相近的词，将其添加到查询中以增加召回。


interface EmbeddingExpander {
  wordEmbeddings: Map<string, Float32Array>;
  threshold: number;
  maxExpansions: number;
}

function semanticExpansion(query: string, expander: EmbeddingExpander): string[] {
  const tokens = tokenize(query);
  const expansions: string[] = [];

  for (const token of tokens) {
    const embedding = expander.wordEmbeddings.get(token);
    if (!embedding) continue;

    const similar = findSimilarWords(embedding, expander.wordEmbeddings, expander.maxExpansions);
    for (const { word, similarity } of similar) {
      if (similarity >= expander.threshold && !tokens.includes(word)) {
        expansions.push(word);
      }
    }
  }

  return [...tokens, ...expansions];
}

interface PRFConfig {
  topK: number;
  termsPerDoc: number;
  minDocFreq: number;
  maxDocFreq: number;
}

function pseudoRelevanceFeedback(query: string, searchResults: SearchResult[], config: PRFConfig): string[] {
  const topDocs = searchResults.slice(0, config.topK);
  const termFreqs = new Map<string, number>();

  for (const doc of topDocs) {
    const tokens = tokenize(doc.content);
    const seen = new Set<string>();
    for (const token of tokens) {
      if (!seen.has(token)) {
        termFreqs.set(token, (termFreqs.get(token) ?? 0) + 1);
        seen.add(token);
      }
    }
  }

  const queryTokens = new Set(tokenize(query));
  const expansionTerms = [...termFreqs.entries()]
    .filter(([term, freq]) => !queryTokens.has(term) && freq >= config.minDocFreq && freq <= config.maxDocFreq)
    .sort((a, b) => b[1] - a[1])
    .slice(0, config.termsPerDoc)
    .map(([term]) => term);

  return expansionTerms;
}
伪相关反馈（Pseudo Relevance Feedback, PRF）是另一种经典的查询扩展方法。它假设初始检索结果中排名靠前的文档是相关的，从这些文档中提取高频词项作为扩展词。RM3（Relevance Model 3）和 Bo1 是两种广泛使用的 PRF 方法。


LLM 驱动的查询改写
大语言模型为查询改写带来了质的飞跃。LLM 能够理解查询的深层意图，生成多样化的改写候选，并且处理复杂的自然语言表达。


interface LLMRewriterConfig {
  model: string;
  temperature: number;
  numRewrites: number;
  maxTokens: number;
}

function buildRewritePrompt(query: string, context?: string): string {
  const systemPrompt = `你是一个搜索查询改写专家。给定用户查询，生成多个语义等价但表达不同的改写版本，以提升搜索召回率。`;

  const userPrompt = context
    ? `原始查询：${query}\n搜索上下文：${context}\n请生成3个改写版本，每行一个：`
    : `原始查询：${query}\n请生成3个改写版本，每行一个：`;

  return `${systemPrompt}\n\n${userPrompt}`;
}

interface HyDE {
  llm: LLMClient;
  encoder: EmbeddingModel;
  retriever: DenseRetriever;
}

async function hypotheticalDocumentEmbedding(query: string, hyde: HyDE): Promise<SearchResult[]> {
  const hypotheticalDoc = await hyde.llm.generate(`请写一段简短的文章来回答以下问题：${query}`);
  const docEmbedding = await hyde.encoder.encode(hypotheticalDoc);
  return hyde.retriever.searchByVector(docEmbedding);
}
HyDE（Hypothetical Document Embedding）是 LLM 查询改写的一种创新范式。它不直接改写查询，而是让 LLM 生成一个假设性的答案文档，然后用这个假设文档的嵌入向量去检索真实文档。这种方法在零样本场景下效果显著，因为假设文档比短查询包含更丰富的语义信息。


Query2Doc 和 GRF（Generate-then-Retrieve-then-Fuse）是类似思路的变体。它们都利用 LLM 的生成能力来桥接查询和文档之间的语义鸿沟。

A/B 测试是评估查询改写在线效果的金标准。需要注意的是，查询改写对不同查询类型的影响差异很大——短查询和模糊查询通常从改写中获益最大，而已经很精确的长查询可能因为改写而引入噪声。


小结
    

  • 查询改写是弥合用户表达与文档内容语义鸿沟的核心技术，直接影响召回率和用户体验
    • 

  • 词典规则方法可控性强但覆盖有限，嵌入扩展方法自动化程度高但可能引入噪声
    • 

  • LLM 驱动的改写（HyDE、Query2Doc）在零样本场景下优势明显，但需要控制延迟和成本
    • 

  • 伪相关反馈（PRF）利用初始检索结果进行无监督扩展，是一种经典且有效的方法
    • 

  • 改写效果评估需要兼顾召回提升、意图保持和延迟影响三个维度
