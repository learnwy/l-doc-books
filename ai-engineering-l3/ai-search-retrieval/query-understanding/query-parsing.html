查询解析

核心概念

查询解析（Query Parsing）是搜索系统将用户输入的自然语言查询转化为结构化检索意图的过程。它是查询理解（Query Understanding）管线的第一步，决定了后续检索的方向和质量。查询解析需要识别查询中的实体、意图、约束条件和语义结构。

查询意图识别
查询意图识别（Query Intent Classification）将用户查询分类为预定义的意图类别，是搜索系统路由和策略选择的基础。典型的意图分类体系包括导航型（Navigational）、信息型（Informational）和交易型（Transactional）三大类。


type QueryIntent = 'navigational' | 'informational' | 'transactional' | 'local';

interface IntentClassifier {
  predict(query: string): Promise<IntentPrediction>;
  predictBatch(queries: string[]): Promise<IntentPrediction[]>;
}

interface IntentPrediction {
  intent: QueryIntent;
  confidence: number;
  subIntents: Array<{ label: string; score: number }>;
}

interface IntentFeatures {
  queryLength: number;
  hasQuestionWord: boolean;
  containsUrl: boolean;
  containsBrandName: boolean;
  containsActionVerb: boolean;
  avgWordIdf: number;
}

function extractIntentFeatures(query: string, vocabulary: Map<string, number>): IntentFeatures {
  const tokens = tokenize(query);
  const questionWords = ['什么', '怎么', '如何', '为什么', '哪里', '哪个'];
  const actionVerbs = ['购买', '下载', '注册', '预约', '比较'];

  return {
    queryLength: tokens.length,
    hasQuestionWord: tokens.some((t) => questionWords.includes(t)),
    containsUrl: /https?:\/\/|www\./.test(query),
    containsBrandName: false,
    containsActionVerb: tokens.some((t) => actionVerbs.includes(t)),
    avgWordIdf: tokens.reduce((sum, t) => sum + (vocabulary.get(t) ?? 0), 0) / tokens.length,
  };
}
在搜索引擎场景中，导航型查询（如 "GitHub 官网"）通常直接返回目标页面，信息型查询（如 "React 和 Vue 的区别"）需要展示丰富的搜索结果摘要，交易型查询（如 "iPhone 15 购买"）需要优先展示商品和价格信息。


现代方法使用 BERT 类模型进行意图分类，将查询的 [CLS] 表示输入一个全连接分类器。对于多标签场景（一个查询可能同时包含多个意图），使用 sigmoid 激活代替 softmax。


查询实体识别与链接
查询实体识别（Query NER）在查询文本中标注出有意义的实体（品牌、产品、属性、地点等），并将其链接到知识库中的规范实体。与文档级 NER 不同，查询 NER 面临文本极短、上下文不足、用户表达多样等挑战。


interface QueryEntity {
  text: string;
  start: number;
  end: number;
  type: EntityType;
  normalizedForm: string;
  linkedId?: string;
  confidence: number;
}

type EntityType = 'brand' | 'product' | 'category' | 'attribute' | 'location' | 'time';

interface EntityLinkingResult {
  entity: QueryEntity;
  candidates: Array<{
    id: string;
    name: string;
    score: number;
    popularity: number;
  }>;
  bestMatch: { id: string; name: string } | null;
}

function queryNER(query: string, model: SequenceLabeler): QueryEntity[] {
  const tokens = tokenize(query);
  const labels = model.predict(tokens);
  const entities: QueryEntity[] = [];
  let currentEntity: Partial<QueryEntity> | null = null;

  for (let i = 0; i < tokens.length; i++) {
    const label = labels[i];
    if (label.startsWith('B-')) {
      if (currentEntity) entities.push(currentEntity as QueryEntity);
      currentEntity = {
        text: tokens[i],
        start: i,
        type: label.slice(2) as EntityType,
        confidence: 0,
      };
    } else if (label.startsWith('I-') && currentEntity) {
      currentEntity.text += tokens[i];
    } else {
      if (currentEntity) entities.push(currentEntity as QueryEntity);
      currentEntity = null;
    }
  }

  if (currentEntity) entities.push(currentEntity as QueryEntity);
  return entities;
}
实体链接（Entity Linking）将识别出的实体文本映射到知识库中的标准实体。在电商搜索中，这意味着将 "苹果手机" 链接到品牌 "Apple" 和品类 "智能手机"；在通用搜索中，这意味着消歧 "苹果" 是水果还是公司。链接过程通常包括候选生成（通过别名词典和模糊匹配找到候选实体）和候选排序（通过上下文和流行度选择最佳匹配）两步。


查询分词与归一化
分词和归一化是查询解析的基础步骤，直接影响后续所有环节的质量。中文查询的分词尤为关键，错误的分词会导致实体断裂、语义扭曲。

查询纠错（Query Spell Correction）是归一化中最重要的环节之一。常见方法包括基于编辑距离的候选生成、基于 N-gram 语言模型的候选排序，以及基于 Seq2Seq 模型的端到端纠错。在搜索日志丰富的场景下，可以利用用户的查询 session 中的改写行为（"iphon → iphone"）自动挖掘纠错对。


小结
    

  • 查询解析是搜索系统的第一道关卡，将自然语言查询转化为结构化的检索意图
    • 

  • 意图分类决定了搜索策略的选择，导航型/信息型/交易型查询需要不同的检索和展示策略
    • 

  • 查询 NER 和实体链接解决了短文本实体识别和消歧问题，是精准检索的基础
    • 

  • 分词和归一化质量直接影响检索效果，中文分词、同义词归一化和查询纠错是重点环节
    • 

  • 现代查询解析趋向端到端的神经网络方法，但规则和词典在处理长尾 case 时仍不可替代
    •
