提示词即规约

核心概念

在传统软件中，PRD（Product Requirements Document）是产品规约的载体——一份描述"产品应该做什么"的自然语言文档。在 AI 产品中，提示词（prompt）扮演着比 PRD 更精确、更可执行、也更可被回归测试的规约角色。本节论证为什么提示词应当被视为 AI 产品的真实规约，并讨论提示词工程化的核心实践：版本化、模板化、回归保护、上线流程。

为什么提示词比 PRD 更适合做规约
提示词作为规约有三个传统 PRD 难以企及的优势：


直接可执行：提示词不需要研发"翻译"成代码逻辑，模型直接读懂并执行。这意味着 PM 写下的内容就是产品最终行为的源头，消除了"PM 写一份意图、研发实现另一份意图"的偏差累积。 变更立即可测：修改提示词后，立即可以用评测集跑一遍看分数变化。这种快速反馈循环让 PM 真正"持有"产品行为，而不是把决策权委托给翻译过程。 版本可回滚：提示词是纯文本，可以用 Git 管理。每一次产品行为的演化都有 commit 记录，回滚到任何历史版本都是一行命令的事。


但提示词作为规约也有局限：


    

  • 不能涵盖所有维度：UI、交互、性能、运营等非 AI 部分仍需传统 PRD 描述。
    • 

  • 依赖模型行为：同一份提示词在不同模型上行为可能差异巨大，所以提示词必须与模型版本绑定。
    • 

  • 可读性挑战：高度优化的提示词（包含 few-shot、CoT 链、JSON Schema 等）对非技术读者不友好。
    • 



提示词模板的结构化
把提示词工程化的第一步是"结构化"——把一坨长文本拆成可复用的组件。一个典型的结构化提示词模板包含以下层次：


每个层次都可以独立维护和测试：


    

  • 系统提示：定义 AI 的角色、任务边界、风格、安全约束。这是变更最少但影响最大的部分。
    • 

  • 少样本示例：通过 2-5 个高质量示例让模型理解期望行为。修改示例的影响往往大于修改文字描述。
    • 

  • 输入数据：用户输入与检索上下文，由产品逻辑动态填充。
    • 

  • 输出约束：JSON Schema、特定字段、长度限制等结构化要求。
    • 



模板化让团队能像维护代码一样维护提示词——每个组件有明确的责任、变更历史、测试覆盖。


提示词的版本化
把提示词放入 Git 是版本化的最低门槛。但完整的版本化还需要：


    

  • 语义化版本号：v1.0.0 / v1.1.0 / v2.0.0 等版本号，让团队能引用具体版本。
    • 

  • 变更日志：每次版本更新记录"修改了什么、为什么、评测分数如何变化"。
    • 

  • 基线快照：每个稳定版本对应的评测分数被保留下来，作为后续回归比较的基线。
    • 

  • A/B 标签：实验性版本与稳定版本并存，让生产环境能在不同流量上跑不同提示词。
    • 



版本化的最大价值是把"提示词改动"从"凭直觉的尝试"升级为"有依据的工程实验"。每次改动都有基线对比，每次决策都有指标支撑。


提示词的回归保护
仅有版本化还不够。提示词必须有自动化回归测试，否则改动 A 修复了某个问题，可能悄悄破坏了另外两个原本工作良好的场景。回归保护的最低实践：


    

  • 核心场景固化：把产品最关键的 20-50 个场景做成回归集，每次提示词变更时自动跑一遍。
    • 

  • 基线分数门禁：回归集分数下降超过阈值（如 2%）时阻止合并。
    • 

  • 分维度回归：除了总分，还跟踪每个评测维度（正确性、风格、安全性）的分数变化，便于定位问题。
    • 

  • 真实流量抽样：定期从生产真实输入中抽样补充评测集，让回归集与真实分布保持同步。
    • 



回归保护的工程实现可以利用标准的 CI/CD 工具——每次提示词 PR 触发评测脚本，结果以 GitHub Check 形式呈现。这种把传统 CI 思想引入 AI 产品的做法，是提示词工程化的最终形态。

特别要强调"一键回滚"的重要性。提示词改动可能在测试中表现良好但在生产真实分布下出问题。准备好让产品经理或值班工程师用一行命令切回稳定版的能力，能让团队敢于尝试新的提示词改进。


与 PRD 的关系
提示词替代不了 PRD 的全部功能。在成熟的 AI 产品团队中，二者通常是这样分工的：


    

  • PRD 描述：业务目标、用户场景、UI 交互、运营策略、合规约束。
    • 

  • 提示词描述：AI 行为规则、输出格式、拒答策略、少样本示例。
    • 

  • 评测集描述：什么样的输出算合格——是 PRD 与提示词共同的"客观仲裁者"。
    • 



实践中，PM 应该同时持有 PRD 与提示词的所有权——前者描述"产品长什么样"，后者定义"AI 怎么响应"。把提示词当作 PM 的核心交付物（而不是研发的实现细节），是 AI 产品组织升级的关键一步。


小结
提示词作为规约不是营销概念，而是 AI 产品方法论的一个核心实践。它把 PM 的产品意图直接转化为可执行、可测试、可版本化的产物，消除了传统软件中"意图与实现的偏差累积"。结构化、版本化、回归保护、规范化的上线流程——这四个工程实践把提示词从"灵光一闪的提示"升级为"可工程化交付的产品规约"。在团队组织上，让 PM 直接持有提示词的编辑权与 review 权（而不是把它当作研发内部细节），能让 AI 产品决策的链路从"PM 写文档 → 研发翻译 → 模型执行"缩短为"PM 写提示 → 模型执行"，决策速度与产品质量同时提升。
