延迟与流式响应设计

核心概念

LLM 推理的本质特征之一是高延迟：一次复杂的 GPT-4 调用可能耗时 5-15 秒，远高于传统 API 的几十毫秒。在这种约束下，如果仍然按照"loading 转圈圈、等结果一次性返回"的传统 UX 模式设计，用户的耐心几乎注定崩溃。延迟与流式响应设计是把"漫长的等待"变成"持续的进展感"的核心方法论。

流式 Token 渲染
流式 token 渲染是 LLM 产品最基础也最高 ROI 的延迟优化。现代 LLM API 都支持 server-sent events（SSE）流式输出，前端只需把每个 token 实时追加到界面即可。这一改动看似简单，但对用户感知的影响是颠覆性的——用户从"等待 10 秒"变成"持续阅读 10 秒"，主观延迟感受可降低 80% 以上。


流式渲染的实现细节：


    

  • 首字延迟（Time To First Token, TTFT）：流式渲染的关键指标。TTFT 在 500ms 以内时用户感知"反应灵敏"，超过 1.5 秒时用户开始怀疑是否卡死。优化方向包括缩短系统提示、使用更小的模型、就近部署、连接复用。
    • 

  • token 渲染节奏：模型生成 token 的速度可能突然变慢或变快。前端可以加平滑算法（如基于固定速率的渲染队列）让 token 出现节奏更均匀，提升阅读体验。
    • 

  • Markdown 增量渲染：流式输出 Markdown 时，每个 token 到达都要重新渲染整段。性能要点是在 token 边界处使用增量解析器，避免每次都从头解析。
    • 

  • 错误中断恢复：流式输出可能中途断开。设计要点：断开时保留已输出内容；提供"继续生成"按钮；内部记录已输出 token 数以便接续。
    • 



阶段性反馈与思考过程
对于涉及多步推理或工具调用的 Agent 类产品，单纯流式输出最终答案仍可能感觉漫长。把"AI 正在做什么"持续告知用户，能显著降低焦虑。


阶段性反馈的设计模式：


    

  • 状态条带：界面顶部展示当前阶段（如"正在搜索""正在分析""正在生成"），让用户始终知道 AI 处于哪一步。
    • 

  • 可展开思考过程：把 AI 的内部推理过程以折叠形式呈现，用户可以选择展开查看详细步骤。这同时增强透明度与减少焦虑。
    • 

  • 资产逐步出现：搜索结果先出现，然后是分析卡片，最后是结论。让用户在等待过程中已经能开始浏览有用信息。
    • 

  • 预估剩余时间：对于可预估的任务，给出"大约还需 5 秒"的提示。但要注意预估必须可靠——预估错误反而比不预估更损害信任。
    • 



阶段性反馈的关键是真实性。如果"正在搜索文档"实际上只是一个固定 1 秒的占位文本，用户很快会识破并失去信任。每个阶段提示应该真实对应底层正在执行的步骤。


推测式预览
最高级的延迟优化是推测式预览（speculative preview）：在用户尚未完成输入时就开始预测可能的输入并预先调用模型，等用户真正按下回车时直接显示已计算好的结果。GitHub Copilot 的代码补全、Gmail 的 Smart Compose 都使用了这一模式。


推测式预览的实现要点：


    

  • 预测时机：用户停顿超过 100ms 时启动推测；用户继续输入时取消上一次推测。
    • 

  • 取消与去重：必须有可靠的取消机制避免浪费的 API 调用。
    • 

  • 结果缓存：相同输入的推测结果应缓存，避免重复推理。
    • 

  • 成本控制：推测式预览会显著增加 API 调用量（很多预测会被取消），需要评估成本与体验的权衡。
    • 



后台异步与通知
对于真正的长任务（数据分析、视频生成、深度调研），同步等待已不现实。这类场景需要后台异步执行 + 完成通知的设计：


    

  • 明确预期：在用户提交任务时清晰告知"预计需要 5 分钟，完成后将通知您"。
    • 

  • 可关闭页面：任务在服务端继续执行，用户关闭页面后再回来仍能查看结果。
    • 

  • 多通道通知：完成时通过页内提示、邮件、push 通知等多个渠道告知。
    • 

  • 进度可见：任务列表展示所有进行中的任务及其进度。
    • 



后台异步模式的核心是"把长等待从前台搬到后台"。用户在等待期间可以做其他事，避免了"盯着 loading 转圈"的心理消耗。

在产品设计阶段就应该明确每个 AI 功能所属的延迟场景，并选择对应的设计模式。把后台任务做成同步等待是常见错误，会显著拉低用户耐心；反过来把对话场景做成后台通知则破坏了实时交互的流畅感。


小结
延迟设计是 AI 产品 UX 的隐形地基。流式渲染、阶段性反馈、推测式预览、后台异步——这四类模式覆盖了从亚秒级到分钟级的全部延迟场景。把"实际延迟"与"感知延迟"区分开是设计师的核心能力——前者由模型与基础设施决定，后者由 UX 决定。即使在底层模型推理速度无法立刻改善的现实下，优秀的延迟 UX 设计可以让用户主观体验提升 5-10 倍。把"用户在等待时看到了什么、做了什么、相信了什么"作为设计评审的固定问题，能让 AI 产品从"功能能用"升级为"体验流畅"。
