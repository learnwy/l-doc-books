成本优化

核心概念

成本优化的手段按「省钱发生在哪一步」排列，核心概念如下：

  • 成本构成：计算（GPU 推理时间）、Token（按调用量计费）、基础设施（存储、网络、运维）三部分，优化空间差异很大。
  • Token 经济学：输入/输出单价不同、输出通常贵数倍；推理模型的思考 token 按输出计费，预算需按可见输出乘放大系数。
  • 缓存层次：精确缓存（完全相同的请求）、语义缓存（语义相似的查询）、Prompt 缓存（相同前缀的长系统提示），是投入产出比最高的手段。
  • 模型路由：按查询复杂度动态选模型，简单问题交给小模型，在质量与成本之间取平衡。
  • 批处理与自部署：批量 API 可显著降费，请求量足够大时自部署开源模型比按量调用更经济。

一条主线是**「先减少不必要的 token，再降低每个 token 的单价」**——缓存和提示精简属于前者，模型路由与自部署属于后者，顺序反了往往收效有限。

LLM 成本构成

在大规模部署 LLM 时，成本控制是工程决策的核心考量之一。LLM 的成本主要来自三个方面：推理计算、模型存储和数据传输。

flowchart TB
    Cost["LLM 总成本"]
    Cost --> Compute["计算成本<br/>GPU 推理时间"]
    Cost --> Token["Token 成本<br/>按调用量计费"]
    Cost --> Infra["基础设施<br/>存储、网络、运维"]
成本项 计费方式 优化空间
API 调用 按 token 计费 大
自部署 GPU 按时间/实例 中
存储 模型文件大小 小
网络 数据传输量 小

Token 经济学

理解 token 计费模型是成本优化的基础：

def estimate_monthly_cost(model_pricing, daily_requests, avg_input_tokens, avg_output_tokens):
    monthly_requests = daily_requests * 30
    input_cost = (monthly_requests * avg_input_tokens / 1e6) * model_pricing["input"]
    output_cost = (monthly_requests * avg_output_tokens / 1e6) * model_pricing["output"]
    return input_cost + output_cost

cost = estimate_monthly_cost(
    pricing["GPT-5"],
    daily_requests=10000,
    avg_input_tokens=1000,
    avg_output_tokens=500
)
print(f"\nGPT-5 月成本估算 (10K 请求/天): ${cost:,.2f}")

提示（2026 年中的两个新变量）： 其一，推理 token 计费——GPT-5 思考模式、Claude 扩展思考、Gemini 思考等推理模型的思维链按输出 token 计费，复杂任务的真实输出量可达可见答案的数倍，预算需按「可见输出 × 放大系数」预估。其二，缓存已成显式价格档——据各厂商定价页：OpenAI 缓存命中输入约为标价的 1/10；Anthropic 缓存写入加价 25%、读取降至标价的 1/10；DeepSeek 缓存命中输入低至约 $0.028/M。长系统提示场景下，缓存优先于其他一切优化。

缓存策略

缓存是最直接的成本优化手段——对相同或相似查询直接返回缓存结果：

flowchart LR
    Q["用户查询"] --> Cache["缓存检查"]
    Cache -->|"命中"| R1["直接返回<br/>成本 = 0"]
    Cache -->|"未命中"| LLM["LLM 推理"]
    LLM --> Save["保存到缓存"]
    Save --> R2["返回结果"]
import hashlib
import json

class LLMCache:
    def __init__(self):
        self.exact_cache = {}
        self.semantic_cache = None
        self.stats = {"hits": 0, "misses": 0}

    def get_key(self, messages, model, temperature):
        content = json.dumps({"messages": messages, "model": model, "temp": temperature})
        return hashlib.sha256(content.encode()).hexdigest()

    def get(self, messages, model, temperature=0):
        if temperature > 0:
            self.stats["misses"] += 1
            return None

        key = self.get_key(messages, model, temperature)
        if key in self.exact_cache:
            self.stats["hits"] += 1
            return self.exact_cache[key]

        self.stats["misses"] += 1
        return None

    def set(self, messages, model, temperature, response):
        if temperature == 0:
            key = self.get_key(messages, model, temperature)
            self.exact_cache[key] = response

    @property
    def hit_rate(self):
        total = self.stats["hits"] + self.stats["misses"]
        return self.stats["hits"] / total if total > 0 else 0

cache = LLMCache()
print(f"缓存命中率: {cache.hit_rate:.0%}")
print("注意: 只有确定性输出 (temperature=0) 才适合精确缓存")
缓存类型 命中条件 适用场景 存储需求
精确缓存 完全相同的请求 确定性查询 低
语义缓存 语义相似的查询 通用问答 中
Prompt 缓存 相同前缀的请求 长系统提示 低

提示： Anthropic 的 Prompt Caching 功能可以缓存系统提示和长文档的预计算结果，将重复请求的输入 token 成本降低 90%。

模型路由

模型路由（Model Routing）根据查询的复杂度自动选择合适的模型，用小模型处理简单问题，只在必要时使用大模型：

flowchart TB
    Q["用户查询"] --> Router["路由器<br/>(复杂度判断)"]
    Router -->|"简单"| Small["小模型<br/>GPT-5 mini<br/>$0.25/M"]
    Router -->|"中等"| Medium["中等模型<br/>Claude Haiku 4.5<br/>$1.00/M"]
    Router -->|"复杂"| Large["大模型<br/>Claude Opus 4.5<br/>$5.00/M"]
class ModelRouter:
    def __init__(self):
        self.models = {
            "simple": {"name": "gpt-5-mini", "cost_per_1m": 0.25},
            "medium": {"name": "claude-haiku-4-5", "cost_per_1m": 1.00},
            "complex": {"name": "claude-opus-4-5", "cost_per_1m": 5.00},
        }

    def classify_complexity(self, query):
        if len(query) < 50 and "?" in query:
            return "simple"
        elif any(kw in query for kw in ["分析", "比较", "设计", "优化"]):
            return "complex"
        else:
            return "medium"

    def route(self, query):
        complexity = self.classify_complexity(query)
        model = self.models[complexity]
        return model

router = ModelRouter()
test_queries = [
    "1+1=?",
    "帮我写一段 Python 排序代码",
    "分析 Transformer 架构与 Mamba 架构的优缺点并设计混合方案",
]

for q in test_queries:
    model = router.route(q)
    print(f"查询: {q[:30]}...")
    print(f"  → 路由到: {model['name']} (${model['cost_per_1m']}/M tokens)\n")

小结

  • LLM 成本主要来自 token 计费和 GPU 推理，需要从多个维度优化。
  • Token 经济学是成本规划的基础，不同模型的性价比差异巨大；推理模型时代还必须把不可见的思考 token 计入预算。
  • 缓存（精确 + 语义 + Prompt）是投入产出比最高的优化策略。
  • 模型路由根据复杂度动态选择模型，在质量和成本之间取得平衡。
  • 当请求量足够大时，自部署开源模型比 API 调用更经济。
