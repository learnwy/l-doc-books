RAG 架构

什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）通过在生成前检索相关文档，为 LLM 提供外部知识支持，从而减少幻觉并使回答基于事实。

Naive RAG
最基础的 RAG 架构包含索引、检索和生成三个阶段：


def naive_rag(query, retriever, llm, top_k=3):
    relevant_docs = retriever.search(query, top_k=top_k)

    context = "\n\n".join([doc.content for doc in relevant_docs])

    prompt = f"""基于以下参考文档回答用户问题。如果文档中没有相关信息，请明确说明。

参考文档：
{context}

用户问题：{query}

回答："""

    answer = llm.generate(prompt)
    return answer

print("Naive RAG 流程: 查询 → 检索 → 拼接 → 生成")

def rerank_documents(query, documents, top_k=3):
    pairs = [(query, doc) for doc in documents]
    # scores = reranker.predict(pairs)
    scores = [0.9, 0.3, 0.7, 0.1, 0.8]  # 示例分数
    ranked = sorted(zip(documents, scores), key=lambda x: x[1], reverse=True)
    return ranked[:top_k]

docs = ["Transformer 架构详解", "今日股市行情", "注意力机制原理", "天气预报", "BERT 预训练方法"]

for doc, score in results:
    print(f"  [{score:.2f}] {doc}")


Modular RAG
Modular RAG 将 RAG 系统分解为可独立替换和组合的模块：


class ModularRAG:
    def __init__(self, query_module, retriever, reranker, compressor, generator, verifier=None):
        self.query_module = query_module
        self.retriever = retriever
        self.reranker = reranker
        self.compressor = compressor
        self.generator = generator
        self.verifier = verifier

    def run(self, query):
        transformed_query = self.query_module.transform(query)
        candidates = self.retriever.search(transformed_query, top_k=20)
        reranked = self.reranker.rerank(query, candidates, top_k=5)
        compressed = self.compressor.compress(reranked)
        answer = self.generator.generate(query, compressed)

        if self.verifier:
            answer = self.verifier.verify(answer, compressed)

        return answer

print("Modular RAG: 每个模块可独立升级和替换")

提示： RAG 系统的性能瓶颈通常在检索环节，而非生成环节。投入更多精力优化分块、嵌入和检索策略，通常比更换更强的 LLM 更有效。






小结
    

  • RAG 通过检索外部文档为 LLM 提供知识支撑，有效减少幻觉。
    • 

  • Naive RAG 存在检索不准、噪声干扰等问题，需要进阶优化。
    • 

  • Advanced RAG 通过查询转换、重排序和上下文压缩显著提升效果。
    • 

  • Modular RAG 将系统分解为可替换模块，便于迭代和维护。
    • 

  • 检索质量是 RAG 系统成败的关键，需要优先投入优化。
