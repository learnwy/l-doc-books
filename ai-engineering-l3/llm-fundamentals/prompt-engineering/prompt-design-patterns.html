提示词设计模式

提示词工程概述

提示词工程（Prompt Engineering）是通过精心设计输入提示来引导 LLM 产生期望输出的技术。好的提示词能显著提升模型输出质量，无需修改模型参数。



角色设计
通过系统提示定义 LLM 的角色，可以显著影响输出的风格、深度和专业性：


role_examples = {
    "通用助手": {
        "system": "你是一个乐于助人的 AI 助手。",
        "特点": "通用、友好、简洁",
    },
    "专家角色": {
        "system": (
            "你是一位资深的机器学习工程师，拥有 10 年的深度学习经验。"
            "你擅长用简单的语言解释复杂概念，并提供可运行的代码示例。"
        ),
        "特点": "专业深度、代码导向",
    },
    "教学角色": {
        "system": (
            "你是一位耐心的 AI 课程教师。遵循以下教学原则：\n"
            "1. 从最简单的概念开始\n"
            "2. 使用类比帮助理解\n"
            "3. 每个概念附带一个例子\n"
            "4. 循序渐进，不跳跃"
        ),
        "特点": "渐进式教学、类比丰富",
    },
}

for role, info in role_examples.items():
    print(f"角色: {role}")
    print(f"  系统提示: {info['system'][:50]}...")
    print(f"  特点: {info['特点']}\n")

提示词模板
结构化的提示词模板能确保输出的一致性和质量：


def create_prompt(template, **kwargs):
    return template.format(**kwargs)

analysis_template = """## 任务
分析以下{domain}概念，并提供详细解释。

## 概念
{concept}

## 输出要求
1. 一句话定义
2. 核心原理（2-3 段）
3. 一个代码示例
4. 常见应用场景
5. 注意事项

## 约束
- 使用中文回答
- 代码使用 Python
- 控制在 500 字以内"""

prompt = create_prompt(
    analysis_template,
    domain="深度学习",
    concept="注意力机制"
)
print(prompt)


常用设计模式
分步指令模式
step_by_step_prompt = """请按以下步骤完成任务：

步骤 1: 阅读并理解用户的问题
步骤 2: 识别问题中的关键概念
步骤 3: 组织回答的逻辑结构
步骤 4: 编写回答，确保准确性
步骤 5: 检查回答是否完整

用户问题：{question}"""

print(step_by_step_prompt.format(question="解释什么是 KV Cache？"))
输入-输出示例模式
io_example_prompt = """将技术术语翻译为通俗解释。

输入: Gradient Descent
输出: 梯度下降就像在雾天下山，每一步都朝着最陡的方向走一小步，最终到达山谷。

输入: Overfitting
输出: 过拟合就像学生只会做练习题原题，换个题目就不会了。模型记住了训练数据的噪声而非规律。

输入: {term}
输出:"""

print(io_example_prompt.format(term="Attention Mechanism"))
约束增强模式
constraint_prompt = """回答以下问题。

约束：
- 回答长度不超过 200 字
- 使用 Markdown 格式
- 至少包含一个代码示例
- 如果不确定，明确说明
- 不要使用"据我所知"等模糊表述

问题：{question}"""

print(constraint_prompt.format(question="如何实现 LoRA 微调？"))

反面模式与避坑
anti_patterns = {
    "过于模糊": {
        "差": "帮我写点代码",
        "好": "用 Python 写一个函数，输入一个字符串列表，返回按长度降序排列的结果",
    },
    "信息过载": {
        "差": "你是一个精通所有编程语言的全栈开发者...(500字角色描述)",
        "好": "你是一个 Python 后端开发专家。回答时提供可运行的代码。",
    },
    "矛盾指令": {
        "差": "简洁回答，并提供详细的逐步解释",
        "好": "提供简洁的总结（2-3句），然后附上详细步骤",
    },
}

for pattern, examples in anti_patterns.items():
    print(f"反模式: {pattern}")
    print(f"  ❌ {examples['差']}")
    print(f"  ✅ {examples['好']}\n")


提示： 好的提示词像好的需求文档——明确、具体、无歧义。当模型输出不符合预期时，先检查提示词是否有歧义，而非直接怀疑模型能力。






小结
    

  • 系统提示定义角色、专长和约束，是控制输出质量的第一道关卡。
    • 

  • 结构化模板（任务 + 上下文 + 格式 + 约束）确保输出的一致性。
    • 

  • 常用模式包括角色扮演、分步指令、输入输出示例和约束增强。
    • 

  • 避免模糊指令、信息过载和矛盾约束等反面模式。
    • 

  • 提示词设计是迭代过程，需要根据输出反馈持续调优。
