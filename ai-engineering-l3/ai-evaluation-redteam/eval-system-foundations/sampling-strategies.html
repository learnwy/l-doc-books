评测集采样策略

核心概念

评测集质量的核心决定因素是样本分布——评测集中各类场景的占比是否反映真实使用分布。一个分布偏差大的评测集即使样本规模大也无法给出有意义的分数。本节系统讲解评测集的采样策略：分层采样、边界采样、对抗采样、长尾采样，让团队能构造出真正反映产品质量的评测集。

分层采样
分层采样把评测集按重要维度分层，每层按比例采样。常见分层维度：


    

  • 按用户群：新用户 / 活跃用户 / 流失用户的需求差异巨大。
    • 

  • 按场景：搜索、写作、问答等不同场景的成功标准不同。
    • 

  • 按难度：简单 / 中等 / 困难三档让评测分数能反映模型的真实能力曲线。
    • 

  • 按地理 / 语言：跨地区产品需要按市场分层。
    • 



分层比例的选择不是"按真实使用分布平均"，而是"按业务重要性加权"——核心场景占比更高，长尾场景占比更低。例如客服产品中，"如何退款"这种高频核心问题应该有 50+ 条样本，而"罕见的产品咨询"可能只有 3-5 条。


边界采样
边界样本是模型最容易出错的地方，也是产品质量真正的瓶颈。主动构造边界样本是评测集构建中最有挑战也最有价值的环节。常见边界类型：


    

  • 模糊输入：用户表达不清晰、缺少关键信息的请求。
    • 

  • 跨领域问题：横跨产品边界的请求（"既问医疗又问法律"）。
    • 

  • 复杂逻辑：需要多步推理、对比、综合判断的场景。
    • 

  • 冲突需求：用户表达矛盾或自相矛盾的请求。
    • 

  • 超长输入：远超日常长度的输入（10k token 以上）。
    • 

  • 空输入：完全无内容或仅含标点的输入。
    • 



边界采样的工程实践：每周从生产环境中筛选模型置信度低、用户重新提问、标注分歧大的样本，加入候选池。每月让领域专家从候选池中挑选最有诊断价值的样本加入评测集。


对抗采样
对抗采样是专门构造的攻击性输入，用于检验产品的安全边界。主要类型：


    

  • 越狱尝试：通过角色扮演、隐喻、特殊指令试图突破安全约束。
    • 

  • Prompt 注入：在用户输入或检索文档中嵌入恶意指令。
    • 

  • 数据提取：试图诱导模型输出系统提示、其他用户内容、训练数据。
    • 

  • 有害生成：试图诱导模型生成违禁、歧视、虚假内容。
    • 

  • 资源攻击：通过超长输入、高频请求等让模型资源耗尽。
    • 



对抗采样的来源：


    

  • 红队测试发现的有效攻击。
    • 

  • 公开的越狱数据集（JailbreakBench、HarmBench 等）。
    • 

  • 从社区论坛（Reddit、Twitter）收集真实用户的越狱尝试。
    • 

  • 自动化生成（用 LLM 生成对抗样本，再人工筛选有效的）。
    • 



长尾采样
长尾样本是罕见但关键的场景——日常发生频率低但一旦失败影响大。例如医疗产品中的"罕见疾病诊断"、自动驾驶中的"突发交通管制"。长尾采样的挑战是数据稀缺——这些场景在真实使用中天然样本量小。


长尾采样的常见方法：


    

  • 专家访谈：让领域专家列出"罕见但关键"的场景清单。
    • 

  • 业务记录：从客服工单、事故报告等记录中筛选罕见 case。
    • 

  • 合成样本：用专家描述的场景模板，通过参数变换生成多个变种。
    • 

  • 跨产品借鉴：从同行业产品的失败案例中借鉴。
    • 



数据脱敏与合规
从真实数据采样必须经过脱敏处理：


    

  • PII 移除：电话、邮箱、身份证等个人信息必须替换或匿名化。
    • 

  • 业务敏感数据：内部价格、未公开战略等需要授权才能加入评测集。
    • 

  • 法规合规：GDPR、CCPA 等法规对数据使用有严格要求，需要法务审核。
    • 

  • 数据保留期：评测集中的数据保留期需要符合公司数据治理政策。
    • 



脱敏不仅是合规要求，也是工程必要——评测集会被多人查看、写入文档、嵌入 CI，任何敏感信息泄露都可能造成严重事故。

小结
评测集的采样策略决定了它是否真正反映产品质量。分层采样保证主流场景的覆盖，边界采样暴露模型能力上限，对抗采样守护安全底线，长尾采样防御罕见但关键的失败模式。把采样策略作为评测集构建的核心工程问题——而不是凭直觉抓样本——是从业余评测走向专业评测的分水岭。一份采样精心设计的 200 条评测集，可能比凭直觉抓的 1000 条评测集更有价值。每个新加入评测集的样本都应该回答一个问题：它能让评测集变得更"有诊断力"还是只是增加噪声？
