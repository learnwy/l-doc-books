评测 Harness 框架

核心概念

评测 Harness 框架是把"零散的评测脚本"工程化为"标准评测基础设施"的工具。它管理评测集、调度模型调用、聚合分数、追踪历史、可视化结果——让团队不必"重复发明轮子"。当前主流的开源框架——Promptfoo、DeepEval、Braintrust、Inspect 等——各有设计哲学与适用场景。本节系统介绍这些框架，讨论选型考量与最佳实践，让团队能从社区成熟工具起步。

Promptfoo：CLI 优先
Promptfoo 是当前最流行的开源评测框架之一。其核心设计：


    

  • YAML 配置：评测集和评测配置都用 YAML 描述，对工程师友好。
    • 

  • CLI 优先：promptfoo eval 一行命令跑评测，输出表格式结果。
    • 

  • 多模型对比：原生支持同时跑多个模型的对比。
    • 

  • 多种 Assertion：支持包含、正则、相似度、LLM-as-Judge 等多种判断方式。
    • 

  • CI 集成简单：输出 JUnit 等格式，能直接接入 GitHub Actions。
    • 



典型配置示例：


prompts:
  - file://prompts/customer-service.txt

providers:
  - openai:gpt-4
  - anthropic:claude-3-opus

tests:
  - vars:
      question: '如何退款'
    assert:
      - type: contains
        value: '退款流程'
      - type: llm-rubric
        value: '回答应该清晰、友好、提供具体步骤'
Promptfoo 适合：


    

  • 中小型项目快速搭建评测。
    • 

  • 提示词工程师做 prompt 对比实验。
    • 

  • CI 中的简单回归保护。
    • 



DeepEval：Python 与 pytest
DeepEval 是 Python 优先的评测框架，与 pytest 深度集成。其特色：


    

  • Pythonic API：用熟悉的 Python 代码写评测，适合 Python 团队。
    • 

  • pytest 集成：评测可以作为 pytest 测试运行，与现有 CI 无缝集成。
    • 

  • 丰富的 Metrics：内置多种评测指标（hallucination、toxicity、bias 等）。
    • 

  • 追溯链路：与 LLM 调用追溯（tracing）框架集成。
    • 



示例代码：


from deepeval import assert_test
from deepeval.metrics import HallucinationMetric

def test_hallucination():
    metric = HallucinationMetric(threshold=0.5)
    test_case = LLMTestCase(
        input="什么是黑洞？",
        actual_output=model_response,
        retrieval_context=[ground_truth]
    )
    assert_test(test_case, [metric])
DeepEval 适合：


    

  • Python 工程团队。
    • 

  • 已有完整 pytest 测试体系，希望评测无缝接入。
    • 

  • 需要丰富内置指标的快速搭建。
    • 



Braintrust：商业协作平台
Braintrust 是商业评测平台，强项是团队协作与可视化：


    

  • 共享工作空间：团队成员能共享评测集、查看历史、对比实验。
    • 

  • 强可视化：评测结果以丰富的图表呈现，包括分数分布、失败样本浏览、AB 对比。
    • 

  • 数据集管理：内置评测集版本化、标注流水线、数据增强工具。
    • 

  • API 灵活：能从任何代码库调用，不限于特定语言。
    • 



Braintrust 适合：


    

  • 中大型团队需要协作评测。
    • 

  • 重视可视化和报告的团队。
    • 

  • 有预算购买商业服务的项目。
    • 



LangSmith：LangChain 生态
LangSmith 是 LangChain 团队提供的评测平台，与 LangChain 框架深度集成：


    

  • LangChain 原生：LangChain 用户能从已有的 chain/agent 直接接入评测。
    • 

  • 追溯（Tracing）：每次调用的完整链路都能追溯，方便调试。
    • 

  • 协作平台：类似 Braintrust 的团队协作能力。
    • 



LangSmith 适合：


    

  • 已经使用 LangChain 的团队。
    • 

  • 需要把 LangChain agent 的执行链路可视化的场景。
    • 



Inspect：安全评测专用
Inspect 是 UK AI Safety Institute 发布的开源框架，专门为 AI 安全评测设计：


    

  • 学术风格：API 偏向学术研究，适合发表论文。
    • 

  • 安全维度：内置安全相关的评测能力（多种红队基准）。
    • 

  • 可重现性：强调可重现的评测协议，适合严肃安全研究。
    • 



Inspect 适合：


    

  • 学术安全研究。
    • 

  • 需要严格可重现性的政府或合规场景。
    •

自建 vs 使用框架
很多团队最初会自建一套简单的评测脚本——读 YAML、调模型、对比结果、输出 JSON。这种最小实现能在第一天跑起来。但随着需求复杂化（多模型对比、可视化、协作），自建成本快速上升。


通常的演进路径：


    

  1. 第 1 周：自建 50 行 Python 脚本，先跑通流程。
    2. 

  2. 第 2-4 周：评测集扩大、需求增多，自建脚本臃肿。
    3. 

  3. 第 5-8 周：迁移到成熟框架（通常 Promptfoo 或 DeepEval）。
    4. 

  4. 第 3-6 月：随团队成长，可能升级到商业平台。
    5. 



迁移成本不小，所以越早评估并选择合适框架越好。


框架与公司基础设施集成
把评测框架与公司其他基础设施集成：


    

  • 模型 API 网关：通过统一网关调模型，便于成本控制、配额管理。
    • 

  • CI/CD：每次提示词、模型、RAG 索引变更触发评测。
    • 

  • 追溯系统：评测中的每次模型调用记录到 LangSmith / Helicone。
    • 

  • 告警系统：评测分数下降触发 PagerDuty 等告警。
    • 

  • 数据仓库：评测历史结果导入数据仓库，做长期趋势分析。
    • 



常见陷阱
使用评测框架时的常见陷阱：


    

  • 被框架特性绑死：把所有逻辑都用框架特性写，未来迁移困难。规避：保持业务逻辑独立。
    • 

  • 忽视成本：商业平台的成本可能爆炸，特别是大量 LLM-as-Judge 调用。规避：成本监控+预算上限。
    • 

  • 数据隐私问题：商业平台可能让评测数据进入第三方。规避：敏感数据用自部署或脱敏。
    • 

  • 框架版本漂移：框架更新可能改变 API 或行为。规避：锁定版本，定期升级。
    • 



小结
评测 Harness 框架是 AI 评测工程化的重要基础设施。从开源的 Promptfoo、DeepEval、Inspect，到商业的 Braintrust、LangSmith，每个框架有各自的设计哲学与适用场景。把"自建评测脚本"升级为"使用成熟框架"是评测能力工程化的关键一步——能让团队聚焦在评测集本身和评测策略，而不是基础设施。在选型上避免"什么火用什么"，根据团队规模、技术栈、预算、合规需求做决策。框架的好坏不在于功能多寡，而在于"对你的具体场景是否合适"。
