智能体为何需要记忆

你跟一个客服智能体聊了二十分钟，把退货原因、订单号、收货地址全都说清楚了，第二天再打开同一个对话框，它却像第一次见你——这不是 bug，而是大语言模型的默认状态。模型本身不存任何东西，它的「记忆」全靠工程师在外面搭。这一篇要说清楚：这种健忘从何而来、为什么必须解决、以及解决之后智能体能多出哪些以前做不到的能力。

核心概念：无状态的模型与有状态的智能体

大语言模型在数学上是一个纯函数：给定一段输入 token 序列，输出下一个 token 的概率分布。同样的输入永远得到同样的分布（采样随机性除外），它不携带任何跨调用的状态。模型权重在训练后就冻结了，推理阶段不会因为你跟它聊了什么而改变一个比特。

这意味着「记忆」从来不在模型里，而是一层外部系统：把过往信息存到模型之外，在下一次调用时挑出相关的部分，拼进输入序列再喂回去。智能体之所以显得「记得」，是因为这层系统每次都把该带的上下文带上了。

flowchart TD
    A[用户输入] --> B[记忆检索<br/>挑出相关历史]
    B --> C[上下文组装<br/>拼成提示词]
    C --> D[无状态 LLM 调用]
    D --> E[生成回复]
    E --> F[记忆写入<br/>存下新信息]
    F -.下一轮.-> B
    D -.权重冻结<br/>不携带状态.-> D

下表对比两者的本质差异，理解这张表是理解整个 hub 的前提：

维度 无状态的 LLM 有记忆的智能体
状态归属 无，纯函数 外部记忆系统持有
跨会话连贯 不可能 可跨天、跨月
个性化 仅靠每次手动重述 自动调用用户画像
长任务 受单次窗口限制 可分解、可续接
信息时效 停在训练截止日 可写入实时新事实

记忆的分类与各自的存储形态会在记忆类型分类里展开，这里只需记住一个分界：模型是无状态的，状态全在外部。

健忘的代价：四个具体场景

抽象地说「模型记不住」没有说服力，看四个会真实出问题的场景。

多轮对话的指代崩溃。 用户先说「帮我订下周三飞上海的票」，几轮后补一句「改成靠窗的」。如果系统没把前面的「下周三、上海」带进上下文，模型根本不知道「改成靠窗」是在改哪张票。短期记忆缺失，对话就会在三五轮后散架。

个性化的反复失效。 用户上个月明确说过「我吃素」，这个月让智能体推荐餐厅，没有长期记忆它又推了一家牛排馆。每一次「重新认识用户」都在消耗信任。

长任务的目标漂移。 让智能体写一份十节的报告，写到第七节时它已经忘了第二节定下的术语口径和整体论点。工作记忆装不下整个任务，输出就会前后矛盾。

知识更新的滞后。 模型的参数知识停在训练截止日。公司上周改了退款政策，模型不可能知道——除非把新政策写进可检索的记忆里。

记忆带来的能力跃迁

把记忆补上，智能体会解锁几类质变能力，它们大多无法靠单纯加大模型来获得。

第一是真正的个性化。系统持续把用户偏好、历史决策沉淀成长期记忆，下次交互自动调用。2026 年消费级 AI 应用里「记住用户」几乎成了基础功能，这也是 Mem0 这类记忆层框架快速走红的直接原因——具体框架见记忆框架与实现。

第二是跨会话的连续性。智能体可以引用「我们三周前讨论过的方案」，而不需要用户重新粘贴一遍背景。

第三是长程任务执行。把任务状态外置到记忆里，智能体就能把一个超出单次窗口的大任务分解成多步、跨多次调用完成，中途还能恢复。

第四是经验积累。把成功与失败的经历存为情景记忆，再巩固成可复用的语义知识，智能体能在重复任务上越做越好——这条线在写入与巩固里详述。

为什么不能靠「模型变强」白嫖记忆

一个常见的反驳是：等模型再大一点、上下文窗口再长一点，记忆问题不就自然消失了？这个想法在两个层面站不住。

参数知识层面，模型权重在训练后冻结，无论多大都无法写入「此刻这个用户刚说的这句话」。这类即时、私有、动态的信息，本质上只能放在外部记忆里。

上下文窗口层面，窗口确实在变大，但它有成本上限、有「中间迷失」效应，且每次调用都得重新加载——它是工作台而非档案库。把窗口当记忆用，既贵又不可靠，这个论证会在上下文窗口与局限里完整展开。

换句话说，记忆系统不是等更强模型来淘汰的临时补丁，而是无状态模型架构下的结构性必需品。

记忆与微调、RAG 的分工

读到这里容易把记忆和另外两种「给模型补信息」的手段混淆：微调和检索增强生成（RAG）。三者解决的问题不同，理清边界能避免选错工具。

微调改的是模型权重，把知识固化进参数。它适合教模型一种稳定的风格、领域术语或通用能力，但有两个硬伤：训练慢、成本高，且一旦训完就又冻结了——它无法承载「此刻这个用户刚说的话」这种即时、私有、高频变化的信息。微调是塑造模型的「性格」，不是记住具体的「某个人某件事」。

RAG 从外部知识库检索相关文档拼进上下文，思路上和记忆检索高度相似，本质上记忆系统可以看作 RAG 的一个特化分支。区别在于内容来源与生命周期：经典 RAG 检索的是相对静态的外部文档（产品手册、知识库），而智能体记忆检索的是交互中动态产生、持续读写演进的个性化信息——用户偏好、对话历史、任务状态。RAG 偏「读公共资料」，记忆偏「读写私有经历」。

下表把三者的分工摆清楚：

手段 改什么 时效 适合承载
微调 模型权重 训练后冻结 稳定风格、领域能力
RAG 上下文（读外部库） 文档更新频率 相对静态的公共知识
记忆 上下文（读写私有库） 实时、持续演进 个性化、对话、任务状态

实践中三者常常叠加：用微调定能力底座，用 RAG 接公共知识，用记忆系统承载与具体用户、具体任务绑定的动态信息。本 hub 聚焦最后一类，它的读写机制会在记忆操作一章系统展开。

小结

  • 大语言模型是无状态纯函数，记忆从不在模型里，而是模型之外的一层读写系统。
  • 没有记忆，智能体会在多轮指代、个性化、长任务、知识时效四个场景上反复出错。
  • 补上记忆后，智能体解锁个性化、跨会话连续、长程执行、经验积累四类质变能力。
  • 记忆问题不会因为模型变大而消失：即时私有信息无法写入冻结的权重，上下文窗口也只是工作台而非档案库。
  • 这一篇确立了「为什么」，记忆的分类见记忆类型分类，窗口的局限见上下文窗口与局限。
