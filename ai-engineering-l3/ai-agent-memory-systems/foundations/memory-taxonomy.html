记忆类型分类

「记忆」是个太笼统的词。把对话缓冲、用户偏好、上周二的报错经历、调用某个 API 的步骤全塞进同一个篮子，结果就是既存不好也读不准。要把记忆系统设计对，第一步是建立一套分类坐标系：知道一条信息属于哪一类，才知道它该用哪种存储、按什么规则读写。这一篇就是整个 hub 的「分类总表」，后续每一种架构、每一条操作规则都会回指到这里定义的类型。

核心概念：两条正交的分类轴

智能体记忆的分类大量借鉴认知科学，但落到工程上主要有两条彼此正交的轴。

第一条是时长轴：短期记忆 vs 长期记忆。短期记忆服务于「当前这件事」，生命周期以一次对话、一个任务为限，通常活在上下文窗口或临时缓冲里；长期记忆要跨会话持久存在，落到外部存储（向量库、数据库、知识图谱）里。

第二条是内容轴：情景记忆、语义记忆、程序性记忆。情景记忆是「发生过什么」——带时间地点的具体经历；语义记忆是「事实是什么」——沉淀下来、与具体发生时刻脱钩的知识；程序性记忆是「怎么做」——完成某类任务的步骤与技能。

两条轴交叉，就能给任何一条记忆精确定位。下图是这套分类的全貌：

graph TD
    M[智能体记忆] --> ST[短期/工作记忆<br/>当前任务·易失]
    M --> LT[长期记忆<br/>跨会话·持久]
    LT --> EP[情景记忆<br/>发生过什么]
    LT --> SE[语义记忆<br/>事实是什么]
    LT --> PR[程序性记忆<br/>怎么做]
    EP -.巩固.-> SE
    ST -.重要内容写入.-> LT

时长轴：短期与长期

短期记忆和工作记忆在智能体语境下常被合称，它们的共同点是易失且容量受限——直接受上下文窗口大小约束。典型内容包括当前对话的最近若干轮、当前任务的中间状态、临时草稿板。一旦任务结束或窗口被挤满，这部分内容就会被丢弃或截断。它的具体实现见短期与工作记忆。

长期记忆则要在会话之外持久存活。它不进上下文窗口常驻，而是存在外部，按需检索。一个智能体可能积累数万条长期记忆，但每次调用只挑出最相关的几条塞回窗口。长期记忆几乎都依赖向量存储来支持语义检索，这套基础设施见长期记忆与向量存储。

两者之间有一条关键的数据流：短期记忆里被判定为「值得长期保留」的内容，会通过写入操作沉淀到长期记忆——这个判定与写入的过程见写入与巩固。

内容轴：情景、语义、程序性

内容轴的三类记忆，区别不在于存多久，而在于信息的性质，因此它们的存储结构和检索方式各不相同。

情景记忆记录带上下文的具体事件，核心字段往往是「时间 + 摘要 + 细节」。「2026 年 5 月用户在结账页放弃了购物车」就是一条情景记忆，它天然带时间线，需要支持「按时间回溯」「在某次会话里发生了什么」这类查询。

语义记忆是脱离具体发生时刻的事实与概念，结构更像「实体 + 属性」或知识图谱里的「实体 + 关系」。「用户偏好深色模式」「公司退款窗口是 14 天」都是语义记忆。它关心的是事实当前是否成立，而非它何时被说出口。

程序性记忆编码「如何完成某类任务」的步骤与策略，比如「下单流程的标准操作序列」「调用支付 API 的参数组装方式」。在很多系统里它体现为可复用的工具用法、提示词模板或学到的工作流。

情景记忆与语义记忆的具体组织形态在情景与语义记忆里展开。

一张落地对照表

把两条轴和常见内容、存储、操作规则放进一张表，这是后续所有章节的索引：

记忆类型 时长 典型内容 主存储 主要操作关注点
工作记忆 短期 当前任务中间状态 上下文窗口/缓冲 窗口预算与组装
对话短期记忆 短期 最近若干轮对话 上下文窗口 截断与摘要
情景记忆 长期 带时间的具体经历 向量库 + 时间线 检索 + 巩固
语义记忆 长期 脱时刻的事实概念 向量库/知识图谱 去重 + 矛盾消解
程序性记忆 长期 任务步骤与技能 模板库/工具库 复用 + 更新

2026 年一些较新的多管理器记忆系统（如 MIRIX）会把记忆进一步细分为核心、情景、语义、程序、资源、知识库等六类，本质上是这套分类的更细粒度版本，相关设计见多智能体共享记忆。

分类为什么决定设计

为什么要在动手前先纠结分类？因为每一类记忆的「正确读写规则」截然不同，错配会直接导致系统失效。

情景记忆要保留原始细节和时间，所以不能随意去重；语义记忆恰恰要主动去重与合并，否则「用户喜欢深色模式」会存十遍。情景记忆通常允许随时间衰减淘汰，旧的浏览记录留着没用；语义事实却要长期保留，且在出现矛盾时（用户改了偏好）做更新而非追加。这些差异化规则——衰减、去重、矛盾消解——会在遗忘与压缩里逐一展开。

换句话说，分类不是给记忆贴标签的学术游戏，而是把「该用哪条操作规则」前置确定下来。分类对了，架构和操作才有正确的对象可施加。

小结

  • 智能体记忆沿两条正交轴分类：时长轴（短期/长期）与内容轴（情景/语义/程序性）。
  • 短期记忆易失、受窗口约束；长期记忆持久、靠向量检索；两者间有「值得保留则写入」的数据流。
  • 情景记忆记「发生过什么」、语义记忆记「事实是什么」、程序性记忆记「怎么做」，三者存储结构与检索方式各异。
  • 落地对照表把类型映射到存储与操作，是后续架构与操作章节的索引。
  • 分类决定设计：不同类型对应截然不同的去重、衰减、矛盾消解规则，错配即失效。
