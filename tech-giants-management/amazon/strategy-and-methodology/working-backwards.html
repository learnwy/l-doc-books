Amazon Working Backwards 逆向工作法 — 从新闻稿写起

知识要点

Working Backwards（逆向工作法）是 Amazon 自 2004 年以来最核心的产品创新流程。其核心理念极为简洁：在写一行代码之前，先写一份面向客户的新闻稿（Press Release）和常见问题解答（FAQ），以此倒推产品应该是什么。

这一方法的设计者 Amazon CTO Werner Vogels 这样描述其初衷：「确保每个服务都满足客户需求（而不是超过客户需求），我们使用了一个叫做'逆向工作'的流程——从客户出发，一路往回走，直到得到满足目标所需的最小技术需求集合。目标是通过持续的、显式的客户聚焦来驱动简单性。」

Working Backwards 解决了产品开发中最常见的陷阱：从技术能力出发寻找市场（Technology Push），而非从客户需求出发寻找解决方案（Market Pull）。当团队被强制先定义「客户为什么会兴奋」，再回头设计产品时，大量技术上酷炫但客户不关心的功能会被自然过滤掉。

Amazon 自 2004 年以来几乎所有重大产品——Kindle、Prime、AWS、Alexa、Amazon Go——都是通过 Working Backwards 流程诞生的。

详细讲解

Working Backwards 的四步流程

步骤 产出物 核心问题 迭代次数
1. 写新闻稿 Press Release (PR) 产品为什么让客户兴奋？ 多次修改至令人信服
2. 写 FAQ Frequently Asked Questions 客户/内部的疑虑如何解答？ 持续扩展至无遗漏
3. 定义体验 Mock-ups / Use Cases 客户具体如何使用？ 直到体验流畅无摩擦
4. 写用户手册 User Manual 完整的使用指南 确保所有场景覆盖

整个流程从最终交付物（新闻稿）往回推导到实现细节（技术需求），每一步都确保客户价值不被技术约束所稀释。

Press Release 的结构规范

关键写作原则：


    

  • 一页以内——如果需要超过一页来描述核心价值，说明产品定位不够清晰
    • 

  • 无专业术语——客户能理解的语言，不是内部技术黑话
    • 

  • 具体而非抽象——「60秒内下载任何书」比「极速下载体验」好
    • 

  • 大胆而非保守——新闻稿应该让读者觉得「真的吗？太棒了！」
    • 



FAQ 的双重结构
FAQ 分为两个部分，服务不同目的：


客户 FAQ（External FAQ）：


    

  • 产品什么时候发布？
    • 

  • 多少钱？
    • 

  • 在哪里可以买到/使用？
    • 

  • 跟现有方案相比有什么优势？
    • 

  • 如果不满意可以退款吗？
    • 



内部 FAQ（Internal FAQ）：


    

  • 技术上可行吗？需要多长时间？
    • 

  • 商业模型是什么？何时盈亏平衡？
    • 

  • 需要多少人和多少资金？
    • 

  • 最大的风险是什么？Plan B 是什么？
    • 

  • 与公司现有业务有冲突吗？
    • 



核心规则：FAQ 必须主动回答那些可能「杀死项目」的尖锐问题——如果一个问题很难回答，恰恰说明它必须被提前思考。

新闻稿的「杀手测试」
Amazon 内部有一个非正式的质量标准：如果写完新闻稿后，你自己重读一遍都不觉得兴奋，那产品想法就不值得做。这被称为「杀手测试」：


    

  • ✅ 通过：读完新闻稿，你会想「如果这个产品存在，我一定会用/买」
    • 

  • ❌ 不通过：读完新闻稿，你的反应是「还行吧」或「所以呢？」
    • 



如果新闻稿写得不够令人兴奋，不要急于修改产品想法——先持续修改新闻稿直到它令人信服，或者承认这个想法不够好。


实践案例
案例一：Kindle 的 PR/FAQ
Kindle 的第一份新闻稿核心表述是：「Amazon 推出一款无线电子阅读设备，让读者在 60 秒内购买并开始阅读任何一本书——不需要电脑、不需要同步线缆。」


这份新闻稿明确了几个不可协商的客户承诺：


    

  • 60 秒内可读——这决定了必须内建无线网络
    • 

  • 任何一本书——这决定了必须有海量内容库
    • 

  • 不需要电脑——这决定了设备必须独立于 PC
    • 



每一个技术决策都从这些客户承诺逆推而来。


案例二：Amazon Prime 的诞生
Prime 的 PR/FAQ 描述了一个「让客户不再为运费焦虑」的服务——年费制无限次两日达免费配送。内部 FAQ 中最尖锐的问题是：「每年运费成本数十亿美元，如何回本？」答案是：Prime 会员的购买频率和客单价显著高于非会员，长期来看会员制能创造远超运费成本的终身客户价值。


案例三：一个被杀死的项目
并非所有 PR/FAQ 都能通过审核。一位前 Amazon 产品经理描述：他的团队为一个内部工具写了三个月的 PR/FAQ，但始终无法让新闻稿变得令人兴奋——无论怎么写，客户利益都显得微不足道或模糊。最终团队承认这个想法不够好，将其搁置。这恰恰是 Working Backwards 的价值——在投入开发资源之前就过滤掉了不够好的想法。

小结
    

  • Working Backwards 的核心是「先写新闻稿，再做产品」——确保所有努力都从客户需求出发
    • 

  • PR/FAQ 是一个低成本的想法验证工具——如果新闻稿写不出令人兴奋的版本，想法本身可能不够好
    • 

  • 四步流程（PR → FAQ → 体验定义 → 用户手册）逐步从愿景细化到执行
    • 

  • 内部 FAQ 必须直面可能「杀死项目」的尖锐问题——回避它们只会让问题在开发后期爆炸
    • 

  • Amazon 几乎所有重大成功产品（Kindle、Prime、AWS、Alexa）都源自 Working Backwards 流程
    •
