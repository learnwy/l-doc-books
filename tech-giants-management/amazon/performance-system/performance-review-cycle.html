Amazon OLR 考核周期 — 数据驱动的绩效评估

知识要点

OLR（Organization and Leadership Review）是 Amazon 绩效管理体系的核心运作周期。与许多公司的年度一次性评估不同，Amazon 的绩效管理是一个持续的、多维度的、数据驱动的系统——它不仅评估「做了什么」（What），还评估「怎么做的」（How），后者直接对标 16 条领导力准则。

Amazon 的绩效评估遵循一个清晰的逻辑链：明确目标 → 持续追踪 → 数据收集 → 校准排名 → 反馈与发展。整个过程高度文档化，依赖大量量化数据而非管理者的主观印象。这种数据驱动的方式既是 Amazon 「Dive Deep」准则的体现，也是保证大规模组织中评估一致性的必要手段。

OLR 周期通常每年进行一次全面评估，但中间穿插着季度 Check-in、持续反馈机制和项目里程碑复盘。理解这套体系需要把它放在 Amazon 更大的人才管理哲学中：绩效评估不是目的，而是维持高人才密度和组织持续进化的工具。

详细讲解

OLR 的年度周期结构

时间节点 活动 关键产出
Q1 初 年度目标设定 个人目标文档（对齐团队/组织目标）
Q1-Q2 持续执行 + 季度 Check-in 进展记录、中期调整
Q3 中期回顾 半年度绩效对话
Q4 年终自评 + 收集反馈 自评文档 + 同事/跨职能反馈
Q4-Q1 OLR 校准会议 全团队排名 + 薪酬/晋升决策
Q1 结果传达 + 发展计划 绩效评级、调薪、晋升或 PIP

目标设定与对齐

Amazon 的目标设定遵循「从组织到个人」的瀑布式对齐：

每个个人目标都必须：


    

  • 与上一级目标明确对齐
    • 

  • 包含可衡量的关键成果指标
    • 

  • 标注对应的 Leadership Principles
    • 

  • 区分「做什么」（业务目标）和「怎么做」（LP 行为目标）
    • 



评估的双维度模型
Amazon 的绩效评估不是单一维度的「完成了多少 KPI」，而是一个 2x2 矩阵：







LP 行为强
LP 行为弱





业务结果强
最佳表现者（晋升候选）
短期高绩效但文化风险（需辅导）




业务结果弱
高潜力但可能需要调岗
低绩效（PIP 候选）





这意味着：即使一个员工交付了出色的业务结果，如果他/她的工作方式严重违反 LP（例如通过破坏团队信任来达成目标），仍然不会被视为优秀绩效。


360 度反馈收集
OLR 期间，Amazon 会系统性收集多来源反馈：


    

  • 自评：员工撰写详细的自评文档，列举对标每条 LP 的具体行为和成果
    • 

  • 管理者评估：直接上级的绩效评价
    • 

  • 同事反馈：被评估者提名 + 管理者指定的同事提供反馈
    • 

  • 跨职能反馈：合作过的其他团队成员的评价
    • 

  • 量化数据：项目交付数据、客户满意度指标、运营指标等
    • 



Calibration 校准会议
Calibration 是 OLR 中最关键也最耗时的环节。同一级别的管理者们集中在一起，对各自团队成员的排名进行跨团队校准：


校准会议的核心规则：


    

  1. 相对标准：不是与绝对标准比，而是与同级别同事比
    2. 

  2. 证据驱动：每一个排名决策都需要具体的行为和成果证据
    3. 

  3. 防止膨胀：强制分布确保不能所有人都是「优秀」
    4. 

  4. 一致性：确保不同管理者对同一级别的标准理解一致
    5.

Amazon 的股票薪酬设计是「后重」模式：入职前两年获得较少的 RSU vesting，第三第四年急剧增加。这一设计的目的是：前两年用较低的股票来「测试」员工是否真的适合 Amazon，如果绩效优秀则在后期给予丰厚回报。


实践案例
案例一：数据驱动的晋升文档
在 Amazon，晋升不是管理者的主观推荐，而是一份详尽的「晋升文档」（Promo Doc）。这份文档必须包含：候选人在当前级别和下一级别要求上的具体表现证据、每条相关 LP 的行为示例、可衡量的业务影响、以及来自多方的反馈。晋升文档会在校准会议上被同级管理者集体审阅和挑战。


案例二：Forte 反馈工具
Amazon 内部使用名为「Forte」的反馈管理工具。员工可以随时向同事请求反馈，也可以主动给予反馈。这些反馈会在 OLR 期间被汇总呈现给管理者。Forte 的设计理念是让反馈成为持续的、日常的行为，而非仅在年终评估时才想起来。


案例三：OP1/OP2 规划与个人目标的关联
Amazon 每年进行两轮运营规划——年中的 OP1（下一年规划）和年初的 OP2（当年修订）。每个团队的目标从这两轮规划中产生，然后逐级分解到个人。这确保了每个人的工作都能追溯到组织最高层级的战略优先级，而不是凭空产生的「忙碌工作」。

对其他企业的启示
    

  1. 「怎么做」和「做了什么」同等重要——只看结果会奖励破坏性的高绩效者
    2. 

  2. 跨团队校准是公平性的必要保障——每个管理者都有自己的宽严标准
    3. 

  3. 绩效评估必须证据驱动——减少主观印象的权重，增加可验证事实的权重
    4. 

  4. 薪酬设计应激励长期投入——Amazon 的后重 RSU 设计值得深思
    5. 



小结
    

  • OLR 是 Amazon 绩效管理的核心周期，整合了目标设定、持续反馈、校准排名和发展规划
    • 

  • 评估采用双维度模型：业务结果（What）和 LP 行为（How）同等重要
    • 

  • Calibration 校准会议通过跨团队比较确保了评估标准的一致性
    • 

  • 数据驱动和书面文档化是大规模组织中维持评估公正性的关键
    • 

  • 薪酬的「后重」设计和绩效的强关联共同构成了高标准激励体系
    •
