Databricks AI 产品矩阵

从数据平台到数据智能平台

Databricks 的 AI 产品矩阵不是一系列独立的 AI 功能，而是围绕"数据智能"（Data Intelligence）这一核心概念构建的完整体系。理解这个产品矩阵的关键在于看到各组件之间的协同关系——数据治理（Unity Catalog）为 AI 提供可信数据基础，模型训练（Mosaic AI）将数据转化为智能，模型服务（Model Serving）将智能部署到生产，而 MLflow 和 Agent 框架则贯穿整个 AI 生命周期。

Mosaic AI：模型训练与推理平台

2023 年 Databricks 以 13 亿美元收购 MosaicML，标志着公司从"数据平台"向"数据 + AI 平台"的战略转型。MosaicML 的核心能力——高效的大规模模型训练——被整合为 Databricks 平台的 Mosaic AI 组件。

核心能力

模型训练。Mosaic AI 提供了企业级的模型训练能力，支持从传统 ML 模型到大语言模型（LLM）的全谱系训练。客户可以在自己的 Databricks 环境中使用自己的数据训练定制化模型，无需将数据传出企业边界。2025 年 Data + AI Summit 上，Databricks 宣布了 Serverless GPU Compute 的 Beta 版本，用户可以在无需管理基础设施的情况下运行训练和推理任务。

模型推理与服务。Model Serving 提供了生产级的模型部署和推理基础设施，支持实时推理和批量推理两种模式。支持 Databricks 自有模型（如 DBRX）和第三方模型（如 OpenAI、Anthropic 的 API 模型）。

Mosaic AI Gateway。作为统一的 AI 模型访问层，Gateway 允许组织通过单一接口管理和调用多个 LLM 提供商的模型，实现模型调用的治理、监控和成本管理。

DBRX：开源大语言模型

2024 年 3 月，Databricks 发布了 DBRX——一个基于混合专家（MoE）架构的开源大语言模型。DBRX 在发布时的基准测试中表现优于 Llama 2 70B 和 Mixtral-8x7B 等同期开源模型。

DBRX 的战略意义不在于与 GPT-4 或 Claude 竞争通用 AI 能力，而在于：展示 Mosaic AI 训练平台的能力（"我们能训练出顶级模型"）；为企业客户提供开源基础模型（企业可以在此基础上用自己的数据微调）；以及在开源社区中建立 Databricks 在 LLM 领域的技术声誉。

Unity Catalog：AI 资产的统一治理

Unity Catalog 最初是数据治理引擎，但在 AI 时代被扩展为"数据 + AI 资产"的统一治理层。这意味着 Unity Catalog 不仅管理表、文件和视图，还管理 ML 模型、AI Agent、Feature Store、向量索引和 Prompt 模板。

AI 治理的具体功能

模型血缘追踪。追踪模型是用哪些数据训练的、经过了哪些处理步骤、以及被部署到了哪些环境。这对于模型审计和合规至关重要。

AI 资产权限管理。控制谁可以访问、使用和修改 AI 模型和相关资产。在受监管行业（如金融、医疗），这种细粒度的权限管理是合规的基本要求。

Prompt 注册与版本管理。MLflow 3.0 引入的 Prompt Registry 与 Unity Catalog 集成，允许组织对 LLM 应用中使用的 Prompt 进行版本管理、测试和治理。

MLflow 3.0：AI 生命周期管理的进化

2025 年 Data + AI Summit 发布的 MLflow 3.0 是对 MLflow 的重大升级，专为生成式 AI 时代重新设计。

关键创新

Agent 可观测性。MLflow 3.0 提供了对 AI Agent 系统的实时监控能力——追踪 Agent 的每一步推理过程、工具调用和决策逻辑。这对于在生产环境中调试和优化 Agent 行为至关重要。

跨平台监控。即使 AI Agent 部署在 Databricks 之外（如 AWS Lambda、GCP Cloud Run 或本地服务器），也可以通过 MLflow 3.0 进行统一的可观测性管理。这使 MLflow 从 Databricks 的内部工具扩展为整个 AI 生态的监控标准。

评估框架。MLflow 3.0 内置了系统化的 AI 模型和 Agent 评估工具，支持自动化的质量评估、回归测试和 A/B 测试。

Agent Bricks：AI Agent 构建框架

2025 年发布的 Agent Bricks 是 Databricks 进入 AI Agent 领域的标志性产品。用户只需描述想要 Agent 完成的任务和需要连接的企业数据，Agent Bricks 就能自动优化 Agent 的构建过程。

核心特性

自动评估生成。Agent Bricks 根据任务描述自动生成评估标准和测试用例，确保 Agent 的质量可衡量。

质量和成本优化。系统自动在质量和成本之间寻找最优平衡——选择最适合特定任务的模型、优化 Prompt 设计、以及调整 Agent 的推理策略。

预置行业模板。Agent Bricks 为常见的企业用例（如结构化信息提取、知识助手、文本转换、多 Agent 协作系统）提供了优化过的模板。

AI/BI Genie：自然语言数据交互

Genie 是 Databricks 面向业务用户的自然语言数据查询界面，在 2025 年正式发布为 GA（General Availability）。用户可以用日常语言提问，Genie 自动将问题转化为 SQL 查询并返回可视化结果。

Genie 代表了 Databricks 数据民主化战略在 AI 时代的具体落地——通过 AI 消除数据访问的技术门槛，让不会编程的业务用户也能直接与数据对话。

Lakebase：AI 原生数据库

2025 年发布的 Lakebase 是 Databricks 收购 Neon 后推出的托管 PostgreSQL 兼容数据库，专为 AI 应用场景设计。Lakebase 的核心创新包括：

计算存储分离。与传统 PostgreSQL 不同，Lakebase 将计算和存储完全分离，支持 Serverless 自动伸缩和零成本即时数据库克隆（类似 Git 分支）。

与 Lakehouse 深度集成。Lakebase 可以直接与 Databricks Lakehouse 中的数据同步，实现分析数据的低延迟服务。

AI 应用优化。集成 pgvector 扩展支持向量搜索，适合 RAG（检索增强生成）和 Feature Serving 等 AI 应用场景。

产品矩阵的协同逻辑

层级 组件 功能
数据层 Delta Lake + Iceberg + Lakebase 存储和管理结构化、半结构化和非结构化数据
治理层 Unity Catalog 统一管理数据和 AI 资产的权限、血缘和合规
处理层 Spark + Lakeflow + SQL Analytics 数据摄入、转换、查询和分析
AI 层 Mosaic AI + MLflow 3.0 + Agent Bricks 模型训练、部署、监控和 Agent 构建
交互层 Genie + Databricks Assistant + Databricks Apps 自然语言查询、AI 编程助手和应用构建

这五层之间的深度集成是 Databricks 相对于单点 AI 工具的核心竞争优势——用户不需要在多个割裂的工具之间切换，可以在一个平台上完成从数据准备到 AI 应用上线的全流程。

对管理实践的启示

Databricks 的 AI 产品矩阵展示了一种"平台型 AI 战略"——不是做一个单一的 AI 产品，而是围绕数据和 AI 的完整生命周期构建平台。这种策略的优势在于：每个组件都为其他组件创造了用户价值和数据网络效应，客户一旦在任何一个层面深度使用 Databricks，就会因为集成便利性而倾向于使用更多组件。挑战在于：维护如此广泛的产品线需要巨大的工程投入，且每个组件都需要达到"同类最优"的水平才能与专精型竞争对手竞争。
