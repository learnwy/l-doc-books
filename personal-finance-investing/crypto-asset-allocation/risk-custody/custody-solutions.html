托管方案

托管的核心权衡

加密资产托管的根本选择是在安全性与便利性之间寻找平衡：

  • 自托管（Self-Custody）：完全控制，但操作失误不可逆
  • 机构托管（Institutional Custody）：专业安全，但引入对手方风险
  • 混合方案：结合两者优势，当前主流趋势
自托管（Self-Custody）

硬件钱包最佳实践：


    

  1. 仅从官方渠道购买：二手或第三方可能被篡改
    2. 

  2. 首次设置验证：确认设备未被预先初始化
    3. 

  3. 助记词离线备份：手写在金属板上（防火防水），从不数字化
    4. 

  4. PIN 码设置：至少 6 位，不使用生日等可猜测数字
    5. 

  5. 固件及时更新：但先等 1-2 周观察社区反馈
    6.

机构托管的风险
    

  1. 对手方风险：FTX 崩盘证明——即使是最大的「托管」平台也可能挪用客户资金
    2. 

  2. 监管冻结：政府可能要求托管商冻结特定账户
    3. 

  3. 操作风险：内部员工作恶或流程错误
    4. 

  4. 保险覆盖不足：多数保险仅覆盖「冷存储被盗」，不覆盖内部欺诈
    5. 

  5. 访问延迟：大额提取可能需要 24-72 小时审批
    6. 



选择机构托管的标准
    

  •  是否受监管机构监督（如 NY BitLicense、联邦银行牌照）
    • 

  •  储备证明（Proof of Reserves）是否定期发布
    • 

  •  保险覆盖范围和额度
    • 

  •  冷/热钱包比例（>95% 冷存储为佳）
    • 

  •  是否有 SOC 2 Type II 审计
    • 

  •  破产隔离条款（客户资产是否法律隔离于公司资产）
    • 



混合方案
MPC 钱包（Multi-Party Computation）
MPC 将私钥分割为多个「碎片」，分布在不同参与方，签名时通过密码学计算完成——无需在任何单点重建完整私钥。


优势：


    

  • 无单点故障（任何单方无法单独控制资金）
    • 

  • 比传统多签更灵活（可动态更换参与方）
    • 

  • 对区块链层透明——看起来像普通交易
    • 



代表产品：Fireblocks、ZenGo、Fordefi


社会恢复钱包
以太坊创始人 Vitalik Buterin 倡导的模式——指定一组「守护者」（Guardian），在用户丢失主密钥时通过多数守护者投票恢复账户。


代表：Argent Wallet


    

  • 用户设定 3-5 个守护者（朋友、家人、硬件钱包）
    • 

  • 日常交易用主密钥正常操作
    • 

  • 丢失主密钥时：多数守护者确认 → 设定新主密钥
    • 

  • 延迟机制：恢复请求有 24-48 小时等待期（防恶意恢复）
    •

Dead Man's Switch（失联触发器）
    

  1. 用户定期（如每月）向服务确认在线
    2. 

  2. 如果连续 N 个月未确认，系统判定用户可能失能/去世
    3. 

  3. 自动向预设继承人发送访问信息
    4. 

  4. 继承人使用该信息获取资产
    5. 



实现方式：


    

  • Google Inactive Account Manager（免费但有限）
    • 

  • 专用加密继承服务（如 Inheriti、Safe Haven）
    • 

  • 智能合约定时触发器
    • 



继承规划最佳实践
    

  1. 记录资产清单：交易所账户、钱包地址、DeFi 仓位——记录在安全位置
    2. 

  2. 为继承人准备操作指南：他们可能不懂加密——写清楚步骤
    3. 

  3. 定期更新：地址变了、换了交易所、新增了资产——及时更新继承文件
    4. 

  4. 考虑税务影响：不同国家的加密遗产税规则不同
    5. 

  5. 分层规划：
      

    • 紧急资金（<$10K）：简单方案，如信封指令
      • 

    • 主要持仓（10K−10K-10K−1M）：Casa/多签 + 律师
      • 

    • 大额资产（>$1M）：信托 + 专业机构托管
      • 

    

    6.
