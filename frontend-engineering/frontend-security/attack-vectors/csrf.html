CSRF 跨站请求伪造

核心概念

跨站请求伪造（Cross-Site Request Forgery, CSRF）是一种利用用户已认证的浏览器会话，在用户不知情的情况下伪造合法请求的攻击方式。当用户在目标网站已登录的状态下访问攻击者控制的页面，攻击者可以诱导浏览器向目标网站发送伪造请求，由于浏览器会自动附带目标站点的 Cookie，服务端无法区分该请求是用户主动发起还是被伪造的。

CSRF 攻击的本质是利用了 Web 的隐式身份认证机制——Cookie 随请求自动发送。与 XSS 不同，CSRF 不需要注入代码到目标站点，而是从外部站点发起合法格式的请求。

攻击原理与实例
CSRF 攻击利用浏览器在跨域请求时仍然自动发送 Cookie 的行为：


<!-- 攻击者页面: evil.com/attack.html -->

<!-- 方式1: 图片标签触发 GET 请求 -->
<img src="https://bank.com/transfer?to=attacker&amount=10000" style="display:none" />

<!-- 方式2: 隐藏表单自动提交 POST 请求 -->
<form id="csrf-form" action="https://bank.com/transfer" method="POST" style="display:none">
  <input type="hidden" name="to" value="attacker" />
  <input type="hidden" name="amount" value="10000" />
</form>
<script>
  document.getElementById('csrf-form').submit();
</script>

<!-- 方式3: 利用 iframe 静默攻击 -->
<iframe style="display:none" name="csrf-frame"></iframe>
<form action="https://bank.com/api/change-email" method="POST" target="csrf-frame">
  <input type="hidden" name="email" value="attacker@evil.com" />
</form>
JSON API 的 CSRF 攻击更隐蔽：


<!-- 利用表单提交 JSON（Content-Type: text/plain 不触发预检） -->
<form action="https://api.example.com/user/settings" method="POST" enctype="text/plain">
  <input type="hidden" name='{"email":"attacker@evil.com","padding":"' value='"}' />
</form>

<!-- 利用 fetch API（需要 CORS 配合或简单请求） -->
<script>
  fetch('https://api.example.com/user/settings', {
    method: 'POST',
    credentials: 'include',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body: 'email=attacker@evil.com',
  });
</script>
Token 防御方案
CSRF Token 是最经典也最有效的防御方式。服务端生成一个不可预测的 Token，嵌入到表单或请求头中，服务端在处理请求时验证 Token 的有效性：


import crypto from 'node:crypto';

const generateCsrfToken = (): string => {
  return crypto.randomBytes(32).toString('hex');
};

app.use((req, res, next) => {
  if (!req.session.csrfToken) {
    req.session.csrfToken = generateCsrfToken();
  }
  res.locals.csrfToken = req.session.csrfToken;
  next();
});

const verifyCsrfToken = (req: Request, res: Response, next: NextFunction) => {
  if (['GET', 'HEAD', 'OPTIONS'].includes(req.method)) {
    return next();
  }

  const token = req.headers['x-csrf-token'] || req.body?._csrf || req.query?._csrf;

  if (!token || token !== req.session.csrfToken) {
    return res.status(403).json({ error: 'CSRF token 验证失败' });
  }

  req.session.csrfToken = generateCsrfToken();
  next();
};

app.use(verifyCsrfToken);
前端发送 CSRF Token：


const getCsrfToken = (): string => {
  const meta = document.querySelector('meta[name="csrf-token"]');
  return meta?.getAttribute('content') ?? '';
};

const apiClient = {
  async post<T>(url: string, data: unknown): Promise<T> {
    const response = await fetch(url, {
      method: 'POST',
      credentials: 'same-origin',
      headers: {
        'Content-Type': 'application/json',
        'X-CSRF-Token': getCsrfToken(),
      },
      body: JSON.stringify(data),
    });

    if (!response.ok) {
      throw new Error(`请求失败: ${response.status}`);
    }

    return response.json();
  },
};
SameSite Cookie 防御
SameSite Cookie 属性是现代浏览器原生提供的 CSRF 防御机制，通过限制 Cookie 在跨站请求中的发送行为来阻止 CSRF：


app.use(
  session({
    name: 'session_id',
    secret: process.env.SESSION_SECRET,
    cookie: {
      httpOnly: true,
      secure: true,
      sameSite: 'lax',
      maxAge: 24 * 60 * 60 * 1000,
      domain: '.example.com',
      path: '/',
    },
  }),
);

双重提交 Cookie 模式
双重提交 Cookie 是一种无状态的 CSRF 防御方案，不需要服务端存储 Token：


const doubleSubmitCookie = () => {
  const csrfToken = crypto.randomBytes(32).toString('hex');

  return {
    setCookie: (res: Response) => {
      res.cookie('csrf_double', csrfToken, {
        httpOnly: false,
        secure: true,
        sameSite: 'lax',
        path: '/',
      });
    },

    verify: (req: Request): boolean => {
      const cookieToken = req.cookies['csrf_double'];
      const headerToken = req.headers['x-csrf-token'];

      if (!cookieToken || !headerToken) return false;

      return crypto.timingSafeEqual(Buffer.from(cookieToken), Buffer.from(headerToken as string));
    },
  };
};

const csrfReadFromCookie = (): string => {
  const match = document.cookie.match(/csrf_double=([^;]+)/);
  return match?.[1] ?? '';
};

const securePost = async (url: string, data: unknown) => {
  return fetch(url, {
    method: 'POST',
    credentials: 'same-origin',
    headers: {
      'Content-Type': 'application/json',
      'X-CSRF-Token': csrfReadFromCookie(),
    },
    body: JSON.stringify(data),
  });
};
小结
    

  • CSRF 利用浏览器自动发送 Cookie 的机制，在用户不知情的情况下伪造合法请求
    • 

  • CSRF Token 是最经典的防御方式，每次表单提交都需要携带不可预测的 Token
    • 

  • SameSite Cookie（Lax/Strict）是现代浏览器原生的 CSRF 防御，推荐所有 Cookie 都设置
    • 

  • 双重提交 Cookie 模式是无状态的防御方案，适合分布式系统
    • 

  • GET 请求不应有副作用（遵循 RESTful 规范），这是最基本的 CSRF 预防措施
    • 

  • Origin/Referer 头检查可作为辅助防御手段，但不应作为唯一防线
    • 

  • 关键操作（转账、修改密码）应要求额外的身份验证（如输入密码、短信验证码）
    • 

  • 多层防御（Token + SameSite + Origin 检查）是最安全的策略
    •
