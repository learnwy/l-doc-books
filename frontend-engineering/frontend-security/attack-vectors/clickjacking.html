点击劫持

核心概念

点击劫持（Clickjacking）是一种视觉欺骗攻击，攻击者将目标网站通过透明的 iframe 覆盖在精心构造的诱饵页面上，诱导用户在看似无害的元素上点击，实际触发的是目标网站上的敏感操作。这种攻击之所以有效，是因为用户无法察觉自己正在与一个隐藏的 iframe 交互。

点击劫持的变种包括光标劫持（Cursorjacking）、触摸劫持（Tapjacking）和拖放劫持（Drag-and-Drop Hijacking）。尽管这类攻击的技术门槛不高，但在社交媒体、支付等场景中造成的危害可能非常严重。

攻击实现方式
经典的点击劫持通过 CSS 将 iframe 设为透明并精确定位：


<!-- 攻击者页面 -->
<style>
  .decoy-container {
    position: relative;
    width: 500px;
    height: 300px;
  }

  .decoy-content {
    position: absolute;
    top: 0;
    left: 0;
    z-index: 1;
    width: 100%;
    height: 100%;
  }

  .target-iframe {
    position: absolute;
    top: 0;
    left: 0;
    width: 500px;
    height: 300px;
    opacity: 0.0001;
    z-index: 2;
    border: none;
  }
</style>

<div class="decoy-container">
  <div class="decoy-content">
    <h2>恭喜中奖！点击领取</h2>
    <button style="font-size: 24px; padding: 20px 40px; cursor: pointer;">立即领取红包</button>
  </div>

  <iframe class="target-iframe" src="https://bank.com/transfer?to=attacker&amount=1000&confirm=true"> </iframe>
</div>

X-Frame-Options 防御
X-Frame-Options 是最早的点击劫持防御标准，通过 HTTP 响应头控制页面是否可以被 iframe 嵌入：


app.use((req, res, next) => {
  res.setHeader('X-Frame-Options', 'DENY');
  next();
});

const frameOptions = (option: 'DENY' | 'SAMEORIGIN' | string) => {
  return (req: Request, res: Response, next: NextFunction) => {
    res.setHeader('X-Frame-Options', option);
    next();
  };
};

app.use('/admin/*', frameOptions('DENY'));
app.use('/embed/*', frameOptions('SAMEORIGIN'));
app.use('/widget/*', (req, res, next) => {
  next();
});




指令值
含义
使用场景





DENY
完全禁止嵌入
管理后台、支付页面




SAMEORIGIN
仅允许同源嵌入
一般业务页面




ALLOW-FROM uri
允许指定源嵌入（已弃用）
不推荐使用





CSP frame-ancestors 防御
CSP 的 frame-ancestors 指令是 X-Frame-Options 的现代替代，提供了更精细的控制能力：


app.use((req, res, next) => {
  res.setHeader('Content-Security-Policy', "frame-ancestors 'none'");
  next();
});

app.use('/page/*', (req, res, next) => {
  res.setHeader('Content-Security-Policy', "frame-ancestors 'self'");
  next();
});

app.use('/widget/*', (req, res, next) => {
  res.setHeader(
    'Content-Security-Policy',
    "frame-ancestors 'self' https://trusted-partner.com https://embed.example.com",
  );
  next();
});

const setFramePolicy = (ancestors: string[]) => {
  return (req: Request, res: Response, next: NextFunction) => {
    const policy = ancestors.length === 0 ? "frame-ancestors 'none'" : `frame-ancestors ${ancestors.join(' ')}`;
    res.setHeader('Content-Security-Policy', policy);
    next();
  };
};

app.use('/admin', setFramePolicy([]));
app.use('/dashboard', setFramePolicy(["'self'"]));
app.use('/embed', setFramePolicy(["'self'", 'https://partner.com']));
JavaScript 框架破解防御
JavaScript 层面的点击劫持防御作为补充手段：


const preventFraming = () => {
  if (window.self !== window.top) {
    document.body.style.display = 'none';

    try {
      if (window.top) {
        window.top.location = window.self.location;
      }
    } catch {
      document.body.innerHTML = `
        <div style="padding: 50px; text-align: center;">
          <h1>安全提醒</h1>
          <p>此页面不允许在 iframe 中打开</p>
          <a href="${window.self.location.href}" target="_top">
            点击此处在新窗口打开
          </a>
        </div>
      `;
      document.body.style.display = 'block';
    }
  }
};

if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', preventFraming);
} else {
  preventFraming();
}

const detectOverlay = () => {
  document.addEventListener(
    'click',
    (e) => {
      const target = e.target as HTMLElement;
      const rect = target.getBoundingClientRect();
      const elementAtPoint = document.elementFromPoint(rect.left + rect.width / 2, rect.top + rect.height / 2);

      if (elementAtPoint !== target && !target.contains(elementAtPoint)) {
        console.warn('检测到可能的 UI 覆盖攻击');
        e.preventDefault();
        e.stopPropagation();
      }
    },
    true,
  );
};
小结
    

  • 点击劫持通过透明 iframe 覆盖诱导用户在目标网站上执行敏感操作
    • 

  • X-Frame-Options: DENY/SAMEORIGIN 是基础防御，但已被 CSP frame-ancestors 取代
    • 

  • CSP frame-ancestors 提供更精细的控制，支持多个允许的域名
    • 

  • JavaScript 框架破解（frame busting）作为补充手段，不应作为唯一防御
    • 

  • 关键操作应要求额外确认（如二次弹窗、密码验证），即使被嵌入也能降低风险
    • 

  • 同时设置 X-Frame-Options 和 CSP frame-ancestors 以兼容旧浏览器
    • 

  • 可嵌入的 widget 页面应严格限制功能范围，避免包含敏感操作
    • 

  • 移动端需额外注意触摸劫持，确保触摸区域与视觉元素精确匹配
    •
