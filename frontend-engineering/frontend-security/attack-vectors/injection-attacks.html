注入攻击

核心概念

注入攻击（Injection Attack）是一类通过在用户输入中嵌入恶意指令，使应用程序将数据误当作代码执行的攻击方式。在前端领域，除了 XSS（本质上是 HTML/JavaScript 注入），还需要关注 SQL 注入（通过前端 API 传递）、命令注入、模板注入、LDAP 注入等多种变体。注入攻击的核心问题在于数据与代码的边界被打破——应用程序未能区分用户提供的数据和可执行的指令。

OWASP Top 10 中，注入类漏洞长期占据首位，其根本原因是开发者在处理不可信输入时未进行充分的验证和转义。

SQL 注入与 API 安全
虽然 SQL 注入主要发生在服务端，但前端开发者需要理解其原理以编写安全的 API 调用和实施前端验证：


// 危险：字符串拼接 SQL（服务端代码）
app.get('/users', async (req, res) => {
  const name = req.query.name;
  // 攻击者输入: ' OR '1'='1' --
  const sql = `SELECT * FROM users WHERE name = '${name}'`;
  const result = await db.query(sql);
  res.json(result);
});

// 安全：参数化查询
app.get('/users', async (req, res) => {
  const name = req.query.name;
  const result = await db.query('SELECT * FROM users WHERE name = $1', [name]);
  res.json(result);
});

// 安全：ORM（如 Prisma）自动处理参数化
app.get('/users', async (req, res) => {
  const name = req.query.name as string;
  const users = await prisma.user.findMany({
    where: { name: { contains: name } },
  });
  res.json(users);
});

const sanitizeSearchInput = (input: string): string => {
  return input
    .replace(/['"\\;]/g, '')
    .trim()
    .slice(0, 200);
};

const validateSortField = (field: string): string => {
  const allowed = ['name', 'created_at', 'updated_at', 'email'];
  if (!allowed.includes(field)) {
    return 'created_at';
  }
  return field;
};
命令注入与路径遍历
命令注入通过用户输入中嵌入操作系统命令来执行任意代码，路径遍历则通过 ../ 访问文件系统中的任意文件：


import { execFile } from 'node:child_process';
import path from 'node:path';

// 危险：直接拼接用户输入到命令中
app.get('/ping', (req, res) => {
  const host = req.query.host;
  // 攻击者输入: 127.0.0.1; cat /etc/passwd
  exec(`ping -c 1 ${host}`, (err, stdout) => {
    res.send(stdout);
  });
});

// 安全：使用 execFile 并严格验证输入
app.get('/ping', (req, res) => {
  const host = req.query.host as string;

  if (!/^[a-zA-Z0-9.-]+$/.test(host)) {
    return res.status(400).json({ error: '无效的主机名' });
  }

  execFile('ping', ['-c', '1', host], (err, stdout) => {
    if (err) {
      return res.status(500).json({ error: '执行失败' });
    }
    res.send(stdout);
  });
});

// 危险：路径遍历
app.get('/files/:filename', (req, res) => {
  const filename = req.params.filename;
  // 攻击者输入: ../../../etc/passwd
  res.sendFile(`/uploads/${filename}`);
});

// 安全：规范化路径并验证
app.get('/files/:filename', (req, res) => {
  const filename = req.params.filename;
  const basePath = '/uploads';
  const resolvedPath = path.resolve(basePath, filename);

  if (!resolvedPath.startsWith(basePath + path.sep)) {
    return res.status(403).json({ error: '禁止访问' });
  }

  res.sendFile(resolvedPath);
});

const safeFilePath = (basedir: string, userPath: string): string | null => {
  const normalized = path.normalize(userPath).replace(/^(\.\.(\/|\\|$))+/, '');
  const resolved = path.resolve(basedir, normalized);

  if (!resolved.startsWith(path.resolve(basedir) + path.sep)) {
    return null;
  }

  return resolved;
};
模板注入
模板注入分为服务端模板注入（SSTI）和客户端模板注入（CSTI），都可能导致代码执行：


// 危险：SSTI - 用户输入作为模板内容
app.get('/greeting', (req, res) => {
  const name = req.query.name;
  // 攻击者输入: {{constructor.constructor('return process')().exit()}}
  const template = `Hello, ${name}!`;
  const compiled = handlebars.compile(template);
  res.send(compiled({}));
});

// 安全：用户输入作为数据而非模板
app.get('/greeting', (req, res) => {
  const name = req.query.name;
  const template = handlebars.compile('Hello, {{name}}!');
  res.send(template({ name }));
});

// 前端 CSTI 示例（Angular 1.x）
// 危险：<div>{{constructor.constructor('alert(1)')()}}</div>

// Vue 中的 CSTI 风险
// 危险：v-html 结合用户输入
// <div v-html="userInput"></div>

// 安全的模板使用
const renderTemplate = (template: string, data: Record<string, string>): string => {
  return template.replace(/\{\{(\w+)\}\}/g, (match, key) => {
    const value = data[key];
    if (value === undefined) return match;
    return escapeHtml(value);
  });
};
输入验证框架
建立完整的输入验证体系是防御所有注入攻击的基础：


import { z } from 'zod';

const userSearchSchema = z.object({
  query: z
    .string()
    .min(1, '搜索词不能为空')
    .max(200, '搜索词过长')
    .regex(/^[\p{L}\p{N}\s\-_.@]+$/u, '包含非法字符'),
  page: z.coerce.number().int().min(1).max(1000).default(1),
  pageSize: z.coerce.number().int().min(10).max(100).default(20),
  sortBy: z.enum(['name', 'created_at', 'updated_at']).default('created_at'),
  sortOrder: z.enum(['asc', 'desc']).default('desc'),
});

app.get('/api/users/search', (req, res) => {
  const result = userSearchSchema.safeParse(req.query);

  if (!result.success) {
    return res.status(400).json({
      error: '参数验证失败',
      details: result.error.issues,
    });
  }

  const { query, page, pageSize, sortBy, sortOrder } = result.data;
  // 使用验证后的安全数据
});

const fileUploadSchema = z.object({
  filename: z
    .string()
    .regex(/^[a-zA-Z0-9_\-]+\.[a-zA-Z0-9]+$/, '文件名格式无效')
    .max(255),
  contentType: z.enum(['image/png', 'image/jpeg', 'image/gif', 'image/webp', 'application/pdf', 'text/plain']),
  size: z.number().max(10 * 1024 * 1024),
});

const sanitizeJsonInput = (input: unknown): unknown => {
  if (typeof input === 'string') {
    return input.replace(/[\x00-\x08\x0B\x0C\x0E-\x1F]/g, '');
  }
  if (Array.isArray(input)) {
    return input.map(sanitizeJsonInput);
  }
  if (input !== null && typeof input === 'object') {
    return Object.fromEntries(
      Object.entries(input as Record<string, unknown>)
        .filter(([key]) => !key.startsWith('__'))
        .map(([key, value]) => [key, sanitizeJsonInput(value)]),
    );
  }
  return input;
};
小结
    

  • 注入攻击的本质是数据与代码的边界被打破，应用程序将用户输入误当作指令执行
    • 

  • SQL 注入通过参数化查询或 ORM 防御，永远不要拼接用户输入到 SQL 语句中
    • 

  • 命令注入使用 execFile（非 exec）并严格验证输入，推荐白名单方式
    • 

  • 路径遍历通过 path.resolve + 前缀检查防御，确保访问不超出基础目录
    • 

  • 模板注入的关键是将用户输入作为数据而非模板内容传递
    • 

  • Zod 等 Schema 验证库是实现类型安全的输入验证的最佳工具
    • 

  • 前端验证是用户体验的一部分，但永远不能替代服务端验证
    • 

  • 防御应遵循最小权限原则：输入白名单 > 输入黑名单 > 输出转义
    •
