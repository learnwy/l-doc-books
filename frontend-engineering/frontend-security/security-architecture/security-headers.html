安全 HTTP 头

核心概念

安全 HTTP 头是 Web 应用纵深防御体系中成本最低、效果最显著的防护手段。通过在 HTTP 响应中设置特定的安全头，可以指示浏览器启用各种内置安全机制，有效防御 XSS、点击劫持、协议降级、MIME 嗅探等多种攻击。大多数安全头的配置只需几行代码，但遗漏它们可能导致严重的安全风险。

安全头的配置应该遵循"默认安全"原则——为所有响应设置基线安全头，然后根据特定路径或资源类型进行微调。

传输安全头
HTTPS 是 Web 安全的基础，HSTS 确保浏览器始终使用 HTTPS 连接：


const setTransportSecurityHeaders = (res: Response) => {
  res.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains; preload');

  res.setHeader('X-Content-Type-Options', 'nosniff');

  res.setHeader('X-DNS-Prefetch-Control', 'off');
};

app.use((req, res, next) => {
  if (req.headers['x-forwarded-proto'] !== 'https' && process.env.NODE_ENV === 'production') {
    return res.redirect(301, `https://${req.hostname}${req.url}`);
  }

  setTransportSecurityHeaders(res);
  next();
});
HSTS Preload 的注意事项：


const hstsConfig = {
  development: '',

内容与隔离安全头
防止内容嗅探、点击劫持和跨域信息泄露：


const setContentSecurityHeaders = (res: Response, nonce: string) => {
  res.setHeader('X-Frame-Options', 'DENY');

  res.setHeader(
    'Content-Security-Policy',
    [
      "default-src 'self'",
      `script-src 'self' 'nonce-${nonce}'`,
      "style-src 'self' 'unsafe-inline'",
      "img-src 'self' data: https:",
      "font-src 'self'",
      "connect-src 'self'",
      "frame-ancestors 'none'",
      "base-uri 'self'",
      "form-action 'self'",
    ].join('; '),
  );

  res.setHeader('Referrer-Policy', 'strict-origin-when-cross-origin');

  res.setHeader(
    'Permissions-Policy',
    [
      'camera=()',
      'microphone=()',
      'geolocation=()',
      'payment=()',
      'usb=()',
      'magnetometer=()',
      'gyroscope=()',
      'accelerometer=()',
    ].join(', '),
  );
};

const setCrossOriginIsolation = (res: Response) => {
  res.setHeader('Cross-Origin-Opener-Policy', 'same-origin');
  res.setHeader('Cross-Origin-Embedder-Policy', 'require-corp');
  res.setHeader('Cross-Origin-Resource-Policy', 'same-origin');
};
安全头中间件
将所有安全头整合到统一的中间件中：


interface SecurityHeadersConfig {
  hsts: boolean;
  csp: boolean;
  frameOptions: 'DENY' | 'SAMEORIGIN';
  referrerPolicy: string;
  permissionsPolicy: string[];
  crossOriginIsolation: boolean;
}

const defaultConfig: SecurityHeadersConfig = {
  hsts: true,
  csp: true,
  frameOptions: 'DENY',
  referrerPolicy: 'strict-origin-when-cross-origin',
  permissionsPolicy: ['camera=()', 'microphone=()', 'geolocation=()', 'payment=()', 'usb=()'],
  crossOriginIsolation: false,
};

const securityHeaders = (config: Partial<SecurityHeadersConfig> = {}) => {
  const cfg = { ...defaultConfig, ...config };

  return (req: Request, res: Response, next: NextFunction) => {
    const nonce = crypto.randomBytes(16).toString('base64');
    res.locals.nonce = nonce;

    if (cfg.hsts) {
      res.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains');
    }

    res.setHeader('X-Content-Type-Options', 'nosniff');
    res.setHeader('X-Frame-Options', cfg.frameOptions);
    res.setHeader('Referrer-Policy', cfg.referrerPolicy);

    if (cfg.permissionsPolicy.length > 0) {
      res.setHeader('Permissions-Policy', cfg.permissionsPolicy.join(', '));
    }

    if (cfg.csp) {
      res.setHeader(
        'Content-Security-Policy',
        [
          "default-src 'self'",
          `script-src 'self' 'nonce-${nonce}' 'strict-dynamic'`,
          "style-src 'self' 'unsafe-inline'",
          "img-src 'self' data: https:",
          "connect-src 'self'",
          "frame-ancestors 'none'",
          "base-uri 'self'",
          "form-action 'self'",
        ].join('; '),
      );
    }

    if (cfg.crossOriginIsolation) {
      res.setHeader('Cross-Origin-Opener-Policy', 'same-origin');
      res.setHeader('Cross-Origin-Embedder-Policy', 'require-corp');
    }

    next();
  };
};

app.use(securityHeaders());

app.use('/api/*', securityHeaders({ csp: false, frameOptions: 'DENY' }));
app.use('/embed/*', securityHeaders({ frameOptions: 'SAMEORIGIN' }));
安全头审计与监控
定期审计安全头配置确保没有遗漏：


interface SecurityHeaderAudit {
  url: string;
  headers: Record<string, string | null>;
  score: number;
  issues: string[];
}

const requiredHeaders = [
  'strict-transport-security',
  'content-security-policy',
  'x-content-type-options',
  'x-frame-options',
  'referrer-policy',
];

const auditSecurityHeaders = async (url: string): Promise<SecurityHeaderAudit> => {
  const response = await fetch(url, { method: 'HEAD' });
  const headers: Record<string, string | null> = {};
  const issues: string[] = [];
  let score = 0;

  for (const header of requiredHeaders) {
    const value = response.headers.get(header);
    headers[header] = value;

    if (value) {
      score += 20;
    } else {
      issues.push(`缺少安全头: ${header}`);
    }
  }

  const dangerousHeaders = ['server', 'x-powered-by', 'x-aspnet-version'];
  for (const header of dangerousHeaders) {
    if (response.headers.get(header)) {
      issues.push(`暴露了服务器信息: ${header}`);
      score -= 5;
    }
  }

  return { url, headers, score: Math.max(0, Math.min(100, score)), issues };
};
小结
    

  • 安全 HTTP 头是成本最低的防护手段，应为所有响应设置基线安全头
    • 

  • HSTS 强制 HTTPS 连接，加入 preload 列表后不可逆，需谨慎评估
    • 

  • X-Content-Type-Options: nosniff 防止浏览器 MIME 类型嗅探
    • 

  • Permissions-Policy 限制敏感 Web API 的使用，减少攻击面
    • 

  • Referrer-Policy 控制 Referer 头的发送策略，防止敏感路径泄露
    • 

  • COOP/COEP 实现跨域隔离，是启用 SharedArrayBuffer 等 API 的前提
    • 

  • 安全头应整合在统一的中间件中，按路径支持不同配置
    • 

  • 定期审计安全头配置，使用 securityheaders.com 等工具检测遗漏
    •
