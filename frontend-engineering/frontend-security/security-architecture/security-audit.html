安全审计与监控

核心概念

前端安全审计与监控是确保安全防御措施持续有效的关键环节。安全审计（Security Audit）是对应用安全状态的系统性检查，安全监控（Security Monitoring）则是对运行时安全事件的实时检测和响应。两者共同构成了前端安全的"检测与响应"能力——即使预防措施被突破，也能及时发现并处置。

在前端场景中，安全监控面临独特的挑战：客户端代码完全暴露、执行环境不可控、用户行为多样且复杂。因此，前端安全监控需要结合客户端采集和服务端分析，建立全链路的安全可观测体系。

自定义安全规则检测常见的前端安全反模式：


const securityPatterns = {
  dangerousHtml: /dangerouslySetInnerHTML|v-html|innerHTML\s*=/g,
  evalUsage: /\beval\s*\(|new\s+Function\s*\(/g,
  documentWrite: /document\.write\s*\(/g,
  insecureProtocol: /http:\/\/(?!localhost|127\.0\.0\.1)/g,
  hardcodedSecret: /(api[_-]?key|secret|password|token)\s*[:=]\s*['"][^'"]{8,}/gi,
  openRedirect: /window\.location\s*=\s*(?!['"]https?:\/\/)/g,
};

interface SecurityFinding {
  file: string;
  line: number;
  pattern: string;
  severity: 'high' | 'medium' | 'low';
  description: string;
}

const scanFile = (content: string, filename: string): SecurityFinding[] => {
  const findings: SecurityFinding[] = [];
  const lines = content.split('\n');

  for (const [name, pattern] of Object.entries(securityPatterns)) {
    for (let i = 0; i < lines.length; i++) {
      if (pattern.test(lines[i])) {
        findings.push({
          file: filename,
          line: i + 1,
          pattern: name,
          severity: name === 'hardcodedSecret' ? 'high' : 'medium',
          description: `检测到安全风险模式: ${name}`,
        });
      }
      pattern.lastIndex = 0;
    }
  }

  return findings;
};
运行时安全监控
前端运行时安全监控采集客户端的安全事件：


interface SecurityEvent {
  type: string;
  timestamp: string;
  url: string;
  details: Record<string, unknown>;
  userAgent: string;
  sessionId: string;
}

class SecurityMonitor {
  private events: SecurityEvent[] = [];
  private readonly endpoint: string;
  private flushInterval: ReturnType<typeof setInterval>;

  constructor(endpoint: string) {
    this.endpoint = endpoint;
    this.flushInterval = setInterval(() => this.flush(), 30000);
    this.setupListeners();
  }

  private setupListeners() {
    this.monitorCspViolations();
    this.monitorConsoleErrors();
    this.monitorNetworkErrors();
  }

  private monitorCspViolations() {
    document.addEventListener('securitypolicyviolation', (e) => {
      this.report({
        type: 'csp_violation',
        details: {
          blockedUri: e.blockedURI,
          violatedDirective: e.violatedDirective,
          effectiveDirective: e.effectiveDirective,
          originalPolicy: e.originalPolicy,
          sourceFile: e.sourceFile,
          lineNumber: e.lineNumber,
          columnNumber: e.columnNumber,
        },
      });
    });
  }

  private monitorConsoleErrors() {
    window.addEventListener('error', (e) => {
      if (e.message?.includes('Content Security Policy')) {
        this.report({
          type: 'csp_error',
          details: { message: e.message, filename: e.filename },
        });
      }
    });
  }

  private monitorNetworkErrors() {
    const originalFetch = window.fetch;
    window.fetch = async (...args) => {
      try {
        const response = await originalFetch(...args);
        if (response.status === 403 || response.status === 401) {
          this.report({
            type: 'auth_failure',
            details: {
              url: typeof args[0] === 'string' ? args[0] : args[0]?.toString(),
              status: response.status,
            },
          });
        }
        return response;
      } catch (error) {
        this.report({
          type: 'network_error',
          details: { url: typeof args[0] === 'string' ? args[0] : '' },
        });
        throw error;
      }
    };
  }

  report(event: Omit<SecurityEvent, 'timestamp' | 'url' | 'userAgent' | 'sessionId'>) {
    this.events.push({
      ...event,
      timestamp: new Date().toISOString(),
      url: window.location.href,
      userAgent: navigator.userAgent,
      sessionId: this.getSessionId(),
    });

    if (this.events.length >= 10) {
      this.flush();
    }
  }

  private async flush() {
    if (this.events.length === 0) return;

    const batch = this.events.splice(0);
    try {
      await fetch(this.endpoint, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ events: batch }),
        keepalive: true,
      });
    } catch {
      this.events.unshift(...batch);
    }
  }

  private getSessionId(): string {
    let id = sessionStorage.getItem('security_session');
    if (!id) {
      id = crypto.randomUUID();
      sessionStorage.setItem('security_session', id);
    }
    return id;
  }

  destroy() {
    clearInterval(this.flushInterval);
    this.flush();
  }
}

小结
    

  • 安全审计和监控构成了前端安全的"检测与响应"层，是预防措施的补充
    • 

  • 静态代码分析（ESLint Security / Semgrep）应集成到 CI/CD 流程中
    • 

  • CSP 违规报告（securitypolicyviolation 事件）是最重要的运行时安全信号
    • 

  • 安全监控需要批量上报 + keepalive，避免影响用户体验
    • 

  • 安全审计清单按传输安全、注入防御、认证会话、供应链四个维度组织
    • 

  • 安全事件分级响应：P0（数据泄露）→ P1（漏洞利用）→ P2（配置缺陷）→ P3（改进建议）
    • 

  • 自动化审计覆盖 70% 以上的检查项，人工审计关注业务逻辑安全
    • 

  • 安全监控数据应与业务监控（如 Sentry）集成，建立统一的可观测体系
