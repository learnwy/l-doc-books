CORS 跨域安全

核心概念

跨域资源共享（Cross-Origin Resource Sharing, CORS）是浏览器的一种安全机制，用于控制不同源（协议 + 域名 + 端口）之间的 HTTP 请求。同源策略（Same-Origin Policy）是浏览器最基本的安全策略之一，它阻止网页脚本向不同源发起请求，防止恶意网站读取其他网站的敏感数据。CORS 则是在这一限制之上提供的一种受控的"放行"机制。

理解 CORS 的工作原理对于前端开发至关重要——错误的 CORS 配置可能导致功能不可用，而过于宽松的配置则可能引入安全漏洞。

简单请求与预检请求
浏览器将跨域请求分为"简单请求"和"需要预检的请求"两类：


// 简单请求的条件（同时满足以下所有条件）
// 1. 方法: GET, HEAD, POST
// 2. Content-Type: text/plain, multipart/form-data, application/x-www-form-urlencoded
// 3. 仅包含安全头: Accept, Accept-Language, Content-Language, Content-Type

// 这些请求会触发预检：
// - 使用 PUT, DELETE, PATCH 方法
// - Content-Type 为 application/json
// - 包含自定义头如 Authorization, X-Custom-Header
服务端 CORS 配置：


import type { Context, Next } from 'hono';

interface CorsConfig {
  origins: string[];
  methods: string[];
  headers: string[];
  credentials: boolean;
  maxAge: number;
  exposeHeaders: string[];
}

const defaultCorsConfig: CorsConfig = {
  origins: [],
  methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH'],
  headers: ['Content-Type', 'Authorization', 'X-Request-ID'],
  credentials: true,
  maxAge: 86400,
  exposeHeaders: ['X-Request-ID', 'X-Total-Count'],
};

const cors = (config: Partial<CorsConfig> = {}) => {
  const cfg = { ...defaultCorsConfig, ...config };

  return async (c: Context, next: Next) => {
    const origin = c.req.header('Origin');

    if (!origin) {
      await next();
      return;
    }

    const isAllowed = cfg.origins.length === 0 || cfg.origins.includes(origin) || cfg.origins.some((o) => o === '*');

    if (!isAllowed) {
      return c.text('Origin not allowed', 403);
    }

    const responseOrigin = cfg.credentials ? origin : cfg.origins.includes('*') ? '*' : origin;
    c.header('Access-Control-Allow-Origin', responseOrigin);

    if (cfg.credentials) {
      c.header('Access-Control-Allow-Credentials', 'true');
    }

    if (cfg.exposeHeaders.length > 0) {
      c.header('Access-Control-Expose-Headers', cfg.exposeHeaders.join(', '));
    }

    if (c.req.method === 'OPTIONS') {
      c.header('Access-Control-Allow-Methods', cfg.methods.join(', '));
      c.header('Access-Control-Allow-Headers', cfg.headers.join(', '));
      c.header('Access-Control-Max-Age', String(cfg.maxAge));
      return c.text('', 204);
    }

    await next();
  };
};
安全配置策略
CORS 配置需要在功能需求和安全性之间取得平衡：


// 最严格：仅允许同域
const strictCors = cors({
  origins: ['https://www.example.com'],
  credentials: true,
});

// 开发环境：允许 localhost
const devCors = cors({
  origins: ['http://localhost:3000', 'http://localhost:5173', 'http://127.0.0.1:3000'],
  credentials: true,
});

// 公共 API：允许所有来源但不带凭证
const publicApiCors = cors({
  origins: ['*'],
  credentials: false,
  methods: ['GET'],
  headers: ['Content-Type'],
});

// 按环境动态配置
const createCorsConfig = (): Partial<CorsConfig> => {
  const env = process.env.NODE_ENV;
  const allowedOrigins = (process.env.CORS_ORIGINS ?? '').split(',').filter(Boolean);

  return {
    origins: env === 'development' ? ['http://localhost:3000', 'http://localhost:5173'] : allowedOrigins,
    credentials: true,
  };
};
常见的 CORS 安全反模式和正确做法：


// 危险：动态反射 Origin 头
const badMiddleware = (req: Request, res: Response, next: NextFunction) => {
  res.setHeader('Access-Control-Allow-Origin', req.headers.origin ?? '*');
  res.setHeader('Access-Control-Allow-Credentials', 'true');
  next();
};

// 安全：白名单校验
const safeOriginCheck = (origin: string, allowedOrigins: string[]): boolean => {
  if (allowedOrigins.includes(origin)) {
    return true;
  }

  return allowedOrigins.some((allowed) => {
    if (allowed.startsWith('*.')) {
      const domain = allowed.slice(2);
      return origin.endsWith(`.${domain}`) || origin === `https://${domain}`;
    }
    return false;
  });
};

// 危险：Access-Control-Allow-Origin: * + credentials: true（浏览器会阻止）

// 安全：明确指定 Origin
const corsWithCredentials = (req: Request, res: Response, next: NextFunction) => {
  const origin = req.headers.origin;
  if (origin && allowedOrigins.includes(origin)) {
    res.setHeader('Access-Control-Allow-Origin', origin);
    res.setHeader('Access-Control-Allow-Credentials', 'true');
    res.setHeader('Vary', 'Origin');
  }
  next();
};
前端跨域请求处理
前端发起跨域请求时的安全实践：


const crossOriginFetch = async (url: string, options: RequestInit = {}): Promise<Response> => {
  const response = await fetch(url, {
    ...options,
    credentials: 'include',
    mode: 'cors',
    headers: {
      'Content-Type': 'application/json',
      ...options.headers,
    },
  });

  return response;
};

const noCookieFetch = async (url: string): Promise<Response> => {
  return fetch(url, {
    credentials: 'omit',
    mode: 'cors',
  });
};

const handleCorsError = async (url: string): Promise<Response> => {
  try {
    const response = await fetch(url, { mode: 'cors' });
    return response;
  } catch (error) {
    if (error instanceof TypeError && error.message.includes('Failed to fetch')) {
      console.error('CORS 请求被阻止:', url);
      throw new Error(`跨域请求失败: ${url}`);
    }
    throw error;
  }
};
特殊跨域场景
处理 WebSocket、Server-Sent Events 和文件上传等特殊场景的跨域配置：


// WebSocket 跨域验证（WebSocket 不受 CORS 限制，需服务端手动验证）
const validateWebSocketOrigin = (req: IncomingMessage): boolean => {
  const origin = req.headers.origin;
  if (!origin) return false;

  const allowed = ['https://www.example.com', 'https://app.example.com'];
  return allowed.includes(origin);
};

// 文件上传的 CORS 配置
app.options(
  '/api/upload',
  cors({
    origins: ['https://www.example.com'],
    methods: ['POST'],
    headers: ['Content-Type', 'X-Upload-Token'],
    maxAge: 3600,
  }),
);

// iframe postMessage 安全
window.addEventListener('message', (event) => {
  if (event.origin !== 'https://trusted-partner.com') {
    return;
  }

  const { type, data } = event.data;
  if (type === 'REQUEST_DATA') {
    event.source?.postMessage({ type: 'RESPONSE_DATA', data: getSafeData() }, { targetOrigin: event.origin });
  }
});
小结
    

  • 同源策略是浏览器的基础安全机制，CORS 提供受控的跨域访问能力
    • 

  • 简单请求直接发送，复杂请求先发 OPTIONS 预检，预检结果可缓存
    • 

  • CORS Origin 白名单应使用精确匹配，避免动态反射 Origin 头
    • 

  • Access-Control-Allow-Origin: * 和 credentials: true 不能同时使用
    • 

  • 带凭证的跨域请求必须返回具体的 Origin 值并设置 Vary: Origin
    • 

  • WebSocket 不受 CORS 限制，需要服务端手动验证 Origin
    • 

  • 预检缓存（Access-Control-Max-Age）减少 OPTIONS 请求开销
    • 

  • postMessage 通信必须验证 event.origin，targetOrigin 不应设为 *
    •
