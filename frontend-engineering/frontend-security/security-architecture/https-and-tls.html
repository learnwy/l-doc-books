HTTPS 与 TLS

核心概念

HTTPS（HTTP over TLS）是 Web 安全的基石，通过 TLS（Transport Layer Security）协议为 HTTP 通信提供加密、完整性验证和身份认证三重保护。在现代 Web 开发中，HTTPS 已不再是可选项——浏览器限制 HTTP 页面使用 Service Worker、地理位置、摄像头等敏感 API，搜索引擎对 HTTP 站点降权，Cookie 的 Secure 属性要求 HTTPS 传输。

TLS 1.3 是当前最新的标准，相比 TLS 1.2 减少了握手延迟（从 2-RTT 到 1-RTT，甚至 0-RTT），移除了不安全的加密套件，显著提升了安全性和性能。

证书管理与自动化
TLS 证书是 HTTPS 的核心，Let's Encrypt 提供了免费的自动化证书管理：


# 使用 certbot 获取证书
certbot certonly --webroot -w /var/www/html -d example.com -d www.example.com

# 自动续签（通过 cron 或 systemd timer）
certbot renew --quiet --post-hook "systemctl reload nginx"
# Nginx HTTPS 配置
server {
    listen 443 ssl http2;
    server_name example.com;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off;

    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;
    ssl_session_tickets off;

    ssl_stapling on;
    ssl_stapling_verify on;
    resolver 8.8.8.8 8.8.4.4 valid=300s;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
}

server {
    listen 80;
    server_name example.com www.example.com;
    return 301 https://$host$request_uri;
}
Node.js 中的 HTTPS 配置：


import https from 'node:https';
import fs from 'node:fs';

const httpsOptions = {
  key: fs.readFileSync('/etc/letsencrypt/live/example.com/privkey.pem'),
  cert: fs.readFileSync('/etc/letsencrypt/live/example.com/fullchain.pem'),
  minVersion: 'TLSv1.2' as const,
  ciphers: [
    'ECDHE-ECDSA-AES128-GCM-SHA256',
    'ECDHE-RSA-AES128-GCM-SHA256',
    'ECDHE-ECDSA-AES256-GCM-SHA384',
    'ECDHE-RSA-AES256-GCM-SHA384',
  ].join(':'),
};

const server = https.createServer(httpsOptions, app);
server.listen(443);
混合内容与协议降级
混合内容（Mixed Content）是 HTTPS 页面中加载 HTTP 资源的问题：


// 检测混合内容
const detectMixedContent = () => {
  if (window.location.protocol !== 'https:') return;

  const observer = new PerformanceObserver((list) => {
    for (const entry of list.getEntries()) {
      if ('name' in entry && typeof entry.name === 'string') {
        if (entry.name.startsWith('http://')) {
          console.warn('混合内容:', entry.name);
        }
      }
    }
  });

  observer.observe({ entryTypes: ['resource'] });
};

const enforceHttps = (req: Request, res: Response, next: NextFunction) => {
  if (process.env.NODE_ENV === 'production') {
    if (req.headers['x-forwarded-proto'] !== 'https') {
      return res.redirect(301, `https://${req.hostname}${req.url}`);
    }

    res.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains');
    res.setHeader('Content-Security-Policy', 'upgrade-insecure-requests');
  }

  next();
};
证书透明度与安全监控
Certificate Transparency（CT）确保 CA 签发的证书公开可审计：


interface CertificateInfo {
  subject: string;
  issuer: string;
  validFrom: Date;
  validTo: Date;
  daysUntilExpiry: number;
  isExpiringSoon: boolean;
}

const checkCertificate = async (hostname: string): Promise<CertificateInfo> => {
  return new Promise((resolve, reject) => {
    const tls = require('node:tls');
    const socket = tls.connect(443, hostname, { servername: hostname }, () => {
      const cert = socket.getPeerCertificate();
      const validTo = new Date(cert.valid_to);
      const now = new Date();
      const daysUntilExpiry = Math.floor((validTo.getTime() - now.getTime()) / 86400000);

      resolve({
        subject: cert.subject.CN,
        issuer: cert.issuer.O,
        validFrom: new Date(cert.valid_from),
        validTo,
        daysUntilExpiry,
        isExpiringSoon: daysUntilExpiry < 30,
      });

      socket.end();
    });

    socket.on('error', reject);
  });
};

const monitorCertificates = async (domains: string[]) => {
  for (const domain of domains) {
    const info = await checkCertificate(domain);
    if (info.isExpiringSoon) {
      console.warn(`证书即将过期: ${domain} (${info.daysUntilExpiry} 天)`);
    }
  }
};
小结
    

  • HTTPS 是现代 Web 安全的基石，提供加密、完整性和身份认证三重保护
    • 

  • TLS 1.3 是推荐标准，握手只需 1-RTT，安全性和性能均优于 TLS 1.2
    • 

  • Let's Encrypt 提供免费证书和自动化续签，消除了 HTTPS 的成本障碍
    • 

  • HSTS 防止协议降级攻击，preload 列表提供浏览器内置保护
    • 

  • 混合内容需要通过 CSP upgrade-insecure-requests 自动升级
    • 

  • 证书透明度（CT）确保 CA 签发行为可审计，防止恶意证书
    • 

  • 证书过期监控应纳入运维体系，提前 30 天告警
    • 

  • 在反向代理（Nginx）层终止 TLS 是最佳实践，应用层通过 X-Forwarded-Proto 判断协议
    •
