认证安全

核心概念

前端认证安全涉及用户身份的验证、会话的管理和凭证的保护。在现代 Web 应用中，认证方案从传统的基于 Cookie 的会话认证发展到 JWT（JSON Web Token）、OAuth 2.0 和 WebAuthn 等多种方式。每种方案都有其适用场景和安全考量，选择不当可能导致账户劫持、会话固定、凭证泄露等严重安全问题。

认证安全的核心原则是：凭证的安全存储、传输的机密性保护、会话的有效期管理和异常行为的检测。

Token 存储安全
JWT 的存储位置直接决定了应用的安全等级：


// 方案1（推荐）: HttpOnly Cookie 存储
// 服务端设置
const setAuthCookie = (res: Response, token: string) => {
  res.cookie('access_token', token, {
    httpOnly: true,
    secure: true,
    sameSite: 'lax',
    maxAge: 15 * 60 * 1000,
    path: '/',
  });
};

// 方案2: 内存存储 + Cookie 刷新令牌
class AuthTokenManager {
  private accessToken: string | null = null;

  setToken(token: string) {
    this.accessToken = token;
  }

  getToken(): string | null {
    return this.accessToken;
  }

  clear() {
    this.accessToken = null;
  }

  async refreshToken(): Promise<string | null> {
    const response = await fetch('/api/auth/refresh', {
      method: 'POST',
      credentials: 'same-origin',
    });

    if (!response.ok) {
      this.clear();
      return null;
    }

    const { accessToken } = await response.json();
    this.setToken(accessToken);
    return accessToken;
  }
}

const authManager = new AuthTokenManager();

const authenticatedFetch = async (url: string, options: RequestInit = {}): Promise<Response> => {
  let token = authManager.getToken();

  if (!token) {
    token = await authManager.refreshToken();
    if (!token) {
      window.location.href = '/login';
      throw new Error('认证失败');
    }
  }

  const response = await fetch(url, {
    ...options,
    headers: {
      ...options.headers,
      Authorization: `Bearer ${token}`,
    },
  });

  if (response.status === 401) {
    token = await authManager.refreshToken();
    if (!token) {
      window.location.href = '/login';
      throw new Error('认证已过期');
    }

    return fetch(url, {
      ...options,
      headers: {
        ...options.headers,
        Authorization: `Bearer ${token}`,
      },
    });
  }

  return response;
};
JWT 安全实践
JWT 的生成、验证和刷新需要严格遵循安全最佳实践：


import jwt from 'jsonwebtoken';

const JWT_SECRET = process.env.JWT_SECRET!;
const ACCESS_TOKEN_TTL = '15m';
const REFRESH_TOKEN_TTL = '7d';

interface TokenPayload {
  userId: string;
  role: string;
  sessionId: string;
}

const generateTokenPair = (payload: TokenPayload) => {
  const accessToken = jwt.sign({ ...payload, type: 'access' }, JWT_SECRET, {
    expiresIn: ACCESS_TOKEN_TTL,
    algorithm: 'HS256',
    issuer: 'myapp',
    audience: 'myapp-client',
  });

  const refreshToken = jwt.sign({ userId: payload.userId, sessionId: payload.sessionId, type: 'refresh' }, JWT_SECRET, {
    expiresIn: REFRESH_TOKEN_TTL,
    algorithm: 'HS256',
  });

  return { accessToken, refreshToken };
};

const verifyAccessToken = (token: string): TokenPayload | null => {
  try {
    const decoded = jwt.verify(token, JWT_SECRET, {
      algorithms: ['HS256'],
      issuer: 'myapp',
      audience: 'myapp-client',
    }) as TokenPayload & { type: string };

    if (decoded.type !== 'access') {
      return null;
    }

    return decoded;
  } catch {
    return null;
  }
};

app.post('/api/auth/refresh', async (req, res) => {
  const refreshToken = req.cookies.refresh_token;

  if (!refreshToken) {
    return res.status(401).json({ error: '缺少刷新令牌' });
  }

  try {
    const decoded = jwt.verify(refreshToken, JWT_SECRET) as { userId: string; sessionId: string; type: string };

    if (decoded.type !== 'refresh') {
      return res.status(401).json({ error: '无效的令牌类型' });
    }

    const session = await db.sessions.findOne({ id: decoded.sessionId });
    if (!session || session.revoked) {
      return res.status(401).json({ error: '会话已失效' });
    }

    const tokens = generateTokenPair({
      userId: decoded.userId,
      role: session.role,
      sessionId: decoded.sessionId,
    });

    res.cookie('refresh_token', tokens.refreshToken, {
      httpOnly: true,
      secure: true,
      sameSite: 'strict',
      maxAge: 7 * 24 * 60 * 60 * 1000,
      path: '/api/auth',
    });

    res.json({ accessToken: tokens.accessToken });
  } catch {
    return res.status(401).json({ error: '刷新令牌已过期' });
  }
});
OAuth 2.0 与 PKCE
OAuth 2.0 + PKCE（Proof Key for Code Exchange）是 SPA 安全接入第三方登录的推荐方案：


const generateCodeVerifier = (): string => {
  const array = new Uint8Array(32);
  crypto.getRandomValues(array);
  return btoa(String.fromCharCode(...array))
    .replace(/\+/g, '-')
    .replace(/\//g, '_')
    .replace(/=/g, '');
};

const generateCodeChallenge = async (verifier: string): Promise<string> => {
  const encoder = new TextEncoder();
  const data = encoder.encode(verifier);
  const hash = await crypto.subtle.digest('SHA-256', data);
  return btoa(String.fromCharCode(...new Uint8Array(hash)))
    .replace(/\+/g, '-')
    .replace(/\//g, '_')
    .replace(/=/g, '');
};

const startOAuthFlow = async () => {
  const codeVerifier = generateCodeVerifier();
  const codeChallenge = await generateCodeChallenge(codeVerifier);
  const state = crypto.randomUUID();

  sessionStorage.setItem('oauth_verifier', codeVerifier);
  sessionStorage.setItem('oauth_state', state);

  const params = new URLSearchParams({
    client_id: 'my-app-id',
    redirect_uri: `${window.location.origin}/callback`,
    response_type: 'code',
    scope: 'openid profile email',
    state,
    code_challenge: codeChallenge,
    code_challenge_method: 'S256',
  });

  window.location.href = `https://auth.example.com/authorize?${params}`;
};

const handleOAuthCallback = async (code: string, state: string) => {
  const savedState = sessionStorage.getItem('oauth_state');
  const codeVerifier = sessionStorage.getItem('oauth_verifier');

  if (state !== savedState) {
    throw new Error('OAuth state 验证失败');
  }

  sessionStorage.removeItem('oauth_state');
  sessionStorage.removeItem('oauth_verifier');

  const response = await fetch('/api/auth/oauth/callback', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ code, code_verifier: codeVerifier }),
    credentials: 'same-origin',
  });

  if (!response.ok) {
    throw new Error('OAuth 认证失败');
  }

  return response.json();
};
安全登出与会话管理
安全的登出机制需要同时清理前端和后端的会话数据：


const secureLogout = async () => {
  try {
    await fetch('/api/auth/logout', {
      method: 'POST',
      credentials: 'same-origin',
    });
  } finally {
    authManager.clear();
    sessionStorage.clear();
    window.location.href = '/login';
  }
};

app.post('/api/auth/logout', async (req, res) => {
  const sessionId = req.user?.sessionId;
  if (sessionId) {
    await db.sessions.update({ id: sessionId }, { revoked: true, revokedAt: new Date() });
  }

  res.clearCookie('access_token', { path: '/' });
  res.clearCookie('refresh_token', { path: '/api/auth' });
  res.json({ success: true });
});
小结
    

  • JWT 存储首选 HttpOnly Cookie，避免 localStorage（对 XSS 完全暴露）
    • 

  • 短期 Access Token + 长期 Refresh Token 是平衡安全性和用户体验的推荐方案
    • 

  • Refresh Token 应存储在 HttpOnly + Secure + SameSite=Strict 的 Cookie 中
    • 

  • OAuth 2.0 SPA 必须使用 PKCE 扩展，防止授权码拦截攻击
    • 

  • JWT 验证必须指定算法白名单（如 algorithms: ['HS256']），防止 none 算法攻击
    • 

  • 安全登出需要同时清理前端状态和后端会话，仅清理前端是不够的
    • 

  • Token 刷新应实现自动重试机制，对用户透明
    • 

  • 敏感操作应要求二次认证，即使持有有效 Token
    •
