输入验证与净化

核心概念

输入验证与净化是 Web 安全的第一道防线。验证（Validation）确认输入数据是否符合预期格式和约束，净化（Sanitization）则对数据进行清洗以移除潜在的恶意内容。两者相辅相成：验证在前端和后端入口处拒绝非法数据，净化在数据使用前消除残余风险。

安全的输入处理遵循一个核心原则：永远不信任任何来自客户端的数据。无论是 URL 参数、表单字段、HTTP 头、Cookie，还是来自第三方 API 的数据，在使用前都必须经过验证和净化。

Schema 验证
使用 Zod 等 Schema 验证库在类型层面保证数据安全：


import { z } from 'zod';

const userRegistrationSchema = z.object({
  username: z
    .string()
    .min(3, '用户名至少 3 个字符')
    .max(30, '用户名最多 30 个字符')
    .regex(/^[a-zA-Z0-9_-]+$/, '用户名只能包含字母、数字、下划线和连字符'),
  email: z.string().email('邮箱格式无效').max(254, '邮箱地址过长'),
  password: z
    .string()
    .min(8, '密码至少 8 个字符')
    .regex(/[A-Z]/, '密码必须包含大写字母')
    .regex(/[a-z]/, '密码必须包含小写字母')
    .regex(/[0-9]/, '密码必须包含数字'),
  age: z.number().int('年龄必须是整数').min(13, '年龄不能小于 13').max(120, '年龄不能大于 120').optional(),
});

type UserRegistration = z.infer<typeof userRegistrationSchema>;

const validateInput = <T>(
  schema: z.ZodSchema<T>,
  data: unknown,
): { success: true; data: T } | { success: false; errors: z.ZodIssue[] } => {
  const result = schema.safeParse(data);
  if (result.success) {
    return { success: true, data: result.data };
  }
  return { success: false, errors: result.error.issues };
};

const apiQuerySchema = z.object({
  search: z.string().max(200).default(''),
  page: z.coerce.number().int().min(1).max(10000).default(1),
  limit: z.coerce.number().int().min(1).max(100).default(20),
  sort: z.enum(['newest', 'oldest', 'popular']).default('newest'),
  category: z
    .string()
    .regex(/^[a-z0-9-]+$/)
    .optional(),
});
HTML 净化
处理富文本内容时，HTML 净化是防止 XSS 的核心手段：


import DOMPurify from 'dompurify';

const createSanitizer = () => {
  const blogPostConfig = {
    ALLOWED_TAGS: [
      'h1',
      'h2',
      'h3',
      'h4',
      'p',
      'br',
      'hr',
      'ul',
      'ol',
      'li',
      'blockquote',
      'b',
      'i',
      'em',
      'strong',
      'u',
      'del',
      'mark',
      'a',
      'img',
      'code',
      'pre',
      'table',
      'thead',
      'tbody',
      'tr',
      'th',
      'td',
    ],
    ALLOWED_ATTR: ['href', 'target', 'rel', 'src', 'alt', 'title', 'width', 'height', 'class', 'id'],
    ALLOW_DATA_ATTR: false,
    ADD_TAGS: [],
    ADD_ATTR: ['target'],
  };

  const commentConfig = {
    ALLOWED_TAGS: ['b', 'i', 'em', 'strong', 'a', 'br', 'p', 'code'],
    ALLOWED_ATTR: ['href'],
    ALLOW_DATA_ATTR: false,
  };

  return {
    blogPost: (html: string) => DOMPurify.sanitize(html, blogPostConfig),
    comment: (html: string) => DOMPurify.sanitize(html, commentConfig),
    plainText: (html: string) => DOMPurify.sanitize(html, { ALLOWED_TAGS: [] }),
  };
};

const sanitizer = createSanitizer();

DOMPurify.addHook('afterSanitizeAttributes', (node) => {
  if (node.tagName === 'A') {
    node.setAttribute('rel', 'noopener noreferrer');
    node.setAttribute('target', '_blank');

    const href = node.getAttribute('href') ?? '';
    if (!/^https?:\/\//.test(href) && !href.startsWith('/')) {
      node.removeAttribute('href');
    }
  }

  if (node.tagName === 'IMG') {
    const src = node.getAttribute('src') ?? '';
    if (!/^https?:\/\//.test(src) && !src.startsWith('/') && !src.startsWith('data:image/')) {
      node.removeAttribute('src');
    }
  }
});
前端表单验证
前端表单验证提升用户体验，但不能替代服务端验证：


import { z } from 'zod'
import { useCallback, useState } from 'react'
import type { FC, FormEvent } from 'react'

const useFormValidation = <T extends z.ZodRawShape>(schema: z.ZodObject<T>) => {
  const [errors, setErrors] = useState<Record<string, string>>({})

  const validate = useCallback((data: Record<string, unknown>) => {
    const result = schema.safeParse(data)
    if (result.success) {
      setErrors({})
      return { valid: true as const, data: result.data }
    }

    const fieldErrors: Record<string, string> = {}
    for (const issue of result.error.issues) {
      const path = issue.path.join('.')
      if (!fieldErrors[path]) {
        fieldErrors[path] = issue.message
      }
    }
    setErrors(fieldErrors)
    return { valid: false as const, errors: fieldErrors }
  }, [schema])

  return { errors, validate, clearErrors: () => setErrors({}) }
}

const loginSchema = z.object({
  email: z.string().email('请输入有效的邮箱地址'),
  password: z.string().min(8, '密码至少 8 个字符'),
})

const LoginForm: FC = () => {
  const { errors, validate } = useFormValidation(loginSchema)

  const handleSubmit = (e: FormEvent<HTMLFormElement>) => {
    e.preventDefault()
    const formData = new FormData(e.currentTarget)
    const data = Object.fromEntries(formData)
    const result = validate(data)
    if (result.valid) {
      // 提交到服务端
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="email" type="email" />
      {errors.email && <span>{errors.email}</span>}
      <input name="password" type="password" />
      {errors.password && <span>{errors.password}</span>}
      <button type="submit">登录</button>
    </form>
  )
}
服务端验证中间件
服务端验证是安全的最后保障：


import { z } from 'zod';
import type { Context, Next } from 'hono';

const validateBody = <T>(schema: z.ZodSchema<T>) => {
  return async (c: Context, next: Next) => {
    const body = await c.req.json().catch(() => null);

    if (!body) {
      return c.json({ error: '请求体格式错误' }, 400);
    }

    const result = schema.safeParse(body);
    if (!result.success) {
      return c.json(
        {
          error: '数据验证失败',
          details: result.error.issues.map((i) => ({
            field: i.path.join('.'),
            message: i.message,
          })),
        },
        400,
      );
    }

    c.set('validatedBody', result.data);
    await next();
  };
};

const validateQuery = <T>(schema: z.ZodSchema<T>) => {
  return async (c: Context, next: Next) => {
    const query = c.req.query();
    const result = schema.safeParse(query);

    if (!result.success) {
      return c.json({ error: '查询参数无效' }, 400);
    }

    c.set('validatedQuery', result.data);
    await next();
  };
};
小结
    

  • 输入验证和净化是纵深防御的第一道防线，遵循"永不信任客户端数据"原则
    • 

  • Zod 等 Schema 验证库提供类型安全的输入验证，兼顾开发体验和安全性
    • 

  • HTML 净化使用 DOMPurify 配合白名单策略，按场景（文章/评论/纯文本）区分配置
    • 

  • 前端验证提升用户体验，服务端验证保障安全——两者缺一不可
    • 

  • 白名单验证优于黑名单过滤——只允许已知安全的值比过滤已知危险值更可靠
    • 

  • 自定义 DOMPurify 钩子可以实现细粒度的安全策略（如强制外链 noopener）
    • 

  • 验证中间件将安全逻辑从业务代码中分离，提高可维护性和一致性
    •
