依赖安全

核心概念

现代前端项目平均依赖数百甚至数千个第三方 npm 包，这些依赖构成了一个庞大的供应链。依赖安全是前端安全中日益重要的领域——一个流行库的漏洞可能影响数百万项目，一个被入侵的包维护者账号可能向整个生态系统注入恶意代码。2021 年的 ua-parser-js 事件和 2022 年的 node-ipc 事件都证明了供应链攻击的破坏力。

依赖安全管理涵盖三个维度：已知漏洞的检测与修复、依赖更新的安全策略、以及对恶意包的防范。

漏洞扫描与管理
漏洞扫描是依赖安全的基础环节：


npm audit
npm audit --production
npm audit fix
npm audit fix --force

npx better-npm-audit audit --level moderate

npx snyk test
npx snyk monitor
在 CI/CD 中集成漏洞扫描：


name: Security Audit
on:
  push:
    branches: [main]
  pull_request:
  schedule:
    - cron: '0 8 * * 1'

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - run: pnpm audit --audit-level=moderate
      - name: Snyk Security Scan
        uses: snyk/actions/node@master
        env:
          SNYK_TOKEN: ${{ secrets.SNYK_TOKEN }}

依赖锁定与版本策略
lockfile 是确保依赖一致性和可审计性的核心工具：


pnpm install --frozen-lockfile

git diff pnpm-lock.yaml | head -100

npm diff --diff=lodash@4.17.20 --diff=lodash@4.17.21

自动化依赖更新
Renovate 和 Dependabot 是自动化依赖更新的两大工具：


{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "extends": ["config:recommended", ":separateMultipleMajorReleases", "group:allNonMajor"],
  "schedule": ["before 8am on Monday"],
  "vulnerabilityAlerts": {
    "enabled": true,
    "schedule": ["at any time"]
  },
  "packageRules": [
    {
      "matchPackagePatterns": ["^@types/"],

依赖审查清单
新增依赖前的安全审查流程：


interface PackageAuditChecklist {
  name: string;
  checks: {
    weeklyDownloads: boolean;
    lastPublish: boolean;
    maintainerCount: boolean;
    knownVulnerabilities: boolean;
    licenseCompatible: boolean;
    noPostInstallScripts: boolean;
    typescriptSupport: boolean;
    bundleSize: boolean;
  };
}

const auditNewDependency = async (packageName: string): Promise<PackageAuditChecklist> => {
  const checks = {
    weeklyDownloads: false,
    lastPublish: false,
    maintainerCount: false,
    knownVulnerabilities: false,
    licenseCompatible: false,
    noPostInstallScripts: false,
    typescriptSupport: false,
    bundleSize: false,
  };
  return { name: packageName, checks };
};
小结
    

  • 前端项目的依赖链构成了庞大的供应链攻击面，需要系统性的安全管理
    • 

  • npm audit / Snyk 是漏洞扫描的基础工具，应集成到 CI 流程中
    • 

  • lockfile 确保依赖一致性，CI 中始终使用 --frozen-lockfile 安装
    • 

  • 版本策略：核心框架精确版本，重要库 tilde，一般依赖 caret
    • 

  • Renovate 或 Dependabot 实现自动化依赖更新，安全补丁应即时合并
    • 

  • 新增依赖前应进行安全审查：下载量、维护活跃度、已知漏洞、许可证兼容性
    • 

  • pnpm.overrides 可以强制修复传递依赖中的已知漏洞
    • 

  • 使用 @scope 前缀防止依赖混淆攻击
    •
