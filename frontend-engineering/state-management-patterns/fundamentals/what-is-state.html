什么是状态

核心概念

状态（State）是程序在某一时刻所持有的全部数据集合，它完整描述了系统当前的情况，并决定了系统对后续输入的响应方式。

从本质上讲，状态是一个从时间到数据的映射函数：在任意时间点 t，系统都存在一个确定的状态值 S(t)。用户的每一次交互、每一次网络响应，都是将系统从 S(t) 推向 S(t+1) 的状态转换。

状态的数学表达
可以将状态系统抽象为一个三元组 (S, A, T)：


    

  • S — 状态空间（所有可能的状态集合）
    • 

  • A — 动作空间（所有可能的事件/输入）
    • 

  • T: S × A → S — 转换函数（给定当前状态和一个动作，产出下一个状态）
    • 



type State = {
  user: User | null;
  items: Item[];
  loading: boolean;
  error: Error | null;
};

type Action =
  | { type: 'FETCH_START' }
  | { type: 'FETCH_SUCCESS'; payload: Item[] }
  | { type: 'FETCH_ERROR'; payload: Error }
  | { type: 'LOGOUT' };

function transition(state: State, action: Action): State {
  switch (action.type) {
    case 'FETCH_START':
      return { ...state, loading: true, error: null };
    case 'FETCH_SUCCESS':
      return { ...state, loading: false, items: action.payload };
    case 'FETCH_ERROR':
      return { ...state, loading: false, error: action.payload };
    case 'LOGOUT':
      return { user: null, items: [], loading: false, error: null };
  }
}

UI = f(State) 原理
现代前端框架的核心哲学可以浓缩为一个公式：


UI = f(State)
UI 不是被命令式地"操作"出来的，而是由状态"声明式地"推导出来的。给定相同的状态输入，函数 f 总是返回相同的 UI 输出 —— 这就是UI 的纯函数特性。


从命令式到声明式
// ❌ 命令式：手动操作 DOM，状态和 UI 分离
function imperativeUpdate(count: number): void {
  const el = document.getElementById('counter')!;
  el.textContent = String(count);
  if (count > 10) {
    el.classList.add('highlight');
  } else {
    el.classList.remove('highlight');
  }
}
// ✅ 声明式：UI 是状态的函数，React 自动处理更新
interface CounterProps {
  count: number;
}

function Counter({ count }: CounterProps) {
  return (
    <span className={count > 10 ? "highlight" : ""}>
      {count}
    </span>
  );
}

完整的单向数据流
UI = f(State) 在实际框架中形成了完整的单向数据流循环：


import { useReducer } from "react";

interface TodoState {
  todos: { id: number; text: string; done: boolean }[];
  filter: "all" | "active" | "completed";
}

type TodoAction =
  | { type: "ADD"; text: string }
  | { type: "TOGGLE"; id: number }
  | { type: "SET_FILTER"; filter: TodoState["filter"] };

function todoReducer(state: TodoState, action: TodoAction): TodoState {
  switch (action.type) {
    case "ADD":
      return {
        ...state,
        todos: [
          ...state.todos,
          { id: Date.now(), text: action.text, done: false },
        ],
      };
    case "TOGGLE":
      return {
        ...state,
        todos: state.todos.map((t) =>
          t.id === action.id ? { ...t, done: !t.done } : t
        ),
      };
    case "SET_FILTER":
      return { ...state, filter: action.filter };
  }
}

function TodoApp() {
  const [state, dispatch] = useReducer(todoReducer, {
    todos: [],
    filter: "all",
  });

  const filtered = state.todos.filter((t) => {
    if (state.filter === "active") return !t.done;
    if (state.filter === "completed") return t.done;
    return true;
  });

  return (
    <div>
      <ul>
        {filtered.map((t) => (
          <li
            key={t.id}
            onClick={() => dispatch({ type: "TOGGLE", id: t.id })}
            style={{ textDecoration: t.done ? "line-through" : "none" }}
          >
            {t.text}
          </li>
        ))}
      </ul>
    </div>
  );
}

状态转换 vs 副作用的边界
核心原则：状态转换函数（reducer）必须是纯函数，副作用应当在转换之外处理。


在 React 中正确分离副作用
import { useState, useEffect, useCallback } from "react";

interface User {
  id: number;
  name: string;
  email: string;
}

function useUser(userId: number) {
  const [user, setUser] = useState<User | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<Error | null>(null);

  useEffect(() => {
    let cancelled = false;

    setLoading(true);
    setError(null);

    fetch(`/api/users/${userId}`)
      .then((res) => {
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        return res.json() as Promise<User>;
      })
      .then((data) => {
        if (!cancelled) {
          setUser(data);
          setLoading(false);
        }
      })
      .catch((err) => {
        if (!cancelled) {
          setError(err);
          setLoading(false);
        }
      });

    return () => {
      cancelled = true;
    };
  }, [userId]);

  return { user, loading, error };
}

function UserProfile({ userId }: { userId: number }) {
  const { user, loading, error } = useUser(userId);

  if (loading) return <div>加载中...</div>;
  if (error) return <div>错误：{error.message}</div>;
  if (!user) return null;

  return (
    <div>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  );
}

状态一致性问题
当同一数据在多个地方有多份副本时，这些副本之间可能出现不一致 —— 这是状态管理中最棘手的问题之一。


不一致的来源
导致不一致的典型模式
import { useState, useEffect } from "react";

interface Product {
  id: number;
  name: string;
  price: number;
  stock: number;
}

function ProductList() {
  const [products, setProducts] = useState<Product[]>([]);

  useEffect(() => {
    fetch("/api/products").then((r) => r.json()).then(setProducts);
  }, []);

  return (
    <ul>
      {products.map((p) => (
        <ProductCard key={p.id} product={p} />
      ))}
    </ul>
  );
}

function ProductCard({ product }: { product: Product }) {
  const [localProduct, setLocalProduct] = useState(product);

  const updateStock = () => {
    setLocalProduct({ ...localProduct, stock: localProduct.stock - 1 });
  };

  return (
    <div>
      <span>{localProduct.name}</span>
      <span>库存: {localProduct.stock}</span>
      <button onClick={updateStock}>购买</button>
    </div>
  );
}
上面的代码存在严重的一致性问题：ProductCard 中的 localProduct 与父组件的 products 列表之间是脱节的。购买操作只更新了本地副本，父组件和服务器都不知道变化。


解决方案：状态提升 + 单一来源
import { useState, useEffect, useCallback } from "react";

interface Product {
  id: number;
  name: string;
  price: number;
  stock: number;
}

function ProductList() {
  const [products, setProducts] = useState<Product[]>([]);

  useEffect(() => {
    fetch("/api/products").then((r) => r.json()).then(setProducts);
  }, []);

  const handlePurchase = useCallback((productId: number) => {
    setProducts((prev) =>
      prev.map((p) =>
        p.id === productId ? { ...p, stock: p.stock - 1 } : p
      )
    );
    fetch(`/api/products/${productId}/purchase`, { method: "POST" });
  }, []);

  return (
    <ul>
      {products.map((p) => (
        <ProductCard
          key={p.id}
          product={p}
          onPurchase={handlePurchase}
        />
      ))}
    </ul>
  );
}

function ProductCard({
  product,
  onPurchase,
}: {
  product: Product;
  onPurchase: (id: number) => void;
}) {
  return (
    <div>
      <span>{product.name}</span>
      <span>库存: {product.stock}</span>
      <button onClick={() => onPurchase(product.id)}>购买</button>
    </div>
  );
}

实现可预测性的手段
利用 TypeScript 类型系统排除非法状态
type AsyncState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; error: Error };

function renderAsync<T>(
  state: AsyncState<T>,
  render: (data: T) => React.ReactNode
): React.ReactNode {
  switch (state.status) {
    case "idle":
      return <div>等待操作...</div>;
    case "loading":
      return <div>加载中...</div>;
    case "success":
      return <>{render(state.data)}</>;
    case "error":
      return <div>错误：{state.error.message}</div>;
  }
}
这种辨别联合类型（Discriminated Union） 模式，使得在 status === "success" 分支中必然存在 data，在 status === "error" 分支中必然存在 error。非法组合（如 status === "loading" 但有 data）在类型层面就被排除了。




单一数据源原则
Single Source of Truth（SSOT） 是状态管理中最重要的设计原则之一。它要求每一条数据只有一个权威来源，所有需要该数据的地方都从这个唯一来源读取。


违反 SSOT 的后果
实践中的 SSOT
import { create } from "zustand";

interface User {
  id: number;
  name: string;
  email: string;
  role: "admin" | "user";
}

interface AuthStore {
  user: User | null;
  token: string | null;
  login: (user: User, token: string) => void;
  logout: () => void;
  updateProfile: (updates: Partial<Pick<User, "name" | "email">>) => void;
}

const useAuthStore = create<AuthStore>((set) => ({
  user: null,
  token: null,
  login: (user, token) => set({ user, token }),
  logout: () => set({ user: null, token: null }),
  updateProfile: (updates) =>
    set((state) => ({
      user: state.user ? { ...state.user, ...updates } : null,
    })),
}));

function Header() {
  const userName = useAuthStore((s) => s.user?.name);
  return <header>{userName ? `你好，${userName}` : "请登录"}</header>;
}

function ProfilePage() {
  const user = useAuthStore((s) => s.user);
  const updateProfile = useAuthStore((s) => s.updateProfile);

  if (!user) return <div>未登录</div>;

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault();
        const formData = new FormData(e.currentTarget);
        updateProfile({
          name: formData.get("name") as string,
          email: formData.get("email") as string,
        });
      }}
    >
      <input name="name" defaultValue={user.name} />
      <input name="email" defaultValue={user.email} />
      <button type="submit">保存</button>
    </form>
  );
}
Header 和 ProfilePage 都从同一个 useAuthStore 读取用户信息。当 ProfilePage 调用 updateProfile 时，Header 自动得到更新 —— 不存在不一致的可能。

状态快照 vs 引用
这是理解 React 等框架状态机制的关键区别。React 的状态是快照语义，而非引用语义。


快照语义
每次渲染都"冻结"了当前的状态值。在同一次渲染的整个过程中，状态值不会改变，即使你在事件处理函数中调用了 setState。


import { useState } from "react";

function SnapshotDemo() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
  };

  return (
    <div>
      <p>{count}</p>
      <button onClick={handleClick}>+3?</button>
    </div>
  );
}
点击按钮后 count 变为 1 而非 3。因为三次 setCount 都基于同一个快照值 count = 0，等价于三次 setCount(0 + 1)。

使用函数式更新解决快照限制
当需要基于"最新状态"做连续更新时，使用函数式更新（updater function）：


import { useState } from "react";

function FunctionalUpdateDemo() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount((prev) => prev + 1);
    setCount((prev) => prev + 1);
    setCount((prev) => prev + 1);
  };

  return (
    <div>
      <p>{count}</p>
      <button onClick={handleClick}>+3</button>
    </div>
  );
}
这次点击后 count 正确变为 3，因为每个 updater 函数接收的 prev 是前一个 updater 的结果。

小结
状态是前端应用的核心骨架。理解状态的本质、生命周期和管理原则，是构建可靠应用的前提。


核心要点回顾：


    

  • 状态是时间维度上的数据映射，由 (S, A, T) 三元组定义
    • 

  • UI = f(State) 是现代前端的根基，声明式优于命令式
    • 

  • 副作用必须与纯粹的状态转换隔离
    • 

  • 状态有明确的生命周期：创建 → 活跃 → 销毁
    • 

  • 多份副本是一致性问题的根源，用 SSOT 原则消除
    • 

  • 可预测性来自纯函数、不可变更新和类型安全
    • 

  • React 的状态是快照语义，连续更新需用函数式 updater
