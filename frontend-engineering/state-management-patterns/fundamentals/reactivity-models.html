Part II · 框架 (Frameworks)状态管理模式 简介基础概念 简介响应式模型

响应式模型

核心概念

响应式是状态变化时自动更新相关依赖的机制，是现代前端框架的核心。不同框架采用不同的响应式模型：React 使用虚拟 DOM diff，Vue 使用基于 Proxy 的依赖追踪，Signals 使用细粒度订阅。理解这些差异有助于选择合适的技术栈和优化策略。每种模型在性能特征、心智模型和调试体验上都有显著差异。

响应式的基本思想
问题：手动更新
// 手动更新，容易出错
let count = 0;
let double = count * 2;

count = 1;
// double 不会自动更新！仍然是 0
console.log(double); // 0，不对！
解决：响应式
// 响应式，自动更新
const count = ref(0);
const double = computed(() => count.value * 2);

count.value = 1;
// double 自动更新为 2
console.log(double.value); // 2，正确！
常见响应式模型
1. 推送模型 (Push-based)
核心思想: 状态变化时，主动推送通知给依赖。


代表: MobX, Vue 2/3, Solid.js


工作原理:


    

  • 使用 Proxy (Vue 3) 或 Object.defineProperty (Vue 2)
    • 

  • 拦截属性的 get/set
    • 

  • get 时收集依赖
    • 

  • set 时通知依赖更新
    • 



示例 (Vue 3):


import { reactive, computed } from 'vue';

const state = reactive({
  count: 0,
});

const double = computed(() => state.count * 2);

// 修改 count
state.count = 1;
// double 自动更新
console.log(double.value); // 2
优点:


    

  • 精确更新（只更新变化的）
    • 

  • 性能通常很好
    • 

  • 代码简洁
    • 



缺点:


    

  • 实现复杂
    • 

  • 调试可能困难
    • 

  • 可能有内存泄漏（如果不清理依赖）
    • 



2. 拉取模型 (Pull-based)
核心思想: 需要时才检查是否变化，重新渲染。


代表: React


工作原理:


    

  • 状态变化时，标记组件为脏
    • 

  • 下次渲染时，重新执行组件函数
    • 

  • 比较新旧虚拟 DOM，更新真实 DOM
    • 



示例 (React):


import { useState, useMemo } from 'react'

function Counter() {
  const [count, setCount] = useState(0)
  const double = useMemo(() => count * 2, [count])

  return (
    <div>
      <p>{double}</p>
      <button onClick={() => setCount(c => c + 1)}>
        Increment
      </button>
    </div>
  )
}
优点:


    

  • 实现简单
    • 

  • 可预测性好
    • 

  • 调试容易
    • 

  • 时间旅行调试容易
    • 



缺点:


    

  • 可能重新渲染不需要的组件
    • 

  • 需要手动优化（memo, useMemo, useCallback）
    • 

  • 大量组件时可能性能问题
    • 



3. 信号模型 (Signals)
核心思想: 细粒度的响应式原语，结合推送和拉取的优点。


代表: Preact Signals, Solid.js, Angular Signals, Qwik


工作原理:


    

  • 信号是可观察的值容器
    • 

  • 自动追踪依赖
    • 

  • 精确更新
    • 

  • 可以在组件外使用
    • 



示例 (Preact Signals):


import { signal, computed } from '@preact/signals'

const count = signal(0)
const double = computed(() => count.value * 2)

// 在组件中使用
function Counter() {
  return (
    <div>
      <p>{double}</p>
      <button onClick={() => count.value++}>
        Increment
      </button>
    </div>
  )
}
优点:


    

  • 性能极佳
    • 

  • 精确更新
    • 

  • 灵活（可在组件外使用）
    • 

  • 简洁的 API
    • 



缺点:


    

  • 相对较新
    • 

  • 生态还在发展
    • 

  • 学习新的概念
    •

小结
    

  • 不同响应式模型有不同的性能特点和优化策略
    • 

  • React 的 Pull 模型需要更多手动优化（memo、useMemo）
    • 

  • Vue/MobX 的 Push 模型自动追踪依赖，优化更简单
    • 

  • Signals 是最新趋势，性能最优但生态较小
    • 



核心要点回顾：


    

  • 响应式自动更新依赖
    • 

  • 三种常见模型：推送、拉取、信号
    • 

  • React 是拉取模型，Vue/MobX 是推送模型
    • 

  • 信号是新兴的、高性能的选择
    • 

  • 根据项目需求和团队选择
    • 



附录：响应式模型演进
从 jQuery 的手动 DOM 操作到 AngularJS 的脏检查，再到 React 虚拟 DOM 和 Vue 的 Proxy 响应式，前端响应式模型经历了多次范式转移。Signals 代表了当前的演进方向——它结合了 Push 模型的精确更新和 Pull 模型的可预测性，正在被 Angular、Preact、Solid 等多个框架采纳。选择响应式模型时，团队熟悉度和生态成熟度往往比理论性能更重要。
