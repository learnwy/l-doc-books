状态分类

核心概念

将状态按不同维度分类，有助于选择合适的管理方式。在前端应用中，状态可以按作用域（本地/共享/全局）、来源（客户端/服务器）和生命周期（临时/持久）等维度划分。正确分类是避免"把所有东西都塞进全局 Store"这一常见反模式的关键第一步。

按作用域分类
1. 本地状态 (Local State)
定义: 只在一个组件或小范围内使用的状态。本地状态是最简单、最高效的状态管理方式，也是绝大多数状态的首选归属。


例子:


    

  • 输入框的内容
    • 

  • 下拉菜单是否展开
    • 

  • 表单的临时输入
    • 

  • 组件内部的加载状态
    • 

  • 模态框的开关状态
    • 



特点:


    

  • 作用域小，变更影响范围可控
    • 

  • 不需要共享给其他组件
    • 

  • 变化频繁但只影响当前组件
    • 

  • 简单管理即可，无需外部库
    • 



管理方式:


    

  • React: useState, useReducer
    • 

  • Vue: data, ref
    • 

  • 不需要外部库
    • 



2. 全局状态 (Global State)
定义: 多个组件需要共享的状态，通常跨越组件树的多个层级。


例子:


    

  • 当前登录的用户信息
    • 

  • 主题设置（浅色/深色/跟随系统）
    • 

  • 购物车内容
    • 

  • 通知列表
    • 

  • 国际化语言偏好
    • 



特点:


    

  • 需要跨组件共享
    • 

  • 变化可能影响多个地方
    • 

  • 需要更高级的管理
    • 



管理方式:


    

  • Redux, Zustand, Jotai (React)
    • 

  • Pinia, Vuex (Vue)
    • 

  • 需要状态管理库
    • 



3. 服务器状态 (Server State)
定义: 从服务器获取的数据，需要同步、缓存、失效处理。服务器状态与客户端状态有本质区别：它不由客户端"拥有"，客户端只是缓存了一份副本。


例子:


    

  • 用户列表
    • 

  • 产品详情
    • 

  • 评论数据
    • 

  • 搜索结果
    • 

  • 分页数据
    • 



特点:


    

  • 来源是服务器
    • 

  • 需要缓存
    • 

  • 需要处理加载、错误状态
    • 

  • 需要在后台更新
    • 

  • 需要失效和重新获取
    • 



管理方式:


    

  • TanStack Query (React Query)
    • 

  • SWR
    • 

  • Apollo Client (GraphQL)
    • 



4. URL 状态 (URL State)
定义: 存储在 URL 中的状态（路由、查询参数）。


例子:


    

  • 当前路由: /users/123
    • 

  • 查询参数: ?page=2&sort=date
    • 

  • Hash: #section-3
    • 



特点:


    

  • 可分享（ bookmarkable）
    • 

  • 可恢复（刷新页面保留）
    • 

  • 影响浏览器历史
    • 

  • SEO 友好
    • 



管理方式:


    

  • React Router
    • 

  • Vue Router
    • 

  • Next.js/App Router
    •

1. 内存状态 (In-Memory State)
定义: 只存在于内存中，刷新页面丢失。


例子:


    

  • 大部分本地状态
    • 

  • 临时的全局状态
    • 

  • 拖拽中的坐标信息
    • 



特点:


    

  • 速度快，无序列化开销
    • 

  • 刷新丢失
    • 

  • 不需要持久化
    • 

  • 适合高频变化数据
    • 



2. 持久化状态 (Persistent State)
定义: 保存在存储中，刷新页面可以恢复。


例子:


    

  • 用户偏好设置（深色模式、字体大小）
    • 

  • 购物车（未登录用户）
    • 

  • 表单草稿（多步骤向导进度）
    •

按变化频率分类
1. 高频变化状态
例子:


    

  • 输入框打字
    • 

  • 鼠标位置
    • 

  • 滚动位置
    • 

  • 动画进度
    • 



特点:


    

  • 变化非常频繁
    • 

  • 可能触发很多渲染
    • 

  • 需要优化性能
    • 



管理考虑:


    

  • 防抖 (debounce)
    • 

  • 节流 (throttle)
    • 

  • 避免不必要的渲染
    • 



2. 低频变化状态
例子:


    

  • 用户信息
    • 

  • 主题设置
    • 

  • 应用配置
    • 

  • 权限信息
    • 



特点:


    

  • 不常变化
    • 

  • 变化时影响较大
    • 

  • 可以缓存
    •

避免过度全局化
常见错误: 把所有状态都放在全局。


问题:


    

  • 不必要的渲染
    • 

  • 代码复杂度增加
    • 

  • 性能下降
    • 



原则:


    

  • 能本地就本地
    • 

  • 需要共享才全局
    • 

  • 来自服务器的用专门的服务器状态管理
    • 



小结
    

  • 能本地就本地，避免过度全局化
    • 

  • 服务器状态用专门的管理库（TanStack Query / SWR）
    • 

  • 正确分类状态是选择合适管理方式的前提
    • 



核心要点回顾：


    

  • 按作用域：本地、全局、服务器、URL
    • 

  • 按持久性：内存、持久化
    • 

  • 按变化频率：高频、低频
    • 

  • 能本地就本地，不要过度全局化
    • 

  • 服务器状态用专门的库管理
    •
