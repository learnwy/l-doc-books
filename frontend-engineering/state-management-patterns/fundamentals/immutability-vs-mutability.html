Part II · 框架 (Frameworks)状态管理模式 简介基础概念 简介不可变 vs 可变

不可变 vs 可变

核心概念

不可变 (Immutability) 和可变 (Mutability) 是两种修改数据的方式，对状态管理影响巨大。不可变数据在每次修改时创建新对象，保留了变更历史，使得时间旅行调试、浅比较优化和并发安全成为可能。可变数据直接修改原对象，代码更简洁但牺牲了可追踪性。

定义
可变 (Mutable)
定义: 直接修改原对象。


// 可变：直接修改
const user = { name: 'Alice', age: 30 };
user.age = 31; // 修改了原对象！
console.log(user); // { name: 'Alice', age: 31 }
不可变 (Immutable)
定义: 不修改原对象，创建新对象。


// 不可变：创建新对象
const user = { name: 'Alice', age: 30 };
const updatedUser = { ...user, age: 31 }; // 新对象！
console.log(user); // 原对象没变：{ name: 'Alice', age: 30 }
console.log(updatedUser); // 新对象：{ name: 'Alice', age: 31 }
对比
代码对比
可变方式
// 修改数组
const todos = [{ text: 'Learn React', done: false }];
todos[0].done = true; // 直接修改
todos.push({ text: 'Learn Redux', done: false }); // 直接修改

// 修改对象
const state = { count: 0 };
state.count++; // 直接修改
不可变方式
// 修改数组
const todos = [{ text: 'Learn React', done: false }];
const updatedTodos = [
  { ...todos[0], done: true }, // 更新第一项
  { text: 'Learn Redux', done: false }, // 添加新项
];

// 修改对象
const state = { count: 0 };
const newState = { ...state, count: state.count + 1 };

不可变的好处
1. 可预测性
// 不可变：函数不会修改输入
function updateUser(user: User) {
  return { ...user, lastLogin: Date.now() };
}

const user = { name: 'Alice' };
const updated = updateUser(user);
console.log(user); // 没变！不用担心副作用
2. 时间旅行调试
Redux DevTools 可以让你回到任何之前的状态，因为状态是不可变的，每一步都保存了完整的快照。


3. React 性能优化
// React.memo 可以用引用比较
const TodoItem = React.memo(({ todo }) => {
  return <div>{todo.text}</div>
})

// 只有 todo 的引用变了，才重新渲染
// 不可变让这变得简单
4. 变更追踪简单
// 只需要比较引用
if (prevState !== nextState) {
  // 状态变了，更新 UI
}
不可变的实现方式
1. 手动实现（对象展开）
// 对象
const state = { count: 0, user: { name: 'Alice' } };
const newState = {
  ...state,
  count: state.count + 1,
  user: { ...state.user, name: 'Bob' }, // 嵌套更新
};

// 数组
const todos = [{ id: 1, text: 'Learn' }];
const newTodos = [...todos.map((t) => (t.id === 1 ? { ...t, done: true } : t)), { id: 2, text: 'New todo' }];
2. Immer (推荐)
Immer 让你用可变的写法，得到不可变的结果。


import { produce } from 'immer';

const state = { count: 0, todos: [] };

const newState = produce(state, (draft) => {
  // 可以直接修改 draft！
  draft.count++;
  draft.todos.push({ text: 'Learn Immer' });
});

// state 没变，newState 是新的！
console.log(state.count); // 0
console.log(newState.count); // 1
优点:


    

  • 代码简洁
    • 

  • 不需要展开操作
    • 

  • 处理嵌套简单
    • 

  • 性能好（结构共享）
    • 



3. 不可变数据库
    

  • Immer: 最流行，最简单
    • 

  • Immutable.js: Facebook 的库，API 复杂
    • 

  • Immer 是目前的最佳选择
    • 



Redux 与不可变
Redux 要求 reducer 是纯函数，不可变。


// ✅ 好：不可变
function counterReducer(state = { count: 0 }, action) {
  switch (action.type) {
    case 'increment':
      return { ...state, count: state.count + 1 };
    default:
      return state;
  }
}

// ❌ 坏：可变
function badCounterReducer(state = { count: 0 }, action) {
  switch (action.type) {
    case 'increment':
      state.count++; // ❌ 直接修改！
      return state;
    default:
      return state;
  }
}
什么时候用哪个
优先不可变的场景
✅ 用不可变:


    

  • React 应用
    • 

  • Redux/Zustand 等状态管理
    • 

  • 需要时间旅行调试
    • 

  • 团队协作（避免副作用）
    • 

  • 需要可预测性
    • 



可以可变的场景
✅ 用可变:


    

  • 局部变量，不会泄露
    • 

  • 性能极高的场景（如游戏循环）
    • 

  • 简单的脚本
    • 

  • 使用 Immer（写起来像可变，实际不可变）
    • 



小结
    

  • 不可变带来可预测性、可调试性和性能优化
    • 

  • Immer 是最佳实践：写起来像可变，结果是不可变
    • 

  • MobX/Valtio 使用 Proxy 让可变也变得可追踪
    • 



核心要点回顾：


    

  • 可变直接修改原对象，不可变创建新对象
    • 

  • 不可变让代码更可预测、更易调试
    • 

  • React 和 Redux 推荐不可变
    • 

  • Immer 让不可变变得简单
    • 

  • 优先用不可变，特别是在 React 应用中
    •
