设计系统中的无障碍

核心概念

无障碍（Accessibility）是设计系统最大的价值主张——核心组件团队投入一次做好无障碍，所有消费方自动受益（路缘效应）。但无障碍必须从第一天就内置到组件中，而非后期补救——后期改造的成本高出 5-10 倍。本节详细讲解设计系统中无障碍的工程化实践——语义化 HTML 默认行为、ARIA 模式、键盘支持、焦点管理、颜色对比度令牌、屏幕阅读器测试、自动化无障碍测试，以及无头组件库的应用。Adobe React Spectrum、Radix UI、Headless UI 是无障碍优先设计系统的典范。

层级 无障碍责任
令牌层 颜色对比度满足 WCAG 标准
组件层 语义化 HTML、ARIA、键盘支持
模式层 无障碍最佳实践文档
测试层 自动化 + 手动 + 残障用户测试
文档层 每个组件标注无障碍说明

设计系统中无障碍的价值

一次投入、全体受益：

  • Combobox 无障碍投入 200 小时一次实现。
  • 100 个产品团队使用 → 节省 20000 小时。
  • 一致的无障碍体验。
  • 简化法律合规。

反面案例（无设计系统时）：

  • 每个产品团队自行实现 Combobox。
  • 大部分无障碍实现有误。
  • 体验不一致。
  • 诉讼风险。

令牌层无障碍

颜色对比度令牌：

  • 设计令牌时验证对比度。
  • AA 级：4.5:1 正常文本、3:1 大号文本。
  • AAA 级：7:1。

检测工具：

  • WebAIM 对比度检查器。
  • Stark（Figma 插件）。
  • 浏览器开发者工具。

实战要点：

  • 验证所有文本与背景的组合配对。
  • 特别注意语义色（如警告黄色在白底上容易不达标）。

令牌提供无障碍安全的颜色配对：

{
  "color.text.primary.on-background": "{color.gray.900}",
  "color.text.primary.on-action-primary": "{color.white}",
  "color.warning.text-on-background": "{color.amber.900}"
}

组件层无障碍

默认使用语义化 HTML：

// 错误示例
<div onClick={handleClick}>点击</div>

// 正确示例
<button onClick={handleClick}>点击</button>

原因：

  • 原生语义标签。
  • 内置键盘支持。
  • 屏幕阅读器自动播报。

多态组件：

<Button as="a" href="...">
  链接
</Button>

让使用方选择正确的 HTML 元素。

ARIA 模式

WAI-ARIA 创作实践：

  • 标准交互模式（组合框、列表框、菜单、对话框、手风琴、标签页）。
  • 提供详细的实现指南。

实战要点：

  • 遵循标准模式。
  • 不要自行发明新方案。

使用无头组件库：

  • Radix UI、Ariakit、Headless UI 已实现标准模式。
  • 复杂交互时优先使用。

键盘支持

各组件的键盘标准：

按钮：

  • Tab 键聚焦。
  • Enter / Space 键激活。

对话框（Modal）：

  • 焦点陷阱（Tab 键在弹窗内循环）。
  • Esc 键关闭。
  • 打开时自动聚焦第一个可聚焦元素。

组合框（Combobox）：

  • Tab 键聚焦输入框。
  • 下箭头打开列表并选中第一项。
  • 上/下箭头导航。
  • Enter 选择。
  • Esc 关闭。

标签页（Tabs）：

  • Tab 键聚焦当前标签。
  • 左右箭头切换标签。
  • Home / End 跳到首/末标签。

测试方法：

  • 断开鼠标。
  • 仅用键盘操作。
  • 是否能完成所有任务？

焦点管理

焦点可见样式：

  • 不要设置 outline: none。
  • 使用 :focus-visible 仅在键盘操作时显示。
  • 高对比度轮廓。

对话框焦点陷阱：

function Modal({ isOpen, children }) {
  const ref = useRef();

  useEffect(() => {
    if (isOpen) {
      const focusable = ref.current.querySelectorAll('button, input, [tabindex]');
      focusable[0]?.focus();
    }
  }, [isOpen]);

  // 将 Tab 导航限制在对话框内
}

或使用现成库：

  • focus-trap-react。
  • Radix UI Dialog（内置焦点陷阱）。

关闭后恢复焦点：

  • 打开前保存 activeElement。
  • 关闭后恢复焦点位置。

实时区域

aria-live 用于动态内容播报：

<div aria-live="polite" aria-atomic="true">
  {message}
</div>

播报级别：

  • off：不播报。
  • polite：空闲时播报。
  • assertive：立即打断播报。

应用场景：

  • Toast 通知。
  • 表单验证消息。
  • 搜索结果数量。

屏幕阅读器测试

必须进行的测试：

VoiceOver（macOS / iOS）：

  • Cmd+F5 开启。
  • 使用 VO+右箭头导航。
  • 听取播报内容。

NVDA（Windows 免费）：

  • 免费下载。
  • Insert+Down 连续朗读。

TalkBack（Android）：

  • 设置 → 无障碍。

测试策略：

  • 每个组件至少在一个屏幕阅读器上测试。
  • 不要仅依赖模拟（不具代表性）。

自动化测试

axe-core / @axe-core/react：

import { axe } from 'jest-axe';

test('Button 无无障碍违规', async () => {
  const { container } = render(<Button>点击</Button>);
  const results = await axe(container);
  expect(results).toHaveNoViolations();
});

Playwright + axe：

const accessibilityScanResults = await new AxeBuilder({ page }).analyze();

Storybook + axe 插件：

  • 每个故事自动执行 axe 扫描。
  • 显示违规项。

覆盖率：

  • 约能发现 30-40% 的问题。
  • 其余需要手动测试和用户测试。

组件无障碍文档

每个组件的标准无障碍说明：

## 无障碍

### 键盘支持

| 按键         | 操作     |
| ------------ | -------- |
| Tab          | 聚焦按钮 |
| Enter、Space | 激活按钮 |

### ARIA 属性

- `role="button"`（非原生按钮时）
- `aria-pressed={isPressed}` 用于切换按钮
- `aria-disabled={isDisabled}` 用于禁用状态

### 屏幕阅读器

- 播报按钮标签
- 切换按钮播报"已按下"状态

### WCAG 合规

- 颜色对比度满足 AA 级（4.5:1）
- 焦点指示器可见

无头无障碍组件库

Radix UI：

  • React 无头组件。
  • 完善的无障碍实现。
  • 样式由使用方提供。

Headless UI：

  • 支持 React + Vue。
  • 与 Tailwind 配合。

Ariakit：

  • 类似 Radix。
  • 组件更丰富。

React Aria（Adobe）：

  • 基于 Hooks。
  • 极其完善的无障碍实现。

使用场景：

  • 在其基础上构建自己的设计系统。
  • 跳过无障碍的繁重实现。

移动端无障碍

iOS（UIKit / SwiftUI）：

  • VoiceOver 支持。
  • 动态字体（字号缩放）。
  • 颜色对比度。

Android（Compose）：

  • TalkBack 支持。
  • 触控目标 ≥ 48dp。

跨平台：

  • 相同的无障碍意图。
  • 各平台不同的实现方式。

令牌中的无障碍

最小触控目标令牌：

{
  "size.target.minimum": "44px"
}

焦点指示器令牌：

{
  "shadow.focus": "0 0 0 2px {color.action.primary}",
  "border.focus.width": "2px",
  "border.focus.color": "{color.action.primary}"
}

对比度验证的颜色配对：

  • 提前验证对比度。
  • 标注比率值。

设计阶段的无障碍约束

让设计师在工作中融入无障碍：

Stark（Figma 插件）：

  • 实时对比度检查。
  • 色盲模拟。
  • 设计师必备工具。

禁用状态设计：

  • 不能仅靠颜色区分。
  • 添加"已禁用"标签或图标。

错误状态设计：

  • 不能仅靠红色。
  • 添加 ⚠️ 图标 + 文字说明"错误：..."。

常见组件无障碍陷阱

对话框（Modal）：

  • 缺少焦点陷阱。
  • Esc 无法关闭。
  • 背景仍可被键盘访问。

组合框（Combobox）：

  • 仅有视觉高亮，无播报。
  • 键盘导航无法工作。

自定义按钮（div）：

  • 无法通过键盘访问。

轮播图：

  • 自动播放让屏幕阅读器用户迷失方向。
  • 需要暂停控制。

表单：

  • 标签未关联输入框。
  • 错误信息未播报。

无障碍审计

季度外部审计：

  • 第三方无障碍专业公司审查。
  • 发现偏移问题。

内部审计：

  • 团队配备专职无障碍专家。
  • 持续改进。

残障用户测试：

  • 招募屏幕阅读器用户。
  • 进行可用性测试。
  • 获取真实反馈。

合规要求

WCAG 2.2（当前版本）：

  • 4 项原则（可感知、可操作、可理解、健壮）。
  • 3 个合规级别（A / AA / AAA）。
  • 大多数法律要求 AA 级。

Section 508（美国联邦）。

ADA（美国公共服务场所）。

EAA（欧盟 2025 年生效）：

  • 面向消费者的产品必须可访问。

诉讼风险：

  • 和解金额 $50k-1M 以上。

反模式

1. 无障碍作为事后补救：

  • 后期添加成本高 5-10 倍。

2. 仅依赖自动化测试：

  • 漏检 60-70% 的问题。
  • 需要手动测试 + 用户测试。

3. 不一致的实现：

  • 部分组件有无障碍，部分没有。

4. 忽视移动端：

  • 仅关注 Web。

5. 不培训设计师：

  • 设计师不了解无障碍约束。

6. 不更新：

  • WCAG / ARIA 在持续演进。
  • 保持跟进。

投资回报率

在设计系统中投入无障碍：

  • 初期专注投入 4-8 周。
  • 持续维护。

回报：

  • 全球 13 亿残障用户市场。
  • 避免诉讼（$50k-1M 以上）。
  • SEO 优势。
  • 品牌声誉。
  • 路缘效应（所有人都受益）。

投资回报通常为正——尤其考虑法律风险。

实战建议

1. 从第一天就内置无障碍：

  • 不要后期补救。

2. 使用无头组件库：

  • Radix UI / React Aria。
  • 跳过繁重的实现工作。

3. 真实屏幕阅读器测试：

  • 不仅仅依赖 axe。

4. 招募残障用户参与测试：

  • 获取真实反馈。

5. 每个组件记录无障碍文档：

  • 键盘、ARIA、屏幕阅读器、WCAG 合规。

6. 培训团队：

  • 设计师和工程师都要有无障碍意识。

7. 持续集成中加入无障碍测试：

  • 回退时阻止合并。

小结

设计系统中的无障碍——一次投入让所有消费方受益（路缘效应），后期改造成本高出 5-10 倍。令牌层无障碍包括颜色对比度验证（WebAIM / Stark）和无障碍安全的颜色配对令牌（文本-背景组合）。组件层要求默认使用语义化 HTML（<button> 而非 <div onclick>）、多态 asChild、遵循 ARIA 模式（WAI-ARIA 创作实践）。键盘支持是每个组件的基本要求（Button Tab/Enter、Modal 焦点陷阱+Esc、Combobox 箭头导航、Tabs 箭头切换）。焦点管理包括可见样式（:focus-visible）、对话框陷阱和恢复、实时区域（aria-live polite/assertive）用于动态内容。屏幕阅读器测试 VoiceOver/NVDA/TalkBack 必不可少。自动化测试 axe-core/jest-axe + Playwright + Storybook 插件可发现 30-40% 问题。每个组件需要无障碍文档标注键盘 + ARIA + 屏幕阅读器 + WCAG 合规。无头组件库 Radix UI / Headless UI / Ariakit / React Aria 提供完善的无障碍能力，跳过繁重实现。移动端 iOS VoiceOver + 动态字体、Android TalkBack + 触控目标 48dp。令牌中的无障碍包括最小目标 44px、焦点阴影和对比度验证的颜色配对。设计阶段通过 Stark Figma 插件实时检查对比度和色盲模拟，禁用和错误状态不能仅靠颜色区分。常见陷阱有对话框缺焦点陷阱/Esc/aria-modal、组合框无播报、自定义 div 按钮、轮播自动播放和表单标签未关联。审计方式包括季度外部审计 + 内部专家 + 残障用户测试。合规要求 WCAG 2.2 AA + Section 508 + ADA + EAA 2025，诉讼风险 $50k-1M。反模式包括事后补救、仅自动化测试、不一致、忽视移动端、不培训和不更新。投入 4-8 周初期 → 13 亿用户市场 + 避免诉讼 + SEO + 品牌 + 路缘效应。建议从第一天内置 + 使用无头库 + 真实屏幕阅读器 + 残障用户 + 每组件文档 + 培训团队 + 持续集成测试。无障碍是设计系统最大的价值主张——做对了让 13 亿残障用户受益 + 公司避免诉讼 + 整个产品组合质量提升。
