设计令牌基础

核心概念

设计令牌（Design Token）是设计系统的"原子层"——将设计决策（颜色、间距、排版等）抽象为命名变量（如 color.primary.500、spacing.md、typography.heading.lg.fontSize）。它解耦了设计值与具体实现——同一令牌在 Web 端输出 CSS 变量、在 iOS 端输出 Swift 常量、在 Android 端输出 XML 资源。令牌让多平台一致性、主题切换（亮色/暗色）、品牌更新、无障碍调整都可以在单一源头完成。Salesforce 2014 年首次系统化令牌概念，Style Dictionary（Amazon 2015 开源）成为行业标准工具，W3C 设计令牌社区组 2023 年发布草案规范。本节介绍令牌概念、与 CSS 变量和 Sass 变量的区别、令牌三大特性（抽象性、单一源头、跨平台）、典型令牌类别、命名规范。

维度 硬编码值 CSS 变量 设计令牌
抽象层级 无 部分 强（语义化）
来源 散落代码各处 集中在一个文件 JSON/规范源文件
跨平台 不支持 仅限 Web Web + iOS + Android
主题化 极难 可以 为此而设计
工具链 无 轻量 完整流水线

令牌是什么

形式：JSON 或 YAML 描述设计值：

{
  "color": {
    "primary": {
      "500": { "value": "#3b82f6" }
    },
    "action": {
      "primary": { "value": "{color.primary.500}" }
    }
  },
  "spacing": {
    "md": { "value": "16px" }
  }
}

用途：

  • 设计师在 Figma 中使用 color.action.primary 而非十六进制色值。
  • 工程师在代码中使用 tokens.color.action.primary 而非十六进制色值。
  • 修改色值一次，所有引用自动更新。

与 CSS 变量的区别

CSS 变量：

  • --primary-color: #3b82f6;
  • 仅限 Web 端。
  • 可以集中在单个文件中。

设计令牌：

  • 抽象源文件（JSON）。
  • 生成 CSS 变量 + iOS Swift 常量 + Android XML 等多平台输出。
  • 跨平台一致性。

令牌是 CSS 变量的超集——CSS 变量是令牌在 Web 端的输出形式。

令牌三大特性

1. 抽象性：

  • 不是原始数值，而是命名概念。
  • color.primary.500 比 #3b82f6 更有意义。

2. 单一真实源：

  • 单一来源（JSON）。
  • 不在多个代码库中重复。
  • 改一处即影响全部。

3. 跨平台：

  • Web（CSS / SCSS / JS）、iOS（Swift）、Android（XML）、React Native、Flutter 共享。
令牌类别
1. 颜色：


    

  • 品牌色（primary、secondary）。
    • 

  • 语义色（成功、警告、错误）。
    • 

  • 中性色（灰度）。
    • 

  • 背景、边框、文本色。
    • 



2. 排版：


    

  • 字体族。
    • 

  • 字号（字号阶梯）。
    • 

  • 字重。
    • 

  • 行高。
    • 

  • 字间距。
    • 



3. 间距：


    

  • 内边距、外边距、间隙。
    • 

  • 4 / 8 像素网格。
    • 

  • T 恤尺寸（xs / sm / md / lg / xl）。
    • 



4. 尺寸：


    

  • 宽度、高度（组件特定）。
    • 

  • 容器最大宽度。
    • 



5. 边框：


    

  • 圆角（方角、圆角、胶囊形）。
    • 

  • 宽度。
    • 

  • 颜色。
    • 



6. 阴影：


    

  • 盒阴影。
    • 

  • 高程（Material 风格）。
    • 



7. 动画：


    

  • 时长（快/正常/慢）。
    • 

  • 缓动曲线。
    • 



8. 层叠顺序（z-index）：


    

  • 分层（模态框、提示框、下拉菜单）。
    • 



命名规范
语义化 vs 字面化：


字面化（描述值本身）：


    

  • color.blue.500
    • 

  • spacing.16px
    • 



语义化（描述用途）：


    

  • color.action.primary
    • 

  • spacing.md
    • 



最佳实践：


    

  • 引用层使用字面化命名。
    • 

  • 系统层使用语义化命名。
    • 

  • 组件层使用特定命名。
    • 



层级命名法：


    

  • 类别.类型.修饰.状态
    • 

  • 例：color.text.primary.disabled。
    • 

  • 易于组织管理。
    • 



常见陷阱：


    

  • 过于具体：color.button.primary.hover.background 过长。
    • 

  • 过于笼统：color.1 无意义。
    • 

  • 不一致：混用多种命名约定。
    • 



令牌分层（多层架构）
三层架构（Adobe Spectrum 方案）：


1. 引用层 / 全局层：


    

  • 原始值：color.blue.500 = #3b82f6。
    • 

  • 不直接在产品代码中使用。
    • 



2. 系统层 / 别名层 / 语义层：


    

  • 语义别名：color.action.primary = {color.blue.500}。
    • 

  • 可主题化（暗色模式覆盖）。
    • 



3. 组件层：


    

  • 特定使用：button.background = {color.action.primary}。
    • 

  • 组件范围内。
    • 



好处：


    

  • 品牌更新：修改系统层，组件层不变。
    • 

  • 主题切换：亮/暗在系统层覆盖。
    • 

  • 组件灵活性：可在组件层自定义而不影响全局。
    • 



令牌生命周期
创建：


    

  • 设计师提议新令牌。
    • 

  • 设计系统团队评审。
    • 

  • 添加到 JSON。
    • 



使用：


    

  • 设计师在 Figma 中使用。
    • 

  • 工程师在代码中使用。
    • 



更新：


    

  • 修改值。
    • 

  • 自动传播到所有平台。
    • 



废弃：


    

  • 标记为已废弃。
    • 

  • 建议替代方案。
    • 

  • 最终移除。
    • 



版本管理：


    

  • 语义化版本（主版本破坏性变更、次版本新增、补丁修复）。
    • 



令牌与主题
主题是令牌值的一组集合。


亮色主题：


{
  "color.background": "#ffffff",
  "color.text": "#000000"
}
暗色主题：


{
  "color.background": "#000000",
  "color.text": "#ffffff"
}
实施方式：


    

  • CSS：@media (prefers-color-scheme: dark)。
    • 

  • 或基于类名：<html class="dark">。
    • 

  • iOS：特征集合（trait collection）。
    • 

  • Android：DayNight 主题。
    • 



多品牌支持：


    

  • 同一组件，不同令牌值。
    • 

  • 如 Atlassian 旗下 Jira、Confluence、Trello 各有品牌色。
    • 



令牌工具
Style Dictionary（Amazon 开源）：


    

  • 行业标准。
    • 

  • JSON → CSS / iOS / Android / 任意格式。
    • 

  • 可配置转换和格式。
    • 



Tokens Studio（Figma 插件）：


    

  • 设计师在 Figma 中编辑令牌。
    • 

  • 同步到 Git。
    • 



Theo（Salesforce 开源）：


    

  • 类似 Style Dictionary。
    • 



Specify：


    

  • 商业令牌同步平台。
    • 



自建方案：


    

  • 大公司自定义流水线。
    • 



W3C 设计令牌规范
W3C 设计令牌社区组：


    

  • 2023 年草案规范。
    • 

  • 标准化令牌 JSON 格式。
    • 

  • 让不同工具互操作。
    • 



格式：


{
  "color": {
    "primary": {
      "500": {
        "$value": "#3b82f6",
        "$type": "color",
        "$description": "品牌主色"
      }
    }
  }
}
关键字段：$value、$type、$description。


采纳情况：


    

  • Figma、Tokens Studio 已支持。
    • 

  • Style Dictionary v4 已对齐。
    • 

  • 预计五年内成为主流标准。
    • 



代码中的令牌使用
不推荐：


.button {
  background: #3b82f6;
}
改进：


.button {
  background: var(--color-action-primary);
}
更好的方式（使用令牌系统）：


import { tokens } from '@design-system/tokens';

<Button style={{ background: tokens.color.action.primary }} />;
原因：


    

  • 单一来源。
    • 

  • 可主题化。
    • 

  • 跨平台。
    • 



令牌反模式
1. 令牌过少：


    

  • 只有几个颜色令牌。
    • 

  • 产品团队仍然硬编码其他值。
    • 



2. 令牌过多：


    

  • 上千个令牌，用户找不到需要的。
    • 

  • 最佳范围约 100-300 个。
    • 



3. 命名过于具体：


    

  • color.button.primary.hover.background.solid。
    • 

  • 太长。
    • 



4. 缺少系统层：


    

  • 直接引用基础层。
    • 

  • 主题切换困难。
    • 



5. 缺少文档：


    

  • 令牌存在但不知何时用哪个。
    • 



6. 单位不一致：


    

  • spacing.md = 16（无单位）、spacing.lg = '24px'。
    • 



实战案例
Material Design 令牌：


    

  • md.sys.color.primary（系统层）。
    • 

  • md.ref.palette.primary40（引用层）。
    • 

  • md.comp.button.container.color（组件层）。
    • 



Carbon 令牌：


    

  • $brand-01（引用层）。
    • 

  • $button-primary（组件层）。
    • 



Salesforce SLDS：


    

  • 早期设计令牌先驱。
    • 

  • 多层架构。
    • 



投资回报
令牌投资：


    

  • 初始搭建 1-4 周。
    • 

  • 持续维护。
    • 



回报：


    

  • 品牌更新时间从数月缩短到数天。
    • 

  • 主题切换从不可能变为简单操作。
    • 

  • 跨平台一致性。
    • 

  • 无障碍调整一站完成。
    • 



小结
设计令牌是设计系统的"原子层"——将设计决策抽象为命名变量（颜色/间距/排版），让多平台共享单一真实源。令牌不是 CSS 变量——而是跨平台抽象（Web CSS + iOS Swift + Android XML 共享）。三大特性——抽象性（命名而非值本身）、单一真实源（单一 JSON）、跨平台。令牌类别包括颜色（品牌/语义/中性/背景/边框/文本）、排版（字体族/字号/字重/行高/字间距）、间距（4/8 像素网格，T 恤尺寸）、尺寸、边框（圆角/宽度/颜色）、阴影（高程）、动画（时长/缓动）、层叠顺序。命名规范分语义化（action.primary）和字面化（blue.500），最佳实践是引用层字面化 + 系统层语义化 + 组件层特定化。层级命名法为"类别.类型.修饰.状态"。三层架构（Adobe Spectrum）——引用层（原始值）+ 系统层（别名）+ 组件层（特定），让品牌更新、主题切换、组件灵活性都能实现。令牌生命周期包括创建/使用/更新/废弃/版本管理。主题是令牌值的集合——亮/暗模式覆盖，CSS 媒体查询或类名方案，iOS 特征集合，Android DayNight。多品牌方案让同组件使用不同令牌值。工具有 Style Dictionary（行业标准）、Tokens Studio（Figma 插件同步 Git）、Theo（Salesforce）、Specify（商业）、自建方案。W3C 规范 2023 草案（value/value/value/type/$description）让跨工具互操作。代码中应使用令牌而非硬编码。反模式包括令牌过少、过多、命名过具体、缺少系统层、缺少文档、单位不一致。Material、Carbon、SLDS 是实战案例。投资回报——初始 1-4 周搭建，回报是品牌更新从数月到数天、主题切换简单化、跨平台一致、无障碍一站完成。一个简单的检验：你能解释"color.blue.500 与 color.action.primary"何时用哪个吗？如果不能，层级区分还需巩固。令牌是设计系统工程化的根本——理解它让多平台、主题、品牌更新从噩梦变为日常操作。
