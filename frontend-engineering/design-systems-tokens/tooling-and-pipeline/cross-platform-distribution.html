跨平台分发

核心概念

设计系统的跨平台分发将令牌和组件从单一数据源部署到 Web（npm）、iOS（CocoaPods / SPM）、Android（Maven / Gradle）、React Native、Flutter、桌面端（Electron / Tauri），以及可选的设计工具（Figma 库）——消费方一行安装命令 + 导入即可使用。Monorepo（Lerna、Turborepo、Nx、pnpm workspace）让多包共享同一源码仓库。版本管理 + 变更日志让消费方追踪更新。分发的核心挑战包括原生二进制构建（iOS / Android）、Web 包体积优化、摇树优化（Tree-shaking）、Storybook 文档托管等。本节详细讲解分发渠道、Monorepo 结构、原生平台打包、包体积优化和文档托管方案。

平台 包管理器 产物格式
Web npm / yarn / pnpm npm 包（CommonJS / ESM / TS）
iOS CocoaPods、SPM Framework / Swift 包
Android Maven、Gradle AAR / 库
React Native npm npm 包（JS）
Flutter pub.dev Pub 包（Dart）
桌面端 Electron / Tauri npm + 原生打包
Figma Figma 库 Figma 文件

Web 分发

npm 包配置：

{
  "name": "@company/design-system",
  "version": "1.0.0",
  "main": "dist/index.cjs.js",
  "module": "dist/index.esm.js",
  "types": "dist/index.d.ts",
  "exports": {
    ".": {
      "import": "./dist/index.esm.js",
      "require": "./dist/index.cjs.js",
      "types": "./dist/index.d.ts"
    },
    "./tokens": {
      "import": "./dist/tokens.esm.js"
    },
    "./styles": "./dist/styles.css"
  }
}

构建工具：

  • Rollup、tsup、Vite。
  • 输出 ESM + CJS + 类型声明。

摇树优化：

  • 使用具名导出。
  • 在 package.json 中标记 sideEffects: false。

消费方使用：

import { Button } from '@company/design-system';
import { tokens } from '@company/design-system/tokens';
import '@company/design-system/styles';

iOS 分发

Swift Package Manager（SPM）：

// Package.swift
let package = Package(
    name: "DesignSystem",
    products: [
        .library(name: "DesignSystem", targets: ["DesignSystem"]),
    ],
    targets: [
        .target(name: "DesignSystem"),
    ]
)

CocoaPods（较旧但仍常见）：

# DesignSystem.podspec
Pod::Spec.new do |s|
  s.name = 'DesignSystem'
  s.version = '1.0.0'
  s.source_files = 'Sources/**/*.swift'
end

消费方使用：

import DesignSystem

let button = DesignSystem.Button()
let primary = DesignSystem.Tokens.colorActionPrimary

Android 分发

Maven Central / GitHub Packages：

// build.gradle
publishing {
    publications {
        release(MavenPublication) {
            groupId = 'com.company'
            artifactId = 'design-system'
            version = '1.0.0'
        }
    }
}

消费方使用：

implementation 'com.company:design-system:1.0.0'

import com.company.designsystem.Button
import com.company.designsystem.Tokens

Monorepo 结构

多包单仓库：

design-system/
├── packages/
│   ├── tokens/           # Style Dictionary 数据源
│   ├── react/            # React 组件（npm）
│   ├── ios/              # Swift 包
│   ├── android/          # Kotlin 库
│   ├── react-native/     # React Native 包
│   └── docs/             # Storybook + 文档站
├── tools/
│   ├── token-build/      # 构建脚本
│   └── component-cli/    # 组件脚手架
├── package.json          # 工作区根配置
└── pnpm-workspace.yaml

优势：

  • 单一数据源。
  • 跨平台原子化变更。
  • 协调更方便。

工具选择：

  • pnpm workspace（轻量）。
  • Lerna（经典）。
  • Turborepo（构建快速）。
  • Nx（功能丰富）。

版本策略

独立版本管理：

  • 每个包独立管理版本号。
  • React 组件 1.5.0 和 iOS 包 2.0.0 并存。
  • 灵活但可能让消费方困惑。

固定版本管理（Lerna 固定模式）：

  • 所有包使用相同版本号。
  • 每次发布全部升级。
  • 简单但可能产生不必要的频繁升级。

混合方式：

  • 令牌和组件使用固定版本。
  • 工具链使用独立版本。

建议：

  • 成熟项目使用独立版本。
  • 早期项目使用固定版本。

构建流水线

Web 平台：

# 1. 构建令牌
npm run build:tokens

# 2. 构建组件
npm run build:web

# 3. 生成类型声明
tsc --emitDeclarationOnly

# 4. 打包 CSS
postcss src/styles.css -o dist/styles.css

# 5. 运行测试
npm test

# 6. 发布
npm publish

多平台并行构建：

  • 在持续集成中并行构建所有平台。
  • 统一发布。

持续集成与持续交付

合并到主分支时：

# .github/workflows/release.yml
on:
  push:
    branches: [main]

jobs:
  release:
    steps:
      - name: 构建所有平台
        run: npm run build:all

      - name: 运行测试
        run: npm run test:all

      - name: 视觉回归测试
        run: npm run chromatic

      - name: 发布 npm 包
        run: npm publish --access public
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}

      - name: 发布 iOS 包
        run: ./scripts/publish-ios.sh

      - name: 发布 Android 包
        run: ./scripts/publish-android.sh

      - name: 部署文档
        run: npm run deploy:docs

发布工具：

  • changesets（npm 生态主流）。
  • semantic-release（自动化）。
  • 手动发布 + Git 标签。

包体积优化

摇树优化：

  • 使用具名导出。
  • 标记 sideEffects: false。
  • 用包分析器验证效果。

CSS 优化：

  • 移除未使用的 CSS。
  • 使用 PurgeCSS。
  • 或采用原子化 CSS（如 Tailwind）。

代码分割：

  • 消费方仅导入使用的部分。
  • 组件级别拆分。

包分析工具：

  • webpack-bundle-analyzer。
  • Rollup visualizer。

Storybook 托管

Storybook 是组件展示和文档的工具。

托管方案：

  • Chromatic（商业方案，体验最佳）。
  • Netlify。
  • Vercel。
  • GitHub Pages。

公开 vs 私有：

  • 开源项目使用公开 Storybook。
  • 内部项目使用认证保护。

每次 PR 预览：

  • 每个合并请求部署预览版 Storybook。
  • 设计师和工程师可直接审查。

文档站点

静态站点方案：

  • Docusaurus。
  • Nextra。
  • VitePress。
  • 基于 MDX。

组件展示 + 代码：

  • 实时交互式预览。
  • 可复制粘贴的代码。
  • 展示各种变体。

无障碍文档：

  • 每个组件标注无障碍说明。
  • ARIA 属性说明。
  • 键盘操作支持。

商业方案：

  • Zeroheight：整合设计与代码文档。
  • Knapsack：类似方案。
  • 自建（Docusaurus + Storybook）。

各平台文档

Web 平台：

  • React 组件使用方式。
  • CSS 类名。
  • 令牌使用方法。

iOS 平台：

  • Swift Package 使用方式。
  • SwiftUI 与 UIKit 示例。
  • 令牌 Swift 常量。

Android 平台：

  • Kotlin / Compose 使用方式。
  • 令牌 XML / Compose 代码。

跨平台：

  • 相同的组件设计。
  • 各平台不同的代码实现。

迁移辅助

自动代码迁移工具：

  • 破坏性变更时自动更新消费方代码。
  • jscodeshift（JavaScript）。
  • ast-grep（通用语法树搜索）。

迁移指南：

  • 无法自动迁移部分的手动说明。
  • 例如：API 重命名步骤。

CDN 分发

unpkg / jsDelivr：

<link rel="stylesheet" href="https://unpkg.com/@company/design-system/dist/styles.css" />
<script type="module">
  import { Button } from 'https://unpkg.com/@company/design-system?module';
</script>

适用场景：

  • 快速原型开发。
  • 无构建流水线的项目。

缺点：

  • 无法摇树优化。
  • 依赖网络。

反模式

1. 所有平台打成一个包：

  • React + iOS + Android 放在一个 npm 包里。
  • 行不通。
  • 应拆分为独立包。

2. 不使用 Monorepo：

  • 多仓库 + 手动同步。
  • 容易偏移不一致。

3. 不做版本管理：

  • 消费方无法感知变更。

4. 包体积过大：

  • 1MB 的 CSS 文件。
  • 应使用摇树优化 + PurgeCSS。

5. 公开 Storybook 包含内部信息：

  • 泄露商业机密。

6. 不测试消费方使用：

  • 发布前不验证消费方体验。
  • 导致消费方报错。

实战建议

1. 从一开始就使用 Monorepo：

  • pnpm + Turborepo。
  • 持续集成更快。

2. 各平台独立版本管理：

  • Web 更新频繁。
  • iOS 更新较少。

3. 自动化发布：

  • 使用 changesets 或 semantic-release。

4. Storybook 必不可少：

  • 组件展示 + 文档一体化。

5. 提供迁移辅助工具：

  • 破坏性变更时提供自动代码迁移。

6. 测试消费方使用：

  • 用示例应用做端到端测试。

小结

跨平台分发将设计系统部署到 Web（npm）、iOS（SPM/CocoaPods）、Android（Maven/Gradle）、React Native（npm）、Flutter（pub）、桌面端（Electron/Tauri）和 Figma 库。Monorepo（pnpm workspace + Turborepo / Lerna / Nx）让多包单仓库实现原子化变更和高效协调。Web npm 包输出多格式（CommonJS + ESM + 类型声明）+ exports 字段 + 摇树优化 sideEffects: false，消费方使用具名导入。iOS 使用 SPM（Package.swift）或 CocoaPods（Pod::Spec），消费方 import DesignSystem。Android 通过 Maven 发布 groupId/artifactId/version，消费方 implementation 'com.company:design-system:1.0.0'。版本策略有独立版本（各包独立）vs 固定版本（全部同步）vs 混合模式，成熟项目用独立、早期项目用固定。构建流水线为令牌 → 组件 → 类型 → CSS → 测试 → 发布。持续集成在合并到主分支时构建所有平台 + 测试 + 视觉回归 + 多平台发布 + 文档部署，工具选择 changesets 或 semantic-release。包体积优化包括摇树 + 具名导出 + sideEffects:false + 包分析器 + CSS 清理 + 代码分割。Storybook 托管方案有 Chromatic / Netlify / Vercel / GitHub Pages，支持每次 PR 预览。文档站点推荐 Docusaurus / Nextra / VitePress + Storybook + 商业方案 Zeroheight。各平台分别提供 Web React / iOS Swift / Android Kotlin Compose 的使用示例。迁移辅助工具 jscodeshift / ast-grep + 迁移指南。CDN 分发通过 unpkg / jsDelivr 适合快速原型但无法摇树。应避免的反模式包括：所有平台打一个包、不用 Monorepo、不做版本管理、包体积过大、泄露内部信息、不测试消费方。建议从一开始就用 Monorepo + 各平台独立版本 + 自动发布 + Storybook + 迁移辅助 + 消费方测试。跨平台分发是设计系统实战的"最后一公里"——做对了让消费方一行安装即用，做不对让设计系统沦为内部孤岛。
