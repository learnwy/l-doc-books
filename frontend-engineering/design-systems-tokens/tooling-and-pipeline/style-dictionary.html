Style Dictionary 构建工具

核心概念

Style Dictionary（亚马逊 2015 年开源）是设计令牌的行业标准构建工具——将单一的 JSON 令牌源文件转换为多平台输出（CSS 变量 / SCSS / Sass / iOS Swift / Android XML / React Native / 任意自定义格式）。它通过转换器（Transform，值变换如 16px → 16 用于 iOS）+ 格式器（Format，输出模板）+ 过滤器（Filter，选择输出的令牌子集）实现跨平台的单一数据源。本节详细讲解 Style Dictionary 的核心概念、配置方法、自定义转换器与格式器、引用解析机制、与 W3C 设计令牌规范的关系，以及最佳实践。

阶段 作用
数据源 令牌 JSON 文件
解析器 读取 JSON 并解析引用
转换器 值变换（如 16px → 16）
过滤器 选择令牌子集
格式器 输出模板（CSS、Swift、XML）
动作 自定义构建动作

为什么选择 Style Dictionary

痛点问题：

  • 颜色、间距等设计值散落在代码库各处。
  • Web、iOS、Android 各自独立维护。
  • 各平台之间严重偏移不一致。

解决方案：

  • 单一 JSON 文件作为唯一数据源。
  • 构建命令自动生成各平台特定的输出文件。

行业采用情况：

  • 亚马逊、Salesforce、Atlassian、Adobe、Shopify 等均在使用。
  • 开源 npm 包，社区活跃。

基础配置

安装：

npm install -D style-dictionary

令牌 JSON 文件（tokens/color.json）：

{
  "color": {
    "blue": {
      "500": { "value": "#3b82f6" }
    },
    "action": {
      "primary": { "value": "{color.blue.500}" }
    }
  }
}

配置文件（config.js）：

module.exports = {
  source: ['tokens/**/*.json'],
  platforms: {
    css: {
      transformGroup: 'css',
      buildPath: 'build/css/',
      files: [
        {
          destination: 'variables.css',
          format: 'css/variables',
        },
      ],
    },
    iOS: {
      transformGroup: 'ios',
      buildPath: 'build/ios/',
      files: [
        {
          destination: 'tokens.swift',
          format: 'ios-swift/class.swift',
          className: 'DesignTokens',
        },
      ],
    },
    android: {
      transformGroup: 'android',
      buildPath: 'build/android/',
      files: [
        {
          destination: 'colors.xml',
          format: 'android/colors',
        },
      ],
    },
  },
};

执行构建：

npx style-dictionary build

输出结果：

build/css/variables.css
build/ios/tokens.swift
build/android/colors.xml

引用解析

令牌引用语法：

{
  "color.action.primary": { "value": "{color.blue.500}" }
}

Style Dictionary 自动解析：

  • {color.blue.500} → #3b82f6。
  • 支持多级链式引用。

输出方式：

  • CSS：--color-action-primary: #3b82f6;（解析后的值）。
  • 或保留引用 --color-action-primary: var(--color-blue-500);。

转换器

转换器将令牌值变换为各平台适配的格式。

内置转换器：

  • attribute/cti：解析 类别.类型.项目 结构。
  • name/cti/kebab：生成连字符命名如 color-action-primary。
  • size/px：保留像素单位。
  • size/dp：iOS 使用 dp 数值。
  • color/hex：保留十六进制格式。
  • color/rgb：转换为 RGBA 格式。

转换器组（Transform Group） 是转换器的集合：

  • css：连字符命名 + 像素单位 + 十六进制颜色。
  • ios：驼峰命名 + 数值 + RGB 颜色。
  • android：下划线命名 + dp 单位 + 十六进制颜色。

格式器

格式器是输出模板。

内置格式器：

  • css/variables：CSS 变量格式。
  • scss/variables：SCSS 变量格式。
  • ios-swift/class.swift：Swift 类。
  • android/colors：Android XML 资源。
  • javascript/object：JavaScript 对象。
  • typescript/es6-declarations：TypeScript 声明文件。

CSS 输出示例：

:root {
  --color-blue-500: #3b82f6;
  --color-action-primary: #3b82f6;
}

Swift 输出示例：

public class DesignTokens {
  public static let colorBlue500 = UIColor(red: 0.231, green: 0.510, blue: 0.965, alpha: 1)
  public static let colorActionPrimary = UIColor(red: 0.231, green: 0.510, blue: 0.965, alpha: 1)
}

自定义转换器

编写自定义转换器：

StyleDictionary.registerTransform({
  name: 'size/rem',
  type: 'value',
  matcher: (token) => token.attributes.category === 'spacing',
  transformer: (token) => `${parseInt(token.value) / 16}rem`,
});

用途：

  • 将 16px 转换为 1rem。
  • 用于 Web 端响应式尺寸。

自定义格式器

编写自定义格式器：

StyleDictionary.registerFormat({
  name: 'json/flat',
  formatter: ({ dictionary }) => {
    const flat = {};
    dictionary.allTokens.forEach((token) => {
      flat[token.name] = token.value;
    });
    return JSON.stringify(flat, null, 2);
  },
});

用途：

  • 为特殊工具生成自定义输出格式。

过滤器

输出令牌子集：

files: [
  {
    destination: 'colors.css',
    format: 'css/variables',
    filter: (token) => token.attributes.category === 'color',
  },
];

仅输出颜色类别的令牌。

使用场景：

  • 按类别拆分文件（color.css、spacing.css）。
  • 按组件拆分文件（button.css）。

多平台流水线

实际项目配置：

{
  source: ['tokens/**/*.json'],
  platforms: {
    web: {
      transformGroup: 'css',
      buildPath: 'dist/web/',
      files: [
        { destination: 'tokens.css', format: 'css/variables' },
        { destination: 'tokens.scss', format: 'scss/variables' },
        { destination: 'tokens.js', format: 'javascript/es6' },
        { destination: 'tokens.d.ts', format: 'typescript/es6-declarations' }
      ]
    },
    ios: {
      transformGroup: 'ios-swift',
      buildPath: 'dist/ios/',
      files: [
        { destination: 'DesignTokens.swift', format: 'ios-swift/class.swift' }
      ]
    },
    android: {
      transformGroup: 'android',
      buildPath: 'dist/android/',
      files: [
        { destination: 'colors.xml', format: 'android/colors' },
        { destination: 'dimens.xml', format: 'android/dimens' }
      ]
    },
    'react-native': {
      transformGroup: 'react-native',
      buildPath: 'dist/react-native/',
      files: [
        { destination: 'tokens.js', format: 'javascript/object' }
      ]
    }
  }
}

一条命令 即可生成所有平台的输出文件。

持续集成
令牌变更时自动构建：


# .github/workflows/tokens.yml
on:
  push:
    paths: ['tokens/**']

jobs:
  build:
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npm run build:tokens
      - uses: actions/upload-artifact@v3
        with:
          path: dist/

  • 构建完成后自动发布 npm 包。

使用语义化版本号：


    

  • 令牌变更对应版本升级。
    • 

  • 主版本（Major）：破坏性变更（重命名、删除）。
    • 

  • 次版本（Minor）：新增令牌。
    • 

  • 补丁版本（Patch）：数值微调。

W3C 设计令牌规范
W3C 规范草案（2023 年发布）：


{
  "color.primary.500": {
    "$value": "#3b82f6",
    "$type": "color",
    "$description": "品牌主色"
  }
}
Style Dictionary v4 已支持。


优势：


    

  • 工具间互通互换。
    • 

  • 格式标准化。
    • 

  • 面向未来兼容。
    •

反模式
1. 不使用引用：


    

  • 到处硬编码值。
    • 

  • 维护极其困难。
    • 



2. 命名不一致：


    

  • color.blue.500 与 color.brand.500 混用。
    • 

  • 缺乏系统性。
    • 



3. 不做令牌校验：


    

  • 拼写错误无法发现。
    • 

  • 引用链路断裂。
    • 



4. 手动构建各平台：


    

  • 应使用 Style Dictionary 自动化。
    • 



5. 不做版本管理：


    

  • 消费方无法感知更新。
    •

小结
Style Dictionary（亚马逊 2015 年开源）是设计令牌构建的行业标准工具——将 JSON 令牌数据源转换为多平台输出（CSS / SCSS / JS / TS / Swift / Android XML / React Native）。流水线由解析器（读取 JSON + 解析引用）+ 转换器（值变换如 16px → 16 用于 iOS）+ 过滤器（子集选择）+ 格式器（输出模板）组成。引用自动解析 {color.blue.500} → #3b82f6，支持多级链式引用。转换器组（css / ios / android）打包常用转换，也支持自定义转换器（如 size/rem）。内置格式器包括 css/variables、scss/variables、ios-swift、android/colors、javascript/object、typescript/declaration，也支持自定义格式器。过滤器实现按类别拆分文件（color.css、spacing.css）。多平台输出一条命令即可生成。持续集成在令牌变更时自动构建并发布 npm 包。版本管理工具推荐 changesets 或 semantic-release。令牌校验确保所有值存在、引用有效、命名规范。W3C 规范草案（2023 年，value/value/value/type/$description）已被 Style Dictionary v4 支持，实现工具间互通。其他工具如 Theo（Salesforce）、Tokens Studio CLI、Specify 是替代选项，但 Style Dictionary 在实际项目中使用最广泛。社区插件 style-dictionary-utils、sd-transforms、tokens-studio 提供扩展能力。应避免的反模式包括：不使用引用、命名不一致、不做校验、手动构建和不做版本管理。建议从小处开始 + 记录命令 + 持续集成检查 + 自动发布 + 消费方文档。Style Dictionary 是设计令牌工程化的核心工具——让跨平台令牌流水线从设想变为日常实践。
