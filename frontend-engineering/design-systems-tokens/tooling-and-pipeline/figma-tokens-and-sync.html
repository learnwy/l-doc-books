Figma 令牌与同步

核心概念

设计师与工程师协作的最大痛点是 Figma 设计与代码实现之间的偏移——设计师在 Figma 修改了颜色，工程师不知道，代码仍然使用旧值。Tokens Studio（前身为 Figma Tokens，2020 年起）是一个 Figma 插件，让设计师直接编辑设计令牌，同步到 GitHub 仓库（JSON 文件），持续集成自动执行 Style Dictionary 构建——设计师修改后工程师无需手动翻译即可获得代码更新。Figma Variables（Figma 2023 年发布）是 Figma 内置的令牌系统，支持模式（亮色/暗色/多品牌）。本节详细讲解 Figma Tokens / Tokens Studio 工作流、Figma Variables 与插件对比、Git 同步机制、设计师与工程师的协作方式，以及常见陷阱。

维度 Figma Style Figma Variables Tokens Studio
引入时间 长期存在 2023 年 2020 年起
令牌类型 颜色、文本 颜色、尺寸、布尔、字符串 所有令牌类型
模式（主题） 不支持 内置多模式 多集合
代码同步 不直接支持 API 导出 内置 Git 同步
层级 单层 2-3 层（别名） 多层架构
适用场景 旧项目 新项目默认 高级用户

Figma Style（传统方式）

Figma 长期以来的方式：

  • 颜色样式 + 文本样式。
  • 设计师创建后通过库共享。

局限性：

  • 仅支持颜色和文本。
  • 不支持间距、圆角等其他令牌。
  • 不支持别名和引用。
  • 不支持 Git 同步。

仍然适用于：

  • 历史遗留项目。
  • 不需要代码同步的场景。

Figma Variables（2023 年起）

Figma 内置变量系统：

  • 支持颜色、数值、布尔值、字符串变量。
  • 多模式支持（亮色 / 暗色 / 多品牌）。
  • 别名功能（一个变量引用另一个）。

模式示例：

  • color.bg.default：亮色模式 = 白色、暗色模式 = 黑色。
  • 切换模式后自动更新。

局限性：

  • 仍未完全覆盖所有令牌类型（如阴影、复合排版）。
  • 有 API 可导出（但需手动配置）。

现状：

  • 现代 Figma 项目的默认选择。
  • 逐步取代传统样式。

Tokens Studio（前身为 Figma Tokens）

面向高级用户的插件：

  • 支持所有令牌类型。
  • 多层架构（引用层 / 别名层 / 组件层）。
  • 多集合（主题、品牌）。
  • 内置 Git 同步。

工作流：

  1. 设计师安装插件。
  2. 在插件中创建令牌。
  3. 将令牌应用到 Figma 元素。
  4. 推送到 Git → 持续集成构建 → 工程师使用。

同步方向：

  • 设计师 → Git（推送）。
  • Git → 设计师（拉取更新）。

格式：

  • 仓库中的 JSON 文件。
  • 与 Style Dictionary 兼容。

端到端流水线

设计师 Figma Tokens → Git 推送 → 持续集成 Style Dictionary 构建 → 多平台输出 → 工程师消费使用。

Git 同步配置
Tokens Studio Git 同步：


    

  • 支持配置 GitHub / GitLab / Azure DevOps。
    • 

  • 使用 OAuth 或个人访问令牌认证。
    • 

  • 选择仓库和分支。
    • 

  • 推送令牌到指定路径（tokens/$themes.json、tokens/global.json）。
    • 



分支策略：


    

  • 设计师推送到 tokens/main 分支。
    • 

  • 持续集成触发构建。
    • 

  • 自动创建合并请求（PR）。
    • 

  • 设计师和工程师共同审查。
    • 

  • 合并后发布。
    • 



或者：


    

  • 设计师推送到 tokens/{设计师名} 分支。
    • 

  • 手动创建合并请求。
    • 



多集合 / 多主题
Tokens Studio 集合：


    

  • core：引用层（color.blue.500 等基础值）。
    • 

  • light：亮色主题覆盖。
    • 

  • dark：暗色主题覆盖。
    • 

  • brand-jira：品牌特定集合。
    • 

  • brand-confluence：另一品牌集合。
    • 



设计师切换集合：


    

  • 在 Figma 中预览不同主题和品牌效果。
    • 



输出：


    

  • 每个集合生成不同的 CSS 文件或模式。
    • 



设计师工作流
添加新颜色：


    

  1. 设计师在 Tokens Studio 插件中创建令牌。
    2. 

  2. 选择引用值（color.blue.500）。
    3. 

  3. 创建别名 color.action.primary 引用该值。
    4. 

  4. 在 Figma 中应用到按钮。
    5. 

  5. 推送到 Git。
    6. 

  6. 持续集成自动构建。
    7. 

  7. 工程师查看变更日志并使用新令牌。
    8. 



耗时：


    

  • 仅需几分钟（之前工程师手动翻译需要数天）。
    • 



工程师工作流
接收令牌更新：


    

  1. 拉取新版本的 npm 包。
    2. 

  2. 查看变更日志。
    3. 

  3. 如有需要则更新组件代码（通常不需要，因为别名不变）。
    4. 



或者：


    

  • Webhook 触发自动更新消费方的合并请求。
    • 



同步冲突
双向同步冲突场景：


    

  • 设计师推送了令牌 A 的修改。
    • 

  • 工程师同时提交了代码变更。
    • 

  • 如果双方修改了同一个令牌则产生冲突。
    • 



解决方案：


    

  • Tokens Studio 会提示冲突。
    • 

  • 手动解决。
    • 

  • 或约定设计师作为令牌值的唯一权威来源。
    • 



最佳实践
1. 设计师作为唯一权威来源：


    

  • 令牌值由设计师拥有。
    • 

  • 工程师不手动编辑 JSON 文件。
    • 



2. 工程师审查：


    

  • 令牌变更通过合并请求审查。
    • 

  • 尽早发现错误。
    • 



3. 命名规范强制执行：


    

  • 通过 Tokens Studio + 校验器检查。
    • 

  • 确保命名一致性。
    • 



4. 文档自动生成：


    

  • 从令牌数据自动生成文档。
    • 

  • 与 Storybook 集成。
    • 



5. 持续集成拦截无效令牌：


    

  • 引用断裂 → 构建失败。
    • 

  • 不发布有问题的令牌。
    • 



Figma Variables 与 Tokens Studio 对比
Figma Variables：


    

  • 内置功能（无需插件）。
    • 

  • 学习曲线较低。
    • 

  • 令牌类型有限。
    • 

  • 有 API 可导出（仍需配置）。
    • 



Tokens Studio：


    

  • 作为插件存在。
    • 

  • 功能完整全面。
    • 

  • 内置 Git 同步。
    • 

  • 学习成本较高。
    • 



选择建议：


    

  • 新项目：先尝试 Figma Variables。
    • 

  • 高级用户或复杂需求：使用 Tokens Studio。
    • 

  • 未来趋势：Figma Variables 可能逐步追上功能差距。
    • 



实战案例：Atlassian
Atlassian 的令牌实践：


    

  • 多品牌（Jira / Confluence / Trello）。
    • 

  • 多主题（亮色 / 暗色）。
    • 

  • 使用 Tokens Studio + Style Dictionary。
    • 

  • 设计师推送 → 持续集成构建 → 产品团队消费。
    • 



节省的时间：


    

  • 之前设计师到工程师的翻译过程需要 1-2 周。
    • 

  • 现在仅需几分钟。
    • 



常见陷阱
1. 设计师未经培训：


    

  • 不了解插件用法。
    • 

  • 令牌使用不当。
    • 

  • 解决方案：新人入职培训。
    • 



2. 命名过于复杂：


    

  • 设计师感到困惑。
    • 

  • 应适当简化。
    • 



3. 缺乏使用文档：


    

  • 令牌创建了但不知何时使用。
    • 

  • 每个令牌都需要描述说明。
    • 



4. 同步不稳定：


    

  • 早期插件存在 Bug。
    • 

  • 使用稳定版本。
    • 



5. 偏移回退：


    

  • 设计师不使用令牌而直接写十六进制色值。
    • 

  • 需要通过校验和强制规则防止。
    • 



6. 缺乏审查：


    

  • 自动合并导致问题。
    • 

  • 有问题的令牌逃过检查。
    • 



Tokens Studio 之外的工具
Specify：


    

  • 商业产品。
    • 

  • Figma + Storybook + Style Dictionary 集成更完善。
    • 



Supernova：


    

  • 商业化设计系统平台。
    • 



Knapsack：


    

  • 商业产品。
    • 

  • 多工具同步。
    • 



选择取决于：


    

  • 预算。
    • 

  • 团队规模。
    • 

  • 复杂程度。
    • 



未来趋势
Figma + AI：


    

  • Figma AI 建议令牌使用。
    • 

  • 自动检测设计不一致。
    • 



W3C 规范成为主流：


    

  • 跨工具互通标准。
    • 

  • 不锁定于特定工具。
    • 



代码优先 vs 设计优先：


    

  • 部分团队由工程师主导（代码作为数据源）。
    • 

  • 部分团队由设计师主导。
    • 

  • 工具链逐步支持两种模式。
    • 



反模式
1. 手动翻译：


    

  • 设计师说"使用 #3b82f6"。
    • 

  • 工程师复制粘贴。
    • 

  • 缺乏系统性。
    • 



2. 不使用引用：


    

  • 设计师每次应用都硬编码。
    • 

  • 修改色值需要全量更新。
    • 



3. 插件未安装：


    

  • 部分设计师跳过安装。
    • 

  • 造成不一致。
    • 



4. 集合过多：


    

  • 创建了 100 个主题集合。
    • 

  • 性能下降且复杂度过高。
    • 



5. 不测试构建：


    

  • 设计师推送了有问题的令牌。
    • 

  • 持续集成延迟发现。
    • 



实战建议
1. 小团队先行试点：


    

  • 一个小团队先试用。
    • 

  • 发现问题。
    • 

  • 逐步迭代优化。
    • 



2. 培训设计师：


    

  • 1 小时工作坊。
    • 

  • 配套文档。
    • 



3. 持续集成守护：


    

  • 引用完整性检查。
    • 

  • 命名规范校验。
    • 



4. 工程师支持：


    

  • 专用沟通渠道。
    • 

  • 定期答疑时间。
    • 



5. 衡量成效：


    

  • 从设计师修改到工程师上线的时间。
    • 

  • 令牌使用率 vs 硬编码比例。
    • 



小结
Figma 与代码之间的偏移是设计师与工程师协作的核心痛点——Tokens Studio（前身为 Figma Tokens）是 Figma 插件，让设计师直接编辑令牌并同步到 Git，持续集成执行 Style Dictionary 构建后工程师无需手动翻译即可获得更新。Figma Variables（2023 年起）是内置变量系统，支持多模式（亮色/暗色/品牌）和别名，逐步取代旧式样式，但令牌类型仍有限。Tokens Studio 作为高级用户插件支持所有令牌类型 + 多层架构 + 多集合 + 内置 Git 同步。端到端流水线为：设计师 Figma Tokens → Git 推送 → 持续集成构建 → 多平台输出 → 工程师消费。Git 同步配置支持 OAuth / 个人访问令牌，选择仓库和分支。分支策略为设计师推送令牌分支 + 持续集成自动创建 PR + 审查 + 合并。多集合包括 core / light / dark / brand-jira / brand-confluence，设计师可在 Figma 中切换预览。设计师工作流添加令牌仅需几分钟（之前翻译需数天）。同步冲突由 Tokens Studio 提示并手动解决，通常约定设计师为唯一数据源。最佳实践包括设计师作为数据源 + 工程师 PR 审查 + 命名强制 + 文档自动生成 + 持续集成拦截无效令牌。Figma Variables 内置易学但功能有限，Tokens Studio 功能全面但需学习成本，新项目先试 Variables，复杂需求用 Tokens Studio。Atlassian 案例展示多品牌+多主题实践，耗时从周级缩短到分钟级。常见陷阱包括设计师未培训、命名过复杂、缺文档、同步不稳定、偏移回退和缺乏审查。Figma 令牌同步是设计与工程协作的"高速公路"——做对了让设计系统真正活起来，不再停滞过时。
