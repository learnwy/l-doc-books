颜色令牌与主题

核心概念

颜色令牌（Color Token）是设计系统中最核心也最复杂的令牌类别——涉及品牌色、语义色（成功/警告/错误）、中性色阶（灰色）、无障碍对比度、暗色模式和多品牌主题。色彩理论（HSL、RGB 与 OKLCH 色彩空间的差异）、色域（sRGB 与 Display P3）、对比度算法（WCAG 比率）都影响设计与实现决策。Material You 引入了基于用户壁纸的动态取色，APCA 是替代 WCAG 比率的新一代对比度算法。本节详细讲解颜色令牌的架构设计、色阶生成方法、语义化命名、暗色模式实施方案、无障碍合规，以及多品牌主题策略。

颜色类别 示例 所属层级
品牌色 brand.primary、brand.secondary 系统层
语义色 success、warning、error、info 系统层
中性色 gray.50 - gray.900 引用层
表面色 background.default、surface.elevated 系统层
文本色 text.primary、text.secondary、text.disabled 系统层
边框色 border.default、border.subtle 系统层
交互色 action.primary、action.hover、focus 系统层

颜色色阶

标准做法：11 级色阶（50, 100, 200, ..., 900, 950）。

生成方式：

  • 选定基准色（如品牌主色）。
  • 通过算法派生各级色值。
  • 常用工具：Tailwind 调色板生成器、Adobe Leonardo、UI Colors。

HSL 方法：

  • 固定色相和饱和度。
  • 按明度步进（95%、90%、80%、...、10%、5%）。

品牌蓝色示例：

{
  "color.blue.50": "#eff6ff",
  "color.blue.100": "#dbeafe",
  "color.blue.200": "#bfdbfe",
  "color.blue.500": "#3b82f6",
  "color.blue.900": "#1e3a8a",
  "color.blue.950": "#172554"
}

语义色

为何需要语义化：

  • 不应直接引用品牌色的色值。
  • "成功"不一定总是绿色（虽然通常如此）。
  • 让主题切换和品牌重塑变得容易。

示例：

{
  "color.success.default": "{color.green.500}",
  "color.success.subtle": "{color.green.100}",
  "color.warning.default": "{color.amber.500}",
  "color.error.default": "{color.red.500}"
}

命名原则：

  • 使用 success 而非 green。
  • 使用 error 或 danger。
  • 使用 warning 或 caution。

中性色阶

灰色色阶：

  • 11 级灰色。
  • gray.50 最浅到 gray.950 最深。

重要性：

  • 界面中 80% 的颜色是中性色。
  • 用于背景、文本、边框、分割线。

色调选择：

  • 纯灰（无色相偏移）。
  • 冷灰（轻微蓝色偏移）。
  • 暖灰（轻微红/黄偏移）。
  • 应与品牌调性匹配。

Tailwind 提供 5 种灰色调：

  • gray、slate、zinc、neutral、stone（从冷到暖排列）。

表面色令牌

表面色 = 背景 + 层级高度。

示例：

{
  "color.surface.default": "{color.gray.0}",
  "color.surface.elevated": "{color.gray.50}",
  "color.surface.overlay": "{color.gray.100}"
}

Material 层级高度系统：

  • 0、1、2、3、6、8、12、16、24 dp。
  • 每个层级对应微妙的背景色和阴影变化。

文本色

文本层级：

{
  "color.text.primary": "{color.gray.900}",
  "color.text.secondary": "{color.gray.700}",
  "color.text.tertiary": "{color.gray.500}",
  "color.text.disabled": "{color.gray.400}",
  "color.text.inverse": "{color.gray.50}",
  "color.text.success": "{color.success.text}",
  "color.text.error": "{color.error.text}"
}

Material 87/60/38 规则——基于认知科学研究，主文本 87% 不透明度、次文本 60%、辅助文本 38%。

交互色

操作状态：

{
  "color.action.primary.default": "{color.brand.500}",
  "color.action.primary.hover": "{color.brand.600}",
  "color.action.primary.active": "{color.brand.700}",
  "color.action.primary.disabled": "{color.gray.300}"
}

状态变化流程：

  • 默认 → 悬停 → 激活 → 禁用。

WCAG 对比度

对比度比率：

  • 文本与背景的亮度比。
  • AA 级：4.5:1（正常文本），3:1（大号文本）。
  • AAA 级：7:1。

检测工具：

  • WebAIM 对比度检查器。
  • Stark（Figma 插件）。
  • 浏览器开发者工具。

实战要点：

  • 测试所有文本与背景的组合配对。
  • 特别注意语义色（如警告黄色在白底上容易不达标）。

常见不达标场景：

  • 浅蓝色链接在白底上：3:1（低于 AA 标准）。
  • 浅灰色次级文本在白底上。

APCA 新对比度算法

WCAG 2 的局限性：

  • 对所有颜色一视同仁。
  • 未考虑人眼对不同颜色的感知差异。
  • 亮底深字与深底亮字得分相同（实际感知不同）。

APCA（可感知对比度算法，Accessible Perceptual Contrast Algorithm）：

  • 具有极性感知能力。
  • 更好地预测实际可读性。
  • 是 WCAG 3 的候选算法。

Lc 评分：

  • 范围 0-100。
  • 正文文本推荐 60 以上。

目前采用状况：

  • 逐步推广中。
  • 各工具正在加入支持。

色彩空间

sRGB：

  • 1996 年以来的标准色彩空间。
  • 覆盖大部分显示器。
  • 每通道 8 位色深。

Display P3：

  • 更宽的色域。
  • Apple 设备原生支持。
  • 比 sRGB 多 25% 的可显示颜色。
  • 能显示更鲜艳的红色和绿色。

OKLCH：

  • 感知均匀的色彩空间。
  • 更适合设计系统的系统化配色。
  • CSS 支持正在增长。

实战建议：

  • 主流场景使用 sRGB。
  • 高端 Apple 设备可用 Display P3。
  • 系统化生成色阶可用 OKLCH（Tailwind v4 已采用）。

暗色模式

实现策略：

1. CSS 变量切换：

:root {
  --color-bg: white;
  --color-text: black;
}
[data-theme='dark'] {
  --color-bg: black;
  --color-text: white;
}

2. 媒体查询：

@media (prefers-color-scheme: dark) {
  :root {
    --color-bg: black;
  }
}

3. 类名切换：

<html className={isDark ? 'dark' : 'light'}>

最佳实践：

  • 使用系统层令牌覆盖。
  • 组件层保持不变。

暗色模式常见陷阱

1. 使用纯黑背景：

  • 阅读困难且视觉疲劳。
  • 应使用深灰色（gray.900）。

2. 使用纯白文本：

  • 在暗色背景上过于刺眼。
  • 应使用 gray.100 或 gray.200。

3. 简单反转颜色：

  • 并非所有颜色直接反转都有效。
  • 例如：红色在暗色模式下仍是红色，但应使用较浅的色调。

4. 未测试图片效果：

  • 图片在暗色背景下可能显得突兀。
  • 应考虑提供暗色模式专用图片。

5. 组件覆盖不完整：

  • 部分组件未适配暗色模式，造成视觉断层。

多品牌主题

同一组件、不同品牌：

// Jira 主题
{
  "color.brand.primary": "{color.blue.500}"
}

// Confluence 主题
{
  "color.brand.primary": "{color.purple.500}"
}

// Trello 主题
{
  "color.brand.primary": "{color.blue.500}"
}

Atlassian 实战经验：

  • 共享组件代码。
  • 不同品牌使用不同令牌值。

实施方式：

  • 为每个品牌构建独立的 CSS 文件。
  • 或在运行时切换 CSS 变量。

Material You 动态取色

Android 12 及以上：

  • 从用户壁纸中提取主色。
  • 自动生成完整调色板。
  • 应用到整个系统界面。

实现机制：

  • Material 配色算法。
  • Android 12 系统 API。

Web 端等效方案：

  • Material Color Utilities（npm 包）。
  • 目前采用范围有限。

工具推荐

调色板生成器：

  • Tailwind 调色板生成器。
  • Adobe Leonardo（免费）。
  • UI Colors。
  • Coolors。

对比度检查器：

  • WebAIM。
  • Stark。
  • WCAG Contrast Checker。

无障碍检测：

  • axe DevTools。
  • Lighthouse。
  • WAVE。

设计工具：

  • Figma 颜色样式。
  • Sketch 调色板。

反模式

1. 到处使用硬编码色值：

  • 没有令牌系统。
  • 修改颜色如同噩梦。

2. 中性色过少：

  • 只有黑和白。
  • 无法建立视觉层级。

3. 未检测对比度：

  • 视觉漂亮但不可读。

4. 品牌色过度使用：

  • 全是品牌红色 → 视觉疲劳。
  • 应多使用中性色。

5. 未考虑色盲用户：

  • 仅靠红绿区分警告状态不够。
  • 应配合图标辅助。

小结

颜色令牌是设计系统中最复杂的令牌类别——涵盖品牌色、语义色、中性色、表面色、文本色、边框色和交互色。颜色色阶采用 11 级（50-950）结构，通过算法生成（Tailwind / Leonardo / UI Colors），HSL 方法固定色相与饱和度、调整明度步进。语义色（成功/警告/错误/信息）引用品牌色，命名描述用途而非颜色本身。中性色占界面颜色的 80%，有纯灰、冷灰、暖灰三种色调选择。表面色包含层级高度概念（Material 0-24 dp）。文本色分为主文本（87%）、次文本（60%）、辅助文本（38%）、禁用态和反色。交互色包含默认/悬停/激活/禁用四个状态。WCAG 对比度要求 AA 级 4.5:1（正常文本）、3:1（大号文本）、AAA 级 7:1，可用 WebAIM / Stark / 开发者工具检测。APCA 是新一代感知对比度算法，具有极性感知能力，是 WCAG 3 候选方案，推荐正文 Lc 60 以上。色彩空间方面，sRGB 是标准、Display P3 色域更宽、OKLCH 感知均匀（Tailwind v4 已采用）。暗色模式推荐使用 CSS 变量切换结合系统层覆盖，避免纯黑背景、纯白文本、简单反转、未测试图片和覆盖不完整等问题。多品牌策略使用相同组件、不同系统层令牌值（Atlassian 的 Jira/Confluence/Trello 即是如此），可构建独立 CSS 或运行时切换。Material You 支持从壁纸动态取色（Android 12+）。应避免的反模式包括：到处硬编码色值、中性色过少、未检测对比度、品牌色过度使用和未考虑色盲用户。颜色令牌是设计系统的"门面"——做好了能让产品视觉一致、无障碍达标、品牌统一且支持主题切换。
