排版令牌

核心概念

排版令牌（Typography Token）系统化管理字体决策——包括字体族（Font Family）、字号阶梯（Type Scale，如标题层级和正文字号）、字重（Weight）、行高（Line Height）和字间距（Letter Spacing）。字号阶梯是排版系统的核心——基于音乐比例（如 1.125 小二度、1.25 大三度、1.5 纯五度、1.618 黄金比例）加上基准字号，生成系统化的字号递进序列。复合令牌（Composite Token，一个令牌包含多个子属性，如 typography.heading.lg = {fontSize, lineHeight, fontWeight}）与原子令牌（Atomic Token）是需要权衡的设计选择。网页字体加载（FOUT 与 FOIT 的区别、font-display 属性）、可变字体（Variable Font）和多语言支持是工程实践的关键。本节详细讲解排版令牌的架构设计、字号阶梯规划、复合与原子令牌的选择、字体加载策略和无障碍考量。

令牌类别 示例 所属层级
字体族 sans、serif、mono 系统层
字号 typography.body.md 系统层
字重 regular、medium、bold 引用层
行高 tight、normal、relaxed 引用层
字间距 tight、normal、wide 引用层
复合令牌 heading.lg、body.md 系统层

字号阶梯

基于比例系数的阶梯：

  • 1.125（小二度）：变化微妙。
  • 1.25（大三度）：均衡适中（推荐默认值）。
  • 1.333（纯四度）：对比鲜明。
  • 1.5（纯五度）：差异显著。
  • 1.618（黄金比例）：极具戏剧性。

生成方法：

  • 基准字号（16px）× 比例系数的 n 次方。
  • 例如比例 1.25、基准 16px：16, 20, 25, 31, 39, 49, 61。

令牌定义：

{
  "fontSize": {
    "xs": "12px",
    "sm": "14px",
    "md": "16px",
    "lg": "18px",
    "xl": "20px",
    "2xl": "24px",
    "3xl": "30px",
    "4xl": "36px",
    "5xl": "48px",
    "6xl": "60px"
  }
}

常用工具：

  • typescale.com。
  • modularscale.com。
  • Tailwind 默认阶梯。

复合令牌

原子令牌：

  • 每个属性单独定义一个令牌。
  • fontSize.md 和 lineHeight.normal 分开管理。

复合令牌：

  • 一个令牌包含多个属性：
{
  "typography.body.md": {
    "fontSize": "16px",
    "lineHeight": "1.5",
    "fontWeight": "400",
    "letterSpacing": "0"
  }
}

复合令牌的优势：

  • 使用一个令牌即可获取全部属性。
  • 设计师无需自行组合搭配。

原子令牌的优势：

  • 组合更灵活。
  • 行高等属性可跨多个字号复用。

最佳实践：

  • 原子令牌用于基础属性。
  • 复合令牌用于常用组合（如 heading-1、body-md）。

常见排版模式

标题：

{
  "typography.heading.1": {
    "fontSize": "{fontSize.4xl}",
    "lineHeight": "1.2",
    "fontWeight": "{fontWeight.bold}",
    "letterSpacing": "-0.02em"
  },
  "typography.heading.2": {
    "fontSize": "{fontSize.3xl}",
    "lineHeight": "1.25",
    "fontWeight": "{fontWeight.bold}"
  }
}

正文：

{
  "typography.body.md": {
    "fontSize": "{fontSize.md}",
    "lineHeight": "1.5",
    "fontWeight": "{fontWeight.regular}"
  }
}

说明文字 / 上标：

{
  "typography.caption": {
    "fontSize": "{fontSize.xs}",
    "lineHeight": "1.4",
    "fontWeight": "{fontWeight.regular}"
  }
}

字体族

字体栈：

{
  "fontFamily.sans": "Inter, -apple-system, BlinkMacSystemFont, sans-serif",
  "fontFamily.serif": "Georgia, serif",
  "fontFamily.mono": "JetBrains Mono, monospace"
}

回退顺序：

  • 系统字体优先（性能最佳）。
  • 品牌字体次之。
  • 通用字体族最后。

可变字体：

  • 一个字体文件支持多个字重和宽度。
  • 减小下载体积。
  • Inter、Roboto、SF Pro 都有可变字体版本。

字重

标准字重值：

  • 100（极细）。
  • 200（特细）。
  • 300（细体）。
  • 400（常规/正常）。
  • 500（中等）。
  • 600（半粗）。
  • 700（粗体）。
  • 800（特粗）。
  • 900（黑体）。

令牌命名：

{
  "fontWeight.regular": "400",
  "fontWeight.medium": "500",
  "fontWeight.semibold": "600",
  "fontWeight.bold": "700"
}

不建议使用 100/200/800/900：

  • 部分字体不提供这些字重。
  • 可能导致字体回退到默认值。

行高

令牌定义：

{
  "lineHeight.tight": "1.1",
  "lineHeight.snug": "1.25",
  "lineHeight.normal": "1.5",
  "lineHeight.relaxed": "1.625",
  "lineHeight.loose": "2"
}

使用比例：

  • 1.5 是正文的典型行高。
  • 1.2 是标题的典型行高。
  • 字号越大，行高系数应越小。

使用无单位值：

  • 使用 line-height: 1.5 而非 1.5em。
  • 确保继承时计算正确。

字间距

令牌定义：

{
  "letterSpacing.tighter": "-0.02em",
  "letterSpacing.tight": "-0.01em",
  "letterSpacing.normal": "0",
  "letterSpacing.wide": "0.01em",
  "letterSpacing.wider": "0.02em"
}

使用模式：

  • 大号文本：使用更紧凑的字间距（负值）。
  • 小型大写字母 / 按钮：使用更宽松的字间距。
  • 正文：保持正常字间距。

字体加载

FOUT 与 FOIT：

  • FOUT（无样式文本闪烁）：先显示回退字体，再切换。
  • FOIT（不可见文本闪烁）：文本不可见直到字体加载完成。
  • 推荐使用 FOUT（对 CLS 指标和可读性更友好）。

font-display 属性：

@font-face {
  font-family: 'Inter';
  src: url('inter.woff2') format('woff2');
  font-display: swap;
}

可选值：

  • auto：浏览器默认行为。
  • block：短暂 FOIT，然后显示回退字体。
  • swap：FOUT 模式。
  • fallback：极短 FOIT，显示回退字体后不再切换。
  • optional：浏览器根据网络状况决定。

推荐：正文使用 swap，装饰性字体使用 optional。

自托管与 Google Fonts

自托管：

  • 加载更快（无第三方 DNS 查询）。
  • 隐私友好（无 Google 追踪）。
  • 可控缓存策略。

Google Fonts：

  • 使用简单。
  • CDN 缓存优化。
  • 但存在 GDPR 合规担忧（德国已有诉讼案例）。

现代推荐方案：

  • 使用 next/font（Next.js）、unfont 等工具自托管。

可变字体

一个文件，支持多字重和样式：

@font-face {
  font-family: 'Inter';
  src: url('Inter-Variable.woff2') format('woff2-variations');
  font-weight: 100 900;
}

.heading {
  font-weight: 700;
  font-variation-settings: 'wght' 700;
}

优势：

  • 文件体积减小（一个文件替代八个）。
  • 字重变化可平滑动画。

无障碍

最小字号：

  • 正文推荐 16px。
  • 无障碍正文的极限是 14px。

行长度：

  • 理想范围是每行 45-75 个字符。
  • 通过 max-width 约束。

层级结构：

  • 视觉层级应与语义层级匹配（使用 h1-h6 标签）。

颜色对比度（见颜色章节）：

  • 正文最小对比度 4.5:1。

多语言

中日韩（CJK）字体：

  • 中日韩字符与拉丁字符度量不同。
  • 需要单独的字体配置。

回退策略：

font-family: 'Inter', 'Noto Sans CJK SC', sans-serif;

多文字系统测试：

  • 测试产品的多语言版本。
  • 根据文字系统调整行高。

令牌与 Tailwind

Tailwind 方案：

  • 内置字号阶梯。
  • 基于类名（text-xl、font-bold）。

设计系统令牌方案：

  • 自定义阶梯。
  • 支持跨平台。

结合使用：

  • Tailwind 配置使用设计系统令牌。
  • 兼得两者优势。

Style Dictionary 实战

令牌 JSON：

{
  "typography": {
    "heading": {
      "lg": {
        "fontSize": { "value": "32px" },
        "lineHeight": { "value": "1.2" },
        "fontWeight": { "value": "700" }
      }
    }
  }
}

构建 CSS：

.typography-heading-lg {
  font-size: 32px;
  line-height: 1.2;
  font-weight: 700;
}

或生成 CSS 变量：

--typography-heading-lg-font-size: 32px;
--typography-heading-lg-line-height: 1.2;
--typography-heading-lg-font-weight: 700;

反模式

1. 字号过多：

  • 定义了 20 个 fontSize 令牌。
  • 推荐 7-10 个是最佳范围。

2. 比例不一致：

  • 随意选取字号。
  • 缺乏系统性。

3. 固定像素值：

  • 不支持响应式。
  • 应使用 rem 或 clamp。

4. 未测试字体加载：

  • FOIT 时间过长。
  • 应使用 font-display: swap。

5. 未使用可变字体：

  • 多个字体文件 → 加载慢。

6. 忽视多语言：

  • 仅测试英文。

小结

排版令牌系统化管理字体决策——包括字体族、字号、字重、行高和字间距。字号阶梯基于音乐比例（1.125-1.618）加上基准字号，1.25 是推荐的均衡比例，基准 16px 可生成 11 级阶梯（xs 12px 到 6xl 60px）。复合令牌是一个令牌包含多个属性（如 typography.body.md = {fontSize, lineHeight, fontWeight}），与原子令牌各有利弊，最佳实践是原子令牌用于基础属性、复合令牌用于常用组合。常见排版模式包括标题 1-6（4xl-md，行高 1.2，粗体）、正文 md（16px，行高 1.5，常规）和说明文字（xs，行高 1.4）。字体栈应系统字体优先、品牌字体次之、通用字体族最后，可变字体用一个文件支持多字重，减小下载体积。标准字重为 100-900，令牌命名常用 regular/medium/semibold/bold（400/500/600/700）。行高正文 1.5、标题 1.2，使用无单位值确保继承正确。字间距大号文本更紧凑、小型大写字母更宽松。字体加载推荐 FOUT 模式而非 FOIT，建议使用 font-display: swap。自托管比 Google Fonts 更快、隐私友好且符合 GDPR（现代方案如 next/font）。可变字体一个文件支持多字重和平滑动画。无障碍要求正文最小 16px、行长度 45-75 字符、视觉与语义层级匹配、对比度 4.5:1 以上。多语言需考虑中日韩字体度量差异、配置回退策略和多文字系统测试。Tailwind 类名可与设计系统令牌结合使用。通过 Style Dictionary 可构建 CSS 类或变量。应避免的反模式包括：字号过多、比例不一致、固定像素值、未测试字体加载、未使用可变字体和忽视多语言。排版令牌是可读性和品牌一致性的基础——做好了能让阅读体验愉悦、品牌视觉统一、跨平台保持一致。
