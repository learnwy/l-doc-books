令牌类别与层级

核心概念

成熟的设计系统令牌（Design Token）不是扁平的一层结构，而是使用多层架构（Multi-tier Architecture）来区分引用层（Reference Tier，存储原始值）、系统层/别名层（System / Alias Tier，语义化映射）和组件层（Component Tier，特定用途）。这种分层设计使得主题切换、品牌重塑、无障碍调整都可以在单一层级完成，而不需要逐个修改组件。Adobe Spectrum 采用三层架构，Material Design 使用 ref/sys/comp 命名，Carbon 也有类似设计。本节详细介绍多层架构的设计原理、命名规范、令牌类别划分，以及各层取值策略。

层级 别名 示例 何时修改
引用层 / 全局层 原始值 color.blue.500 = #3b82f6 极少（品牌调整时）
系统层 / 别名层 / 语义层 令牌 color.action.primary = {color.blue.500} 主题切换时
组件层 特定令牌 button.bg = {color.action.primary} 组件定制时

引用层

用途：

  • 存储原始设计值，如颜色数值、尺寸数值。
  • 对颜色和尺寸进行纯粹的抽象。
  • 不携带任何使用场景上下文。

示例：

{
  "color": {
    "blue": {
      "100": { "value": "#dbeafe" },
      "500": { "value": "#3b82f6" },
      "900": { "value": "#1e3a8a" }
    },
    "gray": {
      "100": { "value": "#f3f4f6" },
      "500": { "value": "#6b7280" },
      "900": { "value": "#111827" }
    }
  },
  "spacing": {
    "0": { "value": "0px" },
    "4": { "value": "4px" },
    "8": { "value": "8px" },
    "16": { "value": "16px" },
    "24": { "value": "24px" }
  }
}

命名方式：使用字面量（直接描述值本身），如 color.blue.500。

使用规则：

  • 不应直接在产品代码中引用。
  • 通过系统层进行间接引用。

系统层 / 别名层

用途：

  • 为引用层的原始值提供语义化别名。
  • 命名描述"用途"而非"值本身"。

示例：

{
  "color": {
    "action": {
      "primary": { "value": "{color.blue.500}" },
      "primary-hover": { "value": "{color.blue.600}" }
    },
    "background": {
      "default": { "value": "{color.gray.100}" },
      "subtle": { "value": "{color.gray.50}" }
    },
    "text": {
      "primary": { "value": "{color.gray.900}" },
      "secondary": { "value": "{color.gray.600}" }
    }
  },
  "spacing": {
    "xs": { "value": "{spacing.4}" },
    "sm": { "value": "{spacing.8}" },
    "md": { "value": "{spacing.16}" },
    "lg": { "value": "{spacing.24}" }
  }
}

命名方式：使用语义化命名（描述用途），如 color.action.primary。

使用规则：

  • 产品代码主要引用此层。
  • 主题覆盖在此层进行。

组件层

用途：

  • 针对特定组件的令牌作用域。
  • 让组件拥有细粒度的控制能力。

示例：

{
  "button": {
    "primary": {
      "background": { "value": "{color.action.primary}" },
      "background-hover": { "value": "{color.action.primary-hover}" },
      "text": { "value": "{color.text.inverse}" },
      "padding-x": { "value": "{spacing.md}" },
      "padding-y": { "value": "{spacing.sm}" }
    }
  }
}

使用规则：

  • 组件实现直接引用此层。
  • 支持组件级别的覆盖定制。

为什么需要多层架构

单层架构的问题：

{
  "color.button.bg": "#3b82f6"
}
  • 品牌重塑时：需要找到所有组件引用并逐一更新。
  • 暗色模式时：需要为每个组件重新定义。
  • 缺乏系统性，维护困难。

多层架构的解决方案：

button.bg → action.primary → blue.500 → #3b82f6
  • 修改引用层的值：只需改一处。
  • 主题覆盖：在系统层操作即可。
  • 组件灵活性：在组件层覆盖。
主题切换
亮色主题的系统层：


{
  "color.background.default": "{color.gray.50}",
  "color.text.primary": "{color.gray.900}"
}
暗色主题的系统层：


{
  "color.background.default": "{color.gray.900}",
  "color.text.primary": "{color.gray.50}"
}
组件层保持不变——按钮背景仍然引用 action.primary，无需任何修改。


实施方式：


    

  • 通过 CSS 变量作用域配合 [data-theme=dark] 属性切换。
    • 

  • 或使用 prefers-color-scheme 媒体查询。
    • 



品牌重塑
只需修改引用层：


{
  "color.brand.primary": "{color.blue.500}",
  "color.brand.primary": "{color.green.500}"
}
    

  • 仅修改一行代码。
    • 

  • 自动向下传播到所有消费者。
    • 



命名规范
引用层：


    

  • 描述值本身：color.blue.500、spacing.16。
    • 



系统层：


    

  • 描述用途：color.action.primary、spacing.md。
    • 



组件层：


    

  • 描述组件具体属性：button.primary.background。
    • 



层级结构：


    

  • 类别.类型.修饰符.状态
    • 

  • 例如：color.text.primary.disabled
    • 



最佳实践：


    

  • 不要使用 "color1"、"color2" 等无含义命名。
    • 

  • 引用层不要过于具体（保持可复用性）。
    • 

  • 组件层不要过于笼统（保持针对性）。
    • 



颜色色阶
Material 11 级色阶：


    

  • 50, 100, 200, ..., 900, A100, A200, A400, A700。
    • 



Tailwind 11 级色阶：


    

  • 50, 100, 200, ..., 900, 950。
    • 



自定义 5 级色阶：


    

  • 最浅、浅、基准、深、最深。
    • 



选择建议：


    

  • 11 级：需要细粒度控制时使用。
    • 

  • 5 级：追求简洁时使用。
    • 



色阶生成方法：


    

  • 手动选取。
    • 

  • 算法生成（基于 HSL 明度步进）。
    • 

  • 工具辅助（Tailwind 调色板生成器、Adobe Leonardo 等）。
    • 



间距色阶
4 像素 / 8 像素网格：


    

  • spacing.4 = 4px、spacing.8 = 8px、spacing.16 = 16px。
    • 

  • 2 的幂次（4、8、16、24、32、48、64）。
    • 



T 恤尺码命名：


    

  • xs = 4、sm = 8、md = 16、lg = 24、xl = 32、2xl = 48、3xl = 64。
    • 



小数刻度：


    

  • 0.25 / 0.5 / 1 / 2 / 4 / 8 rem。
    • 

  • Tailwind 风格。
    • 



引用层与系统层对应：


    

  • 引用层：spacing.16（字面量）。
    • 

  • 系统层：spacing.md（语义化）。
    • 



排版色阶
字号比例系数：


    

  • 1.125（大二度音程）。
    • 

  • 1.25（大三度音程）。
    • 

  • 1.333（纯四度）。
    • 

  • 1.5（纯五度）。
    • 

  • 1.618（黄金比例）。
    • 



选择比例 + 基准字号：


    

  • 基准 16px + 比例 1.25 → 16, 20, 25, 31, 39, 49, 61, 76。
    • 



排版令牌示例：


{
  "typography": {
    "heading": {
      "lg": {
        "fontSize": { "value": "32px" },
        "lineHeight": { "value": "1.2" },
        "fontWeight": { "value": "600" }
      }
    }
  }
}
复合令牌：


    

  • 一个排版令牌包含多个子属性（字号、行高、字重等）。
    • 



多品牌令牌命名
品牌 1：color.brand.primary = blue.500。


品牌 2：color.brand.primary = green.500。


组件引用：button.bg = color.brand.primary。


多品牌策略：


    

  • 相同的组件代码。
    • 

  • 不同的系统层取值。
    • 



令牌与硬编码对比
反模式：


.button {
  background: #3b82f6;
}
正确模式：


.button {
  background: var(--color-action-primary);
}
使用令牌的优势：


    

  • 支持主题切换。
    • 

  • 支持品牌重塑。
    • 

  • 支持跨平台分发。
    • 



实施示例
Style Dictionary 配置：


// config.js
module.exports = {
  source: ['tokens/**/*.json'],
  platforms: {
    css: {
      transformGroup: 'css',
      buildPath: 'build/css/',
      files: [
        {
          destination: 'variables.css',
          format: 'css/variables',
        },
      ],
    },
    iOS: {
      transformGroup: 'ios',
      buildPath: 'build/ios/',
      files: [
        {
          destination: 'tokens.swift',
          format: 'ios-swift/class.swift',
        },
      ],
    },
  },
};
输出结果：


    

  • CSS：--color-action-primary: #3b82f6;。
    • 

  • iOS：static let colorActionPrimary = UIColor(hex: "#3b82f6")。
    • 



常见反模式
1. 缺少引用层：


    

  • 直接将原始值写入系统层：action.primary = "#3b82f6"。
    • 

  • 无法复用抽象。
    • 



2. 缺少系统层：


    

  • 组件直接引用原始值。
    • 

  • 主题切换困难。
    • 



3. 层级混淆：


    

  • 同一令牌名称出现在不同层级。
    • 

  • 造成引用混乱。
    • 



4. 过度细化：


    

  • button.primary.solid.large.hover.bg。
    • 

  • 维度过多，难以管理。
    • 



5. 单位不一致：


    

  • spacing.md = 16、spacing.lg = "24px"。
    • 

  • 混用有单位和无单位值。
    • 



小结
成熟的设计系统令牌采用多层架构——引用层/全局层（原始值如 color.blue.500 = #3b82f6，字面量命名，极少变更）加系统层/别名层/语义层（描述用途如 color.action.primary = {color.blue.500}，主题覆盖在此层进行）加组件层（组件特定如 button.bg = {color.action.primary}）。多层架构让主题切换（亮色/暗色只改系统层，组件不变）、品牌重塑（只改引用层一行）和组件灵活定制都变得简单。命名规范方面，引用层用字面量、系统层用语义化、组件层用具体属性名，层级结构为"类别.类型.修饰符.状态"。颜色色阶有 Material/Tailwind 11 级和自定义 5 级两种选择，可通过算法或工具生成。间距色阶基于 4/8 像素网格和 2 的幂次，配合 T 恤尺码命名。排版色阶基于音乐比例 1.125-1.618 加基准字号，支持复合令牌。多品牌方案使用相同组件、不同系统层取值。通过 Style Dictionary 可输出 CSS 变量和 iOS Swift 常量。应避免的反模式包括：缺少引用层、缺少系统层、层级混淆、过度细化和单位不一致。多层令牌架构是设计系统工程化的核心抽象——让设计决策变得可维护、可扩展且跨平台一致。
