模块系统与解析

JavaScript 模块化的演进

JavaScript 最初被设计为简单的浏览器脚本语言，没有内置的模块系统。所有代码共享全局作用域，这在大型项目中导致了严重的命名冲突和依赖管理问题。社区驱动的模块化方案应运而生，最终演化为今天的标准化模块系统。



CommonJS (CJS)
CommonJS 是 Node.js 采用的模块规范。它的核心特征是同步加载和运行时解析。


基本语法
// math.js - 导出
const PI = 3.14159265;

function add(a, b) {
  return a + b;
}

function multiply(a, b) {
  return a * b;
}

module.exports = { PI, add, multiply };
// app.js - 导入
const { add, multiply } = require('./math');

console.log(add(1, 2));
console.log(multiply(3, 4));
CommonJS 的运行时特性
CommonJS 模块在首次 require 时被执行，执行结果被缓存。后续的 require 调用直接返回缓存值。


// counter.js
let count = 0;

module.exports = {
  increment() {
    count++;
  },
  getCount() {
    return count;
  },
};
// a.js
const counter = require('./counter');
counter.increment();
counter.increment();
console.log(counter.getCount()); // 2

// b.js - 即使在不同文件中引入，共享同一个实例
const counter = require('./counter');
console.log(counter.getCount()); // 2 (共享缓存)
CommonJS 的缓存机制
CommonJS 的关键限制在于：

ES Modules (ESM)
ES Modules 是 ECMAScript 2015（ES6）引入的官方模块标准。与 CommonJS 不同，ESM 采用静态结构和编译时分析。


基本语法
// math.js - 命名导出
export const PI = 3.14159265;

export function add(a, b) {
  return a + b;
}

export function multiply(a, b) {
  return a * b;
}

// 默认导出
export default class Calculator {
  evaluate(expr) {
    return eval(expr);
  }
}
// app.js - 命名导入
import { add, multiply, PI } from './math.js';
import Calculator from './math.js';

// 整体导入
import * as math from './math.js';

// 动态导入
const module = await import('./math.js');
ESM 的静态特性
ESM 最核心的设计决策是静态结构：import 和 export 语句必须出现在模块顶层，不能嵌套在条件语句或函数中。


// 合法 - 顶层 import
import { add } from './math.js';

// 不合法 - 条件 import
if (condition) {
  import { add } from './math.js'; // SyntaxError
}

// 动态导入使用 import() 函数
if (condition) {
  const { add } = await import('./math.js'); // 合法
}
这种静态结构使得打包器可以在不执行代码的情况下，通过静态分析确定完整的依赖图——这正是 Tree-shaking 的基础。


ESM 与 CJS 的核心差异
值的拷贝 vs 值的引用是 CJS 和 ESM 最关键的区别：


// counter.mjs (ESM)
export let count = 0;

export function increment() {
  count++;
}
// app.mjs (ESM)
import { count, increment } from './counter.mjs';

console.log(count); // 0
increment();
increment();
console.log(count); // 2 — ESM 是引用绑定，能看到原模块的变化
在 CommonJS 中，相同场景的 count 始终是初始值 0，因为 require 获取的是值的拷贝。




模块解析算法
当代码中出现 import 'lodash' 或 require('./utils') 时，运行时和打包器需要将这些模块说明符（Module Specifier）解析为文件系统中的实际路径。


Node.js 模块解析
对于裸模块说明符（如 lodash），Node.js 的查找策略是从当前目录开始，逐级向上查找 node_modules 目录：


/project/src/utils/helper.js 中 require('lodash')

查找顺序：
1. /project/src/utils/node_modules/lodash
2. /project/src/node_modules/lodash
3. /project/node_modules/lodash
4. /node_modules/lodash
package.json 中的导出映射
现代 Node.js 引入了 exports 字段，为包提供了精确的导出控制：


{
  "name": "my-library",
  "type": "module",
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    },
    "./utils": {
      "types": "./dist/utils.d.ts",
      "import": "./dist/utils.mjs",
      "require": "./dist/utils.cjs"
    }
  }
}
exports 字段支持条件导出，打包器和运行时根据环境选择合适的入口：

打包器的增强解析
打包器在 Node.js 解析算法基础上提供了更多功能：


// webpack.config.js / rspack.config.js
export default {
  resolve: {
    extensions: ['.ts', '.tsx', '.js', '.jsx'],
    alias: {
      '@': '/src',
      '@components': '/src/components',
      '@utils': '/src/utils',
    },
    mainFields: ['module', 'main'],
    conditionNames: ['import', 'module', 'browser', 'default'],
  },
};
// tsconfig.json 中的路径映射
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "@components/*": ["src/components/*"],
      "@utils/*": ["src/utils/*"]
    }
  }
}


双模块系统的互操作
在现实项目中，CJS 和 ESM 模块经常需要互操作。这是构建工具链中最复杂的问题之一。


// ESM 中导入 CJS 模块
import cjsModule from './legacy.cjs'; // 默认导入获取 module.exports
import { named } from './legacy.cjs'; // 命名导入（Node.js 会尝试静态分析）

// CJS 中使用 ESM 模块
const esmModule = await import('./modern.mjs'); // 只能使用动态 import()
打包器通常会自动处理这种互操作，但理解底层机制有助于排查一些棘手的模块兼容性问题。




小结
    

  • CommonJS 采用同步加载、运行时解析、值拷贝，是 Node.js 的传统模块系统。
    • 

  • ES Modules 采用静态结构、编译时分析、值引用，是 JavaScript 的官方标准。
    • 

  • 模块解析算法决定了模块说明符如何映射到文件系统路径。
    • 

  • package.json 的 exports 字段提供了精确的条件导出控制。
    • 

  • 打包器在标准解析算法上增加了路径别名、扩展名补全等增强功能。
    • 

  • CJS 和 ESM 的互操作是构建工具链中的常见难点。
