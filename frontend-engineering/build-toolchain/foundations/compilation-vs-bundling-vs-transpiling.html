编译、打包与转译

三个核心概念的界定

在构建工具链中，编译（Compilation）、打包（Bundling）和转译（Transpiling）是三个最基础也最容易被混淆的概念。它们代表了代码从源文件到最终产物过程中三种本质不同的变换操作。

编译（Compilation）
编译是最广义的代码转换操作。在前端语境中，编译通常指将一种高级语言转换为另一种语言。最典型的例子是 TypeScript 到 JavaScript 的编译。


TypeScript 编译过程
TypeScript 编译器（tsc）的工作远不止"去掉类型注解"。它经历了完整的编译流水线：


// 输入: TypeScript
enum Direction {
  Up = 'UP',
  Down = 'DOWN',
  Left = 'LEFT',
  Right = 'RIGHT',
}

function move(direction: Direction): void {
  console.log(`Moving ${direction}`);
}

move(Direction.Up);
// 输出: JavaScript (编译后)
var Direction;
(function (Direction) {
  Direction['Up'] = 'UP';
  Direction['Down'] = 'DOWN';
  Direction['Left'] = 'LEFT';
  Direction['Right'] = 'RIGHT';
})(Direction || (Direction = {}));

function move(direction) {
  console.log('Moving '.concat(direction));
}

move(Direction.Up);
注意 enum 被编译为 IIFE（立即执行函数表达式），这是一次真正的"编译"——输出的代码结构与输入完全不同。


CSS 预处理器编译
Sass 到 CSS 的转换同样是编译过程：


// 输入: Sass
$primary: #3498db;
$spacing: 8px;

.card {
  padding: $spacing * 2;
  border: 1px solid darken($primary, 10%);

  &__title {
    color: $primary;
    font-size: 1.5rem;
  }

  &__body {
    margin-top: $spacing;
  }
}
/* 输出: CSS */
.card {
  padding: 16px;
  border: 1px solid #2583c5;
}
.card__title {
  color: #3498db;
  font-size: 1.5rem;
}
.card__body {
  margin-top: 8px;
}
变量被替换为具体值，嵌套选择器被展开为平铺结构，颜色函数被计算——这些都是编译时完成的转换。




转译（Transpiling）
转译是编译的一个子集，特指同一种语言不同版本或方言之间的转换。最典型的场景是将现代 JavaScript（ES2024+）转换为旧版浏览器支持的 ES5。

const result = users.filter((user) => user.age >= 30).map(({ name, age }) => `${name} (${age})`);

JSX 转译
JSX 是 JavaScript 的"方言"，需要被转译为标准 JavaScript 函数调用：


// 输入: JSX
function UserCard({ user }) {
  return (
    <div className="card">
      <h2>{user.name}</h2>
      <p>{user.email}</p>
      {user.isAdmin && <span className="badge">Admin</span>}
    </div>
  );
}
// 输出: JavaScript (React 17+ 自动运行时)
import { jsx, jsxs } from 'react/jsx-runtime';

function UserCard({ user }) {
  return jsxs('div', {
    className: 'card',
    children: [
      jsx('h2', { children: user.name }),
      jsx('p', { children: user.email }),
      user.isAdmin && jsx('span', { className: 'badge', children: 'Admin' }),
    ],
  });
}


打包（Bundling）
打包是将多个独立模块文件合并为少数输出文件的过程。打包器的核心工作是构建依赖图（Dependency Graph），然后按照策略将模块分组输出。


依赖图构建
打包器从入口文件开始，递归解析每个 import/require 语句，构建出完整的模块依赖图。然后根据配置策略，将这些模块分配到不同的 Chunk 中。


打包策略对比
// webpack.config.js - 配置驱动的打包策略
export default {
  entry: {
    app: './src/index.ts',
    vendor: './src/vendor.ts',
  },
  output: {
    filename: '[name].[contenthash].js',
    path: '/dist',
  },
  optimization: {
    splitChunks: {
      chunks: 'all',
      cacheGroups: {
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendors',
          chunks: 'all',
        },
      },
    },
  },
};

三者在构建流水线中的协作
在实际的构建流水线中，编译、转译和打包并非独立运行，而是紧密协作的：


在 Webpack 中，这些步骤通过 Loader 链和 Plugin 系统融合在一个打包过程中：


// webpack.config.js
export default {
  module: {
    rules: [
      {
        test: /\.tsx?$/,
        use: [
          {
            loader: 'swc-loader',
            options: {
              jsc: {
                parser: { syntax: 'typescript', tsx: true },
                target: 'es2020',
              },
            },
          },
        ],
      },
      {
        test: /\.scss$/,
        use: ['style-loader', 'css-loader', 'sass-loader'],
      },
    ],
  },
};
而在 Vite 中，开发阶段利用浏览器原生 ESM 能力，跳过了打包步骤，只做编译和转译：


// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react-swc';

export default defineConfig({
  plugins: [react()],
});


小结
    

  • 编译是语言之间的转换（TypeScript → JavaScript，Sass → CSS）。
    • 

  • 转译是同一语言不同版本间的转换（ES2024 → ES5，JSX → JS）。
    • 

  • 打包是将多个模块合并为少数输出文件。
    • 

  • 三者在构建流水线中协作：先编译/转译单个文件，再打包合并模块，最后优化产物。
    • 

  • 理解这三个概念的区别，是选择和配置构建工具的基础认知。
