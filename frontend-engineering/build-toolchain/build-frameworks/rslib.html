Rslib 库构建工具

库构建的特殊需求

构建一个 npm 库与构建一个 Web 应用有着根本不同的需求。应用构建的目标是生成浏览器可运行的最终产物，而库构建需要生成其他开发者可引用的中间产物。这种差异体现在多个维度：

维度 应用构建 库构建
输出格式 单一格式（浏览器可执行） 多格式（ESM + CJS + UMD）
外部依赖 全部打包 peerDependencies 外置
类型声明 不需要 必须生成 .d.ts
压缩 必须 通常不压缩（由消费者决定）
CSS 处理 提取 + 压缩 可选提取或注入
Tree-shaking 生产优化 必须保证可 shake

Rslib 正是为这些库构建的特殊需求而设计的构建框架。

Rslib 概述

Rslib 基于 Rsbuild 构建，是 Rsbuild 生态中专门面向库开发者的工具。它自动处理了库构建中最繁琐的配置——双格式输出、外部依赖排除、类型声明生成、bundle 与 bundleless 模式选择。



快速开始
npm create rslib@latest
基础配置
// rslib.config.ts
import { defineConfig } from '@rslib/core';

export default defineConfig({
  lib: [
    {
      format: 'esm',
      syntax: 'es2021',
      dts: true,
    },
    {
      format: 'cjs',
      syntax: 'es2021',
    },
  ],
  source: {
    entry: {
      index: './src/index.ts',
    },
  },
});
对应的 package.json
{
  "name": "my-library",
  "version": "1.0.0",
  "type": "module",
  "main": "./dist/cjs/index.cjs",
  "module": "./dist/esm/index.js",
  "types": "./dist/esm/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/esm/index.d.ts",
      "import": "./dist/esm/index.js",
      "require": "./dist/cjs/index.cjs"
    }
  },
  "files": ["dist"],
  "scripts": {
    "build": "rslib build",
    "dev": "rslib build --watch"
  }
}


Bundle vs Bundleless 模式
Rslib 支持两种构建模式，适用于不同场景：


// rslib.config.ts
export default defineConfig({
  lib: [
    {
      format: 'esm',
      bundle: false,
      dts: { bundle: false },
    },
    {
      format: 'cjs',
      bundle: true,
    },
  ],
});




模式
适用场景
优点
缺点





Bundle
工具库、独立组件
单文件分发、无内部依赖泄露
无法 Tree-shake 内部模块




Bundleless
UI 组件库、大型工具集
消费者可精确 Tree-shake
文件数量多







外部依赖处理
库构建的一个核心问题是决定哪些依赖应该被打包进产物，哪些应该作为外部依赖：


export default defineConfig({
  lib: [
    {
      format: 'esm',
      autoExternal: {
        dependencies: true,
        peerDependencies: true,
        devDependencies: true,
      },
    },
  ],
});
{
  "dependencies": {
    "lodash-es": "^4.17.21"
  },
  "peerDependencies": {
    "react": ">=18.0.0",
    "react-dom": ">=18.0.0"
  },
  "devDependencies": {
    "@rslib/core": "^1.0.0",
    "typescript": "^5.0.0"
  }
}
Rslib 的 autoExternal 默认将 dependencies 和 peerDependencies 都排除在打包产物之外，这是库构建的标准做法。




类型声明生成
Rslib 内置了类型声明生成能力，支持 bundle 和 bundleless 两种模式：


export default defineConfig({
  lib: [
    {
      format: 'esm',
      dts: {
        bundle: true,
        distPath: './dist/types',
        abortOnError: true,
      },
    },
  ],
});


React 组件库构建
// rslib.config.ts - React 组件库配置
import { defineConfig } from '@rslib/core';
import { pluginReact } from '@rsbuild/plugin-react';

export default defineConfig({
  plugins: [pluginReact()],
  lib: [
    {
      format: 'esm',
      bundle: false,
      dts: { bundle: false },
      output: {
        distPath: { root: 'dist/esm' },
      },
    },
    {
      format: 'cjs',
      bundle: false,
      dts: false,
      output: {
        distPath: { root: 'dist/cjs' },
      },
    },
  ],
  source: {
    entry: {
      index: './src/index.ts',
    },
  },
  output: {
    externals: ['react', 'react-dom', 'react/jsx-runtime'],
  },
});
组件库的 CSS 处理
export default defineConfig({
  lib: [
    {
      format: 'esm',
      bundle: false,
      output: {
        cssModules: {
          localIdentName: '[local]--[hash:base64:5]',
        },
      },
    },
  ],
});

小结
    

  • Rslib 是基于 Rsbuild 的库构建专用框架，处理了库构建的常见需求。
    • 

  • 支持 Bundle 和 Bundleless 两种构建模式，适用于不同类型的库。
    • 

  • autoExternal 自动将 dependencies 和 peerDependencies 排除。
    • 

  • 内置类型声明（.d.ts）生成能力，支持 bundle 和 bundleless 模式。
    • 

  • 对于 React/Vue 组件库，Rslib 的 Bundleless 模式 + CSS Modules 是推荐方案。
    • 

  • 与 tsup 相比，Rslib 在 CSS 处理和 Bundleless 模式上更具优势。
