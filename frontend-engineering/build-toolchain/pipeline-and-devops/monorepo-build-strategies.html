Monorepo 构建策略

Monorepo 的构建挑战

Monorepo（单一代码仓库）将多个相关项目放在一个仓库中管理。这种方式简化了代码共享和依赖管理，但也带来了独特的构建挑战：如何只构建变更的包？如何处理包间依赖的构建顺序？如何在 CI 中高效地编排构建任务？



包管理器的 Workspace 支持
pnpm Workspace
# pnpm-workspace.yaml
packages:
  - 'apps/*'
  - 'packages/*'
{
  "name": "@myorg/web",
  "dependencies": {
    "@myorg/ui": "workspace:*",
    "@myorg/utils": "workspace:*"
  }
}
pnpm Workspace 确保了包之间的依赖链接是通过符号链接（symlink）实现的，本地修改即时生效，无需发布。




Turborepo：任务编排引擎
Turborepo 是 Vercel 开发的 Monorepo 构建工具，专注于任务编排和缓存。


核心概念
Turborepo 根据包之间的依赖关系自动构建任务图（Task Graph），确保依赖先于消费者构建，并尽可能并行执行独立任务。


配置
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**", ".next/**"]
    },
    "test": {
      "dependsOn": ["build"],
      "inputs": ["src/**", "test/**"]
    },
    "lint": {
      "dependsOn": ["^build"]
    },
    "typecheck": {
      "dependsOn": ["^build"]
    },
    "dev": {
      "cache": false,
      "persistent": true
    }
  }
}




配置项
说明





dependsOn
任务依赖，^build 表示先构建所有上游依赖




outputs
任务输出目录，用于缓存




inputs
任务输入文件，用于计算缓存键




cache
是否启用缓存




persistent
是否为长运行任务（如 dev server）





命令使用
# 构建所有包
turbo build

# 只构建特定包及其依赖
turbo build --filter=@myorg/web

# 只构建变更的包
turbo build --filter=...[HEAD^1]

# 并行运行开发服务器
turbo dev --filter=@myorg/web --filter=@myorg/admin
过滤语法




语法
含义





--filter=web
只运行 web 包




--filter=web...
web 及其所有依赖




--filter=...web
web 及其所有消费者




--filter=...[HEAD^1]
自上次提交以来变更的包




--filter=@myorg/*
匹配 @myorg 下所有包







Nx：全功能 Monorepo 平台
Nx 是另一个成熟的 Monorepo 构建工具，功能比 Turborepo 更加全面：


Nx 配置
{
  "targetDefaults": {
    "build": {
      "dependsOn": ["^build"],
      "cache": true,
      "inputs": ["production", "^production"],
      "outputs": ["{projectRoot}/dist"]
    },
    "test": {
      "cache": true,
      "inputs": ["default", "^production"]
    },
    "lint": {
      "cache": true,
      "inputs": ["default"]
    }
  },
  "namedInputs": {
    "default": ["{projectRoot}/**/*", "sharedGlobals"],
    "production": ["default", "!{projectRoot}/**/*.spec.ts", "!{projectRoot}/tsconfig.spec.json"],
    "sharedGlobals": ["{workspaceRoot}/tsconfig.base.json"]
  }
}
Nx 的受影响包分析
# 分析哪些包受到了影响
nx affected --target=build

# 只测试受影响的包
nx affected --target=test

# 可视化依赖图
nx graph

CI 中的 Monorepo 构建
# .github/workflows/ci.yml - Turborepo + GitHub Actions
name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 2

      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - name: Build affected packages
        run: turbo build --filter=...[HEAD^1]
        env:
          TURBO_TOKEN: ${{ secrets.TURBO_TOKEN }}
          TURBO_TEAM: ${{ vars.TURBO_TEAM }}

      - name: Test affected packages
        run: turbo test --filter=...[HEAD^1]


小结
    

  • Monorepo 的核心挑战是构建编排：依赖顺序、并行执行、变更检测。
    • 

  • pnpm Workspace 通过符号链接管理包间依赖。
    • 

  • Turborepo 以任务图为核心，自动推导构建顺序并并行执行。
    • 

  • --filter 语法实现了只构建变更包及其下游消费者。
    • 

  • Nx 提供更全面的功能（代码生成、可视化依赖图、IDE 集成）。
    • 

  • CI 中结合 --filter=...[HEAD^1] 和远程缓存，大幅缩短流水线时间。
    •
