缓存与增量构建

构建缓存的核心原理

构建缓存的基本思路非常简单：如果输入没有变化，那么输出也不应该变化。通过记录每次构建的输入（源文件、配置、依赖版本）和输出（产物文件），下次遇到相同的输入时直接复用之前的输出，跳过实际的构建过程。



打包器层面的缓存
Webpack/Rspack 持久化缓存
Webpack 5 引入了持久化缓存（Persistent Cache），将编译结果写入磁盘，二次构建速度大幅提升：


// webpack.config.js
export default {
  cache: {
    type: 'filesystem',
    buildDependencies: {
      config: [__filename],
    },
    cacheDirectory: '.cache/webpack',
    name: `${process.env.NODE_ENV}-${process.env.TARGET}`,
    version: '1.0',
  },
};
// rsbuild.config.ts - Rspack 缓存配置
export default {
  performance: {
    buildCache: {
      type: 'filesystem',
      cacheDirectory: '.cache/rspack',
    },
  },
};

Vite 的依赖预构建缓存
Vite 将预构建结果缓存在 node_modules/.vite/ 目录：


// vite.config.ts
export default defineConfig({
  cacheDir: 'node_modules/.vite',
  optimizeDeps: {
    force: false,
  },
});
Vite 的缓存在以下情况自动失效：


    

  • package.json 中的依赖版本变更
    • 

  • 锁文件（pnpm-lock.yaml）变更
    • 

  • vite.config.ts 中的相关配置变更
    • 





TypeScript 增量编译
TypeScript 编译器支持增量编译（Incremental Compilation），通过记录上次编译的状态信息来加速后续编译：


{
  "compilerOptions": {
    "incremental": true,
    "tsBuildInfoFile": ".cache/tsconfig.tsbuildinfo"
  }
}
项目引用的增量构建
# 增量构建所有项目
tsc --build --incremental

# 强制全量构建
tsc --build --force

# 清除增量缓存
tsc --build --clean
tsc 的增量编译通过 .tsbuildinfo 文件记录：


    

  • 每个文件的内容哈希
    • 

  • 文件间的依赖关系
    • 

  • 上次编译的配置
    • 



当只有少数文件变更时，tsc 只需要重新编译变更的文件及其依赖链上的文件。




任务编排层面的缓存
Turborepo 本地缓存
Turborepo 在任务级别实现了缓存。它根据任务的输入（源文件、环境变量、依赖版本）计算哈希，如果哈希匹配则直接从缓存中恢复输出：


$ turbo build

 Tasks:    5 successful, 5 total
 Cached:   4 cached, 5 total
 Time:     1.2s

 @myorg/config#build     cache hit ✅   replaying logs  120ms
 @myorg/utils#build      cache hit ✅   replaying logs  180ms
 @myorg/ui#build          cache hit ✅   replaying logs  350ms
 @myorg/admin#build      cache hit ✅   replaying logs  800ms
 @myorg/web#build         cache miss     executed        1.1s
Turborepo 远程缓存
远程缓存允许团队成员之间共享构建缓存。当 CI 完成构建后，其他开发者和后续的 CI 运行可以直接复用这些缓存：


# 登录远程缓存
npx turbo login

# 链接到团队
npx turbo link

# 构建时自动使用远程缓存
turbo build
自托管远程缓存
# docker-compose.yml - 自托管 Turborepo 缓存服务器
services:
  turbo-cache:
    image: ducktors/turborepo-remote-cache
    ports:
      - '3000:3000'
    environment:
      STORAGE_PROVIDER: s3
      S3_ACCESS_KEY: ${AWS_ACCESS_KEY_ID}
      S3_SECRET_KEY: ${AWS_SECRET_ACCESS_KEY}
      S3_BUCKET: turbo-cache
      S3_REGION: us-east-1
      TURBO_TOKEN: ${TURBO_TOKEN}


CI 中的缓存策略
多层缓存架构
# .github/workflows/ci.yml - 多层缓存
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      # L2: 打包器缓存
      - uses: actions/cache@v4
        with:
          path: |
            .cache/rspack
            node_modules/.vite
          key: build-cache-${{ hashFiles('pnpm-lock.yaml') }}-${{ github.sha }}
          restore-keys: |
            build-cache-${{ hashFiles('pnpm-lock.yaml') }}-
            build-cache-

      - run: pnpm install --frozen-lockfile

      # L3: Turborepo 远程缓存
      - run: turbo build
        env:
          TURBO_TOKEN: ${{ secrets.TURBO_TOKEN }}
          TURBO_TEAM: ${{ vars.TURBO_TEAM }}


缓存失效策略
缓存虽然能大幅提升构建速度，但错误的缓存可能导致构建结果不正确。理解缓存失效时机至关重要：






触发条件
应失效的缓存





源文件变更
受影响的编译缓存 + 任务缓存




依赖版本变更
所有缓存




构建配置变更
打包器缓存 + 任务缓存




Node.js 版本变更
所有缓存




环境变量变更
使用该变量的任务缓存





# 清除 Turborepo 缓存
turbo clean

# 清除 Vite 预构建缓存
rm -rf node_modules/.vite

# 清除 Webpack/Rspack 缓存
rm -rf .cache/webpack
rm -rf .cache/rspack

# 强制全量构建
turbo build --force

小结
    

  • 构建缓存的核心原理：相同的输入产生相同的输出，跳过重复计算。
    • 

  • 打包器缓存（Webpack/Rspack filesystem cache）可将二次构建提速 5-10 倍。
    • 

  • TypeScript 增量编译通过 .tsbuildinfo 文件记录编译状态。
    • 

  • Turborepo 远程缓存实现了团队级别的构建缓存共享。
    • 

  • CI 中应采用多层缓存策略：依赖缓存 → 打包器缓存 → 任务缓存。
    • 

  • 缓存失效策略同样重要——错误的缓存比没有缓存更危险。
    • 

  • 定期监控构建指标，确保构建性能持续健康。
    •
