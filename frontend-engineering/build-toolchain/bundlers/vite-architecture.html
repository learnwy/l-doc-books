Vite 架构

Vite 的设计理念

Vite（法语"快"的意思）由 Vue.js 的作者尤雨溪创建，它的出现源于对 Webpack 开发体验的根本反思：随着项目规模增长，Webpack 的开发服务器启动时间从秒级增长到分钟级，HMR 更新也越来越慢。Vite 的核心思路是利用浏览器原生 ES Modules 支持，彻底跳过开发阶段的打包步骤。



双引擎架构
Vite 在开发环境和生产环境使用完全不同的策略，这是理解 Vite 的关键：

开发环境：原生 ESM 驱动
无打包开发服务器
当浏览器遇到 <script type="module"> 时，会逐个请求模块文件。Vite 利用这一特性，在开发阶段不做任何打包，而是作为一个模块转换中间件，按需将源文件转换为浏览器可执行的 ESM。


<!-- Vite 生成的 HTML -->
<script type="module" src="/src/main.tsx"></script>

依赖预构建
Vite 的"无打包"策略有一个例外：node_modules 中的第三方依赖。这些依赖可能使用 CommonJS 格式，且往往包含数百个内部模块（如 lodash-es 有 600+ 个文件）。Vite 使用 esbuild 对依赖进行预构建：


// vite.config.ts
import { defineConfig } from 'vite';

export default defineConfig({
  optimizeDeps: {
    include: ['react', 'react-dom', 'lodash-es'],
    exclude: ['@my-org/local-package'],
    esbuildOptions: {
      target: 'es2020',
    },
  },
});
预构建完成两件事：


    

  1. CJS → ESM 转换：将 CommonJS 依赖转换为 ESM 格式
    2. 

  2. 模块合并：将拥有大量内部模块的依赖打包为单个文件，减少 HTTP 请求
    3. 



node_modules/.vite/deps/
├── react.js              # 预构建后的单文件
├── react-dom.js
├── lodash-es.js          # 600+ 文件 → 1 文件
└── _metadata.json        # 依赖元数据
HMR 实现
Vite 的 HMR 基于原生 ESM 的精确依赖图，只需要重新请求变更的模块，不需要重新构建整个模块树：


// Vite HMR API
if (import.meta.hot) {
  import.meta.hot.accept('./module.ts', (newModule) => {
    console.log('模块已更新:', newModule);
  });

  import.meta.hot.dispose(() => {
    console.log('清理旧模块副作用');
  });
}


生产环境：Rollup 打包
开发环境的"无打包"策略不适合生产环境，原因包括：网络瀑布流加载效率低、无法进行深度 Tree-shaking、缺乏代码分割优化。因此 Vite 的生产构建使用 Rollup 进行完整打包。


// vite.config.ts - 构建配置
import { defineConfig } from 'vite';

export default defineConfig({
  build: {
    target: 'es2020',
    outDir: 'dist',
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom'],
          router: ['react-router-dom'],
          ui: ['@radix-ui/react-dialog', '@radix-ui/react-dropdown-menu'],
        },
      },
    },
    minify: 'terser',
    sourcemap: true,
    cssCodeSplit: true,
    chunkSizeWarningLimit: 500,
  },
});


插件系统
Vite 的插件系统基于 Rollup 插件接口的超集。一个 Vite 插件可以同时服务于开发和生产环境：


import type { Plugin } from 'vite';

function myPlugin(): Plugin {
  return {
    name: 'vite-plugin-my-transform',
    enforce: 'pre',
    transform(code, id) {
      if (!id.endsWith('.custom')) return null;
      return {
        code: transformCustomSyntax(code),
        map: null,
      };
    },
    configureServer(server) {
      server.middlewares.use((req, res, next) => {
        if (req.url === '/api/health') {
          res.end('ok');
          return;
        }
        next();
      });
    },
  };
}

环境变量与模式
Vite 使用 .env 文件管理环境变量，只有以 VITE_ 为前缀的变量会暴露给客户端代码：


# .env.development
VITE_API_URL=http://localhost:8080/api
VITE_APP_TITLE=My App (Dev)
DB_PASSWORD=secret  # 不会暴露给客户端
// 客户端代码中使用
console.log(import.meta.env.VITE_API_URL);
console.log(import.meta.env.MODE);
console.log(import.meta.env.DEV);
console.log(import.meta.env.PROD);
// env.d.ts - 类型声明
interface ImportMetaEnv {
  readonly VITE_API_URL: string;
  readonly VITE_APP_TITLE: string;
}

interface ImportMeta {
  readonly env: ImportMetaEnv;
}

小结
    

  • Vite 采用双引擎架构：开发环境用原生 ESM + esbuild，生产环境用 Rollup。
    • 

  • 依赖预构建解决了第三方库的 CJS 兼容和请求数量问题。
    • 

  • HMR 基于精确的模块依赖图，更新速度与项目大小无关。
    • 

  • 插件系统基于 Rollup 插件接口的超集，同时服务于开发和生产。
    • 

  • Vite 的"约定优于配置"理念大幅降低了构建工具的使用门槛。
    •
