Webpack 核心概念

Webpack 的设计哲学

Webpack 是前端生态中最具影响力的打包器。它的核心理念是一切皆模块——JavaScript、CSS、图片、字体、HTML 模板，所有资源都可以作为模块被引入和处理。这种统一的模块化视角使得 Webpack 能够构建出完整的依赖图，并对所有资源进行统一的优化和输出。



五大核心概念
Entry（入口）
Entry 是 Webpack 构建依赖图的起点。Webpack 从入口开始，递归地解析所有依赖模块。


// webpack.config.js

// 单入口
export default {
  entry: "./src/index.ts",
};

// 多入口
export default {
  entry: {
    app: "./src/app.ts",
    admin: "./src/admin.ts",
    vendor: ["react", "react-dom"],
  },
};

// 动态入口
export default {
  entry: () => ({
    app: "./src/app.ts",
    ...(process.env.NODE_ENV === "development"
      ? { devtools: "./src/devtools.ts" }
      : {}),
  }),
};
Output（输出）
Output 配置告诉 Webpack 将打包产物写入到哪里，以及如何命名。


export default {
  output: {
    path: '/dist',
    filename: '[name].[contenthash:8].js',
    chunkFilename: 'chunks/[name].[contenthash:8].js',
    publicPath: '/assets/',
    clean: true,
  },
};

Loader（加载器）
Loader 是 Webpack 最强大的扩展机制之一。由于 Webpack 原生只理解 JavaScript 和 JSON，所有其他类型的文件都需要通过 Loader 转换为有效的模块。


export default {
  module: {
    rules: [
      {
        test: /\.tsx?$/,
        exclude: /node_modules/,
        use: [
          {
            loader: 'swc-loader',
            options: {
              jsc: {
                parser: {
                  syntax: 'typescript',
                  tsx: true,
                },
                transform: {
                  react: {
                    runtime: 'automatic',
                  },
                },
              },
            },
          },
        ],
      },
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader', 'postcss-loader'],
      },
      {
        test: /\.svg$/,
        type: 'asset',
        parser: {
          dataUrlCondition: {
            maxSize: 8 * 1024,
          },
        },
      },
    ],
  },
};

Plugin（插件）
Plugin 是 Webpack 构建流程的"钩子系统"。Loader 负责文件级别的转换，而 Plugin 可以介入构建的任何阶段，执行更广泛的任务。


import HtmlWebpackPlugin from 'html-webpack-plugin';
import MiniCssExtractPlugin from 'mini-css-extract-plugin';
import { BundleAnalyzerPlugin } from 'webpack-bundle-analyzer';
import ForkTsCheckerPlugin from 'fork-ts-checker-webpack-plugin';

export default {
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/index.html',
      minify: { collapseWhitespace: true },
    }),
    new MiniCssExtractPlugin({
      filename: 'css/[name].[contenthash:8].css',
    }),
    new ForkTsCheckerPlugin({
      typescript: {
        diagnosticOptions: { semantic: true, syntactic: true },
      },
    }),
    process.env.ANALYZE && new BundleAnalyzerPlugin(),
  ].filter(Boolean),
};
Chunk（代码块）
Chunk 是 Webpack 输出的产物单位。Webpack 会根据配置将模块分配到不同的 Chunk 中。


export default {
  optimization: {
    runtimeChunk: 'single',
    splitChunks: {
      chunks: 'all',
      maxInitialRequests: 20,
      maxAsyncRequests: 20,
      cacheGroups: {
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name(module) {
            const packageName = module.context.match(/[\\/]node_modules[\\/](.*?)([\\/]|$)/)[1];
            return `vendor.${packageName.replace('@', '')}`;
          },
        },
        common: {
          minChunks: 2,
          priority: -10,
          reuseExistingChunk: true,
        },
      },
    },
  },
};

小结
    

  • Webpack 的五大核心概念：Entry、Output、Loader、Plugin、Chunk。
    • 

  • Loader 负责文件级转换，Plugin 介入构建流程的各个阶段。
    • 

  • Chunk 分割策略直接影响应用的加载性能和缓存效率。
    • 

  • HMR 通过 WebSocket 实现开发时的即时模块替换。
    • 

  • Webpack 5 引入了 Module Federation、持久化缓存等重要特性。
    • 

  • 即便 Vite/Rspack 已成为更流行的选择，Webpack 的概念体系仍是理解打包器的基础。
