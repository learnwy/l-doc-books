esbuild 极速构建工具

极速构建的先驱

esbuild 由 Evan Wallace（Figma 联合创始人）用 Go 语言编写，于 2020 年发布。它的出现在前端构建领域引发了一场"性能革命"——在大多数场景下，esbuild 的构建速度比基于 JavaScript 的工具快 10 到 100 倍。这种性能优势不是来自算法优化，而是来自底层语言选择和架构设计。



为什么这么快？
esbuild 的极速性能来自四个关键设计决策：


1. Go 语言的原生性能
Go 编译为原生机器码，没有 JavaScript 的 JIT 编译开销和垃圾回收暂停。Go 的 goroutine 机制使并行处理成本极低。


2. 从零实现的解析器
esbuild 没有使用现有的 JavaScript 解析库，而是从零实现了自己的解析器。这避免了 AST 的序列化/反序列化开销，解析结果直接在内存中使用。


3. 充分的并行化
esbuild 的解析、链接和代码生成阶段都是高度并行的。多个文件可以同时被解析和转换，充分利用多核 CPU。


4. 最小化内存分配
esbuild 精心设计了数据结构，减少内存分配次数和 GC 压力。AST 节点使用紧凑的内存布局，避免了 JavaScript 对象的内存开销。




核心功能
打包
import * as esbuild from 'esbuild';

await esbuild.build({
  entryPoints: ['src/index.ts'],
  bundle: true,
  outdir: 'dist',
  format: 'esm',
  splitting: true,
  sourcemap: true,
  target: ['es2020'],
  minify: true,
  metafile: true,
});
转换（不打包）
esbuild 可以单独用作转换器，不进行打包：


import * as esbuild from 'esbuild';

const result = await esbuild.transform(tsCode, {
  loader: 'tsx',
  target: 'es2020',
  jsx: 'automatic',
  jsxImportSource: 'react',
});

console.log(result.code);
CLI 使用
# 打包
esbuild src/index.ts --bundle --outdir=dist --format=esm --minify

# 转换单个文件
esbuild src/app.tsx --loader=tsx --target=es2020

# 开发服务器
esbuild src/index.ts --bundle --servedir=public --serve=8000


配置详解
入口与输出
await esbuild.build({
  entryPoints: {
    app: 'src/app.ts',
    worker: 'src/worker.ts',
  },
  outdir: 'dist',
  entryNames: '[dir]/[name]-[hash]',
  chunkNames: 'chunks/[name]-[hash]',
  assetNames: 'assets/[name]-[hash]',
  format: 'esm',
  splitting: true,
  bundle: true,
});
Loader 配置
esbuild 通过 Loader 识别不同文件类型：


await esbuild.build({
  entryPoints: ['src/index.ts'],
  bundle: true,
  loader: {
    '.png': 'file',
    '.svg': 'dataurl',
    '.woff2': 'file',
    '.json': 'json',
    '.css': 'css',
  },
  outdir: 'dist',
});

外部依赖
await esbuild.build({
  entryPoints: ['src/index.ts'],
  bundle: true,
  external: ['react', 'react-dom', '*.png', '/images/*'],
  platform: 'node',
  format: 'esm',

Define 和环境变量
await esbuild.build({
  entryPoints: ['src/index.ts'],
  bundle: true,
  define: {
    'process.env.NODE_ENV': '"production"',
    __DEV__: 'false',
    __VERSION__: '"1.0.0"',
  },
  outdir: 'dist',
});


插件系统
esbuild 的插件系统相比 Webpack/Rollup 更加底层，但足以覆盖大多数场景：


const envPlugin = {
  name: 'env',
  setup(build) {
    build.onResolve({ filter: /^env$/ }, (args) => ({
      path: args.path,
      namespace: 'env-ns',
    }));

    build.onLoad({ filter: /.*/, namespace: 'env-ns' }, () => ({
      contents: JSON.stringify(process.env),
      loader: 'json',
    }));
  },
};

await esbuild.build({
  entryPoints: ['src/index.ts'],
  bundle: true,
  outdir: 'dist',
  plugins: [envPlugin],
});

esbuild 的局限性
尽管 esbuild 极其快速，但它有意识地做出了一些取舍：






限制
说明
替代方案





不做类型检查
esbuild 只剥离类型注解，不验证类型正确性
并行运行 tsc --noEmit




不支持某些 TS 特性
const enum、装饰器元数据等需要类型信息的特性
使用 SWC 或 tsc




插件生态较小
相比 Webpack/Rollup 插件数量有限
自定义插件或使用上层封装




CSS Modules 支持有限
不支持 CSS Modules 的组合（composes）
PostCSS 预处理




代码分割能力有限
仅支持 ESM 格式的代码分割
使用 Rollup 进行生产构建







esbuild 在工具链中的角色
esbuild 很少被单独作为应用的最终打包工具使用。它更常见的角色是作为其他工具的底层引擎：


// tsup - 基于 esbuild 的 TS 库打包工具
// tsup.config.ts
import { defineConfig } from 'tsup';

export default defineConfig({
  entry: ['src/index.ts'],
  format: ['cjs', 'esm'],
  dts: true,
  splitting: true,
  sourcemap: true,
  clean: true,
  minify: true,
});


Build API vs Transform API
esbuild 提供两个核心 API：


import * as esbuild from 'esbuild';

// Build API - 完整的打包流程
const buildResult = await esbuild.build({
  entryPoints: ['src/index.ts'],
  bundle: true,
  write: false,
});
console.log(buildResult.outputFiles);

// Transform API - 单文件转换
const transformResult = await esbuild.transform('let x: number = 1', {
  loader: 'ts',
});
console.log(transformResult.code);

// Context API - 增量构建和 Watch 模式
const ctx = await esbuild.context({
  entryPoints: ['src/index.ts'],
  bundle: true,
  outdir: 'dist',
});

await ctx.watch();
const { host, port } = await ctx.serve({ servedir: 'public' });
console.log(`Serving at http://${host}:${port}`);


小结
    

  • esbuild 用 Go 语言编写，构建速度比 JavaScript 工具快 10-100 倍。
    • 

  • 性能优势来自原生编译、自研解析器、充分并行和最小内存分配。
    • 

  • esbuild 支持打包、转换、压缩和开发服务器。
    • 

  • 有意的取舍：不做类型检查、有限的代码分割、较小的插件生态。
    • 

  • esbuild 最常见的角色是作为其他工具（Vite、tsup、Vitest）的底层引擎。
    • 

  • Build API 用于完整打包，Transform API 用于单文件转换，Context API 用于增量构建。
