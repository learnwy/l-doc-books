Tree-shaking 与死代码消除

什么是 Tree-shaking

Tree-shaking 是一种构建时优化技术，通过静态分析模块的导入/导出关系，自动移除最终产物中未被引用的代码。这个比喻来源于"摇晃一棵树，让枯死的叶子掉落"——未被使用的导出就是那些"枯叶"。



Tree-shaking 的前提条件
Tree-shaking 并非在所有场景下都能生效。它依赖几个关键前提：


1. ES Modules 的静态结构
// ✅ 可以 Tree-shake - ESM 的 import/export 是静态的
import { add } from './math.js';

// ❌ 无法 Tree-shake - CommonJS 是动态的
const { add } = require('./math.js');

// ❌ 无法 Tree-shake - 动态导入路径
import(`./${moduleName}.js`);

// ✅ 可以 Tree-shake - 命名导入
import { specific } from 'large-library';

// ⚠️ 部分可 shake - 取决于库的实现
import _ from 'lodash'; // 整体导入，难以 shake
import map from 'lodash-es/map'; // 精确导入，可以 shake
2. 无副作用标记
{
  "name": "my-library",
  "sideEffects": false
}
{
  "name": "my-library",
  "sideEffects": ["*.css", "*.scss", "./src/polyfills.ts", "./src/global-setup.ts"]
}


副作用（Side Effects）的影响
副作用是 Tree-shaking 最大的障碍。如果一个模块在被导入时就会执行某些代码（修改全局变量、发起网络请求、注册事件等），打包器就不敢安全地移除它。


// ❌ 有副作用 - 修改全局对象
Array.prototype.customMethod = function () {
  return this.length;
};
export const helper = () => {};

// ❌ 有副作用 - 模块顶层执行代码
console.log('Module loaded!');
export const utils = {};

// ✅ 无副作用 - 纯导出
export function add(a, b) {
  return a + b;
}

export function subtract(a, b) {
  return a - b;
}
/#PURE/ 标注
当打包器无法确定一个表达式是否有副作用时，可以使用 /*#__PURE__*/ 注释手动标注：


export const logger = /*#__PURE__*/ createLogger({
  level: 'info',
  prefix: 'app',
});

export const theme = /*#__PURE__*/ Object.freeze({
  colors: {
    primary: '#3498db',
    secondary: '#2ecc71',
  },
});


不同打包器的 Tree-shaking 能力
Webpack 的 Tree-shaking 配置
// webpack.config.js
export default {
  mode: 'production',
  optimization: {
    usedExports: true,
    minimize: true,
    sideEffects: true,
    concatenateModules: true,
    innerGraph: true,
  },
};




选项
作用





usedExports
标记哪些导出被使用（Dead Code 标记）




minimize
启用压缩器，移除被标记的死代码




sideEffects
读取 package.json 的 sideEffects 字段




concatenateModules
Module Concatenation / Scope Hoisting




innerGraph
分析函数内部的导出使用关系





Rollup 的 Tree-shaking
Rollup 的 Tree-shaking 能力是业界标杆，开箱即用无需额外配置：


// rollup.config.js
export default {
  input: 'src/index.ts',
  output: { file: 'dist/bundle.js', format: 'esm' },
  treeshake: {
    moduleSideEffects: false,
    propertyReadSideEffects: false,
    tryCatchDeoptimization: false,
  },
};


Tree-shaking 的常见陷阱
陷阱一：重导出（Re-exports）的 barrel 文件
// src/components/index.ts (barrel 文件)
export { Button } from './Button';
export { Modal } from './Modal';
export { Table } from './Table';
export { DatePicker } from './DatePicker';
export { RichEditor } from './RichEditor';
// 消费者
import { Button } from '@my-ui/components';
如果 barrel 文件中的某些组件有副作用（如 CSS 导入），Tree-shaking 可能无法正确移除未使用的组件。


// ✅ 更安全的做法 - 直接导入
import { Button } from '@my-ui/components/Button';
陷阱二：类和装饰器
// 类的方法无法被 Tree-shake
class Utils {
  static formatDate(date: Date): string {
    return date.toISOString();
  }
  static formatCurrency(amount: number): string {
    return `$${amount.toFixed(2)}`;
  }
}

// ✅ 独立函数可以被 Tree-shake
export function formatDate(date: Date): string {
  return date.toISOString();
}

export function formatCurrency(amount: number): string {
  return `$${amount.toFixed(2)}`;
}
陷阱三：CommonJS 依赖
// node_modules/legacy-lib/index.js (CommonJS)
module.exports = {
  featureA: function () {},
  featureB: function () {},
  featureC: function () {},
};
CommonJS 模块的导出是动态的，打包器难以确定哪些属性被使用。大多数情况下，整个模块都会被保留。




验证 Tree-shaking 效果
使用 webpack-bundle-analyzer
import { BundleAnalyzerPlugin } from 'webpack-bundle-analyzer';

export default {
  plugins: [
    new BundleAnalyzerPlugin({
      analyzerMode: 'static',
      openAnalyzer: false,
      reportFilename: 'bundle-report.html',
    }),
  ],
};
使用 Vite 的 rollup-plugin-visualizer
import { defineConfig } from 'vite';
import { visualizer } from 'rollup-plugin-visualizer';

export default defineConfig({
  plugins: [
    visualizer({
      filename: 'dist/stats.html',
      open: true,
      gzipSize: true,
    }),
  ],
});


编写 Tree-shake 友好的代码




实践
说明





使用 ESM 格式发布
确保消费者的打包器可以分析静态结构




设置 sideEffects: false
告诉打包器你的代码没有副作用




避免 barrel 文件中的副作用
确保 index.ts 只做纯粹的重导出




优先使用独立函数而非类方法
函数级别的 Tree-shaking 更可靠




使用 /*#__PURE__*/ 标注
帮助打包器识别无副作用的表达式




提供 module 字段
在 package.json 中指向 ESM 入口







小结
    

  • Tree-shaking 通过静态分析移除未被引用的代码，前提是 ES Modules 的静态结构。
    • 

  • 副作用是 Tree-shaking 的最大障碍，sideEffects 字段和 /*#__PURE__*/ 标注是关键工具。
    • 

  • Rollup 的 Tree-shaking 能力是业界标杆，Webpack 5 通过 innerGraph 显著提升了深度。
    • 

  • 常见陷阱：barrel 文件、类方法、CommonJS 依赖。
    • 

  • 使用 bundle analyzer 工具定期验证 Tree-shaking 效果。
