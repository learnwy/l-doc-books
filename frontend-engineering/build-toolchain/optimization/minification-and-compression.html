压缩与压缩

核心概念

产物优化的最后一段由两件事组成：代码压缩（Minification）与资源压缩（Compression）。前者在语法层做变换——移除空白、缩短标识符、常量折叠、剔除死代码——减少源码体积；后者在传输层压缩——Gzip/Brotli——减少实际传输字节。两者解决的不是同一维度的问题，通常需要叠加使用，这也是「压缩」一词在前端语境下容易混淆的原因。

构建优化的最后一公里

在 Tree-shaking 消除了未使用的代码、代码分割实现了按需加载之后，代码压缩（Minification）和资源压缩（Compression）是构建产物体积优化的最后一道工序。两者协同工作，通常能将产物的实际传输大小减少 70-80%。

flowchart LR
    SRC[源代码<br/>500KB]
    TREE[Tree-shaking<br/>350KB]
    MINIFY[代码压缩<br/>120KB]
    GZIP[Gzip/Brotli<br/>35KB]

    SRC -->|-30%| TREE -->|-66%| MINIFY -->|-71%| GZIP

代码压缩（Minification）

代码压缩是在不改变代码行为的前提下，通过一系列变换减少代码体积。

压缩技术一览

技术 说明 示例
空白移除 移除空格、换行、缩进 a + b → a+b
标识符缩短 将变量名缩短为单字母 userName → n
常量折叠 编译时计算常量表达式 1 + 2 → 3
死代码移除 移除永远不会执行的代码 if (false) {...} → 移除
布尔简化 简化布尔表达式 !!x → x（某些语境下）
属性简写 使用简写属性 {a: a} → {a}
字符串优化 合并相邻字符串 'a'+'b' → 'ab'

压缩前后对比

// 压缩前 (1.2KB)
function calculateTotalPrice(items, taxRate, discountCode) {
  let subtotal = 0;

  for (let index = 0; index < items.length; index++) {
    const currentItem = items[index];
    const itemPrice = currentItem.price * currentItem.quantity;
    subtotal = subtotal + itemPrice;
  }

  let discount = 0;
  if (discountCode === 'SAVE10') {
    discount = subtotal * 0.1;
  } else if (discountCode === 'SAVE20') {
    discount = subtotal * 0.2;
  }

  const afterDiscount = subtotal - discount;
  const tax = afterDiscount * taxRate;
  const totalPrice = afterDiscount + tax;

  return {
    subtotal: subtotal,
    discount: discount,
    tax: tax,
    total: totalPrice,
  };
}
// 压缩后 (280B)
function calculateTotalPrice(t, e, n) {
  let l = 0;
  for (let e = 0; e < t.length; e++) {
    const n = t[e];
    l += n.price * n.quantity;
  }
  let o = 0;
  'SAVE10' === n ? (o = 0.1 * l) : 'SAVE20' === n && (o = 0.2 * l);
  const c = l - o,
    i = c * e;
  return { subtotal: l, discount: o, tax: i, total: c + i };
}

主流压缩工具

Terser

Terser 是 Webpack 5 的默认 JavaScript 压缩工具，是 UglifyJS 的后继者，支持 ES6+ 语法。

// webpack.config.js
import TerserPlugin from 'terser-webpack-plugin';

export default {
  optimization: {
    minimize: true,
    minimizer: [
      new TerserPlugin({
        terserOptions: {
          compress: {
            drop_console: true,
            drop_debugger: true,
            pure_funcs: ['console.log'],
            passes: 2,
          },
          mangle: {
            safari10: true,
          },
          format: {
            comments: false,
          },
        },
        extractComments: false,
        parallel: true,
      }),
    ],
  },
};

esbuild 压缩

esbuild 的压缩速度远超 Terser（约 10-100 倍），但压缩率略低 1-3%：

// Vite 默认使用 esbuild 压缩
import { defineConfig } from 'vite';

export default defineConfig({
  build: {
    minify: 'esbuild',
  },
  esbuild: {
    drop: ['console', 'debugger'],
    legalComments: 'none',
  },
});

SWC 压缩

SWC 也提供了压缩能力，性能介于 esbuild 和 Terser 之间，但压缩率接近 Terser：

// Rspack/Rsbuild 使用 SWC 压缩
export default {
  optimization: {
    minimizer: [
      new SwcJsMinimizerRspackPlugin({
        compress: {
          drop_console: true,
        },
      }),
    ],
  },
};

压缩工具对比

工具 语言 速度 压缩率 适用场景
Terser JS 基准 最好 追求极致压缩率
esbuild Go ~100x 好（-1~3%） 开发构建、追求速度
SWC Rust ~20x 很好 Rspack/Rsbuild 项目

CSS 压缩

cssnano

// postcss.config.js
export default {
  plugins: {
    cssnano: {
      preset: [
        'default',
        {
          discardComments: { removeAll: true },
          normalizeWhitespace: true,
          colormin: true,
          reduceIdents: true,
          mergeRules: true,
          minifyFontValues: true,
          minifyGradients: true,
          minifySelectors: true,
        },
      ],
    },
  },
};
/* 压缩前 */
.container {
  margin-top: 10px;
  margin-right: 20px;
  margin-bottom: 10px;
  margin-left: 20px;
  color: #ff0000;
  background-color: rgba(0, 0, 0, 0.8);
  font-weight: bold;
}

/* 压缩后 */
.container {
  margin: 10px 20px;
  color: red;
  background-color: #000c;
  font-weight: 700;
}

Lightning CSS

Lightning CSS 是用 Rust 编写的 CSS 解析和压缩工具，速度远超 cssnano：

// Vite 中使用 Lightning CSS
import { defineConfig } from 'vite';

export default defineConfig({
  css: {
    transformer: 'lightningcss',
    lightningcss: {
      targets: { chrome: 95 },
      drafts: { customMedia: true },
    },
  },
  build: {
    cssMinify: 'lightningcss',
  },
});

资源压缩（Compression）

资源压缩发生在 HTTP 传输层面。服务器将文件通过 Gzip 或 Brotli 算法压缩后再传输给浏览器，浏览器自动解压。

Gzip vs Brotli

维度 Gzip Brotli
压缩率 好 更好（比 Gzip 小 15-25%）
压缩速度 快 较慢（高压缩级别时）
浏览器支持 全部 所有现代浏览器
HTTPS 要求 不要求 要求 HTTPS
适用场景 通用 静态资源预压缩

构建时预压缩

在构建时生成压缩文件，避免服务器实时压缩的 CPU 开销：

// Vite + vite-plugin-compression
import { defineConfig } from 'vite';
import viteCompression from 'vite-plugin-compression';

export default defineConfig({
  plugins: [
    viteCompression({
      algorithm: 'gzip',
      ext: '.gz',
      threshold: 1024,
    }),
    viteCompression({
      algorithm: 'brotliCompress',
      ext: '.br',
      threshold: 1024,
    }),
  ],
});

Nginx 配置

server {
    gzip on;
    gzip_static on;
    gzip_types text/plain text/css application/json application/javascript text/xml;
    gzip_min_length 1024;
    gzip_comp_level 6;

    brotli on;
    brotli_static on;
    brotli_types text/plain text/css application/json application/javascript text/xml;
    brotli_comp_level 6;

    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}

完整的优化流水线

flowchart TD
    SRC[源代码]
    TREE[Tree-shaking<br/>移除未用代码]
    SPLIT[代码分割<br/>按需加载]
    MINIFY_JS[JS 压缩<br/>Terser/esbuild/SWC]
    MINIFY_CSS[CSS 压缩<br/>cssnano/LightningCSS]
    IMG_OPT[图片优化<br/>WebP/AVIF]
    GZIP[Gzip/Brotli<br/>传输压缩]
    CDN[CDN 分发<br/>边缘缓存]

    SRC --> TREE --> SPLIT --> MINIFY_JS
    SPLIT --> MINIFY_CSS
    SPLIT --> IMG_OPT
    MINIFY_JS --> GZIP
    MINIFY_CSS --> GZIP
    IMG_OPT --> CDN
    GZIP --> CDN

小结

  • 代码压缩（Minification）通过空白移除、标识符缩短、常量折叠等技术减小代码体积。
  • Terser 压缩率最好，esbuild 速度最快，SWC 在两者之间取得平衡。
  • CSS 压缩使用 cssnano（PostCSS 生态）或 Lightning CSS（Rust 实现）。
  • 资源压缩使用 Gzip/Brotli，建议构建时预压缩以减少服务器 CPU 开销。
  • Brotli 比 Gzip 压缩率高 15-25%，但需要 HTTPS。
  • 完整优化链：Tree-shaking → 代码分割 → 压缩 → Gzip/Brotli → CDN。
