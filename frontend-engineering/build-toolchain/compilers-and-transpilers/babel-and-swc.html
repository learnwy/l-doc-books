Babel 与 SWC

两代 JavaScript 转译器

Babel 和 SWC 代表了 JavaScript 转译器的两个时代。Babel 于 2014 年诞生（最初名为 6to5），用 JavaScript 编写，开创了"插件驱动的代码转换"范式；SWC 于 2019 年发布，用 Rust 编写，在保持功能兼容的同时将转译速度提升了 20 倍以上。两者的设计理念一脉相承，但实现路径截然不同。



Babel 核心架构
Babel 的架构由三个核心组件构成：解析器（Parser）、转换器（Transformer）和生成器（Generator）。


编译流程
Preset 与 Plugin
Babel 的转换能力完全由插件（Plugin）提供。Preset 是一组预配置的插件集合：


{
  "presets": [
    [
      "@babel/preset-env",
      {
        "targets": "> 0.25%, not dead",
        "useBuiltIns": "usage",
        "corejs": "3.36",
        "modules": false
      }
    ],
    [
      "@babel/preset-react",
      {
        "runtime": "automatic"
      }
    ],
    "@babel/preset-typescript"
  ],
  "plugins": [
    ["@babel/plugin-proposal-decorators", { "version": "2023-11" }],
    "@babel/plugin-proposal-explicit-resource-management"
  ]
}




Preset
用途





@babel/preset-env
根据目标环境自动确定所需转换




@babel/preset-react
JSX 转换和 React 优化




@babel/preset-typescript
TypeScript 语法剥离（不做类型检查）




@babel/preset-flow
Flow 类型注解剥离





@babel/preset-env 的工作原理
preset-env 是 Babel 最重要的 Preset。它根据目标环境（browserslist）自动选择需要的转换插件：


// .browserslistrc
// > 0.25%
// not dead
// not ie 11

// Babel 会自动确定：
// - 箭头函数：不需要转换（所有目标都支持）
// - Optional Chaining：需要转换（部分目标不支持）
// - Class Fields：需要转换
自定义 Babel 插件
export default function myBabelPlugin({ types: t }) {
  return {
    visitor: {
      CallExpression(path) {
        if (path.node.callee.type === 'MemberExpression' && path.node.callee.object.name === 'console') {
          if (process.env.NODE_ENV === 'production') {
            path.remove();
          }
        }
      },
    },
  };
}


SWC 核心特性
SWC（Speedy Web Compiler）用 Rust 编写，提供了与 Babel 功能相当但速度快得多的转译能力。

SWC 的 API 使用
import { transformSync, transformFileSync } from '@swc/core';

const output = transformSync(
  `
  const greet = (name: string): string => {
    return \`Hello, \${name}!\`;
  };
`,
  {
    jsc: {
      parser: { syntax: 'typescript' },
      target: 'es5',
    },
    sourceMaps: true,
  },
);

console.log(output.code);
console.log(output.map);
SWC 在打包器中的集成
// Webpack + swc-loader
export default {
  module: {
    rules: [
      {
        test: /\.tsx?$/,
        exclude: /node_modules/,
        use: {
          loader: 'swc-loader',
          options: {
            jsc: {
              parser: {
                syntax: 'typescript',
                tsx: true,
              },
              transform: {
                react: { runtime: 'automatic' },
              },
            },
          },
        },
      },
    ],
  },
};
// Vite + @vitejs/plugin-react-swc
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react-swc';

export default defineConfig({
  plugins: [
    react({
      tsDecorators: true,
    }),
  ],
});

两者的互补使用
在某些项目中，可以同时使用 Babel 和 SWC 各取所长：


// 使用 SWC 做主要转译（速度快）
// 使用 Babel 做特殊的自定义转换

export default {
  module: {
    rules: [
      {
        test: /\.tsx?$/,
        exclude: /node_modules/,
        use: [
          {
            loader: 'babel-loader',
            options: {
              plugins: ['my-custom-babel-plugin'],
            },
          },
          {
            loader: 'swc-loader',
            options: {
              jsc: {
                parser: { syntax: 'typescript', tsx: true },
                target: 'es2020',
              },
            },
          },
        ],
      },
    ],
  },
};


Polyfill 策略
Babel 的 Polyfill 方案
{
  "presets": [
    [
      "@babel/preset-env",
      {
        "useBuiltIns": "usage",
        "corejs": "3.36"
      }
    ]
  ]
}




useBuiltIns 值
行为





false
不自动添加 polyfill




entry
在入口处展开为所有目标环境需要的 polyfill




usage
按需导入实际使用的 API 的 polyfill





SWC 的 Polyfill 方案
SWC 通过 swc-plugin-transform-imports 和外部 polyfill 库实现类似功能：


{
  "jsc": {
    "target": "es5"
  },
  "env": {
    "targets": "> 0.25%, not dead",
    "mode": "usage",
    "coreJs": "3.36"
  }
}


小结
    

  • Babel 用 JavaScript 编写，开创了插件驱动的代码转换范式，生态极其丰富。
    • 

  • SWC 用 Rust 编写，速度是 Babel 的 20 倍以上，已被 Vite、Next.js 等广泛采用。
    • 

  • preset-env 根据 browserslist 自动确定需要的转换，避免不必要的代码膨胀。
    • 

  • 选型建议：需要自定义 Babel 插件时用 Babel，否则推荐 SWC。
    • 

  • Polyfill 策略（usage vs entry）直接影响产物体积。
    •
