tsc 与 TypeScript 编译

TypeScript 编译器的角色

TypeScript 编译器（tsc）是 TypeScript 生态的核心。它承担着两个截然不同但同等重要的职责：类型检查和代码生成。在现代构建工具链中，这两个职责往往被分离到不同的工具中——tsc 专注于类型检查，而 SWC 或 esbuild 负责代码生成——但理解 tsc 的完整编译流程仍然是掌握 TypeScript 的基础。



tsconfig.json 核心配置
tsconfig.json 是 TypeScript 项目的配置中心。理解其中的关键选项对于正确配置构建工具链至关重要。


编译目标与模块系统
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2020", "DOM", "DOM.Iterable"],
    "esModuleInterop": true,
    "allowSyntheticDefaultImports": true,
    "isolatedModules": true
  }
}

moduleResolution: "bundler" 是 TypeScript 5.0 引入的新模式，它匹配现代打包器的解析行为——支持 package.json 的 exports 字段、允许省略扩展名等。


严格模式配置
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "noImplicitOverride": true,
    "exactOptionalPropertyTypes": true,
    "noFallthroughCasesInSwitch": true
  }
}

路径映射与别名
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "@components/*": ["src/components/*"],
      "@hooks/*": ["src/hooks/*"],
      "@utils/*": ["src/utils/*"],
      "@types/*": ["src/types/*"]
    }
  }
}
路径映射只影响 tsc 的类型解析，不影响运行时。打包器需要配置对应的 alias 来实现实际的路径解析。


声明文件生成
{
  "compilerOptions": {
    "declaration": true,
    "declarationMap": true,
    "declarationDir": "dist/types",
    "emitDeclarationOnly": true
  }
}


仅类型检查模式
在现代构建流水线中，tsc 通常以"仅类型检查"模式运行，不负责实际的代码生成：

isolatedModules 的重要性
当使用非 tsc 转译器（如 SWC、esbuild）时，isolatedModules: true 是必须的。因为这些工具逐文件转译，无法获取跨文件的类型信息。


// 以下写法在 isolatedModules 下会报错
// 因为转译器无法判断 MyType 是类型还是值
export { MyType } from './types';

// 正确写法 - 明确标记为类型导出
export type { MyType } from './types';

// 或使用 import type
import type { MyType } from './types';
// const enum 在 isolatedModules 下也有限制
// 因为内联替换需要跨文件信息
const enum Direction {
  Up,
  Down,
}

// 应改为普通 enum
enum Direction {
  Up,
  Down,
}


项目引用（Project References）
对于 Monorepo 或大型项目，TypeScript 的项目引用可以实现增量编译和并行构建：


// tsconfig.json (根目录)
{
  "files": [],
  "references": [{ "path": "./packages/core" }, { "path": "./packages/ui" }, { "path": "./packages/utils" }]
}
// packages/core/tsconfig.json
{
  "compilerOptions": {
    "composite": true,
    "declaration": true,
    "declarationMap": true,
    "outDir": "dist"
  },
  "references": [{ "path": "../utils" }]
}
# 增量构建所有项目
tsc --build

# 并行构建
tsc --build --verbose


tsc 与打包器的协作模式
模式一：tsc 全权负责（传统方式）
tsc && node dist/index.js
适用于简单的 Node.js 项目，不需要打包。


模式二：tsc 类型检查 + SWC 转译（推荐）
{
  "scripts": {
    "typecheck": "tsc --noEmit",
    "build": "rsbuild build",
    "dev": "rsbuild dev"
  }
}
模式三：tsc 生成声明文件 + 打包器构建
{
  "scripts": {
    "build:types": "tsc --emitDeclarationOnly",
    "build:js": "rollup -c",
    "build": "npm run build:types && npm run build:js"
  }
}


小结
    

  • tsc 承担类型检查和代码生成两大职责，现代工具链通常分离这两个职责。
    • 

  • moduleResolution: "bundler" 匹配现代打包器的模块解析行为。
    • 

  • isolatedModules: true 在使用非 tsc 转译器时是必须的。
    • 

  • 项目引用（Project References）支持 Monorepo 的增量编译。
    • 

  • 推荐模式：tsc --noEmit 做类型检查，SWC/esbuild 做代码转译。
