CSS-in-JS 权衡

问题背景

CSS-in-JS 将样式逻辑嵌入 JavaScript，享受作用域隔离、动态样式和类型安全等便利。但它也带来了运行时开销、包体积增加和 SSR 复杂性。随着零运行时方案的兴起和 React Server Components 的普及，CSS-in-JS 的格局正在发生重大变化。

运行时方案的工作原理
// 运行时：styled-components
import styled from 'styled-components';

const Box = styled.div<{ $isActive: boolean }>`
  background: ${({ $isActive }) => ($isActive ? 'blue' : 'gray')};
  padding: 1rem;
`;
// 运行时：JS → 计算样式 → 生成 CSS → 注入 <style>
零运行时方案的工作原理
// 零运行时：Vanilla Extract
// Button.css.ts — 构建时编译
import { style } from '@vanilla-extract/css';

export const box = style({
  padding: '1rem',
});

export const active = style({
  background: 'blue',
});

export const inactive = style({
  background: 'gray',
});
// 编译后输出：静态 .css 文件


Bundle Size 影响
对于性能敏感的场景（移动端、低带宽），运行时方案的额外 JS 可能显著影响 TTI（Time to Interactive）。




SSR 挑战
运行时方案的 SSR 问题
// styled-components SSR 配置
import { ServerStyleSheet } from 'styled-components';

const sheet = new ServerStyleSheet();
try {
  const html = renderToString(sheet.collectStyles(<App />));
  const styleTags = sheet.getStyleTags();
  // 需要将 styleTags 注入到 HTML <head> 中
} finally {
  sheet.seal();
}

零运行时方案无 SSR 问题
// Vanilla Extract：无需额外 SSR 配置
// CSS 在构建时已经是静态文件，直接通过 <link> 加载
import { box } from './styles.css';

function Component() {
  return <div className={box}>内容</div>;
}

迁移策略
从运行时 CSS-in-JS 迁移到零运行时方案的渐进路径：


    

  1. 新代码使用零运行时方案——不增加运行时负担
    2. 

  2. 共存阶段——两种方案并存，通过 lint 规则引导
    3. 

  3. 逐步迁移——按模块替换旧的运行时样式
    4. 

  4. 移除运行时——卸载 styled-components/Emotion
    5. 





如何选择


小结
    

  • 运行时 CSS-in-JS 动态样式最灵活，但有 JS 开销和 SSR 复杂性
    • 

  • 零运行时方案 在构建时提取静态 CSS，无运行时开销，兼容 RSC
    • 

  • SSR 中运行时方案需要 ServerStyleSheet 等额外配置，零运行时无需处理
    • 

  • React Server Components 的普及正在推动行业向零运行时方案迁移
    • 

  • Bundle size：运行时方案增加 8-16kB JS，零运行时接近零
    • 

  • 迁移策略：新代码用零运行时，渐进替换旧代码
    •
