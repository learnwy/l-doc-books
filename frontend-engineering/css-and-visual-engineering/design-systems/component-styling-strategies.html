组件样式策略

问题背景

React 组件的样式方案百花齐放，从传统的 CSS Modules 到 CSS-in-JS（styled-components）再到零运行时方案（Vanilla Extract）。每种方案在开发体验、性能、类型安全和可维护性上各有取舍。选择适合项目的方案需要理解它们的核心差异。

CSS Modules
CSS Modules 在构建时将类名哈希化，实现自动作用域隔离：


/* Button.module.css */
.button {
  padding: 0.75rem 1.5rem;
  border-radius: 6px;
  font-weight: 600;
  cursor: pointer;
  transition: background 0.2s ease;
}

.primary {
  background: var(--color-primary);
  color: white;
}

.secondary {
  background: transparent;
  border: 1px solid var(--color-border);
  color: var(--color-text);
}
import styles from './Button.module.css';

interface ButtonProps {
  variant?: 'primary' | 'secondary';
  children: React.ReactNode;
}

function Button({ variant = 'primary', children }: ButtonProps) {
  return (
    <button className={`${styles.button} ${styles[variant]}`}>
      {children}
    </button>
  );
}

styled-components
styled-components 用 Tagged Template Literals 将样式与组件绑定：


import styled from 'styled-components';

interface ButtonProps {
  $variant?: 'primary' | 'secondary';
  $size?: 'sm' | 'md' | 'lg';
}

const Button = styled.button<ButtonProps>`
  padding: ${({ $size }) => {
    const sizes = { sm: '0.5rem 1rem', md: '0.75rem 1.5rem', lg: '1rem 2rem' };
    return sizes[$size || 'md'];
  }};
  border-radius: 6px;
  font-weight: 600;
  cursor: pointer;
  transition: all 0.2s ease;

  ${({ $variant }) =>
    $variant === 'primary'
      ? `
    background: var(--color-primary);
    color: white;
  `
      : `
    background: transparent;
    border: 1px solid var(--color-border);
    color: var(--color-text);
  `}

  &:hover {
    opacity: 0.9;
  }
`;




优势
劣势





动态样式极其灵活
运行时性能开销




自动作用域

SSR 需要额外配置

Vanilla Extract
Vanilla Extract 是零运行时的 CSS-in-TypeScript 方案，编写时是 TypeScript，输出是静态 CSS：


// Button.css.ts
import { style, styleVariants } from '@vanilla-extract/css';
import { vars } from './theme.css';

export const button = style({
  padding: '0.75rem 1.5rem',
  borderRadius: 6,
  fontWeight: 600,
  cursor: 'pointer',
  transition: 'all 0.2s ease',
  ':hover': {
    opacity: 0.9,
  },
});

export const variants = styleVariants({
  primary: {
    background: vars.color.primary,
    color: 'white',
  },
  secondary: {
    background: 'transparent',
    border: `1px solid ${vars.color.border}`,
    color: vars.color.text,
  },
});
// Button.tsx
import { button, variants } from './Button.css';

interface ButtonProps {
  variant?: keyof typeof variants;
  children: React.ReactNode;
}

function Button({ variant = 'primary', children }: ButtonProps) {
  return (
    <button className={`${button} ${variants[variant]}`}>
      {children}
    </button>
  );
}

混合策略
实际项目中常常混合使用多种方案：


// 使用 CSS Modules 做基础布局
import layout from './Layout.module.css';

// 使用 Tailwind 做工具类
<div className={`${layout.container} flex items-center gap-4`}>

// 使用 CSS 变量做主题
<div style={{ '--card-bg': token.bgSubtle } as React.CSSProperties}>


提示： 混合策略的关键是明确每种方案的职责边界——全局令牌用 CSS 变量，组件作用域用 CSS Modules 或 Vanilla Extract，快速原型用 Tailwind。






小结
    

  • CSS Modules 零开销、易迁移，适合不需要复杂动态样式的项目
    • 

  • styled-components 动态样式最强，但有运行时开销和 SSR 复杂性
    • 

  • Vanilla Extract 零运行时 + 完整类型安全，是类型安全偏好团队的首选
    • 

  • Tailwind 原子化思路，快速开发，详见专门章节
    • 

  • 选择方案时重点考量：运行时性能、类型安全、SSR 支持和团队熟悉度
    • 

  • 大型项目常采用混合策略，明确每种方案的职责边界
    •
