Clean Architecture 前端实践

概述

Clean Architecture（整洁架构）由 Robert C. Martin 提出，其核心原则是依赖方向单一指向内层——外层可以依赖内层，内层绝不依赖外层。将这一思想应用于前端，意味着业务逻辑（Domain）完全独立于 UI 框架（React/Vue）、状态管理库（Zustand/Redux）和外部服务（API/Storage）。当你需要从 React 迁移到 Vue，或从 REST 切换到 GraphQL 时，核心业务代码无需任何修改。

核心概念

同心圆分层模型

依赖规则：箭头只能从外向内指。React 组件依赖 ViewModel，ViewModel 依赖 Use Case，Use Case 依赖 Entity。反之则通过接口（依赖反转）实现。

依赖反转在前端的实现
// domain/repositories/OrderRepository.ts - 接口定义（内层）
export interface OrderRepository {
  findById(id: string): Promise<Order>;
  findByUser(userId: string): Promise<Order[]>;
  save(order: Order): Promise<void>;
}

// infrastructure/repositories/HttpOrderRepository.ts - 实现（外层）
import type { OrderRepository } from '@/domain/repositories/OrderRepository';
import { Order } from '@/domain/entities/Order';
import { apiClient } from '@/infrastructure/api/client';

export class HttpOrderRepository implements OrderRepository {
  async findById(id: string): Promise<Order> {
    const data = await apiClient.get(`/orders/${id}`);
    return Order.fromDTO(data);
  }

  async findByUser(userId: string): Promise<Order[]> {
    const data = await apiClient.get(`/users/${userId}/orders`);
    return data.map(Order.fromDTO);
  }

  async save(order: Order): Promise<void> {
    await apiClient.post('/orders', order.toDTO());
  }
}

Use Case 实现
// application/use-cases/CreateOrderUseCase.ts
import { Order } from '@/domain/entities/Order';
import type { OrderRepository } from '@/domain/repositories/OrderRepository';
import type { UserRepository } from '@/domain/repositories/UserRepository';
import { PricingService } from '@/domain/services/PricingService';
import type { CreateOrderDTO } from '../dto/CreateOrderDTO';

export class CreateOrderUseCase {
  constructor(
    private orderRepo: OrderRepository,
    private userRepo: UserRepository,
    private pricing: PricingService,
  ) {}

  async execute(dto: CreateOrderDTO): Promise<Order> {
    const user = await this.userRepo.findById(dto.userId);
    if (!user.isActive) {
      throw new Error('User account is inactive');
    }

    const totalPrice = this.pricing.calculateTotal(dto.items, user.tier);
    const order = Order.create({
      userId: dto.userId,
      items: dto.items,
      totalPrice,
      shippingAddress: dto.address,
    });

    await this.orderRepo.save(order);
    return order;
  }
}
依赖注入与 React Hooks 集成
// infrastructure/di/container.ts - 依赖容器
import { HttpOrderRepository } from '../repositories/HttpOrderRepository';
import { HttpUserRepository } from '../repositories/HttpUserRepository';
import { PricingService } from '@/domain/services/PricingService';
import { CreateOrderUseCase } from '@/application/use-cases/CreateOrderUseCase';

// 简单工厂模式（适合中小项目）
export const container = {
  orderRepository: new HttpOrderRepository(),
  userRepository: new HttpUserRepository(),
  pricingService: new PricingService(),

  get createOrderUseCase() {
    return new CreateOrderUseCase(this.orderRepository, this.userRepository, this.pricingService);
  },
};

// presentation/hooks/useCreateOrder.ts
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { container } from '@/infrastructure/di/container';

export function useCreateOrder() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: (dto: CreateOrderDTO) => container.createOrderUseCase.execute(dto),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['orders'] });
    },
  });
}

测试策略的收益
Clean Architecture 让测试变得自然：


// 单元测试 Use Case - 无需启动 React/浏览器
import { CreateOrderUseCase } from './CreateOrderUseCase';
import { InMemoryOrderRepository } from '@/test/mocks/InMemoryOrderRepository';
import { InMemoryUserRepository } from '@/test/mocks/InMemoryUserRepository';

describe('CreateOrderUseCase', () => {
  it('should create order for active user', async () => {
    const orderRepo = new InMemoryOrderRepository();
    const userRepo = new InMemoryUserRepository();
    userRepo.addUser({ id: '1', isActive: true, tier: 'gold' });

    const useCase = new CreateOrderUseCase(orderRepo, userRepo, new PricingService());
    const order = await useCase.execute({
      userId: '1',
      items: [{ productId: 'p1', quantity: 2 }],
      address: { city: 'Beijing' },
    });

    expect(order.totalPrice).toBeGreaterThan(0);
    expect(orderRepo.orders).toHaveLength(1);
  });
});
前端适配的务实简化
完全的 Clean Architecture 在前端会引入过多抽象。务实建议：


    

  1. 小项目跳过 Use Case 层：直接在 Hooks 中调用 Repository，当逻辑变复杂时再提取。
    2. 

  2. 用函数替代类：TypeScript 中函数式风格更常见，Use Case 可以是函数而非类。
    3. 

  3. Repository 接口按需定义：不需要为每个 Entity 都定义 Repository，仅在有多种实现（测试 mock、缓存代理）时才抽象。
    4. 

  4. Domain 层保持纯净：这是最重要的原则。即使其他层简化，Domain 层绝不依赖框架代码。
    5.

总结
Clean Architecture 在前端的核心价值不是文件夹结构本身，而是它强制建立的思维模式：将业务逻辑与技术实现分离。当团队建立了这种思维模式后，即使在不严格遵循四层结构的项目中，也能自然地写出低耦合、易测试的代码。对于中大型前端项目，建议至少实现 Domain 层的独立——让核心业务规则不依赖任何框架或库。这个投入的回报是：业务逻辑的单元测试可以在毫秒级完成、技术栈迁移时核心代码零修改、新团队成员通过阅读 Domain 层即可理解业务全貌。
