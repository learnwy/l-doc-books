模块化分层策略

概述

模块化分层是将大型前端代码库拆分为独立、可组合模块的实践。不同于 FSD 的标准化规范或 Clean Architecture 的理论框架，本文聚焦实际项目中的模块边界设计——如何利用 monorepo 工具链、TypeScript 路径映射和构建工具能力，构建从小型项目平滑扩展到大型平台的渐进式分层方案。核心目标是：每个模块有明确的职责边界、最小的外部依赖、独立的测试和构建能力。

核心概念

模块化的三个维度

垂直切片：按业务功能划分模块。每个功能是一个独立单元，包含自己的 UI、逻辑和数据层。


水平分层：在垂直切片内部，按技术职责分层。UI 组件、业务逻辑、数据访问各有清晰边界。


包边界：使用 monorepo 的 package 机制或 TypeScript 路径别名，将模块之间的依赖关系显式化。

实战指南
渐进式分层：从简单到复杂
阶段 1：单体应用内部分层（1-3 人团队）


src/
├── modules/
│   ├── auth/
│   │   ├── components/     # 仅 auth 相关的 UI
│   │   ├── hooks/          # auth 状态和逻辑
│   │   ├── api/            # auth API 调用
│   │   ├── types.ts        # auth 类型定义
│   │   └── index.ts        # Public API
│   ├── products/
│   │   ├── components/
│   │   ├── hooks/
│   │   ├── api/
│   │   └── index.ts
│   └── cart/
│       ├── components/
│       ├── hooks/
│       ├── api/
│       └── index.ts
├── shared/                  # 跨模块共享
│   ├── ui/                  # 设计系统组件
│   ├── utils/               # 工具函数
│   └── api/                 # API 客户端基础
└── app/                     # 应用入口和路由
    ├── routes.tsx
    └── providers.tsx
阶段 2：Monorepo 包隔离（3-10 人团队）


packages/
├── shared/
│   ├── ui/                  # @app/ui
│   │   ├── src/
│   │   ├── package.json
│   │   └── tsconfig.json
│   ├── utils/               # @app/utils
│   └── api-client/          # @app/api-client
├── features/
│   ├── auth/                # @app/feature-auth
│   │   ├── src/
│   │   ├── package.json     # dependencies: @app/ui, @app/api-client
│   │   └── tsconfig.json
│   ├── products/            # @app/feature-products
│   └── cart/                # @app/feature-cart
└── apps/
    ├── web/                 # 主 Web 应用
    │   ├── src/
    │   └── package.json     # 依赖所有 feature packages
    └── admin/               # 管理后台（复用部分 features）
Monorepo 工具链配置
// pnpm-workspace.yaml
packages:
  - 'packages/shared/*'
  - 'packages/features/*'
  - 'apps/*'
// packages/features/auth/package.json
{
  "name": "@app/feature-auth",
  "version": "0.0.0",
  "private": true,
  "main": "./src/index.ts",
  "types": "./src/index.ts",
  "dependencies": {
    "@app/ui": "workspace:*",
    "@app/api-client": "workspace:*",
    "@app/utils": "workspace:*"
  }
}
// turbo.json - Turborepo 构建编排
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"]
    },
    "test": {
      "dependsOn": ["^build"]
    },
    "lint": {},
    "typecheck": {
      "dependsOn": ["^build"]
    }
  }
}
TypeScript 项目引用
// tsconfig.json (root)
{
  "references": [
    { "path": "./packages/shared/ui" },
    { "path": "./packages/shared/utils" },
    { "path": "./packages/features/auth" },
    { "path": "./packages/features/products" }
  ]
}

// packages/features/auth/tsconfig.json
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "composite": true,
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "references": [
    { "path": "../shared/ui" },
    { "path": "../shared/api-client" }
  ],
  "include": ["src/**/*"]
}
ESLint 边界规则
// .eslintrc.js
module.exports = {
  rules: {
    'import/no-restricted-paths': [
      'error',
      {
        zones: [
          // features 不能导入其他 features
          {
            target: './packages/features/auth/src',
            from: './packages/features/products/src',
            message: 'Auth feature cannot import from Products feature',
          },
          // shared 不能导入 features
          {
            target: './packages/shared',
            from: './packages/features',
            message: 'Shared packages cannot depend on feature packages',
          },
        ],
      },
    ],
  },
};
最佳实践
模块接口设计
每个模块的 index.ts 是其唯一的对外接口。设计原则：


// packages/features/auth/src/index.ts

// ✅ 导出组件
export { LoginForm } from './components/LoginForm';
export { AuthGuard } from './components/AuthGuard';

// ✅ 导出 Hooks
export { useAuth } from './hooks/useAuth';
export { useCurrentUser } from './hooks/useCurrentUser';

// ✅ 导出类型
export type { User, AuthState, LoginCredentials } from './types';

// ❌ 不导出内部实现细节
// export { authApi } from './api/authApi';
// export { tokenStorage } from './lib/tokenStorage';
依赖方向管理
规则：依赖图必须是 DAG（有向无环图）。如果两个 feature 需要共享逻辑，提升到 shared 层而非直接互相依赖。


渐进式迁移 Checklist
    

  1. 识别模块候选：按业务功能（非技术类型）划分模块边界
    2. 

  2. 创建 barrel exports：为每个模块添加 index.ts，收敛对外接口
    3. 

  3. 添加导入规则：ESLint 或 TypeScript paths 限制跨模块直接导入
    4. 

  4. 提取 shared：将跨模块复用的代码移入 shared 包
    5. 

  5. 独立 package.json：当模块足够独立时，升级为 monorepo package
    6. 

  6. 独立 CI job：按模块变更触发对应的 test/lint/build
    7.

总结
模块化分层的本质是"用构建系统的约束力替代人的纪律性"。小团队可以从目录约定开始，随着项目增长逐步引入 TypeScript 项目引用、ESLint 边界规则，最终演进为完整的 monorepo package 隔离。关键原则是：每次添加约束都应该解决一个已经存在的问题（而非预防假想问题），保持架构复杂度与项目规模匹配。过早引入 monorepo 对 3 人团队是负担，但当团队扩展到 10 人以上时，缺乏包隔离的单体应用将快速陷入"大泥球"困境。
