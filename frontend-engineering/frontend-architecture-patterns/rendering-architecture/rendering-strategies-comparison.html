渲染策略对比与选型

概述

现代前端应用的渲染策略不再是一个全局二选一的决定。2026 年的元框架（Next.js 16、Astro 6、SvelteKit 2）允许开发者在同一项目中按路由选择不同的渲染模式。理解每种策略的工作原理、性能特征和适用场景，是做出正确架构决策的前提。本文系统对比 CSR、SSR、SSG、ISR 四种核心渲染模式，并提供基于页面类型的混合策略决策框架。

核心概念

四种渲染模式的工作原理

CSR（Client-Side Rendering） 服务器返回一个空白 HTML 壳和 JavaScript 打包文件，所有页面内容由浏览器执行 JS 后动态生成。典型实现包括 Create React App 和 Vite + React。


SSR（Server-Side Rendering） 每次请求到达时，服务器实时执行 React/Vue 组件，生成完整 HTML 返回给浏览器。客户端再通过 hydration 附加事件监听器。


SSG（Static Site Generation） 在构建阶段预渲染所有页面为静态 HTML 文件，部署到 CDN 后无需服务器计算。适合内容变化频率低的页面。


ISR（Incremental Static Regeneration） 结合 SSG 的 CDN 性能优势和 SSR 的数据新鲜度。首次访问返回缓存的静态 HTML，同时在后台触发重新生成。

流式 SSR 与 Partial Prerendering
Next.js 16 引入的 Partial Prerendering (PPR) 代表了 SSR 的最新演进。PPR 将页面分为静态壳（从 CDN 即时响应）和动态区域（流式传输填充），兼顾了 SSG 的速度和 SSR 的动态能力：


// Next.js 16 - Partial Prerendering
// 静态壳即时响应，动态区域流式填充
import { Suspense } from 'react';
import { ProductInfo } from './ProductInfo'; // Server Component
import { PersonalizedRecommendations } from './Recommendations';

export default function ProductPage({ params }: { params: { id: string } }) {
  return (
    <main>
      {/* 静态壳 - 从 CDN 即时响应 */}
      <header>Product Details</header>

      {/* 动态区域 - 流式传输 */}
      <Suspense fallback={<ProductSkeleton />}>
        <ProductInfo id={params.id} />
      </Suspense>

      {/* 个性化区域 - 延迟流式 */}
      <Suspense fallback={<RecommendationsSkeleton />}>
        <PersonalizedRecommendations userId={params.id} />
      </Suspense>
    </main>
  );
}
实战指南
基于页面类型的策略选择
营销/着陆页 → SSG。内容由市场团队在 CMS 中维护，更新频率以天计。纯静态部署到 CDN，Lighthouse 分数稳定 95+。


电商产品页 → ISR (revalidate: 60s)。产品信息更新频率适中，库存状态可通过客户端 API 实时获取。


用户仪表盘 → CSR。完全个性化的数据，不需要 SEO，交互密集。认证后加载。


搜索结果页 → SSR with Streaming。每次请求数据不同，需要 SEO 收录，流式传输避免长时间白屏。


博客/文档 → SSG + Islands。内容几乎不变，局部交互（搜索框、代码复制）通过 Islands 注入。

最佳实践
混合策略的黄金法则
    

  1. 默认静态，按需动态：项目中 80% 的页面通常适合 SSG/ISR，仅将真正需要实时数据的页面标记为 SSR。
    

    2. 

  2. 数据新鲜度分层：在同一页面中将静态内容和动态内容分离。产品描述用 ISR (revalidate: 3600)，库存状态用客户端 fetch。
    

    3. 

  3. 避免全局 SSR：SSR 意味着每次请求都消耗服务器资源。对于高流量站点，这直接转化为服务器成本。
    

    4. 

  4. SEO 需求明确化：如果页面不需要搜索引擎索引（如管理后台），不需要 SSR。CSR 的 TTFB 反而更快。
    

    5. 

  5. CDN 友好性优先：SSG 和 ISR 的页面可以直接缓存在边缘节点。设计 cache key 时考虑 URL 参数和 cookie 的影响。
    

    6.

总结
渲染策略选型的核心原则是「数据特征决定渲染模式」：静态内容用 SSG，低频更新用 ISR，实时个性化用 SSR，纯交互用 CSR。2026 年的最佳实践是混合渲染——在同一项目中按路由和数据特征组合多种策略，并通过流式传输和 Partial Prerendering 消除策略间的性能断层。选择渲染策略时，始终从 Core Web Vitals 目标值倒推，而非从技术偏好出发。
