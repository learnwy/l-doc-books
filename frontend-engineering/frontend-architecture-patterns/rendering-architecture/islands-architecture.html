Islands Architecture 实践

概述

Islands Architecture（岛屿架构）是近年来对内容为主的 Web 站点影响最深远的前端架构模式。其核心思想极为简洁：将页面大部分内容渲染为静态 HTML，仅在需要交互的位置注入独立的 JavaScript "岛屿"。这种选择性水合策略让典型内容站点的 JavaScript 体积从 200KB+ 降至 15KB 以下。Astro 是该架构的标杆实现，2026 年初被 Cloudflare 收购后发布了 Astro 6，引入了 Server Islands 和基于 workerd 的开发服务器。

核心概念

选择性水合 vs 全量水合

传统 SPA 框架（React、Vue）对整个页面进行 hydration——即使页面中 90% 的内容是纯展示性的。Islands Architecture 只对需要交互的组件进行 hydration，其余部分保持为零 JavaScript 的静态 HTML。

Client Islands vs Server Islands
Astro 6 引入了两种岛屿类型：


Client Islands：传统的交互式组件，在浏览器中 hydrate 并响应用户操作。通过 client:* 指令控制加载时机。


Server Islands：在服务器端渲染动态/个性化内容的组件，无需客户端 JavaScript。适用于需要鉴权、数据库访问的场景（用户头像、购物车数量等）。


// Client Island - 需要用户交互
// src/components/SearchWidget.tsx
import { useState } from 'react';

export function SearchWidget() {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState([]);

  const handleSearch = async (e: React.FormEvent) => {
    e.preventDefault();
    const res = await fetch(`/api/search?q=${query}`);
    setResults(await res.json());
  };

  return (
    <form onSubmit={handleSearch}>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      <button type="submit">Search</button>
      <ul>{results.map(r => <li key={r.id}>{r.title}</li>)}</ul>
    </form>
  );
}

// src/pages/blog.astro
import { SearchWidget } from '../components/SearchWidget';
import { UserAvatar } from '../components/UserAvatar';
---
<html>
<body>
  <header>
    <!-- Server Island: 服务端渲染个性化内容，零客户端 JS -->
    <UserAvatar server:defer>
      <p slot="fallback">Loading...</p>
    </UserAvatar>

    <!-- Client Island: 只在可见时加载 -->
    <SearchWidget client:visible />
  </header>

  <!-- 纯静态内容: 零 JavaScript -->
  <main>
    <article>
      <h1>Blog Post Title</h1>
      <p>This content is pure static HTML. No JS shipped.</p>
    </article>
  </main>
</body>
</html>

实战指南
从零搭建 Astro 6 Islands 项目
# 创建 Astro 6 项目
npm create astro@latest my-site -- --template blog
cd my-site

# 添加 React 集成（也可以是 Vue、Svelte、Solid）
npx astro add react

# 添加 Cloudflare 适配器
npx astro add cloudflare
// astro.config.mjs
import { defineConfig } from 'astro/config';
import react from '@astrojs/react';
import cloudflare from '@astrojs/cloudflare';

export default defineConfig({
  output: 'hybrid',
  adapter: cloudflare(),
  integrations: [react()],
  experimental: {
    serverIslands: true, // Astro 6 Server Islands
  },
});
多框架混合使用
Islands Architecture 的独特优势之一是支持在同一页面中混合使用不同 UI 框架：


---
// 同一页面使用 React + Vue + Svelte
import { ReactCounter } from '../components/ReactCounter';
import VueWidget from '../components/VueWidget.vue';
import SvelteChart from '../components/SvelteChart.svelte';
---
<main>
  <ReactCounter client:visible />
  <VueWidget client:idle />
  <SvelteChart client:load />
</main>
这种能力让团队可以渐进式迁移框架——先用 Astro 包裹现有组件作为 Islands，再逐步替换。

Islands 粒度设计原则
    

  1. 最小化原则：一个 Island 应该是最小的可交互单元。不要把整个侧边栏做成一个 Island，只 hydrate 其中需要交互的按钮。
    

    2. 

  2. 状态隔离：每个 Island 应有自己的状态管理。跨 Island 通信使用 nanostores（Astro 推荐的轻量状态库）：
    

    3. 



// src/stores/cart.ts
import { atom, map } from 'nanostores';

export const cartItems = map<Record<string, CartItem>>({});
export const cartCount = atom(0);

export function addToCart(item: CartItem) {
  cartItems.setKey(item.id, item);
  cartCount.set(Object.keys(cartItems.get()).length);
}
    

  1. 渐进增强：Island 加载前页面应该可读可用。搜索表单即使 JS 未加载也应能通过 form action 提交。
    

    2. 

  2. 延迟非关键 Islands：首屏之外的交互组件全部使用 client:visible，将初始 JS 降到最低。

总结
Islands Architecture 的核心价值在于「默认零 JavaScript，按需渐进增强」。对于内容驱动的站点（博客、文档、营销页、电商列表），它提供了目前最优的性能表现——Lighthouse 接近满分、毫秒级 FCP、极低的托管成本。Astro 6 通过 Server Islands 进一步扩展了该模式的适用范围，让个性化内容也能在不增加客户端 JS 的前提下动态渲染。选择 Islands 架构的关键判断标准是：页面中静态内容占比是否超过 60%——如果是，Islands 几乎总是比传统 SPA 更好的选择。
