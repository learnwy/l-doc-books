微前端运行时集成

概述

微前端运行时集成是指多个独立构建的前端应用在浏览器中动态组合为一个统一用户体验的架构模式。与构建时集成（monorepo 共享代码）不同，运行时集成允许各子应用独立开发、独立部署、独立升级。2026 年的主流方案包括 Module Federation（模块级集成）、Single-SPA（应用级集成）和 Web Components（组件级集成），每种方案在隔离度、共享能力和复杂度上各有取舍。

核心概念

三种运行时集成模型

维度 Module Federation Single-SPA Web Components
集成粒度 模块/组件 完整应用 自定义元素
框架依赖 需要构建工具插件 框架无关 浏览器标准
共享依赖 原生支持，版本协商 手动管理 Shadow DOM 隔离
学习曲线 中等 较高 低到中等
运行时开销 低 中等 低
状态共享 简单（共享 React Context） 事件总线/CustomEvent 属性 + 事件
独立部署 ✅ ✅ ✅
TypeScript MF2 原生支持 手动类型包 手动类型定义

// 方案 1: CustomEvent（轻量，框架无关）
// 发布事件
function publishCartUpdate(items: CartItem[]) {
  window.dispatchEvent(
    new CustomEvent('micro:cart-update', {
      detail: { items, timestamp: Date.now() },
    }),
  );
}

// 订阅事件（在 React 子应用中）
function useCartSubscription() {
  const [cartItems, setCartItems] = useState<CartItem[]>([]);

  useEffect(() => {
    const handler = (e: CustomEvent<{ items: CartItem[] }>) => {
      setCartItems(e.detail.items);
    };
    window.addEventListener('micro:cart-update', handler as EventListener);
    return () => window.removeEventListener('micro:cart-update', handler as EventListener);
  }, []);

  return cartItems;
}

错误隔离与容错
// Shell 级别的错误边界 - 子应用崩溃不影响整体
function MicroAppBoundary({ name, children }: { name: string; children: React.ReactNode }) {
  return (
    <ErrorBoundary
      fallback={
        <div className="micro-app-error">
          <p>{name} is temporarily unavailable</p>
          <button onClick={() => window.location.reload()}>Refresh</button>
        </div>
      }
      onError={(error) => {
        // 上报但不阻断
        reportError({ source: name, error });
      }}
    >
      <Suspense fallback={<AppSkeleton name={name} />}>
        {children}
      </Suspense>
    </ErrorBoundary>
  );
}

总结
微前端运行时集成的核心价值是"独立交付"——每个团队可以按自己的节奏发布功能，无需等待其他团队或整体发布窗口。选择具体方案时，Module Federation 适合同构建工具、模块级共享的场景（最常见）；Single-SPA 适合异构框架、应用级隔离的场景；Web Components 适合需要最强隔离且交互简单的场景。无论选择哪种方案，都要重点关注三个运维问题：版本兼容性管理、跨应用错误隔离、共享状态一致性。微前端不是技术挑战，而是组织架构在代码中的映射——只有当团队结构确实需要独立部署时，才值得引入运行时集成的复杂度。
