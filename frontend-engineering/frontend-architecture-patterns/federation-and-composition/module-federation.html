Module Federation 实践

概述

Module Federation 是 Webpack 5 引入的运行时模块共享机制，让独立构建的应用可以在运行时动态加载彼此的模块——无需重新编译消费方。2024 年发布的 Module Federation 2.0 在 2025-2026 年达到生产稳定，增加了 TypeScript 类型自动共享、跨构建工具的统一运行时、manifest 协议和 Side Effect Scanner。@module-federation/enhanced 包支持 Webpack、Rspack、Vite 三大构建工具，其中 Rspack + MF2 组合以 5-10 倍的构建速度提升成为当前最佳实践方案。

核心概念

Module Federation 2.0 核心升级

TypeScript 类型共享：MF 2.0 在构建时自动为暴露的模块生成 .d.ts 文件，消费方在开发时自动获得类型提示，类似 npm link 的体验。


统一运行时：将 Module Federation 的运行时逻辑从 Webpack 中解耦，形成独立的 runtime 层。这让 Rspack、Vite 也能支持 MF，且跨构建工具的应用可以互相消费。


manifest 协议：mf-manifest.json 取代了硬编码的 remoteEntry.js URL，支持版本发现、预加载声明和部署平台集成。


Host 与 Remote 模型
// Remote 应用 - 暴露模块供其他应用使用
// product-app/rspack.config.ts
import { ModuleFederationPlugin } from '@module-federation/enhanced/rspack';

export default {
  plugins: [
    new ModuleFederationPlugin({
      name: 'product',
      filename: 'remoteEntry.js',
      exposes: {
        './ProductList': './src/components/ProductList',
        './ProductDetail': './src/components/ProductDetail',
        './useProduct': './src/hooks/useProduct',
      },
      shared: {
        react: { singleton: true, requiredVersion: '^19.0.0' },
        'react-dom': { singleton: true, requiredVersion: '^19.0.0' },
      },
      // MF 2.0: 自动生成类型
      dts: true,
    }),
  ],
};

// Host 应用 - 消费远程模块
// shell-app/rspack.config.ts
import { ModuleFederationPlugin } from '@module-federation/enhanced/rspack';

export default {
  plugins: [
    new ModuleFederationPlugin({
      name: 'shell',
      remotes: {
        product: 'product@http://localhost:3001/mf-manifest.json',
        cart: 'cart@http://localhost:3002/mf-manifest.json',
      },
      shared: {
        react: { singleton: true, requiredVersion: '^19.0.0' },
        'react-dom': { singleton: true, requiredVersion: '^19.0.0' },
        '@tanstack/react-query': { singleton: true },
      },
    }),
  ],
};
实战指南
Rspack + MF2 完整配置
// rspack.config.ts (Remote)
import { defineConfig } from '@rspack/cli';
import { ModuleFederationPlugin } from '@module-federation/enhanced/rspack';

export default defineConfig({
  output: {
    publicPath: 'auto',
    uniqueName: 'product-app',
  },
  plugins: [
    new ModuleFederationPlugin({
      name: 'product',
      filename: 'remoteEntry.js',
      exposes: {
        './ProductList': './src/components/ProductList.tsx',
        './ProductDetail': './src/pages/ProductDetail.tsx',
      },
      shared: {
        react: { singleton: true, eager: false },
        'react-dom': { singleton: true, eager: false },
        'react-router-dom': { singleton: true },
      },
      dts: {
        generateTypes: true,
        consumeTypes: true,
      },
      runtimePlugins: ['./src/mf-runtime-plugin.ts'],
    }),
  ],
});
动态远程注册
// 运行时动态注册远程应用（无需构建时知道所有远程）
import { init, loadRemote } from '@module-federation/enhanced/runtime';

init({
  name: 'shell',
  remotes: [
    {
      name: 'product',
      entry: 'http://cdn.example.com/product/mf-manifest.json',
    },
  ],
  shared: {
    react: { version: '19.0.0', scope: 'default', lib: () => require('react') },
  },
});

// 动态加载远程组件
const ProductList = React.lazy(async () => {
  const module = await loadRemote<{ default: React.ComponentType }>('product/ProductList');
  return { default: module!.default };
});

function App() {
  return (
    <Suspense fallback={<Loading />}>
      <ProductList />
    </Suspense>
  );
}

错误处理与降级
// 远程加载失败的降级处理
import { ErrorBoundary } from 'react-error-boundary';

function RemoteModuleFallback({ error }: { error: Error }) {
  return (
    <div className="remote-error">
      <p>Module temporarily unavailable</p>
      <button onClick={() => window.location.reload()}>Retry</button>
    </div>
  );
}

function App() {
  return (
    <ErrorBoundary FallbackComponent={RemoteModuleFallback}>
      <Suspense fallback={<Skeleton />}>
        <RemoteProductList />
      </Suspense>
    </ErrorBoundary>
  );
}
何时不该用 Module Federation
    

  • 小团队 (1-2 个) 单一部署：monorepo 的开发体验更好
    • 

  • 原型/MVP 阶段：增加复杂度无收益
    • 

  • 强一致性需求：所有模块必须同版本发布时，MF 的独立部署优势消失
    • 

  • 无 CDN 基础设施：远程模块加载依赖稳定的静态资源托管
    •

总结
Module Federation 2.0 解决了微前端运行时集成的三大痛点：类型安全（dts）、构建工具锁定（统一 runtime）、版本管理（manifest 协议）。对于 3 个以上团队并行开发的大型应用，MF2 + Rspack 的组合提供了独立部署、运行时共享、5-10 倍构建加速的完整方案。但它不是银弹——对于单团队维护的项目，monorepo + Code Splitting 仍然是更简单、更高效的选择。选择 Module Federation 的核心判断标准是：是否有多个团队需要独立发布各自负责的功能模块。
