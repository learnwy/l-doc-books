IndexedDB 基础

核心概念

IndexedDB 是浏览器内置的 NoSQL 数据库——支持结构化存储、数 GB 容量、异步 API 和索引查询。它是离线优先 PWA 的主要数据存储方案：HTTP 响应缓存使用 Cache API，而用户生成的应用数据则使用 IndexedDB。然而，原生 API 存在回调地狱和事务管理复杂的问题，现代开发推荐使用封装库——Dexie.js、idb（Jake Archibald 开发）、PouchDB（内置同步能力），让使用变得简单直观。本节涵盖 IndexedDB 核心概念、与 localStorage 的区别、原生 API 用法、主流封装库、以及数据模式设计。

存储方式 类型 容量 同步/异步 适用场景
localStorage 键值对 5-10 MB 同步 简单标志位、设置项
sessionStorage 键值对 5-10 MB 同步 会话级临时数据
Cookie 键值对 4 KB 同步 认证、小量数据
Cache API HTTP 式 GB 级 异步 HTTP 响应缓存
IndexedDB 对象数据库 GB 级 异步 结构化数据存储
OPFS（私有文件系统） 文件系统 GB 级 异步 文件类数据
WebSQL SQL - - 已废弃

为什么选择 IndexedDB

超越 localStorage 的能力：

  • localStorage：最大 5-10 MB，同步 API，只能存字符串。
  • IndexedDB：数 GB 容量，异步 API，支持结构化对象存储。

超越 Cache API 的能力：

  • Cache API：专门存储 HTTP 请求/响应对。
  • IndexedDB：存储任意结构化对象数据。

典型使用场景：

  • 用户生成内容（笔记、草稿）。
  • 应用数据缓存（离线优先单页应用）。
  • 文件元数据和二进制大对象（Blob）。
  • 同步队列（离线操作排队等待上传）。

原生 IndexedDB API

打开数据库：

const request = indexedDB.open('myDB', 1);

request.onupgradeneeded = (event) => {
  const db = event.target.result;
  const store = db.createObjectStore('tasks', { keyPath: 'id', autoIncrement: true });
  store.createIndex('byStatus', 'status', { unique: false });
};

request.onsuccess = (event) => {
  const db = event.target.result;
  // 使用 db 进行操作
};

request.onerror = (event) => {
  console.error(event.target.error);
};

添加数据：

const tx = db.transaction('tasks', 'readwrite');
const store = tx.objectStore('tasks');
store.add({ title: 'Buy milk', status: 'pending' });

tx.oncomplete = () => console.log('Done');

读取数据：

const tx = db.transaction('tasks', 'readonly');
const store = tx.objectStore('tasks');
const request = store.get(1);

request.onsuccess = (event) => {
  console.log(event.target.result);
};

通过索引查询：

const index = store.index('byStatus');
const request = index.getAll('pending');

原生 API 基于回调和事件驱动，代码冗长且容易出错。

现代封装库

1. idb（Jake Archibald 开发）：

  • 轻量级 Promise 封装。
  • 接近原生 API 的使用方式，学习成本低。
import { openDB } from 'idb';

const db = await openDB('myDB', 1, {
  upgrade(db) {
    const store = db.createObjectStore('tasks', { keyPath: 'id', autoIncrement: true });
    store.createIndex('byStatus', 'status');
  },
});

// 添加数据
await db.add('tasks', { title: 'Buy milk', status: 'pending' });

// 按主键获取
const task = await db.get('tasks', 1);

// 按索引查询
const pending = await db.getAllFromIndex('tasks', 'byStatus', 'pending');

2. Dexie.js：

  • 更高层级的抽象封装。
  • 类似 ORM 的查询 API，支持链式调用。
  • 提供类型安全支持。
import Dexie from 'dexie';

const db = new Dexie('myDB');
db.version(1).stores({
  tasks: '++id, status, createdAt',
});

// 添加
await db.tasks.add({ title: 'Buy milk', status: 'pending' });

// 条件查询
const pending = await db.tasks.where('status').equals('pending').toArray();

// 更新
await db.tasks.update(1, { status: 'done' });

// 删除
await db.tasks.delete(1);

3. PouchDB：

  • 基于 IndexedDB 并内置与 CouchDB 的同步能力。
  • 适合需要实时数据同步的场景。

如何选择：

  • 需要轻量封装：选 idb。
  • 需要类似 ORM 的查询体验：选 Dexie.js。
  • 需要内置数据同步：选 PouchDB。

数据模式设计

对象仓库（Object Store）：

  • 类似关系型数据库中的表。
  • 按主键存储对象。

主键路径（Key Path）：

  • 指定对象中作为主键的属性。
  • 例：{ keyPath: 'id', autoIncrement: true } 表示以 id 字段自增作为主键。

索引（Index）：

  • 为非主键字段创建二级索引，加速查询。
  • 例：store.createIndex('byStatus', 'status') 为 status 字段创建索引。

数据模式迁移：

  • 递增版本号触发 upgradeneeded 事件。
  • 在升级回调中创建或修改对象仓库。
const db = await openDB('myDB', 2, {
  upgrade(db, oldVersion, newVersion, tx) {
    if (oldVersion < 1) {
      const store = db.createObjectStore('tasks', { keyPath: 'id' });
      store.createIndex('byStatus', 'status');
    }
    if (oldVersion < 2) {
      // 迁移到版本 2：新增优先级索引
      const store = tx.objectStore('tasks');
      store.createIndex('byPriority', 'priority');
    }
  },
});

事务机制

所有操作都在事务中执行：

const tx = db.transaction('tasks', 'readwrite');
tx.objectStore('tasks').add({ ... });
tx.objectStore('tasks').add({ ... });
await tx.complete;  // 等待事务提交

事务模式：

  • readonly：只读，不修改数据。
  • readwrite：读写模式。
  • versionchange：数据模式迁移专用。

原子性保证：

  • 事务中的所有操作要么全部成功，要么全部回滚。

跨仓库事务：

const tx = db.transaction(['tasks', 'users'], 'readwrite');
tx.objectStore('tasks').add(...);
tx.objectStore('users').put(...);
await tx.complete;
存储配额
浏览器配额限制：


    

  • 每个源（origin）大约可使用磁盘空间的 50%。
    • 

  • 与 Cache API 共享配额。
    • 



查询存储用量：


const { quota, usage } = await navigator.storage.estimate();
console.log(`已使用: ${usage} / 配额: ${quota}`);
申请持久化存储：


const granted = await navigator.storage.persist();
持久化存储获批后，浏览器在存储压力下不会驱逐该源的数据，适用于关键的离线应用数据。


查询方式
按主键获取：


const task = await db.get('tasks', 1);
获取全部：


const all = await db.getAll('tasks');
范围查询：


const range = IDBKeyRange.bound(1, 10);
const tasks = await db.getAll('tasks', range);
索引查询：


const pending = await db.getAllFromIndex('tasks', 'byStatus', 'pending');
游标遍历（适用于大数据集）：


const tx = db.transaction('tasks');
let cursor = await tx.store.openCursor();
while (cursor) {
  console.log(cursor.value);
  cursor = await cursor.continue();
}
排序
默认排序：按主键排序。


基于索引排序：索引字段自动按值排序，默认升序，可通过游标方向控制降序。


let cursor = await tx.store.index('byStatus').openCursor(null, 'next');
批量操作
高效批量插入：


const tx = db.transaction('tasks', 'readwrite');
for (const task of tasks) {
  tx.store.add(task);
}
await tx.complete;
在单个事务中执行多次操作比每次操作都开启新事务要快得多。


Blob 存储
存储文件或二进制大对象：


await db.add('files', {
  name: 'photo.jpg',
  blob: file, // File 或 Blob 对象
});

const stored = await db.get('files', 1);
const url = URL.createObjectURL(stored.blob);
适用场景：


    

  • 下载的图片缓存（作为 Cache API 的替代方案）。
    • 

  • 用户上传的文件离线存储。
    • 



事件驱动的数据更新
IndexedDB 本身不支持响应式数据监听：数据变更后不会自动通知其他标签页。


解决方案：使用 BroadcastChannel API 手动广播变更事件。


const channel = new BroadcastChannel('tasks');

async function addTask(task) {
  await db.add('tasks', task);
  channel.postMessage({ type: 'task-added', task });
}

// 其他标签页监听
channel.onmessage = (event) => {
  if (event.data.type === 'task-added') {
    refreshUI();
  }
};
多标签页冲突
多个标签页同时访问：IndexedDB 数据库在同源的所有标签页间共享，事务提供隔离。


可能出现竞态条件：标签页 A 读取数据 → 标签页 B 更新数据 → 标签页 A 基于旧数据写入。


解决方案：


    

  • 使用事务内原子更新。
    • 

  • 乐观并发控制（版本号检查）。
    • 



性能优化建议
1. 批量事务：多个操作放入同一事务中执行更快。


2. 合理建索引：索引会减慢写入速度但加快查询；仅为频繁查询的字段建索引。


3. 大数据集使用游标：不要对百万条记录使用 getAll。


4. 重计算移至 Web Worker：避免在主线程处理大量数据阻塞界面。


安全注意事项
同源隔离：每个源拥有独立的数据库，无法跨源访问。


敏感数据处理：不要以明文存储密码或令牌，应使用 SubtleCrypto API 加密后存储。


用户清除：用户可通过浏览器设置清除所有存储数据。非持久化存储在存储压力下可能被浏览器自动清除。


浏览器兼容性
广泛支持：所有现代浏览器均支持 IndexedDB，包括 IE 10 及以上版本。


注意事项：Safari 的存储配额较小；各浏览器的存储策略有所不同。


常见反模式
1. 直接使用原生 API：代码冗长且容易出错，应使用封装库。


2. 不使用事务：导致竞态条件和数据不一致。


3. 创建过多索引：严重拖慢写入性能。


4. 大数据集使用 getAll：可能耗尽内存，应使用游标遍历。


5. 不做数据模式迁移：版本升级时旧数据丢失或结构不兼容。


6. 明文存储敏感数据：浏览器存储默认未加密，需自行加密保护。


实战案例
Slack：使用 IndexedDB 缓存消息记录，支持离线查看最近对话。


Notion：大量使用缓存机制实现离线编辑。


Google Docs 离线模式：存储文档内容和编辑历史。


最佳实践
1. 使用 Dexie.js 或 idb 封装库：避免直接使用原生 API 的复杂性。


2. 规划数据模式版本：提前设计好迁移策略。


3. 合理使用事务：批量操作保证原子性和性能。


4. 谨慎创建索引：仅为高频查询字段建索引。


5. 测试离线场景：验证真实离线环境下的数据读写。


6. 关键数据申请持久化：使用 navigator.storage.persist() 防止浏览器驱逐重要数据。


小结
IndexedDB 是浏览器内置的 NoSQL 数据库——支持数 GB 容量、异步操作、索引查询和结构化对象存储，是离线优先 PWA 的数据基石（Cache API 负责 HTTP 缓存，IndexedDB 负责应用数据）。原生 API 基于回调且冗长，现代开发推荐使用封装库：idb 提供轻量 Promise 封装，Dexie.js 提供类 ORM 查询体验和类型安全支持，PouchDB 内置与 CouchDB 的同步能力。数据模式设计中，对象仓库类似数据表，主键路径指定唯一标识，索引加速非主键查询，版本递增触发迁移。事务保证原子性，支持跨仓库操作。存储配额约为磁盘空间的 50%，通过 navigator.storage.estimate() 检查用量，persist() 防止关键数据被驱逐。查询方式涵盖主键获取、范围查询、索引查询和游标遍历。批量操作应在单个事务中完成。Blob 存储支持文件和二进制数据。通过 BroadcastChannel 实现跨标签页数据变更通知。安全方面需注意同源隔离和敏感数据加密。掌握 IndexedDB 的关键在于：选对封装库、设计好数据模式和迁移策略、合理使用事务和索引、并为关键离线数据申请持久化存储。
