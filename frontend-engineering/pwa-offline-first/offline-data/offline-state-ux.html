离线状态用户体验

核心概念

离线优先不仅仅是技术实现——用户体验同样至关重要。用户在离线时必须明确知道：当前处于离线状态、变更已保存在本地、网络恢复后会自动同步。静默失败（点击"提交"但什么都没发生）会彻底摧毁用户信任。在线状态指示器、乐观 UI、加载与离线的区分、冲突通知、同步状态展示——这些用户体验模式让离线体验优雅而可靠。本节涵盖离线 UX 模式、状态指示器、乐观 UI、冲突体验设计、以及在线检测的微妙之处。

模式 触发时机 用户体验
在线状态指示器 始终可见 顶部横幅或图标
乐观 UI 用户操作时 立即反映变更
待同步标记 操作进入队列 "保存中…"或图标
成功确认 同步完成 "已发送 ✓"轻提示
冲突界面 同步产生冲突 差异对比加合并按钮
重试选项 同步失败 "点击重试"

在线检测

navigator.onLine 属性：

console.log(navigator.onLine); // true 或 false

window.addEventListener('online', () => {
  console.log('已恢复在线');
});

window.addEventListener('offline', () => {
  console.log('已断开网络');
});

重要注意事项：

  • navigator.onLine === true 并不保证能访问互联网。
  • 它仅表示"设备有网络连接"。
  • 用户可能连接了局域网但无法访问外网。

更可靠的检测方式：实际请求服务器健康检查端点。

async function checkOnline() {
  try {
    const res = await fetch('/api/health', { method: 'HEAD', cache: 'no-store' });
    return res.ok;
  } catch {
    return false;
  }
}

在线状态指示器

顶部横幅或状态图标：

function OfflineBanner() {
  const [online, setOnline] = useState(navigator.onLine);

  useEffect(() => {
    const handleOnline = () => setOnline(true);
    const handleOffline = () => setOnline(false);
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);

  if (online) return null;
  return <div className="banner">当前处于离线状态，变更已保存在本地。</div>;
}

注意：不要反复弹出"你已离线"的通知，一次横幅提示就够了。

乐观 UI

立即展示用户操作的结果：

async function addTask(text) {
  const tempTask = { id: 'temp-' + Date.now(), text, status: 'pending' };
  setTasks([tempTask, ...tasks]); // 立即更新界面

  try {
    const real = await fetch('/api/tasks', { method: 'POST', body: text }).then((r) => r.json());
    setTasks((prev) => prev.map((t) => (t.id === tempTask.id ? real : t)));
  } catch (err) {
    setTasks((prev) => prev.map((t) => (t.id === tempTask.id ? { ...t, status: 'failed' } : t)));
  }
}

效果：操作感觉瞬间完成，不需要等待网络响应。

待同步标记与保存指示器

显示每条数据的同步状态：

{
  task.status === 'pending' && <span className="badge">保存中…</span>;
}
{
  task.status === 'synced' && <span className="badge">✓</span>;
}
{
  task.status === 'failed' && <span className="badge">⚠️ 重试</span>;
}

视觉提示：不仅仅是文字，还应结合图标和颜色。活跃同步时可显示加载动画。

成功确认轻提示

同步成功后通知用户：

function showToast(message) {
  // 显示提示并自动消失
}

// 同步成功时
showToast('已同步 ✓');

设计原则：不打断用户操作流程，3-5 秒后自动消失。

冲突体验设计

内联差异对比：

function ConflictView({ local, remote }) {
  return (
    <div className="conflict">
      <h3>检测到冲突</h3>
      <div className="diff">
        <div className="local">
          <h4>你的版本</h4>
          {local.text}
        </div>
        <div className="remote">
          <h4>服务器版本</h4>
          {remote.text}
        </div>
      </div>
      <button onClick={() => keepLocal()}>保留我的</button>
      <button onClick={() => keepRemote()}>使用服务器的</button>
      <button onClick={() => merge()}>手动合并</button>
    </div>
  );
}

适用场景：文档编辑冲突，不需要立即解决的非紧急冲突。

重试选项

同步失败时的界面：

{
  task.status === 'failed' && <button onClick={() => retry(task)}>同步失败，点击重试</button>;
}

让用户保有控制权：自动重试的同时提供手动重试入口。

加载与离线的区分

不要混淆这两种状态：

  • 加载中：有网络连接，正在获取数据。
  • 离线：没有网络连接。

不同的界面反馈：

  • 加载中：显示加载动画（spinner）。
  • 离线：显示离线指示器和缓存提示。

组合展示：

  • "正在加载…"（在线但正在获取数据）。
  • "当前离线，显示的是缓存数据"（无网络）。

缓存数据标识

告知用户数据可能不是最新的：

{
  isOffline && <div className="cached-notice">显示的是 {formatRelative(cachedAt)} 的缓存数据</div>;
}

让用户了解数据的新鲜度。

骨架屏与加载动画

骨架屏（Skeleton Screen）：灰色布局占位符，让用户感知加载更快，是现代推荐方案。

加载动画（Spinner）：简单直接，适合短暂等待。

混合使用：按钮操作用加载动画，内容加载用骨架屏。

空状态处理

离线时的空状态应提供不同文案：

{
  tasks.length === 0 &&
    (isOffline ? <p>当前处于离线状态。新任务将在重新连接后同步。</p> : <p>暂无任务，创建一个吧！</p>);
}

根据上下文提供不同的提示信息。

同步状态详情

为高级用户提供详细信息：

  • 同步队列大小。
  • 上次同步时间。
  • 待同步操作数量。

设置页面：提供"查看同步日志"和"强制同步"选项。

表单数据持久化

长表单内容不因离线或崩溃而丢失：

function FormWithDraft() {
  const [draft, setDraft] = useState(() => JSON.parse(localStorage.getItem('draft') || '{}'));

  useEffect(() => {
    localStorage.setItem('draft', JSON.stringify(draft));
  }, [draft]);

  return <Form value={draft} onChange={setDraft} />;
}

效果：刷新页面或应用崩溃后草稿仍在，给用户安全感。

后台标签页处理

标签页不活跃时：不阻塞同步，Service Worker 仍可在后台工作。

标签页重新激活时刷新数据：

document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'visible') {
    // 标签页重新可见时刷新数据
    syncNow();
  }
});

可达性检测

超越 navigator.onLine 的真实检测：

async function isReachable() {
  try {
    const ctrl = new AbortController();
    setTimeout(() => ctrl.abort(), 3000); // 3 秒超时

    const res = await fetch('/api/ping', {
      method: 'HEAD',
      signal: ctrl.signal,
      cache: 'no-store',
    });
    return res.ok;
  } catch {
    return false;
  }
}

确认服务器真正可达，而非仅仅连接了局域网。

手动离线模式切换

部分应用提供手动离线模式：用户主动控制是否尝试同步，类似飞行模式。

适用场景：高级用户、明确知道自己在无网络环境中工作的情况。

通知体验原则

避免过度打扰：

  1. 不要每次状态变化都提醒"你离线了"——一次就够。
  2. 不要每个同步操作都弹提示——合并展示。
  3. 横幅不要永远挂着——重连后自动消失。

测试离线用户体验

测试方法：使用 DevTools 网络限速切换离线模式、真实飞行模式、慢速 3G 网络。

验证要点：

  • 离线指示器正确显示。
  • 操作数据正确保存到本地。
  • 重连后自动同步。
  • 用户在各环节都能了解当前状态。

无障碍考虑

屏幕阅读器状态播报：

<div role="status" aria-live="polite">
  {isOffline ? '当前处于离线状态' : '在线'}
</div>

不要仅依赖颜色：同时使用图标和文字传达状态。

实战案例

Twitter PWA：发推按钮在离线时仍可用，成功后显示"已发送"确认，或持续显示"发送中…"直到网络恢复。

Notion：提供细微的离线指示器，所有编辑保存在本地，显示"上次同步于 X 分钟前"。

Slack：离线时显示横幅提示，消息进入队列，重连后自动发送。

现代设计趋势

本地优先思维模式：不刻意区分在线和离线状态，本地数据始终是来源，同步在后台静默进行。

"天然可用"体验：用户无需关心网络状态，应用无论如何都能正常工作。

代表产品：Linear、Notion（大部分场景）、Obsidian（默认本地优先）。

常见反模式

1. 静默失败：点击"提交"后什么都没发生——用户困惑不解。

2. 错误的在线指示：navigator.onLine === true 但服务器实际不可达——给出虚假的在线状态。

3. 离线时完全阻断操作：显示"离线无法操作"但不提供任何替代方案。

4. 离线时丢失数据：表单内容在离线后消失。

5. 不区分加载中与离线：用户无法判断是在等待响应还是没有网络。

6. 过度通知："在线了！离线了！又在线了！"——令人烦躁。

最佳实践

1. 始终进行可达性检测：不仅依赖 navigator.onLine。

2. 默认使用乐观 UI：操作结果立即展示。

3. 显示待同步标记：让用户了解当前状态。

4. 持久化表单草稿：给用户安全感和信心。

5. 测试真实离线场景：使用飞行模式和 DevTools 全面测试。

6. 无障碍播报：使用 aria-live 通知屏幕阅读器用户。

小结

离线状态的用户体验与技术实现同等重要——静默失败会摧毁用户信任。在线检测应超越 navigator.onLine，通过实际请求健康检查端点确认可达性。在线状态指示器应克制展示（一次横幅足够），重连后自动消失。乐观 UI 让操作感觉瞬间完成。待同步标记、成功确认、重试选项让用户始终了解数据状态。冲突界面提供差异对比和合并选项。区分加载中与离线状态，展示缓存数据的时效信息。表单草稿持久化防止数据丢失。现代本地优先设计趋势追求"天然可用"——用户无需关心网络状态，应用始终正常工作。
