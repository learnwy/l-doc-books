Part IV · 浏览器与平台 (Browser & Platform)PWA 与离线优先离线数据后台同步

后台同步

核心概念

Background Sync API 允许 PWA 在用户离线时注册同步任务，浏览器在网络恢复后（即使页面已关闭）自动触发 Service Worker 处理这些任务。这意味着用户离线提交表单、发送消息不会丢失——Service Worker 会在后台自动重试直到成功。本节涵盖 Background Sync API 的使用、一次性同步与周期性同步的区别、Workbox BackgroundSyncPlugin 集成、与同步队列的协作，以及各项限制。

类型 触发时机 适用场景
一次性同步（One-off Sync） 网络恢复时 提交待处理的表单
周期性同步（Periodic Sync） 定期触发 每日刷新新闻内容

一次性后台同步

在主线程中注册同步任务：

async function postTask(task) {
  try {
    await fetch('/api/tasks', { method: 'POST', body: JSON.stringify(task) });
  } catch (err) {
    // 网络失败时保存到 IndexedDB
    await db.pending.add(task);
    // 注册后台同步
    const reg = await navigator.serviceWorker.ready;
    await reg.sync.register('sync-tasks');
  }
}

Service Worker 处理同步事件：

self.addEventListener('sync', (event) => {
  if (event.tag === 'sync-tasks') {
    event.waitUntil(syncTasks());
  }
});

async function syncTasks() {
  const pending = await getAllPending();
  for (const task of pending) {
    try {
      await fetch('/api/tasks', { method: 'POST', body: JSON.stringify(task) });
      await deletePending(task.id);
    } catch (err) {
      // 抛出错误让浏览器稍后重试
      throw err;
    }
  }
}

浏览器重试机制：失败后浏览器会在之后自动重试；成功则标记完成。

周期性后台同步

用于定期刷新内容：

// 检查权限并注册
const reg = await navigator.serviceWorker.ready;
const status = await navigator.permissions.query({ name: 'periodic-background-sync' });
if (status.state === 'granted') {
  await reg.periodicSync.register('refresh-news', {
    minInterval: 24 * 60 * 60 * 1000, // 最小间隔 1 天
  });
}

Service Worker 处理周期性同步事件：

self.addEventListener('periodicsync', (event) => {
  if (event.tag === 'refresh-news') {
    event.waitUntil(refreshNews());
  }
});

注意：浏览器根据用户使用频率自行决定实际触发间隔，并非精确按设定时间执行。

Workbox BackgroundSyncPlugin

自动重试失败的 POST 请求：

import { BackgroundSyncPlugin } from 'workbox-background-sync';
import { registerRoute } from 'workbox-routing';
import { NetworkOnly } from 'workbox-strategies';

const bgSync = new BackgroundSyncPlugin('apiQueue', {
  maxRetentionTime: 24 * 60, // 最长保留 24 小时
});

registerRoute(({ url }) => url.pathname.startsWith('/api/'), new NetworkOnly({ plugins: [bgSync] }), 'POST');

效果：POST 请求失败后自动进入队列，网络恢复时自动重试，最长保留 24 小时。Workbox 自动处理队列管理——存储和重试全部自动化。

使用场景

1. 离线提交表单：发推文、发评论、提交帖子——用户离线时写入内容，重新连接后自动提交。

2. 离线编辑文档：类似 Notion 的离线编辑体验，重连后同步变更。

3. 发送分析事件：离线期间产生的埋点事件排队等待，确保数据不丢失。

4. 周期性刷新内容：新闻应用每日获取最新内容、邮箱定期检查新邮件。

浏览器支持
Chrome / Edge：一次性同步和周期性同步均完整支持。周期性同步需要用户已安装 PWA 并有一定使用频率。


Firefox / Safari：目前不支持，需要使用回退方案：


if ('SyncManager' in window) {
  // 使用 Background Sync
} else {
  // 回退方案：监听 online 事件
}
回退方案
不支持 Background Sync 时的替代方案：


window.addEventListener('online', () => {
  syncPending();
});

async function syncPending() {
  const pending = await db.pending.toArray();
  for (const item of pending) {
    try {
      await fetch('/api/...', { ... });
      await db.pending.delete(item.id);
    } catch (err) {
      console.error('同步失败', err);
    }
  }
}
回退方案的局限：仅在页面打开时生效。如果用户关闭页面，则不会触发同步——这是与原生 Background Sync 的主要区别。


限制与约束
1. 有限的保留时间：浏览器可能在一段时间后丢弃待处理任务（Workbox 默认 24 小时）。


2. 触发时机不确定：浏览器自行决定何时触发同步事件。


3. 电量与隐私考虑：浏览器对后台活动较为保守。


4. 浏览器支持不完整：必须提供回退方案。


5. 周期性同步需要用户参与度：浏览器仅为已安装且活跃使用的 PWA 执行周期性同步。


大文件上传场景
离线时保存文件到 IndexedDB，网络恢复后同步上传：


// 保存文件到 IndexedDB
await db.uploads.add({ file: bigFile, status: 'pending' });

// Service Worker 同步处理
self.addEventListener('sync', async (event) => {
  if (event.tag === 'upload') {
    const pending = await getAllPendingUploads();
    for (const upload of pending) {
      const formData = new FormData();
      formData.append('file', upload.file);
      try {
        await fetch('/api/upload', { method: 'POST', body: formData });
        await markComplete(upload.id);
      } catch (err) {
        throw err; // 让浏览器重试
      }
    }
  }
});
与同步队列的协作
同步队列是待处理操作的数据源，Background Sync 负责触发队列的处理流程：


    

  • 同步队列存储在 IndexedDB 中，持久化所有待处理操作。
    • 

  • Background Sync 在网络恢复时触发处理队列的逻辑。
    • 

  • 两者使用同一套逻辑，不要分开实现。
    • 



幂等性要求
重试安全是关键：操作可能被多次重试，服务器端必须保证幂等。


使用 UUID 标识每个操作：


{
  id: crypto.randomUUID(),
  type: 'create_task',
  data: { ... }
}
服务器端处理：检查操作 ID 是否已处理过，跳过重复操作。


同步完成通知
同步成功后可选择通知用户：


self.addEventListener('sync', async (event) => {
  if (event.tag === 'sync-tasks') {
    await syncTasks();

    // 通知用户
    await self.registration.showNotification('同步完成！', {
      body: '你的任务已全部同步到服务器',
      icon: '/icon-192.png',
    });
  }
});
注意：不要过度通知，保持克制。


防重放保护
服务器端防重放：跟踪已处理的操作 ID，拒绝重复提交。对于关键操作（如支付）尤为重要。


测试后台同步
Chrome DevTools 测试方法：在 Application 标签页 → Service Workers → 点击"Sync"按钮手动触发同步事件。

常见反模式
1. 不提供回退方案：Safari 用户静默失败。


2. 操作不保证幂等：重试导致重复数据。


3. 无限重试：浪费资源，应设置保留时间上限。


4. 不显示待同步状态：用户不知道离线变更正在等待同步。


5. 崩溃时丢失同步队列：未将队列持久化到 IndexedDB。


6. 周期性同步频率过高：消耗电量，浏览器可能限制执行。


最佳实践
1. 使用 Workbox BackgroundSyncPlugin：简单可靠，经过充分测试。


2. 将队列持久化到 IndexedDB：确保应用崩溃后数据不丢失。


3. 服务器端保证幂等：使用 UUID 和去重逻辑。


4. 显示待同步状态：让用户知道"正在保存…"、"等待同步"。


5. 同步成功后确认：显示"已发送 ✓"的状态反馈。


6. 测试真实离线场景：使用真实离线加重连环境验证完整流程。


实战案例
Twitter PWA：离线发推文后注册同步任务，重连后自动发布，用户几乎无感知差异。


Linear：离线编辑事项（Issue），重连后自动同步变更。


小结
Background Sync API 让 PWA 在离线时注册同步任务，浏览器在网络恢复后自动触发 Service Worker 处理（即使页面已关闭）。一次性同步通过 reg.sync.register('tag') 注册，Service Worker 监听 sync 事件处理，失败自动重试。周期性同步通过 reg.periodicSync.register() 设置最小间隔，需要 PWA 已安装且用户有使用频率。Workbox BackgroundSyncPlugin 提供开箱即用的 POST 请求自动重试能力。关键实践包括：同步队列持久化到 IndexedDB 防止数据丢失、服务器端保证幂等防止重复操作、提供不支持浏览器的回退方案、向用户展示待同步状态以建立信任。Background Sync 是 PWA 可靠性的关键保障——做对了离线操作不丢失，做不对则用户工作付之东流。
