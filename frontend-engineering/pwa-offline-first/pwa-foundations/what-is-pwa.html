什么是 PWA

核心概念

渐进式 Web 应用（Progressive Web App，简称 PWA）是 Google 在 2015 年提出的工程范式——通过组合 Web 平台的现代能力（Service Worker、Web App Manifest、HTTPS）让 Web 应用获得接近原生应用的体验：可安装到主屏、离线工作、推送通知、后台同步、访问摄像头和文件系统等。它不是一项具体技术，而是一组能力与设计原则的组合。Twitter Lite、Pinterest、Starbucks、Uber、Trivago 都是 PWA 的经典案例——Twitter Lite 将流量减少 70%，同时用户参与度提升 65%。Apple 早期对此持抗拒态度（iOS 12 之前），现已支持大部分 PWA 能力（仅推送通知受限）。本节介绍 PWA 的四大特性、PWA 与原生应用和传统 Web 的对比、核心优势、典型案例及当前局限。

维度 原生应用 传统 Web PWA
安装 应用商店 不可安装 添加到主屏
发现 商店搜索 URL / 搜索引擎 URL + 安装提示
更新 商店更新 自动 自动
离线 是 否 是
推送 是 否 是（iOS 受限）
摄像头 是 有限 是
后台运行 是 否 部分支持
存储 大容量 5MB localStorage 多 GB IndexedDB

PWA 四大特性（FIRE）

Fast（快速）：

  • 快速首次绘制（App Shell 架构）。
  • LCP 控制在 3 秒以内。
  • 乐观 UI（操作即时反馈）。

Installable（可安装）：

  • 添加到主屏幕。
  • 桌面端和移动端均支持。
  • 外观接近原生应用。

Reliable（可靠）：

  • 离线可用。
  • 弱网环境仍可运行。
  • Service Worker 缓存保障。

Engaging（互动）：

  • 推送通知。
  • 后台同步。
  • 重新吸引用户。

或 PRPL 模式：

  • Push 推送关键资源。
  • Render 渲染初始路由。
  • Pre-cache 预缓存其他路由。
  • Lazy-load 按需加载其余内容。

PWA 核心组件

1. HTTPS：

  • Service Worker 的运行前提。
  • 现代安全基线。

2. Web App Manifest（清单文件）：

  • 描述应用的 JSON 文件。
  • 包含 name、icons、display、theme_color 等字段。
  • 让浏览器知道如何安装该应用。

3. Service Worker：

  • 在后台线程运行的 JS 文件。
  • 拦截网络请求。
  • 负责缓存、推送通知和后台同步。

4. App Shell（可选但推荐）：

  • 核心 UI 框架预缓存。
  • 动态内容后续加载。
  • 首次绘制极快。
为什么选择 PWA
1. 更低的获客门槛：


    

  • 不需要通过应用商店安装。
    • 

  • 用户访问 URL 后一键安装。
    • 

  • 减少分发摩擦。
    • 



2. 跨平台通用：


    

  • 一套代码覆盖 iOS、Android、桌面端。
    • 

  • 无需维护多个原生应用。
    • 



3. 更低的分发成本：


    

  • 不用支付 30% 平台抽成。
    • 

  • 无需审核流程。
    • 



4. SEO 友好：


    

  • 本质仍是 Web，可被搜索引擎索引。
    • 

  • 相比原生应用商店更易被发现。
    • 



5. 更小的下载体积：


    

  • 初始大小通常仅几百 KB。
    • 

  • 相比原生应用几十 MB 体积优势明显。
    • 



Twitter Lite 案例
背景：


    

  • 2017 年上线。
    • 

  • 目标新兴市场（网络慢、存储小）。
    • 



策略：


    

  • 以 PWA 形式构建。
    • 

  • 使用 Service Worker 实现离线。
    • 

  • 采用 App Shell 实现快速加载。
    • 



成果：


    

  • 流量节省 70%（对比完整版 Twitter）。
    • 

  • 每会话页面浏览量增 65%。
    • 

  • 发推量增 75%。
    • 

  • 跳出率降 20%。
    • 



启示：


    

  • PWA 在新兴市场极为有效。
    • 

  • 不是替代原生，而是互补。
    • 



Starbucks 案例
背景：


    

  • 2017 年上线 PWA 移动点单。
    • 



策略：


    

  • 功能与原生应用对等。
    • 

  • 但通过 Web 分发。
    • 



成果：


    

  • 日活跃用户翻倍。
    • 

  • 弱网环境功能正常。
    • 



何时使用 PWA
适合 PWA 的信号：


    

  • 需要多平台覆盖。
    • 

  • 面向新兴市场（弱网环境）。
    • 

  • 内容为主（新闻、电商、媒体）。
    • 

  • 不需要深度原生 API（AR、系统底层访问）。
    • 



原生应用更合适：


    

  • 重度图形（游戏）。
    • 

  • 深度平台集成（HealthKit）。
    • 

  • 纯本地应用（离线优先、无需网络）。
    • 



混合模式常见：


    

  • PWA + 原生外壳。
    • 

  • Capacitor、React Native + Web。
    • 



浏览器支持
Chrome / Edge：


    

  • 完整 PWA 支持。
    • 

  • 最佳 PWA 体验。
    • 



Firefox：


    

  • 大部分特性支持。
    • 

  • 部分 API 有限制。
    • 



Safari：


    

  • 历史上持抗拒态度。
    • 

  • iOS 16.4（2023）加入推送通知（有限制）。
    • 

  • 支持添加到主屏，但没有类似应用商店的安装体验。
    • 



Samsung Internet：


    

  • 强劲的 PWA 支持。
    • 

  • 中国 Android 主流浏览器之一。
    • 



iOS PWA 限制：


    

  • 推送通知仅在添加到主屏后可用。
    • 

  • 后台同步受限。
    • 

  • IndexedDB 配额有限。
    • 

  • 但仍可渐进增强。
    • 



PWA 与原生应用对比
功能：


    

  • 原生仍有优势（AR、健康数据、深度系统访问）。
    • 

  • PWA 在逐步接近（Project Fugu 计划）。
    • 



性能：


    

  • 原生启动更快。
    • 

  • PWA 已可实现亚秒级加载。
    • 



分发：


    

  • 应用商店有发现优势。
    • 

  • PWA 基于 URL 分发。
    • 



选择建议：


    

  • 大部分产品 PWA 已足够。
    • 

  • 重度图形或系统访问需求选原生。
    • 



Project Fugu
Google 主导的计划——为 Web 平台提供更多原生能力：


    

  • File System Access API。
    • 

  • Web Bluetooth。
    • 

  • Web USB。
    • 

  • Web NFC。
    • 

  • Web Serial。
    • 

  • Idle Detection。
    • 

  • Periodic Background Sync。
    • 



目标：缩小 Web 与原生之间的差距。


现状：


    

  • Chrome / Edge 从实验到正式发布。
    • 

  • Safari / Firefox 采纳速度较慢。
    •

    • 可安装。

实战：


    

  • 发布前运行审计。
    • 

  • 100 分即为 PWA 就绪。
    • 



常见 PWA 误解
1. PWA 就是 Service Worker：


    

  • 错误。Service Worker 是组件之一，但 PWA 是整体方案。
    • 



2. PWA 会替代原生应用：


    

  • 不一定。二者互补。
    • 



3. PWA 只能用于移动端：


    

  • 错误。桌面 PWA 同样支持（Chromebook、Windows、macOS）。
    • 



4. PWA 很慢：


    

  • 实际上构建得当的 PWA 比普通网站更快。
    • 



反模式
1. 注册了 Service Worker 但不做缓存：


    

  • 没有离线能力。
    • 



2. 没有 Manifest 文件：


    

  • 无法安装。
    • 



3. 没有 HTTPS：


    

  • Service Worker 无法工作。
    • 



4. 缓存过多：


    

  • 占满用户设备存储。
    • 



5. 没有更新策略：


    

  • 用户被困在旧版本。
    • 



6. 不测试离线：


    

  • 在 DevTools 中点击"Offline"即可模拟。
    • 



实战搭建
1. Manifest 文件：


<link rel="manifest" href="/manifest.json" />
{
  "name": "My PWA",
  "short_name": "PWA",
  "icons": [{ "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" }],
  "start_url": "/",
  "display": "standalone",
  "theme_color": "#3b82f6",
  "background_color": "#ffffff"
}
2. Service Worker：


// sw.js
self.addEventListener('install', (event) => {
  event.waitUntil(caches.open('v1').then((cache) => cache.addAll(['/', '/styles.css'])));
});

self.addEventListener('fetch', (event) => {
  event.respondWith(caches.match(event.request).then((response) => response || fetch(event.request)));
});
// 在 HTML 或主 JS 中注册
if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js');
}
3. HTTPS：


    

  • Let's Encrypt 提供免费证书。
    • 

  • 开发时 localhost 无需证书。
    • 



现代 PWA 框架
Workbox（Google 出品）：


    

  • Service Worker 工具库。
    • 

  • 封装最佳实践。
    • 



Next.js PWA：


    

  • next-pwa 插件。
    • 



Vite PWA：


    

  • vite-plugin-pwa 插件。
    • 



SvelteKit / Remix：


    

  • 内置或社区插件支持。
    • 



实战建议：


    

  • 使用框架工具，避免手写原始 Service Worker。
    • 



小结
PWA（渐进式 Web 应用，Google 2015 提出）是 Web 平台能力的组合（Service Worker + Manifest + HTTPS），让 Web 获得接近原生的体验——可安装、离线可用、推送通知、后台同步。FIRE 四大特性——Fast（App Shell 实现小于 3 秒加载）、Installable（添加到主屏）、Reliable（离线可用）、Engaging（推送通知）。PRPL 模式——推送关键资源、渲染初始路由、预缓存其他路由、按需加载其余内容。核心组件——HTTPS 必需、Web App Manifest（描述应用的 JSON 文件）、Service Worker（后台 JS，拦截网络）、App Shell（核心 UI 预缓存）。PWA 优势——低获客门槛（无需商店）、跨平台（一套代码）、低成本（无 30% 抽成）、SEO 友好（可索引）、体积小。Twitter Lite 案例流量节省 70% + 参与度提升 65% + 发推量增 75%。Starbucks 日活翻倍。适合 PWA——多平台、新兴市场、内容为主；适合原生——重度图形、深度系统访问。浏览器支持 Chrome/Edge 完整、Firefox 大部分、Safari 历史抗拒现在 iOS 16.4 支持受限推送、Samsung Internet 强。Project Fugu 为 Web 增加原生能力（File System Access、Bluetooth、USB 等）。Lighthouse 审计检查 PWA 标准得分 0-100。误解——PWA 不等于 Service Worker、不总是替代原生、不仅限移动端、构建得当并不慢。反模式——注册 Service Worker 但不缓存、无 Manifest、无 HTTPS、缓存过多、无更新策略、不测试离线。搭建需要 Manifest + Service Worker + HTTPS。现代框架 Workbox / next-pwa / vite-plugin-pwa / SvelteKit / Remix 封装最佳实践。
