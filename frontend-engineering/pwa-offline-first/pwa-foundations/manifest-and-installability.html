Manifest 与可安装性

核心概念

Web App Manifest 是一个 JSON 文件，让浏览器将网站视为可安装的应用——name、icons、theme_color、start_url、display 等字段决定安装后应用的表现形式。浏览器满足安装条件（有效 Manifest + Service Worker + HTTPS + 用户参与度）后会显示"添加到主屏幕"提示或地址栏安装按钮。本节详解 Manifest 字段、图标多尺寸要求、显示模式、作用域、协议处理器、快捷方式、分享目标、安装提示控制及安装体验优化。

字段 含义 示例
name 应用全名 "My App"
short_name 应用短名 "App"
icons 多尺寸图标 192/512 px PNG
start_url 启动 URL "/"
display 显示模式 standalone
theme_color 浏览器栏颜色 "#3b82f6"
background_color 启动画面背景色 "#ffffff"
scope URL 作用域 "/"
orientation 屏幕方向 "portrait"
shortcuts 快捷操作 选项数组
share_target 接收分享 url + params

Manifest 配置

HTML 链接：

<link rel="manifest" href="/manifest.json" />

Manifest 示例：

{
  "name": "My Productivity App",
  "short_name": "MyApp",
  "description": "A productivity app",
  "start_url": "/",
  "scope": "/",
  "display": "standalone",
  "orientation": "portrait",
  "theme_color": "#3b82f6",
  "background_color": "#ffffff",
  "lang": "en",
  "icons": [
    {
      "src": "/icons/icon-192.png",
      "sizes": "192x192",
      "type": "image/png",
      "purpose": "any maskable"
    },
    {
      "src": "/icons/icon-512.png",
      "sizes": "512x512",
      "type": "image/png",
      "purpose": "any maskable"
    }
  ],
  "shortcuts": [
    {
      "name": "New Task",
      "url": "/new",
      "icons": [{ "src": "/icons/new-task.png", "sizes": "96x96" }]
    }
  ]
}

图标要求

必需尺寸：

  • 192x192（最低要求）。
  • 512x512（启动画面必需）。
  • 推荐提供多个尺寸：192、256、384、512。

格式：

  • PNG（通用支持）。
  • SVG（仅 Chrome 支持）。
  • WebP（支持有限）。

用途（purpose）：

  • any：默认模式（浏览器按需填充）。
  • maskable：Android 自适应图标（安全区域裁剪）。
  • monochrome：Android 主题化图标。

可遮罩图标：

  • Android 会将图标裁剪为圆形或方圆形。
  • 需确保安全区域在中心 80%。
  • 可用 Maskable.app 工具生成。
显示模式
fullscreen：


    

  • 全屏，无浏览器界面。
    • 

  • 适合沉浸式场景（游戏）。
    • 



standalone：


    

  • 外观类似原生应用。
    • 

  • 无浏览器界面但保留系统状态栏。
    • 

  • 推荐作为默认选择。
    • 



minimal-ui：


    

  • 保留部分浏览器界面。
    • 

  • 适合需要导航控件的场景。
    • 



browser：


    

  • 标准浏览器标签页。
    • 

  • 等同于不安装。
    • 



实战建议：选择 standalone。


主题色与背景色
theme_color：


    

  • 浏览器地址栏和状态栏颜色。
    • 

  • 应用切换器中的标识颜色。
    • 



background_color：


    

  • 启动画面背景色。
    • 

  • CSS 加载前的初始渲染背景。
    • 



选择建议：


    

  • theme_color 匹配品牌色。
    • 

  • background_color 匹配应用背景色（避免闪屏）。
    • 



启动 URL
start_url：


    

  • 点击图标时打开的 URL。
    • 

  • 通常设为 "/"。
    • 

  • 可添加追踪参数：/?source=pwa。
    • 



用途：


    

  • 区分安装访问与浏览器访问。
    • 

  • 为已安装用户定制落地页。
    • 



作用域
scope：


    

  • 属于"应用内"的 URL 前缀。
    • 

  • 超出作用域的链接会在浏览器中打开。
    • 

  • 通常设为 "/" 表示全站。
    • 



子作用域示例：


    

  • 应用为某子模块：scope: "/app/"。
    • 

  • 仅 /app/* 在 PWA 内运行。
    • 

  • /blog/ 在浏览器中打开。
    • 



安装条件
Chrome / Edge 安装条件：


    

  • HTTPS。
    • 

  • Manifest 包含 name + 图标（192+）+ display standalone。
    • 

  • Service Worker 已注册并有 fetch 处理器。
    • 

  • 用户参与度信号（访问时长等）。
    • 

  • 尚未安装。
    • 



满足条件后浏览器会显示安装提示或图标。


手动触发安装提示：


let deferredPrompt;

window.addEventListener('beforeinstallprompt', (e) => {
  e.preventDefault();
  deferredPrompt = e;
  // 显示自定义安装按钮
  showInstallButton();
});

installButton.addEventListener('click', () => {
  deferredPrompt.prompt();
  deferredPrompt.userChoice.then((result) => {
    if (result.outcome === 'accepted') {
      console.log('Installed');
    }
  });
});
iOS 添加到主屏
添加到主屏幕：


    

  • Safari 分享菜单 → "添加到主屏幕"。
    • 

  • 不会自动弹出提示（需用户手动操作）。
    • 

  • 使用 <meta> 标签适配 iOS：
    • 



<meta name="apple-mobile-web-app-capable" content="yes" />
<meta name="apple-mobile-web-app-status-bar-style" content="default" />
<link rel="apple-touch-icon" href="/icons/icon-192.png" />
iOS 限制：


    

  • 不读取 Manifest 中的图标。
    • 

  • 需用 apple-touch-icon 指定。
    • 

  • 推送通知需 16.4 以上版本。
    • 

  • 部分特性缺失。
    • 



快捷方式
长按应用图标弹出快捷操作：


{
  "shortcuts": [
    {
      "name": "New Task",
      "short_name": "New",
      "description": "Create new task",
      "url": "/new",
      "icons": [{ "src": "/new-icon.png", "sizes": "96x96" }]
    }
  ]
}
平台支持：


    

  • Android、Windows 支持。
    • 

  • iOS 不支持。
    • 



分享目标
让 PWA 接收系统分享：


{
  "share_target": {
    "action": "/share",
    "method": "POST",
    "params": {
      "title": "title",
      "text": "text",
      "url": "url"
    }
  }
}
用户从其他应用分享内容时，PWA 可以接收处理。


服务端：


    

  • 处理 POST /share 请求及其参数。
    • 



协议处理器
让 PWA 处理自定义协议：


{
  "protocol_handlers": [
    {
      "protocol": "web+myapp",
      "url": "/handle?p=%s"
    }
  ]
}
使用 web+myapp://something 即可打开 PWA。


文件处理器
让 PWA 注册为文件处理器：


{
  "file_handlers": [
    {
      "action": "/open",
      "accept": { "text/markdown": [".md"] }
    }
  ]
}
用户打开 .md 文件时可选择 PWA 处理。


Manifest 验证
工具：


    

  • Lighthouse：检查可安装性。
    • 

  • Chrome DevTools Application 面板。
    • 

  • pwabuilder.com：生成 Manifest + 审计。
    • 

  • web.dev/measure。
    • 



常见问题：


    

  • 缺少 192 / 512 图标。
    • 

  • 无 short_name。
    • 

  • start_url 返回非 200。
    • 

  • HTTPS 配置错误。
    • 



安装体验设计
1. 不要立即弹出安装提示：


    

  • 令人厌烦。
    • 

  • 等用户有参与度后再提示。
    • 



2. 自定义安装界面：


    

  • 利用 beforeinstallprompt 事件。
    • 

  • 自定义按钮位置。
    • 



3. 延迟提示：


    

  • 让用户先探索内容。
    • 

  • 在合适的时机展示提示。
    • 



4. 不要反复纠缠：


    

  • 一次拒绝后不要立即再弹。
    • 

  • 30 天后再尝试。
    • 



5. 数据追踪：


    

  • A/B 测试安装提示。
    • 

  • 衡量安装率。
    • 



更新策略
Manifest 不会自动更新：


    

  • 浏览器会积极缓存 Manifest。
    • 

  • 修改 Manifest 后用户可能仍看到旧版，直到缓存过期。
    • 



实战建议：


    

  • Manifest 变更应较少。
    • 

  • 重大变更后可能需要重新提示安装。
    • 



反模式
1. 没有 Manifest：


    

  • 无法安装。
    • 



2. 仅提供一个图标尺寸：


    

  • 浏览器回退显示效果差。
    • 



3. 主题色与内容冲突：


    

  • 视觉混乱。
    • 



4. start_url 错误：


    

  • 安装后启动页面错误。
    • 



5. 没有 maskable 图标：


    

  • Android 上显示异常（裁剪不当）。
    • 



6. 过于激进的安装提示：


    

  • 用户安装率低且反感。
    • 



多个 Manifest
同一域名下多个 PWA：


    

  • 用作用域（scope）区分。
    • 

  • App1 的 scope: /app1/。
    • 

  • App2 的 scope: /app2/。
    • 

  • 各自拥有独立 Manifest。
    • 



启动画面
浏览器自动生成：


    

  • 使用图标 + 名称 + background_color + theme_color。
    • 

  • 无法直接控制样式。
    • 



iOS：


    

  • 使用特定的 <link> 标签指定启动画面图片。
    • 



展示流程：


    

  • 初始加载 → 启动画面。
    • 

  • DOM 就绪 → 显示应用。
    • 



实战建议
1. Lighthouse 满分：


    

  • 通过 PWA 审计。
    • 

  • 根据警告迭代 Manifest。
    • 



2. Maskable 图标：


    

  • 使用 maskable.app 工具生成。
    • 

  • 在 Android 上测试效果。
    • 



3. 主题色与背景色匹配：


    

  • 避免刺眼的过渡。
    • 



4. iOS 专属 meta 标签：


    

  • 确保 iOS 上的最佳体验。
    • 



5. 测试安装流程：


    

  • Chrome 菜单 → 安装。
    • 

  • 验证 start_url、图标、主题色。
    • 



小结
Web App Manifest 是 JSON 文件，让浏览器将网站视为可安装应用——包含 name、icons、start_url、display、theme、background 等字段。通过 HTML 中的 <link rel="manifest"> 引入。图标要求 192/512 最低尺寸，purpose 支持 any/maskable（Android 安全区域 80%）/monochrome。显示模式包括 fullscreen（沉浸式）、standalone（推荐默认）、minimal-ui、browser。theme_color 控制浏览器栏和状态栏颜色，background_color 是启动画面背景。start_url 指定点击图标时的启动 URL（通常 "/"，可加追踪参数）。scope 限定应用内 URL 前缀。安装条件——HTTPS + 有效 Manifest + Service Worker + 用户参与度，满足后浏览器显示安装提示。可通过 beforeinstallprompt 事件自定义安装界面。iOS 需通过 Safari 分享菜单手动添加，需要 apple-touch-icon + meta 标签适配。快捷方式为长按图标弹出的快捷操作（Android / Windows 支持）。分享目标让 PWA 接收系统分享。协议处理器和文件处理器扩展 PWA 的系统集成能力。验证工具有 Lighthouse / DevTools / pwabuilder.com。安装体验设计不应立即弹出提示，应等用户参与后再展示、自定义界面、延迟提示、不反复纠缠、做好数据追踪。Manifest 是 PWA 的"门面"——配置正确让安装顺畅、体验接近原生；配置错误则安装失败或视觉效果差。
