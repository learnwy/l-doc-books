测试与调试

核心概念

PWA 的测试与调试比传统 Web 应用更复杂——Service Worker 生命周期让开发时的缓存问题令人困扰、离线场景难以复现、不同浏览器行为差异大、推送通知难以测试。Chrome DevTools 的 Application 标签页是 PWA 工程师的必备工具——查看 Service Worker 状态、缓存内容、存储情况、清单文件、触发推送和同步。Lighthouse 提供 PWA 审计评分。Playwright / Puppeteer 支持自动化测试。本节涵盖 PWA 专属调试工具、离线测试方法、Service Worker 开发技巧、Lighthouse 审计、以及 CI 集成。

工具 用途
Chrome DevTools Service Worker、存储、网络、推送调试
Lighthouse PWA 审计与评分
Playwright / Puppeteer 自动化端到端测试
ngrok / Cloudflare Tunnel 移动设备远程测试
pwa-asset-generator 生成清单文件所需图标

Chrome DevTools Application 标签页

Service Workers 区域：

  • 状态查看（运行中 / 等待中 / 已激活 / 已废弃）。
  • 勾选"刷新时更新"（每次刷新强制更新 Service Worker）。
  • 勾选"绕过网络"（跳过 Service Worker 拦截）。
  • 注销 Service Worker。
  • 手动触发推送（Push）事件。
  • 手动触发同步（Sync）事件。
  • 手动触发周期性同步（Periodic Sync）事件。

Manifest 区域：

  • 验证清单文件 JSON 格式。
  • 显示可安装性错误。
  • 测试"添加到主屏幕"功能。

Storage 区域：

  • 浏览 Cache Storage（缓存 API 内容）。
  • 浏览 IndexedDB（可查看和编辑数据）。
  • 查看 localStorage / sessionStorage。
  • 一键清除所有存储。
  • 查看存储配额使用情况。

Background Services 区域：

  • Background Fetch / Sync 日志。
  • Push 推送日志。
  • Notification 通知日志。
Service Worker 开发技巧
1. 开发时跳过等待：在 DevTools 中勾选"Update on reload"，每次刷新都使用最新的 Service Worker。


2. 绕过 Service Worker：勾选"Bypass for network"，对比有无 Service Worker 时的行为差异。


3. Service Worker 控制台日志：在 Application 标签页的 Service Workers 区域点击"Inspect"，打开 Service Worker 的独立控制台。


4. 强制更新：


navigator.serviceWorker.getRegistrations().then((regs) => {
  regs.forEach((reg) => reg.update());
});
5. 硬刷新加清除缓存：在 DevTools 打开时右键点击刷新按钮 → 选择"清空缓存并硬性重新加载"。


测试离线场景
DevTools 网络限速：在 Network 标签页选择"Offline"，立即模拟离线状态。


测试场景清单：


    

  • 首次访问（无缓存时）的表现。
    • 

  • 有缓存时的离线访问。
    • 

  • 离线提交表单。
    • 

  • 重新连接后的同步行为。
    • 



真实飞行模式：在移动设备上进行真实离线测试。DevTools 的离线模拟有时不完整（可能不触发 online/offline 事件）。


Lighthouse PWA 审计
运行方式：在 DevTools 的 Lighthouse 标签页勾选"Progressive Web App"类别，点击"生成报告"。


评分因素：


    

  • 使用 HTTPS。
    • 

  • 注册了 Service Worker 且有 fetch 处理器。
    • 

  • 清单文件有效且满足可安装条件。
    • 

  • 有启动画面配置。
    • 

  • 设置了主题色。
    • 

  • 有 viewport meta 标签。
    • 

  • 支持离线访问。
    • 



目标：满分 100 分——通过所有 PWA 标准。


CI 集成配置：


- name: Lighthouse CI
  uses: treosh/lighthouse-ci-action@v10
  with:
    urls: 'https://example.com'
    configPath: ./lighthouse.json
质量门禁：Lighthouse 分数低于阈值时构建失败。


Playwright 自动化测试
测试 Service Worker 和离线行为：


import { test, expect } from '@playwright/test';

test('离线时仍可正常访问', async ({ page, context }) => {
  await page.goto('/');
  await page.waitForFunction(() => navigator.serviceWorker.controller !== null);

  // 切换为离线状态
  await context.setOffline(true);

  // 刷新页面
  await page.reload();
  await expect(page.locator('h1')).toBeVisible();
});

test('安装提示', async ({ page }) => {
  await page.goto('/');
  // 测试 beforeinstallprompt 事件处理
});
测试覆盖范围：离线行为、缓存内容验证、Service Worker 更新流程。


手动测试清单
1. 安装测试：通过 Chrome 菜单安装，验证图标、名称、主题色是否正确。


2. 首次离线访问：清除缓存后断网，验证优雅降级。


3. 缓存后离线访问：先在线访问一次，然后断网刷新和导航。


4. 更新测试：部署新版本后验证更新提示出现，点击后获取最新版本。


5. 推送通知测试：完成订阅后服务器发送推送，验证通知展示和点击行为。


6. 后台同步测试：离线提交操作后重连，验证自动同步。


移动设备测试
真实设备测试：使用 Chrome Android / Safari iOS 在真实网络环境下测试。


ngrok / Cloudflare Tunnel：将本地开发服务暴露为公网 URL，方便手机访问测试。


ngrok http 3000
# 输出公网地址如 https://abc123.ngrok.io
Chrome 远程调试：手机上的 Chrome 可通过桌面的 chrome://inspect 连接，直接用 DevTools 调试手机页面。


Safari 远程调试：iOS Safari 可通过 Mac Safari 的"开发"菜单连接调试。


性能测试
Lighthouse：综合性能评分，包含 LCP / FID / CLS 等核心指标。


WebPageTest：在真实设备和网络条件下测试，提供胶片视图。


Chrome DevTools Performance 面板：录制加载过程，定位性能瓶颈。


真实用户监控（RUM）：通过 web-vitals npm 包收集真实用户的性能数据。


存储检查
DevTools Application Storage 区域：可浏览 Cache Storage、IndexedDB、localStorage 等全部存储内容和配额使用情况。


编程方式检查：


const { usage, quota } = await navigator.storage.estimate();
console.log(`已使用 ${((usage / quota) * 100).toFixed(1)}%`);
推送通知测试
DevTools 测试：在 Application → Service Workers 区域点击"Push"按钮，输入负载数据后触发，验证 Service Worker 接收并展示通知。


真实测试：在开发环境完成订阅后，通过服务器使用 web-push 库实际发送推送。


后台同步测试
DevTools 测试：在 Application → Service Workers 区域点击"Sync"按钮，输入标签名后触发同步事件，验证 Service Worker 正确处理。


清单文件验证
验证工具：Chrome DevTools Manifest 区域、pwabuilder.com（在线验证）、Lighthouse。


常见错误：缺少 192px 图标、start_url 返回非 200 状态、主题色格式无效。


常见问题排查
1. Service Worker 不更新：浏览器缓存了 sw.js 文件。解决：服务器设置 Cache-Control: max-age=0。


2. 缓存永远过时：使用了缓存优先策略但没有失效机制。解决：改用过期重验证策略或版本化缓存。


3. 安装提示不出现：使用 Lighthouse 排查原因，检查控制台警告信息。


4. 推送通知不工作：VAPID 密钥不匹配、订阅已过期。检查服务器是否收到 410 Gone 响应。


5. 离线不工作：Service Worker 没有处理导航请求，或预缓存缺少关键资源。


生产环境调试
远程调试：桌面访问 chrome://inspect 连接手机，检查生产环境页面。


错误监控：集成 Sentry / LogRocket 等工具监控 Service Worker 错误事件。


用户自助诊断：提供"显示诊断信息"按钮，展示 Service Worker 状态、缓存内容、存储用量等信息。


CI/CD 集成
持续集成流水线配置：


- run: npm run build
- run: npm run test # 单元测试 + 集成测试
- run: npm run test:e2e # Playwright 端到端测试
- name: Lighthouse
  uses: treosh/lighthouse-ci-action@v10
质量门禁：Lighthouse 分数 ≥ 90 分，否则构建失败。端到端测试必须通过。


发版测试模板
每次发版需验证：


    

  •  Chrome 桌面端安装。
    • 

  •  Chrome Android 安装。
    • 

  •  Safari macOS 安装。
    • 

  •  Safari iOS 添加到主屏幕。
    • 

  •  离线刷新正常。
    • 

  •  离线提交 + 重连后同步。
    • 

  •  推送订阅 + 接收通知。
    • 

  •  更新提示正常显示。
    • 

  •  更新应用正常。
    • 

  •  Lighthouse PWA 满分。
    • 



常见反模式
1. 仅在 Chrome 上测试：Safari / Firefox 行为可能不同。


2. 仅在桌面端测试：移动端可能存在特有问题。


3. 不测试离线场景：生产用户离线时应用失效。


4. 不测试更新流程：新版本部署后用户体验中断。


5. 不记录 Service Worker 日志：问题不可见无法排查。


6. 不集成 Lighthouse CI：性能回退无法及时发现。


最佳实践
1. 熟练掌握 DevTools Application 标签页：这是日常开发的必备工具。


2. 维持 Lighthouse 满分基线：任何变更不得降低评分。


3. 多浏览器测试：至少覆盖 Chrome、Safari、Firefox、Edge。


4. 真实设备测试：使用真实手机在真实网络下测试。


5. CI 集成 Lighthouse：自动捕获性能回退。


6. 生产环境遥测：监控 Service Worker 错误和用户体验指标。


现代测试技术栈
推荐工具组合：


    

  • Vitest（单元测试）。
    • 

  • Playwright（端到端测试 + 离线场景）。
    • 

  • Lighthouse CI（PWA 审计 + 性能监控）。
    • 

  • Workbox 预编译验证（构建时校验）。
    • 



技术栈组合：Vite + Vitest + Playwright + Lighthouse CI + Workbox，现代工具链集成良好，覆盖 PWA 开发的全部测试需求。


小结
PWA 的测试与调试比传统 Web 更复杂，主要挑战来自 Service Worker 生命周期、离线场景复现和多浏览器差异。Chrome DevTools Application 标签页是核心工具——管理 Service Worker 状态、检查缓存和存储、手动触发推送和同步事件。开发时善用"刷新时更新"和"绕过网络"选项。离线测试需结合 DevTools 模拟和真实飞行模式。Lighthouse PWA 审计应达到满分并集成到 CI 中防止回退。Playwright 可自动化测试离线行为和 Service Worker 更新流程。移动端测试通过 ngrok 暴露本地服务，配合远程调试工具。生产环境需要错误监控和用户自助诊断能力。每次发版应覆盖多浏览器、多设备、离线、同步、推送、更新等全部场景。构建从单元测试到 Lighthouse CI 的完整质量门禁，是保证 PWA 持续可靠的关键。
