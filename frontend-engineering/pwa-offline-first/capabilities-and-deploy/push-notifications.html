推送通知

核心概念

Web Push Notifications（Web 推送通知）让服务器能够向用户设备发送通知——即使 PWA 未打开。这让 PWA 的用户重新触达能力接近原生应用。Web 推送基于 W3C Push API + Notification API + VAPID（自愿应用服务器标识）规范。浏览器通过推送服务（FCM / Mozilla / Apple）将消息路由到设备，Service Worker 接收后展示通知。本节涵盖推送通知完整流程、订阅机制、服务器发送、Service Worker 处理、权限请求体验设计、iOS 16.4 限制、以及最佳实践。

步骤 组件 动作
1. 订阅 客户端 获取推送订阅端点
2. 存储订阅 服务器 保存用户的端点信息
3. 触发推送 服务器 通过推送服务发送
4. 推送服务 FCM / Mozilla / Apple 路由到设备
5. 接收 浏览器 Service Worker 触发 push 事件
6. 展示 Service Worker 调用 showNotification()
7. 点击 用户 触发 notificationclick 事件

VAPID 密钥

VAPID（Voluntary Application Server Identification，自愿应用服务器标识）：

  • 服务器使用 ECDSA 密钥对签名推送请求。
  • 公钥分发给客户端。
  • 推送服务验证签名确保来源合法。

生成密钥对：

npx web-push generate-vapid-keys

输出示例：

Public Key: BL...
Private Key: kS...

密钥存储：公钥同时存储在客户端和服务器端；私钥仅存储在服务器端，绝不暴露给客户端。

订阅流程

客户端订阅推送：

async function subscribe() {
  // 1. 请求通知权限
  const permission = await Notification.requestPermission();
  if (permission !== 'granted') return;

  // 2. 获取 Service Worker 注册
  const reg = await navigator.serviceWorker.ready;

  // 3. 订阅推送
  const sub = await reg.pushManager.subscribe({
    userVisibleOnly: true,
    applicationServerKey: urlBase64ToUint8Array(VAPID_PUBLIC_KEY),
  });

  // 4. 将订阅信息发送到服务器保存
  await fetch('/api/subscribe', {
    method: 'POST',
    body: JSON.stringify(sub),
  });
}

订阅对象结构：

{
  "endpoint": "https://fcm.googleapis.com/...",
  "keys": {
    "p256dh": "...",
    "auth": "..."
  }
}

服务器需要存储该订阅对象，后续发送推送时使用。

服务器发送推送

Node.js 使用 web-push 库：

const webpush = require('web-push');

webpush.setVapidDetails(
  'mailto:admin@example.com',
  VAPID_PUBLIC_KEY,
  VAPID_PRIVATE_KEY
);

// 发送推送
const subscription = { endpoint: '...', keys: {...} };
const payload = JSON.stringify({
  title: '你好！',
  body: '你收到了一条新消息',
  url: '/inbox'
});

await webpush.sendNotification(subscription, payload);

其他语言的推送库：Python 使用 pywebpush，Go 使用 webpush-go，Ruby 使用 web-push gem。

Service Worker 推送处理

self.addEventListener('push', (event) => {
  const data = event.data?.json() || {};

  event.waitUntil(
    self.registration.showNotification(data.title, {
      body: data.body,
      icon: '/icon-192.png',
      badge: '/badge-72.png',
      data: { url: data.url },
      actions: [
        { action: 'open', title: '打开' },
        { action: 'dismiss', title: '忽略' },
      ],
    }),
  );
});

通知选项说明：

  • title、body：标题和正文内容。
  • icon、badge：图标和角标。
  • image：大图预览。
  • actions：自定义操作按钮。
  • data：自定义负载数据（如跳转 URL）。
  • tag：标签（同标签通知会相互替换）。
  • requireInteraction：是否需要用户手动关闭。
  • silent：静音通知。
  • vibrate：震动模式（仅移动端）。

通知点击处理

self.addEventListener('notificationclick', (event) => {
  event.notification.close();

  if (event.action === 'dismiss') return;

  const url = event.notification.data.url || '/';
  event.waitUntil(
    clients.matchAll({ type: 'window' }).then((windowClients) => {
      // 如果已有窗口打开则聚焦
      for (const client of windowClients) {
        if (client.url === url) return client.focus();
      }
      // 否则打开新窗口
      return clients.openWindow(url);
    }),
  );
});
权限请求体验设计
反模式：用户刚进入网站就立即弹出权限请求——大多数用户会直接拒绝。


最佳实践：


1. 先解释再请求：


<Modal>
  <h3>开启通知</h3>
  <p>当有人给你发消息时，我们会通知你。</p>
  <button onClick={() => requestPermission()}>开启通知</button>
  <button onClick={() => skip()}>以后再说</button>
</Modal>
2. 在用户操作后触发：例如用户发送完消息后、完成引导流程后。


3. 不要立即重新请求：如果用户拒绝，等待数天或数周后再考虑提示。


iOS 16.4+ 限制
Apple 长期对 Web Push 持保守态度：


    

  • iOS 16.4 之前：完全不支持 Web Push。
    • 

  • iOS 16.4（2023 年）起：支持，但有前提条件。
    • 



iOS PWA 推送限制：


    

  • 必须先将应用添加到主屏幕（Add to Home Screen）。
    • 

  • 然后才能订阅推送。
    • 

  • Safari 浏览器内直接访问不支持。
    • 



Safari macOS：16.0 起标准支持。


浏览器兼容性
Chrome / Edge / Firefox：完整支持。


Safari macOS：16.0 及以上版本支持。


Safari iOS：16.4 及以上版本，需先添加到主屏幕。


Samsung Internet / Opera：支持。


通知权限状态
console.log(Notification.permission);
// 'default' | 'granted' | 'denied'
一旦被拒绝：无法再自动弹出权限请求，用户必须手动在浏览器设置中重新开启。


测试推送通知
Chrome DevTools 测试：Application 标签页 → Service Workers → 点击"Push"按钮，可模拟推送事件。


服务器端测试：使用 web-push 命令行工具或库发送真实推送。


验证订阅有效性：使用 web-push 库测试端点是否有效。


通知频率控制
避免过度推送：


    

  • 每用户每天最多 1-3 条推送。
    • 

  • 基于用户活跃时间段发送。
    • 



分类管理：


    

  • 直接消息（高优先级）。
    • 

  • 每日摘要（低优先级）。
    • 

  • 营销推广（最低优先级）。
    • 



让用户自主控制：


    

  • 按类别独立订阅或退订。
    • 

  • 提供"免打扰时段"设置。
    • 



标签去重
使用 tag 替换同类通知：


self.registration.showNotification('新消息', {
  tag: 'message-123', // 相同 tag 的通知会相互替换
});
效果：同一对话的多次更新只显示一条通知，而非堆积 N 条。


操作按钮
自定义通知按钮：


{
  actions: [
    { action: 'reply', title: '回复', icon: '/reply.png' },
    { action: 'archive', title: '归档' },
  ];
}
在点击事件中处理不同操作：


self.addEventListener('notificationclick', (event) => {
  if (event.action === 'reply') {
    // 打开回复界面
  } else if (event.action === 'archive') {
    // 在后台执行归档操作
  }
});
富媒体通知
带大图预览的通知：


{
  title: '新照片',
  body: '来自 Alice',
  image: '/photo-large.jpg',  // 大图预览
  icon: '/icon.png'
}
支持情况：Chrome / Edge 桌面端支持较好，移动端表现因平台而异。


静默推送的限制
规范要求 userVisibleOnly: true：浏览器强制要求每次推送必须展示可见通知，不支持真正的静默推送。


替代方案：显示低优先级通知，或使用周期性后台同步（Periodic Background Sync）替代。


隐私保护
订阅信息是设备标识符：端点 URL 在每个设备和浏览器中唯一，使用时需谨慎，不要分享给第三方。


退订流程：


const sub = await reg.pushManager.getSubscription();
await sub.unsubscribe();
await fetch('/api/unsubscribe', { method: 'POST', body: sub.endpoint });
服务器端存储
数据库表结构示例：


CREATE TABLE push_subscriptions (
  id SERIAL PRIMARY KEY,
  user_id INT,
  endpoint TEXT,
  p256dh TEXT,
  auth TEXT,
  created_at TIMESTAMP,
  UNIQUE(endpoint)
);
清理过期订阅：收到 410 Gone 响应时删除对应订阅，不要向已过期的端点发送推送。


错误处理
常见错误码：


    

  • 410 Gone：订阅已过期。
    • 

  • 404 Not Found：端点无效。
    • 

  • 413 Payload Too Large：负载过大，需要精简内容。
    • 

  • 429 Too Many Requests：触发速率限制。
    • 



try {
  await webpush.sendNotification(sub, payload);
} catch (err) {
  if (err.statusCode === 410 || err.statusCode === 404) {
    await deleteSubscription(sub.endpoint);
  }
}
常见反模式
1. 页面加载立即请求权限：用户必然拒绝。


2. 不解释请求原因：用户感到困惑。


3. 推送频率过高：用户退订或禁用通知。


4. 不分类管理：用户只能全部退订。


5. 不清理过期订阅：浪费资源向无效端点发送。


6. 仅发送营销内容：用户很快忽略所有通知。


最佳实践
1. 请求前先说明价值：告诉用户开启通知能获得什么。


2. 在用户操作后触发：不要在页面加载时请求。


3. 按类别管理订阅：让用户选择接收哪类通知。


4. 控制发送频率：质量优先于数量。


5. 定期清理过期订阅：保持数据库健康。


6. 多平台测试：在不同浏览器和操作系统上验证表现。


小结
Web 推送通知让服务器能向设备发送通知（即使 PWA 未打开），基于 W3C Push API + Notification API + VAPID 规范。VAPID 使用 ECDSA 密钥对签名推送请求以验证来源。订阅流程为：请求通知权限 → 获取推送订阅对象 → 将订阅信息发送到服务器保存。服务器通过 web-push 等库向推送服务发送消息。Service Worker 在 push 事件中调用 showNotification 展示通知，在 notificationclick 事件中处理用户点击。权限请求体验的关键是先解释价值再请求、在用户操作后触发、被拒绝后不立即重试。iOS 16.4+ 支持 Web Push 但要求先添加到主屏幕。通知频率应控制在每天 1-3 条，按类别让用户自主订阅。服务器端需要及时清理过期订阅（处理 410 Gone 响应）。推送通知是 PWA 用户重新触达的核心能力——设计得当能显著提升用户参与度，设计不当则只会让用户禁用通知。
