压缩与 CDN

传输压缩

文本类资源（HTML、CSS、JavaScript、JSON、SVG）具有极高的压缩率。通过 Gzip 或 Brotli 压缩，可以将传输体积减少 60-80%，显著加速资源下载。

构建时预压缩
在构建阶段预先生成压缩文件，避免服务器实时压缩的 CPU 开销：


import { gzip, brotliCompress } from 'zlib';
import { promisify } from 'util';
import { readFile, writeFile } from 'fs/promises';
import { glob } from 'glob';

const gzipAsync = promisify(gzip);
const brotliAsync = promisify(brotliCompress);

async function preCompress(pattern: string): Promise<void> {
  const files = await glob(pattern);
  let totalOriginal = 0;
  let totalGzip = 0;
  let totalBrotli = 0;

  for (const file of files) {
    const content = await readFile(file);
    totalOriginal += content.length;

    const gzipped = await gzipAsync(content, { level: 9 });
    await writeFile(`${file}.gz`, gzipped);
    totalGzip += gzipped.length;

    const brotlied = await brotliAsync(content);
    await writeFile(`${file}.br`, brotlied);
    totalBrotli += brotlied.length;
  }

  console.log(`Original: ${(totalOriginal / 1024).toFixed(1)} KB`);
  console.log(
    `Gzip:     ${(totalGzip / 1024).toFixed(1)} KB (${((1 - totalGzip / totalOriginal) * 100).toFixed(1)}% saved)`,
  );
  console.log(
    `Brotli:   ${(totalBrotli / 1024).toFixed(1)} KB (${((1 - totalBrotli / totalOriginal) * 100).toFixed(1)}% saved)`,
  );
}

preCompress('dist/**/*.{js,css,html,json,svg}');

小结
    

  • Brotli 比 Gzip 多节省约 15-20% 的传输体积，优先使用 Brotli。
    • 

  • 构建时预压缩避免服务器运行时的 CPU 开销。
    • 

  • CDN 将静态资源分发到离用户最近的边缘节点，典型减少 80-90% 的网络延迟。
    • 

  • 带哈希指纹的资源配合 CDN 长期缓存 + HTML no-cache 是最佳部署模式。
    • 

  • HTTP/2 多路复用消除了 HTTP/1.1 时代的域名分片和资源合并需求。
