Virtual DOM 与协调算法

Virtual DOM 的本质

Virtual DOM（虚拟 DOM）是一种编程概念——用 JavaScript 对象来描述真实 DOM 结构。当应用状态发生变化时，框架不会直接操作真实 DOM，而是先在内存中生成新的虚拟 DOM 树，通过 diff 算法与旧树比较，计算出最小的变更集，再一次性应用到真实 DOM 上。

VDOM 节点结构
interface VNode {
  type: string | Function;
  props: Record<string, any>;
  children: Array<VNode | string>;
  key: string | number | null;
}

const vdom: VNode = {
  type: 'div',
  props: { className: 'container' },
  key: null,
  children: [
    {
      type: 'h1',
      props: { className: 'title' },
      key: null,
      children: ['Hello World'],
    },
    {
      type: 'ul',
      props: { className: 'list' },
      key: null,
      children: [
        { type: 'li', props: {}, key: '1', children: ['Item 1'] },
        { type: 'li', props: {}, key: '2', children: ['Item 2'] },
        { type: 'li', props: {}, key: '3', children: ['Item 3'] },
      ],
    },
  ],
};


Diff 算法原理
完全比较两棵树的时间复杂度是 O(n³)，这对于包含数千个节点的 UI 来说是不可接受的。React 的 Reconciliation 算法通过三个启发式策略将复杂度降低到 O(n)：


策略一：同层级比较
React 只比较同一层级的节点，不会尝试跨层级匹配。如果一个节点从树的一个位置移到了另一个位置，React 会在旧位置销毁它，在新位置重新创建。


策略二：类型比较
    

  • 类型不同（如 <div> 变为 <span>）：销毁整个旧子树，创建新子树
    • 

  • 类型相同：保留 DOM 节点，只更新变更的属性
    • 



策略三：Key 的作用
Key 帮助 React 识别列表中哪些元素被修改、添加或移除。


function TodoList({ items }: { items: Array<{ id: string; text: string }> }) {
  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>{item.text}</li>
      ))}
    </ul>
  );
}
Key 的错误用法
function BadList({ items }: { items: string[] }) {
  return (
    <ul>
      {items.map((item, index) => (
        <li key={index}>{item}</li>
      ))}
    </ul>
  );
}
使用 index 作为 key 在列表顺序变化时会导致错误的节点复用，产生 UI bug 和不必要的重渲染。




React Fiber 架构
React 16 引入了 Fiber 架构，将渲染工作拆分为可中断的小单元。每个 Fiber 节点代表一个组件实例或 DOM 元素，形成链表结构而非传统的树结构。


双缓冲机制
React 维护两棵 Fiber 树——current 树（当前屏幕上显示的）和 workInProgress 树（正在构建的新树）。当 workInProgress 树构建完成后，通过指针切换成为新的 current 树。


优先级调度
Fiber 架构的核心优势是支持优先级调度——高优先级的更新（用户输入、动画）可以中断低优先级的更新（数据加载、后台同步）。

import { startTransition, useDeferredValue } from "react";

function SearchPage() {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query);

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    setQuery(e.target.value);
  };

  return (
    <div>
      <input value={query} onChange={handleChange} />
      <SearchResults query={deferredQuery} />
    </div>
  );
}


渲染批处理
React 18 引入了自动批处理（Automatic Batching），将同一事件循环中的多次状态更新合并为一次渲染。


import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  const [flag, setFlag] = useState(false);

  const handleClick = () => {
    setCount((c) => c + 1);
    setFlag((f) => !f);
  };

  const handleAsync = async () => {
    const data = await fetch("/api/data").then((r) => r.json());
    setCount(data.count);
    setFlag(data.flag);
  };

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={handleClick}>同步更新（自动批处理）</button>
      <button onClick={handleAsync}>异步更新（React 18 也批处理）</button>
    </div>
  );
}


小结
    

  • Virtual DOM 是 JavaScript 对象描述 UI 结构的抽象层，通过 diff 算法计算最小 DOM 变更。
    • 

  • React diff 算法通过同层比较、类型比较、Key 标识三大策略将复杂度从 O(n³) 降为 O(n)。
    • 

  • Key 必须使用稳定唯一标识符，避免使用 index 作为 key。
    • 

  • Fiber 架构实现了可中断渲染和优先级调度，高优先级更新不会被低优先级更新阻塞。
    • 

  • React 18 的自动批处理覆盖了所有场景（同步、异步、setTimeout），减少不必要的重渲染。
    •
