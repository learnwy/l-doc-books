DOM 与布局抖动

核心概念

DOM 修改本身不贵，贵的是它触发的样式计算、布局与绘制。局部更新（改一个类名）通常只影响子树，而修改会导致整页重新布局。最严重的反模式是"布局抖动"——在同一帧内交替进行 DOM 写入与布局属性读取（如 offsetHeight、getBoundingClientRect），每次读取都会强制浏览器立即同步布局，把可以批量完成的工作拆成多次。规避手段是读写分离：先把所有写入集中执行，再统一读取。批量操作则用 DocumentFragment、innerHTML 一次性写入或离屏节点减少重排次数。

DOM 操作的性能代价

DOM 操作是前端最常见的性能瓶颈之一。每次 DOM 修改都可能触发浏览器的样式计算、布局和绘制流程。虽然现代浏览器会尽量批量处理这些操作，但不当的代码模式会强制浏览器进行同步布局，导致严重的性能问题。

graph TD
    A[DOM 修改] --> B{浏览器是否能批处理?}
    B -->|是| C[累积变更]
    C --> D[下一帧统一处理]
    B -->|否: 读取布局属性| E[强制同步布局]
    E --> F[立即重新计算]
    F --> G[性能下降]

布局抖动（Layout Thrashing）

布局抖动是指在一帧内交替进行 DOM 写入和布局属性读取操作，导致浏览器被迫多次执行同步布局计算。这是前端最严重的性能反模式之一。

问题示例

function resizeAllCards(cards: HTMLElement[]): void {
  for (const card of cards) {
    const width = card.offsetWidth;
    card.style.height = `${width * 0.75}px`;
  }
}

上面的代码在循环中交替读取 offsetWidth（触发布局）和写入 style.height（使布局失效），导致每次迭代都触发一次强制布局。如果有 100 个卡片，就会触发 100 次布局计算。

sequenceDiagram
    participant JS as JavaScript
    participant B as 浏览器

    loop 每个卡片
        JS->>B: 读取 offsetWidth (强制布局)
        B->>B: 计算布局 ⚡
        JS->>B: 写入 style.height (布局失效)
    end
    Note over B: 100 个卡片 = 100 次布局计算!

正确做法：读写分离

function resizeAllCardsOptimized(cards: HTMLElement[]): void {
  const widths = cards.map((card) => card.offsetWidth);

  cards.forEach((card, i) => {
    card.style.height = `${widths[i] * 0.75}px`;
  });
}

触发布局的属性

以下属性和方法在读取时会触发强制布局（如果之前有未处理的样式变更）：

类别 属性/方法
元素几何 offsetTop/Left/Width/Height, clientTop/Left/Width/Height
滚动位置 scrollTop/Left/Width/Height
窗口尺寸 innerWidth/Height, outerWidth/Height
计算样式 getComputedStyle(), getBoundingClientRect()
焦点操作 focus()（某些场景下）
滚动操作 scrollTo(), scrollIntoView()

批量 DOM 操作优化

DocumentFragment

function renderList(items: string[], container: HTMLElement): void {
  const fragment = document.createDocumentFragment();

  for (const item of items) {
    const li = document.createElement('li');
    li.textContent = item;
    li.className = 'list-item';
    fragment.appendChild(li);
  }

  container.appendChild(fragment);
}

innerHTML 批量写入

function renderListFast(items: string[], container: HTMLElement): void {
  container.innerHTML = items.map((item) => `<li class="list-item">${escapeHTML(item)}</li>`).join('');
}

function escapeHTML(str: string): string {
  const div = document.createElement('div');
  div.textContent = str;
  return div.innerHTML;
}

离屏操作

function heavyDOMUpdate(container: HTMLElement): void {
  const parent = container.parentElement!;
  const next = container.nextSibling;

  parent.removeChild(container);

  for (let i = 0; i < 1000; i++) {
    const div = document.createElement('div');
    div.textContent = `Item ${i}`;
    container.appendChild(div);
  }

  parent.insertBefore(container, next);
}

requestAnimationFrame 调度

requestAnimationFrame（rAF）确保 DOM 操作在浏览器的下一次渲染周期前执行，与浏览器的渲染节奏同步。

class DOMBatcher {
  private reads: Array<() => void> = [];
  private writes: Array<() => void> = [];
  private scheduled = false;

  read(fn: () => void): void {
    this.reads.push(fn);
    this.schedule();
  }

  write(fn: () => void): void {
    this.writes.push(fn);
    this.schedule();
  }

  private schedule(): void {
    if (this.scheduled) return;
    this.scheduled = true;

    requestAnimationFrame(() => {
      const reads = this.reads.splice(0);
      const writes = this.writes.splice(0);

      reads.forEach((fn) => fn());
      writes.forEach((fn) => fn());

      this.scheduled = false;
    });
  }
}

const batcher = new DOMBatcher();

function animateElements(elements: HTMLElement[]): void {
  const positions: number[] = [];

  elements.forEach((el, i) => {
    batcher.read(() => {
      positions[i] = el.getBoundingClientRect().top;
    });
  });

  elements.forEach((el, i) => {
    batcher.write(() => {
      el.style.transform = `translateY(${positions[i] * 0.5}px)`;
    });
  });
}

虚拟滚动

当列表包含数千甚至数万条数据时，渲染所有 DOM 节点会导致严重的性能问题。虚拟滚动只渲染可视区域内的元素，大幅减少 DOM 节点数量。

基础虚拟滚动实现

interface VirtualListConfig {
  itemHeight: number;
  containerHeight: number;
  overscan: number;
  totalItems: number;
}

interface VirtualListState {
  startIndex: number;
  endIndex: number;
  offsetY: number;
  visibleItems: number[];
}

function calculateVirtualList(scrollTop: number, config: VirtualListConfig): VirtualListState {
  const { itemHeight, containerHeight, overscan, totalItems } = config;

  const startIndex = Math.max(0, Math.floor(scrollTop / itemHeight) - overscan);
  const visibleCount = Math.ceil(containerHeight / itemHeight);
  const endIndex = Math.min(totalItems - 1, startIndex + visibleCount + overscan * 2);

  const visibleItems: number[] = [];
  for (let i = startIndex; i <= endIndex; i++) {
    visibleItems.push(i);
  }

  return {
    startIndex,
    endIndex,
    offsetY: startIndex * itemHeight,
    visibleItems,
  };
}

React 虚拟滚动组件

import { useRef, useState, useCallback } from 'react';

interface VirtualListProps<T> {
  items: T[];
  itemHeight: number;
  containerHeight: number;
  renderItem: (item: T, index: number) => React.ReactNode;
  overscan?: number;
}

function VirtualList<T>({ items, itemHeight, containerHeight, renderItem, overscan = 5 }: VirtualListProps<T>) {
  const [scrollTop, setScrollTop] = useState(0);
  const containerRef = useRef<HTMLDivElement>(null);

  const totalHeight = items.length * itemHeight;
  const startIndex = Math.max(0, Math.floor(scrollTop / itemHeight) - overscan);
  const visibleCount = Math.ceil(containerHeight / itemHeight) + overscan * 2;
  const endIndex = Math.min(items.length, startIndex + visibleCount);

  const handleScroll = useCallback(() => {
    if (containerRef.current) {
      setScrollTop(containerRef.current.scrollTop);
    }
  }, []);

  const visibleItems = items.slice(startIndex, endIndex);

  return (
    <div ref={containerRef} onScroll={handleScroll} style={{ height: containerHeight, overflow: 'auto' }}>
      <div style={{ height: totalHeight, position: 'relative' }}>
        <div
          style={{
            position: 'absolute',
            top: startIndex * itemHeight,
            left: 0,
            right: 0,
          }}
        >
          {visibleItems.map((item, i) => (
            <div key={startIndex + i} style={{ height: itemHeight }}>
              {renderItem(item, startIndex + i)}
            </div>
          ))}
        </div>
      </div>
    </div>
  );
}

性能对比总结

操作模式 100 个元素 1,000 个元素 10,000 个元素
逐个 DOM 操作 5ms 50ms 800ms
DocumentFragment 2ms 8ms 60ms
innerHTML 1ms 5ms 40ms
虚拟滚动 1ms 1ms 1ms

小结

  • 布局抖动（Layout Thrashing）是交替读写布局属性导致的性能问题——解决方案是读写分离。
  • 批量 DOM 操作使用 DocumentFragment 或 innerHTML 比逐个操作快 10-20 倍。
  • requestAnimationFrame 确保 DOM 操作与浏览器渲染周期同步。
  • 大列表必须使用虚拟滚动，只渲染可视区域内的元素。
  • 避免在循环或高频回调中读取 offsetWidth、getBoundingClientRect 等布局属性。
