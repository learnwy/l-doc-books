性能指标与 Core Web Vitals

为什么需要以用户为中心的性能指标

传统的性能度量方式聚焦于技术指标——页面加载时间、DOMContentLoaded 事件触发时间等。但这些指标无法真实反映用户感知到的体验。一个页面可能在 2 秒内触发了 load 事件，但用户看到的仍然是白屏；另一个页面可能 load 事件在 5 秒后才触发，但用户在 1 秒内就已经看到了有意义的内容并可以开始交互。

Google 提出的 Core Web Vitals 从根本上改变了性能度量的视角——从"浏览器完成了什么"转向"用户体验到了什么"。



Core Web Vitals 三大核心指标
LCP — Largest Contentful Paint（最大内容绘制）
LCP 衡量的是从页面开始加载到视口内最大内容元素完成渲染的时间。"最大内容元素"通常是页面的主图片、标题文本块或视频封面。






评级
时间
用户感受





好
≤ 2.5s
页面加载迅速




需改善
2.5s–4s
略有等待感




差
> 4s
明显感觉到卡顿





LCP 考虑的元素类型包括：


    

  • <img> 元素
    • 

  • <svg> 内的 <image> 元素
    • 

  • <video> 元素的封面图
    • 

  • 通过 background-image 加载的元素
    • 

  • 包含文本节点的块级元素
    • 



const observer = new PerformanceObserver((list) => {
  const entries = list.getEntries();
  const lastEntry = entries[entries.length - 1];
  console.log('LCP:', lastEntry.startTime, 'ms');
  console.log('LCP Element:', lastEntry.element);
});

observer.observe({ type: 'largest-contentful-paint', buffered: true });
影响 LCP 的四大因素：


INP — Interaction to Next Paint（交互到下次绘制）
INP 取代了 FID（First Input Delay），衡量的是用户在整个页面生命周期内所有交互中响应最慢的那次交互延迟。与 FID 只测量第一次交互不同，INP 考量整体交互体验。






评级
时间
用户感受





好
≤ 200ms
交互即时响应




需改善
200–500ms
能感觉到轻微延迟




差
> 500ms
界面明显卡顿





INP 的度量涵盖三个阶段：


const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (entry.interactionId) {
      const duration = entry.duration;
      const inputDelay = entry.processingStart - entry.startTime;
      const processingTime = entry.processingEnd - entry.processingStart;
      const presentationDelay = entry.startTime + entry.duration - entry.processingEnd;

      console.log({
        type: entry.name,
        duration,
        inputDelay,
        processingTime,
        presentationDelay,
      });
    }
  }
});

observer.observe({ type: 'event', durationThreshold: 16, buffered: true });
CLS — Cumulative Layout Shift（累积布局偏移）
CLS 衡量页面在其整个生命周期内发生的意外布局偏移的累积分数。当一个可见元素在两帧之间改变了位置，就会产生布局偏移。注意：用户主动交互（如点击）后 500ms 内的布局变化不计入 CLS。






评级
分数
用户感受





好
≤ 0.1
页面稳定不跳动




需改善
0.1–0.25
偶尔有内容跳动




差
> 0.25
频繁的内容抖动





常见的 CLS 触发场景：


const observer = new PerformanceObserver((list) => {
  let clsScore = 0;

  for (const entry of list.getEntries()) {
    if (!entry.hadRecentInput) {
      clsScore += entry.value;
      console.log('Layout shift:', {
        value: entry.value,
        sources: entry.sources?.map((s) => ({
          node: s.node,
          previousRect: s.previousRect,
          currentRect: s.currentRect,
        })),
      });
    }
  }

  console.log('Cumulative CLS:', clsScore);
});

observer.observe({ type: 'layout-shift', buffered: true });

指标采集架构
在真实生产环境中，性能指标的采集需要一套完整的架构设计：


interface PerformanceMetrics {
  lcp: number;
  inp: number;
  cls: number;
  fcp: number;
  ttfb: number;
  url: string;
  timestamp: number;
  connectionType: string;
  deviceMemory: number;
}

function reportMetrics(metrics: PerformanceMetrics): void {
  const payload = JSON.stringify(metrics);

  if (navigator.sendBeacon) {
    navigator.sendBeacon('/api/metrics', payload);
  } else {
    fetch('/api/metrics', {
      method: 'POST',
      body: payload,
      keepalive: true,
    });
  }
}

function collectAndReport(): void {
  const metrics: Partial<PerformanceMetrics> = {
    url: window.location.href,
    timestamp: Date.now(),
    connectionType: (navigator as any).connection?.effectiveType ?? 'unknown',
    deviceMemory: (navigator as any).deviceMemory ?? 0,
  };

  new PerformanceObserver((list) => {
    const entry = list.getEntries().at(-1);
    if (entry) {
      metrics.lcp = entry.startTime;
      reportMetrics(metrics as PerformanceMetrics);
    }
  }).observe({ type: 'largest-contentful-paint', buffered: true });

  new PerformanceObserver((list) => {
    let cls = 0;
    for (const entry of list.getEntries()) {
      if (!(entry as any).hadRecentInput) cls += (entry as any).value;
    }
    metrics.cls = cls;
  }).observe({ type: 'layout-shift', buffered: true });
}


小结
    

  • Core Web Vitals 包含 LCP（加载）、INP（交互）、CLS（稳定性）三个核心指标，是以用户为中心的性能度量标准。
    • 

  • LCP 目标 ≤ 2.5s，影响因素包括服务器响应、资源加载延迟、客户端渲染。
    • 

  • INP 目标 ≤ 200ms，涵盖输入延迟、事件处理和呈现延迟三个阶段。
    • 

  • CLS 目标 ≤ 0.1，需要为动态内容预留空间并避免意外的布局偏移。
    • 

  • 使用 PerformanceObserver API 可以精确采集各项性能指标，结合 sendBeacon 实现可靠的数据上报。
