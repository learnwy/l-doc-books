度量与分析工具

性能优化的第一原则：度量先行

"你无法优化你无法度量的东西。"这句话是性能优化领域的核心原则。在开始任何优化工作之前，必须建立基线数据，确定优化目标，并在优化后验证效果。盲目的优化不仅可能浪费时间，还可能引入新的问题。

性能度量工具分为两大类：

实验室数据（Lab）

Lighthouse, WebPageTest, DevTools




真实用户数据（RUM）
采集真实用户在生产环境中的数据
Chrome UX Report, web-vitals, 自建 RUM







Chrome DevTools Performance 面板
Performance 面板是前端性能分析最常用也最强大的工具。它能记录页面在一段时间内的所有活动——JavaScript 执行、样式计算、布局、绘制、合成、网络请求等，并以时间线的形式可视化展示。

识别长任务
超过 50ms 的任务被定义为"长任务"（Long Task）。长任务会阻塞主线程，导致用户交互无法及时响应。在 Performance 面板中，长任务以红色三角标记显示。


const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    console.warn('Long Task detected:', {
      duration: `${entry.duration}ms`,
      startTime: `${entry.startTime}ms`,
      name: entry.name,
    });
  }
});

observer.observe({ type: 'longtask', buffered: true });

const measures = performance.getEntriesByType('measure');
for (const m of measures) {
  console.log(`${m.name}: ${m.duration.toFixed(2)}ms`);
}


Lighthouse 性能审计
Lighthouse 是 Google 开发的自动化审计工具，集成在 Chrome DevTools 中，也可以通过 CLI 和 Node.js API 使用。它从性能、无障碍、最佳实践、SEO 等多个维度评估页面质量。

CLI 集成到 CI/CD
import lighthouse from 'lighthouse';
import * as chromeLauncher from 'chrome-launcher';

interface LighthouseAudit {
  url: string;
  scores: {
    performance: number;
    accessibility: number;
    bestPractices: number;
    seo: number;
  };
  metrics: {
    fcp: number;
    lcp: number;
    tbt: number;
    cls: number;
    si: number;
  };
}

async function runAudit(url: string): Promise<LighthouseAudit> {
  const chrome = await chromeLauncher.launch({ chromeFlags: ['--headless'] });

  const result = await lighthouse(url, {
    port: chrome.port,
    output: 'json',
    onlyCategories: ['performance'],
    formFactor: 'mobile',
    throttling: {
      rttMs: 150,
      throughputKbps: 1638.4,
      cpuSlowdownMultiplier: 4,
    },
  });

  await chrome.kill();

  const { categories, audits } = result!.lhr;

  return {
    url,
    scores: {
      performance: categories.performance.score! * 100,
      accessibility: 0,
      bestPractices: 0,
      seo: 0,
    },
    metrics: {
      fcp: audits['first-contentful-paint'].numericValue!,
      lcp: audits['largest-contentful-paint'].numericValue!,
      tbt: audits['total-blocking-time'].numericValue!,
      cls: audits['cumulative-layout-shift'].numericValue!,
      si: audits['speed-index'].numericValue!,
    },
  };
}

async function ciPerformanceCheck(): Promise<void> {
  const audit = await runAudit('https://example.com');

  const thresholds = {
    performance: 90,
    lcp: 2500,
    tbt: 200,
    cls: 0.1,
  };

  const failures: string[] = [];

  if (audit.scores.performance < thresholds.performance) {
    failures.push(`Performance score ${audit.scores.performance} < ${thresholds.performance}`);
  }
  if (audit.metrics.lcp > thresholds.lcp) {
    failures.push(`LCP ${audit.metrics.lcp}ms > ${thresholds.lcp}ms`);
  }
  if (audit.metrics.tbt > thresholds.tbt) {
    failures.push(`TBT ${audit.metrics.tbt}ms > ${thresholds.tbt}ms`);
  }
  if (audit.metrics.cls > thresholds.cls) {
    failures.push(`CLS ${audit.metrics.cls} > ${thresholds.cls}`);
  }

  if (failures.length > 0) {
    console.error('Performance budget exceeded:');
    failures.forEach((f) => console.error(`  - ${f}`));
    process.exit(1);
  }

  console.log('All performance checks passed!');
}

web-vitals 库
Google 官方提供的 web-vitals 库是在生产环境中采集 Core Web Vitals 的最佳选择。它封装了复杂的 PerformanceObserver 逻辑，提供简洁的 API。


import { onLCP, onINP, onCLS, onFCP, onTTFB, type Metric } from 'web-vitals';

interface MetricReport {
  name: string;
  value: number;
  rating: 'good' | 'needs-improvement' | 'poor';
  delta: number;
  id: string;
  navigationType: string;
}

function sendToAnalytics(metric: Metric): void {
  const report: MetricReport = {
    name: metric.name,
    value: metric.value,
    rating: metric.rating,
    delta: metric.delta,
    id: metric.id,
    navigationType: metric.navigationType,
  };

  if (navigator.sendBeacon) {
    navigator.sendBeacon('/api/vitals', JSON.stringify(report));
  }
}

onLCP(sendToAnalytics);
onINP(sendToAnalytics);
onCLS(sendToAnalytics);
onFCP(sendToAnalytics);
onTTFB(sendToAnalytics);


Resource Timing API
Resource Timing API 提供了每个资源加载的详细时间分解，是分析资源加载瓶颈的利器。


interface ResourceMetrics {
  name: string;
  type: string;
  duration: number;
  dns: number;
  tcp: number;
  tls: number;
  ttfb: number;
  download: number;
  size: number;
  protocol: string;
}

function analyzeResources(): ResourceMetrics[] {
  const resources = performance.getEntriesByType('resource') as PerformanceResourceTiming[];

  return resources.map((r) => ({
    name: r.name.split('/').pop() ?? r.name,
    type: r.initiatorType,
    duration: Math.round(r.duration),
    dns: Math.round(r.domainLookupEnd - r.domainLookupStart),
    tcp: Math.round(r.connectEnd - r.connectStart),
    tls: r.secureConnectionStart > 0 ? Math.round(r.requestStart - r.secureConnectionStart) : 0,
    ttfb: Math.round(r.responseStart - r.requestStart),
    download: Math.round(r.responseEnd - r.responseStart),
    size: r.transferSize,
    protocol: r.nextHopProtocol,
  }));
}

function findSlowResources(threshold: number = 1000): ResourceMetrics[] {
  return analyzeResources()
    .filter((r) => r.duration > threshold)
    .sort((a, b) => b.duration - a.duration);
}

function getResourceSummary(): Record<string, { count: number; totalSize: number; totalDuration: number }> {
  const resources = analyzeResources();
  const summary: Record<string, { count: number; totalSize: number; totalDuration: number }> = {};

  for (const r of resources) {
    if (!summary[r.type]) {
      summary[r.type] = { count: 0, totalSize: 0, totalDuration: 0 };
    }
    summary[r.type].count++;
    summary[r.type].totalSize += r.size;
    summary[r.type].totalDuration += r.duration;
  }

  return summary;
}


构建自动化性能报告
将性能度量集成到开发流程中，可以实现性能的持续监控：


interface PerformanceReport {
  timestamp: string;
  url: string;
  device: 'mobile' | 'desktop';
  metrics: {
    lcp: number;
    inp: number;
    cls: number;
    fcp: number;
    ttfb: number;
    tbt: number;
  };
  resources: {
    total: number;
    totalSize: number;
    byType: Record<string, { count: number; size: number }>;
  };
  longTasks: number;
  score: number;
}

function calculateScore(metrics: PerformanceReport['metrics']): number {
  const weights = { lcp: 25, inp: 25, cls: 25, fcp: 10, ttfb: 10, tbt: 5 };
  const thresholds = { lcp: 2500, inp: 200, cls: 0.1, fcp: 1800, ttfb: 800, tbt: 200 };

  let totalScore = 0;

  for (const [key, weight] of Object.entries(weights)) {
    const value = metrics[key as keyof typeof metrics];
    const threshold = thresholds[key as keyof typeof thresholds];
    const ratio = Math.min(value / threshold, 2);
    const score = Math.max(0, 100 - ratio * 50);
    totalScore += score * (weight / 100);
  }

  return Math.round(totalScore);
}


小结
    

  • Chrome DevTools Performance 面板是最强大的前端性能分析工具，善用火焰图定位长任务和热点函数。
    • 

  • Lighthouse 提供自动化性能评审，可集成到 CI/CD 流程中实现性能守门。
    • 

  • WebPageTest 的瀑布图分析适合深入诊断资源加载问题。
    • 

  • web-vitals 库是生产环境采集 Core Web Vitals 的标准方案。
    • 

  • Resource Timing API 提供资源级别的时间分解，适合精确定位加载瓶颈。
    • 

  • 将性能度量自动化，建立持续监控体系，是性能优化长期有效的保障。
