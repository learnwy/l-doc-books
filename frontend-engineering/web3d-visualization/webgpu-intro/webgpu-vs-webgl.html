WebGPU 与 WebGL 对比

核心概念

WebGPU 和 WebGL 是两代 Web 图形 API，它们在设计哲学、性能模型和能力边界上有根本性差异。WebGL 基于 20 年前的 OpenGL ES 标准，采用全局状态机模型；WebGPU 借鉴现代 GPU API（Vulkan/Metal/D3D12），采用显式资源管理和管线状态对象模型。理解两者的差异对于评估迁移时机和技术选型至关重要。

两者最本质的区别在于状态管理模型：WebGL 维护一个全局状态机，每次 draw call 前需要设置大量状态（shader、buffer、texture、blend mode 等），驱动需要在每次调用时验证所有状态的一致性；WebGPU 将所有状态预编译为 Pipeline 对象，draw call 时只需绑定 Pipeline，消除了运行时验证开销。


渲染流程对比
同一个三角形渲染，两种 API 的实现方式体现了设计哲学的差异。


WebGL 实现：


const renderTriangleWebGL = (gl: WebGLRenderingContext): void => {
  const vertexShaderSource = `
    attribute vec2 aPosition;
    attribute vec3 aColor;
    varying vec3 vColor;
    void main() {
      gl_Position = vec4(aPosition, 0.0, 1.0);
      vColor = aColor;
    }
  `;

  const fragmentShaderSource = `
    precision mediump float;
    varying vec3 vColor;
    void main() {
      gl_FragColor = vec4(vColor, 1.0);
    }
  `;

  const program = createProgram(gl, vertexShaderSource, fragmentShaderSource);
  gl.useProgram(program);

  const vertices = new Float32Array([0.0, 0.5, 1.0, 0.0, 0.0, -0.5, -0.5, 0.0, 1.0, 0.0, 0.5, -0.5, 0.0, 0.0, 1.0]);

  const buffer = gl.createBuffer();
  gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
  gl.bufferData(gl.ARRAY_BUFFER, vertices, gl.STATIC_DRAW);

  const aPosition = gl.getAttribLocation(program, 'aPosition');
  gl.enableVertexAttribArray(aPosition);
  gl.vertexAttribPointer(aPosition, 2, gl.FLOAT, false, 20, 0);

  const aColor = gl.getAttribLocation(program, 'aColor');
  gl.enableVertexAttribArray(aColor);
  gl.vertexAttribPointer(aColor, 3, gl.FLOAT, false, 20, 8);

  gl.drawArrays(gl.TRIANGLES, 0, 3);
};
WebGPU 实现的关键区别：管线状态预编译、命令录制与提交分离、资源绑定通过 BindGroup。

Draw Call 瓶颈是 WebGL 最大的性能限制。一个典型的 WebGL 应用每帧 draw call 上限约 1000-3000 次，超过后 CPU 成为瓶颈。WebGPU 通过预编译管线和间接绘制，将这一上限提升到 10000-50000 次。


const benchmarkDrawCalls = (api: 'webgl' | 'webgpu', objectCount: number) => {
  const results = {
    webgl: {
      1000: '16ms (60fps)',
      5000: '45ms (22fps)',
      10000: '90ms (11fps)',
    },
    webgpu: {
      1000: '2ms (60fps)',
      5000: '8ms (60fps)',
      10000: '16ms (60fps)',
    },
  };
  return results[api][objectCount as keyof typeof results.webgl];
};

interface RenderBackend {
  init(canvas: HTMLCanvasElement): Promise<void>;
  createBuffer(data: Float32Array, usage: string): unknown;
  render(scene: SceneGraph): void;
  dispose(): void;
}

const createRenderer = async (canvas: HTMLCanvasElement): Promise<RenderBackend> => {
  if (navigator.gpu) {
    const backend = await createWebGPUBackend(canvas);
    return backend;
  }
  const gl = canvas.getContext('webgl2') ?? canvas.getContext('webgl');
  if (gl) {
    return createWebGLBackend(gl);
  }
  throw new Error('No GPU rendering support');
};

小结
    

  • WebGPU 和 WebGL 的核心区别在于状态管理模型：全局状态机 vs 管线状态对象
    • 

  • WebGPU 在 draw call 开销、计算能力和 CPU 占用方面有显著性能优势
    • 

  • 计算着色器是 WebGPU 的杀手级特性，解锁了浏览器端 GPGPU 能力
    • 

  • 迁移应采用渐进策略，通过抽象层同时支持两种后端
    • 

  • 新项目如果目标用户以 Chrome/Edge 为主，应优先考虑 WebGPU
    • 

  • 需要广泛浏览器兼容的项目，WebGL 仍是更安全的选择
    •
