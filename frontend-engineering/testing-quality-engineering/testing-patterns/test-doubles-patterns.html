测试替身模式

核心概念

测试替身（Test Doubles）是在测试中替代真实依赖的对象。Gerard Meszaros 在《xUnit Test Patterns》中定义了五种测试替身：Dummy、Stub、Spy、Mock 和 Fake。理解它们的区别和适用场景，是编写可靠、可维护测试的关键。

Dummy：占位对象
Dummy 对象仅用于满足函数签名中的必填参数，测试中不会真正使用它。


import { describe, it, expect } from 'vitest';

interface Logger {
  info(message: string): void;
  error(message: string): void;
}

interface Config {
  apiUrl: string;
  timeout: number;
}

class UserService {
  constructor(
    private logger: Logger,
    private config: Config,
  ) {}

  formatUserName(firstName: string, lastName: string): string {
    return `${firstName} ${lastName}`.trim();
  }
}

describe('Dummy 示例', () => {
  it('测试 formatUserName 时 logger 和 config 是 Dummy', () => {
    const dummyLogger = {} as Logger;
    const dummyConfig = {} as Config;

    const service = new UserService(dummyLogger, dummyConfig);

    expect(service.formatUserName('John', 'Doe')).toBe('John Doe');
  });
});
Stub：固定返回值
Stub 提供预设的返回值，控制被测代码的间接输入。


import { describe, it, expect, vi } from 'vitest';

interface PricingService {
  getPrice(productId: string): Promise<number>;
  getDiscount(userId: string): Promise<number>;
}

class OrderCalculator {
  constructor(private pricing: PricingService) {}

  async calculateTotal(productId: string, quantity: number, userId: string): Promise<number> {
    const price = await this.pricing.getPrice(productId);
    const discount = await this.pricing.getDiscount(userId);
    const subtotal = price * quantity;
    return Math.round(subtotal * (1 - discount) * 100) / 100;
  }
}

describe('Stub 示例', () => {
  it('stub 控制依赖返回值', async () => {
    const pricingStub: PricingService = {
      getPrice: vi.fn().mockResolvedValue(100),
      getDiscount: vi.fn().mockResolvedValue(0.1),
    };

    const calculator = new OrderCalculator(pricingStub);
    const total = await calculator.calculateTotal('p1', 3, 'u1');

    expect(total).toBe(270);
  });

  it('不同返回值测试不同场景', async () => {
    const pricingStub: PricingService = {
      getPrice: vi.fn().mockResolvedValue(50),
      getDiscount: vi.fn().mockResolvedValue(0),
    };

    const calculator = new OrderCalculator(pricingStub);
    const total = await calculator.calculateTotal('p2', 2, 'u1');

    expect(total).toBe(100);
  });

  it('stub 异常场景', async () => {
    const pricingStub: PricingService = {
      getPrice: vi.fn().mockRejectedValue(new Error('价格服务不可用')),
      getDiscount: vi.fn(),
    };

    const calculator = new OrderCalculator(pricingStub);

    await expect(calculator.calculateTotal('p1', 1, 'u1')).rejects.toThrow('价格服务不可用');
  });
});
Spy：监视调用
Spy 保留原有实现，同时记录调用信息。


import { describe, it, expect, vi, beforeEach } from 'vitest';

class EventBus {
  private handlers = new Map<string, Array<(...args: unknown[]) => void>>();

  on(event: string, handler: (...args: unknown[]) => void): void {
    const list = this.handlers.get(event) || [];
    list.push(handler);
    this.handlers.set(event, list);
  }

  emit(event: string, ...args: unknown[]): void {
    const list = this.handlers.get(event) || [];
    list.forEach((handler) => handler(...args));
  }
}

class UserActions {
  constructor(private eventBus: EventBus) {}

  login(userId: string): void {
    this.eventBus.emit('user:login', { userId, timestamp: Date.now() });
  }

  logout(userId: string): void {
    this.eventBus.emit('user:logout', { userId });
  }
}

describe('Spy 示例', () => {
  let eventBus: EventBus;
  let actions: UserActions;

  beforeEach(() => {
    eventBus = new EventBus();
    actions = new UserActions(eventBus);
  });

  it('spy 监视 emit 调用', () => {
    const emitSpy = vi.spyOn(eventBus, 'emit');

    actions.login('user-1');

    expect(emitSpy).toHaveBeenCalledTimes(1);
    expect(emitSpy).toHaveBeenCalledWith('user:login', expect.objectContaining({ userId: 'user-1' }));
  });

  it('spy 不改变原实现', () => {
    const handler = vi.fn();
    eventBus.on('user:login', handler);

    const emitSpy = vi.spyOn(eventBus, 'emit');
    actions.login('user-1');

    expect(emitSpy).toHaveBeenCalled();
    expect(handler).toHaveBeenCalledWith(expect.objectContaining({ userId: 'user-1' }));
  });

  it('spy 验证调用顺序', () => {
    const emitSpy = vi.spyOn(eventBus, 'emit');

    actions.login('user-1');
    actions.logout('user-1');

    expect(emitSpy).toHaveBeenNthCalledWith(1, 'user:login', expect.anything());
    expect(emitSpy).toHaveBeenNthCalledWith(2, 'user:logout', expect.anything());
  });
});
Mock：替换并验证
Mock 完全替换原有实现，同时验证交互是否符合预期。


import { describe, it, expect, vi } from 'vitest';

interface NotificationService {
  sendEmail(to: string, subject: string, body: string): Promise<boolean>;
  sendSMS(to: string, message: string): Promise<boolean>;
}

class AlertManager {
  constructor(private notification: NotificationService) {}

  async sendCriticalAlert(email: string, phone: string, message: string): Promise<void> {
    await this.notification.sendEmail(email, '紧急告警', message);
    await this.notification.sendSMS(phone, `[紧急] ${message}`);
  }

  async sendInfoAlert(email: string, message: string): Promise<void> {
    await this.notification.sendEmail(email, '信息通知', message);
  }
}

describe('Mock 示例', () => {
  it('紧急告警应同时发送邮件和短信', async () => {
    const mockNotification: NotificationService = {
      sendEmail: vi.fn().mockResolvedValue(true),
      sendSMS: vi.fn().mockResolvedValue(true),
    };

    const manager = new AlertManager(mockNotification);
    await manager.sendCriticalAlert('admin@test.com', '13800138000', '服务器宕机');

    expect(mockNotification.sendEmail).toHaveBeenCalledWith('admin@test.com', '紧急告警', '服务器宕机');
    expect(mockNotification.sendSMS).toHaveBeenCalledWith('13800138000', '[紧急] 服务器宕机');
  });

  it('信息通知只发送邮件', async () => {
    const mockNotification: NotificationService = {
      sendEmail: vi.fn().mockResolvedValue(true),
      sendSMS: vi.fn(),
    };

    const manager = new AlertManager(mockNotification);
    await manager.sendInfoAlert('user@test.com', '部署完成');

    expect(mockNotification.sendEmail).toHaveBeenCalledOnce();
    expect(mockNotification.sendSMS).not.toHaveBeenCalled();
  });
});
Fake：简化实现
Fake 是一个可工作的简化实现，比 Stub 更真实但比真实依赖更简单。


import { describe, it, expect, beforeEach } from 'vitest';

interface CacheService {
  get<T>(key: string): Promise<T | null>;
  set<T>(key: string, value: T, ttlMs?: number): Promise<void>;
  delete(key: string): Promise<void>;
  clear(): Promise<void>;
}

class FakeCache implements CacheService {
  private store = new Map<string, { value: unknown; expiresAt: number | null }>();

  async get<T>(key: string): Promise<T | null> {
    const entry = this.store.get(key);
    if (!entry) return null;
    if (entry.expiresAt && Date.now() > entry.expiresAt) {
      this.store.delete(key);
      return null;
    }
    return entry.value as T;
  }

  async set<T>(key: string, value: T, ttlMs?: number): Promise<void> {
    this.store.set(key, {
      value,
      expiresAt: ttlMs ? Date.now() + ttlMs : null,
    });
  }

  async delete(key: string): Promise<void> {
    this.store.delete(key);
  }

  async clear(): Promise<void> {
    this.store.clear();
  }
}

class ProductCatalog {
  constructor(private cache: CacheService) {}

  async getProduct(id: string): Promise<{ id: string; name: string } | null> {
    const cached = await this.cache.get<{ id: string; name: string }>(`product:${id}`);
    if (cached) return cached;

    const product = { id, name: `商品 ${id}` };
    await this.cache.set(`product:${id}`, product, 60_000);
    return product;
  }
}

describe('Fake 示例', () => {
  let cache: FakeCache;
  let catalog: ProductCatalog;

  beforeEach(() => {
    cache = new FakeCache();
    catalog = new ProductCatalog(cache);
  });

  it('首次获取应缓存结果', async () => {
    const product = await catalog.getProduct('1');
    expect(product).toEqual({ id: '1', name: '商品 1' });

    const cached = await cache.get('product:1');
    expect(cached).toEqual({ id: '1', name: '商品 1' });
  });

  it('第二次获取应从缓存返回', async () => {
    await catalog.getProduct('1');

    await cache.set('product:1', { id: '1', name: '已修改' });

    const product = await catalog.getProduct('1');
    expect(product?.name).toBe('已修改');
  });

  it('清除缓存后应重新获取', async () => {
    await catalog.getProduct('1');
    await cache.clear();

    const product = await catalog.getProduct('1');
    expect(product?.name).toBe('商品 1');
  });
});
选择决策指南
常见误区与纠正
误区一：Mock 一切
过度 Mock 导致测试与实现紧密耦合。应只 Mock 外部依赖（网络、数据库、文件系统），内部纯函数直接测试。


误区二：混淆 Stub 和 Mock
Stub 控制输入（"当调用 A 时返回 B"），Mock 验证输出（"应该调用了 A"）。两者目的不同。


误区三：Spy 后忘记恢复
使用 vi.spyOn() 后必须调用 vi.restoreAllMocks() 恢复原实现，否则影响后续测试。


误区四：Fake 过于复杂
Fake 应该是简化版本，如果 Fake 的复杂度接近真实实现，说明测试粒度可能需要调整。


小结
测试替身是控制和验证依赖行为的核心工具。


核心要点回顾：


    

  • Dummy 仅满足参数签名，不参与测试逻辑
    • 

  • Stub 提供固定返回值，控制被测代码的间接输入
    • 

  • Spy 保留原实现同时记录调用，适合验证交互
    • 

  • Mock 完全替换实现并验证调用，是最常用的替身
    • 

  • Fake 提供简化但可工作的实现，如内存数据库
    • 

  • 只 Mock 外部依赖，避免过度耦合
    • 

  • 测试结束后恢复所有 Mock，保持测试隔离
