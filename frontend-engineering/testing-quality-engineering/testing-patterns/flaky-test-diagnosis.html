Flaky 测试诊断

核心概念

Flaky 测试是指在代码未变更的情况下时而通过、时而失败的测试。它们是测试体系中最隐蔽的破坏者——侵蚀团队对测试结果的信任、浪费 CI 资源、降低开发效率。识别、诊断和修复 Flaky 测试是维护健康测试体系的关键实践。

Flaky 测试的危害

graph TD
    FLAKY["Flaky 测试"] --> TRUST["🔻 信任侵蚀<br/>团队忽视测试失败"]
    FLAKY --> WASTE["💰 资源浪费<br/>反复重试 CI"]
    FLAKY --> SLOW["🐢 效率降低<br/>等待不确定的结果"]
    FLAKY --> HIDE["🐛 掩盖真实 Bug<br/>失败被当成 Flaky 忽略"]

    TRUST --> SKIP["开始跳过失败测试"]
    SKIP --> QUALITY["质量下降"]

常见原因分类

类别 原因 症状
时序依赖 依赖 setTimeout/setInterval 本地通过，CI 偶发失败
测试顺序依赖 共享全局状态 单独运行通过，全部运行失败
异步竞态 未正确等待异步操作 偶发 "element not found"
外部依赖 依赖真实 API/数据库 网络波动时失败
日期时间 依赖当前时间 特定时间段失败
随机数据 faker 生成边界值 偶发断言失败
内存泄漏 测试未清理订阅/定时器 后续测试受影响
环境差异 不同 OS 行为不同 本地通过，CI 失败

检测方法

方法一：多次重复运行

for i in {1..20}; do
  npx vitest run src/utils.test.ts --reporter=verbose 2>&1 | tail -1
done

npx vitest run --retry 3

方法二：随机化测试顺序

import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    sequence: {
      shuffle: true,
    },
  },
});

方法三：CI 失败追踪

name: Flaky Detection
on:
  schedule:
    - cron: '0 2 * * *'

jobs:
  flaky-check:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        run: [1, 2, 3, 4, 5]
    steps:
      - uses: actions/checkout@v4
      - run: pnpm install
      - run: npx vitest run --reporter=json --outputFile=results-${{ matrix.run }}.json
      - uses: actions/upload-artifact@v4
        with:
          name: test-results-${{ matrix.run }}
          path: results-*.json

修复策略

修复一：时序问题

import { describe, it, expect, vi, beforeEach, afterEach } from 'vitest';

function delayedValue<T>(value: T, ms: number): Promise<T> {
  return new Promise((resolve) => setTimeout(() => resolve(value), ms));
}

describe('修复时序问题', () => {
  beforeEach(() => {
    vi.useFakeTimers();
  });

  afterEach(() => {
    vi.useRealTimers();
  });

  it('使用 fake timers 代替真实等待', async () => {
    const promise = delayedValue('hello', 5000);
    vi.advanceTimersByTime(5000);
    const result = await promise;
    expect(result).toBe('hello');
  });
});

修复二：异步竞态

import { render, screen, waitFor } from '@testing-library/react'
import { describe, it, expect, vi, beforeEach } from 'vitest'
import { useState, useEffect } from 'react'

function UserProfile({ userId }: { userId: string }) {
  const [name, setName] = useState<string>('')
  const [loading, setLoading] = useState(true)

  useEffect(() => {
    fetch(`/api/users/${userId}`)
      .then((res) => res.json())
      .then((data) => {
        setName(data.name)
        setLoading(false)
      })
  }, [userId])

  if (loading) return <div>加载中...</div>
  return <div>用户: {name}</div>
}

describe('修复异步竞态', () => {
  beforeEach(() => {
    vi.stubGlobal('fetch', vi.fn().mockResolvedValue({
      ok: true,
      json: () => Promise.resolve({ name: 'Alice' }),
    }))
  })

  it('使用 waitFor 而非固定延时', async () => {
    render(<UserProfile userId="1" />)

    await waitFor(() => {
      expect(screen.getByText('用户: Alice')).toBeInTheDocument()
    })
  })

  it('使用 findBy 自带等待', async () => {
    render(<UserProfile userId="1" />)

    const element = await screen.findByText('用户: Alice')
    expect(element).toBeInTheDocument()
  })
})

修复三：测试顺序依赖

import { describe, it, expect, beforeEach } from 'vitest';

let globalCounter = 0;

function increment(): number {
  return ++globalCounter;
}

describe('修复测试顺序依赖', () => {
  beforeEach(() => {
    globalCounter = 0;
  });

  it('第一个测试', () => {
    expect(increment()).toBe(1);
  });

  it('第二个测试不受第一个影响', () => {
    expect(increment()).toBe(1);
  });
});

修复四：日期时间依赖

import { describe, it, expect, vi, beforeEach, afterEach } from 'vitest';

function isBusinessHours(): boolean {
  const hour = new Date().getHours();
  return hour >= 9 && hour < 18;
}

function formatRelativeTime(date: Date): string {
  const now = new Date();
  const diffMs = now.getTime() - date.getTime();
  const diffMinutes = Math.floor(diffMs / 60000);

  if (diffMinutes < 1) return '刚刚';
  if (diffMinutes < 60) return `${diffMinutes} 分钟前`;
  const diffHours = Math.floor(diffMinutes / 60);
  if (diffHours < 24) return `${diffHours} 小时前`;
  return `${Math.floor(diffHours / 24)} 天前`;
}

describe('修复日期时间依赖', () => {
  beforeEach(() => {
    vi.useFakeTimers();
  });

  afterEach(() => {
    vi.useRealTimers();
  });

  it('固定时间测试工作时间', () => {
    vi.setSystemTime(new Date('2024-06-15T10:00:00'));
    expect(isBusinessHours()).toBe(true);

    vi.setSystemTime(new Date('2024-06-15T20:00:00'));
    expect(isBusinessHours()).toBe(false);
  });

  it('固定时间测试相对时间', () => {
    vi.setSystemTime(new Date('2024-06-15T12:00:00'));

    expect(formatRelativeTime(new Date('2024-06-15T11:55:00'))).toBe('5 分钟前');
    expect(formatRelativeTime(new Date('2024-06-15T10:00:00'))).toBe('2 小时前');
    expect(formatRelativeTime(new Date('2024-06-14T12:00:00'))).toBe('1 天前');
  });
});

修复五：随机数据边界

import { describe, it, expect, beforeEach } from 'vitest';
import { faker } from '@faker-js/faker';

function validateAge(age: number): boolean {
  return age >= 0 && age <= 150;
}

describe('修复随机数据问题', () => {
  beforeEach(() => {
    faker.seed(42);
  });

  it('使用 seed 固定随机数据', () => {
    const age = faker.number.int({ min: 0, max: 150 });
    expect(validateAge(age)).toBe(true);
  });

  it('或者对随机结果做范围断言', () => {
    const randomAge = faker.number.int({ min: -10, max: 200 });
    if (randomAge >= 0 && randomAge <= 150) {
      expect(validateAge(randomAge)).toBe(true);
    } else {
      expect(validateAge(randomAge)).toBe(false);
    }
  });
});

修复六：清理副作用

import { describe, it, expect, vi, beforeEach, afterEach } from 'vitest';

describe('修复未清理的副作用', () => {
  let intervalId: ReturnType<typeof setInterval> | undefined;
  const listeners: Array<() => void> = [];

  afterEach(() => {
    if (intervalId) {
      clearInterval(intervalId);
      intervalId = undefined;
    }
    listeners.forEach((cleanup) => cleanup());
    listeners.length = 0;
    vi.restoreAllMocks();
  });

  it('定时器需要清理', () => {
    const fn = vi.fn();
    vi.useFakeTimers();

    intervalId = setInterval(fn, 1000);
    vi.advanceTimersByTime(3000);

    expect(fn).toHaveBeenCalledTimes(3);

    vi.useRealTimers();
    clearInterval(intervalId);
    intervalId = undefined;
  });
});

Flaky 测试管理流程

flowchart TD
    DETECT["检测到 Flaky 测试"] --> TAG["标记为 Flaky<br/>添加 @flaky 标签"]
    TAG --> TRACK["追踪到看板"]
    TRACK --> ANALYZE["分析根因"]
    ANALYZE --> FIX["修复"]
    FIX --> VERIFY["验证(多次运行)"]
    VERIFY --> PASS{连续通过 20 次？}
    PASS -->|是| REMOVE["移除 Flaky 标签"]
    PASS -->|否| ANALYZE

临时隔离 Flaky 测试

import { describe, it, expect } from 'vitest';

describe('已知 Flaky 测试', () => {
  it.skip('偶发失败 - 等待修复 (#1234)', () => {
    // ...
  });

  it.todo('修复异步竞态后重新启用');
});

Vitest retry 配置

import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    retry: 2,
    reporters: ['verbose'],
  },
});

预防措施

预防措施 具体做法
使用 Fake Timers 所有涉及时间的测试用 vi.useFakeTimers()
避免 sleep/wait 用 waitFor / findBy 替代固定延时
隔离全局状态 beforeEach 重置，afterEach 清理
Mock 外部依赖 不依赖真实 API/数据库/文件系统
固定随机种子 faker.seed() 保证可重现
随机化运行顺序 sequence.shuffle: true 暴露顺序依赖
CI 重复运行 定期多次运行检测新增 Flaky
清理副作用 定时器、事件监听器、全局修改在 afterEach 恢复

常见误区与纠正

误区一：重试就是解决方案

retry 只是掩盖问题。真正的解决方案是找到根因并修复。retry 应仅作为临时过渡手段。

误区二：跳过就完事了

skip 让 Flaky 测试从视线中消失，但问题依然存在。应立即分析并修复，skip 不超过一个迭代。

误区三：只在本地测试

Flaky 测试往往只在 CI 环境暴露（资源受限、并行度不同）。必须在 CI 中检测。

误区四：认为少量 Flaky 可以接受

即使 1% 的 Flaky 率，在 1000 个测试中也意味着每次运行有 10 个可能失败。零容忍是唯一目标。

小结

Flaky 测试是测试体系健康度的重要指标。

核心要点回顾：

  • 时序依赖是最常见的 Flaky 根因，用 Fake Timers 解决
  • 异步竞态用 waitFor/findBy 替代固定延时
  • 全局状态在 beforeEach/afterEach 中重置和清理
  • 日期时间用 vi.setSystemTime() 固定
  • 随机数据用 faker.seed() 保证可重现
  • 定期多次运行检测新增 Flaky 测试
  • Flaky 测试零容忍，retry 仅作临时过渡
  • 用 sequence.shuffle: true 主动暴露顺序依赖
