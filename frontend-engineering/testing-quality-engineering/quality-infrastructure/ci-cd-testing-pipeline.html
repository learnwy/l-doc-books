CI/CD 测试流水线

核心概念

CI/CD 测试流水线是将测试自动化融入持续集成和持续部署流程的核心基础设施。一个设计良好的流水线能在代码合并前快速发现问题，同时通过并行化、缓存和分层策略保持高效率。本文涵盖流水线设计、并行化策略、缓存优化和失败处理的完整实践。

GitHub Actions 完整配置
name: CI Pipeline
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  lint-and-typecheck:
    name: 静态检查
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile

      - name: TypeScript 类型检查
        run: pnpm -r typecheck

      - name: ESLint 检查
        run: pnpm run lint

  unit-tests:
    name: 单元测试
    needs: lint-and-typecheck
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile

      - name: 运行单元测试
        run: pnpm run test:run -- --coverage

      - name: 上传覆盖率
        uses: actions/upload-artifact@v4
        with:
          name: coverage-report
          path: coverage/

  integration-tests:
    name: 集成测试
    needs: lint-and-typecheck
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile

      - name: 运行集成测试
        run: pnpm run test:integration

  build:
    name: 构建
    needs: [unit-tests, integration-tests]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile

      - name: 构建
        run: pnpm run build

      - name: 上传构建产物
        uses: actions/upload-artifact@v4
        with:
          name: build-output
          path: dist/

  e2e-tests:
    name: E2E 测试
    needs: build
    runs-on: ubuntu-latest
    strategy:
      matrix:
        shard: [1, 2, 3, 4]
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile

      - name: 安装 Playwright 浏览器
        run: npx playwright install --with-deps chromium

      - name: 下载构建产物
        uses: actions/download-artifact@v4
        with:
          name: build-output
          path: dist/

      - name: 运行 E2E 测试（分片 ${{ matrix.shard }}/4）
        run: npx playwright test --shard=${{ matrix.shard }}/4

      - name: 上传测试结果
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report-${{ matrix.shard }}
          path: playwright-report/

依赖缓存
- uses: actions/setup-node@v4
  with:
    node-version: 20
    cache: 'pnpm'
Playwright 浏览器缓存
- name: 获取 Playwright 版本
  id: playwright-version
  run: echo "version=$(npx playwright --version)" >> $GITHUB_OUTPUT

- uses: actions/cache@v4
  with:
    path: ~/.cache/ms-playwright
    key: playwright-${{ steps.playwright-version.outputs.version }}

- name: 安装 Playwright（缓存未命中时）
  if: steps.cache.outputs.cache-hit != 'true'
  run: npx playwright install --with-deps chromium
构建缓存

  with:
    path: |
      node_modules/.vite

    restore-keys: |
      build-cache-${{ hashFiles('pnpm-lock.yaml') }}-
      build-cache-

package.json 脚本设计
{
  "scripts": {
    "lint": "eslint . --ext .ts,.tsx --max-warnings 0",
    "typecheck": "tsc --noEmit",
    "test": "vitest",
    "test:run": "vitest run",
    "test:unit": "vitest run src/**/*.test.ts",
    "test:integration": "vitest run src/**/*.integration.test.ts",
    "test:coverage": "vitest run --coverage",
    "test:e2e": "playwright test",
    "test:e2e:ui": "playwright test --ui",
    "test:ci": "pnpm run typecheck && pnpm run lint && pnpm run test:run --coverage && pnpm run build",
    "build": "vite build"
  }
}

常见误区与纠正
误区一：所有测试在一个 Job 中
将所有测试放在单个 Job 中无法利用并行能力。应按测试类型拆分为独立 Job，并行执行。


误区二：不区分失败类型
Flaky 失败和真实失败需要不同的处理策略。使用 retry 处理 Flaky，但真实失败必须阻止合并。


误区三：忽略缓存
不使用缓存导致每次 CI 都从头安装依赖和浏览器，浪费大量时间。


误区四：E2E 测试阻塞所有 PR
E2E 测试较慢，可以配置为非阻塞检查（仅在合并到 main 时强制要求）。


小结
CI/CD 测试流水线是质量保障的自动化核心。


核心要点回顾：


    

  • 分层执行：静态检查 → 单元 → 集成 → 构建 → E2E
    • 

  • 并行化：Vitest 多线程 + Playwright 分片显著缩短耗时
    • 

  • 缓存策略覆盖依赖、浏览器和构建产物
    • 

  • 失败即停（fail-fast）及早终止无效流水线
    • 

  • 自动重试处理 Flaky，但需追踪并修复
    • 

  • 失败时自动保存截图和报告作为排查证据
    • 

  • 目标：总流水线时间 < 10 分钟，Flaky 率 0%
    •
