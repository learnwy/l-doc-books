性能测试

核心概念

性能测试确保应用在速度、响应性和稳定性方面满足用户期望和业务要求。涵盖前端性能（加载速度、交互响应）、API 性能（吞吐量、延迟）和系统性能（负载能力、资源使用）。现代前端性能测试以 Core Web Vitals 为核心指标，结合 Lighthouse 自动化评分和性能预算，构建完整的性能保障体系。

Lighthouse 自动化测试
Playwright + Lighthouse
import { test, expect } from '@playwright/test';
import { playAudit } from 'playwright-lighthouse';

test.describe('Lighthouse 性能审计', () => {
  test('首页性能评分', async ({ page }) => {
    await page.goto('/');

    const result = await playAudit({
      page,
      thresholds: {
        performance: 90,
        accessibility: 90,
        'best-practices': 90,
        seo: 80,
      },
      port: 9222,
    });

    expect(result.lhr.categories.performance.score * 100).toBeGreaterThanOrEqual(90);
  });
});
Lighthouse CLI 脚本
import { execSync } from 'child_process';
import { readFileSync } from 'fs';

interface LighthouseResult {
  categories: {
    performance: { score: number };
    accessibility: { score: number };
    'best-practices': { score: number };
    seo: { score: number };
  };
  audits: {
    'largest-contentful-paint': { numericValue: number };
    'cumulative-layout-shift': { numericValue: number };
    'total-blocking-time': { numericValue: number };
  };
}

function runLighthouse(url: string): LighthouseResult {
  execSync(
    `npx lighthouse ${url} --output=json --output-path=./lighthouse-result.json --chrome-flags="--headless --no-sandbox"`,
    { stdio: 'inherit' },
  );
  return JSON.parse(readFileSync('./lighthouse-result.json', 'utf-8'));
}

function checkThresholds(result: LighthouseResult): void {
  const thresholds = {
    performance: 90,
    lcp: 2500,
    cls: 0.1,
    tbt: 300,
  };

  const perfScore = result.categories.performance.score * 100;
  const lcp = result.audits['largest-contentful-paint'].numericValue;
  const cls = result.audits['cumulative-layout-shift'].numericValue;
  const tbt = result.audits['total-blocking-time'].numericValue;

  const failures: string[] = [];

  if (perfScore < thresholds.performance) {
    failures.push(`性能评分 ${perfScore} < ${thresholds.performance}`);
  }
  if (lcp > thresholds.lcp) {
    failures.push(`LCP ${lcp}ms > ${thresholds.lcp}ms`);
  }
  if (cls > thresholds.cls) {
    failures.push(`CLS ${cls} > ${thresholds.cls}`);
  }
  if (tbt > thresholds.tbt) {
    failures.push(`TBT ${tbt}ms > ${thresholds.tbt}ms`);
  }

  if (failures.length > 0) {
    console.error('性能检查失败:');
    failures.forEach((f) => console.error(`  ❌ ${f}`));
    process.exit(1);
  }

  console.log('✅ 性能检查通过');
}

自定义包体积检查
import { statSync, readdirSync } from 'fs';
import { join } from 'path';

interface BundleSizeResult {
  file: string;
  sizeKB: number;
  limitKB: number;
  pass: boolean;
}

function checkBundleSize(distDir: string): BundleSizeResult[] {
  const limits: Record<string, number> = {
    main: 200,
    vendor: 150,
    styles: 50,
  };

  const files = readdirSync(join(distDir, 'assets'));
  const results: BundleSizeResult[] = [];

  for (const file of files) {
    const filePath = join(distDir, 'assets', file);
    const stat = statSync(filePath);
    const sizeKB = Math.round(stat.size / 1024);

    for (const [pattern, limit] of Object.entries(limits)) {
      if (file.includes(pattern)) {
        results.push({
          file,
          sizeKB,
          limitKB: limit,
          pass: sizeKB <= limit,
        });
      }
    }
  }

  return results;
}
Vitest 基准测试
import { bench, describe } from 'vitest';

function sortBubble(arr: number[]): number[] {
  const result = [...arr];
  for (let i = 0; i < result.length; i++) {
    for (let j = 0; j < result.length - i - 1; j++) {
      if (result[j] > result[j + 1]) {
        [result[j], result[j + 1]] = [result[j + 1], result[j]];
      }
    }
  }
  return result;
}

function sortNative(arr: number[]): number[] {
  return [...arr].sort((a, b) => a - b);
}

describe('排序算法基准测试', () => {
  const data = Array.from({ length: 1000 }, () => Math.random() * 1000);

  bench('冒泡排序', () => {
    sortBubble(data);
  });

  bench('原生 Array.sort', () => {
    sortNative(data);
  });
});

Playwright 性能测试
import { test, expect } from '@playwright/test';

test('页面加载性能', async ({ page }) => {
  await page.goto('/');

  const performanceMetrics = await page.evaluate(() => {
    const nav = performance.getEntriesByType('navigation')[0] as PerformanceNavigationTiming;
    const paint = performance.getEntriesByType('paint');
    const fcp = paint.find((p) => p.name === 'first-contentful-paint');

    return {
      ttfb: nav.responseStart - nav.requestStart,
      domContentLoaded: nav.domContentLoadedEventEnd - nav.startTime,
      load: nav.loadEventEnd - nav.startTime,
      fcp: fcp?.startTime ?? 0,
    };
  });

  expect(performanceMetrics.ttfb).toBeLessThan(800);
  expect(performanceMetrics.fcp).toBeLessThan(1800);
  expect(performanceMetrics.domContentLoaded).toBeLessThan(3000);
  expect(performanceMetrics.load).toBeLessThan(5000);
});

test('交互响应性能', async ({ page }) => {
  await page.goto('/products');

  const searchStart = Date.now();
  await page.getByPlaceholder('搜索商品').fill('键盘');
  await page.getByRole('button', { name: '搜索' }).click();
  await page.waitForSelector('[data-testid="search-results"]');
  const searchDuration = Date.now() - searchStart;

  expect(searchDuration).toBeLessThan(2000);
});
常见误区与纠正
误区一：只在开发环境测性能
开发环境的性能与生产环境差异巨大。必须在生产构建上测试，使用 pnpm run build 后的产物。


误区二：只看 Lighthouse 评分
Lighthouse 评分是综合指标，需要结合具体的 LCP、CLS、TBT 等子指标分析瓶颈。


误区三：不设性能预算
没有预算就没有退化检测。每次 PR 都应自动检查包体积和关键性能指标。


误区四：性能测试不在 CI 中运行
性能应像功能一样在 CI 中持续监控，防止渐进式退化。


小结
性能测试是用户体验保障的核心环节。


核心要点回顾：


    

  • Core Web Vitals（LCP/INP/CLS）是性能的核心度量
    • 

  • Lighthouse 自动化评分集成到 CI，设定最低分阈值
    • 

  • 包体积预算防止 JS/CSS 膨胀，用 size-limit 自动检查
    • 

  • Vitest bench 做函数级基准测试，比较算法效率
    • 

  • Playwright 测量真实页面加载和交互响应时间
    • 

  • 性能预算覆盖时间、体积和请求数三个维度
    • 

  • 在生产构建上测试，开发环境数据不可靠
    • 

  • CI 持续监控性能，防止渐进式退化
