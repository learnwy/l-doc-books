测试类型全景

核心概念

测试类型按粒度和目标可分为多个层次，从最底层的单元测试到最顶层的端到端测试。每种类型关注不同的质量维度，团队需要根据项目特点和风险分布组合使用。

按测试范围分类
1. 单元测试（Unit Tests）
测试最小的可测试单元，通常是单个函数或方法。


function add(a: number, b: number): number {
  return a + b;
}

test('add', () => {
  expect(add(1, 2)).toBe(3);
  expect(add(-1, 1)).toBe(0);
});
2. 组件测试（Component Tests）
测试单个组件的行为和渲染。


import { render, screen, fireEvent } from '@testing-library/react'
import Button from './Button'

test('Button renders and handles click', () => {
  const handleClick = vi.fn()
  render(<Button onClick={handleClick}>Click me</Button>)

  expect(screen.getByText('Click me')).toBeInTheDocument()
  fireEvent.click(screen.getByText('Click me'))
  expect(handleClick).toHaveBeenCalledTimes(1)
})
3. 集成测试（Integration Tests）
测试多个组件或模块一起工作。


import { render, screen, waitFor } from '@testing-library/react'
import userEvent from '@testing-library/user-event'
import LoginForm from './LoginForm'
import { AuthProvider } from './AuthContext'

test('LoginForm works with AuthProvider', async () => {
  const user = userEvent.setup()
  render(
    <AuthProvider>
      <LoginForm />
    </AuthProvider>
  )

  await user.type(screen.getByLabelText('Email'), 'alice@example.com')
  await user.type(screen.getByLabelText('Password'), 'password123')
  await user.click(screen.getByText('Login'))

  await waitFor(() => {
    expect(screen.getByText('Welcome!')).toBeInTheDocument()
  })
})
4. E2E 测试（End-to-End Tests）
测试整个应用从用户角度的完整流程。


import { test, expect } from '@playwright/test';

test('complete checkout flow', async ({ page }) => {
  await page.goto('/');

  // Add item to cart
  await page.click('[data-testid="add-to-cart"]:first-child');

  // Go to cart
  await page.click('[data-testid="cart-link"]');

  // Proceed to checkout
  await page.click('[data-testid="checkout-button"]');

  // Fill shipping info
  await page.fill('[data-testid="shipping-name"]', 'Alice');
  await page.fill('[data-testid="shipping-address"]', '123 Main St');

  // Place order
  await page.click('[data-testid="place-order-button"]');

  // Verify success
  await expect(page.locator('[data-testid="order-success"]')).toBeVisible();
});
按测试目的分类
1. 功能测试（Functional Tests）
验证功能是否按预期工作。


test('user can create todo', async () => {
  const user = userEvent.setup()
  render(<TodoApp />)

  await user.type(screen.getByLabelText('New todo'), 'Buy milk')
  await user.click(screen.getByText('Add'))

  expect(screen.getByText('Buy milk')).toBeInTheDocument()
})
2. 性能测试（Performance Tests）
验证应用的性能指标。


import { test, expect } from '@playwright/test';

test('page load time', async ({ page }) => {
  const startTime = Date.now();
  await page.goto('/');
  const loadTime = Date.now() - startTime;

  expect(loadTime).toBeLessThan(2000); // Should load in under 2 seconds
});

test('LCP score', async ({ page }) => {
  await page.goto('/');
  const lcp = await page.evaluate(() => {
    return new Promise((resolve) => {
      new PerformanceObserver((list) => {
        const entries = list.getEntries();
        const lastEntry = entries[entries.length - 1];
        resolve(lastEntry.startTime);
      }).observe({ entryTypes: ['largest-contentful-paint'] });
    });
  });

  expect(lcp).toBeLessThan(2500); // LCP < 2.5s is good
});
3. 安全测试（Security Tests）
验证应用的安全性。


import { test, expect } from '@playwright/test';

test('XSS protection', async ({ page }) => {
  await page.goto('/comment');

  // Try to inject XSS
  await page.fill('[data-testid="comment-input"]', '<script>alert("XSS")</script>');
  await page.click('[data-testid="submit-comment"]');

  // Verify script is not executed
  const comment = page.locator('[data-testid="comment"]');
  await expect(comment).toContainText('&lt;script&gt;alert("XSS")&lt;/script&gt;');
});

test('SQL injection protection', async ({ request }) => {
  const response = await request.post('/api/users', {
    data: {
      email: "' OR '1'='1",
      password: 'anything',
    },
  });

  expect(response.ok()).toBeFalsy();
  expect(response.status()).toBe(401);
});
4. 可访问性测试（Accessibility Tests）
验证应用对残障用户的友好性。


import { render, screen } from '@testing-library/react'
import { axe, toHaveNoViolations } from 'jest-axe'
import LoginForm from './LoginForm'

expect.extend(toHaveNoViolations)

test('LoginForm is accessible', async () => {
  const { container } = render(<LoginForm />)
  const results = await axe(container)
  expect(results).toHaveNoViolations()
})

test('form has proper labels', () => {
  render(<LoginForm />)
  expect(screen.getByLabelText('Email')).toBeInTheDocument()
  expect(screen.getByLabelText('Password')).toBeInTheDocument()
})
小结
    

  • 静态分析是成本最低的质量手段，应在 CI 中强制执行
    • 

  • 单元测试关注函数和组件的正确性，追求高速反馈
    • 

  • 集成测试验证模块间的交互和数据流动
    • 

  • 端到端测试从用户视角验证完整流程
    • 

  • 视觉回归和性能测试是专项维度的补充
    • 

  • 不同测试类型互补而非替代，需要根据项目风险合理分配比例
