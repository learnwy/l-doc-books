TDD 与 BDD

核心概念

TDD（Test-Driven Development，测试驱动开发）和 BDD（Behavior-Driven Development，行为驱动开发）是两种以测试为核心的开发方法论。TDD 从技术视角出发，通过"红-绿-重构"循环驱动代码设计；BDD 从业务行为出发，用自然语言描述期望行为，弥合开发与业务之间的沟通鸿沟。两者并非对立，而是互补的实践。

TDD 完整示例：实现密码验证器
第一轮：最小长度验证


import { describe, it, expect } from 'vitest';

interface ValidationResult {
  valid: boolean;
  errors: string[];
}

function validatePassword(password: string): ValidationResult {
  const errors: string[] = [];

  if (password.length < 8) {
    errors.push('密码长度至少为 8 个字符');
  }

  return { valid: errors.length === 0, errors };
}

describe('validatePassword - 第一轮', () => {
  it('短于 8 个字符应返回无效', () => {
    const result = validatePassword('abc');
    expect(result.valid).toBe(false);
    expect(result.errors).toContain('密码长度至少为 8 个字符');
  });

  it('等于 8 个字符应返回有效', () => {
    const result = validatePassword('12345678');
    expect(result.valid).toBe(true);
    expect(result.errors).toHaveLength(0);
  });
});
第二轮：添加大写字母验证


function validatePassword(password: string): ValidationResult {
  const errors: string[] = [];

  if (password.length < 8) {
    errors.push('密码长度至少为 8 个字符');
  }

  if (!/[A-Z]/.test(password)) {
    errors.push('密码必须包含至少一个大写字母');
  }

  return { valid: errors.length === 0, errors };
}

describe('validatePassword - 第二轮', () => {
  it('无大写字母应返回无效', () => {
    const result = validatePassword('abcdefgh');
    expect(result.valid).toBe(false);
    expect(result.errors).toContain('密码必须包含至少一个大写字母');
  });

  it('包含大写字母且长度足够应返回有效', () => {
    const result = validatePassword('Abcdefgh');
    expect(result.valid).toBe(true);
  });
});
第三轮：添加特殊字符验证并重构


type PasswordRule = {
  test: (password: string) => boolean;
  message: string;
};

const passwordRules: PasswordRule[] = [
  {
    test: (p) => p.length >= 8,
    message: '密码长度至少为 8 个字符',
  },
  {
    test: (p) => /[A-Z]/.test(p),
    message: '密码必须包含至少一个大写字母',
  },
  {
    test: (p) => /[0-9]/.test(p),
    message: '密码必须包含至少一个数字',
  },
  {
    test: (p) => /[!@#$%^&*]/.test(p),
    message: '密码必须包含至少一个特殊字符',
  },
];

function validatePassword(password: string): ValidationResult {
  const errors = passwordRules.filter((rule) => !rule.test(password)).map((rule) => rule.message);

  return { valid: errors.length === 0, errors };
}

describe('validatePassword - 完整测试', () => {
  it('空密码应返回所有错误', () => {
    const result = validatePassword('');
    expect(result.valid).toBe(false);
    expect(result.errors).toHaveLength(4);
  });

  it('强密码应通过所有规则', () => {
    const result = validatePassword('MyP@ss123');
    expect(result.valid).toBe(true);
    expect(result.errors).toHaveLength(0);
  });

  it('缺少特殊字符应提示', () => {
    const result = validatePassword('MyPass123');
    expect(result.valid).toBe(false);
    expect(result.errors).toContain('密码必须包含至少一个特殊字符');
  });

  it('多个规则不满足应返回多个错误', () => {
    const result = validatePassword('abc');
    expect(result.errors.length).toBeGreaterThanOrEqual(3);
  });
});
三角法（Triangulation）
三角法是 TDD 中推动泛化实现的技术。当一个测试用例不足以驱动出通用实现时，添加第二个用例来"三角定位"正确实现。


import { describe, it, expect } from 'vitest';

function fibonacci(n: number): number {
  if (n <= 0) return 0;
  if (n === 1) return 1;
  return fibonacci(n - 1) + fibonacci(n - 2);
}

describe('fibonacci - 三角法驱动', () => {
  it('fib(0) = 0', () => {
    expect(fibonacci(0)).toBe(0);
  });

  it('fib(1) = 1', () => {
    expect(fibonacci(1)).toBe(1);
  });

  it('fib(2) = 1（第一次三角化）', () => {
    expect(fibonacci(2)).toBe(1);
  });

  it('fib(3) = 2（第二次三角化，驱动递归实现）', () => {
    expect(fibonacci(3)).toBe(2);
  });

  it('fib(10) = 55（验证通用性）', () => {
    expect(fibonacci(10)).toBe(55);
  });
});
TDD 的进阶技巧
由外向内 TDD（Outside-In）
import { describe, it, expect, vi } from 'vitest';

interface OrderItem {
  productId: string;
  quantity: number;
  price: number;
}

interface Order {
  id: string;
  items: OrderItem[];
  total: number;
  status: 'pending' | 'confirmed' | 'shipped';
}

interface OrderRepository {
  save(order: Omit<Order, 'id'>): Promise<Order>;
  findById(id: string): Promise<Order | null>;
}

interface InventoryService {
  checkStock(productId: string, quantity: number): Promise<boolean>;
  reserve(productId: string, quantity: number): Promise<void>;
}

class OrderService {
  constructor(
    private orderRepo: OrderRepository,
    private inventory: InventoryService,
  ) {}

  async createOrder(items: OrderItem[]): Promise<Order> {
    for (const item of items) {
      const inStock = await this.inventory.checkStock(item.productId, item.quantity);
      if (!inStock) {
        throw new Error(`商品 ${item.productId} 库存不足`);
      }
    }

    const total = items.reduce((sum, item) => sum + item.price * item.quantity, 0);

    for (const item of items) {
      await this.inventory.reserve(item.productId, item.quantity);
    }

    return this.orderRepo.save({ items, total, status: 'pending' });
  }
}

describe('OrderService - 由外向内 TDD', () => {
  const mockRepo: OrderRepository = {
    save: vi.fn().mockImplementation(async (order) => ({
      ...order,
      id: 'order-1',
    })),
    findById: vi.fn(),
  };

  const mockInventory: InventoryService = {
    checkStock: vi.fn().mockResolvedValue(true),
    reserve: vi.fn().mockResolvedValue(undefined),
  };

  it('库存充足时应成功创建订单', async () => {
    const service = new OrderService(mockRepo, mockInventory);
    const items: OrderItem[] = [{ productId: 'p1', quantity: 2, price: 100 }];

    const order = await service.createOrder(items);

    expect(order.id).toBe('order-1');
    expect(order.total).toBe(200);
    expect(order.status).toBe('pending');
    expect(mockInventory.reserve).toHaveBeenCalledWith('p1', 2);
  });

  it('库存不足时应抛出异常', async () => {
    vi.mocked(mockInventory.checkStock).mockResolvedValueOnce(false);

    const service = new OrderService(mockRepo, mockInventory);
    const items: OrderItem[] = [{ productId: 'p1', quantity: 100, price: 50 }];

    await expect(service.createOrder(items)).rejects.toThrow('库存不足');
  });
});

用 Vitest 实现 BDD 风格单元测试
import { describe, it, expect, beforeEach } from 'vitest';

interface CartItem {
  name: string;
  price: number;
  quantity: number;
}

class ShoppingCart {
  private items: CartItem[] = [];

  addItem(name: string, price: number, quantity: number): void {
    const existing = this.items.find((item) => item.name === name);
    if (existing) {
      existing.quantity += quantity;
    } else {
      this.items.push({ name, price, quantity });
    }
  }

  getTotal(): number {
    return this.items.reduce((sum, item) => sum + item.price * item.quantity, 0);
  }

  getItemCount(): number {
    return this.items.reduce((sum, item) => sum + item.quantity, 0);
  }

  applyDiscount(percent: number): number {
    return Math.round(this.getTotal() * (1 - percent / 100));
  }
}

describe('Feature: 购物车管理', () => {
  let cart: ShoppingCart;

  beforeEach(() => {
    cart = new ShoppingCart();
  });

  describe('Scenario: 添加商品到购物车', () => {
    it('Given 购物车为空 / When 添加两件商品 / Then 总价正确', () => {
      cart.addItem('机械键盘', 599, 1);
      cart.addItem('无线鼠标', 199, 1);

      expect(cart.getItemCount()).toBe(2);
      expect(cart.getTotal()).toBe(798);
    });
  });

  describe('Scenario: 修改商品数量', () => {
    it('Given 购物车中有 1 件键盘 / When 再添加 2 件 / Then 总价为 3 倍', () => {
      cart.addItem('机械键盘', 599, 1);
      cart.addItem('机械键盘', 599, 2);

      expect(cart.getItemCount()).toBe(3);
      expect(cart.getTotal()).toBe(1797);
    });
  });

  describe('Scenario Outline: 折扣码', () => {
    const discountCases = [
      { total: 1000, percent: 10, expected: 900 },
      { total: 500, percent: 20, expected: 400 },
      { total: 200, percent: 50, expected: 100 },
    ];

    discountCases.forEach(({ total, percent, expected }) => {
      it(`给定总价 ${total}，折扣 ${percent}%，应为 ${expected}`, () => {
        cart.addItem('测试商品', total, 1);
        expect(cart.applyDiscount(percent)).toBe(expected);
      });
    });
  });
});

TDD 与 BDD 的结合使用
在实际项目中，最佳实践是将两者结合：BDD 定义宏观业务行为，TDD 驱动微观代码实现。


实战：BDD 定义行为 → TDD 驱动实现
import { describe, it, expect, vi, beforeEach } from 'vitest';

interface NotificationService {
  send(userId: string, message: string): Promise<void>;
}

interface UserRepository {
  findById(id: string): Promise<{ id: string; name: string; email: string } | null>;
}

class WelcomeService {
  constructor(
    private userRepo: UserRepository,
    private notification: NotificationService,
  ) {}

  async welcomeUser(userId: string): Promise<string> {
    const user = await this.userRepo.findById(userId);
    if (!user) throw new Error('用户不存在');

    const message = `欢迎你, ${user.name}！`;
    await this.notification.send(userId, message);
    return message;
  }
}

describe('Feature: 新用户欢迎', () => {
  let service: WelcomeService;
  let mockUserRepo: UserRepository;
  let mockNotification: NotificationService;

  beforeEach(() => {
    mockUserRepo = {
      findById: vi.fn(),
    };
    mockNotification = {
      send: vi.fn().mockResolvedValue(undefined),
    };
    service = new WelcomeService(mockUserRepo, mockNotification);
  });

  describe('Scenario: 已存在用户收到欢迎消息', () => {
    it('Given 用户 Alice 存在 / When 触发欢迎 / Then 发送欢迎消息', async () => {
      vi.mocked(mockUserRepo.findById).mockResolvedValue({
        id: '1',
        name: 'Alice',
        email: 'alice@test.com',
      });

      const message = await service.welcomeUser('1');

      expect(message).toBe('欢迎你, Alice！');
      expect(mockNotification.send).toHaveBeenCalledWith('1', '欢迎你, Alice！');
    });
  });

  describe('Scenario: 用户不存在时抛出异常', () => {
    it('Given 用户不存在 / When 触发欢迎 / Then 抛出错误', async () => {
      vi.mocked(mockUserRepo.findById).mockResolvedValue(null);

      await expect(service.welcomeUser('999')).rejects.toThrow('用户不存在');
      expect(mockNotification.send).not.toHaveBeenCalled();
    });
  });
});
常见误区与纠正
误区一：TDD 让开发速度变慢
TDD 前期确实多了写测试的时间，但长期来看：减少了调试时间、降低了回归缺陷率、提升了重构信心。研究表明 TDD 项目的缺陷密度降低 40-80%。


误区二：BDD 就是写 Gherkin 文件
Gherkin 只是 BDD 的工具之一。BDD 的核心是"三方会谈"（Three Amigos）——产品、开发、测试共同讨论需求，用具体的示例（Example）驱动理解。


误区三：必须 100% 使用 TDD
TDD 是工具，不是教条。以下场景适合 TDD：核心业务逻辑、算法、工具函数。以下场景可以不用：原型验证、UI 样式调整、配置文件。


误区四：TDD 不需要设计
TDD 不是"先写测试就不用设计"。在开始 TDD 循环前，应该对模块接口和职责有基本的规划。TDD 帮助验证和演进设计，而不是替代设计。


小结
TDD 和 BDD 是提升代码质量和团队协作效率的强力实践。


核心要点回顾：


    

  • TDD 遵循红-绿-重构循环，每个循环保持小步前进
    • 

  • 三角法用多个测试用例驱动泛化实现
    • 

  • 由外向内 TDD 先定义外层接口，逐步实现内层依赖
    • 

  • BDD 用自然语言描述业务行为，促进团队沟通
    •
