测试金字塔

核心概念

测试金字塔（Test Pyramid）由 Mike Cohn 在《Succeeding with Agile》中提出，是指导测试分层策略的经典模型。它定义了不同类型测试在数量、速度、成本和信心之间的平衡关系。理解并正确应用测试金字塔，是构建高质量测试体系的基础。

单元测试层
单元测试是金字塔的基础，覆盖独立函数、纯逻辑和数据转换。它们不依赖外部系统，执行速度极快。


纯函数测试
import { describe, it, expect } from 'vitest';

interface CartItem {
  name: string;
  price: number;
  quantity: number;
}

function calculateCartTotal(items: CartItem[], taxRate: number): number {
  const subtotal = items.reduce((sum, item) => sum + item.price * item.quantity, 0);
  return Math.round(subtotal * (1 + taxRate) * 100) / 100;
}

function applyDiscount(total: number, discountPercent: number): number {
  if (discountPercent < 0 || discountPercent > 100) {
    throw new RangeError('折扣百分比必须在 0-100 之间');
  }
  return Math.round(total * (1 - discountPercent / 100) * 100) / 100;
}

describe('calculateCartTotal', () => {
  it('应正确计算含税总价', () => {
    const items: CartItem[] = [
      { name: '键盘', price: 299, quantity: 1 },
      { name: '鼠标', price: 99, quantity: 2 },
    ];
    expect(calculateCartTotal(items, 0.1)).toBe(546.7);
  });

  it('空购物车返回零', () => {
    expect(calculateCartTotal([], 0.1)).toBe(0);
  });

  it('零税率不加税', () => {
    const items: CartItem[] = [{ name: '显示器', price: 2000, quantity: 1 }];
    expect(calculateCartTotal(items, 0)).toBe(2000);
  });
});

describe('applyDiscount', () => {
  it('应正确应用折扣', () => {
    expect(applyDiscount(100, 20)).toBe(80);
  });

  it('无效折扣率抛出异常', () => {
    expect(() => applyDiscount(100, -5)).toThrow(RangeError);
    expect(() => applyDiscount(100, 150)).toThrow('折扣百分比必须在 0-100 之间');
  });
});
类方法测试
import { describe, it, expect } from 'vitest';

class PriceFormatter {
  private locale: string;
  private currency: string;

  constructor(locale: string, currency: string) {
    this.locale = locale;
    this.currency = currency;
  }

  format(amount: number): string {
    return new Intl.NumberFormat(this.locale, {
      style: 'currency',
      currency: this.currency,
    }).format(amount);
  }

  parse(formatted: string): number {
    const cleaned = formatted.replace(/[^\d.-]/g, '');
    return parseFloat(cleaned);
  }
}

describe('PriceFormatter', () => {
  const formatter = new PriceFormatter('zh-CN', 'CNY');

  it('应格式化为人民币', () => {
    expect(formatter.format(1234.5)).toContain('1,234.50');
  });

  it('应从格式化字符串中解析数值', () => {
    expect(formatter.parse('¥1,234.50')).toBe(1234.5);
  });
});
集成测试层
集成测试验证多个模块之间的协作，包括组件与 API、服务与数据库等交互场景。


服务层集成测试
import { describe, it, expect, beforeEach, afterEach } from 'vitest';

interface User {
  id: string;
  name: string;
  email: string;
  role: 'admin' | 'user';
}

interface UserRepository {
  save(user: Omit<User, 'id'>): Promise<User>;
  findById(id: string): Promise<User | null>;
  findByEmail(email: string): Promise<User | null>;
  deleteById(id: string): Promise<void>;
}

class UserService {
  constructor(private repo: UserRepository) {}

  async register(name: string, email: string): Promise<User> {
    const existing = await this.repo.findByEmail(email);
    if (existing) throw new Error('邮箱已存在');
    return this.repo.save({ name, email, role: 'user' });
  }

  async getProfile(id: string): Promise<User> {
    const user = await this.repo.findById(id);
    if (!user) throw new Error('用户不存在');
    return user;
  }
}

class InMemoryUserRepository implements UserRepository {
  private store = new Map<string, User>();
  private counter = 0;

  async save(data: Omit<User, 'id'>): Promise<User> {
    const user: User = { ...data, id: String(++this.counter) };
    this.store.set(user.id, user);
    return user;
  }

  async findById(id: string): Promise<User | null> {
    return this.store.get(id) ?? null;
  }

  async findByEmail(email: string): Promise<User | null> {
    for (const user of this.store.values()) {
      if (user.email === email) return user;
    }
    return null;
  }

  async deleteById(id: string): Promise<void> {
    this.store.delete(id);
  }
}

describe('UserService 集成测试', () => {
  let service: UserService;
  let repo: InMemoryUserRepository;

  beforeEach(() => {
    repo = new InMemoryUserRepository();
    service = new UserService(repo);
  });

  it('注册后应能查询到用户', async () => {
    const user = await service.register('Alice', 'alice@test.com');
    const profile = await service.getProfile(user.id);
    expect(profile.name).toBe('Alice');
    expect(profile.email).toBe('alice@test.com');
  });

  it('重复邮箱注册应抛出异常', async () => {
    await service.register('Alice', 'alice@test.com');
    await expect(service.register('Bob', 'alice@test.com')).rejects.toThrow('邮箱已存在');
  });

  it('查询不存在的用户应抛出异常', async () => {
    await expect(service.getProfile('999')).rejects.toThrow('用户不存在');
  });
});
E2E 测试层
E2E 测试模拟真实用户操作，验证完整的业务流程。


import { test, expect } from '@playwright/test';

test.describe('用户注册与登录流程', () => {
  test('新用户应能完成注册并登录', async ({ page }) => {
    await page.goto('/register');

    await page.getByLabel('用户名').fill('testuser');
    await page.getByLabel('邮箱').fill('test@example.com');
    await page.getByLabel('密码').fill('SecureP@ss123');
    await page.getByLabel('确认密码').fill('SecureP@ss123');
    await page.getByRole('button', { name: '注册' }).click();

    await expect(page).toHaveURL('/login');
    await expect(page.getByText('注册成功')).toBeVisible();

    await page.getByLabel('邮箱').fill('test@example.com');
    await page.getByLabel('密码').fill('SecureP@ss123');
    await page.getByRole('button', { name: '登录' }).click();

    await expect(page).toHaveURL('/dashboard');
    await expect(page.getByText('欢迎, testuser')).toBeVisible();
  });

  test('无效凭据应显示错误信息', async ({ page }) => {
    await page.goto('/login');

    await page.getByLabel('邮箱').fill('wrong@example.com');
    await page.getByLabel('密码').fill('wrongpassword');
    await page.getByRole('button', { name: '登录' }).click();

    await expect(page.getByRole('alert')).toContainText('邮箱或密码错误');
    await expect(page).toHaveURL('/login');
  });
});

冰淇淋锥（Ice Cream Cone）是最常见的反模式——E2E 测试最多，单元测试最少。

决策指南：选择哪层测试
常见误区与纠正
误区一：追求各层均等分布
每层测试应按金字塔结构递减。均等分布意味着投入大量资源在高成本的 E2E 测试上，ROI 极低。


误区二：单元测试可以替代一切
单元测试无法发现模块间的集成问题。两个独立正确的模块组合在一起可能出错，只有集成测试能捕获这类缺陷。


误区三：E2E 覆盖一切就够了
E2E 测试慢、脆弱、难以维护。当 E2E 测试失败时，排查问题的成本远高于单元测试。E2E 应仅覆盖核心业务路径。


误区四：100% 覆盖率等于高质量
高覆盖率不等于高质量测试。没有有效断言的测试只会提高覆盖率数字，但不能发现真正的缺陷。


小结
测试金字塔是构建可持续测试策略的核心框架。


核心要点回顾：


    

  • 单元测试为基础，数量最多、速度最快、成本最低
    • 

  • 集成测试覆盖模块间协作，是发现集成缺陷的关键层
    • 

  • E2E 测试只覆盖核心用户流程，数量要严格控制
    • 

  • 冰淇淋锥是最常见的反模式，导致 CI 慢、维护高、反馈延迟
    • 

  • 测试奖杯模型更适合前端项目，强调集成测试的投资回报比
    • 

  • 根据项目类型（前端/后端）调整各层比例
    • 

  • 静态分析（TypeScript + ESLint）是零成本的质量保障底线
    • 

  • 选择测试层级时，优先考虑能以最低成本给出最高信心的层
    •
