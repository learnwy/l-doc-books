快照测试

核心概念

快照测试（Snapshot Testing）是一种回归测试技术，通过序列化组件的渲染输出并保存为基准文件，后续运行时与基准对比来检测意外变化。它特别适合 UI 组件测试，能快速捕获渲染结构的变更，但需要合理使用以避免维护负担。

工作原理

文件快照
import { describe, it, expect } from 'vitest'
import { render } from '@testing-library/react'

interface ButtonProps {
  variant?: 'primary' | 'secondary' | 'danger'
  size?: 'sm' | 'md' | 'lg'
  disabled?: boolean
  children: React.ReactNode
}

function Button({ variant = 'primary', size = 'md', disabled = false, children }: ButtonProps) {
  return (
    <button
      className={`btn btn-${variant} btn-${size}`}
      disabled={disabled}
    >
      {children}
    </button>
  )
}

describe('Button 快照测试', () => {
  it('默认按钮', () => {
    const { container } = render(<Button>点击</Button>)
    expect(container).toMatchSnapshot()
  })

  it('主要按钮 - 大号', () => {
    const { container } = render(
      <Button variant="primary" size="lg">提交</Button>
    )
    expect(container).toMatchSnapshot()
  })

  it('禁用的危险按钮', () => {
    const { container } = render(
      <Button variant="danger" disabled>删除</Button>
    )
    expect(container).toMatchSnapshot()
  })
})

内联快照
内联快照将期望值直接写在测试代码中，首次运行时自动填充。


import { describe, it, expect } from 'vitest'

interface BadgeProps {
  status: 'success' | 'warning' | 'error'
  children: React.ReactNode
}

function Badge({ status, children }: BadgeProps) {
  return <span className={`badge badge-${status}`}>{children}</span>
}

describe('Badge 内联快照', () => {
  it('成功状态', () => {
    const { container } = render(<Badge status="success">通过</Badge>)
    expect(container.innerHTML).toMatchInlineSnapshot(
      `"<span class=\\"badge badge-success\\">通过</span>"`
    )
  })

  it('错误状态', () => {
    const { container } = render(<Badge status="error">失败</Badge>)
    expect(container.innerHTML).toMatchInlineSnapshot(
      `"<span class=\\"badge badge-error\\">失败</span>"`
    )
  })
})
文件系统快照
import { describe, it, expect } from 'vitest';

function generateConfig(env: 'development' | 'production'): string {
  const config = {
    apiUrl: env === 'production' ? 'https://api.prod.com' : 'http://localhost:3000',
    debug: env === 'development',
    logLevel: env === 'production' ? 'error' : 'debug',
    features: {
      analytics: env === 'production',
      devtools: env === 'development',
    },
  };
  return JSON.stringify(config, null, 2);
}

describe('配置生成器', () => {
  it('开发环境配置', async () => {
    const config = generateConfig('development');
    await expect(config).toMatchFileSnapshot('./snapshots/dev-config.json');
  });

  it('生产环境配置', async () => {
    const config = generateConfig('production');
    await expect(config).toMatchFileSnapshot('./snapshots/prod-config.json');
  });
});
数据结构快照
快照测试不限于 UI 组件，也适用于验证复杂数据结构。


import { describe, it, expect } from 'vitest';

interface TreeNode {
  name: string;
  children?: TreeNode[];
}

function buildMenuTree(routes: Array<{ path: string; label: string }>): TreeNode {
  const root: TreeNode = { name: 'root', children: [] };

  for (const route of routes) {
    const segments = route.path.split('/').filter(Boolean);
    let current = root;

    for (let i = 0; i < segments.length; i++) {
      const segment = segments[i];
      let child = current.children?.find((c) => c.name === segment);
      if (!child) {
        child = { name: segment, children: [] };
        current.children = current.children || [];
        current.children.push(child);
      }
      current = child;
    }

    const leaf = current.children?.find((c) => c.name === route.label);
    if (!leaf) {
      current.children = current.children || [];
      current.children.push({ name: route.label });
    }
  }

  return root;
}

describe('菜单树构建', () => {
  it('从路由生成菜单树', () => {
    const routes = [
      { path: '/dashboard', label: '仪表板' },
      { path: '/users/list', label: '用户列表' },
      { path: '/users/roles', label: '角色管理' },
      { path: '/settings/general', label: '基本设置' },
      { path: '/settings/security', label: '安全设置' },
    ];

    const tree = buildMenuTree(routes);
    expect(tree).toMatchSnapshot();
  });
});
自定义序列化器
import { expect } from 'vitest';

class Money {
  constructor(
    public amount: number,
    public currency: string,
  ) {}

  toString(): string {
    return `${this.currency} ${this.amount.toFixed(2)}`;
  }
}

expect.addSnapshotSerializer({
  serialize(val: Money): string {
    return `Money { ${val.currency} ${val.amount.toFixed(2)} }`;
  },
  test(val: unknown): val is Money {
    return val instanceof Money;
  },
});

describe('Money 快照', () => {
  it('使用自定义序列化器', () => {
    const price = new Money(99.9, 'CNY');
    expect(price).toMatchInlineSnapshot(`Money { CNY 99.90 }`);
  });
});
处理动态内容
动态内容（时间戳、随机 ID）会导致快照每次运行都不同。需要在测试中将其固定。


模拟时间
import { describe, it, expect, vi, beforeEach, afterEach } from 'vitest';

interface Notification {
  id: string;
  message: string;
  createdAt: string;
}

function createNotification(message: string): Notification {
  return {
    id: crypto.randomUUID(),
    message,
    createdAt: new Date().toISOString(),
  };
}

describe('Notification 快照', () => {
  beforeEach(() => {
    vi.useFakeTimers();
    vi.setSystemTime(new Date('2024-06-15T10:00:00Z'));

    vi.stubGlobal('crypto', {
      randomUUID: vi.fn().mockReturnValue('fixed-uuid-1234'),
    });
  });

  afterEach(() => {
    vi.useRealTimers();
    vi.unstubAllGlobals();
  });

  it('创建通知', () => {
    const notification = createNotification('新消息');
    expect(notification).toMatchInlineSnapshot(`
      {
        "createdAt": "2024-06-15T10:00:00.000Z",
        "id": "fixed-uuid-1234",
        "message": "新消息",
      }
    `);
  });
});
使用 expect.any 替代动态值
import { describe, it, expect } from 'vitest';

describe('属性级别匹配', () => {
  it('使用 toMatchObject + expect.any', () => {
    const event = {
      id: crypto.randomUUID(),
      type: 'click',
      timestamp: Date.now(),
      payload: { x: 100, y: 200 },
    };

    expect(event).toMatchObject({
      id: expect.any(String),
      type: 'click',
      timestamp: expect.any(Number),
      payload: { x: 100, y: 200 },
    });
  });
});

何时使用快照测试
适合快照的场景
    

  • 稳定的 UI 组件（按钮、徽章、卡片）
    • 

  • 序列化输出（JSON 配置、API 响应）
    • 

  • 生成代码（模板引擎输出）
    • 

  • 错误信息格式
    • 



不适合快照的场景
    

  • 大型页面组件（快照过大难以审查）
    • 

  • 频繁变更的 UI（每次改动都需更新）
    • 

  • 包含大量动态内容的组件
    • 

  • 业务逻辑验证
    • 



常见误区与纠正
误区一：快照越大越好
大型快照文件（100+ 行）几乎不可能被有效审查。当快照更新时，开发者倾向于直接 vitest -u 而不审查内容，失去了快照测试的意义。


误区二：快照可以替代单元测试
快照只能检测"变了没有"，不能判断"对不对"。一个错误的组件首次运行也会生成快照，但这个快照本身就是错的。


误区三：快照更新不需要审查
每次快照更新都应该在代码评审中仔细检查 .snap 文件的 diff。如果审查者无法理解变更的原因，说明快照测试可能不适合这个场景。


误区四：所有组件都应该有快照
只为稳定的、结构重要的组件添加快照测试。频繁变化的组件使用快照只会增加维护成本。


小结
快照测试是 UI 回归检测的高效工具，但必须谨慎使用。


核心要点回顾：


    

  • 文件快照存储在 __snapshots__/，适合较大输出
    • 

  • 内联快照嵌入测试代码，适合小型输出
    • 

  • 文件系统快照用于生成代码和配置文件
    • 

  • 自定义序列化器控制复杂对象的快照格式
    • 

  • 动态内容必须通过 Mock 固定（时间、UUID）
    • 

  • 快照更新必须经过审查，避免盲目 vitest -u
    • 

  • 快照不能替代断言测试，两者互补使用
    • 

  • 只为稳定、结构重要的组件添加快照测试
    •
