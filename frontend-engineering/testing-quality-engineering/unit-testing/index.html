单元测试 简介

单元测试是测试金字塔的基石，也是每一位前端工程师最应该熟练掌握的测试技能。一个函数、一个工具方法、一段业务逻辑——单元测试针对代码中最小的可测试单元进行隔离验证，确保每个独立模块都能按照预期工作。单元测试执行速度极快、反馈周期极短，是日常开发中最高效的质量保障手段。本章以 Vitest 为核心工具，系统讲解单元测试的方方面面。

第一节"Vitest 基础与配置"介绍 Vitest 这一现代测试框架的核心特性与项目配置。Vitest 基于 Vite 构建，天然支持 ESM、TypeScript 和 JSX，无需额外的转译配置即可开箱即用。与 Jest 兼容的 API 设计降低了迁移成本，而与 Vite 共享配置和插件体系的架构则带来了卓越的开发体验和执行性能。

第二节"编写有效断言"深入测试的核心表达方式。断言是测试的灵魂——一个好的断言既要准确表达期望行为，又要在失败时提供清晰的诊断信息。这一节涵盖值比较、对象匹配、异常捕获等常用断言模式，以及如何通过自定义匹配器扩展断言能力。

第三节"Mock 与 Stub 技术"解决单元测试中最常见的难题：外部依赖的隔离。当被测代码依赖网络请求、数据库、定时器或第三方模块时，Mock 和 Stub 能够用可控的替代品取代真实依赖，让测试专注于验证目标代码自身的逻辑。这一节将系统介绍函数模拟、模块模拟、定时器模拟等核心技术。

第四节"异步代码测试"聚焦于前端开发中无处不在的异步场景。Promise、async/await、回调函数、事件监听——异步代码的测试需要特殊的处理方式来确保断言在正确的时机执行。这一节讲解异步测试的常见陷阱和最佳实践，帮助你避免那些"测试永远通过但实际上什么都没验证"的隐蔽问题。

第五节"快照测试"介绍一种自动化捕捉输出变化的测试技术。快照测试将函数的输出序列化后存储为参照基线，后续运行时自动比对变化。它特别适合验证序列化输出、配置生成等场景，但也需要警惕过度使用导致的维护负担。这一节将帮助你理解快照测试的适用边界和管理策略。
