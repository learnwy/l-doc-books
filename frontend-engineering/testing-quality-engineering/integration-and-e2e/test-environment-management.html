测试环境管理

核心概念

测试环境管理确保测试在一致、可控的环境中运行。生产级项目的测试通常依赖数据库、缓存、第三方服务等外部基础设施，如何在本地开发、CI 流水线和预发布环境中一致地管理这些依赖，是测试可靠性的关键。

Docker 测试环境
Docker 容器提供了最可靠的测试环境隔离方案。通过 Dockerfile 和 docker-compose，团队中的每个人——以及 CI 服务器——都运行在完全相同的环境中，消除了"在我机器上可以跑"的问题。


# Dockerfile.test
FROM node:20

WORKDIR /app

COPY package*.json ./
RUN npm ci

COPY . .

RUN npm run build

CMD ["npm", "test"]
# docker-compose.test.yml
version: '3.8'
services:
  app:
    build:
      context: .
      dockerfile: Dockerfile.test
    depends_on:
      - db
      - redis
    environment:
      - NODE_ENV=test
      - DATABASE_URL=postgres://user:pass@db:5432/test
      - REDIS_URL=redis://redis:6379

  db:
    image: postgres:15
    environment:
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=pass
      - POSTGRES_DB=test

  redis:
    image: redis:7
# 运行测试
docker-compose -f docker-compose.test.yml up --abort-on-container-exit

Mock 外部服务
在测试中直接调用外部 API（支付、短信、地图等）既慢、不稳定，又有副作用风险。MSW（Mock Service Worker）在网络层拦截请求，返回预设响应，是目前最推荐的外部服务 Mock 方案。


// mocks/server.ts
import { setupServer } from 'msw/node';
import { rest } from 'msw';

export const server = setupServer(
  rest.get('/api/users/:id', (req, res, ctx) => {
    return res(
      ctx.json({
        id: req.params.id,
        name: 'Mock User',
        email: 'mock@example.com',
      }),
    );
  }),
  rest.post('/api/payment', (req, res, ctx) => {
    return res(ctx.json({ success: true }));
  }),
);
// setupTests.ts
import { beforeAll, afterEach, afterAll } from 'vitest';
import { server } from './mocks/server';

beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());
CI 配置
# .github/workflows/test.yml
name: Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:15
        env:
          POSTGRES_USER: test
          POSTGRES_PASSWORD: test
          POSTGRES_DB: test
        options: >-
          --health-cmd pg_isready --health-interval 10s --health-timeout 5s --health-retries 5


        ports:
          - 5432:5432

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - run: npm ci

      - run: npm test
        env:
          DATABASE_URL: postgres://test:test@localhost:5432/test
