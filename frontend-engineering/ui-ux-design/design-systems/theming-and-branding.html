主题系统与品牌一致性

主题系统概述

主题系统（Theming System）允许同一套组件库在不同的视觉风格之间切换，是实现深色模式、品牌定制和白标产品的技术基础。



主题架构
基于 Design Token 的主题切换
主题的本质是一组 Design Token 值的集合。切换主题 = 替换 Token 值。






层级
固定不变
随主题切换





Global Token
全局色板（blue-500 等）
—




Alias Token
—
color-primary, color-bg 等




Component Token
—
继承 Alias Token 的变化

白标化方案（White-Label）
白标化产品允许客户以自己的品牌来使用同一套产品。


白标化可配置项




配置项
实现方式





Logo
配置平台上传，运行时替换




品牌色
通过 CSS 变量或 Token 注入




字体
加载客户指定的 Web Font




域名
自定义域名 + SSL




邮件模板
替换模板中的品牌元素




Favicon
动态替换





白标设计约束




约束
原因





色彩只允许替换品牌色
功能色需要保持语义一致




组件结构不可更改
保持功能一致性和维护性




Logo 需提供规格要求
避免变形或比例失调




最少提供 3 个品牌色
主色、辅色和强调色

方案

品牌一致性检查




检查维度
工具/方法





色彩使用
自动检查是否使用了 Token 之外的色值




Logo 规范
检查 Logo 周围安全区域和最小尺寸




字体一致
确保所有页面加载了正确的品牌字体




间距规范
检查间距是否基于 Token 定义的倍数




语气一致
文案审核流程，确保语气与品牌调性匹配







小结
    

  • 主题系统的本质是一组 Design Token 值的集合，切换主题 = 替换 Token 值
    • 

  • 品牌规范覆盖 Logo、色彩、字体、图标、插画和语气等多个维度
    • 

  • 白标化通过品牌色和 Logo 注入实现，功能色和组件结构保持不变
    • 

  • CSS 变量是主题切换的主流技术方案，兼顾性能和灵活性
    • 

  • 品牌一致性需要工具化检查，而非依赖人工审核
