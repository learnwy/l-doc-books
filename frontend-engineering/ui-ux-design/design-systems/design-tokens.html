Design Token 与变量

什么是设计令牌

设计令牌（Design Token）是设计决策的最小可复用单元。它将颜色、间距、字号、圆角等视觉属性抽象为命名变量，实现设计意图在不同平台和工具之间的一致传递。

设计令牌的本质是将"设计意图"从"具体实现"中解耦。当品牌颜色从蓝色调整为紫色时，只需修改 Token 源文件中的一个值，所有消费平台（Web、iOS、Android、设计工具）自动获取新值——无需逐一搜索替换代码中散落的色值。




Token 层级体系
设计令牌通常分为三个层级，从全局到组件逐步具象化：






层级
名称
说明
示例





Global Token
全局令牌
最基础的原始值
blue-500: #3B82F6




Alias Token
别名令牌
语义化映射
color-primary: {blue-500}




Component Token
组件令牌
组件专属引用
button-bg: {color-primary}





三层架构的核心价值在于关注点分离。全局层定义调色板中所有可用的颜色值；别名层将颜色赋予语义含义（"这是主色调"）；组件层将语义色绑定到具体 UI 元素。这样当需要实现深色模式时，只需提供一套新的别名层映射，组件层代码完全不变。

命名规范的一致性至关重要。团队应在设计系统初期就确定命名约定并写入文档。常见的陷阱包括：混用 kebab-case 和 camelCase、同一维度使用不同的词汇（如 bg 与 background 混用）、状态后缀不统一。建议使用 linter 规则（如 Stylelint 自定义规则）自动检查 Token 命名的合规性。




跨平台 Token
设计令牌的核心价值之一是跨平台一致性。通过统一的源文件生成多平台代码。


Token 转换流程
Token 源文件格式
{
  "color": {
    "primary": {
      "value": "#2563EB",
      "type": "color"
    },
    "text": {
      "primary": {
        "value": "#111827",
        "type": "color"
      }
    }
  },
  "spacing": {
    "4": {
      "value": "16px",
      "type": "spacing"
    }
  }
}

小结
    

  • 设计令牌是设计决策的最小可复用单元，将视觉属性抽象为命名变量
    • 

  • Token 分三层：Global（原始值）→ Alias（语义化）→ Component（组件级）
    • 

  • 命名遵循 {类别}-{属性}-{变体}-{状态} 的结构化规则
    • 

  • 使用 Style Dictionary 等工具从单一源文件生成多平台代码
    • 

  • Token 需要版本管理、审核机制和废弃流程，确保长期可维护
    • 

  • Token 化是实现主题切换、深色模式和跨平台一致性的基础
    • 

  • 三层架构的关注点分离让深色模式实现只需切换别名层映射
    •
