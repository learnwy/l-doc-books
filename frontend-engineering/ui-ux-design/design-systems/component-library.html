组件库架构与文档

原子设计方法论

Atomic Design 由 Brad Frost 提出，将 UI 分为五个层级，从最小粒度逐步组合为完整页面。





层级
定义
示例





Atoms（原子）
最小不可再分的 UI 元素
按钮、输入框、标签、图标




Molecules（分子）
多个原子组合的功能单元
搜索框（输入框+按钮）




Organisms（有机体）
多个分子组成的完整区块
导航栏、卡片列表、表单




Templates（模板）
页面的骨架结构
列表页模板、详情页模板




Pages（页面）
填充真实数据的最终界面
商品列表页、用户详情页







组件 API 设计
Props 设计原则




原则
说明
示例





最小化 API
只暴露必要的 Props
避免 30 个 Props 的"上帝组件"




语义化命名
Props 名称表达意图
variant="primary" 而非 type=1




合理默认值
最常用的值作为默认
size="md" 为默认




一致性
同类组件使用相同的 Props 名
所有组件统一使用 size、variant

组件变体设计
变体（Variant）是同一组件的不同视觉/功能形态。


变体矩阵
以 Button 为例：






维度
值





variant
primary, secondary, ghost, danger




size
sm (32px), md (40px), lg (48px)




state
default, hover, active, focus, disabled, loading




icon
none, left, right, only





组合数量 = 4 × 3 × 6 × 4 = 288 种状态。在 Figma 中通过 Component Variants 管理，在代码中通过 Props 组合实现。




复合组件模式
复合组件（Compound Components）通过子组件组合实现灵活的组件结构，避免 Props 爆炸。


<Card>
  <Card.Header>
    <Card.Title>标题</Card.Title>
    <Card.Subtitle>副标题</Card.Subtitle>
  </Card.Header>
  <Card.Body>内容区域</Card.Body>
  <Card.Footer>
    <Button variant="primary">确认</Button>
  </Card.Footer>
</Card>




模式
特点
适用场景





单一组件
所有配置通过 Props 传入
简单组件（Badge、Tag）




复合组件
通过子组件组合结构
复杂组件（Card、Table、Form）




Headless 组件
只提供逻辑和状态，不提供样式
需要高度自定义样式的场景

小结
    

  • 原子设计将 UI 分为五级：原子 → 分子 → 有机体 → 模板 → 页面
    • 

  • Props 设计遵循最小化、语义化、一致性原则
    • 

  • 使用 variant × size × state 矩阵管理组件变体
    • 

  • 复合组件模式解决 Props 爆炸问题，提升组件灵活性
    • 

  • 组件文档需包含用法、Props、变体、状态和 Do/Don't 示例
    • 

  • 质量标准覆盖视觉一致性、无障碍、测试和文档四个维度
    •
