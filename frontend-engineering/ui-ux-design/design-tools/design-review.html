设计评审与交付

设计评审的目标

设计评审（Design Review）不是"评判设计好不好看"，而是系统性地检验设计方案是否满足用户需求、遵循设计规范、在技术上可行。

评审方法
启发式走查
按照 Nielsen 十大启发式逐条检查：






启发式
检查问题





系统状态可见性
加载状态和操作结果是否有明确反馈？




系统与现实匹配
术语和图标是否符合用户心智模型？




用户控制与自由
是否提供撤销和返回的途径？




一致性与标准
同类操作的交互方式是否统一？




防错设计
危险操作是否有确认机制？




识别而非回忆
选项和操作是否可见，无需记忆？





设计批评（Design Critique）




规则
说明





聚焦目标
围绕设计目标讨论，而非个人偏好




提问而非评判
"这个间距的考虑是什么？" vs "间距太大了"




具体而非抽象
指出具体问题和位置




建设性建议
指出问题的同时提供改进方向




区分优先级
区分"必须修改"和"建议优化"

小结
    

  • 设计评审的核心是检验需求满足度、规范一致性和技术可行性
    • 

  • 自查、同行评审和跨职能评审分别解决不同层面的质量问题
    • 

  • 设计批评应聚焦目标、提问而非评判、具体而非抽象
    • 

  • 设计 QA 是保证实现质量的最后防线，需要逐像素对比
    • 

  • 反馈循环是持续改进的引擎——收集 → 分类 → 迭代 → 验证
    •
