导航与信息架构

导航的核心职责

导航系统帮助用户回答三个问题：我在哪里？我能去哪里？我怎么回去？导航模式的选择取决于信息架构的深度、宽度和用户的使用场景。



常见导航模式
底部 Tab Bar




特性
说明





适用平台
移动端（iOS / Android）




Tab 数量
3~5 个




内容类型
顶级功能入口




交互
点击切换，支持滑动（可选）




激活态
图标填充 + 品牌色 + 标签文字





设计要点：


    

  • 每个 Tab 应有图标 + 文字标签
    • 

  • 激活态与默认态对比明显
    • 

  • 不超过 5 个 Tab，超过则考虑"更多"入口
    •

Tab 数量
2~6 个




交互
点击切换，可滑动




视觉
下划线指示器或背景高亮

面包屑导航（Breadcrumb）
面包屑展示用户在层级结构中的当前位置，支持快速返回上级页面。

说明

首页 > 分类 > 子分类 > 当前页




当前页
不可点击，文字颜色较浅




分隔符

抽屉导航（Drawer / Bottom Sheet）




类型
方向
适用场景





Left Drawer
从左侧滑出
主导航（移动端）




Right Drawer
从右侧滑出

Bottom Sheet
从底部弹出
操作菜单、分享面板





Bottom Sheet 设计要点：


    

  • 提供拖拽手柄（drag handle）
    • 

  • 支持半屏和全屏两种高度
    • 

  • 背景遮罩点击可关闭
    • 

  • 适配手势操作（下拉关闭）
    •

小结
    

  • 导航设计的核心是帮助用户回答"我在哪、能去哪、怎么回去"
    • 

  • 底部 Tab Bar 适合移动端核心功能导航，限制 3~5 个入口
    • 

  • 侧边栏 适合桌面端多功能后台，支持展开/收缩响应式
    • 

  • 面包屑 是深层级导航的必备辅助，展示用户当前位置
    • 

  • Bottom Sheet 是移动端操作菜单的最佳实践
    • 

  • 导航层级不宜超过 4 层，过深的信息架构需要通过搜索补充
    •
