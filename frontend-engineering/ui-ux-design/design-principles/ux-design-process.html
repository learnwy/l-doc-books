用户体验设计流程

UX 设计流程概述

UX 设计不是一个线性的"画图"过程，而是一个以用户为中心的迭代循环。从理解用户需求到验证设计方案，每个阶段都有明确的目标、方法和产出物。



阶段一：用户调研（Research）
用户调研的目标是理解目标用户的行为、需求和痛点，避免"为自己设计"。


常用调研方法

数据分析

调研产出物




产出物
内容
作用





用户画像（Persona）
典型用户的特征、目标、痛点
让团队对"为谁设计"达成共识




用户旅程图（Journey Map）
用户完成任务的全流程和情绪曲线
发现体验断点和优化机会




同理心地图（Empathy Map）
用户的所想、所说、所做、所感
建立对用户的深度理解







阶段二：问题定义（Define）
将调研发现转化为清晰的设计问题。


核心工具
HMW（How Might We）提问法：


我们如何帮助 [用户] 在 [场景] 中 [目标]？
示例：


    

  • 我们如何帮助新用户在 3 分钟内完成首次下单？
    • 

  • 我们如何帮助运营人员在不依赖开发的情况下更新活动页面？
    •

敏捷团队中的 UX
在敏捷开发中，UX 设计需要适配 Sprint 节奏：






时间节点
UX 活动





Sprint N-1
为下个 Sprint 的需求做用户调研和设计探索




Sprint N 开始
交付高保真设计稿和交互说明




Sprint N 中期
与开发同步走查，解答设计细节问题




Sprint N 结束
参与 Demo 和回顾，收集反馈







小结
    

  • UX 设计是 调研 → 定义 → 设计 → 原型 → 测试 的迭代循环
    • 

  • 用户调研是设计决策的基础，避免"闭门造车"
    • 

  • 线框图先解决结构问题，再进入视觉设计
    • 

  • 可用性测试用 5~8 名用户即可发现 85% 的问题
    • 

  • 在敏捷团队中，设计需要比开发提前一个 Sprint
    • 

  • 整个流程的核心是"以用户为中心"，每个决策都应有用户数据支撑
    •
