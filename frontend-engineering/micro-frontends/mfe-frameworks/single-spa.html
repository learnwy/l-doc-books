single-spa 框架

核心概念

single-spa 是微前端领域最早的框架级解决方案，它提供了一个「元框架」层，负责在多个独立的前端应用之间进行路由协调和生命周期管理。single-spa 不限制子应用的技术栈，允许 React、Vue、Angular 甚至原生 JavaScript 应用在同一个页面中共存运行。

注册与生命周期
single-spa 的核心 API 围绕应用注册和生命周期管理展开。每个子应用通过 registerApplication 注册到 single-spa，声明激活条件和生命周期函数：


interface SingleSpaApp {
  readonly name: string;
  readonly app: () => Promise<LifecycleModule>;
  readonly activeWhen: string | ReadonlyArray<string> | ((location: Location) => boolean);
  readonly customProps?: Record<string, unknown>;
}

interface LifecycleModule {
  readonly bootstrap: LifecycleFn | ReadonlyArray<LifecycleFn>;
  readonly mount: LifecycleFn | ReadonlyArray<LifecycleFn>;
  readonly unmount: LifecycleFn | ReadonlyArray<LifecycleFn>;
  readonly update?: LifecycleFn | ReadonlyArray<LifecycleFn>;
}

type LifecycleFn = (props: AppProps) => Promise<void>;

interface AppProps {
  readonly name: string;
  readonly singleSpa: unknown;
  readonly mountParcel: (config: unknown, props: unknown) => unknown;
  readonly [key: string]: unknown;
}

const registerApps = (apps: ReadonlyArray<SingleSpaApp>): void => {
  apps.forEach((app) => {
    registerApplication({
      name: app.name,
      app: app.app,
      activeWhen: app.activeWhen,
      customProps: app.customProps,
    });
  });
};

const appConfig: ReadonlyArray<SingleSpaApp> = [
  {
    name: '@company/navbar',
    app: () => System.import('@company/navbar'),
    activeWhen: '/',
  },
  {
    name: '@company/order',
    app: () => System.import('@company/order'),
    activeWhen: '/order',
    customProps: { apiBaseUrl: 'https://api.example.com' },
  },
  {
    name: '@company/product',
    app: () => System.import('@company/product'),
    activeWhen: ['/product', '/category'],
  },
];
子应用需要导出符合 single-spa 协议的生命周期函数。以 React 子应用为例，使用 single-spa-react 适配器可以简化集成：


interface ReactAppConfig {
  readonly React: typeof React;
  readonly ReactDOMClient: typeof ReactDOMClient;
  readonly rootComponent: React.ComponentType;
  readonly domElementGetter?: () => HTMLElement;
  readonly errorBoundary?: (err: Error) => React.ReactElement;
}

const createReactApp = (config: ReactAppConfig): LifecycleModule => {
  let root: ReactDOMClient.Root | null = null;

  const bootstrap: LifecycleFn = async () => {
    // 初始化阶段，可预加载资源
  };

  const mount: LifecycleFn = async (props) => {
    const container = config.domElementGetter?.() ?? document.getElementById(`single-spa-application:${props.name}`);

    if (!container) {
      throw new Error(`Container not found for ${props.name}`);
    }

    root = ReactDOMClient.createRoot(container);
    root.render(React.createElement(config.rootComponent, props));
  };

  const unmount: LifecycleFn = async () => {
    root?.unmount();
    root = null;
  };

  return { bootstrap, mount, unmount };
};
Parcel 机制
single-spa 的 Parcel（包裹）机制允许在不受路由控制的情况下按需挂载组件。Parcel 与 Application 的区别在于：Application 由路由自动激活/卸载，而 Parcel 由父应用手动控制生命周期：


interface ParcelConfig {
  readonly bootstrap: LifecycleFn;
  readonly mount: LifecycleFn;
  readonly unmount: LifecycleFn;
  readonly update?: LifecycleFn;
}

interface MountedParcel {
  readonly update: (props: Record<string, unknown>) => Promise<void>;
  readonly unmount: () => Promise<void>;
  readonly getStatus: () => string;
  readonly loadPromise: Promise<void>;
  readonly bootstrapPromise: Promise<void>;
  readonly mountPromise: Promise<void>;
  readonly unmountPromise: Promise<void>;
}

const useParcel = (
  config: () => Promise<ParcelConfig>,
  domElement: HTMLElement,
  customProps: Record<string, unknown> = {},
): { readonly parcel: MountedParcel | null; readonly error: Error | null } => {
  const [parcel, setParcel] = React.useState<MountedParcel | null>(null);
  const [error, setError] = React.useState<Error | null>(null);

  React.useEffect(() => {
    let mounted = true;

    config()
      .then((parcelConfig) => {
        if (!mounted) return;
        const mountedParcel = mountParcel(parcelConfig, {
          domElement,
          ...customProps,
        }) as MountedParcel;
        setParcel(mountedParcel);
      })
      .catch((err) => {
        if (mounted) setError(err as Error);
      });

    return () => {
      mounted = false;
      parcel?.unmount();
    };
  }, []);

  return { parcel, error };
};

Import Map 与模块加载
single-spa 推荐使用 Import Map（浏览器原生或 SystemJS polyfill）管理子应用的模块加载。Import Map 提供了一个运行时的模块 URL 映射表，实现了模块标识符到实际 URL 的解耦：


interface ImportMap {
  readonly imports: Readonly<Record<string, string>>;
  readonly scopes?: Readonly<Record<string, Readonly<Record<string, string>>>>;
}

const importMap: ImportMap = {
  imports: {
    '@company/navbar': 'https://cdn.example.com/navbar/v2.1.0/main.js',
    '@company/order': 'https://cdn.example.com/order/v3.0.1/main.js',
    '@company/product': 'https://cdn.example.com/product/v1.5.0/main.js',
    react: 'https://cdn.example.com/react/18.3.1/react.production.min.js',
    'react-dom': 'https://cdn.example.com/react-dom/18.3.1/react-dom.production.min.js',
  },
};

interface ImportMapService {
  readonly getMap: () => Promise<ImportMap>;
  readonly updateEntry: (name: string, url: string) => Promise<void>;
}

const createImportMapService = (endpoint: string): ImportMapService => {
  const getMap = async (): Promise<ImportMap> => {
    const response = await fetch(endpoint);
    return response.json() as Promise<ImportMap>;
  };

  const updateEntry = async (name: string, url: string): Promise<void> => {
    await fetch(endpoint, {
      method: 'PATCH',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ imports: { [name]: url } }),
    });
  };

  return { getMap, updateEntry };
};
通过在部署时更新 Import Map 中子应用的 URL（通常指向新版本的 CDN 路径），single-spa 实现了子应用的独立部署。无需重新构建主应用，只需更新 Import Map 服务即可让新版本生效。


布局引擎与路由策略
single-spa 的 Layout Engine 提供了声明式的布局配置能力，允许在 HTML 模板中定义子应用的挂载位置和布局关系：


interface LayoutConfig {
  readonly routes: ReadonlyArray<LayoutRoute>;
  readonly defaultRoute?: string;
  readonly errorRoute?: string;
}

interface LayoutRoute {
  readonly type: 'route' | 'application' | 'div';
  readonly path?: string;
  readonly name?: string;
  readonly props?: Record<string, unknown>;
  readonly children?: ReadonlyArray<LayoutRoute>;
  readonly className?: string;
}

const layoutConfig: LayoutConfig = {
  routes: [
    {
      type: 'div',
      className: 'app-layout',
      children: [
        {
          type: 'application',
          name: '@company/navbar',
        },
        {
          type: 'route',
          path: '/order',
          children: [{ type: 'application', name: '@company/order' }],
        },
        {
          type: 'route',
          path: '/product',
          children: [{ type: 'application', name: '@company/product' }],
        },
      ],
    },
  ],
  errorRoute: '/error',
};

const constructApplications = (layout: LayoutConfig): ReadonlyArray<SingleSpaApp> => {
  const apps: Array<SingleSpaApp> = [];

  const traverse = (routes: ReadonlyArray<LayoutRoute>, parentPath = ''): void => {
    routes.forEach((route) => {
      if (route.type === 'application' && route.name) {
        const fullPath = parentPath || '/';
        apps.push({
          name: route.name,
          app: () => System.import(route.name!),
          activeWhen: fullPath,
          customProps: route.props,
        });
      }
      if (route.children) {
        traverse(route.children, route.path ?? parentPath);
      }
    });
  };

  traverse(layout.routes);
  return apps;
};
小结
    

  • single-spa 是微前端领域的「元框架」，通过路由匹配和生命周期协议实现多技术栈应用共存
    • 

  • 核心 API 包括 registerApplication（路由驱动）和 mountParcel（手动控制），覆盖了页面级和组件级两种集成粒度
    • 

  • 子应用通过导出 bootstrap / mount / unmount 生命周期函数与 single-spa 对接
    • 

  • Import Map 实现模块标识符到 URL 的运行时映射，支持子应用独立部署和灰度发布
    • 

  • Layout Engine 提供声明式布局配置，将应用挂载位置与路由结构解耦
    • 

  • single-spa 不内置 JS/CSS 隔离机制，需要配合 qiankun 等上层框架或手动实现沙箱
    •
