Module Federation 模块联邦

核心概念

Module Federation（模块联邦）是 Webpack 5 引入的革命性特性，它允许多个独立构建的应用在运行时共享模块，本质上实现了「构建时独立、运行时共享」的微前端理想形态。每个应用既可以作为 Host（消费者）加载远程模块，也可以作为 Remote（提供者）暴露模块给其他应用使用。

配置模型与运行机制
Module Federation 的配置分为两部分：Remote 端声明暴露哪些模块，Host 端声明从哪些远程容器加载模块。运行时，Webpack 会生成一个 remoteEntry.js 文件作为远程容器的入口点：


interface ModuleFederationRemoteConfig {
  readonly name: string;
  readonly filename: string;
  readonly exposes: Readonly<Record<string, string>>;
  readonly shared: Readonly<Record<string, SharedConfig>>;
}

interface ModuleFederationHostConfig {
  readonly name: string;
  readonly remotes: Readonly<Record<string, string>>;
  readonly shared: Readonly<Record<string, SharedConfig>>;
}

interface SharedConfig {
  readonly singleton?: boolean;
  readonly requiredVersion?: string;
  readonly eager?: boolean;
  readonly strictVersion?: boolean;
}

const remoteConfig: ModuleFederationRemoteConfig = {
  name: 'orderApp',
  filename: 'remoteEntry.js',
  exposes: {
    './OrderList': './src/components/OrderList',
    './OrderAPI': './src/services/OrderAPI',
    './useOrder': './src/hooks/useOrder',
  },
  shared: {
    react: { singleton: true, requiredVersion: '^18.0.0' },
    'react-dom': { singleton: true, requiredVersion: '^18.0.0' },
  },
};

const hostConfig: ModuleFederationHostConfig = {
  name: 'shellApp',
  remotes: {
    orderApp: 'orderApp@https://order.example.com/remoteEntry.js',
    productApp: 'productApp@https://product.example.com/remoteEntry.js',
  },
  shared: {
    react: { singleton: true, requiredVersion: '^18.0.0', eager: true },
    'react-dom': { singleton: true, requiredVersion: '^18.0.0', eager: true },
  },
};
运行时加载远程模块的过程涉及三个关键步骤：初始化共享作用域、加载远程容器、获取模块工厂。Webpack 运行时会自动处理这些步骤，但理解底层机制对于调试和优化至关重要：


interface RemoteContainer {
  readonly init: (shareScope: Record<string, unknown>) => Promise<void>;
  readonly get: (module: string) => Promise<() => unknown>;
}

const loadRemoteModule = async (remoteName: string, modulePath: string): Promise<unknown> => {
  await __webpack_init_sharing__('default');

  const container = (window as Record<string, unknown>)[remoteName] as RemoteContainer;
  await container.init(__webpack_share_scopes__.default);

  const factory = await container.get(modulePath);
  return factory();
};

const RemoteOrderList = React.lazy(() =>
  loadRemoteModule('orderApp', './OrderList').then((module) => ({
    default: (module as { OrderList: React.ComponentType }).OrderList,
  })),
);
共享依赖与版本协商
Module Federation 的共享依赖机制是其最精妙的设计之一。多个应用可以声明自己使用的依赖及版本范围，运行时自动协商使用哪个版本，避免依赖重复加载：


interface SharedDependency {
  readonly name: string;
  readonly version: string;
  readonly loaded: boolean;
  readonly from: string;
  readonly eager: boolean;
}

interface VersionNegotiation {
  readonly requested: ReadonlyArray<{ app: string; version: string }>;
  readonly resolved: string;
  readonly strategy: 'highest' | 'singleton' | 'strict';
}

const negotiateVersion = (
  requests: ReadonlyArray<{ readonly app: string; readonly version: string }>,
  config: SharedConfig,
): VersionNegotiation => {
  const versions = requests.map((r) => r.version);

  if (config.singleton) {
    const highest = versions.sort((a, b) => {
      const [aMajor, aMinor] = a.split('.').map(Number);
      const [bMajor, bMinor] = b.split('.').map(Number);
      return bMajor - aMajor || bMinor - aMinor;
    })[0];

    return {
      requested: requests,
      resolved: highest,
      strategy: 'singleton',
    };
  }

  if (config.strictVersion) {
    const allSame = versions.every((v) => v === versions[0]);
    if (!allSame) {
      console.warn(`Strict version mismatch: ${versions.join(', ')}`);
    }
    return {
      requested: requests,
      resolved: versions[0],
      strategy: 'strict',
    };
  }

  return {
    requested: requests,
    resolved: versions.sort().reverse()[0],
    strategy: 'highest',
  };
};

Module Federation 2.0 与 Rspack
Module Federation 2.0（由 Zack Jackson 主导）引入了类型安全、运行时插件和动态远程注册等增强能力，解决了 1.0 版本的核心痛点。Rspack（字节跳动开源的 Rust 构建工具）也原生支持 Module Federation，提供了显著的构建性能提升：


interface MF2RuntimePlugin {
  readonly name: string;
  readonly beforeInit?: (args: { readonly origin: string }) => void;
  readonly afterResolve?: (args: { readonly id: string; readonly pkgName: string }) => {
    readonly id: string;
    readonly pkgName: string;
  };
  readonly onLoad?: (args: { readonly id: string; readonly expose: string }) => Promise<unknown> | undefined;
}

const createVersionPlugin = (): MF2RuntimePlugin => ({
  name: 'version-guard',
  afterResolve: (args) => {
    const versionMap: Readonly<Record<string, string>> = {
      react: '18.3.1',
      'react-dom': '18.3.1',
    };
    const expectedVersion = versionMap[args.pkgName];
    if (expectedVersion) {
      return { ...args, id: `${args.pkgName}@${expectedVersion}` };
    }
    return args;
  },
});

const createFallbackPlugin = (fallbacks: Readonly<Record<string, string>>): MF2RuntimePlugin => ({
  name: 'remote-fallback',
  onLoad: async (args) => {
    try {
      return undefined;
    } catch {
      const fallbackUrl = fallbacks[args.id];
      if (fallbackUrl) {
        return import(fallbackUrl);
      }
      throw new Error(`Failed to load ${args.id} and no fallback available`);
    }
  },
});
MF 2.0 的类型安全通过自动生成远程模块的 TypeScript 类型声明实现。构建时，Remote 端提取 exposes 的类型信息并发布到类型服务器，Host 端在开发时自动下载并集成到本地类型系统中，实现跨应用的完整类型检查。


Rspack 对 Module Federation 的支持在 API 层面与 Webpack 5 完全兼容，但构建速度提升 5-10 倍。对于大型微前端项目，从 Webpack 迁移到 Rspack 可以显著缩短 CI/CD 管线时间。


动态远程注册与运行时发现
生产环境中，远程应用的 URL 不应硬编码在构建配置中，而应通过运行时发现机制动态注册：


interface RemoteManifest {
  readonly name: string;
  readonly entry: string;
  readonly version: string;
  readonly modules: ReadonlyArray<string>;
  readonly dependencies: Readonly<Record<string, string>>;
}

interface RemoteRegistry {
  readonly register: (manifest: RemoteManifest) => void;
  readonly resolve: (name: string) => RemoteManifest | undefined;
  readonly loadRemote: (name: string, module: string) => Promise<unknown>;
}

const createRemoteRegistry = (): RemoteRegistry => {
  const registry = new Map<string, RemoteManifest>();

  const register = (manifest: RemoteManifest): void => {
    registry.set(manifest.name, manifest);
  };

  const resolve = (name: string): RemoteManifest | undefined => {
    return registry.get(name);
  };

  const loadRemote = async (name: string, module: string): Promise<unknown> => {
    const manifest = registry.get(name);
    if (!manifest) {
      throw new Error(`Remote "${name}" not registered`);
    }

    const script = document.createElement('script');
    script.src = manifest.entry;
    await new Promise<void>((resolve, reject) => {
      script.onload = () => resolve();
      script.onerror = () => reject(new Error(`Failed to load ${manifest.entry}`));
      document.head.appendChild(script);
    });

    const container = (window as Record<string, unknown>)[name] as RemoteContainer;
    await container.init(__webpack_share_scopes__.default);
    const factory = await container.get(module);
    return factory();
  };

  return { register, resolve, loadRemote };
};
小结
    

  • Module Federation 实现了「构建时独立、运行时共享」的微前端理想形态，模块粒度的共享优于应用级别
    • 

  • 核心机制包括远程容器（remoteEntry.js）、共享作用域初始化和模块工厂获取三个阶段
    • 

  • 共享依赖通过 singleton、strictVersion、requiredVersion 等策略实现运行时版本协商
    • 

  • MF 2.0 引入类型安全、运行时插件和动态远程注册，解决了 1.0 的核心痛点
    • 

  • Rspack 原生支持 Module Federation，API 兼容 Webpack 5，构建性能提升 5-10 倍
    • 

  • 生产环境应使用动态远程注册替代硬编码 URL，通过 manifest 服务实现运行时发现
