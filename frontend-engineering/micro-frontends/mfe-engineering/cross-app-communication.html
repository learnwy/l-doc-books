跨应用通信

核心概念

跨应用通信是微前端架构中连接各个独立子应用的神经系统。由于子应用之间相互隔离，它们无法直接共享内存中的状态，需要通过约定的通信协议交换数据。通信机制的设计直接影响微前端系统的耦合度、可维护性和运行时性能。

事件总线模式
事件总线是微前端通信中最常用的解耦方案。它基于发布-订阅模式，子应用之间通过事件名约定通信契约，不需要了解对方的内部实现：


type EventHandler = (...args: ReadonlyArray<unknown>) => void;

interface TypedEventMap {
  readonly 'user:login': { readonly userId: string; readonly token: string };
  readonly 'user:logout': undefined;
  readonly 'cart:update': { readonly items: ReadonlyArray<{ id: string; quantity: number }> };
  readonly 'theme:change': { readonly mode: 'light' | 'dark' };
  readonly 'locale:change': { readonly locale: string };
  readonly 'route:change': { readonly path: string; readonly source: string };
}

interface MicroEventBus {
  readonly on: <K extends keyof TypedEventMap>(event: K, handler: (payload: TypedEventMap[K]) => void) => () => void;
  readonly emit: <K extends keyof TypedEventMap>(event: K, payload: TypedEventMap[K]) => void;
  readonly once: <K extends keyof TypedEventMap>(event: K, handler: (payload: TypedEventMap[K]) => void) => () => void;
  readonly clear: (event?: keyof TypedEventMap) => void;
}

const createEventBus = (): MicroEventBus => {
  const handlers = new Map<string, Set<EventHandler>>();

  const on = <K extends keyof TypedEventMap>(event: K, handler: (payload: TypedEventMap[K]) => void): (() => void) => {
    const key = event as string;
    if (!handlers.has(key)) {
      handlers.set(key, new Set());
    }
    handlers.get(key)!.add(handler as EventHandler);

    return () => {
      handlers.get(key)?.delete(handler as EventHandler);
      if (handlers.get(key)?.size === 0) {
        handlers.delete(key);
      }
    };
  };

  const emit = <K extends keyof TypedEventMap>(event: K, payload: TypedEventMap[K]): void => {
    const key = event as string;
    handlers.get(key)?.forEach((handler) => {
      try {
        handler(payload);
      } catch (err) {
        console.error(`Event handler error for ${key}:`, err);
      }
    });
  };

  const once = <K extends keyof TypedEventMap>(
    event: K,
    handler: (payload: TypedEventMap[K]) => void,
  ): (() => void) => {
    const unsubscribe = on(event, (payload) => {
      unsubscribe();
      handler(payload);
    });
    return unsubscribe;
  };

  const clear = (event?: keyof TypedEventMap): void => {
    if (event) {
      handlers.delete(event as string);
    } else {
      handlers.clear();
    }
  };

  return { on, emit, once, clear };
};
事件总线需要防止内存泄漏。子应用卸载时必须取消所有订阅。一个常见的最佳实践是在子应用的 mount 阶段收集所有订阅的取消函数，在 unmount 阶段统一执行：


interface SubscriptionCollector {
  readonly add: (unsubscribe: () => void) => void;
  readonly disposeAll: () => void;
}

const createSubscriptionCollector = (): SubscriptionCollector => {
  const subscriptions = new Set<() => void>();

  return {
    add: (unsubscribe: () => void) => {
      subscriptions.add(unsubscribe);
    },
    disposeAll: () => {
      subscriptions.forEach((unsub) => unsub());
      subscriptions.clear();
    },
  };
};
全局状态共享
当多个子应用需要共享复杂的业务状态（如用户信息、购物车、权限列表）时，事件总线的简单消息传递可能不够用。全局状态共享方案提供了一个所有子应用都能读写的中心化状态存储：


interface SharedState {
  readonly user: {
    readonly id: string;
    readonly name: string;
    readonly role: 'admin' | 'editor' | 'viewer';
  } | null;
  readonly theme: 'light' | 'dark';
  readonly locale: string;
  readonly permissions: ReadonlyArray<string>;
}

type StateSelector<T> = (state: SharedState) => T;
type StateListener<T> = (newValue: T, oldValue: T) => void;

interface SharedStore {
  readonly getState: () => Readonly<SharedState>;
  readonly setState: (partial: Partial<SharedState>) => void;
  readonly subscribe: <T>(selector: StateSelector<T>, listener: StateListener<T>) => () => void;
  readonly reset: () => void;
}

const createSharedStore = (initialState: SharedState): SharedStore => {
  let state = { ...initialState };
  const listeners = new Set<{
    selector: StateSelector<unknown>;
    listener: StateListener<unknown>;
    lastValue: unknown;
  }>();

  const getState = (): Readonly<SharedState> => state;

  const setState = (partial: Partial<SharedState>): void => {
    const prevState = state;
    state = { ...state, ...partial };

    listeners.forEach((entry) => {
      const newValue = entry.selector(state);
      const oldValue = entry.selector(prevState);
      if (!Object.is(newValue, oldValue)) {
        entry.lastValue = newValue;
        entry.listener(newValue, oldValue);
      }
    });
  };

  const subscribe = <T>(selector: StateSelector<T>, listener: StateListener<T>): (() => void) => {
    const entry = {
      selector: selector as StateSelector<unknown>,
      listener: listener as StateListener<unknown>,
      lastValue: selector(state) as unknown,
    };
    listeners.add(entry);
    return () => listeners.delete(entry);
  };

  const reset = (): void => setState(initialState);

  return { getState, setState, subscribe, reset };
};
在 React 子应用中，可以通过自定义 Hook 将全局状态桥接到组件的响应式系统中：


const useSharedState = <T>(store: SharedStore, selector: StateSelector<T>): T => {
  const [value, setValue] = React.useState(() => selector(store.getState()));

  React.useEffect(() => {
    const unsubscribe = store.subscribe(selector, (newValue) => {
      setValue(newValue as T);
    });
    return unsubscribe;
  }, [store, selector]);

  return value;
};
BroadcastChannel 跨 Tab 通信
当微前端应用需要在同一浏览器的多个 Tab 之间同步状态时（如登录态同步、主题切换），BroadcastChannel 提供了原生的跨 Tab 通信能力：


interface CrossTabMessage<T = unknown> {
  readonly type: string;
  readonly payload: T;
  readonly source: string;
  readonly timestamp: number;
}

interface CrossTabBridge {
  readonly send: <T>(type: string, payload: T) => void;
  readonly on: <T>(type: string, handler: (msg: CrossTabMessage<T>) => void) => () => void;
  readonly close: () => void;
}

const createCrossTabBridge = (channelName: string, appId: string): CrossTabBridge => {
  const channel = new BroadcastChannel(channelName);
  const handlers = new Map<string, Set<(msg: CrossTabMessage) => void>>();

  channel.onmessage = (event: MessageEvent<CrossTabMessage>) => {
    const msg = event.data;
    if (msg.source === appId) return;
    handlers.get(msg.type)?.forEach((handler) => handler(msg));
  };

  const send = <T>(type: string, payload: T): void => {
    const msg: CrossTabMessage<T> = {
      type,
      payload,
      source: appId,
      timestamp: Date.now(),
    };
    channel.postMessage(msg);
  };

  const on = <T>(type: string, handler: (msg: CrossTabMessage<T>) => void): (() => void) => {
    if (!handlers.has(type)) handlers.set(type, new Set());
    handlers.get(type)!.add(handler as (msg: CrossTabMessage) => void);
    return () => handlers.get(type)?.delete(handler as (msg: CrossTabMessage) => void);
  };

  const close = (): void => {
    channel.close();
    handlers.clear();
  };

  return { send, on, close };
};

interface EventContract<T> {
  readonly eventName: string;
  readonly version: number;
  readonly validate: (payload: unknown) => payload is T;
  readonly migrate?: (oldPayload: unknown) => T;
}

const createContract = <T>(
  eventName: string,
  version: number,
  validator: (payload: unknown) => payload is T,
  migrator?: (oldPayload: unknown) => T,
): EventContract<T> => ({
  eventName,
  version,
  validate: validator,
  migrate: migrator,
});

const safeEmit = <T>(bus: MicroEventBus, contract: EventContract<T>, payload: T): void => {
  if (!contract.validate(payload)) {
    console.error(`Invalid payload for ${contract.eventName}`);
    return;
  }
  bus.emit(contract.eventName as keyof TypedEventMap, payload as TypedEventMap[keyof TypedEventMap]);
};
小结
    

  • 跨应用通信是微前端架构的核心基础设施，直接影响系统耦合度和可维护性
    • 

  • 事件总线基于发布-订阅模式实现松耦合通信，子应用卸载时必须取消所有订阅防止内存泄漏
    • 

  • 全局状态共享适合复杂业务状态同步，通过 selector + listener 模式实现精确更新
    • 

  • BroadcastChannel 提供原生的跨 Tab 通信能力，适合登录态同步和全局主题切换
    • 

  • 通信契约应定义为共享的 TypeScript 类型，结合运行时 Schema 验证实现双重安全保障
    • 

  • 通信设计原则：最小化通信量、优先事件驱动、避免双向依赖、每条消息携带版本号
    •
