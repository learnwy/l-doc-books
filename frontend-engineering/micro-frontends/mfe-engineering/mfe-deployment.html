微前端部署策略

核心概念

微前端部署策略是将多个独立构建的子应用安全、高效地发布到生产环境的工程体系。与单体应用的整体部署不同，微前端的部署需要协调多个团队的发布节奏，处理子应用间的版本兼容性，并确保在任意子应用更新时整体系统的稳定性。

独立部署与版本注册
微前端的核心价值之一是子应用的独立部署能力。每个子应用拥有独立的 CI/CD 管线、独立的构建产物和独立的发布流程。部署完成后，子应用需要将新版本注册到中心化的版本服务中：


interface AppVersion {
  readonly name: string;
  readonly version: string;
  readonly entry: string;
  readonly integrity: string;
  readonly buildTime: string;
  readonly commitHash: string;
  readonly dependencies: Readonly<Record<string, string>>;
}

interface VersionRegistry {
  readonly register: (app: AppVersion) => Promise<void>;
  readonly resolve: (name: string, env: string) => Promise<AppVersion>;
  readonly listVersions: (name: string) => Promise<ReadonlyArray<AppVersion>>;
  readonly rollback: (name: string, version: string) => Promise<void>;
}

const createVersionRegistry = (apiUrl: string): VersionRegistry => {
  const register = async (app: AppVersion): Promise<void> => {
    await fetch(`${apiUrl}/apps/${app.name}/versions`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(app),
    });
  };

  const resolve = async (name: string, env: string): Promise<AppVersion> => {
    const response = await fetch(`${apiUrl}/apps/${name}/active?env=${env}`);
    return response.json() as Promise<AppVersion>;
  };

  const listVersions = async (name: string): Promise<ReadonlyArray<AppVersion>> => {
    const response = await fetch(`${apiUrl}/apps/${name}/versions`);
    return response.json() as Promise<ReadonlyArray<AppVersion>>;
  };

  const rollback = async (name: string, version: string): Promise<void> => {
    await fetch(`${apiUrl}/apps/${name}/active`, {
      method: 'PUT',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ version }),
    });
  };

  return { register, resolve, listVersions, rollback };
};
主应用在启动时从版本注册中心拉取最新的子应用 manifest，动态构建 Import Map 或 Module Federation 的远程配置。这样子应用的部署只需更新版本注册中心的记录，无需触发主应用的重新构建。


灰度发布与流量分配
灰度发布是大型微前端系统的标配能力。通过控制流量分配比例，可以将新版本子应用逐步推给一部分用户，观察运行指标后再决定全量发布或回滚：


type TrafficRule =
  | { readonly type: 'percentage'; readonly value: number }
  | { readonly type: 'userId'; readonly whitelist: ReadonlyArray<string> }
  | { readonly type: 'region'; readonly regions: ReadonlyArray<string> }
  | { readonly type: 'header'; readonly key: string; readonly value: string };

interface GrayRelease {
  readonly appName: string;
  readonly stableVersion: string;
  readonly canaryVersion: string;
  readonly rules: ReadonlyArray<TrafficRule>;
  readonly metrics: ReleaseMetrics;
}

interface ReleaseMetrics {
  readonly errorRate: number;
  readonly p99Latency: number;
  readonly successRate: number;
}

interface GrayRouter {
  readonly resolveVersion: (appName: string, context: RequestContext) => string;
}

interface RequestContext {
  readonly userId?: string;
  readonly region?: string;
  readonly headers: Readonly<Record<string, string>>;
  readonly randomSeed: number;
}

const createGrayRouter = (releases: ReadonlyArray<GrayRelease>): GrayRouter => {
  const resolveVersion = (appName: string, context: RequestContext): string => {
    const release = releases.find((r) => r.appName === appName);
    if (!release) return '';

    const matchesCanary = release.rules.some((rule) => {
      switch (rule.type) {
        case 'percentage':
          return context.randomSeed * 100 < rule.value;
        case 'userId':
          return context.userId ? rule.whitelist.includes(context.userId) : false;
        case 'region':
          return context.region ? rule.regions.includes(context.region) : false;
        case 'header':
          return context.headers[rule.key] === rule.value;
        default:
          return false;
      }
    });

    return matchesCanary ? release.canaryVersion : release.stableVersion;
  };

  return { resolveVersion };
};

CDN 与资源分发
微前端的子应用静态资源通常部署在 CDN 上，通过 content hash 文件名实现长期缓存。资源分发策略需要考虑缓存一致性、跨域加载和 CSP 安全策略：


interface CDNConfig {
  readonly domain: string;
  readonly basePath: string;
  readonly cacheControl: string;
  readonly corsOrigins: ReadonlyArray<string>;
}

interface DeploymentArtifact {
  readonly appName: string;
  readonly version: string;
  readonly files: ReadonlyArray<{
    readonly path: string;
    readonly hash: string;
    readonly size: number;
    readonly contentType: string;
  }>;
  readonly entryFile: string;
}

const generateCDNUrls = (artifact: DeploymentArtifact, cdn: CDNConfig): Readonly<Record<string, string>> => {
  const urls: Record<string, string> = {};

  artifact.files.forEach((file) => {
    const cdnPath = `${cdn.basePath}/${artifact.appName}/${artifact.version}/${file.path}`;
    urls[file.path] = `https://${cdn.domain}${cdnPath}`;
  });

  return urls;
};

const generateCSPDirectives = (apps: ReadonlyArray<DeploymentArtifact>, cdns: ReadonlyArray<CDNConfig>): string => {
  const scriptSources = cdns.map((cdn) => `https://${cdn.domain}`);
  const styleSources = cdns.map((cdn) => `https://${cdn.domain}`);

  return [
    `script-src 'self' ${scriptSources.join(' ')}`,
    `style-src 'self' 'unsafe-inline' ${styleSources.join(' ')}`,
    `connect-src 'self' https://api.example.com`,
    `frame-src 'self'`,
  ].join('; ');
};
回滚机制与版本锁定
快速回滚是微前端部署的安全底线。由于子应用的静态资源在 CDN 上保留了所有历史版本，回滚只需要将版本注册中心的活跃版本指针切换到上一个稳定版本：


interface RollbackPlan {
  readonly appName: string;
  readonly fromVersion: string;
  readonly toVersion: string;
  readonly reason: string;
  readonly timestamp: string;
  readonly operator: string;
}

interface RollbackExecutor {
  readonly execute: (plan: RollbackPlan) => Promise<RollbackResult>;
  readonly verify: (plan: RollbackPlan) => Promise<boolean>;
}

interface RollbackResult {
  readonly success: boolean;
  readonly duration: number;
  readonly affectedUsers: number;
  readonly verificationPassed: boolean;
}

const createRollbackExecutor = (
  registry: VersionRegistry,
  healthCheck: (appName: string) => Promise<boolean>,
): RollbackExecutor => {
  const execute = async (plan: RollbackPlan): Promise<RollbackResult> => {
    const startTime = Date.now();

    await registry.rollback(plan.appName, plan.toVersion);

    await new Promise((resolve) => setTimeout(resolve, 5000));

    const healthy = await healthCheck(plan.appName);

    return {
      success: healthy,
      duration: Date.now() - startTime,
      affectedUsers: 0,
      verificationPassed: healthy,
    };
  };

  const verify = async (plan: RollbackPlan): Promise<boolean> => {
    const versions = await registry.listVersions(plan.appName);
    return versions.some((v) => v.version === plan.toVersion);
  };

  return { execute, verify };
};
版本锁定机制允许运维团队在发现问题时快速冻结某个子应用的版本，阻止新版本的自动部署。这在大型促销活动等关键时期尤其有用。

interface EnvironmentConfig {
  readonly name: 'dev' | 'staging' | 'pre-prod' | 'production';
  readonly registryUrl: string;
  readonly cdnDomain: string;
  readonly apiBaseUrl: string;
  readonly featureFlags: Readonly<Record<string, boolean>>;
  readonly versionStrategy: 'latest' | 'locked' | 'gray';
}

const resolveEnvironment = (): EnvironmentConfig => {
  const hostname = window.location.hostname;

  const envMap: Readonly<Record<string, EnvironmentConfig['name']>> = {
    localhost: 'dev',
    'staging.example.com': 'staging',
    'pre.example.com': 'pre-prod',
    'www.example.com': 'production',
  };

  const envName = envMap[hostname] ?? 'dev';
  return environments[envName];
};
小结
    

  • 微前端部署的核心是子应用独立 CI/CD + 中心化版本注册，实现独立构建、独立部署、协调发现
    • 

  • 灰度发布通过按百分比/用户/地域分流实现渐进式发布，配合运行时指标监控自动决策扩量或回滚
    • 

  • CDN 部署通过 content hash 文件名实现长期缓存，结合 CSP 策略保障资源加载安全
    • 

  • 回滚机制只需切换版本注册中心的活跃版本指针，CDN 上的历史版本始终可用
    • 

  • 多环境管理通过环境配置隔离版本策略、API 端点和功能开关，支持从开发到生产的完整流转
    • 

  • 版本锁定机制在关键时期冻结子应用版本，防止非预期的自动部署引发线上故障
    •
