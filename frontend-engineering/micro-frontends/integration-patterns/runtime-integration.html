运行时集成

核心概念

运行时集成是微前端架构中最灵活的集成方式，子应用在浏览器端动态加载并挂载，主应用充当容器（Shell）角色负责路由分发与生命周期管理。与构建时集成相比，运行时集成允许子应用独立部署、独立发布，真正实现团队自治。

JavaScript Entry 与 HTML Entry
运行时集成根据子应用入口格式分为 JS Entry 和 HTML Entry 两种模式，它们在加载方式、解析粒度和兼容性上存在显著差异。


JS Entry 模式下，主应用直接加载子应用导出的 JavaScript bundle。子应用需要暴露标准化的生命周期函数：


interface MicroAppLifecycle {
  readonly bootstrap: () => Promise<void>;
  readonly mount: (container: HTMLElement) => Promise<void>;
  readonly unmount: () => Promise<void>;
  readonly update?: (props: Record<string, unknown>) => Promise<void>;
}

const createJsEntry = (url: string): Promise<MicroAppLifecycle> => {
  return new Promise((resolve, reject) => {
    const script = document.createElement('script');
    script.src = url;
    script.onload = () => {
      const appExports = (window as Record<string, unknown>).__MICRO_APP_EXPORTS__;
      if (!appExports) {
        reject(new Error(`No exports found from ${url}`));
        return;
      }
      resolve(appExports as MicroAppLifecycle);
    };
    script.onerror = () => reject(new Error(`Failed to load ${url}`));
    document.head.appendChild(script);
  });
};
HTML Entry 模式下，主应用拉取子应用的完整 HTML 文档，解析其中的 CSS 和 JS 资源后分别处理：


interface ParsedHtmlEntry {
  readonly template: string;
  readonly scripts: ReadonlyArray<string>;
  readonly styles: ReadonlyArray<string>;
}

const parseHtmlEntry = async (url: string): Promise<ParsedHtmlEntry> => {
  const html = await fetch(url).then((res) => res.text());
  const doc = new DOMParser().parseFromString(html, 'text/html');

  const scripts = Array.from(doc.querySelectorAll('script[src]')).map(
    (el) => new URL(el.getAttribute('src')!, url).href,
  );

  const styles = Array.from(doc.querySelectorAll('link[rel="stylesheet"]')).map(
    (el) => new URL(el.getAttribute('href')!, url).href,
  );

  const template = doc.body.innerHTML;
  return { template, scripts, styles } as const;
};
HTML Entry 的优势在于子应用无需改造入口文件，主应用能够自动发现并加载所有依赖资源，对存量应用迁移非常友好。但它需要处理相对路径转换、内联脚本提取等复杂逻辑。


生命周期管理
微前端运行时集成的核心在于对子应用生命周期的精确管控。一个健壮的生命周期管理系统需要处理加载、挂载、更新、卸载四个阶段以及各阶段可能出现的异常：


type AppStatus =
  | 'NOT_LOADED'
  | 'LOADING'
  | 'NOT_BOOTSTRAPPED'
  | 'BOOTSTRAPPING'
  | 'NOT_MOUNTED'
  | 'MOUNTING'
  | 'MOUNTED'
  | 'UPDATING'
  | 'UNMOUNTING'
  | 'UNLOADING'
  | 'LOAD_ERROR';

interface ManagedApp {
  readonly name: string;
  readonly activeWhen: (location: Location) => boolean;
  status: AppStatus;
  readonly lifecycle: MicroAppLifecycle;
}

const reroute = async (apps: ReadonlyArray<ManagedApp>): Promise<void> => {
  const toUnmount = apps.filter((app) => app.status === 'MOUNTED' && !app.activeWhen(location));
  const toMount = apps.filter((app) => app.status === 'NOT_MOUNTED' && app.activeWhen(location));

  await Promise.all(
    toUnmount.map(async (app) => {
      app.status = 'UNMOUNTING';
      await app.lifecycle.unmount();
      app.status = 'NOT_MOUNTED';
    }),
  );

  await Promise.all(
    toMount.map(async (app) => {
      app.status = 'MOUNTING';
      const container = document.getElementById(`container-${app.name}`);
      if (container) {
        await app.lifecycle.mount(container);
        app.status = 'MOUNTED';
      }
    }),
  );
};
生命周期状态机的关键设计原则包括：状态转换必须是单向的，不允许跳跃；每个中间状态（如 LOADING、MOUNTING）都应设置超时机制；异常发生时必须将状态回退到安全状态并触发降级逻辑。

预加载与资源调度
运行时集成的主要性能瓶颈在于子应用的异步加载。通过合理的预加载策略，可以在不影响当前页面性能的前提下提前加载可能访问的子应用资源：


interface PrefetchStrategy {
  readonly type: 'idle' | 'hover' | 'visible' | 'immediate';
  readonly apps: ReadonlyArray<string>;
  readonly delay?: number;
}

const prefetchApps = (strategies: ReadonlyArray<PrefetchStrategy>): void => {
  strategies.forEach((strategy) => {
    switch (strategy.type) {
      case 'idle':
        if ('requestIdleCallback' in window) {
          requestIdleCallback(
            () => {
              strategy.apps.forEach(loadAppResources);
            },
            { timeout: strategy.delay ?? 3000 },
          );
        }
        break;
      case 'hover':
        strategy.apps.forEach((appName) => {
          const trigger = document.querySelector(`[data-app="${appName}"]`);
          trigger?.addEventListener('mouseenter', () => loadAppResources(appName), { once: true });
        });
        break;
      case 'visible':
        const observer = new IntersectionObserver((entries) => {
          entries
            .filter((e) => e.isIntersecting)
            .forEach((entry) => {
              const appName = (entry.target as HTMLElement).dataset.app;
              if (appName) loadAppResources(appName);
              observer.unobserve(entry.target);
            });
        });
        strategy.apps.forEach((appName) => {
          const el = document.querySelector(`[data-app="${appName}"]`);
          if (el) observer.observe(el);
        });
        break;
    }
  });
};

const loadAppResources = (appName: string): void => {
  const link = document.createElement('link');
  link.rel = 'prefetch';
  link.href = `/apps/${appName}/manifest.json`;
  document.head.appendChild(link);
};
除了预加载，资源调度还需要考虑缓存策略。已加载的子应用 bundle 应缓存在内存中避免重复请求，同时利用 Service Worker 实现离线缓存。对于大型应用，可以将子应用按路由维度拆分为更小的 chunk，实现渐进式加载。


路由劫持与分发
运行时集成需要接管浏览器的路由系统，将 URL 变化映射到对应的子应用。这涉及对 History API 和 hashchange 事件的劫持：


interface RouteRule {
  readonly path: string;
  readonly appName: string;
  readonly exact?: boolean;
}

const createRouter = (rules: ReadonlyArray<RouteRule>) => {
  const originalPushState = history.pushState.bind(history);
  const originalReplaceState = history.replaceState.bind(history);

  const dispatchRouteChange = (): void => {
    const event = new PopStateEvent('popstate');
    window.dispatchEvent(event);
  };

  history.pushState = (...args: Parameters<typeof history.pushState>) => {
    originalPushState(...args);
    dispatchRouteChange();
  };

  history.replaceState = (...args: Parameters<typeof history.replaceState>) => {
    originalReplaceState(...args);
    dispatchRouteChange();
  };

  const matchRoute = (pathname: string): RouteRule | undefined => {
    return rules.find((rule) => {
      if (rule.exact) return pathname === rule.path;
      return pathname.startsWith(rule.path);
    });
  };

  window.addEventListener('popstate', () => {
    const matched = matchRoute(location.pathname);
    if (matched) {
      activateApp(matched.appName);
    }
  });

  return { matchRoute };
};
路由分发的关键挑战在于子应用内部路由与主应用路由的协调。主应用只负责一级路由匹配，子应用内部的路由交由子应用自身处理。为避免冲突，子应用通常配置 basename 前缀：

小结
    

  • 运行时集成是微前端最灵活的集成方式，支持子应用独立开发、独立部署和技术栈自由
    • 

  • JS Entry 和 HTML Entry 是两种主流入口模式，JS Entry 控制力强，HTML Entry 迁移友好
    • 

  • 生命周期管理通过状态机模型保证子应用在 bootstrap → mount → update → unmount 阶段的有序执行
    • 

  • 预加载策略（idle/hover/visible）可有效缓解运行时加载的性能开销
    • 

  • 路由劫持通过接管 History API 实现主应用到子应用的路由分发，子应用通过 basename 隔离内部路由
    • 

  • 运行时集成的核心挑战在于沙箱隔离、资源调度和生命周期异常处理的工程化实现
    •
