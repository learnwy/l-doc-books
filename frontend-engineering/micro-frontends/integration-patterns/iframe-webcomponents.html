iframe 与 Web Components 集成

核心概念

iframe 和 Web Components 是两种基于浏览器原生能力的微前端集成方案。iframe 提供最强的隔离性，每个子应用运行在独立的浏览器上下文中；Web Components 通过 Shadow DOM 和 Custom Elements 实现组件级别的封装与隔离。两者都不依赖额外的微前端框架，是最「原生」的集成方式。

iframe 深度集成
iframe 是历史最悠久的页面嵌入方案，在微前端场景下依然有其独特价值。现代 iframe 集成不再是简单的 <iframe src="..."> 嵌入，而是需要处理通信、路由同步、自适应布局等一系列工程问题：


interface IframeAppConfig {
  readonly name: string;
  readonly url: string;
  readonly container: string;
  readonly sandbox?: ReadonlyArray<string>;
  readonly allow?: ReadonlyArray<string>;
}

interface IframeMessage {
  readonly type: string;
  readonly source: string;
  readonly payload: unknown;
  readonly timestamp: number;
}

const createIframeApp = (config: IframeAppConfig): HTMLIFrameElement => {
  const iframe = document.createElement('iframe');
  iframe.src = config.url;
  iframe.style.width = '100%';
  iframe.style.border = 'none';

  if (config.sandbox) {
    iframe.sandbox.value = config.sandbox.join(' ');
  }

  if (config.allow) {
    iframe.allow = config.allow.join('; ');
  }

  const container = document.getElementById(config.container);
  container?.appendChild(iframe);

  return iframe;
};

const createMessageBridge = (iframe: HTMLIFrameElement, targetOrigin: string) => {
  const handlers = new Map<string, (payload: unknown) => void>();

  window.addEventListener('message', (event: MessageEvent<IframeMessage>) => {
    if (event.origin !== new URL(targetOrigin).origin) return;
    if (event.source !== iframe.contentWindow) return;

    const handler = handlers.get(event.data.type);
    handler?.(event.data.payload);
  });

  const send = (type: string, payload: unknown): void => {
    const message: IframeMessage = {
      type,
      source: 'host',
      payload,
      timestamp: Date.now(),
    };
    iframe.contentWindow?.postMessage(message, targetOrigin);
  };

  const on = (type: string, handler: (payload: unknown) => void): void => {
    handlers.set(type, handler);
  };

  return { send, on };
};
iframe 应用的高度自适应是常见的工程挑战。由于跨域限制，主应用无法直接读取 iframe 内部的文档高度，需要子应用主动上报：


interface ResizeMessage {
  readonly type: 'RESIZE';
  readonly height: number;
  readonly width: number;
}

const setupAutoResize = (iframe: HTMLIFrameElement, bridge: ReturnType<typeof createMessageBridge>): void => {
  bridge.on('RESIZE', (payload) => {
    const { height } = payload as ResizeMessage;
    iframe.style.height = `${height}px`;
  });
};

const childReportSize = (): void => {
  const observer = new ResizeObserver((entries) => {
    const entry = entries[0];
    if (!entry) return;
    const message: ResizeMessage = {
      type: 'RESIZE',
      height: entry.contentRect.height,
      width: entry.contentRect.width,
    };
    window.parent.postMessage(message, '*');
  });
  observer.observe(document.body);
};

Web Components 封装
Web Components 通过 Custom Elements + Shadow DOM + HTML Templates 三大标准实现组件级别的微前端集成。每个子应用封装为一个自定义元素，主应用通过标签名引用：


interface MicroAppElement extends HTMLElement {
  readonly appName: string;
  connectedCallback(): void;
  disconnectedCallback(): void;
  attributeChangedCallback(name: string, oldVal: string, newVal: string): void;
}

const defineMicroApp = (
  tagName: string,
  renderFn: (root: ShadowRoot, props: Record<string, string>) => void,
  cleanupFn: (root: ShadowRoot) => void,
): void => {
  class MicroApp extends HTMLElement implements MicroAppElement {
    readonly appName = tagName;
    private shadow: ShadowRoot;

    static get observedAttributes(): ReadonlyArray<string> {
      return ['route', 'theme', 'locale'];
    }

    constructor() {
      super();
      this.shadow = this.attachShadow({ mode: 'open' });
    }

    connectedCallback(): void {
      const props = this.collectProps();
      renderFn(this.shadow, props);
    }

    disconnectedCallback(): void {
      cleanupFn(this.shadow);
    }

    attributeChangedCallback(name: string, _oldVal: string, newVal: string): void {
      const props = this.collectProps();
      props[name] = newVal;
      renderFn(this.shadow, props);
    }

    private collectProps(): Record<string, string> {
      const props: Record<string, string> = {};
      for (const attr of this.attributes) {
        props[attr.name] = attr.value;
      }
      return props;
    }
  }

  customElements.define(tagName, MicroApp);
};
Shadow DOM 的样式隔离在微前端场景中尤其有价值。子应用的 CSS 不会泄漏到主应用，主应用的全局样式也不会影响子应用内部。但当需要主题同步时，需要通过 CSS Custom Properties（CSS 变量）穿透 Shadow DOM 边界：


interface ThemeContract {
  readonly '--primary-color': string;
  readonly '--bg-color': string;
  readonly '--text-color': string;
  readonly '--border-radius': string;
  readonly '--font-family': string;
}

const injectThemeVariables = (host: HTMLElement, theme: ThemeContract): void => {
  Object.entries(theme).forEach(([key, value]) => {
    host.style.setProperty(key, value);
  });
};

const createThemedComponent = (shadow: ShadowRoot): void => {
  const style = document.createElement('style');
  style.textContent = `
    :host {
      display: block;
      font-family: var(--font-family, system-ui);
      color: var(--text-color, #333);
      background: var(--bg-color, #fff);
    }
    .button {
      background: var(--primary-color, #007bff);
      border-radius: var(--border-radius, 4px);
      color: white;
      padding: 8px 16px;
      border: none;
      cursor: pointer;
    }
  `;
  shadow.appendChild(style);
};
路由与状态同步
无论是 iframe 还是 Web Components，子应用与主应用之间的路由同步和状态共享都是核心工程问题。iframe 的路由同步需要双向通信，而 Web Components 可以利用 CustomEvent 实现更自然的事件流：


interface RouteChangeEvent {
  readonly path: string;
  readonly params: Record<string, string>;
  readonly source: 'host' | 'child';
}

const createRouteSync = (element: HTMLElement) => {
  const notifyRouteChange = (path: string, params: Record<string, string>): void => {
    element.dispatchEvent(
      new CustomEvent<RouteChangeEvent>('route-change', {
        detail: { path, params, source: 'child' },
        bubbles: true,
        composed: true,
      }),
    );
  };

  const listenRouteChange = (callback: (event: RouteChangeEvent) => void): (() => void) => {
    const handler = (e: Event) => {
      const detail = (e as CustomEvent<RouteChangeEvent>).detail;
      if (detail.source !== 'child') {
        callback(detail);
      }
    };
    element.addEventListener('route-change', handler);
    return () => element.removeEventListener('route-change', handler);
  };

  return { notifyRouteChange, listenRouteChange };
};
对于 iframe 场景，由于跨域限制，路由同步只能通过 postMessage。为了保证消息可靠性，可以引入请求-响应模式：


interface RpcMessage {
  readonly id: string;
  readonly method: string;
  readonly params: unknown;
}

interface RpcResponse {
  readonly id: string;
  readonly result?: unknown;
  readonly error?: string;
}

const createRpcBridge = (target: Window, origin: string) => {
  const pending = new Map<
    string,
    {
      resolve: (value: unknown) => void;
      reject: (reason: string) => void;
    }
  >();

  window.addEventListener('message', (event: MessageEvent<RpcResponse>) => {
    if (event.origin !== origin) return;
    const { id, result, error } = event.data;
    const handler = pending.get(id);
    if (!handler) return;
    pending.delete(id);
    error ? handler.reject(error) : handler.resolve(result);
  });

  const call = (method: string, params: unknown): Promise<unknown> => {
    return new Promise((resolve, reject) => {
      const id = crypto.randomUUID();
      pending.set(id, { resolve, reject });
      const message: RpcMessage = { id, method, params };
      target.postMessage(message, origin);
      setTimeout(() => {
        if (pending.has(id)) {
          pending.delete(id);
          reject('RPC timeout');
        }
      }, 5000);
    });
  };

  return { call };
};

在实际项目中，iframe 和 Web Components 经常搭配使用。主框架中的核心模块使用 Web Components 实现轻量集成，而需要强隔离的第三方或遗留模块通过 iframe 嵌入。这种混合策略兼顾了性能和安全性。


Web Components 的浏览器兼容性已经非常成熟，Chrome、Firefox、Safari、Edge 均已原生支持。对于需要支持旧版浏览器的场景，可以使用 @webcomponents/webcomponentsjs polyfill。Lit 框架提供了更便捷的 Web Components 开发体验，封装了响应式属性、模板语法和样式管理。


小结
    

  • iframe 提供最强的隔离性（独立浏览器上下文），适合嵌入第三方应用和需要严格安全隔离的场景
    • 

  • Web Components 通过 Shadow DOM + Custom Elements 实现组件级封装，支持跨框架复用
    • 

  • iframe 通信依赖 postMessage，需要构建消息桥和 RPC 机制保证可靠性
    • 

  • Web Components 利用 CustomEvent + composed 实现跨 Shadow DOM 的事件传播
    • 

  • CSS Custom Properties 是穿透 Shadow DOM 边界同步主题的标准方案
    • 

  • 实际项目中推荐混合策略：核心模块用 Web Components，强隔离模块用 iframe
    •
