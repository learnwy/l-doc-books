模式与组合 简介

React 的组件模型天然支持组合，但"能组合"和"善组合"之间有着巨大的差距。优秀的组件设计不仅要实现功能，还要提供清晰的 API、灵活的扩展性和良好的容错能力。React 社区在十余年的实践中沉淀了一系列经典的组件设计模式，这些模式解决的不是"能不能做"的问题，而是"怎么做更好"的问题。

第一节"复合组件"介绍一种优雅的多组件协作模式。通过隐式的状态共享让一组组件像一个整体一样工作，对外提供声明式的、类似 HTML 原生元素的使用体验——Select 与 Option、Tabs 与 TabPanel、Accordion 与 AccordionItem——复合组件是构建可组合 UI 库的核心手法。

第二节"Render Props 与 HOC"回顾两种经典的逻辑复用模式。虽然自定义 Hook 已经成为主流的逻辑复用方式，但 Render Props 在渲染控制反转场景中仍有独特价值，高阶组件在横切关注点（如权限、日志、数据注入）方面依然广泛使用——理解这些模式的设计动机和权衡取舍，有助于在不同场景下做出更明智的选择。

第三节"无头组件"探索逻辑与表现完全分离的组件设计范式。无头组件只提供行为和状态管理，将所有 UI 渲染的控制权交给使用者——这种模式在 Headless UI、Radix、Downshift 等库中被广泛采用，是构建高度可定制组件的最佳实践。

第四节"错误边界"关注 React 应用的弹性设计。错误边界如何捕获子组件树中的运行时错误、错误恢复策略的设计、与 Suspense 的协同使用，以及在生产环境中构建优雅降级体验——没有错误处理的应用就像没有安全带的汽车，错误边界是 React 应用健壮性的最后一道防线。
