Hooks 内部机制

Hooks 的存储结构

每个函数组件对应一个 Fiber 节点，该节点的 memoizedState 属性指向一个 Hook 链表。组件中每次调用一个 Hook（如 useState、useEffect），都会在链表中创建一个节点。

interface Hook {
  memoizedState: any;
  baseState: any;
  baseQueue: Update<any> | null;
  queue: UpdateQueue<any> | null;
  next: Hook | null;
}

interface UpdateQueue<S> {
  pending: Update<S> | null;
  dispatch: ((action: any) => void) | null;
  lastRenderedReducer: ((state: S, action: any) => S) | null;
  lastRenderedState: S | null;
}
不同 Hook 类型在 memoizedState 中存储的内容各不相同：






Hook
memoizedState 存储内容





useState
当前 state 值




useReducer
当前 state 值




useEffect
Effect 对象（create, destroy, deps）




useMemo
[计算结果, deps]




useCallback
[回调函数, deps]




useRef
{ current: value }







Dispatcher 分发器
React 根据组件的渲染阶段选择不同的 Dispatcher（分发器），决定 Hook 函数的具体实现：


const HooksDispatcherOnMount = {
  useState: mountState,
  useEffect: mountEffect,
  useRef: mountRef,
  useMemo: mountMemo,
  useCallback: mountCallback,
};

const HooksDispatcherOnUpdate = {
  useState: updateState,
  useEffect: updateEffect,
  useRef: updateRef,
  useMemo: updateMemo,
  useCallback: updateCallback,
};

function renderWithHooks(current: FiberNode | null, workInProgress: FiberNode, Component: Function, props: any): any {
  if (current !== null && current.memoizedState !== null) {
    ReactCurrentDispatcher.current = HooksDispatcherOnUpdate;
  } else {
    ReactCurrentDispatcher.current = HooksDispatcherOnMount;
  }

  const children = Component(props);

  ReactCurrentDispatcher.current = ContextOnlyDispatcher;

  return children;
}
渲染结束后 Dispatcher 被设置为 ContextOnlyDispatcher，此时调用任何 Hook 都会报错，防止在组件函数体外使用 Hook。




useState 的实现
Mount 阶段
首次渲染时，mountState 创建一个新的 Hook 节点并加入链表：


function mountState<S>(initialState: S | (() => S)): [S, (action: S | ((prev: S) => S)) => void] {
  const hook = mountWorkInProgressHook();

  if (typeof initialState === 'function') {
    initialState = (initialState as () => S)();
  }

  hook.memoizedState = initialState;
  hook.baseState = initialState;

  const queue: UpdateQueue<S> = {
    pending: null,
    dispatch: null,
    lastRenderedReducer: basicStateReducer,
    lastRenderedState: initialState,
  };
  hook.queue = queue;

  const dispatch = (queue.dispatch = dispatchSetState.bind(null, currentlyRenderingFiber, queue));

  return [hook.memoizedState, dispatch];
}
Update 阶段
后续渲染时，updateState 从链表中取出对应的 Hook，处理队列中的所有更新：


function updateState<S>(initialState: S | (() => S)): [S, (action: S | ((prev: S) => S)) => void] {
  return updateReducer(basicStateReducer, initialState);
}

function basicStateReducer<S>(state: S, action: S | ((prev: S) => S)): S {
  return typeof action === 'function' ? (action as (prev: S) => S)(state) : action;
}


提示： useState 本质上是 useReducer 的语法糖，它使用内置的 basicStateReducer 作为 reducer 函数。






Hook 链表与调用顺序
React 依赖 Hook 的调用顺序来匹配 Mount 和 Update 阶段的 Hook。第 N 次调用 Hook 对应链表中第 N 个节点。这就是 Rules of Hooks 的根本原因。


违反规则的后果
function BrokenComponent({ showExtra }: { showExtra: boolean }) {
  const [name, setName] = useState('');

  if (showExtra) {
    const [extra, setExtra] = useState('');
  }

  const [count, setCount] = useState(0);

  return null;
}

💥 错位





当 showExtra 从 true 变为 false 时，Hook 调用次数发生变化，导致 Update 阶段的 Hook 与 Mount 阶段的对应关系错乱。




Rules of Hooks
基于上述实现机制，React 强制要求遵循两条规则：






规则
原因
正确做法





只在最顶层调用 Hook
保证调用顺序每次渲染一致
不要在条件、循环、嵌套函数中调用




只在 React 函数中调用 Hook
需要 Fiber 上下文和 Dispatcher
在函数组件或自定义 Hook 中调用





使用 eslint-plugin-react-hooks 的 rules-of-hooks 规则可以在编译期捕获违规：


// .eslintrc.ts
const config = {
  plugins: ['react-hooks'],
  rules: {
    'react-hooks/rules-of-hooks': 'error',
    'react-hooks/exhaustive-deps': 'warn',
  },
};


小结
    

  • Hook 以链表形式存储在 Fiber 节点的 memoizedState 上，按调用顺序依次链接
    • 

  • React 通过 Dispatcher 在 Mount 和 Update 阶段切换不同的 Hook 实现
    • 

  • useState 是 useReducer 的语法糖，底层共用相同的更新队列机制
    • 

  • Hook 的正确性依赖于调用顺序的稳定性，条件调用会导致链表错位
    • 

  • 必须遵守 Rules of Hooks：只在顶层调用、只在 React 函数中调用
    •
