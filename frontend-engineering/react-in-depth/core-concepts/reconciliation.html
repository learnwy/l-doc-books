协调算法

什么是协调

协调（Reconciliation） 是 React 比较新旧两棵虚拟 DOM 树，计算出最小变更集并应用到真实 DOM 的过程。由于通用树 diff 算法的时间复杂度为 O(n³)，React 基于两个启发式假设将复杂度降至 O(n)：

  1. 不同类型的元素会产生不同的树
  2. 通过 key 属性标识哪些子元素在不同渲染间是稳定的


Diffing 策略
单节点 Diff
当新的 JSX 只有一个子元素时，React 遍历旧的子 Fiber 链表，寻找 key 和 type 都匹配的节点：


function reconcileSingleElement(
  returnFiber: FiberNode,
  currentFirstChild: FiberNode | null,
  element: ReactElement,
): FiberNode {
  const key = element.key;
  let child = currentFirstChild;

  while (child !== null) {
    if (child.key === key) {
      if (child.type === element.type) {
        deleteRemainingChildren(returnFiber, child.sibling);
        const existing = useFiber(child, element.props);
        existing.return = returnFiber;
        return existing;
      }
      deleteRemainingChildren(returnFiber, child);
      break;
    } else {
      deleteChild(returnFiber, child);
    }
    child = child.sibling;
  }

  const created = createFiberFromElement(element);
  created.return = returnFiber;
  return created;
}

多节点 Diff
当子元素为数组时，React 使用两轮遍历策略：


第一轮： 从左到右逐个比较新旧节点，处理更新的情况。


function reconcileChildrenArray(
  returnFiber: FiberNode,
  currentFirstChild: FiberNode | null,
  newChildren: ReactElement[],
): FiberNode | null {
  let oldFiber = currentFirstChild;
  let newIdx = 0;
  let lastPlacedIndex = 0;

  for (; oldFiber !== null && newIdx < newChildren.length; newIdx++) {
    if (oldFiber.index > newIdx) {
      break;
    }
    const newFiber = updateSlot(returnFiber, oldFiber, newChildren[newIdx]);
    if (newFiber === null) break;
    lastPlacedIndex = placeChild(newFiber, lastPlacedIndex, newIdx);
    oldFiber = oldFiber.sibling;
  }

  // 第二轮处理剩余节点...
}
第二轮： 处理新增、删除和移动。将剩余旧节点放入 Map，通过 key 快速查找可复用节点。




Key 策略
key 是协调算法的核心优化手段。正确使用 key 可以大幅减少不必要的 DOM 操作。


正确的 key 使用
interface TodoItem {
  id: string;
  text: string;
}

function TodoList({ items }: { items: TodoItem[] }) {
  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>{item.text}</li>
      ))}
    </ul>
  );
}

提示： 当列表会发生重新排序、插入或删除时，必须使用稳定且唯一的业务 ID 作为 key，绝不要使用数组索引。






Bailout 优化
当 React 判断组件无需更新时，可以跳过该子树的 Render 阶段，这个优化叫做 Bailout。Bailout 的触发条件：


React 使用 全等比较（===） 来判断 props 是否变化。这意味着如果父组件每次渲染都创建新的对象字面量或匿名函数作为 props，子组件将永远无法 Bailout。


function Parent() {
  const [count, setCount] = useState(0);

  const handleClick = useCallback(() => {
    console.log('clicked');
  }, []);

  const config = useMemo(() => ({ theme: 'dark' }), []);

  return (
    <div>
      <button onClick={() => setCount((c) => c + 1)}>+1</button>
      <ExpensiveChild onClick={handleClick} config={config} />
    </div>
  );
}

const ExpensiveChild = React.memo(function ExpensiveChild({
  onClick,
  config,
}: {
  onClick: () => void;
  config: { theme: string };
}) {
  return <div onClick={onClick}>{config.theme}</div>;
});


元素类型比较
当元素类型发生变化时，React 会卸载整棵旧子树（触发 componentWillUnmount / cleanup），然后挂载全新的子树。这一行为对性能有重大影响：


function App({ isLoggedIn }: { isLoggedIn: boolean }) {
  if (isLoggedIn) {
    return <Dashboard />;
  }
  return <LoginForm />;
}
Dashboard 和 LoginForm 是不同类型的组件，切换时会完全销毁和重建。如果想要保持状态，可以使用条件渲染或 CSS 控制显示隐藏。


function App({ isLoggedIn }: { isLoggedIn: boolean }) {
  return (
    <div>
      <div style={{ display: isLoggedIn ? 'block' : 'none' }}>
        <Dashboard />
      </div>
      {!isLoggedIn && <LoginForm />}
    </div>
  );
}


小结
    

  • React 协调算法基于 类型相同则复用 和 key 标识稳定性 两大假设，将 diff 复杂度从 O(n³) 降至 O(n)
    • 

  • 单节点 diff 逐个匹配 key 和 type；多节点 diff 采用两轮遍历 + Map 查找策略
    • 

  • key 必须使用稳定且唯一的业务标识，不要使用数组索引或随机值
    • 

  • Bailout 通过全等比较 props 跳过无变化的子树，配合 React.memo、useMemo、useCallback 可以显著提升性能
    • 

  • 元素类型变化会导致整棵子树销毁重建，设计组件结构时需要注意类型的稳定性
