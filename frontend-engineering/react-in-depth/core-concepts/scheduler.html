调度器

Scheduler 的角色

React 的 Scheduler（调度器） 是一个独立的包 scheduler，负责管理任务的优先级和执行时机。它决定哪些任务先执行、何时让出主线程、何时恢复被中断的任务。Scheduler 是 React 并发模式的基础设施。



Task Priority 任务优先级
Scheduler 定义了 5 个优先级级别，每个级别对应不同的超时时间。超时时间决定了任务等待多久后会被强制执行：


type PriorityLevel = 1 | 2 | 3 | 4 | 5;

const ImmediatePriority: PriorityLevel = 1;
const UserBlockingPriority: PriorityLevel = 2;
const NormalPriority: PriorityLevel = 3;
const LowPriority: PriorityLevel = 4;
const IdlePriority: PriorityLevel = 5;

const IMMEDIATE_PRIORITY_TIMEOUT = -1;
const USER_BLOCKING_PRIORITY_TIMEOUT = 250;
const NORMAL_PRIORITY_TIMEOUT = 5000;
const LOW_PRIORITY_TIMEOUT = 10000;
const IDLE_PRIORITY_TIMEOUT = 1073741823; // ~12.4 天

提示： 超时时间不是任务的执行时长，而是任务从创建到被强制执行的最大等待时间。过期的任务优先级最高，会被立即执行以避免饥饿。






任务队列实现
Scheduler 维护两个队列，都使用最小堆（Min Heap） 实现，按照到期时间排序：


interface Task {
  id: number;
  callback: ((didTimeout: boolean) => void) | null;
  priorityLevel: PriorityLevel;
  startTime: number;
  expirationTime: number;
  sortIndex: number;
}

const taskQueue: Task[] = [];
const timerQueue: Task[] = [];

function scheduleCallback(
  priorityLevel: PriorityLevel,
  callback: (didTimeout: boolean) => void,
  options?: { delay: number },
): Task {
  const currentTime = getCurrentTime();
  const startTime = options?.delay ? currentTime + options.delay : currentTime;

  const timeout = getTimeoutByPriority(priorityLevel);
  const expirationTime = startTime + timeout;

  const newTask: Task = {
    id: taskIdCounter++,
    callback,
    priorityLevel,
    startTime,
    expirationTime,
    sortIndex: -1,
  };

  if (startTime > currentTime) {
    newTask.sortIndex = startTime;
    push(timerQueue, newTask);
    advanceTimers(currentTime);
  } else {
    newTask.sortIndex = expirationTime;
    push(taskQueue, newTask);
    requestHostCallback();
  }

  return newTask;
}


MessageChannel 与宿主回调
Scheduler 需要一种机制在浏览器空闲时执行任务，同时能够让出主线程。React 选择了 MessageChannel 而非 requestAnimationFrame 或 setTimeout。

const channel = new MessageChannel();
const port = channel.port2;

let scheduledHostCallback: ((hasTimeRemaining: boolean, initialTime: number) => boolean) | null = null;
let isMessageLoopRunning = false;

channel.port1.onmessage = () => {
  if (scheduledHostCallback !== null) {
    const currentTime = getCurrentTime();
    const hasTimeRemaining = true;

    let hasMoreWork = true;
    try {
      hasMoreWork = scheduledHostCallback(hasTimeRemaining, currentTime);
    } finally {
      if (hasMoreWork) {
        port.postMessage(null);
      } else {
        isMessageLoopRunning = false;
        scheduledHostCallback = null;
      }
    }
  }
};

function requestHostCallback(callback: (hasTimeRemaining: boolean, initialTime: number) => boolean): void {
  scheduledHostCallback = callback;
  if (!isMessageLoopRunning) {
    isMessageLoopRunning = true;
    port.postMessage(null);
  }
}


Work Loop 调度流程
Scheduler 的 Work Loop 不断从 taskQueue 中取出最高优先级的任务执行，直到时间片用完或队列为空：


function workLoop(initialTime: number): boolean {
  let currentTime = initialTime;
  advanceTimers(currentTime);

  let currentTask = peek(taskQueue);

  while (currentTask !== null) {
    if (currentTask.expirationTime > currentTime && shouldYieldToHost()) {
      break;
    }

    const callback = currentTask.callback;
    if (callback !== null) {
      currentTask.callback = null;
      const didUserCallbackTimeout = currentTask.expirationTime <= currentTime;
      const continuationCallback = callback(didUserCallbackTimeout);

      if (typeof continuationCallback === 'function') {
        currentTask.callback = continuationCallback;
        return true;
      }

      if (currentTask === peek(taskQueue)) {
        pop(taskQueue);
      }
    } else {
      pop(taskQueue);
    }

    advanceTimers(currentTime);
    currentTask = peek(taskQueue);
  }

  return currentTask !== null;
}


提示： 当任务回调返回一个函数时（continuation），说明任务尚未完成，Scheduler 会在下一个时间切片继续执行。这正是 React Render 阶段被中断后能够恢复的原因。

小结
    

  • Scheduler 是 React 的独立调度包，负责任务的优先级排序和时间切片执行
    • 

  • 5 个优先级级别通过超时时间控制任务的紧迫程度，过期任务会被强制执行以避免饥饿
    • 

  • 使用两个最小堆队列分别管理延迟任务和就绪任务
    • 

  • 选择 MessageChannel 而非 setTimeout 或 rAF，因为它没有最小延迟且在宏任务中执行
    • 

  • 任务回调可以返回 continuation 函数，使得被中断的工作能够在下一个时间切片恢复
