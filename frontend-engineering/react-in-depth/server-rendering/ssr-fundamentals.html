SSR 基础

什么是服务端渲染

服务端渲染（Server-Side Rendering, SSR） 是在服务器上将 React 组件渲染为 HTML 字符串，发送给浏览器后再通过 水合（Hydration） 将静态 HTML 转换为可交互的 React 应用。

renderToString
renderToString 是最基础的 SSR API，将 React 元素同步渲染为 HTML 字符串：


import { renderToString } from 'react-dom/server';
import express from 'express';

const app = express();

app.get('*', (req, res) => {
  const html = renderToString(<App url={req.url} />);

  res.send(`
    <!DOCTYPE html>
    <html>
      <head>
        <title>React SSR</title>
      </head>
      <body>
        <div id="root">${html}</div>
        <script src="/bundle.js"></script>
      </body>
    </html>
  `);
});


提示： renderToString 是同步阻塞的，对于大型页面会阻塞 Node.js 事件循环。React 18 推荐使用 renderToPipeableStream 替代。






Hydration 水合
水合是在客户端将静态 HTML"激活"为可交互应用的过程。React 不会重新创建 DOM，而是复用服务端生成的 DOM 节点，仅绑定事件处理器和建立内部数据结构。


import { hydrateRoot } from 'react-dom/client';

hydrateRoot(document.getElementById('root')!, <App />);

Streaming SSR
React 18 引入了流式 SSR，使用 renderToPipeableStream 逐步发送 HTML，不必等待整个页面渲染完成：


import { renderToPipeableStream } from 'react-dom/server';

app.get('*', (req, res) => {
  const { pipe, abort } = renderToPipeableStream(<App url={req.url} />, {
    bootstrapScripts: ['/bundle.js'],
    onShellReady() {
      res.statusCode = 200;
      res.setHeader('Content-Type', 'text/html');
      pipe(res);
    },
    onShellError(error) {
      res.statusCode = 500;
      res.send('<h1>服务器错误</h1>');
    },
    onError(error) {
      console.error(error);
    },
  });

  setTimeout(() => abort(), 10000);
});

Selective Hydration
选择性水合是 React 18 的重要特性。配合 Suspense，React 可以在部分内容尚未下载完成时就开始水合其他部分：


function App() {
  return (
    <div>
      <Header />
      <Suspense fallback={<SidebarSkeleton />}>
        <Sidebar />
      </Suspense>
      <Suspense fallback={<ContentSkeleton />}>
        <MainContent />
      </Suspense>
      <Suspense fallback={<CommentsSkeleton />}>
        <Comments />
      </Suspense>
    </div>
  );
}
水合过程：


    

  1. Header 最先水合（不在 Suspense 中）
    2. 

  2. Sidebar、MainContent、Comments 并行加载代码
    3. 

  3. 哪个先加载完就先水合哪个
    4. 

  4. 如果用户点击了某个区域，React 会优先水合该区域
    5. 





提示： 选择性水合使得大型应用的 TTI 大幅提升——用户点击的区域会被优先水合，无需等待整个页面水合完成。






小结
    

  • SSR 在服务器上渲染 HTML，提升首屏速度和 SEO，但增加服务器负载和水合成本
    • 

  • renderToString 是同步 API，renderToPipeableStream 是异步流式 API（推荐）
    • 

  • 水合 复用服务端 DOM 并绑定事件，服务端和客户端渲染结果必须一致
    • 

  • 流式 SSR 配合 Suspense 逐步发送 HTML，浏览器可以更早开始渲染
    • 

  • 选择性水合 允许 React 优先水合用户正在交互的区域，显著提升 TTI
    •
