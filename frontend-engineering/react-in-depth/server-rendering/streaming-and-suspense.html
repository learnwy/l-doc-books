流式渲染与 Suspense

传统 SSR 的瓶颈

传统 SSR 是"全有或全无"的——服务器必须渲染完整个页面的 HTML 才能发送响应，水合也必须处理完整个组件树才能开始交互。这在页面包含慢速数据源时会导致严重的性能问题。

Suspense Boundaries
Suspense 组件在流式 SSR 中定义了加载边界。服务端首先发送 Suspense 的 fallback HTML，当实际内容准备好后通过内联 <script> 替换 fallback。


function App() {
  return (
    <div>
      <Header />

      <Suspense fallback={<HeroSkeleton />}>
        <HeroBanner />
      </Suspense>

      <Suspense fallback={<ProductsSkeleton />}>
        <ProductList />
      </Suspense>

      <Suspense fallback={<ReviewsSkeleton />}>
        <Reviews />
      </Suspense>

      <Footer />
    </div>
  );
}

Streaming HTML
React 的流式 SSR 使用浏览器原生的 HTML 流式解析能力。服务端通过 chunked transfer encoding 逐段发送 HTML：


import { renderToPipeableStream } from 'react-dom/server';

app.get('*', (req, res) => {
  const { pipe } = renderToPipeableStream(<App />, {
    bootstrapScripts: ['/main.js'],
    onShellReady() {
      res.setHeader('Content-Type', 'text/html; charset=utf-8');
      res.setHeader('Transfer-Encoding', 'chunked');
      pipe(res);
    },
  });
});
服务端发送的 HTML 结构（简化）：


<!-- 第一块：Shell -->
<div id="root">
  <header>网站标题</header>
  <div>
    <!--$?--><template id="B:0"></template>
    <div>加载中...</div>
    <!--/$-->
  </div>
  <footer>页脚</footer>
</div>

<!-- 后续块：延迟内容 -->
<div hidden id="S:0">
  <h1>实际内容</h1>
  <p>这是从服务器获取的数据</p>
</div>
<script>
  // React 的内联脚本，将 S:0 的内容替换到 B:0 的位置
  $RC('B:0', 'S:0');
</script>


提示： <!--$?--> 和 <!--/$--> 是 React 的 Suspense 边界标记。$RC 是 React 注入的客户端脚本函数，负责用实际内容替换 fallback。






Progressive Loading 渐进式加载
通过嵌套 Suspense 可以实现精细的渐进式加载策略：


async function ArticlePage({ slug }: { slug: string }) {
  const article = await fetchArticle(slug);

  return (
    <article>
      <h1>{article.title}</h1>
      <p className="meta">
        {article.author} · {article.date}
      </p>

      <div>{article.content}</div>

      <Suspense fallback={<RelatedSkeleton />}>
        <RelatedArticles category={article.category} />
      </Suspense>

      <Suspense fallback={<CommentsSkeleton />}>
        <Comments articleId={article.id} />
        <Suspense fallback={<ReplyFormSkeleton />}>
          <ReplyForm articleId={article.id} />
        </Suspense>
      </Suspense>
    </article>
  );
}
优先级控制
结合流式渲染和数据获取策略，可以控制内容的加载优先级：


async function Dashboard() {
  const criticalDataPromise = fetchCriticalData();
  const secondaryDataPromise = fetchSecondaryData();
  const tertiaryDataPromise = fetchTertiaryData();

  const criticalData = await criticalDataPromise;

  return (
    <div>
      <CriticalSection data={criticalData} />

      <Suspense fallback={<SecondaryLoader />}>
        <SecondarySection dataPromise={secondaryDataPromise} />
      </Suspense>

      <Suspense fallback={<TertiaryLoader />}>
        <TertiarySection dataPromise={tertiaryDataPromise} />
      </Suspense>
    </div>
  );
}

async function SecondarySection({ dataPromise }: { dataPromise: Promise<SecondaryData> }) {
  const data = await dataPromise;
  return <div>{data.content}</div>;
}

// app/blog/[slug]/page.tsx
export async function generateMetadata({ params }: { params: { slug: string } }): Promise<Metadata> {
  const article = await fetchArticle(params.slug);
  return {
    title: article.title,
    description: article.excerpt,
    openGraph: {
      title: article.title,
      description: article.excerpt,
      images: [article.coverImage],

  };
}


错误处理
Suspense 边界内的错误会被最近的 Error Boundary 捕获。在流式 SSR 中，如果错误发生在 Suspense 内部，只有该区域会显示错误，其他区域正常：


function App() {
  return (
    <div>
      <Header />
      <ErrorBoundary fallback={<p>内容加载失败</p>}>
        <Suspense fallback={<ContentSkeleton />}>
          <MainContent />
        </Suspense>
      </ErrorBoundary>
      <ErrorBoundary fallback={<p>评论加载失败</p>}>
        <Suspense fallback={<CommentsSkeleton />}>
          <Comments />
        </Suspense>
      </ErrorBoundary>
    </div>
  );
}


小结
    

  • 流式 SSR 突破传统 SSR 的"全有或全无"瓶颈，Shell 就绪即可发送响应
    • 

  • Suspense 定义流式边界，服务端先发送 fallback，延迟内容就绪后通过内联脚本替换
    • 

  • 渐进式加载 通过嵌套 Suspense 实现内容的分层加载，关键内容优先展示
    • 

  • 流式 HTML 使用 chunked transfer encoding，浏览器可以边接收边解析渲染
    • 

  • 错误处理通过 ErrorBoundary + Suspense 组合实现局部降级，不影响其他区域
    •
