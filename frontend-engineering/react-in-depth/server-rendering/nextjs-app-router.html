Next.js App Router 应用路由

App Router 架构

Next.js 13 引入的 App Router 基于 React Server Components 构建，使用文件系统路由。每个路由段可以定义独立的布局、加载状态、错误处理和元数据。



Layout / Page / Loading / Error
Layout
Layout 在路由切换时不重新渲染，保持状态。根布局必须包含 <html> 和 <body>：


// app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="zh-CN">
      <body>
        <nav>
          <Link href="/">首页</Link>
          <Link href="/blog">博客</Link>
          <Link href="/about">关于</Link>
        </nav>
        <main>{children}</main>
      </body>
    </html>
  );
}

// app/blog/layout.tsx
export default function BlogLayout({ children }: { children: React.ReactNode }) {
  return (
    <div className="blog-layout">
      <aside>
        <BlogSidebar />
      </aside>
      <section>{children}</section>
    </div>
  );
}
Page
每个路由段的 page.tsx 定义该路由的 UI，默认为 Server Component：


// app/blog/page.tsx
interface Article {
  id: string;
  title: string;
  excerpt: string;
  createdAt: string;
}

export default async function BlogPage() {
  const articles: Article[] = await fetch('https://api.example.com/articles', {
    next: { revalidate: 60 },
  }).then((res) => res.json());

  return (
    <div>
      <h1>博客文章</h1>
      <ul>
        {articles.map((article) => (
          <li key={article.id}>
            <Link href={`/blog/${article.id}`}>
              <h2>{article.title}</h2>
              <p>{article.excerpt}</p>
            </Link>
          </li>
        ))}
      </ul>
    </div>
  );
}
Loading
loading.tsx 自动包裹在 Suspense 中，在页面数据加载时显示：


// app/blog/[slug]/loading.tsx
export default function Loading() {
  return (
    <div className="skeleton">
      <div className="skeleton-title" />
      <div className="skeleton-line" />
      <div className="skeleton-line" />
      <div className="skeleton-line short" />
    </div>
  );
}
Error
error.tsx 作为错误边界捕获该路由段的错误：


// app/blog/[slug]/error.tsx
'use client';

export default function Error({ error, reset }: { error: Error & { digest?: string }; reset: () => void }) {
  return (
    <div>
      <h2>加载文章出错</h2>
      <p>{error.message}</p>
      <button onClick={reset}>重试</button>
    </div>
  );
}

Parallel Routes
并行路由允许在同一布局中同时渲染多个页面，每个 slot 独立加载和导航：


// app/dashboard/layout.tsx
export default function DashboardLayout({
  children,
  analytics,
  team,
}: {
  children: React.ReactNode;
  analytics: React.ReactNode;
  team: React.ReactNode;
}) {
  return (
    <div className="dashboard">
      <div className="main">{children}</div>
      <div className="sidebar">
        {analytics}
        {team}
      </div>
    </div>
  );
}
app/dashboard/
├── layout.tsx
├── page.tsx
├── @analytics/
│   └── page.tsx
└── @team/
    └── page.tsx


Intercepting Routes
拦截路由允许在当前布局中显示另一个路由的内容，常用于模态框：


app/
├── feed/
│   └── page.tsx
├── photo/
│   └── [id]/
│       └── page.tsx        (独立访问的完整页面)
└── feed/
    └── (..)photo/
        └── [id]/
            └── page.tsx    (在 feed 中以模态框显示)
// app/feed/(..)photo/[id]/page.tsx
export default function PhotoModal({ params }: { params: { id: string } }) {
  return (
    <Modal>
      <PhotoDetail id={params.id} />
    </Modal>
  );
}

// app/photo/[id]/page.tsx
export default function PhotoPage({ params }: { params: { id: string } }) {
  return (
    <div className="full-page">
      <PhotoDetail id={params.id} />
    </div>
  );
}


提示： 拦截路由使用 (.) 匹配同级、(..) 匹配上级、(..)(..) 匹配上上级、(...) 匹配根目录的路由。

小结
    

  • App Router 基于 RSC，使用文件系统路由，每个路由段可定义独立的 layout、loading、error
    • 

  • Layout 跨路由保持状态，Page 定义页面内容，Loading 和 Error 处理异步状态
    • 

  • Parallel Routes 使用 @slot 在同一布局中并行渲染多个页面
    • 

  • Intercepting Routes 拦截导航在当前布局中以模态框等形式展示
    • 

  • 多层缓存策略（Request Memoization → Data Cache → Full Route Cache → Router Cache）提供高性能的数据获取
    •
