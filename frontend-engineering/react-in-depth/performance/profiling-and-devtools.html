性能分析与 DevTools

React 性能分析工具概览

React 提供了多层次的性能分析工具，从内置的 Profiler API 到浏览器 DevTools 扩展，帮助开发者定位和解决性能瓶颈。



React Profiler API
React 内置的 <Profiler> 组件用于程序化地测量渲染性能：


import { Profiler, ProfilerOnRenderCallback } from 'react';

const onRender: ProfilerOnRenderCallback = (id, phase, actualDuration, baseDuration, startTime, commitTime) => {
  console.table({
    id,
    phase,
    actualDuration: `${actualDuration.toFixed(2)}ms`,
    baseDuration: `${baseDuration.toFixed(2)}ms`,
    startTime: `${startTime.toFixed(2)}ms`,
    commitTime: `${commitTime.toFixed(2)}ms`,
  });
};

function App() {
  return (
    <div>
      <Profiler id="Header" onRender={onRender}>
        <Header />
      </Profiler>
      <Profiler id="MainContent" onRender={onRender}>
        <MainContent />
      </Profiler>
      <Profiler id="Sidebar" onRender={onRender}>
        <Sidebar />
      </Profiler>
    </div>
  );
}




参数
说明





id
Profiler 标识符




phase
"mount" 或 "update"




actualDuration
本次渲染实际耗时（ms）




baseDuration
无 memoization 时的预估耗时




startTime
本次渲染开始的时间戳




commitTime
本次 Commit 的时间戳





生产环境性能收集
const onRender: ProfilerOnRenderCallback = (id, phase, actualDuration) => {
  if (actualDuration > 16) {
    reportPerformanceMetric({
      component: id,
      phase,
      duration: actualDuration,
      timestamp: Date.now(),
    });
  }
};


提示： Profiler 在生产构建中默认禁用。如需在生产环境收集数据，使用 react-dom/profiling 构建包。

Flame Chart
火焰图显示每个组件在每次 Commit 中的渲染耗时。颜色越深表示渲染耗时越长：


Ranked Chart
排名图按渲染耗时从长到短排列组件，快速定位最慢的组件。


高亮重渲染
在 React DevTools 的 Settings 中开启 "Highlight updates when components render"，可以在页面上实时看到哪些组件正在重渲染（以闪烁的边框标示）。






边框颜色
含义





蓝色
低频更新




绿色
中频更新




黄色/红色
高频更新（可能需要优化）







why-did-you-render
@welldone-software/why-did-you-render 是一个第三方库，能够自动检测和报告不必要的重渲染原因：


// wdyr.ts — 在应用入口最前面导入
import React from 'react';

if (process.env.NODE_ENV === 'development') {
  const whyDidYouRender = require('@welldone-software/why-did-you-render');
  whyDidYouRender(React, {
    trackAllPureComponents: true,
    trackHooks: true,
    logOnDifferentValues: true,
  });
}

// 对特定组件开启追踪
function ExpensiveComponent({ data }: { data: DataType }) {
  return <div>{/* ... */}</div>;
}

ExpensiveComponent.whyDidYouRender = true;
输出示例：


ExpensiveComponent re-rendered because:
  Props changes:
    - data: { old value } !== { new value }
      (different objects that are equal by value)

  Suggestion: Use React.memo or useMemo to prevent re-renders




检测类型
说明





相同值的新对象
对象内容一样但引用不同




相同值的新数组
数组内容一样但引用不同




相同值的新函数
每次渲染创建的新函数




Hooks 依赖变化
哪个 Hook 的依赖导致了重渲染

const DataList = memo(function DataList({ items }: { items: Item[] }) {
  return (
    <Virtuoso

      totalCount={items.length}
      itemContent={(index) => <ItemCard item={items[index]} />}

提示： 性能优化要以数据为依据，不要凭猜测。先使用 Profiler 和 DevTools 定位瓶颈，再针对性优化。过早优化是万恶之源。






小结
    

  • React Profiler API 程序化测量渲染性能，支持生产环境监控
    • 

  • React DevTools Profiler 可视化分析火焰图和排名图，高亮重渲染
    • 

  • why-did-you-render 自动检测不必要的重渲染并给出优化建议
    • 

  • Chrome Performance 面板用于分析非 React 特有的性能问题（长任务、布局抖动）
    • 

  • 性能优化遵循测量 → 定位 → 优化 → 验证的循环，以数据驱动决策
