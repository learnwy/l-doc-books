屏幕阅读器适配

核心概念

屏幕阅读器（Screen Reader）是视障用户访问 Web 内容的主要工具。它解析页面的可访问性树（Accessibility Tree），将视觉界面转化为语音输出或盲文显示。开发者需要理解屏幕阅读器的工作方式和用户的操作习惯，才能构建真正可访问的 Web 应用。

可访问名称计算
可访问名称（Accessible Name）是屏幕阅读器朗读元素时使用的文本。名称的计算遵循严格的优先级规则，理解这个优先级对于调试无障碍问题至关重要。


const accessibleNamePriority = `
<!-- 优先级从高到低 -->

<!-- 1. aria-labelledby（最高优先级） -->
<button aria-labelledby="btn-label">
  <span id="btn-label">保存设置</span>
</button>

<!-- 2. aria-label -->
<button aria-label="关闭对话框">
  <svg>...</svg>
</button>

<!-- 3. <label> 关联（仅表单控件） -->
<label for="search">搜索</label>
<input id="search" type="text" />

<!-- 4. 文本内容 -->
<button>提交订单</button>
<a href="/docs">查看文档</a>

<!-- 5. title 属性（最低优先级） -->
<abbr title="Web Content Accessibility Guidelines">WCAG</abbr>

<!-- 6. placeholder（不应作为唯一标签） -->
<input placeholder="请输入用户名" />  <!-- 仅作为提示，不是名称 -->
`;

// 调试：查看元素的可访问名称
const getAccessibleName = (element: HTMLElement): string => {
  return element.getAttribute('aria-labelledby')
    ? (document.getElementById(element.getAttribute('aria-labelledby')!)?.textContent ?? '')
    : (element.getAttribute('aria-label') ?? element.textContent ?? '');
};

动态内容通知
单页应用（SPA）中，内容变化不会被屏幕阅读器自动感知。Live Region 机制让屏幕阅读器在内容动态更新时主动朗读变化。


const liveRegions = `
<!-- aria-live="polite"：等当前朗读完毕后播报 -->
<div aria-live="polite" aria-atomic="true">
  搜索结果：找到 42 条记录
</div>

<!-- aria-live="assertive"：立即中断当前朗读 -->
<div aria-live="assertive" role="alert">
  操作失败：网络连接超时
</div>

<!-- role="status"：等价于 aria-live="polite" -->
<div role="status">正在加载...</div>

<!-- role="alert"：等价于 aria-live="assertive" -->
<div role="alert">您的密码即将过期</div>

<!-- aria-atomic：播报整个区域还是仅变化部分 -->
<div aria-live="polite" aria-atomic="false">
  <span>已选择 3 项</span>  <!-- 只朗读变化的部分 -->
</div>
`

// React 中的 Live Region 实现
const useAnnounce = () => {
  const [message, setMessage] = useState('')

  const announce = (text: string, priority: 'polite' | 'assertive' = 'polite') => {
    setMessage('')
    requestAnimationFrame(() => setMessage(text))
  }

  const AnnouncerRegion = () => (
    <div
      aria-live="polite"
      aria-atomic="true"
      className="sr-only"
    >
      {message}
    </div>
  )

  return { announce, AnnouncerRegion }
}

视觉隐藏文本
某些信息只需要对屏幕阅读器可见，视觉上应隐藏。例如图标按钮的文字标签、表格的额外上下文说明等。


const visuallyHiddenCSS = `
/* sr-only 类：视觉隐藏但屏幕阅读器可读 */
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border-width: 0;
}

/* 使用示例 */
/* <button>
     <svg aria-hidden="true">...</svg>
     <span class="sr-only">删除</span>
   </button> */

/* 注意：以下方式会同时对屏幕阅读器隐藏 */
/* display: none — 完全从 AOM 中移除 */
/* visibility: hidden — 完全从 AOM 中移除 */
/* aria-hidden="true" — 从 AOM 中移除但仍占据空间 */
`;

测试与调试
屏幕阅读器适配必须通过实际屏幕阅读器测试验证。自动化工具只能检测技术合规性，无法评估用户体验。


// 测试流程
const screenReaderTestChecklist = [
  '使用 Tab 键导航所有交互元素',

  '检查所有按钮/链接是否有可访问名称',
  '验证图片 alt 文本是否准确',
  '测试表单填写和错误提示流程',

小结
    

  • 屏幕阅读器通过可访问性树（AOM）理解页面，AOM 的质量决定用户体验
    • 

  • 可访问名称计算有严格优先级：aria-labelledby > aria-label > label > 文本内容 > title
    • 

  • Live Region（aria-live）是 SPA 动态内容通知的标准方案，polite 等待、assertive 立即播报
    • 

  • sr-only 类实现视觉隐藏但屏幕阅读器可读，display:none 和 aria-hidden="true" 会同时隐藏
    • 

  • 自动化工具（axe-core）只能检测技术合规，真正的用户体验需要手动屏幕阅读器测试
    • 

  • 每个 Sprint 至少进行一次手动屏幕阅读器测试，覆盖 Tab 导航、表单、动态内容等核心场景
    •
