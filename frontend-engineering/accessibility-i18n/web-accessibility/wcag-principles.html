WCAG 原则与标准

核心概念

Web 内容无障碍指南（WCAG, Web Content Accessibility Guidelines）是 W3C 制定的国际标准，为 Web 内容的无障碍性提供统一规范。WCAG 基于四大原则：可感知（Perceivable）、可操作（Operable）、可理解（Understandable）和鲁棒性（Robust），简称 POUR。每个原则下包含具体的准则和成功标准，分为 A、AA、AAA 三个合规级别。





合规级别
要求
典型标准
适用场景





A
基础无障碍
所有非文本内容有替代文本
最低合规要求




AA
增强无障碍

AAA
最高无障碍
对比度 ≥ 7:1，无时间限制
特定公共服务





可感知原则
可感知原则要求信息和界面组件必须以用户能够感知的方式呈现。对于视觉内容，需要提供文本替代；对于音频内容，需要提供字幕或文字稿。


// 图片替代文本：信息性图片 vs 装饰性图片
const imageAccessibility = `
<!-- 信息性图片：alt 描述图片内容 -->
<img src="chart.png" alt="2024年Q1销售额环比增长15%的柱状图" />

<!-- 功能性图片：alt 描述操作而非图片本身 -->
<button><img src="search.svg" alt="搜索" /></button>

<!-- 装饰性图片：空 alt + role="presentation" -->
<img src="divider.png" alt="" role="presentation" />

<!-- 复杂图片：使用 aria-describedby 提供详细描述 -->
<figure>
  <img src="architecture.png" alt="系统架构图" aria-describedby="arch-desc" />
  <figcaption id="arch-desc">
    系统由前端层、API 网关、微服务集群和数据库层四部分组成...
  </figcaption>
</figure>
`;

// 颜色对比度检查
const contrastCheck = (foreground: string, background: string): ContrastResult => {
  const fgLum = getRelativeLuminance(foreground);
  const bgLum = getRelativeLuminance(background);
  const ratio = (Math.max(fgLum, bgLum) + 0.05) / (Math.min(fgLum, bgLum) + 0.05);

  return {
    ratio: Math.round(ratio * 100) / 100,
    passAA_normal: ratio >= 4.5,
    passAA_large: ratio >= 3,
    passAAA_normal: ratio >= 7,
    passAAA_large: ratio >= 4.5,
  };
};

可操作原则
可操作原则要求所有用户界面组件和导航都可以通过多种输入方式操作，不局限于鼠标。


// 焦点管理和操作超时
const operablePatterns = `
<!-- 所有交互元素必须可聚焦 -->
<button>提交</button>  <!-- 原生可聚焦 -->
<div role="button" tabindex="0">自定义按钮</div>  <!-- 需要手动添加 -->

<!-- 充足的操作时间 -->
<div role="alert" aria-live="assertive">
  您的会话将在 5 分钟后过期。
  <button>延长会话</button>
</div>

<!-- 跳过导航链接 -->
<a href="#main-content" class="skip-link">跳转到主要内容</a>
<nav>...</nav>
<main id="main-content">...</main>
`;

// 跳过链接的 CSS 实现
const skipLinkCSS = `
.skip-link {
  position: absolute;
  left: -9999px;
  z-index: 999;
  padding: 1em;
  background: var(--color-bg-primary);
  color: var(--color-text-primary);
}

.skip-link:focus {
  left: 50%;
  transform: translateX(-50%);
  top: 0;
}
`;
运动和动画需要特别注意。闪烁频率在 3-50Hz 范围内可能引发癫痫发作（光敏性癫痫），WCAG 严格禁止此类内容。此外，prefers-reduced-motion 媒体查询允许用户选择减少动画。


可理解原则
可理解原则关注内容的可读性、界面的可预测性和错误处理的友好性。


// 表单可理解性最佳实践
const understandableForm = `
<form>
  <!-- 清晰的标签 + 说明 -->
  <div>
    <label for="password">密码</label>
    <input 
      id="password" 
      type="password" 
      aria-describedby="password-hint"
      required
    />
    <p id="password-hint">密码需包含至少 8 个字符，包括大写字母和数字</p>
  </div>

  <!-- 错误提示：明确说明问题和解决方案 -->
  <div>
    <label for="email">邮箱地址</label>
    <input 
      id="email" 
      type="email" 
      aria-invalid="true"
      aria-describedby="email-error"
    />
    <p id="email-error" role="alert">
      请输入有效的邮箱地址，例如 user@example.com
    </p>
  </div>
</form>
`;

鲁棒性与合规检测
鲁棒性原则确保内容能被各种用户代理（包括辅助技术）可靠地解析和理解。


// HTML 验证：确保标记规范
const robustnessChecks = `
<!-- 唯一 ID：同一页面不能有重复 ID -->
<!-- 正确的嵌套：标签必须正确闭合和嵌套 -->
<!-- 角色与状态：自定义组件必须声明正确的 ARIA 角色和状态 -->

<!-- 合规的自定义组件 -->
<div 
  role="combobox" 
  aria-expanded="false"
  aria-haspopup="listbox"
  aria-owns="option-list"
>
  <input aria-autocomplete="list" aria-controls="option-list" />
  <ul id="option-list" role="listbox" hidden>
    <li role="option" aria-selected="false">选项 1</li>
    <li role="option" aria-selected="true">选项 2</li>
  </ul>
</div>
`;

WCAG 合规不是一次性工作，而是需要贯穿整个开发生命周期的持续实践。从设计阶段就考虑无障碍性（inclusive design），在开发中使用 linting 工具实时检查，在测试中包含无障碍自动化和手动测试，在部署后持续监控。


小结
    

  • WCAG 基于 POUR 四大原则，每个原则下有具体准则和 A/AA/AAA 三级成功标准
    • 

  • 可感知：所有非文本内容需要替代文本，颜色不能作为唯一信息载体，对比度需满足 4.5:1（AA）
    • 

  • 可操作：所有功能可键盘访问，提供跳过导航链接，避免引发光敏性癫痫的闪烁内容
    • 

  • 可理解：声明页面语言，保持导航一致性，提供清晰的错误识别和修正建议
    • 

  • 鲁棒性：HTML 标记规范，自定义组件正确使用 ARIA 角色和状态
    • 

  • 大多数法规要求达到 AA 级合规，合规检测应贯穿设计→开发→测试→监控全流程
    •
