无障碍自动化工程

核心概念

无障碍自动化工程将无障碍检查嵌入到开发工作流的每个环节——从 IDE 中的实时 linting 到 CI/CD 流水线中的门禁检查。目标是尽早发现问题、自动阻止回归，将无障碍从"发布前检查"转变为"持续保障"。

ESLint 静态分析
eslint-plugin-jsx-a11y 在编码阶段实时检查 JSX 中的无障碍问题，是成本最低的防线。


// .eslintrc.js 配置

组件级测试
jest-axe 在单元测试中对渲染后的 DOM 运行 axe-core 检查，捕获静态分析无法发现的动态渲染问题。


import { render } from '@testing-library/react'
import { axe, toHaveNoViolations } from 'jest-axe'

expect.extend(toHaveNoViolations)

test('ProductCard 无障碍检查', async () => {
  const { container } = render(
    <ProductCard
      title="MacBook Pro"
      price={12999}
      imageUrl="/macbook.jpg"
    />
  )
  const results = await axe(container)
  expect(results).toHaveNoViolations()
})

test('SearchForm 无障碍检查', async () => {
  const { container } = render(<SearchForm onSearch={() => {}} />)
  const results = await axe(container, {
    rules: {
      'color-contrast': { enabled: false },
    },
  })
  expect(results).toHaveNoViolations()
})

test('Modal 打开状态无障碍检查', async () => {
  const { container } = render(
    <Modal isOpen={true} title="确认">
      <p>确定要继续吗？</p>
      <button>确认</button>
      <button>取消</button>
    </Modal>
  )
  const results = await axe(container)
  expect(results).toHaveNoViolations()
})
CI/CD 集成
将无障碍检查集成到 CI 流水线中，作为 PR 合并的必需条件。


// Playwright 配置：无障碍 E2E 测试
import { test, expect } from '@playwright/test';
import { AxeBuilder } from '@axe-core/playwright';

const pages = [
  { name: '首页', url: '/' },
  { name: '产品列表', url: '/products' },
  { name: '购物车', url: '/cart' },
  { name: '登录', url: '/login' },
];

for (const page of pages) {
  test(`${page.name} 无障碍检查`, async ({ browser }) => {
    const context = await browser.newContext();
    const p = await context.newPage();
    await p.goto(page.url);
    await p.waitForLoadState('networkidle');

    const results = await new AxeBuilder({ page: p })
      .withTags(['wcag2a', 'wcag2aa', 'wcag21aa'])
      .exclude('[data-a11y-ignore]')
      .analyze();

    const blockers = results.violations.filter((v) => v.impact === 'critical' || v.impact === 'serious');

    if (blockers.length > 0) {
      const report = blockers
        .map((v) => `[${v.impact}] ${v.id}: ${v.description}\n  ${v.nodes.map((n) => n.html).join('\n  ')}`)
        .join('\n\n');
      expect(blockers, `无障碍问题:\n${report}`).toEqual([]);
    }
  });
}
监控与报告
生产环境的无障碍状态需要持续监控。定期扫描关键页面，生成趋势报告，及时发现回归。


interface A11yReport {
  timestamp: string;
  pages: PageReport[];
  summary: {
    total_violations: number;
    critical: number;
    serious: number;
    trend: 'improving' | 'stable' | 'degrading';
  };
}

interface PageReport {
  url: string;
  violations: number;
  passes: number;
  score: number;
}

const weeklyA11yScan = async (urls: string[]): Promise<A11yReport> => {
  const pages: PageReport[] = [];

  for (const url of urls) {
    const results = await scanPage(url);
    pages.push({
      url,
      violations: results.violations.length,
      passes: results.passes.length,
      score: results.passes.length / (results.passes.length + results.violations.length),
    });
  }

  const totalViolations = pages.reduce((sum, p) => sum + p.violations, 0);
  const previousTotal = await loadPreviousReport();

  return {
    timestamp: new Date().toISOString(),
    pages,
    summary: {
      total_violations: totalViolations,
      critical: pages.reduce((sum, p) => sum + p.violations, 0),
      serious: 0,
      trend:
        totalViolations < previousTotal.total_violations
          ? 'improving'
          : totalViolations === previousTotal.total_violations
            ? 'stable'
            : 'degrading',
    },
  };
};

小结
    

  • 无障碍自动化工程覆盖编码→提交→CI→部署→监控全流程
    • 

  • ESLint jsx-a11y 在编码阶段实时检查，是成本最低的防线
    • 

  • jest-axe 在单元测试中对渲染后 DOM 运行检查，捕获动态渲染问题
    • 

  • CI 集成 axe-core + Playwright 作为 PR 合并门禁，critical/serious 阻止合并
    • 

  • 生产环境定期扫描关键页面，生成趋势报告，监控无障碍评分变化
    • 

  • 自动化覆盖约 35% 的问题，手动测试和用户测试仍然不可或缺
