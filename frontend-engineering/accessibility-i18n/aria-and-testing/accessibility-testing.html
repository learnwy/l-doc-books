无障碍测试

核心概念

无障碍测试验证 Web 应用是否满足 WCAG 标准和用户的实际可访问需求。测试分为自动化测试和手动测试两类——自动化工具可以检测约 30-40% 的 WCAG 问题（如缺少 alt 文本、对比度不足），但需要人工测试才能评估语义正确性和用户体验。完善的无障碍测试策略需要两者结合。

自动化检测工具
axe-core 是最广泛使用的无障碍检测引擎，支持在单元测试、E2E 测试和 CI 流程中运行。


// Playwright + axe-core E2E 测试
import { test, expect } from '@playwright/test'
import { AxeBuilder } from '@axe-core/playwright'

test('首页应通过无障碍检查', async ({ page }) => {
  await page.goto('/')

  const results = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa'])
    .exclude('.third-party-widget')
    .analyze()

  expect(results.violations).toEqual([])
})

test('表单页应通过无障碍检查', async ({ page }) => {
  await page.goto('/checkout')

  await page.fill('#email', 'invalid')
  await page.click('button[type="submit"]')

  const results = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa'])
    .analyze()

  const critical = results.violations.filter(
    v => v.impact === 'critical' || v.impact === 'serious'
  )
  expect(critical).toEqual([])
})

// React Testing Library 无障碍断言
import { render, screen } from '@testing-library/react'

test('按钮应有可访问名称', () => {
  render(<IconButton icon="delete" />)
  expect(screen.getByRole('button', { name: '删除' })).toBeInTheDocument()
})

test('表单输入应关联标签', () => {
  render(<LoginForm />)
  expect(screen.getByLabelText('用户名')).toBeInTheDocument()
  expect(screen.getByLabelText('密码')).toBeInTheDocument()
})

测试报告与修复优先级
无障碍问题的修复应按影响程度排列优先级。critical 和 serious 级别的问题应在当前 Sprint 修复。


interface A11yIssue {
  rule: string;
  impact: 'critical' | 'serious' | 'moderate' | 'minor';
  description: string;
  element: string;
  fix: string;
}

const priorityMatrix: Record<string, string> = {
  critical: '当前 Sprint 必须修复',
  serious: '当前 Sprint 优先修复',
  moderate: '下个 Sprint 修复',
  minor: '排入 backlog',
};

将无障碍测试集成到 CI/CD 流程中可以防止回归。设置 axe-core 检查为 PR 合并的必需条件，critical/serious 级别问题阻止合并。


小结
    

  • 自动化工具可以检测约 30-40% 的 WCAG 问题，剩余需要手动测试
    • 

  • axe-core 是业界标准引擎，可集成到单元测试、E2E 测试和 CI 流程
    • 

  • Testing Library 的 getByRole、getByLabelText 等查询方式天然支持无障碍最佳实践
    • 

  • 每个 Sprint 至少执行一次键盘导航 + 屏幕阅读器手动测试
    • 

  • 无障碍问题按 critical → serious → moderate → minor 排列修复优先级
    • 

  • CI 集成 axe-core 检查，critical/serious 级别阻止 PR 合并
