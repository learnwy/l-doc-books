ARIA 基础

核心概念

ARIA（Accessible Rich Internet Applications）是 W3C 制定的一组 HTML 属性规范，用于增强 Web 内容和应用的无障碍性。当原生 HTML 元素的语义不足以描述复杂组件时，ARIA 提供了角色（Roles）、属性（Properties）和状态（States）来补充语义信息。但 ARIA 的第一原则是：如果原生 HTML 元素能满足需求，就不要使用 ARIA。





ARIA 原则
说明
示例





第一原则
优先使用原生 HTML
用 <button> 而非 <div role="button">




第二原则
不改变原生语义
不在 <h2> 上加 role="tab"




第三原则
所有交互 ARIA 组件可键盘操作
role="button" 必须响应 Enter/Space




第四原则
不在可聚焦元素上用 aria-hidden="true"
会导致焦点不可见




第五原则
所有交互元素必须有可访问名称
按钮必须有文本或 aria-label





常用 ARIA 角色
ARIA 角色分为六大类，每类覆盖不同的无障碍场景。最常用的是组件角色和地标角色。


const ariaRoleExamples = `
<!-- Tab 面板组件 -->
<div role="tablist" aria-label="产品信息">
  <button role="tab" aria-selected="true" aria-controls="panel-1" id="tab-1">
    描述
  </button>
  <button role="tab" aria-selected="false" aria-controls="panel-2" id="tab-2" tabindex="-1">
    规格
  </button>
  <button role="tab" aria-selected="false" aria-controls="panel-3" id="tab-3" tabindex="-1">
    评价
  </button>
</div>

<div role="tabpanel" id="panel-1" aria-labelledby="tab-1">
  产品描述内容...
</div>
<div role="tabpanel" id="panel-2" aria-labelledby="tab-2" hidden>
  规格参数内容...
</div>

<!-- 对话框 -->
<div role="dialog" aria-labelledby="dialog-title" aria-modal="true">
  <h2 id="dialog-title">确认删除</h2>
  <p>确定要删除此项目吗？此操作不可撤销。</p>
  <button>确认</button>
  <button>取消</button>
</div>

<!-- 工具提示 -->
<button aria-describedby="tooltip-1">
  设置
</button>
<div role="tooltip" id="tooltip-1">
  打开应用程序设置面板
</div>

<!-- 进度条 -->
<div role="progressbar" aria-valuenow="65" aria-valuemin="0" aria-valuemax="100"
     aria-label="文件上传进度">
  65%
</div>
`;

ARIA 属性与状态
属性（Properties）描述元素的固有特征，状态（States）描述元素的当前情况。状态值会随用户交互动态变化。


const ariaStates = `
<!-- 展开/折叠状态 -->
<button aria-expanded="false" aria-controls="menu-content">
  菜单
</button>
<div id="menu-content" hidden>
  <ul role="menu">
    <li role="menuitem">选项 1</li>
    <li role="menuitem">选项 2</li>
  </ul>
</div>

<!-- 加载状态 -->
<div aria-busy="true" aria-live="polite">
  正在加载数据...
</div>

<!-- 当前选中状态 -->
<nav>
  <a href="/home" aria-current="page">首页</a>
  <a href="/about">关于</a>
</nav>

<!-- 排序状态 -->
<table>
  <thead>
    <tr>
      <th aria-sort="ascending">名称</th>
      <th aria-sort="none">日期</th>
    </tr>
  </thead>
</table>
`;

// 动态更新 ARIA 状态
const toggleAccordion = (button: HTMLButtonElement, panel: HTMLElement) => {
  const isExpanded = button.getAttribute('aria-expanded') === 'true';
  button.setAttribute('aria-expanded', String(!isExpanded));
  panel.hidden = isExpanded;
};

关系属性
ARIA 关系属性建立元素之间的语义关联，帮助辅助技术理解复杂组件的结构。


const ariaRelationships = `
<!-- aria-labelledby：引用其他元素作为标签 -->
<h2 id="section-title">用户列表</h2>
<table aria-labelledby="section-title">...</table>

<!-- aria-describedby：引用其他元素作为描述 -->
<input aria-describedby="hint error" />
<p id="hint">密码至少 8 个字符</p>
<p id="error" role="alert">密码不符合要求</p>

<!-- aria-controls：当前元素控制另一个元素 -->
<button aria-controls="search-results">搜索</button>
<div id="search-results">...</div>

<!-- aria-owns：建立父子关系（当 DOM 结构不匹配逻辑结构时） -->
<div role="listbox" aria-owns="option-1 option-2 option-3">
  <!-- options 可能在 DOM 中位于其他位置 -->
</div>

<!-- aria-activedescendant：声明当前活跃的子元素 -->
<div role="listbox" tabindex="0" aria-activedescendant="item-2">
  <div role="option" id="item-1">选项一</div>
  <div role="option" id="item-2" aria-selected="true">选项二</div>
  <div role="option" id="item-3">选项三</div>
</div>
`;
aria-activedescendant 是复合组件焦点管理的替代方案（相对于 roving tabindex）。容器元素持有焦点，通过 aria-activedescendant 指向当前活跃的子元素。


常见 ARIA 错误
ARIA 使用不当比不使用更糟糕。错误的 ARIA 会向辅助技术传达误导性的语义信息。


const ariaAntiPatterns = `
<!-- 错误 1：冗余 ARIA -->
<button role="button">提交</button>  <!-- button 已有隐含角色 -->
<a href="/about" role="link">关于</a>  <!-- a[href] 已有隐含角色 -->

<!-- 错误 2：aria-hidden 在可聚焦元素上 -->
<button aria-hidden="true">隐藏按钮</button>  <!-- 焦点可达但不可见 -->

<!-- 错误 3：角色与行为不匹配 -->
<span role="button">点击</span>  <!-- 缺少 tabindex 和键盘事件 -->

<!-- 错误 4：aria-label 覆盖有意义的文本 -->
<a href="/about" aria-label="link">关于我们</a>  <!-- 比可见文本信息更少 -->

<!-- 错误 5：在非交互元素上使用交互角色 -->
<div role="button" onclick="submit()">提交</div>
<!-- 缺少：tabindex="0"、Enter/Space 事件处理 -->
`;




错误类型
影响
正确做法





冗余 ARIA
无害但增加维护成本
移除不必要的 ARIA




aria-hidden + 可聚焦
焦点到达不可见元素
同时设置 tabindex="-1"




角色无键盘支持
键盘用户无法操作
实现完整的键盘交互




aria-label 信息不足
屏幕阅读器获得更少信息
aria-label 应比可见文本更详细





小结
    

  • ARIA 第一原则：优先使用原生 HTML，只在原生语义不足时使用 ARIA
    • 

  • 角色（Roles）定义元素类型，属性（Properties）描述特征，状态（States）反映当前情况
    • 

  • Tab/Dialog/Menu 等复合组件需要正确的角色、状态和完整的键盘交互支持
    • 

  • 关系属性（labelledby、describedby、controls、owns）建立元素间的语义关联
    • 

  • ARIA 使用不当比不使用更糟糕，常见错误包括冗余 ARIA、角色无键盘支持等
    • 

  • 每个 ARIA 角色都有对应的 WAI-ARIA Authoring Practices 指南，实现前应查阅
    •
