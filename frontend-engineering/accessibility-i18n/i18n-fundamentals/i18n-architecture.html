i18n 架构设计

核心概念

国际化（i18n, Internationalization）架构是让 Web 应用支持多语言、多地区的系统性工程。i18n 不仅仅是翻译文本——它涉及文本管理、日期/数字格式化、布局适配（RTL）、图片和媒体本地化等多个维度。良好的 i18n 架构应该让开发者在编写功能时无需关心具体语言，而是通过抽象层自动处理本地化需求。

翻译资源管理
翻译资源通常以 JSON 格式组织，按语言和命名空间分文件。命名空间隔离不同功能模块的翻译，支持按需加载。


// 翻译资源结构
// locales/
// ├── zh-CN/
// │   ├── common.json
// │   ├── auth.json
// │   └── product.json
// ├── en-US/
// │   ├── common.json
// │   ├── auth.json
// │   └── product.json
// └── ja-JP/
//     └── ...

// common.json 示例
const zhCNCommon = {
  app: {
    title: '文档中心',
    loading: '加载中...',
    error: '发生错误，请稍后重试',
  },
  nav: {
    home: '首页',
    docs: '文档',
    settings: '设置',
  },
  actions: {
    save: '保存',
    cancel: '取消',
    delete: '删除',
    confirm: '确认',
  },
};

// i18n 初始化配置
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';

const i18nConfig = {
  fallbackLng: 'en-US',
  supportedLngs: ['zh-CN', 'en-US', 'ja-JP'],
  ns: ['common', 'auth', 'product'],
  defaultNS: 'common',
  interpolation: {
    escapeValue: false,
  },
  backend: {
    loadPath: '/locales/{{lng}}/{{ns}}.json',
  },
};
翻译键的命名规范直接影响维护效率。推荐使用嵌套结构 + 功能语义命名（如 auth.login.title），而非平铺的描述性键名（如 login_page_title_text）。

语言检测与切换
语言检测需要综合多个信号源，按优先级确定用户的首选语言。


const detectLanguage = (): string => {
  const supported = ['zh-CN', 'en-US', 'ja-JP'];

  const urlLang = new URLSearchParams(window.location.search).get('lang');
  if (urlLang && supported.includes(urlLang)) return urlLang;

  const storedLang = localStorage.getItem('preferred-language');
  if (storedLang && supported.includes(storedLang)) return storedLang;

  const browserLangs = navigator.languages || [navigator.language];
  for (const lang of browserLangs) {
    const match = supported.find((s) => s === lang || s.startsWith(lang.split('-')[0]));
    if (match) return match;
  }

  return 'en-US';
};

const switchLanguage = async (lang: string) => {
  await i18n.changeLanguage(lang);
  localStorage.setItem('preferred-language', lang);
  document.documentElement.setAttribute('lang', lang);

  if (isRTL(lang)) {
    document.documentElement.setAttribute('dir', 'rtl');
  } else {
    document.documentElement.setAttribute('dir', 'ltr');
  }
};
按需加载策略
大型应用的翻译资源可能达到数百 KB。按需加载确保用户只下载当前语言和当前页面所需的翻译。


const lazyLoadNamespace = async (ns: string, lng: string): Promise<void> => {
  if (i18n.hasResourceBundle(lng, ns)) return

  const resources = await import(`/locales/${lng}/${ns}.json`)
  i18n.addResourceBundle(lng, ns, resources.default)
}

// React 组件中按需加载
const ProductPage: FC = () => {
  const { t, ready } = useTranslation('product', { useSuspense: true })

  if (!ready) return <LoadingSkeleton />

  return (
    <div>
      <h1>{t('title')}</h1>
      <p>{t('description')}</p>
    </div>
  )
}

// 路由级别的翻译预加载
const routes = [
  {
    path: '/products',
    loader: async () => {
      await lazyLoadNamespace('product', i18n.language)
      return null
    },
    component: ProductPage,
  },
]
小结
    

  • i18n 架构涵盖文本管理、格式化、布局适配和资源加载四个维度
    • 

  • 翻译资源按语言和命名空间组织，支持按需加载和缓存
    • 

  • 翻译键使用嵌套语义命名（如 auth.login.title），保持结构清晰
    • 

  • 语言检测综合 URL 参数、用户偏好和浏览器设置，按优先级匹配
    • 

  • 按需加载确保只下载当前语言和页面所需的翻译，减少首屏负载
    • 

  • 语言切换时需同步更新 html lang 属性和 dir 属性（RTL 支持）
