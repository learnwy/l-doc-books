React i18n 实践

核心概念

React 应用的国际化实践需要选择合适的 i18n 库、设计翻译工作流、处理组件级别的本地化问题。react-intl（FormatJS）和 react-i18next 是 React 生态中最成熟的两个 i18n 解决方案，各有优势。选择的关键不在于库本身，而在于是否与团队的翻译工作流和项目规模匹配。

react-intl 实践
react-intl 基于 ICU MessageFormat，通过 IntlProvider 提供上下文，组件使用 FormattedMessage 或 useIntl hook 进行翻译。


import { IntlProvider, FormattedMessage, useIntl } from 'react-intl'

const messages = {
  'zh-CN': {
    'app.greeting': '你好，{name}！',
    'app.items': '{count, plural, =0 {没有项目} other {共 {count} 个项目}}',
    'app.lastLogin': '上次登录：{date, date, medium}',
  },
  'en-US': {
    'app.greeting': 'Hello, {name}!',
    'app.items': '{count, plural, =0 {No items} one {1 item} other {{count} items}}',
    'app.lastLogin': 'Last login: {date, date, medium}',
  },
}

const App: FC = () => {
  const [locale, setLocale] = useState('zh-CN')

  return (
    <IntlProvider locale={locale} messages={messages[locale]}>
      <Dashboard />
      <LocaleSwitch onSwitch={setLocale} />
    </IntlProvider>
  )
}

const Dashboard: FC = () => {
  const intl = useIntl()

  const pageTitle = intl.formatMessage(
    { id: 'app.greeting' },
    { name: '张三' }
  )

  return (
    <div>
      <h1>{pageTitle}</h1>
      <p>
        <FormattedMessage
          id="app.items"
          values={{ count: 42 }}
        />
      </p>
      <p>
        <FormattedMessage
          id="app.lastLogin"
          values={{ date: new Date() }}
        />
      </p>
    </div>
  )
}
react-i18next 实践
react-i18next 基于 i18next 核心，支持命名空间、懒加载和丰富的插件生态。


import i18n from 'i18next'
import { initReactI18next, useTranslation, Trans } from 'react-i18next'
import Backend from 'i18next-http-backend'
import LanguageDetector from 'i18next-browser-languagedetector'

i18n
  .use(Backend)
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    fallbackLng: 'en-US',
    ns: ['common', 'product'],
    defaultNS: 'common',
    backend: {
      loadPath: '/locales/{{lng}}/{{ns}}.json',
    },
    interpolation: {
      escapeValue: false,
    },
  })

const ProductPage: FC = () => {
  const { t } = useTranslation('product')

  return (
    <div>
      <h1>{t('title')}</h1>
      <p>{t('itemCount', { count: 42 })}</p>
      <p>
        <Trans i18nKey="richText" t={t}>
          请阅读我们的<a href="/terms">服务条款</a>
        </Trans>
      </p>
    </div>
  )
}

// 命名空间预加载
const CheckoutPage: FC = () => {
  const { t, ready } = useTranslation(['checkout', 'common'])

  if (!ready) return <Skeleton />

  return (
    <div>
      <h1>{t('checkout:title')}</h1>
      <button>{t('common:actions.confirm')}</button>
    </div>
  )
}
翻译工作流自动化
翻译工作流的自动化是 i18n 规模化的关键。包括翻译键提取、翻译状态追踪和持续集成。


// 消息提取配置（FormatJS CLI）
// package.json
// "scripts": {
//   "i18n:extract": "formatjs extract 'src/**/*.tsx' --out-file lang/en.json --id-interpolation-pattern '[sha512:contenthash:base64:6]'",
//   "i18n:compile": "formatjs compile lang/zh-CN.json --ast --out-file compiled/zh-CN.json"
// }

// 翻译完整性检查
interface TranslationAudit {
  locale: string;
  total_keys: number;
  translated: number;
  missing: string[];
  unused: string[];
  coverage: number;
}

const auditTranslations = (
  sourceMessages: Record<string, string>,
  targetMessages: Record<string, string>,
  locale: string,
): TranslationAudit => {
  const sourceKeys = Object.keys(sourceMessages);
  const targetKeys = new Set(Object.keys(targetMessages));

  const missing = sourceKeys.filter((k) => !targetKeys.has(k));
  const unused = [...targetKeys].filter((k) => !sourceKeys.includes(k));

  return {
    locale,
    total_keys: sourceKeys.length,
    translated: sourceKeys.length - missing.length,
    missing,
    unused,
    coverage: (sourceKeys.length - missing.length) / sourceKeys.length,
  };
};

组件本地化模式
不同类型的组件需要不同的本地化策略。


// 1. 使用 Intl API 的格式化 Hook
const useFormatters = () => {
  const { locale } = useIntl()

  return {
    formatDate: (date: Date) =>
      new Intl.DateTimeFormat(locale, { dateStyle: 'medium' }).format(date),

    formatCurrency: (amount: number, currency: string) =>
      new Intl.NumberFormat(locale, { style: 'currency', currency }).format(amount),

    formatRelative: (date: Date) => {
      const diff = (date.getTime() - Date.now()) / 1000
      const rtf = new Intl.RelativeTimeFormat(locale, { numeric: 'auto' })
      if (Math.abs(diff) < 60) return rtf.format(Math.round(diff), 'second')
      if (Math.abs(diff) < 3600) return rtf.format(Math.round(diff / 60), 'minute')
      if (Math.abs(diff) < 86400) return rtf.format(Math.round(diff / 3600), 'hour')
      return rtf.format(Math.round(diff / 86400), 'day')
    },
  }
}

// 2. 富文本翻译（包含 JSX 元素）
const RichTextExample: FC = () => {
  const { t } = useTranslation()

  return (
    <Trans
      i18nKey="termsNotice"
      components={{
        bold: <strong />,
        link: <a href="/terms" />,
      }}
    />
  )
}
// termsNotice: "点击确认即表示同意<link>服务条款</link>和<bold>隐私政策</bold>"
小结
    

  • react-intl 和 react-i18next 各有优势，选择取决于团队熟悉度和项目需求
    • 

  • react-intl 的 ICU MessageFormat 更强大，react-i18next 的命名空间和插件生态更灵活
    • 

  • 翻译工作流自动化（键提取→翻译管理→完整性检查）是 i18n 规模化的关键
    • 

  • 组件本地化使用格式化 Hook 封装 Intl API，Trans 组件处理包含 JSX 的富文本翻译
    • 

  • 命名空间支持按需加载，避免首屏加载全部翻译资源
    • 

  • PR 门禁应包含翻译完整性检查，防止遗漏翻译导致上线问题
    •
