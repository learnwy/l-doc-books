文本与消息格式化

核心概念

文本格式化是 i18n 中最复杂的领域之一。不同语言的语法规则差异巨大——复数形式（英语 2 种，阿拉伯语 6 种）、性别一致性、词序变化、数字嵌入方式等都需要格式化系统处理。ICU MessageFormat 是业界标准的消息格式化语法，被 react-intl 和 i18next 等主流库采用。

复数处理
复数是 i18n 中最容易出错的领域。不同语言的复数规则差异极大，Unicode CLDR 定义了六种复数类别：zero、one、two、few、many、other。


// ICU MessageFormat 复数语法
const messages = {
  'zh-CN': {
    items: '{count, plural, =0 {没有项目} other {共 {count} 个项目}}',
    unread: '{count, plural, =0 {没有未读消息} other {{count} 条未读消息}}',
  },
  'en-US': {
    items: '{count, plural, =0 {No items} one {1 item} other {{count} items}}',
    unread: '{count, plural, =0 {No unread messages} one {1 unread message} other {{count} unread messages}}',
  },
  'ar-SA': {
    items: '{count, plural, =0 {لا عناصر} one {عنصر واحد} two {عنصران} few {{count} عناصر} many {{count} عنصرًا} other {{count} عنصر}}',
  },
}

// react-intl 使用复数
import { FormattedMessage } from 'react-intl'

const ItemCount: FC<{ count: number }> = ({ count }) => (
  <FormattedMessage
    id="items"
    defaultMessage="{count, plural, =0 {No items} one {1 item} other {{count} items}}"
    values={{ count }}
  />
)

// i18next 复数处理
// en-US.json
// "item": "{{count}} item"
// "item_plural": "{{count}} items"
// "item_zero": "No items"

数字与货币格式化
数字和货币的格式在不同地区差异显著——千分位分隔符、小数点符号、货币符号位置等都需要本地化。浏览器内置的 Intl API 是处理这些格式化的标准方案。


// Intl.NumberFormat — 数字格式化
const formatNumber = (value: number, locale: string) => {
  return new Intl.NumberFormat(locale).format(value);
};

formatNumber(1234567.89, 'en-US'); // "1,234,567.89"
formatNumber(1234567.89, 'de-DE'); // "1.234.567,89"
formatNumber(1234567.89, 'zh-CN'); // "1,234,567.89"
formatNumber(1234567.89, 'ar-SA'); // "١٬٢٣٤٬٥٦٧٫٨٩"

// 货币格式化
const formatCurrency = (amount: number, currency: string, locale: string) => {
  return new Intl.NumberFormat(locale, {
    style: 'currency',
    currency,
    minimumFractionDigits: 2,
    maximumFractionDigits: 2,
  }).format(amount);
};

formatCurrency(1299.5, 'USD', 'en-US'); // "$1,299.50"
formatCurrency(1299.5, 'EUR', 'de-DE'); // "1.299,50 €"
formatCurrency(1299.5, 'CNY', 'zh-CN'); // "¥1,299.50"
formatCurrency(1299.5, 'JPY', 'ja-JP'); // "￥1,300"

// 紧凑格式（大数字简写）
const formatCompact = (value: number, locale: string) => {
  return new Intl.NumberFormat(locale, {
    notation: 'compact',
    compactDisplay: 'short',
  }).format(value);
};

formatCompact(1500000, 'en-US'); // "1.5M"
formatCompact(1500000, 'zh-CN'); // "150万"
formatCompact(1500000, 'ja-JP'); // "150万"

日期与时间格式化
日期格式化的复杂性在于日期顺序（月/日/年 vs 日/月/年 vs 年/月/日）、历法系统（公历 vs 伊斯兰历 vs 日本纪年）和时区处理。


// Intl.DateTimeFormat — 日期格式化
const formatDate = (date: Date, locale: string, options?: Intl.DateTimeFormatOptions) => {
  return new Intl.DateTimeFormat(locale, options).format(date);
};

const now = new Date('2024-03-15T14:30:00Z');

formatDate(now, 'en-US'); // "3/15/2024"
formatDate(now, 'de-DE'); // "15.3.2024"
formatDate(now, 'zh-CN'); // "2024/3/15"
formatDate(now, 'ja-JP'); // "2024/3/15"

// 完整日期时间格式
formatDate(now, 'en-US', {
  dateStyle: 'full',
  timeStyle: 'short',
}); // "Friday, March 15, 2024 at 2:30 PM"

formatDate(now, 'zh-CN', {
  dateStyle: 'full',
  timeStyle: 'short',
}); // "2024年3月15日星期五 14:30"

// 相对时间格式化
const formatRelativeTime = (value: number, unit: Intl.RelativeTimeFormatUnit, locale: string) => {
  return new Intl.RelativeTimeFormat(locale, { numeric: 'auto' }).format(value, unit);
};

formatRelativeTime(-1, 'day', 'zh-CN'); // "昨天"
formatRelativeTime(-1, 'day', 'en-US'); // "yesterday"
formatRelativeTime(3, 'hour', 'zh-CN'); // "3小时后"
文本方向性处理
在混合文本方向（LTR 文本中嵌入 RTL 内容或反之）时，Unicode 双向算法（Bidi Algorithm）可能产生不正确的显示顺序。需要使用方向隔离标记来解决。


const bidiHandling = `
<!-- Unicode 方向隔离 -->
<p>用户 <bdi>محمد</bdi> 发布了新评论</p>

<!-- CSS 逻辑属性（替代物理属性） -->
<style>
  /* 物理属性 — 不适应 RTL */
  .old { margin-left: 16px; padding-right: 8px; text-align: left; }
  
  /* 逻辑属性 — 自动适应文本方向 */
  .new { margin-inline-start: 16px; padding-inline-end: 8px; text-align: start; }
</style>
`;

// 文本方向检测
const isRTL = (locale: string): boolean => {
  const rtlLocales = ['ar', 'he', 'fa', 'ur'];
  return rtlLocales.some((rtl) => locale.startsWith(rtl));
};
小结
    

  • ICU MessageFormat 是消息格式化的业界标准，支持复数、选择和嵌套格式化
    • 

  • 复数处理需要覆盖目标语言的所有复数类别，阿拉伯语有 6 种复数形式
    • 

  • 数字和货币使用 Intl.NumberFormat，自动处理千分位、小数点和货币符号的地区差异
    • 

  • 日期使用 Intl.DateTimeFormat，支持不同历法和日期顺序
    • 

  • Intl.RelativeTimeFormat 处理相对时间显示（"昨天"、"3小时后"等）
    • 

  • 混合文本方向使用 <bdi> 元素和 CSS 逻辑属性确保正确的显示顺序
    •
