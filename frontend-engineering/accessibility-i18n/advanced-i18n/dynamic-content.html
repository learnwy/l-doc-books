动态内容本地化

核心概念

动态内容本地化处理的是运行时生成的、无法预先翻译的内容——用户生成内容（UGC）、API 响应、实时数据和动态拼接的文本。这些场景对 i18n 系统提出了更高的要求：翻译不能在构建时完成，而是需要在运行时根据数据和语言规则动态生成。

参数化消息与插值
永远不要通过字符串拼接来构造本地化文本。不同语言的词序不同，拼接会导致语法错误的句子。


// 反模式：字符串拼接
const badMessage = t('user') + name + t('posted') + count + t('comments')
// 英语: "User Alice posted 3 comments" ✓
// 日语: "ユーザーAlice投稿した3コメント" ✗（语序错误）

// 正确：参数化消息模板
// zh-CN: "{user} 发布了 {count} 条评论"
// en-US: "{user} posted {count} {count, plural, one {comment} other {comments}}"
// ja-JP: "{user} が {count} 件のコメントを投稿しました"

const GoodMessage: FC<{ user: string; count: number }> = ({ user, count }) => (
  <FormattedMessage
    id="user.postComments"
    values={{ user: <strong>{user}</strong>, count }}
  />
)

// Intl.ListFormat — 本地化列表连接
const formatList = (items: string[], locale: string): string => {
  return new Intl.ListFormat(locale, {
    style: 'long',
    type: 'conjunction',
  }).format(items)
}

formatList(['苹果', '香蕉', '橙子'], 'zh-CN')  // "苹果、香蕉和橙子"
formatList(['Apple', 'Banana', 'Orange'], 'en-US')  // "Apple, Banana, and Orange"
formatList(['Apfel', 'Banane', 'Orange'], 'de-DE')  // "Apfel, Banane und Orange"

// Intl.DisplayNames — 本地化的语言/地区/货币名称
const displayNames = new Intl.DisplayNames('zh-CN', { type: 'language' })
displayNames.of('en')  // "英语"
displayNames.of('ja')  // "日语"

const regionNames = new Intl.DisplayNames('zh-CN', { type: 'region' })
regionNames.of('US')  // "美国"
regionNames.of('JP')  // "日本"

后端多语言数据
当数据本身需要多语言支持时（如产品名称、分类标签），后端需要提供本地化的数据接口。


// 方案 1：Accept-Language 协商
const fetchProduct = async (id: string, locale: string) => {
  const response = await fetch(`/api/products/${id}`, {
    headers: {
      'Accept-Language': locale,
    },
  });
  return response.json();
};

// 方案 2：数据库多语言字段
interface ProductRow {
  product_id: string;
  name_zh: string;
  name_en: string;
  name_ja: string;
  description_zh: string;
  description_en: string;
  description_ja: string;
}

const getLocalizedField = <T extends Record<string, unknown>>(
  row: T,
  field: string,
  locale: string,
  fallback: string = 'en',
): string => {
  const langCode = locale.split('-')[0];
  const key = `${field}_${langCode}` as keyof T;
  const fallbackKey = `${field}_${fallback}` as keyof T;
  return (row[key] as string) || (row[fallbackKey] as string) || '';
};

// 方案 3：JSON 多语言字段
interface ProductWithI18n {

}

实时翻译与机器翻译
某些场景下用户生成内容需要实时翻译，如跨语言客服对话、国际化评论区等。


interface TranslationService {
  translate: (text: string, from: string, to: string) => Promise<string>;
  detectLanguage: (text: string) => Promise<string>;
}

const translateUserContent = async (
  content: string,
  targetLocale: string,
  service: TranslationService,
): Promise<TranslatedContent> => {
  const sourceLanguage = await service.detectLanguage(content);
  const targetLanguage = targetLocale.split('-')[0];

  if (sourceLanguage === targetLanguage) {
    return { original: content, translated: content, isTranslated: false };
  }

  const translated = await service.translate(content, sourceLanguage, targetLanguage);

  return {
    original: content,
    translated,
    isTranslated: true,
    sourceLanguage,
    targetLanguage,
  };
};

// 翻译缓存策略
const translationCache = new Map<string, string>();

const getCacheKey = (text: string, from: string, to: string): string => `${from}:${to}:${hashString(text)}`;

const translateWithCache = async (
  text: string,
  from: string,
  to: string,
  service: TranslationService,
): Promise<string> => {
  const key = getCacheKey(text, from, to);
  const cached = translationCache.get(key);
  if (cached) return cached;

  const result = await service.translate(text, from, to);
  translationCache.set(key, result);
  return result;
};
机器翻译的结果应该明确标注"机器翻译"，让用户了解内容可能不完全准确。同时提供查看原文的选项。


小结
    

  • 动态内容本地化处理运行时生成的文本，不能通过构建时翻译解决
    • 

  • 永远使用参数化消息模板而非字符串拼接，不同语言的词序差异会导致拼接产生语法错误
    • 

  • Intl.ListFormat 和 Intl.DisplayNames 提供本地化的列表连接和名称显示
    • 

  • 后端多语言数据可通过列后缀、JSON 字段或翻译表三种方案实现
    • 

  • 机器翻译适用于 UGC 实时翻译场景，结果需明确标注并提供原文查看
    • 

  • 翻译缓存减少重复翻译的 API 调用和延迟
    •
