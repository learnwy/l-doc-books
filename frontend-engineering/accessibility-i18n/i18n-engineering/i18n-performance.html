i18n 性能优化

核心概念

国际化性能优化的核心挑战是：多语言支持会增加应用的资源体积和加载时间。一个支持 20+ 语言的应用，如果不做优化，翻译文件可能占据数 MB 的包体积。性能优化的关键策略包括翻译资源按需加载、locale 数据拆分、运行时格式化缓存和服务端渲染适配。目标是让用户只加载当前语言的资源，同时保持语言切换的流畅体验。

翻译资源按需加载
按需加载是 i18n 性能优化的核心策略。用户只需下载当前语言的翻译文件，切换语言时再动态加载目标语言：


interface I18nLoaderConfig {
  defaultLocale: string;
  supportedLocales: string[];
  loadPath: string;
  cacheKey: string;
}

const createI18nLoader = (config: I18nLoaderConfig) => {
  const cache = new Map<string, Record<string, string>>();

  const loadLocale = async (locale: string): Promise<Record<string, string>> => {
    if (cache.has(locale)) {
      return cache.get(locale)!;
    }

    const response = await fetch(config.loadPath.replace('{{lng}}', locale));
    const messages = await response.json();
    cache.set(locale, messages);
    return messages;
  };

  const preloadLocale = (locale: string): void => {
    const link = document.createElement('link');
    link.rel = 'prefetch';
    link.href = config.loadPath.replace('{{lng}}', locale);
    document.head.appendChild(link);
  };

  return { loadLocale, preloadLocale };
};
结合路由级别的代码分割，翻译文件可以与页面组件一起按需加载：


const loadPageWithTranslations = async (page: string, locale: string) => {
  const [pageModule, translations] = await Promise.all([
    import(`./pages/${page}/index.tsx`),
    import(`./locales/${locale}/${page}.json`),
  ]);

  return {
    component: pageModule.default,
    messages: translations.default,
  };
};

格式化器缓存
Intl 格式化器的创建开销较大（需要解析 locale 数据和选项），应该缓存复用而非每次创建新实例：


const formatters = new Map<string, Intl.NumberFormat>();

const getCachedFormatter = (locale: string, options?: Intl.NumberFormatOptions): Intl.NumberFormat => {
  const key = `${locale}-${JSON.stringify(options ?? {})}`;
  if (!formatters.has(key)) {
    formatters.set(key, new Intl.NumberFormat(locale, options));
  }
  return formatters.get(key)!;
};

const formatNumber = (value: number, locale: string): string => {
  return getCachedFormatter(locale).format(value);
};

const formatCurrency = (value: number, locale: string, currency: string): string => {
  return getCachedFormatter(locale, { style: 'currency', currency }).format(value);
};

const dateFormatters = new Map<string, Intl.DateTimeFormat>();

const getCachedDateFormatter = (locale: string, options?: Intl.DateTimeFormatOptions): Intl.DateTimeFormat => {
  const key = `${locale}-${JSON.stringify(options ?? {})}`;
  if (!dateFormatters.has(key)) {
    dateFormatters.set(key, new Intl.DateTimeFormat(locale, options));
  }
  return dateFormatters.get(key)!;
};

Intl Polyfill 优化
部分 Intl API 在旧浏览器中需要 polyfill，但 polyfill 数据通常很大。按需加载 locale 数据是关键：


const loadIntlPolyfills = async (locale: string): Promise<void> => {
  if (!Intl.DisplayNames) {
    await import('@formatjs/intl-displaynames/polyfill');
    await import(`@formatjs/intl-displaynames/locale-data/${locale}`);
  }

  if (!Intl.ListFormat) {
    await import('@formatjs/intl-listformat/polyfill');
    await import(`@formatjs/intl-listformat/locale-data/${locale}`);
  }

  if (!Intl.RelativeTimeFormat) {
    await import('@formatjs/intl-relativetimeformat/polyfill');
    await import(`@formatjs/intl-relativetimeformat/locale-data/${locale}`);
  }
};

const setupI18n = async (locale: string): Promise<void> => {
  await loadIntlPolyfills(locale);
  const messages = await loadLocaleMessages(locale);
  initializeI18n(locale, messages);
};

SSR 与 Hydration
服务端渲染的 i18n 需要在请求时确定 locale，避免客户端闪烁：


const detectServerLocale = (request: Request): string => {
  const urlLocale = new URL(request.url).pathname.split('/')[1];
  if (urlLocale && supportedLocales.includes(urlLocale)) {
    return urlLocale;
  }

  const cookieLocale = parseCookie(request.headers.get('cookie') ?? '').locale;
  if (cookieLocale && supportedLocales.includes(cookieLocale)) {
    return cookieLocale;
  }

  const acceptLanguage = request.headers.get('accept-language') ?? '';
  const preferredLocale = parseAcceptLanguage(acceptLanguage).find((lang) => supportedLocales.includes(lang));

  return preferredLocale ?? defaultLocale;
};

const parseAcceptLanguage = (header: string): string[] => {
  return header
    .split(',')
    .map((part) => {
      const [lang, q] = part.trim().split(';q=');
      return { lang: lang.trim(), quality: q ? Number.parseFloat(q) : 1 };
    })
    .sort((a, b) => b.quality - a.quality)
    .map(({ lang }) => lang);
};
小结
    

  • 翻译资源按需加载是 i18n 性能优化最重要的策略，可节省 80-95% 包体积
    • 

  • Intl 格式化器缓存复用可将格式化性能提升 15x
    • 

  • Polyfill 按 locale 动态加载，避免全量引入数百 KB 的 locale 数据
    • 

  • SSR 场景需在请求时检测 locale，通过 URL/Cookie/Accept-Language 优先级链
    • 

  • 预加载（prefetch）常用语言翻译文件可显著改善语言切换体验
    • 

  • 翻译文件应与页面代码分割对齐，实现真正的按需加载
