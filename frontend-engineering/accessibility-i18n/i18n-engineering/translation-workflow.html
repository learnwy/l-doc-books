翻译工作流

核心概念

翻译工作流（Translation Workflow）是连接开发团队与翻译团队的系统化流程。一个高效的翻译工作流应该让开发者专注于功能开发，翻译者专注于语言质量，中间通过自动化工具衔接。核心环节包括：字符串提取、翻译管理、质量检查和部署集成。现代翻译管理系统（TMS）如 Crowdin、Lokalise 和 Phrase 提供了完整的工作流自动化能力。

自动提取源代码中的翻译字符串是工作流的起点。主流 i18n 框架都支持通过 CLI 工具扫描代码并提取翻译键：

  react_intl: `
    # react-intl 提取
    npx formatjs extract 'src/**/*.{ts,tsx}' \\

  i18next: `
    # i18next-parser 提取

  vue_i18n: `

翻译质量检查
自动化质量检查（QA Check）在翻译流程中至关重要，可以在部署前捕获格式错误、缺失翻译和不一致等问题：


interface QACheck {
  name: string;
  severity: 'error' | 'warning' | 'info';
  check: (source: string, target: string) => boolean;
}

const qaChecks: QACheck[] = [
  {
    name: '占位符匹配',
    severity: 'error',
    check: (source, target) => {
      const sourceVars = source.match(/\{[^}]+\}/g) ?? [];
      const targetVars = target.match(/\{[^}]+\}/g) ?? [];
      return sourceVars.length === targetVars.length && sourceVars.every((v) => targetVars.includes(v));
    },
  },
  {
    name: 'HTML 标签匹配',
    severity: 'error',
    check: (source, target) => {
      const sourceTags = source.match(/<[^>]+>/g) ?? [];
      const targetTags = target.match(/<[^>]+>/g) ?? [];
      return sourceTags.length === targetTags.length;
    },
  },
  {
    name: '末尾标点一致',
    severity: 'warning',
    check: (source, target) => {
      const sourceEnd = source.trim().slice(-1);
      const targetEnd = target.trim().slice(-1);
      const punctuation = /[.!?。！？]/;
      if (punctuation.test(sourceEnd)) {
        return punctuation.test(targetEnd);
      }
      return true;
    },
  },
  {
    name: '长度合理性',
    severity: 'warning',
    check: (source, target) => {
      const ratio = target.length / source.length;
      return ratio > 0.5 && ratio < 3.0;
    },
  },
];

const runQAChecks = (source: string, target: string, checks: QACheck[]): { passed: boolean; failures: string[] } => {
  const failures: string[] = [];
  for (const check of checks) {
    if (!check.check(source, target)) {
      failures.push(`[${check.severity}] ${check.name}`);
    }
  }
  return { passed: failures.length === 0, failures };
};
CI/CD 集成
翻译工作流应该深度集成到 CI/CD 流程中，实现提取-上传-同步的全自动化：


# .github/workflows/i18n.yml
name: i18n Sync
on:
  push:
    branches: [main]
    paths: ['src/**/*.{ts,tsx}']

jobs:
  extract-and-upload:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20

      - run: npm ci
      - run: npx formatjs extract 'src/**/*.{ts,tsx}' --out-file lang/en.json

      - name: Upload to Crowdin
        uses: crowdin/github-action@v2
        with:
          upload_sources: true
          download_translations: true
          create_pull_request: true
          pull_request_title: 'chore(i18n): update translations'
        env:
          CROWDIN_PROJECT_ID: ${{ secrets.CROWDIN_PROJECT_ID }}
          CROWDIN_PERSONAL_TOKEN: ${{ secrets.CROWDIN_TOKEN }}
interface CiWorkflow {
  trigger: string;
  steps: string[];
  frequency: string;
}

const ciWorkflows: CiWorkflow[] = [
  {
    trigger: '代码推送到 main',
    steps: ['提取字符串', '上传到 TMS', '触发机器预翻译'],
    frequency: '每次推送',
  },
  {
    trigger: '翻译完成 webhook',
    steps: ['下载翻译', '运行 QA 检查', '创建 PR'],
    frequency: '翻译更新时',
  },
  {
    trigger: '发布前检查',
    steps: ['检查翻译覆盖率', '验证格式正确性', '阻断低于阈值'],
    frequency: '每次发布',
  },
];

小结
    

  • 翻译管理平台（Crowdin/Lokalise）是现代翻译工作流的核心基础设施
    • 

  • 自动字符串提取消除了手动同步翻译键的人工错误
    • 

  • QA 检查（占位符匹配、标签匹配、长度检查）在部署前捕获翻译格式问题
    • 

  • CI/CD 集成实现了提取-上传-翻译-同步的全自动化闭环
    • 

  • 机器翻译作为初稿 + 人工审核是效率和质量的最佳平衡
    • 

  • 翻译覆盖率检查应作为发布阻断条件，防止未翻译内容上线
    •
