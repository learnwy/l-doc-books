wasm-pack 打包工具

工作流概览

wasm-pack 是 Rust WASM 项目的一站式构建工具，整合了编译、wasm-bindgen 处理、npm 包生成和发布的完整流程。

# 安装
curl https://rustwasm.github.io/wasm-pack/installer/init.sh -sSf | sh

# 创建新项目
wasm-pack new my-wasm-lib
cd my-wasm-lib

# 构建
wasm-pack build --target web

# 测试
wasm-pack test --headless --chrome

# 发布到 npm
wasm-pack publish

提示： wasm-pack build 默认使用 --release 模式。如果需要调试信息，显式传入 --dev 标志。开发阶段建议使用 --dev --target web 获得更快的编译速度和更好的调试体验。

wasm-pack 支持三种构建目标，决定了生成的 JS 胶水代码的模块格式。

// --target web: ES Module 加载
import init, { greet } from './pkg/my_wasm.js';
await init();
greet('World');

// --target bundler: 由打包工具处理
import { greet } from 'my-wasm-lib';
greet('World');
// Cargo.toml
// [lib]
// crate-type = ["cdylib", "rlib"]

pkg 目录结构
构建完成后，pkg/ 目录包含完整的 npm 包内容。


pkg/
├── my_wasm_bg.wasm          # 编译后的 WASM 二进制
├── my_wasm_bg.wasm.d.ts     # WASM 二进制的 TS 类型
├── my_wasm.js               # JS 胶水代码（入口）
├── my_wasm.d.ts             # TypeScript 类型声明
├── package.json             # npm 包描述
├── README.md                # 从项目根目录复制
└── snippets/                # 内联 JS 片段
{
  "name": "my-wasm-lib",
  "version": "0.1.0",
  "files": ["my_wasm_bg.wasm", "my_wasm.js", "my_wasm.d.ts"],
  "module": "my_wasm.js",
  "types": "my_wasm.d.ts",
  "sideEffects": ["./snippets/*"]
}

提示： 如果你的 WASM 包需要发布为 scoped 包（如 @myorg/my-wasm），在 Cargo.toml 的 [package.metadata.wasm-pack.profile.release] 中无法设置包名。需要在构建后手动修改 pkg/package.json 的 name 字段，或使用 --scope 选项。






构建优化
生产级 WASM 构建需要多层优化以平衡体积和性能。


# Cargo.toml
[profile.release]
lto = true
opt-level = "z"
codegen-units = 1
strip = true

[package.metadata.wasm-pack.profile.release]
wasm-opt = ["-Oz", "--enable-simd"]




优化手段
配置
效果





LTO（链接时优化）
lto = true
减少 10-20% 体积




体积优化级别
opt-level = "z"
最小体积




速度优化级别
opt-level = 3
最大性能




单编译单元
codegen-units = 1
更好的优化机会




符号剥离
strip = true
移除调试符号




wasm-opt
wasm-opt -Oz
WASM 级别优化




Gzip/Brotli 压缩
服务端配置
传输体积减少 60-80%





# 手动优化流程
wasm-pack build --release --target web

# 进一步用 wasm-opt 优化
wasm-opt pkg/my_wasm_bg.wasm -Oz -o pkg/my_wasm_bg.wasm

# 查看体积
ls -lh pkg/my_wasm_bg.wasm

# Brotli 压缩
brotli pkg/my_wasm_bg.wasm
ls -lh pkg/my_wasm_bg.wasm.br


npm 发布流程
将 WASM 包发布到 npm 后，前端项目可以像使用普通 npm 包一样使用它。


# 第一次发布
wasm-pack login
wasm-pack build --release --target bundler --scope myorg
wasm-pack publish --access public

# 更新版本
# 修改 Cargo.toml 中的 version 字段
wasm-pack build --release --target bundler
wasm-pack publish
{
  "dependencies": {
    "@myorg/my-wasm": "^0.1.0"
  }
}
import { initSync, greet } from '@myorg/my-wasm';

const wasmUrl = new URL('@myorg/my-wasm/my_wasm_bg.wasm', import.meta.url);
const response = await fetch(wasmUrl);
const bytes = await response.arrayBuffer();
initSync(bytes);

const result = greet('npm 用户');

小结
    

  • wasm-pack 整合了 cargo build → wasm-bindgen → wasm-opt → npm publish 的完整工作流。
    • 

  • 三种构建目标（web/bundler/nodejs）对应不同的模块格式和使用场景。
    • 

  • pkg/ 目录包含 WASM 二进制、JS 胶水代码、TypeScript 类型声明和 package.json。
    • 

  • 生产构建通过 LTO + opt-level + wasm-opt + Brotli 多层优化，可将传输体积压缩到原始的 10-20%。
    • 

  • WASM 包可以发布到 npm 仓库，前端项目像使用普通 npm 包一样引入。
    •
