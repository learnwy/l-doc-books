调试 WASM

DWARF 调试信息

DWARF 是 WASM 采用的标准调试信息格式。Rust 编译器可以在 WASM 二进制中嵌入 DWARF 段，让调试器映射回源码。

# Cargo.toml
[profile.release]
debug = true
strip = "none"

[profile.dev]
debug = 2
opt-level = 0
调试级别 Cargo 配置 信息量 体积影响
0 debug = 0 无调试信息 无
1 debug = 1 行号信息 增加 20-50%
2 debug = 2 完整调试信息 增加 100-300%
line debug = "line-tables-only" 仅行号 增加 10-20% 
# 查看 DWARF 段
wasm-objdump -h target/wasm32-unknown-unknown/debug/my_lib.wasm

# 输出示例:
# Sections:
#   ...
#   Custom ".debug_info" (size=125432)
#   Custom ".debug_line" (size=34521)
#   Custom ".debug_abbrev" (size=8921)
#   Custom ".debug_str" (size=45672)


提示： 生产构建应剥离 DWARF 信息（strip = true），但保留一份带调试信息的构建产物用于问题排查。可以用 wasm-split 将调试信息分离到独立文件。

console_error_panic_hook
console_error_panic_hook 将 Rust panic 信息转发到浏览器控制台，是 WASM 调试的必备工具。


use wasm_bindgen::prelude::*;

#[wasm_bindgen(start)]
fn init() {
    console_error_panic_hook::set_once();
}

#[wasm_bindgen]
pub fn risky_operation(index: usize) -> u32 {
    let data = vec![1, 2, 3, 4, 5];
    data[index]
}
# 未安装 panic hook 时的错误信息:
RuntimeError: unreachable executed

# 安装 panic hook 后的错误信息:
panicked at 'index out of bounds: the len is 5 but the index is 10', src/lib.rs:9:5
# Cargo.toml
[dependencies]
console_error_panic_hook = "0.1"
wasm-bindgen = "0.2"

# 可选: 更好的日志输出
console_log = "1"
log = "0.4"

use log::{info, warn, error};

#[wasm_bindgen(start)]
fn init() {
    console_error_panic_hook::set_once();
    console_log::init_with_level(log::Level::Debug).unwrap();
}

#[wasm_bindgen]
pub fn process(data: &[u8]) -> Vec<u8> {
    info!("处理 {} 字节数据", data.len());

    if data.is_empty() {
        warn!("收到空数据");
        return vec![];
    }

    let result: Vec<u8> = data.iter().map(|b| b.wrapping_add(1)).collect();
    info!("处理完成，输出 {} 字节", result.len());
    result
}


提示： console_error_panic_hook 应该在模块初始化时调用一次。使用 #[wasm_bindgen(start)] 标记的函数会在实例化完成后自动执行，是设置 hook 的最佳位置。






性能分析
Chrome DevTools 的 Performance 面板可以分析 WASM 函数的执行时间，帮助定位性能瓶颈。


async function profileWasm() {
  const instance = await init();

  console.time('wasm-compute');
  performance.mark('wasm-start');

  const result = instance.exports.heavy_computation(data);

  performance.mark('wasm-end');
  performance.measure('WASM Computation', 'wasm-start', 'wasm-end');
  console.timeEnd('wasm-compute');

  const measures = performance.getEntriesByName('WASM Computation');
  console.log(`耗时: ${measures[0].duration.toFixed(2)}ms`);
}

小结
    

  • DWARF 调试信息通过自定义段嵌入 WASM，配合 Chrome 扩展可实现源码级断点和变量查看。
    • 

  • Chrome DevTools 原生支持 WASM 的 WAT 查看、内存检查和性能分析。
    • 

  • Source Maps 提供轻量的行号映射，适合生产环境的错误追踪。
    • 

  • console_error_panic_hook 将 Rust panic 转发到浏览器控制台，是WASM 调试的必备工具。
    • 

  • Performance 面板的火焰图可以定位 WASM 热点函数，配合 performance.mark/measure 实现精确计时。
