内存管理

线性内存共享

Rust WASM 模块和 JavaScript 共享同一块线性内存。理解这块共享内存的布局和访问模式是避免 bug 的关键。

use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn allocate(size: usize) -> *mut u8 {
    let mut buf = Vec::with_capacity(size);
    let ptr = buf.as_mut_ptr();
    std::mem::forget(buf);
    ptr
}

#[wasm_bindgen]
pub fn deallocate(ptr: *mut u8, size: usize) {
    unsafe { let _ = Vec::from_raw_parts(ptr, 0, size); }
}

js-sys 与 web-sys
js-sys 和 web-sys 是 wasm-bindgen 生态中两个核心的 Rust 绑定库，分别对应 JavaScript 内置 API 和 Web API。


use js_sys::{Array, Date, Map, Promise, Reflect};
use wasm_bindgen::prelude::*;
use wasm_bindgen_futures::JsFuture;
use web_sys::{console, Document, Element, Window};

#[wasm_bindgen]
pub fn create_element(tag: &str) -> Result<Element, JsValue> {
    let window: Window = web_sys::window().unwrap();
    let document: Document = window.document().unwrap();
    document.create_element(tag)
}

#[wasm_bindgen]
pub async fn fetch_data(url: &str) -> Result<JsValue, JsValue> {
    let window = web_sys::window().unwrap();
    let resp_value = JsFuture::from(window.fetch_with_str(url)).await?;
    let resp: web_sys::Response = resp_value.dyn_into()?;
    JsFuture::from(resp.json()?).await
}

字符串与数组传递
字符串和数组是 Rust↔JS 边界最常见的传递类型，也是性能敏感的操作。


use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn process_string(input: &str) -> String {
    input.chars()
        .filter(|c| c.is_alphanumeric())
        .collect::<String>()
        .to_uppercase()
}

#[wasm_bindgen]
pub fn sum_array(data: &[f64]) -> f64 {
    data.iter().sum()
}

#[wasm_bindgen]
pub fn transform_pixels(pixels: &mut [u8]) {
    for chunk in pixels.chunks_exact_mut(4) {
        let gray = (chunk[0] as f32 * 0.299
            + chunk[1] as f32 * 0.587
            + chunk[2] as f32 * 0.114) as u8;
        chunk[0] = gray;
        chunk[1] = gray;
        chunk[2] = gray;
    }
}

serde-wasm-bindgen
serde-wasm-bindgen 允许在 Rust 和 JS 之间直接序列化/反序列化复杂数据结构，无需手动转换。


use serde::{Deserialize, Serialize};
use wasm_bindgen::prelude::*;

#[derive(Serialize, Deserialize)]
pub struct Config {
    pub width: u32,
    pub height: u32,
    pub title: String,
    pub features: Vec<String>,
    pub theme: Theme,
}

#[derive(Serialize, Deserialize)]
pub enum Theme {
    Light,
    Dark,
    Custom(String),
}

#[wasm_bindgen]
pub fn process_config(val: JsValue) -> Result<JsValue, JsValue> {
    let config: Config = serde_wasm_bindgen::from_value(val)?;

    let processed = Config {
        title: format!("[处理后] {}", config.title),
        ..config
    };

    serde_wasm_bindgen::to_value(&processed)
        .map_err(|e| JsValue::from_str(&e.to_string()))
}

Typed Arrays 与零拷贝
利用 TypedArray 的共享视图可以实现 JS 和 WASM 之间的零拷贝数据交换。


use js_sys::Float64Array;
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub struct DataProcessor {
    buffer: Vec<f64>,
}

#[wasm_bindgen]
impl DataProcessor {
    #[wasm_bindgen(constructor)]
    pub fn new(size: usize) -> DataProcessor {
        DataProcessor { buffer: vec![0.0; size] }
    }

    pub fn get_buffer_view(&self) -> Float64Array {
        unsafe { Float64Array::view(&self.buffer) }
    }

    pub fn compute_mean(&self) -> f64 {
        let sum: f64 = self.buffer.iter().sum();
        sum / self.buffer.len() as f64
    }
}

提示： Float64Array::view() 创建的视图指向 WASM 线性内存。如果 Rust 侧触发了 memory.grow（例如 Vec 扩容），视图的底层 ArrayBuffer 会被 detach，导致 JS 侧访问出错。使用 view 时确保不会触发内存增长。






小结
    

  • Rust WASM 和 JS 共享线性内存，JS 通过 memory.buffer 获取 ArrayBuffer 视图。
    • 

  • js-sys 覆盖 JS 内置 API，web-sys 覆盖 Web API 并通过 Cargo feature 按需引入。
    • 

  • 字符串传递需要 UTF-8/UTF-16 拷贝，切片引用 &[u8] 可实现函数参数的零拷贝传递。
    • 

  • serde-wasm-bindgen 直接操作 JsValue 序列化复杂类型，避免 JSON 字符串的双重解析。
    • 

  • TypedArray::view() 提供零拷贝访问，但必须注意 memory.grow 后视图失效的问题。
