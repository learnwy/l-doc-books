WASM 架构

栈式虚拟机模型

WebAssembly 采用栈式虚拟机（Stack Machine）作为计算模型。与寄存器机器不同，所有运算都通过操作数栈完成——指令从栈顶取操作数，将结果压回栈顶。

(module
  (func $add (param $a i32) (param $b i32) (result i32)
    local.get $a    ;; 将参数 a 压栈
    local.get $b    ;; 将参数 b 压栈
    i32.add         ;; 弹出两个值，相加后压栈
  )
  (export "add" (func $add))
)
特性 栈式机器（WASM） 寄存器机器（x86/ARM）
操作数位置 隐式（栈顶） 显式（寄存器名）
指令编码 更紧凑（无寄存器字段） 更长（含寄存器编号）
验证难度 简单（类型栈推导） 复杂（寄存器分配）
执行方式 解释/JIT 编译为原生代码 直接硬件执行
二进制体积 小（适合网络传输） 大（含冗余编码） 


提示： 虽然 WASM 规范定义的是栈式语义，但实际的引擎实现（如 V8 的 Liftoff/TurboFan）会将栈操作转换为寄存器分配，获得与原生代码相当的执行效率。

#[wasm_bindgen]
pub fn fibonacci(n: u32) -> u32 {
    match n {
        0 => 0,
        1 => 1,
        _ => fibonacci(n - 1) + fibonacci(n - 2),
    }
}


线性内存
线性内存是 WASM 最重要的数据存储机制——一块连续的、可增长的字节数组，以 64KB（1 页）为单位分配。


(module
  (memory (export "memory") 1 10)  ;; 初始 1 页，最大 10 页

  (func $write (param $offset i32) (param $value i32)
    local.get $offset
    local.get $value
    i32.store                      ;; 将 value 写入 offset 位置
  )

  (func $read (param $offset i32) (result i32)
    local.get $offset
    i32.load                       ;; 从 offset 位置读取 i32
  )
)




属性
说明





最小单位
1 页 = 65536 字节（64KB）




地址空间
32 位（最大 4GB），Memory64 提案支持 64 位




增长方式
memory.grow 指令，返回旧页数或 -1




访问方式
load/store 指令族（i32/i64/f32/f64）




边界检查
运行时自动检查，越界触发 trap




JS 侧访问
WebAssembly.Memory → ArrayBuffer





const memory = new WebAssembly.Memory({ initial: 1, maximum: 10 });
const buffer = new Uint8Array(memory.buffer);
buffer[0] = 42;
memory.grow(1);


提示： 线性内存的 ArrayBuffer 在 memory.grow 后会被 detach。JS 侧持有的旧引用将失效，需要重新获取 memory.buffer。这是新手最常遇到的陷阱之一。






函数表
函数表（Table）是 WASM 实现间接函数调用的机制，类似于 C 语言的函数指针数组。


(module
  (type $callback (func (param i32) (result i32)))
  (table 2 funcref)

  (func $double (param i32) (result i32)
    local.get 0
    i32.const 2
    i32.mul)

  (func $triple (param i32) (result i32)
    local.get 0
    i32.const 3
    i32.mul)

  (elem (i32.const 0) $double $triple)

  (func $call_indirect (param $idx i32) (param $val i32) (result i32)
    local.get $val
    local.get $idx
    call_indirect (type $callback))

  (export "call" (func $call_indirect))
)




对比维度
直接调用（call）
间接调用（call_indirect）





目标函数
编译时确定
运行时通过索引查找




类型检查
编译时验证
运行时验证签名匹配




使用场景

回调、虚函数表、插件系统




性能
更快（无查表开销）
略慢（需查表+类型检查）

(func $control_flow_example (param $n i32) (result i32)
  (local $sum i32)
  (local $i i32)
  (local.set $i (i32.const 0))
  (local.set $sum (i32.const 0))
  (block $break
    (loop $continue
      (br_if $break (i32.ge_u (local.get $i) (local.get $n)))
      (local.set $sum
        (i32.add (local.get $sum) (local.get $i)))
      (local.set $i
        (i32.add (local.get $i) (i32.const 1)))
      (br $continue)
    )
  )
  (local.get $sum)
)


提示： WASM 采用结构化控制流——没有任意跳转的 goto 指令。所有分支目标必须是当前作用域的 block/loop 标签，这一设计保证了控制流图的可验证性和安全性。






小结
    

  • WASM 采用栈式虚拟机模型，指令隐式操作栈顶元素，编码紧凑且易于验证。
    • 

  • 模块由多个段组成，Type 段定义签名、Code 段包含函数体、Export 段声明对外接口。
    • 

  • 线性内存是一块连续字节数组，以 64KB 页为单位增长，JS 侧通过 ArrayBuffer 访问。
    • 

  • 函数表实现间接调用，支持回调、虚函数表等动态分派场景，运行时验证类型签名。
    • 

  • 指令集覆盖数值运算、内存操作、控制流和变量操作，采用结构化控制流保证安全性。
    •
