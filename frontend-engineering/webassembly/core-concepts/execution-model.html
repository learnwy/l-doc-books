实例化过程

WASM 模块从加载到执行需要经历解码、验证、编译和实例化四个阶段。实例化是将静态模块变为可执行实例的关键步骤。

const response = await fetch('compute.wasm');
const module = await WebAssembly.compileStreaming(response);

const importObject = {
  env: {
    log: (value: number) => console.log(value),
    memory: new WebAssembly.Memory({ initial: 1 }),
  },
};

const instance = await WebAssembly.instantiate(module, importObject);
const result = instance.exports.compute(42);

调用栈管理
WASM 的调用栈与 JavaScript 调用栈是分离的。每次函数调用会在 WASM 栈上创建一个新的调用帧（Call Frame）。

(module
  (func $factorial (param $n i32) (result i32)
    (if (result i32) (i32.le_s (local.get $n) (i32.const 1))
      (then (i32.const 1))
      (else
        (i32.mul
          (local.get $n)
          (call $factorial
            (i32.sub (local.get $n) (i32.const 1))
          )
        )
      )
    )
  )
  (export "factorial" (func $factorial))
)
#[wasm_bindgen]
pub fn factorial(n: u32) -> u64 {
    (1..=n as u64).product()
}


提示： WASM 规范没有定义调用栈的大小限制，这取决于具体引擎实现。V8 通常允许约 10000 层递归，但生产代码应该避免深递归，改用循环实现。






Trap 处理
Trap 是 WASM 的运行时错误机制。当发生不可恢复的错误时，执行立即终止并向宿主报告错误。

  instance.exports.riskyFunction();
} catch (error) {
  if (error instanceof WebAssembly.RuntimeError) {

#[wasm_bindgen]
pub fn safe_access(data: &[u8], index: usize) -> Result<u8, JsValue> {
    data.get(index)
        .copied()
        .ok_or_else(|| JsValue::from_str("Index out of bounds"))
}


提示： Trap 会立即终止整个 WASM 调用链。如果你需要错误恢复而不是终止，应该在 Rust 侧使用 Result 类型，将错误作为返回值传递给 JS，而不是让 panic 变成 trap。

WASM 的一个重要设计目标是确定性——相同的输入在任何平台上都应该产生相同的输出。

pub fn deterministic_compute(a: f64, b: f64) -> f64 {
    let sum = a + b;
    let product = a * b;
    (sum + product) / 2.0
}


提示： NaN 的位模式是 WASM 中唯一的非确定性来源。如果你的应用需要位级确定性（如区块链场景），需要使用 f32.copysign 等方式规范化 NaN 值。






沙箱安全保证
WASM 的沙箱模型确保模块只能访问被显式授予的资源，不能突破隔离边界。






安全属性
机制





内存隔离
线性内存有明确边界，无法访问宿主内存




无系统调用
WASM 无内置 I/O，必须通过导入函数




代码完整性
已验证代码不可被运行时修改




能力受限

控制流完整性

小结
    

  • WASM 实例化经历解码→验证→编译→链接四阶段，优先使用 Streaming API 实现下载与编译并行。
    • 

  • 调用栈独立于 JS 栈，每个调用帧包含局部变量、操作数栈和返回地址。
    • 

  • Trap 是不可恢复的运行时错误，包括内存越界、除零、类型不匹配等，在 JS 侧表现为 RuntimeError。
    • 

  • WASM 保证确定性执行——除 NaN 位模式外，相同输入在任何引擎上产生相同输出。
    • 

  • 沙箱模型确保 WASM 代码只能访问线性内存和宿主显式提供的导入，无法突破隔离边界。
    •
