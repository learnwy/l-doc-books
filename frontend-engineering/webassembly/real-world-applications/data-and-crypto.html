SQLite WASM (sql.js)

SQLite 编译到 WASM 后，可以在浏览器中运行完整的关系型数据库——无需服务器，数据完全存储在客户端。

import initSqlJs, { Database } from 'sql.js';

async function createDatabase(): Promise<Database> {
  const SQL = await initSqlJs({
    locateFile: (file: string) => `/wasm/${file}`,
  });

  const db = new SQL.Database();

  db.run(`
    CREATE TABLE IF NOT EXISTS notes (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      title TEXT NOT NULL,
      content TEXT,
      created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
      updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
    )
  `);

  db.run('INSERT INTO notes (title, content) VALUES (?, ?)', ['第一条笔记', '这是在浏览器 SQLite 中创建的数据']);

  const results = db.exec('SELECT * FROM notes ORDER BY created_at DESC');
  console.log('查询结果:', results);

  return db;
}

async function persistDatabase(db: Database): Promise<void> {
  const data = db.export();
  const root = await navigator.storage.getDirectory();
  const handle = await root.getFileHandle('app.db', { create: true });
  const writable = await handle.createWritable();
  await writable.write(data);
  await writable.close();
}

async function loadDatabase(SQL: any): Promise<Database> {
  const root = await navigator.storage.getDirectory();
  try {
    const handle = await root.getFileHandle('app.db');
    const file = await handle.getFile();
    const buffer = await file.arrayBuffer();
    return new SQL.Database(new Uint8Array(buffer));
  } catch {
    return new SQL.Database();
  }
}


提示： sql.js 的数据库完全在内存中运行，刷新页面后数据会丢失。使用 OPFS（Origin Private File System）可以实现持久化存储，但需要在安全上下文（HTTPS）中使用。






DuckDB WASM
DuckDB 是一个面向分析的嵌入式数据库，编译到 WASM 后可以在浏览器中处理 GB 级数据分析。


import * as duckdb from '@duckdb/duckdb-wasm';

async function analyzeData() {
  const JSDELIVR_BUNDLES = duckdb.getJsDelivrBundles();
  const bundle = await duckdb.selectBundle(JSDELIVR_BUNDLES);
  const worker = new Worker(bundle.mainWorker!);
  const db = new duckdb.AsyncDuckDB(new duckdb.ConsoleLogger(), worker);
  await db.instantiate(bundle.mainModule, bundle.pthreadWorker);
  const conn = await db.connect();

  await conn.query(`
    CREATE TABLE sales AS SELECT * FROM read_csv_auto('https://example.com/sales.csv')
  `);

  const result = await conn.query(`
    SELECT region, SUM(revenue) AS total_revenue, COUNT(*) AS orders
    FROM sales WHERE date >= '2025-01-01'
    GROUP BY region ORDER BY total_revenue DESC LIMIT 10
  `);

  console.table(result.toArray());
  await conn.close();
}

加密运算
将加密算法编译到 WASM 可以获得比纯 JS 实现更好的性能，同时避免了 Web Crypto API 的异步限制。


use wasm_bindgen::prelude::*;
use sha2::{Sha256, Digest};
use aes_gcm::{aead::{Aead, KeyInit}, Aes256Gcm, Nonce};

#[wasm_bindgen]
pub fn sha256_hash(data: &[u8]) -> Vec<u8> {
    let mut hasher = Sha256::new();
    hasher.update(data);
    hasher.finalize().to_vec()
}

#[wasm_bindgen]
pub fn aes_encrypt(key: &[u8], nonce: &[u8], plaintext: &[u8]) -> Result<Vec<u8>, JsValue> {
    let cipher = Aes256Gcm::new_from_slice(key)
        .map_err(|e| JsValue::from_str(&e.to_string()))?;
    cipher.encrypt(Nonce::from_slice(nonce), plaintext)
        .map_err(|e| JsValue::from_str(&e.to_string()))
}

#[wasm_bindgen]
pub fn aes_decrypt(key: &[u8], nonce: &[u8], ciphertext: &[u8]) -> Result<Vec<u8>, JsValue> {
    let cipher = Aes256Gcm::new_from_slice(key)
        .map_err(|e| JsValue::from_str(&e.to_string()))?;
    cipher.decrypt(Nonce::from_slice(nonce), ciphertext)
        .map_err(|e| JsValue::from_str(&e.to_string()))
}

import { sha256_hash, aes_encrypt, aes_decrypt } from './pkg/crypto_wasm.js';

const data = new TextEncoder().encode('敏感数据');
const hash = sha256_hash(data);
console.log(
  'SHA-256:',
  Array.from(hash)
    .map((b) => b.toString(16).padStart(2, '0'))
    .join(''),
);

const key = crypto.getRandomValues(new Uint8Array(32));
const nonce = crypto.getRandomValues(new Uint8Array(12));
const encrypted = aes_encrypt(key, nonce, data);
const decrypted = aes_decrypt(key, nonce, encrypted);
console.log('解密:', new TextDecoder().decode(decrypted));


提示： WASM 加密实现的一个重要优势是同步执行。Web Crypto API 的所有操作都是异步的，在需要大量小数据块加密的场景（如逐帧加密），WASM 的同步调用避免了 Promise 调度开销。






Protobuf / FlatBuffers in WASM
高效的序列化格式编译到 WASM，可以在浏览器中实现零拷贝数据访问和高速序列化。


use wasm_bindgen::prelude::*;
use prost::Message;

#[derive(Clone, PartialEq, Message)]
pub struct UserEvent {
    #[prost(string, tag = "1")]
    pub user_id: String,
    #[prost(string, tag = "2")]
    pub event_type: String,
    #[prost(int64, tag = "3")]
    pub timestamp: i64,
}

#[wasm_bindgen]
pub fn encode_event(user_id: &str, event_type: &str, timestamp: f64) -> Vec<u8> {
    let event = UserEvent {
        user_id: user_id.to_string(),
        event_type: event_type.to_string(),
        timestamp: timestamp as i64,
    };
    event.encode_to_vec()
}

#[wasm_bindgen]
pub fn decode_event(data: &[u8]) -> JsValue {
    match UserEvent::decode(data) {
        Ok(event) => {
            let obj = js_sys::Object::new();
            js_sys::Reflect::set(&obj, &"userId".into(), &event.user_id.into()).unwrap();
            js_sys::Reflect::set(&obj, &"eventType".into(), &event.event_type.into()).unwrap();
            obj.into()
        }
        Err(e) => JsValue::from_str(&e.to_string()),
    }
}

提示： FlatBuffers 的核心优势是零拷贝反序列化——数据不需要解析到内存对象中，而是直接在二进制缓冲区上访问字段。配合 WASM 的共享线性内存，可以实现 JS 和 WASM 之间的零拷贝数据交换。






小结
    

  • sql.js 将完整 SQLite 编译到 WASM（~1.2MB），支持 SQL 查询、JOIN、事务，配合 OPFS 实现持久化。
    • 

  • DuckDB WASM 面向 OLAP 分析，支持 Parquet 原生读取和远程 HTTP 查询 TB 级数据。
    • 

  • WASM 加密实现提供 同步执行和 Web Crypto 不支持的算法（Argon2、Ed25519、ChaCha20）。
    • 

  • Protobuf 提供高效的二进制序列化，FlatBuffers 实现零拷贝反序列化。
    • 

  • 在浏览器中运行数据库和加密引擎，实现了完全离线和数据不出端的隐私保护架构。
