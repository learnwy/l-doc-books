组件模型

WASM 组件模型概述

WASM 组件模型（Component Model）是 WebAssembly 的下一代架构，旨在让不同语言编写的 WASM 模块像乐高积木一样组合在一起。

// 使用 wit-bindgen 生成绑定
// wit/world.wit:
// package example:calculator;
// world calculator {
//   export add: func(a: s32, b: s32) -> s32;
//   export multiply: func(a: s32, b: s32) -> s32;
// }

wit_bindgen::generate!({
    world: "calculator",
});

struct MyCalculator;

impl Guest for MyCalculator {
    fn add(a: i32, b: i32) -> i32 {
        a + b
    }

    fn multiply(a: i32, b: i32) -> i32 {
        a * b
    }
}

export!(MyCalculator);


提示： 组件模型的核心创新是独立内存——每个组件拥有自己的线性内存，组件间通过接口类型传递数据，由运行时负责数据的拷贝/转换。这消除了共享内存带来的安全风险。






WIT 接口定义语言
WIT（WASM Interface Types）是组件模型的接口定义语言，类似于 Protocol Buffers 或 IDL。


package my-org:image-processing@0.1.0;

interface types {
    record pixel {
        r: u8,
        g: u8,
        b: u8,
        a: u8,
    }

    record image {
        width: u32,
        height: u32,
        pixels: list<pixel>,
    }

    enum format {
        png,
        jpeg,
        webp,
    }

    variant error {
        invalid-format(string),
        decode-failed(string),
        out-of-memory,
    }
}

interface processor {
    use types.{image, format, error};

    resize: func(img: image, width: u32, height: u32) -> result<image, error>;
    convert: func(img: image, fmt: format) -> result<list<u8>, error>;
    blur: func(img: image, radius: f32) -> result<image, error>;
}

world image-editor {
    import wasi:filesystem/types@0.2.0;
    export processor;
}

提示： WIT 的 package 声明使用类似 URL 的命名空间（如 my-org:image-processing@0.1.0），支持版本控制。发布 WIT 接口包类似于发布 npm 包或 Protobuf 定义。






组件可组合性
组件模型的核心价值在于声明式组合——将多个独立组件通过接口匹配连接成完整应用。


# 使用 wasm-tools 组合组件
wasm-tools compose \
  --config compose.yaml \
  main.wasm \
  -o composed.wasm
# compose.yaml
instantiations:
  image-lib:
    source: image-processor.wasm
  crypto-lib:
    source: crypto-utils.wasm
  main:
    source: app-logic.wasm
    arguments:
      processor: image-lib
      crypto: crypto-lib

// cargo-component 创建组件
// Cargo.toml
// [package.metadata.component]
// package = "my-org:image-lib"
//
// [package.metadata.component.target]
// world = "image-editor"

wit_bindgen::generate!({
    world: "image-editor",
    exports: {
        "my-org:image-processing/processor": ImageProcessor,
    },
});

struct ImageProcessor;

impl exports::my_org::image_processing::processor::Guest for ImageProcessor {
    fn resize(img: Image, width: u32, height: u32) -> Result<Image, Error> {
        Ok(img)
    }

    fn blur(img: Image, radius: f32) -> Result<Image, Error> {
        Ok(img)
    }

    fn convert(img: Image, fmt: Format) -> Result<Vec<u8>, Error> {
        Ok(vec![])
    }
}


提示： 组件模型的"语言无关"并非只是理论——Fermyon Spin 框架已经支持在同一个应用中混合使用 Rust、Go、Python 和 JavaScript 组件，每个组件处理不同的 HTTP 路由。






小结
    

  • 组件模型是 WASM 的下一代架构，让不同语言的模块通过WIT 接口定义直接互操作。
    • 

  • 每个组件拥有独立的线性内存，组件间数据交换由运行时负责，消除共享内存安全风险。
    • 

  • WIT 提供了 record、variant、result、list 等丰富的高级类型，直接映射到各语言原生类型。
    • 

  • wasm-tools compose 和 cargo-component 等工具支持声明式组件组合。
    • 

  • 组件模型让 Rust、Go、Python、JavaScript 的代码像乐高积木一样组合，无需 FFI 或 IPC。
