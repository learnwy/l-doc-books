服务端 WASM

核心概念

WASM 的价值不止于浏览器：服务端 WASM 的核心卖点是亚毫秒级冷启动、KB 级体积与强隔离。运行时层面，Wasmtime 和 Wasmer 是最成熟的两位选手，可嵌入 Rust/Go/Python 等宿主语言。框架层面，Spin 让每个 HTTP 请求跑在独立沙箱中；边缘计算平台（Cloudflare Workers、Fastly Compute）借它把计算下沉到全球节点。作为容器形态，WASM 容器体积以 KB 计、启动近于瞬时，已能与 Docker 相提并论。但要看清适用面：它适合无状态的计算密集型服务，复杂有状态服务仍应由传统容器承担。

Wasmtime 与 Wasmer 运行时

WASM 在服务端的运行依赖独立的运行时引擎。Wasmtime 和 Wasmer 是两个最成熟的选择。

# 安装 Wasmtime
curl https://wasmtime.dev/install.sh -sSf | bash

# 运行 WASI 程序
wasmtime run --dir /data my_program.wasm

# 安装 Wasmer
curl https://get.wasmer.io -sSfL | sh

# 运行 WASI 程序
wasmer run --dir /data my_program.wasm

// Rust 中嵌入 Wasmtime
use wasmtime::*;

fn main() -> anyhow::Result<()> {
    let engine = Engine::default();
    let module = Module::from_file(&engine, "my_program.wasm")?;

    let mut linker = Linker::new(&engine);
    wasmtime_wasi::add_to_linker(&mut linker, |s| s)?;

    let wasi = wasmtime_wasi::WasiCtxBuilder::new()
        .inherit_stdio()
        .preopened_dir("/host/data", "/data")?
        .build();

    let mut store = Store::new(&engine, wasi);
    let instance = linker.instantiate(&mut store, &module)?;

    let func = instance.get_typed_func::<(i32, i32), i32>(&mut store, "add")?;
    let result = func.call(&mut store, (3, 5))?;
    println!("3 + 5 = {}", result);

    Ok(())
}

提示： Wasmtime 的 Cranelift 编译器在代码质量和编译速度之间取得了很好的平衡。对于冷启动敏感的场景（如 Serverless），可以使用预编译模块（wasmtime compile）跳过运行时编译阶段。

Spin / Fermyon 框架

Spin 是 Fermyon 开发的 WASM 微服务框架，让开发者用 WASM 组件构建 HTTP 服务。

use spin_sdk::http::{IntoResponse, Request, Response};
use spin_sdk::http_component;

#[http_component]
fn handle_request(req: Request) -> anyhow::Result<impl IntoResponse> {
    let path = req.uri().path();

    match path {
        "/" => Ok(Response::builder()
            .status(200)
            .header("content-type", "text/html")
            .body("你好，WASM 世界！")?),
        "/api/data" => {
            let data = serde_json::json!({
                "message": "来自 WASM 的响应",
                "timestamp": chrono::Utc::now().to_rfc3339(),
            });
            Ok(Response::builder()
                .status(200)
                .header("content-type", "application/json")
                .body(data.to_string())?)
        }
        _ => Ok(Response::builder()
            .status(404)
            .body("Not Found")?),
    }
}

边缘计算：Cloudflare Workers

Cloudflare Workers 支持 WASM 模块，让计算在全球边缘节点执行。

use worker::*;

#[event(fetch)]
async fn main(req: Request, env: Env, _ctx: Context) -> Result<Response> {
    Router::new()
        .get_async("/api/process", |req, ctx| async move {
            let data = process_data().await;
            Response::ok(data)
        })
        .get("/health", |_, _| Response::ok("OK"))
        .run(req, env)
        .await
}

async fn process_data() -> String {
    let values: Vec<f64> = (0..1000).map(|i| (i as f64).sin()).collect();
    let sum: f64 = values.iter().sum();
    format!("计算结果: {:.6}", sum)
}

提示： Cloudflare Workers 的 WASM 模块大小限制为 1MB（免费套餐）或 10MB（付费套餐）。使用 wasm-opt -Oz 和 Brotli 压缩来控制体积。对于大型应用，考虑拆分为多个 Worker。

WASM 容器化

WASM 正在成为容器的轻量级替代方案。"如果 WASM 在 2008 年就存在，我们就不需要发明 Docker"——Docker 联合创始人 Solomon Hykes。

# 使用 Docker + WASM (需要 Docker Desktop 4.15+)
docker run --runtime=io.containerd.wasmtime.v1 \
  --platform=wasi/wasm \
  my-wasm-app

# Kubernetes + WASM (通过 SpinKube)
kubectl apply -f - <<EOF
apiVersion: core.spinoperator.dev/v1alpha1
kind: SpinApp
metadata:
  name: my-wasm-service
spec:
  image: ghcr.io/my-org/my-wasm-service:latest
  replicas: 3
EOF

提示： WASM 容器目前最适合计算密集型的无状态微服务。对于需要复杂网络栈、数据库驱动或系统库的服务，传统容器仍然是更实际的选择。两者不是替代关系，而是互补。

  • Wasmtime 和 Wasmer 是最成熟的服务端 WASM 运行时，支持嵌入 Rust/Go/Python 等宿主语言。
  • Spin 框架实现亚毫秒级冷启动的 HTTP 微服务，每个请求在独立沙箱中执行。
  • 边缘计算平台（Cloudflare Workers/Fastly Compute）利用 WASM 在全球节点实现超低延迟。
  • WASM 容器以 KB 级体积和亚毫秒启动挑战 Docker，Docker Desktop 已内置 WASM 运行时支持。
  • WASM 容器适合无状态计算密集型服务，复杂有状态服务仍建议使用传统容器。
