WASM GC 与未来

WASM GC 提案

WASM GC（Garbage Collection）提案为 WASM 引入了由宿主环境管理的引用类型和结构体，让带 GC 的语言（Java、Kotlin、Dart、Go）能更高效地编译到 WASM。

;; WASM GC 示例 (WAT)
(type $point (struct
  (field $x (mut f64))
  (field $y (mut f64))
))

(type $line (struct
  (field $start (ref $point))
  (field $end (ref $point))
))

(func $create_point (param $x f64) (param $y f64) (result (ref $point))
  (struct.new $point (local.get $x) (local.get $y))
)

(func $distance (param $p1 (ref $point)) (param $p2 (ref $point)) (result f64)
  (local $dx f64)
  (local $dy f64)
  (local.set $dx (f64.sub
    (struct.get $point $x (local.get $p1))
    (struct.get $point $x (local.get $p2))))
  (local.set $dy (f64.sub
    (struct.get $point $y (local.get $p1))
    (struct.get $point $y (local.get $p2))))
  (f64.sqrt (f64.add
    (f64.mul (local.get $dx) (local.get $dx))
    (f64.mul (local.get $dy) (local.get $dy))))
)


提示： Kotlin/WASM 和 Dart（Flutter Web）已经是 WASM GC 提案的主要受益者。Kotlin 团队报告编译到 WASM GC 后，输出体积比编译到 JS 小 50%，执行速度快 2 倍。






异常处理提案
WASM 异常处理（Exception Handling）提案为 WASM 引入了 try/catch/throw 机制，取代当前基于 trap 的错误处理。


;; 异常处理提案语法
(tag $my_error (param i32))

(func $might_fail (param $x i32) (result i32)
  (if (i32.lt_s (local.get $x) (i32.const 0))
    (then (throw $my_error (i32.const -1)))
  )
  (i32.mul (local.get $x) (i32.const 2))
)

(func $safe_call (param $x i32) (result i32)
  (try (result i32)
    (do
      (call $might_fail (local.get $x))
    )
    (catch $my_error
      (drop)
      (i32.const 0)
    )
  )
)

尾调用提案
尾调用（Tail Call）提案允许函数在调用另一个函数时复用当前栈帧，消除尾递归的栈溢出风险。


;; 尾调用：不增长栈帧的递归
(func $factorial_tail (param $n i64) (param $acc i64) (result i64)
  (if (result i64) (i64.le_s (local.get $n) (i64.const 1))
    (then (local.get $acc))
    (else
      (return_call $factorial_tail
        (i64.sub (local.get $n) (i64.const 1))
        (i64.mul (local.get $n) (local.get $acc))
      )
    )
  )
)

(func $factorial (param $n i64) (result i64)
  (call $factorial_tail (local.get $n) (i64.const 1))
)

提示： 尾调用提案对函数式语言（如 Haskell、OCaml、Scheme 编译到 WASM）至关重要。没有尾调用优化，这些语言的惯用递归模式会导致栈溢出。Chrome 和 Firefox 已支持此提案。

小结
    

  • GC 提案让 Java/Kotlin/Dart 等 GC 语言复用宿主 GC，输出体积减小 50%、性能提升 2 倍。
    • 

  • 异常处理提案引入 try/catch/throw，将 WASM 从"trap 终止"升级为可恢复的异常模型。
    • 

  • 尾调用提案通过 return_call 复用栈帧，消除尾递归的栈溢出风险。
    • 

  • 栈切换和线程提案将为 WASM 带来协程和真正的多线程能力。
    • 

  • WASM 标准由 W3C 社区组推进，多个提案从 Phase 1 到 Phase 4 并行快速演进。
