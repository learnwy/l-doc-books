WASI 基础

WASI 概述

WASI（WebAssembly System Interface）为 WASM 模块提供了与操作系统交互的标准化接口，将 WASM 的沙箱安全模型从浏览器扩展到服务端和边缘计算领域。

WIT 接口定义





use std::fs;
use std::io::{self, Read, Write};

fn main() {
    println!("WASI 程序启动");

    if let Ok(entries) = fs::read_dir("/data") {
        for entry in entries.flatten() {
            println!("文件: {:?}", entry.path());
        }
    }

    if let Ok(content) = fs::read_to_string("/data/config.toml") {
        println!("配置内容: {}", content);
    }

    let args: Vec<String> = std::env::args().collect();
    println!("命令行参数: {:?}", args);

    for (key, value) in std::env::vars() {
        println!("环境变量: {}={}", key, value);
    }
}


提示： WASI 程序使用标准的 Rust std 库 API（如 fs::read_to_string），但底层实现由 WASI 运行时提供。同一份 Rust 代码可以编译为原生二进制或 WASM+WASI 目标，实现跨平台一致性。






文件系统访问
WASI 的文件系统访问基于**预打开目录（Pre-opened Directories）**机制，模块只能访问宿主显式授权的目录。


# 使用 Wasmtime 运行，授予 /data 目录访问权
wasmtime run --dir /data::/host/data my_program.wasm

# 多个目录映射
wasmtime run \
  --dir /input::/host/input \
  --dir /output::/host/output \
  my_program.wasm
use std::fs;
use std::path::Path;

fn process_files() -> io::Result<()> {
    let input_dir = Path::new("/input");
    let output_dir = Path::new("/output");

    for entry in fs::read_dir(input_dir)? {
        let entry = entry?;
        let content = fs::read_to_string(entry.path())?;
        let processed = content.to_uppercase();
        let output_path = output_dir.join(entry.file_name());
        fs::write(output_path, processed)?;
    }
    Ok(())
}

时钟与随机数
WASI 提供确定性和非确定性两类系统服务，时钟和随机数是最常用的。


use std::time::{Instant, SystemTime, UNIX_EPOCH};

fn timing_example() {
    let start = Instant::now();

    let mut sum = 0u64;
    for i in 0..1_000_000 {
        sum += i;
    }

    let elapsed = start.elapsed();
    println!("计算耗时: {:?}", elapsed);

    let timestamp = SystemTime::now()
        .duration_since(UNIX_EPOCH)
        .unwrap()
        .as_millis();
    println!("当前时间戳: {}", timestamp);
}

fn random_example() {
    let mut buf = [0u8; 32];
    getrandom::getrandom(&mut buf).unwrap();
    println!("随机字节: {:?}", &buf[..8]);
}

环境变量与命令行参数
WASI 程序可以像传统命令行程序一样接收环境变量和命令行参数。


# 传递环境变量和参数
wasmtime run \
  --env API_KEY=secret123 \
  --env LOG_LEVEL=debug \
  my_program.wasm -- --input data.csv --output result.json
use std::env;

fn main() {
    let args: Vec<String> = env::args().collect();
    println!("程序名: {}", args[0]);
    println!("参数: {:?}", &args[1..]);

    match env::var("LOG_LEVEL") {
        Ok(level) => println!("日志级别: {}", level),
        Err(_) => println!("未设置日志级别，使用默认值"),
    }

    let config = AppConfig {
        api_key: env::var("API_KEY").unwrap_or_default(),
        log_level: env::var("LOG_LEVEL").unwrap_or_else(|_| "info".to_string()),
        input: args.get(1).cloned().unwrap_or_default(),
    };

    println!("配置: {:?}", config);
}

#[derive(Debug)]
struct AppConfig {
    api_key: String,
    log_level: String,
    input: String,
}

基于能力的安全模型
WASI 采用**基于能力（Capability-based）**的安全模型，与传统的基于身份（ACL）模型有本质区别。

# 最小权限原则示例
# 只读访问输入，只写访问输出
wasmtime run \
  --dir /input::/host/input:readonly \
  --dir /output::/host/output \
  my_program.wasm

# 完全隔离运行（无文件系统访问）
wasmtime run my_program.wasm

# 仅允许标准输入输出
wasmtime run --inherit-stdio my_program.wasm


提示： WASI 的安全模型遵循"默认拒绝"原则——如果你不显式授予文件系统访问权限，WASM 模块连 /tmp 都无法访问。这与 Docker 容器的"默认允许"策略形成鲜明对比，安全性更强。






小结
    

  • WASI 为 WASM 提供了标准化的系统接口，覆盖文件系统、时钟、随机数和环境变量。
    • 

  • 文件系统访问基于预打开目录机制，模块只能访问宿主显式授权的路径。
    • 

  • 时钟和随机数通过 WASI API 提供，某些运行时可以控制其确定性行为。
    • 

  • WASI 程序使用标准 Rust std API，同一份代码可编译为原生和 WASM 两种目标。
    • 

  • 基于能力的安全模型遵循最小特权原则，默认零权限，从根本上消除了路径遍历等安全隐患。
