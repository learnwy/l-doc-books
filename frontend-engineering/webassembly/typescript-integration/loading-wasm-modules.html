加载 WASM 模块

WebAssembly.instantiate vs instantiateStreaming

浏览器提供两组 API 来加载 WASM 模块，选择正确的 API 直接影响加载性能。

const importObject = {
  env: { log: (v: number) => console.log(v) },
};

const streamingResult = await WebAssembly.instantiateStreaming(fetch('/module.wasm'), importObject);
const { instance, module } = streamingResult;

const response = await fetch('/module.wasm');
const bytes = await response.arrayBuffer();
const bufferResult = await WebAssembly.instantiate(bytes, importObject);
API 输入 流式编译 缓存优化 推荐场景
instantiateStreaming Response/Promise ✅ 是 ✅ 是 浏览器首选
instantiate ArrayBuffer ❌ 否 ❌ 否 降级/Node.js
compileStreaming Response/Promise ✅ 是 ✅ 是 分离编译
compile ArrayBuffer ❌ 否 ❌ 否 降级方案 


提示： instantiateStreaming 要求服务器返回正确的 MIME 类型 Content-Type: application/wasm。如果你遇到 "Incorrect response MIME type" 错误，检查服务器配置或降级使用 instantiate。






Vite WASM 插件
Vite 对 WASM 的支持已经相当成熟，通过插件可以实现开箱即用的 WASM 集成。


// vite.config.ts
import { defineConfig } from 'vite';
import wasm from 'vite-plugin-wasm';
import topLevelAwait from 'vite-plugin-top-level-await';

export default defineConfig({
  plugins: [wasm(), topLevelAwait()],
  optimizeDeps: {
    exclude: ['my-wasm-lib'],
  },
});
// 方式 1: 通过插件直接导入
import init, { greet } from 'my-wasm-lib';
await init();
greet('Vite 用户');

// 方式 2: 使用 ?init 查询参数
import initWasm from './module.wasm?init';
const instance = await initWasm({
  env: { log: console.log },
});

// 方式 3: 使用 ?url 获取 URL
import wasmUrl from './module.wasm?url';
const { instance: inst } = await WebAssembly.instantiateStreaming(fetch(wasmUrl));

webpack WASM 支持
webpack 5 内置了 WASM 的实验性支持，也可以通过专用插件获得更好的体验。


// webpack.config.js
module.exports = {
  experiments: {
    asyncWebAssembly: true,
  },
  module: {
    rules: [
      {
        test: /\.wasm$/,
        type: 'webassembly/async',
      },
    ],
  },
};
// 异步导入
const wasmModule = await import('./compute.wasm');
const result = wasmModule.add(1, 2);

// 同步导入（需要 syncWebAssembly 实验性功能）
import { add } from './compute.wasm';
const result = add(1, 2);

提示： webpack 的 asyncWebAssembly 会将每个 WASM 文件作为独立的异步 chunk。如果你的应用有多个小 WASM 模块，考虑合并它们以减少网络请求数。






动态导入模式
在大型应用中，WASM 模块通常采用动态导入（Lazy Loading），只在需要时加载。


class WasmLoader {
  private instance: any = null;
  private loading: Promise<void> | null = null;

  async load(): Promise<void> {
    if (this.instance) return;
    if (this.loading) return this.loading;

    this.loading = (async () => {
      const module = await import('./pkg/heavy_compute.js');
      await module.default();
      this.instance = module;
    })();

    return this.loading;
  }

  async compute(data: Float64Array): Promise<Float64Array> {
    await this.load();
    return this.instance.compute(data);
  }
}

const loader = new WasmLoader();
button.addEventListener('click', async () => {
  const result = await loader.compute(inputData);
  render(result);
});

多模块协作
大型项目可能包含多个 WASM 模块，需要合理管理它们的加载和通信。


async function registerModule(name: string, loader: () => Promise<any>) {
  const mod = await loader();
  await mod.default();
  registry[name] = { init: mod.default, exports: mod };
}

await Promise.all([
  registerModule('image', () => import('./pkg/image_wasm.js')),
  registerModule('crypto', () => import('./pkg/crypto_wasm.js')),
]);

const sharedMemory = new WebAssembly.Memory({

小结
    

  • 始终优先使用 instantiateStreaming，它支持流式编译和浏览器编译缓存。
    • 

  • Vite 通过 vite-plugin-wasm 提供开箱即用的 WASM 支持，支持 ?init/?url 等多种导入方式。
    • 

  • webpack 5 通过 asyncWebAssembly 实验性配置支持异步 WASM 加载。
    • 

  • 大型应用应采用动态导入模式，结合预加载和 Service Worker 缓存优化加载体验。
    • 

  • 多模块场景可通过共享内存或模块注册表实现高效协作。
