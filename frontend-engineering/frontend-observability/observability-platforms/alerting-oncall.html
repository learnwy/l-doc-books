告警体系与 On-Call 实践

核心概念

告警体系是可观测性系统的「最后一公里」，将监控数据转化为可操作的通知，驱动工程师及时响应和修复问题。一个成熟的告警体系需要在「足够灵敏以发现问题」和「避免告警疲劳」之间取得平衡。过多的无效告警会让团队麻木，遗漏真正严重的问题。

告警规则设计
有效的告警规则需要结合阈值（静态/动态）、窗口（时间范围）和条件组合，避免单一指标的瞬时波动触发误报：


type AlertOperator = 'gt' | 'lt' | 'gte' | 'lte' | 'eq';
type AlertAggregation = 'avg' | 'max' | 'min' | 'sum' | 'p95' | 'p99' | 'count';

interface AlertRule {
  readonly id: string;
  readonly name: string;
  readonly description: string;
  readonly metric: string;
  readonly aggregation: AlertAggregation;
  readonly operator: AlertOperator;
  readonly threshold: number;
  readonly window: number;
  readonly evaluationInterval: number;
  readonly severity: 'P0' | 'P1' | 'P2' | 'P3';
  readonly filters: Readonly<Record<string, string>>;
  readonly muteWindows?: ReadonlyArray<MuteWindow>;
  readonly autoResolve?: boolean;
}

interface MuteWindow {
  readonly startHour: number;
  readonly endHour: number;
  readonly daysOfWeek: ReadonlyArray<number>;
  readonly reason: string;
}

interface AlertEvaluation {
  readonly rule: AlertRule;
  readonly currentValue: number;
  readonly threshold: number;
  readonly isTriggered: boolean;
  readonly timestamp: number;
}

const evaluateRule = (
  rule: AlertRule,
  dataPoints: ReadonlyArray<{ timestamp: number; value: number }>,
): AlertEvaluation => {
  const windowStart = Date.now() - rule.window * 1000;
  const windowData = dataPoints.filter((d) => d.timestamp >= windowStart);

  if (windowData.length === 0) {
    return { rule, currentValue: 0, threshold: rule.threshold, isTriggered: false, timestamp: Date.now() };
  }

  let aggregatedValue: number;
  const values = windowData.map((d) => d.value);

  switch (rule.aggregation) {
    case 'avg':
      aggregatedValue = values.reduce((a, b) => a + b, 0) / values.length;
      break;
    case 'max':
      aggregatedValue = Math.max(...values);
      break;
    case 'min':
      aggregatedValue = Math.min(...values);
      break;
    case 'sum':
      aggregatedValue = values.reduce((a, b) => a + b, 0);
      break;
    case 'p95': {
      const sorted = [...values].sort((a, b) => a - b);
      aggregatedValue = sorted[Math.floor(sorted.length * 0.95)];
      break;
    }
    case 'count':
      aggregatedValue = values.length;
      break;
    default:
      aggregatedValue = values[values.length - 1];
  }

  const compare = (val: number, op: AlertOperator, thresh: number): boolean => {
    switch (op) {
      case 'gt':
        return val > thresh;
      case 'lt':
        return val < thresh;
      case 'gte':
        return val >= thresh;
      case 'lte':
        return val <= thresh;
      case 'eq':
        return val === thresh;
    }
  };

  return {
    rule,
    currentValue: aggregatedValue,
    threshold: rule.threshold,
    isTriggered: compare(aggregatedValue, rule.operator, rule.threshold),
    timestamp: Date.now(),
  };
};

告警降噪与抑制
告警疲劳是可观测性系统的头号敌人。通过多种降噪策略减少无效告警：


interface NoiseReduction {
  readonly deduplication: DeduplicationConfig;
  readonly grouping: GroupingConfig;
  readonly throttle: ThrottleConfig;
  readonly correlation: CorrelationConfig;
}

interface DeduplicationConfig {
  readonly window: number;
  readonly keyFields: ReadonlyArray<string>;
}

interface GroupingConfig {
  readonly groupBy: ReadonlyArray<string>;
  readonly summaryTemplate: string;
}

interface ThrottleConfig {
  readonly maxAlertsPerHour: number;
  readonly cooldownPeriod: number;
}

interface CorrelationConfig {
  readonly correlateWith: ReadonlyArray<string>;
  readonly suppressIfCorrelated: boolean;
}

const createAlertPipeline = (config: NoiseReduction) => {
  const recentAlerts = new Map<string, number>();

  const shouldSend = (alert: AlertEvaluation): boolean => {
    const key = config.deduplication.keyFields.map((f) => (alert.rule as Record<string, unknown>)[f]).join(':');

    const lastSent = recentAlerts.get(key);
    const now = Date.now();

    if (lastSent && now - lastSent < config.throttle.cooldownPeriod * 1000) {
      return false;
    }

    const hourAlerts = Array.from(recentAlerts.values()).filter((t) => now - t < 3600000).length;

    if (hourAlerts >= config.throttle.maxAlertsPerHour) {
      return false;
    }

    recentAlerts.set(key, now);
    return true;
  };

  return { shouldSend };
};
On-Call 轮值实践
On-Call 制度是保障线上系统稳定性的组织保障。前端 On-Call 与后端有所不同，需要关注浏览器兼容性、CDN 可用性和第三方脚本等前端特有问题：


interface OnCallSchedule {
  readonly team: string;
  readonly rotation: ReadonlyArray<RotationEntry>;
  readonly escalationPolicy: EscalationPolicy;
  readonly handoffProtocol: HandoffProtocol;
}

interface RotationEntry {
  readonly engineer: string;
  readonly startDate: string;
  readonly endDate: string;
  readonly timezone: string;
}

interface EscalationPolicy {
  readonly levels: ReadonlyArray<{
    readonly timeout: number;
    readonly notifyGroup: string;
  }>;
}

interface HandoffProtocol {
  readonly checklistItems: ReadonlyArray<string>;
  readonly reportTemplate: string;
}

事故响应与复盘
每次 P0/P1 事故应遵循标准化的响应流程和事后复盘：


interface IncidentReport {
  readonly id: string;
  readonly title: string;
  readonly severity: 'P0' | 'P1';
  readonly timeline: ReadonlyArray<TimelineEntry>;
  readonly rootCause: string;
  readonly impact: IncidentImpact;
  readonly actionItems: ReadonlyArray<ActionItem>;
}

interface TimelineEntry {
  readonly timestamp: string;
  readonly action: string;
  readonly actor: string;
}

interface IncidentImpact {
  readonly duration: number;
  readonly affectedUsers: number;
  readonly affectedPages: ReadonlyArray<string>;
  readonly revenueImpact?: number;
}

interface ActionItem {
  readonly description: string;
  readonly owner: string;
  readonly deadline: string;
  readonly priority: 'high' | 'medium' | 'low';
  readonly status: 'open' | 'in_progress' | 'done';
}
小结
    

  • 告警体系将监控数据转化为可操作通知，分为 P0-P3 四个严重级别，各有不同的响应 SLA
    • 

  • 告警规则通过聚合方式（avg/p95/count）、时间窗口和阈值组合减少瞬时波动的误报
    • 

  • 告警降噪策略包括去重、分组、节流和关联抑制，防止告警疲劳
    • 

  • On-Call 轮值制度是保障线上稳定性的组织保障，交接时必须写 handoff 文档
    • 

  • 每次 P0/P1 事故必须进行事后复盘（RCA），产出 Action Items 防止同类问题复发
    • 

  • 告警配额预算（P0 ≤ 2/周，P1 ≤ 10/周）是衡量告警质量的关键指标
