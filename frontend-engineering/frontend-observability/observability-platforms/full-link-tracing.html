全链路追踪

核心概念

全链路追踪（Full-Link Tracing / Distributed Tracing）是将一次用户请求在前端、网关、后端微服务和数据库之间的完整调用链路可视化的技术。在微服务架构下，一次页面操作可能触发数十个跨服务 RPC 调用，当出现性能瓶颈或错误时，全链路追踪通过 Trace ID 将散落在不同服务中的日志和指标串联起来，精确定位问题所在的节点和阶段。

W3C Trace Context 标准
W3C Trace Context 是分布式追踪的标准协议，定义了两个 HTTP 头部：traceparent（必需）和 tracestate（可选）。traceparent 格式为 {version}-{trace-id}-{parent-id}-{trace-flags}，其中 trace-id 是 16 字节（32 个十六进制字符）的全局唯一标识，parent-id 是 8 字节的 Span 标识。


前端通过在 Fetch/XHR 请求中注入 traceparent 头部，将浏览器端的 Trace 信息传递给后端服务。后端服务解析该头部并在内部调用中继续传播，形成完整的调用链。


interface TraceContext {
  readonly version: string;
  readonly traceId: string;
  readonly spanId: string;
  readonly traceFlags: number;
  readonly traceState?: string;
}

interface Span {
  readonly traceId: string;
  readonly spanId: string;
  readonly parentSpanId: string | null;
  readonly operationName: string;
  readonly startTime: number;
  readonly endTime: number;
  readonly status: 'ok' | 'error' | 'timeout';
  readonly attributes: ReadonlyMap<string, string | number | boolean>;
  readonly events: ReadonlyArray<SpanEvent>;
}

interface SpanEvent {
  readonly name: string;
  readonly timestamp: number;
  readonly attributes: ReadonlyMap<string, string | number>;
}

function generateTraceId(): string {
  const bytes = new Uint8Array(16);
  crypto.getRandomValues(bytes);
  return Array.from(bytes, (b) => b.toString(16).padStart(2, '0')).join('');
}

function generateSpanId(): string {
  const bytes = new Uint8Array(8);
  crypto.getRandomValues(bytes);
  return Array.from(bytes, (b) => b.toString(16).padStart(2, '0')).join('');
}

function formatTraceparent(ctx: TraceContext): string {
  return `${ctx.version}-${ctx.traceId}-${ctx.spanId}-${ctx.traceFlags.toString(16).padStart(2, '0')}`;
}

function parseTraceparent(header: string): TraceContext | null {
  const parts = header.split('-');
  if (parts.length !== 4) return null;
  return {
    version: parts[0],
    traceId: parts[1],
    spanId: parts[2],
    traceFlags: parseInt(parts[3], 16),
  };
}
前端 Span 创建与上下文传播
前端全链路追踪的核心是为关键操作创建 Span，并通过 HTTP 头部将 Trace Context 传播给后端。典型的前端 Span 包括：页面导航 Span（从导航开始到页面加载完成）、API 请求 Span（从 fetch 发起到响应完成）、组件渲染 Span（React 组件从 render 到 commit）和用户交互 Span（从点击到 UI 更新完成）。


interface SpanManager {
  startSpan(name: string, options?: SpanOptions): ActiveSpan;
  getActiveSpan(): ActiveSpan | null;
  endSpan(span: ActiveSpan): void;
}

interface SpanOptions {
  readonly op: string;
  readonly parentSpan?: ActiveSpan;
  readonly attributes?: Record<string, string | number | boolean>;
}

interface ActiveSpan extends Span {
  setAttribute(key: string, value: string | number | boolean): void;
  addEvent(name: string, attributes?: Record<string, string | number>): void;
  end(): void;
}

function instrumentFetch(spanManager: SpanManager): void {
  const originalFetch = globalThis.fetch;

  globalThis.fetch = async (input, init) => {
    const url = typeof input === 'string' ? input : input.url;
    const span = spanManager.startSpan(`fetch ${new URL(url).pathname}`, {
      op: 'http.client',
      attributes: {
        'http.method': init?.method ?? 'GET',
        'http.url': url,
      },
    });

    const headers = new Headers(init?.headers);
    headers.set(
      'traceparent',
      formatTraceparent({
        version: '00',
        traceId: span.traceId,
        spanId: span.spanId,
        traceFlags: 1,
      }),
    );

    try {
      const response = await originalFetch(input, { ...init, headers });
      span.setAttribute('http.status_code', response.status);
      span.end();
      return response;
    } catch (error) {
      span.setAttribute('error', true);
      span.addEvent('exception', {
        'exception.message': error instanceof Error ? error.message : String(error),
      });
      span.end();
      throw error;
    }
  };
}

function instrumentNavigation(spanManager: SpanManager): void {
  const observer = new PerformanceObserver((list) => {
    for (const entry of list.getEntries()) {
      if (entry.entryType === 'navigation') {
        const navEntry = entry as PerformanceNavigationTiming;
        const span = spanManager.startSpan('page-load', {
          op: 'navigation',
          attributes: {
            'navigation.type': navEntry.type,
            'navigation.ttfb': navEntry.responseStart - navEntry.startTime,
            'navigation.dom_complete': navEntry.domComplete - navEntry.startTime,
            'navigation.load': navEntry.loadEventEnd - navEntry.startTime,
          },
        });
        span.end();
      }
    }
  });
  observer.observe({ type: 'navigation', buffered: true });
}
追踪数据可视化
追踪数据的可视化通常采用甘特图（Gantt Chart）形式，横轴为时间，每行为一个 Span。通过缩进和颜色编码展示父子关系和服务归属。好的追踪可视化需要支持：展开/折叠子 Span、按服务过滤、高亮慢 Span 和错误 Span、以及关联日志查看。

OpenTelemetry（OTel）正在成为全链路追踪的事实标准。OTel 定义了统一的 Trace/Metrics/Logs 数据模型和采集协议（OTLP），支持 Jaeger、Zipkin、Tempo 等多种后端。前端可以使用 @opentelemetry/sdk-trace-web 实现标准化的追踪数据采集。


interface OTelConfig {
  readonly serviceName: string;
  readonly serviceVersion: string;
  readonly collectorUrl: string;
  readonly propagators: ReadonlyArray<'w3c' | 'b3' | 'jaeger'>;
  readonly instrumentations: ReadonlyArray<string>;
  readonly sampleRate: number;
}

function createOTelConfig(appName: string, version: string, env: string): OTelConfig {
  return {
    serviceName: `frontend-${appName}`,
    serviceVersion: version,
    collectorUrl:
      env === 'production' ? 'https://otel-collector.internal/v1/traces' : 'http://localhost:4318/v1/traces',
    propagators: ['w3c'],
    instrumentations: ['fetch', 'document-load', 'user-interaction'],
    sampleRate: env === 'production' ? 0.1 : 1.0,
  };
}
小结
    

  • 全链路追踪通过 Trace ID 串联前端到后端的完整调用链路
    • 

  • W3C Trace Context 通过 traceparent 头部实现标准化的跨服务追踪传播
    • 

  • 前端通过 Fetch 拦截注入追踪头部，创建导航、API、交互等类型的 Span
    • 

  • OpenTelemetry 是全链路追踪的事实标准，统一了数据模型和采集协议
    • 

  • 追踪数据以甘特图形式可视化，支持 Span 展开/折叠和服务过滤
    • 

  • 采样率需要在数据完整性和成本之间权衡，生产环境推荐 0.1（10%）
    • 

  • 全链路追踪与日志和指标的关联（三大支柱统一）是可观测性的终极目标
