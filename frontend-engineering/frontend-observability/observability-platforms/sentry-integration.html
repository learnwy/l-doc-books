Sentry 深度集成

核心概念

Sentry 是前端领域最成熟的错误监控和性能追踪平台，提供从错误捕获、Source Map 解析到性能追踪的完整可观测性方案。深度集成 Sentry 不仅是引入 SDK 那么简单——它涉及 SDK 配置优化、自定义上下文注入、Release 管理、Source Map 上传流水线、性能采样策略和告警规则设计等多个维度。合理的 Sentry 集成能将平均故障响应时间（MTTR）从小时级降低到分钟级。

SDK 初始化与采样策略
Sentry SDK 的初始化配置决定了数据采集的范围和质量。核心配置包括：DSN（数据源名称，标识项目）、release（版本标识，关联 Source Map）、environment（环境标识，区分生产/测试）、tracesSampleRate（性能追踪采样率）和 beforeSend（发送前钩子，用于过滤和增强事件）。


interface SentryConfig {
  readonly dsn: string;
  readonly release: string;
  readonly environment: string;
  readonly tracesSampleRate: number;
  readonly replaysSessionSampleRate: number;
  readonly replaysOnErrorSampleRate: number;
  readonly profilesSampleRate: number;
  readonly maxBreadcrumbs: number;
  readonly ignoreErrors: ReadonlyArray<string | RegExp>;
  readonly denyUrls: ReadonlyArray<string | RegExp>;
  readonly beforeSend: (event: SentryEvent) => SentryEvent | null;
  readonly beforeSendTransaction: (transaction: SentryTransaction) => SentryTransaction | null;
}

interface SentryEvent {
  readonly event_id: string;
  readonly exception?: {
    readonly values: ReadonlyArray<{
      readonly type: string;
      readonly value: string;
      readonly stacktrace: {
        readonly frames: ReadonlyArray<{
          readonly filename: string;
          readonly function: string;
          readonly lineno: number;
          readonly colno: number;
          readonly in_app: boolean;
        }>;
      };
    }>;
  };
  readonly user?: Record<string, unknown>;
  readonly tags?: Record<string, string>;
  readonly extra?: Record<string, unknown>;
  readonly breadcrumbs?: ReadonlyArray<SentryBreadcrumb>;
  readonly release?: string;
  readonly environment?: string;
}

interface SentryTransaction {
  readonly name: string;
  readonly op: string;
  readonly duration: number;
  readonly status: string;
  readonly spans: ReadonlyArray<{
    readonly op: string;
    readonly description: string;
    readonly duration: number;
  }>;
}

interface SentryBreadcrumb {
  readonly type: string;
  readonly category: string;
  readonly message: string;
  readonly level: 'info' | 'warning' | 'error';
  readonly timestamp: number;
  readonly data?: Record<string, unknown>;
}

function createSentryConfig(env: 'production' | 'staging' | 'development', version: string): SentryConfig {
  const sampleRates: Record<string, { traces: number; replays: number }> = {
    production: { traces: 0.1, replays: 0.01 },
    staging: { traces: 1.0, replays: 0.1 },
    development: { traces: 1.0, replays: 0 },
  };

  const rates = sampleRates[env];

  return {
    dsn: 'configured-via-env',
    release: `app@${version}`,
    environment: env,
    tracesSampleRate: rates.traces,
    replaysSessionSampleRate: rates.replays,
    replaysOnErrorSampleRate: 1.0,
    profilesSampleRate: env === 'production' ? 0.05 : 0,
    maxBreadcrumbs: 50,
    ignoreErrors: ['ResizeObserver loop', /Loading chunk \d+ failed/, 'Non-Error promise rejection', /^Network Error$/],
    denyUrls: [/extensions\//i, /^chrome:\/\//i, /^moz-extension:\/\//i],
    beforeSend: (event) => scrubSensitiveData(event),
    beforeSendTransaction: (tx) => tx,
  };
}

function scrubSensitiveData(event: SentryEvent): SentryEvent {
  const sensitiveKeys = ['password', 'token', 'secret', 'authorization', 'cookie'];
  const scrubbed = { ...event };

  if (scrubbed.extra) {
    const cleanExtra: Record<string, unknown> = {};
    for (const [key, value] of Object.entries(scrubbed.extra)) {
      cleanExtra[key] = sensitiveKeys.some((sk) => key.toLowerCase().includes(sk)) ? '[Filtered]' : value;
    }
    (scrubbed as Record<string, unknown>).extra = cleanExtra;
  }

  return scrubbed;
}
Source Map 上传与 Release 管理
每次部署新版本时，需要将 Source Map 上传到 Sentry 并关联到对应的 release。Sentry CLI 的 sentry-cli releases files upload-sourcemaps 命令或 @sentry/vite-plugin 插件可以自动完成此流程。关键是确保 SDK 初始化时的 release 值与上传时的 release 值完全一致。


interface ReleaseConfig {
  readonly org: string;
  readonly project: string;
  readonly release: string;
  readonly sourceMapPaths: ReadonlyArray<string>;
  readonly urlPrefix: string;
  readonly deleteAfterUpload: boolean;
  readonly setCommits: boolean;
}

interface UploadResult {
  readonly release: string;
  readonly filesUploaded: number;
  readonly totalSize: number;
  readonly duration: number;
  readonly warnings: ReadonlyArray<string>;
}

interface VitePluginConfig {
  readonly org: string;
  readonly project: string;
  readonly authToken: string;
  readonly release: { readonly name: string };
  readonly sourcemaps: {
    readonly filesToDeleteAfterUpload: ReadonlyArray<string>;
  };
}

function createViteSentryConfig(version: string): VitePluginConfig {
  return {
    org: process.env.SENTRY_ORG ?? '',
    project: process.env.SENTRY_PROJECT ?? '',
    authToken: process.env.SENTRY_AUTH_TOKEN ?? '',
    release: { name: `app@${version}` },
    sourcemaps: {
      filesToDeleteAfterUpload: ['./dist/**/*.map'],
    },
  };
}

自定义上下文与面包屑
为了在排查错误时获得更多上下文，需要在 Sentry 事件中注入业务相关信息。Sentry 提供了三种上下文注入机制：Tags（索引化标签，可用于过滤和搜索）、Extra（附加数据，不索引）和 Breadcrumbs（面包屑，记录错误发生前的用户操作序列）。


面包屑自动采集包括：DOM 点击事件、console 输出、XHR/Fetch 请求和导航跳转。自定义面包屑可以记录关键业务操作（如加入购物车、提交表单），在排查错误时还原用户操作路径。


interface ContextConfig {
  readonly userIdExtractor: () => string | undefined;
  readonly businessTags: () => Record<string, string>;
  readonly breadcrumbConfig: {
    readonly captureConsole: boolean;
    readonly captureDOM: boolean;
    readonly captureXHR: boolean;
    readonly captureNavigation: boolean;
  };
}

function enrichContext(config: ContextConfig): void {
  const userId = config.userIdExtractor();
  if (userId) {
    setUser({ id: userId });
  }

  const tags = config.businessTags();
  for (const [key, value] of Object.entries(tags)) {
    setTag(key, value);
  }
}

function setUser(_user: { id: string }): void {}
function setTag(_key: string, _value: string): void {}

function addBusinessBreadcrumb(category: string, message: string, data?: Record<string, unknown>): void {
  addBreadcrumb({
    type: 'info',
    category,
    message,
    level: 'info',
    timestamp: Date.now() / 1000,
    data,
  });
}

function addBreadcrumb(_crumb: SentryBreadcrumb): void {}
小结
    

  • Sentry SDK 初始化需要合理配置采样率，生产环境 traces 推荐 0.1、replays 推荐 0.01
    • 

  • beforeSend 钩子是过滤噪音和脱敏敏感数据的核心防线
    • 

  • Source Map 上传必须与 SDK 的 release 值完全一致，推荐使用 Vite 插件自动化
    • 

  • Tags 用于可搜索的业务标签，Extra 用于调试数据，Breadcrumbs 还原操作路径
    • 

  • Session Replay 对排查 UI 问题极有价值，但采样率需严格控制
    • 

  • Release Health 追踪版本稳定性，结合 Git Commit 关联支持快速定位引入问题的代码
    • 

  • 完整的 Sentry 集成应覆盖 CI/CD 全流程，从构建上传到部署通知
    •
