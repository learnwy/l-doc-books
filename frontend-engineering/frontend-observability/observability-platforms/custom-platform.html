自建可观测平台

核心概念

自建可观测性平台是在组织内部构建端到端的前端监控基础设施，覆盖数据采集、传输、存储、分析和可视化的全链路。与 Sentry、Datadog 等 SaaS 平台相比，自建平台在数据安全性（数据不出境）、成本可控性（大规模场景下边际成本极低）和定制灵活性（贴合业务需求）方面具有明显优势，但也需要承担更高的开发和运维成本。

SDK 设计与数据采集
自建 SDK 的核心设计原则是：轻量（不影响页面性能）、可靠（不丢数据）、可扩展（支持插件机制）。SDK 通常采用内核 + 插件架构：内核负责生命周期管理、数据缓冲和上报调度，插件分别处理错误捕获、性能采集、用户行为追踪等。


interface SDKCore {
  readonly plugins: ReadonlyArray<SDKPlugin>;
  init(config: SDKConfig): void;
  use(plugin: SDKPlugin): void;
  report(event: MonitorEvent): void;
  flush(): Promise<void>;
}

interface SDKPlugin {
  readonly name: string;
  readonly type: 'error' | 'performance' | 'behavior' | 'custom';
  setup(core: SDKCore): void;
  teardown(): void;
}

interface SDKConfig {
  readonly appId: string;
  readonly endpoint: string;
  readonly sampleRate: number;
  readonly batchSize: number;
  readonly flushInterval: number;
  readonly maxRetries: number;
  readonly enableBeacon: boolean;
}

interface MonitorEvent {
  readonly type: 'error' | 'performance' | 'behavior' | 'custom';
  readonly timestamp: number;
  readonly sessionId: string;
  readonly pageUrl: string;
  readonly data: Record<string, unknown>;
}

function createSDKCore(config: SDKConfig): SDKCore {
  const plugins: SDKPlugin[] = [];
  const buffer: MonitorEvent[] = [];
  let timer: ReturnType<typeof setInterval> | null = null;

  const report = (event: MonitorEvent) => {
    if (Math.random() > config.sampleRate) return;
    buffer.push(event);
    if (buffer.length >= config.batchSize) {
      flush();
    }
  };

  const flush = async () => {
    if (buffer.length === 0) return;
    const batch = buffer.splice(0);
    await sendBatch(batch, config);
  };

  const init = () => {
    timer = setInterval(flush, config.flushInterval);
    addEventListener('visibilitychange', () => {
      if (document.visibilityState === 'hidden') {
        sendBeacon(buffer.splice(0), config);
      }
    });
  };

  const core: SDKCore = {
    plugins,
    init,
    use: (plugin: SDKPlugin) => {
      plugins.push(plugin);
      plugin.setup(core);
    },
    report,
    flush,
  };

  return core;
}

async function sendBatch(events: ReadonlyArray<MonitorEvent>, config: SDKConfig): Promise<void> {
  const payload = JSON.stringify(events);
  for (let attempt = 0; attempt < config.maxRetries; attempt++) {
    try {
      const response = await fetch(config.endpoint, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: payload,
        keepalive: true,
      });
      if (response.ok) return;
    } catch {
      await new Promise((r) => setTimeout(r, 1000 * (attempt + 1)));
    }
  }
}

function sendBeacon(events: ReadonlyArray<MonitorEvent>, config: SDKConfig): void {
  if (events.length === 0) return;
  const payload = JSON.stringify(events);
  navigator.sendBeacon(config.endpoint, payload);
}
数据传输与存储架构
数据从 SDK 到最终存储经历接入层、消息队列和存储引擎三个阶段。接入层（通常是 Nginx/API Gateway）负责接收 SDK 上报的数据，做基本校验后写入消息队列。消息队列（Kafka）作为缓冲层，解耦数据生产和消费，支持峰值流量的削峰填谷。


存储层的选型是自建平台最关键的技术决策。ClickHouse 因其列式存储、高压缩比和极快的聚合查询性能成为前端监控领域的主流选择。典型的数据模型按事件类型分表：错误事件表、性能事件表和行为事件表，使用 toYYYYMMDD(timestamp) 做分区。

  readonly engine: string;
  readonly partitionKey: string;

  readonly ttl: string;
  readonly columns: ReadonlyArray<{
    readonly name: string;

function createErrorEventSchema(): ClickHouseSchema {
  return {
    tableName: 'error_events',
    engine: 'MergeTree()',
    partitionKey: 'toYYYYMMDD(timestamp)',
    orderBy: ['app_id', 'timestamp', 'fingerprint'],
    ttl: 'timestamp + INTERVAL 90 DAY',
    columns: [
      { name: 'app_id', type: 'String', codec: 'ZSTD(1)' },
      { name: 'timestamp', type: 'DateTime64(3)' },
      { name: 'fingerprint', type: 'String', codec: 'ZSTD(1)' },
      { name: 'error_type', type: 'LowCardinality(String)' },
      { name: 'message', type: 'String', codec: 'ZSTD(1)' },
      { name: 'stack', type: 'String', codec: 'ZSTD(3)' },
      { name: 'url', type: 'String', codec: 'ZSTD(1)' },
      { name: 'user_id', type: 'String', codec: 'ZSTD(1)' },
      { name: 'release', type: 'LowCardinality(String)' },
      { name: 'environment', type: 'LowCardinality(String)' },
      { name: 'browser', type: 'LowCardinality(String)' },
      { name: 'os', type: 'LowCardinality(String)' },
      { name: 'tags', type: 'Map(String, String)' },
    ],
  };
}

实时分析与告警引擎
实时分析引擎负责在数据到达后秒级延迟内完成聚合计算和告警判定。基于 ClickHouse 的 Materialized View 或 Flink 的流处理作业，可以实时计算错误率、P95 响应时间、CLS 分布等关键指标。


告警引擎的核心是规则引擎和通知分发。规则定义了告警触发条件（如「5分钟内错误率超过 1%」或「LCP P75 超过 4秒」），匹配后通过 Webhook、钉钉、Slack 等渠道分发通知。


interface AlertEngine {
  readonly rules: ReadonlyArray<AlertRule>;
  evaluate(metrics: MetricsSnapshot): ReadonlyArray<AlertFiring>;
  notify(alerts: ReadonlyArray<AlertFiring>): Promise<void>;
}

interface MetricsSnapshot {
  readonly appId: string;
  readonly timestamp: number;
  readonly errorRate: number;
  readonly lcpP75: number;
  readonly clsP75: number;
  readonly inpP75: number;
  readonly activeUsers: number;
}

interface AlertRule {
  readonly id: string;
  readonly name: string;
  readonly metric: keyof MetricsSnapshot;
  readonly operator: 'gt' | 'lt' | 'gte' | 'lte';
  readonly threshold: number;
  readonly window: number;
  readonly severity: 'critical' | 'warning' | 'info';
  readonly channels: ReadonlyArray<string>;
}

interface AlertFiring {
  readonly ruleId: string;
  readonly ruleName: string;
  readonly currentValue: number;
  readonly threshold: number;
  readonly severity: string;
  readonly timestamp: number;
}

function evaluateRules(rules: ReadonlyArray<AlertRule>, snapshot: MetricsSnapshot): ReadonlyArray<AlertFiring> {
  const firings: AlertFiring[] = [];

  for (const rule of rules) {
    const value = snapshot[rule.metric] as number;
    const triggered =
      (rule.operator === 'gt' && value > rule.threshold) ||
      (rule.operator === 'gte' && value >= rule.threshold) ||
      (rule.operator === 'lt' && value < rule.threshold) ||
      (rule.operator === 'lte' && value <= rule.threshold);

    if (triggered) {
      firings.push({
        ruleId: rule.id,
        ruleName: rule.name,
        currentValue: value,
        threshold: rule.threshold,
        severity: rule.severity,
        timestamp: snapshot.timestamp,
      });
    }
  }

  return firings;
}
小结
    

  • 自建平台适合大规模、高安全要求和深度定制的场景
    • 

  • SDK 采用内核 + 插件架构，核心追求轻量和可靠
    • 

  • Beacon API 确保页面卸载时的数据不丢失
    • 

  • ClickHouse 是前端监控数据存储的首选，列式存储提供极高压缩比和聚合性能
    • 

  • 消息队列作为缓冲层解耦数据生产和消费
    • 

  • 实时告警基于 Materialized View 或流处理引擎，秒级延迟
    • 

  • 自建平台的总拥有成本（TCO）需要在月上报量超过亿级时才比 SaaS 划算
