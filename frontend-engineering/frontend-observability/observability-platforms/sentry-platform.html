Sentry 与错误监控平台

核心概念

Sentry 是前端错误监控领域最广泛使用的开源平台，它提供了从错误捕获、Source Map 解析、Issue 聚合到告警通知的完整工作流。Sentry 的核心价值在于将「某个页面报了个错」转化为「这个错误影响了多少用户、什么时候首次出现、堆栈指向哪行源码、用户当时在做什么」的可操作情报。

SDK 集成与配置
Sentry SDK 的集成遵循「尽早初始化」原则，在应用入口处配置后自动接管全局错误捕获和性能追踪：


interface SentryConfig {
  readonly dsn: string;
  readonly environment: 'production' | 'staging' | 'development';
  readonly release: string;
  readonly sampleRate: number;
  readonly tracesSampleRate: number;
  readonly replaysSessionSampleRate: number;
  readonly replaysOnErrorSampleRate: number;
  readonly integrations: ReadonlyArray<SentryIntegration>;
  readonly beforeSend?: (event: SentryEvent) => SentryEvent | null;
  readonly ignoreErrors?: ReadonlyArray<string | RegExp>;
}

interface SentryEvent {
  readonly exception?: {
    readonly values: ReadonlyArray<{
      readonly type: string;
      readonly value: string;
      readonly stacktrace?: { readonly frames: ReadonlyArray<StackFrame> };
    }>;
  };
  readonly tags: Readonly<Record<string, string>>;
  readonly user?: { readonly id: string; readonly email?: string };
  readonly breadcrumbs?: ReadonlyArray<Breadcrumb>;
  readonly contexts?: Readonly<Record<string, unknown>>;
}

interface SentryIntegration {
  readonly name: string;
  readonly setup: () => void;
}

const sentryConfig: SentryConfig = {
  dsn: 'https://key@sentry.example.com/1',
  environment: 'production',
  release: 'my-app@1.2.3',
  sampleRate: 1.0,
  tracesSampleRate: 0.1,
  replaysSessionSampleRate: 0.01,
  replaysOnErrorSampleRate: 1.0,
  integrations: [],
  beforeSend: (event) => {
    if (event.exception?.values?.some((e) => e.type === 'ChunkLoadError')) {
      return null;
    }
    return event;
  },
  ignoreErrors: ['ResizeObserver loop limit exceeded', /^Non-Error promise rejection/],
};
beforeSend 钩子是控制上报数据的关键拦截点。常见用途包括过滤已知的无害错误（如 ChunkLoadError、ResizeObserver 误报）和脱敏敏感信息。


Issue 管理与告警配置
Sentry 的 Issue 管理系统将相同指纹的错误聚合为一个 Issue，提供影响分析、趋势图和版本回归检测：


type IssueStatus = 'unresolved' | 'resolved' | 'ignored' | 'regressed';
type IssuePriority = 'critical' | 'high' | 'medium' | 'low';

interface SentryIssue {
  readonly id: string;
  readonly title: string;
  readonly culprit: string;
  readonly status: IssueStatus;
  readonly priority: IssuePriority;
  readonly firstSeen: string;
  readonly lastSeen: string;
  readonly count: number;
  readonly userCount: number;
  readonly assignee?: string;
  readonly platform: string;
  readonly tags: ReadonlyArray<{ readonly key: string; readonly value: string; readonly count: number }>;
}

interface AlertRule {
  readonly name: string;
  readonly conditions: ReadonlyArray<AlertCondition>;
  readonly actions: ReadonlyArray<AlertAction>;
  readonly frequency: number;
}

type AlertCondition =
  | { readonly type: 'event_frequency'; readonly value: number; readonly interval: string }
  | { readonly type: 'user_frequency'; readonly value: number; readonly interval: string }
  | { readonly type: 'first_seen' }
  | { readonly type: 'regression' };

type AlertAction =
  | { readonly type: 'slack'; readonly channel: string }
  | { readonly type: 'email'; readonly recipients: ReadonlyArray<string> }
  | { readonly type: 'webhook'; readonly url: string }
  | { readonly type: 'pagerduty'; readonly serviceKey: string };

Release 追踪与部署关联
Sentry 的 Release 功能将错误与代码版本关联，支持版本间的错误对比和回归检测。通过在 CI/CD 中上传 Source Map 和 commit 信息，可以在错误详情中直接跳转到对应的代码行：


interface ReleaseConfig {
  readonly version: string;
  readonly commits: ReadonlyArray<CommitInfo>;
  readonly sourceMapPaths: ReadonlyArray<string>;
  readonly deployEnvironment: string;
}

interface CommitInfo {
  readonly id: string;
  readonly author: string;
  readonly message: string;
  readonly timestamp: string;
  readonly files: ReadonlyArray<string>;
}

interface DeployInfo {
  readonly environment: string;
  readonly release: string;
  readonly timestamp: string;
  readonly url?: string;
}

const createReleaseWorkflow = (orgSlug: string, projectSlug: string) => {
  const apiBase = `https://sentry.io/api/0/organizations/${orgSlug}`;

  const createRelease = async (config: ReleaseConfig): Promise<void> => {
    await fetch(`${apiBase}/releases/`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        version: config.version,
        projects: [projectSlug],
        commits: config.commits,
      }),
    });
  };

  const uploadSourceMaps = async (
    version: string,
    files: ReadonlyArray<{ name: string; content: string }>,
  ): Promise<void> => {
    for (const file of files) {
      const formData = new FormData();
      formData.append('file', new Blob([file.content]), file.name);
      formData.append('name', `~/${file.name}`);

      await fetch(`${apiBase}/releases/${version}/files/`, {
        method: 'POST',
        body: formData,
      });
    }
  };

  const createDeploy = async (deploy: DeployInfo): Promise<void> => {
    await fetch(`${apiBase}/releases/${deploy.release}/deploys/`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(deploy),
    });
  };

  return { createRelease, uploadSourceMaps, createDeploy };
};

小结
    

  • Sentry 提供了从错误捕获到 Issue 管理的完整工作流，是前端错误监控的事实标准
    • 

  • SDK 集成遵循「尽早初始化」原则，beforeSend 钩子用于过滤无害错误和脱敏
    • 

  • Issue 聚合基于错误指纹，支持状态管理（unresolved → resolved → regressed）
    • 

  • Release 功能将错误与代码版本关联，CI/CD 中上传 Source Map 实现堆栈还原
    • 

  • 告警规则支持频率、用户数、新错误和回归四种触发条件
    • 

  • 小团队推荐 Sentry SaaS，大团队考虑自托管或自建，核心是 ROI 最大化
    •
