OpenTelemetry 前端集成

核心概念

OpenTelemetry（OTel）是 CNCF 主导的可观测性标准框架，提供了统一的 API、SDK 和数据格式来采集 Traces、Metrics 和 Logs 三类信号。在前端领域，OpenTelemetry JS SDK 可以将浏览器中的页面加载、用户交互和 API 调用生成标准化的 Span，并通过 OTLP 协议发送到任意兼容的后端（Jaeger、Zipkin、Grafana Tempo 等）。OTel 的最大价值在于打通前后端的全链路追踪。

SDK 架构与初始化
OpenTelemetry JS SDK 采用模块化架构，核心由 API 层、SDK 层和 Exporter 层组成。前端使用 @opentelemetry/sdk-trace-web 包提供浏览器环境的 Trace 实现：


interface OTelConfig {
  readonly serviceName: string;
  readonly serviceVersion: string;
  readonly environment: string;
  readonly collectorUrl: string;
  readonly samplingRatio: number;
  readonly propagators: ReadonlyArray<string>;
  readonly instrumentations: ReadonlyArray<string>;
}

interface TracerConfig {
  readonly name: string;
  readonly version: string;
}

interface SpanConfig {
  readonly name: string;
  readonly kind: 'INTERNAL' | 'CLIENT' | 'SERVER';
  readonly attributes: Readonly<Record<string, string | number | boolean>>;
}

const initOpenTelemetry = (config: OTelConfig): void => {
  const resource = {
    'service.name': config.serviceName,
    'service.version': config.serviceVersion,
    'deployment.environment': config.environment,
    'telemetry.sdk.name': 'opentelemetry-js',
    'telemetry.sdk.language': 'javascript',
  };

  const traceExporter = createOTLPExporter(config.collectorUrl);
  const spanProcessor = createBatchSpanProcessor(traceExporter);

  const tracerProvider = {
    resource,
    spanProcessor,
    sampler: createTraceIdRatioSampler(config.samplingRatio),
  };

  registerTracerProvider(tracerProvider);
  registerInstrumentations(config.instrumentations);
};

const createOTLPExporter = (url: string) => ({
  url: `${url}/v1/traces`,
  headers: { 'Content-Type': 'application/json' },
  send: async (spans: ReadonlyArray<SerializedSpan>): Promise<void> => {
    await navigator.sendBeacon(`${url}/v1/traces`, JSON.stringify({ resourceSpans: spans }));
  },
});

interface SerializedSpan {
  readonly traceId: string;
  readonly spanId: string;
  readonly parentSpanId?: string;
  readonly name: string;
  readonly kind: number;
  readonly startTimeUnixNano: string;
  readonly endTimeUnixNano: string;
  readonly attributes: ReadonlyArray<{ key: string; value: { stringValue?: string; intValue?: number } }>;
  readonly status: { code: number };
}
自动插桩与手动追踪
OTel 前端 SDK 提供了一系列自动插桩（Instrumentation）模块，无需修改业务代码即可生成 Span：


interface Instrumentation {
  readonly name: string;
  readonly enable: () => void;
  readonly disable: () => void;
}

const createFetchInstrumentation = (
  tracer: Tracer,
  options: {
    readonly ignoreUrls?: ReadonlyArray<string | RegExp>;
    readonly propagateTraceHeaders?: boolean;
  } = {},
): Instrumentation => {
  const originalFetch = window.fetch;
  let enabled = false;

  const enable = (): void => {
    if (enabled) return;
    enabled = true;

    window.fetch = async (input: RequestInfo | URL, init?: RequestInit): Promise<Response> => {
      const url = input instanceof Request ? input.url : input.toString();

      const shouldIgnore = options.ignoreUrls?.some((pattern) =>
        typeof pattern === 'string' ? url.includes(pattern) : pattern.test(url),
      );
      if (shouldIgnore) return originalFetch(input, init);

      const span = tracer.startSpan('HTTP GET', {
        kind: 'CLIENT',
        attributes: {
          'http.method': init?.method ?? 'GET',
          'http.url': url,
          'http.target': new URL(url).pathname,
        },
      });

      const headers = new Headers(init?.headers);
      if (options.propagateTraceHeaders !== false) {
        headers.set('traceparent', formatTraceParent(span));
      }

      try {
        const response = await originalFetch(input, { ...init, headers });
        span.setAttribute('http.status_code', response.status);
        span.setStatus(response.ok ? 'OK' : 'ERROR');
        span.end();
        return response;
      } catch (error) {
        span.setStatus('ERROR');
        span.recordException(error as Error);
        span.end();
        throw error;
      }
    };
  };

  const disable = (): void => {
    window.fetch = originalFetch;
    enabled = false;
  };

  return { name: 'fetch', enable, disable };
};

interface Tracer {
  readonly startSpan: (name: string, config: SpanConfig) => ActiveSpan;
}

interface ActiveSpan {
  readonly spanId: string;
  readonly traceId: string;
  readonly setAttribute: (key: string, value: string | number | boolean) => void;
  readonly setStatus: (status: 'OK' | 'ERROR') => void;
  readonly recordException: (error: Error) => void;
  readonly end: () => void;
}

const formatTraceParent = (span: ActiveSpan): string => {
  return `00-${span.traceId}-${span.spanId}-01`;
};
对于需要精确追踪的业务场景，可以使用手动插桩创建自定义 Span：


const traceUserAction = async <T>(
  tracer: Tracer,
  actionName: string,
  action: () => Promise<T>,
  attributes: Record<string, string> = {},
): Promise<T> => {
  const span = tracer.startSpan(actionName, {
    kind: 'INTERNAL',
    attributes: {
      'user.action': actionName,
      ...attributes,
    },
  });

  try {
    const result = await action();
    span.setStatus('OK');
    return result;
  } catch (error) {
    span.setStatus('ERROR');
    span.recordException(error as Error);
    throw error;
  } finally {
    span.end();
  }
};
W3C TraceContext 与前后端关联
OpenTelemetry 使用 W3C TraceContext 标准在前后端之间传播追踪上下文。当前端发起 API 请求时，SDK 自动将 traceparent 头注入请求，后端提取 TraceID 和 ParentSpanID 后创建子 Span，形成完整的分布式链路：


interface TraceContext {
  readonly version: string;
  readonly traceId: string;
  readonly parentSpanId: string;
  readonly traceFlags: string;
}

const parseTraceParent = (header: string): TraceContext | null => {
  const parts = header.split('-');
  if (parts.length !== 4) return null;

  return {
    version: parts[0],
    traceId: parts[1],
    parentSpanId: parts[2],
    traceFlags: parts[3],
  };
};

前后端统一使用 TraceID 后，可以在 Jaeger 或 Grafana Tempo 中查看从「用户点击按钮 → 前端 API 请求 → 后端处理 → 数据库查询 → 响应返回 → 前端渲染」的完整链路耗时分布。


小结
    

  • OpenTelemetry 是 CNCF 标准的可观测性框架，提供无厂商锁定的统一采集 API 和数据格式
    • 

  • 前端 SDK 通过自动插桩（fetch/XHR/DOM）和手动插桩相结合实现全面的 Trace 采集
    • 

  • W3C TraceContext（traceparent 头）打通前后端链路，形成完整的分布式追踪
    • 

  • OTLP 协议兼容 Jaeger、Zipkin、Grafana Tempo 等主流后端
    • 

  • navigator.sendBeacon 是前端 Span 导出的推荐传输方式
    • 

  • OpenTelemetry 前端成熟度不及 Sentry，推荐搭配使用：Sentry 负责错误，OTel 负责链路
    •
