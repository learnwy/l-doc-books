前端可观测性概述

核心概念

前端可观测性（Frontend Observability）是指在前端应用运行过程中，通过系统化地收集、分析和可视化日志（Logs）、指标（Metrics）和链路追踪（Traces）三类信号数据，实现对应用健康状态、用户体验和性能表现的全面洞察能力。与传统的前端监控相比，可观测性强调的是从被动告警转向主动诊断——不仅知道「出了什么问题」，更能回答「为什么出问题」和「影响了谁」。

从监控到可观测性的演进
传统前端监控聚焦于预定义的指标和告警规则，本质上是一种「已知问题」的检测系统。可观测性则从数据驱动的角度出发，通过高基数（High Cardinality）的维度标签和灵活的查询能力，支持对「未知问题」的探索式排查：


interface MonitoringEvent {
  readonly type: 'error' | 'performance' | 'behavior';
  readonly name: string;
  readonly value: number | string;
  readonly tags: Readonly<Record<string, string>>;
  readonly timestamp: number;
  readonly sessionId: string;
  readonly userId?: string;
}

interface ObservabilityContext {
  readonly traceId: string;
  readonly spanId: string;
  readonly parentSpanId?: string;
  readonly baggage: Readonly<Record<string, string>>;
}

const createObservabilitySDK = () => {
  const context: ObservabilityContext = {
    traceId: crypto.randomUUID(),
    spanId: crypto.randomUUID().slice(0, 16),
    baggage: {},
  };

  const buffer: Array<MonitoringEvent> = [];
  let flushTimer: ReturnType<typeof setTimeout> | null = null;

  const track = (event: Omit<MonitoringEvent, 'timestamp' | 'sessionId'>): void => {
    buffer.push({
      ...event,
      timestamp: Date.now(),
      sessionId: getSessionId(),
    });

    if (buffer.length >= 20) {
      flush();
    } else if (!flushTimer) {
      flushTimer = setTimeout(flush, 5000);
    }
  };

  const flush = async (): Promise<void> => {
    if (buffer.length === 0) return;
    const events = buffer.splice(0, buffer.length);
    flushTimer = null;

    try {
      await navigator.sendBeacon('/api/telemetry', JSON.stringify(events));
    } catch {
      events.forEach((e) => buffer.push(e));
    }
  };

  return { track, flush, context };
};

可观测性架构设计
一个完整的前端可观测性系统包括四个层次：数据采集层、数据传输层、数据存储与处理层、数据消费层：


interface TelemetryPipeline {
  readonly collector: DataCollector;
  readonly transport: DataTransport;
  readonly processor: DataProcessor;
  readonly exporter: DataExporter;
}

interface DataCollector {
  readonly captureError: (error: Error) => void;
  readonly captureMetric: (name: string, value: number, tags?: Record<string, string>) => void;
  readonly startSpan: (name: string) => Span;
}

interface Span {
  readonly spanId: string;
  readonly name: string;
  readonly startTime: number;
  readonly setAttribute: (key: string, value: string | number | boolean) => void;
  readonly end: () => void;
  readonly addEvent: (name: string, attributes?: Record<string, string>) => void;
}

interface DataTransport {
  readonly send: (payload: unknown) => Promise<void>;
  readonly strategy: 'beacon' | 'xhr' | 'fetch' | 'websocket';
  readonly batchSize: number;
  readonly flushInterval: number;
}

interface DataProcessor {
  readonly enrich: (event: MonitoringEvent) => MonitoringEvent;
  readonly sample: (event: MonitoringEvent) => boolean;
  readonly aggregate: (events: ReadonlyArray<MonitoringEvent>) => AggregatedMetric;
}

interface AggregatedMetric {
  readonly name: string;
  readonly count: number;
  readonly sum: number;
  readonly min: number;
  readonly max: number;
  readonly p50: number;
  readonly p95: number;
  readonly p99: number;
}

interface DataExporter {
  readonly exportMetrics: (metrics: ReadonlyArray<AggregatedMetric>) => Promise<void>;
  readonly exportTraces: (traces: ReadonlyArray<Span>) => Promise<void>;
  readonly exportLogs: (logs: ReadonlyArray<MonitoringEvent>) => Promise<void>;
}
数据传输是前端可观测性中最敏感的环节，需要在数据完整性和性能影响之间取得平衡。推荐使用 navigator.sendBeacon 作为默认传输方式，它在页面卸载时也能可靠地发送数据，且不会阻塞页面关闭。


采样与数据治理
前端应用的流量远大于后端服务，全量采集会产生巨大的数据存储成本。智能采样策略需要在数据完整性和成本之间找到平衡：


type SamplingStrategy =
  | { readonly type: 'fixed'; readonly rate: number }
  | { readonly type: 'dynamic'; readonly baseRate: number; readonly errorMultiplier: number }
  | { readonly type: 'priority'; readonly rules: ReadonlyArray<SamplingRule> };

interface SamplingRule {
  readonly condition: (event: MonitoringEvent) => boolean;
  readonly rate: number;
  readonly description: string;
}

const createSampler = (strategy: SamplingStrategy) => {
  const shouldSample = (event: MonitoringEvent): boolean => {
    switch (strategy.type) {
      case 'fixed':
        return Math.random() < strategy.rate;
      case 'dynamic': {
        const rate =
          event.type === 'error' ? Math.min(1, strategy.baseRate * strategy.errorMultiplier) : strategy.baseRate;
        return Math.random() < rate;
      }
      case 'priority': {
        const matchedRule = strategy.rules.find((r) => r.condition(event));
        return Math.random() < (matchedRule?.rate ?? 0.1);
      }
    }
  };

  return { shouldSample };
};

小结
    

  • 前端可观测性通过 Logs、Metrics、Traces 三支柱实现对应用状态的全面洞察
    • 

  • 从传统监控到可观测性的核心升级在于高基数维度标签和统一 TraceID 的全链路关联
    • 

  • 可观测性架构分为采集层、传输层、存储处理层和消费层，每层有独立的技术选型
    • 

  • navigator.sendBeacon 是前端数据上报的首选传输方式，页面卸载时也能可靠发送
    • 

  • 智能采样策略（动态采样/优先级采样）在数据成本和错误覆盖率之间取得平衡
    • 

  • 可观测性的终极目标是从被动告警转向主动诊断，回答「为什么出问题」和「影响了谁」
    •
