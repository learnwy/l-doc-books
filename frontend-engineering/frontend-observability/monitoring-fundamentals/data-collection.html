数据采集与上报策略

核心概念

数据采集是前端可观测性系统的第一道关卡，它决定了原始信号的质量和完整性。前端数据采集面临的独特挑战包括：浏览器环境的多样性、网络条件的不确定性、页面生命周期的复杂性以及对用户体验的零影响要求。一个优秀的采集系统需要做到「无感采集、可靠传输、智能上报」。

自动采集实现
自动采集通过 Monkey Patching 和 Event Listener 拦截浏览器原生 API，无需业务代码改造即可收集性能和错误数据：


interface AutoCollectorConfig {
  readonly captureErrors: boolean;
  readonly captureXHR: boolean;
  readonly captureFetch: boolean;
  readonly captureConsole: boolean;
  readonly captureNavigation: boolean;
}

const setupFetchInterceptor = (
  onRequest: (req: RequestInfo) => void,
  onResponse: (req: RequestInfo, res: Response, duration: number) => void,
  onError: (req: RequestInfo, err: Error) => void,
): void => {
  const originalFetch = window.fetch;

  window.fetch = async (input: RequestInfo | URL, init?: RequestInit): Promise<Response> => {
    const startTime = performance.now();
    const url = input instanceof Request ? input.url : input.toString();
    onRequest(url);

    try {
      const response = await originalFetch(input, init);
      const duration = performance.now() - startTime;
      onResponse(url, response.clone(), duration);
      return response;
    } catch (error) {
      onError(url, error as Error);
      throw error;
    }
  };
};

const setupErrorCapture = (
  onError: (error: { message: string; stack?: string; filename?: string; lineno?: number; colno?: number }) => void,
): void => {
  window.addEventListener('error', (event: ErrorEvent) => {
    onError({
      message: event.message,
      stack: event.error?.stack,
      filename: event.filename,
      lineno: event.lineno,
      colno: event.colno,
    });
  });

  window.addEventListener('unhandledrejection', (event: PromiseRejectionEvent) => {
    const reason = event.reason;
    onError({
      message: reason instanceof Error ? reason.message : String(reason),
      stack: reason instanceof Error ? reason.stack : undefined,
    });
  });
};

const setupResourceMonitor = (onResource: (entry: PerformanceResourceTiming) => void): PerformanceObserver => {
  const observer = new PerformanceObserver((list) => {
    list.getEntries().forEach((entry) => {
      onResource(entry as PerformanceResourceTiming);
    });
  });
  observer.observe({ type: 'resource', buffered: true });
  return observer;
};
数据上报传输
数据上报需要兼顾可靠性和性能。不同的传输方式适用于不同的场景：


type TransportMethod = 'beacon' | 'image' | 'fetch' | 'xhr';

interface TransportConfig {
  readonly endpoint: string;
  readonly method: TransportMethod;
  readonly batchSize: number;
  readonly flushInterval: number;
  readonly maxRetries: number;
  readonly compressThreshold: number;
}

interface TransportLayer {
  readonly send: (data: ReadonlyArray<unknown>) => Promise<boolean>;
  readonly flush: () => Promise<void>;
}

const createTransport = (config: TransportConfig): TransportLayer => {
  const queue: Array<unknown> = [];
  let timer: ReturnType<typeof setTimeout> | null = null;

  const compress = async (data: string): Promise<ArrayBuffer> => {
    const stream = new Blob([data]).stream();
    const compressedStream = stream.pipeThrough(new CompressionStream('gzip'));
    const reader = compressedStream.getReader();
    const chunks: Array<Uint8Array> = [];

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      chunks.push(value);
    }

    const totalLength = chunks.reduce((sum, chunk) => sum + chunk.length, 0);
    const result = new Uint8Array(totalLength);
    let offset = 0;
    chunks.forEach((chunk) => {
      result.set(chunk, offset);
      offset += chunk.length;
    });

    return result.buffer;
  };

  const transmit = async (payload: string): Promise<boolean> => {
    switch (config.method) {
      case 'beacon':
        return navigator.sendBeacon(config.endpoint, payload);
      case 'image': {
        const img = new Image();
        img.src = `${config.endpoint}?data=${encodeURIComponent(payload)}`;
        return true;
      }
      case 'fetch': {
        const body = payload.length > config.compressThreshold ? await compress(payload) : payload;
        const headers: Record<string, string> = { 'Content-Type': 'application/json' };
        if (body instanceof ArrayBuffer) {
          headers['Content-Encoding'] = 'gzip';
        }
        const response = await fetch(config.endpoint, {
          method: 'POST',
          headers,
          body,
          keepalive: true,
        });
        return response.ok;
      }
      default:
        return false;
    }
  };

  const send = async (data: ReadonlyArray<unknown>): Promise<boolean> => {
    queue.push(...data);

    if (queue.length >= config.batchSize) {
      return flush().then(() => true);
    }

    if (!timer) {
      timer = setTimeout(() => {
        flush();
      }, config.flushInterval);
    }

    return true;
  };

  const flush = async (): Promise<void> => {
    if (queue.length === 0) return;
    const batch = queue.splice(0, config.batchSize);
    timer = null;

    const payload = JSON.stringify(batch);
    let retries = 0;
    while (retries < config.maxRetries) {
      const success = await transmit(payload);
      if (success) return;
      retries++;
      await new Promise((r) => setTimeout(r, 1000 * Math.pow(2, retries)));
    }
    queue.unshift(...batch);
  };

  return { send, flush };
};

页面生命周期与数据完整性
前端数据采集的最大挑战之一是页面卸载时的数据丢失。用户关闭 Tab、导航离开、后台冻结等场景都可能导致未上报的数据丢失：


const setupLifecycleHooks = (transport: TransportLayer): void => {
  document.addEventListener('visibilitychange', () => {
    if (document.visibilityState === 'hidden') {
      transport.flush();
    }
  });

  window.addEventListener('pagehide', () => {
    transport.flush();
  });

  window.addEventListener('beforeunload', () => {
    transport.flush();
  });

  if ('onfreeze' in document) {
    (document as Document & { onfreeze: (() => void) | null }).onfreeze = () => {
      transport.flush();
    };
  }
};
Page Lifecycle API 定义了页面的六种状态（Active、Passive、Hidden、Frozen、Terminated、Discarded），采集系统需要在状态转换时触发数据上报。推荐在 visibilitychange 为 hidden 时执行 flush，这是保证数据完整性最可靠的时机。


小结
    

  • 前端数据采集分为自动采集（零侵入）、声明式埋点（低侵入）和命令式埋点（精确控制）三种模式
    • 

  • Fetch/XHR 拦截通过 Monkey Patching 实现，全局 Error 和 UnhandledRejection 事件捕获 JS 异常
    • 

  • sendBeacon + fetch(keepalive) 是最可靠的上报方式，支持页面卸载时发送
    • 

  • 数据批量上报（batch）和压缩传输（gzip）可有效降低网络开销
    • 

  • visibilitychange 为 hidden 是触发数据 flush 最可靠的时机，优于 beforeunload
    • 

  • 采集系统的设计原则：零侵入、可靠传输、批量上报、智能采样、页面卸载保障
    •
