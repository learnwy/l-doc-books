Resource Timing 分析

核心概念

Resource Timing API 是浏览器提供的资源加载性能度量接口，记录了页面中每个资源（JS、CSS、图片、字体、API 请求）从 DNS 查询到响应完成的完整时序信息。通过 Resource Timing 数据，前端性能监控系统可以精确定位哪些资源拖慢了页面加载、哪些 CDN 节点响应异常、哪些 API 调用存在性能瓶颈，从而驱动有针对性的性能优化。

数据采集与解析
performance.getEntriesByType('resource') 返回页面加载的所有资源的 PerformanceResourceTiming 对象。每个对象包含 20+ 个时间戳属性，记录了资源从发起请求到完成的全过程。需要注意的是，跨域资源默认只暴露有限的时间信息，服务端需要设置 Timing-Allow-Origin 头部才能获取完整时序。


interface ResourceTimingEntry {
  readonly name: string;
  readonly entryType: 'resource';
  readonly startTime: number;
  readonly duration: number;
  readonly initiatorType: string;
  readonly transferSize: number;
  readonly encodedBodySize: number;
  readonly decodedBodySize: number;
  readonly domainLookupStart: number;
  readonly domainLookupEnd: number;
  readonly connectStart: number;
  readonly connectEnd: number;
  readonly secureConnectionStart: number;
  readonly requestStart: number;
  readonly responseStart: number;
  readonly responseEnd: number;
  readonly serverTiming: ReadonlyArray<PerformanceServerTiming>;
}

interface ParsedResourceTiming {
  readonly url: string;
  readonly type: string;
  readonly dns: number;
  readonly tcp: number;
  readonly tls: number;
  readonly ttfb: number;
  readonly download: number;
  readonly total: number;
  readonly transferSize: number;
  readonly compressionRatio: number;
  readonly cached: boolean;
  readonly crossOriginBlocked: boolean;
}

function parseResourceTiming(entry: PerformanceResourceTiming): ParsedResourceTiming {
  const crossOriginBlocked = entry.requestStart === 0 && entry.responseStart === 0;

  return {
    url: entry.name,
    type: entry.initiatorType,
    dns: entry.domainLookupEnd - entry.domainLookupStart,
    tcp: entry.connectEnd - entry.connectStart,
    tls: entry.secureConnectionStart > 0 ? entry.connectEnd - entry.secureConnectionStart : 0,
    ttfb: crossOriginBlocked ? 0 : entry.responseStart - entry.requestStart,
    download: entry.responseEnd - entry.responseStart,
    total: entry.duration,
    transferSize: entry.transferSize,
    compressionRatio: entry.encodedBodySize > 0 ? entry.decodedBodySize / entry.encodedBodySize : 1,
    cached: entry.transferSize === 0 && entry.decodedBodySize > 0,
    crossOriginBlocked,
  };
}

function collectResourceTimings(): ReadonlyArray<ParsedResourceTiming> {
  const entries = performance.getEntriesByType('resource') as PerformanceResourceTiming[];
  return entries.map(parseResourceTiming);
}
瀑布图分析
资源瀑布图（Waterfall Chart）是资源加载性能分析的核心可视化工具。它以时间轴为横轴，每行显示一个资源的加载时序，通过颜色编码区分 DNS、TCP、TTFB、下载等阶段。瀑布图能直观地揭示资源加载的串行瓶颈和并行度。


分析瀑布图的关键模式包括：长 DNS 查询（新域名首次解析）、TCP 连接排队（浏览器连接数限制）、大 TTFB（服务端处理慢或 CDN 回源）和长下载时间（大文件或低带宽）。


interface WaterfallEntry {
  readonly url: string;
  readonly type: string;
  readonly phases: ReadonlyArray<{
    readonly name: string;
    readonly start: number;
    readonly end: number;
    readonly color: string;
  }>;
}

interface WaterfallAnalysis {
  readonly criticalPath: ReadonlyArray<string>;
  readonly bottlenecks: ReadonlyArray<{
    readonly resource: string;
    readonly phase: string;
    readonly duration: number;
    readonly suggestion: string;
  }>;
  readonly parallelism: number;
  readonly totalLoadTime: number;
}

function analyzeWaterfall(entries: ReadonlyArray<ParsedResourceTiming>): WaterfallAnalysis {
  const bottlenecks: WaterfallAnalysis['bottlenecks'] = [];

  for (const entry of entries) {
    if (entry.dns > 100) {
      bottlenecks.push({
        resource: entry.url,
        phase: 'DNS',
        duration: entry.dns,
        suggestion: '添加 dns-prefetch 或减少域名数量',
      });
    }
    if (entry.ttfb > 500) {
      bottlenecks.push({
        resource: entry.url,
        phase: 'TTFB',
        duration: entry.ttfb,
        suggestion: '优化服务端响应或检查 CDN 配置',
      });
    }
    if (entry.download > 1000 && entry.transferSize > 100_000) {
      bottlenecks.push({
        resource: entry.url,
        phase: 'Download',
        duration: entry.download,
        suggestion: '启用压缩、减小资源体积或使用 CDN',
      });
    }
  }

  const totalLoadTime = Math.max(...entries.map((e) => e.total), 0);

  return {
    criticalPath: identifyCriticalPath(entries),
    bottlenecks,
    parallelism: calculateParallelism(entries),
    totalLoadTime,
  };
}

function identifyCriticalPath(entries: ReadonlyArray<ParsedResourceTiming>): ReadonlyArray<string> {
  return entries
    .filter((e) => e.type === 'script' || e.type === 'css')
    .sort((a, b) => b.total - a.total)
    .slice(0, 5)
    .map((e) => e.url);
}

function calculateParallelism(entries: ReadonlyArray<ParsedResourceTiming>): number {
  if (entries.length === 0) return 0;
  const serialTime = entries.reduce((sum, e) => sum + e.total, 0);
  const wallTime = Math.max(...entries.map((e) => e.total));
  return wallTime > 0 ? serialTime / wallTime : 1;
}

Server Timing 与端到端追踪
Server Timing API 允许服务端通过 HTTP 响应头 Server-Timing 将后端处理时间暴露给前端监控。前端通过 entry.serverTiming 读取这些信息，实现从浏览器到服务端的端到端性能追踪。


典型的 Server Timing 信息包括：数据库查询时间、缓存命中/未命中、API 网关延迟和应用逻辑处理时间。结合 Resource Timing 的网络时序，可以精确区分性能问题出在网络传输还是服务端处理。


interface ServerTimingMetric {
  readonly name: string;
  readonly duration: number;
  readonly description: string;
}

interface EndToEndTiming {
  readonly resource: string;
  readonly networkTime: number;
  readonly serverTime: number;
  readonly serverBreakdown: ReadonlyArray<ServerTimingMetric>;
  readonly bottleneck: 'network' | 'server' | 'balanced';
}

function analyzeEndToEnd(
  entry: ParsedResourceTiming,
  serverTimings: ReadonlyArray<ServerTimingMetric>,
): EndToEndTiming {
  const networkTime = entry.dns + entry.tcp + entry.tls + entry.download;
  const serverTime = serverTimings.reduce((sum, st) => sum + st.duration, 0);

  return {
    resource: entry.url,
    networkTime,
    serverTime,
    serverBreakdown: serverTimings,
    bottleneck: serverTime > networkTime * 2 ? 'server' : networkTime > serverTime * 2 ? 'network' : 'balanced',
  };
}
小结
    

  • Resource Timing API 提供资源加载全链路的精确时序数据
    • 

  • 跨域资源需要 Timing-Allow-Origin 头部才能暴露完整时序
    • 

  • 瀑布图分析能直观定位 DNS、TTFB、下载等阶段的性能瓶颈
    • 

  • 关键资源的加载优化包括 dns-prefetch、preconnect、HTTP/2 和压缩
    • 

  • Server Timing API 打通前后端性能追踪，精确区分网络和服务端问题
    • 

  • 缓存命中可通过 transferSize === 0 且 decodedBodySize > 0 判断
    • 

  • 资源性能数据应聚合后按页面、域名和资源类型维度分析
