Web Vitals 深度解析

核心概念

Web Vitals 是 Google 提出的一组以用户为中心的性能指标，用于量化真实用户在页面上的加载体验、交互响应和视觉稳定性。2024 年起，Core Web Vitals 由三个核心指标组成：LCP（Largest Contentful Paint）衡量加载速度、INP（Interaction to Next Paint）衡量交互响应、CLS（Cumulative Layout Shift）衡量视觉稳定性。这三个指标直接影响 Google 搜索排名。

LCP 优化策略
LCP 衡量的是视口中最大可见内容元素的渲染时间。LCP 元素通常是图片（<img>）、视频（<video> 的海报帧）或包含大量文本的块级元素。优化 LCP 需要从资源发现、资源加载和渲染三个阶段入手：


interface LCPDiagnostic {
  readonly element: string;
  readonly renderTime: number;
  readonly loadTime: number;
  readonly size: number;
  readonly url?: string;
  readonly breakdown: {
    readonly ttfb: number;
    readonly resourceLoadDelay: number;
    readonly resourceLoadTime: number;
    readonly elementRenderDelay: number;
  };
}

const diagnoseLCP = (): Promise<LCPDiagnostic> => {
  return new Promise((resolve) => {
    const observer = new PerformanceObserver((list) => {
      const entries = list.getEntries();
      const lastEntry = entries[entries.length - 1] as PerformanceEntry & {
        readonly element?: Element;
        readonly renderTime: number;
        readonly loadTime: number;
        readonly size: number;
        readonly url?: string;
      };

      const navEntry = performance.getEntriesByType('navigation')[0] as PerformanceNavigationTiming;
      const ttfb = navEntry.responseStart;

      const resourceUrl = lastEntry.url;
      let resourceLoadDelay = 0;
      let resourceLoadTime = 0;
      if (resourceUrl) {
        const resourceEntry = performance.getEntriesByName(resourceUrl)[0] as PerformanceResourceTiming;
        if (resourceEntry) {
          resourceLoadDelay = resourceEntry.requestStart - ttfb;
          resourceLoadTime = resourceEntry.responseEnd - resourceEntry.requestStart;
        }
      }

      resolve({
        element: lastEntry.element?.tagName ?? 'unknown',
        renderTime: lastEntry.renderTime,
        loadTime: lastEntry.loadTime,
        size: lastEntry.size,
        url: lastEntry.url,
        breakdown: {
          ttfb,
          resourceLoadDelay,
          resourceLoadTime,
          elementRenderDelay:
            lastEntry.renderTime - (lastEntry.loadTime || ttfb + resourceLoadDelay + resourceLoadTime),
        },
      });
    });
    observer.observe({ type: 'largest-contentful-paint', buffered: true });
  });
};

INP 优化策略
INP 是 FID 的替代指标，它衡量的是整个页面生命周期内所有交互中最慢的那个（取 P98 分位数）从用户输入到下一帧绘制的总延迟。INP 的三个组成部分是：Input Delay（事件排队）、Processing Time（事件处理）和 Presentation Delay（渲染到屏幕）：


interface INPBreakdown {
  readonly interactionType: 'click' | 'keydown' | 'pointerdown';
  readonly inputDelay: number;
  readonly processingTime: number;
  readonly presentationDelay: number;
  readonly totalDuration: number;
  readonly target: string;
}

const measureINP = (callback: (breakdown: INPBreakdown) => void): void => {
  const observer = new PerformanceObserver((list) => {
    list.getEntries().forEach((entry) => {
      const eventEntry = entry as PerformanceEntry & {
        readonly interactionId: number;
        readonly processingStart: number;
        readonly processingEnd: number;
        readonly target?: Element;
      };
      if (!eventEntry.interactionId) return;

      callback({
        interactionType: entry.name as INPBreakdown['interactionType'],
        inputDelay: eventEntry.processingStart - entry.startTime,
        processingTime: eventEntry.processingEnd - eventEntry.processingStart,
        presentationDelay: entry.startTime + entry.duration - eventEntry.processingEnd,
        totalDuration: entry.duration,
        target: eventEntry.target?.tagName ?? 'unknown',
      });
    });
  });
  observer.observe({ type: 'event', buffered: true });
};
INP 优化的核心是减少主线程阻塞。当事件处理函数执行时间过长时，后续的交互事件只能排队等待，导致 Input Delay 飙升。使用 requestIdleCallback 和 scheduler.yield() 可以将长任务拆分为多个微任务：


const yieldToMain = (): Promise<void> => {
  if ('scheduler' in globalThis && 'yield' in (globalThis as { scheduler: { yield: () => Promise<void> } }).scheduler) {
    return (globalThis as { scheduler: { yield: () => Promise<void> } }).scheduler.yield();
  }
  return new Promise((resolve) => setTimeout(resolve, 0));
};

const processItemsWithYield = async <T>(
  items: ReadonlyArray<T>,
  processor: (item: T) => void,
  batchSize: number = 5,
): Promise<void> => {
  for (let i = 0; i < items.length; i += batchSize) {
    const batch = items.slice(i, i + batchSize);
    batch.forEach(processor);
    if (i + batchSize < items.length) {
      await yieldToMain();
    }
  }
};
CLS 诊断与修复
CLS 衡量页面生命周期内所有意外布局偏移的累积分数。布局偏移通常由动态插入的内容、延迟加载的图片/字体和 DOM 操作触发。CLS 使用「会话窗口」算法：连续布局偏移组成会话，取最大会话窗口的总分作为 CLS 值：


interface LayoutShiftEntry {
  readonly value: number;
  readonly hadRecentInput: boolean;
  readonly timestamp: number;
  readonly sources: ReadonlyArray<{
    readonly node: Element | null;
    readonly previousRect: DOMRect;
    readonly currentRect: DOMRect;
  }>;
}

interface CLSSession {
  readonly startTime: number;
  readonly endTime: number;
  readonly value: number;
  readonly entries: ReadonlyArray<LayoutShiftEntry>;
}

const trackCLS = (callback: (session: CLSSession) => void): void => {
  const sessions: Array<CLSSession> = [];
  let currentSession: CLSSession | null = null;

  const observer = new PerformanceObserver((list) => {
    list.getEntries().forEach((rawEntry) => {
      const entry = rawEntry as unknown as LayoutShiftEntry;
      if (entry.hadRecentInput) return;

      if (!currentSession || entry.timestamp - currentSession.endTime > 1000) {
        currentSession = {
          startTime: entry.timestamp,
          endTime: entry.timestamp,
          value: entry.value,
          entries: [entry],
        };
        sessions.push(currentSession);
      } else {
        currentSession = {
          ...currentSession,
          endTime: entry.timestamp,
          value: currentSession.value + entry.value,
          entries: [...currentSession.entries, entry],
        };
        sessions[sessions.length - 1] = currentSession;
      }

      const maxSession = sessions.reduce((max, s) => (s.value > max.value ? s : max), sessions[0]);
      callback(maxSession);
    });
  });
  observer.observe({ type: 'layout-shift', buffered: true });
};

小结
    

  • Core Web Vitals（LCP、INP、CLS）是以用户为中心的性能指标，P75 分位是评估标准
    • 

  • LCP 优化从资源发现（preload）、加载（CDN + 压缩）和渲染（消除阻塞）三个阶段入手
    • 

  • INP 优化核心是减少主线程阻塞，通过 scheduler.yield() 拆分长任务让出主线程
    • 

  • CLS 使用会话窗口算法计算，修复重点是为动态内容预留空间和避免字体闪烁
    • 

  • 所有指标应基于真实用户数据（RUM）而非实验室数据（Lighthouse）进行评估
    • 

  • Web Vitals 直接影响 Google 搜索排名，是前端性能优化的首要关注点
    •
