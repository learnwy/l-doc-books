React 状态方案

方案总览

React 生态中有众多状态管理方案，它们在 API 风格、性能特征、适用场景上各有不同。选型不应追求"最流行"，而应基于项目的实际复杂度和团队的技术背景。

Context + useReducer
React 内置的状态共享方案，无需额外依赖。适合数据量小、更新频率低的全局状态（如主题、语言偏好）。


// src/store/AuthContext.tsx
import { createContext, useContext, useReducer } from "react";

interface AuthState {
  user: { id: string; name: string; email: string } | null;
  isAuthenticated: boolean;
}

type AuthAction =
  | { type: "LOGIN"; user: AuthState["user"] }
  | { type: "LOGOUT" };

function authReducer(state: AuthState, action: AuthAction): AuthState {
  switch (action.type) {
    case "LOGIN":
      return { user: action.user, isAuthenticated: true };
    case "LOGOUT":
      return { user: null, isAuthenticated: false };
  }
}

const AuthContext = createContext<{
  state: AuthState;
  dispatch: React.Dispatch<AuthAction>;
} | null>(null);

function AuthProvider({ children }: { children: React.ReactNode }) {
  const [state, dispatch] = useReducer(authReducer, {
    user: null,
    isAuthenticated: false,
  });

  return (
    <AuthContext.Provider value={{ state, dispatch }}>
      {children}
    </AuthContext.Provider>
  );
}

function useAuth() {
  const context = useContext(AuthContext);
  if (!context) throw new Error("useAuth must be used within AuthProvider");
  return context;
}
Context 的性能陷阱
Context 的值变化时，所有消费该 Context 的组件都会重新渲染——即使它们只使用了 Context 中的部分数据。


解决方案：拆分 Context 或使用 Zustand 等外部状态库。




Zustand
Zustand 是目前 React 生态中最受欢迎的轻量级状态管理库。它的 API 极其简洁，没有 Provider、没有 Reducer、没有 Action Type——只有一个 Store 和 Hook。


基础用法
// src/store/useCounterStore.ts
import { create } from 'zustand';

interface CounterState {
  count: number;
  increment: () => void;
  decrement: () => void;
  reset: () => void;
}

const useCounterStore = create<CounterState>((set) => ({
  count: 0,
  increment: () => set((state) => ({ count: state.count + 1 })),
  decrement: () => set((state) => ({ count: state.count - 1 })),
  reset: () => set({ count: 0 }),
}));

export { useCounterStore };
function Counter() {
  const count = useCounterStore((state) => state.count);
  const increment = useCounterStore((state) => state.increment);

  return (
    <div>
      <p>{count}</p>
      <button onClick={increment}>+1</button>
    </div>
  );
}
Selector 与性能优化
Zustand 通过 selector 实现精确的订阅——组件只在它关心的数据变化时重新渲染。


// ✅ 精确订阅：只在 user 变化时重渲染
const user = useAuthStore((state) => state.user);

// ✅ 精确订阅：只在 isAuthenticated 变化时重渲染
const isAuthenticated = useAuthStore((state) => state.isAuthenticated);

// ❌ 全量订阅：store 任何变化都会重渲染
const store = useAuthStore();
实际项目中的 Store
// src/store/useAppStore.ts
import { create } from 'zustand';
import { persist } from 'zustand/middleware';
import { immer } from 'zustand/middleware/immer';

interface AppState {
  theme: 'light' | 'dark' | 'system';
  language: 'zh-CN' | 'en-US';
  sidebarCollapsed: boolean;
  setTheme: (theme: AppState['theme']) => void;
  setLanguage: (language: AppState['language']) => void;
  toggleSidebar: () => void;
}

const useAppStore = create<AppState>()(
  persist(
    immer((set) => ({
      theme: 'system',
      language: 'zh-CN',
      sidebarCollapsed: false,
      setTheme: (theme) =>
        set((state) => {
          state.theme = theme;
        }),
      setLanguage: (language) =>
        set((state) => {
          state.language = language;
        }),
      toggleSidebar: () =>
        set((state) => {
          state.sidebarCollapsed = !state.sidebarCollapsed;
        }),
    })),
    {
      name: 'app-settings',
      partialize: (state) => ({
        theme: state.theme,
        language: state.language,
      }),
    },
  ),
);


Jotai
Jotai 采用原子化（Atomic）的状态模型，每个状态片段是一个独立的 atom，组件按需订阅。


// src/store/atoms.ts
import { atom } from 'jotai';
import { atomWithStorage } from 'jotai/utils';

const themeAtom = atomWithStorage<'light' | 'dark' | 'system'>('theme', 'system');

const userAtom = atom<{ id: string; name: string } | null>(null);

const isAuthenticatedAtom = atom((get) => get(userAtom) !== null);

const userDisplayNameAtom = atom((get) => {
  const user = get(userAtom);
  return user?.name ?? '访客';
});
import { useAtom, useAtomValue } from "jotai";

function ThemeToggle() {
  const [theme, setTheme] = useAtom(themeAtom);

  return (
    <select value={theme} onChange={(e) => setTheme(e.target.value as any)}>
      <option value="light">亮色</option>
      <option value="dark">暗色</option>
      <option value="system">跟随系统</option>
    </select>
  );
}

function UserGreeting() {
  const displayName = useAtomValue(userDisplayNameAtom);
  return <span>你好，{displayName}</span>;
}


方案选型决策树


小结
    

  • 状态方案的选型取决于状态类型、更新频率和项目规模。
    • 

  • Context 适合少量低频全局数据，但有性能陷阱（全量重渲染）。
    • 

  • Zustand 是最受推荐的轻量级方案——API 极简、Selector 订阅精确、中间件丰富。
    • 

  • Jotai 的原子化模型适合需要细粒度状态管理的场景。
    • 

  • 服务端数据应使用 TanStack Query 而非客户端状态库管理。
