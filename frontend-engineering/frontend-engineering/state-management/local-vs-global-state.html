本地状态与全局状态

状态的分类

本地状态：组件的"私有数据"
本地状态是最简单也是最常用的状态形式。它只在单个组件内部使用，不需要与其他组件共享。


useState 的正确使用
function SearchInput() {
  const [query, setQuery] = useState("");
  const [isFocused, setIsFocused] = useState(false);

  return (
    <div className={isFocused ? "ring-2 ring-blue-500" : ""}>
      <input
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        onFocus={() => setIsFocused(true)}
        onBlur={() => setIsFocused(false)}
        placeholder="搜索..."
      />
      {query && (
        <button onClick={() => setQuery("")}>清除</button>
      )}
    </div>
  );
}
useReducer 处理复杂状态
当一个组件的状态逻辑复杂（多个相关联的状态字段、多种更新方式）时，useReducer 比 useState 更合适。


interface FormState {
  values: { email: string; password: string; name: string };
  errors: Record<string, string>;
  isSubmitting: boolean;
  isValid: boolean;
}

type FormAction =
  | { type: "SET_FIELD"; field: string; value: string }
  | { type: "SET_ERROR"; field: string; error: string }
  | { type: "CLEAR_ERRORS" }
  | { type: "SUBMIT_START" }
  | { type: "SUBMIT_SUCCESS" }
  | { type: "SUBMIT_FAILURE"; errors: Record<string, string> };

function formReducer(state: FormState, action: FormAction): FormState {
  switch (action.type) {
    case "SET_FIELD":
      return {
        ...state,
        values: { ...state.values, [action.field]: action.value },
        errors: { ...state.errors, [action.field]: "" },
      };
    case "SET_ERROR":
      return {
        ...state,
        errors: { ...state.errors, [action.field]: action.error },
        isValid: false,
      };
    case "CLEAR_ERRORS":
      return { ...state, errors: {}, isValid: true };
    case "SUBMIT_START":
      return { ...state, isSubmitting: true };
    case "SUBMIT_SUCCESS":
      return { ...state, isSubmitting: false };
    case "SUBMIT_FAILURE":
      return {
        ...state,
        isSubmitting: false,
        errors: action.errors,
        isValid: false,
      };
  }
}

function RegistrationForm() {
  const [state, dispatch] = useReducer(formReducer, {
    values: { email: "", password: "", name: "" },
    errors: {},
    isSubmitting: false,
    isValid: true,
  });

  const handleChange = (field: string, value: string) => {
    dispatch({ type: "SET_FIELD", field, value });
  };

  return (
    <form>
      <input
        value={state.values.email}
        onChange={(e) => handleChange("email", e.target.value)}
      />
      {state.errors.email && <span>{state.errors.email}</span>}
    </form>
  );
}


全局状态：跨组件共享
全局状态是需要在多个不相关组件之间共享的数据。关键判断标准：如果数据只被父子组件链使用，用 props 传递即可；只有真正需要跨越组件树边界共享的数据，才需要全局状态。


过度使用全局状态的反模式
// ❌ 反模式：所有状态都放全局
const useGlobalStore = create((set) => ({
  searchQuery: '',
  isModalOpen: false,
  selectedTab: 'overview',
  tooltipPosition: { x: 0, y: 0 },
  formDraft: {},
}));
上面的 Store 中，searchQuery、isModalOpen、selectedTab 和 tooltipPosition 很可能都是本地状态——它们只被一两个组件使用，完全没有必要放到全局。


// ✅ 正确：只有真正需要跨组件共享的状态
const useAuthStore = create((set) => ({
  user: null,
  isAuthenticated: false,
}));

const useThemeStore = create((set) => ({
  theme: 'system' as 'light' | 'dark' | 'system',
}));


URL 状态管理
URL 是前端应用中经常被忽视的状态容器。搜索条件、分页参数、筛选状态等数据放在 URL 中，可以实现：


    

  • 页面刷新后状态保持
    • 

  • 可分享的链接
    • 

  • 浏览器前进/后退导航
    • 



// 使用 nuqs 库管理 URL 状态
import { useQueryState, parseAsInteger, parseAsString } from "nuqs";

function UserListPage() {
  const [search, setSearch] = useQueryState("q", parseAsString.withDefault(""));
  const [page, setPage] = useQueryState("page", parseAsInteger.withDefault(1));
  const [sort, setSort] = useQueryState(
    "sort",
    parseAsString.withDefault("name")
  );

  const { data } = useQuery({
    queryKey: ["users", { search, page, sort }],
    queryFn: () => fetchUsers({ search, page, sort }),
  });

  return (
    <div>
      <input
        value={search}
        onChange={(e) => {
          setSearch(e.target.value);
          setPage(1);
        }}
        placeholder="搜索用户..."
      />
      <UserTable data={data?.users ?? []} />
      <Pagination
        current={page}
        total={data?.total ?? 0}
        onChange={setPage}
      />
    </div>
  );
}


状态提升与状态下沉
状态提升（Lifting State Up）
当两个兄弟组件需要共享状态时，将状态提升到它们的共同父组件。


function ProductPage() {
  const [selectedColor, setSelectedColor] = useState("red");

  return (
    <div>
      <ProductImage color={selectedColor} />
      <ColorPicker
        selected={selectedColor}
        onChange={setSelectedColor}
      />
    </div>
  );
}
状态下沉（Pushing State Down）
如果某个状态只被组件树中较深层的组件使用，将它从父组件移到实际使用它的组件内部。




小结
    

  • 状态分为四类：本地 UI 状态、共享客户端状态、服务端状态和 URL 状态。
    • 

  • 本地状态使用 useState / useReducer，只在组件内部管理。
    • 

  • 全局状态只用于真正需要跨组件树共享的数据——过度使用全局状态是常见反模式。
    • 

  • URL 状态适合搜索、分页、筛选等需要持久化和分享的场景。
    • 

  • "状态提升"和"状态下沉"是调整状态位置的两个基本手段。
