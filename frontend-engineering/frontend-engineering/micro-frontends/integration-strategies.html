构建时集成
构建时集成是最简单的"微前端"——将每个模块作为 npm 包发布，在 Shell 应用中作为依赖安装。


{
  "name": "@myapp/shell",
  "dependencies": {
    "@myapp/dashboard": "^2.1.0",
    "@myapp/settings": "^1.3.0",
    "@myapp/reports": "^3.0.0"
  }
}
// Shell 应用
import { DashboardPage } from "@myapp/dashboard";
import { SettingsPage } from "@myapp/settings";
import { ReportsPage } from "@myapp/reports";

function App() {
  return (
    <Routes>
      <Route path="/dashboard/*" element={<DashboardPage />} />
      <Route path="/settings/*" element={<SettingsPage />} />
      <Route path="/reports/*" element={<ReportsPage />} />
    </Routes>
  );
}
优势：无运行时开销、类型安全、最佳性能。


劣势：无法独立部署——每次更新子模块都需要重新构建 Shell。


适用场景
    

  • Monorepo 中的内部包共享
    • 

  • 对独立部署无需求的项目
    • 

  • 性能要求极高的 C 端应用
    • 





iframe 集成
iframe 提供了最强的隔离性——样式、JavaScript、DOM 完全隔离。


// Shell 应用
interface MicroFrontendConfig {
  name: string;
  url: string;
  path: string;
}

const microFrontends: MicroFrontendConfig[] = [
  { name: "dashboard", url: "https://dashboard.example.com", path: "/dashboard" },
  { name: "settings", url: "https://settings.example.com", path: "/settings" },
];

function IframeMicroFrontend({ url }: { url: string }) {
  return (
    <iframe
      src={url}
      style={{
        width: "100%",
        height: "calc(100vh - 64px)",
        border: "none",
      }}
      sandbox="allow-scripts allow-same-origin allow-forms allow-popups"
      title="Micro Frontend"
    />
  );
}
iframe 间通信
// Shell -> iframe 通信
const iframe = document.querySelector('iframe');
iframe?.contentWindow?.postMessage(
  { type: 'THEME_CHANGE', payload: { theme: 'dark' } },
  'https://dashboard.example.com',
);

// iframe -> Shell 通信
window.parent.postMessage({ type: 'NAVIGATE', payload: { path: '/settings' } }, 'https://shell.example.com');

// Shell 监听消息
window.addEventListener('message', (event) => {
  if (event.origin !== 'https://dashboard.example.com') return;

  const { type, payload } = event.data;
  switch (type) {
    case 'NAVIGATE':
      router.push(payload.path);
      break;
    case 'NOTIFICATION':
      showNotification(payload.message);
      break;
  }
});
优势：完全隔离，技术栈完全无关。


劣势：性能开销大、SEO 不友好、通信复杂、移动端体验差。




Web Components 集成
Web Components 提供了浏览器原生的组件封装机制，Shadow DOM 实现样式隔离。


// 微前端 A：定义 Web Component
class DashboardElement extends HTMLElement {
  private root: ShadowRoot;

  constructor() {
    super();
    this.root = this.attachShadow({ mode: 'open' });
  }

  connectedCallback() {
    const container = document.createElement('div');
    this.root.appendChild(container);

    import('react-dom/client').then(({ createRoot }) => {
      import('react').then((React) => {
        import('./DashboardApp').then(({ DashboardApp }) => {
          const root = createRoot(container);
          root.render(React.createElement(DashboardApp));
        });
      });
    });
  }

  disconnectedCallback() {
    this.root.innerHTML = '';
  }
}

customElements.define('mf-dashboard', DashboardElement);
<!-- Shell 应用中使用 -->
<mf-dashboard></mf-dashboard>


JavaScript 运行时加载
通过动态加载 JavaScript bundle 并执行挂载函数，是一种灵活的自定义集成方式。


// 微前端接口约定
interface MicroFrontendLifecycle {
  bootstrap(): Promise<void>;
  mount(container: HTMLElement, props: Record<string, unknown>): Promise<void>;
  unmount(): Promise<void>;
}

// Shell 应用加载器
async function loadMicroFrontend(name: string, url: string, container: HTMLElement): Promise<MicroFrontendLifecycle> {
  const module = await import(/* webpackIgnore: true */ url);
  const lifecycle = module.default as MicroFrontendLifecycle;

  await lifecycle.bootstrap();
  await lifecycle.mount(container, {
    basePath: `/${name}`,
    eventBus: globalEventBus,
    theme: currentTheme,
  });

  return lifecycle;
}
// 微前端导出
// apps/dashboard/src/entry.ts
import { createRoot, type Root } from "react-dom/client";
import { DashboardApp } from "./DashboardApp";

let root: Root | null = null;

export default {
  async bootstrap() {
    console.log("[Dashboard] bootstrapped");
  },

  async mount(container: HTMLElement, props: Record<string, unknown>) {
    root = createRoot(container);
    root.render(<DashboardApp {...props} />);
  },

  async unmount() {
    root?.unmount();
    root = null;
  },
};

渐进式迁移策略
从单体到微前端的迁移不应该是一次性的"大重写"，而应该是渐进式的"绞杀者模式"（Strangler Fig Pattern）。


迁移步骤
    

  1. 引入 Shell 应用：创建一个 Shell 应用作为入口，通过路由将流量分发到旧单体应用
    2. 

  2. 抽取第一个微前端：选择边界最清晰、耦合最少的模块作为第一个微前端
    3. 

  3. 逐步迁移：按模块逐步将功能从单体应用迁移到独立的微前端
    4. 

  4. 废弃单体：当所有模块迁移完成后，下线旧的单体应用
    5. 



选择第一个迁移模块的标准




标准
说明





业务边界清晰
与其他模块的数据和功能交叉最少




团队归属明确
有独立的团队负责维护




变更频率高
频繁迭代的模块最能从独立部署中受益




风险可控
非核心业务路径，即使出问题影响范围有限







小结
    

  • 微前端集成方式包括构建时集成、Module Federation、iframe、Web Components 和 JS 运行时加载。
    • 

  • 构建时集成最简单，但不支持独立部署；Module Federation 是同技术栈的最佳选择。
    • 

  • iframe 提供最强隔离但性能较差；Web Components 是跨框架集成的原生方案。
    • 

  • 从单体到微前端应采用渐进式迁移（绞杀者模式），而非一次性重写。
    • 

  • 选择第一个迁移模块时，优先选择边界清晰、变更频率高、风险可控的模块。
    •
