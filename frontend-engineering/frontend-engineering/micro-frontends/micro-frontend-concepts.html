微前端概念

什么是微前端

微前端（Micro Frontends）是一种架构模式，将一个大型前端应用拆分为多个较小的、可独立开发和部署的前端应用。每个微前端拥有自己的代码库、技术栈选择、构建流程和部署周期。

微前端的核心价值在于团队自治——每个团队可以独立选择技术栈、独立开发迭代、独立测试部署，不受其他团队的阻塞。

构建速度
随代码量增长持续恶化
每个微前端独立构建，耗时可控







适用场景
微前端并不适合所有项目。引入微前端架构会增加显著的工程复杂度，只有当收益超过成本时才值得采用。


适合微前端的场景
    

  • 大型企业应用：多个业务团队各自负责不同的功能模块
    • 

  • 渐进式迁移：从旧技术栈（如 jQuery/Angular.js）逐步迁移到新技术栈
    • 

  • 收购/合并：需要将不同公司的前端产品整合到统一入口
    • 

  • 平台型产品：核心平台 + 可插拔的功能模块
    • 



不适合微前端的场景
    

  • 小型团队（< 5 人）开发的应用
    • 

  • 单一技术栈、紧密耦合的业务逻辑
    • 

  • 追求极致性能的 C 端产品
    • 

  • 没有独立部署需求的项目
    • 





微前端的核心挑战
样式隔离
不同微前端的 CSS 可能产生冲突。


解决方案：


    

  • CSS Modules / CSS-in-JS（作用域隔离）
    • 

  • Shadow DOM（完全隔离）
    • 

  • BEM 命名 + 前缀约定
    • 

  • Tailwind CSS（原子化，无冲突风险）
    • 



状态共享
微前端之间需要有限度的数据共享，但不能产生紧耦合。


// 发布-订阅模式
interface MicroFrontendEvent {
  type: string;
  payload: unknown;
}

class EventBus {
  private listeners = new Map<string, Set<(event: MicroFrontendEvent) => void>>();

  emit(event: MicroFrontendEvent) {
    this.listeners.get(event.type)?.forEach((listener) => listener(event));
  }

  on(type: string, listener: (event: MicroFrontendEvent) => void) {
    if (!this.listeners.has(type)) {
      this.listeners.set(type, new Set());
    }
    this.listeners.get(type)!.add(listener);
    return () => this.listeners.get(type)?.delete(listener);
  }
}

const eventBus = new EventBus();

// 微前端 A：发送事件
eventBus.emit({ type: 'USER_LOGIN', payload: { userId: '123' } });

// 微前端 B：监听事件
eventBus.on('USER_LOGIN', (event) => {
  console.log('用户已登录:', event.payload);
});

小结
    

  • 微前端的核心价值是团队自治和独立部署。
    • 

  • 适合大型多团队应用、渐进式迁移和平台型产品。
    • 

  • 核心挑战包括样式隔离、状态共享、路由协调和共享依赖。
    • 

  • 微前端不是银弹——小团队/小项目应优先考虑 Monorepo 模块化方案。
    • 

  • 架构决策需要在团队自治、用户体验和工程复杂度之间找到平衡。
