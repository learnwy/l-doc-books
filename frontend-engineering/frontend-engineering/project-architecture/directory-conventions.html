目录约定

目录结构的价值

目录结构是代码库的"建筑蓝图"。一个清晰、一致的目录约定能够让团队成员在不阅读一行代码的情况下，就能理解项目的模块划分、功能边界和依赖方向。它是团队协作中最基础的"无声契约"。



应用层目录结构
Feature-Based 结构（推荐）
Feature-Based 目录结构以业务功能为维度组织代码，每个 feature 目录内包含该功能所需的所有文件——组件、hooks、工具函数、类型定义、测试等。


src/
├── app/                          # 应用入口与路由配置
│   ├── layout.tsx
│   ├── page.tsx
│   └── providers.tsx
├── features/                     # 业务功能模块
│   ├── auth/

依赖方向规则
Feature-Based 结构的核心约束是依赖方向：features 之间不能直接互相引用，只能通过 shared 层共享代码。


可以通过 ESLint 的 import/no-restricted-paths 规则强制这一约束：


// eslint.config.js
import restrictedPaths from 'eslint-plugin-import/rules/no-restricted-paths';

export default [
  {
    rules: {
      'import/no-restricted-paths': [
        'error',
        {
          zones: [
            {
              target: './src/features/auth',
              from: './src/features/dashboard',
            },
            {
              target: './src/features/dashboard',
              from: './src/features/auth',
            },
          ],
        },
      ],
    },
  },
];


Barrel File 模式
Barrel File（index.ts）是每个模块的"公开 API"。它明确声明了哪些内容可以被外部使用，隐藏了内部实现细节。


// features/auth/index.ts
export { LoginForm } from './components/LoginForm';
export { SignupForm } from './components/SignupForm';
export { useAuth } from './hooks/useAuth';
export type { User, AuthState } from './types/auth';
外部代码只通过 barrel file 访问功能模块：


// features/dashboard/components/Header.tsx
import { useAuth } from '@/features/auth';

路径别名
通过 TypeScript 路径别名避免冗长的相对路径，提升代码可读性。


{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"],
      "@/features/*": ["./src/features/*"],
      "@/shared/*": ["./src/shared/*"]
    }
  }
}
对比效果：


// 没有别名
import { Button } from '../../../shared/components/Button';

// 使用别名
import { Button } from '@/shared/components/Button';


Next.js App Router 目录约定
Next.js App Router 采用文件系统路由，目录结构即路由结构。


app/
├── layout.tsx                  # 根布局
├── page.tsx                    # 首页 /
├── loading.tsx                 # 全局加载 UI
├── error.tsx                   # 全局错误 UI
├── not-found.tsx               # 404 页面
├── (marketing)/                # 路由组（不影响 URL）
│   ├── about/
│   │   └── page.tsx            # /about
│   └── pricing/
│       └── page.tsx            # /pricing
├── (dashboard)/                # 路由组
│   ├── layout.tsx              # 仪表盘布局
│   ├── overview/
│   │   └── page.tsx            # /overview
│   └── settings/
│       └── page.tsx            # /settings
└── api/                        # API 路由
    └── users/
        └── route.ts            # /api/users


小结
    

  • Feature-Based 目录结构以业务功能为维度组织代码，是大中型项目的推荐方案。
    • 

  • 依赖方向规则确保 features 之间的隔离，通过 shared 层实现代码共享。
    • 

  • Barrel File 明确模块的公开 API，隐藏内部实现。
    • 

  • 一致的命名约定和路径别名提升代码的可读性和可维护性。
    • 

  • 框架特定的目录约定（如 Next.js App Router）应当与 Feature-Based 结构有机结合。
