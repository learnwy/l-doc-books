Monorepo 架构

什么是 Monorepo

Monorepo（单一代码仓库）是一种将多个相关项目放在同一个 Git 仓库中管理的代码组织策略。与传统的 Polyrepo（每个项目一个仓库）不同，Monorepo 让团队在一个统一的代码库中共享代码、管理依赖、协调发布。

Google、Meta、Microsoft 等科技巨头都在大规模使用 Monorepo。在前端领域，React、Vue、Babel、Next.js 等开源项目同样采用了 Monorepo 的组织方式。




Monorepo 的核心优势
代码共享与复用
在 Monorepo 中，共享代码不需要发布到 npm，直接通过 workspace 协议引用即可。修改共享代码后，所有依赖它的项目立即生效。


{
  "name": "@myapp/web",
  "dependencies": {
    "@myapp/shared-utils": "workspace:*",
    "@myapp/ui-components": "workspace:*"
  }
}
原子化提交
当一个变更涉及多个包时，可以在一次 commit 中完成所有修改。不需要在多个仓库之间协调版本，不需要先发布依赖包再更新消费方。


统一的工具链配置
ESLint、TypeScript、Prettier 等工具的配置可以在根级别统一管理，各个包继承并按需覆盖。


monorepo-root/
├── .eslintrc.js          # 统一 ESLint 配置
├── tsconfig.base.json    # 基础 TypeScript 配置
├── biome.json            # 统一 Biome 配置
└── packages/
    ├── web-app/
    │   └── tsconfig.json # 继承 base，添加 React 支持
    └── server/
        └── tsconfig.json # 继承 base，添加 Node.js 类型


pnpm Workspace 实践
pnpm 是目前 Monorepo 场景中最受推荐的包管理器。它的 workspace 功能原生支持多包管理，硬链接机制大幅节省磁盘空间，严格的依赖隔离机制避免了幽灵依赖问题。


基础配置
# pnpm-workspace.yaml
packages:
  - 'apps/*'
  - 'packages/*'
  - 'tools/*'
典型目录结构
my-frontend-platform/
├── pnpm-workspace.yaml
├── package.json
├── turbo.json
├── tsconfig.base.json
├── apps/
│   ├── web/                  # 主站 Web 应用
│   │   ├── package.json
│   │   ├── src/
│   │   └── tsconfig.json
│   ├── admin/                # 后台管理系统
│   │   ├── package.json
│   │   ├── src/
│   │   └── tsconfig.json
│   └── docs/                 # 文档站点
│       ├── package.json
│       └── src/
├── packages/
│   ├── ui/                   # 共享 UI 组件库
│   │   ├── package.json
│   │   ├── src/
│   │   └── tsconfig.json
│   ├── shared/               # 共享工具函数
│   │   ├── package.json
│   │   └── src/
│   └── api-client/           # API 客户端
│       ├── package.json
│       └── src/
└── tools/
    ├── eslint-config/        # 共享 ESLint 配置
    │   └── package.json
    └── tsconfig/             # 共享 TypeScript 配置
        └── package.json
常用命令
# 安装所有依赖
pnpm install

# 在特定包中运行命令
pnpm --filter @myapp/web dev
pnpm --filter @myapp/ui build

# 在所有包中运行构建
pnpm -r run build

# 添加依赖到特定包
pnpm --filter @myapp/web add react-router
pnpm --filter @myapp/web add -D @types/react

# 添加工作区内部包依赖
pnpm --filter @myapp/web add @myapp/ui@workspace:*


Turborepo 构建编排
Turborepo 是专为 Monorepo 设计的高性能构建系统。它通过任务依赖图、增量构建和远程缓存，大幅提升多包构建的效率。


{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**", ".next/**"]
    },
    "dev": {
      "dependsOn": ["^build"],
      "persistent": true,
      "cache": false
    },
    "lint": {
      "dependsOn": ["^build"]
    },
    "test": {
      "dependsOn": ["build"]
    },
    "typecheck": {
      "dependsOn": ["^build"]
    }
  }
}
Turborepo 的 ^build 语法表示"先构建所有依赖的包"。上图中，@myapp/web 的构建会自动等待 @myapp/ui 和 @myapp/api-client 构建完成。




包的划分原则
合理的包划分是 Monorepo 成功的关键。划分过细会增加管理成本，划分过粗则失去了模块化的意义。






划分维度
说明
示例





应用层
可独立部署的终端产物
web-app、admin、mobile




组件层
可复用的 UI 组件
ui-components、icons




逻辑层
可复用的业务/工具逻辑
shared-utils、api-client




配置层
共享的工具链配置
eslint-config、tsconfig







Monorepo 的挑战与应对
仓库体积增长
随着包数量增长，Git 仓库体积会持续增大。解决方案包括 Git 浅克隆（shallow clone）、Git LFS 管理大文件，以及合理的 .gitignore 配置。


# CI 中使用浅克隆加速
git clone --depth 1 --filter=blob:none https://github.com/org/monorepo.git
构建速度优化
利用 Turborepo 的远程缓存和增量构建能力，避免重复构建未变更的包。


# 启用远程缓存
npx turbo login
npx turbo link

# 只构建受影响的包
npx turbo run build --filter=...[HEAD~1]
权限控制
在大团队中，可能需要限制某些团队只能修改特定的包。GitHub 的 CODEOWNERS 文件可以实现路径级别的审核控制。


# CODEOWNERS
/apps/web/          @frontend-team
/apps/admin/        @admin-team
/packages/ui/       @design-system-team
/packages/shared/   @platform-team


小结
    

  • Monorepo 通过统一仓库管理多个相关项目，实现代码共享、原子化提交和统一工具链。
    • 

  • pnpm workspace 是目前最推荐的 Monorepo 包管理方案，硬链接和严格依赖隔离是其核心优势。
    • 

  • Turborepo 通过任务依赖图和增量缓存优化多包构建效率。
    • 

  • 包的划分遵循"应用层—组件层—逻辑层—配置层"的分层原则。
    • 

  • Monorepo 的挑战主要在于仓库体积、构建速度和权限控制，都有成熟的应对方案。
