自动化发布

发布的复杂性

在一个 Monorepo 中，发布涉及多个层面的决策：哪些包需要发布？版本号如何确定？CHANGELOG 如何生成？npm 包如何发布？应用如何部署？手动管理这些流程既容易出错，又难以规模化。



Changesets 工作流
Changesets 是 Monorepo 场景中最成熟的版本管理工具。它将版本管理分为两个阶段：日常开发中"记录变更"，发布时"消费变更"。


安装配置
pnpm add -D @changesets/cli @changesets/changelog-github
npx changeset init
// .changeset/config.json
{
  "$schema": "https://unpkg.com/@changesets/config@3.0.0/schema.json",
  "changelog": ["@changesets/changelog-github", { "repo": "org/frontend-platform" }],
  "commit": false,
  "fixed": [],
  "linked": [["@myapp/ui", "@myapp/shared"]],
  "access": "restricted",
  "baseBranch": "main",
  "updateInternalDependencies": "patch",
  "ignore": ["@myapp/web", "@myapp/admin"]
}
日常工作流
记录变更
npx changeset
执行后会交互式地询问：


    

  1. 哪些包受到了影响？
    2. 

  2. 是 major、minor 还是 patch 变更？
    3. 

  3. 变更的描述是什么？
    4. 



生成的 changeset 文件：


---
'@myapp/ui': minor
'@myapp/shared': patch
---

新增 DatePicker 组件，支持日期选择和范围选择。更新了 shared 包中的日期格式化工具函数。

自动化发布 CI
# .github/workflows/release.yml
name: Release

on:
  push:
    branches: [main]

permissions:
  contents: write
  pull-requests: write
  id-token: write

jobs:
  release:
    name: Release
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup pnpm
        uses: pnpm/action-setup@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'
          registry-url: 'https://registry.npmjs.org'

      - name: Install Dependencies
        run: pnpm install --frozen-lockfile

      - name: Build
        run: pnpm run build

      - name: Create Release PR or Publish
        uses: changesets/action@v1
        with:
          publish: pnpm run release
          version: pnpm run version
          title: 'chore: release packages'
          commit: 'chore: release packages'
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
package.json 脚本
{
  "scripts": {
    "version": "changeset version && pnpm install --lockfile-only",
    "release": "changeset publish"
  }
}


CHANGELOG 自动生成
Changesets 自动将所有 changeset 文件合并为结构化的 CHANGELOG：


# @myapp/ui

## 2.1.0

### Minor Changes

- [`a1b2c3d`](https://github.com/org/repo/commit/a1b2c3d) - 新增 DatePicker 组件
  - 支持单日期选择和日期范围选择
  - 内置日期格式化
  - 完整的键盘导航支持

### Patch Changes

- [`d4e5f6g`](https://github.com/org/repo/commit/d4e5f6g) - 修复 Button 在 disabled 状态下的样式问题

- Updated dependencies:
  - @myapp/shared@1.5.1

## 2.0.0

### Major Changes

- [`h7i8j9k`](https://github.com/org/repo/commit/h7i8j9k) - 移除已废弃的 `type` prop

  **迁移指南:**

  ```diff
  - <Button type="submit">提交</Button>
  + <Button htmlType="submit">提交</Button>
  ```


应用发布策略
对于 Web 应用（不发布到 npm），可以基于 Git Tag 或分支触发部署。


# .github/workflows/deploy-app.yml
name: Deploy Application

on:
  push:
    tags:
      - 'app-v*'

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - run: pnpm run build

      - name: Deploy
        run: |
          echo "Deploying version ${{ github.ref_name }}"
          npx vercel deploy --prod --token=${{ secrets.VERCEL_TOKEN }}


小结
    

  • Changesets 将版本管理分为"记录变更"和"消费变更"两个阶段，适合 Monorepo。
    • 

  • 语义化版本（Semver）为版本号赋予明确的兼容性语义。
    • 

  • 自动化发布 CI 通过 GitHub Actions 实现一键式版本发布和 CHANGELOG 生成。
    • 

  • linked 和 fixed 配置控制多包之间的版本关联策略。
    • 

  • 应用部署可基于 Git Tag 或 Release PR 合并触发，与包发布解耦。
    •
