Git Hooks 与 Lefthook

Git Hooks 的作用

Git Hooks 是 Git 在特定事件（如提交、推送）发生时自动执行的脚本。在前端工程化中，Git Hooks 是本地代码质量的"最后一道防线"——确保每一次提交的代码都通过了基本的质量检查。





Hook
触发时机
典型用途





pre-commit
git commit 前
Lint、格式化、类型检查




commit-msg
提交消息写入后
校验 Conventional Commits 格式




pre-push
git push 前
运行测试




post-merge
git merge 后
自动 pnpm install




post-checkout
git checkout 后
自动 pnpm install







Lefthook 配置
Lefthook 是一个用 Go 编写的 Git Hook 管理工具，相比 Husky + lint-staged 的组合，它具有以下优势：


    

  • 单一工具替代 Husky + lint-staged 两个工具
    • 

  • Go 原生执行，启动速度更快
    • 

  • 并行执行多个命令
    • 

  • 原生支持 Monorepo
    • 



安装
pnpm add -D lefthook
npx lefthook install
基础配置
# lefthook.yml
pre-commit:
  parallel: true
  commands:
    lint:
      glob: '*.{ts,tsx,js,jsx}'
      run: npx biome check --apply {staged_files}
      stage_fixed: true
    typecheck:
      glob: '*.{ts,tsx}'
      run: npx tsc --noEmit
    test:
      glob: '*.{ts,tsx}'
      run: npx vitest related {staged_files} --run

commit-msg:
  commands:
    commitlint:
      run: npx commitlint --edit {1}

pre-push:
  commands:
    test:
      run: pnpm run test --run
    build:
      run: pnpm run build
Monorepo 配置
# lefthook.yml (Monorepo)
pre-commit:
  parallel: true
  commands:
    lint:
      glob: '*.{ts,tsx,js,jsx}'
      run: npx biome check --apply {staged_files}
      stage_fixed: true
    typecheck-web:
      root: 'apps/web/'
      glob: 'apps/web/**/*.{ts,tsx}'
      run: npx tsc --noEmit --project tsconfig.json
    typecheck-admin:
      root: 'apps/admin/'
      glob: 'apps/admin/**/*.{ts,tsx}'
      run: npx tsc --noEmit --project tsconfig.json
    typecheck-ui:
      root: 'packages/ui/'
      glob: 'packages/ui/**/*.{ts,tsx}'
      run: npx tsc --noEmit --project tsconfig.json

post-merge:
  commands:
    install:
      run: pnpm install --frozen-lockfile
      glob: '**/pnpm-lock.yaml'

post-checkout:
  commands:
    install:
      run: pnpm install --frozen-lockfile
      glob: '**/pnpm-lock.yaml'


Conventional Commits
Conventional Commits 是一种结构化的提交消息格式，为自动化版本管理和 CHANGELOG 生成提供基础。


格式规范
<type>(<scope>): <description>

[optional body]

[optional footer(s)]
常用 Type




Type
说明
版本影响





feat
新功能
Minor (0.x.0)




fix
Bug 修复
Patch (0.0.x)




docs
文档更新
无




style
代码风格（不影响功能）
无




refactor
重构（不增加功能或修复 Bug）
无




perf
性能优化
Patch




test
测试相关
无




chore
构建/工具/依赖等
无




ci
CI 配置变更
无





commitlint 配置
// commitlint.config.ts
import type { UserConfig } from '@commitlint/types';

const config: UserConfig = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'type-enum': [2, 'always', ['feat', 'fix', 'docs', 'style', 'refactor', 'perf', 'test', 'chore', 'ci', 'revert']],
    'scope-enum': [2, 'always', ['web', 'admin', 'ui', 'shared', 'api-client', 'docs', 'ci']],
    'subject-max-length': [2, 'always', 72],
    'body-max-line-length': [2, 'always', 100],
  },
};

export default config;

实践建议
    

  • pre-commit 应该快：只检查暂存文件，1-5 秒内完成
    • 

  • pre-push 可以更全面：运行测试和构建，10-30 秒可接受
    • 

  • 不要阻塞开发流程：Hook 太慢会导致开发者用 --no-verify 跳过
    • 





小结
    

  • Git Hooks 是本地代码质量的"最后一道防线"。
    • 

  • Lefthook 是单一的 Go 原生工具，替代 Husky + lint-staged 组合。
    • 

  • Conventional Commits 为自动化版本管理和 CHANGELOG 生成提供基础。
    • 

  • pre-commit Hook 应保持快速（1-5 秒），只检查暂存文件。
    • 

  • 本地 Hook 和 CI 流水线是互补关系——前者提供快速反馈，后者提供全面保障。
    •
