ESLint 与 Biome

静态分析的价值

静态代码分析是在不执行代码的前提下，通过分析源代码的语法结构和语义信息来发现潜在问题的技术。与运行时错误发现机制不同，静态分析能够在代码编写阶段就捕获问题，极大地缩短了反馈循环。

静态分析能够捕获的问题包括：


    

  • 未使用的变量和导入
    • 

  • 潜在的空引用和类型错误
    • 

  • 不安全的代码模式（如 eval、innerHTML）
    • 

  • 可访问性问题（a11y）
    • 

  • React Hooks 规则违反
    • 

  • 导入顺序不规范
    • 





ESLint 深度配置
ESLint 是前端领域使用最广泛的 Linter。ESLint 9 引入了 Flat Config 作为新的配置格式，取代了传统的 .eslintrc 层叠配置。


Flat Config 基础
// eslint.config.js
import js from '@eslint/js';
import tsPlugin from '@typescript-eslint/eslint-plugin';
import tsParser from '@typescript-eslint/parser';
import reactPlugin from 'eslint-plugin-react';
import reactHooksPlugin from 'eslint-plugin-react-hooks';
import importPlugin from 'eslint-plugin-import';

export default [
  js.configs.recommended,
  {
    files: ['**/*.{ts,tsx}'],
    languageOptions: {
      parser: tsParser,
      parserOptions: {
        project: './tsconfig.json',
        ecmaFeatures: { jsx: true },
      },
    },
    plugins: {
      '@typescript-eslint': tsPlugin,
      react: reactPlugin,
      'react-hooks': reactHooksPlugin,
      import: importPlugin,
    },
    rules: {
      '@typescript-eslint/no-unused-vars': ['error', { argsIgnorePattern: '^_' }],
      '@typescript-eslint/no-explicit-any': 'error',
      '@typescript-eslint/strict-boolean-expressions': 'error',
      'react-hooks/rules-of-hooks': 'error',
      'react-hooks/exhaustive-deps': 'warn',
      'import/order': [
        'error',
        {
          groups: ['builtin', 'external', 'internal', 'parent', 'sibling', 'index'],
          'newlines-between': 'always',
          alphabetize: { order: 'asc' },
        },
      ],
    },
  },
  {
    ignores: ['dist/', 'node_modules/', '.next/', '*.config.js'],
  },
];
Monorepo 中的 ESLint 配置
在 Monorepo 中，推荐将 ESLint 配置作为独立的共享包管理。


tools/
└── eslint-config/
    ├── package.json
    ├── base.js           # 基础配置
    ├── react.js          # React 项目配置
    ├── next.js           # Next.js 项目配置
    └── library.js        # 库项目配置
// tools/eslint-config/base.js
import js from '@eslint/js';
import tsPlugin from '@typescript-eslint/eslint-plugin';
import tsParser from '@typescript-eslint/parser';

export const baseConfig = [
  js.configs.recommended,
  {
    files: ['**/*.{ts,tsx}'],
    languageOptions: {
      parser: tsParser,
    },
    plugins: {
      '@typescript-eslint': tsPlugin,
    },
    rules: {
      '@typescript-eslint/no-unused-vars': ['error', { argsIgnorePattern: '^_' }],
      '@typescript-eslint/no-explicit-any': 'error',
    },
  },
];
// apps/web/eslint.config.js
import { baseConfig } from '@myapp/eslint-config/base';
import { reactConfig } from '@myapp/eslint-config/react';

export default [...baseConfig, ...reactConfig];


Biome：下一代统一工具
Biome 是用 Rust 编写的前端工具链，同时提供 Linting、Formatting 和 Import Sorting 功能。它的核心优势是速度——相比 ESLint + Prettier 的组合，Biome 通常快 20-100 倍。


基础配置
{
  "$schema": "https://biomejs.dev/schemas/1.9.0/schema.json",
  "organizeImports": {
    "enabled": true
  },
  "linter": {
    "enabled": true,
    "rules": {
      "recommended": true,
      "complexity": {
        "noBannedTypes": "error",
        "noForEach": "warn"
      },
      "correctness": {
        "noUnusedVariables": "error",
        "noUnusedImports": "error",
        "useExhaustiveDependencies": "warn"
      },
      "suspicious": {
        "noExplicitAny": "error",
        "noConsoleLog": "warn"
      },
      "style": {
        "noNonNullAssertion": "warn",
        "useConst": "error"
      }
    }
  },
  "formatter": {
    "enabled": true,
    "indentStyle": "space",
    "indentWidth": 2,
    "lineWidth": 100
  },
  "javascript": {
    "formatter": {
      "quoteStyle": "double",
      "semicolons": "always",
      "trailingCommas": "all"
    }
  }
}

ESLint vs Biome：如何选择
实际建议：


    

  • 新项目、规则需求标准：优先考虑 Biome，简单快速
    • 

  • 已有 ESLint 配置、依赖特定插件：继续使用 ESLint
    • 

  • 大型 Monorepo、CI 时间敏感：Biome 的速度优势显著
    • 





自动修复与 IDE 集成
两种工具都支持 --fix / --apply 自动修复和 IDE 实时检查。


# ESLint 自动修复
npx eslint --fix .

# Biome 自动修复
npx biome check --apply .

# Biome 格式化 + lint + import 排序
npx biome check --apply --formatter-enabled=true --organize-imports-enabled=true .
VS Code 配置（Biome）：


{
  "editor.defaultFormatter": "biomejs.biome",
  "editor.formatOnSave": true,
  "editor.codeActionsOnSave": {
    "quickfix.biome": "explicit",
    "source.organizeImports.biome": "explicit"
  }
}


小结
    

  • 静态分析在代码编写阶段即可发现问题，是代码质量的第一道防线。
    • 

  • ESLint Flat Config 是 ESLint 9 的标准配置方式，支持类型感知规则和丰富插件生态。
    • 

  • Biome 以 Rust 实现，集 Linting、Formatting、Import Sorting 于一体，速度提升 20-100 倍。
    • 

  • 选择取决于项目需求：ESLint 插件生态更丰富，Biome 速度更快、配置更简单。
    • 

  • 在 Monorepo 中，共享配置包是管理 ESLint 配置的最佳实践。
    •
