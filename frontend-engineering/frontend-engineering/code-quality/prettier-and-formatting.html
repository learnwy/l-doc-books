Prettier 与代码格式化

格式化的本质：终结无意义争论

代码格式化工具的核心价值不在于它选择了哪种风格，而在于它终结了关于代码风格的所有争论。Tab 还是 Space？单引号还是双引号？尾逗号还是不加？当团队采用了自动格式化工具后，这些问题都有了唯一确定的答案——工具说了算。



Prettier 配置
Prettier 是前端领域最流行的 Opinionated 代码格式化工具。"Opinionated" 意味着它有意减少配置选项——这不是缺陷，而是设计哲学：选项越少，争论越少。


基础配置
{
  "$schema": "https://json.schemastore.org/prettierrc",
  "semi": true,
  "singleQuote": false,
  "tabWidth": 2,
  "useTabs": false,
  "trailingComma": "all",
  "printWidth": 100,
  "bracketSpacing": true,
  "arrowParens": "always",
  "endOfLine": "lf",
  "plugins": ["prettier-plugin-tailwindcss"],
  "overrides": [
    {
      "files": "*.md",
      "options": {
        "proseWrap": "preserve"
      }
    }
  ]
}
忽略配置
# .prettierignore
dist/
build/
node_modules/
.next/
coverage/
pnpm-lock.yaml
*.min.js


Prettier 与 ESLint 的关系
Prettier 负责代码格式（How code looks），ESLint 负责代码质量（How code works）。两者的职责需要明确分离，避免规则冲突。


集成方案
使用 eslint-config-prettier 关闭 ESLint 中与 Prettier 冲突的格式化规则：


// eslint.config.js
import js from '@eslint/js';
import prettierConfig from 'eslint-config-prettier';

export default [
  js.configs.recommended,
  {
    rules: {
      'no-unused-vars': 'error',
    },
  },
  prettierConfig,
];
推荐执行顺序：


# 先格式化，再 lint
prettier --write .
eslint --fix .


Biome 的格式化方案
如果团队选择了 Biome，格式化功能已经内置，无需额外安装 Prettier。


{
  "formatter": {
    "enabled": true,
    "indentStyle": "space",
    "indentWidth": 2,
    "lineWidth": 100,
    "lineEnding": "lf"
  },
  "javascript": {
    "formatter": {
      "quoteStyle": "double",
      "semicolons": "always",
      "trailingCommas": "all",
      "arrowParentheses": "always",
      "bracketSpacing": true
    }
  },
  "json": {
    "formatter": {
      "trailingCommas": "none"
    }
  },
  "css": {
    "formatter": {
      "quoteStyle": "double"
    }
  }
}
Biome 格式化与 Prettier 的产出差异极小（>96% 兼容），且速度快一到两个数量级。

EditorConfig
.editorconfig 为不使用 Prettier 的文件类型提供基础格式约定：


root = true

[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 2
insert_final_newline = true
trim_trailing_whitespace = true

[*.md]
trim_trailing_whitespace = false

[Makefile]
indent_style = tab


Monorepo 格式化策略
在 Monorepo 中，格式化配置应当在根目录统一管理，各个包默认继承。


monorepo-root/
├── .prettierrc              # 统一配置
├── .prettierignore           # 统一忽略
├── .editorconfig             # 编辑器基础配置
├── apps/
│   └── web/                  # 继承根配置
└── packages/
    └── ui/                   # 继承根配置
格式化检查集成到 CI 流水线：


# CI 中检查格式（不修改文件）
npx prettier --check .

# 或使用 Biome
npx biome check --formatter-enabled=true .

小结
    

  • Prettier 的核心价值是终结代码风格争论，通过 Opinionated 设计减少配置选项。
    • 

  • Prettier 负责格式，ESLint 负责质量——两者职责明确分离。
    • 

  • Biome 内置格式化能力，与 Prettier 产出高度兼容，速度更快。
    • 

  • 格式化应当通过三层保障落地：编辑器自动格式化、Git Hook、CI 检查。
    • 

  • Monorepo 中统一根目录配置，各包默认继承。
