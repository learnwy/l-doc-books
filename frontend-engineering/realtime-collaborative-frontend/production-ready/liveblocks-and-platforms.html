Liveblocks 与协作平台

核心概念

现代协作平台让初创团队可以在几天而非几个月内交付协作功能。主流方案包括：Liveblocks（专注 React、基于 CRDT/Yjs）、PartyKit（基于 Cloudflare 边缘计算）、Convex（全栈实时数据库）、Replicache（后端无关的同步引擎）、Pusher / Ably（实时消息广播）。每个平台抽象了不同的层级——Liveblocks 提供预构建的 React Hooks 用于光标、选区和共享状态；PartyKit 提供边缘实时后端；Convex 提供带实时查询的全栈方案；Replicache 提供本地优先架构配合自定义后端；Pusher / Ably 提供简单的消息通道。本节将对比各平台、帮助选择合适的框架，并分析成本和自托管与平台托管的决策。

Liveblocks

面向 React 的现代协作平台：

  • 预构建 Hooks（useOthers、useMyPresence、useStorage）。
  • 内置 Yjs 集成。
  • 光标、选区、共享状态开箱即用。
  • 托管式基础设施，无需自建服务器。

安装配置：

npm i @liveblocks/client @liveblocks/react
import { createClient } from '@liveblocks/client';
import { createRoomContext } from '@liveblocks/react';

const client = createClient({
  authEndpoint: '/api/liveblocks-auth',
});

const { RoomProvider, useOthers, useMyPresence } = createRoomContext(client);

function App() {
  return (
    <RoomProvider id="room-1" initialPresence={{ cursor: null }}>
      <Editor />
    </RoomProvider>
  );
}

function Editor() {
  const [myPresence, updateMyPresence] = useMyPresence();
  const others = useOthers();

  return (
    <div onMouseMove={(e) => updateMyPresence({ cursor: { x: e.clientX, y: e.clientY } })}>
      <Cursor cursor={myPresence.cursor} />
      {others.map((other) => (
        <Cursor key={other.connectionId} cursor={other.presence.cursor} />
      ))}
    </div>
  );
}

认证端点：

// /api/liveblocks-auth
import { authorize } from '@liveblocks/node';

export async function POST(req) {
  const userId = await getUser(req);
  return authorize({
    room: req.body.room,
    userId,
    userInfo: { name: 'Alice', color: '#ff0000' },
  });
}

定价模型：

  • 免费额度支持 100 月活用户。
  • 超出部分按每千月活用户计费。
  • 价格区间 $30-200/千月活用户。

适用场景：

  • 初创团队需要快速交付协作功能。
  • 以 React 为主的技术栈。
  • 不希望自建和维护实时基础设施。

PartyKit

基于 Cloudflare 的实时边缘后端：

  • 构建于持久对象(Durable Objects)之上。
  • 边缘部署，全球低延迟。
  • 开源项目（可在 Cloudflare 上自托管）。

安装配置：

npm i partykit partysocket

服务端：

// party/server.ts
export default class implements Party.Server {
  constructor(readonly room: Party.Room) {}

  onConnect(connection) {
    this.room.broadcast(`User ${connection.id} joined`);
  }

  onMessage(message, sender) {
    this.room.broadcast(message, [sender.id]);
  }
}

客户端：

import PartySocket from 'partysocket';

const socket = new PartySocket({ host: 'http://...', room: 'room1' });

socket.send('hello');
socket.addEventListener('message', (event) => {
  console.log(event.data);
});

免费额度：

  • 免费额度较为慷慨。
  • 支持边缘部署。

适用场景：

  • 需要边缘实时计算能力。
  • 已在 Cloudflare 生态中。
  • 偏好开源和可自托管的方案。

Convex

全栈实时数据库(Real-time DB)：

  • 数据库 + 无服务器函数 + 实时订阅一体化。
  • 提供 React Hooks 实现实时查询。

安装配置：

npm i convex
npx convex dev

数据模型与函数定义：

// convex/messages.js
export const list = query(async ({ db }) => {
  return await db.query('messages').take(100);
});

export const send = mutation(async ({ db }, { text }) => {
  await db.insert('messages', { text });
});

React 集成：

import { useQuery, useMutation } from 'convex/react';

function Chat() {
  const messages = useQuery(api.messages.list); // 自动实时更新！
  const send = useMutation(api.messages.send);

  return (
    <>
      {messages?.map((m) => (
        <p>{m.text}</p>
      ))}
      <button onClick={() => send({ text: 'hi' })}>Send</button>
    </>
  );
}

数据订阅由平台自动管理，开发者无需手动处理 WebSocket 连接或状态同步。

适用场景：

  • 需要全栈解决方案。
  • 不希望分别管理数据库和实时通信层。

Replicache

后端无关的本地优先同步引擎：

  • 数据存储在本地 IndexedDB 中。
  • 推送待处理的变更(mutation)到服务器。
  • 从服务器拉取权威状态。
  • 内置乐观更新机制。

安装配置：

npm i replicache

客户端：

import { Replicache } from 'replicache';

const rep = new Replicache({
  name: 'user1',
  pushURL: '/api/push',
  pullURL: '/api/pull',
  mutators: {
    addTodo: async (tx, { id, text }) => {
      await tx.put(`todo/${id}`, { text });
    },
  },
});

// 乐观更新——立即反映在 UI 上
await rep.mutate.addTodo({ id: '1', text: 'hi' });

// 订阅数据变化
rep.subscribe(async (tx) => tx.scan(), {
  onData: (data) => render(data),
});

服务端端点：

  • /api/push：接收并应用客户端变更。
  • /api/pull：返回权威状态。

定价模型：

  • 按开发者席位收费。
  • 不按月活用户计费。

适用场景：

  • 追求本地优先(Local-first)架构。
  • 已有自定义后端。
  • 不希望被厂商锁定。

Pusher / Ably

实时消息通道服务：

  • 客户端订阅频道。
  • 服务端发布消息。
  • 所有订阅者实时收到推送。

Pusher 示例：

import Pusher from 'pusher-js';

const pusher = new Pusher('app-key');
const channel = pusher.subscribe('chat');
channel.bind('message', (data) => {
  console.log(data);
});

// 服务端发布消息
pusher.trigger('chat', 'message', { text: 'hello' });

适用场景：

  • 通知推送和扇出分发。
  • 实时信息流。
  • 不涉及协作编辑（无 CRDT 支持）。

成本：

  • 按消息量计费。
  • 每百万条消息 $50-500。

Yjs 自建方案

完全自主控制：

  • 使用 Yjs CRDT 库。
  • 配合 y-websocket 或 HocusPocus 服务器。
  • 自定义 UI 集成。

技术栈：

npm i yjs y-websocket

服务端：

import { WebSocketServer } from 'ws';
import { setupWSConnection } from 'y-websocket/bin/utils';

const wss = new WebSocketServer({ port: 1234 });
wss.on('connection', setupWSConnection);

客户端：

import * as Y from 'yjs';
import { WebsocketProvider } from 'y-websocket';

const doc = new Y.Doc();
const provider = new WebsocketProvider('ws://localhost:1234', 'room', doc);

优势：

  • 完全掌控技术栈。
  • 无厂商锁定。
  • 完全开源。

劣势：

  • 需要自行管理扩容。
  • 需要自行构建所有用户体验层。

决策框架

选择 Liveblocks 的条件：

  • 技术栈以 React 为主。
  • 需要预构建的光标/状态 Hooks。
  • 接受托管模式。
  • 预算充足。

选择 PartyKit 的条件：

  • 已在 Cloudflare 生态中。
  • 需要边缘部署能力。
  • 偏好开源方案。

选择 Convex 的条件：

  • 需要全栈解决方案。
  • 实时查询是核心需求。
  • 不希望管理服务器。

选择 Replicache 的条件：

  • 坚持本地优先原则。
  • 已有自定义后端。
  • 不希望被厂商锁定。

选择 Pusher / Ably 的条件：

  • 仅需实时消息推送。
  • 不涉及协作编辑（无需 CRDT）。

选择 Yjs 自建的条件：

  • 需要完全掌控。
  • 有足够的工程资源。
  • 有特殊需求（隐私、私有化部署）。

迁移路径
从平台起步，规模扩大后迁移：


    

  • 从 Liveblocks 迁移到自建 Yjs 后端。
    • 

  • 迁移难度较高——内部协议有差异。
    • 



反向迁移：


    

  • 从自建 Yjs 迁移到 Liveblocks。
    • 

  • 需要部分数据模型迁移。
    • 



最佳实践：


    

  • 选择以 Yjs 为底层的方案。
    • 

  • 平台本身使用 Yjs（如 Liveblocks 底层就是 Yjs）。
    • 

  • 这样日后迁移路径更清晰。
    • 



自托管与平台托管
平台托管的优势：


    

  • 几天内即可交付。
    • 

  • 无需担心扩容和可用性。
    • 

  • 专注于产品本身。
    • 



平台托管的劣势：


    

  • 成本随规模增长。
    • 

  • 存在厂商锁定风险。
    • 

  • 隐私和数据控制受限。
    • 



自托管的优势：


    

  • 完全掌控。
    • 

  • 成本可预测。
    • 

  • 数据隐私有保障。
    • 



自托管的劣势：


    

  • 需要工程师投入。
    • 

  • 需要全天候运维。
    • 

  • 扩容复杂。
    • 



建议：


    

  • 初创阶段选择平台托管。
    • 

  • 成熟阶段如果成本增长过快，考虑迁移到自托管。
    •

y-websocket-server：

  • 现代的自托管模式，结合边缘计算。

  • 应直接使用 Yjs 等成熟库。
    • 



2. 在超大规模下使用付费平台：


    

  • 成本可能变得不可承受。
    • 

  • 应考虑切换到自托管方案。
    • 



3. 在没有工程团队的情况下自托管：


    

  • 运维负担过重。

  • 迁移代价极高。

小结
现代协作平台将协作功能的开发周期从数月缩短到数天。Liveblocks 专注 React 生态，提供预构建 Hooks（useOthers / useMyPresence / useStorage），集成 Yjs，采用托管模式，费用为 30−200/千月活用户，通过authorize()服务端端点进行认证。PartyKit基于Cloudflare边缘的持久对象，开源可自托管，有免费额度。Convex提供全栈实时数据库+无服务器函数+实时查询，通过useQuery/useMutation自动管理数据订阅。Replicache是同步引擎，数据存储在本地IndexedDB，通过推送/拉取机制同步，内置乐观更新，按开发者席位收费30-200/千月活用户，通过 authorize() 服务端端点进行认证。PartyKit 基于 Cloudflare 边缘的持久对象，开源可自托管，有免费额度。Convex 提供全栈实时数据库 + 无服务器函数 + 实时查询，通过 useQuery / useMutation 自动管理数据订阅。Replicache 是同步引擎，数据存储在本地 IndexedDB，通过推送/拉取机制同步，内置乐观更新，按开发者席位收费30−200/千月活用户，通过authorize()服务端端点进行认证。PartyKit基于Cloudflare边缘的持久对象，开源可自托管，有免费额度。Convex提供全栈实时数据库+无服务器函数+实时查询，通过useQuery/useMutation自动管理数据订阅。Replicache是同步引擎，数据存储在本地IndexedDB，通过推送/拉取机制同步，内置乐观更新，按开发者席位收费499/月，后端无关且无厂商锁定。Pusher / Ably 提供实时消息通道的订阅/发布功能（无 CRDT 支持），每百万消息 $50-500。Yjs 自建方案提供完全控制权，配合 y-websocket 或 HocusPocus 服务器，开源但需要自行管理扩容。


决策框架的核心思路：Liveblocks 适合 React + 预构建 + 托管需求；PartyKit 适合 Cloudflare 边缘 + 开源偏好；Convex 适合全栈 + 实时查询；Replicache 适合本地优先 + 自定义后端；Pusher/Ably 适合纯消息推送场景；Yjs 自建适合需要完全控制且有工程团队的场景。在自托管与平台托管之间的抉择中，建议初创阶段使用平台托管快速验证产品，成熟后根据成本增长情况考虑迁移到自托管。选择以 Yjs 为底层的方案可以让未来的迁移路径更加顺畅。
