实时协作应用测试

核心概念

实时协作应用的测试比传统应用复杂得多，涉及多客户端模拟、CRDT 收敛验证、网络状况模拟、离线场景、冲突解决等方面。常用工具包括 Playwright 多页面模式（模拟多用户）、Yjs 测试工具（应用更新并验证）、网络限流工具，以及 WebSocket 专用的压力测试工具（k6 / Artillery）。在 CI/CD 流程中对这些场景做回归测试至关重要。本节系统介绍测试策略、多客户端测试模式、CRDT 收敛测试、负载测试以及生产环境监控方案。

测试类型 工具 覆盖范围
单元测试（CRDT 逻辑） Vitest / Jest CRDT 变换正确性
集成测试 Yjs apply + verify 文档一致性
端到端多客户端测试 Playwright 多页面 真实用户流程
网络状况测试 DevTools 限流 / Toxiproxy 离线与慢网
负载测试 k6 / Artillery（WebSocket） 服务端扩展性
生产监控 Prometheus / Datadog 线上健康状态

单元测试 CRDT 逻辑

测试变换正确性：

import * as Y from 'yjs';
import { describe, it, expect } from 'vitest';

describe('CRDT merge', () => {
  it('two clients edit text concurrently', () => {
    const doc1 = new Y.Doc();
    const doc2 = new Y.Doc();

    const text1 = doc1.getText('content');
    const text2 = doc2.getText('content');

    text1.insert(0, 'Hello ');
    text2.insert(0, 'World ');

    // 同步
    Y.applyUpdate(doc2, Y.encodeStateAsUpdate(doc1));
    Y.applyUpdate(doc1, Y.encodeStateAsUpdate(doc2));

    // 两端收敛
    expect(text1.toString()).toBe(text2.toString());
  });

  it('handles delete + insert', () => {
    const doc1 = new Y.Doc();
    const doc2 = new Y.Doc();

    const text1 = doc1.getText('t');
    text1.insert(0, 'Hello');

    Y.applyUpdate(doc2, Y.encodeStateAsUpdate(doc1));

    const text2 = doc2.getText('t');
    text1.delete(0, 1); // 删除 'H'
    text2.insert(5, '!'); // 追加 '!'

    Y.applyUpdate(doc1, Y.encodeStateAsUpdate(doc2));
    Y.applyUpdate(doc2, Y.encodeStateAsUpdate(doc1));

    expect(text1.toString()).toBe(text2.toString());
    expect(text1.toString()).toBe('ello!');
  });
});

覆盖要点：

  • CRDT 核心属性（交换律、幂等性）。
  • 具体的边界条件。

集成测试

测试完整的同步流程：

import { WebSocket } from 'ws';
import * as Y from 'yjs';
import { WebsocketProvider } from 'y-websocket';

describe('Sync via WebSocket', () => {
  it('two clients sync', async () => {
    const doc1 = new Y.Doc();
    const provider1 = new WebsocketProvider('ws://localhost:1234', 'test', doc1);

    const doc2 = new Y.Doc();
    const provider2 = new WebsocketProvider('ws://localhost:1234', 'test', doc2);

    await new Promise((r) => setTimeout(r, 500)); // 等待连接建立

    doc1.getText('t').insert(0, 'Hello');

    await new Promise((r) => setTimeout(r, 500)); // 等待同步完成

    expect(doc2.getText('t').toString()).toBe('Hello');
  });
});

端到端多客户端 Playwright 测试

模拟两个用户：

import { test, expect } from '@playwright/test';

test('two users see each other cursor', async ({ browser }) => {
  // 两个浏览器上下文（模拟不同"用户"）
  const ctx1 = await browser.newContext();
  const ctx2 = await browser.newContext();

  const page1 = await ctx1.newPage();
  const page2 = await ctx2.newPage();

  await page1.goto('https://app.example.com/doc/123');
  await page2.goto('https://app.example.com/doc/123');

  // 用户 1 编辑
  await page1.locator('.editor').type('Hello from User 1');

  // 用户 2 看到编辑内容
  await expect(page2.locator('.editor')).toContainText('Hello from User 1');

  // 用户 1 移动鼠标
  await page1.mouse.move(100, 200);

  // 用户 2 看到用户 1 的光标
  const cursor = page2.locator('.remote-cursor[data-user="user1"]');
  await expect(cursor).toBeVisible();
});

覆盖要点：

  • 使用真实浏览器的完整用户流程。
  • 光标与选区同步验证。
  • 冲突场景模拟。

网络状况测试

离线场景：

test('offline edit syncs on reconnect', async ({ page, context }) => {
  await page.goto('/doc/123');

  // 断网
  await context.setOffline(true);

  await page.locator('.editor').type('Offline edit');

  // 验证本地已保存
  const text = await page.locator('.editor').textContent();
  expect(text).toContain('Offline edit');

  // 恢复网络
  await context.setOffline(false);

  // 等待同步
  await page.waitForTimeout(2000);

  // 验证服务端已接收（通过 API 校验）

});

负载测试

使用 k6 进行 WebSocket 负载测试：

import ws from 'k6/ws';
import { check } from 'k6';

export const options = {
  vus: 1000, // 1000 个虚拟用户
  duration: '5m',
};

export default function () {
  const url = 'wss://app.example.com';
  const res = ws.connect(url, {}, function (socket) {
    socket.on('open', () => {
      socket.send(JSON.stringify({ type: 'join', room: 'load-test' }));
    });

    socket.on('message', (data) => {
      // 验证响应
    });

    // 定期发送消息
    socket.setInterval(() => {
      socket.send(JSON.stringify({ type: 'edit', text: 'foo' }));
    }, 1000);

    socket.setTimeout(() => {
      socket.close();
    }, 60000);
  });

  check(res, { connected: (r) => r && r.status === 101 });
}

运行命令：

k6 run load-test.js

关注指标：

  • 延迟 p50 / p95 / p99。
  • 连接成功率。
  • 错误率。
  • 服务端 CPU / 内存占用。

使用 Artillery 进行 WebSocket 负载测试

替代方案：

# artillery.yml
config:
  target: 'wss://app.example.com'
  phases:
    - duration: 60
      arrivalRate: 50

scenarios:
  - engine: ws
    flow:
      - send: '{"type":"join","room":"test"}'
      - think: 1
      - send: '{"type":"edit"}'

运行命令：

artillery run artillery.yml

冲突场景测试

测试并发编辑：

test('concurrent edit converges', async ({ browser }) => {
  const [ctx1, ctx2] = await Promise.all([browser.newContext(), browser.newContext()]);

  const [page1, page2] = await Promise.all([ctx1.newPage(), ctx2.newPage()]);

  await Promise.all([page1.goto('/doc/concurrent'), page2.goto('/doc/concurrent')]);

  // 并发编辑
  await Promise.all([page1.locator('.editor').type('AAA'), page2.locator('.editor').type('BBB')]);

  await page1.waitForTimeout(2000);

  // 两端应该收敛
  const text1 = await page1.locator('.editor').textContent();
  const text2 = await page2.locator('.editor').textContent();

  expect(text1).toBe(text2);
  expect(text1).toContain('AAA');
  expect(text1).toContain('BBB');
});

反模式
1. 仅做单客户端测试：


    

  • 会遗漏协作相关的缺陷。
    • 



2. 不测试离线场景：


    

  • 生产环境中用户离线时会出现故障。
    • 



3. 不做负载测试：


    

  • 发布后遭遇意外崩溃。
    • 



4. 不做混沌测试：


    

  • 生产环境脆弱不堪。
    • 



5. 不监控生产环境：


    

  • 故障发生时无法及时发现。
    • 



6. 仅验证 CRDT 属性：


    

  • 会遗漏实际用户体验层面的缺陷。
    • 



实战建议
1. 分层测试：


    

  • 单元测试（CRDT）+ 集成测试（同步）+ 端到端测试（多客户端）+ 负载测试，层层覆盖。
    • 



2. Playwright 多页面模式：


    

  • 这是协作应用测试的核心手段。
    • 



3. 每个 PR 运行 CI：


    

  • 及时捕获回归问题。
    • 



4. 生产环境监控：


    

  • 追踪真实用户指标。
    • 



5. 发布前进行混沌测试：


    

  • 验证网络分区、慢速网络、断连等极端场景。
    • 



6. 内存增长测试：


    

  • 确保长时间运行不会泄漏。
    •

小结
实时协作应用的测试涵盖多客户端模拟、CRDT 收敛验证、网络状况模拟、离线场景、冲突解决和负载测试等维度。单元测试使用 Vitest/Jest 验证并发编辑收敛、删除与插入组合、交换律与幂等性。集成测试通过 WebSocket 验证完整同步流程——两个文档连接、同步、验证一致性。端到端测试使用 Playwright 多页面模式创建两个浏览器上下文模拟不同用户，验证编辑可见性与光标同步。网络状况测试覆盖离线编辑后重连同步、慢速网络延迟注入。负载测试使用 k6 模拟上千并发 WebSocket 连接，关注连接成功率与延迟分位数；也可用 Artillery 作为替代方案。冲突场景测试验证并发编辑后两端收敛且内容完整。生产监控追踪并发连接数、消息速率、延迟分位数、重连率、错误率、文档体积增长，常用 Prometheus + Grafana 或 Datadog 配合自定义遥测。CI/CD 在每个 PR 上运行单元测试、端到端测试和负载测试，设置延迟阈值作为质量门禁。混沌测试使用 Toxiproxy 注入延迟、丢包、断连验证应用韧性。内存泄漏测试关注长时间运行下的堆内存增长，特别是 Y.Doc 墓碑数据的垃圾回收问题。视觉回归测试通过截图比对验证多人光标渲染正确性。避免仅做单客户端测试、忽略离线场景、不做负载测试和混沌测试、不监控生产环境等反模式。建议采用分层测试策略，将 Playwright 多页面模式作为协作测试核心，坚持 CI 回归检测，完善生产监控，发布前进行混沌测试，并关注长期内存增长。
