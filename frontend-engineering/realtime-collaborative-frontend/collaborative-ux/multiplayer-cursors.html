多人光标

核心概念

多人光标是协作应用中最直观的功能——实时看到其他用户的光标让产品感觉"鲜活"。Figma 于 2016 年推广了这一模式，Google Docs 随后加入，Notion、Linear 跟进，Liveblocks 提供 React hooks 让实现变得简单。设计多人光标需要考虑：光标颜色（区分用户）、姓名标签、平滑动画、性能（节流 + 插值）、扩展性（50+ 用户不卡顿）以及边界情况（屏幕外光标如何提示）。本节介绍多人光标的设计、技术实现、性能优化和 UX 模式。

方面 建议
更新频率 20-30 Hz（50ms 节流）
颜色 每用户固定，通过 ID 哈希生成
姓名标签 紧凑，闲置后淡出
动画 CSS transition 100ms
屏幕外 边缘指示器
不活跃 闲置 5 秒后淡出
层级 在内容之上，在弹窗之下

光标视觉设计

指针形状：

  • 模拟操作系统光标。
  • 或简单的尖角形状。
  • 按用户颜色编码。

姓名标签：

  • 跟随光标移动。
  • 显示用户名（或缩写）。
  • 使用用户颜色作为背景。
  • 紧凑显示（最多 8-12 个字符）。

示例 HTML：

<div className="cursor" style={{ left: x, top: y }}>
  <Pointer color={color} />
  <span className="name" style={{ background: color }}>
    {name}
  </span>
</div>
.cursor {
  position: absolute;
  pointer-events: none;
  transition: transform 100ms ease;
  z-index: 1000;
}

.cursor .name {
  margin-left: 12px;
  padding: 2px 6px;
  border-radius: 4px;
  font-size: 11px;
  color: white;
  white-space: nowrap;
}

颜色分配

每用户稳定颜色：

const COLORS = [
  '#FF6B6B',
  '#4ECDC4',
  '#45B7D1',
  '#FFA07A',
  '#98D8C8',
  '#F7DC6F',
  '#BB8FCE',
  '#85C1E2',
  '#FFB347',
  '#B19CD9',
  '#FF7F50',
  '#90EE90',
];

function userColor(userId) {
  let hash = 0;
  for (let i = 0; i < userId.length; i++) {
    hash = (hash << 5) - hash + userId.charCodeAt(i);
  }
  return COLORS[Math.abs(hash) % COLORS.length];
}

特性：

  • 同一用户始终显示相同颜色。
  • 颜色之间有足够区分度（HSL 空间分离）。
  • 对色盲用户友好（足够对比度）。

坐标系统

页面相对坐标：

{ x: e.pageX, y: e.pageY }
  • 追踪滚动感知的位置。

视口相对坐标：

{ x: e.clientX, y: e.clientY }
  • 不感知滚动。
  • 需要根据各用户滚动位置调整。

容器相对坐标：

const rect = container.getBoundingClientRect();
{ x: e.clientX - rect.left, y: e.clientY - rect.top }
  • 相对于特定元素。

如何选择：

  • 文档应用：使用页面相对坐标。
  • 白板应用：使用画布相对坐标。
  • 用户滚动位置不同时需要进行坐标转换。

节流处理

以 20 Hz（50ms）更新：

import { throttle } from 'lodash';

const updateCursor = throttle((e) => {
  provider.awareness.setLocalStateField('cursor', {
    x: e.pageX,
    y: e.pageY,
  });
}, 50);

document.addEventListener('mousemove', updateCursor);

更高频率：

  • 60 Hz 看起来很丝滑但带宽消耗高。
  • 20 Hz 配合平滑动画通常已足够。

平滑动画

无动画的问题：

  • 光标在 20 Hz 下逐帧跳动。
  • 视觉上有卡顿感。

CSS transition 方案：

.cursor {
  transition: transform 100ms ease;
}
// 通过 transform 更新位置
element.style.transform = `translate(${x}px, ${y}px)`;

效果：

  • 浏览器在 100ms 内自动动画。
  • 接近流畅的视觉效果。

插值方案（进阶）：

// 向目标位置线性插值
function animate() {
  const target = remoteCursor;
  current.x = lerp(current.x, target.x, 0.2);
  current.y = lerp(current.y, target.y, 0.2);
  cursor.style.transform = `translate(${current.x}px, ${current.y}px)`;
  requestAnimationFrame(animate);
}

优点：

  • 即使更新频率低也能保持流畅。
  • 60 fps 渲染。

屏幕外光标

当用户光标在视口外时：

function isOffscreen(x, y, viewport) {
  return x < viewport.left || x > viewport.right || y < viewport.top || y > viewport.bottom;
}

边缘指示器：

{
  isOffscreen(cursor) && (
    <EdgeIndicator direction={getDirection(cursor, viewport)} color={user.color} name={user.name} />
  );
}

视觉效果：

  • 在屏幕边缘显示箭头指向光标方向。
  • 点击可跳转到该用户位置。

闲置淡出

光标超过 5 秒不移动时淡出：

.cursor {
  opacity: 1;
  transition: opacity 500ms;
}

.cursor.idle {
  opacity: 0.3;
}
let idleTimer;
function onCursorUpdate() {
  cursor.classList.remove('idle');
  clearTimeout(idleTimer);
  idleTimer = setTimeout(() => cursor.classList.add('idle'), 5000);
}

UX 效果：

  • 减少闲置用户的视觉干扰。
  • 移动时重新激活显示。

断开连接处理

用户离开时光标消失：

provider.awareness.on('change', () => {
  const states = provider.awareness.getStates();
  // 移除不在 states 中的用户光标
});

淡出效果：

.cursor.leaving {
  opacity: 0;
  transition: opacity 300ms;
}

点击指示器

显示其他用户的点击动作：

provider.awareness.on('change', () => {
  states.forEach((state) => {
    if (state.click) {
      showRipple(state.click.x, state.click.y, state.user.color);
    }
  });
});

document.addEventListener('click', (e) => {
  provider.awareness.setLocalStateField('click', {
    x: e.pageX,
    y: e.pageY,
    time: Date.now(),
  });
});

效果：

  • 在点击位置显示涟漪动画。
  • 逐渐淡出。

选择区域与范围

显示其他用户的文本选择：

{
  others.map(
    (o) =>
      o.selection && <SelectionOverlay key={o.id} from={o.selection.from} to={o.selection.to} color={o.user.color} />,
  );
}

视觉效果：

  • 在选中文本上显示半透明矩形。
  • 使用用户颜色。
  • 在末尾显示姓名标签。

性能优化

100 用户 × 30 Hz = 每秒 3000 条消息：

  • 服务器带宽压力大。
  • 优化方向：

1. 提高节流阈值：

  • 10-15 Hz 也可接受。

2. 压缩数据：

  • 只发送变化的部分（Delta）。
  • 或批量发送。

3. 服务器扇出：

  • 使用 Redis 发布/订阅。

4. 空间分区：

  • 只发送视口区域内的光标。
  • 类似游戏中的区域裁剪。

移动端适配

触屏设备没有光标：

  • 移动端跳过光标显示？
  • 替代方案：显示"点击"指示器。
  • 显示更为克制。

或在触摸时显示光标：

  • 点击时短暂高亮。
  • 显示用户在哪个位置活跃。

Z-index 层级

光标必须在内容之上：

.cursor {
  z-index: 1000;
}

但在弹窗之下：

.modal {
  z-index: 2000;
}

拖拽/选择操作期间：

  • 临时降低自己的光标层级（不阻碍用户操作）。

无障碍设计

屏幕阅读器：

  • 不播报远程光标（纯视觉功能）。

键盘用户：

  • 光标非核心 UX（鼠标驱动）。
  • 提供替代的在线感知 UI（在线用户列表）。

高对比度主题：

  • 确保光标在高对比度主题下可见。

现代工具

Liveblocks：

import { useOthers } from '@liveblocks/react';

function Cursors() {
  const others = useOthers();
  return others.map((o) => <Cursor key={o.connectionId} cursor={o.presence.cursor} user={o.info} />);
}

内置节流和平滑动画。

PartyKit：

  • 提供类似的 React hooks。

Yjs awareness：

  • 更底层。
  • 需要手动设置。

常见陷阱

1. 不做节流：

  • 100 Hz 的 mousemove → 服务器过载。

2. 不做动画：

  • 视觉卡顿。

3. 使用固定定位坐标：

  • 不感知滚动位置。

4. 所有用户相同颜色：

  • 造成混淆。

5. 断开后不消失：

  • 产生幽灵光标。

6. 姓名标签太大：

  • 视觉杂乱。

实战建议

1. 节流 50ms（20 Hz）：

  • 最佳平衡点。

2. CSS transition 平滑动画：

  • 无需手动动画逻辑。

3. 稳定的每用户颜色：

  • 通过用户 ID 哈希。

4. 紧凑的姓名标签：

  • 最多 8-12 个字符。

5. 闲置淡出：

  • 5 秒不移动则淡出。

6. 测试 50+ 用户场景：

  • 检验性能边界。

真实案例

Figma：

  • 流畅的光标 + 姓名。
  • 点击涟漪效果。
  • 点击后视角跟随。

Google Docs：

  • 行内文本光标。
  • 颜色编码。

Notion：

  • 低调的光标。
  • 完整的在线用户头像列表。

Liveblocks 演示：

  • 业界最佳的多人光标实现。

小结

多人光标是协作应用中最直观的功能——实时看到其他用户让产品感觉鲜活。视觉设计包括指针形状（或尖角）加紧凑姓名标签（8-12 字符）跟随光标，使用用户颜色作为背景。颜色通过哈希用户 ID 到调色板索引实现稳定分配（12 种有区分度且可访问的颜色）。坐标系统：文档应用使用页面相对（滚动感知），固定 UI 使用视口相对，画布/白板使用容器相对，不同用户滚动位置需要坐标转换。节流到 20 Hz（50ms），60 Hz 丝滑但带宽高。平滑动画使用 CSS transition 100ms ease 配合 transform，或使用 requestAnimationFrame 进行线性插值实现进阶效果。屏幕外光标使用边缘指示器箭头加点击跳转。闲置 5 秒后淡出减少视觉干扰，移动时重新激活。断开时从状态列表中移除并淡出 300ms。点击指示器在点击位置显示涟漪动画。性能方面 100 用户 × 30 Hz 压力大——可提高节流阈值到 10-15 Hz、压缩发送 Delta、Redis 发布/订阅扇出、空间分区只发视口区域。移动端触屏无光标可用点击指示替代。Z-index 设置为 1000 在内容之上但低于弹窗 2000。无障碍方面不通过屏幕阅读器播报，键盘用户使用替代在线感知 UI，确保高对比度可见。现代工具 Liveblocks React hooks 内置节流动画，PartyKit 类似，Yjs awareness 较底层需手动配置。
