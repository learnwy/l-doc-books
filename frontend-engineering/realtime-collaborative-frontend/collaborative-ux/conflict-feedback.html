Part IV · 浏览器与平台 (Browser & Platform)实时协作前端协作 UX冲突反馈

冲突反馈

核心概念

即使 CRDT 能自动合并——某些冲突仍需要用户感知。例如，两个用户同时编辑同一段落，合并后结果可能不符预期；同一用户在多个标签页编辑；离线编辑重新上线后的合并。良好的 UX 应该做到：细微提示（不惊吓用户）、需要时让用户自行解决、保留撤销能力。与传统文件系统的"合并冲突"不同——协作应用通常静默合并，但视觉提示是有价值的。本节介绍冲突反馈的 UX 模式、细微指示器、显式冲突解决 UI、协作中的撤销/重做以及历史视图。

冲突类型 UX 处理方式
CRDT 自动合并 静默处理（大多数情况）
同用户多标签页 "已同步"指示器
离线恢复在线后合并 "已同步"或通知
编辑分叉（罕见） 行内指示器
连接丢失 横幅提示 + 重试

CRDT 静默合并

最常见的情况：

  • 两个用户同时编辑不同部分。
  • CRDT 自动合并。
  • 用户不知道发生了冲突。

文本场景：

  • Yjs 的 Yata 序列自动合并。
  • 自动校正顺序。

不需要 UI——这正是设计意图。

何时展示冲突

细微指示器：

  • 不打断用户流程。
  • 提示有内容已同步。

显式 UI：

  • 关键冲突场景。
  • 用户必须手动解决。
  • 在 CRDT 中很少出现。

完全隐藏：

  • 大多数协作应用倾向于此。
  • 信任 CRDT 的自动合并。

细微指示器

同步状态显示：

{
  syncing ? <span>同步中...</span> : <span>✓ 已同步</span>;
}

位置：

  • 放在不显眼的位置（右下角）。
  • 非弹窗形式。

用户看到的：

  • 大部分时间显示"已同步"。
  • 短暂的"同步中..."。

连接丢失横幅

当用户处于离线状态时：

{
  !online && <Banner>您当前处于离线状态。更改已保存到本地，重新连接后将自动同步。</Banner>;
}

重新连接后：

  • 自动关闭横幅。
  • 短暂显示"已同步 ✓"提示。

多标签页冲突

同一用户在多个标签页编辑：

  • 每个标签页是独立的客户端。
  • CRDT 会自动合并。
  • 但可能让用户感到困惑。

UX 处理：

  • 通过 BroadcastChannel 检测。
  • 显示"在另一个标签页中编辑"警告？
  • 或静默同步。
const channel = new BroadcastChannel('app');
channel.postMessage({ type: 'tab-active', id: tabId });

channel.onmessage = (event) => {
  if (event.data.type === 'tab-active' && event.data.id !== tabId) {
    showWarning('在另一个标签页中编辑');
  }
};

离线编辑合并

重新连接后：

  • 推送本地待确认操作。
  • 拉取远程操作。
  • CRDT 自动合并。

UX 处理：

  • 显示"正在同步 X 项更改..."。
  • 完成后显示"已同步 ✓"。
  • 成功时也可静默处理。

如果出现冲突（CRDT 中很少发生）：

  • 提示"部分更改可能已被自动调整"。
  • 关键内容可展示差异对比。

更新丢失检测

CRDT 不会丢失更新：

  • 但用户可能感到困惑。
  • 例如：A 删除段落，B 同时在编辑该段落。

UX 处理：

  • 在 CRDT 中段落仍然存在（保留了 B 的编辑）。
  • 但 A 的意图是删除。
  • 用户是否需要冲突视图？

Yjs 默认行为：

  • 保留 B 的编辑内容。
  • A 不知道段落"回来了"。

可选方案：

  • 显示"此段落有新的更改"提示。
  • 让用户重新决定。

行内指示器

近期编辑指示器：

<div className="paragraph">
  {paragraph.text}
  {paragraph.lastEditedRecently && (
    <span className="badge" style={{ background: paragraph.lastEditor.color }}>
      由 {paragraph.lastEditor.name} 更新
    </span>
  )}
</div>

3-5 秒后淡出：

  • 细微的幽灵效果。
  • 让用户注意到变化。

协作中的撤销/重做

仅撤销本地操作：

  • 每个用户只能撤销自己的操作。
  • 不能撤销他人的。

Yjs UndoManager：

import { UndoManager } from 'yjs';

const undoManager = new UndoManager(text, {
  trackedOrigins: new Set([currentUser.id]),
});

undoManager.undo(); // 仅撤销自己的操作
undoManager.redo();

选择性撤销：

  • 追踪每个操作的来源（Origin）。
  • 按来源过滤，只撤销自己的操作。

难点：

  • 如果其他用户在自己的操作之间有编辑，撤销会跳过这些内容。

协作撤销

部分应用实现了：

  • 显示"撤销 Alice 的上次编辑"。
  • 多用户撤销按钮。

UX 定位：

  • 高级用户功能。
  • 非默认提供。

历史视图

时间旅行：

  • 查看过去某个时刻的文档状态。
  • 标注每位协作者的更改。

Yjs 实现：

  • 追踪更新二进制数据。
  • 回放到过去状态。
  • 没有默认 UI。

Notion / Google Docs：

  • 内置版本历史。
  • 显示"Alice 于 2 小时前修改"。

实现方式：

const updates = [];
doc.on('update', (update) => {
  updates.push({ update, timestamp: Date.now() });
});

function rewind(toTime) {
  const filtered = updates.filter((u) => u.timestamp <= toTime);
  const newDoc = new Y.Doc();
  filtered.forEach(({ update }) => Y.applyUpdate(newDoc, update));
  return newDoc;
}

评论与解决

围绕内容的对话：

  • 在选择区域上添加评论线程。
  • 解决后标记为已完成。

与 CRDT 自动合并不同：

  • 评论是显式的用户交互。
  • 非静默处理。

实现方式：

  • 评论作为单独的 Y.Map 存储。
  • 锚定到文档位置。

编辑感知

"Alice 正在编辑此段落"：

{
  paragraph.activeEditors.map((editor) => <span style={{ color: editor.color }}>{editor.name} 正在编辑</span>);
}

检测方式：

  • Awareness 发布当前光标/选择位置。
  • 检查是否在段落范围内。

自动保存指示器

持续的保存状态显示：

const [status, setStatus] = useState('saved');

useEffect(() => {
  doc.on('update', () => {
    setStatus('saving');
    debouncedFlush();
  });
}, []);

return (
  <div className="status">
    {status === 'saving' && '保存中...'}
    {status === 'saved' && '✓ 已保存'}
    {status === 'error' && '⚠ 保存失败'}
  </div>
);

UX 设计：

  • 非弹窗形式。
  • 放在不显眼的位置。

错误处理

保存失败：

  • 显示"保存失败，正在重试..."。
  • 使用指数退避重试。

永久失败：

  • 显示"无法保存，请检查网络连接"。
  • 本地持久化保存。
  • 提供手动重试按钮。

冲突解决弹窗（罕见场景）

用于关键冲突：

<Modal>
  <h3>检测到冲突</h3>
  <p>标题有两个不同的更改，您希望保留哪个？</p>
  <div className="diff">
    <div className="local">
      <h4>您的版本</h4>
      <p>{local.title}</p>
    </div>
    <div className="remote">
      <h4>他人版本</h4>
      <p>{remote.title}</p>
    </div>
  </div>
  <button onClick={() => keepLocal()}>保留我的</button>
  <button onClick={() => keepRemote()}>保留他人的</button>
</Modal>

使用场景：

  • 标题/元数据冲突。
  • 单值字段。
  • 使用 MV-Register（多值寄存器）CRDT 时。

真实案例

Notion：

  • 大多静默合并。
  • "近期更新"的细微提示标记。
  • 版本历史。

Linear：

  • 静默合并。
  • 大多数情况不显示冲突 UI。

Figma：

  • 静默合并。
  • 通过实时光标让协作过程透明可见。

Google Docs：

  • OT 静默合并。
  • 偶尔显示"重新连接后将保存您的编辑"。

反模式

1. 每次变更都弹冲突弹窗：

  • 烦人且打断流程。

2. 不显示同步状态：

  • 用户不确定是否已保存。

3. 过于醒目的通知：

  • "冲突！"之类的惊吓提示。
  • 细微提示更好。

4. 协作中不支持撤销：

  • 用户期望有撤销功能。

5. 不提示离线状态：

  • 静默失败让用户困惑。

6. 不处理重连场景：

  • 用户卡在离线状态。

实战建议

1. 信任 CRDT 自动合并：

  • 大多数情况不需要冲突 UI。

2. 使用细微指示器：

  • "已保存" / "同步中"。

3. 离线状态横幅：

  • 清晰且可操作。

4. 使用 Yjs UndoManager 实现本地撤销：

  • 按用户隔离。

5. 版本历史：

  • 高级用户的安全网。

6. 测试重连场景：

  • 模拟真实离线情况。

小结

即使 CRDT 能自动合并，某些冲突仍需要用户感知。CRDT 静默合并是大多数情况，用户无需知道，大多数协作应用选择此方式。何时展示冲突：细微指示器不打断流程、显式 UI 用于关键冲突（CRDT 中罕见）、完全隐藏（大多数选择）。细微指示器显示同步状态（"同步中..." / "✓ 已同步"），放在右下角非弹窗位置。连接丢失横幅提示离线状态和本地保存，重连后自动关闭并显示"已同步"。多标签页冲突通过 BroadcastChannel 检测，可显示警告或静默同步。离线编辑合并重连后推送/拉取/CRDT 合并，显示同步进度或静默处理。更新丢失检测中 CRDT 不丢失但用户可能困惑（B 编辑保留而 A 删除无效），可选行内提示让用户重新决定。行内指示器显示近期编辑者的标记 3-5 秒后淡出。撤销/重做使用 Yjs UndoManager 按用户来源过滤，仅撤销自己的操作。历史视图通过存储更新实现时间旅行回放，Notion/Google Docs 内置版本历史。评论是显式交互锚定到文档位置，与静默合并不同。冲突解决弹窗仅用于罕见的关键冲突（标题/元数据/单值字段），展示"保留我的/保留他人的"选择。
