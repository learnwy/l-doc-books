Awareness 与在线感知（Presence）

核心概念

Awareness（感知）和 Presence（在线状态）是协作应用的"轻量状态"——谁在线、光标位置、选择区域、正在输入指示器等。这些状态是临时的（不持久化），与文档状态分开处理（不参与冲突合并）。Yjs 内置了 awareness API，Liveblocks 提供 React hooks，PartyKit 和 Replicache 也支持此功能。多人光标和在线感知让协作应用感觉"鲜活"——看到其他用户的存在能提升生产力和信任感。本节介绍 awareness API（Yjs）、presence 模式（Liveblocks）、性能考量（光标更新高频）以及 UX 模式。

状态类型 示例 存储方式
文档状态 文本内容、布局 CRDT 持久化
Awareness 状态 光标、选择区域 临时，不同步存储
Presence 状态 在线用户 临时，广播
用户身份 姓名、头像、颜色 应用层管理

Awareness 与文档状态的区别

文档状态：

  • 持久化。
  • 由 CRDT 追踪。
  • 需要冲突解决。
  • 示例：文本内容、布局、设置。

Awareness 状态：

  • 临时的（每个会话）。
  • 断开连接时不持久化。
  • 不参与冲突合并。
  • 示例：光标位置、选择区域、在线状态、正在输入指示。

为什么要分开：

  • 光标每秒更新 100 次，不应污染文档历史。
  • 用户断开连接后光标消失（正确的 UX 行为）。
Yjs Awareness API
内置于 y-websocket：


const provider = new WebsocketProvider('wss://...', 'room', doc);

// 设置本地状态
provider.awareness.setLocalStateField('user', {
  name: 'Alice',
  color: '#ff0000',
});

provider.awareness.setLocalStateField('cursor', {
  x: 100,
  y: 200,
});

// 监听状态变化
provider.awareness.on('change', () => {
  const states = Array.from(provider.awareness.getStates().values());
  console.log(states); // 所有用户的 awareness 状态
});
内部机制：


    

  • 每个客户端发布自己的状态。
    • 

  • 其他用户接收状态更新。
    • 

  • 不存储在 Y.Doc 中。
    • 



光标追踪
鼠标位置追踪：


document.addEventListener(
  'mousemove',
  throttle((e) => {
    provider.awareness.setLocalStateField('cursor', {
      x: e.clientX,
      y: e.clientY,
    });
  }, 50),
); // 节流 20 Hz
节流/防抖：


    

  • 每秒 100 次鼠标移动事件太多。
    • 

  • 20-30 Hz 是最佳平衡点。
    • 

  • 减少网络流量和 CPU 开销。
    • 



选择区域追踪
文本选择追踪：


editor.on('selectionUpdate', ({ editor }) => {
  const { from, to } = editor.state.selection;
  provider.awareness.setLocalStateField('selection', { from, to });
});
在光标或选择变化时更新。


多人光标 UX
渲染其他用户的光标：


function MultiplayerCursors() {
  const [states, setStates] = useState([]);

  useEffect(() => {
    const update = () => {
      const arr = Array.from(provider.awareness.getStates().entries())
        .filter(([id]) => id !== provider.awareness.clientID)
        .map(([id, state]) => ({ id, ...state }));
      setStates(arr);
    };
    provider.awareness.on('change', update);
    return () => provider.awareness.off('change', update);
  }, []);

  return states.map((s) => (
    <div
      key={s.id}
      className="remote-cursor"
      style={{
        position: 'absolute',
        left: s.cursor?.x,
        top: s.cursor?.y,
        color: s.user?.color,
      }}
    >
      <span>{s.user?.name}</span>
    </div>
  ));
}
视觉效果：


    

  • 光标 + 用户名。
    • 

  • 每用户不同颜色。
    • 

  • 更新之间的平滑动画。
    • 



在线用户（Presence）
显示房间内的用户：


function OnlineUsers() {
  const [users, setUsers] = useState([]);

  useEffect(() => {
    const update = () => {
      const arr = Array.from(provider.awareness.getStates().values())
        .map((s) => s.user)
        .filter(Boolean);
      setUsers(arr);
    };
    provider.awareness.on('change', update);
    return () => provider.awareness.off('change', update);
  }, []);

  return (
    <div className="presence">
      {users.map((u) => (
        <Avatar key={u.id} src={u.avatar} title={u.name} color={u.color} />
      ))}
    </div>
  );
}
UX 设计：


    

  • 头像堆叠显示。
    • 

  • 用户多时显示 "+N"。
    • 

  • 点击头像可跳转到该用户光标位置。
    • 



正在输入指示器
聊天风格的"Alice 正在输入..."：


let typingTimeout;
input.addEventListener('input', () => {
  provider.awareness.setLocalStateField('typing', true);
  clearTimeout(typingTimeout);
  typingTimeout = setTimeout(() => {
    provider.awareness.setLocalStateField('typing', false);
  }, 2000);
});
渲染：


const typingUsers = states.filter((s) => s.typing).map((s) => s.user.name);
return typingUsers.length > 0 && <p>{typingUsers.join(', ')} 正在输入...</p>;
Liveblocks Presence
React hooks：


import { useMyPresence, useOthers } from '@liveblocks/react';

function App() {
  const [myPresence, updateMyPresence] = useMyPresence();
  const others = useOthers();

  useEffect(() => {
    document.addEventListener('mousemove', (e) => {
      updateMyPresence({ cursor: { x: e.clientX, y: e.clientY } });
    });
  }, []);

  return (
    <>
      <MyCursor cursor={myPresence.cursor} />
      {others.map((other) => (
        <Cursor key={other.connectionId} cursor={other.presence.cursor} />
      ))}
    </>
  );
}
托管基础设施——Liveblocks 负责服务器管理。


性能优化
高频更新问题：


    

  • 光标每秒 30+ 次更新。
    • 

  • 多用户 → 消息量指数级增长。
    • 



优化策略：


    

  • 节流（50ms = 20 Hz）。
    • 

  • 批量处理（将光标和选择合并为一次更新）。
    • 

  • 只发送变化的部分（Delta）。
    • 



服务器压力：


    

  • Awareness 的扇出（Fan-out）广播。
    • 

  • 使用高效的消息代理（如 Redis 发布/订阅）。
    • 



带宽考量：


    

  • 每秒每个用户 1 条消息已经很重。
    • 

  • 100 用户 × 30 Hz = 每秒 3000 条消息。
    • 

  • 可考虑压缩。
    • 



Awareness 持久化
断开连接时：


    

  • Awareness 状态应该消失。
    • 

  • 其他用户不应看到幽灵光标。
    • 



Yjs 自动处理：


    

  • 断开连接时广播移除消息。
    • 

  • 其他用户自动过滤掉。
    • 



过期的 Awareness：


    

  • 如果 30 秒内没有更新，强制超时。
    • 

  • 移除不活跃的用户状态。
    • 



用户身份
持久化身份信息：


    

  • 用户资料存储在数据库（姓名、头像）。
    • 

  • 认证令牌（Auth Token）。
    • 



附加到 Awareness：


provider.awareness.setLocalStateField('user', {
  id: currentUser.id,
  name: currentUser.name,
  avatar: currentUser.avatar,
  color: assignColor(currentUser.id),
});
稳定的颜色分配：


    

  • 通过用户 ID 哈希生成一致的颜色。
    • 

  • 同一用户总是显示相同颜色。
    • 



颜色分配算法
从用户 ID 生成颜色：


function assignColor(userId) {
  const colors = ['#FF6B6B', '#4ECDC4', '#45B7D1', '#FFA07A', '#98D8C8', '#F7DC6F', '#BB8FCE', '#85C1E2'];
  const hash = userId.split('').reduce((a, c) => a + c.charCodeAt(0), 0);
  return colors[hash % colors.length];
}
颜色选择原则：


    

  • 颜色间有足够区分度。
    • 

  • 对色盲用户友好（可访问性）。
    •

隐私设置
Awareness 会暴露用户活动：


    

  • 用户可能不希望分享闲置状态或输入状态。
    • 



设置选项：


    

  • 切换"显示我的光标"。
    • 

  • 匿名模式。
    • 



细粒度控制：


    

  • 按房间设置。
    • 

  • 按团队设置。
    • 



反模式
1. 将 Awareness 存储在 Y.Doc 中：


    

  • 会污染文档历史。
    • 

  • 应使用独立的 awareness API。
    • 



2. 高频更新不节流：


    

  • 导致服务器过载。
    • 

  • 应节流到 20 Hz。
    • 



3. 断开后不移除状态：


    

  • 产生幽灵光标。
    • 



4. 所有用户使用相同颜色：


    

  • 造成混淆。
    • 

  • 应为每用户分配不同颜色。
    • 



5. 不显示用户身份：


    

  • 匿名光标价值较低。
    • 



实战建议
1. 使用 Yjs awareness API：


    

  • 或 Liveblocks（如使用 PaaS）。
    • 



2. 节流到 20-30 Hz：


    

  • 流畅且网络开销合理。
    • 



3. 颜色编码：


    

  • 使用有区分度且可访问的颜色调色板。
    • 



4. 显示头像和姓名：


    

  • 身份信息清晰可见。
    • 



5. 添加动画：


    

  • CSS transition 或插值实现平滑效果。
    • 



6. 提供隐私选项：


    

  • 让用户可以禁用光标显示。
    •

小结
Awareness 和 Presence 是协作应用的"轻量状态"——光标、选择区域、输入状态、在线状态等，这些临时状态不持久化也不参与冲突合并，与文档状态分开处理（光标每秒 100 次更新不应污染历史）。Yjs awareness API 内置于 y-websocket，通过 provider.awareness.setLocalStateField 设置状态，on('change') 获取所有用户状态。光标追踪通过 mousemove 事件节流到 20-30 Hz（50ms）。选择追踪通过编辑器的 selectionUpdate 事件发布 from/to。多人光标 UX 渲染其他用户光标，配合颜色编码和姓名标签及动画。在线用户以头像堆叠形式显示，点击可跳转。输入指示器通过 setTimeout 在输入事件后重置。Liveblocks 提供 React hooks（useMyPresence + useOthers）及托管基础设施。高频更新优化策略：节流 50ms、批量合并、只发送变化部分、使用高效代理（Redis）进行扇出。断开连接时 Yjs 自动移除，过期状态 30 秒超时强制移除。用户身份附加姓名/头像/颜色，稳定颜色通过哈希用户 ID 到调色板索引（8-12 种有区分度的可访问颜色）。光标动画使用 CSS transition 100ms 或插值追踪速度预测。选择高亮使用半透明矩形覆盖和姓名标签。隐私设置包括切换"显示光标"、匿名模式、按房间细粒度控制。反模式：awareness 存在 Y.Doc（污染历史）、高频不节流、断开不移除（幽灵光标）、相同颜色（混淆）、无身份信息。
