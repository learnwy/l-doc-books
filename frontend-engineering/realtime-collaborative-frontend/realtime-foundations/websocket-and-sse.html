WebSocket 与 SSE

核心概念

WebSocket（W3C 标准，2011）与 Server-Sent Events（SSE，2009）是 Web 实时通信的两大主流传输协议。WebSocket 提供双向长连接，延迟极低，适合聊天、协作编辑和游戏场景；SSE 是基于 HTTP 的服务器到客户端单向流，实现简单，适合通知推送、实时动态和 AI 流式输出。相比早期的长轮询（Long Polling）和 Comet 技术，两者在性能和开发体验上有大幅提升。本节介绍 WebSocket 与 SSE 的协议细节、浏览器 API、性能特征、扩展方案、适用场景以及常见陷阱。

维度 WebSocket SSE 长轮询
方向 双向通信 仅服务器→客户端 模拟双向
协议 WS/WSS 升级 HTTP HTTP
延迟 低 低 高
重连 需手动实现 内置自动重连 需手动实现
代理兼容 部分支持 一般支持 易支持
适用场景 聊天/协作/游戏 通知/动态流 旧浏览器兼容

WebSocket 协议

从 HTTP 升级连接：

GET /chat HTTP/1.1
Host: example.com
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==
Sec-WebSocket-Version: 13

服务器响应：

HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=

升级完成后：

  • TCP 连接持续保持。
  • 双方可随时发送数据帧。
  • 支持二进制和文本格式。

客户端 API

const ws = new WebSocket('wss://example.com/chat');

ws.addEventListener('open', () => {
  console.log('Connected');
  ws.send('Hello');
});

ws.addEventListener('message', (event) => {
  console.log('Received:', event.data);
});

ws.addEventListener('close', (event) => {
  console.log('Closed', event.code, event.reason);
});

ws.addEventListener('error', (event) => {
  console.error('Error', event);
});

// 发送数据
ws.send('text');
ws.send(JSON.stringify({ type: 'msg', text: 'hello' }));
ws.send(new Uint8Array([1, 2, 3])); // 二进制

// 关闭连接
ws.close(1000, 'Bye'); // 正常关闭

服务端实现（Node.js）

使用 ws 库：

import { WebSocketServer } from 'ws';

const wss = new WebSocketServer({ port: 8080 });

wss.on('connection', (ws) => {
  ws.on('message', (data) => {
    // 广播给所有客户端
    wss.clients.forEach((client) => {
      if (client.readyState === ws.OPEN) {
        client.send(data);
      }
    });
  });
});

其他语言实现：

  • Python：websockets 库。
  • Go：gorilla/websocket 库。
  • Rust：tokio-tungstenite 库。

SSE 协议

基于 HTTP：

GET /events HTTP/1.1
Accept: text/event-stream

服务器响应：

HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

data: hello

data: world

event: update
data: {"foo": "bar"}

格式说明：

  • data: 事件负载内容。
  • event: 命名事件类型。
  • id: 事件 ID（用于断线续传）。
  • retry: 重连延迟（毫秒）。

SSE 客户端 API

const es = new EventSource('/events');

es.addEventListener('message', (event) => {
  console.log(event.data);
});

es.addEventListener('update', (event) => {
  const data = JSON.parse(event.data);
  console.log(data);
});

es.addEventListener('error', (event) => {
  console.error('Error');
});

es.close();

自动重连特性：

  • 浏览器内置自动重连。
  • 从上次事件 ID 恢复接收。

SSE 服务端实现（Node.js）

import express from 'express';

const app = express();

app.get('/events', (req, res) => {
  res.set({
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    Connection: 'keep-alive',
  });

  const interval = setInterval(() => {
    res.write(`data: ${JSON.stringify({ time: Date.now() })}\n\n`);
  }, 1000);

  req.on('close', () => clearInterval(interval));
});
何时选择 WebSocket
需要双向通信时：


    

  • 即时聊天。
    • 

  • 协作编辑（如 Yjs 同步）。
    • 

  • 在线游戏。
    • 

  • 实时反馈交互。
    • 



对延迟要求极高时：


    

  • 交易系统。
    • 

  • 实时光标同步。
    • 



需要自定义协议时：


    

  • 二进制传输。
    • 

  • 长度前缀消息格式。
    • 



何时选择 SSE
仅需服务器向客户端推送时：


    

  • 通知推送。
    • 

  • 实时动态流（新闻、股票）。
    • 

  • AI 流式输出（类 ChatGPT 体验）。
    • 



追求简单实现时：


    

  • 基于 HTTP 协议（防火墙友好）。
    • 

  • 内置自动重连。
    • 

  • 无需 WebSocket 的复杂性。
    • 



大多数场景的判断：


    

  • 不需要双向通信 → 选 SSE。
    • 



何时使用长轮询
兼容旧系统或作为降级方案：


    

  • 老旧浏览器。
    • 

  • 严格的防火墙环境。
    • 



长轮询工作原理：


    

  • 客户端发送 GET 请求 → 服务器保持连接直到有数据。
    • 

  • 响应后客户端立即重新发送 GET 请求。
    • 



基本已被淘汰——SSE 和 WebSocket 已全面替代。

性能特征
WebSocket：


    

  • 延迟最低。
    • 

  • 持久连接。
    • 

  • 二进制传输高效。
    • 

  • 但服务器有状态（每连接占用内存）。
    • 



SSE：


    

  • 每条消息有 HTTP 头部开销。
    • 

  • 仅支持文本。
    • 

  • 浏览器限制每个源约 6 个连接。
    • 



优化方案：


    

  • 在一个连接上复用多个流。
    • 

  • WebSocket 子协议。
    • 

  • HTTP/2 下的 SSE（突破 6 连接限制）。
    • 



扩展方案
WebSocket 扩展：


    

  • 有状态（每个连接维护房间/用户信息）。
    • 

  • 水平扩展困难——需要 Redis 发布/订阅实现跨服务器通信。
    • 

  • 单服务器约支撑 10 万连接（经过调优）。
    • 



SSE 扩展：


    

  • 同样是每连接有状态。
    • 

  • 扩展挑战与 WebSocket 类似。
    • 

  • 但基于 HTTP 的特性更容易做负载均衡。
    • 



典型架构：


客户端 ↔ 负载均衡器 ↔ WS 服务器 1 / 2 / N ↔ Redis 发布/订阅
每个 WebSocket 服务器订阅 Redis 频道：


    

  • 从任意服务器接收消息。
    • 

  • 广播给本服务器上的客户端。
    • 



重连机制
WebSocket 需手动实现：


class ReconnectingWS {
  connect() {
    this.ws = new WebSocket(this.url);
    this.ws.addEventListener('close', () => {
      setTimeout(() => this.connect(), this.backoff());
    });
  }
  backoff() {
    return Math.min(1000 * 2 ** this.attempt++, 30000);
  }
}
SSE 自动重连：


    

  • 无需手动处理。
    • 

  • 自动从最后一个事件 ID 恢复接收。
    • 



推荐库：


    

  • robust-websocket。
    • 

  • ReconnectingWebSocket。
    • 



心跳保活
检测失效连接：


const interval = setInterval(() => {
  if (ws.readyState === WebSocket.OPEN) {
    ws.send(JSON.stringify({ type: 'ping' }));
  }
}, 30000);

ws.addEventListener('message', (event) => {
  const data = JSON.parse(event.data);
  if (data.type === 'pong') {
    // 重置超时计时器
  }
});
服务器需响应 pong 消息。


认证方式
WebSocket 认证：


    

  • 浏览器 API 不支持自定义请求头。
    • 

  • 替代方案：
      

    • URL 中携带令牌：wss://example.com/?token=xxx。
      • 

    • 子协议：new WebSocket(url, ['Bearer.token123'])。
      • 

    • 连接建立后首条消息携带令牌。
      • 

    

    • 



SSE 认证：


    

  • 支持 HTTP Cookie 和 Authorization 头部（需自定义实现）。
    • 

  • 但 EventSource 原生不支持自定义头部。
    • 

  • 通常使用 ?token=xxx 查询参数。
    • 



常见陷阱
1. 不实现重连：


    

  • 网络中断 → 用户连接丢失无法恢复。
    • 

  • 必须实现重连逻辑。
    • 



2. 不处理背压：


    

  • 发送速度过快 → 缓冲区溢出。
    • 

  • 需检查 readyState 和 bufferedAmount。
    • 



3. 不做心跳检测：


    

  • 连接可能已失效（代理超时断开）。
    • 

  • 心跳机制至关重要。
    • 



4. 令牌暴露在 URL 中：


    

  • 会记录在服务器访问日志中。
    • 

  • 存在泄露风险。
    • 

  • 使用短期令牌并定期轮换。
    • 



5. 不限制消息大小：


    

  • 存在拒绝服务攻击风险。
    • 

  • 服务器端需做校验。
    • 



6. 不优雅关闭连接：


    

  • 消息传输中途强制断开。
    • 

  • 应使用关闭码和原因说明。
    • 



WebSocket 子协议
协商通信协议：


const ws = new WebSocket('wss://example.com', ['chat.v2', 'chat.v1']);
服务器根据支持情况选择协议。


使用场景：


    

  • 协议版本管理。
    • 

  • 区分二进制和文本协议。
    • 



二进制 WebSocket
发送 Uint8Array 或 ArrayBuffer：


ws.binaryType = 'arraybuffer';
ws.send(new Uint8Array([1, 2, 3]).buffer);

ws.addEventListener('message', (event) => {
  if (event.data instanceof ArrayBuffer) {
    // 二进制数据
  } else {
    // 文本数据
  }
});
适用场景：


    

  • 游戏状态同步。
    • 

  • 压缩数据传输。
    • 

  • Avro / Protobuf 编码消息。
    • 



SSE 用于 AI 流式输出
类 ChatGPT 流式效果：


const es = new EventSource('/api/chat?prompt=...');
let response = '';

es.addEventListener('message', (event) => {
  if (event.data === '[DONE]') {
    es.close();
    return;
  }
  response += event.data;
  updateUI(response);
});
服务端处理：


    

  • 逐字流式输出 LLM 生成的 token。
    • 

  • 每个 token 作为一个 SSE 事件发送。
    • 



现代趋势
1. 边缘 WebSocket：


    

  • Cloudflare Durable Objects。
    • 

  • 每个房间具有强一致性。
    • 



2. WebTransport：


    

  • 基于 HTTP/3。
    • 

  • WebSocket 的替代方案。
    • 

  • 支持多路复用和不可靠传输模式。
    • 

  • 浏览器支持正在扩展。
    • 



3. SSE 用于 AI：


    

  • ChatGPT、Claude 都采用 SSE 流式输出。
    • 

  • 已成为主流应用场景。
    • 



反模式
1. 所有场景都用 WebSocket：


    

  • 对简单通知来说开销过大。
    • 

  • 仅需服务器推送时应使用 SSE。
    • 



2. 从零实现重连逻辑：


    

  • 应使用成熟的库。
    • 



3. 不做心跳检测：


    

  • 连接失效无法被发现。
    • 



4. 高频消息使用 JSON：


    

  • 解析速度慢。
    • 

  • 应使用二进制格式。
    • 



5. 单服务器架构：


    

  • 应使用 Redis 或集群方案。
    • 



实战建议
1. 选择合适的传输协议：


    

  • WebSocket：双向通信/低延迟场景。
    • 

  • SSE：服务器推送/简单场景/流式输出。
    • 



2. 生产环境使用成熟库：


    

  • ws（Node.js）。
    • 

  • socket.io（功能完备的方案）。
    • 



3. 实现心跳检测：


    

  • 通常设置 30 秒间隔。
    • 



4. 实现指数退避重连：


    

  • 延迟上限为 30 秒。
    • 



5. 使用短期令牌认证：


    

  • 定期轮换令牌。
    • 



6. 测试断线场景：


    

  • 网络中断、设备休眠、代理超时。
    • 



小结
WebSocket（2011）和 SSE（2009）是 Web 实时通信的两大传输协议。WebSocket 提供双向长连接，适合聊天、协作编辑、游戏等低延迟场景；SSE 是基于 HTTP 的服务器到客户端单向流，适合通知推送、实时动态和 AI 流式输出，且内置自动重连。WebSocket 通过 HTTP 升级建立连接（101 协议切换），之后在持久化 TCP 连接上传输二进制或文本帧。客户端使用 new WebSocket 并监听 open/message/close/error 事件。SSE 使用 Content-Type: text/event-stream，格式包含 data:、event:、id:、retry: 字段。性能方面，WebSocket 延迟最低但服务器有状态，SSE 有 HTTP 头开销且浏览器限制连接数（HTTP/2 可突破）。扩展方面，两者都需要 Redis 发布/订阅等方案实现跨服务器通信。认证方面，两者都不方便设置自定义头部，通常通过 URL 参数或首条消息携带令牌。现代趋势包括边缘 WebSocket（Cloudflare Durable Objects）、WebTransport（HTTP/3 替代方案）以及 SSE 用于 AI 流式输出。
