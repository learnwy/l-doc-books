provide/inject 依赖注入

依赖注入概述

Vue 3 的 provide / inject 机制实现了组件树中的依赖注入模式，允许祖先组件向所有后代组件提供数据，无需通过 props 逐层传递。



基本用法
provide
祖先组件通过 provide 提供数据：


<script setup lang="ts">
import { provide, ref } from 'vue';

const theme = ref<'light' | 'dark'>('light');
const toggleTheme = () => {
  theme.value = theme.value === 'light' ? 'dark' : 'light';
};

provide('theme', theme);
provide('toggleTheme', toggleTheme);
</script>
inject
后代组件通过 inject 接收数据：


<script setup lang="ts">
import { inject, type Ref } from 'vue';

const theme = inject<Ref<'light' | 'dark'>>('theme');
const toggleTheme = inject<() => void>('toggleTheme');
</script>

<template>
  <div :class="theme">
    <button @click="toggleTheme">切换主题</button>
  </div>
</template>


类型安全的注入
使用 InjectionKey 可以在 TypeScript 中实现完整的类型推断：


// keys.ts
import type { InjectionKey, Ref } from 'vue';

export interface UserContext {
  user: Ref<{ name: string; role: string } | null>;
  login: (name: string) => void;
  logout: () => void;
}

export const UserKey: InjectionKey<UserContext> = Symbol('user');
<!-- 祖先组件 -->
<script setup lang="ts">
import { provide, ref } from 'vue';
import { UserKey, type UserContext } from '@/keys';

const user = ref<{ name: string; role: string } | null>(null);

const userContext: UserContext = {
  user,
  login(name: string) {
    user.value = { name, role: 'user' };
  },
  logout() {
    user.value = null;
  },
};

provide(UserKey, userContext);
</script>
<!-- 后代组件 -->
<script setup lang="ts">
import { inject } from 'vue';
import { UserKey } from '@/keys';

const userCtx = inject(UserKey);
// TypeScript 自动推断出 UserContext | undefined 类型
</script>


注入默认值
当注入的值可能不存在时，提供默认值避免 undefined：


// 简单默认值
const theme = inject('theme', 'light');

// 工厂函数默认值（避免每次创建新对象）
const config = inject(
  'config',
  () => ({
    apiUrl: '/api',
    timeout: 5000,
  }),
  true,
); // 第三个参数 true 表示使用工厂函数

// 使用 InjectionKey 时的默认值
const userCtx = inject(UserKey, {
  user: ref(null),
  login: () => {},
  logout: () => {},
});




默认值方式
使用场景





直接值
基本类型默认值




工厂函数
对象/数组默认值，避免引用共享




不提供默认值
必须由祖先提供，否则开发警告







响应式注入
provide 的值如果是响应式的（ref / reactive），后代组件注入后同样保持响应性：


<!-- 祖先组件 -->
<script setup lang="ts">
import { provide, reactive } from 'vue';

const appConfig = reactive({
  locale: 'zh-CN',
  currency: 'CNY',
  dateFormat: 'YYYY-MM-DD',
});

provide('appConfig', appConfig);
</script>


提示： 为了保持单向数据流，建议将修改逻辑也通过 provide 提供，而不是让后代直接修改注入的响应式数据。可以使用 readonly 包裹注入的数据来强制执行这一原则。




import { provide, ref, readonly } from 'vue';

const count = ref<number>(0);

provide('count', readonly(count));
provide('incrementCount', () => {
  count.value++;
});


应用级 provide
在应用入口使用 app.provide 可以为整个应用的所有组件提供数据：


// main.ts
import { createApp } from 'vue';
import App from './App.vue';

const app = createApp(App);

app.provide('appVersion', '2.0.0');
app.provide('apiBaseUrl', import.meta.env.VITE_API_URL);

app.mount('#app');


实战模式：组合 provide/inject 与 composable
将 provide / inject 封装为一对 composable，提供更好的 API：


// composables/useDialog.ts
import { provide, inject, ref, type InjectionKey, type Ref } from 'vue';

interface DialogContext {
  visible: Ref<boolean>;
  title: Ref<string>;
  open: (title: string) => void;
  close: () => void;
}

const DialogKey: InjectionKey<DialogContext> = Symbol('dialog');

export function provideDialog(): DialogContext {
  const visible = ref<boolean>(false);
  const title = ref<string>('');

  const ctx: DialogContext = {
    visible,
    title,
    open(t: string) {
      title.value = t;
      visible.value = true;
    },
    close() {
      visible.value = false;
    },
  };

  provide(DialogKey, ctx);
  return ctx;
}

export function useDialog(): DialogContext {
  const ctx = inject(DialogKey);
  if (!ctx) {
    throw new Error('useDialog 必须在 provideDialog 的后代组件中使用');
  }
  return ctx;
}


小结
    

  • provide / inject 实现跨层级的依赖注入，避免 prop drilling
    • 

  • 使用 InjectionKey<T> 实现 TypeScript 类型安全的注入
    • 

  • 注入支持默认值和工厂函数默认值，处理可选依赖
    • 

  • 响应式数据注入后保持响应性，建议用 readonly 保护单向数据流
    • 

  • app.provide 提供应用级全局依赖
    • 

  • 封装为 provide* / use* 对偶 composable 是最佳实践模式
    •
