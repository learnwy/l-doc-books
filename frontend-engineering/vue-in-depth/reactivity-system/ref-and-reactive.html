ref 与 reactive

两种响应式 API

Vue 3 提供了两种创建响应式数据的核心 API：ref 和 reactive。两者底层都依赖 Proxy，但使用场景和行为有着本质区别。



ref 详解
基本用法
ref 将一个值包裹在一个带有 .value 属性的对象中，使其成为响应式：


import { ref } from 'vue';

const count = ref<number>(0);
console.log(count.value); // 0
count.value++;
console.log(count.value); // 1
ref 的内部实现
ref 内部使用类实例的 getter/setter 来拦截 .value 的读写操作：


class RefImpl<T> {
  private _value: T;
  private _rawValue: T;
  public dep: Set<ReactiveEffect> = new Set();

  constructor(value: T) {
    this._rawValue = value;
    this._value = isObject(value) ? reactive(value) : value;
  }

  get value(): T {
    trackRefValue(this);
    return this._value;
  }

  set value(newVal: T) {
    if (hasChanged(newVal, this._rawValue)) {
      this._rawValue = newVal;
      this._value = isObject(newVal) ? reactive(newVal) : newVal;
      triggerRefValue(this);
    }
  }
}


提示： 当 ref 接收一个对象时，内部会自动调用 reactive() 来处理 .value，因此 ref({}) 和 reactive({}) 在深层响应性上表现一致。




模板中的自动解包
在 <template> 中使用 ref 时不需要 .value，Vue 的编译器会自动处理解包：


<script setup lang="ts">
import { ref } from 'vue';

const message = ref<string>('你好 Vue 3');
</script>

<template>
  <!-- 模板中自动解包，无需 .value -->
  <p>{{ message }}</p>
</template>
shallowRef
shallowRef 只对 .value 的替换操作进行追踪，不会对内部嵌套属性进行深层响应式转换：


import { shallowRef, triggerRef } from 'vue';

const state = shallowRef({ count: 0 });

// ❌ 不会触发更新——内部属性变化不被追踪
state.value.count++;

// ✅ 替换整个 .value 会触发更新
state.value = { count: 1 };

// ✅ 手动触发更新
state.value.count++;
triggerRef(state);


reactive 详解
基本用法
reactive 接收一个对象并返回其深层响应式代理：


import { reactive } from 'vue';

interface UserState {
  name: string;
  age: number;
  hobbies: string[];
}

const state = reactive<UserState>({
  name: 'Alice',
  age: 25,
  hobbies: ['reading', 'coding'],
});

state.age = 26;
state.hobbies.push('gaming');
reactive 的限制
reactive 存在几个重要的使用限制：






限制
说明
解决方案





仅支持对象类型
不能用于 string、number 等基本类型
使用 ref




不可替换整个对象
替换会丢失响应式连接
修改属性而非替换




解构丢失响应性
解构后的变量不再是响应式
使用 toRefs




类型限制
不能用于 Map、Set 以外的集合类型
使用 ref 包裹





const state = reactive({ count: 0, name: 'Vue' });

// ❌ 解构后丢失响应性
let { count } = state;
count++; // 不会触发更新

// ❌ 替换整个对象丢失代理
let state2 = reactive({ count: 0 });
state2 = reactive({ count: 1 }); // 旧引用丢失


toRefs 与 toRef
toRefs 和 toRef 是解决 reactive 解构问题的关键工具：


import { reactive, toRefs, toRef } from 'vue';

const state = reactive({
  count: 0,
  name: 'Vue',
});

// toRefs：将 reactive 对象的每个属性转为 ref
const { count, name } = toRefs(state);
count.value++; // ✅ 保持响应性，同步修改 state.count

// toRef：转换单个属性
const countRef = toRef(state, 'count');
countRef.value++; // ✅ 保持响应性
在 composable 函数中返回值时，toRefs 是最常用的模式：


function useCounter() {
  const state = reactive({
    count: 0,
    doubled: computed(() => state.count * 2),
  });

  function increment() {
    state.count++;
  }

  return {
    ...toRefs(state),
    increment,
  };
}

小结
    

  • ref 通过 .value 包裹实现响应式，适用于基本类型和需要替换引用的场景
    • 

  • reactive 直接返回对象的深层 Proxy，使用更简洁但存在解构丢失响应性的问题
    • 

  • shallowRef 只追踪 .value 的替换，适合大型数据结构的性能优化
    • 

  • toRefs / toRef 将 reactive 属性转换为独立的 ref，解决解构问题
    • 

  • 团队应根据一致性原则选定主要 API，推荐优先使用 ref 以获得更好的可预测性
