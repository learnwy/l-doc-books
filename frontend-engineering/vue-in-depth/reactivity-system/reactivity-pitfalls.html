响应式陷阱

常见问题概览

Vue 3 的响应式系统虽然强大，但在实际开发中存在若干容易犯错的场景。了解这些陷阱并掌握对应的解决方案，是避免难以调试的 bug 的关键。



解构丢失响应性
这是 Vue 3 中最常见的陷阱——对 reactive 对象进行解构会断开响应式连接：


import { reactive, toRefs } from 'vue';

const state = reactive({ count: 0, name: 'Vue' });

// ❌ 解构后是普通变量，不再是响应式
const { count, name } = state;
count++; // 不会触发视图更新

// ✅ 使用 toRefs 保持响应性
const { count: countRef, name: nameRef } = toRefs(state);
countRef.value++; // 触发更新，同步到 state.count
同样的问题也发生在函数参数传递中：


// ❌ 传递属性值，丢失响应性
function logCount(count: number) {
  console.log(count); // 只是一个快照
}
logCount(state.count);

// ✅ 传递 ref 或 getter
function logCount(count: () => number) {
  console.log(count()); // 每次调用获取最新值
}
logCount(() => state.count);


reactive 整体替换
替换 reactive 返回的代理对象会导致原始引用断开：


import { reactive } from 'vue';

let state = reactive({ items: [] as string[] });

// ❌ 替换整个对象，组件仍持有旧代理的引用
async function fetchItems() {
  const data = await fetch('/api/items').then((r) => r.json());
  state = reactive({ items: data }); // 组件不会更新
}

// ✅ 修改现有属性
async function fetchItems() {
  const data = await fetch('/api/items').then((r) => r.json());
  state.items = data; // 保持同一代理引用
}

原始值访问（toRaw / markRaw）
有时需要绕过响应式系统访问原始对象，例如将数据传给第三方库或进行深度比较：


import { reactive, toRaw, markRaw } from 'vue';

const state = reactive({ count: 0 });
const raw = toRaw(state);
console.log(raw === state); // false
raw.count++; // 不会触发更新

// markRaw：标记对象永不被代理
const hugeThirdPartyObj = markRaw({
  data: new Float32Array(1000000),
  process() {
    /* ... */
  },
});

const appState = reactive({
  renderer: hugeThirdPartyObj, // 不会被转为响应式
});

readonly 与 shallowReadonly
readonly 创建一个深层只读代理，任何修改尝试都会在开发模式下触发警告：


import { reactive, readonly, shallowReadonly } from 'vue';

const original = reactive({ nested: { count: 0 } });
const readonlyCopy = readonly(original);

// ❌ 开发模式下会警告
readonlyCopy.nested.count++;

// 但原始对象的修改会反映到 readonly 代理中
original.nested.count++; // readonlyCopy.nested.count 也变为 1

// shallowReadonly 只保护顶层属性
const shallow = shallowReadonly(original);
shallow.nested.count++; // ✅ 不会警告（嵌套属性可修改）

// 编译器自动处理，保持响应性


调试响应式
Vue 3 的 computed 和 watch 支持 onTrack / onTrigger 调试钩子：


import { ref, watchEffect } from 'vue';

const count = ref<number>(0);

watchEffect(
  () => {
    console.log(count.value);
  },
  {
    onTrack(e) {
      console.log('依赖被追踪:', e);
    },
    onTrigger(e) {
      console.log('更新被触发:', e);
      debugger;
    },
  },
);


小结
    

  • 解构 reactive 对象会丢失响应性，需使用 toRefs / toRef 转换
    • 

  • 替换 reactive 整体引用会断开组件绑定，应修改属性或使用 ref
    • 

  • toRaw 获取原始对象用于第三方库交互，markRaw 标记对象永不被代理
    • 

  • readonly 创建深层只读代理，shallowReadonly 只保护顶层属性
    • 

  • 使用 onTrack / onTrigger 调试钩子排查响应式相关问题
    • 

  • Vue 3.3+ 的 defineProps 解构语法糖由编译器自动处理响应性保持
