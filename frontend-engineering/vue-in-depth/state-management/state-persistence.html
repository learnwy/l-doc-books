状态持久化

为什么需要持久化

单页应用（SPA）中的状态默认存储在内存中，页面刷新后即丢失。对于用户偏好、登录令牌、表单草稿等数据，需要将状态持久化到浏览器存储中。

手动实现持久化
基础方案
// composables/usePersistedRef.ts
import { ref, watch, type Ref } from 'vue';

export function usePersistedRef<T>(key: string, defaultValue: T, storage: Storage = localStorage): Ref<T> {
  const stored = storage.getItem(key);
  const data = ref<T>(stored ? JSON.parse(stored) : defaultValue) as Ref<T>;

  watch(
    data,
    (newValue) => {
      storage.setItem(key, JSON.stringify(newValue));
    },
    { deep: true },
  );

  return data;
}
<script setup lang="ts">
import { usePersistedRef } from '@/composables/usePersistedRef';

const settings = usePersistedRef('user-settings', {
  theme: 'light' as 'light' | 'dark',
  fontSize: 14,
  language: 'zh-CN',
});
</script>

<template>
  <select v-model="settings.theme">
    <option value="light">浅色</option>
    <option value="dark">深色</option>
  </select>
</template>


pinia-plugin-persistedstate
这是 Pinia 生态中最流行的持久化插件，提供声明式配置：


安装和配置
// main.ts
import { createApp } from 'vue';
import { createPinia } from 'pinia';
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate';

const pinia = createPinia();
pinia.use(piniaPluginPersistedstate);

createApp(App).use(pinia).mount('#app');
基本使用
// stores/settings.ts
import { defineStore } from 'pinia';
import { ref } from 'vue';

export const useSettingsStore = defineStore(
  'settings',
  () => {
    const theme = ref<'light' | 'dark'>('light');
    const locale = ref<string>('zh-CN');
    const sidebarCollapsed = ref<boolean>(false);

    return { theme, locale, sidebarCollapsed };
  },
  {
    persist: true,
  },
);
高级配置
export const useAuthStore = defineStore(
  'auth',
  () => {
    const token = ref<string | null>(null);
    const refreshToken = ref<string | null>(null);
    const user = ref<{ name: string; email: string } | null>(null);
    const sessionId = ref<string>('');

    return { token, refreshToken, user, sessionId };
  },
  {
    persist: [
      {
        key: 'auth-token',
        storage: localStorage,
        pick: ['token', 'refreshToken'],
      },
      {
        key: 'auth-session',
        storage: sessionStorage,
        pick: ['sessionId'],
      },
    ],
  },
);
自定义序列化
export const useSecureStore = defineStore(
  'secure',
  () => {
    const sensitiveData = ref<string>('');
    return { sensitiveData };
  },
  {
    persist: {
      serializer: {
        serialize: (value) => btoa(JSON.stringify(value)),
        deserialize: (value) => JSON.parse(atob(value)),
      },
    },
  },
);

Nuxt 中的自动 Hydration
Nuxt 3 内置了 Pinia 的 SSR 支持，自动处理序列化和 hydration：


// stores/products.ts
export const useProductsStore = defineStore('products', () => {
  const items = ref<Product[]>([]);

  async function fetchProducts() {
    const data = await $fetch<Product[]>('/api/products');
    items.value = data;
  }

  return { items, fetchProducts };
});
<!-- pages/products.vue -->
<script setup lang="ts">
const store = useProductsStore();
await store.fetchProducts();
</script>


SSR 状态传递
在非 Nuxt 的 SSR 应用中，需要手动处理状态传递：


// entry-server.ts
export async function render() {
  const pinia = createPinia();
  const app = createApp(App).use(pinia);

  const html = await renderToString(app);
  const state = JSON.stringify(pinia.state.value);

  return { html, state };
}
// entry-client.ts
const pinia = createPinia();

const stateStr = document.getElementById('__PINIA_STATE__')?.textContent;
if (stateStr) {
  pinia.state.value = JSON.parse(stateStr);
}

createApp(App).use(pinia).mount('#app');


最佳实践




实践
说明





选择性持久化
只持久化必要的字段，避免存储冗余数据




版本管理
存储结构变化时处理迁移逻辑




敏感数据加密
token 等敏感信息使用加密存储




容量监控
避免超出存储限制导致数据丢失




清理策略
用户登出时清除相关持久化数据





export const useAuthStore = defineStore('auth', () => {
  const token = ref<string | null>(null);

  function logout() {
    token.value = null;
    localStorage.removeItem('auth-token');
    sessionStorage.clear();
  }

  return { token, logout };
});


小结
    

  • 浏览器提供 localStorage、sessionStorage、IndexedDB、Cookie 四种存储方式，各有适用场景
    • 

  • pinia-plugin-persistedstate 提供声明式持久化，支持多存储后端、字段筛选和自定义序列化
    • 

  • SSR 场景下的 Hydration 将服务端状态传递到客户端，Nuxt 自动处理
    • 

  • 非 Nuxt SSR 应用需手动序列化 pinia.state.value 并在客户端恢复
    • 

  • 最佳实践包括选择性持久化、敏感数据加密和存储版本管理
