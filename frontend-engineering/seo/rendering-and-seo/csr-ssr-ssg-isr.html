CSR、SSR、SSG 与 ISR

渲染方式与 SEO 的关系

前端渲染方式决定了搜索引擎在抓取页面时能获取到什么内容。搜索引擎爬虫本质上是一个 HTTP 客户端——它发送请求、接收 HTML 响应，然后（可能）执行 JavaScript 来渲染最终内容。不同的渲染策略在这个过程中表现截然不同。

CSR — 客户端渲染
客户端渲染是 SPA（单页应用）的默认模式。服务器返回一个几乎空白的 HTML 文件，所有内容由 JavaScript 在浏览器中动态生成。


<!DOCTYPE html>
<html>
  <head>
    <title>My App</title>
  </head>
  <body>
    <div id="root"></div>
    <script src="/static/js/bundle.js"></script>
  </body>
</html>
import { createRoot } from "react-dom/client";

function App() {
  const [articles, setArticles] = useState<Article[]>([]);

  useEffect(() => {
    fetch("/api/articles")
      .then((res) => res.json())
      .then(setArticles);
  }, []);

  return (
    <main>
      <h1>技术博客</h1>
      {articles.map((article) => (
        <article key={article.id}>
          <h2>{article.title}</h2>
          <p>{article.excerpt}</p>
        </article>
      ))}
    </main>
  );
}

const root = createRoot(document.getElementById("root")!);
root.render(<App />);

SSR — 服务端渲染
服务端渲染在每次请求时在服务器上执行 React（或其他框架）代码，生成完整的 HTML 后返回给客户端。


import type { GetServerSideProps } from "next";

interface ArticlePageProps {
  article: {
    title: string;
    content: string;
    author: string;
    publishedAt: string;
  };
}

export const getServerSideProps: GetServerSideProps<ArticlePageProps> = async (context) => {
  const { slug } = context.params!;
  const article = await fetchArticle(slug as string);

  if (!article) {
    return { notFound: true };
  }

  return {
    props: { article },
  };
};

export default function ArticlePage({ article }: ArticlePageProps) {
  return (
    <>
      <head>
        <title>{article.title} | 技术博客</title>
        <meta name="description" content={article.content.slice(0, 160)} />
      </head>
      <main>
        <article>
          <h1>{article.title}</h1>
          <time dateTime={article.publishedAt}>{article.publishedAt}</time>
          <p>作者：{article.author}</p>
          <div dangerouslySetInnerHTML={{ __html: article.content }} />
        </article>
      </main>
    </>
  );
}
SSR 的 SEO 优势
SSG — 静态站点生成
静态站点生成在构建时预先渲染所有页面为静态 HTML 文件，运行时直接通过 CDN 分发，无需服务器计算。


import type { GetStaticProps, GetStaticPaths } from 'next';

export const getStaticPaths: GetStaticPaths = async () => {
  const articles = await getAllArticleSlugs();

  return {
    paths: articles.map((slug) => ({ params: { slug } })),
    fallback: 'blocking',
  };
};

export const getStaticProps: GetStaticProps<ArticlePageProps> = async (context) => {
  const { slug } = context.params!;
  const article = await fetchArticle(slug as string);

  if (!article) {
    return { notFound: true };
  }

  return {
    props: { article },
  };
};
Next.js App Router 中的 SSG：


export async function generateStaticParams() {
  const articles = await getAllArticles();
  return articles.map((article) => ({
    slug: article.slug,
  }));
}

export default async function ArticlePage({ params }: { params: { slug: string } }) {
  const article = await fetchArticle(params.slug);

  return (
    <main>
      <article>
        <h1>{article.title}</h1>

      </article>
    </main>

ISR — 增量静态再生
ISR 结合了 SSG 和 SSR 的优势：页面在构建时预生成，但可以按照指定的时间间隔在后台自动更新。


export const getStaticProps: GetStaticProps = async (context) => {
  const article = await fetchArticle(context.params!.slug as string);

  return {
    props: { article },
    revalidate: 3600,
  };
};
export const revalidate = 3600;

export default async function ArticlePage({ params }: { params: { slug: string } }) {
  const article = await fetchArticle(params.slug);

  return (
    <main>
      <article>
        <h1>{article.title}</h1>
        <div>{article.content}</div>
      </article>
    </main>
  );
}

小结
    

  • CSR 的初始 HTML 为空，依赖搜索引擎的二次渲染索引，存在延迟和失败风险。
    • 

  • SSR 在每次请求时服务端生成完整 HTML，SEO 友好但增加服务器负载。
    • 

  • SSG 在构建时预生成静态 HTML，SEO 和性能都最优，但内容更新需要重新构建。
    • 

  • ISR 结合 SSG 和 SSR 优势，通过定期后台更新实现近实时的内容刷新。
    • 

  • 需要 SEO 的页面应优先选择 SSG 或 ISR，动态个性化页面使用 SSR，不需要 SEO 的内部页面可以使用 CSR。
