Canonical 标签与 hreflang

内容重复问题

内容重复是 SEO 中最常见也最容易被忽视的问题之一。搜索引擎在遇到多个 URL 包含相同或极其相似的内容时，需要决定哪个版本是"权威版本"并将其展示在搜索结果中。如果搜索引擎判断错误，可能导致链接权重被分散、错误的页面被展示，甚至页面被降权。

Canonical 标签详解
基本用法
<link rel="canonical"> 标签告诉搜索引擎当前页面的"首选版本" URL 是什么。它是一个建议性信号而非强制指令，但搜索引擎通常会尊重正确设置的 canonical 标签。


<!-- 在所有重复页面中指向首选版本 -->
<head>
  <link rel="canonical" href="https://example.com/blog/react-guide" />
</head>
Canonical 标签的设置规则
import type { Metadata } from 'next';

function generateCanonical(pathname: string, searchParams?: URLSearchParams): string {
  const baseUrl = 'https://example.com';
  const cleanPath = pathname.replace(/\/$/, '');

  const allowedParams = ['page', 'category'];
  const filteredParams = new URLSearchParams();

  if (searchParams) {
    allowedParams.forEach((param) => {
      const value = searchParams.get(param);
      if (value) filteredParams.set(param, value);
    });
  }

  const queryString = filteredParams.toString();
  return queryString ? `${baseUrl}${cleanPath}?${queryString}` : `${baseUrl}${cleanPath}`;
}

export async function generateMetadata(): Promise<Metadata> {
  return {
    alternates: {
      canonical: generateCanonical('/blog/react-guide'),
    },
  };
}

HTTP 响应头中的 Canonical
对于非 HTML 资源（如 PDF）或需要在服务端控制的场景，可以使用 HTTP 响应头：


import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  const response = NextResponse.next();
  const canonicalUrl = `https://example.com${request.nextUrl.pathname}`;

  response.headers.set('Link', `<${canonicalUrl}>; rel="canonical"`);

  return response;
}
hreflang 标签详解
多语言与多地区站点的挑战
当一个网站提供多种语言或面向多个国家/地区的内容时，搜索引擎需要知道各个语言版本之间的对应关系，以便为不同地区的用户展示正确的版本。hreflang 标签就是解决这一问题的标准机制。


hreflang 实现方式
方式一：HTML <link> 标签


<head>
  <link rel="alternate" hreflang="zh-CN" href="https://example.com/zh/guide" />
  <link rel="alternate" hreflang="en" href="https://example.com/en/guide" />
  <link rel="alternate" hreflang="ja" href="https://example.com/ja/guide" />
  <link rel="alternate" hreflang="ko" href="https://example.com/ko/guide" />
  <link rel="alternate" hreflang="x-default" href="https://example.com/en/guide" />
</head>
方式二：XML Sitemap


<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"
        xmlns:xhtml="http://www.w3.org/1999/xhtml">
  <url>
    <loc>https://example.com/zh/guide</loc>
    <xhtml:link rel="alternate" hreflang="zh-CN" href="https://example.com/zh/guide"/>
    <xhtml:link rel="alternate" hreflang="en" href="https://example.com/en/guide"/>
    <xhtml:link rel="alternate" hreflang="ja" href="https://example.com/ja/guide"/>
    <xhtml:link rel="alternate" hreflang="x-default" href="https://example.com/en/guide"/>
  </url>
</urlset>
Next.js 中实现多语言 SEO
import type { Metadata } from 'next';

const locales = ['zh-CN', 'en', 'ja', 'ko'] as const;
type Locale = (typeof locales)[number];

interface LocalizedPageProps {
  params: { locale: Locale; slug: string };
}

export async function generateMetadata({ params }: LocalizedPageProps): Promise<Metadata> {
  const { locale, slug } = params;
  const baseUrl = 'https://example.com';

  const languages: Record<string, string> = {};
  locales.forEach((loc) => {
    const langKey = loc.toLowerCase();
    languages[langKey] = `${baseUrl}/${loc}/${slug}`;
  });
  languages['x-default'] = `${baseUrl}/en/${slug}`;

  return {
    alternates: {
      canonical: `${baseUrl}/${locale}/${slug}`,
      languages,
    },
  };
}

常见错误与排查
interface HreflangLink {
  locale: string;
  url: string;
}

function validateHreflang(links: HreflangLink[]): string[] {
  const errors: string[] = [];

  const hasXDefault = links.some((link) => link.locale === 'x-default');
  if (!hasXDefault) {
    errors.push('缺少 x-default 后备语言声明');
  }

  const localePattern = /^[a-z]{2}(-[A-Z]{2})?$|^x-default$/;
  links.forEach((link) => {
    if (!localePattern.test(link.locale)) {
      errors.push(`语言代码格式错误: ${link.locale}`);
    }
  });

  links.forEach((link) => {
    if (!link.url.startsWith('https://')) {
      errors.push(`URL 应使用绝对路径: ${link.url}`);
    }
  });

  return errors;
}
Canonical 与 hreflang 的协同
当同时使用 canonical 和 hreflang 时，需要确保两者的指向保持一致。


<!-- zh-CN 版本页面 -->
<head>
  <link rel="canonical" href="https://example.com/zh/guide" />
  <link rel="alternate" hreflang="zh-CN" href="https://example.com/zh/guide" />
  <link rel="alternate" hreflang="en" href="https://example.com/en/guide" />
  <link rel="alternate" hreflang="x-default" href="https://example.com/en/guide" />
</head>
关键原则：


    

  • 每个语言版本的 canonical 应指向该语言版本自身
    • 

  • hreflang 中引用的 URL 应与对应页面的 canonical URL 一致
    • 

  • 不要将所有语言版本的 canonical 都指向同一个页面
    • 



小结
    

  • 内容重复是 SEO 中的常见问题，包括 URL 参数变体、协议/域名差异、分页等场景。
    • 

  • Canonical 标签告诉搜索引擎页面的首选版本，是一个建议性信号。
    • 

  • Canonical 必须使用绝对 URL，保持与 Sitemap 一致，避免链式引用。
    • 

  • hreflang 标签帮助搜索引擎理解多语言/多地区页面之间的对应关系。
    • 

  • hreflang 必须双向引用（A↔B），包含自引用，并设置 x-default 后备。
    • 

  • Canonical 和 hreflang 需要协同工作，确保指向一致且不产生冲突。
    •
