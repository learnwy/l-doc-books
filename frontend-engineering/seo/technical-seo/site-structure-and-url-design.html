站点结构与 URL 设计

站点结构的 SEO 影响

站点结构决定了搜索引擎爬虫如何发现和遍历你的网站内容。一个良好的站点结构不仅提升爬虫的抓取效率，还帮助搜索引擎理解页面之间的层级关系和主题关联，最终影响页面的排名权重分配。

核心原则是三次点击规则：任何页面都应该在从首页出发三次点击内到达。这不是绝对的规则，但它反映了一个重要的 SEO 理念——页面距离首页越近，获得的抓取频率和链接权重越高。


URL 设计最佳实践
URL 结构规范
URL 是页面在互联网上的唯一标识，也是搜索引擎理解页面内容的重要信号之一。


✅ 好的 URL 设计:
https://example.com/blog/react-performance-optimization
https://example.com/products/wireless-headphones
https://example.com/docs/getting-started/installation

❌ 差的 URL 设计:
https://example.com/p?id=12345&cat=3&ref=home
https://example.com/blog/2026/03/30/post-123456
https://example.com/page.php?action=view&module=articles&id=789

说明
示例





使用连字符分隔
用 - 而非 _ 分隔单词
/react-hooks-guide




全部小写
避免大小写混淆导致重复 URL
/api-design 而非 /API-Design




语义化路径
URL 应描述页面内容
/tutorials/css-grid




避免多余参数
减少查询字符串
/products/shoes 而非 /products?type=shoes




保持简短
避免过长的 URL 路径
控制在 60-80 字符内




使用 HTTPS
Google 明确将 HTTPS 作为排名信号
https:// 而非 http://

面包屑导航
面包屑导航是同时服务于用户和搜索引擎的最佳导航模式之一。


<nav aria-label="面包屑">
  <ol itemscope itemtype="https://schema.org/BreadcrumbList">
    <li itemprop="itemListElement" itemscope itemtype="https://schema.org/ListItem">
      <a itemprop="item" href="/">
        <span itemprop="name">首页</span>
      </a>
      <meta itemprop="position" content="1" />
    </li>
    <li itemprop="itemListElement" itemscope itemtype="https://schema.org/ListItem">
      <a itemprop="item" href="/tutorials">
        <span itemprop="name">教程</span>
      </a>
      <meta itemprop="position" content="2" />
    </li>
    <li itemprop="itemListElement" itemscope itemtype="https://schema.org/ListItem">
      <span itemprop="name">React SEO 指南</span>
      <meta itemprop="position" content="3" />
    </li>
  </ol>
</nav>
import Link from "next/link";

interface BreadcrumbItem {
  label: string;
  href?: string;
}

function Breadcrumb({ items }: { items: BreadcrumbItem[] }) {
  const jsonLd = {
    "@context": "https://schema.org",
    "@type": "BreadcrumbList",
    itemListElement: items.map((item, index) => ({
      "@type": "ListItem",
      position: index + 1,
      name: item.label,
      ...(item.href ? { item: `https://example.com${item.href}` } : {}),
    })),
  };

  return (
    <>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd) }}
      />
      <nav aria-label="面包屑">
        <ol>
          {items.map((item, index) => (
            <li key={index}>
              {item.href ? (
                <Link href={item.href}>{item.label}</Link>
              ) : (
                <span aria-current="page">{item.label}</span>
              )}
            </li>
          ))}
        </ol>
      </nav>
    </>
  );
}
分页与 SEO
分页页面的 SEO 处理是一个常见的技术挑战。


<head>
  <link rel="canonical" href="https://example.com/blog?page=2" />
  <meta name="robots" content="index, follow" />
</head>
import type { Metadata } from 'next';

interface PaginationProps {
  currentPage: number;
  totalPages: number;
  baseUrl: string;
}

export function generatePaginationMetadata({ currentPage, totalPages, baseUrl }: PaginationProps): Metadata {
  const canonical = currentPage === 1 ? baseUrl : `${baseUrl}?page=${currentPage}`;

  return {
    alternates: {
      canonical,
    },
    robots: {
      index: currentPage <= 5,
      follow: true,
    },
  };
}
URL 变更与重定向策略
URL 变更是网站改版时最容易出错的环节之一。错误的重定向策略可能导致严重的 SEO 损失。


const redirectMap: Record<string, { destination: string; permanent: boolean }> = {
  '/old-blog/:slug': { destination: '/blog/:slug', permanent: true },
  '/legacy/products/:id': { destination: '/shop/:id', permanent: true },
  '/temp-promo': { destination: '/current-sale', permanent: false },
};

const nextConfig = {
  async redirects() {
    return Object.entries(redirectMap).map(([source, { destination, permanent }]) => ({
      source,
      destination,
      permanent,
    }));
  },
};

export default nextConfig;

小结
    

  • 扁平的站点结构确保重要页面在 3 次点击内可达，有利于爬虫发现和权重分配。
    • 

  • URL 设计应语义化、使用连字符分隔、全部小写，保持简短且具有描述性。
    • 

  • 面包屑导航同时服务于用户和搜索引擎，配合结构化数据可以增强搜索结果展示。
    • 

  • 分页页面需要合理设置 canonical 和 robots 指令，避免索引膨胀。
    • 

  • URL 变更必须使用正确的重定向类型（301 vs 302），避免重定向链，并保持旧 URL 到新 URL 的完整映射。
