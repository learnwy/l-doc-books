同源策略与安全

同源策略（Same-Origin Policy）

同源策略是浏览器最基本的安全机制。它限制一个源（Origin）的文档或脚本与另一个源的资源交互。两个 URL 的协议、域名和端口完全相同才被视为同源。





URL
与 https://app.example.com 是否同源
原因

✅ 同源
路径不同不影响




http://app.example.com
❌ 跨源
协议不同




https://api.example.com
❌ 跨源
域名不同




https://app.example.com:8080
❌ 跨源
端口不同





function isSameOrigin(urlA: string, urlB: string): boolean {
  const a = new URL(urlA);
  const b = new URL(urlB);
  return a.origin === b.origin;
}

console.log(isSameOrigin('https://a.com/page1', 'https://a.com/page2')); // true
console.log(isSameOrigin('https://a.com', 'http://a.com')); // false


CORS（跨源资源共享）
CORS（Cross-Origin Resource Sharing） 允许服务器声明哪些源可以访问其资源，是突破同源策略限制的标准机制。


简单请求的条件：

无（仅允许安全头）





async function corsRequest(url: string): Promise<unknown> {
  const response = await fetch(url, {
    mode: 'cors',
    credentials: 'include',
    headers: {
      'Content-Type': 'application/json',
    },
  });

  const allowOrigin = response.headers.get('Access-Control-Allow-Origin');
  const allowCredentials = response.headers.get('Access-Control-Allow-Credentials');

  console.log('Allow-Origin:', allowOrigin);
  console.log('Allow-Credentials:', allowCredentials);

  return response.json();
}

提示： Access-Control-Allow-Origin: * 和 Access-Control-Allow-Credentials: true 不能同时使用。需要携带 Cookie 时必须指定具体的源。






CSP（内容安全策略）
CSP（Content Security Policy） 通过 HTTP 响应头或 <meta> 标签限制页面可以加载的资源类型和来源，有效防止 XSS 攻击。


interface CSPDirectives {
  'default-src': string[];
  'script-src': string[];
  'style-src': string[];
  'img-src': string[];
  'connect-src': string[];
  'font-src': string[];
  'frame-src': string[];
  'report-uri'?: string[];
}

function buildCSP(directives: Partial<CSPDirectives>): string {
  return Object.entries(directives)
    .map(([key, values]) => `${key} ${values.join(' ')}`)
    .join('; ');
}

const csp = buildCSP({
  'default-src': ["'self'"],
  'script-src': ["'self'", "'nonce-abc123'"],
  'style-src': ["'self'", "'unsafe-inline'"],
  'img-src': ["'self'", 'data:', 'https://cdn.example.com'],
  'connect-src': ["'self'", 'https://api.example.com'],
  'font-src': ["'self'", 'https://fonts.gstatic.com'],
});

function escapeHTML(str: string): string {
  const map: Record<string, string> = {
    '&': '&amp;',
    '<': '&lt;',
    '>': '&gt;',
    '"': '&quot;',
    "'": '&#x27;',
  };
  return str.replace(/[&<>"']/g, (char) => map[char]);
}

function safeInnerHTML(element: HTMLElement, content: string): void {
  element.textContent = content;
}

function createSafeElement(tag: string, text: string, attrs?: Record<string, string>): HTMLElement {
  const el = document.createElement(tag);
  el.textContent = text;
  if (attrs) {
    for (const [key, value] of Object.entries(attrs)) {
      el.setAttribute(key, value);
    }
  }
  return el;
}


CSRF 防御
CSRF（Cross-Site Request Forgery） 攻击利用用户已认证的会话发起恶意请求。


async function csrfProtectedRequest(url: string, data: unknown): Promise<Response> {
  const csrfToken = document.querySelector<HTMLMetaElement>('meta[name="csrf-token"]')?.content;

  return fetch(url, {
    method: 'POST',
    credentials: 'same-origin',
    headers: {
      'Content-Type': 'application/json',
      'X-CSRF-Token': csrfToken ?? '',
    },
    body: JSON.stringify(data),
  });
}

Trusted Types
Trusted Types 是一种 CSP 级别的 DOM XSS 防护机制，强制要求通过策略函数创建 HTML/URL/Script 内容。


if (window.trustedTypes) {
  const policy = trustedTypes.createPolicy('default', {
    createHTML: (input: string) => {
      const div = document.createElement('div');
      div.textContent = input;
      return div.innerHTML;
    },
    createScriptURL: (input: string) => {
      const url = new URL(input, location.origin);
      if (url.origin !== location.origin) {
        throw new Error('Script URL must be same-origin');
      }
      return url.toString();
    },
  });

  const safeHTML = policy.createHTML('<img src=x onerror=alert(1)>');
  console.log('Safe HTML:', safeHTML);
}


小结
    

  • 同源策略是浏览器安全的基石，限制跨源资源访问
    • 

  • CORS 通过响应头声明允许的跨源访问，非简单请求需要预检
    • 

  • CSP 限制页面可加载资源的来源，是防御 XSS 的重要工具
    • 

  • XSS 防御的核心是输出转义和避免使用 innerHTML
    • 

  • CSRF 防御结合 SameSite Cookie 和 CSRF Token 最为有效
