浏览器架构

从单进程到多进程

早期浏览器（如 IE6）将所有功能集中在一个进程中运行，一个页面崩溃就会拖垮整个浏览器。现代浏览器采用 多进程架构（Multi-Process Architecture），将不同职责拆分到独立进程中，提升稳定性、安全性和性能。



核心进程与职责
现代 Chromium 架构通常包含以下进程：






进程
职责
数量





Browser Process
UI 管理、导航、网络请求调度、子进程管理
1




Renderer Process
HTML/CSS 解析、JS 执行、页面渲染
每个站点一个或多个




GPU Process
3D 绘制、合成层光栅化、视频解码加速
1




Network Service
DNS 解析、HTTP 请求、SSL/TLS 握手
1（服务化）




Plugin Process
运行 NPAPI/PPAPI 插件（逐步淘汰）
按需创建




Utility Process
音频服务、CDM（内容解密模块）等
按需创建





interface ChromiumProcess {
  type: 'browser' | 'renderer' | 'gpu' | 'network' | 'plugin' | 'utility';
  pid: number;
  memory: number;
  cpuUsage: number;
}

  const processes: ChromiumProcess[] = [];
  if ('process' in performance) {

  }
  return processes;

站点隔离（Site Isolation）
站点隔离 是 Chrome 67 引入的关键安全特性，确保不同站点的页面运行在不同的渲染进程中。这从操作系统层面防止了恶意站点通过 Spectre 等侧信道攻击读取其他站点的数据。


站点隔离的关键规则：


    

  • 同一站点（scheme + eTLD+1 相同）的页面共享渲染进程
    • 

  • 跨站 iframe 会被分配到独立渲染进程（Out-of-Process iframes, OOPIF）
    • 

  • document.domain 修改不再允许跨 origin 共享进程
    • 



const isSameSite = (urlA: string, urlB: string): boolean => {
  const a = new URL(urlA);
  const b = new URL(urlB);
  const getETLDPlus1 = (hostname: string): string => {
    const parts = hostname.split('.');
    return parts.slice(-2).join('.');
  };
  return a.protocol === b.protocol && getETLDPlus1(a.hostname) === getETLDPlus1(b.hostname);
};

console.log(isSameSite('https://a.example.com', 'https://b.example.com')); // true
console.log(isSameSite('https://example.com', 'https://other.com')); // false


进程间通信（IPC）
多进程架构依赖高效的 IPC（Inter-Process Communication） 机制。Chromium 使用 Mojo 作为其 IPC 框架，替代了早期的 Chrome IPC。


IPC 通信的核心特征：






特征
说明





异步消息
非阻塞，发送方不等待响应




序列化
使用 Mojo 的 mojom IDL 定义接口和消息




能力传递
通过 Message Pipe 传递句柄和权限




沙箱约束
渲染进程无法直接访问文件系统或网络





interface IPCMessage {
  channel: string;
  payload: ArrayBuffer;
  transferables?: MessagePort[];

渲染进程的内部线程
渲染进程本身也是多线程的，每个线程承担不同职责：






线程
职责
是否阻塞页面交互





主线程
JS 执行、DOM/CSSOM 构建、布局、绘制
是




合成线程
接收图层、处理滚动和动画合成
否




光栅化线程
将图层的 tile 转换为位图
否




Worker 线程
执行 Web Worker / Service Worker
否







提示： transform 和 opacity 动画可以完全在合成线程上运行，不会阻塞主线程，这就是它们性能更好的原因。






小结
    

  • 现代浏览器采用多进程架构，将 Browser、Renderer、GPU、Network 等职责隔离到独立进程
    • 

  • 站点隔离确保不同站点运行在不同渲染进程中，从 OS 层面阻止跨站数据泄露
    • 

  • 进程间通过 Mojo IPC 进行高效的异步消息通信
    • 

  • 渲染进程内部由主线程、合成线程、光栅化线程等多线程协同工作
    • 

  • 理解架构有助于定位性能瓶颈：主线程阻塞影响交互，合成线程处理滚动和动画
    •
