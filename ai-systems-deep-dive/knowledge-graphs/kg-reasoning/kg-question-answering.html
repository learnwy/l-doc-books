知识图谱问答

核心概念

知识图谱问答（Knowledge Graph Question Answering, KGQA）是利用知识图谱中的结构化知识来回答自然语言问题的任务。用户提出自然语言问题，系统将问题转化为图谱查询或推理过程，从知识图谱中检索答案。KGQA 是知识图谱最直接的应用场景之一。

语义解析方法
语义解析（Semantic Parsing）将自然语言问题转化为形式化的图查询语言（如 SPARQL），然后在知识图谱上执行查询获取答案。这是最精确的 KGQA 方法。


interface SemanticParseResult {
  sparql: string;
  entities: LinkedEntity[];
  relations: LinkedRelation[];
  confidence: number;
}

interface LinkedEntity {
  mention: string;
  kgId: string;
  label: string;
  score: number;
}

interface LinkedRelation {
  mention: string;
  kgId: string;
  label: string;
  score: number;
}

function questionToSPARQL(question: string, entities: LinkedEntity[], relations: LinkedRelation[]): string {
  const questionType = classifyQuestionType(question);

  if (questionType === 'count') {
    return `SELECT (COUNT(?x) AS ?count) WHERE { <${entities[0].kgId}> <${relations[0].kgId}> ?x . }`;
  }

  if (questionType === 'boolean') {
    return `ASK WHERE { <${entities[0].kgId}> <${relations[0].kgId}> <${entities[1].kgId}> . }`;
  }

  return `SELECT ?answer WHERE { <${entities[0].kgId}> <${relations[0].kgId}> ?answer . } LIMIT 10`;
}

type QuestionType = 'factoid' | 'count' | 'boolean' | 'list' | 'comparison';

function classifyQuestionType(question: string): QuestionType {
  if (question.includes('多少') || question.includes('几个')) return 'count';
  if (question.includes('是否') || question.includes('是不是')) return 'boolean';
  if (question.includes('哪些') || question.includes('列出')) return 'list';
  if (question.includes('比较') || question.includes('更')) return 'comparison';
  return 'factoid';
}
语义解析的核心挑战是将非结构化的自然语言映射到结构化的查询语言。这个过程需要解决实体链接（将问题中的实体提及映射到 KG 实体）、关系链接（将问题中的关系表达映射到 KG 关系）和查询构造（将识别出的实体和关系组装为合法的查询）三个问题。


多跳推理问答
简单 KGQA 只需一步查询（如 "北京的人口是多少"），但很多问题需要多步推理（如 "发明电话的人出生在哪个国家"）。多跳推理需要沿着知识图谱中的路径进行逐步推理。


interface MultiHopConfig {
  maxHops: number;
  beamWidth: number;
  pruneThreshold: number;
}

interface ReasoningPath {
  entities: string[];
  relations: string[];
  score: number;
}

async function multiHopReasoning(
  question: string,
  startEntity: string,
  kg: KnowledgeGraph,
  config: MultiHopConfig,
): Promise<ReasoningPath[]> {
  let beams: ReasoningPath[] = [
    {
      entities: [startEntity],
      relations: [],
      score: 1.0,
    },
  ];

  for (let hop = 0; hop < config.maxHops; hop++) {
    const nextBeams: ReasoningPath[] = [];

    for (const beam of beams) {
      const lastEntity = beam.entities[beam.entities.length - 1];
      const neighbors = kg.getNeighbors(lastEntity);

      for (const { relation, entity } of neighbors) {
        const stepScore = computeStepScore(question, beam, relation, entity);
        if (stepScore >= config.pruneThreshold) {
          nextBeams.push({
            entities: [...beam.entities, entity],
            relations: [...beam.relations, relation],
            score: beam.score * stepScore,
          });
        }
      }
    }

    beams = nextBeams.sort((a, b) => b.score - a.score).slice(0, config.beamWidth);
  }

  return beams;
}

LLM 与知识图谱结合
大语言模型与知识图谱的结合是 KGQA 的最新范式。LLM 提供强大的自然语言理解和推理能力，知识图谱提供精确、结构化的事实知识，两者互补可以显著提升问答质量。


Think-on-Graph（ToG）是一种代表性方法：LLM 在知识图谱上进行 "思考"，每一步选择最相关的关系和实体进行探索，直到找到答案。StructGPT 则让 LLM 通过工具调用的方式与知识图谱交互，执行结构化查询。


interface TogConfig {
  llm: LLMClient;
  kg: KnowledgeGraph;
  maxDepth: number;
  explorationWidth: number;
}

async function thinkOnGraph(question: string, config: TogConfig): Promise<{ answer: string; reasoning: string[] }> {
  const reasoning: string[] = [];
  const entities = await config.llm.extractEntities(question);
  let currentEntities = await linkEntities(entities, config.kg);

  for (let depth = 0; depth < config.maxDepth; depth++) {
    const relations = getAvailableRelations(currentEntities, config.kg);
    const selectedRelations = await config.llm.selectRelations(
      question,
      currentEntities,
      relations,
      config.explorationWidth,
    );

    const nextEntities = explore(currentEntities, selectedRelations, config.kg);
    const shouldStop = await config.llm.checkTermination(question, nextEntities, reasoning);

    reasoning.push(
      `Step ${depth + 1}: ${selectedRelations.join(', ')} -> ${nextEntities.map((e) => e.label).join(', ')}`,
    );

    if (shouldStop) break;
    currentEntities = nextEntities;
  }

  const answer = await config.llm.generateAnswer(question, reasoning);
  return { answer, reasoning };
}
小结
    

  • KGQA 将自然语言问题转化为知识图谱上的查询或推理，是 KG 最直接的应用场景
    • 

  • 语义解析方法将问题转化为 SPARQL 查询，精确但需要处理实体链接和关系链接
    • 

  • 多跳推理通过路径搜索或嵌入空间运算处理需要多步推理的复杂问题
    • 

  • LLM+KG 结合（ToG、StructGPT）利用 LLM 的推理能力和 KG 的精确知识，是最新前沿方向
    • 

  • 实际 KGQA 系统需要综合语义解析、嵌入推理和 LLM 能力，应对不同复杂度的问题
