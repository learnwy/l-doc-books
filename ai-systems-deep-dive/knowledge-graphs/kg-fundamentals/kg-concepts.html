知识图谱基本概念

核心概念

知识图谱（Knowledge Graph, KG）是一种以图结构存储和表示实体及其关系的结构化知识库。图中的节点表示实体（Entity），边表示实体之间的关系（Relation），每条边构成一个三元组（Subject, Predicate, Object）。知识图谱将非结构化的知识转化为机器可理解和推理的形式化表示。

知识图谱的类型与代表系统
根据覆盖范围和构建方式，知识图谱可分为通用知识图谱和领域知识图谱两大类。通用知识图谱覆盖广泛的世界知识，领域知识图谱聚焦特定领域的专业知识。


interface KnowledgeGraph {
  name: string;
  type: 'general' | 'domain';
  entityCount: number;
  relationCount: number;
  tripleCount: number;
  schema: OntologySchema;
}

interface Triple {
  subject: Entity;
  predicate: Relation;
  object: Entity | LiteralValue;
  confidence?: number;
  source?: string;
  timestamp?: Date;
}

interface Entity {
  id: string;
  label: string;
  types: string[];
  aliases: string[];
  description: string;
  properties: Map<string, unknown>;
}

interface Relation {
  id: string;
  label: string;
  domain: string[];
  range: string[];
  symmetric: boolean;
  transitive: boolean;
}

interface OntologySchema {
  classes: ClassDefinition[];
  properties: PropertyDefinition[];
  constraints: Constraint[];
  axioms: Axiom[];
}

图数据模型
知识图谱的底层数据模型决定了其表达能力和查询方式。主流的图数据模型包括 RDF（Resource Description Framework）和属性图（Property Graph）两种。


interface RDFTriple {
  subject: string;
  predicate: string;
  object: string;
  graph?: string;
}

interface PropertyGraphNode {
  id: string;
  labels: string[];
  properties: Record<string, unknown>;
}

interface PropertyGraphEdge {
  id: string;
  type: string;
  sourceId: string;
  targetId: string;
  properties: Record<string, unknown>;
}

interface GraphDatabase {
  addNode(node: PropertyGraphNode): Promise<void>;
  addEdge(edge: PropertyGraphEdge): Promise<void>;
  query(cypher: string): Promise<QueryResult>;
  shortestPath(from: string, to: string): Promise<Path>;
  neighbors(nodeId: string, depth: number): Promise<SubGraph>;
}

interface SubGraph {
  nodes: PropertyGraphNode[];
  edges: PropertyGraphEdge[];
}
RDF 模型基于 W3C 标准，使用 SPARQL 查询语言，适合开放数据互联（Linked Data）场景。属性图模型更灵活，支持在节点和边上附加属性，使用 Cypher 或 Gremlin 查询语言，更适合工业应用。Neo4j 是最流行的属性图数据库，Apache Jena 和 Blazegraph 是 RDF 数据库的代表。

在选择图数据模型时，需要根据应用场景权衡。如果项目需要与开放数据集互联（如整合 Wikidata 或 DBpedia），RDF 是更自然的选择。如果项目侧重于高性能图查询和灵活的数据建模（如实时推荐或欺诈检测），属性图模型更合适。近年来 Neo4j 等属性图数据库也在逐步增加对 RDF 的兼容性，两种模型之间的边界正在模糊化。


知识图谱生命周期
知识图谱的建设是一个持续迭代的工程过程，涵盖需求分析、本体设计、知识获取、知识融合、存储与服务、评估与维护等阶段。


知识获取（Knowledge Acquisition）是知识图谱构建中最耗时的阶段，包括从结构化数据（数据库、表格）、半结构化数据（HTML、JSON）和非结构化数据（文本、图像）中提取实体和关系。知识融合（Knowledge Fusion）解决不同来源知识的冲突和冗余，包括实体对齐（Entity Alignment）、属性融合和冲突消解。

知识图谱的质量评估是一个持续过程，通常从准确性（三元组是否正确）、完整性（是否遗漏重要知识）和一致性（是否存在逻辑矛盾）三个维度进行衡量。工业实践中，新入库的三元组通常需要经过自动规则检查和人工抽样审核双重验证。


小结
    

  • 知识图谱以三元组形式存储实体和关系，是机器可理解的结构化知识表示
    • 

  • 通用知识图谱（Wikidata、Google KG）覆盖广泛世界知识，领域知识图谱聚焦专业领域
    • 

  • RDF 模型遵循 W3C 标准适合开放数据，属性图模型更灵活适合工业应用
    • 

  • 知识图谱建设是持续迭代过程，知识获取和融合是最核心的技术挑战
    • 

  • 图数据库（Neo4j、Jena）提供高效的图查询和遍历能力，支撑知识图谱的存储和服务
