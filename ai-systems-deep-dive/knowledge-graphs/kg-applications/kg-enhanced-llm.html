知识图谱增强 LLM

核心概念

知识图谱增强 LLM（KG-Enhanced LLM）是将知识图谱的结构化知识与大语言模型的自然语言处理能力结合的技术方向。LLM 擅长自然语言理解和生成但容易产生幻觉，KG 提供精确可验证的事实知识但缺乏灵活的自然语言交互能力。两者结合可以显著减少幻觉、提升事实准确性。

KG-RAG 检索增强

KG-RAG（Knowledge Graph Retrieval Augmented Generation）将知识图谱作为 RAG 的知识源，在 LLM 生成回答之前从 KG 中检索相关的结构化知识，作为上下文提供给模型。

interface KGRAGConfig {
  kg: KnowledgeGraph;
  llm: LLMClient;
  entityLinker: EntityLinker;
  maxTriples: number;
  maxHops: number;
}

async function kgRAG(question: string, config: KGRAGConfig): Promise<{ answer: string; sources: Triple[] }> {
  const entities = await config.entityLinker.link(question);
  const relevantTriples: Triple[] = [];

  for (const entity of entities) {
    const neighbors = config.kg.getNeighborTriples(entity.kgId, config.maxHops);
    const ranked = rankTriplesByRelevance(question, neighbors);
    relevantTriples.push(...ranked.slice(0, config.maxTriples));
  }

  const context = formatTriplesAsContext(relevantTriples);
  const prompt = buildKGRAGPrompt(question, context);
  const answer = await config.llm.generate(prompt);

  return { answer, sources: relevantTriples };
}

function formatTriplesAsContext(triples: Triple[]): string {
  return triples.map((t) => `${t.subject} - ${t.predicate} - ${t.object}`).join('\n');
}

function buildKGRAGPrompt(question: string, kgContext: string): string {
  return `基于以下知识图谱信息回答问题。如果信息不足，请说明。

知识图谱信息：
${kgContext}

问题：${question}
回答：`;
}

与传统文档 RAG 相比，KG-RAG 的优势是：知识以结构化形式存储，精确可控；三元组的粒度更细，减少了无关信息的干扰；图谱的关联关系支持多跳推理；知识的来源和置信度可追溯。

维度 文档 RAG KG-RAG
知识粒度 文本片段（段落/句子） 三元组（精确事实）
检索方式 向量相似度匹配 实体链接 + 图遍历
多跳推理 困难（需多次检索） 原生支持（图谱路径）
知识更新 重新索引文档 更新三元组（增量）
可溯源性 指向源文档 指向具体三元组和来源
噪声干扰 段落中混入无关信息 三元组粒度精确
适用场景 知识密集型文档问答 事实核查、结构化问答

KG-RAG 在实际部署中面临的主要挑战是实体链接的准确率。如果用户问题中的实体被错误地链接到图谱中的错误实体，后续检索的三元组将完全不相关，导致生成结果偏离。因此，实体链接的置信度阈值设置和回退策略（低置信度时降级为文档 RAG）是 KG-RAG 系统可靠性的关键保障。

LLM 驱动的 KG 构建

反过来，LLM 也可以增强知识图谱的构建。LLM 的强大语言理解能力使得从非结构化文本中抽取实体和关系变得更加准确和灵活。截至本篇更新（2026-08），"LLM 抽取三元组 + 本体 Schema 校验"已成为 GraphRAG 类系统构建图谱的标准路径——微软 GraphRAG、LightRAG 等主流实现的图谱构建层均基于此。

interface LLMKGExtractor {
  llm: LLMClient;
  schema: OntologySchema;
  validationKG: KnowledgeGraph;
}

async function extractTriplesByLLM(text: string, schema: OntologySchema, llm: LLMClient): Promise<Triple[]> {
  const entityTypes = schema.classes.map((c) => c.label).join(', ');
  const relationTypes = schema.properties.map((p) => p.label).join(', ');

  const prompt = `从以下文本中提取知识三元组。
实体类型：${entityTypes}
关系类型：${relationTypes}

文本：${text}

请以JSON数组格式输出三元组，每个三元组包含 subject、predicate、object 字段：`;

  const response = await llm.generate(prompt);
  const triples = parseTriples(response);
  return validateTriples(triples, schema);
}

function validateTriples(triples: Triple[], schema: OntologySchema): Triple[] {
  return triples.filter((t) => {
    const relation = schema.properties.find((p) => p.label === t.predicate);
    if (!relation) return false;
    return true;
  });
}

GraphRAG 与社区摘要

GraphRAG 是微软于 2024 年提出并开源的一种基于图结构的 RAG 方法。它不是简单地检索与问题相关的文档片段，而是首先用 LLM 从文档中抽取实体与关系构建知识图谱，然后利用图社区检测算法（通常为 Leiden）将图谱划分为多个主题社区，对每个社区分层生成摘要。查询时，系统将问题与社区摘要进行匹配，选择最相关的社区作为上下文。这种设计将原本分散在数百个文档中的全局信息压缩为若干社区摘要，使 LLM 能够在有限的上下文窗口内获得全局视角。

这种方法特别适合需要全局理解（如 "这个数据集的主要主题是什么"）而非局部检索的问题。传统向量 RAG 在这类问题上表现不佳，因为答案分散在大量文档中，无法通过局部相似度命中。

图 RAG 生态速览（2024 末–2026）

自原版 GraphRAG 开源以来，图 RAG 已从单一实现演化为一个快速演化的生态（以下信息以各项目官方仓库和技术报告为准）：

项目 来源 / 时间 核心思路 相对原版的关键差异
LazyGraphRAG 微软，2024 末 延迟计算：索引期仅用轻量嵌入 + NER 构建概念共现图，查询时才调用 LLM 精炼子图与摘要 索引成本降低约一个数量级，适合数据频繁变化场景
LightRAG 港大等，2024-10（arXiv:2410.05779） 双层检索：低层（实体细节）与高层（主题语义）并行，图谱支持增量插入 更轻量，增量更新无需全量重建社区
Graphiti Zep 开源，2024–2025 时序知识图谱：双时间轴建模（事件发生时间 vs 摄入时间），过时边标记失效而非删除 面向 Agent 记忆的动态图谱，支持时间感知检索

从工程视角看，这条演化线的共同趋势有三点：压低索引期的 LLM 调用成本、支持增量更新而非全量重建、从静态快照走向时序感知。选型直觉：静态语料的全局问答题可用原版 GraphRAG 或 LightRAG；数据高频变化、预算敏感优先 LazyGraphRAG 式延迟计算；Agent 长期记忆场景则应直接考虑 Graphiti 类时序图谱。

interface GraphRAGPipeline {
  extractEntities(chunks: string[]): Promise<Entity[]>;
  buildGraph(entities: Entity[], relations: Relation[]): KnowledgeGraph;
  detectCommunities(graph: KnowledgeGraph): Community[];
  summarizeCommunities(communities: Community[]): CommunitySummary[];
  query(question: string, summaries: CommunitySummary[]): Promise<string>;
}

interface Community {
  id: string;
  nodes: string[];
  edges: Array<{ source: string; target: string; relation: string }>;
  level: number;
}

interface CommunitySummary {
  communityId: string;
  title: string;
  summary: string;
  keyEntities: string[];
  embedding: Float32Array;
}

小结

  • KG 增强 LLM 通过结构化知识减少幻觉、提升事实准确性，是 AI 应用的核心技术方向
  • KG-RAG 在推理阶段从图谱检索结构化知识作为上下文，无需重训模型
  • LLM 反过来可以驱动 KG 构建，利用强大的语言理解能力提升抽取精度，且已成为图 RAG 系统构建图谱的标准路径
  • GraphRAG 通过社区摘要支持全局理解型问题，弥补了传统 RAG 的局限；LazyGraphRAG、LightRAG、Graphiti 等后续工作正在把它推向更低成本、增量更新与时序感知
  • KG 与 LLM 的结合是双向增强：KG 让 LLM 更准确，LLM 让 KG 更完善

延伸阅读与跨学科链接

  • 神经网络推理：LLM+KG 检索增强推理的方法基础
  • 知识图谱问答系统：KG 为 LLM 提供可验证事实的典型问答落地
  • 幻觉缓解（LLM 基础）：KG 增强 LLM 的核心动机——用结构化事实压制幻觉
  • RAG 架构（LLM 基础）：GraphRAG 是 RAG 与 KG 结合的延伸形态
