知识图谱问答系统

核心概念

知识图谱问答系统（Knowledge Graph Question Answering, KGQA）是将用户的自然语言问题转化为知识图谱查询并返回精确答案的系统。与传统搜索引擎返回文档列表不同，KGQA 直接返回结构化答案——用户问「姚明的身高是多少？」，系统返回「226 厘米」而非包含该信息的网页。KGQA 系统是搜索引擎知识面板、智能助手和企业知识管理的核心技术。

语义解析方法
语义解析（Semantic Parsing）方法将自然语言问题转换为结构化查询语言（如 SPARQL、Lambda DCS），再在知识图谱上执行查询获取答案。这是最传统也是精度最高的 KGQA 方法。


核心挑战在于构建从自然语言到逻辑形式的映射。早期方法使用手工编写的语法规则和组合语义，近年来 Seq2Seq 模型（如 T5、BART）被广泛用于端到端地将问题翻译为 SPARQL 查询。


interface SemanticParseResult {
  readonly question: string;
  readonly logicalForm: string;
  readonly sparql: string;
  readonly confidence: number;
  readonly entities: ReadonlyArray<LinkedEntity>;
  readonly relations: ReadonlyArray<string>;
}

interface LinkedEntity {
  readonly mention: string;
  readonly entityId: string;
  readonly entityLabel: string;
  readonly score: number;
}

interface SPARQLQuery {
  readonly selectVariables: ReadonlyArray<string>;
  readonly wherePatterns: ReadonlyArray<TriplePattern>;
  readonly filters: ReadonlyArray<string>;
  readonly orderBy?: string;
  readonly limit?: number;
}

interface TriplePattern {
  readonly subject: string;
  readonly predicate: string;
  readonly object: string;
}

function buildSPARQL(
  topicEntity: LinkedEntity,
  relation: string,
  questionType: 'simple' | 'count' | 'boolean' | 'comparative',
): SPARQLQuery {
  const basePattern: TriplePattern = {
    subject: `<${topicEntity.entityId}>`,
    predicate: `<${relation}>`,
    object: '?answer',
  };

  switch (questionType) {
    case 'simple':
      return {
        selectVariables: ['?answer'],
        wherePatterns: [basePattern],
        filters: [],
      };
    case 'count':
      return {
        selectVariables: ['(COUNT(?answer) AS ?count)'],
        wherePatterns: [basePattern],
        filters: [],
      };
    case 'boolean':
      return {
        selectVariables: ['?answer'],
        wherePatterns: [basePattern],
        filters: [],
        limit: 1,
      };
    case 'comparative':
      return {
        selectVariables: ['?answer'],
        wherePatterns: [basePattern],
        filters: [],
        orderBy: 'DESC(?answer)',
        limit: 1,
      };
  }
}
多跳问答与推理链
简单问答只涉及一跳关系查询（如「姚明的国籍是什么？」），而多跳问答需要在知识图谱上进行多步推理（如「姚明妻子的出生地在哪个省？」需要先找到妻子实体，再查出生地，最后查所属省份）。多跳问答的难度在于需要正确识别和排序推理链上的每一步关系。

interface MultiHopConfig {
  readonly maxHops: number;
  readonly beamSize: number;
  readonly scoreThreshold: number;
}

interface ReasoningPath {
  readonly entities: ReadonlyArray<string>;
  readonly relations: ReadonlyArray<string>;
  readonly score: number;
}

function multiHopSearch(
  startEntity: string,
  targetRelations: ReadonlyArray<string>,
  graph: ReadonlyMap<string, ReadonlyArray<{ relation: string; target: string }>>,
  config: MultiHopConfig,
): ReadonlyArray<ReasoningPath> {
  let beam: ReasoningPath[] = [
    {
      entities: [startEntity],
      relations: [],
      score: 1.0,
    },
  ];

  for (const targetRel of targetRelations) {
    const nextBeam: ReasoningPath[] = [];

    for (const path of beam) {
      const lastEntity = path.entities[path.entities.length - 1];
      const neighbors = graph.get(lastEntity) ?? [];

      for (const neighbor of neighbors) {
        const relScore = neighbor.relation === targetRel ? 1.0 : 0.1;
        nextBeam.push({
          entities: [...path.entities, neighbor.target],
          relations: [...path.relations, neighbor.relation],
          score: path.score * relScore,
        });
      }
    }

    beam = nextBeam.sort((a, b) => b.score - a.score).slice(0, config.beamSize);
  }

  return beam.filter((p) => p.score >= config.scoreThreshold);
}
LLM 增强的知识图谱问答
大语言模型为 KGQA 带来了新的范式。LLM 可以理解复杂的自然语言问题、生成 SPARQL 查询、对检索到的子图进行推理，并以自然语言格式化答案。典型的 LLM+KG 问答流程是：LLM 先识别问题中的实体和意图，然后从 KG 中检索相关子图，将子图信息作为上下文输入 LLM 生成最终答案。


这种方法的核心优势是零样本能力——不需要为每种问题类型标注训练数据。但也存在「幻觉」风险：LLM 可能生成与 KG 事实不一致的答案。通过将答案与 KG 进行事实验证可以缓解这一问题。


interface LLMKGQAConfig {
  readonly entityLinker: {
    readonly model: string;
    readonly topK: number;
  };
  readonly subgraphRetriever: {
    readonly maxHops: number;
    readonly maxTriples: number;
  };
  readonly llm: {
    readonly model: string;
    readonly temperature: number;
  };
  readonly factVerification: boolean;
}

interface QAResult {
  readonly question: string;
  readonly answer: string;
  readonly evidence: ReadonlyArray<{
    readonly subject: string;
    readonly predicate: string;
    readonly object: string;
  }>;
  readonly confidence: number;
  readonly verified: boolean;
}

function formatSubgraphAsContext(
  triples: ReadonlyArray<{ subject: string; predicate: string; object: string }>,
): string {
  const lines = triples.map((t) => `${t.subject} --[${t.predicate}]--> ${t.object}`);
  return `已知以下知识图谱事实：\n${lines.join('\n')}`;
}
小结
    

  • KGQA 将自然语言问题转化为知识图谱查询，返回精确的结构化答案
    • 

  • 语义解析方法精确可解释，但需要标注数据和领域适配
    • 

  • 多跳问答需要在知识图谱上进行多步推理，是 KGQA 的核心挑战
    • 

  • LLM + KG 结合实现了零样本问答能力，但需要事实验证防止幻觉
    • 

  • 实体链接（将文本提及映射到 KG 实体）的准确性直接决定问答质量
    • 

  • 工业系统通常采用混合管道：简单问题走信息抽取，复杂问题走语义解析
    • 

  • KGQA 是搜索引擎知识面板、智能助手和企业知识库的核心技术
