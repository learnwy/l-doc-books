关联规则挖掘

核心概念

关联规则挖掘是从事务数据中发现项目之间有趣关联关系的过程，是数据挖掘中最经典的无监督学习任务之一。其典型应用是购物篮分析——发现"购买尿布的顾客也倾向于购买啤酒"这类共现模式。关联规则挖掘不仅限于零售领域，在网页点击流分析、医疗诊断关联、基因表达模式发现等领域都有广泛应用。

关联规则的形式为 X → Y，其中 X 和 Y 是不相交的项集。规则的强度通过三个核心度量来评估：支持度（Support）表示 X∪Y 在所有事务中的出现频率，置信度（Confidence）表示在包含 X 的事务中同时包含 Y 的比例，提升度（Lift）衡量 X 和 Y 的关联是否超过随机共现水平。

Apriori 算法
Apriori 算法是关联规则挖掘的开创性算法，由 Agrawal 和 Srikant 于 1994 年提出。它基于一个关键的先验性质（Apriori Property）：频繁项集的所有子集也必须是频繁的，或者等价地说，非频繁项集的所有超集也一定是非频繁的。这一性质为搜索空间的剪枝提供了理论基础。


Apriori 采用逐层搜索的迭代策略。第一轮扫描数据库，统计所有单个项目的支持度，保留满足最小支持度的频繁 1-项集。第 k 轮由频繁 (k-1)-项集生成候选 k-项集，再扫描数据库计算候选项集的支持度，过滤出频繁 k-项集。迭代持续到无法生成新的候选项集为止。


候选生成阶段使用连接操作：两个 (k-1)-项集如果前 k-2 个项相同，就可以连接生成候选 k-项集。剪枝阶段检查候选 k-项集的所有 (k-1) 子集是否都在频繁 (k-1)-项集中，如果存在非频繁子集则直接剪枝。


Apriori 的主要瓶颈是需要多次扫描数据库（频繁项集的最大长度决定了扫描次数），并且在候选生成阶段可能产生大量候选项集。当事务数据库规模大或支持度阈值低时，算法效率显著下降。


FP-Growth 算法
FP-Growth（Frequent Pattern Growth）算法由 Han 等人于 2000 年提出，通过引入 FP-Tree 数据结构避免了候选生成步骤，只需两次扫描数据库即可完成频繁项集挖掘，效率远高于 Apriori。


FP-Tree 构建过程：第一次扫描数据库统计每个项目的支持度，按降序排列形成频繁项目列表。第二次扫描数据库，每条事务按频繁项目的降序重新排列后插入 FP-Tree。相同前缀的事务共享树节点，每个节点维护一个计数器记录经过该路径的事务数。同时，通过头表（Header Table）将相同项目的所有节点链接起来。


FP-Growth 挖掘过程：从头表中频率最低的项目开始，提取该项目的所有前缀路径构成条件模式基（Conditional Pattern Base），据此构建条件 FP-Tree，递归地在条件 FP-Tree 上挖掘频繁项集。这种分治策略将原始问题分解为更小的子问题，避免了显式的候选生成。

规则兴趣度度量
支持度和置信度是关联规则最基本的度量，但它们存在明显的局限性。高置信度的规则可能只是反映了结果项本身的高频率，而非真正的关联关系。因此，需要引入额外的兴趣度度量来筛选真正有价值的规则。


提升度（Lift）= P(Y|X)/P(Y) 衡量 X 对 Y 出现概率的提升程度。Lift=1 表示 X 和 Y 统计独立，Lift>1 表示正关联，Lift<1 表示负关联。提升度是最常用的补充度量，但它对稀有项目不敏感。


全置信度（All-Confidence）= Support(X∪Y)/max(Support(X), Support(Y))，保证规则中所有项目的支持度差异在可控范围内，避免了"头重脚轻"的规则。


Kulczynski 度量是 P(Y|X) 和 P(X|Y) 的算术平均，取值范围 [0,1]。它同时考虑了规则的双向置信度，对 null 事务（既不包含 X 也不包含 Y 的事务）不敏感，是近年来被推荐的综合度量。


不平衡比（Imbalance Ratio）= |P(X)-P(Y)|/(P(X)+P(Y)-P(X∪Y))，衡量 X 和 Y 的频率不平衡程度。结合 Kulczynski 度量和不平衡比，可以有效地识别和过滤虚假关联。

关联规则的实际应用
关联规则挖掘在多个领域有成熟的应用模式，但实际部署时需要注意数据特点和业务约束。


零售与电商是最经典的应用场景。购物篮分析帮助制定交叉销售策略和商品陈列方案。在线电商利用关联规则驱动"猜你喜欢"推荐。实践中需要处理的问题包括：事务定义（单次订单还是时间窗口内的多次购买）、长尾商品的支持度过低、季节性和促销活动的干扰。


医疗健康领域利用关联规则发现症状与疾病的共现模式、药物相互作用和治疗方案关联。医疗数据通常维度极高（数千种诊断编码）但事务较短（单次就诊涉及的诊断有限），需要特殊的支持度设定策略。


网络安全利用关联规则发现异常行为模式，如特定事件序列与攻击行为的关联。入侵检测系统通过挖掘正常网络流量的关联规则，将偏离正常模式的流量标记为潜在威胁。


序列模式挖掘是关联规则的时间扩展。将事务中的项目按时间顺序排列，发现"先浏览 A 类商品，然后在三天内购买 B 类商品"这类时序关联。GSP、PrefixSpan 和 SPADE 是三种主流的序列模式挖掘算法。


小结
    

  • 关联规则挖掘从事务数据中发现项目间的共现模式，形式为 X → Y
    • 

  • 支持度衡量规则普遍性，置信度衡量规则可靠性，提升度验证关联的真实性
    • 

  • Apriori 基于逐层搜索和先验剪枝，FP-Growth 通过 FP-Tree 避免候选生成，效率更高
    • 

  • 单一的支持度-置信度框架易产生虚假关联，Kulczynski 等补充度量能有效过滤
    • 

  • 实际应用需要考虑事务定义、长尾问题、季节性干扰等业务约束
    • 

  • 序列模式挖掘将关联规则扩展到时间维度，发现有序的行为模式
