语义搜索与图检索

核心概念

语义搜索是知识库系统对外服务的核心能力，通过结合向量检索、知识图谱遍历和全文检索实现超越关键词匹配的智能搜索体验。在多层知识库架构中，语义搜索横跨索引层、知识图谱层和缓存层，将底层的多种检索能力融合为统一的搜索接口。

向量检索与 ANN 索引
向量检索是语义搜索的基础能力。通过 Embedding 模型将查询和文档块映射到同一向量空间，利用向量距离度量语义相关性。向量检索的核心数据结构是近似最近邻（ANN）索引，它在牺牲少量精度的前提下实现了亚线性时间复杂度的相似度搜索。


HNSW（Hierarchical Navigable Small World）是目前工业界最广泛使用的 ANN 索引。它构建一个多层图结构，上层图稀疏、下层图稠密，搜索时从上层开始逐层定位到目标区域。HNSW 的关键参数是 M（每个节点的连接数）和 efConstruction（构建时的搜索范围），这两个参数决定了索引质量和构建速度的平衡。

const createVectorSearchPipeline = (embeddingModel: EmbeddingModel, vectorIndex: VectorIndex): SearchPipeline => ({
  search: async (query: string, topK: number, filter?: FilterExpression) => {
    const queryVector = await embeddingModel.encode(query);
    const results = await vectorIndex.search(queryVector, topK * 2, filter);
    return results.slice(0, topK).map((r) => ({
      id: r.id,
      score: r.score,
      source: 'vector' as const,
    }));
  },
});
向量检索的质量高度依赖 Embedding 模型的选择。通用 Embedding 模型（如 text-embedding-3-small）适合大多数场景，但在特定领域（如代码搜索、法律文档）可能需要领域微调的模型。多语言 Embedding 模型（如 multilingual-e5）能够处理跨语言检索需求。

知识图谱查询与图遍历
图检索利用知识图谱的结构化关系实现传统检索无法完成的推理查询。典型的图检索场景包括多跳推理（"React 依赖的底层引擎是什么"——需要 React → ReactDOM → V8 两跳遍历）、关系查询（"哪些框架实现了 Transformer 架构"）和路径发现（"从 JavaScript 到 WebAssembly 的技术演进路径"）。


查询解析是图检索的关键环节——需要将自然语言查询转换为图查询语言（如 Cypher、SPARQL）或图遍历操作。LLM 在此环节发挥重要作用，通过理解查询意图来生成对应的结构化图查询。

const nlToGraphQuery = async (query: string, ontology: Ontology, llm: LLMClient): Promise<CypherQuery> => {
  const entityTypes = ontology.entityTypes.map((t) => t.name).join(', ');
  const relationTypes = ontology.relationTypes.map((r) => r.name).join(', ');
  const prompt = `将以下自然语言查询转换为 Cypher 查询。
可用实体类型: ${entityTypes}
可用关系类型: ${relationTypes}
查询: ${query}`;
  const response = await llm.complete(prompt);
  return parseCypherQuery(response);
};
子图检索（Subgraph Retrieval）是图检索的高级形式，返回与查询相关的一个完整子图而非单个实体或路径。子图检索的核心算法是 Personalized PageRank（PPR），它从查询实体出发，通过随机游走在图上传播相关性分数，最终返回分数最高的节点和边构成的子图。


混合检索与结果融合
混合检索将向量检索、图检索和全文检索的结果融合为统一的排序列表。融合策略的选择直接影响最终搜索质量。


Reciprocal Rank Fusion（RRF）是最广泛使用的无参数融合方法，它不需要对不同检索源的分数进行归一化，而是根据每个结果在各检索源中的排名来计算综合分数。加权线性融合适用于检索源质量差异较大的场景，通过为不同源分配不同权重来反映其可信度。


interface HybridSearchEngine {
  search(query: string, options: SearchOptions): Promise<ReadonlyArray<HybridSearchResult>>;
}

interface SearchOptions {
  readonly topK: number;
  readonly sources: ReadonlyArray<'vector' | 'graph' | 'fulltext'>;
  readonly fusionMethod: 'rrf' | 'weighted_linear' | 'learned';
  readonly weights?: Record<string, number>;
  readonly filter?: FilterExpression;
}

interface HybridSearchResult {
  readonly id: string;
  readonly content: string;
  readonly score: number;
  readonly sources: ReadonlyArray<{ source: string; rank: number; score: number }>;
  readonly metadata: Record<string, unknown>;
}

const rrfFusion = (
  resultSets: ReadonlyArray<{ source: string; results: ReadonlyArray<{ id: string; score: number }> }>,
  k = 60,
): ReadonlyArray<HybridSearchResult> => {
  const scoreMap = new Map<string, { scores: Map<string, { rank: number; score: number }>; totalRRF: number }>();
  for (const { source, results } of resultSets) {
    results.forEach(({ id, score }, rank) => {
      const existing = scoreMap.get(id) ?? { scores: new Map(), totalRRF: 0 };
      existing.scores.set(source, { rank, score });
      existing.totalRRF += 1 / (k + rank + 1);
      scoreMap.set(id, existing);
    });
  }
  return [...scoreMap.entries()]
    .map(([id, { scores, totalRRF }]) => ({
      id,
      content: '',
      score: totalRRF,
      sources: [...scores.entries()].map(([source, { rank, score }]) => ({ source, rank, score })),
      metadata: {},
    }))
    .sort((a, b) => b.score - a.score);
};
查询理解与意图路由
查询理解模块分析用户查询的意图和结构，将不同类型的查询路由到最适合的检索策略。简单的关键词查询直接走全文检索，语义模糊的自然语言查询走向量检索，涉及实体关系的查询走图检索，复杂查询则走混合检索。


interface QueryUnderstanding {
  analyze(query: string): Promise<QueryAnalysis>;
}

interface QueryAnalysis {
  readonly intent: QueryIntent;
  readonly entities: ReadonlyArray<{ text: string; type: string }>;
  readonly keywords: ReadonlyArray<string>;
  readonly complexity: 'simple' | 'moderate' | 'complex';
  readonly suggestedSources: ReadonlyArray<'vector' | 'graph' | 'fulltext'>;
}

type QueryIntent =
  | 'fact_lookup'
  | 'concept_explanation'
  | 'comparison'
  | 'how_to'
  | 'relationship_query'
  | 'exploration';

const routeQuery = (analysis: QueryAnalysis): SearchOptions => {
  const baseOptions: SearchOptions = { topK: 10, sources: [], fusionMethod: 'rrf' };
  switch (analysis.intent) {
    case 'fact_lookup':
      return { ...baseOptions, sources: ['fulltext', 'vector'] };
    case 'relationship_query':
      return { ...baseOptions, sources: ['graph', 'vector'] };
    case 'concept_explanation':
      return { ...baseOptions, sources: ['vector', 'fulltext'] };
    case 'comparison':
      return { ...baseOptions, sources: ['vector', 'graph', 'fulltext'] };
    default:
      return { ...baseOptions, sources: analysis.suggestedSources };
  }
};

小结
    

  • 语义搜索融合向量检索、图检索和全文检索三种能力，提供超越关键词匹配的搜索体验
    • 

  • HNSW 索引是向量检索的主流方案，Embedding 模型的选择决定了语义匹配质量
    • 

  • 图检索通过知识图谱遍历实现多跳推理和关系查询，LLM 辅助自然语言到图查询的转换
    • 

  • RRF 融合算法无需分数归一化即可有效合并多源检索结果
    • 

  • 查询理解模块分析查询意图并路由到最优检索策略，避免不必要的计算开销
    • 

  • 端到端的搜索管道需要在每个环节优化延迟，确保整体响应时间在可接受范围内
    •
