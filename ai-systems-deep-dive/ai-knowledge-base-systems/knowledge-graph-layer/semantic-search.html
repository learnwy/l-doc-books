语义搜索与图检索

核心概念

语义搜索是知识库系统对外服务的核心能力，通过结合向量检索、知识图谱遍历和全文检索实现超越关键词匹配的智能搜索体验。

  • 在多层知识库架构中，语义搜索横跨索引层、知识图谱层和缓存层
  • 将底层的多种检索能力融合为统一的搜索接口
graph TD
    Q[用户查询] --> QU[查询理解]
    QU --> VR[向量检索]
    QU --> GR[图检索]
    QU --> TR[全文检索]
    VR --> F[结果融合]
    GR --> F
    TR --> F
    F --> RR[重排序]
    RR --> R[最终结果]

检索模式对比

检索模式 核心能力 优势场景 劣势场景 延迟
向量检索 语义相似度匹配 模糊语义查询 精确关键词匹配 5-50ms
图检索 关系推理与遍历 多跳推理查询 简单信息检索 10-200ms
全文检索 精确关键词匹配 术语精确查找 语义同义匹配 1-10ms
混合检索 多模态融合 复杂综合查询 简单查询过度开销 20-100ms

向量检索与 ANN 索引

向量检索是语义搜索的基础能力——通过 Embedding 模型将查询和文档块映射到同一向量空间，利用向量距离度量语义相关性。

ANN 索引与 HNSW

  • 核心数据结构是近似最近邻（ANN）索引，牺牲少量精度实现亚线性时间复杂度
  • HNSW（Hierarchical Navigable Small World）是工业界最广泛使用的 ANN 索引
  • 构建多层图结构：上层图稀疏、下层图稠密，搜索时从上层逐层定位到目标区域
HNSW 参数 含义 影响
M 每个节点的连接数 索引质量与内存占用
efConstruction 构建时的搜索范围 构建速度与索引质量平衡
efSearch 查询时的搜索范围 查询精度与延迟平衡

检索管道

vectorSearch(q, k):
  qv = encode(q)
  r = index.search(

  取前 k 个结果

Embedding 模型选型

向量检索的质量高度依赖 Embedding 模型的选择。

  • 通用模型适合大多数场景
  • 特定领域（代码搜索、法律文档）可能需要领域微调的模型
  • 多语言模型能够处理跨语言检索需求
Embedding 模型 维度 特点 适用场景
text-embedding-3-small 1536 通用、成本低 通用文档检索
text-embedding-3-large 3072 高精度 高质量要求场景
BGE-M3 1024 多语言、多粒度 跨语言检索
CodeBERT 768 代码语义 代码搜索
GTE-Qwen2 1024 中英双语 中文技术文档

知识图谱查询与图遍历

图检索利用知识图谱的结构化关系实现传统检索无法完成的推理查询。

典型图检索场景

路径发现 "从 JavaScript 到 WebAssembly 的技术演进路径"

LLM 辅助查询解析

查询解析是图检索的关键环节——将自然语言查询转换为图查询语言（Cypher、SPARQL）或图遍历操作，LLM 通过理解查询意图来生成对应的结构化图查询。

nlToGraphQuery:
  prompt 含三要素:
    可用实体类型
    可用关系类型
    用户查询
  llm 生成 Cypher
  解析并执行

子图检索与 PPR

  • 子图检索（Subgraph Retrieval）返回与查询相关的完整子图，而非单个实体或路径
  • 核心算法是 Personalized PageRank（PPR）
  • 从查询实体出发，通过随机游走在图上传播相关性分数
  • 返回分数最高的节点和边构成的子图

混合检索与结果融合

混合检索将向量检索、图检索和全文检索的结果融合为统一的排序列表，融合策略的选择直接影响最终搜索质量。

两类融合策略

  • RRF（Reciprocal Rank Fusion）：最广泛使用的无参数融合方法，不需要分数归一化，按结果在各检索源中的排名计算综合分数
  • 加权线性融合：适用于检索源质量差异较大的场景，为不同源分配权重反映可信度

RRF 实现

RRF (k=60):
  对每个检索源:
    第 rank 名得分
    += 1/(k+rank+1)
  按累计分降序

查询理解与意图路由

查询理解模块分析用户查询的意图和结构，将不同类型的查询路由到最适合的检索策略。

路由原则

  • 简单的关键词查询直接走全文检索
  • 语义模糊的自然语言查询走向量检索
  • 涉及实体关系的查询走图检索
  • 复杂查询走混合检索
routeQuery:
  事实查找
    -> 全文+向量
  关系查询
    -> 图+向量
  概念解释
    -> 向量+全文
  比较查询
    -> 三源混合

意图与检索源映射

查询意图 示例 优先检索源 原因
事实查找 "React 的最新版本号" 全文 > 向量 精确匹配需求
概念解释 "什么是微服务架构" 向量 > 全文 语义理解需求
关系查询 "Vite 依赖哪些工具" 图 > 向量 关系遍历需求
比较查询 "React vs Vue 的区别" 向量 + 图 + 全文 综合检索需求
操作指南 "如何配置 ESLint" 向量 > 全文 步骤性内容

小结

  • 语义搜索融合向量检索、图检索和全文检索三种能力，提供超越关键词匹配的搜索体验
  • HNSW 索引是向量检索的主流方案，Embedding 模型的选择决定了语义匹配质量
  • 图检索通过知识图谱遍历实现多跳推理和关系查询，LLM 辅助自然语言到图查询的转换
  • RRF 融合算法无需分数归一化即可有效合并多源检索结果
  • 查询理解模块分析查询意图并路由到最优检索策略，避免不必要的计算开销
  • 端到端的搜索管道需要在每个环节优化延迟，确保整体响应时间在可接受范围内
