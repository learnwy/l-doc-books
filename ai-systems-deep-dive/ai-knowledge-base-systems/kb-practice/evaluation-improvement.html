评估与持续改进

核心概念

知识库系统的评估与持续改进是确保系统价值持续增长的核心机制。评估不是一次性的验收测试，而是嵌入系统运营的持续过程。一个完善的评估体系需要覆盖知识质量、检索效果、回答质量和用户满意度四个维度，并通过数据驱动的方式识别改进方向和优先级。

离线评估方法
离线评估使用预先构建的评估数据集来系统性地测量知识库各组件的性能。评估数据集是离线评估的基础——它包含一组查询、对应的标准答案以及相关文档的标注。


检索效果评估使用 IR 标准指标。对于每个查询，检索系统返回一个排序列表，评估指标衡量这个列表与标准相关文档列表的匹配程度。NDCG@K 考虑了文档的等级相关性和位置折扣，是最全面的检索质量指标。


interface EvaluationDataset {
  readonly queries: ReadonlyArray<EvalQuery>;
  readonly version: string;
  readonly createdAt: Date;
}

interface EvalQuery {
  readonly id: string;
  readonly query: string;
  readonly relevantDocs: ReadonlyArray<RelevanceJudgment>;
  readonly expectedAnswer?: string;
  readonly category: string;
  readonly difficulty: 'easy' | 'medium' | 'hard';
}

interface RelevanceJudgment {
  readonly docId: string;
  readonly relevance: 0 | 1 | 2 | 3;
}

const computeNDCG = (rankedDocs: ReadonlyArray<string>, relevanceMap: Map<string, number>, k: number): number => {
  let dcg = 0;
  let idcg = 0;
  const idealRanking = [...relevanceMap.values()].sort((a, b) => b - a);
  for (let i = 0; i < k; i++) {
    if (i < rankedDocs.length) {
      const rel = relevanceMap.get(rankedDocs[i]) ?? 0;
      dcg += (Math.pow(2, rel) - 1) / Math.log2(i + 2);
    }
    if (i < idealRanking.length) {
      idcg += (Math.pow(2, idealRanking[i]) - 1) / Math.log2(i + 2);
    }
  }
  return idcg === 0 ? 0 : dcg / idcg;
};

const runOfflineEvaluation = async (
  dataset: EvaluationDataset,
  searchEngine: SearchEngine,
  ragPipeline: RAGPipeline,
): Promise<EvaluationReport> => {
  const retrievalMetrics: RetrievalMetrics[] = [];
  const answerMetrics: AnswerMetrics[] = [];
  for (const evalQuery of dataset.queries) {
    const searchResults = await searchEngine.search(evalQuery.query, { topK: 10 });
    const relevanceMap = new Map(evalQuery.relevantDocs.map((d) => [d.docId, d.relevance]));
    const ndcg = computeNDCG(
      searchResults.map((r) => r.id),
      relevanceMap,
      10,
    );
    const recall = searchResults.filter((r) => relevanceMap.has(r.id)).length / evalQuery.relevantDocs.length;
    retrievalMetrics.push({ queryId: evalQuery.id, ndcg, recall, precision: 0 });
    if (evalQuery.expectedAnswer) {
      const answer = await ragPipeline.answer(evalQuery.query);
      const faithfulness = await evaluateFaithfulness(answer, searchResults);
      const relevance = await evaluateRelevance(answer, evalQuery.query);
      answerMetrics.push({ queryId: evalQuery.id, faithfulness, relevance, completeness: 0 });
    }
  }
  return { retrievalMetrics, answerMetrics, timestamp: new Date() };
};
回答质量评估使用 LLM-as-Judge 方法——让一个独立的 LLM 对 RAG 系统的回答进行多维度评分。评估维度包括忠实度（答案是否忠于检索到的上下文）、相关性（答案是否回答了用户的问题）、完整性（答案是否覆盖了所有方面）和有害性（答案是否包含不当内容）。


在线评估与 A/B 测试
在线评估通过真实用户流量来测量知识库系统的实际效果。与离线评估相比，在线评估能够捕获到更多的真实用户行为信号——用户是否点击了检索结果、是否在回答后继续追问、是否给出了正面或负面反馈。


A/B 测试是在线评估的核心方法。当对知识库的检索策略、Embedding 模型或 Prompt 模板进行改进时，可以通过 A/B 测试对比新旧方案的效果。A/B 测试的关键设计要素包括流量分配（随机且均匀）、评估指标（定义清晰的 primary metric）、统计显著性（确保样本量足够）和实验周期（避免新鲜度效应）。

数据飞轮与持续改进
数据飞轮是知识库系统持续改进的核心机制——用户的每一次交互都产生数据，这些数据经过分析后反馈到系统的各个环节，形成正向循环。


检索飞轮：用户的点击和跳过行为被记录为隐式相关性反馈，这些反馈用于训练和优化检索模型。随着数据积累，检索质量持续提升，进一步增加用户使用频率和数据产出。


知识飞轮：用户查询中频繁出现但知识库未覆盖的问题被自动识别为知识缺口。知识缺口分析报告驱动知识采集和生产，扩大知识覆盖范围。


质量飞轮：用户的负面反馈和查询重写行为被用于识别低质量知识。低质量知识进入审核和改进队列，改进后的知识提升整体质量水平。


interface DataFlywheel {
  readonly feedbackCollector: FeedbackCollector;
  readonly gapAnalyzer: KnowledgeGapAnalyzer;
  readonly qualityImprover: QualityImprover;
  readonly modelTrainer: ModelTrainer;
}

interface KnowledgeGapAnalyzer {
  analyzeGaps(timeRange: TimeRange): Promise<GapReport>;
}

interface GapReport {
  readonly uncoveredTopics: ReadonlyArray<{ topic: string; queryCount: number; urgency: number }>;
  readonly lowQualityAreas: ReadonlyArray<{ area: string; avgQualityScore: number; affectedQueries: number }>;
  readonly emergingTopics: ReadonlyArray<{ topic: string; growthRate: number; firstSeen: Date }>;
}

interface QualityImprover {
  prioritizeImprovements(report: GapReport): ReadonlyArray<ImprovementTask>;
  executeImprovement(task: ImprovementTask): Promise<ImprovementResult>;
}

interface ImprovementTask {
  readonly type: 'add_knowledge' | 'update_knowledge' | 'fix_quality' | 'retrain_model';
  readonly target: string;
  readonly priority: number;
  readonly estimatedImpact: number;
  readonly estimatedEffort: number;
}

const runWeeklyImprovement = async (flywheel: DataFlywheel, timeRange: TimeRange): Promise<ImprovementSummary> => {
  const gaps = await flywheel.gapAnalyzer.analyzeGaps(timeRange);
  const tasks = flywheel.qualityImprover.prioritizeImprovements(gaps);
  const topTasks = tasks.filter((t) => t.priority > 0.7).slice(0, 10);
  const results = [];
  for (const task of topTasks) {
    const result = await flywheel.qualityImprover.executeImprovement(task);
    results.push(result);
  }
  return {
    gapsCovered: gaps.uncoveredTopics.length,
    tasksExecuted: results.length,
    qualityImprovement: results.reduce((sum, r) => sum + r.qualityDelta, 0) / results.length,
  };
};
