知识质量保障体系

核心概念

知识质量保障（Knowledge Quality Assurance，KQA）是贯穿知识库全生命周期的系统化工程。

  • 确保入库、存储和服务的每一条知识都满足准确性、完整性、一致性和时效性
  • 在 LLM 驱动的知识库中尤为重要——LLM 生成的摘要、实体和关系都可能包含幻觉（hallucination）
  • 不加验证地入库会污染整个知识网络
graph TD
    A[入库质量门] --> B[存储期检查]
    B --> C[服务期监控]
    C --> D[反馈驱动优化]
    D --> A
    A --> E[格式验证]
    A --> F[内容验证]
    A --> G[一致性验证]
    C --> H[使用指标]
    C --> I[用户反馈]

五个质量维度

质量维度 定义 检测方法 自动化程度
准确性 知识内容与真实世界一致 源文档交叉验证、事实核查 中
完整性 知识涵盖了必要的信息 Schema 完整性检查、缺失字段检测 高
一致性 不同知识点之间不矛盾 知识图谱约束验证、冲突检测 高
时效性 知识反映当前状态 源更新检测、时间戳比对 高
可读性 知识表达清晰易理解 可读性评分、结构检测 中

入库质量门控

质量门控（Quality Gate）是在知识正式入库前的最后一道关卡，通过一系列自动化检查来拦截低质量或有问题的知识。门控策略采用分级设计——不同严重级别的问题触发不同的处理流程。

门控模型

QualityCheck 的核心字段如下。

字段 取值
category format / content / consistency
severity blocker / critical / warning
check 异步检查函数，返回 CheckResult

门控执行逻辑

runQualityGate(gate, doc):
  并行运行所有检查
  hasBlocker =
    存在未通过的 blocker
  avg = 平均得分
  passed = 无 blocker
    且 avg >= minScore
  action = reject 或 accept

检查项分级

检查项 类别 严重级别 检测方法 自动修复
必填字段缺失 格式 阻断 Schema 验证 否
内容过短 (<100 tokens) 内容 严重 Token 计数 否
编码错误 格式 阻断 编码检测 是
重复内容 内容 严重 SimHash / MinHash 否
死链接 格式 警告 URL 验证 否
格式不规范 格式 信息 Lint 规则 是

格式验证与内容验证

  • 格式验证：必要字段（标题、内容、来源）是否存在，内容长度是否合理，编码是否正确
  • 内容验证：信息量是否足够（非空段落比例），是否存在复制粘贴或模板痕迹，代码片段是否完整

LLM 输出验证

LLM 生成的内容是知识库中最需要质量把控的部分。幻觉问题在知识库场景下尤其危险——一个错误的实体关系或不准确的摘要会在后续的检索和问答中被反复引用，造成级联错误。

三类验证策略

验证策略 做法
事实性验证 摘要中的事实断言与原文逐条比对，用 NLI 模型判断能否从原文推导
结构性验证 检查输出是否符合 JSON Schema：字段完整性、类型、枚举值合法性
一致性验证 新抽取的三元组与知识图谱已有知识比对，检测矛盾

摘要忠实度验证实现

validateFaithfulness:
  claims = 抽取摘要断言
  对每条断言:
    NLI 判断原文蕴含与否
  score = 蕴含比例
  valid = score >= 0.9
  • 无法从原文推导的断言被标记为 hallucination 类 issue
  • 验证结果附带置信度，供人工复核排序

知识一致性检测

知识一致性检测确保知识库中不存在互相矛盾的信息——同一实体在不同文档中被赋予不同属性值，或不同三元组产生逻辑矛盾时，需要识别冲突并提供解决方案。

graph LR
    N[新知识入库] --> C[冲突检测器]
    E[已有知识] --> C
    C --> D{冲突?}
    D -->|否| A[直接入库]
    D -->|是| R[冲突解决]
    R --> M{手动?}
    M -->|是| H[人工审核队列]
    M -->|否| AU[自动解决]
    AU --> A
    H --> A

冲突解决优先级规则

规则 含义
时间优先 更新的信息通常更准确
源优先 官方文档优先于社区讨论
置信度优先 高置信度抽取结果优先于低置信度

无法自动解决的冲突进入人工审核队列，并附带冲突的上下文信息以辅助决策。

冲突数据模型

要素 取值
冲突类型 attribute_conflict / relation_conflict / type_conflict
冲突双方 existingTriple 与 newTriple
解决动作 keep_existing / replace / merge / escalate

持续质量监控

入库后的知识也需要持续监控，定期运行检查任务，检测知识质量的衰减趋势。

核心监控指标

指标 含义
检索命中率 知识被检索到的频率
用户满意度 基于反馈评分
引用准确率 知识被用于生成答案的比例
更新频率 源文档更新后知识库跟进的延迟

异常检测与告警

  • 检索命中率突然下降，可能意味着用户需求变化或知识内容已过时
  • 时间序列分析方法（ARIMA、Prophet）建立质量指标基线
  • 偏离基线超过阈值时自动触发告警

监控结果模型

字段 含义
value 当前指标值
baseline 基线值
status normal / warning / critical
trend improving / stable / degrading

小结

  • 知识质量保障贯穿入库、存储和服务全生命周期，采用分级门控策略
  • 入库质量门控通过格式、内容和一致性三类检查拦截低质量知识
  • LLM 输出验证通过 NLI 模型进行事实性核查，防止幻觉内容入库
  • 知识一致性检测识别跨文档的属性和关系冲突，按优先级规则自动或人工解决
  • 持续质量监控通过时间序列分析建立基线，自动检测质量衰减趋势
  • 端到端的质量体系需要自动化工具和人工审核的有机结合，既保证效率又确保准确性
