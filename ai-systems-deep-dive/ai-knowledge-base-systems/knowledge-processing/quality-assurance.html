知识质量保障体系

核心概念

知识质量保障（Knowledge Quality Assurance，KQA）是贯穿知识库全生命周期的系统化工程，确保入库、存储和服务的每一条知识都满足准确性、完整性、一致性和时效性的要求。在 LLM 驱动的知识库中，质量保障的重要性更加突出——LLM 生成的摘要、实体和关系都可能包含幻觉（hallucination），如果不加验证地入库，会污染整个知识网络。

入库质量门控
质量门控（Quality Gate）是在知识正式入库前的最后一道关卡，通过一系列自动化检查来拦截低质量或有问题的知识。门控策略采用分级设计——不同严重级别的问题触发不同的处理流程。


interface QualityGate {
  readonly checks: ReadonlyArray<QualityCheck>;
  readonly policy: GatePolicy;
}

interface QualityCheck {
  readonly name: string;
  readonly category: 'format' | 'content' | 'consistency' | 'freshness';
  readonly severity: 'blocker' | 'critical' | 'warning' | 'info';
  readonly check: (doc: ProcessedDocument) => Promise<CheckResult>;
}

interface CheckResult {
  readonly passed: boolean;
  readonly score: number;
  readonly issues: ReadonlyArray<QualityIssue>;
}

interface QualityIssue {
  readonly code: string;
  readonly message: string;
  readonly location?: TextSpan;
  readonly suggestion?: string;
  readonly autoFixable: boolean;
}

interface GatePolicy {
  readonly blockOnBlocker: boolean;
  readonly minScore: number;
  readonly maxCriticalIssues: number;
  readonly requireManualReview: boolean;
}

const createQualityGate = (checks: ReadonlyArray<QualityCheck>): QualityGate => ({
  checks,
  policy: {
    blockOnBlocker: true,
    minScore: 0.7,
    maxCriticalIssues: 2,
    requireManualReview: false,
  },
});

const runQualityGate = async (gate: QualityGate, doc: ProcessedDocument): Promise<GateResult> => {
  const results = await Promise.all(
    gate.checks.map(async (check) => ({
      checkName: check.name,
      severity: check.severity,
      result: await check.check(doc),
    })),
  );
  const hasBlocker = results.some((r) => r.severity === 'blocker' && !r.result.passed);
  const criticalCount = results.filter((r) => r.severity === 'critical' && !r.result.passed).length;
  const avgScore = results.reduce((sum, r) => sum + r.result.score, 0) / results.length;
  return {
    passed: !hasBlocker && criticalCount <= gate.policy.maxCriticalIssues && avgScore >= gate.policy.minScore,
    score: avgScore,
    results,
    action: hasBlocker ? 'reject' : criticalCount > 0 ? 'review' : 'accept',
  };
};
格式验证检查文档结构的完整性——必要的字段（标题、内容、来源）是否存在，内容长度是否在合理范围内，编码是否正确。内容验证检查知识的实质质量——是否包含足够的信息量（非空段落比例），是否存在明显的复制粘贴或模板痕迹，代码片段是否完整。

LLM 输出验证
LLM 生成的内容是知识库中最需要质量把控的部分。LLM 幻觉问题在知识库场景下尤其危险——一个错误的实体关系或不准确的摘要会在后续的检索和问答中被反复引用，造成级联错误。


验证 LLM 输出的核心策略包括：事实性验证——将 LLM 生成的摘要中的事实断言与原文进行逐条比对，使用 NLI（自然语言推理）模型判断摘要中的每个陈述是否能从原文中推导出来。结构性验证——检查 LLM 输出是否符合预定义的 JSON Schema，包括字段完整性、类型正确性和枚举值合法性。一致性验证——将新抽取的三元组与知识图谱中已有的知识进行比对，检测是否存在矛盾。


interface LLMOutputValidator {
  validateSummary(summary: string, source: string): Promise<ValidationResult>;
  validateEntities(entities: ReadonlyArray<ExtractedEntity>, source: string): Promise<ValidationResult>;
  validateTriples(triples: ReadonlyArray<ExtractedTriple>, existingKG: KnowledgeGraph): Promise<ValidationResult>;
}

interface ValidationResult {
  readonly valid: boolean;
  readonly score: number;
  readonly issues: ReadonlyArray<ValidationIssue>;
  readonly corrections: ReadonlyArray<Correction>;
}

interface ValidationIssue {
  readonly type: 'hallucination' | 'inconsistency' | 'incompleteness' | 'format_error';
  readonly description: string;
  readonly evidence: string;
  readonly confidence: number;
}

interface Correction {
  readonly original: string;
  readonly corrected: string;
  readonly reason: string;
  readonly autoApply: boolean;
}

const validateSummaryFaithfulness = async (summary: string, source: string): Promise<ValidationResult> => {
  const claims = extractClaims(summary);
  const results = await Promise.all(
    claims.map(async (claim) => {
      const nliResult = await checkEntailment(source, claim);
      return {
        claim,
        entailed: nliResult.label === 'entailment',
        score: nliResult.score,
      };
    }),
  );
  const faithfulClaims = results.filter((r) => r.entailed);
  const score = faithfulClaims.length / results.length;
  return {
    valid: score >= 0.9,
    score,
    issues: results
      .filter((r) => !r.entailed)
      .map((r) => ({
        type: 'hallucination' as const,
        description: `摘要中的断言无法从原文推导: "${r.claim}"`,
        evidence: r.claim,
        confidence: 1 - r.score,
      })),
    corrections: [],
  };
};
知识一致性检测
知识一致性检测确保知识库中不存在互相矛盾的信息。当同一个实体在不同文档中被赋予不同的属性值，或者不同的关系三元组产生逻辑矛盾时，一致性检测系统需要识别这些冲突并提供解决方案。


冲突解决策略遵循优先级规则：时间优先——更新的信息通常更准确；源优先——官方文档优先于社区讨论；置信度优先——高置信度的抽取结果优先于低置信度的。对于无法自动解决的冲突，系统将其放入人工审核队列，并提供冲突的上下文信息以辅助决策。


interface ConflictDetector {
  detect(newTriple: ExtractedTriple, kg: KnowledgeGraph): Promise<ReadonlyArray<Conflict>>;
  resolve(conflict: Conflict, strategy: ResolutionStrategy): Promise<Resolution>;
}

interface Conflict {
  readonly type: 'attribute_conflict' | 'relation_conflict' | 'type_conflict';
  readonly existingTriple: ExtractedTriple;
  readonly newTriple: ExtractedTriple;
  readonly description: string;
}

type ResolutionStrategy = 'newer_wins' | 'source_priority' | 'confidence_priority' | 'manual';

interface Resolution {
  readonly conflictId: string;
  readonly action: 'keep_existing' | 'replace' | 'merge' | 'escalate';
  readonly result?: ExtractedTriple;
  readonly reason: string;
}
持续质量监控
入库后的知识也需要持续监控。持续质量监控系统定期运行一系列检查任务，检测知识质量的衰减趋势。监控的核心指标包括检索命中率（知识被检索到的频率）、用户满意度（基于反馈评分）、引用准确率（知识被用于生成答案的比例）和更新频率（源文档更新后知识库跟进的延迟）。


异常检测算法用于识别质量突变——当某类知识的检索命中率突然下降，可能意味着用户需求发生了变化或者知识内容已过时。时间序列分析方法（如 ARIMA、Prophet）可以建立质量指标的基线，偏离基线超过阈值时自动触发告警。


interface QualityMonitor {
  readonly checks: ReadonlyArray<MonitorCheck>;
  readonly schedule: CronExpression;
  readonly alertThresholds: Record<string, number>;
}

interface MonitorCheck {
  readonly name: string;
  readonly metric: string;
  readonly evaluate: () => Promise<MonitorResult>;
}

interface MonitorResult {
  readonly metric: string;
  readonly value: number;
  readonly baseline: number;
  readonly deviation: number;
  readonly status: 'normal' | 'warning' | 'critical';
  readonly trend: 'improving' | 'stable' | 'degrading';
}

const createQualityDashboard = (monitors: ReadonlyArray<QualityMonitor>): QualityDashboard => ({
  getOverview: async () => {
    const results = await Promise.all(monitors.flatMap((m) => m.checks.map((c) => c.evaluate())));
    return {
      totalChecks: results.length,
      passRate: results.filter((r) => r.status === 'normal').length / results.length,
      criticalIssues: results.filter((r) => r.status === 'critical'),
      degradingMetrics: results.filter((r) => r.trend === 'degrading'),
    };
  },
});
小结
    

  • 知识质量保障贯穿入库、存储和服务全生命周期，采用分级门控策略
    • 

  • 入库质量门控通过格式、内容和一致性三类检查拦截低质量知识
    • 

  • LLM 输出验证通过 NLI 模型进行事实性核查，防止幻觉内容入库
    • 

  • 知识一致性检测识别跨文档的属性和关系冲突，按优先级规则自动或人工解决
    • 

  • 持续质量监控通过时间序列分析建立基线，自动检测质量衰减趋势
    • 

  • 端到端的质量体系需要自动化工具和人工审核的有机结合，既保证效率又确保准确性
