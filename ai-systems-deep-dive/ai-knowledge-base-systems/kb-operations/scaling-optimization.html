扩展与性能优化

核心概念

知识库系统的扩展与性能优化是应对业务增长和性能要求的工程实践。随着知识条目从万级增长到千万级甚至亿级，系统面临存储容量、检索延迟和并发吞吐三重挑战。性能优化需要从索引结构、查询执行、缓存策略和系统架构四个层面协同推进，在检索精度、延迟和资源成本之间找到最优平衡。

向量索引优化
向量检索是知识库的性能瓶颈所在。原始向量（如 1536 维 float32）占用大量内存，暴力搜索在大规模场景下不可行。向量量化和近似最近邻（ANN）索引是核心优化手段。


interface VectorIndexConfig {
  readonly indexType: 'flat' | 'ivf-flat' | 'ivf-pq' | 'hnsw' | 'scann';
  readonly dimension: number;
  readonly metric: 'cosine' | 'l2' | 'inner-product';
  readonly quantization: {
    readonly type: 'none' | 'scalar' | 'product' | 'binary';
    readonly bits: number;
    readonly subQuantizers?: number;
  };
  readonly hnswParams?: {
    readonly m: number;
    readonly efConstruction: number;
    readonly efSearch: number;
  };
  readonly ivfParams?: {
    readonly nlist: number;
    readonly nprobe: number;
  };
}

interface IndexBenchmark {
  readonly config: VectorIndexConfig;
  readonly buildTimeSeconds: number;
  readonly indexSizeBytes: number;
  readonly queryLatencyP50Ms: number;
  readonly queryLatencyP99Ms: number;
  readonly recall10: number;
  readonly qps: number;
}

const estimateIndexSize = (
  numVectors: number,
  config: VectorIndexConfig,
): { readonly rawSizeGB: number; readonly indexSizeGB: number; readonly compressionRatio: number } => {
  const rawBytesPerVector = config.dimension * 4;
  const rawSizeGB = (numVectors * rawBytesPerVector) / 1024 ** 3;

  let bytesPerVector: number;
  switch (config.quantization.type) {
    case 'none':
      bytesPerVector = rawBytesPerVector;
      break;
    case 'scalar':
      bytesPerVector = config.dimension * (config.quantization.bits / 8);
      break;
    case 'product':
      bytesPerVector = (config.quantization.subQuantizers ?? 48) * (config.quantization.bits / 8);
      break;
    case 'binary':
      bytesPerVector = config.dimension / 8;
      break;
  }

  const overheadFactor = config.indexType === 'hnsw' ? 1.5 : 1.2;
  const indexSizeGB = (numVectors * bytesPerVector * overheadFactor) / 1024 ** 3;

  return {
    rawSizeGB,
    indexSizeGB,
    compressionRatio: rawSizeGB / indexSizeGB,
  };
};

const selectOptimalConfig = (
  numVectors: number,
  memoryBudgetGB: number,
  latencyBudgetMs: number,
  minRecall: number,
): VectorIndexConfig => {
  if (numVectors < 100000) {
    return {
      indexType: 'flat',
      dimension: 1536,
      metric: 'cosine',
      quantization: { type: 'none', bits: 32 },
    };
  }

  if (numVectors < 10000000) {
    return {
      indexType: 'hnsw',
      dimension: 1536,
      metric: 'cosine',
      quantization: { type: 'scalar', bits: 8 },
      hnswParams: { m: 32, efConstruction: 200, efSearch: 128 },
    };
  }

  return {
    indexType: 'ivf-pq',
    dimension: 1536,
    metric: 'cosine',
    quantization: { type: 'product', bits: 8, subQuantizers: 48 },
    ivfParams: { nlist: Math.ceil(Math.sqrt(numVectors)), nprobe: 32 },
  };
};
HNSW（Hierarchical Navigable Small World）是当前最广泛使用的 ANN 索引算法，在召回率和查询速度之间提供了优秀的平衡。关键调参包括：M（每层邻居数，影响索引大小和召回率）、efConstruction（构建精度）和 efSearch（查询精度，越大越准但越慢）。Product Quantization（PQ）将高维向量分割为多个子空间，在每个子空间内使用码本量化，可将内存占用降低 4-16 倍。


缓存策略与查询优化
缓存是提升知识库 QPS 最直接有效的手段。知识库查询具有明显的热点特征：少量高频查询占据大部分流量。多级缓存策略在不同粒度上拦截重复计算。


interface CacheConfig {
  readonly levels: ReadonlyArray<{
    readonly name: string;
    readonly type: 'exact-match' | 'semantic' | 'embedding';
    readonly maxSize: number;
    readonly ttlSeconds: number;
    readonly evictionPolicy: 'lru' | 'lfu' | 'ttl';
  }>;
  readonly semanticSimilarityThreshold: number;
}

interface CacheEntry {
  readonly key: string;
  readonly embedding?: ReadonlyArray<number>;
  readonly results: ReadonlyArray<{ readonly docId: string; readonly score: number }>;
  readonly createdAt: number;
  readonly hitCount: number;
}

const semanticCacheLookup = (
  queryEmbedding: ReadonlyArray<number>,
  cache: ReadonlyArray<CacheEntry>,
  threshold: number,
): CacheEntry | null => {
  let bestMatch: CacheEntry | null = null;
  let bestSimilarity = threshold;

  for (const entry of cache) {
    if (!entry.embedding) continue;
    const similarity = cosineSimilarity(queryEmbedding, entry.embedding);
    if (similarity > bestSimilarity) {
      bestSimilarity = similarity;
      bestMatch = entry;
    }
  }

  return bestMatch;
};

const cosineSimilarity = (a: ReadonlyArray<number>, b: ReadonlyArray<number>): number => {
  let dot = 0,
    normA = 0,
    normB = 0;
  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
  }
  const denom = Math.sqrt(normA) * Math.sqrt(normB);
  return denom > 0 ? dot / denom : 0;
};
语义缓存（Semantic Cache）是知识库特有的缓存策略：当新查询与缓存中某个查询的语义相似度超过阈值时，直接返回缓存结果。这比精确匹配缓存的命中率高出数倍，特别适合用户使用不同措辞表达相同意图的场景。

水平扩展架构
当单机无法承载知识库的数据规模和查询压力时，需要通过水平扩展将数据和计算分散到多台机器上。知识库的水平扩展核心策略是数据分片（Sharding）和查询路由。


interface ShardingConfig {
  readonly strategy: 'hash' | 'range' | 'category';
  readonly numShards: number;
  readonly replicaFactor: number;
  readonly rebalanceThreshold: number;
}

interface ShardInfo {
  readonly shardId: number;
  readonly documentCount: number;
  readonly indexSizeBytes: number;
  readonly node: string;
  readonly isPrimary: boolean;
}

const routeQuery = (
  query: string,
  config: ShardingConfig,
  metadata?: ReadonlyMap<string, string>,
): ReadonlyArray<number> => {
  switch (config.strategy) {
    case 'hash':
      return Array.from({ length: config.numShards }, (_, i) => i);
    case 'category': {
      const category = metadata?.get('category');
      if (category) {
        const targetShard = hashString(category) % config.numShards;
        return [targetShard];
      }
      return Array.from({ length: config.numShards }, (_, i) => i);
    }
    case 'range':
      return Array.from({ length: config.numShards }, (_, i) => i);
  }
};

const hashString = (str: string): number => {
  let hash = 0;
  for (let i = 0; i < str.length; i++) {
    hash = (hash << 5) - hash + str.charCodeAt(i);
    hash = hash & hash;
  }
  return Math.abs(hash);
};

const mergeShardResults = (
  shardResults: ReadonlyArray<{
    readonly shardId: number;
    readonly results: ReadonlyArray<{ readonly docId: string; readonly score: number }>;
  }>,
  topK: number,
): ReadonlyArray<{ readonly docId: string; readonly score: number }> => {
  const allResults = shardResults.flatMap((sr) => sr.results);
  return allResults.sort((a, b) => b.score - a.score).slice(0, topK);
};
分片策略的选择取决于查询模式：哈希分片保证数据均匀分布但查询必须广播到所有分片；按类目分片可以将查询路由到特定分片减少扇出，但可能导致数据倾斜。生产环境通常采用二级分片：先按类目粗分，再在类目内按哈希细分。


小结
    

  • 向量索引优化通过 HNSW 调参和 PQ 量化在内存、速度和精度之间寻求平衡
    • 

  • 语义缓存利用嵌入向量相似度匹配缓存命中率可达 30-50%，远超精确匹配缓存
    • 

  • 多级缓存（精确→语义→结果）在不同层面拦截重复计算，整体可提升 QPS 2-5 倍
    • 

  • 水平扩展通过数据分片和查询路由将负载分散到多台机器，实现近线性扩展
    • 

  • 分片策略需要根据查询模式选择，避免数据倾斜和不必要的广播查询
    • 

  • 性能优化是持续过程，需要基于监控数据不断调整索引参数和缓存策略
