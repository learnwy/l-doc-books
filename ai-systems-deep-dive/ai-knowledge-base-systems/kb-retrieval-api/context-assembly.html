上下文组装与 Prompt 工程

核心概念

上下文组装（Context Assembly）是 RAG 管道中将检索到的知识片段、用户查询和系统指令组合为 LLM 输入的过程。这一环节直接决定了 LLM 回答的质量——不恰当的上下文组装会导致答案偏离主题、遗漏关键信息或产生幻觉。Prompt 工程在此环节发挥核心作用，通过精心设计的模板和策略来引导 LLM 生成准确、完整、有据可查的回答。

检索结果后处理
检索到的原始结果通常包含冗余和噪声，需要经过后处理才能作为有效的上下文。后处理包括三个步骤：去重（移除内容高度重叠的片段）、过滤（根据相关性阈值移除低质量结果）和排序（按照对回答的贡献度重新排序）。


去重策略需要在语义层面而非字符层面工作。由于文本切分时使用了重叠窗口，相邻的切片可能包含大量重复内容。通过计算片段之间的余弦相似度，当相似度超过阈值（如 0.85）时只保留得分更高的片段。


interface PostProcessor {
  process(chunks: ReadonlyArray<RetrievedChunk>, config: PostProcessConfig): ReadonlyArray<RetrievedChunk>;
}

interface PostProcessConfig {
  readonly deduplicationThreshold: number;
  readonly minRelevanceScore: number;
  readonly maxChunks: number;
  readonly diversityWeight: number;
}

const createPostProcessor = (embeddingModel: EmbeddingModel): PostProcessor => ({
  process: (chunks, config) => {
    const filtered = chunks.filter((c) => c.score >= config.minRelevanceScore);
    const deduplicated = maxMarginalRelevance(filtered, config.deduplicationThreshold, config.diversityWeight);
    return deduplicated.slice(0, config.maxChunks);
  },
});

const maxMarginalRelevance = (
  chunks: ReadonlyArray<RetrievedChunk>,
  threshold: number,
  diversityWeight: number,
): ReadonlyArray<RetrievedChunk> => {
  const selected: RetrievedChunk[] = [];
  const remaining = [...chunks];
  while (remaining.length > 0) {
    let bestIdx = 0;
    let bestScore = -Infinity;
    for (let i = 0; i < remaining.length; i++) {
      const relevance = remaining[i].score;
      const maxSimilarity =
        selected.length > 0 ? Math.max(...selected.map((s) => computeSimilarity(remaining[i], s))) : 0;
      const mmrScore = (1 - diversityWeight) * relevance - diversityWeight * maxSimilarity;
      if (mmrScore > bestScore) {
        bestScore = mmrScore;
        bestIdx = i;
      }
    }
    if (selected.length > 0) {
      const maxSim = Math.max(...selected.map((s) => computeSimilarity(remaining[bestIdx], s)));
      if (maxSim > threshold) break;
    }
    selected.push(remaining[bestIdx]);
    remaining.splice(bestIdx, 1);
  }
  return selected;
};
Maximal Marginal Relevance（MMR）算法在去重的同时保证结果的多样性——它在选择下一个片段时同时考虑与查询的相关性和与已选片段的差异性，通过 λ 参数控制二者的平衡。


Prompt 模板设计
Prompt 模板是上下文组装的骨架，定义了系统指令、上下文片段和用户查询的组织方式。好的 Prompt 模板需要满足几个目标：明确 LLM 的角色和行为边界、清晰地标记上下文和查询的边界、指导 LLM 如何处理不确定性（如知识不足时说明而非编造）。


interface PromptTemplate {
  readonly name: string;
  readonly systemPrompt: string;
  readonly contextFormat: string;
  readonly queryFormat: string;
  readonly variables: ReadonlyArray<TemplateVariable>;
}

interface TemplateVariable {
  readonly name: string;
  readonly type: 'string' | 'chunks' | 'metadata';
  readonly required: boolean;
}

const QA_TEMPLATE: PromptTemplate = {
  name: 'knowledge_qa',
  systemPrompt: `你是一个基于知识库的专业问答助手。请严格根据提供的参考资料回答问题。
规则：

2. 如果参考资料不足以回答问题，明确说明

多文档综合策略
当查询涉及多个主题或需要综合多个来源的信息时，简单的上下文拼接往往不够——可能超出 token 限制，或者 LLM 难以从大量上下文中提取和综合关键信息。


Map-Reduce 策略将问题分解为两个阶段。Map 阶段：对每个检索到的文档片段独立生成一个中间回答。Reduce 阶段：将所有中间回答综合为最终回答。这种策略能够处理远超上下文窗口的文档量，但增加了 LLM 调用次数和延迟。


Refine 策略是另一种处理多文档的方法——它依次处理每个文档片段，每次在上一轮回答的基础上进行细化和补充。这种策略保证了信息的渐进式整合，但由于是串行处理，延迟更高。


interface MultiDocStrategy {
  synthesize(query: string, chunks: ReadonlyArray<RetrievedChunk>, llm: LLMClient): Promise<SynthesisResult>;
}

interface SynthesisResult {
  readonly answer: string;
  readonly intermediateResults: ReadonlyArray<string>;
  readonly llmCalls: number;
  readonly totalTokens: number;
}

const createMapReduceStrategy = (batchSize: number): MultiDocStrategy => ({
  synthesize: async (query, chunks, llm) => {
    const batches = partition(chunks, batchSize);
    const mapResults = await Promise.all(
      batches.map(async (batch) => {
        const context = batch.map((c) => c.content).join('\n---\n');
        return llm.complete(`根据以下资料，回答问题: ${query}\n\n资料:\n${context}`);
      }),
    );
    const reduceContext = mapResults.map((r, i) => `[来源组 ${i + 1}] ${r}`).join('\n\n');
    const answer = await llm.complete(
      `综合以下各组回答，生成一个完整、不重复的最终回答:\n问题: ${query}\n\n${reduceContext}`,
    );
    return {
      answer,
      intermediateResults: mapResults,
      llmCalls: batches.length + 1,
      totalTokens: 0,
    };
  },
});
引用与溯源
知识库问答的一个核心要求是可溯源性——用户需要知道答案来自哪些原始文档，以便验证和深入阅读。引用系统需要在回答中精确标记每个事实断言的来源。


实现引用的技术方案有两种：Inline 引用——在 Prompt 中要求 LLM 以 [1][2] 格式标注引用；后处理引用——生成回答后，通过 NLI 模型将回答中的每个句子与检索到的片段进行匹配，自动添加引用标注。


interface CitationResult {
  readonly answer: string;
  readonly citations: ReadonlyArray<Citation>;
}

interface Citation {
  readonly index: number;
  readonly text: string;
  readonly sourceId: string;
  readonly sourceTitle: string;
  readonly confidence: number;
  readonly span: { start: number; end: number };
}

const addPostHocCitations = async (
  answer: string,
  chunks: ReadonlyArray<RetrievedChunk>,
  nliModel: NLIModel,
): Promise<CitationResult> => {
  const sentences = splitSentences(answer);
  const citations: Citation[] = [];
  let citationIndex = 1;
  for (const sentence of sentences) {
    const matches = await Promise.all(
      chunks.map(async (chunk) => ({
        chunk,
        entailment: await nliModel.checkEntailment(chunk.content, sentence),
      })),
    );
    const bestMatch = matches
      .filter((m) => m.entailment.score > 0.7)
      .sort((a, b) => b.entailment.score - a.entailment.score)[0];
    if (bestMatch) {
      citations.push({
        index: citationIndex++,
        text: sentence,
        sourceId: bestMatch.chunk.id,
        sourceTitle: bestMatch.chunk.source,
        confidence: bestMatch.entailment.score,
        span: { start: answer.indexOf(sentence), end: answer.indexOf(sentence) + sentence.length },
      });
    }
  }
  return { answer, citations };
};
小结
    

  • 上下文组装将检索结果、用户查询和系统指令组合为最优化的 LLM 输入
    • 

  • MMR 算法在去重时兼顾相关性和多样性，避免检索结果同质化
    • 

  • Prompt 模板按场景差异化设计，通用问答、对比分析、操作指南各有专属模板
    • 

  • Map-Reduce 和 Refine 策略处理超出上下文窗口的多文档综合问题
    • 

  • 可溯源的引用系统通过 Inline 或后处理方式将答案中的每个断言关联到原始来源
    • 

  • Token 预算管理在系统指令、上下文、查询和生成之间合理分配有限资源
