上下文组装与 Prompt 工程

核心概念

上下文组装（Context Assembly）是 RAG 管道中将检索到的知识片段、用户查询和系统指令组合为 LLM 输入的过程。

  • 这一环节直接决定 LLM 回答的质量
  • 不恰当的上下文组装会导致答案偏离主题、遗漏关键信息或产生幻觉
  • Prompt 工程通过精心设计的模板和策略引导 LLM 生成准确、完整、有据可查的回答
graph TD
    R[检索结果] --> F[过滤与去重]
    F --> S[排序与选择]
    S --> C[压缩与格式化]
    C --> T[模板填充]
    Q[用户查询] --> T
    I[系统指令] --> T
    T --> V[Token 验证]
    V --> L[LLM 输入]

组装策略对比

组装策略 适用场景 上下文利用率 实现复杂度
简单拼接 通用问答 60-70% 低
相关性排序 精确问答 70-80% 中
分层组装 复杂推理 80-90% 高
动态压缩 长文档 85-95% 高
Map-Reduce 多文档综合 75-85% 高

检索结果后处理

检索到的原始结果通常包含冗余和噪声，需要经过后处理才能作为有效的上下文。

三个后处理步骤

步骤 做法
去重 移除内容高度重叠的片段
过滤 根据相关性阈值移除低质量结果
排序 按照对回答的贡献度重新排序

语义级去重

  • 去重需要在语义层面而非字符层面工作
  • 文本切分使用重叠窗口，相邻切片可能包含大量重复内容
  • 计算片段之间的余弦相似度，超过阈值（如 0.85）时只保留得分更高的片段

MMR 算法

Maximal Marginal Relevance（MMR）算法在去重的同时保证结果的多样性——选择下一个片段时同时考虑与查询的相关性和与已选片段的差异性，通过 λ 参数控制二者的平衡。

MMR(chunks, λ):
  循环直到无剩余:
    对每个剩余片段 i:
      mmr = (1-λ)·relevance(i)
          - λ·max(sim(i, 已选))
    选 mmr 最高者
    若其与已选相似度 > 阈值: 停止
    移入已选集合

Prompt 模板设计

Prompt 模板是上下文组装的骨架，定义了系统指令、上下文片段和用户查询的组织方式。

模板设计目标

  • 明确 LLM 的角色和行为边界
  • 清晰地标记上下文和查询的边界
  • 指导 LLM 如何处理不确定性（知识不足时说明而非编造）

问答模板示例

系统: 你是基于知识库的问答助手。
规则:
1. 只使用参考资料中的信息
2. 资料不足以回答时明确说明
3. 引用具体的资料来源
4. 使用清晰的中文表达

参考资料:
[来源 {i}] {source}
{content}

问题: {query}

按场景差异化模板

模板类型 适用场景 系统指令重点 输出格式
通用问答 单一知识点查询 忠实性、引用 段落文本
对比分析 多方案比较 客观性、维度 表格 + 建议
操作指南 How-to 类问题 步骤清晰 编号步骤
概念解释 知识概念理解 深入浅出 渐进式解释
代码生成 技术实现问题 可运行、简洁 代码块 + 说明

多文档综合策略

当查询涉及多个主题或需要综合多个来源的信息时，简单的上下文拼接往往不够——可能超出 token 限制，或者 LLM 难以从大量上下文中提取和综合关键信息。

Map-Reduce 策略

  • Map 阶段：对每个检索到的文档片段独立生成一个中间回答
  • Reduce 阶段：将所有中间回答综合为最终回答
  • 能够处理远超上下文窗口的文档量，但增加了 LLM 调用次数和延迟
graph TD
    C1[片段 1] --> M1[中间回答 1]
    C2[片段 2] --> M2[中间回答 2]
    C3[片段 N] --> M3[中间回答 N]
    M1 --> R[Reduce 综合回答]
    M2 --> R
    M3 --> R
mapReduce(query, chunks, batchSize):
  分批 -> 每批并行:
    中间回答 = llm(query + 该批资料)
  最终 = llm("综合以下各组回答,
    生成完整不重复的回答" + 全部中间回答)
  llm 调用数 = 批数 + 1

Refine 策略

  • 依次处理每个文档片段
  • 每次在上一轮回答的基础上进行细化和补充
  • 保证信息的渐进式整合，但串行处理延迟更高

引用与溯源

知识库问答的一个核心要求是可溯源性——用户需要知道答案来自哪些原始文档，以便验证和深入阅读。引用系统需要在回答中精确标记每个事实断言的来源。

两种引用方案

方案 做法
Inline 引用 在 Prompt 中要求 LLM 以 [1][2] 格式标注引用
后处理引用 生成回答后用 NLI 模型将每个句子与检索片段匹配，自动添加标注

后处理引用流程

postHocCitations(answer, chunks, nli):
  对回答中每个句子:
    对每个片段计算 entailment 分数
    取分数 > 0.7 的最佳匹配
    记录 (句子, 来源 id, 置信度, 位置)
  返回 { answer, citations }

小结

  • 上下文组装将检索结果、用户查询和系统指令组合为最优化的 LLM 输入
  • MMR 算法在去重时兼顾相关性和多样性，避免检索结果同质化
  • Prompt 模板按场景差异化设计，通用问答、对比分析、操作指南各有专属模板
  • Map-Reduce 和 Refine 策略处理超出上下文窗口的多文档综合问题
  • 可溯源的引用系统通过 Inline 或后处理方式将答案中的每个断言关联到原始来源
  • Token 预算管理在系统指令、上下文、查询和生成之间合理分配有限资源
