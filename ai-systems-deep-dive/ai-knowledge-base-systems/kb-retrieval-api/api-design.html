知识库 API 设计

核心概念

知识库 API 是多层架构中的最上层，封装了底层所有的检索、推理和生成能力，为外部应用提供统一的访问接口。

  • API 设计需要兼顾功能完整性、使用便捷性和性能可控性
  • 既要让开发者能够利用知识库的全部能力
  • 又要通过合理的抽象隐藏内部复杂性
graph TD
    A[认证/授权] --> R[路由]
    R --> RL[限流]
    RL --> D[降级策略]
    D --> S[搜索 API]
    D --> Q[问答 API]
    D --> B[浏览 API]
    D --> M[管理 API]
    S --> C[核心服务层]
    Q --> C
    B --> C
    M --> C

API 类别总览

API 类别 核心端点 使用场景 认证级别
搜索 API /search, /similar 关键词和语义搜索 基础
问答 API /ask, /chat 对话式知识问答 基础
浏览 API /browse, /topics 知识导航和发现 基础
管理 API /ingest, /update, /stats 知识入库和系统管理 管理员
评估 API /evaluate, /feedback 质量评估和用户反馈 基础

RESTful 与 Streaming API 设计

知识库 API 需要同时支持两种交互模式：请求-响应模式用于搜索和浏览，流式模式用于 LLM 生成的问答回答。

搜索 API 设计决策

  • 分页策略：使用 cursor-based 分页而非 offset-based，避免数据更新时出现重复或遗漏
  • 过滤语法：支持布尔表达式和范围查询
  • 结果格式：包含原文片段、高亮匹配和元数据
SearchRequest 字段 含义
query 查询文本
topK 返回结果数
filter 过滤表达式
sources vector / fulltext / graph 任意组合
cursor 分页游标

过滤表达式

type FilterExpression =
  | { type: 'eq'; field: string; value: unknown }
  | { type: 'range'; field: string; min?; max? }
  | { type: 'in'; field: string; values: unknown[] }
  | { type: 'and' | 'or'; conditions: FilterExpression[] };

问答 API 流式输出

  • 使用 Server-Sent Events（SSE）实现流式输出
  • 用户在 LLM 生成过程中就能看到部分回答
  • 改善用户体验（减少首字节时间）
  • 客户端能在生成过程中展示中间状态（正在检索、正在生成）
  • 事件类型：status / chunk / reference / done / error

API 版本化与兼容性

API 版本化确保知识库的内部演进不会破坏现有客户端。

版本策略选型

版本策略 优势 劣势 适用场景
URL 路径 直观、易路由 URL 变化 公开 API
Query 参数 URL 稳定 容易遗漏 内部 API
Header 语义清晰 调试不便 企业级 API

选择 URL 路径版本（/v1/search、/v2/search）——在浏览器和日志中更直观，也更容易做路由和负载均衡。

三条兼容性原则

  • 增量添加——新版本可以添加新字段和新端点，但不删除或重命名已有字段
  • 过渡期——废弃功能在至少两个版本周期内保持可用，通过 Deprecation Header 提醒客户端
  • SDK 抽象——官方 SDK 封装版本差异，客户端升级 SDK 即可透明迁移
废弃信息字段 含义
version 被废弃的版本号
deprecatedAt 宣布废弃的时间
sunsetAt 彻底下线的时间
migrationGuide 迁移指南链接

限流与降级策略

知识库 API 中不同端点的资源消耗差异巨大——搜索 API 主要消耗 CPU 和内存，问答 API 还额外消耗昂贵的 LLM 计算资源，限流策略需要差异化配置。

graph TD
    R[请求到达] --> T[Token Bucket 检查]
    T --> P{配额充足?}
    P -->|是| H[正常处理]
    P -->|否| D[降级策略]
    D --> D1[搜索降级]
    D --> D2[缓存答案]
    D --> D3[429 拒绝]

级联降级链

降级策略是保障系统可用性的最后一道防线，每层降级都对用户透明，通过响应中的 degradation 字段告知当前服务级别。

触发条件 降级动作
LLM 服务不可用 问答 API 降级为搜索 API，只返回文档片段
向量数据库不可用 语义搜索降级为 BM25 全文搜索
延迟超过 5000ms 返回缓存或部分结果 
降级链:
  llm 不可用
    -> 退回搜索
  向量库不可用
    -> 退回全文
  延迟 > 5s
    -> 缓存/部分结果
  均通知客户端

SDK 设计与开发者体验

官方 SDK 封装了 API 的复杂性，为不同编程语言的开发者提供类型安全和符合语言习惯的接口。TypeScript SDK 能够充分利用类型系统提供编译时校验和自动补全。

四条设计原则

原则 含义
零配置默认 开箱即用，只需提供 API Key
渐进式配置 高级用户可细粒度配置每个参数
流式优先 问答接口默认使用流式输出
错误友好 错误包含清晰的错误码、描述和建议修复方案

客户端接口

KBClient 方法 返回
search Promise（搜索响应）
ask AsyncGenerator（SSE 事件流）
browse Promise（目录浏览响应）
ingest Promise（入库结果） 
ask 流式实现:
  POST /v1/ask
    { stream: true }
  逐块读取 body
  解析 SSE 并 yield

小结

  • 知识库 API 封装搜索、问答、浏览和管理四大类接口，通过网关统一认证、限流和降级
  • 搜索 API 使用 RESTful + cursor 分页，问答 API 使用 SSE 流式输出
  • API 版本化采用 URL 路径策略，废弃功能保留两个版本周期的过渡期
  • 差异化限流根据端点资源消耗特征配置，LLM 调用的配额严格独立管理
  • 级联降级策略确保每层服务不可用时都有可接受的 fallback 方案
  • SDK 遵循零配置默认和渐进式配置原则，为开发者提供类型安全的接口
