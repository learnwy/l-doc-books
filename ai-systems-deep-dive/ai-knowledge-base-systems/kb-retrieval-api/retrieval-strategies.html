检索策略与 RAG 管道

核心概念

检索增强生成（Retrieval-Augmented Generation，RAG）是知识库系统最核心的服务模式，通过检索相关知识片段并将其注入 LLM 的上下文窗口来生成准确、有据可查的回答。RAG 管道的设计直接决定了知识库的回答质量——检索不到相关知识会导致 LLM 生成幻觉，检索到不相关的噪声则会误导 LLM 产生错误答案。

查询改写与扩展
查询改写是 RAG 管道中提升检索召回率的关键环节。用户的原始查询通常是简短且模糊的，直接用于检索可能遗漏大量相关内容。查询改写通过多种策略来扩展和优化查询。


HyDE（Hypothetical Document Embedding）是一种创新的查询改写方法——先让 LLM 生成一个假设性的理想答案文档，然后用这个假设文档的 Embedding 去检索真实文档。由于假设文档比原始查询更接近目标文档的语义分布，因此能显著提升向量检索的召回率。


查询分解将复杂查询拆分为多个简单子查询分别检索。例如 "React 和 Vue 在状态管理上的区别" 可以分解为 "React 状态管理方案" 和 "Vue 状态管理方案" 两个子查询，各自检索后合并结果。


interface QueryRewriter {
  rewrite(query: string): Promise<ReadonlyArray<RewrittenQuery>>;
}

interface RewrittenQuery {
  readonly text: string;
  readonly strategy: 'original' | 'hyde' | 'decomposed' | 'expanded';
  readonly weight: number;
}

const createHyDERewriter = (llm: LLMClient): QueryRewriter => ({
  rewrite: async (query) => {
    const hydePrompt = `请针对以下问题，写一段假设性的理想答案（约 200 字）：\n${query}`;
    const hypotheticalDoc = await llm.complete(hydePrompt);
    return [
      { text: query, strategy: 'original', weight: 0.3 },
      { text: hypotheticalDoc, strategy: 'hyde', weight: 0.7 },
    ];
  },
});

const createDecomposer = (llm: LLMClient): QueryRewriter => ({
  rewrite: async (query) => {
    const decomposePrompt = `将以下复杂查询分解为 2-4 个简单子查询（JSON 数组）：\n${query}`;
    const subQueries = JSON.parse(await llm.complete(decomposePrompt)) as string[];
    return [
      { text: query, strategy: 'original', weight: 0.4 },
      ...subQueries.map((sq) => ({ text: sq, strategy: 'decomposed' as const, weight: 0.6 / subQueries.length })),
    ];
  },
});
上下文组装与 Token 管理
上下文组装是 RAG 管道中将检索结果转化为 LLM 输入的关键步骤。核心挑战是在有限的上下文窗口内最大化有用信息的密度——需要在保留足够上下文的同时避免超出 token 限制。


上下文压缩技术用于在不丢失关键信息的前提下缩短检索到的文本。常见的压缩方法包括：抽取式压缩——只保留与查询最相关的句子；LLM 压缩——让 LLM 总结检索片段，去除冗余信息；去重压缩——检测并移除多个检索片段中的重复内容。


interface ContextAssembler {
  assemble(
    query: string,
    retrievedChunks: ReadonlyArray<RetrievedChunk>,
    config: AssemblyConfig,
  ): Promise<AssembledContext>;
}

interface AssemblyConfig {
  readonly maxTokens: number;
  readonly reservedTokensForQuery: number;
  readonly reservedTokensForResponse: number;
  readonly chunkSeparator: string;
  readonly promptTemplate: string;
  readonly compressionEnabled: boolean;
}

interface AssembledContext {
  readonly prompt: string;
  readonly tokenCount: number;
  readonly includedChunks: ReadonlyArray<string>;
  readonly truncated: boolean;
}

interface RetrievedChunk {
  readonly id: string;
  readonly content: string;
  readonly score: number;
  readonly source: string;
  readonly tokenCount: number;
}

const assembleContext = (
  query: string,
  chunks: ReadonlyArray<RetrievedChunk>,
  config: AssemblyConfig,
): AssembledContext => {
  const availableTokens = config.maxTokens - config.reservedTokensForQuery - config.reservedTokensForResponse;
  const deduplicated = removeDuplicateContent(chunks);
  const selected: RetrievedChunk[] = [];
  let usedTokens = 0;
  for (const chunk of deduplicated) {
    if (usedTokens + chunk.tokenCount > availableTokens) break;
    selected.push(chunk);
    usedTokens += chunk.tokenCount;
  }
  const contextText = selected.map((c) => c.content).join(config.chunkSeparator);
  const prompt = config.promptTemplate.replace('{{context}}', contextText).replace('{{query}}', query);
  return {
    prompt,
    tokenCount: countTokens(prompt),
    includedChunks: selected.map((c) => c.id),
    truncated: selected.length < deduplicated.length,
  };
};

高级 RAG 模式
基础 RAG 管道存在几个已知的局限性：单轮检索可能遗漏需要多次推理的信息，平面检索难以处理需要结构化推理的问题，检索结果可能包含过时或矛盾的信息。高级 RAG 模式通过更复杂的检索和生成策略来解决这些问题。


Agentic RAG 将 RAG 管道嵌入到一个 Agent 循环中——LLM 不仅生成答案，还能决定何时需要更多信息、从哪里检索以及如何组合不同来源的知识。Agent 会在多轮交互中迭代地细化查询和检索，直到获得足够的信息来生成可靠的答案。


GraphRAG 将知识图谱与 RAG 结合，先从知识图谱中检索相关的子图，再将子图信息和文本检索结果一起注入 LLM 上下文。这种方式特别适合需要结构化推理的问题，如 "React 生态中的状态管理库有哪些，它们各自的设计理念是什么"。


interface AgenticRAG {
  answer(query: string, maxIterations: number): Promise<AgentResponse>;
}

interface AgentResponse {
  readonly answer: string;
  readonly sources: ReadonlyArray<SourceReference>;
  readonly reasoning: ReadonlyArray<ReasoningStep>;
  readonly iterations: number;
}

interface ReasoningStep {
  readonly action: 'search' | 'graph_query' | 'analyze' | 'synthesize';
  readonly input: string;
  readonly output: string;
  readonly confidence: number;
}

const createAgenticRAG = (
  retriever: HybridSearchEngine,
  graphEngine: GraphQueryEngine,
  llm: LLMClient,
): AgenticRAG => ({
  answer: async (query, maxIterations) => {
    const steps: ReasoningStep[] = [];
    let currentQuery = query;
    let context = '';
    for (let i = 0; i < maxIterations; i++) {
      const action = await decideAction(llm, currentQuery, context);
      if (action.type === 'synthesize') break;
      if (action.type === 'search') {
        const results = await retriever.search(action.query, {
          topK: 5,
          sources: ['vector', 'fulltext'],
          fusionMethod: 'rrf',
        });
        context += results.map((r) => r.content).join('\n');
        steps.push({
          action: 'search',
          input: action.query,
          output: `Retrieved ${results.length} chunks`,
          confidence: 0.8,
        });
      }
      if (action.type === 'graph_query') {
        const graphResult = await graphEngine.query(action.query);
        context += JSON.stringify(graphResult.entities);
        steps.push({
          action: 'graph_query',
          input: action.query,
          output: `Found ${graphResult.entities.length} entities`,
          confidence: 0.9,
        });
      }
      currentQuery = action.nextQuery ?? currentQuery;
    }
    const answer = await generateAnswer(llm, query, context);
    return { answer, sources: [], reasoning: steps, iterations: steps.length };
  },
});
回答质量评估
RAG 系统的回答质量需要从多个维度进行评估。忠实度（Faithfulness）衡量回答是否忠于检索到的上下文，不添加未经证实的信息。相关性（Relevance）衡量回答是否回答了用户的问题。完整性（Completeness）衡量回答是否覆盖了查询涉及的所有方面。


自动化评估通常使用 LLM-as-Judge 的方式——让另一个 LLM 对回答进行评分。RAGAS 是一个流行的 RAG 评估框架，提供了忠实度、答案相关性、上下文精确度和上下文召回率四个核心指标。

小结
    

  • RAG 管道通过检索知识片段注入 LLM 上下文实现有据可查的回答生成
    • 

  • HyDE 和查询分解是提升检索召回率的两种有效查询改写策略
    • 

  • 上下文组装需要在有限 token 预算内最大化有用信息密度
    • 

  • Agentic RAG 将检索嵌入 Agent 循环，支持多轮迭代检索和推理
    • 

  • GraphRAG 结合知识图谱实现结构化推理，特别适合关系型问题
    • 

  • RAGAS 框架的四个核心指标全面评估 RAG 系统的回答质量
