全量微调

核心概念

全量微调（Full Fine-Tuning）是指更新模型的所有参数来适应目标任务。这是最直接也是效果上限最高的微调方式，但代价是需要大量的 GPU 显存和计算资源。全量微调会修改预训练模型的每个参数，因此模型可以深度适应目标领域，但也更容易出现灾难性遗忘。

graph TB
    A[预训练权重 W] --> B[前向传播]
    B --> C[计算损失 L]
    C --> D[反向传播]
    D --> E[梯度 ∇W]
    E --> F[优化器更新]
    F --> G[更新后权重 W']
    G --> B
特性 全量微调 LoRA QLoRA
可训练参数 100% 0.1-1% 0.1-1%
显存需求 最高 低 最低
训练速度 慢 快 中等
效果上限 最高 高 中高
灾难性遗忘风险 高 低 低
适用场景 大幅度领域迁移 轻度适配 资源受限

HuggingFace Trainer 实践

HuggingFace 的 Trainer API 是全量微调的标准实现。它封装了训练循环、评估、检查点保存和分布式训练等复杂逻辑：

from transformers import (
    AutoModelForCausalLM,
    AutoTokenizer,
    TrainingArguments,
    Trainer,
    DataCollatorForSeq2Seq,
)
from datasets import load_dataset

model_name = "Qwen/Qwen3-8B"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype="auto",
    device_map="auto",
)

if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token

dataset = load_dataset("json", data_files="train.jsonl", split="train")

def preprocess(examples):
    texts = []
    for messages in examples["messages"]:
        text = tokenizer.apply_chat_template(messages, tokenize=False)
        texts.append(text)
    encodings = tokenizer(texts, truncation=True, max_length=2048, padding=False)
    encodings["labels"] = encodings["input_ids"].copy()
    return encodings

tokenized = dataset.map(preprocess, batched=True, remove_columns=dataset.column_names)

training_args = TrainingArguments(
    output_dir="./output",
    num_train_epochs=3,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,
    learning_rate=2e-5,
    weight_decay=0.01,
    warmup_ratio=0.03,
    lr_scheduler_type="cosine",
    bf16=True,
    gradient_checkpointing=True,
    save_strategy="epoch",
    eval_strategy="epoch",
    logging_steps=10,
    save_total_limit=3,
    report_to="wandb",
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized,
    data_collator=DataCollatorForSeq2Seq(tokenizer, padding=True),
)

trainer.train()
trainer.save_model("./final-model")

关键超参数的选择直接影响训练效果：学习率通常设置在 1e-5 到 5e-5 之间，epoch 数控制在 1-5 轮，warmup 比例为 3-10%。

关键超参数调优

超参数的选择需要在欠拟合和过拟合之间取得平衡。以下是全量微调中最重要的超参数及其调优策略：

interface HyperparameterGuide {
  name: string;
  range: string;
  default: string;
  impact: string;
  tuningStrategy: string;
}

const hyperparameters: HyperparameterGuide[] = [
  {
    name: 'learning_rate',
    range: '1e-6 ~ 5e-5',
    default: '2e-5',
    impact: '过高导致不稳定，过低收敛慢',
    tuningStrategy: '先用 2e-5 试跑，看 loss 曲线调整',
  },
  {
    name: 'num_train_epochs',
    range: '1 ~ 5',
    default: '3',
    impact: '过多导致过拟合',
    tuningStrategy: '监控验证集 loss，出现上升则停止',
  },
  {
    name: 'effective_batch_size',
    range: '32 ~ 256',
    default: '64',
    impact: '影响梯度稳定性和收敛速度',
    tuningStrategy: 'batch_size × grad_accum × gpu_count',
  },
  {
    name: 'warmup_ratio',
    range: '0.01 ~ 0.1',
    default: '0.03',
    impact: '防止训练初期学习率过大',
    tuningStrategy: '数据量少时增大到 0.1',
  },
  {
    name: 'weight_decay',
    range: '0 ~ 0.1',
    default: '0.01',
    impact: '正则化，防止过拟合',
    tuningStrategy: '小数据集增大到 0.05',
  },
];
问题现象 可能原因 调整方向
Loss 震荡不降 学习率过高 降低 2-5x
Loss 下降后回升 过拟合 减少 epoch / 增大 weight_decay
Loss 下降极慢 学习率过低 增大 2-5x
验证集表现差 训练数据不够多样 增加数据多样性

当代架构的微调要点：MoE 与多模态

2025 年之后，开源旗舰大量转向 MoE（Mixture of Experts）与原生多模态架构——DeepSeek-V3（2024-12，671B 总参/37B 激活）、Qwen3-235B-A22B（2025-04）、Llama 4 Scout/Maverick（2025-04）都是 MoE；Qwen-VL 系列则是「视觉塔 + LLM」的代表。微调这些架构与稠密纯文本模型有明显差异，直接套用旧流程常导致效果劣化。

MoE 微调的三个特殊点：

  1. 路由器要保守对待。门控网络（router/gate）编码了预训练阶段的专家分工，随机梯度更新会破坏这种分工并引发专家塌缩（所有 token 涌向少数专家）。通行做法是冻结路由器，或对其使用比专家层低一个量级的学习率。
  2. 保留负载均衡辅助损失。训练目标中通常叠加均衡项：
Laux=α⋅N∑i=1Nfi⋅Pi\mathcal{L}_{\text{aux}} = \alpha \cdot N \sum_{i=1}^{N} f_i \cdot P_iLaux​=α⋅Ni=1∑N​fi​⋅Pi​

其中 NNN 是专家数，fif_ifi​ 是专家 iii 承接的 token 比例，PiP_iPi​ 是路由器分配给它的平均概率，α\alphaα 是均衡系数（常取 0.01）。微调时关闭该项是专家塌缩的常见诱因。

  1. 显存按总参算，算力按激活算。MoE 的显存占用取决于全部专家参数（671B 级模型必须多机 + 专家并行），而单步计算量只取决于激活参数（37B 级）。这意味着 MoE 全量微调是「显存贵、计算相对便宜」，与稠密模型恰好相反；LoRA 则通常只加在注意力等共享层上。

多模态微调的三段式分工（LLaVA 范式）：

组件 典型策略 理由
视觉编码器 冻结 保留预训练视觉表征
投影层 全量训练（常先行） 对齐视觉与语言空间
语言模型 LoRA 或小学习率全量 适配任务同时防语言退化

多模态微调的两大陷阱：一是语言能力退化——图文指令数据挤占纯文本配比后，模型在纯文本基准上明显下滑，需要在数据配比中保留足量纯文本样本；二是投影层与 LLM 的训练顺序——先训投影层、再联合微调的两阶段流程比一步到位更稳定。

训练监控与早停

训练过程中需要持续监控关键指标，及时发现问题并做出调整：

interface TrainingMetrics {
  step: number;
  epoch: number;
  trainLoss: number;
  evalLoss: number;
  learningRate: number;
  gradNorm: number;
}

const createEarlyStoppingCallback = (config: { patience: number; minDelta: number }) => {
  let bestLoss = Infinity;
  let waitCount = 0;

  return (metrics: TrainingMetrics): boolean => {
    if (metrics.evalLoss < bestLoss - config.minDelta) {
      bestLoss = metrics.evalLoss;
      waitCount = 0;
      return false;
    }

    waitCount++;
    if (waitCount >= config.patience) {
      console.log(`早停触发：验证损失 ${config.patience} 轮未改善`);
      return true;
    }
    return false;
  };
};

小结

  • 全量微调更新所有参数，效果上限最高但显存需求最大，适合大幅度领域迁移
  • 学习率 2e-5、3 个 epoch、cosine scheduler 是稳健的起点配置
  • 有效 batch size = 单卡 batch × 梯度累积 × GPU 数量，通常目标为 64-256
  • DeepSpeed ZeRO Stage 2 是多 GPU 训练的默认选择，Stage 3 用于超大模型
  • MoE 微调需冻结或保守对待路由器并保留负载均衡损失；多模态微调遵循「冻结视觉塔、训练投影层、LoRA 微调 LLM」的三段式分工
  • 持续监控 train/eval loss 曲线，结合早停机制防止过拟合
