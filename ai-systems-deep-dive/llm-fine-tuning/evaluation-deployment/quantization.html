模型量化与压缩

核心概念

模型量化是将模型参数从高精度数据类型（如 FP32/FP16）转换为低精度数据类型（如 INT8/INT4）的过程。量化后的模型显存占用更小、推理速度更快，使得在消费级硬件上部署大型 LLM 成为可能。量化是微调后部署的关键步骤，它在模型精度和推理效率之间寻找最优平衡点。

GPTQ 量化
GPTQ（Generative Pre-trained Transformer Quantization）是一种基于二阶信息的量化方法。它通过分析 Hessian 矩阵来确定最优的量化顺序和补偿策略，将精度损失降到最低：


from transformers import AutoModelForCausalLM, AutoTokenizer, GPTQConfig

model_name = "./fine-tuned-model"
tokenizer = AutoTokenizer.from_pretrained(model_name)

quantization_config = GPTQConfig(
    bits=4,
    group_size=128,
    desc_act=True,
    dataset="c4",
    tokenizer=tokenizer,
)

model = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=quantization_config,
    device_map="auto",
)

model.save_pretrained("./model-gptq-4bit")
tokenizer.save_pretrained("./model-gptq-4bit")
GPTQ 的关键参数是 group_size——它决定了多少个权重共享一个缩放因子。较小的 group_size（如 32-128）精度更高但量化后模型略大，较大的 group_size（如 1024）压缩更强但精度损失更大。


AWQ 量化
AWQ（Activation-aware Weight Quantization）基于一个关键观察：并非所有权重对模型输出的影响相同。AWQ 保留对激活值影响最大的权重通道（约 1%），对其使用更高精度，从而在相同的 bit 数下获得更好的质量：


from awq import AutoAWQForCausalLM

model = AutoAWQForCausalLM.from_pretrained("./fine-tuned-model")
tokenizer = AutoTokenizer.from_pretrained("./fine-tuned-model")

quant_config = {
    "zero_point": True,
    "q_group_size": 128,
    "w_bit": 4,
    "version": "GEMM",
}

model.quantize(tokenizer, quant_config=quant_config)
model.save_quantized("./model-awq-4bit")
tokenizer.save_pretrained("./model-awq-4bit")

GGUF 与 llama.cpp
GGUF 是 llama.cpp 生态使用的量化格式，支持在 CPU 上高效推理，也支持 GPU 加速。它使用多种量化策略的混合方案：


pip install llama-cpp-python

python -m llama_cpp.llama_cpp \
  --model ./fine-tuned-model \
  --outtype q4_k_m \
  --outfile ./model.gguf
interface GGUFQuantType {
  name: string;
  bitsPerWeight: number;
  quality: string;
  speed: string;
}

const ggufTypes: GGUFQuantType[] = [
  { name: 'Q2_K', bitsPerWeight: 2.6, quality: '最低', speed: '最快' },
  { name: 'Q3_K_M', bitsPerWeight: 3.1, quality: '低', speed: '很快' },
  { name: 'Q4_K_M', bitsPerWeight: 4.1, quality: '良好', speed: '快' },
  { name: 'Q5_K_M', bitsPerWeight: 5.1, quality: '很好', speed: '中' },
  { name: 'Q6_K', bitsPerWeight: 6.6, quality: '接近 FP16', speed: '较慢' },
  { name: 'Q8_0', bitsPerWeight: 8.5, quality: '极好', speed: '慢' },
];
Q4_K_M 是最常用的量化级别，它在精度和压缩比之间取得了最佳平衡。对于大多数应用场景，Q4_K_M 的输出质量与 FP16 几乎无法区分。


量化效果评估
量化后必须验证模型质量没有显著下降。评估应覆盖通用基准和目标任务：


interface QuantizationBenchmark {
  metric: string;
  fp16Score: number;
  int8Score: number;
  int4GptqScore: number;
  int4AwqScore: number;
}

const benchmarks: QuantizationBenchmark[] = [
  { metric: 'MMLU (5-shot)', fp16Score: 68.2, int8Score: 68.0, int4GptqScore: 67.1, int4AwqScore: 67.5 },
  { metric: 'HellaSwag', fp16Score: 82.5, int8Score: 82.3, int4GptqScore: 81.4, int4AwqScore: 81.8 },
  { metric: 'HumanEval', fp16Score: 45.0, int8Score: 44.5, int4GptqScore: 42.0, int4AwqScore: 43.5 },
  { metric: 'Perplexity (PPL)', fp16Score: 5.2, int8Score: 5.3, int4GptqScore: 5.6, int4AwqScore: 5.4 },
];
量化质量的可接受标准：MMLU 等基准下降不超过 2%，Perplexity 增加不超过 10%，目标任务的关键指标下降不超过 3%。


小结
    

  • 量化是微调后部署的关键步骤，在精度和效率之间寻找最优平衡
    • 

  • GPTQ 使用 Hessian 信息优化量化顺序，AWQ 保护对激活值影响大的权重通道
    • 

  • GGUF 格式支持 CPU 推理，Q4_K_M 是最通用的量化级别
    • 

  • AWQ 在 4-bit 量化中通常表现最好，是 GPU 推理的首选
    • 

  • 量化后必须验证模型质量，可接受的精度下降范围为基准分数的 2-3%
