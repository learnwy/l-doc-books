模型服务化部署

核心概念

微调完成后，模型需要通过推理服务对外提供能力。模型服务化涵盖推理引擎选择、API 设计、批处理优化和扩展策略。对于 LLM 来说，推理的核心瓶颈是自回归生成的顺序性——每个 Token 的生成都依赖前一个 Token，这使得传统的并行化策略效果有限。

vLLM 部署
vLLM 是当前最流行的 LLM 推理引擎，其核心创新是 PagedAttention——借鉴操作系统的虚拟内存管理，动态分配 KV Cache 内存，将 GPU 利用率从传统方案的 30-50% 提升到 90% 以上：


pip install vllm

python -m vllm.entrypoints.openai.api_server \
  --model ./fine-tuned-model \
  --served-model-name my-model \
  --host 0.0.0.0 \
  --port 8000 \
  --max-model-len 4096 \
  --gpu-memory-utilization 0.9 \
  --tensor-parallel-size 1 \
  --quantization awq \
  --dtype bfloat16
const callVLLM = async (prompt: string): Promise<string> => {
  const response = await fetch('http://localhost:8000/v1/chat/completions', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'my-model',
      messages: [{ role: 'user', content: prompt }],
      max_tokens: 1024,
      temperature: 0.7,
      stream: false,
    }),
  });

  const data = await response.json();
  return data.choices[0].message.content;
};

const streamVLLM = async function* (prompt: string) {
  const response = await fetch('http://localhost:8000/v1/chat/completions', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'my-model',
      messages: [{ role: 'user', content: prompt }],
      max_tokens: 1024,
      stream: true,
    }),
  });

  const reader = response.body!.getReader();
  const decoder = new TextDecoder();

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    const chunk = decoder.decode(value);
    const lines = chunk.split('\n').filter((l) => l.startsWith('data: '));
    for (const line of lines) {
      const data = line.replace('data: ', '');
      if (data === '[DONE]') return;
      const parsed = JSON.parse(data);
      const content = parsed.choices[0]?.delta?.content;
      if (content) yield content;
    }
  }
};
vLLM 的关键配置参数：gpu-memory-utilization 控制 GPU 显存使用比例（生产环境建议 0.85-0.9），tensor-parallel-size 设置张量并行的 GPU 数量，max-model-len 限制最大序列长度以控制 KV Cache 内存。


批处理与并发优化
Continuous Batching（连续批处理）是现代 LLM 推理的核心优化。它允许新请求在前一批请求的不同生成阶段加入处理，避免了传统静态批处理中短请求等待长请求的问题：


interface BatchConfig {
  maxBatchSize: number;
  maxWaitTimeMs: number;
  maxTokenBudget: number;
}

const defaultBatchConfig: BatchConfig = {
  maxBatchSize: 32,
  maxWaitTimeMs: 100,
  maxTokenBudget: 32768,
};

多模型与 LoRA 热切换
生产环境经常需要同时服务多个微调版本的模型。vLLM 支持同一基础模型上动态加载多个 LoRA 适配器：


python -m vllm.entrypoints.openai.api_server \
  --model meta-llama/Llama-3-8B \
  --enable-lora \
  --lora-modules \
    customer-service=./lora-adapters/customer-service \
    code-review=./lora-adapters/code-review \
    medical-qa=./lora-adapters/medical-qa \
  --max-lora-rank 32
const callWithAdapter = async (prompt: string, adapter: string) => {
  const response = await fetch('http://localhost:8000/v1/chat/completions', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: adapter,
      messages: [{ role: 'user', content: prompt }],
      max_tokens: 512,
    }),
  });
  return response.json();
};

const customerResponse = await callWithAdapter('如何退货？', 'customer-service');
const codeResponse = await callWithAdapter('审查这段代码', 'code-review');
LoRA 热切换的优势是多个适配器共享基础模型的 GPU 显存，每个适配器只需额外几十 MB 的内存。这使得单台服务器可以同时服务数十个微调版本。

小结
    

  • vLLM 的 PagedAttention 是当前最高效的推理引擎，GPU 利用率可达 90%+
    • 

  • 连续批处理是现代 LLM 推理的核心优化，避免了短请求等待长请求的问题
    • 

  • LoRA 热切换允许单台服务器同时服务数十个微调版本，共享基础模型显存
    • 

  • 推理 API 应兼容 OpenAI 格式，降低客户端集成成本
    • 

  • 生产部署需要完善的监控告警和自动扩缩容策略
