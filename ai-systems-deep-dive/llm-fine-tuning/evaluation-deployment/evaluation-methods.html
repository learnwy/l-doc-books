微调评估方法

核心概念

微调评估是验证模型是否达到预期目标的系统化方法。LLM 评估面临独特挑战：开放式生成的输出难以用传统的精确匹配指标衡量，同一问题可能有多个合理答案，且不同维度（准确性、流畅性、安全性）之间可能存在冲突。系统的评估策略需要结合自动化基准测试、LLM-as-Judge 和人工评估三种方法。

自动化基准测试
主流的 LLM 基准测试覆盖了知识、推理、代码和安全等多个维度。微调后应该在相关基准上验证模型没有出现能力退化：


import lm_eval

results = lm_eval.simple_evaluate(
    model="hf",
    model_args="pretrained=./fine-tuned-model,dtype=bfloat16",
    tasks=["mmlu", "hellaswag", "arc_challenge", "truthfulqa_mc2"],
    batch_size=4,
    num_fewshot=5,
)

for task, metrics in results["results"].items():
    acc = metrics.get("acc,none", metrics.get("acc_norm,none", 0))
    print(f"{task}: {acc:.4f}")

LLM-as-Judge 评估
使用强大的 LLM（如 GPT-4）作为评判者，对模型输出进行多维度评分。这种方法在成本和质量之间取得了很好的平衡：


interface JudgeConfig {
  model: string;
  criteria: Array<{
    name: string;
    description: string;
    weight: number;
  }>;
  scaleMin: number;
  scaleMax: number;
}

const createLLMJudge = (config: JudgeConfig) => {
  const buildEvalPrompt = (question: string, answer: string) => {
    const criteriaText = config.criteria.map((c) => `- ${c.name}（权重 ${c.weight}）: ${c.description}`).join('\n');

    return `你是一位专业的 AI 输出质量评审员。请根据以下标准评估回答质量。

评估标准：
${criteriaText}

问题：${question}

回答：${answer}

请以 JSON 格式输出每个维度的评分（${config.scaleMin}-${config.scaleMax} 分）和总体评分。
格式：{"scores": {"维度名": 分数, ...}, "overall": 总分, "reasoning": "评分理由"}`;
  };

  return { buildEvalPrompt };
};

const judge = createLLMJudge({
  model: 'gpt-4-turbo',
  criteria: [
    { name: '准确性', description: '信息是否事实正确', weight: 0.3 },
    { name: '完整性', description: '是否充分回答了问题', weight: 0.25 },
    { name: '清晰度', description: '表达是否清晰易懂', weight: 0.2 },
    { name: '安全性', description: '是否避免有害内容', weight: 0.15 },
    { name: '格式', description: '是否遵循输出格式要求', weight: 0.1 },
  ],
  scaleMin: 1,
  scaleMax: 5,
});
LLM-as-Judge 的主要偏见包括位置偏见（偏好第一个回答）、冗长偏见（偏好较长的回答）和自我偏好（GPT-4 偏好 GPT-4 风格）。缓解策略包括随机交换回答顺序、多次评估取平均、使用不同模型交叉评估。


A/B 测试与对比评估
对比评估让评估者直接比较两个模型的输出，是最可靠的评估方式：


interface ABTestResult {
  prompt: string;
  modelA: string;
  modelB: string;
  winner: 'A' | 'B' | 'tie';
  confidence: number;
  dimension: string;
}

const calculateWinRate = (
  results: ABTestResult[],
): {
  winRateA: number;
  winRateB: number;
  tieRate: number;
  byDimension: Record<string, { A: number; B: number; tie: number }>;
} => {
  const total = results.length;
  const winsA = results.filter((r) => r.winner === 'A').length;
  const winsB = results.filter((r) => r.winner === 'B').length;
  const ties = results.filter((r) => r.winner === 'tie').length;

  const byDimension: Record<string, { A: number; B: number; tie: number }> = {};
  for (const r of results) {
    if (!byDimension[r.dimension]) {
      byDimension[r.dimension] = { A: 0, B: 0, tie: 0 };
    }
    byDimension[r.dimension][r.winner === 'tie' ? 'tie' : r.winner]++;
  }

  return {
    winRateA: winsA / total,
    winRateB: winsB / total,
    tieRate: ties / total,
    byDimension,
  };
};

小结
    

  • 微调评估应结合自动化基准、LLM-as-Judge 和人工评估三种方法
    • 

  • 自动化基准检测能力退化（MMLU、HumanEval 等），每次训练后必须运行
    • 

  • LLM-as-Judge 在成本和质量间取得平衡，需注意位置偏见和冗长偏见
    • 

  • A/B 对比测试是最可靠的评估方式，适合上线前的关键决策
    • 

  • 退化检测确保微调不会损害模型的基础能力，安全评估确保不引入新风险
