Prefix Tuning 前缀微调

核心概念

Prefix Tuning 是一种参数高效微调方法，通过在 Transformer 每一层的注意力机制前添加可学习的"虚拟前缀"向量来引导模型行为。这些前缀不对应任何真实的文本 Token，而是作为连续的软提示直接在注意力空间中工作。与全量微调冻结所有原始参数不同，Prefix Tuning 仅训练这些额外注入的前缀参数，可训练参数量通常不到模型总参数的 0.1%。

前缀的工作机制
Prefix Tuning 的核心思想是在每一层的 Key 和 Value 矩阵前面拼接可学习的向量。假设原始注意力计算为 Attention(Q, K, V)，添加前缀后变为 Attention(Q, [P_K; K], [P_V; V])，其中 P_K 和 P_V 是该层对应的前缀向量。


这种设计意味着每个注意力头在计算时，查询（Query）不仅会关注输入的真实 Token，还会关注前缀向量。前缀向量因此能够"引导"注意力的分配模式，间接影响模型的输出行为。


from peft import PrefixTuningConfig, get_peft_model, TaskType
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B",
    torch_dtype="auto",
    device_map="auto",
)

prefix_config = PrefixTuningConfig(
    task_type=TaskType.CAUSAL_LM,
    num_virtual_tokens=20,
    prefix_projection=True,
    encoder_hidden_size=256,
    token_dim=model.config.hidden_size,
    num_layers=model.config.num_hidden_layers,
    num_attention_heads=model.config.num_attention_heads,
)

prefix_model = get_peft_model(model, prefix_config)
prefix_model.print_trainable_parameters()
直接优化高维前缀向量往往不稳定，因此 Prefix Tuning 引入了一个重参数化技巧：使用一个较小的 MLP（前缀投影网络）来生成实际的前缀向量。训练时优化 MLP 的参数，训练结束后将 MLP 的输出固化为最终的前缀向量，推理时不再需要 MLP。


prefix_config_with_projection = PrefixTuningConfig(
    task_type=TaskType.CAUSAL_LM,
    num_virtual_tokens=30,
    prefix_projection=True,
    encoder_hidden_size=512,
)

prefix_config_without_projection = PrefixTuningConfig(
    task_type=TaskType.CAUSAL_LM,
    num_virtual_tokens=30,
    prefix_projection=False,
)

Prompt Tuning 对比
Prompt Tuning 是 Prefix Tuning 的简化版本，它只在输入嵌入层添加软提示向量，而不是在每一层都添加前缀。这意味着 Prompt Tuning 的可训练参数量更少，但表达能力也相对有限。


from peft import PromptTuningConfig, PromptTuningInit, get_peft_model

prompt_config = PromptTuningConfig(
    task_type=TaskType.CAUSAL_LM,
    num_virtual_tokens=8,
    prompt_tuning_init=PromptTuningInit.TEXT,
    prompt_tuning_init_text="将以下文本分类为正面或负面：",
    tokenizer_name_or_path="meta-llama/Llama-3-8B",
)

prompt_model = get_peft_model(model, prompt_config)
prompt_model.print_trainable_parameters()
Prompt Tuning 有一个重要发现：随着模型规模增大，软提示的效果逐渐接近全量微调。在 10B+ 参数的模型上，仅 8-20 个虚拟 Token 就能达到不错的适配效果。这意味着对于足够大的模型，Prompt Tuning 可能是最具性价比的方法。


P-Tuning v2 是 Prefix Tuning 在中文社区的改进版本，它将前缀扩展到每一层（类似 Prefix Tuning），但使用了不同的初始化策略和训练技巧：


from peft import PrefixTuningConfig, get_peft_model

p_tuning_v2_config = PrefixTuningConfig(
    task_type=TaskType.CAUSAL_LM,
    num_virtual_tokens=20,
    prefix_projection=True,
    encoder_hidden_size=128,
)

p_tuning_model = get_peft_model(model, p_tuning_v2_config)
多任务场景应用
Prefix Tuning 在多任务和多租户场景中有天然优势。每个任务只需存储一组前缀向量（通常仅几 MB），切换任务时只需替换前缀，无需重新加载模型。


interface PrefixTaskConfig {
  taskName: string;
  prefixLength: number;
  prefixStorageSize: string;
  switchLatency: string;
}

const multiTaskSetup: PrefixTaskConfig[] = [
  {
    taskName: '中文摘要',
    prefixLength: 20,
    prefixStorageSize: '2.4 MB',
    switchLatency: '<1 ms',
  },
  {
    taskName: '英文翻译',
    prefixLength: 30,
    prefixStorageSize: '3.6 MB',
    switchLatency: '<1 ms',
  },
  {
    taskName: '代码生成',
    prefixLength: 40,
    prefixStorageSize: '4.8 MB',
    switchLatency: '<1 ms',
  },
  {
    taskName: '情感分析',
    prefixLength: 10,
    prefixStorageSize: '1.2 MB',
    switchLatency: '<1 ms',
  },
];
在实际部署中，可以将多组前缀预加载到 GPU 显存中，通过索引快速切换。这种模式特别适合 API 服务需要同时支持多个定制化任务的场景，避免了为每个任务维护独立模型副本的开销。

训练实践要点
Prefix Tuning 的训练比全量微调简单得多，但仍有一些关键参数需要调优。前缀长度（num_virtual_tokens）是最重要的超参数，它直接影响模型的适配能力和推理时的上下文占用：


from transformers import TrainingArguments, Trainer

training_args = TrainingArguments(
    output_dir="./prefix-tuning-output",
    num_train_epochs=5,
    per_device_train_batch_size=8,
    learning_rate=3e-2,
    warmup_ratio=0.06,
    weight_decay=0.01,
    logging_steps=10,
    save_strategy="epoch",
    fp16=True,
)

trainer = Trainer(
    model=prefix_model,
    args=training_args,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
)

trainer.train()
学习率的选择也至关重要。由于前缀参数是从零开始学习的（不像 LoRA 有预训练权重的信息），通常需要比 LoRA 更高的学习率（1e-2 到 5e-2），并配合适当的 warmup。

小结
    

  • Prefix Tuning 通过在每层注入可学习前缀向量实现参数高效微调，可训练参数不到 0.1%
    • 

  • 前缀投影（重参数化）技巧显著提升训练稳定性，是默认推荐配置
    • 

  • Prompt Tuning 是其简化版本，在大模型上效果接近全量微调
    • 

  • 多任务场景是 Prefix Tuning 的核心优势，前缀切换延迟极低
    • 

  • 训练时需要比 LoRA 更高的学习率，并注意 warmup 配置
    • 

  • 前缀长度是最关键的超参数，需根据任务复杂度在 10-50 之间调整
    •
