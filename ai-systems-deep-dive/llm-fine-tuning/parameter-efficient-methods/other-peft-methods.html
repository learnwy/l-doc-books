其他参数高效方法

核心概念

参数高效微调（Parameter-Efficient Fine-Tuning, PEFT）不仅限于 LoRA。研究社区提出了多种方法，从不同角度解决"如何用最少的参数更新获得最大的适配效果"。这些方法在可训练参数量、实现复杂度、适配能力和推理开销之间做出不同的权衡。

Adapter Tuning
Adapter Tuning 在 Transformer 的每一层中插入小型的瓶颈网络（bottleneck module）。这些适配器由下投影、非线性激活和上投影组成，通过残差连接与原始层融合：


from transformers import AutoModelForCausalLM
from peft import get_peft_model, AdaLoraConfig, TaskType

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B",
    torch_dtype="auto",
    device_map="auto",
)

adalora_config = AdaLoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    init_r=12,
    target_r=8,
    beta1=0.85,
    beta2=0.85,
    tinit=200,
    tfinal=1000,
    deltaT=10,
)

model = get_peft_model(model, adalora_config)
Adapter 的核心设计是瓶颈结构——先将维度从 d 降到 r（通常 r=64-256），经过非线性后再升回 d 维。残差连接确保了当适配器输出接近零时，模型行为退化为原始预训练模型。这种设计比 LoRA 的参数量大但灵活性更强。


Prefix Tuning 与 Prompt Tuning
Prefix Tuning 在每一层的 Key-Value 对前面添加可学习的"虚拟前缀"。这些前缀不对应任何实际的文本 Token，而是直接在注意力空间中引导模型行为：


from peft import PrefixTuningConfig, PromptTuningConfig, PromptTuningInit, get_peft_model

prefix_config = PrefixTuningConfig(
    task_type="CAUSAL_LM",
    num_virtual_tokens=20,
    prefix_projection=True,
    encoder_hidden_size=256,
)

prompt_config = PromptTuningConfig(
    task_type="CAUSAL_LM",
    num_virtual_tokens=8,
    prompt_tuning_init=PromptTuningInit.TEXT,
    prompt_tuning_init_text="将以下文本分类为正面或负面情感：",
    tokenizer_name_or_path="meta-llama/Llama-3-8B",
)

prefix_model = get_peft_model(model, prefix_config)
prefix_model.print_trainable_parameters()

prompt_model = get_peft_model(model, prompt_config)
prompt_model.print_trainable_parameters()

Prompt Tuning 的有趣之处在于，随着模型规模增大，软提示（soft prompt）的效果逐渐接近全量微调。在 10B+ 参数的模型上，仅 8 个虚拟 Token 就能达到不错的适配效果。


IA3 与 BitFit
IA3（Infused Adapter by Inhibiting and Amplifying Inner Activations）是参数量最少的 PEFT 方法之一，它只学习三组缩放向量来调节 Key、Value 和 FFN 的激活值：


from peft import IA3Config, get_peft_model

ia3_config = IA3Config(
    task_type="CAUSAL_LM",
    target_modules=["k_proj", "v_proj", "down_proj"],
    feedforward_modules=["down_proj"],
)

ia3_model = get_peft_model(model, ia3_config)
ia3_model.print_trainable_parameters()
BitFit 更为极端——它只微调模型中的偏置项（bias terms），可训练参数仅占总参数的 0.04%。尽管如此简单，BitFit 在某些分类任务上仍能达到全量微调 80-90% 的效果。

方法选择指南
不同场景下的最佳 PEFT 方法选择：


interface PEFTRecommendation {
  scenario: string;
  primaryMethod: string;
  alternativeMethod: string;
  reasoning: string;
}

const recommendations: PEFTRecommendation[] = [
  {
    scenario: '通用领域适配（充足显存）',
    primaryMethod: 'LoRA (r=32)',
    alternativeMethod: 'Adapter Tuning',
    reasoning: 'LoRA 效果好、合并后无推理开销',
  },
  {
    scenario: '显存极度受限',
    primaryMethod: 'QLoRA (r=16)',
    alternativeMethod: 'IA3',
    reasoning: 'QLoRA 降低硬件门槛，IA3 参数更少',
  },
  {
    scenario: '多任务/多租户',
    primaryMethod: 'LoRA + 适配器切换',
    alternativeMethod: 'Prefix Tuning',
    reasoning: '每个任务独立的小适配器，切换成本低',
  },
  {
    scenario: '快速原型验证',
    primaryMethod: 'Prompt Tuning',
    alternativeMethod: 'IA3',
    reasoning: '训练最快，参数最少，适合验证思路',
  },
];
小结
    

  • PEFT 方法家族包含适配器、提示和低秩三大类，各有不同的参数-效果权衡
    • 

  • Adapter Tuning 通过瓶颈网络注入适配层，参数量 1-5%，灵活但增加推理延迟
    • 

  • Prefix Tuning 在每层添加虚拟前缀，Prompt Tuning 仅在输入层添加，后者在大模型上效果显著
    • 

  • IA3 和 BitFit 是参数量最少的方法，适合快速原型验证和极端资源受限场景
    • 

  • 实践中 LoRA/QLoRA 是最通用的选择，其他方法适合特定约束下的替代方案
    •
