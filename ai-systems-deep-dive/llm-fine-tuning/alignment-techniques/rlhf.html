RLHF 与人类偏好对齐

核心概念

RLHF（Reinforcement Learning from Human Feedback）是将语言模型与人类偏好对齐的标准方法论。它在监督微调（SFT）的基础上，通过人类标注的偏好数据训练奖励模型（Reward Model），再利用强化学习算法（如 PPO）优化语言模型的生成策略，使模型输出更符合人类的期望。

奖励模型训练
奖励模型（Reward Model）是 RLHF 的核心组件。它接收一个提示和回答作为输入，输出一个标量分数来衡量回答的质量。训练数据通常是人类对同一提示的多个回答进行排序：


from transformers import AutoModelForSequenceClassification, AutoTokenizer, TrainingArguments
from trl import RewardTrainer

reward_model = AutoModelForSequenceClassification.from_pretrained(
    "meta-llama/Llama-3-8B",
    num_labels=1,
    torch_dtype="auto",
)

tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3-8B")
tokenizer.pad_token = tokenizer.eos_token

def preprocess_reward_data(example):
    chosen = tokenizer(
        example["prompt"] + example["chosen"],
        truncation=True,
        max_length=2048,
        padding="max_length",
    )
    rejected = tokenizer(
        example["prompt"] + example["rejected"],
        truncation=True,
        max_length=2048,
        padding="max_length",
    )
    return {
        "input_ids_chosen": chosen["input_ids"],
        "attention_mask_chosen": chosen["attention_mask"],
        "input_ids_rejected": rejected["input_ids"],
        "attention_mask_rejected": rejected["attention_mask"],
    }

training_args = TrainingArguments(
    output_dir="./reward-model",
    num_train_epochs=1,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=1.5e-5,
    bf16=True,
    evaluation_strategy="steps",
    eval_steps=200,
    save_strategy="steps",
    save_steps=500,
    logging_steps=10,
)

trainer = RewardTrainer(
    model=reward_model,
    args=training_args,
    tokenizer=tokenizer,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
)

trainer.train()
奖励模型的质量直接决定了 RLHF 的效果上限。人类标注的一致性是关键挑战——不同标注者可能对同一回答有截然不同的评价。通常需要多位标注者的一致性检验（Cohen's Kappa > 0.7）。


PPO 优化过程
PPO（Proximal Policy Optimization）是 RLHF 中最常用的强化学习算法。它通过限制策略更新的幅度来保持训练稳定性：


from trl import PPOTrainer, PPOConfig, AutoModelForCausalLMWithValueHead

ppo_config = PPOConfig(
    learning_rate=1.41e-5,
    batch_size=256,
    mini_batch_size=64,
    ppo_epochs=4,
    gradient_accumulation_steps=1,
    early_stopping=True,
    target_kl=6.0,
    kl_penalty="kl",
    init_kl_coef=0.2,
    adap_kl_ctrl=True,
    cliprange=0.2,
    cliprange_value=0.2,
)

model = AutoModelForCausalLMWithValueHead.from_pretrained("./sft-model")
ref_model = AutoModelForCausalLMWithValueHead.from_pretrained("./sft-model")

ppo_trainer = PPOTrainer(
    config=ppo_config,
    model=model,
    ref_model=ref_model,
    tokenizer=tokenizer,
)

for batch in dataloader:
    query_tensors = batch["input_ids"]
    response_tensors = ppo_trainer.generate(query_tensors, max_new_tokens=256)
    rewards = compute_rewards(query_tensors, response_tensors, reward_model)
    stats = ppo_trainer.step(query_tensors, response_tensors, rewards)
PPO 训练的关键约束是 KL 散度惩罚——它防止策略模型偏离参考模型太远，避免模型为了获取高奖励而产生不自然的输出（reward hacking）。

RLHF 的挑战与替代方案

DPO（Direct Preference Optimization）作为最主要的替代方案，直接从偏好数据优化策略，跳过奖励模型训练阶段，大幅简化了训练流程。


小结
    

  • RLHF 通过 SFT → 奖励模型 → PPO 三阶段实现人类偏好对齐
    • 

  • 奖励模型质量决定 RLHF 上限，标注一致性（Kappa > 0.7）是关键
    • 

  • PPO 的 KL 散度惩罚防止 reward hacking，但训练稳定性仍是主要挑战
    • 

  • 偏好数据构建可结合专家标注和 AI 辅助标注降低成本
    • 

  • DPO 等替代方案跳过奖励模型训练，大幅简化流程且效果接近
    •
