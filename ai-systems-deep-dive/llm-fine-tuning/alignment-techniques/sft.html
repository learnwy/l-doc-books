SFT 监督微调

核心概念

SFT（Supervised Fine-Tuning）是 LLM 对齐流程中的第一个关键步骤。它使用指令-回答对（instruction-response pairs）对预训练模型进行监督学习，使模型学会遵循指令、理解对话格式和产出有用回答。SFT 是后续 RLHF 或 DPO 对齐的基础——没有良好的 SFT 基线，对齐训练往往事倍功半。

对话数据构建
SFT 的数据质量至关重要。高质量的指令数据应覆盖多种任务类型、难度级别和对话风格：


interface SFTSample {
  messages: Array<{
    role: 'system' | 'user' | 'assistant';
    content: string;
  }>;
}

interface DataMix {
  category: string;
  proportion: number;
  examples: number;
  quality: string;
}

const recommendedDataMix: DataMix[] = [
  { category: '通用对话', proportion: 0.2, examples: 2000, quality: '高质量多轮' },
  { category: '知识问答', proportion: 0.15, examples: 1500, quality: '准确、有来源' },
  { category: '代码生成', proportion: 0.15, examples: 1500, quality: '可运行、有测试' },
  { category: '创意写作', proportion: 0.1, examples: 1000, quality: '风格多样' },
  { category: '逻辑推理', proportion: 0.1, examples: 1000, quality: '步骤清晰' },
  { category: '指令遵循', proportion: 0.1, examples: 1000, quality: '格式严格' },
  { category: '拒绝回答', proportion: 0.1, examples: 1000, quality: '礼貌且解释原因' },
  { category: '多轮对话', proportion: 0.1, examples: 1000, quality: '上下文连贯' },
];
数据配比的原则是"想让模型擅长什么就多给什么"。如果目标是代码助手，代码数据的比例应提高到 30-40%；如果是客服场景，对话和拒绝数据应占主导。


训练策略与实践
SFT 训练的关键技术包括：只对 assistant 回答部分计算损失（避免学习用户的提问方式）、使用 Chat Template 标准化对话格式、以及 Packing 技术提高 GPU 利用率：


from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from trl import SFTTrainer, DataCollatorForCompletionOnlyLM
from datasets import load_dataset

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B",
    torch_dtype="auto",
    device_map="auto",
)
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3-8B")
tokenizer.pad_token = tokenizer.eos_token

dataset = load_dataset("json", data_files="sft_data.jsonl", split="train")

def format_chat(example):
    return {
        "text": tokenizer.apply_chat_template(
            example["messages"],
            tokenize=False,
            add_generation_prompt=False,
        )
    }

dataset = dataset.map(format_chat)

response_template = "<|start_header_id|>assistant<|end_header_id|>"
collator = DataCollatorForCompletionOnlyLM(
    response_template=response_template,
    tokenizer=tokenizer,
)

training_args = TrainingArguments(
    output_dir="./sft-output",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-5,
    warmup_ratio=0.05,
    lr_scheduler_type="cosine",
    bf16=True,
    gradient_checkpointing=True,
    logging_steps=10,
    save_strategy="epoch",
    evaluation_strategy="epoch",
)

trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    data_collator=collator,
    tokenizer=tokenizer,
    max_seq_length=2048,
    dataset_text_field="text",
    packing=True,
)

trainer.train()
DataCollatorForCompletionOnlyLM 确保损失只在 assistant 的回答部分计算，这是 SFT 训练的关键设计。Packing（packing=True）将多个短样本拼接到同一个序列中，避免 padding 浪费 GPU 算力。


多轮对话处理
多轮对话是 SFT 的常见场景，需要正确处理对话历史和上下文窗口管理：


interface MultiTurnStrategy {
  name: string;
  description: string;
  prosAndCons: { pro: string; con: string };
}

const strategies: MultiTurnStrategy[] = [
  {
    name: '完整对话训练',
    description: '将整个多轮对话作为一个训练样本',
    prosAndCons: { pro: '保持对话连贯性', con: '长对话可能超出上下文窗口' },
  },
  {
    name: '滑动窗口',
    description: '取最近 K 轮对话作为上下文',
    prosAndCons: { pro: '控制序列长度', con: '可能丢失早期上下文' },
  },
  {
    name: '逐轮展开',
    description: '每轮回答作为独立样本，前文作为上下文',
    prosAndCons: { pro: '数据量最大化', con: '训练数据冗余' },
  },
];

小结
    

  • SFT 是对齐流程的基础步骤，将预训练模型转化为能遵循指令的对话模型
    • 

  • 数据配比应根据目标场景调整，核心原则是"想擅长什么就多给什么"
    • 

  • 只对 assistant 部分计算损失、Packing 和 Chat Template 是 SFT 训练的三个关键技术
    • 

  • 多轮对话推荐完整对话训练策略，长对话场景使用滑动窗口
    • 

  • SFT 质量评估需要覆盖指令遵循、知识准确、对话质量和安全性多个维度
