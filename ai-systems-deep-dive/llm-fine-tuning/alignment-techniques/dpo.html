DPO 直接偏好优化

核心概念

DPO（Direct Preference Optimization）是一种无需训练奖励模型的对齐方法。它将 RLHF 的强化学习问题转化为一个简单的分类损失函数，直接从偏好数据对优化语言模型。DPO 的核心洞察是：Bradley-Terry 偏好模型隐含了一个最优策略的闭式解，因此可以跳过奖励模型训练和 PPO 优化，用一个二元交叉熵损失直接对齐模型。

DPO 训练实现
使用 TRL 库实现 DPO 训练非常简洁，关键是准备好 chosen/rejected 偏好数据对：


from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from trl import DPOTrainer, DPOConfig
from datasets import load_dataset
from peft import LoraConfig
import torch

model_name = "meta-llama/Llama-3-8B-Instruct"
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.bfloat16,
    device_map="auto",
)
tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.pad_token = tokenizer.eos_token

ref_model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.bfloat16,
    device_map="auto",
)

dataset = load_dataset("json", data_files="preference_data.jsonl", split="train")

lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    bias="none",
    task_type="CAUSAL_LM",
)

dpo_config = DPOConfig(
    output_dir="./dpo-output",
    num_train_epochs=1,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,
    learning_rate=5e-7,
    beta=0.1,
    loss_type="sigmoid",
    warmup_ratio=0.1,
    bf16=True,
    gradient_checkpointing=True,
    logging_steps=10,
    save_strategy="epoch",
    max_length=2048,
    max_prompt_length=1024,
)

trainer = DPOTrainer(
    model=model,
    ref_model=ref_model,
    args=dpo_config,
    train_dataset=dataset,
    tokenizer=tokenizer,
    peft_config=lora_config,
)

trainer.train()
trainer.save_model("./dpo-adapter")
DPO 的关键超参数 β 控制了偏好对齐的强度——β 越小对齐越强但模型多样性下降，β 越大保持更多原始能力但对齐效果减弱。通常从 0.1 开始，根据效果在 0.01-0.5 之间调整。


偏好数据格式
DPO 的训练数据格式要求每条样本包含 prompt、chosen 和 rejected 三个字段：


interface DPOSample {
  prompt: string;
  chosen: string;
  rejected: string;
}

const createDPODataset = (
  rawData: Array<{
    prompt: string;
    responses: Array<{ text: string; score: number }>;
  }>,
): DPOSample[] => {
  const samples: DPOSample[] = [];

  for (const item of rawData) {
    const sorted = [...item.responses].sort((a, b) => b.score - a.score);

    for (let i = 0; i < sorted.length - 1; i++) {
      for (let j = i + 1; j < sorted.length; j++) {
        if (sorted[i].score - sorted[j].score > 0.5) {
          samples.push({
            prompt: item.prompt,
            chosen: sorted[i].text,
            rejected: sorted[j].text,
          });
        }
      }
    }
  }

  return samples;
};
偏好数据的质量要求：chosen 和 rejected 之间的质量差异应该足够明显（避免模糊的偏好对），同时 rejected 不应该是完全错误的回答（否则模型学不到细微的偏好信号）。


DPO 变体
DPO 的成功催生了多种改进变体，每种都尝试解决原始 DPO 的某些局限：


interface DPOVariant {
  name: string;
  improvement: string;
  dataRequirement: string;
  complexity: string;
}

const variants: DPOVariant[] = [
  {
    name: 'IPO (Identity Preference Optimization)',
    improvement: '解决 DPO 在确定性偏好下的过拟合问题',
    dataRequirement: '偏好对',
    complexity: '与 DPO 相同',
  },
  {
    name: 'SimPO (Simple Preference Optimization)',
    improvement: '无需参考模型，用序列平均 log-prob 替代',
    dataRequirement: '偏好对',
    complexity: '更简单',
  },
  {
    name: 'KTO (Kahneman-Tversky Optimization)',

    dataRequirement: '单条 + 正/负标签',
    complexity: '最简单',
  },
  {
    name: 'ORPO (Odds Ratio Preference Optimization)',
    improvement: '无需参考模型和单独 SFT 阶段',
    dataRequirement: '偏好对',
    complexity: '更简单',
  },

对齐效果评估
评估对齐效果需要多个维度的指标，不能仅依赖单一分数：


interface AlignmentEvalMetrics {
  helpfulness: number;
  harmlessness: number;
  honesty: number;
  followInstructions: number;
  winRate: number;
}

const evaluateAlignment = async (
  model: { generate: (prompt: string) => Promise<string> },
  testCases: Array<{ prompt: string; criteria: string[] }>,
  judgeModel: { invoke: (messages: Array<{ role: string; content: string }>) => Promise<{ content: string }> },
): Promise<AlignmentEvalMetrics> => {
  const scores = { helpfulness: 0, harmlessness: 0, honesty: 0, followInstructions: 0, winRate: 0 };
  let count = 0;

  for (const tc of testCases) {
    const response = await model.generate(tc.prompt);
    const evalResult = await judgeModel.invoke([
      {
        role: 'user',
        content: `评估以下回答的质量（1-5 分）：
          问题：${tc.prompt}
          回答：${response}
          评估维度：有用性、无害性、诚实性、指令遵循度
          以 JSON 格式输出四个维度的分数。`,
      },
    ]);
    const parsed = JSON.parse(evalResult.content as string);
    scores.helpfulness += parsed.helpfulness ?? 0;
    scores.harmlessness += parsed.harmlessness ?? 0;
    scores.honesty += parsed.honesty ?? 0;
    scores.followInstructions += parsed.followInstructions ?? 0;
    count++;
  }

  return {
    helpfulness: scores.helpfulness / count,
    harmlessness: scores.harmlessness / count,
    honesty: scores.honesty / count,
    followInstructions: scores.followInstructions / count,
    winRate: 0,
  };
};
小结
    

  • DPO 将 RLHF 的强化学习问题简化为分类损失优化，无需训练奖励模型
    • 

  • β 参数控制对齐强度，通常从 0.1 开始，在 0.01-0.5 间调整
    • 

  • 偏好数据的质量要求 chosen 和 rejected 差异明显且 rejected 不能过于离谱
    • 

  • SimPO 和 ORPO 进一步简化了流程（无需参考模型），KTO 降低了数据要求（无需偏好对）
    • 

  • 对齐效果应从有用性、无害性、诚实性和指令遵循度多维度评估
    •
