模型序列化

什么是模型序列化

模型序列化（Model Serialization）是将训练好的模型保存为文件，以便后续加载用于推理或继续训练。这是将模型从实验环境部署到生产环境的第一步。

flowchart LR
    A["训练完成的模型<br/>(内存中)"] --> B["序列化<br/>保存到磁盘"]
    B --> C["模型文件"]
    C --> D["反序列化<br/>从磁盘加载"]
    D --> E["推理 / 继续训练"]

核心概念

模型序列化围绕三个概念展开：

  • 序列化边界：把内存中的模型变成磁盘上的字节。关键在于"保存了什么"——权重（state_dict）与模型结构分离，前者稳定、后者与代码和库版本强绑定。
  • 可移植性（Portability）：模型文件能否脱离原训练环境加载。这是 pickle 与 ONNX 的分水岭：前者依赖 Python 与库版本，后者是跨框架的中间表示。
  • 安全边界：反序列化本质上是在执行文件里的代码。pickle 可以执行任意代码，因此"不加载来路不明的模型文件"不是建议而是硬约束。

三者的取舍回答了部署选型：本地复用选 pickle/joblib，跨环境部署选 ONNX，脱离 Python 运行选 TorchScript。而"总是保存权重而非完整模型"这条建议，正是第一点的直接推论。

Python Pickle

Pickle 是 Python 原生的序列化方式，scikit-learn 模型最常使用 pickle 或 joblib 保存。

import pickle
import joblib
from sklearn.ensemble import RandomForestClassifier
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split

iris = load_iris()
X_train, X_test, y_train, y_test = train_test_split(
    iris.data, iris.target, test_size=0.3, random_state=42
)

model = RandomForestClassifier(n_estimators=100, random_state=42)
model.fit(X_train, y_train)

with open('/tmp/model_pickle.pkl', 'wb') as f:
    pickle.dump(model, f)

joblib.dump(model, '/tmp/model_joblib.pkl')

model_loaded = joblib.load('/tmp/model_joblib.pkl')
print(f"原始模型准确率:   {model.score(X_test, y_test):.4f}")
print(f"加载模型准确率:   {model_loaded.score(X_test, y_test):.4f}")

import os
pickle_size = os.path.getsize('/tmp/model_pickle.pkl')
joblib_size = os.path.getsize('/tmp/model_joblib.pkl')
print(f"\nPickle 文件大小: {pickle_size / 1024:.1f} KB")
print(f"Joblib 文件大小: {joblib_size / 1024:.1f} KB")
方法 优点 缺点
pickle Python 内置 安全风险、版本依赖
joblib 大 NumPy 数组更高效 同样有安全风险

提示： 永远不要加载不信任来源的 pickle 文件。Pickle 可以执行任意代码，存在严重的安全风险。

PyTorch 模型保存

PyTorch 提供两种保存模型的方式：保存完整模型和只保存权重（推荐）。

import torch
import torch.nn as nn

class SimpleNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(10, 50)
        self.relu = nn.ReLU()
        self.fc2 = nn.Linear(50, 3)

    def forward(self, x):
        return self.fc2(self.relu(self.fc1(x)))

model = SimpleNet()

torch.save(model.state_dict(), '/tmp/model_weights.pth')

model_loaded = SimpleNet()
model_loaded.load_state_dict(torch.load('/tmp/model_weights.pth'))
model_loaded.eval()

x = torch.randn(1, 10)
with torch.no_grad():
    out_original = model(x)
    out_loaded = model_loaded(x)
print(f"输出一致: {torch.allclose(out_original, out_loaded)}")

checkpoint = {
    'epoch': 50,
    'model_state_dict': model.state_dict(),
    'optimizer_state_dict': torch.optim.Adam(model.parameters()).state_dict(),
    'loss': 0.05,
}
torch.save(checkpoint, '/tmp/checkpoint.pth')
print(f"Checkpoint 已保存")
保存方式 内容 推荐场景
state_dict 只保存权重 部署、迁移学习
完整模型 模型结构 + 权重 快速原型
Checkpoint 权重 + 优化器 + epoch 断点续训

ONNX 格式

ONNX（Open Neural Network Exchange）是跨框架的模型交换标准。训练在 PyTorch 中完成，推理可以用 ONNX Runtime、TensorRT 等高效引擎。

import torch
import torch.nn as nn

class SimpleNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(10, 50)
        self.relu = nn.ReLU()
        self.fc2 = nn.Linear(50, 3)

    def forward(self, x):
        return self.fc2(self.relu(self.fc1(x)))

model = SimpleNet()
model.eval()

dummy_input = torch.randn(1, 10)

torch.onnx.export(
    model, dummy_input,
    '/tmp/model.onnx',
    input_names=['input'],
    output_names=['output'],
    dynamic_axes={'input': {0: 'batch'}, 'output': {0: 'batch'}},
    opset_version=18,
)
print("ONNX 模型已导出")

版本注意： dynamic_axes 属于基于 TorchScript 的遗留导出路径。PyTorch 2.x 起官方推荐 dynamo=True（现已默认开启）的新导出路径，它基于 torch.export，动态维度改用 dynamic_shapes 参数描述；旧参数仍可用但不再演进（见 torch.onnx 官方文档）。ONNX 算子集本身也在持续演进：opset 13 发布于 2021 年，而截至 2026 年 ONNX 1.23 文档对应的默认算子集已到 opset 28（见 onnx.ai）；示例选 opset 18 是为了兼容主流推理引擎的常见交集。

flowchart LR
    A["PyTorch 模型"] --> B["torch.onnx.export"]
    B --> C["ONNX 文件"]
    C --> D["ONNX Runtime"]
    C --> E["TensorRT"]
    C --> F["CoreML"]
    C --> G["LiteRT<br/>(原 TFLite)"]

TorchScript

TorchScript 是 PyTorch 自带的模型序列化方案，支持脱离 Python 环境运行。

import torch
import torch.nn as nn

class SimpleNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(10, 50)
        self.relu = nn.ReLU()
        self.fc2 = nn.Linear(50, 3)

    def forward(self, x):
        return self.fc2(self.relu(self.fc1(x)))

model = SimpleNet()
model.eval()

scripted = torch.jit.script(model)
scripted.save('/tmp/model_scripted.pt')

traced = torch.jit.trace(model, torch.randn(1, 10))
traced.save('/tmp/model_traced.pt')

loaded = torch.jit.load('/tmp/model_scripted.pt')
x = torch.randn(1, 10)
with torch.no_grad():
    out = loaded(x)
print(f"TorchScript 输出形状: {list(out.shape)}")
方式 原理 适用场景
torch.jit.script 编译 Python 代码 包含条件/循环的模型
torch.jit.trace 跟踪一次前向传播 固定控制流的模型

版本控制

模型版本控制是生产环境中必不可少的实践，确保模型的可追溯性和可复现性。

工具 特点 适用场景
Git LFS Git 大文件扩展 小团队、小模型
DVC 数据版本控制 数据 + 模型版本管理
MLflow Model Registry 模型注册中心 企业级 MLOps
W&B Artifacts 实验追踪 + 制品管理 实验管理
Hugging Face Hub (GGUF) LLM 权重托管与 GGUF 格式分发 开源大模型的分发与复用

说明： 在大语言模型场景，社区事实上的分发格式是 GGUF（llama.cpp 生态使用的单文件权重格式，见 ggml 规范文档 与 Hugging Face GGUF 文档），它把权重、分词器和元数据打包为一个文件，直接面向端侧推理。

model_metadata = {
    "model_name": "iris_classifier",
    "version": "1.2.0",
    "framework": "sklearn",
    "algorithm": "RandomForest",
    "metrics": {
        "accuracy": 0.9556,
        "f1_weighted": 0.9554,
    },
    "hyperparameters": {
        "n_estimators": 100,
        "max_depth": None,
    },
    "training_data": "iris_dataset_v2",
    "created_at": "2026-03-30",
}

import json
print(json.dumps(model_metadata, indent=2))

提示： 在生产环境中，总是保存权重而非完整模型。完整模型与 Python 版本和库版本强绑定，容易在环境变化时出问题。同时，ONNX 是跨框架部署的最佳选择。

小结

  • Pickle/Joblib 是 scikit-learn 模型的标准保存方式，但有安全风险。
  • PyTorch 推荐保存 state_dict，Checkpoint 用于断点续训。
  • ONNX 是跨框架模型交换标准，搭配 ONNX Runtime 可实现高效推理；导出时注意 opset 版本与 PyTorch 新旧两条导出路径的差异。
  • TorchScript 支持脱离 Python 运行，适合 C++ 推理环境。
  • 版本控制确保模型的可追溯性，DVC 和 MLflow 是常用工具。
