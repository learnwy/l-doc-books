TFLite 移动端部署

什么是 TensorFlow Lite

TensorFlow Lite（TFLite）是 Google 推出的轻量级推理框架，专为移动设备、嵌入式设备和物联网场景设计。它通过模型转换和量化技术，实现了在资源受限设备上的高效推理。

命名更新： 自 2024 年 9 月起，Google 将 TensorFlow Lite 正式更名为 LiteRT（见官方公告与 LiteRT 官方站点）。.tflite 模型格式不变，转换 API 与本节代码保持一致；Android/iOS 的 SDK 坐标则逐步迁移到 LiteRT 命名（下文集成部分已更新）。社区里 "TFLite" 与 "LiteRT" 目前仍在混用，指同一个运行时。

flowchart LR
    A["TensorFlow / PyTorch 模型"] --> B["LiteRT Converter<br/>(原 TFLite Converter)"]
    B --> C["模型文件<br/>.tflite"]
    C --> D["Android"]
    C --> E["iOS"]
    C --> F["嵌入式设备"]
    C --> G["Microcontrollers"]

核心概念

端侧部署围绕三个概念展开：

  • 量化（Quantization）：把权重和激活从高精度降到低精度（FP16/INT8/INT4）。它同时减小体积与加速推理，是端侧部署的核心手段。代价是精度损失，而"需要多少校准数据"是划分量化类型的依据。
  • 委托（Delegate）：把计算卸载到专用加速器（GPU/NPU/DSP）的机制。它是把"模型可跑"变成"跑得够快"的桥梁。
  • 端侧约束：移动端的关键不仅是精度，而是延迟、模型大小、功耗与内存四者的平衡。这也是端侧 LLM 带来的新压力——KV cache 随上下文长度增长。

三者的因果关系很直接：硬件约束驱动了量化，而不同硬件又需要不同的 Delegate 才能发挥性能。理解这条链，就能理解为何"先动态量化快速验证、再静态量化或 QAT 进一步优化"是合理的实践顺序。

模型转换

将 TensorFlow 模型转换为 TFLite 格式是部署的第一步。

import numpy as np

def tflite_conversion_example():
    try:
        import tensorflow as tf

        model = tf.keras.Sequential([
            tf.keras.layers.Conv2D(16, 3, activation='relu', input_shape=(28, 28, 1)),
            tf.keras.layers.MaxPooling2D(2),
            tf.keras.layers.Conv2D(32, 3, activation='relu'),
            tf.keras.layers.GlobalAveragePooling2D(),
            tf.keras.layers.Dense(10, activation='softmax'),
        ])

        converter = tf.lite.TFLiteConverter.from_keras_model(model)
        tflite_model = converter.convert()

        with open('/tmp/model.tflite', 'wb') as f:
            f.write(tflite_model)

        print(f"TFLite 模型大小: {len(tflite_model) / 1024:.1f} KB")
    except ImportError:
        print("需要安装 tensorflow: pip install tensorflow")

量化

量化（Quantization）是将模型权重和激活值从高精度（FP32）转换为低精度（INT8/FP16）的技术，可以显著减小模型体积并加速推理。

flowchart TD
    A["量化类型"]
    A --> B["训练后动态量化<br/>Post-training Dynamic"]
    A --> C["训练后静态量化<br/>Post-training Static"]
    A --> D["量化感知训练<br/>QAT"]
    B --> E["权重 INT8<br/>激活 FP32"]
    C --> F["权重 INT8<br/>激活 INT8"]
    D --> G["训练时模拟量化<br/>精度最优"]
量化方式 精度损失 模型压缩 速度提升 需要校准数据
动态量化 很小 ~2-4x ~2x 否
静态量化（INT8） 小 ~4x ~3-4x 是
FP16 量化 极小 ~2x ~1.5-2x 否
QAT 最小 ~4x ~3-4x 否（训练集） 
def quantization_example():
    try:
        import tensorflow as tf
        import numpy as np

        model = tf.keras.Sequential([
            tf.keras.layers.Dense(64, activation='relu', input_shape=(20,)),
            tf.keras.layers.Dense(32, activation='relu'),
            tf.keras.layers.Dense(10, activation='softmax'),
        ])
        model.compile(optimizer='adam', loss='sparse_categorical_crossentropy')

        converter = tf.lite.TFLiteConverter.from_keras_model(model)

        tflite_fp32 = converter.convert()

        converter.optimizations = [tf.lite.Optimize.DEFAULT]
        tflite_dynamic = converter.convert()

        converter.optimizations = [tf.lite.Optimize.DEFAULT]
        converter.target_spec.supported_types = [tf.float16]
        tflite_fp16 = converter.convert()

        print(f"FP32 模型:  {len(tflite_fp32) / 1024:.1f} KB")
        print(f"动态量化:   {len(tflite_dynamic) / 1024:.1f} KB  "
              f"(压缩 {len(tflite_fp32)/len(tflite_dynamic):.1f}x)")
        print(f"FP16 量化:  {len(tflite_fp16) / 1024:.1f} KB  "
              f"(压缩 {len(tflite_fp32)/len(tflite_fp16):.1f}x)")
    except ImportError:
        print("需要安装 tensorflow: pip install tensorflow")

quantization_example()

Delegate（硬件加速）

TFLite 通过 Delegate 机制将计算卸载到专用硬件加速器上。

Delegate 硬件 平台
GPU Delegate GPU Android/iOS
NNAPI Delegate Android NPU Android 8.1+（NNAPI 已在 Android 15 中弃用，见 Android 官方说明，新项目应改用 LiteRT 的 GPU Delegate 或 Play services 运行时）
Core ML Delegate Apple Neural Engine iOS
XNNPACK CPU（优化 SIMD） 跨平台
Hexagon Delegate Qualcomm DSP Android 
delegate_config = {
    "android": {
        "primary": "GPU Delegate / LiteRT via Google Play services",
        "fallback": "XNNPACK (CPU)",
        "note": "NNAPI 已随 Android 15 弃用，官方建议迁移到 LiteRT + Play services 提供的加速路径",
    },
    "ios": {
        "primary": "Core ML Delegate",
        "fallback": "GPU Delegate → XNNPACK",
        "note": "Core ML 利用 Neural Engine",
    },
}

for platform, config in delegate_config.items():
    print(f"\n{platform.upper()} 推理策略:")
    print(f"  首选: {config['primary']}")
    print(f"  回退: {config['fallback']}")
    print(f"  备注: {config['note']}")

从端侧小模型到端侧 LLM

TFLite/LiteRT 的经典场景是 MB 级的视觉与音频小模型。2024 年以来，随着量化技术（INT4/INT8 权重量化）和小型开源模型的成熟，在手机和笔记本上直接运行十亿参数级大语言模型已成为主流工程实践，形成了几条独立的端侧 LLM 推理栈：

推理栈 平台 说明
llama.cpp 跨平台（CPU/GPU） C/C++ 实现的高效 LLM 推理引擎，是端侧/本地 LLM 部署事实上的标准
GGUF 格式 与 llama.cpp 配套 单文件打包权重 + 分词器 + 元数据，社区分发标准（规范、Hugging Face 文档）
MediaPipe LLM Inference API Android/iOS/Web Google 官方移动端 LLM 推理封装，可直接运行 Gemma 3n 等开源小模型
MLX / mlx-lm Apple silicon Apple 官方开源的数组计算框架，Mac 本地运行 LLM 的首选 
edge_llm_stacks = {
    "llama.cpp": {
        "format": "GGUF (单文件, 量化等级 Q4_K_M 等)",
        "runtime": "纯 C/C++, 无 Python 依赖",
        "targets": "手机 App 内嵌 / 桌面本地推理 / 服务器 CPU 推理",
    },
    "MediaPipe LLM Inference": {
        "format": ".task / .bin (LiteRT 生态模型包)",
        "runtime": "Android/iOS SDK 封装",
        "targets": "移动 App 快速集成 Gemma 系列开源模型",
    },
    "MLX (mlx-lm)": {
        "format": "MLX safetensors (4-bit 量化常用)",
        "runtime": "Python/Swift, 针对 Apple 统一内存优化",
        "targets": "macOS 本地 LLM 应用与研究",
    },
}

for name, info in edge_llm_stacks.items():
    print(f"\n{name}:")
    for k, v in info.items():
        print(f"  {k:10s}: {v}")

与传统 TFLite 小模型部署相比，端侧 LLM 的工程关注点从「模型体积与延迟」扩展到 内存占用（KV cache 随上下文长度增长）、token 吞吐量与电量消耗；量化也从可选项变成了默认前提。

提示： 移动端部署的关键不仅是模型精度，更要关注推理延迟、模型大小和功耗。建议先用动态量化快速验证，再用静态量化或 QAT 进一步优化。

小结

  • TFLite/LiteRT 是移动端和嵌入式设备的主流推理框架，支持 Android 和 iOS；框架自 2024 年 9 月起更名为 LiteRT。
  • 量化是减小模型体积和加速推理的核心技术，动态量化最简单，QAT 精度最好。
  • Delegate 机制将推理卸载到 GPU/NPU/DSP 等硬件加速器，显著提升速度；Android 上 NNAPI 已随 Android 15 弃用，应改用 GPU Delegate 或 Play services 运行时。
  • 端侧部署的版图已从 MB 级小模型扩展到端侧 LLM：llama.cpp/GGUF、MediaPipe LLM Inference API 与 Apple MLX 构成了新的推理栈。
  • 移动端部署需要综合考虑精度、延迟、模型大小和功耗的平衡。
