数据隐私与脱敏

核心概念

数据隐私保护是 AI 数据工程中不可回避的核心议题。训练数据中包含的个人身份信息（PII）、敏感属性和行为数据如果处理不当，不仅会违反法律法规，还会导致严重的信任危机。数据脱敏（Data Masking/Anonymization）是在保留数据分析价值的前提下移除或模糊个人可识别信息的技术手段。

数据脱敏技术
数据脱敏是最直接的隐私保护手段，通过对敏感字段进行变换使其无法识别个体，同时保持数据的统计特性和分析价值。


PII 检测与分类 是脱敏的第一步，需要自动识别数据中的各类敏感信息：


interface PIIDetector {
  detect(text: string): PIIEntity[];
  detectInDataFrame(data: DataRow[]): PIIReport;
  classify(entity: string): PIISensitivityLevel;
}

interface PIIEntity {
  text: string;
  type: PIIType;
  startOffset: number;
  endOffset: number;
  confidence: number;
  sensitivityLevel: PIISensitivityLevel;
}

type PIIType =
  | 'name'
  | 'id_number'
  | 'phone'
  | 'email'
  | 'address'
  | 'bank_account'
  | 'ip_address'
  | 'date_of_birth'
  | 'medical_record'
  | 'biometric';

type PIISensitivityLevel = 'low' | 'medium' | 'high' | 'critical';

interface PIIReport {
  totalRows: number;
  piiDetected: boolean;
  detections: {
    column: string;
    piiType: PIIType;
    detectionCount: number;
    sampleValues: string[];
    sensitivityLevel: PIISensitivityLevel;
    suggestedAction: MaskingAction;
  }[];
}
脱敏方法 根据敏感性级别和数据用途选择不同的脱敏策略：


type MaskingAction =
  | { type: 'delete' }
  | { type: 'hash'; algorithm: 'sha256' | 'md5'; salt: string }
  | { type: 'replace'; pattern: string }
  | { type: 'generalize'; level: number }
  | { type: 'perturb'; noise: number }
  | { type: 'pseudonymize'; mappingTable: string }
  | { type: 'tokenize'; tokenStore: string }
  | { type: 'format_preserving_encrypt'; key: string };

interface MaskingPolicy {
  rules: MaskingRule[];
  defaultAction: MaskingAction;
  auditLog: boolean;
}

interface MaskingRule {
  column: string;
  piiType: PIIType;
  action: MaskingAction;
  condition?: string;
}

function applyMasking(data: DataRow[], policy: MaskingPolicy): { maskedData: DataRow[]; report: MaskingReport } {
  const maskedData = data.map((row) => {
    const maskedRow = { ...row };
    for (const rule of policy.rules) {
      if (rule.column in maskedRow) {
        maskedRow[rule.column] = maskValue(maskedRow[rule.column], rule.action);
      }
    }
    return maskedRow;
  });

  return {
    maskedData,
    report: generateMaskingReport(data, maskedData, policy),
  };
}

差分隐私
差分隐私（Differential Privacy, DP）提供数学可证的隐私保证：无论某个个体是否在数据集中，查询结果的概率分布变化都可以被严格限制在参数 ε 定义的范围内。


DP-SGD 是将差分隐私应用于深度学习训练的标准方法，通过对梯度裁剪和添加噪声实现隐私保护：


interface DPSGDConfig {
  epsilon: number;
  delta: number;
  maxGradNorm: number;
  noiseMultiplier: number;
  batchSize: number;
  epochs: number;
  accountant: 'rdp' | 'gdp' | 'pld';
}

interface PrivacyAccountant {
  epsilon: number;
  delta: number;
  stepsCompleted: number;
  remainingBudget(): number;
  composedEpsilon(steps: number): number;
}

function dpSGDStep(gradients: number[][], config: DPSGDConfig): number[][] {
  const clipped = gradients.map((grad) => {
    const norm = Math.sqrt(grad.reduce((s, g) => s + g * g, 0));
    const scale = Math.min(1, config.maxGradNorm / norm);
    return grad.map((g) => g * scale);
  });

  const aggregated = clipped[0].map((_, j) => clipped.reduce((sum, grad) => sum + grad[j], 0) / clipped.length);

  const noised = aggregated.map((g) => g + gaussianNoise(0, config.noiseMultiplier * config.maxGradNorm));

  return [noised];
}

K-匿名与数据泛化
K-匿名（K-Anonymity）确保数据集中每条记录至少与 K-1 条其他记录在准标识符（Quasi-Identifier）上不可区分。它是传统数据脱敏中最广泛应用的模型。


interface KAnonymityConfig {
  quasiIdentifiers: string[];
  sensitiveAttributes: string[];
  kValue: number;
  generalizationHierarchies: Record<string, GeneralizationHierarchy>;
  suppressionThreshold: number;
}

interface GeneralizationHierarchy {
  attribute: string;
  levels: HierarchyLevel[];
}

interface HierarchyLevel {
  level: number;
  mapping: Record<string, string>;
}

function checkKAnonymity(data: DataRow[], quasiIdentifiers: string[], k: number): KAnonymityResult {
  const groups = new Map<string, DataRow[]>();

  for (const row of data) {
    const key = quasiIdentifiers.map((qi) => String(row[qi])).join('|');
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key)!.push(row);
  }

  const violations = [...groups.entries()]
    .filter(([_, rows]) => rows.length < k)
    .map(([key, rows]) => ({
      equivalenceClass: key,
      size: rows.length,
      deficit: k - rows.length,
    }));

  return {
    satisfied: violations.length === 0,
    kValue: k,
    totalGroups: groups.size,
    violatingGroups: violations.length,
    violations,
    minGroupSize: Math.min(...[...groups.values()].map((g) => g.length)),
  };
}

隐私保护架构
生产环境中的隐私保护需要从架构层面系统化实施，涵盖数据采集、存储、处理和共享的全生命周期。


interface PrivacyArchitecture {
  dataClassification: DataClassificationPolicy;
  accessControl: PrivacyAccessControl;
  maskingEngine: MaskingEngine;
  auditSystem: PrivacyAuditSystem;
  consentManagement: ConsentManager;
}

interface DataClassificationPolicy {
  levels: ClassificationLevel[];
  autoClassifier: PIIDetector;
  reviewProcess: ApprovalWorkflow;
}

type ClassificationLevel =
  | { level: 'public'; restrictions: [] }
  | { level: 'internal'; restrictions: ['auth_required'] }
  | { level: 'confidential'; restrictions: ['auth_required', 'encrypted', 'audit_logged'] }
  | {
      level: 'restricted';
      restrictions: ['auth_required', 'encrypted', 'audit_logged', 'approval_required', 'masked'];
    };
小结
    

  • 数据隐私保护是 AI 数据工程的法律义务和伦理底线，必须从设计阶段就纳入考量
    • 

  • PII 自动检测是脱敏流程的起点，需要覆盖文本、结构化数据和日志等多种场景
    • 

  • 脱敏方法的选择取决于数据用途和隐私要求，假名化保留关联性，泛化损失最大
    • 

  • 差分隐私提供数学可证的隐私保证，ε < 5 是合理的隐私预算范围
    • 

  • K-匿名及其扩展解决记录链接和属性泄露攻击，但面对高维数据效用下降严重
    • 

  • 隐私保护需要架构级实施，覆盖数据全生命周期的自动化分类、脱敏和审计
    •
