数据血缘追踪

核心概念

数据血缘（Data Lineage）是记录数据从源头到消费全链路转化过程的元数据体系。在 AI 数据工程中，数据血缘追踪回答三个核心问题：这条数据从哪里来、经过了什么处理、被谁使用。它是数据治理的基石，也是模型可解释性、问题定位和合规审计的关键能力。

血缘图模型
血缘关系本质上是一个有向无环图（DAG），节点代表数据实体，边代表转换关系。设计合理的图模型是血缘追踪系统的核心。


interface LineageGraph {
  nodes: Map<string, LineageNode>;
  edges: LineageEdge[];
  addNode(node: LineageNode): void;
  addEdge(edge: LineageEdge): void;
  getUpstream(nodeId: string, depth: number): LineageNode[];
  getDownstream(nodeId: string, depth: number): LineageNode[];
  getPath(fromId: string, toId: string): LineagePath[];
}

interface LineageNode {
  id: string;
  type: NodeType;
  name: string;
  version?: string;
  metadata: Record<string, unknown>;
  createdAt: Date;
  updatedAt: Date;
  owner: string;
  tags: Record<string, string>;
}

type NodeType =
  | 'source'
  | 'table'
  | 'view'
  | 'feature_view'
  | 'dataset'
  | 'model'
  | 'endpoint'
  | 'dashboard'
  | 'pipeline';

interface LineageEdge {
  id: string;
  sourceId: string;
  targetId: string;
  type: EdgeType;
  transformation?: TransformationSpec;
  executedAt: Date;
  executedBy: string;
  jobId?: string;
}

type EdgeType = 'derived_from' | 'trained_on' | 'deployed_as' | 'consumed_by' | 'transformed_by';
列级血缘 提供最精确的溯源能力，记录每个字段如何从上游字段计算得来：


interface ColumnLineage {
  targetColumn: ColumnRef;
  sourceColumns: ColumnRef[];
  transformation: string;
  transformationType: 'direct' | 'aggregation' | 'join' | 'filter' | 'expression';
}

interface ColumnRef {
  table: string;
  column: string;
  version?: string;
}

function extractColumnLineage(sqlQuery: string): ColumnLineage[] {
  const parsed = parseSQL(sqlQuery);
  const lineages: ColumnLineage[] = [];

  for (const selectCol of parsed.selectColumns) {
    const sources = traceColumnSources(selectCol, parsed);
    lineages.push({
      targetColumn: { table: parsed.targetTable, column: selectCol.alias },
      sourceColumns: sources,
      transformation: selectCol.expression,
      transformationType: classifyTransformation(selectCol.expression),
    });
  }

  return lineages;
}
自动血缘采集
手动维护血缘关系不可持续。自动化采集通过解析 SQL、分析代码和拦截运行时操作来自动构建血缘图。


SQL 解析 是最成熟的自动采集方法：


interface SQLLineageExtractor {
  parse(sql: string): ParsedQuery;
  extractTableLineage(query: ParsedQuery): TableLineage[];
  extractColumnLineage(query: ParsedQuery): ColumnLineage[];
}

interface ParsedQuery {
  type: 'select' | 'insert' | 'create_table_as' | 'merge';
  sourceTables: TableRef[];
  targetTable?: TableRef;
  selectColumns: ColumnExpression[];
  joins: JoinSpec[];
  filters: FilterExpression[];
  groupBy: ColumnRef[];
}

interface TableRef {
  database: string;
  schema: string;
  table: string;
  alias?: string;
}

影响分析与溯源
血缘图的核心价值在于支持两个方向的分析：正向影响分析（上游变更影响哪些下游）和逆向溯源（下游问题追溯到哪个上游）。


影响分析 在上游数据源变更或下线前评估影响范围：


interface ImpactAnalysis {
  sourceNode: string;
  changeType: 'schema_change' | 'data_change' | 'deprecation' | 'deletion';
  impactedNodes: ImpactedNode[];
  riskLevel: 'low' | 'medium' | 'high' | 'critical';
  recommendations: string[];
}

interface ImpactedNode {
  nodeId: string;
  nodeType: NodeType;
  impactType: 'direct' | 'transitive';
  distance: number;
  owner: string;
  severity: 'breaking' | 'degrading' | 'informational';
}

function analyzeImpact(graph: LineageGraph, sourceId: string, changeType: string): ImpactAnalysis {
  const downstream = graph.getDownstream(sourceId, 10);

  const impacted = downstream.map((node) => ({
    nodeId: node.id,
    nodeType: node.type,
    impactType: isDirectDependency(graph, sourceId, node.id) ? 'direct' : 'transitive',
    distance: shortestPath(graph, sourceId, node.id),
    owner: node.owner,
    severity: assessSeverity(node, changeType),
  }));

  const criticalCount = impacted.filter((n) => n.severity === 'breaking').length;
  const riskLevel = criticalCount > 5 ? 'critical' : criticalCount > 0 ? 'high' : 'medium';

  return {
    sourceNode: sourceId,
    changeType: changeType as ImpactAnalysis['changeType'],
    impactedNodes: impacted,
    riskLevel,
    recommendations: generateRecommendations(impacted, changeType),
  };
}

血缘可视化与治理集成
血缘信息需要以直观的方式呈现给不同角色的用户，并与数据治理流程深度集成。


interface LineageVisualization {
  renderGraph(
    nodeId: string,
    direction: 'upstream' | 'downstream' | 'both',
    depth: number,
    filters?: LineageFilter,
  ): LineageView;
  highlightPath(fromId: string, toId: string): LineageView;
  showColumnLineage(tableId: string, columnName: string): ColumnLineageView;
}

interface LineageFilter {
  nodeTypes?: NodeType[];
  owners?: string[];
  tags?: Record<string, string>;
  timeRange?: { start: Date; end: Date };
}

interface LineageView {
  nodes: VisualNode[];
  edges: VisualEdge[];
  layout: LayoutConfig;
  metadata: {
    totalNodes: number;
    maxDepth: number;
    criticalPaths: string[][];
  };
}

interface GovernanceIntegration {
  onSchemaChange(event: SchemaChangeEvent): ImpactAnalysis;
  onDataQualityAlert(alert: QualityAlert): RootCauseAnalysis;
  onComplianceAudit(request: AuditRequest): ComplianceReport;
  onDeprecationRequest(nodeId: string): DeprecationPlan;
}
小结
    

  • 数据血缘是数据治理的基石，回答数据从哪里来、经过什么处理、被谁使用
    • 

  • 列级血缘提供最精确的溯源能力，是高质量治理的标配
    • 

  • 自动化采集（SQL 解析 + 运行时拦截）是可持续维护血缘的唯一方案
    • 

  • 影响分析帮助在上游变更前评估风险，避免不可预期的下游故障
    • 

  • 根因溯源在模型性能下降时快速定位数据层面的根本原因
    • 

  • 血缘系统需要与变更管理、合规审计和数据质量监控深度集成
