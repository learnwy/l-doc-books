ETL 管道设计

核心概念

ETL（Extract-Transform-Load）管道是 AI 数据工程的骨架，负责从多种数据源提取原始数据，经过清洗、转换和聚合后加载到目标存储中供模型训练和推理使用。现代 ML 管道已从传统的批量 ETL 演进为支持流式、增量和混合模式的数据编排系统。

管道架构设计
一个健壮的 ETL 管道需要考虑可靠性、可观测性、可扩展性和可维护性四个维度。


分层架构 将数据处理分为多个逻辑层，每层职责清晰：


interface ETLPipeline {
  name: string;
  version: string;
  stages: PipelineStage[];
  schedule: ScheduleConfig;
  errorHandling: ErrorStrategy;
  monitoring: MonitoringConfig;
}

interface PipelineStage {
  name: string;
  type: 'extract' | 'transform' | 'load' | 'validate';
  config: StageConfig;
  retryPolicy: RetryPolicy;
  dependencies: string[];
  timeout: number;
}

interface RetryPolicy {
  maxRetries: number;
  backoffStrategy: 'fixed' | 'exponential' | 'linear';
  initialDelay: number;
  maxDelay: number;
  retryableErrors: string[];
}

interface ErrorStrategy {
  onFailure: 'stop' | 'skip' | 'dead_letter' | 'alert';
  deadLetterQueue?: string;
  alertChannels: string[];
  maxFailureRate: number;
}

提取层设计
提取层负责从异构数据源可靠地获取数据，需要处理连接管理、增量提取和 Schema 演化等问题。


增量提取策略 避免每次全量读取，显著降低资源消耗：


interface IncrementalExtractor {
  source: DataSourceConfig;
  strategy: IncrementalStrategy;
  watermark: WatermarkState;
}

type IncrementalStrategy =
  | { type: 'timestamp'; column: string; format: string }
  | { type: 'id'; column: string; lastId: number }
  | { type: 'cdc'; binlogPosition: string }
  | { type: 'hash'; columns: string[]; hashStore: string };

interface WatermarkState {
  lastExtractedAt: Date;
  lastValue: string;
  rowsExtracted: number;
  checksum: string;
}

function buildIncrementalQuery(table: string, strategy: IncrementalStrategy, watermark: WatermarkState): string {
  switch (strategy.type) {
    case 'timestamp':
      return `SELECT * FROM ${table} WHERE ${strategy.column} > '${watermark.lastValue}' ORDER BY ${strategy.column}`;
    case 'id':
      return `SELECT * FROM ${table} WHERE ${strategy.column} > ${watermark.lastValue} ORDER BY ${strategy.column}`;
    case 'cdc':
      return `SHOW BINLOG EVENTS FROM '${strategy.binlogPosition}'`;
    default:
      return `SELECT * FROM ${table}`;
  }
}

转换层设计
转换层是 ETL 管道中最复杂的部分，包括数据清洗、格式标准化、特征计算和业务逻辑实现。


转换操作分类 按复杂度和依赖关系组织：


type TransformOperation =
  | { type: 'map'; fn: (row: Record<string, unknown>) => Record<string, unknown> }
  | { type: 'filter'; predicate: (row: Record<string, unknown>) => boolean }
  | { type: 'aggregate'; groupBy: string[]; aggregations: AggregationSpec[] }
  | { type: 'join'; rightSource: string; joinKey: string[]; joinType: JoinType }
  | { type: 'window'; partitionBy: string[]; orderBy: string; windowFn: WindowFunction }
  | { type: 'pivot'; indexCol: string; pivotCol: string; valueCol: string }
  | { type: 'custom'; processFn: (batch: DataBatch) => DataBatch };

interface TransformDAG {
  nodes: Map<string, TransformNode>;

  execute(input: DataBatch): Promise<DataBatch>;
}

interface TransformNode {
  id: string;
  operation: TransformOperation;
  inputSchema: SchemaDefinition;
  outputSchema: SchemaDefinition;
  estimatedCost: ResourceEstimate;
}

加载与质量保障
加载层将转换后的数据写入目标存储，需要保证原子性和幂等性。


幂等写入 确保重试不会产生重复数据：


interface LoadStrategy {
  target: TargetConfig;
  writeMode: 'append' | 'upsert' | 'overwrite' | 'merge';
  idempotencyKey?: string;
  partitioning?: PartitionConfig;
  batchSize: number;
}

interface PartitionConfig {
  columns: string[];
  strategy: 'hash' | 'range' | 'list';
  granularity?: 'hourly' | 'daily' | 'monthly';
}

function upsertBatch(target: DataStore, batch: DataBatch, keyColumns: string[]): Promise<UpsertResult> {
  const existing = target.query({
    filter: buildKeyFilter(batch, keyColumns),
  });

  const toInsert = batch.rows.filter((row) => !existing.has(extractKey(row, keyColumns)));
  const toUpdate = batch.rows.filter((row) => existing.has(extractKey(row, keyColumns)));

  return target.transaction(async (tx) => {
    await tx.bulkInsert(toInsert);
    await tx.bulkUpdate(toUpdate, keyColumns);
    return { inserted: toInsert.length, updated: toUpdate.length };
  });
}

管道监控与可观测性
生产级 ETL 管道需要完善的监控体系，覆盖运行状态、数据质量和资源使用三个维度。


interface PipelineMetrics {
  execution: {
    runId: string;
    startTime: Date;
    endTime: Date;
    status: 'success' | 'failed' | 'partial';

  dataQuality: {
    totalRows: number;
    validRows: number;

    qualityScore: number;

  inputRows: number;

小结
    

  • ETL 管道是 AI 数据工程的核心基础设施，连接数据源和模型训练
    • 

  • 增量提取（时间戳、CDC）相比全量提取显著降低资源消耗和延迟
    • 

  • DAG 编排是管道调度的标准模式，清晰表达任务间的依赖关系
    • 

  • Schema 演化处理是长期运行管道的必备能力，需要兼容性检查和自动适应
    • 

  • 幂等写入保证重试安全性，是管道可靠性的基础
    • 

  • 端到端监控覆盖执行状态、数据质量和资源使用，SLA 追踪保障业务承诺
