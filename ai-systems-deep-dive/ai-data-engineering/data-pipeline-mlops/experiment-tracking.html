实验追踪

核心概念

实验追踪（Experiment Tracking）是系统化记录、比较和分析机器学习实验过程和结果的实践。每次实验涉及数据、代码、超参数、环境和模型产物等多个维度，手动管理这些信息不仅效率低下且容易出错。实验追踪工具将这一过程自动化，是 MLOps 工作流的核心组件。

实验记录架构
实验追踪系统的核心数据模型围绕 Experiment → Run → Metric/Param/Artifact 三层结构组织。


interface Experiment {
  id: string;
  name: string;
  description: string;
  tags: Record<string, string>;
  runs: Run[];
  createdAt: Date;
  owner: string;
}

interface Run {
  id: string;
  experimentId: string;
  status: 'running' | 'completed' | 'failed' | 'killed';
  startTime: Date;
  endTime?: Date;
  params: Record<string, string>;
  metrics: MetricHistory[];
  artifacts: Artifact[];
  tags: Record<string, string>;
  gitInfo: GitInfo;
  systemInfo: SystemInfo;
}

interface MetricHistory {
  key: string;
  values: { step: number; timestamp: Date; value: number }[];
}

interface Artifact {
  path: string;
  type: 'model' | 'dataset' | 'figure' | 'config' | 'other';
  size: number;
  hash: string;
  uri: string;
}

interface GitInfo {
  commit: string;
  branch: string;
  remoteUrl: string;
  isDirty: boolean;
  diff?: string;
}

interface SystemInfo {
  hostname: string;
  gpu: string[];
  cpuCount: number;
  memoryGB: number;
  pythonVersion: string;
  dependencies: Record<string, string>;
}
自动化追踪集成 将追踪逻辑嵌入训练代码，最小化对业务逻辑的侵入：


interface ExperimentTracker {
  startRun(config: RunConfig): Run;
  logParam(key: string, value: string | number): void;
  logParams(params: Record<string, string | number>): void;
  logMetric(key: string, value: number, step?: number): void;
  logMetrics(metrics: Record<string, number>, step?: number): void;
  logArtifact(localPath: string, artifactPath?: string): void;
  logModel(model: ModelArtifact, registeredName?: string): void;
  setTag(key: string, value: string): void;
  endRun(status?: string): void;
}

function trainWithTracking(tracker: ExperimentTracker, config: TrainingConfig, data: TrainingData): TrainedModel {
  const run = tracker.startRun({ name: config.experimentName });

  tracker.logParams({
    learning_rate: config.learningRate,
    batch_size: config.batchSize,
    epochs: config.epochs,
    model_type: config.modelType,
    optimizer: config.optimizer,
  });

  tracker.setTag('dataset_version', data.version);
  tracker.setTag('framework', 'pytorch');

  const model = initializeModel(config);

  for (let epoch = 0; epoch < config.epochs; epoch++) {
    const trainMetrics = trainEpoch(model, data.trainLoader, config);
    const valMetrics = evaluate(model, data.valLoader);

    tracker.logMetrics(
      {
        train_loss: trainMetrics.loss,
        train_accuracy: trainMetrics.accuracy,
        val_loss: valMetrics.loss,
        val_accuracy: valMetrics.accuracy,
        val_f1: valMetrics.f1,
      },
      epoch,
    );
  }

  tracker.logModel({ model, framework: 'pytorch' }, config.modelName);
  tracker.endRun('completed');

  return model;
}
实验比较与分析
当积累了大量实验后，系统化的比较分析能力决定了能否从中发现有价值的洞见。


多维度比较 同时对比参数、指标和训练过程：


interface ExperimentComparison {
  runs: Run[];
  paramDiff: ParamDiffTable;
  metricComparison: MetricComparisonTable;
  bestRun: Run;
  insights: ComparisonInsight[];
}

interface ParamDiffTable {
  commonParams: Record<string, string>;
  differingParams: {
    paramName: string;
    values: { runId: string; value: string }[];
  }[];
}

interface MetricComparisonTable {
  metrics: {
    metricName: string;
    values: { runId: string; value: number; rank: number }[];
    best: { runId: string; value: number };
    worst: { runId: string; value: number };
    stdDev: number;
  }[];
}

interface ComparisonInsight {
  type: 'correlation' | 'anomaly' | 'trend' | 'recommendation';
  description: string;
  confidence: number;
  relatedParams?: string[];
  relatedMetrics?: string[];
}

function compareExperiments(runs: Run[], primaryMetric: string): ExperimentComparison {
  const paramDiff = computeParamDiff(runs);
  const metricComparison = computeMetricComparison(runs);

  const bestRun = runs.reduce((best, run) => {
    const bestVal = getLatestMetric(best, primaryMetric);
    const runVal = getLatestMetric(run, primaryMetric);
    return runVal > bestVal ? run : best;
  });

  const insights = generateInsights(runs, paramDiff, metricComparison);

  return { runs, paramDiff, metricComparison, bestRun, insights };
}

模型注册与生命周期
实验追踪的最终目的是选出最优模型并将其推向生产。模型注册表（Model Registry）管理从实验到部署的完整生命周期。


interface ModelRegistry {
  registerModel(name: string, runId: string, artifactPath: string): RegisteredModel;
  transitionStage(name: string, version: number, stage: ModelStage): void;
  getLatestVersion(name: string, stage: ModelStage): ModelVersion;
  compareVersions(name: string, versionA: number, versionB: number): ModelComparison;
}

type ModelStage = 'none' | 'staging' | 'production' | 'archived';

interface RegisteredModel {
  name: string;
  versions: ModelVersion[];
  tags: Record<string, string>;
  description: string;
}

interface ModelVersion {
  version: number;
  stage: ModelStage;
  runId: string;
  metrics: Record<string, number>;
  createdAt: Date;
  lastUpdatedAt: Date;
  approvedBy?: string;
}

小结
    

  • 实验追踪将实验管理从手动记录升级为自动化系统，是 MLOps 的核心组件
    • 

  • 追踪维度涵盖超参数、指标、数据版本、代码版本、环境和模型产物
    • 

  • 系统化的比较分析帮助从大量实验中发现洞见，参数重要性分析指导超参搜索方向
    • 

  • 模型注册表管理从实验到部署的完整生命周期，阶段流转确保只有验证通过的模型进入生产
    • 

  • 工具选择应根据团队规模和基础设施决定，MLflow 是开源场景的标准选择
    • 

  • 实验追踪的价值随时间累积，建议从项目初期就建立规范的追踪流程
