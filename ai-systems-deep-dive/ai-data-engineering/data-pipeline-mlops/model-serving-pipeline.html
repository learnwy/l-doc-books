模型服务管道

核心概念

模型服务管道（Model Serving Pipeline）是将训练好的模型部署为生产级推理服务的完整系统。它涵盖模型打包、服务化、流量管理、监控和自动化更新等环节，是 MLOps 中连接模型训练和业务价值的关键桥梁。

模型打包与容器化
模型打包将训练产物（权重、配置、依赖）封装为可部署的标准化格式，容器化则将运行环境一同打包，消除"在我机器上能跑"的问题。

动态批处理（Dynamic Batching） 将短时间内到达的多个请求合并为一个批次推理，在保持延迟可控的同时显著提升 GPU 利用率：


interface DynamicBatchConfig {
  maxBatchSize: number;
  maxWaitTimeMs: number;
  preferredBatchSize: number;
  adaptiveBatching: boolean;
}

interface BatchScheduler {
  config: DynamicBatchConfig;
  pendingRequests: QueuedRequest[];
  schedule(): BatchGroup[];
}

interface QueuedRequest {
  requestId: string;
  input: TensorData;
  arrivalTime: number;
  deadline: number;
}

function scheduleBatch(
  queue: QueuedRequest[],
  config: DynamicBatchConfig,
): { batch: QueuedRequest[]; remaining: QueuedRequest[] } {
  const now = Date.now();
  const eligible = queue.filter((r) => r.deadline - now > config.maxWaitTimeMs);

  if (eligible.length >= config.preferredBatchSize) {
    return {
      batch: eligible.slice(0, config.maxBatchSize),
      remaining: eligible.slice(config.maxBatchSize),
    };
  }

  const oldest = queue[0];
  if (oldest && now - oldest.arrivalTime >= config.maxWaitTimeMs) {
    const batchSize = Math.min(queue.length, config.maxBatchSize);
    return {
      batch: queue.slice(0, batchSize),
      remaining: queue.slice(batchSize),
    };
  }

  return { batch: [], remaining: queue };
}

生产监控与自动化
模型部署后的持续监控是保障服务质量的最后防线。监控维度包括系统性能、模型质量和业务指标。


interface ServingMonitor {
  systemMetrics: {
    requestsPerSecond: number;
    latencyP50: number;
    latencyP95: number;
    latencyP99: number;
    errorRate: number;
    gpuUtilization: number;
    memoryUsage: number;
    queueDepth: number;
  };
  modelMetrics: {
    predictionDistribution: Record<string, number>;
    confidenceDistribution: number[];
    inputDriftScore: number;
    outputDriftScore: number;
    featureMissingRate: Record<string, number>;
  };
  businessMetrics: {
    conversionRate: number;
    clickThroughRate: number;
    revenuePerRequest: number;
    userSatisfaction: number;
  };
  alerts: AlertRule[];
}

interface AlertRule {
  name: string;
  condition: string;
  threshold: number;
  window: number;
  severity: 'critical' | 'warning' | 'info';
  action: 'page' | 'email' | 'slack' | 'auto_rollback';
}

小结
    

  • 模型服务管道是将训练产出转化为业务价值的关键环节，需要工程化思维
    • 

  • 标准化模型格式（ONNX）和容器化消除部署环境差异
    • 

  • 动态批处理在保持延迟的同时显著提升 GPU 利用率
    • 

  • 金丝雀发布是最推荐的部署策略，能在低风险下验证新模型
    • 

  • 生产监控覆盖系统、模型和业务三个维度，自动回滚是最后的安全网
    • 

  • 端到端的自动化（从模型注册到部署到监控）是 MLOps 成熟度的关键标志
