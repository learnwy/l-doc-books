RLHF 与大模型对齐

核心概念

RLHF（Reinforcement Learning from Human Feedback）是将人类偏好信号融入大语言模型（LLM）训练的关键技术，也是 ChatGPT 等对话 AI 系统成功的核心因素之一。RLHF 解决的核心问题是：如何让语言模型的输出符合人类的价值观、有用性和安全性标准——这些标准难以用简单的数学公式定义，但人类可以通过比较两个回答来表达偏好。

RLHF 的基本流程分为三个阶段：监督微调（SFT）→ 奖励模型训练 → 强化学习优化。监督微调用高质量的人类标注数据教模型基本的对话能力，奖励模型从人类偏好比较中学习评估回答质量的能力，最后通过 PPO（早期主流）或 GRPO 等策略优化算法调整语言模型使其最大化奖励信号。这一"三阶段"框架源自 InstructGPT（2022）；本文其后各节将交代它到 2024–2026 年间向可验证奖励、推理模型 RL 与 Agentic RL 的范式扩展。

奖励模型训练

奖励模型（Reward Model, RM）是 RLHF 的核心组件，它从人类偏好标注数据中学习评估语言模型输出质量的能力。偏好数据的形式是：给定同一个提示（Prompt），人类标注者从两个或多个模型回答中选择更优的一个。

奖励模型的训练使用 Bradley-Terry 模型：给定两个回答 ywy_wyw​（被偏好）和 yly_lyl​（不被偏好），假设偏好概率为

P(yw≻yl∣x)=σ(r(x,yw)−r(x,yl))P(y_w \succ y_l \mid x) = \sigma\big(r(x, y_w) - r(x, y_l)\big)P(yw​≻yl​∣x)=σ(r(x,yw​)−r(x,yl​))

其中 rrr 是奖励函数，σ\sigmaσ 是 sigmoid 函数。损失函数为交叉熵损失：

L(θ)=− E(x,yw,yl)∼D[log⁡σ(rθ(x,yw)−rθ(x,yl))]\mathcal{L}(\theta) = -\,\mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}}\left[\log \sigma\big(r_\theta(x, y_w) - r_\theta(x, y_l)\big)\right]L(θ)=−E(x,yw​,yl​)∼D​[logσ(rθ​(x,yw​)−rθ​(x,yl​))]

奖励模型通常基于与策略模型相同架构的 LLM，去掉最后的语言模型头，替换为输出标量奖励的线性层。使用 SFT 模型的权重初始化奖励模型可以加速训练。

graph LR
    A[提示 x] --> B[回答 y_w 被偏好]
    A --> C[回答 y_l 不被偏好]
    B --> D[RM 评分 r_w]
    C --> E[RM 评分 r_l]
    D --> F[r_w 应大于 r_l]
    E --> F
    F --> G[Bradley-Terry 损失]

奖励模型的质量直接决定 RLHF 的效果。核心挑战包括：标注一致性（不同标注者的偏好可能不一致）、奖励黑客（策略模型利用奖励模型的弱点获取高分但回答质量差）、以及分布偏移（RL 优化后策略产生的输出超出奖励模型的训练分布）。

PPO 优化与 KL 约束

RLHF 的第三阶段用策略优化算法（经典做法为 PPO）最大化奖励模型的评分，同时通过 KL 散度惩罚防止策略过度偏离 SFT 参考模型。优化目标为：

J(θ)=Ex∼D, y∼πθ[rRM(x,y)]−β DKL[πθ(⋅∣x) ∥ πref(⋅∣x)]J(\theta) = \mathbb{E}_{x \sim \mathcal{D},\, y \sim \pi_\theta}\big[r_{\mathrm{RM}}(x, y)\big] - \beta\, \mathbb{D}_{\mathrm{KL}}\big[\pi_\theta(\cdot \mid x) \,\|\, \pi_{\mathrm{ref}}(\cdot \mid x)\big]J(θ)=Ex∼D,y∼πθ​​[rRM​(x,y)]−βDKL​[πθ​(⋅∣x)∥πref​(⋅∣x)]

其中 rRMr_{\mathrm{RM}}rRM​ 是奖励模型的评分，πref\pi_{\mathrm{ref}}πref​ 是参考策略（通常是 SFT 模型），β\betaβ 是 KL 惩罚系数。KL 约束的作用至关重要：它防止策略完全偏离预训练模型的语言能力，限制奖励黑客的程度，并保持输出的多样性和流畅性。

KL 系数 β 策略行为 奖励模型利用 语言质量
β 过大 接近 SFT 低 高但缺乏改进
β 适中 平衡优化 适中 高且有所改进
β 过小 远离 SFT 高（可能奖励黑客） 可能下降
β 自适应 动态调整 可控 最佳平衡

PPO 在 RLHF 中的实现与标准 PPO 有一些重要差异。语言模型的"动作"是整个回答的 token 序列（而非单步动作），奖励通常在回答完成后一次性给出（稀疏奖励）。价值函数用于估计每个 token 位置的期望未来奖励，帮助 PPO 进行逐 token 的信用分配。

DPO 与替代方法

DPO（Direct Preference Optimization） 是 RLHF 的一个重要替代方案，它绕过了显式的奖励模型训练和 RL 优化，直接从偏好数据中优化语言模型。DPO 的关键洞见是：RLHF 中带 KL 约束的优化问题存在闭式最优解，可以将奖励函数隐式地表示为策略和参考模型的对数概率比。

DPO 的损失函数为：

L(θ)=− E(x,yw,yl)[log⁡σ(βlog⁡πθ(yw∣x)πref(yw∣x)−βlog⁡πθ(yl∣x)πref(yl∣x))]\mathcal{L}(\theta) = -\,\mathbb{E}_{(x, y_w, y_l)}\left[\log \sigma\Big(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\mathrm{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\mathrm{ref}}(y_l \mid x)}\Big)\right]L(θ)=−E(x,yw​,yl​)​[logσ(βlogπref​(yw​∣x)πθ​(yw​∣x)​−βlogπref​(yl​∣x)πθ​(yl​∣x)​)]

这等价于 RLHF 的优化目标，但完全消除了奖励模型和 RL 训练循环。DPO 的优势包括：实现简单（仅需要标准的语言模型训练循环）、训练稳定（无需调节 PPO 超参数和处理奖励模型偏差）、计算高效（不需要维护四个模型：策略、参考、奖励和价值）。

然而 DPO 也有局限：它对偏好数据的质量更敏感（RLHF 中奖励模型可以在一定程度上平滑标注噪声），且在某些场景中 PPO 的灵活性（如在线采样和迭代优化）带来更好的最终性能。

RLAIF（RL from AI Feedback） 用 AI 评估（如强大的 LLM）替代人类偏好标注，大幅降低标注成本。Constitutional AI 用一组预定义的规则让 AI 自我评判和修正。这些方法代表了经典谱系内向更可扩展方向的发展。

从偏好奖励到可验证奖励：RLVR 与推理模型 RL

经典 RLHF 的奖励来自人类偏好拟合出的神经网络评分器，它有三重固有困难：标注昂贵且主观、容易被策略黑客利用、且随任务规模扩大一致性下降。但对数学、代码这类客观任务，答案对错本就可以程序化验证——这催生了范式迁移。

RLVR（Reinforcement Learning with Verifiable Rewards） 用可执行的验证器取代学习出来的奖励模型：数学答案做精确匹配、代码跑单元测试、格式做规则校验。这一术语由 AI2 的 Tulu 3 工作（arXiv:2411.15124）确立；DeepSeek-R1-Zero 更进一步展示了只用"答案正确性 + 格式"两条规则奖励、完全不依赖人类偏好标注和神经奖励模型，纯 RL 就能从基座模型直接涌现出长链思考、自我检查与反思等推理行为。

沿着这条线的里程碑是 o1/R1 类推理模型：OpenAI o1（2024 年 9 月）首次把"用 RL 提升长链推理"作为产品化能力提出；DeepSeek-R1（arXiv:2501.12948，2025 年 1 月开源）以 GRPO 为优化器复现并开放了完整配方，其中 R1-Zero 的纯 RL 实验是公开文献中最重要的证据之一；Kimi k1.5（arXiv:2501.12599）等同期工作给出了相互印证的训练方案。此后各家公开报告的主流推理模型普遍采用"SFT 冷启动 + 大规模 RLVR + 偏好对齐收尾"的混合流水线（具体配比以各实验室公开技术报告为准）。优化算法上，GRPO 及其变体（DAPO 等）取代 PPO 成为主力——机制细节见第 3 章 PPO 与 TRPO 的"PPO 之后"一节。

奖励粒度上还有一条并行线索——结果奖励 vs 过程奖励：

维度 结果奖励模型 ORM 过程奖励模型 PRM 规则奖励（RLVR）
监督信号 最终答案对错 每个推理步骤是否正确 程序化验证器
标注成本 低（只需最终比较） 高（逐步人工标注）/中（自动构造） 极低（写验证器即可）
信用分配 稀疏、延迟 密集、逐步骤 回合级但客观
风险 步骤错结论对也会被奖励 步骤标签噪声 奖励面窄（限客观任务）
代表工作 Cobbe et al. 2021 Let's Verify Step by Step (2305.20050)、Math-Shepherd (2312.08935) Tulu 3、R1

过程监督的思想源自 Lightman 等人的 Let's Verify Step by Step（arXiv:2305.20050，ICLR 2024）：逐步标注在数学推理上显著优于只看结果；Math-Shepherd 与 OmegaPRM（arXiv:2406.06592）随后用蒙特卡洛 rollout 自动构造步骤标签，绕开昂贵的人工逐题标注。不过需要如实交代 2025 年以来的"冷思考"：多个公开复现（含 Qwen 团队 arXiv:2501.07301）指出蒙特卡洛式步骤标签噪声大、PRM 在大规模训练中的增益不稳定，因此截至本篇更新（2026-08），主力方案仍是以 RLVR 规则奖励为主、PRM 更多用于测试时筛选与数据过滤。

Agentic RL：从单轮生成到多轮智能体

RLVR 与推理模型 RL 解决的是"单轮内把一道题想清楚"；Agentic RL 则把 RL 目标进一步推向真实任务：智能体在多轮交互中使用工具、观察反馈、跨回合累积信用——搜索问答中发起检索、编程任务中读写仓库并跑测试、GUI 任务中操作浏览器。它与 RLVR 是继承关系：奖励通常仍是任务级的可验证结果（测试是否通过、任务是否完成），但决策结构从一次生成变成了一条带分支的状态-动作轨迹。

这一步跨越带来四个新的技术挑战：

  • 轨迹级信用分配：回合级奖励落在几十次工具调用的长轨迹上，GAE/优势估计必须横跨多轮上下文，比单轮逐 token 困难得多；
  • 环境非平稳且部分可观测：工具返回值、文件系统状态都是环境状态的一部分，转移函数无法枚举，只能靠大规模 rollout 经验逼近；
  • 采样成本高企：真实环境交互（跑测试、操作浏览器）远慢于纯文本生成，吞吐瓶颈从 GPU 转移到环境侧，催生了异步 rollout 架构；
  • 奖励设计回归中心舞台：哪些中间信号可以安全给分而不被黑客，直接决定训练成败。

公开可查的代表工作包括：Search-R1（arXiv:2503.09516）训练模型交错调用搜索引擎完成推理问答；Meta 的 SWE-RL（arXiv:2502.18449）用软件工程任务数据做 RL 提升真实代码修复能力；各类 tool-use RL 工作（ReTool 等）覆盖代码解释器调用场景。基础设施层面，veRL/HybridFlow（arXiv:2409.19256）、OpenRLHF、TRL 等开源框架提供了多轮 rollout 与训练解耦的工程底座，是上述工作普遍依赖的工具链。

截至本篇更新（2026-08），从各家公开报告与综述（如 2025 年发表的 agentic RL 综述）可以归纳出的行业趋势是：前沿实验室的后训练重心正从单轮推理向长程智能体任务扩展；高质量可验证的训练环境取代算力成为最稀缺的资源，"环境工程"被提升为一等学科；让模型从自身经验中持续改进（experience-driven learning）是公认的下一阶段主线。这些属于趋势性判断，具体进展以最新公开文献为准。

从 InstructGPT 到 R1 再到智能体训练，强化学习在大模型中的角色一路加重。可以相对稳妥地总结：单轮偏好对齐技术已趋于成熟并广泛产品化；能力前沿的竞争集中在可验证奖励驱动的推理与智能体训练上；而如何为更长程的任务构建可信奖励与高保真环境、防范更高级的奖励黑客，仍是这个方向最活跃的研究前线。
