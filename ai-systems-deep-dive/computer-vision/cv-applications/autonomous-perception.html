自动驾驶感知

核心概念

自动驾驶感知系统是自动驾驶汽车的"眼睛"，负责感知车辆周围环境中的道路、车辆、行人、交通标志等关键要素。感知系统需要在极端天气、复杂光照和高速运动等条件下保持稳定可靠，其输出直接影响下游的预测和规划模块，对行车安全至关重要。

自动驾驶感知系统通常融合多种传感器：相机提供丰富的语义和纹理信息，激光雷达提供精确的三维几何信息，毫米波雷达在恶劣天气下仍能工作。多传感器融合在鸟瞰图（BEV）统一表示空间中进行，已经成为当前的主流范式。

BEV 感知架构
BEV（Bird's Eye View）感知将多个传感器的数据统一到鸟瞰图表示空间中进行处理。BEV 表示具有天然优势：在 BEV 空间中目标没有遮挡问题，尺度一致（近大远小的透视效应消失），且多传感器的数据可以自然对齐。


从相机图像到 BEV 特征的转换是 BEV 感知的核心挑战。LSS（Lift-Splat-Shoot）通过在深度维度上显式分布图像特征来完成投影：对每个图像像素预测其深度分布，然后将特征"提升"到三维空间再"铺展"到 BEV 网格上。


import torch
import torch.nn as nn

class LSSTransform(nn.Module):
    def __init__(self, in_channels, depth_bins=59):
        super().__init__()
        self.depth_net = nn.Sequential(
            nn.Conv2d(in_channels, in_channels, 3, padding=1),
            nn.BatchNorm2d(in_channels),
            nn.ReLU(),
            nn.Conv2d(in_channels, depth_bins + in_channels, 1),
        )
        self.depth_bins = depth_bins

    def forward(self, image_features, intrinsics, extrinsics):
        depth_logits = self.depth_net(image_features)
        depth = depth_logits[:, :self.depth_bins].softmax(dim=1)
        context = depth_logits[:, self.depth_bins:]
        volume = depth.unsqueeze(1) * context.unsqueeze(2)
        return volume
BEVFormer 使用可变形注意力（Deformable Attention）从多相机图像中查询 BEV 空间的特征。它在 BEV 网格上放置可学习的 queries，每个 query 通过投影关系在对应的图像区域上进行注意力采样。BEVFormer 还引入了时序自注意力，将当前帧的 BEV 特征与前几帧的 BEV 特征进行融合，增强了对运动目标的感知能力。


占据网络与三维场景表示
占据网络（Occupancy Network）是自动驾驶感知的新范式。传统的 3D 检测以边界框表示目标，无法精确描述不规则形状的物体和通用障碍物。占据网络将三维空间划分为细粒度的体素网格，预测每个体素的占据状态和语义类别，提供了更完整的三维场景理解。


import torch
import torch.nn as nn

class OccupancyHead(nn.Module):
    def __init__(self, bev_channels, num_classes, z_bins=16):
        super().__init__()
        self.z_expand = nn.Sequential(
            nn.Conv2d(bev_channels, bev_channels * z_bins, 1),
        )
        self.sem_head = nn.Sequential(
            nn.Conv3d(bev_channels, 128, 3, padding=1),
            nn.BatchNorm3d(128),
            nn.ReLU(),
            nn.Conv3d(128, num_classes, 1),
        )
        self.z_bins = z_bins

    def forward(self, bev_features):
        b, c, h, w = bev_features.shape
        volume = self.z_expand(bev_features)
        volume = volume.view(b, c, self.z_bins, h, w)
        semantic = self.sem_head(volume)
        return semantic
Occ3D 和 SurroundOcc 是占据预测的代表方法。它们将多相机 BEV 特征扩展到三维体素空间，预测每个体素的语义类别（包括空闲空间）。占据网络在 nuScenes 的 Occ3D 基准和 Waymo 的占据预测挑战中展现出了巨大的潜力。

端到端自动驾驶
端到端自动驾驶将感知、预测和规划统一到一个神经网络中，直接从传感器输入输出驾驶决策（方向盘角度、油门、刹车）。这种方法避免了传统模块化系统中各模块间的信息丢失和误差累积。


UniAD（Unified Autonomous Driving）是端到端自动驾驶的标志性工作。它在统一的 Transformer 架构中依次执行检测、追踪、在线建图、运动预测和规划五大任务，任务间通过查询传递（query-based）机制共享信息。每个下游任务都能利用上游任务的输出作为输入，形成了信息流的级联增强。


import torch
import torch.nn as nn

class EndToEndPlanner(nn.Module):
    def __init__(self, bev_channels, num_waypoints=6):
        super().__init__()
        self.bev_encoder = nn.Sequential(
            nn.Conv2d(bev_channels, 256, 3, padding=1),
            nn.ReLU(),
            nn.Conv2d(256, 128, 3, padding=1),
            nn.ReLU(),
            nn.AdaptiveAvgPool2d(1),
        )
        self.command_embed = nn.Embedding(3, 64)
        self.planner = nn.Sequential(
            nn.Linear(128 + 64, 256),
            nn.ReLU(),
            nn.Linear(256, num_waypoints * 2),
        )

    def forward(self, bev_features, command):
        bev_feat = self.bev_encoder(bev_features).flatten(1)
        cmd_feat = self.command_embed(command)
        combined = torch.cat([bev_feat, cmd_feat], dim=1)
        waypoints = self.planner(combined)
        return waypoints.view(-1, 6, 2)
VAD（Vectorized Scene Representation for Efficient Autonomous Driving）使用矢量化场景表示，将道路元素（车道线、交通标志）表示为有序点集，避免了稠密 BEV 栅格的高计算成本。DriveVLM 引入了大型视觉-语言模型来增强对复杂驾驶场景的理解和推理能力。


小结
    

  • BEV 感知是自动驾驶感知的主流范式，统一了多传感器在鸟瞰空间的融合
    • 

  • LSS 和 BEVFormer 是相机到 BEV 转换的两大技术路线
    • 

  • 占据网络提供了比 3D 检测框更精细的三维场景理解
    • 

  • 端到端自动驾驶通过统一架构避免了模块间的信息丢失
    • 

  • UniAD 展示了感知-预测-规划联合训练的巨大潜力
    • 

  • 自动驾驶感知系统的可靠性和安全性是工程化的核心挑战
