序列推荐模型

核心概念

序列推荐模型（Sequential Recommendation Models）通过建模用户的历史行为序列来捕捉用户兴趣的动态演化，从而更精准地预测用户的下一步行为。与传统协同过滤把用户行为视为无序集合不同，序列推荐明确利用行为的时间顺序信息，能够捕捉短期兴趣漂移、周期性行为模式和长期偏好。从早期的马尔可夫链到 RNN、CNN，再到当前主流的 Transformer 自注意力架构，序列推荐模型不断突破对序列信息的建模能力。

基于 RNN 的序列建模
GRU4Rec 是最早将循环神经网络应用于会话推荐的里程碑模型。它将用户的一次会话（session）中的点击序列建模为时间序列问题，通过 GRU 隐状态来编码用户的实时兴趣。GRU4Rec 的关键创新包括：基于 session 的小批量并行训练策略（session-parallel mini-batches）、基于排序的损失函数（BPR Loss 和 TOP1 Loss）以及负采样策略。


interface GRU4RecConfig {
  readonly embeddingDim: number;
  readonly hiddenDim: number;
  readonly numLayers: number;
  readonly dropoutRate: number;
  readonly lossType: 'bpr' | 'top1' | 'cross-entropy';
}

interface SessionBatch {
  readonly sessionIds: ReadonlyArray<string>;
  readonly itemSequences: ReadonlyArray<ReadonlyArray<number>>;
  readonly timestamps: ReadonlyArray<ReadonlyArray<number>>;
}

const createSessionParallelBatches = (
  sessions: ReadonlyArray<SessionBatch>,
  batchSize: number,
): ReadonlyArray<SessionBatch> => {
  const sortedSessions = [...sessions].sort((a, b) => a.itemSequences[0].length - b.itemSequences[0].length);

  const batches: SessionBatch[] = [];
  for (let i = 0; i < sortedSessions.length; i += batchSize) {
    batches.push({
      sessionIds: sortedSessions.slice(i, i + batchSize).flatMap((s) => s.sessionIds),
      itemSequences: sortedSessions.slice(i, i + batchSize).flatMap((s) => s.itemSequences),
      timestamps: sortedSessions.slice(i, i + batchSize).flatMap((s) => s.timestamps),
    });
  }
  return batches;
};
RNN 系列模型的局限在于：梯度消失导致长序列建模困难、顺序计算无法并行化、隐状态难以显式解释。后续的改进方向包括引入注意力机制（NARM）和数据增强（Data Augmentation for Session-based Rec），但根本性的架构突破要等到 Transformer 的引入。


自注意力序列推荐
SASRec（Self-Attentive Sequential Recommendation）将 Transformer 的单向自注意力机制引入序列推荐，成为当前序列推荐研究的基准模型。SASRec 使用因果掩码（causal mask）确保每个位置只关注其左侧的历史行为，结合可学习的位置编码捕捉行为的时序关系。


interface SASRecConfig {
  readonly maxSeqLen: number;
  readonly numItems: number;
  readonly embeddingDim: number;
  readonly numHeads: number;
  readonly numBlocks: number;
  readonly dropoutRate: number;
}

interface AttentionBlock {
  readonly multiHeadAttention: {
    readonly queryWeight: ReadonlyArray<ReadonlyArray<number>>;
    readonly keyWeight: ReadonlyArray<ReadonlyArray<number>>;
    readonly valueWeight: ReadonlyArray<ReadonlyArray<number>>;
  };
  readonly feedForward: {
    readonly w1: ReadonlyArray<ReadonlyArray<number>>;
    readonly w2: ReadonlyArray<ReadonlyArray<number>>;
  };
  readonly layerNorm1: { readonly gamma: ReadonlyArray<number>; readonly beta: ReadonlyArray<number> };
  readonly layerNorm2: { readonly gamma: ReadonlyArray<number>; readonly beta: ReadonlyArray<number> };
}

const computeCausalMask = (seqLen: number): ReadonlyArray<ReadonlyArray<boolean>> => {
  return Array.from({ length: seqLen }, (_, i) => Array.from({ length: seqLen }, (_, j) => j <= i));
};

const computeSelfAttention = (
  queries: ReadonlyArray<ReadonlyArray<number>>,
  keys: ReadonlyArray<ReadonlyArray<number>>,
  values: ReadonlyArray<ReadonlyArray<number>>,
  mask: ReadonlyArray<ReadonlyArray<boolean>>,
  dk: number,
): ReadonlyArray<ReadonlyArray<number>> => {
  const scores = queries.map((q, i) =>
    keys.map((k, j) => {
      const dot = q.reduce((sum, val, idx) => sum + val * k[idx], 0);
      return mask[i][j] ? dot / Math.sqrt(dk) : -Infinity;
    }),
  );
  return scores.map((row, i) => {
    const maxScore = Math.max(...row);
    const expScores = row.map((s) => Math.exp(s - maxScore));
    const sumExp = expScores.reduce((a, b) => a + b, 0);
    const weights = expScores.map((e) => e / sumExp);
    return values[0].map((_, d) => weights.reduce((sum, w, j) => sum + w * values[j][d], 0));
  });
};
BERT4Rec 进一步引入双向注意力和完形填空（Cloze Task）训练目标，随机遮盖序列中的物品并预测被遮盖的物品。双向注意力让模型同时利用左右两侧的上下文信息，在离线指标上通常优于 SASRec，但在线部署时需要额外处理因果推理的问题。

轻量级序列模型
尽管 Transformer 在序列推荐中取得了优异效果，其 O(n²) 的注意力复杂度和大量参数在移动端和长序列场景下面临挑战。轻量级序列模型旨在以更低的计算开销达到接近甚至超越 Transformer 的效果。


FMLP-Rec 提出用全 MLP 架构替代自注意力。其核心是 Filter-enhanced MLP Block：先在频域对序列表示进行可学习的滤波操作（通过 FFT 和逐元素乘法），再通过 MLP 进行非线性变换。频域滤波天然具有全局感受野，无需显式的注意力计算。


interface FMLPConfig {
  readonly maxSeqLen: number;
  readonly embeddingDim: number;
  readonly numBlocks: number;
  readonly filterSize: number;
  readonly dropoutRate: number;
}

interface FilterBlock {
  readonly complexWeight: {
    readonly real: ReadonlyArray<ReadonlyArray<number>>;
    readonly imag: ReadonlyArray<ReadonlyArray<number>>;
  };
  readonly mlp: {
    readonly w1: ReadonlyArray<ReadonlyArray<number>>;
    readonly w2: ReadonlyArray<ReadonlyArray<number>>;
  };
}

const applyFrequencyFilter = (
  sequenceEmb: ReadonlyArray<ReadonlyArray<number>>,
  filterWeight: FilterBlock['complexWeight'],
): ReadonlyArray<ReadonlyArray<number>> => {
  const seqLen = sequenceEmb.length;
  const dim = sequenceEmb[0].length;
  const filtered = sequenceEmb.map((row, i) =>
    row.map((val, d) => {
      const realPart = val * filterWeight.real[i % filterWeight.real.length][d];
      const imagPart = val * filterWeight.imag[i % filterWeight.imag.length][d];
      return Math.sqrt(realPart * realPart + imagPart * imagPart);
    }),
  );
  return filtered;
};
LinRec 和 ETA（Efficient Target Attention）等方法通过线性近似注意力或局部哈希加速来降低 Transformer 的计算开销。工业界通常采用混合策略：短序列用标准 Transformer，长序列用分段注意力或兴趣聚类。


工业部署与工程优化
序列推荐模型的工业部署需要解决几个核心工程问题：实时序列更新、长序列高效推理和模型在线服务。


实时序列更新方面，用户的每次行为都需要实时追加到行为序列中，Kafka + Flink 是典型的流式管道方案。序列存储通常使用 Redis 的 List 结构或专用序列数据库，按用户 ID 分片并设置合理的 TTL 和最大长度。


interface SequenceStore {
  readonly maxSeqLen: number;
  readonly ttlSeconds: number;
}

interface UserAction {
  readonly userId: string;
  readonly itemId: number;
  readonly actionType: 'click' | 'purchase' | 'like';
  readonly timestamp: number;
}

const appendUserAction = (
  store: SequenceStore,
  action: UserAction,
): { readonly sequence: ReadonlyArray<number>; readonly truncated: boolean } => {
  const currentSeq = getUserSequence(action.userId);
  const newSeq = [...currentSeq, action.itemId];
  const truncated = newSeq.length > store.maxSeqLen;
  const finalSeq = truncated ? newSeq.slice(newSeq.length - store.maxSeqLen) : newSeq;
  return { sequence: finalSeq, truncated };
};

const getUserSequence = (userId: string): ReadonlyArray<number> => {
  return [];
};

interface InferenceOptimization {
  readonly strategy: 'kv-cache' | 'incremental' | 'batch-prefill';
  readonly cacheHitRate: number;
  readonly latencyMs: number;
}

const selectInferenceStrategy = (seqLen: number, latencyBudget: number): InferenceOptimization['strategy'] => {
  if (seqLen <= 50) return 'batch-prefill';
  if (seqLen <= 200) return 'kv-cache';
  return 'incremental';
};
KV Cache 是 Transformer 序列推荐在线推理的核心优化：当新行为追加到序列末尾时，无需重新计算整个序列的注意力，只需复用已缓存的 Key-Value 矩阵，仅计算新 token 的注意力输出，将推理复杂度从 O(n²) 降为 O(n)。


小结
    

  • 序列推荐模型通过显式建模行为时序来捕捉用户兴趣的动态演化
    • 

  • GRU4Rec 开创了深度序列推荐，但 RNN 架构在长序列和并行化上存在瓶颈
    • 

  • SASRec 和 BERT4Rec 将 Transformer 引入序列推荐，分别代表自回归和双向掩码两种范式
    • 

  • 轻量级模型（FMLP-Rec、LinRec）通过频域滤波或线性近似降低计算开销
    • 

  • 工业部署需要解决实时序列更新、KV Cache 推理和长序列处理三大工程问题
    • 

  • 未来方向包括超长序列建模（万级行为）、多模态序列融合和因果序列推荐
    •
