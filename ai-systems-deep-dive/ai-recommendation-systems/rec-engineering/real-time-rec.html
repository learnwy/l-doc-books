实时推荐与特征服务

核心概念

实时推荐（Real-time Recommendation）是指在用户发生行为后的毫秒到秒级时间内，将该行为反映到推荐结果中的能力。传统离线推荐系统每天或每小时更新一次模型和特征，无法捕捉用户的实时兴趣变化。实时推荐通过流式特征计算、在线模型推理和实时索引更新三大技术支柱，让推荐系统具备即时响应的能力。

特征服务架构
特征服务（Feature Service / Feature Store）是推荐系统的数据中枢，负责统一管理、存储和服务推荐模型所需的各类特征。一个完整的特征服务需要解决特征注册、存储、计算、服务和监控五大核心问题。


interface FeatureDefinition {
  readonly name: string;
  readonly entity: 'user' | 'item' | 'context' | 'cross';
  readonly dtype: 'float' | 'int' | 'string' | 'vector' | 'list';
  readonly source: 'batch' | 'stream' | 'realtime';
  readonly ttlSeconds: number;
  readonly defaultValue: unknown;
  readonly version: number;
}

interface FeatureStoreConfig {
  readonly onlineStore: {
    readonly type: 'redis' | 'tikv' | 'dynamodb';
    readonly clusterNodes: ReadonlyArray<string>;
    readonly readTimeoutMs: number;
    readonly batchSize: number;
  };
  readonly offlineStore: {
    readonly type: 'hive' | 's3' | 'iceberg';
    readonly path: string;
  };
  readonly streamEngine: {
    readonly type: 'flink' | 'spark-streaming';
    readonly checkpointInterval: number;
  };
}

interface FeatureRequest {
  readonly userId: string;
  readonly itemIds: ReadonlyArray<number>;
  readonly featureNames: ReadonlyArray<string>;
  readonly timestamp: number;
}

interface FeatureResponse {
  readonly userFeatures: ReadonlyMap<string, unknown>;
  readonly itemFeatures: ReadonlyMap<number, ReadonlyMap<string, unknown>>;
  readonly crossFeatures: ReadonlyMap<string, unknown>;
  readonly latencyMs: number;
  readonly missRate: number;
}

const fetchFeatures = async (request: FeatureRequest, config: FeatureStoreConfig): Promise<FeatureResponse> => {
  const startTime = Date.now();
  const misses: string[] = [];

  const userFeatures = new Map<string, unknown>();
  const itemFeatures = new Map<number, Map<string, unknown>>();

  for (const featureName of request.featureNames) {
    const cached = await getFromOnlineStore(request.userId, featureName, config);
    if (cached !== undefined) {
      userFeatures.set(featureName, cached);
    } else {
      misses.push(featureName);
      userFeatures.set(featureName, getDefaultValue(featureName));
    }
  }

  return {
    userFeatures,
    itemFeatures,
    crossFeatures: new Map(),
    latencyMs: Date.now() - startTime,
    missRate: misses.length / request.featureNames.length,
  };
};

const getFromOnlineStore = async (
  entityId: string,
  featureName: string,
  config: FeatureStoreConfig,
): Promise<unknown> => {
  return undefined;
};

const getDefaultValue = (featureName: string): unknown => {
  return 0;
};
特征一致性是特征服务的核心挑战。训练和推理使用不同的特征来源（离线和在线）可能导致 Training-Serving Skew，即模型在线上看到的特征分布与训练时不同，严重影响推荐效果。解决方案是 Feature Logging：将线上推理时的实际特征值记录下来，作为训练样本的特征来源，确保训练和推理使用完全一致的特征。


流式特征计算
流式特征计算基于 Flink 等流处理框架，从 Kafka 消费用户行为事件，实时计算滑动窗口统计特征（如 30 分钟点击次数、1 小时类目偏好分布）并写入在线存储。


interface StreamFeatureJob {
  readonly jobName: string;
  readonly inputTopic: string;
  readonly windows: ReadonlyArray<{
    readonly type: 'sliding' | 'tumbling' | 'session';
    readonly sizeMinutes: number;
    readonly slideMinutes: number;
  }>;
  readonly aggregations: ReadonlyArray<{
    readonly field: string;
    readonly func: 'count' | 'sum' | 'avg' | 'distinct_count' | 'topk';
    readonly outputKey: string;
  }>;
  readonly sinkConfig: {
    readonly store: 'redis' | 'tikv';
    readonly keyPattern: string;
    readonly ttlSeconds: number;
  };
}

interface WindowState {
  readonly windowStart: number;
  readonly windowEnd: number;
  readonly counts: ReadonlyMap<string, number>;
  readonly sums: ReadonlyMap<string, number>;
  readonly distinctSets: ReadonlyMap<string, ReadonlySet<string>>;
}

const computeWindowAggregation = (
  events: ReadonlyArray<{ readonly field: string; readonly value: number; readonly timestamp: number }>,
  windowStart: number,
  windowEnd: number,
): WindowState => {
  const windowEvents = events.filter((e) => e.timestamp >= windowStart && e.timestamp < windowEnd);

  const counts = new Map<string, number>();
  const sums = new Map<string, number>();
  const distinctSets = new Map<string, Set<string>>();

  for (const event of windowEvents) {
    counts.set(event.field, (counts.get(event.field) ?? 0) + 1);
    sums.set(event.field, (sums.get(event.field) ?? 0) + event.value);
    if (!distinctSets.has(event.field)) {
      distinctSets.set(event.field, new Set());
    }
    distinctSets.get(event.field)?.add(String(event.value));
  }

  return { windowStart, windowEnd, counts, sums, distinctSets };
};

在线推理与模型服务
在线推理服务将训练好的模型加载到内存中，接收特征输入并实时返回预测结果。推荐系统的在线推理有严格的延迟和吞吐量要求：精排模型需要在 200ms 内处理上千个候选物品。


模型服务的核心架构是 Model Serving Gateway + Worker Pool 模式。Gateway 负责请求路由、限流和降级，Worker Pool 负责实际的模型推理。GPU Worker 和 CPU Worker 分开管理，精排等计算密集型任务使用 GPU，召回和特征处理使用 CPU。


interface ModelServingConfig {
  readonly modelName: string;
  readonly modelVersion: string;
  readonly runtime: 'tensorflow-serving' | 'triton' | 'onnxruntime' | 'torchserve';
  readonly batchConfig: {
    readonly maxBatchSize: number;
    readonly batchTimeoutMs: number;
    readonly dynamicBatching: boolean;
  };
  readonly resources: {
    readonly gpuType: string;
    readonly gpuCount: number;
    readonly cpuCores: number;
    readonly memoryGb: number;
  };
  readonly scaling: {
    readonly minReplicas: number;
    readonly maxReplicas: number;
    readonly targetQPS: number;
    readonly scaleUpThreshold: number;
  };
}

interface InferenceResult {
  readonly predictions: ReadonlyArray<{
    readonly itemId: number;
    readonly scores: ReadonlyMap<string, number>;
  }>;
  readonly modelVersion: string;
  readonly latencyMs: number;
  readonly batchSize: number;
}

const dynamicBatch = (
  requests: ReadonlyArray<{ readonly itemIds: ReadonlyArray<number> }>,
  config: ModelServingConfig,
): ReadonlyArray<ReadonlyArray<number>> => {
  const allItems = requests.flatMap((r) => [...r.itemIds]);
  const batches: number[][] = [];

  for (let i = 0; i < allItems.length; i += config.batchConfig.maxBatchSize) {
    batches.push(allItems.slice(i, i + config.batchConfig.maxBatchSize));
  }

  return batches;
};
模型热更新是在线推理的重要能力：当新模型训练完成后，需要无损地替换线上运行的旧模型。典型方案是蓝绿部署或灰度切换：先将新模型加载到备用 Worker，通过影子流量验证后逐步切换正式流量。


小结
    

  • 实时推荐通过流式特征计算、在线推理和实时索引更新三大支柱实现毫秒级响应
    • 

  • 特征服务统一管理离线和在线特征，Feature Logging 解决训练-推理一致性问题
    • 

  • 流式特征基于 Flink 滑动窗口计算用户实时行为统计，延迟控制在秒级
    • 

  • 在线推理通过动态批处理、GPU 加速和模型量化满足严格的延迟和吞吐要求
    • 

  • 模型热更新采用蓝绿部署或灰度切换，确保模型迭代不影响线上服务
    • 

  • 监控告警覆盖特征缺失率、推理延迟、模型 AUC 衰减和流量异常四大维度
