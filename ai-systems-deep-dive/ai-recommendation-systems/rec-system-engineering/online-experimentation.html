在线实验与 A/B 测试

核心概念

在线实验（Online Experimentation）是推荐系统验证算法改进效果的金标准。A/B 测试将用户随机分为实验组和对照组，通过比较两组的在线指标差异来判断新策略是否有效。在线实验直接反映真实用户的行为反馈，是离线评估无法替代的。

实验设计与分流
正确的实验设计是在线实验可靠性的基础。关键设计要素包括分流策略、样本量计算和实验时长。

function userBucketAssignment(userId: string, experimentId: string, salt: string, numBuckets: number = 1000): number {
  const hash = murmurhash(`${userId}:${experimentId}:${salt}`);
  return hash % numBuckets;
}

function calculateRequiredSampleSize(
  baselineMetric: number,
  expectedUplift: number,
  alpha: number = 0.05,
  beta: number = 0.2,
): number {
  const delta = baselineMetric * expectedUplift;
  const variance = baselineMetric * (1 - baselineMetric);
  const zAlpha = 1.96;
  const zBeta = 0.84;
  return Math.ceil((2 * variance * (zAlpha + zBeta) ** 2) / delta ** 2);
}
分层实验（Layered Experimentation）允许多个实验同时运行在同一批用户上。通过将流量分为正交的层（Layer），不同层的实验互不干扰。Google 的 Overlapping Experiment Infrastructure 是分层实验的工业标杆。


推荐核心指标体系
推荐系统的在线指标需要覆盖用户体验、商业价值和平台生态三个维度。


分层实验的核心设计是流量正交性。每一层使用不同的哈希盐（Salt），确保同一用户在不同层被独立随机分配到不同实验组。例如，召回层实验和排序层实验位于不同的实验层，同一用户可能在召回层属于实验组，在排序层属于对照组。这种设计使得多个团队可以并行开展实验而互不干扰。

interface ExperimentLayer {
  layerId: string
  salt: string
  experiments: ExperimentConfig[]
  trafficAllocation: Map<string, number>
}

interface MultiLayerSystem {
  layers: ExperimentLayer[]
}

function getLayerAssignment(
  userId: string,
  layer: ExperimentLayer,
): string {
  const bucket = murmurhash(`${userId}:${layer.salt}`) % 1000
  let accumulated = 0
  for (const [experimentId, traffic] of layer.trafficAllocation) {
    accumulated += traffic * 1000
    if (bucket < accumulated) return experimentId
  }
  return 'control'
}

function computeGiniCoefficient(exposures: number[]): number { const sorted = [...exposures].sort((a, b) => a - b); const n = sorted.length; const mean = sorted.reduce((s, v) => s + v, 0) / n; let numerator = 0; for (let i = 0; i < n; i++) { for (let j = 0; j < n; j++) { numerator += Math.abs(sorted[i] - sorted[j]); } } return numerator / (2 _ n _ n * mean); }

## 常见实验陷阱

在线实验中存在多种可能导致错误结论的陷阱，需要仔细识别和避免。

Simpson 悖论：在整体和子群中观察到相反的趋势。例如，新策略整体 CTR 下降，但在每个用户群中 CTR 都上升——这是因为新策略改变了不同用户群的流量占比。新奇效应：用户对新策略的初始反应可能高于或低于长期效果。需要等待足够长的时间让效果稳定。溢出效应：实验组用户的行为可能影响对照组（如社交推荐场景），导致实验效果被低估或高估。

## 小结

- A/B 测试是验证推荐策略改进的金标准，分流正确性和样本量是基础保障
- 分层实验允许多个实验并行运行，是大规模推荐系统的标准实验基础设施
- 推荐指标需覆盖用户体验（CTR、时长）、商业价值（GMV、CVR）和生态健康（覆盖率、基尼系数）
- Simpson 悖论、新奇效应和溢出效应是常见的实验陷阱，需要通过正确的实验设计来规避
- 实验决策应基于主要指标的统计显著性和护栏指标的安全性综合判断
