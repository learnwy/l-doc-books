召回策略

核心概念

召回（Recall/Retrieval）是推荐系统级联架构的第一阶段，从百万甚至亿级的全量物品库中快速筛选出千级候选集。召回的核心目标是在极低延迟内保证高召回率——确保用户可能感兴趣的物品不被遗漏。召回质量直接决定了后续排序阶段的性能上界。

基于向量的召回
向量召回使用深度学习模型将用户和物品编码为稠密向量，通过 ANN（近似最近邻）搜索找到与用户向量最相似的物品向量。双塔模型（Two-Tower Model）是向量召回的标准架构。


interface TwoTowerModel {
  userTower: MLPLayer[];
  itemTower: MLPLayer[];
  embeddingDim: number;
  temperature: number;
}

function userTowerForward(userFeatures: Float32Array, tower: MLPLayer[]): Float32Array {
  let hidden = userFeatures;
  for (const layer of tower) {
    hidden = relu(addVec(matVecMul(layer.weight, hidden), layer.bias));
  }
  return l2Normalize(hidden);
}

function itemTowerForward(itemFeatures: Float32Array, tower: MLPLayer[]): Float32Array {
  let hidden = itemFeatures;
  for (const layer of tower) {
    hidden = relu(addVec(matVecMul(layer.weight, hidden), layer.bias));
  }
  return l2Normalize(hidden);
}

interface VectorRecallConfig {
  indexType: 'hnsw' | 'ivf_pq';
  topK: number;
  efSearch: number;
  nprobe: number;
}

async function vectorRecall(
  userEmbedding: Float32Array,
  index: ANNIndex,
  config: VectorRecallConfig,
): Promise<Array<{ itemId: string; score: number }>> {
  return index.search(userEmbedding, config.topK);
}
双塔模型的训练通常采用 Sampled Softmax 或 In-Batch Negatives 策略。关键挑战包括：样本选择偏差（点击数据不等于用户偏好）、曝光偏差校正（用户只看到了被推荐的物品）和负样本策略（随机负采样 vs 困难负采样的权衡）。


Swing 与 I2I 召回
I2I（Item-to-Item）召回基于物品之间的相似度进行推荐：用户历史交互的物品的相似物品构成候选集。Swing 是阿里巴巴提出的一种改进的 I2I 相似度计算方法。


interface SwingConfig {
| 负采样策略 | 方法 | 优势 | 劣势 | 适用阶段 |
|-----------|------|------|------|---------|
| 随机负采样 | 全局随机采样物品 | 简单高效 | 过于简单，区分度低 | 训练初期 |
| In-Batch Negatives | 同 batch 内其他样本 | 无额外开销 | 受 batch 大小限制 | 通用 |
| 困难负采样 | 采样排名靠前的负样本 | 区分度高 | 可能引入假负例 | 训练后期 |
| 混合负采样 | 随机 + 困难按比例混合 | 兼顾效率和难度 | 超参数需调优 | 工业实践 |

ANN（近似最近邻）索引的选择直接影响向量召回的在线性能。HNSW（Hierarchical Navigable Small World）在低延迟高召回率场景表现最优，是当前工业界的主流选择；IVF-PQ（Inverted File + Product Quantization）在内存受限场景更有优势，通过向量量化将存储开销压缩 10-50 倍。Faiss 和 Milvus 是最常用的 ANN 检索引擎。

  alpha: number;
  topK: number;
  minSupport: number;
}

function swingSimilarity(
  item1: string,
  item2: string,
  userItems: Map<string, Set<string>>,
  config: SwingConfig,
): number {
  const users1 = new Set<string>();
  const users2 = new Set<string>();

  for (const [userId, items] of userItems) {
    if (items.has(item1)) users1.add(userId);
    if (items.has(item2)) users2.add(userId);
  }

  const commonUsers = [...users1].filter((u) => users2.has(u));
  if (commonUsers.length < config.minSupport) return 0;

  let score = 0;
  for (let i = 0; i < commonUsers.length; i++) {
    for (let j = i + 1; j < commonUsers.length; j++) {
      const userI = commonUsers[i];
      const userJ = commonUsers[j];
      const commonCount = [...userItems.get(userI)!].filter((item) => userItems.get(userJ)!.has(item)).length;
      score += 1 / (commonCount + config.alpha);
    }
  }

  return score;
}
Swing 的核心思想是：如果两个物品被共同交互的用户对之间重叠较少（即这些用户的兴趣比较独特），那么这两个物品的相似度应该更高。这种设计惩罚了活跃用户对相似度计算的过大影响。


多路召回融合与配额分配
多路召回的配额分配直接影响推荐效果。每路召回的配额需要根据其对最终推荐效果的贡献来动态调整。

召回通道之间的重合度也是重要的监控指标。如果两个通道的重合度过高，说明它们覆盖了相似的物品空间，应该考虑合并或调整。


小结
    

  • 召回是推荐系统的第一阶段，从全量物品中快速筛选候选集，核心目标是高召回率和低延迟
    • 

  • 向量召回（双塔模型 + ANN）是最主流的泛化召回方法，能捕获语义层面的用户-物品匹配
    • 

  • Swing 改进了 I2I 相似度计算，惩罚活跃用户的过大影响，提升长尾物品的召回
    • 

  • 多路召回覆盖不同推荐维度，配额分配需要基于效果贡献动态优化
    • 

  • 召回质量是排序效果的上界，召回阶段遗漏的物品无法在后续阶段被补回
    •
