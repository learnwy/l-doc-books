文本到音频生成

核心概念

文本到音频生成涵盖语音合成（Text-to-Speech, TTS）、音乐生成和通用音频效果生成三个子领域。音频信号是一维时序数据，采样率通常为 16kHz-48kHz，这意味着一秒钟的音频包含数万个采样点。音频生成模型需要在极长的序列上保持连贯性和自然度，同时处理音色、节奏、旋律等多层次的结构信息。

graph TD
    A[文本到音频] --> B[语音合成 TTS]
    A --> C[音乐生成]
    A --> D[音频效果]
    B --> E[WaveNet / Tacotron]
    B --> F[VITS / Bark]
    B --> K[CosyVoice / Kokoro 等 LLM-TTS]
    C --> G[MusicLM / MusicGen]
    C --> H[Stable Audio]
    D --> I[AudioLDM]
    D --> J[Make-An-Audio]

音频生成的技术演进经历了从参数合成到神经网络合成、从自回归到并行生成、从特定任务到通用生成的三次范式转换。2024 年以来第四次转换正在发生：以大语言模型为骨干的语音合成（LLM-TTS）把零样本音色克隆、流式低延迟和情感可控变成行业标配，详见下文专门小节。

模型 任务 架构 音频表示 采样率 核心创新
WaveNet TTS 自回归 CNN 波形 24kHz 因果膨胀卷积
Tacotron 2 TTS 编码器-解码器 梅尔频谱 22kHz 注意力对齐
VITS TTS VAE + Flow 波形 22kHz 端到端
Bark 通用语音 自回归 Transformer 语义 token 24kHz 多级 token

音频表示与特征编码

音频生成模型的第一个设计决策是选择合适的音频表示。原始波形保留了完整信息但维度极高，梅尔频谱图（Mel Spectrogram）通过时频变换将波形压缩为二维图像表示，离散音频 token 通过神经编解码器（如 EnCodec、SoundStream）将音频压缩为离散符号序列。

梅尔频谱图将音频信号通过短时傅里叶变换（STFT）转化为时频表示，再通过梅尔滤波器组压缩频率轴。典型配置为 80 个梅尔频带、512-1024 的 FFT 窗口大小，产生的频谱图可以视为单通道图像，直接使用图像生成模型的技术栈进行处理。从梅尔频谱还原波形需要声码器（Vocoder），如 HiFi-GAN。

import torch
import torchaudio

class AudioProcessor:
    def __init__(self, sample_rate=22050, n_mels=80, n_fft=1024, hop_length=256):
        self.sample_rate = sample_rate
        self.mel_transform = torchaudio.transforms.MelSpectrogram(
            sample_rate=sample_rate, n_mels=n_mels,
            n_fft=n_fft, hop_length=hop_length,
        )
        self.amplitude_to_db = torchaudio.transforms.AmplitudeToDB()

    def waveform_to_mel(self, waveform):
        mel = self.mel_transform(waveform)
        mel_db = self.amplitude_to_db(mel)
        return mel_db

    def normalize_mel(self, mel_db, min_db=-80.0, max_db=0.0):
        return (mel_db - min_db) / (max_db - min_db) * 2 - 1

class EnCodecTokenizer:
    def __init__(self, bandwidth=6.0):
        self.model = torchaudio.models.EnCodec(bandwidth=bandwidth)

    def encode(self, waveform):
        with torch.no_grad():
            codes = self.model.encode(waveform.unsqueeze(0))
        return codes

    def decode(self, codes):
        with torch.no_grad():
            waveform = self.model.decode(codes)
        return waveform.squeeze(0)

EnCodec 和 SoundStream 是基于残差向量量化（RVQ）的神经音频编解码器。它们将 24kHz 音频压缩为多层离散 token——第一层编码最粗粒度的信息，后续层逐步添加细节。这种层次化表示天然适合自回归生成：先生成粗粒度 token 确定基本结构，再生成细粒度 token 补充细节。

语音合成与端到端 TTS

现代 TTS 系统已经从级联架构（文本分析→声学模型→声码器）演进到端到端架构。VITS（Variational Inference with adversarial learning for end-to-end Text-to-Speech）将变分推断、标准化流和 GAN 训练结合，直接从文本生成波形，实现了自然度接近人类的语音合成。

graph LR
    subgraph VITS 架构

        TE --> PRIOR[先验编码器]
        PRIOR --> FLOW[标准化流]
        FLOW --> Z[隐变量 z]
        Z --> DEC[HiFi-GAN 解码器]
        DEC --> WAV[波形]
    end
    subgraph 训练时
        WAV2[真实波形] --> PE[后验编码器]
        PE --> Z2[隐变量 z]
    end

Bark 和 VALL-E 代表了基于语言模型的 TTS 新范式。它们将语音视为另一种"语言"，用自回归 Transformer 生成音频 token 序列。VALL-E 只需 3 秒的参考语音即可克隆说话人的音色，生成任意文本的语音。这种方法的优势是灵活性和泛化能力，但也带来了语音深度伪造的伦理风险。

LLM-TTS 浪潮：语音合成的大模型化（2024–2026）

VALL-E 指出的方向在 2024 年后成为整个行业的默认路线：语音合成的骨干从专门的声学模型换成大语言模型，业界俗称 LLM-TTS。其标准配方由三段构成：

graph LR
    TXT[文本] --> NORM[文本正则化]
    REF[秒级参考音频] --> TOK[音频 tokenizer]
    TOK --> SEM[语义 token 提取]
    NORM --> LLM[LLM 骨干自回归生成]
    SEM --> LLM
    LLM --> ACO[声学 token / 流匹配解码]
    ACO --> VOC[声码器还原波形]
    VOC --> OUT[克隆音色语音]

第一段是音频 tokenizer。RVQ 类编解码器把波形压缩为多层离散 token，逐层量化残差：

rt(0)=xt,rt(k)=rt(k−1)−Qk ⁣(rt(k−1)),ct(k)=Qk ⁣(rt(k−1))r_t^{(0)} = x_t, \qquad r_t^{(k)} = r_t^{(k-1)} - Q_k\!\left(r_t^{(k-1)}\right), \qquad c_t^{(k)} = Q_k\!\left(r_t^{(k-1)}\right)rt(0)​=xt​,rt(k)​=rt(k−1)​−Qk​(rt(k−1)​),ct(k)​=Qk​(rt(k−1)​)

其中 QkQ_kQk​ 是第 kkk 层码本，ct(k)c_t^{(k)}ct(k)​ 为该层 token。另一派走单码本路线（如 Spark-TTS 的 BiCodec），用单一 token 流换取 LLM 建模的简洁性。第二段是以预训练 LLM 为骨干的自回归生成——参考音频的 token 作为前缀拼入上下文，模型由此实现零样本音色与韵律克隆，这正是「LLM 化」的含义：说话人身份不再需要显式建模，而是变成 in-context 学习问题。第三段是把 token 还原为波形的流匹配或扩散头。

相比 VITS/Bark 时代，这轮浪潮带来三项可量化的能力跃迁：

  • 零样本克隆成为标配：数秒参考音频即可复刻音色，无需逐说话人微调；
  • 流式低延迟：CosyVoice 2（阿里 FunAudioLLM，论文 arXiv:2412.10117）报告首包延迟约 150ms 量级，达到准实时对话水平；
  • 副语言学可控：笑声、呼吸、停顿、情绪标签进入文本接口，情感与方言控制从研究演示走向产品功能。

音乐生成与 MusicGen

MusicGen 是 Meta 开发的基于 Transformer 的音乐生成模型。它使用 EnCodec 将音乐编码为多层离散 token，然后用单个自回归 Transformer 以特殊的延迟模式（delay pattern）同时生成多个量化层的 token。延迟模式通过在不同量化层之间引入固定的时间偏移，使得一个 Transformer 可以并行建模多层 token 之间的依赖关系。

from transformers import AutoProcessor, MusicgenForConditionalGeneration
import torch

processor = AutoProcessor.from_pretrained("facebook/musicgen-small")
model = MusicgenForConditionalGeneration.from_pretrained("facebook/musicgen-small")

inputs = processor(
    text=["cheerful acoustic guitar melody with gentle drums"],
    padding=True, return_tensors="pt",
)

audio_values = model.generate(**inputs, max_new_tokens=256, do_sample=True, temperature=1.0)
sampling_rate = model.config.audio_encoder.sampling_rate
print(f"Generated {audio_values.shape[-1] / sampling_rate:.1f}s audio at {sampling_rate}Hz")

AudioLDM 将隐空间扩散模型应用于音频生成。它使用 VAE 将梅尔频谱压缩到隐空间，然后在隐空间中执行文本条件扩散。AudioLDM 2 引入了"音频语言"概念——先用语言模型生成音频的语义表示（AudioMAE 特征），再用扩散模型在该语义表示条件下生成梅尔频谱。这种两阶段设计在保持生成质量的同时提升了文本-音频对齐精度。

音乐模型 架构 条件 音质 多样性 可控性

MusicLM 层次化自回归 文本 高 中 中
Stable Audio 隐空间扩散 文本+时长 极高 高 高
