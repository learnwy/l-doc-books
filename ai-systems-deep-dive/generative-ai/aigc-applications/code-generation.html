代码生成

核心概念

AI 代码生成是生成式 AI 对软件工程影响最直接的应用方向。从简单的代码补全到完整函数生成，从自然语言到代码的翻译到代码库级别的重构，AI 正在改变开发者编写代码的方式。代码生成模型的核心是在海量代码语料上预训练的大型语言模型，结合代码理解和推理能力来生成语法正确、语义准确且风格一致的代码。

代码生成与自然语言生成有本质区别：代码有严格的语法约束，必须能够编译和执行；代码有明确的功能性正确性标准，可以通过测试验证；代码的上下文依赖更为复杂，涉及类型系统、API 约定和项目级别的架构模式。

代码补全与上下文理解
代码补全是最基础也是使用频率最高的代码生成能力。现代代码补全系统不仅根据当前文件的上下文预测接下来的代码，还需要理解项目级别的依赖关系、API 约定和编码风格。GitHub Copilot 是这一领域的标杆产品，它基于 OpenAI Codex 模型在编辑器中提供实时补全建议。


import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

class CodeCompleter:
    def __init__(self, model_name="bigcode/starcoder2-7b"):
        self.tokenizer = AutoTokenizer.from_pretrained(model_name)
        self.model = AutoModelForCausalLM.from_pretrained(
            model_name, torch_dtype=torch.float16, device_map="auto"
        )

    def complete(self, code_prefix, max_new_tokens=256, temperature=0.2):
        inputs = self.tokenizer(code_prefix, return_tensors="pt").to(self.model.device)
        with torch.no_grad():
            outputs = self.model.generate(
                **inputs,
                max_new_tokens=max_new_tokens,
                temperature=temperature,
                top_p=0.95,
                do_sample=True,
                pad_token_id=self.tokenizer.eos_token_id,
            )
        generated = outputs[0][inputs["input_ids"].shape[1]:]
        return self.tokenizer.decode(generated, skip_special_tokens=True)

    def fill_in_middle(self, prefix, suffix, max_new_tokens=128):
        prompt = f"<fim_prefix>{prefix}<fim_suffix>{suffix}<fim_middle>"
        inputs = self.tokenizer(prompt, return_tensors="pt").to(self.model.device)
        with torch.no_grad():
            outputs = self.model.generate(**inputs, max_new_tokens=max_new_tokens, temperature=0.2)
        generated = outputs[0][inputs["input_ids"].shape[1]:]
        return self.tokenizer.decode(generated, skip_special_tokens=True)
Fill-in-the-Middle（FIM）是代码补全的关键训练策略。传统的自回归模型只能根据前缀预测后续内容，而 FIM 训练使模型能够根据前缀和后缀预测中间的代码。这对于实际编辑场景至关重要——开发者的光标通常位于已有代码的中间位置。StarCoder 和 CodeLlama 都支持 FIM 补全。


上下文窗口的大小直接限制了代码补全的质量。早期模型的 2K-4K token 窗口只能看到当前文件的一部分，而现代模型的 128K+ 窗口可以包含多个相关文件的内容。Retrieval-Augmented Generation（RAG）进一步通过检索项目中的相关代码片段来增强上下文，使补全建议更符合项目的特定约定和模式。


代码 Agent 与自动化开发
代码 Agent 将代码生成从被动的补全升级为主动的任务执行。Agent 接收高层次的任务描述（如"为这个 API 添加分页功能"），自主规划实现步骤，编写代码，运行测试，修复错误，直到任务完成。这种模式将 AI 从"编辑器插件"升级为"虚拟开发者"。


class CodeAgent:
    def __init__(self, llm, tools):
        self.llm = llm
        self.tools = tools

    def plan(self, task_description, codebase_context):
        prompt = f"""Task: {task_description}
Context: {codebase_context}
Create a step-by-step plan to implement this task."""
        return self.llm.generate(prompt)

    def execute_step(self, step, current_code):
        prompt = f"""Step: {step}
Current code:
{current_code}
Write the code to implement this step."""
        new_code = self.llm.generate(prompt)
        return new_code

    def run_tests(self, code):
        result = self.tools["test_runner"].run(code)
        return result

    def fix_errors(self, code, error_message):
        prompt = f"""Code:
{code}
Error:
{error_message}
Fix the error and return the corrected code."""
        return self.llm.generate(prompt)

    def execute_task(self, task, context, max_retries=3):
        plan = self.plan(task, context)
        code = context
        for step in plan:
            code = self.execute_step(step, code)
            test_result = self.run_tests(code)
            retries = 0
            while not test_result.passed and retries < max_retries:
                code = self.fix_errors(code, test_result.error)
                test_result = self.run_tests(code)
                retries += 1
        return code

代码 Agent 的核心挑战是可靠性。在简单任务上，Agent 可以端到端地完成工作；但在复杂任务上，错误会在规划、实现和调试的循环中累积。当前最有效的人机协作模式是"AI 起草，人类审查"——Agent 完成初始实现，开发者审查并修正，Agent 再根据反馈优化。


代码质量保障与测试生成
AI 代码生成的质量保障是工程落地的关键环节。生成的代码可能存在功能性错误、安全漏洞、性能问题和风格不一致等问题。自动化测试生成是 AI 辅助质量保障的核心能力——如果 AI 能够同时生成代码和测试，就能在一定程度上自我验证。


AI 生成代码的常见质量问题包括：幻觉 API（调用不存在的函数或方法）、上下文不一致（使用错误的变量名或类型）、安全隐患（SQL 注入、路径遍历）和过度复杂（生成不必要的抽象层）。建立系统性的质量检查流程——类型检查、静态分析、单元测试和安全扫描——是确保生成代码可靠性的必要手段。
