搜索与排序

核心概念

搜索与排序是互联网最古老也最核心的 NLP 应用。用户输入一个查询，系统从海量文档中找到最相关的结果并按相关性排序返回——这个看似简单的过程背后涉及查询理解、文档表示、相关性计算和排序优化等多个技术环节。从关键词匹配的 BM25 到语义理解的神经排序模型，搜索技术经历了从统计到语义的深刻转变。理解搜索排序不仅对搜索引擎开发者有价值，对任何涉及信息检索的系统（如 RAG、推荐系统）都是必备知识。

搜索系统的核心设计原则是漏斗架构——每一阶段用更复杂的模型在更小的候选集上做更精细的排序。这在效果和效率之间取得了最佳平衡。


查询理解
查询理解是搜索系统的第一个环节，目标是深入理解用户输入的真实意图。用户的查询往往简短、模糊甚至有拼写错误——"ipone 15 价格"需要纠错为 "iPhone 15 价格"，"苹果"需要判断是指水果还是公司，"怎么做蛋糕"需要识别为教程类意图。


查询改写（Query Rewriting）将用户的原始查询转换为更有效的检索查询。同义词扩展将"手机"扩展为"手机 OR 智能手机 OR 移动电话"；查询简化去除噪声词；查询补全补充隐含信息。基于 Seq2Seq 的查询改写模型可以自动学习这些变换。


from dataclasses import dataclass

@dataclass
class QueryAnalysis:
    original_query: str
    corrected_query: str
    intent: str
    entities: list[dict[str, str]]
    expanded_terms: list[str]
    filters: dict[str, str]

def analyze_query(query: str) -> QueryAnalysis:
    corrected = _spell_correct(query)
    intent = _classify_intent(corrected)
    entities = _extract_entities(corrected)
    expanded = _expand_synonyms(corrected)
    filters = _extract_filters(corrected)
    return QueryAnalysis(
        original_query=query,
        corrected_query=corrected,
        intent=intent,
        entities=entities,
        expanded_terms=expanded,
        filters=filters
    )

def _spell_correct(q: str) -> str: return q
def _classify_intent(q: str) -> str: return "search"
def _extract_entities(q: str) -> list[dict[str, str]]: return []
def _expand_synonyms(q: str) -> list[str]: return []
def _extract_filters(q: str) -> dict[str, str]: return {}
意图分类识别查询的类型——导航型（找特定网站）、信息型（找答案）和事务型（完成操作）。不同意图类型需要不同的搜索策略和结果展示方式。实体识别从查询中提取关键实体和属性，为结构化搜索和过滤提供支持。


稀疏检索与稠密检索
稀疏检索以 BM25 为代表，基于词频统计计算查询与文档的相关性。BM25 是 TF-IDF 的改进版本，引入了文档长度归一化和词频饱和（高词频的边际收益递减）。BM25 通过倒排索引实现高效检索——倒排索引记录每个词出现在哪些文档中，查询时只需合并查询词的倒排列表。


稠密检索用神经网络将查询和文档映射为稠密向量，通过向量相似度（如余弦相似度或内积）计算相关性。双编码器（Bi-Encoder）分别编码查询和文档，文档向量可以离线预计算并建立向量索引。DPR、E5 和 BGE 是常用的稠密检索模型。

混合检索将稀疏和稠密检索的结果融合，通常能获得比单一方法更好的效果。BM25 擅长精确关键词匹配（专有名词、型号等），稠密检索擅长语义匹配（同义词、概念理解），二者互补。融合方法包括分数线性组合、倒数排名融合（RRF）和学习融合权重。


学习排序与神经排序模型
学习排序（Learning to Rank，LTR）用机器学习模型从训练数据中学习排序函数。按照损失函数的设计，LTR 分为三大类：Pointwise（对每个文档独立预测相关性分数）、Pairwise（学习文档对之间的偏序关系，如 RankNet、LambdaMART）和 Listwise（直接优化列表级排序指标，如 ListNet）。


LambdaMART 是工业界最广泛使用的 LTR 模型之一。它基于梯度提升决策树（GBDT），使用 Lambda 梯度直接优化 NDCG 指标。LambdaMART 的优势在于：对特征工程友好（可以方便地加入各种手工特征）、可解释性好（可以分析特征重要性）和训练推理速度快。


BERT 交叉编码器将查询和文档拼接输入 BERT，通过深层交叉注意力实现精细的语义匹配。这种方法的排序效果最好，但计算成本极高——需要为每个（查询, 文档）对做一次完整的 BERT 前向传播，无法用于大规模候选的初始检索阶段。


知识蒸馏是将交叉编码器的精排能力迁移到双编码器的有效方法。用交叉编码器为训练数据中的（查询, 文档）对打分，将这些分数作为软标签训练双编码器。蒸馏后的双编码器在保持高效检索的同时，排序效果接近交叉编码器。


小结
    

  • 搜索系统采用漏斗架构，每阶段用更复杂的模型在更小候选集上排序
    • 

  • 查询理解包括纠错、改写、意图识别和实体提取，是搜索质量的第一道关
    • 

  • BM25 和稠密检索各有优势，混合检索通常能获得最佳效果
    • 

  • BERT 交叉编码器排序效果最好但成本高，知识蒸馏可以将其能力迁移到高效模型
    • 

  • LambdaMART 在工业界广泛应用，对特征工程友好且可解释性好
    • 

  • 搜索质量评估以 NDCG 和 MRR 为核心指标，需要持续的在线 A/B 测试
    •
