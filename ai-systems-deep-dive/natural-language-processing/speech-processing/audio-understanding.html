音频理解

核心概念

音频理解将理解范围从人类语音扩展到所有声音事件。环境声音分类、音频事件检测、音频场景识别和音频描述生成等任务让机器能够"听懂"非语言的声音世界。汽车鸣笛声意味着交通环境，婴儿啼哭声可能需要关注，键盘敲击声暗示办公场景——这些声音携带了丰富的语义信息。音频理解技术在智能安防、自动驾驶、辅助技术和多媒体分析等领域有广泛应用。

音频理解与语音识别的核心区别在于：语音识别聚焦于人类语音的内容转写，而音频理解关注所有声音事件的语义理解。AudioSet 是 Google 发布的大规模音频数据集，包含约 200 万条 10 秒音频片段和 632 个事件类别的标注，是音频理解领域的 ImageNet。


音频特征与频谱表示
音频信号的特征提取与语音类似但有其独特需求。语音识别主要关注频谱包络（与语音内容相关），而音频理解需要捕捉更丰富的频谱细节——不同声音事件在时频平面上有独特的模式（鸟鸣是高频的短促脉冲，汽车引擎是低频的持续振动）。


Log-Mel Spectrogram 是音频理解最常用的特征表示。与语音识别中 80 维的梅尔频谱图不同，音频理解通常使用 128 维以捕捉更细致的频率信息。时间维度上，10 秒音频在 10ms 帧移下产生 1000 帧。整个特征可以视为一张单通道"图像"（时间×频率），这为利用图像分类模型提供了天然的桥梁。


from dataclasses import dataclass
import numpy as np

@dataclass
class AudioFeature:
    mel_spectrogram: np.ndarray
    sample_rate: int
    n_mels: int
    hop_length: int
    duration: float

    @property
    def num_frames(self) -> int:
        return self.mel_spectrogram.shape[0]

    @property
    def time_resolution(self) -> float:
        return self.hop_length / self.sample_rate
数据增强对音频理解模型的泛化能力至关重要。SpecAugment 在频谱图上随机遮盖时间条和频率条，模拟时间变化和频率缺失。Mixup 将两个音频样本及其标签按比例混合，增加训练数据的多样性。时间拉伸和音高偏移模拟录音条件的变化。


CNN 与 Transformer 音频模型
早期的音频理解模型直接借鉴了图像分类架构。将 Log-Mel Spectrogram 视为图像，用 VGGish、ResNet 等 CNN 进行分类。PANNs（Pretrained Audio Neural Networks）在 AudioSet 上预训练的 CNN 模型是音频分类的强基线——CNN14 在 AudioSet 上达到了 0.431 的 mAP。


AST（Audio Spectrogram Transformer）将 Vision Transformer 迁移到音频领域。它将频谱图切分为 16×16 的补丁（patch），通过线性投影将每个补丁映射为 token，然后用标准 Transformer 编码器处理。AST 从 ImageNet 预训练的 ViT 初始化权重，在 AudioSet 上微调后达到了 0.485 的 mAP，显著超越 CNN 方法。


BEATs（Audio Pre-Training with Acoustic Tokenizers）采用自监督预训练策略。它使用声学分词器（Acoustic Tokenizer）将音频转换为离散标记，然后用掩码预测目标训练 Transformer。这种方法不需要人工标注，利用大规模无标注音频数据学习通用的音频表示。BEATs 在 AudioSet 上达到了 0.981 的 mAP（fine-tuned），刷新了记录。

音频-文本多模态理解
音频-文本多模态理解将音频信号与自然语言连接起来，实现音频内容的文本描述、音频-文本检索和基于文本指令的音频事件检测等能力。


CLAP（Contrastive Language-Audio Pretraining）借鉴了 CLIP 在视觉-语言领域的成功，通过对比学习将音频和文本映射到共享的嵌入空间。训练数据是（音频, 文本描述）对，模型学习让匹配对的嵌入靠近、不匹配对的嵌入远离。训练完成后，CLAP 可以进行零样本音频分类——只需提供类别的文本描述，无需任何音频标注数据。


音频描述生成（Audio Captioning）用自然语言描述音频中发生的事件。"一辆汽车在雨天行驶，雨刮器发出节奏性的声音"——这种描述需要模型同时理解多个并发的声音事件及其时间关系。编码器-解码器架构是标准方案，音频编码器提取声学特征，文本解码器生成描述。


大语言模型正在深刻改变音频理解的范式。Whisper 证明了大规模预训练在语音理解中的威力，类似的方法正在扩展到通用音频理解。Qwen-Audio 等音频大模型通过将音频编码器与大语言模型连接，实现了通用的音频理解和对话能力——用户可以上传任意音频并用自然语言提问。


小结
    

  • 音频理解从语音扩展到所有声音事件的语义理解，AudioSet 是标准基准
    • 

  • Log-Mel Spectrogram 是主流特征，可以视为"图像"利用 CNN 和 ViT 处理
    • 

  • AST 和 BEATs 等 Transformer 模型在 AudioSet 上大幅超越 CNN 基线
    • 

  • CLAP 通过对比学习实现了零样本音频分类和音频-文本检索
    • 

  • 音频大模型将音频编码器与 LLM 结合，实现了通用的音频理解和对话能力
    • 

  • 声音事件检测需要帧级预测，时间分辨率和多标签处理是工程挑战
    •
