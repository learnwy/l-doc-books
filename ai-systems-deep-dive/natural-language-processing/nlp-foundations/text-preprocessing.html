文本预处理

核心概念

文本预处理是 NLP 流水线的第一个环节，它将原始的、充满噪声的自然语言文本转换为模型可以处理的规范化输入。预处理质量直接决定了下游任务的性能上限——"垃圾进、垃圾出"在 NLP 中尤为明显。一个完整的预处理流水线通常包括文本清洗、分词、规范化、特征提取等多个阶段，每个阶段都需要根据具体任务和语言特点做出设计决策。

预处理并非越复杂越好。在大模型时代，很多传统的预处理步骤（如停用词过滤、词干提取）反而可能损害模型性能，因为预训练模型已经具备了处理原始文本的能力。关键在于理解每一步操作的目的和副作用，根据具体任务做出合理选择。


文本清洗与规范化
文本清洗是预处理的第一步，目标是去除噪声、统一格式。真实世界的文本数据来源极为多样——网页爬取的 HTML 标签、社交媒体的特殊符号、OCR 识别的错误字符、不同编码系统的混用——这些噪声如果不加处理，会严重干扰模型学习。


HTML 和 XML 标签的去除是最常见的清洗操作。除了简单的正则匹配，还需要处理嵌套标签、自闭合标签和实体引用（如 &amp;、&lt;）。对于富文本，保留部分结构信息（如段落分隔、列表结构）有时对下游任务有帮助。


Unicode 规范化是容易被忽视但极为重要的环节。同一个字符可能有多种 Unicode 表示——例如"ü"既可以是单个码点 U+00FC，也可以是 "u" + "̈" 两个码点的组合。NFC（Canonical Decomposition, followed by Canonical Composition）和 NFKC（Compatibility Decomposition, followed by Canonical Composition）是两种常用的规范化形式，NFKC 会额外将兼容等价字符统一（如将全角字母转为半角）。


大小写转换看似简单，但需要注意语言特异性。英语的大小写转换相对直接，但德语中 "ß" 的大写形式是 "SS"，土耳其语中 "I" 的小写不是 "i" 而是 "ı"。在多语言系统中，必须使用 locale-aware 的大小写转换函数。


import unicodedata
import re

def clean_text(text: str) -> str:
    text = re.sub(r'<[^>]+>', '', text)
    text = unicodedata.normalize('NFKC', text)
    text = re.sub(r'\s+', ' ', text).strip()
    return text
数字和日期的规范化需要根据任务决定策略。在情感分析中，具体数字通常不重要，可以替换为特殊标记 <NUM>；但在信息抽取中，数字本身是关键信息，必须保留。类似地，URL、邮箱、电话号码等结构化信息的处理策略也取决于下游任务。


分词技术体系
分词是将连续文本切分为离散 token 的过程，是文本转化为模型输入的关键步骤。不同语言的分词挑战截然不同——英语等用空格分隔的语言看似简单，但缩写词（"don't"）、连字符词（"state-of-the-art"）和多词表达（"New York"）仍需要特殊处理；中文、日文等无空格语言则面临根本性的歧义问题。


中文分词的核心难题是歧义消解。"结合成分子"既可以切分为"结合/成分/子"，也可以切分为"结/合成/分子"。基于词典的最大匹配法速度快但无法处理未登录词；基于统计的方法（如 HMM、CRF）将分词建模为序列标注问题，用 BMES 标注体系（Begin、Middle、End、Single）标记每个字的位置；基于深度学习的方法（如 BiLSTM-CRF）进一步提升了分词精度。


子词分词（Subword Tokenization）是当前预训练模型的标准选择。它在词级和字符级之间找到平衡——高频词保持完整，低频词被切分为有意义的子词片段。BPE（Byte Pair Encoding）算法的核心思想是迭代合并出现频率最高的字符对：初始词表为所有单字符，每一步合并训练语料中最频繁的相邻 token 对，直到词表达到预设大小。


WordPiece 是 BERT 采用的分词算法，与 BPE 的区别在于合并标准——WordPiece 选择使语言模型似然增益最大的字符对，而非简单的频率最高。SentencePiece 则进一步将分词统一为无监督的语言模型问题，基于 Unigram 语言模型的子词分词使用 EM 算法从大词表中逐步移除对似然贡献最小的子词。


停用词与特征选择
停用词过滤是传统 NLP 中的标准操作，但在深度学习时代需要重新审视其价值。停用词是指在文本中高频出现但对特定任务贡献较小的词，如英语中的 "the"、"is"、"at"，中文中的"的"、"了"、"在"。传统的词袋模型和 TF-IDF 特征高度依赖停用词过滤来减少噪声，但预训练语言模型已经具备了自动学习哪些词重要、哪些可忽略的能力。


停用词表的选择会显著影响任务效果。通用停用词表（如 NLTK 的英文停用词表）可能不适用于特定领域——在医学文本中，"patient"不是停用词；在法律文本中，"shall"和"hereby"承载了重要语义。更合理的做法是根据语料统计和任务需求定制停用词表，或使用基于信息论的方法（如互信息、卡方检验）自动识别低信息量词。

词形还原（Lemmatization）和词干提取（Stemming）是英语等屈折语言中的常见规范化操作。词干提取使用简单规则截断词尾（如 Porter Stemmer 将 "running" 变为 "run"），速度快但可能产生非法词形；词形还原则借助词典和语法规则还原到词典形式（如将 "better" 还原为 "good"），更准确但速度较慢。对于中文等分析性语言，这一步通常不需要。


工业级预处理流水线
在生产环境中，文本预处理需要考虑的不仅是算法正确性，还有处理效率、可维护性和可扩展性。一个工业级的预处理流水线通常采用管道架构，每个处理步骤作为独立的可配置组件，通过统一的接口串联。


from dataclasses import dataclass, field
from typing import Protocol

class TextProcessor(Protocol):
    def process(self, text: str) -> str: ...

@dataclass
class PreprocessPipeline:
    processors: list[TextProcessor] = field(default_factory=list)

    def run(self, text: str) -> str:
        for proc in self.processors:
            text = proc.process(text)
        return text
批处理优化是工业场景的关键。当需要处理百万级文档时，逐条处理的效率不可接受。分词器通常提供批处理接口，利用 SIMD 指令和多线程加速。Hugging Face Tokenizers 库的 Rust 后端能在单线程下达到每秒百万 token 的处理速度，通过并行化还可以进一步线性扩展。


增量处理和缓存策略也是生产系统的必备能力。对于搜索引擎等需要持续索引新文档的场景，不可能每次都重新处理全量数据。设计良好的预处理流水线应该支持增量更新——只处理新增或修改的文档，并缓存分词结果以避免重复计算。


多语言支持是全球化产品的核心挑战。不同语言的预处理需求差异巨大——日语需要处理汉字、平假名、片假名的混用，阿拉伯语是从右向左书写的，泰语没有词间空格也没有标点符号。工业级方案通常采用语言检测 + 语言特定处理器的分发架构，先识别文本语言再路由到对应的处理流水线。


小结
    

  • 文本预处理是 NLP 流水线的起点，质量直接决定下游任务的性能上限
    • 

  • 文本清洗包括去标签、Unicode 规范化、大小写转换等，需根据任务需求选择合适的策略
    • 

  • 分词是将连续文本离散化的关键步骤，子词分词（BPE、WordPiece、SentencePiece）是当前预训练模型的标准选择
    • 

  • 停用词过滤和词形还原在传统方法中很重要，但在预训练模型时代需要谨慎使用
    • 

  • 工业级预处理需要考虑管道架构、批处理效率、增量更新和多语言支持
    • 

  • 预处理策略的选择应当以任务为导向，不存在放之四海而皆准的方案
