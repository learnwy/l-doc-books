评估指标

核心概念

NLP 评估指标是衡量模型能力的标尺，正确选择和解读评估指标是避免"刷榜陷阱"、做出合理技术决策的关键能力。不同类型的 NLP 任务——分类、序列标注、生成、匹配——需要不同的评估度量，而同一个任务在不同的应用场景下也可能需要侧重不同的指标。一个优秀的 NLP 工程师不仅要知道如何计算这些指标，更要理解每个指标的假设、局限和适用范围。

评估方法论的核心原则是：没有万能的指标，只有适合特定任务和场景的指标。理想的评估方案通常组合多个互补的指标，从不同维度衡量模型能力。


分类与序列标注指标
分类任务是 NLP 中最基础的评估场景。对于二分类问题，四个基本统计量——真正例（TP）、假正例（FP）、真负例（TN）、假负例（FN）——构成了所有分类指标的基础。


精确率（Precision）= TP/(TP+FP)，衡量"预测为正的样本中有多少是真正的正样本"；召回率（Recall）= TP/(TP+FN)，衡量"所有正样本中有多少被正确找到了"。两者天然存在权衡关系——提高阈值增加精确率但降低召回率，反之亦然。


F1 Score 是精确率和召回率的调和平均：F1=2×P×RP+RF1 = 2 \times \frac{P \times R}{P + R}F1=2×P+RP×R​。调和平均比算术平均更严格——只有当 P 和 R 都较高时，F1 才高。在某些场景中，精确率和召回率的重要性不对等——例如垃圾邮件过滤中误杀正常邮件（低 P）比漏放垃圾邮件（低 R）更严重——此时可以使用 FβF_\betaFβ​ 指标来调整权重。


from dataclasses import dataclass

@dataclass
class ClassificationMetrics:
    tp: int = 0
    fp: int = 0
    fn: int = 0
    tn: int = 0

    @property
    def precision(self) -> float:
        return self.tp / (self.tp + self.fp) if (self.tp + self.fp) > 0 else 0.0

    @property
    def recall(self) -> float:
        return self.tp / (self.tp + self.fn) if (self.tp + self.fn) > 0 else 0.0

    @property
    def f1(self) -> float:
        p, r = self.precision, self.recall
        return 2 * p * r / (p + r) if (p + r) > 0 else 0.0
多分类任务的 F1 有三种平均方式：Macro-F1 对每个类别独立计算 F1 再取平均，对所有类别同等重视；Micro-F1 先汇总所有类别的 TP/FP/FN 再计算 F1，受大类主导；Weighted-F1 按类别样本量加权。类别不平衡时，Macro-F1 更能反映模型在小类上的表现。


序列标注任务（如 NER）的评估更复杂。字符级 F1 逐字评估标注是否正确，但可能高估性能——即使实体边界不对但部分字符标注正确也能得分。实体级 F1 要求实体的边界和类型完全匹配才算正确，是更严格也更有意义的评估方式。


文本生成评估指标
文本生成评估是 NLP 中最具挑战性的问题之一。生成任务的输出空间极大——同一个意思可以有无数种表达方式——因此很难定义"标准答案"。自动评估指标试图在有限的参考答案下量化生成质量，但每种指标都有其盲区。


BLEU（Bilingual Evaluation Understudy）是机器翻译中最经典的评估指标。它计算候选翻译与参考翻译之间的 n-gram 精确率，然后取几何平均。为了避免简短输出获得虚高分数，BLEU 引入了简短惩罚因子（Brevity Penalty）。BLEU-4 通常计算 1-gram 到 4-gram 的加权几何平均。


ROUGE（Recall-Oriented Understudy for Gisting Evaluation）是文本摘要任务的标准指标。与 BLEU 侧重精确率不同，ROUGE 侧重召回率——衡量参考摘要中有多少内容被候选摘要覆盖。ROUGE-1/2 分别计算 unigram 和 bigram 的召回率，ROUGE-L 计算最长公共子序列的比率。

BERTScore 代表了基于模型的评估方向。它使用预训练 BERT 的上下文嵌入计算候选文本和参考文本之间的相似度，通过贪心匹配计算精确率、召回率和 F1。BERTScore 能够捕捉同义词替换、句式变换等 n-gram 匹配无法处理的语义等价，与人工评估的相关性显著高于 BLEU 和 ROUGE。


排序与检索评估指标
搜索和推荐等排序任务需要专门的评估指标。与分类不同，排序任务不仅关心预测是否正确，更关心正确结果的排列位置。


MRR（Mean Reciprocal Rank）计算所有查询中第一个正确结果排名倒数的平均值。如果第一个正确结果排在第 3 位，其倒数排名为 1/3。MRR 只关注第一个正确结果，适合用户只需要一个答案的场景（如问答系统）。


NDCG（Normalized Discounted Cumulative Gain）是最全面的排序指标。它用 DCG 公式量化一个排序列表的价值：DCG@k=∑i=1krelilog⁡2(i+1)DCG@k = \sum_{i=1}^{k} \frac{rel_i}{\log_2(i+1)}DCG@k=∑i=1k​log2​(i+1)reli​​，其中 relirel_ireli​ 是第 iii 位结果的相关度。分母的对数衰减体现了位置折扣——排在前面的结果价值更大。NDCG 将 DCG 除以理想排序的 DCG（IDCG）进行归一化，使得不同查询之间可以比较。


MAP（Mean Average Precision）在每个召回点计算精确率再取平均。它综合考虑了排序质量和召回完整性，是信息检索中经典的评估指标。与 NDCG 不同，MAP 只处理二值相关性（相关/不相关），而 NDCG 可以处理多级相关性。


人工评估与评估方法论
自动指标终究是人类判断的近似，在很多场景下无法替代人工评估。对话系统的对话质量、创意写作的文学性、翻译的自然度——这些主观维度很难用自动指标准确衡量。


人工评估常用的方法包括：Likert 量表评分（1-5 分评估流畅度、相关性等维度）、A/B 对比测试（评估者在两个系统的输出中选择更好的）和 Elo 评分系统（类似棋手等级的评分方法，如 Chatbot Arena）。


评估者一致性是人工评估质量的关键保证。Krippendorff's Alpha 和 Cohen's Kappa 是两种常用的一致性度量。当一致性低于阈值时，需要修改评估标准或加强评估者培训。


现代评估方法论越来越多地采用 LLM-as-Judge 方案——使用 GPT-4 等强大的语言模型作为自动评估者。研究表明，GPT-4 的评估结果与人工评估的一致性已经接近人工评估者之间的一致性水平。这种方法大幅降低了评估成本，但也引入了模型偏差（如偏好自己风格的输出、偏好较长的回答）等问题。


小结
    

  • 不同 NLP 任务需要不同的评估指标，没有万能的度量标准
    • 

  • 分类任务用精确率、召回率和 F1，多分类需注意 Macro/Micro 平均的选择
    • 

  • 序列标注任务应使用实体级 F1 而非字符级 F1 来避免高估性能
    • 

  • 生成任务的 BLEU 和 ROUGE 各有偏向，BERTScore 能更好地捕捉语义相似度
    • 

  • 排序任务用 MRR、NDCG 和 MAP 衡量结果排列的质量
    • 

  • 自动指标应与人工评估结合使用，LLM-as-Judge 是降低人工评估成本的新趋势
