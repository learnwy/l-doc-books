表格抽取

核心概念

表格抽取（Table Extraction）是从文档中检测、识别和理解表格结构的技术。表格是信息组织最密集的形式之一——财务报表、科研数据、统计报告中的关键数据大多以表格形式呈现。然而，表格的多样性（有线表格、无线表格、合并单元格、嵌套表格）和来源的复杂性（PDF、图片、网页）使得表格抽取成为一个极具挑战性的问题。完整的表格抽取流水线包括表格检测、结构识别和内容提取三个阶段。

表格抽取的终极目标不仅是恢复表格的物理结构，更是理解表格的语义——每个单元格的内容是什么含义，行列标题与数据单元格之间是什么关系，表格整体表达了什么信息。


表格检测与结构识别
表格检测的目标是在文档页面中定位表格的位置和边界。对于有明确表格线的表格，基于规则的方法（检测水平线和垂直线的交叉点）效果良好。但大量真实文档中的表格没有完整的边框线，甚至完全无线，这时需要深度学习方法。


基于目标检测的方法将表格检测建模为 object detection 问题。CascadeTabNet 使用 Cascade R-CNN 检测表格和表格内部的单元格。DETR 系列的端到端检测器由于不需要 NMS 后处理和锚框设计，在表格检测上也取得了优秀效果。


from dataclasses import dataclass

@dataclass
class TableCell:
    row: int
    col: int
    row_span: int
    col_span: int
    bbox: tuple[float, float, float, float]
    content: str

@dataclass
class TableStructure:
    num_rows: int
    num_cols: int
    cells: list[TableCell]

    def to_matrix(self) -> list[list[str]]:
        matrix = [["" for _ in range(self.num_cols)] for _ in range(self.num_rows)]
        for cell in self.cells:
            for r in range(cell.row, cell.row + cell.row_span):
                for c in range(cell.col, cell.col + cell.col_span):
                    if r < self.num_rows and c < self.num_cols:
                        matrix[r][c] = cell.content
        return matrix
结构识别是表格抽取最核心也最困难的环节。它需要确定表格的行列结构以及每个单元格的位置和跨度。合并单元格（一个单元格跨越多行或多列）是主要的困难来源。基于分割的方法将结构识别建模为行分隔线和列分隔线的检测问题。基于图的方法将每个文本区域作为节点，预测哪些相邻节点属于同一个单元格。


表格语义理解
表格语义理解超越了物理结构的识别，深入到表格内容的含义理解。TAPAS（Table Parsing）是 Google 提出的表格理解预训练模型。它在 BERT 的基础上引入了行列位置嵌入和数值排序嵌入，通过在大量表格-问题对上预训练来学习表格推理能力。

表格问答（Table QA）要求模型根据表格内容回答自然语言问题。简单问题（"2023年的销售额是多少？"）只需定位到对应单元格；复杂问题（"哪一年的增长率最高？"）需要跨行比较和数值计算。TAPAS 将问题分解为单元格选择和聚合操作两步——先选择哪些单元格与问题相关，再决定对这些单元格执行什么操作（求和、平均、计数等）。


TaPEx 采用了另一种优雅的方案——将表格推理问题转化为程序执行问题。它在预训练阶段用 SQL 执行引擎生成大量（表格, SQL, 执行结果）三元组作为训练数据，让模型学习"执行"SQL 查询的能力。这种方法使模型能够处理复杂的数值推理和多步操作。


跨格式表格处理
真实应用中的表格来源多样——HTML 表格、PDF 表格、图片中的表格、Excel 表格——每种格式都有其独特的处理挑战。


HTML 表格是最结构化的来源，<table>, <tr>, <td> 标签直接编码了表格结构。但即使是 HTML 表格也有复杂情况——colspan 和 rowspan 属性表示合并单元格，嵌套表格、表格作为布局工具等情况需要特殊处理。


PDF 表格是最具挑战性的来源。PDF 是一种以页面为单位的显示格式，本身不包含表格的逻辑结构信息。PDF 中的"表格"只是一组按特定坐标排列的文字和线条，需要通过坐标分析和启发式规则重建表格结构。跨页表格（一个表格跨越多个页面）更增加了处理难度。


大语言模型在表格处理中展现出强大的灵活性。对于简单表格，将表格转换为 Markdown 格式输入 LLM，模型就能进行问答和推理。对于复杂表格，多模态 LLM 能直接从表格图像中理解结构和内容。这种方式虽然推理成本高，但几乎不需要领域特定的开发工作，在需要快速验证的场景中极具价值。


小结
    

  • 表格抽取包括检测、结构识别和内容提取三个阶段，合并单元格是核心难点
    • 

  • 基于目标检测和图方法的结构识别技术能处理有线和无线表格
    • 

  • TAPAS 和 TaPEx 是表格语义理解的代表模型，分别采用选择+聚合和 SQL 执行范式
    • 

  • 表格问答需要数值推理能力，复杂问题需要多步操作和跨行比较
    • 

  • PDF 表格是最具挑战性的来源，需要从坐标信息重建逻辑结构
    • 

  • 大语言模型通过 Markdown 转换或多模态输入，在表格理解中展现出零样本能力
    •
