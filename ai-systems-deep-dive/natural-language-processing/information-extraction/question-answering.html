问答系统

核心概念

问答系统（Question Answering，QA）是信息抽取最直观的应用形态——用户提出自然语言问题，系统给出精确的答案。从搜索引擎的精选摘要到智能客服的自动回答，问答系统已经成为人们获取信息的主要方式之一。技术上，QA 系统需要同时具备问题理解、信息检索和答案生成能力，是 NLP 综合能力的集中体现。大模型时代的 RAG（检索增强生成）架构更是将问答推向了新的高度。

问答系统的核心挑战包括：问题理解（识别问题类型和关键约束）、证据检索（从海量文档中找到相关段落）、答案推理（从证据中推导出答案）和答案验证（确保答案的正确性）。


抽取式阅读理解
抽取式阅读理解是最经典的 QA 范式。给定一段文本（context）和一个问题（question），模型需要从文本中找到答案所在的起始和结束位置。SQuAD（Stanford Question Answering Dataset）是这一范式的标志性数据集。


BERT-QA 的标准做法是将问题和文本拼接为 [CLS] question [SEP] context [SEP]，输入 BERT 编码器，然后用两个线性层分别预测答案的起始位置和结束位置。起始和结束位置的概率分布通过 softmax 在所有 context token 上计算。


import torch
import torch.nn as nn

class ExtractiveQA(nn.Module):
    def __init__(self, encoder_dim: int):
        super().__init__()
        self.start_classifier = nn.Linear(encoder_dim, 1)
        self.end_classifier = nn.Linear(encoder_dim, 1)

    def forward(self, sequence_output: torch.Tensor, context_mask: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
        start_logits = self.start_classifier(sequence_output).squeeze(-1)
        end_logits = self.end_classifier(sequence_output).squeeze(-1)
        start_logits = start_logits.masked_fill(~context_mask, float('-inf'))
        end_logits = end_logits.masked_fill(~context_mask, float('-inf'))
        return start_logits, end_logits
SQuAD 2.0 增加了不可回答问题——某些问题在给定的文本中没有答案。模型需要学会判断何时应该回答"无法回答"。常见做法是将 [CLS] 位置的得分作为"无答案"的置信度，与最佳 span 得分进行比较。


检索增强生成
RAG（Retrieval-Augmented Generation）是大模型时代问答系统的主流架构。它将信息检索与文本生成有机结合——先从外部知识库中检索相关文档，再将检索到的文档作为上下文输入生成模型，由模型基于检索结果生成答案。


检索阶段通常采用双编码器（Bi-Encoder）架构——用一个编码器编码查询，另一个编码器编码文档，通过向量相似度进行快速检索。DPR（Dense Passage Retrieval）用对比学习训练双编码器，正样本是问题-正确段落对，负样本包括 BM25 返回的困难负例。

检索质量直接决定了 RAG 系统的上限。多阶段检索策略先用稀疏检索（BM25）快速召回候选文档，再用稠密检索或交叉编码器重排序，在效率和精度之间取得平衡。查询改写（Query Rewriting）和假设文档嵌入（HyDE）等技术通过优化查询表示来提升检索质量。


多跳推理与复杂问答
简单问答只需从单个段落中找到答案，但复杂问题往往需要跨多个文档进行链式推理。"哈利·波特的作者出生在哪个国家？"需要先找到"作者是 J.K. 罗琳"，再找到"罗琳出生在英国"，完成两跳推理。


HotpotQA 是多跳问答的标准基准数据集。它要求模型不仅给出正确答案，还要提供支持答案的证据句子链。多跳推理方法包括：迭代检索（先检索第一跳的文档，从中提取线索用于第二跳检索）、图推理（将实体和文档构建为图，在图上传播信息）和链式思维（Chain-of-Thought，让模型逐步分解和推理复杂问题）。


大语言模型在多跳推理上展现出强大能力。通过 Chain-of-Thought 提示，模型能够将复杂问题分解为多个子问题并逐步求解。ReAct 框架将推理和行动交替进行——模型先推理出需要什么信息，然后调用搜索工具获取信息，再基于新信息继续推理。


小结
    

  • 问答系统从抽取式到生成式演进，RAG 是当前的主流架构
    • 

  • 抽取式 QA 将阅读理解建模为 span 定位问题，BERT-QA 是标准方案
    • 

  • RAG 将检索和生成结合，检索质量直接决定系统的性能上限
    • 

  • 多跳推理需要跨文档的链式推理能力，Chain-of-Thought 是有效的提示策略
    • 

  • 大模型通过 ReAct 等框架将推理与工具调用结合，扩展了问答系统的能力边界
    • 

  • 问答系统的工程化需要关注检索效率、缓存策略和答案一致性
