流式语音识别

核心概念

流式语音识别（Streaming ASR）是指在用户说话过程中实时输出识别结果的技术，区别于离线 ASR 需要等待完整音频后才进行处理。它是语音助手、实时字幕、同声传译、电话客服等交互式场景的核心基础设施，对延迟的要求通常在 200ms 以内。

流式与离线 ASR 的核心差异在于信息因果性——流式模型在时间 t 只能使用 t 及之前的音频信息，无法利用未来上下文：

编码器流式化策略
将离线 Transformer/Conformer 编码器改造为流式版本是核心挑战，主要有三种策略。


因果卷积 + 因果注意力是最直接的方法。将标准卷积替换为因果卷积（左填充），将全局自注意力限制为只关注当前及之前的帧。这种方式实现简单但性能损失较大，因为完全放弃了未来信息。


分块注意力（Chunk-wise Attention） 是目前主流方案。将输入音频按固定大小的块（chunk）进行处理，块内使用双向注意力，块间使用因果注意力。这在延迟和准确率之间取得了平衡：


import torch
import torch.nn as nn

class ChunkedAttention(nn.Module):
    def __init__(self, d_model: int, chunk_size: int, left_chunks: int):
        super().__init__()
        self.chunk_size = chunk_size
        self.left_chunks = left_chunks
        self.attention = nn.MultiheadAttention(d_model, num_heads=8)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        B, T, D = x.shape
        num_chunks = T // self.chunk_size
        chunks = x.view(B, num_chunks, self.chunk_size, D)

        outputs = []
        for i in range(num_chunks):
            start = max(0, i - self.left_chunks)
            context = chunks[:, start:i+1].reshape(B, -1, D)
            query = chunks[:, i]
            out, _ = self.attention(query, context, context)
            outputs.append(out)

        return torch.cat(outputs, dim=1)
Emformer（Efficient Memory Transformer） 是 Meta 提出的流式架构，在分块注意力基础上引入了记忆机制。每个块处理后生成一个固定大小的记忆向量（Memory Bank），后续块通过注意力访问这些记忆而非原始历史帧，将复杂度从 O(T²) 降为 O(T·C)（C 为块大小）。

解码策略与端点检测
流式 ASR 的解码策略与离线有本质不同，需要在延迟和准确率之间动态权衡。


RNN-Transducer（RNNT） 是流式 ASR 最主流的解码框架。它由三个组件构成：编码器（处理音频帧）、预测网络（类似语言模型，处理已输出的 token）和联合网络（合并两者并输出下一个 token 或空白符 ∅）。每当编码器产生新帧时，解码器会贪心或 beam search 地输出 token 直到预测 ∅，然后等待下一帧。


CTC Prefix Beam Search 在流式 CTC 模型中，使用前缀 beam search 算法增量地扩展候选序列。每到达一个新的音频帧，更新所有候选前缀的概率，合并以空白符结尾和非空白符结尾的路径。

FastEmit 正则化通过在 RNNT 损失中增加对非空白符输出的奖励，鼓励模型尽早输出 token 而不是等待更多音频帧，从而在不增加模型复杂度的前提下减少延迟约 100-200ms。


生产系统架构
构建生产级流式 ASR 系统需要考虑音频传输、计算资源管理和结果后处理等工程问题。


WebSocket 双向通信是流式 ASR 的标准通信协议。客户端持续发送音频数据块，服务端异步返回部分结果和最终结果：


import asyncio
import websockets
import json

async def stream_recognize(audio_path: str, ws_url: str):
    async with websockets.connect(ws_url) as ws:
        await ws.send(json.dumps({
            "config": {
                "sample_rate": 16000,
                "encoding": "pcm_s16le",
                "language": "zh-CN",
            }
        }))

        with open(audio_path, "rb") as f:
            while chunk := f.read(3200):
                await ws.send(chunk)
                response = await ws.recv()
                result = json.loads(response)
                if result.get("is_final"):
                    print(f"最终: {result['text']}")
                else:
                    print(f"临时: {result['text']}", end="\r")

        await ws.send(json.dumps({"eof": True}))
        final = json.loads(await ws.recv())
        print(f"完成: {final['text']}")
服务端架构设计的关键考量：


    

  • 动态批处理：将多个并发请求的音频帧打包为一个 batch 进行 GPU 推理，利用率从 10-20% 提升到 80%+
    • 

  • 有状态会话管理：每个连接维护编码器状态（历史缓存、记忆向量），使用 sticky session 或将状态存入 Redis
    • 

  • 热词增强（Hot Word Boosting）：在解码时提高特定词汇（人名、产品名）的输出概率，通常通过 CTC 前缀分数偏置或 WFST 融合实现
    • 

  • 反向文本规范化（ITN）：将 ASR 输出的口语化文本转为书面格式（"一百二十三" → "123"，"百分之五十" → "50%"）
    • 



小结
    

  • 流式 ASR 的核心约束是因果性——只能使用历史信息，无法利用未来上下文
    • 

  • 分块注意力是目前主流的编码器流式化方案，在 160-640ms 延迟下仅损失 1-3% WER
    • 

  • RNNT 是流式解码的首选框架，FastEmit 正则化可有效降低端到端延迟
    • 

  • 端点检测需要综合静音、模型信号和语义判断，是影响用户体验的关键因素
    • 

  • 生产系统需要 WebSocket 通信、动态批处理、有状态会话管理和热词增强等工程基础设施
    •
