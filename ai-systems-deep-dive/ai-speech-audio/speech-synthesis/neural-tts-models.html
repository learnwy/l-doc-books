神经网络语音合成模型

核心概念

神经网络语音合成模型（Neural TTS）是指使用深度学习方法直接建模文本到语音的映射关系的模型。从 2017 年 Tacotron 的出现到 2024 年基于语言模型的 TTS，这一领域经历了从 Seq2Seq、非自回归、到大语言模型三代架构的快速演进，合成语音的自然度已经接近甚至达到人类水平。

离散语音表示与神经编解码器

第三代 TTS 模型的核心创新是将连续语音波形转换为离散 Token 序列，使得语音生成可以复用 NLP 领域成熟的语言模型技术。

EnCodec（Meta） 是最具代表性的神经音频编解码器。它使用 1D 卷积编码器将 24kHz 音频压缩为连续向量，再通过残差向量量化（Residual Vector Quantization, RVQ）将每个向量映射为 N 层离散码本索引。每层码本大小为 1024，使用 8 层 RVQ 时，每帧（75 帧/秒）产生 8 个 Token。

from encodec import EncodecModel
from encodec.utils import convert_audio
import torchaudio

model = EncodecModel.encodec_model_24khz()
model.set_target_bandwidth(6.0)

wav, sr = torchaudio.load("speech.wav")
wav = convert_audio(wav, sr, model.sample_rate, model.channels)

encoded_frames = model.encode(wav.unsqueeze(0))
codes = encoded_frames[0][0]

decoded_wav = model.decode(encoded_frames)

RVQ 的分层结构是理解语音 Token 的关键：第 1 层码本编码语音的核心内容（语义、音素），后续层逐步添加声学细节（音色、音质）。这种分层特性被 VALL-E 等模型巧妙利用——用自回归模型生成第 1 层（确保语义正确），用非自回归模型并行生成第 2-8 层（补充声学细节）。

SoundStream Google 24kHz 3-18 kbps 3-18 50 Hz 高

VALL-E 与语音语言模型

VALL-E 是微软于 2023 年提出的开创性模型，首次将 TTS 重新定义为语言建模问题：给定文本 Token 和 3 秒参考语音的 Token，自回归地生成目标语音的 Token 序列。

两阶段生成架构：

  • AR 阶段：自回归 Transformer 解码器，输入为文本 Token + 参考语音的第 1 层 RVQ Token，输出目标语音的第 1 层 Token。这一阶段决定了语音的语义内容和韵律节奏
  • NAR 阶段：非自回归 Transformer，以第 1 层 Token 为条件，并行预测第 2-8 层 Token。这一阶段填充声学细节，恢复音质
graph LR
    subgraph 输入
        TXT[文本 Token]
        REF[参考语音<br>3s RVQ Token]
    end
    TXT --> AR[AR Decoder<br>自回归生成]
    REF --> AR
    AR --> L1[第 1 层 Token<br>语义+韵律]
    L1 --> NAR[NAR Decoder<br>非自回归生成]
    NAR --> L28[第 2-8 层 Token<br>声学细节]
    L1 --> DEC[EnCodec<br>解码器]
    L28 --> DEC
    DEC --> WAV[合成语音]

VALL-E 2 在此基础上做了重要改进：引入 Repetition Aware Sampling（重复感知采样）解决自回归生成中的循环重复问题；使用 Grouped Code Modeling 将多层 Token 合并预测以加速推理。

CosyVoice（阿里通义） 采用了不同的语音 Token 化策略——使用监督训练的语义 Token（从 ASR 编码器提取）而非 RVQ 编解码器 Token，然后使用条件流匹配（Conditional Flow Matching）从语义 Token 生成梅尔频谱图，最后用 HiFi-GAN 合成波形。这种方式避免了 RVQ 多层生成的复杂性。

扩散与流匹配模型

扩散模型（Diffusion Model）和流匹配（Flow Matching）是另一类强大的生成范式，在 TTS 中展现出优异的音质和多样性。

Grad-TTS 首次将扩散模型引入 TTS，将梅尔频谱图的生成建模为从高斯噪声到目标分布的去噪过程。声学模型先预测对齐和均值，然后扩散模型以此为条件逐步去噪生成精细频谱图。

NaturalSpeech 2（微软） 使用扩散模型在连续潜在空间生成语音，结合 in-context learning 实现零样本克隆：

模型 生成范式 零样本能力 MOS 推理速度 训练数据
NaturalSpeech 2 扩散 支持（5s 参考） 4.5 中 44K 小时
NaturalSpeech 3 FAR + Flow 支持 4.6 快 200K 小时
Voicebox Flow Matching 支持 4.5 中 60K 小时
E2-TTS Flow Matching 支持 4.4 中 10K 小时
F5-TTS Flow Matching 支持 4.5 快 100K 小时

Flow Matching 相比扩散模型的优势在于训练和推理效率。扩散模型需要上千步去噪，而流匹配学习从噪声到数据的直线路径（Optimal Transport），通常只需 10-50 步即可生成高质量语音。F5-TTS 使用 DiT（Diffusion Transformer）架构结合流匹配，在保持高音质的同时实现了接近实时的推理速度。

E2-TTS 的创新在于极简架构——直接将文本和语音拼接为统一序列，使用流匹配 Transformer 从带掩码的输入生成完整语音，无需显式的文本-语音对齐、音素转换或持续时间预测。

开源生态与工程选型

开源 TTS 生态繁荣，但格局迭代极快——2024 年的主流推荐（XTTS v2、CosyVoice v1、MeloTTS）到 2025 年已整体换血。

Coqui TTS / XTTS v2 曾是社区最活跃的通用 TTS 库（17 种语言、5 秒参考克隆），但 Coqui 公司已于 2024 年初停止运营，权重仍可用而演进停滞，新项目不建议再作为首选。

CosyVoice 2（阿里，2024 底） 是 CosyVoice 的流式升级版：0.5B 参数，块状流式生成把首包延迟压到约 150ms，在中文/中英混合场景保持开源第一梯队；其后续 CosyVoice 3 技术报告进一步扩展了规模与多语种能力。

Kokoro-82M（2025 初） 以 82M 参数实现接近大模型的自然度，Apache 2.0 协议 + CPU 实时推理使其成为边缘部署与低成本批量配音的爆款选择。Orpheus TTS（2025） 基于 Llama 底座支持情感标签与零样本克隆；Sesame CSM-1B 与 Higgs Audio v2（2025） 把对话上下文感知引入开源 TTS——生成的语音会跟随对话情绪起伏，专为语音伴侣/Agent 场景设计；B 站 IndexTTS-2 则在零样本克隆的情感控制上表现突出。

闭源 API 同步进入"可指导"时代：OpenAI gpt-4o-mini-tts（2025）首次允许用自然语言指令控制说话方式（如"用耐心的导师口吻讲"）；ElevenLabs v3（2025）通过内联 audio tags 在文本中直接标注 [whispers]、[laughs] 等情感表演指令，把 TTS 从"朗读"推向"配音表演"。

小结

  • 神经 TTS 经历了 Seq2Seq → NAR → LM-based 三代演进，合成自然度从 MOS 4.0 提升到 4.6
  • 离散语音 Token（RVQ 编解码器）是第三代 TTS 的关键创新，使语音生成可复用语言模型技术
  • VALL-E 将 TTS 重定义为语言建模，通过 AR+NAR 两阶段生成实现 3 秒零样本语音克隆
  • 流匹配模型（F5-TTS、E2-TTS）以更少的推理步数实现了与扩散模型相当的音质
  • 2025 开源选型：中文流式首选 CosyVoice 2，低成本/边缘选 Kokoro-82M，对话场景看 Sesame CSM / Higgs Audio v2；XTTS v2 已随 Coqui 停运而冻结
  • 闭源 API 的差异化在于可控性：gpt-4o-mini-tts 用自然语言指令定风格，ElevenLabs v3 用内联标签做情感表演
