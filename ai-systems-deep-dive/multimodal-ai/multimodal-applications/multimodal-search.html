多模态检索

核心概念

多模态检索（Multimodal Search/Retrieval）是将多模态理解技术应用于信息检索的核心应用场景。它允许用户通过一种模态的查询（如文本描述）检索另一种模态的内容（如图像、视频、音频），或者使用多种模态的混合查询进行更精确的检索。从电商的以图搜图到学术论文的跨模态检索，多模态检索正在重塑人们获取信息的方式。

多模态检索的技术核心是跨模态嵌入空间的构建——将不同模态的内容映射到同一向量空间中，使得语义相关的跨模态内容在向量距离上接近。CLIP 的出现极大地降低了构建多模态检索系统的门槛，但从研究原型到亿级规模的生产系统，仍有大量工程挑战需要解决。

双塔检索架构
双塔架构（Dual Encoder/Bi-Encoder）是多模态检索的基础范式。查询和文档分别由独立的编码器编码为向量，通过向量相似度（通常是余弦相似度或内积）进行匹配。这种架构的核心优势是文档向量可以离线预计算并索引，在线检索时只需编码查询并进行向量搜索。


CLIP 是最常用的双塔多模态检索模型。对于文搜图场景，文本编码器将查询文本编码为向量，图像编码器将所有候选图像编码为向量并建立索引。检索时，计算查询向量与所有图像向量的相似度，返回最相似的 K 个图像。


import faiss
import numpy as np

class MultimodalRetriever:
    def __init__(self, clip_model, dimension=512):
        self.model = clip_model
        self.index = faiss.IndexFlatIP(dimension)
        self.metadata = []

    def index_images(self, images, metadata_list):
        features = self.model.encode_image(images)
        features = features / np.linalg.norm(features, axis=1, keepdims=True)
        self.index.add(features.astype('float32'))
        self.metadata.extend(metadata_list)

    def search(self, query_text, top_k=10):
        text_features = self.model.encode_text(query_text)
        text_features = text_features / np.linalg.norm(text_features)
        scores, indices = self.index.search(
            text_features.reshape(1, -1).astype('float32'), top_k
        )
        return [(self.metadata[i], scores[0][j]) for j, i in enumerate(indices[0])]
CLIP4Clip 将 CLIP 扩展到视频检索。它探索了三种视频表示策略：均值池化（对所有帧的 CLIP 特征取平均）、时序 Transformer（学习帧间关系）和紧凑交互（查询与帧特征的早期融合）。实验表明，简单的均值池化在多数场景下已经足够有效。


向量索引与近似最近邻
生产级多模态检索系统需要在毫秒级延迟下处理亿级规模的向量库。精确的暴力搜索在这种规模下完全不可行，近似最近邻（Approximate Nearest Neighbor，ANN）算法是必不可少的。


HNSW（Hierarchical Navigable Small World）是当前最流行的 ANN 算法。它构建了一个多层的可导航小世界图——上层节点稀疏，用于快速定位到目标附近区域；下层节点密集，用于精确搜索。HNSW 在召回率和查询速度之间取得了优异的平衡，通常能在 99%+ 召回率下实现毫秒级查询。


IVF（Inverted File Index）通过将向量空间划分为多个聚类，先确定查询属于哪些聚类，再只在相关聚类内搜索，大幅减少搜索范围。IVF-PQ（Product Quantization）进一步将向量压缩为短码，实现了亿级向量的内存级检索。

Faiss（Facebook AI Similarity Search）和 Milvus 是最常用的向量检索引擎。Faiss 提供了丰富的索引算法实现，适合研究和中等规模部署；Milvus 是分布式向量数据库，支持数十亿向量的高可用检索。


组合检索与多模态融合查询
组合检索（Composed Retrieval）允许用户同时使用多种模态的查询来精确描述搜索意图。最典型的场景是"图像 + 修改文本"——用户提供一张参考图片并附带文本修改指令（如"这件外套换成红色的"），系统需要找到满足修改条件的目标图像。


CIRR（Composed Image Retrieval on Real-life images）是组合检索的标准基准。CompoDiff 使用扩散模型在 CLIP 空间中根据参考图像和修改文本生成目标图像的嵌入向量，然后检索最接近的真实图像。


多模态融合查询的另一种形式是多条件检索——同时指定多个维度的约束。例如在电商场景中，用户可能同时提供一张产品图片、一段文本描述和一个价格范围。处理这种查询需要在向量相似度基础上叠加结构化过滤条件。


稀疏-稠密混合检索（Hybrid Retrieval）结合了关键词匹配（BM25 等稀疏检索）和语义检索（向量检索）的优势。对于多模态场景，文本查询同时走稀疏和稠密两路检索，图像查询走稠密检索，最后通过 Reciprocal Rank Fusion 等方法合并结果。


多模态重排序与 RAG
检索后的重排序（Re-ranking）使用更精确但更耗时的模型对粗检索结果进行精排。


跨编码器（Cross-Encoder）重排序将查询和候选文档拼接后送入单个 Transformer 编码，通过深度交互获得更精确的匹配分数。这种方式比双塔的独立编码更准确，但由于需要逐对评分，只能应用于粗检索返回的少量候选。


多模态 RAG（Retrieval-Augmented Generation）是检索与生成的结合。先通过多模态检索获取相关的图文文档，然后将检索结果作为上下文送入多模态大模型生成回答。这种方式使大模型能够访问其训练数据之外的知识，在企业知识库问答、技术文档检索等场景中非常实用。


ColPali 是多模态 RAG 的创新方案。它直接对文档的截图（而非 OCR 提取的文本）建立视觉索引，使用 PaLiGemma 视觉语言模型编码文档页面的视觉特征。查询时，文本查询与文档页面的视觉特征进行 Late Interaction 匹配。这种方法跳过了 OCR 步骤，对排版复杂的文档（包含图表、公式、表格）的检索效果显著优于纯文本方法。


小结
    

  • 多模态检索通过跨模态嵌入空间实现不同模态间的语义匹配，CLIP 是最常用的基础模型
    • 

  • 双塔架构将查询和文档独立编码，支持文档向量的离线索引和在线高效检索
    • 

  • ANN 算法（HNSW、IVF-PQ）使亿级规模的向量检索在毫秒级延迟下成为可能
    • 

  • 组合检索支持多模态混合查询，满足复杂搜索场景的精确意图表达需求
    • 

  • ColPali 等视觉索引方案跳过 OCR，对复杂版面文档的检索效果显著优于纯文本方法
    • 

  • 多模态检索是连接多模态理解与实际应用的桥梁，规模化部署仍需在精度与效率间寻找平衡
