Part III · 生成式与多模态 (Generative & Multimodal)多模态 AI 简介通才模型 简介统一架构

统一架构

核心概念

统一架构（Unified Architecture）是多模态 AI 追求的理想形态——用一个单一的模型架构处理所有模态和所有任务。传统的多模态系统为每种任务和模态组合设计专用模型，导致系统复杂度爆炸式增长。统一架构的目标是将视觉问答、图像描述、目标检测、文本生成等数十种任务整合到同一个模型中，通过任务指令或特殊 Token 切换不同的任务模式。

统一架构的核心洞察是：几乎所有多模态任务都可以被形式化为序列到序列（Seq2Seq）的映射问题。图像分类是"图像 Token → 类别文本"，目标检测是"图像 Token → 框坐标 + 类别文本"，VQA 是"图像 Token + 问题 Token → 答案 Token"。通过统一的 Token 化和序列建模，一个模型就能处理所有这些任务。

Unified-IO 全任务统一
Unified-IO（Allen AI）是最具雄心的统一多模态模型之一。它将超过 90 种视觉和语言任务统一到单一的编码器-解码器架构中。


Unified-IO 的关键创新在于全面的 Token 化方案。文本使用标准的 SentencePiece Token 化；图像通过 VQ-GAN 离散化为视觉 Token；边界框被转换为离散的坐标 Token（将坐标量化为 1000 个 bin）；分割掩码被编码为多边形坐标序列。所有输入和输出都是 Token 序列，由统一的 Transformer 编码器-解码器处理。


task_formats = {
    "vqa": "Image: [IMG_TOKENS] Question: {question} Answer:",
    "caption": "Image: [IMG_TOKENS] Generate a caption:",
    "detection": "Image: [IMG_TOKENS] Detect {class}:",
    "segmentation": "Image: [IMG_TOKENS] Segment {class}:",
    "generation": "Generate image: {description}",
}
Unified-IO 2 进一步扩展了支持的模态和任务。它增加了音频、视频和 3D 点云的处理能力，使用动态的模态编码和多模态混合训练策略。在 35 个评测基准上，Unified-IO 2 在不使用任何任务专用模块的情况下，性能接近甚至超过了许多任务专用模型。


这种全任务统一的方法的核心优势在于知识共享：目标检测任务学到的空间理解能力可以提升 VQA 的表现，图像描述任务学到的语言生成能力可以提升视觉对话的表现。任务之间的正向迁移使得统一模型的总体能力超过了各专用模型之和。


OFA 序列到序列统一
OFA（One For All）采用了优雅的序列到序列统一框架。它的核心理念是：将所有任务统一为"给定多模态输入序列，生成目标序列"的形式，使用标准的 Transformer 编码器-解码器架构处理。


OFA 的任务统一设计非常精巧。图像描述：输入 = 图像 Token，输出 = 描述文本 Token。VQA：输入 = 图像 Token + 问题 Token，输出 = 答案 Token。图像生成：输入 = 文本 Token，输出 = 图像 Token（通过 VQ-GAN 解码为图像）。Grounding：输入 = 图像 Token + 文本 Token，输出 = 坐标 Token。


OFA 的训练采用多任务联合训练策略。不同任务按照预设的采样比例混合，较难的任务给予较高的采样权重。预训练阶段在大规模未标注数据上训练跨模态理解能力，微调阶段在多个任务的标注数据上联合训练。


Pix2Seq 系列将目标检测完全转化为序列生成问题。给定图像，模型自回归地生成 "类别 x1 y1 x2 y2 类别 x1 y1 x2 y2 ..." 的 Token 序列。这种方法完全消除了传统检测模型中的 Anchor、NMS 等复杂后处理步骤，架构极为简洁。


多任务学习与任务冲突
统一架构面临的核心挑战之一是多任务学习中的任务冲突问题。不同任务可能对模型参数有矛盾的优化方向——提升检测性能的梯度更新可能损害描述生成的质量，反之亦然。


梯度冲突（Gradient Conflict）是最直接的表现。当两个任务的梯度方向相反时，简单的梯度平均会导致两个任务都无法充分优化。GradNorm 和 PCGrad 等方法通过动态调整任务权重或投影冲突梯度来缓解这一问题。


任务干扰（Task Interference）表现为增加新任务后旧任务性能下降。这类似于持续学习中的灾难性遗忘，但发生在多任务同时训练的场景中。Mixture of Experts（MoE）通过为不同任务路由到不同的专家子网络，减少任务之间的参数竞争。

任务指令（Task Instruction）和 Prompt 设计也是缓解任务冲突的有效手段。通过为每个任务设计独特的指令前缀，模型可以根据指令调整其内部处理路径，隐式地实现了任务特定的参数激活。InstructBLIP 的视觉指令微调证明了好的指令设计可以显著提升多任务性能。


统一架构的扩展性设计
随着支持的模态和任务不断增加，统一架构需要具备良好的扩展性——添加新模态或新任务时不应该影响已有能力。


模态插件（Modality Plugin）设计将每种模态的编码和解码模块化。新增一种模态只需要添加对应的 Token 化器和解编码器，模型的核心 Transformer 不需要修改。Meta-Transformer 探索了这种模态无关的设计，用冻结的 Transformer 处理由不同模态 Token 化器产生的 Token 序列。


适配器（Adapter）和 LoRA 等参数高效方法使得为新任务定制模型变得轻量级。在冻结的统一模型上，只需为每个新任务训练少量适配器参数，即可获得接近全模型微调的性能。这种方法使得统一模型可以快速扩展到新任务，而不需要重新训练整个模型。


模块化组合（Modular Composition）是另一种扩展策略。将统一模型拆分为可组合的模块（视觉编码器、语言模型、坐标解码器等），新任务通过组合现有模块来实现。这种设计的灵活性最高，但需要精心设计模块间的接口。


小结
    

  • 统一架构将所有多模态任务形式化为序列到序列映射，用单一模型处理所有任务
    • 

  • Unified-IO 通过全面的 Token 化方案统一了 90+ 种任务，展示了任务间知识共享的巨大价值
    • 

  • OFA 和 Pix2Seq 证明了序列统一框架的简洁性和有效性
    • 

  • 多任务学习中的梯度冲突和任务干扰是统一架构的核心挑战，需要动态权重和参数隔离来缓解
    • 

  • 模态插件、适配器和模块化设计使统一架构具备良好的扩展性
    • 

  • 统一架构是迈向通用人工智能的重要技术路径，任务数量和模态覆盖仍在持续扩展
    •
