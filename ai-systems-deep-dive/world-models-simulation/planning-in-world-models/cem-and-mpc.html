CEM 与 MPC：连续控制的规划方法

核心概念

Cross-Entropy Method（CEM）与 Model Predictive Control（MPC）是连续控制场景最实用的两种规划方法。它们都基于"在世界模型中模拟多个候选动作序列，选择最优执行"的思想，但实现细节有所不同。CEM 是一种迭代的进化优化算法，特别适合采样优化；MPC 是控制理论的经典方法，特别适合实时闭环。两者都不需要训练策略网络（虽然策略可以作为 warm start），是世界模型规划的"零样本"应用。本节系统讲解这两种方法、它们的协同、与具体的工程实践。

Cross-Entropy Method (CEM)
CEM 是一种简单但强大的全局优化方法，核心思想是用迭代的高斯分布拟合最优解。在控制场景中：


初始化：动作分布 N(μ0,σ02)\mathcal{N}(\mu_0, \sigma_0^2)N(μ0​,σ02​)，通常 μ0=0\mu_0 = 0μ0​=0（保守起步）、σ0\sigma_0σ0​ 大（充分探索）。


采样：从分布中采样 N 个完整动作序列，每个长度 H。


评估：用世界模型模拟每个序列，计算累积奖励。


精英选择：选取奖励最高的 K 个序列（K = N × elite_frac, 典型 elite_frac = 0.1）。


分布更新：用精英序列的均值和方差更新分布参数：

重复：重复采样-评估-更新数次（典型 5-10 次迭代）。


输出：最终分布 μT\mu_TμT​ 的第一步动作作为执行命令。


CEM 的工程实现
CEM 的关键工程要点：


采样规模与迭代次数：


    

  • 采样数 N 越大，探索越充分，但计算成本越高。机器人控制典型 N = 200-2000。
    • 

  • 迭代次数越多，结果越精细。典型 5-10 次。
    • 

  • N × 迭代次数 决定总仿真调用次数，是计算成本的主要来源。
    • 



精英比例：精英比例 elite_frac 典型 0.05-0.1。太低则统计不稳定，太高则丧失选择压力。


温度调节：在迭代后期可以缩小方差（让分布更集中），相当于退火。


初始化策略：


    

  • 零初始化：从 μ0=0\mu_0 = 0μ0​=0 开始，最保守。
    • 

  • 上一周期 warm start：把上次规划的最优动作序列作为初始均值，加速收敛。这是 MPC 配合 CEM 的关键工程技巧。
    • 

  • 策略 warm start：用学到的策略网络初始化，让 CEM 在策略基础上微调。
    • 



并行化：N 个序列的世界模型模拟可以完全并行，特别适合 GPU。这让 CEM 能在 GPU 上实现实时性。


Model Predictive Control (MPC)
MPC 不是单一算法而是一类控制框架，核心特征是"接收当前状态、规划未来 H 步、只执行第一步、下一周期重新规划"。MPC 的关键优势是闭环鲁棒性——即使世界模型有偏差，每周期重规划能不断纠正。


MPC 内部使用什么优化方法是实现细节——可以是 CEM、CMA-ES、QP、梯度下降等。常见的具体 MPC 实现：


Direct Collocation MPC：把动作序列作为优化变量，用梯度方法或非线性规划求解。需要可微的世界模型。


CEM-MPC：每周期用 CEM 求解，把上一周期的解作为 warm start。这是当前机器人 RL 中最常用的范式之一。


MPPI（Model Predictive Path Integral）：基于路径积分的 MPC 变体，用加权重要性采样替代 CEM 的精英选择。MPPI 在 GPU 上特别高效，是 NVIDIA Isaac Gym 等仿真平台的标配。


TD-MPC2：学习的策略 + MPC
TD-MPC2（南加大，2024）把 MPC 与端到端学到的策略网络结合，在多个机器人基准上达到最佳水平。其关键思路：


    

  • 学习世界模型：类似 Dreamer 的潜空间动力学。
    • 

  • 学习策略：训练一个策略网络作为 MPC 的初始化（warm start）。
    • 

  • 学习 Q 函数：训练价值估计，作为 MPC 的终值估计。
    • 

  • 执行时：用 CEM 在世界模型上规划，用学到的策略和 Q 函数加速。
    • 

  • 训练时：MPC 的输出作为策略训练目标，让策略不断逼近 MPC 性能。
    • 



TD-MPC2 的优势是同时获得规划质量与策略速度——简单情况直接用策略快速决策，复杂情况下 MPC 精细规划。这种"双系统"思想在 2024-2026 年正在成为机器人 RL 的主流范式。


计算成本与实时性
CEM 与 MPC 的计算成本主要来自世界模型的多次调用：


    

  • 单次 CEM：N × H × 迭代次数 次调用。例：N=500, H=10, 迭代=5，则 25,000 次调用。
    • 

  • 单次 MPC：每周期一次完整 CEM。如果控制频率 50 Hz，则每秒 25,000 × 50 = 1.25M 次世界模型调用。
    • 



这种计算量在 CPU 上不现实，但在 GPU 上可以实时——尤其是 Brax、Isaac Gym 等 GPU 并行仿真平台让 CEM 的内层模拟可以批量并行。


实践中常用的优化：


层级规划：高频用快速规划（短 horizon、少采样），低频用精细规划（长 horizon、多采样）。 温启动复用：连续帧之间的最优动作有连续性，复用上一周期的解大幅减少计算。 自适应规模：根据状态难度动态调整 N 和迭代次数——简单状态少算，复杂状态多算。

工程实践中，离散决策选 MCTS，连续控制选 CEM/MPC。混合空间问题需要专门设计——例如机器人导航中的"高层路径选择（离散）+ 低层运动控制（连续）"分别用 MCTS 和 MPC。


关键挑战
CEM/MPC 在工程化中的常见问题：


世界模型偏差：长 horizon 规划中世界模型误差累积。常见的应对是限制 horizon、加入不确定性估计、定期与真实数据校准。


局部最优：CEM 的迭代优化可能陷入局部最优。常见的应对是多起点 CEM、添加随机扰动、与策略网络协同。


实时性瓶颈：高频控制场景的实时性挑战。常见的应对是 GPU 并行、模型简化、分层规划。


调参复杂：CEM 和 MPC 都有许多超参（采样数、horizon、迭代次数、精英比例），调好需要工程经验。常见的应对是参考成熟实现的默认值（TD-MPC2、Dreamer 公开了它们的超参）。


小结
CEM 和 MPC 是连续控制规划的两个支柱。CEM 提供高质量的动作序列优化，MPC 提供闭环鲁棒的控制框架，两者结合（CEM-MPC、MPPI、TD-MPC2）成为当前机器人 RL 中最实用的工程范式。理解它们的核心算法、工程优化、与 MCTS 的差异，能让研究者根据问题特性（动作空间类型、实时性约束、世界模型质量）选择合适的规划方法。把"在学到的世界模型上规划"作为机器人控制的标准范式（而非纯 model-free 反应式策略），是从研究 demo 走向产品级控制的关键一步。CEM 与 MPC 在 2026 年仍在快速演进，TD-MPC2 等工作展示了规划与学习深度结合的潜力。
