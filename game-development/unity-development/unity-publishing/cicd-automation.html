CI/CD 自动化

核心概念

CI/CD（持续集成/持续部署）将 Unity 项目的构建、测试和发布流程自动化，消除人工操作瓶颈。Unity 项目的 CI/CD 有其特殊性：构建需要 Unity Editor 许可证、构建时间长（30 分钟到数小时）、产出物是平台特定的安装包、需要处理大量二进制资源文件。成熟的 CI/CD 管线可以将团队从重复的手动构建中解放出来，确保每次发布的可重复性和一致性。

GitHub Actions 工作流
GitHub Actions 配合 GameCI 社区维护的 Action 是目前最流行的 Unity CI/CD 方案。GameCI 提供了预配置的 Docker 镜像，内含指定版本的 Unity Editor，支持 Linux/macOS/Windows 构建环境。


核心流程分为三个阶段：测试（Test）、构建（Build）、部署（Deploy）。Unity License 通过 GitHub Secrets 以环境变量形式注入，支持个人版（Personal）和专业版（Professional）许可证激活。


name: Unity CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

env:
  UNITY_VERSION: 2022.3.20f1
  PROJECT_PATH: .

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          lfs: true

      - uses: actions/cache@v4
        with:
          path: Library
          key: Library-${{ hashFiles('Assets/**', 'Packages/**', 'ProjectSettings/**') }}
          restore-keys: Library-

      - uses: game-ci/unity-test-runner@v4
        env:
          UNITY_LICENSE: ${{ secrets.UNITY_LICENSE }}
        with:
          projectPath: ${{ env.PROJECT_PATH }}
          unityVersion: ${{ env.UNITY_VERSION }}
          testMode: all
          artifactsPath: TestResults

      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: test-results
          path: TestResults

  build-android:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          lfs: true

      - uses: actions/cache@v4
        with:
          path: Library
          key: Library-${{ hashFiles('Assets/**', 'Packages/**', 'ProjectSettings/**') }}

      - uses: game-ci/unity-builder@v4
        env:
          UNITY_LICENSE: ${{ secrets.UNITY_LICENSE }}
        with:
          projectPath: ${{ env.PROJECT_PATH }}
          unityVersion: ${{ env.UNITY_VERSION }}
          targetPlatform: Android
          androidKeystoreName: user.keystore
          androidKeystoreBase64: ${{ secrets.ANDROID_KEYSTORE_BASE64 }}
          androidKeystorePass: ${{ secrets.ANDROID_KEYSTORE_PASS }}
          androidKeyaliasName: ${{ secrets.ANDROID_KEYALIAS_NAME }}
          androidKeyaliasPass: ${{ secrets.ANDROID_KEYALIAS_PASS }}

      - uses: actions/upload-artifact@v4
        with:
          name: android-build
          path: build/Android

  build-ios:
    needs: test
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
        with:
          lfs: true

      - uses: game-ci/unity-builder@v4
        env:
          UNITY_LICENSE: ${{ secrets.UNITY_LICENSE }}
        with:
          projectPath: ${{ env.PROJECT_PATH }}
          unityVersion: ${{ env.UNITY_VERSION }}
          targetPlatform: iOS

      - uses: actions/upload-artifact@v4
        with:
          name: ios-build
          path: build/iOS
Library 缓存是加速 Unity CI 构建的关键。Unity 在首次导入资源时生成 Library 文件夹中的缓存数据，后续构建可直接复用。通过 actions/cache 配合资源文件哈希作为 key，可以显著缩短构建时间。


自动化测试集成
Unity Test Framework 基于 NUnit，支持 EditMode 测试和 PlayMode 测试。在 CI 管线中运行测试可以在构建前捕获逻辑错误和回归问题。GameCI 的 unity-test-runner 自动收集测试结果并生成 JUnit 格式的报告。


using NUnit.Framework;
using UnityEngine;
using UnityEngine.TestTools;
using System.Collections;

[TestFixture]
public class PlayerHealthTests
{
    private PlayerHealth _health;

    [SetUp]
    public void Setup()
    {
        var go = new GameObject();
        _health = go.AddComponent<PlayerHealth>();
        _health.Initialize(100);
    }

    [TearDown]
    public void Teardown()
    {
        Object.DestroyImmediate(_health.gameObject);
    }

    [Test]
    public void TakeDamage_ReducesHealth()
    {
        _health.TakeDamage(30);
        Assert.AreEqual(70, _health.CurrentHealth);
    }

    [Test]
    public void TakeDamage_DoesNotGoBelowZero()
    {
        _health.TakeDamage(150);
        Assert.AreEqual(0, _health.CurrentHealth);
    }

    [UnityTest]
    public IEnumerator Regeneration_RestoresHealthOverTime()
    {
        _health.TakeDamage(50);
        _health.StartRegeneration(10f);

        yield return new WaitForSeconds(2f);

        Assert.Greater(_health.CurrentHealth, 50);
    }
}
版本管理与发布自动化
自动化版本管理确保每次构建有唯一的版本标识，方便追踪问题和回滚。常见策略是使用语义化版本（SemVer）配合构建号自增。在 CI 环境中，可以通过 Git 标签触发发布构建，自动设置版本号并推送到应用商店。


using UnityEditor;
using UnityEditor.Build;
using UnityEditor.Build.Reporting;
using System;

public class VersionManager : IPreprocessBuildWithReport
{
    public int callbackOrder => -1;

    public void OnPreprocessBuild(BuildReport report)
    {
        string version = Environment.GetEnvironmentVariable(
            "BUILD_VERSION") ?? "0.0.1";
        string buildNumber = Environment.GetEnvironmentVariable(
            "BUILD_NUMBER") ?? "1";

        PlayerSettings.bundleVersion = version;

        switch (report.summary.platform)
        {
            case BuildTarget.Android:
                PlayerSettings.Android.bundleVersionCode =
                    int.Parse(buildNumber);
                break;
            case BuildTarget.iOS:
                PlayerSettings.iOS.buildNumber = buildNumber;
                break;
        }
    }

    public static string GenerateVersion(
        string branch, int runNumber)
    {
        if (branch == "main")
            return $"1.0.{runNumber}";
        if (branch.StartsWith("release/"))
            return branch.Replace("release/", "") +
                   $".{runNumber}";
        return $"0.0.{runNumber}-dev";
    }
}

构建缓存与加速策略
Unity 项目的 CI 构建时间通常在 30-90 分钟，对于大型项目甚至超过 2 小时。构建加速是 CI/CD 管线优化的核心课题。除了 Library 缓存外，还有多种加速手段可以显著缩短构建时间。


Unity Accelerator 是官方提供的资源导入缓存服务，团队成员共享同一个 Accelerator 实例，任何一台机器导入过的资源都可以被其他机器直接复用。在 CI 环境中部署 Accelerator 可以将首次构建后的增量构建时间缩短 50-80%。


public static class CIBuildOptimizer
{
    public static void ConfigureForCI()
    {
        EditorPrefs.SetString(
            "CacheServerIPAddress", "accelerator.internal:10443");
        EditorPrefs.SetInt("CacheServerMode", 2);

        EditorSettings.spritePackerMode =
            SpritePackerMode.AlwaysOnAtlas;
        EditorSettings.asyncShaderCompilation = false;

        PlayerSettings.stripEngineCode = true;
        PlayerSettings.SetManagedStrippingLevel(
            BuildTargetGroup.Android,
            ManagedStrippingLevel.Medium);
    }

    public static void CleanupBeforeBuild()
    {
        AssetDatabase.ReleaseCachedFileHandles();
        GC.Collect();
    }
}
自托管 Runner 是另一个重要的加速手段。云端 CI 每次启动都是全新的环境，而自托管 Runner 可以保持 Library 缓存和 Unity Accelerator 的本地数据，大幅减少资源导入时间。对于需要频繁构建的团队，投资自托管硬件的回报非常显著。


小结
    

  • CI/CD 将 Unity 构建、测试、发布流程自动化，GitHub Actions + GameCI 是最流行的方案
    • 

  • Library 缓存是加速构建的第一优先级，配合 Unity Accelerator 可缩短 50-80% 增量构建时间
    • 

  • Unity Test Framework 支持 EditMode 和 PlayMode 测试，CI 中自动运行可前置发现回归
    • 

  • 自动化版本管理通过环境变量注入版本号，配合 Git 标签触发发布构建
    • 

  • Fastlane 集成实现 Google Play 和 App Store 的自动化发布
    • 

  • 自托管 Runner 保持本地缓存，是高频构建团队的最佳投资
