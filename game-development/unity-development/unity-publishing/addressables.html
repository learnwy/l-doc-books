Addressables 资源管理

核心概念

Unity Addressables 是新一代资源管理系统，替代传统的 Resources 文件夹和 AssetBundle 手动管理方案。Addressables 通过逻辑地址（Address）引用资源，将资源的加载位置（本地、远程 CDN）与代码逻辑解耦。开发者只需通过地址或标签请求资源，系统自动处理依赖解析、下载、缓存和内存管理。

Addressables 建立在 AssetBundle 之上，但提供了更高层的抽象：自动依赖管理、引用计数、异步加载 API、资源分析工具和热更新能力。这使得资源管理从手动维护 AssetBundle 的依赖图简化为配置 Group 和 Profile。

Group 与 Profile 配置

Addressables Group 定义了一组资源的打包策略和加载位置。Group Schema 配置决定了 AssetBundle 的压缩方式、加载路径、缓存行为等参数。合理的 Group 划分是资源管理效率的关键——粒度太粗导致加载冗余，粒度太细导致请求过多。

Profile 定义了不同环境下的路径变量（如 LocalBuildPath、RemoteLoadPath），通过切换 Profile 可以在本地测试和线上发布间无缝切换，不需要修改任何 Group 配置。

using UnityEditor;
using UnityEditor.AddressableAssets;
using UnityEditor.AddressableAssets.Settings;
using UnityEditor.AddressableAssets.Settings.GroupSchemas;

public static class AddressableGroupSetup
{
    public static AddressableAssetGroup CreateRemoteGroup(
        AddressableAssetSettings settings, string groupName)
    {
        var group = settings.CreateGroup(
            groupName, false, false, false, null,
            typeof(BundledAssetGroupSchema),
            typeof(ContentUpdateGroupSchema)
        );

        var schema = group.GetSchema<BundledAssetGroupSchema>();
        schema.BuildPath.SetVariableByName(
            settings, AddressableAssetSettings.kRemoteBuildPath);
        schema.LoadPath.SetVariableByName(
            settings, AddressableAssetSettings.kRemoteLoadPath);
        schema.BundleMode =
            BundledAssetGroupSchema.BundlePackingMode.PackSeparately;
        schema.Compression =
            BundledAssetGroupSchema.BundleCompressionMode.LZ4;
        schema.UseAssetBundleCrc = true;

        return group;
    }

    public static void ConfigureProfile(
        AddressableAssetSettings settings, string profileName,
        string remoteBuildPath, string remoteLoadPath)
    {
        var profileId = settings.profileSettings
            .GetProfileId(profileName);
        if (string.IsNullOrEmpty(profileId))
            profileId = settings.profileSettings
                .AddProfile(profileName, null);

        settings.profileSettings.SetValue(
            profileId, "RemoteBuildPath", remoteBuildPath);
        settings.profileSettings.SetValue(
            profileId, "RemoteLoadPath", remoteLoadPath);
    }
}

推荐的 Group 划分策略：按功能模块分组（UI、角色、场景、音频）；频繁更新的资源单独成组方便热更新；大型资源（视频、高清贴图）单独成组按需加载；共享依赖资源（通用材质、Shader）放在独立的共享组避免重复打包。

异步加载与引用计数

Addressables 的所有加载操作都是异步的，返回 AsyncOperationHandle 对象。通过 handle.Completed 回调或 await handle.Task 获取加载结果。每次加载操作会增加资源的引用计数，调用 Release 减少引用计数，当计数归零时系统自动卸载 AssetBundle 释放内存。

using UnityEngine;
using UnityEngine.AddressableAssets;
using UnityEngine.ResourceManagement.AsyncOperations;
using System.Collections.Generic;
using System.Threading.Tasks;

public class AddressableLoader : MonoBehaviour
{
    private readonly List<AsyncOperationHandle> _handles = new(32);

    public async Task<T> LoadAssetAsync<T>(string address) where T : Object
    {
        var handle = Addressables.LoadAssetAsync<T>(address);
        _handles.Add(handle);
        await handle.Task;

        if (handle.Status == AsyncOperationStatus.Succeeded)
            return handle.Result;

        Debug.LogError($"Failed to load: {address}");
        return null;
    }

    public async Task<GameObject> InstantiateAsync(
        string address, Transform parent = null)
    {
        var handle = Addressables.InstantiateAsync(address, parent);
        _handles.Add(handle);
        await handle.Task;
        return handle.Result;
    }

    public async Task<IList<T>> LoadByLabelAsync<T>(string label)
        where T : Object
    {
        var handle = Addressables.LoadAssetsAsync<T>(
            label, null);
        _handles.Add(handle);
        await handle.Task;
        return handle.Result;
    }

    public void ReleaseAll()
    {
        foreach (var handle in _handles)
        {
            if (handle.IsValid())
                Addressables.Release(handle);
        }
        _handles.Clear();
    }

    private void OnDestroy()
    {
        ReleaseAll();
    }
}

    A[LoadAssetAsync] --> B[引用计数 +1]
    B --> C[使用资源]
    C --> D[Release]
    D --> E[引用计数 -1]
    E --> F{计数 = 0?}
    F -->|是| G[卸载 AssetBundle]

    I[InstantiateAsync] --> B
    J[LoadByLabel] --> B
    K[内存泄漏] --> L[忘记 Release]

引用计数管理是 Addressables 最容易出错的环节。每一次 Load 必须对应一次 Release，否则资源永远不会释放。推荐在 MonoBehaviour 的 OnDestroy 中统一释放所有加载的资源。对于通过 InstantiateAsync 创建的 GameObject，可以使用 Addressables.ReleaseInstance 在销毁时自动处理引用计数。

内容更新与热更新

Addressables 的内容更新（Content Update）机制允许在不重新发布安装包的情况下更新游戏资源。第一次完整构建会生成 addressables_content_state.bin 文件，后续更新构建基于此文件检测变更的资源，只重新打包变更的 AssetBundle。

热更新的工作流程是：修改资源 → Check for Content Update Restrictions → Build Update → 上传变更的 Bundle 到 CDN → 客户端自动检测并下载更新。标记为 Can Change Post Release 的 Group 中的资源可以在不更新安装包的前提下替换。

using UnityEngine;
using UnityEngine.AddressableAssets;
using UnityEngine.AddressableAssets.ResourceLocators;
using UnityEngine.ResourceManagement.AsyncOperations;
using System.Collections.Generic;

public class ContentUpdater : MonoBehaviour
{
    public async void CheckForUpdates()
    {
        var checkHandle = Addressables.CheckForCatalogUpdates(false);
        await checkHandle.Task;

        List<string> catalogs = new(checkHandle.Result);
        Addressables.Release(checkHandle);

        if (catalogs.Count > 0)
        {
            var updateHandle =
                Addressables.UpdateCatalogs(catalogs, false);
            await updateHandle.Task;

            foreach (IResourceLocator locator in updateHandle.Result)
            {
                Debug.Log($"Updated catalog: {locator.LocatorId}, " +
                          $"Keys: {locator.Keys.Count()}");
            }

            Addressables.Release(updateHandle);
        }
    }

    public async Task<long> GetDownloadSize(string label)
    {
        var sizeHandle = Addressables.GetDownloadSizeAsync(label);
        await sizeHandle.Task;
        long size = sizeHandle.Result;
        Addressables.Release(sizeHandle);
        return size;
    }

    public async Task PredownloadAssets(string label)
    {
        var handle = Addressables.DownloadDependenciesAsync(label);

        while (!handle.IsDone)
        {
            float progress = handle.PercentComplete;
            UpdateProgressUI(progress);
            await Task.Yield();
        }

        Addressables.Release(handle);
    }

    private void UpdateProgressUI(float progress) { }
}

  root((Addressables))
    核心架构

    最佳实践
      避免引用泄漏
      预下载策略
      共享依赖分组
  • Addressables 通过逻辑地址解耦资源引用与物理位置，替代 Resources 和手动 AssetBundle 管理
  • Group 划分按功能模块分组，频繁更新资源独立成组，共享依赖放入共享组避免重复
  • 所有加载操作异步执行并管理引用计数，每次 Load 必须对应 Release 防止内存泄漏
  • 内容更新机制基于 content_state.bin 文件检测变更，只重新打包修改的 Bundle
  • Profile 实现本地测试和线上部署的路径无缝切换，不需要修改 Group 配置
  • 预下载（DownloadDependenciesAsync）配合进度 UI 可实现后台资源预加载
