构建管线

核心概念

Unity 构建管线（Build Pipeline）是将项目资源、脚本和配置打包为可执行文件的完整流程。从编辑器中点击 Build 到生成最终安装包，中间经历了脚本编译、资源处理、Shader 编译、代码裁剪、打包压缩等多个阶段。理解构建管线的每个阶段，是优化构建速度、控制包体大小、排查构建错误的基础。

graph TD
    A[Build 触发] --> B[脚本编译]
    B --> C[资源导入与处理]
    C --> D[Shader 编译]
    D --> E[场景处理]
    E --> F[代码裁剪 Stripping]
    F --> G[IL2CPP 转换]
    G --> H[原生编译]
    H --> I[打包与签名]
    I --> J[输出安装包]
    K[BuildPlayerOptions] --> A
    L[Build Report] --> J
构建阶段 耗时占比 影响因素 优化手段
脚本编译 10-15% 程序集数量、代码量 Assembly Definition 分割
资源导入 15-25% 纹理、模型数量 Asset Import Pipeline v2 缓存
Shader 编译 20-40% Shader 变体数量 变体剥离、预热缓存
IL2CPP 转换 15-30% 泛型使用、代码量 增量构建、裁剪级别
打包压缩 5-10% 资源总量 LZ4 压缩替代 LZMA

构建脚本自动化

BuildPipeline.BuildPlayer 是 Unity 提供的核心构建 API，通过 BuildPlayerOptions 配置构建参数。在团队协作中，将构建流程脚本化可以确保每次构建的一致性，消除人工操作失误。

构建脚本通常放在 Editor 文件夹下，通过菜单项或命令行触发。BuildPlayerOptions 可以指定目标平台、场景列表、输出路径、构建选项（开发版、调试符号、压缩方式）等参数。

using UnityEditor;
using UnityEditor.Build.Reporting;
using UnityEngine;

public static class BuildAutomation
{
    [MenuItem("Build/Android Release")]
    public static void BuildAndroidRelease()
    {
        var options = new BuildPlayerOptions
        {
            scenes = GetEnabledScenes(),
            locationPathName = "Builds/Android/game.apk",
            target = BuildTarget.Android,
            options = BuildOptions.CompressWithLz4HC
        };

        ConfigureAndroidSettings();
        ExecuteBuild(options);
    }

    [MenuItem("Build/iOS Release")]
    public static void BuildIOSRelease()
    {
        var options = new BuildPlayerOptions
        {
            scenes = GetEnabledScenes(),
            locationPathName = "Builds/iOS",
            target = BuildTarget.iOS,
            options = BuildOptions.CompressWithLz4
        };

        ConfigureIOSSettings();
        ExecuteBuild(options);
    }

    private static void ExecuteBuild(BuildPlayerOptions options)
    {
        BuildReport report = BuildPipeline.BuildPlayer(options);
        BuildSummary summary = report.summary;

        if (summary.result == BuildResult.Succeeded)
        {
            Debug.Log($"Build succeeded: {summary.totalSize / 1024 / 1024}MB " +
                      $"in {summary.totalTime.TotalMinutes:F1}min");
        }
        else
        {
            Debug.LogError($"Build failed: {summary.result}");
            foreach (var step in report.steps)
            {
                foreach (var msg in step.messages)
                {
                    if (msg.type == LogType.Error)
                        Debug.LogError($"[{step.name}] {msg.content}");
                }
            }
        }
    }

    private static string[] GetEnabledScenes()
    {
        return System.Array.ConvertAll(
            EditorBuildSettings.scenes,
            s => s.path
        );
    }

    private static void ConfigureAndroidSettings()
    {
        PlayerSettings.Android.targetArchitectures =
            AndroidArchitecture.ARM64;
        PlayerSettings.SetScriptingBackend(
            BuildTargetGroup.Android, ScriptingImplementation.IL2CPP);
        EditorUserBuildSettings.androidBuildSystem =
            AndroidBuildSystem.Gradle;
    }

    private static void ConfigureIOSSettings()
    {
        PlayerSettings.SetScriptingBackend(
            BuildTargetGroup.iOS, ScriptingImplementation.IL2CPP);
        PlayerSettings.iOS.appleEnableAutomaticSigning = true;
    }
}

通过命令行调用构建脚本是 CI/CD 集成的基础。Unity 提供 -executeMethod 参数指定要执行的静态方法，配合 -batchmode 和 -nographics 实现无界面构建。

Shader 变体管理

Shader 变体（Shader Variants）是构建时间和包体大小的最大元凶之一。Unity 的 Shader 系统通过 multi_compile 和 shader_feature 关键字为不同的功能组合生成变体。一个包含 10 个关键字的 Shader，理论上会产生 2^10 = 1024 个变体。

shader_feature 只编译实际被材质引用的变体，而 multi_compile 会编译所有组合。在自定义 Shader 中应尽量使用 shader_feature 替代 multi_compile。Unity 的 URP/HDRP 内置 Shader 使用大量 multi_compile，可以通过 Shader Stripping 配置剥离不需要的变体。

using UnityEditor.Build;
using UnityEditor.Rendering;
using UnityEngine;
using UnityEngine.Rendering;
using System.Collections.Generic;

public class ShaderVariantStripper : IPreprocessShaders
{
    public int callbackOrder => 0;

    private static readonly ShaderKeyword FogLinear =
        new("FOG_LINEAR");
    private static readonly ShaderKeyword FogExp =
        new("FOG_EXP");
    private static readonly ShaderKeyword FogExp2 =
        new("FOG_EXP2");
    private static readonly ShaderKeyword InstancingOn =
        new("INSTANCING_ON");

    public void OnProcessShader(
        Shader shader, ShaderSnippetData snippet,
        IList<ShaderCompilerData> data)
    {
        for (int i = data.Count - 1; i >= 0; i--)
        {
            bool strip = false;

            if (data[i].shaderKeywordSet.IsEnabled(FogExp))
                strip = true;
            if (data[i].shaderKeywordSet.IsEnabled(FogExp2))
                strip = true;

            if (snippet.passType == PassType.Meta)
                strip = true;

            if (strip)
                data.RemoveAt(i);
        }
    }
}

代码裁剪与 IL2CPP

IL2CPP（Intermediate Language To C++）将 C# IL 代码转换为 C++ 代码再编译为原生机器码。与 Mono 相比，IL2CPP 提供更好的运行时性能和更小的包体，但构建时间显著增加。iOS 平台强制使用 IL2CPP。

代码裁剪（Managed Stripping Level）在 IL2CPP 转换前移除未使用的代码。裁剪级别从低到高分为 Minimal、Low、Medium、High。更高的裁剪级别意味着更小的包体，但也更容易因反射调用被误裁而导致运行时崩溃。

using System;
using UnityEngine;
using UnityEngine.Scripting;

[Preserve]
public class ReflectionSafeClass
{
    [Preserve]
    public void DynamicMethod()
    {
        Debug.Log("This method is called via reflection");
    }
}

public static class LinkXmlHelper
{
    public static string GenerateLinkXml(Type[] preserveTypes)
    {
        var sb = new System.Text.StringBuilder();
        sb.AppendLine("<linker>");
        foreach (var type in preserveTypes)
        {
            sb.AppendLine($"  <assembly fullname=\"{type.Assembly.GetName().Name}\">");
            sb.AppendLine($"    <type fullname=\"{type.FullName}\" preserve=\"all\"/>");
            sb.AppendLine("  </assembly>");
        }
        sb.AppendLine("</linker>");
        return sb.ToString();
    }
}
裁剪级别 包体减小 风险等级 适用场景
Minimal 5-10% 极低 开发调试
Low 15-25% 低 安全发布
Medium 25-40% 中 推荐默认
High 40-60% 高 极致包体优化

构建报告与包体分析

Build Report 提供了构建过程的详细信息，包括每个资源的大小、构建步骤耗时、警告和错误信息。通过分析 Build Report 可以精确定位包体膨胀的原因和构建耗时的瓶颈。

Unity 编辑器日志（Editor.log）中包含构建完成后的资源分类统计，按类型汇总了纹理、网格、音频、Shader、脚本等各类资源的占比。第三方工具如 Build Report Inspector 可以可视化展示这些数据。

using UnityEditor;
using UnityEditor.Build.Reporting;
using System.Linq;
using UnityEngine;

public static class BuildAnalyzer
{
    public static void AnalyzeReport(BuildReport report)
    {
        var packedAssets = report.packedAssets;
        foreach (var pack in packedAssets)
        {
            Debug.Log($"Pack: {pack.shortPath}, Contents: {pack.contents.Length}");

            var topAssets = pack.contents
                .OrderByDescending(a => a.packedSize)
                .Take(20);

            foreach (var asset in topAssets)
            {
                float sizeMB = asset.packedSize / (1024f * 1024f);
                Debug.Log($"  {sizeMB:F2}MB - {asset.sourceAssetPath}");
            }
        }

        var summary = report.summary;
        Debug.Log($"Total Size: {summary.totalSize / 1024 / 1024}MB");
        Debug.Log($"Total Time: {summary.totalTime.TotalMinutes:F1}min");
        Debug.Log($"Warnings: {summary.totalWarnings}");
        Debug.Log($"Errors: {summary.totalErrors}");
    }
}
