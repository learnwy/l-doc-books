ScriptableObject 数据架构

核心概念

ScriptableObject 是 Unity 中一种不依赖 GameObject 的数据容器类。与 MonoBehaviour 必须挂载在场景对象上不同，ScriptableObject 作为独立的资源文件存在于 Project 面板中，可以跨场景共享、编辑器中持久化，并且在运行时多个对象引用同一份数据实例。这种设计天然适合存储游戏配置、共享运行时状态和构建数据驱动的架构。

数据配置容器
ScriptableObject 最基础的用途是作为数据配置容器，将游戏参数从代码中抽离到可编辑的资源文件中。通过 CreateAssetMenu 特性，可以在 Project 面板的右键菜单中快速创建数据资产。


using UnityEngine;

[CreateAssetMenu(fileName = "NewWeaponData", menuName = "Game/Weapon Data")]
public class WeaponData : ScriptableObject
{
    [Header("基础属性")]
    public string weaponName;
    public Sprite icon;
    public GameObject prefab;

    [Header("战斗数值")]
    [Range(1, 100)]
    public int damage = 10;
    public float attackSpeed = 1f;
    public float attackRange = 2f;

    [Header("弹药设置")]
    public bool usesAmmo;
    public int maxAmmo = 30;
    public float reloadTime = 2f;

    [Header("音效")]
    public AudioClip fireSound;
    public AudioClip reloadSound;

    public float DPS => damage * attackSpeed;
}
使用数据配置的组件只需持有 ScriptableObject 的引用，通过 Inspector 拖拽不同的数据资产即可切换武器属性，无需修改任何代码：


using UnityEngine;

public class WeaponController : MonoBehaviour
{
    [SerializeField] private WeaponData weaponData;

    private int currentAmmo;
    private float nextAttackTime;

    private void Awake()
    {
        currentAmmo = weaponData.maxAmmo;
    }

    public void Attack()
    {
        if (Time.time < nextAttackTime) return;

        if (weaponData.usesAmmo && currentAmmo <= 0) return;

        PerformAttack();
        nextAttackTime = Time.time + 1f / weaponData.attackSpeed;

        if (weaponData.usesAmmo)
        {
            currentAmmo--;
        }
    }

    private void PerformAttack()
    {
        Debug.Log($"{weaponData.weaponName} 造成 {weaponData.damage} 点伤害");
    }
}
这种模式的核心优势在于：100 个相同类型的敌人引用同一份 WeaponData 资产，修改该资产后所有敌人的行为立即更新，且只占用一份内存。


运行时共享状态
ScriptableObject 不仅可以存储静态配置，还能作为运行时的共享状态容器。多个系统通过引用同一个 SO 实例来读写共享数据，实现了无需直接引用彼此的间接通信。


using UnityEngine;

[CreateAssetMenu(menuName = "Runtime/Player Runtime Data")]
public class PlayerRuntimeData : ScriptableObject
{
    [Header("生命值")]
    public float currentHealth;
    public float maxHealth = 100f;

    [Header("资源")]
    public int coins;
    public int experience;
    public int level;

    [Header("位置")]
    public Vector3 lastCheckpoint;

    public float HealthPercent => maxHealth > 0 ? currentHealth / maxHealth : 0f;

    public void Reset()
    {
        currentHealth = maxHealth;
        coins = 0;
        experience = 0;
        level = 1;
        lastCheckpoint = Vector3.zero;
    }

    private void OnEnable()
    {
        Reset();
    }
}
多个系统通过 Inspector 引用同一个 PlayerRuntimeData 资产，战斗系统修改血量后 UI 系统自动读到最新值：


using UnityEngine;
using UnityEngine.UI;

public class PlayerHUD : MonoBehaviour
{
    [SerializeField] private PlayerRuntimeData playerData;
    [SerializeField] private Slider healthSlider;
    [SerializeField] private Text coinText;
    [SerializeField] private Text levelText;

    private void Update()
    {
        healthSlider.value = playerData.HealthPercent;
        coinText.text = playerData.coins.ToString();
        levelText.text = $"Lv.{playerData.level}";
    }
}
需要注意的关键点：ScriptableObject 在编辑器中的修改是持久的（会写入 .asset 文件），但在构建后的运行时修改只在当前会话有效，退出游戏后恢复原值。通过 OnEnable 中的 Reset 方法可以确保每次进入游戏都是干净的初始状态。


枚举式 ScriptableObject
利用 ScriptableObject 的引用语义，可以替代传统枚举实现可扩展的类型系统。每个"枚举值"是一个独立的 SO 资产，新增类型只需创建新资产而无需修改代码。


using UnityEngine;

[CreateAssetMenu(menuName = "Game/Element Type")]
public class ElementType : ScriptableObject
{
    public string displayName;
    public Color color;
    public Sprite icon;
    public float damageMultiplier = 1f;
}

[CreateAssetMenu(menuName = "Game/Damage Type Relation")]
public class DamageRelation : ScriptableObject
{
    [System.Serializable]
    public struct Effectiveness
    {
        public ElementType attackerElement;
        public ElementType defenderElement;
        [Range(0f, 3f)]
        public float multiplier;
    }

    [SerializeField] private Effectiveness[] relations;

    public float GetMultiplier(ElementType attacker, ElementType defender)
    {
        foreach (var relation in relations)
        {
            if (relation.attackerElement == attacker &&
                relation.defenderElement == defender)
            {
                return relation.multiplier;
            }
        }
        return 1f;
    }
}

工厂与策略模式
ScriptableObject 天然适合实现工厂模式和策略模式，将行为逻辑封装在可替换的资产中。通过定义抽象基类，不同的 SO 资产可以实现不同的行为策略。


using UnityEngine;

public abstract class AttackStrategy : ScriptableObject
{
    public abstract void Execute(Transform attacker, Transform target, int damage);
}

[CreateAssetMenu(menuName = "Strategies/Melee Attack")]
public class MeleeAttackStrategy : AttackStrategy
{
    [SerializeField] private float hitRadius = 1.5f;
    [SerializeField] private GameObject hitEffectPrefab;

    public override void Execute(Transform attacker, Transform target, int damage)
    {
        float dist = Vector3.Distance(attacker.position, target.position);
        if (dist <= hitRadius)
        {
            var damageable = target.GetComponent<IDamageable>();
            damageable?.TakeDamage(damage);

            if (hitEffectPrefab != null)
            {
                Object.Instantiate(hitEffectPrefab, target.position, Quaternion.identity);
            }
        }
    }
}

[CreateAssetMenu(menuName = "Strategies/Ranged Attack")]
public class RangedAttackStrategy : AttackStrategy
{
    [SerializeField] private GameObject projectilePrefab;
    [SerializeField] private float projectileSpeed = 20f;

    public override void Execute(Transform attacker, Transform target, int damage)
    {
        if (projectilePrefab == null) return;

        var go = Object.Instantiate(projectilePrefab, attacker.position, attacker.rotation);
        var proj = go.GetComponent<Projectile>();
        proj.Initialize(target, damage, projectileSpeed);
    }
}
使用策略的组件通过 Inspector 切换不同的攻击行为，同一个敌人类可以轻松配置为近战或远程：


using UnityEngine;

public class EnemyAI : MonoBehaviour
{
    [SerializeField] private AttackStrategy attackStrategy;
    [SerializeField] private int baseDamage = 10;

    private Transform currentTarget;

    public void PerformAttack()
    {
        if (currentTarget == null) return;
        attackStrategy.Execute(transform, currentTarget, baseDamage);
    }
}
小结
    

  • ScriptableObject 是不依赖 GameObject 的数据容器，作为资源文件存在于 Project 中
    • 

  • 作为数据配置容器，多个对象引用同一份数据实现内存共享和集中管理
    • 

  • 作为运行时共享状态，多个系统通过同一个 SO 实例间接通信，实现松耦合
    • 

  • 枚举式 SO 通过创建新资产扩展类型系统，比 C# enum 更灵活
    • 

  • 策略模式中 SO 封装可替换的行为逻辑，通过 Inspector 配置不同策略
    • 

  • 编辑器中修改 SO 会持久化，但构建后运行时修改仅在当前会话有效
    •
