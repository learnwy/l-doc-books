MonoBehaviour 生命周期

核心概念

MonoBehaviour 是 Unity 脚本系统的基础类，所有挂载在 GameObject 上的用户脚本都继承自它。MonoBehaviour 定义了一套完整的生命周期回调方法，这些方法由 Unity 引擎在特定时机自动调用，开发者通过重写这些方法来实现游戏逻辑。理解生命周期的执行顺序与时机，是编写正确、高效 Unity 脚本的前提。

Awake 与 Start 的执行时机
Awake 和 Start 是最常用的两个初始化方法，但它们的调用时机和用途有本质区别。Awake 在脚本实例被加载时立即调用（即使脚本组件处于禁用状态），而 Start 仅在脚本第一次启用后的第一帧 Update 之前调用。


这种分离设计遵循了"先准备、后启动"的模式。Awake 用于建立对象自身的内部引用关系，Start 用于建立对象之间的外部依赖关系。这确保了当 Start 执行时，所有对象的 Awake 已经完成。


using UnityEngine;

public class WeaponSystem : MonoBehaviour
{
    private AudioSource audioSource;
    private ParticleSystem muzzleFlash;
    private AmmoManager ammoManager;

    private void Awake()
    {
        audioSource = GetComponent<AudioSource>();
        muzzleFlash = GetComponentInChildren<ParticleSystem>();
    }

    private void Start()
    {
        ammoManager = FindFirstObjectByType<AmmoManager>();
        ammoManager.RegisterWeapon(this);
    }
}

在多脚本协作场景中，可以通过 Script Execution Order（Edit → Project Settings → Script Execution Order）手动设置脚本的执行优先级，确保关键系统的初始化顺序可控。


Update、FixedUpdate 与 LateUpdate
Unity 的三个更新方法服务于不同的更新需求。Update 每帧调用一次，帧率不固定；FixedUpdate 按固定时间间隔调用（默认 0.02 秒），与物理引擎同步；LateUpdate 在所有 Update 完成后调用，适合需要在其他逻辑之后执行的操作。


FixedUpdate 与 Update 的帧率差异会导致一帧内 FixedUpdate 执行多次或零次。在低帧率场景下，一帧可能触发多次 FixedUpdate 来追赶物理模拟进度。


using UnityEngine;

public class PlayerController : MonoBehaviour
{
    [SerializeField] private float moveSpeed = 5f;
    [SerializeField] private float jumpForce = 8f;

    private Rigidbody rb;
    private Vector3 moveInput;
    private bool jumpRequested;

    private void Awake()
    {
        rb = GetComponent<Rigidbody>();
    }

    private void Update()
    {
        float h = Input.GetAxisRaw("Horizontal");
        float v = Input.GetAxisRaw("Vertical");
        moveInput = new Vector3(h, 0f, v).normalized;

        if (Input.GetButtonDown("Jump"))
        {
            jumpRequested = true;
        }
    }

    private void FixedUpdate()
    {
        rb.MovePosition(rb.position + moveInput * moveSpeed * Time.fixedDeltaTime);

        if (jumpRequested)
        {
            rb.AddForce(Vector3.up * jumpForce, ForceMode.Impulse);
            jumpRequested = false;
        }
    }
}
相机跟随是 LateUpdate 的经典应用场景。如果在 Update 中更新相机位置，可能会因为目标对象尚未移动而导致画面抖动：


using UnityEngine;

public class CameraFollow : MonoBehaviour
{
    [SerializeField] private Transform target;
    [SerializeField] private Vector3 offset = new Vector3(0f, 5f, -10f);
    [SerializeField] private float smoothSpeed = 0.125f;

    private void LateUpdate()
    {
        if (target == null) return;

        Vector3 desiredPosition = target.position + offset;
        Vector3 smoothed = Vector3.Lerp(transform.position, desiredPosition, smoothSpeed);
        transform.position = smoothed;
        transform.LookAt(target);
    }
}
OnEnable 与 OnDisable 的对称设计
OnEnable 和 OnDisable 是一对对称的回调方法。每次脚本组件被启用时调用 OnEnable，被禁用时调用 OnDisable。与 Awake/Start 不同，这两个方法在对象的生命周期内可以被多次触发，适合管理需要反复开启和关闭的功能。


事件订阅与注销是 OnEnable/OnDisable 最典型的应用场景。在 OnEnable 中订阅事件，在 OnDisable 中注销，可以避免因对象禁用后仍然接收事件而导致空引用异常：


using UnityEngine;

public class DamageReceiver : MonoBehaviour
{
    [SerializeField] private int maxHealth = 100;
    private int currentHealth;

    private void Awake()
    {
        currentHealth = maxHealth;
    }

    private void OnEnable()
    {
        EventBus.OnDamageDealt += HandleDamage;
        EventBus.OnHealApplied += HandleHeal;
    }

    private void OnDisable()
    {
        EventBus.OnDamageDealt -= HandleDamage;
        EventBus.OnHealApplied -= HandleHeal;
    }

    private void HandleDamage(int damage)
    {
        currentHealth = Mathf.Max(0, currentHealth - damage);
        if (currentHealth <= 0)
        {
            gameObject.SetActive(false);
        }
    }

    private void HandleHeal(int amount)
    {
        currentHealth = Mathf.Min(maxHealth, currentHealth + amount);
    }
}
对象池模式中，对象通过 SetActive(true/false) 反复激活和休眠，此时 OnEnable/OnDisable 会反复触发。利用这一特性可以在对象"复活"时重置状态：

物理回调与碰撞检测
Unity 的物理系统提供了一组专用的生命周期回调，用于处理碰撞和触发器事件。这些回调在 FixedUpdate 之后、Update 之前执行，确保物理状态已经更新完毕。


碰撞回调分为两类：Collision 系列（OnCollisionEnter/Stay/Exit）用于具有物理碰撞响应的对象，Trigger 系列（OnTriggerEnter/Stay/Exit）用于设置了 Is Trigger 的碰撞体。


using UnityEngine;

public class Projectile : MonoBehaviour
{
    [SerializeField] private int damage = 25;
    [SerializeField] private float lifetime = 5f;
    [SerializeField] private GameObject hitEffectPrefab;

    private void OnEnable()
    {
        Invoke(nameof(Deactivate), lifetime);
    }

    private void OnDisable()
    {
        CancelInvoke();
    }

    private void OnCollisionEnter(Collision collision)
    {
        var damageable = collision.gameObject.GetComponent<IDamageable>();
        damageable?.TakeDamage(damage);

        if (hitEffectPrefab != null)
        {
            ContactPoint contact = collision.GetContact(0);
            Instantiate(hitEffectPrefab, contact.point, Quaternion.LookRotation(contact.normal));
        }

        Deactivate();
    }

    private void OnTriggerEnter(Collider other)
    {
        if (other.CompareTag("PickupZone"))
        {
            other.GetComponent<IPickupHandler>()?.OnPickup(gameObject);
        }
    }

    private void Deactivate()
    {
        gameObject.SetActive(false);
    }
}
使用物理回调时需要确保至少一方挂载了 Rigidbody 组件，否则碰撞回调不会触发。对于不需要物理模拟的触发器检测，可以将 Rigidbody 设置为 Kinematic。


小结
    

  • Awake 和 Start 遵循"先准备、后启动"模式，Awake 处理自身引用，Start 处理跨对象依赖
    • 

  • FixedUpdate 与物理引擎同步，Update 每帧调用，LateUpdate 在所有 Update 之后执行
    • 

  • OnEnable/OnDisable 是对称的启用/禁用回调，适合事件订阅管理和对象池模式
    • 

  • 物理回调区分 Collision（碰撞响应）和 Trigger（触发检测）两类，需要 Rigidbody 组件支持
    • 

  • Script Execution Order 可以控制多脚本的初始化优先级
    • 

  • 在正确的生命周期阶段执行正确的操作，是避免竞态条件和空引用的关键
