内存优化

核心概念

Unity 内存管理分为托管内存（Managed Memory）和原生内存（Native Memory）两大体系。托管内存由 Mono/IL2CPP 运行时通过垃圾回收（GC）机制管理，原生内存由 Unity 引擎底层直接分配和释放。内存优化的核心目标是减少总内存占用、降低 GC 频率和耗时、避免内存泄漏。在移动平台上，内存是最稀缺的资源之一，iOS 设备在内存压力过大时会直接终止应用。

GC 优化策略
Unity 使用 Boehm GC（非分代、非压缩式回收器），每次 GC 需要遍历整个托管堆，暂停所有脚本线程。在 IL2CPP 后端下可启用增量式 GC（Incremental GC），将回收工作分散到多帧执行，降低单帧卡顿。


减少 GC 分配是最有效的优化手段。每一次堆内存分配都会增加下次 GC 的工作量。常见的隐式分配包括字符串拼接、LINQ 查询、协程中的 yield return new、装箱操作等。


public class GCOptimization : MonoBehaviour
{
    private readonly List<Enemy> _enemyBuffer = new(64);
    private readonly StringBuilder _sb = new(256);
    private readonly WaitForSeconds _waitOneSecond = new(1f);
    private readonly Dictionary<string, GameObject> _poolDict = new(32);

    private void Update()
    {
        _enemyBuffer.Clear();
        FindEnemiesNonAlloc(_enemyBuffer);

        _sb.Clear();
        _sb.Append("Score: ");
        _sb.Append(score);
        scoreText.SetText(_sb);
    }

    private IEnumerator SpawnRoutine()
    {
        while (true)
        {
            SpawnEnemy();
            yield return _waitOneSecond;
        }
    }

    private void FindEnemiesNonAlloc(List<Enemy> results)
    {
        int count = Physics.OverlapSphereNonAlloc(
            transform.position, 10f, _colliderBuffer
        );
        for (int i = 0; i < count; i++)
        {
            if (_colliderBuffer[i].TryGetComponent<Enemy>(out var enemy))
                results.Add(enemy);
        }
    }
}
关键的 GC 优化规则包括：预分配集合容量避免扩容分配；使用 StringBuilder 替代字符串拼接；缓存 WaitForSeconds 等 yield 指令对象；使用 NonAlloc 版本的物理查询 API；避免在 Update 中使用 LINQ 或闭包表达式。


对象池与内存复用
对象池（Object Pool）是游戏开发中最重要的内存优化模式。频繁创建和销毁 GameObject 不仅产生 GC 压力，还会触发引擎底层的资源分配和初始化开销。对象池通过预创建一批对象并循环复用，彻底消除运行时的实例化开销。


Unity 2021+ 提供了内置的 ObjectPool 泛型实现，支持自定义创建、获取、释放和销毁回调。对于 GameObject 池化，需要注意在释放时重置对象状态、禁用而非销毁、管理父物体层级。


using UnityEngine;
using UnityEngine.Pool;

public class BulletPool : MonoBehaviour
{
    [SerializeField] private GameObject bulletPrefab;
    [SerializeField] private int defaultCapacity = 50;
    [SerializeField] private int maxSize = 200;

    private ObjectPool<GameObject> _pool;

    private void Awake()
    {
        _pool = new ObjectPool<GameObject>(
            createFunc: () => Instantiate(bulletPrefab),
            actionOnGet: obj =>
            {
                obj.SetActive(true);
                obj.transform.SetParent(null);
            },
            actionOnRelease: obj =>
            {
                obj.SetActive(false);
                obj.transform.SetParent(transform);
            },
            actionOnDestroy: Destroy,
            collectionCheck: false,
            defaultCapacity: defaultCapacity,
            maxSize: maxSize
        );
    }

    public GameObject Get() => _pool.Get();

    public void Release(GameObject obj) => _pool.Release(obj);

    private void OnDestroy()
    {
        _pool.Clear();
    }
}

纹理与资源内存管理
纹理通常是游戏中内存占用最大的资源类型，一张未压缩的 2048×2048 RGBA 纹理占用 16MB 内存。合理的纹理压缩格式选择和 Mipmap 配置可以将内存占用降低 4-8 倍。


不同平台有最佳的压缩格式：iOS 使用 ASTC，Android 使用 ETC2 或 ASTC，PC 使用 BC7 或 DXT5。Mipmap 对 3D 场景中的纹理是必须的，它避免远处物体采样高分辨率纹理造成的性能浪费，但会增加约 33% 的内存。UI 纹理通常不需要 Mipmap。


public static class TextureMemoryUtil
{
    public static long EstimateTextureMemory(
        int width, int height, TextureFormat format, bool hasMipmap)
    {
        int bitsPerPixel = format switch
        {
            TextureFormat.RGBA32 => 32,
            TextureFormat.RGB24 => 24,
            TextureFormat.ASTC_6x6 => 3,
            TextureFormat.ASTC_8x8 => 2,
            TextureFormat.ETC2_RGBA8 => 8,
            TextureFormat.BC7 => 8,
            TextureFormat.DXT5 => 8,
            _ => 32
        };

        long baseSize = (long)width * height * bitsPerPixel / 8;
        return hasMipmap ? baseSize * 4 / 3 : baseSize;
    }

    public static void ConfigureTextureImport(TextureImporter importer)
    {
        importer.mipmapEnabled = !importer.textureType.Equals(TextureImporterType.Sprite);
        importer.streamingMipmaps = true;
        importer.streamingMipmapsPriority = 0;

        var platformSettings = new TextureImporterPlatformSettings
        {
            name = "iPhone",
            overridden = true,
            format = TextureImporterFormat.ASTC_6x6,
            maxTextureSize = 1024,
            compressionQuality = 50
        };
        importer.SetPlatformTextureSettings(platformSettings);
    }
}
Texture Streaming（纹理流式加载）是 Unity 提供的自动 Mipmap 管理系统。它根据相机距离动态加载合适级别的 Mipmap，而非一次性加载最高分辨率。通过 QualitySettings.streamingMipmapsMemoryBudget 设置纹理流预算，引擎会自动在预算范围内调度加载。


内存泄漏检测与诊断
内存泄漏在 Unity 中表现为两种形式：托管内存泄漏（对象虽然不再使用但仍被引用，GC 无法回收）和原生内存泄漏（资源加载后未正确卸载）。Memory Profiler 是诊断内存泄漏的核心工具，它可以捕获完整的内存快照并支持两个快照间的对比分析。


常见的泄漏场景包括：事件监听未注销导致对象被持有、静态集合持有临时对象引用、加载的资源未调用 Resources.UnloadUnusedAssets 或 AssetBundle.Unload、材质实例化后未手动销毁。


public class MemoryLeakPrevention : MonoBehaviour
{
    private Material _instancedMaterial;

    private void OnEnable()
    {
        EventManager.OnEnemyDeath += HandleEnemyDeath;
    }

    private void OnDisable()
    {
        EventManager.OnEnemyDeath -= HandleEnemyDeath;
    }

    private void Start()
    {
        _instancedMaterial = new Material(baseMaterial);
        GetComponent<Renderer>().material = _instancedMaterial;
    }

    private void OnDestroy()
    {
        if (_instancedMaterial != null)
        {
            Destroy(_instancedMaterial);
            _instancedMaterial = null;
        }
    }

    private void HandleEnemyDeath(Enemy enemy)
    {
        score += enemy.ScoreValue;
    }

    public static void ForceCleanup()
    {
        Resources.UnloadUnusedAssets();
        GC.Collect();
    }
}
小结
    

  • Unity 内存分为托管内存（GC 管理）和原生内存（引擎管理），优化策略各不相同
    • 

  • GC 优化核心是减少堆分配：预分配集合、缓存 yield 对象、使用 NonAlloc API
    • 

  • 对象池通过循环复用消除运行时实例化开销，Unity 内置 ObjectPool 简化实现
    • 

  • 纹理是内存占用最大的资源，ASTC/ETC2 压缩配合 Texture Streaming 可大幅降低占用
    • 

  • 内存泄漏通过 Memory Profiler 快照对比定位，重点检查事件监听和资源卸载
    • 

  • 移动平台内存优化是生死线，iOS 在内存压力下会直接终止应用
