物理优化

核心概念

Unity 物理系统基于 NVIDIA PhysX 引擎（3D）和 Box2D（2D），在每个固定时间步（FixedUpdate）内执行碰撞检测、约束求解和刚体积分。物理模拟是 CPU 密集型操作，在复杂场景中往往成为性能瓶颈。物理优化的核心目标是减少碰撞检测的计算量、降低约束求解的迭代次数、合理配置物理参数以在精度和性能之间取得平衡。

碰撞体优化
碰撞体的选择和配置直接决定了 Narrowphase 的计算量。基本原则是使用最简单的碰撞体形状来近似物体外形。Box、Sphere、Capsule 是基本碰撞体（Primitive Collider），PhysX 对它们有专门的快速路径优化。Mesh Collider 是最昂贵的碰撞体类型，应该尽量避免或用复合基本碰撞体替代。


对于需要精确碰撞的静态环境（如地形、建筑），可以使用凸包分解（Convex Decomposition）将一个复杂网格拆分为多个凸碰撞体。Unity 的 Mesh Collider 在勾选 Convex 选项后会自动生成凸包，但顶点数限制为 255 个。


public class ColliderOptimizer : MonoBehaviour
{
    public static void SetupCompoundCollider(GameObject target)
    {
        var meshCollider = target.GetComponent<MeshCollider>();
        if (meshCollider != null)
            DestroyImmediate(meshCollider);

        var bounds = target.GetComponent<Renderer>().bounds;

        var body = new GameObject("Body");
        body.transform.SetParent(target.transform, false);
        var box = body.AddComponent<BoxCollider>();
        box.size = bounds.size * 0.8f;

        var head = new GameObject("Head");
        head.transform.SetParent(target.transform, false);
        head.transform.localPosition = Vector3.up * bounds.size.y * 0.4f;
        var sphere = head.AddComponent<SphereCollider>();
        sphere.radius = bounds.size.x * 0.3f;
    }

    public static void OptimizeMeshCollider(MeshCollider collider)
    {
        collider.convex = true;
        collider.cookingOptions =
            MeshColliderCookingOptions.CookForFasterSimulation |
            MeshColliderCookingOptions.WeldColocatedVertices |
            MeshColliderCookingOptions.EnableMeshCleaning;
    }
}
碰撞层矩阵（Layer Collision Matrix）是最被低估的优化手段。通过 Physics Settings 配置哪些层与哪些层进行碰撞检测，可以大幅减少 Broadphase 需要处理的碰撞对数量。例如，子弹只需要与敌人和环境碰撞，不需要与其他子弹或友方单位检测。


物理查询优化
物理查询（Raycast、OverlapSphere、SphereCast 等）在 AI 感知、射击检测、视线判断等场景中频繁使用。每次查询都是一次完整的碰撞检测过程，高频调用会显著影响性能。


优化原则包括：使用 NonAlloc 版本避免 GC 分配；通过 LayerMask 限制查询范围；设置合理的最大距离；对不需要每帧更新的查询进行分帧处理；缓存查询结果。


public class PhysicsQueryOptimizer : MonoBehaviour
{
    private readonly RaycastHit[] _rayHits = new RaycastHit[16];
    private readonly Collider[] _overlapResults = new Collider[32];
    private const int EnemyLayer = 1 << 8;
    private const int EnvironmentLayer = 1 << 9;

    private int _queryFrame;
    private bool _hasLineOfSight;

    private void FixedUpdate()
    {
        if (_queryFrame % 3 == 0)
            UpdateLineOfSight();

        if (_queryFrame % 5 == 0)
            ScanNearbyEnemies();

        _queryFrame++;
    }

    private void UpdateLineOfSight()
    {
        Vector3 direction = target.position - transform.position;
        float distance = direction.magnitude;

        int hitCount = Physics.RaycastNonAlloc(
            transform.position,
            direction.normalized,
            _rayHits,
            distance,
            EnvironmentLayer
        );

        _hasLineOfSight = hitCount == 0;
    }

    private void ScanNearbyEnemies()
    {
        int count = Physics.OverlapSphereNonAlloc(
            transform.position,
            detectionRadius,
            _overlapResults,
            EnemyLayer
        );

        for (int i = 0; i < count; i++)
        {
            ProcessDetectedEnemy(_overlapResults[i]);
        }
    }
}

FixedUpdate 与时间步配置
FixedUpdate 的执行频率由 Time.fixedDeltaTime 决定，默认值为 0.02 秒（50Hz）。如果一帧的实际耗时超过 fixedDeltaTime，物理系统会在一帧内连续执行多次 FixedUpdate 来追赶时间，这种"物理堆积"会导致严重的性能恶化。


Maximum Allowed Timestep 参数限制了每帧最多执行的物理步数。将其设置为合理的值（如 0.1 秒）可以防止物理堆积失控，代价是物理模拟在低帧率时会出现慢动作效果。


public static class PhysicsConfig
{
    public static void ApplyMobileOptimized()
    {
        Time.fixedDeltaTime = 0.04f;
        Time.maximumDeltaTime = 0.1f;
        Physics.defaultSolverIterations = 4;
        Physics.defaultSolverVelocityIterations = 1;
        Physics.defaultMaxAngularSpeed = 7f;
        Physics.bounceThreshold = 2f;
        Physics.sleepThreshold = 0.05f;
        Physics.defaultContactOffset = 0.02f;
        Physics.autoSimulation = true;
    }

    public static void ApplyDesktopBalanced()
    {
        Time.fixedDeltaTime = 0.02f;
        Time.maximumDeltaTime = 0.1f;
        Physics.defaultSolverIterations = 6;
        Physics.defaultSolverVelocityIterations = 1;
        Physics.sleepThreshold = 0.005f;
    }

    public static void ApplyHighPrecision()
    {
        Time.fixedDeltaTime = 0.01f;
        Time.maximumDeltaTime = 0.05f;
        Physics.defaultSolverIterations = 12;
        Physics.defaultSolverVelocityIterations = 4;
        Physics.sleepThreshold = 0.001f;
    }
}
Solver Iterations 控制约束求解的精度。默认值为 6 次位置迭代和 1 次速度迭代。对于简单的游戏（如跑酷、射击），可以降低到 4 次位置迭代；对于需要稳定堆叠的物理模拟（如搭建类游戏），可能需要提高到 12 次以上。


休眠与空间分区
PhysX 的刚体休眠机制是重要的性能优化特性。当刚体的动能低于 sleepThreshold 并保持一段时间后，物理系统会将其标记为休眠状态，不再参与模拟计算。保持静止物体处于休眠状态可以显著降低物理系统的负载。


避免意外唤醒休眠刚体：不要对休眠物体执行 transform.position 修改（应使用 Rigidbody.MovePosition）；不要在无需物理的装饰物上添加 Rigidbody；合理设置 sleepThreshold 避免微小扰动导致反复唤醒。


public class SleepManager : MonoBehaviour
{
    [SerializeField] private float activationRadius = 30f;
    private readonly List<Rigidbody> _managedBodies = new(128);
    private Transform _playerTransform;

    private void FixedUpdate()
    {
        Vector3 playerPos = _playerTransform.position;

        for (int i = 0; i < _managedBodies.Count; i++)
        {
            Rigidbody rb = _managedBodies[i];
            float distSq = (rb.position - playerPos).sqrMagnitude;
            float thresholdSq = activationRadius * activationRadius;

            if (distSq > thresholdSq && !rb.IsSleeping())
            {
                rb.Sleep();
            }
        }
    }

    public void RegisterBody(Rigidbody rb)
    {
        rb.sleepThreshold = 0.05f;
        rb.interpolation = RigidbodyInterpolation.None;
        _managedBodies.Add(rb);
    }
}
对于大规模物理场景，使用空间分区策略将物理模拟限制在玩家附近的区域。远处的物体可以禁用 Rigidbody 和 Collider 组件，只在进入激活范围后才启用物理模拟。这种按距离分层的激活策略可以将物理系统的负载控制在恒定范围内，不随场景规模增长。


小结
    

  • 物理模拟流水线包含 Broadphase、Narrowphase、约束求解三大阶段，各有针对性优化策略
    • 

  • 碰撞体优先使用基本形状，避免 Mesh Collider；碰撞层矩阵可大幅减少检测量
    • 

  • 物理查询必须使用 NonAlloc 版本，配合 LayerMask 过滤和分帧策略降低开销
    • 

  • FixedUpdate 频率和 Solver 迭代次数需要根据游戏类型在精度和性能间平衡
    • 

  • 刚体休眠机制和距离激活策略是大规模物理场景的关键优化手段
    • 

  • 移动平台建议 25Hz 物理更新频率（fixedDeltaTime = 0.04），桌面保持默认 50Hz
    •
