GameObject 与组件系统

核心概念

Unity 的核心架构基于 GameObject-Component 模式：场景中的一切实体都是 GameObject，而 GameObject 本身只是一个空容器，其行为和表现完全由挂载的组件（Component）决定。这种组合优于继承的设计理念，是 Unity 区别于传统面向对象游戏引擎的关键特征。

GameObject 生命周期与层级关系
GameObject 在 Unity 中存在明确的生命周期：创建（Instantiate）→ 激活（SetActive）→ 存活 → 停用 → 销毁（Destroy）。通过 Hierarchy 面板可以建立父子关系，子对象的 Transform 受父对象影响。


using UnityEngine;

public class GameObjectLifecycle : MonoBehaviour
{
    [SerializeField] private GameObject enemyPrefab;

    public GameObject SpawnEnemy(Vector3 position)
    {
        GameObject enemy = Instantiate(enemyPrefab, position, Quaternion.identity);
        enemy.name = "Enemy_" + Time.frameCount;
        enemy.transform.SetParent(transform);
        return enemy;
    }

    public void DeactivateEnemy(GameObject enemy)
    {
        enemy.SetActive(false);
    }

    public void DestroyEnemy(GameObject enemy)
    {
        Destroy(enemy, 0.5f);
    }
}
父子关系是 Unity 场景组织的基础。子对象的世界坐标由父对象的 Transform 叠加自身本地 Transform 计算得出。修改父对象的位置、旋转或缩放会自动级联到所有子对象。

using UnityEngine;

public class HierarchyManager : MonoBehaviour
{
    public void ReparentAll(Transform newParent)
    {
        while (transform.childCount > 0)
        {
            transform.GetChild(0).SetParent(newParent, true);
        }
    }

    public T FindInChildren<T>(string objectName) where T : Component
    {
        Transform child = transform.Find(objectName);
        return child != null ? child.GetComponent<T>() : null;
    }
}
内置组件体系
Unity 提供了丰富的内置组件，覆盖渲染、物理、音频、UI 等各个子系统。这些组件经过高度优化，是构建游戏功能的基础积木。


渲染组件决定 GameObject 的视觉表现。MeshRenderer 配合 MeshFilter 渲染 3D 模型，SpriteRenderer 用于 2D 精灵，Camera 定义视角，Light 提供光照。


物理组件赋予 GameObject 物理行为。Rigidbody 让对象参与物理模拟，Collider 定义碰撞形状，两者配合实现真实的物理交互。


using UnityEngine;

public class PhysicsSetup : MonoBehaviour
{
    public void ConfigurePhysicsObject(GameObject target)
    {
        var rb = target.GetComponent<Rigidbody>();
        if (rb == null)
            rb = target.AddComponent<Rigidbody>();

        rb.mass = 5f;
        rb.linearDamping = 0.5f;
        rb.angularDamping = 0.1f;
        rb.useGravity = true;
        rb.collisionDetectionMode = CollisionDetectionMode.Continuous;

        var col = target.GetComponent<BoxCollider>();
        if (col == null)
            col = target.AddComponent<BoxCollider>();

        col.center = Vector3.zero;
        col.size = Vector3.one;
    }
}

using UnityEngine;

public interface IDamageable
{
    void TakeDamage(float amount);
    float CurrentHealth { get; }
}

public class HealthSystem : MonoBehaviour, IDamageable
{
    [SerializeField] private float maxHealth = 100f;
    private float currentHealth;

    public float CurrentHealth => currentHealth;

    private void Awake()
    {
        currentHealth = maxHealth;
    }

    public void TakeDamage(float amount)
    {
        currentHealth = Mathf.Max(0, currentHealth - amount);
        if (currentHealth <= 0)
            HandleDeath();
    }

    private void HandleDeath()
    {
        Destroy(gameObject, 0.1f);
    }
}

public class Weapon : MonoBehaviour
{
    [SerializeField] private float damage = 25f;

    public void Attack(Collider target)
    {
        if (target.TryGetComponent<IDamageable>(out var damageable))
        {
            damageable.TakeDamage(damage);
        }
    }
}
TryGetComponent 是 Unity 2019.2+ 引入的方法，相比 GetComponent 不会在组件不存在时产生 GC 分配，是组件查询的最佳实践。


Tag、Layer 与对象查找
Unity 提供 Tag 和 Layer 两种标记机制用于对象分类。Tag 是字符串标识，用于逻辑层面的对象查找；Layer 是位掩码，用于物理碰撞和渲染过滤。

using UnityEngine;

public class ObjectFinder : MonoBehaviour
{
    [SerializeField] private LayerMask enemyLayer;

    public GameObject FindNearestEnemy(Vector3 position, float radius)
    {
        Collider[] hits = Physics.OverlapSphere(position, radius, enemyLayer);
        GameObject nearest = null;
        float minDist = float.MaxValue;

        foreach (var hit in hits)
        {
            if (!hit.CompareTag("Enemy")) continue;

            float dist = Vector3.Distance(position, hit.transform.position);
            if (dist < minDist)
            {
                minDist = dist;
                nearest = hit.gameObject;
            }
        }

        return nearest;
    }
}
使用 CompareTag 而非 == "Tag" 进行标签比较，前者不产生字符串分配，性能更优。避免在 Update 中调用 Find 系列方法，应在 Awake/Start 中缓存引用。


小结
    

  • Unity 采用 GameObject-Component 架构，组合优于继承是核心设计理念
    • 

  • GameObject 本身只是容器，所有功能由挂载的 Component 提供
    • 

  • 父子层级关系影响 Transform 级联计算，是场景组织的基础
    • 

  • 内置组件覆盖渲染、物理、音频、UI 四大子系统
    • 

  • 组件通信推荐使用接口 + TryGetComponent 模式，避免 SendMessage
    • 

  • Tag 用于逻辑分类，Layer 用于物理/渲染过滤，运行时应缓存查找结果
    •
