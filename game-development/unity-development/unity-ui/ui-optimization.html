UI 性能优化

核心概念

UI 渲染在许多游戏项目中占据了相当比例的性能开销。UGUI 的 Canvas 系统在元素发生变化时会触发 Mesh 重建（Rebuild），这个过程涉及布局计算、顶点生成和批次合并，是 UI 性能瓶颈的主要来源。理解 Canvas 的更新机制和批处理规则，是优化 UI 性能的前提。

Canvas 分离与动静分层
Canvas Rebuild 的核心规则是：一个 Canvas 内任何元素发生变化，整个 Canvas 的所有元素都需要重新计算。因此，将频繁变化的 UI（血条、计时器、伤害数字）和静态 UI（背景、边框、标题）分离到不同的 Canvas 中，是最重要的优化手段。


using UnityEngine;
using UnityEngine.UI;

public class OptimizedHUD : MonoBehaviour
{
    [Header("静态 Canvas（几乎不变化）")]
    [SerializeField] private Canvas staticCanvas;

    [Header("动态 Canvas（每帧更新）")]
    [SerializeField] private Canvas dynamicCanvas;

    [Header("动态元素")]
    [SerializeField] private Slider healthSlider;
    [SerializeField] private Text ammoText;
    [SerializeField] private Text timerText;

    private int lastAmmo = -1;
    private float displayedHealth = -1f;

    public void UpdateHealth(float normalized)
    {
        if (Mathf.Approximately(displayedHealth, normalized)) return;
        displayedHealth = normalized;
        healthSlider.value = normalized;
    }

    public void UpdateAmmo(int current)
    {
        if (current == lastAmmo) return;
        lastAmmo = current;
        ammoText.text = current.ToString();
    }

    public void UpdateTimer(float seconds)
    {
        int minutes = (int)(seconds / 60f);
        int secs = (int)(seconds % 60f);
        timerText.text = $"{minutes:D2}:{secs:D2}";
    }
}
嵌套 Canvas（子 Canvas）是实现分层的另一种方式。子 Canvas 拥有独立的 Rebuild 范围，子 Canvas 内的变化不会触发父 Canvas 的重建。但需要注意子 Canvas 会打断父 Canvas 的批处理。

批处理与图集优化
UGUI 的渲染器会尝试将相邻的、使用相同材质和纹理的 UI 元素合并为一个 Draw Call。但当元素的材质、纹理、裁剪矩形不同，或元素在层级中交叉排列时，批处理会被打断。


Sprite Atlas（图集）将多张小图合并为一张大纹理，让使用不同精灵的 UI 元素可以合批渲染：


using UnityEngine;
using UnityEngine.U2D;

public class AtlasManager : MonoBehaviour
{
    [SerializeField] private SpriteAtlas uiAtlas;

    private void OnEnable()
    {
        SpriteAtlasManager.atlasRequested += OnAtlasRequested;
    }

    private void OnDisable()
    {
        SpriteAtlasManager.atlasRequested -= OnAtlasRequested;
    }

    private void OnAtlasRequested(string tag, System.Action<SpriteAtlas> callback)
    {
        if (tag == "UIAtlas")
        {
            callback(uiAtlas);
        }
    }

    public Sprite GetSprite(string spriteName)
    {
        return uiAtlas.GetSprite(spriteName);
    }
}

通过 Frame Debugger（Window → Analysis → Frame Debugger）可以逐个查看每个 Draw Call 的合批情况，精准定位批处理断裂的位置。


Raycast 优化
GraphicRaycaster 在每次点击或触摸时对 Canvas 内所有开启了 Raycast Target 的元素进行射线检测。默认情况下所有 Graphic 组件（Image、Text 等）的 Raycast Target 都是开启的，但实际上大部分纯显示元素不需要响应点击事件。


using UnityEngine;
using UnityEngine.UI;

public class RaycastOptimizer : MonoBehaviour
{
    public void OptimizeCanvasRaycasts(Canvas canvas)
    {
        var graphics = canvas.GetComponentsInChildren<Graphic>(true);
        int disabled = 0;

        foreach (var graphic in graphics)
        {
            bool needsRaycast = graphic.GetComponent<IEventSystemHandler>() != null
                || graphic.GetComponent<Button>() != null
                || graphic.GetComponent<Toggle>() != null
                || graphic.GetComponent<Slider>() != null
                || graphic.GetComponent<InputField>() != null
                || graphic.GetComponent<ScrollRect>() != null;

            if (!needsRaycast && graphic.raycastTarget)
            {
                graphic.raycastTarget = false;
                disabled++;
            }
        }

        Debug.Log($"已禁用 {disabled}/{graphics.Length} 个不必要的 Raycast Target");
    }
}
对于大量 UI 元素的场景（如背包格子），可以通过 RaycastPadding 缩小射线检测区域，或在父级使用一个大的透明 Image 作为统一的 Raycast 接收器，然后通过位置计算确定点击了哪个格子。


对象池与文本优化
频繁创建和销毁 UI 元素（如伤害数字、飘字提示）会产生大量 GC 分配。对象池模式通过预创建和复用来消除运行时的实例化开销：


using UnityEngine;
using System.Collections.Generic;
using UnityEngine.UI;

public class DamageNumberPool : MonoBehaviour
{
    [SerializeField] private GameObject damageNumberPrefab;
    [SerializeField] private Transform poolParent;
    [SerializeField] private int initialPoolSize = 20;

    private readonly Queue<GameObject> pool = new();

    private void Awake()
    {
        for (int i = 0; i < initialPoolSize; i++)
        {
            var go = Instantiate(damageNumberPrefab, poolParent);
            go.SetActive(false);
            pool.Enqueue(go);
        }
    }

    public GameObject Get(Vector3 worldPosition, int damage)
    {
        GameObject go;

        if (pool.Count > 0)
        {
            go = pool.Dequeue();
        }
        else
        {
            go = Instantiate(damageNumberPrefab, poolParent);
        }

        go.transform.position = worldPosition;
        go.GetComponentInChildren<Text>().text = damage.ToString();
        go.SetActive(true);
        return go;
    }

    public void Return(GameObject go)
    {
        go.SetActive(false);
        pool.Enqueue(go);
    }
}
文本更新是另一个常见的性能陷阱。每次修改 Text 组件的 text 属性都会触发 Mesh 重建和字符串分配。避免在 Update 中无条件更新文本，只在值真正变化时才赋值：


using UnityEngine;
using UnityEngine.UI;
using System.Text;

public class OptimizedScoreDisplay : MonoBehaviour
{
    [SerializeField] private Text scoreText;
    [SerializeField] private Text fpsText;

    private int lastScore = -1;
    private int lastFps = -1;
    private readonly StringBuilder sb = new(16);
    private float fpsUpdateInterval = 0.5f;
    private float fpsTimer;

    public void SetScore(int score)
    {
        if (score == lastScore) return;
        lastScore = score;

        sb.Clear();
        sb.Append("Score: ");
        sb.Append(score);
        scoreText.text = sb.ToString();
    }

    private void Update()
    {
        fpsTimer += Time.unscaledDeltaTime;
        if (fpsTimer < fpsUpdateInterval) return;
        fpsTimer = 0f;

        int fps = (int)(1f / Time.unscaledDeltaTime);
        if (fps == lastFps) return;
        lastFps = fps;

        sb.Clear();
        sb.Append("FPS: ");
        sb.Append(fps);
        fpsText.text = sb.ToString();
    }
}
小结
    

  • Canvas Rebuild 是 UI 性能的核心瓶颈，分离动态和静态元素到不同 Canvas 是最重要的优化
    • 

  • Sprite Atlas 合并纹理减少 Draw Call，Frame Debugger 精准定位批处理断裂
    • 

  • 禁用纯显示元素的 Raycast Target 减少不必要的射线检测开销
    • 

  • 对象池模式消除 UI 元素频繁创建销毁的 GC 压力
    • 

  • 文本更新应做变化检测，使用 StringBuilder 替代字符串拼接减少内存分配
    • 

  • 子 Canvas 提供独立的 Rebuild 范围，但会打断父级的批处理合并
    •
