数据序列化与协议设计

核心概念

数据序列化是将游戏中的结构化数据（如玩家位置、游戏事件）转换为可通过网络传输的字节流的过程。协议设计则定义了这些字节流的组织方式，包括消息的格式、类型标识和版本控制。高效的序列化和精心设计的协议是游戏网络性能的关键因素。

在游戏网络中，每秒可能需要发送数十到上百个数据包，每个数据包的大小直接影响带宽消耗。相比 JSON 等文本格式，二进制序列化可以将数据量减少 50%-90%，这对于带宽受限的移动游戏和大规模多人游戏尤为重要。

二进制序列化基础
二进制序列化的核心思想是直接将数据写入字节缓冲区，避免文本格式的字符串转换和分隔符开销。游戏中最常用的方法是使用 DataView 或自定义的 BitWriter/BitReader 进行精确的位级操作。


class ByteWriter {
  private buffer: ArrayBuffer;
  private view: DataView;
  private offset: number;

  constructor(size: number) {
    this.buffer = new ArrayBuffer(size);
    this.view = new DataView(this.buffer);
    this.offset = 0;
  }

  writeUint8(value: number): void {
    this.view.setUint8(this.offset, value);
    this.offset += 1;
  }

  writeUint16(value: number): void {
    this.view.setUint16(this.offset, value, true);
    this.offset += 2;
  }

  writeUint32(value: number): void {
    this.view.setUint32(this.offset, value, true);
    this.offset += 4;
  }

  writeFloat32(value: number): void {
    this.view.setFloat32(this.offset, value, true);
    this.offset += 4;
  }

  writeString(value: string): void {
    const encoder = new TextEncoder();
    const bytes = encoder.encode(value);
    this.writeUint16(bytes.length);
    new Uint8Array(this.buffer, this.offset).set(bytes);
    this.offset += bytes.length;
  }

  getBuffer(): ArrayBuffer {
    return this.buffer.slice(0, this.offset);
  }
}

class ByteReader {
  private view: DataView;
  private offset: number;

  constructor(buffer: ArrayBuffer) {
    this.view = new DataView(buffer);
    this.offset = 0;
  }

  readUint8(): number {
    const value = this.view.getUint8(this.offset);
    this.offset += 1;
    return value;
  }

  readUint16(): number {
    const value = this.view.getUint16(this.offset, true);
    this.offset += 2;
    return value;
  }

  readUint32(): number {
    const value = this.view.getUint32(this.offset, true);
    this.offset += 4;
    return value;
  }

  readFloat32(): number {
    const value = this.view.getFloat32(this.offset, true);
    this.offset += 4;
    return value;
  }

  readString(): string {
    const length = this.readUint16();
    const decoder = new TextDecoder();
    const bytes = new Uint8Array(this.view.buffer, this.offset, length);
    this.offset += length;
    return decoder.decode(bytes);
  }
}
位打包（Bit Packing）技术可以将数据压缩到更小的尺寸。例如，玩家的朝向角度范围是 0-360 度，如果使用 Float32 需要 4 字节（32 位），但用 10 位无符号整数（0-1023）表示精度约为 0.35 度就足够了，节省了 69% 的空间。


消息协议架构
游戏网络协议通常由消息头和消息体组成。消息头包含协议标识、消息类型、序列号等元数据，消息体则是具体的游戏数据。


const enum MessageType {
  Ping = 0x01,
  Pong = 0x02,
  PlayerInput = 0x10,
  StateSnapshot = 0x11,
  SpawnEntity = 0x20,
  DestroyEntity = 0x21,
  PlayerJoin = 0x30,
  PlayerLeave = 0x31,
  ChatMessage = 0x40,
  RpcCall = 0x50,
}

interface MessageHeader {
  protocolId: number;
  messageType: MessageType;
  sequence: number;
  timestamp: number;
  payloadLength: number;
}

const PROTOCOL_ID = 0x474e4554;
const HEADER_SIZE = 16;

const encodeHeader = (header: MessageHeader, writer: ByteWriter): void => {
  writer.writeUint32(header.protocolId);
  writer.writeUint16(header.messageType);
  writer.writeUint32(header.sequence);
  writer.writeUint32(header.timestamp);
  writer.writeUint16(header.payloadLength);
};

const decodeHeader = (reader: ByteReader): MessageHeader | null => {
  const protocolId = reader.readUint32();
  if (protocolId !== PROTOCOL_ID) return null;

  return {
    protocolId,
    messageType: reader.readUint16() as MessageType,
    sequence: reader.readUint32(),
    timestamp: reader.readUint32(),
    payloadLength: reader.readUint16(),
  };
};

interface PlayerInputPayload {
  inputSequence: number;
  moveX: number;
  moveZ: number;
  yaw: number;
  actions: number;
}

const encodePlayerInput = (input: PlayerInputPayload, writer: ByteWriter): void => {
  writer.writeUint32(input.inputSequence);
  writer.writeFloat32(input.moveX);
  writer.writeFloat32(input.moveZ);
  writer.writeUint16(Math.floor((input.yaw / 360) * 65535));
  writer.writeUint8(input.actions);
};

const decodePlayerInput = (reader: ByteReader): PlayerInputPayload => ({
  inputSequence: reader.readUint32(),
  moveX: reader.readFloat32(),
  moveZ: reader.readFloat32(),
  yaw: (reader.readUint16() / 65535) * 360,
  actions: reader.readUint8(),
});
消息类型的编号规划需要考虑扩展性。常见的做法是按功能域分段：0x00-0x0F 为连接管理、0x10-0x1F 为游戏状态、0x20-0x2F 为实体管理、0x30-0x3F 为玩家事件、0x40-0x4F 为社交功能。这种分段方式便于路由分发和权限控制。


版本兼容与协议演进
随着游戏更新迭代，网络协议不可避免地需要修改。良好的版本兼容策略可以让不同版本的客户端和服务器共存，避免强制全量更新。


常见的版本兼容策略包括：字段追加（只在消息末尾添加新字段）、协议版本号协商和向后兼容的编码格式。


interface ProtocolNegotiation {
  minVersion: number;
  maxVersion: number;
  features: string[];
}

const negotiateProtocol = (clientProto: ProtocolNegotiation, serverProto: ProtocolNegotiation): number | null => {
  const minCompatible = Math.max(clientProto.minVersion, serverProto.minVersion);
  const maxCompatible = Math.min(clientProto.maxVersion, serverProto.maxVersion);
  return minCompatible <= maxCompatible ? maxCompatible : null;
};

interface VersionedMessage {
  version: number;
  type: MessageType;
  payload: Uint8Array;
}

interface SchemaField {
  name: string;
  type: 'uint8' | 'uint16' | 'uint32' | 'float32' | 'string';
  addedInVersion: number;
  defaultValue: number | string;
}

interface MessageSchema {
  messageType: MessageType;
  fields: SchemaField[];
}

const decodeVersioned = (
  schema: MessageSchema,
  reader: ByteReader,
  version: number,
): Record<string, number | string> => {
  const result: Record<string, number | string> = {};

  for (const field of schema.fields) {
    if (field.addedInVersion > version) {
      result[field.name] = field.defaultValue;
      continue;
    }

    switch (field.type) {
      case 'uint8':
        result[field.name] = reader.readUint8();
        break;
      case 'uint16':
        result[field.name] = reader.readUint16();
        break;
      case 'uint32':
        result[field.name] = reader.readUint32();
        break;
      case 'float32':
        result[field.name] = reader.readFloat32();
        break;
      case 'string':
        result[field.name] = reader.readString();
        break;
    }
  }
  return result;
};

性能优化技术
在高频率的游戏网络通信中，序列化性能直接影响服务器的承载能力。以下是几个关键的优化方向。


对象池化可以避免频繁的内存分配和垃圾回收。预先分配一批序列化缓冲区，使用完毕后归还池中复用。


class BufferPool {
  private pool: ArrayBuffer[];
  private bufferSize: number;

  constructor(initialCount: number, bufferSize: number) {
    this.bufferSize = bufferSize;
    this.pool = Array.from({ length: initialCount }, () => new ArrayBuffer(bufferSize));
  }

  acquire(): ArrayBuffer {
    return this.pool.pop() ?? new ArrayBuffer(this.bufferSize);
  }

  release(buffer: ArrayBuffer): void {
    if (buffer.byteLength === this.bufferSize && this.pool.length < 256) {
      this.pool.push(buffer);
    }
  }
}

const quantizeFloat = (value: number, min: number, max: number, bits: number): number => {
  const maxVal = (1 << bits) - 1;
  const normalized = (value - min) / (max - min);
  return Math.round(Math.max(0, Math.min(1, normalized)) * maxVal);
};

const dequantizeFloat = (quantized: number, min: number, max: number, bits: number): number => {
  const maxVal = (1 << bits) - 1;
  return min + (quantized / maxVal) * (max - min);
};
量化（Quantization）是另一个重要的优化手段。通过将浮点数映射到有限范围的整数，可以在可接受的精度损失下大幅减少数据量。例如，将 -100 到 100 范围的位置坐标量化为 16 位整数，精度约为 0.003 个单位，对于大多数游戏来说完全足够。


批量消息聚合也能显著降低网络开销。将同一帧内的多个小消息合并为一个大数据包发送，可以减少 UDP 包头开销和系统调用次数。
