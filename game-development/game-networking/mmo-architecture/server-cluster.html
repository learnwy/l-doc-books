服务器集群架构

核心概念

大型多人在线游戏（MMO）的服务器集群架构是游戏网络中最复杂的系统之一。与小规模竞技游戏的单服务器实例不同，MMO 需要同时支持数千甚至数万名玩家在同一个持久世界中交互。这要求服务器系统具备水平扩展能力、故障容忍能力和高效的负载均衡机制。

MMO 服务器集群通常由多种功能角色的服务器组成：网关服务器负责连接管理和负载均衡、游戏服务器负责具体的游戏逻辑模拟、世界服务器负责全局状态管理、数据库服务器负责持久化存储。这些角色通过内部消息总线进行高效通信。

网关与负载均衡

网关服务器是客户端连接的入口点，负责将玩家请求路由到正确的游戏服务器。网关本身是无状态的，可以通过简单地增加实例来水平扩展。

interface GatewayConfig {
  maxConnections: number;
  heartbeatTimeout: number;
  routingStrategy: 'region' | 'load' | 'sticky';
}

interface PlayerSession {
  playerId: string;
  gatewayId: string;
  gameServerId: string;
  regionId: string;
  connectTime: number;
  lastActivity: number;
}

interface ServerLoad {
  serverId: string;
  playerCount: number;
  cpuUsage: number;
  memoryUsage: number;
  tickRate: number;
  regionId: string;
}

class GatewayRouter {
  private sessions: Map<string, PlayerSession> = new Map();
  private serverLoads: Map<string, ServerLoad> = new Map();
  private config: GatewayConfig;

  constructor(config: GatewayConfig) {
    this.config = config;
  }

  routePlayer(playerId: string, targetRegion: string): string {
    const existing = this.sessions.get(playerId);
    if (existing && this.config.routingStrategy === 'sticky') {
      return existing.gameServerId;
    }

    const candidates = this.getServersForRegion(targetRegion);
    if (candidates.length === 0) {
      return this.spawnNewServer(targetRegion);
    }

    return this.selectBestServer(candidates);
  }

  private getServersForRegion(regionId: string): ServerLoad[] {
    return Array.from(this.serverLoads.values()).filter((s) => s.regionId === regionId);
  }

  private selectBestServer(candidates: ServerLoad[]): string {
    const scored = candidates.map((s) => ({
      serverId: s.serverId,
      score: this.calculateScore(s),
    }));
    scored.sort((a, b) => a.score - b.score);
    return scored[0].serverId;
  }

  private calculateScore(load: ServerLoad): number {
    const playerWeight = 0.4;
    const cpuWeight = 0.4;
    const memWeight = 0.2;
    return (load.playerCount / 1000) * playerWeight + load.cpuUsage * cpuWeight + load.memoryUsage * memWeight;
  }

  updateServerLoad(load: ServerLoad): void {
    this.serverLoads.set(load.serverId, load);
  }

  private spawnNewServer(_regionId: string): string {
    return crypto.randomUUID();
  }
}

负载均衡策略需要考虑多个因素：玩家所在的游戏区域（保证同区域玩家在同一个游戏服务器）、服务器的当前负载（CPU、内存、玩家数量）、以及会话粘性（同一玩家尽量保持在同一服务器以减少迁移成本）。

区域分割与无缝世界

MMO 的游戏世界通常被划分为多个区域，每个区域由一个独立的游戏服务器进程负责。区域分割的方式和跨区域的无缝过渡是 MMO 架构的核心挑战。

interface WorldRegion {
  regionId: string;
  serverId: string;
  bounds: RegionBounds;
  playerCount: number;
  maxPlayers: number;
  neighbors: string[];
}

interface RegionBounds {
  minX: number;
  minZ: number;
  maxX: number;
  maxZ: number;
}

interface EntityTransfer {
  entityId: string;
  fromRegion: string;
  toRegion: string;
  position: { x: number; y: number; z: number };
  fullState: Uint8Array;
  timestamp: number;
}

class RegionManager {
  private regions: Map<string, WorldRegion> = new Map();
  private borderWidth: number = 50;

  addRegion(region: WorldRegion): void {
    this.regions.set(region.regionId, region);
  }

  getRegionForPosition(x: number, z: number): WorldRegion | null {
    for (const [, region] of this.regions) {
      if (x >= region.bounds.minX && x < region.bounds.maxX && z >= region.bounds.minZ && z < region.bounds.maxZ) {
        return region;
      }
    }
    return null;
  }

  isInBorderZone(x: number, z: number, regionId: string): boolean {
    const region = this.regions.get(regionId);
    if (!region) return false;

    return (
      x - region.bounds.minX < this.borderWidth ||
      region.bounds.maxX - x < this.borderWidth ||
      z - region.bounds.minZ < this.borderWidth ||
      region.bounds.maxZ - z < this.borderWidth
    );
  }

  initiateTransfer(
    entityId: string,
    fromRegion: string,
    toRegion: string,
    state: Uint8Array,
    position: { x: number; y: number; z: number },
  ): EntityTransfer {
    return {
      entityId,
      fromRegion,
      toRegion,
      position,
      fullState: state,
      timestamp: Date.now(),
    };
  }

  getNeighborRegions(regionId: string): WorldRegion[] {
    const region = this.regions.get(regionId);
    if (!region) return [];
    return region.neighbors.map((id) => this.regions.get(id)).filter((r): r is WorldRegion => r !== undefined);
  }
}

无缝世界的关键技术是边界区域（Border Zone）重叠。在两个区域的交界处设置一个重叠地带，实体在这个区域内同时存在于两个区域的服务器上。当实体完全进入新区域后，旧区域的服务器释放该实体的所有权。这种方式对玩家完全透明，不需要加载画面或传送过场。

服务发现与内部通信

集群中的各个服务器需要一个高效的服务发现和内部通信机制。服务发现让每个服务器知道其他服务器的地址和状态，消息总线提供服务器之间的异步通信能力。

interface ServiceInfo {
  serviceId: string;
  type: 'gateway' | 'game' | 'world' | 'chat' | 'match';
  address: string;
  port: number;
  status: 'starting' | 'running' | 'draining' | 'stopped';
  metadata: Record<string, string>;
  lastHeartbeat: number;
}

class ServiceRegistry {
  private services: Map<string, ServiceInfo> = new Map();
  private listeners: Map<string, ((services: ServiceInfo[]) => void)[]> = new Map();

  register(service: ServiceInfo): void {
    this.services.set(service.serviceId, service);
    this.notifyListeners(service.type);
  }

  deregister(serviceId: string): void {
    const service = this.services.get(serviceId);
    if (service) {
      this.services.delete(serviceId);
      this.notifyListeners(service.type);
    }
  }

  discover(type: string): ServiceInfo[] {
    return Array.from(this.services.values()).filter((s) => s.type === type && s.status === 'running');
  }

  watch(type: string, callback: (services: ServiceInfo[]) => void): void {
    const list = this.listeners.get(type) ?? [];
    list.push(callback);
    this.listeners.set(type, list);
  }

  healthCheck(): void {
    const now = Date.now();
    const timeout = 30000;
    for (const [id, service] of this.services) {
      if (now - service.lastHeartbeat > timeout) {
        service.status = 'stopped';
        this.deregister(id);
      }
    }
  }

  private notifyListeners(type: string): void {
    const callbacks = this.listeners.get(type) ?? [];
    const services = this.discover(type);
    for (const cb of callbacks) {
      cb(services);
    }
  }
}
通信模式 特点 适用场景
请求-响应 同步、强一致 跨区域实体查询
发布-订阅 异步、解耦 全服公告、事件广播
点对点 低延迟、直连 区域间实体迁移
广播 一对多 服务器状态更新

弹性伸缩与故障恢复

MMO 服务器集群需要根据在线人数动态调整容量。弹性伸缩（Auto-Scaling）系统持续监控集群负载，在高峰期自动增加服务器实例，在低谷期回收资源。

interface ScalingPolicy {
  minInstances: number;
  maxInstances: number;
  targetCpuUtilization: number;
  scaleUpThreshold: number;
  scaleDownThreshold: number;
  cooldownSeconds: number;
}

class AutoScaler {
  private policy: ScalingPolicy;
  private currentInstances: number;
  private lastScaleTime: number = 0;

  constructor(policy: ScalingPolicy) {
    this.policy = policy;
    this.currentInstances = policy.minInstances;
  }

  evaluate(loads: ServerLoad[]): ScalingDecision {
    const now = Date.now();
    if (now - this.lastScaleTime < this.policy.cooldownSeconds * 1000) {
      return { action: 'none', reason: 'cooldown' };
    }

    const avgCpu = loads.reduce((sum, l) => sum + l.cpuUsage, 0) / loads.length;

    if (avgCpu > this.policy.scaleUpThreshold && this.currentInstances < this.policy.maxInstances) {
      const needed = Math.ceil(this.currentInstances * (avgCpu / this.policy.targetCpuUtilization));
      const newCount = Math.min(needed, this.policy.maxInstances);
      this.currentInstances = newCount;
      this.lastScaleTime = now;
      return { action: 'scale_up', reason: `cpu=${avgCpu.toFixed(1)}%`, target: newCount };
    }

    if (avgCpu < this.policy.scaleDownThreshold && this.currentInstances > this.policy.minInstances) {
      const needed = Math.ceil(this.currentInstances * (avgCpu / this.policy.targetCpuUtilization));
      const newCount = Math.max(needed, this.policy.minInstances);
      this.currentInstances = newCount;
      this.lastScaleTime = now;
      return { action: 'scale_down', reason: `cpu=${avgCpu.toFixed(1)}%`, target: newCount };
    }

    return { action: 'none', reason: 'within_threshold' };
  }
}

interface ScalingDecision {
  action: 'scale_up' | 'scale_down' | 'none';
  reason: string;
  target?: number;
}

故障恢复通过优雅降级（Graceful Drain）实现。当某个游戏服务器需要下线时，先将其标记为"排空"状态，停止接受新玩家，等待现有玩家自然离开或主动迁移到其他服务器后再关闭。紧急情况下则直接将玩家状态快照保存到数据库，通知客户端重连到其他服务器。
