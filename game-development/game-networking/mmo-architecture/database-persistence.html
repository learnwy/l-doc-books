数据持久化与存储

核心概念

数据持久化是 MMO 游戏中确保玩家进度和世界状态不因服务器重启或故障而丢失的关键基础设施。与无状态的竞技游戏不同，MMO 拥有持久世界（Persistent World），玩家的角色数据、装备、任务进度、社交关系等信息需要可靠地存储和高效地读写。

游戏数据库面临的核心挑战是同时满足高频写入（位置更新、战斗数据）和低延迟读取（物品查询、好友列表）的需求。这通常通过多层缓存架构来解决：热数据保持在内存中供游戏逻辑直接访问，定期批量写入持久存储。

数据分区策略对性能至关重要。按角色 ID 分片可以确保单个角色的所有数据落在同一个数据库节点上，避免跨分片查询。公会和社交数据可能跨越多个分片，这类查询通常通过专用的社交数据库或缓存层来处理。


写入策略与数据一致性
MMO 游戏中的数据写入分为两类：低频但关键的事务型写入（如物品交易、装备强化）和高频但可容忍丢失的状态型写入（如位置更新、经验值变化）。


const enum WritePolicy {
  Immediate = 0,
  Batched = 1,
  Lazy = 2,
}

interface WriteOperation {
  characterId: string;
  dataType: string;
  payload: Uint8Array;
  policy: WritePolicy;
  timestamp: number;
  retryCount: number;
}

class PersistenceManager {
  private writeQueue: WriteOperation[] = [];
  private batchInterval: number;
  private dirtyCharacters: Map<string, Set<string>> = new Map();
  private memoryCache: Map<string, CharacterData> = new Map();
  private batchTimer: ReturnType<typeof setInterval> | null = null;

  constructor(batchInterval: number = 5000) {
    this.batchInterval = batchInterval;
  }

  start(): void {
    this.batchTimer = setInterval(() => this.flushBatch(), this.batchInterval);
  }

  stop(): void {
    if (this.batchTimer) clearInterval(this.batchTimer);
    this.flushAll();
  }

  async writeImmediate(characterId: string, data: Partial<CharacterData>): Promise<boolean> {
    this.updateCache(characterId, data);
    return this.persistToDatabase(characterId, data);
  }

  writeBatched(characterId: string, fields: string[]): void {
    const dirty = this.dirtyCharacters.get(characterId) ?? new Set();
    for (const field of fields) dirty.add(field);
    this.dirtyCharacters.set(characterId, dirty);
  }

  writeLazy(characterId: string, field: string, value: unknown): void {
    const cached = this.memoryCache.get(characterId);
    if (cached) {
      (cached as Record<string, unknown>)[field] = value;
    }
  }

  private async flushBatch(): Promise<void> {
    const operations: Promise<boolean>[] = [];

    for (const [charId, fields] of this.dirtyCharacters) {
      const cached = this.memoryCache.get(charId);
      if (!cached) continue;

      const partial: Record<string, unknown> = {};
      for (const field of fields) {
        partial[field] = (cached as Record<string, unknown>)[field];
      }

      operations.push(this.persistToDatabase(charId, partial as Partial<CharacterData>));
    }

    await Promise.allSettled(operations);
    this.dirtyCharacters.clear();
  }

  private async flushAll(): Promise<void> {
    await this.flushBatch();
    for (const [charId, data] of this.memoryCache) {
      await this.persistToDatabase(charId, data);
    }
  }

  private updateCache(characterId: string, data: Partial<CharacterData>): void {
    const existing = this.memoryCache.get(characterId) ?? ({} as CharacterData);
    this.memoryCache.set(characterId, { ...existing, ...data });
  }

  private async persistToDatabase(_characterId: string, _data: Partial<CharacterData>): Promise<boolean> {
    return true;
  }
}

事务与原子操作
物品交易、拍卖行操作等关键业务需要原子性保证。两个玩家之间的物品交换必须同时成功或同时失败，不能出现一方物品消失而另一方没有收到的情况。


interface Transaction {
  transactionId: string;
  type: 'trade' | 'auction' | 'mail' | 'craft';
  participants: string[];
  operations: TransactionOp[];
  status: 'pending' | 'committed' | 'rolled_back';
  createdAt: number;
}

interface TransactionOp {
  characterId: string;
  action: 'add_item' | 'remove_item' | 'add_currency' | 'remove_currency';
  itemId?: string;
  quantity: number;
}

class TransactionManager {
  private activeTransactions: Map<string, Transaction> = new Map();

  async execute(transaction: Transaction): Promise<boolean> {
    transaction.status = 'pending';
    this.activeTransactions.set(transaction.transactionId, transaction);

    const validated = await this.validate(transaction);
    if (!validated) {
      transaction.status = 'rolled_back';
      return false;
    }

    const locks = await this.acquireLocks(transaction.participants);
    if (!locks) {
      transaction.status = 'rolled_back';
      return false;
    }

    const results = await this.applyOperations(transaction.operations);

    if (results.every((r) => r)) {
      transaction.status = 'committed';
      await this.logTransaction(transaction);
      this.releaseLocks(transaction.participants);
      return true;
    }

    await this.rollbackOperations(transaction.operations);
    transaction.status = 'rolled_back';
    this.releaseLocks(transaction.participants);
    return false;
  }

  private async validate(transaction: Transaction): Promise<boolean> {
    for (const op of transaction.operations) {
      if (op.action === 'remove_item') {
        const hasItem = await this.checkInventory(op.characterId, op.itemId!, op.quantity);
        if (!hasItem) return false;
      }
      if (op.action === 'remove_currency') {
        const hasGold = await this.checkCurrency(op.characterId, op.quantity);
        if (!hasGold) return false;
      }
    }
    return true;
  }

  private async acquireLocks(_participants: string[]): Promise<boolean> {
    return true;
  }
  private releaseLocks(_participants: string[]): void {}
  private async applyOperations(_ops: TransactionOp[]): Promise<boolean[]> {
    return _ops.map(() => true);
  }
  private async rollbackOperations(_ops: TransactionOp[]): Promise<void> {}
  private async logTransaction(_tx: Transaction): Promise<void> {}
  private async checkInventory(_charId: string, _itemId: string, _qty: number): Promise<boolean> {
    return true;
  }
  private async checkCurrency(_charId: string, _amount: number): Promise<boolean> {
    return true;
  }
}
分布式事务在跨服务器场景中更加复杂。常见的实现方案是两阶段提交（2PC）或基于事件溯源的最终一致性。对于游戏来说，在玩家可接受的延迟范围内使用乐观锁加重试通常是更实用的选择。


数据备份与灾难恢复
MMO 游戏的数据资产价值极高——玩家投入了大量时间和金钱。完善的备份和灾难恢复策略是运营的基本要求。


interface BackupConfig {
  fullBackupInterval: number;
  incrementalInterval: number;
  retentionDays: number;
  maxBackupSize: number;
}

interface BackupMetadata {
  backupId: string;
  type: 'full' | 'incremental';
  startTime: number;
  endTime: number;
  sizeBytes: number;
  checksum: string;
  baseBackupId?: string;
}

class BackupScheduler {
  private config: BackupConfig;
  private backups: BackupMetadata[] = [];
  private lastFullBackup: number = 0;
  private lastIncrementalBackup: number = 0;

  constructor(config: BackupConfig) {
    this.config = config;
  }

  shouldRunBackup(currentTime: number): 'full' | 'incremental' | null {
    if (currentTime - this.lastFullBackup >= this.config.fullBackupInterval) {
      return 'full';
    }
    if (currentTime - this.lastIncrementalBackup >= this.config.incrementalInterval) {
      return 'incremental';
    }
    return null;
  }

  recordBackup(metadata: BackupMetadata): void {
    this.backups.push(metadata);
    if (metadata.type === 'full') this.lastFullBackup = metadata.endTime;
    else this.lastIncrementalBackup = metadata.endTime;

    this.pruneOldBackups();
  }

  private pruneOldBackups(): void {
    const cutoff = Date.now() - this.config.retentionDays * 86400000;
    this.backups = this.backups.filter((b) => b.endTime > cutoff);
  }

  getRecoveryChain(targetTime: number): BackupMetadata[] {
    const fullBackups = this.backups
      .filter((b) => b.type === 'full' && b.endTime <= targetTime)
      .sort((a, b) => b.endTime - a.endTime);

    if (fullBackups.length === 0) return [];

    const base = fullBackups[0];
    const incrementals = this.backups
      .filter((b) => b.type === 'incremental' && b.endTime > base.endTime && b.endTime <= targetTime)
      .sort((a, b) => a.endTime - b.endTime);

    return [base, ...incrementals];
  }
}

实际运营中通常采用多层备份策略：实时的 WAL（Write-Ahead Log）保证秒级恢复点、每小时增量备份保证快速恢复、每天全量备份保证灾难恢复。同时将备份数据异地存储以防止机房级别的故障。


小结
    

  • MMO 数据持久化通过多层缓存架构平衡读写性能和持久性保证
    • 

  • 玩家数据按账号-角色-会话三层建模，支持高效的分片和查询
    • 

  • 关键事务使用同步写入，常规数据使用批量写入，位置数据延迟持久化
    • 

  • 物品交易等原子操作需要分布式锁和事务回滚保证一致性
    • 

  • 多层备份策略结合 WAL 日志实现秒级恢复点目标
    • 

  • 备份数据异地存储防止机房级故障导致数据丢失
