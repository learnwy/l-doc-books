快照插值

核心概念

快照插值（Snapshot Interpolation）是一种客户端渲染平滑技术。在权威服务器架构中，服务器以固定频率（如 20-60 Tick/s）发送世界状态快照，但客户端的渲染帧率通常高得多（60-240 FPS）。快照插值通过在两个已收到的快照之间进行数学插值，生成中间帧的渲染数据，从而消除因更新频率不足导致的画面卡顿。

快照插值的核心思想是让客户端的渲染始终滞后于最新服务器状态一个固定的时间量（通常称为插值延迟或渲染延迟）。这样客户端总是拥有两个时间点的快照数据可用于插值，确保渲染的连续性。

插值缓冲区设计
插值缓冲区是快照插值系统的核心数据结构。它存储最近收到的若干个服务器快照，并根据当前渲染时间查找用于插值的前后两个快照。


interface Snapshot {
  tick: number;
  serverTime: number;
  receiveTime: number;
  entities: Map<string, EntitySnapshot>;
}

interface EntitySnapshot {
  id: string;
  position: Vector3;
  rotation: Quaternion;
  velocity: Vector3;
  animationState: string;
  health: number;
}

interface Vector3 {
  x: number;
  y: number;
  z: number;
}

interface Quaternion {
  x: number;
  y: number;
  z: number;
  w: number;
}

class InterpolationBuffer {
  private snapshots: Snapshot[] = [];
  private maxSnapshots: number;
  private interpolationDelay: number;

  constructor(maxSnapshots: number = 30, interpolationDelay: number = 100) {
    this.maxSnapshots = maxSnapshots;
    this.interpolationDelay = interpolationDelay;
  }

  addSnapshot(snapshot: Snapshot): void {
    snapshot.receiveTime = performance.now();
    this.snapshots.push(snapshot);
    this.snapshots.sort((a, b) => a.serverTime - b.serverTime);

    while (this.snapshots.length > this.maxSnapshots) {
      this.snapshots.shift();
    }
  }

  getInterpolationPair(currentTime: number): { from: Snapshot; to: Snapshot; alpha: number } | null {
    const renderTime = currentTime - this.interpolationDelay;

    let fromIdx = -1;
    for (let i = this.snapshots.length - 1; i >= 0; i--) {
      if (this.snapshots[i].serverTime <= renderTime) {
        fromIdx = i;
        break;
      }
    }

    if (fromIdx < 0 || fromIdx >= this.snapshots.length - 1) return null;

    const from = this.snapshots[fromIdx];
    const to = this.snapshots[fromIdx + 1];
    const range = to.serverTime - from.serverTime;
    const alpha = range > 0 ? (renderTime - from.serverTime) / range : 0;

    return { from, to, alpha: Math.max(0, Math.min(1, alpha)) };
  }

  getBufferHealth(): number {
    if (this.snapshots.length < 2) return 0;
    const newest = this.snapshots[this.snapshots.length - 1];
    const renderTime = performance.now() - this.interpolationDelay;
    return newest.serverTime - renderTime;
  }
}
插值延迟的选择需要权衡平滑度和响应性。较大的插值延迟（150-200ms）可以容忍更多的网络抖动，渲染更平滑；但玩家看到的画面更滞后于实际游戏状态。对于 FPS 游戏，通常使用 100ms 左右的插值延迟；MMO 可以放宽到 150-200ms。


线性插值与高阶插值
线性插值是最常用的快照插值方法。它根据时间比例在两个快照状态之间做线性混合，实现简单且效果良好。


const lerpScalar = (a: number, b: number, t: number): number => a + (b - a) * t;

const lerpVector3 = (a: Vector3, b: Vector3, t: number): Vector3 => ({
  x: lerpScalar(a.x, b.x, t),
  y: lerpScalar(a.y, b.y, t),
  z: lerpScalar(a.z, b.z, t),
});

const slerpQuaternion = (a: Quaternion, b: Quaternion, t: number): Quaternion => {
  let dot = a.x * b.x + a.y * b.y + a.z * b.z + a.w * b.w;
  const target = { ...b };

  if (dot < 0) {
    dot = -dot;
    target.x = -target.x;
    target.y = -target.y;
    target.z = -target.z;
    target.w = -target.w;
  }

  if (dot > 0.9999) {
    return {
      x: lerpScalar(a.x, target.x, t),
      y: lerpScalar(a.y, target.y, t),
      z: lerpScalar(a.z, target.z, t),
      w: lerpScalar(a.w, target.w, t),
    };
  }

  const theta = Math.acos(dot);
  const sinTheta = Math.sin(theta);
  const wa = Math.sin((1 - t) * theta) / sinTheta;
  const wb = Math.sin(t * theta) / sinTheta;

  return {
    x: a.x * wa + target.x * wb,
    y: a.y * wa + target.y * wb,
    z: a.z * wa + target.z * wb,
    w: a.w * wa + target.w * wb,
  };
};

const interpolateEntity = (from: EntitySnapshot, to: EntitySnapshot, alpha: number): EntitySnapshot => ({
  id: from.id,
  position: lerpVector3(from.position, to.position, alpha),
  rotation: slerpQuaternion(from.rotation, to.rotation, alpha),
  velocity: lerpVector3(from.velocity, to.velocity, alpha),
  animationState: alpha < 0.5 ? from.animationState : to.animationState,
  health: alpha < 0.5 ? from.health : to.health,
});
对于高速移动或频繁变向的场景，线性插值可能产生不自然的运动轨迹。三次 Hermite 插值利用速度信息生成更平滑的曲线，特别适合赛车和飞行类游戏。


const hermiteInterpolate = (p0: number, v0: number, p1: number, v1: number, t: number, dt: number): number => {
  const t2 = t * t;
  const t3 = t2 * t;
  const h00 = 2 * t3 - 3 * t2 + 1;
  const h10 = (t3 - 2 * t2 + t) * dt;
  const h01 = -2 * t3 + 3 * t2;
  const h11 = (t3 - t2) * dt;
  return h00 * p0 + h10 * v0 + h01 * p1 + h11 * v1;
};

const hermiteVector3 = (p0: Vector3, v0: Vector3, p1: Vector3, v1: Vector3, t: number, dt: number): Vector3 => ({
  x: hermiteInterpolate(p0.x, v0.x, p1.x, v1.x, t, dt),
  y: hermiteInterpolate(p0.y, v0.y, p1.y, v1.y, t, dt),
  z: hermiteInterpolate(p0.z, v0.z, p1.z, v1.z, t, dt),
});
外推与混合策略
当网络延迟或丢包导致客户端没有足够的快照用于插值时，需要使用外推（Extrapolation）来预测实体的未来状态，避免画面冻结。


interface ExtrapolationConfig {
  maxExtrapolationTime: number;
  blendDuration: number;
  velocityDecay: number;
}

const extrapolateEntity = (
  lastSnapshot: EntitySnapshot,
  elapsedMs: number,
  config: ExtrapolationConfig,
): EntitySnapshot => {
  const dt = elapsedMs / 1000;
  const decay = Math.pow(config.velocityDecay, dt);

  const position: Vector3 = {
    x: lastSnapshot.position.x + lastSnapshot.velocity.x * dt * decay,
    y: lastSnapshot.position.y + lastSnapshot.velocity.y * dt * decay,
    z: lastSnapshot.position.z + lastSnapshot.velocity.z * dt * decay,
  };

  return { ...lastSnapshot, position };
};

class InterpolationSystem {
  private buffer: InterpolationBuffer;
  private extraConfig: ExtrapolationConfig;
  private lastRenderedStates: Map<string, EntitySnapshot>;

  constructor(buffer: InterpolationBuffer, extraConfig: ExtrapolationConfig) {
    this.buffer = buffer;
    this.extraConfig = extraConfig;
    this.lastRenderedStates = new Map();
  }

  update(currentTime: number): Map<string, EntitySnapshot> {
    const pair = this.buffer.getInterpolationPair(currentTime);
    const result = new Map<string, EntitySnapshot>();

    if (pair) {
      for (const [id, fromEntity] of pair.from.entities) {
        const toEntity = pair.to.entities.get(id);
        if (toEntity) {
          result.set(id, interpolateEntity(fromEntity, toEntity, pair.alpha));
        }
      }
    }

    this.lastRenderedStates = result;
    return result;
  }
}
外推的可靠性随时间快速下降。在实际项目中，外推通常限制在 200-300ms 以内。超过这个时间，实体的行为将难以预测（特别是受玩家输入控制的实体），继续外推反而会造成更大的视觉跳跃。


自适应插值延迟
固定的插值延迟在网络波动较大时可能表现不佳。当网络稳定时延迟过大会浪费响应性，当网络波动时延迟不足又会导致缓冲区耗尽。自适应插值延迟根据实时网络状况动态调整延迟值。


class AdaptiveInterpolation {
  private targetDelay: number;
  private currentDelay: number;
  private jitterHistory: number[] = [];
  private windowSize: number;
  private minDelay: number;
  private maxDelay: number;

  constructor(initialDelay: number = 100, minDelay: number = 50, maxDelay: number = 300, windowSize: number = 30) {
    this.targetDelay = initialDelay;
    this.currentDelay = initialDelay;
    this.minDelay = minDelay;
    this.maxDelay = maxDelay;
    this.windowSize = windowSize;
  }

  recordSnapshotArrival(serverTime: number, receiveTime: number): void {
    if (this.jitterHistory.length > 0) {
      const expectedInterval = serverTime - this.lastServerTime;
      const actualInterval = receiveTime - this.lastReceiveTime;
      const jitter = Math.abs(actualInterval - expectedInterval);
      this.jitterHistory.push(jitter);

      if (this.jitterHistory.length > this.windowSize) {
        this.jitterHistory.shift();
      }

      this.updateTargetDelay();
    }

    this.lastServerTime = serverTime;
    this.lastReceiveTime = receiveTime;
  }

  private lastServerTime: number = 0;
  private lastReceiveTime: number = 0;

  private updateTargetDelay(): void {
    const avgJitter = this.jitterHistory.reduce((a, b) => a + b, 0) / this.jitterHistory.length;
    const maxJitter = Math.max(...this.jitterHistory);
    this.targetDelay = Math.max(this.minDelay, Math.min(this.maxDelay, avgJitter * 2 + maxJitter * 0.5));
  }

  tick(deltaTime: number): number {
    const smoothSpeed = 0.05;
    this.currentDelay += (this.targetDelay - this.currentDelay) * smoothSpeed * deltaTime * 60;
    return this.currentDelay;
  }
}

小结
    

  • 快照插值通过在两个服务器快照之间做数学插值，为高帧率渲染生成平滑的中间状态
    • 

  • 插值缓冲区是核心数据结构，存储快照并根据渲染时间查找插值对
    • 

  • 位置使用线性插值，旋转使用球面线性插值（Slerp），离散状态使用阈值切换
    • 

  • 外推用于应对网络延迟导致的缓冲区不足，但应限制在 200-300ms 以内
    • 

  • 自适应插值延迟根据实时网络抖动动态调整，平衡平滑度和响应性
    • 

  • 不同网络状况需要不同的缓冲区深度和插值延迟配置
    •
