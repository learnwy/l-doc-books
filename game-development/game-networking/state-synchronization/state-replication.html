状态复制策略

核心概念

状态复制（State Replication）是权威服务器向客户端传播游戏世界状态的机制。它解决的核心问题是：如何高效地将服务器上数千个游戏实体的状态同步到每个客户端，同时尽可能减少带宽消耗和延迟。

不同于简单地将完整世界状态每帧发送给所有客户端，现代游戏引擎使用精细的复制策略：只同步变化的属性、根据实体与玩家的距离调整更新频率、按优先级分配带宽预算。这些策略共同构成了状态复制系统。

属性级脏标记系统
属性级复制的基础是脏标记（Dirty Flag）系统。当实体的某个属性被修改时，系统自动标记该属性为"脏"，只有被标记为脏的属性才会在下一次复制中被发送。


type PropertyKey = string;

interface ReplicatedProperty {
  key: PropertyKey;
  value: unknown;
  dirty: boolean;
  lastReplicatedTick: number;
  replicationCondition: ReplicationCondition;
  reliability: 'reliable' | 'unreliable';
}

const enum ReplicationCondition {
  Always = 0,
  OnChanged = 1,
  InitialOnly = 2,
  OwnerOnly = 3,
  SkipOwner = 4,
  Custom = 5,
}

class ReplicatedEntity {
  private entityId: string;
  private properties: Map<PropertyKey, ReplicatedProperty>;
  private dirtyMask: Set<PropertyKey>;

  constructor(entityId: string) {
    this.entityId = entityId;
    this.properties = new Map();
    this.dirtyMask = new Set();
  }

  registerProperty(
    key: PropertyKey,
    initialValue: unknown,
    condition: ReplicationCondition = ReplicationCondition.OnChanged,
    reliability: 'reliable' | 'unreliable' = 'unreliable',
  ): void {
    this.properties.set(key, {
      key,
      value: initialValue,
      dirty: true,
      lastReplicatedTick: 0,
      replicationCondition: condition,
      reliability,
    });
    this.dirtyMask.add(key);
  }

  setProperty(key: PropertyKey, value: unknown): void {
    const prop = this.properties.get(key);
    if (!prop) return;

    if (prop.value !== value) {
      prop.value = value;
      prop.dirty = true;
      this.dirtyMask.add(key);
    }
  }

  getDirtyProperties(): ReplicatedProperty[] {
    const result: ReplicatedProperty[] = [];
    for (const key of this.dirtyMask) {
      const prop = this.properties.get(key);
      if (prop?.dirty) result.push(prop);
    }
    return result;
  }

  clearDirty(tick: number): void {
    for (const key of this.dirtyMask) {
      const prop = this.properties.get(key);
      if (prop) {
        prop.dirty = false;
        prop.lastReplicatedTick = tick;
      }
    }
    this.dirtyMask.clear();
  }

  getEntityId(): string {
    return this.entityId;
  }

  isDirty(): boolean {
    return this.dirtyMask.size > 0;
  }
}
复制条件（Replication Condition）控制属性在不同情况下的复制行为。OwnerOnly 表示属性只同步给拥有者客户端（如玩家的弹药数），SkipOwner 表示属性同步给除拥有者外的所有客户端（如本地已预测的位置），InitialOnly 表示属性只在实体创建时同步一次（如角色模型 ID）。


优先级与带宽预算
在大规模游戏中，服务器不可能每帧将所有变化的属性发送给所有客户端。优先级系统决定了哪些实体的哪些属性应该优先获得有限的带宽资源。


interface PriorityConfig {
  bandwidthBudget: number;
  maxEntitiesPerUpdate: number;
  distanceFalloff: number;
  updateRateByDistance: Map<string, number>;
}

interface EntityPriority {
  entityId: string;
  basePriority: number;
  distancePriority: number;
  staleness: number;
  finalPriority: number;
}

class ReplicationPrioritizer {
  private config: PriorityConfig;
  private lastUpdateTick: Map<string, Map<string, number>>;

  constructor(config: PriorityConfig) {
    this.config = config;
    this.lastUpdateTick = new Map();
  }

  calculatePriorities(
    clientId: string,
    clientPosition: Vector3,
    entities: Map<string, ReplicatedEntity>,
    currentTick: number,
  ): EntityPriority[] {
    const clientUpdates = this.lastUpdateTick.get(clientId) ?? new Map();
    const priorities: EntityPriority[] = [];

    for (const [entityId, entity] of entities) {
      if (!entity.isDirty()) continue;

      const entityPos = entity.getDirtyProperties().find((p) => p.key === 'position')?.value as Vector3 | undefined;

      const basePriority = this.getBasePriority(entityId, clientId);
      const dist = entityPos ? this.distance(clientPosition, entityPos) : 100;
      const distancePriority = Math.max(0, 1 - dist / this.config.distanceFalloff);
      const lastTick = clientUpdates.get(entityId) ?? 0;
      const staleness = (currentTick - lastTick) / 60;

      priorities.push({
        entityId,
        basePriority,
        distancePriority,
        staleness,
        finalPriority: basePriority * 0.3 + distancePriority * 0.5 + staleness * 0.2,
      });
    }

    return priorities.sort((a, b) => b.finalPriority - a.finalPriority);
  }

  private getBasePriority(entityId: string, clientId: string): number {
    return entityId === clientId ? 10 : 1;
  }

  private distance(a: Vector3, b: Vector3): number {
    const dx = a.x - b.x;
    const dz = a.z - b.z;
    return Math.sqrt(dx * dx + dz * dz);
  }
}

interface Vector3 {
  x: number;
  y: number;
  z: number;
}
带宽预算机制限制了每帧可发送的数据总量。例如，如果服务器以 30 Tick/s 运行，目标带宽为 50KB/s，那么每 Tick 的预算约为 1.7KB。优先级排序确保了最重要的更新（如玩家自己的状态、近距离敌人）总是优先获得带宽。


条件复制与作用域
条件复制（Conditional Replication）根据客户端的上下文决定是否发送特定实体或属性。最常见的条件是基于距离的作用域（Relevancy），只有在玩家视野范围内的实体才需要同步。


interface RelevancyConfig {
  maxRelevantDistance: number;
  relevancyCheckInterval: number;
  alwaysRelevantTypes: string[];
  ownerAlwaysRelevant: boolean;
}

class RelevancySystem {
  private config: RelevancyConfig;
  private relevancySets: Map<string, Set<string>>;
  private lastCheckTick: Map<string, number>;

  constructor(config: RelevancyConfig) {
    this.config = config;
    this.relevancySets = new Map();
    this.lastCheckTick = new Map();
  }

  updateRelevancy(
    clientId: string,
    clientPosition: Vector3,
    entities: Map<string, EntityInfo>,
    currentTick: number,
  ): Set<string> {
    const lastCheck = this.lastCheckTick.get(clientId) ?? 0;
    if (currentTick - lastCheck < this.config.relevancyCheckInterval) {
      return this.relevancySets.get(clientId) ?? new Set();
    }

    const relevant = new Set<string>();
    const previousSet = this.relevancySets.get(clientId) ?? new Set();

    for (const [entityId, entity] of entities) {
      if (this.config.alwaysRelevantTypes.includes(entity.type)) {
        relevant.add(entityId);
        continue;
      }

      if (this.config.ownerAlwaysRelevant && entity.ownerId === clientId) {
        relevant.add(entityId);
        continue;
      }

      const dist = this.distance(clientPosition, entity.position);
      if (dist <= this.config.maxRelevantDistance) {
        relevant.add(entityId);
      }
    }

    this.handleRelevancyChanges(clientId, previousSet, relevant);
    this.relevancySets.set(clientId, relevant);
    this.lastCheckTick.set(clientId, currentTick);
    return relevant;
  }

  private handleRelevancyChanges(_clientId: string, previous: Set<string>, current: Set<string>): void {
    for (const entityId of current) {
      if (!previous.has(entityId)) {
        this.onEntityBecomeRelevant(entityId);
      }
    }
    for (const entityId of previous) {
      if (!current.has(entityId)) {
        this.onEntityBecomeIrrelevant(entityId);
      }
    }
  }

  private onEntityBecomeRelevant(_entityId: string): void {}
  private onEntityBecomeIrrelevant(_entityId: string): void {}

  private distance(a: Vector3, b: Vector3): number {
    const dx = a.x - b.x;
    const dz = a.z - b.z;
    return Math.sqrt(dx * dx + dz * dz);
  }
}

interface EntityInfo {
  type: string;
  ownerId: string;
  position: Vector3;
}
当实体进入客户端的相关范围时，需要发送完整的初始状态（Spawn 消息）；当实体离开范围时，发送销毁通知（Despawn 消息）。这种进出机制确保了客户端只维护相关实体的状态，减少了内存和渲染开销。


远程过程调用
除了持续的状态复制，游戏还需要远程过程调用（RPC）来处理离散事件，如释放技能、打开宝箱、发送聊天消息。RPC 与状态复制互为补充：状态复制适合持续变化的数据，RPC 适合一次性的事件。


const enum RpcTarget {
  Server = 0,
  Client = 1,
  AllClients = 2,
  AllClientsExceptSender = 3,
  NetMulticast = 4,
}

interface RpcDefinition {
  name: string;
  target: RpcTarget;
  reliable: boolean;
  params: RpcParam[];
}

interface RpcParam {
  name: string;
  type: 'int' | 'float' | 'string' | 'vector3' | 'bool';
}

interface RpcInvocation {
  rpcId: number;
  entityId: string;
  params: unknown[];
  senderId: string;
  timestamp: number;
}

class RpcSystem {
  private definitions: Map<number, RpcDefinition>;
  private handlers: Map<number, (invocation: RpcInvocation) => void>;
  private nextRpcId: number = 0;

  constructor() {
    this.definitions = new Map();
    this.handlers = new Map();
  }

  registerRpc(definition: RpcDefinition, handler: (invocation: RpcInvocation) => void): number {
    const rpcId = this.nextRpcId++;
    this.definitions.set(rpcId, definition);
    this.handlers.set(rpcId, handler);
    return rpcId;
  }

  invoke(rpcId: number, entityId: string, senderId: string, params: unknown[]): void {
    const def = this.definitions.get(rpcId);
    if (!def) return;

    const invocation: RpcInvocation = {
      rpcId,
      entityId,
      params,
      senderId,
      timestamp: Date.now(),
    };

    const handler = this.handlers.get(rpcId);
    if (handler) handler(invocation);
  }
}

小结
    

  • 属性级脏标记系统只复制发生变化的属性，大幅减少冗余数据传输
    • 

  • 复制条件控制属性在不同场景下的同步行为（仅拥有者、跳过拥有者、仅初始化）
    • 

  • 优先级系统结合距离、陈旧度和基础权重，在带宽预算内分配资源
    • 

  • 条件复制通过距离作用域限制每个客户端需要同步的实体数量
    • 

  • RPC 与状态复制互补，处理离散事件通信
    • 

  • 混合使用多种复制策略是大型游戏的标准实践
