Part III · 网络与设计游戏网络与多人联机 简介延迟补偿 简介客户端预测

客户端预测

核心概念

客户端预测（Client-Side Prediction）是解决权威服务器架构中输入延迟问题的核心技术。在纯粹的权威服务器模型中，玩家按下按键后需要等待输入传输到服务器、服务器处理后再将结果返回客户端，整个过程的延迟等于一个完整的网络往返时间（RTT）。在 100ms RTT 的网络条件下，玩家操作后需要等待至少 100ms 才能看到角色移动，这种延迟在动作游戏中是不可接受的。

客户端预测的核心思想是：客户端在发送输入给服务器的同时，立即在本地执行相同的游戏逻辑来预测结果。这样玩家可以即时看到自己操作的反馈，而服务器的权威结果在稍后到达时用于校正预测误差。

预测循环实现
客户端预测系统需要维护一个输入历史缓冲区，记录每帧发送给服务器的输入及其对应的预测状态。当收到服务器的权威响应时，将预测状态与权威状态进行比较，如果存在偏差则进行回滚和重新模拟。


interface PredictedInput {
  sequence: number;
  tick: number;
  moveX: number;
  moveZ: number;
  jump: boolean;
  shoot: boolean;
  timestamp: number;
}

interface PredictedState {
  position: Vector3;
  velocity: Vector3;
  isGrounded: boolean;
}

interface Vector3 {
  x: number;
  y: number;
  z: number;
}

interface ServerState {
  tick: number;
  lastProcessedInput: number;
  position: Vector3;
  velocity: Vector3;
  isGrounded: boolean;
}

class ClientPrediction {
  private pendingInputs: PredictedInput[] = [];
  private predictedState: PredictedState;
  private inputSequence: number = 0;
  private simulationConfig: SimulationConfig;

  constructor(initialState: PredictedState, config: SimulationConfig) {
    this.predictedState = { ...initialState };
    this.simulationConfig = config;
  }

  processInput(rawInput: RawInput): PredictedInput {
    const input: PredictedInput = {
      sequence: this.inputSequence++,
      tick: 0,
      moveX: rawInput.horizontal,
      moveZ: rawInput.vertical,
      jump: rawInput.jump,
      shoot: rawInput.shoot,
      timestamp: performance.now(),
    };

    this.predictedState = this.simulate(this.predictedState, input);
    this.pendingInputs.push(input);

    return input;
  }

  onServerState(serverState: ServerState): PredictedState {
    this.pendingInputs = this.pendingInputs.filter((input) => input.sequence > serverState.lastProcessedInput);

    let state: PredictedState = {
      position: { ...serverState.position },
      velocity: { ...serverState.velocity },
      isGrounded: serverState.isGrounded,
    };

    for (const input of this.pendingInputs) {
      state = this.simulate(state, input);
    }

    this.predictedState = state;
    return state;
  }

  private simulate(state: PredictedState, input: PredictedInput): PredictedState {
    const dt = 1 / this.simulationConfig.tickRate;
    const speed = this.simulationConfig.moveSpeed;
    const gravity = this.simulationConfig.gravity;

    const newVelocity: Vector3 = {
      x: input.moveX * speed,
      y: state.velocity.y,
      z: input.moveZ * speed,
    };

    if (input.jump && state.isGrounded) {
      newVelocity.y = this.simulationConfig.jumpForce;
    }

    newVelocity.y += gravity * dt;

    const newPosition: Vector3 = {
      x: state.position.x + newVelocity.x * dt,
      y: state.position.y + newVelocity.y * dt,
      z: state.position.z + newVelocity.z * dt,
    };

    let isGrounded = false;
    if (newPosition.y <= 0) {
      newPosition.y = 0;
      newVelocity.y = 0;
      isGrounded = true;
    }

    return { position: newPosition, velocity: newVelocity, isGrounded };
  }

  getPredictedState(): PredictedState {
    return this.predictedState;
  }

  getPendingInputCount(): number {
    return this.pendingInputs.length;
  }
}

interface SimulationConfig {
  tickRate: number;
  moveSpeed: number;
  gravity: number;
  jumpForce: number;
}

interface RawInput {
  horizontal: number;
  vertical: number;
  jump: boolean;
  shoot: boolean;
}
预测循环的关键点在于：客户端和服务器必须使用完全相同的物理模拟代码（或等价的确定性实现）。任何模拟差异都会导致预测误差，进而触发不必要的回滚修正，影响玩家体验。


预测范围与限制
并非所有游戏行为都适合客户端预测。一个好的原则是：只预测由本地玩家输入直接驱动的、确定性的行为；不预测依赖其他玩家或服务器随机性的行为。

乐观预测（Optimistic Prediction）是一种折中方案。对于物品拾取等操作，客户端先乐观地认为操作会成功并立即显示效果，如果服务器随后否定了这个操作，再回滚到之前的状态。虽然可能产生偶尔的闪回，但大多数时候能提供更好的响应感。


输入缓冲与发送策略
客户端需要持续发送输入给服务器，发送策略直接影响带宽消耗和服务器收到输入的及时性。常见的策略包括冗余发送和输入聚合。


class InputSender {
  private pendingInputs: PredictedInput[] = [];
  private redundancyCount: number;
  private sendRate: number;
  private lastSendTime: number = 0;

  constructor(redundancy: number = 3, sendRate: number = 60) {
    this.redundancyCount = redundancy;
    this.sendRate = sendRate;
  }

  queueInput(input: PredictedInput): void {
    this.pendingInputs.push(input);
  }

  shouldSend(currentTime: number): boolean {
    const interval = 1000 / this.sendRate;
    return currentTime - this.lastSendTime >= interval;
  }

  buildPacket(): InputPacket {
    const recentInputs = this.pendingInputs.slice(-this.redundancyCount);
    const packet: InputPacket = {
      inputs: recentInputs,
      latestSequence: recentInputs[recentInputs.length - 1]?.sequence ?? 0,
    };
    return packet;
  }

  onAck(ackedSequence: number): void {
    this.pendingInputs = this.pendingInputs.filter((input) => input.sequence > ackedSequence);
  }

  send(currentTime: number): InputPacket | null {
    if (!this.shouldSend(currentTime) || this.pendingInputs.length === 0) {
      return null;
    }
    this.lastSendTime = currentTime;
    return this.buildPacket();
  }
}

interface InputPacket {
  inputs: PredictedInput[];
  latestSequence: number;
}
冗余发送是应对 UDP 丢包的关键策略。每个数据包不仅包含当前帧的输入，还包含前 2-3 帧的输入。即使某个包丢失，服务器仍能从后续包中获取到之前的输入。这种策略以少量额外带宽（每个输入约 8-12 字节）换取了更好的输入完整性。


预测误差平滑
当服务器的权威状态与客户端的预测状态存在偏差时，直接跳变到正确位置会造成视觉上的突兀跳跃。预测误差平滑通过在多帧内逐渐修正偏差，使校正过程对玩家透明。


class PredictionErrorSmoother {
  private positionError: Vector3 = { x: 0, y: 0, z: 0 };
  private smoothingDuration: number;
  private smoothingTimer: number = 0;
  private errorThreshold: number;

  constructor(smoothingDuration: number = 200, errorThreshold: number = 5) {
    this.smoothingDuration = smoothingDuration;
    this.errorThreshold = errorThreshold;
  }

  onCorrectionReceived(predicted: Vector3, corrected: Vector3): void {
    const error: Vector3 = {
      x: corrected.x - predicted.x,
      y: corrected.y - predicted.y,
      z: corrected.z - predicted.z,
    };

    const errorMag = Math.sqrt(error.x ** 2 + error.y ** 2 + error.z ** 2);

    if (errorMag > this.errorThreshold) {
      this.positionError = { x: 0, y: 0, z: 0 };
      this.smoothingTimer = 0;
      return;
    }

    this.positionError = {
      x: this.positionError.x + error.x,
      y: this.positionError.y + error.y,
      z: this.positionError.z + error.z,
    };
    this.smoothingTimer = this.smoothingDuration;
  }

  update(deltaMs: number): Vector3 {
    if (this.smoothingTimer <= 0) return { x: 0, y: 0, z: 0 };

    const t = Math.min(deltaMs / this.smoothingTimer, 1);
    const correction: Vector3 = {
      x: this.positionError.x * t,
      y: this.positionError.y * t,
      z: this.positionError.z * t,
    };

    this.positionError.x -= correction.x;
    this.positionError.y -= correction.y;
    this.positionError.z -= correction.z;
    this.smoothingTimer -= deltaMs;

    return correction;
  }

  getRemainingError(): number {
    return Math.sqrt(this.positionError.x ** 2 + this.positionError.y ** 2 + this.positionError.z ** 2);
  }
}
误差平滑的阈值设置很关键。小偏差（< 0.5 单位）通常不需要修正，可以直接忽略；中等偏差（0.5-5 单位）应用平滑修正；大偏差（> 5 单位）说明预测严重失误，应直接跳变到正确位置。


小结
    

  • 客户端预测消除了权威服务器带来的输入延迟，玩家可即时看到操作反馈
    • 

  • 预测系统维护输入历史缓冲区，收到服务器状态后回滚并重新模拟未确认的输入
    • 

  • 客户端和服务器必须使用相同的物理模拟逻辑以最小化预测误差
    • 

  • 只对本地玩家输入驱动的确定性行为进行预测，命中判定等依赖服务端权威
    • 

  • 冗余发送策略以少量额外带宽换取更好的抗丢包能力
    • 

  • 预测误差通过平滑修正对玩家透明，大偏差时直接跳变
