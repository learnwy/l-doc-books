帧锁定与回滚网络

核心概念

帧锁定（Lockstep）和回滚（Rollback）是 P2P 架构中两种主要的网络同步模型，它们解决的核心问题是：在没有权威服务器的情况下，如何保证所有客户端的游戏状态完全一致。

帧锁定模型要求所有玩家在同一逻辑帧收齐所有输入后才推进游戏。这保证了完美的同步一致性，但游戏的推进速度受制于最慢的网络连接。回滚网络则允许客户端基于本地输入立即推进游戏，当收到远程玩家的实际输入后，如果与预测不一致，就回滚到分歧点重新模拟。

这两种模型在格斗游戏、RTS 和各种竞技游戏中广泛应用，选择哪种模型取决于游戏类型、玩家数量和延迟容忍度。

帧锁定实现
帧锁定的核心是输入同步屏障：游戏逻辑只在收到所有玩家的输入后才推进到下一帧。这需要每个客户端在每帧开始时广播自己的输入，并等待其他所有客户端的输入到达。


interface FrameInput {
  playerId: string;
  frame: number;
  actions: number;
  checksum: number;
}

interface LockstepConfig {
  inputDelayFrames: number;
  timeoutMs: number;
  maxRollbackFrames: number;
  playerCount: number;
}

class LockstepManager {
  private config: LockstepConfig;
  private currentFrame: number = 0;
  private inputBuffer: Map<number, Map<string, FrameInput>>;
  private localPlayerId: string;
  private confirmedFrame: number = -1;

  constructor(localPlayerId: string, config: LockstepConfig) {
    this.localPlayerId = localPlayerId;
    this.config = config;
    this.inputBuffer = new Map();
  }

  submitLocalInput(actions: number): FrameInput {
    const targetFrame = this.currentFrame + this.config.inputDelayFrames;
    const input: FrameInput = {
      playerId: this.localPlayerId,
      frame: targetFrame,
      actions,
      checksum: 0,
    };

    this.storeInput(input);
    return input;
  }

  receiveRemoteInput(input: FrameInput): void {
    this.storeInput(input);
  }

  private storeInput(input: FrameInput): void {
    if (!this.inputBuffer.has(input.frame)) {
      this.inputBuffer.set(input.frame, new Map());
    }
    this.inputBuffer.get(input.frame)!.set(input.playerId, input);
  }

  canAdvance(): boolean {
    const nextFrame = this.confirmedFrame + 1;
    const inputs = this.inputBuffer.get(nextFrame);
    if (!inputs) return false;
    return inputs.size >= this.config.playerCount;
  }

  advance(): Map<string, FrameInput> | null {
    if (!this.canAdvance()) return null;

    const nextFrame = this.confirmedFrame + 1;
    const inputs = this.inputBuffer.get(nextFrame)!;
    this.confirmedFrame = nextFrame;
    this.currentFrame = nextFrame;

    this.cleanupOldFrames(nextFrame - 60);
    return inputs;
  }

  private cleanupOldFrames(beforeFrame: number): void {
    for (const [frame] of this.inputBuffer) {
      if (frame < beforeFrame) this.inputBuffer.delete(frame);
    }
  }

  getConfirmedFrame(): number {
    return this.confirmedFrame;
  }
}
输入延迟（Input Delay）是帧锁定的关键参数。它决定了玩家的输入在多少帧之后才生效。例如，3 帧的输入延迟意味着玩家在帧 N 的输入会在帧 N+3 被执行。这给了足够的时间让输入通过网络传输到所有客户端。输入延迟通常设置为 RTT/2 对应的帧数加 1-2 帧的安全余量。


帧锁定的主要缺点是当某个玩家的网络波动时，所有玩家都会感受到卡顿。这就是为什么帧锁定在高延迟环境下体验较差的原因。


回滚网络架构
回滚网络（Rollback Netcode）通过预测远程玩家的输入来消除等待延迟。当本地玩家按下按键时，游戏立即推进；对于远程玩家，系统假设他们会重复上一帧的输入。当实际输入到达后，如果预测正确则无需任何操作；如果预测错误，系统回滚到分歧帧并用正确输入重新模拟到当前帧。


interface RollbackConfig {
  maxRollbackFrames: number;
  inputPredictionStrategy: 'repeat' | 'neutral';
  desyncCheckInterval: number;
}

interface GameStateSnapshot {
  frame: number;
  data: Uint8Array;
  checksum: number;
}

class RollbackNetcode {
  private config: RollbackConfig;
  private localFrame: number = 0;
  private remoteConfirmedFrame: number = -1;
  private stateHistory: GameStateSnapshot[] = [];
  private localInputs: Map<number, number> = new Map();
  private remoteInputs: Map<number, number> = new Map();
  private predictedInputs: Map<number, number> = new Map();

  constructor(config: RollbackConfig) {
    this.config = config;
  }

  advanceFrame(localActions: number): AdvanceResult {
    this.localInputs.set(this.localFrame, localActions);

    const remoteActions = this.getRemoteInputForFrame(this.localFrame);

    this.saveState(this.localFrame);
    this.localFrame++;

    return {
      frame: this.localFrame - 1,
      localInput: localActions,
      remoteInput: remoteActions,
      predicted: !this.remoteInputs.has(this.localFrame - 1),
    };
  }

  onRemoteInput(frame: number, actions: number): void {
    this.remoteInputs.set(frame, actions);

    if (frame <= this.localFrame) {
      const predicted = this.predictedInputs.get(frame);
      if (predicted !== undefined && predicted !== actions) {
        this.rollbackAndResimulate(frame);
      }
    }

    this.updateConfirmedFrame();
  }

  private rollbackAndResimulate(divergenceFrame: number): void {
    const snapshot = this.findSnapshot(divergenceFrame);
    if (!snapshot) return;

    this.restoreState(snapshot);

    for (let f = divergenceFrame; f < this.localFrame; f++) {
      const local = this.localInputs.get(f) ?? 0;
      const remote = this.getRemoteInputForFrame(f);
      this.simulateFrame(local, remote);
      this.saveState(f);
    }
  }

  private getRemoteInputForFrame(frame: number): number {
    const actual = this.remoteInputs.get(frame);
    if (actual !== undefined) return actual;

    let predicted: number;
    if (this.config.inputPredictionStrategy === 'repeat') {
      predicted = this.getLastKnownRemoteInput();
    } else {
      predicted = 0;
    }

    this.predictedInputs.set(frame, predicted);
    return predicted;
  }

  private getLastKnownRemoteInput(): number {
    let latest = -1;
    let latestInput = 0;
    for (const [frame, input] of this.remoteInputs) {
      if (frame > latest) {
        latest = frame;
        latestInput = input;
      }
    }
    return latestInput;
  }

  private updateConfirmedFrame(): void {
    while (this.remoteInputs.has(this.remoteConfirmedFrame + 1)) {
      this.remoteConfirmedFrame++;
    }
  }

  private saveState(_frame: number): void {}
  private findSnapshot(_frame: number): GameStateSnapshot | null {
    return null;
  }
  private restoreState(_snapshot: GameStateSnapshot): void {}
  private simulateFrame(_local: number, _remote: number): void {}
}

interface AdvanceResult {
  frame: number;
  localInput: number;
  remoteInput: number;
  predicted: boolean;
}
状态序列化与校验
回滚网络要求快速保存和恢复游戏状态，以及通过校验和（Checksum）检测两端的模拟是否同步。


interface SerializableGameState {
  playerPositions: Float32Array;
  playerVelocities: Float32Array;
  playerHealth: Uint16Array;
  entityStates: Uint8Array;
}

class StateSerializer {
  serialize(state: SerializableGameState): Uint8Array {
    const totalSize =
      state.playerPositions.byteLength +
      state.playerVelocities.byteLength +
      state.playerHealth.byteLength +
      state.entityStates.byteLength;

    const buffer = new Uint8Array(totalSize);
    let offset = 0;

    buffer.set(new Uint8Array(state.playerPositions.buffer), offset);
    offset += state.playerPositions.byteLength;

    buffer.set(new Uint8Array(state.playerVelocities.buffer), offset);
    offset += state.playerVelocities.byteLength;

    buffer.set(new Uint8Array(state.playerHealth.buffer), offset);
    offset += state.playerHealth.byteLength;

    buffer.set(state.entityStates, offset);

    return buffer;
  }

  computeChecksum(data: Uint8Array): number {
    let hash = 0x811c9dc5;
    for (let i = 0; i < data.length; i++) {
      hash ^= data[i];
      hash = Math.imul(hash, 0x01000193);
    }
    return hash >>> 0;
  }
}

class DesyncDetector {
  private checksumHistory: Map<number, Map<string, number>> = new Map();

  reportChecksum(playerId: string, frame: number, checksum: number): void {
    if (!this.checksumHistory.has(frame)) {
      this.checksumHistory.set(frame, new Map());
    }
    this.checksumHistory.get(frame)!.set(playerId, checksum);
  }

  detectDesync(frame: number, playerCount: number): boolean {
    const checksums = this.checksumHistory.get(frame);
    if (!checksums || checksums.size < playerCount) return false;

    const values = Array.from(checksums.values());
    return !values.every((v) => v === values[0]);
  }
}
反同步（Desync）检测是回滚网络的安全网。双方定期交换已确认帧的状态校验和，如果发现不一致就说明发生了反同步。反同步通常由浮点精度差异、未处理的非确定性行为或 Bug 导致。


GGPO 与现代实现
GGPO（Good Game Peace Out）是回滚网络的事实标准库，最初由 Tony Cannon 为格斗游戏开发。它的核心创新是将网络同步的复杂性封装为简洁的回调接口，游戏只需实现状态序列化、反序列化和模拟逻辑。


interface GGPOCallbacks {
  saveGameState: (frame: number) => Uint8Array;
  loadGameState: (frame: number, data: Uint8Array) => void;
  advanceFrame: (inputs: Map<number, number>) => void;
  onEvent: (event: GGPOEvent) => void;
}

interface GGPOEvent {
  type: 'connected' | 'synchronizing' | 'synchronized' | 'disconnected' | 'desync';
  player?: number;
  data?: unknown;
}

interface GGPOSessionConfig {
  numPlayers: number;
  inputSize: number;
  localPort: number;
  remoteEndpoints: { address: string; port: number }[];
}

现代回滚网络实现通常包含以下优化：预测输入使用"重复上一帧"策略（格斗游戏中约 85% 的帧输入与上一帧相同）、限制最大回滚帧数（通常 7-8 帧）避免过大的视觉跳跃、时间同步确保双方的本地时钟对齐。


小结
    

  • 帧锁定保证完美同步但受限于最慢连接，适合 RTS 和低延迟环境
    • 

  • 回滚网络通过预测输入实现即时响应，预测错误时回滚重新模拟
    • 

  • 回滚网络要求游戏逻辑完全确定性，以及快速的状态保存和恢复
    • 

  • 校验和检测用于发现不同客户端之间的模拟偏差（反同步）
    • 

  • GGPO 是回滚网络的标准实现，将复杂性封装为简洁的回调接口
    • 

  • 选择帧锁定还是回滚取决于游戏类型、玩家数量和延迟容忍度
