服务端回滚与校正

核心概念

服务端回滚与校正（Server Reconciliation）是客户端预测的互补机制。当服务器处理完玩家输入并返回权威状态时，客户端需要将服务器状态与本地预测状态进行对比。如果发现偏差，客户端必须回滚到服务器的权威状态，然后重新应用所有尚未被服务器确认的输入，重新模拟出最新的预测状态。

这个过程称为"回滚-重放"（Rollback-Replay），是保证客户端预测系统正确性的关键环节。没有服务端校正，客户端的预测误差会随时间累积，最终导致客户端状态与服务器状态严重分歧。

回滚-重放机制
回滚-重放的核心流程是：收到服务器状态后，找到对应的输入序列号，将客户端状态重置为服务器的权威状态，然后按顺序重新模拟所有后续的未确认输入。


interface AuthoritativeState {
  tick: number;
  lastInputSequence: number;
  position: Vector3;
  velocity: Vector3;
  isGrounded: boolean;
  health: number;
  ammo: number;
}

interface Vector3 {
  x: number;
  y: number;
  z: number;
}

interface BufferedInput {
  sequence: number;
  input: PlayerInput;
  predictedState: PlayerState;
}

interface PlayerInput {
  moveX: number;
  moveZ: number;
  jump: boolean;
  shoot: boolean;
}

interface PlayerState {
  position: Vector3;
  velocity: Vector3;
  isGrounded: boolean;
}

interface ReconciliationResult {
  stateChanged: boolean;
  positionError: number;
  inputsReplayed: number;
  newState: PlayerState;
}

class ServerReconciliation {
  private inputHistory: BufferedInput[] = [];
  private maxHistorySize: number;
  private simulateStep: (state: PlayerState, input: PlayerInput) => PlayerState;
  private currentState: PlayerState;

  constructor(
    initialState: PlayerState,
    maxHistory: number,
    simulateFn: (state: PlayerState, input: PlayerInput) => PlayerState,
  ) {
    this.currentState = { ...initialState };
    this.maxHistorySize = maxHistory;
    this.simulateStep = simulateFn;
  }

  recordInput(sequence: number, input: PlayerInput): void {
    const predictedState = this.simulateStep(this.currentState, input);
    this.inputHistory.push({ sequence, input, predictedState });
    this.currentState = predictedState;

    if (this.inputHistory.length > this.maxHistorySize) {
      this.inputHistory.shift();
    }
  }

  reconcile(serverState: AuthoritativeState): ReconciliationResult {
    const ackSeq = serverState.lastInputSequence;

    this.inputHistory = this.inputHistory.filter((entry) => entry.sequence > ackSeq);

    const authoritative: PlayerState = {
      position: { ...serverState.position },
      velocity: { ...serverState.velocity },
      isGrounded: serverState.isGrounded,
    };

    let replayState = authoritative;
    for (const entry of this.inputHistory) {
      replayState = this.simulateStep(replayState, entry.input);
      entry.predictedState = replayState;
    }

    const positionError = this.distanceBetween(this.currentState.position, replayState.position);

    this.currentState = replayState;

    return {
      stateChanged: positionError > 0.001,
      positionError,
      inputsReplayed: this.inputHistory.length,
      newState: replayState,
    };
  }

  private distanceBetween(a: Vector3, b: Vector3): number {
    const dx = a.x - b.x;
    const dy = a.y - b.y;
    const dz = a.z - b.z;
    return Math.sqrt(dx * dx + dy * dy + dz * dz);
  }

  getCurrentState(): PlayerState {
    return this.currentState;
  }
}
回滚-重放的计算开销取决于需要重新模拟的输入数量，这等于 RTT 期间积累的输入帧数。在 100ms RTT、60 Tick/s 的条件下，每次校正需要重新模拟约 6 帧。对于简单的移动模拟，这个开销完全可以接受。


状态快照管理
高效的回滚-重放需要一个状态快照管理系统来记录每帧的完整状态，以便精确定位回滚目标。


interface StateSnapshot {
  tick: number;
  inputSequence: number;
  state: PlayerState;
  timestamp: number;
}

class StateSnapshotBuffer {
  private snapshots: StateSnapshot[] = [];
  private maxSize: number;

  constructor(maxSize: number = 128) {
    this.maxSize = maxSize;
  }

  save(tick: number, inputSequence: number, state: PlayerState): void {
    this.snapshots.push({
      tick,
      inputSequence,
      state: this.cloneState(state),
      timestamp: performance.now(),
    });

    while (this.snapshots.length > this.maxSize) {
      this.snapshots.shift();
    }
  }

  findByInputSequence(sequence: number): StateSnapshot | undefined {
    return this.snapshots.find((s) => s.inputSequence === sequence);
  }

  findByTick(tick: number): StateSnapshot | undefined {
    return this.snapshots.find((s) => s.tick === tick);
  }

  getSnapshotsAfter(sequence: number): StateSnapshot[] {
    const idx = this.snapshots.findIndex((s) => s.inputSequence > sequence);
    return idx >= 0 ? this.snapshots.slice(idx) : [];
  }

  private cloneState(state: PlayerState): PlayerState {
    return {
      position: { ...state.position },
      velocity: { ...state.velocity },
      isGrounded: state.isGrounded,
    };
  }

  clear(): void {
    this.snapshots = [];
  }

  getSize(): number {
    return this.snapshots.length;
  }
}
快照缓冲区的大小需要足够覆盖最大 RTT 期间产生的所有帧。以 200ms 最大 RTT 和 60 Tick/s 计算，至少需要 12 帧的缓冲空间。通常设置为 64-128 帧以提供足够的安全余量。


确定性模拟保证
回滚-重放的正确性依赖于一个关键前提：给定相同的初始状态和相同的输入，客户端和服务器的模拟必须产生完全相同的结果。这就是确定性模拟的要求。


非确定性因素包括浮点运算顺序差异、不同平台的数学库实现差异、随机数生成器状态不一致和物理引擎的非确定性行为。


class DeterministicRandom {
  private state: number;

  constructor(seed: number) {
    this.state = seed;
  }

  next(): number {
    this.state = (this.state * 1103515245 + 12345) & 0x7fffffff;
    return this.state / 0x7fffffff;
  }

  nextRange(min: number, max: number): number {
    return min + this.next() * (max - min);
  }

  nextInt(min: number, max: number): number {
    return Math.floor(this.nextRange(min, max + 1));
  }

  getState(): number {
    return this.state;
  }

  setState(state: number): void {
    this.state = state;
  }
}

class FixedPointMath {
  static readonly SCALE = 1000;

  static fromFloat(value: number): number {
    return Math.round(value * FixedPointMath.SCALE);
  }

  static toFloat(value: number): number {
    return value / FixedPointMath.SCALE;
  }

  static multiply(a: number, b: number): number {
    return Math.round((a * b) / FixedPointMath.SCALE);
  }

  static divide(a: number, b: number): number {
    return Math.round((a * FixedPointMath.SCALE) / b);
  }

  static sqrt(value: number): number {
    return Math.round(Math.sqrt(value * FixedPointMath.SCALE));
  }
}

在实际项目中，完全的确定性通常难以实现（特别是使用第三方物理引擎时）。更实用的做法是接受微小的模拟偏差，通过误差平滑来隐藏这些偏差，同时将偏差控制在可接受的范围内。


多实体校正
在复杂的游戏场景中，不仅玩家角色需要预测和校正，玩家驾驶的载具、推动的物体等交互实体也需要参与回滚-重放过程。


interface EntityReconciliation {
  entityId: string;
  ownerClientId: string;
  predictable: boolean;
  lastServerState: EntityState;
}

interface EntityState {
  position: Vector3;
  velocity: Vector3;
  rotation: number;
  customData: Record<string, number>;
}

class MultiEntityReconciler {
  private entities: Map<string, EntityReconciliation> = new Map();
  private stateHistory: Map<string, EntityState[]> = new Map();
  private historyLimit: number;

  constructor(historyLimit: number = 64) {
    this.historyLimit = historyLimit;
  }

  registerEntity(entityId: string, ownerId: string, predictable: boolean): void {
    this.entities.set(entityId, {
      entityId,
      ownerClientId: ownerId,
      predictable,
      lastServerState: {
        position: { x: 0, y: 0, z: 0 },
        velocity: { x: 0, y: 0, z: 0 },
        rotation: 0,
        customData: {},
      },
    });
    this.stateHistory.set(entityId, []);
  }

  onServerUpdate(entityId: string, serverState: EntityState, serverTick: number): EntityState | null {
    const entity = this.entities.get(entityId);
    if (!entity) return null;

    entity.lastServerState = serverState;

    if (!entity.predictable) {
      return serverState;
    }

    const history = this.stateHistory.get(entityId) ?? [];
    const predicted = history[history.length - 1];

    if (!predicted) return serverState;

    const error = this.calculateError(predicted, serverState);
    if (error > 0.01) {
      return this.reconcileEntity(entityId, serverState, serverTick);
    }

    return null;
  }

  private reconcileEntity(_entityId: string, serverState: EntityState, _serverTick: number): EntityState {
    return serverState;
  }

  private calculateError(predicted: EntityState, server: EntityState): number {
    const dx = predicted.position.x - server.position.x;
    const dy = predicted.position.y - server.position.y;
    const dz = predicted.position.z - server.position.z;
    return Math.sqrt(dx * dx + dy * dy + dz * dz);
  }
}
多实体校正增加了回滚-重放的复杂度和计算开销。一种优化策略是按交互距离设置校正优先级：与玩家直接交互的实体（如正在驾驶的载具）进行完整的回滚-重放；距离较远的实体只做简单的插值校正。
