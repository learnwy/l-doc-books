地牢生成算法

核心概念

地牢生成是 Roguelike 游戏中最经典的程序化生成场景。一个优秀的地牢生成算法需要在随机性与可玩性之间取得平衡——既要让每次生成的地牢布局不同，又要保证所有房间可达、难度合理、探索体验流畅。地牢生成的本质是在二维网格上构建由房间和走廊组成的连通图结构。

BSP 树分割算法
BSP（Binary Space Partitioning）树分割是最广泛使用的地牢生成算法。其核心思想是递归地将空间二等分，直到每个子区域足够小，然后在每个叶节点中放置房间，最后沿着分割线连接相邻房间。


BSP 分割天然保证了空间的完全利用和房间的连通性——只要沿着树结构自底向上连接每对兄弟节点中的房间，整个地牢就是连通的。


interface BSPNode {
  x: number;
  y: number;
  width: number;
  height: number;
  left: BSPNode | null;
  right: BSPNode | null;
  room: Room | null;
}

interface Room {
  x: number;
  y: number;
  width: number;
  height: number;
}

function splitBSP(node: BSPNode, minSize: number, rng: () => number): void {
  if (node.width < minSize * 2 && node.height < minSize * 2) return;

  const splitHorizontal = node.width < node.height ? true : node.height < node.width ? false : rng() > 0.5;

  if (splitHorizontal) {
    const split = Math.floor(node.height * (0.3 + rng() * 0.4));
    node.left = {
      x: node.x,
      y: node.y,
      width: node.width,
      height: split,
      left: null,
      right: null,
      room: null,
    };
    node.right = {
      x: node.x,
      y: node.y + split,
      width: node.width,
      height: node.height - split,
      left: null,
      right: null,
      room: null,
    };
  } else {
    const split = Math.floor(node.width * (0.3 + rng() * 0.4));
    node.left = {
      x: node.x,
      y: node.y,
      width: split,
      height: node.height,
      left: null,
      right: null,
      room: null,
    };
    node.right = {
      x: node.x + split,
      y: node.y,
      width: node.width - split,
      height: node.height,
      left: null,
      right: null,
      room: null,
    };
  }

  splitBSP(node.left, minSize, rng);
  splitBSP(node.right, minSize, rng);
}

function createRooms(node: BSPNode, padding: number, rng: () => number): void {
  if (node.left === null && node.right === null) {
    const roomW = Math.floor((node.width - padding * 2) * (0.6 + rng() * 0.4));
    const roomH = Math.floor((node.height - padding * 2) * (0.6 + rng() * 0.4));
    const roomX = node.x + padding + Math.floor(rng() * (node.width - padding * 2 - roomW));
    const roomY = node.y + padding + Math.floor(rng() * (node.height - padding * 2 - roomH));
    node.room = { x: roomX, y: roomY, width: roomW, height: roomH };
    return;
  }
  if (node.left) createRooms(node.left, padding, rng);
  if (node.right) createRooms(node.right, padding, rng);
}
BSP 分割的参数直接影响地牢风格：最小分割尺寸决定房间密度，分割比例范围控制房间大小的均匀程度，padding 参数控制房间间距。通过调整这些参数，同一算法可以生成从紧凑密集到宽敞稀疏的各种地牢风格。


随机游走与洞穴生成
随机游走（Drunkard's Walk）算法模拟一个醉汉在网格上随机移动，每到一格就将其标记为地板。算法运行到地板覆盖率达到目标百分比时停止。这种方法产生不规则的、有机形态的洞穴，非常适合自然洞穴和矿井场景。


type TileGrid = Uint8Array;

const WALL = 0;
const FLOOR = 1;

function drunkardWalk(width: number, height: number, fillPercent: number, rng: () => number): TileGrid {
  const grid = new Uint8Array(width * height);
  const totalTiles = width * height;
  const targetFloor = Math.floor(totalTiles * fillPercent);

  let cx = Math.floor(width / 2);
  let cy = Math.floor(height / 2);
  let floorCount = 0;

  const directions = [
    [0, -1],
    [0, 1],
    [-1, 0],
    [1, 0],
  ];

  while (floorCount < targetFloor) {
    const idx = cy * width + cx;
    if (grid[idx] === WALL) {
      grid[idx] = FLOOR;
      floorCount++;
    }

    const dir = directions[Math.floor(rng() * 4)];
    const nx = cx + dir[0];
    const ny = cy + dir[1];

    if (nx > 0 && nx < width - 1 && ny > 0 && ny < height - 1) {
      cx = nx;
      cy = ny;
    }
  }

  return grid;
}
随机游走的变体包括：多起点游走（从多个位置同时开始）、方向偏置游走（增加某个方向的概率形成长廊）、以及带回溯的游走（记录历史路径，偶尔回到之前的位置开辟分支）。


细胞自动机是另一种生成有机洞穴的方法。初始化时随机填充网格（约 45% 为墙壁），然后迭代应用规则：如果一个格子周围 8 格中有 4 个以上是墙壁，则该格变为墙壁，否则变为地板。经过 4-5 轮迭代后，网格会自组织成平滑的洞穴形态。


function cellularAutomata(
  width: number,
  height: number,
  initialWallChance: number,
  iterations: number,
  rng: () => number,
): TileGrid {
  const grid = new Uint8Array(width * height);

  for (let i = 0; i < grid.length; i++) {
    const x = i % width;
    const y = Math.floor(i / width);
    if (x === 0 || x === width - 1 || y === 0 || y === height - 1) {
      grid[i] = WALL;
    } else {
      grid[i] = rng() < initialWallChance ? WALL : FLOOR;
    }
  }

  for (let iter = 0; iter < iterations; iter++) {
    const next = new Uint8Array(grid);
    for (let y = 1; y < height - 1; y++) {
      for (let x = 1; x < width - 1; x++) {
        let walls = 0;
        for (let dy = -1; dy <= 1; dy++) {
          for (let dx = -1; dx <= 1; dx++) {
            if (dx === 0 && dy === 0) continue;
            if (grid[(y + dy) * width + (x + dx)] === WALL) walls++;
          }
        }
        next[y * width + x] = walls > 4 ? WALL : FLOOR;
      }
    }
    grid.set(next);
  }

  return grid;
}
走廊连接与连通性验证
房间生成之后，需要通过走廊将它们连接成一个可通行的整体。走廊生成的核心挑战是既要保证完全连通，又要避免过多冗余路径导致地牢过于线性或过于复杂。


常见的走廊连接策略包括 L 形走廊（先水平再垂直或反之）、最小生成树连接（保证最少的走廊数量实现完全连通）以及 Delaunay 三角剖分（在最小生成树基础上添加少量额外连接增加环路）。


连通性验证使用洪水填充（Flood Fill）算法：从任意一个地板格开始，扩展到所有可达的地板格，如果存在未被访问的地板区域，则地牢不连通。对于不连通的情况，可以找到两个最近的断开区域，在它们之间开凿一条走廊。


function floodFill(grid: TileGrid, width: number, height: number, startX: number, startY: number): Set<number> {
  const visited = new Set<number>();
  const queue: Array<[number, number]> = [[startX, startY]];

  while (queue.length > 0) {
    const [x, y] = queue.shift()!;
    const idx = y * width + x;

    if (visited.has(idx)) continue;
    if (grid[idx] !== FLOOR) continue;
    if (x < 0 || x >= width || y < 0 || y >= height) continue;

    visited.add(idx);
    queue.push([x + 1, y], [x - 1, y], [x, y + 1], [x, y - 1]);
  }

  return visited;
}

function ensureConnectivity(grid: TileGrid, width: number, height: number): void {
  const regions: Array<Set<number>> = [];

  const globalVisited = new Set<number>();
  for (let y = 0; y < height; y++) {
    for (let x = 0; x < width; x++) {
      const idx = y * width + x;
      if (grid[idx] === FLOOR && !globalVisited.has(idx)) {
        const region = floodFill(grid, width, height, x, y);
        region.forEach((v) => globalVisited.add(v));
        regions.push(region);
      }
    }
  }

  if (regions.length <= 1) return;

  regions.sort((a, b) => b.size - a.size);
  const mainRegion = regions[0];

  for (let i = 1; i < regions.length; i++) {
    connectRegions(grid, width, mainRegion, regions[i]);
    regions[i].forEach((v) => mainRegion.add(v));
  }
}

function connectRegions(grid: TileGrid, width: number, regionA: Set<number>, regionB: Set<number>): void {
  let bestDist = Infinity;
  let bestA = 0;
  let bestB = 0;

  for (const a of regionA) {
    for (const b of regionB) {
      const ax = a % width,
        ay = Math.floor(a / width);
      const bx = b % width,
        by = Math.floor(b / width);
      const dist = Math.abs(ax - bx) + Math.abs(ay - by);
      if (dist < bestDist) {
        bestDist = dist;
        bestA = a;
        bestB = b;
      }
    }
  }

  carveCorridor(grid, width, bestA % width, Math.floor(bestA / width), bestB % width, Math.floor(bestB / width));
}

function carveCorridor(grid: TileGrid, width: number, x1: number, y1: number, x2: number, y2: number): void {
  let x = x1,
    y = y1;
  while (x !== x2) {
    grid[y * width + x] = FLOOR;
    x += x < x2 ? 1 : -1;
  }
  while (y !== y2) {
    grid[y * width + x] = FLOOR;
    y += y < y2 ? 1 : -1;
  }
}
地牢布局的可玩性评估
生成地牢后需要评估其可玩性。关键指标包括：关键路径长度（从入口到出口的最短路径）、分支系数（支线房间占总房间的比例）、密度分布（房间在地图上的分布均匀程度）和死胡同数量。

可以通过拒绝-重生成策略来保证质量：如果生成的地牢不满足可玩性阈值，则丢弃并重新生成。更高级的做法是在生成过程中动态调整参数，例如当关键路径过短时增大地图尺寸，当分支系数过低时增加额外走廊。


在实际 Roguelike 游戏中，地牢生成还需要考虑怪物布置、宝箱分配、陷阱设置等内容填充。这些通常基于关键路径距离和房间类型进行规则化分配——距离入口越远的房间放置更强的敌人和更好的奖励，死胡同适合放置隐藏宝箱或 Boss 战斗区域。
