延迟渲染与前向渲染

核心概念

前向渲染（Forward Rendering）和延迟渲染（Deferred Rendering）是两种根本不同的光照管线架构。前向渲染在绘制每个物体时直接计算所有光源的光照，而延迟渲染将几何信息先写入 G-Buffer，再在一个全屏 Pass 中统一计算光照。两种架构各有优劣，现代引擎往往采用混合方案以兼顾两者的长处。

选择渲染架构的核心考量是场景中的光源数量和几何复杂度。对于光源少于 10 个的场景，前向渲染通常更高效；当场景包含数十甚至上百个动态光源时，延迟渲染的优势就非常明显。


前向渲染管线
前向渲染是最直观的渲染方式：遍历场景中的每个可见物体，在片段着色器中直接计算所有影响该片段的光源贡献。其核心优势在于简单性和对材质系统的无限制支持。


在多光源场景下，前向渲染的基本策略是在片段着色器中循环遍历所有光源：


#version 450

layout(set = 0, binding = 0) uniform sampler2D albedoMap;
layout(set = 0, binding = 1) uniform sampler2D normalMap;

struct PointLight {
    vec4 positionAndRadius;
    vec4 colorAndIntensity;
};

layout(set = 1, binding = 0) uniform LightBuffer {
    PointLight lights[64];
    int lightCount;
};

layout(set = 2, binding = 0) uniform CameraData {
    vec3 cameraPos;
    mat4 viewProjection;
};

layout(location = 0) in vec3 fragWorldPos;
layout(location = 1) in vec3 fragNormal;
layout(location = 2) in vec2 fragTexCoord;
layout(location = 3) in mat3 fragTBN;

layout(location = 0) out vec4 outColor;

void main() {
    vec3 albedo = texture(albedoMap, fragTexCoord).rgb;
    vec3 normalTS = texture(normalMap, fragTexCoord).rgb * 2.0 - 1.0;
    vec3 N = normalize(fragTBN * normalTS);
    vec3 V = normalize(cameraPos - fragWorldPos);

    vec3 totalLight = vec3(0.03) * albedo;

    for (int i = 0; i < lightCount; i++) {
        vec3 lightPos = lights[i].positionAndRadius.xyz;
        float radius = lights[i].positionAndRadius.w;
        vec3 lightColor = lights[i].colorAndIntensity.rgb;
        float intensity = lights[i].colorAndIntensity.w;

        vec3 L = lightPos - fragWorldPos;
        float dist = length(L);
        if (dist > radius) continue;

        L = normalize(L);
        float attenuation = 1.0 - smoothstep(0.0, radius, dist);
        float NdotL = max(dot(N, L), 0.0);

        totalLight += albedo * lightColor * intensity * NdotL * attenuation;
    }

    outColor = vec4(totalLight, 1.0);
}
前向渲染的过绘制（Overdraw）问题是主要性能瓶颈。当多个物体在屏幕同一位置重叠时，被遮挡物体的光照计算完全浪费。Z-Prepass 是缓解过绘制的标准方案。


Forward+ 是前向渲染的改进方案，也称为 Tiled Forward Rendering。它将屏幕划分为若干 Tile（通常 16×16 像素），在 Compute Shader 中为每个 Tile 计算可见光源列表。片段着色器只需遍历当前 Tile 的光源，而不是全部光源，从而大幅降低光照计算复杂度。


G-Buffer 设计与几何 Pass
延迟渲染的第一步是几何 Pass（Geometry Pass），将场景中所有不透明物体的几何信息写入 G-Buffer（Geometry Buffer）。G-Buffer 是一组多渲染目标（MRT），每个附件存储不同的材质和几何属性。

法线压缩是 G-Buffer 优化的重要技巧。由于法线是单位向量，只需存储两个分量即可重建第三个。八面体编码（Octahedral Encoding）是目前最常用的法线压缩方法，将三维单位向量映射到二维 [-1, 1] 范围，仅需两个通道即可存储。


几何 Pass 的片段着色器只负责采样纹理和写入 G-Buffer，不做任何光照计算，因此非常轻量：


#version 450

layout(set = 0, binding = 0) uniform sampler2D albedoMap;
layout(set = 0, binding = 1) uniform sampler2D normalMap;
layout(set = 0, binding = 2) uniform sampler2D armMap;

layout(location = 0) in vec3 fragWorldPos;
layout(location = 1) in vec2 fragTexCoord;
layout(location = 2) in mat3 fragTBN;

layout(location = 0) out vec4 gAlbedoAO;
layout(location = 1) out vec4 gNormalRoughnessMetallic;
layout(location = 2) out vec4 gEmissive;

vec2 encodeOctahedral(vec3 n) {
    n /= (abs(n.x) + abs(n.y) + abs(n.z));
    if (n.z < 0.0) {
        n.xy = (1.0 - abs(n.yx)) * vec2(n.x >= 0.0 ? 1.0 : -1.0, n.y >= 0.0 ? 1.0 : -1.0);
    }
    return n.xy * 0.5 + 0.5;
}

void main() {
    vec3 albedo = texture(albedoMap, fragTexCoord).rgb;
    vec3 normalTS = texture(normalMap, fragTexCoord).rgb * 2.0 - 1.0;
    vec3 N = normalize(fragTBN * normalTS);
    vec3 arm = texture(armMap, fragTexCoord).rgb;

    gAlbedoAO = vec4(albedo, arm.r);
    vec2 encodedN = encodeOctahedral(N);
    gNormalRoughnessMetallic = vec4(encodedN, arm.g, arm.b);
    gEmissive = vec4(0.0);
}
光照 Pass 与光源体积
延迟渲染的第二步是光照 Pass（Lighting Pass），读取 G-Buffer 中的几何信息，对每个屏幕像素计算所有影响它的光源贡献。


对于全局光源（方向光、环境光），绘制一个全屏四边形（Full-screen Quad）即可处理所有像素。对于局部光源（点光源、聚光灯），使用光源体积（Light Volume）优化：只为光源影响范围内的像素执行光照计算。


点光源的影响体积是一个球体，在屏幕空间表现为一个圆形区域。实际渲染时使用低多边形球体网格代表光源体积，在片段着色器中采样 G-Buffer 并计算光照：


interface LightVolumePass {
  renderPointLights(
    encoder: GPURenderPassEncoder,
    lights: ReadonlyArray<{
      position: [number, number, number];
      radius: number;
      color: [number, number, number];
      intensity: number;
    }>,
    gBufferBindGroup: GPUBindGroup,
    cameraBindGroup: GPUBindGroup,
  ): void;
}

const createLightVolumePass = (
  device: GPUDevice,
  sphereMesh: { vertexBuffer: GPUBuffer; indexBuffer: GPUBuffer; indexCount: number },
): LightVolumePass => ({
  renderPointLights(encoder, lights, gBufferBindGroup, cameraBindGroup) {
    encoder.setPipeline(lightVolumePipeline);
    encoder.setBindGroup(0, gBufferBindGroup);
    encoder.setBindGroup(1, cameraBindGroup);
    encoder.setVertexBuffer(0, sphereMesh.vertexBuffer);
    encoder.setIndexBuffer(sphereMesh.indexBuffer, 'uint16');

    for (const light of lights) {
      const lightData = new Float32Array([...light.position, light.radius, ...light.color, light.intensity]);
      encoder.setBindGroup(2, createLightBindGroup(device, lightData));
      encoder.drawIndexed(sphereMesh.indexCount);
    }
  },
});
光源体积渲染需要注意背面剔除的设置：当相机在光源体积外部时使用背面剔除，当相机进入光源体积内部时需要切换为正面剔除并反转深度测试。


Tiled 与 Clustered 延迟渲染
传统延迟渲染在光源数量极多时仍有性能问题，因为每个光源体积 Pass 都需要读取 G-Buffer。Tiled Deferred 和 Clustered Deferred 是更高级的方案。

Clustered Deferred 将视锥体在深度方向上进一步切分，形成三维网格（Cluster）。每个 Cluster 只包含真正影响该空间区域的光源，进一步减少无效光照计算。这也是 Unreal Engine 和 Unity 等主流引擎的默认方案。


在 Forward+ 管线中，同样的 Tile/Cluster 光源分配机制也可应用于前向渲染。WebGPU 的 Compute Shader 使这种实现变得可行：


const lightCullingPipeline = device.createComputePipeline({
  layout: cullingPipelineLayout,
  compute: {
    module: device.createShaderModule({ code: lightCullingShader }),
    entryPoint: 'main',
  },
});

const tileCountX = Math.ceil(canvas.width / 16);
const tileCountY = Math.ceil(canvas.height / 16);

const computePass = commandEncoder.beginComputePass();
computePass.setPipeline(lightCullingPipeline);
computePass.setBindGroup(0, cullingBindGroup);
computePass.dispatchWorkgroups(tileCountX, tileCountY, 1);
computePass.end();
小结
    

  • 前向渲染直观简单但光源扩展性差，延迟渲染通过 G-Buffer 解耦几何与光照
    • 

  • G-Buffer 设计需平衡信息完整性与带宽，八面体编码是法线压缩的最佳选择
    • 

  • 光源体积将局部光源的计算限制在其影响范围内，减少无效着色
    • 

  • Tiled/Clustered 方案将屏幕空间划分后分配光源，支撑数百个动态光源
    • 

  • Forward+ 将 Tiled 思想应用于前向渲染，兼具前向渲染的材质灵活性和延迟渲染的光源扩展性
    • 

  • 现代引擎多采用混合方案：不透明物体走延迟管线，半透明物体走前向管线
