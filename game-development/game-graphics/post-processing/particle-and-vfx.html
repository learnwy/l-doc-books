粒子系统与视觉特效

核心概念

粒子系统（Particle System）是游戏中模拟大量小型元素集体行为的技术框架，用于创建火焰、烟雾、爆炸、魔法效果、雨雪天气等视觉特效。每个粒子是一个具有位置、速度、生命周期和视觉属性的简单实体，大量粒子的集体运动和渲染产生复杂的宏观视觉效果。现代粒子系统已从 CPU 驱动演进到 GPU Compute Shader 驱动，支持数百万粒子的实时模拟。

粒子系统的设计核心是将复杂的视觉效果分解为简单粒子的行为规则——发射模式、力场影响、颜色/尺寸随生命周期变化的曲线、以及渲染方式的选择。


粒子生命周期管理
粒子系统的运行时管理包括发射（Emission）、更新（Update）和回收（Recycle）三个环节。对象池（Object Pool）是避免频繁内存分配的标准方案，预分配固定数量的粒子槽位，通过环形缓冲或空闲列表管理粒子的生死。


interface Particle {
  position: Float32Array;
  velocity: Float32Array;
  color: Float32Array;
  size: number;
  age: number;
  lifetime: number;
  alive: boolean;
}

interface ParticleEmitter {
  maxParticles: number;
  emissionRate: number;
  particles: Particle[];
  aliveCount: number;
  accumulator: number;
}

function updateEmitter(emitter: ParticleEmitter, deltaTime: number): void {
  emitter.accumulator += emitter.emissionRate * deltaTime;
  const toEmit = Math.floor(emitter.accumulator);
  emitter.accumulator -= toEmit;

  for (let i = 0; i < toEmit; i++) {
    const slot = findDeadParticle(emitter);
    if (slot < 0) break;
    initializeParticle(emitter.particles[slot], emitter);
  }

  for (let i = 0; i < emitter.maxParticles; i++) {
    const p = emitter.particles[i];
    if (!p.alive) continue;

    p.age += deltaTime;
    if (p.age >= p.lifetime) {
      p.alive = false;
      emitter.aliveCount--;
      continue;
    }

    p.velocity[1] -= 9.8 * deltaTime;
    p.position[0] += p.velocity[0] * deltaTime;
    p.position[1] += p.velocity[1] * deltaTime;
    p.position[2] += p.velocity[2] * deltaTime;

    const t = p.age / p.lifetime;
    p.size = lerp(1.0, 0.1, t);
    p.color[3] = 1.0 - t * t;
  }
}

function findDeadParticle(emitter: ParticleEmitter): number {
  for (let i = 0; i < emitter.maxParticles; i++) {
    if (!emitter.particles[i].alive) return i;
  }
  return -1;
}

function lerp(a: number, b: number, t: number): number {
  return a + (b - a) * t;
}

function initializeParticle(p: Particle, emitter: ParticleEmitter): void {
  p.alive = true;
  p.age = 0;
  p.lifetime = 1.0 + Math.random() * 2.0;
  p.position[0] = (Math.random() - 0.5) * 0.5;
  p.position[1] = 0;
  p.position[2] = (Math.random() - 0.5) * 0.5;
  p.velocity[0] = (Math.random() - 0.5) * 2.0;
  p.velocity[1] = 5.0 + Math.random() * 3.0;
  p.velocity[2] = (Math.random() - 0.5) * 2.0;
  p.size = 0.5 + Math.random() * 0.5;
  p.color.set([1.0, 0.8, 0.3, 1.0]);
  emitter.aliveCount++;
}
发射模式决定了粒子的初始位置和速度分布。常见的发射器形状包括点发射、球面发射、锥形发射、网格表面发射等。每种形状的参数化方式不同，但核心都是在发射区域内随机采样位置并计算初始速度方向。


GPU 粒子系统
当粒子数量达到数十万甚至数百万时，CPU 端逐粒子更新成为瓶颈。GPU 粒子系统将模拟和渲染完全放在 GPU 上执行，通过 Compute Shader 并行更新所有粒子状态。


GPU 粒子使用 Storage Buffer 存储粒子数据，通过 Compute Shader Dispatch 并行处理。间接绘制（Indirect Draw）读取 GPU 端计算出的活跃粒子数作为绘制实例数，完全避免 GPU→CPU 的数据回读：


const particleBuffer = device.createBuffer({
  size: maxParticles * particleStride,
  usage: GPUBufferUsage.STORAGE | GPUBufferUsage.VERTEX,
});

const counterBuffer = device.createBuffer({
  size: 16,
  usage: GPUBufferUsage.STORAGE | GPUBufferUsage.INDIRECT,
});

const computePass = encoder.beginComputePass();

computePass.setPipeline(emitPipeline);
computePass.setBindGroup(0, emitBindGroup);
computePass.dispatchWorkgroups(Math.ceil(emitCount / 64));

computePass.setPipeline(simulatePipeline);
computePass.setBindGroup(0, simulateBindGroup);
computePass.dispatchWorkgroups(Math.ceil(maxParticles / 256));

computePass.end();

const renderPass = encoder.beginRenderPass(renderPassDescriptor);
renderPass.setPipeline(particleRenderPipeline);
renderPass.setVertexBuffer(0, quadVertexBuffer);
renderPass.setVertexBuffer(1, particleBuffer);
renderPass.drawIndirect(counterBuffer, 0);
renderPass.end();
GPU 粒子系统的一个关键挑战是原子操作和内存管理。发射新粒子需要在空闲列表中原子地分配槽位，回收死亡粒子需要原子地归还槽位。WebGPU 的 atomicAdd 和 atomicCompareExchangeWeak 提供了必要的同步原语。


Billboard 渲染与排序
粒子渲染最常用的技术是 Billboard——将每个粒子渲染为一个始终面向相机的四边形。Billboard 矩阵通过相机的右向量和上向量构建，确保四边形始终正对观察者。

速度对齐 Billboard 将粒子沿速度方向拉伸，非常适合表现高速运动的火花和弹道轨迹：


#version 450

layout(set = 0, binding = 0) uniform CameraData {
    mat4 viewProjection;
    vec3 cameraRight;
    vec3 cameraUp;
    vec3 cameraPos;
};

layout(location = 0) in vec2 quadVertex;
layout(location = 1) in vec3 particlePos;
layout(location = 2) in vec3 particleVel;
layout(location = 3) in float particleSize;
layout(location = 4) in vec4 particleColor;

layout(location = 0) out vec2 texCoord;
layout(location = 1) out vec4 color;

void main() {
    vec3 velocity = particleVel;
    float speed = length(velocity);

    vec3 forward;
    vec3 right;
    if (speed > 0.001) {
        forward = normalize(velocity);
        right = normalize(cross(forward, cameraPos - particlePos));
    } else {
        right = cameraRight;
        forward = cameraUp;
    }

    float stretchFactor = 1.0 + speed * 0.1;
    vec3 worldPos = particlePos
        + right * quadVertex.x * particleSize
        + forward * quadVertex.y * particleSize * stretchFactor;

    gl_Position = viewProjection * vec4(worldPos, 1.0);
    texCoord = quadVertex * 0.5 + 0.5;
    color = particleColor;
}
半透明粒子的排序是粒子渲染的经典难题。正确的混合要求从后向前绘制，但对数十万粒子进行排序代价高昂。常用的折中方案包括：加法混合（无需排序）、预乘 Alpha 混合（降低排序敏感度）、以及使用 OIT（Order-Independent Transparency）技术。


视觉特效合成
完整的游戏特效通常由多个粒子系统和其他视觉元素（光源、Decal、屏幕扭曲）组合而成。例如一个爆炸效果可能包含：闪光粒子、碎片粒子、烟雾粒子、冲击波扭曲、动态点光源和屏幕震动。


屏幕空间扭曲（Screen Space Distortion）通过偏移 UV 采样坐标来模拟热浪、冲击波等折射效果。实现方式是在后处理阶段读取扭曲法线贴图（通常由粒子写入的独立 Render Target 提供），将其转化为 UV 偏移量并对颜色缓冲重新采样。


Decal 系统将纹理投影到场景表面，用于弹孔、血迹、法阵等效果。延迟贴花（Deferred Decal）在 G-Buffer 阶段将贴花信息写入 Albedo 和法线缓冲，与场景几何完美贴合。


小结
    

  • 粒子系统通过大量简单实体的集体行为模拟复杂视觉效果，是游戏特效的核心技术
    • 

  • 对象池和环形缓冲避免运行时内存分配，是粒子生命周期管理的标准方案
    • 

  • GPU 粒子系统通过 Compute Shader 并行更新数百万粒子，间接绘制避免 GPU→CPU 数据回读
    • 

  • Billboard 渲染使粒子始终面向相机，速度对齐拉伸适合表现高速运动效果
    • 

  • 半透明排序是粒子渲染的经典难题，加法混合和 OIT 是常用的折中方案
    • 

  • 完整特效由粒子、光源、Decal、屏幕扭曲等多种元素协同构成
    •
