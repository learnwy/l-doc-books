色调映射与 HDR 渲染

核心概念

高动态范围（HDR, High Dynamic Range）渲染使用浮点精度的颜色缓冲存储场景的完整亮度范围，从深邃的阴影到耀眼的高光。真实世界的亮度范围跨越数个数量级（室内 ~100 cd/m² 到阳光直射 10⁹ cd/m²），而显示器只能输出有限的亮度范围（SDR 约 0100 nit）。色调映射（Tone Mapping）是将 HDR 颜色空间压缩到显示器可表示范围的关键步骤，其选择直接决定画面的整体观感和艺术风格。

HDR 渲染管线的完整流程是：所有光照计算在线性 HDR 空间进行 → 自动或手动曝光调整 → 色调映射压缩到 [0, 1] → 色彩分级 → Gamma 编码输出。


曝光控制与自动曝光
曝光控制（Exposure Control）决定了在色调映射前对 HDR 颜色的全局缩放，模拟摄影中光圈、快门速度和 ISO 的组合效果。正确的曝光使场景的中间调亮度映射到目标范围，既不过曝也不欠曝。


自动曝光（Auto Exposure）模拟人眼的明暗适应。通过计算场景的平均亮度来动态调整曝光值，使得从明亮环境走入暗室时画面逐渐变亮，反之逐渐变暗。


#version 450

layout(set = 0, binding = 0) uniform sampler2D hdrTexture;
layout(set = 0, binding = 1, r32f) uniform image2D luminanceImage;

layout(set = 0, binding = 2) uniform ExposureParams {
    float minExposure;
    float maxExposure;
    float adaptSpeed;
    float targetLuminance;
    float deltaTime;
    float prevExposure;
};

layout(location = 0) in vec2 texCoord;
layout(location = 0) out vec4 outColor;

float computeLuminance(vec3 color) {
    return dot(color, vec3(0.2126, 0.7152, 0.0722));
}

void main() {
    vec3 hdrColor = texture(hdrTexture, texCoord).rgb;

    float avgLuminance = imageLoad(luminanceImage, ivec2(0, 0)).r;
    float ev = log2(max(avgLuminance, 0.001) / targetLuminance);
    float targetExposure = clamp(1.0 / pow(2.0, ev), minExposure, maxExposure);
    float exposure = mix(prevExposure, targetExposure, 1.0 - exp(-adaptSpeed * deltaTime));

    outColor = vec4(hdrColor * exposure, 1.0);
}
平均亮度的计算通常使用对数平均（Log Average Luminance），先对每个像素取对数再平均，最后取指数。这种方式比算术平均更能反映场景的整体感知亮度，因为人眼对亮度的感知是对数关系。


亮度直方图（Luminance Histogram）是更精确的自动曝光方案。通过 Compute Shader 构建场景亮度的直方图，忽略极端亮和极端暗的像素（通常排除最亮和最暗各 5%），用中间 90% 的加权平均作为曝光参考值：

经典色调映射算子
Reinhard 色调映射是最经典的 HDR 压缩方案，其数学形式简洁优雅：对每个颜色通道应用 c / (1 + c) 变换，将 [0, ∞) 范围映射到 [0, 1)。扩展 Reinhard 增加了白点参数 W，使得亮度达到 W 的像素被映射到纯白：


vec3 reinhardToneMap(vec3 color) {
    return color / (1.0 + color);
}

vec3 reinhardExtended(vec3 color, float whitePoint) {
    vec3 numerator = color * (1.0 + color / (whitePoint * whitePoint));
    return numerator / (1.0 + color);
}
Uncharted 2 色调映射（也称为 Filmic Tone Mapping）由 John Hable 提出，使用分段函数模拟电影胶片的 S 曲线响应。它在暗部有一个脚部（Toe）提升，中间调线性，亮部有一个肩部（Shoulder）压缩：


vec3 uncharted2ToneMap(vec3 x) {
    float A = 0.15;
    float B = 0.50;
    float C = 0.10;
    float D = 0.20;
    float E = 0.02;
    float F = 0.30;
    return ((x * (A * x + C * B) + D * E) / (x * (A * x + B) + D * F)) - E / F;
}

vec3 applyUncharted2(vec3 color) {
    float exposureBias = 2.0;
    vec3 curr = uncharted2ToneMap(color * exposureBias);
    vec3 whiteScale = 1.0 / uncharted2ToneMap(vec3(11.2));
    return curr * whiteScale;
}
ACES 与现代色调映射
ACES（Academy Color Encoding System）是电影工业标准的颜色管理系统，其色调映射曲线已成为游戏行业的事实标准。ACES 的 RRT（Reference Rendering Transform）+ ODT（Output Device Transform）组合提供了电影级的色彩处理。


游戏中常用的是 Stephen Hill 对 ACES Filmic 的拟合版本，计算效率高且效果接近完整 ACES 管线：


vec3 acesFilmic(vec3 x) {
    float a = 2.51;
    float b = 0.03;
    float c = 2.43;
    float d = 0.59;
    float e = 0.14;
    return clamp((x * (a * x + b)) / (x * (c * x + d) + e), 0.0, 1.0);
}
ACES Filmic 的已知问题是对高饱和颜色的色相偏移——明亮的蓝色会偏向紫色，红色会偏向橙色。这种现象在 HDR 显示器上更加明显。


AgX 是为解决 ACES 色相偏移问题而提出的新一代色调映射方案。它在色度空间中进行映射，确保在压缩亮度的同时保持色度的稳定性。Blender 已将 AgX 作为默认色调映射选项。

HDR 显示器输出
随着 HDR 显示器的普及，游戏需要支持直接输出 HDR 信号。HDR 显示不需要将全部亮度范围压缩到 SDR，而是将场景亮度映射到显示器的物理亮度范围（如 1000 nit 或 4000 nit），保留更多的高光细节和暗部层次。

PQ（Perceptual Quantizer）传输函数是 HDR10 的核心，将线性亮度值编码为与人眼感知均匀匹配的非线性信号：


vec3 linearToPQ(vec3 linearColor, float maxNits) {
    vec3 Y = linearColor * maxNits / 10000.0;
    float m1 = 0.1593017578125;
    float m2 = 78.84375;
    float c1 = 0.8359375;
    float c2 = 18.8515625;
    float c3 = 18.6875;
    vec3 Ym1 = pow(Y, vec3(m1));
    return pow((c1 + c2 * Ym1) / (1.0 + c3 * Ym1), vec3(m2));
}
在 HDR 输出管线中，色调映射的角色发生变化：不再是将全部亮度压缩到 [0, 1]，而是对超出显示器峰值亮度的像素进行柔和的肩部压缩（Shoulder Roll-off），同时保留显示器亮度范围内的 HDR 细节。


小结
    

  • HDR 渲染使用浮点缓冲存储全范围亮度，色调映射将其压缩到显示器可表示范围
    • 

  • 自动曝光通过亮度直方图或对数平均动态调整曝光值，模拟人眼明暗适应
    • 

  • ACES Filmic 是当前游戏行业标准，提供电影级色彩风格但存在高饱和度色相偏移
    • 

  • AgX 通过色度空间映射解决了 ACES 的色相偏移问题，是新一代色调映射的代表
    • 

  • HDR 显示器输出使用 PQ 传输函数，保留显示器亮度范围内的完整 HDR 细节
    • 

  • 完整的 HDR 管线需要线性空间计算、正确的曝光控制、适当的色调映射和匹配的色彩空间输出
