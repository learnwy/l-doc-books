游戏循环模式

核心概念

游戏循环是游戏引擎的心脏，它持续不断地执行输入处理、游戏逻辑更新和画面渲染三个核心步骤。不同的循环模式决定了游戏的流畅度、确定性和跨平台一致性。

简单游戏循环
最基本的游戏循环没有时间控制，尽可能快地执行每一帧。这意味着在不同性能的硬件上，游戏运行速度不同——快速的机器上游戏跑得更快，慢速机器上跑得更慢。


class SimpleGameLoop {
  private running = false;

  start(): void {
    this.running = true;
    while (this.running) {
      this.processInput();
      this.update();
      this.render();
    }
  }

  stop(): void {
    this.running = false;
  }

  private processInput(): void {}
  private update(): void {}
  private render(): void {}
}
这种模式在早期游戏中很常见，但在现代游戏开发中几乎不使用，因为它缺乏帧率控制和时间同步机制。然而，理解它是学习更复杂循环模式的基础。


固定时间步循环
固定时间步循环以恒定的时间间隔更新游戏逻辑。每个逻辑更新之间的时间差始终相同（通常是 1/60 秒或 1/120 秒），与实际运行帧率无关。


class FixedTimestepLoop {
  private running = false;
  private readonly fixedDt = 1 / 60;
  private accumulator = 0;

  start(): void {
    this.running = true;
    let previousTime = performance.now() / 1000;

    const loop = (): void => {
      if (!this.running) return;

      const currentTime = performance.now() / 1000;
      let frameTime = currentTime - previousTime;
      previousTime = currentTime;

      if (frameTime > 0.25) {
        frameTime = 0.25;
      }

      this.accumulator += frameTime;

      this.processInput();

      while (this.accumulator >= this.fixedDt) {
        this.fixedUpdate(this.fixedDt);
        this.accumulator -= this.fixedDt;
      }

      const alpha = this.accumulator / this.fixedDt;
      this.render(alpha);

      requestAnimationFrame(loop);
    };

    requestAnimationFrame(loop);
  }

  stop(): void {
    this.running = false;
  }

  private processInput(): void {}
  private fixedUpdate(_dt: number): void {}
  private render(_alpha: number): void {}
}
固定时间步的核心优势是物理模拟的确定性——无论实际帧率如何，物理计算总是在相同的时间间隔上执行，确保了跨平台的一致结果。渲染时使用插值参数 alpha 在两个物理状态之间插值，消除视觉抖动。


可变时间步循环
可变时间步循环将实际经过的时间直接传给更新函数，每帧的 deltaTime 可能不同。这种模式实现简单，但在物理模拟中可能产生不确定行为。


class VariableTimestepLoop {
  private running = false;
  private lastTime = 0;
  private frameCount = 0;
  private fpsAccumulator = 0;
  private currentFps = 0;

  start(): void {
    this.running = true;
    this.lastTime = performance.now() / 1000;

    const loop = (): void => {
      if (!this.running) return;

      const now = performance.now() / 1000;
      const dt = Math.min(now - this.lastTime, 0.1);
      this.lastTime = now;

      this.updateFpsCounter(dt);
      this.processInput();
      this.update(dt);
      this.render();

      requestAnimationFrame(loop);
    };

    requestAnimationFrame(loop);
  }

  private updateFpsCounter(dt: number): void {
    this.frameCount++;
    this.fpsAccumulator += dt;
    if (this.fpsAccumulator >= 1.0) {
      this.currentFps = this.frameCount;
      this.frameCount = 0;
      this.fpsAccumulator -= 1.0;
    }
  }

  getFps(): number {
    return this.currentFps;
  }

  stop(): void {
    this.running = false;
  }

  private processInput(): void {}
  private update(_dt: number): void {}
  private render(): void {}
}
可变时间步的关键问题是"螺旋式死亡"（Spiral of Death）——当一帧的计算时间超过预期，deltaTime 增大导致下一帧的计算量更大，形成恶性循环。因此通常设置 deltaTime 上限（如 0.1 秒）来截断过长的帧。


半固定时间步与混合策略
半固定时间步是固定时间步和可变时间步的混合体。物理和核心逻辑使用固定时间步保证确定性，渲染和动画使用实际帧时间保证流畅度。


class HybridGameLoop {
  private running = false;
  private readonly physicsStep = 1 / 60;
  private readonly maxPhysicsSteps = 5;
  private accumulator = 0;
  private physicsTime = 0;

  private previousState: GameState = { position: 0, velocity: 0 };
  private currentState: GameState = { position: 0, velocity: 0 };

  start(): void {
    this.running = true;
    let lastTime = performance.now() / 1000;

    const loop = (): void => {
      if (!this.running) return;

      const now = performance.now() / 1000;
      const frameTime = Math.min(now - lastTime, 0.25);
      lastTime = now;

      this.processInput();

      this.accumulator += frameTime;
      let steps = 0;

      while (this.accumulator >= this.physicsStep && steps < this.maxPhysicsSteps) {
        this.previousState = { ...this.currentState };
        this.physicsUpdate(this.physicsStep);
        this.physicsTime += this.physicsStep;
        this.accumulator -= this.physicsStep;
        steps++;
      }

      const alpha = this.accumulator / this.physicsStep;
      const interpolated = this.interpolate(this.previousState, this.currentState, alpha);

      this.animationUpdate(frameTime);
      this.render(interpolated);

      requestAnimationFrame(loop);
    };

    requestAnimationFrame(loop);
  }

  private interpolate(prev: GameState, curr: GameState, alpha: number): GameState {
    return {
      position: prev.position * (1 - alpha) + curr.position * alpha,
      velocity: prev.velocity * (1 - alpha) + curr.velocity * alpha,
    };
  }

  stop(): void {
    this.running = false;
  }
  private processInput(): void {}
  private physicsUpdate(_dt: number): void {}
  private animationUpdate(_dt: number): void {}
  private render(_state: GameState): void {}
}

interface GameState {
  position: number;
  velocity: number;
}

小结
    

  • 游戏循环是引擎的核心驱动机制，不同模式在确定性和流畅度之间权衡
    • 

  • 固定时间步通过累加器模式保证物理模拟的确定性
    • 

  • 可变时间步更简单但需防止螺旋式死亡
    • 

  • 半固定时间步是最佳实践，将物理和渲染的时间模型分离
    • 

  • 状态插值是连接固定物理步和可变渲染帧的关键技术
