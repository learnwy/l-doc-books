固定与可变时间步对比

核心概念

时间步（Timestep）是游戏循环中每次逻辑更新所使用的时间间隔。固定时间步（Fixed Timestep）使用恒定的时间增量，而可变时间步（Variable Timestep）使用实际经过的时间。两者的选择深刻影响游戏的物理行为、网络同步和玩家体验。

固定时间步的数学基础
固定时间步中，每次更新使用相同的 Δt。当实际帧时间与固定步长不匹配时，需要累加器（Accumulator）来管理时间剩余。


设实际帧时间为 frameTime，固定步长为 fixedDt，累加器为 acc：


acc += frameTime
while acc >= fixedDt:
    update(fixedDt)
    acc -= fixedDt
alpha = acc / fixedDt   // 插值系数
渲染时使用 alpha 在上一帧状态和当前帧状态之间线性插值，消除由于渲染时刻与物理时刻不对齐造成的视觉抖动。


class PhysicsWorld {
  private bodies: RigidBody[] = [];
  private gravity = -9.81;

  step(dt: number): void {
    for (const body of this.bodies) {
      if (body.isStatic) continue;

      body.prevPosition = body.position;
      body.prevRotation = body.rotation;

      body.velocity += this.gravity * body.inverseMass * dt;
      body.position += body.velocity * dt;
    }
  }

  getInterpolatedState(body: RigidBody, alpha: number): InterpolatedState {
    return {
      position: body.prevPosition * (1 - alpha) + body.position * alpha,
      rotation: body.prevRotation * (1 - alpha) + body.rotation * alpha,
    };
  }
}

interface RigidBody {
  position: number;
  prevPosition: number;
  rotation: number;
  prevRotation: number;
  velocity: number;
  inverseMass: number;
  isStatic: boolean;
}

interface InterpolatedState {
  position: number;
  rotation: number;
}
可变时间步的陷阱与对策
可变时间步看似简单——只需将真实经过时间传入更新函数。但当 deltaTime 波动较大时，物理模拟会产生严重问题：小物体可能穿透碰撞体，弹簧系统可能爆炸式振荡。


class VariablePhysicsDemo {
  position = 0;
  velocity = 10;
  readonly damping = 0.98;

  updateNaive(dt: number): void {
    this.position += this.velocity * dt;
    this.velocity *= Math.pow(this.damping, dt * 60);
  }

  updateSubStepped(dt: number): void {
    const maxSubStep = 1 / 120;
    let remaining = dt;

    while (remaining > 0) {
      const subDt = Math.min(remaining, maxSubStep);
      this.position += this.velocity * subDt;
      this.velocity *= Math.pow(this.damping, subDt * 60);
      remaining -= subDt;
    }
  }
}
子步进（Sub-stepping）是一种常见对策：将大的可变时间步分割为多个小步执行，每个小步的时间间隔不超过设定阈值。这在一定程度上缓解了稳定性问题，但增加了计算开销。


网络游戏中的时间步策略
在网络多人游戏中，时间步的选择直接影响同步策略。固定时间步使得服务器和客户端可以用相同的步长独立运行相同的模拟，只需要同步输入而非完整状态。


interface NetworkFrame {
  frameNumber: number;
  inputs: PlayerInput[];
  timestamp: number;
}

interface PlayerInput {
  playerId: string;
  moveX: number;
  moveY: number;
  actions: string[];
}

class DeterministicSimulation {
  private frameNumber = 0;
  private readonly fixedDt = 1 / 60;
  private stateHistory: Map<number, GameSnapshot> = new Map();

  advanceFrame(inputs: PlayerInput[]): GameSnapshot {
    this.frameNumber++;
    const snapshot = this.simulate(inputs, this.fixedDt);
    this.stateHistory.set(this.frameNumber, snapshot);

    if (this.stateHistory.size > 300) {
      const oldest = this.frameNumber - 300;
      this.stateHistory.delete(oldest);
    }

    return snapshot;
  }

  rollbackTo(frameNumber: number): void {
    const snapshot = this.stateHistory.get(frameNumber);
    if (snapshot) {
      this.restoreState(snapshot);
      this.frameNumber = frameNumber;
    }
  }

  resimulate(fromFrame: number, toFrame: number, correctedInputs: Map<number, PlayerInput[]>): void {
    this.rollbackTo(fromFrame);
    for (let f = fromFrame + 1; f <= toFrame; f++) {
      const inputs = correctedInputs.get(f) ?? [];
      this.advanceFrame(inputs);
    }
  }

  private simulate(_inputs: PlayerInput[], _dt: number): GameSnapshot {
    return { frameNumber: this.frameNumber, entityStates: [] };
  }

  private restoreState(_snapshot: GameSnapshot): void {}
}

interface GameSnapshot {
  frameNumber: number;
  entityStates: unknown[];
}
确定性模拟（Deterministic Simulation）要求：相同的初始状态 + 相同的输入 + 相同的时间步 = 相同的结果。这对浮点运算的精度和操作顺序都有严格要求。

性能分析与时间步选择
选择时间步模式需要考虑游戏类型、目标平台和性能预算。移动平台的帧率波动更大，更需要健壮的时间步策略。


class PerformanceMonitor {
  private frameTimes: number[] = [];
  private readonly sampleCount = 120;

  recordFrame(dt: number): void {
    this.frameTimes.push(dt);
    if (this.frameTimes.length > this.sampleCount) {
      this.frameTimes.shift();
    }
  }

  getAverageFrameTime(): number {
    if (this.frameTimes.length === 0) return 0;
    const sum = this.frameTimes.reduce((a, b) => a + b, 0);
    return sum / this.frameTimes.length;
  }

  getFrameTimeVariance(): number {
    const avg = this.getAverageFrameTime();
    const squaredDiffs = this.frameTimes.map((t) => (t - avg) ** 2);
    return squaredDiffs.reduce((a, b) => a + b, 0) / this.frameTimes.length;
  }

  getPercentile(p: number): number {
    const sorted = [...this.frameTimes].sort((a, b) => a - b);
    const index = Math.ceil((sorted.length * p) / 100) - 1;
    return sorted[Math.max(0, index)];
  }

  shouldSwitchToFixedStep(): boolean {
    const variance = this.getFrameTimeVariance();
    const p99 = this.getPercentile(99);
    return variance > 0.001 || p99 > 0.033;
  }
}
小结
    

  • 固定时间步提供物理确定性，是网络游戏和竞技游戏的首选
    • 

  • 可变时间步实现简单但存在稳定性风险，需要 dt 上限和子步进保护
    • 

  • 网络多人游戏几乎必须使用固定时间步以支持确定性回滚
    • 

  • 半固定混合是工业界最佳实践，物理固定、渲染可变
    • 

  • 性能监控帮助在运行时动态选择最优时间步策略
    •
