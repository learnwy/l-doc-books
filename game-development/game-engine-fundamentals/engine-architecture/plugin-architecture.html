插件式架构

核心概念

插件式架构允许在不修改引擎核心代码的情况下扩展引擎功能。通过定义标准化的插件接口，第三方开发者可以开发渲染器、物理引擎、音频后端等独立模块，引擎在运行时动态加载和管理这些插件。

插件接口设计
良好的插件接口设计是插件系统成功的关键。接口应当稳定、最小化、版本化，并提供清晰的语义约定。


interface PluginManifest {
  name: string;
  version: string;
  engineVersion: string;
  author: string;
  dependencies: Array<{ name: string; minVersion: string }>;
  extensionPoints: string[];
}

interface PluginContext {
  getService<T>(name: string): T;
  registerExtension(point: string, extension: unknown): void;
  addEventListener(event: string, handler: (...args: unknown[]) => void): void;
  getConfig<T>(key: string): T | undefined;
  getLogger(): Logger;
}

interface IPlugin {
  manifest: PluginManifest;
  activate(context: PluginContext): Promise<void>;
  deactivate(): Promise<void>;
}

interface Logger {
  info(message: string): void;
  warn(message: string): void;
  error(message: string): void;
}

class PhysicsPlugin implements IPlugin {
  manifest: PluginManifest = {
    name: 'bullet-physics',
    version: '1.0.0',
    engineVersion: '>=2.0.0',
    author: 'Engine Team',
    dependencies: [],
    extensionPoints: ['physics.solver', 'physics.broadphase'],
  };

  private context!: PluginContext;

  async activate(context: PluginContext): Promise<void> {
    this.context = context;
    context.registerExtension('physics.solver', new BulletSolver());
    context.registerExtension('physics.broadphase', new DbvtBroadphase());
    context.addEventListener('engine.preUpdate', this.preUpdate.bind(this));
    context.getLogger().info('Bullet Physics plugin activated');
  }

  async deactivate(): Promise<void> {
    this.context.getLogger().info('Bullet Physics plugin deactivated');
  }

  private preUpdate(): void {}
}

class BulletSolver {
  solve(): void {}
}
class DbvtBroadphase {
  query(): void {}
}
插件清单（Manifest）包含元数据和依赖声明，引擎在加载前验证版本兼容性和依赖是否满足，避免运行时冲突。


扩展点与钩子系统
扩展点（Extension Point）定义了引擎中可被插件替换或增强的位置。钩子系统（Hook System）允许插件在引擎执行流程的特定点插入自定义逻辑。


type HookHandler = (...args: unknown[]) => unknown;

class HookSystem {
  private hooks = new Map<string, Array<{ handler: HookHandler; priority: number }>>();

  register(hookName: string, handler: HookHandler, priority = 0): void {
    if (!this.hooks.has(hookName)) {
      this.hooks.set(hookName, []);
    }
    const handlers = this.hooks.get(hookName)!;
    handlers.push({ handler, priority });
    handlers.sort((a, b) => b.priority - a.priority);
  }

  async execute(hookName: string, ...args: unknown[]): Promise<unknown[]> {
    const handlers = this.hooks.get(hookName) ?? [];
    const results: unknown[] = [];
    for (const { handler } of handlers) {
      const result = await handler(...args);
      results.push(result);
    }
    return results;
  }

  executePipeline<T>(hookName: string, initialValue: T): T {
    const handlers = this.hooks.get(hookName) ?? [];
    let value = initialValue;
    for (const { handler } of handlers) {
      value = handler(value) as T;
    }
    return value;
  }
}

class ExtensionRegistry {
  private extensions = new Map<string, unknown[]>();

  register(point: string, extension: unknown): void {
    if (!this.extensions.has(point)) {
      this.extensions.set(point, []);
    }
    this.extensions.get(point)!.push(extension);
  }

  getAll<T>(point: string): T[] {
    return (this.extensions.get(point) ?? []) as T[];
  }

  getFirst<T>(point: string): T | undefined {
    const extensions = this.extensions.get(point);
    return extensions?.[0] as T | undefined;
  }
}
管道式钩子（Pipeline Hook）将前一个处理器的输出作为后一个的输入，常用于数据变换场景，如渲染后处理链、资源加载管道等。


插件依赖与版本管理
当插件数量增多时，依赖关系和版本兼容性成为关键挑战。引擎需要一套健壮的依赖解析和版本检查机制。


class PluginResolver {
  private manifests = new Map<string, PluginManifest>();

  addManifest(manifest: PluginManifest): void {
    this.manifests.set(manifest.name, manifest);
  }

  resolve(): string[] {
    this.checkCompatibility();
    return this.topologicalSort();
  }

  private checkCompatibility(): void {
    for (const [name, manifest] of this.manifests) {
      for (const dep of manifest.dependencies) {
        const depManifest = this.manifests.get(dep.name);
        if (!depManifest) {
          throw new Error(`Plugin "${name}" requires "${dep.name}" which is not installed`);
        }
        if (!this.isVersionCompatible(depManifest.version, dep.minVersion)) {
          throw new Error(`Plugin "${name}" requires "${dep.name}" >= ${dep.minVersion}, found ${depManifest.version}`);
        }
      }
    }
  }

  private isVersionCompatible(actual: string, required: string): boolean {
    const [aMajor, aMinor, aPatch] = actual.split('.').map(Number);
    const [rMajor, rMinor, rPatch] = required.split('.').map(Number);
    if (aMajor !== rMajor) return aMajor > rMajor;
    if (aMinor !== rMinor) return aMinor > rMinor;
    return aPatch >= rPatch;
  }

  private topologicalSort(): string[] {
    const visited = new Set<string>();
    const result: string[] = [];
    const visit = (name: string): void => {
      if (visited.has(name)) return;
      visited.add(name);
      const manifest = this.manifests.get(name);
      if (manifest) {
        for (const dep of manifest.dependencies) {
          visit(dep.name);
        }
        result.push(name);
      }
    };
    for (const name of this.manifests.keys()) {
      visit(name);
    }
    return result;
  }
}
热插拔与安全沙箱
高级插件系统支持热插拔——在引擎运行时加载和卸载插件。这对编辑器和开发工具尤其重要，因为开发者需要在不重启引擎的情况下测试插件变更。


安全沙箱限制插件的权限范围，防止恶意或有缺陷的插件破坏引擎状态或访问敏感资源。


interface SandboxPolicy {
  allowFileAccess: boolean;
  allowNetworkAccess: boolean;
  allowNativeCode: boolean;
  maxMemoryMB: number;
  maxCPUTimeMS: number;
  allowedAPIs: string[];
}

class PluginSandbox {
  private policy: SandboxPolicy;
  private memoryUsage = 0;

  constructor(policy: SandboxPolicy) {
    this.policy = policy;
  }

  checkFileAccess(path: string): boolean {
    if (!this.policy.allowFileAccess) return false;
    const allowed = ['/assets/', '/config/', '/plugins/'];
    return allowed.some((prefix) => path.startsWith(prefix));
  }

  checkNetworkAccess(url: string): boolean {
    if (!this.policy.allowNetworkAccess) return false;
    const blocked = ['localhost', '127.0.0.1', '0.0.0.0'];
    return !blocked.some((host) => url.includes(host));
  }

  checkMemory(bytes: number): boolean {
    this.memoryUsage += bytes;
    return this.memoryUsage <= this.policy.maxMemoryMB * 1024 * 1024;
  }

  createProxiedContext(realContext: PluginContext): PluginContext {
    const sandbox = this;
    return new Proxy(realContext, {
      get(target, prop: string) {
        if (!sandbox.policy.allowedAPIs.includes(prop)) {
          throw new Error(`API "${prop}" is not allowed by sandbox policy`);
        }
        return Reflect.get(target, prop);
      },
    });
  }
}
小结
    

  • 插件式架构通过标准化接口实现引擎的无侵入式扩展
    • 

  • 扩展点和钩子系统提供了灵活的插入点，支持替换和增强
    • 

  • 依赖管理通过版本检查和拓扑排序确保加载顺序正确
    • 

  • 安全沙箱限制插件权限，防止破坏引擎稳定性
    • 

  • 热插拔支持开发时的快速迭代，无需重启引擎
