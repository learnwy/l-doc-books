引擎子系统设计

核心概念

游戏引擎的子系统设计决定了引擎的可扩展性、可维护性和性能表现。每个子系统负责一个独立的功能域，通过明确的接口与其他子系统交互。优秀的子系统设计遵循单一职责原则，确保每个模块只关注一件事。

子系统生命周期管理
每个子系统都遵循统一的生命周期：创建 → 初始化 → 运行 → 暂停 → 恢复 → 关闭 → 销毁。生命周期管理器负责按依赖顺序驱动各子系统的状态转换。


enum SystemState {
  Created = 'created',
  Initializing = 'initializing',
  Running = 'running',
  Paused = 'paused',
  ShuttingDown = 'shutting_down',
  Destroyed = 'destroyed',
}

interface SubSystemDescriptor {
  name: string;
  dependencies: string[];
  priority: number;
}

abstract class SubSystem {
  state = SystemState.Created;
  abstract descriptor: SubSystemDescriptor;

  abstract onInit(): Promise<void>;
  abstract onUpdate(dt: number): void;
  abstract onShutdown(): void;

  async init(): Promise<void> {
    this.state = SystemState.Initializing;
    await this.onInit();
    this.state = SystemState.Running;
  }

  update(dt: number): void {
    if (this.state === SystemState.Running) {
      this.onUpdate(dt);
    }
  }

  shutdown(): void {
    this.state = SystemState.ShuttingDown;
    this.onShutdown();
    this.state = SystemState.Destroyed;
  }
}

class SystemManager {
  private systems = new Map<string, SubSystem>();
  private initOrder: string[] = [];

  register(system: SubSystem): void {
    this.systems.set(system.descriptor.name, system);
  }

  async initAll(): Promise<void> {
    this.initOrder = this.topologicalSort();
    for (const name of this.initOrder) {
      const system = this.systems.get(name)!;
      await system.init();
    }
  }

  private topologicalSort(): string[] {
    const visited = new Set<string>();
    const result: string[] = [];
    const visit = (name: string): void => {
      if (visited.has(name)) return;
      visited.add(name);
      const system = this.systems.get(name);
      if (system) {
        for (const dep of system.descriptor.dependencies) {
          visit(dep);
        }
        result.push(name);
      }
    };
    for (const name of this.systems.keys()) {
      visit(name);
    }
    return result;
  }

  shutdownAll(): void {
    for (const name of [...this.initOrder].reverse()) {
      this.systems.get(name)?.shutdown();
    }
  }
}
子系统的关闭顺序必须是初始化顺序的逆序，确保依赖方先于被依赖方关闭，避免悬空引用。


依赖注入与服务定位
子系统之间的依赖获取有两种主流模式：依赖注入（DI）和服务定位器（Service Locator）。游戏引擎中两者常混合使用。


依赖注入在初始化时将依赖传入，使依赖关系显式化，便于测试和替换。服务定位器通过全局注册表查找服务，使用更灵活但依赖关系隐式。


class ServiceLocator {
  private static services = new Map<string, unknown>();

  static register<T>(key: string, service: T): void {
    this.services.set(key, service);
  }

  static get<T>(key: string): T {
    const service = this.services.get(key);
    if (!service) {
      throw new Error(`Service not found: ${key}`);
    }
    return service as T;
  }

  static has(key: string): boolean {
    return this.services.has(key);
  }

  static clear(): void {
    this.services.clear();
  }
}

interface IRenderer {
  drawSprite(x: number, y: number, texture: string): void;
  clear(): void;
  present(): void;
}

interface IPhysics {
  stepSimulation(dt: number): void;
  createBody(shape: string, mass: number): number;
}

class GameplaySystem extends SubSystem {
  descriptor = { name: 'gameplay', dependencies: ['renderer', 'physics'], priority: 100 };

  private renderer!: IRenderer;
  private physics!: IPhysics;

  async onInit(): Promise<void> {
    this.renderer = ServiceLocator.get<IRenderer>('renderer');
    this.physics = ServiceLocator.get<IPhysics>('physics');
  }

  onUpdate(dt: number): void {
    this.physics.stepSimulation(dt);
    this.renderer.clear();
    this.renderer.present();
  }

  onShutdown(): void {}
}
子系统通信模式
子系统间通信模式的选择直接影响引擎的耦合度和性能。常见模式包括直接调用、共享数据、消息传递和黑板系统。


直接调用最高效但耦合最紧。共享数据通过公共数据结构交换信息，适合高频数据如变换矩阵。消息传递通过事件总线异步通信，适合低频通知。黑板系统是一种共享知识库，各子系统读写同一数据源。


interface BlackboardEntry {
  value: unknown;
  timestamp: number;
  source: string;
}

class Blackboard {
  private entries = new Map<string, BlackboardEntry>();

  write(key: string, value: unknown, source: string): void {
    this.entries.set(key, {
      value,
      timestamp: performance.now(),
      source,
    });
  }

  read<T>(key: string): T | undefined {
    return this.entries.get(key)?.value as T | undefined;
  }

  readWithMeta(key: string): BlackboardEntry | undefined {
    return this.entries.get(key);
  }

  has(key: string): boolean {
    return this.entries.has(key);
  }

  clear(): void {
    this.entries.clear();
  }
}

class AISubSystem extends SubSystem {
  descriptor = { name: 'ai', dependencies: ['physics'], priority: 80 };
  private blackboard!: Blackboard;

  async onInit(): Promise<void> {
    this.blackboard = ServiceLocator.get<Blackboard>('blackboard');
  }

  onUpdate(_dt: number): void {
    const playerPos = this.blackboard.read<[number, number, number]>('player.position');
    if (playerPos) {
      const threat = this.evaluateThreat(playerPos);
      this.blackboard.write('ai.threatLevel', threat, 'ai');
    }
  }

  private evaluateThreat(position: [number, number, number]): number {
    const distance = Math.sqrt(position[0] ** 2 + position[1] ** 2 + position[2] ** 2);
    return Math.max(0, 1 - distance / 100);
  }

  onShutdown(): void {}
}

小结
    

  • 子系统按核心、功能、玩法三层分类，各层有不同的初始化时机和线程模型
    • 

  • 生命周期管理通过拓扑排序确保依赖顺序正确，关闭顺序为初始化的逆序
    • 

  • 依赖注入和服务定位器各有优劣，实践中常混合使用
    • 

  • 通信模式从直接调用到黑板系统，耦合度递减，灵活性递增
    • 

  • 良好的子系统设计是引擎可扩展性和可维护性的基石
