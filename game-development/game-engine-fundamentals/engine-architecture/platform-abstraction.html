平台抽象层设计

核心概念

平台抽象层（Platform Abstraction Layer, PAL）是游戏引擎中位于最底层的架构组件，它将操作系统和硬件的差异封装在统一的接口之后。通过 PAL，引擎上层代码无需关心底层平台是 Windows、macOS、Linux、iOS 还是 Android，只需调用统一的 API 即可。

图形 API 抽象
图形 API 抽象是平台抽象层中最复杂的部分。现代引擎需要同时支持 Vulkan、Direct3D 12、Metal 和 WebGPU 等多种图形 API，它们的设计理念和资源管理方式差异显著。


抽象的关键在于找到各 API 的最大公约数，同时保留足够的灵活性以利用各平台的特有优势。过度抽象会损失性能，抽象不足则增加平台适配成本。


interface GfxTextureDesc {
  width: number;
  height: number;
  format: TextureFormat;
  usage: TextureUsage;
  mipLevels: number;
}

interface GfxBufferDesc {
  size: number;
  usage: BufferUsage;
  memoryType: MemoryType;
}

interface IGfxDevice {
  createTexture(desc: GfxTextureDesc): GfxTexture;
  createBuffer(desc: GfxBufferDesc): GfxBuffer;
  createShader(source: string, stage: ShaderStage): GfxShader;
  createPipeline(desc: PipelineDesc): GfxPipeline;
  createCommandBuffer(): GfxCommandBuffer;
  submit(commands: GfxCommandBuffer): void;
  present(): void;
}

type TextureFormat = 'rgba8' | 'rgba16f' | 'depth24' | 'depth32f';
type TextureUsage = 'sampled' | 'storage' | 'render_target';
type BufferUsage = 'vertex' | 'index' | 'uniform' | 'storage';
type MemoryType = 'gpu_only' | 'cpu_visible' | 'cpu_to_gpu';
type ShaderStage = 'vertex' | 'fragment' | 'compute';

interface GfxTexture {
  readonly id: number;
}
interface GfxBuffer {
  readonly id: number;
}
interface GfxShader {
  readonly id: number;
}
interface GfxPipeline {
  readonly id: number;
}
interface GfxCommandBuffer {
  beginRenderPass(desc: RenderPassDesc): void;
  setPipeline(pipeline: GfxPipeline): void;
  setVertexBuffer(buffer: GfxBuffer, slot: number): void;
  draw(vertexCount: number, instanceCount: number): void;
  endRenderPass(): void;
}
interface PipelineDesc {
  vertexShader: GfxShader;
  fragmentShader: GfxShader;
}
interface RenderPassDesc {
  colorAttachments: GfxTexture[];
}
interface Entity {
  id: number;
}
interface Level {
  name: string;

  applySettings(s: unknown): void;

文件系统抽象
文件系统抽象需要处理不同平台间路径分隔符、文件权限、异步 I/O 模型等差异。Web 平台尤其特殊，传统文件系统操作需要通过 Fetch API、IndexedDB 或 Origin Private File System（OPFS）来模拟。


interface IFileSystem {
  exists(path: string): Promise<boolean>;
  readFile(path: string): Promise<Uint8Array>;
  readText(path: string): Promise<string>;
  writeFile(path: string, data: Uint8Array): Promise<void>;
  listDir(path: string): Promise<string[]>;
  getSize(path: string): Promise<number>;
}

class WebFileSystem implements IFileSystem {
  private baseUrl: string;
  private cache = new Map<string, Uint8Array>();

  constructor(baseUrl: string) {
    this.baseUrl = baseUrl.replace(/\/$/, '');
  }

  async exists(path: string): Promise<boolean> {
    try {
      const response = await fetch(`${this.baseUrl}/${path}`, { method: 'HEAD' });
      return response.ok;
    } catch {
      return false;
    }
  }

  async readFile(path: string): Promise<Uint8Array> {
    if (this.cache.has(path)) {
      return this.cache.get(path)!;
    }
    const response = await fetch(`${this.baseUrl}/${path}`);
    if (!response.ok) throw new Error(`File not found: ${path}`);
    const buffer = await response.arrayBuffer();
    const data = new Uint8Array(buffer);
    this.cache.set(path, data);
    return data;
  }

  async readText(path: string): Promise<string> {
    const data = await this.readFile(path);
    return new TextDecoder().decode(data);
  }

  async writeFile(_path: string, _data: Uint8Array): Promise<void> {
    throw new Error('Write not supported on web platform');
  }

  async listDir(_path: string): Promise<string[]> {
    throw new Error('Directory listing not supported on web platform');
  }

  async getSize(path: string): Promise<number> {
    const data = await this.readFile(path);
    return data.byteLength;
  }
}
输入系统抽象
输入系统抽象需要统一处理键盘、鼠标、触摸屏和手柄等多种输入设备。不同平台的输入事件模型差异很大，Web 使用 DOM 事件，桌面平台使用系统级 API，移动平台使用触摸事件。


interface InputState {
  pressed: boolean;
  justPressed: boolean;
  justReleased: boolean;
  value: number;
}

interface IInputProvider {
  poll(): void;
  getButton(code: string): InputState;
  getAxis(code: string): number;
  getPointerPosition(): { x: number; y: number };
}

class ActionMapping {
  private bindings = new Map<string, string[]>();
  private provider: IInputProvider;

  constructor(provider: IInputProvider) {
    this.provider = provider;
  }

  bind(action: string, inputs: string[]): void {
    this.bindings.set(action, inputs);
  }

  isActionPressed(action: string): boolean {
    const inputs = this.bindings.get(action);
    if (!inputs) return false;
    return inputs.some((input) => this.provider.getButton(input).pressed);
  }

  isActionJustPressed(action: string): boolean {
    const inputs = this.bindings.get(action);
    if (!inputs) return false;
    return inputs.some((input) => this.provider.getButton(input).justPressed);
  }

  getActionAxis(action: string): number {
    const inputs = this.bindings.get(action);
    if (!inputs) return 0;
    let maxValue = 0;
    for (const input of inputs) {
      const value = this.provider.getAxis(input);
      if (Math.abs(value) > Math.abs(maxValue)) {
        maxValue = value;
      }
    }
    return maxValue;
  }
}
动作映射（Action Mapping）是输入抽象的核心模式——它将物理输入绑定到逻辑动作上，使游戏逻辑与具体输入设备解耦，支持玩家自定义按键绑定。


跨平台编译与构建
平台抽象不仅体现在运行时代码中，还体现在构建流程中。现代引擎需要支持从同一代码库编译到多个目标平台，这涉及条件编译、平台特定代码隔离和交叉编译工具链配置。


interface PlatformCapabilities {
  supportsCompute: boolean;
  supportsRayTracing: boolean;
  maxTextureSize: number;
  maxDrawCalls: number;
  touchSupport: boolean;
  gamepadSupport: boolean;
}

class PlatformDetector {
  static detect(): PlatformCapabilities {
    const isWeb = typeof window !== 'undefined';
    const isMobile = isWeb && /Android|iPhone|iPad/.test(navigator.userAgent);

    return {
      supportsCompute: !isMobile && this.checkComputeSupport(),
      supportsRayTracing: false,
      maxTextureSize: isMobile ? 4096 : 16384,
      maxDrawCalls: isMobile ? 1000 : 10000,
      touchSupport: isMobile || (isWeb && 'ontouchstart' in window),
      gamepadSupport: isWeb && 'getGamepads' in navigator,
    };
  }

  private static checkComputeSupport(): boolean {
    try {
      const canvas = document.createElement('canvas');
      const gl = canvas.getContext('webgl2');
      return gl !== null;
    } catch {
      return false;
    }
  }
}
平台能力检测是运行时适配的关键——引擎根据检测结果动态选择渲染路径、调整画质预设和启用或禁用特定功能。
