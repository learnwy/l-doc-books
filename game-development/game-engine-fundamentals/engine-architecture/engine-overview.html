游戏引擎架构概述

核心概念

游戏引擎是一个复杂的软件框架，它提供了游戏开发所需的核心功能模块，包括渲染、物理、音频、输入处理、资源管理等子系统。理解游戏引擎的整体架构是深入学习各个子系统的基础。

现代游戏引擎架构通常采用分层设计，每一层为上层提供抽象接口，同时隐藏底层的实现细节。

引擎运行时架构
游戏引擎的运行时架构决定了各子系统如何协同工作。典型的运行时架构包括初始化阶段、主循环阶段和清理阶段三个核心生命周期。


初始化阶段负责创建窗口、加载配置、初始化各子系统。主循环阶段是引擎的心跳，每帧依次执行输入处理、物理更新、逻辑更新、渲染输出。清理阶段在退出时释放所有资源。


interface SubSystem {
  name: string;
  priority: number;
  init(): Promise<void>;
  update(deltaTime: number): void;
  shutdown(): void;
}

class Engine {
  private systems: SubSystem[] = [];
  private running = false;

  registerSystem(system: SubSystem): void {
    this.systems.push(system);
    this.systems.sort((a, b) => a.priority - b.priority);
  }

  async start(): Promise<void> {
    for (const system of this.systems) {
      await system.init();
    }
    this.running = true;
    this.mainLoop();
  }

  private mainLoop(): void {
    let lastTime = performance.now();
    const loop = (): void => {
      if (!this.running) return;
      const now = performance.now();
      const dt = (now - lastTime) / 1000;
      lastTime = now;
      for (const system of this.systems) {
        system.update(dt);
      }
      requestAnimationFrame(loop);
    };
    requestAnimationFrame(loop);
  }

  shutdown(): void {
    this.running = false;
    for (const system of [...this.systems].reverse()) {
      system.shutdown();
    }
  }
}
子系统的初始化顺序至关重要——文件系统必须先于资源管理器，资源管理器必须先于渲染器，因为渲染器需要加载着色器和纹理资源。


数据驱动设计
现代游戏引擎普遍采用数据驱动设计，将游戏行为的定义从代码中分离到外部数据文件中。这种设计使得策划和美术人员可以在不修改代码的情况下调整游戏内容。


数据驱动设计的核心理念是"代码定义行为模式，数据定义具体参数"。引擎通过配置文件（JSON、YAML、XML）、脚本文件（Lua、C#）和资源描述文件来控制游戏行为。


interface EntityDefinition {
  type: string;
  components: Record<string, unknown>;
}

interface LevelDefinition {
  name: string;
  entities: EntityDefinition[];
  settings: {
    gravity: [number, number, number];
    ambientLight: [number, number, number];
    fogDensity: number;
  };
}

class DataDrivenLoader {
  private entityFactories = new Map<string, (data: Record<string, unknown>) => Entity>();

  registerFactory(type: string, factory: (data: Record<string, unknown>) => Entity): void {
    this.entityFactories.set(type, factory);
  }

  loadLevel(definition: LevelDefinition): Level {
    const level = new Level(definition.name);
    level.applySettings(definition.settings);
    for (const entityDef of definition.entities) {
      const factory = this.entityFactories.get(entityDef.type);
      if (factory) {
        const entity = factory(entityDef.components);
        level.addEntity(entity);
      }
    }
    return level;
  }
}
数据驱动架构的关键优势在于热重载能力——在游戏运行时修改数据文件，引擎能够实时反映变化，极大提升了迭代效率。


事件与消息系统
引擎子系统之间的通信是架构设计的核心挑战。直接调用会导致紧耦合，而事件/消息系统提供了一种松耦合的通信机制。


常见的事件系统实现模式包括观察者模式、发布-订阅模式和命令模式。每种模式在延迟、内存占用和解耦程度上各有权衡。


type EventHandler<T = unknown> = (data: T) => void;

class EventBus {
  private handlers = new Map<string, Set<EventHandler>>();
  private deferredEvents: Array<{ type: string; data: unknown }> = [];

  on<T>(type: string, handler: EventHandler<T>): () => void {
    if (!this.handlers.has(type)) {
      this.handlers.set(type, new Set());
    }
    this.handlers.get(type)!.add(handler as EventHandler);
    return () => this.handlers.get(type)?.delete(handler as EventHandler);
  }

  emit<T>(type: string, data: T): void {
    this.deferredEvents.push({ type, data });
  }

  flush(): void {
    const events = [...this.deferredEvents];
    this.deferredEvents.length = 0;
    for (const { type, data } of events) {
      const handlers = this.handlers.get(type);
      if (handlers) {
        for (const handler of handlers) {
          handler(data);
        }
      }
    }
  }
}
延迟事件分发（Deferred Dispatch）是游戏引擎中的常见做法——事件在产生时入队，在帧末统一分发，避免了事件处理过程中的递归触发问题。


引擎启动与配置管理
引擎的启动流程涉及配置加载、子系统注册、依赖检查和资源预加载等步骤。一个健壮的启动流程需要处理配置缺失、硬件不支持、资源损坏等异常情况。


配置管理系统通常支持多层配置覆盖：默认配置 → 项目配置 → 用户配置 → 命令行参数，后者覆盖前者。


interface EngineConfig {
  renderer: {
    backend: 'webgl2' | 'webgpu';
    resolution: [number, number];
    vsync: boolean;
    msaa: number;
  };
  physics: {
    gravity: [number, number, number];
    fixedTimestep: number;
    maxSubSteps: number;
  };
  audio: {
    masterVolume: number;
    maxChannels: number;
  };
}

class ConfigManager {
  private config: EngineConfig;
  private overrides: Partial<EngineConfig>[] = [];

  constructor(defaults: EngineConfig) {
    this.config = structuredClone(defaults);
  }

  loadFromFile(source: Partial<EngineConfig>): void {
    this.overrides.push(source);
    this.rebuildConfig();
  }

  get<K extends keyof EngineConfig>(key: K): EngineConfig[K] {
    return this.config[key];
  }

  private rebuildConfig(): void {
    let merged = structuredClone(this.config);
    for (const override of this.overrides) {
      merged = this.deepMerge(merged, override);
    }
    this.config = merged;
  }

  private deepMerge(target: Record<string, unknown>, source: Record<string, unknown>): Record<string, unknown> {
    const result = { ...target };
    for (const key of Object.keys(source)) {
      if (source[key] && typeof source[key] === 'object' && !Array.isArray(source[key])) {
        result[key] = this.deepMerge(
          (target[key] as Record<string, unknown>) ?? {},
          source[key] as Record<string, unknown>,
        );
      } else {
        result[key] = source[key];
      }
    }
    return result;
  }
}
