Figure AI 绩效考核：Demo 驱动的极速评估体系

绩效哲学

Figure AI 的绩效考核体系建立在一个核心信念上：在人形机器人这个快速演进的领域，唯一有意义的绩效证据是可演示的成果。

与传统大厂基于 OKR 或 360 度评估的年度周期不同，Figure AI 的绩效系统以 Sprint 里程碑为节奏，以 Demo 为核心证据。

绩效评估原则

原则 含义 对比传统方式
Demo 驱动 能展示的才算完成 vs 纸面进度报告
Sprint 节奏 两周为一个评估单元 vs 年度/半年度评估
结果优先 只看产出，不看投入时间 vs 考勤式管理
投资人对齐 绩效目标与融资承诺挂钩 vs 内部 KPI 闭环
快速反馈 问题当天暴露 vs 等待绩效周期

Sprint 里程碑模型

两周 Sprint 结构

Sprint 目标设定
每个 Sprint 的目标遵循三个层次：


    

  1. 必须完成（Must） — 与投资人承诺或客户交付直接相关
    2. 

  2. 应该完成（Should） — 推进技术路线图的关键步骤
    3. 

  3. 可以完成（Could） — 探索性工作或技术债清理
    4. 



目标与投资人承诺的对齐
Figure AI 的独特之处在于将内部绩效目标直接与外部融资承诺挂钩：

Demo 作为核心评估工具
Demo Day 制度
每两周的周五下午是 Figure AI 的 Demo Day：


    

  • 全员参加 — 不分层级，所有人都有资格展示
    • 

  • 实物优先 — 真实机器人动作 > 仿真视频 > PPT 讲解
    • 

  • 限时 5 分钟 — 强迫简洁，避免冗长解释
    • 

  • 现场提问 — CEO 和其他团队可以直接挑战
    • 

  • 录像存档 — 所有 Demo 被记录，作为晋升评估证据
    •

Demo 文化的深层逻辑
Demo 驱动绩效不仅是评估工具，更是一种组织理性：


    

  1. 消除信息不对称 — 管理者不需要"跟进"，成果自动可见
    2. 

  2. 激励持续产出 — 每两周一次的展示压力保持节奏
    3. 

  3. 促进知识共享 — 所有团队了解其他团队的进展
    4. 

  4. 加速决策 — 问题在 Demo 中暴露，当场讨论解决方案
    5.

KPI 示例
BMW 部署期间的核心 KPI：


    

  • Cycle Time — 总循环时间 ≤84 秒，装载时间 ≤37 秒
    • 

  • Placement Accuracy — 每班次 >99% 正确放置
    • 

  • Interventions — 每班次人工干预次数 = 0（目标）
    • 

  • Hardware Failures — 月度硬件故障 <2 次
    • 

  • Uptime — 每日可用时间 ≥9.5 小时（10 小时班次）
    •

晋升标准
晋升的核心标准是"持续在更高层级运作"：


    

  • 连续 2-3 个季度 Strong/Exceptional
    • 

  • Demo 记录显示系统级影响力
    • 

  • 能力覆盖下一层级的核心职责
    • 

  • 获得跨团队同事的认可
    • 



绩效系统的优势与风险
优势
    

  1. 高度透明 — Demo 记录人人可见，减少政治博弈
    2. 

  2. 快速反馈 — 不需要等半年才知道自己的表现
    3. 

  3. 结果导向 — 鼓励实质产出而非"看起来很忙"
    4. 

  4. 战略对齐 — 每个人的工作都与公司目标可追溯
    5. 



风险
    

  1. 短期主义 — 两周 Sprint 可能不利于长期研究
    2. 

  2. Demo 偏见 — 可展示的工作 ≠ 最有价值的工作（基础设施、技术债）
    3. 

  3. 压力过大 — 持续的展示压力可能导致倦怠
    4. 

  4. 协作低估 — 帮助他人的工作不容易在 Demo 中体现
    5.
