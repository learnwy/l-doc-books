模块边界

在大型 iOS 项目中，合理定义模块边界是架构健康的基石。本文介绍模块类型划分、依赖方向设计、公开 API 控制以及无环依赖原则。

模块类型

iOS 模块化项目通常将模块分为三大类：





模块类型
职责
示例





Feature（功能模块）
封装独立业务功能，包含 UI 和业务逻辑
首页、个人中心、搜索




Core（核心模块）
提供基础设施能力，无业务逻辑
网络层、存储层、埋点




Shared（共享模块）
跨模块复用的工具和组件
UI 组件库、扩展方法、公共模型







依赖方向
模块间的依赖必须遵循严格的方向规则，避免循环依赖：


依赖规则：


    

  • Feature → Core ✅ 功能模块可以依赖核心模块
    • 

  • Feature → Shared ✅ 功能模块可以依赖共享模块
    • 

  • Core → Shared ✅ 核心模块可以依赖共享模块
    • 

  • Feature → Feature ❌ 功能模块之间不能直接依赖
    • 

  • Core → Feature ❌ 核心模块不能依赖功能模块
    • 

  • Shared → Core/Feature ❌ 共享模块不能依赖上层模块
    • 





提示： Feature 之间的通信应通过接口模块或路由机制实现，而非直接依赖。






公开 API 控制
Swift 的访问控制修饰符是模块边界的第一道防线：


// ✅ 模块公开 API — 使用 public
public protocol PaymentServiceProtocol {
    func processPayment(amount: Decimal, currency: String) async throws -> PaymentResult
}

public struct PaymentResult {
    public let transactionId: String
    public let status: PaymentStatus
    public let timestamp: Date

    public init(transactionId: String, status: PaymentStatus, timestamp: Date) {
        self.transactionId = transactionId
        self.status = status
        self.timestamp = timestamp
    }
}

public enum PaymentStatus {
    case success
    case pending
    case failed(reason: String)
}

// ❌ 模块内部实现 — 使用 internal 或 private
final class StripePaymentService: PaymentServiceProtocol {
    private let apiKey: String
    private let httpClient: HTTPClientProtocol

    init(apiKey: String, httpClient: HTTPClientProtocol) {
        self.apiKey = apiKey
        self.httpClient = httpClient
    }

    func processPayment(amount: Decimal, currency: String) async throws -> PaymentResult {
        let response = try await httpClient.post("/charges", body: [
            "amount": amount,
            "currency": currency
        ])
        return PaymentResult(
            transactionId: response.id,
            status: .success,
            timestamp: Date()
        )
    }
}

无环依赖原则（ADP）
无环依赖原则（Acyclic Dependencies Principle）要求模块依赖图中不能存在环路：


打破循环依赖的策略：


// 场景：模块 A 需要调用模块 B，模块 B 也需要通知模块 A
// 解决方案：提取接口模块

// InterfaceModule（共享接口）
public protocol NotificationHandler: AnyObject {
    func handleNotification(_ notification: AppNotification)
}

// 模块 B — 依赖接口模块
public final class NotificationCenter {
    private weak var handler: NotificationHandler?

    public init(handler: NotificationHandler) {
        self.handler = handler
    }

    public func dispatch(_ notification: AppNotification) {
        handler?.handleNotification(notification)
    }
}

// 模块 A — 依赖接口模块并实现协议
extension AppCoordinator: NotificationHandler {
    public func handleNotification(_ notification: AppNotification) {
        switch notification {
        case .userLoggedOut:
            navigateToLogin()
        case .deepLink(let url):
            handleDeepLink(url)
        }
    }
}

小结
    

  • 模块分为 Feature（功能）、Core（核心）、Shared（共享）三大类型
    • 

  • 依赖方向必须自上而下：App → Feature → Core → Shared
    • 

  • Feature 模块之间禁止直接依赖，应通过接口模块或路由通信
    • 

  • 使用 Swift 访问控制修饰符严格管理模块公开 API
    • 

  • 遵循无环依赖原则，通过接口提取和依赖反转打破循环
    • 

  • 在 CI 中集成依赖图分析工具，持续守护模块边界
