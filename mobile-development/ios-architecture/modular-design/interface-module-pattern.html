接口模块模式

接口模块模式（Interface Module Pattern）是大型 iOS 模块化项目中解耦模块间依赖的核心手段。通过将协议定义与具体实现分离到不同模块，实现模块级别的依赖反转。

问题背景

当模块 A 需要使用模块 B 的功能时，直接依赖会导致紧耦合：

这种直接依赖带来的问题：






问题
影响





编译耦合
修改 B 会触发 A 重新编译




测试困难
测试 A 需要引入整个 B




循环风险
B 未来可能也需要 A 的功能




并行构建受限
A 和 B 无法并行编译







接口模块解决方案
将协议抽取到独立的接口模块中：




协议模块（Protocol-Only Module）
接口模块只包含协议定义和值类型，不包含任何实现代码：


// FeatureProfileInterface 模块
public struct UserProfile: Sendable {
    public let id: String
    public let displayName: String
    public let avatarURL: URL?
    public let bio: String

    public init(id: String, displayName: String, avatarURL: URL?, bio: String) {
        self.id = id
        self.displayName = displayName
        self.avatarURL = avatarURL
        self.bio = bio
    }
}

public protocol ProfileServiceProtocol: Sendable {
    func fetchProfile(userId: String) async throws -> UserProfile
    func updateProfile(_ profile: UserProfile) async throws
}

public protocol ProfileNavigatorProtocol: AnyObject {
    func showProfile(userId: String)
    func showEditProfile()
}


实现模块（Implementation Module）
实现模块依赖接口模块并提供具体实现：


// FeatureProfile 模块（依赖 FeatureProfileInterface）
import FeatureProfileInterface
import CoreNetworking

final class ProfileService: ProfileServiceProtocol {
    private let httpClient: HTTPClientProtocol

    init(httpClient: HTTPClientProtocol) {
        self.httpClient = httpClient
    }

    func fetchProfile(userId: String) async throws -> UserProfile {
        let dto: ProfileDTO = try await httpClient.get("/users/\(userId)/profile")
        return UserProfile(
            id: dto.id,
            displayName: dto.name,
            avatarURL: URL(string: dto.avatar),
            bio: dto.bio
        )
    }

    func updateProfile(_ profile: UserProfile) async throws {
        try await httpClient.put("/users/\(profile.id)/profile", body: ProfileDTO(from: profile))
    }
}


消费模块的使用方式
消费模块只依赖接口模块，通过依赖注入获取实现：


// FeatureHome 模块（只依赖 FeatureProfileInterface）
import FeatureProfileInterface

@MainActor
final class HomeViewModel: ObservableObject {
    @Published var userProfile: UserProfile?

    private let profileService: ProfileServiceProtocol
    private let profileNavigator: ProfileNavigatorProtocol

    init(profileService: ProfileServiceProtocol, profileNavigator: ProfileNavigatorProtocol) {
        self.profileService = profileService
        self.profileNavigator = profileNavigator
    }

    func loadProfile(userId: String) async {
        userProfile = try? await profileService.fetchProfile(userId: userId)
    }

    func navigateToProfile() {
        guard let profile = userProfile else { return }
        profileNavigator.showProfile(userId: profile.id)
    }
}


Package.swift 配置
// FeatureProfileInterface 包
let package = Package(
    name: "FeatureProfileInterface",
    platforms: [.iOS(.v17)],
    products: [
        .library(name: "FeatureProfileInterface", targets: ["FeatureProfileInterface"])
    ],
    targets: [
        .target(name: "FeatureProfileInterface", dependencies: [])
    ]
)

// FeatureProfile 实现包
let package = Package(
    name: "FeatureProfile",
    platforms: [.iOS(.v17)],
    products: [
        .library(name: "FeatureProfile", targets: ["FeatureProfile"])
    ],
    dependencies: [
        .package(path: "../FeatureProfileInterface"),
        .package(path: "../CoreNetworking"),
    ],
    targets: [
        .target(
            name: "FeatureProfile",
            dependencies: ["FeatureProfileInterface", "CoreNetworking"]
        )
    ]
)
或采用单包多 target 结构：


let package = Package(
    name: "FeatureProfile",
    platforms: [.iOS(.v17)],
    products: [
        .library(name: "FeatureProfile", targets: ["FeatureProfile"]),
        .library(name: "FeatureProfileInterface", targets: ["FeatureProfileInterface"]),
    ],
    dependencies: [
        .package(path: "../CoreNetworking"),
    ],
    targets: [
        .target(name: "FeatureProfileInterface", dependencies: []),
        .target(
            name: "FeatureProfile",
            dependencies: ["FeatureProfileInterface", "CoreNetworking"]
        ),
        .testTarget(name: "FeatureProfileTests", dependencies: ["FeatureProfile"])
    ]
)


模块级依赖反转
接口模块模式本质上是依赖反转原则（DIP）在模块级别的应用：






维度
直接依赖
接口模块模式





编译影响
实现变更触发重编译
只有接口变更触发重编译




并行编译
受限
接口模块稳定后可充分并行




测试隔离
需引入完整实现模块
只需依赖接口模块 + Mock




代码量
少
多（需维护接口模块）







提示： 不是所有模块都需要接口模块。对于 Shared 和 Core 层的稳定模块，直接依赖即可。接口模块主要用于 Feature 层之间的解耦。






小结
    

  • 接口模块模式将协议定义与具体实现分离到不同的 SPM 包或 Target
    • 

  • 协议模块只包含 protocol 和值类型，零实现依赖，编译速度极快
    • 

  • 消费模块只依赖接口模块，通过依赖注入在运行时获取具体实现
    • 

  • 这种模式本质上是依赖反转原则在模块级别的应用
    • 

  • 推荐使用单包多 Target 结构来减少包的数量
    • 

  • 接口模块适用于 Feature 间的解耦，Core/Shared 层通常不需要
    •
