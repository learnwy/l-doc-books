整洁架构

整洁架构（Clean Architecture）由 Robert C. Martin 提出，其核心思想是通过分层和依赖规则让业务逻辑独立于框架、UI 和数据库。本文介绍如何在 iOS 项目中落地整洁架构。

分层结构

整洁架构将系统分为三个核心层，每层有明确的职责边界：





层
职责
依赖方向





表现层
UI 展示、用户交互、状态管理
依赖领域层




领域层
业务规则、用例、实体定义
不依赖任何外层




数据层
网络请求、本地存储、数据映射
依赖领域层（实现协议）







依赖规则
整洁架构最重要的原则：依赖方向只能从外向内。内层不知道外层的存在。




提示： 通过协议（Protocol）实现依赖反转——领域层定义接口，数据层提供实现。






Entity（实体）
实体是核心业务对象，不包含任何框架依赖：


struct Article {
    let id: String
    let title: String
    let content: String
    let author: Author
    let publishedAt: Date
    let tags: [String]
}

struct Author {
    let id: String
    let name: String
    let avatarURL: URL?
}


Use Case（用例）
用例封装单一业务操作，是表现层与数据层的桥梁：


protocol FetchArticlesUseCaseProtocol {
    func execute(page: Int, pageSize: Int) async throws -> [Article]
}

final class FetchArticlesUseCase: FetchArticlesUseCaseProtocol {
    private let articleRepository: ArticleRepositoryProtocol

    init(articleRepository: ArticleRepositoryProtocol) {
        self.articleRepository = articleRepository
    }

    func execute(page: Int, pageSize: Int) async throws -> [Article] {
        let articles = try await articleRepository.fetchArticles(page: page, pageSize: pageSize)
        return articles.filter { !$0.tags.contains("draft") }
    }
}
用例可以组合多个 Repository：


final class PublishArticleUseCase {
    private let articleRepo: ArticleRepositoryProtocol
    private let analyticsRepo: AnalyticsRepositoryProtocol

    init(articleRepo: ArticleRepositoryProtocol, analyticsRepo: AnalyticsRepositoryProtocol) {
        self.articleRepo = articleRepo
        self.analyticsRepo = analyticsRepo
    }

    func execute(article: Article) async throws {
        try await articleRepo.save(article)
        try await analyticsRepo.trackEvent(.articlePublished(id: article.id))
    }
}


Repository 模式
Repository 在领域层定义协议，在数据层提供实现：


protocol ArticleRepositoryProtocol {
    func fetchArticles(page: Int, pageSize: Int) async throws -> [Article]
    func fetchArticle(id: String) async throws -> Article
    func save(_ article: Article) async throws
    func delete(id: String) async throws
}
数据层实现：


final class ArticleRepository: ArticleRepositoryProtocol {
    private let remoteDataSource: ArticleRemoteDataSource
    private let localDataSource: ArticleLocalDataSource

    init(remote: ArticleRemoteDataSource, local: ArticleLocalDataSource) {
        self.remoteDataSource = remote
        self.localDataSource = local
    }

    func fetchArticles(page: Int, pageSize: Int) async throws -> [Article] {
        do {
            let dtos = try await remoteDataSource.fetchArticles(page: page, pageSize: pageSize)
            let articles = dtos.map { $0.toDomain() }
            try await localDataSource.cache(articles)
            return articles
        } catch {
            return try await localDataSource.fetchCached()
        }
    }

    func fetchArticle(id: String) async throws -> Article {
        let dto = try await remoteDataSource.fetchArticle(id: id)
        return dto.toDomain()
    }

    func save(_ article: Article) async throws {
        let dto = ArticleDTO(from: article)
        try await remoteDataSource.save(dto)
    }

    func delete(id: String) async throws {
        try await remoteDataSource.delete(id: id)
        try await localDataSource.remove(id: id)
    }
}


DTO 与领域模型映射
数据传输对象（DTO）与领域实体之间需要显式映射：


struct ArticleDTO: Codable {
    let id: String
    let title: String
    let content: String
    let authorName: String
    let authorAvatar: String?
    let publishedTimestamp: TimeInterval
    let tags: String

    func toDomain() -> Article {
        Article(
            id: id,
            title: title,
            content: content,
            author: Author(
                id: "",
                name: authorName,
                avatarURL: authorAvatar.flatMap(URL.init)
            ),
            publishedAt: Date(timeIntervalSince1970: publishedTimestamp),
            tags: tags.split(separator: ",").map(String.init)
        )
    }

    init(from article: Article) {
        self.id = article.id
        self.title = article.title
        self.content = article.content
        self.authorName = article.author.name
        self.authorAvatar = article.author.avatarURL?.absoluteString
        self.publishedTimestamp = article.publishedAt.timeIntervalSince1970
        self.tags = article.tags.joined(separator: ",")
    }
}


表现层集成
ViewModel 只依赖 Use Case，不直接访问数据层：


@MainActor
final class ArticleListViewModel: ObservableObject {
    @Published var articles: [Article] = []
    @Published var isLoading = false
    @Published var error: String?

    private let fetchArticlesUseCase: FetchArticlesUseCaseProtocol
    private var currentPage = 0

    init(fetchArticlesUseCase: FetchArticlesUseCaseProtocol) {
        self.fetchArticlesUseCase = fetchArticlesUseCase
    }

    func loadNextPage() async {
        isLoading = true
        do {
            let newArticles = try await fetchArticlesUseCase.execute(page: currentPage, pageSize: 20)
            articles.append(contentsOf: newArticles)
            currentPage += 1
        } catch {
            self.error = error.localizedDescription
        }
        isLoading = false
    }
}


小结
    

  • 整洁架构通过领域层/数据层/表现层三层划分实现关注点分离
    • 

  • 依赖规则要求所有依赖从外层指向内层，内层通过协议定义接口
    • 

  • Entity 是纯业务对象，Use Case 封装单一业务操作
    • 

  • Repository 模式在领域层定义协议、在数据层实现，实现存储细节隐藏
    • 

  • DTO 与领域模型的显式映射保证了层间数据的独立演进
    • 

  • 整洁架构适合业务复杂度高、需要长期维护的项目
    •
