TCA 可组合架构

The Composable Architecture（TCA）是由 Point-Free 团队打造的 Swift 架构框架，强调可组合性、可测试性和人机工效。本文深入介绍 TCA 的核心概念：State、Action、Reducer、Store，以及 Effect 管理和依赖注入机制。

核心概念

TCA 的架构由四个核心组件组成，形成单向数据流：





组件
职责





State
描述功能所需的全部数据




Action
枚举所有可能的用户意图和系统事件




Reducer
纯函数，根据 Action 计算新 State 并返回 Effect




Store
运行时容器，连接 View 与 Reducer







基本实现
以一个计数器功能为例，展示 TCA 的完整实现流程：


import ComposableArchitecture

@Reducer
struct CounterFeature {
    @ObservableState
    struct State: Equatable {
        var count = 0
        var isLoading = false
        var fact: String?
    }

    enum Action {
        case incrementButtonTapped
        case decrementButtonTapped
        case factButtonTapped
        case factResponse(String)
    }

    @Dependency(\.numberFact) var numberFact

    var body: some ReducerOf<Self> {
        Reduce { state, action in
            switch action {
            case .incrementButtonTapped:
                state.count += 1
                state.fact = nil
                return .none

            case .decrementButtonTapped:
                state.count -= 1
                state.fact = nil
                return .none

            case .factButtonTapped:
                state.isLoading = true
                state.fact = nil
                return .run { [count = state.count] send in
                    let fact = try await numberFact.fetch(count)
                    await send(.factResponse(fact))
                }

            case .factResponse(let fact):
                state.isLoading = false
                state.fact = fact
                return .none
            }
        }
    }
}


Effect 管理
Effect 是 TCA 中处理副作用的核心机制。所有异步操作（网络请求、定时器、通知等）都通过 Effect 表达。


enum Action {
    case startTimer
    case stopTimer
    case timerTick
}

var body: some ReducerOf<Self> {
    Reduce { state, action in
        switch action {
        case .startTimer:
            return .run { send in
                for await _ in clock.timer(interval: .seconds(1)) {
                    await send(.timerTick)
                }
            }
            .cancellable(id: CancelID.timer)

        case .stopTimer:
            return .cancel(id: CancelID.timer)

        case .timerTick:
            state.secondsElapsed += 1
            return .none
        }
    }
}

private enum CancelID {
    case timer
}


提示： 使用 .cancellable(id:) 和 .cancel(id:) 配对管理长生命周期的 Effect，防止内存泄漏。






Scoping（作用域划分）
TCA 通过 Scope 机制将大的 Feature 拆分为多个小 Feature，实现真正的可组合性：


@Reducer
struct AppFeature {
    @ObservableState
    struct State: Equatable {
        var tab1 = CounterFeature.State()
        var tab2 = CounterFeature.State()
        var currentTab: Tab = .tab1
    }

    enum Tab { case tab1, tab2 }

    enum Action {
        case tab1(CounterFeature.Action)
        case tab2(CounterFeature.Action)
        case tabChanged(Tab)
    }

    var body: some ReducerOf<Self> {
        Scope(state: \.tab1, action: \.tab1) {
            CounterFeature()
        }
        Scope(state: \.tab2, action: \.tab2) {
            CounterFeature()
        }
        Reduce { state, action in
            switch action {
            case .tabChanged(let tab):
                state.currentTab = tab
                return .none
            case .tab1, .tab2:
                return .none
            }
        }
    }
}


依赖注入
TCA 内置了 @Dependency 属性包装器和依赖注册机制：


struct NumberFactClient {
    var fetch: @Sendable (Int) async throws -> String
}

extension NumberFactClient: DependencyKey {
    static let liveValue = NumberFactClient { number in
        let url = URL(string: "http://numbersapi.com/\(number)")!
        let (data, _) = try await URLSession.shared.data(from: url)
        return String(data: data, encoding: .utf8) ?? ""
    }

    static let testValue = NumberFactClient { number in
        "\(number) 是一个有趣的数字"
    }
}

extension DependencyValues {
    var numberFact: NumberFactClient {
        get { self[NumberFactClient.self] }
        set { self[NumberFactClient.self] = newValue }
    }
}


测试
TCA 的 TestStore 提供了精确的状态断言机制：


import XCTest
@testable import ComposableArchitecture

final class CounterFeatureTests: XCTestCase {
    @MainActor
    func testIncrement() async {
        let store = TestStore(initialState: CounterFeature.State()) {
            CounterFeature()
        }

        await store.send(.incrementButtonTapped) {
            $0.count = 1
        }

        await store.send(.decrementButtonTapped) {
            $0.count = 0
        }
    }

    @MainActor
    func testFact() async {
        let store = TestStore(initialState: CounterFeature.State()) {
            CounterFeature()
        } withDependencies: {
            $0.numberFact.fetch = { "\($0) 的测试事实" }
        }

        await store.send(.factButtonTapped) {
            $0.isLoading = true
        }

        await store.receive(\.factResponse) {
            $0.isLoading = false
            $0.fact = "0 的测试事实"
        }
    }
}


小结
    

  • TCA 通过 State/Action/Reducer/Store 四元组构建单向数据流架构
    • 

  • Effect 系统将所有副作用显式化，支持取消和依赖注入
    • 

  • Scope 机制允许将复杂功能拆分为可独立开发和测试的小模块
    • 

  • @Dependency 提供编译期安全的依赖注入，testValue 让测试零配置
    • 

  • TestStore 支持逐步断言状态变化和 Effect 产生的 Action
    • 

  • TCA 适合中大型项目，学习曲线较陡但长期收益显著
    •
