Part I · iOSiOS 架构与模块化 简介架构模式 简介从 MVC 到 MVVM

从 MVC 到 MVVM

iOS 开发最经典的架构演进路线就是从 Apple MVC 走向 MVVM。本文将深入分析 MVC 的痛点，以及 MVVM 如何通过数据绑定和 Combine 框架解决这些问题。

Apple MVC 的问题

Apple 官方推荐的 MVC（Model-View-Controller）在实际项目中往往演变为 Massive View Controller。





问题
描述





职责膨胀
UIViewController 同时承担视图生命周期、数据转换、网络请求、路由等职责




测试困难
业务逻辑与 UIKit 耦合，需要实例化完整视图层才能测试




复用性差
Controller 中的逻辑无法跨界面复用




并行开发受限
多人同时修改同一个 Controller 极易冲突







提示： 如果你的 ViewController 超过 300 行，大概率已经出现了职责膨胀的信号。






MVVM 架构概览
MVVM（Model-View-ViewModel）将表现逻辑从 Controller 中抽离到 ViewModel，通过数据绑定实现视图与状态的同步。


MVVM 的核心原则：


    

  • View 只负责展示和用户交互
    • 

  • ViewModel 持有状态、处理业务逻辑、暴露可观察属性
    • 

  • Model 为纯数据层，不依赖任何 UI 框架
    • 





基于 Combine 的 MVVM 实现
Swift Combine 框架为 MVVM 的数据绑定提供了原生支持。


import Combine
import Foundation

struct User {
    let id: UUID
    var name: String
    var email: String
}

protocol UserServiceProtocol {
    func fetchUser(id: UUID) -> AnyPublisher<User, Error>
}

final class ProfileViewModel: ObservableObject {
    @Published var userName: String = ""
    @Published var userEmail: String = ""
    @Published var isLoading: Bool = false
    @Published var errorMessage: String?

    private let userService: UserServiceProtocol
    private var cancellables = Set<AnyCancellable>()

    init(userService: UserServiceProtocol) {
        self.userService = userService
    }

    func loadUser(id: UUID) {
        isLoading = true
        errorMessage = nil

        userService.fetchUser(id: id)
            .receive(on: DispatchQueue.main)
            .sink(
                receiveCompletion: { [weak self] completion in
                    self?.isLoading = false
                    if case .failure(let error) = completion {
                        self?.errorMessage = error.localizedDescription
                    }
                },
                receiveValue: { [weak self] user in
                    self?.userName = user.name
                    self?.userEmail = user.email
                }
            )
            .store(in: &cancellables)
    }
}
在 SwiftUI 中绑定 ViewModel：


import SwiftUI

struct ProfileView: View {
    @StateObject private var viewModel: ProfileViewModel

    init(userService: UserServiceProtocol) {
        _viewModel = StateObject(wrappedValue: ProfileViewModel(userService: userService))
    }

    var body: some View {
        VStack(spacing: 16) {
            if viewModel.isLoading {
                ProgressView()
            } else {
                Text(viewModel.userName)
                    .font(.title)
                Text(viewModel.userEmail)
                    .foregroundStyle(.secondary)
            }

            if let error = viewModel.errorMessage {
                Text(error)
                    .foregroundStyle(.red)
            }
        }
        .task {
            viewModel.loadUser(id: UUID())
        }
    }
}

测试收益
MVVM 最显著的优势在于 ViewModel 可以脱离 UI 层独立测试：


import XCTest
import Combine

final class ProfileViewModelTests: XCTestCase {
    private var cancellables = Set<AnyCancellable>()

    func testLoadUserSuccess() {
        let mockService = MockUserService(result: .success(User(
            id: UUID(),
            name: "张三",
            email: "zhangsan@example.com"
        )))

        let viewModel = ProfileViewModel(userService: mockService)
        let expectation = XCTestExpectation(description: "用户数据加载完成")

        viewModel.$userName
            .dropFirst()
            .sink { name in
                XCTAssertEqual(name, "张三")
                expectation.fulfill()
            }
            .store(in: &cancellables)

        viewModel.loadUser(id: UUID())
        wait(for: [expectation], timeout: 1.0)
    }
}


提示： 通过协议抽象服务依赖，可以在测试中注入 Mock 实现，无需真实网络请求。






小结
    

  • Apple MVC 在实践中容易演变为 Massive View Controller，导致测试困难和职责不清
    • 

  • MVVM 通过引入 ViewModel 层将表现逻辑从 Controller 中解耦
    • 

  • Combine 框架的 @Published 和 ObservableObject 为数据绑定提供原生支持
    • 

  • SwiftUI 天然适配 MVVM 模式，@StateObject 与 @ObservedObject 是标准绑定方式
    • 

  • ViewModel 可独立于 UI 进行单元测试，显著提升代码的可测试性
    • 

  • 迁移建议：先将数据转换逻辑提取到 ViewModel，再逐步迁移网络和路由逻辑
    •
