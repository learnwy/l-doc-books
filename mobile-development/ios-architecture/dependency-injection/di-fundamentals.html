依赖注入基础

依赖注入（Dependency Injection, DI）是实现松耦合架构的核心技术。本文介绍 DI 的三种注入方式、IoC 容器与手动 DI 的对比，以及 Service Locator 反模式。

什么是依赖注入

依赖注入的核心思想是：一个对象不应该自己创建它所依赖的对象，而应该由外部提供。



三种注入方式
构造器注入（Constructor Injection）
最推荐的方式，在初始化时提供所有依赖：


protocol AnalyticsServiceProtocol {
    func track(event: String, properties: [String: Any])
}

protocol UserRepositoryProtocol {
    func fetchCurrentUser() async throws -> User
}

final class DashboardViewModel: ObservableObject {
    @Published var user: User?

    private let userRepository: UserRepositoryProtocol
    private let analytics: AnalyticsServiceProtocol

    init(userRepository: UserRepositoryProtocol, analytics: AnalyticsServiceProtocol) {
        self.userRepository = userRepository
        self.analytics = analytics
    }

    func loadDashboard() async {
        analytics.track(event: "dashboard_viewed", properties: [:])
        user = try? await userRepository.fetchCurrentUser()
    }
}
属性注入（Property Injection）
通过属性赋值提供依赖，适用于可选依赖或框架约束场景：


final class SettingsViewController: UIViewController {
    var themeService: ThemeServiceProtocol?
    var logger: LoggerProtocol?

    override func viewDidLoad() {
        super.viewDidLoad()
        logger?.log("Settings screen loaded")
        themeService?.apply(to: view)
    }
}
方法注入（Method Injection）
通过方法参数传入依赖，适合依赖只在特定操作中使用的场景：


struct ImageProcessor {
    func resize(image: UIImage, using filter: ImageFilterProtocol) -> UIImage {
        let filtered = filter.apply(to: image)
        return filtered.resized(to: CGSize(width: 200, height: 200))
    }

    func export(image: UIImage, encoder: ImageEncoderProtocol) -> Data {
        encoder.encode(image)
    }
}

提示： 优先使用构造器注入。只有当框架不支持（如 UIKit Storyboard 实例化）或依赖确实可选时，才考虑属性注入。






IoC 容器 vs 手动 DI
手动 DI（Pure DI）
直接在组合根（Composition Root）手动装配所有依赖：


@MainActor
final class AppDependencyContainer {
    private lazy var httpClient: HTTPClientProtocol = URLSessionHTTPClient()
    private lazy var userRepository: UserRepositoryProtocol = UserRepository(httpClient: httpClient)
    private lazy var analyticsService: AnalyticsServiceProtocol = FirebaseAnalyticsService()

    func makeDashboardViewModel() -> DashboardViewModel {
        DashboardViewModel(
            userRepository: userRepository,
            analytics: analyticsService
        )
    }

    func makeSettingsViewModel() -> SettingsViewModel {
        SettingsViewModel(
            userRepository: userRepository
        )
    }

    func makeProfileViewModel(userId: String) -> ProfileViewModel {
        ProfileViewModel(
            userId: userId,
            userRepository: userRepository,
            analytics: analyticsService
        )
    }
}
IoC 容器
使用容器自动解析依赖关系：


let container = DIContainer()

container.register(HTTPClientProtocol.self) { _ in
    URLSessionHTTPClient()
}

container.register(UserRepositoryProtocol.self) { resolver in
    UserRepository(httpClient: resolver.resolve(HTTPClientProtocol.self))
}

container.register(DashboardViewModel.self) { resolver in
    DashboardViewModel(
        userRepository: resolver.resolve(UserRepositoryProtocol.self),
        analytics: resolver.resolve(AnalyticsServiceProtocol.self)
    )
}

let viewModel: DashboardViewModel = container.resolve()

Service Locator 反模式
Service Locator 看似方便，实则隐藏了依赖关系：


// ❌ Service Locator 反模式
final class OrderViewModel {
    func placeOrder() async {
        let paymentService = ServiceLocator.shared.resolve(PaymentServiceProtocol.self)
        let orderService = ServiceLocator.shared.resolve(OrderServiceProtocol.self)
        let analytics = ServiceLocator.shared.resolve(AnalyticsServiceProtocol.self)

        let order = try? await orderService.createOrder()
        try? await paymentService.charge(order: order!)
        analytics.track(event: "order_placed", properties: [:])
    }
}

// ✅ 构造器注入
final class OrderViewModel {
    private let paymentService: PaymentServiceProtocol
    private let orderService: OrderServiceProtocol
    private let analytics: AnalyticsServiceProtocol

    init(
        paymentService: PaymentServiceProtocol,
        orderService: OrderServiceProtocol,
        analytics: AnalyticsServiceProtocol
    ) {
        self.paymentService = paymentService
        self.orderService = orderService
        self.analytics = analytics
    }

    func placeOrder() async {
        let order = try? await orderService.createOrder()
        try? await paymentService.charge(order: order!)
        analytics.track(event: "order_placed", properties: [:])
    }
}

小结
    

  • 依赖注入的核心是让对象从外部接收依赖，而非自己创建
    • 

  • 构造器注入是首选方式，保证不可变性和编译期安全
    • 

  • 属性注入适用于可选依赖和框架限制场景
    • 

  • 方法注入适用于只在特定操作中使用的依赖
    • 

  • 手动 DI 类型安全、调试友好；IoC 容器适合大型项目减少样板代码
    • 

  • Service Locator 是反模式，它隐藏了依赖关系，应尽量避免使用
    •
