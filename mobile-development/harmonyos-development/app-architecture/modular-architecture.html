模块化架构与 HAP/HSP 设计

概述

随着 HarmonyOS 应用复杂度增长，单一模块的工程结构难以维护。HarmonyOS 采用 HAP（Harmony Ability Package）和 HSP（Harmony Shared Package）两级模块化体系，配合 HAR（Harmony Archive）静态库，为大型应用提供了灵活的分包、复用和按需加载能力。理解模块化架构是构建可维护、可扩展应用的工程基础。

HAP 分包策略
Entry HAP 设计原则
Entry HAP 是应用安装时必定包含的模块，应当只包含：


    

  • 应用入口 Ability
    • 

  • 首屏页面（确保启动速度）
    • 

  • 核心导航框架
    • 

  • 首次使用必需的基础功能
    •

Feature HAP 按需加载
Feature HAP 支持按需下载安装，适合低频使用的大型功能模块：


import { bundleManager } from '@kit.AbilityKit';

// 检查模块是否已安装
async function isModuleInstalled(moduleName: string): Promise<boolean> {
  try {
    const bundleInfo = await bundleManager.getBundleInfoForSelf(
      bundleManager.BundleFlag.GET_BUNDLE_INFO_WITH_HAP_MODULE,
    );
    return bundleInfo.hapModulesInfo.some((m) => m.name === moduleName);
  } catch {
    return false;
  }
}

// 动态加载 Feature HAP
async function loadFeatureModule(moduleName: string): Promise<void> {
  const installed = await isModuleInstalled(moduleName);

  if (!installed) {
    // 触发模块下载
    // 显示下载进度 UI
    console.info(`正在下载模块: ${moduleName}`);
  }

  // 跳转到 Feature HAP 中的 Ability
  const want: Want = {
    bundleName: 'com.example.myapp',
    moduleName: moduleName,
    abilityName: 'FeatureAbility',
  };
  const context = getContext(this) as common.UIAbilityContext;
  await context.startAbility(want);
}

模块间路由设计
大型应用需要统一的路由框架管理模块间的页面跳转：


// commons/router/src/RouterManager.ets
interface RouteConfig {
  path: string;
  moduleName: string;
  pagePath: string;
  needLogin?: boolean;
}

class RouterManager {
  private static routes: Map<string, RouteConfig> = new Map();

  static register(config: RouteConfig): void {
    RouterManager.routes.set(config.path, config);
  }

  static async navigate(path: string, params?: Record<string, Object>): Promise<void> {
    const config = RouterManager.routes.get(path);
    if (!config) {
      console.error(`未注册的路由: ${path}`);
      return;
    }

    if (config.needLogin && !AuthManager.isLoggedIn()) {
      // 重定向到登录页
      RouterManager.navigate('/login', { redirect: path });
      return;
    }

    router.pushUrl({
      url: config.pagePath,
      params: params,
    });
  }
}

// 各模块注册路由
RouterManager.register({
  path: '/shopping/cart',
  moduleName: 'shopping',
  pagePath: 'pages/CartPage',
  needLogin: true,
});

RouterManager.register({
  path: '/social/chat',
  moduleName: 'social',
  pagePath: 'pages/ChatPage',
  needLogin: true,
});

包体积优化策略
    

  1. 资源分离：大图片、视频等资源放入 rawfile，支持按需下载
    2. 

  2. Tree Shaking：确保 HSP/HAR 导出粒度够细，编译器可消除未使用代码
    3. 

  3. 延迟加载：非首屏功能放入 Feature HAP，首次使用时下载
    4. 

  4. 共享提取：多模块公共代码提取为 HSP，避免 HAR 重复打包
    5. 

  5. 资源压缩：启用图片压缩和代码混淆
    6. 



小结
HarmonyOS 的模块化体系通过 HAP（分发单元）、HSP（共享单元）和 HAR（复用单元）三层设计，为应用提供了从代码组织到运行时加载的完整解决方案。合理的分包策略能显著改善安装体积、启动速度和团队协作效率。在实际项目中，建议以功能边界划分 Feature HAP，以复用频率决定 HSP 还是 HAR，并通过统一路由框架管理模块间的导航。
