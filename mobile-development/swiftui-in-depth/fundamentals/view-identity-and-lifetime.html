Part I · iOSSwiftUI 深入实践 简介基础 简介视图标识与生命周期

视图标识与生命周期

概述

SwiftUI 使用**视图标识（View Identity）**来追踪界面中的每个视图。标识决定了视图是被「更新」还是被「替换」，直接影响状态是否保留、动画是否流畅。理解结构标识与显式标识的区别，以及视图树 Diff 的工作方式，是写出高效 SwiftUI 代码的前提。

flowchart TD
    VI["视图标识"]
    VI --> SI["结构标识<br/>Structural Identity"]
    VI --> EI["显式标识<br/>Explicit Identity"]

    SI --> POS["基于代码位置"]
    SI --> CB["条件分支 = 不同标识"]

    EI --> ID[".id() 修饰器"]
    EI --> FE["ForEach 的 id 参数"]

    POS --> KEEP["位置不变 → 状态保留"]
    CB --> RESET["分支切换 → 状态重置"]
    ID --> CHANGE["id 变化 → 状态重置"]

核心概念

SwiftUI 用「标识」回答一个根本问题：这次更新是同一个视图的新状态，还是一个全新的视图。答案只有两种——更新（保留状态）或替换（重置状态）。

概念 来源 状态行为
结构标识 视图在树中的位置 位置不变则更新并保留状态
条件分支 if-else 的两条路径 视为不同视图，切换即重置
显式标识 .id() / ForEach(id:) id 变化即销毁重建
视图树 Diff 按标识逐一对比 只更新发生变化的部分
生命周期回调 onAppear / .task(id:) 与可见性和标识绑定

结构标识 (Structural Identity)

结构标识 (Structural Identity)

在没有显式 .id() 的情况下，SwiftUI 根据视图在视图树中的位置来确定标识。这被称为结构标识。

struct ExampleView: View {
    @State private var isExpanded = false

    var body: some View {
        VStack {
            Text("标题")

            if isExpanded {
                Text("展开内容")
                    .transition(.opacity)
            }

            Button("切换") {
                withAnimation {
                    isExpanded.toggle()
                }
            }
        }
    }
}

在这个例子中，「展开内容」的 Text 通过它在 VStack 子视图列表中的位置索引获得身份。当 isExpanded 为 false 时，这个节点从视图树中消失。

条件分支与标识

if-else 的不同分支代表不同的结构位置：

struct BranchView: View {
    @State private var useAlternate = false

    var body: some View {
        VStack {
            if useAlternate {
                CounterView()
            } else {
                CounterView()
            }
            Toggle("切换", isOn: $useAlternate)
        }
    }
}

struct CounterView: View {
    @State private var count = 0

    var body: some View {
        Button("计数：\(count)") {
            count += 1
        }
    }
}

虽然两个分支都是 CounterView，但由于处于不同的条件分支，SwiftUI 将它们视为不同的视图。切换时 count 状态会被重置为 0。

场景 标识行为 状态
同一分支内修改属性 同一视图的更新 保留
if-else 分支切换 不同视图的替换 重置
ForEach 中 id 不变 同一视图的更新 保留
ForEach 中 id 变化 旧视图移除，新视图创建 重置

显式标识 (.id 修饰器)

使用 .id() 修饰器可以手动指定视图的标识：

struct ProfileView: View {
    let userId: String
    @State private var scrollPosition: CGFloat = 0

    var body: some View {
        ScrollView {
            UserContent(userId: userId)
        }
        .id(userId)
    }
}

当 userId 发生变化时，整个 ScrollView 被视为新视图，之前的滚动位置和所有内部状态都会被重置。

利用 .id 强制刷新

这个特性可以用来强制重建视图：

struct RefreshableView: View {
    @State private var refreshToken = UUID()

    var body: some View {
        VStack {
            ComplexContentView()
                .id(refreshToken)

            Button("强制刷新") {
                refreshToken = UUID()
            }
        }
    }
}

提示： .id() 是一个强力工具，但过度使用会导致不必要的视图重建和状态丢失。只在确实需要「全新开始」的场景中使用。

视图树 Diffing

SwiftUI 在每次状态变化后，通过比较新旧视图树来确定最小更新范围：

sequenceDiagram
    participant Old as 旧视图树
    participant Diff as Diff 引擎
    participant New as 新视图树
    participant UI as 渲染层

    New->>Diff: 提交新的视图描述
    Diff->>Old: 按标识逐一对比
    Diff->>Diff: 识别新增/删除/更新
    Diff->>UI: 仅发送变化部分
    UI->>UI: 增量渲染

Diff 的对比基于以下规则：

struct ItemListView: View {
    @State private var items = ["苹果", "香蕉", "橘子"]

    var body: some View {
        VStack {
            ForEach(items, id: \.self) { item in
                ItemRow(name: item)
            }

            Button("添加葡萄") {
                items.append("葡萄")
            }

            Button("打乱顺序") {
                items.shuffle()
            }
        }
    }
}

struct ItemRow: View {
    let name: String
    @State private var isFavorite = false

    var body: some View {
        HStack {
            Text(name)
            Spacer()
            Button(action: { isFavorite.toggle() }) {
                Image(systemName: isFavorite ? "heart.fill" : "heart")
                    .foregroundStyle(isFavorite ? .red : .gray)
            }
        }
        .padding()
    }
}

因为使用 \.self 作为 id，当打乱顺序后，SwiftUI 会根据字符串值追踪每个 item 的标识。isFavorite 状态会跟随对应的字符串值移动。

状态重置场景分析

以下是各种场景下状态行为的详细对比：

struct ScenarioA: View {
    @State private var flag = true
    var body: some View {
        VStack {
            if flag {
                Text("Hello").bold()
            } else {
                Text("Hello").italic()
            }
            Toggle("切换", isOn: $flag)
        }
    }
}

struct ScenarioB: View {
    @State private var flag = true
    var body: some View {
        VStack {
            Text("Hello")
                .fontWeight(flag ? .bold : .regular)
            Toggle("切换", isOn: $flag)
        }
    }
}
场景 写法 标识变化 状态行为
A if-else 分支 标识变化 状态重置，有销毁/创建
B 条件修饰器 标识不变 状态保留，仅属性更新

提示： 如果只是需要修改视图的外观而非整体结构，优先使用条件修饰器而非条件分支。这样可以保留状态并获得更流畅的动画。

onAppear 与 onDisappear

视图的生命周期回调与标识密切相关：

struct LifecycleView: View {
    @State private var selectedTab = 0

    var body: some View {
        TabView(selection: $selectedTab) {
            PageView(title: "首页", color: .blue)
                .tag(0)
                .tabItem { Label("首页", systemImage: "house") }

            PageView(title: "设置", color: .green)
                .tag(1)
                .tabItem { Label("设置", systemImage: "gear") }
        }
    }
}

struct PageView: View {
    let title: String
    let color: Color
    @State private var loadCount = 0

    var body: some View {
        VStack {
            Text(title)
                .font(.largeTitle)
            Text("出现次数：\(loadCount)")
        }
        .frame(maxWidth: .infinity, maxHeight: .infinity)
        .background(color.opacity(0.1))
        .onAppear { loadCount += 1 }
        .onDisappear { print("\(title) 消失") }
    }
}
stateDiagram-v2
    [*] --> Created: 视图首次出现
    Created --> Appeared: onAppear
    Appeared --> Disappeared: 视图不可见
    Disappeared --> Appeared: 视图重新可见
    Appeared --> Destroyed: 标识变化/移除
    Destroyed --> [*]

注意 onAppear 可能被调用多次（例如 TabView 切换），而视图的 @State 只在标识首次出现时初始化一次。

task 修饰器与生命周期

.task 修饰器结合了 onAppear 和 Swift Concurrency：

struct AsyncView: View {
    let userId: String
    @State private var profile: UserProfile?

    var body: some View {
        Group {
            if let profile {
                ProfileContent(profile: profile)
            } else {
                ProgressView()
            }
        }
        .task(id: userId) {
            profile = await fetchProfile(userId: userId)
        }
    }

    func fetchProfile(userId: String) async -> UserProfile? {
        try? await Task.sleep(for: .seconds(1))
        return UserProfile(name: "用户\(userId)")
    }
}

.task(id:) 会在 id 变化时自动取消旧任务并启动新任务，与视图标识系统完美配合。

小结

  • SwiftUI 使用视图标识决定视图是「更新」还是「替换」
  • 结构标识基于视图在代码中的位置，if-else 不同分支是不同标识
  • 显式标识通过 .id() 修饰器手动指定，id 变化时状态完全重置
  • 视图树 Diff 按标识逐一对比，只更新发生变化的部分
  • 条件修饰器（不改变结构）比条件分支（改变结构）更适合仅修改外观的场景
  • onAppear / onDisappear 与视图的可见性绑定，可能被多次调用
  • .task(id:) 在 id 变化时自动取消旧任务并启动新任务
  • 合理利用标识机制可以实现强制刷新、状态保持和流畅动画
