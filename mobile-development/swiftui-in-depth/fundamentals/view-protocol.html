Part I · iOSSwiftUI 深入实践 简介基础 简介View 协议

View 协议

概述

View 协议是 SwiftUI 中一切可视元素的基石。无论是内置的 Text、Image，还是开发者自定义的组件，都遵循 View 协议。理解 View 协议的工作方式，是掌握 SwiftUI 架构的第一步。



View 协议的定义
View 协议的核心极其简洁，只要求一个关联类型和一个计算属性：


public protocol View {
    associatedtype Body: View
    @ViewBuilder var body: Self.Body { get }
}
每个遵循 View 的结构体都必须提供 body 属性，返回另一个 View。这形成了递归的视图树结构，直到遇到原始视图（primitive view）——由 SwiftUI 框架内部实现的基础视图，如 Text、Color 等。


struct WelcomeView: View {
    var body: some View {
        VStack {
            Text("欢迎来到 SwiftUI")
                .font(.largeTitle)
            Image(systemName: "swift")
                .font(.system(size: 60))
                .foregroundStyle(.orange)
        }
    }
}


提示： View 协议的 Body 关联类型是在编译期确定的，这让 SwiftUI 能够在编译期构建完整的类型信息，避免运行时的类型擦除开销。






body 属性的本质
body 是一个计算属性，而不是存储属性。每次 SwiftUI 需要了解视图的当前外观时，就会调用 body。这意味着：






特性
说明





调用时机
状态变化时由框架调用




调用频率
可能被多次调用，不可预测




纯函数性
相同状态应产生相同的视图描述




性能要求
必须快速返回，禁止执行耗时操作




副作用
不应包含网络请求、文件 IO 等副作用





struct TimerView: View {
    @State private var count = 0

    var body: some View {
        VStack(spacing: 16) {
            Text("计数: \(count)")
                .font(.title)
            Button("增加") {
                count += 1
            }
        }
    }
}
当 count 发生变化时，SwiftUI 会重新调用 body，获取新的视图描述，再与旧描述进行 diff，最终只更新变化的部分。




some View 与不透明返回类型
some View 是 Swift 5.1 引入的不透明返回类型（Opaque Return Type）。它告诉编译器：「返回值遵循 View 协议，但具体类型由实现决定」。


struct ProfileView: View {
    var body: some View {
        HStack {
            Image(systemName: "person.circle")
            Text("用户名")
        }
    }
}
编译器会推断 body 的真实类型为 HStack<TupleView<(Image, Text)>>，但对外只暴露 some View。这有两个关键优势：




视图标识 (View Identity)
SwiftUI 需要在视图树更新时识别每个视图的身份，以决定哪些视图是「同一个」视图的新状态，哪些是全新的视图。


结构标识 (Structural Identity)
默认情况下，SwiftUI 根据视图在视图树中的位置来确定其身份：


struct ContentView: View {
    @State private var showDetail = false

    var body: some View {
        VStack {
            if showDetail {
                DetailView()
            } else {
                PlaceholderView()
            }
        }
    }
}
在这个例子中，DetailView 和 PlaceholderView 占据不同的分支位置，SwiftUI 将它们视为不同的视图。切换时会销毁旧视图并创建新视图。


显式标识 (Explicit Identity)
使用 .id() 修饰器可以为视图赋予显式标识：


struct ListView: View {
    let items: [Item]

    var body: some View {
        ScrollView {
            LazyVStack {
                ForEach(items) { item in
                    ItemRow(item: item)
                        .id(item.id)
                }
            }
        }
    }
}


提示： 当显式标识发生变化时，SwiftUI 会销毁旧视图并创建新实例，同时重置所有关联的状态。这可以用于强制刷新视图。






结构型视图与修饰器视图
SwiftUI 中的视图可分为两大类：






类别
说明
示例





结构型视图
直接产生可见内容或布局结构
Text, Image, VStack, List




修饰器视图
包装并修改现有视图的外观或行为
.font(), .padding(), .background()





修饰器的本质是返回一个新的视图，包裹住原视图：


let view = Text("Hello")
    .font(.title)
    .padding()
    .background(.blue)
    .clipShape(RoundedRectangle(cornerRadius: 8))
上面的代码在编译后形成嵌套结构：


每一层修饰器都是一个泛型包装结构体。修饰器的顺序很重要——先 padding 再 background 与先 background 再 padding 效果完全不同。


struct OrderMattersView: View {
    var body: some View {
        VStack(spacing: 20) {
            Text("先 padding 再 background")
                .padding()
                .background(.blue)

            Text("先 background 再 padding")
                .background(.blue)
                .padding()
        }
        .foregroundStyle(.white)
    }
}


视图是值类型
SwiftUI 的 View 是结构体（struct），而不是类。这意味着视图是值类型，具有以下特性：






特性
影响





值语义
视图的复制是廉价的




无继承
通过组合而非继承来复用




轻量级
视图只是状态的描述，不持有 UI 资源




短生命周期
每次 body 调用时可能创建新实例





struct CardView: View {
    let title: String
    let subtitle: String

    var body: some View {
        VStack(alignment: .leading, spacing: 4) {
            Text(title)
                .font(.headline)
            Text(subtitle)
                .font(.subheadline)
                .foregroundStyle(.secondary)
        }
        .padding()
        .background(.regularMaterial)
        .clipShape(RoundedRectangle(cornerRadius: 12))
    }
}
视图结构体本身非常轻量，真正的渲染工作由 SwiftUI 的内部引擎负责。开发者创建的 View 结构体本质上只是一份渲染描述。




小结
    

  • View 协议是 SwiftUI 的核心抽象，只要求实现 body 计算属性
    • 

  • body 返回 some View（不透明返回类型），编译期确定具体类型，零运行时开销
    • 

  • 视图标识分为结构标识（基于位置）和显式标识（.id() 修饰器）
    • 

  • 视图分为结构型视图（产生内容）和修饰器视图（包装修改）两类
    • 

  • 修饰器的顺序影响最终效果，因为每层修饰器都是一个新的包装视图
    • 

  • View 是值类型（struct），轻量且无继承，通过组合实现复用
    • 

  • body 应当是纯函数，不包含副作用，可被框架任意次数调用
    •
