布局系统 简介

SwiftUI 的布局系统采用了独特的"提议-响应"机制：父视图向子视图提议可用空间，子视图返回自己期望的尺寸，父视图再据此决定子视图的最终位置。这套机制与 UIKit 的 Auto Layout 约束系统截然不同，它更加简洁直觉，却也意味着开发者需要重新建立对布局行为的心智模型。当标准的 HStack、VStack 和 ZStack 无法满足需求时，深入理解布局协议和几何信息获取方式就变得至关重要。

第一节"Layout 协议"深入 SwiftUI 布局引擎的核心接口。Layout 协议中 sizeThatFits 与 placeSubviews 两个方法如何分别对应提议与放置阶段、LayoutSubview 代理如何在不直接访问子视图的前提下获取布局信息、缓存机制如何避免重复计算——Layout 协议将 SwiftUI 内置容器的布局能力完整地开放给了开发者，是实现任意复杂排列方式的基础。

第二节"GeometryReader"解析在声明式框架中获取几何信息的特殊工具。GeometryReader 的工作时机与对布局流程的影响、GeometryProxy 提供的坐标空间与安全区域信息、GeometryReader 导致的常见布局问题与规避策略——GeometryReader 是一把强大但需要谨慎使用的双刃剑，理解其行为特征才能在需要时正确运用。

第三节"对齐与间距"精确控制视图之间的空间关系。对齐指南的工作原理与自定义对齐的实现方式、spacing 参数在不同容器中的默认行为差异、alignmentGuide 修饰符如何微调单个视图的对齐位置——对齐与间距看似简单，却是决定界面是否精致的细节所在，也是设计稿精确还原的技术保障。

第四节"自定义布局"展示突破标准容器限制的实战能力。如何基于 Layout 协议实现流式布局、环形布局等非标准排列、动画布局切换如何在不同排列方式之间平滑过渡、自定义布局在实际项目中的应用场景与性能考量——自定义布局是 SwiftUI 布局能力的终极体现，掌握它意味着不再受限于框架预设的排列模式。
