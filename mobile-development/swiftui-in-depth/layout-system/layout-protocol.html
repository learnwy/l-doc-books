Part I · iOSSwiftUI 深入实践 简介布局系统 简介Layout 协议

Layout 协议

概述

iOS 16 引入了 Layout 协议，允许开发者创建完全自定义的布局容器。通过实现 sizeThatFits 和 placeSubviews 两个核心方法，可以精确控制子视图的测量和放置逻辑。Layout 协议是 SwiftUI 布局系统最底层的抽象，理解它有助于掌握 HStack、VStack 等内置容器的工作原理。



布局协商流程
SwiftUI 的布局采用三阶段协商机制：






阶段
方法
职责





测量
sizeThatFits(proposal:subviews:cache:)
根据提议尺寸和子视图需求，确定容器尺寸




放置

将每个子视图放置到容器内的具体坐标




缓存

实现一个简单的自定义 Layout
以下是一个均匀分布子视图的水平布局实现：


struct EvenlySpacedHStack: Layout {
    var spacing: CGFloat = 8

    func sizeThatFits(
        proposal: ProposedViewSize,
        subviews: Subviews,
        cache: inout ()
    ) -> CGSize {
        let sizes = subviews.map { $0.sizeThatFits(.unspecified) }
        let totalWidth = sizes.reduce(0) { $0 + $1.width }
        let totalSpacing = spacing * CGFloat(max(subviews.count - 1, 0))
        let maxHeight = sizes.reduce(0) { max($0, $1.height) }

        return CGSize(
            width: totalWidth + totalSpacing,
            height: maxHeight
        )
    }

    func placeSubviews(
        in bounds: CGRect,
        proposal: ProposedViewSize,
        subviews: Subviews,
        cache: inout ()
    ) {
        var x = bounds.minX

        for subview in subviews {
            let size = subview.sizeThatFits(.unspecified)
            subview.place(
                at: CGPoint(x: x, y: bounds.midY),
                anchor: .leading,
                proposal: ProposedViewSize(size)
            )
            x += size.width + spacing
        }
    }
}
使用方式与内置容器完全一致：


struct DemoView: View {
    var body: some View {
        EvenlySpacedHStack(spacing: 12) {
            ForEach(0..<5) { i in
                RoundedRectangle(cornerRadius: 8)
                    .frame(width: 50, height: 50)
                    .foregroundStyle(.blue.opacity(Double(i + 1) / 5.0))
            }
        }
    }
}


ProposedViewSize 的三种模式
父视图通过 ProposedViewSize 向子视图提议尺寸，它有三种典型模式：






模式
值
含义





精确值

父视图建议的精确尺寸




未指定
.unspecified (nil 维度)
子视图应返回理想尺寸




零
.zero
子视图应返回最小尺寸




无穷大
.infinity

struct FlexibleLayout: Layout {
    func sizeThatFits(
        proposal: ProposedViewSize,
        subviews: Subviews,
        cache: inout ()
    ) -> CGSize {
        let idealSizes = subviews.map { $0.sizeThatFits(.unspecified) }
        let minSizes = subviews.map { $0.sizeThatFits(.zero) }

        let availableWidth = proposal.width ?? idealSizes.reduce(0) { $0 + $1.width }
        let height = idealSizes.reduce(0) { max($0, $1.height) }

        return CGSize(width: availableWidth, height: height)
    }

    func placeSubviews(
        in bounds: CGRect,
        proposal: ProposedViewSize,
        subviews: Subviews,
        cache: inout ()
    ) {
        let equalWidth = bounds.width / CGFloat(subviews.count)
        for (index, subview) in subviews.enumerated() {
            let x = bounds.minX + equalWidth * CGFloat(index) + equalWidth / 2
            subview.place(
                at: CGPoint(x: x, y: bounds.midY),
                anchor: .center,
                proposal: ProposedViewSize(width: equalWidth, height: bounds.height)
            )
        }
    }
}


Layout Cache
对于复杂布局，可以使用缓存避免重复计算：


struct CachedGridLayout: Layout {
    let columns: Int

    struct CacheData {
        var cellSize: CGSize
        var rows: Int
    }

    func makeCache(subviews: Subviews) -> CacheData {
        let maxSize = subviews.reduce(CGSize.zero) { result, subview in
            let size = subview.sizeThatFits(.unspecified)
            return CGSize(
                width: max(result.width, size.width),
                height: max(result.height, size.height)
            )
        }
        let rows = (subviews.count + columns - 1) / columns
        return CacheData(cellSize: maxSize, rows: rows)
    }

    func sizeThatFits(
        proposal: ProposedViewSize,
        subviews: Subviews,
        cache: inout CacheData
    ) -> CGSize {
        CGSize(
            width: cache.cellSize.width * CGFloat(columns),
            height: cache.cellSize.height * CGFloat(cache.rows)
        )
    }

    func placeSubviews(
        in bounds: CGRect,
        proposal: ProposedViewSize,
        subviews: Subviews,
        cache: inout CacheData
    ) {
        for (index, subview) in subviews.enumerated() {
            let col = index % columns
            let row = index / columns
            let x = bounds.minX + cache.cellSize.width * CGFloat(col)
            let y = bounds.minY + cache.cellSize.height * CGFloat(row)
            subview.place(
                at: CGPoint(x: x, y: y),
                anchor: .topLeading,
                proposal: ProposedViewSize(cache.cellSize)
            )
        }
    }
}


提示： makeCache 在子视图集合变化时会被重新调用。updateCache 方法可以在子视图属性变化但集合不变时更新缓存。






访问子视图布局属性
Layout.Subviews 的每个元素都支持通过 LayoutValueKey 传递自定义布局参数：


struct LayoutPriorityKey: LayoutValueKey {
    static let defaultValue: Double = 0
}

extension View {
    func customPriority(_ value: Double) -> some View {
        layoutValue(key: LayoutPriorityKey.self, value: value)
    }
}

struct PriorityLayout: Layout {
    func sizeThatFits(
        proposal: ProposedViewSize,
        subviews: Subviews,
        cache: inout ()
    ) -> CGSize {
        proposal.replacingUnspecifiedDimensions()
    }

    func placeSubviews(
        in bounds: CGRect,
        proposal: ProposedViewSize,
        subviews: Subviews,
        cache: inout ()
    ) {
        let sorted = subviews.sorted {
            $0[LayoutPriorityKey.self] > $1[LayoutPriorityKey.self]
        }
        var remaining = bounds.width
        for subview in sorted {
            let size = subview.sizeThatFits(ProposedViewSize(width: remaining, height: bounds.height))
            subview.place(at: bounds.origin, proposal: ProposedViewSize(size))
            remaining -= size.width
        }
    }
}


小结
    

  • Layout 协议提供了 sizeThatFits 和 placeSubviews 两个核心方法
    • 

  • SwiftUI 布局采用三阶段协商：提议尺寸 → 子视图返回需求 → 容器决定最终布局
    • 

  • ProposedViewSize 有精确值、未指定、零、无穷大四种典型模式
    • 

  • makeCache 可以缓存布局计算结果，避免 sizeThatFits 和 placeSubviews 之间的重复计算
    • 

  • LayoutValueKey 允许子视图向布局容器传递自定义参数
    • 

  • 自定义 Layout 的使用方式与 HStack、VStack 等内置容器完全一致
    •
