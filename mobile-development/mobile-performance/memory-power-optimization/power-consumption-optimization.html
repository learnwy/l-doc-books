功耗优化与后台任务管理

知识要点

移动设备的电池容量有限，用户对续航极度敏感。应用功耗过高不仅导致设备发热、续航缩短，还会被系统限制后台运行甚至被应用商店降权。功耗优化需要从 CPU、GPU、网络、定位、传感器五大维度系统治理，尤其要关注后台场景下的不合理资源占用。

五大功耗源及其量化：

功耗源 典型功率 最大占比 优化优先级
CPU 计算 200-2000mW 30-50% 最高
网络通信 100-800mW 20-35% 高
GPU 渲染 100-500mW 15-25% 中
GPS 定位 50-200mW 10-20% 中
屏幕显示 300-1000mW 固定开销 应用无法优化

详细讲解

功耗度量方法

iOS 功耗度量：


    

  • Xcode Energy Organizer：查看 App Store 用户的汇总功耗报告，分为 CPU、Location、Display、Network 四类
    • 

  • MetricKit：iOS 13+ 系统每 24 小时回调一次汇总数据，包含 CPU 时间、网络传输量、GPU 时间等
    • 

  • Instruments - Energy Impact：实时查看功耗等级（Low/High/Overhead）
    • 



Android 功耗度量：


    

  • Battery Historian：可视化分析 bugreport 中的 wakelock、alarm、网络活动等
    • 

  • Android Vitals：Google Play Console 展示过度唤醒、后台网络过多等功耗问题
    • 

  • PowerManager 接口：BatteryManager 获取实时电流/电压
    •

2. 降低 CPU 频率


移动 CPU 支持 DVFS（Dynamic Voltage and Frequency Scaling）。高频率意味着高功耗（功耗与频率的关系近似 P∝V2×fP \propto V^2 \times fP∝V2×f）。应用层虽无法直接控制频率，但可以通过以下方式间接影响：


    

  • 使用 QoS 标记任务优先级：iOS DispatchQoS.utility / Android THREAD_PRIORITY_BACKGROUND
    • 

  • 避免短时间内的密集计算引发 CPU boost
    • 

  • 批量处理 + 集中执行，让 CPU 有机会进入低频状态
    • 



3. 避免后台 CPU 唤醒


iOS 后台限制严格，但以下场景仍可能消耗 CPU：


    

  • Background Fetch：设置合理的 minimumBackgroundFetchInterval
    • 

  • Background Processing：使用 BGProcessingTaskRequest 在充电时执行
    • 

  • VoIP Push：仅用于真正的通话场景
    • 



网络功耗优化
网络模块的功耗来自无线电（Radio）状态切换。蜂窝网络的无线电有三种状态：


Tail 状态问题：每次网络请求结束后，Radio 不会立即进入 Idle，而是维持高功率的 Tail 状态 12-20 秒。频繁的小请求会使 Radio 永远无法回到 Idle 状态。

WorkManager 最佳实践：

    .setRequiredNetworkType(NetworkType.UNMETERED)  // WiFi
    .setRequiresCharging(true)                       // 充电中
    .build()

val uploadWork = OneTimeWorkRequestBuilder<UploadWorker>()
    .setConstraints(constraints)
    .setBackoffCriteria(BackoffPolicy.EXPONENTIAL, 10, TimeUnit.MINUTES)
    .build()

WorkManager.getInstance(context).enqueue(uploadWork)

小结
功耗优化的核心策略是「减少不必要的硬件活动」和「批量集中执行」。CPU 层面通过减少计算量、降低优先级、避免后台唤醒来省电；网络层面通过请求合并、预取缓存、心跳优化来减少 Radio 活跃时间；后台任务必须使用系统调度 API（WorkManager / BGTask）而非自行轮询。定位功耗根据精度需求选择最低功耗方案。建立功耗监控（MetricKit / Android Vitals）是持续治理的基础。
