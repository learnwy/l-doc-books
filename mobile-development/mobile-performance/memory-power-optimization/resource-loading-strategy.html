资源加载策略与包体积治理

知识要点

应用包体积（IPA/APK 大小）直接影响下载转化率与更新率。研究数据表明，包体积每增加 6MB，下载转化率下降约 1%。资源（图片、字体、动画文件、SO 库）通常占包体积的 40-60%。资源加载策略的优化目标是在不损害用户体验的前提下，尽可能减小初始包体积并提高运行时的资源加载效率。

包体积组成分析：

组成部分 典型占比 优化空间
可执行代码 25-40% 编译优化、无用代码移除
图片资源 20-35% 格式转换、压缩、动态下发
第三方 SDK 15-25% 精简依赖、按需集成
动态库/SO 10-20% 合并、strip
本地化/字体 5-10% 按需下载
其他 5-10% 配置文件、数据库预置

  2. 解析产物中的 LinkMap-xxx.txt
    3. 

  3. 按 Object File / Section 聚合统计

代码瘦身
iOS 代码瘦身：


    

  1. Link-Time Optimization (LTO)：编译器跨模块优化，可减少 5-15% 代码段大小
    2. 

  2. Dead Code Stripping：-dead_strip 移除未调用函数（默认开启）
    3. 

  3. ObjC 类/方法清理：ObjC 动态特性使编译器无法自动移除。需通过 AppCode Inspect / 自定义脚本扫描
    4. 

  4. Swift 泛型特化：-whole-module-optimization 启用全模块优化
    5. 



Android 代码瘦身：


    

  1. R8/ProGuard：混淆 + 摇树（Tree Shaking）移除未使用代码
    2. 

  2. ABI 分包：仅包含目标架构的 SO（arm64-v8a 为主）
    3. 

  3. 资源缩减：shrinkResources true 移除未引用资源
    4. 



// build.gradle.kts
android {
    buildTypes {
        release {
            isMinifyEnabled = true      // R8 代码缩减
            isShrinkResources = true    // 资源缩减
            proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"))
        }
    }
    splits {
        abi {
            isEnable = true
            reset()
            include("arm64-v8a", "armeabi-v7a")  // 仅包含目标架构
        }
    }
}

iOS On-Demand Resources：

  • 资源打标签（Tag）并设为按需下载

  • 系统自动管理下载、缓存和清理

  • NSBundleResourceRequest API 触发下载
    • 



Android Dynamic Feature Modules：


通过 Play Feature Delivery 将功能模块独立为按需下载的 Dynamic Feature：


    

  • install-time：安装时包含（默认）
    • 

  • on-demand：用户触发时下载
    • 

  • conditional：满足条件时自动下发（如设备类型、国家）

小结
资源加载策略与包体积治理是一个「做减法」的过程。核心方法论是：分析（Link Map / APK Analyzer 定位大头）→ 瘦身（图片压缩、代码裁剪、SDK 精简）→ 动态化（非核心资源按需下发）→ 防劣化（CI 包体积监控）。需要在包体积、加载性能、用户体验三者之间找到平衡点。建议将包体积纳入 CI 卡口指标，每次 MR 增量超过阈值时自动告警。
