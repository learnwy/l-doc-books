延迟初始化与按需加载

知识要点

延迟初始化（Lazy Initialization）是冷启动优化中收益最显著的手段之一。核心思想是将启动路径上非首屏必需的工作延后执行——不是不做，而是在合适的时机再做。按需加载（On-demand Loading）则进一步将模块的加载时机推迟到用户真正触发时。两者结合可以将启动路径缩减到最小必要集，实测可降低 30-50% 的启动耗时。

实现延迟初始化需要解决三个核心问题：

  1. 依赖关系分析：哪些初始化有先后依赖？哪些可以并行？
  2. 时机选择：何时执行延迟任务？idle 时、首帧后、还是用户触发时？
  3. 安全保障：延迟后是否会导致首次使用时卡顿（首次惩罚）？

详细讲解

启动任务分级模型

将所有启动任务按优先级分为四个等级：

优先级 含义 执行时机 典型任务
P0 启动阻塞型 main 之前或首帧前同步执行 Crash SDK、安全校验、基础网络配置
P1 首屏依赖型 首帧渲染前异步并行 首页数据预取、AB 实验配置、用户态恢复
P2 功能就绪型 首帧后 idle 时执行 推送注册、IM 长连接、埋点 SDK
P3 触发加载型 用户主动触发时 直播 SDK、支付模块、分享组件

任务编排框架设计

一个生产级的启动任务编排框架需要支持：依赖声明、优先级调度、并行执行、超时控制和耗时统计。

iOS 实现要点：


// 任务定义协议
protocol LaunchTask {
    var name: String { get }
    var priority: TaskPriority { get }
    var dependencies: [String] { get }
    func execute(completion: @escaping () -> Void)
}

// 调度器利用 OperationQueue 管理依赖
class LaunchScheduler {
    private let queue = OperationQueue()

    func schedule(tasks: [LaunchTask]) {
        let operations = tasks.map { TaskOperation(task: $0) }
        // 建立依赖关系
        for op in operations {
            for dep in op.task.dependencies {
                if let depOp = operations.first(where: { $0.task.name == dep }) {
                    op.addDependency(depOp)
                }
            }
        }
        queue.addOperations(operations, waitUntilFinished: false)
    }
}

延迟加载的具体模式
模式一：首帧后 idle 加载


iOS 利用 RunLoop 的 idle 状态：


CFRunLoopPerformBlock(CFRunLoopGetMain(), CFRunLoopMode.defaultMode.rawValue) {
    // 首帧后 RunLoop idle 时执行
    PushSDK.shared.register()
}
Android 利用 IdleHandler：


Looper.myQueue().addIdleHandler {
    // 主线程空闲时执行
    PushManager.init(context)
    false // 返回 false 表示只执行一次
}
模式二：路由触发懒加载


将非核心功能模块注册为路由节点，真正跳转时才加载：


Router.register("/live/room") { params in
    // 此时才初始化直播 SDK
    LiveSDK.shared.setup()
    let vc = LiveRoomViewController(roomId: params["id"])
    return vc
}

首次惩罚与预加载
延迟初始化的副作用是「首次使用惩罚」——用户第一次触发功能时可能有额外加载延迟。解决策略：


    

  1. 预热（Warm-up）：在用户高概率路径之前提前预加载。例如首页出现直播入口时提前初始化直播 SDK。
    2. 

  2. 渐进加载：先展示占位 UI，后台完成初始化后再刷新真实内容。
    3. 

  3. 预测性加载：基于用户行为模型预测下一步操作，提前加载对应模块。
    4.

小结
延迟初始化的本质是「把正确的事放在正确的时机做」。通过任务分级（P0-P3）、依赖关系分析（DAG 拓扑排序）、编排框架（并行 + idle + 路由触发）三层设计，可以系统化地缩减启动关键路径。需要注意首次惩罚问题，通过预热和预测性加载来平衡启动速度与功能可用性。下一节将讲解如何建立启动指标体系，持续监控这些优化成果不发生劣化。
