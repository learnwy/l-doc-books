列表滚动与复杂视图性能

知识要点

列表（UITableView/UICollectionView/RecyclerView）是移动应用最核心的交互形态，Feed 流、商品列表、聊天记录等场景无处不在。列表滚动的性能直接决定了用户对应用流畅度的整体评价。滚动卡顿的根源通常在于 Cell 创建/绑定耗时过长、图片解码阻塞主线程、布局复杂度过高以及预加载策略不当等问题。

列表性能优化核心指标：

指标 目标值 测量方法
滚动帧率 ≥ 55fps (P50) CADisplayLink / Choreographer
Cell 绑定耗时 < 4ms Instruments Time Profiler
Cell 高度计算 < 1ms 预计算 + 缓存
图片加载首屏 < 200ms 从 Cell 可见到图片显示
内存峰值 < 200MB Xcode Memory Gauge

Cell 复用机制与优化

iOS UITableView/UICollectionView 优化要点：


    

  1. 注册复用标识符：确保所有 Cell 类型都通过 register 注册，避免 dequeueReusableCell 返回 nil 而创建新实例。
    

    2. 

  2. Cell 类型精简：过多的 Cell 类型导致复用命中率下降。建议同类布局使用同一 Cell 类型 + 组件显隐控制。
    

    3. 

  3. prepareForReuse 轻量化：取消进行中的网络请求、清除图片引用，但不要重置布局。
    

    4. 

  4. Self-sizing Cell 性能陷阱：UITableViewAutomaticDimension 每次都会触发 Auto Layout 求解。对 Feed 流建议预计算高度并缓存。
    

    5. 



Android RecyclerView 优化要点：


    

  1. ViewHolder 池容量调优：
    2. 



recyclerView.recycledViewPool.setMaxRecycledViews(VIEW_TYPE_CARD, 20)
// 增大常用类型的池容量，减少 onCreateViewHolder 调用
    

  1. setHasStableIds(true)：当数据项有唯一 ID 时启用，可优化 notifyDataSetChanged 时的动画和复用效率。
    

    2. 

  2. DiffUtil 代替全量刷新：
    

    3. 



val diffResult = DiffUtil.calculateDiff(MyDiffCallback(oldList, newList))
diffResult.dispatchUpdatesTo(adapter)
// 增量更新，避免 notifyDataSetChanged 导致全部 Cell 重建

降采样（Downsampling）：避免将 3000x3000 的原图解码到内存，再缩放到 300x300 显示。正确做法是在解码阶段直接按目标尺寸采样：


// iOS ImageIO 降采样
let options: [CFString: Any] = [
    kCGImageSourceThumbnailMaxPixelSize: max(targetWidth, targetHeight) * scale,
    kCGImageSourceCreateThumbnailFromImageAlways: true,
    kCGImageSourceShouldCacheImmediately: true
]
let thumbnail = CGImageSourceCreateThumbnailAtIndex(source, 0, options as CFDictionary)

预加载与分帧策略
预加载（Prefetch）：在 Cell 进入可见区域之前提前开始数据加载。


// iOS UICollectionViewDataSourcePrefetching
func collectionView(_ collectionView: UICollectionView,
                    prefetchItemsAt indexPaths: [IndexPath]) {
    for indexPath in indexPaths {
        let url = dataSource[indexPath.item].imageURL
        ImagePrefetcher.shared.prefetch(url: url)
    }
}
// Android RecyclerView Prefetch
recyclerView.addOnScrollListener(object : RecyclerView.OnScrollListener() {
    override fun onScrolled(rv: RecyclerView, dx: Int, dy: Int) {
        val lastVisible = layoutManager.findLastVisibleItemPosition()
        // 提前 5 个位置开始预加载
        preloadImages(lastVisible + 1, lastVisible + 5)
    }
})

小结
列表滚动性能优化是一个系统工程，需要从 Cell 复用效率、图片加载管线、布局计算开销、预加载策略和内存管理等多个维度协同治理。核心原则是：减少 Cell 创建开销（复用池调优）、降低绑定耗时（异步 + 缓存）、控制图片内存（降采样 + 格式优化）、平滑视觉体验（预加载 + 分帧渲染）。对于异构 Feed 场景，组件化架构与模板收敛是规模化的关键。
