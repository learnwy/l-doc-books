APM 架构与端上采集

知识要点

APM（Application Performance Monitoring）是性能治理的基础设施。一个完善的移动端 APM 系统需要覆盖启动、页面加载、网络请求、卡顿、崩溃、内存、功耗等多个维度的性能数据采集，并将这些数据汇聚到后端平台进行分析、告警和归因。端上采集层是 APM 系统的核心组件，其设计直接决定了数据质量和对应用性能的自身影响。

APM 系统分层架构：

层次 职责 关键组件
采集层 端上数据采集与预处理 Hook 引擎、埋点 SDK、堆栈采样器
传输层 数据上报与流控 压缩编码、采样策略、离线缓存
存储层 海量时序数据存储 ClickHouse、Druid、TSDB
分析层 聚合计算与归因 Flink 实时流、离线批处理
展示层 可视化与告警 Grafana、自研看板、告警规则

Method Swizzling 实现函数耗时采集：


extension UIViewController {
    static func swizzleViewDidAppear() {
        let originalSel = #selector(viewDidAppear(_:))
        let swizzledSel = #selector(apm_viewDidAppear(_:))

        guard let originalMethod = class_getInstanceMethod(self, originalSel),
              let swizzledMethod = class_getInstanceMethod(self, swizzledSel) else { return }

        method_exchangeImplementations(originalMethod, swizzledMethod)
    }

    @objc func apm_viewDidAppear(_ animated: Bool) {
        let start = CFAbsoluteTimeGetCurrent()
        apm_viewDidAppear(animated)  // 调用原实现
        let duration = CFAbsoluteTimeGetCurrent() - start
        APMReporter.report(event: .pageAppear, duration: duration, page: type(of: self))
    }
}
2. Android 字节码插桩


Android 端通过 Gradle Transform API + ASM 在编译期对字节码进行插桩：


// ASM ClassVisitor 插桩示例
class PerformanceMethodVisitor(mv: MethodVisitor) : MethodVisitor(ASM9, mv) {
    override fun visitCode() {
        super.visitCode()
        // 在方法入口注入 startTime 记录
        mv.visitMethodInsn(INVOKESTATIC, "com/apm/Tracer", "begin", "(Ljava/lang/String;)V")
    }

    override fun visitInsn(opcode: Int) {
        if (opcode in IRETURN..RETURN || opcode == ATHROW) {
            // 在方法出口注入 endTime 记录
            mv.visitMethodInsn(INVOKESTATIC, "com/apm/Tracer", "end", "(Ljava/lang/String;)V")
        }
        super.visitInsn(opcode)
    }
}

小结
APM 架构设计的核心挑战是在「数据完整性」和「性能自身开销」之间取得平衡。端上采集通过 Hook + 插桩获取性能数据，使用无锁缓冲、异步处理、采样策略控制开销；传输层通过压缩和批量上报减少网络消耗；后端通过实时流处理实现秒级告警。一个好的 APM SDK 应该像空气一样——存在但不被感知。
