构建可复现性与环境一致性

概述

"在我机器上能编过"是软件工程中最经典的问题之一，在移动开发中尤为突出。iOS 构建依赖特定版本的 Xcode、Swift 编译器和系统 SDK，Android 构建则需要匹配特定的 JDK、Gradle、AGP 和 Build Tools 版本。当团队成员的本地环境存在差异，或 CI 机器的环境随时间漂移时，构建结果的不一致性会引发难以排查的问题。

构建可复现性（Build Reproducibility）的目标是：给定相同的源代码和构建配置，在任意时间、任意机器上都能产出比特级一致的构建产物。这不仅是工程实践的最高标准，也是安全审计和合规要求的基础。

Android Docker 构建镜像
# Android CI 构建镜像示例
FROM ubuntu:22.04

# 锁定 JDK 版本
ENV JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
RUN apt-get update && apt-get install -y openjdk-17-jdk

# 锁定 Android SDK 版本
ENV ANDROID_SDK_ROOT=/opt/android-sdk
RUN sdkmanager "platform-tools" \
    "platforms;android-34" \
    "build-tools;34.0.0" \
    "ndk;25.2.9519653"

# 预缓存 Gradle 分发包
COPY gradle/wrapper/gradle-wrapper.properties /tmp/
RUN gradle --version

小结
构建可复现性不是一个单点问题，而是贯穿工具链管理、环境标准化、构建配置和依赖治理的系统工程。核心原则是：所有影响构建输出的因素都必须被版本控制或锁定。这不仅能消除"在我机器上能编过"的问题，也为安全审计、故障回溯和产物验证提供了坚实基础。投入构建可复现性建设的团队，长期来看会获得更高的工程效率和更低的排障成本。
