二进制产物管理与缓存加速

概述

在大型移动项目中，全量源码编译的时间成本使得"每次修改都从零编译"变得不可接受。二进制产物管理与缓存加速是解决这一问题的核心工程手段。通过将稳定模块预编译为二进制产物，并建立高效的缓存分发机制，可以将构建时间从数十分钟缩短到数分钟级别。

这一领域的核心挑战在于：如何在保证正确性的前提下最大化缓存命中率，以及如何设计产物仓库的版本化策略使其能够支撑数百个模块的并行开发。

Android 二进制化方案
Android 的二进制化通过 AAR（Android Archive）实现，配合 Maven 仓库进行分发：


    

  • Local Maven：本地 .m2 缓存，适用于个人开发
    • 

  • Remote Maven：团队共享的 Nexus/Artifactory 仓库
    • 

  • Composite Build：Gradle 的 includeBuild 机制，允许按需在源码和二进制间切换
    • 



// settings.gradle.kts - 动态切换源码/二进制
val sourceBuildModules = providers.gradleProperty("sourceBuild")
    .getOrElse("").split(",")

include(":app")
if ("feature-login" in sourceBuildModules) {
    include(":feature-login")
} else {
    // Use AAR from Maven
}
远程构建缓存
缓存原理与架构
远程构建缓存的核心思想：如果某个编译任务的输入（源文件、编译参数、依赖版本）未发生变化，其输出（.o 文件、.dex 文件）可以直接从缓存中获取，跳过实际的编译过程。


Gradle Remote Cache
Gradle 内建了完善的远程缓存支持：


// settings.gradle.kts
buildCache {
    local { isEnabled = true }
    remote<HttpBuildCache> {
        url = uri("https://cache.company.com/gradle/")
        isPush = System.getenv("CI") != null  // 仅 CI 推送
        credentials {
            username = System.getenv("CACHE_USER")
            password = System.getenv("CACHE_PASS")
        }
    }
}
缓存命中率优化要点：


    

  • 确保 Task 的 inputs/outputs 声明完整且准确
    • 

  • 消除不稳定输入（时间戳、绝对路径、随机值）
    • 

  • 使用 --build-cache 配合 --scan 诊断缓存未命中原因
    •

推荐的混合策略：Release 版本使用语义化版本号（方便依赖声明），CI 构建使用 Git Hash（保证唯一性），产物存储使用内容 Hash（天然去重和缓存）。


产物仓库架构
增量构建优化
Swift 增量编译
Swift 增量编译通过 .swiftdeps 文件追踪文件间依赖。关键优化点：


    

  • 减少跨文件类型依赖：internal 类型变更只影响同模块文件
    • 

  • 合理使用 @_implementationOnly import：减少接口暴露
    • 

  • 模块粒度控制：过大的模块（>200 文件）会显著降低增量编译效率
    • 



Gradle 增量编译与 Avoidance
Gradle 的增量编译分为两个层次：


    

  • Task-level avoidance：通过 UP-TO-DATE 检查跳过未变更 Task
    • 

  • Compilation avoidance：即使源文件变更，如果 ABI（Application Binary Interface）未变，下游模块不需要重新编译
    • 



// 利用 api/implementation 分离 ABI
dependencies {
    // ABI 依赖 - 变更会触发下游重编译
    api("com.example:core-api:1.0")
    // Implementation 依赖 - 变更不影响下游
    implementation("com.example:core-impl:1.0")
}
小结
二进制产物管理与缓存加速是大型移动项目构建效率的命脉。核心原则是：将构建产物视为可缓存、可复用、可追溯的资产来管理。无论是 iOS 的 XCFramework 还是 Android 的 AAR，都需要配套的版本化策略、分发机制和缓存失效规则。远程缓存的投入产出比极高——一次正确的缓存配置可以为团队每天节省数百个工程师小时。
