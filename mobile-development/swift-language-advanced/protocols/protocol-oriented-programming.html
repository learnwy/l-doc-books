面向协议编程

概述

面向协议编程（Protocol-Oriented Programming, POP）是 Swift 的核心编程范式。在 2015 年 WWDC 上，Apple 明确提出"Swift 是一门面向协议的语言"。POP 用协议组合替代类继承，通过协议扩展提供默认实现，以值类型配合协议达到多态效果，避免了传统面向对象编程中的深层继承链和脆弱基类问题。

核心概念

面向协议编程（POP）的核心主张是：用协议组合替代类继承。它把「共享什么能力」和「类型是什么」解耦——类型通过遵循一组小协议来声明自己具备哪些能力，而不是通过继承一条基类链来获得实现。围绕这一主张有几个关键概念：

  • 协议组合——用 & 把多个小协议拼成所需的类型约束，遵循「小协议、大组合」原则；
  • 协议扩展——为协议提供默认实现，使遵循类型无需重复样板代码（详见「协议扩展」一篇）；
  • 追溯遵循（Retroactive Conformance）——通过扩展让已有类型遵循新协议，无需修改源码；
  • 值类型多态——struct/enum 配合协议达成多态，既保留值语义又避免深层继承；
  • 协议 vs 类继承——继承适合引用语义与身份标识，协议适合行为契约与解耦。

正是这些机制的组合，使 POP 规避了传统 OOP 的单继承限制、脆弱基类与高耦合问题。

协议 vs 类继承

传统面向对象使用类继承实现代码复用和多态，但存在诸多局限：

维度 类继承 协议组合
继承层级 单继承（树形） 多协议遵循（扁平）
适用类型 仅 class struct、enum、class、actor
语义 引用语义 值语义 + 引用语义
代码复用 继承父类实现 协议扩展提供默认实现
耦合度 高（子类依赖父类细节） 低（仅依赖协议契约）
扩展性 需要修改继承链 追溯遵循，无需修改源码 
protocol Flyable {
    var maxAltitude: Double { get }
    func fly()
}

protocol Swimmable {
    var maxDepth: Double { get }
    func swim()
}

struct Duck: Flyable, Swimmable {
    var maxAltitude: Double { 1000 }
    var maxDepth: Double { 5 }
    func fly() { print("Duck flying") }
    func swim() { print("Duck swimming") }
}

协议组合

Swift 允许一个类型同时遵循多个协议，并且可以使用 & 运算符组合协议作为类型约束：

protocol Identifiable {
    var id: String { get }
}

protocol Displayable {
    var displayName: String { get }
}

protocol Persistable {
    func save() throws
}

func show(_ item: some Identifiable & Displayable) {
    print("\(item.id): \(item.displayName)")
}

typealias FullEntity = Identifiable & Displayable & Persistable

协议组合的设计哲学是小协议、大组合——每个协议只定义一个最小的能力集合，通过组合满足不同场景的需求。

追溯遵循（Retroactive Conformance）

追溯遵循允许在不修改原始类型源码的情况下，通过扩展使其遵循新协议：

protocol Summable {
    static func +(lhs: Self, rhs: Self) -> Self
}

extension Int: Summable {}
extension Double: Summable {}
extension String: Summable {}

func sumAll<T: Summable>(_ values: [T]) -> T? {
    guard let first = values.first else { return nil }
    return values.dropFirst().reduce(first, +)
}

这是 POP 的杀手级特性——即使是标准库或第三方库的类型，也可以通过追溯遵循融入你的协议体系。

提示： 追溯遵循应遵守"所有权规则"：只有协议的定义者或类型的定义者才应该添加遵循。在两者都不属于你的情况下添加追溯遵循可能导致冲突。

POP 设计模式

能力组合模式

将不同的能力拆分为独立协议，按需组合：

protocol Cacheable {
    var cacheKey: String { get }
    var cacheExpiry: TimeInterval { get }
}

protocol Loggable {
    var logDescription: String { get }
}

protocol Validatable {
    func validate() throws
}

struct UserProfile: Cacheable, Loggable, Validatable {
    let name: String
    let email: String

    var cacheKey: String { "user_\(email)" }
    var cacheExpiry: TimeInterval { 3600 }
    var logDescription: String { "UserProfile(\(name))" }

    func validate() throws {
        guard email.contains("@") else {
            throw ValidationError.invalidEmail
        }
    }
}

依赖抽象模式

用协议定义依赖接口，便于测试和替换：

protocol NetworkClient {
    func fetch<T: Decodable>(from url: URL) async throws -> T
}

protocol StorageClient {
    func save<T: Encodable>(_ value: T, forKey key: String) throws
    func load<T: Decodable>(forKey key: String) throws -> T?
}

struct UserService {
    let network: any NetworkClient
    let storage: any StorageClient

    func refreshUser(id: String) async throws -> User {
        let url = URL(string: "https://api.example.com/users/\(id)")!
        let user: User = try await network.fetch(from: url)
        try storage.save(user, forKey: "user_\(id)")
        return user
    }
}

何时选择协议 vs 类

虽然 POP 是 Swift 的推荐范式，但类继承在某些场景仍有价值：

// 适合类继承：需要引用语义和身份标识
class ViewController: UIViewController {
    override func viewDidLoad() { }
}

// 适合协议：定义行为契约
protocol DataSource {
    func numberOfItems() -> Int
    func item(at index: Int) -> Any
}

// 适合协议 + 值类型：无共享状态
struct Point: Equatable, Hashable, Codable {
    var x: Double
    var y: Double
}

小结

  • 面向协议编程用协议组合替代类继承，是 Swift 的核心范式
  • 协议组合通过 & 运算符灵活组合多个能力，遵循"小协议、大组合"原则
  • 追溯遵循允许对已有类型扩展协议遵循，无需修改源码
  • POP 常见模式包括能力组合和依赖抽象，提高代码的可测试性和解耦性
  • 类继承在需要引用语义、身份标识和框架互操作（如 UIKit）时仍有价值
  • 值类型 + 协议是 Swift 推荐的默认选择，兼具安全性和性能
