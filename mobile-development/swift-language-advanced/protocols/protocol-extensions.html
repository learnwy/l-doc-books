协议扩展

概述

协议扩展（Protocol Extension）是 Swift 面向协议编程的基石。它允许为协议提供方法、计算属性和下标的默认实现，使遵循类型无需重复编写样板代码。然而，协议扩展中的方法分派机制——静态分派 vs 动态分派——是 Swift 中最容易引起混淆的知识点之一。

默认实现
协议扩展可以为协议的所有方法提供默认实现：


protocol Greetable {
    var name: String { get }
    func greet() -> String
}

extension Greetable {
    func greet() -> String {
        "Hello, \(name)!"
    }
}

struct Person: Greetable {
    let name: String
}

struct Robot: Greetable {
    let name: String

    func greet() -> String {
        "Beep boop, I am \(name)."
    }
}

let person = Person(name: "Alice")
let robot = Robot(name: "R2D2")
print(person.greet()) // Hello, Alice!
print(robot.greet())  // Beep boop, I am R2D2.
Person 使用默认实现，Robot 提供了自定义实现来覆盖默认行为。




静态分派 vs 动态分派
这是协议扩展中最关键的概念。协议要求中声明的方法使用动态分派，仅在扩展中添加的方法使用静态分派：


protocol Describable {
    func describe() -> String
}

extension Describable {
    func describe() -> String {
        "I am Describable"
    }

    func detailedDescription() -> String {
        "Detail: \(describe())"
    }
}

struct Cat: Describable {
    func describe() -> String {
        "I am a Cat"
    }

    func detailedDescription() -> String {
        "Cat Detail: meow"
    }
}

let cat = Cat()
let describable: any Describable = cat

print(cat.describe())                    // I am a Cat
print(describable.describe())            // I am a Cat ✅ 动态分派

print(cat.detailedDescription())         // Cat Detail: meow
print(describable.detailedDescription()) // Detail: I am a Cat ⚠️ 静态分派

提示： 这个分派规则是 Swift 中最常见的"意外行为"来源。如果你希望子类型能够覆盖某个方法，必须在协议声明中列出该方法。






定制点（Customization Points）
利用分派机制可以设计"定制点"模式——在协议要求中声明可定制方法，在扩展中提供包含定制点调用的复合方法：


protocol Renderer {
    func renderHeader() -> String
    func renderBody() -> String
    func renderFooter() -> String
}

extension Renderer {
    func renderHeader() -> String { "<header/>" }
    func renderBody() -> String { "<body/>" }
    func renderFooter() -> String { "<footer/>" }

    func render() -> String {
        """
        \(renderHeader())
        \(renderBody())
        \(renderFooter())
        """
    }
}

struct HTMLRenderer: Renderer {
    func renderBody() -> String {
        "<body><p>Custom HTML</p></body>"
    }
}

let renderer = HTMLRenderer()
print(renderer.render())
render() 是非定制的组合方法，而 renderHeader()、renderBody()、renderFooter() 是定制点。遵循类型只需覆盖需要定制的部分。




条件扩展
协议扩展可以添加 where 子句，仅对满足条件的类型生效：


extension Collection where Element: Numeric {
    func total() -> Element {
        reduce(0, +)
    }
}

extension Collection where Element: StringProtocol {
    func joined(with separator: String = ", ") -> String {
        map(String.init).joined(separator: separator)
    }
}

let numbers = [1, 2, 3, 4, 5]
print(numbers.total()) // 15

let words = ["Swift", "is", "great"]
print(words.joined(with: " ")) // Swift is great


协议扩展 vs 基类默认实现
// 基类方式：需要继承，仅限 class
class BaseLogger {
    func log(_ message: String) {
        print("[LOG] \(message)")
    }
}

// 协议扩展方式：任何类型均可使用
protocol Logger {
    func log(_ message: String)
}

extension Logger {
    func log(_ message: String) {
        print("[LOG] \(message)")
    }
}

struct FileLogger: Logger {
    func log(_ message: String) {
        print("[FILE] \(message)")
    }
}

struct ConsoleLogger: Logger {}

常见陷阱
协议扩展中的存储
协议扩展不能添加存储属性，但可以通过关联对象（仅 class）或计算属性变通：


protocol Timestamped {
    var createdAt: Date { get }
}

extension Timestamped {
    var age: TimeInterval {
        Date().timeIntervalSince(createdAt)
    }

    var isRecent: Bool {
        age < 3600
    }
}
避免协议扩展的过度使用
// ❌ 不好：大量无关方法堆在一个协议扩展中
extension MyProtocol {
    func methodA() { }
    func methodB() { }
    func methodC() { }
    func methodD() { }
}

// ✅ 好：按功能拆分为多个协议
protocol Readable { func read() -> Data }
protocol Writable { func write(_ data: Data) }
protocol Deletable { func delete() }


小结
    

  • 协议扩展为协议方法提供默认实现，是 POP 的基石
    • 

  • 动态分派应用于协议要求中声明的方法；静态分派应用于仅在扩展中添加的方法
    • 

  • 利用分派机制可设计定制点模式，让遵循类型只覆盖需要定制的部分
    • 

  • 条件扩展通过 where 子句为特定类型提供额外功能
    • 

  • 协议扩展不能添加存储属性，但可通过计算属性提供派生值
    • 

  • 避免在协议扩展中堆积大量无关方法，应按功能拆分为多个小协议
    •
