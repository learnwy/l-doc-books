Actors 行为体

概述

Actor 是 Swift 5.5 引入的并发安全类型（SE-0306），它通过**隔离（isolation）**机制保护其内部状态，确保同一时间只有一个任务访问 actor 的可变状态。Actor 消除了传统并发编程中手动管理锁和同步的需要，将数据竞争的防护提升到语言层面。

核心概念

Actor 是 Swift 5.5 引入的并发安全类型（SE-0306），它把「保护可变状态」从手动加锁提升为语言级保证：同一时间只允许一个任务访问 actor 的可变状态，跨隔离边界的访问被编译器强制要求 await。围绕它有几个关键概念：

  • Actor 隔离——actor 的属性与方法默认被隔离，串行化访问，从外部访问需 await；
  • @MainActor——特殊的全局 actor，确保代码在主线程执行，是 UI 更新的标准方式；
  • 全局 Actor——@globalActor 自定义隔离域，把分散的代码统一到同一隔离边界；
  • nonisolated——让方法脱离隔离可同步调用，但只能访问不可变状态（let）；
  • 重入性（Reentrancy）——actor 方法在 await 挂起时会让出，其他任务可进入，因此 await 前后状态可能变化，必须重新校验。

一句话概括：actor 用隔离和串行化消灭数据竞争，但重入性要求你在每个 await 后重新验证状态。

Actor 基础

Actor 的声明类似 class，但所有属性和方法默认被隔离：

actor BankAccount {
    let accountNumber: String
    private(set) var balance: Double

    init(accountNumber: String, initialBalance: Double) {
        self.accountNumber = accountNumber
        self.balance = initialBalance
    }

    func deposit(_ amount: Double) {
        balance += amount
    }

    func withdraw(_ amount: Double) throws -> Double {
        guard balance >= amount else {
            throw BankError.insufficientFunds
        }
        balance -= amount
        return amount
    }
}

从外部访问 actor 的隔离成员必须使用 await：

let account = BankAccount(accountNumber: "001", initialBalance: 1000)

await account.deposit(500)
let withdrawn = try await account.withdraw(200)
print(await account.balance)

Actor 隔离机制

Actor 保证其内部状态的串行化访问——多个并发任务对同一 actor 的访问会被自动排队：

sequenceDiagram
    participant T1 as Task 1
    participant T2 as Task 2
    participant A as BankAccount Actor
    T1->>A: await deposit(100)
    Note over A: 执行 deposit
    T2->>A: await withdraw(50)
    Note over A: Task 2 等待
    A->>T1: 完成
    Note over A: 执行 withdraw
    A->>T2: 完成

编译器在编译时检查隔离边界：

actor Counter {
    var count = 0

    func increment() {
        count += 1
    }
}

let counter = Counter()

// ✅ 从 async 上下文中通过 await 访问
Task {
    await counter.increment()
}

// ❌ 编译错误：不能从非隔离上下文同步访问
// counter.count += 1

MainActor

@MainActor 是一个特殊的全局 actor，它确保代码在主线程上执行，是 UI 更新的关键机制：

@MainActor
class ViewModel: ObservableObject {
    @Published var users: [User] = []
    @Published var isLoading = false

    func loadUsers() async {
        isLoading = true
        do {
            users = try await userService.fetchAll()
        } catch {
            print("Failed to load: \(error)")
        }
        isLoading = false
    }
}

也可以对单个方法或属性标记：

actor DataProcessor {
    func process(data: Data) async -> ProcessedData {
        let result = heavyComputation(data)

        await MainActor.run {
            NotificationCenter.default.post(
                name: .processingComplete,
                object: result
            )
        }

        return result
    }
}

全局 Actor

自定义全局 actor 用于将分散的代码统一到同一个隔离域：

@globalActor
actor DatabaseActor {
    static let shared = DatabaseActor()
}

@DatabaseActor
class DatabaseManager {
    private var connection: DatabaseConnection?

    func connect(to url: URL) throws {
        connection = try DatabaseConnection(url: url)
    }

    func execute(_ query: String) throws -> [Row] {
        guard let conn = connection else {
            throw DatabaseError.notConnected
        }
        return try conn.execute(query)
    }
}

@DatabaseActor
func migrateDatabase() async throws {
    let manager = DatabaseManager()
    try manager.connect(to: dbURL)
    try manager.execute("ALTER TABLE users ADD COLUMN age INTEGER")
}

nonisolated

使用 nonisolated 关键字可以让 actor 中的方法脱离隔离，允许同步访问：

actor UserCache {
    let maxSize: Int
    private var cache: [String: User] = [:]

    init(maxSize: Int) {
        self.maxSize = maxSize
    }

    nonisolated var description: String {
        "UserCache(maxSize: \(maxSize))"
    }

    nonisolated func cacheKeyFor(id: String) -> String {
        "user_\(id)"
    }

    func store(_ user: User) {
        let key = cacheKeyFor(id: user.id)
        cache[key] = user
        if cache.count > maxSize {
            evictOldest()
        }
    }
}

let cache = UserCache(maxSize: 100)
print(cache.description) // 不需要 await
print(cache.maxSize)     // let 属性自动 nonisolated
访问修饰 需要 await 可访问
隔离方法/属性 是 可变状态
nonisolated 方法 否 仅不可变状态（let）
let 属性 否 自动 nonisolated

重入性（Reentrancy）

Actor 方法是可重入的——当方法在 await 处挂起时，其他任务可以进入该 actor 执行：

actor ImageLoader {
    private var cache: [URL: UIImage] = [:]

    func loadImage(from url: URL) async throws -> UIImage {
        if let cached = cache[url] {
            return cached
        }

        // ⚠️ 挂起点：此时其他任务可进入 actor
        let (data, _) = try await URLSession.shared.data(from: url)
        let image = UIImage(data: data)!

        // 需要重新检查：挂起期间状态可能已变
        cache[url] = cache[url] ?? image
        return cache[url]!
    }
}

提示： 在每个 await 之后，actor 的状态可能已被其他任务修改。永远不要假设 await 前后状态一致——这是 actor 编程最重要的原则。

sequenceDiagram
    participant T1 as Task 1
    participant T2 as Task 2
    participant A as ImageLoader
    T1->>A: loadImage(urlA)
    Note over A: 缓存未命中
    A->>A: await URLSession(挂起)
    T2->>A: loadImage(urlA)
    Note over A: 缓存未命中
    A->>A: await URLSession(挂起)
    Note over A: T1 恢复,写入缓存
    Note over A: T2 恢复,检查缓存

小结

  • Actor 通过隔离机制保护可变状态，同一时间只允许一个任务访问
  • 跨隔离边界访问 actor 成员必须使用 await，编译器在编译时检查
  • @MainActor 确保代码在主线程执行，是 UI 更新的标准方式
  • 全局 Actor 可以将分散的代码统一到同一隔离域
  • nonisolated 让方法脱离隔离，仅可访问不可变状态
  • Actor 方法是可重入的，await 前后状态可能变化，需要重新验证
