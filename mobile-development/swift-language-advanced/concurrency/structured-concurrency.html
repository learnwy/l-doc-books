结构化并发

概述

结构化并发（Structured Concurrency）是 Swift 并发模型的核心设计原则（SE-0304）。它确保并发任务的生命周期受其作用域约束——子任务在父作用域结束前必须完成，取消会自动传播，资源会被正确释放。这与传统的"发射即忘"式并发形成鲜明对比。

async let：静态并发
async let 允许同时启动多个异步操作，然后在需要结果时等待：


func loadDashboard() async throws -> Dashboard {
    async let profile = fetchProfile()
    async let posts = fetchRecentPosts()
    async let notifications = fetchNotifications()

    return try await Dashboard(
        profile: profile,
        posts: posts,
        notifications: notifications
    )
}
三个网络请求并发执行，而非顺序执行。对比顺序方式：


// 顺序执行：总时间 = T1 + T2 + T3
let profile = try await fetchProfile()
let posts = try await fetchRecentPosts()
let notifications = try await fetchNotifications()

// async let 并发：总时间 ≈ max(T1, T2, T3)
async let profile = fetchProfile()
async let posts = fetchRecentPosts()
async let notifications = fetchNotifications()


提示： async let 创建的子任务在离开作用域时，如果尚未等待会被自动取消。这就是"结构化"的含义——生命周期与作用域绑定。






TaskGroup：动态并发
当并发任务数量在编译时未知时，使用 TaskGroup：


func fetchAllImages(urls: [URL]) async throws -> [UIImage] {
    try await withThrowingTaskGroup(of: (Int, UIImage).self) { group in
        for (index, url) in urls.enumerated() {
            group.addTask {
                let (data, _) = try await URLSession.shared.data(from: url)
                guard let image = UIImage(data: data) else {
                    throw ImageError.invalidData
                }
                return (index, image)
            }
        }

        var images = Array<UIImage?>(repeating: nil, count: urls.count)
        for try await (index, image) in group {
            images[index] = image
        }
        return images.compactMap { $0 }
    }
}

任务取消
结构化并发的取消是协作式的——系统设置取消标志，任务需要主动检查：


func processLargeDataset(_ items: [Item]) async throws -> [Result] {
    try await withThrowingTaskGroup(of: Result.self) { group in
        for item in items {
            try Task.checkCancellation()

            group.addTask {
                try await process(item)
            }
        }

        var results: [Result] = []
        for try await result in group {
            results.append(result)
        }
        return results
    }
}
取消检查的两种方式：


// 方式一：抛出 CancellationError
try Task.checkCancellation()

// 方式二：检查标志，自行处理
if Task.isCancelled {
    return partialResults
}


任务优先级
Swift 任务有优先级层级，影响调度顺序：


Task(priority: .high) {
    await criticalWork()
}

Task(priority: .background) {
    await maintenanceWork()
}

await withTaskGroup(of: Void.self) { group in
    group.addTask(priority: .userInitiated) {
        await loadVisibleContent()
    }
    group.addTask(priority: .utility) {
        await prefetchNextPage()
    }
}

提示： Swift 支持优先级提升（Priority Escalation）——如果高优先级任务等待低优先级任务的结果，低优先级任务会被临时提升优先级。






作用域绑定任务
结构化并发的核心保证是作用域绑定：


func scopeExample() async throws {
    try await withThrowingTaskGroup(of: Void.self) { group in
        group.addTask { await task1() }
        group.addTask { await task2() }
        group.addTask { await task3() }
    }
    // 执行到这里时，所有子任务已完成或已取消
    print("All tasks finished")
}

限制并发度
TaskGroup 默认不限制并发子任务数量。可以手动限制：


func processWithLimit(
    items: [Item],
    maxConcurrency: Int = 4
) async throws -> [ProcessedItem] {
    try await withThrowingTaskGroup(of: ProcessedItem.self) { group in
        var results: [ProcessedItem] = []
        var iterator = items.makeIterator()

        for _ in 0..<min(maxConcurrency, items.count) {
            if let item = iterator.next() {
                group.addTask { try await process(item) }
            }
        }

        for try await result in group {
            results.append(result)
            if let item = iterator.next() {
                group.addTask { try await process(item) }
            }
        }

        return results
    }
}


小结
    

  • 结构化并发确保子任务的生命周期受父作用域约束，自动处理取消和清理
    • 

  • async let 用于编译时已知数量的并发任务，语法简洁
    • 

  • TaskGroup 用于动态数量的并发任务，结果类型必须统一
    • 

  • 取消是协作式的，任务需要主动调用 checkCancellation() 或检查 isCancelled
    • 

  • 任务优先级影响调度顺序，支持自动优先级提升
    • 

  • 可以通过手动控制 addTask 时机来限制并发度
    •
