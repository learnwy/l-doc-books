Sendable 与隔离

概述

Sendable 是 Swift 并发安全的类型级保证（SE-0302）。一个类型遵循 Sendable 协议，表示它的值可以安全地跨并发域传递——跨 actor 边界、跨任务边界。配合 @Sendable 闭包和严格并发检查（Strict Concurrency Checking），Swift 在编译时消除数据竞争。Swift 5.10 进一步引入了基于区域的隔离（Region-based Isolation），完善了并发安全模型。

Sendable 协议
Sendable 是一个标记协议（marker protocol），表示类型的值可以在并发域间安全共享：


struct Point: Sendable {
    let x: Double
    let y: Double
}

final class ImmutableConfig: Sendable {
    let apiKey: String
    let timeout: TimeInterval

    init(apiKey: String, timeout: TimeInterval) {
        self.apiKey = apiKey
        self.timeout = timeout
    }
}

    let name: String

enum NetworkState: Sendable {

提示： 在启用严格并发检查后，传递非 Sendable 类型跨隔离边界会产生编译警告或错误。这是 Swift 6 的默认行为。






@Sendable 闭包
@Sendable 标记闭包可以安全地在并发环境中使用：


func processInBackground(
    _ work: @Sendable @escaping () async -> Void
) {
    Task.detached {
        await work()
    }
}

actor DataStore {
    var items: [String] = []

    func process(transform: @Sendable (String) -> String) {
        items = items.map(transform)
    }
}
@Sendable 闭包有严格的捕获规则：


var mutableValue = 42

// ❌ 编译错误：@Sendable 闭包不能捕获可变变量
// Task { print(mutableValue) }

let immutableValue = 42
Task { print(immutableValue) } // ✅ 捕获不可变值

let sendableData = UserData(name: "Alice", age: 30, tags: [])
Task { print(sendableData) } // ✅ 捕获 Sendable 值


严格并发检查
Swift 提供三个级别的并发检查，通过编译器设置控制：


// Package.swift 中设置
.target(
    name: "MyApp",
    swiftSettings: [
        .enableExperimentalFeature("StrictConcurrency")
    ]
)

常见的并发检查场景：


class NonSendableCache {
    var data: [String: Any] = [:]
}

actor Worker {
    // ❌ complete 模式下：NonSendableCache 不是 Sendable
    // func process(cache: NonSendableCache) { }

    // ✅ 使用 Sendable 类型
    func process(data: [String: String]) {
        // ...
    }
}


@unchecked Sendable
对于你确信线程安全但编译器无法证明的类型，使用 @unchecked Sendable：


final class ThreadSafeCache<Key: Hashable, Value>: @unchecked Sendable {
    private let lock = NSLock()
    private var storage: [Key: Value] = [:]

    func get(_ key: Key) -> Value? {
        lock.lock()
        defer { lock.unlock() }
        return storage[key]
    }

    func set(_ key: Key, value: Value) {
        lock.lock()
        defer { lock.unlock() }
        storage[key] = value
    }
}


提示： @unchecked Sendable 绕过了编译器的安全检查。使用时必须确保类型真的是线程安全的，否则会引入数据竞争。






基于区域的隔离（Region-based Isolation）
Swift 5.10 和 Swift 6 引入了基于区域的隔离分析，能更精确地判断值是否可以安全传递：


func createAndSend() async {
    let config = NonSendableConfig()
    config.setup()

    // Swift 6：编译器分析 config 在发送后不再被访问
    // 即使 NonSendableConfig 不是 Sendable，也可以安全传递
    await actor.use(config)
    // config 在此之后不再被使用 → 安全
}
区域隔离的核心思想是所有权转移——如果一个值在发送到另一个隔离域后不再被当前上下文使用，即使它不是 Sendable，传递也是安全的。




迁移到完整并发安全
分步迁移策略：


// 步骤 1：将不可变值类型标记为 Sendable
struct AppConfig: Sendable {
    let environment: String
    let version: String
}

// 步骤 2：将内部同步的类标记为 @unchecked Sendable
final class Logger: @unchecked Sendable {
    private let queue = DispatchQueue(label: "logger")
    func log(_ message: String) {
        queue.async { print(message) }
    }
}

// 步骤 3：将可变共享状态迁移到 actor
actor SessionManager {
    private var sessions: [String: Session] = [:]

    func createSession(for user: String) -> Session {
        let session = Session(user: user)
        sessions[user] = session
        return session
    }
}

// 步骤 4：确保闭包是 @Sendable
func scheduleWork(_ work: @Sendable @escaping () async -> Void) {
    Task { await work() }
}


小结
    

  • Sendable 是标记协议，表示值可以安全跨并发域传递
    • 

  • 值类型（struct、enum）在属性都是 Sendable 时自动遵循；类需要显式声明且满足条件
    • 

  • @Sendable 闭包不能捕获可变变量，确保跨隔离边界安全
    • 

  • 严格并发检查有三个级别，complete 是 Swift 6 默认行为
    • 

  • @unchecked Sendable 绕过编译器检查，需自行保证线程安全
    • 

  • 区域隔离分析值在发送后是否还被使用，实现更精确的安全判断
