ARC 内部机制

概述

自动引用计数（Automatic Reference Counting, ARC）是 Swift 管理类实例内存的核心机制。与垃圾回收（GC）不同，ARC 在编译时插入 retain/release 调用，运行时无需暂停即可回收内存。理解 ARC 的内部实现——包括引用计数的存储方式、side table、weak/unowned 的区别以及循环引用的处理——是编写高效 Swift 代码的基础。

    }

var ref2 = node                   // 强引用计数 = 2
ref2 = nil                        // 强引用计数 = 1
node = nil                        // 强引用计数 = 0 → deinit


Side Table
当对象存在弱引用时，Swift 运行时会创建一个 side table（侧表）来管理弱引用：


Side table 的设计目的：


    

  • 将弱引用的管理从对象本身解耦
    • 

  • 对象可以在强引用为零时立即析构和释放属性内存
    • 

  • Side table 在弱引用和无主引用都为零时才释放
    • 





weak 与 unowned
class Person {
    let name: String
    var apartment: Apartment?

    init(name: String) { self.name = name }
    deinit { print("\(name) deinit") }
}

class Apartment {
    let unit: String
    weak var tenant: Person?

    init(unit: String) { self.unit = unit }
    deinit { print("Apartment \(unit) deinit") }
}

var john: Person? = Person(name: "John")
var apt: Apartment? = Apartment(unit: "4A")
john?.apartment = apt
apt?.tenant = john

john = nil  // John deinit，apt.tenant 自动置为 nil
apt = nil   // Apartment 4A deinit

class Customer {
    let name: String
    var card: CreditCard?
    init(name: String) { self.name = name }
}

class CreditCard {
    let number: String
    unowned let owner: Customer

    init(number: String, owner: Customer) {
        self.number = number
        self.owner = owner
    }
}


提示： 选择 weak 还是 unowned 的原则：如果引用的对象可能先于自身释放，用 weak；如果确定引用对象的生命周期至少与自身相同，用 unowned 以获得更好的性能。






循环引用
循环引用（Retain Cycle）是 ARC 最常见的内存泄漏来源：


class ViewController {
    var onComplete: (() -> Void)?

    func setup() {
        // ❌ 循环引用：self → onComplete → self
        onComplete = {
            self.dismiss()
        }

        // ✅ 使用 weak 打破循环
        onComplete = { [weak self] in
            self?.dismiss()
        }

        // ✅ 确定 self 不会提前释放时用 unowned
        onComplete = { [unowned self] in
            self.dismiss()
        }
    }

    func dismiss() { }
}
常见的循环引用场景：


// 场景 1：delegate 循环
class TableView {
    weak var delegate: TableViewDelegate?
}

// 场景 2：Timer 循环
class Scheduler {
    var timer: Timer?

    func start() {
        timer = Timer.scheduledTimer(withTimeInterval: 1, repeats: true) { [weak self] _ in
            self?.tick()
        }
    }

    func tick() { }
}

// 场景 3：NotificationCenter 循环
class Observer {
    var token: NSObjectProtocol?

    func observe() {
        token = NotificationCenter.default.addObserver(
            forName: .someNotification,
            object: nil,
            queue: .main
        ) { [weak self] notification in
            self?.handle(notification)
        }
    }

    func handle(_ notification: Notification) { }
}

小结
    

  • ARC 在编译时插入 retain/release，无运行时 GC 暂停
    • 

  • 引用计数存储在对象头部，64 位字段中包含强引用和无主引用计数
    • 

  • Side table 在存在弱引用时创建，将弱引用管理从对象解耦
    • 

  • weak 引用在对象释放后自动置 nil，需要 side table；unowned 不置零但更高效
    • 

  • 循环引用是最常见的内存泄漏，通过 [weak self] 或 [unowned self] 打破
    • 

  • 对象经历 Live → Deiniting → Deinited → Freed 四个生命周期阶段
