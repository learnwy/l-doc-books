Part I · iOSiOS 开发 简介架构 简介MVVM 模式

MVVM 模式

概述

MVVM（Model-View-ViewModel）是 iOS 开发中最主流的架构模式之一。它在 MVC 的基础上引入了 ViewModel 层，将表示逻辑（Presentation Logic）从 Controller/View 中抽离，解决了 MVC 中 Controller 过于臃肿的问题。

MVVM 的核心优势在于数据绑定——View 通过观察 ViewModel 的状态变化来自动更新 UI，不再需要手动同步。在 SwiftUI 中，@Published、@Observable 和 @StateObject 等属性包装器使 MVVM 成为天然契合的架构选择。在 UIKit 中，可以通过 Combine 框架或闭包回调实现类似效果。

核心概念
Model 层
Model 层与 MVC 中完全一致——纯数据结构和业务逻辑，不依赖任何 UI 框架：


struct Article: Identifiable, Codable {
    let id: Int
    var title: String
    var content: String
    var author: String
    var publishedAt: Date
    var isBookmarked: Bool
}

protocol ArticleRepository {
    func fetchArticles() async throws -> [Article]
    func toggleBookmark(id: Int) async throws -> Article
}

class RemoteArticleRepository: ArticleRepository {
    func fetchArticles() async throws -> [Article] {
        let url = URL(string: "https://api.example.com/articles")!
        let (data, _) = try await URLSession.shared.data(from: url)
        let decoder = JSONDecoder()
        decoder.dateDecodingStrategy = .iso8601
        return try decoder.decode([Article].self, from: data)
    }

    func toggleBookmark(id: Int) async throws -> Article {
        let url = URL(string: "https://api.example.com/articles/\(id)/bookmark")!
        var request = URLRequest(url: url)
        request.httpMethod = "POST"
        let (data, _) = try await URLSession.shared.data(for: request)
        return try JSONDecoder().decode(Article.self, from: data)
    }
}
ViewModel 层
ViewModel 是 MVVM 的核心。它持有 View 所需的全部状态，将 Model 数据转换为 View 可以直接使用的形式，并暴露用户操作的接口：


@Observable
class ArticleListViewModel {
    private let repository: ArticleRepository

    var articles: [Article] = []
    var isLoading = false
    var errorMessage: String?

    var bookmarkedCount: Int {
        articles.filter(\.isBookmarked).count
    }

    init(repository: ArticleRepository = RemoteArticleRepository()) {
        self.repository = repository
    }

    func loadArticles() async {
        isLoading = true
        errorMessage = nil
        do {
            articles = try await repository.fetchArticles()
        } catch {
            errorMessage = error.localizedDescription
        }
        isLoading = false
    }

    func toggleBookmark(for article: Article) async {
        do {
            let updated = try await repository.toggleBookmark(id: article.id)
            if let index = articles.firstIndex(where: { $0.id == updated.id }) {
                articles[index] = updated
            }
        } catch {
            errorMessage = "收藏失败：\(error.localizedDescription)"
        }
    }

    func formattedDate(for article: Article) -> String {
        let formatter = DateFormatter()
        formatter.dateStyle = .medium
        formatter.locale = Locale(identifier: "zh_CN")
        return formatter.string(from: article.publishedAt)
    }
}
View 层 —— SwiftUI 天然 MVVM
SwiftUI 的声明式语法与数据驱动机制天然适配 MVVM。View 只负责描述 UI 结构，通过绑定自动响应 ViewModel 状态变化：


struct ArticleListView: View {
    @State private var viewModel = ArticleListViewModel()

    var body: some View {
        NavigationStack {
            Group {
                if viewModel.isLoading {
                    ProgressView("加载中...")
                } else if let error = viewModel.errorMessage {
                    ContentUnavailableView(
                        "加载失败",
                        systemImage: "exclamationmark.triangle",
                        description: Text(error)
                    )
                } else {
                    articleList
                }
            }
            .navigationTitle("文章列表")
            .toolbar {
                ToolbarItem(placement: .topBarTrailing) {
                    Text("\(viewModel.bookmarkedCount) 已收藏")
                        .font(.caption)
                }
            }
            .task {
                await viewModel.loadArticles()
            }
        }
    }

    private var articleList: some View {
        List(viewModel.articles) { article in
            ArticleRow(
                article: article,
                formattedDate: viewModel.formattedDate(for: article),
                onBookmarkToggle: {
                    Task { await viewModel.toggleBookmark(for: article) }
                }
            )
        }
    }
}

struct ArticleRow: View {
    let article: Article
    let formattedDate: String
    let onBookmarkToggle: () -> Void

    var body: some View {
        VStack(alignment: .leading, spacing: 4) {
            Text(article.title)
                .font(.headline)
            Text(article.author)
                .font(.subheadline)
                .foregroundStyle(.secondary)
            HStack {
                Text(formattedDate)
                    .font(.caption)
                Spacer()
                Button(action: onBookmarkToggle) {
                    Image(systemName: article.isBookmarked ? "bookmark.fill" : "bookmark")
                }
            }
        }
        .padding(.vertical, 4)
    }
}
UIKit + Combine 实现 MVVM
在 UIKit 项目中，使用 Combine 的 @Published 属性实现数据绑定：


class ArticleListCombineViewModel: ObservableObject {
    @Published var articles: [Article] = []
    @Published var isLoading = false
    @Published var errorMessage: String?

    private let repository: ArticleRepository

    init(repository: ArticleRepository = RemoteArticleRepository()) {
        self.repository = repository
    }

    func loadArticles() {
        isLoading = true
        Task { @MainActor in
            do {
                articles = try await repository.fetchArticles()
            } catch {
                errorMessage = error.localizedDescription
            }
            isLoading = false
        }
    }
}

class ArticleListUIKitViewController: UIViewController {
    private let viewModel = ArticleListCombineViewModel()
    private let tableView = UITableView()
    private var cancellables = Set<AnyCancellable>()

    override func viewDidLoad() {
        super.viewDidLoad()
        bindViewModel()
        viewModel.loadArticles()
    }

    private func bindViewModel() {
        viewModel.$articles
            .receive(on: DispatchQueue.main)
            .sink { [weak self] _ in
                self?.tableView.reloadData()
            }
            .store(in: &cancellables)

        viewModel.$isLoading
            .receive(on: DispatchQueue.main)
            .sink { [weak self] loading in
                loading ? self?.showLoadingIndicator() : self?.hideLoadingIndicator()
            }
            .store(in: &cancellables)

        viewModel.$errorMessage
            .compactMap { $0 }
            .receive(on: DispatchQueue.main)
            .sink { [weak self] message in
                self?.showAlert(message: message)
            }
            .store(in: &cancellables)
    }

    private func showLoadingIndicator() {}
    private func hideLoadingIndicator() {}
    private func showAlert(message: String) {}
}
单元测试优势
ViewModel 不依赖 UI 框架，可以直接用 XCTest 进行快速、稳定的单元测试：


class MockArticleRepository: ArticleRepository {
    var stubbedArticles: [Article] = []
    var shouldFail = false

    func fetchArticles() async throws -> [Article] {
        if shouldFail { throw URLError(.badServerResponse) }
        return stubbedArticles
    }

    func toggleBookmark(id: Int) async throws -> Article {
        guard var article = stubbedArticles.first(where: { $0.id == id }) else {
            throw URLError(.badURL)
        }
        article.isBookmarked.toggle()
        return article
    }
}

@Test
func loadArticlesSuccess() async {
    let mock = MockArticleRepository()
    mock.stubbedArticles = [
        Article(id: 1, title: "Swift 并发", content: "...",
                author: "Alice", publishedAt: Date(), isBookmarked: false)
    ]

    let viewModel = ArticleListViewModel(repository: mock)
    await viewModel.loadArticles()

    #expect(viewModel.articles.count == 1)
    #expect(viewModel.articles.first?.title == "Swift 并发")
    #expect(viewModel.isLoading == false)
    #expect(viewModel.errorMessage == nil)
}

@Test
func loadArticlesFailure() async {
    let mock = MockArticleRepository()
    mock.shouldFail = true

    let viewModel = ArticleListViewModel(repository: mock)
    await viewModel.loadArticles()

    #expect(viewModel.articles.isEmpty)
    #expect(viewModel.errorMessage != nil)
}
使用方式
模式一：一个 View 对应一个 ViewModel
每个屏幕/页面拥有独立的 ViewModel，职责清晰：


struct ArticleDetailView: View {
    @State private var viewModel: ArticleDetailViewModel

    init(articleId: Int) {
        _viewModel = State(initialValue: ArticleDetailViewModel(articleId: articleId))
    }

    var body: some View {
        ScrollView {
            if let article = viewModel.article {
                VStack(alignment: .leading, spacing: 16) {
                    Text(article.title).font(.largeTitle)
                    Text(article.author).font(.subheadline)
                    Text(article.content).font(.body)
                }
                .padding()
            }
        }
        .task { await viewModel.load() }
    }
}
模式二：共享 ViewModel 用于父子视图
当多个视图需要共享同一份状态时，将 ViewModel 通过 Environment 注入：


@Observable
class CartViewModel {
    var items: [CartItem] = []

    var totalPrice: Double {
        items.reduce(0) { $0 + $1.price * Double($1.quantity) }
    }

    func addItem(_ item: CartItem) {
        if let index = items.firstIndex(where: { $0.id == item.id }) {
            items[index].quantity += 1
        } else {
            items.append(item)
        }
    }

    func removeItem(_ item: CartItem) {
        items.removeAll { $0.id == item.id }
    }
}

struct ShopView: View {
    @State private var cart = CartViewModel()

    var body: some View {
        TabView {
            ProductListView()
                .tabItem { Label("商品", systemImage: "list.bullet") }
            CartView()
                .tabItem { Label("购物车", systemImage: "cart") }
        }
        .environment(cart)
    }
}

每个功能模块包含自己的 View、ViewModel 和对应的测试文件。Model 和 Service 放在共享目录中供多个模块复用。


常见陷阱
陷阱一：ViewModel 引用 View 类型
ViewModel 必须完全独立于 UI 框架。引用 SwiftUI.View、UIKit 类型或 Color 会破坏可测试性：


@Observable
class BadViewModel {
    // var backgroundColor: Color = .red  ← 不应引用 SwiftUI 类型
}

@Observable
class GoodViewModel {
    var isHighlighted = false
}
在 View 层根据 ViewModel 的语义状态决定具体的颜色、字体等视觉表现。


陷阱二：ViewModel 变成"胖 Model"
将所有逻辑都塞进 ViewModel 会重蹈 Massive ViewController 的覆辙。业务规则应该留在 Model/Service 层，ViewModel 只负责表示逻辑（格式化、状态映射、用户操作路由）：


@Observable
class OrderViewModel {
    private let pricingService: PricingService
    private let orderService: OrderService

    var displayTotal: String {
        let total = pricingService.calculateTotal(for: items)
        return currencyFormatter.string(from: NSNumber(value: total)) ?? "¥0"
    }

    func placeOrder() async {
        await orderService.submit(items: items)
    }
}
陷阱三：Combine 中忘记切换到主线程
@Published 属性的变更必须在主线程发生，否则会触发运行时警告或崩溃：


viewModel.$articles
    .receive(on: DispatchQueue.main)
    .sink { [weak self] _ in
        self?.tableView.reloadData()
    }
    .store(in: &cancellables)
陷阱四：循环引用
ViewModel 持有闭包时，如果闭包捕获了持有 ViewModel 的对象，会产生循环引用：


viewModel.$errorMessage
    .sink { [weak self] message in
        self?.showAlert(message: message ?? "")
    }
    .store(in: &cancellables)
始终在闭包中使用 [weak self] 捕获列表。


小结
    

  • MVVM 通过引入 ViewModel 层将表示逻辑从 View/Controller 中分离，ViewModel 持有状态、转换数据、处理用户操作。
    • 

  • SwiftUI 天然适配 MVVM：@Observable / @StateObject + @Published 提供自动化的数据绑定机制。
    • 

  • UIKit 通过 Combine 的 $property → sink 管道实现响应式数据绑定。
    • 

  • ViewModel 的核心原则：不引用任何 UI 框架，只暴露数据和操作接口，使单元测试可以脱离 UI 直接运行。
    • 

  • 每个屏幕对应一个 ViewModel（一对一），共享状态可通过 Environment 注入。
    • 

  • 避免 ViewModel 膨胀——业务逻辑应归属 Model/Service，ViewModel 只承担表示逻辑。
    • 

  • 注意 Combine 中的主线程派发和循环引用问题。
