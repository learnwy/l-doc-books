Part I · iOSiOS 开发 简介架构 简介MVC 模式

MVC 模式

概述

MVC（Model-View-Controller）是 Apple 官方推荐的 Cocoa 应用架构模式，也是 iOS 开发中最基础、最广泛使用的设计模式。它将应用程序的代码按职责划分为三个核心层：Model（数据与业务逻辑）、View（用户界面）和 Controller（协调者）。

MVC 的核心价值在于关注点分离——每一层只负责自己的职责，降低耦合度，提升可维护性。然而在实际 iOS 开发中，由于 UIViewController 同时承担了 Controller 和部分 View 的职责，经常演变为"Massive View Controller"问题。理解 MVC 的本质及其局限性，是学习其他架构模式的前提。

核心概念
Model 层
Model 层负责数据的定义和业务逻辑的封装。它完全独立于 UI，不引用任何 UIKit 或 SwiftUI 框架：


struct User {
    let id: Int
    var name: String
    var email: String
    var avatar: URL?
}

class UserService {
    private var users: [User] = []

    func fetchUsers() async throws -> [User] {
        let url = URL(string: "https://api.example.com/users")!
        let (data, _) = try await URLSession.shared.data(from: url)
        return try JSONDecoder().decode([User].self, from: data)
    }

    func findUser(by id: Int) -> User? {
        users.first { $0.id == id }
    }
}
Model 层对外通过值类型（struct）暴露数据，通过服务类封装网络请求、数据库操作等副作用逻辑。


View 层
View 层负责将数据可视化并捕获用户交互。在 UIKit 中，View 应当是"哑"的——它不包含业务逻辑，只负责展示：


class UserCell: UITableViewCell {
    private let nameLabel = UILabel()
    private let emailLabel = UILabel()

    override init(style: UITableViewCell.CellStyle, reuseIdentifier: String?) {
        super.init(style: style, reuseIdentifier: reuseIdentifier)
        setupLayout()
    }

    required init?(coder: NSCoder) {
        fatalError("init(coder:) has not been implemented")
    }

    func configure(name: String, email: String) {
        nameLabel.text = name
        emailLabel.text = email
    }

    private func setupLayout() {
        let stack = UIStackView(arrangedSubviews: [nameLabel, emailLabel])
        stack.axis = .vertical
        stack.spacing = 4
        stack.translatesAutoresizingMaskIntoConstraints = false
        contentView.addSubview(stack)
        NSLayoutConstraint.activate([
            stack.leadingAnchor.constraint(equalTo: contentView.leadingAnchor, constant: 16),
            stack.trailingAnchor.constraint(equalTo: contentView.trailingAnchor, constant: -16),
            stack.topAnchor.constraint(equalTo: contentView.topAnchor, constant: 8),
            stack.bottomAnchor.constraint(equalTo: contentView.bottomAnchor, constant: -8)
        ])
    }
}
Controller 层
Controller 是 Model 和 View 之间的协调者。在 UIKit 中，UIViewController 就是 Controller 的实体：


class UserListViewController: UIViewController {
    private let tableView = UITableView()
    private let service = UserService()
    private var users: [User] = []

    override func viewDidLoad() {
        super.viewDidLoad()
        title = "用户列表"
        setupTableView()
        loadData()
    }

    private func setupTableView() {
        tableView.dataSource = self
        tableView.delegate = self
        tableView.register(UserCell.self, forCellReuseIdentifier: "UserCell")
        tableView.translatesAutoresizingMaskIntoConstraints = false
        view.addSubview(tableView)
        NSLayoutConstraint.activate([
            tableView.topAnchor.constraint(equalTo: view.topAnchor),
            tableView.leadingAnchor.constraint(equalTo: view.leadingAnchor),
            tableView.trailingAnchor.constraint(equalTo: view.trailingAnchor),
            tableView.bottomAnchor.constraint(equalTo: view.bottomAnchor)
        ])
    }

    private func loadData() {
        Task {
            do {
                users = try await service.fetchUsers()
                tableView.reloadData()
            } catch {
                showError(error)
            }
        }
    }

    private func showError(_ error: Error) {
        let alert = UIAlertController(
            title: "错误",
            message: error.localizedDescription,
            preferredStyle: .alert
        )
        alert.addAction(UIAlertAction(title: "确定", style: .default))
        present(alert, animated: true)
    }
}

extension UserListViewController: UITableViewDataSource {
    func tableView(_ tableView: UITableView, numberOfRowsInSection section: Int) -> Int {
        users.count
    }

    func tableView(_ tableView: UITableView, cellForRowAt indexPath: IndexPath) -> UITableViewCell {
        let cell = tableView.dequeueReusableCell(withIdentifier: "UserCell", for: indexPath) as! UserCell
        let user = users[indexPath.row]
        cell.configure(name: user.name, email: user.email)
        return cell
    }
}

extension UserListViewController: UITableViewDelegate {
    func tableView(_ tableView: UITableView, didSelectRowAt indexPath: IndexPath) {
        tableView.deselectRow(at: indexPath, animated: true)
        let user = users[indexPath.row]
        let detailVC = UserDetailViewController(user: user)
        navigationController?.pushViewController(detailVC, animated: true)
    }
}

使用方式
模式一：拆分 DataSource 和 Delegate
将 UITableViewDataSource 提取为独立对象，减轻 ViewController 的负担：


class UserListDataSource: NSObject, UITableViewDataSource {
    var users: [User] = []

    func tableView(_ tableView: UITableView, numberOfRowsInSection section: Int) -> Int {
        users.count
    }

    func tableView(_ tableView: UITableView, cellForRowAt indexPath: IndexPath) -> UITableViewCell {
        let cell = tableView.dequeueReusableCell(withIdentifier: "UserCell", for: indexPath) as! UserCell
        let user = users[indexPath.row]
        cell.configure(name: user.name, email: user.email)
        return cell
    }
}

class UserListViewController: UIViewController {
    private let tableView = UITableView()
    private let dataSource = UserListDataSource()

    override func viewDidLoad() {
        super.viewDidLoad()
        tableView.dataSource = dataSource
    }
}
模式二：使用 Child View Controller
将复杂页面拆分为多个 Child ViewController，每个负责独立的功能区域：


class ProfileViewController: UIViewController {
    private let headerVC = ProfileHeaderViewController()
    private let contentVC = ProfileContentViewController()

    override func viewDidLoad() {
        super.viewDidLoad()
        addChild(headerVC)
        view.addSubview(headerVC.view)
        headerVC.didMove(toParent: self)

        addChild(contentVC)
        view.addSubview(contentVC.view)
        contentVC.didMove(toParent: self)
    }
}
模式三：提取 Router 处理导航
将导航逻辑从 ViewController 中抽离到专用 Router：


protocol UserListRouter {
    func showUserDetail(_ user: User)
    func showSettings()
}

class DefaultUserListRouter: UserListRouter {
    weak var viewController: UIViewController?

    func showUserDetail(_ user: User) {
        let detailVC = UserDetailViewController(user: user)
        viewController?.navigationController?.pushViewController(detailVC, animated: true)
    }

    func showSettings() {
        let settingsVC = SettingsViewController()
        viewController?.present(settingsVC, animated: true)
    }
}
常见陷阱
陷阱一：Model 层引用 UIKit
Model 不应依赖任何 UI 框架。引入 UIImage 或 UIColor 会破坏 Model 的平台无关性，使其无法在测试或其他目标（如 macOS、watchOS）中复用：


struct Product {
    let name: String
    let price: Double
    // var image: UIImage  ← 错误：Model 不应依赖 UIKit
    var imageURL: URL?     // ✅ 使用 URL 替代
}
陷阱二：View 直接操作 Model
View 应该通过 Controller 间接访问 Model，而不是直接持有和修改 Model 实例。直接操作会绕过 Controller 的协调逻辑，导致状态不一致：


class BadUserCell: UITableViewCell {
    // var user: User?  ← 不推荐：View 持有完整 Model
    // func updateUser() { user?.name = "..." }  ← View 直接修改 Model
}

class GoodUserCell: UITableViewCell {
    func configure(name: String, email: String) {
        // ✅ View 只接收展示所需的原始值
    }
}
陷阱三：在 Controller 中硬编码业务逻辑
价格计算、数据校验等业务逻辑应该放在 Model 层，而非 Controller：


extension User {
    var displayName: String {
        name.isEmpty ? "匿名用户" : name
    }

    var isValid: Bool {
        !name.isEmpty && email.contains("@")
    }
}
陷阱四：忽视 ViewController 的生命周期
在错误的生命周期阶段执行操作（如在 init 中访问 view、在 viewDidLoad 中获取正确的布局尺寸）是常见的 MVC 错误：


class DetailViewController: UIViewController {
    override func viewDidLoad() {
        super.viewDidLoad()
        // ✅ 配置 UI 元素
    }

    override func viewDidLayoutSubviews() {
        super.viewDidLayoutSubviews()
        // ✅ 需要准确尺寸的操作
    }

    override func viewWillAppear(_ animated: Bool) {
        super.viewWillAppear(animated)
        // ✅ 刷新数据
    }
}
小结
    

  • MVC 将代码分为 Model（数据）、View（界面）、Controller（协调者）三层，是 iOS 开发最基础的架构模式。
    • 

  • Apple 的 Cocoa MVC 中 UIViewController 天然耦合了 View 和 Controller 的职责，容易产生 Massive View Controller 问题。
    • 

  • 通过拆分 DataSource、使用 Child ViewController、提取 Router 等重构策略，可以有效缓解 Controller 膨胀。
    • 

  • Model 层必须保持 UI 无关性，View 层应保持"哑"的特性，业务逻辑应归属 Model 而非 Controller。
    • 

  • MVC 适合小型项目和快速原型；当项目规模增长时，应考虑迁移到 MVVM、Clean Architecture 等更可扩展的模式。
    • 

  • 理解 MVC 的优势与局限是掌握所有 iOS 架构模式的基础。
