Part I · iOSiOS 开发 简介实践 简介调试技巧

调试技巧

概述

调试是 iOS 开发中最日常的技能——从定位崩溃原因到分析内存泄漏，从检查 UI 布局到模拟弱网环境，熟练的调试技巧直接影响开发效率。Xcode 提供了 LLDB 调试器、Memory Graph、View Debugger 等强大工具；配合 Console.app 和 Network Link Conditioner，可以覆盖绝大多数调试场景。



一、LLDB 命令
要点
LLDB 是 Xcode 内置的调试器。在断点暂停时，可以在 Debug Console 中输入命令来检查和修改程序状态。






命令
用途
示例





po
打印对象描述（debugDescription）
po user




p
打印值（带类型信息）
p user.name




v
直接读取变量（不执行代码，更快）
v user




bt
打印调用栈
bt / bt all




fr v
打印当前栈帧的所有局部变量
fr v




fr s
切换栈帧
fr s 3




expr
执行表达式（可修改变量）
expr user.name = "Test"




thread return
强制函数返回指定值
thread return false




watchpoint
监视变量变化
watchpoint set variable count





示例代码
在调试器中动态修改 UI 状态，无需重新编译：


@MainActor
class DebugHelper {
    static func printViewHierarchy() {
        let windows = UIApplication.shared.connectedScenes
            .compactMap { $0 as? UIWindowScene }
            .flatMap { $0.windows }

        for window in windows {
            Self.printView(window, indent: 0)
        }
    }

    private static func printView(_ view: UIView, indent: Int) {
        let prefix = String(repeating: "  ", count: indent)
        let frame = view.frame
        let type = String(describing: type(of: view))
        print("\(prefix)\(type) - frame: \(frame), hidden: \(view.isHidden)")
        for subview in view.subviews {
            printView(subview, indent: indent + 1)
        }
    }
}
LLDB 实用技巧：


// 在 LLDB 中调用 Swift 方法
(lldb) expr -l swift -- import UIKit
(lldb) expr -l swift -- UIApplication.shared.windows.first?.rootViewController

// 打印 JSON 格式的 Codable 对象
(lldb) po try! JSONEncoder().encode(user).prettyPrinted
(lldb) po String(data: try! JSONEncoder().encode(user), encoding: .utf8)!

// 修改视图背景色（实时生效）
(lldb) expr view.backgroundColor = UIColor.red
(lldb) expr CATransaction.flush()

// 暂停后继续执行到指定行
(lldb) thread until 42

// 打印所有线程的调用栈
(lldb) bt all

闭包中的循环引用检测模式：


class NetworkManager {
    var completionHandler: ((Data) -> Void)?
    private var session: URLSession?

    func startRequest(url: URL) {
        session = URLSession(configuration: .default)
        let task = session?.dataTask(with: url) { [weak self] data, _, _ in
            guard let data else { return }
            self?.completionHandler?(data)
        }
        task?.resume()
    }

    deinit {
        session?.invalidateAndCancel()
        print("NetworkManager deallocated ✅")
    }
}

示例代码
在代码中做好网络异常处理：


@MainActor
class DataLoader: ObservableObject {
    @Published var state: LoadState = .idle

    enum LoadState: Equatable {
        case idle
        case loading
        case loaded(String)
        case error(String)
        case offline

        static func == (lhs: Self, rhs: Self) -> Bool {
            switch (lhs, rhs) {
            case (.idle, .idle), (.loading, .loading), (.offline, .offline):
                return true
            case (.loaded(let a), .loaded(let b)):
                return a == b
            case (.error(let a), .error(let b)):
                return a == b
            default:
                return false
            }
        }
    }

    func load(from url: URL) async {
        state = .loading
        do {
            let (data, response) = try await URLSession.shared.data(from: url)
            guard let http = response as? HTTPURLResponse, http.statusCode == 200 else {
                state = .error("服务器错误")
                return
            }
            let text = String(data: data, encoding: .utf8) ?? ""
            state = .loaded(text)
        } catch let error as URLError where error.code == .notConnectedToInternet {
            state = .offline
        } catch let error as URLError where error.code == .timedOut {
            state = .error("请求超时，请检查网络连接")
        } catch {
            state = .error(error.localizedDescription)
        }
    }
}


六、Console.app 与统一日志
要点
Apple 的统一日志系统（Unified Logging / os.Logger）是 print() 的专业替代方案——支持日志分级、隐私控制、性能极佳且可在 Console.app 中实时过滤查看。


示例代码
import os

extension Logger {
    static let networking = Logger(subsystem: Bundle.main.bundleIdentifier!, category: "networking")
    static let storage = Logger(subsystem: Bundle.main.bundleIdentifier!, category: "storage")
    static let ui = Logger(subsystem: Bundle.main.bundleIdentifier!, category: "ui")
}

struct NetworkLogger {
    static func logRequest(_ request: URLRequest) {
        Logger.networking.info("→ \(request.httpMethod ?? "GET") \(request.url?.absoluteString ?? "nil")")
    }

    static func logResponse(_ response: HTTPURLResponse, data: Data, duration: TimeInterval) {
        let status = response.statusCode
        let size = ByteCountFormatter.string(fromByteCount: Int64(data.count), countStyle: .memory)
        if (200..<300).contains(status) {
            Logger.networking.info("← \(status) [\(size)] in \(String(format: "%.0f", duration * 1000))ms")
        } else {
            Logger.networking.error("← \(status) [\(size)] in \(String(format: "%.0f", duration * 1000))ms")
        }
    }

    static func logError(_ error: Error, context: String) {
        Logger.networking.fault("❌ [\(context)] \(error.localizedDescription)")
    }
}

七、崩溃日志分析
要点
崩溃日志（Crash Log）是定位线上问题的关键。崩溃日志需要**符号化（Symbolication）**后才能看到具体的函数名和行号。


崩溃日志来源：

获取方式

设备

第三方
Firebase Crashlytics、Sentry 等





示例代码
手动符号化崩溃日志：


# 查找 dSYM 文件
mdfind "com_apple_xcode_dsym_uuids == '<UUID>'"

# 使用 atos 符号化单个地址
atos -arch arm64 -o MyApp.app.dSYM/Contents/Resources/DWARF/MyApp \
  -l 0x100000000 0x100001234

# 使用 symbolicatecrash 完整符号化
export DEVELOPER_DIR="/Applications/Xcode.app/Contents/Developer"
/Applications/Xcode.app/Contents/SharedFrameworks/DVTFoundation.framework/\
Versions/A/Resources/symbolicatecrash crash.ips MyApp.app.dSYM > symbolicated.crash
在代码中设置全局异常处理器捕获未处理的异常：


func setupCrashReporting() {
    NSSetUncaughtExceptionHandler { exception in
        let name = exception.name.rawValue
        let reason = exception.reason ?? "Unknown"
        let stack = exception.callStackSymbols.joined(separator: "\n")
        let crashInfo = "Exception: \(name)\nReason: \(reason)\nStack:\n\(stack)"
        Logger.networking.fault("\(crashInfo)")
    }

    signal(SIGABRT) { _ in
        Logger.networking.fault("SIGABRT received")
    }

    signal(SIGSEGV) { _ in
        Logger.networking.fault("SIGSEGV received")
    }
}

小结
    

  • LLDB 是最强大的调试工具——po 打印对象、expr 修改变量、bt 查看调用栈，可以在运行时动态修改程序状态。
    • 

  • 条件断点 + Action 可以在不暂停程序的情况下自动打印日志，替代散布在代码中的 print。
    • 

  • 符号断点用于在系统方法上设置断点，如 UIViewAlertForUnsatisfiableConstraints 检测 AutoLayout 冲突。
    • 

  • 异常断点和 Runtime Issue 断点可以在异常/线程问题发生的第一现场暂停，快速定位根因。
    • 

  • Memory Graph 可视化对象引用关系，紫色 ⚠️ 标记内存泄漏，检查引用链定位循环引用。
    • 

  • View Debugger 以 3D 视图展示 UI 层级，诊断布局问题、视图遮挡和约束冲突。
    • 

  • Network Link Conditioner 模拟弱网环境，验证 App 在网络异常时的用户体验。
    • 

  • os.Logger 替代 print()——支持分级、隐私控制、高性能，在 Console.app 中按 subsystem/category 过滤。
    • 

  • 崩溃日志需要 dSYM 符号化才能看到函数名和行号，确保 Archive 时保留 dSYM 文件。
    •
