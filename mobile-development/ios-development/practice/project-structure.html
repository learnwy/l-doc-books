工程结构最佳实践

概述

良好的工程结构是 iOS 项目可维护性和团队协作效率的基础。随着项目规模增长，如果缺乏清晰的目录组织、模块划分和环境管理策略，代码会迅速变得混乱——编译时间变长、合并冲突频发、新成员上手困难。本文涵盖目录命名约定、Feature-based vs Layer-based 组织方式、SPM 模块化、多 Target 管理、共享代码策略和 xcconfig 环境管理。

要点
统一的命名约定让团队成员能快速定位文件，减少沟通成本：

便于 Mock 和测试

protocol UserRepository {

二、Feature-based vs Layer-based 组织
要点
两种主流目录组织方式各有适用场景：


Layer-based（按层分组）：


MyApp/
├── Models/
│   ├── User.swift
│   ├── Order.swift
│   └── Product.swift
├── Views/
│   ├── UserProfileView.swift
│   ├── OrderListView.swift
│   └── ProductDetailView.swift
├── ViewModels/
│   ├── UserProfileViewModel.swift
│   ├── OrderListViewModel.swift
│   └── ProductDetailViewModel.swift
├── Services/
│   ├── AuthService.swift
│   ├── OrderService.swift
│   └── ProductService.swift
└── Resources/
    ├── Assets.xcassets
    └── Localizable.xcstrings
Feature-based（按功能分组）：


MyApp/
├── Features/
│   ├── Auth/
│   │   ├── LoginView.swift
│   │   ├── LoginViewModel.swift
│   │   ├── RegisterView.swift
│   │   └── AuthService.swift
│   ├── Profile/
│   │   ├── ProfileView.swift
│   │   ├── ProfileViewModel.swift
│   │   └── ProfileService.swift
│   └── Orders/
│       ├── OrderListView.swift
│       ├── OrderDetailView.swift
│       ├── OrderViewModel.swift
│       └── Order.swift
├── Shared/
│   ├── Components/
│   ├── Extensions/
│   └── Utilities/
├── Core/
│   ├── Networking/
│   ├── Storage/
│   └── DI/
└── Resources/
    ├── Assets.xcassets
    └── Localizable.xcstrings
示例代码
Feature-based 结构中，每个功能模块自包含，便于独立开发和测试：


enum AuthFeature {
    struct LoginView: View {
        @StateObject private var viewModel = LoginViewModel()

        var body: some View {
            VStack(spacing: 16) {
                TextField("邮箱", text: $viewModel.email)
                    .textFieldStyle(.roundedBorder)
                    .textContentType(.emailAddress)

                SecureField("密码", text: $viewModel.password)
                    .textFieldStyle(.roundedBorder)

                Button("登录") {
                    Task { await viewModel.login() }
                }
                .buttonStyle(.borderedProminent)
                .disabled(viewModel.isLoading)
            }
            .padding()
        }
    }
}


三、SPM 模块化
要点
Swift Package Manager 是 Apple 推荐的模块化方案。将独立功能拆分为本地 Package，可以缩短编译时间、强制依赖方向、提升代码复用率：


示例代码
本地 Package 的 Package.swift：


// swift-tools-version: 5.9
import PackageDescription

let package = Package(
    name: "CoreKit",
    platforms: [.iOS(.v16)],
    products: [
        .library(name: "CoreKit", targets: ["CoreKit"]),
        .library(name: "NetworkKit", targets: ["NetworkKit"]),
        .library(name: "StorageKit", targets: ["StorageKit"]),
    ],
    dependencies: [],
    targets: [
        .target(
            name: "CoreKit",
            dependencies: ["NetworkKit", "StorageKit"]
        ),
        .target(name: "NetworkKit"),
        .target(name: "StorageKit"),
        .testTarget(
            name: "CoreKitTests",
            dependencies: ["CoreKit"]
        ),
        .testTarget(
            name: "NetworkKitTests",
            dependencies: ["NetworkKit"]
        ),
    ]
)
在主 App 中引入本地 Package：Xcode → File → Add Package Dependencies → Add Local...


import NetworkKit

struct APIClient {
    private let session: NetworkSession

    init(session: NetworkSession = .shared) {
        self.session = session
    }

    func fetchUsers() async throws -> [User] {
        let request = NetworkRequest(
            path: "/users",
            method: .get
        )
        return try await session.execute(request)
    }
}


四、多 Target 管理
要点
一个 Xcode 项目可能包含多个 Target——主 App、Widget Extension、Notification Extension、Intent Extension 等。合理管理多 Target 的关键是：






策略
说明





App Groups
多 Target 间共享数据（UserDefaults、文件）




共享 Framework
公共代码抽取到 Framework Target 或 SPM Package




独立 Bundle ID
每个 Target 使用独立的 Bundle ID（主 App 的子 ID）




独立签名
每个 Target 需要独立的 Provisioning Profile





示例代码
通过 App Groups 在主 App 和 Widget 之间共享数据：


import WidgetKit

let appGroupID = "group.com.myteam.app"

struct SharedDataManager {
    private let defaults: UserDefaults

    init() {
        guard let defaults = UserDefaults(suiteName: appGroupID) else {
            fatalError("App Group not configured")
        }
        self.defaults = defaults
    }

    var lastSyncDate: Date? {
        get { defaults.object(forKey: "lastSyncDate") as? Date }
        set { defaults.set(newValue, forKey: "lastSyncDate") }
    }

    var cachedCount: Int {
        get { defaults.integer(forKey: "cachedCount") }
        set {
            defaults.set(newValue, forKey: "cachedCount")
            WidgetCenter.shared.reloadAllTimelines()
        }
    }
}


五、共享代码策略
要点
在多 Target 或多项目间共享代码有几种常见策略：






策略
适用场景
优缺点





SPM 本地 Package
同一项目内的模块化
✅ 编译快、依赖清晰；❌ 仅限本项目




SPM 远程 Package
跨项目复用
✅ 版本管理；❌ 需维护独立仓库




Framework Target
传统方案
✅ Xcode 原生支持；❌ 配置复杂




源文件引用
简单共享
✅ 零配置；❌ 无法控制访问级别





示例代码
使用 Swift 的访问控制确保模块边界清晰：


public protocol StorageService: Sendable {
    func save<T: Codable>(_ value: T, forKey key: String) throws
    func load<T: Codable>(forKey key: String, as type: T.Type) throws -> T?
    func remove(forKey key: String)
}

public final class UserDefaultsStorage: StorageService, @unchecked Sendable {
    private let defaults: UserDefaults
    private let encoder = JSONEncoder()
    private let decoder = JSONDecoder()

    public init(suiteName: String? = nil) {
        self.defaults = suiteName.flatMap { UserDefaults(suiteName: $0) } ?? .standard
    }

    public func save<T: Codable>(_ value: T, forKey key: String) throws {
        let data = try encoder.encode(value)
        defaults.set(data, forKey: key)
    }

    public func load<T: Codable>(forKey key: String, as type: T.Type) throws -> T? {
        guard let data = defaults.data(forKey: key) else { return nil }
        return try decoder.decode(type, from: data)
    }

    public func remove(forKey key: String) {
        defaults.removeObject(forKey: key)
    }
}


六、xcconfig 环境管理
要点
xcconfig 文件是管理 Xcode Build Settings 的最佳方式——可读性好、支持版本控制、支持继承和条件配置：


示例代码
// Base.xcconfig
PRODUCT_NAME = MyApp
PRODUCT_BUNDLE_IDENTIFIER = com.myteam.app$(BUNDLE_ID_SUFFIX)
MARKETING_VERSION = 1.0.0
CURRENT_PROJECT_VERSION = 1
SWIFT_VERSION = 5.9
IPHONEOS_DEPLOYMENT_TARGET = 16.0
SWIFT_ACTIVE_COMPILATION_CONDITIONS = $(inherited)

// Debug.xcconfig
#include "Base.xcconfig"
BUNDLE_ID_SUFFIX = .debug
PRODUCT_NAME = MyApp Dev
SWIFT_ACTIVE_COMPILATION_CONDITIONS = $(inherited) DEBUG
API_BASE_URL = https:\/\/api-dev.example.com
CODE_SIGN_IDENTITY = Apple Development
PROVISIONING_PROFILE_SPECIFIER =

// Release.xcconfig
#include "Base.xcconfig"
BUNDLE_ID_SUFFIX =
PRODUCT_NAME = MyApp
SWIFT_ACTIVE_COMPILATION_CONDITIONS = $(inherited) RELEASE
API_BASE_URL = https:\/\/api.example.com
CODE_SIGN_IDENTITY = Apple Distribution
PROVISIONING_PROFILE_SPECIFIER = MyApp_AppStore
SWIFT_OPTIMIZATION_LEVEL = -O
在 Info.plist 中引用 xcconfig 变量：


<key>API_BASE_URL</key>
<string>$(API_BASE_URL)</string>
<key>CFBundleDisplayName</key>
<string>$(PRODUCT_NAME)</string>
在代码中安全读取：


enum Configuration {
    enum Error: Swift.Error {
        case missingKey(String)
        case invalidValue(String)
    }

    static func value<T>(for key: String) throws -> T where T: LosslessStringConvertible {
        guard let object = Bundle.main.object(forInfoDictionaryKey: key) else {
            throw Error.missingKey(key)
        }
        guard let string = object as? String, let value = T(string) else {
            throw Error.invalidValue(key)
        }
        return value
    }

    static var apiBaseURL: URL {
        let urlString: String = try! value(for: "API_BASE_URL")
        return URL(string: urlString)!
    }
}

小结
    

  • 命名约定统一全团队——文件名 = 类型名、PascalCase 目录、extension 用 + 后缀。
    • 

  • 小项目用 Layer-based，中大型项目用 Feature-based——按功能而非层次组织代码。
    • 

  • SPM 本地 Package 是最推荐的模块化方案——编译隔离、依赖方向可控、零配置开销。
    • 

  • 多 Target 通过 App Groups 共享数据，每个 Target 独立 Bundle ID 和签名。
    • 

  • 共享代码优先用 SPM Package（本地或远程），善用 Swift 访问控制（public / internal）定义模块边界。
    • 

  • xcconfig 是管理多环境配置的最佳实践——支持继承、可版本控制、比 Xcode GUI 更可靠。
    • 

  • 根据项目规模选择合适的复杂度——不要过早引入重量级架构。
