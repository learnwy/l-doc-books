声明式 UI 入门

概述

SwiftUI 是 Apple 在 WWDC 2019 推出的声明式 UI 框架，彻底改变了 iOS 应用的构建方式。与传统 UIKit 的命令式编程不同，SwiftUI 让开发者描述界面应该是什么样子，而非如何一步步构建界面。

本节将学习 SwiftUI 的核心理念、App/Scene/View 层级结构、@main 入口、Preview 实时预览，以及声明式与命令式范式的本质区别。

基础用法
声明式 vs 命令式：对比理解
用一个简单的「显示标签 + 按钮」界面来对比两种范式。


UIKit（命令式）：


import UIKit

class ViewController: UIViewController {
    private let label = UILabel()
    private let button = UIButton(type: .system)

    override func viewDidLoad() {
        super.viewDidLoad()

        label.text = "Hello, UIKit!"
        label.font = .systemFont(ofSize: 24, weight: .bold)
        label.translatesAutoresizingMaskIntoConstraints = false
        view.addSubview(label)

        button.setTitle("点击我", for: .normal)
        button.translatesAutoresizingMaskIntoConstraints = false
        button.addTarget(self, action: #selector(buttonTapped), for: .touchUpInside)
        view.addSubview(button)

        NSLayoutConstraint.activate([
            label.centerXAnchor.constraint(equalTo: view.centerXAnchor),
            label.centerYAnchor.constraint(equalTo: view.centerYAnchor, constant: -20),
            button.centerXAnchor.constraint(equalTo: view.centerXAnchor),
            button.topAnchor.constraint(equalTo: label.bottomAnchor, constant: 16)
        ])
    }

    @objc private func buttonTapped() {
        label.text = "被点击了！"
    }
}
SwiftUI（声明式）：


import SwiftUI

struct ContentView: View {
    @State private var message = "Hello, SwiftUI!"

    var body: some View {
        VStack(spacing: 16) {
            Text(message)
                .font(.title)
                .bold()

            Button("点击我") {
                message = "被点击了！"
            }
        }
    }
}
两种范式的核心区别：






维度
命令式 (UIKit)
声明式 (SwiftUI)





关注点
怎么做 — 逐步操作 UI
是什么 — 描述 UI




状态管理
手动同步 Model 与 View
框架自动驱动 UI 更新




布局
AutoLayout 约束
组合式布局容器




代码量
多（创建 + 配置 + 约束）
少（声明即完成）




可预览
需要运行模拟器
Xcode Canvas 实时预览





App / Scene / View 三层结构
SwiftUI 应用由三层嵌套结构组成：


import SwiftUI

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}
    

  • App：应用的顶层入口，使用 @main 标注。整个应用只有一个 App 实例。
    • 

  • Scene：管理一组视图的生命周期。WindowGroup 是最常用的 Scene，在 iOS 上对应一个窗口。
    • 

  • View：界面的基本构建单元。所有可见元素都是 View。
    • 



body 属性
每个 View 都必须实现 body 计算属性，返回 some View：


struct GreetingView: View {
    var body: some View {
        Text("你好，世界")
    }
}
some View 是一个不透明返回类型（Opaque Return Type），意味着编译器知道具体类型，但外部调用者只知道它遵循 View 协议。这让 SwiftUI 能在编译期优化视图类型，同时保持 API 的简洁性。


@main 入口
@main 特性标记应用程序的入口点，替代了传统的 main.swift 文件和 UIApplicationDelegate：


@main
struct TodoApp: App {
    @StateObject private var store = TodoStore()

    var body: some Scene {
        WindowGroup {
            TodoListView()
                .environmentObject(store)
        }
    }
}
进阶用法
多 Scene 支持
在 iPadOS 和 macOS 上，可以定义多个 Scene：


@main
struct MultiSceneApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }

        #if os(macOS)
        Settings {
            SettingsView()
        }

        Window("帮助", id: "help") {
            HelpView()
        }
        #endif
    }
}
Preview 实时预览
SwiftUI 的 Preview 机制允许在不运行模拟器的情况下即时查看界面效果：


#Preview {
    ContentView()
}

#Preview("深色模式") {
    ContentView()
        .preferredColorScheme(.dark)
}

#Preview("大字体") {
    ContentView()
        .environment(\.dynamicTypeSize, .xxxLarge)
}
Swift 5.9 引入了 #Preview 宏，比旧版 PreviewProvider 更加简洁。可以同时定义多个 Preview 来测试不同的环境配置。


声明式范式的工作原理
SwiftUI 的核心循环：


    

  1. 状态变化：用户交互或外部事件触发 @State 等属性改变
    2. 

  2. 重新求值：SwiftUI 调用受影响视图的 body 属性
    3. 

  3. 差异对比：框架将新的视图描述与旧的进行 diff
    4. 

  4. 增量更新：只更新实际发生变化的 UI 部分
    5. 



这意味着开发者只需关心「状态 → UI」的映射关系，不用手动处理 UI 的增删改操作。


条件渲染与视图组合
struct AdaptiveView: View {
    @State private var isLoggedIn = false
    @State private var showDetail = false

    var body: some View {
        VStack {
            if isLoggedIn {
                Text("欢迎回来！")
                    .font(.title)

                if showDetail {
                    DetailPanel()
                }
            } else {
                LoginView(onLogin: {
                    isLoggedIn = true
                })
            }

            Toggle("显示详情", isOn: $showDetail)
                .padding()
        }
    }
}
完整示例
一个结合上述概念的完整迷你应用：


import SwiftUI

@main
struct CounterApp: App {
    var body: some Scene {
        WindowGroup {
            CounterView()
        }
    }
}

struct CounterView: View {
    @State private var count = 0
    @State private var history: [Int] = []

    var body: some View {
        NavigationStack {
            VStack(spacing: 24) {
                Text("\(count)")
                    .font(.system(size: 72, weight: .bold, design: .rounded))
                    .foregroundStyle(count >= 0 ? .blue : .red)

                HStack(spacing: 32) {
                    Button(action: { updateCount(-1) }) {
                        Image(systemName: "minus.circle.fill")
                            .font(.system(size: 44))
                    }

                    Button(action: { updateCount(1) }) {
                        Image(systemName: "plus.circle.fill")
                            .font(.system(size: 44))
                    }
                }

                Button("重置") {
                    count = 0
                    history.removeAll()
                }
                .buttonStyle(.bordered)

                if !history.isEmpty {
                    VStack(alignment: .leading, spacing: 8) {
                        Text("操作历史")
                            .font(.headline)

                        ForEach(history.indices, id: \.self) { index in
                            Text("第 \(index + 1) 步: \(history[index])")
                                .font(.caption)
                                .foregroundStyle(.secondary)
                        }
                    }
                    .frame(maxWidth: .infinity, alignment: .leading)
                    .padding()
                }
            }
            .padding()
            .navigationTitle("计数器")
        }
    }

    private func updateCount(_ delta: Int) {
        count += delta
        history.append(count)
    }
}

#Preview {
    CounterView()
}

#Preview("深色模式") {
    CounterView()
        .preferredColorScheme(.dark)
}
最佳实践




✅ 推荐做法
❌ 避免做法





保持 body 简洁，提取子视图
在单个 body 中堆砌数百行




使用 some View 作为返回类型
手动拼写具体的泛型类型




利用 #Preview 测试多种环境
每次修改都启动模拟器验证




让状态驱动 UI，避免手动刷新
试图用命令式思维操作视图




优先使用 SwiftUI 原生组件
不必要地桥接 UIKit 组件




用 @main 统一管理应用入口
保留过时的 AppDelegate 生命周期





关于 body 的性能要点：


    

  • body 应该是纯函数：相同的状态应产生相同的视图描述
    • 

  • 不要在 body 中执行耗时操作（网络请求、文件 IO）
    • 

  • SwiftUI 可能在任意时刻多次调用 body，不要依赖调用次数
    • 



小结
    

  • SwiftUI 采用声明式范式，开发者描述「界面是什么」而非「如何构建」
    • 

  • 应用结构为三层嵌套：App → Scene → View
    • 

  • @main 标注应用入口，替代传统的 AppDelegate
    • 

  • 每个 View 通过 body 属性返回 some View
    • 

  • 状态变化自动触发 UI 更新，框架负责 diff 与增量渲染
    • 

  • #Preview 宏支持在 Xcode Canvas 中实时预览多种环境配置
    • 

  • SwiftUI 相比 UIKit 大幅减少样板代码，提升开发效率
    • 

  • 保持 body 为纯函数是性能优化的基础
    •
