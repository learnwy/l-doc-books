代码签名与描述文件

概述

代码签名是 iOS 应用从开发到分发的信任基石——Apple 通过签名机制确保每个安装到设备上的 App 都来自已识别的开发者，且代码未被篡改。理解证书（Certificate）、描述文件（Provisioning Profile）和权限声明（Entitlements）三者的关系，是团队协作开发和自动化构建的前提。

签名流程涉及 Apple Developer Portal、本地 Keychain 和 Xcode 三方交互，手动管理容易出错。fastlane match 等工具将证书和描述文件集中存储在 Git 仓库或云端，实现团队共享和 CI/CD 自动化。

每个证书由一对公私钥组成——私钥保存在本地 Keychain，公钥以 .cer 形式上传到 Apple Portal。创建证书时需要先生成 CSR（Certificate Signing Request）。

Entitlements（权限声明）
Entitlements 是嵌入到签名中的键值对，声明 App 需要的系统能力：


// MyApp.entitlements (XML plist)
// 常见权限项：
// com.apple.developer.applesignin        → Sign in with Apple
// com.apple.security.application-groups   → App Groups 共享数据
// aps-environment                         → 推送通知 (development/production)
// com.apple.developer.associated-domains  → Universal Links
// keychain-access-groups                  → Keychain 共享
Xcode 自动签名 vs 手动签名
自动签名在 Xcode 的 Signing & Capabilities 中启用 Automatically manage signing，Xcode 会根据 Team 和 Bundle ID 自动创建或更新所需的证书和描述文件。手动签名需要在 Apple Developer Portal 中提前创建好对应的描述文件，然后在 Xcode 中手动选择。


企业分发
Enterprise 证书（Apple Developer Enterprise Program）允许绑定不限设备数量的 In-House 描述文件，用于公司内部分发，无需经过 App Store 审核。但 Apple 对企业证书的滥用监管严格，一旦检测到面向公众分发可能吊销证书。


fastlane match
fastlane match 将证书和描述文件集中存储在 Git 仓库（或 Google Cloud Storage / S3），团队成员和 CI 机器共享同一套签名资源：


# Matchfile
git_url("https://github.com/myteam/certificates")
storage_mode("git")
type("appstore")
app_identifier(["com.myteam.app", "com.myteam.app.widget"])
username("ci@myteam.com")
# 团队成员首次同步
fastlane match development
fastlane match appstore

# CI 环境（只读模式，不创建新证书）
fastlane match appstore --readonly
实战演示
一个完整的签名配置示例——从命令行验证签名信息：


# 查看已安装的签名身份
security find-identity -v -p codesigning

# 查看 .ipa 的签名信息
codesign -dv --verbose=4 MyApp.app

# 查看描述文件内容
security cms -D -i embedded.mobileprovision

# 重新签名（替换描述文件后）
codesign -f -s "Apple Distribution: My Team (TEAMID)" \
  --entitlements MyApp.entitlements \
  MyApp.app
在 Xcode 项目中使用 xcconfig 管理多环境签名：


// Debug.xcconfig
CODE_SIGN_STYLE = Automatic
DEVELOPMENT_TEAM = ABCDEF1234
CODE_SIGN_IDENTITY = Apple Development
PROVISIONING_PROFILE_SPECIFIER =

// Release.xcconfig
CODE_SIGN_STYLE = Manual
DEVELOPMENT_TEAM = ABCDEF1234
CODE_SIGN_IDENTITY = Apple Distribution
PROVISIONING_PROFILE_SPECIFIER = MyApp_AppStore_Profile
常见问题
问题一：构建时报 "No signing certificate" 错误
原因：Keychain 中缺少对应的私钥，或证书已过期。


解决：


    

  1. 检查 Keychain Access 中是否有对应的证书和关联私钥
    2. 

  2. 如果使用 match，运行 fastlane match development 重新同步
    3. 

  3. 如果证书过期，在 Apple Developer Portal 中撤销旧证书并创建新证书
    4. 



问题二：描述文件不包含当前设备
原因：Ad Hoc 或 Development 描述文件未包含目标设备的 UDID。


解决：在 Apple Developer Portal 的 Devices 中注册设备 UDID，然后重新生成描述文件。


问题三：Entitlements 不匹配
原因：项目中的 .entitlements 文件声明的权限与描述文件中的 capabilities 不一致。


解决：确保 Apple Developer Portal 中 App ID 的 Capabilities 与本地 .entitlements 文件一致，然后重新生成描述文件。


问题四：CI 环境签名失败
原因：CI 机器的 Keychain 被锁定或无法访问。


解决：


# CI 脚本中解锁 Keychain
security unlock-keychain -p "$KEYCHAIN_PASSWORD" ~/Library/Keychains/login.keychain-db
security set-keychain-settings -t 3600 ~/Library/Keychains/login.keychain-db
问题五：多 Target 签名配置混乱
原因：主 App、Widget Extension、Notification Extension 等使用不同的 Bundle ID 和描述文件。


解决：为每个 Target 创建独立的描述文件，在 fastlane match 中用数组指定所有 app_identifier。


小结
    

  • 证书分为 Development（调试）和 Distribution（分发）两类，私钥存储在本地 Keychain，需妥善备份。
    • 

  • 描述文件将证书、App ID、设备列表、权限绑定在一起，不同分发方式使用不同类型。
    • 

  • Entitlements 声明 App 需要的系统权限，必须与 Apple Developer Portal 中的 App ID Capabilities 一致。
    • 

  • 自动签名适合个人开发和小团队，手动签名适合 CI/CD 和大团队协作。
    • 

  • Enterprise 分发用于公司内部，无需 App Store 审核，但严禁面向公众分发。
    • 

  • fastlane match 将签名资源集中在 Git 仓库，团队共享同一套证书和描述文件，CI 使用 --readonly 模式。
    • 

  • 在 CI 环境中需要注意 Keychain 解锁、证书安装和描述文件路径配置。
    • 

  • 使用 codesign 和 security 命令行工具可以排查签名问题。
    •
