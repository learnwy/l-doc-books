CI/CD 自动化流水线

概述

CI/CD（持续集成 / 持续交付）是现代 iOS 开发的标准实践——将构建、测试、签名、分发等重复性流程自动化，减少人工操作错误，加快发版节奏。一条成熟的 iOS CI/CD 流水线涵盖代码检查、单元测试、UI 测试、构建签名、TestFlight 分发甚至 App Store 提交。

iOS CI/CD 的核心挑战在于：macOS 运行环境依赖、代码签名管理和 Apple 生态的封闭性。Xcode Cloud、GitHub Actions（macOS runner）和 fastlane 是当前最主流的方案组合。

多环境配置
iOS 项目通常需要管理多个环境——Debug、Staging（测试环境）和 Release（生产环境）：


使用 xcconfig 管理环境变量：


// Shared.xcconfig
PRODUCT_NAME = MyApp
SWIFT_VERSION = 5.9
IPHONEOS_DEPLOYMENT_TARGET = 16.0

// Debug.xcconfig
#include "Shared.xcconfig"
API_BASE_URL = https:\/\/api-dev.example.com
BUNDLE_ID_SUFFIX = .debug
DISPLAY_NAME_SUFFIX = (Dev)
CODE_SIGN_IDENTITY = Apple Development

// Staging.xcconfig
#include "Shared.xcconfig"
API_BASE_URL = https:\/\/api-staging.example.com
BUNDLE_ID_SUFFIX = .staging
DISPLAY_NAME_SUFFIX = (Staging)
CODE_SIGN_IDENTITY = Apple Distribution

// Release.xcconfig
#include "Shared.xcconfig"
API_BASE_URL = https:\/\/api.example.com
BUNDLE_ID_SUFFIX =
DISPLAY_NAME_SUFFIX =
CODE_SIGN_IDENTITY = Apple Distribution

版本号自动递增
在 CI 中自动管理版本号，避免手动修改：


import Foundation

enum VersionBump {
    case major, minor, patch
}

func incrementVersion(_ current: String, bump: VersionBump) -> String {
    let parts = current.split(separator: ".").compactMap { Int($0) }
    guard parts.count == 3 else { return current }

    switch bump {
    case .major: return "\(parts[0] + 1).0.0"
    case .minor: return "\(parts[0]).\(parts[1] + 1).0"
    case .patch: return "\(parts[0]).\(parts[1]).\(parts[2] + 1)"
    }
}
fastlane 中的版本号管理：


lane :bump_build do
  increment_build_number(
    build_number: ENV["CI_BUILD_NUMBER"] || Time.now.strftime("%Y%m%d%H%M")
  )
end

lane :bump_version do |options|
  bump_type = options[:type] || "patch"
  increment_version_number(bump_type: bump_type)
end
GitHub Actions 完整流水线
# .github/workflows/ios-ci.yml
name: iOS CI/CD

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

env:
  SCHEME: MyApp
  WORKSPACE: MyApp.xcworkspace
  DESTINATION: 'platform=iOS Simulator,name=iPhone 16,OS=18.0'

jobs:
  lint:
    runs-on: macos-14
    steps:
      - uses: actions/checkout@v4
      - name: SwiftLint
        run: |
          brew install swiftlint
          swiftlint lint --strict

  test:
    runs-on: macos-14
    needs: lint
    steps:
      - uses: actions/checkout@v4
      - name: Select Xcode
        run: sudo xcode-select -s /Applications/Xcode_16.app
      - name: Resolve packages
        run: |
          xcodebuild -resolvePackageDependencies \
            -workspace $WORKSPACE \
            -scheme $SCHEME
      - name: Run tests
        run: |
          xcodebuild test \
            -workspace $WORKSPACE \
            -scheme $SCHEME \
            -destination "$DESTINATION" \
            -resultBundlePath TestResults.xcresult \
            -enableCodeCoverage YES
      - name: Upload test results
        uses: actions/upload-artifact@v4
        with:
          name: test-results
          path: TestResults.xcresult

  deploy-testflight:
    runs-on: macos-14
    needs: test
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      - name: Select Xcode
        run: sudo xcode-select -s /Applications/Xcode_16.app
      - name: Install fastlane
        run: gem install fastlane
      - name: Setup signing
        env:
          MATCH_PASSWORD: ${{ secrets.MATCH_PASSWORD }}
          MATCH_GIT_URL: ${{ secrets.MATCH_GIT_URL }}
        run: fastlane match appstore --readonly
      - name: Build and upload
        env:
          APP_STORE_CONNECT_API_KEY_ID: ${{ secrets.ASC_KEY_ID }}
          APP_STORE_CONNECT_API_ISSUER_ID: ${{ secrets.ASC_ISSUER_ID }}
          APP_STORE_CONNECT_API_KEY_CONTENT: ${{ secrets.ASC_KEY_CONTENT }}
        run: fastlane beta

fastlane 完整 Fastfile
# fastlane/Fastfile
default_platform(:ios)

platform :ios do
  before_all do
    setup_ci if ENV["CI"]
  end

  lane :lint do
    swiftlint(
      mode: :lint,
      strict: true,
      raise_if_swiftlint_error: true
    )
  end

  lane :test do
    run_tests(
      workspace: "MyApp.xcworkspace",
      scheme: "MyApp",
      device: "iPhone 16",
      code_coverage: true,
      result_bundle: true,
      output_directory: "./fastlane/test_output"
    )
  end

  lane :beta do
    lint
    test
    increment_build_number(
      build_number: ENV["CI_BUILD_NUMBER"] || latest_testflight_build_number + 1
    )
    match(type: "appstore", readonly: is_ci)
    build_app(
      workspace: "MyApp.xcworkspace",
      scheme: "MyApp",
      export_method: "app-store",
      xcargs: "-allowProvisioningUpdates"
    )
    upload_to_testflight(
      skip_waiting_for_build_processing: true,
      changelog: changelog_from_git_commits(
        commits_count: 10,
        pretty: "- %s"
      )
    )
    slack(
      message: "新的 TestFlight 构建已上传！",
      success: true,
      default_payloads: [:git_branch, :git_author]
    ) if ENV["SLACK_URL"]
  end

  lane :release do
    beta
    upload_to_app_store(
      submit_for_review: true,
      automatic_release: false,
      force: true
    )
  end

  error do |lane, exception|
    slack(
      message: "#{lane} 失败: #{exception.message}",
      success: false
    ) if ENV["SLACK_URL"]
  end
end
环境变量管理
关键原则：


    

  • 敏感信息（密码、API Key、证书密码）绝不提交到代码仓库
    • 

  • 使用 CI 平台的 Secrets 管理功能存储
    • 

  • fastlane 的 .env 文件加入 .gitignore
    • 

  • App Store Connect API Key 优先于 Apple ID + 密码方式认证
    •

常见问题
问题一：GitHub Actions macOS runner 构建慢
原因：GitHub 提供的 macOS runner 资源有限，SPM 依赖下载和 Xcode 构建耗时较长。


解决：


    

  1. 缓存 SPM 依赖：使用 actions/cache 缓存 ~/Library/Developer/Xcode/DerivedData
    2. 

  2. 使用 macos-14（M1）runner，性能优于 macos-13（Intel）
    3. 

  3. 拆分 lint / test / build 到不同 job，并行执行无依赖的步骤
    4. 



问题二：CI 环境签名失败 "No signing certificate found"
原因：CI 机器缺少证书和私钥。


解决：使用 fastlane match 同步签名资源，在 CI 步骤中添加 setup_ci 和 match(readonly: true)。


问题三：测试在 CI 上随机失败（Flaky Tests）
原因：UI 测试依赖模拟器状态，异步操作的时序在不同机器上不一致。


解决：


    

  1. 在测试前重置模拟器状态
    2. 

  2. 使用 XCTWaiter 替代硬编码的 sleep
    3. 

  3. 将不稳定的 UI 测试隔离到独立的 test plan
    4. 



问题四：Xcode Cloud 构建号冲突
原因：多个分支同时触发构建，使用了相同的构建号。


解决：使用 Xcode Cloud 内置的 $CI_BUILD_NUMBER 环境变量，它会自动递增。


问题五：fastlane 版本不一致导致行为差异
原因：本地和 CI 使用了不同版本的 fastlane。


解决：使用 Bundler 锁定 fastlane 版本：


# Gemfile
source "https://rubygems.org"
gem "fastlane", "~> 2.225"
gem "cocoapods", "~> 1.15" if needed
bundle install
bundle exec fastlane beta
小结
    

  • iOS CI/CD 流水线的核心环节：代码检查 → 测试 → 构建签名 → 分发通知。
    • 

  • 使用 xcconfig 管理多环境配置（Debug/Staging/Release），避免硬编码环境变量。
    • 

  • GitHub Actions 提供灵活的 macOS runner，适合开源和自定义流程；Xcode Cloud 与 Apple 生态深度集成。
    • 

  • fastlane 是 iOS CI/CD 的事实标准工具链，涵盖构建（gym）、测试（scan）、签名（match）、分发（pilot/deliver）。
    • 

  • 版本号在 CI 中自动递增，使用 CI_BUILD_NUMBER 或 latest_testflight_build_number + 1。
    • 

  • 敏感信息通过 CI 平台的 Secrets 管理，绝不提交到代码仓库。
    • 

  • 使用 App Store Connect API Key 替代 Apple ID + 密码，更安全且不受双重认证影响。
    • 

  • 用 Bundler 锁定 fastlane 版本，确保本地和 CI 行为一致。
    •
