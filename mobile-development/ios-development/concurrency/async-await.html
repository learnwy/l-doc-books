async/await 与结构化并发

概述

Swift 5.5 引入的 async/await 是一种全新的并发编程模型，用线性的代码风格替代嵌套的回调闭包，让异步代码像同步代码一样易读。配合结构化并发（Structured Concurrency）——Task、TaskGroup、async let——开发者可以安全地组织并发任务，享受自动取消传播和作用域生命周期管理。

相比 GCD 的回调模式，async/await 消除了回调地狱（Callback Hell）、忘记调用 completion handler、多路径返回不一致等常见错误。编译器可以在编译期检查 Sendable 约束，配合 @MainActor 确保 UI 更新安全。async/await 是 Apple 推荐的现代并发方案，也是未来 iOS 开发的主流方向。

核心概念
async/await 基础语法
用 async 标记函数为异步函数，用 await 在调用点挂起当前任务等待结果：


func fetchUser(id: String) async throws -> User {
    let url = URL(string: "https://api.example.com/users/\(id)")!
    let (data, response) = try await URLSession.shared.data(from: url)

    guard let httpResponse = response as? HTTPURLResponse,
          httpResponse.statusCode == 200 else {
        throw APIError.invalidResponse
    }

    return try JSONDecoder().decode(User.self, from: data)
}

func loadProfile() async {
    do {
        let user = try await fetchUser(id: "123")
        print("用户名：\(user.name)")
    } catch {
        print("加载失败：\(error)")
    }
}
await 标记的是挂起点（suspension point）——当前任务在此处暂停执行，让出线程给其他任务使用。当异步操作完成后，任务恢复执行。整个过程不阻塞任何线程。


Task
Task 是非结构化并发的入口——它创建一个独立的并发执行上下文。从同步代码调用 async 函数时，必须通过 Task 桥接：


class ProfileViewController: UIViewController {
    override func viewDidLoad() {
        super.viewDidLoad()

        Task {
            do {
                let user = try await fetchUser(id: "123")
                nameLabel.text = user.name
            } catch {
                showError(error)
            }
        }
    }
}
Task 继承创建它的上下文的 actor 隔离和优先级。在 @MainActor 标注的类中创建的 Task 自动运行在主 actor 上。


Task.detached 创建完全独立的任务，不继承任何上下文：


Task.detached(priority: .background) {
    await self.syncDataToCloud()
}
async let（并发绑定）
async let 在结构化并发中实现子任务并发执行——多个异步操作同时启动，在需要结果时 await：


func loadDashboard() async throws -> Dashboard {
    async let user = fetchUser(id: "123")
    async let orders = fetchOrders(userId: "123")
    async let recommendations = fetchRecommendations()

    let dashboard = try await Dashboard(
        user: user,
        orders: orders,
        recommendations: recommendations
    )
    return dashboard
}
与串行 await 的对比：


func loadDashboardSerial() async throws -> Dashboard {
    let user = try await fetchUser(id: "123")           // ~200ms
    let orders = try await fetchOrders(userId: "123")    // ~150ms
    let recommendations = try await fetchRecommendations() // ~100ms
    // 总耗时 ≈ 450ms（串行）

    return Dashboard(user: user, orders: orders, recommendations: recommendations)
}

func loadDashboardConcurrent() async throws -> Dashboard {
    async let user = fetchUser(id: "123")
    async let orders = fetchOrders(userId: "123")
    async let recommendations = fetchRecommendations()
    // 总耗时 ≈ 200ms（并发，取最长）

    return try await Dashboard(user: user, orders: orders, recommendations: recommendations)
}
TaskGroup
TaskGroup 适用于动态数量的并发子任务——数量在编译期未知的场景：


func fetchAllImages(urls: [URL]) async throws -> [URL: UIImage] {
    try await withThrowingTaskGroup(of: (URL, UIImage).self) { group in
        for url in urls {
            group.addTask {
                let (data, _) = try await URLSession.shared.data(from: url)
                guard let image = UIImage(data: data) else {
                    throw ImageError.decodingFailed
                }
                return (url, image)
            }
        }

        var results: [URL: UIImage] = [:]
        for try await (url, image) in group {
            results[url] = image
        }
        return results
    }
}
可以限制 TaskGroup 的并发数来避免资源耗尽：


func fetchImagesThrottled(urls: [URL]) async throws -> [UIImage] {
    try await withThrowingTaskGroup(of: UIImage.self) { group in
        let maxConcurrency = 4
        var results: [UIImage] = []
        var index = 0

        for _ in 0..<min(maxConcurrency, urls.count) {
            let url = urls[index]
            group.addTask { try await self.downloadImage(from: url) }
            index += 1
        }

        for try await image in group {
            results.append(image)
            if index < urls.count {
                let url = urls[index]
                group.addTask { try await self.downloadImage(from: url) }
                index += 1
            }
        }

        return results
    }
}
Sendable
Sendable 协议标记一个类型可以安全地跨并发域传递。值类型（struct/enum）只要所有存储属性都是 Sendable 的，编译器会自动推断其 Sendable 一致性。引用类型需要手动声明：


struct UserDTO: Sendable {
    let id: String
    let name: String
    let email: String
}

final class ImmutableConfig: Sendable {
    let apiKey: String
    let baseURL: URL

    init(apiKey: String, baseURL: URL) {
        self.apiKey = apiKey
        self.baseURL = baseURL
    }
}

class MutableState {
    var count = 0  // ❌ 非 Sendable — 可变状态 + class
}
闭包跨并发域传递时也需要满足 @Sendable 约束：


Task.detached { @Sendable in
    await self.process()
}
@MainActor
@MainActor 确保代码在主线程上执行，是 UI 安全更新的编译期保证：


@MainActor
class ProfileViewModel: ObservableObject {
    @Published var user: User?
    @Published var isLoading = false
    @Published var error: Error?

    func loadUser() async {
        isLoading = true
        defer { isLoading = false }

        do {
            user = try await fetchUser(id: "123")
        } catch {
            self.error = error
        }
    }
}
@MainActor 可以标注类、方法或属性。标注在类上时，类的所有属性和方法都隔离到主 actor。


取消机制
结构化并发的任务取消是协作式的——系统设置取消标志，任务需要主动检查：


func processLargeDataset(_ items: [DataItem]) async throws -> [Result] {
    var results: [Result] = []

    for item in items {
        try Task.checkCancellation()
        let result = await process(item)
        results.append(result)
    }

    return results
}

func monitorCancellation() async {
    let task = Task {
        try await processLargeDataset(items)
    }

    DispatchQueue.main.asyncAfter(deadline: .now() + 2) {
        task.cancel()
    }
}
取消在结构化并发中会自动向下传播——父任务取消时，所有子任务（async let、TaskGroup 中的任务）也会被取消：


func loadPage() async throws -> Page {
    async let header = fetchHeader()   // 父任务取消时自动取消
    async let content = fetchContent() // 父任务取消时自动取消
    async let footer = fetchFooter()   // 父任务取消时自动取消

    return try await Page(header: header, content: content, footer: footer)
}

使用方式
模式一：ViewModel 中加载数据
SwiftUI ViewModel 的标准异步数据加载模式：


@MainActor
class ArticleListViewModel: ObservableObject {
    @Published var articles: [Article] = []
    @Published var state: LoadingState = .idle

    private var loadTask: Task<Void, Never>?

    func load() {
        loadTask?.cancel()
        loadTask = Task {
            state = .loading
            do {
                let fetched = try await ArticleService.shared.fetchArticles()
                guard !Task.isCancelled else { return }
                articles = fetched
                state = .loaded
            } catch is CancellationError {
                return
            } catch {
                state = .error(error)
            }
        }
    }

    func cancelLoad() {
        loadTask?.cancel()
    }
}

enum LoadingState: Equatable {
    case idle, loading, loaded
    case error(Error)

    static func == (lhs: Self, rhs: Self) -> Bool {
        switch (lhs, rhs) {
        case (.idle, .idle), (.loading, .loading), (.loaded, .loaded):
            return true
        case (.error, .error):
            return true
        default:
            return false
        }
    }
}
模式二：并发请求 + 超时
对多个并发请求设置整体超时：


func fetchWithTimeout<T: Sendable>(
    timeout: Duration,
    operation: @Sendable @escaping () async throws -> T
) async throws -> T {
    try await withThrowingTaskGroup(of: T.self) { group in
        group.addTask {
            try await operation()
        }

        group.addTask {
            try await Task.sleep(for: timeout)
            throw TimeoutError()
        }

        let result = try await group.next()!
        group.cancelAll()
        return result
    }
}

let user = try await fetchWithTimeout(timeout: .seconds(5)) {
    try await fetchUser(id: "123")
}
模式三：从回调 API 桥接到 async/await
使用 withCheckedThrowingContinuation 将回调式 API 转为 async 函数：


func fetchLegacyData() async throws -> Data {
    try await withCheckedThrowingContinuation { continuation in
        LegacyNetworkClient.shared.request(url: someURL) { result in
            switch result {
            case .success(let data):
                continuation.resume(returning: data)
            case .failure(let error):
                continuation.resume(throwing: error)
            }
        }
    }
}
continuation.resume 必须且只能被调用一次。withCheckedContinuation 在 Debug 模式下会检测多次 resume 或未 resume 的错误。


常见陷阱
陷阱一：Task 泄漏
在 ViewController/ViewModel 中创建 Task 却不持有引用，导致无法取消：


class ViewController: UIViewController {
    override func viewDidLoad() {
        super.viewDidLoad()
        Task {
            await loadData()  // ❌ 页面关闭后任务仍在运行
        }
    }
}
正确做法——持有 Task 引用并在适当时机取消：


class ViewController: UIViewController {
    private var loadTask: Task<Void, Never>?

    override func viewDidLoad() {
        super.viewDidLoad()
        loadTask = Task {
            await loadData()
        }
    }

    override func viewDidDisappear(_ animated: Bool) {
        super.viewDidDisappear(animated)
        loadTask?.cancel()
    }
}
陷阱二：在 await 之后假设状态未变
await 是挂起点，挂起期间其他代码可能修改了共享状态：


@MainActor
class CartViewModel: ObservableObject {
    @Published var items: [CartItem] = []

    func checkout() async throws {
        guard !items.isEmpty else { return }

        let order = try await OrderService.shared.createOrder(items: items)
        // ⚠️ await 恢复后 items 可能已被用户修改
        // 应重新验证状态
        guard !items.isEmpty else { throw CheckoutError.cartModified }
        try await OrderService.shared.confirmOrder(order)
    }
}
陷阱三：Continuation 多次 resume 或未 resume
func broken() async throws -> Data {
    try await withCheckedThrowingContinuation { continuation in
        legacyFetch { data, error in
            if let error {
                continuation.resume(throwing: error)
            }
            if let data {
                continuation.resume(returning: data) // ❌ 可能第二次 resume
            }
        }
    }
}
正确做法——确保恰好 resume 一次：


func fixed() async throws -> Data {
    try await withCheckedThrowingContinuation { continuation in
        legacyFetch { data, error in
            if let error {
                continuation.resume(throwing: error)
                return
            }
            guard let data else {
                continuation.resume(throwing: FetchError.noData)
                return
            }
            continuation.resume(returning: data)
        }
    }
}
陷阱四：在非隔离上下文中访问 @MainActor 属性
@MainActor
class ViewModel: ObservableObject {
    @Published var title = ""
}

func backgroundWork(vm: ViewModel) async {
    // ❌ 编译错误：在非 MainActor 上下文访问 MainActor 隔离属性
    // vm.title = "New Title"

    await MainActor.run {
        vm.title = "New Title"  // ✅ 显式切换到 MainActor
    }
}
小结
    

  • async/await 用线性代码风格替代回调嵌套，await 标记挂起点，让出线程但不阻塞。
    • 

  • Task 是非结构化并发入口，从同步代码桥接到异步世界；Task.detached 创建完全独立的任务。
    • 

  • async let 实现固定数量的并发子任务，TaskGroup 处理动态数量的并发子任务。
    • 

  • 结构化并发的子任务生命周期绑定父作用域，取消和错误自动传播；非结构化并发灵活但需手动管理。
    • 

  • Sendable 约束确保跨并发域传递的数据是安全的，编译器在严格并发模式下强制检查。
    • 

  • @MainActor 提供编译期保证，确保 UI 更新在主线程执行，替代手动 DispatchQueue.main.async。
    • 

  • 取消是协作式的——需要在异步代码中主动调用 Task.checkCancellation() 或检查 Task.isCancelled。
    • 

  • 使用 withCheckedThrowingContinuation 将回调式 API 桥接为 async 函数，continuation 必须恰好 resume 一次。
    • 

  • 持有 Task 引用以便在适当时机取消，避免页面销毁后任务仍在运行造成资源浪费。
    •
