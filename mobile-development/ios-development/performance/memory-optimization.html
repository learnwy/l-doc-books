内存优化

概述

iOS 是一个内存受限的平台——没有交换空间（Swap），当系统内存紧张时，会向应用发送内存警告，若应用未能及时释放内存，系统将直接终止进程（OOM Kill）。与桌面端不同，iOS 应用的内存上限通常在 1~2 GB 左右（因设备型号而异），且前台应用与后台应用共享有限的物理内存。

内存优化的目标不仅是避免 OOM 崩溃，还包括降低内存水位以减少系统清理后台应用的频率、减少内存分配带来的 CPU 开销、以及提升整体用户体验。本文覆盖从内存警告处理、自动释放池、图片缓存策略到 Memory Graph Debugger 等核心优化手段。

核心工具
Xcode Memory Report
Xcode Debug Navigator 中的 Memory 面板实时显示应用的内存占用曲线。它是最轻量的监控手段，适合在开发过程中随时观察内存趋势。


Memory Graph Debugger
点击 Xcode Debug 区域的 🔀 按钮可以捕获当前堆内存的完整对象图。它可视化展示所有存活对象及其引用关系，紫色三角警告图标标记检测到的泄漏。

内存警告处理
当系统内存紧张时，会向所有运行中的应用发送内存警告。应用应在收到警告时主动释放可重建的缓存数据：


class ImageCacheManager {
    static let shared = ImageCacheManager()
    private let cache = NSCache<NSString, UIImage>()

    private init() {
        cache.totalCostLimit = 100 * 1024 * 1024
        cache.countLimit = 200

        NotificationCenter.default.addObserver(
            self,
            selector: #selector(handleMemoryWarning),
            name: UIApplication.didReceiveMemoryWarningNotification,
            object: nil
        )
    }

    @objc private func handleMemoryWarning() {
        cache.removeAllObjects()
    }

    func image(forKey key: String) -> UIImage? {
        cache.object(forKey: key as NSString)
    }

    func store(_ image: UIImage, forKey key: String) {
        let cost = Int(image.size.width * image.size.height * image.scale * image.scale * 4)
        cache.setObject(image, forKey: key as NSString, cost: cost)
    }
}
NSCache 本身在内存压力下会自动淘汰部分对象，但在收到 didReceiveMemoryWarningNotification 时主动清空可以更快释放大块内存，降低被系统杀掉的风险。


autoreleasepool 优化循环分配
在 Swift 中，大量临时对象在循环中创建时，它们的释放可能被延迟到当前 RunLoop 迭代结束。使用 autoreleasepool 可以强制在每次迭代后释放临时对象，避免内存峰值：


func processLargeDataset(items: [Data]) -> [ProcessedResult] {
    var results: [ProcessedResult] = []
    results.reserveCapacity(items.count)

    for item in items {
        autoreleasepool {
            let decoded = try? JSONDecoder().decode(RawRecord.self, from: item)
            if let decoded {
                let processed = transform(decoded)
                results.append(processed)
            }
        }
    }

    return results
}

func importImages(from paths: [String]) {
    for path in paths {
        autoreleasepool {
            guard let image = UIImage(contentsOfFile: path) else { return }
            let thumbnail = image.preparingThumbnail(of: CGSize(width: 100, height: 100))
            saveThumbnail(thumbnail, for: path)
        }
    }
}
图片降采样
直接加载大尺寸图片会消耗大量内存（一张 4000×3000 的图片解码后占用约 48MB）。当显示尺寸远小于原始尺寸时，应使用 ImageIO 进行降采样，只解码目标尺寸的像素数据：


import ImageIO

func downsample(imageAt url: URL, to pointSize: CGSize, scale: CGFloat) -> UIImage? {
    let maxDimensionInPixels = max(pointSize.width, pointSize.height) * scale

    let options: [CFString: Any] = [
        kCGImageSourceCreateThumbnailFromImageAlways: true,
        kCGImageSourceShouldCacheImmediately: true,
        kCGImageSourceCreateThumbnailWithTransform: true,
        kCGImageSourceThumbnailMaxPixelSize: maxDimensionInPixels
    ]

    guard let imageSource = CGImageSourceCreateWithURL(url as CFURL, nil),
          let cgImage = CGImageSourceCreateThumbnailAtIndex(imageSource, 0, options as CFDictionary)
    else { return nil }

    return UIImage(cgImage: cgImage)
}
图片缓存策略
多级缓存策略平衡性能与内存占用——内存缓存提供最快访问速度，磁盘缓存提供持久性：


class TieredImageCache {
    private let memoryCache = NSCache<NSString, UIImage>()
    private let diskCacheURL: URL
    private let ioQueue = DispatchQueue(label: "com.app.imagecache.io")

    init() {
        let caches = FileManager.default.urls(for: .cachesDirectory, in: .userDomainMask)[0]
        diskCacheURL = caches.appendingPathComponent("ImageCache")
        try? FileManager.default.createDirectory(at: diskCacheURL, withIntermediateDirectories: true)

        memoryCache.totalCostLimit = 50 * 1024 * 1024
    }

    func loadImage(for url: URL, targetSize: CGSize) async -> UIImage? {
        let key = url.absoluteString

        if let cached = memoryCache.object(forKey: key as NSString) {
            return cached
        }

        let diskPath = diskCacheURL.appendingPathComponent(key.md5Hash)
        if FileManager.default.fileExists(atPath: diskPath.path),
           let image = downsample(imageAt: diskPath, to: targetSize, scale: UIScreen.main.scale) {
            memoryCache.setObject(image, forKey: key as NSString)
            return image
        }

        guard let (data, _) = try? await URLSession.shared.data(from: url) else { return nil }

        ioQueue.async {
            try? data.write(to: diskPath)
        }

        guard let image = downsample(data: data, to: targetSize, scale: UIScreen.main.scale) else { return nil }
        memoryCache.setObject(image, forKey: key as NSString)
        return image
    }

    private func downsample(data: Data, to pointSize: CGSize, scale: CGFloat) -> UIImage? {
        let maxDimension = max(pointSize.width, pointSize.height) * scale
        let options: [CFString: Any] = [
            kCGImageSourceCreateThumbnailFromImageAlways: true,
            kCGImageSourceShouldCacheImmediately: true,
            kCGImageSourceCreateThumbnailWithTransform: true,
            kCGImageSourceThumbnailMaxPixelSize: maxDimension
        ]
        guard let source = CGImageSourceCreateWithData(data as CFData, nil),
              let cgImage = CGImageSourceCreateThumbnailAtIndex(source, 0, options as CFDictionary)
        else { return nil }
        return UIImage(cgImage: cgImage)
    }
}
大数据分页加载
一次性加载所有数据会导致内存峰值过高。分页加载按需请求数据，配合列表的滚动位置触发下一页加载：


class PaginatedDataSource<Item: Decodable> {
    private(set) var items: [Item] = []
    private var currentPage = 0
    private let pageSize = 20
    private var isLoading = false
    private var hasMore = true

    let baseURL: URL

    init(baseURL: URL) {
        self.baseURL = baseURL
    }

    func loadNextPage() async throws {
        guard !isLoading, hasMore else { return }
        isLoading = true
        defer { isLoading = false }

        var components = URLComponents(url: baseURL, resolvingAgainstBaseURL: false)!
        components.queryItems = [
            URLQueryItem(name: "page", value: "\(currentPage)"),
            URLQueryItem(name: "size", value: "\(pageSize)")
        ]

        let (data, _) = try await URLSession.shared.data(from: components.url!)
        let page = try JSONDecoder().decode([Item].self, from: data)

        items.append(contentsOf: page)
        hasMore = page.count == pageSize
        currentPage += 1
    }

    func reset() {
        items.removeAll()
        currentPage = 0
        hasMore = true
    }
}
Memory Graph Debugger 实战
当怀疑存在内存泄漏时，使用 Memory Graph Debugger 的标准流程：


    

  1. 运行 App，执行可能泄漏的操作（如打开并关闭某个页面）
    2. 

  2. 点击 Debug Navigator 中的 🔀 按钮捕获内存快照
    3. 

  3. 在左侧面板搜索目标类名（如 DetailViewController）
    4. 

  4. 如果页面已关闭但实例仍然存活，说明泄漏
    5. 

  5. 选中该实例，在右侧查看完整引用链，找到阻止释放的强引用
    6. 



class DetailViewController: UIViewController {
    var onDismiss: (() -> Void)?
    private var dataManager = DataManager()

    override func viewDidLoad() {
        super.viewDidLoad()
        dataManager.onDataReady = { [weak self] data in
            self?.updateUI(with: data)
        }
    }

    private func updateUI(with data: [String]) {
        // ...
    }

    deinit {
        print("✅ DetailViewController 已释放")
    }
}
如果 deinit 没有被调用，在 Memory Graph 中就能看到是哪条引用链阻止了释放。


常见问题
Q：NSCache 和 Dictionary 有什么区别？
NSCache 是线程安全的，且在内存紧张时会自动淘汰部分对象。Dictionary 不会自动释放任何内容。用于缓存场景时应优先选择 NSCache。


Q：autoreleasepool 在 Swift 中还有用吗？
有用。虽然 Swift 大部分对象由 ARC 直接管理，但调用 Objective-C API（如 UIImage(contentsOfFile:)）返回的对象可能进入 autorelease pool。在循环中大量调用这类 API 时，手动 autoreleasepool 可以显著降低内存峰值。


Q：如何判断 App 的内存上限？
iOS 没有公开的内存上限 API。可以使用 os_proc_available_memory() 获取当前可用内存。经验值：当应用内存超过设备物理内存的 50% 时，被系统杀掉的风险显著增加。


Q：图片降采样和 UIImage resize 有什么区别？
UIImage 的 resize 方式（如 UIGraphicsImageRenderer）需要先将原图完整解码到内存，再缩放——峰值内存等于原图大小。而 ImageIO 降采样在解码阶段就按目标尺寸采样，峰值内存约等于目标尺寸。


Q：如何检测后台被杀？
MetricKit 的 MXBackgroundExitData 提供后台退出原因统计。如果 cumulativeMemoryPressureExitCount 持续增长，说明应用因内存压力被系统终止。


小结
    

  • 内存警告是系统给应用的最后机会——收到警告时应立即释放缓存、临时数据等可重建资源。
    • 

  • autoreleasepool 在循环中处理大量 ObjC 对象时仍然必要，可以显著降低内存峰值。
    • 

  • 图片降采样（ImageIO）是最有效的图片内存优化手段，在解码阶段就控制像素数量，避免原图完整解码。
    • 

  • NSCache 提供线程安全、自动淘汰的缓存能力，配合 totalCostLimit 可精确控制内存上限。
    • 

  • 分页加载按需请求数据，避免一次性将全部数据加载到内存。
    • 

  • Memory Graph Debugger 是定位内存泄漏的最直观工具，可视化对象引用链，紫色警告标记泄漏。
    • 

  • 使用 os_proc_available_memory() 监控可用内存，建立内存水位预警机制。
    • 

  • 优化策略：减少峰值（降采样、分页）→ 及时释放（autoreleasepool、缓存淘汰）→ 检测泄漏（Memory Graph）。
