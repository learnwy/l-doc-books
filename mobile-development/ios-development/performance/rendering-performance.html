Part I · iOSiOS 开发 简介性能优化 简介渲染性能

渲染性能

概述

iOS 设备的屏幕刷新率为 60fps（ProMotion 设备为 120fps），意味着每帧的渲染预算仅有 16.67ms（或 8.33ms）。当某一帧的渲染超过预算时间时，该帧被丢弃（dropped frame），用户感知到的就是卡顿。渲染性能优化的核心目标是确保每一帧都能在预算时间内完成。

iOS 的渲染由 Core Animation 驱动，采用独立的 Render Server 进程完成最终合成。理解渲染管线的各个阶段、识别离屏渲染和图层混合等性能陷阱、以及针对 UIKit 和 SwiftUI 的优化策略，是保证流畅用户体验的关键。

CADisplayLink
CADisplayLink 与屏幕刷新率同步触发回调，可以用来实时监测帧率：


class FPSMonitor {
    private var displayLink: CADisplayLink?
    private var lastTimestamp: CFTimeInterval = 0
    private var frameCount: Int = 0

    func start() {
        displayLink = CADisplayLink(target: self, selector: #selector(tick))
        displayLink?.add(to: .main, forMode: .common)
    }

    func stop() {
        displayLink?.invalidate()
        displayLink = nil
    }

    @objc private func tick(_ link: CADisplayLink) {
        if lastTimestamp == 0 {
            lastTimestamp = link.timestamp
            return
        }

        frameCount += 1
        let elapsed = link.timestamp - lastTimestamp

        if elapsed >= 1.0 {
            let fps = Double(frameCount) / elapsed
            print("FPS: \(Int(round(fps)))")
            frameCount = 0
            lastTimestamp = link.timestamp
        }
    }
}

离屏渲染优化
离屏渲染（Offscreen Rendering）是指 GPU 无法直接在当前帧缓冲区中完成合成，需要开辟额外的离屏缓冲区，导致 GPU 上下文切换，开销很大。常见触发场景及优化方案：


class AvatarView: UIView {
    let imageView = UIImageView()

    // ❌ 触发离屏渲染
    func setupBad() {
        imageView.layer.cornerRadius = 40
        imageView.clipsToBounds = true
    }

    // ✅ 使用预渲染圆角图片
    func setupGood() {
        imageView.image = makeRoundedImage(
            image: originalImage,
            size: CGSize(width: 80, height: 80),
            radius: 40
        )
    }

    private func makeRoundedImage(image: UIImage?, size: CGSize, radius: CGFloat) -> UIImage? {
        guard let image else { return nil }
        let renderer = UIGraphicsImageRenderer(size: size)
        return renderer.image { context in
            let rect = CGRect(origin: .zero, size: size)
            UIBezierPath(roundedRect: rect, cornerRadius: radius).addClip()
            image.draw(in: rect)
        }
    }
}
class ShadowCardView: UIView {
    func setupBad() {
        layer.cornerRadius = 12
        layer.shadowColor = UIColor.black.cgColor
        layer.shadowOffset = CGSize(width: 0, height: 2)
        layer.shadowRadius = 4
        layer.shadowOpacity = 0.1
    }

    func setupGood() {
        layer.cornerRadius = 12
        layer.shadowColor = UIColor.black.cgColor
        layer.shadowOffset = CGSize(width: 0, height: 2)
        layer.shadowRadius = 4
        layer.shadowOpacity = 0.1
        layer.shadowPath = UIBezierPath(roundedRect: bounds, cornerRadius: 12).cgPath
    }

    override func layoutSubviews() {
        super.layoutSubviews()
        layer.shadowPath = UIBezierPath(roundedRect: bounds, cornerRadius: 12).cgPath
    }
}
图层混合优化
当多个半透明图层叠加时，GPU 需要逐像素计算混合颜色，开销随重叠层数线性增长。减少图层混合的方法：


class OptimizedCell: UITableViewCell {
    private let titleLabel = UILabel()
    private let subtitleLabel = UILabel()

    override init(style: UITableViewCell.CellStyle, reuseIdentifier: String?) {
        super.init(style: style, reuseIdentifier: reuseIdentifier)

        backgroundColor = .white
        contentView.backgroundColor = .white

        for label in [titleLabel, subtitleLabel] {
            label.backgroundColor = .white
            label.isOpaque = true
        }
    }

    required init?(coder: NSCoder) { fatalError() }
}
光栅化
shouldRasterize 将图层及其子图层渲染为一张位图并缓存。适用于内容不频繁变化的复杂图层：


class ComplexCardView: UIView {
    func enableRasterization() {
        layer.shouldRasterize = true
        layer.rasterizationScale = UIScreen.main.scale
    }
}

drawRect 优化
自定义绘制（draw(_:)）在主线程执行，应尽量减少绘制区域和复杂度：


class WaveformView: UIView {
    var amplitudes: [CGFloat] = [] {
        didSet {
            setNeedsDisplay()
        }
    }

    override func draw(_ rect: CGRect) {
        guard let context = UIGraphicsGetCurrentContext() else { return }

        let barWidth: CGFloat = 3
        let gap: CGFloat = 2
        let totalWidth = barWidth + gap
        let startIndex = Int(rect.minX / totalWidth)
        let endIndex = min(amplitudes.count, Int(rect.maxX / totalWidth) + 1)

        context.setFillColor(UIColor.systemBlue.cgColor)

        for i in startIndex..<endIndex {
            let x = CGFloat(i) * totalWidth
            let height = amplitudes[i] * bounds.height
            let y = (bounds.height - height) / 2
            context.fill(CGRect(x: x, y: y, width: barWidth, height: height))
        }
    }
}
只绘制 rect 区域内的元素，避免全屏重绘。配合 setNeedsDisplay(_:) 指定脏区域可以进一步减少绘制范围。


列表滑动优化
UITableView / UICollectionView 的滑动流畅度是最常见的渲染性能问题。核心优化策略：


class FeedViewController: UIViewController {
    private lazy var collectionView: UICollectionView = {
        var config = UICollectionLayoutListConfiguration(appearance: .plain)
        let layout = UICollectionViewCompositionalLayout.list(using: config)
        let cv = UICollectionView(frame: .zero, collectionViewLayout: layout)
        cv.prefetchDataSource = self
        return cv
    }()

    private let imageCache = NSCache<NSString, UIImage>()
    private var prefetchTasks: [IndexPath: Task<Void, Never>] = [:]
}

extension FeedViewController: UICollectionViewDataSourcePrefetching {
    func collectionView(_ collectionView: UICollectionView, prefetchItemsAt indexPaths: [IndexPath]) {
        for indexPath in indexPaths {
            let item = dataSource[indexPath.item]
            guard imageCache.object(forKey: item.imageURL.absoluteString as NSString) == nil else { continue }

            prefetchTasks[indexPath] = Task {
                guard let (data, _) = try? await URLSession.shared.data(from: item.imageURL),
                      let image = UIImage(data: data)
                else { return }
                imageCache.setObject(image, forKey: item.imageURL.absoluteString as NSString)
            }
        }
    }

    func collectionView(_ collectionView: UICollectionView, cancelPrefetchingForItemsAt indexPaths: [IndexPath]) {
        for indexPath in indexPaths {
            prefetchTasks[indexPath]?.cancel()
            prefetchTasks.removeValue(forKey: indexPath)
        }
    }
}
关键点：使用 Prefetching 预加载即将显示的 cell 数据；取消不再需要的预加载任务；图片解码在后台线程完成；cell 高度尽量使用固定值或缓存计算结果。


SwiftUI 渲染优化
SwiftUI 通过 body 重新求值来更新视图。优化的核心是减少不必要的 body 求值：


struct MessageRow: View, Equatable {
    let message: Message

    var body: some View {
        HStack(spacing: 12) {
            AsyncImage(url: message.avatarURL) { image in
                image.resizable().scaledToFill()
            } placeholder: {
                Color.gray.opacity(0.3)
            }
            .frame(width: 44, height: 44)
            .clipShape(Circle())

            VStack(alignment: .leading, spacing: 4) {
                Text(message.sender)
                    .font(.headline)
                Text(message.content)
                    .font(.subheadline)
                    .foregroundStyle(.secondary)
                    .lineLimit(2)
            }

            Spacer()

            Text(message.formattedTime)
                .font(.caption)
                .foregroundStyle(.tertiary)
        }
        .padding(.vertical, 8)
    }

    static func == (lhs: MessageRow, rhs: MessageRow) -> Bool {
        lhs.message.id == rhs.message.id &&
        lhs.message.content == rhs.message.content
    }
}

struct MessageList: View {
    let messages: [Message]

    var body: some View {
        ScrollView {
            LazyVStack(spacing: 0) {
                ForEach(messages) { message in
                    EquatableView(content: MessageRow(message: message))
                    Divider()
                }
            }
        }
    }
}
SwiftUI 优化要点：实现 Equatable 并使用 EquatableView 跳过不必要的 diff；使用 LazyVStack / LazyHStack 延迟创建视图；将大视图拆分为小的子视图，缩小 body 重新求值的范围；避免在 body 中执行复杂计算。


常见问题
Q：如何判断是 CPU 瓶颈还是 GPU 瓶颈？
使用 Time Profiler 和 Core Animation Instrument 分别分析。主线程 CPU 占用率高但 GPU 空闲 → CPU 瓶颈（布局/绘制太慢）。CPU 很快提交图层树但帧率仍低 → GPU 瓶颈（离屏渲染/图层混合/纹理过大）。


Q：cornerRadius 一定触发离屏渲染吗？
不一定。单独设置 cornerRadius 不触发离屏渲染。只有同时设置 cornerRadius 和 masksToBounds = true（或 clipsToBounds = true），且图层有子内容需要裁剪时才会触发。iOS 9+ 对 UIImageView 的单图层圆角做了优化，不再触发离屏渲染。


Q：ProMotion 设备（120fps）需要特别优化吗？
120fps 的帧预算缩短到 8.33ms，对渲染性能要求更高。使用 CADisplayLink.preferredFrameRateRange 可以声明应用所需的帧率范围，让系统智能选择合适的刷新率。


Q：SwiftUI 的 List 和 LazyVStack 性能有差异吗？
List 基于 UITableView，自带 cell 复用机制，适合大量同构数据。LazyVStack 只延迟创建但不复用，滚动过的视图会保留在内存中。数据量大时 List 性能更优。


Q：如何检测主线程卡顿？
可以使用 RunLoop Observer 监测主线程状态——在后台线程通过信号量等待 RunLoop 回调，如果等待超时（如 50ms），说明主线程被长时间阻塞。也可以使用 MetricKit 的 MXHangDiagnostic 在生产环境自动采集卡顿诊断数据。


小结
    

  • 60fps 意味着每帧预算 16.67ms，超时即掉帧——渲染优化的核心指标。
    • 

  • Core Animation 渲染管线分为 App 进程（布局→绘制→提交）和 Render Server（合成→显示）两阶段。
    • 

  • 离屏渲染是最常见的 GPU 性能杀手——避免 cornerRadius + clipsToBounds，使用预渲染圆角或指定 shadowPath。
    • 

  • 图层混合通过设置不透明背景色（isOpaque = true）和避免透明度来优化。
    • 

  • 光栅化（shouldRasterize）适用于内容静态的复杂图层，不适合频繁变化的内容。
    • 

  • 列表优化：使用 Prefetching 预加载、后台解码图片、缓存 cell 高度、固定尺寸优先。
    • 

  • SwiftUI 优化：实现 Equatable 减少 body 求值、使用 LazyVStack、拆分视图缩小更新范围。
    • 

  • CADisplayLink 可实时监测帧率，RunLoop Observer 可检测主线程卡顿。
