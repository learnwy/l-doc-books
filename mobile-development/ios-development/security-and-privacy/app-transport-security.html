App Transport Security 应用传输安全

概述

**App Transport Security（ATS）**是 Apple 在 iOS 9 引入的网络安全机制，强制所有通过 URLSession、WKWebView 等系统 API 发起的网络请求使用 HTTPS，并要求服务端满足最低 TLS 版本和密码套件标准。ATS 默认启用且无需任何配置，其目标是防止明文传输、中间人攻击和使用过时加密协议。

在 ATS 默认策略下，HTTP 请求会被直接拒绝。对于需要连接不支持 HTTPS 的遗留服务器，可以通过 Info.plist 配置例外。但更重要的安全实践是 证书固定（Certificate Pinning）——即使 HTTPS 连接建立成功，App 也只信任预置的特定证书或公钥，防止 CA 被攻破后的中间人攻击。iOS 14+ 引入了声明式的 NSPinnedDomains 配置，大幅简化了证书固定的实现。

证书固定（Certificate Pinning）
HTTPS 保证传输加密，但依赖 CA（证书颁发机构）信任链。如果设备上安装了恶意 CA 证书（企业 MDM、代理工具），中间人可以伪造合法证书。证书固定通过在 App 中预置信任锚点，拒绝所有非预期的证书：


NSPinnedDomains（iOS 14+）
iOS 14 引入了声明式证书固定，通过 Info.plist 配置，无需编写代码：


<key>NSAppTransportSecurity</key>
<dict>
    <key>NSPinnedDomains</key>
    <dict>
        <key>api.example.com</key>
        <dict>
            <key>NSIncludesSubdomains</key>
            <true/>
            <key>NSPinnedCAIdentities</key>
            <array>
                <dict>
                    <key>SPKI-SHA256-BASE64</key>
                    <string>YLh1dUR9y6Kja30RrAn7JKnbQG/uEtLMkBgFF2Fuihg=</string>
                </dict>
            </array>
        </dict>
    </dict>
</dict>
SPKI-SHA256-BASE64 是证书公钥的 SHA-256 哈希的 Base64 编码。可通过 OpenSSL 获取：


openssl s_client -connect api.example.com:443 -servername api.example.com < /dev/null 2>/dev/null | \
  openssl x509 -pubkey -noout | \
  openssl pkey -pubin -outform DER | \
  openssl dgst -sha256 -binary | \
  base64

URLSessionDelegate 手动验证
对于 iOS 14 以下或需要更灵活控制的场景，通过 URLSessionDelegate 手动实现证书固定：


import Foundation
import CryptoKit

class PinningSessionDelegate: NSObject, URLSessionDelegate {
    private let pinnedHashes: Set<String>

    init(pinnedHashes: Set<String>) {
        self.pinnedHashes = pinnedHashes
    }

    func urlSession(
        _ session: URLSession,
        didReceive challenge: URLAuthenticationChallenge,
        completionHandler: @escaping (URLSession.AuthChallengeDisposition, URLCredential?) -> Void
    ) {
        guard challenge.protectionSpace.authenticationMethod == NSURLAuthenticationMethodServerTrust,
              let serverTrust = challenge.protectionSpace.serverTrust else {
            completionHandler(.cancelAuthenticationChallenge, nil)
            return
        }

        let policies = [SecPolicyCreateSSL(true, challenge.protectionSpace.host as CFString)]
        SecTrustSetPolicies(serverTrust, policies as CFTypeRef)

        var error: CFError?
        guard SecTrustEvaluateWithError(serverTrust, &error) else {
            completionHandler(.cancelAuthenticationChallenge, nil)
            return
        }

        guard let certificateChain = SecTrustCopyCertificateChain(serverTrust) as? [SecCertificate] else {
            completionHandler(.cancelAuthenticationChallenge, nil)
            return
        }

        for certificate in certificateChain {
            if let publicKey = SecCertificateCopyKey(certificate) {
                var keyError: Unmanaged<CFError>?
                if let keyData = SecKeyCopyExternalRepresentation(publicKey, &keyError) as Data? {
                    let hash = SHA256.hash(data: keyData)
                    let hashBase64 = Data(hash).base64EncodedString()
                    if pinnedHashes.contains(hashBase64) {
                        completionHandler(.useCredential, URLCredential(trust: serverTrust))
                        return
                    }
                }
            }
        }

        completionHandler(.cancelAuthenticationChallenge, nil)
    }
}
使用方式
模式一：最小化 ATS 例外
只对确实需要的域名添加例外，而非全局关闭 ATS：


<key>NSAppTransportSecurity</key>
<dict>
    <key>NSAllowsLocalNetworking</key>
    <true/>
    <key>NSExceptionDomains</key>
    <dict>
        <key>legacy-internal.company.com</key>
        <dict>
            <key>NSExceptionAllowsInsecureHTTPLoads</key>
            <true/>
            <key>NSIncludesSubdomains</key>
            <false/>
        </dict>
    </dict>
</dict>
NSAllowsLocalNetworking 允许本地开发服务器使用 HTTP，而无需打开全局例外。


模式二：声明式证书固定 + 备用证书
在 NSPinnedDomains 中配置多个公钥哈希，包含当前证书和下一个证书，确保证书轮换时不中断服务：


<key>NSPinnedDomains</key>
<dict>
    <key>api.example.com</key>
    <dict>
        <key>NSIncludesSubdomains</key>
        <true/>
        <key>NSPinnedCAIdentities</key>
        <array>
            <dict>
                <key>SPKI-SHA256-BASE64</key>
                <string>YLh1dUR9y6Kja30RrAn7JKnbQG/uEtLMkBgFF2Fuihg=</string>
            </dict>
            <dict>
                <key>SPKI-SHA256-BASE64</key>
                <string>sRHdihwgkaib1P1gN7SkKPDEMoSfzeLXq3BkFPSc1r4=</string>
            </dict>
        </array>
    </dict>
</dict>
模式三：网络请求封装带固定验证
import Foundation

struct NetworkClient {
    private let session: URLSession

    init(pinnedHashes: Set<String>) {
        let delegate = PinningSessionDelegate(pinnedHashes: pinnedHashes)
        let config = URLSessionConfiguration.default
        config.tlsMinimumSupportedProtocolVersion = .TLSv12
        session = URLSession(configuration: config, delegate: delegate, delegateQueue: nil)
    }

    func request(url: URL) async throws -> (Data, URLResponse) {
        try await session.data(from: url)
    }
}

let client = NetworkClient(pinnedHashes: [
    "YLh1dUR9y6Kja30RrAn7JKnbQG/uEtLMkBgFF2Fuihg=",
    "sRHdihwgkaib1P1gN7SkKPDEMoSfzeLXq3BkFPSc1r4="
])
常见陷阱
陷阱一：全局关闭 ATS
NSAllowsArbitraryLoads = true 会彻底关闭 ATS，允许所有 HTTP 连接。这不仅是安全隐患，App Store 审核也会要求提供合理理由。除非 App 本身是浏览器或需要加载任意用户内容，否则不应使用此选项：


<key>NSAllowsArbitraryLoads</key>
<true/>
正确做法是逐个域名配置例外，或使用 NSAllowsArbitraryLoadsInWebContent 仅放开 WebView 的限制。


陷阱二：证书固定不含备用证书
如果只固定当前证书的公钥，当服务端更换证书时，所有已发布的 App 版本将无法连接服务器。必须至少固定两个公钥——当前证书和下一个计划使用的证书（或中间 CA 证书）：


陷阱三：ATS 例外配置中子域名不生效
NSExceptionDomains 中的域名默认不包含子域名。如果 API 分布在 api.example.com 和 cdn.example.com 等子域名上，必须显式设置 NSIncludesSubdomains 为 true，或分别为每个子域名添加条目。


陷阱四：URLSessionDelegate 中错误地信任所有证书
开发调试时，有些开发者为绕过证书问题而在 delegate 中无条件信任所有证书。如果这段代码泄漏到生产环境，等于完全禁用了 HTTPS 的安全保障：


func urlSession(
    _ session: URLSession,
    didReceive challenge: URLAuthenticationChallenge,
    completionHandler: @escaping (URLSession.AuthChallengeDisposition, URLCredential?) -> Void
) {
    let credential = URLCredential(trust: challenge.protectionSpace.serverTrust!)
    completionHandler(.useCredential, credential)
}
生产代码中绝不能出现上述写法。应通过编译标志（#if DEBUG）严格隔离调试代码。


小结
    

  • ATS 默认强制 HTTPS + TLS 1.2+ + 前向保密 + CA 签发证书，保护网络传输安全。
    • 

  • 通过 Info.plist 的 NSAppTransportSecurity 配置例外，应最小化例外范围，逐域名配置而非全局关闭。
    • 

  • NSAllowsLocalNetworking 可单独放开本地网络，适合开发调试场景。
    • 

  • 证书固定防止 CA 被攻破后的中间人攻击，固定公钥哈希（SPKI）比固定证书更稳定。
    • 

  • NSPinnedDomains（iOS 14+）提供声明式证书固定，仅需 Info.plist 配置，覆盖所有网络请求。
    • 

  • 通过 URLSessionDelegate 的 didReceive challenge 方法可实现自定义证书验证逻辑，兼容 iOS 14 以下版本。
    • 

  • 证书固定必须包含备用证书（至少两个公钥哈希），防止证书轮换导致服务中断。
    • 

  • 生产代码中绝不能无条件信任所有证书，调试代码必须通过 #if DEBUG 隔离。
    •
