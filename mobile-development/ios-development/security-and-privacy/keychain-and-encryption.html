Keychain 与加密

概述

iOS 提供了 Keychain Services 作为系统级安全存储机制，用于持久化保存密码、密钥、证书等敏感数据。Keychain 数据经过硬件加密，独立于 App 沙盒，即使 App 被删除后重装数据仍可保留（取决于访问控制配置）。与 UserDefaults 或文件存储不同，Keychain 不会以明文形式暴露在设备备份中。

除了安全存储，Apple 在 iOS 13 引入了 CryptoKit 框架，提供 Swift 原生的加密能力——哈希摘要（SHA256/SHA384/SHA512）、对称加密（AES-GCM/ChaChaPoly）、非对称签名与密钥协商（Curve25519/P256）。CryptoKit 替代了繁琐的 CommonCrypto C API，让加密操作类型安全且符合 Swift 习惯。

核心概念
Keychain 数据模型
Keychain 中的每条记录称为 Keychain Item，由一组属性（attributes）描述。最重要的属性是 kSecClass，决定了记录的类型：






kSecClass 值
用途
典型场景





kSecClassGenericPassword
通用密码

kSecClassInternetPassword

带 URL/端口的凭证




kSecClassCertificate

CRUD 操作
Keychain 的核心 API 是四个 C 函数，操作 CFDictionary 格式的查询字典：


import Foundation
import Security

let account = "user@example.com"
let tokenData = "access_token_abc123".data(using: .utf8)!

let addQuery: [String: Any] = [
    kSecClass as String: kSecClassGenericPassword,
    kSecAttrAccount as String: account,
    kSecAttrService as String: "com.app.auth",
    kSecValueData as String: tokenData
]
SecItemDelete(addQuery as CFDictionary)
let addStatus = SecItemAdd(addQuery as CFDictionary, nil)

var searchQuery: [String: Any] = [
    kSecClass as String: kSecClassGenericPassword,
    kSecAttrAccount as String: account,
    kSecAttrService as String: "com.app.auth",
    kSecReturnData as String: true,
    kSecMatchLimit as String: kSecMatchLimitOne
]
var result: AnyObject?
let searchStatus = SecItemCopyMatching(searchQuery as CFDictionary, &result)

let updateQuery: [String: Any] = [
    kSecClass as String: kSecClassGenericPassword,
    kSecAttrAccount as String: account,
    kSecAttrService as String: "com.app.auth"
]
let newData = "new_token_xyz".data(using: .utf8)!
let updateAttributes: [String: Any] = [kSecValueData as String: newData]
let updateStatus = SecItemUpdate(updateQuery as CFDictionary, updateAttributes as CFDictionary)

let deleteQuery: [String: Any] = [
    kSecClass as String: kSecClassGenericPassword,
    kSecAttrAccount as String: account,
    kSecAttrService as String: "com.app.auth"
]
let deleteStatus = SecItemDelete(deleteQuery as CFDictionary)
所有函数返回 OSStatus，成功为 errSecSuccess（0），常见错误码包括 errSecItemNotFound（-25300）和 errSecDuplicateItem（-25299）。


访问控制（kSecAttrAccessible）
kSecAttrAccessible 控制 Keychain Item 何时可被访问，与设备锁屏状态直接相关：






访问级别
含义





kSecAttrAccessibleWhenUnlocked
设备解锁时可用（默认值）




kSecAttrAccessibleAfterFirstUnlock
首次解锁后始终可用，适合后台刷新




kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly
仅设备有密码时可用，删除密码后自动清除




kSecAttrAccessibleWhenUnlockedThisDeviceOnly
解锁时可用，不迁移到新设备





带 ThisDeviceOnly 后缀的选项不会通过 iCloud 备份或设备迁移传输，安全性更高。


CryptoKit 哈希摘要
CryptoKit 提供 SHA256、SHA384、SHA512 三种哈希算法，API 极其简洁：


import CryptoKit

let message = "Hello, CryptoKit!".data(using: .utf8)!
let digest = SHA256.hash(data: message)
let hexString = digest.map { String(format: "%02x", $0) }.joined()
CryptoKit 对称加密（AES-GCM）
AES-GCM 提供认证加密——同时保证数据的机密性和完整性：


import CryptoKit

let key = SymmetricKey(size: .bits256)

let plaintext = "敏感用户数据".data(using: .utf8)!
let sealedBox = try AES.GCM.seal(plaintext, using: key)

let combined = sealedBox.combined!

let reopenedBox = try AES.GCM.SealedBox(combined: combined)
let decrypted = try AES.GCM.open(reopenedBox, using: key)
let originalText = String(data: decrypted, encoding: .utf8)
combined 包含 nonce + 密文 + tag，可安全存储或传输。


CryptoKit 非对称密钥（Curve25519）
Curve25519 用于密钥协商（ECDH）和数字签名：


import CryptoKit

let alicePrivateKey = Curve25519.KeyAgreement.PrivateKey()
let alicePublicKey = alicePrivateKey.publicKey

let bobPrivateKey = Curve25519.KeyAgreement.PrivateKey()
let bobPublicKey = bobPrivateKey.publicKey

let aliceSharedSecret = try alicePrivateKey.sharedSecretFromKeyAgreement(with: bobPublicKey)
let bobSharedSecret = try bobPrivateKey.sharedSecretFromKeyAgreement(with: alicePublicKey)

let symmetricKey = aliceSharedSecret.hkdfDerivedSymmetricKey(
    using: SHA256.self,
    salt: Data(),
    sharedInfo: "encryption".data(using: .utf8)!,
    outputByteCount: 32
)
使用方式
模式一：封装 KeychainManager
将底层 C API 封装为类型安全的 Swift 接口：


enum KeychainError: Error {
    case duplicateItem
    case itemNotFound
    case unexpectedStatus(OSStatus)
}

struct KeychainManager {
    static func save(key: String, data: Data, service: String = Bundle.main.bundleIdentifier!) throws {
        let query: [String: Any] = [
            kSecClass as String: kSecClassGenericPassword,
            kSecAttrAccount as String: key,
            kSecAttrService as String: service,
            kSecValueData as String: data,
            kSecAttrAccessible as String: kSecAttrAccessibleWhenUnlockedThisDeviceOnly
        ]

        let status = SecItemAdd(query as CFDictionary, nil)
        if status == errSecDuplicateItem {
            let updateAttrs: [String: Any] = [kSecValueData as String: data]
            let updateStatus = SecItemUpdate(query as CFDictionary, updateAttrs as CFDictionary)
            guard updateStatus == errSecSuccess else {
                throw KeychainError.unexpectedStatus(updateStatus)
            }
        } else if status != errSecSuccess {
            throw KeychainError.unexpectedStatus(status)
        }
    }

    static func load(key: String, service: String = Bundle.main.bundleIdentifier!) throws -> Data {
        let query: [String: Any] = [
            kSecClass as String: kSecClassGenericPassword,
            kSecAttrAccount as String: key,
            kSecAttrService as String: service,
            kSecReturnData as String: true,
            kSecMatchLimit as String: kSecMatchLimitOne
        ]

        var result: AnyObject?
        let status = SecItemCopyMatching(query as CFDictionary, &result)
        guard status == errSecSuccess, let data = result as? Data else {
            throw status == errSecItemNotFound
                ? KeychainError.itemNotFound
                : KeychainError.unexpectedStatus(status)
        }
        return data
    }

    static func delete(key: String, service: String = Bundle.main.bundleIdentifier!) throws {
        let query: [String: Any] = [
            kSecClass as String: kSecClassGenericPassword,
            kSecAttrAccount as String: key,
            kSecAttrService as String: service
        ]

        let status = SecItemDelete(query as CFDictionary)
        guard status == errSecSuccess || status == errSecItemNotFound else {
            throw KeychainError.unexpectedStatus(status)
        }
    }
}
模式二：加密存储 Codable 对象
结合 CryptoKit AES-GCM 和 Keychain，先加密再存储：


struct SecureStorage {
    private let encryptionKey: SymmetricKey

    init() throws {
        let tag = "com.app.encryption.key"
        if let existingKeyData = try? KeychainManager.load(key: tag) {
            encryptionKey = SymmetricKey(data: existingKeyData)
        } else {
            let newKey = SymmetricKey(size: .bits256)
            let keyData = newKey.withUnsafeBytes { Data($0) }
            try KeychainManager.save(key: tag, data: keyData)
            encryptionKey = newKey
        }
    }

    func save<T: Encodable>(_ value: T, forKey key: String) throws {
        let plaintext = try JSONEncoder().encode(value)
        let sealedBox = try AES.GCM.seal(plaintext, using: encryptionKey)
        try KeychainManager.save(key: key, data: sealedBox.combined!)
    }

    func load<T: Decodable>(forKey key: String, as type: T.Type) throws -> T {
        let combined = try KeychainManager.load(key: key)
        let sealedBox = try AES.GCM.SealedBox(combined: combined)
        let plaintext = try AES.GCM.open(sealedBox, using: encryptionKey)
        return try JSONDecoder().decode(T.self, from: plaintext)
    }
}
模式三：数字签名验证
使用 Curve25519 对消息进行签名和验证，常用于 API 请求防篡改：


import CryptoKit

struct MessageSigner {
    private let privateKey: Curve25519.Signing.PrivateKey

    init() {
        privateKey = Curve25519.Signing.PrivateKey()
    }

    var publicKeyData: Data {
        privateKey.publicKey.rawRepresentation
    }

    func sign(data: Data) throws -> Data {
        try privateKey.signature(for: data)
    }

    static func verify(signature: Data, data: Data, publicKeyData: Data) throws -> Bool {
        let publicKey = try Curve25519.Signing.PublicKey(rawRepresentation: publicKeyData)
        return publicKey.isValidSignature(signature, for: data)
    }
}
常见陷阱
陷阱一：errSecDuplicateItem 未处理
SecItemAdd 在记录已存在时返回 -25299（errSecDuplicateItem），而非覆盖。直接忽略返回值会导致数据更新失败但无任何提示：


SecItemAdd(query as CFDictionary, nil)
正确做法是先尝试添加，失败后用 SecItemUpdate 覆盖——或先删除再添加。KeychainManager 的封装中已包含此逻辑。


陷阱二：模拟器与真机 Keychain 行为差异
模拟器上的 Keychain 不要求设备密码，kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly 在模拟器上行为与真机不同。访问控制相关代码必须在真机上测试。此外，模拟器上不同 App 可能共享同一个 Keychain（取决于签名），而真机上严格按 Keychain Group 隔离。


陷阱三：密钥存储在代码中
将加密密钥硬编码在源码中是严重的安全漏洞——攻击者可以通过逆向工程轻松提取。密钥应存储在 Keychain 中，或通过服务端安全分发：


let key = SymmetricKey(size: .bits256)
let keyData = key.withUnsafeBytes { Data($0) }
try KeychainManager.save(key: "app.encryption.key", data: keyData)
陷阱四：kSecAttrAccessible 默认值不适合后台任务
默认的 kSecAttrAccessibleWhenUnlocked 在设备锁屏时无法访问 Keychain。如果 App 需要在后台刷新中读取凭证，必须使用 kSecAttrAccessibleAfterFirstUnlock：


let query: [String: Any] = [
    kSecClass as String: kSecClassGenericPassword,
    kSecAttrAccount as String: "refreshToken",
    kSecAttrService as String: "com.app.auth",
    kSecValueData as String: tokenData,
    kSecAttrAccessible as String: kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly
]
小结
    

  • Keychain Services 是 iOS 上存储密码、密钥等敏感数据的首选方案，数据经过硬件级加密，独立于 App 沙盒。
    • 

  • 核心 API 为四个 C 函数：SecItemAdd（添加）、SecItemCopyMatching（查询）、SecItemUpdate（更新）、SecItemDelete（删除），操作 CFDictionary 查询字典。
    • 

  • kSecClass 定义记录类型，最常用的是 kSecClassGenericPassword（通用密码）。
    • 

  • kSecAttrAccessible 控制 Keychain Item 的可用时机，带 ThisDeviceOnly 后缀的选项不会迁移到新设备。
    • 

  • CryptoKit 提供 Swift 原生加密能力：SHA256 哈希摘要、AES.GCM 认证加密、Curve25519 非对称签名与密钥协商。
    • 

  • 实际项目中应将 Keychain C API 封装为类型安全的 Swift 接口（如 KeychainManager），统一错误处理。
    • 

  • 加密密钥绝不能硬编码在源码中，应存储在 Keychain 或通过安全通道获取。
    • 

  • 访问控制相关行为在模拟器与真机之间存在差异，必须在真机上验证。
    •
