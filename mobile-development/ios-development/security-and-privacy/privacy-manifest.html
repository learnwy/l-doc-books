隐私清单与 ATT

概述

Apple 从 2023 年起逐步推行**隐私清单（Privacy Manifest）**机制，要求 App 和第三方 SDK 通过 PrivacyInfo.xcprivacy 文件声明数据收集类型、使用目的、以及调用的受限 API。与此同时，**App Tracking Transparency（ATT）**框架要求 App 在追踪用户或访问 IDFA 前必须获得用户明确授权。这两个机制共同构成了 iOS 隐私保护的核心：隐私清单回答「App 收集什么数据、为什么收集」，ATT 回答「是否允许跨 App 追踪」。

从 2024 年春季起，App Store 要求所有新提交和更新的 App 包含隐私清单，并对使用特定「必需理由 API（Required Reason API）」的 App 强制声明调用理由。不符合要求的 App 会在审核阶段收到警告甚至被拒。理解隐私清单的结构、ATT 的授权流程、以及 SKAdNetwork 归因机制，是上架合规的必备知识。

ATTrackingManager 与 IDFA
**IDFA（Identifier for Advertisers）**是 Apple 分配给每台设备的广告标识符。iOS 14.5 起，App 必须通过 ATT 框架获得用户授权才能访问 IDFA：


import AppTrackingTransparency
import AdSupport

func requestTrackingPermission() {
    ATTrackingManager.requestTrackingAuthorization { status in
        switch status {
        case .authorized:
            let idfa = ASIdentifierManager.shared().advertisingIdentifier
            print("IDFA: \(idfa)")
        case .denied:
            print("用户拒绝追踪")
        case .restricted:
            print("追踪受限（家长控制等）")
        case .notDetermined:
            print("尚未请求授权")
        @unknown default:
            break
        }
    }
}
ATT 授权弹窗文案通过 Info.plist 的 NSUserTrackingUsageDescription 配置：


<key>NSUserTrackingUsageDescription</key>
<string>我们需要您的许可来提供个性化广告体验，您的数据不会用于其他目的</string>
NSPrivacyTrackingDomains
当 NSPrivacyTracking 为 true 时，NSPrivacyTrackingDomains 列出所有用于追踪的网络域名。如果用户拒绝 ATT 授权，iOS 会自动阻止向这些域名发起的网络请求：


<key>NSPrivacyTracking</key>
<true/>
<key>NSPrivacyTrackingDomains</key>
<array>
    <string>analytics.example.com</string>
    <string>tracking.adnetwork.com</string>
</array>
这意味着不需要在代码中手动检查 ATT 状态来决定是否发送追踪请求——系统层面已经强制执行。


SKAdNetwork
SKAdNetwork 是 Apple 提供的隐私安全广告归因框架。它允许广告网络在不获取 IDFA 的情况下衡量广告效果：


<key>SKAdNetworkItems</key>
<array>
    <dict>
        <key>SKAdNetworkIdentifier</key>
        <string>cstr6suwn9.skadnetwork</string>
    </dict>
    <dict>
        <key>SKAdNetworkIdentifier</key>
        <string>4fzdc2evr5.skadnetwork</string>
    </dict>
</array>

使用方式
模式一：完整的 ATT 授权管理
import AppTrackingTransparency
import AdSupport

struct TrackingManager {
    static var isTrackingAuthorized: Bool {
        ATTrackingManager.trackingAuthorizationStatus == .authorized
    }

    static func requestAuthorizationIfNeeded() async -> ATTrackingManager.AuthorizationStatus {
        let currentStatus = ATTrackingManager.trackingAuthorizationStatus
        if currentStatus == .notDetermined {
            return await ATTrackingManager.requestTrackingAuthorization()
        }
        return currentStatus
    }

    static var advertisingIdentifier: String? {
        guard isTrackingAuthorized else { return nil }
        let idfa = ASIdentifierManager.shared().advertisingIdentifier
        guard idfa != UUID(uuidString: "00000000-0000-0000-0000-000000000000") else {
            return nil
        }
        return idfa.uuidString
    }

    static func configureAnalytics() async {
        let status = await requestAuthorizationIfNeeded()
        switch status {
        case .authorized:
            initializeFullAnalytics()
        case .denied, .restricted:
            initializePrivacyFriendlyAnalytics()
        case .notDetermined:
            break
        @unknown default:
            initializePrivacyFriendlyAnalytics()
        }
    }

    private static func initializeFullAnalytics() {
        print("初始化完整分析（含 IDFA）")
    }

    private static func initializePrivacyFriendlyAnalytics() {
        print("初始化隐私友好分析（无 IDFA）")
    }
}
模式二：SwiftUI 中的 ATT 请求时机
ATT 弹窗应在 App 完成启动后、用户理解追踪价值后再展示，而非在 application(_:didFinishLaunchingWithOptions:) 中立即弹出：


import SwiftUI
import AppTrackingTransparency

struct OnboardingView: View {
    @State private var currentStep = 0
    @State private var trackingRequested = false

    var body: some View {
        VStack {
            switch currentStep {
            case 0:
                WelcomeStepView {
                    currentStep = 1
                }
            case 1:
                FeatureHighlightView {
                    currentStep = 2
                }
            case 2:
                TrackingExplanationView {
                    requestTracking()
                }
            default:
                MainAppView()
            }
        }
    }

    private func requestTracking() {
        ATTrackingManager.requestTrackingAuthorization { _ in
            DispatchQueue.main.async {
                currentStep = 3
            }
        }
    }
}
模式三：隐私清单的第三方 SDK 聚合
当 App 集成多个第三方 SDK 时，每个 SDK 应包含自己的 PrivacyInfo.xcprivacy。Xcode 15+ 在生成 Privacy Report 时会自动聚合所有 Framework 的隐私清单：


import Foundation

struct PrivacyComplianceChecker {
    static func generateReport() {
        let frameworks = Bundle.allFrameworks
        var apisUsed: [String] = []

        for framework in frameworks {
            let privacyURL = framework.url(forResource: "PrivacyInfo", withExtension: "xcprivacy")
            if let url = privacyURL {
                print("发现隐私清单：\(framework.bundleIdentifier ?? "unknown") -> \(url)")
                apisUsed.append(framework.bundleIdentifier ?? "unknown")
            }
        }

        print("包含隐私清单的 Framework 数量：\(apisUsed.count)")
    }
}
在 Xcode 中，通过 Product → Archive → Generate Privacy Report 可以导出完整的隐私报告 PDF，确认所有声明是否完整。


常见陷阱
陷阱一：过早弹出 ATT 授权对话框
在 App 启动时立即弹出 ATT 对话框，用户还未理解 App 的价值，大概率会拒绝。研究表明，在适当时机（如引导页结束后、首次展示广告前）展示并解释追踪用途，授权率可提升 30-50%：


func application(
    _ application: UIApplication,
    didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
) -> Bool {
    ATTrackingManager.requestTrackingAuthorization { _ in }
    return true
}
上面的代码看起来简单，实际上可能在 App 的 UI 尚未完全加载时弹出对话框，导致用户体验和授权率双双下降。


陷阱二：遗漏必需理由 API 声明
UserDefaults、FileManager 的时间戳属性、ProcessInfo.systemUptime 等日常 API 都被列为必需理由 API。许多开发者不知道自己的代码（或依赖的 SDK）调用了这些 API，导致审核时收到警告。应使用 Xcode 的 Privacy Report 功能全面检查：


陷阱三：NSPrivacyTracking 设为 true 但未实现 ATT
如果隐私清单中 NSPrivacyTracking 为 true，但 App 未集成 ATT 框架或未调用 requestTrackingAuthorization，系统会在用户未授权的情况下自动阻断 NSPrivacyTrackingDomains 中的网络请求，可能导致功能异常。


陷阱四：SKAdNetwork 标识符列表过期
广告网络会定期更新其 SKAdNetwork 标识符。如果 Info.plist 中的 SKAdNetworkItems 列表过期，广告归因数据可能丢失，影响广告投放效果和收入。应在每次发版前更新此列表，或使用广告平台提供的自动集成工具。


小结
    

  • **隐私清单（PrivacyInfo.xcprivacy）**是 App Store 合规的必备文件，声明数据收集类型、追踪行为和受限 API 使用理由。
    • 

  • NSPrivacyTracking 声明是否追踪，NSPrivacyTrackingDomains 列出追踪域名——用户拒绝 ATT 后系统自动阻断这些域名的请求。
    • 

  • NSPrivacyCollectedDataTypes 需为每种收集的数据类型声明关联性、追踪用途和收集目的。
    • 

  • 必需理由 API 包括 UserDefaults、文件时间戳、系统启动时间等常见 API，必须在隐私清单中声明调用理由码。
    • 

  • ATTrackingManager 是访问 IDFA 的前置条件，授权弹窗应在用户理解价值后再展示，而非启动时立即弹出。
    • 

  • IDFA 在用户拒绝追踪后返回全零 UUID，App 应在此状态下回退到隐私友好的分析方案。
    • 

  • SKAdNetwork 提供不依赖 IDFA 的广告归因，通过转化值和系统回传衡量广告效果。
    • 

  • 第三方 SDK 应各自包含隐私清单，Xcode 15+ 可自动聚合生成 Privacy Report。
    • 

  • 每次发版前应检查必需理由 API 声明的完整性和 SKAdNetwork 标识符列表的时效性。
    •
