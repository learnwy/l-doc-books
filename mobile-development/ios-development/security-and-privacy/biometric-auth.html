Part I · iOSiOS 开发 简介安全与隐私 简介生物认证

生物认证

概述

iOS 设备支持两种生物识别认证方式：Face ID（面容识别）和 Touch ID（指纹识别）。Apple 通过 LocalAuthentication 框架提供统一的生物认证 API，开发者无需关心底层硬件差异，只需调用 LAContext 即可发起认证请求。生物识别数据存储在设备的 Secure Enclave 芯片中，永远不会离开设备，也不会被 App 或操作系统访问。

生物认证是保护敏感操作（支付确认、密码查看、App 解锁）的标准手段。正确实现生物认证需要处理多种场景：设备不支持生物识别、用户未注册面容/指纹、认证失败后的回退方案、以及 Face ID 必须的隐私说明配置。

核心概念
LAContext
LAContext 是 LocalAuthentication 框架的核心类，代表一个认证上下文。每次认证应创建新的 LAContext 实例：


import LocalAuthentication

let context = LAContext()

canEvaluatePolicy — 能力检测
在发起认证前，必须先调用 canEvaluatePolicy 检测设备是否支持生物认证：


import LocalAuthentication

let context = LAContext()
var error: NSError?

if context.canEvaluatePolicy(.deviceOwnerAuthenticationWithBiometrics, error: &error) {
    switch context.biometryType {
    case .faceID:
        print("支持 Face ID")
    case .touchID:
        print("支持 Touch ID")
    case .opticID:
        print("支持 Optic ID")
    @unknown default:
        print("未知生物识别类型")
    }
} else {
    if let error = error {
        switch LAError.Code(rawValue: error.code) {
        case .biometryNotAvailable:
            print("设备不支持生物识别")
        case .biometryNotEnrolled:
            print("用户未注册生物识别")
        case .biometryLockout:
            print("多次失败已锁定，需输入设备密码")
        default:
            print("其他错误：\(error.localizedDescription)")
        }
    }
}
两种常用策略：






策略
说明





.deviceOwnerAuthenticationWithBiometrics
仅生物识别，失败不自动回退设备密码




.deviceOwnerAuthentication

evaluatePolicy — 发起认证
import LocalAuthentication

func authenticateUser() async throws -> Bool {
    let context = LAContext()
    context.localizedCancelTitle = "取消"
    context.localizedFallbackTitle = "使用密码"

    var error: NSError?
    guard context.canEvaluatePolicy(.deviceOwnerAuthenticationWithBiometrics, error: &error) else {
        throw error ?? LAError(.biometryNotAvailable)
    }

    return try await context.evaluatePolicy(
        .deviceOwnerAuthenticationWithBiometrics,
        localizedReason: "验证身份以查看敏感信息"
    )
}
localizedReason 是必填参数，描述认证用途，会展示在系统弹窗中。对于 Face ID，用户还会看到 Info.plist 中配置的使用说明。


Face ID 的 Info.plist 配置
使用 Face ID 的 App 必须在 Info.plist 中声明 NSFaceIDUsageDescription，否则 App 调用认证时直接崩溃：


<key>NSFaceIDUsageDescription</key>
<string>需要使用面容 ID 验证您的身份以保护账户安全</string>
Touch ID 不需要此配置，但统一添加是最佳实践。

Keychain 集成
生物认证可以直接绑定到 Keychain 项的访问控制中，在读取时自动弹出认证：


import Security
import LocalAuthentication

let accessControl = SecAccessControlCreateWithFlags(
    nil,
    kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly,
    .biometryCurrentSet,
    nil
)!

let addQuery: [String: Any] = [
    kSecClass as String: kSecClassGenericPassword,
    kSecAttrAccount as String: "user_secret",
    kSecAttrService as String: "com.app.secrets",
    kSecValueData as String: "top_secret".data(using: .utf8)!,
    kSecAttrAccessControl as String: accessControl
]
SecItemAdd(addQuery as CFDictionary, nil)

let context = LAContext()
context.localizedReason = "访问安全数据"

let searchQuery: [String: Any] = [
    kSecClass as String: kSecClassGenericPassword,
    kSecAttrAccount as String: "user_secret",
    kSecAttrService as String: "com.app.secrets",
    kSecReturnData as String: true,
    kSecUseAuthenticationContext as String: context
]

var result: AnyObject?
let status = SecItemCopyMatching(searchQuery as CFDictionary, &result)
.biometryCurrentSet 表示使用当前注册的生物信息——如果用户重新注册了面容/指纹，旧的 Keychain 项将无法访问，这提供了额外的安全保障。


使用方式
模式一：完整的认证管理器
import LocalAuthentication

enum BiometricAuthError: Error {
    case notAvailable
    case notEnrolled
    case lockedOut
    case cancelled
    case failed(String)
}

struct BiometricAuthManager {
    enum BiometricType {
        case faceID
        case touchID
        case none
    }

    static var availableBiometricType: BiometricType {
        let context = LAContext()
        var error: NSError?
        guard context.canEvaluatePolicy(.deviceOwnerAuthenticationWithBiometrics, error: &error) else {
            return .none
        }
        switch context.biometryType {
        case .faceID: return .faceID
        case .touchID: return .touchID
        default: return .none
        }
    }

    static func authenticate(reason: String) async throws {
        let context = LAContext()
        context.localizedCancelTitle = "取消"
        context.localizedFallbackTitle = "使用密码"

        var error: NSError?
        guard context.canEvaluatePolicy(.deviceOwnerAuthenticationWithBiometrics, error: &error) else {
            throw mapError(error)
        }

        do {
            try await context.evaluatePolicy(.deviceOwnerAuthenticationWithBiometrics, localizedReason: reason)
        } catch let authError as LAError {
            throw mapLAError(authError)
        }
    }

    private static func mapError(_ error: NSError?) -> BiometricAuthError {
        guard let code = error.flatMap({ LAError.Code(rawValue: $0.code) }) else {
            return .notAvailable
        }
        switch code {
        case .biometryNotEnrolled: return .notEnrolled
        case .biometryLockout: return .lockedOut
        default: return .notAvailable
        }
    }

    private static func mapLAError(_ error: LAError) -> BiometricAuthError {
        switch error.code {
        case .userCancel: return .cancelled
        case .userFallback: return .cancelled
        case .biometryLockout: return .lockedOut
        default: return .failed(error.localizedDescription)
        }
    }
}
模式二：SwiftUI 集成
import SwiftUI

struct ProtectedView: View {
    @State private var isUnlocked = false
    @State private var showError = false
    @State private var errorMessage = ""

    var body: some View {
        Group {
            if isUnlocked {
                SecretContentView()
            } else {
                VStack(spacing: 20) {
                    Image(systemName: biometricIcon)
                        .font(.system(size: 64))
                        .foregroundStyle(.blue)

                    Text("需要验证身份")
                        .font(.title2)

                    Button("验证") {
                        Task { await unlock() }
                    }
                    .buttonStyle(.borderedProminent)
                }
            }
        }
        .alert("认证失败", isPresented: $showError) {
            Button("确定") {}
        } message: {
            Text(errorMessage)
        }
    }

    private var biometricIcon: String {
        switch BiometricAuthManager.availableBiometricType {
        case .faceID: return "faceid"
        case .touchID: return "touchid"
        case .none: return "lock"
        }
    }

    private func unlock() async {
        do {
            try await BiometricAuthManager.authenticate(reason: "验证身份以访问敏感内容")
            isUnlocked = true
        } catch {
            errorMessage = "\(error)"
            showError = true
        }
    }
}
模式三：带设备密码回退
当生物认证不可用时，自动回退到设备密码认证：


import LocalAuthentication

struct AuthService {
    static func authenticateWithFallback(reason: String) async throws -> Bool {
        let context = LAContext()

        let biometricAvailable = context.canEvaluatePolicy(
            .deviceOwnerAuthenticationWithBiometrics, error: nil
        )

        let policy: LAPolicy = biometricAvailable
            ? .deviceOwnerAuthenticationWithBiometrics
            : .deviceOwnerAuthentication

        return try await context.evaluatePolicy(policy, localizedReason: reason)
    }
}
使用 .deviceOwnerAuthentication 时，系统会自动在生物认证失败后展示设备密码输入界面，无需额外代码。


常见陷阱
陷阱一：缺少 NSFaceIDUsageDescription
在 iPhone X 及以上设备（支持 Face ID）上调用 evaluatePolicy 时，如果 Info.plist 缺少 NSFaceIDUsageDescription，App 会直接崩溃。这个错误只在 Face ID 设备上出现，在 Touch ID 设备和模拟器上可能正常运行，容易在测试阶段被遗漏。


陷阱二：复用 LAContext 实例
LAContext 是一次性对象。已认证的 LAContext 实例不应复用，否则可能跳过认证直接通过：


let context = LAContext()
try await context.evaluatePolicy(.deviceOwnerAuthenticationWithBiometrics, localizedReason: "第一次认证")

try await context.evaluatePolicy(.deviceOwnerAuthenticationWithBiometrics, localizedReason: "第二次认证")
每次需要认证时，应创建全新的 LAContext 实例。


陷阱三：仅在客户端验证
生物认证仅证明「设备前的人是设备的主人」，并不能替代服务端身份验证。正确的做法是：生物认证通过后从 Keychain 取出凭证（token/密钥），用凭证与服务端通信。不要将生物认证的布尔结果作为唯一的安全依据。


陷阱四：忽略 biometryLockout 状态
用户连续多次认证失败后，生物识别会被锁定（Face ID 5 次、Touch ID 5 次），此时 canEvaluatePolicy 返回 false，错误码为 .biometryLockout。必须使用设备密码解锁后才能重新使用生物识别。App 应在此状态下引导用户使用密码方案或前往系统设置。


小结
    

  • LocalAuthentication 框架通过 LAContext 提供统一的生物认证 API，支持 Face ID、Touch ID 和 Optic ID。
    • 

  • 认证前必须调用 canEvaluatePolicy 检测设备能力，区分硬件不支持、未注册、已锁定等状态。
    • 

  • Face ID 应用必须在 Info.plist 中配置 NSFaceIDUsageDescription，否则运行时崩溃。
    • 

  • evaluatePolicy 支持两种策略：仅生物识别（.deviceOwnerAuthenticationWithBiometrics）和生物识别+设备密码回退（.deviceOwnerAuthentication）。
    • 

  • 生物认证可通过 SecAccessControl 直接绑定到 Keychain 项，实现「认证通过才能读取」的安全模型。
    • 

  • 每次认证应创建全新的 LAContext，不要复用已认证的实例。
    • 

  • 生物认证是本地安全手段，不能替代服务端身份验证。正确模式是：认证通过 → 读取 Keychain 凭证 → 使用凭证与服务端通信。
    • 

  • 处理 .biometryLockout 锁定状态，提供密码回退或引导用户到系统设置。
    •
