Part I · iOSiOS 开发 简介Swift 进阶 简介泛型

泛型

概述

泛型（Generics）是 Swift 中最强大的特性之一，它允许编写灵活、可复用的函数和类型，能够适配任何类型，同时保持完整的编译期类型安全。Swift 标准库的绝大部分——Array、Dictionary、Optional、Result——都是泛型类型。

泛型解决的核心问题是代码重复。没有泛型，你需要为每种类型编写几乎相同的逻辑；有了泛型，一份代码就能处理所有符合约束的类型。Swift 5.1 引入的 Opaque Types（some）和 Swift 5.7 引入的 Existential Types 显式标注（any）进一步完善了泛型系统的表达能力。

核心概念
泛型函数
泛型函数使用类型参数（Type Parameter）声明在函数名后的尖括号中，编译器在调用时自动推断具体类型：


func swapValues<T>(_ a: inout T, _ b: inout T) {
    let temp = a
    a = b
    b = temp
}

var x = 10, y = 20
swapValues(&x, &y)

var s1 = "hello", s2 = "world"
swapValues(&s1, &s2)
T 是类型参数的占位符，代表"某种类型"。编译器会在每个调用点将 T 替换为实际类型（Int、String 等），并进行完整的类型检查。


多个类型参数之间用逗号分隔：


func makePair<A, B>(_ first: A, _ second: B) -> (A, B) {
    (first, second)
}

let pair = makePair("Swift", 5.9)
泛型类型
泛型不仅适用于函数，也可以定义泛型 struct、class、enum：


struct Queue<Element> {
    private var storage: [Element] = []

    var isEmpty: Bool { storage.isEmpty }
    var count: Int { storage.count }

    mutating func enqueue(_ element: Element) {
        storage.append(element)
    }

    mutating func dequeue() -> Element? {
        isEmpty ? nil : storage.removeFirst()
    }

    var peek: Element? {
        storage.first
    }
}

var intQueue = Queue<Int>()
intQueue.enqueue(1)
intQueue.enqueue(2)
print(intQueue.dequeue())

var stringQueue = Queue<String>()
stringQueue.enqueue("Alpha")
stringQueue.enqueue("Beta")
同一个 Queue 定义可以用于任何元素类型，编译器为每种使用生成类型安全的代码。


类型约束（where 子句）
无约束的类型参数只能进行最基本的操作（赋值、传参）。要对类型参数进行有意义的操作，需要添加类型约束：


func findIndex<T: Equatable>(of value: T, in array: [T]) -> Int? {
    for (index, element) in array.enumerated() {
        if element == value {
            return index
        }
    }
    return nil
}
where 子句提供更灵活的约束表达：


func merge<C1: Collection, C2: Collection>(
    _ first: C1,
    _ second: C2
) -> [C1.Element] where C1.Element == C2.Element, C1.Element: Comparable {
    (Array(first) + Array(second)).sorted()
}

let result = merge([3, 1, 4], [1, 5, 9])

关联类型
关联类型是协议中的"泛型参数"，由遵循者决定具体类型。关联类型可以带默认值和约束：


protocol DataStore {
    associatedtype Key: Hashable
    associatedtype Value
    associatedtype Err: Error = Never

    func get(_ key: Key) -> Result<Value, Err>
    mutating func set(_ key: Key, value: Value) throws
}

struct InMemoryStore<V>: DataStore {
    typealias Key = String
    typealias Value = V

    private var data: [String: V] = [:]

    func get(_ key: String) -> Result<V, Never> {
        if let value = data[key] {
            return .success(value)
        }
        fatalError("Key not found: \(key)")
    }

    mutating func set(_ key: String, value: V) {
        data[key] = value
    }
}
当关联类型有默认值（如 Err: Error = Never）时，遵循者可以不指定该类型。


泛型下标
Swift 支持为泛型类型定义泛型下标：


extension Queue {
    subscript<Indices: Sequence>(indices: Indices) -> [Element]
        where Indices.Element == Int
    {
        indices.compactMap { index in
            guard index >= 0 && index < count else { return nil }
            return storage[index]
        }
    }
}

var q = Queue<String>()
q.enqueue("a")
q.enqueue("b")
q.enqueue("c")
let selected = q[[0, 2]]
类型擦除：any、some 与 AnyX
Swift 的泛型系统中有三种处理协议类型的方式，理解它们的区别至关重要：


Opaque Types（some）
some 表示"某个确定的类型，但调用者不知道具体是什么"。编译器知道实际类型，可以进行静态派发和优化：


func makeShape() -> some Shape {
    Circle(center: .zero, radius: 10)
}

let shape = makeShape()
some 常用于 SwiftUI 中的 some View：


var body: some View {
    Text("Hello")
}
关键限制：同一个函数的 some 返回类型在所有代码路径中必须返回相同的具体类型。


Existential Types（any）
any 表示"任何遵循该协议的类型"，允许存储不同的具体类型：


var shapes: [any Shape] = [
    Circle(center: .zero, radius: 5),
    Rectangle(origin: .zero, size: CGSize(width: 10, height: 20))
]

func printArea(of shape: any Shape) {
    print("面积：\(shape.area)")
}

for shape in shapes {
    printArea(of: shape)
}
any 使用 existential container 进行运行时分派，有额外的内存和性能开销。


手动类型擦除（AnyX）
在 Swift 5.7 之前，带关联类型的协议无法直接用作类型，需要手动编写类型擦除包装器：


protocol Transformer {
    associatedtype Input
    associatedtype Output
    func transform(_ input: Input) -> Output
}

struct AnyTransformer<I, O>: Transformer {
    typealias Input = I
    typealias Output = O

    private let _transform: (I) -> O

    init<T: Transformer>(_ base: T) where T.Input == I, T.Output == O {
        _transform = base.transform
    }

    func transform(_ input: I) -> O {
        _transform(input)
    }
}

struct UppercaseTransformer: Transformer {
    func transform(_ input: String) -> String {
        input.uppercased()
    }
}

let erased = AnyTransformer(UppercaseTransformer())
print(erased.transform("hello"))
在 Swift 5.7+ 中，多数场景可以直接使用 any Transformer 代替手动擦除。

使用方式
模式一：泛型 Repository 抽象数据层
使用泛型定义统一的数据仓库接口，不同的存储后端只需遵循协议：


protocol Repository<Model> {
    associatedtype Model: Identifiable

    func findAll() async throws -> [Model]
    func find(by id: Model.ID) async throws -> Model?
    mutating func save(_ model: Model) async throws
    mutating func delete(by id: Model.ID) async throws
}

struct User: Identifiable, Codable {
    let id: UUID
    var name: String
    var email: String
}

struct InMemoryRepository<M: Identifiable>: Repository {
    typealias Model = M

    private var store: [M.ID: M] = [:]

    func findAll() async throws -> [M] {
        Array(store.values)
    }

    func find(by id: M.ID) async throws -> M? {
        store[id]
    }

    mutating func save(_ model: M) async throws {
        store[model.id] = model
    }

    mutating func delete(by id: M.ID) async throws {
        store.removeValue(forKey: id)
    }
}
模式二：泛型结果构建器
利用泛型构建类型安全的构建器模式：


struct RequestBuilder<Body: Encodable> {
    private(set) var method: String = "GET"
    private(set) var url: URL
    private(set) var headers: [String: String] = [:]
    private(set) var body: Body?

    init(url: URL) {
        self.url = url
    }

    func method(_ method: String) -> RequestBuilder {
        var copy = self
        copy.method = method
        return copy
    }

    func header(_ key: String, _ value: String) -> RequestBuilder {
        var copy = self
        copy.headers[key] = value
        return copy
    }

    func body(_ body: Body) -> RequestBuilder {
        var copy = self
        copy.body = body
        return copy
    }

    func build() throws -> URLRequest {
        var request = URLRequest(url: url)
        request.httpMethod = method
        headers.forEach { request.setValue($1, forHTTPHeaderField: $0) }
        if let body {
            request.httpBody = try JSONEncoder().encode(body)
            request.setValue("application/json", forHTTPHeaderField: "Content-Type")
        }
        return request
    }
}

struct CreateUserBody: Encodable {
    let name: String
    let email: String
}

let request = try RequestBuilder<CreateUserBody>(
    url: URL(string: "https://api.example.com/users")!
)
.method("POST")
.header("Authorization", "Bearer token")
.body(CreateUserBody(name: "小明", email: "ming@example.com"))
.build()
模式三：利用 where 子句为集合添加受约束的扩展
extension Collection where Element: Numeric {
    var average: Double {
        guard !isEmpty else { return 0 }
        let sum = reduce(0, +)
        return Double("\(sum)")! / Double(count)
    }
}

extension Collection where Element: Comparable {
    var minMax: (min: Element, max: Element)? {
        guard let first = first else { return nil }
        return reduce((first, first)) { result, element in
            (min(result.0, element), max(result.1, element))
        }
    }
}

extension RangeReplaceableCollection where Element: Equatable {
    mutating func removeAllDuplicates() {
        var seen: [Element] = []
        removeAll { element in
            if seen.contains(element) {
                return true
            }
            seen.append(element)
            return false
        }
    }
}

var numbers = [1, 3, 2, 3, 1, 4, 2]
numbers.removeAllDuplicates()
print(numbers)
常见陷阱
陷阱一：some 返回类型必须一致
some 要求所有代码路径返回完全相同的具体类型，否则编译报错：


func makeView(isLoggedIn: Bool) -> some View {
    // if isLoggedIn {
    //     Text("Welcome")   ← 返回 Text
    // } else {
    //     Image("login")    ← 返回 Image，类型不同！编译错误
    // }

    Group {
        if isLoggedIn {
            Text("Welcome")
        } else {
            Image("login")
        }
    }
}
解决方案：使用 @ViewBuilder、AnyView、Group 或条件表达式统一返回类型。


陷阱二：泛型约束过少导致编译错误
忘记添加必要的约束时，编译器无法确认类型具备所需能力：


func findMax<T>(_ array: [T]) -> T? {
    // array.max()  ← 编译错误：T 没有 Comparable 约束
    nil
}

func findMax<T: Comparable>(_ array: [T]) -> T? {
    array.max()
}
陷阱三：any 的性能开销
any 类型使用 existential container 存储，每次方法调用都经过间接分派。在性能敏感的循环中，优先使用泛型参数或 some：


func sumAreas(shapes: [any Shape]) -> Double {
    shapes.reduce(0) { $0 + $1.area }
}

func sumAreas<S: Shape>(shapes: [S]) -> Double {
    shapes.reduce(0) { $0 + $1.area }
}
第二种写法允许编译器进行特化（specialization），性能显著优于 any 版本，但要求数组中所有元素类型相同。


陷阱四：类型参数命名不当
避免滥用单字母 T、U、V。当类型参数有明确语义时，使用描述性名称：


func transform<Input, Output>(
    _ value: Input,
    using transformer: (Input) -> Output
) -> Output {
    transformer(value)
}
小结
    

  • 泛型函数通过类型参数实现一份代码适配多种类型，编译器在调用点推断并检查类型。
    • 

  • 泛型类型（struct/class/enum）让数据结构与具体元素类型解耦，Queue<Element>、Result<Success, Failure> 都是典型例子。
    • 

  • 类型约束（T: Protocol、where 子句）为类型参数添加能力要求，确保泛型代码中可以调用所需方法。
    • 

  • 关联类型是协议层面的泛型，由遵循者决定具体类型。
    • 

  • **some（Opaque Types）**隐藏具体类型但保留类型身份，编译器可进行静态优化，是 SwiftUI 的基础。
    • 

  • **any（Existential Types）**支持运行时异构存储和动态分派，灵活但有性能开销。
    • 

  • 类型擦除（AnyX 模式）在 Swift 5.7 之前是处理带关联类型协议的主要手段，现在多数场景可用 any 替代。
    • 

  • 优先使用 some 和泛型参数以获得最佳性能，仅在确实需要异构集合或运行时多态时才使用 any。
