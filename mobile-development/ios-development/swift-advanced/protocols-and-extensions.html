Part I · iOSiOS 开发 简介Swift 进阶 简介协议与扩展

协议与扩展

概述

协议（Protocol）是 Swift 类型系统的基石，它定义了一组行为契约，任何遵循该协议的类型都必须满足这些契约。与面向对象语言中的抽象类不同，Swift 的协议支持值类型（struct、enum）遵循，并且可以通过**协议扩展（Protocol Extension）**提供默认实现，形成面向协议编程（Protocol-Oriented Programming, POP）的核心范式。

扩展（Extension）则允许在不修改原始源码的前提下为已有类型添加新功能——包括计算属性、方法、构造器、下标和协议遵循。协议与扩展的组合是 Swift 区别于其他语言最重要的设计特征之一。

核心概念
协议定义
协议声明一组属性和方法要求，但不提供实现。遵循协议的类型必须实现所有要求：


protocol Drawable {
    var boundingBox: CGRect { get }
    func draw(on context: CGContext)
}

protocol Resizable {
    mutating func resize(to size: CGSize)
}
属性要求使用 { get } 或 { get set } 标注读写权限。对于值类型中可能修改 self 的方法，需要添加 mutating 关键字。


struct Circle: Drawable, Resizable {
    var center: CGPoint
    var radius: Double

    var boundingBox: CGRect {
        CGRect(
            x: center.x - radius,
            y: center.y - radius,
            width: radius * 2,
            height: radius * 2
        )
    }

    func draw(on context: CGContext) {
        context.addEllipse(in: boundingBox)
        context.drawPath(using: .stroke)
    }

    mutating func resize(to size: CGSize) {
        radius = min(size.width, size.height) / 2
    }
}
协议继承
协议可以继承一个或多个协议，形成层级关系。遵循子协议的类型必须同时满足所有父协议的要求：


protocol Shape: Drawable {
    var area: Double { get }
    var perimeter: Double { get }
}

protocol AnimatableShape: Shape, Animatable {
    func animate(to target: Shape, duration: TimeInterval)
}
通过继承可以构建精细的协议层次，在保持接口小而专注的同时实现功能组合。


协议组合
当函数参数需要同时满足多个协议时，使用 & 运算符进行协议组合，而不需要定义一个新的协议：


protocol Named {
    var name: String { get }
}

protocol Aged {
    var age: Int { get }
}

func greet(person: Named & Aged) {
    print("你好，\(person.name)，你今年 \(person.age) 岁。")
}

struct Student: Named, Aged {
    let name: String
    let age: Int
}

let student = Student(name: "小明", age: 20)
greet(person: student)
协议组合也可以与类类型混合使用：UIViewController & UITableViewDelegate。


关联类型
关联类型（Associated Type）为协议引入了泛型能力，让遵循者自行决定具体类型：


protocol Container {
    associatedtype Item
    var count: Int { get }
    mutating func append(_ item: Item)
    subscript(i: Int) -> Item { get }
}

struct Stack<Element>: Container {
    typealias Item = Element

    private var storage: [Element] = []

    var count: Int { storage.count }

    mutating func append(_ item: Element) {
        storage.append(item)
    }

    subscript(i: Int) -> Element {
        storage[i]
    }
}
关联类型可以添加约束来限制遵循者的选择：


protocol SortableContainer: Container where Item: Comparable {
    func sorted() -> [Item]
}
协议扩展与默认实现
协议扩展是 POP 的核心机制。它允许为协议中的方法提供默认实现，遵循者可以直接使用或覆盖：


protocol Describable {
    var title: String { get }
    var subtitle: String { get }
}

extension Describable {
    var subtitle: String {
        "No subtitle"
    }

    var fullDescription: String {
        "\(title) — \(subtitle)"
    }
}

struct Article: Describable {
    let title: String
}

let article = Article(title: "Swift 协议")
print(article.fullDescription)
条件性遵循
通过 where 子句，可以让泛型类型在特定条件下才遵循某个协议：


extension Array: Describable where Element: Describable {
    var title: String {
        map(\.title).joined(separator: ", ")
    }
}
标准库大量使用此特性。例如 Array 在其 Element 遵循 Equatable 时才自动遵循 Equatable：


let a = [1, 2, 3]
let b = [1, 2, 3]
print(a == b)
如果 Element 不遵循 Equatable，则 Array 也不会获得 == 运算符。


Extension 实际用法
扩展不仅用于协议，它可以为任何已有类型添加功能：


extension Double {
    var km: Double { self * 1_000.0 }
    var m: Double { self }
    var cm: Double { self / 100.0 }
}

let marathon = 42.195.km
print("马拉松全程 \(marathon) 米")
为已有类型追加协议遵循：


extension Int: Describable {
    var title: String { "\(self)" }
}
为泛型类型追加受约束的方法：


extension Collection where Element: Numeric {
    var total: Element {
        reduce(0, +)
    }
}

let numbers = [1, 2, 3, 4, 5]
print(numbers.total)
使用方式
模式一：用协议抽象依赖实现可测试性
将外部依赖抽象为协议，在生产代码和测试代码中分别提供不同实现：


protocol NetworkService {
    func fetch(url: URL) async throws -> Data
}

struct URLSessionService: NetworkService {
    func fetch(url: URL) async throws -> Data {
        let (data, _) = try await URLSession.shared.data(from: url)
        return data
    }
}

struct MockNetworkService: NetworkService {
    var mockData: Data

    func fetch(url: URL) async throws -> Data {
        mockData
    }
}

class UserViewModel {
    private let network: NetworkService

    init(network: NetworkService) {
        self.network = network
    }

    func loadUser(id: Int) async throws -> Data {
        let url = URL(string: "https://api.example.com/users/\(id)")!
        return try await network.fetch(url: url)
    }
}
模式二：协议扩展构建能力层
通过多层协议扩展为类型逐步叠加能力，每一层只关注单一职责：


protocol Identifiable {
    var id: String { get }
}

protocol Timestamped {
    var createdAt: Date { get }
    var updatedAt: Date { get }
}

protocol Persistable: Identifiable, Timestamped {
    func save() throws
    static func find(by id: String) throws -> Self?
}

extension Persistable {
    func save() throws {
        print("Saving \(id) to default store...")
    }
}

extension Timestamped {
    var isRecent: Bool {
        updatedAt.timeIntervalSinceNow > -86_400
    }
}
模式三：Extension 分离关注点
使用 extension 将一个类型的实现按逻辑分组，提升可读性：


struct UserProfile {
    let name: String
    let email: String
    let avatarURL: URL?
}

extension UserProfile: Codable {}

extension UserProfile: CustomStringConvertible {
    var description: String {
        "\(name) <\(email)>"
    }
}

extension UserProfile {
    var initials: String {
        name.split(separator: " ")
            .compactMap(\.first)
            .map(String.init)
            .joined()
    }
}
这种模式在 iOS 开发中非常常见——将 UITableViewDataSource、UITableViewDelegate 等协议遵循放在不同的 extension 中，让代码结构一目了然。


常见陷阱
陷阱一：协议扩展的方法派发
协议扩展中定义的方法如果不在协议要求中声明，则使用静态派发而非动态派发。这会导致多态行为失效：


protocol Greeter {
    func greet() -> String
}

extension Greeter {
    func greet() -> String { "Hello!" }
    func farewell() -> String { "Goodbye!" }
}

struct FrenchGreeter: Greeter {
    func greet() -> String { "Bonjour!" }
    func farewell() -> String { "Au revoir!" }
}

let greeter: Greeter = FrenchGreeter()
print(greeter.greet())
print(greeter.farewell())
greet() 是协议要求的方法，动态派发输出 "Bonjour!"。而 farewell() 不在协议要求中，静态派发输出 "Goodbye!"——这是最常见的 Swift 协议陷阱。


陷阱二：关联类型导致协议不能作为类型使用
带有关联类型或 Self 要求的协议不能直接作为变量类型使用：


protocol Repository {
    associatedtype Model
    func getAll() -> [Model]
}

// let repo: Repository  ← 编译错误
// 需要使用 any Repository 或 some Repository
let repo: any Repository
在 Swift 5.7+ 中，使用 any 关键字进行**存在类型（Existential Type）标注，或使用 some 进行不透明类型（Opaque Type）**标注。


陷阱三：Extension 中不能添加存储属性
Extension 只能添加计算属性，不能添加存储属性：


extension UserProfile {
    // var nickname: String = ""  ← 编译错误
    // 可以用计算属性或关联对象（ObjC runtime）替代
}
如果确实需要为已有类型添加存储，可以考虑使用组合（Composition）模式包装原类型。


陷阱四：过度使用协议
不是所有抽象都需要协议。如果一个协议只有一个遵循者且未来不太会扩展，直接使用具体类型即可。过度抽象会增加代码复杂度和认知负担。


小结
    

  • 协议定义行为契约，支持属性、方法、构造器和关联类型要求，是 Swift 类型系统的核心抽象机制。
    • 

  • 协议继承允许构建协议层次，协议组合（&）允许临时组合多个协议要求。
    • 

  • 关联类型为协议引入泛型能力，但会使协议不能直接作为类型使用（需要 any / some）。
    • 

  • 协议扩展提供默认实现，是面向协议编程（POP）的核心——但需注意方法派发的静态 vs 动态区别。
    • 

  • 条件性遵循让泛型类型在满足特定约束时自动获得协议能力。
    • 

  • Extension 可为任何类型添加计算属性、方法、构造器和协议遵循，是组织代码、分离关注点的利器。
    • 

  • 避免协议扩展中非要求方法的多态陷阱，避免过度抽象，合理评估是否真正需要协议层。
    •
