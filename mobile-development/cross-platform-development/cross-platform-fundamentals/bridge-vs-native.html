桥接 vs 原生

核心概念

桥接（Bridge）机制是跨平台框架的核心基础设施，它负责在 JavaScript 运行时和原生平台之间建立通信通道。从最早的 JSON 序列化桥接，到 React Native 的 JSI 直接内存访问，再到 FFI（Foreign Function Interface）二进制调用，桥接技术的每一次演进都在追求更低的通信延迟和更高的数据传输效率。理解桥接原理是掌握跨平台性能调优的关键。

通信机制全景

JSON Bridge（传统桥接）
React Native 旧架构使用的 JSON Bridge 是最经典的桥接实现。JS 线程和原生线程各自独立运行，所有跨线程通信都需要将数据序列化为 JSON 字符串，通过消息队列异步传递，再在目标线程反序列化。


传统桥接的性能瓶颈
import { NativeModules } from 'react-native';

const { ImageProcessor } = NativeModules;

async function processImageBatch(images: ImageData[]) {
  const results: ProcessedImage[] = [];

  for (const image of images) {
    const result = await ImageProcessor.process({
      uri: image.uri,
      width: image.width,
      height: image.height,
      filters: image.filters,
    });
    results.push(result);
  }

  return results;
}
上面代码的性能问题在于：每次 process 调用都经历一次完整的 JSON 序列化→消息队列→反序列化→执行→序列化结果→回调的完整链路。若处理 100 张图片，光桥接开销就可能消耗 100-200ms。


优化：批量桥接
import { NativeModules } from 'react-native';

const { ImageProcessor } = NativeModules;

async function processImageBatchOptimized(images: ImageData[]) {
  const batchPayload = images.map((img) => ({
    uri: img.uri,
    width: img.width,
    height: img.height,
    filters: img.filters,
  }));

  const results = await ImageProcessor.processBatch(batchPayload);
  return results;
}
JSI（JavaScript Interface）
JSI 是 React Native 新架构的基石。它通过 C++ 层直接将原生对象和方法绑定到 JS 运行时的全局对象上，实现了 JS 和原生之间的同步、零拷贝通信。


JSI HostObject 实现
#include <jsi/jsi.h>
#include <string>
#include <unordered_map>

using namespace facebook::jsi;

class StorageHostObject : public HostObject {
 public:
  Value get(Runtime& runtime, const PropNameID& name) override {
    auto propName = name.utf8(runtime);

    if (propName == "getItem") {
      return Function::createFromHostFunction(
        runtime,
        PropNameID::forAscii(runtime, "getItem"),
        1,
        [this](Runtime& rt, const Value&, const Value* args, size_t) -> Value {
          auto key = args[0].asString(rt).utf8(rt);
          auto it = storage_.find(key);
          if (it != storage_.end()) {
            return String::createFromUtf8(rt, it->second);
          }
          return Value::undefined();
        }
      );
    }

    if (propName == "setItem") {
      return Function::createFromHostFunction(
        runtime,
        PropNameID::forAscii(runtime, "setItem"),
        2,
        [this](Runtime& rt, const Value&, const Value* args, size_t) -> Value {
          auto key = args[0].asString(rt).utf8(rt);
          auto value = args[1].asString(rt).utf8(rt);
          storage_[key] = value;
          return Value::undefined();
        }
      );
    }

    return Value::undefined();
  }

  void set(Runtime&, const PropNameID&, const Value&) override {}

  std::vector<PropNameID> getPropertyNames(Runtime& runtime) override {
    return {
      PropNameID::forAscii(runtime, "getItem"),
      PropNameID::forAscii(runtime, "setItem"),
    };
  }

 private:
  std::unordered_map<std::string, std::string> storage_;
};

void installStorage(Runtime& runtime) {
  auto storage = std::make_shared<StorageHostObject>();
  auto obj = Object::createFromHostObject(runtime, storage);
  runtime.global().setProperty(runtime, "nativeStorage", std::move(obj));
}

TurboModules
TurboModules 是基于 JSI 构建的原生模块系统，它替代了旧架构的 NativeModules。核心改进包括：懒加载（按需初始化）、类型安全（Codegen 生成接口）和同步调用支持。


TurboModule 定义与实现
import type { TurboModule } from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  getDeviceInfo(): {
    brand: string;
    model: string;
    systemVersion: string;
    appVersion: string;
    buildNumber: string;
  };

  getBatteryLevel(): Promise<number>;

  vibrate(pattern: number[], repeat: boolean): void;

  addListener(eventName: string): void;
  removeListeners(count: number): void;
}

export default TurboModuleRegistry.getEnforcing<Spec>('DeviceInfo');
package com.myapp.deviceinfo

import com.facebook.react.bridge.ReactApplicationContext
import com.facebook.react.bridge.ReadableMap
import com.facebook.react.module.annotations.ReactModule

@ReactModule(name = DeviceInfoModule.NAME)
class DeviceInfoModule(reactContext: ReactApplicationContext) :
    NativeDeviceInfoSpec(reactContext) {

    override fun getName(): String = NAME

    override fun getDeviceInfo(): WritableMap {
        val map = Arguments.createMap()
        map.putString("brand", Build.BRAND)
        map.putString("model", Build.MODEL)
        map.putString("systemVersion", Build.VERSION.RELEASE)
        map.putString("appVersion", getAppVersion())
        map.putString("buildNumber", getBuildNumber())
        return map
    }

    override fun getBatteryLevel(promise: Promise) {
        val bm = reactApplicationContext
            .getSystemService(Context.BATTERY_SERVICE) as BatteryManager
        val level = bm.getIntProperty(BatteryManager.BATTERY_PROPERTY_CAPACITY)
        promise.resolve(level.toDouble())
    }

    override fun vibrate(pattern: ReadableArray, repeat: Boolean) {
        val vibrator = reactApplicationContext
            .getSystemService(Context.VIBRATOR_SERVICE) as Vibrator
        val longPattern = LongArray(pattern.size()) { pattern.getInt(it).toLong() }
        vibrator.vibrate(longPattern, if (repeat) 0 else -1)
    }

    companion object {
        const val NAME = "DeviceInfo"
    }
}
FFI（Foreign Function Interface）
FFI 允许一种编程语言直接调用另一种语言编写的函数，无需 JSON 序列化或消息传递。在跨平台场景中，Dart FFI（Flutter）和 Kotlin/Native 的 C Interop 是典型代表。


Dart FFI 调用 C 函数
import 'dart:ffi';
import 'dart:io' show Platform;

typedef NativeAdd = Int32 Function(Int32, Int32);
typedef DartAdd = int Function(int, int);

typedef NativeImageProcess = Pointer<Uint8> Function(
  Pointer<Uint8> data,
  Int32 width,
  Int32 height,
  Int32 filterType,
);
typedef DartImageProcess = Pointer<Uint8> Function(
  Pointer<Uint8> data,
  int width,
  int height,
  int filterType,
);

class NativeBinding {
  late final DynamicLibrary _lib;
  late final DartAdd add;
  late final DartImageProcess processImage;

  NativeBinding() {
    _lib = Platform.isAndroid
        ? DynamicLibrary.open('libnative_processor.so')
        : DynamicLibrary.process();

    add = _lib.lookupFunction<NativeAdd, DartAdd>('native_add');

    processImage = _lib.lookupFunction<NativeImageProcess, DartImageProcess>(
      'native_process_image',
    );
  }
}

void main() {
  final binding = NativeBinding();
  final result = binding.add(3, 7);
  print('3 + 7 = $result');
}
#include <stdint.h>

int32_t native_add(int32_t a, int32_t b) {
    return a + b;
}

uint8_t* native_process_image(
    uint8_t* data,
    int32_t width,
    int32_t height,
    int32_t filter_type
) {
    for (int i = 0; i < width * height * 4; i += 4) {
        switch (filter_type) {
            case 0:
                break;
            case 1: {
                uint8_t gray = (data[i] * 299 + data[i+1] * 587 + data[i+2] * 114) / 1000;
                data[i] = data[i+1] = data[i+2] = gray;
                break;
            }
        }
    }
    return data;
}

React Native 新架构线程管理
import { InteractionManager } from 'react-native';

function handleHeavyComputation(data: LargeDataset) {
  InteractionManager.runAfterInteractions(() => {
    requestAnimationFrame(() => {
      const chunk = data.slice(0, 100);
      processChunk(chunk);

      if (data.length > 100) {
        handleHeavyComputation(data.slice(100));
      }
    });
  });
}
import kotlinx.coroutines.*

class HeavyNativeModule(reactContext: ReactApplicationContext) :
    NativeHeavyComputationSpec(reactContext) {

    private val scope = CoroutineScope(Dispatchers.Default + SupervisorJob())

    override fun computeInBackground(input: String, promise: Promise) {
        scope.launch {
            try {
                val result = withContext(Dispatchers.Default) {
                    performHeavyComputation(input)
                }
                withContext(Dispatchers.Main) {
                    promise.resolve(result)
                }
            } catch (e: Exception) {
                promise.reject("COMPUTATION_ERROR", e.message)
            }
        }
    }

    private fun performHeavyComputation(input: String): String {
        return input.reversed().uppercase()
    }
}

小结
桥接技术的演进方向是清晰的：从高开销的 JSON 序列化走向零开销的直接内存访问。JSI 的出现让 React Native 的性能产生了质的飞跃，而 FFI 则为计算密集型场景提供了最优解。选择桥接方案时，需要根据调用频率、数据量、延迟敏感度和团队技术栈综合判断。


核心要点回顾：


    

  • JSON Bridge 简单但开销大，每次调用需要完整的序列化/反序列化链路
    • 

  • JSI 通过 C++ HostObject 实现 JS 和原生的直接内存共享，性能提升 100 倍
    • 

  • TurboModules 基于 JSI 构建，提供懒加载和类型安全
    • 

  • FFI 是性能最优的方案，适合大数据传输和计算密集型场景
    • 

  • 新架构的线程模型更灵活，支持同步调用和并发执行
    • 

  • 实际项目中通常混合使用多种桥接方案，按场景选择最优策略
