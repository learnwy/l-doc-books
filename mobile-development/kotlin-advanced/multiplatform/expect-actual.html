expect/actual 机制

expect/actual 是 Kotlin Multiplatform 的核心抽象机制。通过在公共代码中声明 expect 接口，在各平台模块中提供 actual 实现，实现了编译时安全的跨平台代码共享。

基本语法

在 commonMain 中用 expect 声明，在各平台源集中用 actual 实现：

// commonMain/kotlin/Platform.kt
expect fun getPlatformName(): String

expect class DeviceInfo {
    val os: String
    val version: String
}
// androidMain/kotlin/Platform.android.kt
actual fun getPlatformName(): String = "Android ${android.os.Build.VERSION.SDK_INT}"

actual class DeviceInfo {
    actual val os: String = "Android"
    actual val version: String = android.os.Build.VERSION.RELEASE
}
// iosMain/kotlin/Platform.ios.kt
import platform.UIKit.UIDevice

actual fun getPlatformName(): String = UIDevice.currentDevice.systemName()

actual class DeviceInfo {
    actual val os: String = "iOS"
    actual val version: String = UIDevice.currentDevice.systemVersion
}

使用类型别名实现 actual
当平台已有完全匹配的类型时，actual typealias 是最简洁的实现方式：


// commonMain
expect class AtomicRef<V>(value: V) {
    fun get(): V
    fun set(value: V)
}

// jvmMain
actual typealias AtomicRef<V> = java.util.concurrent.atomic.AtomicReference<V>

// nativeMain — 需要手动实现
actual class AtomicRef<V> actual constructor(value: V) {
    private val ref = kotlin.native.concurrent.AtomicReference(value)
    actual fun get(): V = ref.value
    actual fun set(value: V) { ref.value = value }
}


提示： actual typealias 要求目标类型的所有成员签名与 expect 声明完全匹配，包括可见性修饰符。






expect/actual 的约束与限制
1. 成员必须完全匹配
// commonMain
expect class Logger {
    fun log(message: String)
    fun debug(message: String)
}

// actual 必须实现所有 expect 成员
actual class Logger {
    actual fun log(message: String) { /* ... */ }
    actual fun debug(message: String) { /* ... */ }
    fun extra() { /* actual 可以有额外成员 */ }
}
2. 不能有函数体
// commonMain
expect fun compute(): Int           // 正确：无函数体
// expect fun compute(): Int = 42   // 错误：expect 不能有默认实现
3. 接口不需要 expect
// 接口本身是抽象的，天然跨平台
interface Repository {
    suspend fun getData(): List<Item>
}

// 各平台可以有不同的实现
class AndroidRepository : Repository {
    override suspend fun getData(): List<Item> = roomDatabase.getAll()
}


平台特定实现模式
工厂模式
// commonMain
expect object HttpClientFactory {
    fun create(): HttpClient
}

// androidMain
actual object HttpClientFactory {
    actual fun create(): HttpClient = HttpClient(Android) {
        install(ContentNegotiation) { json() }
    }
}

// iosMain
actual object HttpClientFactory {
    actual fun create(): HttpClient = HttpClient(Darwin) {
        install(ContentNegotiation) { json() }
    }
}
接口 + expect 工厂
// commonMain
interface KeyValueStore {
    fun getString(key: String): String?
    fun putString(key: String, value: String)
}

expect fun createKeyValueStore(): KeyValueStore

// androidMain
actual fun createKeyValueStore(): KeyValueStore = object : KeyValueStore {
    private val prefs = context.getSharedPreferences("kmp", Context.MODE_PRIVATE)
    override fun getString(key: String): String? = prefs.getString(key, null)
    override fun putString(key: String, value: String) {
        prefs.edit().putString(key, value).apply()
    }
}

// iosMain
actual fun createKeyValueStore(): KeyValueStore = object : KeyValueStore {
    private val defaults = NSUserDefaults.standardUserDefaults
    override fun getString(key: String): String? = defaults.stringForKey(key)
    override fun putString(key: String, value: String) {
        defaults.setObject(value, forKey = key)
    }
}


测试 expect/actual
// commonTest
class PlatformTest {
    @Test
    fun testPlatformName() {
        val name = getPlatformName()
        assertTrue(name.isNotBlank(), "平台名称不应为空")
    }
}

// androidTest
class AndroidPlatformTest {
    @Test
    fun testAndroidSpecific() {
        val name = getPlatformName()
        assertTrue(name.startsWith("Android"))
    }
}

小结
    

  • expect 在公共代码中声明平台相关的接口，actual 在各平台提供具体实现
    • 

  • 支持函数、属性、类、对象、类型别名、注解、枚举等声明类型
    • 

  • actual typealias 是最简洁的实现方式，适合平台已有匹配类型的场景
    • 

  • expect 声明不能有函数体，actual 实现必须匹配所有成员签名
    • 

  • 接口天然跨平台，不需要 expect/actual
    • 

  • 常用模式：工厂模式、接口 + expect 工厂、typealias 映射
    • 

  • 公共测试在所有平台运行，平台测试验证各自的 actual 实现
    •
