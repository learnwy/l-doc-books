KMP 项目搭建

Kotlin Multiplatform（KMP）允许在多个平台（Android、iOS、Desktop、Web）之间共享 Kotlin 代码。通过统一的项目结构和 Gradle 配置，开发者可以将业务逻辑、网络层、数据模型等代码编写一次，在多个平台上运行。

KMP 项目结构

标准的 KMP 项目遵循源集（Source Set）分层结构：

my-kmp-project/
├── build.gradle.kts
├── settings.gradle.kts
├── shared/
│   ├── build.gradle.kts
│   └── src/
│       ├── commonMain/kotlin/       ← 公共代码
│       ├── commonTest/kotlin/       ← 公共测试
│       ├── androidMain/kotlin/      ← Android 特定实现
│       ├── iosMain/kotlin/          ← iOS 特定实现
│       ├── desktopMain/kotlin/      ← Desktop 特定实现
│       └── wasmJsMain/kotlin/       ← Web 特定实现
├── androidApp/                      ← Android 应用壳
├── iosApp/                          ← iOS 应用壳 (Xcode)
└── desktopApp/                      ← Desktop 应用壳


Gradle 配置
settings.gradle.kts
pluginManagement {
    repositories {
        google()
        mavenCentral()
        gradlePluginPortal()
    }
}

dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
    }
}

rootProject.name = "MyKmpProject"
include(":shared")
include(":androidApp")
include(":desktopApp")
shared/build.gradle.kts
plugins {
    kotlin("multiplatform")
    id("com.android.library")
    kotlin("plugin.serialization")
}

kotlin {
    androidTarget {
        compilations.all {
            kotlinOptions {
                jvmTarget = "17"
            }
        }
    }

    listOf(
        iosX64(),
        iosArm64(),
        iosSimulatorArm64()
    ).forEach {
        it.binaries.framework {
            baseName = "shared"
            isStatic = true
        }
    }

    jvm("desktop")

    sourceSets {
        commonMain.dependencies {
            implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.7.3")
            implementation("org.jetbrains.kotlinx:kotlinx-serialization-json:1.6.0")
            implementation("io.ktor:ktor-client-core:2.3.5")
        }
        commonTest.dependencies {
            implementation(kotlin("test"))
        }
        androidMain.dependencies {
            implementation("io.ktor:ktor-client-android:2.3.5")
        }
        iosMain.dependencies {
            implementation("io.ktor:ktor-client-darwin:2.3.5")
        }
        val desktopMain by getting {
            dependencies {
                implementation("io.ktor:ktor-client-cio:2.3.5")
            }
        }
    }
}

android {
    namespace = "com.example.shared"
    compileSdk = 34
    defaultConfig {
        minSdk = 24
    }
}


提示： KMP 项目的 Gradle 配置是学习曲线最陡峭的部分。建议使用 JetBrains 的 KMP 向导 (kmp.jetbrains.com) 生成初始项目。






expect/actual 机制概览
expect/actual 是 KMP 的核心机制，允许在公共代码中声明平台相关的接口，由各平台提供具体实现：


// commonMain
expect fun platformName(): String

expect class PlatformLogger() {
    fun log(message: String)
}

// androidMain
actual fun platformName(): String = "Android"

actual class PlatformLogger actual constructor() {
    actual fun log(message: String) {
        android.util.Log.d("KMP", message)
    }
}

// iosMain
actual fun platformName(): String = "iOS"

actual class PlatformLogger actual constructor() {
    actual fun log(message: String) {
        platform.Foundation.NSLog(message)
    }
}


源集层次结构
KMP 支持中间源集，实现代码在部分平台间共享：


kotlin {
    sourceSets {
        val nativeMain by creating {
            dependsOn(commonMain.get())
        }
        iosMain {
            dependsOn(nativeMain)
        }
    }
}

小结
    

  • KMP 通过共享 Kotlin 代码实现多平台开发，覆盖 Android、iOS、Desktop、Web
    • 

  • 项目结构基于源集（Source Set），commonMain 存放公共代码，各平台源集存放特定实现
    • 

  • Gradle 配置定义目标平台、依赖和编译选项，是项目搭建的核心
    • 

  • expect/actual 机制桥接公共接口与平台实现
    • 

  • 中间源集（如 nativeMain、jvmMain）允许在部分平台间共享代码
    • 

  • 推荐使用 KMP 向导生成初始项目模板，减少手动配置错误
