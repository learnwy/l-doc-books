空安全模式

空安全是 Kotlin 最核心的语言特性之一。通过类型系统将可空性编码为类型信息，Kotlin 在编译时消除了大部分空指针异常（NPE）。本文介绍 Kotlin 空安全的操作符、模式和防御性编程技巧。

可空类型系统

Kotlin 的类型系统区分可空和非空类型：

val nonNull: String = "hello"   // 不能为 null
val nullable: String? = null     // 可以为 null

// nonNull = null  // 编译错误
// nullable.length // 编译错误：需要空安全调用


核心操作符
?. 安全调用
val name: String? = fetchName()
val length: Int? = name?.length // name 为 null 时返回 null

// 链式安全调用
val city: String? = user?.address?.city?.uppercase()
?: Elvis 操作符
val length: Int = name?.length ?: 0 // name 为 null 时使用默认值

val displayName = user?.name ?: throw IllegalArgumentException("用户名不能为空")

val config = loadConfig() ?: return // 为 null 时提前返回
!! 非空断言
val length: Int = name!!.length // 如果 name 为 null，抛出 NPE

提示： 尽量避免使用 !!。如果发现频繁使用，通常意味着类型设计需要改进。






安全类型转换
val value: Any = "Hello"

// 不安全转换：失败时抛出 ClassCastException
val str1: String = value as String

// 安全转换：失败时返回 null
val str2: String? = value as? String
val num: Int? = value as? Int // null，不会抛异常


平台类型
来自 Java 的类型在 Kotlin 中表示为"平台类型"（标记为 Type!），编译器不强制空安全检查：


// Java 代码
// public String getName() { return null; }

// Kotlin 中调用
val name: String = javaObj.getName() // 编译通过，但运行时可能 NPE
val safeName: String? = javaObj.getName() // 推荐：显式声明为可空




Java 注解
Kotlin 解读





@NotNull
非空类型 String




@Nullable
可空类型 String?




无注解
平台类型 String!







提示： 在 Java 交互边界处，始终显式声明 Kotlin 变量的可空性，不要依赖平台类型的隐式推断。






空安全模式与惯用法
模式 1：提前返回
fun processUser(user: User?) {
    val name = user?.name ?: return
    val email = user.email ?: return
    sendWelcomeEmail(name, email)
}
模式 2：let 转换
val email: String? = user?.email

email?.let { nonNullEmail ->
    sendEmail(nonNullEmail)
    logEmailSent(nonNullEmail)
}
模式 3：require/check 断言
fun createOrder(userId: Long?, productId: Long?) {
    requireNotNull(userId) { "用户 ID 不能为空" }
    requireNotNull(productId) { "商品 ID 不能为空" }
    // 此后 userId 和 productId 都是非空类型
    orderRepository.create(userId, productId)
}
模式 4：when + smart cast
fun describe(value: Any?): String = when (value) {
    null -> "空值"
    is String -> "字符串: $value (长度=${value.length})"
    is Int -> "整数: $value"
    is List<*> -> "列表: ${value.size} 个元素"
    else -> "其他: $value"
}


空安全构建器
为集合操作提供空安全的构建器模式：


fun buildUserProfile(user: User?): Map<String, String> = buildMap {
    user?.name?.let { put("name", it) }
    user?.email?.let { put("email", it) }
    user?.phone?.let { put("phone", it) }
    user?.address?.let { addr ->
        addr.city?.let { put("city", it) }
        addr.zipCode?.let { put("zipCode", it) }
    }
}

val emptyList: List<String> = user?.tags?.filterNotNull() ?: emptyList()


防御性编程策略
在边界处处理空值
// API 层：接收外部数据，严格验证
class UserController {
    fun createUser(request: CreateUserRequest) {
        val name = request.name
            ?: throw BadRequestException("name 是必填字段")
        val email = request.email
            ?: throw BadRequestException("email 是必填字段")
        userService.create(name, email) // 传入非空值
    }
}

// 服务层：内部代码，使用非空类型
class UserService {
    fun create(name: String, email: String): User { // 非空参数
        return userRepository.save(User(name = name, email = email))
    }
}
集合中的空值处理
val mixedList: List<String?> = listOf("a", null, "b", null, "c")

val nonNullList: List<String> = mixedList.filterNotNull() // [a, b, c]
val firstNonNull: String = mixedList.filterNotNull().first()
val mappedSafe: List<Int> = mixedList.mapNotNull { it?.length } // [1, 1, 1]


小结
    

  • Kotlin 通过类型系统区分 可空类型（T?）和非空类型（T），在编译时防止 NPE
    • 

  • ?. 安全调用、?: Elvis 操作符是最常用的空安全工具
    • 

  • !! 应尽量避免，频繁使用说明类型设计有问题
    • 

  • 平台类型来自 Java 互操作，应在边界处显式声明可空性
    • 

  • 常用模式：提前返回（?: return）、let 转换、requireNotNull 断言、when + smart cast
    • 

  • 防御性策略：在 API 边界处验证空值，内部代码使用非空类型
    • 

  • filterNotNull()、mapNotNull() 处理集合中的空值
