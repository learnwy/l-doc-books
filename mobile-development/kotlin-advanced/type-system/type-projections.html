类型投影

类型投影（Type Projections）是 Kotlin 在使用处限制泛型类型读写能力的机制。当泛型类在声明时未标注型变（即不变），但某些使用场景只需要读取或写入时，类型投影能提供更灵活的类型安全保证。

不变类型的困境

Array<T> 在 Kotlin 中是不变的——Array<String> 既不是 Array<Any> 的子类型，也不是其父类型。

fun copy(from: Array<Any>, to: Array<Any>) {
    for (i in from.indices) to[i] = from[i]
}

val strings: Array<String> = arrayOf("a", "b", "c")
val anys: Array<Any> = arrayOf(1, 2, 3)

// copy(strings, anys) // 编译错误：Array<String> 不能赋值给 Array<Any>

这种设计防止了运行时错误，但也限制了灵活性。类型投影正是为了解决这一问题。

out 投影（协变投影）

使用 out 将泛型参数限制为只读（生产者角色）：

fun copy(from: Array<out Any>, to: Array<Any>) {
    for (i in from.indices) {
        to[i] = from[i] // 合法：从 from 读取
    }
    // from[0] = "x" // 编译错误：out 投影禁止写入
}

val strings = arrayOf("a", "b", "c")
val anys = arrayOf<Any>(1, 2, 3)
copy(strings, anys) // 现在合法


in 投影（逆变投影）
使用 in 将泛型参数限制为只写（消费者角色）：


fun fill(dest: Array<in String>, value: String) {
    for (i in dest.indices) {
        dest[i] = value // 合法：向 dest 写入
    }
    // val s: String = dest[0] // 编译错误：in 投影读取返回 Any?
}

val anys = arrayOf<Any>("x", "y", "z")
fill(anys, "filled") // 合法：Array<Any> 可作为 Array<in String>

与 Java 有界通配符的对比
Kotlin 的类型投影与 Java 的有界通配符（bounded wildcards）在概念上对应，但语法和语义更加清晰：

星投影/无界通配符





Java 的 PECS（Producer Extends Consumer Super）原则在 Kotlin 中有了更直观的表达：


// Kotlin 版 PECS
fun <T> transfer(
    source: MutableList<out T>,  // Producer: out (extends)
    target: MutableList<in T>    // Consumer: in (super)
) {
    for (item in source) {
        target.add(item)
    }
}


提示： Kotlin 的 out/in 比 Java 的 extends/super 更符合直觉——out 表示数据从中流出，in 表示数据向其流入。






类型投影的限制
类型投影并非万能，有以下限制需要注意：


1. 不能调用接受投影类型参数的方法
fun readOnly(list: MutableList<out Number>) {
    // list.add(42)          // 编译错误
    // list[0] = 42          // 编译错误
    val n: Number = list[0]  // 合法
}
2. 嵌套投影的复杂性
fun process(map: Map<String, List<out Number>>) {
    val numbers: List<out Number> = map["key"] ?: emptyList()
    // 返回类型为 Number，不会丢失信息
    val first: Number? = numbers.firstOrNull()
}
3. 声明处型变优先
如果类型在声明时已标注型变，使用处不能与之矛盾：


interface Source<out T> {
    fun next(): T
}

// fun demo(s: Source<in String>) { } // 错误：Source 已声明为 out


实际应用示例
安全的集合复制工具
fun <T> safeTransfer(
    source: Iterable<out T>,
    destination: MutableCollection<in T>
) {
    for (element in source) {
        destination.add(element)
    }
}

val ints: List<Int> = listOf(1, 2, 3)
val numbers: MutableList<Number> = mutableListOf()
safeTransfer(ints, numbers) // Int 是 Number 的子类型，完全安全
通用比较器
fun <T> findMax(
    list: List<out T>,
    comparator: Comparator<in T>
): T? {
    if (list.isEmpty()) return null
    var max = list[0]
    for (i in 1 until list.size) {
        if (comparator.compare(list[i], max) > 0) {
            max = list[i]
        }
    }
    return max
}


小结
    

  • 类型投影在使用处限制泛型类型的读写能力，解决不变类型的灵活性问题
    • 

  • out 投影将类型限制为只读（生产者），对应 Java 的 ? extends
    • 

  • in 投影将类型限制为只写（消费者），对应 Java 的 ? super
    • 

  • Kotlin 的 out/in 语义比 Java 的 PECS 更直观
    • 

  • 声明处型变优先于使用处投影，两者不能矛盾
    • 

  • 嵌套投影会增加复杂性，应优先考虑声明处型变简化 API
    •
