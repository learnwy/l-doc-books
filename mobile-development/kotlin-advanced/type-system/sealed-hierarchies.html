密封层级

密封类（sealed class）和密封接口（sealed interface）是 Kotlin 中用于表示受限类层次结构的强大工具。它们确保所有子类型在编译时可知，从而实现穷尽检查（exhaustive checking）和精确的领域建模。

密封类基础

密封类限制了其直接子类型只能在同一包内定义（Kotlin 1.5+ 放宽至同一模块）：

sealed class Result<out T> {
    data class Success<T>(val data: T) : Result<T>()
    data class Error(val message: String, val cause: Throwable? = null) : Result<Nothing>()
    data object Loading : Result<Nothing>()
}

密封类本身是抽象的，不能直接实例化。

when 表达式穷尽检查

密封类与 when 配合使用时，编译器可以确保所有分支都已覆盖：

fun <T> handleResult(result: Result<T>): String = when (result) {
    is Result.Success -> "成功: ${result.data}"
    is Result.Error -> "错误: ${result.message}"
    is Result.Loading -> "加载中..."
    // 无需 else 分支，编译器已知所有子类型
}

提示： 如果添加了新的密封子类型但忘记更新 when 表达式，编译器会报错。这在大型项目中是极其重要的安全保障。

密封接口

Kotlin 1.5+ 引入了密封接口，提供了更灵活的建模能力：

sealed interface UiEvent
sealed interface NavigationEvent : UiEvent

data class Click(val id: String) : UiEvent
data class Swipe(val direction: String) : UiEvent
data class Navigate(val route: String) : NavigationEvent
data object Back : NavigationEvent

密封接口的优势在于一个类可以实现多个密封接口：

sealed interface Loggable
sealed interface Serializable

data class UserAction(val name: String) : Loggable, Serializable


密封类 vs 枚举
两者都表示有限的类型集合，但适用场景不同：

// 枚举：每个方向都是相同结构的单例
enum class Direction { NORTH, SOUTH, EAST, WEST }

// 密封类：每种形状携带不同的属性
sealed class Shape {
    data class Circle(val radius: Double) : Shape()
    data class Rectangle(val width: Double, val height: Double) : Shape()
    data class Triangle(val a: Double, val b: Double, val c: Double) : Shape()
}

fun area(shape: Shape): Double = when (shape) {
    is Shape.Circle -> Math.PI * shape.radius * shape.radius
    is Shape.Rectangle -> shape.width * shape.height
    is Shape.Triangle -> {
        val s = (shape.a + shape.b + shape.c) / 2
        Math.sqrt(s * (s - shape.a) * (s - shape.b) * (s - shape.c))
    }
}


层次化建模
密封类支持多层嵌套，形成精确的领域模型：


sealed class PaymentMethod {
    sealed class Card : PaymentMethod() {
        data class Credit(val number: String, val limit: Double) : Card()
        data class Debit(val number: String, val balance: Double) : Card()
    }

    sealed class Digital : PaymentMethod() {
        data class Alipay(val account: String) : Digital()
        data class WeChatPay(val openId: String) : Digital()
    }

    data class Cash(val currency: String) : PaymentMethod()
}

fun describe(method: PaymentMethod): String = when (method) {
    is PaymentMethod.Card.Credit -> "信用卡: ${method.number}"
    is PaymentMethod.Card.Debit -> "借记卡: ${method.number}"
    is PaymentMethod.Digital.Alipay -> "支付宝: ${method.account}"
    is PaymentMethod.Digital.WeChatPay -> "微信支付: ${method.openId}"
    is PaymentMethod.Cash -> "现金 (${method.currency})"
}


密封类与状态机
密封类非常适合表示有限状态机：


sealed class DownloadState {
    data object Idle : DownloadState()
    data class Downloading(val progress: Int) : DownloadState()
    data class Paused(val progress: Int) : DownloadState()
    data class Completed(val filePath: String) : DownloadState()
    data class Failed(val error: Throwable) : DownloadState()
}

fun transition(state: DownloadState, action: String): DownloadState = when (state) {
    is DownloadState.Idle -> when (action) {
        "start" -> DownloadState.Downloading(0)
        else -> state
    }
    is DownloadState.Downloading -> when (action) {
        "pause" -> DownloadState.Paused(state.progress)
        "complete" -> DownloadState.Completed("/downloads/file.zip")
        "fail" -> DownloadState.Failed(RuntimeException("网络错误"))
        else -> state
    }
    is DownloadState.Paused -> when (action) {
        "resume" -> DownloadState.Downloading(state.progress)
        else -> state
    }
    is DownloadState.Completed -> state
    is DownloadState.Failed -> when (action) {
        "retry" -> DownloadState.Downloading(0)
        else -> state
    }
}


最佳实践
    

  1. 优先使用密封接口：当不需要共享状态时，密封接口更灵活
    2. 

  2. 搭配 when 表达式：充分利用穷尽检查，避免 else 分支
    3. 

  3. 配合 data class/data object：自动获得 equals、hashCode、toString
    4. 

  4. 合理控制层级深度：超过三层嵌套会降低可读性
    5. 





提示： Kotlin 1.7+ 中，密封类的 when 穷尽检查已扩展为语句（statement）也强制要求，不仅限于表达式。






小结
    

  • 密封类限制子类型在同一模块内定义，使编译器能进行穷尽检查
    • 

  • 密封接口更灵活，允许一个类实现多个密封接口
    • 

  • 与 枚举的区别：密封类的子类可以携带不同属性、拥有多个实例
    • 

  • 密封类支持层次化嵌套，适合复杂领域建模
    • 

  • 典型应用场景包括：Result 类型、UI 状态、支付方式、状态机等
    • 

  • 搭配 when 的穷尽检查是密封类最重要的编译时安全保障
