协程上下文

协程上下文（CoroutineContext）是协程运行时环境的核心配置，决定了协程在哪个线程上执行、如何命名、以及异常如何处理。理解上下文机制是掌握协程调度与管理的关键。

CoroutineContext 结构

CoroutineContext 是一个不可变的集合，由多个 Element 组合而成，每个 Element 通过唯一的 Key 标识：

val context: CoroutineContext = Dispatchers.IO + CoroutineName("数据加载") + SupervisorJob()
上下文元素可以通过 + 运算符组合，右侧元素会覆盖左侧的同 Key 元素：


val base = Dispatchers.IO + CoroutineName("基础")
val overridden = base + Dispatchers.Default // Dispatcher 被覆盖为 Default


调度器（Dispatchers）
调度器决定协程在哪个线程或线程池上执行：






调度器
线程池
适用场景





Dispatchers.Main
主线程
UI 更新、轻量操作




Dispatchers.IO
共享 IO 线程池（默认 64 线程）
网络请求、文件读写、数据库操作




Dispatchers.Default
CPU 核心数大小的线程池
计算密集型任务（排序、解析、加密）




Dispatchers.Unconfined
不限制线程
测试、特殊场景





import kotlinx.coroutines.*

fun main() = runBlocking {
    launch(Dispatchers.Default) {
        println("Default: ${Thread.currentThread().name}")
    }

    launch(Dispatchers.IO) {
        println("IO: ${Thread.currentThread().name}")
    }

    launch(Dispatchers.Unconfined) {
        println("Unconfined 挂起前: ${Thread.currentThread().name}")
        delay(100)
        println("Unconfined 恢复后: ${Thread.currentThread().name}")
    }
}


提示： Dispatchers.Unconfined 会在挂起点后切换到恢复它的线程，通常只用于测试或特殊框架集成。






线程切换：withContext
使用 withContext 可以在协程内部切换调度器：


suspend fun fetchAndParse(): ParsedData {
    val raw = withContext(Dispatchers.IO) {
        httpClient.get("https://api.example.com/data") // IO 线程
    }
    return withContext(Dispatchers.Default) {
        parseJson(raw) // CPU 密集线程
    }
}


上下文继承
子协程自动继承父协程的上下文，但会使用新的 Job：


val parentContext = Dispatchers.IO + CoroutineName("父协程")

val scope = CoroutineScope(parentContext)
scope.launch { // 继承 Dispatchers.IO + CoroutineName("父协程")
    println("子协程: ${coroutineContext[CoroutineName]}")

    launch(CoroutineName("内部子协程")) { // 覆盖 Name，继承 Dispatcher
        println("内部: ${coroutineContext[CoroutineName]}")
        println("调度器: ${coroutineContext[ContinuationInterceptor]}")
    }
}
继承公式：


子协程上下文 = 父协程上下文 + 子协程参数覆盖 + 新 Job


CoroutineName
CoroutineName 为协程命名，便于调试和日志追踪：


val scope = CoroutineScope(Dispatchers.Default + CoroutineName("数据处理"))

scope.launch {
    println("运行在: ${coroutineContext[CoroutineName]?.name}")
    // 输出: 运行在: 数据处理
}
配合 -Dkotlinx.coroutines.debug JVM 参数，线程名中会包含协程名：


Thread: DefaultDispatcher-worker-1 @数据处理#1


自定义上下文元素
可以创建自定义的上下文元素来传递协程级别的数据：


class RequestId(val id: String) : AbstractCoroutineContextElement(RequestId) {
    companion object Key : CoroutineContext.Key<RequestId>
}

suspend fun logWithRequestId(message: String) {
    val requestId = coroutineContext[RequestId]?.id ?: "unknown"
    println("[$requestId] $message")
}

val scope = CoroutineScope(Dispatchers.Default + RequestId("req-001"))
scope.launch {
    logWithRequestId("开始处理") // [req-001] 开始处理

    launch(RequestId("req-002")) {
        logWithRequestId("子任务") // [req-002] 子任务
    }
}


自定义调度器
通过 Executor 可以创建自定义调度器：


import java.util.concurrent.Executors

val singleThread = Executors.newSingleThreadExecutor()
    .asCoroutineDispatcher()

val fixedPool = Executors.newFixedThreadPool(4)
    .asCoroutineDispatcher()

val scope = CoroutineScope(fixedPool)
scope.launch {
    println("运行在自定义线程池: ${Thread.currentThread().name}")
}

// 不再需要时关闭
singleThread.close()
fixedPool.close()
也可以使用 limitedParallelism 限制并行度：


val limitedIO = Dispatchers.IO.limitedParallelism(4)

repeat(100) {
    scope.launch(limitedIO) {
        // 最多 4 个协程同时在 IO 线程上执行
        performDatabaseQuery()
    }
}


小结
    

  • CoroutineContext 是不可变的元素集合，通过 + 组合，相同 Key 的元素会被覆盖
    • 

  • Dispatchers 控制协程的执行线程：Main（主线程）、IO（IO 密集）、Default（CPU 密集）、Unconfined（不限定）
    • 

  • withContext 在协程内部切换调度器，不创建新协程
    • 

  • 上下文继承遵循公式：子上下文 = 父上下文 + 显式覆盖 + 新 Job
    • 

  • CoroutineName 用于调试追踪，配合 debug 模式效果更佳
    • 

  • 可以通过 AbstractCoroutineContextElement 创建自定义上下文元素
    • 

  • limitedParallelism 可限制特定调度器的并行度
    •
