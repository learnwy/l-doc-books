异常处理

协程的异常处理遵循结构化并发原则——异常在协程层级中自动传播，父协程负责处理子协程的失败。理解异常传播机制和 SupervisorJob 的作用，是构建健壮异步系统的关键。

协程中的异常传播

默认情况下，子协程的未捕获异常会向上传播到父协程，并导致所有兄弟协程被取消：

fun main() = runBlocking {
    val scope = CoroutineScope(Job())

    scope.launch {
        launch {
            delay(200)
            throw RuntimeException("子协程1失败")
        }
        launch {
            delay(500)
            println("子协程2完成") // 不会执行，已被取消
        }
    }

    delay(1000)
}


launch vs async 的异常行为




构建器
异常时机
行为





launch
立即传播
异常直接传递给父协程或 CoroutineExceptionHandler




async
延迟到 await()
异常封装在 Deferred 中，调用 await() 时抛出





fun main() = runBlocking {
    supervisorScope {
        val deferred = async {
            throw ArithmeticException("计算错误")
        }

        try {
            deferred.await() // 异常在此处抛出
        } catch (e: ArithmeticException) {
            println("捕获到: ${e.message}")
        }
    }
}


提示： async 的异常只有在 await() 时才暴露，但如果 async 是 coroutineScope 的直接子协程，异常仍会立即传播。






try-catch 的正确使用
在协程内部可以使用标准的 try-catch 捕获异常：


suspend fun riskyOperation(): String {
    delay(100)
    throw IOException("网络异常")
}

fun main() = runBlocking {
    launch {
        try {
            riskyOperation()
        } catch (e: IOException) {
            println("已处理: ${e.message}")
        }
    }
}
注意：try-catch 不能包裹 launch/async 来捕获子协程异常：


fun main() = runBlocking {
    try {
        launch {
            throw RuntimeException("这个 catch 捕获不到")
        }
    } catch (e: Exception) {
        // 不会被执行！launch 的异常传播给父协程
    }
}


CoroutineExceptionHandler
CoroutineExceptionHandler 是协程的全局异常处理器，只对 launch 有效：


val handler = CoroutineExceptionHandler { context, exception ->
    println("捕获异常: ${exception.message}")
    println("协程: ${context[CoroutineName]?.name}")
}

fun main() = runBlocking {
    val scope = CoroutineScope(
        SupervisorJob() + handler + CoroutineName("主作用域")
    )

    scope.launch(CoroutineName("任务A")) {
        throw IllegalStateException("任务A失败")
    }

    scope.launch(CoroutineName("任务B")) {
        delay(500)
        println("任务B正常完成")
    }

    delay(1000)
}
// 捕获异常: 任务A失败
// 协程: 任务A
// 任务B正常完成

SupervisorJob
SupervisorJob 改变了异常传播方向——子协程的失败不会影响父协程和兄弟协程：


fun main() = runBlocking {
    val supervisor = SupervisorJob()
    val scope = CoroutineScope(supervisor + Dispatchers.Default)

    val job1 = scope.launch {
        println("Job1 开始")
        throw RuntimeException("Job1 崩溃")
    }

    val job2 = scope.launch {
        delay(500)
        println("Job2 正常完成") // 不受 Job1 影响
    }

    delay(1000)
    supervisor.cancel()
}
supervisorScope
supervisorScope 创建一个使用 SupervisorJob 的作用域：


suspend fun loadAllData() = supervisorScope {
    val users = async { fetchUsers() }
    val products = async { fetchProducts() }

    try {
        println("用户: ${users.await()}")
    } catch (e: Exception) {
        println("用户加载失败: ${e.message}")
    }

    try {
        println("商品: ${products.await()}")
    } catch (e: Exception) {
        println("商品加载失败: ${e.message}")
    }
}


异常处理策略对比


取消与 CancellationException
协程取消通过抛出 CancellationException 实现，这是一种特殊异常，不会传播给父协程：


fun main() = runBlocking {
    val job = launch {
        try {
            repeat(1000) { i ->
                println("工作中 $i")
                delay(100)
            }
        } catch (e: CancellationException) {
            println("协程被取消")
            throw e // 最佳实践：重新抛出
        } finally {
            println("执行清理")
        }
    }

    delay(350)
    job.cancelAndJoin()
}


提示： 捕获 CancellationException 后应重新抛出，否则会破坏取消机制。如果需要在取消后执行不可取消的清理操作，使用 withContext(NonCancellable)。




finally {
    withContext(NonCancellable) {
        delay(100) // 取消后 delay 正常工作
        saveState()
    }
}


实际场景：网络请求重试
suspend fun <T> retryWithExponentialBackoff(
    maxRetries: Int = 3,
    initialDelayMs: Long = 1000,
    block: suspend () -> T
): T {
    var currentDelay = initialDelayMs
    repeat(maxRetries - 1) { attempt ->
        try {
            return block()
        } catch (e: Exception) {
            if (e is CancellationException) throw e
            println("第 ${attempt + 1} 次重试，等待 ${currentDelay}ms")
        }
        delay(currentDelay)
        currentDelay *= 2
    }
    return block()
}


小结
    

  • 协程异常默认向上传播，导致父协程和兄弟协程被取消
    • 

  • launch 的异常立即传播，async 的异常延迟到 await() 抛出
    • 

  • try-catch 用于 suspend 函数内部，不能包裹 launch/async
    • 

  • CoroutineExceptionHandler 是根协程的最后异常处理机会，只对 launch 有效
    • 

  • SupervisorJob / supervisorScope 隔离子协程失败，防止影响兄弟协程
    • 

  • CancellationException 是特殊异常，不会传播给父协程，捕获后应重新抛出
    • 

  • 实际项目中应组合使用 SupervisorJob、Handler 和 try-catch 构建分层异常处理策略
