协程基础

Kotlin 协程是一种轻量级的并发解决方案，允许以顺序化的代码风格编写异步逻辑。协程不绑定到特定线程，可以在一个线程上挂起并在另一个线程上恢复，极大简化了异步编程的复杂度。

什么是协程

协程本质上是一种可挂起的计算。与线程不同，协程是协作式的——它们主动让出执行权，而非被操作系统强制调度。



提示： 一个线程可以运行数千个协程，而创建同等数量的线程会导致内存耗尽。






suspend 函数
suspend 关键字标记可以被挂起的函数。挂起函数只能在协程或其他挂起函数中调用：


suspend fun fetchUser(id: Long): User {
    delay(1000) // 挂起 1 秒，不阻塞线程
    return User(id, "张三")
}

suspend fun fetchUserPosts(userId: Long): List<Post> {
    delay(500)
    return listOf(Post("Kotlin 协程入门"), Post("Flow 实战"))
}
挂起函数在编译后会被转换为带有 Continuation 参数的普通函数：


// 编译后的签名大致为：
// fun fetchUser(id: Long, continuation: Continuation<User>): Any?


CoroutineScope
CoroutineScope 定义了协程的生命周期边界。所有协程都必须在某个作用域内启动：


class UserRepository {
    private val scope = CoroutineScope(SupervisorJob() + Dispatchers.IO)

    fun loadUser(id: Long) {
        scope.launch {
            val user = fetchUser(id)
            println("加载用户: ${user.name}")
        }
    }

    fun cleanup() {
        scope.cancel()
    }
}

Job 与生命周期
每个协程都关联一个 Job 对象，用于管理协程的生命周期：


val job = scope.launch {
    repeat(100) { i ->
        println("工作中 $i ...")
        delay(500)
    }
}

delay(2000)
job.cancel()       // 取消协程
job.join()         // 等待协程完成取消
// 或
job.cancelAndJoin() // 合并操作


launch vs async
Kotlin 提供两种主要的协程构建器：


fun main() = runBlocking {
    // launch: 启动即忘（fire-and-forget），返回 Job
    val job = launch {
        delay(1000)
        println("launch 完成")
    }

    // async: 启动并返回结果，返回 Deferred<T>
    val deferred = async {
        delay(1000)
        "async 的结果"
    }

    val result = deferred.await() // 等待结果
    println(result)
}

并行分解
async 特别适合将任务分解为并行子任务：


suspend fun loadDashboard(): Dashboard = coroutineScope {
    val userDeferred = async { fetchUser(userId) }
    val postsDeferred = async { fetchUserPosts(userId) }
    val statsDeferred = async { fetchStats(userId) }

    // 三个请求并行执行，总耗时取决于最慢的请求
    Dashboard(
        user = userDeferred.await(),
        posts = postsDeferred.await(),
        stats = statsDeferred.await()
    )
}


结构化并发
Kotlin 协程遵循结构化并发原则——父协程会等待所有子协程完成，子协程的失败会传播给父协程：


suspend fun processOrders(orders: List<Order>) = coroutineScope {
    orders.forEach { order ->
        launch {
            processOrder(order)
        }
    }
    // coroutineScope 会等待所有 launch 的子协程完成
    // 如果任何一个子协程失败，所有兄弟协程都会被取消
}


提示： coroutineScope 创建的作用域会等待所有子协程，而 supervisorScope 允许子协程独立失败。






runBlocking
runBlocking 桥接阻塞世界与协程世界，它会阻塞当前线程直到内部协程完成：


fun main() = runBlocking {
    launch {
        delay(1000)
        println("World!")
    }
    println("Hello")
}
// 输出：Hello
// （1 秒后）World!


提示： runBlocking 主要用于 main 函数和测试代码。在生产代码中应避免使用，以免阻塞线程。






小结
    

  • 协程是轻量级的并发原语，可以挂起和恢复而不阻塞线程
    • 

  • suspend 函数通过 suspend 关键字声明，是协程中执行异步操作的基本单元
    • 

  • CoroutineScope 定义协程的生命周期边界，确保资源正确释放
    • 

  • Job 管理协程的生命周期状态，支持取消和等待操作
    • 

  • launch 用于不需要返回值的异步任务，async 用于需要返回结果的并行计算
    • 

  • 结构化并发确保父子协程之间的生命周期关系清晰、异常传播可控
    •
