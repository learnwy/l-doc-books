Part II · AndroidKotlin 语言进阶 简介协程 简介通道

通道

通道（Channel）是协程之间通信的核心原语，提供了类似阻塞队列的语义，但以挂起代替阻塞。通道实现了生产者-消费者模式，是协程间安全传递数据的首选方式。

Channel 基础

Channel 提供 send 和 receive 两个挂起操作：

import kotlinx.coroutines.*
import kotlinx.coroutines.channels.*

fun main() = runBlocking {
    val channel = Channel<Int>()

    launch {
        for (x in 1..5) {
            channel.send(x * x)
            println("发送: ${x * x}")
        }
        channel.close()
    }

    for (value in channel) {
        println("接收: $value")
    }
}

提示： 生产者完成后应调用 channel.close()，消费者可以通过 for 循环迭代已关闭的通道。

Channel 类型

Kotlin 提供四种缓冲策略的 Channel：

类型 容量 send 行为 receive 行为
Rendezvous 0 挂起直到有接收者 挂起直到有发送者
Buffered 固定值 N 缓冲满时挂起 缓冲空时挂起
Conflated 1（覆盖） 不挂起，覆盖旧值 只取最新值
Unlimited 无限 不挂起（可能 OOM） 无数据时挂起 
val rendezvous = Channel<Int>()                         // Rendezvous
val buffered = Channel<Int>(capacity = 10)              // Buffered
val conflated = Channel<Int>(Channel.CONFLATED)         // Conflated
val unlimited = Channel<Int>(Channel.UNLIMITED)         // Unlimited


produce 构建器
produce 是创建生产者协程的便捷方式，它自动管理通道的关闭：


fun CoroutineScope.generateNumbers(): ReceiveChannel<Int> = produce {
    var n = 1
    while (true) {
        send(n++)
        delay(100)
    }
}

fun main() = runBlocking {
    val numbers = generateNumbers()
    repeat(5) {
        println(numbers.receive())
    }
    numbers.cancel()
}


Fan-Out（扇出）
多个协程从同一个通道接收数据，实现负载均衡：


fun main() = runBlocking {
    val channel = produce {
        repeat(10) {
            send(it)
            delay(50)
        }
    }

    repeat(3) { workerId ->
        launch {
            for (msg in channel) {
                println("Worker $workerId 处理: $msg")
                delay(150)
            }
        }
    }
}


提示： Fan-Out 模式下，每条消息只会被一个消费者接收，实现自动的任务分发。






Fan-In（扇入）
多个协程向同一个通道发送数据：


suspend fun produceMessages(channel: SendChannel<String>, id: String, count: Int) {
    repeat(count) {
        channel.send("来自 $id 的消息 #$it")
        delay(100)
    }
}

fun main() = runBlocking {
    val channel = Channel<String>()

    launch { produceMessages(channel, "传感器A", 5) }
    launch { produceMessages(channel, "传感器B", 5) }

    repeat(10) {
        println(channel.receive())
    }
}


管道（Pipeline）
通道可以串联形成处理管道：


fun CoroutineScope.produceInts(): ReceiveChannel<Int> = produce {
    var x = 1
    while (true) send(x++)
}

fun CoroutineScope.square(input: ReceiveChannel<Int>): ReceiveChannel<Int> = produce {
    for (x in input) send(x * x)
}

fun CoroutineScope.filter(input: ReceiveChannel<Int>, predicate: (Int) -> Boolean): ReceiveChannel<Int> = produce {
    for (x in input) {
        if (predicate(x)) send(x)
    }
}

fun main() = runBlocking {
    val numbers = produceInts()
    val squares = square(numbers)
    val filtered = filter(squares) { it < 100 }

    for (value in filtered) {
        println(value) // 1, 4, 9, 16, 25, 36, 49, 64, 81
    }

    coroutineContext.cancelChildren()
}


select 表达式
select 可以同时等待多个通道的操作，哪个先就绪就执行哪个：


import kotlinx.coroutines.selects.select

suspend fun selectDemo() = coroutineScope {
    val fast = produce {
        delay(100)
        send("快速结果")
    }

    val slow = produce {
        delay(500)
        send("慢速结果")
    }

    val result = select {
        fast.onReceive { "从快通道收到: $it" }
        slow.onReceive { "从慢通道收到: $it" }
    }

    println(result) // 从快通道收到: 快速结果
    coroutineContext.cancelChildren()
}




select 子句
说明

小结
    

  • Channel 是协程间安全传递数据的核心原语，以挂起代替阻塞
    • 

  • 四种缓冲策略：Rendezvous（无缓冲）、Buffered（固定缓冲）、Conflated（保留最新）、Unlimited（无限缓冲）
    • 

  • produce 构建器简化了生产者协程的创建和资源管理
    • 

  • Fan-Out 实现多消费者负载均衡，Fan-In 实现多生产者汇聚
    • 

  • 管道模式通过串联通道构建数据处理流水线
    • 

  • select 表达式支持同时等待多个通道操作
    • 

  • Channel 是热的，适合协程间通信；Flow 是冷的，适合数据流场景
