上下文接收者

上下文接收者（Context Receivers）是 Kotlin 中一项实验性特性，允许为函数声明多个隐式接收者。它解决了扩展函数只能有一个接收者的限制，使得需要多个上下文的场景更加优雅。

问题背景

传统的扩展函数只能有一个接收者：

// 只能有一个接收者
fun Transaction.saveUser(user: User) { /* ... */ }

// 如果同时需要 Logger 上下文呢？
// fun Transaction.Logger.saveUser(user: User) { } // 不合法！

现有的解决方案都有局限：

方案 限制
参数传递 代码冗长，调用处不够简洁
嵌套扩展函数 只能有一层嵌套接收者
接口继承组合 类型膨胀，不灵活
全局或 ThreadLocal 不类型安全，难以管理

context() 语法

提示： 上下文接收者目前是实验性特性，需要添加编译器参数 -Xcontext-receivers。Kotlin 团队正在重新设计该特性，未来语法可能变化。

context(Logger, Transaction)
fun saveUser(user: User) {
    log("保存用户: ${user.name}")  // 来自 Logger
    execute("INSERT INTO users VALUES ('${user.name}')")  // 来自 Transaction
}

使用时需要在正确的上下文中调用：

interface Logger {
    fun log(message: String)
}

interface Transaction {
    fun execute(sql: String)
}

fun demo(logger: Logger, tx: Transaction) {
    with(logger) {
        with(tx) {
            saveUser(User("张三")) // 两个上下文都可用
        }
    }
}


多接收者示例
日志 + 配置上下文
interface AppConfig {
    val maxRetries: Int
    val timeout: Long
}

interface Logger {
    fun log(message: String)
}

context(AppConfig, Logger)
fun fetchWithRetry(url: String): String {
    repeat(maxRetries) { attempt ->       // 来自 AppConfig
        log("第 ${attempt + 1} 次尝试: $url") // 来自 Logger
        try {
            return httpGet(url, timeout)   // 来自 AppConfig
        } catch (e: Exception) {
            log("失败: ${e.message}")
        }
    }
    throw RuntimeException("超过最大重试次数")
}
领域建模
interface MoneyContext {
    val currency: String
    fun formatAmount(amount: Double): String
}

interface TaxContext {
    val taxRate: Double
}

context(MoneyContext, TaxContext)
fun calculateTotal(subtotal: Double): String {
    val tax = subtotal * taxRate                // 来自 TaxContext
    val total = subtotal + tax
    return formatAmount(total)                   // 来自 MoneyContext
}

// 扩展函数：适合"对象.操作"的语义
fun String.toSlug(): String = this.lowercase().replace(" ", "-")

// 上下文接收者：适合"在某个上下文中执行操作"的语义
context(Logger)
fun String.logAndProcess(): String {
    log("处理: $this")         // Logger 上下文
    return this.uppercase()    // String 扩展接收者
}


作用域控制
上下文接收者可以与 @DslMarker 配合，控制嵌套作用域中的可见性：


@DslMarker
annotation class ServiceDsl

@ServiceDsl
interface DatabaseScope {
    fun query(sql: String): List<Map<String, Any>>
}

@ServiceDsl
interface CacheScope {
    fun get(key: String): String?
    fun put(key: String, value: String)
}

context(DatabaseScope, CacheScope)
fun getCachedUser(id: Long): Map<String, Any>? {
    val cached = get("user:$id")                          // CacheScope
    if (cached != null) return mapOf("name" to cached)

    val results = query("SELECT * FROM users WHERE id = $id") // DatabaseScope
    results.firstOrNull()?.let { user ->
        put("user:$id", user["name"].toString())          // CacheScope
    }
    return results.firstOrNull()
}


迁移策略
由于上下文接收者仍在演进中，建议采用渐进式迁移：


当前推荐的替代模式：


// 方案 1：参数传递
fun saveUser(user: User, logger: Logger, tx: Transaction) {
    logger.log("保存用户")
    tx.execute("INSERT ...")
}

// 方案 2：包装类
class UserService(
    private val logger: Logger,
    private val tx: Transaction
) {
    fun saveUser(user: User) {
        logger.log("保存用户")
        tx.execute("INSERT ...")
    }
}

// 方案 3：作用域函数嵌套（短期可用）
fun demo(logger: Logger, tx: Transaction) {
    with(logger) {
        with(tx) {
            // 两个上下文都可用
        }
    }
}


编译器配置
启用上下文接收者需要添加编译器参数：


// build.gradle.kts
tasks.withType<KotlinCompile> {
    kotlinOptions {
        freeCompilerArgs += "-Xcontext-receivers"
    }
}


提示： Kotlin 团队正在开发名为"context parameters"的新设计来替代当前的上下文接收者语法。关注 KEEP-259 提案了解最新进展。






小结
    

  • 上下文接收者允许为函数声明多个隐式接收者，解决扩展函数的单接收者限制
    • 

  • 通过 context(A, B) 语法声明，函数体内可直接访问所有上下文成员
    • 

  • 与扩展函数的区别：上下文接收者表达"在某个上下文中执行"，扩展函数表达"对象的操作"
    • 

  • 目前仍是实验性特性，需要编译器参数 -Xcontext-receivers
    • 

  • 生产代码建议使用接口 + 参数或包装类作为替代，DSL/框架代码可以谨慎使用
    • 

  • Kotlin 团队正在开发 context parameters 新设计，未来语法可能变化
    •
