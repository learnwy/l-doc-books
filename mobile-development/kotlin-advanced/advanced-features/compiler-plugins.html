编译器插件

Kotlin 编译器插件在编译阶段修改或生成代码，是许多框架和工具的核心技术。从 KSP（Kotlin Symbol Processing）到序列化插件，编译器插件让开发者能够消除样板代码、实现代码生成和增强编译时检查。

KSP 处理器示例
// build.gradle.kts
plugins {
    id("com.google.devtools.ksp") version "1.9.20-1.0.14"
}

dependencies {
    ksp("com.example:my-processor:1.0")
}
一个简单的 KSP 处理器结构：


class MyProcessor(
    private val codeGenerator: CodeGenerator,
    private val logger: KSPLogger
) : SymbolProcessor {

    override fun process(resolver: Resolver): List<KSAnnotated> {
        val symbols = resolver.getSymbolsWithAnnotation("com.example.AutoFactory")
            .filterIsInstance<KSClassDeclaration>()

        symbols.forEach { classDecl ->
            generateFactory(classDecl)
        }

        return emptyList() // 返回未处理的符号（下一轮再处理）
    }

    private fun generateFactory(classDecl: KSClassDeclaration) {
        val packageName = classDecl.packageName.asString()
        val className = classDecl.simpleName.asString()

        val file = codeGenerator.createNewFile(
            Dependencies(true, classDecl.containingFile!!),
            packageName,
            "${className}Factory"
        )

        file.writer().use { writer ->
            writer.write("""
                package $packageName

                object ${className}Factory {
                    fun create(): $className = $className()
                }
            """.trimIndent())
        }
    }
}

class MyProcessorProvider : SymbolProcessorProvider {
    override fun create(environment: SymbolProcessorEnvironment): SymbolProcessor {
        return MyProcessor(environment.codeGenerator, environment.logger)
    }
}


提示： KSP 处理器需要在 META-INF/services/com.google.devtools.ksp.processing.SymbolProcessorProvider 中注册。






all-open 插件
all-open 插件自动为标注了特定注解的类添加 open 修饰符。Spring 框架需要 CGLIB 代理，而 Kotlin 类默认是 final 的：


// build.gradle.kts
plugins {
    kotlin("plugin.allopen") version "1.9.20"
}

allOpen {
    annotation("org.springframework.stereotype.Service")
    annotation("org.springframework.stereotype.Component")
    annotation("org.springframework.transaction.annotation.Transactional")
}
@Service // 编译后自动变为 open
class UserService {
    // 所有方法也自动变为 open
    fun findUser(id: Long): User? = repository.findById(id)
}


no-arg 插件
no-arg 插件为标注了特定注解的类生成无参构造函数。JPA 实体需要无参构造函数：


// build.gradle.kts
plugins {
    kotlin("plugin.noarg") version "1.9.20"
}

noArg {
    annotation("jakarta.persistence.Entity")
    invokeInitializers = true // 调用 init 块
}
@Entity
data class User(
    @Id val id: Long,
    val name: String,
    val email: String
)
// 编译后自动生成 User() 无参构造函数
// 源码中不可见，但反射和 JPA 可以使用


kotlin-serialization 插件
序列化插件是最广泛使用的 Kotlin 编译器插件，为 @Serializable 类自动生成序列化器：


// build.gradle.kts
plugins {
    kotlin("plugin.serialization") version "1.9.20"
}

dependencies {
    implementation("org.jetbrains.kotlinx:kotlinx-serialization-json:1.6.0")
}
import kotlinx.serialization.*
import kotlinx.serialization.json.*

@Serializable
data class User(
    val id: Long,
    val name: String,
    @SerialName("email_address")
    val email: String,
    val roles: List<String> = emptyList()
)

val json = Json { prettyPrint = true }
val user = User(1, "张三", "zhangsan@example.com", listOf("admin"))

val jsonString = json.encodeToString(user)
val decoded = json.decodeFromString<User>(jsonString)

自定义编译器插件基础
自定义编译器插件开发涉及 Kotlin 编译器的 IR（Intermediate Representation）层：


// 插件注册
class MyCompilerPlugin : CompilerPluginRegistrar() {
    override val supportsK2: Boolean = true

    override fun ExtensionStorage.registerExtensions(configuration: CompilerConfiguration) {
        IrGenerationExtension.registerExtension(MyIrExtension())
    }
}

// IR 变换
class MyIrExtension : IrGenerationExtension {
    override fun generate(moduleFragment: IrModuleFragment, pluginContext: IrPluginContext) {
        moduleFragment.transformChildrenVoid(object : IrElementTransformerVoid() {
            override fun visitFunction(declaration: IrFunction): IrStatement {
                // 在此处修改函数的 IR
                return super.visitFunction(declaration)
            }
        })
    }
}


提示： 自定义编译器插件开发门槛较高，需要深入理解 Kotlin IR。对于大多数代码生成需求，KSP 是更好的选择。






插件选择指南


小结
    

  • KSP 是轻量级的 Kotlin 符号处理器，比 KAPT 更快且支持 KMP
    • 

  • all-open 插件为标注注解的类自动添加 open，解决 Spring 代理需求
    • 

  • no-arg 插件为标注注解的类生成无参构造函数，满足 JPA 需求
    • 

  • kotlin-serialization 插件为 @Serializable 类自动生成序列化器
    • 

  • 自定义编译器插件通过 IR 变换实现深度编译行为修改，开发门槛较高
    • 

  • 优先选择 KSP 进行代码生成，只有在需要修改编译行为时才考虑自定义编译器插件
    •
