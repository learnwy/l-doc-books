Espresso UI 测试框架

Espresso 是 Android 传统 View 体系的 UI 测试框架，提供可靠的同步机制和丰富的匹配器。尽管 Jetpack Compose 有自己的测试框架，但在混合项目中或测试非 Compose UI 时，Espresso 仍然不可或缺。

ViewMatchers / ViewActions / ViewAssertions

Espresso 测试由三个核心部分组成：查找视图、执行操作、验证结果。

@RunWith(AndroidJUnit4::class)
class LoginActivityTest {

    @get:Rule
    val activityRule = ActivityScenarioRule(LoginActivity::class.java)

    @Test
    fun loginFlow_withValidCredentials_navigatesToHome() {
        onView(withId(R.id.username_input))
            .perform(typeText("admin"), closeSoftKeyboard())

        onView(withId(R.id.password_input))
            .perform(typeText("password123"), closeSoftKeyboard())

        onView(withId(R.id.login_button))
            .perform(click())

        onView(withId(R.id.welcome_text))
            .check(matches(withText(containsString("欢迎"))))
    }

    @Test
    fun loginButton_disabled_whenFieldsEmpty() {
        onView(withId(R.id.login_button))
            .check(matches(not(isEnabled())))
    }

    @Test
    fun errorMessage_shown_withInvalidCredentials() {
        onView(withId(R.id.username_input))
            .perform(typeText("wrong"), closeSoftKeyboard())
        onView(withId(R.id.password_input))
            .perform(typeText("wrong"), closeSoftKeyboard())
        onView(withId(R.id.login_button))
            .perform(click())

        onView(withText("用户名或密码错误"))
            .check(matches(isDisplayed()))
    }
}

Idling Resources
Espresso 的自动同步机制确保在 UI 空闲时才执行操作。对于自定义异步操作，需要通过 Idling Resource 通知 Espresso。


class DataLoadingIdlingResource : IdlingResource {

    @Volatile
    private var isIdle = true
    private var callback: IdlingResource.ResourceCallback? = null

    override fun getName(): String = "DataLoadingIdlingResource"

    override fun isIdleNow(): Boolean = isIdle

    override fun registerIdleTransitionCallback(callback: IdlingResource.ResourceCallback) {
        this.callback = callback
    }

    fun setIdle(idle: Boolean) {
        isIdle = idle
        if (idle) callback?.onTransitionToIdle()
    }
}

class OkHttpIdlingResource private constructor(
    private val dispatcher: okhttp3.Dispatcher
) : IdlingResource {

    override fun getName(): String = "OkHttp"

    override fun isIdleNow(): Boolean = dispatcher.runningCallsCount() == 0

    override fun registerIdleTransitionCallback(callback: IdlingResource.ResourceCallback) {
        dispatcher.idleCallback = Runnable { callback.onTransitionToIdle() }
    }

    companion object {
        fun create(client: OkHttpClient): OkHttpIdlingResource {
            return OkHttpIdlingResource(client.dispatcher)
        }
    }
}

@RunWith(AndroidJUnit4::class)
class ArticleListTest {

    private val idlingResource = DataLoadingIdlingResource()

    @Before
    fun setup() {
        IdlingRegistry.getInstance().register(idlingResource)
    }

    @After
    fun teardown() {
        IdlingRegistry.getInstance().unregister(idlingResource)
    }

    @Test
    fun articleList_showsAfterLoading() {
        onView(withId(R.id.article_list))
            .check(matches(isDisplayed()))
        onView(withText("文章标题"))
            .check(matches(isDisplayed()))
    }
}


Intent 测试
Espresso-Intents 扩展库允许验证和模拟 Intent 交互。


@RunWith(AndroidJUnit4::class)
class ShareActivityTest {

    @get:Rule
    val intentsRule = IntentsRule()

    @get:Rule
    val activityRule = ActivityScenarioRule(ArticleActivity::class.java)

    @Test
    fun shareButton_sendsCorrectIntent() {
        onView(withId(R.id.share_button)).perform(click())

        intended(allOf(
            hasAction(Intent.ACTION_SEND),
            hasType("text/plain"),
            hasExtra(Intent.EXTRA_TEXT, containsString("https://"))
        ))
    }

    @Test
    fun cameraButton_launchesCamera() {
        val resultData = Intent().apply {
            putExtra("photo_uri", "content://photo/1")
        }
        intending(hasAction(MediaStore.ACTION_IMAGE_CAPTURE))
            .respondWith(Instrumentation.ActivityResult(Activity.RESULT_OK, resultData))

        onView(withId(R.id.camera_button)).perform(click())

        onView(withId(R.id.photo_preview))
            .check(matches(isDisplayed()))
    }
}

自定义匹配器
当内置匹配器不够用时，可以创建自定义匹配器。


fun withItemCount(expectedCount: Int): Matcher<View> {
    return object : BoundedMatcher<View, RecyclerView>(RecyclerView::class.java) {
        override fun describeTo(description: Description) {
            description.appendText("RecyclerView should have $expectedCount items")
        }

        override fun matchesSafely(view: RecyclerView): Boolean {
            return view.adapter?.itemCount == expectedCount
        }
    }
}

fun atPosition(position: Int, itemMatcher: Matcher<View>): Matcher<View> {
    return object : BoundedMatcher<View, RecyclerView>(RecyclerView::class.java) {
        override fun describeTo(description: Description) {
            description.appendText("has item at position $position: ")
            itemMatcher.describeTo(description)
        }

        override fun matchesSafely(view: RecyclerView): Boolean {
            val viewHolder = view.findViewHolderForAdapterPosition(position)
            return viewHolder != null && itemMatcher.matches(viewHolder.itemView)
        }
    }
}

@Test
fun recyclerView_displaysCorrectItems() {
    onView(withId(R.id.article_list))
        .check(matches(withItemCount(10)))

    onView(withId(R.id.article_list))
        .check(matches(atPosition(0, hasDescendant(withText("第一篇文章")))))
}


提示： 在混合 Compose + View 的项目中，可以同时使用 Espresso 和 Compose Testing，它们可以在同一个测试中共存。






小结
    

  • Espresso 通过 ViewMatcher → ViewAction → ViewAssertion 三步完成 UI 测试
    • 

  • Idling Resource 通知 Espresso 自定义异步操作的完成状态
    • 

  • Espresso-Intents 验证和模拟 Intent 交互，适合测试页面跳转和系统交互
    • 

  • 自定义匹配器通过 BoundedMatcher 实现，扩展 Espresso 的匹配能力
    • 

  • Espresso 与 Compose Testing 可以在混合项目中共存
    •
