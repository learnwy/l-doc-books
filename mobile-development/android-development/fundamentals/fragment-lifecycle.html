Fragment 生命周期

Fragment 是 Android 中可重用的 UI 组件，拥有自己独立的生命周期。尽管 Jetpack Compose 逐渐替代传统 Fragment，但在许多现有项目和特定场景中（如 Navigation Component），Fragment 仍然扮演着重要角色。

Fragment Manager

FragmentManager 是管理 Fragment 的核心类，负责 Fragment 的添加、移除、替换和回退栈管理。

class HostActivity : AppCompatActivity() {

    fun navigateToDetail(itemId: String) {
        supportFragmentManager.commit {
            replace(
                R.id.fragment_container,
                DetailFragment.newInstance(itemId),
                "detail"
            )
            addToBackStack("detail")
            setReorderingAllowed(true)
        }
    }
}

class DetailFragment : Fragment(R.layout.fragment_detail) {

    companion object {
        fun newInstance(itemId: String) = DetailFragment().apply {
            arguments = bundleOf("itemId" to itemId)
        }
    }
}


提示： 始终调用 setReorderingAllowed(true) 以启用 Fragment 事务优化，这是 Navigation Component 的默认行为。






viewLifecycleOwner
Fragment 有两个不同的生命周期：Fragment 自身的生命周期和其 View 的生命周期。在观察 LiveData 或收集 Flow 时，必须使用 viewLifecycleOwner 而非 Fragment 自身。


class UserListFragment : Fragment(R.layout.fragment_user_list) {

    private val viewModel: UserListViewModel by viewModels()

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        viewLifecycleOwner.lifecycleScope.launch {
            viewLifecycleOwner.repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.users.collect { users ->
                    adapter.submitList(users)
                }
            }
        }
    }
}

提示： 在 onDestroyView 中清除对 View 的引用（如 _binding = null），避免 Fragment 在回退栈中时因持有已销毁的 View 而导致内存泄漏。






父子 Fragment
Fragment 可以嵌套使用，子 Fragment 通过 childFragmentManager 管理。


class DashboardFragment : Fragment(R.layout.fragment_dashboard) {

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        if (savedInstanceState == null) {
            childFragmentManager.commit {
                replace(R.id.chart_container, ChartFragment())
                replace(R.id.stats_container, StatsFragment())
                setReorderingAllowed(true)
            }
        }
    }
}

Fragment Result API
Fragment Result API 提供了 Fragment 之间类型安全的通信方式，替代了旧的 setTargetFragment 方法。


class FilterFragment : Fragment() {

    private fun applyFilter(filter: Filter) {
        setFragmentResult("filter_request", bundleOf(
            "category" to filter.category,
            "sort_by" to filter.sortBy
        ))
        parentFragmentManager.popBackStack()
    }
}

class ProductListFragment : Fragment() {

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        setFragmentResultListener("filter_request") { _, bundle ->
            val category = bundle.getString("category") ?: "all"
            val sortBy = bundle.getString("sort_by") ?: "name"
            viewModel.applyFilter(category, sortBy)
        }
    }
}
父子 Fragment 之间通信时使用 childFragmentManager：


class ParentFragment : Fragment() {

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        childFragmentManager.setFragmentResultListener("child_result", viewLifecycleOwner) { _, bundle ->
            val data = bundle.getString("data")
            handleChildResult(data)
        }
    }
}


小结
    

  • FragmentManager 负责 Fragment 事务管理，commit 时始终启用 setReorderingAllowed(true)
    • 

  • Fragment 拥有双重生命周期，观察数据时必须使用 viewLifecycleOwner 避免内存泄漏
    • 

  • 子 Fragment 通过 childFragmentManager 管理，与父 Fragment 通过 parentFragmentManager 通信
    • 

  • Fragment Result API 是 Fragment 间通信的推荐方式，类型安全且生命周期感知
    • 

  • 在 onDestroyView 中清除 View 绑定引用，防止回退栈场景下的内存泄漏
