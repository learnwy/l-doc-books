Activity 生命周期

Activity 是 Android 应用中用户交互的基本单元。理解 Activity 的生命周期是构建健壮 Android 应用的基础，它直接影响到用户体验、数据保存和资源管理。

生命周期回调

Activity 的生命周期由一系列回调方法组成，系统会在 Activity 状态发生变化时调用这些方法。

每个回调的职责：






回调
触发时机
典型操作





onCreate()
Activity 首次创建
初始化布局、绑定数据、注入依赖




onStart()
Activity 变为可见
注册广播接收器、启动动画




onResume()
Activity 获取焦点，可交互
启动相机预览、恢复播放器




onPause()
Activity 失去焦点
暂停动画、保存草稿




onStop()
Activity 不再可见
释放重资源、保存持久化数据




onDestroy()
Activity 即将销毁
最终清理（通常由 ViewModel 管理）





class MainActivity : ComponentActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            MyApp()
        }
    }

    override fun onStart() {
        super.onStart()
        analyticsTracker.trackScreenView("main")
    }

    override fun onResume() {
        super.onResume()
        sensorManager.registerListener(this, accelerometer, SENSOR_DELAY_UI)
    }

    override fun onPause() {
        super.onPause()
        sensorManager.unregisterListener(this)
    }

    override fun onStop() {
        super.onStop()
        draftRepository.saveDraft(currentDraft)
    }
}


提示： 在 Jetpack Compose 中，大部分生命周期感知逻辑应通过 DisposableEffect 和 LaunchedEffect 处理，而非直接重写 Activity 回调。






状态恢复
当系统因资源不足而销毁 Activity 时，需要通过 onSaveInstanceState 保存临时 UI 状态。


class SearchActivity : ComponentActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        val query = savedInstanceState?.getString("search_query") ?: ""
        val scrollPosition = savedInstanceState?.getInt("scroll_position") ?: 0

        setContent {
            SearchScreen(initialQuery = query, initialScroll = scrollPosition)
        }
    }

    override fun onSaveInstanceState(outState: Bundle) {
        super.onSaveInstanceState(outState)
        outState.putString("search_query", currentQuery)
        outState.putInt("scroll_position", currentScrollPosition)
    }
}

配置变更
配置变更（如屏幕旋转、语言切换、暗黑模式切换）默认会销毁并重建 Activity。


处理配置变更的最佳实践：


class ArticleViewModel(
    private val savedStateHandle: SavedStateHandle,
    private val repository: ArticleRepository
) : ViewModel() {

    val searchQuery = savedStateHandle.getStateFlow("query", "")

    val articles = searchQuery
        .debounce(300)
        .flatMapLatest { query ->
            repository.searchArticles(query)
        }
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5000),
            initialValue = emptyList()
        )

    fun updateQuery(query: String) {
        savedStateHandle["query"] = query
    }
}


提示： 避免在 AndroidManifest.xml 中使用 android:configChanges 来阻止 Activity 重建，这种方式难以维护且容易遗漏某些配置变更场景。






进程死亡
当应用处于后台时，系统可能因内存压力杀死整个应用进程。进程死亡与普通的 Activity 销毁不同，ViewModel 中的数据也会丢失。


模拟进程死亡进行测试：


// 使用 ADB 命令模拟进程死亡
// adb shell am kill com.example.myapp

// 在测试中验证状态恢复
@Test
fun testProcessDeathRecovery() {
    val savedState = SavedStateHandle(mapOf("query" to "Android"))
    val viewModel = ArticleViewModel(savedState, fakeRepository)

    assertEquals("Android", viewModel.searchQuery.value)
}

小结
    

  • Activity 生命周期包含六个核心回调：onCreate、onStart、onResume、onPause、onStop、onDestroy
    • 

  • 使用 SavedStateHandle 和 rememberSaveable 保存 UI 状态，确保配置变更和进程死亡后可恢复
    • 

  • 配置变更（旋转、语言等）会默认重建 Activity，应通过 ViewModel 持有数据避免重复加载
    • 

  • 进程死亡会导致 ViewModel 数据丢失，必须依赖 SavedStateHandle 或持久化存储恢复关键状态
    • 

  • 使用 ADB 命令 am kill 可以模拟进程死亡场景，确保应用在极端情况下正确恢复
