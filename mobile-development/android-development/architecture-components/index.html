架构组件 简介

构建一个功能完整的 Android 应用不仅需要精美的界面，更需要可靠的数据管理、生命周期感知的状态持有和稳定的后台任务执行能力。Jetpack 架构组件正是为解决这些核心问题而设计的官方库集合，它们将 Google 多年积累的最佳实践封装为开箱即用的工具，帮助开发者构建健壮、可测试、可维护的应用架构。本章深入四个最重要的架构组件，它们共同构成了现代 Android 应用数据层和业务层的基础设施。

第一节"ViewModel"介绍 Android 中最核心的状态管理组件。ViewModel 在配置变更（如屏幕旋转）时保持存活的生命周期特性、它作为界面层与数据层之间桥梁的职责定位、通过 StateFlow 或 Compose State 向界面暴露数据的最佳模式，以及在 Compose 和 Fragment 中获取与共享 ViewModel 的不同方式——正确使用 ViewModel 是实现关注点分离的第一步。

第二节"Room 数据库"深入 Android 本地持久化的标准方案。Room 在 SQLite 之上提供的编译期 SQL 校验能力、Entity 和 DAO 的定义方式与数据访问模式、数据库版本迁移的策略与实践，以及 Room 与 Flow 的结合如何实现数据变更的自动通知——Room 让本地数据库操作从容易出错的字符串拼接变为类型安全的 Kotlin 代码。

第三节"DataStore"介绍用于替代 SharedPreferences 的现代键值存储方案。Preferences DataStore 的类型安全读写、Proto DataStore 基于 Protocol Buffers 的结构化存储、DataStore 的异步非阻塞 API 设计，以及在数据迁移场景下从 SharedPreferences 平滑过渡的策略——对于轻量级的配置和偏好数据，DataStore 提供了更安全、更高效的存储选择。

第四节"WorkManager"解决 Android 后台任务调度这一长期痛点。WorkManager 对设备重启后任务恢复的可靠保证、约束条件（网络、充电、存储等）的灵活配置、一次性任务与周期性任务的定义方式，以及任务链的编排与并行执行策略——在 Android 日益严格的后台限制下，WorkManager 是执行可延迟后台工作的唯一官方推荐方案。

建议先学习 ViewModel 建立架构思维，再根据项目需求选择性地深入 Room、DataStore 或 WorkManager。这四个组件在实际项目中往往协同使用，理解它们各自的职责边界和协作方式，是设计清晰应用架构的关键。
