Koin 替代方案

Koin 是一个轻量级的 Kotlin 依赖注入框架，采用 DSL 声明式语法，不依赖代码生成或注解处理。对于中小型项目或偏好简洁配置的团队，Koin 是 Hilt/Dagger 的优秀替代方案。

DSL 声明

Koin 使用 Kotlin DSL 声明依赖关系，语法直观且易于理解。

val networkModule = module {
    single {
        OkHttpClient.Builder()
            .connectTimeout(30, TimeUnit.SECONDS)
            .addInterceptor(get<AuthInterceptor>())
            .build()
    }

    single {
        Retrofit.Builder()
            .baseUrl("https://api.example.com/")
            .client(get())
            .addConverterFactory(Json.asConverterFactory("application/json".toMediaType()))
            .build()
    }

    single { get<Retrofit>().create(ArticleApi::class.java) }
}

val repositoryModule = module {
    single<ArticleRepository> { ArticleRepositoryImpl(get(), get()) }
    single<UserRepository> { UserRepositoryImpl(get()) }
    factory { GetArticlesUseCase(get()) }
}

val viewModelModule = module {
    viewModelOf(::ArticleListViewModel)
    viewModelOf(::ArticleDetailViewModel)
    viewModelOf(::UserProfileViewModel)
}

Koin DSL 关键字对比：

DSL 生命周期 等价 Hilt 注解 说明
single 单例 @Singleton + @Provides 全局唯一实例
factory 每次新建 无作用域的 @Provides 每次注入创建新实例
scoped 作用域内单例 @ActivityScoped 等 在指定作用域内共享
viewModelOf ViewModel @HiltViewModel ViewModel 工厂

提示： Koin 的 single 和 factory 使用 get() 函数解析依赖，Koin 会自动根据类型匹配。

Module 声明与组织

大型项目中应按功能划分 Module，保持清晰的模块结构。

class MyApplication : Application() {

    override fun onCreate() {
        super.onCreate()

        startKoin {
            androidLogger(Level.DEBUG)
            androidContext(this@MyApplication)
            modules(
                networkModule,
                databaseModule,
                repositoryModule,
                viewModelModule,
                featureModules
            )
        }
    }
}

val databaseModule = module {
    single {
        Room.databaseBuilder(
            androidContext(),
            AppDatabase::class.java,
            "app_database"
        ).build()
    }
    single { get<AppDatabase>().articleDao() }
    single { get<AppDatabase>().userDao() }
}

val featureModules = module {
    includes(
        homeModule,
        searchModule,
        profileModule
    )
}

val homeModule = module {
    scope<HomeActivity> {
        scoped { HomeNavigator(get()) }
        viewModelOf(::HomeViewModel)
    }
}


Lazy 与 Eager 注入
Koin 支持多种注入方式，满足不同场景需求。


class ArticleListActivity : AppCompatActivity() {

    private val viewModel: ArticleListViewModel by viewModel()

    private val analytics: AnalyticsTracker by inject()

    private val logger: Logger by inject { parametersOf("ArticleList") }

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
    }
}

@Composable
fun ArticleListScreen(
    viewModel: ArticleListViewModel = koinViewModel()
) {
    val uiState by viewModel.uiState.collectAsStateWithLifecycle()

    LazyColumn {
        items(uiState.articles) { article ->
            ArticleItem(article = article)
        }
    }
}

val parameterizedModule = module {
    factory { (tag: String) -> Logger(tag) }
    factory { (userId: String) -> UserSession(userId, get()) }
}

Koin 与 Hilt 对比
两个框架各有优势，选择取决于项目规模和团队偏好。


// Hilt 方式
@Module
@InstallIn(SingletonComponent::class)
object NetworkModule {
    @Provides
    @Singleton
    fun provideApi(retrofit: Retrofit): ArticleApi =
        retrofit.create(ArticleApi::class.java)
}

@HiltViewModel
class ArticleViewModel @Inject constructor(
    private val repository: ArticleRepository
) : ViewModel()

// Koin 方式
val networkModule = module {
    single<ArticleApi> { get<Retrofit>().create(ArticleApi::class.java) }
}

val viewModelModule = module {
    viewModelOf(::ArticleViewModel)
}

Koin 的验证测试确保模块配置正确：


class KoinModuleVerificationTest : KoinTest {

    @Test
    fun checkAllModules() {
        koinApplication {
            androidContext(ApplicationProvider.getApplicationContext())
            modules(
                networkModule,
                databaseModule,
                repositoryModule,
                viewModelModule
            )
        }.checkModules()
    }
}


提示： Koin 3.5+ 引入了 ksp 编译时验证功能（Koin Annotations），可以在编译时检查依赖图的完整性，弥补了运行时解析的不足。






小结
    

  • Koin 使用 Kotlin DSL 声明依赖，语法简洁，无需注解处理器
    • 

  • single、factory、scoped 分别对应单例、工厂和作用域内单例
    • 

  • by inject() 在 Android 组件中使用，koinViewModel() 在 Compose 中使用
    • 

  • Hilt 适合大型项目（编译时安全），Koin 适合中小项目（快速开发）
    • 

  • checkModules() 测试可以验证 Koin 模块配置的正确性
    •
