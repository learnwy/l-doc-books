并行测试

核心概念

并行测试是缩短 CI 反馈时间的最直接手段。当测试套件增长到数千个用例、执行时间超过 10 分钟时，单一执行器已无法满足"快速反馈"的要求。并行化的核心挑战不是"如何分配"，而是如何分配得均匀——如果一个分片需要 10 分钟而另一个只需要 1 分钟，总时间仍然是 10 分钟。

Vitest 分片
Vitest 原生支持 --shard 参数，通过对测试文件路径哈希来分配分片。这是最简单的并行化方案——零配置，只需在 CI 中使用矩阵策略。


jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        shard: [1, 2, 3, 4]
    steps:
      - uses: actions/checkout@v4
      - uses: ./.github/actions/setup-pnpm

      - name: Run tests
        run: pnpm vitest --run --shard=${{ matrix.shard }}/4 --reporter=json --outputFile=results-${{ matrix.shard }}.json

      - name: Upload results
        uses: actions/upload-artifact@v4
        with:
          name: test-results-${{ matrix.shard }}
          path: results-${{ matrix.shard }}.json

  merge-results:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/download-artifact@v4
        with:
          pattern: test-results-*
          merge-multiple: true

      - name: Merge and report
        run: |
          jq -s '{ numTotalTests: (map(.numTotalTests) | add), numPassedTests: (map(.numPassedTests) | add), numFailedTests: (map(.numFailedTests) | add) }' results-*.json
interface ShardConfig {
  total: number;
  index: number;
  strategy: 'hash' | 'round-robin' | 'timing-based';
}

interface TestDistribution {
  shard: number;
  files: string[];
  estimatedDuration: number;
}

const distributeByTiming = (files: TestFile[], shardCount: number): TestDistribution[] => {
  const sorted = [...files].sort((a, b) => b.avgDuration - a.avgDuration);
  const shards: TestDistribution[] = Array.from({ length: shardCount }, (_, i) => ({
    shard: i + 1,
    files: [],
    estimatedDuration: 0,
  }));

  for (const file of sorted) {
    const lightest = shards.reduce((min, s) => (s.estimatedDuration < min.estimatedDuration ? s : min));
    lightest.files.push(file.path);
    lightest.estimatedDuration += file.avgDuration;
  }

  return shards;
};
Playwright 并行化
Playwright 的并行化分两个层次：进程内并行（同一 Worker 中并行执行测试）和 CI 分片（跨多个 Runner 分配测试）。


jobs:
  e2e:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        shard: [1, 2, 3]
    steps:
      - uses: actions/checkout@v4
      - uses: ./.github/actions/setup-pnpm

      - name: Install browsers
        run: pnpm playwright install --with-deps chromium

      - name: Run E2E tests
        run: pnpm playwright test --shard=${{ matrix.shard }}/3

      - name: Upload blob report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: blob-report-${{ matrix.shard }}
          path: blob-report/
          retention-days: 3

  merge-reports:
    needs: e2e
    if: always()
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ./.github/actions/setup-pnpm

      - uses: actions/download-artifact@v4
        with:
          pattern: blob-report-*
          merge-multiple: true
          path: all-blob-reports

      - run: pnpm playwright merge-reports --reporter html all-blob-reports

      - uses: actions/upload-artifact@v4
        with:
          name: html-report
          path: playwright-report/
Playwright 的 Blob Reporter 是为 CI 分片设计的。每个分片生成一个 blob 文件，合并后可以生成完整的 HTML 报告。这比分别上传单独的报告更优雅。


import { defineConfig } from '@playwright/test';

const config = defineConfig({
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  workers: process.env.CI ? 1 : undefined,
  reporter: process.env.CI ? [['blob'], ['github']] : [['html', { open: 'never' }]],
  use: {
    trace: 'on-first-retry',
    screenshot: 'only-on-failure',
  },
});
CI 中 workers 设为 1 是一个关键配置。在 CI 的标准 Runner（2 vCPU）上，多 worker 会导致 CPU 争用，反而比单 worker 慢。并行化应该通过 CI 分片（多个 Runner）而不是单机多 worker 来实现。


结果聚合与报告
分片测试的一个挑战是结果分散——4 个分片产生 4 份独立报告。需要一个聚合步骤将它们合并为统一视图。


interface TestSummary {
  totalTests: number;
  passed: number;
  failed: number;
  skipped: number;
  duration: number;
  shards: ShardSummary[];
  failedTests: FailedTest[];
}

interface ShardSummary {
  index: number;
  tests: number;
  duration: number;
  passed: number;
  failed: number;
}

interface FailedTest {
  name: string;
  file: string;
  shard: number;
  error: string;
  retryCount: number;
}

const aggregateResults = (shardResults: ShardResult[]): TestSummary => {
  const failedTests: FailedTest[] = [];
  let total = 0,
    passed = 0,
    failed = 0,
    skipped = 0;

  const shards = shardResults.map((result, i) => {
    total += result.total;
    passed += result.passed;
    failed += result.failed;
    skipped += result.skipped;

    result.failures.forEach((f) => {
      failedTests.push({ ...f, shard: i + 1 });
    });

    return {
      index: i + 1,
      tests: result.total,
      duration: result.duration,
      passed: result.passed,
      failed: result.failed,
    };
  });

  return {
    totalTests: total,
    passed,
    failed,
    skipped,
    duration: Math.max(...shards.map((s) => s.duration)),
    shards,
    failedTests,
  };
};
聚合结果应发布为 GitHub Actions Job Summary 或 PR 评论，让开发者无需逐个查看分片日志。


小结
    

  • 并行测试的核心挑战是均匀分配——基于历史耗时的分片比哈希分片更均衡
    • 

  • Vitest --shard 零配置并行化，配合矩阵策略实现跨 Runner 分片
    • 

  • Playwright Blob Reporter 专为 CI 分片设计，合并后生成完整 HTML 报告
    • 

  • CI 中 Playwright workers 应设为 1，并行化通过 CI 分片而非单机多 worker 实现
    • 

  • 结果聚合（merge-reports）将分散的分片报告合并为统一视图
    •
