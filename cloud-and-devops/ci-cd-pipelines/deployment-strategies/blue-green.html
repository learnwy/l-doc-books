蓝绿部署

核心概念

蓝绿部署（Blue-Green Deployment）是最经典的零停机部署策略。它维护两套完全相同的生产环境——"蓝"（当前活跃）和"绿"（新版本）。新版本先部署到绿环境，验证通过后通过负载均衡器切换流量，蓝环境变为备用。如果新版本出问题，只需将流量切回蓝环境，回滚在秒级完成。

实现架构
蓝绿部署的核心组件是流量切换层。在不同基础设施上，切换机制不同：


interface BlueGreenConfig {
  blueEnvironment: EnvironmentSpec;
  greenEnvironment: EnvironmentSpec;
  activeSlot: 'blue' | 'green';
  router: RouterConfig;
  healthCheck: HealthCheckConfig;
  autoRollback: AutoRollbackConfig;
}

interface EnvironmentSpec {
  name: string;
  endpoint: string;
  version: string;
  replicas: number;
  resources: ResourceSpec;
}

interface RouterConfig {
  type: 'dns' | 'load-balancer' | 'ingress';
  switchTimeout: number;
  drainingTimeout: number;
}
在 Kubernetes 中，蓝绿部署通过 Service 的 selector 切换实现：


apiVersion: v1
kind: Service
metadata:
  name: app-production
spec:
  selector:
    app: my-app
    slot: green
  ports:
    - port: 80
      targetPort: 3000

---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-green
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
      slot: green
  template:
    metadata:
      labels:
        app: my-app
        slot: green
    spec:
      containers:
        - name: app
          image: registry.io/app:v1.1.0
          readinessProbe:
            httpGet:
              path: /health
              port: 3000
            initialDelaySeconds: 10
            periodSeconds: 5
在 CI/CD 流水线中编排蓝绿部署：


jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - name: Determine target slot
        id: slot
        run: |
          CURRENT=$(kubectl get svc app-production -o jsonpath='{.spec.selector.slot}')
          TARGET=$([[ "$CURRENT" == "blue" ]] && echo "green" || echo "blue")
          echo "current=$CURRENT" >> $GITHUB_OUTPUT
          echo "target=$TARGET" >> $GITHUB_OUTPUT

      - name: Deploy to target slot
        run: |
          kubectl set image deployment/app-${{ steps.slot.outputs.target }} \
            app=registry.io/app:${{ github.sha }}
          kubectl rollout status deployment/app-${{ steps.slot.outputs.target }} --timeout=300s

      - name: Run smoke tests
        run: |
          TARGET_URL=$(kubectl get svc app-${{ steps.slot.outputs.target }} -o jsonpath='{.status.loadBalancer.ingress[0].hostname}')
          curl -sf "$TARGET_URL/health" || exit 1

      - name: Switch traffic
        run: |
          kubectl patch svc app-production -p \
            '{"spec":{"selector":{"slot":"${{ steps.slot.outputs.target }}"}}}'

      - name: Verify and drain
        run: |
          sleep 30
          kubectl scale deployment/app-${{ steps.slot.outputs.current }} --replicas=1
数据库迁移兼容
蓝绿部署的最大挑战是数据库迁移。两个环境共享同一个数据库，因此数据库变更必须向前兼容——新旧版本的代码都能正常工作。


这要求采用 Expand-Contract 模式：


interface MigrationStrategy {
  phase: 'expand' | 'migrate' | 'contract';
  backwardCompatible: boolean;
  rollbackSafe: boolean;
}

const renamingColumnSafely: MigrationStrategy[] = [
  {
    phase: 'expand',
    backwardCompatible: true,
    rollbackSafe: true,
  },
  {
    phase: 'migrate',
    backwardCompatible: true,
    rollbackSafe: true,
  },
  {
    phase: 'contract',
    backwardCompatible: false,
    rollbackSafe: false,
  },
];
关键规则：永远不要在部署时运行破坏性迁移（如删除列、重命名表）。这些操作应该在确认所有实例都运行新版本后的独立步骤中执行。


健康检查与自动回滚
健康检查是蓝绿部署的安全网。切换流量后，持续监控新环境的健康状态，异常时自动回滚。


interface HealthCheckResult {
  status: 'healthy' | 'degraded' | 'unhealthy';
  checks: Check[];
  latency: number;
  timestamp: Date;
}

interface AutoRollbackPolicy {
  errorRateThreshold: number;
  latencyP99Threshold: number;
  evaluationWindow: number;
  cooldownPeriod: number;
  rollbackAction: () => Promise<void>;
}

const monitorAndRollback = async (policy: AutoRollbackPolicy, getMetrics: () => Promise<Metrics>): Promise<void> => {
  const startTime = Date.now();

  while (Date.now() - startTime < policy.evaluationWindow) {
    const metrics = await getMetrics();

    if (metrics.errorRate > policy.errorRateThreshold) {
      console.error(`Error rate ${metrics.errorRate}% exceeds threshold`);
      await policy.rollbackAction();
      return;
    }

    if (metrics.latencyP99 > policy.latencyP99Threshold) {
      console.error(`P99 latency ${metrics.latencyP99}ms exceeds threshold`);
      await policy.rollbackAction();
      return;
    }

    await sleep(5000);
  }
};
小结
    

  • 蓝绿部署维护双环境，通过负载均衡切换实现秒级发布和回滚
    • 

  • 资源开销是最大代价——需要 2x 的基础设施成本
    • 

  • 数据库迁移必须采用 Expand-Contract 模式，确保新旧版本代码兼容
    • 

  • Kubernetes 中通过 Service selector 切换实现，配合 readinessProbe 确保就绪
    • 

  • 健康检查 + 自动回滚是安全网——错误率或延迟超阈值时自动切回旧版本
    •
