工作流模式

核心概念

GitHub Actions 的真正威力在于组合——通过模式化的工作流设计，将简单的构建块组装成复杂的自动化流程。掌握常见的工作流模式，可以避免重复造轮子，同时确保流水线的可维护性和可扩展性。

可复用工作流
可复用工作流（Reusable Workflows）是 GitHub Actions 的模块化基石。它允许将常见的工作流逻辑抽取到独立文件中，被其他工作流通过 uses 调用。


# .github/workflows/reusable-build.yml
name: Reusable Build
on:
  workflow_call:
    inputs:
      node-version:
        type: string
        default: '20'
      working-directory:
        type: string
        default: '.'
    outputs:
      artifact-name:
        value: ${{ jobs.build.outputs.artifact-name }}
    secrets:
      NPM_TOKEN:
        required: false

jobs:
  build:
    runs-on: ubuntu-latest
    outputs:
      artifact-name: ${{ steps.upload.outputs.artifact-name }}
    defaults:
      run:
        working-directory: ${{ inputs.working-directory }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ inputs.node-version }}
      - run: pnpm install --frozen-lockfile
      - run: pnpm build
      - id: upload
        uses: actions/upload-artifact@v4
        with:
          name: build-${{ github.sha }}
          path: ${{ inputs.working-directory }}/dist
调用方只需要一行 uses：


# .github/workflows/ci.yml
jobs:
  build:
    uses: ./.github/workflows/reusable-build.yml
    with:
      node-version: '20'
      working-directory: 'web'
    secrets: inherit
secrets: inherit 将调用方的所有 secrets 传递给可复用工作流，避免逐个声明。跨仓库引用使用 owner/repo/.github/workflows/file.yml@ref 格式。


路径过滤与变更检测
Monorepo 中最常见的优化是只运行受影响的工作流。GitHub Actions 原生支持 paths 过滤，但更精细的变更检测需要自定义逻辑。


on:
  push:
    paths:
      - 'web/packages/core/**'
      - 'web/packages/markdown/**'
      - 'web/apps/doc-hub/**'

jobs:
  detect:
    runs-on: ubuntu-latest
    outputs:
      core: ${{ steps.filter.outputs.core }}
      apps: ${{ steps.filter.outputs.apps }}
    steps:
      - uses: actions/checkout@v4
      - uses: dorny/paths-filter@v3
        id: filter
        with:
          filters: |
            core:
              - 'web/packages/core/**'
            markdown:
              - 'web/packages/markdown/**'
            apps:
              - 'web/apps/**'

  build-core:
    needs: detect
    if: needs.detect.outputs.core == 'true'
    uses: ./.github/workflows/reusable-build.yml
    with:
      working-directory: web/packages/core
interface ChangeDetectionResult {
  affectedPackages: string[];
  affectedApps: string[];
  requiresFullBuild: boolean;
}

const detectChanges = (changedFiles: string[], dependencyGraph: Map<string, string[]>): ChangeDetectionResult => {
  const directlyAffected = new Set<string>();
  for (const file of changedFiles) {
    const pkg = resolvePackage(file);
    if (pkg) directlyAffected.add(pkg);
  }

  const allAffected = new Set(directlyAffected);
  for (const pkg of directlyAffected) {
    const dependents = dependencyGraph.get(pkg) ?? [];
    dependents.forEach((d) => allAffected.add(d));
  }

  return {
    affectedPackages: [...allAffected].filter((p) => p.startsWith('packages/')),
    affectedApps: [...allAffected].filter((p) => p.startsWith('apps/')),
    requiresFullBuild: changedFiles.some((f) => f === 'pnpm-lock.yaml' || f === 'tsconfig.base.json'),
  };
};
PR 自动化工作流
Pull Request 是团队协作的核心节点。围绕 PR 的自动化可以显著提升代码审查效率和代码质量。


name: PR Automation
on:
  pull_request:
    types: [opened, synchronize, reopened, labeled]

jobs:
  size-label:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Label PR by size
        uses: codelytv/pr-size-labeler@v1
        with:
          xs_max_size: 10
          s_max_size: 100
          m_max_size: 500
          l_max_size: 1000

  auto-assign:
    runs-on: ubuntu-latest
    steps:
      - uses: kentaro-m/auto-assign-action@v2

  preview-deploy:
    if: contains(github.event.pull_request.labels.*.name, 'preview')
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pnpm build
      - name: Deploy preview
        id: deploy
        run: |
          URL=$(npx vercel deploy --prebuilt --token=${{ secrets.VERCEL_TOKEN }})
          echo "url=$URL" >> $GITHUB_OUTPUT
      - name: Comment PR
        uses: actions/github-script@v7
        with:
          script: |
            github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body: `🚀 Preview: ${{ steps.deploy.outputs.url }}`
            })
定时与维护工作流
除了代码变更触发的工作流，定时工作流用于周期性维护任务：依赖更新检查、安全扫描、过期资源清理等。


name: Weekly Maintenance
on:
  schedule:
    - cron: '0 9 * * 1'
  workflow_dispatch:

jobs:
  dependency-audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pnpm audit --audit-level=high
      - name: Create issue on failure
        if: failure()
        uses: actions/github-script@v7
        with:
          script: |
            await github.rest.issues.create({
              owner: context.repo.owner,
              repo: context.repo.repo,
              title: '🔒 Security: High severity vulnerabilities found',
              body: 'Weekly audit detected high severity vulnerabilities. Run `pnpm audit` for details.',
              labels: ['security', 'automated']
            })

  stale-branches:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - name: List stale branches
        run: |
          git branch -r --sort=committerdate | head -20 | while read branch; do
            last_commit=$(git log -1 --format='%ci' "$branch")
            echo "$branch: $last_commit"
          done
小结
    

  • 可复用工作流是模块化的核心，workflow_call + secrets: inherit 实现跨工作流共享
    • 

  • 路径过滤和变更检测确保 Monorepo 中只运行受影响的构建，节省 60-80% 的 CI 时间
    • 

  • PR 自动化（大小标签、自动分配、预览部署、PR 评论）提升代码审查体验
    • 

  • 定时工作流覆盖依赖审计、安全扫描、过期资源清理等维护任务
    • 

  • 工作流成熟度从单体 → 模块化 → 可复用 → 组合 → 自适应逐级递进
    •
