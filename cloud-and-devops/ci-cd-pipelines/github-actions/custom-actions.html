自定义 Action 开发

核心概念

GitHub Actions 的生态系统建立在可复用 Action之上。当 Marketplace 上没有满足需求的 Action，或者团队有特定的自动化逻辑需要封装时，就需要开发自定义 Action。Action 本质上是一个独立的执行单元，接收输入、执行逻辑、产生输出。

JavaScript Action
JavaScript Action 是最常用的类型。它直接在 Runner 的 Node.js 环境中运行，启动速度最快。GitHub 提供了 @actions/core、@actions/github、@actions/exec 等 SDK 简化开发。


# action.yml
name: 'Bundle Size Check'
description: 'Compare bundle size against baseline'
inputs:
  baseline-branch:
    description: 'Branch to compare against'
    required: false
    default: 'main'
  threshold:
    description: 'Max allowed size increase in KB'
    required: false
    default: '50'
outputs:
  size-diff:
    description: 'Size difference in KB'
  passed:
    description: 'Whether the check passed'
runs:
  using: 'node20'
  main: 'dist/index.js'
import { getInput, setOutput, setFailed, summary } from '@actions/core';
import { getOctokit, context } from '@actions/github';
import { exec, getExecOutput } from '@actions/exec';

const run = async (): Promise<void> => {
  const baselineBranch = getInput('baseline-branch');
  const threshold = parseInt(getInput('threshold'), 10);

  await exec('pnpm', ['build']);
  const { stdout: currentSize } = await getExecOutput('du', ['-sk', 'dist']);
  const current = parseInt(currentSize.split('\t')[0], 10);

  await exec('git', ['fetch', 'origin', baselineBranch]);
  await exec('git', ['checkout', `origin/${baselineBranch}`]);
  await exec('pnpm', ['build']);
  const { stdout: baselineSize } = await getExecOutput('du', ['-sk', 'dist']);
  const baseline = parseInt(baselineSize.split('\t')[0], 10);

  const diff = current - baseline;
  const passed = diff <= threshold;

  setOutput('size-diff', diff.toString());
  setOutput('passed', passed.toString());

  await summary
    .addHeading('Bundle Size Report')
    .addTable([
      ['Metric', 'Value'],
      ['Baseline', `${baseline} KB`],
      ['Current', `${current} KB`],
      ['Diff', `${diff > 0 ? '+' : ''}${diff} KB`],
      ['Status', passed ? '✅ Passed' : '❌ Failed'],
    ])
    .write();

  if (!passed) {
    setFailed(`Bundle size increased by ${diff}KB, exceeding threshold of ${threshold}KB`);
  }
};

run();
使用 @vercel/ncc 将 Action 编译为单文件，避免在仓库中提交 node_modules：


{
  "scripts": {
    "build": "ncc build src/index.ts -o dist --minify",
    "test": "vitest"
  }
}
Composite Action
Composite Action 不需要编写代码——它通过组合已有的 Step 来创建可复用的模块。适合封装团队的标准流程，如"安装 pnpm + 设置缓存 + 安装依赖"。


# .github/actions/setup-pnpm/action.yml
name: 'Setup pnpm with cache'
description: 'Install pnpm, restore cache, install dependencies'
inputs:
  node-version:
    description: 'Node.js version'
    default: '20'
  working-directory:
    description: 'Working directory'
    default: '.'
runs:
  using: 'composite'
  steps:
    - uses: actions/setup-node@v4
      with:
        node-version: ${{ inputs.node-version }}

    - uses: pnpm/action-setup@v4
      with:
        version: 9

    - name: Get pnpm store directory
      id: pnpm-cache
      shell: bash
      run: echo "dir=$(pnpm store path)" >> $GITHUB_OUTPUT

    - uses: actions/cache@v4
      with:
        path: ${{ steps.pnpm-cache.outputs.dir }}
        key: pnpm-${{ runner.os }}-${{ hashFiles('**/pnpm-lock.yaml') }}
        restore-keys: pnpm-${{ runner.os }}-

    - name: Install dependencies
      shell: bash
      working-directory: ${{ inputs.working-directory }}
      run: pnpm install --frozen-lockfile
调用方代码极为简洁：


steps:
  - uses: actions/checkout@v4
  - uses: ./.github/actions/setup-pnpm
    with:
      node-version: '20'
      working-directory: 'web'
  - run: pnpm test
Docker Action
Docker Action 在隔离的容器中运行，可以使用任何语言和工具链。适合需要系统级依赖（如 FFmpeg、ImageMagick）或非 Node.js 语言的场景。


FROM alpine:3.19

RUN apk add --no-cache bash curl jq

COPY entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh

ENTRYPOINT ["/entrypoint.sh"]
# action.yml
name: 'Health Check'
description: 'Verify endpoint health after deployment'
inputs:
  url:
    description: 'URL to check'
    required: true
  max-retries:
    description: 'Maximum retry attempts'
    default: '10'
  interval:
    description: 'Seconds between retries'
    default: '5'
outputs:
  status-code:
    description: 'Final HTTP status code'
  response-time:
    description: 'Response time in ms'
runs:
  using: 'docker'
  image: 'Dockerfile'
  args:
    - ${{ inputs.url }}
    - ${{ inputs.max-retries }}
    - ${{ inputs.interval }}
#!/bin/bash
URL=$1
MAX_RETRIES=$2
INTERVAL=$3

for i in $(seq 1 "$MAX_RETRIES"); do
  START=$(date +%s%N)
  STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$URL" 2>/dev/null)
  END=$(date +%s%N)
  DURATION=$(( (END - START) / 1000000 ))

  if [ "$STATUS" = "200" ]; then
    echo "status-code=$STATUS" >> "$GITHUB_OUTPUT"
    echo "response-time=$DURATION" >> "$GITHUB_OUTPUT"
    exit 0
  fi
  sleep "$INTERVAL"
done

echo "Health check failed after $MAX_RETRIES attempts"
exit 1
Action 测试与发布
Action 的质量保证需要单元测试和集成测试。JavaScript Action 使用 Vitest 进行单元测试，模拟 @actions/core 的输入输出：


import { describe, it, expect, vi, beforeEach } from 'vitest';

vi.mock('@actions/core', () => ({
  getInput: vi.fn(),
  setOutput: vi.fn(),
  setFailed: vi.fn(),
  summary: {
    addHeading: vi.fn().mockReturnThis(),
    addTable: vi.fn().mockReturnThis(),
    write: vi.fn(),
  },
}));

describe('Bundle Size Check', () => {
  beforeEach(() => {
    vi.clearAllMocks();
  });

  it('should pass when size diff is within threshold', async () => {
    const core = await import('@actions/core');
    vi.mocked(core.getInput).mockImplementation((name: string) => {
      if (name === 'threshold') return '50';
      return 'main';
    });
  });
});
发布 Action 使用 GitHub Releases + 语义化版本。约定使用 major 版本标签（如 v1）指向最新的 minor/patch 版本，让用户既能获得修复又保持稳定：


git tag -fa v1 -m "Update v1 tag"
git push origin v1 --force
小结
    

  • 三种 Action 类型各有适用场景：JavaScript 最快、Docker 最灵活、Composite 最简单
    • 

  • JavaScript Action 使用 @actions/core SDK，ncc 编译为单文件避免提交 node_modules
    • 

  • Composite Action 封装标准流程（如 pnpm 安装），调用方代码最简洁
    • 

  • Docker Action 适合系统级依赖场景，容器隔离保障环境一致性
    • 

  • Action 发布使用 major 版本标签（v1）指向最新 patch，平衡稳定性与更新
    •
