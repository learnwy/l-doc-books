gRPC 基础

核心概念

gRPC 是 Google 开源的高性能 RPC（Remote Procedure Call）框架。与 REST 的"资源"抽象不同，gRPC 直接暴露服务方法——客户端像调用本地函数一样调用远程服务。它基于 HTTP/2 协议，使用 Protocol Buffers（Protobuf）作为接口定义语言和序列化格式，性能远超 JSON-based REST。

服务定义与 Proto 文件
gRPC 的核心是 .proto 文件——它定义了服务的方法签名、请求/响应消息结构。所有客户端和服务端代码都从这个文件生成。


syntax = "proto3";

package user.v1;

option go_package = "github.com/org/api/gen/user/v1";

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
  rpc ListUsers(ListUsersRequest) returns (ListUsersResponse);
  rpc CreateUser(CreateUserRequest) returns (CreateUserResponse);
  rpc UpdateUser(UpdateUserRequest) returns (UpdateUserResponse);
  rpc DeleteUser(DeleteUserRequest) returns (DeleteUserResponse);
  rpc WatchUsers(WatchUsersRequest) returns (stream UserEvent);
}

message User {
  string id = 1;
  string name = 2;
  string email = 3;
  UserRole role = 4;
  google.protobuf.Timestamp created_at = 5;
  google.protobuf.Timestamp updated_at = 6;
}

enum UserRole {
  USER_ROLE_UNSPECIFIED = 0;
  USER_ROLE_USER = 1;
  USER_ROLE_ADMIN = 2;
  USER_ROLE_MODERATOR = 3;
}

message GetUserRequest {
  string id = 1;
}

message GetUserResponse {
  User user = 1;
}

message ListUsersRequest {
  int32 page_size = 1;
  string page_token = 2;
  string filter = 3;
  string order_by = 4;
}

message ListUsersResponse {
  repeated User users = 1;
  string next_page_token = 2;
  int32 total_count = 3;
}
字段编号（= 1, = 2）是 Protobuf 的核心设计——序列化时用编号而不是字段名，这是它高性能的原因。编号一旦分配就不能修改，删除的字段编号应标记为 reserved。


interface ProtoFieldRule {
  rule: string;
  reason: string;
}

const protoRules: ProtoFieldRule[] = [
  { rule: '字段编号不可修改', reason: '二进制兼容性' },
  { rule: '删除字段用 reserved', reason: '防止编号重用' },
  { rule: '枚举首值为 0 + UNSPECIFIED', reason: '零值默认语义' },
  { rule: '方法名用 PascalCase', reason: 'gRPC 约定' },
  { rule: '消息名用 PascalCase', reason: 'Protobuf 约定' },
  { rule: '字段名用 snake_case', reason: 'Protobuf 约定' },
  { rule: '包名含版本号', reason: 'API 版本控制' },
];
四种通信模式
gRPC 支持四种通信模式，覆盖了所有远程调用场景：


service DataService {
  // Unary: 请求-响应
  rpc GetItem(GetItemRequest) returns (GetItemResponse);

  // Server Streaming: 服务端流式返回
  rpc ListItems(ListItemsRequest) returns (stream Item);

  // Client Streaming: 客户端流式发送
  rpc UploadFile(stream FileChunk) returns (UploadResponse);

  // Bidirectional: 双向流
  rpc Chat(stream ChatMessage) returns (stream ChatMessage);
}

错误处理与状态码
gRPC 使用自己的状态码体系，而不是 HTTP 状态码。每个状态码有明确的语义：


interface GrpcStatus {
  code: number;
  name: string;
  httpEquivalent: number;
  usage: string;
}

const statusCodes: GrpcStatus[] = [
  { code: 0, name: 'OK', httpEquivalent: 200, usage: '成功' },
  { code: 3, name: 'INVALID_ARGUMENT', httpEquivalent: 400, usage: '参数错误' },
  { code: 5, name: 'NOT_FOUND', httpEquivalent: 404, usage: '资源不存在' },
  { code: 6, name: 'ALREADY_EXISTS', httpEquivalent: 409, usage: '资源已存在' },
  { code: 7, name: 'PERMISSION_DENIED', httpEquivalent: 403, usage: '权限不足' },
  { code: 8, name: 'RESOURCE_EXHAUSTED', httpEquivalent: 429, usage: '配额耗尽' },
  { code: 13, name: 'INTERNAL', httpEquivalent: 500, usage: '内部错误' },
  { code: 14, name: 'UNAVAILABLE', httpEquivalent: 503, usage: '服务不可用' },
  { code: 16, name: 'UNAUTHENTICATED', httpEquivalent: 401, usage: '未认证' },
];
gRPC 还支持 Rich Error Model——通过 google.rpc.Status 附加结构化的错误详情，类似 REST 的 Problem Details：


import "google/rpc/error_details.proto";

// 错误详情可以包含多种类型
// BadRequest: 字段级错误
// RetryInfo: 重试间隔
// DebugInfo: 调试信息（仅内部）
拦截器与中间件
gRPC 的拦截器（Interceptor）等同于 HTTP 中间件，在请求处理前后执行横切逻辑。


interface UnaryInterceptor {
  (request: unknown, metadata: Metadata, next: UnaryHandler): Promise<unknown>;
}

const loggingInterceptor: UnaryInterceptor = async (request, metadata, next) => {
  const start = Date.now();
  const method = metadata.get('method')[0];

  try {
    const response = await next(request, metadata);
    const duration = Date.now() - start;
    console.log(`gRPC ${method} OK ${duration}ms`);
    return response;
  } catch (error) {
    const duration = Date.now() - start;
    console.error(`gRPC ${method} ERROR ${duration}ms`, error);
    throw error;
  }
};

const authInterceptor: UnaryInterceptor = async (request, metadata, next) => {
  const token = metadata.get('authorization')[0];
  if (!token) {
    throw { code: 16, message: 'Missing authentication token' };
  }

  const user = await validateToken(token as string);
  metadata.set('user-id', user.id);
  return next(request, metadata);
};
小结
    

  • gRPC 基于 HTTP/2 + Protobuf，性能比 REST/JSON 快 5-10 倍，适合内部微服务通信
    • 

  • Proto 文件是契约驱动开发的核心，字段编号不可修改，删除用 reserved
    • 

  • 四种通信模式覆盖所有场景：Unary、Server/Client Streaming、Bidirectional
    • 

  • gRPC 状态码体系独立于 HTTP，Rich Error Model 支持结构化错误详情
    • 

  • 拦截器实现横切关注点（日志、认证、限流），等同于 HTTP 中间件
    •
