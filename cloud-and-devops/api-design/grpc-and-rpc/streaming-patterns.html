流式通信模式

核心概念

流式通信（Streaming）是 gRPC 区别于 REST 的核心能力。在传统的 Unary RPC 中，客户端发送一个请求，等待一个响应——这适合简单的 CRUD 操作。但当数据量大（批量处理）、实时性要求高（事件推送）或交互复杂（双向通信）时，流式模式提供了更高效的解决方案。

graph TD
    A[流式通信] --> B[Server Streaming]
    A --> C[Client Streaming]
    A --> D[Bidirectional Streaming]
    B --> E[实时通知/日志推送]
    C --> F[文件上传/批量导入]
    D --> G[聊天/实时协作]
    subgraph HTTP/2 多路复用
        B
        C
        D
    end
模式 连接特征 背压控制 典型延迟 适用场景
Unary 请求-响应 无需 1 RTT CRUD
Server Streaming 长连接下行 Flow Control 持续 日志、变更推送
Client Streaming 长连接上行 Flow Control 批量 文件上传
Bidirectional 全双工 双向 Flow Control 实时 聊天、协作

Server Streaming

Server Streaming 适用于"请求一次，持续接收"的场景。客户端发送一个请求，服务端返回一个消息流。

service MonitorService {
  rpc WatchMetrics(WatchMetricsRequest) returns (stream MetricEvent);
  rpc StreamLogs(StreamLogsRequest) returns (stream LogEntry);
  rpc ExportData(ExportDataRequest) returns (stream DataChunk);
}

message WatchMetricsRequest {
  repeated string metric_names = 1;
  int32 interval_seconds = 2;
}

message MetricEvent {
  string name = 1;
  double value = 2;
  google.protobuf.Timestamp timestamp = 3;
  map<string, string> labels = 4;
}
interface StreamHandler<T> {
  onData: (data: T) => void;
  onError: (error: Error) => void;
  onEnd: () => void;
}

const watchMetrics = (request: WatchMetricsRequest, handler: StreamHandler<MetricEvent>): CancelFunction => {
  const stream = client.watchMetrics(request);

  stream.on('data', (event: MetricEvent) => {
    handler.onData(event);
  });

  stream.on('error', (error: Error) => {
    if (error.code === 'CANCELLED') return;
    handler.onError(error);
  });

  stream.on('end', () => {
    handler.onEnd();
  });

  return () => stream.cancel();
};

Server Streaming 的关键设计点是心跳和超时。长连接可能因网络问题静默断开，定期发送心跳消息可以检测连接状态：

message StreamEvent {
  oneof event {
    MetricEvent metric = 1;
    HeartbeatEvent heartbeat = 2;
    ErrorEvent error = 3;
  }
}

message HeartbeatEvent {
  google.protobuf.Timestamp timestamp = 1;
}

Client Streaming

Client Streaming 适用于"分批发送，汇总响应"的场景。典型应用是文件上传和批量数据导入。

service ImportService {
  rpc UploadFile(stream FileChunk) returns (UploadResponse);
  rpc BatchImport(stream ImportRecord) returns (ImportSummary);
}

message FileChunk {
  string filename = 1;
  int64 offset = 2;
  bytes data = 3;
  bool is_last = 4;
}

message UploadResponse {
  string file_id = 1;
  int64 total_bytes = 2;
  string checksum = 3;
}

message ImportRecord {
  int32 row_number = 1;
  map<string, string> fields = 2;
}

message ImportSummary {
  int32 total_records = 1;
  int32 succeeded = 2;
  int32 failed = 3;
  repeated ImportError errors = 4;
}
const uploadFile = async (filePath: string, chunkSize: number = 64 * 1024): Promise<UploadResponse> => {
  const stream = client.uploadFile();

  const fileBuffer = await readFile(filePath);
  const filename = path.basename(filePath);
  let offset = 0;

  while (offset < fileBuffer.length) {
    const end = Math.min(offset + chunkSize, fileBuffer.length);
    const chunk: FileChunk = {
      filename,
      offset,
      data: fileBuffer.subarray(offset, end),
      isLast: end >= fileBuffer.length,
    };
    stream.write(chunk);
    offset = end;
  }

  return new Promise((resolve, reject) => {
    stream.end();
    stream.on('data', resolve);
    stream.on('error', reject);
  });
};

分块上传的关键是续传能力。当连接中断时，客户端可以从上次的 offset 继续发送，而不是重新开始。

Bidirectional Streaming

双向流是 gRPC 最强大的模式——客户端和服务端可以同时发送和接收消息，不需要等待对方响应。

service ChatService {
  rpc Chat(stream ChatMessage) returns (stream ChatMessage);
  rpc Collaborate(stream EditOperation) returns (stream EditOperation);
}

message ChatMessage {
  string sender_id = 1;
  string channel_id = 2;
  string content = 3;
  MessageType type = 4;
  google.protobuf.Timestamp timestamp = 5;
}

enum MessageType {
  MESSAGE_TYPE_UNSPECIFIED = 0;
  MESSAGE_TYPE_TEXT = 1;
  MESSAGE_TYPE_JOIN = 2;
  MESSAGE_TYPE_LEAVE = 3;
  MESSAGE_TYPE_TYPING = 4;
}
const startChat = (channelId: string, userId: string): ChatSession => {
  const stream = client.chat();
  const listeners = new Map<string, Set<(msg: ChatMessage) => void>>();

  stream.on('data', (message: ChatMessage) => {
    const handlers = listeners.get('message') ?? new Set();
    handlers.forEach((handler) => handler(message));
  });

  stream.on('error', (error: Error) => {
    const handlers = listeners.get('error') ?? new Set();
    handlers.forEach((handler) => handler(error as unknown as ChatMessage));
  });

  const send = (content: string, type: MessageType = MessageType.TEXT): void => {
    stream.write({
      senderId: userId,
      channelId,
      content,
      type,
      timestamp: new Date(),
    });
  };

  const on = (event: string, handler: (msg: ChatMessage) => void): void => {
    if (!listeners.has(event)) listeners.set(event, new Set());
    listeners.get(event)!.add(handler);
  };

  const close = (): void => {
    stream.end();
  };

  return { send, on, close };
};

流控与背压

HTTP/2 的 Flow Control 为 gRPC 流提供了内置的背压（Back Pressure） 机制。当接收方处理不过来时，它会减小接收窗口，发送方会自动降速。

interface FlowControlConfig {
  initialWindowSize: number;
  maxConcurrentStreams: number;
  keepAliveTime: number;
  keepAliveTimeout: number;
}

const serverConfig: FlowControlConfig = {
  initialWindowSize: 1024 * 1024,
  maxConcurrentStreams: 100,
  keepAliveTime: 30000,
  keepAliveTimeout: 5000,
};
流控参数 默认值 调优建议 影响
initialWindowSize 64KB 高吞吐量场景增大 缓冲区大小
maxConcurrentStreams 100 按负载调整 并发流数量
keepAliveTime 2h 不稳定网络调低 连接活性检测
keepAliveTimeout 20s 按网络延迟调整 超时判定

在应用层面，当处理速度跟不上接收速度时，需要实现限流或丢弃策略：

interface BackpressureStrategy {
  type: 'buffer' | 'drop' | 'latest' | 'throttle';
  bufferSize?: number;
  throttleMs?: number;
}

const processWithBackpressure = async <T>(
  stream: AsyncIterable<T>,
  processor: (item: T) => Promise<void>,
  strategy: BackpressureStrategy,
): Promise<void> => {
  const buffer: T[] = [];

  for await (const item of stream) {
    if (strategy.type === 'buffer') {
      buffer.push(item);
      if (buffer.length >= (strategy.bufferSize ?? 100)) {
        await Promise.all(buffer.map(processor));
        buffer.length = 0;
      }
    } else if (strategy.type === 'drop' && buffer.length >= (strategy.bufferSize ?? 100)) {
      continue;
    } else {
      await processor(item);
    }
  }

  if (buffer.length > 0) {
    await Promise.all(buffer.map(processor));
  }
};

小结

  • Server Streaming 适合"请求一次，持续接收"——日志推送、实时监控、数据导出
  • Client Streaming 适合"分批发送，汇总响应"——文件上传、批量导入
  • Bidirectional Streaming 实现全双工实时通信——聊天、协作编辑
  • HTTP/2 Flow Control 提供内置背压机制，应用层需配合限流或丢弃策略
  • 长连接需要心跳检测和重连机制，keepAlive 参数按网络环境调整
