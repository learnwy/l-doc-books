Schema 设计

核心概念

Schema 设计是 GraphQL API 成败的关键。一个好的 Schema 不仅是技术契约，更是产品的 API 接口——它应该反映业务领域的概念，而不是数据库的结构。Schema First（先定义 Schema）vs Code First（从代码生成 Schema）是两种主要的设计方法，各有适用场景。





方法
Schema First
Code First





定义方式
.graphql SDL 文件
TypeScript 代码




优势
语言无关、可读性好
类型安全、可编程




劣势
Schema-代码同步
可读性略差

GraphQL Codegen
内置




适用场景
跨团队协作
单团队全栈




代表工具

命名与约定
一致的命名约定让 Schema 自文档化。GraphQL 社区已形成广泛共识：


type User {
  id: ID!
  firstName: String!
  lastName: String!
  emailAddress: String!
  isActive: Boolean!
  createdAt: DateTime!
  updatedAt: DateTime!
}

type Query {
  user(id: ID!): User
  users(filter: UserFilter, first: Int, after: String): UserConnection!
  searchUsers(query: String!, first: Int): [User!]!
}

type Mutation {
  createUser(input: CreateUserInput!): CreateUserPayload!
  updateUser(input: UpdateUserInput!): UpdateUserPayload!
  deleteUser(id: ID!): DeleteUserPayload!
}
interface NamingConvention {
  element: string;
  convention: string;
  example: string;
}

const conventions: NamingConvention[] = [
  { element: '类型名', convention: 'PascalCase', example: 'UserProfile' },
  { element: '字段名', convention: 'camelCase', example: 'firstName' },
  { element: '枚举值', convention: 'SCREAMING_SNAKE', example: 'ADMIN' },
  { element: 'Input 类型', convention: '{Action}{Type}Input', example: 'CreateUserInput' },
  { element: 'Payload 类型', convention: '{Action}{Type}Payload', example: 'CreateUserPayload' },
  { element: '布尔字段', convention: 'is/has/can 前缀', example: 'isActive, hasAccess' },
  { element: '列表字段', convention: '复数名词', example: 'users, tags' },
  { element: '连接字段', convention: '{Type}Connection', example: 'UserConnection' },
];
Relay 连接规范
Relay Connection Specification 是 GraphQL 分页的事实标准。它定义了 Connection → Edge → Node 的三层结构，配合 PageInfo 实现基于游标的分页。


type UserConnection {
  edges: [UserEdge!]!
  pageInfo: PageInfo!
  totalCount: Int!
}

type UserEdge {
  node: User!
  cursor: String!
}

type PageInfo {
  hasNextPage: Boolean!
  hasPreviousPage: Boolean!
  startCursor: String
  endCursor: String
}

type Query {
  users(first: Int, after: String, last: Int, before: String, filter: UserFilter): UserConnection!
}
interface ConnectionArgs {
  first?: number;
  after?: string;
  last?: number;
  before?: string;
}

interface Connection<T> {
  edges: Edge<T>[];
  pageInfo: PageInfo;
  totalCount: number;
}

interface Edge<T> {
  node: T;
  cursor: string;
}

const buildConnection = <T extends { id: string }>(
  nodes: T[],
  args: ConnectionArgs,
  totalCount: number,
): Connection<T> => {
  const edges = nodes.map((node) => ({
    node,
    cursor: Buffer.from(`cursor:${node.id}`).toString('base64'),
  }));

  return {
    edges,
    pageInfo: {
      hasNextPage: args.first ? nodes.length === args.first : false,
      hasPreviousPage: !!args.after,
      startCursor: edges[0]?.cursor ?? null,
      endCursor: edges[edges.length - 1]?.cursor ?? null,
    },
    totalCount,
  };
};
Connection 规范虽然比简单的列表分页复杂，但它提供了统一的分页接口，客户端库（如 Relay、Apollo）可以自动处理分页逻辑。


Mutation 设计模式
Mutation 的设计直接影响 API 的可用性和可演进性。核心原则是Input/Payload 模式：每个 Mutation 接收一个 Input 对象，返回一个 Payload 对象。


input CreateOrderInput {
  items: [OrderItemInput!]!
  shippingAddressId: ID!
  couponCode: String
}

type CreateOrderPayload {
  order: Order
  userErrors: [UserError!]!
}

type UserError {
  field: [String!]
  message: String!
  code: ErrorCode!
}

enum ErrorCode {
  INVALID_INPUT
  NOT_FOUND
  INSUFFICIENT_STOCK
  COUPON_EXPIRED
}
UserError 模式是 Shopify 推广的最佳实践——将业务错误作为 Payload 的一部分返回（而不是 GraphQL 错误），这样客户端可以精确地将错误消息绑定到对应的表单字段。


interface MutationPayload<T> {
  data: T | null;
  userErrors: UserError[];
}

interface UserError {
  field: string[];
  message: string;
  code: string;
}

const createOrder = async (input: CreateOrderInput): Promise<MutationPayload<Order>> => {
  const errors: UserError[] = [];

  const stock = await checkStock(input.items);
  if (!stock.sufficient) {
    errors.push({
      field: ['items'],
      message: '库存不足',
      code: 'INSUFFICIENT_STOCK',
    });
  }

  if (input.couponCode) {
    const coupon = await validateCoupon(input.couponCode);
    if (!coupon.valid) {
      errors.push({
        field: ['couponCode'],
        message: '优惠券已过期',
        code: 'COUPON_EXPIRED',
      });
    }
  }

  if (errors.length > 0) {
    return { data: null, userErrors: errors };
  }

  const order = await orderService.create(input);
  return { data: order, userErrors: [] };
};
Schema 演进
Schema 演进需要向后兼容。GraphQL 的 @deprecated 指令提供了标准的废弃机制：


type User {
  id: ID!
  name: String! @deprecated(reason: "Use displayName instead")
  displayName: String!
  email: String! @deprecated(reason: "Use emailAddress instead")
  emailAddress: String!
}

小结
    

  • Schema 设计面向业务领域而非数据库——好的 Schema 是自文档化的产品接口
    • 

  • Schema First 适合跨团队协作，Code First 适合全栈团队，都需要代码生成
    • 

  • Relay Connection 规范是分页的事实标准，Connection → Edge → Node 三层结构
    • 

  • Input/Payload + UserError 模式是 Mutation 设计的最佳实践
    • 

  • Schema 演进遵循"只增不减"原则，@deprecated 提供标准废弃机制
    •
