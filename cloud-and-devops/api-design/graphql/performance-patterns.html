GraphQL 性能模式

核心概念

GraphQL 的灵活性是一把双刃剑——客户端可以请求任意深度和广度的数据，这使得服务端面临独特的性能挑战。REST 中一个端点的性能是可预测的，但 GraphQL 的一个 Query 可能触发成百上千次数据库查询。性能优化需要在查询执行、数据加载和响应传输三个层面同时发力。

DataLoader 与 N+1 解决
N+1 问题是 GraphQL 性能的头号杀手。当查询 10 个用户的文章时，朴素的 Resolver 会为每个用户单独查询一次数据库——共 11 次查询（1 次获取用户 + 10 次获取文章）。


DataLoader 通过批量化和去重解决这个问题。它将同一事件循环中的多个 .load(id) 调用合并为一次批量查询：


import DataLoader from 'dataloader';

const createLoaders = (dataSources: DataSources) => ({
  userLoader: new DataLoader<string, User>(async (ids) => {
    const users = await dataSources.db.query(`SELECT * FROM users WHERE id IN (${ids.map(() => '?').join(',')})`, [
      ...ids,
    ]);
    const userMap = new Map(users.map((u) => [u.id, u]));
    return ids.map((id) => userMap.get(id) ?? new Error(`User ${id} not found`));
  }),

  postsByAuthorLoader: new DataLoader<string, Post[]>(async (authorIds) => {
    const posts = await dataSources.db.query(
      `SELECT * FROM posts WHERE author_id IN (${authorIds.map(() => '?').join(',')})`,
      [...authorIds],
    );
    const grouped = new Map<string, Post[]>();
    for (const post of posts) {
      const list = grouped.get(post.authorId) ?? [];
      list.push(post);
      grouped.set(post.authorId, list);
    }
    return authorIds.map((id) => grouped.get(id) ?? []);
  }),
});
DataLoader 的关键约束：返回数组的长度和顺序必须与输入 ID 数组一致。这确保了每个 .load(id) 调用都能正确获得其对应的结果。


const resolvers = {
  User: {
    posts: (parent: User, _: unknown, ctx: Context) => {
      return ctx.loaders.postsByAuthorLoader.load(parent.id);
    },
  },
  Post: {
    author: (parent: Post, _: unknown, ctx: Context) => {
      return ctx.loaders.userLoader.load(parent.authorId);
    },
  },
};
DataLoader 实例应该每个请求创建一个——它的缓存是请求级别的，不同请求之间不应共享。


查询复杂度控制
开放的 GraphQL API 必须防御恶意查询。一个精心构造的嵌套查询可以轻松让服务器 OOM：


# 恶意查询：指数级嵌套
{
  users(first: 100) {
    posts(first: 100) {
      author {
        posts(first: 100) {
          author {
            posts(first: 100) {
              title
            }
          }
        }
      }
    }
  }
}
防护措施包括深度限制、复杂度分析和超时控制：


interface QueryLimits {
  maxDepth: number;
  maxComplexity: number;
  maxAliases: number;
  timeout: number;
}

const limits: QueryLimits = {
  maxDepth: 10,
  maxComplexity: 1000,
  maxAliases: 30,
  timeout: 30000,
};

interface FieldComplexity {
  type: string;
  field: string;
  cost: number;
  multiplier?: string;
}

const complexityRules: FieldComplexity[] = [
  { type: 'Query', field: 'users', cost: 1, multiplier: 'first' },
  { type: 'User', field: 'posts', cost: 2, multiplier: 'first' },
  { type: 'Post', field: 'comments', cost: 2, multiplier: 'first' },
];

const calculateComplexity = (
  query: DocumentNode,
  rules: FieldComplexity[],
  variables: Record<string, unknown>,
): number => {
  let totalCost = 0;

  const visitor = {
    Field: (node: FieldNode) => {
      const rule = rules.find((r) => r.field === node.name.value);
      if (!rule) return;

      let cost = rule.cost;
      if (rule.multiplier) {
        const multiplierArg = node.arguments?.find((a) => a.name.value === rule.multiplier);
        const multiplierValue = multiplierArg ? parseInt(String(resolveValue(multiplierArg.value, variables)), 10) : 10;
        cost *= multiplierValue;
      }
      totalCost += cost;
    },
  };

  visit(query, visitor);
  return totalCost;
};
持久化查询
持久化查询（Persisted Queries）将 GraphQL 查询字符串替换为哈希值。客户端发送哈希而不是完整查询，服务端根据哈希查找对应的查询。


interface PersistedQueryConfig {
  store: Map<string, string>;
  allowArbitraryQueries: boolean;
}

const queryStore = new Map<string, string>([
  ['abc123', '{ user(id: $id) { id name email } }'],
  ['def456', '{ users(first: $first) { edges { node { id name } } } }'],
]);

const resolvePersistedQuery = (hash: string, config: PersistedQueryConfig): string | null => {
  return config.store.get(hash) ?? null;
};

在生产环境中，构建时自动从客户端代码提取查询并注册到服务端，运行时只接受已注册的查询哈希。


响应缓存
GraphQL 的缓存比 REST 困难——因为请求都发到同一个 URL（POST /graphql），HTTP 缓存无法直接使用。缓存需要在应用层实现。


interface CacheConfig {
  maxAge: number;
  scope: 'public' | 'private';
  varyBy: string[];
}

interface FieldCacheHint {
  typeName: string;
  fieldName: string;
  maxAge: number;
  scope: 'public' | 'private';
}

const cacheHints: FieldCacheHint[] = [
  { typeName: 'Query', fieldName: 'user', maxAge: 300, scope: 'private' },
  { typeName: 'Query', fieldName: 'posts', maxAge: 60, scope: 'public' },
  { typeName: 'User', fieldName: 'profile', maxAge: 3600, scope: 'private' },
];
客户端侧，Apollo Client 使用 Normalized Cache——将响应数据按实体 ID 拆分存储，不同查询获取的同一实体共享缓存：


const cache = new InMemoryCache({
  typePolicies: {
    User: {
      keyFields: ['id'],
      fields: {
        posts: {
          keyArgs: ['filter'],
          merge: (existing = [], incoming) => [...existing, ...incoming],
        },
      },
    },
  },
});
