API 安全

核心概念

API 安全是系统安全的关键环节——API 是系统的"大门"，每个端点都是潜在的攻击面。OWASP API Security Top 10 列出了 API 面临的最常见安全威胁。API 安全不是一个功能，而是一个横切关注点——它应该嵌入到设计、开发、测试和运维的每个环节中。

认证方案
认证回答"你是谁"的问题。JWT（JSON Web Token）是 API 认证的主流方案，但需要正确使用才能保障安全。


import { sign, verify } from 'hono/jwt';

interface JWTPayload {
  sub: string;
  email: string;
  role: string;
  iat: number;
  exp: number;
  jti: string;
}

const issueToken = async (user: User): Promise<string> => {
  const payload: JWTPayload = {
    sub: user.id,
    email: user.email,
    role: user.role,
    iat: Math.floor(Date.now() / 1000),
    exp: Math.floor(Date.now() / 1000) + 3600,
    jti: crypto.randomUUID(),
  };

  return sign(payload, SECRET_KEY);
};

const authMiddleware = async (c: Context, next: Next) => {
  const authHeader = c.req.header('Authorization');
  if (!authHeader?.startsWith('Bearer ')) {
    return c.json({ error: { code: 'UNAUTHENTICATED', message: '缺少认证信息' } }, 401);
  }

  const token = authHeader.slice(7);

  try {
    const payload = (await verify(token, SECRET_KEY)) as JWTPayload;
    if (payload.exp < Math.floor(Date.now() / 1000)) {
      return c.json({ error: { code: 'TOKEN_EXPIRED', message: 'Token 已过期' } }, 401);
    }
    c.set('user', payload);
    await next();
  } catch {
    return c.json({ error: { code: 'INVALID_TOKEN', message: 'Token 无效' } }, 401);
  }
};

授权模型
授权回答"你能做什么"的问题。RBAC（Role-Based Access Control）是最常用的模型，ABAC（Attribute-Based Access Control）提供更细粒度的控制。


type Role = 'user' | 'admin' | 'moderator';
type Permission = 'read:users' | 'write:users' | 'delete:users' | 'read:admin';

const rolePermissions: Record<Role, Permission[]> = {
  user: ['read:users'],
  moderator: ['read:users', 'write:users'],
  admin: ['read:users', 'write:users', 'delete:users', 'read:admin'],
};

const requirePermission = (permission: Permission) => {
  return async (c: Context, next: Next) => {
    const user = c.get('user') as JWTPayload;
    const permissions = rolePermissions[user.role as Role] ?? [];

    if (!permissions.includes(permission)) {
      return c.json(
        {
          error: {
            code: 'INSUFFICIENT_PERMISSIONS',
            message: `需要 ${permission} 权限`,
          },
        },
        403,
      );
    }

    await next();
  };
};

app.get('/users', authMiddleware, requirePermission('read:users'), listUsers);
app.post('/users', authMiddleware, requirePermission('write:users'), createUser);
app.delete('/users/:id', authMiddleware, requirePermission('delete:users'), deleteUser);
对象级授权是最容易被忽略的安全点——即使用户有"读取用户"权限，也不意味着可以读取所有用户的数据：


const getUserHandler = async (c: Context) => {
  const currentUser = c.get('user') as JWTPayload;
  const targetId = c.req.param('id');

  if (currentUser.role !== 'admin' && currentUser.sub !== targetId) {
    return c.json({ error: { code: 'FORBIDDEN', message: '无权访问此资源' } }, 403);
  }

  const user = await getUserById(targetId);
  return c.json({ data: user });
};
限流与配额
限流（Rate Limiting）防止 API 被滥用——无论是恶意攻击还是客户端 Bug 导致的过量请求。


interface RateLimitConfig {
  windowMs: number;
  maxRequests: number;
  keyGenerator: (c: Context) => string;
  skipIf?: (c: Context) => boolean;
}

const rateLimitConfigs: RateLimitConfig[] = [
  {
    windowMs: 60_000,
    maxRequests: 100,
    keyGenerator: (c) => c.get('user')?.sub ?? c.req.header('x-forwarded-for') ?? 'anonymous',
  },
  {
    windowMs: 60_000,
    maxRequests: 10,
    keyGenerator: (c) => `login:${c.req.header('x-forwarded-for')}`,
    skipIf: (c) => c.req.path !== '/auth/login',
  },
];

interface RateLimitResult {
  allowed: boolean;
  remaining: number;
  resetAt: Date;
  limit: number;
}

const checkRateLimit = async (
  key: string,
  config: RateLimitConfig,
  store: RateLimitStore,
): Promise<RateLimitResult> => {
  const current = await store.increment(key, config.windowMs);

  return {
    allowed: current <= config.maxRequests,
    remaining: Math.max(0, config.maxRequests - current),
    resetAt: new Date(Date.now() + config.windowMs),
    limit: config.maxRequests,
  };
};
限流响应需要携带标准化的 Header，让客户端知道限额状态：


const rateLimitMiddleware = (config: RateLimitConfig) => {
  return async (c: Context, next: Next) => {
    if (config.skipIf?.(c)) {
      await next();
      return;
    }

    const key = config.keyGenerator(c);
    const result = await checkRateLimit(key, config, store);

    c.header('X-RateLimit-Limit', result.limit.toString());
    c.header('X-RateLimit-Remaining', result.remaining.toString());
    c.header('X-RateLimit-Reset', Math.floor(result.resetAt.getTime() / 1000).toString());

    if (!result.allowed) {
      c.header('Retry-After', Math.ceil(config.windowMs / 1000).toString());
      return c.json(
        {
          error: { code: 'RATE_LIMITED', message: '请求过于频繁' },
        },
        429,
      );
    }

    await next();
  };
};
输入安全
所有外部输入都是不可信的。输入校验是防御注入攻击的第一道防线。


import { z } from 'zod';

const sanitizeString = (input: string): string => {
  return input.replace(/[<>]/g, '').trim().slice(0, 10000);
};

const safeUserInput = z.object({
  name: z.string().min(1).max(100).transform(sanitizeString),
  email: z.string().email().max(255),
  bio: z.string().max(1000).transform(sanitizeString).optional(),
});

const requestSizeLimit = async (c: Context, next: Next) => {
  const contentLength = parseInt(c.req.header('content-length') ?? '0', 10);
  if (contentLength > 1024 * 1024) {
    return c.json(
      {
        error: { code: 'PAYLOAD_TOO_LARGE', message: '请求体超过 1MB 限制' },
      },
      413,
    );
  }
  await next();
};
小结
    

  • API 安全是横切关注点——嵌入设计、开发、测试和运维的每个环节
    • 

  • JWT 认证需要短有效期、HTTPS 传输和 Token 刷新机制
    • 

  • RBAC 控制功能级权限，对象级授权确保"只能访问自己的资源"
    • 

  • 限流使用标准 Header（X-RateLimit-*）+ Retry-After，不同端点差异化配额
    • 

  • 输入校验 + 大小限制 + 字符过滤是防御注入攻击的三道防线
    •
