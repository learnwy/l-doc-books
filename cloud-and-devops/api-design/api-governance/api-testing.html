API 测试

核心概念

API 测试是确保接口正确性、可靠性和性能的关键实践。与 UI 测试不同，API 测试直接验证契约和行为——请求格式、响应结构、错误处理、边界条件和并发安全。API 测试的投入产出比极高：它比 E2E 测试快 10-100 倍，比单元测试覆盖更多的集成场景。

契约测试
契约测试验证 API 的实际行为是否符合其声明的契约（OpenAPI Spec、Proto 文件等）。它是自动化测试的第一道防线——如果响应结构都不对，功能测试就没有意义。


import { describe, it, expect } from 'vitest';

const BASE_URL = 'http://localhost:3000/api/v2';

describe('User API Contract', () => {
  it('GET /users returns valid list response', async () => {
    const response = await fetch(`${BASE_URL}/users?page=1&per_page=10`);

    expect(response.status).toBe(200);
    expect(response.headers.get('content-type')).toContain('application/json');

    const body = await response.json();

    expect(body).toHaveProperty('data');
    expect(body).toHaveProperty('meta');
    expect(Array.isArray(body.data)).toBe(true);
    expect(body.meta).toMatchObject({
      page: expect.any(Number),
      perPage: expect.any(Number),
      total: expect.any(Number),
    });

    if (body.data.length > 0) {
      const user = body.data[0];
      expect(user).toHaveProperty('id');
      expect(user).toHaveProperty('name');
      expect(user).toHaveProperty('email');
    }
  });

  it('POST /users validates required fields', async () => {
    const response = await fetch(`${BASE_URL}/users`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({}),
    });

    expect(response.status).toBe(422);
    const body = await response.json();
    expect(body.error.code).toBe('VALIDATION_FAILED');
    expect(body.error.details).toBeDefined();
    expect(body.error.details.length).toBeGreaterThan(0);
  });
});
使用 Zod Schema 做契约断言更为精确：


import { z } from 'zod';

const userResponseSchema = z.object({
  data: z.array(
    z.object({
      id: z.string(),
      name: z.string(),
      email: z.string().email(),
      role: z.enum(['user', 'admin', 'moderator']),
      createdAt: z.string().datetime(),
    }),
  ),
  meta: z.object({
    page: z.number(),
    perPage: z.number(),
    total: z.number(),
    totalPages: z.number(),
  }),
});

it('response matches schema', async () => {
  const response = await fetch(`${BASE_URL}/users`);
  const body = await response.json();
  const result = userResponseSchema.safeParse(body);
  expect(result.success).toBe(true);
});
功能测试
功能测试验证 API 的业务逻辑正确性——CRUD 操作、状态转换、业务规则、权限控制等。


describe('User CRUD', () => {
  let userId: string;

  it('creates a user', async () => {
    const response = await fetch(`${BASE_URL}/users`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${adminToken}` },
      body: JSON.stringify({
        name: 'Test User',
        email: 'test@example.com',
        role: 'user',
      }),
    });

    expect(response.status).toBe(201);
    const body = await response.json();
    expect(body.data.name).toBe('Test User');
    userId = body.data.id;
  });

  it('reads the created user', async () => {
    const response = await fetch(`${BASE_URL}/users/${userId}`, {
      headers: { Authorization: `Bearer ${adminToken}` },
    });

    expect(response.status).toBe(200);
    const body = await response.json();
    expect(body.data.id).toBe(userId);
  });

  it('updates the user', async () => {
    const response = await fetch(`${BASE_URL}/users/${userId}`, {
      method: 'PATCH',
      headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${adminToken}` },
      body: JSON.stringify({ name: 'Updated User' }),
    });

    expect(response.status).toBe(200);
    const body = await response.json();
    expect(body.data.name).toBe('Updated User');
  });

  it('deletes the user', async () => {
    const response = await fetch(`${BASE_URL}/users/${userId}`, {
      method: 'DELETE',
      headers: { Authorization: `Bearer ${adminToken}` },
    });

    expect(response.status).toBe(204);
  });

  it('returns 404 for deleted user', async () => {
    const response = await fetch(`${BASE_URL}/users/${userId}`, {
      headers: { Authorization: `Bearer ${adminToken}` },
    });

    expect(response.status).toBe(404);
  });
});
边界条件测试
API 的边界条件是 Bug 的高发区。系统化地测试边界条件可以发现大量隐藏问题。


describe('Boundary Conditions', () => {
  it('handles maximum page size', async () => {
    const response = await fetch(`${BASE_URL}/users?per_page=101`);
    expect(response.status).toBe(422);
  });

  it('handles special characters in search', async () => {
    const response = await fetch(`${BASE_URL}/users?search=${encodeURIComponent("O'Brien & Co.")}`);
    expect(response.status).toBe(200);
  });

  it('handles concurrent updates', async () => {
    const updates = Array.from({ length: 5 }, (_, i) =>
      fetch(`${BASE_URL}/users/${userId}`, {
        method: 'PATCH',
        headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${adminToken}` },
        body: JSON.stringify({ name: `Concurrent ${i}` }),
      }),
    );

    const responses = await Promise.all(updates);
    const successCount = responses.filter((r) => r.status === 200).length;
    expect(successCount).toBeGreaterThanOrEqual(1);
  });

  it('handles empty request body', async () => {
    const response = await fetch(`${BASE_URL}/users`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${adminToken}` },
      body: '',
    });
    expect(response.status).toBe(400);
  });
});

小结
    

  • API 测试投入产出比极高——比 E2E 快 10-100 倍，覆盖更多集成场景
    • 

  • 契约测试是第一道防线，用 Zod Schema 断言确保响应结构与声明一致
    • 

  • 功能测试覆盖 CRUD 全生命周期，包括创建→读取→更新→删除→404 确认
    • 

  • 边界条件测试（空值、极值、特殊字符、并发）是发现隐藏 Bug 的关键
    • 

  • 性能基准测试在 CI 中检测退化，阈值超标自动阻断发布
