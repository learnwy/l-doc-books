API 文档

核心概念

API 文档是 API 产品的"用户界面"——开发者通过文档理解 API 的能力、使用方式和限制。好的 API 文档不仅是技术参考手册，更是开发者的入职引导和问题解决工具。研究表明，开发者选择 API 时，文档质量的权重甚至超过功能本身。

OpenAPI 规范
OpenAPI（原 Swagger）是 REST API 描述的事实标准。它用 YAML/JSON 格式描述 API 的全部细节，工具链可以从中生成文档、客户端 SDK 和服务器存根。


openapi: 3.1.0
info:
  title: User Service API
  version: 2.0.0
  description: 用户管理服务 API
  contact:
    name: Platform Team
    email: platform@example.com

servers:
  - url: https://api.example.com/v2
    description: Production
  - url: https://api-staging.example.com/v2
    description: Staging

paths:
  /users:
    get:
      operationId: listUsers
      summary: 获取用户列表
      tags: [Users]
      parameters:
        - name: page
          in: query
          schema:
            type: integer
            default: 1
            minimum: 1
        - name: per_page
          in: query
          schema:
            type: integer
            default: 20
            minimum: 1
            maximum: 100
        - name: role
          in: query
          schema:
            $ref: '#/components/schemas/UserRole'
      responses:
        '200':
          description: 用户列表
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/UserListResponse'
        '401':
          $ref: '#/components/responses/Unauthorized'
interface OpenAPISpec {
  openapi: string;
  info: APIInfo;
  servers: Server[];
  paths: Record<string, PathItem>;
  components: Components;
}

interface APIInfo {
  title: string;
  version: string;
  description: string;
  contact: ContactInfo;
}
Schema 定义与代码同步
OpenAPI 的最大挑战是保持文档与代码同步。手动维护的 OpenAPI 文件很快就会与实际 API 不一致。解决方案是从代码生成文档或从文档生成代码。


在 Hono + Zod 技术栈中，可以从 Zod Schema 自动生成 OpenAPI 规范：


import { z } from 'zod';

const userSchema = z.object({
  id: z.string().uuid(),
  name: z.string().min(2).max(50),
  email: z.string().email(),
  role: z.enum(['user', 'admin', 'moderator']),
  createdAt: z.string().datetime(),
});

const createUserInput = z.object({
  name: z.string().min(2).max(50),
  email: z.string().email(),
  role: z.enum(['user', 'admin', 'moderator']).optional().default('user'),
});

const listUsersParams = z.object({
  page: z.coerce.number().int().min(1).default(1),
  perPage: z.coerce.number().int().min(1).max(100).default(20),
  role: z.enum(['user', 'admin', 'moderator']).optional(),
});
Zod-to-OpenAPI 库（如 @asteasolutions/zod-to-openapi）可以从 Zod Schema 自动生成 OpenAPI 组件：


import { OpenAPIRegistry, OpenApiGeneratorV31 } from '@asteasolutions/zod-to-openapi';

const registry = new OpenAPIRegistry();

registry.registerPath({
  method: 'get',
  path: '/users',
  request: {
    query: listUsersParams,
  },
  responses: {
    200: {
      description: '用户列表',
      content: {
        'application/json': {
          schema: z.object({
            data: z.array(userSchema),
            meta: paginationMeta,
          }),
        },
      },
    },
  },
});

const generator = new OpenApiGeneratorV31(registry.definitions);
const spec = generator.generateDocument({
  openapi: '3.1.0',
  info: { title: 'User API', version: '2.0.0' },
});
交互式文档
静态文档不够——开发者需要试用 API。交互式文档让开发者在浏览器中直接发送请求，看到实际响应。

代码示例与 SDK
好的 API 文档包含每个端点的代码示例，至少覆盖 cURL 和主流语言。


interface CodeExample {
  language: string;
  label: string;
  code: string;
}

const listUsersExamples: CodeExample[] = [
  {
    language: 'bash',
    label: 'cURL',
    code: `curl -X GET "https://api.example.com/v2/users?page=1&per_page=20" \\
  -H "Authorization: Bearer $TOKEN" \\
  -H "Accept: application/json"`,
  },
  {
    language: 'typescript',
    label: 'TypeScript',
    code: `const response = await fetch('https://api.example.com/v2/users?page=1', {
  headers: { Authorization: \`Bearer \${token}\` },
})
const { data, meta } = await response.json()`,
  },
];
自动生成客户端 SDK 是更进一步的做法。OpenAPI Generator 可以从 OpenAPI 规范生成多种语言的类型安全客户端。


小结
    

  • API 文档是 API 产品的用户界面——文档质量直接影响开发者采用率
    • 

  • OpenAPI 是 REST API 描述的事实标准，工具链可生成文档、SDK 和测试
    • 

  • 从代码生成文档（Zod → OpenAPI）是保持文档与代码同步的最佳方式
    • 

  • 交互式文档（Swagger UI、Scalar）让开发者直接试用 API，降低入门门槛
    • 

  • 代码示例至少覆盖 cURL 和主流语言，类型安全的 SDK 是最佳开发者体验
    •
