块存储与文件存储

核心概念

块存储和文件存储是云计算中另外两种重要的存储形态。块存储提供低延迟的随机读写能力，像物理硬盘一样挂载到计算实例上，适合数据库和需要高 IOPS 的应用。文件存储提供共享文件系统，多个实例可以同时挂载同一文件系统，适合内容管理和共享工作负载。

EBS 卷类型与性能特征
AWS EBS 提供多种卷类型，在性能、延迟和成本之间做出不同权衡。选择合适的卷类型需要根据工作负载的 IOPS、吞吐量和延迟要求。


gp3 是当前的通用 SSD 默认选择。它提供 3000 基础 IOPS 和 125 MiB/s 基础吞吐量，可独立调整到最高 16000 IOPS 和 1000 MiB/s。gp3 的定价比 gp2 低约 20%，且性能配置更灵活。适合大多数通用工作负载，包括中小型数据库、开发测试环境和应用启动卷。


io2 Block Express 是最高性能的 SSD 卷。它支持最高 256000 IOPS 和 4000 MiB/s 吞吐量，延迟在亚毫秒级。io2 支持多挂载（Multi-Attach），允许最多 16 个 EC2 实例同时挂载同一卷，适合集群化数据库。io2 适合 Oracle、SAP HANA 等关键业务数据库和需要极高 IOPS 的在线事务处理系统。


st1 是吞吐优化型 HDD，最高提供 500 MiB/s 的顺序读写吞吐。sc1 是冷存储 HDD，成本最低但性能也最低。HDD 卷适合大数据分析、日志处理等需要高吞吐但不需要高 IOPS 的场景。


EBS 快照是 EBS 的数据保护机制。快照存储在 S3 中，采用增量式备份——只保存上次快照以来变更的数据块。快照可以跨 AZ 和跨 Region 复制，是灾备和迁移的基础。EBS 快照生命周期管理器（DLM）可以自动化快照的创建和保留策略。

EFS 弹性文件系统
AWS EFS 是完全托管的弹性 NFS 文件系统，支持数千个 EC2 实例和 ECS 容器同时挂载。EFS 的核心优势是自动弹性——文件系统容量随数据量增减自动扩展和收缩，无需预配置。


EFS 提供两种性能模式。通用模式（General Purpose）提供最低延迟，适合大多数工作负载。最大 I/O 模式适合需要更高聚合吞吐的大规模并行工作负载，但延迟稍高。


EFS 的吞吐模式分为三种。弹性吞吐（Elastic）根据工作负载自动调整，按实际使用付费。预置吞吐（Provisioned）允许指定固定的吞吐量，适合吞吐需求稳定且超出文件系统大小所允许的基础吞吐的场景。突增吞吐（Bursting）基于文件系统大小提供基础吞吐，允许短时间突增。


EFS 同样支持存储类分层。标准存储类提供最低延迟，低频访问存储类（IA）成本更低但按访问次数收费。生命周期策略可以自动将指定天数未访问的文件转移到 IA 存储类。单区域 EFS（One Zone）只在单个 AZ 存储数据，成本比标准 EFS 低约 47%，适合不需要跨 AZ 冗余的场景。


EFS 的典型使用场景包括：容器化应用的共享存储（ECS/EKS 持久卷）、内容管理系统（WordPress、Drupal）的媒体文件存储、开发工具的共享工作区、机器学习的训练数据共享和 CI/CD 构建缓存。


高性能文件系统 FSx
AWS FSx 提供四种托管文件系统，满足不同的性能和协议需求。


FSx for Lustre 是面向 HPC 和大数据的高性能并行文件系统。单文件系统可提供数百 GiB/s 的吞吐和数百万 IOPS，延迟在亚毫秒级。Lustre 可以与 S3 无缝集成——文件系统的数据透明映射到 S3 存储桶，计算任务读取数据时自动从 S3 拉取，任务完成后可以将结果写回 S3。


FSx for Windows File Server 提供 SMB 协议的托管文件系统，支持 Windows ACL、DFS 命名空间和 Active Directory 集成。适合 Windows 工作负载、.NET 应用和企业文件共享。


FSx for NetApp ONTAP 提供企业级的多协议文件系统，同时支持 NFS、SMB 和 iSCSI。它继承了 NetApp 的数据管理功能，包括快照、克隆、压缩和分层。适合从本地 NetApp 环境迁移到云的企业。


FSx for OpenZFS 提供基于 ZFS 的高性能文件系统，支持数据压缩、快照和克隆。适合 Linux 工作负载和需要 ZFS 特性的应用。


存储架构设计策略
存储架构设计需要根据工作负载特征选择合适的存储类型和配置。关键考量因素包括性能要求（IOPS、吞吐量、延迟）、数据访问模式（随机/顺序、读写比例）、持久性和可用性要求、数据共享需求和成本预算。


数据库存储设计通常选择 EBS io2 或 gp3。关系型数据库需要高 IOPS 和低延迟的随机读写，io2 适合关键生产数据库，gp3 适合开发测试和中小规模生产。数据库日志和备份可以利用 st1 的高吞吐特性。


容器化应用的存储通过 CSI（Container Storage Interface）驱动集成。EBS CSI Driver 提供 Pod 级别的块存储，EFS CSI Driver 提供 Pod 间的共享存储。StatefulSet 中的 VolumeClaimTemplate 自动为每个 Pod 创建独立的 PV。


数据湖架构以 S3 对象存储为基础，FSx for Lustre 作为高性能计算层。ETL 管道将原始数据写入 S3，计算任务通过 Lustre 高速访问数据，结果写回 S3 供后续分析和查询。


小结
    

  • 块存储（EBS）提供低延迟随机读写能力，通过卷类型选择（gp3/io2/st1/sc1）匹配不同性能需求
    • 

  • EBS 快照实现增量备份，支持跨 AZ 和跨 Region 复制用于灾备
    • 

  • EFS 提供弹性共享文件系统，容量自动伸缩，支持数千实例并发挂载
    • 

  • FSx 系列提供特定协议和高性能文件系统：Lustre（HPC）、Windows（SMB）、ONTAP（多协议）、OpenZFS
    • 

  • 存储选型核心考量：IOPS 需求、吞吐量、延迟、共享需求和成本
    • 

  • 数据湖架构通常将 S3 作为存储底座，FSx for Lustre 作为高性能计算缓存层
    •
