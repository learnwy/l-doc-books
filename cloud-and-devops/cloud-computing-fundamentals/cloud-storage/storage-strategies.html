云存储策略

核心概念

云存储策略涵盖数据的分类、放置、保护、迁移和成本优化等关键决策。有效的存储策略不仅确保数据安全和可用，更能显著降低存储成本。在数据量爆炸式增长的时代，存储策略已成为云架构设计中不可忽视的重要环节。

数据分类与分层存储
数据分类是存储策略的起点。根据数据的访问频率、业务价值和保留要求，将数据划分为不同层级，然后匹配到相应成本的存储服务。


热数据（Hot Data）是频繁访问的活跃数据，如用户会话数据、最新交易记录和实时分析数据。热数据需要毫秒级或亚毫秒级的访问延迟，应存储在 S3 Standard、EBS gp3/io2 或 ElastiCache 中。


温数据（Warm Data）是偶尔访问的数据，如 30 天以上的日志文件、历史订单和月度报表。温数据可以接受稍高的访问延迟，适合存储在 S3 Standard-IA 或 S3 One Zone-IA 中，比 Standard 节省约 40% 的存储成本。


冷数据（Cold Data）是极少访问但需要长期保留的数据，如法规要求保留 7 年的交易记录、历史备份和归档日志。冷数据适合存储在 S3 Glacier 或 Glacier Deep Archive 中，成本仅为热存储的 1/10 到 1/30。


自动化数据分层是实现成本优化的关键。S3 Intelligent-Tiering 通过监控对象访问模式自动在频繁访问、低频访问和归档访问层之间移动数据。S3 生命周期策略基于对象年龄自动转换存储类或删除过期数据。EFS 的 Lifecycle Management 自动将未访问文件迁移到 IA 存储类。


备份与灾备策略
数据保护的核心指标是 RPO（Recovery Point Objective，恢复点目标）和 RTO（Recovery Time Objective，恢复时间目标）。RPO 定义了可接受的数据丢失时间窗口，RTO 定义了系统恢复到正常运行的最大允许时间。


AWS Backup 是集中化的备份管理服务，支持 EBS、EFS、RDS、DynamoDB、FSx 等服务的统一备份。通过备份计划（Backup Plan）定义备份频率、保留期和跨 Region 复制规则。备份保管库（Backup Vault）使用 KMS 加密存储备份数据，并支持 Vault Lock 实现 WORM（一次写入多次读取）保护。


灾备策略按恢复能力从低到高分为四个级别。备份与恢复（Backup & Restore）定期将数据备份到另一个 Region，灾难发生时从备份恢复基础设施。RTO 数小时到数天。先导服务（Pilot Light）在灾备 Region 维持最小化的核心服务运行。RTO 数十分钟。热备份（Warm Standby）在灾备 Region 运行缩减版的完整环境。RTO 分钟级。多活（Multi-Site Active/Active）在多个 Region 同时处理流量。RTO 接近零。


数据迁移策略
云数据迁移是将本地存储的数据转移到云端的过程。迁移策略的选择取决于数据量、可用带宽、迁移时间窗口和数据一致性要求。


在线迁移通过网络传输数据。AWS DataSync 是高性能的数据传输服务，支持从本地 NFS/SMB 存储迁移到 S3、EFS 和 FSx。DataSync 自动处理加密、数据完整性验证和增量传输，传输速度可达 10Gbps。S3 Transfer Acceleration 利用 CloudFront 边缘节点加速跨地域上传。


对于 PB 级数据量或网络带宽不足的场景，物理迁移设备是更实际的选择。AWS Snow 系列提供三种物理设备：Snowcone（8-14TB）适合边缘计算和小规模迁移，Snowball Edge（80-210TB）适合中等规模迁移和边缘计算，Snowmobile（100PB）是 45 英尺集装箱级的超大规模迁移方案。


数据库迁移使用专门的工具。AWS DMS（Database Migration Service）支持同构（如 MySQL → MySQL）和异构（如 Oracle → PostgreSQL）数据库迁移。Schema Conversion Tool（SCT）自动转换数据库 schema 和存储过程。DMS 支持持续复制（CDC），实现零停机迁移。

存储性能优化
存储性能优化需要从应用层、存储层和网络层三个维度综合考虑。


应用层优化包括数据压缩（减少存储量和传输量）、数据格式选择（Parquet/ORC 比 CSV 的查询效率高数倍）和缓存策略（将热点数据缓存到 ElastiCache 或应用内存）。


S3 的请求性能取决于前缀（Prefix）的设计。S3 对每个前缀支持每秒 5,500 次 GET 和 3,500 次 PUT 请求。通过将数据分散到多个前缀可以线性提升总吞吐。例如将日期作为前缀的一部分（/2024/01/01/）比将所有文件放在同一前缀下性能更好。


EBS 性能优化关注 IOPS 和吞吐量的匹配。EBS-optimized 实例提供专用的 EBS 带宽通道，避免与网络流量竞争。实例类型决定了可用的最大 EBS 带宽——选择实例时需要确保实例的 EBS 带宽上限不低于 EBS 卷的配置吞吐。RAID 0 可以将多个 EBS 卷的 IOPS 和吞吐叠加，但增加了数据丢失风险。


数据传输优化包括使用 Multipart Upload 并行上传大文件（S3 要求 5GB 以上文件必须使用 Multipart Upload，建议 100MB 以上就使用）、使用 S3 Byte-Range Fetches 并行下载大文件的不同部分、选择同 Region 的存储服务避免跨区域传输费用。


小结
    

  • 数据分类（热/温/冷）是存储策略的基础，不同层级数据匹配不同成本的存储服务
    • 

  • 自动化分层（Intelligent-Tiering、生命周期策略）是存储成本优化的关键手段
    • 

  • 灾备策略从备份恢复到多活，RPO/RTO 要求越高成本越高，需要与业务价值匹配
    • 

  • 数据迁移策略根据数据量选择在线传输（DataSync）或物理设备（Snow 系列）
    • 

  • 存储性能优化从应用层（压缩、缓存）、存储层（前缀设计、IOPS 配置）和网络层（Multipart Upload）三个维度入手
    • 

  • 存储策略应定期审查和调整，随着数据增长和访问模式变化持续优化
    •
