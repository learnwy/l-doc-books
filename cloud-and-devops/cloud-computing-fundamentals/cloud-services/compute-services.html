云计算服务

核心概念

云计算服务是云平台的核心能力，为用户提供按需获取的虚拟计算资源。从传统虚拟机到现代容器和无服务器函数，计算服务经历了多次抽象层次的演进。理解不同计算服务的特性和适用场景，是构建高效云架构的基础。

虚拟机实例与实例族
虚拟机（VM）是最基础也最通用的云计算服务形态。用户可以选择操作系统、配置 CPU 和内存规格、挂载存储卷，获得接近物理服务器的使用体验。


各云平台将 VM 按用途分为不同的实例族（Instance Family）。通用型实例（如 AWS m7g、GCP n2-standard）提供均衡的 CPU 和内存配比，适合 Web 服务器、应用服务器和中小型数据库。计算密集型实例（如 AWS c7g、GCP c2）提供高 CPU-内存比，适合批处理、视频编码和科学计算。内存密集型实例（如 AWS r7g、GCP m2）提供高内存-CPU 比，适合内存数据库、大数据分析和缓存服务。


GPU 实例（如 AWS p5、GCP a3）配备 NVIDIA A100/H100 等高性能 GPU，是 AI 模型训练和推理的主力。存储优化型实例（如 AWS i4i）提供高 IOPS 的本地 NVMe 存储，适合高性能数据库和数据仓库。


实例的 CPU 架构选择也影响成本和性能。AWS Graviton（ARM 架构）相比同规格的 x86 实例提供约 20% 的性价比提升。GCP 的 Tau T2A 和 Azure 的 Ampere Altra 同样提供 ARM 选项。对于不依赖 x86 特定指令集的工作负载，ARM 实例通常是更经济的选择。


VM 的生命周期管理包括创建、启动、停止、终止和快照。stopped 状态下 VM 不产生计算费用但仍计算存储费用。Machine Image 和 Launch Template 机制支持快速创建标准化的实例配置。


自动伸缩与弹性计算
自动伸缩（Auto Scaling）是云计算区别于传统 IT 的核心能力。它允许系统根据实际负载动态调整计算资源，在保证性能的同时最小化成本。


水平扩展（Scale Out/In）通过增减实例数量应对负载变化。AWS Auto Scaling Group、GCP Managed Instance Group 和 Azure VMSS 提供了声明式的扩缩容策略。常见的扩缩触发指标包括 CPU 使用率、内存使用率、网络吞吐量和自定义 CloudWatch/Stackdriver 指标。


扩缩容策略分为三类。目标追踪策略（Target Tracking）维持某个指标在目标值附近，如将平均 CPU 使用率保持在 60%。步进策略（Step Scaling）根据指标偏离阈值的程度执行不同幅度的扩缩动作。计划策略（Scheduled Scaling）在可预测的时间点提前调整容量，适合已知流量模式的场景。


预测性扩缩容（Predictive Scaling）利用机器学习分析历史负载模式，提前预测并准备容量。AWS 和 GCP 都提供了预测性扩缩容功能，可以显著减少反应延迟。


自动伸缩的最佳实践包括：设置合理的最小和最大实例数量作为安全边界、配置冷却期（Cooldown Period）避免震荡扩缩、使用多指标综合评估避免单一指标误判、定期审查扩缩容日志优化策略参数。


容器化计算服务
容器是现代云计算的主流计算单元。相比虚拟机，容器共享宿主机操作系统内核，具有更快的启动速度、更低的资源开销和更好的可移植性。


云平台提供两类容器计算服务。托管 Kubernetes 服务（如 AWS EKS、GCP GKE、Azure AKS）为用户管理 Kubernetes 控制平面，用户只需关注工作负载的部署和运行。全托管容器服务（如 AWS Fargate、GCP Cloud Run、Azure Container Instances）进一步消除了节点管理的负担，用户只需提交容器镜像即可运行。


容器注册表（Container Registry）是容器化工作流的核心组件。AWS ECR、GCP Artifact Registry 和 Azure ACR 提供了私有镜像仓库，支持镜像的存储、扫描和分发。镜像安全扫描可以在 CI/CD 阶段检测已知漏洞。


容器计算的成本优化策略包括：使用 Spot/Preemptible 节点运行容错性强的工作负载、通过 Cluster Autoscaler 动态调整节点数量、合理设置 Pod 的 resource requests 和 limits 避免过度配置、使用 Karpenter 等智能调度器优化节点选择。


无服务器计算与事件驱动
无服务器计算（Serverless）是计算抽象的最高层次。用户只需编写处理事件的函数代码，平台负责所有的执行环境管理，包括资源分配、扩缩容、故障恢复和安全补丁。


AWS Lambda 是最广泛使用的 FaaS 平台，支持 Node.js、Python、Java、Go、.NET 等运行时。GCP Cloud Functions 和 Azure Functions 提供类似能力。函数的执行时长、内存配置和并发数是关键的配置参数。


无服务器计算的事件源包括：HTTP 请求（API Gateway）、消息队列（SQS、Pub/Sub）、对象存储事件（S3、GCS）、数据库变更流（DynamoDB Streams）和定时触发（CloudWatch Events）。事件驱动架构使无服务器计算天然适合构建松耦合、高弹性的系统。


冷启动（Cold Start）是无服务器计算的主要性能挑战。当函数首次调用或长时间未调用后被调用时，平台需要初始化执行环境，可能产生毫秒到秒级的额外延迟。预配置并发（Provisioned Concurrency）可以消除冷启动但会产生持续费用。轻量化运行时（如自定义 Runtime 或 GraalVM native-image）可以显著缩短冷启动时间。

小结
    

  • 云计算服务从裸金属到无服务器形成了完整的抽象层次，每层在灵活性和管理便利性之间做出不同权衡
    • 

  • 虚拟机实例通过实例族分类满足不同工作负载的 CPU、内存、GPU 和存储需求，ARM 架构提供更好的性价比
    • 

  • 自动伸缩是云计算弹性的核心实现，目标追踪、步进和计划三种策略适配不同场景
    • 

  • 容器化计算通过 Kubernetes 托管服务和全托管容器服务提供云原生的部署体验
    • 

  • 无服务器计算实现了极致的运维简化和按需计费，冷启动是需要关注的性能挑战
    • 

  • 实际架构中通常混合使用多种计算服务，根据工作负载特征选择最合适的计算形态
    •
