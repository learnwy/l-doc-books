CDN 与边缘计算

核心概念

内容分发网络（CDN）通过在全球分布的边缘节点缓存内容，将用户请求路由到物理距离最近的节点，从而大幅降低延迟并减轻源站压力。边缘计算进一步将计算能力推送到靠近用户的位置，实现毫秒级响应。CDN 和边缘计算是现代全球化应用架构的关键组件。

CDN 缓存架构与策略
CDN 的核心是缓存机制。边缘节点根据 HTTP 缓存头（Cache-Control、Expires、ETag）决定是否缓存响应以及缓存多长时间。合理的缓存策略是 CDN 发挥效能的关键。


Cache-Control 头是控制缓存行为的主要手段。max-age=3600 表示内容在 3600 秒内有效。s-maxage 专门控制共享缓存（如 CDN）的过期时间，优先级高于 max-age。no-cache 表示每次使用前必须到源站验证，no-store 表示完全不缓存。stale-while-revalidate 允许在后台更新缓存时继续使用过期内容，提升用户体验。


缓存键（Cache Key）决定了 CDN 如何区分不同的缓存对象。默认缓存键通常包含 URL 路径和查询字符串。CloudFront 和 Fastly 支持自定义缓存键，可以包含 HTTP Header、Cookie 或地理位置信息。缓存键设计不当会导致缓存命中率下降（键空间过大）或内容错误（键空间过小）。


缓存失效（Invalidation）是 CDN 运营的重要操作。当源站内容更新时，需要清除边缘节点上的旧缓存。CloudFront 支持按路径模式失效（如 /images/*），但大规模失效操作有速率限制。更好的实践是使用版本化 URL（如 /app.v2.js）或内容哈希（如 /app.a1b2c3.js），避免主动失效。


AWS CloudFront 提供了 400+ 个边缘节点和 13 个区域性边缘缓存。区域性边缘缓存位于源站和边缘节点之间，增加了一层缓存，进一步减少回源请求。CloudFront 支持 Origin Shield 功能，在源站前增加集中式缓存层，将回源请求合并为单次请求。


CDN 安全与防护
CDN 不仅加速内容分发，还是安全防护的第一道防线。DDoS 攻击、恶意爬虫和数据窃取等威胁可以在边缘节点被拦截。


AWS Shield 提供 DDoS 防护。Shield Standard 免费提供 L3/L4 DDoS 防护，Shield Advanced 提供 L7 DDoS 防护、实时攻击通知、DDoS 响应团队支持和成本保护。CDN 的全球分布式架构天然具备抗 DDoS 能力——攻击流量被分散到数百个边缘节点，不会集中冲击源站。


AWS WAF（Web Application Firewall）可以部署在 CloudFront 上，基于规则过滤恶意请求。WAF 规则支持 IP 黑白名单、地理位置限制、速率限制、SQL 注入和 XSS 检测。AWS 提供托管规则组（如 OWASP Top 10）和第三方规则组。


HTTPS 配置是 CDN 安全的基础。CloudFront 支持自定义 SSL 证书（通过 ACM 免费获取）和 TLS 1.3。安全策略（Security Policy）控制 CDN 与客户端之间的最低 TLS 版本和加密套件。Origin Protocol Policy 控制 CDN 与源站之间的通信协议。


签名 URL 和签名 Cookie 提供了内容访问控制。通过 CloudFront 密钥对生成限时签名，确保只有授权用户才能访问受保护的内容。这对视频点播、付费下载和私有 API 等场景至关重要。


边缘计算平台
边缘计算将代码执行推送到 CDN 边缘节点，在用户最近的位置运行业务逻辑。这超越了传统 CDN 的纯缓存能力，实现了在边缘进行个性化、A/B 测试、认证、重定向等动态处理。


CloudFront Functions 是轻量级的边缘函数，运行在 CloudFront 的所有边缘节点上。它使用 JavaScript（ES 5.1）运行时，启动时间在亚毫秒级，适合 HTTP Header 操作、URL 重写、简单的认证检查和缓存键操作。限制包括：无网络访问、最大执行时间 1ms、最大内存 2MB。


Lambda@Edge 运行在 CloudFront 的区域性边缘缓存上，功能更强大。支持 Node.js 和 Python 运行时，可以访问网络和 AWS 服务，最大执行时间 30 秒。Lambda@Edge 适合复杂的请求/响应转换、动态源站选择、图片实时处理和服务端渲染。


Cloudflare Workers 是另一个主流的边缘计算平台，基于 V8 引擎提供全球分布的 JavaScript/WebAssembly 运行时。Workers 支持 KV 存储、Durable Objects（有状态边缘计算）和 R2 对象存储，构建了完整的边缘应用平台。

全站加速与动态内容优化
传统 CDN 主要加速静态内容，但现代应用的大部分流量是动态的（API 响应、个性化页面）。全站加速（Dynamic Site Acceleration, DSA）技术通过优化动态请求的传输路径来降低延迟。


动态加速的核心技术包括：TCP 连接优化（在边缘和源站之间维护长连接池，避免每次请求的 TCP 三次握手开销）、智能路由（选择最优的网络路径而非 BGP 默认路径）、协议优化（使用 HTTP/2 或 QUIC 在边缘和源站之间传输）和预取（在边缘节点预测性地建立与源站的连接）。


图片优化是 CDN 的重要增值服务。Cloudflare Image Resizing、CloudFront 配合 Lambda@Edge 可以在边缘实时调整图片大小、格式转换（WebP/AVIF）和质量压缩。这避免了源站存储多个尺寸的图片副本，同时为不同设备提供最优格式。


视频分发利用 CDN 的分段缓存能力。HLS 和 DASH 协议将视频切分为小片段（通常 2-10 秒），每个片段独立缓存和分发。自适应码率（ABR）根据网络状况动态切换视频质量，CDN 缓存所有码率的片段以支持无缝切换。


小结
    

  • CDN 通过全球边缘缓存将内容推送到离用户最近的节点，是降低延迟和减轻源站压力的核心手段
    • 

  • 缓存策略（Cache-Control、缓存键、失效机制）决定了 CDN 的效能，版本化 URL 优于主动失效
    • 

  • CDN 安全防护涵盖 DDoS 防御（Shield）、WAF 规则过滤和签名 URL 访问控制
    • 

  • 边缘计算（CloudFront Functions、Lambda@Edge、Workers）将动态逻辑推送到边缘执行
    • 

  • 全站加速通过 TCP 优化、智能路由和协议升级提升动态请求性能
    • 

  • 图片和视频分发是 CDN 的重要应用场景，边缘实时处理避免了源站的重复存储
    •
