负载均衡

核心概念

负载均衡是分布式系统中将流量均匀分配到多个后端实例的技术。在云环境中，负载均衡器是构建高可用、高性能应用架构的核心组件。它不仅分发流量，还承担健康检查、SSL 终止、会话保持和流量调度等关键职责。

应用负载均衡器（ALB）
应用负载均衡器工作在 OSI 第 7 层（HTTP/HTTPS），能够基于请求内容进行智能路由。这是现代 Web 应用和微服务架构中使用最广泛的负载均衡类型。


ALB 的路由规则基于监听器（Listener）和规则（Rule）。监听器定义在特定端口和协议上接收请求，规则定义将请求路由到哪个目标组（Target Group）。路由条件支持：主机名（Host Header）、URL 路径（Path）、HTTP 方法、查询字符串和源 IP。


基于路径的路由是微服务架构的关键能力。例如将 /api/* 路由到 API 服务组，/static/* 路由到静态资源服务组，/ws/* 路由到 WebSocket 服务组。基于主机名的路由允许在单个 ALB 上承载多个域名的服务。


ALB 原生支持 HTTP/2 和 WebSocket 协议。HTTP/2 的多路复用特性可以显著减少连接数和延迟。gRPC 应用也可以通过 ALB 的 HTTP/2 支持进行负载均衡。


目标组是 ALB 路由的终点，可以包含 EC2 实例、ECS 容器任务、Lambda 函数或 IP 地址。ALB 支持加权目标组，允许按比例分配流量到不同版本的服务，实现蓝绿部署和金丝雀发布。


ALB 的健康检查通过定期向目标发送 HTTP 请求并检查响应状态码来判断实例健康状态。健康检查参数包括检查路径、间隔时间、超时时间、健康阈值和不健康阈值。合理配置健康检查参数是避免误判和快速故障剔除的关键。


网络负载均衡器（NLB）
网络负载均衡器工作在 OSI 第 4 层（TCP/UDP/TLS），直接基于 IP 地址和端口进行流量分发。NLB 的核心优势在于超高性能和超低延迟，能够处理每秒数百万个请求，延迟仅增加微秒级别。


NLB 保留客户端源 IP 地址，这对需要基于客户端 IP 进行安全策略或日志分析的场景至关重要。ALB 默认会替换源 IP（需通过 X-Forwarded-For 头传递原始 IP），而 NLB 的透传特性使后端实例直接看到真实客户端 IP。


NLB 支持静态 IP 和弹性 IP。每个 AZ 分配一个固定 IP，适合需要固定入口 IP 的防火墙规则配置。NLB 也支持 PrivateLink，可以将服务通过 VPC Endpoint 暴露给其他 VPC 或账户。


NLB 的 TLS 终止功能支持在负载均衡器层处理 TLS 解密，减轻后端实例的 CPU 负担。对于需要端到端加密的场景，NLB 可以配置为 TLS 透传模式，由后端实例直接处理 TLS。


NLB 适用场景包括：需要极高吞吐和低延迟的实时应用、TCP/UDP 协议的非 HTTP 服务（如数据库代理、游戏服务器）、需要固定 IP 的场景以及需要通过 PrivateLink 暴露的服务。


全球负载均衡与流量管理
全球负载均衡将用户请求路由到距离最近或最优的 Region，实现全球化应用的低延迟访问和灾备切换。


AWS Global Accelerator 利用 AWS 全球骨干网加速流量传输。用户请求先到达最近的 AWS Edge Location，然后通过 AWS 内部网络路由到目标 Region，避免了公共互联网的拥堵和不稳定。Global Accelerator 提供两个 Anycast 静态 IP 作为全球入口。


GCP Global Load Balancer 提供真正的全球级 L7 负载均衡。单个 IP 地址可以将流量路由到全球多个 Region 的后端，基于用户地理位置自动选择最优后端。GCP GLB 支持 CDN 集成和 Cloud Armor WAF。


AWS Route 53 的路由策略提供了 DNS 级别的全球流量管理。加权路由（Weighted）按权重分配流量到不同 Region。延迟路由（Latency-based）将用户路由到延迟最低的 Region。地理位置路由（Geolocation）根据用户所在国家/地区路由。故障转移路由（Failover）在主站点故障时自动切换到备用站点。

高级负载均衡模式
在微服务和 Kubernetes 环境中，负载均衡呈现出更丰富的模式。


客户端负载均衡通过在客户端维护服务实例列表并执行负载均衡算法来实现。gRPC 客户端负载均衡、Envoy Sidecar 代理和 Kubernetes 的 kube-proxy 都采用这种模式。客户端负载均衡消除了集中式负载均衡器的性能瓶颈，但增加了客户端的复杂性。


服务网格（如 Istio）提供了透明的 L7 负载均衡。Envoy Sidecar 拦截所有出站流量，执行基于 HTTP Header、Cookie 等的高级路由策略。服务网格还支持熔断、限流和故障注入等流量治理能力。


Kubernetes Service 提供了集群内的负载均衡。ClusterIP 类型通过 iptables/IPVS 实现集群内服务间的四层负载均衡。NodePort 和 LoadBalancer 类型将服务暴露到集群外部。Ingress Controller（如 nginx-ingress、Traefik）提供七层负载均衡和路由功能。


负载均衡算法的选择影响流量分配的均匀性和性能。轮询（Round Robin）最简单但不考虑后端负载差异。最少连接（Least Connections）将请求路由到当前连接数最少的实例。加权轮询和加权最少连接允许按实例能力分配不同的流量比例。一致性哈希基于请求特征将同一客户端的请求路由到同一后端，适合有状态服务。


小结
    

  • 负载均衡器是构建高可用云架构的核心组件，分为 L4（NLB）和 L7（ALB）两大类
    • 

  • ALB 提供基于内容的智能路由，支持路径、主机名、Header 等多维度路由规则
    • 

  • NLB 提供超高性能的四层负载均衡，保留源 IP，支持固定 IP 和 PrivateLink
    • 

  • 全球负载均衡通过 Global Accelerator、Route 53 和 CDN 实现跨 Region 流量管理
    • 

  • 微服务环境中客户端负载均衡、服务网格和 Kubernetes Ingress 提供更灵活的流量控制
    • 

  • 负载均衡算法（轮询、最少连接、一致性哈希）应根据服务特性合理选择
    •
