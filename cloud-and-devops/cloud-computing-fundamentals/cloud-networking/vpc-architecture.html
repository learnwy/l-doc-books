VPC 网络架构

核心概念

虚拟私有云（VPC）是云计算网络层的基础构建块，为用户在公有云中提供逻辑隔离的网络环境。VPC 允许用户自定义 IP 地址范围、创建子网、配置路由表和网络 ACL，构建与传统数据中心类似的网络拓扑。理解 VPC 架构是设计安全、高可用云基础设施的前提。

子网设计与 IP 地址规划
子网设计是 VPC 架构的核心决策。合理的子网划分直接影响安全隔离、高可用性和网络可扩展性。


IP 地址规划的第一步是选择 VPC 的 CIDR 块。/16 是最常用的选择，提供 65536 个 IP 地址，足以支撑大多数应用场景。在需要 VPC Peering 或 Transit Gateway 互连多个 VPC 的环境中，必须确保各 VPC 的 CIDR 不重叠。


子网按访问模式分为公有子网和私有子网。公有子网关联的路由表包含指向 Internet Gateway 的默认路由（0.0.0.0/0 → igw），其中的实例可以直接被互联网访问。私有子网没有到 Internet Gateway 的路由，其中的实例通过 NAT Gateway 访问互联网，但无法从互联网直接访问。


多 AZ 部署是高可用架构的基础。每个 AZ 至少创建一个公有子网和一个私有子网，确保任意一个 AZ 故障时服务可以在其他 AZ 继续运行。典型的三层架构将 Web 层放在公有子网，应用层和数据层放在私有子网。


子网 CIDR 的大小影响可分配的 IP 数量。AWS 在每个子网中保留 5 个 IP 地址（网络地址、VPC 路由器、DNS 服务器、预留和广播地址），/24 子网实际可用 251 个 IP。对于需要大量 Pod IP 的 Kubernetes 集群，需要预留足够大的子网。


安全组与网络 ACL
安全组（Security Group）是 VPC 的核心安全机制，作用于实例级别的虚拟防火墙。安全组是有状态的——如果允许入站流量，对应的出站响应会自动放行，反之亦然。


安全组只支持允许规则，默认拒绝所有入站流量，允许所有出站流量。规则由协议、端口范围和源/目标组成。源可以是 CIDR 块、另一个安全组 ID 或 Prefix List。引用安全组 ID 是实现服务间精细访问控制的最佳实践——例如允许 Web 安全组访问应用安全组的 8080 端口。


网络 ACL（Network Access Control List）作用于子网级别，是无状态的防火墙。ACL 同时支持允许和拒绝规则，按序号从低到高评估，匹配到第一条规则即停止。由于无状态特性，需要同时配置入站和出站规则。


安全组和网络 ACL 形成了纵深防御。安全组适合精细化的服务间访问控制，网络 ACL 适合子网级别的粗粒度防护（如封禁恶意 IP 段）。实践中大部分安全策略通过安全组实现，网络 ACL 作为额外防线。


VPC 互连与混合网络
跨 VPC 通信和混合云网络连接是企业级架构的关键需求。AWS 提供了多种互连机制满足不同场景。


VPC Peering 在两个 VPC 之间建立点对点的私有网络连接。Peering 流量不经过公网，延迟低且带宽高。但 Peering 不支持传递路由——如果 VPC-A 与 VPC-B 和 VPC-C 都建立了 Peering，VPC-B 和 VPC-C 之间不能通过 VPC-A 通信。


Transit Gateway 解决了 VPC Peering 的扩展性问题。它作为中心化的网络枢纽，连接多个 VPC 和本地网络。Transit Gateway 支持路由表隔离，可以实现复杂的网络拓扑（如共享服务 VPC、环境隔离等）。


混合云网络连接有两种主要方式。Site-to-Site VPN 通过加密隧道在 VPC 和本地网络之间建立连接，部署快但带宽受限于互联网质量。Direct Connect（专线）提供专用的物理网络连接，带宽可达 100Gbps，延迟稳定，适合大数据传输和延迟敏感的应用。


PrivateLink 提供了服务级别的私有连接。通过 VPC Endpoint 访问 AWS 服务（如 S3、DynamoDB）时，流量在 AWS 网络内部传输，不经过互联网。Interface Endpoint 基于 ENI 实现，Gateway Endpoint 基于路由实现。PrivateLink 也支持跨账户和跨 VPC 的私有服务暴露。

小结
    

  • VPC 是云网络的基础构建块，提供逻辑隔离的网络环境，支持自定义 IP 规划和路由策略
    • 

  • 子网设计应区分公有和私有子网，跨多 AZ 部署确保高可用性
    • 

  • 安全组（有状态、实例级）和网络 ACL（无状态、子网级）构成纵深防御体系
    • 

  • VPC Peering 适合少量 VPC 互连，Transit Gateway 适合大规模网络架构
    • 

  • 混合网络通过 VPN 和 Direct Connect 连接云端与本地，PrivateLink 提供私有服务访问
    • 

  • IP 地址规划应留有余量，避免 CIDR 冲突影响后续网络互连
    •
