密钥与凭证管理

核心概念

密钥与凭证管理（Secrets Management）是云安全架构中保护敏感信息的核心实践。密钥包括数据库密码、API Key、OAuth Token、TLS 证书、SSH 密钥、加密密钥等。这些敏感信息如果处理不当（硬编码、明文存储、日志泄露），将直接导致安全事件。

有效的密钥管理需要解决四个核心问题：安全存储（密钥不能明文存储）、安全分发（密钥如何安全地传递给应用）、权限控制（谁可以读取哪些密钥）、生命周期管理（密钥的轮换、过期和撤销）。

AWS Secrets Manager
AWS Secrets Manager 是 AWS 推荐的密钥管理服务。它提供加密存储、自动轮换、跨区域复制和精细化的访问控制。


存储与加密：每个密钥使用 AWS KMS 加密（可选 AWS 托管密钥或客户管理密钥 CMK）。密钥值支持字符串和二进制格式，最大 64KB。密钥支持版本控制，每次更新创建新版本（AWSCURRENT 标签指向当前版本）。


自动轮换是 Secrets Manager 的核心差异化功能。配置轮换后，Secrets Manager 通过 Lambda 函数自动更新密钥值和关联的服务凭证。对于 RDS、Redshift 和 DocumentDB，AWS 提供预建的轮换 Lambda 函数。


import { SecretsManagerClient, GetSecretValueCommand, RotateSecretCommand } from '@aws-sdk/client-secrets-manager';

const sm = new SecretsManagerClient({});

const getDbCredentials = async () => {
  const response = await sm.send(
    new GetSecretValueCommand({
      SecretId: 'prod/database/primary',
      VersionStage: 'AWSCURRENT',
    }),
  );
  return JSON.parse(response.SecretString!) as {
    host: string;
    username: string;
    password: string;
    port: number;
  };
};

const enableRotation = async (secretId: string) => {
  await sm.send(
    new RotateSecretCommand({
      SecretId: secretId,
      RotationLambdaARN: 'arn:aws:lambda:us-east-1:123:function:rotate-db-secret',
      RotationRules: {
        AutomaticallyAfterDays: 30,
      },
    }),
  );
};

AWS KMS 密钥管理
AWS Key Management Service（KMS）是加密密钥的集中管理服务。KMS 管理的密钥用于加密 EBS 卷、S3 对象、RDS 数据库、Secrets Manager 密钥值等。


密钥层次结构：KMS 采用信封加密（Envelope Encryption）模型。KMS 根密钥（CMK）存储在 FIPS 140-2 Level 3 认证的硬件安全模块（HSM）中，永不离开 HSM。CMK 用于加密数据密钥（Data Key），数据密钥用于加密实际数据。

HashiCorp Vault 与多云密钥管理
对于多云环境或需要更高级密钥管理功能的场景，HashiCorp Vault 是业界最广泛使用的开源密钥管理系统。


Vault 核心功能包括动态密钥（动态生成短期数据库凭证）、加密即服务（Transit Engine 提供加密/解密 API 而不暴露密钥）、PKI 引擎（自动签发 TLS 证书）和审计日志（详细记录每次密钥访问）。


动态密钥是 Vault 的杀手级功能。应用请求数据库凭证时，Vault 实时创建一个具有有限权限和短 TTL 的数据库用户。凭证过期后自动销毁。这消除了长期凭证泄露的风险——即使凭证被截获，也会在数分钟内失效。

应用中的密钥使用模式
在应用代码中安全使用密钥需要遵循特定的模式和最佳实践。


缓存策略：每次函数调用都从 Secrets Manager 获取密钥会增加延迟和成本。推荐在 Lambda Handler 外部获取并缓存密钥，温启动时复用缓存。Lambda Powertools Parameters 提供内置的 TTL 缓存。


连接池管理：数据库连接应在函数初始化时建立（Handler 外部），利用实例复用。使用 RDS Proxy 管理连接池，避免 Lambda 函数创建过多数据库连接。

安全编码规则：


    

  • 永远不在日志中输出密钥值（即使是 DEBUG 级别）
    • 

  • 不将密钥值存入版本控制系统
    • 

  • 使用完毕后清理内存中的密钥（在支持的语言中）
    • 

  • 密钥传输始终使用 TLS
    • 

  • 为每个环境（dev/staging/prod）使用独立的密钥
    • 



小结
    

  • 密钥管理解决四个核心问题：安全存储、安全分发、权限控制、生命周期管理
    • 

  • AWS Secrets Manager 提供加密存储和自动轮换（四步模型）
    • 

  • KMS 采用信封加密：CMK 加密数据密钥，数据密钥加密实际数据
    • 

  • 密钥策略 + IAM 策略实现精细化的加密密钥访问控制
    • 

  • HashiCorp Vault 的动态密钥消除长期凭证风险，适合多云环境
    • 

  • 应用中缓存密钥减少延迟和成本，结合 RDS Proxy 管理连接池
    • 

  • 安全编码：不日志输出密钥、不版本控制密钥、传输使用 TLS
