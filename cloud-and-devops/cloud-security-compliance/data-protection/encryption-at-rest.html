静态数据加密

核心概念

静态数据加密（Encryption at Rest）是保护存储在磁盘、数据库、对象存储等介质上的数据免遭未授权访问的核心安全措施。即使物理存储设备被盗或底层存储系统被入侵，加密后的数据也无法被读取。在云环境中，静态加密是合规要求（如 GDPR、HIPAA、PCI DSS）的基本条件。

AWS 的静态加密基于 KMS（Key Management Service）提供的信封加密模型。数据使用数据密钥（Data Key）加密，数据密钥使用 KMS 主密钥（CMK）加密。这种两层架构将密钥管理与数据加密分离，既保证了安全性（CMK 永不离开 HSM），又保证了性能（大量数据使用本地数据密钥加密，避免 KMS API 调用成为瓶颈）。

S3 对象加密
Amazon S3 支持四种服务端加密方式和客户端加密。从 2023 年起，S3 默认对所有新对象启用 SSE-S3 加密——即使用户未明确配置，数据也会被加密。


SSE-S3（Server-Side Encryption with Amazon S3-Managed Keys）：S3 管理加密密钥的生成、使用和轮换。每个对象使用唯一的密钥加密，密钥本身由 S3 定期轮换的主密钥加密。用户完全无需管理密钥，但也无法控制密钥的使用和审计。


SSE-KMS（Server-Side Encryption with KMS Keys）：使用 KMS CMK 加密对象。每次加密/解密操作都会在 CloudTrail 中留下审计记录。支持密钥轮换、跨账户共享和精细化访问控制。推荐用于需要合规审计的场景。


import { S3Client, PutObjectCommand, GetObjectCommand } from '@aws-sdk/client-s3';

const s3 = new S3Client({});

await s3.send(
  new PutObjectCommand({
    Bucket: 'my-secure-bucket',
    Key: 'sensitive-data/report.pdf',
    Body: Buffer.from('sensitive content'),
    ServerSideEncryption: 'aws:kms',
    SSEKMSKeyId: 'arn:aws:kms:us-east-1:123:key/abc-def',
    BucketKeyEnabled: true,
  }),
);
S3 Bucket Key 是成本优化功能。启用后，S3 生成一个桶级数据密钥用于加密对象，而非每个对象都调用 KMS API。这将 KMS API 调用次数降低 99%，显著减少成本（KMS API 调用 $0.03/万次）。


默认加密策略：通过 S3 桶策略强制所有上传必须使用指定的加密方式。拒绝未加密的上传请求：


{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyUnencryptedUpload",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::my-secure-bucket/*",
      "Condition": {
        "StringNotEquals": {
          "s3:x-amz-server-side-encryption": "aws:kms"
        }
      }
    }
  ]
}
数据库加密
RDS 加密：RDS 支持使用 KMS CMK 对整个数据库实例进行加密，包括数据文件、日志文件、自动备份和只读副本。加密在实例创建时配置，已创建的未加密实例无法直接启用加密——需要创建快照、复制快照时启用加密、从加密快照恢复新实例。


DynamoDB 加密：DynamoDB 默认使用 AWS 管理密钥对所有表数据加密。用户可以选择使用客户管理密钥（CMK）获得更精细的密钥控制和审计能力。加密覆盖表数据、本地二级索引（LSI）和全局二级索引（GSI），但不包括表名和属性名。

EBS 与文件系统加密
EBS（Elastic Block Store）加密：EBS 支持使用 KMS CMK 加密卷数据。加密在卷创建时配置。可以设置账户级默认加密——新创建的 EBS 卷自动使用指定的 CMK 加密。加密覆盖数据卷、快照和从快照创建的卷。


EFS（Elastic File System）加密：EFS 支持静态加密（数据写入磁盘时加密）和传输加密（NFS 连接使用 TLS）。静态加密在文件系统创建时配置，使用 KMS CMK。传输加密通过 EFS Mount Helper 自动配置 TLS。


加密性能影响：现代 CPU 内置 AES-NI 指令集，硬件加速的 AES-256 加密对性能的影响通常小于 5%。对于高 IOPS 场景（如数据库），加密的性能开销可以忽略不计。

客户端加密与端到端加密
客户端加密（Client-Side Encryption, CSE）在数据发送到云存储之前就完成加密。云服务提供商永远无法看到明文数据——即使内部员工或合规请求也无法解密。这是最高安全级别的加密方案。


AWS Encryption SDK 提供了标准化的客户端加密实现。支持多种编程语言（Java、Python、JavaScript、C）。使用信封加密模型，支持多密钥加密（同一数据可以用多个 CMK 加密，任一 CMK 即可解密）。


import { KmsKeyringNode, buildClient, CommitmentPolicy } from '@aws-crypto/client-node';

const { encrypt, decrypt } = buildClient(CommitmentPolicy.REQUIRE_ENCRYPT_REQUIRE_DECRYPT);

const keyring = new KmsKeyringNode({
  generatorKeyId: 'arn:aws:kms:us-east-1:123456789012:key/primary-key',
  keyIds: ['arn:aws:kms:eu-west-1:123456789012:key/backup-key'],
});

const plaintext = Buffer.from('sensitive data');
const { result: ciphertext } = await encrypt(keyring, plaintext, {
  encryptionContext: { purpose: 'user-data', userId: 'USR-123' },
});

const { plaintext: decrypted } = await decrypt(keyring, ciphertext);
加密上下文（Encryption Context） 是 KMS 的重要安全特性。加密上下文是一组键值对，在加密时绑定到密文。解密时必须提供相同的上下文，否则解密失败。这提供了额外的认证层——即使攻击者获得了密文和密钥访问权限，也需要知道正确的上下文才能解密。


小结
    

  • 静态加密基于 KMS 信封加密模型：CMK 加密数据密钥，数据密钥加密实际数据
    • 

  • S3 默认启用 SSE-S3 加密，合规场景推荐 SSE-KMS + 桶策略强制加密
    • 

  • S3 Bucket Key 将 KMS API 调用降低 99%，显著节省成本
    • 

  • RDS 加密在实例创建时配置，已创建的实例需通过快照迁移启用
    • 

  • DynamoDB 默认全表加密，支持客户管理密钥审计
    • 

  • EBS/EFS 加密性能影响 <5%，推荐设置账户级默认加密
    • 

  • 客户端加密（AWS Encryption SDK）提供端到端保护，云提供商无法解密
    • 

  • 加密上下文提供额外的认证层，增强密文安全性
