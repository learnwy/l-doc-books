传输数据加密

核心概念

传输数据加密（Encryption in Transit）保护数据在网络传输过程中的机密性和完整性。数据在客户端与服务器、服务与服务、以及跨区域之间传输时，如果未加密，可能被中间人（Man-in-the-Middle）攻击截获和篡改。TLS（Transport Layer Security）是传输加密的标准协议，几乎所有现代云服务都默认支持 TLS 1.2+。

在云环境中，传输加密需要关注三个层面：客户端到云服务（外部通信）、云服务之间（内部通信）、以及跨区域/跨云的数据传输。每个层面的威胁模型和加密策略不同。

TLS 证书管理
TLS 证书是传输加密的基础。AWS Certificate Manager（ACM）提供免费的公共 TLS 证书，自动续期，与 CloudFront、ALB、API Gateway 等服务无缝集成。


ACM 公共证书：ACM 签发的公共证书由 Amazon Trust Services CA 签发，受所有主流浏览器信任。支持域名验证（DNS 验证或邮件验证），DNS 验证推荐使用 Route 53 自动配置。证书自动在到期前 60 天续期。


ACM 私有证书：通过 AWS Private CA 签发内部使用的 TLS 证书。适用于服务间 mTLS、内部 API 加密、IoT 设备认证。Private CA 支持完整的 PKI 层次结构（根 CA → 中间 CA → 终端实体证书）。


import { ACMClient, RequestCertificateCommand, DescribeCertificateCommand } from '@aws-sdk/client-acm';

const acm = new ACMClient({});

const cert = await acm.send(
  new RequestCertificateCommand({
    DomainName: 'api.example.com',
    SubjectAlternativeNames: ['*.api.example.com'],
    ValidationMethod: 'DNS',
    KeyAlgorithm: 'EC_prime256v1',
  }),
);

const describe = await acm.send(
  new DescribeCertificateCommand({
    CertificateArn: cert.CertificateArn,
  }),
);

推荐使用 ECDSA P-256（EC_prime256v1）：安全强度等同 RSA 3072，但 TLS 握手性能显著优于 RSA，证书体积更小。


TLS 配置与安全策略
TLS 版本控制：TLS 1.0 和 1.1 已被认定为不安全（存在 BEAST、POODLE 等已知漏洞）。AWS 服务和所有现代部署应仅允许 TLS 1.2 和 TLS 1.3。


CloudFront 安全策略：CloudFront 通过安全策略（Security Policy）控制支持的 TLS 版本和密码套件。推荐使用 TLSv1.2_2021 或更新的策略。


ALB 安全策略：ALB 的 HTTPS 监听器关联安全策略，定义支持的 TLS 版本和密码套件。推荐使用 ELBSecurityPolicy-TLS13-1-2-2021-06（支持 TLS 1.3 + TLS 1.2）。


TLS 1.3 相比 TLS 1.2 的改进：握手从 2-RTT 降至 1-RTT（0-RTT 可选）、移除不安全的密码套件（RC4、3DES、CBC）、前向保密（Forward Secrecy）成为必须、握手过程部分加密（保护证书信息）。

服务间 mTLS
双向 TLS（Mutual TLS, mTLS）要求通信双方互相验证证书，实现服务间的零信任认证。在标准 TLS 中，只有服务端提供证书，客户端验证服务端身份。mTLS 中，客户端也提供证书，服务端验证客户端身份。


AWS App Mesh + mTLS：App Mesh 作为服务网格控制面，Envoy 代理作为数据面。App Mesh 与 AWS Private CA 集成，自动为每个服务签发和轮换 mTLS 证书。服务间通信自动使用 mTLS，应用代码无需修改。


Kubernetes + Istio mTLS：Istio 的 PeerAuthentication 策略控制 mTLS 模式（STRICT 强制 mTLS、PERMISSIVE 兼容明文）。Istio 的 Citadel 组件自动签发和轮换 SPIFFE X.509 证书。


apiVersion: security.istio.io/v1beta1
kind: PeerAuthentication
metadata:
  name: default
  namespace: production
spec:
  mtls:
    mode: STRICT

---
apiVersion: security.istio.io/v1beta1
kind: AuthorizationPolicy
metadata:
  name: allow-orders-service
  namespace: production
spec:
  selector:
    matchLabels:
      app: payment-service

        - source:
            principals:
              - cluster.local/ns/production/sa/orders-service

VPC 内部与跨区域传输安全
VPC 内部流量：默认情况下，同一 VPC 内的流量不加密。对于高安全要求的场景（如金融、医疗），即使在 VPC 内部也应启用传输加密。Nitro 系统（新一代 EC2 实例）支持自动加密同 VPC 内的流量。


VPC Peering 与 Transit Gateway：跨 VPC 的流量在 AWS 骨干网络传输，自动加密（AWS 网络层加密）。Transit Gateway 汇聚多个 VPC 的流量，支持跨区域对等连接，流量在 AWS 全球网络上加密传输。


Site-to-Site VPN：连接本地数据中心和 AWS VPC。使用 IPsec 隧道加密（AES-256-GCM），支持 IKEv2 密钥交换。每条 VPN 连接包含两条冗余隧道，确保高可用。


AWS Direct Connect + MACsec：Direct Connect 提供专用物理连接，MACsec（IEEE 802.1AE）在链路层加密流量。适用于需要高带宽（1Gbps-100Gbps）和低延迟的场景，同时保证传输安全。

小结
    

  • TLS 1.2 是最低要求，推荐 TLS 1.3（1-RTT 握手、强制前向保密）
    • 

  • ACM 提供免费公共 TLS 证书，自动续期，推荐 ECDSA P-256 密钥
    • 

  • CloudFront 和 ALB 通过安全策略控制 TLS 版本和密码套件
    • 

  • mTLS 实现服务间零信任认证，App Mesh/Istio 自动管理证书
    • 

  • VPC 内部流量默认不加密，Nitro 实例支持自动加密
    • 

  • 跨区域传输通过 VPN（IPsec）或 Direct Connect（MACsec）加密
    • 

  • 数据库连接必须启用 TLS，使用强制 SSL 策略
