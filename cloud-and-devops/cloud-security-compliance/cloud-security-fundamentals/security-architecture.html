云安全架构设计

核心概念

云安全架构设计是将安全原则系统化地嵌入到云基础设施和应用架构中的实践。好的安全架构不是事后的补救措施，而是从设计阶段就将安全作为核心约束条件。云安全架构的核心原则包括：纵深防御（Defense in Depth）、最小权限（Least Privilege）、零信任（Zero Trust）、安全默认（Secure by Default）和失败安全（Fail-Safe）。

纵深防御是最重要的安全架构原则——通过在多个层次部署安全控制，确保单一层次的失败不会导致整体安全崩溃。在云环境中，纵深防御体现在网络层（VPC、安全组、WAF）、身份层（IAM、MFA）、数据层（加密、分类）和应用层（输入验证、依赖扫描）的多层防护。

网络安全架构
网络安全是云安全架构的基础层。VPC（Virtual Private Cloud）提供了逻辑隔离的网络环境，子网划分实现了不同安全级别的工作负载隔离。


多层子网架构是推荐的网络设计模式：


公有子网（Public Subnet）：放置需要直接面向互联网的组件——Application Load Balancer、NAT Gateway、Bastion Host。通过 Internet Gateway 访问公网。


私有子网（Private Subnet）：放置应用服务器（EC2、ECS、Lambda）。不直接暴露到互联网，通过 NAT Gateway 访问公网（出站）。从公网到私有子网的入站流量必须经过 ALB。


数据子网（Data Subnet）：放置数据库（RDS、ElastiCache、DynamoDB VPC Endpoint）。完全隔离，不能访问公网，只接受来自私有子网的连接。


安全组策略：遵循"最小开放"原则。每个资源类型定义独立的安全组，只允许已知的合法流量。

VPC Flow Logs 记录网络流量元数据（源/目标 IP、端口、协议、字节数），发送到 CloudWatch Logs 或 S3。用于安全审计、异常流量检测和网络调试。


AWS PrivateLink（VPC Endpoint）允许在不经过公网的情况下访问 AWS 服务。消除了数据在公网传输的风险，同时避免 NAT Gateway 的数据传输费用。


多账户安全策略
AWS 最佳实践推荐使用多账户架构隔离不同环境和工作负载。AWS Organizations 提供了集中管理多账户的框架，Service Control Policies（SCP）在组织级别设置权限边界。


AWS Landing Zone 架构定义了标准的多账户结构：


    

  • 管理账户（Management Account）：Organizations 根账户，仅用于账户管理和计费
    • 

  • 安全账户（Security Account）：集中日志（CloudTrail）、安全监控（GuardDuty、Security Hub）
    • 

  • 共享服务账户（Shared Services）：DNS、VPC Transit Gateway、目录服务
    • 

  • 网络账户（Network Account）：集中管理 VPC、VPN、Direct Connect
    • 

  • 工作负载账户（Workload Accounts）：按环境或团队隔离——dev、staging、production
    •

AWS Control Tower 自动化了 Landing Zone 的部署和管理。它预配置了安全基线（必要的 Guardrails）、账户工厂（Account Factory）支持自助式新账户创建、并持续检测合规偏差。


安全自动化与 DevSecOps
安全自动化（Security Automation）是实现"安全左移"（Shift Left Security）的关键。将安全检查嵌入到 CI/CD 管道中，在代码提交和部署之前发现和修复安全问题。

Infrastructure as Code（IaC）安全扫描：Terraform、CloudFormation 模板在部署前通过工具扫描安全配置。Checkov、tfsec、cfn-nag 等工具检查 IaC 中的安全反模式（如未加密的 S3 桶、公开的安全组、缺失的日志配置）。


安全事件自动响应：将 GuardDuty 发现通过 EventBridge 路由到 Lambda 函数，自动执行响应操作。高严重度事件（如 Root 账户使用、加密挖矿）触发即时响应（隔离实例、撤销密钥）。中低严重度事件创建工单并通知安全团队。


import { EC2Client, ModifyInstanceAttributeCommand } from '@aws-sdk/client-ec2';
import { SNSClient, PublishCommand } from '@aws-sdk/client-sns';

interface GuardDutyFinding {
  detail: {
    severity: number;
    type: string;
    resource: {
      instanceDetails?: { instanceId: string };
    };
  };
}

const ec2 = new EC2Client({});
const sns = new SNSClient({});

export const handler = async (event: GuardDutyFinding) => {
  const { severity, type } = event.detail;
  const instanceId = event.detail.resource.instanceDetails?.instanceId;

  if (severity >= 7 && instanceId) {
    await ec2.send(
      new ModifyInstanceAttributeCommand({
        InstanceId: instanceId,
        Groups: ['sg-quarantine'],
      }),
    );
  }

  await sns.send(
    new PublishCommand({
      TopicArn: process.env.SECURITY_TOPIC_ARN,
      Subject: `[Security] ${type}`,
      Message: JSON.stringify(event.detail, null, 2),
    }),
  );
};
