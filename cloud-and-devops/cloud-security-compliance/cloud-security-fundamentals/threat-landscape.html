云安全威胁全景

核心概念

云环境的威胁全景（Threat Landscape）与传统数据中心有显著差异。云原生架构的动态性、API 驱动的管理模型、以及多租户共享基础设施的特性，催生了一系列新型攻击向量。理解这些威胁是制定有效防御策略的前提。

MITRE ATT&CK Cloud Matrix 是系统化理解云安全威胁的权威框架。它将攻击链分为初始访问（Initial Access）、执行（Execution）、持久化（Persistence）、权限提升（Privilege Escalation）、防御规避（Defense Evasion）、凭证访问（Credential Access）、发现（Discovery）、横向移动（Lateral Movement）、收集（Collection）、影响（Impact）十个阶段。

凭证泄露与 API 安全
凭证泄露是云安全事件的头号原因。据统计，超过 80% 的云安全事件与凭证泄露或配置错误有关。常见的凭证泄露路径包括：


代码仓库泄露：开发者将 AWS Access Key、数据库密码等敏感信息误提交到 Git 仓库。即使事后删除，Git 历史中仍保留这些凭证。自动化扫描工具（如 truffleHog、GitLeaks）可以在数分钟内扫描公开仓库，攻击者通常在凭证暴露后 5 分钟内即发起攻击。


环境变量泄露：CI/CD 管道、容器编排系统和日志系统中的环境变量可能包含敏感信息。Docker 镜像层中的 ENV 指令、Kubernetes ConfigMap 中的明文密码、Lambda 环境变量的日志输出都是高风险泄露点。


元数据服务攻击：EC2 Instance Metadata Service（IMDS）允许实例查询自身的 IAM 角色临时凭证。如果 Web 应用存在 SSRF（Server-Side Request Forgery）漏洞，攻击者可以通过 http://169.254.169.254/latest/meta-data/iam/security-credentials/ 获取 IAM 临时凭证。IMDSv2（要求使用 PUT 请求获取 Token）可以缓解此风险。


import { STSClient, GetCallerIdentityCommand } from '@aws-sdk/client-sts';
import { IAMClient, ListAccessKeysCommand, GetAccessKeyLastUsedCommand } from '@aws-sdk/client-iam';

const iam = new IAMClient({});

const listKeys = async (userName: string) => {
  const response = await iam.send(new ListAccessKeysCommand({ UserName: userName }));

  for (const key of response.AccessKeyMetadata ?? []) {
    const lastUsed = await iam.send(new GetAccessKeyLastUsedCommand({ AccessKeyId: key.AccessKeyId }));

    const daysSinceUse = lastUsed.AccessKeyLastUsed?.LastUsedDate
      ? Math.floor((Date.now() - lastUsed.AccessKeyLastUsed.LastUsedDate.getTime()) / 86400000)
      : Infinity;

    if (daysSinceUse > 90) {
      console.warn(`Key ${key.AccessKeyId} unused for ${daysSinceUse} days - should be rotated`);
    }
  }
};

配置错误与数据泄露
云配置错误（Misconfiguration）是数据泄露的第二大原因。S3 存储桶公开访问、数据库公开到互联网、安全组允许 0.0.0.0/0 入站流量——这些看似低级的错误每年导致数十亿条记录泄露。


S3 安全是配置错误的重灾区。2017-2020 年间，多起重大数据泄露事件源于 S3 存储桶配置为公开访问。AWS 已经引入多层防护：S3 Block Public Access（账户级和桶级）、S3 Access Analyzer（分析外部共享）、S3 Object Lock（防止删除和修改）。


安全组（Security Group） 的配置直接影响网络层安全。常见错误包括：允许 0.0.0.0/0 的 SSH（22）或 RDP（3389）入站规则、数据库端口（3306/5432）暴露到公网、安全组规则过于宽松（允许所有端口）。


自动化配置检测：AWS Config Rules 可以持续监控资源配置，检测偏离安全基线的变更。预定义规则覆盖 S3、安全组、IAM、加密等常见安全要求。自定义规则使用 Lambda 函数实现特定的合规检查。

供应链攻击与容器安全
供应链攻击（Supply Chain Attack）是云原生环境中快速增长的威胁类别。攻击者通过入侵开源依赖、容器镜像或 CI/CD 管道，将恶意代码注入到合法的软件交付过程中。


依赖投毒：npm、PyPI 等包管理器中的恶意包冒充合法包名（Typosquatting）或注入后门。2021 年的 ua-parser-js 事件影响了数百万下载者。防御手段包括使用 npm audit、Snyk、Socket 等扫描工具，以及锁定依赖版本。


容器镜像安全：Docker Hub 上的公开镜像可能包含已知漏洞或恶意软件。使用经过验证的基础镜像（AWS ECR Public Gallery、Google Distroless）、在 CI/CD 中集成镜像扫描（Trivy、Snyk Container、ECR 扫描）、使用多阶段构建最小化镜像攻击面。


CI/CD 管道攻击：攻击者入侵 CI/CD 系统（GitHub Actions、Jenkins）后，可以修改构建脚本注入恶意代码、窃取部署凭证、或在构建产物中植入后门。防御措施包括：严格限制 CI/CD 系统的权限、使用 OIDC 联邦认证（避免长期密钥）、签名构建产物（Sigstore/Cosign）。


SBOM（Software Bill of Materials） 是供应链安全的关键实践——记录软件中使用的所有组件及其版本。当新的 CVE 发布时，可以快速定位受影响的系统。


横向移动与权限提升
攻击者获取初始访问后，通常会尝试在云环境中横向移动（Lateral Movement）和权限提升（Privilege Escalation），以扩大控制范围。


IAM 权限提升路径：攻击者利用过宽的 IAM 策略，通过一系列 API 调用逐步提升权限。典型路径包括：


    

  • iam:PassRole + lambda:CreateFunction：创建新 Lambda 并关联高权限角色
    • 

  • iam:CreatePolicyVersion：为现有策略创建新版本，添加管理员权限
    • 

  • sts:AssumeRole：假冒其他角色获取更高权限
    • 

  • ec2:RunInstances + Instance Profile：创建 EC2 并关联高权限实例角色
    • 



跨账户横向移动：在多账户架构中，攻击者可能利用跨账户信任关系从低权限账户移动到高权限账户。防御措施包括：限制 sts:AssumeRole 的条件（ExternalId、MFA）、使用 SCP 限制跨账户操作、监控 CloudTrail 中的 AssumeRole 事件。


检测与响应：AWS GuardDuty 使用机器学习检测异常行为——异常 API 调用模式、异地登录、加密挖矿活动、异常数据传输。GuardDuty 的发现（Finding）可以触发 Lambda 自动响应（如隔离实例、撤销密钥、通知安全团队）。

小结
    

  • 云安全威胁以凭证泄露和配置错误为主，占事件的 80% 以上
    • 

  • MITRE ATT&CK Cloud Matrix 提供系统化的威胁分析框架
    • 

  • 凭证防护：消除长期密钥、强制 IMDSv2、Pre-commit 扫描、自动轮换
    • 

  • 配置安全：AWS Config Rules 持续检测、S3 Block Public Access、安全组最小化
    • 

  • 供应链安全：依赖扫描、镜像签名、SBOM、CI/CD 最小权限
    • 

  • IAM 权限提升是攻击者获取初始访问后的主要目标，需持续监控
    • 

  • GuardDuty + CloudTrail + Security Hub 构成云安全检测与响应的核心
    •
