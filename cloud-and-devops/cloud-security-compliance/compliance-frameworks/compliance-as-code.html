合规即代码

核心概念

合规即代码（Compliance as Code, CaC）是将合规要求编码为可执行的策略规则，通过自动化工具持续验证云基础设施和应用的合规状态。传统的合规管理依赖人工检查和定期审计，周期长、成本高、覆盖面有限。CaC 将合规检查嵌入到 CI/CD 管道和运行时环境中，实现实时、持续、全覆盖的合规验证。

CaC 的核心理念是"策略即代码"（Policy as Code）——安全策略不再是 Word 文档中的文字描述，而是可以被版本控制、测试、部署和自动执行的代码。当基础设施变更违反策略时，系统自动阻止部署或触发修复。

AWS Config 与合规规则
AWS Config 是 AWS 原生的配置审计和合规评估服务。Config 持续记录 AWS 资源的配置变更，并通过 Config Rules 评估资源配置是否符合预定义的安全基线。


Config Rules 类型：


AWS 托管规则：AWS 预建的 300+ 条合规规则，覆盖 IAM、S3、EC2、RDS、Lambda 等常见服务的安全最佳实践。开箱即用，无需编写代码。


自定义规则：使用 Lambda 函数实现组织特定的合规检查。当资源配置变更时触发 Lambda 函数评估，返回 COMPLIANT 或 NON_COMPLIANT。


import type { ConfigServiceClient } from '@aws-sdk/client-config-service';

interface ConfigEvent {
  invokingEvent: string;
  ruleParameters: string;
  resultToken: string;
}

interface ConfigurationItem {
  resourceType: string;
  resourceId: string;
  configuration: Record<string, unknown>;
}

export const handler = async (event: ConfigEvent) => {
  const invokingEvent = JSON.parse(event.invokingEvent);
  const configItem: ConfigurationItem = invokingEvent.configurationItem;

  let compliance = 'COMPLIANT';

  if (configItem.resourceType === 'AWS::S3::Bucket') {
    const encryption = configItem.configuration.serverSideEncryptionConfiguration;
    if (!encryption) {
      compliance = 'NON_COMPLIANT';
    }
  }

  return {
    compliance,
    annotation: compliance === 'NON_COMPLIANT' ? 'S3 bucket does not have encryption enabled' : undefined,
  };
};

自动修复：Config Rules 检测到不合规资源后，可以通过 SSM Automation 自动修复。例如：检测到未加密的 EBS 卷 → 自动创建快照 → 从快照创建加密卷 → 替换原卷。


Open Policy Agent 与策略引擎
Open Policy Agent（OPA）是 CNCF 毕业项目，提供通用的策略引擎。OPA 使用 Rego 语言编写策略，可以评估任意结构化数据（JSON/YAML）。在云安全领域，OPA 用于 IaC 安全扫描、Kubernetes 准入控制和 API 授权。


Rego 策略语言示例——检查 Terraform 配置中 S3 桶是否启用加密：


package terraform.s3

deny[msg] {
    resource := input.resource.aws_s3_bucket[name]
    not resource.server_side_encryption_configuration
    msg := sprintf("S3 bucket '%s' must have encryption enabled", [name])
}

deny[msg] {
    resource := input.resource.aws_s3_bucket[name]
    not resource.versioning[_].enabled == true
    msg := sprintf("S3 bucket '%s' must have versioning enabled", [name])
}

deny[msg] {
    resource := input.resource.aws_s3_bucket[name]
    resource.acl == "public-read"
    msg := sprintf("S3 bucket '%s' must not be publicly readable", [name])
}
Kubernetes 准入控制：OPA Gatekeeper 作为 Kubernetes 的准入 Webhook，在资源创建/更新时评估策略。拒绝不合规的资源（如使用 latest 标签的容器、未设置资源限制的 Pod、以 root 运行的容器）。

IaC 安全扫描
Infrastructure as Code（IaC）安全扫描在基础设施部署之前检测安全配置错误。这是"安全左移"（Shift Left）的核心实践——在代码阶段而非运行时发现问题，修复成本最低。


Checkov 是最流行的 IaC 安全扫描工具，支持 Terraform、CloudFormation、Kubernetes、Dockerfile 和 Serverless Framework。内置 1000+ 检查规则，覆盖 AWS、Azure、GCP 的安全最佳实践。


CI/CD 集成示例（GitHub Actions）：


name: Security Scan
on: [pull_request]

jobs:
  iac-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Run Checkov
        uses: bridgecrewio/checkov-action@v12
        with:
          directory: terraform/
          framework: terraform
          soft_fail: false
          output_format: sarif

      - name: Run tfsec
        uses: aquasecurity/tfsec-action@v1
        with:
          working_directory: terraform/
          soft_fail: false

      - name: Run Trivy Config
        uses: aquasecurity/trivy-action@master
        with:
          scan-type: config
          scan-ref: terraform/
          exit-code: 1

持续合规监控
合规不是一次性的项目，而是持续的过程。持续合规监控确保基础设施在整个生命周期中保持合规状态。


AWS Security Hub 是安全态势的集中视图。它聚合来自 GuardDuty、Inspector、Macie、Config、Firewall Manager 等服务的安全发现。内置安全标准（CIS AWS Foundations、AWS Foundational Security Best Practices、PCI DSS）提供合规分数和趋势。

GitOps 合规流程：将合规策略存储在 Git 仓库中，通过 Pull Request 审批策略变更。CI/CD 管道自动部署策略到 Config Rules / OPA / Gatekeeper。任何策略变更都有完整的审计追踪（Git 历史 + PR 审批记录）。


小结
    

  • 合规即代码将安全策略编码为可自动执行的规则，实现实时持续合规
    • 

  • AWS Config + Conformance Pack 提供 AWS 原生的合规评估和自动修复

  • OPA/Rego 是通用策略引擎，支持 IaC 扫描和 Kubernetes 准入控制
    • 

  • Checkov/tfsec 在 CI/CD 中扫描 IaC 配置，阻止不安全的部署
    • 

  • Security Hub 聚合安全发现，提供 CIS/PCI DSS 合规分数
    • 

  • 合规度量：合规率 >99%、MTTR <24h、关键发现数 = 0
    •
