Code Review 实践

Code Review 的价值

Code Review（代码审查） 是软件工程中最有效的质量保障手段之一。Google 的工程实践表明，Code Review 不仅能发现缺陷，更重要的是促进知识共享和代码一致性。

价值维度 说明
缺陷发现 在合并前发现逻辑错误和边界情况
知识共享 团队成员了解代码库的各个部分
代码一致性 确保风格和架构模式的统一
导师作用 资深成员指导新成员的成长
文档效果 PR 描述和讨论成为变更的永久记录

Review Checklist

结构化的检查清单能确保审查的全面性和一致性：

检查维度 检查项
正确性 逻辑是否正确，边界条件是否处理
安全性 是否有注入、泄露风险
性能 是否有 N+1 查询、不必要的循环
可读性 命名是否清晰，结构是否合理
测试 是否有充分的测试覆盖
文档 公共 API 是否有文档说明
向后兼容 是否破坏了已有接口 
# .github/pull_request_template.md
## Review Checklist
- [ ] 代码逻辑正确，边界条件已处理
- [ ] 无安全风险（注入、泄露）
- [ ] 性能可接受
- [ ] 测试充分
- [ ] 命名清晰，可读性好

Conventional Commits

Conventional Commits（约定式提交） 为提交消息定义了结构化格式，便于自动化生成 CHANGELOG 和语义化版本号：

<type>(<scope>): <description>

[optional body]

[optional footer(s)]
类型 说明 版本影响
feat 新功能 minor 版本
fix Bug 修复 patch 版本
docs 文档变更 无
style 代码风格 无
refactor 重构 无
perf 性能优化 patch 版本
test 测试相关 无
chore 构建/工具变更 无
ci CI 配置变更 无 
git commit -m "feat(auth): add OAuth2 login support"
git commit -m "fix(parser): handle empty input gracefully"
git commit -m "docs(readme): update installation guide"

# Breaking Change
git commit -m "feat(api)!: change response format to JSON:API"

强制执行 Conventional Commits：

# 使用 commitlint
npm install --save-dev @commitlint/cli @commitlint/config-conventional

# commitlint.config.js
# module.exports = { extends: ['@commitlint/config-conventional'] };

# 配合 Husky pre-commit hook
npx husky add .husky/commit-msg 'npx --no -- commitlint --edit "$1"'

提交签名

签名提交（Signed Commits） 使用 GPG 或 SSH 密钥证明提交确实由声称的作者创建：

gpg --full-generate-key
gpg --list-secret-keys --keyid-format=long

git config --global user.signingkey <KEY_ID>
git config --global commit.gpgsign true

git commit -S -m "feat: signed commit"
git log --show-signature

SSH 签名（Git 2.34+）：

git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519.pub
git config --global commit.gpgsign true
签名方式 优点 缺点
GPG 标准方案，广泛支持 密钥管理较复杂
SSH 简单，复用已有 SSH 密钥 需要 Git 2.34+ 


提示： GitHub 和 GitLab 都支持在 commit 旁显示 "Verified" 标记。在安全敏感项目中，建议强制要求所有提交必须签名。

git config --global credential.helper store

git config --global credential.helper cache --timeout=3600

小结
    

  • Code Review 是质量保障和知识共享的核心实践，结构化 Checklist 确保审查全面性
    • 

  • Conventional Commits 标准化提交消息，支持自动生成 CHANGELOG 和语义化版本
    • 

  • GPG/SSH 签名验证提交身份，在安全敏感项目中应强制启用
    • 

  • Review 规范应明确 Reviewer 数量、响应时间和反馈方式
    • 

  • 使用 SSH Key 或系统凭证管理器安全地管理 Git 认证信息
    •
