冲突解决策略

三路合并原理

Git 的合并冲突解决基于三路合并（Three-Way Merge） 算法。它比较三个版本：Base（共同祖先）、Ours（当前分支） 和 Theirs（目标分支）。

Base
Ours
Theirs

A

B（自动合并）




双方不同修改
A
B

冲突





git merge feature
# 查看冲突文件
git diff --name-only --diff-filter=U


冲突标记解读
<<<<<<< HEAD
echo "ours: current branch version"
||||||| merged common ancestors
echo "base: original version"
=======
echo "theirs: incoming branch version"
>>>>>>> feature
开启 diff3 风格查看 base 版本：


git config --global merge.conflictstyle diff3
| 标记区域               | 含义                   |
| ---------------------- | ---------------------- | --- | --- | --- | --- | --- | ------------ | -------------------- |
| <<<<<<< HEAD 到    |                        |     |     |     |     |     |            | Ours（当前分支版本） |
|                      |                        |     |     |     |     |     |到======= | Base（共同祖先版本） |
| ======= 到 >>>>>>> | Theirs（传入分支版本） |




提示： 强烈推荐启用 diff3 冲突风格，有了 Base 版本的参照，冲突解决会直观很多。






Ours 与 Theirs 策略
当确定某一方的版本完全正确时，可以使用策略性解决：


git merge -X ours feature
git merge -X theirs feature

git checkout --ours -- src/config.sh
git checkout --theirs -- src/config.sh
git add src/config.sh




命令
冲突解决方式





-X ours
冲突时自动采用当前分支版本




-X theirs
冲突时自动采用传入分支版本




-s ours
完全忽略对方的所有更改




--ours (文件级)
单个文件采用当前分支版本




--theirs (文件级)
单个文件采用传入分支版本







提示： -X ours 和 -s ours 完全不同。-X ours 仅在冲突时选择 ours，非冲突部分正常合并；-s ours 完全丢弃对方的所有更改。






Rerere 自动记忆
Rerere（Reuse Recorded Resolution） 让 Git 记住你对冲突的解决方案，当相同冲突再次出现时自动应用。


git config --global rerere.enabled true

ls .git/rr-cache/

git rerere status
git rerere diff

git rerere forget -- src/config.sh
Rerere 特别有用的场景：

说明





频繁 rebase 的长期分支
每次 rebase 可能遇到相同冲突




反复测试合并

多分支维护
相同修复需要合并到多个版本分支

预防冲突的策略




策略
说明





频繁同步主分支
定期 rebase 或 merge 主分支到功能分支




小步提交
减少单次提交的变更范围




模块化代码
减少多人修改同一文件的概率

明确文件归属，减少意外修改




沟通协调
修改公共文件前通知相关人员





# .github/CODEOWNERS

小结
    

  • 三路合并比较 Base、Ours、Theirs 三个版本，启用 diff3 风格能显著提升冲突解决效率
    • 

  • -X ours/theirs 在冲突时自动选择一方，但非冲突部分仍正常合并
    • 

  • Rerere 记住冲突解决方案并自动复用，对频繁 rebase 的场景价值巨大
    • 

  • 配置趁手的 merge tool（如 VS Code 三面板）可以大幅提升解决复杂冲突的效率
    • 

  • 预防胜于解决：频繁同步主分支、模块化代码和 CODEOWNERS 是减少冲突的最佳实践
    •
