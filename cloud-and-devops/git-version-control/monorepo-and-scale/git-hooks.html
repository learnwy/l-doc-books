Git Hooks 钩子机制

什么是 Git Hooks

Git Hooks（钩子） 是 Git 在特定事件发生时自动执行的脚本。它们存储在 .git/hooks/ 目录下，可以在提交、推送等操作前后运行自定义逻辑。

ls .git/hooks/
# applypatch-msg.sample  post-update.sample     pre-push.sample
# commit-msg.sample      pre-applypatch.sample  pre-rebase.sample
# ...

Hook 类型

Hook 名称 触发时机 常见用途
pre-commit commit 前 代码风格检查、lint
prepare-commit-msg 编辑器打开前 自动填充提交消息模板
commit-msg 提交消息写入后 验证提交消息格式
post-commit commit 完成后 通知、统计
pre-push push 前 运行测试、安全扫描
pre-rebase rebase 前 阻止在公共分支上 rebase
post-merge merge 完成后 安装依赖、清理缓存
post-checkout checkout 完成后 环境切换、依赖更新 


手动创建 Hook
cat > .git/hooks/pre-commit << 'EOF'
#!/bin/bash
echo "Running pre-commit checks..."

if git diff --cached --name-only | grep -q '\.sh$'; then
    echo "Checking shell scripts..."
    for file in $(git diff --cached --name-only --diff-filter=ACM | grep '\.sh$'); do
        shellcheck "$file"
        if [ $? -ne 0 ]; then
            echo "ShellCheck failed for $file"
            exit 1
        fi
    done
fi

echo "Pre-commit checks passed!"
EOF

chmod +x .git/hooks/pre-commit
commit-msg hook 验证 Conventional Commits：


cat > .git/hooks/commit-msg << 'EOF'
#!/bin/bash
commit_regex='^(feat|fix|docs|style|refactor|perf|test|chore|ci)(\(.+\))?!?: .{1,100}'
if ! grep -qE "$commit_regex" "$1"; then
    echo "ERROR: Commit message does not follow Conventional Commits format."
    echo "Expected: <type>(<scope>): <description>"
    exit 1
fi
EOF

chmod +x .git/hooks/commit-msg


提示： .git/hooks/ 不会被 Git 跟踪，因此手动创建的 hooks 无法在团队间共享。这正是 Husky 和 Lefthook 等工具存在的原因。






Husky
Husky 是 JavaScript 生态中最流行的 Git Hooks 管理工具，将 hooks 脚本纳入版本控制：


npm install --save-dev husky
npx husky init

# .husky/pre-commit
npx lint-staged

# .husky/commit-msg
npx --no -- commitlint --edit "$1"
配合 lint-staged 只检查暂存的文件：


npm install --save-dev lint-staged
# package.json
# {
#   "lint-staged": {
#     "*.{js,ts}": ["eslint --fix", "prettier --write"],
#     "*.sh": ["shellcheck"],
#     "*.md": ["prettier --write"]
#   }
# }


Lefthook
Lefthook 是一个快速、跨语言的 Git Hooks 管理器，使用 Go 编写，比 Husky 更快：


brew install lefthook
lefthook install
# lefthook.yml
pre-commit:
  parallel: true
  commands:
    lint:
      glob: "*.{js,ts}"
      run: npx eslint {staged_files}
    format:
      glob: "*.{js,ts,json,md}"
      run: npx prettier --check {staged_files}
    shellcheck:
      glob: "*.sh"
      run: shellcheck {staged_files}

commit-msg:
  commands:
    validate:
      run: 'echo "$1" | grep -qE "^(feat|fix|docs|style|refactor|perf|test|chore|ci)"'

跳过 Hooks
紧急情况下可以临时跳过 hooks：


git commit --no-verify -m "hotfix: urgent production fix"
git push --no-verify

LEFTHOOK=0 git commit -m "skip hooks"
HUSKY=0 git commit -m "skip hooks"


提示： --no-verify 应仅用于紧急情况。如果团队成员频繁使用此选项，说明 hooks 可能过重或有误报，需要优化。

小结
    

  • Git Hooks 在特定事件时自动执行脚本，是本地代码质量保障的第一道防线
    • 

  • pre-commit 用于代码检查，commit-msg 用于消息格式验证，pre-push 用于测试
    • 

  • Husky 适合 JavaScript 生态，Lefthook 更快且跨语言，根据项目技术栈选择
    • 

  • 配合 lint-staged 只检查暂存文件，避免全量检查带来的性能问题
    • 

  • Hooks 应保持快速执行（秒级），耗时的检查应放到 CI 而非本地 hooks 中
    •
