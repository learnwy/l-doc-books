性能调优

Git 性能瓶颈

大型仓库（文件数超过 10 万或历史超过 10 万 commit）中，常见的性能瓶颈包括：

瓶颈 表现 影响操作
index 文件过大 status/add 变慢 日常开发
Pack 文件碎片 clone/fetch 变慢 网络传输
松散对象过多 磁盘占用膨胀 存储
工作目录文件多 checkout/status 变慢 分支切换
历史过深 log/blame 变慢 历史查询 
git count-objects -vH

time git status

git rev-list --count HEAD
find . -not -path './.git/*' -type f | wc -l

Index 优化

Index（索引） 文件（.git/index）记录了工作目录中所有跟踪文件的状态。文件越多，index 读写越慢。

ls -lh .git/index

git update-index --index-version 4
Index 版本 特点
v2 默认版本
v3 支持扩展
v4 路径名前缀压缩，更小更快

Fsmonitor 文件系统监控

Fsmonitor 使用操作系统的文件系统事件通知（如 macOS 的 FSEvents、Linux 的 inotify）来加速 git status，避免遍历整个工作目录：

git config core.fsmonitor true
git config core.untrackedcache true

brew install watchman
git config core.fsmonitor "$(which watchman)"
配置 作用
core.fsmonitor 启用文件系统监控
core.untrackedcache 缓存未跟踪文件列表
feature.manyFiles 一键开启大仓库优化 
git config feature.manyFiles true

提示： feature.manyFiles 是 Git 提供的大仓库一键优化开关，会自动启用 fsmonitor、untrackedcache 等性能特性。

GC 与 Pack 优化

git gc（Garbage Collection） 清理不可达对象、压缩松散对象为 Pack 文件：

git gc
git gc --aggressive
git gc --auto

git config gc.auto 256
git config gc.autoPackLimit 50
Pack 文件手动优化：


git repack -a -d -f --depth=250 --window=250

git prune

git maintenance start

Git Maintenance 自动维护
Git 2.29+ 引入了 maintenance 命令，自动化后台维护任务：


git maintenance start

git maintenance run --task=gc
git maintenance run --task=commit-graph
git maintenance run --task=prefetch

频率
作用

每小时
更新 commit 图缓存

清理松散对象

每天
增量重打包




gc
每周
完整垃圾回收







Commit Graph 加速
Commit Graph 是一个预计算的 commit 元数据缓存，显著加速 git log、git merge-base 等操作：


git commit-graph write --reachable

git config core.commitGraph true

git commit-graph verify

大仓库配置模板
git config core.fsmonitor true
git config core.untrackedcache true
git config core.commitGraph true
git config gc.auto 256
git config fetch.writeCommitGraph true
git config feature.manyFiles true

git maintenance start

小结
    

  • Index v4 和 untrackedcache 加速工作目录状态检查
    • 

  • Fsmonitor 利用系统文件事件通知避免全目录扫描，是大仓库 git status 的关键优化
    • 

  • git gc 和 repack 压缩对象，maintenance 实现自动化后台维护
    • 

  • Commit Graph 预计算提交元数据，将 log 和 merge-base 操作加速到毫秒级
    • 

  • 使用 feature.manyFiles=true 一键开启大仓库优化，配合 git maintenance start 实现自动维护
