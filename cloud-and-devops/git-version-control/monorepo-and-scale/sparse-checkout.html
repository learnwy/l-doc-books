稀疏检出与部分克隆

大仓库的挑战

当 Git 仓库包含数十万文件或数 GB 历史时，常规的 git clone 会耗时数分钟甚至更久。开发者通常只需要仓库的一小部分，完整克隆是对时间和磁盘的浪费。

问题 原因 解决方案
克隆时间长 下载完整历史和所有文件 partial-clone
磁盘占用大 包含不需要的历史和文件 shallow clone
checkout 慢 写入大量不需要的文件 sparse-checkout 


Shallow Clone 浅克隆
浅克隆（Shallow Clone） 只下载指定深度的提交历史：


git clone --depth 1 https://github.com/org/large-repo.git

git clone --depth 10 https://github.com/org/large-repo.git

git clone --shallow-since="2025-01-01" https://github.com/org/repo.git

git clone --single-branch --branch main --depth 1 https://github.com/org/repo.git
浅克隆的限制：

✅

提示： 浅克隆最适合 CI/CD 场景——只需要最新代码进行构建和测试，无需完整历史。






Partial Clone 部分克隆
部分克隆（Partial Clone） 允许按需下载 Git 对象，初始克隆时跳过大文件或 blob：


git clone --filter=blob:none https://github.com/org/repo.git

git clone --filter=blob:limit=1m https://github.com/org/repo.git

git clone --filter=tree:0 https://github.com/org/repo.git




过滤器
作用





blob:none
不下载任何 blob，按需获取




blob:limit=<size>
不下载超过指定大小的 blob




tree:0
不下载 tree 对象，按需获取





git rev-list --filter=blob:none --all --objects | wc -l


Sparse Checkout 稀疏检出
稀疏检出（Sparse Checkout） 只将仓库中指定的目录/文件检出到工作目录，其余文件不会出现在磁盘上：


git clone --no-checkout https://github.com/org/monorepo.git
cd monorepo
git sparse-checkout init --cone
git sparse-checkout set apps/my-app libs/shared
git checkout main
git sparse-checkout list

git sparse-checkout add docs/

git sparse-checkout disable




命令
作用





sparse-checkout init
初始化稀疏检出




--cone
使用 cone 模式（推荐）




sparse-checkout set
设置检出目录




sparse-checkout add
添加检出目录




sparse-checkout list
列出当前检出目录




sparse-checkout disable
禁用稀疏检出







提示： --cone 模式比传统的模式文件匹配更快，推荐始终使用 cone 模式。






组合使用
三种技术可以组合使用，实现最优的性能：


git clone \
  --filter=blob:none \
  --sparse \
  https://github.com/org/huge-monorepo.git

cd huge-monorepo
git sparse-checkout set apps/my-app libs/core

小结
    

  • Shallow Clone 限制历史深度，适合只需最新代码的 CI/CD 场景
    • 

  • Partial Clone 按需下载 Git 对象，首次克隆快但后续操作可能触发网络请求
    • 

  • Sparse Checkout 只检出需要的目录，是 Monorepo 开发的利器
    • 

  • 三种技术可以组合使用实现最优性能：--filter=blob:none --sparse 是日常开发推荐方案
    • 

  • 使用前确认服务端支持 Git Protocol v2 和部分克隆过滤器
    •
