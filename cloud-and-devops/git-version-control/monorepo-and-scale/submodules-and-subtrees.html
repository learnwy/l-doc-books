Git Submodule
子模块（Submodule） 在当前仓库中嵌入另一个 Git 仓库的引用，记录特定的 commit：


git submodule add https://github.com/org/lib.git libs/shared
git submodule init
git submodule update

git clone --recurse-submodules https://github.com/user/repo.git

git submodule update --remote
Submodule 的文件结构：


cat .gitmodules
# [submodule "libs/shared"]
#   path = libs/shared
#   url = https://github.com/org/lib.git

cat .git/config
git submodule status




操作
命令





添加子模块
git submodule add <url> <path>




初始化
git submodule init




更新到记录的版本
git submodule update




更新到远程最新
git submodule update --remote




递归克隆
git clone --recurse-submodules <url>




删除子模块
git submodule deinit <path> + git rm <path>







提示： Submodule 的最大痛点是容易忘记初始化和更新。使用 git clone --recurse-submodules 或配置 submodule.recurse=true 可以减少这类问题。






Git Subtree
子树（Subtree） 将外部仓库的内容直接合并到当前仓库的子目录中，不需要额外的 .gitmodules 配置：


git subtree add --prefix=libs/shared https://github.com/org/lib.git main --squash

git subtree pull --prefix=libs/shared https://github.com/org/lib.git main --squash

git subtree push --prefix=libs/shared https://github.com/org/lib.git main
git remote add shared-lib https://github.com/org/lib.git
git subtree add --prefix=libs/shared shared-lib main --squash
git subtree pull --prefix=libs/shared shared-lib main --squash

小结
    

  • Submodule 以引用方式嵌入外部仓库，保持历史独立性，适合松耦合的依赖管理
    • 

  • Subtree 将外部代码完整合并到主仓库，对使用者透明，但会增加仓库体积
    • 

  • Monorepo 支持原子提交和直接代码共享，但需要 Turborepo、Nx 等专用工具支持
    • 

  • Polyrepo 更简单，适合独立性强的项目，但跨仓库的代码共享和一致性维护成本高
    • 

  • 选择策略需综合考虑团队规模、代码耦合度、CI/CD 成熟度和权限需求
    •
