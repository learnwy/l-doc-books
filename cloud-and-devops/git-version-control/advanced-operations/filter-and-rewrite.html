历史重写

为什么需要重写历史

当仓库中不慎提交了敏感数据（Sensitive Data）（API 密钥、密码、证书）或大文件（二进制包、数据集），这些内容会永久存在于 Git 历史中，即使后续删除也不安全。仅靠 git rm 只能从当前版本移除文件，历史提交中的数据仍然可以被恢复。

场景 风险 解决方案
提交了 API 密钥 密钥泄露，安全风险 历史重写 + 轮换密钥
提交了大型二进制文件 仓库体积膨胀，克隆缓慢 历史重写 + Git LFS
错误的作者信息 贡献统计不准确 历史重写
需要拆分仓库 Monorepo 拆分为多个独立仓库 filter-repo

git filter-repo（推荐）

git-filter-repo 是 Git 官方推荐的历史重写工具，替代已废弃的 git filter-branch。它使用 Python 实现，速度比 filter-branch 快 10-100 倍。

pip install git-filter-repo

git filter-repo --analyze
cat .git/filter-repo/analysis/path-all-sizes.txt

删除敏感文件：

git filter-repo --invert-paths --path secrets.env

git filter-repo --invert-paths --path-glob '*.pem'

git filter-repo --invert-paths --path config/credentials/ --path .env

按文件大小过滤：

git filter-repo --strip-blobs-bigger-than 10M

修改作者信息：

git filter-repo --mailmap mailmap.txt

mailmap 文件格式：

New Name <new@email.com> <old@email.com>
New Name <new@email.com> Old Name <old@email.com>

提示： git filter-repo 要求在干净的克隆仓库上操作。先用 git clone --mirror 创建镜像副本，在副本上执行重写，确认无误后再推送。

git filter-branch（已废弃）

虽然已被官方废弃，了解其语法有助于理解旧脚本：

git filter-branch --force --index-filter \
  'git rm --cached --ignore-unmatch secrets.env' \
  --prune-empty --tag-name-filter cat -- --all
对比维度 filter-repo filter-branch
状态 推荐使用 已废弃
性能 快 10-100 倍 慢
安全性 更安全的默认行为 需要手动处理
依赖 Python bash
维护 活跃维护 不再更新

BFG Repo-Cleaner

BFG 是专门用于清理大文件和敏感数据的工具，使用 Java 编写，操作简单直观：

java -jar bfg.jar --delete-files secrets.env repo.git

java -jar bfg.jar --strip-blobs-bigger-than 50M repo.git

java -jar bfg.jar --replace-text passwords.txt repo.git

BFG 工作流程：

git clone --mirror https://github.com/user/repo.git
java -jar bfg.jar --strip-blobs-bigger-than 100M repo.git
cd repo.git
git reflog expire --expire=now --all
git gc --prune=now --aggressive
git push --force

重写后的善后工作
历史重写后必须执行以下步骤：


git reflog expire --expire=now --all
git gc --prune=now --aggressive

git push origin --force --all
git push origin --force --tags
通知所有协作者：


# 协作者需要执行
git fetch origin
git reset --hard origin/main

# 或重新克隆
git clone <repo-url>


提示： 历史重写是不可逆的破坏性操作。务必在操作前备份仓库，通知所有协作者，并在重写后强制所有人重新同步。

小结
    

  • git filter-repo 是官方推荐的历史重写工具，速度快、安全性高、功能全面
    • 

  • BFG Repo-Cleaner 专注于大文件和敏感数据清理，操作简单直观
    • 

  • filter-branch 已废弃，新项目不应再使用
    • 

  • 历史重写后必须执行 gc prune 和 force push，并通知所有协作者重新同步
    • 

  • 预防胜于治疗：使用 gitleaks、.gitignore 和 pre-commit hook 从源头杜绝敏感数据入库
