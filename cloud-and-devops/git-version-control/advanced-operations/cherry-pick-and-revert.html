精选与回退

三种撤销策略概览

Git 提供三种不同层次的撤销手段，它们的安全性和适用场景各不相同：

命令 方式 是否改写历史 安全性 适用场景
git revert 创建反向提交 否 高 已推送的公共分支
git reset 移动分支指针 是 中 本地未推送的提交
git cherry-pick 复制提交 否 高 从其他分支提取提交

Cherry-Pick 精选提取

Cherry-Pick 将指定的一个或多个提交应用到当前分支，生成新的 commit（新的 SHA-1）：

git cherry-pick abc1234

git cherry-pick abc1234 def5678 ghi9012

git cherry-pick abc1234..def5678

git cherry-pick -n abc1234
git cherry-pick --no-commit abc1234
处理 cherry-pick 冲突：


git cherry-pick abc1234
# CONFLICT...
vi conflicted-file.sh
git add conflicted-file.sh
git cherry-pick --continue

git cherry-pick --abort


提示： cherry-pick 生成的是全新 commit，与原提交有不同的 SHA-1。如果后续需要合并原分支，可能产生重复更改。建议记录 cherry-pick 来源。






Git Revert 安全回退
Revert 创建一个新的提交来撤销指定提交的更改，不改写历史：


git revert abc1234

git revert HEAD

git revert abc1234..def5678

git revert -n abc1234
回退合并提交需要指定保留的 parent：


git revert -m 1 <merge-commit-hash>

git log --oneline --graph




-m 值
含义





1
保留第一个 parent（主分支）




2
保留第二个 parent（功能分支）







提示： revert 合并提交后，如果后续需要重新合并同一分支，需要先 revert 那个 revert commit，否则 Git 会认为该分支的更改已经存在。






Git Reset 三种模式
Reset 通过移动 HEAD 和分支指针来"撤销"提交，有三种模式：






模式
HEAD
暂存区
工作目录
用途





--soft
移动
保留
保留
重新组织提交




--mixed
移动
重置
保留
取消暂存（默认模式）




--hard
移动
重置
重置
完全丢弃更改





git reset --soft HEAD~1
git reset --mixed HEAD~1
git reset --hard HEAD~1

git reset HEAD -- src/config.sh

git reflog
git reset --hard HEAD@{2}


提示： git reset --hard 是破坏性操作，会丢失工作目录中未提交的更改。执行前务必确认，或先用 git stash 保存当前工作。






三者对比与选择




场景
推荐命令





撤销已推送的 bug 修复
git revert <hash>




合并了一个提交但需要取消合并
git revert -m 1 <hash>




本地提交写错了想重写
git reset --soft HEAD~1




完全丢弃最近 3 个本地提交
git reset --hard HEAD~3




把 hotfix 分支的修复拿过来
git cherry-pick <hash>




只想取消暂存，保留文件修改
git reset HEAD -- <file>







实战场景
# 场景 1：撤销最近一次推送的提交
git revert HEAD
git push origin main

# 场景 2：将最近 3 个提交合并为 1 个
git reset --soft HEAD~3
git commit -m "feat: complete user auth module"

# 场景 3：从 release 分支提取紧急修复
git checkout main
git cherry-pick release/v1.2..release/v1.2.1

# 场景 4：误操作恢复
git reflog
git reset --hard HEAD@{1}


小结
    

  • Cherry-pick 从任意分支精确提取提交，生成新 commit，适合 hotfix 移植
    • 

  • Revert 通过反向提交安全撤销更改，不改写历史，是公共分支的首选撤销方式
    • 

  • Reset 提供 soft/mixed/hard 三种级别的回退，仅适用于未推送的本地提交
    • 

  • 选择原则：已推送用 revert，未推送用 reset，跨分支用 cherry-pick
    • 

  • 误操作后 reflog 是恢复的最后防线，几乎任何操作都可以通过 reflog 回退
    •
