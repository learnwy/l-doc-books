Part I · 版本控制与协作Git 与版本控制 简介基础与原理 简介合并与变基

合并与变基

三种整合策略概览

将一个分支的更改整合到另一个分支，Git 提供三种主要策略：

策略 命令 历史形态 适用场景
Merge git merge feature 保留分支拓扑 团队协作，保留完整历史
Rebase git rebase main 线性历史 个人分支整理
Squash git merge --squash feature 压缩为单次提交 功能分支合并

Fast-Forward 与三路合并

当目标分支没有新提交时，Git 执行 Fast-Forward（快进）合并，直接移动分支指针：

git checkout main
git merge feature
当两个分支都有新提交时，Git 执行三路合并（Three-Way Merge），创建一个新的合并 commit：


git checkout main
git merge feature --no-ff

git log --oneline --graph

提示： 使用 --no-ff 可以在历史中保留功能分支的起止信息，便于后续追溯。




三路合并的名称来源于它使用三个版本进行比较：两个分支的最新 commit（ours 和 theirs），以及它们的最近公共祖先（base）。Git 对比 base 与 ours 的差异、base 与 theirs 的差异，然后尝试自动合并两组变更。




Rebase 变基
变基（Rebase） 将当前分支的提交"重放"到目标分支之上，生成全新的 commit（新的 SHA-1），从而获得线性历史。


git checkout feature
git rebase main

git log --oneline --graph
黄金法则：永远不要对已经推送到公共仓库的提交执行 rebase，这会改变已有的历史，导致其他协作者的基底失效。


git rebase main
git rebase --abort
git rebase --continue
git rebase --skip
交互式 Rebase
交互式 rebase 允许你在变基过程中编辑、合并或重排 commit，是整理本地提交历史的利器：


git rebase -i HEAD~5
在打开的编辑器中，每行一个 commit，可选操作包括 pick（保留）、squash（合并到前一个）、edit（暂停以修改）、drop（丢弃）和 reword（修改提交消息）。




Squash 合并
Squash 合并将功能分支的所有提交压缩为一个 commit 合入目标分支：


git checkout main
git merge --squash feature
git commit -m "feat: add user authentication module"

冲突解决
当两个分支修改了同一文件的同一区域，Git 无法自动合并，产生合并冲突（Merge Conflict）。


git merge feature
# CONFLICT (content): Merge conflict in src/config.sh
git status

cat src/config.sh
冲突标记格式：


<<<<<<< HEAD
echo "current branch content"
=======
echo "incoming branch content"
>>>>>>> feature
解决步骤：


vi src/config.sh

git add src/config.sh
git merge --continue

git merge --abort
冲突解决工具：


git mergetool

git config merge.tool vimdiff
git config mergetool.prompt false


提示： 频繁地将主分支的更新合并到功能分支（或 rebase），可以减少最终合并时的冲突规模。






策略选择指南


小结
    

  • Merge 保留完整的分支拓扑和历史，是团队协作的安全选择
    • 

  • Rebase 生成线性历史但会重写 commit，仅用于未推送的本地分支
    • 

  • Squash merge 将整个功能压缩为单次提交，适合保持主分支的简洁性
    • 

  • 冲突解决的核心是理解三路合并原理：base、ours、theirs 三个版本的差异比对
    • 

  • 选择策略时需权衡历史可读性、可追溯性和团队协作安全性
    •
