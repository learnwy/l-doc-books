Git 内部原理

对象数据库

Git 的核心是一个内容寻址文件系统（Content-Addressable Filesystem）。所有数据以对象形式存储在 .git/objects/ 目录下，每个对象通过其内容的 SHA-1 哈希值唯一标识。

Git 有四种基本对象类型：

对象类型 作用 存储内容
blob 存储文件内容 纯文件数据，不含文件名
tree 存储目录结构 文件名、权限和指向 blob/tree 的引用
commit 存储提交信息 tree 引用、parent、作者、提交信息
tag 存储带注释的标签 指向 commit 的引用、标签信息

查看对象类型和内容：

git cat-file -t HEAD
git cat-file -p HEAD

git cat-file -p HEAD^{tree}

git cat-file -p <blob-hash>

对象的存储格式为 <类型> <长度>\0<内容>，经过 zlib 压缩后写入磁盘。对象的 SHA-1 哈希值就是对这个完整字符串（含头部）计算得到的。这意味着即使一个字节的差异也会产生完全不同的哈希值，从而保证数据完整性。

Blob 与 Tree

Blob（Binary Large Object） 只存储文件内容，不包含文件名或路径信息。两个内容完全相同的文件在 Git 中只会存储一份 blob。

Tree 对象相当于目录，记录了每个条目的文件模式、对象类型、SHA-1 和文件名。

git ls-tree HEAD
git ls-tree -r HEAD --name-only

echo "hello" | git hash-object --stdin
echo "hello" | git hash-object -w --stdin
Tree 对象中的文件模式遵循 UNIX 权限表示法：100644 表示普通文件，100755 表示可执行文件，040000 表示子目录，120000 表示符号链接。




Commit 与 DAG
每个 commit 对象包含一个指向 tree 的引用、零或多个 parent commit 引用、作者信息和提交消息。多个 commit 通过 parent 引用形成有向无环图（Directed Acyclic Graph，DAG）。


git log --oneline --graph --all

git rev-parse HEAD
git rev-parse HEAD~3

git cat-file -p HEAD
DAG 结构使 Git 能够高效地进行分支、合并和历史遍历：




提示： git log --graph 是可视化 DAG 的最快方式，配合 --all 可查看所有分支的完整图谱。




合并 commit 有两个 parent 引用，分别指向被合并的两个分支的最新 commit。这使得 Git 能够精确追踪每一次合并的来源。初始 commit 没有 parent，而普通 commit 有一个 parent。




引用系统
引用（Refs） 是指向 commit 对象的命名指针，存储在 .git/refs/ 目录下。

cat .git/HEAD
cat .git/refs/heads/main

git show-ref
git symbolic-ref HEAD

git update-ref refs/heads/test HEAD
git update-ref -d refs/heads/test
HEAD 通常是一个符号引用（Symbolic Reference），指向当前分支。当 HEAD 直接指向某个 commit 而非分支时，进入分离 HEAD（Detached HEAD） 状态：


git checkout HEAD~2
git checkout main
Git 还维护了 reflog（引用日志），记录每个引用的历史变化。即使 commit 不再被任何分支引用，仍可以通过 reflog 找回，默认保留 90 天：


git reflog
git reflog show feature


Pack 文件与存储优化
Git 使用松散对象（Loose Objects） 存储单个对象文件，但随着对象增多会切换到 Pack 文件格式以节省空间。Pack 文件使用增量压缩（Delta Compression），只存储对象之间的差异。


git count-objects -v

git gc
git verify-pack -v .git/objects/pack/*.idx | head -20

git fsck

git gc 触发打包操作时，Git 会选择最新版本作为基础对象完整存储，旧版本以 delta（差异）形式存储。这个策略优化了最常访问的对象（最新版本）的读取速度。




小结
    

  • Git 的底层是一个内容寻址文件系统，通过 SHA-1 哈希实现对象的唯一标识和完整性校验
    • 

  • 四种对象类型（blob、tree、commit、tag）构成了 Git 的完整数据模型
    • 

  • Commit 通过 parent 引用形成 DAG，支撑了分支、合并等所有高层操作
    • 

  • 引用是指向 commit 的命名指针，分支本质上就是一个可移动的引用
    • 

  • Pack 文件通过增量压缩实现高效的存储和传输
    •
