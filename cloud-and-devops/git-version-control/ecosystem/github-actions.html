GitHub Actions 持续集成

什么是 GitHub Actions

GitHub Actions 是 GitHub 原生的 CI/CD 和自动化平台。通过 YAML 文件定义工作流（Workflow），在代码推送、PR 创建等事件触发时自动执行构建、测试和部署任务。

mkdir -p .github/workflows

核心概念

概念 说明
Workflow 由 YAML 定义的自动化流程
Event 触发 workflow 的事件（push、PR 等）
Job workflow 中的一组步骤，运行在同一 runner
Step job 中的单个任务（运行命令或 action）
Action 可复用的自动化单元
Runner 执行 job 的虚拟机 


基础 Workflow
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Lint
        run: npm run lint

      - name: Test
        run: npm test

      - name: Build
        run: npm run build


矩阵构建
矩阵构建（Matrix Build） 并行测试多种环境组合：


# .github/workflows/matrix.yml
name: Matrix CI

on: [push, pull_request]

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
        node-version: [18, 20, 22]
      fail-fast: false

    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
      - run: npm ci
      - run: npm test




矩阵配置
说明





matrix
定义变量组合




fail-fast
false 表示一个失败不取消其他




exclude
排除特定组合




include
添加额外组合







事件触发




事件
触发条件





push
推送到指定分支




pull_request
PR 创建/更新/合并




schedule
定时执行（cron 表达式）




workflow_dispatch
手动触发




release
发布 Release




issue_comment
Issue/PR 评论





on:
  schedule:
    - cron: '0 2 * * 1'  # 每周一凌晨 2 点
  workflow_dispatch:
    inputs:
      environment:
        description: 'Deploy environment'
        required: true
        default: 'staging'
        type: choice
        options:
          - staging
          - production


缓存与产物
      - name: Cache node modules
        uses: actions/cache@v4
        with:
          path: ~/.npm
          key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-node-

      - name: Upload artifact
        uses: actions/upload-artifact@v4
        with:
          name: build-output
          path: dist/
          retention-days: 7


Secrets 与环境变量
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - name: Deploy
        env:
          API_KEY: ${{ secrets.API_KEY }}
          NODE_ENV: production
        run: |
          echo "Deploying to production..."
          ./deploy.sh


提示： 永远不要在 workflow 文件中硬编码密钥。使用 GitHub Secrets 存储敏感信息，Actions 运行时会自动脱敏日志输出。

小结
    

  • GitHub Actions 通过 YAML 定义工作流，支持 push、PR、定时等多种触发方式
    • 

  • 矩阵构建并行测试多种 OS 和运行时组合，fail-fast: false 确保全量测试
    • 

  • 缓存依赖和构建产物可以显著加速 CI 运行时间
    • 

  • 使用 Secrets 安全管理敏感信息，永远不要硬编码密钥
    • 

  • GitHub Marketplace 提供丰富的可复用 Actions，覆盖从构建到部署的全流程
