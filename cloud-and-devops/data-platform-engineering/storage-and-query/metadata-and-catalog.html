Part VII · 数据与伸缩数据平台工程 简介存储与查询 简介元数据与数据目录

元数据与数据目录

概述

元数据是"描述数据的数据"，是数据平台从无序存储走向有序资产管理的关键基础设施。在 PB 级数据湖中，没有完善的元数据管理，数据就是一堆无法被发现、理解和信任的文件。数据目录（Data Catalog）则是元数据的统一展示和访问入口，为数据生产者和消费者提供数据发现、理解和治理的能力。

一个成熟的元数据系统需要回答三个核心问题：这里有什么数据（发现）？这些数据是什么意思（理解）？这些数据可以信任吗（治理）？

元数据分类体系

技术元数据

描述数据的物理和逻辑结构：

  • Schema 信息：列名、数据类型、可空性、默认值
  • 存储信息：文件路径、格式、分区方式、文件大小
  • 统计信息：行数、列基数、min/max 值、null 比例
  • 表属性：表格式版本、压缩算法、排序键

业务元数据

描述数据的业务含义和用途：

  • 描述与文档：列的业务含义、计算逻辑说明
  • 标签与分类：业务域归属、数据敏感级别
  • 所有者信息：负责人、团队、联系方式
  • 使用指南：推荐查询模式、常见陷阱

运营元数据

描述数据的生命周期和运行状态：

  • 血缘关系：数据从哪来，流向哪里
  • 访问日志：谁在什么时候查询了什么数据
  • 质量指标：数据新鲜度、完整性、准确性得分
  • 变更历史：Schema 演进记录、数据修改日志

社交元数据

描述数据的社区使用情况：

  • 使用频率：热门表和列的排名
  • 用户评价：数据质量反馈、使用建议
  • 知识沉淀：FAQ、最佳实践、使用案例

Hive Metastore

Hive Metastore（HMS）是大数据生态中最基础的元数据存储服务，几乎所有主流引擎都支持通过 HMS 访问表元数据。

架构

查询引擎（Spark/Trino/Flink）
       ↓ Thrift API
Hive Metastore Service
       ↓ JDBC
关系数据库（MySQL/PostgreSQL）

HMS 存储的核心实体：

  • Database：命名空间
  • Table：表定义（Schema、SerDe、存储位置）
  • Partition：分区元数据（路径、统计信息）
  • Column Statistics：列级统计（用于 CBO）

局限性

HMS 在大规模场景下暴露出显著不足：

  • 单点瓶颈：所有引擎共享一个 Metastore 实例
  • 无版本控制：Schema 变更没有原子性保证
  • 权限粗粒度：缺乏列级和行级访问控制
  • 无血缘追踪：只存储静态结构，不记录数据流动
  • 分区爆炸：万级分区的列表操作极慢

现代数据目录方案

Apache Atlas

Atlas 是 Apache 生态的数据治理框架，提供元数据管理、数据分类和血缘追踪能力。

核心能力：

  • 类型系统：可扩展的实体类型定义（Table、Column、Process 等）
  • 血缘图：自动采集 Hive/Spark 等引擎的操作血缘
  • 分类标签：灵活的标签体系支持数据分类和访问控制
  • 搜索与发现：全文搜索和基于属性的筛选

适用场景：Hadoop 生态为主的组织，需要自动化血缘采集的场景。

OpenMetadata

OpenMetadata 是新一代开源数据目录，以用户体验和协作为核心设计理念：

# OpenMetadata 核心概念
Entity Types:
  - Table / Topic / Dashboard / Pipeline / ML Model
  - Database Service / Messaging Service / Dashboard Service

Metadata Aspects:
  - Schema / Profile / Quality / Lineage
  - Owner / Tags / Description / Usage

差异化特点：

  • 统一数据模型：一套 API 管理所有元数据类型
  • 数据 Profiler：自动分析数据分布和质量
  • 协作功能：评论、任务分配、数据问答
  • Ingestion Framework：声明式连接器配置
  • 数据质量集成：内建质量测试和告警

Datahub（LinkedIn）

Datahub 以事件驱动架构和实时元数据更新为特色：

  • GMS（Generalized Metadata Service）：核心元数据存储
  • MCE/MAE（Metadata Change/Audit Events）：通过 Kafka 实时同步元数据变更
  • Graph Service：Neo4j 存储关系图，支持血缘和影响分析查询
  • Search Service：Elasticsearch 支持全文搜索

Unity Catalog（Databricks）

Unity Catalog 代表了商业化数据目录的方向：

  • 跨工作区的统一权限管理
  • 表、卷（Volume）、模型、函数的统一治理
  • 行级和列级安全策略
  • 与 Delta Lake 深度集成的列级血缘

血缘管理

血缘粒度

粒度 追踪内容 实现复杂度 价值
表级 表 A → 表 B 低 影响分析
列级 表A.col1 → 表B.col2 中 精准影响分析
行级 哪些源行产出了目标行 极高 审计合规
值级 最终值如何由源值计算 极高 数据取证

血缘采集方法

SQL 解析法：解析 SQL 的 AST，提取列间映射关系

# SQL 血缘解析示例
from sqllineage.runner import LineageRunner

sql = """
INSERT INTO mart.user_metrics
SELECT user_id, COUNT(*) as event_count
FROM staging.events
GROUP BY user_id
"""

runner = LineageRunner(sql)
# 表级: staging.events → mart.user_metrics
# 列级: staging.events.user_id → mart.user_metrics.user_id

执行日志法：从查询引擎的执行日志中提取实际访问的表和列

Hook 拦截法：在引擎执行过程中注入 Hook，实时捕获血缘信息

血缘应用场景

  • 影响分析：源表 Schema 变更时，哪些下游表会受影响？
  • 根因分析：某个报表数据异常，追溯到哪个上游表/管道出了问题？
  • 合规审计：敏感数据（如 PII）从源头流向了哪些目标？
  • 优化评估：某张表被多少下游使用？是否可以安全下线？

数据发现与搜索

搜索体验设计

优秀的数据目录需要支持多维度搜索：

  • 全文搜索：按表名、列名、描述搜索
  • 属性过滤：按数据库、所有者、标签、质量评分筛选
  • 使用排名：热门表优先展示
  • 相关推荐：基于血缘和使用模式推荐相关数据集

数据预览

在搜索结果中提供数据预览能力：

  • 前 N 行采样数据
  • 列值分布统计
  • 数据 Profile（min/max、null 比例、基数）
  • 最近的质量检查结果

实施建议

渐进式采用

  1. 第一阶段：技术元数据自动采集（Schema、统计信息）
  2. 第二阶段：血缘自动追踪 + 基础搜索能力
  3. 第三阶段：业务元数据标注 + 数据分类
  4. 第四阶段：完整的数据治理策略执行

元数据质量

元数据本身也需要质量管理：

  • 定期校验元数据与实际数据的一致性
  • 监控"无主表"（没有 owner 标注的表）
  • 跟踪文档覆盖率（有描述的列占总列数的比例）
  • 清理过期元数据（已删除表的残留记录）

组织推广

技术能力建成后，推广采用同样关键：

  • 将数据目录集成到日常工作流（IDE 插件、BI 工具内嵌）
  • 设立数据管家（Data Steward）角色负责业务元数据维护
  • 建立激励机制鼓励高质量的文档和标注
  • 定期发布数据目录使用报告，展示价值
