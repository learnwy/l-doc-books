数据质量工程

概述

数据质量工程是构建可信数据平台的核心保障体系。当数据消费者对数据的信任度下降时，他们会回归直觉决策，数据平台的投资就失去了意义。数据质量工程的目标是建立从预防、检测到修复的完整闭环，在质量问题影响下游之前拦截并修复。

与传统的手工数据审核不同，现代数据质量工程强调自动化、可编程和持续监控。它借鉴了软件工程中测试和 CI/CD 的理念，将数据质量检查嵌入数据管道的每个环节。

数据质量维度

六大核心维度

维度 定义 度量方法
完整性（Completeness） 必填字段是否都有值 NULL 比例、缺失记录占比
准确性（Accuracy） 数据是否反映真实世界 与权威数据源对比、规则校验
一致性（Consistency） 跨系统的数据是否一致 字段间逻辑关系校验、跨表对比
时效性（Timeliness） 数据是否在预期时间到达 数据新鲜度监控、SLA 达成率
唯一性（Uniqueness） 是否存在重复记录 主键唯一性检查、去重比例
有效性（Validity） 数据是否符合定义的格式和范围 Schema 校验、值域检查

质量指标量化

每个维度应该有可量化的指标：

-- 完整性检查示例
SELECT
  COUNT(*) AS total_rows,
  SUM(CASE WHEN user_id IS NULL THEN 1 ELSE 0 END) AS null_user_id,
  SUM(CASE WHEN email IS NULL THEN 1 ELSE 0 END) AS null_email,
  ROUND(SUM(CASE WHEN user_id IS NULL THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 2)
    AS null_user_id_pct
FROM staging.users
WHERE load_date = CURRENT_DATE;

数据质量检查框架

dbt Tests

dbt 内建了四种通用测试，并支持自定义测试：

# schema.yml - dbt 数据测试定义
models:
  - name: orders
    columns:
      - name: order_id
        tests:
          - unique # 唯一性
          - not_null # 非空
      - name: amount
        tests:
          - not_null
          - dbt_utils.accepted_range:
              min_value: 0
              max_value: 1000000
      - name: status
        tests:
          - accepted_values:
              values: ['pending', 'completed', 'cancelled', 'refunded']
    tests:
      - dbt_utils.expression_is_true:
          expression: 'completed_at >= created_at'

Great Expectations

Great Expectations（GX）是最流行的开源数据质量框架，提供丰富的期望库（Expectations）和数据验证工作流：

import great_expectations as gx

context = gx.get_context()

# 定义期望套件
suite = context.add_expectation_suite("orders_validation")

# 添加期望
suite.add_expectation(
    gx.expectations.ExpectColumnValuesToNotBeNull(column="order_id")
)
suite.add_expectation(
    gx.expectations.ExpectColumnValuesToBeBetween(
        column="amount", min_value=0, max_value=1000000
    )
)
suite.add_expectation(
    gx.expectations.ExpectTableRowCountToBeBetween(
        min_value=10000, max_value=10000000
    )
)

# 执行验证
result = context.run_checkpoint(checkpoint_name="orders_checkpoint")

Soda

Soda 以 YAML 声明式语法定义数据质量检查，适合非开发者使用：

# checks.yml
checks for orders:
  - row_count > 0
  - missing_count(order_id) = 0
  - duplicate_count(order_id) = 0
  - avg(amount) between 50 and 500
  - freshness(created_at) < 2h
  - schema:
      fail:
        when required column missing: [order_id, user_id, amount]
        when wrong type:
          order_id: varchar
          amount: decimal

数据契约（Data Contracts）

数据契约是源系统（生产者）与数据平台（消费者）之间的明确协议，定义了数据的格式、语义和质量保证。

契约内容

# data-contract.yaml
apiVersion: datacontract/v1
kind: DataContract
metadata:
  name: user-events
  version: 2.1.0
  owner: user-platform-team
  domain: user-engagement

schema:
  type: object
  properties:
    event_id:
      type: string
      format: uuid
      description: 全局唯一事件标识符
    user_id:
      type: string
      pattern: '^U[0-9]{10}$'
    event_type:
      type: string
      enum: [page_view, click, purchase, search]
    timestamp:
      type: string
      format: date-time

quality:
  freshness: '< 5 minutes'
  completeness:
    event_id: 100%
    user_id: '>= 99.9%'
  volume:
    daily_min: 1000000
    daily_max: 50000000

sla:
  availability: 99.95%
  support: '#data-quality-alerts'

evolution:
  breaking_changes: 'require 2-week notice'
  additive_changes: 'notify consumers within 24h'

契约执行

契约不能只是文档——必须通过自动化执行：

  1. 准入检查：数据写入前验证是否符合契约
  2. 持续监控：运行时检测契约违规
  3. 变更管控：Schema 变更触发兼容性检查
  4. 违约告警：自动通知双方团队

异常检测

统计异常检测

基于历史模式自动发现数据异常：

  • 行数异常：今日数据量与历史均值偏差超过 3σ
  • 值分布漂移：列的统计分布发生显著变化
  • NULL 突增：某列的空值比例突然升高
  • 基数变化：唯一值数量异常增减

机器学习检测

对于复杂的异常模式，可引入 ML 方法：

  • 时间序列异常检测（Prophet、Isolation Forest）
  • 多维度联合异常（DBSCAN 聚类）
  • 季节性和趋势分解后的残差分析

质量保障流程

分层防御

第一层：Schema 验证（入口）
  → 格式正确性、必填字段非空、类型匹配

第二层：业务规则验证（管道内）
  → 值域约束、跨字段一致性、引用完整性

第三层：统计异常检测（产出后）
  → 行数波动、分布漂移、延迟监控

第四层：跨系统对账（周期性）
  → 源与目标数据一致性、聚合值对比

质量问题响应

检测到质量问题后的标准响应流程：

  1. 分类：是否为阻塞性问题（影响数据正确性 vs 仅统计偏差）
  2. 隔离：阻塞下游管道，防止脏数据传播
  3. 通知：告警相关数据所有者和消费者
  4. 诊断：定位问题根因（源系统变更？管道 Bug？基础设施故障？）
  5. 修复：修复根因 + 修复已受影响的数据
  6. 回顾：事后复盘，完善检查规则防止再发

度量与报告

质量评分卡

为每个数据产品维护质量评分：

指标 权重 当前值 目标 状态
完整性 30% 99.7% ≥99.5% ✓
唯一性 20% 100% 100% ✓
时效性 25% 97.2% ≥99% ✗
准确性 25% 99.1% ≥99% ✓
综合 98.8% ≥99% ✗

趋势监控

追踪质量指标的时间趋势：

  • 发现缓慢恶化的质量问题
  • 评估质量改进措施的效果
  • 为 SLA 设定提供数据支撑

实践建议

  1. 从关键数据产品开始：优先保障业务影响最大的数据集
  2. 测试前移：在管道中尽早检测问题，而非在最终产出后
  3. 分级告警：区分严重性等级，避免告警疲劳
  4. 闭环改进：每次质量事故后完善检查规则，形成质量知识库
  5. 组织文化：将数据质量纳入团队 KPI，激励主动改进
