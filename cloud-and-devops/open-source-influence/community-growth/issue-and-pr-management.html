Issue 与 PR 管理

Issue 分诊流程

Issue 分诊（Triage）是维护者的核心日常工作。一套高效的分诊流程可以大幅减少管理开销，确保重要问题得到及时处理。

gh issue list --label="needs-triage" --sort=created --json number,title,createdAt

gh issue edit 123 --add-label="bug,priority:high" --milestone="v2.1"

gh issue comment 123 --body="感谢报告！已确认此问题，将在 v2.1 中修复。"


提示： 设立 needs-triage 标签作为所有新 Issue 的默认标签。分诊完成后移除此标签，这样可以快速找到未处理的 Issue。






标签体系设计
合理的标签体系是高效管理的基础。标签应按维度分类，使用一致的命名约定和颜色编码。


gh label create "type:bug" --color=d73a4a --description="确认的缺陷"
gh label create "type:feature" --color=a2eeef --description="新功能请求"
gh label create "type:docs" --color=0075ca --description="文档相关"
gh label create "priority:critical" --color=b60205 --description="需立即处理"
gh label create "priority:high" --color=d93f0b --description="当前版本必须解决"
gh label create "priority:medium" --color=fbca04 --description="近期版本解决"
gh label create "priority:low" --color=0e8a16 --description="有空再处理"
gh label create "status:needs-triage" --color=ededed --description="等待分诊"
gh label create "status:confirmed" --color=c5def5 --description="已确认"
gh label create "status:wontfix" --color=ffffff --description="不予修复"

# .github/CODEOWNERS

gh pr list --review-requested=@me --json number,title,createdAt

gh pr review 456 --approve --body="LGTM! 测试全面，逻辑清晰。"

gh pr review 456 --request-changes --body="请补充边界情况的测试。"


自动化机器人
GitHub Bot 可以自动化大量重复性管理工作，释放维护者的时间。


# .github/stale.yml (Stale Bot 配置)
daysUntilStale: 60
daysUntilClose: 7
staleLabel: stale
markComment: >
  此 Issue 已超过 60 天未活跃。如果问题仍然存在，请留言说明， 否则将在 7 天后自动关闭。


closeComment: >
  此 Issue 因长期不活跃已自动关闭。如需重新打开，请留言说明。


exemptLabels:
  - 'priority:critical'
  - 'priority:high'
  - 'status:confirmed'

里程碑与路线图
使用里程碑（Milestone）和项目看板（Project Board）规划和追踪版本进度。


gh api repos/{owner}/{repo}/milestones --method POST \
  -f title="v2.1" \
  -f description="性能优化与新 API" \
  -f due_on="2026-06-01T00:00:00Z"

gh issue edit 123 --milestone="v2.1"

gh api repos/{owner}/{repo}/milestones --jq '.[] | "\(.title): \(.open_issues)/\(.open_issues + .closed_issues)"'

小结
    

  • Issue 分诊应在 48 小时内首次回复，使用 needs-triage 标签追踪未处理 Issue。
    • 

  • 标签按类型、优先级、状态、领域等维度分类，使用一致的前缀命名和颜色编码。
    • 

  • PR 审查根据类型设定不同的审查重点和时间目标，使用 CODEOWNERS 自动分配审查者。
    • 

  • GitHub Bot（Stale、Auto-label、Welcome）自动化重复管理工作，释放维护者时间。
    • 

  • 里程碑和路线图让社区了解项目方向，提升参与者的归属感和贡献动力。
    •
