RFC 与技术提案

RFC 的作用

RFC（Request for Comments）是一种结构化的技术决策文档。它将重大技术决策从即时讨论转变为深思熟虑的书面论证，确保决策透明、可追溯、经过充分讨论。

影响所有下游用户

✅ 需要

✅ 需要

如果改变 API 行为则需要







提示： RFC 不仅用于开源项目。在企业内部技术团队中，RFC 文化同样有效，它可以减少会议时间、提升决策质量、建立技术知识库。






RFC 文档结构
一份好的 RFC 应该清晰、完整、有理有据。以下是经过实践验证的标准结构。


# RFC-0042: 引入服务端组件缓存层

- 状态：讨论中
- 作者：@username
- 创建日期：2026-04-01
- 最后更新：2026-04-01

## 概要

一两段话总结提案的核心内容。

## 动机

为什么需要这个变更？当前存在什么问题？

## 详细设计

具体的技术方案，包含 API 设计、数据结构、流程图等。

## 替代方案

考虑过哪些其他方案？为什么没有选择它们？

## 缺点与风险

这个方案的缺点是什么？有哪些已知风险？

## 未解决问题

哪些问题需要在实施过程中进一步确定？

## 实施计划

分阶段的实施路线图和时间表。

RFC 流程设计
建立标准化的 RFC 流程，确保每份提案都经过充分讨论和正式决策。


mkdir -p rfcs

cat > rfcs/0042-server-component-cache.md << 'EOF'
# RFC-0042: 引入服务端组件缓存层

- 状态：Draft
- 作者：@username
- 创建日期：2026-04-01
EOF

gh pr create \
  --title "RFC-0042: 引入服务端组件缓存层" \
  --body "请参阅 rfcs/0042-server-component-cache.md" \
  --label "rfc"

利益相关方分析
RFC 的成功不仅取决于技术方案的质量，还取决于对利益相关方的准确分析和有效沟通。

小结
    

  • RFC 将重大技术决策从即时讨论转变为结构化的书面论证，确保决策质量和可追溯性。
    • 

  • 标准 RFC 包含概要、动机、详细设计、替代方案、风险评估和实施计划。
    • 

  • RFC 流程经历 Draft → Discussion → FCP → 决策四个阶段。
    • 

  • 准确的利益相关方分析和主动的沟通是 RFC 成功的关键非技术因素。
    • 

  • 学习 Rust、React、Vue 等项目的 RFC 实践，可以快速提升提案写作能力。
    •
