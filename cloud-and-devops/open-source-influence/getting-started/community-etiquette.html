社区礼仪

行为准则的意义

行为准则（Code of Conduct, CoC）是开源社区的基本社会契约。它定义了社区成员的行为期望和违规处理机制，确保社区环境安全、包容和高效。

添加行为准则到项目中：


curl -o CODE_OF_CONDUCT.md \
  https://www.contributor-covenant.org/version/2/1/code_of_conduct/code_of_conduct.md

sed -i '' 's/\[INSERT CONTACT METHOD\]/conduct@yourproject.org/g' CODE_OF_CONDUCT.md


提示： 仅添加 Code of Conduct 文件是不够的。作为维护者，你需要建立执行机制并在实际冲突中践行承诺，否则行为准则将形同虚设。

PR Review 礼仪
代码审查是开源协作中最敏感的环节。作为提交者和审查者，都应遵循特定的礼仪规范。


作为 PR 提交者：


- 保持 PR 小而聚焦，一个 PR 只解决一个问题
- 在 PR 描述中说明"为什么"而不仅仅是"是什么"
- 主动标注需要重点审查的部分
- 对 Review 反馈表示感谢，即使你不同意
- 讨论完成后及时更新代码
作为 代码审查者：


- 先肯定好的部分，再提出改进建议
- 区分"必须修改"和"建议修改"
- 提供具体的改进方案，而非仅指出问题
- 避免主观偏好（tab vs space 这类争论）
- 及时完成 Review，不让 PR 长期挂起




反馈类型
标记方式
示例





必须修改
[blocking]
这里有内存泄漏，必须修复




建议修改
[nit] 或 [optional]
这个变量名可以更具描述性




疑问
[question]
这里为什么选择递归而非迭代？




赞赏
无需标记
这个解法很优雅！







提示： 在审查他人代码时，始终记住屏幕另一端是一个活生生的人。你的反馈方式直接影响对方的参与意愿和社区的整体氛围。






维护者视角
理解维护者的处境，可以帮助你成为更受欢迎的贡献者。


维护者面临的常见挑战：






挑战
描述





时间有限
多数维护者是业余时间志愿参与




通知过载
热门项目每天收到大量 Issue 和 PR




情绪消耗
持续面对不合理要求和消极反馈




决策压力
每个 API 变更都影响大量下游用户





作为贡献者，你可以通过以下方式减轻维护者的负担：


- 提交 PR 前确保通过所有 CI 检查
- 遵循项目的代码风格和贡献指南
- 在 Issue 中帮助其他用户解答问题
- 帮助分诊（Triage）新提交的 Issue
- 公开感谢维护者的付出


小结
    

  • 行为准则是开源社区的基本社会契约，需要配合执行机制才能真正发挥作用。
    • 

  • 异步文字沟通应遵循尊重、善意、具体、感谢和耐心五项基本原则。
    • 

  • Issue 讨论应一次性提供完整信息，避免"+1"刷屏和跑题讨论。
    • 

  • PR 审查中应区分必须修改和建议修改，先肯定再建议，提供具体方案。
    • 

  • 理解维护者的处境和挑战，主动承担力所能及的社区工作，减轻维护者负担。
    •
