选择开源许可证

许可证的重要性

开源许可证（License）是开源项目的法律基础。它定义了用户可以如何使用、修改和分发你的代码。没有许可证的代码在法律上默认"保留所有权利"，即使公开在 GitHub 上也不是真正的开源。

选择许可证时需要考虑的核心因素：






考虑因素
关键问题





使用自由度
是否允许商业使用？是否允许闭源使用？




修改与分发
修改后的代码是否必须开源？




专利保护
是否包含明确的专利授权条款？




归属要求
是否要求保留原始版权声明？




社区兼容性
是否与项目依赖的其他许可证兼容？







提示： 许可证一旦选定并被他人使用，变更许可证将需要所有贡献者的同意。因此在项目初期就做出正确选择至关重要。






宽松型许可证
宽松型（Permissive）许可证对使用者的限制最少，允许在几乎任何场景下使用代码，包括闭源商业项目。

Copyleft 型许可证
Copyleft 许可证要求衍生作品必须以相同或兼容的许可证发布。这确保了代码及其改进始终保持开源。

许可证选择决策树

实际添加许可证到项目中：


cd my-project

curl -o LICENSE https://raw.githubusercontent.com/licenses/license-templates/master/templates/mit.txt

sed -i '' "s/\[year\]/$(date +%Y)/g" LICENSE
sed -i '' "s/\[fullname\]/Your Name/g" LICENSE

head -5 LICENSE


许可证兼容性
当项目依赖多个开源库时，许可证兼容性（License Compatibility）是必须考虑的问题。不兼容的许可证组合可能导致法律风险。

使用工具检查项目依赖的许可证：


npx license-checker --summary

npx license-checker --onlyAllow "MIT;Apache-2.0;BSD-2-Clause;BSD-3-Clause;ISC"

npx license-checker --failOn "GPL-2.0;GPL-3.0;AGPL-3.0"


小结
    

  • 开源许可证是项目的法律基础，无许可证的代码默认版权保留。
    • 

  • 宽松型许可证（MIT、Apache 2.0）最大化代码采用率，适合库和工具类项目。
    • 

  • Copyleft 许可证（GPL、AGPL）要求衍生作品保持开源，适合保护项目核心价值。
    • 

  • Apache 2.0 提供明确的专利授权，在企业环境中更受青睐。
    • 

  • 使用工具定期检查项目依赖的许可证兼容性，避免潜在法律风险。
