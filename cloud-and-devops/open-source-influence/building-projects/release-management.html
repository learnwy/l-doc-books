版本发布管理

语义化版本控制

语义化版本（Semantic Versioning, SemVer）是开源社区广泛采用的版本编号约定。版本号格式为 MAJOR.MINOR.PATCH，每个部分有明确的递增规则。





版本变更
触发条件
用户影响
示例





MAJOR
移除 API、改变行为
需要修改代码
1.x → 2.0.0




MINOR
新增功能、新增 API
无需修改，可选择使用
1.2.x → 1.3.0




PATCH
Bug 修复、安全补丁
无需修改，建议立即更新
1.2.3 → 1.2.4




Pre-release
测试版本
不保证稳定性
2.0.0-alpha.1





npm version patch -m "chore: release %s"

npm version minor -m "chore: release %s"

npm version major -m "chore: release %s"

npm version prerelease --preid=alpha


提示： 在 1.0.0 之前（即 0.x.y 阶段），API 被视为不稳定。此阶段 MINOR 版本变更也可能包含不兼容修改。尽早发布 1.0.0 向用户传达稳定性承诺。






Changesets 工作流
Changesets 是一种现代化的版本管理方式，特别适合 Monorepo 项目。每次 PR 附带一个描述变更的 changeset 文件。


npx changeset init

npx changeset add

npx changeset version

npx changeset publish
一个 changeset 文件的内容：


---
'my-awesome-lib': minor
---

新增暗色模式支持，通过 `useTheme` Hook 可在运行时切换主题。

状态检查
changeset status
查看待发布变更







自动化发布流水线
将发布过程完全自动化，减少人为失误并提高发布频率。


name: Release

on:
  push:
    branches: [main]

permissions:
  contents: write
  packages: write
  pull-requests: write

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          registry-url: https://registry.npmjs.org
      - run: pnpm install --frozen-lockfile
      - run: pnpm build
      - run: pnpm test
      - uses: changesets/action@v1
        with:
          publish: pnpm changeset publish
          version: pnpm changeset version
          commit: 'chore: version packages'
          title: 'chore: version packages'
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
npm pack --dry-run

npm publish --dry-run

npm publish --access public

npm dist-tag add my-awesome-lib@2.0.0-beta.1 next


GitHub Release 与分发
GitHub Release 是向用户传达版本信息和分发预编译产物的标准方式。


gh release create v1.2.0 \
  --title "v1.2.0" \
  --notes-file CHANGELOG.md \
  --generate-notes

gh release create v2.0.0-alpha.1 \
  --title "v2.0.0 Alpha 1" \
  --prerelease \
  --notes "首个 v2 预览版，请谨慎用于生产环境。"

gh release upload v1.2.0 dist/*.tar.gz

破坏性变更管理
MAJOR 版本升级需要特别谨慎的变更管理策略，帮助用户平滑迁移。


# 从 v1 迁移到 v2

## 破坏性变更

### `createApp` API 签名变更

**v1:** createApp(options)

**v2:** createApp(root, options)

### 移除的功能

| 已移除功能     | 替代方案            |
| -------------- | ------------------- |
| legacyMode     | 使用 compatMode     |
| renderToString | 使用 renderToStream |

## 自动迁移工具

运行 codemod 自动完成大部分迁移：

npx @mylib/codemod v2
npx @mylib/codemod v2 --dry-run

npx @mylib/codemod v2 --path=src/

git diff --stat


小结
    

  • 语义化版本（SemVer）是开源社区的版本编号标准，MAJOR.MINOR.PATCH 各有明确含义。
    • 

  • Changesets 工作流让每个 PR 附带变更描述，自动汇总生成 CHANGELOG 和版本号。
    • 

  • 自动化发布流水线（GitHub Actions + Changesets）减少人为失误，提高发布频率。
    • 

  • GitHub Release 用于分发预编译产物和传达版本信息，配合 dist-tag 管理预览版。
    • 

  • MAJOR 版本升级应提供详细迁移指南和自动化 Codemod 工具，帮助用户平滑过渡。
    •
