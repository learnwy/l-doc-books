项目结构设计

一个规范的开源项目结构让贡献者能快速理解项目组织方式。不同类型的项目有不同的最佳结构，但核心文件是通用的。

my-awesome-lib/
├── .github/
│   ├── ISSUE_TEMPLATE/
│   │   ├── bug_report.md
│   │   └── feature_request.md
│   ├── PULL_REQUEST_TEMPLATE.md
│   └── workflows/
│       ├── ci.yml
│       └── release.yml
├── src/
│   ├── index.ts
│   └── core/
├── tests/
│   └── core.test.ts
├── docs/
│   └── getting-started.md
├── .gitignore
├── .editorconfig
├── LICENSE
├── README.md
├── CONTRIBUTING.md
├── CHANGELOG.md
├── package.json
└── tsconfig.json
文件/目录 用途 是否必需
LICENSE 开源许可证 ✅ 必需
README.md 项目说明入口 ✅ 必需
CONTRIBUTING.md 贡献者指南 ✅ 推荐
CHANGELOG.md 变更记录 ✅ 推荐
CODE_OF_CONDUCT.md 行为准则 ✅ 推荐
.github/ GitHub 配置 ✅ 推荐
.editorconfig 编辑器统一配置 ✅ 推荐
.gitignore Git 忽略规则 ✅ 必需

初始化项目

使用现代工具链快速初始化项目结构：

mkdir my-awesome-lib && cd my-awesome-lib

git init

npm init -y

npx gitignore node

cat > .editorconfig << 'EOF'
root = true

[*]
indent_style = space
indent_size = 2
end_of_line = lf
charset = utf-8
trim_trailing_whitespace = true
insert_final_newline = true

[*.md]
trim_trailing_whitespace = false
EOF


提示： 使用 .editorconfig 可以确保不同编辑器和 IDE 的用户都遵循统一的代码格式，减少因格式差异产生的无意义 diff。






代码规范工具链
自动化的代码规范工具能显著降低 Code Review 中关于格式的讨论，让审查聚焦于逻辑。


npm install -D eslint prettier eslint-config-prettier

npm install -D husky lint-staged

npx husky init

cat > .husky/pre-commit << 'EOF'
npx lint-staged
EOF
{
  "lint-staged": {
    "*.{ts,tsx}": ["eslint --fix", "prettier --write"],
    "*.{json,md,yml}": ["prettier --write"]
  }
}

CONTRIBUTING.md 指南
贡献指南是面向潜在贡献者的操作手册。它应该降低参与门槛，而不是制造障碍。


# 贡献指南

感谢你对本项目的关注！以下指南将帮助你快速参与贡献。

## 开发环境

- Node.js >= 18
- pnpm >= 8

## 搭建步骤

1. Fork 并 Clone 仓库
2. 运行 `pnpm install`
3. 运行 `pnpm test` 确认环境正常
4. 创建特性分支 `git checkout -b feat/your-feature`

## 提交规范

本项目使用 Conventional Commits 规范。

## Pull Request 流程

1. 确保所有测试通过
2. 更新相关文档
3. 填写 PR 模板
4. 等待 Code Review

小结
    

  • 规范的项目结构让贡献者能快速理解项目组织，降低参与门槛。
    • 

  • LICENSE、README、CONTRIBUTING.md 和 .gitignore 是开源项目的必备文件。
    • 

  • 自动化代码规范工具（ESLint + Prettier + Husky）减少格式相关的 Review 讨论。
    • 

  • README 应在 30 秒内传达项目价值，包含安装、示例和文档链接。
    • 

  • CONTRIBUTING.md 是面向贡献者的操作手册，应持续根据反馈改进。
