服务网格核心概念

核心概念

服务网格（Service Mesh）是处理微服务间通信的专用基础设施层，将网络通信的复杂性从业务代码中抽离到独立的代理进程中。服务网格以 Sidecar 模式在每个服务实例旁部署一个代理（如 Envoy），所有入站和出站流量都经过该代理处理。代理负责服务发现、负载均衡、流量管理、安全通信、可观测性等横切关注点，使业务服务可以专注于业务逻辑而无需关心网络层的复杂性。

数据面与控制面
服务网格的架构分为数据面（Data Plane）和控制面（Control Plane）两层。数据面由所有 Sidecar 代理组成，处理实际的网络流量。控制面管理和配置数据面代理，提供服务发现、配置分发、证书管理和策略执行等功能。


Envoy 是最主流的数据面代理，由 Lyft 开发并捐赠给 CNCF。Envoy 的核心能力包括：L4/L7 代理、动态配置（xDS API）、主动/被动健康检查、高级负载均衡（Zone-aware、Ring Hash、Maglev）、流量镜像、故障注入和分布式追踪集成。

控制面通过 xDS API 向数据面代理推送配置变更，实现毫秒级的动态路由调整。这种配置与数据分离的架构使得流量管理策略可以在不重启代理或业务服务的情况下热更新。


流量管理
服务网格的流量管理能力是其核心价值之一，涵盖请求路由、流量分割、超时重试、断路器和故障注入等功能。


请求路由支持基于 HTTP Header、URL 路径、Query Parameter 等条件的精细化路由。典型场景包括：基于用户 ID 的灰度路由（特定用户群体访问新版本）、基于请求头的 A/B 测试路由、基于权重的金丝雀发布路由。


流量分割（Traffic Splitting）将请求按权重分配到不同版本的服务实例。金丝雀发布的典型流程是：部署新版本 → 分配 5% 流量 → 监控关键指标 → 逐步提升权重 → 全量切换或回滚。服务网格的流量分割在代理层实现，无需修改应用代码或 Kubernetes Service。


超时和重试策略在代理层统一配置，替代在每个服务中重复实现。代理层超时包括连接超时和请求超时，请求超时可按路由粒度配置。重试策略指定重试条件（5xx 错误、连接失败）、最大重试次数和退避间隔。


断路器在检测到下游服务异常时快速切断请求，防止级联故障。Envoy 的断路器支持按连接数、并发请求数、挂起请求数和重试次数四个维度设置阈值，任何一个维度超限都会触发断路。


安全通信
服务网格最重要的安全能力是透明的 mTLS（Mutual TLS）加密。传统方式下实现服务间 TLS 需要每个服务管理证书的申请、续期和配置，工作量巨大且容易出错。服务网格的控制面自动为每个服务签发短期证书（如 24 小时有效期），Sidecar 代理自动完成 TLS 握手和证书轮换，整个过程对业务服务完全透明。


零信任网络（Zero Trust Networking）是服务网格安全模型的理论基础。零信任假设网络内部和外部同样不可信，每个请求都必须经过身份验证和授权。服务网格通过 mTLS 验证服务身份（基于 SPIFFE 标准的服务身份），通过授权策略控制哪些服务可以访问哪些端点。

小结
    

  • 服务网格以 Sidecar 代理模式将通信复杂性从业务代码中抽离，实现语言无关的统一治理
    • 

  • 数据面（Envoy）处理实际流量，控制面管理配置下发，xDS 协议连接两者
    • 

  • 流量管理支持精细化路由、流量分割、超时重试和断路器，在代理层统一配置
    • 

  • 透明 mTLS 和零信任安全模型是服务网格最重要的安全能力
    • 

  • 服务网格引入约 1ms 延迟和 Sidecar 资源开销，适合中大规模异构微服务架构
    • 

  • Envoy 的 xDS 动态配置实现了流量策略的热更新，无需重启服务
    •
