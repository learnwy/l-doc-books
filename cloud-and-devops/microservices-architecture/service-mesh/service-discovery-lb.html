服务发现与负载均衡

核心概念

服务发现（Service Discovery）是微服务架构中定位服务实例网络地址的核心机制。在单体应用中，所有功能运行在同一进程，函数调用是本地操作。微服务架构下，服务实例动态创建和销毁，IP 地址和端口不断变化，消费者需要一种动态发现可用服务实例的方式。服务发现与负载均衡配合，将请求分发到健康的服务实例上，是微服务通信的基础设施。

注册中心架构
服务注册中心是服务发现的核心组件，维护所有可用服务实例的地址信息。服务实例启动时向注册中心注册自己的地址，关闭时注销。注册中心通过健康检查机制定期验证实例可用性，自动移除不健康的实例。


Consul 是 HashiCorp 的服务注册中心，提供服务发现、健康检查、KV 存储和服务网格功能。Consul 采用 Raft 一致性协议保证注册数据的强一致性，通过 Gossip 协议实现集群成员管理和故障检测。Consul 的健康检查支持 HTTP、TCP、gRPC 和脚本四种方式，检查间隔和超时可按服务独立配置。


service {
  name = "webapp"
  port = 8080
  tags = ["production", "v2.1"]

  check {
    http     = "http://localhost:8080/health"
    interval = "10s"
    timeout  = "3s"
  }

  connect {
    sidecar_service {}
  }
}
etcd 和 ZooKeeper 是两种通用的分布式一致性存储，也被广泛用作服务注册中心的后端。etcd 是 Kubernetes 的默认存储，使用 Raft 协议。ZooKeeper 使用 ZAB 协议，是 Kafka 和 HBase 等系统的传统依赖。Nacos 是阿里巴巴开源的注册中心，支持 AP 和 CP 两种一致性模式切换，在国内微服务生态中广泛使用。


Kubernetes 原生的服务发现通过 Service 和 Endpoint 资源实现。每个 Service 创建一个虚拟 ClusterIP，kube-proxy 通过 iptables 或 IPVS 规则将发往 ClusterIP 的流量负载均衡到后端 Pod。CoreDNS 将 Service 名称解析为 ClusterIP，使服务可以通过 DNS 名称（<service>.<namespace>.svc.cluster.local）访问。

一致性哈希（Consistent Hashing）在缓存亲和性场景中尤为重要。请求按 Key（如用户 ID）哈希到哈希环上的固定节点，同一 Key 的请求始终路由到同一实例，充分利用本地缓存。当节点增减时，一致性哈希只重新映射 K/N 的 Key（K 为总 Key 数，N 为节点数），避免全量重分布。Envoy 和 Nginx 都支持一致性哈希负载均衡。


Zone-aware 负载均衡是多可用区部署的重要策略，优先将请求路由到与调用方相同可用区的实例，减少跨可用区的网络延迟和数据传输成本。只有当本区实例不健康或负载过高时才会跨区路由。Envoy 和 Istio 原生支持 Zone-aware 策略。


健康检查与优雅上下线
健康检查（Health Check）是保障服务发现数据准确性的关键机制。健康检查分为主动检查（注册中心/代理定期探测实例）和被动检查（根据实际请求的成功率判断健康状态）。


Kubernetes 的三种探针（Probe）覆盖了完整的健康检查生命周期：Startup Probe（启动检查，防止慢启动服务被错杀）、Readiness Probe（就绪检查，控制流量接入时机）、Liveness Probe（存活检查，检测运行时故障）。三者配合确保只有健康且就绪的实例接收流量。


优雅关闭（Graceful Shutdown）确保实例在下线前处理完所有进行中的请求。流程包括：接收关闭信号 → 停止接受新请求 → 从注册中心注销 → 等待进行中的请求完成（设定超时时间）→ 关闭连接和资源 → 进程退出。Kubernetes 的 preStop Hook 和 terminationGracePeriodSeconds 参数控制 Pod 的优雅关闭行为。


连接池预热（Connection Warming）在新实例加入负载均衡池后，逐步增加分配给它的流量比例。新实例可能需要加载缓存、建立数据库连接池等预热操作，突然接收大量流量可能导致超时。慢启动（Slow Start）配置使新实例在指定时间窗口内线性增加接收的请求权重。


小结
    

  • 服务发现分为客户端发现、服务端发现和平台原生三种模式，Kubernetes DNS 是最常用方案
    • 

  • 注册中心（Consul/etcd/Nacos）维护服务实例的动态地址信息和健康状态
    • 

  • 负载均衡策略按场景选择：轮询适合同质实例，一致性哈希适合缓存场景，P2C 适合大规模集群
    • 

  • Zone-aware 策略优先本区路由，减少跨可用区延迟
    • 

  • 三种 Kubernetes 探针覆盖启动、就绪和存活的完整健康检查生命周期
    • 

  • 优雅关闭和慢启动机制确保实例上下线时流量的平滑过渡
