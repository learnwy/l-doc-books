三大支柱集成

核心概念

可观测性（Observability）的三大支柱——指标（Metrics）、日志（Logs）和追踪（Traces）——各自提供了系统运行状态的不同视角。单独使用任何一根支柱都无法完整理解分布式系统的行为，只有将三者关联集成，才能构建从宏观健康概览到微观事件细节的完整诊断链路。集成的核心是通过共享上下文（如 TraceID、服务名称、时间范围）在三种数据类型之间建立关联。

Exemplar 关联机制
Exemplar 是 Prometheus 和 OpenTelemetry 引入的关联机制，将指标数据点与具体的追踪记录关联。当 Prometheus 记录一个直方图观测值时，可以附加一个 Exemplar 引用，包含对应请求的 TraceID。分析高延迟指标时，用户可以直接从异常数据点跳转到具体的追踪记录，查看该请求的完整调用链路。


http_request_duration_seconds_bucket{le="0.5"} 12345 # {traceID="abc123"} 0.48
http_request_duration_seconds_bucket{le="1.0"} 12890 # {traceID="def456"} 0.92
在 Grafana 中配置 Exemplar 后，指标图表上的数据点会显示为可点击的标记。点击后直接跳转到追踪系统（Jaeger/Tempo）查看对应的追踪详情。这种从宏观指标到微观追踪的一键下钻能力大幅缩短了故障排查时间。


统一关联标识
TraceID 是三大支柱集成的核心纽带。请求进入系统时，入口服务（API 网关或第一个接收请求的服务）生成全局唯一的 TraceID，该 ID 在请求经过的所有服务中传播。每个服务在记录指标、日志和追踪数据时都附带这个 TraceID，使三种数据可以通过 TraceID 精确关联。


OpenTelemetry 的 Baggage 机制允许在追踪上下文中携带额外的键值对（如 userId、tenantId），这些值在整个调用链路中传播，所有服务的指标和日志都可以使用这些值作为标签或字段。这使得"按用户维度查看端到端的指标+日志+追踪"成为可能。


服务元数据（Service Name、Service Version、Environment）是另一组关键的关联维度。OpenTelemetry 的 Resource 概念将这些元数据附加到所有遥测数据上，确保在不同后端系统中能够一致地过滤和关联同一服务的指标、日志和追踪。


Grafana 统一可观测平台
Grafana 是可观测性数据的统一可视化和查询平台，通过数据源（Data Source）机制连接 Prometheus（指标）、Loki（日志）、Tempo（追踪）、Jaeger 和 Elasticsearch 等多种后端。

Grafana 的 Explore 视图支持跨数据源的关联查询。在查看 Loki 日志时，可以将日志中的 TraceID 字段配置为链接到 Tempo 追踪视图。在查看 Prometheus 指标时，Exemplar 标记可直接跳转到追踪详情。在查看追踪详情时，可以展开每个 Span 查看对应时间范围内的日志。


仪表板设计的最佳实践：顶层仪表板展示黄金信号概览（SLI/SLO 状态），中层仪表板按服务展示详细指标，底层通过 Explore 深入日志和追踪。变量（Variables）和模板（Template）使同一仪表板适用于不同环境和服务实例。


集成架构模式
全栈可观测性的架构选型需要平衡功能、成本和运维复杂度。


PLG（Prometheus + Loki + Grafana + Tempo）全家桶是当前最流行的开源组合。四个组件由 Grafana Labs 维护，天然集成度最高。所有数据通过 OpenTelemetry SDK 和 Collector 统一采集，使用 Grafana 统一查询和可视化。

OpenTelemetry Collector 是实现后端无关的关键组件。应用通过 OTLP 协议将指标、日志和追踪统一发送到 Collector，Collector 通过配置的 Pipeline（Receiver → Processor → Exporter）将数据路由到不同的后端。更换后端只需修改 Collector 配置，无需修改应用代码。


小结
    

  • 三大支柱集成的核心是通过 TraceID、服务名和时间范围建立跨数据类型的关联
    • 

  • Exemplar 机制实现从指标异常数据点到具体追踪记录的一键下钻
    • 

  • OpenTelemetry 的 Resource 和 Baggage 提供统一的服务元数据和上下文传播
    • 

  • Grafana 作为统一平台连接多种后端，Explore 视图支持跨数据源的关联查询
    • 

  • PLG 全家桶是开源场景下集成度最高的组合，OpenTelemetry Collector 实现后端无关
    • 

  • 仪表板设计遵循概览→详情→深入的三层结构，变量和模板提高复用性
