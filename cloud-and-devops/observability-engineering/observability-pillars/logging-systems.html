Part VI · 可观测性与安全可观测性工程 简介可观测性三支柱 简介日志系统

日志系统

核心概念

日志（Logging）是可观测性三大支柱中信息最丰富的一根，以时间有序的文本记录捕获系统运行过程中的离散事件。日志记录了事件的完整上下文——请求参数、处理步骤、异常堆栈和业务决策，是故障排查和安全审计的核心数据源。与指标的聚合性质不同，日志保留了每个事件的完整细节，但代价是存储和查询成本显著更高。

结构化日志
结构化日志（Structured Logging）使用 JSON 或其他机器可解析格式替代传统的纯文本日志。结构化日志的每个字段都有明确的键名和类型，使日志分析工具能够精确地过滤、聚合和关联日志记录。


{
  "timestamp": "2025-01-15T10:23:45.123Z",
  "level": "ERROR",
  "service": "order-service",
  "traceId": "abc123def456",
  "spanId": "span789",
  "userId": "user_42",
  "method": "POST",
  "path": "/api/v1/orders",
  "statusCode": 500,
  "duration_ms": 234,
  "error": {
    "type": "InsufficientInventoryError",
    "message": "Product SKU-12345 out of stock",
    "stack": "InsufficientInventoryError: Product SKU-12345 out of stock\n    at InventoryService.reserve..."
  }
}
结构化日志的核心字段标准化是跨服务日志关联的基础。必选字段包括：timestamp（ISO 8601 格式）、level（日志级别）、service（服务名称）、traceId（分布式追踪 ID）。推荐字段包括：spanId、userId、requestId、duration_ms 和业务相关的上下文字段。


日志上下文传播通过日志框架的 MDC（Mapped Diagnostic Context）或 AsyncLocalStorage（Node.js）实现。请求进入服务时，中间件将 traceId、userId 等上下文信息注入日志上下文，该请求后续的所有日志自动携带这些字段，无需手动传递。


日志采样（Log Sampling）在高流量场景下控制日志量。采样策略包括：按比例采样（如记录 10% 的请求日志）、按条件采样（只记录错误和慢请求的详细日志）和动态采样（错误率升高时自动提升采样率）。头部采样（Head-based）在请求入口决定是否记录，尾部采样（Tail-based）在请求完成后根据结果决定是否保留。

Elasticsearch 作为日志存储引擎的核心配置包括：索引模板（定义字段映射和分析器）、索引生命周期管理（ILM，自动滚动、降级和删除索引）和分片策略（平衡查询性能和存储效率）。日志索引通常按天或按大小滚动，热数据使用 SSD 存储快速查询，温数据迁移到 HDD 节约成本，冷数据归档到对象存储。


Loki 是 Grafana Labs 推出的轻量级日志聚合系统，与传统方案不同，Loki 不对日志内容建立全文索引，而只索引标签（Label）。这种设计大幅降低了存储和运维成本，但牺牲了全文搜索性能。Loki 与 Grafana 的深度集成使其成为已使用 Prometheus + Grafana 的团队的自然选择。


日志安全与合规
日志数据包含大量敏感信息（用户身份、请求参数、会话令牌），需要在采集、传输和存储的全生命周期中实施安全保护。


脱敏（Masking/Redaction）在日志写入时对敏感字段进行处理：信用卡号保留后四位、密码替换为 ***、API 密钥截断显示。脱敏应在应用层实现而非依赖日志管道，确保敏感数据从源头就不进入日志流。

日志传输加密使用 TLS 保护从采集器到存储引擎的链路。存储加密使用磁盘级加密（如 LUKS）或存储服务的内置加密（S3 SSE-KMS）。访问审计记录谁在什么时间查看了哪些日志，满足合规框架对日志访问的追踪要求。


小结
    

  • 日志记录离散事件的完整上下文，是故障排查和安全审计的核心数据源，六个日志级别（TRACE→FATAL）对应不同的使用场景和生产环境策略
    • 

  • 结构化日志以 JSON 格式输出，字段标准化（timestamp、level、service、traceId）实现跨服务的日志关联和高效的机器解析
    • 

  • ELK/EFK 提供完整的日志采集-处理-存储-查询链路，Loki 以"只索引标签"的设计大幅降低存储成本
    • 

  • 日志采样（按比例、按条件、动态采样）和索引生命周期管理（热→温→冷→归档）是控制日志量和存储成本的关键手段
    • 

  • 日志安全覆盖源头脱敏、传输加密（TLS）、存储加密和访问审计，满足 GDPR/PCI DSS/SOC2 等合规要求
    • 

  • traceId 是连接日志与分布式追踪的关键桥梁，MDC/AsyncLocalStorage 实现请求级上下文的自动传播
    •
