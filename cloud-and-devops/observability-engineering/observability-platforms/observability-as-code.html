可观测性即代码

核心概念

可观测性即代码（Observability as Code, OaC）是将可观测性系统的所有配置——仪表盘、告警规则、SLO 定义、数据源配置和通知渠道——以声明式代码的形式管理，纳入版本控制系统，通过 CI/CD 流水线自动部署。OaC 将可观测性配置从"在 Web UI 上手动点击"转变为"在代码仓库中审查和提交"，解决了传统手动配置方式面临的三大问题：配置漂移（环境间不一致）、变更不可追溯和难以规模化管理。

OaC 的理念源自 Infrastructure as Code（IaC），核心原则是：声明式定义（描述期望状态而非操作步骤）、版本控制（所有变更可追溯可回滚）、自动化部署（通过 CI/CD 消除人工操作）和环境一致性（开发/预发/生产使用相同的配置模板）。

Terraform 管理可观测性资源
Terraform 通过其 Provider 生态系统可以管理几乎所有可观测性平台的资源。Grafana Provider 支持管理仪表盘、数据源、告警规则、文件夹和团队权限。Datadog Provider 和 New Relic Provider 同样提供了完整的资源管理能力。


interface TerraformGrafanaResources {
  datasource: {
    type: string;
    url: string;
    jsonDataEncoded: string;
  };
  folder: {
    title: string;
    uid: string;
  };
  dashboard: {
    configJson: string;
    folder: string;
    overwrite: boolean;
  };
  alertRule: {
    name: string;
    condition: string;
    notifications: string[];
  };
}
resource "grafana_data_source" "prometheus" {
  type = "prometheus"
  name = "Mimir-Production"
  url  = "https://mimir.internal:9009/prometheus"

  json_data_encoded = jsonencode({
    httpMethod   = "POST"
    exemplarTraceIdDestinations = [{
      datasourceUid = grafana_data_source.tempo.uid
      name          = "traceID"
    }]
  })
}

resource "grafana_folder" "platform" {
  title = "Platform Team"
  uid   = "platform-team"
}

resource "grafana_dashboard" "service_overview" {
  folder    = grafana_folder.platform.id
  overwrite = true

  config_json = templatefile("${path.module}/dashboards/service-overview.json", {
    datasource_uid = grafana_data_source.prometheus.uid
    environment    = var.environment
  })
}

resource "grafana_rule_group" "slo_alerts" {
  org_id           = 1
  name             = "SLO Alerts"
  folder_uid       = grafana_folder.platform.uid
  interval_seconds = 60

  rule {
    name      = "High Error Budget Burn Rate"
    condition = "C"

    data {
      ref_id = "A"
      relative_time_range {
        from = 3600
        to   = 0
      }
      datasource_uid = grafana_data_source.prometheus.uid
      model = jsonencode({
        expr = "sum(rate(http_requests_total{status=~\"5..\"}[1h])) / sum(rate(http_requests_total[1h]))"
      })
    }
  }
}
Grafana Provisioning
Grafana 内置的 Provisioning 机制允许通过 YAML 配置文件和 JSON 仪表盘文件来管理 Grafana 的数据源、仪表盘和告警通知渠道。这是一种比 Terraform 更轻量的 OaC 实现方式，特别适合 Kubernetes 环境中通过 ConfigMap 管理 Grafana 配置。


数据源 Provisioning：


apiVersion: 1
datasources:
  - name: Mimir
    type: prometheus
    access: proxy
    url: http://mimir-query-frontend:8080/prometheus
    isDefault: true
    jsonData:
      httpMethod: POST
      exemplarTraceIdDestinations:
        - datasourceUid: tempo
          name: traceID

  - name: Loki
    type: loki
    access: proxy
    url: http://loki-gateway:3100
    jsonData:
      derivedFields:
        - datasourceUid: tempo
          matcherRegex: "traceID=(\\w+)"
          name: TraceID
          url: '$${__value.raw}'

  - name: Tempo
    type: tempo
    access: proxy
    url: http://tempo-query-frontend:3100
    uid: tempo
    jsonData:
      tracesToLogsV2:
        datasourceUid: loki
        filterByTraceID: true
      tracesToMetrics:
        datasourceUid: mimir
仪表盘 Provisioning：将仪表盘 JSON 文件存储在 Git 仓库中，通过 Grafana 的 Dashboard Provider 自动加载。仪表盘文件中的硬编码值（数据源 UID、环境标识）应替换为变量，通过 CI/CD 流水线在部署时注入实际值。


Jsonnet 与仪表盘模板化
当需要管理数十个结构相似但参数不同的仪表盘时，手动维护 JSON 文件变得不可持续。Jsonnet（以及其库 Grafonnet）提供了仪表盘的编程化生成能力。


Grafonnet 是 Grafana 官方维护的 Jsonnet 库，将仪表盘的每个元素（Panel、Row、Template Variable）封装为可组合的函数。通过编写 Jsonnet 代码，可以定义仪表盘模板，然后参数化生成不同服务、不同环境的仪表盘实例。

CI/CD 集成与 GitOps
OaC 的最终目标是实现完整的 GitOps 工作流——所有可观测性配置的变更都通过 Git PR 提交、审查和自动部署。


标准 GitOps 流程：


    

  1. 工程师修改仪表盘/告警配置文件，提交 PR
    2. 

  2. CI 流水线运行验证：JSON/YAML 语法检查、Terraform plan（显示变更预览）、仪表盘 JSON 的 Schema 验证
    3. 

  3. 同行评审 PR——确认告警阈值合理、仪表盘查询正确
    4. 

  4. 合并 PR 后 CD 流水线自动部署：terraform apply 或 Grafana Provisioning 重载
    5. 

  5. 部署后自动验证：检查数据源连通性、仪表盘是否可访问、告警规则是否生效
    6. 



多环境管理：通过 Terraform Workspaces 或目录结构（envs/staging/, envs/production/）管理不同环境的配置差异。共享的仪表盘模板和告警逻辑定义在 modules/ 中，每个环境只需覆盖特定的参数（数据源 URL、告警阈值、通知渠道）。


小结
    

  • OaC 将可观测性配置从手动 UI 操作转变为声明式代码管理，解决配置漂移、变更不可追溯和规模化管理三大问题
    • 

  • Terraform Grafana Provider 可管理仪表盘、数据源、告警规则等全部资源，是企业级 OaC 的首选方案
    • 

  • Grafana Provisioning 是更轻量的 OaC 实现，适合 Kubernetes + ConfigMap 的部署模式
    • 

  • Grafonnet（Jsonnet）实现仪表盘的编程化生成，适合管理大量结构相似的仪表盘
    • 

  • GitOps 工作流确保所有配置变更经过 PR 审查和自动验证，支持回滚和审计
    • 

  • 多环境管理通过共享模板 + 环境参数覆盖实现，保证环境间配置的一致性
    •
