Terraform 基础

核心概念

Terraform 是 HashiCorp 推出的基础设施即代码（IaC）工具，通过声明式配置语言 HCL（HashiCorp Configuration Language）定义和管理云基础设施资源。Terraform 的核心理念是将基础设施的创建、修改和销毁转化为代码版本管理的工程实践，实现基础设施的可重复性、可审计性和自动化。

HCL 语法与资源定义
HCL 是一种介于配置语言和编程语言之间的声明式语言。它的设计目标是对人类可读可写，同时对机器可解析。


resource 块是 Terraform 的核心构建单元。每个 resource 块定义一个基础设施资源，指定资源类型（如 aws_instance）和本地名称。资源的属性通过键值对配置，引用其他资源的属性使用 resource_type.name.attribute 语法。


data 块用于查询已有的基础设施资源。例如查询最新的 AMI ID、已有的 VPC 信息或 DNS 区域。data 源只读不创建资源，在 plan 阶段执行查询。


variable 块定义输入参数，支持类型约束（string、number、bool、list、map、object）和默认值。输入变量通过命令行 -var 参数、.tfvars 文件或环境变量传入。sensitive 标志防止变量值在输出中显示。


output 块定义模块的输出值，用于向调用者暴露资源属性。例如输出创建的实例 ID、负载均衡器 DNS 名称或数据库连接字符串。output 值可以被其他模块引用或在 terraform output 中查看。


locals 块定义本地变量，用于中间计算和复杂表达式的复用。locals 不接受外部输入，仅在当前配置上下文中使用。


HCL 的表达式系统支持字符串插值（"${var.name}-instance"）、条件表达式（var.create ? 1 : 0）、for 表达式（[for s in var.list : upper(s)]）和内置函数（length、merge、file、cidrsubnet 等）。


执行流程与状态管理
Terraform 的执行流程遵循 init → plan → apply 三步工作法。


terraform init 初始化工作目录，下载 Provider 插件和远程模块，配置后端存储。init 是幂等操作，可以安全地多次执行。


terraform plan 创建执行计划，比较当前状态与期望配置之间的差异。plan 输出详细的变更列表（创建、修改、销毁），在不修改任何实际资源的情况下预览变更影响。plan 输出可以保存为文件（-out=plan.out）用于后续 apply。


terraform apply 执行变更计划，创建、修改或销毁基础设施资源。apply 按照依赖关系图的拓扑顺序执行操作，并行执行无依赖关系的操作以提高效率。


状态文件（terraform.tfstate）记录了 Terraform 管理的所有资源的当前状态。状态文件是 Terraform 的核心数据——它建立了配置文件中的资源定义与云平台上实际资源之间的映射关系。


远程状态后端（如 S3 + DynamoDB、Terraform Cloud、GCS）是生产环境的标准做法。远程后端解决了三个问题：团队共享状态（多人协作）、状态锁定（防止并发修改）和状态加密（保护敏感数据）。


Provider 与资源依赖
Provider 是 Terraform 与云平台或服务交互的插件。每个 Provider 封装了特定平台的 API 调用逻辑。AWS Provider（hashicorp/aws）、Google Provider（hashicorp/google）和 Azure Provider（hashicorp/azurerm）是最常用的三个。


Provider 配置定义了认证凭证和默认区域。多 Provider 配置（alias）允许在同一配置中管理多个区域或账户的资源。Provider 版本约束（required_providers）确保了团队使用一致的 Provider 版本。


资源依赖分为隐式依赖和显式依赖。当资源 A 引用了资源 B 的属性时，Terraform 自动推断 A 依赖 B（隐式依赖）。depends_on 参数指定无法通过属性引用推断的依赖关系（显式依赖）。


Terraform 根据依赖关系构建有向无环图（DAG），确定资源的创建和销毁顺序。terraform graph 命令输出依赖关系图的 DOT 格式，可以用 Graphviz 可视化。


lifecycle 块控制资源的生命周期行为。create_before_destroy 在销毁旧资源前先创建新资源，实现零停机更新。prevent_destroy 防止意外删除关键资源（如数据库、S3 桶）。ignore_changes 忽略特定属性的外部变更，避免 Terraform 覆盖手动或自动化工具的修改。replace_triggered_by 允许基于其他资源的变更触发资源替换。


Terraform 模块（Module）是配置复用的基本单元。模块封装了一组相关资源及其配置逻辑，通过 variable 接受输入，通过 output 暴露属性。公共模块发布在 Terraform Registry 上，私有模块可以通过 Git 仓库、S3 桶或私有 Registry 分发。模块的版本化（version 约束）确保了升级的可控性。

小结
    

  • Terraform 通过 HCL 声明式配置和状态文件管理实现基础设施的代码化管理
    • 

  • init → plan → apply 三步工作法确保变更的可预测性和安全性
    • 

  • 状态文件是 Terraform 的核心数据，远程后端（S3+DynamoDB）是生产必需
    • 

  • Provider 插件封装了云平台 API，支持多云和多区域资源管理
    • 

  • 资源依赖通过属性引用自动推断，DAG 确保正确的执行顺序
    • 

  • HCL 的类型系统和表达式能力支持复杂的基础设施配置
