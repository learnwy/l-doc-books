配置管理工具

核心概念

配置管理工具负责在服务器创建之后对其进行软件安装、配置文件管理和服务状态维护。与 Terraform 等资源编排工具不同，配置管理工具关注的是服务器内部的软件环境而非基础设施资源本身。Ansible、Chef、Puppet 和 SaltStack 是四大主流配置管理工具。

Ansible 架构与实践
Ansible 是目前最流行的配置管理工具，以无代理（Agentless）架构和简洁的 YAML 语法著称。Ansible 通过 SSH 连接目标主机执行任务，不需要在目标主机上安装任何代理软件。


Ansible 的核心概念包括 Inventory（主机清单）、Playbook（剧本）、Role（角色）和 Module（模块）。Inventory 定义管理的主机和分组。Playbook 是 YAML 格式的自动化脚本，定义在哪些主机上执行哪些任务。Role 是可复用的 Playbook 组织单位。Module 是执行具体操作的功能单元（如 apt、yum、copy、template）。


Playbook 的幂等性是 Ansible 的关键特性。大多数 Ansible Module 在执行前会检查目标状态，只有当前状态不符合期望时才执行操作。例如 apt 模块在软件包已安装时不会重新安装。这使得 Playbook 可以安全地多次执行。


Ansible Galaxy 是 Role 的社区仓库，提供了数千个预构建的 Role 覆盖常见的配置场景（如 Nginx 安装、MySQL 配置、安全加固）。ansible-galaxy install 下载并安装社区 Role。


Ansible 与 Terraform 的配合模式：Terraform 负责创建基础设施资源（VPC、EC2 实例、RDS），Ansible 负责在创建的实例上安装和配置软件。Terraform 的 local-exec provisioner 可以在资源创建后触发 Ansible Playbook。


Ansible 的高级特性包括 Vault（密钥管理）、Callback Plugin（自定义输出格式）和 Dynamic Inventory（从云平台 API 动态获取主机列表）。Dynamic Inventory 特别重要——在弹性伸缩环境中，主机列表不断变化，静态 Inventory 文件无法反映实时状态。AWS EC2 Dynamic Inventory 插件自动发现 EC2 实例并按标签、区域和状态分组。


Ansible 的执行性能可以通过多种方式优化。SSH 管道（pipelining = True）减少 SSH 连接次数。异步任务（async + poll）允许长时间任务在后台运行。Mitogen 插件通过 Python 进程注入替代 SSH 文件传输，将执行速度提升 3-7 倍。

配置漂移检测与修复
配置漂移（Configuration Drift）是指系统实际配置与预期配置之间的偏差。手动修改、临时调试和未受管的变更是漂移的主要来源。


检测漂移的方式包括：定期执行配置管理工具的 dry-run 模式（如 ansible-playbook --check）、使用 InSpec 或 Serverspec 编写合规测试、Terraform 的 terraform plan 检测资源漂移。


修复漂移的策略取决于漂移的类型和严重程度。对于 IaC 管理的资源，重新执行 terraform apply 或 ansible-playbook 可以将状态恢复到期望配置。对于严重漂移的服务器，不可变基础设施模式建议直接替换——销毁漂移的实例并从标准镜像重建。


持续合规（Continuous Compliance）将漂移检测集成到 CI/CD 流水线中。AWS Config Rules、Azure Policy 和 GCP Organization Policy 提供了云原生的合规检测能力。Open Policy Agent（OPA）提供了跨平台的策略引擎。


多环境配置策略
管理多个环境（开发、测试、预发布、生产）的配置是 IaC 的常见挑战。核心原则是代码复用和配置差异化。


Terraform Workspace 提供了在同一配置下管理多个环境状态的机制。每个 Workspace 有独立的状态文件，通过 terraform.workspace 变量在配置中区分环境。Workspace 适合配置相似的环境（如 staging 和 production），不适合配置差异大的环境。


目录结构隔离是更灵活的多环境策略。每个环境有独立的目录，共享模块通过 module 引用。环境特定的变量通过 .tfvars 文件传入。这种方式适合环境间配置差异较大的场景。


Terragrunt 是专门解决多环境管理的 Terraform 包装工具。它通过 DRY（Don't Repeat Yourself）原则消除了跨环境的配置重复。include 块继承公共配置，inputs 块注入环境特定的变量，dependency 块管理跨模块依赖。

小结
    

  • 配置管理工具负责服务器内部的软件安装和配置，与资源编排工具互补
    • 

  • Ansible 以无代理架构和 YAML 语法成为最流行的配置管理工具
    • 

  • 配置漂移检测和修复是持续合规的关键，不可变基础设施从根本上消除漂移
    • 

  • 多环境管理通过 Workspace、目录隔离或 Terragrunt 实现代码复用和配置差异化
    • 

  • IaC 技术栈通常组合使用：Terraform 编排资源、Ansible 管理配置、Packer 构建镜像
    • 

  • 选择工具时应考虑团队规模、基础设施复杂度和自动化程度
    •
