IaC 测试策略

核心概念

基础设施代码与应用代码一样需要系统化测试来保障质量。IaC 测试金字塔从底层的静态分析到顶层的端到端集成测试，逐层保障配置的正确性、安全性和合规性。完善的测试策略可以在变更上线前发现配置错误、安全漏洞和策略违规，显著降低基础设施变更的风险。

静态分析与安全扫描
静态分析不执行代码即可发现配置问题。这是 IaC 测试金字塔的基础层，应集成到开发者的本地工作流和 CI 管道中。


terraform validate 是最基础的检查，验证配置文件的语法正确性和内部一致性（如变量引用是否存在）。terraform fmt -check 检查代码格式是否符合标准。


tflint 是 Terraform 的高级 lint 工具。它检查最佳实践违反（如未使用的变量和声明）、云 API 约束（如不存在的实例类型、无效的 AMI ID）和自定义规则。tflint 通过插件支持 AWS、GCP 和 Azure 的特定规则。


Checkov 是全面的 IaC 安全扫描工具，支持 Terraform、CloudFormation、Kubernetes、Dockerfile 等多种格式。内置超过 1000 条安全策略，覆盖 CIS Benchmark、PCI DSS 和 SOC2 等合规框架。典型检测包括：S3 桶未启用加密、安全组允许 0.0.0.0/0 入站、RDS 实例未启用备份。


tfsec 专注于 Terraform 的安全扫描，检测速度快且误报率低。它支持自定义规则和忽略标记，可以逐步推进安全基线的提升。


策略即代码
策略即代码（Policy as Code）通过可编程的策略引擎在变更执行前强制执行组织规则。策略检查位于静态分析和 Plan 测试之间，是安全和合规的关键防线。


Open Policy Agent（OPA）是最流行的通用策略引擎。OPA 使用 Rego 语言编写策略，可以对 Terraform plan 的 JSON 输出进行断言验证。Conftest 是 OPA 的 CLI 封装，简化了 IaC 配置的策略测试。


常见策略规则包括：所有资源必须有标签（Team、Environment、CostCenter）、禁止使用特定实例类型（成本控制）、S3 桶必须启用加密和版本控制、安全组不允许 SSH 端口对外开放、数据库实例必须在私有子网。


Terraform Cloud/Enterprise 的 Sentinel 策略引擎提供了更深度的 Terraform 集成。Sentinel 策略在 Plan 之后 Apply 之前执行，可以检查 Plan 的变更细节（如将要创建的资源类型、将要修改的属性）。策略评估结果分为 advisory（建议）、soft-mandatory（可覆盖）和 hard-mandatory（强制）三个级别。


集成测试与 Terratest
集成测试在真实云环境中创建资源并验证其行为。Terratest 是最流行的 IaC 集成测试框架，使用 Go 语言编写测试用例。


Terratest 的典型测试流程：在独立的测试环境中执行 terraform init 和 apply，通过 AWS SDK 或 HTTP 请求验证创建的资源是否符合预期（如检查 EC2 实例是否在目标 VPC 中，ALB 是否返回 200 状态码），测试完成后执行 terraform destroy 清理所有资源。


测试隔离是集成测试的关键。每个测试用例使用独立的 Terraform 状态和随机化的资源名称前缀，避免与其他测试或环境冲突。测试 AWS 账户应与生产账户隔离，使用 SCP 限制可创建的资源类型和区域。


成本控制措施包括：在 CI 中设置测试超时确保 destroy 执行、使用 cloud-nuke 定期清理测试账户中的残留资源、在测试环境中限制可使用的实例类型和区域。

CI/CD 集成
IaC 测试应完整集成到 CI/CD 管道中，实现每次变更的自动化验证。


PR 阶段运行静态分析、安全扫描和策略检查。这些检查速度快且不产生云资源成本。PR 评审者应能看到 terraform plan 的输出，了解变更的具体影响。


合并后阶段运行集成测试（可选，对关键模块）和 terraform apply。生产环境的 apply 应要求人工审批，非生产环境可以全自动。


Atlantis 和 Terraform Cloud 提供了 PR 驱动的 Terraform 工作流。在 PR 中自动运行 plan 并将结果作为评论发布，审批后通过评论命令触发 apply。这种方式将基础设施变更的审查和执行统一在 Git 工作流中。


小结
    

  • IaC 测试金字塔从格式检查到端到端测试逐层保障配置质量和安全性
    • 

  • 静态分析（tflint/Checkov/tfsec）是成本最低但收益最高的测试层
    • 

  • 策略即代码通过 OPA/Sentinel 在变更执行前强制执行组织规则
    • 

  • Terratest 在真实云环境中进行集成测试，验证资源的实际行为
    • 

  • 测试隔离和成本控制是集成测试的工程挑战，需要独立账户和清理机制
    • 

  • CI/CD 集成确保每次变更都经过完整的测试验证，Atlantis 提供 PR 驱动的工作流
    •
