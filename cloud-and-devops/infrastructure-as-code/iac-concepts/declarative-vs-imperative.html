声明式与命令式对比

核心概念

在基础设施即代码（IaC）领域，声明式和命令式是两种根本不同的编程范式。声明式描述"系统应该是什么样子"（What），命令式描述"如何一步步达到目标"（How）。这两种范式的选择深刻影响了团队的工作方式、代码的可维护性和系统的可靠性。

Terraform 的声明式模型
Terraform 使用 HCL（HashiCorp Configuration Language）作为声明式配置语言。用户定义资源的期望属性，Terraform 引擎负责计算当前状态与期望状态的差异并执行必要的变更。


HCL 的设计哲学是"对人类可读可写，对机器可解析"。resource 块定义资源，data 块查询已有资源，variable 块定义参数，output 块导出值。这种结构化的语法使配置文件即是文档。


Terraform 的 plan-apply 工作流是声明式范式的典型体现。plan 阶段计算差异但不执行变更，apply 阶段执行变更并更新状态。这种两阶段模型提供了变更预览的安全网。


声明式的局限性体现在复杂逻辑上。HCL 的 for_each、dynamic 块和条件表达式虽然提供了一定的编程能力，但在处理复杂的条件分支、错误处理和外部 API 调用时不如通用编程语言方便。


Terraform 模块是声明式配置的复用单元。模块封装了一组相关资源的配置，通过输入变量和输出值定义接口。公共模块仓库（Terraform Registry）提供了数千个社区维护的模块，覆盖了常见的基础设施模式。


Pulumi 的命令式模型
Pulumi 允许使用 TypeScript、Python、Go、C# 和 Java 等通用编程语言定义基础设施。每个资源是一个类的实例，资源之间通过变量引用建立依赖关系。Pulumi 引擎分析依赖图并生成执行计划。


命令式模型的核心优势在于可以利用编程语言的完整能力。条件创建资源只需 if 语句，批量创建资源用 for 循环，复用逻辑用函数和类。类型系统提供了编译时的配置验证。单元测试框架可以直接测试基础设施代码。


Pulumi 的 ComponentResource 类似于 Terraform 的模块，将相关资源封装为可复用的组件。但 ComponentResource 是真正的 OOP 类——支持继承、组合和多态，复用能力更强。


Pulumi 的 Automation API 允许在应用代码中嵌入基础设施管理。这使得创建自助服务平台、动态环境和测试基础设施变得可能。例如 CI/CD 管道可以在测试前自动创建隔离的云环境，测试后自动销毁。


CDK 与混合范式
AWS CDK（Cloud Development Kit）代表了声明式和命令式的混合范式。用户使用 TypeScript 或 Python 编写 Construct（构造），CDK 将其合成（Synthesize）为 CloudFormation 模板后部署。


CDK 的三层 Construct 抽象：L1 Construct 是 CloudFormation 资源的一对一映射，L2 Construct 封装了最佳实践和合理默认值（如 S3 Bucket 自动启用加密），L3 Construct 组合多个资源为完整的架构模式（如 VPC + 子网 + NAT Gateway）。


Terraform CDK（CDKTF）将 CDK 的理念引入 Terraform 生态。用户使用 TypeScript 或 Python 编写配置，CDKTF 将其转换为 Terraform JSON 配置并执行。这为偏好编程语言的团队提供了使用 Terraform Provider 的途径。

实践中的选型策略
团队在选择声明式或命令式工具时，应考虑以下因素。


小型团队或运维导向的团队倾向于 Terraform。HCL 语法简单，社区资源丰富，不需要深厚的编程背景。Terraform 的 plan 输出清晰直观，适合变更审查。


开发者导向的团队倾向于 Pulumi 或 CDK。使用团队熟悉的编程语言降低了学习成本，IDE 的代码补全和类型检查提升了编写效率。单元测试和集成测试可以复用已有的测试框架。


大型组织通常同时使用多种工具。平台团队使用 Terraform 管理底层基础设施（网络、安全、共享服务），应用团队使用 CDK 或 Pulumi 管理应用层资源。标准化的模块和组件库确保跨团队的一致性。


小结
    

  • 声明式范式描述期望状态，天然幂等且易于理解，Terraform 是代表
    • 

  • 命令式范式利用通用编程语言，灵活性强且开发体验好，Pulumi 是代表
    • 

  • CDK 系列工具代表混合范式，用编程语言编写后合成为声明式配置
    • 

  • 选型需考虑团队背景、项目复杂度和组织标准化需求
    • 

  • 大型组织通常混合使用声明式和命令式工具，平台团队和应用团队各取所需
    • 

  • 无论选择哪种范式，版本控制、代码审查和自动化测试都是必须的工程实践
    •
