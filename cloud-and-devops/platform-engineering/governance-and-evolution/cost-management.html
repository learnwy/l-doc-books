成本管理

核心概念

成本管理是平台工程中连接技术决策与业务价值的关键环节。云原生架构下，资源使用量与成本直接挂钩——每个 Pod、每个数据库实例、每次 CI 构建都在产生费用。FinOps（Financial Operations）实践将成本意识融入工程文化，让每个团队都能看到和管理自己的云支出。

平台工程在成本管理中扮演双重角色：一方面，平台提供成本可见性工具，让团队了解自己的支出；另一方面，平台通过标准化和自动化降低整体成本——黄金路径中的资源规格推荐、闲置资源检测、自动扩缩容等能力都是成本优化的手段。

FinOps 实践
FinOps 框架将云成本管理分为三个阶段：通知（Inform）、优化（Optimize）和运营（Operate）。平台工程为每个阶段提供工具支撑。


interface FinOpsPhases {
  inform: {
    goal: '让每个团队看到自己的成本';
    capabilities: [
      '实时成本仪表板（按团队/服务/环境）',
      '成本趋势分析（日/周/月）',
      '预算 vs 实际对比',
      '异常支出告警',
    ];
    tools: ['Kubecost', 'OpenCost', '云厂商 Cost Explorer'];
  };
  optimize: {
    goal: '识别和执行节约机会';
    capabilities: ['资源规格推荐（right-sizing）', '闲置资源检测', '预留实例 / Savings Plans 建议', 'Spot 实例策略'];
    tools: ['Kubecost', 'CAST AI', 'Spot.io'];
  };
  operate: {
    goal: '将成本优化融入日常流程';
    capabilities: ['成本预算自动化', '资源申请的成本预估', '成本异常自动化响应', 'FinOps 文化培养'];
    tools: ['平台自建 + FinOps 框架'];
  };
}
finops_implementation:
  tagging_strategy:
    required_tags:
      - key: 'team'
        description: '负责团队'
        source: 'catalog-info.yaml 自动继承'
      - key: 'service'
        description: '所属服务'
        source: 'Kubernetes 标签自动继承'
      - key: 'environment'
        description: '环境类型（dev/staging/prod）'
        source: '命名空间标签'
      - key: 'cost-center'
        description: '成本中心'
        source: '团队元数据'
    enforcement:
      - 'Kubernetes: 准入控制器强制标签'
      - 'Cloud: SCP/Tag Policy 强制标签'
      - 'CI: 构建时验证资源标签完整性'
    coverage_target: '> 95% 资源有完整标签'
资源标签是成本归属的基础。没有完整的标签，就无法将成本准确分摊到团队和服务。平台团队应该通过准入控制器强制所有 Kubernetes 资源带有标准标签，云资源通过 Tag Policy 强制。


资源归属与分摊
成本归属将云账单中的每一笔费用归属到具体的团队、服务和环境，让成本透明化。


interface CostAttribution {
  directCosts: {
    description: '可直接归属到服务的资源成本';
    examples: ['专用数据库实例', 'Pod CPU/内存', '专用缓存'];
    method: '通过标签直接映射';
  };
  sharedCosts: {
    description: '多团队共享的基础设施成本';
    examples: ['Kubernetes 控制面', '日志存储', '网络带宽', '平台团队人力'];
    allocationMethods: {
      proportional: '按资源使用比例分摊';
      equal: '平均分摊到所有团队';
      fixed: '固定比例（基于 SLA 等级）';
    };
  };
  unattributed: {
    description: '无法归属的成本';
    target: '< 5% 总成本';
    handling: '归入平台公共成本池';
  };
}
cost_report_template:
  team_monthly_report:
    header:
      team: 'Order Team'
      period: '2024-03'
      total_cost: '$12,450'
      budget: '$15,000'
      utilization: '83%'

    breakdown_by_service:
      - service: 'order-service'
        cost: '$4,200'
        trend: '+5%'

          - 'EKS Pods (8 replicas): $1,400'
          - 'ElastiCache Redis: $700'

        cost: '$3,800'
        trend: '-2%'

    breakdown_by_environment:
      production: '$8,200 (66%)'
      staging: '$2,500 (20%)'
      development: '$1,750 (14%)'

    optimization_opportunities:
      - type: 'right-sizing'
        resource: 'order-service staging pods'
        current: '4 pods x 2CPU/4GB'
        recommended: '2 pods x 1CPU/2GB'
        monthly_savings: '$300'

      - type: 'idle-resource'
        resource: 'test-db-20240201'
        idle_since: '2024-02-15'
        monthly_cost: '$150'
        action: '确认后删除'
成本报告应该是可操作的——不仅展示"花了多少"，更要指出"哪里可以省"。每份报告都应该包含具体的优化建议和预估节约金额，让团队能立即行动。


成本可视化与预算管理
成本仪表板将复杂的账单数据转化为直观的可视化，帮助团队实时了解支出状况。


interface BudgetManagement {
  budgetSetting: {
    granularity: '按团队 + 环境设置';
    method: '历史基线 + 预期增长 + 优化目标';
    approval: '团队主管 + 工程 VP';
  };
  alerting: {
    thresholds: [
      { level: 'info'; percent: 70; channel: 'email' },
      { level: 'warning'; percent: 85; channel: 'slack' },
      { level: 'critical'; percent: 95; channel: 'pagerduty' },
      { level: 'breach'; percent: 100; channel: 'all + 自动冻结非生产资源' },
    ];
  };
  enforcement: {
    softLimit: '超预算告警，不阻断操作';
    hardLimit: '严重超预算时冻结非生产环境资源创建';
    exception: '紧急业务需求可申请临时配额提升';
  };
  forecasting: {
    method: '基于历史趋势和已知变更的线性预测';
    horizon: '3 个月滚动预测';
    alerts: '预测超预算时提前 30 天告警';
  };
}
预算管理的核心理念是"透明但不阻断"。大多数情况下，预算超支应该触发告警和讨论，而非自动阻断服务。只有在严重超预算且持续不处理时，才考虑强制措施（如冻结非生产资源）。


平台级成本优化
平台团队拥有跨组织的视角，能够识别和执行全局性的成本优化策略。


interface PlatformCostOptimization {
  rightSizing: {
    description: '根据实际使用量调整资源规格';
    automation: 'VPA 推荐 → 平台评估 → 自动调整（非生产）';
    humanReview: '生产环境 right-sizing 需要确认';
    savings: '平均可节省 20-30% 计算成本';
  };
  spotInstances: {
    description: '使用竞价实例降低计算成本';
    scope: 'CI 构建、非生产环境、无状态工作负载';
    fallback: '竞价中断时自动切换到按需实例';
    savings: '可节省 60-80% 计算成本';
  };
  scheduledScaling: {
    description: '按时间计划调整资源';
    rules: ['非生产环境工作日 8:00-20:00 全量、其他时间缩容到 0', 'CI Runner 工作日峰值扩容、周末缩容'];
    savings: '非生产环境可节省 50-60%';
  };
  reservedCapacity: {
    description: '预留实例 / Savings Plans';
    scope: '稳定的生产工作负载';
    analysis: '基于 6 个月历史数据推荐预留策略';
    savings: '可节省 30-50% 长期运行成本';
  };
  wasteElimination: {
    idleResources: '30 天无访问 → 通知 → 60 天 → 自动暂停';
    orphanResources: '无 owner 标签 → 限期认领 → 自动删除';
    overProvisioned: 'CPU 使用率 < 10% 持续 7 天 → right-sizing 建议';
  };
}
平台级成本优化的最大杠杆通常来自三个方面：非生产环境的定时关停（节省 50-60%）、闲置资源回收（节省 10-20%）和计算资源 right-sizing（节省 20-30%）。平台团队应该自动化这些优化策略，让成本控制成为平台的默认能力。


小结
    

  • FinOps 将成本管理分为通知（看到成本）、优化（降低成本）和运营（持续管理）三个阶段
    • 

  • 资源标签是成本归属的基础，覆盖率目标 > 95%
    • 

  • 成本报告应可操作——不仅展示支出，更要指出优化机会
    • 

  • 预算管理遵循"透明但不阻断"原则，严重超支才考虑强制措施
    • 

  • 最大节约杠杆：非生产环境定时关停、闲置回收、right-sizing
    • 

  • 成本意识应融入工程文化，让每个团队都能看到和管理自己的支出
    •
