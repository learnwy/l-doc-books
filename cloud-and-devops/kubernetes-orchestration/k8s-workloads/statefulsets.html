StatefulSet 与有状态应用

核心概念

StatefulSet 是 Kubernetes 中管理有状态应用的工作负载资源。与 Deployment 不同，StatefulSet 为每个 Pod 提供稳定的网络标识和持久化存储，Pod 的创建、删除和更新遵循严格的顺序保证。数据库、消息队列和分布式存储等有状态服务依赖这些特性来维护数据一致性和集群成员关系。

稳定网络标识与 Headless Service
StatefulSet 的每个 Pod 拥有基于序号的固定名称（如 mysql-0、mysql-1、mysql-2），即使 Pod 被重建也保持不变。这种稳定性对分布式系统的节点发现和集群组建至关重要。


Headless Service（ClusterIP 设为 None 的 Service）为 StatefulSet 的每个 Pod 创建独立的 DNS A 记录。Pod 的 DNS 名称格式为 {pod-name}.{headless-service}.{namespace}.svc.cluster.local。例如 mysql-0.mysql-headless.default.svc.cluster.local 始终解析到 mysql-0 Pod 的 IP，即使 Pod 被重建后 IP 发生变化。


这种稳定的 DNS 名称使得分布式系统的节点可以通过固定地址互相发现和通信。MySQL 的主从复制可以配置从节点指向 mysql-0 作为主节点。ZooKeeper 集群的成员列表可以使用 Pod DNS 名称。Redis Cluster 的节点间通信也依赖稳定的网络标识。


StatefulSet Pod 的顺序创建和删除保证了集群初始化的正确性。对于需要先启动主节点再启动从节点的数据库集群，Pod-0 总是第一个创建和就绪。缩容时 Pod 按逆序删除，最后一个加入的节点最先被移除。podManagementPolicy 可以设为 Parallel 来放宽顺序约束，适合不需要严格顺序的场景。


持久化存储与 VolumeClaimTemplate
volumeClaimTemplate 是 StatefulSet 的关键特性。它为每个 Pod 自动创建独立的 PersistentVolumeClaim（PVC），确保每个实例拥有专属的存储卷。当 Pod 被重建时，它会重新挂载到之前的 PVC，实现数据持久化。


PVC 的名称由 volumeClaimTemplate 名称和 Pod 名称组合而成（如 data-mysql-0）。即使 StatefulSet 被删除，PVC 默认不会被自动删除（persistentVolumeClaimRetentionPolicy 可以改变此行为），确保数据安全。


存储类（StorageClass）决定了 PV 的动态供给方式。EBS CSI Driver 创建 EBS 卷，EFS CSI Driver 创建 EFS 访问点。不同的存储类提供不同的性能特征（IOPS、吞吐量）和可用区约束。


StatefulSet 扩容时自动为新 Pod 创建 PVC。缩容时 Pod 被删除但 PVC 保留。再次扩容时，Pod 会重新绑定到之前的 PVC，无需数据迁移。这种设计使得有状态应用的扩缩容变得安全和高效。


StatefulSet 更新策略
StatefulSet 支持两种更新策略：RollingUpdate 和 OnDelete。


RollingUpdate 是默认策略，按照 Pod 序号从高到低逐个更新。每个 Pod 更新完成并就绪后才更新下一个。partition 参数可以实现分阶段更新——只有序号大于等于 partition 值的 Pod 会被更新。这为金丝雀发布提供了原生支持。


例如，设置 partition=2 后更新 StatefulSet，只有 Pod-2 及之后的 Pod 会更新到新版本，Pod-0 和 Pod-1 保持旧版本。验证新版本后将 partition 设为 0 完成全量更新。


OnDelete 策略要求手动删除 Pod 才会触发更新。Pod 被删除后，StatefulSet 控制器创建的新 Pod 将使用更新后的模板。这种策略适合需要精确控制更新时机的场景。


有状态应用的更新比无状态应用更加复杂。数据库主从切换、集群成员变更和数据迁移可能需要在 Pod 更新前后执行特定操作。PreStop Hook 和 Init Container 可以在一定程度上自动化这些操作，但复杂场景通常需要 Operator 来协调。


Operator 模式
Operator 模式将运维知识编码为 Kubernetes 控制器，自动管理有状态应用的完整生命周期。Operator 通过自定义资源（CRD）扩展 Kubernetes API，实现特定应用的声明式管理。


数据库 Operator 的典型能力包括：自动初始化集群（主从配置、权限设置）、自动备份和恢复（定时快照、时间点恢复）、自动扩缩容（添加/移除从节点）、自动故障转移（检测主节点故障并提升从节点）和自动版本升级（滚动更新数据库版本）。


常见的数据库 Operator 包括：CloudNativePG（PostgreSQL）、Percona XtraDB Cluster Operator（MySQL）、MongoDB Community Operator 和 Redis Operator。

小结
    

  • StatefulSet 为有状态应用提供稳定的网络标识、有序的部署和删除以及持久化存储
    • 

  • Headless Service 为每个 Pod 创建固定 DNS 记录，支持分布式系统的节点发现
    • 

  • volumeClaimTemplate 为每个 Pod 自动创建独立 PVC，缩容时 PVC 保留确保数据安全
    • 

  • 更新策略支持 RollingUpdate（可配合 partition 实现金丝雀）和 OnDelete
    • 

  • Operator 模式将有状态应用的运维知识编码为控制器，实现自动化生命周期管理
    • 

  • 选择自建 StatefulSet 还是使用 Operator 取决于应用复杂度和团队能力
    •
