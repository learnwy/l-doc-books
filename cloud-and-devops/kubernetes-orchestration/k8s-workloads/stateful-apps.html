有状态应用管理

核心概念

有状态应用（Stateful Applications）在处理请求时依赖持久化数据或维护会话状态。数据库、消息队列、缓存集群和分布式文件系统都属于有状态应用。Kubernetes 通过 StatefulSet、PersistentVolume 和 Headless Service 提供了管理有状态应用的完整机制。

PersistentVolume 与存储配置
PersistentVolume（PV）是集群级的存储资源抽象。PV 可以由管理员预创建（Static Provisioning）或通过 StorageClass 动态创建（Dynamic Provisioning）。动态供给是生产环境的标准做法，用户创建 PVC 时自动触发 PV 的创建。


StorageClass 定义了存储供给者（Provisioner）和参数。AWS EBS CSI Driver 的 StorageClass 可配置卷类型（gp3/io2）、加密、IOPS 和吞吐量。不同工作负载使用不同的 StorageClass 匹配性能和成本需求。


PVC 的访问模式决定了卷的共享能力。ReadWriteOnce（RWO）允许单节点读写，适合 EBS 等块存储。ReadWriteMany（RWX）允许多节点同时读写，适合 EFS 等文件存储。ReadOnlyMany（ROX）允许多节点只读。


卷扩容（Volume Expansion）允许在不停机的情况下扩大 PVC 容量。StorageClass 设置 allowVolumeExpansion: true 启用此功能。修改 PVC 的 spec.resources.requests.storage 后，CSI Driver 自动扩容底层卷并扩展文件系统。


VolumeSnapshot 提供了 PV 的快照能力。通过 VolumeSnapshotClass 和 VolumeSnapshot CRD，可以在 Kubernetes 原生创建和恢复存储快照。快照可以用于数据备份、克隆环境和灾难恢复。


StatefulSet 的更新策略通过 updateStrategy 字段配置。RollingUpdate（默认）按逆序逐个更新 Pod（从最大序号到 0）。partition 参数实现金丝雀更新——只更新序号 ≥ partition 的 Pod，允许分批验证新版本。OnDelete 策略要求手动删除 Pod 才会触发更新，适合需要精确控制更新时机的场景。

Operator 模式与数据库运维
Kubernetes Operator 将有状态应用的运维知识编码为自动化控制器。Operator 通过 CRD 扩展 Kubernetes API，实现数据库集群的声明式管理。


CloudNativePG 是 PostgreSQL 的 Kubernetes Operator，提供集群自动部署、主从复制管理、自动故障转移、备份恢复和滚动更新。创建一个 Cluster CR 即可获得完整的 PostgreSQL 高可用集群，包含主节点、同步/异步从节点和自动备份策略。


Percona Operator for MySQL 管理 Percona XtraDB Cluster 和 MySQL Group Replication。Redis Operator 管理 Redis Sentinel 和 Redis Cluster 模式。Strimzi 管理 Apache Kafka 集群。


Operator 的分级成熟度模型（Operator Capability Level）定义了五个级别：Level 1（基本安装）、Level 2（升级）、Level 3（生命周期管理）、Level 4（深度洞察）和 Level 5（自动驾驶）。成熟的 Operator 应达到 Level 3 以上。


有状态应用的备份与恢复
数据备份是有状态应用运维的核心。Kubernetes 环境下的备份策略包括应用级备份和存储级备份。


应用级备份使用数据库原生的备份机制。PostgreSQL 的 pg_dump/pg_basebackup、MySQL 的 mysqldump/xtrabackup 和 MongoDB 的 mongodump。Operator 通常将备份自动化，定时执行备份并上传到 S3 等对象存储。


存储级备份使用 VolumeSnapshot 创建 PV 快照。快照是块级别的，速度比应用级备份更快，但恢复时需要确保数据一致性。对于数据库，应在创建快照前暂停写入或使用支持 crash-consistent 的文件系统。


Velero 是 Kubernetes 级别的备份恢复工具。它可以备份整个 Namespace 或选定资源（包括 PV 数据），支持定时备份和跨集群恢复。Velero 特别适合灾难恢复和集群迁移场景。


备份频率和保留策略需要根据业务 RPO（恢复点目标）和 RTO（恢复时间目标）确定。核心交易数据库的 RPO 通常要求分钟级（WAL 归档 + 流复制），日志和分析型数据库的 RPO 可以放宽到小时级。定期执行恢复演练验证备份的有效性是生产环境的必要实践——未经验证的备份等同于没有备份。

小结
    

  • 有状态应用通过 StatefulSet 获得稳定标识、有序操作和独立存储
    • 

  • PersistentVolume 通过 StorageClass 动态供给，支持卷扩容和快照
    • 

  • Operator 模式将数据库运维自动化，CloudNativePG 和 Strimzi 是成熟代表
    • 

  • 备份策略应结合应用级备份和存储级备份，Velero 提供集群级备份恢复
    • 

  • 有状态应用的更新和扩缩容比无状态更复杂，需要考虑数据一致性和集群成员关系
    • 

  • 生产环境建议使用成熟的 Operator 而非手动管理有状态应用
