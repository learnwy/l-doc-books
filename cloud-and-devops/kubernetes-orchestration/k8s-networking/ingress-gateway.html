Ingress 与 Gateway API

核心概念

Ingress 和 Gateway API 是 Kubernetes 中管理集群外部 HTTP/HTTPS 流量入口的标准机制。Ingress 通过声明式规则定义 URL 路径和主机名到 Service 的映射，Ingress Controller 负责实际的流量路由。Gateway API 是 Ingress 的下一代演进，提供了更丰富的路由能力和更清晰的关注点分离。

Ingress 配置与路由
Ingress 资源定义了外部请求到集群内 Service 的路由规则。每个 Ingress 规则包含可选的主机名匹配和一组路径规则。


基于路径的路由是最常用的配置方式。pathType 支持三种模式：Exact（精确匹配）、Prefix（前缀匹配）和 ImplementationSpecific（由 Controller 决定）。Prefix 模式下 /api 匹配 /api、/api/ 和 /api/users。


基于主机名的路由通过 host 字段配置。同一 Ingress Controller 可以服务多个域名，每个域名路由到不同的 Service。通配符主机名（如 *.example.com）匹配所有子域名。


TLS 终止通过 Ingress 的 tls 字段配置。SSL 证书存储在 Kubernetes Secret 中（type: kubernetes.io/tls），Ingress 引用 Secret 名称。cert-manager 自动从 Let's Encrypt 等 CA 申请和续期证书，与 Ingress 无缝集成。


Ingress 的 annotations 提供了 Controller 特定的配置能力。nginx-ingress 通过 annotations 配置 CORS、速率限制、重写规则、自定义 Header 和上游超时。不同 Controller 的 annotations 格式不统一，这也是 Gateway API 要解决的问题之一。


常见的 Ingress Controller 包括：nginx-ingress-controller（最广泛使用）、Traefik（自动服务发现和 Let's Encrypt 集成）、HAProxy Ingress 和 AWS ALB Ingress Controller（基于 AWS ALB 实现，不需要额外的代理层）。


选择 Ingress Controller 需要综合评估性能、功能和运维成本。nginx-ingress 社区版（kubernetes/ingress-nginx）与商业版（nginxinc/kubernetes-ingress）在功能和许可上有显著差异。Traefik 的自动配置发现和中间件链机制降低了运维复杂度。在 AWS 环境中，ALB Ingress Controller 利用原生 ALB 的弹性伸缩和 WAF 集成能力，避免了额外管理反向代理实例的开销。

Gateway API 架构与实践
Gateway API 通过分层资源模型解决了 Ingress 的局限性。GatewayClass 定义基础设施实现（由平台团队管理），Gateway 定义集群入口点（由集群运维管理），HTTPRoute/TCPRoute/GRPCRoute 定义路由规则（由应用团队管理）。


这种分层设计天然支持多租户场景。平台团队提供 GatewayClass，每个团队创建自己的 Gateway 和 Route，通过 RBAC 和 Namespace 隔离实现权限控制。


HTTPRoute 的路由匹配条件比 Ingress 更丰富。除了路径和主机名，还支持 HTTP Method、Header 和 Query Parameter 匹配。BackendRef 的 weight 字段原生支持流量分割——将 90% 流量路由到稳定版本，10% 路由到金丝雀版本。


Filter 是 Gateway API 的请求/响应转换机制。RequestHeaderModifier 添加或修改请求头。URLRewrite 重写请求路径。RequestRedirect 执行 HTTP 重定向。RequestMirror 将请求复制到镜像后端用于测试。


高级流量管理
SSL/TLS 管理是入口流量的安全基础。Ingress/Gateway 的 TLS 终止在边缘解密 HTTPS 流量，后端 Service 使用明文 HTTP 通信。端到端 TLS 要求后端也使用 HTTPS，通过 Gateway API 的 BackendTLSPolicy 配置。


IP 访问控制通过 annotations（Ingress）或附加策略（Gateway API）限制客户端 IP。速率限制防止 API 滥用，基于客户端 IP 或 HTTP Header 限制请求频率。


跨域资源共享（CORS）配置允许浏览器跨域访问 API。nginx-ingress 通过 nginx.ingress.kubernetes.io/enable-cors annotation 启用 CORS，自定义允许的 Origin、Method 和 Header。


WebSocket 和 gRPC 协议需要特殊的 Ingress/Gateway 配置。WebSocket 需要保持长连接，nginx-ingress 通过 proxy-read-timeout 和 proxy-send-timeout 设置连接超时。gRPC 需要 HTTP/2 支持，nginx-ingress 通过 nginx.ingress.kubernetes.io/backend-protocol: GRPC annotation 启用。

小结
    

  • Ingress 通过路径和主机名路由 HTTP/HTTPS 流量到集群内 Service
    • 

  • cert-manager 自动管理 TLS 证书，与 Ingress 和 Gateway API 无缝集成
    • 

  • Gateway API 通过 GatewayClass/Gateway/Route 分层模型提供更好的多租户支持
    • 

  • HTTPRoute 原生支持 Header 匹配、流量分割和请求转换，超越 Ingress 的能力
    • 

  • Ingress Controller 选择（nginx/Traefik/ALB）影响可用特性和性能特征
    • 

  • Gateway API 是 Ingress 的演进方向，新项目推荐优先采用 Gateway API
