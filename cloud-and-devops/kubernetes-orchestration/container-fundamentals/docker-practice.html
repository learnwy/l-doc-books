Docker 实践

核心概念

Docker 是最流行的容器化平台，将容器技术从底层 Linux 特性提升为开发者友好的工具链。Docker 生态包括 Docker Engine（容器运行时）、Docker CLI（命令行工具）、Docker Compose（多容器编排）和 Docker Hub（镜像仓库）。掌握 Docker 的核心操作和最佳实践是进入容器化世界的第一步。

Dockerfile 编写最佳实践
Dockerfile 的质量直接影响镜像大小、构建速度和运行安全性。生产级 Dockerfile 需要遵循一系列最佳实践。


基础镜像选择是第一个关键决策。Alpine Linux（约 5MB）是最常用的精简基础镜像，但其使用 musl libc 可能与某些依赖不兼容。Debian Slim（约 80MB）提供了更好的兼容性。Google 的 Distroless 镜像只包含应用运行时，没有 shell 和包管理器，安全性最高。


多阶段构建将编译和运行分离为不同阶段。第一阶段使用包含编译工具链的完整镜像构建应用，第二阶段只从第一阶段复制编译产物到精简基础镜像。这种方式可以将 Node.js 应用的镜像从 1GB 减少到 100MB 以下。


FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --production=false
COPY . .
RUN npm run build

FROM node:20-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
EXPOSE 3000
CMD ["node", "dist/index.js"]
层缓存优化是加速构建的关键。将变化频率低的指令放在前面（如 COPY package.json 和 RUN npm install），变化频率高的指令放在后面（如 COPY . .）。这样当只修改应用代码时，依赖安装层可以命中缓存。


安全实践包括：使用非 root 用户运行容器（USER 指令）、不在镜像中包含敏感信息（密钥、密码）、使用 .dockerignore 排除不需要的文件、定期更新基础镜像获取安全补丁、使用镜像扫描工具检测已知漏洞。


Docker Compose 服务编排
Docker Compose 使用 YAML 文件定义多容器应用的完整环境。它简化了服务间的网络连接、存储挂载和启动顺序管理，是本地开发和测试的标准工具。


Compose 文件定义了服务（services）、网络（networks）和卷（volumes）三个顶级概念。每个服务对应一个容器定义，包括镜像、端口映射、环境变量、健康检查和依赖关系。


服务发现在 Compose 网络中自动实现。同一 Compose 项目中的服务可以通过服务名直接通信（如 http://api:3000），Docker 的内置 DNS 服务器自动解析服务名到容器 IP。


健康检查（healthcheck）让 Compose 了解服务的实际就绪状态。depends_on 配合 condition: service_healthy 确保依赖服务完全就绪后才启动上游服务，避免启动顺序导致的连接失败。


存储卷（volumes）持久化容器数据。命名卷（named volumes）由 Docker 管理，适合数据库数据等需要持久化但不需要直接访问的数据。绑定挂载（bind mounts）将宿主机目录挂载到容器内，适合开发环境中的代码热重载。


Docker 网络与存储管理
Docker 网络管理提供了灵活的容器通信配置。默认的 bridge 网络适合单机简单场景，自定义 bridge 网络提供了容器间的 DNS 解析和更好的隔离。


端口映射（Port Mapping）是容器对外暴露服务的主要方式。-p 8080:3000 将宿主机的 8080 端口映射到容器的 3000 端口。-p 127.0.0.1:8080:3000 限制只监听本地回环接口，防止外部直接访问。


Docker 存储驱动管理镜像层和容器层的读写。overlay2 是现代 Linux 内核的默认选择，提供了良好的性能和空间效率。存储驱动的选择影响容器的 I/O 性能和磁盘使用效率。


数据管理的最佳实践包括：将有状态数据存储在命名卷中而非容器层、定期清理无用的镜像和容器（docker system prune）、为数据库等有状态服务配置备份策略、使用 tmpfs 挂载临时数据避免磁盘 I/O。


生产环境 Docker 实践
生产环境中运行 Docker 容器需要额外关注安全、监控和资源管理。


资源限制通过 --memory 和 --cpus 参数设置。内存限制防止单个容器耗尽宿主机内存导致 OOM。CPU 限制确保关键服务获得足够的计算资源。在 Kubernetes 环境中，这些限制通过 Pod 的 resources.limits 和 resources.requests 配置。


日志管理通过 Docker 日志驱动实现。默认的 json-file 驱动将日志写入宿主机文件，需要配置 max-size 和 max-file 防止日志无限增长。生产环境通常使用 fluentd 或 journald 驱动将日志转发到集中式日志系统。应用应将日志输出到 stdout/stderr，而非写入容器内文件。

小结
    

  • Docker 将容器技术封装为开发者友好的工具链，是容器化实践的起点
    • 

  • Dockerfile 优化（多阶段构建、层缓存、精简基础镜像）显著影响镜像质量
    • 

  • Docker Compose 是本地多容器开发的标准工具，通过 YAML 定义服务、网络和存储
    • 

  • Docker 网络提供 bridge、host、overlay 等模式，CNI 标准统一了 Kubernetes 网络接口
    • 

  • 生产环境需要关注资源限制、日志管理、安全扫描和健康检查
    • 

  • Docker 是容器生态的基础，但生产编排应使用 Kubernetes 等专业平台
    •
