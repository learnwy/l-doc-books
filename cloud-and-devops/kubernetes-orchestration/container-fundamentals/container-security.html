容器安全

核心概念

容器安全贯穿容器生命周期的每个阶段——从镜像构建到运行时防护，从网络隔离到合规审计。容器共享宿主机内核的特性使其隔离边界相比虚拟机更薄，因此需要在多个层面实施纵深防御策略。

镜像安全与供应链防护
容器镜像是供应链攻击的主要目标。恶意或含有漏洞的基础镜像、被篡改的依赖包和不安全的构建流程都可能引入安全风险。


镜像漏洞扫描是第一道防线。Trivy 是最流行的开源镜像扫描工具，可以检测操作系统包和应用依赖中的已知漏洞（CVE）。扫描应集成到 CI/CD 流水线中，在镜像推送到仓库前自动执行。严重和高危漏洞应阻止镜像发布。


镜像签名确保镜像的完整性和来源可信。Cosign（Sigstore 项目）提供了轻量级的镜像签名和验证方案。签名信息存储在 OCI 镜像仓库中，部署时通过准入控制器验证签名，拒绝未签名或签名无效的镜像。


基础镜像管理是降低漏洞面的关键。使用官方维护的基础镜像、定期更新基础镜像版本、使用 Distroless 镜像消除不必要的系统工具和 shell。固定基础镜像的摘要（digest）而非标签，避免因标签变更引入意外变化。


软件物料清单（SBOM）记录了镜像中所有软件组件及其版本。Syft 可以生成 SPDX 或 CycloneDX 格式的 SBOM，为漏洞响应和合规审计提供依据。


容器运行时安全
运行时安全关注容器进程的权限控制和行为监控，防止容器逃逸和恶意行为。


非 root 运行是最基本的安全加固。默认情况下容器以 root 用户运行，一旦发生容器逃逸，攻击者将获得宿主机 root 权限。通过 Dockerfile 的 USER 指令或 Kubernetes 的 securityContext.runAsNonRoot 强制非 root 运行。


Linux 安全模块（LSM）为容器提供强制访问控制。AppArmor 通过配置文件限制容器进程可以访问的文件路径和系统调用。SELinux 通过安全标签实现更细粒度的访问控制。seccomp 配置文件限制容器可以使用的系统调用集合，默认 seccomp 配置已经禁止了大量危险系统调用。


Capabilities 机制将传统 root 权限拆分为细粒度的能力。默认情况下容器已经移除了大部分 Linux capabilities，但仍保留了一些。生产环境应通过 drop ALL 移除所有 capabilities，然后只添加应用实际需要的（如 NET_BIND_SERVICE 用于绑定低于 1024 的端口）。


只读根文件系统（readOnlyRootFilesystem）防止容器进程修改文件系统，有效阻止恶意软件的写入行为。应用需要写入的目录（如 /tmp）通过 emptyDir 卷挂载。


Kubernetes 安全策略
Kubernetes 提供了多层安全机制来保护容器化工作负载。


Pod Security Standards（PSS）定义了三个安全级别：Privileged（无限制）、Baseline（基础安全）和 Restricted（最严格）。通过给 Namespace 添加标签即可启用对应级别的安全策略。Restricted 级别要求非 root 运行、只读根文件系统、禁止特权容器和禁止主机网络。


准入控制器（Admission Controller）在资源创建前执行验证和变更。OPA Gatekeeper 和 Kyverno 是主流的策略引擎，支持自定义准入策略。常见策略包括：拒绝 latest 标签的镜像、要求资源限制、限制镜像来源仓库和要求安全上下文配置。


RBAC（Role-Based Access Control）控制用户和服务账户对 Kubernetes API 的访问权限。最小权限原则要求每个服务账户只获得完成其任务所需的最小权限集。应避免使用 cluster-admin 角色，而是为每个应用创建专属的 Role 和 RoleBinding。


网络策略（NetworkPolicy）控制 Pod 间的网络通信。默认情况下所有 Pod 可以互相通信，通过 NetworkPolicy 可以限制入站和出站流量。最佳实践是默认拒绝所有流量，然后显式允许必要的通信路径。

容器安全监控与响应
运行时安全监控检测容器中的异常行为和安全事件，是纵深防御的最后一层。


Falco 是 CNCF 的运行时安全监控项目。它通过 eBPF 或内核模块监控系统调用，基于规则检测异常行为。默认规则涵盖：容器内启动 shell、读取敏感文件（/etc/shadow）、意外的网络连接和特权升级尝试。Falco 的告警可以集成到 Slack、PagerDuty 或 SIEM 系统中。


容器取证在安全事件发生后收集和分析证据。由于容器的临时性，传统的主机取证方法难以直接应用。容器取证工具（如 Sysdig）可以捕获容器的系统调用轨迹、网络流量和文件变更。生产环境应保留容器的审计日志和镜像版本信息，以便事后分析。


安全基线扫描工具（如 kube-bench）检查 Kubernetes 集群配置是否符合 CIS Benchmark。自动化扫描应定期运行，发现的配置偏差应及时修复。


小结
    

  • 容器安全需要覆盖构建、存储、部署和运行四个阶段的完整生命周期
    • 

  • 镜像扫描（Trivy）和签名（Cosign）是供应链安全的基础
    • 

  • 运行时安全通过非 root、seccomp、AppArmor、Capabilities 和只读文件系统实现纵深防御
    • 

  • Kubernetes PSS、RBAC、准入控制和网络策略构成平台级安全框架
    • 

  • Falco 等运行时监控工具检测异常行为，是安全防御的最后一道防线
    • 

  • 安全是持续过程，需要定期扫描、更新基础镜像和审查安全策略
    •
