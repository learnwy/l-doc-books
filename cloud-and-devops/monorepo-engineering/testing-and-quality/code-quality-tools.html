代码质量工具

Monorepo 中的代码质量治理

代码质量工具在 Monorepo 中面临独特挑战：不同类型的包需要不同的规则集（React 组件 vs Node.js 服务），但又需要一套统一的基线规范。解决方案是共享配置包 + 分层继承——在工具链层将 ESLint、Prettier、commitlint 等工具的配置抽象为可复用的包。



ESLint 共享配置
创建一个共享的 ESLint 配置包，使用 flat config 格式（ESLint v9+）：


// tooling/eslint-config/base.ts
import type { Linter } from 'eslint';
import eslint from '@eslint/js';
import tseslint from 'typescript-eslint';

const config: Linter.Config[] = [
  eslint.configs.recommended,
  ...tseslint.configs.recommended,
  {
    rules: {
      'no-console': 'warn',
      '@typescript-eslint/no-unused-vars': ['error', { argsIgnorePattern: '^_' }],
      '@typescript-eslint/consistent-type-imports': ['error', { prefer: 'type-imports' }],
    },
  },
  {
    ignores: ['dist/**', 'node_modules/**', '.turbo/**'],
  },
];

export default config;
// tooling/eslint-config/react.ts
import type { Linter } from 'eslint';
import baseConfig from './base';
import reactPlugin from 'eslint-plugin-react';
import hooksPlugin from 'eslint-plugin-react-hooks';

const config: Linter.Config[] = [
  ...baseConfig,
  {
    plugins: {
      react: reactPlugin,
      'react-hooks': hooksPlugin,
    },
    rules: {
      'react/jsx-key': 'error',
      'react-hooks/rules-of-hooks': 'error',
      'react-hooks/exhaustive-deps': 'warn',
    },
    settings: {
      react: { version: 'detect' },
    },
  },
];

export default config;
各包的使用方式：


// apps/web/eslint.config.ts
import reactConfig from '@myorg/eslint-config/react';

export default reactConfig;
// apps/api/eslint.config.ts
import nodeConfig from '@myorg/eslint-config/node';

export default nodeConfig;


Biome 作为替代方案
Biome 是一个用 Rust 编写的高性能工具，同时提供 linting 和 formatting 能力，可以替代 ESLint + Prettier 的组合：


{
  "$schema": "https://biomejs.dev/schemas/1.9.0/schema.json",
  "organizeImports": {
    "enabled": true
  },
  "linter": {
    "enabled": true,
    "rules": {
      "recommended": true,
      "complexity": {
        "noExcessiveCognitiveComplexity": "warn"
      },
      "suspicious": {
        "noExplicitAny": "error"
      }
    }
  },
  "formatter": {
    "enabled": true,
    "indentStyle": "space",
    "indentWidth": 2,
    "lineWidth": 100
  }
}

Prettier 格式化配置
即使使用 ESLint，格式化通常交给 Prettier：


{
  "semi": true,
  "singleQuote": true,
  "trailingComma": "all",
  "printWidth": 100,
  "tabWidth": 2,
  "arrowParens": "always",
  "endOfLine": "lf"
}
{
  "scripts": {
    "format": "prettier --write \"**/*.{ts,tsx,json,md,yml}\"",
    "format:check": "prettier --check \"**/*.{ts,tsx,json,md,yml}\""
  }
}


commitlint 提交规范
commitlint 确保所有提交信息遵循 Conventional Commits 规范：


// commitlint.config.ts
import type { UserConfig } from '@commitlint/types';

const config: UserConfig = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'scope-enum': [2, 'always', ['ui', 'utils', 'types', 'config', 'web', 'admin', 'api', 'deps', 'release']],
    'body-max-line-length': [2, 'always', 200],
  },
};

export default config;
{
  "scripts": {
    "prepare": "husky"
  },
  "devDependencies": {
    "husky": "^9.0.0",
    "@commitlint/cli": "^19.0.0",
    "@commitlint/config-conventional": "^19.0.0"
  }
}
# .husky/commit-msg
npx --no -- commitlint --edit $1


lint-staged 增量检查
lint-staged 只对暂存区（staged）的文件执行检查，避免全量 lint 的耗时：


{
  "lint-staged": {
    "*.{ts,tsx}": ["eslint --fix", "prettier --write"],
    "*.{json,md,yml}": ["prettier --write"]
  }
}
# .husky/pre-commit
npx lint-staged


提示： 在 Monorepo 中，lint-staged 应配置在根目录。它会自动根据变更文件的路径调用对应的 lint 规则。






小结
    

  • Monorepo 代码质量治理的核心是"统一基线 + 差异化扩展"，通过共享配置包实现
    • 

  • ESLint flat config 使配置共享更加简洁，通过数组合并实现规则叠加
    • 

  • Biome 以极快的速度提供 lint + format 一体化方案，适合对生态插件依赖不强的项目
    • 

  • commitlint + husky 确保提交信息的规范性，为自动化版本管理提供基础
    • 

  • lint-staged 只检查暂存文件，避免全量 lint 的性能问题
    •
