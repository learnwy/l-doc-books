CI 流水线设计

Monorepo CI 的核心挑战

传统的 CI 配置为每个仓库运行固定的构建和测试流程。但在 Monorepo 中，每次 PR 可能只修改了一个包，运行全部包的构建和测试是巨大的浪费。Monorepo CI 设计的核心目标是：只运行必要的检查，同时保证变更不会破坏任何依赖方。



affected-only CI 策略
使用 Turborepo 的 --filter 配合 Git diff 实现 affected-only CI：


name: CI
on:
  pull_request:
    branches: [main, develop]

jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: pnpm/action-setup@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - name: Typecheck
        run: pnpm turbo run typecheck --filter=...[origin/main...HEAD]

      - name: Lint
        run: pnpm turbo run lint --filter=...[origin/main...HEAD]

      - name: Test
        run: pnpm turbo run test --filter=...[origin/main...HEAD]

      - name: Build
        run: pnpm turbo run build --filter=...[origin/main...HEAD]


提示： ...[origin/main...HEAD] 表示"自 origin/main 以来发生变更的所有包，以及它们的下游依赖"。这确保了即使你只修改了 utils，依赖 utils 的 ui 和 web 也会被检查。






矩阵构建策略
对于大型 Monorepo，可以将不同包的检查分散到多个 CI 作业中运行：


name: CI Matrix

on:
  pull_request:
    branches: [main]

jobs:
  detect-changes:
    runs-on: ubuntu-latest
    outputs:
      matrix: ${{ steps.detect.outputs.matrix }}
      has-changes: ${{ steps.detect.outputs.has-changes }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: pnpm/action-setup@v4
      - run: pnpm install --frozen-lockfile
      - id: detect
        run: |
          PACKAGES=$(pnpm turbo run build --filter=...[origin/main...HEAD] --dry-run=json | jq -c '{"package": [.tasks[].package] | unique}')
          HAS_CHANGES=$(echo $PACKAGES | jq '.package | length > 0')
          echo "matrix=$PACKAGES" >> $GITHUB_OUTPUT
          echo "has-changes=$HAS_CHANGES" >> $GITHUB_OUTPUT

  check:
    needs: detect-changes
    if: needs.detect-changes.outputs.has-changes == 'true'
    runs-on: ubuntu-latest
    strategy:
      matrix: ${{ fromJson(needs.detect-changes.outputs.matrix) }}
      fail-fast: false
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - run: pnpm install --frozen-lockfile
      - run: pnpm turbo run build test lint typecheck --filter=${{ matrix.package }}...


构建产物共享
CI 中的不同作业可能需要共享构建产物。使用 GitHub Actions 的 artifacts 机制：


jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - run: pnpm install --frozen-lockfile
      - run: pnpm turbo run build

      - name: Upload build artifacts
        uses: actions/upload-artifact@v4
        with:
          name: build-output
          path: |
            packages/*/dist
            apps/*/dist
            apps/*/.next

  e2e:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - run: pnpm install --frozen-lockfile

      - name: Download build artifacts
        uses: actions/download-artifact@v4
        with:
          name: build-output

      - name: Run E2E tests
        run: pnpm turbo run test:e2e --filter=./apps/*


Turbo 远程缓存在 CI 中的应用
CI 中启用 Turborepo 远程缓存可以显著减少重复构建：


jobs:
  ci:
    runs-on: ubuntu-latest
    env:
      TURBO_TOKEN: ${{ secrets.TURBO_TOKEN }}
      TURBO_TEAM: ${{ vars.TURBO_TEAM }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: pnpm/action-setup@v4
      - run: pnpm install --frozen-lockfile
      - run: pnpm turbo run build test lint typecheck --filter=...[origin/main...HEAD]

依赖安装缓存
CI 中缓存 node_modules 和 pnpm store 可以显著加速依赖安装：


- uses: actions/setup-node@v4
  with:
    node-version: 20
    cache: pnpm

- name: Get pnpm store directory
  shell: bash
  run: echo "STORE_PATH=$(pnpm store path --silent)" >> $GITHUB_ENV

- uses: actions/cache@v4
  with:
    path: ${{ env.STORE_PATH }}
    key: pnpm-store-${{ hashFiles('**/pnpm-lock.yaml') }}
    restore-keys: pnpm-store-


完整的 CI 流水线模板
name: CI
on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  ci:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    env:
      TURBO_TOKEN: ${{ secrets.TURBO_TOKEN }}
      TURBO_TEAM: ${{ vars.TURBO_TEAM }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - name: Check formatting
        run: pnpm format:check

      - name: Lint, typecheck, test, build
        run: |
          pnpm turbo run lint typecheck test build \
            --filter=...[origin/main...HEAD]


小结
    

  • affected-only 是 Monorepo CI 的核心策略，通过 Git diff + 依赖图只运行受影响的检查
    • 

  • 矩阵构建将不同包的检查分散到多个 CI 作业中，适合大型 Monorepo
    • 

  • 远程构建缓存 + 依赖安装缓存 + artifacts 共享，三层缓存机制最大化 CI 效率
    • 

  • 使用 concurrency 配置避免同一 PR 的多次推送触发重复 CI
    • 

  • 合理设置 timeout-minutes 防止失控的构建占用 CI 资源
    •
