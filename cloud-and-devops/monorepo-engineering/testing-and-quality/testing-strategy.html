Part II · 命令行与本地工具Monorepo 工程实践 简介测试与质量 简介测试策略

测试策略

核心概念

Monorepo 测试用测试金字塔分层，并让每一层落在仓库中的正确位置：

层级 验证对象 在 Monorepo 中的位置 数量/速度
单元测试 包内逻辑 每个包内部 大量 · 快
集成测试 包间交互 使用真实内部依赖的包 适量 · 中速
E2E 测试 完整用户流程 apps/ 应用层 少量 · 慢

Monorepo 给测试带来一个独特优势：集成测试可以直接使用内部包的真实实现，无需 mock，从而捕获包间接口不匹配的问题。执行策略沿维度划分——本地 watch 单包、PR 只跑受影响包（affected-only）、合并到 main 全量运行；由于各包独立运行测试产生独立报告，覆盖率还需要聚合为全局视图。

Monorepo 测试的分层模型

在 Monorepo 中，测试不仅要覆盖单个包的功能正确性，还要验证包之间的集成是否正常。测试金字塔（Test Pyramid）在 Monorepo 场景下有了新的含义：单元测试聚焦于包内逻辑，集成测试聚焦于包间交互，端到端测试则验证完整应用的用户流程。

单元测试：包内逻辑验证

每个包应该有独立的单元测试，覆盖其公开 API 的行为。在 Monorepo 中，推荐使用 Vitest 作为测试框架，因为它与 Vite 生态集成良好，支持 TypeScript 和 ESM：

// packages/utils/src/format.test.ts
import { describe, it, expect } from 'vitest';
import { formatCurrency, formatDate, clamp } from './format';

describe('formatCurrency', () => {
  it('should format CNY correctly', () => {
    expect(formatCurrency(1234.56, 'CNY')).toBe('¥1,234.56');
  });

  it('should handle zero', () => {
    expect(formatCurrency(0, 'USD')).toBe('$0.00');
  });
});

describe('clamp', () => {
  it('should clamp value within range', () => {
    expect(clamp(150, 0, 100)).toBe(100);
    expect(clamp(-10, 0, 100)).toBe(0);
    expect(clamp(50, 0, 100)).toBe(50);
  });
});

共享测试配置

在根目录定义共享的 Vitest 配置，各包通过继承扩展：

// vitest.workspace.ts
import { defineWorkspace } from 'vitest/config';

export default defineWorkspace(['packages/*/vitest.config.ts', 'apps/*/vitest.config.ts']);
// packages/utils/vitest.config.ts
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    globals: true,
    environment: 'node',
    include: ['src/**/*.test.ts'],
    coverage: {
      provider: 'v8',
      reporter: ['text', 'json', 'html'],
      thresholds: {
        branches: 80,
        functions: 80,
        lines: 80,
      },
    },
  },
});

集成测试：包间交互验证

集成测试验证多个包协同工作的正确性。在 Monorepo 中，集成测试可以直接引用内部包的真实实现：

// packages/ui/src/user-card.integration.test.ts
import { describe, it, expect } from 'vitest';
import { render, screen } from '@testing-library/react';
import { UserCard } from './user-card';
import { formatDate } from '@myorg/utils';
import type { User } from '@myorg/types';

describe('UserCard integration with utils', () => {
  const mockUser: User = {
    id: '1',
    name: 'Alice',
    email: 'alice@example.com',
    role: 'admin',
    createdAt: '2024-01-15T08:00:00Z',
  };

  it('should render user with formatted date', () => {
    render(<UserCard user={mockUser} />);
    expect(screen.getByText('Alice')).toBeDefined();
    expect(screen.getByText(formatDate(mockUser.createdAt))).toBeDefined();
  });
});

提示： 集成测试不应该 mock 内部包——这是 Monorepo 的优势之一。直接使用真实的内部依赖，能捕获包间接口不匹配的问题。

E2E 测试：完整用户流程验证

E2E 测试运行在应用层（apps），验证从用户操作到后端响应的完整流程：

// apps/web/e2e/login.spec.ts
import { test, expect } from '@playwright/test';

test.describe('Login flow', () => {
  test('should login with valid credentials', async ({ page }) => {
    await page.goto('/login');
    await page.fill('[data-testid="email"]', 'user@example.com');
    await page.fill('[data-testid="password"]', 'password123');
    await page.click('[data-testid="login-button"]');
    await expect(page).toHaveURL('/dashboard');
    await expect(page.locator('[data-testid="user-name"]')).toHaveText('User');
  });
});
{
  "tasks": {
    "test": {
      "dependsOn": ["^build"],
      "outputs": []
    },
    "test:e2e": {
      "dependsOn": ["build"],
      "outputs": [],
      "cache": false
    }
  }
}

测试执行策略

策略 触发时机 范围 工具
本地单元测试 保存文件时 当前包 vitest --watch
PR 单元测试 PR 创建/更新 受影响的包 turbo run test --filter=...[origin/main]
全量测试 合并到 main 所有包 turbo run test
E2E 测试 每日/发布前 应用层 Playwright 
{
  "scripts": {
    "test": "turbo run test",
    "test:watch": "vitest --watch",
    "test:coverage": "turbo run test -- --coverage",
    "test:affected": "turbo run test --filter=...[origin/main...HEAD]",
    "test:e2e": "turbo run test:e2e --filter=./apps/*"
  }
}

覆盖率聚合

Monorepo 中每个包独立运行测试产生独立的覆盖率报告，需要聚合为全局报告：

// vitest.config.ts (根目录)
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    coverage: {
      provider: 'v8',
      reporter: ['text-summary', 'json', 'lcov'],
      reportsDirectory: './coverage',
    },
  },
});
{
  "scripts": {
    "test:coverage": "vitest run --coverage --workspace",
    "coverage:merge": "nyc merge coverage coverage/merged.json",
    "coverage:report": "nyc report --reporter=html --temp-dir=coverage"
  }
}

  • Monorepo 测试金字塔：大量包内单元测试 + 适量包间集成测试 + 少量应用层 E2E 测试
  • 单元测试使用 Vitest + workspace 模式，每个包独立配置但共享基础设置
  • 集成测试应使用内部包的真实实现而非 mock，充分发挥 Monorepo 的优势
  • PR 阶段使用 affected-only 策略只运行受影响包的测试，合并到 main 后全量运行
  • 覆盖率报告需要聚合各包的独立结果，生成全局覆盖率视图
