依赖图分析

为什么需要依赖图分析

随着 Monorepo 中包数量的增长，包之间的依赖关系会越来越复杂。没有主动的依赖图分析（Dependency Graph Analysis），架构会在不经意间走向混乱：循环依赖悄然产生、底层包开始依赖上层应用、本应独立的模块变得紧密耦合。依赖图分析是 Monorepo 架构健康的自动化守护者。



循环依赖检测
循环依赖（Circular Dependencies）是 Monorepo 中最危险的架构问题。当 A → B → C → A 形成环时，构建顺序变得不确定，类型推导可能失败，运行时行为可能不可预测。


使用 madge 检测循环依赖
// 安装 madge
// pnpm add -D madge -w

// 检测包内的循环依赖
// npx madge --circular packages/utils/src

// 检测 TypeScript 文件的循环依赖
// npx madge --circular --extensions ts,tsx packages/ui/src

// 生成依赖图（SVG）
// npx madge --image graph.svg packages/ui/src
使用 Nx 的依赖图可视化
// 启动 Nx 依赖图 Web UI
// npx nx graph

// 查看受影响的项目
// npx nx affected --graph

// 输出 JSON 格式的依赖图
// npx nx graph --file=output.json
{
  "scripts": {
    "graph": "nx graph",
    "check:circular": "madge --circular --extensions ts,tsx packages/*/src apps/*/src",
    "check:deps": "turbo run build --dry-run --graph"
  }
}


包边界约束
包边界（Package Boundaries）定义了哪些包可以依赖哪些包。例如：packages/ 下的库不能依赖 apps/ 下的应用，utils 不能依赖 ui。这些规则需要自动化检查来强制执行。


使用 Nx 的 Module Boundary Rules

// eslint.config.ts - 使用 @nx/enforce-module-boundaries
import nxPlugin from '@nx/eslint-plugin';

export default [
  {
    plugins: { '@nx': nxPlugin },
    rules: {
      '@nx/enforce-module-boundaries': [
        'error',
        {
          depConstraints: [
            {
              sourceTag: 'type:app',
              onlyDependOnLibsWithTags: ['type:lib', 'type:util'],
            },
            {
              sourceTag: 'type:lib',
              onlyDependOnLibsWithTags: ['type:lib', 'type:util'],
            },
            {
              sourceTag: 'type:util',
              onlyDependOnLibsWithTags: ['type:util'],
            },
          ],
        },
      ],
    },
  },
];


层级约束
在分层架构中，依赖应该只从上层流向下层。自定义脚本可以验证这一约束：


// scripts/check-layer-constraints.ts
import { readFileSync, readdirSync } from 'node:fs';
import { join } from 'node:path';

interface PackageInfo {
  name: string;
  layer: 'app' | 'feature' | 'shared' | 'foundation';
  dependencies: string[];
}

const LAYER_ORDER: Record<string, number> = {
  foundation: 0,
  shared: 1,
  feature: 2,
  app: 3,
};

function getLayer(pkgPath: string): string {
  if (pkgPath.startsWith('apps/')) return 'app';
  if (pkgPath.startsWith('packages/features/')) return 'feature';
  if (pkgPath.startsWith('packages/shared/')) return 'shared';
  return 'foundation';
}

function checkConstraints(packages: PackageInfo[]): string[] {
  const violations: string[] = [];
  const pkgMap = new Map(packages.map((p) => [p.name, p]));

  for (const pkg of packages) {
    const sourceLevel = LAYER_ORDER[pkg.layer] ?? 0;
    for (const dep of pkg.dependencies) {
      const depPkg = pkgMap.get(dep);
      if (!depPkg) continue;
      const targetLevel = LAYER_ORDER[depPkg.layer] ?? 0;
      if (targetLevel > sourceLevel) {
        violations.push(`${pkg.name} (${pkg.layer}) → ${dep} (${depPkg.layer})`);
      }
    }
  }

  return violations;
}

提示： 将依赖图健康检查加入 CI 流水线，确保每次 PR 都不会引入新的架构违规。预防远比修复容易。






小结
    

  • 依赖图分析是 Monorepo 架构健康的自动化守护者，应集成到 CI 中持续运行
    • 

  • 循环依赖应零容忍，使用 madge 或 Nx graph 定期检测
    • 

  • 包边界约束通过 Nx 的 enforce-module-boundaries 规则或自定义脚本强制执行
    • 

  • 层级约束确保依赖只从上层流向下层，防止架构腐化
    • 

  • 量化健康指标（循环数、依赖深度、扇出度）持续监测依赖图的健康状态
    •
