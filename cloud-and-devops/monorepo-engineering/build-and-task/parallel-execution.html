并行执行

并行执行的价值

Monorepo 中的许多任务天然可以并行化。当拓扑排序将任务分为多个批次后，同一批次内的任务之间没有依赖关系，可以同时执行。在一台 8 核 CPU 的机器上，理论上可以同时运行 8 个构建任务。并行执行（Parallel Execution）就是充分利用这种并行度，将总构建时间从所有任务的线性累加压缩到关键路径的长度。



Turborepo 的并发控制
Turborepo 默认会尽可能并行执行任务，但可以通过 --concurrency 参数控制并发数量：


// 默认：使用可用 CPU 核心数的 100%
// turbo run build

// 限制并发数
// turbo run build --concurrency=4

// 使用 CPU 核心数的百分比
// turbo run build --concurrency=50%

// 只串行执行（调试用）
// turbo run build --concurrency=1

// 并行执行无依赖的 dev 任务
// turbo run dev --parallel
{
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"]
    },
    "lint": {
      "dependsOn": []
    },
    "typecheck": {
      "dependsOn": ["^build"]
    },
    "dev": {
      "cache": false,
      "persistent": true
    }
  }
}


提示： "dependsOn": [] 意味着 lint 任务不依赖任何其他任务，可以与 build 的第一批次同时开始执行，最大化并行度。






资源限制与内存管理
并行执行虽然提升了速度，但也增加了内存和 CPU 压力。特别是在 CI 环境中，资源通常比开发者本地机器更有限：


// Node.js 内存限制
// NODE_OPTIONS=--max-old-space-size=4096 turbo run build

// TypeScript 编译器内存优化
{
  "compilerOptions": {
    "incremental": true,
    "skipLibCheck": true,
    "disableReferencedProjectLoad": true
  }
}
{
  "scripts": {
    "build": "turbo run build --concurrency=50%",
    "build:ci": "turbo run build --concurrency=2",
    "test:ci": "turbo run test --concurrency=1"
  }
}

CI 矩阵优化
对于大型 Monorepo，可以使用 CI 矩阵（Matrix Strategy）将不同包的构建分散到多个 CI 作业中：


# .github/workflows/ci.yml
name: CI Matrix

on:
  pull_request:
    branches: [main]

jobs:
  detect:
    runs-on: ubuntu-latest
    outputs:
      packages: ${{ steps.affected.outputs.packages }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: pnpm/action-setup@v4
      - run: pnpm install --frozen-lockfile
      - id: affected
        run: |
          PACKAGES=$(pnpm turbo run build --filter=...[origin/main...HEAD] --dry-run=json | jq -c '[.tasks[].package] | unique')
          echo "packages=$PACKAGES" >> $GITHUB_OUTPUT

  build:
    needs: detect
    if: needs.detect.outputs.packages != '[]'
    runs-on: ubuntu-latest
    strategy:
      matrix:
        package: ${{ fromJson(needs.detect.outputs.packages) }}
      fail-fast: false
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - run: pnpm install --frozen-lockfile
      - run: pnpm turbo run build test lint --filter=${{ matrix.package }}...


Nx 的分布式任务执行
Nx Cloud 提供了分布式任务执行（Distributed Task Execution，DTE），可以将一次构建的任务分散到多台 CI 机器上：


# .github/workflows/ci.yml
jobs:
  main:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: pnpm/action-setup@v4
      - run: pnpm install --frozen-lockfile
      - run: npx nx-cloud start-ci-run --distribute-on="3 linux-medium-js"
      - run: npx nx affected -t build test lint
      - run: npx nx-cloud stop-all-agents
// nx.json - DTE 配置
{
  "nxCloudAccessToken": "your-token",
  "parallel": 3,
  "cacheDirectory": ".nx/cache"
}


并行度与关键路径
即使并行度再高，总构建时间也不可能低于关键路径（Critical Path）的长度。关键路径是依赖图中最长的链条：

小结
    

  • 并行执行通过同时运行无依赖关系的任务，将构建时间压缩到关键路径的长度
    • 

  • --concurrency 参数控制并发数量，应根据运行环境（本地 vs CI）适当调整
    • 

  • CI 矩阵策略将不同包的构建分散到多个作业中，适合大型 Monorepo
    • 

  • Nx Cloud 的分布式任务执行可以跨多台 CI 机器协调构建任务
    • 

  • 优化总构建时间的关键是识别和优化关键路径上的瓶颈包
    •
