增量构建

增量构建的核心思想

增量构建（Incremental Build）的核心思想是：只重新构建受变更影响的最小包集合。在一个包含 50 个包的 Monorepo 中，如果只修改了 @myorg/utils 的一个函数，全量构建需要重新构建全部 50 个包，而增量构建只需要构建 utils 及其下游依赖——可能只有 5 个包。



Turborepo --filter 机制
Turborepo 的 --filter 参数是增量构建的主要手段，支持丰富的过滤语法：


// 按包名过滤
// turbo run build --filter=@myorg/ui

// 按目录过滤
// turbo run build --filter=./apps/*

// 按依赖关系过滤：构建 ui 及其所有依赖
// turbo run build --filter=@myorg/ui...

// 按依赖关系过滤：构建所有依赖 ui 的包
// turbo run build --filter=...@myorg/ui

// 基于 Git diff 的变更检测
// turbo run build --filter=...[HEAD~1]
// turbo run build --filter=...[main...HEAD]
// turbo run build --filter=@myorg/ui...[origin/main...HEAD]




过滤语法
含义
应用场景





--filter=pkg

Nx affected 检测
Nx 的 affected 命令通过分析 Git diff 和项目依赖图，自动确定受影响的项目集合：


// 只构建受影响的项目
// npx nx affected -t build
// npx nx affected -t test
// npx nx affected -t lint

// 基于特定 base 和 head
// npx nx affected -t build --base=main --head=HEAD

// 查看受影响的项目列表
// npx nx show projects --affected
// npx nx affected --graph  // 可视化依赖图


TypeScript Project References
TypeScript Project References 是 TypeScript 原生的增量编译机制。它允许将一个大型 TypeScript 项目拆分为多个子项目，每个子项目独立编译并生成 .tsbuildinfo 文件记录编译状态，实现真正的增量类型检查：


{
  "compilerOptions": {
    "composite": true,
    "declaration": true,
    "declarationMap": true,
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src"]
}
{
  "compilerOptions": {
    "composite": true,
    "outDir": "./dist"
  },
  "references": [{ "path": "../types" }, { "path": "../utils" }],
  "include": ["src"]
}
根目录的 tsconfig.json 使用 references 串联所有子项目：


{
  "files": [],
  "references": [
    { "path": "./packages/types" },
    { "path": "./packages/utils" },
    { "path": "./packages/ui" },
    { "path": "./apps/web" },
    { "path": "./apps/admin" }
  ]
}
// 使用 tsc --build 进行增量构建
// tsc --build                    # 增量构建所有项目
// tsc --build --verbose          # 显示详细构建信息
// tsc --build --clean            # 清除构建产物
// tsc --build --force            # 强制全量重建

// .tsbuildinfo 文件记录了上次编译的文件哈希
// 只有变更的文件会被重新编译


提示： composite: true 是 Project References 的必需配置。它强制要求 declaration: true 和所有文件必须被 include 或 files 覆盖，确保项目边界清晰。






增量构建在 CI 中的应用
CI 环境是增量构建价值最大化的场景。通过对比 PR 分支与主分支的差异，精确确定需要构建和测试的包：


# .github/workflows/ci.yml
name: CI
on:
  pull_request:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: pnpm/action-setup@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - name: Build affected packages
        run: pnpm turbo run build --filter=...[origin/main...HEAD]

      - name: Test affected packages
        run: pnpm turbo run test --filter=...[origin/main...HEAD]

      - name: Lint affected packages
        run: pnpm turbo run lint --filter=...[origin/main...HEAD]


提示： fetch-depth: 0 是必需的，否则 Git 无法计算与主分支的差异。如果仓库历史很长，可以使用 fetch-depth: 2 配合 HEAD~1 作为基准。

小结
    

  • 增量构建的核心是只重新构建受变更影响的最小包集合，避免全量构建的浪费
    • 

  • Turborepo 的 --filter 支持按包名、目录和 Git diff 多种过滤维度
    • 

  • Nx 的 affected 命令自动分析 Git diff 和依赖图，开箱即用
    • 

  • TypeScript Project References 实现文件级的增量类型检查，适合大型 TypeScript 项目
    • 

  • CI 中应始终使用增量构建策略，配合 fetch-depth: 0 确保能正确计算变更范围
    •
