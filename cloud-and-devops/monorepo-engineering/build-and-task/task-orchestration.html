任务编排

为什么需要任务编排

在 Monorepo 中，一个简单的 build 命令涉及多个包，而这些包之间存在依赖关系。如果 @myorg/ui 依赖 @myorg/utils，那么 utils 必须先于 ui 构建。任务编排（Task Orchestration）就是自动理解这些依赖关系，按正确顺序执行任务，同时最大化并行度的能力。

没有任务编排工具时，开发者要么手动按顺序运行构建脚本，要么写复杂的 shell 脚本来处理依赖顺序。这在包数量增长后迅速变得不可维护。




Turborepo
Turborepo 是 Vercel 推出的高性能 Monorepo 构建系统，以简洁的配置和极致的缓存能力著称。它通过 turbo.json 定义任务的依赖关系和缓存策略：


{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**", ".next/**"],
      "inputs": ["src/**", "tsconfig.json"]
    },
    "test": {
      "dependsOn": ["build"],
      "outputs": [],
      "inputs": ["src/**", "tests/**"]
    },
    "lint": {
      "dependsOn": [],
      "outputs": []
    },
    "typecheck": {
      "dependsOn": ["^build"],
      "outputs": []
    },
    "dev": {
      "cache": false,
      "persistent": true
    }
  }
}
依赖语义




语法
含义

^build
先构建所有上游依赖包
ui 依赖 utils，先构建 utils




build
同一个包内先执行 build

[]
无依赖，可立即并行执行

// 常用 Turborepo 命令
// turbo run build                    构建所有包
// turbo run build --filter=@myorg/ui 只构建指定包
// turbo run build --filter=./apps/*  只构建 apps 下的包
// turbo run dev --parallel           并行启动所有 dev server
// turbo run build --dry-run          预览执行计划
// turbo run build --graph            生成依赖图


Nx
Nx 是由 Nrwl 开发的功能丰富的 Monorepo 工具集，不仅提供任务编排，还内置了代码生成器、依赖图可视化和插件体系。


{
  "targetDefaults": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["{projectRoot}/dist"],
      "cache": true
    },
    "test": {
      "dependsOn": ["build"],
      "cache": true
    },
    "lint": {
      "cache": true
    }
  },
  "namedInputs": {
    "default": ["{projectRoot}/**/*"],
    "production": ["default", "!{projectRoot}/tests/**/*", "!{projectRoot}/**/*.spec.ts"]
  }
}
// Nx 项目级配置 - project.json
{
  "name": "web",
  "targets": {
    "build": {
      "executor": "@nx/next:build",
      "options": {
        "outputPath": "dist/apps/web"
      }
    },
    "serve": {
      "executor": "@nx/next:server",
      "options": {
        "port": 3000
      }
    }
  }
}

Lerna
Lerna 是最早的 Monorepo 管理工具之一，现在由 Nx 团队维护，底层使用 Nx 的任务调度能力：


{
  "$schema": "node_modules/lerna/schemas/lerna-schema.json",
  "version": "independent",
  "npmClient": "pnpm",
  "useWorkspaces": true,
  "command": {
    "version": {
      "conventionalCommits": true
    },
    "publish": {
      "registry": "https://registry.npmjs.org"
    }
  }
}


提示： 如果你的核心需求是多包版本管理和发布，Lerna + Changesets 的组合仍然是成熟的方案。如果更侧重构建性能和缓存，Turborepo 或 Nx 是更好的选择。

拓扑排序与任务调度
任务编排的核心算法是拓扑排序（Topological Sort）。它将包的依赖 DAG 转化为线性执行序列，确保每个包在其依赖包之后执行：


interface TaskNode {
  name: string;
  dependencies: string[];
}

function topologicalSort(nodes: TaskNode[]): string[][] {
  const inDegree = new Map<string, number>();
  const graph = new Map<string, string[]>();

  for (const node of nodes) {
    inDegree.set(node.name, node.dependencies.length);
    for (const dep of node.dependencies) {
      const existing = graph.get(dep) ?? [];
      existing.push(node.name);
      graph.set(dep, existing);
    }
  }

  const batches: string[][] = [];
  const queue = [...inDegree.entries()].filter(([, degree]) => degree === 0).map(([name]) => name);

  while (queue.length > 0) {
    batches.push([...queue]);
    const nextQueue: string[] = [];
    for (const name of queue) {
      for (const dependent of graph.get(name) ?? []) {
        const newDegree = (inDegree.get(dependent) ?? 0) - 1;
        inDegree.set(dependent, newDegree);
        if (newDegree === 0) nextQueue.push(dependent);
      }
    }
    queue.length = 0;
    queue.push(...nextQueue);
  }

  return batches;
}


小结
    

  • 任务编排的核心是理解包间依赖关系，基于拓扑排序确定正确的执行顺序
    • 

  • Turborepo 以简洁的 turbo.json 配置和极致的缓存能力著称，适合大多数项目
    • 

  • Nx 提供完整的工具集，包括代码生成、依赖图可视化和插件体系，适合大型团队
    • 

  • Lerna 现在底层依赖 Nx，核心价值在于多包版本管理和发布流程
    • 

  • 拓扑排序将 DAG 转化为可并行执行的批次序列，最大化构建效率
