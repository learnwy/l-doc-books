Part II · 命令行与本地工具Monorepo 工程实践 简介构建与任务 简介缓存策略

缓存策略

缓存是 Monorepo 的性能基石

在没有缓存的 Monorepo 中，每次执行 turbo run build 都会重新构建所有包——即使大部分包的源码并未改变。构建缓存（Build Cache）通过记录每次任务的输入哈希和输出产物，在输入未变时直接复用上次的输出，将构建时间从分钟级降低到秒级。



本地缓存
本地缓存（Local Cache）存储在开发者的机器上，默认位于项目的 node_modules/.cache/turbo（Turborepo）或 .nx/cache（Nx）目录。


{
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"],
      "inputs": ["src/**", "tsconfig.json", "package.json"]
    }
  }
}
当你执行 turbo run build 后再次执行相同命令，Turborepo 会检测到所有输入文件未变化，直接从缓存恢复输出：


$ turbo run build

 Tasks:    5 successful, 5 total
 Cached:   4 cached, 5 total
 Time:     1.2s >>> FULL TURBO


提示： 看到 FULL TURBO 意味着所有任务都命中了缓存。这是 Monorepo 开发体验的巅峰时刻。






远程缓存
远程缓存（Remote Cache）将构建产物存储在云端，让团队所有成员和 CI 环境共享缓存。当同事已经构建过某个包，你在本地执行时可以直接下载他的构建结果，无需重新构建。


Turborepo 远程缓存配置
{
  "remoteCache": {
    "enabled": true,
    "signature": true
  }
}
// 使用 Vercel Remote Cache
// npx turbo login
// npx turbo link

// 或自托管远程缓存
// 设置环境变量
// TURBO_API=https://cache.mycompany.com
// TURBO_TOKEN=your-auth-token
// TURBO_TEAM=my-team
Nx Cloud 远程缓存
// nx.json
{
  "nxCloudAccessToken": "your-nx-cloud-token",
  "tasksRunnerOptions": {
    "default": {
      "runner": "nx-cloud",
      "options": {
        "cacheableOperations": ["build", "test", "lint"]
      }
    }
  }
}


哈希输入机制
缓存的正确性取决于哈希输入（Hash Inputs）的精确定义。哈希输入包括所有可能影响任务输出的因素：

{
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"],
      "inputs": ["src/**", "tsconfig.json", "!src/**/*.test.ts", "$NODE_ENV"]
    }
  },
  "globalDependencies": ["tsconfig.base.json", ".env"],
  "globalEnv": ["CI", "NODE_ENV"]
}


提示： 使用 ! 前缀排除测试文件等不影响构建输出的文件，可以减少不必要的缓存失效。






缓存命中率优化
缓存命中率（Cache Hit Rate）是衡量缓存效果的核心指标。以下策略可以显著提升命中率：


精确定义 inputs
{
  "tasks": {
    "build": {
      "inputs": [
        "src/**/*.ts",
        "src/**/*.tsx",
        "tsconfig.json",
        "package.json",
        "!src/**/*.test.ts",
        "!src/**/*.spec.ts",
        "!src/**/__tests__/**"
      ]
    },
    "test": {
      "inputs": ["src/**", "tests/**", "vitest.config.ts"]
    }
  }
}
分离关注点
将不同类型的任务拆分，避免一个任务的输入变化导致另一个不相关任务的缓存失效：


{
  "tasks": {
    "build": {
      "outputs": ["dist/**"]
    },
    "typecheck": {
      "outputs": []
    },
    "lint": {
      "outputs": []
    }
  }
}

缓存的安全性
远程缓存涉及构建产物的传输和存储，安全性不可忽视：


{
  "remoteCache": {
    "enabled": true,
    "signature": true
  }
}
// 缓存签名验证确保产物未被篡改
// TURBO_REMOTE_CACHE_SIGNATURE_KEY=your-secret-key

interface CacheEntry {
  hash: string;
  outputs: string[];
  signature: string;
  createdAt: number;
  duration: number;
}


小结
    

  • 构建缓存是 Monorepo 性能优化的基石，通过输入哈希匹配实现任务输出的复用
    • 

  • 本地缓存让同一台机器上的重复构建瞬间完成，远程缓存让团队和 CI 共享构建结果
    • 

  • 哈希输入的精确定义决定了缓存的正确性和命中率
    • 

  • 排除测试文件、分离任务类型、避免非确定性输出是提升缓存命中率的关键策略
    • 

  • 远程缓存应启用签名验证，确保构建产物的完整性和安全性
    •
