Workspace 协议

Workspace 的概念

Workspace（工作空间）是包管理器提供的原生 Monorepo 支持能力。它允许在一个仓库中定义多个包，包管理器会自动处理这些包之间的依赖链接、依赖提升和安装优化。三大主流包管理器——pnpm、npm 和 yarn——都提供了 Workspace 支持，但实现机制和行为差异显著。



pnpm Workspace
pnpm 通过 pnpm-workspace.yaml 文件定义工作空间，是目前 Monorepo 场景下最推荐的包管理器。它使用内容寻址存储（Content-addressable Storage）和硬链接（Hard Links）来实现高效的磁盘利用和严格的依赖隔离。


# pnpm-workspace.yaml
packages:
  - 'apps/*'
  - 'packages/*'
  - 'tools/*'
{
  "name": "my-monorepo",
  "private": true,
  "packageManager": "pnpm@9.15.0",
  "engines": {
    "node": ">=20.0.0"
  }
}
pnpm 的依赖存储机制
pnpm 不会将依赖平铺到 node_modules 根目录，而是使用虚拟存储（Virtual Store）：


node_modules/
├── .pnpm/                          # 虚拟存储
│   ├── react@18.3.1/
│   │   └── node_modules/
│   │       └── react/              # 硬链接到全局 store
│   └── lodash@4.17.21/
│       └── node_modules/
│           └── lodash/
├── react -> .pnpm/react@18.3.1/node_modules/react    # 符号链接
└── @myorg/
    └── ui -> ../../packages/ui                        # workspace 包链接


提示： pnpm 的严格模式默认禁止访问未在 package.json 中声明的依赖，从根源上杜绝了幽灵依赖问题。






npm Workspace
npm 从 v7 开始支持 Workspace，通过 package.json 的 workspaces 字段定义：


{
  "name": "my-monorepo",
  "private": true,
  "workspaces": ["apps/*", "packages/*"]
}
npm Workspace 使用提升策略（Hoisting），将所有包的依赖尽可能提升到根目录的 node_modules：


node_modules/
├── react/                          # 提升到根目录
├── lodash/
├── @myorg/
│   ├── ui -> ../../packages/ui     # workspace 包符号链接
│   └── utils -> ../../packages/utils
└── apps/web/node_modules/
    └── some-conflicting-dep/       # 版本冲突时保留在子目录
常用的 workspace 命令：


// 等效的 npm workspace 命令
// npm run build --workspace=packages/ui
// npm run build -w packages/ui
// npm run build --workspaces  (所有 workspace)
// npm install lodash -w packages/utils


yarn Workspace
yarn（尤其是 yarn v3+ / Berry）的 Workspace 支持也通过 package.json 的 workspaces 字段定义，但其 Plug'n'Play（PnP） 模式彻底改变了依赖解析机制：


{
  "name": "my-monorepo",
  "private": true,
  "workspaces": ["apps/*", "packages/*"],
  "packageManager": "yarn@4.6.0"
}
# .yarnrc.yml
nodeLinker: pnp # 或 node-modules
enableGlobalCache: true
nmHoistingLimits: workspaces


依赖提升与幽灵依赖
依赖提升（Hoisting）是 npm 和 yarn classic 的默认行为：将子包的依赖"提升"到根目录的 node_modules，减少磁盘占用和安装时间。但这带来了一个严重的副作用——幽灵依赖（Phantom Dependencies）。


// packages/app/src/index.ts

// ❌ 幽灵依赖：app 没有声明 lodash 为依赖，但因为提升可以访问
import { merge } from 'lodash';

// ✅ 正确：app 自己声明了 react 为依赖
import React from 'react';

Workspace 协议版本说明符
在 Monorepo 中引用内部包时，使用 workspace: 协议前缀：


{
  "name": "@myorg/web",
  "dependencies": {
    "@myorg/ui": "workspace:*",
    "@myorg/utils": "workspace:^",
    "@myorg/config": "workspace:~"
  }
}




说明符
含义
发布时转换为





workspace:*
任意版本
实际版本号，如 1.2.3




workspace:^
兼容版本
^1.2.3




workspace:~
近似版本
~1.2.3







提示： workspace:* 在发布时会被自动替换为包的实际版本号，这是 Monorepo 发布流程的关键机制。






小结
    

  • Workspace 是包管理器对 Monorepo 的原生支持，实现包间链接、依赖提升和统一 lockfile
    • 

  • pnpm 通过内容寻址存储和严格隔离机制，从根源上解决了幽灵依赖问题，是 Monorepo 场景的首选
    • 

  • npm Workspace 的提升策略简单直接但存在幽灵依赖风险，适合对兼容性要求高的项目
    • 

  • yarn Berry 的 PnP 模式彻底去除了 node_modules，但可能面临第三方库的兼容性问题
    • 

  • workspace:* 协议是 Monorepo 内部包引用的标准方式，发布时会自动转换为实际版本号
    •
