类型共享

类型共享的价值

在 TypeScript Monorepo 中，类型共享（Type Sharing）是跨包协作的核心机制。当 @myorg/api 定义了 API 响应的数据结构，@myorg/web 和 @myorg/admin 都需要使用这些类型来确保前后端数据契约的一致性。没有类型共享，每个包各自定义类型，不一致的风险将随包数量线性增长。



共享类型包的设计
一个专门的类型共享包是最简洁的方案。它只包含类型定义，不包含运行时代码，因此不需要构建步骤：


{
  "name": "@myorg/types",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": {
      "types": "./src/index.ts",
      "default": "./src/index.ts"
    },
    "./api": {
      "types": "./src/api.ts",
      "default": "./src/api.ts"
    },
    "./db": {
      "types": "./src/db.ts",
      "default": "./src/db.ts"
    }
  }
}
// packages/types/src/api.ts
export interface ApiResponse<T> {
  code: number;
  data: T;
  message: string;
  timestamp: number;
}

export interface PaginatedResponse<T> extends ApiResponse<T[]> {
  pagination: {
    page: number;
    pageSize: number;
    total: number;
    totalPages: number;
  };
}

export interface User {
  id: string;
  name: string;
  email: string;
  role: 'admin' | 'editor' | 'viewer';
  createdAt: string;
}

export interface Product {
  id: string;
  title: string;
  price: number;
  status: 'draft' | 'published' | 'archived';
}
// packages/types/src/index.ts
export type { ApiResponse, PaginatedResponse, User, Product } from './api';
export type { DbConfig, ConnectionPool } from './db';
export type { AppConfig, FeatureFlags } from './config';


消费方的使用方式
消费方通过标准的包导入使用共享类型：


// apps/web/src/services/user.ts
import type { ApiResponse, PaginatedResponse, User } from '@myorg/types';

async function fetchUsers(page: number): Promise<PaginatedResponse<User>> {
  const response = await fetch(`/api/users?page=${page}`);
  return response.json();
}

async function updateUser(id: string, data: Partial<User>): Promise<ApiResponse<User>> {
  const response = await fetch(`/api/users/${id}`, {
    method: 'PATCH',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(data),
  });
  return response.json();
}
// apps/api/src/routes/users.ts
import type { ApiResponse, PaginatedResponse, User } from '@myorg/types';

function createResponse<T>(data: T): ApiResponse<T> {
  return {
    code: 200,
    data,
    message: 'success',
    timestamp: Date.now(),
  };
}


提示： 使用 import type 确保类型导入在编译后被完全擦除，不会引入运行时依赖。






Declaration Files 策略
当共享包包含运行时代码需要构建时，declaration files（.d.ts 文件）的生成策略至关重要：


策略一：源码直引（开发模式）
在 Monorepo 内部，消费方直接引用包的 TypeScript 源码，无需构建：


{
  "name": "@myorg/utils",
  "exports": {
    ".": {
      "types": "./src/index.ts",
      "default": "./src/index.ts"
    }
  }
}
策略二：构建 + 声明文件（发布模式）
发布到 npm 时，需要生成 .d.ts 文件：


{
  "name": "@myorg/utils",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs"
    }
  },
  "scripts": {
    "build": "tsup src/index.ts --format esm --dts"
  }
}
// tsup.config.ts
import { defineConfig } from 'tsup';

export default defineConfig({
  entry: ['src/index.ts'],
  format: ['esm', 'cjs'],
  dts: true,
  clean: true,
  sourcemap: true,
});
策略三：双入口（publishConfig 覆盖）
{
  "name": "@myorg/utils",
  "exports": {
    ".": {
      "types": "./src/index.ts",
      "default": "./src/index.ts"
    }
  },
  "publishConfig": {
    "exports": {
      ".": {
        "types": "./dist/index.d.ts",
        "import": "./dist/index.mjs"
      }
    }
  }
}

路径映射配置
TypeScript 的路径映射（Path Mapping）在 Monorepo 中有多种配置方式：


tsconfig paths（传统方式）
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@myorg/ui": ["../../packages/ui/src"],
      "@myorg/ui/*": ["../../packages/ui/src/*"],
      "@myorg/utils": ["../../packages/utils/src"],
      "@myorg/types": ["../../packages/types/src"]
    }
  }
}
依赖 workspace 链接（推荐方式）
现代 Monorepo 工具链推荐直接依赖 workspace 的符号链接，配合包的 exports 字段，无需手动配置 paths：


{
  "compilerOptions": {
    "moduleResolution": "bundler",
    "module": "ESNext",
    "strict": true
  }
}


提示： moduleResolution: "bundler" 是现代 Monorepo 的推荐配置，它支持 exports 字段解析和条件导出，无需手动配置路径映射。






小结
    

  • 共享类型包是 TypeScript Monorepo 跨包类型安全的基础，应使用纯类型定义无需构建
    • 

  • 开发模式下包可直接指向 TypeScript 源码，发布时通过 publishConfig 切换到构建产物
    • 

  • moduleResolution: "bundler" 配合 workspace 链接和 exports 字段，是现代 Monorepo 路径解析的推荐方案
    • 

  • 始终使用 import type 导入类型，确保类型导入不引入运行时依赖
    • 

  • 共享类型是前后端数据契约的"单一事实来源"，修改一处即可在编译时发现所有不一致
    •
