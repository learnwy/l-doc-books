发布工作流

Monorepo 发布的复杂性

在 Polyrepo 中发布一个包很简单：更新版本号、构建、发布。但在 Monorepo 中，一次发布可能涉及多个包，且这些包之间有依赖关系——@myorg/ui 依赖 @myorg/utils，如果 utils 更新了版本，ui 的依赖声明也需要同步更新。发布工作流（Publishing Workflow）就是自动化处理这些复杂关系的流程。



Changesets Publish 流程
Changesets 提供了完整的版本更新和发布命令：


// 步骤 1：消费 changeset 文件，更新版本号
// pnpm changeset version

// 步骤 2：构建所有需要发布的包
// pnpm turbo run build --filter=...[HEAD~1]

// 步骤 3：发布到 npm registry
// pnpm changeset publish

// 完整流程脚本
// package.json
{
  "scripts": {
    "version-packages": "changeset version",
    "release": "pnpm build && changeset publish"
  }
}

prepublishOnly 脚本
prepublishOnly 是 npm 生命周期中在 npm publish 执行前自动触发的脚本。在 Monorepo 中，它是确保发布前构建完成的安全网：


{
  "name": "@myorg/ui",
  "version": "2.1.0",
  "scripts": {
    "build": "tsup",
    "prepublishOnly": "pnpm run build",
    "postpublish": "echo 'Published @myorg/ui@${npm_package_version}'"
  },
  "files": ["dist", "README.md", "CHANGELOG.md"]
}
npm 发布生命周期


提示： prepublishOnly 只在 npm publish 时触发，不在 npm install 时触发。这是它与 prepare 脚本的关键区别。






发布前验证
在实际发布到 npm 之前，应该执行一系列验证确保包的质量：


{
  "scripts": {
    "prepublishOnly": "pnpm run verify && pnpm run build",
    "verify": "pnpm run typecheck && pnpm run test && pnpm run lint"
  }
}

npm Provenance
npm Provenance（npm 来源证明）是 npm 的供应链安全特性，它将发布的包与 CI 构建链接起来，让消费方能验证包确实来自指定的源代码仓库和 CI 流水线：


# .github/workflows/release.yml
jobs:
  release:
    runs-on: ubuntu-latest
    permissions:
      contents: write
      id-token: write
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          registry-url: https://registry.npmjs.org

      - run: pnpm install --frozen-lockfile

      - name: Publish with provenance
        run: pnpm changeset publish --provenance
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
{
  "scripts": {
    "release": "changeset publish --provenance --access public"
  },
  "publishConfig": {
    "provenance": true,
    "access": "public",
    "registry": "https://registry.npmjs.org"
  }
}


提示： npm provenance 需要 CI 环境（如 GitHub Actions）的 OIDC 支持。它在 npm 网站上会显示一个绿色的"Provenance" 徽章，证明包的来源可追溯。






完整的自动化发布流水线
将以上所有步骤整合为一个完整的自动化发布流水线：


name: Release
on:
  push:
    branches: [main]

concurrency:
  group: release
  cancel-in-progress: false

jobs:
  release:
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      id-token: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: pnpm/action-setup@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm
          registry-url: https://registry.npmjs.org

      - run: pnpm install --frozen-lockfile

      - name: Build all packages
        run: pnpm turbo run build

      - name: Run tests
        run: pnpm turbo run test

      - name: Create Release PR or Publish
        uses: changesets/action@v1
        with:
          version: pnpm changeset version
          publish: pnpm changeset publish --provenance
          commit: 'chore(release): version packages'
          title: 'chore(release): version packages'
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}


小结
    

  • Changesets 提供了完整的版本更新和发布流程，自动处理多包间的版本依赖关系
    • 

  • prepublishOnly 脚本是发布前构建的安全网，确保产物始终是最新的
    • 

  • 发布前应使用 publint 和 @arethetypeswrong/cli 验证包配置和类型声明
    • 

  • npm Provenance 将包与 CI 构建关联，提供供应链安全的可追溯性
    • 

  • 通过 GitHub Actions + Changesets Action 实现完全自动化的版本 PR 和发布流程
    •
