Part II · 命令行与本地工具命令行工具开发 简介基础 简介CLI 设计原则

CLI 设计原则

Unix 哲学

Unix 哲学（Unix Philosophy）是命令行工具设计的基石，由 Ken Thompson、Doug McIlroy 等人在 1970 年代提出。其核心思想可以归纳为几条简洁有力的原则。

| 原则 | 说明 | 经典范例 | | ---------------- | ------------------------------------ | ---------------------------- | ------------ | ------ | | 做好一件事 | 每个程序只解决一个问题，并把它解决好 | wc 只做字数统计 | | 协同工作 | 程序的输出能成为另一个程序的输入 | cat file | grep pattern | wc -l | | 文本是通用接口 | 用纯文本作为程序之间的数据交换格式 | ls、ps、env 都输出文本 | | 尽早原型 | 快速构建可用版本，然后迭代改进 | 先做最小可用工具 | | 可组合优于可配置 | 简单工具的组合胜过一个功能庞大的程序 | 管道组合优于单一大程序 |

fn main() {
    let args: Vec<String> = std::env::args().collect();
    if args.len() < 2 {
        eprintln!("用法: mytool <文件>");
        std::process::exit(1);
    }
    let content = std::fs::read_to_string(&args[1]).unwrap_or_else(|e| {
        eprintln!("错误: {}", e);
        std::process::exit(1);
    });
    let line_count = content.lines().count();
    println!("{}", line_count);
}

提示： 遵循"做好一件事"原则时，将额外功能拆分为独立的子命令或独立工具，而不是堆积到一个命令中。

POSIX 约定

POSIX（Portable Operating System Interface）定义了命令行参数的标准约定，确保不同工具之间的用法一致性。

约定 格式 示例
短选项 单破折号 + 单字母 -v、-n
长选项 双破折号 + 单词 --verbose、--count
短选项合并 多个短选项组合 -vn 等同于 -v -n
选项值 空格或等号分隔 -o file 或 --output=file
位置参数 无前缀 mytool input.txt
双破折号终止符 -- 后的内容视为位置参数 rm -- -file 
use clap::Parser;

#[derive(Parser)]
#[command(name = "linecount", about = "统计文件行数")]
struct Cli {
    #[arg(help = "目标文件路径")]
    file: String,

    #[arg(short, long, help = "显示详细信息")]
    verbose: bool,

    #[arg(short, long, default_value_t = 0, help = "跳过前 N 行")]
    skip: usize,
}

fn main() {
    let cli = Cli::parse();
    if cli.verbose {
        eprintln!("正在处理文件: {}", cli.file);
    }
    let content = std::fs::read_to_string(&cli.file).unwrap_or_else(|e| {
        eprintln!("错误: {}", e);
        std::process::exit(1);
    });
    let count = content.lines().skip(cli.skip).count();
    println!("{}", count);
}

Exit Codes 退出码约定

退出码（Exit Code）是 CLI 工具向调用者传达执行结果的标准机制。零表示成功，非零表示各类失败。

退出码 含义 使用场景
0 成功 正常完成所有操作
1 一般性错误 运行时逻辑错误
2 用法错误 参数不正确或缺失
126 无法执行 权限不足
127 命令未找到 不存在的命令
128+N 被信号 N 终止 如 130 = Ctrl+C (SIGINT) 
use std::process::ExitCode;

fn run() -> Result<(), String> {
    let args: Vec<String> = std::env::args().collect();
    if args.len() < 2 {
        return Err("缺少必要参数".to_string());
    }
    let path = &args[1];
    std::fs::metadata(path).map_err(|e| format!("无法访问 {}: {}", path, e))?;
    println!("文件存在: {}", path);
    Ok(())
}

fn main() -> ExitCode {
    match run() {
        Ok(()) => ExitCode::SUCCESS,
        Err(msg) => {
            eprintln!("错误: {}", msg);
            ExitCode::FAILURE
        }
    }
}

提示： 在 shell 脚本中可通过 $? 获取上一个命令的退出码，因此保持一致的退出码约定对自动化流程至关重要。

可组合性设计

可组合性是 Unix 工具链的灵魂。好的 CLI 工具应该既能独立使用，又能与其他工具通过管道（Pipe）无缝协作。

use std::io::{self, Read, BufRead, BufReader};

fn main() {
    let args: Vec<String> = std::env::args().collect();
    let input: Box<dyn Read> = if args.len() > 1 {
        Box::new(std::fs::File::open(&args[1]).unwrap_or_else(|e| {
            eprintln!("错误: {}", e);
            std::process::exit(1);
        }))
    } else {
        Box::new(io::stdin())
    };

    let reader = BufReader::new(input);
    for line in reader.lines() {
        let line = line.unwrap();
        if line.contains("ERROR") {
            println!("{}", line);
        }
    }
}

小结
    

  • Unix 哲学的核心是"做好一件事"和"可组合"，这两条原则指导了几乎所有优秀 CLI 工具的设计
    • 

  • POSIX 约定规范了参数格式，用户能凭经验猜到新工具的用法
    • 

  • 退出码是自动化流程的关键信号，0 表示成功，非零表示失败
    • 

  • 可组合性要求工具正确使用 stdout/stderr，支持管道输入，并在非 TTY 环境下降级输出格式
    • 

  • 命名应简短易记，版本号遵循语义化规范
    •
