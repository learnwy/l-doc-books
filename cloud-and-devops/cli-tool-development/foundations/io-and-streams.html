Part II · 命令行与本地工具命令行工具开发 简介基础 简介IO 与流

IO 与流

核心概念

IO 与流（IO & Streams）描述 CLI 程序如何与外界交换数据。核心心智模型是三个标准流：stdin 接收输入、stdout 输出结果、stderr 输出诊断信息。分清"结果"与"诊断"是可组合性的第一道门槛。

概念 作用 关键约束
标准流 程序与外界的三条通道 结果走 stdout，日志走 stderr
管道/重定向 重新连接流的去向 不改变程序，只改变连接
TTY 检测 判断是否运行在交互终端 非 TTY 时自动降级为纯文本
缓冲 批量系统调用提升性能 大文件避免一次性读入内存
结构化输出 让结果可被程序消费 提供 --json 等机器可读格式

一个工具只要正确处理这五点，就能同时服务人类用户和下游脚本。本文从标准流讲到缓冲与结构化输出。

三大标准流

每个 CLI 程序都与三个标准流（Standard Streams）相连，它们是程序与外界沟通的基本通道。

流 文件描述符 默认目标 用途
stdin 0 键盘 接收输入数据
stdout 1 终端 输出程序结果
stderr 2 终端 输出错误和诊断信息 
graph LR
    A[键盘/管道] -->|stdin fd=0| B[CLI 程序]
    B -->|stdout fd=1| C[终端/管道/文件]
    B -->|stderr fd=2| D[终端]

正确区分 stdout 和 stderr 是构建可组合 CLI 工具的基础原则：

fn main() {
    let result = process_data();
    match result {
        Ok(output) => println!("{}", output),
        Err(e) => {
            eprintln!("错误: {}", e);
            std::process::exit(1);
        }
    }
}

fn process_data() -> Result<String, String> {
    Ok("处理结果输出到 stdout".to_string())
}

提示： 永远将程序的正式输出发送到 stdout，将日志、进度和错误信息发送到 stderr。这样用户才能通过管道只捕获有用的数据。

管道与重定向

管道（Pipe）是 Unix 工具链的核心机制，将一个程序的 stdout 连接到另一个程序的 stdin。

操作 语法 说明
管道 cmd1 | cmd2 stdout → stdin
输出重定向 cmd > file stdout → 文件（覆盖）
追加重定向 cmd >> file stdout → 文件（追加）
错误重定向 cmd 2> file stderr → 文件
合并重定向 cmd 2>&1 stderr → stdout
输入重定向 cmd < file 文件 → stdin 
use std::io::{self, BufRead, Write, BufWriter};

fn main() {
    let stdin = io::stdin();
    let stdout = io::stdout();
    let mut writer = BufWriter::new(stdout.lock());

    let mut line_num = 0;
    for line in stdin.lock().lines() {
        let line = line.unwrap();
        line_num += 1;
        writeln!(writer, "{:>4} | {}", line_num, line).unwrap();
    }
}

使用示例：

cat src/main.rs | mytool          # 从管道读取
mytool < input.txt                # 从文件重定向
mytool < input.txt > output.txt   # 同时重定向输入输出

TTY 检测

TTY（Teletypewriter）检测用于判断程序是否在交互式终端中运行。这一信息决定了是否输出颜色、是否显示进度条等行为。

use std::io::IsTerminal;

fn main() {
    let stdin_is_tty = std::io::stdin().is_terminal();
    let stdout_is_tty = std::io::stdout().is_terminal();

    if stdout_is_tty {
        println!("\x1b[32m✓ 运行在交互式终端\x1b[0m");
    } else {
        println!("✓ 运行在交互式终端");
    }

    if stdin_is_tty {
        eprintln!("等待用户输入...");
    } else {
        eprintln!("从管道读取数据...");
    }
}
场景 stdin stdout 行为调整
交互式 TTY TTY 彩色输出，显示进度条
管道输出 TTY 非 TTY 禁用颜色，纯文本输出
管道输入 非 TTY TTY 从管道读取，正常显示
全管道 非 TTY 非 TTY 纯文本，无交互

提示： 大多数颜色库（如 owo-colors、chalk）自带 TTY 检测，但你仍需在自定义格式化逻辑中手动处理。

流式处理与缓冲

高效的 IO 处理需要理解缓冲（Buffering）机制。Rust 标准库提供了 BufReader 和 BufWriter 来优化 IO 性能。

use std::io::{self, Read, BufRead, BufReader, Write, BufWriter};
use std::fs::File;

fn count_matches(path: Option<&str>, pattern: &str) -> io::Result<usize> {
    let reader: Box<dyn BufRead> = match path {
        Some(p) => Box::new(BufReader::new(File::open(p)?)),
        None => Box::new(BufReader::new(io::stdin().lock())),
    };

    let mut count = 0;
    for line in reader.lines() {
        let line = line?;
        if line.contains(pattern) {
            count += 1;
        }
    }
    Ok(count)
}

fn main() {
    let args: Vec<String> = std::env::args().collect();
    let pattern = args.get(1).expect("用法: mytool <pattern> [file]");
    let path = args.get(2).map(|s| s.as_str());

    match count_matches(path, pattern) {
        Ok(n) => println!("{}", n),
        Err(e) => {
            eprintln!("错误: {}", e);
            std::process::exit(1);
        }
    }
}
graph TD
    A[原始 IO] -->|每次系统调用| B[性能差]
    C[BufReader/BufWriter] -->|批量系统调用| D[性能好]
    E[逐行读取] -->|内存可控| F[适合大文件]
    G[read_to_string] -->|全部加载到内存| H[不适合大文件]

结构化输出

现代 CLI 工具常需支持多种输出格式，以适应不同的消费场景。

use serde::Serialize;

#[derive(Serialize)]
struct FileInfo {
    name: String,
    size: u64,
    modified: String,
}

fn format_output(files: &[FileInfo], json: bool) {
    if json {
        println!("{}", serde_json::to_string_pretty(files).unwrap());
    } else {
        println!("{:<30} {:>10} {}", "名称", "大小", "修改时间");
        println!("{}", "-".repeat(60));
        for f in files {
            println!("{:<30} {:>10} {}", f.name, f.size, f.modified);
        }
    }
}

fn main() {
    let files = vec![
        FileInfo { name: "main.rs".into(), size: 1234, modified: "2026-04-01".into() },
        FileInfo { name: "lib.rs".into(), size: 5678, modified: "2026-03-30".into() },
    ];
    let use_json = std::env::args().any(|a| a == "--json");
    format_output(&files, use_json);
}
输出格式 适用场景 实现方式
纯文本 人类阅读 println! 格式化
JSON 程序消费/jq 处理 serde_json
CSV/TSV 表格数据导出 csv crate
表格 终端美观展示 tabled crate

  • stdin/stdout/stderr 三个标准流各有明确职责，正确使用是可组合性的前提
  • 管道和重定向让简单工具通过组合产生强大能力
  • TTY 检测决定了颜色、进度条等交互元素的开关，非 TTY 环境应自动降级
  • BufReader/BufWriter 是高性能 IO 的基础，避免对大文件使用 read_to_string
  • 支持 --json 等结构化输出格式，让工具既能服务人类也能服务程序
