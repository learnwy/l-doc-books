错误处理

错误处理的两面

CLI 工具的错误处理（Error Handling）面向两个受众：使用工具的人类用户，以及调用工具的脚本和自动化流程。好的错误处理在两个层面都提供清晰的信息。

受众 关注点 传达方式
人类用户 发生了什么，如何修复 stderr 中的友好消息
脚本/自动化 成功还是失败，什么类型的失败 退出码 


用户友好的错误消息
用户友好的错误消息应包含三个要素：发生了什么、为什么发生、如何修复。


use std::path::Path;

fn validate_config(path: &Path) -> Result<String, String> {
    if !path.exists() {
        return Err(format!(
            "配置文件 '{}' 不存在\n\
             提示: 运行 `mytool init` 创建默认配置文件",
            path.display()
        ));
    }

    let content = std::fs::read_to_string(path)
        .map_err(|e| format!(
            "无法读取配置文件 '{}': {}\n\
             提示: 请检查文件权限",
            path.display(), e
        ))?;

    if content.trim().is_empty() {
        return Err(format!(
            "配置文件 '{}' 为空\n\
             提示: 至少需要包含 [project] 段落",
            path.display()
        ));
    }

    Ok(content)
}

fn main() {
    let path = std::path::Path::new("config.toml");
    match validate_config(path) {
        Ok(config) => println!("配置已加载: {} 字节", config.len()),
        Err(msg) => {
            eprintln!("错误: {}", msg);
            std::process::exit(1);
        }
    }
}

提示： 始终将错误消息输出到 stderr，而不是 stdout。这样即使在管道中，错误信息也能正确显示给用户。






退出码约定
定义清晰的退出码（Exit Code）约定，让调用方能够程序化地处理不同类型的错误。


#[repr(u8)]
enum ExitCode {
    Success = 0,
    GeneralError = 1,
    UsageError = 2,
    ConfigError = 3,
    IoError = 4,
    NetworkError = 5,
}

impl From<ExitCode> for std::process::ExitCode {
    fn from(code: ExitCode) -> Self {
        std::process::ExitCode::from(code as u8)
    }
}

#[derive(Debug)]
enum AppError {
    Usage(String),
    Config(String),
    Io(std::io::Error),
    Network(String),
}

impl AppError {
    fn exit_code(&self) -> ExitCode {
        match self {
            AppError::Usage(_) => ExitCode::UsageError,
            AppError::Config(_) => ExitCode::ConfigError,
            AppError::Io(_) => ExitCode::IoError,
            AppError::Network(_) => ExitCode::NetworkError,
        }
    }

    fn message(&self) -> String {
        match self {
            AppError::Usage(msg) => format!("用法错误: {}", msg),
            AppError::Config(msg) => format!("配置错误: {}", msg),
            AppError::Io(e) => format!("IO 错误: {}", e),
            AppError::Network(msg) => format!("网络错误: {}", msg),
        }
    }
}

fn main() {
    if let Err(e) = run() {
        eprintln!("{}", e.message());
        std::process::exit(e.exit_code() as i32);
    }
}

fn run() -> Result<(), AppError> {
    let args: Vec<String> = std::env::args().collect();
    if args.len() < 2 {
        return Err(AppError::Usage("缺少目标文件参数".into()));
    }
    let content = std::fs::read_to_string(&args[1])
        .map_err(AppError::Io)?;
    println!("{} 行", content.lines().count());
    Ok(())
}


anyhow 与 thiserror
Rust 生态中，anyhow 和 thiserror 是错误处理的两大支柱：anyhow 用于应用级错误（快速包装），thiserror 用于库级错误（精确定义）。


use anyhow::{Context, Result, bail};
use std::path::PathBuf;

fn load_config(path: &PathBuf) -> Result<toml::Value> {
    let content = std::fs::read_to_string(path)
        .with_context(|| format!("读取配置文件 '{}' 失败", path.display()))?;

    let config: toml::Value = toml::from_str(&content)
        .with_context(|| format!("解析配置文件 '{}' 失败", path.display()))?;

    if config.get("project").is_none() {
        bail!("配置文件缺少 [project] 段落");
    }

    Ok(config)
}

fn main() -> Result<()> {
    let path = PathBuf::from("config.toml");
    let config = load_config(&path)?;
    println!("项目: {}", config["project"]);
    Ok(())
}

enum ToolError {
    #[error("配置文件 '{path}' 不存在")]
    ConfigNotFound { path: String },

    #[error("端口 {port} 已被占用")]
    PortInUse { port: u16 },

Panic 与 Graceful 错误
在 Rust 中，panic 和 graceful error 代表两种截然不同的错误处理策略。CLI 工具应几乎总是选择后者。






策略
行为
适用场景





panic
立即终止，打印堆栈
编程错误（bug），不可恢复




Result + ?
向上传播，由调用者决定
可预见的运行时错误




process::exit
立即退出，指定退出码
最终错误处理点





use anyhow::{Context, Result};

fn main() {
    if let Err(e) = run() {
        eprintln!("错误: {:#}", e);
        std::process::exit(1);
    }
}

fn run() -> Result<()> {
    let path = find_config()?;
    let config = load_config(&path)?;
    execute(&config)?;
    Ok(())
}

fn find_config() -> Result<std::path::PathBuf> {
    let candidates = ["./config.toml", "~/.config/mytool/config.toml"];
    for c in &candidates {
        let p = std::path::PathBuf::from(c);
        if p.exists() {
            return Ok(p);
        }
    }
    anyhow::bail!("未找到配置文件，已搜索: {:?}", candidates);
}

fn load_config(path: &std::path::Path) -> Result<String> {
    std::fs::read_to_string(path)
        .with_context(|| format!("读取 '{}' 失败", path.display()))
}

fn execute(config: &str) -> Result<()> {
    println!("执行配置: {} 字节", config.len());
    Ok(())
}


提示： 在 main 函数中捕获所有错误并格式化输出，永远不要让 panic 信息直接展示给终端用户。设置 panic = "abort" 可以在发生 panic 时直接终止而不展示回溯。






错误输出的层次
成熟的 CLI 工具提供分层的错误输出，用户可以按需获取不同详细程度的信息。


use anyhow::{Context, Result};

fn run(verbose: bool) -> Result<()> {
    let result = std::fs::read_to_string("data.json")
        .context("无法加载数据文件");

    match result {
        Ok(data) => {
            println!("加载了 {} 字节数据", data.len());
            Ok(())
        }
        Err(e) => {
            if verbose {
                eprintln!("详细错误链:");
                for (i, cause) in e.chain().enumerate() {
                    eprintln!("  {}: {}", i, cause);
                }
            }
            Err(e)
        }
    }
}

fn main() {
    let verbose = std::env::args().any(|a| a == "-v" || a == "--verbose");
    if let Err(e) = run(verbose) {
        if !verbose {
            eprintln!("错误: {}", e);
            eprintln!("提示: 使用 -v 查看详细错误信息");
        }
        std::process::exit(1);
    }
}


小结
    

  • 用户友好的错误消息应包含发生了什么、为什么发生、如何修复三个要素
    • 

  • 退出码是脚本和自动化流程判断 CLI 工具执行结果的标准机制
    • 

  • anyhow 适合应用程序的快速错误包装，thiserror 适合库的精确错误定义
    • 

  • CLI 工具应避免 panic，始终通过 Result 传播错误并在 main 中统一处理
    • 

  • 支持 --verbose 分层错误输出，让用户按需获取详细信息
