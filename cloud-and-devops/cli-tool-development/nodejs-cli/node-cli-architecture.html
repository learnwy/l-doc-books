Part II · 命令行与本地工具命令行工具开发 简介Node.js CLI 简介Node CLI 架构

Node CLI 架构

Package.json 的 bin 字段

Node.js CLI 工具的入口通过 package.json 的 bin 字段注册。npm 在安装时会将指定的脚本文件链接到系统 PATH 中。

{
  "name": "devtool",
  "version": "1.0.0",
  "type": "module",
  "bin": {
    "devtool": "./dist/cli.mjs"
  },
  "files": ["dist"],
  "engines": {
    "node": ">=18.0.0"
  }
}
bin 配置方式 语法 效果
单命令 "bin": "./cli.mjs" 命令名 = 包名
命名命令 "bin": { "dt": "./cli.mjs" } 命令名 = dt
多命令 "bin": { "dt": "...", "dtx": "..." } 注册多个命令 


Shebang 行
Shebang（#!）是 Unix 系统用来指定脚本解释器的机制。Node.js CLI 脚本的第一行必须包含 shebang。


#!/usr/bin/env node

import { Command } from 'commander';

const program = new Command();

program.name('devtool').version('1.0.0').description('全栈开发工具');

program
  .command('init <name>')
  .description('初始化新项目')
  .option('-t, --template <template>', '项目模板', 'default')
  .action((name: string, options: { template: string }) => {
    console.log(`初始化项目: ${name} (模板: ${options.template})`);
  });

program.parse();




Shebang
说明
适用场景





#!/usr/bin/env node
通过 env 查找 node
推荐，兼容性最好




#!/usr/bin/node
固定路径
不推荐，路径可能不同




#!/usr/bin/env -S node --experimental-vm-modules
传递参数
需要特殊 Node 标志







提示： 使用 #!/usr/bin/env node 而不是硬编码 Node.js 路径，因为不同系统上 Node.js 的安装位置可能不同。






ESM 脚本组织
现代 Node.js CLI 工具应使用 ESM（ECMAScript Modules）模块系统，配合 TypeScript 获得类型安全。


// src/cli.ts - 入口文件
#!/usr/bin/env node

import { createCommand } from './commands/index.js';

const program = createCommand();
program.parse();
// src/commands/index.ts - 命令注册
import { Command } from 'commander';
import { registerInit } from './init.js';
import { registerBuild } from './build.js';
import { registerDeploy } from './deploy.js';

export function createCommand(): Command {
  const program = new Command();

  program.name('devtool').version('1.0.0').description('全栈开发工具');

  registerInit(program);
  registerBuild(program);
  registerDeploy(program);

  return program;
}
// src/commands/init.ts - 独立命令模块
import { Command } from 'commander';
import path from 'node:path';
import fs from 'node:fs/promises';

interface InitOptions {
  template: string;
  git: boolean;
}

export function registerInit(program: Command): void {
  program
    .command('init <name>')
    .description('初始化新项目')
    .option('-t, --template <template>', '项目模板', 'default')
    .option('--no-git', '不初始化 Git')
    .action(async (name: string, options: InitOptions) => {
      const targetDir = path.resolve(process.cwd(), name);
      await fs.mkdir(targetDir, { recursive: true });
      console.log(`✓ 创建目录: ${targetDir}`);
      console.log(`✓ 模板: ${options.template}`);
    });
}

TypeScript 配置
CLI 工具的 TypeScript 配置需要特别注意模块系统和输出格式。


{
  "compilerOptions": {
    "target": "ES2022",
    "module": "Node16",
    "moduleResolution": "Node16",
    "outDir": "./dist",
    "rootDir": "./src",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "declaration": false,
    "sourceMap": false
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist", "tests"]
}


提示： 使用 "module": "Node16" 确保输出的 ESM 代码与 Node.js 的模块系统完全兼容。






小结
    

  • package.json 的 bin 字段是 Node.js CLI 工具的注册入口，npm 安装时自动创建命令链接
    • 

  • Shebang 行 #!/usr/bin/env node 是必须的，它告诉操作系统使用 Node.js 执行脚本
    • 

  • 现代 CLI 工具应使用 ESM 模块系统，配合 TypeScript 获得类型安全
    • 

  • 命令应按模块拆分，每个命令一个文件，通过统一注册函数组织
    • 

  • TypeScript 配置使用 "module": "Node16" 确保 ESM 兼容性
    •
