Part II · 命令行与本地工具命令行工具开发 简介Node.js CLI 简介打包与分发

打包与分发

分发策略选择

Node.js CLI 工具的分发（Distribution）方式多样，选择取决于目标用户群体和运行时要求。

分发方式 依赖 Node.js 安装方式 适用用户
npm publish 是 npm install -g 开发者
npx 是 npx mytool 临时使用
单文件打包 是 直接运行 减少依赖
pkg/ncc 否 下载可执行文件 非开发者
Docker 否 docker run 容器环境 


Esbuild 单文件打包
esbuild 可以将整个 CLI 项目及其依赖打包为单个文件，大幅减少安装时间和磁盘占用。


// scripts/build.mts
import { build } from 'esbuild';

await build({
  entryPoints: ['src/cli.ts'],
  bundle: true,
  platform: 'node',
  target: 'node18',
  format: 'esm',
  outfile: 'dist/cli.mjs',
  minify: true,
  treeShaking: true,
  banner: {
    js: '#!/usr/bin/env node',
  },
  external: ['fsevents'],
  define: {
    'process.env.NODE_ENV': '"production"',
  },
});

console.log('✓ 打包完成: dist/cli.mjs');

Pkg：独立可执行文件
pkg（现由 @yao-pkg/pkg 维护）将 Node.js 应用打包为独立的可执行文件，用户无需安装 Node.js。


{
  "name": "mytool",
  "bin": "./dist/cli.mjs",
  "pkg": {
    "targets": ["node18-linux-x64", "node18-macos-x64", "node18-macos-arm64", "node18-win-x64"],
    "outputPath": "release",
    "assets": ["templates/**/*"]
  }
}
# 安装 pkg
npm install -g @yao-pkg/pkg

# 打包
pkg . --targets node18-linux-x64,node18-macos-arm64,node18-win-x64

# 输出
# release/mytool-linux-x64
# release/mytool-macos-arm64
# release/mytool-win-x64.exe

npm 发布配置
发布到 npm 是 Node.js CLI 工具最标准的分发方式。


{
  "name": "@myorg/devtool",
  "version": "1.0.0",
  "description": "全栈开发工具",
  "type": "module",
  "bin": {
    "devtool": "./dist/cli.mjs"
  },
  "files": ["dist", "templates"],
  "engines": {
    "node": ">=18.0.0"
  },
  "keywords": ["cli", "developer-tools"],
  "repository": {
    "type": "git",
    "url": "https://github.com/myorg/devtool"
  },
  "license": "MIT",
  "scripts": {
    "build": "node scripts/build.mts",
    "prepublishOnly": "npm run build"
  }
}
发布前的检查清单：


import { execSync } from 'node:child_process';
import fs from 'node:fs';

function prePublishCheck(): void {
  const pkg = JSON.parse(fs.readFileSync('package.json', 'utf-8'));

  if (!pkg.bin) {
    throw new Error('package.json 缺少 bin 字段');
  }

  const binPath = typeof pkg.bin === 'string' ? pkg.bin : (Object.values(pkg.bin)[0] as string);
  if (!fs.existsSync(binPath)) {
    throw new Error(`bin 入口文件不存在: ${binPath}`);
  }

  if (!pkg.files || pkg.files.length === 0) {
    console.warn('⚠ 未设置 files 字段，可能发布多余文件');
  }

  const packOutput = execSync('npm pack --dry-run 2>&1', { encoding: 'utf-8' });
  console.log('发布内容预览:');
  console.log(packOutput);
}

prePublishCheck();


npx 即用即走
npx 允许用户直接执行 npm 包中的命令而无需全局安装，是 CLI 工具分发的重要补充。


# 无需安装，直接使用
npx @myorg/devtool init my-project

# 指定版本
npx @myorg/devtool@1.2.0 build

# 等效于
npm install -g @myorg/devtool && devtool init my-project

小结
    

  • npm publish 是最标准的分发方式，files 字段控制发布范围，prepublishOnly 自动构建
    • 

  • npx 实现零安装即用，对于初始化工具和偶尔使用的命令特别有价值
    • 

  • esbuild 单文件打包大幅减少安装时间和依赖数量，是分发优化的首选手段
    • 

  • pkg 将 Node.js 运行时内嵌到可执行文件中，适合分发给非 Node.js 用户
    • 

  • 发布前使用 npm pack --dry-run 检查发布内容，确保不包含敏感文件或多余依赖
    •
