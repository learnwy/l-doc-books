Part II · 命令行与本地工具命令行工具开发 简介Node.js CLI 简介配置与环境

配置与环境

核心概念

配置与环境关乎工具"从哪里读取用户设定"。成熟做法是分层覆盖：从命令行参数到内置默认值，高优先级层覆盖低优先级层，最终收敛为一份有效配置。

层次 位置 优先级
命令行参数 --port 3000 最高
环境变量 MYAPP_PORT=3000 次高
项目级配置 .myapprc / myapp.config.ts 中
用户级配置 ~/.config/myapp/config.json 次低
内置默认值 代码内置 最低

两个规范化要点：环境变量用 dotenv 加载，配置文件的发现与合并交给 cosmiconfig，路径遵循 XDG 规范。本文据此展开每一层。

配置层次模型

成熟的 CLI 工具支持多层配置（Configuration），每一层有明确的优先级。用户可以在不同粒度上定制工具行为。

graph TD
    A[命令行参数] -->|最高优先级| F[最终配置]
    B[环境变量] -->|次高| F
    C[项目级配置文件] -->|中| F
    D[用户级配置文件] -->|次低| F
    E[内置默认值] -->|最低| F
层次 位置 适用场景
命令行参数 --port 3000 一次性覆盖
环境变量 MYAPP_PORT=3000 CI/CD、Docker
项目级配置 .myapprc / myapp.config.ts 项目共享设置
用户级配置 ~/.config/myapp/config.json 个人偏好
默认值 代码内置 开箱即用

Dotenv 环境变量

dotenv 从 .env 文件加载环境变量，是开发环境中管理配置的标准方式。

import { config } from 'dotenv';
import { resolve } from 'node:path';

function loadEnv(mode: string = 'development'): void {
  const envFiles = [`.env.${mode}.local`, `.env.${mode}`, '.env.local', '.env'];

  for (const file of envFiles) {
    config({ path: resolve(process.cwd(), file) });
  }
}

interface AppConfig {
  host: string;
  port: number;
  logLevel: string;
  dbUrl: string;
  apiKey: string;
}

function getConfig(): AppConfig {
  return {
    host: process.env.HOST || '127.0.0.1',
    port: parseInt(process.env.PORT || '3000', 10),
    logLevel: process.env.LOG_LEVEL || 'info',
    dbUrl: process.env.DATABASE_URL || 'sqlite://local.db',
    apiKey: process.env.API_KEY || '',
  };
}

loadEnv(process.env.NODE_ENV);
const config_ = getConfig();
console.log(`启动: ${config_.host}:${config_.port}`);

提示： 永远不要将 .env 文件提交到版本控制中。提供 .env.example 作为配置模板。

Cosmiconfig 配置发现

cosmiconfig 自动搜索多种格式和位置的配置文件，是 eslint、prettier 等工具使用的配置发现标准。

import { cosmiconfig } from 'cosmiconfig';

interface ToolConfig {
  output: string;
  verbose: boolean;
  ignore: string[];
  plugins: string[];
}

const DEFAULT_CONFIG: ToolConfig = {
  output: 'dist',
  verbose: false,
  ignore: ['node_modules', '.git'],
  plugins: [],
};

async function loadConfig(searchFrom?: string): Promise<ToolConfig> {
  const explorer = cosmiconfig('mytool', {
    searchPlaces: [
      'package.json',
      '.mytoolrc',
      '.mytoolrc.json',
      '.mytoolrc.yaml',
      '.mytoolrc.yml',
      'mytool.config.js',
      'mytool.config.ts',
      'mytool.config.mjs',
    ],
  });

  const result = await explorer.search(searchFrom);

  if (!result || result.isEmpty) {
    console.log('未找到配置文件，使用默认配置');
    return DEFAULT_CONFIG;
  }

  console.log(`加载配置: ${result.filepath}`);
  return { ...DEFAULT_CONFIG, ...(result.config as Partial<ToolConfig>) };
}

async function main(): Promise<void> {
  const config = await loadConfig();
  console.log('配置:', JSON.stringify(config, null, 2));
}

main().catch(console.error);

cosmiconfig 自动搜索的位置和格式：

搜索位置 格式 示例
package.json 字段 JSON "mytool": { ... }
.mytoolrc JSON/YAML { "verbose": true }
.mytoolrc.json JSON 标准 JSON
.mytoolrc.yaml YAML YAML 格式
mytool.config.js JS 模块 module.exports = { ... }
mytool.config.ts TypeScript export default { ... }

XDG 目录规范

XDG Base Directory Specification 定义了配置文件、数据文件和缓存文件的标准存储位置。

import { homedir } from 'node:os';
import { join } from 'node:path';
import { mkdirSync, existsSync } from 'node:fs';

interface XDGPaths {
  config: string;
  data: string;
  cache: string;
  state: string;
}

function getXDGPaths(appName: string): XDGPaths {
  const home = homedir();

  const paths: XDGPaths = {
    config: join(process.env.XDG_CONFIG_HOME || join(home, '.config'), appName),
    data: join(process.env.XDG_DATA_HOME || join(home, '.local', 'share'), appName),
    cache: join(process.env.XDG_CACHE_HOME || join(home, '.cache'), appName),
    state: join(process.env.XDG_STATE_HOME || join(home, '.local', 'state'), appName),
  };

  for (const dir of Object.values(paths)) {
    if (!existsSync(dir)) {
      mkdirSync(dir, { recursive: true });
    }
  }

  return paths;
}

const paths = getXDGPaths('mytool');
console.log('配置目录:', paths.config);
console.log('数据目录:', paths.data);
console.log('缓存目录:', paths.cache);
XDG 目录 环境变量 默认路径 用途
配置 XDG_CONFIG_HOME ~/.config/ 配置文件
数据 XDG_DATA_HOME ~/.local/share/ 持久数据
缓存 XDG_CACHE_HOME ~/.cache/ 可删除的缓存
状态 XDG_STATE_HOME ~/.local/state/ 运行时状态

提示： 在 macOS 上，用户更习惯 ~/Library/Application Support/ 等路径。可以使用 env-paths 库自动适配各平台的约定。

全局配置管理

将配置管理封装为统一的模块，处理加载、合并和持久化。

import fs from 'node:fs/promises';
import path from 'node:path';

interface GlobalConfig {
  defaultTemplate: string;
  editor: string;
  colorEnabled: boolean;
  telemetry: boolean;
}

class ConfigManager {
  private configPath: string;
  private config: GlobalConfig;
  private defaults: GlobalConfig = {
    defaultTemplate: 'minimal',
    editor: process.env.EDITOR || 'vim',
    colorEnabled: true,
    telemetry: true,
  };

  constructor(configDir: string) {
    this.configPath = path.join(configDir, 'config.json');
    this.config = { ...this.defaults };
  }

  async load(): Promise<void> {
    try {
      const content = await fs.readFile(this.configPath, 'utf-8');
      const saved = JSON.parse(content) as Partial<GlobalConfig>;
      this.config = { ...this.defaults, ...saved };
    } catch {
      this.config = { ...this.defaults };
    }
  }

  get<K extends keyof GlobalConfig>(key: K): GlobalConfig[K] {
    return this.config[key];
  }

  async set<K extends keyof GlobalConfig>(key: K, value: GlobalConfig[K]): Promise<void> {
    this.config[key] = value;
    await this.save();
  }

  private async save(): Promise<void> {
    const dir = path.dirname(this.configPath);
    await fs.mkdir(dir, { recursive: true });
    await fs.writeFile(this.configPath, JSON.stringify(this.config, null, 2));
  }
}

export { ConfigManager };
