Part II · 命令行与本地工具命令行工具开发 简介用户体验 简介进度与动画

进度与动画

核心概念

进度反馈（Progress Feedback）解决的是"等待的不确定性"：当操作耗时超过一秒，用户需要知道程序仍在正常工作、进展到哪一步。反馈形式应与耗时是否可预估相匹配。

耗时/已知量 推荐形式 传达的信息
< 1 秒 无需反馈 直接给结果
时长未知 Spinner + 文本 仍在运行
总量已知 进度条 + 百分比 完成比例与 ETA

两条工程约束贯穿全文：进度输出必须走 stderr（避免污染 stdout 的管道数据），以及在非 TTY 环境自动降级（避免在日志里堆满动画转义码）。本文对比 Rust 的 indicatif 与 Node.js 的 ora。

为什么需要进度反馈

进度反馈（Progress Feedback）是 CLI 工具用户体验的关键组成部分。当一个操作耗时超过一秒，用户就需要知道程序是否在正常工作。没有任何反馈的长时间等待，会让用户怀疑程序是否已经卡死。

操作耗时 推荐反馈 说明
< 1秒 无需反馈 直接显示结果
1-5秒 Spinner 表示正在处理
5秒以上 进度条 显示完成百分比
不确定时长 Spinner + 状态文本 告知当前步骤

    A[开始任务] --> B{耗时预估}
    B -->|已知总量| C[进度条]
    B -->|未知时长| D[Spinner]
    C --> E[百分比 + ETA]
    D --> F[动画 + 状态文本]
    E --> G[完成消息]

Rust：indicatif

indicatif 是 Rust 生态中功能最强大的进度显示库，支持单进度条、多进度条和 spinner。

use indicatif::{ProgressBar, ProgressStyle, MultiProgress, ProgressFinish};
use std::time::Duration;

fn download_simulation() {
    let pb = ProgressBar::new(100);
    pb.set_style(
        ProgressStyle::default_bar()
            .template("{spinner:.green} [{elapsed_precise}] [{bar:40.cyan/blue}] {pos}/{len} ({eta}) {msg}")
            .unwrap()
            .progress_chars("█▓░"),
    );

    for i in 0..100 {
        pb.set_message(format!("下载文件 {}.dat", i));
        pb.inc(1);
        std::thread::sleep(Duration::from_millis(50));
    }
    pb.finish_with_message("下载完成 ✓");
}

fn multi_task_simulation() {
    let mp = MultiProgress::new();

    let style = ProgressStyle::default_bar()
        .template("{prefix:>12.cyan.bold} [{bar:25}] {pos}/{len} {msg}")
        .unwrap();

    let pb1 = mp.add(ProgressBar::new(50));
    pb1.set_style(style.clone());
    pb1.set_prefix("编译");

    let pb2 = mp.add(ProgressBar::new(30));
    pb2.set_style(style.clone());
    pb2.set_prefix("测试");

    let pb3 = mp.add(ProgressBar::new(20));
    pb3.set_style(style);
    pb3.set_prefix("打包");

    let handles: Vec<_> = vec![
        (pb1, 50, 40),
        (pb2, 30, 60),
        (pb3, 20, 80),
    ]
    .into_iter()
    .map(|(pb, total, delay)| {
        std::thread::spawn(move || {
            for _ in 0..total {
                pb.inc(1);
                std::thread::sleep(Duration::from_millis(delay));
            }
            pb.finish_with_message("✓");
        })
    })
    .collect();

    for h in handles {
        h.join().unwrap();
    }
}

fn main() {
    download_simulation();
    println!();
    multi_task_simulation();
}

Spinner 动画

Spinner（旋转动画）用于不确定时长的操作，告诉用户程序仍在运行。

use indicatif::{ProgressBar, ProgressStyle};
use std::time::Duration;

fn spinner_demo() {
    let spinner = ProgressBar::new_spinner();
    spinner.set_style(
        ProgressStyle::default_spinner()
            .tick_strings(&["⠋", "⠙", "⠹", "⠸", "⠼", "⠴", "⠦", "⠧", "⠇", "⠏"])
            .template("{spinner:.green} {msg}")
            .unwrap(),
    );

    let steps = vec![
        "正在解析依赖...",
        "正在下载包...",
        "正在编译项目...",
        "正在运行测试...",
    ];

    for step in steps {
        spinner.set_message(step.to_string());
        for _ in 0..20 {
            spinner.tick();
            std::thread::sleep(Duration::from_millis(50));
        }
    }

    spinner.finish_with_message("✓ 全部完成");
}

fn main() {
    spinner_demo();
}

Node.js：ora

ora 是 Node.js 生态中最流行的 spinner 库，API 简洁优雅。

import ora from 'ora';

async function buildProject(): Promise<void> {
  const spinner = ora('正在编译项目...').start();

  try {
    await new Promise((resolve) => setTimeout(resolve, 2000));
    spinner.text = '正在运行测试...';

    await new Promise((resolve) => setTimeout(resolve, 1500));
    spinner.text = '正在生成产物...';

    await new Promise((resolve) => setTimeout(resolve, 1000));
    spinner.succeed('构建完成');
  } catch (error) {
    spinner.fail('构建失败');
    throw error;
  }
}

async function multiStep(): Promise<void> {
  const steps = [
    { text: '安装依赖', duration: 2000 },
    { text: '编译源码', duration: 3000 },
    { text: '运行测试', duration: 1500 },
    { text: '打包产物', duration: 1000 },
  ];

  for (const step of steps) {
    const spinner = ora(step.text).start();
    await new Promise((resolve) => setTimeout(resolve, step.duration));
    spinner.succeed();
  }
}

进度条与 stderr

进度信息应输出到 stderr 而非 stdout，这样管道中的数据不会被进度条污染。

use indicatif::ProgressBar;

fn main() {
    let pb = ProgressBar::new(100)
        .with_style(
            indicatif::ProgressStyle::default_bar()
                .template("{bar:40} {pos}/{len}")
                .unwrap(),
        );

    for i in 0..100 {
        println!("data_line_{}", i);
        pb.inc(1);
        std::thread::sleep(std::time::Duration::from_millis(20));
    }
    pb.finish_and_clear();
}
输出通道 内容 说明
stdout 程序结果数据 可被管道捕获
stderr 进度条、spinner 不影响管道数据

提示： indicatif 默认将进度条渲染到 stderr，这是正确的行为。如果使用自定义进度输出，确保写入 stderr。

  • 操作耗时超过 1 秒应提供进度反馈，已知总量用进度条，未知时长用 spinner
  • indicatif 是 Rust 生态的进度显示标准库，支持单进度条、多进度条和 spinner
  • ora 是 Node.js 生态中最简洁的 spinner 库，适合多步骤任务展示
  • 进度信息应输出到 stderr，确保不污染管道中的数据流
  • 任务完成后应显示成功/失败标记，或清除进度显示
