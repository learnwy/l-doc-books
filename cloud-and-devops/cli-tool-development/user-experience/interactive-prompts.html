交互式提示

何时使用交互式提示

交互式提示（Interactive Prompts）适用于 CLI 工具需要收集用户输入的场景。与纯命令行参数相比，交互式提示降低了使用门槛，特别适合初始化向导和配置流程。

场景 推荐方式 原因
项目初始化 交互式提示 选项多，用户不熟悉
日常操作 命令行参数 效率优先，可脚本化
危险操作确认 确认提示 防止误操作
首次配置 引导式提示 一次性设置 


提示： 交互式提示应始终支持非交互模式（通过命令行参数传入所有值），以便在 CI/CD 和脚本环境中使用。






Rust：dialoguer
dialoguer 是 Rust 生态中最流行的交互式提示库，提供确认、输入、选择和多选等组件。


use dialoguer::{theme::ColorfulTheme, Confirm, Input, Select, MultiSelect, Password};

fn interactive_setup() -> Result<(), Box<dyn std::error::Error>> {
    let theme = ColorfulTheme::default();

    let name: String = Input::with_theme(&theme)
        .with_prompt("项目名称")
        .default("my-project".into())
        .validate_with(|input: &String| {
            if input.chars().all(|c| c.is_alphanumeric() || c == '-') {
                Ok(())
            } else {
                Err("项目名称只能包含字母、数字和连字符")
            }
        })
        .interact_text()?;

    let frameworks = vec!["Axum", "Actix-web", "Rocket", "Warp"];
    let framework_idx = Select::with_theme(&theme)
        .with_prompt("选择 Web 框架")
        .items(&frameworks)
        .default(0)
        .interact()?;

    let features = vec!["数据库", "认证", "日志", "CORS", "限流", "WebSocket"];
    let selected_features = MultiSelect::with_theme(&theme)
        .with_prompt("选择功能模块（空格选择，回车确认）")
        .items(&features)
        .defaults(&[true, true, true, false, false, false])
        .interact()?;

    let db_password = Password::with_theme(&theme)
        .with_prompt("数据库密码")
        .with_confirmation("确认密码", "两次输入不一致")
        .interact()?;

    let confirm = Confirm::with_theme(&theme)
        .with_prompt(format!("确认创建项目 '{}'?", name))
        .default(true)
        .interact()?;

    if confirm {
        println!("创建项目: {}", name);
        println!("框架: {}", frameworks[framework_idx]);
        let chosen: Vec<_> = selected_features.iter().map(|&i| features[i]).collect();
        println!("功能: {:?}", chosen);
    }

    Ok(())
}

fn main() {
    if let Err(e) = interactive_setup() {
        eprintln!("错误: {}", e);
        std::process::exit(1);
    }
}


Node.js：prompts 与 inquirer
Node.js 生态中，prompts 轻量高效，inquirer 功能丰富，两者都广泛用于 CLI 交互。


import prompts from 'prompts';

interface SetupResult {
  name: string;
  framework: string;
  features: string[];
  confirm: boolean;
}

async function interactiveSetup(): Promise<SetupResult> {
  const response = await prompts([
    {
      type: 'text',
      name: 'name',
      message: '项目名称',
      initial: 'my-project',
      validate: (v: string) => /^[a-z0-9-]+$/.test(v) || '只允许小写字母、数字和连字符',
    },
    {
      type: 'select',
      name: 'framework',
      message: '选择框架',
      choices: [
        { title: 'Express', value: 'express' },
        { title: 'Fastify', value: 'fastify' },
        { title: 'Koa', value: 'koa' },
        { title: 'Hono', value: 'hono' },
      ],
    },
    {
      type: 'multiselect',
      name: 'features',
      message: '选择功能',
      choices: [
        { title: '数据库', value: 'database', selected: true },
        { title: '认证', value: 'auth', selected: true },
        { title: '日志', value: 'logging' },
        { title: 'CORS', value: 'cors' },
      ],
    },
    {
      type: 'confirm',
      name: 'confirm',
      message: '确认创建?',
      initial: true,
    },
  ]);

  return response as SetupResult;
}

非交互模式兼容
成熟的 CLI 工具必须同时支持交互和非交互两种模式。


use clap::Parser;
use dialoguer::{theme::ColorfulTheme, Input, Select};
use std::io::IsTerminal;

#[derive(Parser)]
struct Cli {
    #[arg(long)]
    name: Option<String>,

    #[arg(long)]
    template: Option<String>,
}

fn get_name(cli_value: Option<String>) -> String {
    if let Some(name) = cli_value {
        return name;
    }
    if !std::io::stdin().is_terminal() {
        eprintln!("错误: 非交互模式下必须提供 --name 参数");
        std::process::exit(2);
    }
    Input::with_theme(&ColorfulTheme::default())
        .with_prompt("项目名称")
        .interact_text()
        .unwrap()
}

fn get_template(cli_value: Option<String>) -> String {
    if let Some(t) = cli_value {
        return t;
    }
    if !std::io::stdin().is_terminal() {
        return "default".to_string();
    }
    let templates = vec!["default", "minimal", "full"];
    let idx = Select::with_theme(&ColorfulTheme::default())
        .with_prompt("选择模板")
        .items(&templates)
        .default(0)
        .interact()
        .unwrap();
    templates[idx].to_string()
}

fn main() {
    let cli = Cli::parse();
    let name = get_name(cli.name);
    let template = get_template(cli.template);
    println!("项目: {}, 模板: {}", name, template);
}


提示： 在非交互环境中使用默认值或要求显式参数，永远不要让工具在 CI 中阻塞等待输入。






小结
    

  • 交互式提示适合初始化向导和危险操作确认，日常操作应优先使用命令行参数
    • 

  • dialoguer 是 Rust 生态的首选交互式提示库，提供完整的组件集合
    • 

  • prompts 和 inquirer 在 Node.js 生态中各有优势，前者轻量后者功能丰富
    • 

  • 所有交互式功能都必须支持非交互模式，通过命令行参数绕过提示
    • 

  • 输入验证应在提示阶段完成，避免用户输入无效数据后才报错
    •
