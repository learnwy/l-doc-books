Tokio 异步 CLI

何时需要异步

并非所有 CLI 工具都需要异步运行时（Async Runtime）。同步代码更简单、调试更容易。只有在以下场景中，引入 Tokio 才有明确价值。

场景 是否需要异步 原因
文件处理 通常不需要 同步 IO 已足够快
单次 HTTP 请求 可选 ureq 等同步库更简单
并发网络请求 需要 同时请求多个 API
文件监听 需要 事件驱动的持续运行
WebSocket 需要 长连接通信
子进程并发管理 需要 同时运行多个任务 


Async Main 入口
Tokio 提供的 #[tokio::main] 宏将 main 函数转换为异步入口点。


use clap::Parser;
use anyhow::Result;

#[derive(Parser)]
struct Cli {
    #[arg(help = "要检查的 URL 列表")]
    urls: Vec<String>,

    #[arg(short, long, default_value_t = 5)]
    timeout: u64,

    #[arg(short, long, default_value_t = 10)]
    concurrency: usize,
}

#[tokio::main]
async fn main() -> Result<()> {
    let cli = Cli::parse();

    if cli.urls.is_empty() {
        anyhow::bail!("至少提供一个 URL");
    }

    println!("检查 {} 个 URL (并发: {}, 超时: {}s)",
        cli.urls.len(), cli.concurrency, cli.timeout);

    check_urls(&cli.urls, cli.timeout, cli.concurrency).await?;
    Ok(())
}

async fn check_urls(urls: &[String], timeout: u64, concurrency: usize) -> Result<()> {
    let client = reqwest::Client::builder()
        .timeout(std::time::Duration::from_secs(timeout))
        .build()?;

    let semaphore = std::sync::Arc::new(tokio::sync::Semaphore::new(concurrency));
    let mut handles = vec![];

    for url in urls {
        let client = client.clone();
        let url = url.clone();
        let sem = semaphore.clone();

        let handle = tokio::spawn(async move {
            let _permit = sem.acquire().await.unwrap();
            match client.get(&url).send().await {
                Ok(resp) => println!("  ✓ {} → {}", url, resp.status()),
                Err(e) => eprintln!("  ✗ {} → {}", url, e),
            }
        });
        handles.push(handle);
    }

    for h in handles {
        h.await?;
    }
    Ok(())
}


并发任务编排
CLI 工具中的常见模式是同时执行多个独立任务，然后收集结果。Tokio 的 JoinSet 和 tokio::select! 是核心工具。


use tokio::task::JoinSet;
use anyhow::Result;
use std::time::Duration;

struct TaskResult {
    name: String,
    duration: Duration,
    success: bool,
}

async fn run_pipeline() -> Result<Vec<TaskResult>> {
    let mut set = JoinSet::new();

    set.spawn(async {
        let start = std::time::Instant::now();
        tokio::time::sleep(Duration::from_millis(500)).await;
        TaskResult { name: "lint".into(), duration: start.elapsed(), success: true }
    });

    set.spawn(async {
        let start = std::time::Instant::now();
        tokio::time::sleep(Duration::from_millis(800)).await;
        TaskResult { name: "typecheck".into(), duration: start.elapsed(), success: true }
    });

    set.spawn(async {
        let start = std::time::Instant::now();
        tokio::time::sleep(Duration::from_millis(300)).await;
        TaskResult { name: "test".into(), duration: start.elapsed(), success: true }
    });

    let mut results = vec![];
    while let Some(res) = set.join_next().await {
        results.push(res?);
    }
    Ok(results)
}

#[tokio::main]
async fn main() -> Result<()> {
    let results = run_pipeline().await?;
    for r in &results {
        let icon = if r.success { "✓" } else { "✗" };
        println!("{} {} ({:.1}s)", icon, r.name, r.duration.as_secs_f64());
    }
    Ok(())
}

信号处理
CLI 工具需要正确响应操作系统信号（Signals），特别是 Ctrl+C（SIGINT）和 SIGTERM。


use tokio::signal;
use tokio::sync::watch;
use anyhow::Result;

async fn graceful_server(mut shutdown_rx: watch::Receiver<bool>) -> Result<()> {
    let mut interval = tokio::time::interval(std::time::Duration::from_secs(1));
    let mut count = 0;

    loop {
        tokio::select! {
            _ = interval.tick() => {
                count += 1;
                println!("处理第 {} 个任务...", count);
            }
            _ = shutdown_rx.changed() => {
                println!("收到关闭信号，正在清理...");
                tokio::time::sleep(std::time::Duration::from_millis(500)).await;
                println!("清理完成");
                break;
            }
        }
    }
    Ok(())
}

#[tokio::main]
async fn main() -> Result<()> {
    let (shutdown_tx, shutdown_rx) = watch::channel(false);

    let server_handle = tokio::spawn(graceful_server(shutdown_rx));

    signal::ctrl_c().await?;
    println!("\n收到 Ctrl+C");
    shutdown_tx.send(true)?;

    server_handle.await??;
    println!("程序退出");
    Ok(())
}


提示： 永远不要在信号处理中直接调用 process::exit()。让正在运行的任务有机会完成当前工作并清理资源。

use tokio::runtime::Runtime;

fn main() {
    let rt = Runtime::builder()
        .worker_threads(2)
        .enable_io()
        .enable_time()
        .build()
        .unwrap();

    rt.block_on(async {
        println!("在自定义运行时中执行");
    });
}


小结
    

  • 并非所有 CLI 工具都需要异步，单次操作和简单文件处理优先使用同步代码
    • 

  • #[tokio::main] 是最常用的异步入口，简单任务可用 current_thread 模式减少开销
    • 

  • JoinSet 管理并发任务集合，Semaphore 控制并发度，select! 实现竞争和超时
    • 

  • 信号处理应通过 watch 或 CancellationToken 通知任务优雅关闭，而非直接退出
    • 

  • 运行时配置应根据实际需求选择，大多数 CLI 工具使用默认配置即可
    •
