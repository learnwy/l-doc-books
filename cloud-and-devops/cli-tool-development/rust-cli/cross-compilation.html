Part II · 命令行与本地工具命令行工具开发 简介Rust CLI 简介交叉编译

交叉编译

为什么需要交叉编译

交叉编译（Cross-Compilation）是指在一个平台上编译出另一个平台的可执行文件。CLI 工具的用户遍布 Linux、macOS 和 Windows，发布时需要为每个平台提供预编译的二进制文件。

目标平台 Target Triple 常见场景
Linux x86_64 x86_64-unknown-linux-gnu 服务器、CI
Linux ARM64 aarch64-unknown-linux-gnu ARM 服务器、树莓派
Linux musl x86_64-unknown-linux-musl 静态链接、Alpine
macOS x86_64 x86_64-apple-darwin Intel Mac
macOS ARM64 aarch64-apple-darwin Apple Silicon
Windows x86_64-pc-windows-msvc Windows 桌面 


Cargo 原生交叉编译
Rust 通过 --target 参数支持原生交叉编译，但需要安装目标平台的链接器和系统库。


// Cargo.toml 配置
// [package]
// name = "mytool"
// version = "0.1.0"
// edition = "2021"
# 添加目标平台
rustup target add x86_64-unknown-linux-musl
rustup target add aarch64-apple-darwin

# 编译到指定目标
cargo build --release --target x86_64-unknown-linux-musl
cargo build --release --target aarch64-apple-darwin
在 .cargo/config.toml 中配置目标平台的链接器：


[target.x86_64-unknown-linux-musl]
linker = "x86_64-linux-musl-gcc"

[target.aarch64-unknown-linux-gnu]
linker = "aarch64-linux-gnu-gcc"

[target.x86_64-pc-windows-gnu]
linker = "x86_64-w64-mingw32-gcc"


Cross 工具
cross 通过 Docker 容器提供开箱即用的交叉编译环境，无需手动安装交叉编译工具链。


# 安装 cross
cargo install cross --git https://github.com/cross-rs/cross

# 使用方式与 cargo 完全相同
cross build --release --target x86_64-unknown-linux-musl
cross build --release --target aarch64-unknown-linux-gnu
cross build --release --target x86_64-pc-windows-gnu

Cargo-zigbuild
cargo-zigbuild 使用 Zig 的 C 编译器作为链接器，无需 Docker 即可交叉编译到大多数平台。


# 安装
cargo install cargo-zigbuild
pip install ziglang

# 编译
cargo zigbuild --release --target x86_64-unknown-linux-gnu
cargo zigbuild --release --target aarch64-unknown-linux-gnu
cargo zigbuild --release --target x86_64-unknown-linux-musl

# 同时编译多个目标
cargo zigbuild --release \
  --target x86_64-unknown-linux-gnu \
  --target aarch64-unknown-linux-gnu


提示： cargo-zigbuild 特别适合在 macOS 上交叉编译 Linux 二进制文件，速度快且配置简单。






Musl 静态链接
musl 是 C 标准库的轻量级实现，编译出的二进制文件完全静态链接，无需系统库依赖。


# 安装 musl 目标
rustup target add x86_64-unknown-linux-musl

# 静态编译
cargo build --release --target x86_64-unknown-linux-musl

# 验证静态链接
file target/x86_64-unknown-linux-musl/release/mytool
# mytool: ELF 64-bit LSB executable, statically linked

对于需要 OpenSSL 的项目，使用 vendored 特性编译静态版本：


[dependencies]
reqwest = { version = "0.12", features = ["rustls-tls"] }


提示： 使用 rustls 替代 OpenSSL 可以避免交叉编译时的 OpenSSL 依赖问题。






多架构发布脚本
完整的发布流程通常通过 CI 脚本自动化。以下是一个构建多平台二进制的脚本示例：


use std::process::Command;

struct Target {
    triple: &'static str,
    ext: &'static str,
}

const TARGETS: &[Target] = &[
    Target { triple: "x86_64-unknown-linux-musl", ext: "" },
    Target { triple: "aarch64-unknown-linux-musl", ext: "" },
    Target { triple: "x86_64-apple-darwin", ext: "" },
    Target { triple: "aarch64-apple-darwin", ext: "" },
    Target { triple: "x86_64-pc-windows-msvc", ext: ".exe" },
];

fn build_target(name: &str, target: &Target) {
    println!("编译 {} ({})", name, target.triple);
    let status = Command::new("cargo")
        .args(["zigbuild", "--release", "--target", target.triple])
        .status()
        .expect("编译失败");

    if !status.success() {
        eprintln!("编译失败: {}", target.triple);
        std::process::exit(1);
    }

    let src = format!("target/{}/release/{}{}", target.triple, name, target.ext);
    let dst = format!("dist/{}-{}{}", name, target.triple, target.ext);
    std::fs::create_dir_all("dist").ok();
    std::fs::copy(&src, &dst).expect("复制失败");
    println!("  → {}", dst);
}

fn main() {
    let name = "mytool";
    for target in TARGETS {
        build_target(name, target);
    }
    println!("所有目标构建完成!");
}


小结
    

  • 交叉编译让一个代码仓库产出多平台二进制，是 CLI 工具分发的基础
    • 

  • cross 通过 Docker 提供开箱即用的体验，cargo-zigbuild 更轻量且无需 Docker
    • 

  • musl 静态链接实现零依赖分发，适合 Linux 环境的广泛兼容
    • 

  • 使用 rustls 替代 OpenSSL 可以避免交叉编译中最常见的依赖问题
    • 

  • CI 中的矩阵构建应覆盖所有目标平台，自动化打包发布到 GitHub Release
    •
