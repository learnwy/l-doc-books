版本管理与迁移

语义化版本号

语义化版本号（Semantic Versioning，简称 SemVer）是软件版本管理的行业标准。版本号格式为 MAJOR.MINOR.PATCH，每个数字的变更传达明确的兼容性信息。

版本部分 变更时机 兼容性影响
MAJOR 不兼容的 API 变更 用户可能需要修改用法
MINOR 向后兼容的新功能 用户无需修改
PATCH 向后兼容的问题修复 用户无需修改 
在 Cargo.toml 中管理版本：


[package]
name = "mytool"
version = "1.2.3"
use clap::Parser;

#[derive(Parser)]
#[command(version = env!("CARGO_PKG_VERSION"))]
struct Cli {
    #[command(subcommand)]
    command: Commands,
}

#[derive(clap::Subcommand)]
enum Commands {
    Version,
}

fn main() {
    let cli = Cli::parse();
    match cli.command {
        Commands::Version => {
            println!("mytool {}", env!("CARGO_PKG_VERSION"));
            println!("commit: {}", option_env!("GIT_HASH").unwrap_or("unknown"));
            println!("target: {}", env!("TARGET"));
        }
    }
}

破坏性变更（Breaking Changes）是 CLI 工具中最敏感的版本决策。以下行为被视为破坏性变更：

fn check_compatibility() {
    let breaking_changes = vec![
        "移除或重命名子命令",
        "移除或重命名命令行选项",
        "改变现有选项的默认值",
        "改变 stdout/stderr 的输出格式",
        "改变退出码的含义",
        "改变配置文件格式",
        "提高最低运行时版本要求",
    ];

    let safe_changes = vec![
        "新增子命令",
        "新增选项（有默认值）",
        "新增输出格式选项",
        "改进错误消息文本",
        "优化性能",
        "新增环境变量支持",
    ];

    println!("=== 破坏性变更 ===");
    for change in &breaking_changes {
        println!("  ✗ {}", change);
    }
    println!("\n=== 安全变更 ===");
    for change in &safe_changes {
        println!("  ✓ {}", change);
    }
}

fn main() {
    check_compatibility();
}


提示： 当不确定变更是否破坏性时，保守处理——将其视为破坏性变更并提升 MAJOR 版本号。






Deprecation 策略
弃用策略（Deprecation Strategy）为用户提供平滑过渡的时间窗口。弃用的功能应在至少一个 MINOR 版本中保留并发出警告，然后在下一个 MAJOR 版本中移除。


use std::io::IsTerminal;

fn deprecated_warning(old: &str, new: &str, remove_version: &str) {
    if std::io::stderr().is_terminal() {
        eprintln!(
            "\x1b[33m⚠ 弃用警告: '{}' 将在 v{} 中移除，请使用 '{}' 代替\x1b[0m",
            old, remove_version, new
        );
    } else {
        eprintln!(
            "⚠ 弃用警告: '{}' 将在 v{} 中移除，请使用 '{}' 代替",
            old, remove_version, new
        );
    }
}

fn handle_legacy_arg(arg: &str) -> &str {
    match arg {
        "--output-dir" => {
            deprecated_warning("--output-dir", "--out-dir", "3.0");
            "--out-dir"
        }
        "--no-color" => {
            deprecated_warning("--no-color", "NO_COLOR 环境变量", "3.0");
            "--no-color"
        }
        other => other,
    }
}

fn main() {
    let args: Vec<String> = std::env::args().collect();
    for arg in &args[1..] {
        let resolved = handle_legacy_arg(arg);
        println!("使用参数: {}", resolved);
    }
}

迁移指南
每个 MAJOR 版本升级都应提供详细的迁移指南（Migration Guide），帮助用户平滑过渡。


fn print_migration_guide() {
    let guide = r#"
# v2 → v3 迁移指南

## 破坏性变更

### 1. 配置文件格式变更
- v2: `config.json`
- v3: `config.toml`
- 迁移: 运行 `mytool migrate-config`

### 2. 参数重命名
- `--output-dir` → `--out-dir`
- `--no-color` → 使用 `NO_COLOR=1` 环境变量

### 3. 子命令变更
- `mytool deploy --env prod` → `mytool deploy prod`
- `mytool config show` → `mytool config list`

## 自动迁移

运行以下命令自动执行大部分迁移:
  mytool migrate --from v2

## 需要帮助?

提交 issue: https://github.com/myorg/mytool/issues
"#;
    println!("{}", guide);
}

fn main() {
    print_migration_guide();
}

版本信息嵌入
在编译时嵌入版本信息，帮助用户和维护者定位具体的构建。


fn main() {
    println!("cargo:rustc-env=GIT_HASH={}", git_hash());
    println!("cargo:rustc-env=BUILD_DATE={}", build_date());
    println!("cargo:rustc-env=TARGET={}", std::env::var("TARGET").unwrap_or_default());
}

fn git_hash() -> String {
    std::process::Command::new("git")
        .args(["rev-parse", "--short", "HEAD"])
        .output()
        .ok()
        .and_then(|o| String::from_utf8(o.stdout).ok())
        .map(|s| s.trim().to_string())
        .unwrap_or_else(|| "unknown".to_string())
}

fn build_date() -> String {
    chrono::Utc::now().format("%Y-%m-%d").to_string()
}
fn print_version_info() {
    println!("mytool {}", env!("CARGO_PKG_VERSION"));
    println!("  commit:  {}", env!("GIT_HASH"));
    println!("  built:   {}", env!("BUILD_DATE"));
    println!("  target:  {}", env!("TARGET"));
    println!("  rustc:   {}", env!("RUSTC_VERSION"));
}


提示： 在 --version 输出中包含 Git commit hash 和构建日期，能帮助用户在报告问题时提供准确的版本信息。






小结
    

  • 语义化版本号通过 MAJOR.MINOR.PATCH 传达变更的兼容性影响
    • 

  • 破坏性变更包括移除命令、修改参数名、改变输出格式和默认值等
    • 

  • 弃用策略提供过渡期：先警告至少一个 MINOR 版本，再在下一个 MAJOR 版本移除
    • 

  • 每个 MAJOR 版本升级应提供迁移指南和自动迁移工具
    • 

  • 版本信息中嵌入 Git hash 和构建日期，帮助精确定位和问题排查
    •
