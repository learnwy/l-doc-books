CLI 测试

CLI 测试的独特性

CLI 测试（CLI Testing）与普通单元测试有本质区别：输入是命令行参数和 stdin 数据，输出是 stdout 文本、stderr 错误信息和退出码。测试需要从用户的视角验证工具的行为。

测试类型 验证对象 工具 粒度
单元测试 内部函数逻辑 #[test] / vitest 函数级
集成测试 命令行行为 assert_cmd 命令级
快照测试 输出文本 insta / toml 输出级
E2E 测试 完整工作流 shell 脚本 流程级 


Rust：assert_cmd
assert_cmd 提供了优雅的 API 来测试 Rust CLI 工具的命令行行为。


#[cfg(test)]
mod tests {
    use assert_cmd::Command;
    use predicates::prelude::*;

    #[test]
    fn test_help_output() {
        Command::cargo_bin("mytool")
            .unwrap()
            .arg("--help")
            .assert()
            .success()
            .stdout(predicate::str::contains("用法"))
            .stdout(predicate::str::contains("--verbose"));
    }

    #[test]
    fn test_version() {
        Command::cargo_bin("mytool")
            .unwrap()
            .arg("--version")
            .assert()
            .success()
            .stdout(predicate::str::starts_with("mytool "));
    }

    #[test]
    fn test_missing_argument() {
        Command::cargo_bin("mytool")
            .unwrap()
            .assert()
            .failure()
            .stderr(predicate::str::contains("错误"));
    }

    #[test]
    fn test_file_processing() {
        Command::cargo_bin("mytool")
            .unwrap()
            .arg("process")
            .arg("test-data/sample.txt")
            .assert()
            .success()
            .stdout(predicate::str::contains("处理完成"));
    }

    #[test]
    fn test_stdin_input() {
        Command::cargo_bin("mytool")
            .unwrap()
            .arg("count")
            .write_stdin("line1\nline2\nline3\n")
            .assert()
            .success()
            .stdout("3\n");
    }

    #[test]
    fn test_exit_code() {
        Command::cargo_bin("mytool")
            .unwrap()
            .arg("validate")
            .arg("nonexistent.toml")
            .assert()
            .code(1);
    }
}


assert_fs：文件系统测试
assert_fs 提供临时目录和文件断言，用于测试涉及文件系统操作的命令。


#[cfg(test)]
mod tests {
    use assert_cmd::Command;
    use assert_fs::prelude::*;
    use assert_fs::TempDir;
    use predicates::prelude::*;

    #[test]
    fn test_init_creates_project() {
        let temp = TempDir::new().unwrap();

        Command::cargo_bin("mytool")
            .unwrap()
            .arg("init")
            .arg("my-project")
            .current_dir(temp.path())
            .assert()
            .success();

        temp.child("my-project").assert(predicate::path::is_dir());
        temp.child("my-project/Cargo.toml").assert(predicate::path::exists());
        temp.child("my-project/src/main.rs").assert(predicate::path::exists());
    }

    #[test]
    fn test_config_generation() {
        let temp = TempDir::new().unwrap();
        let config = temp.child("config.toml");
        config.write_str("[project]\nname = \"test\"\n").unwrap();

        Command::cargo_bin("mytool")
            .unwrap()
            .arg("validate")
            .arg(config.path())
            .assert()
            .success()
            .stdout(predicate::str::contains("配置有效"));
    }

    #[test]
    fn test_output_file() {
        let temp = TempDir::new().unwrap();
        let input = temp.child("input.txt");
        input.write_str("hello\nworld\n").unwrap();

        let output = temp.child("output.txt");

        Command::cargo_bin("mytool")
            .unwrap()
            .args(["transform", "--output"])
            .arg(output.path())
            .arg(input.path())
            .assert()
            .success();

        output.assert(predicate::str::contains("HELLO"));
    }
}


快照测试
快照测试（Snapshot Testing）冻结命令的输出，后续运行时自动与快照比对。Rust 的 insta 是这一领域的标准工具。


#[cfg(test)]
mod tests {
    use assert_cmd::Command;

    #[test]
    fn test_list_output_snapshot() {
        let output = Command::cargo_bin("mytool")
            .unwrap()
            .args(["list", "--format", "text"])
            .output()
            .unwrap();

        let stdout = String::from_utf8(output.stdout).unwrap();
        insta::assert_snapshot!("list_text_output", stdout);
    }

    #[test]
    fn test_json_output_snapshot() {
        let output = Command::cargo_bin("mytool")
            .unwrap()
            .args(["list", "--format", "json"])
            .output()
            .unwrap();

        let stdout = String::from_utf8(output.stdout).unwrap();
        let value: serde_json::Value = serde_json::from_str(&stdout).unwrap();
        insta::assert_json_snapshot!("list_json_output", value);
    }
}




快照操作
命令
说明





首次生成
cargo test
自动创建快照文件




审查变更
cargo insta review
交互式审查差异




接受更新
cargo insta accept
接受新的快照




拒绝变更
cargo insta reject
恢复原有快照







提示： 快照测试非常适合验证 --help 输出、格式化文本和 JSON 响应。当输出发生意外变化时能立即被发现。






E2E 测试
端到端测试（End-to-End Testing）验证完整的用户工作流，包括安装、配置、执行和清理。


#[cfg(test)]
mod e2e {
    use assert_cmd::Command;
    use assert_fs::TempDir;
    use predicates::prelude::*;

    #[test]
    fn test_full_workflow() {
        let workspace = TempDir::new().unwrap();

        Command::cargo_bin("mytool")
            .unwrap()
            .args(["init", "demo-project", "--template", "minimal"])
            .current_dir(workspace.path())
            .assert()
            .success()
            .stdout(predicate::str::contains("项目创建成功"));

        let project_dir = workspace.child("demo-project");

        Command::cargo_bin("mytool")
            .unwrap()
            .args(["build"])
            .current_dir(project_dir.path())
            .assert()
            .success()
            .stdout(predicate::str::contains("构建完成"));

        Command::cargo_bin("mytool")
            .unwrap()
            .args(["test"])
            .current_dir(project_dir.path())
            .assert()
            .success();

        Command::cargo_bin("mytool")
            .unwrap()
            .args(["clean"])
            .current_dir(project_dir.path())
            .assert()
            .success();
    }
}


小结
    

  • CLI 测试从用户视角验证工具行为，关注参数解析、输出格式和退出码
    • 

  • assert_cmd 是 Rust CLI 集成测试的标准工具，支持 stdin 注入和 stdout/stderr 断言
    • 

  • assert_fs 提供临时目录和文件断言，确保文件系统测试的隔离性
    • 

  • 快照测试适合验证格式化输出和帮助文本，insta 提供交互式的快照审查流程
    • 

  • E2E 测试验证完整的用户工作流，但应控制数量，聚焦核心场景
    •
