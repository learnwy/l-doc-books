CI 与发布

GitHub Actions Release 工作流

GitHub Actions 为 CLI 工具的自动化构建和发布提供了完整的 CI/CD 能力。典型的发布流程是：推送 Git 标签 → 触发 CI → 多平台构建 → 创建 GitHub Release。

name: Release

on:
  push:
    tags:
      - 'v*'

permissions:
  contents: write

jobs:
  build:
    name: Build ${{ matrix.target }}
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        include:
          - target: x86_64-unknown-linux-musl
            os: ubuntu-latest
            archive: tar.gz
          - target: aarch64-unknown-linux-musl
            os: ubuntu-latest
            archive: tar.gz
          - target: x86_64-apple-darwin
            os: macos-latest
            archive: tar.gz
          - target: aarch64-apple-darwin
            os: macos-latest
            archive: tar.gz
          - target: x86_64-pc-windows-msvc
            os: windows-latest
            archive: zip

    steps:
      - uses: actions/checkout@v4

      - uses: dtolnay/rust-toolchain@stable
        with:
          targets: ${{ matrix.target }}

      - name: Build
        run: cargo build --release --target ${{ matrix.target }}

      - name: Package (Unix)
        if: matrix.archive == 'tar.gz'
        run: |
          cd target/${{ matrix.target }}/release
          tar czf ../../../mytool-${{ matrix.target }}.tar.gz mytool
          cd ../../..

      - name: Package (Windows)
        if: matrix.archive == 'zip'
        run: |
          cd target/${{ matrix.target }}/release
          7z a ../../../mytool-${{ matrix.target }}.zip mytool.exe
          cd ../../..

      - uses: actions/upload-artifact@v4
        with:
          name: mytool-${{ matrix.target }}
          path: mytool-${{ matrix.target }}.*

  release:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/download-artifact@v4
        with:
          merge-multiple: true

      - name: Create Release
        uses: softprops/action-gh-release@v2
        with:
          files: mytool-*
          generate_release_notes: true


矩阵构建
矩阵构建（Matrix Build）同时在多个平台和配置上运行构建任务，确保 CLI 工具在所有目标环境中都能正确工作。

fn print_build_matrix() {
    let targets = vec![
        ("Linux x86_64", "x86_64-unknown-linux-musl", "ubuntu-latest"),
        ("Linux ARM64", "aarch64-unknown-linux-musl", "ubuntu-latest"),
        ("macOS Intel", "x86_64-apple-darwin", "macos-latest"),
        ("macOS ARM", "aarch64-apple-darwin", "macos-latest"),
        ("Windows", "x86_64-pc-windows-msvc", "windows-latest"),
    ];

    println!("{:<15} {:<35} {}", "平台", "Target Triple", "Runner");
    println!("{}", "-".repeat(70));
    for (name, target, runner) in &targets {
        println!("{:<15} {:<35} {}", name, target, runner);
    }
}

fn main() {
    print_build_matrix();
}


提示： ARM64 Linux 的交叉编译需要额外的工具链。使用 cross 工具或在 CI 中安装 gcc-aarch64-linux-gnu 来处理。






Changelog 自动生成
Changelog（变更日志）让用户了解每个版本的变化。git-cliff 和 conventional commits 是自动化 changelog 的主流方案。


# cliff.toml - git-cliff 配置
[changelog]
header = "# 变更日志\n\n"
body = """
{% for group, commits in commits | group_by(attribute="group") %}
### {{ group | upper_first }}
{% for commit in commits %}
- {{ commit.message | upper_first }} ({{ commit.id | truncate(length=7, end="") }})
{% endfor %}
{% endfor %}
"""
trim = true

[git]
conventional_commits = true
commit_parsers = [
    { message = "^feat", group = "✨ 新功能" },
    { message = "^fix", group = "🐛 修复" },
    { message = "^perf", group = "⚡ 性能" },
    { message = "^refactor", group = "♻️ 重构" },
    { message = "^doc", group = "📝 文档" },
    { message = "^ci", group = "👷 CI" },
]

发布流程自动化
完整的发布流程应最大限度地自动化，减少人工操作。


#!/usr/bin/env bash

VERSION=$1
if [ -z "$VERSION" ]; then
  echo "用法: ./release.sh <version>"
  exit 1
fi

echo "=== 发布 v$VERSION ==="

echo "1. 更新版本号..."
sed -i '' "s/^version = \".*\"/version = \"$VERSION\"/" Cargo.toml
cargo check

echo "2. 生成 changelog..."
git-cliff --tag "v$VERSION" -o CHANGELOG.md

echo "3. 提交变更..."
git add Cargo.toml Cargo.lock CHANGELOG.md
git commit -m "chore: release v$VERSION"

echo "4. 创建标签..."
git tag -a "v$VERSION" -m "Release v$VERSION"

echo "5. 推送..."
git push origin main --tags

echo "=== 完成! CI 将自动构建和发布 ==="


小结
    

  • GitHub Actions 的 tag 触发模式是 CLI 工具发布的标准流程
    • 

  • 矩阵构建同时覆盖 Linux、macOS、Windows 三大平台和 x86_64、ARM64 两种架构
    • 

  • git-cliff 基于 conventional commits 自动生成结构化的 changelog
    • 

  • 发布流程应自动化为脚本，减少人工操作中的遗漏和错误
    • 

  • softprops/action-gh-release 自动创建 GitHub Release 并附加预编译二进制
