全局负载均衡

概述

全局负载均衡（Global Server Load Balancing, GSLB）解决的是跨数据中心、跨地域的流量调度问题——将用户请求智能路由到最近、最健康、或最有容量的数据中心。与单集群内的负载均衡不同，全局负载均衡需要处理网络延迟差异、地理合规要求、灾难恢复切换等跨区域特有的复杂性。

2026年，多区域部署已成为规模化服务的标配架构。用户期望全球任何位置都能获得低延迟体验，业务要求在单区域故障时秒级切换，合规法规要求数据不出境。全局负载均衡正是实现这些要求的基础设施层关键能力。

核心概念

GSLB的决策维度

全局负载均衡在做路由决策时需要综合考虑多个因素：

维度 说明 优先级
地理接近性 将用户路由到物理最近的数据中心 高（降低延迟）
健康状态 只路由到健康的数据中心 最高（可用性基础）
容量余量 避免路由到已过载的站点 高（防止雪崩）
延迟数据 基于实时测量的网络延迟选择最优路径 中高
数据亲和性 将请求路由到持有其数据的区域 场景依赖
合规要求 数据主权/隐私法规约束 强制
成本 不同区域的计算和带宽成本差异 中

DNS-Based GSLB

最传统也是最广泛使用的全局负载均衡方式：

工作原理：

    2. 

  2. 权威DNS基于用户IP的地理位置判断最近站点

  3. 结合健康检查结果，返回最优站点的IP
    4. 

  4. 通过TTL控制DNS缓存时间，实现故障切换

Anycast路由


Anycast将同一IP地址在多个位置公告，利用BGP路由协议自动将流量导向网络距离最近的实例：


    

  • 多个数据中心公告相同的VIP（Virtual IP）
    • 

  • BGP路由器自动选择最短网络路径
    • 

  • 切换速度取决于BGP收敛（通常10-30秒）
    • 

  • 适合DNS服务器和CDN边缘节点
    • 



Cloudflare、Google Cloud和AWS CloudFront都大量使用Anycast。其核心优势是无需客户端DNS协助，直接在网络层完成路由。


基于延迟的智能路由


现代GSLB方案通过实时延迟测量实现最优路由：


    

  1. 主动测量：各站点间持续探测RTT
    2. 

  2. 客户端测量：通过JavaScript信标收集真实用户延迟
    3. 

  3. 综合决策：结合RTT + 服务器负载 + 历史数据做出路由
    4. 



AWS Route 53的Latency-Based Routing和Cloudflare的Smart Routing都采用这种方式。

容量感知的全局调度
仅基于地理位置路由可能导致热点区域过载。容量感知调度需要：


    

  1. 实时容量API：每个数据中心暴露当前负载百分比
    2. 

  2. 溢出策略：当本地站点负载>80%时，将增量流量导向邻近站点
    3. 

  3. 权重动态调整：根据各站点容量实时调整DNS权重
    4. 

  4. 预算控制：设置每个站点的最大流量限额
    5.

最佳实践
全局健康检查架构
全局健康检查不同于局部健康检查——它需要从多个观测点判断一个站点的全局可达性：


    

  • 多地探测：从3+个不同区域的探测点发起健康检查
    • 

  • 多维检测：TCP连通性 + HTTP状态码 + 业务语义检查
    • 

  • 多数决策：3个探测点中2个报告异常才判定为不健康（避免网络分区误判）
    • 

  • 渐进式摘除：检测到异常后先降低权重（50%→20%→0%），而非立即完全摘除
    • 



流量回切策略
故障恢复后的流量回切比切走更复杂：


    

  1. 验证恢复：确认故障站点完全恢复（不仅是连通，还需验证数据一致性）
    2. 

  2. 小比例导入：先回切5-10%流量观察
    3. 

  3. 逐步增加：5%→20%→50%→100%，每步观察10分钟
    4. 

  4. 自动回退：任一步出现异常自动回退到上一步
    5. 



监控与可观测性
全局负载均衡的监控维度：


    

  • 各区域流量分布比例（是否符合预期）
    • 

  • 跨区域延迟矩阵（是否有突变）
    • 

  • DNS解析时间和TTL命中率
    • 

  • 故障切换次数和切换耗时
    • 

  • 合规路由命中率（是否有误路由）
    •

总结
全局负载均衡是多区域架构的流量总调度器，通过DNS路由、Anycast、延迟感知路由等技术实现跨地域的智能流量分配。生产环境中需要综合考虑地理接近性、健康状态、容量余量和合规约束来做出路由决策。关键原则：健康优先（不健康的站点不路由）、延迟优先（在健康站点中选最快的）、容量兜底（过载站点自动溢出）、合规强制（法规约束不可逾越）。灾难恢复切换要快切慢回，避免二次故障。
