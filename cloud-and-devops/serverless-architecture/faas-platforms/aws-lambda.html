AWS Lambda 深入实践

核心概念

AWS Lambda 是 Amazon 于 2014 年推出的函数即服务（FaaS）产品，也是 Serverless 计算的开创者和市场领导者。Lambda 支持 Node.js、Python、Java、Go、.NET、Ruby 等多种运行时，以及通过 Custom Runtime 支持任意语言。理解 Lambda 的内部架构、执行模型和高级特性是构建生产级 Serverless 应用的基础。

Lambda 的核心价值在于将开发者从服务器管理中彻底解放：无需配置、无需补丁、无需扩缩容——只需编写函数代码，定义触发器，Lambda 处理一切。

Lambda 执行模型与并发
Lambda 的执行模型基于"一个请求一个执行环境"的原则。每个并发请求由独立的执行环境处理，执行环境之间完全隔离（基于 Firecracker microVM）。这意味着 Lambda 的并发数等于同时处理的请求数。


并发管理分为三种模式：


Unreserved Concurrency（不预留并发）：函数共享账户级别的并发池（默认 1000）。当某个函数突发流量时可能耗尽并发池，导致其他函数被限流。


Reserved Concurrency（预留并发）：为函数预留固定数量的并发实例，保证该函数始终有足够的并发能力，同时限制其最大并发数，防止下游服务被压垮。


Provisioned Concurrency（预置并发）：预先初始化指定数量的执行环境，消除冷启动。适用于延迟敏感的 API。


import {
  LambdaClient,
  PutFunctionConcurrencyCommand,
  PutProvisionedConcurrencyConfigCommand,
} from '@aws-sdk/client-lambda';

const lambda = new LambdaClient({});

await lambda.send(
  new PutFunctionConcurrencyCommand({
    FunctionName: 'my-api-handler',
    ReservedConcurrentExecutions: 100,
  }),
);

await lambda.send(
  new PutProvisionedConcurrencyConfigCommand({
    FunctionName: 'my-api-handler',
    Qualifier: 'prod',
    ProvisionedConcurrentExecutions: 20,
  }),
);
并发突增限制（Burst Limit）：Lambda 不会瞬间从 0 扩展到 1000 并发。在 us-east-1 区域，初始突增为 3000，之后每分钟增加 500。其他区域初始突增为 500-1000。超过突增限制的请求会被限流（返回 429 TooManyRequestsException）。

事件源映射（Event Source Mapping）是 Lambda 轮询式消费流/队列消息的机制。对于 SQS，Lambda 自动从队列拉取消息，批量传递给函数。批量大小（BatchSize）和批量窗口（MaximumBatchingWindowInSeconds）可配置：


import { CreateEventSourceMappingCommand } from '@aws-sdk/client-lambda';

await lambda.send(
  new CreateEventSourceMappingCommand({
    FunctionName: 'order-processor',
    EventSourceArn: 'arn:aws:sqs:us-east-1:123456789:orders',
    BatchSize: 10,
    MaximumBatchingWindowInSeconds: 5,
    FunctionResponseTypes: ['ReportBatchItemFailures'],
    ScalingConfig: {
      MaximumConcurrency: 50,
    },
  }),
);
ReportBatchItemFailures 是关键特性：函数可以报告批次中哪些消息处理失败，Lambda 只重试失败的消息而不是整个批次。这避免了已成功处理的消息被重复消费。


Kinesis 和 DynamoDB Streams 的事件源映射支持并行化因子（ParallelizationFactor），每个分片可由最多 10 个 Lambda 实例并行处理，提升吞吐量。配合 Bisect on Function Error，当批次处理失败时自动二分批次，快速定位问题记录。


Lambda 与 VPC 网络
Lambda 默认运行在 AWS 管理的 VPC 中，可以访问公网服务（如外部 API、SaaS 服务），但无法访问用户 VPC 内的资源（如 RDS、ElastiCache）。将 Lambda 配置为在用户 VPC 中运行后，函数实例通过 Hyperplane ENI 连接到指定的子网。


Hyperplane ENI（Elastic Network Interface）是 AWS 2019 年引入的优化。在此之前，每个 Lambda 执行环境都需要创建独立的 ENI，导致冷启动增加 8-10 秒。Hyperplane ENI 采用共享 ENI 架构，多个执行环境共享同一组 ENI，将 VPC 冷启动开销降至接近零。


VPC Lambda 访问公网需要 NAT Gateway（或 NAT Instance），这会增加 $30-50/月的固定成本。对于只需要访问 AWS 服务（如 DynamoDB、S3、SQS）的 Lambda，推荐使用 VPC Endpoint（PrivateLink），避免流量经过 NAT Gateway。


安全组与子网配置：Lambda 需要配置至少两个可用区的子网（高可用），安全组需允许出站流量到目标服务。入站规则通常不需要配置（Lambda 不接受入站连接）。


Lambda 高级特性
Lambda Destinations：异步调用的结果路由。成功和失败的调用可以分别路由到 SQS、SNS、EventBridge 或另一个 Lambda。替代传统的 DLQ（Dead Letter Queue），提供更灵活的错误处理。


Lambda Extensions：扩展函数的生命周期。内部扩展（In-process）作为运行时的一部分，外部扩展（Out-of-process）作为独立进程。典型用途包括：将日志发送到第三方服务、集成 APM 工具、缓存配置和密钥。


Lambda@Edge 与 CloudFront Functions：在 CDN 边缘节点执行函数。Lambda@Edge 支持 Node.js 和 Python，执行时长最长 30 秒（Origin 请求/响应）或 5 秒（Viewer 请求/响应）。CloudFront Functions 更轻量，执行时长最长 1ms，适合简单的 HTTP 头操作和 URL 重写。

小结
    

  • Lambda 基于 Firecracker microVM 提供函数级隔离，支持多种运行时和容器镜像
    • 

  • 并发管理三层：Unreserved（共享池）→ Reserved（预留隔离）→ Provisioned（预初始化）
    • 

  • 事件源分三种模式：同步、异步、事件源映射（SQS/Kinesis/DynamoDB Streams）
    • 

  • ReportBatchItemFailures 避免批次级重试的消息重复消费问题
    • 

  • VPC Lambda 通过 Hyperplane ENI 实现零额外冷启动，VPC Endpoint 避免 NAT 成本
    • 

  • Lambda Destinations 替代 DLQ 提供更灵活的异步调用结果路由
    • 

  • Lambda@Edge 和 CloudFront Functions 在 CDN 边缘执行，适合 HTTP 操作和内容定制
