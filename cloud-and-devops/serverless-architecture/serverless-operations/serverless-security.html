Serverless 安全实践

核心概念

Serverless 安全既继承了传统应用安全的核心原则（最小权限、纵深防御、安全默认），也引入了独特的安全挑战。函数的短暂生命周期、高度依赖第三方服务、事件驱动的输入多样性、以及传统安全工具（WAF、IDS）的适应困难，共同构成了 Serverless 安全的复杂性。

Serverless 安全的责任模型（Shared Responsibility Model）与传统架构有本质区别。云提供商负责运行时环境安全（OS 补丁、网络隔离、执行环境）；用户负责应用代码安全（函数逻辑、依赖管理、IAM 权限、数据加密）。这看似减轻了用户的安全负担，实际上提升了应用层安全的重要性——因为底层已经安全，攻击面聚焦在应用层。

IAM 最小权限实践
IAM（Identity and Access Management）是 Serverless 安全的基石。每个 Lambda 函数都有一个执行角色（Execution Role），定义函数可以访问的 AWS 服务和资源。遵循最小权限原则（Principle of Least Privilege），每个函数只授予完成其任务所需的最小权限集。


反模式：许多 Serverless 项目为了方便，给所有函数共享同一个具有广泛权限的角色（如 AmazonDynamoDBFullAccess、AmazonS3FullAccess）。这严重违反最小权限原则——一个只需要读取特定 DynamoDB 表的函数不应该有权删除任何表。


最佳实践：每个函数一个角色，权限精确到资源 ARN 和操作。


{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["dynamodb:GetItem", "dynamodb:Query"],
      "Resource": "arn:aws:dynamodb:us-east-1:123456789:table/Users"
    },
    {
      "Effect": "Allow",
      "Action": ["dynamodb:GetItem", "dynamodb:Query"],
      "Resource": "arn:aws:dynamodb:us-east-1:123456789:table/Users/index/*"
    },
    {
      "Effect": "Allow",
      "Action": ["sqs:SendMessage"],
      "Resource": "arn:aws:sqs:us-east-1:123456789:user-notifications"
    }
  ]
}
IAM Access Analyzer 可以自动分析 CloudTrail 日志，生成基于实际使用的最小权限策略。在开发阶段给予较宽松的权限，上线前使用 Access Analyzer 收敛到实际使用的最小集合。


权限边界（Permission Boundary）：为整个 Serverless 应用设置权限边界，限制函数角色能够获得的最大权限范围。即使开发者错误配置了过宽的权限，边界也能阻止越权访问。

输入验证与注入防护
Serverless 函数的输入来源比传统 API 更多样：HTTP 请求、SQS 消息、S3 事件、DynamoDB Streams、Kinesis 记录、EventBridge 事件等。每种输入都可能携带恶意数据，必须进行严格的验证和清洗。


OWASP Serverless Top 10 中排名最高的风险就是注入攻击（Injection）。攻击者通过恶意事件数据注入 SQL、NoSQL、OS 命令或表达式。


import { z } from 'zod';

const orderEventSchema = z.object({
  orderId: z.string().uuid(),
  userId: z.string().regex(/^USR-[0-9]+$/),
  amount: z.number().positive().max(1000000),
  currency: z.enum(['USD', 'EUR', 'GBP', 'CNY']),
  items: z
    .array(
      z.object({
        sku: z.string().regex(/^[A-Z]{3}-[0-9]{6}$/),
        quantity: z.number().int().positive().max(999),
      }),
    )
    .min(1)
    .max(100),
});

export const handler = async (event: SQSEvent) => {
  for (const record of event.Records) {
    const parsed = orderEventSchema.safeParse(JSON.parse(record.body));
    if (!parsed.success) {
      console.error('Invalid event', parsed.error.flatten());
      continue;
    }
    await processOrder(parsed.data);
  }
};
DynamoDB 注入防护：DynamoDB 的表达式语法支持条件表达式和投影表达式。如果将用户输入直接拼接到表达式中，攻击者可以修改查询逻辑。使用 ExpressionAttributeNames 和 ExpressionAttributeValues 参数化表达式。


API Gateway 请求验证：在 API Gateway 层配置请求模型验证（JSON Schema），在请求到达 Lambda 之前拒绝不合规的输入。这减少了无效请求消耗的 Lambda 计算资源。


密钥管理与加密
Serverless 函数需要访问数据库密码、API Key、证书等敏感信息。将密钥硬编码在代码或环境变量中是高风险做法。


AWS Secrets Manager 是推荐的密钥管理方案。它提供加密存储、自动轮换、审计日志和跨账户共享。Lambda 通过 AWS SDK 在运行时获取密钥，而非在部署时注入。


import { SecretsManagerClient, GetSecretValueCommand } from '@aws-sdk/client-secrets-manager';

const client = new SecretsManagerClient({});
let cachedSecret: Record<string, string> | null = null;

const getSecret = async (secretId: string): Promise<Record<string, string>> => {
  if (cachedSecret) return cachedSecret;

  const response = await client.send(new GetSecretValueCommand({ SecretId: secretId }));

  cachedSecret = JSON.parse(response.SecretString!);
  return cachedSecret!;
};

export const handler = async () => {
  const secrets = await getSecret('prod/database-credentials');
  const dbConnection = await connect({
    host: secrets.host,
    username: secrets.username,
    password: secrets.password,
  });
};
Lambda Powertools Parameters 提供内置的密钥缓存和 TTL 管理。在 Handler 外部获取并缓存密钥，温启动时直接使用缓存，减少 Secrets Manager API 调用。


传输加密：Lambda 与 AWS 服务之间的通信默认使用 TLS 1.2+ 加密。VPC 内的通信通过 VPC Endpoint 的 PrivateLink 加密。外部 API 调用必须验证 TLS 证书。


静态加密：Lambda 环境变量支持 KMS 加密。DynamoDB 表支持 AWS 托管密钥或客户管理密钥（CMK）加密。S3 对象支持 SSE-S3、SSE-KMS 和 SSE-C 三种加密方式。

供应链安全与依赖管理
Serverless 函数的依赖包（npm、pip）是攻击面的重要组成部分。供应链攻击（如 npm 包投毒、恶意依赖注入）是近年来增长最快的安全威胁之一。


依赖扫描：在 CI/CD 管道中集成 npm audit、Snyk、GitHub Dependabot 或 OWASP Dependency-Check。定期扫描已知漏洞（CVE），阻断含有高危漏洞的部署。


依赖锁定：使用 package-lock.json（npm）或 pnpm-lock.yaml（pnpm）锁定精确的依赖版本。禁止在 CI 中使用 npm install（可能更新版本），改用 npm ci（严格遵循 lock 文件）。


最小依赖原则：每个函数只打包必需的依赖。使用 esbuild 的 Tree Shaking 消除未使用的代码。定期审查 package.json，移除不再使用的依赖。


Lambda 代码签名：AWS 支持对 Lambda 部署包进行代码签名验证。只有经过签名的代码包才能部署，防止未授权的代码变更。


小结
    

  • Serverless 安全聚焦应用层：IAM 权限、输入验证、密钥管理、依赖安全
    • 

  • IAM 最小权限：每个函数独立角色，权限精确到资源 ARN 和操作
    • 

  • 输入验证：Zod Schema 验证 + API Gateway 请求模型 + WAF 规则三层防护
    • 

  • 密钥管理：Secrets Manager + Powertools 缓存，禁止明文硬编码
    • 

  • 供应链安全：npm ci 锁定版本 + Snyk 扫描 + Lambda 代码签名
    • 

  • 传输加密默认 TLS 1.2+，静态加密使用 KMS 管理密钥
    • 

  • 权限边界和 SCP 提供组织级安全约束
