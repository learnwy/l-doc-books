Serverless 监控与可观测性

核心概念

Serverless 应用的监控与可观测性面临独特挑战：函数实例生命周期短暂（毫秒到分钟级）、执行环境不可访问、分布式调用链跨越多个托管服务。传统的基于 Agent 的监控方案（如在服务器安装 Prometheus Node Exporter）在 Serverless 架构中不适用。需要采用无侵入或轻侵入的监控策略。

Serverless 可观测性的三大支柱与传统架构相同——指标（Metrics）、日志（Logs）、追踪（Traces），但每个支柱的实现方式和关注点有所不同。核心关注的指标包括：调用次数、错误率、执行时长（P50/P95/P99）、冷启动比例、并发使用率和限流事件。

CloudWatch 与 Lambda 指标
AWS CloudWatch 是 Lambda 监控的默认平台。Lambda 自动发送以下指标到 CloudWatch（无需任何配置）：


Invocations：函数被调用的次数。包括成功和失败的调用，但不包括被限流的请求。


Errors：导致函数错误的调用次数。包括函数代码抛出的异常、运行时错误和超时。区分于 Throttles（限流不算错误）。


Duration：函数执行时长（毫秒）。从 Handler 开始到返回响应的时间。不包括冷启动的 Init Duration。CloudWatch 自动计算 P50、P90、P99 百分位。


ConcurrentExecutions：同一时刻正在执行的函数实例数。是容量规划和并发配置的关键指标。


CloudWatch Logs Insights 是分析 Lambda 日志的利器。Lambda 的 REPORT 日志行包含丰富的执行元数据：


REPORT RequestId: abc-123
Duration: 45.67 ms
Billed Duration: 46 ms
Memory Size: 256 MB
Max Memory Used: 128 MB
Init Duration: 234.56 ms
使用 Logs Insights 查询冷启动模式：


filter @type = "REPORT"
| stats count() as invocations,
        count(@initDuration) as coldStarts,
        avg(@initDuration) as avgColdStart,
        max(@initDuration) as maxColdStart,
        avg(@duration) as avgDuration,
        max(@maxMemoryUsed) / max(@memorySize) * 100 as memoryUtilization
| by bin(1h)
Embedded Metrics Format (EMF) 允许在 Lambda 日志中嵌入自定义指标，CloudWatch 自动提取为可查询的指标。无需调用 CloudWatch PutMetricData API，延迟更低、成本更低。


import { MetricUnit, logMetrics } from '@aws-lambda-powertools/metrics';

const metrics = logMetrics({ namespace: 'OrderService' });

export const handler = async (event: unknown) => {
  metrics.addMetric('OrderProcessed', MetricUnit.Count, 1);
  metrics.addMetric('ProcessingTime', MetricUnit.Milliseconds, 45);
  metrics.addDimension('Environment', 'production');
  metrics.publishStoredMetrics();
};
分布式追踪与 X-Ray
AWS X-Ray 是 Serverless 应用的分布式追踪服务。X-Ray 自动追踪 Lambda 函数的调用链，包括对 AWS SDK、HTTP 客户端和 SQL 数据库的下游调用。


Active Tracing 启用后，Lambda 自动为每次调用创建一个 Trace Segment。X-Ray SDK 或 ADOT（AWS Distro for OpenTelemetry）自动捕获 AWS SDK 调用、HTTP 请求和数据库查询作为 Subsegment。


X-Ray Service Map 自动生成服务依赖关系图，显示每个服务节点的延迟、错误率和请求量。对于排查跨服务性能问题极为有效。


OpenTelemetry 集成：AWS 提供 ADOT Lambda Layer，将 OpenTelemetry SDK 集成到 Lambda 函数中。ADOT 同时发送 Traces 到 X-Ray 和第三方平台（Datadog、Honeycomb、Jaeger）。


import { trace, SpanStatusCode } from '@opentelemetry/api';

const tracer = trace.getTracer('order-service');

export const handler = async (event: unknown) => {
  return tracer.startActiveSpan('processOrder', async (span) => {
    try {
      span.setAttribute('order.id', 'ORD-123');
      const result = await processOrderLogic(event);
      span.setStatus({ code: SpanStatusCode.OK });
      return result;
    } catch (error) {
      span.setStatus({ code: SpanStatusCode.ERROR });
      span.recordException(error as Error);
      throw error;
    } finally {
      span.end();
    }
  });
};

Lambda Powertools 工具链
AWS Lambda Powertools 是一套 Serverless 最佳实践工具库，提供结构化日志、指标、追踪和幂等性等开箱即用的功能。支持 TypeScript、Python、Java 和 .NET。


Logger（结构化日志）：自动注入 Lambda 上下文（function_name、request_id、cold_start）到每条日志。支持日志采样（仅记录指定比例的 DEBUG 日志）。


import { Logger } from '@aws-lambda-powertools/logger';

const logger = new Logger({
  serviceName: 'order-service',
  logLevel: 'INFO',
  sampleRateValue: 0.1,
});

export const handler = async (event: unknown) => {
  logger.addContext({ orderId: 'ORD-123' });
  logger.info('Processing order', { items: 3 });
  logger.warn('Inventory low', { sku: 'PROD-001', remaining: 5 });
};
Tracer（追踪增强）：基于 X-Ray SDK 的封装，自动捕获 Lambda Handler 和方法级的追踪。支持注解（Annotation）和元数据（Metadata）添加。


Idempotency（幂等性）：基于 DynamoDB 的幂等性中间件。使用幂等键（从请求中提取）和过期时间防止重复处理。

第三方监控平台
对于生产级 Serverless 应用，云原生监控工具（CloudWatch + X-Ray）可能不足以满足复杂的监控需求。第三方平台提供更丰富的可视化、更智能的告警和跨云统一的监控体验。


Datadog Serverless Monitoring 提供 Lambda 函数的自动检测、端到端分布式追踪、实时日志关联和成本分析。Datadog Lambda Layer 自动注入追踪和指标收集。Serverless 专用视图展示冷启动比例、内存利用率、超时风险等 Serverless 特有指标。


Lumigo 是 Serverless 专注的可观测性平台。零代码自动追踪（通过 Lambda Layer 自动 hook SDK 调用）。Payload 可视化：自动捕获并展示每个函数调用的输入和输出（可选脱敏）。Timeline 视图：直观展示事件在多个函数间的传播路径。


Honeycomb 以高基数分析见长，适合排查复杂的分布式系统问题。BubbleUp 功能自动发现导致延迟或错误飙升的异常维度组合。
