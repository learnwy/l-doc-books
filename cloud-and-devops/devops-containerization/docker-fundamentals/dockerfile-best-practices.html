Dockerfile 最佳实践

Dockerfile 基础结构

Dockerfile 是构建容器镜像的声明式脚本，每条指令创建镜像的一个新层。编写高质量的 Dockerfile 直接影响镜像大小、构建速度和运行时安全性。

FROM node:20-alpine AS base
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile
COPY . .
RUN pnpm build
FROM node:20-alpine AS runtime
WORKDIR /app
COPY --from=base /app/dist ./dist
COPY --from=base /app/node_modules ./node_modules
USER 1000:1000
EXPOSE 3000
CMD ["node", "dist/index.js"]
指令 作用 是否创建新层
FROM 指定基础镜像 是
WORKDIR 设置工作目录 是
COPY 复制文件到镜像 是
RUN 执行命令 是
CMD 容器启动命令 否（元数据）
EXPOSE 声明端口 否（元数据）
ENV 设置环境变量 是
ARG 构建时变量 否
USER 指定运行用户 是
ENTRYPOINT 入口点命令 否（元数据）

多阶段构建

多阶段构建（Multi-stage Build）是优化镜像大小的核心技术。通过在一个 Dockerfile 中定义多个 FROM 阶段，将构建依赖与运行时依赖分离。

FROM golang:1.22-alpine AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -ldflags="-s -w" -o /app/server ./cmd/server

FROM gcr.io/distroless/static-debian12 AS runtime
COPY --from=build /app/server /server
ENTRYPOINT ["/server"]

层缓存优化
Docker 使用层缓存加速构建。当某一层的输入没有变化时，Docker 直接复用缓存而不重新执行。理解缓存失效规则是优化构建速度的关键。


关键优化策略：


COPY package.json pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile

COPY tsconfig.json ./
COPY src/ ./src/
RUN pnpm build
错误示范与正确做法对比：


RUN apt-get update
RUN apt-get install -y curl
RUN apt-get install -y git

RUN apt-get update && \
    apt-get install -y --no-install-recommends \
      curl \
      git && \
    rm -rf /var/lib/apt/lists/*

安全加固
安全是 Dockerfile 编写中不可忽视的维度。遵循最小权限原则，减少攻击面。


FROM node:20-alpine

RUN addgroup -g 1001 appgroup && \
    adduser -u 1001 -G appgroup -D appuser

WORKDIR /app
COPY --chown=appuser:appgroup . .

RUN npm ci --omit=dev

USER appuser

HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost:3000/health || exit 1

CMD ["node", "src/index.js"]
docker scout cves nginx:alpine

docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \
  aquasec/trivy image nginx:alpine


提示： 永远不要在 Dockerfile 中硬编码密钥、令牌或密码。使用 Docker BuildKit 的 --secret 挂载或运行时的环境变量注入来管理敏感信息。docker history 命令可以查看镜像的所有层，任何通过 ENV 或 COPY 写入的数据都会被永久记录。

小结
    

  • Dockerfile 每条 RUN、COPY、ADD 指令创建一个新的镜像层，合理组织指令顺序可显著提升构建速度。
    • 

  • 多阶段构建将编译环境与运行时环境分离，可将镜像大小从 GB 级缩小到 MB 级。
    • 

  • 层缓存的关键策略：先复制依赖清单文件并安装依赖，再复制源代码。
    • 

  • 安全加固三要素：非 root 用户运行、不在镜像中存储敏感信息、定期扫描镜像漏洞。
    • 

  • .dockerignore 文件应排除 .git、node_modules、.env 等敏感或无用文件。
    •
