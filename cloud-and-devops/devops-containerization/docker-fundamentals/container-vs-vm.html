容器与虚拟机

虚拟化技术演进

从物理服务器到虚拟机，再到容器，计算资源的虚拟化经历了三个重要阶段。每一次演进都在追求更高的资源利用率和更快的交付速度。

物理服务器时代，每台服务器只能运行一个操作系统和一组应用，资源利用率通常不到 15%。虚拟机通过 Hypervisor 在一台物理机上运行多个完整的操作系统实例，将利用率提升到 60-80%。而容器则更进一步，通过共享宿主机内核，将启动时间从分钟级降低到秒级。

架构对比
虚拟机和容器的根本区别在于虚拟化的层次。虚拟机虚拟化整个硬件层，每个 VM 运行完整的操作系统；容器虚拟化操作系统层，所有容器共享宿主机内核。


容器不包含完整的操作系统，而是复用宿主机内核，只打包应用本身和它的运行时依赖。这种设计带来了显著的性能优势：


docker run --rm alpine cat /proc/version

docker stats --no-stream --format "table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}"


提示： 容器并不是一种全新的虚拟化技术，而是利用 Linux 内核已有的隔离机制（Namespace + Cgroup）构建的进程管理方案。容器中的进程本质上就是宿主机上的普通进程。






Linux 内核隔离机制
容器的隔离能力来自 Linux 内核的三大机制：Namespace、Cgroup 和 UnionFS。


Namespace
Namespace 为容器提供了独立的系统视图，让容器内的进程认为自己运行在一个独立的操作系统中。

Cgroup
Cgroup（Control Group）限制容器可使用的资源上限，防止单个容器耗尽宿主机资源。


docker run -d --name limited \
  --cpus="1.5" \
  --memory="512m" \
  --memory-swap="1g" \
  nginx:alpine

cat /sys/fs/cgroup/memory/docker/$(docker inspect --format '{{.Id}}' limited)/memory.limit_in_bytes
UnionFS
UnionFS（联合文件系统）实现了镜像的分层存储，多个只读层叠加一个可写层，形成容器的文件系统视图。




OCI 标准
Open Container Initiative（OCI）定义了容器技术的开放标准，确保不同容器运行时之间的互操作性。

提示： Docker 不再是唯一的容器运行时。containerd、CRI-O、Podman 等都遵循 OCI 标准，可以运行相同的容器镜像。Kubernetes 从 1.24 版本开始已移除对 Docker 运行时的直接支持，转而使用 containerd。






容器安全边界
容器的隔离是进程级的，相比虚拟机有更薄的安全边界。了解这一点对于生产环境的安全部署至关重要。


关键安全措施：


docker run --rm \
  --read-only \
  --tmpfs /tmp \
  --security-opt=no-new-privileges \
  --cap-drop ALL \
  --cap-add NET_BIND_SERVICE \
  --user 1000:1000 \
  nginx:alpine

小结
    

  • 虚拟机通过 Hypervisor 虚拟化硬件层，每个 VM 包含完整操作系统；容器通过 Namespace 和 Cgroup 虚拟化操作系统层，共享宿主机内核。
    • 

  • 容器的启动速度为毫秒到秒级，资源占用在 MB 级别，单机可运行数百到数千个容器。
    • 

  • Namespace 提供隔离视图，Cgroup 限制资源配额，UnionFS 实现分层存储。
    • 

  • OCI 标准确保了容器镜像和运行时的跨平台互操作性。
    • 

  • 容器的安全边界弱于虚拟机，生产环境必须采取非 root 运行、能力裁剪等安全加固措施。
    •
