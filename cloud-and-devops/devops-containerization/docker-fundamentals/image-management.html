镜像管理

镜像分层存储

Docker 镜像由一系列只读层（Layer）按顺序叠加而成，每一层代表 Dockerfile 中的一条指令。容器运行时会在顶部添加一个可写层（Container Layer），所有运行时修改都发生在这一层。

docker image inspect nginx:alpine --format '{{json .RootFS.Layers}}' | jq .

docker history nginx:alpine --format "table {{.CreatedBy}}\t{{.Size}}"




概念
说明





镜像层
Dockerfile 中每条指令产生的只读文件系统差异




容器层
容器运行时在镜像层之上的可写层




内容寻址
每层通过 SHA256 哈希唯一标识




层共享
相同基础镜像的容器共享底层只读层




Copy-on-Write
修改文件时将文件从只读层复制到可写层







提示： 镜像层的共享机制意味着，如果 10 个容器都基于同一个 node:20-alpine 基础镜像，磁盘上只需存储一份基础镜像层。这是容器比虚拟机更节省磁盘空间的关键原因之一。






标签策略
镜像标签（Tag）是镜像版本管理的核心。合理的标签策略能够保证部署的可追溯性和回滚能力。


docker tag myapp:latest registry.example.com/team/myapp:1.2.3
docker tag myapp:latest registry.example.com/team/myapp:1.2
docker tag myapp:latest registry.example.com/team/myapp:1
docker tag myapp:latest registry.example.com/team/myapp:latest
docker tag myapp:latest registry.example.com/team/myapp:sha-a1b2c3d

提示： 在生产环境中永远不要使用 latest 标签部署。latest 是一个可变标签，不同时间 pull 可能得到不同的镜像内容，无法保证部署的确定性。始终使用精确的语义化版本或 Git SHA 标签。






镜像仓库
镜像仓库（Registry）是存储和分发容器镜像的服务。根据安全和合规需求，可以选择公共仓库或私有仓库。


docker login registry.example.com

docker push registry.example.com/team/myapp:1.2.3

docker pull registry.example.com/team/myapp:1.2.3

docker manifest inspect registry.example.com/team/myapp:1.2.3

镜像生命周期管理
随着持续构建，镜像仓库中会积累大量过期镜像。合理的生命周期策略保证存储成本可控。


docker image prune -a --filter "until=720h"

docker system prune --all --volumes

docker images --filter "dangling=true" -q | xargs docker rmi

小结
    

  • Docker 镜像由只读层叠加而成，使用内容寻址（SHA256）实现层共享和去重。
    • 

  • 标签策略应结合语义化版本和 Git SHA，生产环境禁止使用 latest 标签。
    • 

  • 镜像仓库选择取决于安全需求：公共项目用 Docker Hub / GHCR，企业内部用 ECR / Harbor。
    • 

  • 镜像瘦身的最大收益来自多阶段构建和更换轻量基础镜像，可节省 90% 以上体积。
    • 

  • 建立自动化的镜像生命周期管理策略，定期清理过期镜像以控制存储成本。
    •
