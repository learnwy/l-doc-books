ConfigMap 与 Secret

配置管理原则

Kubernetes 倡导将应用配置与容器镜像分离——同一个镜像应能通过不同的配置运行在开发、测试和生产环境中。ConfigMap 和 Secret 是实现这一目标的核心资源。





原则
说明





配置与代码分离
镜像不包含环境特定的配置




环境无关镜像
同一镜像通过不同配置适配不同环境




敏感数据加密
密码、密钥等使用 Secret 并加密存储




配置版本化
配置变更应可追溯和回滚







ConfigMap
ConfigMap 存储非敏感的键值配置数据，可以通过环境变量或挂载文件的方式注入到 Pod 中。


创建 ConfigMap
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  LOG_LEVEL: 'info'
  MAX_CONNECTIONS: '100'
  DATABASE_HOST: 'postgres.default.svc.cluster.local'
  nginx.conf: |
    server {
        listen 80;
        server_name localhost;
        location / {
            proxy_pass http://api:3000;
        }
    }
kubectl create configmap app-config \
  --from-literal=LOG_LEVEL=info \
  --from-literal=MAX_CONNECTIONS=100

kubectl create configmap nginx-config \
  --from-file=nginx.conf=./config/nginx.conf

kubectl get configmap app-config -o yaml
使用 ConfigMap
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
spec:
  template:
    spec:
      containers:
        - name: api
          image: myapi:1.0.0
          envFrom:
            - configMapRef:
                name: app-config
          env:
            - name: SPECIFIC_KEY
              valueFrom:
                configMapKeyRef:
                  name: app-config
                  key: LOG_LEVEL
          volumeMounts:
            - name: config-volume
              mountPath: /etc/nginx/conf.d
              readOnly: true
      volumes:
        - name: config-volume
          configMap:
            name: app-config
            items:
              - key: nginx.conf
                path: default.conf




注入方式
适用场景
实时更新





envFrom
注入所有键值为环境变量
需重启 Pod




env.valueFrom
注入特定键为环境变量
需重启 Pod




volumeMount
以文件形式挂载
自动更新







提示： 通过 Volume 挂载的 ConfigMap 在更新后会自动同步到 Pod 中（延迟约 1-2 分钟）。但以环境变量方式注入的值不会自动更新，需要重启 Pod 才能生效。






Secret
Secret 用于存储敏感数据，如密码、OAuth 令牌、TLS 证书等。Secret 的值以 Base64 编码存储。


apiVersion: v1
kind: Secret
metadata:
  name: db-credentials
type: Opaque
data:
  username: YWRtaW4=
  password: c3VwZXJzZWNyZXQ=
kubectl create secret generic db-credentials \
  --from-literal=username=admin \
  --from-literal=password=supersecret

kubectl create secret tls app-tls \
  --cert=./tls.crt \
  --key=./tls.key

echo -n 'admin' | base64
echo 'YWRtaW4=' | base64 -d

apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
spec:
  template:
    spec:
      containers:
        - name: api
          image: myapi:1.0.0
          env:
            - name: DB_USERNAME
              valueFrom:
                secretKeyRef:
                  name: db-credentials
                  key: username
            - name: DB_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: db-credentials
                  key: password
          volumeMounts:
            - name: tls-certs
              mountPath: /etc/tls
              readOnly: true
      volumes:
        - name: tls-certs
          secret:
            secretName: app-tls


提示： Kubernetes Secret 默认仅使用 Base64 编码，并非真正的加密。生产环境中应启用 etcd 静态加密（Encryption at Rest），或使用外部密钥管理服务（如 Vault、AWS Secrets Manager）配合 External Secrets Operator 管理敏感数据。






不可变 ConfigMap 与 Secret
从 Kubernetes 1.21 开始，可以将 ConfigMap 和 Secret 标记为不可变（immutable），防止意外修改并提升性能。


apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config-v2
immutable: true
data:
  LOG_LEVEL: 'warn'
  MAX_CONNECTIONS: '200'




特性
可变配置
不可变配置





修改
可随时修改
创建后不可修改




更新方式
直接修改 + 重启 Pod
创建新版本 + 滚动更新




API 压力
kubelet 持续监听变化
无需监听，性能更优




回滚
需要记录历史值
保留旧版本即可回滚







配置管理最佳实践
kubectl create configmap app-config-v3 \
  --from-env-file=.env.production \
  --dry-run=client -o yaml | kubectl apply -f -

kubectl rollout restart deployment/api




最佳实践
说明





版本化命名

分环境管理
每个环境独立的 ConfigMap/Secret




使用 Kustomize
通过 overlay 管理环境差异




外部密钥管理
Vault / AWS Secrets Manager 集成




定期轮换密钥
建立密钥自动轮换机制




RBAC 限制访问
限制 Secret 的读取权限







小结
    

  • ConfigMap 存储非敏感配置，支持环境变量注入和文件挂载两种方式。
    • 

  • Secret 存储敏感数据，默认 Base64 编码，生产环境应启用 etcd 加密或使用外部密钥管理。
    • 

  • Volume 挂载的配置支持自动更新，环境变量注入的配置需要重启 Pod 才能生效。
    • 

  • 不可变配置通过版本化命名和滚动更新实现安全的配置变更，同时降低 API Server 压力。
    • 

  • 使用 Kustomize 管理多环境配置差异，使用 External Secrets Operator 集成外部密钥管理服务。
    •
