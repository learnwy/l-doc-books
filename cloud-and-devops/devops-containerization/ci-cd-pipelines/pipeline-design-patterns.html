流水线设计模式

CI/CD 核心阶段

一条完整的 CI/CD 流水线通常由源码管理、构建、测试、安全扫描、制品发布和部署六个核心阶段组成。每个阶段都应该是自动化的、可重复的。

提示： 流水线的核心原则是"快速失败"（Fail Fast）。将速度最快、最容易发现问题的检查（如代码格式化、类型检查）放在最前面，耗时较长的测试（如 E2E 测试）放在后面，减少开发者等待时间。

触发机制
流水线触发机制决定了何时以及如何启动自动化流程。


on:
  push:
    branches: [main]
    paths-ignore:
      - '**.md'
      - 'docs/**'
  pull_request:
    branches: [main]
  schedule:
    - cron: '0 2 * * 1'
  workflow_dispatch:
    inputs:
      environment:
        type: choice
        options: [staging, production]

流水线优化
流水线执行速度直接影响开发者体验和交付效率。优化策略从并行化、缓存和增量构建三个维度展开。


并行化
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - run: npm run lint

  typecheck:
    runs-on: ubuntu-latest
    steps:
      - run: npm run typecheck

  unit-test:
    runs-on: ubuntu-latest
    steps:
      - run: npm test

  build:
    needs: [lint, typecheck, unit-test]
    runs-on: ubuntu-latest
    steps:
      - run: npm run build
缓存策略
- uses: actions/cache@v4
  with:
    path: ~/.pnpm-store
    key: pnpm-${{ hashFiles('pnpm-lock.yaml') }}
    restore-keys: pnpm-

提示： 在 CI 中使用 pnpm install --frozen-lockfile 而非 pnpm install。--frozen-lockfile 确保安装的依赖与锁文件完全一致，如果不一致则直接报错，避免 CI 环境中出现与开发环境不同的依赖版本。






质量门禁
质量门禁（Quality Gate）是流水线中的检查点，只有通过所有检查的代码才能进入下一阶段。


jobs:
  quality-gate:
    runs-on: ubuntu-latest
    steps:
      - name: lint
        run: npm run lint

      - name: typecheck
        run: npm run typecheck

      - name: test with coverage
        run: npm test -- --coverage

      - name: check coverage threshold
        run: |
          COVERAGE=$(cat coverage/coverage-summary.json | jq '.total.lines.pct')
          if (( $(echo "$COVERAGE < 80" | bc -l) )); then
            echo "Coverage $COVERAGE% is below 80% threshold"
            exit 1
          fi

小结
    

  • CI/CD 流水线包含构建、测试、安全扫描、制品发布和部署六个核心阶段。
    • 

  • Trunk-Based Development 适合高频交付团队，GitHub Flow 是小团队的平衡选择。
    • 

  • 遵循"快速失败"原则，将轻量检查前置，耗时任务后置。
    • 

  • 通过作业并行化和依赖缓存可以将流水线时间缩短 60% 以上。
    • 

  • 质量门禁确保只有通过所有检查的代码才能合并和部署。
    •
