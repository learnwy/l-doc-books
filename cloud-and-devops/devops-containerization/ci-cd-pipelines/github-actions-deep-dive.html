GitHub Actions 深入

工作流基础结构

GitHub Actions 是 GitHub 原生的 CI/CD 平台，通过 YAML 文件定义自动化工作流。工作流文件存储在仓库的 .github/workflows/ 目录中。

name: CI Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

permissions:
  contents: read
  packages: write

env:
  NODE_VERSION: '20'
  REGISTRY: ghcr.io

jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: pnpm

      - run: pnpm install --frozen-lockfile
      - run: pnpm run lint
      - run: pnpm run typecheck
      - run: pnpm test
工作流组件 说明 示例
name 工作流名称 CI Pipeline
on 触发条件 push, pull_request
permissions GITHUB_TOKEN 权限 contents: read
env 工作流级环境变量 NODE_VERSION: "20"
jobs 作业定义 ci, build, deploy
steps 作业中的步骤 checkout, test, build 


作业编排
多个 Job 之间可以定义依赖关系，实现并行执行和条件执行。


jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pnpm run lint

  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [18, 20, 22]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
      - run: pnpm install --frozen-lockfile
      - run: pnpm test

  build:
    needs: [lint, test]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pnpm run build

  deploy:
    needs: build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment: production
    steps:
      - run: echo "Deploying to production"

缓存与制品
合理利用缓存和制品传递可以显著加速流水线并在 Job 间共享数据。


jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/cache@v4
        id: deps-cache
        with:
          path: |
            ~/.pnpm-store
            node_modules
          key: deps-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            deps-${{ runner.os }}-

      - run: pnpm install --frozen-lockfile

      - run: pnpm build

      - uses: actions/upload-artifact@v4
        with:
          name: build-output
          path: dist/
          retention-days: 7

  deploy:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/download-artifact@v4
        with:
          name: build-output
          path: dist/

Docker 镜像构建与推送
在 CI 中构建容器镜像并推送到镜像仓库是容器化部署流水线的核心环节。


jobs:
  docker:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v4

      - uses: docker/setup-buildx-action@v3

      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - uses: docker/metadata-action@v5
        id: meta
        with:
          images: ghcr.io/${{ github.repository }}
          tags: |
            type=semver,pattern={{version}}
            type=semver,pattern={{major}}.{{minor}}
            type=sha

      - uses: docker/build-push-action@v6
        with:
          context: .
          push: ${{ github.event_name != 'pull_request' }}
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max




Action
功能





docker/setup-buildx-action
配置 BuildKit 构建器




docker/login-action
登录镜像仓库




docker/metadata-action
自动生成标签和标注




docker/build-push-action
构建并推送镜像







提示： 使用 cache-from: type=gha 和 cache-to: type=gha,mode=max 可以利用 GitHub Actions 的缓存存储 Docker 层缓存，大幅加速后续构建。mode=max 会缓存所有中间层，而不仅仅是最终镜像的层。

小结
    

  • GitHub Actions 工作流由 on（触发）、jobs（作业）和 steps（步骤）三层结构组成。
    • 

  • needs 定义作业依赖，matrix 实现多维度并行测试，if 支持条件执行。
    • 

  • 使用 actions/cache 缓存依赖，upload/download-artifact 在 Job 间传递构建产物。
    • 

  • Docker 镜像构建推荐使用 docker/build-push-action 配合 GHA 层缓存加速构建。
    • 

  • 敏感数据通过 Repository/Environment Secrets 管理，生产环境启用审批保护。
