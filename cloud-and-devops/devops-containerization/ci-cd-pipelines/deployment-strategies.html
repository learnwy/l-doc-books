部署策略概览

部署策略决定了新版本如何替换旧版本。不同的策略在风险控制、资源消耗和回滚速度之间做出不同的权衡。选择合适的部署策略是实现零停机和安全发布的关键。

滚动更新
滚动更新（Rolling Update）逐步用新版本 Pod 替换旧版本，是 Kubernetes Deployment 的默认策略。


apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
spec:
  replicas: 4
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    spec:
      containers:
        - name: api
          image: myapi:2.0.0
          readinessProbe:
            httpGet:
              path: /ready
              port: 3000
            initialDelaySeconds: 10
            periodSeconds: 5
kubectl rollout status deployment/api

kubectl rollout history deployment/api

kubectl rollout undo deployment/api


提示： 设置 maxUnavailable: 0 确保更新过程中始终有足够的 Pod 处理请求。配合 readinessProbe 使用，只有新 Pod 通过就绪检查后才会终止旧 Pod，实现真正的零停机更新。






蓝绿部署
蓝绿部署同时维护两个完全相同的环境——蓝色（当前版本）和绿色（新版本）。通过切换流量入口实现瞬间切换和快速回滚。


apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-green
  labels:
    app: api
    version: green
spec:
  replicas: 4
  selector:
    matchLabels:
      app: api
      version: green
  template:
    metadata:
      labels:
        app: api
        version: green
    spec:
      containers:
        - name: api
          image: myapi:2.0.0
---
apiVersion: v1
kind: Service
metadata:
  name: api
spec:
  selector:
    app: api
    version: green
  ports:
    - port: 80
      targetPort: 3000
kubectl patch service api -p '{"spec":{"selector":{"version":"green"}}}'

kubectl patch service api -p '{"spec":{"selector":{"version":"blue"}}}'

金丝雀发布
金丝雀发布（Canary Release）将新版本先暴露给一小部分流量，验证无误后再逐步扩大到全量。这是大规模服务最安全的发布策略。


apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-canary
spec:
  replicas: 1
  selector:
    matchLabels:
      app: api
      track: canary
  template:
    metadata:
      labels:
        app: api
        track: canary
    spec:
      containers:
        - name: api
          image: myapi:2.0.0
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-stable
spec:
  replicas: 9
  selector:
    matchLabels:
      app: api
      track: stable
  template:
    metadata:
      labels:
        app: api
        track: stable
    spec:
      containers:
        - name: api
          image: myapi:1.0.0
---
apiVersion: v1
kind: Service
metadata:
  name: api
spec:
  selector:
    app: api
  ports:
    - port: 80
      targetPort: 3000

自动回滚
自动回滚是部署安全的最后一道防线。基于健康检查和监控指标，在检测到异常时自动恢复到上一个稳定版本。


kubectl rollout undo deployment/api

kubectl rollout undo deployment/api --to-revision=3

kubectl rollout history deployment/api

小结
    

  • 滚动更新是 Kubernetes 默认策略，通过 maxSurge 和 maxUnavailable 控制更新节奏。
    • 

  • 蓝绿部署同时维护两个完整环境，通过切换 Service selector 实现瞬间流量切换和秒级回滚。
    • 

  • 金丝雀发布先将新版本暴露给小比例流量，验证通过后逐步扩大，是大规模服务最安全的策略。
    • 

  • progressDeadlineSeconds 配合健康检查实现部署超时自动检测，rollout undo 一键回滚。
    • 

  • 完善的部署策略应结合自动化监控和告警，实现从异常检测到自动回滚的闭环。
