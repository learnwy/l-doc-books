制品与镜像仓库

构建制品管理

构建制品（Artifact）是 CI/CD 流水线的核心产出物——编译后的二进制文件、打包的容器镜像、前端静态资源等。可靠的制品管理确保部署的可追溯性和回滚能力。

容器镜像仓库
容器镜像仓库是存储、管理和分发 OCI 镜像的核心基础设施。根据团队规模和安全需求选择合适的仓库服务。


GitHub Container Registry (GHCR)
jobs:
  publish:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v4

      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: ghcr.io/${{ github.repository }}:${{ github.sha }}
AWS ECR
aws ecr get-login-password --region us-east-1 | \

镜像标签策略
一致的标签策略是制品可追溯性的基础。推荐结合语义化版本、Git SHA 和构建元数据多维度标记。


- uses: docker/metadata-action@v5
  id: meta
  with:
    images: ghcr.io/${{ github.repository }}
    tags: |
      type=semver,pattern={{version}}
      type=semver,pattern={{major}}.{{minor}}
      type=semver,pattern={{major}}
      type=sha,prefix=
      type=ref,event=branch
      type=ref,event=pr

镜像安全扫描
每个发布到仓库的镜像都应经过安全漏洞扫描，将其集成到 CI 流水线中实现自动化。


jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: docker/build-push-action@v6
        with:
          context: .
          load: true
          tags: myapp:scan

      - uses: aquasecurity/trivy-action@master
        with:
          image-ref: myapp:scan
          format: sarif
          output: trivy-results.sarif
          severity: CRITICAL,HIGH

      - uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: trivy-results.sarif
trivy image --severity HIGH,CRITICAL ghcr.io/myorg/myapp:1.2.3

grype ghcr.io/myorg/myapp:1.2.3

提示： 将安全扫描设置为 CI 的阻断门禁——当发现 CRITICAL 或 HIGH 级别漏洞时，自动阻止镜像推送和部署。同时建立定期扫描机制，检测新披露的漏洞对已部署镜像的影响。






制品生命周期
制品的存储是有成本的，需要建立清晰的生命周期管理策略。


aws ecr put-lifecycle-policy --repository-name myapp --lifecycle-policy-text '{
  "rules": [
    {
      "rulePriority": 1,
      "description": "Keep last 10 tagged images",
      "selection": {
        "tagStatus": "tagged",
        "tagPrefixList": ["v"],
        "countType": "imageCountMoreThan",
        "countNumber": 10
      },
      "action": { "type": "expire" }
    },
    {
      "rulePriority": 2,
      "description": "Expire untagged after 7 days",
      "selection": {
        "tagStatus": "untagged",
        "countType": "sinceImagePushed",
        "countUnit": "days",
        "countNumber": 7
      },
      "action": { "type": "expire" }
    }
  ]
}'

小结
    

  • 构建制品包括容器镜像、npm 包、Helm Chart 和静态资源，需要统一的版本管理和存储策略。
    • 

  • GHCR 对开源项目免费且与 GitHub Actions 深度集成，企业内部推荐 Harbor 或云平台方案。
    • 

  • 标签策略应结合语义化版本和 Git SHA，生产环境使用精确版本号。
    • 

  • 安全扫描应集成到 CI 流水线中作为阻断门禁，同时建立定期扫描机制。
    • 

  • 制品生命周期管理通过自动清理策略控制存储成本，生产版本保留更久。
