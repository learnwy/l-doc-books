Part IV · 容器与编排DevOps 与容器化 简介Docker Compose 简介多服务编排

多服务编排

服务依赖管理

在多服务架构中，服务之间存在启动顺序依赖。Docker Compose 通过 depends_on 配置项管理服务的启动顺序和依赖条件。

services:
  api:
    build: ./api
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy
      migrations:
        condition: service_completed_successfully

  db:
    image: postgres:16-alpine
    healthcheck:
      test: ['CMD-SHELL', 'pg_isready -U postgres']
      interval: 5s
      timeout: 3s
      retries: 10

  redis:
    image: redis:7-alpine
    healthcheck:
      test: ['CMD', 'redis-cli', 'ping']
      interval: 5s
      timeout: 3s
      retries: 10

  migrations:
    build: ./api
    command: ['node', 'scripts/migrate.js']
    depends_on:
      db:
        condition: service_healthy




依赖条件
说明
适用场景





service_started
服务已启动（默认）
无强依赖




service_healthy
健康检查通过
数据库、缓存




service_completed_successfully
服务成功退出
迁移、初始化







提示： 仅使用 depends_on 不带条件只保证启动顺序，不保证服务就绪。数据库等需要初始化时间的服务必须配合 healthcheck 使用 condition: service_healthy。






健康检查
健康检查是可靠编排的基石。通过定义检查命令和频率，Compose 能够准确判断服务是否真正就绪。


services:
  web:
    image: nginx:alpine
    healthcheck:
      test: ['CMD', 'curl', '-f', 'http://localhost/health']
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
      start_interval: 5s

  api:
    build: ./api
    healthcheck:
      test: ['CMD-SHELL', 'wget --no-verbose --tries=1 --spider http://localhost:3000/health || exit 1']
      interval: 15s
      timeout: 5s
      retries: 5
      start_period: 30s
docker compose ps --format "table {{.Name}}\t{{.Status}}\t{{.Health}}"

docker inspect --format '{{json .State.Health}}' myproject-api-1 | jq .

服务扩缩容
Compose 支持通过 --scale 参数或 deploy.replicas 配置运行多个服务实例。


docker compose up -d --scale worker=5

docker compose ps
services:
  worker:
    build: ./worker
    deploy:
      replicas: 3
      resources:
        limits:
          cpus: '1.0'
          memory: 512M
    environment:
      QUEUE_URL: amqp://rabbitmq:5672

  nginx:
    image: nginx:alpine
    ports:
      - '80:80'
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    depends_on:
      - api

  api:
    build: ./api
    deploy:
      replicas: 2
    expose:
      - '3000'

提示： 使用 --scale 时，服务不能定义固定的宿主机端口映射（如 "8080:3000"），否则端口冲突。应使用 expose 暴露容器端口，通过负载均衡器统一对外服务。






服务配置继承
Compose 通过 extends、YAML 锚点和 profiles 实现配置复用与环境差异化。


YAML 锚点复用
x-common-env: &common-env
  LOG_LEVEL: info
  TZ: Asia/Shanghai

x-healthcheck: &default-healthcheck
  interval: 15s
  timeout: 5s
  retries: 3

services:
  api:
    build: ./api
    environment:
      <<: *common-env
      NODE_ENV: production
    healthcheck:
      <<: *default-healthcheck
      test: ['CMD-SHELL', 'curl -f http://localhost:3000/health']

  worker:
    build: ./worker
    environment:
      <<: *common-env
      NODE_ENV: production
    healthcheck:
      <<: *default-healthcheck
      test: ['CMD-SHELL', 'curl -f http://localhost:3001/health']
Profiles 环境隔离
services:
  api:
    build: ./api

  db:
    image: postgres:16-alpine

  debug-tools:
    image: nicolaka/netshoot
    profiles:
      - debug

  monitoring:
    image: grafana/grafana
    profiles:
      - monitoring
docker compose up -d

docker compose --profile debug up -d

docker compose --profile debug --profile monitoring up -d

小结
    

  • depends_on 配合 condition: service_healthy 确保依赖服务真正就绪后再启动下游服务。
    • 

  • 健康检查应覆盖所有关键服务，设置合理的 start_period 避免初始化阶段的误报。
    • 

  • 使用 deploy.replicas 或 --scale 实现水平扩缩容，需配合负载均衡器使用。
    • 

  • YAML 锚点和 profiles 机制实现配置复用，多文件组合管理环境差异。
    • 

  • 生产环境推荐使用 compose.yaml + compose.prod.yaml 的覆盖模式。
    •
