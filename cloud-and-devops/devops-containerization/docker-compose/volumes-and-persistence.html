数据卷与持久化

容器数据持久化问题

容器的文件系统是临时的——容器删除后，可写层中的所有数据随之消失。数据卷（Volume）是 Docker 提供的持久化存储机制，独立于容器生命周期，确保数据在容器重建后依然存在。

命名数据卷
命名数据卷（Named Volume）由 Docker 管理，存储在宿主机的 /var/lib/docker/volumes/ 目录下。它是生产环境推荐的持久化方案。


services:
  postgres:
    image: postgres:16-alpine
    volumes:
      - pgdata:/var/lib/postgresql/data
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: admin
      POSTGRES_PASSWORD_FILE: /run/secrets/db_password
    secrets:
      - db_password

  redis:
    image: redis:7-alpine
    volumes:
      - redis-data:/data
    command: redis-server --appendonly yes

volumes:
  pgdata:
    driver: local
  redis-data:
    driver: local
docker volume ls

docker volume inspect pgdata

docker volume create --driver local \
  --opt type=none \
  --opt o=bind \
  --opt device=/mnt/ssd/pgdata \
  fast-pgdata

提示： 使用 external: true 可以引用已存在的数据卷，避免 docker compose down -v 意外删除生产数据。对于关键数据（如数据库），强烈建议使用外部数据卷。






绑定挂载
绑定挂载（Bind Mount）将宿主机的目录或文件直接挂载到容器中。它是开发环境中实现源码同步的首选方案。


services:
  api:
    build: ./api
    volumes:
      - ./api/src:/app/src:cached
      - ./api/package.json:/app/package.json:ro
      - /app/node_modules
    command: ['npx', 'nodemon', 'src/index.js']

  frontend:
    build: ./web
    volumes:
      - ./web/src:/app/src:cached
      - /app/node_modules
    ports:
      - '5173:5173'

数据备份与恢复
数据卷的备份与恢复是运维的关键操作。Docker 提供多种备份策略。


docker run --rm \
  -v pgdata:/source:ro \
  -v $(pwd)/backups:/backup \
  alpine tar czf /backup/pgdata-$(date +%Y%m%d).tar.gz -C /source .

docker run --rm \
  -v pgdata:/target \
  -v $(pwd)/backups:/backup \
  alpine sh -c "cd /target && tar xzf /backup/pgdata-20260401.tar.gz"
services:
  db-backup:
    image: postgres:16-alpine
    volumes:
      - ./backups:/backups
    environment:
      PGHOST: postgres
      PGUSER: admin
      PGPASSWORD_FILE: /run/secrets/db_password
    command: >
      sh -c 'pg_dump -Fc myapp > /backups/myapp-$$(date +%Y%m%d_%H%M%S).dump'


    depends_on:
      postgres:
        condition: service_healthy
    profiles:
      - backup

提示： docker compose down -v 会删除所有命名数据卷。在生产环境中执行此命令前务必确认已完成数据备份。建议在脚本中添加确认提示或使用 external 数据卷防止误删。






tmpfs 与安全存储
tmpfs 挂载将数据存储在内存中，容器停止后数据自动消失。适用于存储敏感的临时数据。


services:
  api:
    image: myapi:latest
    tmpfs:
      - /tmp
      - /run:size=64M
    volumes:
      - type: tmpfs
        target: /app/sessions
        tmpfs:
          size: 128M
          mode: 1777

小结
    

  • 容器可写层是临时的，生产数据必须使用命名数据卷持久化。
    • 

  • 开发环境使用绑定挂载实现源码的实时同步，macOS 上推荐 :cached 模式提升性能。
    • 

  • 关键数据的数据卷应标记为 external: true，防止 docker compose down -v 误删。
    • 

  • 数据库备份应结合逻辑备份（pg_dump）和数据卷快照（tar），建立定期自动备份机制。
    • 

  • 敏感临时数据使用 tmpfs 存储在内存中，容器停止后自动清除。
    •
