基于 Compose 的本地开发环境

Docker Compose 将整个应用的基础设施打包为一个声明式配置文件，新成员只需 docker compose up 即可获得完整的开发环境，消除了"在我机器上能跑"的经典问题。

services:
  api:
    build:
      context: ./api
      target: dev
    volumes:
      - ./api/src:/app/src:cached
      - /app/node_modules
    ports:
      - '3000:3000'
      - '9229:9229'
    environment:
      NODE_ENV: development
      DATABASE_URL: postgres://dev:dev@db:5432/myapp_dev
      REDIS_URL: redis://redis:6379
    command: ['npx', 'nodemon', '--inspect=0.0.0.0:9229', 'src/index.js']
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy

  web:
    build:
      context: ./web
      target: dev
    volumes:
      - ./web/src:/app/src:cached
      - /app/node_modules
    ports:
      - '5173:5173'
    environment:
      VITE_API_URL: http://localhost:3000

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: myapp_dev
      POSTGRES_USER: dev
      POSTGRES_PASSWORD: dev
    volumes:
      - pgdata:/var/lib/postgresql/data
      - ./scripts/init-db.sql:/docker-entrypoint-initdb.d/init.sql:ro
    ports:
      - '5432:5432'
    healthcheck:
      test: ['CMD-SHELL', 'pg_isready -U dev']
      interval: 5s
      timeout: 3s
      retries: 10

  redis:
    image: redis:7-alpine
    ports:
      - '6379:6379'
    healthcheck:
      test: ['CMD', 'redis-cli', 'ping']
      interval: 5s
      timeout: 3s
      retries: 10

多阶段 Dockerfile 的开发模式
通过 Dockerfile 的 target 参数，同一个 Dockerfile 可以服务于开发和生产两种构建模式。


FROM node:20-alpine AS base
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable

FROM base AS dev
RUN pnpm install
CMD ["npx", "nodemon", "src/index.js"]

FROM base AS build
RUN pnpm install --frozen-lockfile
COPY . .
RUN pnpm build

FROM node:20-alpine AS production
WORKDIR /app
COPY --from=build /app/dist ./dist
COPY --from=build /app/node_modules ./node_modules
USER 1000:1000
CMD ["node", "dist/index.js"]

提示： 开发阶段不需要 COPY . . 复制源码到镜像，因为源码通过绑定挂载实时同步。这样每次代码修改无需重新构建镜像，极大提升开发效率。






环境差异管理
使用多文件覆盖策略管理开发、测试和生产环境的配置差异。


services:
  api:
    build:
      context: ./api
      target: production
    deploy:
      replicas: 2
      resources:
        limits:
          cpus: '1.0'
          memory: 512M
    environment:
      NODE_ENV: production
      LOG_LEVEL: warn
    restart: unless-stopped
docker compose -f compose.yaml -f compose.dev.yaml up -d

docker compose -f compose.yaml -f compose.prod.yaml up -d

docker compose -f compose.yaml -f compose.test.yaml run --rm test

项目初始化脚本
为团队成员提供一键启动的开发环境初始化体验。


#!/usr/bin/env bash
set -euo pipefail

if [ ! -f .env ]; then
  cp .env.example .env
  echo "Created .env from .env.example"
fi

docker compose pull
docker compose build
docker compose up -d
docker compose exec api npx prisma migrate dev
echo "Development environment is ready!"
echo "API:      http://localhost:3000"
echo "Frontend: http://localhost:5173"
echo "DB:       localhost:5432"

小结
    

  • Docker Compose 让团队成员通过 docker compose up 一键获得完整的本地开发环境。
    • 

  • 多阶段 Dockerfile 通过 target 参数在开发和生产模式间切换，开发阶段通过绑定挂载同步源码。
    • 

  • 使用多文件覆盖策略（compose.yaml + compose.dev.yaml）管理不同环境的配置差异。
    • 

  • 掌握 logs、exec、top、stats 等调试命令是容器化环境故障排查的基础。
    • 

  • 为团队提供初始化脚本和 .env.example 模板，降低环境搭建门槛。
