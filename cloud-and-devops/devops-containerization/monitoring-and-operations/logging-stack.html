日志体系

日志的价值与挑战

在容器化环境中，日志是排查问题的第一手线索。但容器的临时性和大规模部署给日志管理带来了独特挑战——容器销毁后日志消失、数百个容器的日志分散在不同节点、日志格式不统一导致难以检索。

结构化日志
结构化日志（Structured Logging）使用 JSON 等机器可解析的格式输出日志，取代传统的纯文本日志。这是可观测性的基础。


echo '{"timestamp":"2026-04-01T10:30:00Z","level":"info","service":"api","trace_id":"abc123","message":"Request processed","method":"GET","path":"/api/users","status":200,"duration_ms":45}'
对比传统日志：


echo '[2026-04-01 10:30:00] INFO: Request processed GET /api/users 200 45ms'

提示： 结构化日志的关键字段包括 timestamp、level、service、trace_id 和 message。其中 trace_id 尤为重要——它是在分布式系统中关联同一请求跨服务日志的唯一标识。






EFK 日志栈
EFK（Elasticsearch + Fluentd/Fluent Bit + Kibana）是 Kubernetes 环境中最流行的日志解决方案。


Fluent Bit 配置
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: fluent-bit
  namespace: logging
spec:
  selector:
    matchLabels:
      app: fluent-bit
  template:
    metadata:
      labels:
        app: fluent-bit
    spec:
      containers:
        - name: fluent-bit
          image: fluent/fluent-bit:3.0
          volumeMounts:
            - name: varlog
              mountPath: /var/log
            - name: config
              mountPath: /fluent-bit/etc/
      volumes:
        - name: varlog
          hostPath:
            path: /var/log
        - name: config
          configMap:
            name: fluent-bit-config
kubectl logs -n logging fluent-bit-xxxxx --tail 50

kubectl get pods -n logging

日志查询与分析
有效的日志查询能力是快速定位问题的关键。掌握日志平台的查询语法可以将排障时间从小时缩短到分钟。


kubectl logs deployment/api --tail 100 -f

kubectl logs deployment/api --since=1h | grep ERROR

kubectl logs -l app=api --all-containers --prefix
Elasticsearch 查询示例：


curl -X GET "localhost:9200/logs-*/_search" -H 'Content-Type: application/json' -d '{
  "query": {
    "bool": {
      "must": [
        {"match": {"level": "error"}},
        {"match": {"service": "api"}},
        {"range": {"@timestamp": {"gte": "now-1h"}}}
      ]
    }
  },
  "sort": [{"@timestamp": "desc"}],
  "size": 50
}'

小结
    

  • 容器化环境的日志管理面临临时性、分散性和异构性三大挑战。
    • 

  • 结构化 JSON 日志是可观测性的基础，trace_id 字段实现跨服务日志关联。
    • 

  • EFK 栈（Fluent Bit + Elasticsearch + Kibana）是 Kubernetes 日志的主流方案。
    • 

  • 掌握 kubectl logs、Kibana 查询和 stern 工具，可显著加速问题排查。
    • 

  • 通过热/温/冷/归档分层存储策略平衡查询性能和存储成本。
