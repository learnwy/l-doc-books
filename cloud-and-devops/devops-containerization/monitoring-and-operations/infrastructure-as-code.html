基础设施即代码

IaC 核心理念

基础设施即代码（Infrastructure as Code, IaC）是将基础设施的创建、配置和管理过程编写为可版本化、可审计、可重复执行的代码。它消除了手动操作的不确定性，使基础设施变更像应用代码一样经过代码审查和自动化测试。





IaC 原则
说明





声明式配置
描述期望状态而非操作步骤




版本控制
所有配置纳入 Git 管理




幂等性
多次执行结果一致




可重复性
同一代码在任何环境产生相同结果




不可变基础设施
变更通过替换而非修改实现







提示： IaC 的最大价值不在于自动化本身，而在于可审计性和可重复性。当生产环境出现问题时，你可以通过 Git 历史精确追溯到每一次基础设施变更，快速定位根因。






Terraform 基础
Terraform 是 HashiCorp 出品的多云基础设施编排工具，使用 HCL（HashiCorp Configuration Language）声明式定义云资源。


terraform init

terraform plan

terraform apply

terraform destroy
基础示例
cat > main.tf << 'EOF'
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
  backend "s3" {
    bucket = "my-terraform-state"
    key    = "prod/terraform.tfstate"
    region = "us-east-1"
  }
}

provider "aws" {
  region = var.region
}

resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
  tags = {
    Name        = "${var.project}-vpc"
    Environment = var.environment
  }
}

resource "aws_subnet" "public" {
  count             = 2
  vpc_id            = aws_vpc.main.id
  cidr_block        = cidrsubnet(aws_vpc.main.cidr_block, 8, count.index)
  availability_zone = data.aws_availability_zones.available.names[count.index]
}
EOF

Terraform 模块化
模块（Module）是 Terraform 配置的复用单元，将常用的资源组合封装为可参数化的模块。


cat > modules/eks-cluster/main.tf << 'EOF'
variable "cluster_name" {
  type = string
}

variable "node_count" {
  type    = number
  default = 3
}

resource "aws_eks_cluster" "main" {
  name     = var.cluster_name
  role_arn = aws_iam_role.cluster.arn
  vpc_config {
    subnet_ids = var.subnet_ids
  }
}

resource "aws_eks_node_group" "workers" {
  cluster_name    = aws_eks_cluster.main.name
  node_group_name = "${var.cluster_name}-workers"
  scaling_config {
    desired_size = var.node_count
    max_size     = var.node_count * 2
    min_size     = 1
  }
}

output "cluster_endpoint" {
  value = aws_eks_cluster.main.endpoint
}
EOF
cat > environments/production/main.tf << 'EOF'
module "eks" {
  source       = "../../modules/eks-cluster"
  cluster_name = "prod-cluster"
  node_count   = 5
  subnet_ids   = module.vpc.private_subnet_ids
}
EOF

Ansible 配置管理
Ansible 是无代理的配置管理工具，通过 SSH 远程执行任务。适合服务器配置、应用部署和运维自动化。


---
- name: 配置 Kubernetes Worker 节点
  hosts: workers
  become: true
  tasks:
    - name: 安装容器运行时
      apt:
        name:
          - containerd
          - apt-transport-https
        state: present
        update_cache: true

    - name: 配置 containerd
      copy:
        src: files/containerd-config.toml
        dest: /etc/containerd/config.toml
      notify: restart containerd

    - name: 加入 Kubernetes 集群
      command: '{{ kubeadm_join_command }}'
      when: not kubelet_configured

  handlers:
    - name: restart containerd
      service:
        name: containerd
        state: restarted

提示： Terraform 和 Ansible 各有侧重且互补：Terraform 擅长云资源的创建和管理（VPC、EC2、RDS），Ansible 擅长服务器内部的配置和软件安装。典型的工作流是 Terraform 创建基础设施，Ansible 配置服务器。






GitOps 工作流
GitOps 是 IaC 的进阶实践——以 Git 仓库作为基础设施和应用配置的唯一真实来源（Single Source of Truth），通过 Git 操作驱动部署。

小结
    

  • IaC 将基础设施定义为版本化代码，实现可审计、可重复的基础设施管理。
    • 

  • Terraform 使用 HCL 声明式定义云资源，模块化设计实现配置复用。
    • 

  • Ansible 通过 SSH 无代理执行服务器配置，与 Terraform 互补。
    • 

  • Terraform 负责基础设施创建，Ansible 负责服务器配置，是最佳组合。
    • 

  • GitOps 以 Git 为唯一真实来源，通过 ArgoCD/Flux 自动同步集群状态。
