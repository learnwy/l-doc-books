边缘与 Serverless

SQLite 在边缘的崛起

传统的 Serverless 架构中，数据库通常是中心化的，函数执行节点需要跨区域访问远程数据库，产生显著的网络延迟。边缘数据库（Edge Database）将数据推向靠近用户的边缘节点，从根本上解决延迟问题。SQLite 的轻量级和零配置特性使其成为边缘数据库的理想选择。

Cloudflare D1
D1 是 Cloudflare 基于 SQLite 构建的 Serverless 数据库，运行在 Cloudflare 的边缘网络上，与 Workers 深度集成。


export interface Env {
  DB: D1Database;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const { results } = await env.DB.prepare('SELECT * FROM users WHERE city = ?').bind('北京').all();

    return Response.json(results);
  },
};
D1 的核心操作：


export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const stmt = env.DB.prepare('INSERT INTO users (name, email) VALUES (?, ?)');
    await stmt.bind('Alice', 'alice@example.com').run();

    const user = await env.DB.prepare('SELECT * FROM users WHERE id = ?').bind(1).first();

    const batch = await env.DB.batch([
      env.DB.prepare('INSERT INTO logs (msg) VALUES (?)').bind('操作1'),
      env.DB.prepare('INSERT INTO logs (msg) VALUES (?)').bind('操作2'),
    ]);

    return Response.json({ user, batch });
  },
};

CREATE TABLE products (
    id   INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,

);

-- JSON 函数
SELECT json_extract(meta, '$.brand') FROM products;

-- 窗口函数
SELECT name, ROW_NUMBER() OVER (ORDER BY id) FROM products;


提示： D1 的读操作在全球边缘执行，延迟极低。写操作路由到主数据库所在区域，延迟取决于用户到主区域的距离。对于读多写少的应用，D1 的性能表现极为出色。






Turso 边缘部署
Turso 基于 libsql 提供全球分布式 SQLite，支持在多个边缘区域部署只读副本：


import { createClient } from '@libsql/client';

const db = createClient({
  url: process.env.TURSO_DATABASE_URL!,
  authToken: process.env.TURSO_AUTH_TOKEN!,
});

const result = await db.execute({
  sql: 'SELECT * FROM articles WHERE published = ? ORDER BY created_at DESC LIMIT ?',
  args: [1, 20],
});

const tx = await db.transaction('write');
await tx.execute({
  sql: 'INSERT INTO articles (title, body) VALUES (?, ?)',
  args: ['新文章', '文章内容...'],
});
await tx.execute({
  sql: 'UPDATE stats SET article_count = article_count + 1 WHERE id = 1',
  args: [],
});
await tx.commit();

边缘 Worker 模式
在 Serverless 函数中使用 SQLite 的通用模式：


interface EdgeDbConfig {
  primaryUrl: string;
  replicaUrl?: string;
  authToken: string;
}

function createEdgeDb(config: EdgeDbConfig) {
  const readClient = createClient({
    url: config.replicaUrl ?? config.primaryUrl,
    authToken: config.authToken,
  });

  const writeClient = createClient({
    url: config.primaryUrl,
    authToken: config.authToken,
  });

  return {
    read: readClient,
    write: writeClient,
  };
}

-- 边缘 SQLite 最佳实践

-- 1. 读写分离：读操作在边缘，写操作路由到主库
-- 2. 幂等写入：边缘环境可能重试请求
CREATE TABLE IF NOT EXISTS idempotency_keys (
    key       TEXT PRIMARY KEY,
    result    TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))
) STRICT, WITHOUT ROWID;

-- 3. 合理利用缓存
-- 边缘节点的 SQLite 副本本身就是一层缓存


提示： 边缘 SQLite 最大的优势是将读操作的延迟降到最低。设计应用时应尽量将读密集型逻辑放在边缘执行，写操作通过异步队列或直接路由到主数据库。






小结
    

  • 边缘 SQLite 将数据推向靠近用户的节点，读取延迟从 50-200ms 降至 1-5ms。
    • 

  • Cloudflare D1 与 Workers 深度集成，适合 Cloudflare 生态内的应用。
    • 

  • Turso 基于 libsql，支持嵌入式副本和向量搜索，部署更灵活。
    • 

  • 边缘架构的核心模式是读写分离：边缘节点处理读请求，主数据库处理写请求。
    • 

  • 边缘 SQLite 适合读多写少的场景，不适合高频写入或需要强一致性的应用。
    •
