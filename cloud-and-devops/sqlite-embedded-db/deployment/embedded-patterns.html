嵌入模式

桌面应用中的 SQLite

SQLite 在 Electron 和 Tauri 等桌面应用框架中是最常见的本地数据存储方案。嵌入式部署需要处理数据库文件位置、进程模型和原生模块打包等特有问题。

数据库文件位置
选择正确的数据库文件存储位置至关重要：


import { app } from 'electron';
import { join } from 'node:path';
import Database from 'better-sqlite3';

const userDataPath = app.getPath('userData');
const dbPath = join(userDataPath, 'data.db');

const db = new Database(dbPath);
db.pragma('journal_mode = WAL');
db.pragma('synchronous = NORMAL');
db.pragma('foreign_keys = ON');

推荐路径

提示： 永远不要将数据库文件放在应用安装目录中。安装目录可能是只读的（macOS App Sandbox），且更新应用时可能被覆盖。使用操作系统指定的用户数据目录。






多进程访问
桌面应用中可能出现多个进程同时访问同一个数据库文件的情况：


import Database from 'better-sqlite3';

function createSafeConnection(dbPath: string): Database.Database {
  const db = new Database(dbPath);

  db.pragma('journal_mode = WAL');
  db.pragma('busy_timeout = 10000');
  db.pragma('synchronous = NORMAL');
  db.pragma('foreign_keys = ON');

  return db;
}

function withRetry<T>(fn: () => T, maxRetries: number = 3, delayMs: number = 100): T {
  for (let i = 0; i < maxRetries; i++) {
    try {
      return fn();
    } catch (err: unknown) {
      const error = err as Error;
      if (error.message.includes('SQLITE_BUSY') && i < maxRetries - 1) {
        const jitter = Math.random() * delayMs;
        Atomics.wait(new Int32Array(new SharedArrayBuffer(4)), 0, 0, delayMs + jitter);
        continue;
      }
      throw err;
    }
  }
  throw new Error('重试次数已用尽');
}


提示： 在多进程场景中，建议将所有写操作集中在一个进程中（如 Electron 主进程），其他进程通过 IPC 提交写请求。这样避免了跨进程的锁竞争。

小结
    

  • 桌面应用中 SQLite 应在主进程中运行，渲染进程通过 IPC 访问。
    • 

  • 数据库文件应存放在用户数据目录，不要放在应用安装目录。
    • 

  • WAL 模式 + busy_timeout 是多进程访问的标准配置。
    • 

  • 建议将写操作集中在单个进程，避免跨进程锁竞争。
    • 

  • 移动端应根据平台和框架选择对应的 SQLite 绑定库。
