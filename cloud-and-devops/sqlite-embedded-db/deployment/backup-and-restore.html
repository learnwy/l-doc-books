备份与恢复

备份策略概述

SQLite 数据库备份不同于传统数据库——没有 pg_dump 这样的专用工具，也没有内置的 binlog 归档机制。但 SQLite 的单文件架构提供了独特的备份优势：数据库就是一个文件，理论上直接复制即可。然而实际操作中需要注意事务一致性和辅助文件的处理。

文件复制备份
最直接的备份方式是复制数据库文件。但必须确保复制时没有活跃的写事务。


-- 在 WAL 模式下，需要同时复制三个文件：
-- myapp.db
-- myapp.db-wal
-- myapp.db-shm

-- 或者先执行 checkpoint 将 WAL 合并
PRAGMA wal_checkpoint(TRUNCATE);
-- 此时只需复制 myapp.db
import Database from 'better-sqlite3';
import { copyFileSync } from 'node:fs';

function fileBackup(dbPath: string, backupPath: string) {
  const db = new Database(dbPath, { readonly: true });

  db.pragma('wal_checkpoint(TRUNCATE)');

  db.close();

  copyFileSync(dbPath, backupPath);
}


提示： 在 WAL 模式下，如果只复制主数据库文件而不复制 -wal 文件，备份可能缺少最近提交但尚未 checkpoint 的数据。始终先执行 wal_checkpoint(TRUNCATE) 或同时复制所有辅助文件。






.backup API
SQLite 的 Online Backup API 允许在数据库运行中进行热备份，不会阻塞读写操作。


import Database from 'better-sqlite3';

async function onlineBackup(dbPath: string, backupPath: string) {
  const db = new Database(dbPath);

  await db.backup(backupPath, {
    progress({ totalPages, remainingPages }) {
      const pct = Math.round(((totalPages - remainingPages) / totalPages) * 100);
      console.log(`备份进度: ${pct}%`);
    },
  });

  db.close();
}

VACUUM INTO
VACUUM INTO 将整个数据库重建并写入新文件，同时压缩碎片。


-- 将数据库重建到新文件
VACUUM INTO '/backups/myapp-20260401.db';
import Database from 'better-sqlite3';

function vacuumBackup(dbPath: string, backupPath: string) {
  const db = new Database(dbPath, { readonly: true });
  db.exec(`VACUUM INTO '${backupPath}'`);
  db.close();
}

提示： VACUUM INTO 产生的备份文件通常比 .backup 更小，因为它会消除碎片和空闲页面。但对于大型数据库，执行时间明显更长。






自动备份方案
import Database from 'better-sqlite3';
import { mkdirSync, readdirSync, unlinkSync, statSync } from 'node:fs';
import { join } from 'node:path';

interface BackupConfig {
  dbPath: string;
  backupDir: string;
  maxBackups: number;
  intervalMs: number;
}

function setupAutoBackup(config: BackupConfig) {
  mkdirSync(config.backupDir, { recursive: true });

  const backup = async () => {
    const timestamp = new Date().toISOString().replace(/[:.]/g, '-');
    const backupPath = join(config.backupDir, `backup-${timestamp}.db`);

    const db = new Database(config.dbPath);
    await db.backup(backupPath);
    db.close();

    rotateBackups(config.backupDir, config.maxBackups);
  };

  setInterval(backup, config.intervalMs);

  return backup;
}

function rotateBackups(dir: string, maxCount: number) {
  const files = readdirSync(dir)
    .filter((f) => f.startsWith('backup-') && f.endsWith('.db'))
    .map((f) => ({ name: f, path: join(dir, f), mtime: statSync(join(dir, f)).mtime }))
    .sort((a, b) => b.mtime.getTime() - a.mtime.getTime());

  for (const file of files.slice(maxCount)) {
    unlinkSync(file.path);
  }
}


恢复操作
import Database from 'better-sqlite3';
import { copyFileSync, existsSync } from 'node:fs';

function restore(backupPath: string, targetPath: string) {
  if (!existsSync(backupPath)) {
    throw new Error(`备份文件不存在: ${backupPath}`);
  }

  const backup = new Database(backupPath, { readonly: true });
  const integrity = backup.pragma('integrity_check', { simple: true });
  backup.close();

  if (integrity !== 'ok') {
    throw new Error(`备份文件损坏: ${integrity}`);
  }

  copyFileSync(backupPath, targetPath);

  const db = new Database(targetPath);
  db.pragma('journal_mode = WAL');
  db.pragma('wal_checkpoint(TRUNCATE)');
  db.close();
}
-- 验证备份完整性
PRAGMA integrity_check;

-- 快速完整性检查
PRAGMA quick_check;


小结
    

  • 文件复制是最简单的备份方式，但必须确保 WAL 已 checkpoint 或同时复制辅助文件。
    • 

  • .backup API 支持在线热备份，渐进式复制不阻塞数据库读写。
    • 

  • VACUUM INTO 在备份的同时消除碎片和空闲页面，生成更小的备份文件。
    • 

  • 生产环境应设置自动备份策略，包括定时备份、轮转清理和完整性验证。
    • 

  • 恢复前务必使用 integrity_check 验证备份文件的完整性。
