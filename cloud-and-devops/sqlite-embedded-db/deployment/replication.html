突破单文件限制

SQLite 的单文件架构意味着原生不支持数据库复制。但随着 SQLite 在生产环境中的使用日益增多，社区和商业项目发展出了多种复制方案，让 SQLite 数据库可以在多个节点间同步。

Litestream
Litestream 是一个独立运行的守护进程，持续监控 SQLite 的 WAL 文件变化，并将增量数据流式复制到远程存储（S3、GCS、Azure Blob 等）。


-- Litestream 要求 WAL 模式
PRAGMA journal_mode = WAL;

-- Litestream 会管理 checkpoint，应禁用自动 checkpoint
PRAGMA wal_autocheckpoint = 0;

import { execSync } from 'node:child_process';

function restoreFromLitestream(bucket: string, dbPath: string) {
  execSync(`litestream restore -o ${dbPath} s3://${bucket}/myapp.db`, { stdio: 'inherit' });
}


提示： Litestream 通过接管 WAL checkpoint 来确保所有变更都被捕获。在使用 Litestream 时，应将 wal_autocheckpoint 设为 0，让 Litestream 全权管理 checkpoint 时机。






LiteFS
LiteFS 是 Fly.io 开发的基于 FUSE（Filesystem in Userspace）的分布式文件系统。它在文件系统层面拦截 SQLite 的读写操作，实现透明的主从复制。

LiteFS 的工作原理：


-- LiteFS 挂载点下的 SQLite 文件
-- 应用像访问本地文件一样操作

-- 主节点：读写正常
INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com');

-- 从节点：只读（写操作会被转发到主节点或返回错误）
SELECT * FROM users;


Turso 与 libsql
Turso 是基于 libsql（SQLite 的开源分支）构建的分布式数据库平台。它将 SQLite 的简洁性与全球分布式架构结合，支持边缘部署和多区域复制。


import { createClient } from '@libsql/client';

const client = createClient({
  url: 'libsql://my-database-org.turso.io',
  authToken: process.env.TURSO_AUTH_TOKEN,
});

const result = await client.execute('SELECT * FROM users WHERE city = ?', ['北京']);

await client.execute({
  sql: 'INSERT INTO users (name, email) VALUES (?, ?)',
  args: ['Alice', 'alice@example.com'],
});

const batch = await client.batch(
  [
    { sql: 'INSERT INTO users (name, email) VALUES (?, ?)', args: ['Bob', 'bob@example.com'] },
    { sql: 'INSERT INTO users (name, email) VALUES (?, ?)', args: ['Carol', 'carol@example.com'] },
  ],
  'write',
);

提示： Turso 的嵌入式副本（Embedded Replica）模式将远程数据库同步到本地 SQLite 文件，读操作完全本地化（零延迟），写操作透明地提交到主数据库并同步回来。

小结
    

  • Litestream 通过 WAL 流式复制到对象存储，适合备份和灾难恢复。
    • 

  • LiteFS 在文件系统层面实现透明复制，适合多节点读扩展。
    • 

  • Turso/libsql 提供全球分布式 SQLite，支持边缘部署和嵌入式副本。
    • 

  • 所有方案都遵循单主写入模型，写入始终发生在一个节点。
    • 

  • 根据需求选择：备份用 Litestream，读扩展用 LiteFS，全球分发用 Turso。
