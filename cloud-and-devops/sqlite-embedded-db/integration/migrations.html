数据库迁移

为什么需要迁移

数据库迁移（Database Migration）是管理数据库 Schema 演进的系统化方法。随着应用功能的迭代，数据库结构需要随之变化——新增表、修改列、添加索引。迁移机制确保这些变更可追踪、可重复、可回滚。

版本管理
SQLite 提供了内置的版本存储机制——user_version pragma：


-- 查看当前版本
PRAGMA user_version;

-- 设置版本
PRAGMA user_version = 3;
import Database from 'better-sqlite3';

interface Migration {
  version: number;
  up: (db: Database.Database) => void;
  down: (db: Database.Database) => void;
}

const migrations: Migration[] = [
  {
    version: 1,
    up: (db) => {
      db.exec(`
        CREATE TABLE users (
          id    INTEGER PRIMARY KEY AUTOINCREMENT,
          name  TEXT NOT NULL,
          email TEXT NOT NULL UNIQUE
        ) STRICT
      `);
    },
    down: (db) => {
      db.exec('DROP TABLE IF EXISTS users');
    },
  },
  {
    version: 2,
    up: (db) => {
      db.exec('ALTER TABLE users ADD COLUMN age INTEGER');
    },
    down: (db) => {
      db.exec(`
        CREATE TABLE users_backup AS SELECT id, name, email FROM users;
        DROP TABLE users;
        ALTER TABLE users_backup RENAME TO users;
      `);
    },
  },
  {
    version: 3,
    up: (db) => {
      db.exec('CREATE INDEX idx_users_email ON users(email)');
    },
    down: (db) => {
      db.exec('DROP INDEX IF EXISTS idx_users_email');
    },
  },
];


迁移执行器
function migrate(db: Database.Database, targetVersion?: number) {
  const currentVersion = db.pragma('user_version', { simple: true }) as number;
  const target = targetVersion ?? Math.max(...migrations.map((m) => m.version));

  if (currentVersion === target) return;

  const runMigration = db.transaction(() => {
    if (currentVersion < target) {
      const pending = migrations
        .filter((m) => m.version > currentVersion && m.version <= target)
        .sort((a, b) => a.version - b.version);

      for (const m of pending) {
        m.up(db);
      }
    } else {
      const pending = migrations
        .filter((m) => m.version <= currentVersion && m.version > target)
        .sort((a, b) => b.version - a.version);

      for (const m of pending) {
        m.down(db);
      }
    }

    db.pragma(`user_version = ${target}`);
  });

  runMigration();
}

const db = new Database('myapp.db');
db.pragma('journal_mode = WAL');
migrate(db);


提示： 将所有迁移放在单个事务中执行。如果任何一步失败，整个迁移回滚，数据库保持在一致状态。

Schema 差异检测
function getSchema(db: Database.Database): Map<string, string> {
  const tables = db
    .prepare("SELECT name, sql FROM sqlite_master WHERE type = 'table' AND name NOT LIKE 'sqlite_%'")
    .all() as Array<{ name: string; sql: string }>;

  const schema = new Map<string, string>();
  for (const t of tables) {
    schema.set(t.name, t.sql);
  }
  return schema;
}

function diffSchemas(
  current: Map<string, string>,
  target: Map<string, string>,
): { added: string[]; removed: string[]; modified: string[] } {
  const added = [...target.keys()].filter((k) => !current.has(k));
  const removed = [...current.keys()].filter((k) => !target.has(k));
  const modified = [...current.keys()].filter((k) => target.has(k) && current.get(k) !== target.get(k));
  return { added, removed, modified };
}


零停机迁移
对于需要在运行中执行迁移的应用（如 Electron 应用），需要考虑零停机迁移（Zero-Downtime Migration）策略：


function safeMigrate(dbPath: string) {
  const backupPath = `${dbPath}.backup-${Date.now()}`;

  const src = new Database(dbPath, { readonly: true });
  src.backup(backupPath).then(() => {
    src.close();

    const db = new Database(dbPath);
    db.pragma('journal_mode = WAL');

    try {
      migrate(db);
    } catch (err) {
      db.close();
      throw err;
    }

    db.close();
  });
}

小结
    

  • 数据库迁移通过版本化脚本管理 Schema 演进，确保变更可追踪、可回滚。
    • 

  • 使用 user_version pragma 存储当前 Schema 版本号。
    • 

  • 所有迁移应在单个事务中执行，失败时自动回滚。
    • 

  • SQLite 的 ALTER TABLE 功能有限，复杂的列变更需要重建表。
    • 

  • 生产环境迁移应先备份数据库，并选择适合应用架构的零停机策略。
