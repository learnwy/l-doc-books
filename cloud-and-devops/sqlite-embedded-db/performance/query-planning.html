Part II · 命令行与本地工具SQLite 与嵌入式数据库 简介性能 简介查询计划

查询计划

EXPLAIN QUERY PLAN

EXPLAIN QUERY PLAN（简称 EQP）是分析 SQLite 查询执行策略的核心工具。它展示了 SQLite 优化器选择的访问路径、索引使用和连接策略。

-- 基本用法
EXPLAIN QUERY PLAN
SELECT * FROM users WHERE city = '北京';

-- 输出示例
-- QUERY PLAN
-- `--SEARCH users USING INDEX idx_users_city (city=?)

EQP 输出中的关键词：

关键词 含义
SCAN table 全表扫描（未使用索引）
SEARCH table USING INDEX 使用索引查找
COVERING INDEX 覆盖索引（无需回表）
USING ROWID 通过 rowid 直接查找
AUTOMATIC INDEX 优化器创建的临时自动索引
TEMP B-TREE FOR ORDER BY 使用临时 B-tree 排序
USE TEMP B-TREE FOR GROUP BY 使用临时 B-tree 分组
COMPOUND SUBQUERIES 复合子查询 
-- 全表扫描示例
EXPLAIN QUERY PLAN
SELECT * FROM users WHERE age > 25;
-- `--SCAN users

-- 索引查找示例
EXPLAIN QUERY PLAN
SELECT * FROM users WHERE email = 'alice@example.com';
-- `--SEARCH users USING INDEX sqlite_autoindex_users_1 (email=?)

-- 覆盖索引示例
EXPLAIN QUERY PLAN
SELECT name, email FROM users WHERE city = '北京';
-- `--SEARCH users USING COVERING INDEX idx_covering (city=?)

完整 EXPLAIN

EXPLAIN（不带 QUERY PLAN）展示 VDBE 字节码，提供更底层的执行细节：

EXPLAIN
SELECT name FROM users WHERE city = '北京' LIMIT 10;

-- 输出：操作码序列
-- addr  opcode          p1    p2    p3    p4             p5
-- ----  --------------  ----  ----  ----  -------------  --
-- 0     Init            0     12    0                    0
-- 1     OpenRead        0     2     0     5              0
-- 2     OpenRead        1     4     0     k(2,,)         0
-- ...


提示： 日常性能分析主要使用 EXPLAIN QUERY PLAN。完整的 EXPLAIN 字节码输出主要用于深度调试或理解 SQLite 内部工作机制。






索引选择策略
SQLite 优化器在选择索引时考虑多个因素：


CREATE TABLE orders (
    id          INTEGER PRIMARY KEY,
    customer_id INTEGER NOT NULL,
    total       REAL NOT NULL,
    status      TEXT NOT NULL,
    order_date  TEXT NOT NULL
);

CREATE INDEX idx_orders_customer ON orders(customer_id);
CREATE INDEX idx_orders_status ON orders(status);
CREATE INDEX idx_orders_date ON orders(order_date);

-- 单索引选择
EXPLAIN QUERY PLAN
SELECT * FROM orders WHERE customer_id = 100;
-- SEARCH orders USING INDEX idx_orders_customer (customer_id=?)

-- 多条件时的索引选择
EXPLAIN QUERY PLAN
SELECT * FROM orders WHERE customer_id = 100 AND status = 'completed';
-- SQLite 会选择选择性更高的索引




选择因素
描述





等值条件优先
= 比 > < BETWEEN 更适合索引查找




选择性
过滤掉更多行的索引优先




覆盖索引优先
避免回表的索引得到额外加分




索引列数
与查询条件匹配更多列的索引优先




排序避免
能同时满足排序需求的索引优先





-- 复合索引 vs 多个单列索引
CREATE INDEX idx_orders_composite ON orders(customer_id, status, order_date);

EXPLAIN QUERY PLAN
SELECT * FROM orders
WHERE customer_id = 100 AND status = 'completed'
ORDER BY order_date;
-- SEARCH orders USING INDEX idx_orders_composite (customer_id=? AND status=?)
-- 无需额外排序！


自动索引
当 SQLite 估计创建临时索引的成本低于全表扫描时，会自动创建自动索引（Automatic Index）：


EXPLAIN QUERY PLAN
SELECT o.id, c.name
FROM orders o
JOIN customers c ON o.customer_id = c.id
WHERE o.status = 'pending';
-- SCAN orders
-- SEARCH customers USING AUTOMATIC COVERING INDEX (id=?)
-- 禁用自动索引
PRAGMA automatic_index = OFF;

-- 查看当前设置
PRAGMA automatic_index;


提示： 如果 EQP 频繁显示 AUTOMATIC INDEX，说明缺少持久化索引。应该创建对应的永久索引来避免每次查询都重建临时索引的开销。

-- ❌ 函数包装索引列
SELECT * FROM users WHERE lower(name) = 'alice';

-- ✅ 创建表达式索引
CREATE INDEX idx_name_lower ON users(lower(name));
SELECT * FROM users WHERE lower(name) = 'alice';

-- ❌ OR 连接不同列
SELECT * FROM orders WHERE customer_id = 100 OR status = 'pending';

-- ✅ 改用 UNION
SELECT * FROM orders WHERE customer_id = 100
UNION
SELECT * FROM orders WHERE status = 'pending';


ANALYZE 与统计信息
-- 收集统计信息
ANALYZE;

-- 查看统计数据
SELECT * FROM sqlite_stat1;
-- tbl    idx                         stat
-- users  idx_users_city              1000 50
-- users  idx_users_email_lower       1000 1

-- stat 列的含义：
-- 第一个数字：表的总行数
-- 后续数字：每个索引列的平均重复行数（选择性的倒数）

-- 手动更新统计信息（谨慎使用）
DELETE FROM sqlite_stat1;
INSERT INTO sqlite_stat1 VALUES ('users', 'idx_users_city', '100000 200');
ANALYZE sqlite_schema;


小结
    

  • EXPLAIN QUERY PLAN 是分析查询性能的首要工具，关注 SCAN vs SEARCH 的区别。
    • 

  • SQLite 优化器根据等值条件、选择性、覆盖索引等因素选择最优索引。
    • 

  • 自动索引是 SQLite 的自适应优化，但频繁出现说明缺少永久索引。
    • 

  • 避免常见反模式：SELECT *、函数包装索引列、隐式类型转换。
    • 

  • 定期运行 ANALYZE 更新统计信息，帮助优化器做出更好的决策。
    •
