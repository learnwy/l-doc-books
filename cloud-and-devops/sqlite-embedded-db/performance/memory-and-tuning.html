内存与调优

页面缓存

SQLite 通过页面缓存（Page Cache）在内存中维护最近访问过的数据库页面，减少磁盘 I/O。缓存命中率直接影响查询性能。

-- 设置页面缓存大小
-- 正数：页面数；负数：以 KB 为单位
PRAGMA cache_size = -64000;

-- 查看当前缓存大小
PRAGMA cache_size;

-- 查看实际缓存使用情况
PRAGMA cache_spill;

页面大小（创建时设置）





-- 页面大小影响缓存效率
-- 创建数据库前设置（创建后不可更改，除非 VACUUM）
PRAGMA page_size = 8192;

-- 通过 VACUUM 更改已有数据库的页面大小
PRAGMA page_size = 8192;
VACUUM;


提示： 对于包含大量 BLOB 数据或大行的数据库，增大页面大小可以减少溢出页的使用，提升读取效率。对于以小型行为主的数据库，4096 字节是最佳选择。






内存映射 I/O
mmap（内存映射 I/O）允许 SQLite 将数据库文件的一部分或全部映射到进程地址空间，通过内存地址直接访问数据，减少系统调用开销。


-- 启用内存映射（256MB）
PRAGMA mmap_size = 268435456;

-- 禁用内存映射
PRAGMA mmap_size = 0;

-- 查看当前设置
PRAGMA mmap_size;

提示： SQLite 的 mmap 实现仅用于只读访问。写操作仍然通过传统 I/O 完成。因此 mmap 在读密集型工作负载中效果最佳。






临时存储
SQLite 在查询处理过程中可能需要创建临时表、临时索引和排序缓冲区。temp_store 控制这些临时数据的存储位置。


-- 临时数据存储在内存中（推荐）
PRAGMA temp_store = MEMORY;

-- 临时数据存储在磁盘上
PRAGMA temp_store = FILE;

-- 使用默认策略（编译时决定）
PRAGMA temp_store = DEFAULT;

VACUUM
VACUUM 重建整个数据库文件，消除碎片、回收删除数据留下的空闲页面、整理页面布局。


-- 完整 VACUUM：重建整个数据库
VACUUM;

-- VACUUM INTO：重建到新文件（不影响原数据库）
VACUUM INTO '/tmp/compacted.db';

-- 增量 VACUUM（需要先启用 auto_vacuum = INCREMENTAL）
PRAGMA auto_vacuum = INCREMENTAL;
PRAGMA incremental_vacuum(100);

-- auto_vacuum 模式对比
-- NONE：从不自动回收（需手动 VACUUM）
PRAGMA auto_vacuum = NONE;

-- FULL：每次事务后自动回收空闲页
PRAGMA auto_vacuum = FULL;

-- INCREMENTAL：在手动调用时回收
PRAGMA auto_vacuum = INCREMENTAL;


提示： VACUUM 需要约两倍数据库大小的临时磁盘空间，并持有排他锁。对于大型数据库，建议使用 VACUUM INTO 或 incremental_vacuum 来避免长时间锁定。






ANALYZE
ANALYZE 收集表和索引的统计信息，存储在 sqlite_stat1（和 sqlite_stat4）表中，帮助查询优化器做出更好的索引选择决策。


-- 分析所有表和索引
ANALYZE;

-- 只分析特定表
ANALYZE users;

-- 查看统计数据
SELECT * FROM sqlite_stat1;

-- sqlite_stat1 表结构：
-- tbl：表名
-- idx：索引名
-- stat：统计信息（总行数 + 每列平均重复数）
-- 理解 stat 列的含义
-- stat = "10000 200 5"
-- 10000：表中总行数
-- 200：索引第一列的平均重复行数
-- 5：索引前两列组合的平均重复行数

-- 选择性 = 1 / 平均重复数
-- 选择性越高（接近 1/总行数），索引越有效


综合调优清单
-- 生产环境综合调优模板
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA cache_size = -64000;
PRAGMA mmap_size = 268435456;
PRAGMA temp_store = MEMORY;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

PRAGMA auto_vacuum = INCREMENTAL;

ANALYZE;
PRAGMA optimize;
PRAGMA incremental_vacuum(500);

小结
    

  • 页面缓存是 SQLite 最直接的性能杠杆，合理设置 cache_size 可显著减少磁盘 I/O。
    • 

  • mmap 通过内存映射消除系统调用开销，适合读密集型场景。
    • 

  • VACUUM 消除碎片和回收空间，大型数据库推荐使用增量模式。
    • 

  • ANALYZE 更新统计信息，帮助优化器选择最优执行计划。
    • 

  • 综合调优应覆盖日志模式、缓存、mmap、临时存储和定期维护等多个维度。
    •
