WAL 与并发

WAL 模式原理

WAL（Write-Ahead Logging，预写日志）是 SQLite 3.7.0 引入的日志模式。在 WAL 模式下，修改不直接写入数据库文件，而是追加到独立的 WAL 文件中。这一设计使得读操作和写操作可以并发执行。





特性

WAL 模式





写入目标
数据库文件

支持

事务完成标志

崩溃恢复

-- 启用 WAL 模式
PRAGMA journal_mode = WAL;

-- 验证当前模式
PRAGMA journal_mode;
-- wal


读写并发机制
WAL 模式下的并发模型基于快照隔离（Snapshot Isolation）：


关键规则：






规则
描述





多读者并发
多个读事务可以同时进行




单写者
同一时刻只允许一个写事务




读不阻塞写
读事务不会阻塞写事务




写不阻塞读
写事务不会阻塞读事务




快照隔离
读事务看到开始时刻的数据快照





-- 写事务推荐使用 BEGIN IMMEDIATE
-- 避免在事务中途升级锁导致 SQLITE_BUSY
BEGIN IMMEDIATE;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;


提示： 即使在 WAL 模式下，SQLite 仍然只允许一个写者。如果多个连接同时尝试写入，后来的写者会等待（受 busy_timeout 限制），超时则返回 SQLITE_BUSY 错误。






WAL 检查点
检查点（Checkpoint）是将 WAL 文件中的修改合并回数据库文件的过程。


SQLite 支持四种检查点模式：






模式
行为





PASSIVE
尽可能多地合并，不等待读者/写者




FULL
等待写者完成，合并所有帧，但不截断 WAL




RESTART
FULL + 将 WAL 重置到开头




TRUNCATE
RESTART + 截断 WAL 文件为零字节





-- 自动检查点阈值（默认 1000 页）
PRAGMA wal_autocheckpoint = 1000;

-- 手动执行检查点
PRAGMA wal_checkpoint(PASSIVE);
PRAGMA wal_checkpoint(FULL);
PRAGMA wal_checkpoint(TRUNCATE);

-- 查看检查点结果
-- 返回三列：busy(是否受阻), log(WAL总页数), checkpointed(已合并页数)
PRAGMA wal_checkpoint(PASSIVE);
-- 0|150|150


WAL 文件增长管理
WAL 文件会持续增长，直到检查点将内容合并回数据库并截断。


-- 监控 WAL 文件大小
PRAGMA wal_checkpoint(PASSIVE);

-- 强制截断 WAL（需要独占访问）
PRAGMA wal_checkpoint(TRUNCATE);

-- 调整自动检查点频率
PRAGMA wal_autocheckpoint = 500;
WAL 文件无法缩小的常见原因：






原因
解决方案





长时间运行的读事务
缩短读事务持续时间




从未执行检查点
确保 autocheckpoint 已启用




PASSIVE 检查点受阻
使用 TRUNCATE 模式




写入速度远超检查点速度
增加检查点频率或批量写入







提示： 长时间运行的读事务会阻止 WAL 检查点前进，导致 WAL 文件持续增长。在生产环境中，确保读事务尽快完成。






WAL 模式的限制
-- WAL 模式不支持的场景

-- 1. 网络文件系统（NFS, SMB）
-- WAL 依赖共享内存（-shm文件），网络文件系统的锁机制不可靠

-- 2. 只读文件系统
-- WAL 需要创建 -wal 和 -shm 文件

-- 3. 数据库大小 > 可用虚拟地址空间
-- 32 位系统上限制约 2GB

-- 检查是否在正确的文件系统上
PRAGMA journal_mode = WAL;
-- 如果返回 "delete" 而非 "wal"，说明 WAL 不可用




限制
描述





网络文件系统
不支持 NFS/SMB 上的 WAL




只读介质
无法创建辅助文件




单写者
无法多线程/进程同时写入




初次读取开销
需要重放 WAL 帧到内存缓存







小结
    

  • WAL 模式将修改写入独立的 WAL 文件，实现了读写并发。
    • 

  • 读事务基于快照隔离，看到事务开始时刻的数据快照。
    • 

  • 检查点将 WAL 内容合并回数据库，四种模式适用于不同场景。
    • 

  • 长时间运行的读事务会阻塞 WAL 检查点前进，导致 WAL 文件持续增长。
    • 

  • WAL 模式不支持网络文件系统和只读介质。
