索引策略

B-tree 索引基础

SQLite 中的所有索引都基于 B-tree（B-树）数据结构实现。表数据本身存储在 B+tree 中（以 rowid 为键），而索引则存储在独立的 B-tree 中。理解 B-tree 的结构是优化索引策略的前提。

CREATE TABLE users (
    id    INTEGER PRIMARY KEY,
    name  TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE,
    age   INTEGER,
    city  TEXT
);

-- 创建单列索引
CREATE INDEX idx_users_city ON users(city);

-- 查看表的索引列表
PRAGMA index_list(users);

-- 查看索引的列信息
PRAGMA index_info(idx_users_city);


复合索引
复合索引（Composite Index）包含多个列，列的顺序至关重要。SQLite 使用最左前缀（Leftmost Prefix）规则匹配复合索引。


-- 创建复合索引
CREATE INDEX idx_users_city_age ON users(city, age);

-- 能使用索引的查询
SELECT * FROM users WHERE city = '北京';
SELECT * FROM users WHERE city = '北京' AND age > 25;
SELECT * FROM users WHERE city = '北京' AND age BETWEEN 20 AND 30;

-- 不能使用该索引的查询（跳过了首列）
SELECT * FROM users WHERE age > 25;
复合索引的列顺序选择原则：






优先级
原则
理由





1
等值条件的列放前面
等值过滤后范围更窄




2
选择性高的列放前面
更早缩小结果集




3
排序列紧跟等值列
避免额外排序





-- 最优顺序：等值列 → 范围列 → 排序列
CREATE INDEX idx_optimal ON users(city, age, name);

-- 查询：city 等值 + age 范围 + name 排序
SELECT name, age FROM users
WHERE city = '上海' AND age > 20
ORDER BY name;


覆盖索引
覆盖索引（Covering Index）包含查询所需的所有列，SQLite 可以仅从索引中获取数据而无需访问表数据（回表）。


-- 覆盖索引：包含查询所需的所有列
CREATE INDEX idx_covering ON users(city, name, email);

-- 此查询完全从索引中获取数据
SELECT name, email FROM users WHERE city = '北京';

-- EXPLAIN QUERY PLAN 会显示 "COVERING INDEX"
EXPLAIN QUERY PLAN
SELECT name, email FROM users WHERE city = '北京';


提示： 覆盖索引以额外的存储空间和写入开销换取查询性能。在读多写少的场景中，覆盖索引特别有效。






部分索引
部分索引（Partial Index）只对满足 WHERE 条件的行建立索引，减小索引大小和维护成本。


-- 仅为活跃用户建立索引
CREATE INDEX idx_active_users ON users(name)
WHERE active = 1;

-- 仅为高价值订单建立索引
CREATE INDEX idx_high_value_orders ON orders(customer_id, total)
WHERE total > 1000;

-- 仅为非空值建立索引
CREATE INDEX idx_users_email_nonnull ON users(email)
WHERE email IS NOT NULL;

-- 查询必须包含与部分索引匹配的条件
-- ✅ 会使用部分索引
SELECT name FROM users WHERE active = 1 AND name LIKE 'A%';

-- ❌ 不会使用部分索引（缺少 active = 1 条件）
SELECT name FROM users WHERE name LIKE 'A%';


表达式索引
表达式索引（Expression Index）对表达式的计算结果建立索引，SQLite 3.9.0+ 支持。


-- 对小写 email 建立索引（大小写不敏感查询）
CREATE INDEX idx_users_email_lower ON users(lower(email));

-- 查询时使用相同表达式
SELECT * FROM users WHERE lower(email) = 'alice@example.com';

-- 对 JSON 路径建立索引
CREATE INDEX idx_products_brand ON products(json_extract(meta, '$.brand'));

-- 对日期部分建立索引
CREATE INDEX idx_orders_month ON orders(strftime('%Y-%m', order_date));

SELECT * FROM orders WHERE strftime('%Y-%m', order_date) = '2026-03';


提示： 表达式索引的 WHERE 子句中的表达式必须与索引定义中的表达式完全一致（包括空格和函数名大小写），否则 SQLite 不会使用该索引。






索引维护
-- 查看索引使用情况（需要开启 stat 表）
ANALYZE;
SELECT * FROM sqlite_stat1;

-- 重建所有索引
REINDEX;

-- 重建特定索引
REINDEX idx_users_city;

-- 删除不再需要的索引
DROP INDEX IF EXISTS idx_old_unused;

-- 查看索引占用空间
SELECT
    name,
    SUM(pageno) AS pages
FROM dbstat
WHERE name LIKE 'idx_%'
GROUP BY name;

小结
    

  • SQLite 使用 B-tree 索引结构，等值查找和范围查找的时间复杂度为 O(log n)。
    • 

  • 复合索引遵循最左前缀规则，列顺序决定了哪些查询能使用索引。
    • 

  • 覆盖索引包含查询所需的所有列，避免回表读取，显著提升读取性能。
    • 

  • 部分索引仅对满足条件的行建立索引，减小索引体积和写入开销。
    • 

  • 表达式索引对函数计算结果建立索引，支持 JSON 路径查询和大小写不敏感搜索。
    •
