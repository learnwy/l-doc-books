SQLite 架构

设计哲学

SQLite（Structured Query Language + Lite）是一个自包含、无服务器、零配置的嵌入式关系数据库引擎。它以库（Library）的形式嵌入到宿主应用中，不需要独立的数据库服务器进程。整个数据库存储在单个跨平台的磁盘文件中，支持完整的 ACID（Atomicity, Consistency, Isolation, Durability）事务。

与传统的客户端/服务器架构相比，SQLite 的进程内嵌入模型消除了网络通信开销和进程间通信的复杂性。

内部组件架构
SQLite 的内部架构分为前端（Front-end）和后端（Back-end）两大部分，中间通过字节码虚拟机连接。


前端：SQL → 字节码
词法分析器（Tokenizer）将输入的 SQL 文本拆分为一系列标记（Token），识别关键字、标识符、运算符和字面量。


语法解析器（Parser）使用 Lemon 解析器生成器构建的 LALR(1) 解析器，将标记序列转换为抽象语法树（AST）。


代码生成器（Code Generator）遍历 AST，生成 VDBE（Virtual Database Engine）字节码指令序列。查询优化也在此阶段完成。


-- 查看 SQLite 生成的字节码
EXPLAIN SELECT name FROM users WHERE age > 25;
后端：字节码 → 磁盘 I/O
VDBE 虚拟机是 SQLite 的执行引擎，逐条执行字节码指令。每条指令由操作码（Opcode）和最多五个操作数组成。


B-tree 模块负责数据的逻辑组织。SQLite 使用两种 B-tree 结构：

页面管理器（Pager）是 B-tree 与磁盘之间的中间层，负责页面的读写、缓存和事务日志管理。SQLite 的默认页面大小为 4096 字节。


VFS（Virtual File System）是操作系统抽象层，将所有文件操作封装为统一接口，使 SQLite 能够在不同操作系统上运行。




数据库文件格式
SQLite 的数据库文件由固定大小的页面（Page）组成，第一个页面包含 100 字节的文件头。


-- 查看当前数据库页面大小
PRAGMA page_size;

-- 查看数据库总页面数
PRAGMA page_count;

-- 查看空闲页面数
PRAGMA freelist_count;

小结
    

  • SQLite 是一个嵌入式数据库引擎，以库的形式链接到应用中，无需独立服务器进程。
    • 

  • 内部架构分为前端（SQL 解析与代码生成）和后端（虚拟机执行与磁盘 I/O）。
    • 

  • VDBE 虚拟机是执行核心，将 SQL 编译为字节码后逐条执行。
    • 

  • 数据库文件由固定大小的页面组成，默认页面大小为 4096 字节。
    • 

  • SQLite 适用于嵌入式、移动、桌面、开发测试和边缘计算等场景。
