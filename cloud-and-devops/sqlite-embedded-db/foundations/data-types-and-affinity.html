Part II · 命令行与本地工具SQLite 与嵌入式数据库 简介基础 简介数据类型与亲和性

数据类型与亲和性

动态类型系统

SQLite 采用动态类型（Dynamic Typing）系统，这是它与其他关系数据库最显著的区别之一。在 PostgreSQL 或 MySQL 中，类型绑定在列上；而在 SQLite 中，类型绑定在值（Value）上。任何列可以存储任何类型的数据。

SQLite 定义了五种基本存储类（Storage Class）：

存储类 描述 占用空间
NULL 空值 0 字节
INTEGER 有符号整数，1/2/3/4/6/8 字节 可变（1-8 字节）
REAL 8 字节 IEEE 754 浮点数 8 字节
TEXT UTF-8/UTF-16 编码的文本字符串 可变
BLOB 二进制大对象，按输入原样存储 可变 
-- SQLite 允许任何列存储任何类型
CREATE TABLE demo (value);

INSERT INTO demo VALUES (42);
INSERT INTO demo VALUES (3.14);
INSERT INTO demo VALUES ('hello');
INSERT INTO demo VALUES (NULL);
INSERT INTO demo VALUES (X'DEADBEEF');

-- 查看每个值的实际类型
SELECT value, typeof(value) FROM demo;
-- 42       | integer
-- 3.14     | real
-- hello    | text
-- NULL     | null
-- DEADBEEF | blob

提示： typeof() 函数返回的是值的实际存储类，而不是列声明的类型。这是理解 SQLite 类型系统的关键。

类型亲和性

虽然 SQLite 是动态类型的，但它通过类型亲和性（Type Affinity）机制为列提供了"推荐类型"。当插入数据时，SQLite 会尝试将值转换为该列的亲和类型。

SQLite 定义了五种类型亲和性：





亲和性
规则
转换行为





TEXT
声明包含 "CHAR"、"CLOB"、"TEXT"
将数值转为文本




NUMERIC
不匹配其他规则的声明
尝试转为 INTEGER 或 REAL




INTEGER
声明包含 "INT"
尝试转为整数




REAL
声明包含 "REAL"、"FLOA"、"DOUB"
尝试转为浮点数




BLOB
声明包含 "BLOB" 或无声明
不做任何转换





亲和性的判定遵循优先级规则：


-- INTEGER 亲和性：声明中包含 "INT"
CREATE TABLE t1 (x INTEGER);
INSERT INTO t1 VALUES ('123');
SELECT x, typeof(x) FROM t1;
-- 123 | integer（文本 '123' 被转换为整数）

-- TEXT 亲和性：声明中包含 "TEXT"
CREATE TABLE t2 (x TEXT);
INSERT INTO t2 VALUES (456);
SELECT x, typeof(x) FROM t2;
-- 456 | text（整数 456 被转换为文本）

-- BLOB 亲和性：无类型声明
CREATE TABLE t3 (x);
INSERT INTO t3 VALUES (789);
SELECT x, typeof(x) FROM t3;
-- 789 | integer（无亲和性，保持原始类型）


类型比较规则
SQLite 在比较不同存储类的值时遵循固定的排序规则：


NULL < INTEGER/REAL < TEXT < BLOB
-- 混合类型比较示例
CREATE TABLE mixed (val);
INSERT INTO mixed VALUES (NULL);
INSERT INTO mixed VALUES (1);
INSERT INTO mixed VALUES (2.5);
INSERT INTO mixed VALUES ('abc');
INSERT INTO mixed VALUES (X'FF');

SELECT val, typeof(val) FROM mixed ORDER BY val;
-- NULL     | null
-- 1        | integer
-- 2.5      | real
-- abc      | text
-- FF       | blob


提示： 在 WHERE 条件中比较不同类型时，SQLite 可能不会使用索引。确保比较双方类型一致，是避免性能问题的关键。






STRICT Tables
SQLite 3.37.0（2021-11）引入了 STRICT 表，为需要强类型约束的场景提供支持。


-- 普通表：允许类型混搭
CREATE TABLE loose (id INTEGER, name TEXT);
INSERT INTO loose VALUES ('not_a_number', 42);  -- 不报错

-- STRICT 表：强制类型检查
CREATE TABLE strict_users (
    id   INTEGER PRIMARY KEY,
    name TEXT,
    age  INTEGER,
    data BLOB
) STRICT;

-- 类型不匹配时抛出错误
INSERT INTO strict_users VALUES (1, 'Alice', 'not_a_number', NULL);
-- Error: cannot store TEXT value in INTEGER column strict_users.age
STRICT 表支持的数据类型：






类型

-- 组合使用 STRICT 和 WITHOUT ROWID
CREATE TABLE config (
    key   TEXT PRIMARY KEY,
    value ANY
) STRICT, WITHOUT ROWID;

INSERT INTO config VALUES ('version', 1);
INSERT INTO config VALUES ('name', 'myapp');
INSERT INTO config VALUES ('debug', X'01');

SELECT key, value, typeof(value) FROM config;

    id        INTEGER PRIMARY KEY,

INSERT INTO events (name) VALUES ('部署上线');

小结
    

  • SQLite 采用动态类型系统，类型绑定在值上而非列上。
    • 

  • 五种存储类是 SQLite 类型系统的基础：NULL、INTEGER、REAL、TEXT、BLOB。
    • 

  • 类型亲和性为列提供"推荐类型"，插入时自动尝试类型转换。
    • 

  • 不同存储类之间有固定的排序规则，混合类型比较可能导致索引失效。
    • 

  • STRICT 表（3.37+）提供强制类型检查，适合对数据完整性要求高的场景。
    •
