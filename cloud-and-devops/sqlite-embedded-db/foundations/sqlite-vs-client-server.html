PRAGMA busy_timeout = 5000;

-- 当遇到锁冲突时，SQLite 会等待最多 5 秒
-- 如果超时仍未获得锁，返回 SQLITE_BUSY 错误
BEGIN IMMEDIATE;

COMMIT;


提示： SQLite 使用 BEGIN IMMEDIATE 可以在事务开始时就获取写锁，避免在事务中途遇到锁冲突导致的回滚和重试。

选型决策
选择 SQLite 的场景：


-- 嵌入式应用：配置存储
CREATE TABLE app_config (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
) STRICT, WITHOUT ROWID;

-- 本地缓存：API 响应缓存
CREATE TABLE http_cache (
    url       TEXT PRIMARY KEY,
    response  BLOB NOT NULL,
    etag      TEXT,
    cached_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now')),
    ttl       INTEGER NOT NULL DEFAULT 3600
) STRICT, WITHOUT ROWID;
选择客户端/服务器数据库的场景：


-- 多服务写入同一数据库
-- 需要行级锁和高并发写入
-- 需要角色和权限管理
-- 需要数据库内置复制和高可用
-- 数据量超过单机存储能力

小结
    

  • SQLite 是嵌入式数据库，以库的形式运行在应用进程内，无需独立服务器。
    • 

  • 并发是最关键的差异点：SQLite 不支持多写者并发，WAL 模式仅实现读写并发。
    • 

  • SQLite 在单连接、低并发场景下性能卓越，消除了网络通信和进程间通信开销。
    • 

  • 功能上 SQLite 已支持大部分现代 SQL 特性，但缺少存储过程、物化视图和内置复制。
    • 

  • 选型核心原则：嵌入式、单机、低并发写入选 SQLite；多机、高并发写入、复杂权限选客户端/服务器。
