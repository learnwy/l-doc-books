全栈性能优化体系

端到端性能视角

全栈性能优化的本质是缩短从用户操作到结果呈现的全链路时间。一个用户点击"下单"按钮后经历的完整路径：浏览器事件处理 → JavaScript 执行 → HTTP 请求发送 → 网络传输 → API Gateway → BFF 聚合 → 多个微服务调用 → 数据库查询 → 响应组装 → 网络传输 → 浏览器渲染。优化只关注其中一个环节而忽略其他，往往是在错误的地方投入精力。

全链路延迟瀑布：

总端到端延迟：~500ms。优化的第一步是建立这样的全链路基线，识别瓶颈环节。

渲染性能
// 避免主线程长任务 - 使用 Scheduler API 拆分工作
async function processLargeList(items: Item[]) {
  const CHUNK_SIZE = 50;
  for (let i = 0; i < items.length; i += CHUNK_SIZE) {
    const chunk = items.slice(i, i + CHUNK_SIZE);
    renderChunk(chunk);
    // 让出主线程，保持响应性
    await scheduler.yield();
  }
}
API 层性能优化
响应时间治理

缓存是性能优化最高杠杆的手段，但也是一致性问题的主要来源。全栈缓存分层：


缓存策略选择：

描述

应用先查缓存，未命中查 DB 并回填

写操作同时更新缓存和 DB

Read-Through
缓存层自动加载缺失数据
最终一致
简化应用代码





缓存失效的 Edge Case：


// 安全的缓存更新模式 - 避免缓存与 DB 不一致
async function updateOrder(id: string, data: UpdateOrderDto) {
  // 1. 更新数据库
  await db.orders.update(id, data);
  // 2. 删除缓存（而非更新缓存 - 避免并发写导致脏数据）
  await redis.del(`order:${id}`);
  // 3. 发布事件通知其他服务的缓存失效
  await eventBus.publish('order.updated', { id });
}
