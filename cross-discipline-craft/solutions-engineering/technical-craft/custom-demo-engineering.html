定制 demo 工程

核心概念

定制 demo 是 SE 最高杠杆的工具——把产品装在客户业务上下文中演示，转化率比通用 demo 高 3 至 5 倍。一个通用 demo 是"我们产品有 50 个功能、看 5 个"，一个定制 demo 是"看，我们用你们公司今天真实的订单数据，跑一遍全流程"。客户工程师立刻能想象"如果我把它接进我们系统，会是什么样"。但定制 demo 也是 SE 时间黑洞——一个 deal 准备 1 至 2 周、20 至 40 小时是常态。Demo 平台、沙箱、数据生成器、模板复用机制让 SE 把单次 demo 准备时间从 20 小时压到 2 至 4 小时。本节给出 demo 工程的策略——demo 类型、定制层次、demo 平台架构、数据生成、live demo 安全、复用机制。

Demo 类型 受众 时长 定制深度
通用 overview 所有受众 30 分钟 0%（标准）
行业定制 行业相关人 30-45 分钟 30%
客户定制 单个客户 45-60 分钟 60%-80%
工作坊 客户工程师 2-4 小时 80%-100%
现场动手 客户工程师 1 整天 100%

Demo 的三层定制

第 0 层：通用 demo：

  • 标准产品 tour。
  • 用产品自带样本数据。
  • 不针对特定客户。

第 1 层：行业定制：

  • 银行客户用合规相关样本。
  • 电商客户用 SKU 与订单样本。
  • 同行业可复用。

第 2 层：客户定制：

  • 用客户真实数据（脱敏后）。
  • 用客户自家的术语、流程、KPI。
  • 不可复用，但 ROI 最高。

取舍：

  • 早期 deal 用第 1 层节省时间。
  • 大 deal（100 万美元以上）值得做第 2 层。

一个好定制 demo 的四要素

1. 命中真实痛点：

  • 在 discovery 中识别的痛点。
  • Demo 第一段就要直击。

2. 用客户的语言：

  • 客户叫他们的工单系统"work order"，你别叫"ticket"。
  • 客户叫他们的商品"item"，你别叫"product"。

3. Live 操作而不是 slide：

  • 真实点击、真实结果。
  • Slide 只用作过渡。

4. 留时间给互动：

  • 60 分钟 demo 留 20 分钟 Q&A。
  • 客户的问题往往揭示真实关切。

Demo 平台架构

核心组件：

沙箱环境池：


    

  • 每个 SE 一个独立 instance。
    • 

  • 不互相干扰。
    • 

  • 共享底层基础设施。
    • 



数据生成器：


    

  • 生成行业相关样本数据。
    • 

  • 银行：账户、交易、欺诈案例。
    • 

  • 电商：SKU、订单、用户行为。
    • 

  • SaaS：租户、用户、订阅。
    • 



场景模板库：


    

  • 注册流程脚本。
    • 

  • 订单流程脚本。
    • 

  • 故障排查脚本。
    • 

  • SE 直接调用模板加少量定制。
    • 



Reset 脚本：


    

  • 一键把 demo 环境恢复初始状态。
    • 

  • 15 秒以内。
    • 

  • Demo 之间快速切换。
    • 



数据生成
行业数据集：


    

  • 银行：开户、交易、欺诈案例。
    • 

  • 电商：商品目录、订单、退货。
    • 

  • SaaS：租户、订阅、计费。
    • 

  • 医疗：患者、就诊、处方（注意 HIPAA 合规）。
    • 



生成工具：


    

  • Faker、Mockaroo、自研。
    • 



真实感：


    

  • 数据要看起来像真的。
    • 

  • 用户名不要是"User1、User2"。
    • 

  • 金额不要是"100、200、300"整数。
    • 



规模：


    

  • 演示性能时数据量要够大（几百万行）。
    • 

  • 演示流程时几十行就够。
    • 



客户真实数据
最高定制层次：


    

  • 客户提供脱敏数据。
    • 

  • SE 加载到 demo 环境。
    • 

  • 演示时客户看到自己的业务。
    • 



法律风险：


    

  • NDA 保护。
    • 

  • 数据销毁约定。
    • 

  • 不要永久保留。
    • 



脱敏要求：


    

  • PII 去除（姓名、邮箱、手机、身份证）。
    • 

  • 金额可以保留（信号有用）。
    • 

  • 关系结构保留。
    • 



Live demo 安全
Live demo 是高风险操作：


    

  • 一次崩溃整场尴尬。
    • 

  • 数据库挂掉、网络断、权限错误。
    • 



预防措施：


1. 多次预演：


    

  • 至少 5 次完整跑通。
    • 

  • 在 demo 实际网络环境跑。
    • 



2. 录制备份视频：


    

  • 每个 demo 录一份。
    • 

  • Live 失败立刻切到录像。
    • 



3. 离线 fallback：


    

  • 关键演示步骤本地数据兜底。
    • 

  • 网络挂了也能继续。
    • 



4. 不要在 demo 中实时修代码：


    

  • 代码改好提前放好。
    • 

  • 现场只 reveal。
    • 



5. Demo 数据预先准备：


    

  • 不要现场 INSERT。
    • 

  • 现场只 SELECT 与 UPDATE。
    • 



Demo 流程设计
经典三段式：


1. 起点（5 分钟）
   - 展示空白或初始状态
   - 解释痛点
2. 构建（30 至 40 分钟）
   - 步步演示功能
   - 每 5 分钟一个 visual confirm
3. 收尾（10 分钟）
   - 展示完整结果
   - Q&A
节奏控制：


    

  • 前 5 分钟决定客户是否听完。
    • 

  • 高潮在第 30 分钟左右。
    • 

  • 最后 5 分钟必须留给下一步共识。
    • 



复用机制
模板库：


    

  • 每个 SE 的 demo 加入团队库。
    • 

  • 行业 + 用例分类。
    • 

  • 后续 SE 可借用。
    • 



版本控制：


    

  • Git 仓库管理 demo 脚本。
    • 

  • 与产品版本对齐。
    • 

  • 产品升级时 demo 跟着升级。
    • 



评级：


    

  • 哪个模板转化率高？
    • 

  • 内部 review 与 retire 烂模板。
    •

自研 vs 买：


    

  • 早期团队（< 5 SE）用现成。
    • 

  • 团队规模化后部分场景自研。
    • 



Demo 失败的反模式
1. 通用 demo 应付企业级 deal：


    

  • 客户感觉"你不重视我"。
    • 



2. Slide-heavy demo：


    

  • 客户想看产品不想听演讲。
    • 



3. 修复 bug live：


    

  • "等一下我看看"——5 分钟尴尬。
    • 



4. 数据看起来假：


    

  • "User1、User2、User3"——失去真实感。
    • 



5. 没有下一步：


    

  • Demo 结束散场——deal 不推进。
    • 



6. 超时：


    

  • 给 60 分钟讲 90 分钟——客户失去耐心。
    • 



7. 一个人讲 90 分钟：


    

  • 留 Q&A 太少。
    • 



异步 demo
录像 demo：


    

  • 5 至 10 分钟。
    • 

  • 适合 follow-up 或决策方分享。
    • 



交互式 demo（点击式）：


    

  • Reprise、Walnut 这类工具录制。
    • 

  • 客户自己点击体验。
    • 

  • 适合 self-serve 场景。
    • 



优势：


    

  • 不占 SE 时间。
    • 

  • 可被 forward 到客户内部其他人。
    • 



Demo 后的复盘
Internal：


    

  • 哪一段卡住？
    • 

  • Q&A 有什么意外问题？
    • 

  • 客户的肢体语言？
    • 



External（客户）：


    

  • 24 小时内发感谢邮件。
    • 

  • 总结要点 + 下一步 + 共享 demo 录像。
    •

实战建议
1. 投入 demo 平台：


    

  • 5 SE 以上的团队 ROI 极高。
    • 



2. 第 1 层定制覆盖 80% deal：


    

  • 不是每个 deal 都做第 2 层。
    • 



3. 多次预演：


    

  • 至少 5 次。
    • 



4. 录像备份必备：


    

  • 不可省。
    • 



5. 模板共享：


    

  • 团队库。
    • 



6. 客户用语：


    

  • Demo 前研究客户网站、文档。
    • 



7. Demo 后 24 小时复盘邮件：


    

  • 不可省。
    • 



8. 不修 bug live：


    

  • 提前修好。
    • 



小结
定制 demo 是 SE 最高杠杆的工具——产品装在客户业务上下文中演示转化率比通用 demo 高 3 至 5 倍，"我们用你们今天真实的订单数据跑一遍全流程"远胜"我们有 50 个功能看 5 个"，但定制 demo 也是 SE 时间黑洞每 deal 1 至 2 周加 20 至 40 小时常态，demo 平台加沙箱加数据生成器加模板复用让单次准备从 20 小时压到 2 至 4 小时。Demo 三层定制——第 0 层通用 demo 标准 tour 用产品自带样本不针对特定客户、第 1 层行业定制银行用合规电商用 SKU 与订单同行业可复用、第 2 层客户定制用客户真实脱敏数据加客户术语流程 KPI 不可复用但 ROI 最高，取舍早期 deal 用第 1 层省时大 deal 100 万美元以上值得第 2 层。好定制 demo 四要素——命中真实痛点 discovery 识别的第一段直击、用客户语言客户叫 work order 别叫 ticket 客户叫 item 别叫 product、Live 操作真实点击真实结果 slide 只过渡、留时间给互动 60 分钟留 20 分钟 Q&A 客户问题揭示真实关切。Demo 平台架构核心组件——沙箱环境池每 SE 独立 instance 不干扰共享底层基础设施、数据生成器行业数据集银行账户交易欺诈与电商 SKU 订单与 SaaS 租户订阅、场景模板库注册与订单与故障流程脚本 SE 调用模板加少量定制、Reset 脚本一键恢复初始 15 秒以内 demo 之间快速切换。数据生成——行业数据集银行电商 SaaS 医疗（注意 HIPAA），生成工具 Faker / Mockaroo / 自研，真实感用户名不要 User1 User2 金额不要整数，规模演示性能几百万行演示流程几十行。客户真实数据最高定制——客户提供脱敏 SE 加载到 demo 环境演示时客户看到自己业务，法律 NDA 保护加销毁约定加不永久保留，脱敏 PII 去除（姓名邮箱手机身份证）金额保留信号有用关系结构保留。Live demo 安全高风险——一次崩溃整场尴尬数据库挂网络断权限错，预防多次预演至少 5 次完整跑通在 demo 实际网络、录制备份视频每 demo 录一份 live 失败切录像、离线 fallback 关键步骤本地数据兜底网络挂也能继续、不要 demo 中实时修代码代码改好提前放现场只 reveal、demo 数据预先准备不现场 INSERT 现场只 SELECT 与 UPDATE。Demo 流程经典三段——起点 5 分钟空白或初始加痛点解释、构建 30 至 40 分钟步步演示每 5 分钟 visual confirm、收尾 10 分钟完整结果加 Q&A，节奏控制前 5 分钟决定听完否加高潮第 30 分钟加最后 5 分钟必须留下一步共识。复用机制——模板库每 SE demo 加入团队库行业加用例分类后续可借用、版本控制 Git 仓库管理 demo 脚本与产品版本对齐升级时跟着升、评级哪模板转化率高内部 review 与 retire 烂模板。SE 工具栈——Reprise / Walnut 交互式 demo 录制、Demostack 平台、Storylane 引导式、Loom 异步视频、Tella 录制剪辑、Notion 脚本与笔记，自研 vs 买早期 5 SE 以下用现成规模化后部分自研。失败反模式——通用 demo 应付企业级 deal 客户感觉不重视、slide-heavy 客户想看产品不听演讲、live 修 bug 5 分钟尴尬、数据看起来假 User1 User2 失真实感、没下一步散场 deal 不推进、超时给 60 讲 90 客户失耐心、一人讲 90 分钟留 Q&A 太少。异步 demo——录像 demo 5 至 10 分钟适合 follow-up 或决策方分享、交互式（点击式）Reprise / Walnut 录制客户自己点击体验适合 self-serve，优势不占 SE 时间加可被 forward 客户内部其他人。Demo 后复盘——内部哪段卡住加 Q&A 意外问题加客户肢体语言、外部 24 小时内感谢邮件加总结要点加下一步加共享 demo 录像。度量——demo 数量 SE 季度产出、转化率 demo 后进 POC 比例、平均时长 60 分钟为标准、NPS 客户满意度、reuse 率模板被多少 SE 复用。实战建议——投入 demo 平台 5 SE 以上 ROI 极高、第 1 层定制覆盖 80% deal 不是每个第 2 层、多次预演至少 5 次、录像备份必备不可省、模板共享团队库、客户用语 demo 前研究客户网站文档、demo 后 24 小时复盘邮件不可省、不修 bug live 提前修好。一个简单的检验：你能为一个企业级 deal 在 4 小时内构建出第 2 层定制 demo 吗？如果不能，定制 demo 工程还需要继续 practice。定制 demo 是 SE 把"产品在客户业务上的样子"具象化的杠杆——做对让客户工程师立刻能想象"接进我们系统会是什么样"，做错沦为通用 tour 加 slide-heavy 加 live demo 翻车的尴尬现场。
