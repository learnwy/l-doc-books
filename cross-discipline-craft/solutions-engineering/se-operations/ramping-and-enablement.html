Ramping 与赋能

核心概念

新 SE 的 ramping 是 SE 团队规模化的瓶颈——招到合适的人难，让他在 30 至 90 天内能独立跑 deal 更难。一个糟糕的 ramping 让新 SE 6 个月才上 quota，期间客户体验差、AE 不愿带他、新 SE 自己挫败感累积。一个好的 ramping 用结构化的 30/60/90 计划、影子学习、认证机制让新 SE 在第 90 天达到 80% 配额。本节给出 ramping 流程、培训内容、影子学习、认证体系、enablement 资源、SE manager 的角色。

阶段 时长 主要目标 SE 主要活动
上岗准备 第 0 周 Setup、入职、文档导览 阅读、设备、账号
产品深入 第 1-2 周 真懂产品、能跑通 demo 产品培训、自己跑 quickstart
影子学习 第 3-6 周 看资深 SE 跑 deal 旁听 discovery、demo、POC
主导小 deal 第 7-12 周 自己跑小 deal Manager 监督跑 SMB / 中端 deal
完整产能 第 13 周+ 80% 配额 跑企业级 deal

上岗准备（第 0 周）

Day 1：

  • 设备、账号、办公室介绍。
  • 团队午餐。
  • Manager 1 对 1 讲文化与期待。

Day 2-3：

  • 阅读公司文档（mission、产品、客户、竞品）。
  • 看产品 demo 视频。
  • 看历史 conference talk。

Day 4-5：

  • 与 AE、PM、产品工程互相介绍。
  • 加入 Slack channel。
  • 设置 SE 工具（CRM、demo 平台、Gong）。

关键：

  • 不要 Day 1 就让新人跑 demo。
  • 给空间消化信息。

产品深入（第 1-2 周）

目标：

  • 真懂产品（不只是知道有什么功能）。
  • 能自己跑通 quickstart。
  • 能讲清产品的 value proposition。

活动：

1. Hands-on 跑产品：

  • 跟着 quickstart 自己 build hello world。
  • 不让 SE 第一手验证产品 → 后续不真懂。

2. 产品培训：

  • PM 或资深 SE 讲产品架构。
  • 30 至 60 分钟一节，分多节。

3. 写一篇 internal 博客：

  • "我作为新 SE 学习 X 产品的 30 天感受"。
  • 强迫消化、暴露盲点。

4. 答 FAQ：

  • 给一份客户常问 50 题。
  • SE 自己答出来再 review。

影子学习（第 3-6 周）

目标：

  • 看资深 SE 怎么跑 deal。
  • 学话术、节奏、互动。

活动：

1. 旁听 discovery：

  • 资深 SE 跑 discovery，新 SE 旁听。
  • 会后 30 分钟复盘。

2. 旁听 demo：

  • 至少 5 次不同行业 demo。
  • 看怎么定制、怎么互动。

3. 旁听 POC review：

  • 看 POC 是怎么设计、怎么交付、怎么报告的。

4. 双 SE 跑 deal：

  • 资深 SE 主导，新 SE 副手。
  • 新 SE 负责一小部分（demo 中某段、笔记记录）。

5. 录像回看：

  • Gong 录音回听。
  • 自己思考"我会怎么应对"。

主导小 deal（第 7-12 周）

目标：

  • 自己跑 SMB 或中端 deal。
  • Manager 在背后监督。

活动：

1. 第一个 deal manager shadow：

  • 新 SE 主导，manager 旁听。
  • 会后逐项 feedback。

2. 单飞 SMB deal：

  • 短周期、低风险。
  • Manager 每周 1 对 1 review。

3. 提交 demo / POC 给 review：

  • 资深 SE 或 manager review。
  • 不放过细节。

4. 客户反馈收集：

  • 每个 deal 后客户 NPS 调查。

完整产能（第 13 周+）

目标：

  • 80% 配额。
  • 自主跑企业级 deal。
  • 不需 manager shadow。

activities：

  • 持续学习（产品 release、行业动态）。
  • 影子比自己更资深的 SE。
  • 开始辅导更新的 SE。
30/60/90 计划
第 30 天：


    

  • 跑通产品 quickstart。
    • 

  • 旁听 5 个 discovery + 5 个 demo。
    • 

  • 自己讲 1 次 demo（内部）。
    • 

  • 完成产品认证。
    • 



第 60 天：


    

  • 自己主导 1 个 SMB deal。
    • 

  • 旁听 1 个 POC 全流程。
    • 

  • 完成行业认证（你 cover 哪个行业）。
    • 



第 90 天：


    

  • 主导 2 个中端 deal。
    • 

  • 跑 1 个 POC。
    • 

  • 达成 50% 配额。
    • 



第 180 天：


    

  • 主导企业级 deal。
    • 

  • 80% 配额。
    • 



培训内容
产品培训：


    

  • 架构。
    • 

  • 主要 use case。
    • 

  • 集成模式。
    • 

  • Roadmap。
    • 



销售培训：


    

  • MEDDIC 或 SPICED。
    • 

  • 异议处理。
    • 

  • Discovery 技巧。
    • 



行业培训（如果有 vertical specialization）：


    

  • 行业术语、合规、典型痛点。
    • 



软技能培训：


    

  • 演讲与白板。
    • 

  • 客户互动。
    • 

  • 跨文化沟通（如服务全球客户）。
    • 



工具培训：


    

  • CRM、demo 平台、Gong、RFP 工具。
    • 



影子学习的细节
资深 SE 选择：


    

  • 选耐心 + 愿意教的。
    • 

  • 不是最强的——最强可能太忙或不擅教。
    • 



频率：


    

  • 至少 3 个不同资深 SE 各 shadow 1 周。
    • 

  • 不同风格不同行业。
    • 



复盘：


    

  • 每场 deal 后 30 分钟复盘。
    • 

  • 学到什么、有什么疑问。
    • 



双向：


    

  • 资深 SE 也教学相长。
    • 

  • 给新 SE 反馈机会。
    • 



认证体系
Level 1：产品基础：


    

  • 答 50 道选择题。
    • 

  • 跑通 hello world 录像证明。
    • 



Level 2：行业知识：


    

  • 给一个客户 case 写 discovery 提问 + demo 思路。
    • 

  • 资深 SE review。
    • 



Level 3：完整 deal：


    

  • 模拟一个企业级 deal cycle。
    • 

  • 审稿团队评估。
    • 



Level 4：Principal：


    

  • 战略 deal 复盘。
    • 

  • Roadmap 影响力。
    • 



Enablement 资源
SE 内部 wiki：


    

  • Demo 模板、playbook、case study。
    • 

  • Discovery 提问清单。
    • 

  • 异议答案库。
    • 

  • RFP 答案库。
    • 



新人 onboarding 文档：


    

  • 30/60/90 计划模板。
    • 

  • 培训 schedule。
    • 

  • FAQ。
    • 



Internal Slack channel：


    

  • 新 SE 频道。
    • 

  • 资深 SE 答疑。
    • 



月度 SE all-hands：


    

  • 分享案例。
    • 

  • 产品更新。
    • 

  • 跨团队同步。
    • 



SE Manager 在 ramping 中的角色
Day 1 至 30：


    

  • 每周 30 分钟 1 对 1。
    • 

  • 主动 check-in。
    • 



Day 31 至 90：


    

  • 每两周 1 对 1。
    • 

  • Shadow 第一个 deal。
    • 



Day 91+：


    

  • 月度 1 对 1。
    • 

  • Quarterly review。
    • 



Manager 的责任：


    

  • 配资深 SE 做 mentor。
    • 

  • 协调 AE 给新 SE 合适的 deal。
    • 

  • 监控 ramping 进展。
    • 

  • 在 ramping 失败时早识别。
    • 



Ramping 失败的信号
信号 1：客户 NPS 持续低：


    

  • 客户对新 SE 不满。
    • 

  • Manager 介入辅导。
    • 



信号 2：第 60 天还没跑 deal：


    

  • 流程卡住——找根因。
    • 



信号 3：新 SE 抱怨没机会：


    

  • AE 不带——manager 协调。
    • 



信号 4：第 90 天 0 deal：


    

  • 红色警告——可能不适合。
    • 



信号 5：演讲与白板不长进：


    

  • 需要专项辅导。
    • 



Enablement 与 DevRel 协作
复用：


    

  • DevRel 写的 tutorial = SE 培训素材。
    • 

  • DevRel 做的 conference talk = SE 学习视频。
    • 

  • DevRel 维护的 sample 仓库 = SE demo 起点。
    • 



协同：


    

  • DevRel 与 SE Enablement 月度同步。
    • 

  • 新产品发布共建培训 deck。
    • 



反模式
1. 没有结构化 ramping：


    

  • 让新 SE "自己摸索"——挫败感大。
    • 



2. Day 1 就跑客户 demo：


    

  • 还没真懂产品就上场——客户体验差。
    • 



3. 配 mentor 不耐心：


    

  • "我没时间教"——新 SE 学不到。
    • 



4. 第 30 天就要业绩：


    

  • 期待不现实——失败率高。
    • 



5. 培训只在第一周：


    

  • 一次性 firehose——记不住。
    • 



6. 不让新 SE 跑实际 deal：


    

  • 永远 shadow 不上手——学不会。
    • 



7. Ramping 失败不早识别：


    

  • 第 90 天才发现 ramping 失败——浪费 6 个月。
    • 



8. 不与 DevRel 协同：


    

  • 重复造培训轮子。
    • 



实战建议
1. 30/60/90 计划文档化：


    

  • 每个新 SE 一份。
    • 



2. 配资深 SE 做 mentor：


    

  • 选耐心愿意教的。
    • 



3. Hands-on 第 1 周：


    

  • 跑通 quickstart。
    • 



4. 影子 5 次以上：


    

  • 不同 SE 不同行业。
    • 



5. 第一个 deal manager shadow：


    

  • 不让新 SE 单飞第一个 deal。
    • 



6. 月度 review ramping：


    

  • Manager 与 mentor 共同评估。
    • 



7. 复用 DevRel 素材：


    

  • 不重复造轮子。
    • 



8. 早识别 ramping 失败：


    

  • 第 60 天还没 deal 介入。
    •

小结
新 SE ramping 是 SE 团队规模化的瓶颈——招合适的人难加 30 至 90 天独立跑 deal 更难；糟糕 ramping 让新 SE 6 个月才上 quota 加客户体验差加 AE 不愿带加新 SE 挫败累积；好 ramping 用结构化 30/60/90 计划加影子学习加认证机制让新 SE 第 90 天达 80% 配额。Ramping 5 个阶段——上岗准备第 0 周（setup 加入职加文档导览）、产品深入第 1-2 周（真懂产品加跑通 demo）、影子学习第 3-6 周（看资深 SE 跑 deal）、主导小 deal 第 7-12 周（manager 监督跑 SMB/中端）、完整产能第 13 周+（80% 配额）。上岗准备——day 1 设备账号办公室介绍加团队午餐加 manager 1 对 1 文化期待；day 2-3 阅读公司文档（mission 加产品加客户加竞品）加看产品 demo 视频加历史 conference talk；day 4-5 与 AE 加 PM 加产品工程互相介绍加加入 Slack 加设置 SE 工具（CRM/demo 平台/Gong）；关键不要 day 1 跑 demo 给空间消化。产品深入目标真懂产品（不只知功能）加跑通 quickstart 加讲清 value proposition；活动 hands-on 跑产品（跟 quickstart build hello world）加产品培训（PM 或资深讲架构 30 至 60 分钟分多节）加写 internal 博客（30 天感受强迫消化暴露盲点）加答 FAQ（客户常问 50 题自己答 review）。影子学习目标看资深 SE 怎么跑 deal 加学话术节奏互动；活动旁听 discovery 加旁听 demo 至少 5 次不同行业加旁听 POC review 加双 SE 跑 deal（资深主导新人副手负责一小部分）加录像回看 Gong 思考"我会怎么应对"。主导小 deal 目标自己跑 SMB 或中端 manager 监督；活动第一个 deal manager shadow 主导加 manager 旁听加会后逐项 feedback 加单飞 SMB deal 短周期低风险加 manager 每周 1 对 1 review 加提交 demo/POC review 加客户反馈收集 NPS。完整产能目标 80% 配额加自主跑企业级加不需 shadow；活动持续学习加影子更资深加开始辅导更新 SE。30/60/90 计划——第 30 天跑通 quickstart 加旁听 5 discovery+5 demo 加讲 1 次内部 demo 加完成产品认证；第 60 天主导 1 个 SMB deal 加旁听 1 个 POC 全流程加完成行业认证；第 90 天主导 2 个中端 deal 加跑 1 个 POC 加达 50% 配额；第 180 天主导企业级加 80% 配额。培训内容——产品培训（架构加 use case 加集成模式加 roadmap）加销售培训（MEDDIC 或 SPICED 加异议处理加 discovery 技巧）加行业培训如有 vertical specialization（术语加合规加典型痛点）加软技能培训（演讲白板加客户互动加跨文化沟通）加工具培训（CRM/demo 平台/Gong/RFP 工具）。影子学习细节——资深 SE 选择耐心+愿意教不是最强（可能太忙或不擅教）；频率至少 3 个不同资深各 shadow 1 周不同风格不同行业；复盘每场 30 分钟学到什么疑问；双向资深也教学相长加给新 SE 反馈机会。认证体系——Level 1 产品基础（50 道选择题加录像证明跑通 hello world）；Level 2 行业知识（discovery 提问+demo 思路 + 资深 review）；Level 3 完整 deal（模拟企业级 deal cycle + 审稿团队评估）；Level 4 Principal（战略 deal 复盘 + roadmap 影响力）。Enablement 资源——SE 内部 wiki（demo 模板/playbook/case study/discovery 清单/异议答案/RFP 答案）加新人 onboarding 文档（30/60/90 模板/培训 schedule/FAQ）加 internal Slack channel 新 SE 频道资深答疑加月度 SE all-hands（案例分享/产品更新/跨团队同步）。SE Manager 角色——day 1 至 30 每周 30 分钟 1 对 1 加主动 check-in；day 31 至 90 每两周 1 对 1 加 shadow 第一个 deal；day 91+ 月度 1 对 1 加 quarterly review；manager 责任配资深 SE mentor 加协调 AE 给新 SE 合适 deal 加监控 ramping 进展加 ramping 失败时早识别。Ramping 失败信号——客户 NPS 持续低 manager 介入辅导、第 60 天还没跑 deal 流程卡住找根因、新 SE 抱怨没机会 AE 不带 manager 协调、第 90 天 0 deal 红色警告可能不适合、演讲白板不长进需专项辅导。Enablement 与 DevRel 协作——复用 DevRel tutorial = SE 培训素材加 conference talk = SE 学习视频加 sample 仓库 = SE demo 起点；协同月度同步加新产品发布共建培训 deck。反模式——没有结构化 ramping 让新 SE 自己摸索挫败、day 1 就跑客户 demo 还没真懂产品上场客户体验差、配 mentor 不耐心"我没时间教"学不到、第 30 天就要业绩期待不现实失败率高、培训只在第一周一次性 firehose 记不住、不让新 SE 跑实际 deal 永远 shadow 不上手学不会、ramping 失败不早识别第 90 天才发现浪费 6 月、不与 DevRel 协同重复造培训轮子。实战建议——30/60/90 计划文档化每新 SE 一份、配资深 SE 做 mentor 选耐心愿意教、hands-on 第 1 周跑通 quickstart、影子 5 次以上不同 SE 不同行业、第一个 deal manager shadow 不让单飞、月度 review ramping manager 与 mentor 共同评估、复用 DevRel 素材不重复造轮子、早识别 ramping 失败第 60 天还没 deal 介入。度量 ramping 效果——第 30 天产品认证 100% 完成、第 60 天主导小 deal 1 个以上、第 90 天配额完成 50%、第 180 天配额完成 80%、第 1 年留存率 90% 以上、第 1 年客户 NPS 与资深 SE 接近。一个简单的检验：你能为新 SE 设计 30/60/90 计划加配 mentor 加 milestone 检查点吗？如果不能，ramping 还需要继续 practice。Ramping 与赋能是 SE 团队的"种子培育"——做对让新 SE 第 90 天达 80% 配额加 AE 抢着合作加客户满意，做错让新 SE 6 个月没产出加挫败累积加离职率高。
