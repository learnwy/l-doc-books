SE 度量与配额

核心概念

SE 度量与配额体系决定团队战略方向、个人激励、leadership 对 SE 价值的认知。一个糟糕的 SE 度量体系把 SE 简化为"AE 的影子"——只看 AE 配额完成度，让 SE 失去自己的工作驱动力。一个好的 SE 度量体系既看 SE 与 AE 联合背的配额，也看 SE 独立的技术指标（technical close rate、POC 通过率、SE attach rate、deal velocity），让 SE 有自己的 north star。本节给出 SE 度量层次、SE-specific KPI、配额结构、薪酬设计、forecasting、避免的反模式。

层次 指标 谁背
业务层 ARR、win rate、retention SE Lead 与 VP
团队层 Pipeline coverage、ramp time SE Manager
个人层 联合配额、technical close rate SE 与 AE 联合
活动层 Demo 数、POC 数、RFP 数 SE 自己

配额结构

联合背配额：

  • SE 与 AE 共背同一 ARR 数字。
  • 通常 100% 完成度时 SE 拿满 OTE 的 variable 部分。
  • 超额时 SE 与 AE 都拿 accelerator。

为什么联合：

  • SE 与 AE 利益对齐。
  • 减少"SE 不在乎 AE 关单"的张力。

为什么也独立：

  • 全联合让 SE 失去自己的 north star。
  • SE 的努力与 AE 的努力比例不同。

理想配比：

  • 70% 联合配额（与 AE）。
  • 30% SE-specific 度量。

SE OTE 拆分

典型 SE OTE 70/30：

  • 70% 底薪。
  • 30% variable。

Variable 的拆分：

  • 70% 联合配额（与 AE 完成度挂钩）。
  • 20% SE-specific 度量（technical close rate、POC pass rate）。
  • 10% 战略目标（团队赋能、文档贡献等）。

Accelerator：

  • 完成 100% 配额开始 accelerator。
  • 完成 200% 配额时 variable 翻倍。

SE-specific KPI

Technical close rate：

  • (技术 closed-won deal / 技术参与 deal 数)。
  • 目标 ≥ 30%（SaaS 平均）。
  • 反映 SE 让 deal 在技术上"过关"的能力。

POC pass rate：

  • (POC 通过 / POC 总数)。
  • 目标 ≥ 70%。
  • 反映 POC 设计与执行质量。

SE attach rate：

  • (有 SE 参与的 deal / 总 SQL 数)。
  • 目标 ≥ 80% for enterprise tier。
  • 反映 SE 资源分配是否充分。

Deal velocity：

  • 平均 SQL → closed-won 时间。
  • 越短越好。
  • SE 介入的 deal 通常比无 SE deal 快。

Customer satisfaction：

  • POC 客户对 SE 的 NPS。
  • 衡量 SE 的客户体验质量。
团队层 KPI
Pipeline coverage：


    

  • 当前 pipeline 总额 / 季度配额。
    • 

  • 目标 ≥ 3x（健康 pipeline）。
    • 



Ramp time：


    

  • 新 hire 多久达到完整产能。
    • 

  • 目标 ≤ 90 天（一个完整的销售周期）。
    • 



SE 离职率：


    

  • 年化 SE 离职率。
    • 

  • 目标 ≤ 15%。
    • 

  • 高离职率信号薪酬或文化问题。
    • 



SE 与 AE 比例：


    

  • 健康企业级 1 比 1。
    • 

  • 中端市场 1 比 0.3。
    • 



业务层 KPI
ARR 贡献：


    

  • SE 参与 deal 的 ARR 总额。
    • 



Win rate：


    

  • (closed-won / closed-won + closed-lost)。
    • 

  • 目标 ≥ 30%（企业级）。
    • 



Customer retention：


    

  • 12 个月 NRR。
    • 

  • SE 间接负责（onboarding 影响 retention）。
    • 



Deal size：


    

  • SE 参与 deal 的平均合同金额。
    • 

  • 通常比无 SE deal 大 2 至 3 倍。
    • 



活动层度量
警告：


    

  • 活动指标只是 leading indicator，不应作为主 KPI。
    • 

  • "本季 50 个 demo"不重要，"50 个 demo 转化 15 个 POC"才重要。
    • 



追踪：


    

  • Demo 数 + 转化率。
    • 

  • POC 数 + 通过率。
    • 

  • RFP 数 + 通过率。
    • 



配额设定方法
Top-down：


    

  • 公司收入目标 → SE Lead 分配。
    • 

  • 简单但可能不公平。
    • 



Bottom-up：


    

  • SE 自报 pipeline 与目标。
    • 

  • 再聚合到 leadership。
    • 



混合：


    

  • Top-down 做框架。
    • 

  • Bottom-up 做调整。
    • 



配额随经验调整
第一年新 SE：


    

  • 配额 70% 至 80%（vs 资深 SE）。
    • 

  • 给 ramping 时间。
    • 



资深 SE：


    

  • 100% 配额。
    • 



Principal SE：


    

  • 110% 至 130%（管理 strategic deal）。
    • 



度量的 leading vs lagging
Lagging（结果）：


    

  • ARR、win rate、retention。
    • 

  • 周期长（季度或年）。
    • 



Leading（过程）：


    

  • Demo 数、POC 转化率、deal velocity。
    • 

  • 周期短（周或月）。
    • 



Dashboard 设计：


    

  • Leading 监控每周。
    • 

  • Lagging 监控每季度。
    • 



SE Forecast
SE 在 forecast 中的角色：


    

  • 提供技术 confidence。
    • 

  • POC 成功概率。
    • 

  • 客户参与度。
    • 



Forecast 类型：


    

  • Commit：≥ 90% 把握。
    • 

  • Best case：50% 至 90%。
    • 

  • Pipeline：< 50%。
    • 



SE 的偏差：


    

  • 新 SE 倾向乐观（高估 commit）。
    • 

  • 资深 SE 学会保守。
    • 



反模式
1. SE 完全跟 AE 配额：


    

  • SE 失去自己的 north star。
    • 

  • "AE 不努力 → SE 也不努力"。
    • 



2. 活动指标做主 KPI：


    

  • "本季 50 demo"——可能 50 个失败 demo。
    • 



3. 不区分新人与资深配额：


    

  • 新人压力过大。
    • 



4. 不奖励 SE 战略贡献：


    

  • 写文档、培训新人——没激励。
    • 



5. 度量太多：


    

  • SE 不知道关注什么。
    • 

  • 3 至 5 个核心 KPI 足够。
    • 



6. KPI 与 comp 100% 挂钩：


    

  • SE 操纵 KPI（sandbagging、cherry-picking deal）。
    • 



7. 不 review forecast 偏差：


    

  • SE 的 forecast 越来越不准。
    • 



8. 不公布 leaderboard：


    

  • 内部 transparency 不够。
    • 



实战建议
1. 70/30 配额结构：


    

  • 联合 70% + SE-specific 30%。
    • 



2. 3 至 5 个核心 KPI：


    

  • Technical close rate、POC pass rate、SE attach rate、deal velocity。
    • 



3. 区分新人与资深：


    

  • 新人配额 70% 至 80%。
    • 



4. 战略贡献给 10% 权重：


    

  • 文档、培训、招聘协助。
    • 



5. Dashboard 大家可见：


    

  • Transparency 文化。
    • 



6. 月度 review forecast：


    

  • 提升 SE forecasting 准确度。
    • 



7. 季度 calibration：


    

  • 同梯队 SE 的 KPI 互相比较。
    • 



8. 不要 100% comp 挂钩：


    

  • 80% 挂钩 + 20% leader judgment。
    • 



度量平台
工具：


    

  • Salesforce / HubSpot CRM 收集 deal 数据。
    • 

  • Clari / Aviso 做 forecast。
    • 

  • Looker / Tableau 做 dashboard。
    • 

  • Gong / Chorus 收集 call 数据。
    • 



集成：


    

  • 自动化 KPI 计算。
    • 

  • SE 不用手填。
    • 



SE 离职率与 KPI 设计
高离职率信号：


    

  • KPI 不可达成（设定过高）。
    • 

  • 配额不公平（与同梯队 SE 比）。
    • 

  • Comp 不有竞争力。
    • 



低离职率信号：


    

  • KPI 可达成且 stretch。
    • 

  • 透明 calibration。
    • 

  • Comp 有竞争力（OTE 250k至250k 至250k至400k 资深 SE）。
    • 



SE Manager 的 KPI
团队层：


    

  • 团队总 ARR 贡献。
    • 

  • 团队 win rate。
    • 

  • 团队 ramp time。
    • 

  • 团队 retention rate。
    • 



个人层（管理者自己）：


    

  • 1 对 1 频率。
    • 

  • 个人 SE 配额完成分布。
    • 

  • 招聘成功率。
    • 



小结
SE 度量与配额体系决定团队战略方向加个人激励加 leadership 对 SE 价值的认知；糟糕的体系把 SE 简化为"AE 的影子"只看 AE 配额完成度让 SE 失去自己工作驱动力；好的体系既看联合配额也看 SE 独立指标（technical close rate 加 POC 通过率加 SE attach rate 加 deal velocity）让 SE 有 north star。配额结构——联合背 SE 与 AE 共背同一 ARR 数字加 100% 完成时 SE 满 variable 加超额都拿 accelerator；为什么联合 SE 与 AE 利益对齐加减少"SE 不在乎 AE 关单"张力；为什么也独立全联合 SE 失自己 north star 加 SE 努力与 AE 不同比例；理想配比 70% 联合 + 30% SE-specific。SE OTE 70/30——70% 底薪加 30% variable；variable 拆分 70% 联合配额（与 AE 完成度挂钩）加 20% SE-specific（technical close rate 加 POC pass rate）加 10% 战略目标（团队赋能加文档贡献）；accelerator 100% 开始加 200% 翻倍。SE-specific KPI——technical close rate 技术 closed-won / 参与 deal 目标 ≥ 30% 反映让 deal 技术过关能力；POC pass rate 通过 / 总数目标 ≥ 70% 反映 POC 设计执行质量；SE attach rate 有 SE deal / 总 SQL 目标 ≥ 80% enterprise tier 反映资源分配是否充分；deal velocity SQL → closed-won 时间越短越好 SE 介入比无 SE 快；customer satisfaction POC 客户对 SE 的 NPS 衡量客户体验质量。团队层 KPI——pipeline coverage 总 pipeline / 季度配额目标 ≥ 3x；ramp time 新 hire 达完整产能目标 ≤ 90 天；SE 离职率年化目标 ≤ 15% 高信号薪酬或文化问题；SE 与 AE 比例企业级 1 比 1 加中端 1 比 0.3。业务层 KPI——ARR 贡献 SE 参与 deal 总额；win rate closed-won / closed-won+closed-lost 目标 ≥ 30% 企业级；customer retention 12 个月 NRR SE 间接负责 onboarding 影响；deal size SE 参与 deal 平均合同金额通常比无 SE 大 2 至 3 倍。活动层度量警告——只是 leading indicator 不应作主 KPI"50 个 demo"不重要"50 个 demo 转化 15 个 POC"才重要；追踪 demo 数+转化率加 POC 数+通过率加 RFP 数+通过率。配额设定方法——top-down 公司收入目标 SE Lead 分配简单但不公平；bottom-up SE 自报 pipeline 与目标聚合 leadership；混合 top-down 框架加 bottom-up 调整。配额随经验调整——第一年 70% 至 80% 给 ramping 时间；资深 100%；Principal 110% 至 130% 管 strategic deal。度量 leading vs lagging——lagging 结果 ARR / win rate / retention 周期长季度或年；leading 过程 demo 数 / POC 转化率 / deal velocity 周期短周或月；dashboard leading 每周加 lagging 每季度。SE forecast——角色提供技术 confidence 加 POC 成功概率加客户参与度；类型 commit ≥ 90% 把握加 best case 50% 至 90% 加 pipeline < 50%；偏差新 SE 倾向乐观高估 commit 加资深学会保守。反模式——SE 完全跟 AE 配额失自己 north star "AE 不努力 SE 也不努力"、活动指标做主 KPI 50 demo 可能 50 失败、不区分新人与资深配额新人压力过大、不奖励战略贡献文档培训新人没激励、度量太多 SE 不知关注什么 3 至 5 个核心足够、KPI 与 comp 100% 挂钩 SE 操纵 sandbagging cherry-picking、不 review forecast 偏差越来越不准、不公布 leaderboard transparency 不够。实战建议——70/30 配额结构联合 70% + SE-specific 30%、3 至 5 核心 KPI（technical close rate 加 POC pass rate 加 SE attach rate 加 deal velocity）、区分新人与资深新人 70% 至 80%、战略贡献给 10% 权重（文档加培训加招聘协助）、dashboard 大家可见 transparency、月度 review forecast 提升准确度、季度 calibration 同梯队互相比较、不 100% comp 挂钩 80% 挂钩 + 20% leader judgment。度量平台——工具 Salesforce/HubSpot CRM 收集 deal 数据加 Clari/Aviso 做 forecast 加 Looker/Tableau 做 dashboard 加 Gong/Chorus 收集 call 数据；集成自动化 KPI 计算 SE 不用手填。SE 离职率与 KPI 设计——高离职率信号 KPI 不可达成（设定过高）加配额不公平加 comp 不竞争；低离职率 KPI 可达成且 stretch 加透明 calibration 加 comp 竞争（OTE 250k至250k 至250k至400k 资深 SE）。SE Manager KPI——团队层（ARR 贡献加 win rate 加 ramp time 加 retention rate）；个人层（1 对 1 频率加 SE 配额完成分布加招聘成功率）。一个简单的检验：你能为 10 人 SE 团队设计 70/30 配额结构加 5 个核心 KPI 加 3 个梯队配额吗？如果不能，SE 度量与配额还需要继续 practice。SE 度量与配额是 SE 团队的"指南针"——做对让 SE 有自己 north star 加联合 AE 关单 加战略贡献被认可，做错让 SE 沦为 AE 影子加 cherry-picking deal 加高离职率。
