高级查询：窗口函数、CTE、子查询优化

窗口函数基础

窗口函数是 SQL 分析中最强大的工具之一。与聚合函数不同，窗口函数在执行计算时不会折叠结果集的行数，每一行都保留其原始数据的同时获得计算结果。

窗口函数语法结构
SELECT
    column_name,
    window_function() OVER (
        PARTITION BY partition_column
        ORDER BY order_column
        ROWS BETWEEN frame_start AND frame_end
    ) AS result
FROM table_name;

排名函数
排名函数是窗口函数中最常用的一类，用于给结果集中的行分配序号。


SELECT
    department,
    employee_name,
    salary,
    ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS row_num,
    RANK()       OVER (PARTITION BY department ORDER BY salary DESC) AS rank_val,
    DENSE_RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS dense_rank_val
FROM employees;

偏移函数
LAG 和 LEAD 函数可以访问当前行前后指定偏移量的行数据，在环比分析和同比分析中极为常用。


SELECT
    date,
    daily_revenue,
    LAG(daily_revenue, 1)  OVER (ORDER BY date) AS prev_day_revenue,
    LEAD(daily_revenue, 1) OVER (ORDER BY date) AS next_day_revenue,
    daily_revenue - LAG(daily_revenue, 1) OVER (ORDER BY date) AS day_over_day_change,
    ROUND(
        (daily_revenue - LAG(daily_revenue, 1) OVER (ORDER BY date))
        / LAG(daily_revenue, 1) OVER (ORDER BY date) * 100, 2
    ) AS dod_change_pct
FROM daily_metrics;
聚合窗口函数
传统聚合函数加上 OVER 子句即成为窗口聚合函数，可以在不折叠行的前提下计算累计值、移动平均等。


SELECT
    date,
    daily_revenue,
    SUM(daily_revenue) OVER (ORDER BY date) AS cumulative_revenue,
    AVG(daily_revenue) OVER (
        ORDER BY date
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS seven_day_moving_avg,
    SUM(daily_revenue) OVER (
        PARTITION BY DATE_TRUNC('month', date)
        ORDER BY date
    ) AS mtd_revenue
FROM daily_metrics;
窗口帧详解
窗口帧定义了参与计算的行范围，是窗口函数中最容易被忽视但最需要精确控制的部分。






帧边界
含义





UNBOUNDED PRECEDING
分区的第一行




N PRECEDING
当前行前 N 行




CURRENT ROW
当前行




N FOLLOWING
当前行后 N 行




UNBOUNDED FOLLOWING
分区的最后一行





SELECT
    date,
    daily_revenue,
    -- 累计总和（从分区起始到当前行）
    SUM(daily_revenue) OVER (
        ORDER BY date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total,
    -- 前后各一行的移动平均
    AVG(daily_revenue) OVER (
        ORDER BY date
        ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
    ) AS centered_moving_avg,
    -- 从当前行到分区末尾的总和
    SUM(daily_revenue) OVER (
        ORDER BY date
        ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING
    ) AS remaining_total
FROM daily_metrics;


公用表表达式（CTE）
CTE 通过 WITH 子句为复杂查询提供了命名的临时结果集，极大地提升了 SQL 的可读性和可维护性。


基础 CTE
WITH monthly_revenue AS (
    SELECT
        DATE_TRUNC('month', order_date) AS month,
        SUM(amount) AS revenue
    FROM orders
    WHERE order_date >= '2025-01-01'
    GROUP BY DATE_TRUNC('month', order_date)
),
monthly_growth AS (
    SELECT
        month,
        revenue,
        LAG(revenue) OVER (ORDER BY month) AS prev_month_revenue,
        ROUND(
            (revenue - LAG(revenue) OVER (ORDER BY month))
            / LAG(revenue) OVER (ORDER BY month) * 100, 2
        ) AS growth_rate
    FROM monthly_revenue
)
SELECT * FROM monthly_growth ORDER BY month;
递归 CTE
递归 CTE 通过自引用实现层级数据的遍历，适用于组织架构、分类树等场景。


WITH RECURSIVE org_tree AS (
    SELECT
        employee_id,
        employee_name,
        manager_id,
        1 AS level,
        employee_name::TEXT AS path
    FROM employees
    WHERE manager_id IS NULL

    UNION ALL

    SELECT
        e.employee_id,
        e.employee_name,
        e.manager_id,
        t.level + 1,
        t.path || ' > ' || e.employee_name
    FROM employees e
    INNER JOIN org_tree t ON e.manager_id = t.employee_id
)
SELECT * FROM org_tree ORDER BY path;

子查询优化
子查询是 SQL 中常见的查询模式，但不当使用可能导致严重的性能问题。


关联子查询与非关联子查询
非关联子查询只执行一次，性能通常可接受：


SELECT employee_name, salary
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
关联子查询对外层查询的每一行都执行一次，是性能瓶颈的常见来源：


-- 关联子查询（性能较差）
SELECT
    d.department_name,
    (SELECT COUNT(*) FROM employees e WHERE e.department_id = d.department_id) AS emp_count
FROM departments d;

-- 改写为 JOIN（性能更优）
SELECT
    d.department_name,
    COUNT(e.employee_id) AS emp_count
FROM departments d
LEFT JOIN employees e ON d.department_id = e.department_id
GROUP BY d.department_name;
EXISTS vs IN 优化




场景
推荐方式
原因

IN
优化器可以高效处理小结果集




子查询结果集大
EXISTS
EXISTS 在找到第一个匹配后即停止




子查询含 NULL 值
EXISTS
IN 遇到 NULL 时的三值逻辑行为不直观




需要反向匹配
NOT EXISTS
NOT IN 遇到 NULL 会返回空结果集





-- NOT IN 的 NULL 陷阱
SELECT * FROM orders
WHERE customer_id NOT IN (SELECT customer_id FROM blacklist);
-- 如果 blacklist.customer_id 含有 NULL，上述查询返回空结果

-- 安全的写法
SELECT * FROM orders o
WHERE NOT EXISTS (
    SELECT 1 FROM blacklist b WHERE b.customer_id = o.customer_id
);
子查询改写为 JOIN 的常见模式
-- 原始：子查询获取每个部门薪资最高的员工
SELECT * FROM employees
WHERE (department_id, salary) IN (
    SELECT department_id, MAX(salary)
    FROM employees
    GROUP BY department_id
);

-- 优化：使用窗口函数
WITH ranked AS (
    SELECT
        *,
        ROW_NUMBER() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rn
    FROM employees
)
SELECT * FROM ranked WHERE rn = 1;


实战 SQL 模式
GROUPING SETS 多维分析
SELECT
    COALESCE(region, '全部') AS region,
    COALESCE(product_category, '全部') AS category,
    SUM(revenue) AS total_revenue,
    COUNT(DISTINCT customer_id) AS customer_count
FROM sales
GROUP BY GROUPING SETS (
    (region, product_category),
    (region),
    (product_category),
    ()
)
ORDER BY region, category;
LATERAL JOIN 行级子查询
SELECT
    u.user_id,
    u.user_name,
    recent_orders.order_id,
    recent_orders.order_date,
    recent_orders.amount
FROM users u
CROSS JOIN LATERAL (
    SELECT order_id, order_date, amount
    FROM orders o
    WHERE o.user_id = u.user_id
    ORDER BY order_date DESC
    LIMIT 3
) AS recent_orders;
FILTER 子句条件聚合
SELECT
    DATE_TRUNC('month', order_date) AS month,
    COUNT(*) AS total_orders,
    COUNT(*) FILTER (WHERE status = 'completed') AS completed_orders,
    COUNT(*) FILTER (WHERE status = 'refunded') AS refunded_orders,
    SUM(amount) FILTER (WHERE status = 'completed') AS completed_revenue,
    ROUND(
        COUNT(*) FILTER (WHERE status = 'completed')::NUMERIC / COUNT(*) * 100, 2
    ) AS completion_rate
FROM orders
GROUP BY DATE_TRUNC('month', order_date)
ORDER BY month;


小结
    

  • 窗口函数通过 OVER 子句在不折叠行的前提下完成排名、偏移、聚合计算，是数据分析 SQL 的核心工具
    • 

  • CTE 通过命名临时结果集提升复杂查询的可读性，递归 CTE 可处理层级数据遍历
    • 

  • 关联子查询是常见的性能瓶颈，应优先考虑改写为 JOIN 或窗口函数
    • 

  • EXISTS 在处理大结果集和 NULL 值时比 IN 更安全高效
    • 

  • GROUPING SETS、LATERAL JOIN、FILTER 子句是高级分析场景中的实用模式
    •
