埋点基础：事件模型、属性设计、埋点分类

什么是埋点

埋点是在应用程序中植入数据采集代码，记录用户行为和系统状态的技术手段。埋点采集的数据是整个数据分析链路的源头，数据质量的上限在埋点设计阶段就已经确定。



事件模型
事件的基本结构
现代数据采集普遍采用事件模型（Event Model），将用户的每一个行为抽象为一个事件。

CREATE TABLE events (

全埋点
-- 全埋点自动采集的数据示例
SELECT
    event_name,       -- $pageview, $click, $input 等预定义事件
    element_id,       -- 被交互元素的 ID
    element_type,     -- button, link, input 等
    element_content,  -- 元素的文本内容
    page_url,         -- 当前页面 URL
    event_time
FROM auto_track_events
WHERE user_id = 'U12345'
ORDER BY event_time;
手动埋点
-- 手动埋点的数据更具业务语义
SELECT
    event_name,       -- add_to_cart（精确的业务事件名）
    properties->>'product_id' AS product_id,
    (properties->>'price')::DECIMAL AS price,
    (properties->>'quantity')::INT AS quantity,
    properties->>'source_page' AS source_page,
    event_time
FROM manual_track_events
WHERE user_id = 'U12345'
ORDER BY event_time;

ID 关联（ID Mapping）
-- ID Mapping 表
CREATE TABLE id_mapping (
    unified_id    VARCHAR(64),
    id_type       VARCHAR(20),
    id_value      VARCHAR(64),
    first_seen_at TIMESTAMP,
    PRIMARY KEY (id_type, id_value)
);

-- 查询某个用户的所有关联 ID
SELECT * FROM id_mapping WHERE unified_id = 'U_unified_001';

-- 通过任意 ID 查找统一 ID
SELECT unified_id FROM id_mapping
WHERE id_type = 'anonymous' AND id_value = 'anon_abc123';


会话（Session）设计




会话切割规则
说明





时间间隔
两次事件间隔超过 30 分钟则切割新会话




跨天切割
跨自然日时切割新会话




来源变化
用户来源渠道变化时切割新会话




前后台切换
App 从后台恢复时切割新会话





-- 基于时间间隔的会话切割
WITH event_gaps AS (
    SELECT
        user_id,
        event_time,
        LAG(event_time) OVER (PARTITION BY user_id ORDER BY event_time) AS prev_event_time,
        CASE
            WHEN event_time - LAG(event_time) OVER (PARTITION BY user_id ORDER BY event_time) > INTERVAL '30 minutes'
            THEN 1
            ELSE 0
        END AS is_new_session
    FROM events
),
session_ids AS (
    SELECT
        user_id,
        event_time,
        SUM(is_new_session) OVER (PARTITION BY user_id ORDER BY event_time) AS session_number
    FROM event_gaps
)
SELECT
    user_id,
    session_number,
    MIN(event_time) AS session_start,
    MAX(event_time) AS session_end,
    COUNT(*) AS event_count,
    MAX(event_time) - MIN(event_time) AS session_duration
FROM session_ids
GROUP BY user_id, session_number;


小结
    

  • 事件模型是现代数据采集的标准范式，每个事件由事件名称、事件属性、用户属性和时间戳组成
    • 

  • 属性设计应遵循原子性、可枚举、正交性和稳定性原则，避免过度采集
    • 

  • 全埋点覆盖广但缺乏业务语义，手动埋点精确但成本高，混合策略是最佳实践
    • 

  • 用户标识需要建立匿名 ID 到登录 ID 的关联机制（ID Mapping）实现跨端统一
    • 

  • 会话切割通常基于 30 分钟的事件间隔规则，是用户行为分析的基本分析单元
    •
