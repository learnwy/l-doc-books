隐私合规：GDPR/CCPA 合规、用户同意管理、数据脱敏

隐私合规的必要性

随着全球隐私法规的不断完善，数据采集已从"能采尽采"转变为"合法合规才能采"。对于程序员而言，隐私合规不是法务部门的事情，而是需要在技术架构和代码实现层面落地的工程实践。

同意状态管理
-- 用户同意记录表
CREATE TABLE user_consent (
    consent_id      VARCHAR(64) PRIMARY KEY,
    user_id         VARCHAR(64),
    anonymous_id    VARCHAR(64),
    consent_type    VARCHAR(20) NOT NULL,
    is_granted      BOOLEAN NOT NULL,
    granted_at      TIMESTAMP,
    revoked_at      TIMESTAMP,
    consent_version VARCHAR(10),
    ip_address      VARCHAR(45),
    user_agent      TEXT,
    created_at      TIMESTAMP NOT NULL DEFAULT NOW()
);

-- 查询用户当前的同意状态
SELECT
    consent_type,
    is_granted,
    COALESCE(revoked_at, granted_at) AS last_updated
FROM user_consent
WHERE user_id = 'U12345'
  AND consent_id IN (
    SELECT MAX(consent_id)
    FROM user_consent
    WHERE user_id = 'U12345'
    GROUP BY consent_type
  );
基于同意的数据采集控制
-- 检查埋点数据是否符合用户同意范围
SELECT
    e.event_id,
    e.event_name,
    e.user_id,
    e.event_time,
    CASE
        WHEN e.event_name IN ('page_view', 'click') AND NOT COALESCE(c.analytics_granted, FALSE)
        THEN '未授权分析性数据'
        WHEN e.event_name IN ('ad_click', 'campaign_view') AND NOT COALESCE(c.marketing_granted, FALSE)
        THEN '未授权营销性数据'
        ELSE '合规'
    END AS compliance_status
FROM events e
LEFT JOIN (
    SELECT
        user_id,
        BOOL_OR(is_granted AND consent_type = 'analytics') AS analytics_granted,
        BOOL_OR(is_granted AND consent_type = 'marketing') AS marketing_granted
    FROM user_consent
    WHERE revoked_at IS NULL
    GROUP BY user_id
) c ON e.user_id = c.user_id
WHERE e.event_time >= CURRENT_DATE - INTERVAL '1 day';

数据删除（被遗忘权）实现
-- 用户数据删除流程
-- 步骤 1：标记用户为待删除
UPDATE users
SET deletion_requested_at = NOW(),
    status = 'pending_deletion'
WHERE user_id = 'U12345';

-- 步骤 2：删除事件数据中的个人信息
UPDATE events
SET user_id = NULL,
    properties = properties - 'email' - 'phone' - 'ip_address',
    anonymous_id = 'DELETED_' || MD5(anonymous_id)
WHERE user_id = 'U12345';

-- 步骤 3：删除用户画像数据
DELETE FROM user_profiles WHERE user_id = 'U12345';

-- 步骤 4：记录删除操作
INSERT INTO data_deletion_log (user_id, requested_at, completed_at, tables_affected)
VALUES ('U12345', NOW(), NOW(), ARRAY['events', 'user_profiles']);

-- SQL 层面的数据脱敏函数
-- 手机号脱敏
SELECT
    user_id,
    CONCAT(LEFT(phone, 3), '****', RIGHT(phone, 4)) AS masked_phone
FROM users;

-- 邮箱脱敏
SELECT
    user_id,
    CONCAT(LEFT(email, 1), '***@', SPLIT_PART(email, '@', 2)) AS masked_email
FROM users;

-- IP 地址泛化
SELECT
    event_id,
    CONCAT(
        SPLIT_PART(ip_address, '.', 1), '.',
        SPLIT_PART(ip_address, '.', 2), '.',
        SPLIT_PART(ip_address, '.', 3), '.0'
    ) AS generalized_ip
FROM events;

    SELECT MIN(event_time)

小结
    

  • GDPR、CCPA 和 PIPL 是当前最重要的三部隐私法规，违规处罚严厉
    • 

  • 用户同意管理需要分级（必要/功能性/分析性/营销性），并在技术层面控制数据采集范围
    • 

  • 用户有访问、更正、删除（被遗忘权）和数据可携带等权利，需要提供技术实现
    • 

  • 数据脱敏技术包括哈希、加密、掩码、泛化和差分隐私，应根据使用场景选择合适方法
    • 

  • 数据保留策略应明确各类数据的保留期限和到期处理方式，平衡业务需求和合规要求
    •
