-- 上线后的数据验证 SQL
-- 检查新事件的数据量趋势
SELECT
    DATE(event_time) AS date,
    event_name,
    COUNT(*) AS event_count,
    COUNT(DISTINCT user_id) AS user_count,
    COUNT(*) FILTER (WHERE properties->>'product_id' IS NULL) AS missing_product_id
FROM events
WHERE event_name IN ('add_to_cart', 'view_product', 'submit_order')
  AND event_time >= CURRENT_DATE - INTERVAL '7 days'
GROUP BY DATE(event_time), event_name
ORDER BY date, event_name;


小结
    

  • 埋点方案设计是一个从需求分析到持续监控的完整流程，需要产品、数据和研发的协作
    • 

  • 埋点文档应包含背景目标、事件清单、属性定义、流程图和验收标准
    • 

  • 事件命名采用动宾结构 + 小写下划线格式，属性命名使用统一的后缀约定
    • 

  • 埋点 Review 应覆盖需求完整性、命名规范、技术可行性、隐私合规等维度
    • 

  • 埋点测试需要在开发自测、联调验证和线上监控三个阶段进行数据质量验证
    •
