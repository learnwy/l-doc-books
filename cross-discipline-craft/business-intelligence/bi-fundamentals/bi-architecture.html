BI 系统架构

核心概念

BI 系统架构是支撑商业智能运转的技术骨架，它定义了数据如何从源头流向最终用户。一个设计良好的架构能够在数据量增长、分析需求变化时保持弹性，而一个糟糕的架构则会让整个 BI 项目陷入"技术债务泥潭"。

典型的 BI 系统采用分层架构，每一层承担明确的职责，层与层之间通过标准化接口交互。这种分层设计的核心优势在于关注点分离——数据工程师专注于数据管道，分析师专注于语义层，前端工程师专注于可视化。

数据源层设计
数据源层是 BI 架构的输入端，其复杂度通常远超预期。一个中型互联网公司可能有数十个业务数据库、多套日志系统、若干第三方 SaaS 服务，以及散落在各处的 Excel 文件。


数据源接入的核心挑战是异构性。不同系统的数据格式、更新频率、访问协议各不相同。关系型数据库提供结构化数据，日志系统输出半结构化的 JSON，第三方 API 可能有速率限制和分页机制。


在架构设计中，通常采用连接器模式（Connector Pattern）来抽象数据源的差异。每种数据源对应一个标准化的连接器，负责处理认证、分页、重试等通用逻辑，向上层提供统一的数据流接口。


数据源层还需要考虑变更数据捕获（CDC，Change Data Capture）。相比全量同步，CDC 只传输增量变更，能够显著降低数据延迟和网络带宽消耗。Debezium 是目前最流行的开源 CDC 方案，它通过监听数据库的 binlog 来捕获行级变更。


数据集成层架构
数据集成层负责将异构数据源的原始数据转化为可分析的格式。传统上采用 ETL（Extract-Transform-Load）模式，现代架构更倾向于 ELT（Extract-Load-Transform）模式。


ETL 与 ELT 的本质区别在于转换发生的位置。ETL 在数据加载到目标系统之前完成转换，适合目标系统计算能力有限的场景。ELT 先将原始数据加载到强大的云数据仓库中，然后利用仓库的计算能力完成转换。


ELT 模式在现代数据栈中占主导地位，原因包括：云数据仓库的计算弹性消除了提前转换的必要性；原始数据保留提高了分析灵活性；dbt 等工具使 SQL 转换可以纳入版本控制和 CI/CD。


数据集成层的关键设计考量包括幂等性（重复执行不产生重复数据）、可观测性（每个步骤的执行状态可追踪）、以及错误处理（失败任务的自动重试与告警）。


数据存储层选型
数据存储层是 BI 架构的核心，存储层的选型直接决定了查询性能、存储成本和系统可维护性。


主流的存储方案可以分为三大类：传统数据仓库（如 Oracle、Teradata）适合对数据一致性要求极高的金融场景；云数据仓库（如 Snowflake、BigQuery、Redshift）提供弹性计算和按量计费；OLAP 引擎（如 ClickHouse、Apache Druid、Apache Doris）针对实时分析场景优化。

近年来，湖仓一体（Lakehouse）架构逐渐成为趋势，它结合了数据湖的灵活存储和数据仓库的查询性能。Apache Iceberg、Delta Lake 等表格式（Table Format）使数据湖具备了 ACID 事务、时间旅行、模式演进等传统仓库的能力。


语义层与指标管理
语义层（Semantic Layer）是 BI 架构中最容易被忽视但最关键的组件。它的职责是在物理数据模型和业务用户之间建立一道"翻译层"，将技术表名和字段名映射为业务术语，将复杂的 SQL 逻辑封装为可复用的指标定义。


没有语义层的 BI 系统会面临严重的"指标口径不一致"问题。同一个"日活跃用户数"指标，A 部门可能用登录行为定义，B 部门可能用页面访问定义，当两个部门的数据对不上时，信任就会崩塌。


语义层的核心组件包括：指标定义（Metric Definitions）描述每个指标的计算逻辑和口径；维度定义（Dimension Definitions）描述可用于切片分析的属性；关系定义（Join Definitions）描述维度表和事实表之间的关联方式。


目前主流的语义层实现方案有 Looker 的 LookML、dbt 的 Semantic Layer、Cube.js 以及 MetricFlow。它们的共同点是用声明式语法定义指标和维度，通过版本控制管理变更，通过 API 向下游 BI 工具暴露查询接口。


小结
    

  • BI 系统采用分层架构，包括数据源、集成、存储、语义、分析五层
    • 

  • 数据源层的核心挑战是异构性，通过连接器模式和 CDC 技术解决
    • 

  • ELT 已取代 ETL 成为现代数据集成的主流范式
    • 

  • 存储层选型需要在查询性能、成本和灵活性之间权衡
    • 

  • 语义层是保证指标口径一致性的关键组件
    • 

  • 湖仓一体架构正在成为统一数据存储与分析的新趋势
    •
