开发者画像与旅程

核心概念

DevRel 必须先回答"谁是我的开发者"——开发者不是同质群体。Builder（写 production 代码的）、Decision-maker（CTO、Architect 决定 stack）、Influencer（Twitter / blog / 社区意见领袖）三类人决策影响产品采用，但需要不同 messaging、不同 content、不同 channel。Developer journey 沿 AAARRR 漏斗——Awareness（听过你的名字）→ Acquisition（上你网站 / signup）→ Activation（hello world 跑通）→ Retention（持续用 / 升级 plan）→ Referral（推荐给同事 / 写 blog）→ Revenue（付费）。本节给画像方法、journey 阶段、各阶段 DevRel 该做什么。

Persona 谁 决策力度 DevRel 接触点
Builder 一线写 production 代码 中 Tutorial、sample、docs
Decision-maker CTO、Architect、Tech Lead 高 White paper、case study
Influencer Twitter / blog / OSS owner 间接但广 Podcast、early access

Builder

画像：

  • 1-7 年工程经验。
  • 写一线 feature code。
  • 选 stack 主要看 DX、文档、性能。

痛点：

  • 文档烂——找不到我要的 API。
  • Quickstart 写得太 toy——实际 production 还要 1 小时配置。
  • 没有 "real-world" sample（GitHub repo 只有 hello world）。

DevRel content：

  • Tutorial（10-30 分钟读完）。
  • Sample repo（可 fork 改）。
  • Reference docs（Stripe 风格——可 copy code）。

Channel：

  • GitHub README、文档站、StackOverflow、Reddit。

Decision-maker

画像：

  • CTO、VP Engineering、Architect。
  • 决定团队 stack。
  • 风险厌恶——选错 stack 后果严重。

痛点：

  • 不知 你 production-ready 吗？
  • 多少 Fortune 500 用？
  • Pricing 透不透明？
  • Support SLA 怎么样？
  • 给我 case study + reference call。

DevRel content：

  • White paper（深度技术 + 商业价值）。
  • Case study（X 公司用 Y 实现了 Z）。
  • Webinar（架构 deep dive）。

Channel：

  • LinkedIn、industry conference (KubeCon、AWS re:Invent)、analyst report (Gartner)。

Influencer

画像：

  • Twitter follower 5k-500k。
  • Blog reader 1k-100k/post。
  • OSS project maintainer。

痛点：

  • "Pitch 给我吧但别 pitch 给我"——他们厌恶推销。
  • 想要 early access、深度访谈、独特 story。

DevRel approach：

  • 1-on-1 outreach（不是 mass email）。
  • Early access 给反馈机会。
  • 邀请上 podcast / conference talk。
  • 不要"求"他 promote——给值得他自发 promote 的 thing。

Channel：

  • Twitter/X DM、private Discord channel、in-person dinner at conference。

AAARRR Funnel for Devs

Pirate Funnel 改造为 dev：

Stage Dev Behavior DevRel Asset Metric
Awareness 听过名字、看过 tweet Brand content、tweet Impression、reach
Acquisition 访问 home page / docs Landing page、quickstart Site visit、signup
Activation Hello world 跑通 Quickstart guide、sample TTFHW (time to first hello world)
Retention 持续 deploy、用 advanced 功能 Tutorial、advanced docs DAU/MAU、API call
Referral 推荐给同事 / blog Ambassador program、share NPS、referral count
Revenue 升 paid tier Pricing page、case study Conversion rate 
画像研究方法
1. Survey：


    

  • 季度 1 次 dev community survey。
    • 

  • 问：你工作 stack？年限？为什么选 X？
    • 

  • 工具：Typeform、Tally、Google Forms。
    • 



2. User Interview：


    

  • 季度 5-10 个 dev 1-on-1 30 分钟。
    • 

  • 录音 + 整理 quote。
    • 

  • 找 pattern。
    • 



3. Analytics：


    

  • Google Analytics、PostHog 看哪个 doc page 最 hot。
    • 

  • StackOverflow 看 top tag 问题。
    • 



4. Community Listening：


    

  • Twitter search "我们的产品 sucks" "我们的产品 is great"。
    • 

  • Reddit、HN 帖子 monitor。
    • 

  • Discord 高活跃 channel 发的话题。
    • 



开发者画像 Card 模板
Persona Card（举例）：


Name: Alex the Builder
Role: Senior Frontend Engineer @ Series-B SaaS startup
Experience: 5 years
Stack: Next.js + Vercel + Supabase + Tailwind
Pain points:
- 文档不更新随版本
- 没有 production-grade auth example
- 想要 RBAC tutorial
Channels:
- Twitter, GitHub, Reddit r/nextjs
- Reads Lee Robinson, Theo blog
- Watches Fireship YouTube
Decision criteria:
- DX quality (90%)
- Pricing transparency (5%)
- Vendor stability (5%)
Quote: "I want to ship features, not configure infra."
Journey Map
沿 AAARRR 画 dev 一日：


8:00 Twitter scroll → 看到 X 产品 thread → Awareness
9:30 Coffee 时点 link → docs 读 quickstart → Acquisition
10:00 跟 quickstart 写 hello world → Activation
14:00 build feature → 遇 bug → 看 tutorial → Retention
17:30 在 Discord 问问题 → community 答 → Retention deeper
Day 7：blog "How I built X with Y" → Referral
Day 30：team 决采购 paid tier → Revenue
各阶段 DevRel 工作
Awareness：


    

  • Twitter thread、conference keynote、podcast appearance。
    • 

  • Brand content（高产 + 一致 voice）。
    • 



Acquisition：


    

  • Landing page A/B test。
    • 

  • "Quick demo" video 30 秒。
    • 

  • Free tier offer。
    • 



Activation = DevRel 主战场：


    

  • TTFHW < 5 分钟是世界级标准。
    • 

  • Quickstart 必须 copy-paste 跑通。
    • 

  • "If error, then" troubleshoot section。
    • 



Retention：


    

  • Advanced tutorial。
    • 

  • 邀加 Discord、订 newsletter。
    • 

  • 季度 changelog email。
    • 



Referral：


    

  • Ambassador program（详见 3 章）。
    • 

  • Swag、credit、recognition。
    • 

  • 让 dev 写 blog、上 podcast、share Twitter。
    • 



Revenue：


    

  • Pricing page 透明。
    • 

  • Case study 给 Decision-maker。
    • 

  • ROI calculator。
    • 



TTFHW (Time to First Hello World)
关键 activation metric：


    

  • 从 signup 到第一次成功 API call 时间。
    • 

  • < 5 分钟：世界级。
    • 

  • 5-15 分钟：good。
    • 

  • 

    30 分钟：需 fix。
    

    

    • 



测量：


    

  • 内部 dogfood 计时。
    • 

  • 日志：signup ts → first API call ts。
    • 

  • 不同 OS / 不同 framework 跑测。
    • 



优化：


    

  • 减 prereq（不必装 docker 就能 hello world）。
    • 

  • 提供 sandbox（无需自己 setup）。
    • 

  • Stripe / Linear / Supabase 都极致优化。
    • 



反模式
1. 一种 messaging fits all：


    

  • Builder 看不懂 white paper，CTO 不读 quickstart。
    • 

  • 必须 segment。
    • 



2. 跳过 activation 直奔 revenue：


    

  • 没 hello world 哪来 LTV。
    • 

  • DevRel 主精力 should 投 activation。
    • 



3. Influencer outreach 群发：


    

  • 5k follower 的 dev 一天收 50 个 pitch。
    • 

  • 1-on-1、个性化、有价值才 work。
    • 



4. 不研究画像 just guess：


    

  • 你以为 dev 想 X 实际想 Y。
    • 

  • Survey + interview 是必要投入。
    • 



实战 advice
1. Start with 1 primary persona：


    

  • 早期不要 cover 所有 dev——选最赚钱 segment。
    • 

  • 例：Vercel 早期 focus Next.js dev，later expand。
    • 



2. Update persona quarterly：


    

  • 市场变化、产品变化、用户变化。
    • 

  • 季度 refresh。
    • 



3. Journey map 上墙：


    

  • DevRel 全员看得到。
    • 

  • 决定下次 sprint focus 哪个 stage。
    • 



4. TTFHW < 5 min target：


    

  • 砍 prereq、提供 sandbox、优化 quickstart copy。
    • 



5. Decision-maker content separately：


    

  • 不混 builder content 一起。
    • 

  • Webinar、白皮书、case study 独立 produce。
    • 



6. Influencer 不要 mass-pitch：


    

  • 1-on-1、具名、给 value。
    • 



小结
Developer 不是同质群体——三类 persona：Builder（1-7y experience 写 production code 选 stack 看 DX/docs/性能 痛点：文档烂 / quickstart toy / 无 real-world sample channel：GitHub/StackOverflow/Reddit）、Decision-maker（CTO/VPE/Architect 风险厌恶 想 production-ready / Fortune 500 用户 / case study channel：LinkedIn/conference/Gartner）、Influencer（Twitter 5k-500k follower / OSS maintainer 厌恶 pitch 想 early access + 独特 story 1-on-1 outreach 不要 mass email）。Journey AAARRR——Awareness（impression / reach / brand content）→ Acquisition（site visit / signup / landing page + quickstart）→ Activation（TTFHW < 5min DevRel 主战场 quickstart copy-paste 跑通 + troubleshoot section）→ Retention（DAU/MAU / API call / advanced tutorial / Discord / newsletter）→ Referral（NPS / referral count / ambassador program / swag / blog / podcast）→ Revenue（conversion / pricing transparent / case study / ROI calc）。画像研究方法——quarterly survey（Typeform）、5-10 dev user interview 30min、analytics（GA / PostHog 哪个 doc 最 hot / StackOverflow top tag）、community listening（Twitter search / Reddit / HN / Discord 高活跃 channel）。Persona Card 模板——name + role + experience + stack + pain points + channels + decision criteria + quote。Journey map 沿一日轨迹——8:00 Twitter scroll → awareness 9:30 docs → acquisition 10:00 hello world → activation 14:00 bug + tutorial → retention 17:30 Discord 问 → retention deeper Day 7 blog → referral Day 30 team 采购 → revenue。各阶段 DevRel 工作——Awareness Twitter thread/keynote/podcast、Acquisition landing A/B + 30s demo + free tier、Activation TTFHW 5min copy-paste quickstart 主战场、Retention advanced tutorial + Discord 邀 + changelog、Referral ambassador + swag + credit + recognition、Revenue pricing transparent + case study + ROI calc。TTFHW 关键——< 5min 世界级 / 5-15min good / > 30min 需 fix，测量 signup → first API call ts，优化减 prereq + sandbox + Stripe/Linear/Supabase 极致。反模式——一种 messaging fits all（必须 segment）、跳过 activation 直奔 revenue（没 hello world 无 LTV）、influencer 群发 mass-pitch（每天 50 pitch 1-on-1 才 work）、不研究画像 just guess（必 survey + interview）。Advice——start with 1 primary persona（Vercel 早期 Next.js focus）、quarterly refresh、journey map 上墙全员看、TTFHW < 5min target、decision-maker content 独立 produce 不混、influencer 1-on-1 具名给 value。一个简单的检验：你能写出三个 persona card + 画 AAARRR funnel + report TTFHW 数字吗？如果不能，画像与 journey 还需 practice。Persona + journey 是 DevRel 的"地图"——做对让 content / community / metric 都聚焦同一目标，做不对沦为发散无效 work。
