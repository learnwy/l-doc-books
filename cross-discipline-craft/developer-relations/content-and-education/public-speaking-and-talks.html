演讲与会议演讲

核心概念

公开演讲是开发者关系中最具杠杆效应的触点——一场会议主题演讲可以触达 1000 多现场观众加上 5 万以上视频观看和转发。但面向开发者的演讲不是营销报告——开发者看到销售推介会立即心理屏蔽，看到演示崩溃会立即质疑产品，看到空洞幻灯片会立即看手机。一个好的开发者演讲必须具备"我学到东西了"的价值、有可运行的演示（不只是幻灯片）、诚实承认不足之处、有让人离场后能行动的收获。本节涵盖演讲类型、征稿流程、幻灯片设计、演示准备、现场发挥和演讲后复用。

演讲类型 时长 受众 主要价值
闪电演讲 5-10 分钟 任意 一个关键想法
工作坊演讲 30-45 分钟 构建者 动手实操教程
主题演讲 30-60 分钟 全场 愿景 / 大议题
圆桌讨论 30-60 分钟 任意 多角度讨论
网络研讨会 30-60 分钟 决策者 深度探讨加问答
播客 30-90 分钟 长形式 对话
内部技术分享 30-60 分钟 工程团队 知识传递

选择会议和活动

顶级会议：

  • KubeCon、AWS re:Invent、GitHub Universe、Next.js Conf、Web Summit。
  • 触达广、声望高、征稿竞争激烈。

中级会议：

  • 区域性会议（DevDays、各城市版 PyCon）。
  • 专题会议（GraphQL Conf、JSConf）。

小型活动：

  • 技术聚会（本地 50-200 人）。
  • 企业内部活动。

选择标准：

  • 受众是否匹配目标用户画像？
  • 期望触达量？
  • 成本收益比（差旅制作成本与触达量）？
  • 活动后内容价值（视频/照片）？

征稿（CFP）

写征稿摘要：

标题: Building a Real-time Collaborative Editor with CRDTs and Y.js
摘要 (250 字):
现状：协作编辑曾是"巨头特权"——Google Docs 投入数百工程师 5 年。
痛点：多人实时编辑让前端开发者望而却步——OT、CRDT、网络分区让人头大。
本演讲用 Y.js + WebSocket + React 从零到一实演构建协作文本编辑器，30 分钟内你能：
- 理解 CRDT 与 OT 的本质差别
- 用 Y.Doc + Y.Text + y-websocket 构建同步层
- 用 awareness API 实现多光标
- 处理离线编辑和网络恢复冲突
受众：中级前端工程师，了解 React 和 WebSocket。
收获：你将带走一个可 fork 的演示仓库 + 决策框架"何时用 CRDT 还是 Liveblocks 等 PaaS"。

标题要求：

  • 简短且具体。
  • "如何实现 X"或"构建 Y"的句式。
  • 反例："X 入门"——太笼统。

摘要结构：

  1. 钩子（问题）。
  2. 你的角度（为什么独特）。
  3. 大纲（受众能学到什么）。
  4. 适合谁。
  5. 收获总结。

个人简介：

  • 100 字、第三人称。
  • 含公信力（GitHub 仓库、从业年限、过往演讲经历）。

提交策略

目标会议清单：

  • 每年向 5-10 个会议提交。
  • 资深水平命中率 20-30%。

时间节点：

  • 征稿通常提前 4-6 个月。
  • 早提交更好（评审人还有精力）。

多次提交：

  • 同一演讲可以向多个会议投稿。
  • 针对不同受众修改摘要。

幻灯片设计

每页一个想法：

  • 一页幻灯片不超过一个核心观点。
  • 字体大（不低于 28pt）。

少文字多视觉：

  • 一页不超过 30 个字。
  • 用图表、代码和图片。

幻灯片上的代码：

  • 字体不低于 24pt（即使是代码）。
  • 高对比度配色方案（投影仪环境用深色主题）。
  • 高亮关键行。

首页幻灯片：

  • 演讲标题。
  • 姓名 + 社交媒体账号。
  • 会议标志（按会议规定）。

结尾幻灯片：

  • "试试看：（短链接）"。
  • "找到我：@账号"。
  • "幻灯片 + 代码：链接"。

避免：

  • 超过 5 条要点的列表。
  • 大段文字墙。
  • 俗套图库照片（开发者觉得假）。

现场演示

演示是开发者演讲的灵魂：

  • 但有风险——演示之神喜怒无常。

准备工作：

  • 跑 5 次以上排练。
  • 录制备份视频（演示失败时切换视频）。
  • 离线版本（无需网络）。
  • 重置脚本（快速重置状态）。

演示流程：

  • 展示起点（空项目或 Hello World）。
  • 构建功能 1（现场编码 30 秒到 2 分钟）。
  • 展示结果（视觉确认）。
  • 重复功能 2-3。
  • 不超过 15 分钟（注意力极限）。

现场编码技巧：

  • 预先输入代码片段（用编辑器宏或演示工具）。
  • 编辑器大字体（不低于 18pt）。
  • 隐藏系统界面（全屏）。
  • 演示数据提前准备好（不现场插入数据）。

现场发挥

开场：

  • 30 秒内用钩子抓住注意力——用问题或惊人事实。
  • 不要"大家好，今天我要讲……"。

节奏：

  • 平均每分钟 100-150 个英文词。
  • 慢不等于无聊，快不等于激动。
  • 战略性停顿（强调要点）。

声音：

  • 投射（让后排听见）。
  • 变换语调（单调会催眠）。

身体语言：

  • 站直、不要来回走太多。
  • 手势自然。

眼神接触：

  • 扫全场，不定在一个区域。
  • 不盯着笔记。

结尾：

  • "回顾 3 个要点"。
  • "试试 X，社交媒体上找到我"。

问答环节

复述问题：

  • 让全场听到问题内容。
  • 给自己思考时间。

"我不知道"是好答案：

  • 比胡说八道强。
  • "很好的问题，我在社交媒体上跟进你。"

提问冗长的人：

  • 礼貌打断"让我先回应 X 部分"。

带有敌意的提问者：

  • 不要上钩。
  • "有意思的观点，结束后我们喝杯咖啡聊。"

演讲后续

当天：

  • 发布推文串总结。
  • 将幻灯片和代码推送到 GitHub。
  • 感谢组织者。

一周内：

  • 写博客版本（同内容不同媒介）。
  • 发 LinkedIn。

一个月内：

  • 交叉发布录像。
  • 更新个人网站"演讲"页面。

长尾复用：

  • 复用幻灯片到下个会议（修改 30%）。
  • 将工作坊转化为视频教程。

内部技术分享

面向工程团队：

  • 月度技术分享开发者关系也参与。
  • 把社区反馈讲给工程团队。
  • 把产品路线图讲给开发者关系团队。

形式：

  • 午餐加分享。
  • 录像方便异步观看。

演讲者培养

新布道师培养：

  • 第一次先做 5 分钟闪电演讲。
  • 内部排练至少 2 次。
  • 管理者或资深同事观摩加反馈。

信心建设：

  • 小聚会 → 大会议的进阶路径。
  • 不要直接上主题演讲台。

差旅与倦怠

会议差旅：

  • 飞行加时区加演讲者晚宴 = 疲惫。
  • 一个布道师一年不超过 8-10 个大型会议。
  • 周末活动占用——给补休。

倦怠信号：

  • 不愿写演讲稿。
  • 演示准备草率。
  • 与观众互动减少。

预防措施：

  • 限制每季度差旅配额。
  • 备用演讲者（不让一个人负责一切）。
  • 恢复时间（大型会议后一周不接新安排）。

反模式

1. 营销推介伪装成演讲：

  • 全部幻灯片都是公司标志。
  • 开发者立即心理屏蔽。

2. 幻灯片上的代码无法看清：

  • 字小、对比度低、灯光差。

3. 演示不准备备份方案：

  • 演示失败 → 全场尴尬 → 信任崩塌。

4. 超时：

  • 给 30 分钟讲了 45 分钟——开发者失去耐心、组织者恼火。

5. 不致谢前人工作：

  • "我发明了 X"——开发者知道你没有。

6. 问答环节胡说八道：

  • 不知道装知道，开发者立刻察觉。

7. 演讲后不跟进：

  • 错失势头。

实战建议

1. 第一个演讲从闪电演讲开始：

  • 5 分钟，低风险练手。

2. 同一个演讲多次讲：

  • 每次打磨——不要每场会议都全新幻灯片。

3. 演示是演讲的灵魂：

  • 70% 准备时间花在演示上。

4. 录制备份视频：

  • 每个演示都录一份备用。

5. 回看自己的视频：

  • 痛苦但有用——发现口头禅、节奏和废话。

6. 和非技术朋友做排练：

  • 找出术语卡点。

7. 差旅配额限制：

  • 防止倦怠。

8. 后续跟进：

  • 推文、博客、录像交叉发布。

小结

公开演讲是开发者关系中最具杠杆效应的触点。好的开发者演讲必须有"我学到了东西"的真实价值、可运行的演示、诚实面对不足、以及可操作的收获。演讲类型从 5 分钟闪电演讲到 60 分钟主题演讲各有适用场景。征稿（CFP）需要简短具体的标题和结构化的摘要（钩子、角度、大纲、受众、收获）。幻灯片设计遵循每页一想法、少文字多视觉、代码字体足够大的原则。现场演示是演讲灵魂但需要充分准备（5 次以上排练、备份视频、离线方案）。现场发挥要注意 30 秒钩子开场、节奏控制、声音投射和眼神扫全场。演讲后要做好长尾复用：当天发推文、一周内写博客版本、一个月内发布录像。关键实践包括从闪电演讲起步、同一演讲多次打磨、限制差旅配额防止倦怠。需避免的反模式包括营销推介伪装演讲、演示无备份方案、超时、不跟进等。
