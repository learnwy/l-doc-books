文档、教程与示例代码

核心概念

文档、教程和示例代码是开发者关系中最具长尾价值的资产——一份好的参考文档可以 6 年内每天被数千开发者查阅，一个维护良好的示例仓库可以累积 1000 多颗星并持续被复制使用。但很多公司把文档当作事后补充——让程序员写的发布说明充当文档、快速入门写得太简陋、示例仓库一年没更新——结果开发者来了试不通就离开了。本节将文档提升到一等公民级别的工程交付物——用 Diátaxis 框架分类、用代码即文档的工作流维护、用快速入门驱动优化首次成功耗时、用单体仓库加持续集成管理示例代码。

文档类型 负责人 频率 举例
参考文档 工程 + 开发者关系 每次发布 API 参考、类型定义
快速入门 开发者关系 季度审查 "5 分钟 Hello World"
教程 开发者关系 季度及以上 "构建功能 X"
操作指南 开发者关系 月度及以上 "如何添加认证"
概念文档 开发者关系 + 工程 半年审查 "X 如何工作"
示例仓库 开发者关系 持续集成 参考实现

参考文档

规格准确性是第一优先级：

  • API、类型、参数、返回值、示例。
  • 与 OpenAPI 或 TypeScript 类型自动同步。

自动生成：

  • TypeDoc / JSDoc / OpenAPI Generator。
  • 开发者关系负责审核并添加语义上下文。

多版本管理：

  • v1、v2、v3 分别托管。
  • 编写"从 v1 升级到 v2"的迁移指南。

可搜索：

  • Algolia DocSearch 或 Typesense。
  • 支持模糊搜索、关键词搜索和按类型筛选。

每个方法配代码示例：

  • 不只写"参数：字符串"——加上可运行的示例。

快速入门优化

目标：首次成功耗时小于 5 分钟：

  • 从注册到第一次成功调用 API。
  • 计时并设基准。

减少前置条件：

  • 不必安装 Docker。
  • 不必配置开发环境。
  • 不必理解认证流程。

沙盒环境：

  • 内嵌编辑器（CodeSandbox / StackBlitz）。
  • 纯浏览器示例。
  • "不注册即可体验"的预览。

一键部署：

  • "部署到 Vercel" / "在 Replit 运行"按钮。
  • GitHub 模板仓库。

错误处理：

  • 列出常见错误及修复方法。
  • "如果你看到 X，执行 Y"。

教程制作

教程 = 通过构建来教概念：

  • 不只是参考文档的堆砌。
  • 线性流程从头到尾。

篇幅：

  • 30-90 分钟阅读加动手。
  • 超过 90 分钟拆成多篇系列。

结构：

1. 你将构建什么（配截图或动图）
2. 前置条件
3. 环境搭建（环境、依赖）
4. 步骤 1：核心概念 A
5. 步骤 2：添加功能 B
6. 步骤 3：部署 / 生产环境
7. 故障排查
8. 下一步

测试教程：

  • 让外部开发者跟着跑一遍。
  • 看哪一步卡住——这就是文档缺口。

配套示例仓库：

  • 教程文章 + 完整 GitHub 仓库。
  • 仓库分支对齐教程步骤。

示例仓库策略

1. Hello World 级别：

  • 5 个文件，极简主义。
  • README 不超过 200 字。

2. 生产级别：

  • 完整的认证、错误处理、日志、测试。
  • "这就是真实使用 X 的样子"。

3. 用例专属：

  • "Stripe + Supabase + Vercel 的 SaaS 模板"。
  • "Y.js + React 实时编辑器"。

4. 持续维护：

  • 持续集成每周或每次发布运行。
  • Renovate / Dependabot 跟踪依赖版本。
  • 锁定主版本防止意外破坏。

仓库结构：

example-app/
├── README.md (5 分钟快速入门)
├── docs/ (每个功能的深度说明)
├── src/
├── tests/
├── .github/workflows/ (持续集成)
└── package.json

代码即文档工作流

Markdown 源码在单体仓库或文档仓库：

  • 用 Git 版本控制。
  • 通过拉取请求（PR）审查加检查。

静态站点生成器：

  • Docusaurus、Nextra、VitePress、MkDocs。

构建管线：

  • 拉取请求 → 预览部署（Vercel / Netlify）。
  • 合并 → 生产发布。

检查工具：

  • Prettier、Vale、Markdownlint。
  • 死链检查器。
  • 代码块语法检查。

翻译：

  • Crowdin / Lokalise。
  • 或社区贡献式翻译。

版本管理
方案：


    

  • /v1/、/v2/ 文件夹分隔。
    • 

  • 每个版本独立构建站点。
    • 



版本选择器：


    

  • 页面顶部下拉框。
    • 

  • 默认链接到最新版。
    • 



迁移指南：


    

  • "从 v1 升级到 v2" 的专页。
    • 

  • 列出所有不兼容变更。
    • 



废弃策略：


    

  • 旧版本标记"已废弃"，6 个月后归档。
    • 



本地化
策略：


    

  • 主体英文，根据用户数据翻译为中文、日文、韩文。
    • 



工具：


    

  • Crowdin（付费）。
    • 

  • 社区贡献式（Vue.js 模式）。
    • 



陷阱：


    

  • 过期的翻译比没有翻译更糟（开发者按旧说明操作）。
    • 

  • 必须有同步机制。
    •

示例仓库持续集成
每周运行：


    

  • 更新依赖。
    • 

  • 跑构建和测试。
    • 

  • 如果出错通知负责人。
    • 



产品发布时：


    

  • 更新示例到新版本。
    • 

  • 兼容性测试。
    • 



代码检查：


    

  • 与主产品代码同标准。
    • 



自动依赖更新：


    

  • Renovate / Dependabot 自动创建拉取请求。
    • 

  • 测试通过则自动合并。
    • 



反模式
1. 文档是事后补充：


    

  • 工程师把发布说明当文档。
    • 

  • 不是生产级质量。
    • 



2. 示例代码过时：


    

  • 示例是 v1 但产品已到 v3。
    • 

  • 开发者跟着做 → 失败 → 信任下降。
    • 



3. 没有快速入门或太长：


    

  • 30 分钟的快速入门 = 首次成功耗时超 30 分钟。
    • 

  • 不可接受。
    • 



4. 文档中的代码不可测试：


    

  • 代码无法直接复制粘贴运行。
    • 

  • 代码块必须完整可执行。
    • 



5. 没有搜索或搜索体验差：


    

  • 开发者找不到 → 离开。
    • 



6. 单一无版本站点：


    

  • 升级 v2 → 老用户看到 v1 信息时困惑。
    • 



7. 只有英文文档但有全球用户：


    

  • 30% 潜在用户是中文或日文使用者。
    • 



8. 示例仓库不维护：


    

  • 一年没有提交 → 被认为已归档。
    • 



实战建议
1. 用 Diátaxis 四类型分类：


    

  • 每篇文档标注类型。
    • 

  • 不要混用。
    • 



2. 首次成功耗时小于 5 分钟：


    

  • 砍掉前置条件、提供沙盒环境。
    • 



3. 示例仓库持续集成：


    

  • 每周运行防止无声破坏。
    • 



4. 反馈小组件：


    

  • 每页收集信号。
    • 



5. 季度文档审计：


    

  • 审查前 20 页的准确性。
    • 



6. 招聘文档专员：


    

  • 团队 5 人以上时招专职技术作者。
    • 



7. 开发者关系与产品经理共同拥有路线图文档：


    

  • 新功能必须带文档上线。
    • 



8. 市场验证后再本地化：


    

  • 不要早期就翻译 5 种语言。
    • 



度量关键指标
激活漏斗：


    

  • 快速入门浏览 → 注册 → 首次调用 → 第二次调用。
    • 



文档参与度：


    

  • 前 10 热门页面（每季度刷新）。
    • 

  • 后 10 冷门页面（删除或改进）。
    • 



搜索分析：


    

  • 热门搜索词。
    • 

  • 零结果搜索词（必须修复）。
    • 



示例仓库：


    

  • 星标数、复制数、问题数、拉取请求数。
    • 

  • 活跃维护者数量。
    • 



小结
文档、教程和示例代码是开发者关系最具长尾价值的资产。参考文档以规格准确性为第一优先级，通过自动生成工具和开发者关系审核确保质量；快速入门以首次成功耗时小于 5 分钟为目标，通过减少前置条件和提供沙盒环境实现；教程通过构建来教概念而非堆砌参考信息；示例仓库需要持续集成保证可用性。代码即文档的工作流用 Git 版本控制加拉取请求审查加静态站点生成器实现自动化发布。文档站架构遵循 Diátaxis 四类型（教程、操作指南、参考、概念）的信息架构，配合全文搜索、版本管理和本地化策略。度量文档效果通过页面浏览量、搜索分析、反馈小组件和激活漏斗转化率来衡量。关键实践包括季度文档审计、示例仓库每周运行持续集成、新功能必须带文档上线。
