测试数据管理

测试数据的挑战

测试数据管理是自动化测试中最容易被忽视、却最常导致测试失败的环节。"测试写好了但数据不对""测试在本地通过但在 CI 上失败""测试之间互相干扰"——这些问题的根源往往都指向测试数据管理的缺失。

数据工厂模式
数据工厂是测试数据管理的最佳实践。它通过编程方式按需生成测试数据，确保每个测试都有独立的、可控的数据环境。


数据工厂的核心原则：






原则
说明





按需创建
每个测试只创建自己需要的数据




最小化数据
只生成测试断言所需的最少字段




自动清理
测试结束后自动清理创建的数据




模板可覆盖
提供合理的默认值，允许测试按需覆盖




关系自动处理
自动创建外键依赖的关联数据

Mock 服务
为什么需要 Mock
在自动化测试中，被测系统通常依赖多个外部服务（支付网关、短信服务、第三方 API 等）。直接调用这些外部服务会带来诸多问题：


Mock 的层次




Mock 层次
说明
工具示例
适用场景





函数级 Mock

Jest.mock、Mockito
单元测试




模块级 Mock
替换整个模块或类
Jest.mock、unittest.mock
单元测试




HTTP 级 Mock
拦截 HTTP 请求返回模拟响应
MSW、WireMock、Nock
集成测试




服务级 Mock
运行独立的模拟服务
WireMock、MockServer
集成/E2E 测试




基础设施 Mock

Mock 最佳实践




原则
说明





只 Mock 边界
Mock 外部系统，不要 Mock 内部实现




保持 Mock 更新
外部 API 变更时同步更新 Mock 响应




Mock 应反映真实行为
包括错误响应、延迟、超时等异常情况




使用契约测试验证 Mock
确保 Mock 行为与真实服务一致




避免过度 Mock
过度 Mock 会降低测试的可信度

测试数据管理成熟度




级别
特征
实践





L1
手工准备数据，无清理策略
数据混乱，测试不可重复




L2
使用 SQL 脚本初始化数据
脚本与测试分离，维护成本高




L3
数据工厂 + 自动清理
测试数据可编程化，基本可重复




L4
容器化环境 + 数据脱敏
完全隔离，接近生产数据质量




L5
数据即代码 + 智能数据生成
数据管理全自动化，覆盖边界场景





测试数据管理是一个需要持续投入的领域。从长远来看，在数据工厂和环境隔离上的投资会通过减少 Flaky 测试和加速问题定位得到数倍回报。
