自动化金字塔

重新审视测试金字塔

测试金字塔最初由 Mike Cohn 在《Succeeding with Agile》一书中提出，它用一个简单而直观的三角形来表达测试策略的核心原则：底层大量快速的单元测试、中层适量的集成测试、顶层少量的端到端测试。这个模型虽然简单，但其背后的设计思想——快速反馈、低维护成本、高置信度——至今仍然是自动化测试架构设计的金标准。

然而，随着微服务架构、前端 SPA、移动应用等技术的发展，经典的三层金字塔已不能完全满足现代软件系统的测试需求。本节将从经典金字塔出发，探讨其现代演进和各层的设计原则。

经典三层金字塔

单元测试层
单元测试是金字塔的基座，占据最大比例。它们验证单个函数、方法或类的行为，不依赖外部系统。

集成测试层
集成测试验证多个组件或服务之间的交互是否正确。它位于金字塔的中间层，是连接单元测试和 E2E 测试的桥梁。

E2E 测试层
E2E 测试从用户视角验证完整的业务流程，它需要完整的系统环境来运行。


E2E 测试的黄金法则：






规则
说明





只测试关键业务路径
不要尝试用 E2E 覆盖所有场景




保持测试独立
每个测试不依赖其他测试的状态




投资于测试稳定性
Flaky 测试会严重损害团队对自动化的信任




合理设置超时
网络延迟等因素需要宽裕的超时时间




使用 API 进行数据准备
不要通过 UI 操作来创建测试前置数据
