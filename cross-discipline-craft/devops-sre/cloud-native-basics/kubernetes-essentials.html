Kubernetes 核心

Kubernetes 是什么

Kubernetes（简称 K8s）是一个开源的容器编排平台，用于自动化容器化应用的部署、扩缩容和管理。它最初由 Google 基于内部 Borg 系统的经验设计，现已成为云原生基础设施的事实标准。

Kubernetes 解决的核心问题：当你有成百上千个容器需要运行时，如何决定它们运行在哪台机器上？如何确保它们始终保持运行？如何让它们相互通信？如何在不中断服务的情况下更新它们？

核心资源
Pod
Pod 是 K8s 中最小的调度和部署单元。一个 Pod 可以包含一个或多个紧密关联的容器，它们共享网络和存储。


apiVersion: v1
kind: Pod
metadata:
  name: web-app
  labels:
    app: web
    version: v1
spec:
  containers:
    - name: app
      image: myapp:1.0.0
      ports:
        - containerPort: 3000
      resources:
        requests:
          cpu: '100m'
          memory: '128Mi'
        limits:
          cpu: '500m'
          memory: '512Mi'
      livenessProbe:
        httpGet:
          path: /healthz
          port: 3000
        initialDelaySeconds: 10
        periodSeconds: 15
      readinessProbe:
        httpGet:
          path: /ready
          port: 3000
        initialDelaySeconds: 5
        periodSeconds: 10

Deployment
Deployment 管理 Pod 的声明式更新，提供滚动更新和回滚能力：


apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: app
          image: myapp:1.0.0
          ports:
            - containerPort: 3000
          resources:
            requests:
              cpu: '100m'
              memory: '128Mi'
            limits:
              cpu: '500m'
              memory: '512Mi'

# 查看部署状态
kubectl rollout status deployment/web-app

# 查看历史版本
kubectl rollout history deployment/web-app

# 回滚到上一个版本
kubectl rollout undo deployment/web-app

# 回滚到指定版本
kubectl rollout undo deployment/web-app --to-revision=2
Service
Service 为一组 Pod 提供稳定的网络访问入口和负载均衡：


apiVersion: v1
kind: Service
metadata:
  name: web-service
spec:
  selector:
    app: web
  type: ClusterIP
  ports:
    - port: 80
      targetPort: 3000
      protocol: TCP

资源管理
Requests 和 Limits




概念
说明
调度影响
运行影响





requests
Pod 运行所需的最小资源
调度器根据 requests 分配节点
保证能获取到的资源量




limits
Pod 可使用的最大资源
不影响调度
超过 CPU 限制会被节流，超过内存限制会被 OOMKilled





QoS 类别
最佳实践：始终为生产 Pod 设置 requests 和 limits。关键服务使用 Guaranteed QoS（requests = limits），非关键服务可以使用 Burstable。

apiVersion: v1
kind: ResourceQuota
metadata:
  name: team-quota
  namespace: team-a
spec:
  hard:
    requests.cpu: '10'
    requests.memory: 20Gi
    limits.cpu: '20'
    limits.memory: 40Gi
    pods: '50'
    services: '10'


小结
Kubernetes 通过声明式 API 管理容器化应用的完整生命周期。理解 Pod、Deployment、Service 和 ConfigMap 这四个核心资源是使用 K8s 的基础。掌握资源管理（requests/limits）、更新策略（RollingUpdate）和探针配置（liveness/readiness）是保障生产环境稳定性的关键。Kubernetes 的学习曲线较陡，建议从单个应用的部署开始，逐步扩展到多服务编排和集群管理。
