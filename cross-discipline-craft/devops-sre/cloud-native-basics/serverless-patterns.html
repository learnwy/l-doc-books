GitOps 与声明式基础设施

什么是 GitOps

GitOps 是一种以 Git 仓库作为唯一事实来源（Single Source of Truth）的运维模式。它将基础设施和应用的期望状态以声明式配置文件的形式存储在 Git 中，通过自动化工具持续将集群的实际状态与 Git 中的期望状态保持同步。

自愈

ArgoCD
ArgoCD 架构
Application 定义
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: web-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/org/gitops-repo.git
    targetRevision: main
    path: apps/web-app/production
  destination:
    server: https://kubernetes.default.svc
    namespace: production
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
      allowEmpty: false
    syncOptions:
      - CreateNamespace=true
    retry:
      limit: 5
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m

Kustomize 实践
Kustomize 是 Kubernetes 原生的配置管理工具，通过叠加（Overlay）的方式管理多环境配置差异：


# base/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - deployment.yaml
  - service.yaml
  - configmap.yaml

# production/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - ../base
patches:
  - path: patches/replicas.yaml
  - path: patches/resources.yaml
images:
  - name: myapp
    newName: registry.example.com/myapp
    newTag: v1.2.3
namespace: production
# production/patches/replicas.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app
spec:
  replicas: 5

# production/patches/resources.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app
spec:
  template:
    spec:
      containers:
        - name: app
          resources:
            requests:
              cpu: "500m"
              memory: "512Mi"
            limits:
              cpu: "1000m"
              memory: "1Gi"

# External Secrets Operator 示例
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: app-secrets
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: aws-secrets-manager
    kind: ClusterSecretStore
  target:
    name: app-secrets
    creationPolicy: Owner
  data:
    - secretKey: DATABASE_URL
      remoteRef:
        key: production/app/database-url
    - secretKey: API_KEY
      remoteRef:
        key: production/app/api-key


常见陷阱




陷阱
说明
避免方法





Git 仓库过大
大量 YAML 文件导致仓库膨胀
使用 Helm Chart 或 Kustomize 减少重复




Secret 泄露
明文 Secret 被提交到 Git
使用 Sealed Secrets 或 External Secrets




循环同步
控制器修改导致 Git 与集群反复不同步
配置忽略规则（ignoreDifferences）




环境差异管理混乱
多环境配置散乱
使用 Kustomize overlay 统一管理




回滚不完整
Git revert 后依赖的基础设施未回滚
将所有依赖纳入 GitOps 管理







小结
GitOps 通过将 Git 作为唯一事实来源，实现了声明式、版本化、自动化和自愈的基础设施管理。ArgoCD 提供了直观的 Web UI 和完善的多集群支持，Flux 则更贴近 Kubernetes 原生设计。选择合适的仓库结构、配置管理工具（Kustomize/Helm）和 Secret 管理方案，是成功实施 GitOps 的关键。GitOps 的核心价值在于：每一次变更都是一个可审计的 Git commit，每一次回滚都是一个简单的 Git revert。
