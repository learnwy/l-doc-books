定义 SLI

什么是 SLI

SLI（Service Level Indicator，服务等级指标）是对服务行为某个方面的定量度量。它是整个 SLI/SLO/SLA 框架的基础——如果无法准确度量服务的表现，就无法设定目标，更无法对外做出承诺。

一个好的 SLI 必须满足以下条件：

要求 说明 正面示例 反面示例
可量化 能用数值表示 请求延迟的 P99 "系统感觉很快"
可观测 能从系统中采集到 Prometheus 指标 无法采集的内部状态
与用户体验相关 反映用户感知的服务质量 页面加载时间 后台 Cron Job CPU 使用率
有明确的好坏标准 能判断是"好的"还是"坏的" 延迟 < 200ms 为好 请求总数（无好坏之分）

SLI 的标准形式

所有 SLI 都可以归纳为一个统一的比率公式：

SLI = 好的事件数 / 总事件数
这种基于比率的 SLI 形式具有重要优势：


    

  • 范围固定：值域在 0% 到 100% 之间
    • 

  • 直觉清晰：99.9% 比 99% 好
    • 

  • 可聚合：多个时间窗口的 SLI 可以合并计算
    • 

  • 与 SLO 对接：SLO 就是对这个比率设定一个目标值
    • 





四大类 SLI
可用性（Availability）
衡量服务是否能够正常响应请求。


可用性 SLI = 成功请求数 / 总请求数

延迟（Latency）
衡量服务处理请求的速度。


延迟 SLI = 延迟低于阈值的请求数 / 总请求数




度量方式
说明
适用场景





P50（中位数）
50% 的请求在此延迟内完成
了解"典型"用户体验




P90
90% 的请求在此延迟内完成
大多数用户的体验




P99
99% 的请求在此延迟内完成
接近最差情况的用户体验




P99.9
99.9% 的请求在此延迟内完成
极端情况





最佳实践：对于面向用户的 API，推荐同时关注 P50 和 P99。P50 反映大多数用户的体验，P99 反映尾部延迟。两者的差异（P99/P50 比值）越大，说明延迟分布越不均匀，需要重点排查。

吞吐量 SLI = 当前处理速率 / 预期处理速率

SLI 选择清单
选择 SLI 时，依次回答以下问题：


    

  1. 用户最关心什么？ — 从用户视角出发，而非从基础设施视角
    2. 

  2. 能否可靠地度量？ — 确保数据采集链路稳定
    3. 

  3. 是否有明确的好坏标准？ — 能清晰定义什么算"好的事件"
    4. 

  4. 是否足够简单？ — 团队每个人都能理解这个指标
    5. 

  5. 是否覆盖了关键路径？ — 不要遗漏核心功能
    6.

最佳实践：优先在负载均衡器或 API 网关层面度量 SLI（最接近用户且数据可靠），同时在服务端补充细粒度度量用于排障。

小结
SLI 是量化服务质量的基石。好的 SLI 遵循"好的事件数 / 总事件数"的统一形式，从用户视角出发，可靠度量、简单明了。可用性、延迟、吞吐量和错误率是四大核心 SLI 类别。选择 SLI 时应根据服务类型和用户关注点来确定优先级，并在尽可能靠近用户的位置进行度量。SLI 定义清晰后，才能在此基础上设定合理的 SLO。
