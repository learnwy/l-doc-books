架构文档标准

架构文档概述

架构文档是将架构知识从架构师的头脑中转移到团队共享认知中的关键载体。好的架构文档不是面面俱到的百科全书，而是精准地回答不同利益相关者最关心的问题。

架构文档面临的核心矛盾是：太少则信息不足，新成员无法理解系统；太多则维护成本过高，文档很快过时。解决这个矛盾的关键是选择正确的文档化方法，并建立可持续的维护机制。

C4 模型

C4 模型简介

C4 模型由 Simon Brown 提出，是一种分层的架构可视化方法。它用四个层次由粗到细地描述系统架构，就像地图从世界地图逐级放大到街景一样。

Level 1: 系统上下文图
系统上下文图展示了系统与外部世界的关系——系统的用户是谁，它与哪些外部系统交互。

Level 3: 组件图
组件图展示一个容器内部的组件构成和交互关系。


Level 4: 代码图
代码图是最底层的视图，展示组件内部的代码结构（类、接口及其关系）。通常只对最关键的组件绘制代码图，而且建议用 IDE 自动生成而非手动维护。

arc42 模板
arc42 简介
arc42 是一个成熟的架构文档模板，由 Gernot Starke 和 Peter Hruschka 创建。它定义了 12 个章节，覆盖了架构文档所需的所有方面。

ADR 记录
ADR 在文档体系中的角色
ADR（Architecture Decision Record）是架构文档中最"活"的部分。C4 图和 arc42 模板描述的是架构的"现状"，而 ADR 记录的是"为什么是现在这个样子"——它保留了架构演化的决策历史。


ADR 的组织管理




管理维度
建议

编号规则

命名格式
{编号}-{简短描述}.md，如 001-use-event-driven-for-orders.md




版本管理
随代码一起版本控制




索引维护

评审流程
新 ADR 通过 Pull Request 评审

本节小结
架构文档的目标不是追求面面俱到，而是用最小的维护成本传递最大的架构知识。C4 模型提供了分层的可视化框架，arc42 模板确保了文档结构的完整性，ADR 保留了决策的历史脉络。"文档即代码"的理念将文档管理融入开发流程，大幅降低了维护成本。记住：最好的架构文档是团队实际在使用的文档——没人看的完美文档不如有人维护的简略文档。
