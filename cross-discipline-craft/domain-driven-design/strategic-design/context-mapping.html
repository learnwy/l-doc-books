上下文映射

核心概念

上下文映射（Context Mapping）描述了不同限界上下文之间的关系和集成方式。如果说限界上下文定义了"边界在哪里"，那么上下文映射回答的是"边界之间如何协作"。

在真实系统中，没有任何一个限界上下文是完全孤立的。订单上下文需要从商品目录获取价格，支付上下文需要从订单上下文获取金额，物流上下文需要从订单上下文获取收货地址。这些跨上下文的交互构成了系统的集成拓扑。

共享内核模式
共享内核（Shared Kernel）是耦合度最高的映射模式。两个上下文共享一小部分模型代码，任何变更都需双方协商一致。


// shared-kernel/user-identity.ts
// 由用户身份上下文和订单上下文共同维护
interface UserId {
  readonly value: string;
}

interface UserBasicInfo {
  readonly id: UserId;
  readonly displayName: string;
  readonly email: Email;
}

// 变更规则：
// 1. 任何对共享内核的修改必须双方团队 Code Review
// 2. 共享内核应尽可能小，只包含真正需要共享的类型
// 3. 使用语义化版本控制共享内核的变更
共享内核适用于两个团队紧密协作、沟通成本低的场景。如果团队之间沟通不畅，共享内核会迅速变成耦合地狱。


关键约束：共享内核的大小应该不超过各上下文模型的 10%。如果共享部分持续增长，说明两个上下文可能应该合并为一个。


客户-供应商与遵奉者模式
客户-供应商（Customer-Supplier）是最常见的上下游关系。上游团队是"供应商"，下游团队是"客户"。双方协商接口，上游需要考虑下游的需求。


// 上游：订单上下文提供订单状态查询接口
// 供应商承诺的契约
interface OrderStatusService {
  getOrderStatus(orderId: string): Promise<OrderStatusDTO>;
  subscribeToStatusChange(orderId: string, callback: StatusChangeHandler): Subscription;
}

interface OrderStatusDTO {
  orderId: string;
  status: 'pending' | 'confirmed' | 'shipped' | 'delivered';
  updatedAt: string;
}

// 下游：物流上下文消费订单状态
// 客户可以要求供应商提供所需的接口形式
class ShippingService {
  constructor(private readonly orderService: OrderStatusService) {}

  async schedulePickup(orderId: string): Promise<PickupSchedule> {
    const status = await this.orderService.getOrderStatus(orderId);
    if (status.status !== 'confirmed') {
      throw new DomainError('Order not ready for shipping');
    }
    return this.createPickupSchedule(orderId);
  }

  private createPickupSchedule(orderId: string): PickupSchedule {
    return { orderId, scheduledAt: new Date(), carrier: 'default' };
  }
}
当下游完全没有话语权时，客户-供应商退化为**遵奉者（Conformist）**模式——下游被迫接受上游的模型，即使它不完全适合自己的领域。

防腐层模式
防腐层（Anti-Corruption Layer, ACL）是保护己方模型不被外部系统污染的关键模式。它在两个上下文之间建立一个翻译层，将外部模型转换为内部模型。


// 外部支付网关的模型（我们无法控制）
interface ExternalPaymentResponse {
  txn_id: string;
  amt: number;
  ccy: string;
  sts: 'S' | 'F' | 'P';
  ts: number;
}

// 我们的领域模型
interface PaymentResult {
  readonly transactionId: TransactionId;
  readonly amount: Money;
  readonly status: PaymentStatus;
  readonly completedAt: Date;
}

type PaymentStatus = 'succeeded' | 'failed' | 'pending';

// 防腐层：翻译外部模型到内部模型
class PaymentGatewayACL {
  translatePaymentResponse(external: ExternalPaymentResponse): PaymentResult {
    return {
      transactionId: TransactionId.create(external.txn_id),
      amount: Money.create(external.amt, external.ccy),
      status: this.mapStatus(external.sts),
      completedAt: new Date(external.ts * 1000),
    };
  }

  private mapStatus(externalStatus: string): PaymentStatus {
    const mapping: Record<string, PaymentStatus> = {
      S: 'succeeded',
      F: 'failed',
      P: 'pending',
    };
    const status = mapping[externalStatus];
    if (!status) throw new Error(`Unknown payment status: ${externalStatus}`);
    return status;
  }
}
防腐层不仅翻译数据格式，还负责协议适配、错误转换和语义映射。它是系统对外集成的防火墙。


开放主机服务与发布语言
开放主机服务（Open Host Service, OHS）定义了一组标准化的协议供多个下游消费。搭配发布语言（Published Language），上游以文档化的标准格式暴露能力。


// 开放主机服务：商品目录上下文提供标准化 API
// 使用 Published Language (JSON Schema / OpenAPI)
interface CatalogOpenHostService {
  searchProducts(query: ProductSearchQuery): Promise<ProductSearchResult>;
  getProductById(id: string): Promise<ProductDTO>;
  getCategories(): Promise<CategoryTree>;
}

interface ProductDTO {
  id: string;
  title: string;
  description: string;
  price: { amount: number; currency: string };
  availability: 'in_stock' | 'out_of_stock' | 'pre_order';
  attributes: Record<string, string>;
}

// 多个下游消费同一份 Published Language
// 订单上下文 → 获取价格和可用性
// 推荐引擎 → 获取商品属性
// 搜索服务 → 获取标题和描述
OHS 与防腐层经常配合使用——上游通过 OHS 暴露标准接口，下游通过 ACL 将标准模型翻译为自己的领域模型。


集成策略选择
选择合适的集成策略需要综合考虑团队关系、技术约束和业务需求。


type IntegrationDecisionFactors = {
  teamRelationship: 'same_team' | 'partner' | 'external_vendor';
  changeFrequency: 'high' | 'medium' | 'low';
  dataConsistencyRequirement: 'strong' | 'eventual';
  latencyRequirement: 'sync' | 'async_acceptable';
};

function chooseIntegrationPattern(factors: IntegrationDecisionFactors): string {
  if (factors.teamRelationship === 'same_team') {
    return 'shared_kernel_or_customer_supplier';
  }
  if (factors.teamRelationship === 'external_vendor') {
    return 'anti_corruption_layer';
  }
  if (factors.dataConsistencyRequirement === 'eventual' && factors.latencyRequirement === 'async_acceptable') {
    return 'domain_events_with_acl';
  }
  return 'customer_supplier_with_ohs';
}

小结
    

  • 上下文映射描述限界上下文之间的关系，是战略设计的集成蓝图
    • 

  • 共享内核耦合度最高，仅适用于紧密协作且共享模型很小的场景
    • 

  • 客户-供应商是最常见的上下游模式，遵奉者是其退化形态
    • 

  • 防腐层是对外集成的核心防线，翻译外部模型以保护内部领域纯洁性
    • 

  • 开放主机服务搭配发布语言，为多下游提供标准化集成接口
    • 

  • 选择集成策略需综合考虑团队关系、一致性要求和延迟容忍度
