领域事件

核心概念

领域事件（Domain Event）是对领域中已经发生的事实的描述。它捕获了业务上有意义的状态变迁，以过去时态命名（如 OrderPlaced、PaymentReceived），代表了不可逆转的业务事实。

领域事件的价值在于解耦。当订单被创建后，需要通知库存扣减、发送确认邮件、更新用户积分。如果这些逻辑全部塞在下单方法中，订单服务将耦合大量无关上下文的逻辑。领域事件让订单上下文只需发出"订单已创建"事件，其他上下文自行订阅和处理。

事件建模
领域事件的建模应该反映业务事实，而非技术操作。事件名称使用过去时态，携带足够的上下文信息让订阅方无需回查源头。


interface DomainEvent {
  readonly eventId: string;
  readonly occurredAt: Date;
  readonly aggregateId: string;
  readonly eventType: string;
}

class OrderPlaced implements DomainEvent {
  readonly eventType = 'OrderPlaced';

  constructor(
    readonly eventId: string,
    readonly occurredAt: Date,
    readonly aggregateId: string,
    readonly customerId: string,
    readonly items: ReadonlyArray<{
      productId: string;
      quantity: number;
      unitPrice: number;
    }>,
    readonly totalAmount: number,
    readonly shippingAddress: {
      province: string;
      city: string;
      street: string;
    },
  ) {}
}

class OrderCancelled implements DomainEvent {
  readonly eventType = 'OrderCancelled';

  constructor(
    readonly eventId: string,
    readonly occurredAt: Date,
    readonly aggregateId: string,
    readonly reason: string,
    readonly cancelledBy: string,
  ) {}
}

class PaymentReceived implements DomainEvent {
  readonly eventType = 'PaymentReceived';

  constructor(
    readonly eventId: string,
    readonly occurredAt: Date,
    readonly aggregateId: string,
    readonly transactionId: string,
    readonly amount: number,
    readonly method: string,
  ) {}
}

聚合内事件发布
在聚合中收集领域事件，在仓储保存后统一发布。这确保了事件只在状态成功持久化后才被分发。


abstract class AggregateRoot {
  private domainEvents: DomainEvent[] = [];

  protected addDomainEvent(event: DomainEvent): void {
    this.domainEvents.push(event);
  }

  pullDomainEvents(): DomainEvent[] {
    const events = [...this.domainEvents];
    this.domainEvents = [];
    return events;
  }
}

class Order extends AggregateRoot {
  private status: OrderStatus = 'draft';

  constructor(
    readonly id: OrderId,
    private readonly customerId: CustomerId,
    private items: OrderLineItem[],
    private shippingAddress: Address,
  ) {
    super();
  }

  submit(): void {
    if (this.items.length === 0) {
      throw new DomainError('Cannot submit empty order');
    }
    this.status = 'submitted';

    this.addDomainEvent(
      new OrderPlaced(
        crypto.randomUUID(),
        new Date(),
        this.id.value,
        this.customerId.value,
        this.items.map((i) => ({
          productId: i.productId.value,
          quantity: i.quantity,
          unitPrice: i.unitPrice.amount,
        })),
        this.totalAmount.amount,
        {
          province: this.shippingAddress.province,
          city: this.shippingAddress.city,
          street: this.shippingAddress.street,
        },
      ),
    );
  }

  cancel(reason: string, cancelledBy: string): void {
    if (this.status === 'cancelled') {
      throw new DomainError('Order already cancelled');
    }
    this.status = 'cancelled';

    this.addDomainEvent(new OrderCancelled(crypto.randomUUID(), new Date(), this.id.value, reason, cancelledBy));
  }

  get totalAmount(): Money {
    return this.items.reduce((sum, item) => sum.add(item.subtotal), Money.create(0, 'CNY'));
  }
}
事件处理与订阅
事件处理器（Event Handler）订阅特定类型的事件并执行响应逻辑。处理器应该是幂等的，因为事件可能被重复投递。


interface EventHandler<T extends DomainEvent> {
  handle(event: T): Promise<void>;
}

class InventoryReservationHandler implements EventHandler<OrderPlaced> {
  constructor(private readonly inventoryService: InventoryService) {}

  async handle(event: OrderPlaced): Promise<void> {
    for (const item of event.items) {
      await this.inventoryService.reserve(item.productId, item.quantity, event.aggregateId);
    }
  }
}

class OrderConfirmationEmailHandler implements EventHandler<OrderPlaced> {
  constructor(private readonly emailService: EmailService) {}

  async handle(event: OrderPlaced): Promise<void> {
    await this.emailService.sendOrderConfirmation(event.customerId, event.aggregateId, event.totalAmount);
  }
}

// 事件分发器
class EventDispatcher {
  private handlers = new Map<string, EventHandler<DomainEvent>[]>();

  register<T extends DomainEvent>(eventType: string, handler: EventHandler<T>): void {
    const existing = this.handlers.get(eventType) ?? [];
    existing.push(handler as EventHandler<DomainEvent>);
    this.handlers.set(eventType, existing);
  }

  async dispatch(event: DomainEvent): Promise<void> {
    const handlers = this.handlers.get(event.eventType) ?? [];
    await Promise.allSettled(handlers.map((h) => h.handle(event)));
  }
}
事件驱动的跨聚合一致性
当一个业务操作需要修改多个聚合时，使用领域事件实现最终一致性，而非分布式事务。


// 场景：订单支付成功后，需要更新订单状态 + 扣减库存 + 发放积分
// 反模式：一个事务中修改三个聚合

//   order.markPaid(); inventory.deduct(); loyalty.addPoints();

// 正确模式：事件驱动的最终一致性
class PaymentApplicationService {
  constructor(
    private readonly orderRepo: OrderRepository,
    private readonly eventDispatcher: EventDispatcher,
  ) {}

  async handlePaymentSuccess(orderId: OrderId, transactionId: string): Promise<void> {
    const order = await this.orderRepo.findById(orderId);
    if (!order) throw new Error('Order not found');

    order.markAsPaid(transactionId);
    await this.orderRepo.save(order);

    const events = order.pullDomainEvents();
    for (const event of events) {
      await this.eventDispatcher.dispatch(event);
    }
  }
}

// NotificationHandler: 订阅 OrderPaid → 发送通知
小结
    

  • 领域事件是对已发生业务事实的描述，使用过去时态命名
    • 

  • 事件携带充足的上下文信息，让订阅方无需回查源聚合
    • 

  • 聚合内收集事件，仓储保存成功后统一分发
    • 

  • 事件处理器必须设计为幂等的，以应对重复投递
    • 

  • 跨聚合的业务一致性通过领域事件实现最终一致性
    • 

  • 领域事件是解耦上下文、实现可扩展架构的核心机制
