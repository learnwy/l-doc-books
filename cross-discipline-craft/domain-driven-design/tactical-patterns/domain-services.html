领域服务

核心概念

领域服务（Domain Service）封装了不自然属于任何单个实体或值对象的领域逻辑。当一个业务操作涉及多个聚合的协调，或者不适合放在某个特定实体上时，领域服务是合适的归属。

区分领域服务和应用服务（Application Service）至关重要：领域服务包含业务规则，属于领域层；应用服务编排工作流程，属于应用层。领域服务回答"业务规则是什么"，应用服务回答"按什么顺序执行"。

何时使用领域服务
领域服务的使用有明确的判断标准。滥用领域服务会导致贫血模型，所有逻辑都从实体中抽离。


// 场景一：操作天然不属于任何实体
// "计算两个地址之间的运费"——这既不是发货地的行为，也不是收货地的行为
class ShippingCostCalculator {
  calculate(from: Address, to: Address, weight: Weight, carrier: CarrierType): Money {
    const distance = this.calculateDistance(from, to);
    const baseRate = this.getBaseRate(carrier);
    const weightSurcharge = this.calculateWeightSurcharge(weight, carrier);
    const distanceCost = baseRate.multiply(distance / 1000);
    return distanceCost.add(weightSurcharge);
  }

  private calculateDistance(from: Address, to: Address): number {
    return 0;
  }

  private getBaseRate(carrier: CarrierType): Money {
    const rates: Record<CarrierType, number> = {
      standard: 5,
      express: 12,
      overnight: 25,
    };
    return Money.create(rates[carrier], 'CNY');
  }

  private calculateWeightSurcharge(weight: Weight, carrier: CarrierType): Money {
    if (weight.kilograms <= 1) return Money.create(0, 'CNY');
    return Money.create((weight.kilograms - 1) * 2, 'CNY');
  }
}

type CarrierType = 'standard' | 'express' | 'overnight';
// 场景二：涉及多个聚合的业务规则
// "转账"涉及两个账户聚合，放在任一账户上都不合适
class TransferService {
  transfer(from: BankAccount, to: BankAccount, amount: Money): TransferResult {
    if (from.id.equals(to.id)) {
      throw new DomainError('Cannot transfer to the same account');
    }
    if (!from.hasSufficientFunds(amount)) {
      return TransferResult.insufficientFunds();
    }

    from.debit(amount);
    to.credit(amount);

    return TransferResult.success(from.id, to.id, amount);
  }
}

// 场景三：需要外部信息参与的业务决策
// "检查用户是否有资格享受折扣"需要查询多种数据
class DiscountEligibilityService {
  constructor(
    private readonly membershipPolicy: MembershipPolicy,
    private readonly promotionRules: PromotionRules,
  ) {}

  checkEligibility(customer: Customer, order: Order, currentPromotions: Promotion[]): DiscountResult {
    const memberDiscount = this.membershipPolicy.getDiscount(customer.memberLevel());
    const promotionDiscount = this.promotionRules.getBestPromotion(order, currentPromotions);

    return DiscountResult.bestOf(memberDiscount, promotionDiscount);
  }
}
领域服务 vs 实体方法
一个常见的错误是将本应属于实体的逻辑放到领域服务中，导致贫血模型。


// 反模式：贫血实体 + 臃肿服务
class Order {
  items: OrderLineItem[] = [];
  status: string = 'draft';
}

class OrderService {
  addItem(order: Order, item: OrderLineItem): void {
    order.items.push(item);
  }

  calculateTotal(order: Order): number {
    return order.items.reduce((sum, item) => sum + item.price * item.quantity, 0);
  }

  canSubmit(order: Order): boolean {
    return order.items.length > 0 && order.status === 'draft';
  }
}

// 正确模式：充血实体 + 精准服务
class Order {
  private items: OrderLineItem[] = [];
  private status: OrderStatus = 'draft';

  addItem(productId: ProductId, quantity: number, unitPrice: Money): void {
    if (this.status !== 'draft') throw new DomainError('Order not editable');
    this.items.push(OrderLineItem.create(productId, quantity, unitPrice));
  }

  get totalAmount(): Money {
    return this.items.reduce((sum, i) => sum.add(i.subtotal), Money.create(0, 'CNY'));
  }

  canSubmit(): boolean {
    return this.items.length > 0 && this.status === 'draft';
  }
}

规格模式
规格模式（Specification Pattern）是一种特殊的领域服务模式，用于封装可组合的业务规则。


interface Specification<T> {
  isSatisfiedBy(candidate: T): boolean;
  and(other: Specification<T>): Specification<T>;
  or(other: Specification<T>): Specification<T>;
  not(): Specification<T>;
}

abstract class CompositeSpecification<T> implements Specification<T> {
  abstract isSatisfiedBy(candidate: T): boolean;

  and(other: Specification<T>): Specification<T> {
    return new AndSpecification(this, other);
  }

  or(other: Specification<T>): Specification<T> {
    return new OrSpecification(this, other);
  }

  not(): Specification<T> {
    return new NotSpecification(this);
  }
}

class AndSpecification<T> extends CompositeSpecification<T> {
  constructor(
    private left: Specification<T>,
    private right: Specification<T>,
  ) {
    super();
  }
  isSatisfiedBy(candidate: T): boolean {
    return this.left.isSatisfiedBy(candidate) && this.right.isSatisfiedBy(candidate);
  }
}

class OrSpecification<T> extends CompositeSpecification<T> {
  constructor(
    private left: Specification<T>,
    private right: Specification<T>,
  ) {
    super();
  }
  isSatisfiedBy(candidate: T): boolean {
    return this.left.isSatisfiedBy(candidate) || this.right.isSatisfiedBy(candidate);
  }
}

class NotSpecification<T> extends CompositeSpecification<T> {
  constructor(private spec: Specification<T>) {
    super();
  }
  isSatisfiedBy(candidate: T): boolean {
    return !this.spec.isSatisfiedBy(candidate);
  }
}

// 具体业务规格
class VIPCustomerSpec extends CompositeSpecification<Customer> {
  isSatisfiedBy(customer: Customer): boolean {
    return customer.memberLevel() === 'vip' || customer.memberLevel() === 'svip';
  }
}

class HighValueOrderSpec extends CompositeSpecification<Order> {
  constructor(private readonly threshold: Money) {
    super();
  }
  isSatisfiedBy(order: Order): boolean {
    return order.totalAmount.isGreaterThan(this.threshold);
  }
}

// 组合使用
const eligibleForPremiumShipping = new VIPCustomerSpec();
const highValueOrder = new HighValueOrderSpec(Money.create(1000, 'CNY'));
小结
    

  • 领域服务封装不属于单个实体的业务逻辑，是领域层的一等公民
    • 

  • 领域服务是无状态的，与有状态的实体形成互补
    • 

  • 区分领域服务和应用服务：前者包含业务规则，后者编排流程
    • 

  • 警惕贫血模型反模式——实体自身的逻辑不应外移到服务中
    • 

  • 规格模式提供了可组合的业务规则封装，适合复杂的条件判断场景
    • 

  • 领域服务应该精准使用，大部分业务逻辑仍应归属于实体和值对象
    •
