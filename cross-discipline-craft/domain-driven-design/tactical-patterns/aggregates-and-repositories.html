聚合与仓储

核心概念

聚合（Aggregate）是一组相关对象的集合，被视为数据修改的基本单元。每个聚合有一个聚合根（Aggregate Root），外部只能通过聚合根访问聚合内部的对象。仓储（Repository）则是聚合的持久化抽象，负责在领域层和基础设施层之间架设桥梁。

聚合解决的核心问题是一致性边界——在一个事务中，哪些对象必须同时保持一致。没有聚合概念时，任何对象都可能引用和修改任何其他对象，导致一致性无法保障。

聚合根与一致性边界
聚合根是聚合的入口点，负责维护整个聚合的业务不变量。所有对聚合内部状态的修改都必须通过聚合根的方法完成。


class Order {
  private readonly items: OrderLineItem[] = [];
  private status: OrderStatus = 'draft';
  private version: number = 0;

  constructor(
    readonly id: OrderId,
    private readonly customerId: CustomerId,
    private shippingAddress: Address,
  ) {}

  addItem(productId: ProductId, quantity: number, unitPrice: Money): void {
    if (this.status !== 'draft') {
      throw new DomainError('Cannot add items to a non-draft order');
    }
    if (quantity <= 0) {
      throw new DomainError('Quantity must be positive');
    }

    const existingItem = this.items.find((item) => item.productId.equals(productId));
    if (existingItem) {
      existingItem.increaseQuantity(quantity);
    } else {
      this.items.push(OrderLineItem.create(productId, quantity, unitPrice));
    }
  }

  removeItem(productId: ProductId): void {
    if (this.status !== 'draft') {
      throw new DomainError('Cannot remove items from a non-draft order');
    }
    const index = this.items.findIndex((item) => item.productId.equals(productId));
    if (index === -1) throw new DomainError('Item not found in order');
    this.items.splice(index, 1);
  }

  submit(): void {
    if (this.items.length === 0) {
      throw new DomainError('Cannot submit an empty order');
    }
    if (this.status !== 'draft') {
      throw new DomainError('Order already submitted');
    }
    this.status = 'submitted';
  }

  get totalAmount(): Money {
    return this.items.reduce((sum, item) => sum.add(item.subtotal), Money.create(0, 'CNY'));
  }
}

聚合的大小设计
聚合应该尽可能小。过大的聚合导致并发冲突、内存压力和事务超时。

仓储模式实现
仓储（Repository）为领域层提供了一个类似集合的接口来访问聚合。它隐藏了底层存储的细节（数据库、文件系统、API 等），让领域逻辑不依赖基础设施。


// 仓储接口定义在领域层
interface OrderRepository {
  findById(id: OrderId): Promise<Order | null>;
  save(order: Order): Promise<void>;
  delete(id: OrderId): Promise<void>;
  findByCustomerId(customerId: CustomerId): Promise<Order[]>;
  nextId(): OrderId;
}

// 仓储实现在基础设施层
class PostgresOrderRepository implements OrderRepository {
  constructor(private readonly db: Database) {}

  async findById(id: OrderId): Promise<Order | null> {
    const row = await this.db.query('SELECT * FROM orders WHERE id = $1', [id.value]);
    if (!row) return null;
    return this.toDomain(row);
  }

  async save(order: Order): Promise<void> {
    const data = this.toPersistence(order);
    await this.db.query(
      `INSERT INTO orders (id, customer_id, status, shipping_address, version)
       VALUES ($1, $2, $3, $4, $5)
       ON CONFLICT (id) DO UPDATE SET
         status = $3, shipping_address = $4, version = $5`,
      [data.id, data.customerId, data.status, data.shippingAddress, data.version],
    );
    await this.saveLineItems(order);
  }

  async delete(id: OrderId): Promise<void> {
    await this.db.query('DELETE FROM orders WHERE id = $1', [id.value]);
  }

  async findByCustomerId(customerId: CustomerId): Promise<Order[]> {
    const rows = await this.db.query('SELECT * FROM orders WHERE customer_id = $1', [customerId.value]);
    return rows.map((row: Record<string, unknown>) => this.toDomain(row));
  }

  nextId(): OrderId {
    return OrderId.generate();
  }

  private toDomain(row: Record<string, unknown>): Order {
    return {} as Order;
  }

  private toPersistence(order: Order): Record<string, unknown> {
    return {};
  }

  private async saveLineItems(order: Order): Promise<void> {}
}

// 实践一：仓储只操作聚合根
// 正确：orderRepository.save(order)
// 错误：orderLineItemRepository.save(lineItem) ← 不应存在

// 实践二：使用乐观锁处理并发
class OptimisticLockingRepository implements OrderRepository {
  async save(order: Order): Promise<void> {
    const result = await this.db.query(
      `UPDATE orders SET status = $1, version = version + 1
       WHERE id = $2 AND version = $3`,
      [order.status, order.id.value, order.version],
    );
    if (result.rowCount === 0) {
      throw new ConcurrencyError('Order was modified by another transaction');
    }
  }

  async findById(id: OrderId): Promise<Order | null> {
    return null;
  }
  async delete(id: OrderId): Promise<void> {}
  async findByCustomerId(customerId: CustomerId): Promise<Order[]> {
    return [];
  }
  nextId(): OrderId {
    return OrderId.generate();
  }
}

// 实践三：仓储返回完整聚合（非部分加载）

小结
    

  • 聚合是一致性边界，聚合根是唯一入口，保护内部不变量
    • 

  • 外部不能直接访问聚合内部对象，所有修改通过聚合根方法
    • 

  • 聚合应尽可能小，跨聚合引用使用 ID 而非对象引用
    • 

  • 仓储为聚合提供集合式的持久化接口，接口定义在领域层
    • 

  • 仓储只操作聚合根级别，不为内部实体创建独立仓储
    • 

  • 复杂查询应分离到独立的查询服务，不应污染仓储接口
    •
