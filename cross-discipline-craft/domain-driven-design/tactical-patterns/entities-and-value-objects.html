实体与值对象

核心概念

实体（Entity）和值对象（Value Object）是领域模型中最基本的两种构造块。它们的根本区别在于身份标识：实体通过唯一标识符来区分，即使所有属性相同，两个不同 ID 的实体也是不同的；值对象通过结构相等性来比较，没有独立的身份标识，属性完全相同的两个值对象就是同一个。

一个直观的例子：两个同名同年龄的"用户"仍然是不同的用户（实体），但两个面值相同的"100 元人民币"是可以互换的（值对象）。

实体的身份标识设计
实体的核心是身份标识。标识策略的选择直接影响系统的可维护性和可扩展性。


// 策略一：自然键 —— 使用业务含义的唯一标识
class Employee {
  constructor(
    readonly employeeId: EmployeeId, // 工号 EMP-2024-001
    private name: string,
    private department: Department,
  ) {}
}

// 策略二：代理键 —— 使用系统生成的无业务含义标识
class Order {
  constructor(
    readonly id: OrderId, // UUID 或雪花 ID
    private items: OrderLineItem[],
    private status: OrderStatus,
  ) {}
}

// 推荐：使用类型化的标识符（避免原始类型偏执）
class OrderId {
  private constructor(readonly value: string) {}

  static create(value: string): OrderId {
    if (!value || value.trim().length === 0) {
      throw new Error('OrderId cannot be empty');
    }
    return new OrderId(value);
  }

  static generate(): OrderId {
    return new OrderId(crypto.randomUUID());
  }

  equals(other: OrderId): boolean {
    return this.value === other.value;
  }
}

// 类型化 ID 防止参数混淆
function transferOrder(fromUserId: UserId, toUserId: UserId, orderId: OrderId): void {
  // 编译器阻止 transferOrder(orderId, userId, userId) 这样的错误
}
实体的相等性基于 ID 而非属性：


class Entity<TId> {
  constructor(readonly id: TId) {}

  equals(other: Entity<TId>): boolean {
    if (other === null || other === undefined) return false;
    if (this === other) return true;
    return JSON.stringify(this.id) === JSON.stringify(other.id);
  }
}
值对象的不可变性
值对象的核心特征是不可变性。一旦创建，值对象的任何属性都不能被修改。如果需要不同的值，创建一个新的值对象来替换。


class Money {
  private constructor(
    readonly amount: number,
    readonly currency: string,
  ) {}

  static create(amount: number, currency: string): Money {
    if (amount < 0) throw new Error('Amount cannot be negative');
    if (!currency || currency.length !== 3) throw new Error('Invalid currency code');
    return new Money(amount, currency);
  }

  add(other: Money): Money {
    this.ensureSameCurrency(other);
    return Money.create(this.amount + other.amount, this.currency);
  }

  subtract(other: Money): Money {
    this.ensureSameCurrency(other);
    return Money.create(this.amount - other.amount, this.currency);
  }

  multiply(factor: number): Money {
    return Money.create(this.amount * factor, this.currency);
  }

  isGreaterThan(other: Money): boolean {
    this.ensureSameCurrency(other);
    return this.amount > other.amount;
  }

  equals(other: Money): boolean {
    return this.amount === other.amount && this.currency === other.currency;
  }

  private ensureSameCurrency(other: Money): void {
    if (this.currency !== other.currency) {
      throw new Error(`Currency mismatch: ${this.currency} vs ${other.currency}`);
    }
  }
}

// 使用：不修改原对象，而是创建新对象
const price = Money.create(100, 'CNY');
const discountedPrice = price.multiply(0.8); // 新对象，price 不变
值对象的丰富行为
值对象不仅仅是数据容器。好的值对象封装了领域规则和业务行为，避免了"原始类型偏执"（Primitive Obsession）。


class EmailAddress {
  private constructor(readonly value: string) {}

  static create(raw: string): EmailAddress {
    const normalized = raw.trim().toLowerCase();
    if (!EmailAddress.isValid(normalized)) {
      throw new Error(`Invalid email: ${raw}`);
    }
    return new EmailAddress(normalized);
  }

  private static isValid(email: string): boolean {
    return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
  }

  get domain(): string {
    return this.value.split('@')[1];
  }

  equals(other: EmailAddress): boolean {
    return this.value === other.value;
  }
}

class DateRange {
  private constructor(
    readonly start: Date,
    readonly end: Date,
  ) {}

  static create(start: Date, end: Date): DateRange {
    if (start >= end) throw new Error('Start must be before end');
    return new DateRange(start, end);
  }

  contains(date: Date): boolean {
    return date >= this.start && date <= this.end;
  }

  overlaps(other: DateRange): boolean {
    return this.start < other.end && other.start < this.end;
  }

  get durationInDays(): number {
    return Math.ceil((this.end.getTime() - this.start.getTime()) / (1000 * 60 * 60 * 24));
  }

  equals(other: DateRange): boolean {
    return this.start.getTime() === other.start.getTime() && this.end.getTime() === other.end.getTime();
  }
}

class Address {
  private constructor(
    readonly province: string,
    readonly city: string,
    readonly district: string,
    readonly street: string,
    readonly postalCode: string,
  ) {}

  static create(props: {
    province: string;
    city: string;
    district: string;
    street: string;
    postalCode: string;
  }): Address {
    return new Address(props.province, props.city, props.district, props.street, props.postalCode);
  }

  get fullAddress(): string {
    return `${this.province}${this.city}${this.district}${this.street}`;
  }

  equals(other: Address): boolean {
    return this.fullAddress === other.fullAddress && this.postalCode === other.postalCode;
  }
}
实体与值对象的选择决策
判断一个概念应该建模为实体还是值对象，需要回到业务上下文中思考。同一个概念在不同上下文中可能有不同的建模方式。


// "地址"在不同上下文中的建模
// 物流上下文：地址需要独立追踪和验证 → 实体
class ShippingAddress {
  constructor(
    readonly id: AddressId,
    private street: string,
    private verified: boolean,
    private geocode: GeoCoordinate,
  ) {}

  verify(geocode: GeoCoordinate): void {
    this.geocode = geocode;
    this.verified = true;
  }
}

// 订单上下文：地址只是订单的一个属性快照 → 值对象
class OrderAddress {
  private constructor(
    readonly province: string,
    readonly city: string,
    readonly street: string,
  ) {}

  static fromShipping(address: { province: string; city: string; street: string }): OrderAddress {
    return new OrderAddress(address.province, address.city, address.street);
  }

  equals(other: OrderAddress): boolean {
    return this.province === other.province && this.city === other.city && this.street === other.street;
  }
}

回答"是" → 实体
回答"否" → 值对象





需要在整个生命周期中追踪它吗？
用户、订单
金额、颜色

两个同名用户
两个 100 元

商品可被多个订单引用
地址通常嵌入订单

订单状态变更
金额计算产生新值





小结
    

  • 实体通过唯一标识符区分，值对象通过结构相等性比较
    • 

  • 值对象是不可变的，任何变更都产生新实例
    • 

  • 使用类型化 ID 替代原始字符串，利用编译器防止参数混淆
    • 

  • 好的值对象不仅承载数据，还封装领域规则和业务行为
    • 

  • 同一概念在不同上下文中可能建模为实体或值对象
    • 

  • 实践中应优先考虑值对象——大多数领域概念不需要独立身份标识
    •
