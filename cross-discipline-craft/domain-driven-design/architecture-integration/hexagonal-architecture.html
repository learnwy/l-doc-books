六边形架构

核心概念

六边形架构（Hexagonal Architecture），也称为端口与适配器架构（Ports and Adapters），由 Alistair Cockburn 提出。它的核心思想是将应用程序的业务逻辑与外部世界完全隔离——所有外部交互（数据库、API、UI、消息队列）都通过明确定义的端口（Port）和适配器（Adapter）接入。

这种架构与 DDD 天然契合：领域模型位于六边形的中心，不依赖任何外部技术。技术选型的变更（更换数据库、切换消息中间件）只影响适配器层，不触及核心领域逻辑。

端口定义
端口（Port）是应用程序与外部世界交互的抽象接口。分为两类：驱动端口（Driving Port）定义应用提供的能力，被驱动端口（Driven Port）定义应用需要的外部能力。


// 驱动端口：定义应用对外提供的能力（左侧端口）
// 外部世界通过这些端口驱动应用
interface OrderManagementPort {
  placeOrder(command: PlaceOrderCommand): Promise<OrderId>;
  cancelOrder(command: CancelOrderCommand): Promise<void>;
  getOrderStatus(orderId: string): Promise<OrderStatusDTO>;
}

interface PlaceOrderCommand {
  customerId: string;
  items: Array<{ productId: string; quantity: number }>;
  shippingAddress: {
    province: string;
    city: string;
    street: string;
  };
}

// 被驱动端口：定义应用需要的外部能力（右侧端口）
// 应用通过这些端口驱动外部世界
interface OrderPersistencePort {
  findById(id: OrderId): Promise<Order | null>;
  save(order: Order): Promise<void>;
}

interface ProductCatalogPort {
  getProductPrice(productId: string): Promise<Money>;
  checkAvailability(productId: string, quantity: number): Promise<boolean>;
}

interface NotificationPort {
  sendOrderConfirmation(customerId: string, orderId: string): Promise<void>;
}
适配器实现
适配器（Adapter）是端口的具体实现。驱动适配器将外部请求翻译为端口调用，被驱动适配器将端口调用翻译为外部系统操作。


// 驱动适配器：HTTP REST → 驱动端口
class OrderHttpAdapter {
  constructor(private readonly orderService: OrderManagementPort) {}

  async handlePlaceOrder(req: HttpRequest): Promise<HttpResponse> {
    const command: PlaceOrderCommand = {
      customerId: req.body.customerId,
      items: req.body.items,
      shippingAddress: req.body.shippingAddress,
    };

    const orderId = await this.orderService.placeOrder(command);
    return { status: 201, body: { orderId: orderId.value } };
  }

  async handleCancelOrder(req: HttpRequest): Promise<HttpResponse> {
    await this.orderService.cancelOrder({
      orderId: req.params.orderId,
      reason: req.body.reason,
    });
    return { status: 204, body: null };
  }
}

// 被驱动适配器：被驱动端口 → PostgreSQL
class PostgresOrderAdapter implements OrderPersistencePort {
  constructor(private readonly db: Database) {}

  async findById(id: OrderId): Promise<Order | null> {
    const row = await this.db.query('SELECT * FROM orders WHERE id = $1', [id.value]);
    return row ? this.mapToDomain(row) : null;
  }

  async save(order: Order): Promise<void> {
    await this.db.query(
      'INSERT INTO orders (id, data, version) VALUES ($1, $2, $3) ON CONFLICT (id) DO UPDATE SET data = $2, version = $3',
      [order.id.value, JSON.stringify(order), order.version],
    );
  }

  private mapToDomain(row: Record<string, unknown>): Order {
    return {} as Order;
  }
}

// 被驱动适配器：被驱动端口 → 外部 API
class ExternalProductCatalogAdapter implements ProductCatalogPort {
  constructor(private readonly httpClient: HttpClient) {}

  async getProductPrice(productId: string): Promise<Money> {
    const response = await this.httpClient.get(`/products/${productId}`);
    return Money.create(response.price, response.currency);
  }

  async checkAvailability(productId: string, quantity: number): Promise<boolean> {
    const response = await this.httpClient.get(`/products/${productId}/stock`);
    return response.available >= quantity;
  }
}
依赖反转与可测试性
六边形架构的核心优势是通过依赖反转实现极高的可测试性。应用服务依赖端口接口而非具体实现，测试时可以轻松替换为内存实现。


// 应用服务：只依赖端口接口
class OrderApplicationService implements OrderManagementPort {
  constructor(
    private readonly orderRepo: OrderPersistencePort,
    private readonly catalog: ProductCatalogPort,
    private readonly notification: NotificationPort,
  ) {}

  async placeOrder(command: PlaceOrderCommand): Promise<OrderId> {
    const orderId = OrderId.generate();
    const order = new Order(orderId, CustomerId.create(command.customerId));

    for (const item of command.items) {
      const available = await this.catalog.checkAvailability(item.productId, item.quantity);
      if (!available) throw new Error(`Product ${item.productId} out of stock`);
      const price = await this.catalog.getProductPrice(item.productId);
      order.addItem(ProductId.create(item.productId), item.quantity, price);
    }

    order.submit();
    await this.orderRepo.save(order);
    await this.notification.sendOrderConfirmation(command.customerId, orderId.value);
    return orderId;
  }

  async cancelOrder(command: CancelOrderCommand): Promise<void> {
    const order = await this.orderRepo.findById(OrderId.create(command.orderId));
    if (!order) throw new Error('Order not found');
    order.cancel(command.reason, 'system');
    await this.orderRepo.save(order);
  }

  async getOrderStatus(orderId: string): Promise<OrderStatusDTO> {
    return {} as OrderStatusDTO;
  }
}

// 测试：使用内存适配器，无需真实数据库或外部服务
class InMemoryOrderAdapter implements OrderPersistencePort {
  private orders = new Map<string, Order>();

  async findById(id: OrderId): Promise<Order | null> {
    return this.orders.get(id.value) ?? null;
  }

  async save(order: Order): Promise<void> {
    this.orders.set(order.id.value, order);
  }
}

class StubProductCatalogAdapter implements ProductCatalogPort {
  async getProductPrice(): Promise<Money> {
    return Money.create(100, 'CNY');
  }
  async checkAvailability(): Promise<boolean> {
    return true;
  }
}

class SpyNotificationAdapter implements NotificationPort {
  sentNotifications: Array<{ customerId: string; orderId: string }> = [];
  async sendOrderConfirmation(customerId: string, orderId: string): Promise<void> {
    this.sentNotifications.push({ customerId, orderId });
  }
}
组装与依赖注入
六边形架构需要在组合根（Composition Root）中将所有端口和适配器组装起来。


// 组合根：应用启动时组装依赖
function createApplication(config: AppConfig): OrderManagementPort {
  const db = new Database(config.databaseUrl);
  const httpClient = new HttpClient(config.catalogApiUrl);

  const orderRepo = new PostgresOrderAdapter(db);
  const catalog = new ExternalProductCatalogAdapter(httpClient);
  const notification = new EmailNotificationAdapter(config.smtpConfig);

  return new OrderApplicationService(orderRepo, catalog, notification);
}

// 测试时的组装
function createTestApplication(): {
  service: OrderManagementPort;
  notificationSpy: SpyNotificationAdapter;
} {
  const orderRepo = new InMemoryOrderAdapter();
  const catalog = new StubProductCatalogAdapter();
  const notificationSpy = new SpyNotificationAdapter();

  const service = new OrderApplicationService(orderRepo, catalog, notificationSpy);
  return { service, notificationSpy };
}

小结
    

  • 六边形架构将领域逻辑置于中心，所有外部交互通过端口和适配器接入
    • 

  • 驱动端口定义应用提供的能力，被驱动端口定义应用需要的外部能力
    • 

  • 依赖反转确保领域层不依赖任何外部技术实现
    • 

  • 测试时用内存适配器替换真实适配器，无需数据库或外部服务
    • 

  • 技术选型变更只影响适配器层，核心领域逻辑完全不受影响
    • 

  • 六边形架构与 DDD 天然契合，是实现领域模型隔离的理想架构模式
