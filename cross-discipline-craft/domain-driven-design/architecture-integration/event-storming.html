事件风暴

核心概念

事件风暴（Event Storming）是由 Alberto Brandolini 发明的一种协作式建模工作坊。它通过在大面积墙上粘贴彩色便利贴，让领域专家和开发者共同发现业务事件、命令、聚合和策略，从而快速建立对复杂业务领域的共同理解。

事件风暴不是写代码，而是在写代码之前确保所有人对业务有一致的理解。它是连接"业务需求"和"DDD 模型设计"的桥梁，其产出直接映射为限界上下文、聚合和领域事件。





便利贴颜色
含义
示例





🟧 橙色
领域事件（已发生的事实）
订单已创建、支付已完成




🟦 蓝色
命令（触发事件的动作）
创建订单、确认支付




🟨 黄色
聚合（处理命令的实体）
订单、支付、库存




🟪 紫色
策略/业务规则
VIP 满减规则、库存预警




🟩 绿色
读模型/视图
订单列表、仪表盘




🟥 红色
热点/问题/疑问
并发冲突、边界不清




🩷 粉色
外部系统
支付网关、物流API




🧑 小人贴
角色/用户
买家、卖家、管理员





工作坊流程
事件风暴工作坊通常分为四个阶段，每个阶段逐步深入。

第四阶段：识别限界上下文


通过观察聚合之间的关系和语言边界，划分出限界上下文。


从事件风暴到代码
事件风暴的产出可以直接映射为 DDD 的战术模式代码。


// 事件风暴产出 → 代码映射

// 🟨 黄色便利贴 "订单" → 聚合根
class Order extends AggregateRoot {
  private status: OrderStatus;
  private items: OrderLineItem[];
  private payment: PaymentReference | null;

  // 🟦 蓝色便利贴 "创建订单" → 聚合方法
  static create(id: OrderId, customerId: CustomerId, items: OrderLineItem[]): Order {
    const order = new Order(id, customerId, items);
    // 🟧 橙色便利贴 "订单已创建" → 领域事件
    order.addDomainEvent(new OrderCreated(id.value, customerId.value, new Date()));
    return order;
  }

  // 🟦 "确认支付" → 聚合方法
  confirmPayment(paymentId: PaymentId, amount: Money): void {
    if (!this.totalAmount.equals(amount)) {
      throw new DomainError('Payment amount mismatch');
    }
    this.payment = PaymentReference.create(paymentId);
    this.status = 'paid';
    // 🟧 "支付已确认" → 领域事件
    this.addDomainEvent(new OrderPaymentConfirmed(this.id.value, paymentId.value, new Date()));
  }

  // 🟦 "申请退款" → 聚合方法
  requestRefund(reason: string): void {
    if (this.status !== 'paid' && this.status !== 'shipped') {
      throw new DomainError('Cannot refund in current status');
    }
    this.status = 'refund_requested';
    // 🟧 "退款已申请" → 领域事件
    this.addDomainEvent(new RefundRequested(this.id.value, reason, new Date()));
  }

  constructor(
    readonly id: OrderId,
    private readonly customerId: CustomerId,
    items: OrderLineItem[],
  ) {
    super();
    this.items = items;
    this.status = 'created';
    this.payment = null;
  }

  get totalAmount(): Money {
    return this.items.reduce((sum, i) => sum.add(i.subtotal), Money.create(0, 'CNY'));
  }
}

// 🟪 紫色便利贴 "库存预检查" → 领域服务或策略
class InventoryCheckPolicy {
  constructor(private readonly inventoryPort: InventoryPort) {}

  async verify(items: Array<{ productId: string; quantity: number }>): Promise<boolean> {
    for (const item of items) {
      const available = await this.inventoryPort.checkStock(item.productId);
      if (available < item.quantity) return false;
    }
    return true;
  }
}
限界上下文的发现
事件风暴最有价值的产出之一是自然浮现的限界上下文边界。


识别上下文边界的信号：


type ContextBoundarySignals = {
  languageShift: boolean; // 同一术语含义变化
  ownershipChange: boolean; // 负责的角色/团队变化

小结
    

  • 事件风暴是连接业务需求和 DDD 模型设计的协作式工作坊
    • 

  • 通过彩色便利贴在墙上建模，降低参与门槛，让非技术人员也能贡献
    • 

  • 四阶段流程：事件发现 → 时间线排序 → 命令与聚合 → 上下文边界
    • 

  • 产出直接映射为代码：橙色事件 → DomainEvent，蓝色命令 → 聚合方法
    • 

  • 自然浮现的上下文边界是事件风暴最有价值的发现
    • 

  • 领域专家的深度参与是工作坊成功的关键前提
