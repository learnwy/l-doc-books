CQRS 集成

核心概念

CQRS（Command Query Responsibility Segregation，命令查询职责分离）将系统的读操作和写操作分离到不同的模型中。写模型（Command Model）负责处理业务命令，维护领域不变量；读模型（Query Model）针对查询场景优化，提供高效的数据展示。

CQRS 与 DDD 的结合点在于：DDD 的聚合和领域事件自然构成了写模型，而读模型可以基于领域事件异步构建，专门为 UI 需求优化。这解决了"用 DDD 写入很优雅但查询很痛苦"的矛盾。

命令端设计
命令端（Command Side）使用 DDD 的聚合模型处理所有状态变更。命令是一个意图明确的请求，由命令处理器执行。


// 命令定义
interface Command {
  readonly type: string;
}

class PlaceOrderCommand implements Command {
  readonly type = 'PlaceOrder';
  constructor(
    readonly customerId: string,
    readonly items: Array<{ productId: string; quantity: number }>,
    readonly shippingAddress: { province: string; city: string; street: string },
  ) {}
}

class CancelOrderCommand implements Command {
  readonly type = 'CancelOrder';
  constructor(
    readonly orderId: string,
    readonly reason: string,
  ) {}
}

// 命令处理器
class PlaceOrderHandler {
  constructor(
    private readonly orderRepo: OrderRepository,
    private readonly catalog: ProductCatalogPort,
    private readonly eventBus: EventBus,
  ) {}

  async execute(command: PlaceOrderCommand): Promise<OrderId> {
    const orderId = this.orderRepo.nextId();
    const order = new Order(orderId, CustomerId.create(command.customerId));

    for (const item of command.items) {
      const price = await this.catalog.getProductPrice(item.productId);
      order.addItem(ProductId.create(item.productId), item.quantity, price);
    }

    order.submit();
    await this.orderRepo.save(order);

    const events = order.pullDomainEvents();
    await this.eventBus.publishAll(events);

    return orderId;
  }
}

// 命令总线
class CommandBus {
  private handlers = new Map<string, (cmd: Command) => Promise<unknown>>();

  register<T extends Command>(type: string, handler: (cmd: T) => Promise<unknown>): void {
    this.handlers.set(type, handler as (cmd: Command) => Promise<unknown>);
  }

  async dispatch(command: Command): Promise<unknown> {
    const handler = this.handlers.get(command.type);
    if (!handler) throw new Error(`No handler for command: ${command.type}`);
    return handler(command);
  }
}
查询端设计
查询端（Query Side）使用专门的读模型，完全独立于聚合。读模型可以是扁平的 DTO、预计算的视图，甚至是搜索引擎索引。


// 查询定义
interface Query {
  readonly type: string;
}

class GetOrderDetailsQuery implements Query {
  readonly type = 'GetOrderDetails';
  constructor(readonly orderId: string) {}
}

class ListCustomerOrdersQuery implements Query {
  readonly type = 'ListCustomerOrders';
  constructor(
    readonly customerId: string,
    readonly page: number,
    readonly pageSize: number,
  ) {}
}

// 读模型 DTO —— 专门为 UI 优化
interface OrderDetailsView {
  orderId: string;
  customerName: string;
  status: string;
  items: Array<{
    productName: string;
    quantity: number;
    unitPrice: number;
    subtotal: number;
  }>;
  totalAmount: number;
  shippingAddress: string;
  createdAt: string;
  lastUpdatedAt: string;
}

interface OrderListItemView {
  orderId: string;
  status: string;
  itemCount: number;
  totalAmount: number;
  createdAt: string;
}

// 查询处理器 —— 直接查询读数据库
class GetOrderDetailsHandler {
  constructor(private readonly readDb: ReadDatabase) {}

  async execute(query: GetOrderDetailsQuery): Promise<OrderDetailsView | null> {
    return this.readDb.query<OrderDetailsView>('SELECT * FROM order_details_view WHERE order_id = $1', [query.orderId]);
  }
}

class ListCustomerOrdersHandler {
  constructor(private readonly readDb: ReadDatabase) {}

  async execute(query: ListCustomerOrdersQuery): Promise<OrderListItemView[]> {
    const offset = (query.page - 1) * query.pageSize;
    return this.readDb.query<OrderListItemView[]>(
      'SELECT * FROM order_list_view WHERE customer_id = $1 ORDER BY created_at DESC LIMIT $2 OFFSET $3',
      [query.customerId, query.pageSize, offset],
    );
  }
}
事件投影：连接读写模型
读模型通过订阅领域事件来构建和更新。这个过程称为"投影"（Projection），将事件流转化为查询优化的视图。


// 投影器：将领域事件转化为读模型更新
class OrderDetailsProjection {
  constructor(private readonly readDb: ReadDatabase) {}

  async handleOrderPlaced(event: OrderPlaced): Promise<void> {
    await this.readDb.execute(
      `INSERT INTO order_details_view
       (order_id, customer_id, status, total_amount, shipping_address, created_at)
       VALUES ($1, $2, $3, $4, $5, $6)`,
      [
        event.aggregateId,
        event.customerId,
        'submitted',
        event.totalAmount,
        JSON.stringify(event.shippingAddress),
        event.occurredAt.toISOString(),
      ],
    );

    for (const item of event.items) {
      await this.readDb.execute(
        `INSERT INTO order_items_view (order_id, product_id, quantity, unit_price, subtotal)
         VALUES ($1, $2, $3, $4, $5)`,
        [event.aggregateId, item.productId, item.quantity, item.unitPrice, item.quantity * item.unitPrice],
      );
    }
  }

  async handleOrderCancelled(event: OrderCancelled): Promise<void> {
    await this.readDb.execute('UPDATE order_details_view SET status = $1, last_updated_at = $2 WHERE order_id = $3', [
      'cancelled',
      event.occurredAt.toISOString(),
      event.aggregateId,
    ]);
  }

  async handlePaymentReceived(event: PaymentReceived): Promise<void> {
    await this.readDb.execute(
      'UPDATE order_details_view SET status = $1, payment_method = $2, last_updated_at = $3 WHERE order_id = $4',
      ['paid', event.method, event.occurredAt.toISOString(), event.aggregateId],
    );
  }
}
CQRS 的适用场景与权衡
CQRS 增加了系统复杂度，不是所有系统都需要它。


type CQRSDecisionFactors = {
  readWriteRatio: 'read_heavy' | 'balanced' | 'write_heavy';
  queryComplexity: 'simple' | 'complex_joins' | 'aggregation_heavy';
  scalingNeeds: 'uniform' | 'independent';
  consistencyRequirement: 'strong' | 'eventual_acceptable';
  teamSize: 'small' | 'medium' | 'large';
};

function shouldUseCQRS(factors: CQRSDecisionFactors): boolean {
  if (factors.readWriteRatio === 'balanced' && factors.queryComplexity === 'simple') {
    return false;
  }
  if (factors.consistencyRequirement === 'strong' && factors.teamSize === 'small') {
    return false;
  }
  return (
    factors.readWriteRatio === 'read_heavy' ||
    factors.queryComplexity === 'aggregation_heavy' ||
    factors.scalingNeeds === 'independent'
  );
}

不适用场景

小结
    

  • CQRS 将读写操作分离到不同模型，写模型用 DDD 聚合，读模型针对查询优化
    • 

  • 命令处理器执行业务逻辑并发布领域事件，查询处理器直接查询读数据库
    • 

  • 事件投影将领域事件转化为读模型更新，实现读写模型的最终一致性
    • 

  • CQRS 适合读写比例不对称、查询复杂度高的系统
    • 

  • 简单 CRUD 应用不需要 CQRS，过度设计带来的复杂度超过收益
    • 

  • CQRS 与 DDD 天然互补：聚合保护写入一致性，读模型自由优化展示
    •
