TypeScript 中的 DDD

核心概念

TypeScript 的类型系统为领域驱动设计提供了强大的建模工具。联合类型、品牌类型（Branded Types）、只读属性和类型守卫使得领域概念可以直接编码到类型系统中，让编译器成为领域规则的守护者。

与 Java/C# 等传统 OOP 语言不同，TypeScript 的结构类型系统和函数式特性使 DDD 实现更加灵活——既可以用类实现经典的聚合模式，也可以用纯函数和不可变数据结构实现函数式 DDD。

品牌类型与类型安全 ID
品牌类型（Branded Types）让 TypeScript 在编译期区分结构相同但语义不同的类型，完全没有运行时开销。


type Brand<T, B extends string> = T & { readonly __brand: B };

type OrderId = Brand<string, 'OrderId'>;
type CustomerId = Brand<string, 'CustomerId'>;
type ProductId = Brand<string, 'ProductId'>;

function createOrderId(value: string): OrderId {
  if (!value || value.trim().length === 0) {
    throw new Error('OrderId cannot be empty');
  }
  return value as OrderId;
}

function createCustomerId(value: string): CustomerId {
  return value as CustomerId;
}

function findOrder(orderId: OrderId): void {}
function findCustomer(customerId: CustomerId): void {}

const orderId = createOrderId('ord-123');
const customerId = createCustomerId('cust-456');

findOrder(orderId); // ✅ 编译通过
// findOrder(customerId); // ❌ 编译报错：类型不兼容
// findOrder("raw-str");  // ❌ 编译报错：string 不能赋值给 OrderId
对于更丰富的行为，可以使用类包装：


class Money {
  private constructor(
    readonly amount: number,
    readonly currency: string,
  ) {
    Object.freeze(this);
  }

  static of(amount: number, currency: string): Money {
    if (!Number.isFinite(amount)) throw new Error('Invalid amount');
    if (currency.length !== 3) throw new Error('Currency must be ISO 4217');
    return new Money(Math.round(amount * 100) / 100, currency.toUpperCase());
  }

  add(other: Money): Money {
    this.assertSameCurrency(other);
    return Money.of(this.amount + other.amount, this.currency);
  }

  multiply(factor: number): Money {
    return Money.of(this.amount * factor, this.currency);
  }

  isGreaterThan(other: Money): boolean {
    this.assertSameCurrency(other);
    return this.amount > other.amount;
  }

  equals(other: Money): boolean {
    return this.amount === other.amount && this.currency === other.currency;
  }

  private assertSameCurrency(other: Money): void {
    if (this.currency !== other.currency) {
      throw new Error(`Currency mismatch: ${this.currency} vs ${other.currency}`);
    }
  }
}
联合类型与状态机建模
TypeScript 的判别联合类型（Discriminated Union）是建模领域状态机的利器。编译器会强制穷举所有状态分支。


type OrderState =
  | { status: 'draft'; items: OrderLineItem[] }
  | { status: 'submitted'; items: OrderLineItem[]; submittedAt: Date }
  | { status: 'paid'; items: OrderLineItem[]; submittedAt: Date; paidAt: Date; transactionId: string }
  | { status: 'shipped'; items: OrderLineItem[]; submittedAt: Date; paidAt: Date; trackingNumber: string }
  | { status: 'cancelled'; reason: string; cancelledAt: Date };

function submitOrder(state: Extract<OrderState, { status: 'draft' }>): Extract<OrderState, { status: 'submitted' }> {
  if (state.items.length === 0) throw new Error('Cannot submit empty order');
  return {
    status: 'submitted',
    items: state.items,
    submittedAt: new Date(),
  };
}

function confirmPayment(
  state: Extract<OrderState, { status: 'submitted' }>,
  transactionId: string,
): Extract<OrderState, { status: 'paid' }> {
  return {
    status: 'paid',
    items: state.items,
    submittedAt: state.submittedAt,
    paidAt: new Date(),
    transactionId,
  };
}

function getOrderSummary(state: OrderState): string {
  switch (state.status) {
    case 'draft':
      return `草稿订单，${state.items.length} 个商品`;
    case 'submitted':
      return `已提交，等待支付`;
    case 'paid':
      return `已支付，交易号 ${state.transactionId}`;
    case 'shipped':
      return `已发货，快递号 ${state.trackingNumber}`;
    case 'cancelled':
      return `已取消：${state.reason}`;
  }
}
仓储封装与依赖反转
TypeScript 的接口和泛型为仓储模式提供了优雅的抽象。


interface Repository<T, TId> {
  findById(id: TId): Promise<T | null>;
  save(entity: T): Promise<void>;
  delete(id: TId): Promise<void>;
}

interface OrderRepository extends Repository<Order, OrderId> {
  findByCustomerId(customerId: CustomerId): Promise<Order[]>;
  findByStatus(status: string): Promise<Order[]>;
}

class InMemoryOrderRepository implements OrderRepository {
  private store = new Map<string, Order>();

  async findById(id: OrderId): Promise<Order | null> {
    return this.store.get(id as string) ?? null;
  }

  async save(order: Order): Promise<void> {
    this.store.set(order.id as string, order);
  }

  async delete(id: OrderId): Promise<void> {
    this.store.delete(id as string);
  }

  async findByCustomerId(customerId: CustomerId): Promise<Order[]> {
    return [...this.store.values()].filter((o) => o.customerId === customerId);
  }

  async findByStatus(status: string): Promise<Order[]> {
    return [...this.store.values()].filter((o) => o.status === status);
  }
}
领域事件的类型安全实现
利用判别联合类型实现类型安全的事件系统。


type DomainEvent =
  | { type: 'OrderCreated'; orderId: string; customerId: string; occurredAt: Date }
  | { type: 'OrderPaid'; orderId: string; transactionId: string; amount: number; occurredAt: Date }
  | { type: 'OrderShipped'; orderId: string; trackingNumber: string; occurredAt: Date }
  | { type: 'OrderCancelled'; orderId: string; reason: string; occurredAt: Date };

type EventHandler<T extends DomainEvent['type']> = (event: Extract<DomainEvent, { type: T }>) => Promise<void>;

class TypedEventBus {
  private handlers = new Map<string, Array<(event: DomainEvent) => Promise<void>>>();

  on<T extends DomainEvent['type']>(type: T, handler: EventHandler<T>): void {
    const existing = this.handlers.get(type) ?? [];
    existing.push(handler as (event: DomainEvent) => Promise<void>);
    this.handlers.set(type, existing);
  }

  async emit(event: DomainEvent): Promise<void> {
    const handlers = this.handlers.get(event.type) ?? [];
    await Promise.allSettled(handlers.map((h) => h(event)));
  }
}

const eventBus = new TypedEventBus();

eventBus.on('OrderCreated', async (event) => {
  console.log(`Order ${event.orderId} created for customer ${event.customerId}`);
});

eventBus.on('OrderPaid', async (event) => {
  console.log(`Order ${event.orderId} paid: ${event.amount}`);
});

小结
    

  • 品牌类型实现零开销的类型安全 ID，编译期防止参数混淆
    • 

  • 判别联合类型是建模状态机的最佳工具，编译器强制穷举所有状态
    • 

  • 值对象使用私有构造器 + 静态工厂 + Object.freeze 确保不可变性
    • 

  • 仓储使用泛型接口定义，基础设施层提供具体实现
    • 

  • 领域事件使用联合类型实现类型安全的发布订阅
    • 

  • 项目结构遵循依赖反转原则：领域层不依赖任何外部，基础设施层实现领域接口
