重构到 DDD

核心概念

大多数系统不是从零开始用 DDD 构建的，而是从已有的贫血模型（Anemic Domain Model）或事务脚本（Transaction Script）逐步重构而来。重构到 DDD 是一个渐进式过程，不能一步到位，需要在持续交付业务价值的同时逐步改善模型。

贫血模型是 Martin Fowler 定义的反模式：领域对象只有数据属性（getter/setter），没有行为；所有业务逻辑都在服务层的过程化代码中。充血模型则是 DDD 的目标：领域对象同时拥有数据和行为，业务规则内聚在对象中。

步骤一：提取值对象
重构的第一步通常是从原始类型中提取值对象。这是风险最低、收益最高的重构。


// 重构前：原始类型偏执
class OrderService {
  calculateShipping(province: string, city: string, weight: number): number {
    if (weight <= 0) throw new Error('Invalid weight');
    if (!province || !city) throw new Error('Invalid address');
    const baseRate = province === '浙江' ? 5 : 10;
    return baseRate + Math.ceil(weight) * 2;
  }

  validateEmail(email: string): boolean {
    return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
  }

  formatMoney(amount: number, currency: string): string {
    if (currency === 'CNY') return `¥${amount.toFixed(2)}`;
    return `$${amount.toFixed(2)}`;
  }
}

// 重构后：提取值对象
class Weight {
  private constructor(readonly kilograms: number) {}
  static of(kg: number): Weight {
    if (kg <= 0) throw new Error('Weight must be positive');
    return new Weight(kg);
  }
  get ceilKg(): number {
    return Math.ceil(this.kilograms);
  }
}

class ShippingAddress {
  private constructor(
    readonly province: string,
    readonly city: string,
  ) {}
  static create(province: string, city: string): ShippingAddress {
    if (!province || !city) throw new Error('Invalid address');
    return new ShippingAddress(province, city);
  }
  get isLocal(): boolean {
    return this.province === '浙江';
  }
}

class EmailAddress {
  private constructor(readonly value: string) {}
  static create(raw: string): EmailAddress {
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(raw)) throw new Error('Invalid email');
    return new EmailAddress(raw.toLowerCase());
  }
}
步骤二：将行为移入实体
第二步是将分散在 Service 中的业务逻辑移入对应的实体。


// 重构前：逻辑全在 Service
class OrderService {
  addItem(order: OrderData, productId: string, quantity: number, price: number): void {
    if (order.status !== 'draft') throw new Error('Cannot modify');
    if (quantity <= 0) throw new Error('Invalid quantity');

    const existing = order.items.find((i) => i.productId === productId);
    if (existing) {
      existing.quantity += quantity;
    } else {
      order.items.push({ productId, quantity, unitPrice: price });
    }
    order.totalAmount = order.items.reduce((sum, i) => sum + i.quantity * i.unitPrice, 0);
  }

  submitOrder(order: OrderData): void {
    if (order.items.length === 0) throw new Error('Empty order');
    if (order.status !== 'draft') throw new Error('Already submitted');
    order.status = 'submitted';
    order.submittedAt = new Date();
  }
}

// 重构后：行为在实体内
class Order {
  private status: OrderStatus = 'draft';
  private items: OrderLineItem[] = [];

  addItem(productId: ProductId, quantity: number, unitPrice: Money): void {
    this.assertDraft();
    if (quantity <= 0) throw new DomainError('Quantity must be positive');

    const existing = this.items.find((i) => i.productId.equals(productId));
    if (existing) {
      existing.increaseQuantity(quantity);
    } else {
      this.items.push(OrderLineItem.create(productId, quantity, unitPrice));
    }
  }

  submit(): void {
    if (this.items.length === 0) throw new DomainError('Cannot submit empty order');
    this.assertDraft();
    this.status = 'submitted';
    this.addDomainEvent(new OrderSubmitted(this.id, new Date()));
  }

  private assertDraft(): void {
    if (this.status !== 'draft') throw new DomainError('Order is not editable');
  }

  get totalAmount(): Money {
    return this.items.reduce((sum, i) => sum.add(i.subtotal), Money.of(0, 'CNY'));
  }
}
步骤三：定义聚合边界与引入仓储
确定聚合边界后，引入仓储模式隔离持久化细节。


// 重构前：Service 直接操作数据库
class OrderService {
  constructor(private readonly db: Database) {}

  async createOrder(customerId: string, items: Array<{ productId: string; qty: number }>): Promise<string> {
    const orderId = crypto.randomUUID();
    await this.db.query("INSERT INTO orders (id, customer_id, status) VALUES ($1, $2, 'draft')", [orderId, customerId]);

    for (const item of items) {
      await this.db.query('INSERT INTO order_items (order_id, product_id, quantity) VALUES ($1, $2, $3)', [
        orderId,
        item.productId,
        item.qty,
      ]);
    }
    return orderId;
  }
}

// 重构后：通过仓储操作聚合
class PlaceOrderUseCase {
  constructor(
    private readonly orderRepo: OrderRepository,
    private readonly eventDispatcher: EventDispatcher,
  ) {}

  async execute(command: PlaceOrderCommand): Promise<OrderId> {
    const orderId = this.orderRepo.nextId();
    const order = Order.create(orderId, CustomerId.create(command.customerId));

    for (const item of command.items) {
      order.addItem(ProductId.create(item.productId), item.quantity, Money.of(item.unitPrice, 'CNY'));
    }

    order.submit();
    await this.orderRepo.save(order);

    for (const event of order.pullDomainEvents()) {
      await this.eventDispatcher.dispatch(event);
    }

    return orderId;
  }
}
渐进式重构策略
// 绞杀者模式（Strangler Fig Pattern）
// 新功能用 DDD 实现，旧功能逐步迁移

// Phase 1: 新旧并存，通过 Facade 路由
class OrderFacade {
  constructor(
    private readonly legacyService: LegacyOrderService,
    private readonly newService: PlaceOrderUseCase,
    private readonly featureFlags: FeatureFlags,
  ) {}

  async placeOrder(request: OrderRequest): Promise<string> {
    if (this.featureFlags.isEnabled('new-order-flow')) {
      const orderId = await this.newService.execute(this.mapToCommand(request));
      return orderId.value;
    }
    return this.legacyService.createOrder(request);
  }

  private mapToCommand(req: OrderRequest): PlaceOrderCommand {
    return {
      customerId: req.customerId,
      items: req.items,
      shippingAddress: req.address,
    };
  }
}

小结
    

  • 重构到 DDD 是渐进式过程，不能一步到位
    • 

  • 优先重构核心域，通用域保持现状或替换为外部服务
    • 

  • 提取值对象是风险最低、收益最高的第一步
    • 

  • 使用绞杀者模式和 Feature Flag 实现新旧并存的平滑过渡
    • 

  • 每一步重构都应该是可独立部署和回滚的
    • 

  • 重构的目标不是技术完美，而是让核心业务逻辑更内聚、更可维护
