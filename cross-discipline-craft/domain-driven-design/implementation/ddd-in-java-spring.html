Java Spring 中的 DDD

核心概念

Java Spring 生态是 DDD 实践最成熟的平台之一。Spring Data 提供了仓储抽象，Spring 的依赖注入天然支持六边形架构，@DomainEvents 注解简化了领域事件发布，而 Java 的类型系统和模块化机制为领域模型的封装提供了坚实基础。

尽管本项目以 TypeScript 为主，理解 Java Spring 中的 DDD 实现对于与后端团队协作、理解行业最佳实践至关重要。两种实现方式的核心思想一致，区别在于语言特性和框架支持。

Spring Data 仓储模式
Spring Data JPA 的 Repository 接口与 DDD 仓储概念高度吻合，但需要注意保持聚合根级别的仓储。


// 以 TypeScript 风格表示 Java Spring Data 的模式
// 对应 Java: public interface OrderRepository extends JpaRepository<Order, OrderId>

// Spring Data 自动生成实现
interface OrderJpaRepository {
  findById(id: OrderId): Promise<Order | null>;
  save(order: Order): Promise<Order>;
  delete(order: Order): Promise<void>;
  findByCustomerId(customerId: CustomerId): Promise<Order[]>;
  findByStatusAndCreatedAtAfter(status: string, date: Date): Promise<Order[]>;
}

// DDD 仓储接口（领域层定义）
interface OrderRepository {
  findById(id: OrderId): Promise<Order | null>;
  save(order: Order): Promise<void>;
  nextId(): OrderId;
}

// 基础设施层适配器：将 Spring Data 接口适配为 DDD 仓储
class SpringOrderRepository implements OrderRepository {
  constructor(private readonly jpaRepo: OrderJpaRepository) {}

  async findById(id: OrderId): Promise<Order | null> {
    return this.jpaRepo.findById(id);
  }

  async save(order: Order): Promise<void> {
    await this.jpaRepo.save(order);
  }

  nextId(): OrderId {
    return createOrderId(crypto.randomUUID());
  }
}
Spring Data 的查询方法命名约定（如 findByStatusAndCreatedAtAfter）虽然方便，但容易在仓储接口中暴露过多查询方法，违背 DDD 的仓储精简原则。推荐的做法是将复杂查询分离到专门的查询服务中。


@DomainEvents 机制
Spring Data 提供了 @DomainEvents 注解，让聚合根在保存时自动发布收集的领域事件。


// 对应 Java 的 AbstractAggregateRoot 模式
abstract class AbstractAggregateRoot {
  private domainEvents: DomainEvent[] = [];

  protected registerEvent(event: DomainEvent): void {
    this.domainEvents.push(event);
  }

  // @DomainEvents — Spring Data 在 save() 后自动调用
  getDomainEvents(): DomainEvent[] {
    return [...this.domainEvents];
  }

  // @AfterDomainEventPublication — 清除已发布事件
  clearDomainEvents(): void {
    this.domainEvents = [];
  }
}

class Order extends AbstractAggregateRoot {
  private status: string = 'draft';
  private items: OrderLineItem[] = [];

  constructor(
    readonly id: OrderId,
    private customerId: CustomerId,
  ) {
    super();
  }

  submit(): void {
    if (this.items.length === 0) throw new Error('Empty order');
    this.status = 'submitted';
    this.registerEvent({
      type: 'OrderSubmitted',
      orderId: this.id,
      customerId: this.customerId,
      occurredAt: new Date(),
    });
  }

  confirmPayment(transactionId: string): void {
    this.status = 'paid';
    this.registerEvent({
      type: 'OrderPaid',
      orderId: this.id,
      transactionId,
      occurredAt: new Date(),
    });
  }
}

// 事件监听器
// @TransactionalEventListener 确保在事务提交后处理
class OrderEventHandler {
  constructor(
    private readonly inventoryService: InventoryService,
    private readonly notificationService: NotificationService,
  ) {}

  // @TransactionalEventListener
  async handleOrderSubmitted(event: { type: 'OrderSubmitted'; orderId: OrderId }): Promise<void> {
    await this.notificationService.sendOrderConfirmation(event.orderId);
  }

  // @TransactionalEventListener
  async handleOrderPaid(event: { type: 'OrderPaid'; orderId: OrderId }): Promise<void> {
    await this.inventoryService.deductStock(event.orderId);
  }
}
模块化与包结构
Java Spring 项目的包结构直接影响 DDD 模型的隔离性和可维护性。


// Java Spring DDD 推荐包结构（以 TypeScript 目录表示）
const javaPackageStructure = {
  'com/example/order/': {
    'domain/': {
      'model/': 'Order.java, OrderLineItem.java, Money.java',

与 TypeScript DDD 的对比
// 值对象对比
// Java: @Value @Embeddable class Money { BigDecimal amount; String currency; }
// TypeScript:
class Money {
  private constructor(
    readonly amount: number,
    readonly currency: string,
  ) {
    Object.freeze(this);
  }
  static of(amount: number, currency: string): Money {
    return new Money(amount, currency);
  }
}

// 聚合根对比
// Java: @Entity class Order extends AbstractAggregateRoot<Order> { @Id OrderId id; }
// TypeScript:
class Order extends AggregateRoot {
  constructor(readonly id: OrderId) {
    super();
  }
}

// 仓储对比
// Java: interface OrderRepo extends JpaRepository<Order, OrderId> {}
// TypeScript:
interface OrderRepository {
  findById(id: OrderId): Promise<Order | null>;
  save(order: Order): Promise<void>;
}

小结
    

  • Spring Data 的 Repository 接口天然契合 DDD 仓储模式，但需控制查询方法数量
    • 

  • @DomainEvents + AbstractAggregateRoot 简化了领域事件的收集和发布
    • 

  • 包结构直接决定了领域模型的隔离性，ArchUnit 可自动化架构守护
    • 

  • 领域层必须保持零框架依赖，Spring 注解只出现在基础设施和应用层
    • 

  • Java Spring 提供更多自动化（DI、事务、事件发布），TypeScript 需手动实现但更灵活
    • 

  • 两种语言的 DDD 核心模式完全一致，区别仅在语言特性和框架支持层面
