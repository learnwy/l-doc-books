实验分析工具与流程

核心概念

实验分析是 A/B 测试从数据到决策的桥梁。一个完整的分析流程不仅包括统计检验（p 值和置信区间），还需要数据质量验证、亚组分析、长期效应评估和结果可视化。实验分析的目标是将统计结果转化为可操作的业务洞察。自动化分析工具可以大幅降低分析门槛，但理解分析方法的原理对于正确解读结果至关重要——工具能告诉你"数据说了什么"，但只有理解方法论才能判断"数据说得对不对"。

数据质量验证流程
在进行任何统计分析之前，必须先验证数据质量。数据质量问题是 A/B 测试中最常见的陷阱之一——如果数据本身有问题，再精确的统计方法也无法得出正确结论。


SRM（Sample Ratio Mismatch）检查是最关键的质量验证。它通过卡方检验判断实际样本比例是否与设计比例一致。SRM 检查应该在实验开始后的第一天就进行，发现问题越早，损失越小。

核心分析方法
实验的核心分析围绕核心指标展开。标准分析流程包括以下步骤：


点估计与区间估计：计算实验组与对照组的差异（绝对差异和相对提升），以及差异的 95% 置信区间。置信区间比 p 值更有信息量，因为它同时反映了效应的方向、大小和精度。


假设检验：计算 p 值，判断差异是否统计显著。需要注意选择正确的检验方法（比例用 Z 检验，连续用 t 检验）和检验方向（通常使用双侧检验）。


效应量评估：统计显著不等于实际有意义。需要对照预设的最小实际效应阈值，判断效应是否值得推广。


interface ExperimentResult {
  controlMean: number;
  treatmentMean: number;
  absoluteDiff: number;
  relativeLift: number;
  confidenceInterval: [number, number];
  pValue: number;
  sampleSizeControl: number;
  sampleSizeTreatment: number;
  isSignificant: boolean;
}

function analyzeProportionMetric(
  controlSuccesses: number,
  controlTotal: number,
  treatmentSuccesses: number,
  treatmentTotal: number,
  alpha: number = 0.05,
): ExperimentResult {
  const pC = controlSuccesses / controlTotal;
  const pT = treatmentSuccesses / treatmentTotal;
  const diff = pT - pC;
  const pooledP = (controlSuccesses + treatmentSuccesses) / (controlTotal + treatmentTotal);
  const se = Math.sqrt(pooledP * (1 - pooledP) * (1 / controlTotal + 1 / treatmentTotal));
  const z = diff / se;
  const pValue = 2 * (1 - normalCDF(Math.abs(z)));
  const zCrit = normalQuantile(1 - alpha / 2);
  const ciSe = Math.sqrt((pT * (1 - pT)) / treatmentTotal + (pC * (1 - pC)) / controlTotal);

  return {
    controlMean: pC,
    treatmentMean: pT,
    absoluteDiff: diff,
    relativeLift: diff / pC,
    confidenceInterval: [diff - zCrit * ciSe, diff + zCrit * ciSe],
    pValue,
    sampleSizeControl: controlTotal,
    sampleSizeTreatment: treatmentTotal,
    isSignificant: pValue < alpha,
  };
}
亚组分析与异质效应
亚组分析（Subgroup Analysis）检查实验效应是否在不同用户群体中表现一致。例如，一个功能改动可能对新用户有正面效果，但对老用户有负面效果。如果只看总体结果，两种效应可能互相抵消，导致"不显著"的结论——但分开看每个亚组都有显著效应。

亚组分析的核心陷阱是多重比较问题。如果分析 10 个亚组 × 5 个指标 = 50 个检验，即使所有效应都为零，也期望观察到 2-3 个"显著"结果。因此，亚组分析的结果应被视为探索性发现而非确认性结论。有重要发现时，应该设计新实验专门验证。


自动化分析平台
大型科技公司的实验分析平台通常具备以下自动化能力：


自动报告生成：实验达到预设样本量或运行时间后，自动生成包含所有预注册指标的分析报告。报告包括核心指标、辅助指标、护栏指标的统计检验结果，以及时间趋势图和亚组分析。


异常告警：实时监控护栏指标，一旦出现显著恶化（如崩溃率上升 20%），自动发送告警并可选择自动暂停实验。


因果归因：当核心指标变化时，自动分析辅助指标和用户行为漏斗，帮助理解变化的原因（"为什么转化率下降了？是因为页面加载变慢了，还是因为新设计降低了用户的理解度？"）。

小结
    

  • 数据质量验证（尤其是 SRM 检查）必须在统计分析之前完成
    • 

  • 核心分析应同时报告 p 值、置信区间和效应量，三者缺一不可
    • 

  • 亚组分析是探索性的，发现的效应需要新实验验证
    • 

  • 辛普森悖论提醒我们总体结果可能掩盖亚组间的异质效应
    • 

  • 自动化分析平台通过标准化流程降低人为错误和分析门槛
    • 

  • 实验分析的最终目标是将统计结果转化为可操作的业务洞察
