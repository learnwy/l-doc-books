交叉实验方法

核心概念

交叉实验（Interleaving）是一种高灵敏度的在线实验方法，特别适用于排序系统和推荐系统的评估。与传统 A/B 测试将用户分为完全独立的两组不同，交叉实验让每个用户同时看到来自两个系统的结果——将两个排序算法的输出"交叉"混合成一个列表展示给用户，然后根据用户点击了哪些结果来判断哪个算法更优。交叉实验的核心优势是灵敏度极高——通常只需要传统 A/B 测试 1% 到 10% 的样本量就能检测到相同大小的效应。

Team Draft Interleaving
Team Draft Interleaving 是最常用的交叉方法。它的灵感来自体育比赛的"选人"机制：两个队长（代表两个算法）交替从自己的排序列表中选择结果放入最终列表。


算法步骤：


    

  1. 随机决定哪个算法先选（A 或 B）
    2. 

  2. 每轮中，当前选择权的算法从其排序中选取排名最高且尚未被选中的结果
    3. 

  3. 交替进行，直到填满展示位
    4. 

  4. 记录每个结果属于哪个算法
    5. 

  5. 用户点击后，该点击计入对应算法的得分
    6. 



interface SearchResult {
  id: string;
  rankInA: number;
  rankInB: number;
}

function teamDraftInterleave(
  listA: string[],
  listB: string[],
  slots: number,
): { interleavedList: string[]; assignments: Map<string, 'A' | 'B'> } {
  const interleavedList: string[] = [];
  const assignments = new Map<string, 'A' | 'B'>();
  const used = new Set<string>();
  let idxA = 0;
  let idxB = 0;
  let teamACount = 0;
  let teamBCount = 0;

  const firstPicker = Math.random() < 0.5 ? 'A' : 'B';

  while (interleavedList.length < slots) {
    const pickA =
      teamACount <= teamBCount ? (firstPicker === 'A' ? teamACount < teamBCount + 1 : teamACount <= teamBCount) : false;

    if (pickA || idxB >= listB.length) {
      while (idxA < listA.length && used.has(listA[idxA])) idxA++;
      if (idxA < listA.length) {
        interleavedList.push(listA[idxA]);
        assignments.set(listA[idxA], 'A');
        used.add(listA[idxA]);
        teamACount++;
        idxA++;
      }
    } else {
      while (idxB < listB.length && used.has(listB[idxB])) idxB++;
      if (idxB < listB.length) {
        interleavedList.push(listB[idxB]);
        assignments.set(listB[idxB], 'B');
        used.add(listB[idxB]);
        teamBCount++;
        idxB++;
      }
    }
  }

  return { interleavedList, assignments };
}
Optimized Interleaving
Optimized Interleaving 是 Team Draft 的改进版本，解决了 Team Draft 在某些场景下灵敏度不足的问题。其核心改进是在生成交叉列表时，优化列表的信息量——选择那些最能区分两个算法优劣的排列方式。


Optimized Interleaving 的工作原理：


    

  1. 枚举所有可能的交叉列表（在约束条件下）
    2. 

  2. 对每种排列计算其"区分度"——两个算法在该排列下得分差异的期望值
    3. 

  3. 选择区分度最高的排列
    4. 



实际中由于枚举所有排列的计算成本太高，通常使用近似方法或约束优化。

多维度交叉实验
在搜索和推荐系统中，用户界面通常包含多个可以独立优化的维度：排序顺序、卡片样式、摘要文案等。多维度交叉实验（Multidimensional Interleaving）将交叉方法扩展到多个维度，允许同时评估多个独立变量的效果。


例如，对于搜索结果页面，可以同时交叉测试：


    

  • 排序维度：算法 A vs 算法 B 的排序
    • 

  • 摘要维度：摘要生成方式 X vs 方式 Y
    • 

  • 展示维度：卡片样式 1 vs 样式 2
    • 



每个结果的每个维度独立地从两个候选中选择，形成一个多因素的组合实验。用户的每次点击可以同时为多个维度提供信号。


交叉实验的局限与最佳实践
交叉实验虽然灵敏度极高，但存在几个重要的局限性：


只适用于排序/列表场景：交叉实验的核心假设是结果可以被混合展示。对于非列表类的功能变更（如改变按钮颜色、修改支付流程），交叉方法不适用。


无法评估全局效应：交叉实验衡量的是"用户更偏好哪个系统的结果"，但无法评估系统级的全局效应（如总搜索量的变化、用户留存率）。这些全局效应仍然需要传统 A/B 测试来评估。


位置偏差：用户倾向于点击列表中靠前的结果（位置偏差）。如果一个算法的结果总是被放在更靠前的位置，它会获得不公平的优势。Team Draft 通过交替选择的机制来缓解这个问题。






最佳实践
说明





先 Interleaving，后 A/B
用高灵敏度的交叉实验快速筛选候选算法，再用 A/B 测试确认全局效应




控制位置偏差
使用 Team Draft 或 Optimized 方法，随机化首选权




足够的展示位
至少 10 个展示位才能让交叉方法有效工作




排除重复结果
两个算法返回相同结果时，该结果的点击不计入任何一方




监控用户体验
交叉列表不应导致不一致的用户体验（如相关性突变）





小结
    

  • 交叉实验通过在单个列表中混合两个系统的结果，实现极高的灵敏度
    • 

  • Team Draft 是最常用的交叉方法，通过交替选择机制控制偏差
    • 

  • Optimized Interleaving 通过优化列表排列进一步提升灵敏度
    • 

  • 多维度交叉实验允许同时评估排序、摘要、展示等多个独立维度
    • 

  • 交叉实验只适用于排序/列表场景，全局效应仍需 A/B 测试验证
    • 

  • 最佳实践是"先交叉筛选，后 A/B 确认"的两阶段流程
    •
