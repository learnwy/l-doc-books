随机化策略与分组方法

核心概念

随机化是 A/B 测试的基石。它确保实验组和对照组在所有已知和未知的混淆因素上是统计等价的，从而使观测到的差异可以归因于实验处理本身。随机化策略的选择直接影响实验的内部有效性（因果推断的可靠性）和外部有效性（结论的可推广性）。不同的业务场景需要不同的随机化方案——用户级、会话级、页面级、集群级各有适用条件和注意事项。

用户级随机化的实现
用户级随机化是最常用的方式。每个用户在实验期间始终看到相同的版本，确保了体验的一致性。实现的核心是哈希分桶：将用户 ID 和实验 ID 组合后做哈希运算，根据哈希值的余数决定分组。


function assignBucket(userId: string, experimentId: string, numBuckets: number): number {
  const key = `${experimentId}_${userId}`;
  const hash = murmurhash3(key);
  return hash % numBuckets;
}

function isInExperiment(userId: string, experimentId: string, trafficPercent: number): boolean {
  const bucket = assignBucket(userId, experimentId, 10000);
  return bucket < trafficPercent * 100;
}
哈希函数的选择至关重要。理想的哈希函数应该满足：均匀性（不同输入均匀分布到所有桶）、确定性（相同输入始终产生相同输出）、独立性（不同实验的分桶结果相互独立）。MurmurHash3 和 MD5 的低位都是常用选择。


实验间的独立性是一个容易被忽视的问题。如果两个实验使用相同的哈希函数和种子，可能导致用户在两个实验中总是被分到同一个桶（相关分桶）。解决方法是使用实验 ID 作为哈希的盐值（salt），确保不同实验的分桶互相独立。

分层随机化
分层随机化（Stratified Randomization）在随机分组之前，先按关键特征（如平台、地区、用户活跃度）将用户分层，然后在每一层内独立进行随机分配。这样可以保证每一层中实验组和对照组的比例一致，减少因混淆变量导致的方差。


分层的好处体现在两方面。精度提升：如果分层变量与因变量高度相关（如 iOS 和 Android 用户的行为差异大），分层随机化可以显著降低估计的方差。亚组分析：分层使得每个层都有均衡的实验和对照数据，支持可靠的亚组效应分析。


分层的代价是实施复杂度增加。层数越多，每层的样本量越小，如果层的划分过于细致，反而可能降低统计效率。一般建议分层数不超过 3-5 个关键维度。


interface StratificationConfig {
  dimensions: Array<{
    name: string;
    bucketFn: (user: UserProfile) => string;
  }>;
  experimentId: string;
  trafficPercent: number;
}

function stratifiedAssign(user: UserProfile, config: StratificationConfig): string {
  const stratum = config.dimensions.map((d) => d.bucketFn(user)).join('_');
  const key = `${config.experimentId}_${stratum}_${user.id}`;
  const hash = murmurhash3(key);
  return hash % 10000 < config.trafficPercent * 100 ? 'treatment' : 'control';
}
集群随机化与干扰处理
当用户之间存在相互影响（如社交网络中的口碑传播），传统的用户级随机化会导致 SUTVA 违反——实验组用户的行为会通过社交关系影响对照组用户，从而稀释实验效应。集群随机化（Cluster Randomization）通过将相互影响的用户分到同一个集群，以集群为单位进行随机分配，来解决这个问题。

集群随机化的统计效率低于用户级随机化。有效样本量取决于集群数量而非总用户数。计算有效样本量需要引入组内相关系数（ICC，Intraclass Correlation Coefficient）：


有效样本量 ≈ 总样本量 / (1 + (集群大小 - 1) × ICC)


ICC 衡量的是同一集群内用户之间的相似程度。ICC 越高，有效样本量折损越严重。例如，若每个集群有 100 个用户、ICC = 0.05，则有效样本量约为原来的 1/6。


流量分配与多实验并行
在大型产品中，通常有数十甚至数百个实验同时运行。流量分配系统需要解决两个核心问题：流量隔离和流量复用。


流量隔离（Mutual Exclusion）确保用户不会同时参与两个可能相互干扰的实验。例如，两个都修改首页布局的实验不能让同一个用户同时参与。隔离通常通过将流量空间划分为互斥的层（Layer）来实现。


流量复用（Overlapping）允许用户同时参与多个不相互干扰的实验。例如，一个改变搜索排序算法的实验和一个改变支付页面按钮颜色的实验，两者不会相互影响，可以复用同一批用户。


interface TrafficLayer {
  layerId: string;
  experiments: Array<{
    experimentId: string;
    trafficRange: [number, number];
  }>;
}

function assignToExperiments(userId: string, layers: TrafficLayer[]): Map<string, string> {
  const assignments = new Map<string, string>();

  for (const layer of layers) {
    const bucket = assignBucket(userId, layer.layerId, 10000);

    for (const exp of layer.experiments) {
      const [start, end] = exp.trafficRange;
      if (bucket >= start && bucket < end) {
        const group = assignBucket(userId, exp.experimentId, 2);
        assignments.set(exp.experimentId, group === 0 ? 'control' : 'treatment');
      }
    }
  }

  return assignments;
}
Google 的 Overlapping Experiment Infrastructure 论文描述了经典的分层流量架构：将整个流量空间划分为多个正交层，同一层内的实验互斥，不同层的实验可重叠。每个层使用不同的哈希种子，确保跨层分配的独立性。


小结
    

  • 随机化粒度的选择取决于业务场景：用户级最通用，集群级处理网络效应
    • 

  • 哈希分桶是用户级随机化的标准实现，需确保均匀性和实验间独立性
    • 

  • 分层随机化通过先分层后随机来降低方差，建议分层不超过 3-5 个维度
    • 

  • 集群随机化处理 SUTVA 违反问题，但有效样本量会因 ICC 而大幅折损
    • 

  • 多实验并行需要流量隔离（互斥层）和流量复用（正交层）的协调
    • 

  • Google 的分层流量架构是业界标准的多实验并行解决方案
