消息代理集成

核心概念

在事件溯源与 CQRS 架构中，消息代理（Message Broker）承担事件分发的职责——将命令端产生的领域事件可靠地传递给所有下游消费者（投影器、Saga、通知服务等）。消息代理与事件存储的职责不同：事件存储负责事件的持久化和溯源查询，消息代理负责事件的实时分发和消费协调。

消息代理的选择取决于系统对延迟、吞吐量、消息保留和运维复杂度的综合需求。在事件溯源场景中，Kafka 因其日志模型与事件流的天然亲和性而最常被选用。


Kafka 事件分发
Kafka 的分区日志模型与事件溯源的追加写入语义高度契合。每个事件按聚合 ID 路由到固定分区，保证同一聚合的事件有序处理。


interface KafkaEventPublisher {
  publish(event: DomainEvent): Promise<void>;
  publishBatch(events: ReadonlyArray<DomainEvent>): Promise<void>;
}

const createKafkaEventPublisher = (producer: KafkaProducer, topic: string): KafkaEventPublisher => ({
  async publish(event) {
    await producer.send({
      topic,
      messages: [
        {
          key: event.aggregateId,
          value: JSON.stringify({
            eventId: event.eventId,
            eventType: event.eventType,
            aggregateId: event.aggregateId,
            version: event.version,
            data: event.payload,
            metadata: event.metadata,
            timestamp: event.timestamp.toISOString(),
          }),
          headers: {
            'event-type': event.eventType,
            'aggregate-id': event.aggregateId,
            'correlation-id': event.metadata.correlationId,
          },
        },
      ],
    });
  },

  async publishBatch(events) {
    const messages = events.map((event) => ({
      key: event.aggregateId,
      value: JSON.stringify(event),
      headers: {
        'event-type': event.eventType,
        'aggregate-id': event.aggregateId,
      },
    }));
    await producer.send({ topic, messages });
  },
});

interface KafkaEventConsumer {
  subscribe(groupId: string, handler: (event: DomainEvent) => Promise<void>): Promise<void>;
}

const createKafkaEventConsumer = (consumer: KafkaConsumer, topic: string): KafkaEventConsumer => ({
  async subscribe(groupId, handler) {
    await consumer.connect();
    await consumer.subscribe({ topic, fromBeginning: false });

    await consumer.run({
      eachMessage: async ({ message }) => {
        const event = JSON.parse(message.value?.toString() ?? '{}') as DomainEvent;
        await handler(event);
      },
    });
  },
});
Kafka 消费者组机制保证了每条消息在同一组内只被一个消费者处理，不同组之间可以独立消费。这意味着投影器和 Saga 可以作为不同的消费者组独立运行，互不干扰。


RabbitMQ 集成
RabbitMQ 的推送模型和灵活的路由机制使其在低延迟场景中表现优异。通过 Exchange 和 Binding 的组合，可以实现复杂的事件路由策略。


interface RabbitMQEventPublisher {
  publish(event: DomainEvent): Promise<void>;
}

const createRabbitMQPublisher = (channel: AmqpChannel, exchange: string): RabbitMQEventPublisher => ({
  async publish(event) {
    const routingKey = `${event.eventType}.${event.aggregateId.split('-')[0]}`;

    channel.publish(exchange, routingKey, Buffer.from(JSON.stringify(event)), {
      persistent: true,
      messageId: event.eventId,
      type: event.eventType,
      correlationId: event.metadata.correlationId,
      timestamp: event.timestamp.getTime(),
      headers: {
        'aggregate-id': event.aggregateId,
        'event-version': event.version,
      },
    });
  },
});

const setupEventTopology = async (channel: AmqpChannel): Promise<void> => {
  await channel.assertExchange('domain.events', 'topic', { durable: true });

  await channel.assertQueue('projections.order-list', { durable: true });
  await channel.bindQueue('projections.order-list', 'domain.events', 'Order*.#');

  await channel.assertQueue('sagas.order-fulfillment', { durable: true });
  await channel.bindQueue('sagas.order-fulfillment', 'domain.events', 'Order*.#');

  await channel.assertQueue('notifications.email', { durable: true });
  await channel.bindQueue('notifications.email', 'domain.events', 'OrderConfirmed.#');
};
RabbitMQ 的 Topic Exchange 允许消费者通过通配符模式订阅感兴趣的事件类型。例如 Order*.# 匹配所有以 Order 开头的事件类型，而 OrderConfirmed.# 只匹配订单确认事件。这种细粒度的路由避免了消费者接收无关消息。


事件发布模式
从事件存储到消息代理的事件发布是一个关键环节。最常见的两种模式是：Outbox 模式（事务保证）和 CDC 模式（变更数据捕获）。


interface OutboxEntry {
  readonly id: string;
  readonly eventId: string;
  readonly eventType: string;
  readonly payload: string;
  readonly createdAt: Date;
  readonly publishedAt: Date | null;
}

const appendWithOutbox = async (
  pool: Pool,
  streamId: string,
  events: ReadonlyArray<NewEvent>,
  expectedVersion: number,
): Promise<void> => {
  const client = await pool.connect();
  try {
    await client.query('BEGIN');

    for (let i = 0; i < events.length; i++) {
      const event = events[i];
      await client.query(
        `INSERT INTO events (event_id, stream_id, event_type, stream_version, data)
         VALUES ($1, $2, $3, $4, $5)`,
        [event.eventId, streamId, event.eventType, expectedVersion + i + 1, JSON.stringify(event.data)],
      );

      await client.query(
        `INSERT INTO outbox (id, event_id, event_type, payload, created_at)
         VALUES ($1, $2, $3, $4, NOW())`,
        [crypto.randomUUID(), event.eventId, event.eventType, JSON.stringify(event)],
      );
    }

    await client.query('COMMIT');
  } catch (error) {
    await client.query('ROLLBACK');
    throw error;
  } finally {
    client.release();
  }
};

const createOutboxPoller = (
  pool: Pool,
  publisher: KafkaEventPublisher,
  intervalMs = 100,
): { start: () => void; stop: () => void } => {
  let timer: NodeJS.Timeout | null = null;

  const poll = async () => {
    const { rows } = await pool.query(`SELECT * FROM outbox WHERE published_at IS NULL ORDER BY created_at LIMIT 100`);
    for (const row of rows) {
      await publisher.publish(JSON.parse(row.payload) as DomainEvent);
      await pool.query(`UPDATE outbox SET published_at = NOW() WHERE id = $1`, [row.id]);
    }
  };

  return {
    start: () => {
      timer = setInterval(poll, intervalMs);
    },
    stop: () => {
      if (timer) clearInterval(timer);
    },
  };
};
Outbox 模式通过将事件写入和 Outbox 记录放在同一数据库事务中，保证了"事件写入"与"发布意图记录"的原子性。轮询器异步读取 Outbox 并发送到消息代理。CDC 模式则直接监听数据库的事务日志（如 PostgreSQL 的 WAL），无需额外的 Outbox 表。


小结
    

  • Kafka 的分区日志模型与事件溯源的追加写入语义天然契合，适合大规模系统
    • 

  • RabbitMQ 的推送模型和 Topic Exchange 提供了低延迟和灵活的事件路由能力
    • 

  • Outbox 模式通过同一事务保证事件写入与发布意图的原子性，是最可靠的发布方案
    • 

  • CDC 模式直接监听数据库事务日志，无需 Outbox 表但依赖特定数据库能力
    • 

  • 消息代理的职责是事件分发，与事件存储（持久化+溯源）的职责互补而非替代
    • 

  • 消费者组机制保证了不同下游系统可以独立消费同一事件流
    •
