事件重放与投影

核心概念

事件重放（Event Replay）是事件溯源的核心机制——通过按顺序处理事件流，将原始事件转化为可查询的状态表示。投影（Projection）是这个过程的产物：为特定查询需求定制的物化视图。一个事件流可以驱动无数个不同的投影，每个投影关注不同的数据维度，服务于不同的业务场景。

投影的本质是一个纯函数：(currentState, event) => newState。这个函数式的特性保证了投影的确定性——同样的事件序列始终产生同样的结果，这为投影的重建和测试提供了坚实的理论基础。


物化视图构建
物化视图（Materialized View）是投影的持久化形态。与数据库层面的物化视图不同，事件溯源中的物化视图由应用层控制——投影器负责监听事件流、更新视图状态，并维护处理进度（检查点）。


interface Projection<TState> {
  readonly projectionName: string;
  readonly initialState: TState;
  handle(state: TState, event: PersistedEvent): TState;
}

interface ProjectionStore<TState> {
  getState(key: string): Promise<TState | undefined>;
  setState(key: string, state: TState): Promise<void>;
  getCheckpoint(projectionName: string): Promise<bigint>;
  setCheckpoint(projectionName: string, position: bigint): Promise<void>;
}

const orderSummaryProjection: Projection<OrderSummary> = {
  projectionName: 'order-summary',
  initialState: { orderId: '', status: 'unknown', itemCount: 0, total: 0 },
  handle(state, event) {
    switch (event.eventType) {
      case 'OrderCreated': {
        const data = JSON.parse(event.data.toString()) as OrderCreatedPayload;
        return {
          orderId: event.streamId,
          status: 'created',
          itemCount: data.items.length,
          total: data.totalAmount,
        };
      }
      case 'OrderConfirmed':
        return { ...state, status: 'confirmed' };
      case 'OrderShipped':
        return { ...state, status: 'shipped' };
      default:
        return state;
    }
  },
};
物化视图是"用空间换时间"的经典策略。预先计算好查询结果，读取时直接返回，避免了每次查询都重放事件的开销。在实际系统中，一个订单事件流可能同时驱动订单详情视图、客户订单列表视图、日销售统计视图等多个物化视图。


物化视图的一个重要特性是可以随时销毁并重建。如果投影逻辑发生变化（例如需要增加一个新字段），只需要修改投影器代码，清空旧视图数据，然后从事件存储的起始位置重新投影即可。这种"重放即迁移"的能力是事件溯源相比传统 CRUD 的核心优势之一。


投影器模式
投影器（Projector）是连接事件存储和物化视图的运行时组件。一个健壮的投影器需要处理检查点管理、错误恢复、背压控制和并发安全。


class ProjectionRunner<TState> {
  constructor(
    private readonly projection: Projection<TState>,
    private readonly eventStore: EventStore,
    private readonly store: ProjectionStore<TState>,
  ) {}

  async runCatchUp(): Promise<void> {
    const checkpoint = await this.store.getCheckpoint(this.projection.projectionName);
    const events = await this.eventStore.readAll(checkpoint);

    for (const event of events) {
      const key = event.streamId;
      const currentState = (await this.store.getState(key)) ?? this.projection.initialState;
      const newState = this.projection.handle(currentState, event);
      await this.store.setState(key, newState);
      await this.store.setCheckpoint(this.projection.projectionName, event.globalPosition);
    }
  }

  async runLive(): Promise<Subscription> {
    await this.runCatchUp();

    return this.eventStore.subscribe(await this.store.getCheckpoint(this.projection.projectionName), async (event) => {
      const key = event.streamId;
      const currentState = (await this.store.getState(key)) ?? this.projection.initialState;
      const newState = this.projection.handle(currentState, event);
      await this.store.setState(key, newState);
      await this.store.setCheckpoint(this.projection.projectionName, event.globalPosition);
    });
  }
}
投影器的生命周期通常分为两个阶段：追赶阶段（Catch-up）从检查点读取历史事件并逐个处理；实时阶段（Live）订阅新事件并实时处理。当订阅连接断开时，投影器回退到追赶阶段重新追赶。


跨流投影
单流投影处理单个聚合的事件，而跨流投影（Cross-stream Projection）聚合多个流的事件来构建更复杂的视图。这是构建仪表盘、报表和搜索索引的关键模式。


interface DashboardView {
  totalOrders: number;
  totalRevenue: number;
  ordersByStatus: Record<string, number>;
  topCustomers: Array<{ customerId: string; orderCount: number; totalSpent: number }>;
}

const dashboardProjection: Projection<DashboardView> = {
  projectionName: 'sales-dashboard',
  initialState: {
    totalOrders: 0,
    totalRevenue: 0,
    ordersByStatus: {},
    topCustomers: [],
  },
  handle(state, event) {
    switch (event.eventType) {
      case 'OrderCreated': {
        const data = JSON.parse(event.data.toString()) as OrderCreatedPayload;
        return {
          ...state,
          totalOrders: state.totalOrders + 1,
          totalRevenue: state.totalRevenue + data.totalAmount,
          ordersByStatus: {
            ...state.ordersByStatus,
            created: (state.ordersByStatus.created ?? 0) + 1,
          },
        };
      }
      case 'OrderConfirmed':
        return {
          ...state,
          ordersByStatus: {
            ...state.ordersByStatus,
            created: (state.ordersByStatus.created ?? 0) - 1,
            confirmed: (state.ordersByStatus.confirmed ?? 0) + 1,
          },
        };
      default:
        return state;
    }
  },
};
跨流投影依赖全局有序读取——事件必须按全局位置排序处理，否则投影状态可能出现不一致。例如，如果先处理 OrderConfirmed 再处理 OrderCreated，状态计数就会出错。全局位置的单调递增性保证了因果顺序的正确性。


投影重建与版本管理
当投影逻辑变更时，需要重建投影。一个成熟的投影管理系统需要支持版本化管理和蓝绿切换，避免重建过程影响线上查询。


interface VersionedProjectionManager {
  currentVersion: number;
  rebuildVersion: number | null;
}

const rebuildProjection = async <TState>(
  runner: ProjectionRunner<TState>,
  store: ProjectionStore<TState>,
  projectionName: string,
): Promise<void> => {
  const rebuildName = `${projectionName}_v${Date.now()}`;
  const rebuildStore = createProjectionStore<TState>(rebuildName);

  await runner.runFullRebuild(rebuildStore);

  await atomicSwap(store, rebuildStore, projectionName);
};

const createProjectionRegistry = () => {
  const projections = new Map<string, ProjectionRunner<unknown>>();

  const register = <TState>(name: string, version: number, runner: ProjectionRunner<TState>): void => {
    const versionedName = `${name}_v${version}`;
    projections.set(versionedName, runner as ProjectionRunner<unknown>);
  };

  const startAll = async (): Promise<void> => {
    const promises = [...projections.values()].map((runner) => runner.runLive());
    await Promise.all(promises);
  };

  return { register, startAll };
};
蓝绿切换的流程是：在后台启动新版本投影的全量重建，重建完成后原子性地将查询路由切换到新版本，最后清理旧版本的数据。这个过程对线上用户完全透明。


小结
    

  • 投影是事件到查询视图的纯函数转换，同一事件序列始终产生同一结果
    • 

  • 物化视图是投影的持久化形态，用空间换时间，可随时销毁重建
    • 

  • 投影器分为追赶和实时两个阶段，通过检查点实现断点续传
    • 

  • 跨流投影依赖全局有序读取，是构建仪表盘和报表的关键模式
    • 

  • 投影重建通过蓝绿切换实现零停机迁移，对线上用户完全透明
    • 

  • "重放即迁移"是事件溯源相比传统 CRUD 的核心优势之一
