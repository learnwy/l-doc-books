事件溯源核心概念

核心概念

事件溯源（Event Sourcing）是一种将系统所有状态变更以不可变事件序列的形式持久化的架构模式。与传统 CRUD 直接修改数据库中的当前状态不同，事件溯源记录的是"发生了什么"——每一个事件都是一条不可撤销的事实。当前状态不再直接存储，而是通过顺序重放事件序列计算得到。

这种范式转变的核心思想是：数据的真相不是"当前是什么"，而是"经历了什么"。事件是系统中唯一的事实来源（Single Source of Truth），所有的读模型、投影、缓存都是从事件流派生出来的二级产物。


事件即事实
在事件溯源中，事件是对已发生业务行为的不可变记录。一个设计良好的事件包含足够的上下文信息，使得任何消费者都能理解这个事实的完整含义。


interface DomainEvent {
  readonly eventId: string;
  readonly aggregateId: string;
  readonly eventType: string;
  readonly version: number;
  readonly timestamp: Date;
  readonly payload: Record<string, unknown>;
  readonly metadata: EventMetadata;
}

interface EventMetadata {
  readonly correlationId: string;
  readonly causationId: string;
  readonly userId: string;
}

interface OrderCreatedEvent extends DomainEvent {
  readonly eventType: 'OrderCreated';
  readonly payload: {
    readonly customerId: string;
    readonly items: ReadonlyArray<OrderItem>;
    readonly totalAmount: number;
    readonly currency: string;
  };
}
事件命名遵循过去时态的动词形式：OrderCreated、PaymentProcessed、ItemShipped。这强调了事件是已经完成的事实，而非正在执行的命令。事件一旦写入事件存储就不可修改——如果需要"撤销"某个操作，正确的做法是追加一个补偿事件（如 OrderCancelled），而不是删除原始事件。


事件的不可变性带来了一个强大的特性：任何时刻的系统状态都可以通过从头重放事件序列精确还原。这意味着调试生产问题时，你可以在本地环境中重放相同的事件序列来复现完全相同的状态。


状态重建
聚合（Aggregate）是事件溯源中的核心构建块。每个聚合维护自己的事件流，通过将事件逐个应用到初始状态来重建当前状态。


class OrderAggregate {
  private state: OrderState = { status: 'empty', items: [], total: 0 };
  private version = 0;

  static rehydrate(events: ReadonlyArray<DomainEvent>): OrderAggregate {
    const aggregate = new OrderAggregate();
    for (const event of events) {
      aggregate.apply(event);
    }
    return aggregate;
  }

  private apply(event: DomainEvent): void {
    switch (event.eventType) {
      case 'OrderCreated':
        this.state = {
          status: 'created',
          items: event.payload.items as ReadonlyArray<OrderItem>,
          total: event.payload.totalAmount as number,
        };
        break;
      case 'OrderConfirmed':
        this.state = { ...this.state, status: 'confirmed' };
        break;
      case 'OrderShipped':
        this.state = { ...this.state, status: 'shipped' };
        break;
    }
    this.version = event.version;
  }

  getState(): Readonly<OrderState> {
    return this.state;
  }
}
状态重建的过程是确定性的——给定相同的事件序列，始终产生相同的状态。这个特性是事件溯源许多高级功能的基础，包括时间旅行查询（重放到指定时间点）和并行投影（多个读模型从同一事件流独立构建）。


重建过程的性能开销与事件数量成正比。对于生命周期较长的聚合（如拥有数千个事件的用户账户），每次加载都从头重放显然不现实。这正是快照机制存在的原因——定期保存中间状态快照，下次重建时从最近的快照开始重放后续事件即可。


聚合与事件流
聚合是事件溯源中的一致性边界。每个聚合实例拥有独立的事件流，通过聚合标识符（Aggregate ID）关联。聚合在处理命令时通过业务规则验证来保护不变量，然后产生事件。


class OrderAggregate {
  private uncommittedEvents: DomainEvent[] = [];

  createOrder(command: CreateOrderCommand): void {
    if (this.state.status !== 'empty') {
      throw new Error('Order already exists');
    }
    if (command.items.length === 0) {
      throw new Error('Order must contain at least one item');
    }
    this.raiseEvent({
      eventType: 'OrderCreated',
      payload: {
        customerId: command.customerId,
        items: command.items,
        totalAmount: this.calculateTotal(command.items),
        currency: command.currency,
      },
    });
  }

  confirmOrder(): void {
    if (this.state.status !== 'created') {
      throw new Error(`Cannot confirm order in ${this.state.status} status`);
    }
    this.raiseEvent({ eventType: 'OrderConfirmed', payload: {} });
  }

  private raiseEvent(partial: Partial<DomainEvent>): void {
    const event = {
      ...partial,
      eventId: crypto.randomUUID(),
      aggregateId: this.id,
      version: this.version + 1,
      timestamp: new Date(),
    } as DomainEvent;
    this.apply(event);
    this.uncommittedEvents.push(event);
  }
}
聚合的设计原则是尽量小——只包含维护业务不变量所必需的数据。跨聚合的协调通过事件驱动的最终一致性来实现，而不是在单个事务中修改多个聚合。


命令与事件的生命周期
命令（Command）表达意图，事件（Event）记录事实。命令可能被拒绝（业务规则校验失败），但事件一旦产生就不可否认。这个区分是理解事件溯源的关键。


interface Command {
  readonly commandId: string;
  readonly aggregateId: string;
  readonly timestamp: Date;
}

interface CreateOrderCommand extends Command {
  readonly customerId: string;
  readonly items: ReadonlyArray<OrderItem>;
  readonly currency: string;
}

type CommandResult = { success: true; events: ReadonlyArray<DomainEvent> } | { success: false; reason: string };

const handleCommand = async (command: CreateOrderCommand, eventStore: EventStore): Promise<CommandResult> => {
  const events = await eventStore.loadStream(command.aggregateId);
  const aggregate = OrderAggregate.rehydrate(events);
  try {
    aggregate.createOrder(command);
    const newEvents = aggregate.getUncommittedEvents();
    await eventStore.appendToStream(command.aggregateId, newEvents, aggregate.version);
    return { success: true, events: newEvents };
  } catch (error) {
    return { success: false, reason: (error as Error).message };
  }
};
乐观并发控制是事件溯源中处理竞态条件的标准方式。写入事件时附带预期版本号，如果事件存储中的当前版本不匹配，说明有其他进程已经写入了新事件，此时写入操作失败，调用方需要重新加载并重试。


小结
    

  • 事件溯源将状态变更记录为不可变的事件序列，事件是系统中唯一的事实来源
    • 

  • 事件采用过去时态命名，一旦写入不可修改，"撤销"通过追加补偿事件实现
    • 

  • 当前状态通过顺序重放事件序列确定性地重建，同一事件序列始终产生相同状态
    • 

  • 聚合是一致性边界，每个聚合拥有独立事件流，通过业务规则验证来保护不变量
    • 

  • 命令表达操作意图（可被拒绝），事件记录已发生的事实（不可否认）
    • 

  • 乐观并发控制通过版本号检查解决多进程竞态写入问题
    • 

  • 相比 CRUD，事件溯源天然支持审计追踪、时间旅行查询和完整历史回溯，但引入了更高的系统复杂度
    •
