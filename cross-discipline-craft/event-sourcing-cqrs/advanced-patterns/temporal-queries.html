Part II · 架构实践事件溯源与 CQRS 简介高级模式 简介时间旅行查询

时间旅行查询

核心概念

事件溯源天然保留了系统的完整历史——每一个状态变更都以事件的形式永久记录。时间旅行查询（Temporal Query）利用这个特性，允许查询系统在任意历史时间点的状态。这不仅仅是技术上的可能，更是审计追踪、合规检查和业务分析的刚性需求。





时间查询类型
含义
典型场景





时间点查询
某时刻的状态快照
"昨天该账户余额是多少"




时间范围查询
一段时间内的状态变化
"上周订单状态的所有变更"




因果查询
导致某状态的事件链
"这笔退款是由哪些操作触发的"




假设查询
如果某事件未发生的状态
"如果没有那次折扣，总额是多少"




差异查询
两个时间点的状态差异
"本月与上月的库存变化"





传统 CRUD 系统要实现时间旅行查询需要额外的历史表和触发器，而事件溯源系统天然具备这个能力——只需要重放到指定时间点即可。


双时间轴模型
在复杂的审计场景中，需要区分两个独立的时间维度：事实时间（Valid Time / Business Time）是事件在业务世界中实际发生的时间，记录时间（Transaction Time / System Time）是事件被系统记录的时间。二者可能不同——例如，周五发生的退货可能在周一才被录入系统。


interface BitemporalEvent extends DomainEvent {
  readonly validTime: Date;
  readonly transactionTime: Date;
}

interface BitemporalQuery {
  readonly asOfValidTime?: Date;
  readonly asOfTransactionTime?: Date;
}

interface BitemporalEventStore {
  appendToStream(streamId: string, events: ReadonlyArray<BitemporalEvent>, expectedVersion: number): Promise<void>;

  readStreamAsOf(streamId: string, query: BitemporalQuery): Promise<ReadonlyArray<BitemporalEvent>>;
}

const createBitemporalEventStore = (baseStore: EventStore): BitemporalEventStore => ({
  async appendToStream(streamId, events, expectedVersion) {
    const enrichedEvents = events.map((e) => ({
      ...e,
      transactionTime: new Date(),
      validTime: e.validTime ?? new Date(),
    }));
    await baseStore.appendToStream(streamId, enrichedEvents, expectedVersion);
  },

  async readStreamAsOf(streamId, query) {
    const allEvents = await baseStore.readStream(streamId);
    const bitemporalEvents = allEvents as ReadonlyArray<BitemporalEvent>;

    return bitemporalEvents.filter((e) => {
      const validTimeOk = !query.asOfValidTime || e.validTime <= query.asOfValidTime;
      const txTimeOk = !query.asOfTransactionTime || e.transactionTime <= query.asOfTransactionTime;
      return validTimeOk && txTimeOk;
    });
  },
});
双时间轴的查询组合有四种：当前事实/当前记录（即实时状态）、历史事实/当前记录（业务时间旅行）、当前事实/历史记录（系统时间旅行）、历史事实/历史记录（完全历史回溯）。金融和医疗系统经常需要第四种组合来满足合规审计要求。


历史状态查询实现
实现时间旅行查询的核心是将事件重放截止到指定时间点。对于频繁的历史查询，可以预先构建时间索引的投影来加速。


interface TemporalQueryService {
  getStateAt<T>(
    streamId: string,
    timestamp: Date,
    rehydrator: (events: ReadonlyArray<PersistedEvent>) => T,
  ): Promise<T>;

  getStatesBetween<T>(
    streamId: string,
    from: Date,
    to: Date,
    rehydrator: (events: ReadonlyArray<PersistedEvent>) => T,
  ): Promise<ReadonlyArray<{ timestamp: Date; state: T }>>;

  diff<T>(
    streamId: string,
    time1: Date,
    time2: Date,
    rehydrator: (events: ReadonlyArray<PersistedEvent>) => T,
    comparator: (a: T, b: T) => StateDiff<T>,
  ): Promise<StateDiff<T>>;
}

const createTemporalQueryService = (eventStore: EventStore): TemporalQueryService => ({
  async getStateAt(streamId, timestamp, rehydrator) {
    const allEvents = await eventStore.readStream(streamId);
    const eventsUpTo = allEvents.filter((e) => e.timestamp <= timestamp);
    return rehydrator(eventsUpTo);
  },

  async getStatesBetween(streamId, from, to, rehydrator) {
    const allEvents = await eventStore.readStream(streamId);
    const snapshots: Array<{ timestamp: Date; state: ReturnType<typeof rehydrator> }> = [];
    const eventsInRange = allEvents.filter((e) => e.timestamp >= from && e.timestamp <= to);

    let cumulativeEvents = allEvents.filter((e) => e.timestamp < from);

    for (const event of eventsInRange) {
      cumulativeEvents = [...cumulativeEvents, event];
      snapshots.push({
        timestamp: event.timestamp,
        state: rehydrator(cumulativeEvents),
      });
    }

    return snapshots;
  },

  async diff(streamId, time1, time2, rehydrator, comparator) {
    const state1 = await this.getStateAt(streamId, time1, rehydrator);
    const state2 = await this.getStateAt(streamId, time2, rehydrator);
    return comparator(state1, state2);
  },
});
对于大数据量的历史查询，每次都从头重放事件效率太低。优化策略包括：定期快照（减少重放起点）、时间索引投影（预计算关键时间点的状态）、以及分层缓存（热门历史查询结果缓存）。


审计追踪
审计追踪是时间旅行查询最重要的应用场景。事件溯源系统的不可变事件流天然构成了一个完整的审计日志——谁在什么时候做了什么操作，产生了什么结果。


interface AuditEntry {
  readonly eventId: string;
  readonly timestamp: Date;
  readonly actor: string;
  readonly action: string;
  readonly resourceType: string;
  readonly resourceId: string;
  readonly before: Record<string, unknown> | null;
  readonly after: Record<string, unknown>;
  readonly metadata: AuditMetadata;
}

interface AuditMetadata {
  readonly ipAddress: string;
  readonly userAgent: string;
  readonly correlationId: string;
  readonly sessionId: string;
}

const createAuditProjection = (auditStore: AuditStore): Projection<null> => ({
  projectionName: 'audit-trail',
  initialState: null,

  handle(_state, event) {
    const metadata = event.metadata as unknown as AuditMetadata;
    const auditEntry: AuditEntry = {
      eventId: event.eventId,
      timestamp: event.timestamp,
      actor: metadata.sessionId ?? 'system',
      action: event.eventType,
      resourceType: event.streamId.split('-')[0],
      resourceId: event.streamId,
      before: null,
      after: JSON.parse(event.data.toString()),
      metadata,
    };
    auditStore.append(auditEntry);
    return null;
  },
});

interface AuditQueryService {
  getAuditTrail(
    resourceId: string,
    options?: { from?: Date; to?: Date; actor?: string },
  ): Promise<ReadonlyArray<AuditEntry>>;

  getActorActivity(actor: string, from: Date, to: Date): Promise<ReadonlyArray<AuditEntry>>;
}

事件溯源的审计追踪相比传统方案的最大优势是"不可篡改"——事件一旦写入就不能修改或删除。即使是管理员也无法在不留痕迹的情况下修改历史。这在金融监管、医疗合规等场景下具有关键意义。


小结
    

  • 事件溯源天然支持时间旅行查询——只需将事件重放截止到指定时间点
    • 

  • 双时间轴模型区分事实时间和记录时间，满足金融、医疗等领域的合规审计需求
    • 

  • 审计追踪是时间旅行查询最重要的应用，事件溯源的不可变性保证了日志不可篡改
    • 

  • 历史查询的性能优化依赖快照、时间索引投影和分层缓存
    • 

  • 差异查询通过对比两个时间点的重放结果，揭示状态在特定时段内的变化
    • 

  • 时间旅行还能用于假设分析——通过排除或修改特定事件来模拟替代历史
    •
