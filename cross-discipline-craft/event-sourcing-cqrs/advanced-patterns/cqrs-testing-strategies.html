CQRS 测试策略

核心概念

CQRS 和事件溯源系统的测试与传统 CRUD 应用有本质区别。命令端的测试验证"给定历史事件 + 命令 → 产生正确的新事件"，投影端的测试验证"给定事件序列 → 生成正确的读模型"。这种基于事件的测试范式被称为 Given-When-Then 模式，它使测试变得异常清晰和确定性。

事件溯源测试的核心优势是确定性——同一输入始终产生同一输出，没有数据库状态依赖，没有时间敏感逻辑（时间可以注入），没有外部服务调用（通过接口抽象）。


命令端测试
命令端测试的 Given-When-Then 模式：Given（给定历史事件建立聚合初始状态），When（执行命令），Then（验证产生的新事件或错误）。


interface AggregateTestFixture<TAggregate, TState> {
  given(...events: ReadonlyArray<DomainEvent>): AggregateTestFixture<TAggregate, TState>;
  when(command: Command): AggregateTestResult;
}

interface AggregateTestResult {
  thenExpectEvents(...expectedEvents: ReadonlyArray<Partial<DomainEvent>>): void;
  thenExpectError(errorMessage: string): void;
  thenExpectNoEvents(): void;
}

const createAggregateTestFixture = <TState>(
  aggregateFactory: () => EventSourcedAggregate<TState>,
  commandHandler: (aggregate: EventSourcedAggregate<TState>, command: Command) => void,
): AggregateTestFixture<EventSourcedAggregate<TState>, TState> => {
  let givenEvents: DomainEvent[] = [];

  const fixture: AggregateTestFixture<EventSourcedAggregate<TState>, TState> = {
    given(...events) {
      givenEvents = [...events];
      return fixture;
    },

    when(command) {
      const aggregate = aggregateFactory();
      for (const event of givenEvents) {
        aggregate.apply(event);
      }

      let producedEvents: DomainEvent[] = [];
      let error: Error | null = null;

      try {
        commandHandler(aggregate, command);
        producedEvents = aggregate.getUncommittedEvents();
      } catch (e) {
        error = e as Error;
      }

      return {
        thenExpectEvents(...expected) {
          if (error) throw new Error(`Expected events but got error: ${error.message}`);
          expect(producedEvents.length).toBe(expected.length);
          for (let i = 0; i < expected.length; i++) {
            expect(producedEvents[i]).toMatchObject(expected[i]);
          }
        },
        thenExpectError(message) {
          expect(error).not.toBeNull();
          expect(error!.message).toContain(message);
        },
        thenExpectNoEvents() {
          expect(producedEvents.length).toBe(0);
        },
      };
    },
  };

  return fixture;
};

投影测试
投影测试验证事件序列被正确转换为读模型状态。投影是纯函数，测试极其简单——输入事件序列，验证输出状态。


interface ProjectionTestFixture<TState> {
  given(...events: ReadonlyArray<PersistedEvent>): ProjectionTestFixture<TState>;
  thenExpectState(expected: Partial<TState>): void;
  thenExpectStateAt(key: string, expected: Partial<TState>): void;
}

const createProjectionTestFixture = <TState>(projection: Projection<TState>): ProjectionTestFixture<TState> => {
  let events: PersistedEvent[] = [];
  const states = new Map<string, TState>();

  return {
    given(...givenEvents) {
      events = [...givenEvents];
      return this;
    },

    thenExpectState(expected) {
      let state = projection.initialState;
      for (const event of events) {
        state = projection.handle(state, event);
      }
      expect(state).toMatchObject(expected);
    },

    thenExpectStateAt(key, expected) {
      for (const event of events) {
        const currentState = states.get(key) ?? projection.initialState;
        states.set(key, projection.handle(currentState, event));
      }
      expect(states.get(key)).toMatchObject(expected);
    },
  };
};

const projectionFixture = createProjectionTestFixture(orderSummaryProjection);

projectionFixture
  .given(
    createPersistedEvent('order-1', 'OrderCreated', { items: [item1], totalAmount: 100 }),
    createPersistedEvent('order-1', 'OrderConfirmed', {}),
  )
  .thenExpectState({ status: 'confirmed', total: 100 });
投影测试应覆盖以下场景：单事件处理、多事件状态累积、未知事件类型（应被安全忽略）、重复事件处理（验证幂等性）、以及边界情况（空事件序列、极端数据值）。


端到端验证
端到端测试验证从命令提交到读模型更新的完整流程。由于最终一致性的存在，端到端测试需要处理异步等待和状态轮询。


interface E2ETestContext {
  commandBus: CommandBus;
  queryBus: QueryBus;
  waitForProjection(predicate: () => Promise<boolean>, timeoutMs?: number): Promise<void>;
}

const createE2ETestContext = async (): Promise<E2ETestContext> => {
  const app = await createTestApplication();
  await app.start();

  return {
    commandBus: app.commandBus,
    queryBus: app.queryBus,

    async waitForProjection(predicate, timeoutMs = 5000) {
      const deadline = Date.now() + timeoutMs;
      while (Date.now() < deadline) {
        if (await predicate()) return;
        await new Promise((r) => setTimeout(r, 50));
      }
      throw new Error('Projection did not converge within timeout');
    },
  };
};

const testOrderCreationE2E = async () => {
  const ctx = await createE2ETestContext();

  const result = await ctx.commandBus.dispatch({
    type: 'CreateOrder',
    aggregateId: 'order-e2e-1',
    customerId: 'customer-1',
    items: [{ productId: 'p1', quantity: 2, unitPrice: 50 }],
    timestamp: new Date(),
  });

  expect(result.success).toBe(true);

  await ctx.waitForProjection(async () => {
    const orders = await ctx.queryBus.execute({
      type: 'OrderList',
      customerId: 'customer-1',
      page: 1,
      pageSize: 10,
    });
    return (orders as { items: unknown[] }).items.length > 0;
  });

  const detail = await ctx.queryBus.execute({
    type: 'OrderDetail',
    orderId: 'order-e2e-1',
  });

  expect(detail).toMatchObject({
    orderId: 'order-e2e-1',
    status: 'created',
  });
};

小结
    

  • Given-When-Then 模式是事件溯源测试的核心范式：给定历史 → 执行操作 → 验证结果
    • 

  • 命令端测试验证"历史事件 + 命令 → 新事件"，投影测试验证"事件序列 → 读模型状态"
    • 

  • 事件溯源测试天然具有确定性——同一输入始终产生同一输出，无外部状态依赖
    • 

  • 端到端测试需要处理最终一致性的异步性，通过轮询等待投影收敛
    • 

  • 测试应分层组织：聚合单元测试覆盖业务逻辑，投影测试覆盖读模型，集成测试覆盖管道
    • 

  • 测试夹具和事件工厂是提高测试效率的关键工具
