Part II · 架构实践事件溯源与 CQRS 简介实战应用 简介金融系统审计追踪

金融系统审计追踪

核心概念

金融系统对数据完整性和可追溯性有最严格的要求。每一笔交易、每一次余额变动、每一个审批操作都必须留下不可篡改的记录。事件溯源的不可变追加语义与金融系统的审计需求天然契合——事件流就是账本，事件就是凭证，重放就是核账。

金融系统选择事件溯源的核心动机不是性能，而是合规——监管机构要求金融操作的完整可追溯性和不可篡改性。传统方案需要额外机制来满足这些要求，而事件溯源在架构层面就天然提供了这些保证。


账本模型
复式记账法是金融系统的基石。在事件溯源中，每一笔交易表示为一个或多个事件，每个事件记录借方和贷方的变动，保证"有借必有贷，借贷必相等"。


interface LedgerEntry {
  readonly entryId: string;
  readonly transactionId: string;
  readonly accountId: string;
  readonly direction: 'debit' | 'credit';
  readonly amount: number;
  readonly currency: string;
  readonly balanceAfter: number;
  readonly timestamp: Date;
  readonly description: string;
}

interface AccountState {
  readonly accountId: string;
  readonly balance: number;
  readonly currency: string;
  readonly status: 'active' | 'frozen' | 'closed';
  readonly lastTransactionAt: Date | null;
}

class AccountAggregate {
  private state: AccountState;
  private events: DomainEvent[] = [];

  debit(transactionId: string, amount: number, description: string): void {
    if (this.state.status !== 'active') {
      throw new Error('账户非活跃状态，无法借记');
    }
    if (this.state.balance < amount) {
      throw new Error(`余额不足: 当前 ${this.state.balance}，需要 ${amount}`);
    }
    this.raiseEvent({
      eventType: 'AccountDebited',
      payload: {
        transactionId,
        amount,
        balanceAfter: this.state.balance - amount,
        description,
      },
    });
  }

  credit(transactionId: string, amount: number, description: string): void {
    if (this.state.status !== 'active') {
      throw new Error('账户非活跃状态，无法贷记');
    }
    this.raiseEvent({
      eventType: 'AccountCredited',
      payload: {
        transactionId,
        amount,
        balanceAfter: this.state.balance + amount,
        description,
      },
    });
  }

  freeze(reason: string, frozenBy: string): void {
    if (this.state.status !== 'active') {
      throw new Error('只能冻结活跃账户');
    }
    this.raiseEvent({
      eventType: 'AccountFrozen',
      payload: { reason, frozenBy, frozenAt: new Date().toISOString() },
    });
  }

  private applyEvent(event: DomainEvent): void {
    const payload = event.payload as Record<string, unknown>;
    switch (event.eventType) {
      case 'AccountDebited':
        this.state = {
          ...this.state,
          balance: payload.balanceAfter as number,
          lastTransactionAt: event.timestamp,
        };
        break;
      case 'AccountCredited':
        this.state = {
          ...this.state,
          balance: payload.balanceAfter as number,
          lastTransactionAt: event.timestamp,
        };
        break;
      case 'AccountFrozen':
        this.state = { ...this.state, status: 'frozen' };
        break;
    }
  }

  private raiseEvent(partial: Partial<DomainEvent>): void {
    const event = {
      ...partial,
      eventId: crypto.randomUUID(),
      aggregateId: this.state.accountId,
      timestamp: new Date(),
    } as DomainEvent;
    this.applyEvent(event);
    this.events.push(event);
  }
}
每个借记/贷记事件都记录了操作后的余额（balanceAfter）——这是金融系统的关键设计。通过对比连续事件的 balanceAfter 值，可以快速验证余额计算的正确性，无需从头重放整个事件流。


合规审计
合规审计要求系统能够回答以下问题：谁在什么时候对哪个账户做了什么操作？操作前后账户状态如何变化？一系列关联操作的因果链是什么？


interface ComplianceAuditRecord {
  readonly auditId: string;
  readonly timestamp: Date;
  readonly actor: AuditActor;
  readonly operation: string;
  readonly target: AuditTarget;
  readonly context: AuditContext;
  readonly outcome: 'success' | 'failure';
  readonly details: Record<string, unknown>;
}

interface AuditActor {
  readonly userId: string;
  readonly role: string;
  readonly ipAddress: string;
  readonly sessionId: string;
}

interface AuditTarget {
  readonly entityType: string;
  readonly entityId: string;
  readonly stateBefore: Record<string, unknown> | null;
  readonly stateAfter: Record<string, unknown>;
}

interface AuditContext {
  readonly correlationId: string;
  readonly causationId: string;
  readonly regulatoryScope: ReadonlyArray<string>;
}

const createComplianceProjection = (auditStore: ComplianceAuditStore): Projection<null> => ({
  projectionName: 'compliance-audit',
  initialState: null,

  handle(_state, event) {
    const metadata = event.metadata as unknown as {
      userId: string;
      role: string;
      ipAddress: string;
      sessionId: string;
      correlationId: string;
      causationId: string;
    };

    const record: ComplianceAuditRecord = {
      auditId: crypto.randomUUID(),
      timestamp: event.timestamp,
      actor: {
        userId: metadata.userId ?? 'system',
        role: metadata.role ?? 'system',
        ipAddress: metadata.ipAddress ?? 'internal',
        sessionId: metadata.sessionId ?? '',
      },
      operation: event.eventType,
      target: {
        entityType: event.streamId.split('-')[0],
        entityId: event.streamId,
        stateBefore: null,
        stateAfter: JSON.parse(event.data.toString()),
      },
      context: {
        correlationId: metadata.correlationId,
        causationId: metadata.causationId,
        regulatoryScope: determineRegulatoryScope(event.eventType),
      },
      outcome: 'success',
      details: {},
    };

    auditStore.persist(record);
    return null;
  },
});

const determineRegulatoryScope = (eventType: string): ReadonlyArray<string> => {
  const scopes: Record<string, ReadonlyArray<string>> = {
    AccountDebited: ['AML', 'KYC'],
    AccountCredited: ['AML', 'KYC'],
    AccountFrozen: ['AML', 'COMPLIANCE'],
    LargeTransfer: ['AML', 'CTR', 'SAR'],
  };
  return scopes[eventType] ?? [];
};
合规投影为每个事件生成一条审计记录，包含操作者身份、操作目标、操作上下文和监管范围。correlationId 串联了一个业务流程中的所有相关操作，regulatoryScope 标记了该操作涉及的监管法规（如反洗钱 AML、了解你的客户 KYC）。


不可篡改记录
事件溯源的不可变性在架构层面保证了记录不可篡改。但仅有应用层的保证不够——还需要存储层和密码学层面的加固。


interface TamperProofEvent extends PersistedEvent {
  readonly hash: string;
  readonly previousHash: string;
}

const computeEventHash = (event: PersistedEvent, previousHash: string): string => {
  const content = JSON.stringify({
    eventId: event.eventId,
    streamId: event.streamId,
    eventType: event.eventType,
    version: event.version,
    data: event.data.toString(),
    previousHash,
  });
  return createHash('sha256').update(content).digest('hex');
};

const createTamperProofEventStore = (baseStore: EventStore): EventStore => ({
  async appendToStream(streamId, events, expectedVersion) {
    const existing = await baseStore.readStream(streamId);
    let previousHash = existing.length > 0 ? (existing[existing.length - 1] as TamperProofEvent).hash : '0'.repeat(64);

    const tamperProofEvents = events.map((event) => {
      const hash = computeEventHash(event as PersistedEvent, previousHash);
      previousHash = hash;
      return { ...event, hash, previousHash: hash };
    });

    return baseStore.appendToStream(streamId, tamperProofEvents, expectedVersion);
  },

  readStream: baseStore.readStream,
  readAll: baseStore.readAll,
  subscribe: baseStore.subscribe,
});

const verifyStreamIntegrity = async (
  store: EventStore,
  streamId: string,
): Promise<{ valid: boolean; brokenAt?: number }> => {
  const events = (await store.readStream(streamId)) as ReadonlyArray<TamperProofEvent>;
  let previousHash = '0'.repeat(64);

  for (let i = 0; i < events.length; i++) {
    const expected = computeEventHash(events[i], previousHash);
    if (expected !== events[i].hash) {
      return { valid: false, brokenAt: i };
    }
    previousHash = events[i].hash;
  }
  return { valid: true };
};

哈希链的原理类似区块链——每个事件的哈希包含前一个事件的哈希，形成链式结构。如果任何一个事件被修改，其后所有事件的哈希都会失效，篡改立即可被检测。
