Part II · 架构实践事件溯源与 CQRS 简介实战应用 简介性能与扩展

性能与扩展

核心概念

事件溯源系统在性能和扩展性方面既有天然优势也有独特挑战。写端的追加写入语义天然适合高吞吐量场景，但读端的状态重建和投影同步引入了额外的延迟。CQRS 的读写分离为两端提供了独立的扩展路径——写端可以通过事件流分片扩展写入能力，读端可以通过增加读副本和缓存层扩展查询能力。

扩展策略的核心原则是"按瓶颈扩展"——先识别系统的性能瓶颈点，然后针对性地扩展该层级，而不是盲目地全面扩容。


分片策略
事件流的天然独立性使得分片（Sharding）成为最自然的写端扩展方式。同一聚合的所有事件必须在同一分片上以保证乐观并发控制的正确性。


interface ShardRouter {
  resolveShardId(aggregateId: string): number;
  getShardConnection(shardId: number): EventStoreConnection;
}

const createConsistentHashRouter = (
  shardCount: number,
  connections: ReadonlyArray<EventStoreConnection>,
): ShardRouter => {
  const hashRing = createHashRing(shardCount);

  return {
    resolveShardId(aggregateId) {
      return hashRing.getNode(aggregateId);
    },

    getShardConnection(shardId) {
      return connections[shardId];
    },
  };
};

const createShardedEventStore = (router: ShardRouter): EventStore => ({
  async appendToStream(streamId, events, expectedVersion) {
    const shardId = router.resolveShardId(streamId);
    const connection = router.getShardConnection(shardId);
    return connection.appendToStream(streamId, events, expectedVersion);
  },

  async readStream(streamId, fromVersion, count) {
    const shardId = router.resolveShardId(streamId);
    const connection = router.getShardConnection(shardId);
    return connection.readStream(streamId, fromVersion, count);
  },

  async readAll(fromPosition, count) {
    const allShardEvents = await Promise.all(
      Array.from({ length: router.shardCount }, (_, i) => router.getShardConnection(i).readAll(fromPosition, count)),
    );
    return mergeByGlobalPosition(allShardEvents);
  },

  subscribe(fromPosition, handler) {
    const subscriptions = Array.from({ length: router.shardCount }, (_, i) =>
      router.getShardConnection(i).subscribe(fromPosition, handler),
    );
    return createCompositeSubscription(subscriptions);
  },
});
一致性哈希环确保了在分片数量变化时，只有少量聚合需要迁移。分片后最大的挑战是全局有序读取（readAll）——需要从所有分片拉取事件并按全局位置合并排序，这在大规模系统中可能成为瓶颈。


读模型优化
读模型是 CQRS 系统查询性能的关键。通过为不同查询场景选择最优的存储引擎和索引策略，可以将查询延迟降低到极致。


interface ReadModelOptimizer {
  analyzeQueryPattern(queries: ReadonlyArray<QueryMetric>): OptimizationPlan;
}

interface QueryMetric {
  readonly queryType: string;
  readonly avgLatencyMs: number;
  readonly p99LatencyMs: number;
  readonly qps: number;
  readonly resultSize: number;
}

interface OptimizationPlan {
  readonly recommendations: ReadonlyArray<{
    queryType: string;
    currentStorage: string;
    recommendedStorage: string;
    expectedImprovement: string;
    indexSuggestions: ReadonlyArray<string>;
  }>;
}

const createMultiTierReadModel = (
  primaryStore: ReadDatabase,
  searchEngine: SearchEngine,
  cache: CacheClient,
): QueryRouter => ({
  async route(query: Query) {
    switch (query.type) {
      case 'OrderDetail':
        return this.cacheFirst(query, () => primaryStore.findOne('orders', { id: query.orderId }));
      case 'OrderSearch':
        return searchEngine.search('orders', query.searchTerm, query.filters);
      case 'OrderAnalytics':
        return primaryStore.aggregate('order_analytics', query.dimensions);
      case 'HotProducts':
        return cache.get(`hot-products:${query.period}`);
      default:
        return primaryStore.query(query.type, query);
    }
  },

  async cacheFirst(query: Query, fallback: () => Promise<unknown>) {
    const cacheKey = buildCacheKey(query);
    const cached = await cache.get(cacheKey);
    if (cached) return cached;
    const result = await fallback();
    if (result) await cache.set(cacheKey, result, { ttlMs: 30_000 });
    return result;
  },
});

读模型优化的核心思路是"每种查询模式使用最适合的存储引擎"。这就是 CQRS 读写分离的核心价值——不再被单一数据库的能力边界所限制。


高吞吐设计
在高吞吐场景下（每秒数万到数百万事件），系统需要从写入路径、投影管道和存储引擎三个层面进行优化。


interface BatchProcessor {
  process(events: ReadonlyArray<PersistedEvent>): Promise<void>;
}

const createBatchProjectionRunner = (
  projection: Projection<unknown>,
  store: ProjectionStore<unknown>,
  batchSize: number,
  flushIntervalMs: number,
): BatchProcessor => {
  let buffer: PersistedEvent[] = [];
  let timer: NodeJS.Timeout | null = null;

  const flush = async () => {
    if (buffer.length === 0) return;
    const batch = [...buffer];
    buffer = [];

    const stateUpdates = new Map<string, unknown>();

    for (const event of batch) {
      const key = event.streamId;
      const currentState = stateUpdates.get(key) ?? (await store.getState(key)) ?? projection.initialState;
      stateUpdates.set(key, projection.handle(currentState, event));
    }

    await store.batchSetState(stateUpdates);
    if (batch.length > 0) {
      await store.setCheckpoint(projection.projectionName, batch[batch.length - 1].globalPosition);
    }
  };

  return {
    async process(events) {
      buffer.push(...events);
      if (buffer.length >= batchSize) {
        await flush();
      } else if (!timer) {
        timer = setTimeout(async () => {
          timer = null;
          await flush();
        }, flushIntervalMs);
      }
    },
  };
};

const createParallelProjectionPipeline = (
  eventStore: EventStore,
  projections: ReadonlyArray<{
    projection: Projection<unknown>;
    store: ProjectionStore<unknown>;
  }>,
  partitionCount: number,
): { start: () => Promise<void> } => ({
  async start() {
    const runners = projections.map(({ projection, store }) =>
      createBatchProjectionRunner(projection, store, 500, 100),
    );

    eventStore.subscribe(0n, async (event) => {
      await Promise.all(runners.map((runner) => runner.process([event])));
    });
  },
});
批量处理是高吞吐设计的核心——将单个事件的逐一处理聚合为批量操作，显著减少 I/O 次数。配合异步管道和背压控制，可以在不丢失数据的前提下处理突发流量。


小结
    

  • CQRS 的读写分离为两端提供了独立的扩展路径，按瓶颈针对性扩展
    • 

  • 事件流分片通过一致性哈希保证同一聚合的事件在同一分片，支持写端水平扩展
    • 

  • 读模型优化的核心是"每种查询模式使用最适合的存储引擎"
    • 

  • 高吞吐设计的关键是批量处理——将逐条处理聚合为批量操作，减少 I/O 次数
    • 

  • 分片后的全局有序读取是最大挑战，需要多分片合并排序
    • 

  • 分层缓存（内存 → Redis → 读数据库）确保各级查询都有合理的性能表现
