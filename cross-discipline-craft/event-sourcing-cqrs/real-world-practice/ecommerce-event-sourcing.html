Part II · 架构实践事件溯源与 CQRS 简介实战应用 简介电商系统事件溯源

电商系统事件溯源

核心概念

电商系统是事件溯源和 CQRS 最经典的应用场景之一。订单从创建到完成经历多个状态迁转，每一步都涉及库存、支付、物流等多个聚合的协调。事件溯源天然适合这种状态机驱动的业务——每个状态变更都是一个不可逆的业务事实，完整的事件流为客服追溯、财务对账和纠纷处理提供了坚实的数据基础。





聚合
核心事件
不变量





订单（Order）
Created, Confirmed, Shipped, Delivered
已发货不可取消




库存（Inventory）
Reserved, Released, Deducted
可用库存不能为负




支付（Payment）
Authorized, Captured, Refunded
退款不超过支付金额




物流（Shipment）
Created, PickedUp, InTransit, Delivered
状态只能前进




购物车（Cart）
ItemAdded, ItemRemoved, Cleared
数量必须为正





电商事件溯源的核心挑战是跨聚合协调——订单创建时需要同时锁定库存和发起支付，任何一步失败都需要回滚已完成的步骤。这正是 Saga 模式发挥作用的场景。


订单流建模
订单是电商系统的核心聚合，其事件流完整记录了从下单到完成的每一步操作。


type OrderStatus = 'created' | 'paid' | 'preparing' | 'shipped' | 'delivered' | 'cancelled' | 'refunding' | 'refunded';

interface OrderState {
  readonly orderId: string;
  readonly customerId: string;
  readonly items: ReadonlyArray<OrderItem>;
  readonly totalAmount: number;
  readonly status: OrderStatus;
  readonly paymentId: string | null;
  readonly shipmentId: string | null;
  readonly createdAt: Date;
}

class OrderAggregate {
  private state: OrderState;
  private events: DomainEvent[] = [];

  static create(command: CreateOrderCommand): OrderAggregate {
    const order = new OrderAggregate();
    order.raiseEvent({
      eventType: 'OrderCreated',
      payload: {
        customerId: command.customerId,
        items: command.items,
        totalAmount: command.items.reduce((sum, item) => sum + item.unitPrice * item.quantity, 0),
        shippingAddress: command.shippingAddress,
      },
    });
    return order;
  }

  markPaid(paymentId: string): void {
    this.assertStatus('created');
    this.raiseEvent({
      eventType: 'OrderPaid',
      payload: { paymentId, paidAt: new Date().toISOString() },
    });
  }

  ship(shipmentId: string, carrier: string, trackingNumber: string): void {
    this.assertStatus('preparing');
    this.raiseEvent({
      eventType: 'OrderShipped',
      payload: { shipmentId, carrier, trackingNumber, shippedAt: new Date().toISOString() },
    });
  }

  cancel(reason: string): void {
    if (this.state.status === 'shipped' || this.state.status === 'delivered') {
      throw new Error('已发货订单不能直接取消');
    }
    this.raiseEvent({
      eventType: 'OrderCancelled',
      payload: { reason, cancelledAt: new Date().toISOString() },
    });
  }

  private assertStatus(expected: OrderStatus): void {
    if (this.state.status !== expected) {
      throw new Error(`期望状态 ${expected}，实际 ${this.state.status}`);
    }
  }

  private raiseEvent(partial: Partial<DomainEvent>): void {
    const event = { ...partial, eventId: crypto.randomUUID(), timestamp: new Date() } as DomainEvent;
    this.applyEvent(event);
    this.events.push(event);
  }

  private applyEvent(event: DomainEvent): void {
    switch (event.eventType) {
      case 'OrderCreated':
        this.state = {
          ...event.payload,
          orderId: event.aggregateId,
          status: 'created',
          paymentId: null,
          shipmentId: null,
          createdAt: event.timestamp,
        } as OrderState;
        break;
      case 'OrderPaid':
        this.state = { ...this.state, status: 'paid', paymentId: (event.payload as { paymentId: string }).paymentId };
        break;
      case 'OrderShipped':
        this.state = {
          ...this.state,
          status: 'shipped',
          shipmentId: (event.payload as { shipmentId: string }).shipmentId,
        };
        break;
      case 'OrderCancelled':
        this.state = { ...this.state, status: 'cancelled' };
        break;
    }
  }
}
订单聚合通过 assertStatus 方法保护状态转换的合法性——已发货的订单不能取消，未支付的订单不能发货。这些不变量在命令端强制执行，确保事件流中不会出现非法的状态转换。


库存管理
库存聚合需要保证"可用库存不为负"的核心不变量。在事件溯源中，库存变动被记录为 Reserved、Released、Deducted 等事件。


interface InventoryState {
  readonly productId: string;
  readonly totalStock: number;
  readonly reservedStock: number;
  readonly availableStock: number;
}

class InventoryAggregate {
  private state: InventoryState;

  reserve(orderId: string, quantity: number): void {
    if (this.state.availableStock < quantity) {
      throw new Error(`库存不足: 可用 ${this.state.availableStock}, 需要 ${quantity}`);
    }
    this.raiseEvent({
      eventType: 'InventoryReserved',
      payload: { orderId, quantity, productId: this.state.productId },
    });
  }

  release(orderId: string, quantity: number): void {
    this.raiseEvent({
      eventType: 'InventoryReleased',
      payload: { orderId, quantity, productId: this.state.productId },
    });
  }

  deduct(orderId: string, quantity: number): void {
    this.raiseEvent({
      eventType: 'InventoryDeducted',
      payload: { orderId, quantity, productId: this.state.productId },
    });
  }

  private applyEvent(event: DomainEvent): void {
    const payload = event.payload as { quantity: number };
    switch (event.eventType) {
      case 'InventoryReserved':
        this.state = {
          ...this.state,
          reservedStock: this.state.reservedStock + payload.quantity,
          availableStock: this.state.availableStock - payload.quantity,
        };
        break;
      case 'InventoryReleased':
        this.state = {
          ...this.state,
          reservedStock: this.state.reservedStock - payload.quantity,
          availableStock: this.state.availableStock + payload.quantity,
        };
        break;
      case 'InventoryDeducted':
        this.state = {
          ...this.state,
          reservedStock: this.state.reservedStock - payload.quantity,
          totalStock: this.state.totalStock - payload.quantity,
        };
        break;
    }
  }
}
支付状态机
支付聚合管理支付的全生命周期：授权 → 捕获 → 可能的退款。支付事件与第三方支付网关的回调紧密关联。


type PaymentStatus = 'pending' | 'authorized' | 'captured' | 'refunding' | 'refunded' | 'failed';

interface PaymentState {
  readonly paymentId: string;
  readonly orderId: string;
  readonly amount: number;
  readonly currency: string;
  readonly status: PaymentStatus;
  readonly gatewayTransactionId: string | null;
  readonly refundedAmount: number;
}

class PaymentAggregate {
  private state: PaymentState;

  authorize(gatewayTransactionId: string): void {
    this.assertStatus('pending');
    this.raiseEvent({
      eventType: 'PaymentAuthorized',
      payload: { gatewayTransactionId, authorizedAt: new Date().toISOString() },
    });
  }

  capture(): void {
    this.assertStatus('authorized');
    this.raiseEvent({
      eventType: 'PaymentCaptured',
      payload: { capturedAt: new Date().toISOString(), amount: this.state.amount },
    });
  }

  refund(amount: number, reason: string): void {
    if (this.state.status !== 'captured') {
      throw new Error('只能退款已捕获的支付');
    }
    if (this.state.refundedAmount + amount > this.state.amount) {
      throw new Error('退款金额超过支付金额');
    }
    this.raiseEvent({
      eventType: 'PaymentRefunded',
      payload: { amount, reason, refundedAt: new Date().toISOString() },
    });
  }

  private assertStatus(expected: PaymentStatus): void {
    if (this.state.status !== expected) {
      throw new Error(`支付状态错误: 期望 ${expected}，实际 ${this.state.status}`);
    }
  }
}
支付的"退款不超过支付金额"不变量通过累计退款金额来保护。部分退款是常见需求——一个支付可能对应多次部分退款事件，但总退款金额不能超过原始支付金额。


小结
    

  • 订单、库存、支付作为独立聚合，各自维护核心不变量
    • 

  • 订单状态机通过 assertStatus 在命令端强制合法状态转换
    • 

  • 库存聚合通过预留-释放-扣减三步操作保证可用库存不为负
    • 

  • 支付聚合通过累计退款金额防止退款超额
    • 

  • 跨聚合协调通过 Saga 实现：库存预留 → 支付处理 → 订单确认，任意步骤失败触发补偿
    • 

  • 完整的事件流为客服追溯、财务对账和纠纷处理提供了可靠的数据基础
    •
