CQRS 实现

核心概念

CQRS 实现将命令查询分离原则落地为具体的代码架构。一个完整的 CQRS 系统由三大核心组件构成：命令处理器（Command Handler）负责验证和执行写操作，查询服务（Query Service）负责从读模型获取数据，中间件编排层（Middleware Pipeline）负责横切关注点的统一处理。

CQRS 实现的关键设计原则是保持命令和查询路径的完全独立——它们共享的只有事件（从命令端流向查询端），不共享任何运行时状态或数据库连接。


命令处理器实现
命令处理器是 CQRS 写端的核心。每个命令类型对应一个处理器，处理器遵循统一的模式：验证命令 → 加载聚合 → 执行业务逻辑 → 持久化事件。


interface CommandHandler<TCommand extends Command = Command> {
  readonly commandType: string;
  validate(command: TCommand): ValidationResult;
  handle(command: TCommand): Promise<CommandResult>;
}

interface ValidationResult {
  readonly valid: boolean;
  readonly errors: ReadonlyArray<string>;
}

const createOrderCommandHandler = (
  repository: AggregateRepository<OrderAggregate>,
  eventPublisher: EventPublisher,
): CommandHandler<CreateOrderCommand> => ({
  commandType: 'CreateOrder',

  validate(command) {
    const errors: string[] = [];
    if (!command.customerId) errors.push('customerId is required');
    if (!command.items || command.items.length === 0) errors.push('At least one item required');
    if (command.items?.some((i) => i.quantity <= 0)) errors.push('Quantity must be positive');
    return { valid: errors.length === 0, errors };
  },

  async handle(command) {
    const validation = this.validate(command);
    if (!validation.valid) {
      return { success: false, error: validation.errors.join('; ') };
    }

    const aggregate = OrderAggregate.create({
      orderId: command.aggregateId,
      customerId: command.customerId,
      items: command.items,
    });

    const events = aggregate.getUncommittedEvents();
    await repository.save(aggregate);
    await eventPublisher.publishAll(events);

    return { success: true, eventIds: events.map((e) => e.eventId) };
  },
});

const createCommandDispatcher = (handlers: ReadonlyArray<CommandHandler>): CommandBus => {
  const handlerMap = new Map(handlers.map((h) => [h.commandType, h]));

  return {
    async dispatch(command) {
      const handler = handlerMap.get(command.type);
      if (!handler) {
        return { success: false, error: `Unknown command type: ${command.type}` };
      }
      return handler.handle(command);
    },
  };
};
命令处理器的一个重要设计约束是单聚合事务：每个命令只修改一个聚合。跨聚合的操作通过 Saga 或流程管理器实现，而不是在单个命令中操作多个聚合。


查询服务实现
查询服务从读模型中检索数据。与命令处理器不同，查询服务不产生副作用，不修改任何状态——它是一个纯粹的数据读取层。


interface QueryService<TQuery extends Query, TResult> {
  readonly queryType: string;
  handle(query: TQuery): Promise<TResult>;
}

const createOrderListService = (
  readDb: ReadDatabase,
): QueryService<OrderListQuery, PaginatedResult<OrderListItem>> => ({
  queryType: 'OrderList',

  async handle(query) {
    const { filters, sort, pagination } = buildQueryParams(query);

    const [items, total] = await Promise.all([
      readDb.find('order_list', { filters, sort, ...pagination }),
      readDb.count('order_list', { filters }),
    ]);

    return {
      items,
      total,
      page: query.page,
      pageSize: query.pageSize,
      totalPages: Math.ceil(total / query.pageSize),
    };
  },
});

const createOrderDetailService = (
  readDb: ReadDatabase,
  cache: CacheClient,
): QueryService<OrderDetailQuery, OrderDetail | null> => ({
  queryType: 'OrderDetail',

  async handle(query) {
    const cacheKey = `order:${query.orderId}`;
    const cached = await cache.get<OrderDetail>(cacheKey);
    if (cached) return cached;

    const detail = await readDb.findOne<OrderDetail>('order_detail', {
      orderId: query.orderId,
    });

    if (detail) {
      await cache.set(cacheKey, detail, { ttlMs: 60_000 });
    }
    return detail;
  },
});

const createQueryDispatcher = (services: ReadonlyArray<QueryService<Query, unknown>>): QueryBus => {
  const serviceMap = new Map(services.map((s) => [s.queryType, s]));

  return {
    async execute(query) {
      const service = serviceMap.get(query.type);
      if (!service) {
        throw new Error(`Unknown query type: ${query.type}`);
      }
      return service.handle(query);
    },
  };
};
查询服务可以自由使用缓存、并行查询等优化手段，因为它没有副作用，不需要担心缓存一致性（读模型本身已经是最终一致的）。


中间件编排
中间件管道为命令和查询路径提供横切关注点的统一处理。命令路径和查询路径的中间件栈通常不同——命令路径更关注安全性和事务性，查询路径更关注性能。


type Middleware<T, R> = (input: T, next: (input: T) => Promise<R>) => Promise<R>;

const createLoggingMiddleware = <T extends { type: string }, R>(logger: Logger): Middleware<T, R> => {
  return async (input, next) => {
    const start = performance.now();
    logger.info(`Processing ${input.type}`);
    try {
      const result = await next(input);
      logger.info(`Completed ${input.type} in ${performance.now() - start}ms`);
      return result;
    } catch (error) {
      logger.error(`Failed ${input.type}:`, error);
      throw error;
    }
  };
};

const createRetryMiddleware = <T, R>(maxRetries: number, retryableErrors: ReadonlyArray<string>): Middleware<T, R> => {
  return async (input, next) => {
    for (let attempt = 0; attempt <= maxRetries; attempt++) {
      try {
        return await next(input);
      } catch (error) {
        const isRetryable = retryableErrors.some((e) => (error as Error).message.includes(e));
        if (!isRetryable || attempt === maxRetries) throw error;
        await new Promise((r) => setTimeout(r, Math.pow(2, attempt) * 100));
      }
    }
    throw new Error('Unreachable');
  };
};

const composePipeline = <T, R>(
  middlewares: ReadonlyArray<Middleware<T, R>>,
  handler: (input: T) => Promise<R>,
): ((input: T) => Promise<R>) => {
  return middlewares.reduceRight((next, middleware) => (input: T) => middleware(input, next), handler);
};
中间件的组合是通过函数组合实现的——每个中间件接收一个 next 函数（下一个中间件），在调用 next 前后可以插入自己的逻辑。这种洋葱模型使得添加新的横切关注点只需要注册一个新的中间件，无需修改已有代码。


完整组装
将命令处理器、查询服务和中间件组装成一个完整的 CQRS 应用：


interface CqrsApplication {
  readonly commandBus: CommandBus;
  readonly queryBus: QueryBus;
  start(): Promise<void>;
  stop(): Promise<void>;
}

const createCqrsApplication = (config: CqrsConfig): CqrsApplication => {
  const eventStore = createEventStore(config.eventStore);
  const eventPublisher = createEventPublisher(config.messageBroker);
  const readDb = createReadDatabase(config.readStore);

  const commandHandlers = [
    createOrderCommandHandler(createOrderRepository(eventStore), eventPublisher),
    createConfirmOrderHandler(createOrderRepository(eventStore), eventPublisher),
  ];

  const queryServices = [
    createOrderListService(readDb),
    createOrderDetailService(readDb, createCacheClient(config.cache)),
  ];

  const commandPipeline = composePipeline(
    [createLoggingMiddleware(logger), createRetryMiddleware(3, ['WrongExpectedVersion'])],
    createCommandDispatcher(commandHandlers).dispatch,
  );

  const queryPipeline = composePipeline(
    [createLoggingMiddleware(logger)],
    createQueryDispatcher(queryServices).execute,
  );

  return {
    commandBus: { dispatch: commandPipeline },
    queryBus: { execute: queryPipeline },
    async start() {
      await eventStore.connect();
      await readDb.connect();
    },
    async stop() {
      await eventStore.disconnect();
      await readDb.disconnect();
    },
  };
};
小结
    

  • 命令处理器遵循统一模式：验证 → 加载聚合 → 执行逻辑 → 持久化事件 → 发布
    • 

  • 查询服务是纯数据读取层，无副作用，可自由使用缓存和并行查询
    • 

  • 中间件通过函数组合实现洋葱模型，命令路径和查询路径使用不同的中间件栈
    • 

  • 命令处理器的关键约束是单聚合事务，跨聚合操作通过 Saga 实现
    • 

  • 完整的 CQRS 应用通过依赖注入将所有组件组装，管道组合使得扩展只需注册新中间件
    •
