Markdown 与 MDX 管道

核心概念

Markdown 与 MDX 管道是 Docs-as-Code 体系中的内容处理核心——它将开发者编写的纯文本标记转换为结构化的 HTML 页面，并在此过程中完成语法高亮、数学公式渲染、目录生成、组件注入等一系列增强处理。理解管道的工作原理，是构建高质量文档站的基础。

Markdown 和 MDX 在文档工程中扮演不同角色：

unified 生态与插件体系
现代 Markdown 处理管道几乎都构建在 unified 生态之上。unified 是一个通用的文本处理框架，通过标准化的 AST（抽象语法树）格式和插件接口，将解析、转换和序列化解耦为独立的可组合步骤。


unified 生态的核心组件包括三个层次：


remark 层负责 Markdown 的解析和转换。remark-parse 将 Markdown 文本解析为 MDAST（Markdown AST），remark 插件在 MDAST 上进行各种转换操作。常用的 remark 插件包括：remark-gfm（GitHub Flavored Markdown 支持）、remark-math（数学公式识别）、remark-frontmatter（YAML front matter 解析）、remark-toc（自动目录生成）。


rehype 层负责 HTML 的处理和增强。remark-rehype 将 MDAST 转换为 HAST（HTML AST），rehype 插件在 HAST 上进行 HTML 级别的转换。常用的 rehype 插件包括：rehype-highlight / rehype-shiki（代码语法高亮）、rehype-katex（数学公式渲染）、rehype-slug（标题锚点）、rehype-autolink-headings（标题自动链接）。


序列化层将处理后的 AST 转换为最终输出。rehype-stringify 输出 HTML 字符串，rehype-react 输出 React 元素树。


import { unified } from 'unified';
import remarkParse from 'remark-parse';
import remarkGfm from 'remark-gfm';
import remarkMath from 'remark-math';
import remarkRehype from 'remark-rehype';
import rehypeKatex from 'rehype-katex';
import rehypeShiki from '@shikijs/rehype';
import rehypeStringify from 'rehype-stringify';

const processor = unified()
  .use(remarkParse)
  .use(remarkGfm)
  .use(remarkMath)
  .use(remarkRehype)
  .use(rehypeKatex)
  .use(rehypeShiki, { theme: 'github-dark' })
  .use(rehypeStringify);

const result = await processor.process(markdownContent);
插件的执行顺序至关重要。remark 插件必须在 remark-rehype 之前注册，rehype 插件必须在之后注册。同层插件的顺序也会影响结果——例如 remark-math 必须在 remark-rehype 之前运行，否则数学公式将作为普通文本转换为 HTML。


MDX 编译流程
MDX 在 Markdown 基础上引入了 JSX 支持，使文档可以嵌入交互式组件。MDX 的编译流程比纯 Markdown 更复杂，因为它需要处理两种语法的混合。


MDX 编译器（@mdx-js/mdx）的工作流程分为三个阶段：


解析阶段：MDX 解析器同时识别 Markdown 语法和 JSX 语法，生成包含两种节点类型的混合 AST。JSX 表达式和组件标签被识别为特殊节点类型（mdxJsxFlowElement、mdxJsxTextElement）。


转换阶段：与纯 Markdown 类似，MDX 也支持 remark 和 rehype 插件。但插件需要能正确处理 JSX 节点，避免将组件标签误当作 HTML 元素处理。


代码生成阶段：MDX 编译器将混合 AST 转换为 JavaScript 模块代码。每个 MDX 文件被编译为一个导出 React 组件的 ES Module，Markdown 内容转换为 JSX 元素，嵌入的组件保留为 JSX 调用。


MDX 的组件映射机制是其最强大的特性之一。通过 MDXProvider 或 components prop，可以将 Markdown 元素映射为自定义 React 组件：


const components = {
  h1: (props) => <CustomHeading level={1} {...props} />,
  code: (props) => <CodeBlock {...props} />,
  table: (props) => <ResponsiveTable {...props} />,
  Callout: (props) => <CalloutBox {...props} />,
};
Front Matter 与元数据系统
Front Matter 是文档管道中的元数据层，通常以 YAML 格式置于文档顶部。它为每篇文档提供结构化的元数据，驱动文档站的分类、排序、导航和 SEO 等功能。


一个设计良好的 Front Matter 模式应包含以下字段类别：


必填字段：title（文档标题，用于页面标题和导航）、description（简短描述，用于 SEO meta 和搜索摘要）。


分类字段：tags（标签列表，用于交叉索引）、category（所属分类）、sidebar_position（侧边栏排序权重）。


状态字段：draft（草稿标记，构建时跳过）、last_updated（最后更新日期，用于保鲜度监控）。


SEO 字段：slug（自定义 URL 路径）、image（社交分享图片）、keywords（搜索引擎关键词）。


Front Matter 的处理发生在 Markdown 管道的最早阶段。remark-frontmatter 插件将 YAML 块从文档内容中分离，解析为 JavaScript 对象后注入到文件的 data 属性中。文档框架（如 Docusaurus）随后使用这些元数据驱动页面布局和站点功能。


元数据验证是保证文档质量的重要环节。可以使用 JSON Schema 或 Zod 对 Front Matter 进行模式验证，在 CI 阶段发现缺失或格式错误的元数据：


import { z } from 'zod';

const frontMatterSchema = z.object({
  title: z.string().min(1).max(100),
  description: z.string().min(10).max(200),
  tags: z.array(z.string()).optional(),
  draft: z.boolean().default(false),
  last_updated: z
    .string()
    .regex(/^\d{4}-\d{2}-\d{2}$/)
    .optional(),
});
自定义插件开发
当社区插件无法满足特定需求时，开发自定义 unified 插件是文档工程师的必备技能。unified 插件本质上是一个接收 AST 树并进行修改的函数。


开发 remark 插件需要理解 MDAST 的节点类型和树遍历方法。unist-util-visit 是最常用的遍历工具，它支持按节点类型过滤和深度优先遍历：


import type { Plugin } from 'unified';
import type { Root } from 'mdast';
import { visit } from 'unist-util-visit';

const remarkCustomAdmonition: Plugin<[], Root> = () => {
  return (tree) => {
    visit(tree, 'blockquote', (node, index, parent) => {
      const firstChild = node.children[0];
      if (firstChild?.type === 'paragraph') {
        const text = firstChild.children[0];
        if (text?.type === 'text' && text.value.startsWith('[!')) {
          const match = text.value.match(/^\[!(\w+)\]/);
          if (match) {
            node.data = {
              hName: 'div',
              hProperties: { className: [`admonition-${match[1]}`] },
            };
          }
        }
      }
    });
  };
};
开发 rehype 插件则操作 HAST（HTML AST），节点类型对应 HTML 元素。常见的自定义 rehype 插件包括：为外部链接添加 target="_blank" 和安全属性、为图片添加懒加载和响应式属性、为代码块添加复制按钮的标记、为表格添加包裹容器实现响应式滚动。


插件开发的最佳实践包括：保持插件功能单一、提供配置选项而非硬编码行为、编写单元测试验证 AST 转换结果、在 README 中说明插件的输入输出格式。


小结
    

  • Markdown 处理管道基于 unified 生态，通过 remark（Markdown AST）和 rehype（HTML AST）两层插件链实现内容转换
    • 

  • MDX 在 Markdown 基础上引入 JSX 支持，编译为 JavaScript 模块，通过组件映射实现交互式文档
    • 

  • Front Matter 提供文档元数据，驱动分类、导航和 SEO，应通过 Schema 验证保证数据质量
    • 

  • 自定义插件开发基于 AST 遍历和转换，是满足特定文档需求的核心技能
    • 

  • 插件执行顺序直接影响处理结果，remark 插件必须在 rehype 之前注册
    •
