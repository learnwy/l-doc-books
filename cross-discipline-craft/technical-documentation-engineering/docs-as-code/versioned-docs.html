版本化文档

核心概念

版本化文档是指为软件产品的不同版本维护独立的文档集合，使用户能够查阅与其使用版本精确对应的文档内容。当一个产品同时存在多个活跃版本（如 v2.x 和 v3.x 并行维护），版本化文档确保每个版本的用户都能获得准确的参考信息，而不会被其他版本的功能变更或废弃特性所困扰。

语义化版本与文档对齐
文档版本化策略应与产品的语义化版本（SemVer）策略对齐。语义化版本的三个数字（主版本.次版本.补丁版本）对文档有不同的影响：


**主版本变更（Major）**通常意味着破坏性 API 变更，需要创建全新的文档版本。旧版本文档应保留并标记为"旧版本"，新版本文档需要包含迁移指南。例如从 React 17 到 React 18，Hooks API 的变化需要独立的文档版本来说明新旧差异。


**次版本变更（Minor）**引入新功能但保持向后兼容。文档更新应在当前版本上进行，新增功能的文档标注"新增于 vX.Y"。不需要创建新的文档版本分支，但需要在版本化文档中标记功能可用性。


**补丁版本变更（Patch）**修复 Bug，通常不影响文档。如果涉及行为修正，应在当前文档中更新描述并注明修复版本号。


文档版本号不一定要与产品版本号完全一致。许多项目采用简化的文档版本策略，只为主版本创建独立文档版本，次版本和补丁版本的变更在同一文档版本中累积更新。


Docusaurus 版本化实践
Docusaurus 是目前版本化文档支持最成熟的框架之一，采用目录复制策略实现版本管理。


创建版本快照：运行 docusaurus docs:version X.Y 命令，Docusaurus 将当前 docs/ 目录复制到 versioned_docs/version-X.Y/，同时保存侧边栏配置到 versioned_sidebars/，并在 versions.json 中注册新版本。当前 docs/ 目录始终代表"下一个版本"（next）。


my-project/
├── docs/                           # next 版本（开发中）
├── versioned_docs/
│   ├── version-2.0/               # v2.0 快照
│   └── version-1.0/               # v1.0 快照
├── versioned_sidebars/
│   ├── version-2.0-sidebars.json
│   └── version-1.0-sidebars.json
└── versions.json                   # ["2.0", "1.0"]
版本选择行为：Docusaurus 自动生成版本选择器下拉菜单。URL 结构为 /docs/ 对应最新版本，/docs/1.0/ 对应历史版本，/docs/next/ 对应开发中版本。未找到的页面可配置回退到最近版本。


跨版本修复：当需要修复历史版本文档的错误时，直接编辑 versioned_docs/ 中对应版本的文件。这是目录复制策略的一个痛点——同一个修复可能需要在多个版本目录中重复操作。


版本生命周期管理：随着版本增多，构建时间和仓库体积会显著增长。应制定版本退役策略——例如只维护最新两个主版本的文档，更早的版本标记为"归档"并从主构建中排除，但仍保留在仓库中供需要时手动构建。


版本间差异管理
版本化文档的最大挑战不是创建版本，而是管理版本间的差异。随着版本增多，维护成本呈指数增长。


差异追踪策略：建立版本变更矩阵，记录每个文档页面在各版本中的差异状态。状态分为：无变化（直接复制）、内容更新（需要手动编辑）、新增页面（仅存在于新版本）、废弃页面（仅存在于旧版本）。


条件内容渲染：对于版本间差异较小的文档，可以使用条件渲染避免完全复制。在 MDX 中通过组件实现版本条件展示：


const VersionBlock = ({ since, children }) => {
  const { siteConfig } = useDocusaurusContext();
  const currentVersion = siteConfig.customFields.docVersion;
  if (compareVersions(currentVersion, since) >= 0) {
    return <>{children}</>;
  }
  return null;
};
共享内容片段：对于跨版本不变的内容（如概念解释、通用配置说明），抽取为独立的 Markdown 片段文件，在各版本文档中通过 import 或 include 机制引用。这样修改一处即可同步所有版本。


自动化差异检测：编写脚本对比版本间的文件差异，自动生成差异报告。在 CI 中运行，当检测到某个版本的文档落后于源代码变更时发出预警。


版本切换体验设计
版本化文档的用户体验设计直接影响用户能否快速找到正确版本的信息。


版本选择器位置：通常放置在导航栏的显著位置，使用下拉菜单展示所有可用版本。当前选择的版本应有明确的视觉标识。推荐显示格式为"v2.0 (Latest)"和"v1.0 (Legacy)"，让用户一目了然。


版本切换行为：用户切换版本时，应尝试导航到目标版本中的对应页面。如果对应页面不存在（该页面在目标版本中尚未添加或已废弃），应友好地提示并引导到最近的可用页面或版本首页。


版本提示横幅：当用户浏览非最新版本时，页面顶部应显示醒目的横幅提示"您正在查看 v1.0 的文档，最新版本为 v2.0"，并提供一键跳转到最新版本对应页面的链接。


搜索与版本联动：文档搜索功能应默认只搜索当前选择版本的内容。搜索结果中标注版本号，支持切换搜索范围到全部版本或指定版本。避免搜索结果中混杂多个版本的内容导致混淆。


小结
    

  • 版本化文档确保不同产品版本的用户都能获得准确的参考信息
    • 

  • 目录复制、Git 分支、条件渲染等策略各有适用场景，应根据版本数量和差异程度选择
    • 

  • 文档版本化应与语义化版本对齐，主版本创建独立文档版本，次版本在当前版本标注
    • 

  • 版本间差异管理是最大挑战，共享内容片段和自动化差异检测是关键应对手段
    • 

  • 版本选择器、提示横幅和搜索联动是良好版本切换体验的三大要素
    •
