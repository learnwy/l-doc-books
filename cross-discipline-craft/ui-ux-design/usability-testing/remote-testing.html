测试脚本设计

概述

测试脚本是可用性测试的核心文档——它定义了测试的流程、任务和问题，直接决定了你能获得什么质量的数据。好的测试脚本能引导用户自然地展示真实行为，差的测试脚本则会引导用户给出你想听的答案。对程序员来说，设计测试脚本的逻辑与编写测试用例的逻辑非常相似：都需要覆盖核心场景、设计边界条件、确保结果可量化。

追问技巧


思出声法（Think-Aloud）
方法介绍
思出声法（Think-Aloud Protocol）要求用户在完成任务时持续说出自己的想法——看到了什么、在想什么、准备做什么、为什么选择这个选项。这是可用性测试中最核心的数据收集技巧。






类型
描述
优势
劣势





并发思出声
用户边做边说
实时捕捉思维过程
可能影响任务执行速度




回顾思出声
完成后看录像回忆
不影响自然行为
回忆可能不准确

小结
测试脚本设计是可用性测试质量的决定因素。核心要点是：用场景化的任务代替直白的指令、用开放式问题代替封闭式问题、用思出声法捕捉用户的真实思维过程。远程测试需要额外关注技术环境准备、任务的自解释性和网络延迟的应对策略。编写测试脚本就像编写测试用例一样——好的测试能暴露真正的问题，差的测试则只会告诉你一切正常。
