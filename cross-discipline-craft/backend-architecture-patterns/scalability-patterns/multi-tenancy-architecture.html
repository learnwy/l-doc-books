多租户架构

核心概念

多租户（Multi-Tenancy）架构是 SaaS 应用的基础设计模式，它允许一套系统同时为多个租户（Tenant）提供服务，每个租户拥有独立的数据空间和配置，但共享底层基础设施。多租户设计的核心挑战是在资源共享和数据隔离之间取得平衡。

不同的隔离级别决定了安全性、运维复杂度和资源利用率。从完全共享到完全隔离，每种策略都有明确的适用场景。

租户识别与路由
多租户系统的第一步是识别每个请求属于哪个租户。常见的识别方式包括子域名、请求头、URL 路径和 JWT 载荷。


import { Hono } from 'hono';
import type { MiddlewareHandler, Context } from 'hono';

interface TenantInfo {
  id: string;
  name: string;
  plan: 'free' | 'pro' | 'enterprise';
  config: Record<string, unknown>;
}

type TenantResolver = (c: Context) => Promise<TenantInfo | null>;

const createSubdomainResolver = (tenantRepo: TenantRepository): TenantResolver => {
  return async (c) => {
    const host = c.req.header('host') ?? '';
    const subdomain = host.split('.')[0];
    if (!subdomain || subdomain === 'www' || subdomain === 'api') return null;
    return tenantRepo.findBySlug(subdomain);
  };
};

const createHeaderResolver = (tenantRepo: TenantRepository): TenantResolver => {
  return async (c) => {
    const tenantId = c.req.header('x-tenant-id');
    if (!tenantId) return null;
    return tenantRepo.findById(tenantId);
  };
};

const createTenantMiddleware = (resolver: TenantResolver): MiddlewareHandler => {
  return async (c, next) => {
    const tenant = await resolver(c);
    if (!tenant) {
      return c.json({ error: { code: 'TENANT_NOT_FOUND', message: 'Tenant not identified' } }, 404);
    }

    c.set('tenant', tenant);
    c.set('tenantId', tenant.id);
    await next();
  };
};

const app = new Hono();
app.use('/api/*', createTenantMiddleware(createSubdomainResolver(tenantRepo)));
子域名识别是最直观的方式——acme.app.com 自动识别为 acme 租户。对于 API 优先的场景，请求头方式更灵活，不依赖 DNS 配置。


行级数据隔离
行级隔离是最常见的多租户数据策略。所有租户的数据存储在同一张表中，通过 tenant_id 列区分。查询时必须在每个 SQL 条件中包含 tenant_id。


interface TenantAwareRepository<T> {
  findById(tenantId: string, id: string): Promise<T | null>;
  findAll(tenantId: string, options?: PaginationOptions): Promise<T[]>;
  save(tenantId: string, data: Omit<T, 'id' | 'tenantId'>): Promise<T>;
  update(tenantId: string, id: string, data: Partial<T>): Promise<T>;
  remove(tenantId: string, id: string): Promise<void>;
}

const createTenantAwareRepo = <T extends { id: string }>(pool: Pool, tableName: string): TenantAwareRepository<T> => ({
  async findById(tenantId, id) {
    const { rows } = await pool.query(`SELECT * FROM ${tableName} WHERE tenant_id = $1 AND id = $2`, [tenantId, id]);
    return rows[0] ?? null;
  },

  async findAll(tenantId, options) {
    const limit = options?.pageSize ?? 20;
    const offset = ((options?.page ?? 1) - 1) * limit;
    const { rows } = await pool.query(
      `SELECT * FROM ${tableName} WHERE tenant_id = $1 ORDER BY created_at DESC LIMIT $2 OFFSET $3`,
      [tenantId, limit, offset],
    );
    return rows;
  },

  async save(tenantId, data) {
    const id = crypto.randomUUID();
    const allData = { id, tenant_id: tenantId, ...data, created_at: new Date() };
    const keys = Object.keys(allData);
    const values = Object.values(allData);
    const placeholders = keys.map((_, i) => `$${i + 1}`).join(', ');
    const { rows } = await pool.query(
      `INSERT INTO ${tableName} (${keys.join(', ')}) VALUES (${placeholders}) RETURNING *`,
      values,
    );
    return rows[0];
  },

  async update(tenantId, id, data) {
    const entries = Object.entries(data).filter(([, v]) => v !== undefined);
    const sets = entries.map(([k], i) => `${k} = $${i + 1}`).join(', ');
    const values = [...entries.map(([, v]) => v), tenantId, id];
    const { rows } = await pool.query(
      `UPDATE ${tableName} SET ${sets} WHERE tenant_id = $${entries.length + 1} AND id = $${entries.length + 2} RETURNING *`,
      values,
    );
    return rows[0];
  },

  async remove(tenantId, id) {
    await pool.query(`DELETE FROM ${tableName} WHERE tenant_id = $1 AND id = $2`, [tenantId, id]);
  },
});
行级隔离的最大风险是 SQL 查询忘记添加 tenant_id 条件，导致跨租户数据泄漏。通过仓储层强制注入 tenant_id 可以系统性地消除这个风险。PostgreSQL 的 Row Level Security（RLS）可以在数据库层面提供额外的安全保障。


租户配额与资源限制
不同租户的套餐可能有不同的资源配额。配额管理防止个别租户过度消耗共享资源。


interface TenantQuota {
  maxUsers: number;
  maxStorage: number;
  apiRateLimit: number;
  maxProjects: number;
}

const PLAN_QUOTAS: Record<string, TenantQuota> = {
  free: { maxUsers: 5, maxStorage: 1_073_741_824, apiRateLimit: 100, maxProjects: 3 },
  pro: { maxUsers: 50, maxStorage: 10_737_418_240, apiRateLimit: 1000, maxProjects: 20 },
  enterprise: { maxUsers: -1, maxStorage: -1, apiRateLimit: 10000, maxProjects: -1 },
};

const createQuotaChecker = (redis: Redis) => {
  const checkUsage = async (
    tenantId: string,
    resource: keyof TenantQuota,
    plan: string,
  ): Promise<{ allowed: boolean; current: number; limit: number }> => {
    const quota = PLAN_QUOTAS[plan];
    const limit = quota[resource];

    if (limit === -1) return { allowed: true, current: 0, limit: -1 };

    const current = Number(await redis.get(`quota:${tenantId}:${resource}`)) || 0;
    return { allowed: current < limit, current, limit };
  };

  const increment = async (tenantId: string, resource: string, amount = 1) => {
    await redis.incrby(`quota:${tenantId}:${resource}`, amount);
  };

  const decrement = async (tenantId: string, resource: string, amount = 1) => {
    await redis.decrby(`quota:${tenantId}:${resource}`, amount);
  };

  return { checkUsage, increment, decrement };
};

租户数据迁移与生命周期
租户的创建、套餐升降级和注销是多租户系统的完整生命周期。数据迁移（特别是在隔离级别变更时）是最复杂的操作。


interface TenantLifecycleManager {
  provision(name: string, plan: string): Promise<TenantInfo>;
  changePlan(tenantId: string, newPlan: string): Promise<void>;
  suspend(tenantId: string, reason: string): Promise<void>;
  deprovision(tenantId: string): Promise<void>;
}

const createLifecycleManager = (tenantRepo: TenantRepository, redis: Redis): TenantLifecycleManager => ({
  async provision(name, plan) {
    const slug = name.toLowerCase().replace(/\s+/g, '-');
    const tenant = await tenantRepo.create({ name, slug, plan, status: 'active' });

    await redis.set(`quota:${tenant.id}:maxUsers`, '0');
    await redis.set(`quota:${tenant.id}:maxStorage`, '0');

    return tenant;
  },

  async changePlan(tenantId, newPlan) {
    await tenantRepo.update(tenantId, { plan: newPlan });

    const quotas = PLAN_QUOTAS[newPlan];
    for (const [key, limit] of Object.entries(quotas)) {
      await redis.set(`plan:${tenantId}:${key}`, String(limit));
    }
  },

  async suspend(tenantId, reason) {
    await tenantRepo.update(tenantId, { status: 'suspended', suspendReason: reason });
  },

  async deprovision(tenantId) {
    await tenantRepo.update(tenantId, { status: 'deprovisioning' });

    await Promise.all([
      pool.query('DELETE FROM user_data WHERE tenant_id = $1', [tenantId]),
      pool.query('DELETE FROM projects WHERE tenant_id = $1', [tenantId]),
    ]);

    await tenantRepo.update(tenantId, { status: 'deleted' });
    const keys = await redis.keys(`*:${tenantId}:*`);
    if (keys.length) await redis.del(...keys);
  },
});
注销租户时数据删除必须彻底，包括数据库记录、Redis 缓存和对象存储文件。分阶段删除（标记 → 软删除 → 硬删除）提供了误操作的恢复窗口。


小结
    

  • 行级隔离通过 tenant_id 实现最低成本的数据隔离，适合大多数 SaaS 应用
    • 

  • 仓储层强制注入 tenant_id 系统性地防止跨租户数据泄漏
    • 

  • 子域名是最直观的租户识别方式，API 场景适合请求头方式
    • 

  • 配额管理通过 Redis 计数器实现实时资源用量追踪
    • 

  • 租户注销需分阶段执行，提供数据恢复窗口
    • 

  • 隔离级别选择取决于安全需求、成本预算和运维能力
