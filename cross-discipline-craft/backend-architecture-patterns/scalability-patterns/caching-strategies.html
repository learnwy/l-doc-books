缓存策略

核心概念

缓存（Cache）是提升后端服务性能最直接、最有效的手段。通过在数据源和消费者之间存储数据的副本，缓存大幅减少了对底层存储的访问频率，降低响应延迟并提升吞吐量。据统计，合理的缓存策略可以将 API 响应时间从数百毫秒降到个位数毫秒。

缓存设计的核心挑战在于数据一致性——当源数据变化时，缓存中的旧数据（Stale Data）如何及时更新或失效。不同的缓存模式在一致性、性能和复杂度之间做出不同的权衡。

Cache-Aside 模式
Cache-Aside（旁路缓存）是最常用的缓存模式。应用代码负责管理缓存的读写：读时先查缓存，未命中则查数据源并回填缓存；写时先更新数据源，再失效缓存。


import type { Redis } from 'ioredis';

interface CacheOptions {
  ttl: number;
  prefix: string;
}

const createCacheAside = <T>(redis: Redis, options: CacheOptions) => {
  const makeKey = (id: string) => `${options.prefix}:${id}`;

  return {
    get: async (id: string, loader: () => Promise<T | null>): Promise<T | null> => {
      const key = makeKey(id);
      const cached = await redis.get(key);

      if (cached) {
        return JSON.parse(cached) as T;
      }

      const data = await loader();
      if (data) {
        await redis.set(key, JSON.stringify(data), 'EX', options.ttl);
      }

      return data;
    },

    invalidate: async (id: string): Promise<void> => {
      await redis.del(makeKey(id));
    },

    invalidatePattern: async (pattern: string): Promise<void> => {
      const keys = await redis.keys(`${options.prefix}:${pattern}`);
      if (keys.length > 0) {
        await redis.del(...keys);
      }
    },

    set: async (id: string, data: T): Promise<void> => {
      await redis.set(makeKey(id), JSON.stringify(data), 'EX', options.ttl);
    },
  };
};

const userCache = createCacheAside<User>(redis, { ttl: 300, prefix: 'user' });

app.get('/api/users/:id', async (c) => {
  const id = c.req.param('id');
  const user = await userCache.get(id, () => userRepo.findById(id));
  if (!user) return c.json({ error: 'Not found' }, 404);
  return c.json(user);
});

app.put('/api/users/:id', async (c) => {
  const id = c.req.param('id');
  const data = await c.req.json();
  const user = await userRepo.update(id, data);
  await userCache.invalidate(id);
  return c.json(user);
});
Cache-Aside 的经典问题是"缓存击穿"——当缓存过期瞬间大量请求同时查询数据源。解决方案是使用互斥锁（Mutex Lock）或提前刷新（Stale-While-Revalidate）。


多级缓存架构
单层缓存在高并发场景下可能成为瓶颈。多级缓存通过在不同层次设置缓存，逐级吸收请求，大幅降低下游压力。


interface CacheLayer<T> {
  name: string;
  get(key: string): Promise<T | null>;
  set(key: string, data: T, ttl: number): Promise<void>;
  del(key: string): Promise<void>;
}

const createMemoryCache = <T>(): CacheLayer<T> => {
  const store = new Map<string, { data: T; expireAt: number }>();

  return {
    name: 'memory',
    async get(key) {
      const entry = store.get(key);
      if (!entry) return null;
      if (Date.now() > entry.expireAt) {
        store.delete(key);
        return null;
      }
      return entry.data;
    },
    async set(key, data, ttl) {
      store.set(key, { data, expireAt: Date.now() + ttl * 1000 });
    },
    async del(key) {
      store.delete(key);
    },
  };
};

const createMultiLevelCache = <T>(layers: CacheLayer<T>[]) => {
  return {
    async get(key: string, loader: () => Promise<T | null>): Promise<T | null> {
      for (let i = 0; i < layers.length; i++) {
        const data = await layers[i].get(key);
        if (data !== null) {
          for (let j = 0; j < i; j++) {
            await layers[j].set(key, data, 60);
          }
          return data;
        }
      }

      const data = await loader();
      if (data !== null) {
        for (const layer of layers) {
          await layer.set(key, data, 300);
        }
      }
      return data;
    },

    async invalidate(key: string) {
      await Promise.all(layers.map((l) => l.del(key)));
    },
  };
};

缓存失效策略
缓存失效被称为"计算机科学中两大难题之一"。选择正确的失效策略直接影响数据一致性和系统复杂度。


const createStaleWhileRevalidate = <T>(
  redis: Redis,
  options: { freshTTL: number; staleTTL: number; prefix: string },
) => {
  const makeKey = (id: string) => `${options.prefix}:${id}`;
  const refreshing = new Set<string>();

  return {
    async get(id: string, loader: () => Promise<T>): Promise<T | null> {
      const key = makeKey(id);
      const raw = await redis.get(key);

      if (!raw) {
        const data = await loader();
        await redis.set(key, JSON.stringify({ data, fetchedAt: Date.now() }), 'EX', options.staleTTL);
        return data;
      }

      const { data, fetchedAt } = JSON.parse(raw);
      const age = Date.now() - fetchedAt;

      if (age > options.freshTTL * 1000 && !refreshing.has(key)) {
        refreshing.add(key);
        loader()
          .then(async (fresh) => {
            await redis.set(key, JSON.stringify({ data: fresh, fetchedAt: Date.now() }), 'EX', options.staleTTL);
          })
          .finally(() => refreshing.delete(key));
      }

      return data;
    },
  };
};
Stale-While-Revalidate（过期后台刷新）策略在数据过期后立即返回旧数据，同时在后台异步刷新。这种策略提供了极低的读延迟，同时保持数据的相对新鲜度。适用于对一致性要求不高但对延迟敏感的场景，如商品列表、用户资料等。


缓存穿透与雪崩防护
缓存穿透和缓存雪崩是两个需要专门防护的问题。穿透是查询不存在的数据导致每次都打到数据库，雪崩是大量缓存同时过期导致数据库压力骤增。


const createProtectedCache = <T>(redis: Redis, prefix: string) => {
  const nullPlaceholder = '__NULL__';

  const getWithNullProtection = async (id: string, loader: () => Promise<T | null>, ttl: number): Promise<T | null> => {
    const key = `${prefix}:${id}`;
    const cached = await redis.get(key);

    if (cached === nullPlaceholder) return null;
    if (cached) return JSON.parse(cached);

    const data = await loader();
    if (data) {
      const jitter = Math.floor(Math.random() * 60);
      await redis.set(key, JSON.stringify(data), 'EX', ttl + jitter);
    } else {
      await redis.set(key, nullPlaceholder, 'EX', 60);
    }
    return data;
  };

  const getWithMutex = async (id: string, loader: () => Promise<T | null>, ttl: number): Promise<T | null> => {
    const key = `${prefix}:${id}`;
    const lockKey = `${prefix}:lock:${id}`;
    const cached = await redis.get(key);
    if (cached) return JSON.parse(cached);

    const locked = await redis.set(lockKey, '1', 'EX', 10, 'NX');
    if (locked) {
      try {
        const data = await loader();
        if (data) await redis.set(key, JSON.stringify(data), 'EX', ttl);
        return data;
      } finally {
        await redis.del(lockKey);
      }
    }

    await new Promise((r) => setTimeout(r, 100));
    const retried = await redis.get(key);
    return retried ? JSON.parse(retried) : null;
  };

  return { getWithNullProtection, getWithMutex };
};
空值缓存（Null Cache）防穿透：对不存在的数据也缓存一个短 TTL 的空标记。TTL 抖动（Jitter）防雪崩：为每个缓存项的 TTL 添加随机偏移，避免大量缓存同时过期。互斥锁防击穿：同一时刻只有一个请求去加载数据源，其他请求等待。


小结
    

  • Cache-Aside 是最通用的缓存模式，应用代码负责缓存的读写和失效
    • 

  • 多级缓存逐层吸收请求，L1 进程内存提供亚毫秒级延迟
    • 

  • Stale-While-Revalidate 策略在低延迟和数据新鲜度之间取得平衡
    • 

  • 空值缓存防穿透、TTL 抖动防雪崩、互斥锁防击穿是三大防护机制
    • 

  • L1 缓存 TTL 必须远短于 L2，避免跨实例数据不一致
    • 

  • 缓存失效比缓存写入更重要，写操作后必须及时失效相关缓存
