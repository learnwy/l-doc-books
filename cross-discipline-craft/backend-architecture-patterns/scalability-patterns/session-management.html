会话管理

核心概念

会话（Session）管理是后端服务维持用户状态的机制。HTTP 协议本身是无状态的，每次请求都是独立的。会话管理通过在客户端和服务端之间建立状态关联，实现登录态保持、购物车、用户偏好等有状态功能。

会话管理的两大流派是"有状态会话"（服务端存储会话数据）和"无状态会话"（客户端携带全部状态）。选择取决于安全需求、扩展性要求和架构复杂度。

分布式 Session 实现
在水平扩展的服务中，Session 必须存储在所有实例都能访问的共享存储中。Redis 是最常用的 Session 存储方案。


import type { Redis } from 'ioredis';

interface SessionData {
  userId: string;
  role: string;
  loginAt: number;
  lastActiveAt: number;
  metadata: Record<string, unknown>;
}

interface SessionManager {
  create(data: Omit<SessionData, 'lastActiveAt'>): Promise<string>;
  get(sessionId: string): Promise<SessionData | null>;
  update(sessionId: string, data: Partial<SessionData>): Promise<void>;
  destroy(sessionId: string): Promise<void>;
  touch(sessionId: string): Promise<void>;
  listByUser(userId: string): Promise<string[]>;
}

const createSessionManager = (redis: Redis, options: { ttl: number; prefix: string }): SessionManager => {
  const makeKey = (id: string) => `${options.prefix}:${id}`;
  const userKey = (userId: string) => `${options.prefix}:user:${userId}`;

  return {
    async create(data) {
      const sessionId = crypto.randomUUID();
      const session: SessionData = { ...data, lastActiveAt: Date.now() };

      await redis.set(makeKey(sessionId), JSON.stringify(session), 'EX', options.ttl);
      await redis.sadd(userKey(data.userId), sessionId);
      await redis.expire(userKey(data.userId), options.ttl);

      return sessionId;
    },

    async get(sessionId) {
      const raw = await redis.get(makeKey(sessionId));
      return raw ? JSON.parse(raw) : null;
    },

    async update(sessionId, data) {
      const existing = await redis.get(makeKey(sessionId));
      if (!existing) return;

      const session = { ...JSON.parse(existing), ...data, lastActiveAt: Date.now() };
      await redis.set(makeKey(sessionId), JSON.stringify(session), 'EX', options.ttl);
    },

    async destroy(sessionId) {
      const raw = await redis.get(makeKey(sessionId));
      if (raw) {
        const session: SessionData = JSON.parse(raw);
        await redis.srem(userKey(session.userId), sessionId);
      }
      await redis.del(makeKey(sessionId));
    },

    async touch(sessionId) {
      await redis.expire(makeKey(sessionId), options.ttl);
    },

    async listByUser(userId) {
      return redis.smembers(userKey(userId));
    },
  };
};
listByUser 方法支持"踢人下线"功能——获取某用户的所有活跃 Session，逐个销毁即可。Redis Set 记录了每个用户的 Session ID 集合。


Cookie 与 Token 安全配置
会话标识的传递方式直接影响安全性。Cookie 和 Authorization Header 各有安全考量。


import { Hono } from 'hono';
import { getCookie, setCookie, deleteCookie } from 'hono/cookie';
import type { MiddlewareHandler } from 'hono';

const createSessionMiddleware = (sessionManager: SessionManager): MiddlewareHandler => {
  return async (c, next) => {
    const sessionId = getCookie(c, 'session_id') ?? c.req.header('authorization')?.replace('Bearer ', '');

    if (!sessionId) {
      return c.json({ error: 'Unauthorized' }, 401);
    }

    const session = await sessionManager.get(sessionId);
    if (!session) {
      deleteCookie(c, 'session_id');
      return c.json({ error: 'Session expired' }, 401);
    }

    await sessionManager.touch(sessionId);
    c.set('session', session);
    c.set('sessionId', sessionId);

    await next();
  };
};

const loginHandler = async (c: Context) => {
  const { email, password } = await c.req.json();
  const user = await verifyCredentials(email, password);

  const sessionId = await sessionManager.create({
    userId: user.id,
    role: user.role,
    loginAt: Date.now(),
    metadata: {
      ip: c.req.header('x-forwarded-for'),
      userAgent: c.req.header('user-agent'),
    },
  });

  setCookie(c, 'session_id', sessionId, {
    httpOnly: true,
    secure: true,
    sameSite: 'Lax',
    maxAge: 86400,
    path: '/',
  });

  return c.json({ user: { id: user.id, name: user.name } });
};

HttpOnly 是防御 XSS 攻击的关键——即使页面被注入恶意脚本，脚本也无法通过 document.cookie 读取 Session ID。SameSite: Lax 允许从外部链接进入时携带 Cookie（如收藏夹点击），但阻止跨站 POST 请求携带 Cookie。


Session 固定攻击防护
Session 固定（Session Fixation）攻击是指攻击者预先获取一个有效的 Session ID，诱导用户使用该 ID 登录，从而劫持用户会话。


const secureLoginHandler = async (c: Context) => {
  const { email, password } = await c.req.json();
  const user = await verifyCredentials(email, password);

  const oldSessionId = getCookie(c, 'session_id');
  if (oldSessionId) {
    await sessionManager.destroy(oldSessionId);
  }

  const newSessionId = await sessionManager.create({
    userId: user.id,
    role: user.role,
    loginAt: Date.now(),
    metadata: {
      ip: c.req.header('x-forwarded-for'),
      userAgent: c.req.header('user-agent'),
    },
  });

  setCookie(c, 'session_id', newSessionId, {
    httpOnly: true,
    secure: true,
    sameSite: 'Lax',
    maxAge: 86400,
    path: '/',
  });

  return c.json({ user: { id: user.id, name: user.name } });
};

const logoutHandler = async (c: Context) => {
  const sessionId = c.get('sessionId') as string;
  await sessionManager.destroy(sessionId);
  deleteCookie(c, 'session_id');
  return c.json({ success: true });
};

const logoutAllHandler = async (c: Context) => {
  const session = c.get('session') as SessionData;
  const sessionIds = await sessionManager.listByUser(session.userId);

  await Promise.all(sessionIds.map((id) => sessionManager.destroy(id)));
  deleteCookie(c, 'session_id');

  return c.json({ success: true, destroyedSessions: sessionIds.length });
};
防护的核心是登录成功后立即销毁旧 Session 并创建新 Session。logoutAll 功能让用户可以一次性注销所有设备上的会话。


Token 黑名单与即时撤销
JWT 的最大劣势是无法即时撤销——Token 在到期前始终有效。Token 黑名单机制弥补了这个缺陷。


const createTokenBlacklist = (redis: Redis) => {
  const blacklist = async (token: string, expiresIn: number): Promise<void> => {
    const jti = extractJTI(token);
    await redis.set(`blacklist:${jti}`, '1', 'EX', expiresIn);
  };

  const isBlacklisted = async (token: string): Promise<boolean> => {
    const jti = extractJTI(token);
    const result = await redis.get(`blacklist:${jti}`);
    return result !== null;
  };

  const blacklistAllForUser = async (userId: string, currentExp: number): Promise<void> => {
    const now = Math.floor(Date.now() / 1000);
    await redis.set(`user-blacklist:${userId}`, String(now), 'EX', currentExp - now);
  };

  const isUserBlacklisted = async (userId: string, iat: number): Promise<boolean> => {
    const blacklistedAt = await redis.get(`user-blacklist:${userId}`);
    if (!blacklistedAt) return false;
    return iat < Number(blacklistedAt);
  };

  return { blacklist, isBlacklisted, blacklistAllForUser, isUserBlacklisted };
};
黑名单方案有两个级别：单 Token 黑名单（精确撤销指定 Token）和用户级黑名单（撤销某用户在某时间点之前签发的所有 Token）。用户级黑名单只需存储一个时间戳，非常轻量。


小结
    

  • 有状态 Session 支持即时撤销，无状态 JWT 天然支持水平扩展
    • 

  • Redis 是分布式 Session 存储的首选，支持 TTL 自动过期
    • 

  • Cookie 必须设置 HttpOnly + Secure + SameSite 防御 XSS 和 CSRF
    • 

  • 登录时必须销毁旧 Session 创建新 Session，防止 Session 固定攻击
    • 

  • Token 黑名单通过 Redis 存储实现 JWT 的即时撤销能力
    • 

  • 用户级黑名单只需一个时间戳，即可撤销该用户所有已签发 Token
    •
