水平 vs 垂直扩展

核心概念

扩展（Scaling）是应对流量增长的核心策略。当单台服务器无法承载所有请求时，系统需要扩展来提升处理能力。扩展策略分为两个方向：垂直扩展（Scale Up）通过增强单机硬件来提升性能，水平扩展（Scale Out）通过增加服务器数量来分担负载。

垂直扩展简单直接但存在物理上限，水平扩展理论上无限但需要架构层面的支持。现代后端架构的核心设计原则之一就是"为水平扩展而设计"——这意味着服务必须是无状态的，或者状态必须外部化。

无状态服务设计
水平扩展的前提是服务实例之间可以互相替代——任何请求可以被任何实例处理。这要求服务本身不持有请求间的状态，所有状态都外部化到共享存储（数据库、Redis、对象存储）。


import { Hono } from 'hono';

const createStatelessApp = (config: { redisUrl: string; dbUrl: string }) => {
  const app = new Hono();
  const redis = createRedisClient(config.redisUrl);
  const db = createDbPool(config.dbUrl);

  app.get('/api/users/:id', async (c) => {
    const id = c.req.param('id');
    const cacheKey = `user:${id}`;

    const cached = await redis.get(cacheKey);
    if (cached) return c.json(JSON.parse(cached));

    const user = await db.query('SELECT * FROM users WHERE id = $1', [id]);
    if (user) {
      await redis.set(cacheKey, JSON.stringify(user), 'EX', 300);
    }

    return c.json(user);
  });

  app.post('/api/events', async (c) => {
    const event = await c.req.json();
    await redis.lpush('event-queue', JSON.stringify(event));
    return c.json({ status: 'queued' }, 202);
  });

  return app;
};
无状态设计的核心原则：不使用进程内全局变量存储请求间状态、不依赖本地文件系统存储用户数据、会话信息存入 Redis 而非内存。每个实例都是对等的，负载均衡器可以将请求分配给任意实例。


负载均衡策略
负载均衡器将入站请求分发到多个后端实例，是水平扩展的核心组件。不同的分发算法适用于不同的场景。


type LoadBalancerStrategy = 'round-robin' | 'least-connections' | 'weighted' | 'ip-hash';

interface Backend {
  url: string;
  weight: number;
  connections: number;
  healthy: boolean;
}

const createLoadBalancer = (backends: Backend[], strategy: LoadBalancerStrategy) => {
  let rrIndex = 0;

  const roundRobin = () => {
    const healthy = backends.filter((b) => b.healthy);
    if (healthy.length === 0) throw new Error('No healthy backends');
    const selected = healthy[rrIndex % healthy.length];
    rrIndex++;
    return selected;
  };

  const leastConnections = () => {
    const healthy = backends.filter((b) => b.healthy);
    return healthy.reduce((min, b) => (b.connections < min.connections ? b : min));
  };

  const weighted = () => {
    const healthy = backends.filter((b) => b.healthy);
    const totalWeight = healthy.reduce((sum, b) => sum + b.weight, 0);
    let random = Math.random() * totalWeight;

    for (const backend of healthy) {
      random -= backend.weight;
      if (random <= 0) return backend;
    }
    return healthy[0];
  };

  const ipHash = (clientIp: string) => {
    const healthy = backends.filter((b) => b.healthy);
    let hash = 0;
    for (let i = 0; i < clientIp.length; i++) {
      hash = (hash * 31 + clientIp.charCodeAt(i)) | 0;
    }
    return healthy[Math.abs(hash) % healthy.length];
  };

  return {
    select: (clientIp?: string) => {
      switch (strategy) {
        case 'round-robin':
          return roundRobin();
        case 'least-connections':
          return leastConnections();
        case 'weighted':
          return weighted();
        case 'ip-hash':
          return ipHash(clientIp ?? '127.0.0.1');
      }
    },
  };
};

自动扩缩容策略
容器编排平台（如 Kubernetes）支持基于指标的自动扩缩容（HPA），根据实时负载自动调整实例数量。


interface ScalingPolicy {
  minReplicas: number;
  maxReplicas: number;
  targetCPUPercent: number;
  targetMemoryPercent: number;
  scaleUpCooldown: number;
  scaleDownCooldown: number;
}

interface MetricsSnapshot {
  avgCPU: number;
  avgMemory: number;
  requestRate: number;
  avgLatency: number;
}

const calculateDesiredReplicas = (current: number, metrics: MetricsSnapshot, policy: ScalingPolicy): number => {
  const cpuRatio = metrics.avgCPU / policy.targetCPUPercent;
  const memoryRatio = metrics.avgMemory / policy.targetMemoryPercent;

  const ratio = Math.max(cpuRatio, memoryRatio);
  const desired = Math.ceil(current * ratio);

  return Math.min(policy.maxReplicas, Math.max(policy.minReplicas, desired));
};

const simulateAutoScaling = (policy: ScalingPolicy) => {
  let currentReplicas = policy.minReplicas;
  let lastScaleUp = 0;
  let lastScaleDown = 0;

  return {
    evaluate: (metrics: MetricsSnapshot) => {
      const desired = calculateDesiredReplicas(currentReplicas, metrics, policy);
      const now = Date.now();

      if (desired > currentReplicas && now - lastScaleUp > policy.scaleUpCooldown) {
        currentReplicas = desired;
        lastScaleUp = now;
        return { action: 'scale-up' as const, replicas: currentReplicas };
      }

      if (desired < currentReplicas && now - lastScaleDown > policy.scaleDownCooldown) {
        currentReplicas = desired;
        lastScaleDown = now;
        return { action: 'scale-down' as const, replicas: currentReplicas };
      }

      return { action: 'none' as const, replicas: currentReplicas };
    },
  };
};
冷却时间（Cooldown）防止扩缩容抖动。扩容冷却通常较短（1-3 分钟），缩容冷却较长（5-10 分钟），因为扩容的紧迫性高于缩容。


数据库扩展策略
应用层的水平扩展相对容易，数据库层的扩展则更具挑战性。常见策略包括读写分离和分片。


interface DatabaseCluster {
  writer: Pool;
  readers: Pool[];
}

const createReadWriteRouter = (cluster: DatabaseCluster) => {
  let readerIndex = 0;

  return {
    write: () => cluster.writer,
    read: () => {
      if (cluster.readers.length === 0) return cluster.writer;
      const reader = cluster.readers[readerIndex % cluster.readers.length];
      readerIndex++;
      return reader;
    },
  };
};

const createShardRouter = (shardCount: number, shards: Pool[]) => {
  const getShardIndex = (key: string): number => {
    let hash = 0;
    for (let i = 0; i < key.length; i++) {
      hash = (hash * 31 + key.charCodeAt(i)) | 0;
    }
    return Math.abs(hash) % shardCount;
  };

  return {
    getShard: (key: string) => shards[getShardIndex(key)],
    getAllShards: () => shards,
  };
};

读写分离将写操作路由到主库、读操作路由到从库，适合读多写少的场景。水平分片按 key 将数据分散到多个数据库实例，支持海量数据存储但跨分片查询复杂。


小结
    

  • 垂直扩展简单但有上限，水平扩展理论无限但需要无状态设计
    • 

  • 无状态服务是水平扩展的前提，所有状态必须外部化
    • 

  • 负载均衡策略根据场景选择：轮询适合通用场景，最少连接适合长连接
    • 

  • 自动扩缩容通过指标驱动动态调整实例数，冷却时间防止抖动
    • 

  • 数据库扩展比应用层更具挑战，读写分离和分片是主要策略
    • 

  • 为水平扩展而设计是现代后端架构的核心原则
