结构化日志

核心概念

结构化日志（Structured Logging）是将日志信息以机器可解析的格式（通常是 JSON）输出的实践。相比传统的纯文本日志（如 [INFO] User 123 logged in），结构化日志 {"level":"info","userId":"123","event":"login","timestamp":"2024-01-01T00:00:00Z"} 可以被日志聚合系统（如 ELK、Datadog）高效地索引、搜索和分析。

在微服务架构中，日志是排查问题的第一手资料。结构化日志通过统一的格式、上下文传播和日志级别管理，让分布式系统的问题排查从"大海捞针"变成"精确定位"。

日志器设计与实现
一个生产级的日志器需要支持日志级别、上下文注入、格式化输出和性能优化。


type LogLevel = 'debug' | 'info' | 'warn' | 'error' | 'fatal';

interface LogEntry {
  level: LogLevel;
  message: string;
  timestamp: string;
  service: string;
  [key: string]: unknown;
}

interface Logger {
  debug(message: string, data?: Record<string, unknown>): void;
  info(message: string, data?: Record<string, unknown>): void;
  warn(message: string, data?: Record<string, unknown>): void;
  error(message: string, data?: Record<string, unknown>): void;
  fatal(message: string, data?: Record<string, unknown>): void;
  child(context: Record<string, unknown>): Logger;
}

const LOG_LEVELS: Record<LogLevel, number> = {
  debug: 0,
  info: 1,
  warn: 2,
  error: 3,
  fatal: 4,
};

const createLogger = (options: { service: string; level: LogLevel; context?: Record<string, unknown> }): Logger => {
  const minLevel = LOG_LEVELS[options.level];
  const baseContext = options.context ?? {};

  const log = (level: LogLevel, message: string, data?: Record<string, unknown>) => {
    if (LOG_LEVELS[level] < minLevel) return;

    const entry: LogEntry = {
      level,
      message,
      timestamp: new Date().toISOString(),
      service: options.service,
      ...baseContext,
      ...data,
    };

    const output = JSON.stringify(entry);

    if (LOG_LEVELS[level] >= LOG_LEVELS.error) {
      process.stderr.write(output + '\n');
    } else {
      process.stdout.write(output + '\n');
    }
  };

  return {
    debug: (msg, data) => log('debug', msg, data),
    info: (msg, data) => log('info', msg, data),
    warn: (msg, data) => log('warn', msg, data),
    error: (msg, data) => log('error', msg, data),
    fatal: (msg, data) => log('fatal', msg, data),
    child: (context) =>
      createLogger({
        ...options,
        context: { ...baseContext, ...context },
      }),
  };
};

const logger = createLogger({ service: 'user-api', level: 'info' });
const reqLogger = logger.child({ requestId: 'abc-123', userId: 'user-456' });
reqLogger.info('User profile updated', { field: 'email' });
child 方法是结构化日志的核心功能——它创建一个继承父级上下文的子日志器。请求级别的 requestId 和 userId 通过 child logger 注入，后续该请求中的所有日志都自动携带这些上下文字段。


请求上下文传播
在一个请求的生命周期中，日志上下文需要在中间件、业务逻辑和数据访问层之间传播。Node.js 的 AsyncLocalStorage 提供了优雅的上下文传播机制。


import { AsyncLocalStorage } from 'node:async_hooks';
import type { MiddlewareHandler } from 'hono';

interface RequestContext {
  requestId: string;
  userId?: string;
  traceId?: string;
  startTime: number;
}

const requestStore = new AsyncLocalStorage<RequestContext>();

const requestContextMiddleware: MiddlewareHandler = async (c, next) => {
  const context: RequestContext = {
    requestId: c.req.header('x-request-id') ?? crypto.randomUUID(),
    traceId: c.req.header('x-trace-id'),
    startTime: performance.now(),
  };

  c.header('X-Request-Id', context.requestId);

  await requestStore.run(context, async () => {
    await next();
  });
};

const getContextLogger = (): Logger => {
  const context = requestStore.getStore();
  if (!context) return logger;

  return logger.child({
    requestId: context.requestId,
    userId: context.userId,
    traceId: context.traceId,
  });
};
AsyncLocalStorage 在整个异步调用链中自动传播上下文，无需在每个函数签名中传递 logger 参数。任何代码位置调用 getContextLogger() 都能获得包含当前请求上下文的日志器。


日志级别策略与动态调整
不同环境需要不同的日志级别，且生产环境应支持不受重启影响的动态日志级别调整。


interface DynamicLogConfig {
  getLevel(): LogLevel;
  setLevel(level: LogLevel): void;
  getLevelForNamespace(namespace: string): LogLevel;
  setLevelForNamespace(namespace: string, level: LogLevel): void;
}

const createDynamicLogConfig = (defaultLevel: LogLevel): DynamicLogConfig => {
  let globalLevel = defaultLevel;
  const namespaceOverrides = new Map<string, LogLevel>();

  return {
    getLevel: () => globalLevel,
    setLevel: (level) => {
      globalLevel = level;
    },
    getLevelForNamespace: (ns) => namespaceOverrides.get(ns) ?? globalLevel,
    setLevelForNamespace: (ns, level) => namespaceOverrides.set(ns, level),
  };
};

const logConfig = createDynamicLogConfig('info');

app.post('/internal/log-level', async (c) => {
  const { level, namespace } = await c.req.json();

  if (namespace) {
    logConfig.setLevelForNamespace(namespace, level);
  } else {
    logConfig.setLevel(level);
  }

  return c.json({ success: true, level, namespace });
});

动态调整在排查生产问题时非常有用——临时将某个模块的日志级别降到 debug，获取详细信息后恢复。无需重启服务，通过内部 API 即可操作。


敏感数据脱敏
日志中不可避免地会涉及敏感信息。脱敏策略确保密码、Token、身份证号等敏感数据不会出现在日志中。


interface SanitizeRule {
  fields: string[];
  strategy: 'mask' | 'hash' | 'remove';
}

const DEFAULT_RULES: SanitizeRule[] = [
  { fields: ['password', 'secret', 'token', 'authorization'], strategy: 'remove' },
  { fields: ['email'], strategy: 'mask' },
  { fields: ['creditCard', 'ssn'], strategy: 'mask' },
];

const sanitize = (data: Record<string, unknown>, rules: SanitizeRule[]): Record<string, unknown> => {
  const result = { ...data };

  for (const rule of rules) {
    for (const field of rule.fields) {
      if (!(field in result)) continue;

      switch (rule.strategy) {
        case 'remove':
          result[field] = '[REDACTED]';
          break;
        case 'mask': {
          const value = String(result[field]);
          if (value.length <= 4) {
            result[field] = '****';
          } else {
            result[field] = value.slice(0, 2) + '*'.repeat(value.length - 4) + value.slice(-2);
          }
          break;
        }
        case 'hash':
          result[field] = `sha256:${hashValue(String(result[field]))}`;
          break;
      }
    }
  }

  return result;
};

const createSanitizedLogger = (baseLogger: Logger, rules: SanitizeRule[]): Logger => ({
  ...baseLogger,
  info: (msg, data) => baseLogger.info(msg, data ? sanitize(data, rules) : undefined),
  warn: (msg, data) => baseLogger.warn(msg, data ? sanitize(data, rules) : undefined),
  error: (msg, data) => baseLogger.error(msg, data ? sanitize(data, rules) : undefined),
  debug: (msg, data) => baseLogger.debug(msg, data ? sanitize(data, rules) : undefined),
  fatal: (msg, data) => baseLogger.fatal(msg, data ? sanitize(data, rules) : undefined),
  child: (ctx) => createSanitizedLogger(baseLogger.child(ctx), rules),
});
脱敏应在日志器层面统一处理，而非在每个调用点手动过滤。三种脱敏策略：remove（完全替换为 [REDACTED]）适用于密码和 Token，mask（部分遮盖）适用于邮箱和手机号，hash（哈希）适用于需要关联但不可逆的场景。


小结
    

  • 结构化日志以 JSON 格式输出，支持日志聚合系统的高效索引和查询
    • 

  • child 方法创建携带上下文的子日志器，是请求级日志的核心机制
    • 

  • AsyncLocalStorage 在异步调用链中自动传播上下文，无需手动传递
    • 

  • 动态日志级别调整让生产问题排查无需重启服务
    • 

  • 敏感数据脱敏应在日志器层面统一处理，防止信息泄漏
    • 

  • 错误日志输出到 stderr，普通日志输出到 stdout，便于运维分流
