分布式追踪实现

核心概念

分布式追踪（Distributed Tracing）是在微服务架构中追踪一个请求跨多个服务的完整调用路径的技术。当一个用户请求经过 API 网关、用户服务、订单服务和支付服务时，分布式追踪将这些分散的调用关联成一条完整的链路，让开发者能够看到请求在每个服务中花费的时间和发生的错误。

OpenTelemetry 是目前分布式追踪的行业标准，它统一了 Trace、Span、Context 三个核心概念，提供跨语言、跨框架的追踪能力。

graph LR
    A["Trace: abc-123"] --> B[Span: API Gateway 50ms]
    B --> C[Span: User Service 20ms]
    B --> D[Span: Order Service 30ms]
    D --> E[Span: DB Query 15ms]
    D --> F[Span: Cache Lookup 2ms]
概念 定义 生命周期 示例
Trace 一个完整请求的调用链 从入口到最终响应 用户下单的完整流程
Span 调用链中的一个操作单元 操作开始到结束 一次 HTTP 调用、一次 DB 查询
Context 跨服务传播的追踪信息 请求生命周期 TraceId + SpanId + Flags
Baggage 跨服务传播的业务数据 请求生命周期 userId, tenantId

Span 模型与追踪器

Span 是分布式追踪的基本单元。每个 Span 记录了一个操作的开始时间、结束时间、状态和上下文信息。

interface SpanContext {
  traceId: string;
  spanId: string;
  parentSpanId?: string;
  traceFlags: number;
}

interface SpanData {
  context: SpanContext;
  name: string;
  kind: 'server' | 'client' | 'internal' | 'producer' | 'consumer';
  startTime: number;
  endTime?: number;
  status: 'ok' | 'error' | 'unset';
  attributes: Record<string, string | number | boolean>;
  events: Array<{ name: string; timestamp: number; attributes?: Record<string, unknown> }>;
}

interface Tracer {
  startSpan(name: string, options?: { kind?: SpanData['kind']; parent?: SpanContext }): Span;
}

interface Span {
  context: SpanContext;
  setAttribute(key: string, value: string | number | boolean): void;
  addEvent(name: string, attributes?: Record<string, unknown>): void;
  setStatus(status: SpanData['status'], message?: string): void;
  end(): void;
}

const generateId = (bytes: number): string =>
  Array.from(crypto.getRandomValues(new Uint8Array(bytes)))
    .map((b) => b.toString(16).padStart(2, '0'))
    .join('');

const createTracer = (serviceName: string, exporter: SpanExporter): Tracer => ({
  startSpan(name, options) {
    const parentContext = options?.parent;
    const traceId = parentContext?.traceId ?? generateId(16);
    const spanId = generateId(8);

    const span: SpanData = {
      context: { traceId, spanId, parentSpanId: parentContext?.spanId, traceFlags: 1 },
      name,
      kind: options?.kind ?? 'internal',
      startTime: performance.now(),
      status: 'unset',
      attributes: { 'service.name': serviceName },
      events: [],
    };

    return {
      context: span.context,
      setAttribute: (key, value) => {
        span.attributes[key] = value;
      },
      addEvent: (eventName, attrs) => {
        span.events.push({ name: eventName, timestamp: performance.now(), attributes: attrs });
      },
      setStatus: (status, message) => {
        span.status = status;
        if (message) span.attributes['status.message'] = message;
      },
      end: () => {
        span.endTime = performance.now();
        exporter.export(span);
      },
    };
  },
});

Span Kind 标识了 Span 在调用关系中的角色：server 表示被调用方，client 表示调用方，internal 表示内部操作。这个信息帮助追踪系统正确地渲染调用关系图。

上下文传播机制

上下文传播（Context Propagation）是分布式追踪的核心挑战。当服务 A 调用服务 B 时，追踪上下文必须通过 HTTP 头传递，让服务 B 知道这次调用属于哪个 Trace。

const W3C_TRACEPARENT = 'traceparent';
const W3C_TRACESTATE = 'tracestate';

const injectContext = (context: SpanContext, headers: Headers): void => {
  const version = '00';
  const traceFlags = context.traceFlags.toString(16).padStart(2, '0');
  headers.set(W3C_TRACEPARENT, `${version}-${context.traceId}-${context.spanId}-${traceFlags}`);
};

const extractContext = (headers: Headers): SpanContext | null => {
  const traceparent = headers.get(W3C_TRACEPARENT);
  if (!traceparent) return null;

  const parts = traceparent.split('-');
  if (parts.length !== 4) return null;

  return {
    traceId: parts[1],
    spanId: parts[2],
    traceFlags: parseInt(parts[3], 16),
  };
};

const tracingMiddleware = (tracer: Tracer): MiddlewareHandler => {
  return async (c, next) => {
    const parentContext = extractContext(c.req.raw.headers);

    const span = tracer.startSpan(`${c.req.method} ${c.req.path}`, {
      kind: 'server',
      parent: parentContext ?? undefined,
    });

    span.setAttribute('http.method', c.req.method);
    span.setAttribute('http.url', c.req.url);
    span.setAttribute('http.route', c.req.path);

    c.set('span', span);
    c.header('X-Trace-Id', span.context.traceId);

    try {
      await next();
      span.setAttribute('http.status_code', c.res.status);
      span.setStatus(c.res.status < 400 ? 'ok' : 'error');
    } catch (error) {
      span.setStatus('error', (error as Error).message);
      span.addEvent('exception', {
        'exception.type': (error as Error).name,
        'exception.message': (error as Error).message,
      });
      throw error;
    } finally {
      span.end();
    }
  };
};

W3C Trace Context 是上下文传播的标准格式。traceparent 头包含版本号、Trace ID、Span ID 和 Trace Flags。每个服务收到请求后提取 parent context，创建新 Span 时将其设为父 Span。

自动插桩与手动插桩

插桩（Instrumentation）是将追踪逻辑注入到应用代码中的过程。自动插桩拦截 HTTP 客户端、数据库驱动等库的调用，手动插桩则用于业务逻辑的关键路径。

const tracedFetch = (tracer: Tracer, parentSpan: Span) => {
  return async (url: string, init?: RequestInit): Promise<Response> => {
    const span = tracer.startSpan(`HTTP ${init?.method ?? 'GET'} ${new URL(url).pathname}`, {
      kind: 'client',
      parent: parentSpan.context,
    });

    span.setAttribute('http.method', init?.method ?? 'GET');
    span.setAttribute('http.url', url);

    const headers = new Headers(init?.headers);
    injectContext(span.context, headers);

    try {
      const response = await fetch(url, { ...init, headers });
      span.setAttribute('http.status_code', response.status);
      span.setStatus(response.ok ? 'ok' : 'error');
      return response;
    } catch (error) {
      span.setStatus('error', (error as Error).message);
      throw error;
    } finally {
      span.end();
    }
  };
};

const tracedQuery = (tracer: Tracer, parentSpan: Span, pool: Pool) => {
  return async (sql: string, params?: unknown[]) => {
    const span = tracer.startSpan('DB Query', {
      kind: 'client',
      parent: parentSpan.context,
    });

    span.setAttribute('db.system', 'postgresql');
    span.setAttribute('db.statement', sql.slice(0, 200));

    try {
      const result = await pool.query(sql, params);
      span.setAttribute('db.rows_affected', result.rowCount ?? 0);
      span.setStatus('ok');
      return result;
    } catch (error) {
      span.setStatus('error', (error as Error).message);
      throw error;
    } finally {
      span.end();
    }
  };
};

自动插桩封装了 fetch 和数据库查询，自动创建 client Span 并注入上下文。SQL 语句记录时应截断长度，避免日志膨胀和敏感数据泄漏。

采样策略与性能优化

在高流量系统中，为每个请求都创建完整的追踪数据会导致巨大的存储和网络开销。采样策略决定哪些请求需要被追踪。

type SamplerDecision = 'record' | 'drop';

interface Sampler {
  shouldSample(context: SpanContext): SamplerDecision;
}

const createProbabilitySampler = (rate: number): Sampler => ({
  shouldSample: () => (Math.random() < rate ? 'record' : 'drop'),
});

const createRateLimitingSampler = (maxPerSecond: number): Sampler => {
  let tokens = maxPerSecond;
  let lastRefill = Date.now();

  return {
    shouldSample: () => {
      const now = Date.now();
      const elapsed = (now - lastRefill) / 1000;
      tokens = Math.min(maxPerSecond, tokens + elapsed * maxPerSecond);
      lastRefill = now;

      if (tokens >= 1) {
        tokens -= 1;
        return 'record';
      }
      return 'drop';
    },
  };
};

const createCompositeSampler = (
  rules: Array<{
    matcher: (name: string) => boolean;
    sampler: Sampler;
  }>,
): Sampler => ({
  shouldSample: (context) => {
    for (const rule of rules) {
      if (rule.matcher(context.traceId)) {
        return rule.sampler.shouldSample(context);
      }
    }
    return 'drop';
  },
});
采样策略 准确性 开销 适用场景
全量采样 100% 最高 低流量/调试
概率采样 (10%) 统计准确 低 高流量通用
速率限制 (100/s) 固定采样量 可控 稳定开销需求
基于错误 错误 100% 低 错误排查优先

最佳实践是组合使用多种策略：错误请求 100% 采样，正常请求 10% 概率采样，慢请求（延迟超阈值）100% 采样。

  • 分布式追踪通过 Trace-Span 模型关联跨服务的调用链路
  • W3C Trace Context 是上下文传播的行业标准，通过 traceparent 头传递
  • 自动插桩封装 HTTP 客户端和数据库驱动，减少手动编码
  • 采样策略在追踪精度和性能开销之间取得平衡
  • 错误请求应 100% 采样，确保故障链路完整可追踪
  • Span 属性遵循 OpenTelemetry 语义约定，便于跨系统互操作
