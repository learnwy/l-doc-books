健康检查模式

核心概念

健康检查（Health Check）是后端服务向外部系统报告自身运行状态的机制。在容器编排（Kubernetes）、负载均衡器和服务发现系统中，健康检查决定了流量是否被路由到该实例、实例是否需要重启、以及新实例何时可以接受请求。

Kubernetes 定义了三种探针（Probe），分别对应服务生命周期的不同阶段。正确配置这三种探针是保障服务可用性的关键。

多层健康检查实现
生产级的健康检查不是简单的 200 OK 响应，而是需要检查数据库连接、缓存可用性、磁盘空间等关键依赖。


import { Hono } from 'hono';

type HealthStatus = 'healthy' | 'degraded' | 'unhealthy';

interface DependencyCheck {
  name: string;
  check: () => Promise<{ status: HealthStatus; message?: string; latency?: number }>;
  critical: boolean;
}

interface HealthReport {
  status: HealthStatus;
  timestamp: string;
  uptime: number;
  version: string;
  dependencies: Array<{
    name: string;
    status: HealthStatus;
    latency?: number;
    message?: string;
  }>;
}

const createHealthChecker = (dependencies: DependencyCheck[], version: string) => {
  const startTime = Date.now();

  const check = async (): Promise<HealthReport> => {
    const results = await Promise.allSettled(
      dependencies.map(async (dep) => {
        const start = performance.now();
        try {
          const result = await Promise.race([
            dep.check(),
            new Promise<never>((_, reject) => setTimeout(() => reject(new Error('Health check timeout')), 5000)),
          ]);
          return {
            name: dep.name,
            ...result,
            latency: performance.now() - start,
            critical: dep.critical,
          };
        } catch (error) {
          return {
            name: dep.name,
            status: 'unhealthy' as HealthStatus,
            message: (error as Error).message,
            latency: performance.now() - start,
            critical: dep.critical,
          };
        }
      }),
    );

    const depResults = results.map((r) =>
      r.status === 'fulfilled' ? r.value : { name: 'unknown', status: 'unhealthy' as HealthStatus, critical: true },
    );

    const hasCriticalFailure = depResults.some((d) => d.critical && d.status === 'unhealthy');
    const hasAnyFailure = depResults.some((d) => d.status !== 'healthy');

    return {
      status: hasCriticalFailure ? 'unhealthy' : hasAnyFailure ? 'degraded' : 'healthy',
      timestamp: new Date().toISOString(),
      uptime: Math.floor((Date.now() - startTime) / 1000),
      version,
      dependencies: depResults.map(({ critical, ...rest }) => rest),
    };
  };

  return { check };
};
Promise.race 配合超时确保单个依赖的检查不会阻塞整个健康报告。关键依赖（critical: true）的失败导致整体状态为 unhealthy，非关键依赖的失败导致 degraded。


依赖健康检查
每种依赖类型需要特定的检查方法。数据库检查连接是否可用，Redis 检查是否响应，磁盘检查可用空间。


import type { Pool } from 'pg';
import type { Redis } from 'ioredis';

const createDbCheck = (pool: Pool): DependencyCheck => ({
  name: 'postgresql',
  critical: true,
  check: async () => {
    try {
      const { rows } = await pool.query('SELECT 1 as ok');
      const poolStats = {
        total: pool.totalCount,
        idle: pool.idleCount,
        waiting: pool.waitingCount,
      };

      const status: HealthStatus = pool.waitingCount > 5 ? 'degraded' : 'healthy';

      return { status, message: JSON.stringify(poolStats) };
    } catch (error) {
      return { status: 'unhealthy', message: (error as Error).message };
    }
  },
});

const createRedisCheck = (redis: Redis): DependencyCheck => ({
  name: 'redis',
  critical: true,
  check: async () => {
    try {
      const start = performance.now();
      await redis.ping();
      const latency = performance.now() - start;

      const status: HealthStatus = latency > 100 ? 'degraded' : 'healthy';
      return { status, latency };
    } catch (error) {
      return { status: 'unhealthy', message: (error as Error).message };
    }
  },
});

const createDiskCheck = (path: string, minFreeGB: number): DependencyCheck => ({
  name: 'disk',
  critical: false,
  check: async () => {
    try {
      const { availableForUser } = await import('node:fs/promises').then((fs) => fs.statfs(path));
      const freeGB = Number(availableForUser) / 1024 ** 3;
      const status: HealthStatus = freeGB < minFreeGB ? 'degraded' : 'healthy';
      return { status, message: `${freeGB.toFixed(1)} GB free` };
    } catch (error) {
      return { status: 'unhealthy', message: (error as Error).message };
    }
  },
});

const createMemoryCheck = (maxUsagePercent: number): DependencyCheck => ({
  name: 'memory',
  critical: false,
  check: async () => {
    const usage = process.memoryUsage();
    const heapUsedMB = usage.heapUsed / (1024 * 1024);
    const heapTotalMB = usage.heapTotal / (1024 * 1024);
    const usagePercent = (heapUsedMB / heapTotalMB) * 100;

    const status: HealthStatus = usagePercent > maxUsagePercent ? 'degraded' : 'healthy';
    return {
      status,
      message: `${heapUsedMB.toFixed(0)}MB / ${heapTotalMB.toFixed(0)}MB (${usagePercent.toFixed(1)}%)`,
    };
  },
});
数据库连接池的 waitingCount 是衡量数据库健康的重要指标——当等待连接的请求过多时，说明池中连接不足或查询过慢，标记为 degraded。


健康检查路由注册
健康检查端点需要区分轻量级探针（Kubernetes 使用）和详细报告（运维使用），并且必须不受认证中间件的影响。


const registerHealthRoutes = (app: Hono, checker: ReturnType<typeof createHealthChecker>) => {
  app.get('/health/live', (c) => c.json({ status: 'ok' }));

  app.get('/health/ready', async (c) => {
    const report = await checker.check();
    const httpStatus = report.status === 'unhealthy' ? 503 : 200;
    return c.json({ status: report.status }, httpStatus as 200);
  });

  app.get('/health/startup', async (c) => {
    const report = await checker.check();
    const httpStatus = report.status === 'unhealthy' ? 503 : 200;
    return c.json({ status: report.status }, httpStatus as 200);
  });

  app.get('/health/detail', async (c) => {
    const report = await checker.check();
    const httpStatus = report.status === 'unhealthy' ? 503 : 200;
    return c.json(report, httpStatus as 200);
  });
};

const healthChecker = createHealthChecker(
  [createDbCheck(pool), createRedisCheck(redis), createDiskCheck('/data', 1), createMemoryCheck(90)],
  process.env.APP_VERSION ?? '0.0.0',
);

registerHealthRoutes(app, healthChecker);

存活探针（/health/live）应尽可能轻量——它只需要证明进程还在运行，不需要检查任何依赖。如果存活探针去检查数据库，数据库短暂不可用会导致容器被不必要地重启，引发更大的故障。


健康检查缓存与抖动防护
频繁的健康检查可能对依赖系统造成压力。缓存和抖动防护确保健康检查既及时又不造成负担。


const createCachedHealthChecker = (checker: ReturnType<typeof createHealthChecker>, cacheDurationMs: number) => {
  let cachedReport: HealthReport | null = null;
  let lastCheckTime = 0;
  let consecutiveFailures = 0;
  const failureThreshold = 3;

  return {
    check: async (): Promise<HealthReport> => {
      const now = Date.now();

      if (cachedReport && now - lastCheckTime < cacheDurationMs) {
        return cachedReport;
      }

      const report = await checker.check();
      lastCheckTime = now;

      if (report.status === 'unhealthy') {
        consecutiveFailures++;
        if (consecutiveFailures < failureThreshold && cachedReport?.status !== 'unhealthy') {
          return cachedReport ?? report;
        }
      } else {
        consecutiveFailures = 0;
      }

      cachedReport = report;
      return report;
    },
  };
};
抖动防护的核心逻辑是：只有连续 N 次检查都失败时才真正报告 unhealthy。这防止了因网络瞬断或短暂负载导致的误判。缓存机制避免了高频探针请求对依赖系统的压力。


小结
    

  • 三种 Kubernetes 探针对应服务生命周期的不同阶段，配置各有侧重
    • 

  • 存活探针必须轻量，不检查外部依赖，避免依赖故障导致不必要的容器重启
    • 

  • 关键依赖失败导致 unhealthy（503），非关键依赖失败导致 degraded（200）
    • 

  • Promise.allSettled 并行检查所有依赖，单个超时不影响整体
    • 

  • 抖动防护要求连续多次检查失败才报告 unhealthy，避免瞬断误判
    • 

  • 详细健康报告端点供运维使用，探针端点供编排平台使用
