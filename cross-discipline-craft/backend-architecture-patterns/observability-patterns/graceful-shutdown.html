优雅关闭

核心概念

优雅关闭（Graceful Shutdown）是后端服务在收到终止信号后，有序地完成所有正在进行的工作、释放资源并安全退出的过程。与暴力终止（直接 kill -9）不同，优雅关闭确保正在处理的请求不会被中断、数据库事务不会处于不一致状态、消息队列中的消息不会丢失。

在容器编排环境（Kubernetes）中，Pod 终止时会先发送 SIGTERM 信号，等待 terminationGracePeriodSeconds（默认 30 秒），然后发送 SIGKILL 强制终止。服务必须在这个窗口内完成所有清理工作。

信号处理与关闭流程
Node.js 进程通过监听系统信号启动关闭流程。SIGTERM 是标准的优雅终止信号，SIGINT 对应 Ctrl+C 中断。


import type { Server } from 'node:http';

interface ShutdownHook {
  name: string;
  handler: () => Promise<void>;
  timeout: number;
  order: number;
}

const createGracefulShutdown = (server: Server, options: { timeout: number }) => {
  const hooks: ShutdownHook[] = [];
  let isShuttingDown = false;

  const register = (hook: ShutdownHook) => {
    hooks.push(hook);
    hooks.sort((a, b) => a.order - b.order);
  };

  const shutdown = async (signal: string) => {
    if (isShuttingDown) return;
    isShuttingDown = true;

    console.log(`Received ${signal}, starting graceful shutdown...`);

    const forceExitTimer = setTimeout(() => {
      console.error('Graceful shutdown timeout, forcing exit');
      process.exit(1);
    }, options.timeout);

    try {
      await new Promise<void>((resolve, reject) => {
        server.close((err) => {
          if (err) reject(err);
          else resolve();
        });
      });

      console.log('HTTP server closed, running shutdown hooks...');

      for (const hook of hooks) {
        try {
          await Promise.race([
            hook.handler(),
            new Promise<never>((_, reject) =>
              setTimeout(() => reject(new Error(`Hook ${hook.name} timeout`)), hook.timeout),
            ),
          ]);
          console.log(`Hook ${hook.name} completed`);
        } catch (error) {
          console.error(`Hook ${hook.name} failed:`, (error as Error).message);
        }
      }

      clearTimeout(forceExitTimer);
      console.log('Graceful shutdown complete');
      process.exit(0);
    } catch (error) {
      console.error('Shutdown error:', error);
      clearTimeout(forceExitTimer);
      process.exit(1);
    }
  };

  process.on('SIGTERM', () => shutdown('SIGTERM'));
  process.on('SIGINT', () => shutdown('SIGINT'));

  return { register, isShuttingDown: () => isShuttingDown };
};
全局超时定时器（forceExitTimer）是最后的安全网——即使某个清理步骤卡住，服务也不会无限期地拖延关闭过程。Hook 按 order 排序确保了正确的关闭顺序（先关闭上游依赖，再关闭下游依赖）。


连接排空与请求完成
关闭 HTTP 服务器后，已建立的 Keep-Alive 连接上可能还有正在处理的请求。连接排空确保这些请求能够正常完成。


import type { MiddlewareHandler } from 'hono';

const createDrainingMiddleware = (shutdownState: { isShuttingDown: () => boolean }): MiddlewareHandler => {
  let activeRequests = 0;
  const waiters: Array<() => void> = [];

  const middleware: MiddlewareHandler = async (c, next) => {
    if (shutdownState.isShuttingDown()) {
      c.header('Connection', 'close');
      return c.json({ error: 'Service is shutting down' }, 503);
    }

    activeRequests++;
    try {
      await next();
    } finally {
      activeRequests--;
      if (activeRequests === 0) {
        for (const resolve of waiters) resolve();
        waiters.length = 0;
      }
    }
  };

  const waitForDrain = (): Promise<void> => {
    if (activeRequests === 0) return Promise.resolve();
    return new Promise((resolve) => waiters.push(resolve));
  };

  return Object.assign(middleware, { waitForDrain, getActiveCount: () => activeRequests });
};
Connection: close 响应头告知客户端此连接不可复用，引导客户端将后续请求发往其他健康实例。已在处理中的请求正常完成，新请求直接返回 503。


资源清理钩子注册
数据库连接池、Redis 客户端、定时任务等资源都需要在关闭时正确清理。


import type { Pool } from 'pg';
import type { Redis } from 'ioredis';

const registerResourceHooks = (
  shutdown: ReturnType<typeof createGracefulShutdown>,
  resources: {
    pool?: Pool;
    redis?: Redis;
    schedulers?: Array<{ stop: () => void; name: string }>;
    workers?: Array<{ terminate: () => Promise<number> }>;
    draining?: ReturnType<typeof createDrainingMiddleware>;
  },
) => {
  if (resources.draining) {
    shutdown.register({
      name: 'drain-requests',
      handler: async () => {
        const draining = resources.draining as { waitForDrain: () => Promise<void>; getActiveCount: () => number };
        console.log(`Draining ${draining.getActiveCount()} active requests...`);
        await draining.waitForDrain();
      },
      timeout: 15_000,
      order: 1,
    });
  }

  if (resources.schedulers) {
    for (const scheduler of resources.schedulers) {
      shutdown.register({
        name: `scheduler-${scheduler.name}`,
        handler: async () => {
          scheduler.stop();
        },
        timeout: 1_000,
        order: 2,
      });
    }
  }

  if (resources.workers) {
    shutdown.register({
      name: 'worker-threads',
      handler: async () => {
        await Promise.all(resources.workers!.map((w) => w.terminate()));
      },
      timeout: 5_000,
      order: 3,
    });
  }

  if (resources.redis) {
    shutdown.register({
      name: 'redis',
      handler: async () => {
        await resources.redis!.quit();
      },
      timeout: 3_000,
      order: 4,
    });
  }

  if (resources.pool) {
    shutdown.register({
      name: 'postgresql',
      handler: async () => {
        await resources.pool!.end();
      },
      timeout: 5_000,
      order: 5,
    });
  }
};
关闭顺序遵循依赖关系：先排空 HTTP 请求（order 1），再停止定时任务（order 2），然后终止 Worker 线程（order 3），接着关闭 Redis（order 4），最后关闭数据库（order 5）。数据库最后关闭是因为前面的步骤可能仍需要数据库操作。


完整服务启动与关闭
将所有组件组合在一起，构建完整的服务生命周期管理。


const bootstrap = async () => {
  const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });
  const redis = new Redis(process.env.REDIS_URL);

  const app = new Hono();
  const shutdownManager = createGracefulShutdown(server, { timeout: 30_000 });
  const draining = createDrainingMiddleware(shutdownManager);

  app.use('*', draining);

  const healthChecker = createHealthChecker(
    [createDbCheck(pool), createRedisCheck(redis)],
    process.env.APP_VERSION ?? '0.0.0',
  );

  registerHealthRoutes(app, healthChecker);

  app.get('/api/hello', (c) => c.json({ message: 'Hello' }));

  registerResourceHooks(shutdownManager, {
    pool,
    redis,
    draining,
  });

  const server = app.listen(Number(process.env.PORT ?? 3000), () => {
    console.log(
      JSON.stringify({
        event: 'server_started',
        port: process.env.PORT ?? 3000,
        pid: process.pid,
        nodeVersion: process.version,
      }),
    );
  });
};

bootstrap().catch((error) => {
  console.error('Failed to start server:', error);
  process.exit(1);
});

小结
    

  • 优雅关闭确保正在处理的请求不被中断，资源被正确释放
    • 

  • SIGTERM 是标准的优雅终止信号，Kubernetes 在杀死 Pod 前先发送 SIGTERM
    • 

  • 连接排空通过中间件追踪活跃请求数，新请求返回 503 + Connection: close
    • 

  • 资源清理按依赖顺序执行：HTTP → 调度器 → Worker → Redis → 数据库
    • 

  • 全局超时定时器确保关闭过程不会无限期挂起
    • 

  • 每个清理钩子都有独立超时，单个钩子失败不阻塞整体关闭流程
