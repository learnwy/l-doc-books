仓储模式

核心概念

仓储模式（Repository Pattern）是领域驱动设计（DDD）中的核心模式之一，它在业务逻辑层和数据持久化层之间建立一个抽象层，使得领域代码不直接依赖具体的数据库实现。仓储对外暴露类似集合的接口（增删改查），内部封装了数据库查询、ORM 调用等持久化细节。

这种解耦带来的最大收益是可测试性——业务逻辑可以通过 Mock 仓储进行单元测试，无需启动真实数据库。同时，当需要更换数据库或存储方案时，只需替换仓储实现，业务逻辑层无需修改。

仓储接口设计
仓储接口是模式的核心，它定义了领域层对数据访问的期望。接口设计应遵循领域语言，方法命名反映业务意图而非数据库操作。


interface Entity {
  id: string;
  createdAt: Date;
  updatedAt: Date;
}

interface User extends Entity {
  name: string;
  email: string;
  role: 'admin' | 'user' | 'guest';
  status: 'active' | 'inactive' | 'banned';
}

interface UserRepository {
  findById(id: string): Promise<User | null>;
  findByEmail(email: string): Promise<User | null>;
  findActiveByRole(role: User['role']): Promise<User[]>;
  save(user: Omit<User, 'id' | 'createdAt' | 'updatedAt'>): Promise<User>;
  update(id: string, data: Partial<Pick<User, 'name' | 'role' | 'status'>>): Promise<User>;
  remove(id: string): Promise<void>;
  count(filter?: { role?: User['role']; status?: User['status'] }): Promise<number>;
}

interface PaginatedResult<T> {
  items: T[];
  total: number;
  page: number;
  pageSize: number;
  hasMore: boolean;
}

interface UserQueryOptions {
  page?: number;
  pageSize?: number;
  sortBy?: keyof User;
  sortOrder?: 'asc' | 'desc';
  filter?: { role?: User['role']; status?: User['status'] };
}

interface ExtendedUserRepository extends UserRepository {
  search(query: string, options?: UserQueryOptions): Promise<PaginatedResult<User>>;
}
接口方法应避免暴露数据库特定的概念（如 SQL WHERE 子句、MongoDB 查询文档）。findActiveByRole 比 findByStatusAndRole 更具领域语义。分页结果类型 PaginatedResult<T> 是通用的，可以在多个仓储间复用。


PostgreSQL 仓储实现
仓储实现负责将接口方法转换为具体的数据库操作。每个实现封装了特定数据库的查询语法和连接管理。


import type { Pool } from 'pg';

const createPgUserRepository = (pool: Pool): UserRepository => {
  const findById = async (id: string): Promise<User | null> => {
    const { rows } = await pool.query('SELECT * FROM users WHERE id = $1', [id]);
    return rows[0] ? mapRowToUser(rows[0]) : null;
  };

  const findByEmail = async (email: string): Promise<User | null> => {
    const { rows } = await pool.query('SELECT * FROM users WHERE email = $1', [email]);
    return rows[0] ? mapRowToUser(rows[0]) : null;
  };

  const findActiveByRole = async (role: User['role']): Promise<User[]> => {
    const { rows } = await pool.query(
      "SELECT * FROM users WHERE role = $1 AND status = 'active' ORDER BY created_at DESC",
      [role],
    );
    return rows.map(mapRowToUser);
  };

  const save = async (data: Omit<User, 'id' | 'createdAt' | 'updatedAt'>): Promise<User> => {
    const id = crypto.randomUUID();
    const now = new Date();
    const { rows } = await pool.query(
      `INSERT INTO users (id, name, email, role, status, created_at, updated_at)
       VALUES ($1, $2, $3, $4, $5, $6, $7) RETURNING *`,
      [id, data.name, data.email, data.role, data.status, now, now],
    );
    return mapRowToUser(rows[0]);
  };

  const update = async (id: string, data: Partial<Pick<User, 'name' | 'role' | 'status'>>): Promise<User> => {
    const fields: string[] = [];
    const values: unknown[] = [];
    let idx = 1;

    for (const [key, value] of Object.entries(data)) {
      if (value !== undefined) {
        fields.push(`${toSnakeCase(key)} = $${idx++}`);
        values.push(value);
      }
    }

    fields.push(`updated_at = $${idx++}`);
    values.push(new Date());
    values.push(id);

    const { rows } = await pool.query(`UPDATE users SET ${fields.join(', ')} WHERE id = $${idx} RETURNING *`, values);
    return mapRowToUser(rows[0]);
  };

  const remove = async (id: string): Promise<void> => {
    await pool.query('DELETE FROM users WHERE id = $1', [id]);
  };

  const count = async (filter?: { role?: User['role']; status?: User['status'] }): Promise<number> => {
    let sql = 'SELECT COUNT(*) FROM users';
    const conditions: string[] = [];
    const values: unknown[] = [];

    if (filter?.role) {
      conditions.push(`role = $${conditions.length + 1}`);
      values.push(filter.role);
    }
    if (filter?.status) {
      conditions.push(`status = $${conditions.length + 1}`);
      values.push(filter.status);
    }

    if (conditions.length) sql += ` WHERE ${conditions.join(' AND ')}`;
    const { rows } = await pool.query(sql, values);
    return Number(rows[0].count);
  };

  return { findById, findByEmail, findActiveByRole, save, update, remove, count };
};
仓储实现通过工厂函数接收数据库连接池，返回符合接口的对象。mapRowToUser 函数处理数据库行到领域对象的映射（如 snake_case 到 camelCase），将这种映射逻辑集中在一处。


内存仓储与测试策略
内存仓储是仓储模式最重要的附加价值之一。它提供了一个零依赖的仓储实现，用于单元测试和开发阶段的快速迭代。


const createInMemoryUserRepository = (): UserRepository => {
  const store = new Map<string, User>();

  return {
    findById: async (id) => store.get(id) ?? null,

    findByEmail: async (email) => [...store.values()].find((u) => u.email === email) ?? null,

    findActiveByRole: async (role) => [...store.values()].filter((u) => u.role === role && u.status === 'active'),

    save: async (data) => {
      const user: User = {
        ...data,
        id: crypto.randomUUID(),
        createdAt: new Date(),
        updatedAt: new Date(),
      };
      store.set(user.id, user);
      return user;
    },

    update: async (id, data) => {
      const existing = store.get(id);
      if (!existing) throw new Error(`User ${id} not found`);
      const updated = { ...existing, ...data, updatedAt: new Date() };
      store.set(id, updated);
      return updated;
    },

    remove: async (id) => {
      store.delete(id);
    },

    count: async (filter) => {
      let users = [...store.values()];
      if (filter?.role) users = users.filter((u) => u.role === filter.role);
      if (filter?.status) users = users.filter((u) => u.status === filter.status);
      return users.length;
    },
  };
};
测试时使用内存仓储替代真实数据库，测试执行速度提升数十倍，且不需要管理测试数据库的生命周期。每个测试用例可以使用独立的仓储实例，天然隔离测试数据。


泛型仓储与组合
当系统中存在多个实体时，重复编写 CRUD 操作是低效的。泛型仓储提取了通用操作，具体仓储通过继承或组合扩展领域特定方法。


interface BaseRepository<T extends Entity> {
  findById(id: string): Promise<T | null>;
  findAll(options?: { limit?: number; offset?: number }): Promise<T[]>;
  save(data: Omit<T, 'id' | 'createdAt' | 'updatedAt'>): Promise<T>;
  update(id: string, data: Partial<T>): Promise<T>;
  remove(id: string): Promise<void>;
  count(): Promise<number>;
}

const createBaseRepository = <T extends Entity>(
  pool: Pool,
  tableName: string,
  mapRow: (row: Record<string, unknown>) => T,
): BaseRepository<T> => ({
  findById: async (id) => {
    const { rows } = await pool.query(`SELECT * FROM ${tableName} WHERE id = $1`, [id]);
    return rows[0] ? mapRow(rows[0]) : null;
  },

  findAll: async (options) => {
    const limit = options?.limit ?? 50;
    const offset = options?.offset ?? 0;
    const { rows } = await pool.query(`SELECT * FROM ${tableName} ORDER BY created_at DESC LIMIT $1 OFFSET $2`, [
      limit,
      offset,
    ]);
    return rows.map(mapRow);
  },

  save: async (data) => {
    const id = crypto.randomUUID();
    const now = new Date();
    const entry = { id, ...data, created_at: now, updated_at: now };
    const keys = Object.keys(entry);
    const values = Object.values(entry);
    const placeholders = keys.map((_, i) => `$${i + 1}`).join(', ');
    const { rows } = await pool.query(
      `INSERT INTO ${tableName} (${keys.join(', ')}) VALUES (${placeholders}) RETURNING *`,
      values,
    );
    return mapRow(rows[0]);
  },

  update: async (id, data) => {
    const entries = Object.entries(data).filter(([, v]) => v !== undefined);
    const sets = entries.map(([k], i) => `${k} = $${i + 1}`).join(', ');
    const values = [...entries.map(([, v]) => v), id];
    const { rows } = await pool.query(
      `UPDATE ${tableName} SET ${sets}, updated_at = NOW() WHERE id = $${values.length} RETURNING *`,
      values,
    );
    return mapRow(rows[0]);
  },

  remove: async (id) => {
    await pool.query(`DELETE FROM ${tableName} WHERE id = $1`, [id]);
  },

  count: async () => {
    const { rows } = await pool.query(`SELECT COUNT(*) FROM ${tableName}`);
    return Number(rows[0].count);
  },
});
泛型仓储通过表名和行映射函数参数化，避免了每个实体重复编写相同的 CRUD 逻辑。领域特定的查询方法（如 findActiveByRole）通过组合模式在泛型仓储基础上扩展。


小结
    

  • 仓储模式在业务逻辑和数据持久化之间建立抽象层，实现关注点分离
    • 

  • 接口方法命名应反映领域语义而非数据库操作
    • 

  • 内存仓储是单元测试的利器，提供零依赖的快速测试环境
    • 

  • 泛型仓储提取通用 CRUD，通过组合模式扩展领域特定查询
    • 

  • 工厂函数模式接收连接池参数，便于依赖注入和生命周期管理
    • 

  • 行到领域对象的映射应集中处理，保持数据转换的一致性
