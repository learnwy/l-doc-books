连接池管理

核心概念

连接池（Connection Pool）是后端服务管理数据库连接的核心机制。建立一个数据库连接涉及 TCP 握手、认证协商、会话初始化等步骤，耗时通常在 20-100ms。如果每次请求都创建新连接，这个开销会成为严重的性能瓶颈。连接池预先创建并维护一组数据库连接，请求到来时从池中借出（checkout）连接，使用完毕后归还（release），大幅降低连接创建的频率。

连接池的设计需要在资源利用率、响应延迟和稳定性之间取得平衡。池太小导致请求排队等待，池太大则浪费数据库资源并可能触发数据库端的连接数上限。

连接池实现原理
一个生产级连接池需要管理连接的完整生命周期：创建、借出、归还、健康检查、回收和销毁。


interface PoolOptions {
  min: number;
  max: number;
  idleTimeoutMs: number;
  acquireTimeoutMs: number;
  createConnection: () => Promise<Connection>;
  destroyConnection: (conn: Connection) => Promise<void>;
  validateConnection: (conn: Connection) => Promise<boolean>;
}

interface Connection {
  id: string;
  query(sql: string, params?: unknown[]): Promise<unknown>;
  release(): void;
}

interface PooledConnection {
  connection: Connection;
  createdAt: number;
  lastUsedAt: number;
  useCount: number;
}

const createConnectionPool = (options: PoolOptions) => {
  const idle: PooledConnection[] = [];
  const active = new Set<PooledConnection>();
  const waitQueue: Array<{
    resolve: (conn: Connection) => void;
    reject: (err: Error) => void;
    timer: ReturnType<typeof setTimeout>;
  }> = [];

  const totalCount = () => idle.length + active.size;

  const createPooled = async (): Promise<PooledConnection> => {
    const connection = await options.createConnection();
    return {
      connection,
      createdAt: Date.now(),
      lastUsedAt: Date.now(),
      useCount: 0,
    };
  };

  const acquire = async (): Promise<Connection> => {
    if (idle.length > 0) {
      const pooled = idle.pop()!;
      pooled.lastUsedAt = Date.now();
      pooled.useCount++;
      active.add(pooled);
      return wrapConnection(pooled);
    }

    if (totalCount() < options.max) {
      const pooled = await createPooled();
      pooled.useCount++;
      active.add(pooled);
      return wrapConnection(pooled);
    }

    return new Promise((resolve, reject) => {
      const timer = setTimeout(() => {
        const idx = waitQueue.findIndex((w) => w.resolve === resolve);
        if (idx >= 0) waitQueue.splice(idx, 1);
        reject(new Error('Connection acquire timeout'));
      }, options.acquireTimeoutMs);

      waitQueue.push({ resolve, reject, timer });
    });
  };

  const release = (pooled: PooledConnection) => {
    active.delete(pooled);

    if (waitQueue.length > 0) {
      const waiter = waitQueue.shift()!;
      clearTimeout(waiter.timer);
      pooled.lastUsedAt = Date.now();
      pooled.useCount++;
      active.add(pooled);
      waiter.resolve(wrapConnection(pooled));
      return;
    }

    pooled.lastUsedAt = Date.now();
    idle.push(pooled);
  };

  const wrapConnection = (pooled: PooledConnection): Connection => ({
    ...pooled.connection,
    release: () => release(pooled),
  });

  return { acquire, getStats: () => ({ idle: idle.length, active: active.size, waiting: waitQueue.length }) };
};
等待队列是连接池应对突发流量的关键机制。当所有连接都在使用中且已达到最大数量时，新请求进入等待队列，直到有连接归还或超时。


健康检查与坏连接处理
数据库连接可能因网络中断、数据库重启、防火墙超时等原因变为不可用。健康检查机制定期验证连接的存活状态，及时踢出坏连接。


const startHealthCheck = (pool: { getIdle: () => PooledConnection[] }, options: PoolOptions) => {
  const checkInterval = setInterval(async () => {
    const idleConnections = pool.getIdle();
    const now = Date.now();

    for (const pooled of idleConnections) {
      if (now - pooled.lastUsedAt > options.idleTimeoutMs) {
        await options.destroyConnection(pooled.connection);
        removeFromIdle(pooled);
        continue;
      }

      const isValid = await options.validateConnection(pooled.connection);
      if (!isValid) {
        await options.destroyConnection(pooled.connection);
        removeFromIdle(pooled);
      }
    }

    while (pool.getIdle().length < options.min) {
      try {
        const newConn = await options.createConnection();
        addToIdle({
          connection: newConn,
          createdAt: Date.now(),
          lastUsedAt: Date.now(),
          useCount: 0,
        });
      } catch {
        break;
      }
    }
  }, 30_000);

  return () => clearInterval(checkInterval);
};
验证查询通常使用 SELECT 1 或 SELECT true，开销极小但能有效检测连接是否存活。对于 PostgreSQL，还可以检查连接的 processID 是否仍然有效。


连接泄漏检测
连接泄漏是生产环境中最危险的问题之一。当业务代码借出连接但忘记归还时，池中的可用连接逐渐耗尽，最终导致所有请求超时。


interface LeakDetectorOptions {
  leakTimeoutMs: number;
  onLeak: (info: LeakInfo) => void;
}

interface LeakInfo {
  connectionId: string;
  acquiredAt: number;
  duration: number;
  stackTrace: string;
}

const withLeakDetection = (pool: { acquire: () => Promise<Connection> }, options: LeakDetectorOptions) => {
  const tracked = new Map<string, { timer: ReturnType<typeof setTimeout>; stack: string }>();

  return {
    acquire: async (): Promise<Connection> => {
      const stack = new Error().stack ?? '';
      const conn = await pool.acquire();

      const timer = setTimeout(() => {
        options.onLeak({
          connectionId: conn.id,
          acquiredAt: Date.now() - options.leakTimeoutMs,
          duration: options.leakTimeoutMs,
          stackTrace: stack,
        });
      }, options.leakTimeoutMs);

      tracked.set(conn.id, { timer, stack });

      const originalRelease = conn.release;
      conn.release = () => {
        const entry = tracked.get(conn.id);
        if (entry) {
          clearTimeout(entry.timer);
          tracked.delete(conn.id);
        }
        originalRelease();
      };

      return conn;
    },
  };
};
泄漏检测的原理是为每个借出的连接设置超时计时器。如果连接在预期时间内未被归还，触发告警并记录获取连接时的调用栈，帮助开发者定位泄漏源头。生产环境建议将泄漏超时设为 30-60 秒。


生产环境配置
不同框架和数据库驱动提供了开箱即用的连接池实现，关键是正确配置参数。


import pg from 'pg';

const pool = new pg.Pool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT ?? '5432'),
  database: process.env.DB_NAME,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  min: 2,
  max: 10,
  idleTimeoutMillis: 30_000,
  connectionTimeoutMillis: 5_000,
  maxUses: 7500,
  allowExitOnIdle: false,
});

pool.on('error', (err) => {
  console.error('Unexpected pool error:', err.message);
});

pool.on('connect', (client) => {
  client.query("SET statement_timeout = '30s'");
});

const getPoolMetrics = () => ({
  total: pool.totalCount,
  idle: pool.idleCount,
  waiting: pool.waitingCount,
});

maxUses 参数限制单个连接的使用次数，到达上限后强制销毁并创建新连接。这可以防止长期运行的连接积累内存泄漏或状态污染。


小结
    

  • 连接池通过复用连接避免频繁的 TCP 握手和认证开销
    • 

  • 最大连接数推荐 CPU 核数 × 2 + 1，平衡吞吐量和数据库资源
    • 

  • 健康检查定期验证连接存活，及时踢出坏连接并补充新连接
    • 

  • 连接泄漏检测通过超时计时器发现未归还的连接
    • 

  • 等待队列让连接池在突发流量下平滑降级而非立即失败
    • 

  • 生产环境必须配置 statement_timeout 和 maxUses 防止连接劣化
