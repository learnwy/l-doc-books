查询优化模式

核心概念

数据库查询是后端服务中最常见的性能瓶颈。查询优化模式是一套经过实践验证的策略，用于解决常见的数据访问性能问题。从经典的 N+1 查询问题到复杂的批量加载策略，掌握这些模式能让数据库交互效率提升数量级。

查询优化的核心原则是减少数据库往返次数（Round Trips）和减少每次查询的数据扫描量。网络延迟通常比查询执行时间更大，因此合并多次查询为一次批量操作往往比优化单条 SQL 更有效。

N+1 问题与批量加载
N+1 问题是 ORM 和手写查询中最常见的性能陷阱。当加载一个列表的关联数据时，先执行 1 次查询获取列表，再对列表中的每一项执行 1 次查询获取关联数据，总共 N+1 次查询。


const getUsersWithPosts_bad = async (pool: Pool) => {
  const { rows: users } = await pool.query('SELECT * FROM users LIMIT 20');
  for (const user of users) {
    const { rows: posts } = await pool.query('SELECT * FROM posts WHERE user_id = $1', [user.id]);
    user.posts = posts;
  }
  return users;
};

const getUsersWithPosts_good = async (pool: Pool) => {
  const { rows: users } = await pool.query('SELECT * FROM users LIMIT 20');
  if (users.length === 0) return users;

  const userIds = users.map((u) => u.id);
  const { rows: posts } = await pool.query('SELECT * FROM posts WHERE user_id = ANY($1)', [userIds]);

  const postsByUser = new Map<string, unknown[]>();
  for (const post of posts) {
    const list = postsByUser.get(post.user_id) ?? [];
    list.push(post);
    postsByUser.set(post.user_id, list);
  }

  for (const user of users) {
    user.posts = postsByUser.get(user.id) ?? [];
  }

  return users;
};
批量加载将 N 次单条查询合并为 1 次 WHERE IN 查询，数据库往返次数从 N+1 降低到 2。对于 20 条用户数据，查询次数从 21 次降到 2 次，性能提升 10 倍以上。


DataLoader 模式
DataLoader 是 Facebook 提出的通用批量加载模式，它在一个事件循环 tick 内收集所有加载请求，合并为一次批量查询。这种模式在 GraphQL 场景中尤其重要。


type BatchLoadFn<K, V> = (keys: K[]) => Promise<(V | null)[]>;

const createDataLoader = <K, V>(batchFn: BatchLoadFn<K, V>) => {
  let batch: {
    keys: K[];
    resolvers: Array<{
      resolve: (value: V | null) => void;
      reject: (error: Error) => void;
    }>;
  } | null = null;

  const scheduleBatch = () => {
    if (!batch) return;

    const currentBatch = batch;
    batch = null;

    queueMicrotask(async () => {
      try {
        const results = await batchFn(currentBatch.keys);
        for (let i = 0; i < currentBatch.resolvers.length; i++) {
          currentBatch.resolvers[i].resolve(results[i]);
        }
      } catch (error) {
        for (const resolver of currentBatch.resolvers) {
          resolver.reject(error as Error);
        }
      }
    });
  };

  const load = (key: K): Promise<V | null> => {
    return new Promise((resolve, reject) => {
      if (!batch) {
        batch = { keys: [], resolvers: [] };
        scheduleBatch();
      }
      batch.keys.push(key);
      batch.resolvers.push({ resolve, reject });
    });
  };

  return { load };
};

const userLoader = createDataLoader<string, User>(async (ids) => {
  const { rows } = await pool.query('SELECT * FROM users WHERE id = ANY($1)', [ids]);
  return ids.map((id) => rows.find((r) => r.id === id) ?? null);
});
DataLoader 的关键在于 queueMicrotask，它延迟批量执行到当前微任务队列末尾，让同一个 tick 内的所有 load 调用都能被收集到同一批次中。


查询构建器模式
动态查询构建是数据访问层的常见需求，硬编码 SQL 拼接容易导致 SQL 注入和维护困难。查询构建器提供类型安全的 API 来动态构建 SQL。


interface QueryBuilder {
  select(...columns: string[]): QueryBuilder;
  from(table: string): QueryBuilder;
  where(condition: string, ...params: unknown[]): QueryBuilder;
  orderBy(column: string, direction?: 'asc' | 'desc'): QueryBuilder;
  limit(count: number): QueryBuilder;
  offset(count: number): QueryBuilder;
  build(): { sql: string; params: unknown[] };
}

const createQueryBuilder = (): QueryBuilder => {
  const state = {
    columns: [] as string[],
    table: '',
    conditions: [] as { clause: string; params: unknown[] }[],
    orderClauses: [] as string[],
    limitVal: undefined as number | undefined,
    offsetVal: undefined as number | undefined,
  };

  let paramIndex = 1;

  const builder: QueryBuilder = {
    select: (...columns) => {
      state.columns = columns;
      return builder;
    },
    from: (table) => {
      state.table = table;
      return builder;
    },
    where: (condition, ...params) => {
      const indexed = condition.replace(/\?/g, () => `$${paramIndex++}`);
      state.conditions.push({ clause: indexed, params });
      return builder;
    },
    orderBy: (column, direction = 'asc') => {
      state.orderClauses.push(`${column} ${direction.toUpperCase()}`);
      return builder;
    },
    limit: (count) => {
      state.limitVal = count;
      return builder;
    },
    offset: (count) => {
      state.offsetVal = count;
      return builder;
    },
    build: () => {
      const cols = state.columns.length ? state.columns.join(', ') : '*';
      let sql = `SELECT ${cols} FROM ${state.table}`;
      const allParams: unknown[] = [];

      if (state.conditions.length) {
        sql += ` WHERE ${state.conditions.map((c) => c.clause).join(' AND ')}`;
        for (const c of state.conditions) allParams.push(...c.params);
      }
      if (state.orderClauses.length) {
        sql += ` ORDER BY ${state.orderClauses.join(', ')}`;
      }
      if (state.limitVal !== undefined) {
        sql += ` LIMIT $${paramIndex++}`;
        allParams.push(state.limitVal);
      }
      if (state.offsetVal !== undefined) {
        sql += ` OFFSET $${paramIndex++}`;
        allParams.push(state.offsetVal);
      }
      return { sql, params: allParams };
    },
  };

  return builder;
};

const buildUserQuery = (filters: {
  role?: string;
  status?: string;
  search?: string;
  page?: number;
  pageSize?: number;
}) => {
  const qb = createQueryBuilder().select('*').from('users');

  if (filters.role) qb.where('role = ?', filters.role);
  if (filters.status) qb.where('status = ?', filters.status);
  if (filters.search) qb.where('name ILIKE ?', `%${filters.search}%`);

  qb.orderBy('created_at', 'desc');

  const page = filters.page ?? 1;
  const pageSize = filters.pageSize ?? 20;
  qb.limit(pageSize).offset((page - 1) * pageSize);

  return qb.build();
};
查询构建器通过参数化查询防止 SQL 注入，通过链式 API 提供良好的开发体验。? 占位符自动转换为 $N 形式的 PostgreSQL 参数占位符。


请求级查询缓存
同一个 HTTP 请求中可能多次查询相同的数据（例如在多个中间件或服务中都需要当前用户信息）。请求级缓存在单次请求的生命周期内缓存查询结果，避免重复查询。


const createRequestCache = () => {
  const cache = new Map<string, Promise<unknown>>();

  return {
    get: <T>(key: string, loader: () => Promise<T>): Promise<T> => {
      const existing = cache.get(key);
      if (existing) return existing as Promise<T>;

      const promise = loader();
      cache.set(key, promise);

      promise.catch(() => cache.delete(key));

      return promise;
    },

    invalidate: (key: string) => cache.delete(key),
    clear: () => cache.clear(),
    size: () => cache.size,
  };
};

const createCachedUserRepo = (repo: UserRepository, cache: ReturnType<typeof createRequestCache>): UserRepository => ({
  ...repo,
  findById: (id) => cache.get(`user:${id}`, () => repo.findById(id)),
  findByEmail: (email) => cache.get(`user:email:${email}`, () => repo.findByEmail(email)),
});
请求级缓存缓存的是 Promise 而非结果值，这确保了并发调用同一个 key 时只会触发一次实际查询（去重效果）。缓存生命周期绑定到请求，请求结束后自动释放，无需手动管理过期。
