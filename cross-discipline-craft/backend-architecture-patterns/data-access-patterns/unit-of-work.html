工作单元模式

核心概念

工作单元模式（Unit of Work）是一种事务管理模式，它追踪一个业务操作中所有对实体的变更（新增、修改、删除），在操作完成时将这些变更作为一个原子事务统一提交到数据库。如果任何步骤失败，所有变更都会回滚，确保数据一致性。

工作单元的核心价值在于将事务边界的管理从业务代码中抽离出来。业务逻辑只需要操作实体对象，不必关心何时开启事务、何时提交或回滚——这些由工作单元统一协调。

事务管理抽象
事务管理是工作单元的基础能力。通过抽象事务接口，业务代码不直接依赖具体的数据库事务 API。


interface Transaction {
  query<T = unknown>(sql: string, params?: unknown[]): Promise<T[]>;
  commit(): Promise<void>;
  rollback(): Promise<void>;
}

interface TransactionManager {
  begin(): Promise<Transaction>;
  execute<T>(fn: (tx: Transaction) => Promise<T>): Promise<T>;
}

import type { Pool, PoolClient } from 'pg';

const createTransactionManager = (pool: Pool): TransactionManager => {
  const begin = async (): Promise<Transaction> => {
    const client = await pool.connect();
    await client.query('BEGIN');

    return {
      query: async (sql, params) => {
        const result = await client.query(sql, params);
        return result.rows;
      },
      commit: async () => {
        await client.query('COMMIT');
        client.release();
      },
      rollback: async () => {
        await client.query('ROLLBACK');
        client.release();
      },
    };
  };

  const execute = async <T>(fn: (tx: Transaction) => Promise<T>): Promise<T> => {
    const tx = await begin();
    try {
      const result = await fn(tx);
      await tx.commit();
      return result;
    } catch (error) {
      await tx.rollback();
      throw error;
    }
  };

  return { begin, execute };
};
execute 方法是最常用的事务执行模式——它自动处理事务的提交和回滚，业务代码只需要在回调中执行操作。这种模式消除了忘记提交或回滚的风险。


变更追踪机制
变更追踪是工作单元的高级能力，它记录实体在业务操作过程中的所有变更，在提交时生成最小化的 SQL 语句。


type ChangeType = 'insert' | 'update' | 'delete';

interface Change {
  type: ChangeType;
  entity: string;
  id: string;
  data: Record<string, unknown>;
  original?: Record<string, unknown>;
}

interface UnitOfWork {
  register(entity: string, id: string, data: Record<string, unknown>): void;
  markNew(entity: string, data: Record<string, unknown>): string;
  markDirty(entity: string, id: string, data: Record<string, unknown>): void;
  markDeleted(entity: string, id: string): void;
  commit(): Promise<void>;
  rollback(): Promise<void>;
  getChanges(): Change[];
}

const createUnitOfWork = (txManager: TransactionManager): UnitOfWork => {
  const identityMap = new Map<string, Record<string, unknown>>();
  const changes: Change[] = [];

  const makeKey = (entity: string, id: string) => `${entity}:${id}`;

  return {
    register(entity, id, data) {
      identityMap.set(makeKey(entity, id), structuredClone(data));
    },

    markNew(entity, data) {
      const id = crypto.randomUUID();
      changes.push({ type: 'insert', entity, id, data: { ...data, id } });
      return id;
    },

    markDirty(entity, id, data) {
      const original = identityMap.get(makeKey(entity, id));
      changes.push({ type: 'update', entity, id, data, original });
    },

    markDeleted(entity, id) {
      changes.push({ type: 'delete', entity, id, data: {} });
    },

    async commit() {
      if (changes.length === 0) return;

      await txManager.execute(async (tx) => {
        for (const change of changes) {
          switch (change.type) {
            case 'insert': {
              const keys = Object.keys(change.data);
              const placeholders = keys.map((_, i) => `$${i + 1}`).join(', ');
              await tx.query(
                `INSERT INTO ${change.entity} (${keys.join(', ')}) VALUES (${placeholders})`,
                Object.values(change.data),
              );
              break;
            }
            case 'update': {
              const entries = Object.entries(change.data);
              const sets = entries.map(([k], i) => `${k} = $${i + 1}`).join(', ');
              await tx.query(`UPDATE ${change.entity} SET ${sets} WHERE id = $${entries.length + 1}`, [
                ...entries.map(([, v]) => v),
                change.id,
              ]);
              break;
            }
            case 'delete':
              await tx.query(`DELETE FROM ${change.entity} WHERE id = $1`, [change.id]);
              break;
          }
        }
      });

      changes.length = 0;
      identityMap.clear();
    },

    async rollback() {
      changes.length = 0;
      identityMap.clear();
    },

    getChanges: () => [...changes],
  };
};
Identity Map 模式确保同一个实体在一次工作单元中只有一份引用。register 方法记录实体的原始状态，markDirty 时可以与原始状态对比，只生成真正变更的字段的 UPDATE 语句。


业务操作编排
工作单元在实际业务中的典型应用是编排涉及多个实体的复杂操作。


interface OrderService {
  createOrder(userId: string, items: OrderItem[]): Promise<Order>;
  cancelOrder(orderId: string): Promise<void>;
}

const createOrderService = (uowFactory: () => UnitOfWork, userRepo: UserRepository): OrderService => ({
  async createOrder(userId, items) {
    const uow = uowFactory();

    const user = await userRepo.findById(userId);
    if (!user) throw new Error('User not found');

    const orderId = uow.markNew('orders', {
      user_id: userId,
      status: 'pending',
      total: items.reduce((sum, item) => sum + item.price * item.quantity, 0),
      created_at: new Date(),
    });

    for (const item of items) {
      uow.markNew('order_items', {
        order_id: orderId,
        product_id: item.productId,
        quantity: item.quantity,
        price: item.price,
      });
    }

    uow.markDirty('users', userId, {
      order_count: ((user as Record<string, unknown>).order_count as number) + 1,
      updated_at: new Date(),
    });

    await uow.commit();

    return { id: orderId, userId, items, status: 'pending' } as Order;
  },

  async cancelOrder(orderId) {
    const uow = uowFactory();

    uow.markDirty('orders', orderId, {
      status: 'cancelled',
      cancelled_at: new Date(),
    });

    await uow.commit();
  },
});
这个例子展示了创建订单时需要同时操作三个表（orders、order_items、users）的场景。工作单元确保这三个操作要么全部成功，要么全部回滚。业务代码只关注领域逻辑，不需要手动管理事务边界。


并发控制与乐观锁
工作单元在并发场景下需要处理脏写问题。乐观锁通过版本号机制检测并发冲突。


interface VersionedEntity extends Entity {
  version: number;
}

const createOptimisticUoW = (txManager: TransactionManager) => {
  const updates: Array<{
    table: string;
    id: string;
    data: Record<string, unknown>;
    expectedVersion: number;
  }> = [];

  return {
    markDirtyWithVersion(table: string, id: string, data: Record<string, unknown>, currentVersion: number) {
      updates.push({
        table,
        id,
        data: { ...data, version: currentVersion + 1 },
        expectedVersion: currentVersion,
      });
    },

    async commit() {
      await txManager.execute(async (tx) => {
        for (const update of updates) {
          const entries = Object.entries(update.data);
          const sets = entries.map(([k], i) => `${k} = $${i + 1}`).join(', ');
          const values = [...entries.map(([, v]) => v), update.id, update.expectedVersion];

          const result = await tx.query(
            `UPDATE ${update.table} SET ${sets} WHERE id = $${entries.length + 1} AND version = $${entries.length + 2}`,
            values,
          );

          if ((result as unknown as { rowCount: number }).rowCount === 0) {
            throw new Error(`Optimistic lock conflict on ${update.table}:${update.id}`);
          }
        }
      });

      updates.length = 0;
    },
  };
};
乐观锁在 UPDATE 的 WHERE 条件中加入 version = expectedVersion，如果受影响行数为 0，说明数据已被其他事务修改，抛出冲突异常。业务层捕获异常后可以选择重试或通知用户。


小结
    

  • 工作单元模式将事务边界管理从业务代码中抽离，确保多实体操作的原子性
    • 

  • execute 模式自动处理提交和回滚，消除事务泄漏风险
    • 

  • 变更追踪通过 Identity Map 记录实体原始状态，提交时生成最小化 SQL
    • 

  • 乐观锁通过版本号检测并发冲突，适用于读多写少场景
    • 

  • 工作单元工厂模式确保每个业务操作使用独立的事务上下文
    • 

  • 业务代码只需标记实体变更，不直接操作数据库事务
