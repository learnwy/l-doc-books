路由与分发

核心概念

路由（Routing）是后端框架的核心机制，负责将入站 HTTP 请求映射到对应的处理函数。路由系统的设计直接影响框架的性能、开发体验和 API 的可维护性。一个优秀的路由系统需要在匹配效率、表达能力和组织灵活性之间取得平衡。

路由匹配的本质是模式匹配问题——给定一个请求的 HTTP 方法和 URL 路径，在预定义的路由表中找到最佳匹配项，并提取路径参数。

Trie 前缀树路由
Trie（前缀树）是现代后端框架最常用的路由匹配数据结构。它将 URL 路径按 / 分割为多个段，每段对应树的一个节点。匹配过程就是从根节点到叶节点的遍历，时间复杂度只与路径段数相关，与路由总数无关。


interface TrieNode {
  children: Map<string, TrieNode>;
  paramChild: TrieNode | null;
  paramName: string | null;
  wildcardChild: TrieNode | null;
  handler: Map<string, Function>;
}

const createNode = (): TrieNode => ({
  children: new Map(),
  paramChild: null,
  paramName: null,
  wildcardChild: null,
  handler: new Map(),
});

const insert = (root: TrieNode, method: string, path: string, handler: Function) => {
  const segments = path.split('/').filter(Boolean);
  let current = root;

  for (const segment of segments) {
    if (segment.startsWith(':')) {
      if (!current.paramChild) {
        current.paramChild = createNode();
        current.paramChild.paramName = segment.slice(1);
      }
      current = current.paramChild;
    } else if (segment === '*') {
      if (!current.wildcardChild) {
        current.wildcardChild = createNode();
      }
      current = current.wildcardChild;
      break;
    } else {
      if (!current.children.has(segment)) {
        current.children.set(segment, createNode());
      }
      current = current.children.get(segment)!;
    }
  }

  current.handler.set(method, handler);
};
Trie 路由的匹配优先级遵循：静态节点 > 参数节点 > 通配符节点。这意味着 /users/admin 会优先匹配静态路由 /users/admin，而非参数路由 /users/:id。这种优先级规则直观且可预测。


参数化路由与路径提取
参数化路由允许 URL 中包含动态段，这些段在匹配时被提取为键值对，供处理函数使用。不同框架支持不同复杂度的参数模式。


import { Hono } from 'hono';

const app = new Hono();

app.get('/users/:id', (c) => {
  const id = c.req.param('id');
  return c.json({ userId: id });
});

app.get('/files/:path{.+}', (c) => {
  const filePath = c.req.param('path');
  return c.json({ path: filePath });
});

app.get('/posts/:year/:month/:slug', (c) => {
  const { year, month, slug } = c.req.param();
  return c.json({ year, month, slug });
});

app.get('/docs/*', (c) => {
  const wildcard = c.req.path.replace('/docs/', '');
  return c.json({ path: wildcard });
});
参数类型在路由层面通常不做校验，但可以通过中间件或验证层将字符串参数转换为强类型。常见做法是在处理函数入口处使用 parseInt() 或 schema 验证将路径参数转换为期望类型。


路由组织策略
随着 API 规模增长，路由组织变得至关重要。良好的路由组织策略能提高代码的可维护性和团队协作效率。


import { Hono } from 'hono';

const createUserRoutes = () => {
  const router = new Hono();

  router.get('/', listUsers);
  router.post('/', createUser);
  router.get('/:id', getUser);
  router.put('/:id', updateUser);
  router.delete('/:id', deleteUser);
  router.get('/:id/posts', getUserPosts);

  return router;
};

const createPostRoutes = () => {
  const router = new Hono();

  router.get('/', listPosts);
  router.post('/', createPost);
  router.get('/:id', getPost);
  router.put('/:id', updatePost);

  return router;
};

const createApiV1 = () => {
  const api = new Hono();

  api.route('/users', createUserRoutes());
  api.route('/posts', createPostRoutes());

  return api;
};

const app = new Hono();
app.route('/api/v1', createApiV1());
app.route('/api/v2', createApiV2());

路由工厂函数模式将每组路由封装在工厂函数中，返回独立的路由实例。这种模式的优势在于：每组路由可以独立测试，依赖可以通过参数注入，路由注册在顶层一目了然。


路由冲突与调试
路由冲突是开发中常见的问题，尤其在参数化路由和静态路由混合使用时。理解匹配优先级和调试方法能快速定位问题。


import { Hono } from 'hono';
import type { MiddlewareHandler } from 'hono';

const routeDebugger: MiddlewareHandler = async (c, next) => {
  const start = performance.now();
  const { method, path } = c.req;

  await next();

  const duration = performance.now() - start;
  console.log(
    JSON.stringify({
      method,
      path,
      status: c.res.status,
      duration: `${duration.toFixed(2)}ms`,
      matched: c.req.routePath,
    }),
  );
};

const app = new Hono();
app.use('*', routeDebugger);

app.get('/users/me', (c) => c.json({ type: 'current-user' }));
app.get('/users/:id', (c) => c.json({ type: 'user-by-id', id: c.req.param('id') }));
app.get('/users/:id/settings', (c) => c.json({ type: 'user-settings' }));
在上面的例子中，/users/me 必须定义在 /users/:id 之前（如果框架按注册顺序匹配），否则 me 会被当作 :id 参数。基于 Trie 的路由系统通过静态优先匹配自动解决这个问题，但理解规则仍然重要。


小结
    

  • Trie 前缀树是现代框架的主流路由算法，匹配效率只与路径深度相关
    • 

  • 匹配优先级：静态节点 > 参数节点 > 通配符节点
    • 

  • 参数化路由通过 :param 语法提取 URL 中的动态部分
    • 

  • 路由工厂函数模式提供最佳的可测试性和可组合性
    • 

  • 路由组织应遵循资源导向原则，配合版本隔离支持 API 演进
    • 

  • 理解路由冲突规则和调试手段是维护大规模 API 的必备技能
