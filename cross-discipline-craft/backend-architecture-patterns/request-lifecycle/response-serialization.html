响应序列化

核心概念

响应序列化是将服务端内部数据结构转换为客户端可理解的传输格式的过程。这个阶段是请求生命周期的最后一环，直接影响 API 的性能、兼容性和开发体验。序列化不仅仅是 JSON.stringify()，它涉及内容协商、字段过滤、格式转换、流式传输等一系列策略。

优秀的序列化层需要处理三个核心问题：输出什么格式（内容协商）、输出哪些字段（数据裁剪）、如何高效输出（传输优化）。

内容协商机制
内容协商（Content Negotiation）是 HTTP 协议中客户端与服务端协商响应格式的机制。服务端根据请求的 Accept 头选择最合适的表示形式返回。


import { Hono } from 'hono';

interface User {
  id: string;
  name: string;
  email: string;
  createdAt: Date;
}

const serializeToCSV = (users: User[]): string => {
  const headers = 'id,name,email,createdAt';
  const rows = users.map((u) => `${u.id},${u.name},${u.email},${u.createdAt.toISOString()}`);
  return [headers, ...rows].join('\n');
};

const app = new Hono();

app.get('/api/users', async (c) => {
  const users = await fetchUsers();
  const accept = c.req.header('accept') ?? 'application/json';

  if (accept.includes('text/csv')) {
    c.header('Content-Type', 'text/csv');
    c.header('Content-Disposition', 'attachment; filename="users.csv"');
    return c.body(serializeToCSV(users));
  }

  if (accept.includes('application/msgpack')) {
    const packed = encodeMsgpack(users);
    c.header('Content-Type', 'application/msgpack');
    return c.body(packed);
  }

  return c.json(users);
});
内容协商的最佳实践是默认返回 JSON，同时支持通过 Accept 头或查询参数（如 ?format=csv）选择其他格式。当客户端请求不支持的格式时，应返回 406 Not Acceptable。


JSON 序列化深度优化
JSON 是 API 响应最常见的格式，但默认的 JSON.stringify() 在面对复杂对象时存在性能和安全问题。深度优化涵盖自定义序列化器、字段过滤和循环引用处理。


interface SerializerOptions {
  fields?: string[];
  exclude?: string[];
  dateFormat?: 'iso' | 'unix' | 'ms';
}

const createSerializer = <T extends Record<string, unknown>>(options: SerializerOptions = {}) => {
  const { fields, exclude, dateFormat = 'iso' } = options;

  return (data: T): Record<string, unknown> => {
    let keys = Object.keys(data);

    if (fields?.length) {
      keys = keys.filter((k) => fields.includes(k));
    }
    if (exclude?.length) {
      keys = keys.filter((k) => !exclude.includes(k));
    }

    const result: Record<string, unknown> = {};
    for (const key of keys) {
      const value = data[key];
      if (value instanceof Date) {
        result[key] =
          dateFormat === 'iso'
            ? value.toISOString()
            : dateFormat === 'unix'
              ? Math.floor(value.getTime() / 1000)
              : value.getTime();
      } else {
        result[key] = value;
      }
    }
    return result;
  };
};

const userSerializer = createSerializer<User>({
  exclude: ['passwordHash', 'internalNotes'],
  dateFormat: 'iso',
});

app.get('/api/users/:id', async (c) => {
  const user = await findUser(c.req.param('id'));
  return c.json(userSerializer(user));
});
敏感字段泄漏是 API 安全的常见漏洞。序列化层应作为最后一道防线，确保内部字段（如密码哈希、内部备注）永远不会出现在响应中。白名单模式（明确列出可输出字段）比黑名单模式更安全。


流式响应与 Server-Sent Events
当响应数据量大或需要实时推送时，流式响应比一次性发送更高效。流式传输避免了在内存中构建完整响应体，降低内存峰值并缩短首字节时间（TTFB）。


import { Hono } from 'hono';
import { streamSSE } from 'hono/streaming';

const app = new Hono();

app.get('/api/export', async (c) => {
  c.header('Content-Type', 'application/x-ndjson');

  return c.stream(async (stream) => {
    const cursor = createDBCursor('SELECT * FROM large_table');
    let batch: Record<string, unknown>[] = [];

    for await (const row of cursor) {
      batch.push(row);
      if (batch.length >= 100) {
        const lines = batch.map((r) => JSON.stringify(r)).join('\n') + '\n';
        await stream.write(lines);
        batch = [];
      }
    }

    if (batch.length > 0) {
      const lines = batch.map((r) => JSON.stringify(r)).join('\n') + '\n';
      await stream.write(lines);
    }
  });
});

app.get('/api/events', (c) => {
  return streamSSE(c, async (stream) => {
    let id = 0;
    while (true) {
      const event = await pollForChanges();
      if (!event) break;
      await stream.writeSSE({
        data: JSON.stringify(event),
        event: 'update',
        id: String(id++),
      });
    }
  });
});
NDJSON（Newline Delimited JSON）是流式 JSON 的标准格式，每行一个 JSON 对象，便于客户端逐行解析。Server-Sent Events（SSE）适用于服务端向客户端的单向实时推送，如通知、进度更新。


响应封装与统一格式
统一的响应格式是 API 一致性的基础。封装层标准化了成功响应和错误响应的结构，使客户端能够用统一的逻辑处理所有 API 调用。


interface ApiResponse<T> {
  success: boolean;
  data?: T;
  error?: { code: string; message: string };
  meta?: { total?: number; page?: number; pageSize?: number };
}

const ok = <T>(c: Context, data: T, meta?: ApiResponse<T>['meta']) => {
  const response: ApiResponse<T> = { success: true, data };
  if (meta) response.meta = meta;
  return c.json(response);
};

const fail = (c: Context, status: number, code: string, message: string) => {
  const response: ApiResponse<never> = {
    success: false,
    error: { code, message },
  };
  return c.json(response, status as 400);
};

app.get('/api/users', async (c) => {
  const page = Number(c.req.query('page') ?? '1');
  const pageSize = Number(c.req.query('pageSize') ?? '20');

  const { users, total } = await paginateUsers(page, pageSize);
  return ok(c, users, { total, page, pageSize });
});

app.get('/api/users/:id', async (c) => {
  const user = await findUser(c.req.param('id'));
  if (!user) {
    return fail(c, 404, 'USER_NOT_FOUND', '用户不存在');
  }
  return ok(c, user);
});

说明
示例





success 标志

data 字段
成功时携带业务数据

error 字段
失败时携带错误信息
{ code, message }




meta 字段
分页等元信息
{ total, page }





统一响应格式让前端可以编写通用的 API 客户端，用一致的方式判断请求是否成功、提取数据或展示错误。success 字段比依赖 HTTP 状态码更明确，因为某些 API 可能在 200 状态码下返回业务级别的错误。


小结
    

  • 内容协商通过 Accept 头实现多格式响应，JSON 作为默认格式
    • 

  • 序列化层是防止敏感数据泄漏的最后防线，白名单模式更安全
    • 

  • 流式响应降低内存峰值，NDJSON 和 SSE 分别适用于批量导出和实时推送
    • 

  • 统一响应封装标准化 API 输出结构，简化客户端处理逻辑
    • 

  • 自定义序列化器通过工厂模式支持字段过滤、日期格式化等需求
    • 

  • 选择序列化格式需权衡大小、速度、可读性和生态支持
