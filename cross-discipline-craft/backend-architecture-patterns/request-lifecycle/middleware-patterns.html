中间件模式

核心概念

中间件（Middleware）是后端框架中最核心的架构模式之一，它允许在请求处理的各个阶段插入横切关注点（Cross-Cutting Concerns）逻辑，如日志记录、认证鉴权、错误处理和响应压缩。中间件模式的本质是函数组合——将多个处理函数按特定顺序串联，形成一条处理链。

不同框架采用不同的中间件执行模型，理解这些模型的差异对于编写正确、高效的中间件至关重要。

洋葱模型与 Koa/Hono 实现
洋葱模型是最优雅的中间件执行模型。请求从外层向内层穿透，到达核心处理器后，响应再从内层向外层返回。每个中间件都能访问请求的"前"和"后"两个阶段，这使得计时、日志等横切逻辑的实现异常简洁。


import { Hono } from 'hono';
import type { MiddlewareHandler } from 'hono';

const timing: MiddlewareHandler = async (c, next) => {
  const start = performance.now();
  await next();
  const duration = performance.now() - start;
  c.header('X-Response-Time', `${duration.toFixed(2)}ms`);
};

const requestLogger: MiddlewareHandler = async (c, next) => {
  const { method, path } = c.req;
  console.log(`--> ${method} ${path}`);
  await next();
  console.log(`<-- ${method} ${path} ${c.res.status}`);
};

const app = new Hono();
app.use('*', timing);
app.use('*', requestLogger);

app.get('/api/health', (c) => c.json({ status: 'ok' }));
洋葱模型的关键在于 await next() 调用。next() 之前的代码在请求阶段执行，next() 之后的代码在响应阶段执行。这种对称结构让中间件能够自然地"包裹"内层逻辑，就像洋葱的层层嵌套。


如果中���件不调用 next()，请求链将被中断，后续中间件和处理器都不会执行。这是实现认证拦截、缓存命中等提前返回逻辑的基础。


Express 管道模型与局限
Express 采用线性管道模型，中间件按注册顺序依次执行。每个中间件通过调用 next() 将控制权传递给下一个，或者直接发送响应终止管道。


import express from 'express';
import type { Request, Response, NextFunction } from 'express';

const app = express();

const authMiddleware = (req: Request, res: Response, next: NextFunction) => {
  const token = req.headers.authorization?.replace('Bearer ', '');
  if (!token) {
    res.status(401).json({ error: 'Unauthorized' });
    return;
  }
  try {
    const payload = verifyToken(token);
    (req as Record<string, unknown>).user = payload;
    next();
  } catch {
    res.status(401).json({ error: 'Invalid token' });
  }
};

const errorHandler = (err: Error, _req: Request, res: Response, _next: NextFunction) => {
  console.error(err.stack);
  res.status(500).json({ error: 'Internal server error' });
};

app.use(authMiddleware);
app.get('/api/profile', (req, res) => {
  res.json((req as Record<string, unknown>).user);
});
app.use(errorHandler);
Express 的管道模型有两个显著局限：一是缺乏天然的后置处理机制，响应阶段的逻辑（如计时、日志）需要通过事件监听或封装实现；二是错误处理中间件必须放在路由之后，且需要四个参数的特殊签名才能被识别为错误处理器。


中间件组合与条件执行
复杂应用需要根据路径、方法或请求特征有条件地执行中间件。框架通常提供路径匹配和中间件组合机制来实现精细控制。


import { Hono } from 'hono';
import { cors } from 'hono/cors';
import { jwt } from 'hono/jwt';
import { compress } from 'hono/compress';
import type { MiddlewareHandler } from 'hono';

const compose = (...middlewares: MiddlewareHandler[]): MiddlewareHandler => {
  return async (c, next) => {
    let index = middlewares.length;
    const dispatch = async (i: number): Promise<void> => {
      if (i >= index) {
        await next();
        return;
      }
      await middlewares[i](c, () => dispatch(i + 1));
    };
    await dispatch(0);
  };
};

const app = new Hono();

app.use('*', compress());
app.use('*', cors({ origin: ['https://example.com'] }));

app.use('/api/*', jwt({ secret: 'my-secret' }));

const adminGuard = compose(jwt({ secret: 'my-secret' }), async (c, next) => {
  const payload = c.get('jwtPayload');
  if (payload.role !== 'admin') {
    return c.json({ error: 'Forbidden' }, 403);
  }
  await next();
});

app.use('/admin/*', adminGuard);
中间件组合函数 compose 将多个中间件合并为一个，简化了路由级别的中间件配置。路径模式匹配（如 /api/*）让全局中间件和路由级中间件可以共存，实现分层的关注点分离。


中间件最佳实践与反模式
编写高质量的中间件需要遵循一系列原则，同时避免常见的反模式。


import type { MiddlewareHandler } from 'hono';

const createRateLimiter = (options: { windowMs: number; max: number }): MiddlewareHandler => {
  const hits = new Map<string, { count: number; resetAt: number }>();

  return async (c, next) => {
    const key = c.req.header('x-forwarded-for') ?? 'unknown';
    const now = Date.now();
    const record = hits.get(key);

    if (!record || now > record.resetAt) {
      hits.set(key, { count: 1, resetAt: now + options.windowMs });
      await next();
      return;
    }

    if (record.count >= options.max) {
      c.header('Retry-After', String(Math.ceil((record.resetAt - now) / 1000)));
      return c.json({ error: 'Too many requests' }, 429);
    }

    record.count++;
    await next();
  };
};

const rateLimiter = createRateLimiter({ windowMs: 60_000, max: 100 });
