认证与授权流程

核心概念

认证（Authentication）回答"你是谁"，授权（Authorization）回答"你能做什么"。这两个阶段是 API 安全的基石，任何后端服务都必须正确实现。认证验证请求者的身份，授权则基于身份判断请求者是否有权执行特定操作。

现代后端服务通常采用无状态的 Token 认证（JWT/OAuth2），配合基于角色（RBAC）或基于属性（ABAC）的授权模型。理解这些模式的完整流程和安全边界，是构建安全 API 的前提。

JWT 生命周期管理
JSON Web Token（JWT）是无状态认证的核心技术。JWT 包含三部分：Header（算法声明）、Payload（用户信息）和 Signature（防篡改签名）。


import { sign, verify } from 'hono/jwt';

interface TokenPayload {
  sub: string;
  role: string;
  permissions: string[];
  iat: number;
  exp: number;
}

interface TokenPair {
  accessToken: string;
  refreshToken: string;
  expiresIn: number;
}

const createTokenService = (secret: string) => {
  const generateTokenPair = async (user: User): Promise<TokenPair> => {
    const now = Math.floor(Date.now() / 1000);

    const accessPayload: TokenPayload = {
      sub: user.id,
      role: user.role,
      permissions: user.permissions,
      iat: now,
      exp: now + 900,
    };

    const refreshPayload = {
      sub: user.id,
      type: 'refresh',
      iat: now,
      exp: now + 604800,
    };

    const [accessToken, refreshToken] = await Promise.all([
      sign(accessPayload, secret),
      sign(refreshPayload, secret + ':refresh'),
    ]);

    return { accessToken, refreshToken, expiresIn: 900 };
  };

  const verifyAccessToken = async (token: string): Promise<TokenPayload> => {
    const payload = await verify(token, secret);
    return payload as TokenPayload;
  };

  const refreshAccessToken = async (refreshToken: string): Promise<TokenPair> => {
    const payload = await verify(refreshToken, secret + ':refresh');
    const user = await findUser(payload.sub as string);
    return generateTokenPair(user);
  };

  return { generateTokenPair, verifyAccessToken, refreshAccessToken };
};
Access Token 设置较短的过期时间（15 分钟），Refresh Token 较长（7 天）。这种双 Token 机制在安全性和用户体验之间取得平衡——即使 Access Token 泄漏，影响窗口也仅有 15 分钟。


OAuth2 授权流程
OAuth2 是第三方授权的行业标准，允许用户授权第三方应用访问其在另一个服务上的数据，而无需提供密码。


import { Hono } from 'hono';

interface OAuth2Config {
  clientId: string;
  clientSecret: string;
  authorizationUrl: string;
  tokenUrl: string;
  redirectUri: string;
  scopes: string[];
}

const createOAuth2Routes = (config: OAuth2Config) => {
  const router = new Hono();

  router.get('/auth/login', (c) => {
    const state = crypto.randomUUID();
    const params = new URLSearchParams({
      client_id: config.clientId,
      redirect_uri: config.redirectUri,
      response_type: 'code',
      scope: config.scopes.join(' '),
      state,
    });

    setCookie(c, 'oauth_state', state, { httpOnly: true, maxAge: 300 });
    return c.redirect(`${config.authorizationUrl}?${params}`);
  });

  router.get('/auth/callback', async (c) => {
    const code = c.req.query('code');
    const state = c.req.query('state');
    const savedState = getCookie(c, 'oauth_state');

    if (!code || !state || state !== savedState) {
      return c.json({ error: 'Invalid OAuth callback' }, 400);
    }

    const tokenResponse = await fetch(config.tokenUrl, {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: new URLSearchParams({
        grant_type: 'authorization_code',
        code,
        redirect_uri: config.redirectUri,
        client_id: config.clientId,
        client_secret: config.clientSecret,
      }),
    });

    const tokens = await tokenResponse.json();
    const userInfo = await fetchUserInfo(tokens.access_token);
    const localTokens = await tokenService.generateTokenPair(userInfo);

    return c.json(localTokens);
  });

  return router;
};
OAuth2 的 state 参数是防御 CSRF 攻击的关键。服务端在发起授权请求前生成随机 state 并存储，回调时验证 state 是否匹配。


RBAC 授权模型
基于角色的访问控制（RBAC）是最常用的授权模型。用户被分配角色，角色拥有一组权限，权限决定了对资源的操作能力。


type Permission = 'users:read' | 'users:write' | 'users:delete' | 'posts:read' | 'posts:write' | 'admin:all';

const ROLE_PERMISSIONS: Record<string, Permission[]> = {
  admin: ['admin:all'],
  editor: ['users:read', 'posts:read', 'posts:write'],
  viewer: ['users:read', 'posts:read'],
};

const hasPermission = (role: string, required: Permission): boolean => {
  const permissions = ROLE_PERMISSIONS[role] ?? [];
  return permissions.includes('admin:all') || permissions.includes(required);
};

const requirePermission = (permission: Permission): MiddlewareHandler => {
  return async (c, next) => {
    const payload = c.get('jwtPayload') as TokenPayload;

    if (!hasPermission(payload.role, permission)) {
      return c.json({ error: { code: 'FORBIDDEN', message: 'Insufficient permissions' } }, 403);
    }

    await next();
  };
};

const requireAnyPermission = (...permissions: Permission[]): MiddlewareHandler => {
  return async (c, next) => {
    const payload = c.get('jwtPayload') as TokenPayload;
    const hasAny = permissions.some((p) => hasPermission(payload.role, p));

    if (!hasAny) {
      return c.json({ error: { code: 'FORBIDDEN', message: 'Insufficient permissions' } }, 403);
    }

    await next();
  };
};

app.get('/api/users', requirePermission('users:read'), listUsersHandler);
app.post('/api/users', requirePermission('users:write'), createUserHandler);
app.delete('/api/users/:id', requirePermission('users:delete'), deleteUserHandler);

RBAC 的权限采用 resource:action 格式，便于理解和管理。admin:all 是超级权限，绕过所有权限检查。中间件模式让权限检查声明式地应用到路由上。


小结
    

  • 认证验证身份（401），授权检查权限（403），两者职责明确分离
    • 

  • 双 Token 机制（短期 Access + 长期 Refresh）平衡安全性和用户体验
    • 

  • OAuth2 的 state 参数是防御 CSRF 攻击的关键安全机制
    • 

  • RBAC 通过角色-权限映射实现访问控制，权限格式为 resource:action
    • 

  • 权限中间件实现声明式的路由级权限控制
    • 

  • Token 有效期应尽可能短，Refresh Token 需安全存储
