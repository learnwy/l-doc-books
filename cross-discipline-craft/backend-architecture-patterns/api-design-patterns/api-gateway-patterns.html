API 网关模式

核心概念

API 网关（API Gateway）是微服务架构中的核心基础设施组件，它作为所有客户端请求的统一入口点，承担路由转发、认证鉴权、限流熔断、协议转换、响应聚合等横切职责。没有网关，每个微服务都需要独立处理这些关注点，导致大量重复代码和不一致的安全策略。

网关模式的本质是在客户端和后端服务之间插入一个反向代理层，将分散在各服务中的横切逻辑集中到一个地方管理。不同的网关模式适用于不同的架构需求。

路由转发与服务发现
网关的基础功能是根据请求路径将流量路由到对应的后端服务。路由配置可以是静态的也可以结合服务发现动态更新。


import { Hono } from 'hono';

interface ServiceConfig {
  name: string;
  prefix: string;
  target: string;
  healthCheck?: string;
  timeout?: number;
}

const services: ServiceConfig[] = [
  { name: 'user-service', prefix: '/api/users', target: 'http://localhost:3001', healthCheck: '/health' },
  { name: 'order-service', prefix: '/api/orders', target: 'http://localhost:3002', healthCheck: '/health' },
  { name: 'product-service', prefix: '/api/products', target: 'http://localhost:3003', healthCheck: '/health' },
];

const createProxyHandler = (service: ServiceConfig) => {
  return async (c: Context) => {
    const path = c.req.path.replace(service.prefix, '');
    const targetUrl = `${service.target}${path}`;
    const timeout = service.timeout ?? 10_000;

    const controller = new AbortController();
    const timer = setTimeout(() => controller.abort(), timeout);

    try {
      const headers = new Headers(c.req.raw.headers);
      headers.set('X-Forwarded-For', c.req.header('x-forwarded-for') ?? '');
      headers.set('X-Forwarded-Host', c.req.header('host') ?? '');
      headers.set('X-Request-Id', c.req.header('x-request-id') ?? crypto.randomUUID());

      const response = await fetch(targetUrl, {
        method: c.req.method,
        headers,
        body: c.req.method !== 'GET' ? c.req.raw.body : undefined,
        signal: controller.signal,
      });

      const responseHeaders = new Headers(response.headers);
      responseHeaders.set('X-Upstream-Service', service.name);

      return new Response(response.body, {
        status: response.status,
        headers: responseHeaders,
      });
    } catch (error) {
      if ((error as Error).name === 'AbortError') {
        return c.json({ error: 'Gateway timeout' }, 504);
      }
      return c.json({ error: 'Bad gateway' }, 502);
    } finally {
      clearTimeout(timer);
    }
  };
};

const gateway = new Hono();

for (const service of services) {
  gateway.all(`${service.prefix}/*`, createProxyHandler(service));
}
网关在转发请求时添加 X-Forwarded-* 头传递客户端信息，后端服务可以据此获取真实客户端 IP。X-Request-Id 贯穿整个调用链，便于分布式追踪。


BFF 模式（Backend for Frontend）
BFF（Backend for Frontend）模式为每种客户端类型创建专属的网关层。Web 端需要丰富的数据，Mobile 端需要精简的数据，它们的 API 需求差异显著，共用一个网关无法满足。


const createWebBFF = () => {
  const app = new Hono();

  app.get('/api/dashboard', async (c) => {
    const userId = c.get('userId');

    const [userResult, ordersResult, statsResult] = await Promise.allSettled([
      fetch(`http://user-service/api/users/${userId}`).then((r) => r.json()),
      fetch(`http://order-service/api/users/${userId}/orders?limit=5`).then((r) => r.json()),
      fetch(`http://stats-service/api/users/${userId}/stats`).then((r) => r.json()),
    ]);

    return c.json({
      user: userResult.status === 'fulfilled' ? userResult.value : null,
      recentOrders: ordersResult.status === 'fulfilled' ? ordersResult.value : [],
      stats: statsResult.status === 'fulfilled' ? statsResult.value : null,
    });
  });

  return app;
};

const createMobileBFF = () => {
  const app = new Hono();

  app.get('/api/dashboard', async (c) => {
    const userId = c.get('userId');

    const user = await fetch(`http://user-service/api/users/${userId}`).then((r) => r.json());

    return c.json({
      name: user.name,
      avatar: user.avatar,
      unreadCount: user.notifications?.unread ?? 0,
    });
  });

  return app;
};
Web BFF 聚合三个服务的数据构建完整的 Dashboard 视图，Mobile BFF 只返回移动端需要的精简数据。Promise.allSettled 确保部分服务故障不影响整体响应——降级为 null 而非报错。


网关横切功能集成
生产级网关需要集成认证、限流、日志、熔断等横切功能，这些功能通过中间件链实现。


import { Hono } from 'hono';
import { cors } from 'hono/cors';
import { jwt } from 'hono/jwt';

const createGateway = (config: GatewayConfig) => {
  const gateway = new Hono();

  gateway.use('*', cors({ origin: config.allowedOrigins }));

  gateway.use('*', async (c, next) => {
    const requestId = c.req.header('x-request-id') ?? crypto.randomUUID();
    c.header('X-Request-Id', requestId);
    c.set('requestId', requestId);

    const start = performance.now();
    await next();
    const duration = performance.now() - start;

    console.log(
      JSON.stringify({
        requestId,
        method: c.req.method,
        path: c.req.path,
        status: c.res.status,
        duration: `${duration.toFixed(2)}ms`,
        upstream: c.res.headers.get('x-upstream-service'),
      }),
    );
  });

  const publicPaths = ['/api/auth/login', '/api/auth/register', '/health'];
  gateway.use('*', async (c, next) => {
    if (publicPaths.some((p) => c.req.path.startsWith(p))) {
      return next();
    }
    return jwt({ secret: config.jwtSecret })(c, next);
  });

  gateway.use(
    '/api/*',
    createRateLimitMiddleware({
      windowMs: 60_000,
      max: 100,
    }),
  );

  for (const service of config.services) {
    gateway.all(`${service.prefix}/*`, createProxyHandler(service));
  }

  gateway.get('/health', (c) => c.json({ status: 'ok', timestamp: Date.now() }));

  return gateway;
};

中间件链的顺序至关重要：CORS 必须最先处理（preflight 请求不携带 Token），认证在限流之前（未认证请求不应消耗限流配额），路由转发在所有检查通过后执行。


网关健康聚合与监控
网关不仅需要自身健康，还需要聚合所有后端服务的健康状态，提供系统全局的健康视图。


interface ServiceHealth {
  name: string;
  status: 'healthy' | 'degraded' | 'unhealthy';
  responseTime?: number;
  lastChecked: number;
}

const createHealthAggregator = (services: ServiceConfig[]) => {
  const healthCache = new Map<string, ServiceHealth>();

  const checkService = async (service: ServiceConfig): Promise<ServiceHealth> => {
    const start = performance.now();
    try {
      const response = await fetch(`${service.target}${service.healthCheck ?? '/health'}`, {
        signal: AbortSignal.timeout(3000),
      });
      return {
        name: service.name,
        status: response.ok ? 'healthy' : 'degraded',
        responseTime: performance.now() - start,
        lastChecked: Date.now(),
      };
    } catch {
      return {
        name: service.name,
        status: 'unhealthy',
        responseTime: performance.now() - start,
        lastChecked: Date.now(),
      };
    }
  };

  const checkAll = async () => {
    const results = await Promise.all(services.map(checkService));
    for (const result of results) {
      healthCache.set(result.name, result);
    }
    return results;
  };

  setInterval(() => checkAll(), 30_000);

  return {
    checkAll,
    getHealth: () => [...healthCache.values()],
    getOverallStatus: () => {
      const services = [...healthCache.values()];
      if (services.every((s) => s.status === 'healthy')) return 'healthy';
      if (services.some((s) => s.status === 'unhealthy')) return 'degraded';
      return 'healthy';
    },
  };
};
健康聚合器定期探测每个后端服务的健康端点，汇总为系统级别的健康状态。Kubernetes 等编排平台可以基于网关的健康端点决定是否将流量路由到该实例。


小结
    

  • API 网关作为统一入口集中管理认证、限流、路由等横切关注点
    • 

  • BFF 模式为不同客户端创建专属网关，优化各端的数据获取效率
    • 

  • Promise.allSettled 在聚合多服务数据时提供部分故障容忍
    • 

  • 中间件链顺序：CORS → 追踪 → 认证 → 限流 → 路由转发
    • 

  • 健康聚合器定期探测后端服务，提供系统级健康视图
    • 

  • X-Request-Id 贯穿网关和后端服务，支持分布式追踪
