分页与过滤

核心概念

分页（Pagination）和过滤（Filtering）是数据密集型 API 的基础能力。当数据集包含数万甚至数百万条记录时，一次性返回所有数据既不现实也不安全——它会导致响应时间过长、内存溢出和网络带宽浪费。分页将大数据集切分为可管理的小块，过滤则让客户端只获取真正需要的数据子集。

分页策略的选择直接影响 API 的性能特征和用户体验。偏移分页简单直观但在大数据集上性能退化严重，游标分页性能稳定但实现复杂，keyset 分页则在两者之间取得平衡。

偏移分页实现
偏移分页（Offset Pagination）是最传统的分页方式，通过 OFFSET 和 LIMIT 控制返回的数据范围。它的优势是支持随机跳页，劣势是 OFFSET 值越大性能越差。


import { Hono } from 'hono';

interface PaginationParams {
  page: number;
  pageSize: number;
}

interface PaginatedResponse<T> {
  data: T[];
  pagination: {
    page: number;
    pageSize: number;
    total: number;
    totalPages: number;
    hasNext: boolean;
    hasPrev: boolean;
  };
}

const parsePagination = (c: { req: { query: (k: string) => string | undefined } }): PaginationParams => {
  const page = Math.max(1, Number(c.req.query('page') ?? '1'));
  const pageSize = Math.min(100, Math.max(1, Number(c.req.query('pageSize') ?? '20')));
  return { page, pageSize };
};

const app = new Hono();

app.get('/api/users', async (c) => {
  const { page, pageSize } = parsePagination(c);
  const offset = (page - 1) * pageSize;

  const [users, total] = await Promise.all([
    pool.query('SELECT * FROM users ORDER BY created_at DESC LIMIT $1 OFFSET $2', [pageSize, offset]),
    pool.query('SELECT COUNT(*) FROM users'),
  ]);

  const totalPages = Math.ceil(total / pageSize);
  const response: PaginatedResponse<User> = {
    data: users,
    pagination: {
      page,
      pageSize,
      total,
      totalPages,
      hasNext: page < totalPages,
      hasPrev: page > 1,
    },
  };

  return c.json(response);
});
偏移分页的性能问题源于数据库必须扫描并跳过 OFFSET 条记录才能返回结果。当 OFFSET = 100000 时，数据库实际上扫描了 100020 条记录但只返回 20 条。对于超过万级的数据集，应考虑切换到游标分页。


游标分页实现
游标分页（Cursor Pagination）使用上一页最后一条记录的唯一标识作为游标，查询该标识之后的记录。这避免了 OFFSET 的性能问题，因为数据库可以直接从索引位置开始扫描。


interface CursorPaginationParams {
  cursor?: string;
  limit: number;
  direction: 'forward' | 'backward';
}

interface CursorPaginatedResponse<T> {
  data: T[];
  pageInfo: {
    hasNextPage: boolean;
    hasPreviousPage: boolean;
    startCursor: string | null;
    endCursor: string | null;
  };
}

const encodeCursor = (id: string, createdAt: Date): string =>
  Buffer.from(JSON.stringify({ id, t: createdAt.getTime() })).toString('base64url');

const decodeCursor = (cursor: string): { id: string; t: number } =>
  JSON.parse(Buffer.from(cursor, 'base64url').toString());

app.get('/api/posts', async (c) => {
  const limit = Math.min(50, Number(c.req.query('limit') ?? '20'));
  const after = c.req.query('after');
  const before = c.req.query('before');

  let sql = 'SELECT * FROM posts';
  const params: unknown[] = [];
  let paramIdx = 1;

  if (after) {
    const cursor = decodeCursor(after);
    sql += ` WHERE (created_at, id) < ($${paramIdx++}, $${paramIdx++})`;
    params.push(new Date(cursor.t), cursor.id);
  } else if (before) {
    const cursor = decodeCursor(before);
    sql += ` WHERE (created_at, id) > ($${paramIdx++}, $${paramIdx++})`;
    params.push(new Date(cursor.t), cursor.id);
  }

  sql += ` ORDER BY created_at DESC, id DESC LIMIT $${paramIdx}`;
  params.push(limit + 1);

  const { rows } = await pool.query(sql, params);
  const hasMore = rows.length > limit;
  const data = hasMore ? rows.slice(0, limit) : rows;

  const response: CursorPaginatedResponse<Post> = {
    data,
    pageInfo: {
      hasNextPage: hasMore,
      hasPreviousPage: !!after,
      startCursor: data.length > 0 ? encodeCursor(data[0].id, data[0].created_at) : null,
      endCursor: data.length > 0 ? encodeCursor(data[data.length - 1].id, data[data.length - 1].created_at) : null,
    },
  };

  return c.json(response);
});
游标编码为 Base64url 字符串，包含排序字段的值（时间戳和 ID），客户端无需理解其内部结构。LIMIT N+1 技巧是判断是否有下一页的常用方法——多查一条，如果能查到说明还有更多数据。


复合过滤语法
复杂的数据查询需要灵活的过滤语法。常见的方案包括简单键值对、LHS 括号语法和 JSON 过滤表达式。


interface FilterOptions {
  field: string;
  operator: 'eq' | 'neq' | 'gt' | 'gte' | 'lt' | 'lte' | 'like' | 'in';
  value: string | number | string[];
}

const parseFilters = (query: Record<string, string>): FilterOptions[] => {
  const filters: FilterOptions[] = [];

  for (const [key, value] of Object.entries(query)) {
    const match = key.match(/^filter\[(\w+)\]\[(\w+)\]$/);
    if (!match) continue;

    const [, field, operator] = match;
    if (['eq', 'neq', 'gt', 'gte', 'lt', 'lte', 'like', 'in'].includes(operator)) {
      filters.push({
        field,
        operator: operator as FilterOptions['operator'],
        value: operator === 'in' ? value.split(',') : value,
      });
    }
  }

  return filters;
};

const buildFilterSQL = (filters: FilterOptions[]): { where: string; params: unknown[] } => {
  const conditions: string[] = [];
  const params: unknown[] = [];
  let idx = 1;

  const operatorMap: Record<string, string> = {
    eq: '=',
    neq: '!=',
    gt: '>',
    gte: '>=',
    lt: '<',
    lte: '<=',
    like: 'ILIKE',
  };

  for (const filter of filters) {
    if (filter.operator === 'in' && Array.isArray(filter.value)) {
      conditions.push(`${filter.field} = ANY($${idx++})`);
      params.push(filter.value);
    } else {
      const op = operatorMap[filter.operator];
      const val = filter.operator === 'like' ? `%${filter.value}%` : filter.value;
      conditions.push(`${filter.field} ${op} $${idx++}`);
      params.push(val);
    }
  }

  return {
    where: conditions.length ? `WHERE ${conditions.join(' AND ')}` : '',
    params,
  };
};

排序与字段选择
排序和字段选择让客户端进一步控制返回数据的形态，减少不必要的数据传输。


interface QueryOptions {
  sort?: Array<{ field: string; order: 'asc' | 'desc' }>;
  fields?: string[];
}

const parseSortParam = (sort?: string): QueryOptions['sort'] => {
  if (!sort) return undefined;
  return sort.split(',').map((s) => {
    const desc = s.startsWith('-');
    return { field: desc ? s.slice(1) : s, order: desc ? ('desc' as const) : ('asc' as const) };
  });
};

const parseFieldsParam = (fields?: string): string[] | undefined => {
  if (!fields) return undefined;
  const allowed = new Set(['id', 'name', 'email', 'role', 'createdAt']);
  return fields.split(',').filter((f) => allowed.has(f));
};

app.get('/api/users', async (c) => {
  const { page, pageSize } = parsePagination(c);
  const sort = parseSortParam(c.req.query('sort'));
  const fields = parseFieldsParam(c.req.query('fields'));
  const filters = parseFilters(Object.fromEntries(new URL(c.req.url).searchParams));

  const columns = fields?.length ? fields.join(', ') : '*';
  const orderBy = sort?.map((s) => `${s.field} ${s.order.toUpperCase()}`).join(', ') ?? 'created_at DESC';
  const { where, params } = buildFilterSQL(filters);

  const offset = (page - 1) * pageSize;
  const sql = `SELECT ${columns} FROM users ${where} ORDER BY ${orderBy} LIMIT $${params.length + 1} OFFSET $${params.length + 2}`;

  const { rows } = await pool.query(sql, [...params, pageSize, offset]);
  return c.json({ data: rows });
});
排序参数使用 -field 表示降序，field 表示升序，多字段用逗号分隔（如 ?sort=-createdAt,name）。字段选择必须有白名单校验，防止客户端请求敏感字段或不存在的字段。


小结
    

  • 偏移分页适合管理后台等需要跳页的场景，大数据集下性能退化
    • 

  • 游标分页性能稳定、数据一致，适合无限滚动和 Feed 流
    • 

  • LIMIT N+1 技巧高效判断是否有下一页
    • 

  • LHS 括号语法提供灵活的过滤操作符支持
    • 

  • 排序参数用 - 前缀表示降序，多字段逗号分隔
    • 

  • 字段选择必须有白名单校验，防止敏感字段泄漏
