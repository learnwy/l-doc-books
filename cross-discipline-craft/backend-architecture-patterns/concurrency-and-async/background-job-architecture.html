后台任务架构

核心概念

后台任务是指不在 HTTP 请求-响应周期内同步完成的工作。当业务操作耗时较长（如发送邮件、生成报告、处理图片）或不需要立即返回结果时，将其从请求路径中剥离到后台执行，是提升 API 响应速度和系统可靠性的关键架构决策。

后台任务架构的核心组件包括：任务生产者（Producer）、任务队列（Queue）、任务消费者（Worker）和结果存储（Result Store）。生产者将任务放入队列，消费者从队列中取出并执行，执行结果存入结果存储供后续查询。

内存任务队列实现
对于中小规模应用，内存队列是最简单的后台任务方案。它避免了引入消息中间件的运维复杂度，适合单实例部署。


interface Task<T = unknown> {
  id: string;
  type: string;
  payload: T;
  createdAt: number;
  attempts: number;
  maxRetries: number;
  status: 'pending' | 'processing' | 'completed' | 'failed';
  scheduledAt?: number;
  error?: string;
}

interface TaskHandler<T = unknown> {
  (payload: T): Promise<void>;
}

const createTaskQueue = () => {
  const queue: Task[] = [];
  const handlers = new Map<string, TaskHandler>();
  const results = new Map<string, Task>();
  let processing = false;

  const register = <T>(type: string, handler: TaskHandler<T>) => {
    handlers.set(type, handler as TaskHandler);
  };

  const enqueue = <T>(type: string, payload: T, options?: { delay?: number; maxRetries?: number }): string => {
    const task: Task<T> = {
      id: crypto.randomUUID(),
      type,
      payload,
      createdAt: Date.now(),
      attempts: 0,
      maxRetries: options?.maxRetries ?? 3,
      status: 'pending',
      scheduledAt: options?.delay ? Date.now() + options.delay : undefined,
    };
    queue.push(task as Task);
    scheduleProcessing();
    return task.id;
  };

  const processNext = async () => {
    if (processing || queue.length === 0) return;
    processing = true;

    const now = Date.now();
    const idx = queue.findIndex((t) => t.status === 'pending' && (!t.scheduledAt || t.scheduledAt <= now));

    if (idx === -1) {
      processing = false;
      return;
    }

    const task = queue.splice(idx, 1)[0];
    task.status = 'processing';
    task.attempts++;

    const handler = handlers.get(task.type);
    if (!handler) {
      task.status = 'failed';
      task.error = `No handler for type: ${task.type}`;
      results.set(task.id, task);
      processing = false;
      scheduleProcessing();
      return;
    }

    try {
      await handler(task.payload);
      task.status = 'completed';
    } catch (error) {
      if (task.attempts < task.maxRetries) {
        task.status = 'pending';
        task.scheduledAt = Date.now() + 1000 * Math.pow(2, task.attempts);
        queue.push(task);
      } else {
        task.status = 'failed';
        task.error = (error as Error).message;
      }
    }

    results.set(task.id, task);
    processing = false;
    scheduleProcessing();
  };

  const scheduleProcessing = () => {
    setImmediate(() => processNext());
  };

  return { register, enqueue, getStatus: (id: string) => results.get(id) };
};
内存队列的局限是进程重启时丢失所有未完成的任务。对于关键业务任务，应使用持久化队列（如 Redis 或数据库）。


基于 Redis 的持久化队列
Redis 提供了 List、Sorted Set 等数据结构，天然适合实现持久化任务队列。延迟任务可以利用 Sorted Set 的分数排序特性。


import type { Redis } from 'ioredis';

interface RedisQueue {
  enqueue(task: Task): Promise<void>;
  dequeue(): Promise<Task | null>;
  scheduleDelayed(): Promise<number>;
  getStatus(id: string): Promise<Task | null>;
}

const createRedisQueue = (redis: Redis, prefix = 'taskq'): RedisQueue => {
  const keys = {
    pending: `${prefix}:pending`,
    delayed: `${prefix}:delayed`,
    processing: `${prefix}:processing`,
    task: (id: string) => `${prefix}:task:${id}`,
  };

  return {
    async enqueue(task) {
      const serialized = JSON.stringify(task);
      await redis.set(keys.task(task.id), serialized, 'EX', 86400);

      if (task.scheduledAt && task.scheduledAt > Date.now()) {
        await redis.zadd(keys.delayed, task.scheduledAt, task.id);
      } else {
        await redis.lpush(keys.pending, task.id);
      }
    },

    async dequeue() {
      const taskId = await redis.brpoplpush(keys.pending, keys.processing, 5);
      if (!taskId) return null;

      const data = await redis.get(keys.task(taskId));
      return data ? JSON.parse(data) : null;
    },

    async scheduleDelayed() {
      const now = Date.now();
      const ready = await redis.zrangebyscore(keys.delayed, 0, now);

      if (ready.length === 0) return 0;

      const pipeline = redis.pipeline();
      for (const taskId of ready) {
        pipeline.lpush(keys.pending, taskId);
        pipeline.zrem(keys.delayed, taskId);
      }
      await pipeline.exec();

      return ready.length;
    },

    async getStatus(id) {
      const data = await redis.get(keys.task(id));
      return data ? JSON.parse(data) : null;
    },
  };
};
BRPOPLPUSH 是 Redis 队列的核心操作：原子地从 pending 列表取出任务并放入 processing 列表。如果 Worker 崩溃，processing 列表中的任务可以被恢复，保证了至少一次投递语义。


Cron 定时调度
定时任务是后台架构的重要组成部分。Node.js 中可以使用轻量级的 Cron 表达式解析器实现定时调度。


interface ScheduledJob {
  name: string;
  cronExpression: string;
  handler: () => Promise<void>;
  running: boolean;
  lastRun?: Date;
  nextRun?: Date;
}

const createScheduler = () => {
  const jobs: ScheduledJob[] = [];
  let timer: ReturnType<typeof setInterval> | null = null;

  const parseCron = (expr: string): { matches: (date: Date) => boolean } => {
    const [minute, hour, dayOfMonth, month, dayOfWeek] = expr.split(' ');

    const matchField = (field: string, value: number): boolean => {
      if (field === '*') return true;
      if (field.includes('/')) {
        const step = Number(field.split('/')[1]);
        return value % step === 0;
      }
      return field.split(',').map(Number).includes(value);
    };

    return {
      matches: (date) =>
        matchField(minute, date.getMinutes()) &&
        matchField(hour, date.getHours()) &&
        matchField(dayOfMonth, date.getDate()) &&
        matchField(month, date.getMonth() + 1) &&
        matchField(dayOfWeek, date.getDay()),
    };
  };

  const register = (name: string, cronExpression: string, handler: () => Promise<void>) => {
    jobs.push({ name, cronExpression, handler, running: false });
  };

  const start = () => {
    timer = setInterval(async () => {
      const now = new Date();
      for (const job of jobs) {
        if (job.running) continue;
        const cron = parseCron(job.cronExpression);
        if (cron.matches(now)) {
          job.running = true;
          job.lastRun = now;
          try {
            await job.handler();
          } catch (error) {
            console.error(`Job ${job.name} failed:`, error);
          } finally {
            job.running = false;
          }
        }
      }
    }, 60_000);
  };

  const stop = () => {
    if (timer) clearInterval(timer);
  };

  return { register, start, stop, getJobs: () => [...jobs] };
};
定时调度器每分钟检查一次所有注册的 Job，与当前时间匹配 Cron 表达式。running 标志防止同一个 Job 重叠执行。在分布式部署中，需要使用分布式锁（如 Redis SETNX）确保同一时刻只有一个实例执行定时任务。


任务监控与死信队列
生产环境中，任务执行的可观测性至关重要。死信队列（Dead Letter Queue）收集反复失败的任务，供人工排查。


interface TaskMetrics {
  processed: number;
  succeeded: number;
  failed: number;
  retried: number;
  avgDurationMs: number;
}

const createTaskMonitor = () => {
  const metrics: Record<string, TaskMetrics> = {};
  const deadLetters: Task[] = [];

  const track = (taskType: string, duration: number, success: boolean) => {
    if (!metrics[taskType]) {
      metrics[taskType] = { processed: 0, succeeded: 0, failed: 0, retried: 0, avgDurationMs: 0 };
    }
    const m = metrics[taskType];
    m.processed++;
    if (success) m.succeeded++;
    else m.failed++;
    m.avgDurationMs = (m.avgDurationMs * (m.processed - 1) + duration) / m.processed;
  };

  const addDeadLetter = (task: Task) => {
    deadLetters.push(task);
    if (deadLetters.length > 1000) deadLetters.shift();
  };

  return {
    track,
    addDeadLetter,
    getMetrics: () => ({ ...metrics }),
    getDeadLetters: () => [...deadLetters],
    retryDeadLetter: (id: string) => {
      const idx = deadLetters.findIndex((t) => t.id === id);
      if (idx >= 0) return deadLetters.splice(idx, 1)[0];
      return null;
    },
  };
};

小结
    

  • 后台任务将耗时操作从请求路径中剥离，提升 API 响应速度
    • 

  • 内存队列适合单实例非关键任务，Redis 队列提供持久化和分布式支持
    • 

  • BRPOPLPUSH 实现原子取任务，保证 Worker 崩溃时任务不丢失
    • 

  • Cron 调度器通过分钟级检查实现定时任务，分布式部署需加分布式锁
    • 

  • 死信队列收集反复失败的任务，支持人工排查和手动重试
    • 

  • 完善的监控指标（队列深度、失败率、处理延迟）是生产运维的基础
