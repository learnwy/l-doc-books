异步处理模型

核心概念

异步处理模型是后端服务处理并发请求的基础架构决策。不同的异步模型决定了服务如何利用系统资源、处理 I/O 等待和管理并发任务。选择合适的异步模型直接影响服务的吞吐量、延迟和资源效率。

Node.js 采用单线程事件循环模型，通过非阻塞 I/O 在一个线程上高效处理大量并发连接。Go 使用 Goroutine（协程），Java 传统上依赖线程池，Erlang/Elixir 使用 Actor 模型。每种模型都有其适用场景和局限性。

事件循环深度解析
Node.js 的事件循环是理解其异步模型的关键。事件循环由多个阶段组成，每个阶段处理特定类型的回调。


import { EventEmitter } from 'node:events';

const demonstrateEventLoop = () => {
  console.log('1. 同步代码');

  setTimeout(() => console.log('2. setTimeout (timers 阶段)'), 0);

  setImmediate(() => console.log('3. setImmediate (check 阶段)'));

  Promise.resolve().then(() => console.log('4. Promise (微任务)'));

  process.nextTick(() => console.log('5. nextTick (微任务优先)'));

  console.log('6. 同步代码结束');
};

const createAsyncQueue = () => {
  const queue: Array<() => Promise<void>> = [];
  let processing = false;

  const process = async () => {
    if (processing) return;
    processing = true;

    while (queue.length > 0) {
      const task = queue.shift()!;
      try {
        await task();
      } catch (error) {
        console.error('Task failed:', error);
      }
    }

    processing = false;
  };

  return {
    enqueue: (task: () => Promise<void>) => {
      queue.push(task);
      queueMicrotask(() => process());
    },
    size: () => queue.length,
  };
};
执行顺序为：5 → 4 → 1 → 6 → 2 → 3。process.nextTick 优先于 Promise.then，两者都在进入下一个事件循环阶段前执行。理解这个执行顺序对于编写正确的异步代码至关重要。


Worker Threads 与 CPU 密集任务
事件循环模型的最大弱点是 CPU 密集型任务会阻塞整个循环。Node.js 通过 Worker Threads 将 CPU 密集任务卸载到独立线程。


import { Worker, isMainThread, parentPort, workerData } from 'node:worker_threads';
import { cpus } from 'node:os';

interface WorkerTask<T, R> {
  data: T;
  resolve: (result: R) => void;
  reject: (error: Error) => void;
}

const createWorkerPool = <T, R>(workerScript: string, poolSize?: number) => {
  const size = poolSize ?? Math.max(cpus().length - 1, 1);
  const workers: Worker[] = [];
  const taskQueue: WorkerTask<T, R>[] = [];
  const idle: Worker[] = [];

  for (let i = 0; i < size; i++) {
    const worker = new Worker(workerScript);
    workers.push(worker);
    idle.push(worker);
  }

  const dispatch = () => {
    while (idle.length > 0 && taskQueue.length > 0) {
      const worker = idle.pop()!;
      const task = taskQueue.shift()!;

      const onMessage = (result: R) => {
        worker.removeListener('error', onError);
        task.resolve(result);
        idle.push(worker);
        dispatch();
      };

      const onError = (error: Error) => {
        worker.removeListener('message', onMessage);
        task.reject(error);
        idle.push(worker);
        dispatch();
      };

      worker.once('message', onMessage);
      worker.once('error', onError);
      worker.postMessage(task.data);
    }
  };

  return {
    execute: (data: T): Promise<R> =>
      new Promise((resolve, reject) => {
        taskQueue.push({ data, resolve, reject });
        dispatch();
      }),
    terminate: () => Promise.all(workers.map((w) => w.terminate())),
    stats: () => ({
      total: size,
      idle: idle.length,
      queued: taskQueue.length,
    }),
  };
};
Worker Pool 模式预创建一组 Worker 线程，复用而非每次都创建新线程。任务通过 postMessage 发送给空闲 Worker，Worker 完成后通过 message 事件返回结果。这种模式适用于图片处理、加密解密、大量 JSON 解析等 CPU 密集场景。


Promise 并发控制
在批量处理场景中，同时发起过多的异步操作可能耗尽系统资源（文件描述符、网络连接、内存）。并发控制限制同时执行的异步操作数量。


const createConcurrencyLimiter = (maxConcurrency: number) => {
  let active = 0;
  const queue: Array<() => void> = [];

  const acquire = (): Promise<void> => {
    if (active < maxConcurrency) {
      active++;
      return Promise.resolve();
    }
    return new Promise((resolve) => queue.push(resolve));
  };

  const release = () => {
    active--;
    if (queue.length > 0) {
      active++;
      const next = queue.shift()!;
      next();
    }
  };

  return {
    run: async <T>(fn: () => Promise<T>): Promise<T> => {
      await acquire();
      try {
        return await fn();
      } finally {
        release();
      }
    },
    stats: () => ({ active, queued: queue.length }),
  };
};

const processUrls = async (urls: string[], concurrency = 5) => {
  const limiter = createConcurrencyLimiter(concurrency);
  const results = await Promise.allSettled(urls.map((url) => limiter.run(() => fetch(url).then((r) => r.json()))));
  return results;
};
Promise.allSettled 配合并发限制器是批量处理的最佳模式——它不会因为一个请求失败而中断所有请求，同时控制并发数防止资源耗尽。


异步错误处理策略
异步代码的错误处理比同步代码更复杂，未捕获的 Promise 拒绝可能导致进程崩溃。


process.on('unhandledRejection', (reason, promise) => {
  console.error('Unhandled rejection at:', promise, 'reason:', reason);
});

const withRetry = async <T>(
  fn: () => Promise<T>,
  options: { maxRetries: number; delayMs: number; backoff: number },
): Promise<T> => {
  let lastError: Error | undefined;
  let delay = options.delayMs;

  for (let attempt = 0; attempt <= options.maxRetries; attempt++) {
    try {
      return await fn();
    } catch (error) {
      lastError = error as Error;
      if (attempt < options.maxRetries) {
        await new Promise((resolve) => setTimeout(resolve, delay));
        delay *= options.backoff;
      }
    }
  }

  throw lastError;
};

const withTimeout = <T>(promise: Promise<T>, ms: number): Promise<T> => {
  const timeout = new Promise<never>((_, reject) =>
    setTimeout(() => reject(new Error(`Operation timed out after ${ms}ms`)), ms),
  );
  return Promise.race([promise, timeout]);
};

const fetchWithResilience = async (url: string) => {
  return withRetry(
    () =>
      withTimeout(
        fetch(url).then((r) => r.json()),
        5000,
      ),
    { maxRetries: 3, delayMs: 1000, backoff: 2 },
  );
};
重试（Retry）和超时（Timeout）是异步弹性模式的两个基本构件。指数退避（Exponential Backoff）避免在服务恢复时造成流量尖峰。Promise.race 实现超时机制，在原始操作和定时器之间竞争。


小结
    

  • Node.js 事件循环通过非阻塞 I/O 在单线程上实现高并发
    • 

  • 微任务（nextTick、Promise）在每个事件循环阶段之间执行
    • 

  • Worker Threads 将 CPU 密集任务卸载到独立线程，避免阻塞事件循环
    • 

  • 并发限制器通过信号量模式控制同时执行的异步操作数量
    • 

  • 重试和超时是异步弹性的基础构件，指数退避防止恢复期的流量尖峰
    • 

  • Promise.allSettled 是批量异步操作的最佳选择，容忍部分失败
