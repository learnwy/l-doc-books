any、unknown、never 与 void

核心概念

TypeScript 类型系统中有四个特殊类型，它们在类型层级中扮演着关键角色：any 是类型检查的逃逸舱口，unknown 是类型安全的顶层类型，never 是不可能存在的底层类型，void 表示函数没有返回值。理解它们的语义差异和适用场景，是写出类型安全代码的关键。

基本语法
any：逃逸舱口
any 类型完全绕过类型检查，可以赋值给任何类型，也可以接收任何类型的值：


let value: any = 42;
value = 'hello'; // ✅
value = true; // ✅
value = { x: 1 }; // ✅

value.foo(); // ✅ 不检查属性是否存在
value.bar.baz; // ✅ 不检查链式访问
value(); // ✅ 不检查是否可调用

const num: number = value; // ✅ any 可赋值给任何类型
any 是"传染性"的——一旦某个值为 any，所有对它的操作结果也是 any：


const obj: any = { name: 'Alice' };
const name = obj.name; // name 的类型是 any，不是 string
const upper = name.toUpperCase(); // upper 也是 any
unknown：类型安全的顶层类型
unknown 可以接收任何类型的值，但不能直接对它进行任何操作，必须先通过类型收窄：


let value: unknown = 42;
value = 'hello'; // ✅
value = true; // ✅

value.toString(); // ❌ 'unknown' 类型上不存在属性 'toString'
value + 1; // ❌ 运算符 '+' 不能应用于 'unknown'

if (typeof value === 'string') {
  console.log(value.toUpperCase()); // ✅ 收窄后可以安全使用
}
never：空类型
never 表示不可能存在的值。没有任何值可以赋给 never 类型（除了 never 本身）：


function throwError(message: string): never {
  throw new Error(message);
}

function infiniteLoop(): never {
  while (true) {}
}

const x: never = throwError('oops'); // ✅ throwError 返回 never
void：无返回值
void 表示函数不返回有意义的值。与 undefined 不同，void 是专门用于函数返回类型的语义标记：


function log(message: string): void {
  console.log(message);
}

function noop(): void {}

const result: void = log('hello');
// result 的类型是 void，实际值是 undefined
类型推断行为
any 的隐式产生
在非严格模式下，未注解的参数和未初始化的变量会被推断为 any：


// noImplicitAny: false 时
function double(n) {
  // n 隐式推断为 any
  return n * 2;
}

let items = [];
// items 隐式推断为 any[]
开启 noImplicitAny: true（包含在 strict: true 中）后，以上代码会报错。


void 与回调返回值
当函数类型声明返回 void 时，实现可以返回任何值，但调用者不能使用返回值：


type Callback = () => void;

const fn: Callback = () => {
  return 42; // ✅ 不报错，返回值被忽略
};

const result = fn();
// result 类型为 void，不能当 number 使用
这个设计是为了兼容 Array.prototype.forEach 等 API，它们的回调返回 void，但实际回调可能返回值。


never 的推断
当 TypeScript 判断某个代码路径不可达时，会推断为 never：


function process(value: string | number) {
  if (typeof value === 'string') {
    return value.toUpperCase();
  } else if (typeof value === 'number') {
    return value.toFixed(2);
  } else {
    // value 在这里是 never，因为所有可能性都已穷尽
    const exhaustive: never = value;
    return exhaustive;
  }
}

never 的穷尽性检查
never 最强大的应用之一是确保 switch 语句覆盖了所有可能的分支：


type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'rectangle'; width: number; height: number }
  | { kind: 'triangle'; base: number; height: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2;
    case 'rectangle':
      return shape.width * shape.height;
    case 'triangle':
      return (shape.base * shape.height) / 2;
    default: {
      const _exhaustive: never = shape;
      return _exhaustive;
    }
  }
}
如果后续向 Shape 联合类型添加了新的成员但忘记在 switch 中处理，default 分支中的 never 赋值就会报错，提醒开发者补全逻辑。


常见误区
误区一：用 any 代替 unknown
当接收外部数据时，应该使用 unknown 而非 any：


// ❌ 不安全：any 关闭了所有类型检查
function parseJSON(text: string): any {
  return JSON.parse(text);
}
const data = parseJSON('{"name": "Alice"}');
console.log(data.age.toString()); // 运行时崩溃，编译期无警告

// ✅ 安全：unknown 强制调用者进行类型检查
function parseJSON(text: string): unknown {
  return JSON.parse(text);
}
const data = parseJSON('{"name": "Alice"}');
if (typeof data === 'object' && data !== null && 'name' in data) {
  console.log(data.name);
}
误区二：混淆 void 和 undefined
void 和 undefined 不完全等价：


// void 作为返回类型时，函数可以没有 return 语句
function logA(): void {
  console.log('a');
}

// undefined 作为返回类型时，必须显式 return undefined
function logB(): undefined {
  console.log('b');
  return undefined; // 必须写
}
误区三：忽略 never 在联合类型中的消失
never 在联合类型中会被自动消除：


type A = string | never; // 等价于 string
type B = number | never; // 等价于 number
type C = never | never; // 等价于 never
这个特性在条件类型中非常有用，可以用来"过滤"联合类型中的某些成员。


与 JavaScript 的关系
JavaScript 没有 any、unknown、never 这些概念——它们纯粹是 TypeScript 的编译期类型。void 在 JavaScript 中是一个运算符（void 0 返回 undefined），而在 TypeScript 中是一个类型。编译后所有这些类型注解都会被擦除。


// TypeScript
function safeParse(text: string): unknown {
  return JSON.parse(text);
}

// 编译后的 JavaScript
function safeParse(text) {
  return JSON.parse(text);
}
小结
    

  • any 完全关闭类型检查，应仅在渐进迁移等特殊场景中使用。
    • 

  • unknown 是类型安全的顶层类型，接收外部数据时应优先使用。
    • 

  • never 是底层类型，用于表示不可达代码和穷尽性检查。
    • 

  • void 专用于函数返回类型，表示函数不返回有意义的值。
    • 

  • 开启 strict 模式，避免隐式 any，是保证类型安全的第一步。
