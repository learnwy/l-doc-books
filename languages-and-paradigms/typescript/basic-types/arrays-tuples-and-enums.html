数组、元组与枚举

核心概念

TypeScript 提供了三种重要的集合/枚举结构来组织数据：数组用于存储同类型的变长序列，元组用于存储固定长度和固定类型顺序的序列，枚举用于定义一组命名常量。理解它们各自的适用场景和类型行为，是高效使用 TypeScript 的基础。

基本语法
数组类型
数组有两种等价的类型表示方式：


const nums: number[] = [1, 2, 3];
const strs: Array<string> = ['a', 'b', 'c'];
两种写法功能完全一致，T[] 语法更简洁，社区中更常用；Array<T> 在泛型组合时可读性更好：


type Matrix = Array<Array<number>>; // 比 number[][] 更清晰
type Pair = [string, number];
只读数组
readonly 修饰符可以创建不可变的数组，禁止 push、pop、索引赋值等修改操作：


const items: readonly number[] = [1, 2, 3];
// 或等价写法
const items2: ReadonlyArray<number> = [1, 2, 3];

items.push(4); // ❌ 'readonly number[]' 上不存在 'push'
items[0] = 10; // ❌ 索引签名仅允许读取


readonly T[] 是 T[] 的父类型——可以把 T[] 赋值给 readonly T[]，反之不行。




数组推断
TypeScript 根据初始值推断数组类型：


const nums = [1, 2, 3]; // number[]
const mixed = [1, 'hello']; // (string | number)[]
const empty: string[] = []; // 空数组必须注解
元组（Tuple）
元组是固定长度、每个位置有确定类型的数组。与普通数组不同，元组可以在每个索引位上拥有不同类型：


type Point = [number, number];
type NameAge = [string, number];

const origin: Point = [0, 0];
const person: NameAge = ['Alice', 30];

const x: number = origin[0]; // ✅
const name: string = person[0]; // ✅
带标签的元组
TypeScript 4.0+ 支持为元组的每个位置添加标签，提升可读性：


type Range = [start: number, end: number];
type Entry = [key: string, value: unknown];

function setRange(...range: [start: number, end: number]): void {
  const [start, end] = range;
  console.log(`${start} - ${end}`);
}
可选元素与剩余元素
元组支持可选元素和剩余元素：


type OptionalTuple = [string, number?];
const a: OptionalTuple = ['hello']; // ✅
const b: OptionalTuple = ['hello', 42]; // ✅

type StringAndNums = [string, ...number[]];
const c: StringAndNums = ['hello', 1, 2, 3]; // ✅
只读元组
与数组类似，元组也支持 readonly：


type ReadonlyPoint = readonly [number, number];

const p: ReadonlyPoint = [1, 2];
p[0] = 3; // ❌ 无法分配到 '0'，因为它是只读属性
as const 断言会自动生成只读元组：


const point = [1, 2] as const;
// 类型为 readonly [1, 2]
枚举（Enum）
枚举用于定义一组命名常量。TypeScript 支持三种枚举类型：


数字枚举
默认情况下，枚举成员从 0 开始自增：


enum Direction {
  Up, // 0
  Down, // 1
  Left, // 2
  Right, // 3
}

const dir: Direction = Direction.Up;
console.log(dir); // 0
数字枚举支持反向映射——可以通过值找到名称：


console.log(Direction[0]); // "Up"
字符串枚举
每个成员必须用字符串字面量初始化：


enum Color {
  Red = 'RED',
  Green = 'GREEN',
  Blue = 'BLUE',
}

const c: Color = Color.Red;
console.log(c); // "RED"
字符串枚举不支持反向映射，但运行时值更可读，调试更方便。


const 枚举
const enum 在编译时被完全内联，不生成运行时对象：


const enum HttpStatus {
  OK = 200,
  NotFound = 404,
  ServerError = 500,
}

const status = HttpStatus.OK;
// 编译后直接变成：const status = 200;


const enum 更高效，但不能用于需要遍历枚举值的场景。




编译产物对比
// 普通枚举编译后生成对象
enum Fruit {
  Apple,
  Banana,
}
// 编译为：
// var Fruit;
// (function (Fruit) {
//     Fruit[Fruit["Apple"] = 0] = "Apple";
//     Fruit[Fruit["Banana"] = 1] = "Banana";
// })(Fruit || (Fruit = {}));

// const 枚举编译后完全内联
const enum Drink {
  Water,
  Juice,
}
const d = Drink.Water;
// 编译为：const d = 0;

推荐的做法：


// ✅ 优先使用字面量联合
type Theme = 'light' | 'dark' | 'system';

// ✅ 需要运行时值集合时，用 as const + typeof
const THEMES = ['light', 'dark', 'system'] as const;
type Theme = (typeof THEMES)[number];
// Theme = "light" | "dark" | "system"
// THEMES 数组在运行时可遍历
常见误区
误区一：元组越界访问
元组有固定长度，但 TypeScript 允许通过 push 等方法越界（除非 readonly）：


const pair: [string, number] = ['hello', 42];
pair.push(true); // ❌ 类型 'boolean' 的参数不能赋给 '[string, number]' 的 push 参数
pair.push('x'); // ✅ 但逻辑上已越界，建议使用 readonly
误区二：数字枚举的隐式值陷阱
在数字枚举中间插入成员会导致后续值偏移：


enum Status {
  Active = 1,
  Pending, // 2
  Disabled, // 3
}

// 如果后来在 Active 后插入 Verified，Pending 和 Disabled 的值会变化
// 建议：为所有成员显式赋值
误区三：混淆数组与元组
// 这是数组，不是元组
const arr: (string | number)[] = ['hello', 42, 'world', 100];

// 这才是元组
const tuple: [string, number] = ['hello', 42];
与 JavaScript 的关系
JavaScript 原生没有元组和枚举的概念。数组在 JS 中本质是对象，长度可变、元素类型不限。TypeScript 的元组在编译后就是普通数组；普通枚举编译后生成 IIFE 对象；const enum 和联合类型在编译后完全消失。


// TypeScript 元组
const point: [number, number] = [1, 2];
// 编译后
const point = [1, 2];

// TypeScript 枚举
enum Role {
  Admin,
  User,
}
// 编译后生成运行时对象（可被 JS 代码使用）
小结
    

  • 数组使用 T[] 或 Array<T> 表示，readonly 可创建不可变数组。
    • 

  • 元组是固定长度、位置类型确定的数组，支持标签、可选元素和剩余元素。
    • 

  • 枚举分为数字枚举、字符串枚举和 const enum，各有适用场景。
    • 

  • 多数场景下，字面量联合类型 + as const 数组是比枚举更轻量的替代方案。
    • 

  • 空数组必须显式注解类型，否则会被推断为 any[]。
