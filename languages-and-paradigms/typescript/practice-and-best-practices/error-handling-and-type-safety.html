错误处理与类型安全

场景描述

JavaScript 的错误处理机制（try/catch）天生缺乏类型信息——catch 子句的参数是 any（或启用严格模式后的 unknown），开发者无法在编译时知道可能抛出什么错误。TypeScript 通过类型化错误处理模式弥补这一不足，让错误像数据一样可追踪、可组合、可穷举。



模式与方案
Result / Either 模式
Result 模式将成功值和错误值统一编码为返回类型，避免使用异常控制流。调用方必须显式处理两种情况，编译器在每个分支中自动收窄类型。


type Result<T, E = Error> = { readonly ok: true; readonly value: T } | { readonly ok: false; readonly error: E };

function ok<T>(value: T): Result<T, never> {
  return { ok: true, value };
}

function err<E>(error: E): Result<never, E> {
  return { ok: false, error };
}
使用示例：


interface User {
  id: string;
  name: string;
  email: string;
}

type ParseError =
  | { type: 'INVALID_JSON'; raw: string }
  | { type: 'MISSING_FIELD'; field: string }
  | { type: 'INVALID_EMAIL'; email: string };

function parseUser(input: string): Result<User, ParseError> {
  let data: unknown;
  try {
    data = JSON.parse(input);
  } catch {
    return err({ type: 'INVALID_JSON', raw: input });
  }

  if (typeof data !== 'object' || data === null) {
    return err({ type: 'INVALID_JSON', raw: input });
  }

  const obj = data as Record<string, unknown>;

  if (typeof obj['name'] !== 'string') {
    return err({ type: 'MISSING_FIELD', field: 'name' });
  }

  if (typeof obj['email'] !== 'string') {
    return err({ type: 'MISSING_FIELD', field: 'email' });
  }

  if (!obj['email'].includes('@')) {
    return err({ type: 'INVALID_EMAIL', email: obj['email'] as string });
  }

  return ok({
    id: typeof obj['id'] === 'string' ? obj['id'] : crypto.randomUUID(),
    name: obj['name'] as string,
    email: obj['email'] as string,
  });
}
调用方的穷举处理：


const result = parseUser('{"name": "Alice"}');

if (result.ok) {
  console.log(`用户: ${result.value.name}`);
} else {
  switch (result.error.type) {
    case 'INVALID_JSON':
      console.error(`JSON 解析失败: ${result.error.raw}`);
      break;
    case 'MISSING_FIELD':
      console.error(`缺少字段: ${result.error.field}`);
      break;
    case 'INVALID_EMAIL':
      console.error(`邮箱格式错误: ${result.error.email}`);
      break;
  }
}
Result 工具函数
function map<T, U, E>(result: Result<T, E>, fn: (value: T) => U): Result<U, E> {
  if (result.ok) {
    return ok(fn(result.value));
  }
  return result;
}

function flatMap<T, U, E>(result: Result<T, E>, fn: (value: T) => Result<U, E>): Result<U, E> {
  if (result.ok) {
    return fn(result.value);
  }
  return result;
}

function unwrapOr<T, E>(result: Result<T, E>, defaultValue: T): T {
  if (result.ok) {
    return result.value;
  }
  return defaultValue;
}

const parsed = parseUser('{"name": "Bob", "email": "bob@example.com"}');
const greeting = map(parsed, (user) => `你好, ${user.name}`);
const message = unwrapOr(greeting, '你好, 访客');
自定义错误类层次
当需要使用 throw 异常机制时，自定义错误类能提供更好的类型信息和错误分类：


class AppError extends Error {
  constructor(
    message: string,
    readonly code: string,
    readonly statusCode: number,
  ) {
    super(message);
    this.name = 'AppError';
  }
}

class ValidationError extends AppError {
  constructor(
    message: string,
    readonly field: string,
    readonly constraint: string,
  ) {
    super(message, 'VALIDATION_ERROR', 400);
    this.name = 'ValidationError';
  }
}

class NotFoundError extends AppError {
  constructor(
    readonly resource: string,
    readonly resourceId: string,
  ) {
    super(`${resource} "${resourceId}" 不存在`, 'NOT_FOUND', 404);
    this.name = 'NotFoundError';
  }
}

class AuthenticationError extends AppError {
  constructor(message: string = '认证失败') {
    super(message, 'AUTH_ERROR', 401);
    this.name = 'AuthenticationError';
  }
}

class AuthorizationError extends AppError {
  constructor(
    readonly requiredPermission: string,
    message: string = '权限不足',
  ) {
    super(message, 'FORBIDDEN', 403);
    this.name = 'AuthorizationError';
  }
}
穷举错误匹配
结合自定义错误类和类型守卫，实现穷举匹配：


function isAppError(error: unknown): error is AppError {
  return error instanceof AppError;
}

function handleError(error: unknown): { status: number; message: string } {
  if (error instanceof ValidationError) {
    return {
      status: 400,
      message: `验证失败: ${error.field} - ${error.constraint}`,
    };
  }

  if (error instanceof NotFoundError) {
    return {
      status: 404,
      message: `${error.resource} "${error.resourceId}" 未找到`,
    };
  }

  if (error instanceof AuthenticationError) {
    return { status: 401, message: error.message };
  }

  if (error instanceof AuthorizationError) {
    return {
      status: 403,
      message: `需要权限: ${error.requiredPermission}`,
    };
  }

  if (isAppError(error)) {
    return { status: error.statusCode, message: error.message };
  }

  return { status: 500, message: '内部服务器错误' };
}
类型安全的 try/catch
启用 useUnknownInCatchVariables 后，catch 变量类型为 unknown。封装一个安全的错误处理工具：


function trySafe<T>(fn: () => T): Result<T, Error> {
  try {
    return ok(fn());
  } catch (error) {
    if (error instanceof Error) {
      return err(error);
    }
    return err(new Error(String(error)));
  }
}

async function trySafeAsync<T>(fn: () => Promise<T>): Promise<Result<T, Error>> {
  try {
    const value = await fn();
    return ok(value);
  } catch (error) {
    if (error instanceof Error) {
      return err(error);
    }
    return err(new Error(String(error)));
  }
}

const jsonResult = trySafe(() => JSON.parse('{"key": "value"}'));

if (jsonResult.ok) {
  console.log(jsonResult.value);
}

const fetchResult = await trySafeAsync(() => fetch('https://api.example.com/data').then((r) => r.json()));
错误边界模式
在大型应用中，使用错误边界隔离不同模块的错误，防止一个模块的失败影响整个系统：


type BoundaryResult<T> = {
  readonly module: string;
  readonly result: Result<T, Error>;
  readonly duration: number;
};

async function withErrorBoundary<T>(module: string, fn: () => Promise<T>): Promise<BoundaryResult<T>> {
  const start = Date.now();
  try {
    const value = await fn();
    return {
      module,
      result: ok(value),
      duration: Date.now() - start,
    };
  } catch (error) {
    return {
      module,
      result: err(error instanceof Error ? error : new Error(String(error))),
      duration: Date.now() - start,
    };
  }
}

const results = await Promise.all([
  withErrorBoundary('用户模块', () => fetchUsers()),
  withErrorBoundary('订单模块', () => fetchOrders()),
  withErrorBoundary('通知模块', () => fetchNotifications()),
]);

for (const { module, result, duration } of results) {
  if (result.ok) {
    console.log(`${module}: 成功 (${duration}ms)`);
  } else {
    console.error(`${module}: 失败 - ${result.error.message} (${duration}ms)`);
  }
}

async function fetchUsers(): Promise<string[]> {
  return ['Alice', 'Bob'];
}
async function fetchOrders(): Promise<number[]> {
  return [1, 2, 3];
}
async function fetchNotifications(): Promise<string[]> {
  return ['新消息'];
}

小结
    

  • Result 类型（{ok: true, value} | {ok: false, error}）将错误编码为返回值，让编译器强制调用方处理两种情况。
    • 

  • map 和 flatMap 工具函数让 Result 类型支持链式组合，避免嵌套 if/else。
    • 

  • 自定义错误类层次（AppError → ValidationError / NotFoundError）为异常机制提供类型化的分类和元数据。
    • 

  • 启用 useUnknownInCatchVariables 后，catch 变量为 unknown，必须通过 instanceof 或类型守卫缩窄后使用。
    • 

  • trySafe / trySafeAsync 封装将 try/catch 异常转换为 Result 类型，在两种模式之间架起桥梁。
    • 

  • 错误边界模式隔离不同模块的错误，防止局部故障扩散到整个系统。
    • 

  • 可预期的业务错误适合使用 Result 类型，不可预期的系统错误适合使用异常机制。
