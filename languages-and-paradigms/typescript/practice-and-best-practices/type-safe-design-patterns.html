类型安全的设计模式

场景描述

设计模式不仅是面向对象编程的专利——TypeScript 强大的类型系统让我们能够在编译时而非运行时捕获模式使用中的错误。通过可辨识联合、泛型约束和类型推断，经典设计模式在 TypeScript 中获得了类型级别的保障。



模式与方案
可辨识联合（Discriminated Unions）用于状态管理
可辨识联合是 TypeScript 中最常用的模式之一，它通过一个字面量类型的判别属性区分不同的状态分支，让编译器能够在每个分支中自动收窄类型。


interface IdleState {
  readonly type: 'idle';
}

interface LoadingState {
  readonly type: 'loading';
  readonly startedAt: number;
}

interface SuccessState<T> {
  readonly type: 'success';
  readonly data: T;
  readonly completedAt: number;
}

interface ErrorState {
  readonly type: 'error';
  readonly error: Error;
  readonly retryCount: number;
}

type RequestState<T> = IdleState | LoadingState | SuccessState<T> | ErrorState;

function renderState<T>(state: RequestState<T>): string {
  switch (state.type) {
    case 'idle':
      return '等待操作';
    case 'loading':
      return `加载中，开始于 ${state.startedAt}`;
    case 'success':
      return `加载完成: ${JSON.stringify(state.data)}`;
    case 'error':
      return `错误: ${state.error.message}（已重试 ${state.retryCount} 次）`;
  }
}
穷举性检查确保所有状态都被处理：


function assertNever(value: never): never {
  throw new Error(`未处理的状态: ${JSON.stringify(value)}`);
}

function handleState<T>(state: RequestState<T>): void {
  switch (state.type) {
    case 'idle':
      break;
    case 'loading':
      break;
    case 'success':
      break;
    case 'error':
      break;
    default:
      assertNever(state);
  }
}
Builder 模式与类型累积
传统 Builder 模式在运行时构建对象，TypeScript 可以通过泛型实现编译时的字段追踪——确保必填字段在调用 build() 前全部设置。


interface UserConfig {
  name: string;
  email: string;
  age: number;
  role: string;
}

type BuilderState = {
  [K in keyof UserConfig]?: true;
};

class UserConfigBuilder<State extends BuilderState = {}> {
  private config: Partial<UserConfig> = {};

  setName(name: string): UserConfigBuilder<State & { name: true }> {
    this.config.name = name;
    return this as unknown as UserConfigBuilder<State & { name: true }>;
  }

  setEmail(email: string): UserConfigBuilder<State & { email: true }> {
    this.config.email = email;
    return this as unknown as UserConfigBuilder<State & { email: true }>;
  }

  setAge(age: number): UserConfigBuilder<State & { age: true }> {
    this.config.age = age;
    return this as unknown as UserConfigBuilder<State & { age: true }>;
  }

  setRole(role: string): UserConfigBuilder<State & { role: true }> {
    this.config.role = role;
    return this as unknown as UserConfigBuilder<State & { role: true }>;
  }

  build(
    this: UserConfigBuilder<{
      name: true;
      email: true;
      age: true;
      role: true;
    }>,
  ): UserConfig {
    return this.config as UserConfig;
  }
}

const user = new UserConfigBuilder().setName('Alice').setEmail('alice@example.com').setAge(30).setRole('admin').build();
类型安全的依赖注入
通过 TypeScript 的类型系统实现一个简单的依赖注入容器，确保注册和解析的类型完全匹配：


class TypedContainer {
  private services = new Map<string, unknown>();

  register<T>(key: string, factory: () => T): void {
    this.services.set(key, factory);
  }

  resolve<T>(key: string): T {
    const factory = this.services.get(key);
    if (!factory) {
      throw new Error(`服务 "${key}" 未注册`);
    }
    return (factory as () => T)();
  }
}

interface ServiceMap {
  logger: Logger;
  database: Database;
  cache: CacheService;
}

class DIContainer {
  private factories = new Map<string, () => unknown>();

  register<K extends keyof ServiceMap>(key: K, factory: () => ServiceMap[K]): void {
    this.factories.set(key, factory);
  }

  resolve<K extends keyof ServiceMap>(key: K): ServiceMap[K] {
    const factory = this.factories.get(key);
    if (!factory) {
      throw new Error(`服务 "${key}" 未注册`);
    }
    return factory() as ServiceMap[K];
  }
}

interface Logger {
  info(message: string): void;
}

interface Database {
  query(sql: string): Promise<unknown[]>;
}

interface CacheService {
  get(key: string): unknown | undefined;
  set(key: string, value: unknown): void;
}

const container = new DIContainer();

container.register('logger', () => ({
  info: (message: string) => console.log(message),
}));

const logger = container.resolve('logger');
logger.info('依赖注入成功');
泛型 Repository 模式
Repository 模式封装数据访问逻辑。结合泛型，可以为不同实体创建类型安全的仓储：


interface Entity {
  readonly id: string;
  readonly createdAt: Date;
  readonly updatedAt: Date;
}

interface Repository<T extends Entity> {
  findById(id: string): Promise<T | null>;
  findAll(filter?: Partial<T>): Promise<T[]>;
  create(data: Omit<T, 'id' | 'createdAt' | 'updatedAt'>): Promise<T>;
  update(id: string, data: Partial<Omit<T, 'id' | 'createdAt' | 'updatedAt'>>): Promise<T>;
  delete(id: string): Promise<boolean>;
}

interface User extends Entity {
  name: string;
  email: string;
  role: 'admin' | 'user' | 'guest';
}

interface Post extends Entity {
  title: string;
  content: string;
  authorId: string;
  published: boolean;
}

class InMemoryRepository<T extends Entity> implements Repository<T> {
  private items = new Map<string, T>();

  async findById(id: string): Promise<T | null> {
    return this.items.get(id) ?? null;
  }

  async findAll(filter?: Partial<T>): Promise<T[]> {
    const all = Array.from(this.items.values());
    if (!filter) return all;
    return all.filter((item) => Object.entries(filter).every(([key, value]) => item[key as keyof T] === value));
  }

  async create(data: Omit<T, 'id' | 'createdAt' | 'updatedAt'>): Promise<T> {
    const now = new Date();
    const entity = {
      ...data,
      id: crypto.randomUUID(),
      createdAt: now,
      updatedAt: now,
    } as T;
    this.items.set(entity.id, entity);
    return entity;
  }

  async update(id: string, data: Partial<Omit<T, 'id' | 'createdAt' | 'updatedAt'>>): Promise<T> {
    const existing = this.items.get(id);
    if (!existing) throw new Error(`实体 ${id} 不存在`);
    const updated = { ...existing, ...data, updatedAt: new Date() } as T;
    this.items.set(id, updated);
    return updated;
  }

  async delete(id: string): Promise<boolean> {
    return this.items.delete(id);
  }
}

const userRepo: Repository<User> = new InMemoryRepository<User>();
const postRepo: Repository<Post> = new InMemoryRepository<Post>();
Strategy 模式与类型化处理器
Strategy 模式将算法族封装为可互换的策略对象。通过泛型映射，确保策略的输入输出类型完全匹配：


interface ValidationRule<T> {
  readonly name: string;
  validate(value: T): ValidationResult;
}

interface ValidationResult {
  readonly valid: boolean;
  readonly message?: string;
}

const required: ValidationRule<string> = {
  name: 'required',
  validate(value: string): ValidationResult {
    return value.trim().length > 0 ? { valid: true } : { valid: false, message: '字段不能为空' };
  },
};

const minLength = (min: number): ValidationRule<string> => ({
  name: `minLength(${min})`,
  validate(value: string): ValidationResult {
    return value.length >= min ? { valid: true } : { valid: false, message: `最少需要 ${min} 个字符` };
  },
});

const range = (min: number, max: number): ValidationRule<number> => ({
  name: `range(${min}, ${max})`,
  validate(value: number): ValidationResult {
    return value >= min && value <= max ? { valid: true } : { valid: false, message: `值必须在 ${min} 到 ${max} 之间` };
  },
});

class Validator<T> {
  private rules: ValidationRule<T>[] = [];

  addRule(rule: ValidationRule<T>): this {
    this.rules.push(rule);
    return this;
  }

  validate(value: T): ValidationResult[] {
    return this.rules
      .map((rule) => ({ ...rule.validate(value), ruleName: rule.name }))
      .filter((result) => !result.valid);
  }
}

const nameValidator = new Validator<string>().addRule(required).addRule(minLength(2));

const ageValidator = new Validator<number>().addRule(range(0, 150));

const nameErrors = nameValidator.validate('');
const ageErrors = ageValidator.validate(200);


类型安全技巧
利用 const 断言锁定字面量类型
const EVENTS = {
  USER_LOGIN: 'user:login',
  USER_LOGOUT: 'user:logout',
  DATA_SYNC: 'data:sync',
} as const;

type EventName = (typeof EVENTS)[keyof typeof EVENTS];

function emit(event: EventName, payload: unknown): void {
  console.log(`事件 ${event} 已触发`);
}

emit(EVENTS.USER_LOGIN, { userId: '123' });
利用 satisfies 兼顾推断与约束
interface Route {
  path: string;
  method: 'GET' | 'POST' | 'PUT' | 'DELETE';
  handler: string;
}

const routes = {
  home: { path: '/', method: 'GET', handler: 'HomeController.index' },
  login: { path: '/login', method: 'POST', handler: 'AuthController.login' },
} satisfies Record<string, Route>;

const homePath = routes.home.path;

小结
    

  • 可辨识联合是 TypeScript 中最强大的模式之一，通过判别属性实现编译时的类型收窄和穷举检查。
    • 

  • Builder 模式结合泛型类型累积，可以在编译时保证所有必填字段都已设置，避免运行时缺字段错误。
    • 

  • 依赖注入容器通过 ServiceMap 接口映射服务键与类型，实现类型安全的注册和解析。
    • 

  • 泛型 Repository 封装数据访问逻辑，T extends Entity 约束确保所有实体共享基础字段。
    • 

  • Strategy 模式通过泛型参数 ValidationRule<T> 确保策略的输入类型与验证器匹配。
    • 

  • as const 和 satisfies 是两个重要的类型安全工具：前者锁定字面量类型，后者兼顾类型约束与推断。
    • 

  • 设计模式的核心价值在于将运行时错误提前到编译时，这正是 TypeScript 类型系统的优势所在。
