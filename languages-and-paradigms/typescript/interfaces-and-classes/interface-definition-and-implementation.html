接口定义与实现

问题背景

在大型 TypeScript 项目中，不同模块之间需要约定数据的形状和行为契约。如果只靠口头约定或注释，随着代码规模增长，类型不一致的 Bug 会越来越多。接口（interface）正是 TypeScript 提供的核心契约机制——它描述对象必须具备哪些属性和方法，但不关心具体实现。

基本语法
接口声明
接口使用 interface 关键字声明，定义对象的属性和方法签名：


interface User {
  id: number;
  name: string;
  email: string;
  greet(): string;
}

const user: User = {
  id: 1,
  name: '张三',
  email: 'zhangsan@example.com',
  greet() {
    return `你好，我是 ${this.name}`;
  },
};
可选属性与只读属性
interface Config {
  readonly host: string;
  readonly port: number;
  protocol?: string;
  timeout?: number;
}

const config: Config = {
  host: 'localhost',
  port: 3000,
};

// config.host = "remote"; // 错误：无法分配到 "host" ，因为它是只读属性
索引签名
当对象的键名不确定时，可以使用索引签名：


interface StringMap {
  [key: string]: string;
}

const headers: StringMap = {
  'Content-Type': 'application/json',
  Authorization: 'Bearer token123',
};

interface NumberList {
  [index: number]: string;
}

const colors: NumberList = ['red', 'green', 'blue'];
索引签名可以与固定属性共存，但固定属性的类型必须兼容索引签名的值类型：


interface MixedMap {
  [key: string]: string | number;
  length: number;
  name: string;
}
进阶用法
接口继承
接口可以通过 extends 继承一个或多个接口，实现契约的组合与复用：


interface Timestamped {
  createdAt: Date;
  updatedAt: Date;
}

interface SoftDeletable {
  deletedAt?: Date;
  isDeleted: boolean;
}

interface Entity extends Timestamped, SoftDeletable {
  id: string;
}

interface UserEntity extends Entity {
  name: string;
  email: string;
}

const user: UserEntity = {
  id: 'u-001',
  name: '李四',
  email: 'lisi@example.com',
  createdAt: new Date(),
  updatedAt: new Date(),
  isDeleted: false,
};
声明合并
同名接口会自动合并，这在扩展第三方库类型时非常有用：


interface Window {
  appVersion: string;
}

interface Window {
  analytics: {
    track(event: string): void;
  };
}

declare const window: Window;
window.appVersion;
window.analytics.track('page_view');
函数接口与可调用签名
interface SearchFunc {
  (source: string, keyword: string): boolean;
}

const search: SearchFunc = (source, keyword) => {
  return source.includes(keyword);
};

interface EventHandler {
  (event: string, data: unknown): void;
  version: string;
}

const handler: EventHandler = Object.assign(
  (event: string, _data: unknown) => {
    console.log(`处理事件: ${event}`);
  },
  { version: '1.0.0' },
);

泛型接口
interface Repository<T> {
  findById(id: string): Promise<T | null>;
  findAll(): Promise<T[]>;
  save(entity: T): Promise<T>;
  delete(id: string): Promise<boolean>;
}

interface User {
  id: string;
  name: string;
}

class UserRepository implements Repository<User> {
  private users: Map<string, User> = new Map();

  async findById(id: string): Promise<User | null> {
    return this.users.get(id) ?? null;
  }

  async findAll(): Promise<User[]> {
    return Array.from(this.users.values());
  }

  async save(entity: User): Promise<User> {
    this.users.set(entity.id, entity);
    return entity;
  }

  async delete(id: string): Promise<boolean> {
    return this.users.delete(id);
  }
}
实际应用
API 响应类型建模
interface ApiResponse<T> {
  code: number;
  message: string;
  data: T;
  timestamp: number;
}

interface PaginatedData<T> {
  items: T[];
  total: number;
  page: number;
  pageSize: number;
  hasNext: boolean;
}

interface UserDTO {
  id: string;
  name: string;
  avatar?: string;
}

type UserListResponse = ApiResponse<PaginatedData<UserDTO>>;

async function fetchUsers(page: number): Promise<UserListResponse> {
  const response = await fetch(`/api/users?page=${page}`);
  return response.json() as Promise<UserListResponse>;
}
插件系统接口设计
interface Plugin {
  readonly name: string;
  readonly version: string;
  install(app: Application): void;
  uninstall?(): void;
}

interface Application {
  use(plugin: Plugin): this;
  getPlugin(name: string): Plugin | undefined;
}

interface LoggerPlugin extends Plugin {
  log(level: 'info' | 'warn' | 'error', message: string): void;
}

const loggerPlugin: LoggerPlugin = {
  name: 'logger',
  version: '1.0.0',
  install(app) {
    console.log(`插件 ${this.name} 已安装到应用`);
  },
  log(level, message) {
    console[level](`[${level.toUpperCase()}] ${message}`);
  },
};
小结
    

  • 接口是 TypeScript 描述对象形状的核心机制，使用 interface 关键字声明属性和方法签名
    • 

  • 可选属性（?）和只读属性（readonly）提供了灵活且安全的属性修饰能力
    • 

  • 索引签名允许接口描述动态键名的对象结构
    • 

  • 接口支持多重继承（extends），便于组合和复用类型契约
    • 

  • 声明合并是接口独有的特性，适合扩展第三方库的类型定义
    • 

  • 选择 interface 还是 type 取决于具体场景：优先用接口定义对象形状，需要联合/映射类型时用 type
    • 

  • 泛型接口可以创建高度可复用的类型契约，如 Repository<T> 模式
    •
