模块系统

问题背景

随着前端项目规模的增长，将所有代码放在一个文件中变得不可维护。模块系统解决了三个核心问题：作用域隔离（避免全局污染）、依赖管理（明确声明文件间关系）和代码复用（跨项目共享逻辑）。

TypeScript 完整支持 ES Modules 标准，并在此基础上增加了类型导入/导出的能力。理解模块系统是构建大型 TypeScript 项目的基础。



在 TypeScript 中，任何包含顶层 import 或 export 语句的文件都被视为模块；否则被视为脚本，其内容在全局作用域中可见。






基本语法
命名导出（Named Exports）
命名导出允许一个模块导出多个值，消费者按名称选择性导入：


export interface User {
  id: string;
  name: string;
  email: string;
}

export type UserRole = 'admin' | 'editor' | 'viewer';

export function createUser(name: string, email: string): User {
  return { id: crypto.randomUUID(), name, email };
}

export const MAX_USERS = 1000;
导入时必须使用花括号，并且名称需与导出一致：


import { User, UserRole, createUser, MAX_USERS } from './user';

const admin: User = createUser('Alice', 'alice@example.com');
const role: UserRole = 'admin';
默认导出（Default Export）
每个模块最多有一个默认导出，导入时可自由命名：


export default class Logger {
  private prefix: string;

  constructor(prefix: string) {
    this.prefix = prefix;
  }

  log(message: string): void {
    console.log(`[${this.prefix}] ${message}`);
  }
}
import Logger from './logger';
import MyLogger from './logger';

进阶用法
重命名导入/导出
import { createUser as createNewUser } from './user';

export { Logger as DefaultLogger } from './logger';
整体导入（Namespace Import）
import * as UserModule from './user';

const user: UserModule.User = UserModule.createUser('Bob', 'bob@test.com');
重导出（Re-exports）
将多个模块的内容聚合到一个入口文件中，这是构建库公共 API 的常见模式：


export { User, createUser } from './user';
export { Logger } from './logger';
export { default as Config } from './config';

export * from './utils';
export * as Validators from './validators';
动态导入（Dynamic Imports）
import() 返回 Promise，用于代码分割和按需加载：


async function loadChart(): Promise<void> {
  const { Chart } = await import('./chart');
  const chart = new Chart('container');
  chart.render();
}

type Locale = 'zh' | 'en' | 'ja';

async function loadLocale(lang: Locale): Promise<Record<string, string>> {
  const module = await import(`./locales/${lang}.json`);
  return module.default;
}
TypeScript 会正确推断动态导入返回的模块类型，IDE 中可获得完整的类型补全。


仅类型导入/导出
TypeScript 3.8 引入了 import type 语法，确保导入内容在编译后完全擦除：


import type { User } from './user';
import { createUser, type UserRole } from './user';

export type { User };
export { type UserRole, createUser };


类型推断与约束
模块 vs 脚本上下文
TypeScript 根据文件是否包含顶层 import/export 来决定文件的解析模式：


// script.ts — 脚本模式，变量泄漏到全局
const globalValue = 42;

// module.ts — 模块模式，作用域隔离
export const localValue = 42;

// 将脚本强制转为模块的技巧
export {};
模块解析策略
TypeScript 提供多种模块解析策略，通过 tsconfig.json 中的 moduleResolution 配置：


{
  "compilerOptions": {
    "module": "esnext",
    "moduleResolution": "bundler"
  }
}

小结
    

  • ES Modules 是 TypeScript 推荐的模块方案，使用 import/export 进行依赖管理。
    • 

  • 命名导出对 Tree-shaking 和 IDE 补全更友好，默认导出适合模块只有单一职责时使用。
    • 

  • 重导出（barrel files）可以聚合内部模块，为消费者提供简洁的公共 API。
    • 

  • 动态导入 import() 返回 Promise，是代码分割和按需加载的基础。
    • 

  • import type 确保类型信息在编译时完全擦除，避免不必要的运行时依赖。
    • 

  • 模块解析策略的选择取决于运行环境：Node.js 项目用 node16/nodenext，打包器项目用 bundler。
    • 

  • 合理的模块组织结构和路径映射能显著提升大型项目的可维护性。
