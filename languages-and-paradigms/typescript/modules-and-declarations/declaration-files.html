声明文件与类型声明

问题背景

JavaScript 生态中有海量的库没有原生 TypeScript 支持。当你使用 lodash、express 等库时，TypeScript 编译器并不知道这些库的 API 类型信息。声明文件（.d.ts）解决了这个问题——它们为 JavaScript 代码提供类型描述，让 TypeScript 在不修改原始代码的前提下获得完整的类型检查和 IDE 补全能力。



声明文件只包含类型信息，不包含任何运行时逻辑。编译后它们不会出现在输出的 JavaScript 中。






基本语法
declare 关键字
declare 告诉编译器"这个值在运行时存在，但不在当前文件中定义"：


declare const API_BASE_URL: string;

declare function fetchData(url: string): Promise<unknown>;

declare class EventBus {
  on(event: string, callback: (...args: unknown[]) => void): void;
  emit(event: string, ...args: unknown[]): void;
}
声明文件结构（.d.ts）
声明文件以 .d.ts 为后缀，其中只允许类型声明，不允许实现代码：


// types/math-utils.d.ts
export declare function add(a: number, b: number): number;
export declare function multiply(a: number, b: number): number;

export interface MathResult {
  value: number;
  precision: number;
}
全局声明
在没有 import/export 的 .d.ts 文件中，声明会进入全局作用域：


// globals.d.ts
declare const __DEV__: boolean;
declare const __VERSION__: string;

interface Window {
  dataLayer: Array<Record<string, unknown>>;
}

declare namespace NodeJS {
  interface ProcessEnv {
    NODE_ENV: 'development' | 'production' | 'test';
    DATABASE_URL: string;
    API_KEY: string;
  }
}


进阶用法
模块声明
为没有类型的第三方库编写模块声明：


// types/untyped-lib.d.ts
declare module 'untyped-lib' {
  export interface Config {
    host: string;
    port: number;
  }

  export function initialize(config: Config): void;
  export function shutdown(): Promise<void>;
}
使用通配符模块声明处理非 JS 资源：


// types/assets.d.ts
declare module '*.css' {
  const classes: Record<string, string>;
  export default classes;
}

declare module '*.svg' {
  const content: string;
  export default content;
}

declare module '*.png' {
  const src: string;
  export default src;
}
DefinitelyTyped 与 @types
DefinitelyTyped 是社区维护的类型声明仓库，通过 @types 命名空间发布到 npm：


npm install --save-dev @types/lodash
npm install --save-dev @types/express
npm install --save-dev @types/node

类型推断与约束
声明文件解析流程
声明合并（Declaration Merging）
TypeScript 允许同名声明自动合并，这是声明文件中的强大特性：


interface User {
  id: string;
  name: string;
}

interface User {
  email: string;
  role: string;
}

// 合并后等价于：
// interface User {
//   id: string;
//   name: string;
//   email: string;
//   role: string;
// }
环境声明的作用域规则
// 全局声明（无 import/export）— 自动进入全局作用域
declare const VERSION: string;

// 模块声明 — 仅在导入时可用
export declare function parse(input: string): unknown;
一旦文件中出现 import 或 export，整个文件变为模块作用域。如果需要在模块文件中声明全局类型，使用 declare global：


import type { SomeType } from './types';

declare global {
  interface Window {
    myApp: SomeType;
  }

  var DEBUG: boolean;
}

export {};


实际应用
为无类型的 JS 库编写声明文件
假设有一个 JavaScript 工具库 string-utils，以下是为它编写声明文件的完整流程：


// types/string-utils.d.ts
declare module 'string-utils' {
  export function capitalize(str: string): string;
  export function truncate(str: string, maxLength: number): string;
  export function slugify(str: string): string;

  export interface FormatOptions {
    locale?: string;
    currency?: string;
    decimals?: number;
  }

  export function formatNumber(value: number, options?: FormatOptions): string;
}
// 使用时获得完整类型支持
import { capitalize, formatNumber } from 'string-utils';

const title = capitalize('hello world');
const price = formatNumber(19.99, { currency: 'CNY', decimals: 2 });
生成声明文件
TypeScript 编译器可以从 .ts 源码自动生成 .d.ts 文件：


{
  "compilerOptions": {
    "declaration": true,
    "declarationDir": "./dist/types",
    "emitDeclarationOnly": false
  }
}
src/
├── index.ts
├── utils.ts
└── types.ts

dist/
├── index.js
├── utils.js
├── types/
│   ├── index.d.ts    ← 自动生成
│   ├── utils.d.ts    ← 自动生成
│   └── types.d.ts    ← 自动生成
声明文件与 package.json 集成
{
  "name": "my-lib",
  "main": "./dist/index.js",
  "types": "./dist/types/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/types/index.d.ts",
      "import": "./dist/esm/index.js",
      "require": "./dist/cjs/index.cjs"
    }
  }
}


types 条件应始终放在 exports 映射的最前面，确保 TypeScript 优先匹配类型文件。






小结
    

  • .d.ts 声明文件为 JavaScript 代码提供类型描述，是 TypeScript 类型系统的桥梁。
    • 

  • declare 关键字用于声明运行时存在但未在当前文件中定义的值。
    • 

  • 全局声明在无 import/export 的 .d.ts 文件中自动进入全局作用域；模块中需用 declare global。
    • 

  • DefinitelyTyped（@types）是社区维护的第三方库类型声明来源，已覆盖数万个 npm 包。
    • 

  • 声明合并允许跨文件扩展接口，是模块增强的重要机制。
    • 

  • TypeScript 编译器可通过 declaration 选项自动从源码生成 .d.ts 文件。
    • 

  • 发布 npm 库时，在 package.json 的 types 和 exports 中正确配置声明文件路径至关重要。
    •
