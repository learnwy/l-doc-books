命名空间与三斜杠指令

问题背景

在 ES Modules 成为标准之前，TypeScript 使用命名空间（namespace）来组织代码并避免全局命名冲突。虽然现代项目几乎全面采用 ES Modules，但命名空间在某些场景中仍然不可替代——特别是声明合并和全局类型增强。

三斜杠指令（/// <reference>）是 TypeScript 最早期的依赖声明方式。如今它的使用范围已大幅缩小，但在声明文件和全局类型引用中仍有其存在价值。



新项目应优先使用 ES Modules。命名空间的主要用途已收窄到声明合并和全局类型增强。






基本语法
命名空间定义
命名空间使用 namespace 关键字，内部使用 export 暴露成员：


namespace Validation {
  export interface StringValidator {
    isValid(s: string): boolean;
  }

  export class EmailValidator implements StringValidator {
    isValid(s: string): boolean {
      return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(s);
    }
  }

  export class PhoneValidator implements StringValidator {
    isValid(s: string): boolean {
      return /^\d{11}$/.test(s);
    }
  }

  const internalHelper = 'not exported';
}

const validator: Validation.StringValidator = new Validation.EmailValidator();
console.log(validator.isValid('test@example.com'));
嵌套命名空间
namespace App {
  export namespace Models {
    export interface User {
      id: string;
      name: string;
    }
  }

  export namespace Services {
    export function getUser(id: string): Models.User {
      return { id, name: 'Alice' };
    }
  }
}

const user: App.Models.User = App.Services.getUser('1');
三斜杠指令
三斜杠指令必须出现在文件的最顶部（在任何语句之前）：


/// <reference path="./validation.ts" />
/// <reference types="node" />
/// <reference lib="es2022" />




指令
用途
示例





reference path
引用另一个 TypeScript 文件
/// <reference path="./types.ts" />




reference types
引用 @types 包或类型声明包
/// <reference types="node" />




reference lib
包含内置库声明（如 es2022、dom）
/// <reference lib="dom" />







进阶用法
声明合并：命名空间增强类
命名空间可以与同名的类、函数或枚举合并，这是它在现代 TypeScript 中最有价值的能力：


class Album {
  label: Album.AlbumLabel;

  constructor(label: Album.AlbumLabel) {
    this.label = label;
  }
}

namespace Album {
  export interface AlbumLabel {
    name: string;
    country: string;
  }

  export function createLabel(name: string): AlbumLabel {
    return { name, country: 'CN' };
  }
}

const label = Album.createLabel('EMI');
const album = new Album(label);
命名空间增强枚举
enum Color {
  Red = 'RED',
  Green = 'GREEN',
  Blue = 'BLUE',
}

namespace Color {
  export function fromHex(hex: string): Color {
    const map: Record<string, Color> = {
      '#FF0000': Color.Red,
      '#00FF00': Color.Green,
      '#0000FF': Color.Blue,
    };
    return map[hex.toUpperCase()] ?? Color.Red;
  }

  export function toHex(color: Color): string {
    const map: Record<Color, string> = {
      [Color.Red]: '#FF0000',
      [Color.Green]: '#00FF00',
      [Color.Blue]: '#0000FF',
    };
    return map[color];
  }
}

const color = Color.fromHex('#00FF00');
const hex = Color.toHex(Color.Blue);
模块增强（Module Augmentation）
在模块系统中扩展已有模块的类型定义：


import { Request } from 'express';

declare module 'express' {
  interface Request {
    userId?: string;
    sessionId?: string;
    permissions?: string[];
  }
}

export {};
import type { Request, Response } from 'express';

function authMiddleware(req: Request, _res: Response, next: () => void): void {
  req.userId = 'user-123';
  req.permissions = ['read', 'write'];
  next();
}
全局增强（Global Augmentation）
在模块文件中向全局作用域添加类型：


export {};

declare global {
  interface Array<T> {
    first(): T | undefined;
    last(): T | undefined;
  }

  interface String {
    toTitleCase(): string;
  }
}

Array.prototype.first = function <T>(this: T[]): T | undefined {
  return this[0];
};

Array.prototype.last = function <T>(this: T[]): T | undefined {
  return this[this.length - 1];
};

String.prototype.toTitleCase = function (this: string): string {
  return this.replace(/\b\w/g, (c) => c.toUpperCase());
};

三斜杠指令的适用场景
在现代 TypeScript 项目中，三斜杠指令仅在以下情况使用：


// ✅ 场景 1：声明文件中引用其他声明文件
/// <reference path="./globals.d.ts" />

// ✅ 场景 2：引入 @types 包的类型（当 tsconfig 未自动包含时）
/// <reference types="vite/client" />

// ✅ 场景 3：在 lib 选项不足时显式引入内置类型
/// <reference lib="esnext.disposable" />

// ❌ 不推荐：在模块文件中用 reference path 代替 import
// 应使用 import 语句


实际应用
为声明文件组织复杂 API 类型
// types/payment.d.ts
declare namespace Payment {
  interface Transaction {
    id: string;
    amount: number;
    currency: string;
    status: TransactionStatus;
  }

  type TransactionStatus = 'pending' | 'completed' | 'failed' | 'refunded';

  interface Gateway {
    charge(amount: number, currency: string): Promise<Transaction>;
    refund(transactionId: string): Promise<Transaction>;
    getTransaction(id: string): Promise<Transaction>;
  }

  interface Config {
    apiKey: string;
    sandbox: boolean;
    timeout: number;
  }
}

declare function createPaymentGateway(config: Payment.Config): Payment.Gateway;
增强 Vue Router 的类型
import 'vue-router';

declare module 'vue-router' {
  interface RouteMeta {
    requiresAuth?: boolean;
    title?: string;
    roles?: Array<'admin' | 'editor' | 'viewer'>;
  }
}

export {};
组合使用模块增强与全局增强

  interface AxiosRequestConfig {
    retryCount?: number;
    retryDelay?: number;
  }

declare global {

小结
    

  • 命名空间是 TypeScript 早期的代码组织方式，现代项目中已被 ES Modules 取代。
    • 

  • 命名空间的核心价值在于声明合并——可以与类、函数、枚举合并，为它们添加静态成员和嵌套类型。
    • 

  • 模块增强（declare module）用于扩展第三方库的类型定义，如给 Express 的 Request 添加自定义字段。
    • 

  • 全局增强（declare global）用于在模块文件中向全局作用域注入类型，如扩展 Array.prototype。
    • 

  • 三斜杠指令的使用场景已缩小到声明文件间的引用、@types 包引入和内置库声明。
    • 

  • 新代码应始终优先使用 import/export，仅在类型增强场景中使用命名空间和三斜杠指令。
    •
