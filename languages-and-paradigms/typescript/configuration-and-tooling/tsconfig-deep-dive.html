tsconfig.json 详解

概述

tsconfig.json 是 TypeScript 项目的核心配置文件，它告诉编译器如何编译代码、编译哪些文件以及输出什么格式。一个合理的 tsconfig 配置直接决定了项目的类型安全程度、编译性能和开发体验。

一个完整的 tsconfig.json 由顶层选项和 compilerOptions 两大部分组成。理解每个选项的作用和相互关系，是构建可靠 TypeScript 工程的第一步。




核心配置项
顶层选项总览




选项
类型
作用





compilerOptions
对象
编译器行为配置




include
字符串数组
指定包含的文件 glob 模式




exclude
字符串数组
指定排除的文件 glob 模式




files
字符串数组
精确指定要编译的文件列表




extends
字符串
继承另一个 tsconfig 文件




references
对象数组
声明项目引用（多项目构建）





include 与 exclude
include 使用 glob 模式确定编译范围，exclude 从中排除特定目录或文件：


{
  "include": ["src/**/*", "types/**/*"],
  "exclude": ["node_modules", "dist", "**/*.spec.ts"]
}
glob 模式支持以下通配符：






模式
含义





*
匹配零个或多个字符（不含路径分隔符）




?
匹配单个字符




**/
匹配任意深度的子目录





如果未指定 include，默认包含 tsconfig 所在目录及子目录下所有 .ts、.tsx、.d.ts 文件。exclude 的默认值为 ["node_modules", "bower_components", "jspm_packages"] 加上 outDir 指定的目录。


files
files 用于精确指定需要编译的文件，适合小型项目或需要精确控制的场景：


{
  "files": ["src/index.ts", "src/config.ts", "src/types.ts"]
}
files 中列出的文件不会被 exclude 排除。如果同时指定了 files 和 include，两者取并集。


extends
extends 实现配置继承，子配置会覆盖父配置中的同名选项：


{
  "extends": "./tsconfig.base.json",
  "compilerOptions": {
    "outDir": "./dist"
  },
  "include": ["src/**/*"]
}
从 TypeScript 5.0 开始，extends 支持数组形式，实现多重继承：


{
  "extends": ["@tsconfig/node20/tsconfig.json", "./tsconfig.paths.json"]
}
多重继承时，后面的配置会覆盖前面的同名选项。


references
references 用于多项目构建场景（Monorepo），声明当前项目依赖的其他 TypeScript 项目：


{
  "references": [{ "path": "../shared" }, { "path": "../utils" }]
}
被引用的项目必须启用 composite: true，详见项目引用章节。




常见场景配置
compilerOptions 分类详解
compilerOptions 包含数十个选项，按功能可分为以下几类：


类型检查（Type Checking）
控制 TypeScript 类型系统的严格程度：


{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noFallthroughCasesInSwitch": true,
    "noImplicitOverride": true,
    "noPropertyAccessFromIndexSignature": true
  }
}




选项
作用





strict
启用所有严格类型检查选项




noUncheckedIndexedAccess
索引访问结果自动包含 undefined




exactOptionalPropertyTypes
区分可选属性和 undefined 值属性




noFallthroughCasesInSwitch
禁止 switch 语句穿透




noImplicitOverride
子类覆盖父类方法必须显式标记 override





模块（Modules）
控制模块解析和导入行为：


{
  "compilerOptions": {
    "module": "ESNext",
    "moduleResolution": "bundler",
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "@utils/*": ["src/utils/*"]
    },
    "resolveJsonModule": true,
    "allowImportingTsExtensions": true
  }
}




选项
作用





module
输出的模块格式（ESNext/CommonJS 等）




moduleResolution
模块解析策略（bundler/node16 等）




baseUrl
路径解析基准目录




paths
路径别名映射




resolveJsonModule
允许导入 JSON 文件




allowImportingTsExtensions
允许导入 .ts 扩展名（需 noEmit）





moduleResolution 的选择对项目影响重大：






值
适用场景





bundler
使用 Webpack/Vite 等打包工具




node16
Node.js 16+ 原生 ESM




nodenext
Node.js 最新版本，跟随 Node 演进





产物输出（Emit）
控制编译产物的格式和位置：


{
  "compilerOptions": {
    "target": "ES2022",
    "outDir": "./dist",
    "rootDir": "./src",
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "removeComments": false,
    "noEmit": false
  }
}




选项
作用





target
编译目标 ECMAScript 版本




outDir
输出目录




rootDir
源码根目录（影响输出目录结构）




declaration
生成 .d.ts 类型声明文件




declarationMap
生成声明文件的 source map




sourceMap
生成 .js.map 文件




noEmit
仅做类型检查，不输出文件





JavaScript 支持
允许在 TypeScript 项目中处理 JavaScript 文件：


{
  "compilerOptions": {
    "allowJs": true,
    "checkJs": true,
    "maxNodeModuleJsDepth": 1
  }
}




选项
作用





allowJs
允许编译 .js 文件




checkJs
对 .js 文件进行类型检查




maxNodeModuleJsDepth
检查 node_modules 中 JS 的深度





互操作约束（Interop Constraints）
处理不同模块系统之间的兼容性：


{
  "compilerOptions": {
    "esModuleInterop": true,
    "allowSyntheticDefaultImports": true,
    "forceConsistentCasingInFileNames": true,
    "isolatedModules": true,
    "verbatimModuleSyntax": true
  }
}




选项
作用





esModuleInterop
生成兼容代码以支持 CJS/ESM 互操作




allowSyntheticDefaultImports
允许从无默认导出的模块中默认导入




forceConsistentCasingInFileNames
强制文件名大小写一致




isolatedModules
确保每个文件可独立编译（兼容 Babel 等工具）




verbatimModuleSyntax
强制使用 type 标注仅类型导入







最佳实践
推荐的基础配置
适用于大多数现代 TypeScript 项目的基础配置：


{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "skipLibCheck": true,
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "resolveJsonModule": true,
    "isolatedModules": true,
    "verbatimModuleSyntax": true,
    "noUncheckedIndexedAccess": true,
    "noImplicitOverride": true,
    "noFallthroughCasesInSwitch": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
Node.js 后端项目
{
  "extends": "@tsconfig/node20/tsconfig.json",
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src",
    "declaration": true,
    "sourceMap": true
  },
  "include": ["src/**/*"]
}
React 前端项目
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "jsx": "react-jsx",
    "noEmit": true,
    "isolatedModules": true,
    "esModuleInterop": true,
    "resolveJsonModule": true,
    "forceConsistentCasingInFileNames": true,
    "skipLibCheck": true,
    "paths": {
      "@/*": ["./src/*"]
    }
  },
  "include": ["src"]
}
库（Library）项目
发布 npm 包时需要特别注意声明文件和模块格式：


{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "declaration": true,
    "declarationMap": true,
    "outDir": "./dist",
    "rootDir": "./src",
    "sourceMap": true,
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "verbatimModuleSyntax": true
  },
  "include": ["src/**/*"],
  "exclude": ["**/*.spec.ts", "**/*.test.ts"]
}
配置继承策略
在 Monorepo 中使用分层配置：


根目录 tsconfig.base.json：


{
  "compilerOptions": {
    "strict": true,
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "skipLibCheck": true,
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "composite": true,
    "verbatimModuleSyntax": true
  }
}
子项目 packages/core/tsconfig.json：


{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src/**/*"],
  "references": []
}
常见错误排查




问题
原因
解决方案





文件未被编译
不在 include 范围内
检查 include/exclude 配置




路径别名运行时报错
paths 只影响编译，不影响运行时
配合 bundler 或 tsconfig-paths 使用




Cannot find module 错误
moduleResolution 与运行时不匹配
根据运行环境选择正确的解析策略




声明文件未生成
未启用 declaration
设置 declaration: true




编译产物目录结构异常
rootDir 配置错误
确保 rootDir 指向源码根目录





小结
    

  • tsconfig.json 由顶层选项（include、exclude、files、extends、references）和 compilerOptions 两大部分组成。
    • 

  • include/exclude 使用 glob 模式控制编译范围，files 用于精确指定文件。
    • 

  • extends 实现配置继承，支持单继承和多重继承（TypeScript 5.0+），是 Monorepo 配置复用的基础。
    • 

  • compilerOptions 按功能分为类型检查、模块、产物输出、JavaScript 支持和互操作约束五大类。
    • 

  • moduleResolution 的选择（bundler/node16/nodenext）直接决定模块解析行为，必须与项目的运行环境和构建工具匹配。
    • 

  • 不同项目类型（Node 后端、React 前端、npm 库、Monorepo）需要针对性的配置策略。
    • 

  • 路径别名 paths 仅在编译阶段生效，运行时需配合打包工具或 tsconfig-paths 解决。
    •
