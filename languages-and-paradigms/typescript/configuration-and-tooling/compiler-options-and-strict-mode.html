编译选项与严格模式

概述

TypeScript 的 strict 标志是一组严格类型检查选项的总开关。启用 strict: true 相当于同时开启多个子选项，每个子选项都能捕获特定类别的潜在错误。理解这些选项的含义和影响，是写出健壮 TypeScript 代码的关键。

除了 strict 包含的选项外，还有 noUncheckedIndexedAccess 和 exactOptionalPropertyTypes 等额外严格选项，它们不在 strict 范围内，但能进一步增强类型安全。




核心配置项
strict 标志总览
strict: true 等价于同时启用以下所有选项：






选项

strictNullChecks
null 和 undefined 不再可赋值给任意类型




strictFunctionTypes
函数参数类型采用逆变检查

严格检查 bind/call/apply 的参数类型

类属性必须在构造函数中初始化

禁止隐式 any 类型

在 tsconfig 中启用：


{
  "compilerOptions": {
    "strict": true
  }
}
启用 strict 后仍可单独关闭某个子选项（不推荐）：


{
  "compilerOptions": {
    "strict": true,
    "strictPropertyInitialization": false
  }
}


常见场景配置
strictNullChecks
启用后，null 和 undefined 成为独立类型，不再隐式兼容其他类型。


关闭时的代码：


// strictNullChecks: false — 编译通过但运行时可能崩溃
function getLength(str: string) {
  return str.length;
}

const result = getLength(null as any);
启用后的安全写法：


// strictNullChecks: true — 必须处理 null/undefined
function getLength(str: string | null): number {
  if (str === null) {
    return 0;
  }
  return str.length;
}

const result = getLength(null);
strictFunctionTypes
启用后，函数参数类型检查采用逆变（contravariant）规则，禁止不安全的函数赋值。


关闭时的代码：


// strictFunctionTypes: false — 允许不安全的协变参数
type Handler = (event: Event) => void;

const mouseHandler = (event: MouseEvent) => {
  console.log(event.clientX);
};

const handler: Handler = mouseHandler;
启用后的安全写法：


// strictFunctionTypes: true — 阻止不安全赋值
type Handler = (event: MouseEvent) => void;

const handler: Handler = (event: MouseEvent) => {
  console.log(event.clientX);
};
strictBindCallApply
启用后，bind、call、apply 方法会严格检查参数类型：


关闭时的代码：


// strictBindCallApply: false — 参数类型不检查
function greet(name: string, age: number): string {
  return `${name} is ${age}`;
}

const result = greet.call(undefined, 'Alice', 'not a number');
启用后的安全写法：


// strictBindCallApply: true — 类型安全的 call
function greet(name: string, age: number): string {
  return `${name} is ${age}`;
}

const result = greet.call(undefined, 'Alice', 30);

const boundGreet = greet.bind(undefined, 'Bob');
const result2 = boundGreet(25);
strictPropertyInitialization
启用后，类的非可选属性必须在声明时或构造函数中初始化：


关闭时的代码：


// strictPropertyInitialization: false — 遗漏初始化不报错
class User {
  name: string;
  email: string;

  constructor(name: string) {
    this.name = name;
  }
}
启用后的安全写法：


// strictPropertyInitialization: true — 必须初始化所有属性
class User {
  name: string;
  email: string;

  constructor(name: string, email: string) {
    this.name = name;
    this.email = email;
  }
}

class Config {
  readonly timeout: number = 3000;
  host: string | undefined;
}
如果属性确实需要延迟初始化，使用明确赋值断言（!）：


class Component {
  element!: HTMLElement;

  initialize(el: HTMLElement): void {
    this.element = el;
  }
}
noImplicitAny
禁止变量或参数在无法推断类型时隐式成为 any：


关闭时的代码：


// noImplicitAny: false — 参数隐式为 any
function process(data) {
  return data.length;
}
启用后的安全写法：


// noImplicitAny: true — 必须显式标注类型
function process(data: string): number {
  return data.length;
}

function transform(items: unknown[]): string[] {
  return items.map((item) => String(item));
}
noImplicitThis
禁止 this 在函数内隐式推断为 any：


关闭时的代码：


// noImplicitThis: false — this 隐式为 any
const calculator = {
  value: 0,
  add(n: number) {
    return function () {
      this.value += n;
    };
  },
};
启用后的安全写法：


// noImplicitThis: true — 使用 this 参数或箭头函数
const calculator = {
  value: 0,
  add(this: { value: number }, n: number) {
    this.value += n;
  },
};

class Counter {
  value = 0;
  increment = () => {
    this.value += 1;
  };
}
alwaysStrict
在每个输出文件顶部添加 "use strict" 指令，并以 ECMAScript 严格模式解析源文件。对于使用 ESM 模块的项目，此选项本质上已内含（ESM 默认启用严格模式）。


{
  "compilerOptions": {
    "alwaysStrict": true
  }
}
useUnknownInCatchVariables
将 catch 子句的变量类型从 any 改为 unknown，强制在使用前进行类型检查：


关闭时的代码：


// useUnknownInCatchVariables: false — error 为 any
try {
  JSON.parse('invalid');
} catch (error) {
  console.log(error.message);
}
启用后的安全写法：


// useUnknownInCatchVariables: true — error 为 unknown
try {
  JSON.parse('invalid');
} catch (error) {
  if (error instanceof Error) {
    console.log(error.message);
  } else {
    console.log('未知错误:', String(error));
  }
}


额外严格选项（不在 strict 范围内）
noUncheckedIndexedAccess
通过索引签名访问的值自动包含 undefined，防止对不存在的键进行不安全访问：


关闭时的代码：


// noUncheckedIndexedAccess: false — 默认不含 undefined
const scores: Record<string, number> = { math: 95, english: 88 };
const science: number = scores['science'];
console.log(science.toFixed(2));
启用后的安全写法：


// noUncheckedIndexedAccess: true — 自动包含 undefined
const scores: Record<string, number> = { math: 95, english: 88 };
const science: number | undefined = scores['science'];

if (science !== undefined) {
  console.log(science.toFixed(2));
}

const items: string[] = ['a', 'b', 'c'];
const first: string | undefined = items[0];
exactOptionalPropertyTypes
启用后，可选属性 ? 不再隐含 undefined 可赋值。即可选属性的含义是"可以缺失"，但如果存在，值不能是 undefined：


关闭时的代码：


// exactOptionalPropertyTypes: false — 可选属性允许赋 undefined
interface Theme {
  color?: string;
}

const theme: Theme = { color: undefined };
启用后的安全写法：


// exactOptionalPropertyTypes: true — 区分"缺失"与"undefined"
interface Theme {
  color?: string;
}

const theme1: Theme = {};
const theme2: Theme = { color: 'blue' };

interface ThemeWithUndefined {
  color?: string | undefined;
}

const theme3: ThemeWithUndefined = { color: undefined };


最佳实践
新项目：直接启用全部严格选项
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noImplicitOverride": true,
    "noFallthroughCasesInSwitch": true
  }
}

配合 ESLint 加强检查
TypeScript 的严格选项关注类型层面，ESLint 的 @typescript-eslint 插件则关注代码质量和风格。两者配合使用效果最佳：


{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true
  }
}
{
  "extends": ["eslint:recommended", "plugin:@typescript-eslint/strict-type-checked"],
  "rules": {
    "@typescript-eslint/no-explicit-any": "error",
    "@typescript-eslint/no-non-null-assertion": "warn",
    "@typescript-eslint/prefer-nullish-coalescing": "error"
  }
}
小结
    

  • strict: true 是一个总开关，同时启用 8 个严格类型检查子选项。
    • 

  • strictNullChecks 是影响最大的选项，让 null/undefined 成为独立类型，强制开发者处理空值。
    • 

  • strictFunctionTypes 确保函数参数类型遵循逆变规则，防止不安全的函数赋值。
    • 

  • strictPropertyInitialization 要求类属性必须在构造函数中初始化，确保对象状态完整。
    • 

  • useUnknownInCatchVariables 将 catch 变量类型从 any 改为 unknown，强制进行类型检查后再使用。
    • 

  • noUncheckedIndexedAccess 和 exactOptionalPropertyTypes 虽不在 strict 范围内，但能显著提升类型安全，建议在新项目中启用。
    • 

  • 存量项目应逐步启用严格选项，先从 noImplicitAny 和 strictNullChecks 开始，逐步过渡到完全严格模式。
    • 

  • 编译器选项与 ESLint 规则互补，前者守护类型安全，后者守护代码质量。
