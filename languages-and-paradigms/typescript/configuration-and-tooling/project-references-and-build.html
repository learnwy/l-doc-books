项目引用与构建流水线

概述

当 TypeScript 项目规模增长到一定程度——特别是在 Monorepo 架构下——单一 tsconfig.json 已无法满足多包编译、增量构建和依赖隔离的需求。项目引用（Project References）是 TypeScript 提供的官方解决方案，它将大型代码库拆分为多个独立编译单元，配合 tsc --build 实现依赖感知的增量编译。

项目引用的核心价值：增量编译减少重复构建时间、依赖边界防止包之间的循环依赖、声明文件隔离确保每个包只暴露公共 API。




核心配置项
composite 选项
composite: true 是项目引用的基础——被引用的项目必须开启此选项：


{
  "compilerOptions": {
    "composite": true,
    "declaration": true,
    "declarationMap": true,
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src/**/*"]
}
启用 composite 后，TypeScript 会强制执行以下约束：






约束
说明





declaration 必须为 true
必须生成声明文件供引用方使用




必须设置 rootDir
确保输出目录结构可预测




所有源文件必须被匹配
include 或 files 必须覆盖所有实现文件




生成 .tsbuildinfo 文件
记录构建状态，支持增量编译





references 选项
在引用方的 tsconfig 中声明依赖关系：


{
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "references": [{ "path": "../shared" }, { "path": "../core" }],
  "include": ["src/**/*"]
}
path 指向被引用项目的目录（包含 tsconfig.json），或直接指向 tsconfig 文件。


tsBuildInfoFile
增量编译的状态文件路径，默认与 outDir 中的 .tsbuildinfo 同名：


{
  "compilerOptions": {
    "composite": true,
    "incremental": true,
    "tsBuildInfoFile": "./dist/.tsbuildinfo"
  }
}
.tsbuildinfo 文件记录了上次编译的文件哈希和依赖关系，使 tsc --build 能够跳过未修改的项目。

Monorepo 完整配置
一个典型的 Monorepo 项目结构：


monorepo/
├── tsconfig.base.json
├── tsconfig.json          # 根 solution 文件
├── packages/
│   ├── shared/
│   │   ├── src/
│   │   │   └── index.ts
│   │   ├── tsconfig.json
│   │   └── package.json
│   ├── core/
│   │   ├── src/
│   │   │   └── index.ts
│   │   ├── tsconfig.json
│   │   └── package.json
│   └── app/
│       ├── src/
│       │   └── index.ts
│       ├── tsconfig.json
│       └── package.json
根目录 tsconfig.base.json（公共配置）：


{
  "compilerOptions": {
    "strict": true,
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "skipLibCheck": true,
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "composite": true
  }
}
根目录 tsconfig.json（Solution 文件）：


{
  "files": [],
  "references": [{ "path": "./packages/shared" }, { "path": "./packages/core" }, { "path": "./packages/app" }]
}
packages/shared/tsconfig.json：


{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src/**/*"]
}
packages/core/tsconfig.json：


{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "references": [{ "path": "../shared" }],
  "include": ["src/**/*"]
}
packages/app/tsconfig.json：


{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src",
    "composite": false,
    "noEmit": true
  },
  "references": [{ "path": "../shared" }, { "path": "../core" }],
  "include": ["src/**/*"]
}
增量编译原理
增量编译依赖 .tsbuildinfo 文件记录每个源文件的签名（内容哈希）：


对于非 composite 的独立项目，也可以使用 incremental 选项启用增量编译：


{
  "compilerOptions": {
    "incremental": true,
    "tsBuildInfoFile": "./dist/.tsbuildinfo"
  }
}
跨包导入
被引用的包通过 package.json 的 exports 或 main/types 字段暴露入口：


{
  "name": "@monorepo/shared",
  "main": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    }
  }
}
在 core 包中导入：


import { Logger, type LogLevel } from '@monorepo/shared';

const logger = new Logger('core');
logger.info('初始化完成');
与打包工具集成
项目引用是 TypeScript 编译器层面的概念，打包工具（Webpack、Vite、esbuild）有各自的模块解析机制。两者的协作方式：






模式
TypeScript 职责
打包工具职责





noEmit: true
仅类型检查
负责转译和打包




emitDeclarationOnly
仅生成声明文件
负责 JS 转译和打包




完全由 tsc 编译
编译 + 类型检查 + 声明
仅打包已编译的 JS





在 Vite 项目中的典型配置：


{
  "compilerOptions": {
    "noEmit": true,
    "composite": false
  },
  "references": [{ "path": "../shared" }, { "path": "../core" }]
}
构建脚本分离类型检查和打包：


{
  "scripts": {
    "typecheck": "tsc --build --noEmit",
    "build": "vite build",
    "build:all": "tsc --build && vite build"
  }
}

项目引用设计原则




原则
说明





单向依赖
禁止循环引用，保持依赖图为 DAG




最小暴露
每个包只导出必要的公共 API




独立可编译
每个子项目应能独立通过 tsc -b 编译




共享基础配置
使用 extends 继承公共 tsconfig.base.json




叶子节点不设 composite
最终应用（不被其他包引用）可以关闭 composite

小结
    

  • 项目引用通过 composite + references 将大型代码库拆分为独立编译单元，实现依赖感知的构建。
    • 

  • composite: true 是被引用项目的必要条件，它强制生成声明文件并启用增量编译支持。
    • 

  • tsc --build 是项目引用的专用构建命令，自动按依赖拓扑排序编译，跳过未修改的项目。
    • 

  • .tsbuildinfo 文件记录编译状态（文件哈希），是增量编译的基础，大幅减少重复构建时间。
    • 

  • Monorepo 场景下，根目录使用 Solution 文件（files: [] + references）统一管理所有子项目。
    • 

  • 与打包工具协作时，通常将 TypeScript 限定为类型检查（noEmit: true），由 Vite/Webpack 负责实际的转译和打包。
    • 

  • 项目引用的依赖图必须是有向无环图（DAG），禁止循环引用。
    •
