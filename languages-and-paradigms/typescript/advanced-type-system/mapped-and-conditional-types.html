映射类型与条件类型

问题背景

随着项目中类型定义增多，大量结构相似但略有差异的类型会造成维护负担。例如，一个实体类型需要对应"创建用"、"更新用"、"只读"三种变体，手动定义它们既重复又容易遗漏。TypeScript 的映射类型（Mapped Types）和条件类型（Conditional Types）提供了在类型层面进行"编程"的能力——基于已有类型自动生成新类型。

基本语法
映射类型
映射类型通过遍历已有类型的键来生成新类型：


interface User {
  id: string;
  name: string;
  email: string;
  age: number;
}

type Optional<T> = {
  [K in keyof T]?: T[K];
};

type ReadonlyUser = {
  readonly [K in keyof User]: User[K];
};

type OptionalUser = Optional<User>;
// { id?: string; name?: string; email?: string; age?: number }
映射类型中可以使用 + 或 - 修饰符来添加或移除 readonly 和 ?：


type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};

type Required<T> = {
  [K in keyof T]-?: T[K];
};
条件类型
条件类型根据类型关系选择不同的结果类型：


type IsString<T> = T extends string ? true : false;

type A = IsString<string>; // true
type B = IsString<number>; // false
type C = IsString<'hello'>; // true
条件类型可以嵌套使用：


type TypeName<T> = T extends string
  ? 'string'
  : T extends number
    ? 'number'
    : T extends boolean
      ? 'boolean'
      : T extends undefined
        ? 'undefined'
        : T extends Function
          ? 'function'
          : 'object';

type T1 = TypeName<string>; // "string"
type T2 = TypeName<() => void>; // "function"
type T3 = TypeName<string[]>; // "object"
进阶用法
键重映射（as）
TypeScript 4.1+ 支持在映射类型中使用 as 子句重映射键名：


type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type Setters<T> = {
  [K in keyof T as `set${Capitalize<string & K>}`]: (value: T[K]) => void;
};

interface Person {
  name: string;
  age: number;
}

type PersonGetters = Getters<Person>;
// { getName: () => string; getAge: () => number }

type PersonSetters = Setters<Person>;
// { setName: (value: string) => void; setAge: (value: number) => void }
结合条件类型可以过滤键：


type OnlyStrings<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
};

interface Mixed {
  id: number;
  name: string;
  email: string;
  active: boolean;
}

type StringFields = OnlyStrings<Mixed>;
// { name: string; email: string }
infer 关键字
infer 在条件类型中声明一个待推断的类型变量：


type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

type FnReturn = ReturnType<(x: number) => string>; // string

type FirstArg<T> = T extends (first: infer F, ...rest: any[]) => any ? F : never;

type Arg = FirstArg<(name: string, age: number) => void>; // string

type ArrayElement<T> = T extends (infer E)[] ? E : never;

type Elem = ArrayElement<string[]>; // string

type PromiseValue<T> = T extends Promise<infer V> ? V : T;

type Val = PromiseValue<Promise<number>>; // number
type NoChange = PromiseValue<string>; // string
分布式条件类型
当条件类型的被检查类型是裸类型参数时，联合类型会自动分布：


type Exclude<T, U> = T extends U ? never : T;

type Result = Exclude<'a' | 'b' | 'c', 'a' | 'c'>;
// "b"
// 分布过程：
// ("a" extends "a" | "c" ? never : "a") => never
// | ("b" extends "a" | "c" ? never : "b") => "b"
// | ("c" extends "a" | "c" ? never : "c") => never
// = never | "b" | never = "b"

type Extract<T, U> = T extends U ? T : never;

type OnlyNumbers = Extract<string | number | boolean, number>;
// number
阻止分布行为可以用元组包装：


type NoDistribute<T> = [T] extends [string] ? 'yes' : 'no';

type D1 = NoDistribute<string>; // "yes"
type D2 = NoDistribute<string | number>; // "no"（不分布，整体检查）
类型推断与约束
映射类型 + 条件类型组合
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? (T[K] extends Function ? T[K] : DeepReadonly<T[K]>) : T[K];
};

interface Config {
  database: {
    host: string;
    port: number;
    credentials: {
      username: string;
      password: string;
    };
  };
  cache: {
    ttl: number;
  };
}

type FrozenConfig = DeepReadonly<Config>;
// 所有层级的属性都变为 readonly
深度可选类型
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? (T[K] extends Function ? T[K] : DeepPartial<T[K]>) : T[K];
};

type PartialConfig = DeepPartial<Config>;
// 所有层级的属性都变为可选
挑选特定类型的键
type KeysOfType<T, V> = {
  [K in keyof T]: T[K] extends V ? K : never;
}[keyof T];

interface Model {
  id: number;
  name: string;
  email: string;
  active: boolean;
  score: number;
}

type StringKeys = KeysOfType<Model, string>; // "name" | "email"
type NumberKeys = KeysOfType<Model, number>; // "id" | "score"

type PickByType<T, V> = Pick<T, KeysOfType<T, V>>;

type StringFields = PickByType<Model, string>;
// { name: string; email: string }
实际应用
表单类型生成器
type FormField<T> = {
  value: T;
  error: string | null;
  touched: boolean;
  dirty: boolean;
};

type FormState<T> = {
  [K in keyof T]: FormField<T[K]>;
};

type FormActions<T> = {
  [K in keyof T as `set${Capitalize<string & K>}`]: (value: T[K]) => void;
} & {
  [K in keyof T as `validate${Capitalize<string & K>}`]: () => boolean;
} & {
  reset: () => void;
  submit: () => Promise<void>;
};

interface LoginData {
  username: string;
  password: string;
  remember: boolean;
}

type LoginForm = FormState<LoginData>;
// {
//   username: FormField<string>;
//   password: FormField<string>;
//   remember: FormField<boolean>;
// }

type LoginActions = FormActions<LoginData>;
// {
//   setUsername: (value: string) => void;
//   setPassword: (value: string) => void;
//   setRemember: (value: boolean) => void;
//   validateUsername: () => boolean;
//   validatePassword: () => boolean;
//   validateRemember: () => boolean;
//   reset: () => void;
//   submit: () => Promise<void>;
// }
API 路由类型推导
type ExtractParams<T extends string> = T extends `${string}:${infer Param}/${infer Rest}`
  ? { [K in Param | keyof ExtractParams<Rest>]: string }
  : T extends `${string}:${infer Param}`
    ? { [K in Param]: string }
    : Record<string, never>;

type UserParams = ExtractParams<'/api/users/:userId'>;
// { userId: string }

type PostParams = ExtractParams<'/api/users/:userId/posts/:postId'>;
// { userId: string; postId: string }
小结
    

  • 映射类型通过 [K in keyof T] 遍历已有类型的键，对每个属性进行转换，是构建类型变体的基础
    • 

  • as 子句支持键名重映射和过滤，可以批量生成 getter/setter 类型或按条件排除键
    • 

  • 条件类型 T extends U ? X : Y 实现类型层面的条件分支
    • 

  • infer 关键字在条件类型中声明待推断的类型变量，可用于提取返回值、参数、数组元素等类型
    • 

  • 分布式条件类型对联合类型的每个成员单独应用，是 Exclude、Extract 等工具类型的基础
    • 

  • 映射类型和条件类型组合使用，可以实现 DeepReadonly、DeepPartial、PickByType 等复杂类型变换
    • 

  • 善用这两大工具可以极大减少重复的类型定义，让类型系统真正成为代码的"活文档"
    •
