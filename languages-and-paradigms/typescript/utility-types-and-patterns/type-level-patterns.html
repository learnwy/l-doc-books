类型级编程模式

问题背景

TypeScript 的类型系统已经强大到可以在类型层面表达复杂的业务逻辑。通过品牌类型防止语义上不兼容的值互相赋值、通过类型安全的状态机确保状态转换的合法性、通过Builder 模式在类型层面追踪配置状态——这些模式将运行时错误提前到编译期捕获。

类型级编程不是炫技，而是在关键业务场景中提供编译时保障的实用技术。本文介绍最具实战价值的类型级设计模式。



基本语法
品牌类型（Branded Types）
品牌类型通过添加一个虚拟的标记属性，使结构相同但语义不同的类型彼此不兼容：


type Brand<T, B extends string> = T & { readonly __brand: B };

type UserId = Brand<string, 'UserId'>;
type OrderId = Brand<string, 'OrderId'>;
type Email = Brand<string, 'Email'>;

function createUserId(id: string): UserId {
  return id as UserId;
}

function createOrderId(id: string): OrderId {
  return id as OrderId;
}

function getUser(id: UserId): void {
  console.log('Fetching user:', id);
}

function getOrder(id: OrderId): void {
  console.log('Fetching order:', id);
}

const userId = createUserId('usr_123');
const orderId = createOrderId('ord_456');

getUser(userId);
getOrder(orderId);
// getUser(orderId);  // ❌ Error: OrderId 不能赋值给 UserId
// getOrder(userId);  // ❌ Error: UserId 不能赋值给 OrderId
带验证的品牌类型
结合验证逻辑，确保品牌类型的值始终合法：


type PositiveNumber = Brand<number, 'PositiveNumber'>;
type NonEmptyString = Brand<string, 'NonEmptyString'>;
type Percentage = Brand<number, 'Percentage'>;

function toPositive(n: number): PositiveNumber {
  if (n <= 0) throw new Error(`Expected positive number, got ${n}`);
  return n as PositiveNumber;
}

function toNonEmpty(s: string): NonEmptyString {
  if (s.trim().length === 0) throw new Error('String must not be empty');
  return s as NonEmptyString;
}

function toPercentage(n: number): Percentage {
  if (n < 0 || n > 100) throw new Error(`Percentage must be 0-100, got ${n}`);
  return n as Percentage;
}

function setDiscount(pct: Percentage): void {
  console.log(`Discount: ${pct}%`);
}

setDiscount(toPercentage(15));
// setDiscount(15);  // ❌ Error: number 不能赋值给 Percentage


进阶用法
幻影类型（Phantom Types）
幻影类型参数不出现在值的运行时结构中，仅用于类型层面的区分：


interface Currency<C extends string> {
  readonly amount: number;
  readonly __currency?: C;
}

type USD = Currency<'USD'>;
type CNY = Currency<'CNY'>;
type EUR = Currency<'EUR'>;

function usd(amount: number): USD {
  return { amount };
}

function cny(amount: number): CNY {
  return { amount };
}

function addMoney<C extends string>(a: Currency<C>, b: Currency<C>): Currency<C> {
  return { amount: a.amount + b.amount };
}

const price1 = usd(10);
const price2 = usd(20);
const total = addMoney(price1, price2);

const priceInCNY = cny(100);
// addMoney(price1, priceInCNY);  // ❌ Error: USD 和 CNY 不能混合运算
类型安全的 Builder 模式
在类型层面追踪 Builder 的配置状态，确保必要的配置项都已设置：


interface BuilderState {
  hasHost: boolean;
  hasPort: boolean;
  hasDatabase: boolean;
}

interface ConnectionConfig {
  host: string;
  port: number;
  database: string;
  ssl?: boolean;
  poolSize?: number;
}

class ConnectionBuilder<S extends BuilderState = { hasHost: false; hasPort: false; hasDatabase: false }> {
  private config: Partial<ConnectionConfig> = {};

  host(host: string): ConnectionBuilder<S & { hasHost: true }> {
    this.config.host = host;
    return this as unknown as ConnectionBuilder<S & { hasHost: true }>;
  }

  port(port: number): ConnectionBuilder<S & { hasPort: true }> {
    this.config.port = port;
    return this as unknown as ConnectionBuilder<S & { hasPort: true }>;
  }

  database(db: string): ConnectionBuilder<S & { hasDatabase: true }> {
    this.config.database = db;
    return this as unknown as ConnectionBuilder<S & { hasDatabase: true }>;
  }

  ssl(enabled: boolean): ConnectionBuilder<S> {
    this.config.ssl = enabled;
    return this;
  }

  poolSize(size: number): ConnectionBuilder<S> {
    this.config.poolSize = size;
    return this;
  }

  build(this: ConnectionBuilder<{ hasHost: true; hasPort: true; hasDatabase: true }>): ConnectionConfig {
    return this.config as ConnectionConfig;
  }
}

const config = new ConnectionBuilder().host('localhost').port(5432).database('mydb').ssl(true).build();

// new ConnectionBuilder()
//   .host("localhost")
//   .build();  // ❌ Error: 缺少 port 和 database


类型推断与约束
穷尽匹配（Exhaustive Pattern Matching）
利用 never 类型确保 switch 语句处理了所有可能的情况：


type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'rectangle'; width: number; height: number }
  | { kind: 'triangle'; base: number; height: number };

function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${JSON.stringify(value)}`);
}

function calculateArea(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2;
    case 'rectangle':
      return shape.width * shape.height;
    case 'triangle':
      return (shape.base * shape.height) / 2;
    default:
      return assertNever(shape);
  }
}
当联合类型新增成员时，未处理的分支会产生编译错误：


type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'rectangle'; width: number; height: number }
  | { kind: 'triangle'; base: number; height: number }
  | { kind: 'ellipse'; rx: number; ry: number };

// ❌ 现在 calculateArea 会在 default 分支报错：
// Argument of type '{ kind: "ellipse"; ... }' is not assignable to parameter of type 'never'
类型安全的状态机
在类型层面定义合法的状态转换，使非法转换无法编译：


type OrderState = 'draft' | 'pending' | 'paid' | 'shipped' | 'delivered' | 'cancelled';

interface Order<S extends OrderState> {
  id: string;
  state: S;
  items: Array<{ name: string; price: number }>;
}

interface StateTransitions {
  draft: 'pending' | 'cancelled';
  pending: 'paid' | 'cancelled';
  paid: 'shipped' | 'cancelled';
  shipped: 'delivered';
  delivered: never;
  cancelled: never;
}

function transition<From extends OrderState, To extends StateTransitions[From]>(
  order: Order<From>,
  to: To,
): Order<To & OrderState> {
  return { ...order, state: to } as Order<To & OrderState>;
}

function createOrder(): Order<'draft'> {
  return { id: crypto.randomUUID(), state: 'draft', items: [] };
}

const draft = createOrder();
const pending = transition(draft, 'pending');
const paid = transition(pending, 'paid');
const shipped = transition(paid, 'shipped');
const delivered = transition(shipped, 'delivered');

// transition(draft, "shipped");    // ❌ Error: "shipped" 不在 "pending" | "cancelled" 中
// transition(delivered, "draft");  // ❌ Error: never 中没有有效目标


实际应用
类型安全的事件发射器
interface EventMap {
  'user:login': { userId: string; timestamp: number };
  'user:logout': { userId: string };
  'cart:add': { productId: string; quantity: number };
  'cart:remove': { productId: string };
  'order:create': { orderId: string; total: number };
}

class TypedEventEmitter<E extends Record<string, unknown>> {
  private listeners = new Map<string, Set<(data: unknown) => void>>();

  on<K extends keyof E & string>(event: K, handler: (data: E[K]) => void): () => void {
    if (!this.listeners.has(event)) {
      this.listeners.set(event, new Set());
    }
    const handlers = this.listeners.get(event)!;
    handlers.add(handler as (data: unknown) => void);
    return () => handlers.delete(handler as (data: unknown) => void);
  }

  emit<K extends keyof E & string>(event: K, data: E[K]): void {
    const handlers = this.listeners.get(event);
    if (handlers) {
      handlers.forEach((handler) => handler(data));
    }
  }
}

const emitter = new TypedEventEmitter<EventMap>();

emitter.on('user:login', (data) => {
  console.log(data.userId, data.timestamp);
});

emitter.emit('user:login', { userId: '123', timestamp: Date.now() });
// emitter.emit("user:login", { userId: "123" });  // ❌ Error: 缺少 timestamp
// emitter.emit("unknown:event", {});               // ❌ Error: 未知事件
组合模式：品牌类型 + 状态机
type Brand<T, B extends string> = T & { readonly __brand: B };

type DraftPost = Brand<
  {
    title: string;
    content: string;
  },
  'DraftPost'
>;

type PublishedPost = Brand<
  {
    title: string;
    content: string;
    publishedAt: Date;
    slug: string;
  },
  'PublishedPost'
>;

type ArchivedPost = Brand<
  {
    title: string;
    content: string;
    publishedAt: Date;
    archivedAt: Date;
    slug: string;
  },
  'ArchivedPost'
>;

function createDraft(title: string, content: string): DraftPost {
  return { title, content } as DraftPost;
}

function publish(post: DraftPost): PublishedPost {
  return {
    ...post,
    publishedAt: new Date(),
    slug: post.title.toLowerCase().replace(/\s+/g, '-'),
  } as PublishedPost;
}

function archive(post: PublishedPost): ArchivedPost {
  return {
    ...post,
    archivedAt: new Date(),
  } as ArchivedPost;
}

const draft = createDraft('Hello', 'World');
const published = publish(draft);
const archived = archive(published);

// archive(draft);     // ❌ Error: DraftPost 不能赋值给 PublishedPost
// publish(published); // ❌ Error: PublishedPost 不能赋值给 DraftPost


小结
    

  • 品牌类型通过虚拟标记属性使结构相同但语义不同的类型不可互换，是防止 ID 混用、单位混算的利器。
    • 

  • 幻影类型在类型参数层面区分值的语义（如币种），但不影响运行时结构。
    • 

  • Builder 模式在类型层面追踪已设置的配置项，build() 方法仅在所有必要配置就绪时可调用。
    • 

  • 穷尽匹配利用 never 类型确保 switch/if 语句覆盖了联合类型的所有分支，新增成员时编译器会自动报错。
    • 

  • 类型安全状态机通过泛型约束定义合法的状态转换路径，使非法转换在编译期被拦截。
    • 

  • 类型安全事件发射器利用泛型映射类型，确保事件名称和负载类型的严格对应。
    • 

  • 这些模式可以组合使用，将核心业务逻辑的正确性从运行时测试提升到编译时保障。
