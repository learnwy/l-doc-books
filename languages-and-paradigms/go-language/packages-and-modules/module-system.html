Module System 模块系统

核心概念

Go Module 是 Go 1.11 引入、Go 1.16 默认启用的依赖管理系统。一个 Module 是一组相关 Go 包的集合，以 go.mod 文件为根，定义了模块路径和依赖关系。





概念
说明
示例





Module
包的集合，有版本
github.com/user/project




Package
同目录下的 .go 文件集合
github.com/user/project/pkg/auth




Module Path
模块的唯一标识
github.com/user/project




Module Version
语义化版本号
v1.2.3





go.mod 文件
go.mod 是模块的核心配置文件：


module github.com/myorg/myapp

go 1.22

require (
	github.com/gin-gonic/gin v1.9.1
	github.com/redis/go-redis/v9 v9.4.0
	go.uber.org/zap v1.27.0
	google.golang.org/grpc v1.62.0
)

require (
	github.com/cespare/xxhash/v2 v2.2.0 // indirect
	github.com/dgryski/go-rendezvous v0.0.0-20200823014737-9f7001d12a5f // indirect
	golang.org/x/net v0.21.0 // indirect
)

retract (
	v1.0.0 // 包含严重 bug
	[v1.1.0, v1.2.0] // 不推荐使用
)




指令
用途
示例





module
声明模块路径
module github.com/user/app




go
指定 Go 最低版本
go 1.22




require
声明依赖及版本
require github.com/pkg/errors v0.9.1




replace
替换依赖路径/版本
replace old => new v1.0.0




exclude
排除特定版本
exclude github.com/pkg/lib v1.1.0




retract
撤回已发布的版本
retract v1.0.0




toolchain
指定工具链版本（Go 1.21+）
toolchain go1.22.0





go.sum 文件
go.sum 记录每个依赖的加密哈希值，确保构建的可复现性和安全性：


github.com/gin-gonic/gin v1.9.1 h1:4idEAncQnU5cB7BeOkPtxjfCSye0AAm1R0RVIqFPSA=
github.com/gin-gonic/gin v1.9.1/go.mod h1:hPrL/0KcuKfyOTQFB4sBVY...=
每行格式：模块路径 版本 算法:哈希值






文件
是否提交到 VCS
用途





go.mod
✅ 必须
声明依赖




go.sum
✅ 必须
校验依赖完整性




vendor/
可选
本地依赖缓存





语义版本（Semver）
Go Module 强制使用语义化版本控制：






版本变更
含义
Go Module 规则





v0.x.x
不稳定，API 可随时变
导入路径无后缀




v1.x.x
稳定，遵守兼容性承诺
导入路径无后缀




v2.x.x
不兼容变更
导入路径必须加 /v2




v3+.x.x
更多不兼容变更
导入路径必须加 /vN





v2+ 导入路径规则：


package main

import (
	"github.com/myorg/mylib"
	mylib2 "github.com/myorg/mylib/v2"
	mylib3 "github.com/myorg/mylib/v3"
)

func main() {
	mylib.DoSomething()
	mylib2.DoSomethingV2()
	mylib3.DoSomethingV3()
}
**伪版本号（Pseudo-version）**用于引用未打 tag 的提交：


v0.0.0-20240301120000-abcdef123456
格式：vX.Y.Z-yyyymmddhhmmss-commithash


Module 代理
Go Module 代理加速依赖下载并提供不可变性保证：


go env GOPROXY
# 默认: https://proxy.golang.org,direct

# 设置国内代理
go env -w GOPROXY=https://goproxy.cn,direct

# 多代理回退
go env -w GOPROXY=https://goproxy.cn,https://proxy.golang.org,direct




环境变量
用途
默认值





GOPROXY
模块代理地址
https://proxy.golang.org,direct




GONOSUMCHECK
跳过校验和检查的模块
空




GONOSUMDB
不经过校验和数据库的模块
空




GOPRIVATE
私有模块模式（同时设置 GONOSUMDB 和 GONOSUMCHECK）
空




GONOPROXY
不使用代理的模块
空





私有 Module
对于企业内部的私有模块，需要特殊配置：


go env -w GOPRIVATE=github.com/myorg/*,gitlab.mycompany.com/*

go env -w GONOSUMDB=github.com/myorg/*
go env -w GONOPROXY=github.com/myorg/*
Git 认证配置：


git config --global url."https://oauth2:${TOKEN}@gitlab.mycompany.com".insteadOf "https://gitlab.mycompany.com"

git config --global url."ssh://git@github.com/".insteadOf "https://github.com/"
在 .netrc 中配置认证：


machine github.com
login oauth2
password ghp_xxxxxxxxxxxx

machine gitlab.mycompany.com
login oauth2
password glpat-xxxxxxxxxxxx
Workspace 模式
Go 1.18 引入 Workspace 模式，允许同时开发多个模块：


mkdir workspace && cd workspace
git clone https://github.com/myorg/module-a
git clone https://github.com/myorg/module-b
git clone https://github.com/myorg/shared-lib

go work init ./module-a ./module-b ./shared-lib
生成的 go.work 文件：


go 1.22

use (
	./module-a
	./module-b
	./shared-lib
)




命令
用途





go work init
初始化 workspace




go work use ./path
添加模块到 workspace




go work sync
同步 workspace 中各模块的依赖




go work edit
编辑 go.work 文件





注意事项：






规则
说明





go.work 不提交到 VCS
它是本地开发工具




workspace 内的 replace 自动生效
无需在 go.mod 中 replace




CI/CD 不使用 workspace
用 go.mod 的正式依赖





模块初始化与发布
初始化新模块：


mkdir myapp && cd myapp
go mod init github.com/myorg/myapp
发布模块：


git tag v1.0.0
git push origin v1.0.0

git tag v2.0.0
git push origin v2.0.0
package main

import (
	"fmt"
	"os/exec"
	"strings"
)

func getModuleVersion() string {
	cmd := exec.Command("go", "list", "-m", "-json")
	out, err := cmd.Output()
	if err != nil {
		return "unknown"
	}
	return strings.TrimSpace(string(out))
}

func main() {
	fmt.Println(getModuleVersion())
}
常用 Module 命令速查




命令
用途





go mod init <path>
初始化模块




go mod tidy
添加缺失依赖，移除未使用依赖




go mod download
下载依赖到本地缓存




go mod verify
验证依赖的校验和




go mod graph
打印依赖图




go mod why <pkg>
解释为何需要某依赖




go mod edit -json
JSON 格式输出 go.mod




go mod vendor
将依赖复制到 vendor/




go list -m all
列出所有依赖




go list -m -versions <mod>
列出模块所有版本





小结
Go Module 系统是 Go 生态的基石，理解 go.mod、语义版本、代理和 workspace 对日常开发和项目管理至关重要。






知识点
核心要点





go.mod
模块声明、依赖管理、replace/exclude




go.sum
依赖校验和，确保可复现构建




语义版本
Major 不兼容、Minor 新功能、Patch 修复




v2+ 规则
导入路径必须包含 /vN




Module 代理
GOPROXY 加速下载、提供不可变性




私有 Module
GOPRIVATE 跳过代理和校验和检查




Workspace
go.work 支持多模块并行开发
