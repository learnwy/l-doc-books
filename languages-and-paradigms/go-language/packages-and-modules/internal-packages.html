Internal Packages 内部包

核心概念

Go 的 internal 包机制是一种编译器强制的包可见性控制。位于 internal 目录下的包只能被 internal 目录的父目录（及其子目录）导入，其他位置的代码导入将导致编译错误。





目录
可见性
用途





internal/
仅父目录及子目录
实现细节，不对外暴露




pkg/
任何包可导入
公共 API，供外部使用




根目录
任何包可导入
模块入口





Internal 目录约定
基本规则
目录树可见性示例：


github.com/myorg/myapp/
├── main.go                          # ✅ 可导入 internal/*
├── internal/
│   ├── auth/
│   │   ├── auth.go                  # ✅ 可导入 internal/db
│   │   └── internal/                # 嵌套 internal
│   │       └── token/
│   │           └── token.go         # 仅 auth/ 可导入
│   ├── db/
│   │   └── db.go
│   └── service/
│       └── user.go                  # ✅ 可导入 internal/auth, internal/db
├── pkg/
│   └── client/
│       └── client.go                # ❌ 不可导入 internal/*
└── cmd/
    └── worker/
        └── main.go                  # ✅ 可导入 internal/*
package main

import (
	"fmt"

	"github.com/myorg/myapp/internal/auth"
	"github.com/myorg/myapp/internal/db"
	"github.com/myorg/myapp/internal/service"
)

func main() {
	database := db.New("postgres://localhost:5432/mydb")
	defer database.Close()

	authSvc := auth.New(database)
	userSvc := service.NewUserService(database, authSvc)

	user, err := userSvc.GetUser("123")
	if err != nil {
		fmt.Println("错误:", err)
		return
	}
	fmt.Println("用户:", user.Name)
}
嵌套 internal
internal 可以嵌套使用，每层 internal 只对其直接父目录可见：


internal/
└── auth/
    ├── auth.go          # 暴露给 internal 同级包
    └── internal/
        └── token/
            └── jwt.go   # 仅 auth 包可用
package auth

import (
	"github.com/myorg/myapp/internal/auth/internal/token"
)

type Service struct {
	tokenMgr *token.Manager
}

func New(db DB) *Service {
	return &Service{
		tokenMgr: token.NewManager("secret"),
	}
}

func (s *Service) Login(username, password string) (string, error) {
	return s.tokenMgr.Generate(username)
}
包可见性
Go 使用首字母大小写控制导出（exported）和未导出（unexported）的可见性，配合 internal 形成三层可见性体系：


package db

type Config struct {
	Host     string
	Port     int
	Database string
	Password string
}

type pool struct {
	maxConns int
	conns    []conn
}

type conn struct {
	id     int
	active bool
}

type DB struct {
	config Config
	pool   *pool
}

func New(cfg Config) *DB {
	return &DB{
		config: cfg,
		pool:   newPool(cfg),
	}
}

func newPool(cfg Config) *pool {
	return &pool{
		maxConns: 10,
		conns:    make([]conn, 0, 10),
	}
}

func (d *DB) Query(sql string, args ...any) ([]map[string]any, error) {
	return nil, nil
}

func (d *DB) Close() error {
	return nil
}

分层架构实现
Domain 层（领域模型）：


package domain

import "time"

type User struct {
	ID        string
	Email     string
	Name      string
	CreatedAt time.Time
	UpdatedAt time.Time
}

type UserRepository interface {
	FindByID(id string) (*User, error)
	FindByEmail(email string) (*User, error)
	Save(user *User) error
	Delete(id string) error
}

type OrderStatus int

const (
	OrderPending OrderStatus = iota
	OrderConfirmed
	OrderShipped
	OrderDelivered
	OrderCancelled
)

type Order struct {
	ID        string
	UserID    string
	Items     []OrderItem
	Status    OrderStatus
	Total     int64
	CreatedAt time.Time
}

type OrderItem struct {
	ProductID string
	Quantity  int
	Price     int64
}

type OrderRepository interface {
	FindByID(id string) (*Order, error)
	FindByUserID(userID string) ([]*Order, error)
	Save(order *Order) error
}
Service 层（业务逻辑）：


package service

import (
	"fmt"

	"github.com/myorg/myapp/internal/domain"
)

type UserService struct {
	repo domain.UserRepository
}

func NewUserService(repo domain.UserRepository) *UserService {
	return &UserService{repo: repo}
}

func (s *UserService) GetUser(id string) (*domain.User, error) {
	user, err := s.repo.FindByID(id)
	if err != nil {
		return nil, fmt.Errorf("查找用户失败: %w", err)
	}
	if user == nil {
		return nil, fmt.Errorf("用户 %s 不存在", id)
	}
	return user, nil
}

func (s *UserService) CreateUser(email, name string) (*domain.User, error) {
	existing, _ := s.repo.FindByEmail(email)
	if existing != nil {
		return nil, fmt.Errorf("邮箱 %s 已存在", email)
	}
	user := &domain.User{
		Email: email,
		Name:  name,
	}
	if err := s.repo.Save(user); err != nil {
		return nil, fmt.Errorf("保存用户失败: %w", err)
	}
	return user, nil
}
Handler 层（HTTP 处理）：


package handler

import (
	"encoding/json"
	"net/http"

	"github.com/myorg/myapp/internal/service"
)

type UserHandler struct {
	svc *service.UserService
}

func NewUserHandler(svc *service.UserService) *UserHandler {
	return &UserHandler{svc: svc}
}

func (h *UserHandler) GetUser(w http.ResponseWriter, r *http.Request) {
	id := r.PathValue("id")
	user, err := h.svc.GetUser(id)
	if err != nil {
		http.Error(w, err.Error(), http.StatusNotFound)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(user)
}

小结
Internal 包和包可见性是 Go 项目架构的重要基石，合理使用能有效控制 API 暴露面和代码耦合度。






知识点
核心要点





internal 规则
编译器强制，仅父目录可导入




嵌套 internal
每层独立，更细粒度控制




三层可见性
未导出 → internal 导出 → 公开导出




标准布局
cmd/ + internal/ + pkg/ + api/




分层架构
Handler → Service → Repository → Domain




internal vs pkg
业务逻辑用 internal，通用工具用 pkg
