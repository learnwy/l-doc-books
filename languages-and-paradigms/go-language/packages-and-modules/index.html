包与模块 简介

Go 的包和模块系统是其工程化能力的基石。包是 Go 代码组织的基本单位，每个目录对应一个包，包内的所有文件共享同一命名空间。模块则是包的集合，以 go.mod 文件为根，定义了依赖关系和版本约束。从早期的 GOPATH 到 Go Modules 的全面普及，Go 的依赖管理经历了深刻的演进，最终建立起一套去中心化、可复现、语义化版本驱动的现代依赖管理体系。

本章从四个维度深入包与模块的核心知识。

模块系统是理解 Go 项目结构的钥匙。go.mod 文件声明模块路径和 Go 版本要求，go.sum 文件记录依赖的加密校验哈希以确保构建的可复现性。理解模块路径的命名约定、主版本后缀规则以及 replace 和 retract 指令的用法，是管理复杂项目依赖的基础。workspace 模式进一步简化了多模块项目的本地开发流程。

依赖管理覆盖了日常开发中与依赖打交道的全部场景。go get 获取和升级依赖，go mod tidy 清理无用依赖并补全缺失依赖，go mod vendor 将依赖复制到本地 vendor 目录以支持离线构建。语义化版本导入兼容性规则——相同主版本号的不同版本应保持 API 兼容——是 Go 模块生态的基本契约。GOPROXY 和 GONOSUMDB 等环境变量为企业内网和私有仓库提供了灵活的配置手段。

标准库导览带领你走进 Go 最引以为傲的资产。Go 的标准库覆盖面之广令人赞叹：net/http 提供生产级的 HTTP 服务器和客户端，encoding/json 处理 JSON 编解码，context 管理请求生命周期和取消信号，io 定义了流式数据处理的核心接口。深入了解标准库的设计模式，往往比引入第三方依赖更能写出地道的 Go 代码。

内部包机制是 Go 在包可见性控制上的独特设计。import 路径中包含 internal 的包只能被其父目录树内的代码导入，为大型项目提供了一种在不导出 API 的前提下共享实现代码的手段。结合合理的目录结构规划，internal 包能有效防止内部实现细节被外部意外依赖。

掌握包与模块的运作机制，你将具备在团队协作和开源生态中高效组织、发布和维护 Go 代码的能力。
