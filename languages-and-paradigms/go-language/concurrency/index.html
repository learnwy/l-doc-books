并发编程 简介

并发是 Go 语言的灵魂。Go 从语言层面内置了并发支持，将其视为一等公民而非后期添加的库特性。Rob Pike 的名言"不要通过共享内存来通信，要通过通信来共享内存"深刻地影响了 Go 的并发模型设计。这一理念源自 Tony Hoare 的 CSP（通信顺序进程）理论，goroutine 和 channel 正是这一理论在工程实践中的优雅实现。

本章从四个维度系统讲解 Go 的并发编程体系。

goroutine 是 Go 并发的基本执行单元。它不是操作系统线程，而是由 Go 运行时调度器管理的轻量级协程。一个 goroutine 的初始栈空间仅有几 KB，可以按需增长和收缩，因此在单个进程中轻松创建数十万个 goroutine 是完全可行的。理解 GMP 调度模型——G（goroutine）、M（操作系统线程）和 P（逻辑处理器）三者的协作关系——是深入理解 Go 并发性能特征的基础。

channel 是 goroutine 之间通信的管道。有缓冲和无缓冲通道具有不同的同步语义：无缓冲通道要求发送和接收双方同时就绪，天然具备同步功能；有缓冲通道则在缓冲区未满时允许异步发送。通道的关闭、单向通道类型约束以及 nil 通道的阻塞特性，都是编写正确并发代码的关键知识。

select 与并发模式将 channel 的威力进一步释放。select 语句可以同时等待多个通道操作，实现超时控制、多路复用和优雅退出等常见模式。fan-in、fan-out、pipeline 和 worker pool 是 Go 社区中久经验证的并发设计模式，它们将简单的 goroutine 和 channel 组合成强大的并发处理流水线。

同步原语为共享状态并发提供了必要的工具。sync.Mutex 和 sync.RWMutex 保护临界区，sync.WaitGroup 等待一组 goroutine 完成，sync.Once 确保初始化只执行一次，sync.Pool 复用临时对象以减轻垃圾回收压力。在 channel 不适合的场景下，这些原语是不可或缺的补充。

Go 的并发优势不仅在于 goroutine 的轻量，更在于它提供了一套完整且一致的并发编程范式，让开发者能够自信地构建高并发系统。
