Goroutines 协程

核心概念

Goroutine 是 Go 语言并发编程的核心抽象单元。与操作系统线程不同，Goroutine 是由 Go 运行时管理的用户态轻量级协程，初始栈空间仅 2KB（可动态增长至 GB 级别），创建和切换的开销远低于系统线程。

GMP 调度器
Go 的并发调度器采用 GMP 模型，是理解 Goroutine 高效运行的关键。






组件
全称
职责
数量





G
Goroutine
执行用户代码的协程
无上限（百万级）




M
Machine
操作系统线程，执行 G 的载体
默认上限 10000




P
Processor
逻辑处理器，持有本地运行队列
默认 = GOMAXPROCS（CPU 核数）





调度流程核心规则：


    

  1. 每个 P 维护一个本地运行队列（最多 256 个 G）
    2. 

  2. 新创建的 G 优先放入当前 P 的本地队列
    3. 

  3. 本地队列满时，一半 G 被转移到全局队列
    4. 

  4. M 从绑定的 P 的本地队列获取 G 执行
    5. 

  5. 本地队列为空时，M 尝试从全局队列或其他 P 窃取（Work Stealing）
    6.

import (
	"fmt"
	"runtime"
)

func main() {
	fmt.Println("CPU 核数:", runtime.NumCPU())
	fmt.Println("GOMAXPROCS:", runtime.GOMAXPROCS(0))

	runtime.GOMAXPROCS(4)
	fmt.Println("设置后 GOMAXPROCS:", runtime.GOMAXPROCS(0))

	fmt.Println("当前 Goroutine 数:", runtime.NumGoroutine())
}
Goroutine 生命周期
启动与退出
最基本的启动方式是使用 go 关键字：


package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup

	wg.Add(1)
	go func() {
		defer wg.Done()
		fmt.Println("匿名函数 goroutine")
	}()

	wg.Add(1)
	go func(msg string) {
		defer wg.Done()
		fmt.Println(msg)
	}("带参数的 goroutine")

	wg.Wait()
}
使用 errgroup 管理一组 Goroutine 的启动与错误收集：


package main

import (
	"context"
	"fmt"
	"net/http"

	"golang.org/x/sync/errgroup"
)

func main() {
	g, ctx := errgroup.WithContext(context.Background())

	urls := []string{
		"https://go.dev",
		"https://pkg.go.dev",
		"https://play.golang.org",
	}

	for _, url := range urls {
		g.Go(func() error {
			req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
			if err != nil {
				return err
			}
			resp, err := http.DefaultClient.Do(req)
			if err != nil {
				return err
			}
			defer resp.Body.Close()
			fmt.Printf("%s -> %s\n", url, resp.Status)
			return nil
		})
	}

	if err := g.Wait(); err != nil {
		fmt.Println("错误:", err)
	}
}
Goroutine 泄漏
Goroutine 泄漏是指 Goroutine 启动后永远无法退出，导致内存持续增长。以下是常见的泄漏场景：


场景一：被遗忘的发送者


package main

func leak1() {
	ch := make(chan int)
	go func() {
		val := <-ch
		_ = val
	}()
}
场景二：无人消费的生产者


package main

func leak2() {
	ch := make(chan int)
	go func() {
		ch <- 42
	}()
}
场景三：无限循环未检测退出信号


package main

import "time"

func leak3() {
	go func() {
		for {
			time.Sleep(time.Second)
		}
	}()
}
正确的做法——使用 context 控制生命周期：


package main

import (
	"context"
	"fmt"
	"time"
)

func worker(ctx context.Context, id int) {
	for {
		select {
		case <-ctx.Done():
			fmt.Printf("worker %d: 收到退出信号\n", id)
			return
		default:
			fmt.Printf("worker %d: 工作中\n", id)
			time.Sleep(500 * time.Millisecond)
		}
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
	defer cancel()

	for i := 0; i < 3; i++ {
		go worker(ctx, i)
	}

	<-ctx.Done()
	time.Sleep(100 * time.Millisecond)
	fmt.Println("所有 worker 已退出")
}
使用 goleak 检测泄漏（测试中）：


package main

import (
	"testing"

	"go.uber.org/goleak"
)

func TestMain(m *testing.M) {
	goleak.VerifyTestMain(m)
}

func TestNoLeak(t *testing.T) {
	defer goleak.VerifyNone(t)
	ch := make(chan int, 1)
	go func() {
		ch <- 42
	}()
	<-ch
}
并发模式
Pipeline（管道）
将数据处理分为多个阶段，每个阶段由独立的 Goroutine 执行：


package main

import "fmt"

func generator(nums ...int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for _, n := range nums {
			out <- n
		}
	}()
	return out
}

func square(in <-chan int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for n := range in {
			out <- n * n
		}
	}()
	return out
}

func main() {
	ch := generator(2, 3, 4, 5)
	out := square(ch)

	for v := range out {
		fmt.Println(v)
	}
}
Fan-Out / Fan-In
Fan-Out 将工作分发给多个 Goroutine 并行处理；Fan-In 将多个结果汇聚到一个 channel：


package main

import (
	"fmt"
	"sync"
)

func producer(nums ...int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for _, n := range nums {
			out <- n
		}
	}()
	return out
}

func squareWorker(in <-chan int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for n := range in {
			out <- n * n
		}
	}()
	return out
}

func merge(channels ...<-chan int) <-chan int {
	out := make(chan int)
	var wg sync.WaitGroup

	for _, ch := range channels {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for v := range ch {
				out <- v
			}
		}()
	}

	go func() {
		wg.Wait()
		close(out)
	}()

	return out
}

func main() {
	in := producer(1, 2, 3, 4, 5, 6, 7, 8)

	w1 := squareWorker(in)
	w2 := squareWorker(in)
	w3 := squareWorker(in)

	for result := range merge(w1, w2, w3) {
		fmt.Println(result)
	}
}
Worker Pool（工作池）
限制并发数量，避免资源耗尽：


package main

import (
	"fmt"
	"sync"
	"time"
)

type Job struct {
	ID      int
	Payload string
}

type Result struct {
	JobID  int
	Output string
}

func workerPool(jobs <-chan Job, results chan<- Result, wg *sync.WaitGroup) {
	defer wg.Done()
	for job := range jobs {
		time.Sleep(100 * time.Millisecond)
		results <- Result{
			JobID:  job.ID,
			Output: fmt.Sprintf("处理完成: %s", job.Payload),
		}
	}
}

func main() {
	const numWorkers = 3
	const numJobs = 10

	jobs := make(chan Job, numJobs)
	results := make(chan Result, numJobs)

	var wg sync.WaitGroup
	for i := 0; i < numWorkers; i++ {
		wg.Add(1)
		go workerPool(jobs, results, &wg)
	}

	for i := 0; i < numJobs; i++ {
		jobs <- Job{ID: i, Payload: fmt.Sprintf("任务-%d", i)}
	}
	close(jobs)

	go func() {
		wg.Wait()
		close(results)
	}()

	for r := range results {
		fmt.Printf("Job %d: %s\n", r.JobID, r.Output)
	}
}
使用 semaphore 控制并发度
package main

import (
	"context"
	"fmt"
	"time"

	"golang.org/x/sync/semaphore"
)

func main() {
	sem := semaphore.NewWeighted(3)
	ctx := context.Background()

	for i := 0; i < 10; i++ {
		if err := sem.Acquire(ctx, 1); err != nil {
			fmt.Println("获取信号量失败:", err)
			break
		}
		go func() {
			defer sem.Release(1)
			fmt.Printf("任务 %d 执行中\n", i)
			time.Sleep(time.Second)
		}()
	}

	sem.Acquire(ctx, 3)
	fmt.Println("所有任务完成")
}
调度细节与调优




场景
建议





CPU 密集型任务
GOMAXPROCS = CPU 核数（默认值）




I/O 密集型任务
可适当增大 GOMAXPROCS




大量 Goroutine 竞争
使用 Worker Pool 限制并发




长时间运行的 Goroutine
添加 runtime.Gosched() 让出时间片




调试调度问题
GODEBUG=schedtrace=1000





package main

import (
	"fmt"
	"runtime"
	"sync"
)

func main() {
	runtime.GOMAXPROCS(2)

	var wg sync.WaitGroup
	for i := 0; i < 10; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			sum := 0
			for j := 0; j < 1e8; j++ {
				sum += j
			}
			fmt.Println("sum:", sum)
		}()
	}
	wg.Wait()
}
小结
Goroutine 是 Go 并发模型的基石，理解 GMP 调度器和常见并发模式对编写高性能 Go 程序至关重要。






知识点
核心要点





GMP 模型
G=协程, M=线程, P=处理器，Work Stealing 保证负载均衡




生命周期
创建→可运行→运行→阻塞→退出




泄漏防范
始终使用 context 控制退出，goleak 检测




Pipeline
多阶段处理，channel 连接各阶段




Fan-Out/Fan-In
分发+汇聚，提升吞吐量




Worker Pool
固定并发数，避免资源耗尽
