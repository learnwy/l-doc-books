Channels 通道

Channel 核心概念

Channel 是 Go 语言中 Goroutine 之间通信的核心机制，体现了 Go 的并发哲学："不要通过共享内存来通信，而要通过通信来共享内存。"

graph LR
    G1[Goroutine A] -->|发送数据| CH{Channel}
    CH -->|接收数据| G2[Goroutine B]

Channel 的底层是一个带锁的环形缓冲队列（有缓冲时），配合发送者和接收者的等待队列实现同步。

有缓冲 vs 无缓冲

graph TB
    subgraph "无缓冲 Channel"
        direction LR
        S1[发送者] -->|阻塞直到<br/>接收者就绪| U[ ]
        U -->|阻塞直到<br/>发送者就绪| R1[接收者]
    end
    subgraph "有缓冲 Channel (cap=3)"
        direction LR
        S2[发送者] --> B1[槽1]
        B1 --> B2[槽2]
        B2 --> B3[槽3]
        B3 --> R2[接收者]
    end
特性 无缓冲 make(chan T) 有缓冲 make(chan T, n)
同步语义 同步（发送=接收同时发生） 异步（缓冲区未满时不阻塞）
发送阻塞条件 没有接收者 缓冲区已满
接收阻塞条件 没有发送者 缓冲区为空
典型用途 信号同步、交接数据 生产者-消费者、流量控制
性能 每次通信需要调度切换 缓冲区内不需切换 
package main

import (
	"fmt"
	"time"
)

func main() {
	unbuffered := make(chan string)

	go func() {
		fmt.Println("发送前（无缓冲会阻塞）")
		unbuffered <- "hello"
		fmt.Println("发送后")
	}()

	time.Sleep(time.Second)
	fmt.Println("接收:", <-unbuffered)

	buffered := make(chan string, 2)
	buffered <- "A"
	buffered <- "B"
	fmt.Println("有缓冲：两次发送无需等待")
	fmt.Println(<-buffered)
	fmt.Println(<-buffered)
}

Channel 方向

Go 支持在函数签名中限制 channel 的方向，增强类型安全：

package main

import "fmt"

func producer(out chan<- int) {
	for i := 0; i < 5; i++ {
		out <- i
	}
	close(out)
}

func consumer(in <-chan int) {
	for val := range in {
		fmt.Printf("收到: %d\n", val)
	}
}

func main() {
	ch := make(chan int, 5)
	go producer(ch)
	consumer(ch)
}
声明方式 含义 允许的操作
chan T 双向 channel 发送、接收、关闭
chan<- T 只发送 channel 发送、关闭
<-chan T 只接收 channel 接收

方向转换规则：双向 → 单向（隐式转换），单向 → 双向（不允许）。

Channel 关闭语义

关闭 channel 是一个重要的信号机制，需要遵守严格的规则：

规则 说明
只能关闭一次 重复关闭引发 panic
只由发送方关闭 接收方关闭可能导致发送方 panic
关闭后不可发送 向已关闭 channel 发送引发 panic
关闭后可接收 返回剩余值，然后返回零值
nil channel 发送和接收永远阻塞 
package main

import "fmt"

func main() {
	ch := make(chan int, 5)
	for i := 1; i <= 5; i++ {
		ch <- i
	}
	close(ch)

	for val := range ch {
		fmt.Println(val)
	}

	val, ok := <-ch
	fmt.Printf("val=%d, ok=%v\n", val, ok)
}

安全关闭模式——使用 sync.Once：

package main

import (
	"fmt"
	"sync"
)

type SafeChannel struct {
	ch   chan int
	once sync.Once
}

func NewSafeChannel(size int) *SafeChannel {
	return &SafeChannel{ch: make(chan int, size)}
}

func (sc *SafeChannel) Close() {
	sc.once.Do(func() {
		close(sc.ch)
	})
}

func (sc *SafeChannel) Send(val int) (ok bool) {
	defer func() {
		if recover() != nil {
			ok = false
		}
	}()
	sc.ch <- val
	return true
}

func main() {
	sc := NewSafeChannel(10)
	sc.Send(1)
	sc.Send(2)
	sc.Close()
	sc.Close()
	fmt.Println("安全关闭，无 panic")
}

Select 多路复用

select 语句让一个 Goroutine 同时等待多个 channel 操作，类似于网络编程中的 epoll：

graph TB
    Select[select 语句] --> C1{case ch1}
    Select --> C2{case ch2}
    Select --> C3{case ch3}
    Select --> D{default}
    C1 -->|就绪| A1[执行分支1]
    C2 -->|就绪| A2[执行分支2]
    C3 -->|就绪| A3[执行分支3]
    D -->|全部未就绪| A4[执行默认分支]
package main

import (
	"fmt"
	"time"
)

func main() {
	ch1 := make(chan string)
	ch2 := make(chan string)

	go func() {
		time.Sleep(1 * time.Second)
		ch1 <- "来自 channel 1"
	}()

	go func() {
		time.Sleep(2 * time.Second)
		ch2 <- "来自 channel 2"
	}()

	for i := 0; i < 2; i++ {
		select {
		case msg := <-ch1:
			fmt.Println(msg)
		case msg := <-ch2:
			fmt.Println(msg)
		}
	}
}

超时控制

package main

import (
	"fmt"
	"time"
)

func queryDatabase() <-chan string {
	ch := make(chan string)
	go func() {
		time.Sleep(3 * time.Second)
		ch <- "查询结果"
	}()
	return ch
}

func main() {
	result := queryDatabase()

	select {
	case data := <-result:
		fmt.Println("成功:", data)
	case <-time.After(2 * time.Second):
		fmt.Println("超时：查询未在 2 秒内完成")
	}
}

非阻塞操作

package main

import "fmt"

func main() {
	ch := make(chan int, 1)

	select {
	case ch <- 42:
		fmt.Println("发送成功")
	default:
		fmt.Println("channel 已满，跳过")
	}

	select {
	case val := <-ch:
		fmt.Println("接收:", val)
	default:
		fmt.Println("channel 为空，跳过")
	}
}

Channel 常用模式

Done Channel（完成信号）

使用空结构体 channel 作为轻量级退出信号：

package main

import (
	"fmt"
	"time"
)

func worker(done <-chan struct{}, id int) {
	for {
		select {
		case <-done:
			fmt.Printf("worker %d: 退出\n", id)
			return
		default:
			fmt.Printf("worker %d: 工作中\n", id)
			time.Sleep(300 * time.Millisecond)
		}
	}
}

func main() {
	done := make(chan struct{})

	for i := 0; i < 3; i++ {
		go worker(done, i)
	}

	time.Sleep(1 * time.Second)
	close(done)
	time.Sleep(100 * time.Millisecond)
	fmt.Println("所有 worker 已退出")
}

Pipeline 模式

多阶段 channel 连接，每个阶段是独立的 Goroutine：

package main

import "fmt"

func generate(nums ...int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for _, n := range nums {
			out <- n
		}
	}()
	return out
}

func multiply(in <-chan int, factor int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for n := range in {
			out <- n * factor
		}
	}()
	return out
}

func offset(in <-chan int, delta int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for n := range in {
			out <- n + delta
		}
	}()
	return out
}

func main() {
	ch := generate(1, 2, 3, 4, 5)
	ch = multiply(ch, 3)
	ch = offset(ch, 10)

	for v := range ch {
		fmt.Println(v)
	}
}

Fan-Out 模式

将同一个 channel 的数据分发给多个消费者：

package main

import (
	"fmt"
	"sync"
)

func fanOut(in <-chan int, workers int) []<-chan int {
	outs := make([]<-chan int, workers)
	for i := 0; i < workers; i++ {
		out := make(chan int)
		outs[i] = out
		go func(id int) {
			defer close(out)
			for val := range in {
				fmt.Printf("worker %d 处理: %d\n", id, val)
				out <- val * val
			}
		}(i)
	}
	return outs
}

func fanIn(channels ...<-chan int) <-chan int {
	out := make(chan int)
	var wg sync.WaitGroup

	for _, ch := range channels {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for val := range ch {
				out <- val
			}
		}()
	}

	go func() {
		wg.Wait()
		close(out)
	}()

	return out
}

func main() {
	in := make(chan int, 10)
	go func() {
		defer close(in)
		for i := 1; i <= 10; i++ {
			in <- i
		}
	}()

	workers := fanOut(in, 3)
	results := fanIn(workers...)

	for r := range results {
		fmt.Println("结果:", r)
	}
}

Or-Channel（任一完成）

等待多个 channel 中任意一个返回信号：

package main

import (
	"fmt"
	"time"
)

func or(channels ...<-chan struct{}) <-chan struct{} {
	switch len(channels) {
	case 0:
		return nil
	case 1:
		return channels[0]
	}

	orDone := make(chan struct{})
	go func() {
		defer close(orDone)
		switch len(channels) {
		case 2:
			select {
			case <-channels[0]:
			case <-channels[1]:
			}
		default:
			select {
			case <-channels[0]:
			case <-channels[1]:
			case <-channels[2]:
			case <-or(append(channels[3:], orDone)...):
			}
		}
	}()
	return orDone
}

func after(d time.Duration) <-chan struct{} {
	ch := make(chan struct{})
	go func() {
		defer close(ch)
		time.Sleep(d)
	}()
	return ch
}

func main() {
	start := time.Now()
	<-or(
		after(2*time.Second),
		after(5*time.Second),
		after(1*time.Second),
		after(3*time.Second),
	)
	fmt.Printf("最快完成耗时: %v\n", time.Since(start))
}

Ticker 定时器

package main

import (
	"context"
	"fmt"
	"time"
)

func periodicTask(ctx context.Context, interval time.Duration) {
	ticker := time.NewTicker(interval)
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			fmt.Println("定时任务退出")
			return
		case t := <-ticker.C:
			fmt.Println("tick:", t.Format("15:04:05"))
		}
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
	defer cancel()

	periodicTask(ctx, 500*time.Millisecond)
}

最佳实践

实践 说明
由发送方关闭 永远不要在接收方关闭 channel
优先使用 struct{} 信号 channel 使用空结构体，零内存
避免 nil channel 向 nil channel 发送/接收永远阻塞
设置超时 永远不要无限等待，使用 select + time.After 或 context
限制缓冲区大小 过大的缓冲区掩盖同步问题
用 context 替代 done channel 标准库统一的取消机制
range 遍历 自动检测关闭，代码更简洁

常见陷阱

  • 对 nil channel 收发：向 nil channel 发送或接收会永久阻塞；在 select 中，nil channel 的分支永远不会就绪，可借此临时禁用某个分支。
  • 重复关闭或关闭后发送：close 只能调用一次，重复关闭、以及向已关闭 channel 发送都会 panic。
  • 关闭方错位：由接收方关闭 channel 时，仍持有发送权的 goroutine 一旦发送就会 panic，关闭责任必须归属唯一的发送方。
  • 无接收者时发送：向无缓冲 channel 发送且当时没有接收者，当前 goroutine 会一直阻塞；若发生在主 goroutine 即为死锁。
  • 忘记关闭导致泄漏：接收方用 for range ch 遍历却无人 close，该 goroutine 会永久阻塞在接收上。

小结

Channel 是 Go 并发编程的核心原语，掌握 channel 的各种模式是编写正确、高效并发程序的关键。

知识点 核心要点
有缓冲 vs 无缓冲 无缓冲=同步交换，有缓冲=异步队列
方向限制 chan<- 只发送，<-chan 只接收
关闭语义 只关一次、发送方关、关后可收
select 多路复用、超时控制、非阻塞操作
Done 模式 chan struct{} + close 广播退出
Pipeline 阶段串联，channel 传递数据
