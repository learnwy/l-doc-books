CLI 工具开发

核心概念

CLI 工具的核心诉求是可分发、可脚本化、可预测：Rust 编译为单一静态二进制、启动无运行时初始化、内存占用可预测，天然契合这三点。理解本篇的关键，是把一个 CLI 拆成四个职责——参数解析、交互输入、输出呈现、错误与退出码，它们各自有成熟的 crate，组合方式高度标准化。

graph LR
    A["命令行参数"] --> B["clap 解析"]
    B --> C["命令分发"]
    C --> D["业务逻辑"]
    D --> E["退出码 + 输出"]
  • 参数解析用声明式派生：clap 的 #[derive(Parser)] 把参数结构直接映射为类型，验证在编译期与解析期完成。
  • 交互与进度是体验层：dialoguer 处理选择与确认，indicatif 渲染进度，colored/console 负责终端样式。
  • 退出码是接口契约：脚本依赖退出码判断成败，因此错误路径必须显式 process::exit(1) 而非静默返回。

Rust 的 CLI 优势

Rust 天然适合构建 CLI 工具：编译为单一静态二进制、启动速度极快、内存占用低、交叉编译简单。

优势 说明
单文件分发 编译为无依赖的二进制，直接复制运行
极速启动 无运行时初始化，毫秒级启动
低资源占用 无 GC，内存占用可预测
交叉编译 一次编写，编译到多个平台
类型安全 参数解析、配置读取编译期检查

Clap：命令行参数解析

clap 是 Rust 最流行的命令行参数解析库，支持声明式的派生宏语法。

use clap::{Parser, Subcommand};

#[derive(Parser)]
#[command(name = "mytool")]
#[command(about = "一个示例 CLI 工具", version)]
struct Cli {
    #[arg(short, long, default_value = "info")]
    log_level: String,

    #[command(subcommand)]
    command: Commands,
}

#[derive(Subcommand)]
enum Commands {
    Init {
        #[arg(short, long)]
        name: String,
    },
    Build {
        #[arg(short, long)]
        release: bool,
    },
    Clean,
}

fn main() {
    let cli = Cli::parse();

    println!("日志级别: {}", cli.log_level);

    match cli.command {
        Commands::Init { name } => {
            println!("初始化项目: {}", name);
        }
        Commands::Build { release } => {
            println!("构建项目 (release={})", release);
        }
        Commands::Clean => {
            println!("清理构建产物");
        }
    }
}
$ mytool --log-level debug init --name my-project
日志级别: debug
初始化项目: my-project

$ mytool build --release
构建项目 (release=true)

参数类型与验证

use clap::Parser;
use std::path::PathBuf;

#[derive(Parser)]
struct Cli {
    #[arg(value_parser = clap::value_parser!(PathBuf))]
    input: PathBuf,

    #[arg(short, long, default_value_t = 8080)]
    port: u16,

    #[arg(short, long, value_delimiter = ',')]
    tags: Vec<String>,

    #[arg(long, env = "MY_TOKEN")]
    token: Option<String>,
}
特性 语法 说明
默认值 #[arg(default_value_t = 42)] 未提供时使用默认值
环境变量 #[arg(env = "VAR")] 从环境变量读取
多值 #[arg(value_delimiter = ',')] 逗号分隔的多值
必填 不加 Option 包装 未提供则报错
可选 Option<T> 可不提供
布尔开关 #[arg(long)] 搭配 bool --flag 为 true

交互式输入

dialoguer 提供交互式命令行输入组件。

use dialoguer::{Confirm, Input, Select, MultiSelect, theme::ColorfulTheme};

fn main() {
    let name: String = Input::with_theme(&ColorfulTheme::default())
        .with_prompt("项目名称")
        .default("my-project".into())
        .interact_text()
        .unwrap();

    let frameworks = vec!["Axum", "Actix", "Rocket"];
    let selection = Select::with_theme(&ColorfulTheme::default())
        .with_prompt("选择框架")
        .items(&frameworks)
        .default(0)
        .interact()
        .unwrap();

    let features = vec!["数据库", "认证", "日志", "CORS"];
    let selected = MultiSelect::with_theme(&ColorfulTheme::default())
        .with_prompt("选择功能")
        .items(&features)
        .interact()
        .unwrap();

    let confirm = Confirm::with_theme(&ColorfulTheme::default())
        .with_prompt("确认创建?")
        .default(true)
        .interact()
        .unwrap();

    if confirm {
        println!("创建项目: {}, 框架: {}", name, frameworks[selection]);
        println!("功能: {:?}", selected.iter().map(|&i| features[i]).collect::<Vec<_>>());
    }
}

进度条与输出美化

use indicatif::{ProgressBar, ProgressStyle, MultiProgress};
use std::time::Duration;

fn main() {
    let pb = ProgressBar::new(100);
    pb.set_style(
        ProgressStyle::default_bar()
            .template("{spinner:.green} [{bar:40.cyan/blue}] {pos}/{len} {msg}")
            .unwrap()
            .progress_chars("=>-"),
    );

    for i in 0..100 {
        pb.set_message(format!("处理项目 {}", i));
        pb.inc(1);
        std::thread::sleep(Duration::from_millis(30));
    }
    pb.finish_with_message("完成!");
}

错误处理与退出码

use anyhow::{Context, Result};
use std::process;

fn run() -> Result<()> {
    let config = std::fs::read_to_string("config.toml")
        .context("读取配置文件失败")?;

    println!("配置: {}", config);
    Ok(())
}

fn main() {
    if let Err(e) = run() {
        eprintln!("{}: {:#}", "错误".red(), e);
        process::exit(1);
    }
}

小结

  • Rust 编译为单一静态二进制、启动快、占用低，是构建 CLI 工具的天然选择。
  • clap 的声明式派生宏把参数定义映射为类型，默认值、环境变量、多值与必填校验都在解析期完成。
  • dialoguer 与 indicatif 分别负责交互式输入与进度呈现，colored/console 用于输出美化。
  • 错误应携带上下文（anyhow）并映射为明确的退出码，因为退出码是脚本依赖的接口契约。
  • 分发方式可按受众选择：cargo install 面向开发者，GitHub Releases 与 Homebrew 面向终端用户。
