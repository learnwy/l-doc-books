WebAssembly 与 Rust

Rust 与 WebAssembly

Rust 是编译到 WebAssembly（Wasm）的最佳语言之一。没有垃圾回收、可控的内存管理、编译后体积小，使 Rust 在 Wasm 场景中具有显著优势。

特性 Rust + Wasm JavaScript
执行速度 接近原生 JIT 优化后较快
包体积 很小（可到 KB 级） 取决于框架
内存管理 确定性释放 垃圾回收
类型安全 编译期保证 运行时动态
适用场景 计算密集、图形、解码 DOM 操作、UI 交互

Wasm 的核心优势在于"一次编译，到处运行"的可移植性。Rust 编译生成的 .wasm 二进制可在浏览器、Node.js、Deno、边缘计算节点（Cloudflare Workers、Fastly Compute）甚至嵌入式系统中执行，无需修改代码。

工具链设置

# 安装 wasm 目标
rustup target add wasm32-unknown-unknown

# 安装 wasm-pack
cargo install wasm-pack

# 安装 wasm-bindgen CLI（可选）
cargo install wasm-bindgen-cli

wasm-bindgen：Rust 与 JS 互操作

wasm-bindgen 是 Rust 和 JavaScript 之间互操作的核心桥梁。它自动生成胶水代码，处理 Rust 和 JS 之间的类型转换——包括字符串的 UTF-8/UTF-16 转换、结构体到 JS 对象的映射、以及错误传播。

use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn greet(name: &str) -> String {
    format!("你好, {}! 来自 Rust Wasm", name)
}

#[wasm_bindgen]
pub struct Calculator {
    value: f64,
}

#[wasm_bindgen]
impl Calculator {
    #[wasm_bindgen(constructor)]
    pub fn new() -> Calculator {
        Calculator { value: 0.0 }
    }

    pub fn add(&mut self, n: f64) {
        self.value += n;
    }

    pub fn result(&self) -> f64 {
        self.value
    }
}

JavaScript 端使用：

import init, { greet, Calculator } from './pkg/my_wasm.js';

async function main() {
  await init();
  console.log(greet('World'));

  const calc = new Calculator();
  calc.add(10);
  calc.add(20);
  console.log(`结果: ${calc.result()}`);
}
main();

需要注意的是，Wasm 和 JS 之间的数据传递涉及线性内存拷贝。对于大量数据（如图像像素、音频采样），应尽量在 Wasm 侧完成处理后再传回 JS，避免频繁的跨边界数据拷贝成为瓶颈。

调用 Web API
通过 web-sys 和 js-sys 调用浏览器 API。


use wasm_bindgen::prelude::*;
use web_sys::{Document, Element, HtmlElement};

#[wasm_bindgen(start)]
pub fn main() -> Result<(), JsValue> {
    let window = web_sys::window().unwrap();
    let document = window.document().unwrap();
    let body = document.body().unwrap();

    let div = document.create_element("div")?;
    div.set_text_content(Some("Hello from Rust!"));
    div.set_attribute("style", "color: blue; font-size: 24px;")?;

    body.append_child(&div)?;
    Ok(())
}
# Cargo.toml
[dependencies]
wasm-bindgen = "0.2"
web-sys = { version = "0.3", features = ["Document", "Element", "HtmlElement", "Window"] }
js-sys = "0.3"
web-sys 通过 cargo feature flags 按需启用 Web API 绑定，未启用的 API 不会增加编译产物体积。这种设计让开发者可以精确控制依赖的 API 范围，同时享受完整的类型安全。




WASI：服务端 Wasm
WASI（WebAssembly System Interface）将 Wasm 扩展到服务端和边缘计算场景。


# 安装 WASI 目标
rustup target add wasm32-wasip1

# 编译 WASI 程序
cargo build --target wasm32-wasip1 --release

# 使用 wasmtime 运行
wasmtime target/wasm32-wasip1/release/my_app.wasm

WASI 的沙箱安全模型基于 capability-based security：程序默认无法访问任何文件系统或网络资源，必须由运行时显式授予目录访问权限（--dir 参数）。这使得 Wasm 模块天然适合作为插件系统的执行沙箱——宿主程序精确控制插件的权限边界。
