所有权规则与移动语义

所有权三大规则

Rust 的所有权系统基于三条核心规则，编译器在编译期严格执行这些规则以保证内存安全。

规则 说明 编译器行为
每个值有且只有一个所有者 任何时刻，一个值只能被一个变量拥有 违反时产生编译错误
所有者离开作用域时值被释放 作用域结束自动调用 drop 类似 C++ 的 RAII
赋值默认执行移动（Move） 所有权转移后原变量失效 使用已移动变量报错

所有权系统是 Rust 区别于其他系统编程语言的核心特性。C/C++ 依赖程序员手动管理内存，容易产生悬垂指针和双重释放；Go/Java 使用垃圾回收器，运行时有 GC 暂停开销。Rust 通过所有权在编译期静态检查内存安全，零运行时开销。

Move 语义

在 Rust 中，赋值和函数传参默认执行"移动"操作——所有权从一个变量转移到另一个变量，原变量不再可用。

fn main() {
    let s1 = String::from("hello");
    let s2 = s1; // s1 的所有权移动到 s2

    // println!("{}", s1); // 编译错误：value borrowed here after move
    println!("{}", s2); // 正常输出 "hello"
}

函数传参同样触发移动：

fn take_ownership(s: String) {
    println!("获得所有权: {}", s);
} // s 在此处被 drop

fn main() {
    let name = String::from("Rust");
    take_ownership(name);
    // println!("{}", name); // 编译错误：name 已被移动
}
Move 语义在底层实现上是栈上数据（指针、长度、容量三元组）的按位拷贝，堆上的数据没有被复制。编译器随后将源变量标记为无效，阻止任何后续访问。这种设计既避免了深拷贝的性能开销，又防止了两个变量同时指向同一块堆内存导致的双重释放问题。

    let x = 42;
    let y = x; // 按位复制，x 仍然有效

    let s = String::from("hello");
    let t = s; // 移动，s 不再有效
    // println!("{}", s); // 编译错误

为自定义类型派生 Copy：


#[derive(Debug, Clone, Copy)]
struct Point {
    x: f64,
    y: f64,
}

fn main() {
    let p1 = Point { x: 1.0, y: 2.0 };
    let p2 = p1; // Copy，p1 仍然有效
    println!("{:?} {:?}", p1, p2);
}


注意：实现 Copy 的前提是类型必须同时实现 Clone，且类型中所有字段都是 Copy 的。包含 String、Vec 等堆分配字段的结构体无法实现 Copy。






Clone 显式深拷贝
对于不可 Copy 的类型，可以调用 .clone() 进行显式的深拷贝。


fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone(); // 堆上数据也被复制
    println!("s1 = {}, s2 = {}", s1, s2); // 两者均有效
}
.clone() 会分配新的堆内存并复制全部数据，因此有明确的性能成本。Rust 通过要求显式调用 .clone() 让开发者意识到这一开销——不同于 C++ 中隐式触发的拷贝构造函数，Rust 的每次深拷贝都在代码中清晰可见。在性能敏感路径上，频繁出现的 .clone() 通常是值得优化的信号。




Drop 与资源释放
当所有者离开作用域时，Rust 自动调用 Drop trait 的 drop 方法释放资源。


struct DatabaseConn {
    url: String,
}

impl Drop for DatabaseConn {
    fn drop(&mut self) {
        println!("关闭数据库连接: {}", self.url);
    }
}

fn main() {
    let conn = DatabaseConn {
        url: String::from("postgres://localhost/mydb"),
    };
    println!("使用连接...");
} // conn 在此处自动调用 drop
关键约束：一个类型不能同时实现 Copy 和 Drop，因为 Copy 意味着按位复制后两份数据都有效，而 Drop 会导致同一资源被释放两次。


Drop 的调用顺序遵循 LIFO（后进先出）规则：在同一作用域内，变量按声明的逆序被 drop。对于结构体，字段按声明顺序被 drop。如果需要提前释放资源（而不是等到作用域结束），可以使用 std::mem::drop() 函数显式触发。




所有权与函数返回值
函数可以通过返回值将所有权转移给调用者：


fn create_greeting(name: &str) -> String {
    format!("你好, {}!", name)
}

fn main() {
    let greeting = create_greeting("Rust"); // 所有权从函数内部转移到 greeting
    println!("{}", greeting);
}
