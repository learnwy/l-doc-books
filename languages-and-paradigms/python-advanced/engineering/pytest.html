测试框架 pytest

概述

pytest 是 Python 最流行的测试框架。相比标准库 unittest，pytest 语法更简洁、功能更强大——fixture 依赖注入、参数化测试、丰富的插件生态，让编写和维护测试变得高效。

基本用法

def add(a: int, b: int) -> int:
    return a + b

def test_add():
    assert add(1, 2) == 3
    assert add(-1, 1) == 0
    assert add(0, 0) == 0
pytest tests/ -v
pytest tests/test_core.py::test_add
pytest -x  # 遇到第一个失败即停止
pytest -k "test_add or test_sub"

pytest 最大的优势之一是使用原生 assert 语句而非 self.assertEqual() 等方法。当 assert 失败时，pytest 通过 AST 重写技术自动展开表达式的中间值，例如 assert a + b == 5 失败时会显示 a=2, b=1，无需手动编写错误消息。

Fixture 依赖注入

import pytest

@pytest.fixture
def sample_users():
    return [
        {"name": "Alice", "age": 30},
        {"name": "Bob", "age": 25},
    ]

@pytest.fixture
def db_connection():
    conn = create_connection()
    yield conn
    conn.close()

def test_user_count(sample_users):
    assert len(sample_users) == 2

def test_query(db_connection):
    result = db_connection.execute("SELECT 1")
    assert result is not None

Fixture 作用域

作用域 参数 生命周期
function scope="function" 每个测试函数
class scope="class" 每个测试类
module scope="module" 每个测试模块
session scope="session" 整个测试会话

Fixture 的 yield 语法是资源管理的关键模式——yield 之前的代码是 setup，之后的代码是 teardown。这比 unittest 的 setUp/tearDown 更加直观，并且 fixture 之间可以自由组合。例如一个 db_connection fixture 可以被 db_session fixture 使用，实现层级化的资源管理。

参数化测试

import pytest

@pytest.mark.parametrize("input,expected", [
    (1, 1),
    (2, 4),
    (3, 9),
    (-1, 1),
    (0, 0),
])
def test_square(input, expected):
    assert input ** 2 == expected

@pytest.mark.parametrize("x", [1, 2, 3])
@pytest.mark.parametrize("y", [10, 20])
def test_multiply(x, y):
    assert x * y > 0

多个 @parametrize 装饰器叠加时会产生笛卡尔积——上面的 test_multiply 会生成 6 个测试用例（3 x 2）。这种方式在测试矩阵组合（如不同数据库引擎 × 不同操作类型）时非常高效。

异常与警告测试

import pytest

def divide(a: int, b: int) -> float:
    if b == 0:
        raise ValueError("Cannot divide by zero")
    return a / b

def test_divide_by_zero():
    with pytest.raises(ValueError, match="Cannot divide by zero"):
        divide(1, 0)

def test_deprecation_warning():
    with pytest.warns(DeprecationWarning):
        old_function()

Mock 与 monkeypatch

from unittest.mock import patch, MagicMock

def test_api_call():
    with patch("myproject.client.httpx.get") as mock_get:
        mock_get.return_value = MagicMock(status_code=200, json=lambda: {"ok": True})
        result = fetch_data("https://api.com")
        assert result["ok"] is True
        mock_get.assert_called_once()

def test_env_var(monkeypatch):
    monkeypatch.setenv("API_KEY", "test-key-123")
    config = load_config()
    assert config.api_key == "test-key-123"
工具 用途 特点
unittest.mock 替换对象和方法 标准库，功能全面
monkeypatch 修改环境变量/属性 pytest 内置
responses Mock HTTP 请求 requests 专用
respx Mock HTTP 请求 httpx 专用

测试覆盖率

pip install pytest-cov
pytest --cov=src --cov-report=html --cov-report=term-missing
[tool.coverage.run]
source = ["src"]
omit = ["*/tests/*"]

[tool.coverage.report]
fail_under = 80
show_missing = true

覆盖率报告中的 term-missing 选项会在终端直接显示未覆盖的行号，方便快速定位需要补充测试的代码路径。html 报告则提供可视化的源码标注视图，适合深入分析覆盖情况。建议同时使用 branch coverage（--cov-branch）来检测条件分支的覆盖完整性。

最佳实践
    

  • 测试文件与源码目录结构镜像：src/core.py → tests/test_core.py
    • 

  • 使用 fixture 替代测试中的重复 setup 代码
    • 

  • 参数化测试覆盖边界条件：空值、负数、超大输入
    • 

  • 设置覆盖率门禁（如 80%），在 CI 中强制执行

  • 使用 pytest-xdist 并行执行加速大型测试套件
