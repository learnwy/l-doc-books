项目结构与包管理

概述

现代 Python 项目以 pyproject.toml 为核心配置文件，以虚拟环境隔离依赖，以 uv/pip 管理包。合理的项目结构和包管理实践是团队协作和 CI/CD 的基础。

标准项目结构

my-project/
├── pyproject.toml
├── README.md
├── LICENSE
├── src/
│   └── my_project/
│       ├── __init__.py
│       ├── core.py
│       └── utils.py
├── tests/
│   ├── __init__.py
│   ├── test_core.py
│   └── test_utils.py
├── docs/
└── scripts/

src layout vs flat layout

布局 目录结构 优势
src layout src/my_project/ 避免意外导入本地未安装的包
flat layout my_project/ 简单直接，小项目适用

src layout 的核心优势是强制开发者通过 pip install -e . 安装包后再使用，避免"在项目根目录下运行测试时意外导入了本地源码而非安装后的包"的问题。这个差异在有 C 扩展的项目中尤为关键——flat layout 可能导致测试运行的是纯 Python 版本而非编译后的版本。对于库（发布到 PyPI 的包），强烈推荐 src layout。

pyproject.toml

[project]
name = "my-project"
version = "0.1.0"
description = "A sample Python project"
requires-python = ">=3.11"
dependencies = [
    "httpx>=0.27",
    "pydantic>=2.0",
]

[project.optional-dependencies]
dev = [
    "pytest>=8.0",
    "ruff>=0.4",
    "mypy>=1.10",
]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.ruff]
line-length = 100
target-version = "py311"

[tool.ruff.lint]
select = ["E", "F", "I", "N", "UP"]

[tool.mypy]
strict = true

[tool.pytest.ini_options]
testpaths = ["tests"]

pyproject.toml 统一了项目元数据、构建配置和工具配置。在此之前，Python 项目需要维护 setup.py、setup.cfg、requirements.txt、MANIFEST.in 等多个文件，配置分散且容易不一致。PEP 621 标准化了 [project] 表的字段定义，使得不同构建后端可以读取相同的元数据。

构建后端对比

后端 特点 适用场景
hatchling 快速、配置简洁 纯 Python 项目
setuptools 最广泛支持 传统项目迁移
flit 极简 简单库
maturin Rust 扩展支持 Python + Rust

虚拟环境

python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

包管理工具对比

工具 速度 锁文件 特点
pip 中等 无 标准工具
uv 极快 uv.lock Rust 实现，pip 兼容
poetry 中等 poetry.lock 一体化管理
pdm 快 pdm.lock PEP 标准优先

uv 使用

pip install uv
uv venv
uv pip install -e ".[dev]"
uv pip compile requirements.in -o requirements.txt

uv 是 Astral（ruff 的开发公司）推出的 Python 包管理器，用 Rust 编写，解析和安装速度比 pip 快 10-100 倍。它完全兼容 pip 的命令行接口，支持 requirements.txt 和 pyproject.toml，可以直接替换 pip 使用。

Linting 与格式化

Ruff：全能 linter

ruff check src/ --fix
ruff format src/

Ruff 使用 Rust 编写，速度是 flake8 的 10-100 倍，可以替代 flake8 + isort + pyupgrade + autoflake。

工具链速查

工具 用途 替代对象
ruff Linting + 格式化 flake8 + black + isort
mypy 类型检查 —
pyright 类型检查 mypy（更快）
pre-commit Git 钩子 手动运行 lint

pre-commit 配置

repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.4.0
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
  - repo: https://github.com/pre-commit/mirrors-mypy
    rev: v1.10.0
    hooks:
      - id: mypy
pip install pre-commit
pre-commit install
pre-commit run --all-files

CI/CD 集成

name: CI
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - run: pip install uv && uv pip install -e ".[dev]"
      - run: ruff check src/
      - run: mypy src/
      - run: pytest --cov

最佳实践

  • 始终使用 pyproject.toml 作为项目配置的单一来源
  • 使用 src layout 避免开发时意外导入未安装的包
  • 锁定依赖版本（uv.lock / requirements.txt）确保可复现构建
  • 在 CI 中运行 ruff + mypy + pytest 三重质量门禁
  • 使用 pre-commit 在提交前自动检查代码质量
  • 区分 dependencies（运行时）和 optional-dependencies（开发时），保持生产依赖精简
