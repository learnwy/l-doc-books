运行时类型检查与 Pydantic

概述

Python 的标准类型标注在运行时不会被强制执行——它们仅是"提示"。然而在 API 输入校验、配置解析、数据序列化等场景中，运行时类型验证不可或缺。Pydantic 是 Python 生态中最流行的运行时验证库，以类型标注为基础，提供高性能数据解析与校验能力。

运行时验证的必要性

场景 风险 验证手段
REST API 输入 用户提交非法数据 Pydantic / marshmallow
配置文件解析 YAML/JSON 字段缺失或类型错误 Pydantic Settings
外部数据集成 第三方系统返回脏数据 模型校验 + 异常捕获
CLI 参数 用户输入格式错误 typer + 类型验证

Pydantic V2 核心用法

BaseModel 定义

from pydantic import BaseModel, Field
from datetime import datetime

class User(BaseModel):
    name: str = Field(min_length=1, max_length=50)
    age: int = Field(ge=0, le=150)
    email: str
    created_at: datetime = Field(default_factory=datetime.now)

user = User(name="Alice", age=30, email="alice@example.com")
print(user.model_dump())

自动类型转换

Pydantic 默认开启"宽松模式"（lax mode），会尝试将输入数据转换为目标类型：

user = User(name="Bob", age="25", email="bob@test.com")
print(user.age)        # 25（int，从 str 自动转换）
print(type(user.age))  # <class 'int'>

校验器（Validator）

字段校验器

from pydantic import BaseModel, field_validator

class Product(BaseModel):
    name: str
    price: float
    sku: str

    @field_validator("sku")
    @classmethod
    def validate_sku(cls, v: str) -> str:
        if not v.startswith("SKU-"):
            raise ValueError("SKU must start with 'SKU-'")
        return v.upper()

模型校验器

from pydantic import BaseModel, model_validator

class DateRange(BaseModel):
    start: datetime
    end: datetime

    @model_validator(mode="after")
    def check_order(self) -> "DateRange":
        if self.start >= self.end:
            raise ValueError("start must be before end")
        return self

校验器类型对比

校验器类型 装饰器 作用范围 执行时机
字段校验（前） field_validator 单个字段 类型转换前
字段校验（后） field_validator 单个字段 类型转换后
模型校验（前） model_validator 整个模型 字段校验前
模型校验（后） model_validator 整个模型 字段校验后

序列化与反序列化

user = User(name="Alice", age=30, email="a@b.com")

json_str = user.model_dump_json()
user_dict = user.model_dump(exclude={"created_at"})

user2 = User.model_validate_json(json_str)
user3 = User.model_validate({"name": "Bob", "age": 25, "email": "b@c.com"})
方法 方向 输入 输出
model_dump() 模型 → 字典 Model dict
model_dump_json() 模型 → JSON Model str
model_validate() 字典 → 模型 dict Model
model_validate_json() JSON → 模型 str Model

Pydantic Settings

from pydantic_settings import BaseSettings

class AppConfig(BaseSettings):
    database_url: str
    redis_host: str = "localhost"
    debug: bool = False

    model_config = {"env_prefix": "APP_"}

config = AppConfig()

运行时从环境变量 APP_DATABASE_URL、APP_REDIS_HOST 等自动读取并校验。

其他运行时验证方案

工具 特点 性能 适用场景
Pydantic V2 Rust 内核、功能全面 ⭐⭐⭐⭐⭐ API / 配置 / ORM
attrs + cattrs 轻量、与 attrs 生态集成 ⭐⭐⭐⭐ 内部数据结构
beartype 零开销装饰器式检查 ⭐⭐⭐⭐⭐ 函数入参快速守卫
typeguard 运行时全面检查 ⭐⭐⭐ 调试和测试环境
msgspec 极致性能的序列化 + 校验 ⭐⭐⭐⭐⭐ 高吞吐 JSON 处理 


最佳实践
    

  • 在系统边界（API 入口、外部数据源）使用 Pydantic 做验证，内部逻辑依赖静态检查
    • 

  • 优先使用 Pydantic V2 的 model_config 替代 V1 的 class Config
    • 

  • 对性能敏感的热路径考虑 msgspec 或 beartype
    • 

  • 将 Pydantic 模型作为 DTO（数据传输对象），与领域模型分离
    • 

  • 使用 model_json_schema() 自动生成 JSON Schema 用于文档和前端校验
