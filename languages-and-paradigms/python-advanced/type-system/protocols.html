Protocol 与结构化子类型

概述

Python 的鸭子类型哲学——"如果它走路像鸭子、叫声像鸭子，那它就是鸭子"——在 PEP 544 中获得了正式的静态类型支持。Protocol 类定义了一组方法或属性签名，任何实现了这些签名的类都自动满足该协议，无需显式继承。这种机制称为结构化子类型（Structural Subtyping）。

名义子类型 vs 结构化子类型

维度 名义子类型（Nominal） 结构化子类型（Structural）
判断依据 显式继承关系 方法和属性签名匹配
典型语言 Java、C# Go（interface）、TypeScript
Python ABC / 普通继承 Protocol
优势 类型关系明确 灵活、无耦合
劣势 需要修改被适配类 类型错误信息可能不直观

定义与使用 Protocol

基本定义

from typing import Protocol, runtime_checkable

class Drawable(Protocol):
    def draw(self, x: int, y: int) -> None: ...

class Circle:
    def draw(self, x: int, y: int) -> None:
        print(f"Circle at ({x}, {y})")

class Square:
    def draw(self, x: int, y: int) -> None:
        print(f"Square at ({x}, {y})")

def render(shape: Drawable) -> None:
    shape.draw(10, 20)

render(Circle())
render(Square())

Circle 和 Square 无需继承 Drawable，只要实现了 draw 方法即可。

属性协议

class Sized(Protocol):
    @property
    def size(self) -> int: ...

class MyList:
    @property
    def size(self) -> int:
        return 42

def check(obj: Sized) -> int:
    return obj.size

runtime_checkable

默认情况下，Protocol 仅供静态检查使用。添加 @runtime_checkable 装饰器后，可在运行时用 isinstance 检查。

@runtime_checkable
class Closeable(Protocol):
    def close(self) -> None: ...

class Connection:
    def close(self) -> None:
        print("closed")

print(isinstance(Connection(), Closeable))  # True

运行时检查的局限

能力 支持 说明
检查方法是否存在 ✅ 基于 hasattr
检查方法签名 ❌ 不验证参数类型和返回值
检查属性类型 ❌ 仅检查属性名是否存在
检查泛型参数 ❌ 泛型在运行时被擦除

内置协议模式

Python 标准库的许多"魔法方法"本质上就是隐式协议：

协议 魔法方法 typing 中的 Protocol
可迭代 __iter__, __next__ Iterable, Iterator
可哈希 __hash__, __eq__ Hashable
上下文管理 __enter__, __exit__ contextlib.AbstractContextManager
可比较 __lt__, __le__ 等 SupportsLessThan（自定义）
可调用 __call__ Callable

自定义复合协议

from typing import Protocol, Iterator

class Repository(Protocol):
    def get(self, id: str) -> dict: ...
    def save(self, entity: dict) -> None: ...
    def list_all(self) -> Iterator[dict]: ...

泛型 Protocol
from typing import Protocol, TypeVar

T = TypeVar("T")

class Comparable(Protocol):
    def __lt__(self, other: "Comparable") -> bool: ...

class Stack(Protocol[T]):
    def push(self, item: T) -> None: ...
    def pop(self) -> T: ...
    def peek(self) -> T: ...
泛型 Protocol 可以参数化协议中的类型，使其适用于多种数据类型的容器或算法。




最佳实践
    

  • 优先使用 Protocol 而非 ABC 来定义接口，除非需要共享默认实现
    • 

  • 为 Protocol 起描述行为的名称（如 Drawable、Serializable）而非名词
    • 

  • 保持 Protocol 精简——每个协议只描述一组紧密相关的方法
    • 

  • 谨慎使用 @runtime_checkable，它无法验证方法签名的正确性
    • 

  • 在团队项目中将核心 Protocol 集中定义在 protocols.py 或 interfaces.py 中
    •
