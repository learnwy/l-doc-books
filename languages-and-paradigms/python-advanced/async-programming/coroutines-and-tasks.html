协程与任务调度

概述

协程（Coroutine）是 Python 异步编程的基本执行单元。通过 async def 定义、await 挂起，协程在事件循环中被包装为 Task 进行调度。理解协程的生命周期、Task 的创建与取消，是构建可靠异步系统的关键。

创建与运行 Task
import asyncio

async def fetch_data(url: str) -> str:
    print(f"Fetching {url}...")
    await asyncio.sleep(1)
    return f"Data from {url}"

async def main():
    task1 = asyncio.create_task(fetch_data("https://api.example.com/a"))
    task2 = asyncio.create_task(fetch_data("https://api.example.com/b"))

    result1 = await task1
    result2 = await task2
    print(result1, result2)

asyncio.run(main())

取消与超时
任务取消
async def long_running():
    try:
        await asyncio.sleep(3600)
    except asyncio.CancelledError:
        print("Task was cancelled, cleaning up...")
        raise

async def main():
    task = asyncio.create_task(long_running())
    await asyncio.sleep(1)
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("Confirmed: task cancelled")
超时控制
async def main():
    try:
        async with asyncio.timeout(5):
            result = await fetch_data("https://slow-api.com")
    except TimeoutError:
        print("Request timed out!")

    result = await asyncio.wait_for(fetch_data("https://api.com"), timeout=3.0)

Future 对象
Future 是 Task 的基类，表示一个尚未完成的异步操作结果：


async def main():
    loop = asyncio.get_running_loop()
    future = loop.create_future()

    async def set_result():
        await asyncio.sleep(1)
        future.set_result("Done!")

    asyncio.create_task(set_result())
    result = await future
    print(result)

异步生成器
async def countdown(n: int):
    while n > 0:
        yield n
        await asyncio.sleep(0.5)
        n -= 1

async def main():
    async for num in countdown(5):
        print(num)
异步生成器结合了生成器的惰性产出和协程的异步等待，适用于分页查询、流式数据等场景。




任务命名与内省
async def worker(task_id: int):
    await asyncio.sleep(1)

async def main():
    tasks = [
        asyncio.create_task(worker(i), name=f"worker-{i}")
        for i in range(5)
    ]
    for task in asyncio.all_tasks():
        print(task.get_name())
    await asyncio.gather(*tasks)


最佳实践
    

  • 总是 await 或 gather 创建的 Task，避免"发射并忘记"导致异常被静默吞掉
    • 

  • 在 CancelledError 处理中执行清理逻辑后重新 raise，保持取消传播
    • 

  • 为 Task 设置有意义的名称，便于调试和日志追踪
    • 

  • 使用 asyncio.timeout() 替代 wait_for 获得更清晰的超时语义
    • 

  • 避免创建大量无限制的并发 Task，使用信号量或 TaskGroup 控制并发度
