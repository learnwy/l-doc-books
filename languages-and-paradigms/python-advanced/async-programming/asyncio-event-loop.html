asyncio 事件循环

概述

事件循环（Event Loop）是 asyncio 的核心引擎。它持续监听 I/O 事件和定时器回调，将就绪的协程恢复执行。理解事件循环的运行机制，是掌握 Python 异步编程的基础。

事件循环运行原理

事件循环的每一轮迭代（tick）执行以下步骤：






步骤
操作
说明





1
执行所有就绪回调
包括 call_soon 注册的回调




2
轮询 I/O 事件
使用 epoll（Linux）或 kqueue（macOS）




3
处理到期的定时器回调
call_later / call_at 注册的




4
回到步骤 1
持续循环直到没有任务





事件循环本质上是一个协作式调度器。与操作系统的抢占式线程调度不同，asyncio 中的协程只有在遇到 await 表达式时才会主动让出控制权。这意味着如果一个协程执行了长时间的 CPU 计算而没有 await，整个事件循环会被阻塞，其他协程得不到执行机会。




启动与获取事件循环
推荐方式（Python 3.7+）
import asyncio

async def main():
    print("Hello, asyncio!")
    await asyncio.sleep(1)
    print("Done!")

asyncio.run(main())
asyncio.run() 内部创建新的事件循环、运行协程、并在结束时关闭循环。它还会取消所有未完成的任务并等待它们处理 CancelledError，确保资源正确释放。


底层 API
import asyncio

loop = asyncio.new_event_loop()
try:
    loop.run_until_complete(main())
finally:
    loop.close()

回调式 API
事件循环提供低层级的回调注册接口，是协程机制的底层基础：


import asyncio

def callback(name: str):
    print(f"Hello, {name}!")

async def main():
    loop = asyncio.get_running_loop()
    loop.call_soon(callback, "Alice")
    loop.call_later(1.0, callback, "Bob")
    await asyncio.sleep(2)

asyncio.run(main())




方法
执行时机
参数





call_soon()
本轮迭代结束后立即
callback, *args




call_later()
指定秒数后
delay, callback, *args




call_at()
指定时间戳
when, callback, *args





call_soon_threadsafe() 是 call_soon() 的线程安全版本，专门用于从其他线程向事件循环提交回调。在多线程与异步混合的架构中，这是跨线程通信的标准方式。




自定义事件循环
Python 支持替换默认事件循环实现。uvloop 是基于 libuv 的高性能替代品：


import asyncio
import uvloop

asyncio.set_event_loop_policy(uvloop.EventLoopPolicy())
asyncio.run(main())

uvloop 的性能优势来自于 libuv 对系统调用的优化和更高效的内存管理。在 HTTP 服务器基准测试中，uvloop 通常能将吞吐量提升 2-4 倍。需要注意的是 uvloop 不支持 Windows，Windows 平台可选 winloop 或 Python 3.12+ 默认的 IOCP 实现。




调试模式
asyncio.run(main(), debug=True)
开启调试模式后，事件循环会：


    

  • 检测未被 await 的协程并发出警告
    • 

  • 检测执行时间过长的回调（默认阈值 100ms）
    • 

  • 记录所有异常的完整堆栈
    • 

  • 检测未关闭的资源（如 transport）
    • 





信号处理
import asyncio
import signal

async def main():
    loop = asyncio.get_running_loop()
    stop = loop.create_future()
    loop.add_signal_handler(signal.SIGTERM, stop.set_result, None)
    print("Waiting for SIGTERM...")
    await stop
    print("Received SIGTERM, shutting down.")

asyncio.run(main())


最佳实践
    

  • 始终使用 asyncio.run() 作为程序入口，避免手动管理事件循环
    • 

  • 生产环境使用 uvloop 提升吞吐量
    • 

  • 开发阶段开启 debug=True 捕获常见异步错误
    • 

  • 不要在协程中执行阻塞操作，使用 loop.run_in_executor() 将其放到线程池
    • 

  • 使用 asyncio.get_running_loop() 替代已弃用的 asyncio.get_event_loop()
    • 

  • CPU 密集计算使用 ProcessPoolExecutor 配合 run_in_executor 避免阻塞事件循环
