并发模式与最佳实践

概述

在异步编程中，并发控制决定了系统的吞吐量和稳定性。Python asyncio 提供了从简单的 gather 到结构化的 TaskGroup 等多种并发原语，适用于不同复杂度的场景。本文系统介绍主流并发模式及其在生产环境中的最佳实践。

asyncio.gather

最常用的并发执行方式，将多个协程并行运行并收集结果：

import asyncio

async def fetch(url: str) -> str:
    await asyncio.sleep(1)
    return f"Result from {url}"

async def main():
    results = await asyncio.gather(
        fetch("https://api.a.com"),
        fetch("https://api.b.com"),
        fetch("https://api.c.com"),
        return_exceptions=True,
    )
    for r in results:
        if isinstance(r, Exception):
            print(f"Error: {r}")
        else:
            print(r)
参数 说明
*coros 可变数量的协程或 Task
return_exceptions True 时异常作为结果返回而非抛出

TaskGroup（Python 3.11+）

结构化并发的核心原语，确保所有子任务在退出上下文管理器前完成或取消：

async def main():
    async with asyncio.TaskGroup() as tg:
        task1 = tg.create_task(fetch("https://api.a.com"))
        task2 = tg.create_task(fetch("https://api.b.com"))

    print(task1.result(), task2.result())

gather vs TaskGroup

特性 gather TaskGroup
Python 版本 3.4+ 3.11+
异常处理 可选收集或抛出 任一失败则全部取消
生命周期管理 无自动取消 自动取消剩余任务
动态添加任务 不支持（预先传入） 上下文内可继续创建
推荐度 兼容场景 新项目首选

信号量控制并发度

async def rate_limited_fetch(sem: asyncio.Semaphore, url: str) -> str:
    async with sem:
        return await fetch(url)

async def main():
    sem = asyncio.Semaphore(10)
    urls = [f"https://api.com/item/{i}" for i in range(100)]
    tasks = [rate_limited_fetch(sem, url) for url in urls]
    results = await asyncio.gather(*tasks)


生产者-消费者模式
async def producer(queue: asyncio.Queue[str]):
    for i in range(20):
        await queue.put(f"item-{i}")
        await asyncio.sleep(0.1)
    await queue.put(None)

async def consumer(queue: asyncio.Queue[str], name: str):
    while True:
        item = await queue.get()
        if item is None:
            queue.task_done()
            await queue.put(None)
            break
        print(f"{name} processing {item}")
        await asyncio.sleep(0.3)
        queue.task_done()

async def main():
    queue: asyncio.Queue[str] = asyncio.Queue(maxsize=5)
    async with asyncio.TaskGroup() as tg:
        tg.create_task(producer(queue))
        for i in range(3):
            tg.create_task(consumer(queue, f"consumer-{i}"))

import anyio

async def fetch_with_anyio(url: str) -> str:
    await anyio.sleep(1)

async def main():
    async with anyio.create_task_group() as tg:
        tg.start_soon(fetch_with_anyio, "https://api.a.com")

异常处理策略
async def safe_fetch(url: str) -> str | None:
    try:
        return await fetch(url)
    except aiohttp.ClientError as e:
        print(f"HTTP error for {url}: {e}")
        return None
    except asyncio.CancelledError:
        print(f"Cancelled: {url}")
        raise

async def main():
    async with asyncio.TaskGroup() as tg:
        tasks = [tg.create_task(safe_fetch(url)) for url in urls]


最佳实践
    

  • 新项目使用 TaskGroup 替代 gather，获得自动取消和结构化生命周期
    • 

  • 对外部 API 调用使用 Semaphore 控制并发数，避免触发速率限制
    • 

  • 始终处理 CancelledError：做清理后重新 raise
    • 

  • 使用 asyncio.Queue 实现生产者-消费者解耦
    • 

  • 需要跨异步框架兼容时选择 AnyIO 作为抽象层
    • 

  • 避免在异步代码中使用 threading.Lock，应使用 asyncio.Lock
