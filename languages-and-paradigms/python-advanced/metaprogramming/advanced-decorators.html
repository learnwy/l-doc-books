装饰器进阶

概述

装饰器是 Python 元编程最常用的工具。基础装饰器大家已经熟悉，本文聚焦进阶用法：参数化装饰器、类装饰器、装饰器栈的执行顺序，以及如何编写类型安全的装饰器。

核心概念

装饰器的本质是接受可调用对象并返回新可调用对象的函数——@my_decorator 只是 greet = my_decorator(greet) 的语法糖。从这一句出发可以推出进阶用法的全部规则：

  • 元信息会丢失：包装函数替换了原函数，__name__、__doc__ 等不再正确，必须用 @functools.wraps 还原。
  • 参数化需要三层嵌套：外层收参数、中层收函数、内层执行逻辑；想同时兼容 @deco 与 @deco(...)，就要靠默认参数区分。
  • 栈顺序是"由内向外包装、由外向内执行"：@a @b @c 等价于 a(b(c(f)))，调用时前置钩子从外到内、后置钩子从内到外。
关注点 问题 解法
元信息 __name__ 变成 wrapper @functools.wraps
类型签名 装饰后签名丢失 ParamSpec + Callable[P, R]
有参/无参兼容 两种调用方式 默认参数 + 分支返回
状态保持 需要闭包内的可变状态 用类实现装饰器

装饰器本质

装饰器是一个接受函数（或类）并返回新函数（或类）的可调用对象：

def my_decorator(func):
    def wrapper(*args, **kwargs):
        print("Before")
        result = func(*args, **kwargs)
        print("After")
        return result
    return wrapper

@my_decorator
def greet(name: str) -> str:
    return f"Hello, {name}"

等价于 greet = my_decorator(greet)。

保留原函数元信息

from functools import wraps

def my_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper
属性 不用 wraps 用 wraps
__name__ "wrapper" "greet"
__doc__ wrapper 的文档 原函数文档
__module__ 装饰器所在模块 原函数模块
__wrapped__ 不存在 指向原函数

参数化装饰器

参数化装饰器需要三层嵌套：外层接收参数，中层接收函数，内层执行逻辑。

from functools import wraps
import time

def retry(max_attempts: int = 3, delay: float = 1.0):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if attempt == max_attempts:
                        raise
                    time.sleep(delay)
        return wrapper
    return decorator

@retry(max_attempts=5, delay=0.5)
def fetch_data(url: str) -> str:
    ...

兼容有参/无参调用

def decorator(func=None, *, retries=3):
    def actual_decorator(f):
        @wraps(f)
        def wrapper(*args, **kwargs):
            for i in range(retries):
                try:
                    return f(*args, **kwargs)
                except Exception:
                    if i == retries - 1:
                        raise
        return wrapper

    if func is not None:
        return actual_decorator(func)
    return actual_decorator

@decorator
def a(): ...

@decorator(retries=5)
def b(): ...

类装饰器

装饰器不仅可以修饰函数，也可以修饰类：

def singleton(cls):
    instances = {}
    @wraps(cls)
    def get_instance(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
        return instances[cls]
    return get_instance

@singleton
class Database:
    def __init__(self, url: str):
        self.url = url

用类实现装饰器

class Timer:
    def __init__(self, func):
        wraps(func)(self)
        self.func = func

    def __call__(self, *args, **kwargs):
        start = time.perf_counter()
        result = self.func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{self.func.__name__} took {elapsed:.4f}s")
        return result

@Timer
def compute(n: int) -> int:
    return sum(range(n))

装饰器栈执行顺序

@decorator_a
@decorator_b
@decorator_c
def func(): ...

等价于 func = decorator_a(decorator_b(decorator_c(func)))。

graph TD
  A[原始函数] --> C[decorator_c 包装]
  C --> B[decorator_b 包装]
  B --> D[decorator_a 包装]
  D --> E[最终调用]

调用时执行顺序：A 的前置 → B 的前置 → C 的前置 → 原函数 → C 的后置 → B 的后置 → A 的后置。

类型安全的装饰器

使用 ParamSpec 让装饰后的函数保留原始签名：

from typing import ParamSpec, TypeVar, Callable
from functools import wraps

P = ParamSpec("P")
R = TypeVar("R")

def logged(func: Callable[P, R]) -> Callable[P, R]:
    @wraps(func)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        print(f"Calling {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

常见装饰器模式速查

模式 用途 典型实现
缓存 避免重复计算 @functools.cache
重试 自动重试失败操作 自定义 retry
权限检查 控制函数访问 Flask @login_required
注册 收集函数到注册表 插件系统
日志 记录调用信息 自定义 logged
验证 校验参数合法性 beartype

最佳实践

  • 始终使用 @wraps 保留原函数的元信息
  • 参数化装饰器使用关键字参数提升可读性
  • 使用 ParamSpec 让装饰器对类型检查器透明
  • 装饰器栈不宜超过 3 层，过深会增加调试难度
  • 优先使用标准库装饰器（@cache、@property）而非重新发明

小结

  • 装饰器本质是"接受可调用对象、返回新可调用对象"，@ 只是赋值语法糖。
  • 始终用 @functools.wraps 保留元信息，否则 __name__、__doc__ 会被覆盖。
  • 参数化装饰器需三层嵌套；用默认参数与分支返回兼容有参/无参两种调用。
  • 装饰器可作用于函数或类，也可以用类（实现 __call__）来写装饰器以携带状态。
  • 装饰器栈由内向外包装、由外向内执行，后置逻辑顺序相反。
  • 用 ParamSpec 让装饰器对类型检查器透明，装饰器栈不宜超过 3 层。
