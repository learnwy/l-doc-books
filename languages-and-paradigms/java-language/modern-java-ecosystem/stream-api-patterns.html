Stream API 进阶模式

核心概念

Stream API 是 Java 8 引入的函数式数据处理框架，提供了声明式的集合操作方式。Stream 不是数据结构，而是从数据源（集合、数组、IO）出发，通过一系列中间操作（过滤、映射、排序）形成流水线，最终由终端操作（收集、归约、遍历）触发执行。理解 Stream 的惰性求值和短路特性，以及 Collector 的组合能力，是高效使用 Stream API 的关键。

高级 Collector
Collectors 工具类提供了大量预定义的收集器，同时支持自定义收集器来处理复杂的归约逻辑。


分组与分区：


Map<Department, List<Employee>> byDept = employees.stream()
    .collect(Collectors.groupingBy(Employee::getDepartment));

Map<Department, Long> countByDept = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::getDepartment,
        Collectors.counting()
    ));

Map<Department, Optional<Employee>> topEarners = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::getDepartment,
        Collectors.maxBy(Comparator.comparingDouble(Employee::getSalary))
    ));

Map<Department, DoubleSummaryStatistics> salaryStats = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::getDepartment,
        Collectors.summarizingDouble(Employee::getSalary)
    ));
多级分组：


Map<Department, Map<JobLevel, List<Employee>>> nested = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::getDepartment,
        Collectors.groupingBy(Employee::getJobLevel)
    ));
自定义 Collector——实现一个将流元素收集为不可变 Map 的收集器：


public static <T, K, V> Collector<T, ?, Map<K, V>> toUnmodifiableMap(
        Function<T, K> keyMapper, Function<T, V> valueMapper) {
    return Collector.of(
        HashMap::new,
        (map, item) -> map.put(keyMapper.apply(item), valueMapper.apply(item)),
        (m1, m2) -> { m1.putAll(m2); return m1; },
        Collections::unmodifiableMap
    );
}

flatMap 与流的扁平化
flatMap 是处理嵌套数据结构的核心操作——将每个元素映射为一个流，然后将所有流合并为一个：


List<List<String>> nestedWords = List.of(
    List.of("hello", "world"),
    List.of("java", "stream"),
    List.of("flat", "map")
);

List<String> allWords = nestedWords.stream()
    .flatMap(Collection::stream)
    .toList();
// ["hello", "world", "java", "stream", "flat", "map"]

// 实际场景：订单中的所有商品
List<Product> allProducts = orders.stream()
    .flatMap(order -> order.getLineItems().stream())
    .map(LineItem::getProduct)
    .distinct()
    .toList();

// Optional 的 flatMap
Optional<String> city = getUser()
    .flatMap(User::getAddress)
    .flatMap(Address::getCity);
mapMulti（Java 16）——flatMap 的命令式替代，适合一对少数的映射：


List<Integer> result = numbers.stream()
    .<Integer>mapMulti((num, consumer) -> {
        if (num % 2 == 0) {
            consumer.accept(num);
            consumer.accept(num * 10);
        }
    })
    .toList();
并行流与性能
并行流通过 ForkJoinPool 自动将数据分割、并行处理、合并结果。但并行并非总是更快——数据量、操作类型和数据源结构都影响并行化效果：


long count = hugeList.parallelStream()
    .filter(item -> item.isValid())
    .count();

double total = transactions.parallelStream()
    .mapToDouble(Transaction::getAmount)
    .sum();

并行流陷阱：


// 陷阱1：共享可变状态
List<Integer> results = new ArrayList<>();
stream.parallel().forEach(results::add);  // 线程不安全！

// 正确做法：
List<Integer> results = stream.parallel().collect(Collectors.toList());

// 陷阱2：自定义 ForkJoinPool
// 默认使用 commonPool，线程数 = CPU 核心数 - 1
// 自定义池
ForkJoinPool customPool = new ForkJoinPool(4);
customPool.submit(() ->
    stream.parallel().forEach(this::process)
).get();

// 陷阱3：顺序依赖
stream.parallel().forEachOrdered(System.out::println);  // 保证顺序但损失性能
Stream 实战模式
模式1：构建索引：


Map<String, Product> productIndex = products.stream()
    .collect(Collectors.toMap(
        Product::getSku,
        Function.identity(),
        (existing, replacement) -> existing  // 重复 key 策略
    ));
模式2：窗口/分页：


public <T> List<List<T>> partition(List<T> list, int size) {
    return IntStream.range(0, (list.size() + size - 1) / size)
        .mapToObj(i -> list.subList(i * size, Math.min((i + 1) * size, list.size())))
        .toList();
}
模式3：管道复用——Stream 只能消费一次，使用 Supplier 延迟创建：


Supplier<Stream<Order>> orderStream = () -> orders.stream()
    .filter(o -> o.getDate().isAfter(startDate));

long count = orderStream.get().count();
double total = orderStream.get().mapToDouble(Order::getAmount).sum();
模式4：teeing 双收集器（Java 12）：


var result = employees.stream().collect(
    Collectors.teeing(
        Collectors.averagingDouble(Employee::getSalary),
        Collectors.counting(),
        (avg, count) -> "平均薪资: %.2f, 人数: %d".formatted(avg, count)
    )
);
小结
    

  • Stream 采用惰性求值，中间操作不会立即执行，终端操作触发整个流水线
    • 

  • Collectors 提供分组（groupingBy）、分区（partitioningBy）、汇总（summarizing）等强大收集器，支持多级组合
    • 

  • flatMap 是处理嵌套结构的核心，Java 16 的 mapMulti 是一对少数映射的命令式替代
    • 

  • 并行流适合大数据量 + CPU 密集型 + 支持高效分割的数据源，避免共享可变状态和 IO 密集操作
    • 

  • 实战模式包括构建索引、分页分组、Stream 复用（Supplier 延迟创建）和 teeing 双收集
    • 

  • Stream 不适合所有场景——简单循环、需要提前终止或有复杂分支的逻辑，传统 for 循环更清晰
    •
