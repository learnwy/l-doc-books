Java 模块系统 JPMS

核心概念

Java 平台模块系统（Java Platform Module System, JPMS）是 Java 9 引入的模块化机制，项目代号 Jigsaw。JPMS 在包（package）之上引入了模块（module）的概念，提供了强封装（strong encapsulation）和可靠配置（reliable configuration）。它解决了长期困扰 Java 的 JAR Hell 问题——类路径上的冲突、缺失依赖和内部 API 滥用。

module-info.java 详解
每个模块的根目录下有一个 module-info.java 文件，声明模块的名称、依赖和导出：


module com.example.order {
    requires java.base;                    // 隐式依赖，可省略
    requires java.sql;                     // 依赖 JDBC 模块
    requires transitive com.example.core;  // 传递依赖：依赖方也能看到 core

    exports com.example.order.api;         // 导出 API 包
    exports com.example.order.model;       // 导出模型包
    // com.example.order.internal 未导出，外部不可访问

    opens com.example.order.model to com.fasterxml.jackson.databind;  // 允许 Jackson 反射

    provides com.example.core.spi.PaymentProvider
        with com.example.order.payment.AlipayProvider;  // SPI 提供者

    uses com.example.core.spi.NotificationService;       // SPI 消费者
}

迁移到模块化
未命名模块与自动模块
JPMS 提供了两种兼容机制，使非模块化的 JAR 可以在模块系统中使用：


// 未命名模块（Unnamed Module）
// classpath 上的所有 JAR 自动归入一个未命名模块
// 可以读取所有命名模块，导出所有包
// 不能被命名模块 requires

// 自动模块（Automatic Module）
// 将 JAR 放到模块路径上，JPMS 自动推导模块名
// 模块名 = JAR 文件名去掉版本号，连字符转点号
// 例：guava-31.1.jar → module guava
渐进式迁移策略：


// 阶段1：使用 --add-exports 临时打开内部 API
// java --add-exports java.base/sun.misc=ALL-UNNAMED -jar app.jar

// 阶段2：使用 --add-opens 允许反射（框架需要）
// java --add-opens java.base/java.lang=ALL-UNNAMED -jar app.jar

// 阶段3：为自己的 JAR 添加 module-info.java
// 使用 jdeps 分析依赖
// jdeps --generate-module-info out/ mylib.jar

JLink 定制运行时
JLink 工具可以根据应用依赖的模块，创建一个只包含所需模块的精简 JRE：


# 分析应用依赖
jdeps --print-module-deps target/app.jar

# 创建定制运行时
jlink --module-path $JAVA_HOME/jmods:mods \
      --add-modules com.example.app \
      --output custom-jre \
      --strip-debug \
      --compress=2 \
      --no-header-files \
      --no-man-pages

# 运行
./custom-jre/bin/java -m com.example.app/com.example.app.Main

模块系统与框架兼容性
Spring、Hibernate 等框架大量使用反射，需要通过 opens 指令开放相关包：


module com.example.webapp {
    requires spring.boot;
    requires spring.boot.autoconfigure;
    requires spring.web;
    requires jakarta.persistence;

    opens com.example.webapp to spring.core, spring.beans, spring.context;
    opens com.example.webapp.entity to org.hibernate.orm.core;
}

小结
    

  • JPMS 在包之上引入模块概念，通过 module-info.java 声明依赖和导出，解决 JAR Hell
    • 

  • exports 控制编译可见性，opens 控制反射可见性，两者正交
    • 

  • requires transitive 传递依赖，requires static 用于编译期可选依赖（如 Lombok）
    • 

  • 未命名模块和自动模块提供兼容性，支持渐进式迁移
    • 

  • JLink 创建定制 JRE 可将运行时大小从 200MB 降至 30MB，对容器化部署价值显著
    • 

  • Spring Boot 3+、Hibernate 6+ 等主流框架已完整支持 JPMS
    •
