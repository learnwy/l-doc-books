Java 构建工具

核心概念

Java 项目的构建工具负责依赖管理、编译、测试、打包和发布。Maven 和 Gradle 是 Java 生态的两大主流构建工具，Maven 以约定优于配置（Convention over Configuration）和 XML 声明式配置著称，Gradle 则提供了基于 Groovy/Kotlin DSL 的灵活脚本能力和更快的增量构建。理解两者的核心机制和适用场景，有助于为项目选择合适的构建方案。

Maven 核心机制
生命周期与阶段
Maven 定义了三个标准生命周期，每个生命周期包含有序的阶段（phase）：


# default 生命周期的关键阶段
mvn compile    # 编译 src/main/java
mvn test       # 运行 src/test/java
mvn package    # 打包为 JAR/WAR
mvn install    # 安装到本地仓库 ~/.m2
mvn deploy     # 发布到远程仓库

# 执行某个阶段会自动执行该阶段之前的所有阶段
mvn package    # 自动执行 compile → test → package
POM 配置
<project>
    <modelVersion>4.0.0</modelVersion>
    <groupId>com.example</groupId>
    <artifactId>order-service</artifactId>
    <version>1.0.0</version>
    <packaging>jar</packaging>

    <properties>
        <java.version>21</java.version>
        <maven.compiler.source>${java.version}</maven.compiler.source>
        <maven.compiler.target>${java.version}</maven.compiler.target>
        <spring-boot.version>3.2.0</spring-boot.version>
    </properties>

    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
            <version>${spring-boot.version}</version>
        </dependency>
        <dependency>
            <groupId>org.junit.jupiter</groupId>
            <artifactId>junit-jupiter</artifactId>
            <version>5.10.0</version>
            <scope>test</scope>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
                <version>${spring-boot.version}</version>
            </plugin>
        </plugins>
    </build>
</project>

Gradle 核心机制

plugins {
    java
    id("org.springframework.boot") version "3.2.0"
    id("io.spring.dependency-management") version "1.1.4"

    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}

    mavenCentral()
}

    implementation("org.springframework.boot:spring-boot-starter-web")
    runtimeOnly("com.mysql:mysql-connector-j")
    testImplementation("org.springframework.boot:spring-boot-starter-test")
}

tasks.test {
    useJUnitPlatform()
}
增量构建与构建缓存
Gradle 的核心性能优势来自于增量构建和构建缓存：


// 增量编译：只重新编译变更的文件
// Gradle 跟踪每个 Task 的输入和输出
// 输入未变 → 跳过任务（UP-TO-DATE）

// 构建缓存：跨构建复用任务输出
// gradle.properties
// org.gradle.caching=true

// 配置缓存（Gradle 8+）：缓存配置阶段
// org.gradle.configuration-cache=true

多模块项目管理
Maven 多模块：


<!-- parent/pom.xml -->
<project>
    <groupId>com.example</groupId>
    <artifactId>platform</artifactId>
    <packaging>pom</packaging>
    <modules>
        <module>common</module>
        <module>order-service</module>
        <module>user-service</module>
    </modules>
    <dependencyManagement>
        <dependencies>
            <dependency>
                <groupId>com.example</groupId>
                <artifactId>common</artifactId>
                <version>${project.version}</version>
            </dependency>
        </dependencies>
    </dependencyManagement>
</project>
Gradle 多模块：


// settings.gradle.kts
rootProject.name = "platform"
include("common", "order-service", "user-service")

// buildSrc/src/main/kotlin/java-conventions.gradle.kts
plugins {
    java
}

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}

// order-service/build.gradle.kts
plugins {
    id("java-conventions")
}
dependencies {
    implementation(project(":common"))
}
依赖冲突解决
依赖冲突是构建工具最常见的问题之一——不同库依赖了同一个库的不同版本：


# Maven：查看依赖树
mvn dependency:tree
# Maven 策略：最近优先（nearest wins）

# Gradle：查看依赖树
gradle dependencies --configuration runtimeClasspath
# Gradle 策略：最新版本优先（newest wins）
// Gradle 强制指定版本
configurations.all {
    resolutionStrategy {
        force("com.google.guava:guava:32.1.3-jre")
        failOnVersionConflict()
    }
}

// Gradle BOM 统一版本管理
dependencies {
    implementation(platform("org.springframework.boot:spring-boot-dependencies:3.2.0"))
    implementation("com.fasterxml.jackson.core:jackson-databind")
}

小结
    

  • Maven 和 Gradle 是 Java 两大主流构建工具，Maven 约定优于配置，Gradle 更灵活高效
    • 

  • Maven 使用三阶段生命周期模型，POM XML 声明依赖和插件
    • 

  • Gradle 通过增量构建、构建缓存和守护进程实现数倍于 Maven 的构建速度
    • 

  • 多模块项目使用 dependencyManagement（Maven）或 platform + convention plugin（Gradle）统一版本
    • 

  • 依赖冲突通过 dependency:tree 诊断，通过 BOM、force、exclusion 等策略解决
    • 

  • 新项目推荐 Gradle + Kotlin DSL，大型企业项目中 Maven 仍是主流选择
