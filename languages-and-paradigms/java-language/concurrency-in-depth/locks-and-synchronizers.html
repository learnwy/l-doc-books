锁与同步器

核心概念

Java 提供了两套锁机制：内置锁（synchronized）和显式锁（java.util.concurrent.locks）。两者的底层都依赖于操作系统的互斥量或 CAS 操作，但显式锁提供了更灵活的特性——可中断获取、超时获取、公平性选择和条件变量。显式锁的核心是 AbstractQueuedSynchronizer（AQS），它是 j.u.c 中几乎所有同步器的实现基础。

synchronized 锁升级
Java 6 引入了偏向锁和轻量级锁优化，使 synchronized 的性能显著提升。锁状态存储在对象头的 Mark Word 中，随竞争程度逐步升级：


// 锁升级过程：无锁 → 偏向锁 → 轻量级锁 → 重量级锁

// 偏向锁：当只有一个线程反复进入同步块时
// Mark Word 记录线程 ID，后续进入只需比较线程 ID
synchronized (obj) {
    // 第一次获取：CAS 写入线程 ID → 偏向锁
    // 同一线程再次进入：直接比较 → 无开销
}

// 轻量级锁：当第二个线程尝试获取
// 在栈帧中创建 Lock Record，CAS 替换 Mark Word
// 成功则获取轻量级锁，自旋等待

// 重量级锁：自旋失败后膨胀
// 关联 ObjectMonitor，线程挂起/唤醒（内核态切换）

ReentrantLock 与 AQS
ReentrantLock 基于 AQS（AbstractQueuedSynchronizer）实现。AQS 使用一个 int state 变量表示同步状态，一个 FIFO 队列管理等待线程：


ReentrantLock lock = new ReentrantLock(true);  // true = 公平锁

lock.lock();
try {
    // 临界区
} finally {
    lock.unlock();
}

// 可中断获取
lock.lockInterruptibly();

// 超时获取
if (lock.tryLock(1, TimeUnit.SECONDS)) {
    try {
        // 获取成功
    } finally {
        lock.unlock();
    }
} else {
    // 获取失败，执行降级逻辑
}
Condition 条件变量——替代 wait/notify，支持多个等待条件：


ReentrantLock lock = new ReentrantLock();
Condition notFull = lock.newCondition();
Condition notEmpty = lock.newCondition();
int[] buffer = new int[10];
int count = 0;

public void put(int value) throws InterruptedException {
    lock.lock();
    try {
        while (count == buffer.length) {
            notFull.await();
        }
        buffer[count++] = value;
        notEmpty.signal();
    } finally {
        lock.unlock();
    }
}

public int take() throws InterruptedException {
    lock.lock();
    try {
        while (count == 0) {
            notEmpty.await();
        }
        int value = buffer[--count];
        notFull.signal();
        return value;
    } finally {
        lock.unlock();
    }
}

ReadWriteLock 与 StampedLock
ReadWriteLock 允许多个读线程并发访问，但写线程独占。适用于读多写少的场景：


ReadWriteLock rwLock = new ReentrantReadWriteLock();
Map<String, String> cache = new HashMap<>();

public String get(String key) {
    rwLock.readLock().lock();
    try {
        return cache.get(key);
    } finally {
        rwLock.readLock().unlock();
    }
}

public void put(String key, String value) {
    rwLock.writeLock().lock();
    try {
        cache.put(key, value);
    } finally {
        rwLock.writeLock().unlock();
    }
}
StampedLock（Java 8）引入了乐观读模式，在无竞争时完全避免加锁开销：


StampedLock sl = new StampedLock();

public double distanceFromOrigin(double x, double y) {
    long stamp = sl.tryOptimisticRead();  // 乐观读，不加锁
    double currentX = x, currentY = y;
    if (!sl.validate(stamp)) {            // 检查是否有写入发生
        stamp = sl.readLock();            // 退化为悲观读锁
        try {
            currentX = x;
            currentY = y;
        } finally {
            sl.unlockRead(stamp);
        }
    }
    return Math.sqrt(currentX * currentX + currentY * currentY);
}

死锁诊断与预防
死锁发生在两个或多个线程互相等待对方持有的锁。四个必要条件：互斥、占有并等待、不可抢占、循环等待。


// 经典死锁场景
Object lockA = new Object(), lockB = new Object();

// 线程1
synchronized (lockA) {
    synchronized (lockB) { }  // 等待 lockB
}

// 线程2
synchronized (lockB) {
    synchronized (lockA) { }  // 等待 lockA → 死锁
}

// 预防：固定加锁顺序
private static final Object LOCK_FIRST = lockA.hashCode() < lockB.hashCode() ? lockA : lockB;
private static final Object LOCK_SECOND = LOCK_FIRST == lockA ? lockB : lockA;

# jstack 查看线程转储

# JMX 编程检测
ThreadMXBean tmx = ManagementFactory.getThreadMXBean();

小结
    

  • synchronized 经过偏向锁→轻量级锁→重量级锁的升级优化，单线程场景性能极高
    • 

  • ReentrantLock 基于 AQS，提供可中断、可超时、公平性和多条件变量等高级特性
    • 

  • ReadWriteLock 适用于读多写少场景，StampedLock 通过乐观读进一步提升读性能
    • 

  • AQS 是 j.u.c 同步器的基石，通过 state 变量和 CLH 队列实现各种同步语义
    • 

  • 死锁预防的核心策略：固定加锁顺序、使用超时获取、最小化持锁范围
    • 

  • 选择锁时优先考虑 synchronized（简单场景），需要高级特性时使用 ReentrantLock
    •
