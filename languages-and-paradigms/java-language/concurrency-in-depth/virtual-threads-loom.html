虚拟线程与 Project Loom

核心概念

虚拟线程（Virtual Threads）是 Java 21 正式引入的轻量级线程实现，属于 Project Loom 项目的核心成果。虚拟线程由 JVM 管理而非操作系统，创建和切换成本极低（约 1KB 栈空间 vs 平台线程的 1MB），使得"一个请求一个线程"的编程模型可以扩展到百万级并发。这从根本上改变了 Java 服务端的并发架构。

虚拟线程的使用方式
Java 21 提供了多种创建和使用虚拟线程的 API：


// 方式1：Thread.startVirtualThread
Thread vt = Thread.startVirtualThread(() -> {
    System.out.println("Running on: " + Thread.currentThread());
});

// 方式2：Thread.ofVirtual() 构建器
Thread vt2 = Thread.ofVirtual()
    .name("vt-", 0)
    .start(() -> processRequest());

// 方式3：虚拟线程执行器（最推荐的方式）
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 100_000; i++) {
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1));
            return fetchFromDatabase();
        });
    }
}

// 方式4：StructuredTaskScope（Java 21 Preview）
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Subtask<User> userTask = scope.fork(() -> findUser(id));
    Subtask<List<Order>> ordersTask = scope.fork(() -> findOrders(id));
    scope.join().throwIfFailed();
    return new UserProfile(userTask.get(), ordersTask.get());
}
关键原则：虚拟线程不需要池化——它们的创建成本极低，每个任务直接创建一个虚拟线程即可。


虚拟线程调度原理
虚拟线程采用 M:N 调度模型——M 个虚拟线程映射到 N 个平台线程（载体线程，carrier threads）。当虚拟线程执行阻塞操作时，JVM 自动将其从载体线程上卸载（unmount），载体线程可以继续运行其他虚拟线程。


// 阻塞操作的行为变化：
// 平台线程：Thread.sleep → OS 线程挂起 → 浪费一个 OS 线程
// 虚拟线程：Thread.sleep → 从载体线程卸载 → 载体线程服务其他虚拟线程

// 以下操作都会触发虚拟线程的卸载：
Thread.sleep(duration);         // 定时等待
socket.read();                  // 网络 IO
channel.read(buffer);           // NIO 通道
Lock.lock();                    // j.u.c 锁（非 synchronized）
BlockingQueue.take();           // 阻塞队列
固定（Pinning）问题：在以下情况下，虚拟线程无法从载体线程卸载，会"固定"载体线程：


// 情况1：synchronized 块中执行阻塞操作
synchronized (lock) {
    Thread.sleep(1000);  // 固定！虚拟线程无法卸载
}

// 解决方案：使用 ReentrantLock 替代 synchronized
ReentrantLock lock = new ReentrantLock();
lock.lock();
try {
    Thread.sleep(1000);  // 正常卸载
} finally {
    lock.unlock();
}

// 情况2：native 方法或 JNI 调用中的阻塞
// 这种情况无法避免，需要注意

// 监测固定
// -Djdk.tracePinnedThreads=short
// -Djdk.tracePinnedThreads=full

结构化并发
结构化并发（Structured Concurrency, Java 21 Preview）将并发任务的生命周期绑定到代码结构中，确保子任务在父作用域结束前完成或取消，消除了线程泄漏和悬挂任务问题。


// ShutdownOnFailure：任一失败则取消所有
Response handle(Request request) throws Exception {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        Subtask<User> user = scope.fork(() -> fetchUser(request.userId()));
        Subtask<Inventory> inv = scope.fork(() -> checkInventory(request.itemId()));
        Subtask<BigDecimal> price = scope.fork(() -> getPrice(request.itemId()));

        scope.join().throwIfFailed();

        return new Response(user.get(), inv.get(), price.get());
    }
}

// ShutdownOnSuccess：首个成功即返回
<T> T race(List<Callable<T>> tasks) throws Exception {
    try (var scope = new StructuredTaskScope.ShutdownOnSuccess<T>()) {
        for (var task : tasks) {
            scope.fork(task);
        }
        scope.join();
        return scope.result();
    }
}

迁移指南与最佳实践
// 迁移前：线程池 + 异步回调
ExecutorService pool = Executors.newFixedThreadPool(200);
Future<Result> future = pool.submit(() -> blockingCall());
Result result = future.get();  // 阻塞等待

// 迁移后：虚拟线程 + 同步代码
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    Future<Result> future = executor.submit(() -> blockingCall());
    Result result = future.get();  // 虚拟线程中的阻塞不浪费资源
}

注意事项：


    

  • 不要池化虚拟线程——每个任务创建新的虚拟线程
    • 

  • 将 synchronized 替换为 ReentrantLock（避免固定）
    • 

  • ThreadLocal 在虚拟线程中仍然可用，但百万线程时要注意内存开销
    • 

  • 使用 ScopedValue（Preview）替代 ThreadLocal 减少内存占用
    • 



小结
    

  • 虚拟线程是 Java 21 引入的轻量级线程，创建成本约 1μs、栈空间约 1KB，可扩展到百万级
    • 

  • M:N 调度模型将虚拟线程映射到少量载体线程，阻塞 IO 时自动卸载不浪费资源
    • 

  • synchronized 内的阻塞操作会导致固定（Pinning），应替换为 ReentrantLock
    • 

  • 结构化并发将子任务生命周期绑定到作用域，自动处理取消和异常，消除线程泄漏
    • 

  • 虚拟线程最适合 IO 密集型场景（HTTP 服务、数据库访问、微服务调用），不适合 CPU 密集型
    • 

  • 不要池化虚拟线程，使用 Executors.newVirtualThreadPerTaskExecutor() 为每个任务创建新线程
    •
