java.util.concurrent 核心组件

核心概念

java.util.concurrent（j.u.c）是 Java 5 引入的并发工具包，由 Doug Lea 主导设计，提供了线程池、原子变量、并发集合、同步器等高级并发构建块。相比于原始的 synchronized 和 wait/notify，j.u.c 提供了更灵活、更高性能的并发解决方案。理解其核心组件的设计和使用方式，是 Java 并发编程的必备技能。

ThreadPoolExecutor 深入解析
ThreadPoolExecutor 是 Java 线程池的核心实现。理解其 7 个构造参数和任务处理流程是正确使用线程池的关键。


ThreadPoolExecutor executor = new ThreadPoolExecutor(
    4,                             // corePoolSize: 核心线程数
    8,                             // maximumPoolSize: 最大线程数
    60L,                           // keepAliveTime: 非核心线程空闲存活时间
    TimeUnit.SECONDS,              // unit: 时间单位
    new ArrayBlockingQueue<>(100), // workQueue: 任务队列
    new ThreadFactory() {          // threadFactory: 线程创建工厂
        private final AtomicInteger counter = new AtomicInteger(1);
        public Thread newThread(Runnable r) {
            Thread t = new Thread(r, "biz-pool-" + counter.getAndIncrement());
            t.setDaemon(false);
            return t;
        }
    },
    new ThreadPoolExecutor.CallerRunsPolicy()  // handler: 拒绝策略
);

原子变量与 CAS
j.u.c.atomic 包提供了基于 CAS（Compare-And-Swap）的原子操作类，在无锁的情况下实现线程安全的读写。


AtomicInteger counter = new AtomicInteger(0);

counter.incrementAndGet();     // 原子自增
counter.compareAndSet(5, 10);  // CAS：期望值为5时设为10
counter.getAndUpdate(x -> x * 2);  // 原子更新

// CAS 的底层实现
// Unsafe.compareAndSwapInt(obj, offset, expect, update)
// 映射到 CPU 的 CMPXCHG 指令（x86）
ABA 问题与解决：


// ABA 问题：值从 A → B → A，CAS 认为没有变化
AtomicStampedReference<String> ref = new AtomicStampedReference<>("A", 0);
int[] stampHolder = new int[1];
String current = ref.get(stampHolder);
ref.compareAndSet(current, "B", stampHolder[0], stampHolder[0] + 1);
高竞争场景的优化——LongAdder：


// AtomicLong 在高竞争下性能退化（大量 CAS 重试）
// LongAdder 使用分段累加 + 最终汇总，减少竞争

LongAdder adder = new LongAdder();
adder.increment();          // 分段累加到 Cell[]
adder.sum();                // 汇总所有 Cell 的值

// 性能对比（16 线程并发自增）：
// AtomicLong: ~150ns/op
// LongAdder:  ~20ns/op

同步工具类
j.u.c 提供了多种线程协调工具，它们都基于 AQS（AbstractQueuedSynchronizer）实现：


CountDownLatch——一次性倒计数：


CountDownLatch latch = new CountDownLatch(3);

for (int i = 0; i < 3; i++) {
    executor.submit(() -> {
        try {
            doWork();
        } finally {
            latch.countDown();  // 每完成一个，计数减一
        }
    });
}

latch.await(10, TimeUnit.SECONDS);  // 等待所有完成或超时
CyclicBarrier——可重用屏障：


CyclicBarrier barrier = new CyclicBarrier(3, () -> {
    System.out.println("所有线程到达屏障，执行汇总操作");
});

for (int i = 0; i < 3; i++) {
    executor.submit(() -> {
        processPhase1();
        barrier.await();     // 等待所有线程完成阶段1
        processPhase2();
        barrier.await();     // 等待所有线程完成阶段2（可重用）
    });
}
Semaphore——限流/资源池：


Semaphore semaphore = new Semaphore(10);  // 最多 10 个并发

public void accessResource() throws InterruptedException {
    semaphore.acquire();
    try {
        useSharedResource();
    } finally {
        semaphore.release();
    }
}

BlockingQueue 与生产者-消费者
BlockingQueue 是实现生产者-消费者模式的核心接口——当队列满时 put 阻塞，当队列空时 take 阻塞：


BlockingQueue<Task> queue = new ArrayBlockingQueue<>(100);

// 生产者
executor.submit(() -> {
    while (running) {
        Task task = generateTask();
        queue.put(task);  // 队列满时阻塞
    }
});

// 消费者
executor.submit(() -> {
    while (running) {
        Task task = queue.take();  // 队列空时阻塞
        processTask(task);
    }
});

小结
    

  • j.u.c 是 Java 并发编程的核心工具包，提供线程池、原子变量、同步工具和并发集合
    • 

  • ThreadPoolExecutor 有 7 个关键参数，任务处理遵循核心线程 → 队列 → 非核心线程 → 拒绝策略的流程
    • 

  • 原子变量基于 CAS 实现无锁线程安全，高竞争场景使用 LongAdder 替代 AtomicLong
    • 

  • CountDownLatch（一次性倒数）、CyclicBarrier（可重用屏障）、Semaphore（限流）是三大线程协调工具
    • 

  • BlockingQueue 是生产者-消费者模式的标准实现，ArrayBlockingQueue 和 LinkedBlockingQueue 最常用
    • 

  • 始终使用 ThreadPoolExecutor 构造器而非 Executors 工厂方法，明确控制队列和线程数上限
    •
