垃圾回收算法

核心概念

垃圾回收（Garbage Collection, GC）是 JVM 自动管理堆内存的机制——自动识别不再被引用的对象并释放其占用的内存。GC 的设计需要在吞吐量（应用代码执行时间占比）、延迟（GC 暂停时间）和内存占用三个维度间做权衡。不同的 GC 算法和收集器适用于不同的应用场景。

分代假说：绝大多数对象朝生夕灭（弱分代假说），经历多次 GC 存活的对象更难被回收（强分代假说）。基于此，JVM 将堆分为新生代和老年代，分别采用不同的回收策略。


新生代回收
新生代采用标记-复制算法，将空间划分为一个 Eden 区和两个 Survivor 区（S0、S1），默认比例为 8:1:1。每次 Minor GC 时，将 Eden 和当前使用的 Survivor 中的存活对象复制到另一个 Survivor，然后清空 Eden 和旧 Survivor。


// 新生代默认大小配置
// -Xmn256m  或  -XX:NewRatio=2（老年代:新生代 = 2:1）
// -XX:SurvivorRatio=8（Eden:S0:S1 = 8:1:1）

// 对象晋升到老年代的条件：
// 1. 年龄达到阈值 -XX:MaxTenuringThreshold=15
// 2. Survivor 空间不足（动态年龄判断）
// 3. 大对象直接进入老年代 -XX:PretenureSizeThreshold
分配优化——TLAB（Thread-Local Allocation Buffer）：每个线程在 Eden 区预分配一块私有缓冲区，对象分配无需加锁：


// TLAB 默认开启
// -XX:+UseTLAB（默认 true）
// -XX:TLABSize=512k

// 对象分配流程：
// 1. TLAB 快速分配（无锁）
// 2. TLAB 用尽 → Eden 区 CAS 分配
// 3. Eden 满 → Minor GC
// 4. Survivor 不够 → 晋升老年代
// 5. 老年代满 → Major/Full GC

主流垃圾收集器
G1 收集器
G1（Garbage-First）是 Java 9+ 的默认收集器，将堆划分为大小相等的 Region（默认 2048 个），每个 Region 可以是 Eden、Survivor、Old 或 Humongous（大对象）。G1 通过优先回收垃圾最多的 Region 来控制暂停时间。


// G1 配置
// -XX:+UseG1GC（Java 9+ 默认）
// -XX:MaxGCPauseMillis=200（目标暂停时间）
// -XX:G1HeapRegionSize=4m（Region 大小，1-32MB）
// -XX:InitiatingHeapOccupancyPercent=45（触发并发标记的阈值）

ZGC
ZGC（Z Garbage Collector）是低延迟收集器，暂停时间不超过几毫秒且不随堆大小增长。它使用着色指针（Colored Pointers）和读屏障（Load Barriers）实现了几乎完全并发的回收。


// ZGC 配置（Java 17+ 生产就绪）
// -XX:+UseZGC
// -XX:+ZGenerational（Java 21+ 分代 ZGC）
// -Xmx16g

// ZGC 特点：
// 暂停时间 < 1ms（与堆大小无关）
// 支持 TB 级堆
// 并发标记、并发转移、并发重映射

GC 调优实战
基本调优原则：首先确定优化目标（延迟、吞吐量还是内存），然后选择合适的收集器，最后微调参数。


# 监控 GC 行为
java -Xlog:gc*:file=gc.log:time,uptime,level,tags -jar app.jar

# 关键指标
# Young GC 频率和耗时
# Full GC 是否发生（G1/ZGC 不应有 Full GC）
# 堆内存使用趋势
常见调优场景：


// 场景1：频繁 Young GC
// 原因：新生代太小，或大量短命对象
// 方案：增大新生代（-Xmn）或优化代码减少对象创建

// 场景2：频繁 Full GC
// 原因：老年代空间不足，内存泄漏
// 方案：增大堆（-Xmx），排查内存泄漏

// 场景3：GC 暂停过长
// 原因：堆太大 + 非并发收集器
// 方案：切换到 G1/ZGC，设置暂停目标

// 场景4：内存泄漏
// 工具：jmap -dump:live,format=b,file=heap.hprof <pid>
// 分析：Eclipse MAT / VisualVM 查找 dominator tree

小结
    

  • GC 三大基础算法：标记-清除（产生碎片）、标记-复制（空间换时间）、标记-整理（移动开销）
    • 

  • 分代假说驱动了新生代（复制算法）和老年代（整理/清除算法）的分代回收策略
    • 

  • G1 是 Java 9+ 默认收集器，通过 Region 化和优先回收实现可控暂停时间
    • 

  • ZGC 通过着色指针和并发回收实现亚毫秒暂停，适用于大堆低延迟场景
    • 

  • GC 调优首先确定目标（延迟/吞吐量/内存），选择合适收集器，再微调参数
    • 

  • 避免 Full GC 是 G1/ZGC 调优的核心目标，频繁 Full GC 通常意味着内存泄漏或堆空间不足
    •
