Java 异常处理模式

核心概念

Java 的异常处理机制基于 try-catch-finally 语法和 Throwable 类层次结构，提供了结构化的错误处理方式。Java 将异常分为检查异常（Checked Exception）和非检查异常（Unchecked Exception），这一设计决策在业界引发了持续的讨论。掌握异常处理的最佳实践，对于构建健壮的 Java 系统至关重要。

异常处理的核心原则：只捕获你能处理的异常，其余让它向上传播。过度捕获异常（尤其是吞掉异常）是 Java 代码中最常见的反模式之一。


检查异常与非检查异常
Java 的检查异常要求调用方必须显式处理（catch 或 throws），这一机制旨在强制开发者考虑异常路径。但在实际项目中，检查异常常常导致大量的 throws 声明传播和无意义的 catch 块。


检查异常的合理使用场景：


public class FileProcessor {
    public String readConfig(Path path) throws IOException {
        return Files.readString(path);
    }

    public Config loadConfig(Path path) {
        try {
            String content = readConfig(path);
            return parseConfig(content);
        } catch (IOException e) {
            return Config.defaults();
        }
    }
}
将检查异常转换为非检查异常——在分层架构中，底层的检查异常不应暴露给上层：


public class UserRepository {
    public User findById(long id) {
        try {
            return jdbcTemplate.queryForObject(SQL, mapper, id);
        } catch (DataAccessException e) {
            throw new UserNotFoundException("User not found: " + id, e);
        }
    }
}

public class UserNotFoundException extends RuntimeException {
    public UserNotFoundException(String message, Throwable cause) {
        super(message, cause);
    }
}

资源管理与 try-with-resources
Java 7 引入的 try-with-resources 自动关闭实现了 AutoCloseable 接口的资源，消除了 finally 块中容易出错的资源清理代码：


public List<String> readLines(Path path) throws IOException {
    try (BufferedReader reader = Files.newBufferedReader(path);
         Stream<String> lines = reader.lines()) {
        return lines.filter(line -> !line.isBlank())
                    .collect(Collectors.toList());
    }
}

public void transferData(DataSource source, DataSource target) throws SQLException {
    try (Connection srcConn = source.getConnection();
         Connection tgtConn = target.getConnection();
         PreparedStatement read = srcConn.prepareStatement(SELECT_SQL);
         PreparedStatement write = tgtConn.prepareStatement(INSERT_SQL)) {

        ResultSet rs = read.executeQuery();
        while (rs.next()) {
            write.setString(1, rs.getString("name"));
            write.addBatch();
        }
        write.executeBatch();
    }
}
异常链与根因保留
捕获异常后重新抛出时，必须将原始异常作为 cause 传递，否则会丢失根本原因：


public void processOrder(Order order) {
    try {
        paymentService.charge(order);
    } catch (PaymentException e) {
        throw new OrderProcessingException("Failed to process order: " + order.getId(), e);
    }
}

// 获取根因
public static Throwable getRootCause(Throwable t) {
    Throwable cause = t;
    while (cause.getCause() != null) {
        cause = cause.getCause();
    }
    return cause;
}
精确捕获与多异常处理
Java 7 支持在单个 catch 块中捕获多种异常类型：


try {
    reflectiveOperation();
} catch (ClassNotFoundException | NoSuchMethodException | IllegalAccessException e) {
    throw new ReflectionException("Reflection failed", e);
}
避免捕获过于宽泛的异常类型：


// 反模式：捕获 Exception 会吞掉所有异常
try {
    riskyOperation();
} catch (Exception e) {
    log.error("Error", e);
}

// 正确做法：精确捕获
try {
    riskyOperation();
} catch (SpecificException e) {
    handleSpecific(e);
} catch (AnotherException e) {
    handleAnother(e);
}
自定义异常体系设计
在大型项目中，应设计分层的自定义异常体系，而非依赖通用异常：


public abstract class AppException extends RuntimeException {
    private final ErrorCode errorCode;

    protected AppException(ErrorCode errorCode, String message) {
        super(message);
        this.errorCode = errorCode;
    }

    protected AppException(ErrorCode errorCode, String message, Throwable cause) {
        super(message, cause);
        this.errorCode = errorCode;
    }

    public ErrorCode getErrorCode() { return errorCode; }
}

public class BusinessException extends AppException {
    public BusinessException(ErrorCode code, String message) {
        super(code, message);
    }
}

public class InfrastructureException extends AppException {
    public InfrastructureException(ErrorCode code, String message, Throwable cause) {
        super(code, message, cause);
    }
}

public enum ErrorCode {
    USER_NOT_FOUND(404, "用户不存在"),
    INSUFFICIENT_BALANCE(400, "余额不足"),
    DB_CONNECTION_FAILED(503, "数据库连接失败");

    private final int httpStatus;
    private final String description;

    ErrorCode(int httpStatus, String description) {
        this.httpStatus = httpStatus;
        this.description = description;
    }
}
全局异常处理（Spring Boot）：


@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<ErrorResponse> handleBusiness(BusinessException e) {
        ErrorCode code = e.getErrorCode();
        return ResponseEntity.status(code.getHttpStatus())
                .body(new ErrorResponse(code.name(), e.getMessage()));
    }

    @ExceptionHandler(InfrastructureException.class)
    public ResponseEntity<ErrorResponse> handleInfra(InfrastructureException e) {
        log.error("Infrastructure error", e);
        return ResponseEntity.status(503)
                .body(new ErrorResponse("SERVICE_UNAVAILABLE", "服务暂时不可用"));
    }
}

异常性能与反模式
异常创建涉及栈帧捕获（fillInStackTrace），在高频路径上使用异常做流程控制会严重影响性能：


// 反模式：用异常做流程控制
public int parseOrDefault(String s, int defaultVal) {
    try {
        return Integer.parseInt(s);
    } catch (NumberFormatException e) {
        return defaultVal;
    }
}

// 正确做法：先验证再解析
public int parseOrDefault(String s, int defaultVal) {
    if (s == null || !s.matches("-?\\d+")) {
        return defaultVal;
    }
    return Integer.parseInt(s);
}
对于已知的、可以预防的条件，使用条件检查而非异常捕获。但对于真正的异常情况（文件不存在、网络超时等不可预测的外部因素），异常处理是正确的选择。


高性能场景的优化：如果确实需要在热路径上抛出异常，可以覆盖 fillInStackTrace 来消除栈帧捕获的开销：


public class LightweightException extends RuntimeException {
    @Override
    public synchronized Throwable fillInStackTrace() {
        return this;
    }
}

小结
    

  • Java 异常分为 Error（JVM 错误）、Checked Exception（编译强制处理）和 RuntimeException（编程错误）
    • 

  • 检查异常在分层架构中应转换为非检查异常，避免 throws 声明污染上层接口
    • 

  • try-with-resources 是管理 AutoCloseable 资源的标准方式，彻底替代 try-finally
    • 

  • 重新抛出异常时必须保留异常链（传入 cause），避免丢失根因
    • 

  • 大型项目应设计分层异常体系：业务异常、基础设施异常、校验异常
    • 

  • 异常不应用于流程控制，高频路径优先使用条件检查
