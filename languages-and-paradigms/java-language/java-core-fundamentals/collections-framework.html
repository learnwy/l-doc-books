Java 集合框架

核心概念

Java 集合框架（Java Collections Framework, JCF）是 java.util 包中一套统一的数据结构和算法 API。它以 Collection 和 Map 两大接口为根，衍生出 List、Set、Queue、Deque 等容器类型，是 Java 日常开发中使用频率最高的 API 之一。理解集合框架的内部数据结构和时间复杂度，对于写出高性能 Java 代码至关重要。

HashMap 实现原理
HashMap 是 Java 中最常用的 Map 实现，基于哈希表（数组 + 链表 + 红黑树）。Java 8 引入了链表到红黑树的升级机制，将最坏情况的查找复杂度从 O(n) 降低到 O(log n)。


哈希计算与扰动函数：HashMap 对 key 的 hashCode() 进行二次哈希（高16位异或低16位），降低哈希碰撞概率：


static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
数组索引计算：index = (n - 1) & hash，其中 n 是数组长度（必须是 2 的幂）。位运算替代取模运算，性能更优。


扩容机制：当元素数量超过 capacity × loadFactor（默认 0.75）时触发扩容，容量翻倍。扩容需要重新计算所有元素的位置：


Map<String, Integer> map = new HashMap<>(16, 0.75f);

// 扩容时，每个元素要么留在原位，要么移动到 原位 + oldCapacity
// 这由 hash & oldCapacity 是否为 0 决定
树化与退化：当单个桶的链表长度 ≥ 8 且数组长度 ≥ 64 时，链表转为红黑树；当树节点数 ≤ 6 时退化回链表：


static final int TREEIFY_THRESHOLD = 8;
static final int UNTREEIFY_THRESHOLD = 6;
static final int MIN_TREEIFY_CAPACITY = 64;

ArrayList 与 LinkedList 对比
ArrayList 基于动态数组，LinkedList 基于双向链表。两者在不同操作上有显著的性能差异。


ArrayList 扩容策略：初始容量 10，每次扩容为原容量的 1.5 倍（oldCapacity + (oldCapacity >> 1)）：


List<String> list = new ArrayList<>();

// 内部数组增长：10 → 15 → 22 → 33 → ...
// 扩容涉及 Arrays.copyOf，即整个数组的复制

// 预分配减少扩容
List<String> list = new ArrayList<>(10000);
随机访问性能：ArrayList 支持 O(1) 的随机访问（实现了 RandomAccess 标记接口），LinkedList 需要从头或尾遍历到目标位置：


List<Integer> arrayList = new ArrayList<>(List.of(1, 2, 3, 4, 5));
List<Integer> linkedList = new LinkedList<>(List.of(1, 2, 3, 4, 5));

arrayList.get(2);   // O(1)：直接 elementData[2]
linkedList.get(2);  // O(n)：从 head 或 tail 遍历
插入和删除：LinkedList 在已知节点位置时插入/删除为 O(1)，但定位本身是 O(n)。ArrayList 的中间插入需要移动后续元素：


// ArrayList 头部插入：O(n) — 需要移动所有元素
arrayList.add(0, element);

// LinkedList 头部插入：O(1) — 直接修改指针
linkedList.addFirst(element);

// 但迭代器中间插入，两者差异不大
// 因为 ArrayList 有 CPU 缓存友好的连续内存布局

实践建议：绝大多数场景优先选择 ArrayList。仅在需要频繁头部/中间插入且不需要随机访问时考虑 LinkedList，或者使用 ArrayDeque 替代 LinkedList 作为队列。


TreeMap 与排序集合
TreeMap 基于红黑树实现，保证 key 的自然排序或自定义排序。它实现了 NavigableMap 接口，提供了丰富的范围查询能力。


TreeMap<String, Integer> scores = new TreeMap<>();
scores.put("Alice", 95);
scores.put("Bob", 87);
scores.put("Charlie", 92);
scores.put("David", 88);

scores.firstKey();                    // "Alice"
scores.lastKey();                     // "David"
scores.subMap("Bob", "David");        // {Bob=87, Charlie=92}
scores.headMap("Charlie");            // {Alice=95, Bob=87}
scores.ceilingEntry("Ca");            // Charlie=92
scores.floorEntry("Ca");             // Bob=87
自定义排序：


TreeMap<String, Integer> caseInsensitive = new TreeMap<>(String.CASE_INSENSITIVE_ORDER);

TreeMap<Employee, String> byAge = new TreeMap<>(
    Comparator.comparingInt(Employee::getAge)
              .thenComparing(Employee::getName)
);

并发集合
JDK 提供了多种线程安全的集合实现，从早期的同步包装器到 java.util.concurrent 下的高性能并发集合。


ConcurrentHashMap（Java 8+）放弃了分段锁，改为 CAS + synchronized 锁单个桶：


ConcurrentHashMap<String, AtomicLong> counters = new ConcurrentHashMap<>();

// 原子性计算
counters.computeIfAbsent("pageViews", k -> new AtomicLong()).incrementAndGet();

// merge 操作
counters.merge("clicks", new AtomicLong(1), (old, val) -> {
    old.addAndGet(val.get());
    return old;
});
CopyOnWriteArrayList 适用于读远多于写的场景——每次修改都复制整个底层数组：


CopyOnWriteArrayList<String> listeners = new CopyOnWriteArrayList<>();

// 写操作：复制整个数组，替换引用
listeners.add("listener1");

// 读操作：无锁，直接读取当前数组快照
for (String listener : listeners) {
    // 迭代期间不会抛出 ConcurrentModificationException
}

小结
    

  • Java 集合框架以 Collection 和 Map 为根，提供了 List、Set、Queue、Map 四大体系
    • 

  • HashMap 使用数组 + 链表 + 红黑树结构，链表长度 ≥ 8 时树化，已知容量时预设初始大小避免扩容
    • 

  • ArrayList 在绝大多数场景优于 LinkedList，得益于 CPU 缓存友好的连续内存布局
    • 

  • TreeMap/TreeSet 基于红黑树提供有序存储和范围查询，适用于需要排序的场景
    • 

  • 并发场景使用 ConcurrentHashMap（高并发读写）、CopyOnWriteArrayList（读多写少）等专用集合，避免使用 Collections.synchronizedXxx 包装器
    • 

  • 选择集合时关注三个维度：有序性需求、唯一性需求、并发安全需求
