关联容器

核心概念

STL 关联容器（Associative Containers）通过键（key）组织元素，提供高效的查找、插入和删除操作。分为有序关联容器（基于红黑树，O(log n)）和无序关联容器（基于哈希表，均摊 O(1)）两大类。正确选择关联容器对数据密集型应用的性能至关重要。

graph TD
    A[关联容器] --> B[有序 Ordered]
    A --> C[无序 Unordered]
    B --> D[std::set]
    B --> E[std::map]
    B --> F[std::multiset]
    B --> G[std::multimap]
    C --> H[std::unordered_set]
    C --> I[std::unordered_map]
    C --> J[std::unordered_multiset]
    C --> K[std::unordered_multimap]
    B --> L[红黑树实现]
    C --> M[哈希表实现]
    L --> N[O log n 操作]
    M --> O[均摊 O1 操作]
容器 底层结构 查找 插入 有序遍历 内存开销
map / set 红黑树 O(log n) O(log n) 支持 每节点 3 指针+颜色
unordered_map / set 哈希表 均摊 O(1) 均摊 O(1) 不支持 bucket 数组+链表
multimap / multiset 红黑树 O(log n) O(log n) 支持 同 map/set
flat_map (C++23) 排序 vector O(log n) O(n) 支持 连续内存

std::map 与 std::set

std::map 存储键值对，std::set 只存储键。两者都基于红黑树实现，元素按键的 < 运算符排序：

#include <map>
#include <set>
#include <string>

void demonstrate_map() {
    std::map<std::string, int> scores;

    scores["Alice"] = 95;
    scores["Bob"] = 87;
    scores.insert({"Charlie", 92});
    scores.emplace("Dave", 88);
    auto [it, inserted] = scores.try_emplace("Alice", 100);  // 不覆盖已有

    if (auto found = scores.find("Bob"); found != scores.end()) {
        int score = found->second;
    }

    bool has_alice = scores.contains("Alice");  // C++20

    for (const auto& [name, score] : scores) {
        // 按键的字典序遍历
    }

    auto lower = scores.lower_bound("B");
    auto upper = scores.upper_bound("D");
    for (auto it = lower; it != upper; ++it) {
        // 范围查询：B <= key < D 的所有元素
    }

    if (auto node = scores.extract("Bob"); !node.empty()) {
        node.key() = "Robert";                // 修改键（C++17）
        scores.insert(std::move(node));
    }
}

void demonstrate_set() {
    std::set<int> unique_nums = {5, 3, 1, 4, 2, 3, 1};  // 自动去重排序

    unique_nums.insert(6);
    unique_nums.erase(3);

    auto [it, inserted] = unique_nums.insert(5);  // inserted = false

    std::set<int> other = {4, 5, 6, 7};
    std::vector<int> intersection;
    std::set_intersection(
        unique_nums.begin(), unique_nums.end(),
        other.begin(), other.end(),
        std::back_inserter(intersection)
    );
}

std::unordered_map

unordered_map 基于哈希表实现，提供均摊 O(1) 的查找和插入。理解负载因子（load factor）和 rehash 策略对性能调优至关重要：

#include <unordered_map>
#include <functional>

struct Point {
    int x, y;
    bool operator==(const Point& other) const {
        return x == other.x && y == other.y;
    }
};

struct PointHash {
    size_t operator()(const Point& p) const {
        auto h1 = std::hash<int>{}(p.x);
        auto h2 = std::hash<int>{}(p.y);
        return h1 ^ (h2 << 1);
    }
};

void demonstrate_unordered_map() {
    std::unordered_map<std::string, int> cache;
    cache.reserve(1000);           // 预分配 bucket

    cache["key1"] = 42;
    cache.emplace("key2", 100);

    float lf = cache.load_factor();        // 当前负载因子
    float mlf = cache.max_load_factor();   // 触发 rehash 的阈值（默认 1.0）
    size_t bc = cache.bucket_count();      // bucket 数量

    std::unordered_map<Point, std::string, PointHash> point_labels;
    point_labels[{1, 2}] = "origin";
}
哈希表参数 默认值 影响 调优建议
max_load_factor 1.0 负载因子超过此值触发 rehash 高性能场景设为 0.7
bucket_count 实现定义 哈希桶数量 reserve 预分配
hash 函数 std::hash 分布均匀性 自定义高质量哈希

自定义比较器与哈希

关联容器支持自定义排序规则和哈希函数：

#include <set>
#include <unordered_set>

struct CaseInsensitiveLess {
    bool operator()(const std::string& a, const std::string& b) const {
        return std::lexicographical_compare(
            a.begin(), a.end(), b.begin(), b.end(),
            [](char c1, char c2) {
                return std::tolower(c1) < std::tolower(c2);
            }
        );
    }
};

void demonstrate_custom_comparator() {
    std::set<std::string, CaseInsensitiveLess> names;
    names.insert("Alice");
    names.insert("alice");   // 不会插入（大小写不敏感相等）
    names.insert("Bob");

    auto cmp = [](int a, int b) { return a > b; };
    std::set<int, decltype(cmp)> max_heap(cmp);
    max_heap.insert(3);
    max_heap.insert(1);
    max_heap.insert(4);
}

实战场景与性能基准

不同关联容器在实际工程场景中的性能表现差异巨大。元素数量、键的分布、访问模式和内存布局共同决定了最优选择。小规模数据（< 100 个元素）中排序 vector 的缓存友好性往往超过红黑树和哈希表：

#include <map>
#include <unordered_map>
#include <vector>
#include <algorithm>

template<typename K, typename V>
class FlatMap {
    std::vector<std::pair<K, V>> data_;
public:
    void insert(K key, V value) {
        auto it = std::lower_bound(data_.begin(), data_.end(), key,
            [](const auto& p, const K& k) { return p.first < k; });
        data_.emplace(it, std::move(key), std::move(value));
    }

    const V* find(const K& key) const {
        auto it = std::lower_bound(data_.begin(), data_.end(), key,
            [](const auto& p, const K& k) { return p.first < k; });
        if (it != data_.end() && it->first == key) return &it->second;
        return nullptr;
    }

    size_t size() const { return data_.size(); }
};

void benchmark_scenario() {
    FlatMap<int, std::string> flat;
    flat.insert(1, "one");
    flat.insert(2, "two");

    std::map<int, std::string> tree;
    tree[1] = "one";
    tree[2] = "two";
}
场景 推荐容器 原因
小集合查找（< 50） 排序 vector / flat_map 缓存友好，二分查找
大集合高频查找 unordered_map 均摊 O(1) 查找
需要范围查询 std::map lower_bound/upper_bound
只读配置表 排序 vector + binary_search 构建一次，查询多次
多线程并发读写 concurrent_hash_map（第三方） 分段锁/无锁设计
稳定迭代器需求 std::map 插入删除不影响其他迭代器

小结

  • 有序容器（map/set）基于红黑树，O(log n) 操作，支持范围查询和有序遍历
  • 无序容器（unordered_map/set）基于哈希表，均摊 O(1) 操作，不支持有序遍历
  • unordered_map 的性能关键在于负载因子控制和高质量哈希函数，预分配 bucket 避免 rehash
  • 小集合（< 50 元素）使用排序 vector 比红黑树和哈希表更快，因为缓存友好
  • C++17 的 extract + insert 支持在不拷贝的情况下修改 map 的键
  • C++20 的 contains 方法简化了存在性检查
  • 选择经验：需要有序用 map/set，纯查找用 unordered_map/set，小集合用排序 vector
