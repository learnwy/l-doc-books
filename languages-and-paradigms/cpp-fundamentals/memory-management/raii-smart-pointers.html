RAII 与智能指针

核心概念

RAII（Resource Acquisition Is Initialization）是 C++ 中管理资源生命周期的核心范式。RAII 将资源的获取绑定到对象的构造函数中，将资源的释放绑定到析构函数中，利用 C++ 作用域规则和栈展开机制保证资源在任何退出路径（包括异常）下都被正确释放。智能指针是 RAII 在堆内存管理中最重要的应用：unique_ptr 实现独占所有权、shared_ptr 实现共享所有权、weak_ptr 解决循环引用。

RAII 原则与实现
RAII 的核心思想是将资源的生命周期与对象的生命周期绑定。构造时获取资源，析构时释放资源。由于 C++ 保证局部对象在离开作用域时一定调用析构函数（即使是由于异常展开），RAII 为资源管理提供了异常安全的保证。


class FileHandle {
public:
    explicit FileHandle(const char* path, const char* mode)
        : handle_(std::fopen(path, mode)) {
        if (!handle_) throw std::runtime_error("Failed to open file");
    }

    ~FileHandle() {
        if (handle_) std::fclose(handle_);
    }

    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;

    FileHandle(FileHandle&& other) noexcept : handle_(other.handle_) {
        other.handle_ = nullptr;
    }

    FileHandle& operator=(FileHandle&& other) noexcept {
        if (this != &other) {
            if (handle_) std::fclose(handle_);
            handle_ = other.handle_;
            other.handle_ = nullptr;
        }
        return *this;
    }

    std::size_t read(void* buf, std::size_t size) {
        return std::fread(buf, 1, size, handle_);
    }

    std::size_t write(const void* buf, std::size_t size) {
        return std::fwrite(buf, 1, size, handle_);
    }

private:
    std::FILE* handle_;
};
RAII 类的设计遵循「资源所有权」原则：一个 RAII 对象拥有其管理的资源。为了防止资源被错误地多次释放，RAII 类通常禁止拷贝构造和拷贝赋值（Rule of Five 中删除拷贝操作），但允许移动构造和移动赋值来转移所有权。

unique_ptr 独占所有权
std::unique_ptr 是现代 C++ 中堆内存管理的默认选择。它实现了独占所有权语义：同一时刻只有一个 unique_ptr 可以指向给定的堆对象。unique_ptr 的开销为零——编译后的代码与手动使用裸指针完全等价。


#include <memory>
#include <vector>

struct TreeNode {
    int value;
    std::unique_ptr<TreeNode> left;
    std::unique_ptr<TreeNode> right;

    explicit TreeNode(int v) : value(v), left(nullptr), right(nullptr) {}
};

auto buildTree(const std::vector<int>& values, int lo, int hi)
    -> std::unique_ptr<TreeNode> {
    if (lo > hi) return nullptr;
    int mid = lo + (hi - lo) / 2;
    auto node = std::make_unique<TreeNode>(values[mid]);
    node->left = buildTree(values, lo, mid - 1);
    node->right = buildTree(values, mid + 1, hi);
    return node;
}

auto transferOwnership(std::unique_ptr<TreeNode> node)
    -> std::unique_ptr<TreeNode> {
    node->value *= 2;
    return node;
}

void uniquePtrPatterns() {
    auto root = std::make_unique<TreeNode>(42);

    auto movedRoot = std::move(root);

    auto customDeleter = std::unique_ptr<FILE, decltype(&std::fclose)>(
        std::fopen("data.bin", "rb"), &std::fclose
    );

    auto arr = std::make_unique<int[]>(1024);
    arr[0] = 42;
}
make_unique 是创建 unique_ptr 的推荐方式，它保证了异常安全性：如果构造函数抛出异常，内存会被正确释放。避免直接使用 new 配合 unique_ptr 构造函数，因为在复杂表达式中可能导致内存泄漏。


shared_ptr 与 weak_ptr
std::shared_ptr 通过引用计数实现共享所有权。多个 shared_ptr 可以同时指向同一个对象，当最后一个 shared_ptr 销毁时，对象被释放。shared_ptr 的引用计数使用原子操作保证线程安全，但这也带来了性能开销。


#include <memory>
#include <unordered_map>
#include <string>

struct CacheEntry {
    std::string key;
    std::string data;
    std::size_t sizeBytes;
};

class LRUCache {
public:
    explicit LRUCache(std::size_t maxSize) : maxSize_(maxSize), currentSize_(0) {}

    auto get(const std::string& key) -> std::shared_ptr<CacheEntry> {
        auto it = cache_.find(key);
        if (it != cache_.end()) {
            if (auto entry = it->second.lock()) {
                return entry;
            }
            cache_.erase(it);
        }
        return nullptr;
    }

    void put(std::shared_ptr<CacheEntry> entry) {
        cache_[entry->key] = entry;
        currentSize_ += entry->sizeBytes;
    }

private:
    std::size_t maxSize_;
    std::size_t currentSize_;
    std::unordered_map<std::string, std::weak_ptr<CacheEntry>> cache_;
};

struct Observer {
    std::weak_ptr<CacheEntry> watched;

    auto check() -> bool {
        return !watched.expired();
    }

    auto access() -> std::shared_ptr<CacheEntry> {
        return watched.lock();
    }
};

void sharedPtrPatterns() {
    auto entry = std::make_shared<CacheEntry>();
    entry->key = "user:1001";
    entry->data = "cached data";
    entry->sizeBytes = 128;

    std::weak_ptr<CacheEntry> weakRef = entry;

    {
        auto shared2 = entry;
        auto useCount = entry.use_count();
    }

    if (auto locked = weakRef.lock()) {
        auto& data = locked->data;
    }
}
weak_ptr 用于打破循环引用和实现缓存。在双向链表、树的父指针和观察者模式等场景中，如果两个对象通过 shared_ptr 互相引用，引用计数永远不会降为零，导致内存泄漏。将其中一个方向改为 weak_ptr 即可解决。


智能指针性能与最佳实践
智能指针的性能特征决定了它们的适用场景。unique_ptr 几乎没有额外开销，应该作为堆内存管理的默认选择。shared_ptr 的控制块（包含引用计数、weak 计数和删除器）通常占 32-40 字节，且原子引用计数操作在高并发场景下可能成为瓶颈。


#include <memory>
#include <chrono>
#include <vector>

struct BenchmarkResult {
    double rawPtrNs;
    double uniquePtrNs;
    double sharedPtrNs;
    double makeSharedNs;
};

auto benchmarkCreation(int iterations) -> BenchmarkResult {
    BenchmarkResult result{};

    {
        auto start = std::chrono::high_resolution_clock::now();
        for (int i = 0; i < iterations; ++i) {
            auto* p = new int(i);
            delete p;
        }
        auto end = std::chrono::high_resolution_clock::now();
        result.rawPtrNs = std::chrono::duration<double, std::nano>(end - start).count() / iterations;
    }

    {
        auto start = std::chrono::high_resolution_clock::now();
        for (int i = 0; i < iterations; ++i) {
            auto p = std::make_unique<int>(i);
        }
        auto end = std::chrono::high_resolution_clock::now();
        result.uniquePtrNs = std::chrono::duration<double, std::nano>(end - start).count() / iterations;
    }

    {
        auto start = std::chrono::high_resolution_clock::now();
        for (int i = 0; i < iterations; ++i) {
            auto p = std::make_shared<int>(i);
        }
        auto end = std::chrono::high_resolution_clock::now();
        result.makeSharedNs = std::chrono::duration<double, std::nano>(end - start).count() / iterations;
    }

    return result;
}

小结
    

  • RAII 将资源生命周期绑定到对象生命周期，保证异常安全的资源释放
    • 

  • unique_ptr 是堆内存管理的默认选择，零开销且独占所有权
    • 

  • shared_ptr 通过原子引用计数实现共享所有权，有控制块和原子操作开销
    • 

  • weak_ptr 用于打破循环引用和实现非拥有观察，是缓存和观察者模式的关键
    • 

  • Rule of Zero/Five 指导 RAII 类的特殊成员函数设计
    • 

  • make_unique 和 make_shared 是创建智能指针的推荐方式，兼顾异常安全和性能
