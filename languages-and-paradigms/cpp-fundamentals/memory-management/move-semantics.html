移动语义与完美转发

核心概念

移动语义（Move Semantics）是 C++11 引入的最重要的性能优化特性。它允许将即将销毁的对象（右值）的内部资源「偷取」到新对象中，避免昂贵的深拷贝。完美转发（Perfect Forwarding）则是模板编程中保持参数值类别（左值/右值）不变地传递给下一层函数的技术。

移动构造与移动赋值
移动构造函数和移动赋值运算符通过右值引用参数（T&&）接收即将销毁的对象，将其内部资源转移到新对象中：


#include <utility>
#include <cstring>
#include <algorithm>

class DynamicArray {
    int* data_;
    size_t size_;

public:
    explicit DynamicArray(size_t n)
        : data_(new int[n]), size_(n) {
        std::fill_n(data_, n, 0);
    }

    ~DynamicArray() { delete[] data_; }

    DynamicArray(const DynamicArray& other)
        : data_(new int[other.size_]), size_(other.size_) {
        std::copy_n(other.data_, size_, data_);
    }

    DynamicArray(DynamicArray&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;
        other.size_ = 0;
    }

    DynamicArray& operator=(DynamicArray&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = other.data_;
            size_ = other.size_;
            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }

    DynamicArray& operator=(const DynamicArray& other) {
        if (this != &other) {
            DynamicArray tmp(other);
            std::swap(data_, tmp.data_);
            std::swap(size_, tmp.size_);
        }
        return *this;
    }

    size_t size() const { return size_; }
};

void demonstrate_move() {
    DynamicArray a(1000000);
    DynamicArray b = std::move(a);     // 移动构造：O(1)
    DynamicArray c(100);
    c = std::move(b);                  // 移动赋值：O(1)
}
noexcept 声明对移动操作至关重要。std::vector 在扩容时只有在移动操作标记为 noexcept 的情况下才会使用移动而非拷贝，因为移动失败后对象处于不确定状态，无法提供强异常安全保证。


std::move 与 std::forward
std::move 是一个无条件的转换——它将任意值转换为右值引用，但本身不执行任何移动操作。实际的资源转移发生在接收右值引用的移动构造/赋值中：


#include <utility>
#include <string>
#include <vector>

template<typename T>
constexpr std::remove_reference_t<T>&& my_move(T&& t) noexcept {
    return static_cast<std::remove_reference_t<T>&&>(t);
}

template<typename T>
constexpr T&& my_forward(std::remove_reference_t<T>& t) noexcept {
    return static_cast<T&&>(t);
}

template<typename... Args>
auto make_vector(Args&&... args) {
    std::vector<std::string> vec;
    (vec.push_back(std::forward<Args>(args)), ...);
    return vec;
}

void demonstrate_forwarding() {
    std::string s = "hello";

    auto v1 = make_vector(s);                // s 被拷贝（lvalue）
    auto v2 = make_vector(std::move(s));     // s 被移动（rvalue）
    auto v3 = make_vector("world");          // 字面量被移动
    auto v4 = make_vector(s, "foo", std::string("bar"));
}
引用折叠与转发引用
完美转发的底层机制是引用折叠（Reference Collapsing）规则。当模板参数 T 被推导为引用类型时，T&& 的行为取决于 T 的类型：


template<typename T>
void wrapper(T&& arg) {
    inner(std::forward<T>(arg));
}

转发引用（forwarding reference，也称万能引用）只在两种上下文中出现：模板参数 T&& 和 auto&&。它们不是右值引用，而是根据传入参数的值类别推导为左值引用或右值引用。


返回值优化
现代编译器通过 NRVO（Named Return Value Optimization）和 RVO（Return Value Optimization）消除函数返回时的拷贝/移动。C++17 将 prvalue 的 RVO 强制为语言标准（mandatory copy elision）：


DynamicArray create_array() {
    DynamicArray arr(1000);
    return arr;                    // NRVO：直接在调用者内存构造
}

DynamicArray create_temp() {
    return DynamicArray(1000);     // RVO：C++17 强制优化
}

void demonstrate_rvo() {
    auto a = create_array();       // 零拷贝零移动（NRVO）
    auto b = create_temp();        // 零拷贝零移动（RVO，C++17 保证）
}
移动语义的常见陷阱
正确使用移动语义需要理解几个关键陷阱。错误地使用 std::move 可能导致性能下降甚至程序错误：


#include <string>
#include <vector>

std::string create_greeting(const std::string& name) {
    std::string result = "Hello, " + name + "!";
    return result;            // NRVO 优化，不要写 return std::move(result)
}

void anti_patterns() {
    const std::string s = "immutable";
    // std::string moved = std::move(s);  // const 对象移动退化为拷贝

    std::string a = "hello";
    std::string b = std::move(a);
    // a.size();              // 合法但值不确定
    a = "reset";             // 赋值后恢复有效状态
}

class Widget {
    std::vector<int> data_;
public:
    void set_data(std::vector<int> data) {
        data_ = std::move(data);    // 值传递 + move：统一处理左值和右值
    }
};

小结
    

  • 移动语义将深拷贝的 O(n) 操作降为 O(1) 的指针交换，是 C++11 最重要的性能优化
    • 

  • noexcept 移动操作对 std::vector 扩容至关重要，缺少 noexcept 会退回到拷贝
    • 

  • std::move 是无条件的右值转换，std::forward 是有条件的转发（保持值类别）
    • 

  • 引用折叠规则：T& && → T&，T&& && → T&&，是完美转发的底层机制
    • 

  • C++17 强制 prvalue 的拷贝消除（mandatory copy elision），返回临时对象零开销
    • 

  • 不要对返回的局部变量使用 std::move，这会阻止 NRVO 优化
    • 

  • 移动 const 对象会静默退化为拷贝，编译器不会报错
    • 

  • 移动后的对象处于「有效但不确定」状态，只能执行析构和赋值操作
    •
