依赖解析与 node_modules
npm 的扁平化策略
npm v3 之前使用嵌套结构，导致 Windows 上路径过长的问题。npm v3+ 采用扁平化（hoisting）策略：


扁平化解决了路径过长的问题，但引入了幽灵依赖问题——项目可以 require 没有在 package.json 中声明的包（因为它被提升到了 node_modules 根目录）。


幽灵依赖示例
import lodash from 'lodash';
如果 lodash 只是某个依赖包的子依赖，但被 npm 提升到了顶层，上面的 import 会正常工作。但当依赖结构变化时（比如那个依赖包升级了不再使用 lodash），代码就会突然崩溃。

Lockfile 的作用
Lockfile（如 package-lock.json）记录了依赖树中每个包的精确版本和下载地址，确保在不同环境中安装完全相同的依赖：


{
  "name": "my-app",
  "version": "1.0.0",
  "lockfileVersion": 3,
  "packages": {
    "node_modules/express": {
      "version": "4.18.2",
      "resolved": "https://registry.npmjs.org/express/-/express-4.18.2.tgz",
      "integrity": "sha512-...",
      "dependencies": {
        "accepts": "~1.3.8",
        "body-parser": "1.20.1"
      }
    }
  }
}
关键原则：


    

  • Lockfile 必须提交到版本控制，确保团队成员和 CI 安装一致的依赖
    • 

  • 使用 npm ci 在 CI 环境中安装，它严格按照 lockfile 安装，速度更快且更可靠
    • 

  • 不要手动编辑 lockfile
    •

私有 Registry
企业环境中常需要搭建私有 npm Registry：


npm config set registry https://registry.company.com/
npm login --registry=https://registry.company.com/
const registryOptions = {
  Verdaccio: '轻量级私有 Registry，开源免费',

  'AWS CodeArtifact': 'AWS 托管的包仓库服务',

可以在 .npmrc 中配置不同 scope 使用不同的 Registry：


@company:registry=https://registry.company.com/
//registry.company.com/:_authToken=${NPM_TOKEN}


小结
    

  • npm 生态由 Registry（包存储）、CLI（命令行）和 Website（Web 界面）三部分组成。
    • 

  • npm、yarn、pnpm 是三大主流包管理器，pnpm 在磁盘效率和幽灵依赖防护方面表现最佳。
    • 

  • npm 的扁平化策略解决了路径过长问题，但引入了幽灵依赖风险。
    • 

  • Lockfile 必须提交到版本控制，CI 环境应使用 npm ci 安装。
    • 

  • 定期执行 npm audit 进行安全审计，使用 .npmrc 配置私有 Registry。
    •
