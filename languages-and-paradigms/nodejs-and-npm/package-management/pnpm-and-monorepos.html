pnpm 与 Monorepo

pnpm 的核心优势

pnpm（Performant npm）是一个革命性的包管理器，它通过内容寻址存储和硬链接机制，从根本上解决了 npm 和 yarn 的两大痛点：磁盘空间浪费和幽灵依赖。





对比维度
npm/yarn
pnpm





存储方式
每个项目完整拷贝
全局内容寻址存储 + 硬链接




10 个项目同依赖
10 份完整拷贝
1 份存储 + 10 个硬链接




幽灵依赖
可能访问未声明的包
严格隔离，不可访问




安装速度
中等
最快（已缓存时接近零）







pnpm 的 node_modules 结构
pnpm 使用独特的符号链接 + 硬链接结构来组织 node_modules：


关键设计：


    

  1. node_modules 根目录只包含 package.json 中声明的直接依赖的符号链接
    2. 

  2. 所有包的实际文件存储在 .pnpm/ 目录中
    3. 

  3. .pnpm/ 中的文件通过硬链接指向全局内容寻址存储
    4. 

  4. 子依赖通过符号链接互相引用
    5. 



这意味着幽灵依赖完全不可能——只有 package.json 中声明的包才会出现在 node_modules 的根层级。




pnpm 基本使用
npm install -g pnpm

pnpm install
pnpm add express
pnpm add -D typescript
pnpm remove lodash

pnpm run dev
pnpm test
pnpm dlx tsx script.ts
常用配置（.npmrc）
shamefully-hoist=false
strict-peer-dependencies=true
auto-install-peers=true
node-linker=hoisted
shamefully-hoist=true 会将所有依赖提升到根 node_modules，模拟 npm 的行为——这主要用于兼容不支持 pnpm 严格结构的工具，但会失去幽灵依赖防护。




Monorepo 基础
Monorepo（单仓多包）是将多个相关项目放在同一个 Git 仓库中管理的工程实践。

pnpm Workspace
pnpm 通过 pnpm-workspace.yaml 定义 workspace：


packages:
  - 'packages/*'
  - 'apps/*'
  - 'tools/*'
项目结构示例
monorepo/
├── pnpm-workspace.yaml
├── package.json
├── packages/
│   ├── core/
│   │   ├── package.json
│   │   └── src/
│   ├── utils/
│   │   ├── package.json
│   │   └── src/
│   └── types/
│       ├── package.json
│       └── src/
├── apps/
│   ├── web/
│   │   ├── package.json
│   │   └── src/
│   └── api/
│       ├── package.json
│       └── src/
└── tsconfig.base.json
workspace 协议
{
  "name": "@myorg/web",
  "dependencies": {
    "@myorg/core": "workspace:*",
    "@myorg/utils": "workspace:^1.0.0"
  }
}
workspace: 协议告诉 pnpm 从本地 workspace 解析包，而非从 Registry 下载。发布时，pnpm 会自动将 workspace:* 替换为实际版本号。






协议写法
含义
发布时替换为





workspace:*
匹配当前版本
1.2.3




workspace:^
兼容当前版本
^1.2.3




workspace:~
近似当前版本
~1.2.3







Workspace 命令
pnpm --filter @myorg/web dev

pnpm --filter @myorg/core build

pnpm --filter "./packages/**" test

pnpm --filter @myorg/web... build

pnpm -r run build

pnpm -r --parallel run lint
过滤器语法
const filterPatterns = {
  '--filter <package>': '指定单个包',
  '--filter <package>...': '指定包及其所有依赖',
  '--filter ...<package>': '指定包及其所有依赖者',
  "--filter './packages/**'": '匹配目录模式',
  "--filter '...[origin/main]'": '自上次发布以来变更的包',
  '-r': '所有 workspace 包',
};


共享配置
TypeScript 配置继承
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true
  }
}
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src/"]
}
根 package.json
{
  "private": true,
  "scripts": {
    "build": "pnpm -r run build",
    "test": "pnpm -r run test",
    "lint": "pnpm -r --parallel run lint",
    "clean": "pnpm -r exec rm -rf dist node_modules"
  },
  "devDependencies": {
    "typescript": "^5.3.0"
  }
}
将所有包共用的 devDependencies 安装在根目录，避免重复声明。




Turborepo 加速构建
pnpm workspace 经常与 Turborepo 搭配使用，实现智能缓存和并行构建：


{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"]
    },
    "test": {
      "dependsOn": ["build"],
      "outputs": []
    },
    "lint": {
      "outputs": []
    }
  }
}
Turborepo 会分析任务依赖图，自动并行执行不相互依赖的任务，并缓存已完成的任务输出。当文件没有变化时，后续构建几乎是即时完成。




小结
    

  • pnpm 通过内容寻址存储和硬链接实现包的全局去重，大幅节省磁盘空间。
    • 

  • pnpm 的严格 node_modules 结构彻底杜绝了幽灵依赖问题。
    • 

  • pnpm-workspace.yaml 定义 workspace 包范围，workspace: 协议管理包间依赖。
    • 

  • 使用 --filter 精确控制命令执行范围，-r 在所有包中执行。
    • 

  • 共享配置（TypeScript、ESLint 等）放在根目录，通过继承机制复用。
    • 

  • Turborepo 与 pnpm workspace 搭配使用，实现智能缓存和并行构建。
    •
