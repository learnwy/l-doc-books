版本管理与发布

语义化版本（SemVer）

语义化版本是 npm 生态的版本管理基石。每个版本号由三部分组成：MAJOR.MINOR.PATCH。

版本变更规则




变更类型
版本号变化
示例





修复 bug（不改 API）
PATCH +1
1.2.3 → 1.2.4




新增功能（向下兼容）
MINOR +1
1.2.3 → 1.3.0




破坏性变更
MAJOR +1
1.2.3 → 2.0.0





预发布版本
const prereleaseVersions = {
  '1.0.0-alpha.1': '内部测试版本',
  '1.0.0-beta.1': '公开测试版本',
  '1.0.0-rc.1': '发布候选版本',
  '1.0.0': '正式发布版本',
};
预发布版本的排序规则：alpha < beta < rc < release




版本范围语法
npm 使用版本范围（Version Range）来声明依赖的可接受版本：






语法
含义
示例范围





^1.2.3
兼容 1.x.x（允许 minor 和 patch）
>=1.2.3 <2.0.0




~1.2.3
近似 1.2.x（只允许 patch）
>=1.2.3 <1.3.0




1.2.3
精确版本
只有 1.2.3




>=1.2.3
大于等于
>=1.2.3




1.2.x
通配 patch
>=1.2.0 <1.3.0




*
任意版本
>=0.0.0





^（脱字符）的特殊行为
const caretBehavior = {
  '^1.2.3': '>=1.2.3 <2.0.0   (标准行为)',
  '^0.2.3': '>=0.2.3 <0.3.0   (0.x 版本 minor 视为 breaking)',
  '^0.0.3': '>=0.0.3 <0.0.4   (0.0.x 版本 patch 视为 breaking)',
};
对于 0.x 版本，^ 的行为更保守——这反映了 SemVer 规范中 0.x 版本 "API 不稳定" 的语义。

npm publish 流程
发布前检查
npm pack --dry-run

npm pack
tar -tzf my-package-1.0.0.tgz

npm pack 会生成与发布到 Registry 完全相同的 tarball，便于在发布前检查包含了哪些文件。

npm publish

Changesets 工具链
Changesets 是一个专门为 monorepo 设计的版本管理和发布工具：


pnpm add -Dw @changesets/cli
pnpm changeset init
工作流程
Changeset 文件示例
---
'@myorg/core': minor
'@myorg/utils': patch
---

新增 `formatCurrency` 工具函数，支持多种货币格式化。修复了 `parseDate` 在处理闰年时的边界错误。
自动化 CI/CD 发布
name: Release
on:
  push:
    branches: [main]

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v2
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm

      - run: pnpm install --frozen-lockfile
      - run: pnpm run build
      - run: pnpm run test

      - name: Create Release PR or Publish
        uses: changesets/action@v1
        with:
          publish: pnpm changeset publish
          version: pnpm changeset version
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
Changeset GitHub Action 会自动创建一个"Version Packages"的 PR，收集所有待发布的变更。当 PR 被合并时，自动执行发布。




废弃与撤回
npm deprecate my-package@1.0.0 "此版本存在安全漏洞，请升级到 1.0.1"

npm deprecate my-package@"<2.0.0" "1.x 版本已停止维护"

npm unpublish my-package@1.0.0-beta.1
关于 npm unpublish 的规则：


    

  • 发布 72 小时内可以撤回
    • 

  • 72 小时后只能使用 deprecate
    • 

  • 被其他包依赖的版本不能撤回
    •

小结
    

  • SemVer（MAJOR.MINOR.PATCH）是 npm 生态的版本管理标准。
    • 

  • ^ 允许 minor 和 patch 更新，~ 只允许 patch 更新，0.x 版本有特殊行为。
    • 

  • npm version 自动更新版本、创建 commit 和 tag。
    • 

  • npm pack 和 --dry-run 是发布前必做的检查步骤。
    • 

  • dist-tag 管理多发布通道（latest、beta、next、canary）。
    • 

  • Changesets 是 monorepo 版本管理和自动化发布的最佳工具。
    • 

  • 发布后 72 小时内可以 unpublish，之后只能 deprecate。
    •
