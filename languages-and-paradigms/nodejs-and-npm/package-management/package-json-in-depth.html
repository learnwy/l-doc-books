深入 package.json

package.json 的角色

package.json 是每个 Node.js 项目的核心配置文件。它不仅描述了项目的基本信息和依赖关系，还定义了入口点、脚本命令、导出映射等关键配置。一个精心配置的 package.json 是高质量 npm 包的基础。

基础字段

{
  "name": "@scope/my-package",
  "version": "1.2.3",
  "description": "一个优秀的 Node.js 工具库",
  "keywords": ["nodejs", "utility", "tools"],
  "license": "MIT",
  "author": {
    "name": "张三",
    "email": "zhangsan@example.com",
    "url": "https://zhangsan.dev"
  },
  "repository": {
    "type": "git",
    "url": "https://github.com/user/my-package.git"
  },
  "bugs": {
    "url": "https://github.com/user/my-package/issues"
  },
  "homepage": "https://my-package.dev"
}
字段 必填 说明
name 是 包名，可带 @scope 前缀
version 是 语义化版本号
description 推荐 简短描述，影响 npm 搜索结果
keywords 推荐 关键词数组，影响搜索排名
license 推荐 开源许可证标识符
author 推荐 作者信息（字符串或对象）

入口点配置

main、module 和 types

{
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  "type": "module"
}
字段 用途 消费者
main CommonJS 入口 require() 调用时使用
module ESM 入口（非官方） 打包工具（webpack、rollup）
types TypeScript 类型声明入口 TypeScript 编译器
type 模块类型声明 Node.js 运行时

exports —— 现代入口映射

exports 字段是 Node.js 12+ 引入的模块入口映射机制，它比 main 更强大、更精确：

{
  "exports": {
    ".": {
      "import": {
        "types": "./dist/index.d.mts",
        "default": "./dist/index.mjs"
      },
      "require": {
        "types": "./dist/index.d.cts",
        "default": "./dist/index.cjs"
      }
    },
    "./utils": {
      "import": "./dist/utils.mjs",
      "require": "./dist/utils.cjs"
    },
    "./package.json": "./package.json"
  }
}
重要规则：当 exports 存在时，只有 exports 中明确列出的路径可以被外部导入。未列出的路径（如内部实现文件）对外不可见——这提供了真正的封装性。


imports —— 内部路径映射
{
  "imports": {
    "#config": "./src/config.ts",
    "#utils/*": "./src/utils/*.ts",
    "#db": {
      "development": "./src/db/sqlite.ts",
      "production": "./src/db/postgres.ts"
    }
  }
}
import { loadConfig } from '#config';
import { formatDate } from '#utils/date';
imports 映射以 # 开头，只在包内部使用，支持条件导出。




scripts 字段
{
  "scripts": {
    "dev": "tsx watch src/index.ts",
    "build": "tsup src/index.ts --format cjs,esm --dts",
    "test": "vitest run",
    "test:watch": "vitest",
    "lint": "eslint src/",
    "lint:fix": "eslint src/ --fix",
    "typecheck": "tsc --noEmit",
    "prepublishOnly": "npm run build && npm run test",
    "preversion": "npm run lint && npm run typecheck",
    "postversion": "git push && git push --tags"
  }
}

依赖声明
dependencies 与 devDependencies
{
  "dependencies": {
    "express": "^4.18.0",
    "zod": "^3.22.0"
  },
  "devDependencies": {
    "typescript": "^5.3.0",
    "@types/express": "^4.17.0",
    "vitest": "^1.0.0",
    "tsup": "^8.0.0"
  }
}
判断标准：如果包的代码在运行时被执行，放 dependencies；如果只在开发/构建/测试时使用，放 devDependencies。


peerDependencies
{
  "name": "eslint-plugin-custom",
  "peerDependencies": {
    "eslint": "^8.0.0 || ^9.0.0"
  },
  "peerDependenciesMeta": {
    "eslint": {
      "optional": false
    }
  }
}
peerDependencies 声明"我的包需要宿主项目安装这个依赖"。常用于插件系统：ESLint 插件依赖 ESLint、React 组件库依赖 React 等。


overrides
{
  "overrides": {
    "semver": "7.5.4",
    "trim@<0.0.3": "0.0.3",
    "express": {
      "cookie": "0.6.0"
    }
  }
}
overrides 可以强制覆盖嵌套依赖的版本，常用于修复安全漏洞。




发布相关配置
files 字段
{
  "files": ["dist/", "LICENSE", "README.md"]
}
files 字段是发布时的白名单——只有列出的文件/目录会被包含在 npm 包中。这比 .npmignore 更安全可靠。


engines 字段
{
  "engines": {
    "node": ">=18.0.0",
    "npm": ">=9.0.0"
  },
  "engineStrict": false
}
publishConfig
{
  "publishConfig": {
    "access": "public",
    "registry": "https://registry.npmjs.org/"
  }
}
对于 @scope/package 形式的包，默认是 private，需要显式设置 access: "public" 才能发布为公开包。




现代 package.json 最佳实践
{
  "name": "@myorg/toolkit",
  "version": "2.0.0",
  "type": "module",
  "exports": {
    ".": {
      "import": {
        "types": "./dist/index.d.mts",
        "default": "./dist/index.mjs"
      },
      "require": {
        "types": "./dist/index.d.cts",
        "default": "./dist/index.cjs"
      }
    }
  },
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.mts",
  "files": ["dist/"],
  "scripts": {
    "build": "tsup",
    "test": "vitest run",
    "prepublishOnly": "npm run build && npm run test"
  },
  "engines": {
    "node": ">=18"
  },
  "sideEffects": false
}
sideEffects: false 告诉打包工具这个包的所有模块都没有副作用，可以安全地进行 Tree-Shaking。




小结
    

  • package.json 是 Node.js 项目的核心配置文件，定义了元数据、入口、依赖和脚本。
    • 

  • exports 字段是现代包的入口映射标准，提供精确的路径控制和封装性。
    • 

  • imports 以 # 开头，用于包内部的路径映射和条件导出。
    • 

  • 生命周期钩子（prepare、prepublishOnly 等）可以自动化构建和发布流程。
    • 

  • files 白名单确保只发布必要的文件，engines 声明运行环境要求。
    • 

  • 现代库应同时支持 CJS 和 ESM，通过 exports 的条件导出实现。
    •
