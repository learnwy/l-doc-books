模块系统：CommonJS 与 ESM

模块化的意义

模块化是现代软件工程的基石。在 Node.js 的发展历程中，模块系统经历了从 CommonJS（CJS）到 ECMAScript Modules（ESM）的演进。理解这两种模块系统的设计哲学、运行机制和实践差异，对于编写可维护的 Node.js 应用至关重要。



CommonJS 模块系统
CommonJS 是 Node.js 最初采用的模块规范。它使用 require() 函数加载模块，使用 module.exports 或 exports 导出内容。


基本用法
const fs = require('node:fs');
const { join } = require('node:path');

function readConfig(filename: string): Record<string, unknown> {
  const filepath = join(process.cwd(), filename);
  const content = fs.readFileSync(filepath, 'utf-8');
  return JSON.parse(content);
}

module.exports = { readConfig };

模块缓存机制
CommonJS 的一个核心特性是模块缓存。模块在第一次 require 时被加载和执行，之后的 require 调用会返回缓存的 module.exports 对象：


let callCount = 0;
callCount++;
console.log(`模块被加载了 ${callCount} 次`);

module.exports = { callCount };
const a = require('./counter');
const b = require('./counter');

console.log(a === b);
console.log(a.callCount);
模块只会被执行一次，a 和 b 引用的是同一个对象。这个特性使得 CommonJS 模块天然具有单例行为。


循环依赖处理
CommonJS 对循环依赖的处理比较宽容——它返回未完成的 exports 对象：


console.log('a.ts 开始加载');
const b = require('./b');
console.log(`a.ts 中获取到 b.done = ${b.done}`);
module.exports = { done: true };
console.log('a.ts 加载完成');
console.log('b.ts 开始加载');
const a = require('./a');
console.log(`b.ts 中获取到 a.done = ${a.done}`);
module.exports = { done: true };
console.log('b.ts 加载完成');
执行 require('./a') 的输出：


a.ts 开始加载
b.ts 开始加载
b.ts 中获取到 a.done = undefined   // a 尚未完成加载
b.ts 加载完成
a.ts 中获取到 b.done = true
a.ts 加载完成


ECMAScript Modules (ESM)
ESM 是 JavaScript 的官方标准模块系统。它使用 import 和 export 语法，具有静态分析能力和异步加载特性。


启用 ESM 的方式
在 Node.js 中使用 ESM 有两种方式：






方式
说明





文件扩展名 .mjs
单个文件使用 ESM




package.json 设置 "type": "module"
整个项目默认使用 ESM





基本用法
import fs from 'node:fs/promises';
import { join, resolve } from 'node:path';
import { fileURLToPath } from 'node:url';

const __filename = fileURLToPath(import.meta.url);
const __dirname = join(__filename, '..');

export async function readConfig(filename: string): Promise<Record<string, unknown>> {
  const filepath = resolve(__dirname, filename);
  const content = await fs.readFile(filepath, 'utf-8');
  return JSON.parse(content);
}

export default class ConfigManager {
  private cache = new Map<string, Record<string, unknown>>();

  async get(name: string): Promise<Record<string, unknown>> {
    if (!this.cache.has(name)) {
      this.cache.set(name, await readConfig(name));
    }
    return this.cache.get(name)!;
  }
}
静态分析与 Tree-Shaking
ESM 最重要的技术优势是静态分析能力。import 和 export 语句必须出现在模块的顶层，不能放在条件语句或函数内部：


import { readFile } from 'node:fs/promises';

export function processFile(path: string): Promise<string> {
  return readFile(path, 'utf-8');
}

export function unusedFunction(): void {
  console.log('这个函数没有被任何地方导入');
}
打包工具（如 Rollup、esbuild）可以在构建时静态分析 import 图谱，移除 unusedFunction 等未被使用的导出——这就是 Tree-Shaking。CommonJS 的动态 require() 调用无法实现这种优化。


动态导入
虽然 ESM 的 import 声明是静态的，但 ESM 也支持动态导入——import() 表达式返回一个 Promise：


async function loadPlugin(name: string): Promise<Record<string, Function>> {
  const plugin = await import(`./plugins/${name}.js`);
  return plugin;
}

async function conditionalLoad(env: string): Promise<void> {
  if (env === 'development') {
    const { devTools } = await import('./dev-tools.js');
    devTools.init();
  }
}

活绑定 vs 值拷贝
这是 CJS 和 ESM 最本质的区别之一：


export let count = 0;

export function increment(): void {
  count++;
}
import { count, increment } from './counter.js';

console.log(count);
increment();
console.log(count);
在 ESM 中，count 是一个活绑定——导入方看到的总是导出方的最新值。而在 CommonJS 中，require 返回的是值的拷贝，修改导出方的变量不会影响导入方。




互操作性
在从 CJS 迁移到 ESM 的过渡期，经常需要处理两种模块系统的互操作：


import cjsModule from './legacy-module.cjs';

const { specificExport } = await import('./legacy-module.cjs');
async function loadEsmFromCjs(): Promise<void> {
  const esmModule = await import('./modern-module.mjs');
  console.log(esmModule.default);
}

loadEsmFromCjs();
关键规则：


    

  • ESM 可以 import CJS 模块（CJS 的 module.exports 作为默认导出）
    • 

  • CJS 不能 require ESM 模块（必须使用动态 import()）
    • 

  • 发布 npm 包时可以通过 package.json 的 exports 字段同时支持两种格式
    • 



{
  "name": "my-library",
  "exports": {
    ".": {
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    }
  }
}


迁移策略
从 CommonJS 迁移到 ESM 的推荐步骤：


import { readFileSync } from 'node:fs';
import { fileURLToPath } from 'node:url';
import { dirname, join } from 'node:path';

const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);

const pkg = JSON.parse(readFileSync(join(__dirname, 'package.json'), 'utf-8'));


小结
    

  • CommonJS 是 Node.js 的传统模块系统，使用 require/module.exports，同步加载，运行时解析。
    • 

  • ESM 是 JavaScript 的标准模块系统，使用 import/export，静态分析，支持 Tree-Shaking 和顶级 await。
    • 

  • ESM 使用活绑定（Live Binding），CJS 使用值拷贝——这是最本质的行为差异。
    • 

  • 新项目推荐使用 ESM；库作者应通过 package.json exports 字段支持双格式。
    • 

  • ESM 可以导入 CJS，但 CJS 只能通过动态 import() 加载 ESM。
