Node.js 架构与事件循环

Node.js 整体架构

Node.js 是一个基于 Chrome V8 引擎构建的 JavaScript 运行时环境。它的设计目标是提供一个高效、轻量的平台来构建可扩展的网络应用。Node.js 的架构分为多个层次，每一层都承担着不同的职责。

从上到下，Node.js 的架构可以分为三层：

单线程与事件驱动模型
Node.js 采用单线程事件驱动的并发模型。这意味着主线程（也称为事件循环线程）只有一个，所有的 JavaScript 代码都在这个单线程上执行。


这个设计带来了几个关键特性：


import http from 'node:http';

const server = http.createServer((req, res) => {
  if (req.url === '/fast') {
    res.end('快速响应');
  }

  if (req.url === '/slow') {
    setTimeout(() => {
      res.end('延迟响应');
    }, 1000);
  }
});

server.listen(3000);
在上面的例子中，/slow 路由不会阻塞 /fast 路由。当 setTimeout 被调用时，Node.js 将定时器注册到事件循环中，主线程立即继续处理下一个请求。定时器到期后，回调函数被放入事件队列等待执行。




事件循环的六个阶段
事件循环是 Node.js 异步模型的核心引擎。它不是一个简单的 while(true) 循环，而是由六个精心设计的阶段组成的处理管线。


各阶段详解
Timers 阶段：执行 setTimeout() 和 setInterval() 的回调函数。注意，定时器的时间阈值是"最小延迟"，不是精确时间。


Poll 阶段：这是事件循环中最关键的阶段。它负责获取新的 I/O 事件，执行与 I/O 相关的回调。如果队列为空，Poll 阶段会阻塞等待新事件，直到有定时器到期或有新的 I/O 事件到来。


Check 阶段：专门用于执行 setImmediate() 的回调。setImmediate 保证在当前 Poll 阶段结束后立即执行。


执行顺序验证
import { setTimeout, setImmediate } from 'node:timers';

console.log('1. 同步代码开始');

setTimeout(() => {
  console.log('5. setTimeout 回调');
}, 0);

setImmediate(() => {
  console.log('6. setImmediate 回调');
});

process.nextTick(() => {
  console.log('3. process.nextTick 回调');
});

Promise.resolve().then(() => {
  console.log('4. Promise.then 回调');
});

console.log('2. 同步代码结束');
执行结果的顺序是确定的（3 和 4 始终在 5 和 6 之前），因为微任务（nextTick 和 Promise）在每个阶段转换之间都会被清空。




微任务与宏任务
Node.js 中的异步任务分为两大类：微任务（Microtask）和宏任务（Macrotask）。微任务总是优先于宏任务执行。

function demonstratePriority(): void {
  setImmediate(() => console.log('setImmediate'));

  setTimeout(() => console.log('setTimeout'), 0);

  Promise.resolve().then(() => {
    console.log('Promise (微任务)');
    process.nextTick(() => console.log('nextTick 嵌套在 Promise 中'));
  });

  process.nextTick(() => {
    console.log('nextTick (最高优先级微任务)');
    Promise.resolve().then(() => console.log('Promise 嵌套在 nextTick 中'));
  });
}

demonstratePriority();
关键规则：在事件循环的每个阶段切换时，Node.js 会先清空所有 process.nextTick 队列，然后清空所有 Promise 微任务队列，最后才进入下一个阶段。




setTimeout 与 setImmediate 的竞态
在主模块的顶层代码中，setTimeout(fn, 0) 和 setImmediate(fn) 的执行顺序是不确定的，因为这取决于系统的时钟精度：


setTimeout(() => console.log('timeout'), 0);
setImmediate(() => console.log('immediate'));
但在 I/O 回调内部，setImmediate 总是先于 setTimeout 执行：


import fs from 'node:fs';

fs.readFile(__filename, () => {
  setTimeout(() => console.log('timeout'), 0);
  setImmediate(() => console.log('immediate'));
});


事件循环阻塞与防护
单线程模型最大的风险是事件循环阻塞。任何耗时的同步操作都会冻结整个应用。


function blockingOperation(): void {
  const start = Date.now();
  while (Date.now() - start < 5000) {
    // 阻塞 5 秒 —— 整个服务器在此期间无法响应任何请求
  }
}

function nonBlockingAlternative(iterations: number): Promise<number> {
  return new Promise((resolve) => {
    let result = 0;
    let i = 0;
    const batchSize = 10000;

    function processBatch(): void {
      const end = Math.min(i + batchSize, iterations);
      for (; i < end; i++) {
        result += Math.sqrt(i);
      }
      if (i < iterations) {
        setImmediate(processBatch);
      } else {
        resolve(result);
      }
    }

    processBatch();
  });
}
防护策略：


    

  • 将 CPU 密集型任务分解为小批次，用 setImmediate 让出事件循环
    • 

  • 使用 worker_threads 将计算任务分配到独立线程
    • 

  • 避免使用同步版本的 I/O API（如 fs.readFileSync）
    • 

  • 监控事件循环延迟，设置告警阈值
    • 





小结
    

  • Node.js 采用分层架构：应用层 → 核心库 → V8 + libuv + 其他 C/C++ 库。
    • 

  • 单线程事件驱动模型是 Node.js 的核心特征，适合 I/O 密集型场景。
    • 

  • 事件循环由六个阶段组成：Timers → Pending → Idle → Poll → Check → Close。
    • 

  • 微任务（nextTick、Promise）在每个阶段之间被优先清空。
    • 

  • 避免阻塞事件循环是 Node.js 编程的第一原则。
    •
