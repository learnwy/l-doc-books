回调与 Promise

回调函数：异步编程的起点

回调函数（Callback）是 Node.js 最早的异步编程模式。Node.js 的核心 API 几乎都遵循Error-First 回调约定：回调函数的第一个参数是错误对象，第二个参数是结果数据。

import fs from 'node:fs';

fs.readFile('/etc/hosts', 'utf-8', (err: NodeJS.ErrnoException | null, data?: string) => {
  if (err) {
    console.error('读取失败:', err.message);
    return;
  }
  console.log('文件内容:', data);
});

Error-First 约定

这个约定不仅仅是风格偏好，而是整个 Node.js 生态系统的契约：

type NodeCallback<T> = (error: Error | null, result?: T) => void;

function readJsonFile(path: string, callback: NodeCallback<Record<string, unknown>>): void {
  fs.readFile(path, 'utf-8', (err, data) => {
    if (err) {
      callback(err);
      return;
    }
    try {
      const parsed = JSON.parse(data!);
      callback(null, parsed);
    } catch (parseError) {
      callback(parseError as Error);
    }
  });
}

回调地狱

当多个异步操作存在依赖关系时，回调函数会不断嵌套，形成所谓的"回调地狱"（Callback Hell）：

fs.readFile('config.json', 'utf-8', (err, configData) => {
  if (err) return handleError(err);
  const config = JSON.parse(configData!);

  fs.readFile(config.dataFile, 'utf-8', (err, rawData) => {
    if (err) return handleError(err);

    processData(rawData!, (err, processed) => {
      if (err) return handleError(err);

      fs.writeFile('output.json', JSON.stringify(processed), (err) => {
        if (err) return handleError(err);
        console.log('处理完成');
      });
    });
  });
});

function handleError(err: Error): void {
  console.error('操作失败:', err.message);
}

回调地狱带来的问题不仅仅是缩进——它让错误处理变得冗余、让代码逻辑难以追踪、让资源清理（如关闭文件句柄）容易遗漏。

Promise 的本质

Promise 是对"未来某个时刻将会完成的异步操作"的抽象。一个 Promise 对象有三种状态：

含义
转换条件

已成功

rejected
已失败

创建 Promise
function readFileAsync(path: string): Promise<string> {
  return new Promise((resolve, reject) => {
    fs.readFile(path, 'utf-8', (err, data) => {
      if (err) {
        reject(err);
      } else {
        resolve(data!);
      }
    });
  });
}
Node.js 也提供了内置的 promisify 工具和 Promise 版本的 API：


import { promisify } from 'node:util';
import fs from 'node:fs';
import fsPromises from 'node:fs/promises';

const readFile = promisify(fs.readFile);

const data1 = await readFile('config.json', 'utf-8');

const data2 = await fsPromises.readFile('config.json', 'utf-8');


Promise 链式调用
Promise 最强大的特性是链式调用。每个 .then() 返回一个新的 Promise，形成处理管线：


import fsPromises from 'node:fs/promises';

function processPipeline(configPath: string): Promise<void> {
  return fsPromises
    .readFile(configPath, 'utf-8')
    .then((configData) => JSON.parse(configData))
    .then((config) => fsPromises.readFile(config.dataFile, 'utf-8'))
    .then((rawData) => transform(rawData))
    .then((processed) => fsPromises.writeFile('output.json', JSON.stringify(processed)))
    .then(() => console.log('处理完成'));
}

function transform(data: string): Record<string, unknown> {
  return { result: data.toUpperCase(), timestamp: Date.now() };
}
对比回调版本，Promise 链将嵌套的金字塔结构拉平为线性的处理流程。


值的穿透
.then() 回调的返回值决定了下一个 .then() 接收的参数：


Promise.resolve(1)
  .then((val) => val + 1)
  .then((val) => val * 3)
  .then((val) => console.log(val));

Promise.resolve('hello')
  .then((val) => Promise.resolve(val.toUpperCase()))
  .then((val) => console.log(val));
如果 .then() 返回一个 Promise，链会等待该 Promise 解决后再继续。




Promise 错误处理
Promise 的错误处理通过 .catch() 实现，它捕获链中任何环节抛出的错误：


function robustPipeline(url: string): Promise<void> {
  return fetch(url)
    .then((response) => {
      if (!response.ok) {
        throw new Error(`HTTP ${response.status}: ${response.statusText}`);
      }
      return response.json();
    })
    .then((data) => validateData(data))
    .then((validated) => saveToDatabase(validated))
    .catch((err: Error) => {
      console.error('管线失败:', err.message);
      reportError(err);
    })
    .finally(() => {
      console.log('管线执行结束（无论成功失败）');
    });
}

function validateData(data: unknown): Record<string, unknown> {
  if (!data || typeof data !== 'object') {
    throw new Error('数据格式无效');
  }
  return data as Record<string, unknown>;
}

function saveToDatabase(data: Record<string, unknown>): Promise<void> {
  return Promise.resolve();
}

function reportError(err: Error): void {
  console.error('上报错误:', err.message);
}
未捕获的 Promise 拒绝
Node.js 对未处理的 Promise 拒绝非常严格——从 Node.js 15 开始，未捕获的 Promise 拒绝会导致进程退出：


process.on('unhandledRejection', (reason: unknown, promise: Promise<unknown>) => {
  console.error('未处理的 Promise 拒绝:', reason);
});

process.on('rejectionHandled', (promise: Promise<unknown>) => {
  console.log('之前未处理的 Promise 拒绝已被处理');
});


Promise 静态方法
Promise 提供了多个静态方法用于组合多个异步操作：


Promise.all —— 全部成功才成功
async function fetchAllUserData(userId: string): Promise<{
  profile: unknown;
  posts: unknown;
  notifications: unknown;
}> {
  const [profile, posts, notifications] = await Promise.all([
    fetch(`/api/users/${userId}`).then((r) => r.json()),
    fetch(`/api/users/${userId}/posts`).then((r) => r.json()),
    fetch(`/api/users/${userId}/notifications`).then((r) => r.json()),
  ]);

  return { profile, posts, notifications };
}
Promise.allSettled —— 等待全部完成
interface SettledResult<T> {
  status: 'fulfilled' | 'rejected';
  value?: T;
  reason?: Error;
}

async function batchProcess(urls: string[]): Promise<void> {
  const results = await Promise.allSettled(urls.map((url) => fetch(url).then((r) => r.json())));

  const succeeded = results.filter((r) => r.status === 'fulfilled');
  const failed = results.filter((r) => r.status === 'rejected');

  console.log(`成功: ${succeeded.length}, 失败: ${failed.length}`);
}
Promise.race —— 取最快的
function fetchWithTimeout<T>(promise: Promise<T>, ms: number): Promise<T> {
  const timeout = new Promise<never>((_, reject) => {
    setTimeout(() => reject(new Error(`操作超时 (${ms}ms)`)), ms);
  });

  return Promise.race([promise, timeout]);
}

const data = await fetchWithTimeout(
  fetch('https://api.example.com/data').then((r) => r.json()),
  5000,
);
Promise.any —— 取第一个成功的
async function fetchFromMirrors(mirrors: string[]): Promise<unknown> {
  return Promise.any(mirrors.map((url) => fetch(url).then((r) => r.json())));
}

从回调到 Promise 的迁移
Node.js 提供了 util.promisify 工具将 Error-First 回调风格的函数转换为 Promise 版本：


import { promisify } from 'node:util';
import { exec } from 'node:child_process';
import dns from 'node:dns';

const execAsync = promisify(exec);
const dnsResolve = promisify(dns.resolve);

async function getSystemInfo(): Promise<void> {
  const { stdout } = await execAsync('uname -a');
  console.log('系统信息:', stdout.trim());

  const addresses = await dnsResolve('google.com');
  console.log('DNS 解析:', addresses);
}
对于自定义的回调函数，也可以手动封装：


function callbackApi(input: string, cb: (err: Error | null, result?: string) => void): void {
  setTimeout(() => cb(null, input.toUpperCase()), 100);
}

function promisifiedApi(input: string): Promise<string> {
  return new Promise((resolve, reject) => {
    callbackApi(input, (err, result) => {
      if (err) reject(err);
      else resolve(result!);
    });
  });
}


小结
    

  • Error-First 回调是 Node.js 最原始的异步模式，但会导致回调地狱。
    • 

  • Promise 将异步操作抽象为三种状态（pending / fulfilled / rejected），支持链式调用。
    • 

  • .catch() 可以捕获 Promise 链中任何环节的错误，.finally() 用于必要的清理操作。
    • 

  • Promise.all、Promise.allSettled、Promise.race、Promise.any 提供了灵活的异步组合能力。
    • 

  • util.promisify 和 node:fs/promises 让旧的回调 API 也能以 Promise 方式使用。
    • 

  • 从 Node.js 15 开始，未捕获的 Promise 拒绝会导致进程退出——必须总是处理错误。
