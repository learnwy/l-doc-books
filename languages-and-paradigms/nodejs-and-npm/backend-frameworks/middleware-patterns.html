中间件模式

什么是中间件

中间件（Middleware）是 Node.js Web 框架中最核心的设计模式。它是一个函数，可以访问请求对象、响应对象以及请求-响应周期中的下一个中间件函数。中间件可以执行任何代码、修改请求/响应对象、终止请求-响应周期，或调用下一个中间件。



Express 线性中间件模型
Express 的中间件按照注册顺序依次执行，通过 next() 将控制权传递给下一个中间件：


import express, { Request, Response, NextFunction } from 'express';

const app = express();

app.use((req: Request, res: Response, next: NextFunction) => {
  console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`);
  next();
});

app.use((req: Request, res: Response, next: NextFunction) => {
  const token = req.headers.authorization?.replace('Bearer ', '');
  if (!token) {
    res.status(401).json({ error: '未提供认证令牌' });
    return;
  }
  (req as any).userId = 'user-from-token';
  next();
});

app.get('/api/data', (req: Request, res: Response) => {
  res.json({ data: 'hello', user: (req as any).userId });
});

app.listen(3000);
Express 中间件的执行是单向的——一旦 next() 被调用，控制权就不会再回到当前中间件（除非使用错误处理中间件）。




Koa 洋葱模型
Koa 的中间件模型是一个洋葱结构——请求从外到内穿过每个中间件的"前半部分"，到达核心处理器后，响应从内到外穿过每个中间件的"后半部分"：


import Koa from 'koa';

const app = new Koa();

app.use(async (ctx, next) => {
  console.log('→ 中间件 1 进入');
  const start = Date.now();
  await next();
  const ms = Date.now() - start;
  console.log(`← 中间件 1 返回 (${ms}ms)`);
  ctx.set('X-Response-Time', `${ms}ms`);
});

app.use(async (ctx, next) => {
  console.log('  → 中间件 2 进入');
  await next();
  console.log('  ← 中间件 2 返回');
});

app.use(async (ctx) => {
  console.log('    ◆ 核心处理');
  ctx.body = { message: 'Hello' };
});

app.listen(3000);
执行输出：


→ 中间件 1 进入
  → 中间件 2 进入
    ◆ 核心处理
  ← 中间件 2 返回
← 中间件 1 返回 (2ms)


实现中间件组合函数
理解中间件模式的最好方式是实现 Koa 的 compose 函数：


type Middleware<T> = (ctx: T, next: () => Promise<void>) => Promise<void>;

function compose<T>(middlewares: Middleware<T>[]): Middleware<T> {
  return function (ctx: T, next?: () => Promise<void>) {
    let index = -1;

    function dispatch(i: number): Promise<void> {
      if (i <= index) {
        return Promise.reject(new Error('next() 被多次调用'));
      }
      index = i;

      const fn = i === middlewares.length ? next : middlewares[i];
      if (!fn) return Promise.resolve();

      try {
        return Promise.resolve(fn(ctx, () => dispatch(i + 1)));
      } catch (err) {
        return Promise.reject(err);
      }
    }

    return dispatch(0);
  };
}
这段代码简洁但精妙：


    

  1. dispatch(0) 开始执行第一个中间件
    2. 

  2. 每个中间件通过 next() 触发 dispatch(i + 1)
    3. 

  3. 当最内层的中间件完成后，Promise 链自内向外依次 resolve
    4. 

  4. 多次调用 next() 会被检测并报错
    5.

import { Hono } from 'hono';

const app = new Hono();

app.use('*', async (c, next) => {
  const start = Date.now();

  const path = c.req.path;

  const duration = Date.now() - start;

认证中间件
import { Hono, Context, Next } from 'hono';
import { HTTPException } from 'hono/http-exception';

interface AuthContext {
  userId: string;
  role: string;
}

async function authMiddleware(c: Context, next: Next): Promise<void> {
  const token = c.req.header('Authorization')?.replace('Bearer ', '');

  if (!token) {
    throw new HTTPException(401, { message: '缺少认证令牌' });
  }

  const payload = await verifyToken(token);
  c.set('auth', payload);
  await next();
}

function requireRole(...roles: string[]) {
  return async (c: Context, next: Next): Promise<void> => {
    const auth = c.get('auth') as AuthContext;
    if (!roles.includes(auth.role)) {
      throw new HTTPException(403, { message: '权限不足' });
    }
    await next();
  };
}

async function verifyToken(token: string): Promise<AuthContext> {
  return { userId: 'user-1', role: 'admin' };
}

const app = new Hono();

app.use('/api/*', authMiddleware);
app.use('/api/admin/*', requireRole('admin'));

app.get('/api/profile', (c) => {
  const auth = c.get('auth') as AuthContext;
  return c.json({ userId: auth.userId });
});

app.get('/api/admin/dashboard', (c) => {
  return c.json({ dashboard: 'admin only' });
});
限流中间件
class RateLimiter {
  private requests = new Map<string, { count: number; resetAt: number }>();

  constructor(
    private maxRequests: number,
    private windowMs: number,
  ) {}

  check(key: string): { allowed: boolean; remaining: number; resetAt: number } {
    const now = Date.now();
    const record = this.requests.get(key);

    if (!record || now > record.resetAt) {
      this.requests.set(key, { count: 1, resetAt: now + this.windowMs });
      return { allowed: true, remaining: this.maxRequests - 1, resetAt: now + this.windowMs };
    }

    if (record.count >= this.maxRequests) {
      return { allowed: false, remaining: 0, resetAt: record.resetAt };
    }

    record.count++;
    return { allowed: true, remaining: this.maxRequests - record.count, resetAt: record.resetAt };
  }
}

function rateLimitMiddleware(maxRequests: number, windowMs: number) {
  const limiter = new RateLimiter(maxRequests, windowMs);

  return async (c: Context, next: Next): Promise<void> => {
    const key = c.req.header('X-Forwarded-For') || 'unknown';
    const result = limiter.check(key);

    c.header('X-RateLimit-Limit', String(maxRequests));
    c.header('X-RateLimit-Remaining', String(result.remaining));
    c.header('X-RateLimit-Reset', String(Math.ceil(result.resetAt / 1000)));

    if (!result.allowed) {
      throw new HTTPException(429, { message: '请求过于频繁' });
    }

    await next();
  };
}
错误处理中间件
import { Hono } from 'hono';
import { HTTPException } from 'hono/http-exception';

const app = new Hono();

app.onError((err, c) => {
  if (err instanceof HTTPException) {
    return c.json({ error: err.message, status: err.status }, err.status);
  }

  console.error('未预期的错误:', err);
  return c.json({ error: '服务器内部错误', status: 500 }, 500);
});

app.notFound((c) => {
  return c.json({ error: '资源不存在', status: 404 }, 404);
});


中间件栈设计
生产环境中的中间件栈通常按以下顺序组织：


import { Hono } from 'hono';
import { cors } from 'hono/cors';
import { logger } from 'hono/logger';
import { secureHeaders } from 'hono/secure-headers';
import { compress } from 'hono/compress';
import { timing } from 'hono/timing';
import { requestId } from 'hono/request-id';

const app = new Hono();

app.use('*', requestId());
app.use('*', logger());
app.use('*', secureHeaders());
app.use('*', cors());
app.use('*', compress());
app.use('*', timing());

export default app;
设计原则




原则
说明





单一职责
每个中间件只做一件事




从通用到特殊
全局中间件在前，路由中间件在后




安全优先
安全相关中间件尽早执行




性能优先
耗时操作（如认证）应在快速检查（如限流）之后




可组合
中间件之间不应有隐式依赖




可配置
通过工厂函数参数化中间件行为







中间件工厂模式
interface CacheOptions {
  maxAge: number;
  staleWhileRevalidate?: number;
  private?: boolean;
}

function cache(options: CacheOptions) {
  return async (c: Context, next: Next): Promise<void> => {
    await next();

    const directives: string[] = [];
    if (options.private) {
      directives.push('private');
    } else {
      directives.push('public');
    }
    directives.push(`max-age=${options.maxAge}`);
    if (options.staleWhileRevalidate) {
      directives.push(`stale-while-revalidate=${options.staleWhileRevalidate}`);
    }

    c.header('Cache-Control', directives.join(', '));
  };
}

app.get('/api/static-data', cache({ maxAge: 3600, private: false }), (c) => {
  return c.json({ data: 'cached content' });
});

app.get('/api/user-data', cache({ maxAge: 60, private: true }), (c) => {
  return c.json({ data: 'private content' });
});


小结
    

  • 中间件是 Node.js Web 框架的核心抽象，每个中间件负责请求处理链中的一个环节。
    • 

  • Express 使用线性模型（单向），Koa/Hono 使用洋葱模型（双向）。
    • 

  • 洋葱模型让中间件可以在 await next() 前后分别执行逻辑。
    • 

  • compose 函数是中间件组合的核心实现，理解它就理解了中间件的本质。
    • 

  • 生产环境的中间件栈应遵循"从通用到特殊、安全优先、性能优先"的原则。
    • 

  • 中间件工厂模式通过闭包参数化中间件行为，提高复用性和灵活性。
    •
