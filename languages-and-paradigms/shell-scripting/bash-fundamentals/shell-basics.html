Shell 基础入门

核心概念

Shell 是用户与操作系统内核之间的命令行接口，它既是一种命令解释器，也是一种功能强大的脚本编程语言。在 Unix/Linux 系统中，Shell 扮演着将用户输入的文本命令翻译为系统调用的核心角色。理解 Shell 的工作机制，是掌握 Linux 系统管理和 DevOps 自动化的第一步。

现代 Linux 系统中最常见的 Shell 是 Bash（Bourne Again Shell），它继承了 Bourne Shell（sh）的语法，并融合了 C Shell 和 Korn Shell 的诸多优秀特性。除此之外，Zsh、Fish 等新一代 Shell 也在开发者群体中日益流行。

Shell 的启动与初始化
Shell 的启动过程涉及多个配置文件的加载，理解这一流程对于正确配置环境变量和别名至关重要。Shell 分为 login shell 和 non-login shell 两种模式，它们加载的配置文件不同。


login shell 的启动顺序：首先读取 /etc/profile（系统全局配置），然后按顺序查找用户目录下的 ~/.bash_profile、~/.bash_login、~/.profile，找到第一个存在的文件后停止查找。non-login shell（如在终端模拟器中打开新标签页）则只读取 ~/.bashrc。


#!/bin/bash

echo "当前 Shell: $SHELL"
echo "Bash 版本: $BASH_VERSION"
echo "进程 ID: $$"
echo "父进程 ID: $PPID"

if shopt -q login_shell; then
    echo "这是一个 login shell"
else
    echo "这是一个 non-login shell"
fi

echo "配置文件加载顺序检测:"
echo "HOME=$HOME"
echo "PATH=$PATH"
交互式 Shell 和非交互式 Shell 的区分同样重要。交互式 Shell 等待用户输入命令，而非交互式 Shell 通常用于执行脚本文件。可以通过检查 $- 变量中是否包含 i 标志来判断：


case "$-" in
    *i*) echo "交互式 Shell" ;;
    *)   echo "非交互式 Shell" ;;
esac
命令执行机制
Shell 执行命令时遵循严格的解析和执行流程。首先进行词法分析（将输入拆分为 token），然后判断命令类型，最后执行并收集结果。


命令查找的优先级顺序为：别名（alias）→ 关键字（如 if、while）→ 函数（function）→ 内置命令（builtin）→ 外部命令（通过 PATH 查找）。可以使用 type 命令来确认一个命令的类型：


type cd          # cd is a shell builtin
type ls          # ls is /bin/ls (或 alias)
type if          # if is a shell keyword
type -a echo     # 列出所有匹配的 echo

which python3    # 只搜索 PATH，不含内置命令
command -v git   # POSIX 标准方式检查命令是否存在
子进程与环境继承是理解 Shell 行为的关键。当 Shell 执行外部命令时，会通过 fork() 创建子进程，子进程继承父进程的环境变量，但不继承局部变量：


MY_VAR="hello"
export MY_ENV="world"

bash -c 'echo "MY_VAR=$MY_VAR"'   # 输出为空，局部变量不继承
bash -c 'echo "MY_ENV=$MY_ENV"'   # 输出 world，环境变量会继承

(
    echo "子 Shell 中的 PID: $$"
    echo "子 Shell 中的 MY_VAR: $MY_VAR"  # 子 Shell 可以访问
)
管道与重定向
管道（pipe）和重定向（redirect）是 Shell 最强大的特性之一，它们实现了 Unix 哲学中"组合简单工具完成复杂任务"的理念。


标准文件描述符有三个：stdin（0）、stdout（1）、stderr（2）。重定向操作符可以改变这些文件描述符的指向：


ls /valid/path > output.txt 2> error.txt

ls /valid/path > all.txt 2>&1

ls /valid/path &> all.txt

cat << 'EOF' > config.txt
database_host=localhost
database_port=5432
EOF

read -r line < input.txt

exec 3> custom.log
echo "写入自定义文件描述符" >&3
exec 3>&-  # 关闭文件描述符 3
管道将前一个命令的 stdout 连接到后一个命令的 stdin，形成数据处理流水线。每个管道段都在独立的子进程中运行：


cat /var/log/syslog | grep "error" | sort | uniq -c | sort -rn | head -10

find /project -name "*.ts" | xargs wc -l | sort -n | tail -20

ps aux | awk '{print $1, $2, $11}' | column -t

ls -la /tmp | tee /dev/stderr | wc -l

echo "hello" | { read -r word; echo "got: $word"; }
进程替换（Process Substitution）是管道的高级形式，它用文件描述符替代临时文件：


diff <(ls /dir1) <(ls /dir2)

while IFS= read -r line; do
    echo "处理: $line"
done < <(find /path -name "*.log")

comm -13 <(sort file1.txt) <(sort file2.txt)
通配符与扩展
Shell 提供了丰富的扩展机制，在命令执行前对输入进行预处理。理解扩展的顺序和行为对于编写正确的脚本至关重要。


扩展的执行顺序为：花括号扩展 → 波浪号扩展 → 参数和变量扩展 → 命令替换 → 算术扩展 → 词分割 → 路径名扩展（通配符）。


echo {1..5}              # 1 2 3 4 5
echo {a..z}              # a b c ... z
echo file{1,2,3}.txt     # file1.txt file2.txt file3.txt
mkdir -p project/{src,test,docs}/{main,utils}

echo ~                   # /home/username
echo ~root               # /root

name="world"
echo "Hello ${name}"     # Hello world
echo "长度: ${#name}"     # 长度: 5
echo "${name^^}"          # WORLD（转大写）
echo "${name:0:3}"        # wor（子串截取）
通配符（Globbing）是路径名扩展的核心机制：


ls *.md                   # 匹配所有 .md 文件
ls file?.txt              # file1.txt, fileA.txt 等
ls [abc]*.log             # 以 a、b 或 c 开头的 .log 文件
ls [!0-9]*.txt            # 不以数字开头的 .txt 文件

shopt -s globstar
ls **/*.ts                # 递归匹配所有 .ts 文件

shopt -s extglob
ls !(*.log|*.tmp)         # 排除 .log 和 .tmp 文件
ls @(*.ts|*.tsx)          # 匹配 .ts 或 .tsx 文件
命令替换允许将命令的输出作为另一个命令的参数：


current_date=$(date +%Y-%m-%d)
file_count=$(find . -name "*.md" | wc -l)

echo "项目有 ${file_count} 个 Markdown 文件"
echo "Git 提交数: $(git rev-list --count HEAD)"

result=$((3 + 5 * 2))
echo "计算结果: $result"
echo "随机数: $((RANDOM % 100))"
小结
    

  • Shell 是用户与操作系统之间的命令行接口，Bash 是最广泛使用的 Shell 实现
    • 

  • Shell 分为 login/non-login 和交互式/非交互式四种组合模式，各自加载不同的配置文件
    • 

  • 命令查找遵循 alias → keyword → function → builtin → external 的优先级顺序
    • 

  • 管道将多个命令的 stdin/stdout 串联，实现数据流水线处理
    • 

  • 重定向可改变标准文件描述符（0/1/2）的指向，支持自定义文件描述符
    • 

  • Shell 扩展按照严格顺序执行：花括号 → 波浪号 → 变量 → 命令替换 → 算术 → 词分割 → 通配符
    • 

  • 进程替换（<(...) 和 >(...))是管道和临时文件的高级替代方案
    • 

  • 掌握这些基础机制是编写可靠 Shell 脚本的前提
    •
