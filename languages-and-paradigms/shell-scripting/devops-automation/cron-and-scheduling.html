Cron 与定时调度

核心概念

Cron 是 Unix/Linux 系统中最经典的任务调度工具，它允许用户在指定的时间点或时间间隔自动执行命令和脚本。对于 DevOps 工程师而言，Cron 是定时备份、日志清理、数据同步、健康检查等周期性任务的基础设施。理解 Cron 的调度机制、环境特性和常见陷阱，是编写可靠定时任务的前提。

现代 Linux 系统中还提供了 systemd timer 作为 Cron 的替代方案，它提供了更精确的调度控制、更好的日志集成和依赖管理能力。两者各有适用场景，可以根据需求选择。

Cron 表达式语法
Cron 表达式由 5 个时间字段组成，分别表示分钟、小时、日期、月份和星期：


# ┌───────────── 分钟 (0-59)
# │ ┌───────────── 小时 (0-23)
# │ │ ┌───────────── 日期 (1-31)
# │ │ │ ┌───────────── 月份 (1-12)
# │ │ │ │ ┌───────────── 星期 (0-7, 0和7都是周日)
# │ │ │ │ │
# * * * * *  command

0 2 * * *     # 每天凌晨 2:00
*/5 * * * *   # 每 5 分钟
0 */2 * * *   # 每 2 小时的整点
30 8 * * 1-5  # 工作日 8:30
0 0 1 * *     # 每月 1 号 0:00
0 0 * * 0     # 每周日 0:00
0 9,18 * * *  # 每天 9:00 和 18:00
0 0 1,15 * *  # 每月 1 号和 15 号
管理用户 crontab 的常用操作：


crontab -e        # 编辑当前用户的 crontab
crontab -l        # 列出当前用户的 crontab
crontab -r        # 删除当前用户的 crontab（危险！）

crontab -l > crontab_backup.txt     # 备份
crontab crontab_backup.txt          # 从文件恢复

echo "0 2 * * * /opt/scripts/backup.sh" | crontab -    # 从 stdin 设置
编写健壮的 Cron 任务
Cron 任务运行在一个极简的环境中，与交互式 Shell 环境有本质区别。必须理解并处理这些差异：


#!/usr/bin/env bash
set -euo pipefail

export PATH="/usr/local/bin:/usr/bin:/bin"
export HOME="/home/deploy"
export LANG="en_US.UTF-8"

readonly SCRIPT_NAME="$(basename "$0")"
readonly LOCK_FILE="/tmp/${SCRIPT_NAME}.lock"
readonly LOG_FILE="/var/log/cron/${SCRIPT_NAME}.log"

mkdir -p "$(dirname "$LOG_FILE")"

log() {
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] [$SCRIPT_NAME] $*" >> "$LOG_FILE"
}

exec >> "$LOG_FILE" 2>&1

if ! mkdir "$LOCK_FILE" 2>/dev/null; then
    local lock_pid
    lock_pid=$(cat "${LOCK_FILE}/pid" 2>/dev/null || echo "unknown")
    log "跳过执行: 锁文件存在 (PID: $lock_pid)"
    exit 0
fi
echo $$ > "${LOCK_FILE}/pid"

trap 'rm -rf "$LOCK_FILE"' EXIT

log "任务开始"

daily_backup() {
    local backup_dir="/backup/$(date +%Y%m%d)"
    mkdir -p "$backup_dir"

    pg_dump -h localhost -U app mydb | gzip > "${backup_dir}/mydb.sql.gz"

    tar czf "${backup_dir}/config.tar.gz" /etc/myapp/

    find /backup -maxdepth 1 -mtime +30 -exec rm -rf {} +

    log "备份完成: $backup_dir"
}

daily_backup

log "任务完成"
Crontab 条目应包含完整的路径和错误处理：


SHELL=/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin
MAILTO=ops@example.com

0 2 * * * /opt/scripts/backup.sh >> /var/log/cron/backup.log 2>&1

*/5 * * * * /opt/scripts/health-check.sh >> /var/log/cron/health.log 2>&1 || /opt/scripts/alert.sh "健康检查失败"

0 3 * * * /usr/bin/flock -n /tmp/cleanup.lock /opt/scripts/cleanup.sh

0 4 * * 0 /opt/scripts/weekly-report.sh 2>&1 | /usr/bin/logger -t weekly-report
并发控制与防重入
Cron 不会等待上一次执行完成就启动下一次，因此需要手动实现并发控制：


acquire_flock() {
    local lock_file="$1"
    local fd="${2:-200}"

    eval "exec ${fd}>\"${lock_file}\""

    if ! flock -n "$fd"; then
        echo "另一个实例正在运行，退出"
        exit 0
    fi
}

acquire_flock "/tmp/myjob.lock"

acquire_mkdir_lock() {
    local lock_dir="$1"
    local timeout="${2:-0}"
    local waited=0

    while ! mkdir "$lock_dir" 2>/dev/null; do
        if (( timeout > 0 && waited >= timeout )); then
            echo "获取锁超时" >&2
            return 1
        fi

        if [[ -f "${lock_dir}/pid" ]]; then
            local old_pid
            old_pid=$(cat "${lock_dir}/pid")
            if ! kill -0 "$old_pid" 2>/dev/null; then
                echo "清理陈旧锁 (PID: $old_pid)" >&2
                rm -rf "$lock_dir"
                continue
            fi
        fi

        sleep 1
        ((waited++))
    done

    echo $$ > "${lock_dir}/pid"
    trap 'rm -rf "'"$lock_dir"'"' EXIT
}

with_timeout() {
    local timeout=$1
    shift

    timeout "$timeout" "$@"
    local exit_code=$?

    if (( exit_code == 124 )); then
        echo "任务超时（${timeout}秒）" >&2
        return 1
    fi

    return $exit_code
}

with_timeout 3600 /opt/scripts/long-running-job.sh
systemd Timer 替代方案
systemd timer 提供了比 cron 更强大的调度能力：


# /etc/systemd/system/backup.service
[Unit]
Description=Daily Database Backup
After=postgresql.service

[Service]
Type=oneshot
User=deploy
ExecStart=/opt/scripts/backup.sh
StandardOutput=journal
StandardError=journal
TimeoutStartSec=3600
# /etc/systemd/system/backup.timer
[Unit]
Description=Run backup daily at 2am

[Timer]
OnCalendar=*-*-* 02:00:00
Persistent=true
RandomizedDelaySec=300

[Install]
WantedBy=timers.target
管理 systemd timer 的常用操作：


sudo systemctl enable backup.timer
sudo systemctl start backup.timer

systemctl list-timers --all

systemctl status backup.timer
systemctl status backup.service

journalctl -u backup.service --since "1 hour ago"

sudo systemctl start backup.service
一个管理 cron 任务的辅助脚本：


list_cron_jobs() {
    echo "=== 系统 Crontab ==="
    cat /etc/crontab 2>/dev/null || true

    echo -e "\n=== Cron.d 目录 ==="
    for f in /etc/cron.d/*; do
        [[ -f "$f" ]] || continue
        echo "--- $(basename "$f") ---"
        grep -v '^#\|^$' "$f"
    done

    echo -e "\n=== 用户 Crontab ==="
    crontab -l 2>/dev/null || echo "(无)"

    echo -e "\n=== Systemd Timers ==="
    systemctl list-timers --no-pager 2>/dev/null || true
}

validate_cron_expression() {
    local expr="$1"
    local fields
    read -ra fields <<< "$expr"

    if (( ${#fields[@]} != 5 )); then
        echo "错误: Cron 表达式必须有 5 个字段" >&2
        return 1
    fi

    echo "有效的 Cron 表达式: $expr"
}
小结
    

  • Cron 表达式由 5 个时间字段组成：分、时、日、月、周，支持通配符、范围和步进
    • 

  • Cron 任务运行在极简环境中，必须显式设置 PATH、HOME、LANG 等环境变量
    • 

  • 并发控制是 Cron 任务的必备机制，推荐使用 flock 或 mkdir 实现文件锁
    • 

  • 所有 Cron 任务应将 stdout 和 stderr 重定向到日志文件
    • 

  • systemd timer 是 cron 的现代替代方案，提供了更精确的调度、日志集成和依赖管理
    • 

  • Persistent=true 允许 systemd timer 补偿错过的执行，cron 不具备此能力
    • 

  • 备份和清理任务应设置超时限制，防止异常时无限运行
    • 

  • 建议维护一个 cron 任务清单文档，记录每个任务的用途、频率和负责人
    •
