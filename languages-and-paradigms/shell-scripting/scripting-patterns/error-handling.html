错误处理

核心概念

Shell 脚本的错误处理是区分"能用的脚本"和"生产级脚本"的关键分水岭。默认情况下，Shell 脚本在某个命令失败时会继续执行后续命令，这种"静默失败"的行为是大量线上事故的根源。健壮的错误处理策略需要结合退出状态码、trap 信号处理、set 选项和防御性编程技巧。

Bash 通过退出状态码（exit status）传递命令的执行结果：0 表示成功，1-255 表示各种失败。每条命令执行后，其退出码保存在特殊变量 $? 中。管道命令的退出码默认为最后一个命令的退出码，除非设置了 pipefail 选项。

strict 模式与安全开头
生产级脚本应始终以 strict 模式开头，这是 Shell 脚本安全的第一道防线：


#!/usr/bin/env bash
set -euo pipefail

readonly SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
readonly SCRIPT_NAME="$(basename "${BASH_SOURCE[0]}")"

main() {
    echo "脚本开始执行"
    validate_prerequisites
    do_work
    echo "脚本执行完成"
}

main "$@"
set -e 的行为细节需要深入理解，否则容易踩坑：


set -e

grep "pattern" file.txt || true

if grep -q "pattern" file.txt; then
    echo "找到了"
fi

count=$(grep -c "pattern" file.txt || true)

result=0
some_command || result=$?
if (( result != 0 )); then
    echo "命令失败，退出码: $result"
fi

set -e
false && echo "不会触发 set -e"
! false
echo "以上两行不会导致脚本退出"

trap 信号处理与资源清理
trap 是 Shell 中实现资源清理和信号处理的核心机制。它允许在脚本退出或接收到信号时执行指定的命令：


cleanup() {
    local exit_code=$?
    echo "清理临时文件..." >&2
    rm -rf "${TEMP_DIR:-}"
    rm -f "${LOCK_FILE:-}"
    exit "$exit_code"
}

trap cleanup EXIT

TEMP_DIR=$(mktemp -d)
LOCK_FILE="/tmp/$(basename "$0").lock"

trap 'echo "捕获到 SIGINT (Ctrl+C)"; cleanup' INT
trap 'echo "捕获到 SIGTERM"; cleanup' TERM

on_error() {
    local exit_code=$?
    local line_number=$1
    echo "错误: 第 ${line_number} 行命令失败（退出码: ${exit_code}）" >&2
}
trap 'on_error $LINENO' ERR

create_temp_resources() {
    TEMP_DIR=$(mktemp -d)
    trap 'rm -rf "$TEMP_DIR"' EXIT

    TEMP_FILE=$(mktemp "$TEMP_DIR/XXXXXX")
    echo "临时目录: $TEMP_DIR"
    echo "临时文件: $TEMP_FILE"
}

acquire_lock() {
    local lock_file="$1"
    local max_wait="${2:-30}"
    local waited=0

    while ! mkdir "$lock_file" 2>/dev/null; do
        if (( waited >= max_wait )); then
            echo "获取锁超时: $lock_file" >&2
            return 1
        fi
        sleep 1
        ((waited++))
    done

    trap 'rmdir "$lock_file" 2>/dev/null' EXIT
    echo "获取锁成功: $lock_file"
}
错误报告与日志系统
完善的错误报告机制是调试和运维的基础：


readonly RED='\033[0;31m'
readonly YELLOW='\033[1;33m'
readonly GREEN='\033[0;32m'
readonly NC='\033[0m'

log_info()  { echo -e "${GREEN}[INFO]${NC}  $(date '+%H:%M:%S') $*"; }
log_warn()  { echo -e "${YELLOW}[WARN]${NC}  $(date '+%H:%M:%S') $*" >&2; }
log_error() { echo -e "${RED}[ERROR]${NC} $(date '+%H:%M:%S') $*" >&2; }

die() {
    log_error "$@"
    exit 1
}

LOG_FILE="/var/log/myapp/$(date +%Y%m%d).log"

log_to_file() {
    local level="$1"
    shift
    local timestamp
    timestamp=$(date '+%Y-%m-%d %H:%M:%S')
    echo "[$timestamp] [$level] $*" >> "$LOG_FILE"

    case "$level" in
        ERROR|FATAL) echo "[$timestamp] [$level] $*" >&2 ;;
    esac
}

run_logged() {
    log_info "执行: $*"
    local output
    if output=$("$@" 2>&1); then
        log_info "成功: $*"
        echo "$output"
    else
        local exit_code=$?
        log_error "失败: $* (退出码: $exit_code)"
        log_error "输出: $output"
        return $exit_code
    fi
}

run_logged docker build -t myapp .
run_logged npm run test
防御性编程模式
防御性编程通过主动验证来预防错误，而非事后处理：


require_command() {
    for cmd in "$@"; do
        if ! command -v "$cmd" &> /dev/null; then
            die "缺少必要命令: $cmd，请先安装"
        fi
    done
}

require_file() {
    for file in "$@"; do
        [[ -f "$file" ]] || die "文件不存在: $file"
    done
}

require_dir() {
    for dir in "$@"; do
        [[ -d "$dir" ]] || die "目录不存在: $dir"
    done
}

require_env() {
    for var in "$@"; do
        [[ -n "${!var:-}" ]] || die "环境变量未设置: $var"
    done
}

validate_port() {
    local port="$1"
    if ! [[ "$port" =~ ^[0-9]+$ ]] || (( port < 1 || port > 65535 )); then
        die "无效端口号: $port"
    fi
}

safe_cd() {
    cd "$1" || die "无法进入目录: $1"
}

safe_rm() {
    local target="$1"
    if [[ -z "$target" || "$target" == "/" ]]; then
        die "危险: 拒绝删除根目录或空路径"
    fi
    rm -rf "$target"
}

confirm() {
    local message="${1:-确认继续?}"
    read -rp "$message [y/N] " response
    [[ "$response" =~ ^[Yy]$ ]]
}

if confirm "即将删除所有构建产物，是否继续?"; then
    safe_rm "./dist"
fi
完整的生产级脚本模板：


#!/usr/bin/env bash
set -euo pipefail

readonly SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

TEMP_DIR=""

cleanup() {
    local exit_code=$?
    [[ -n "$TEMP_DIR" ]] && rm -rf "$TEMP_DIR"
    exit "$exit_code"
}

trap cleanup EXIT
trap 'echo "中断" >&2; exit 130' INT TERM

die() { echo "[ERROR] $*" >&2; exit 1; }

main() {
    require_command git node docker
    TEMP_DIR=$(mktemp -d)

    local env="${1:-development}"

    case "$env" in
        development|staging|production) ;;
        *) die "无效环境: $env" ;;
    esac

    echo "部署到 $env 环境..."
}

require_command() {
    for cmd in "$@"; do
        command -v "$cmd" &>/dev/null || die "缺少: $cmd"
    done
}

main "$@"
小结
    

  • 生产级脚本必须以 set -euo pipefail 开头，启用 strict 模式
    • 

  • trap EXIT 确保脚本退出时执行清理逻辑，是资源管理的核心机制
    • 

  • trap ERR 配合 $LINENO 提供精确的错误定位信息
    • 

  • 防御性编程通过 require_command、require_file 等函数主动验证前置条件
    • 

  • set -e 在条件判断和 || 链中不会触发退出，需要理解其例外规则
    • 

  • 日志系统应区分级别（INFO/WARN/ERROR），错误信息输出到 stderr
    • 

  • 涉及文件删除等危险操作时，使用 safe_rm 和 confirm 等防护函数
    • 

  • 使用 readonly 声明脚本常量，防止意外修改
    •
