JSON 与半结构化数据

核心概念

现代关系数据库不再局限于严格的表结构。JSON/JSONB 数据类型让 SQL 数据库能够处理半结构化数据，在关系模型的强一致性和 NoSQL 的灵活性之间取得平衡。PostgreSQL 的 JSONB 是这一领域的标杆，提供了完整的查询、索引和操作符支持。

JSONB 查询操作符
PostgreSQL 提供了丰富的 JSONB 操作符，支持路径导航、类型提取和包含检查。


const jsonbOperators = `
-- 示例数据
CREATE TABLE products (
    product_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(200),
    attributes JSONB NOT NULL DEFAULT '{}'
);

INSERT INTO products (name, attributes) VALUES
('MacBook Pro', '{
    "brand": "Apple",
    "specs": {"cpu": "M3", "ram": 16, "storage": 512},
    "tags": ["laptop", "pro", "portable"],
    "price": {"amount": 12999, "currency": "CNY"}
}');

-- -> 返回 JSON 对象
SELECT attributes->'specs' FROM products;
-- 返回: {"cpu": "M3", "ram": 16, "storage": 512}

-- ->> 返回 TEXT
SELECT attributes->>'brand' FROM products;
-- 返回: Apple

-- #> 和 #>> 路径导航
SELECT attributes#>'{specs,cpu}' FROM products;     -- 返回: "M3"（JSON）
SELECT attributes#>>'{specs,cpu}' FROM products;    -- 返回: M3（TEXT）

-- @> 包含检查（左侧是否包含右侧）
SELECT * FROM products 
WHERE attributes @> '{"brand": "Apple"}';

-- ? 键存在检查
SELECT * FROM products 
WHERE attributes ? 'brand';

-- ?| 任一键存在
SELECT * FROM products 
WHERE attributes ?| array['brand', 'manufacturer'];

-- ?& 所有键存在
SELECT * FROM products 
WHERE attributes ?& array['brand', 'specs'];
`;

JSONB 索引策略
JSONB 的查询性能依赖正确的索引策略。GIN 索引支持通用的包含和存在查询，表达式索引支持特定路径的精确查询。


const jsonbIndexing = `
-- GIN 索引：支持 @>, ?, ?| 等操作符
CREATE INDEX idx_product_attrs ON products USING GIN (attributes);

-- 查询示例（利用 GIN 索引）
SELECT * FROM products WHERE attributes @> '{"brand": "Apple"}';
SELECT * FROM products WHERE attributes ? 'warranty';

-- GIN jsonb_path_ops：更小的索引，只支持 @>
CREATE INDEX idx_attrs_pathops ON products 
    USING GIN (attributes jsonb_path_ops);

-- 表达式索引：针对特定路径的精确查询
CREATE INDEX idx_brand ON products ((attributes->>'brand'));
SELECT * FROM products WHERE attributes->>'brand' = 'Apple';

-- 数值路径索引（需要类型转换）
CREATE INDEX idx_ram ON products (((attributes#>>'{specs,ram}')::INT));
SELECT * FROM products WHERE (attributes#>>'{specs,ram}')::INT >= 16;

-- 部分索引 + JSONB
CREATE INDEX idx_laptop_tags ON products USING GIN (attributes)
    WHERE attributes @> '{"tags": ["laptop"]}';
`;

JSONB 修改操作
JSONB 的修改不是原地更新，而是生成新的 JSONB 值。PostgreSQL 提供了多个函数来简化 JSONB 的修改操作。


const jsonbModification = `
-- jsonb_set：设置指定路径的值
UPDATE products
SET attributes = jsonb_set(attributes, '{specs,ram}', '32')
WHERE product_id = 1;

-- 嵌套路径设置（create_if_missing 参数）
UPDATE products
SET attributes = jsonb_set(
    attributes, 
    '{warranty,years}', 
    '3', 
    true  -- 路径不存在时创建
)
WHERE product_id = 1;

-- || 合并操作
UPDATE products
SET attributes = attributes || '{"color": "silver", "weight": "1.6kg"}'
WHERE product_id = 1;

-- - 删除键
UPDATE products
SET attributes = attributes - 'obsolete_field'
WHERE product_id = 1;

-- #- 按路径删除
UPDATE products
SET attributes = attributes #- '{specs,old_cpu}'
WHERE product_id = 1;

-- 数组操作
UPDATE products
SET attributes = jsonb_set(
    attributes,
    '{tags}',
    (attributes->'tags') || '"new-tag"'
)
WHERE product_id = 1;

-- jsonb_strip_nulls：移除所有 null 值
UPDATE products
SET attributes = jsonb_strip_nulls(attributes)
WHERE attributes @> 'null';
`;
JSONB 聚合与分析
JSONB 数据可以展开为行进行聚合分析，也可以将行数据聚合为 JSONB 结构。


const jsonbAnalytics = `
-- jsonb_each：展开为键值对
SELECT p.name, kv.key, kv.value
FROM products p, jsonb_each(p.attributes->'specs') AS kv;

-- jsonb_array_elements：展开数组
SELECT p.name, tag.value AS tag
FROM products p, jsonb_array_elements_text(p.attributes->'tags') AS tag;

-- 聚合：行数据转 JSONB
SELECT jsonb_agg(
    jsonb_build_object('id', product_id, 'name', name, 'price', price)
) AS products_json
FROM products
WHERE category_id = 5;

-- jsonb_object_agg：键值对聚合为对象
SELECT jsonb_object_agg(setting_key, setting_value) AS settings
FROM user_settings
WHERE user_id = 1;

-- 统计 JSONB 数组中的标签分布
SELECT tag, COUNT(*) AS product_count
FROM products, jsonb_array_elements_text(attributes->'tags') AS tag
GROUP BY tag
ORDER BY product_count DESC;

-- JSON Path 查询（PostgreSQL 12+）
SELECT * FROM products
WHERE jsonb_path_exists(attributes, '$.specs.ram ? (@ >= 16)');

SELECT jsonb_path_query(attributes, '$.tags[*]') AS tag
FROM products;
`;
选择何时使用 JSONB 而非关系表：当字段结构频繁变化（如商品属性）、不同行的字段集合差异大（如多态实体）、或需要存储第三方 API 响应时，JSONB 是更好的选择。但如果字段结构稳定且需要频繁聚合查询，关系表仍是首选。


小结
    

  • JSONB 以二进制分解格式存储，支持高效查询和索引，优于 JSON 文本格式
    • 

  • -> 返回 JSONB，->> 返回 TEXT，@> 检查包含关系，? 检查键存在
    • 

  • GIN 索引支持 @> 和 ? 操作符，jsonb_path_ops 变体更小但只支持 @>
    • 

  • 表达式索引针对特定路径的精确查询，是最精准高效的索引方式
    • 

  • JSONB 修改通过 jsonb_set、|| 合并和 - 删除实现，本质是生成新值
    • 

  • jsonb_each 和 jsonb_array_elements 将 JSONB 展开为行，jsonb_agg 将行聚合为 JSONB
    • 

  • 字段结构多变、多态实体适合 JSONB，结构稳定且需频繁聚合适合关系表
    •
