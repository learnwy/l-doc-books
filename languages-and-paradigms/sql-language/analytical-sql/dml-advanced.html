DML 进阶操作

核心概念

数据操作语言（DML）的进阶用法远超基础的 INSERT/UPDATE/DELETE。批量操作、UPSERT、RETURNING 子句、多表更新等高级特性是构建高效数据处理流程的关键。掌握这些进阶操作可以将原本需要应用层多次往返的逻辑压缩为单条 SQL，大幅提升性能和一致性。

批量操作与性能
批量操作是提升写入性能的基本手段。逐行 INSERT 的网络往返开销远大于批量操作。


const batchOperations = `
-- 单行 INSERT（性能最差）
INSERT INTO products (name, price) VALUES ('商品A', 100);
INSERT INTO products (name, price) VALUES ('商品B', 200);

-- 批量 INSERT（推荐，一次性插入多行）
INSERT INTO products (name, price) VALUES
    ('商品A', 100),
    ('商品B', 200),
    ('商品C', 300),
    ('商品D', 400);

-- INSERT ... SELECT（从查询结果批量插入）
INSERT INTO product_archive (product_id, name, price, archived_at)
SELECT product_id, name, price, NOW()
FROM products
WHERE status = 'discontinued';

-- COPY 命令（PostgreSQL 最快的批量加载方式）
COPY products (name, price, category_id) 
FROM '/tmp/products.csv' 
WITH (FORMAT csv, HEADER true, DELIMITER ',');

-- 应用层批量插入最佳实践
-- 每批 1000-5000 行，太大可能导致内存问题和长事务
`;

UPSERT（插入或更新）
UPSERT 是"如果不存在则插入，如果已存在则更新"的原子操作。这消除了应用层"先查询再决定插入还是更新"的竞态条件。


const upsertPatterns = `
-- PostgreSQL ON CONFLICT
INSERT INTO user_settings (user_id, setting_key, setting_value)
VALUES (1, 'theme', 'dark')
ON CONFLICT (user_id, setting_key) 
DO UPDATE SET 
    setting_value = EXCLUDED.setting_value,
    updated_at = NOW();

-- ON CONFLICT DO NOTHING（忽略冲突，幂等插入）
INSERT INTO unique_events (event_id, event_type, created_at)
VALUES ('evt_123', 'click', NOW())
ON CONFLICT (event_id) DO NOTHING;

-- 条件性 UPSERT（只在特定条件下更新）
INSERT INTO product_prices (product_id, price, updated_at)
VALUES (1, 299, NOW())
ON CONFLICT (product_id)
DO UPDATE SET 
    price = EXCLUDED.price,
    updated_at = NOW()
WHERE product_prices.price <> EXCLUDED.price;

-- 批量 UPSERT
INSERT INTO inventory (product_id, warehouse_id, quantity)
VALUES 
    (1, 'WH001', 100),
    (2, 'WH001', 200),
    (3, 'WH002', 50)
ON CONFLICT (product_id, warehouse_id)
DO UPDATE SET 
    quantity = EXCLUDED.quantity,
    updated_at = NOW();

-- MySQL ON DUPLICATE KEY UPDATE
-- INSERT INTO user_settings (user_id, setting_key, setting_value)
-- VALUES (1, 'theme', 'dark')
-- ON DUPLICATE KEY UPDATE setting_value = VALUES(setting_value);
`;
UPSERT 的关键是冲突目标的选择——必须是唯一索引或主键。EXCLUDED 关键字引用试图插入的新值。


RETURNING 子句
RETURNING 子句使 INSERT/UPDATE/DELETE 在执行操作的同时返回受影响的行数据，避免了额外的 SELECT 查询。


const returningClause = `
-- INSERT RETURNING：获取自动生成的 ID 和默认值
INSERT INTO orders (user_id, amount)
VALUES (1, 500)
RETURNING order_id, created_at;

-- 批量 INSERT RETURNING
INSERT INTO notifications (user_id, message)
SELECT user_id, '系统升级通知'
FROM users WHERE status = 1
RETURNING notification_id, user_id;

-- UPDATE RETURNING：获取更新前后的值
UPDATE products
SET price = price * 0.9
WHERE category_id = 5
RETURNING product_id, name, price AS new_price;

-- DELETE RETURNING：获取被删除的数据
DELETE FROM expired_sessions
WHERE expires_at < NOW()
RETURNING session_id, user_id;

-- CTE + RETURNING：链式操作
WITH deleted AS (
    DELETE FROM orders 
    WHERE status = 'cancelled' AND created_at < '2023-01-01'
    RETURNING *
)
INSERT INTO order_archive SELECT * FROM deleted;
`;
RETURNING 在应用层开发中极为有用。例如创建订单后需要返回订单 ID 给前端，传统做法需要 INSERT + SELECT 两步，用 RETURNING 一步完成。


CTE 与 DML 组合
PostgreSQL 支持在 CTE 中使用 DML 语句（可写 CTE），实现复杂的多步数据操作流水线。


const writableCTE = `
-- 归档 + 删除：一步完成
WITH archived AS (
    DELETE FROM events 
    WHERE created_at < '2023-01-01'
    RETURNING *
)
INSERT INTO events_archive SELECT * FROM archived;

-- 更新 + 插入日志
WITH updated AS (
    UPDATE orders 
    SET status = 'shipped', shipped_at = NOW()
    WHERE order_id = 12345
    RETURNING order_id, user_id, status, shipped_at
)
INSERT INTO order_status_log (order_id, user_id, new_status, changed_at)
SELECT order_id, user_id, status, shipped_at FROM updated;

-- 条件更新 + 汇总
WITH price_updates AS (
    UPDATE products
    SET price = price * 1.1
    WHERE category_id = 5 AND last_update < '2024-01-01'
    RETURNING product_id, price
)
SELECT COUNT(*) AS updated_count, AVG(price) AS new_avg_price
FROM price_updates;

-- 多表关联更新
UPDATE orders o
SET total_amount = sub.calc_total
FROM (
    SELECT order_id, SUM(quantity * unit_price) AS calc_total
    FROM order_items
    GROUP BY order_id
) sub
WHERE o.order_id = sub.order_id
  AND o.total_amount <> sub.calc_total;
`;
可写 CTE 的执行是原子的——所有 CTE 中的 DML 和最终语句在同一个事务中执行。如果任何步骤失败，整个操作回滚。这保证了复杂数据操作的一致性。


软删除与数据生命周期
软删除是在不实际删除数据的情况下标记数据为"已删除"，常用于需要恢复能力或审计追踪的场景。


const softDeletePatterns = `
-- 软删除：标记而非物理删除
UPDATE products 
SET deleted_at = NOW() 
WHERE product_id = 123;

-- 查询时排除已删除记录（需要每个查询都加条件）
SELECT * FROM products WHERE deleted_at IS NULL;

-- 更好的方案：使用视图封装
CREATE VIEW active_products AS
SELECT * FROM products WHERE deleted_at IS NULL;

-- 配合部分索引优化查询
CREATE INDEX idx_active_products ON products(category_id) 
    WHERE deleted_at IS NULL;

-- 定期清理软删除数据（物理删除超过保留期的记录）
DELETE FROM products 
WHERE deleted_at IS NOT NULL 
  AND deleted_at < NOW() - INTERVAL '90 days';
`;

小结
    

  • 批量 INSERT 比逐行 INSERT 性能高数十倍，COPY 是 PostgreSQL 最快的批量加载方式
    • 

  • UPSERT（ON CONFLICT）提供原子的"存在则更新，不存在则插入"语义，消除竞态条件
    • 

  • RETURNING 子句使 DML 语句同时返回受影响的行数据，避免额外的 SELECT 查询
    • 

  • 可写 CTE 在 PostgreSQL 中支持复杂的多步 DML 流水线，所有操作在同一事务中原子执行
    • 

  • 多表关联更新使用 UPDATE ... FROM 语法，避免应用层多次往返
    • 

  • 软删除通过 deleted_at 列标记代替物理删除，配合视图和部分索引保持查询效率
    •
