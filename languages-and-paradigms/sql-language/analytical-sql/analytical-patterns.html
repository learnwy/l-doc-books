分析函数实战

核心概念

SQL 分析函数（Analytical Functions）是数据分析和报表场景的核心工具。它们将窗口函数、聚合函数和高级 SQL 特性组合使用，解决时序分析、漏斗分析、留存分析、排行榜等实际业务问题。本文聚焦于真实业务场景中的分析模式，展示如何用纯 SQL 完成通常需要 Python/Pandas 才能实现的数据分析工作。

时序分析
时序分析是最常见的数据分析场景，涵盖同比、环比、移动平均和趋势检测。


const timeSeriesAnalysis = `
-- 日级营收 + 7 天移动平均 + 环比增长
WITH daily_revenue AS (
    SELECT 
        DATE_TRUNC('day', created_at)::DATE AS day,
        SUM(amount) AS revenue,
        COUNT(DISTINCT user_id) AS unique_buyers
    FROM orders
    WHERE created_at >= '2024-01-01'
    GROUP BY 1
)
SELECT 
    day,
    revenue,
    unique_buyers,
    AVG(revenue) OVER (ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) 
        AS moving_avg_7d,
    LAG(revenue, 1) OVER (ORDER BY day) AS prev_day_revenue,
    ROUND(
        (revenue - LAG(revenue, 1) OVER (ORDER BY day)) * 100.0 
        / NULLIF(LAG(revenue, 1) OVER (ORDER BY day), 0), 
        2
    ) AS dod_growth_pct,
    LAG(revenue, 7) OVER (ORDER BY day) AS same_day_last_week,
    ROUND(
        (revenue - LAG(revenue, 7) OVER (ORDER BY day)) * 100.0 
        / NULLIF(LAG(revenue, 7) OVER (ORDER BY day), 0), 
        2
    ) AS wow_growth_pct
FROM daily_revenue
ORDER BY day;

-- 月度同比分析
WITH monthly AS (
    SELECT 
        DATE_TRUNC('month', created_at)::DATE AS month,
        SUM(amount) AS revenue
    FROM orders
    GROUP BY 1
)
SELECT 
    month,
    revenue,
    LAG(revenue, 12) OVER (ORDER BY month) AS same_month_last_year,
    ROUND(
        (revenue - LAG(revenue, 12) OVER (ORDER BY month)) * 100.0 
        / NULLIF(LAG(revenue, 12) OVER (ORDER BY month), 0), 
        2
    ) AS yoy_growth_pct
FROM monthly;
`;
漏斗分析
漏斗分析跟踪用户在多步骤流程中的转化率和流失点。核心技巧是使用条件聚合（CASE WHEN）配合窗口函数。


const funnelAnalysis = `
-- 电商购买漏斗：浏览 → 加购 → 下单 → 支付
WITH user_events AS (
    SELECT 
        user_id,
        MAX(CASE WHEN event_type = 'page_view' THEN 1 ELSE 0 END) AS viewed,
        MAX(CASE WHEN event_type = 'add_to_cart' THEN 1 ELSE 0 END) AS added,
        MAX(CASE WHEN event_type = 'checkout' THEN 1 ELSE 0 END) AS checked_out,
        MAX(CASE WHEN event_type = 'payment' THEN 1 ELSE 0 END) AS paid
    FROM events
    WHERE created_at >= CURRENT_DATE - INTERVAL '7 days'
    GROUP BY user_id
)
SELECT 
    '浏览' AS step,
    COUNT(*) FILTER (WHERE viewed = 1) AS users,
    100.0 AS pct_of_first
UNION ALL
SELECT 
    '加购',
    COUNT(*) FILTER (WHERE added = 1),
    ROUND(COUNT(*) FILTER (WHERE added = 1) * 100.0 
        / NULLIF(COUNT(*) FILTER (WHERE viewed = 1), 0), 2)
FROM user_events
UNION ALL
SELECT 
    '下单',
    COUNT(*) FILTER (WHERE checked_out = 1),
    ROUND(COUNT(*) FILTER (WHERE checked_out = 1) * 100.0 
        / NULLIF(COUNT(*) FILTER (WHERE viewed = 1), 0), 2)
FROM user_events
UNION ALL
SELECT 
    '支付',
    COUNT(*) FILTER (WHERE paid = 1),
    ROUND(COUNT(*) FILTER (WHERE paid = 1) * 100.0 
        / NULLIF(COUNT(*) FILTER (WHERE viewed = 1), 0), 2)
FROM user_events;

-- 带时间约束的严格漏斗（步骤必须按顺序发生）
WITH ordered_events AS (
    SELECT 
        user_id,
        event_type,
        created_at,
        LEAD(event_type) OVER (PARTITION BY user_id ORDER BY created_at) AS next_event,
        LEAD(created_at) OVER (PARTITION BY user_id ORDER BY created_at) AS next_time
    FROM events
    WHERE event_type IN ('page_view', 'add_to_cart', 'checkout', 'payment')
)
SELECT 
    event_type AS from_step,
    next_event AS to_step,
    COUNT(*) AS transitions,
    AVG(EXTRACT(EPOCH FROM (next_time - created_at))) AS avg_seconds
FROM ordered_events
WHERE next_event IS NOT NULL
GROUP BY event_type, next_event;
`;
留存分析
留存分析衡量用户在首次行为后的回访率。经典的 N 日留存通过队列分析（Cohort Analysis）实现。


const retentionAnalysis = `
-- N 日留存矩阵
WITH first_visit AS (
    SELECT 
        user_id,
        MIN(DATE_TRUNC('day', created_at))::DATE AS cohort_date
    FROM events
    GROUP BY user_id
),
user_activity AS (
    SELECT DISTINCT 
        user_id,
        DATE_TRUNC('day', created_at)::DATE AS active_date
    FROM events
)
SELECT 
    fv.cohort_date,
    COUNT(DISTINCT fv.user_id) AS cohort_size,
    COUNT(DISTINCT CASE WHEN ua.active_date = fv.cohort_date + 1 
        THEN ua.user_id END) AS day_1,
    COUNT(DISTINCT CASE WHEN ua.active_date = fv.cohort_date + 3 
        THEN ua.user_id END) AS day_3,
    COUNT(DISTINCT CASE WHEN ua.active_date = fv.cohort_date + 7 
        THEN ua.user_id END) AS day_7,
    COUNT(DISTINCT CASE WHEN ua.active_date = fv.cohort_date + 30 
        THEN ua.user_id END) AS day_30,
    ROUND(
        COUNT(DISTINCT CASE WHEN ua.active_date = fv.cohort_date + 7 
            THEN ua.user_id END) * 100.0 
        / COUNT(DISTINCT fv.user_id), 2
    ) AS retention_7d_pct
FROM first_visit fv
LEFT JOIN user_activity ua ON fv.user_id = ua.user_id
WHERE fv.cohort_date >= CURRENT_DATE - INTERVAL '30 days'
GROUP BY fv.cohort_date
ORDER BY fv.cohort_date;
`;

会话切割与分析
将连续的用户事件流切割为"会话"（Session），通常以 30 分钟无活动作为会话边界。


const sessionAnalysis = `
-- 基于时间间隔切割会话
WITH event_gaps AS (
    SELECT 
        user_id,
        event_type,
        created_at,
        LAG(created_at) OVER (
            PARTITION BY user_id ORDER BY created_at
        ) AS prev_event_at,
        EXTRACT(EPOCH FROM (
            created_at - LAG(created_at) OVER (
                PARTITION BY user_id ORDER BY created_at
            )
        )) / 60 AS gap_minutes
    FROM events
),
session_marks AS (
    SELECT *,
        SUM(CASE WHEN gap_minutes IS NULL OR gap_minutes > 30 THEN 1 ELSE 0 END)
            OVER (PARTITION BY user_id ORDER BY created_at) AS session_id
    FROM event_gaps
)
SELECT 
    user_id,
    session_id,
    MIN(created_at) AS session_start,
    MAX(created_at) AS session_end,
    COUNT(*) AS event_count,
    EXTRACT(EPOCH FROM (MAX(created_at) - MIN(created_at))) / 60 AS duration_minutes
FROM session_marks
GROUP BY user_id, session_id;

-- 会话级指标聚合
WITH sessions AS (
    -- ... (上面的会话切割逻辑)
)
SELECT 
    DATE_TRUNC('day', session_start)::DATE AS day,
    COUNT(*) AS total_sessions,
    AVG(event_count) AS avg_events_per_session,
    AVG(duration_minutes) AS avg_duration_minutes,
    PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY duration_minutes) AS median_duration
FROM sessions
GROUP BY 1
ORDER BY 1;
`;
会话切割的核心是 LAG + 条件累计求和的组合模式：先用 LAG 计算相邻事件的时间间隔，然后用 CASE 标记超过阈值的间隔为新会话起点，最后用 SUM OVER 累计生成会话 ID。


小结
    

  • 时序分析使用 LAG/LEAD 计算同比环比，窗口聚合实现移动平均和累计趋势
    • 

  • 漏斗分析通过条件聚合（CASE WHEN + COUNT）计算各步骤转化率
    • 

  • 留存分析的核心是队列分析，通过首次行为日期分组后计算 N 日回访率
    • 

  • 会话切割使用 LAG + 条件 SUM OVER 模式，以时间间隔阈值（如 30 分钟）划分会话
    • 

  • FILTER (WHERE ...) 是 PostgreSQL 中条件聚合的简洁替代语法
    • 

  • 这些分析模式可以组合使用，如按会话维度做漏斗分析或按留存队列做时序趋势
