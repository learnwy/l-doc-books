时间序列 SQL

核心概念

时间序列分析是 SQL 数据分析中最重要的应用场景之一。从日活跃用户统计到收入趋势预测，几乎所有业务分析都涉及时间维度。SQL 提供了丰富的日期函数、窗口函数和生成序列工具，可以直接在数据库层完成复杂的时序计算，避免将大量数据导出到应用层处理。

时间粒度转换
DATE_TRUNC 是时间序列分析的基础工具，将精确时间戳截断到指定粒度：


SELECT
    DATE_TRUNC('month', order_date) AS month,
    COUNT(*) AS order_count,
    SUM(amount) AS revenue,
    COUNT(DISTINCT customer_id) AS unique_customers,
    ROUND(SUM(amount) / COUNT(DISTINCT customer_id), 2) AS arpu
FROM orders
WHERE order_date >= '2024-01-01'
GROUP BY DATE_TRUNC('month', order_date)
ORDER BY month;
不同数据库的日期截断语法差异：


-- PostgreSQL: DATE_TRUNC
SELECT DATE_TRUNC('week', created_at) AS week_start FROM events;

-- MySQL: 需要组合函数
SELECT DATE(created_at - INTERVAL (WEEKDAY(created_at)) DAY) AS week_start FROM events;

-- BigQuery: DATE_TRUNC
SELECT DATE_TRUNC(created_at, WEEK) AS week_start FROM events;

-- SQL Server: DATETRUNC (2022+)
SELECT DATETRUNC(week, created_at) AS week_start FROM events;

时间序列填充
真实数据中某些日期可能没有记录（如假期无订单），直接聚合会导致时间序列断裂。使用 generate_series 生成连续日期序列，再 LEFT JOIN 填充缺失：


WITH date_series AS (
    SELECT generate_series(
        '2024-01-01'::date,
        '2024-12-31'::date,
        '1 day'::interval
    )::date AS dt
),
daily_metrics AS (
    SELECT
        DATE(order_date) AS dt,
        COUNT(*) AS order_count,
        SUM(amount) AS revenue
    FROM orders
    WHERE order_date >= '2024-01-01'
    GROUP BY DATE(order_date)
)
SELECT
    ds.dt,
    COALESCE(dm.order_count, 0) AS order_count,
    COALESCE(dm.revenue, 0) AS revenue,
    EXTRACT(DOW FROM ds.dt) AS day_of_week,
    CASE WHEN EXTRACT(DOW FROM ds.dt) IN (0, 6) THEN true ELSE false END AS is_weekend
FROM date_series ds
LEFT JOIN daily_metrics dm ON ds.dt = dm.dt
ORDER BY ds.dt;
MySQL 没有 generate_series，可以使用递归 CTE：


WITH RECURSIVE date_series AS (
    SELECT DATE('2024-01-01') AS dt
    UNION ALL
    SELECT dt + INTERVAL 1 DAY
    FROM date_series
    WHERE dt < '2024-12-31'
)
SELECT ds.dt, COALESCE(dm.order_count, 0) AS order_count
FROM date_series ds
LEFT JOIN (
    SELECT DATE(order_date) AS dt, COUNT(*) AS order_count
    FROM orders
    GROUP BY DATE(order_date)
) dm ON ds.dt = dm.dt;
移动平均与累计计算
窗口函数的 ROWS BETWEEN 子句定义滑动窗口，实现移动平均、累计求和等时序计算：


SELECT
    dt,
    revenue,
    ROUND(AVG(revenue) OVER (
        ORDER BY dt ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ), 2) AS ma_7d,
    ROUND(AVG(revenue) OVER (
        ORDER BY dt ROWS BETWEEN 29 PRECEDING AND CURRENT ROW
    ), 2) AS ma_30d,
    SUM(revenue) OVER (
        ORDER BY dt ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS cumulative_revenue,
    revenue - LAG(revenue) OVER (ORDER BY dt) AS daily_change
FROM daily_revenue
ORDER BY dt;
指数加权移动平均（EWMA）在 SQL 中实现较复杂，可以用递归 CTE 近似：


WITH RECURSIVE ewma AS (
    SELECT
        dt,
        revenue,
        revenue::NUMERIC AS ewma_value,
        1 AS rn
    FROM daily_revenue
    WHERE dt = (SELECT MIN(dt) FROM daily_revenue)

    UNION ALL

    SELECT
        d.dt,
        d.revenue,
        ROUND(0.3 * d.revenue + 0.7 * e.ewma_value, 2),
        e.rn + 1
    FROM daily_revenue d
    JOIN ewma e ON d.dt = (
        SELECT MIN(dt) FROM daily_revenue WHERE dt > e.dt
    )
)
SELECT dt, revenue, ewma_value
FROM ewma
ORDER BY dt;

同比与环比分析
LAG 函数结合 INTERVAL 运算实现同比（Year-over-Year）和环比（Month-over-Month）计算：


WITH monthly_revenue AS (
    SELECT
        DATE_TRUNC('month', order_date) AS month,
        SUM(amount) AS revenue
    FROM orders
    GROUP BY DATE_TRUNC('month', order_date)
)
SELECT
    month,
    revenue,
    LAG(revenue, 1) OVER (ORDER BY month) AS prev_month,
    LAG(revenue, 12) OVER (ORDER BY month) AS same_month_last_year,
    ROUND(
        (revenue - LAG(revenue, 1) OVER (ORDER BY month)) * 100.0 /
        NULLIF(LAG(revenue, 1) OVER (ORDER BY month), 0),
        2
    ) AS mom_growth_pct,
    ROUND(
        (revenue - LAG(revenue, 12) OVER (ORDER BY month)) * 100.0 /
        NULLIF(LAG(revenue, 12) OVER (ORDER BY month), 0),
        2
    ) AS yoy_growth_pct
FROM monthly_revenue
ORDER BY month;
小结
    

  • DATE_TRUNC 是时间粒度转换的核心工具，不同数据库语法有差异
    • 

  • generate_series + LEFT JOIN 填充缺失日期，确保时间序列连续
    • 

  • 窗口函数的 ROWS BETWEEN 实现移动平均和累计计算
    • 

  • LAG/LEAD 配合 INTERVAL 运算计算同比环比增长率
    • 

  • 递归 CTE 可实现 MySQL 的日期序列生成和指数移动平均
    • 

  • 时间序列分析应尽量在 SQL 层完成，避免将大量数据导出到应用层
