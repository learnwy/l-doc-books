CTE 与递归查询

核心概念

公共表表达式（CTE, Common Table Expression）使用 WITH 子句定义临时命名的结果集，在后续查询中引用。CTE 提升了 SQL 的可读性和模块化程度，将复杂查询分解为逻辑清晰的步骤。递归 CTE 是处理层级数据（如组织架构、分类树、图遍历）的标准工具。

普通 CTE
普通 CTE 将复杂查询拆分为逻辑单元，每个 CTE 可以引用前面定义的 CTE，形成数据处理流水线。


const basicCTE = `
-- 多步数据处理流水线
WITH monthly_sales AS (
    SELECT 
        user_id,
        DATE_TRUNC('month', order_date) AS month,
        SUM(amount) AS total_amount,
        COUNT(*) AS order_count
    FROM orders
    WHERE order_date >= '2024-01-01'
    GROUP BY user_id, DATE_TRUNC('month', order_date)
),
user_tiers AS (
    SELECT 
        user_id,
        AVG(total_amount) AS avg_monthly_spend,
        CASE 
            WHEN AVG(total_amount) >= 10000 THEN 'platinum'
            WHEN AVG(total_amount) >= 5000 THEN 'gold'
            WHEN AVG(total_amount) >= 1000 THEN 'silver'
            ELSE 'bronze'
        END AS tier
    FROM monthly_sales
    GROUP BY user_id
)
SELECT 
    ut.tier,
    COUNT(*) AS user_count,
    AVG(ut.avg_monthly_spend) AS avg_spend
FROM user_tiers ut
GROUP BY ut.tier
ORDER BY avg_spend DESC;

-- CTE 引用链
WITH raw_data AS (
    SELECT * FROM events WHERE event_date = CURRENT_DATE
),
aggregated AS (
    SELECT event_type, COUNT(*) AS cnt FROM raw_data GROUP BY event_type
),
ranked AS (
    SELECT *, RANK() OVER (ORDER BY cnt DESC) AS rnk FROM aggregated
)
SELECT * FROM ranked WHERE rnk <= 10;
`;
CTE 的物化（Materialization）行为因数据库而异。PostgreSQL 12+ 默认内联非递归 CTE（等价于子查询），可以用 MATERIALIZED / NOT MATERIALIZED 显式控制。MySQL 8.0 总是物化 CTE。


递归 CTE
递归 CTE 由两部分组成：锚点成员（Anchor Member，初始数据集）和递归成员（Recursive Member，迭代扩展规则）。每次迭代将递归成员的结果与之前的结果合并，直到递归成员返回空集。


const recursiveCTE = `
-- 组织架构树展开
WITH RECURSIVE org_tree AS (
    -- 锚点：顶级节点（没有上级的员工）
    SELECT 
        employee_id, 
        employee_name, 
        manager_id, 
        1 AS depth,
        employee_name::TEXT AS path
    FROM employees
    WHERE manager_id IS NULL
    
    UNION ALL
    
    -- 递归：连接子节点
    SELECT 
        e.employee_id, 
        e.employee_name, 
        e.manager_id, 
        t.depth + 1,
        t.path || ' > ' || e.employee_name
    FROM employees e
    INNER JOIN org_tree t ON e.manager_id = t.employee_id
)
SELECT * FROM org_tree ORDER BY path;

-- 分类树遍历（包含子孙计数）
WITH RECURSIVE category_tree AS (
    SELECT category_id, parent_id, name, 0 AS level
    FROM categories WHERE parent_id IS NULL
    
    UNION ALL
    
    SELECT c.category_id, c.parent_id, c.name, ct.level + 1
    FROM categories c
    INNER JOIN category_tree ct ON c.parent_id = ct.category_id
)
SELECT 
    REPEAT('  ', level) || name AS display_name,
    category_id,
    level
FROM category_tree
ORDER BY category_id;
`;

递归查询实战模式
递归 CTE 不仅用于树遍历，还能解决日期序列生成、图路径查找、层级聚合等问题。


const recursivePatterns = `
-- 日期序列生成（无需 generate_series）
WITH RECURSIVE dates AS (
    SELECT DATE '2024-01-01' AS dt
    UNION ALL
    SELECT dt + INTERVAL '1 day'
    FROM dates
    WHERE dt < DATE '2024-12-31'
)
SELECT dt FROM dates;

-- 图最短路径（BFS）
WITH RECURSIVE shortest_path AS (
    SELECT 
        node_id AS target,
        ARRAY[start_node, node_id] AS path,
        1 AS distance
    FROM edges
    WHERE start_node = 1
    
    UNION ALL
    
    SELECT 
        e.node_id,
        sp.path || e.node_id,
        sp.distance + 1
    FROM edges e
    INNER JOIN shortest_path sp ON e.start_node = sp.target
    WHERE e.node_id <> ALL(sp.path)
      AND sp.distance < 10
)
SELECT DISTINCT ON (target) target, path, distance
FROM shortest_path
ORDER BY target, distance;

-- 层级聚合（求子树下所有节点的总销售额）
WITH RECURSIVE subtree AS (
    SELECT category_id FROM categories WHERE category_id = 5
    UNION ALL
    SELECT c.category_id
    FROM categories c
    INNER JOIN subtree s ON c.parent_id = s.category_id
)
SELECT SUM(p.sales_amount) AS total_sales
FROM products p
WHERE p.category_id IN (SELECT category_id FROM subtree);
`;
CTE 与性能权衡
CTE 的性能影响取决于数据库的优化策略和查询复杂度。


const ctePerformance = `
-- PostgreSQL 12+：NOT MATERIALIZED 让优化器内联 CTE
WITH active_users AS NOT MATERIALIZED (
    SELECT user_id FROM users WHERE status = 1
)
SELECT * FROM orders o
WHERE o.user_id IN (SELECT user_id FROM active_users);

-- MATERIALIZED 强制物化（当 CTE 被多次引用时有用）
WITH user_stats AS MATERIALIZED (
    SELECT user_id, COUNT(*) AS cnt, SUM(amount) AS total
    FROM orders GROUP BY user_id
)
SELECT * FROM user_stats WHERE cnt > 10
UNION ALL
SELECT * FROM user_stats WHERE total > 50000;
`;

小结
    

  • CTE 使用 WITH 子句定义临时命名结果集，将复杂查询分解为逻辑清晰的步骤
    • 

  • 普通 CTE 可以链式引用，形成数据处理流水线，提升可读性和维护性
    • 

  • 递归 CTE 由锚点成员和递归成员组成，用于树遍历、图路径、日期生成等场景
    • 

  • 递归查询必须设置深度限制和终止条件，防止无限递归耗尽资源
    • 

  • CTE 物化行为因数据库而异，PostgreSQL 12+ 支持 MATERIALIZED / NOT MATERIALIZED 显式控制
    • 

  • 性能权衡：单次引用优先内联，多次引用优先物化
    •
