子查询

核心概念

子查询（Subquery）是嵌套在另一条 SQL 语句内部的查询，可以出现在 SELECT、FROM、WHERE、HAVING 等子句中。子查询是 SQL 表达能力的重要扩展——许多复杂的数据查询需求只有通过子查询才能简洁地表达。根据返回结果的形态和与外部查询的关系，子查询分为多种类型。

WHERE 子查询
WHERE 子句中的子查询是最常见的用法，通过 IN、EXISTS、比较运算符等与外部查询配合过滤行。


const whereSubqueries = `
-- IN 子查询：查找有订单的用户
SELECT user_id, username
FROM users
WHERE user_id IN (
    SELECT DISTINCT user_id FROM orders WHERE amount > 1000
);

-- EXISTS 子查询：语义相同但通常更高效
SELECT u.user_id, u.username
FROM users u
WHERE EXISTS (
    SELECT 1 FROM orders o 
    WHERE o.user_id = u.user_id AND o.amount > 1000
);

-- 比较运算符 + 标量子查询
SELECT product_id, product_name, price
FROM products
WHERE price > (SELECT AVG(price) FROM products);

-- ALL / ANY 运算符
SELECT product_name, price
FROM products
WHERE price >= ALL (
    SELECT price FROM products WHERE category_id = 5
);

-- NOT EXISTS：反半连接
SELECT u.user_id, u.username
FROM users u
WHERE NOT EXISTS (
    SELECT 1 FROM orders o WHERE o.user_id = u.user_id
);
`;
IN 与 EXISTS 的选择是经典的 SQL 优化话题。现代优化器通常能自动在两者之间转换，但在某些情况下手动选择仍有意义：

FROM 子查询（派生表）
FROM 子句中的子查询称为派生表（Derived Table），它将子查询的结果作为一个临时表使用。派生表必须有别名。


const derivedTables = `
-- 派生表：先聚合再连接
SELECT 
    u.username,
    o.order_count,
    o.total_amount
FROM users u
INNER JOIN (
    SELECT 
        user_id,
        COUNT(*) AS order_count,
        SUM(amount) AS total_amount
    FROM orders
    GROUP BY user_id
) o ON u.user_id = o.user_id
WHERE o.total_amount > 10000;

-- 嵌套聚合：求每个类别中超过平均价的商品
SELECT p.product_name, p.price, ca.avg_price
FROM products p
INNER JOIN (
    SELECT category_id, AVG(price) AS avg_price
    FROM products
    GROUP BY category_id
) ca ON p.category_id = ca.category_id
WHERE p.price > ca.avg_price;

-- 行号生成（在不支持窗口函数的场景中）
SELECT *
FROM (
    SELECT *, ROW_NUMBER() OVER (ORDER BY created_at DESC) AS rn
    FROM events
) ranked
WHERE rn BETWEEN 11 AND 20;
`;
关联子查询
关联子查询（Correlated Subquery）引用了外部查询的列，逻辑上对外部查询的每一行都执行一次。虽然看起来效率低，但优化器通常能将其转换为等价的 JOIN 操作。


const correlatedSubqueries = `
-- 每个类别中价格最高的商品
SELECT p.product_name, p.price, p.category_id
FROM products p
WHERE p.price = (
    SELECT MAX(p2.price) 
    FROM products p2 
    WHERE p2.category_id = p.category_id
);

-- SELECT 中的标量关联子查询
SELECT 
    u.username,
    (SELECT COUNT(*) FROM orders o WHERE o.user_id = u.user_id) AS order_count,
    (SELECT MAX(amount) FROM orders o WHERE o.user_id = u.user_id) AS max_order
FROM users u;

-- LATERAL 替代关联子查询（PostgreSQL，性能更好）
SELECT u.username, stats.order_count, stats.max_order
FROM users u
CROSS JOIN LATERAL (
    SELECT COUNT(*) AS order_count, MAX(amount) AS max_order
    FROM orders o
    WHERE o.user_id = u.user_id
) stats;
`;
关联子查询在 SELECT 列表中作为标量使用时，如果外部查询返回大量行，性能可能成为瓶颈。此时应改写为 LEFT JOIN + 聚合或使用 LATERAL。


子查询优化策略
子查询的性能问题通常不在于子查询本身，而在于优化器能否有效地将其转换为更高效的执行计划。


const optimizationPatterns = `
-- 反模式：SELECT 中的多个关联子查询
-- 差：对每个用户执行 3 次子查询
SELECT u.username,
    (SELECT COUNT(*) FROM orders o WHERE o.user_id = u.user_id),
    (SELECT SUM(amount) FROM orders o WHERE o.user_id = u.user_id),
    (SELECT MAX(created_at) FROM orders o WHERE o.user_id = u.user_id)
FROM users u;

-- 优化：改写为 LEFT JOIN + 单次聚合
SELECT u.username, 
    COALESCE(o.cnt, 0) AS order_count,
    COALESCE(o.total, 0) AS total_amount,
    o.latest
FROM users u
LEFT JOIN (
    SELECT user_id, 
        COUNT(*) AS cnt, 
        SUM(amount) AS total, 
        MAX(created_at) AS latest
    FROM orders
    GROUP BY user_id
) o ON u.user_id = o.user_id;

-- 反模式：WHERE IN (大量值的子查询)
-- 当子查询返回上万行时，IN 列表过大
-- 优化：改写为 EXISTS 或 JOIN
SELECT p.* FROM products p
WHERE EXISTS (
    SELECT 1 FROM active_categories ac 
    WHERE ac.category_id = p.category_id
);
`;

小结
    

  • 子查询按返回结果分为标量、行、表三种类型，按关联性分为非关联和关联子查询
    • 

  • WHERE 中 EXISTS 通常优于 IN，尤其在涉及 NULL 值和需要反半连接（NOT EXISTS）时
    • 

  • 派生表（FROM 子查询）将子查询结果作为临时表使用，适合先聚合再连接的场景
    • 

  • 关联子查询逻辑上每行执行一次，优化器通常能转换为 JOIN，但 SELECT 列表中的多个关联子查询应手动优化
    • 

  • 子查询优化的核心思路：减少执行次数（关联→非关联）、减少数据传输（IN→EXISTS）、提升可读性（嵌套→CTE）
