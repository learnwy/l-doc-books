集合操作

核心概念

集合操作将两个或多个查询的结果集按集合论规则合并。SQL 提供四种集合操作：UNION（并集）、INTERSECT（交集）、EXCEPT（差集），以及对应的 ALL 变体。集合操作要求参与的查询具有相同的列数和兼容的数据类型。

UNION 与 UNION ALL
UNION 合并两个查询的结果并去除重复行，UNION ALL 保留所有行（包括重复）。由于去重需要排序或哈希，UNION ALL 的性能显著优于 UNION。


const unionExamples = `
-- UNION ALL：合并多个事件来源（已知不重复）
SELECT user_id, 'login' AS event_type, login_time AS event_time
FROM login_events
UNION ALL
SELECT user_id, 'purchase', purchase_time
FROM purchase_events
UNION ALL
SELECT user_id, 'pageview', view_time
FROM pageview_events
ORDER BY event_time DESC;

-- UNION：合并并去重
SELECT email FROM customers
UNION
SELECT email FROM newsletter_subscribers;

-- UNION ALL + GROUP BY 替代 UNION（更灵活）
SELECT email, COUNT(*) AS source_count
FROM (
    SELECT email FROM customers
    UNION ALL
    SELECT email FROM newsletter_subscribers
) combined
GROUP BY email;

-- 多表分区查询（历史表 + 当前表）
SELECT order_id, amount, created_at FROM orders_2024
WHERE created_at >= '2024-06-01'
UNION ALL
SELECT order_id, amount, created_at FROM orders_archive
WHERE created_at >= '2023-06-01' AND created_at < '2024-01-01';
`;

INTERSECT 交集
INTERSECT 返回同时存在于两个结果集中的行。它比使用 INNER JOIN 或 EXISTS 更简洁，尤其在比较整行数据时。


const intersectExamples = `
-- 查找既是客户又订阅了新闻的用户
SELECT user_id FROM customers
INTERSECT
SELECT user_id FROM newsletter_subscribers;

-- 等价的 EXISTS 写法
SELECT DISTINCT c.user_id 
FROM customers c
WHERE EXISTS (
    SELECT 1 FROM newsletter_subscribers n WHERE n.user_id = c.user_id
);

-- INTERSECT ALL 保留重复次数
-- 集合 A: {1, 1, 2, 3}
-- 集合 B: {1, 1, 1, 3}
-- INTERSECT ALL 结果: {1, 1, 3}（取每个值的最小出现次数）

-- 多条件交集：同时满足多个标签
SELECT product_id FROM product_tags WHERE tag = '热销'
INTERSECT
SELECT product_id FROM product_tags WHERE tag = '新品'
INTERSECT
SELECT product_id FROM product_tags WHERE tag = '包邮';
`;
INTERSECT 对 NULL 的处理与等值比较不同——两个 NULL 值在 INTERSECT 中被视为相等（而 NULL = NULL 返回 UNKNOWN）。这是集合操作的特殊语义。


EXCEPT 差集
EXCEPT 返回在第一个结果集中存在但不在第二个结果集中的行。它是查找差异和排除数据的简洁方式。


const exceptExamples = `
-- 查找未下过订单的用户
SELECT user_id FROM users
EXCEPT
SELECT DISTINCT user_id FROM orders;

-- 等价的 NOT EXISTS 写法
SELECT u.user_id FROM users u
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.user_id);

-- 数据对比：找出两个环境的差异
SELECT table_name, column_name, data_type
FROM production_schema.columns
EXCEPT
SELECT table_name, column_name, data_type
FROM staging_schema.columns;

-- 双向差异（完整对比）
-- A 有但 B 没有
(SELECT * FROM table_a EXCEPT SELECT * FROM table_b)
UNION ALL
-- B 有但 A 没有
(SELECT * FROM table_b EXCEPT SELECT * FROM table_a);

-- EXCEPT ALL：逐一移除匹配
-- 集合 A: {1, 1, 2, 3, 3}
-- 集合 B: {1, 3}
-- EXCEPT ALL 结果: {1, 2, 3}（从 A 中各移除一个匹配）
`;
集合操作的组合与优化
多个集合操作可以组合使用，但需要注意执行优先级和括号的使用。


const combinedOperations = `
-- INTERSECT 优先级高于 UNION（SQL 标准）
-- A UNION B INTERSECT C 等价于 A UNION (B INTERSECT C)
-- 建议始终使用括号明确优先级

-- 复杂组合：核心用户 = (活跃用户 ∩ 付费用户) - 黑名单
(
    SELECT user_id FROM active_users
    INTERSECT
    SELECT user_id FROM paid_users
)
EXCEPT
SELECT user_id FROM blacklist;

-- 性能优化：用 JOIN 替代集合操作
-- 当两个集合都很大时，INTERSECT 可能不如 JOIN 高效
-- INTERSECT 替代：
SELECT a.user_id
FROM active_users a
INNER JOIN paid_users p ON a.user_id = p.user_id
WHERE a.user_id NOT IN (SELECT user_id FROM blacklist);
`;

小结
    

  • UNION ALL 无去重开销，优先于 UNION 使用；只在确实需要去重时才用 UNION
    • 

  • INTERSECT 查找交集，在集合操作中 NULL 值被视为相等，这与等值比较不同
    • 

  • EXCEPT 查找差集，是 NOT EXISTS 的简洁替代
    • 

  • 集合操作要求列数和类型兼容，ORDER BY 只能出现在最终结果上
    • 

  • INTERSECT 优先级高于 UNION，建议使用括号明确组合顺序
    • 

  • 大数据集上考虑用 JOIN / EXISTS 替代 INTERSECT / EXCEPT，优化器可能生成更好的执行计划
