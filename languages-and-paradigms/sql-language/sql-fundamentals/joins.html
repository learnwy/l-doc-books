连接查询

核心概念

连接（JOIN）是关系数据库的核心操作，将两个或多个表中的数据按关联条件组合成一个结果集。理解不同连接类型的语义和性能特征是写出正确且高效 SQL 的基础。连接的本质是笛卡尔积加过滤——先产生所有行的组合，再通过 ON 条件筛选匹配的行。

INNER JOIN 内连接
INNER JOIN 是最常用的连接类型，只返回两个表中满足连接条件的行。如果一行在另一个表中没有匹配，该行不出现在结果中。


const innerJoinExamples = `
-- 基础 INNER JOIN
SELECT 
    o.order_id,
    o.amount,
    u.username,
    u.email
FROM orders o
INNER JOIN users u ON o.user_id = u.user_id;

-- 多表连接
SELECT 
    o.order_id,
    u.username,
    p.product_name,
    oi.quantity,
    oi.unit_price,
    (oi.quantity * oi.unit_price) AS line_total
FROM orders o
INNER JOIN users u ON o.user_id = u.user_id
INNER JOIN order_items oi ON o.order_id = oi.order_id
INNER JOIN products p ON oi.product_id = p.product_id
WHERE o.status = 1;

-- 非等值连接（较少见但有用）
SELECT 
    e.employee_name,
    sg.grade_level
FROM employees e
INNER JOIN salary_grades sg 
    ON e.salary BETWEEN sg.min_salary AND sg.max_salary;
`;
INNER JOIN 的连接顺序在逻辑上不影响结果，但优化器会根据统计信息选择最优的物理执行顺序。小表驱动大表（小表作为外循环）通常更高效。


LEFT JOIN 外连接
LEFT JOIN 保留左表的所有行，右表没有匹配的行用 NULL 填充。这是"主表 + 可选关联"场景的标准解法。


const leftJoinExamples = `
-- 用户及其订单（包括没有订单的用户）
SELECT 
    u.user_id,
    u.username,
    COUNT(o.order_id) AS order_count,
    COALESCE(SUM(o.amount), 0) AS total_spent
FROM users u
LEFT JOIN orders o ON u.user_id = o.user_id
GROUP BY u.user_id, u.username;

-- 查找没有匹配的行（反连接 Anti-Join）
SELECT u.user_id, u.username
FROM users u
LEFT JOIN orders o ON u.user_id = o.user_id
WHERE o.order_id IS NULL;

-- 等价的 NOT EXISTS 写法（通常性能更好）
SELECT u.user_id, u.username
FROM users u
WHERE NOT EXISTS (
    SELECT 1 FROM orders o WHERE o.user_id = u.user_id
);
`;
LEFT JOIN 的常见陷阱是在 WHERE 子句中对右表列进行非 NULL 过滤，这会将 LEFT JOIN 退化为 INNER JOIN：






写法
实际效果
原因





LEFT JOIN b ON ... WHERE b.col = 1
等价于 INNER JOIN
NULL = 1 为 UNKNOWN，不匹配行被过滤

仅保留右表无匹配的行




LEFT JOIN b ON ... AND b.col = 1

CROSS JOIN 与 LATERAL
CROSS JOIN 产生两表的笛卡尔积，每一行与另一表的所有行组合。虽然通常应避免无条件笛卡尔积，但在特定场景下非常有用。


const crossJoinExamples = `
-- 生成日期维度表
SELECT d.date_val, h.hour_val
FROM generate_series('2024-01-01'::DATE, '2024-12-31'::DATE, '1 day') AS d(date_val)
CROSS JOIN generate_series(0, 23) AS h(hour_val);

-- 每个用户 × 每个产品类别 的评分矩阵（包括未评分的组合）
SELECT 
    u.user_id,
    c.category_id,
    COALESCE(r.avg_rating, 0) AS avg_rating
FROM users u
CROSS JOIN categories c
LEFT JOIN (
    SELECT user_id, category_id, AVG(rating) AS avg_rating
    FROM reviews
    GROUP BY user_id, category_id
) r ON u.user_id = r.user_id AND c.category_id = r.category_id;
`;

// LATERAL JOIN（PostgreSQL）— 子查询可以引用外部表
const lateralJoin = `
-- 每个用户的最近 3 笔订单
SELECT u.user_id, u.username, recent.*
FROM users u
CROSS JOIN LATERAL (
    SELECT order_id, amount, created_at
    FROM orders o
    WHERE o.user_id = u.user_id
    ORDER BY o.created_at DESC
    LIMIT 3
) recent;
`;
LATERAL JOIN 是 SQL 中极为强大的特性，它允许子查询引用外部查询的列。这在"每组取 Top N"等场景中比窗口函数方案更直观高效。


自连接与递归关系
自连接（Self Join）是表与自身的连接，用于处理层级关系、时序比较等场景。


const selfJoinExamples = `
-- 组织架构层级
SELECT 
    e.employee_name AS employee,
    m.employee_name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.employee_id;

-- 同一天相邻订单的金额差异
SELECT 
    a.order_id,
    a.amount,
    b.order_id AS next_order_id,
    b.amount AS next_amount,
    (b.amount - a.amount) AS amount_diff
FROM orders a
INNER JOIN orders b 
    ON a.user_id = b.user_id 
    AND a.created_at < b.created_at
    AND NOT EXISTS (
        SELECT 1 FROM orders c
        WHERE c.user_id = a.user_id
        AND c.created_at > a.created_at
        AND c.created_at < b.created_at
    );

-- 查找重复数据
SELECT a.email, COUNT(*) AS duplicate_count
FROM users a
INNER JOIN users b 
    ON a.email = b.email 
    AND a.user_id < b.user_id
GROUP BY a.email;
`;
连接性能优化
连接的性能取决于连接算法、索引设计和数据量。数据库优化器通常在三种物理连接算法中选择：

const performanceTips = `
-- 确保连接列有索引
CREATE INDEX idx_orders_user_id ON orders(user_id);
CREATE INDEX idx_order_items_order_id ON order_items(order_id);

-- 避免在 ON 条件中使用函数（破坏索引利用）
-- 差：ON LOWER(a.email) = LOWER(b.email)
-- 好：ON a.email = b.email （存储时已统一为小写）

-- 多表连接时，WHERE 条件尽早过滤减少中间结果集
SELECT o.order_id, p.product_name
FROM orders o
INNER JOIN order_items oi ON o.order_id = oi.order_id
INNER JOIN products p ON oi.product_id = p.product_id
WHERE o.created_at >= '2024-01-01'  -- 尽早缩小 orders 范围
  AND p.category_id = 5;
`;
小结
    

  • INNER JOIN 只返回匹配行，LEFT JOIN 保留左表全部行并对不匹配用 NULL 填充
    • 

  • LEFT JOIN + WHERE 右表列 IS NULL 实现反连接（Anti-Join），但 NOT EXISTS 通常性能更好
    • 

  • WHERE 子句中对 LEFT JOIN 右表列的非 NULL 过滤会使 LEFT JOIN 退化为 INNER JOIN
    • 

  • CROSS JOIN 用于笛卡尔积场景，如维度表生成和矩阵填充
    • 

  • LATERAL JOIN 允许子查询引用外部列，是"每组取 Top N"的高效解法
    • 

  • 连接列必须有索引，ON 条件中避免函数调用，优化器在 Nested Loop / Hash Join / Merge Join 三种算法中选择
    •
