SELECT 查询基础

核心概念

SELECT 是 SQL 中最常用的语句，也是数据查询的核心。一条 SELECT 语句的执行遵循严格的逻辑处理顺序，理解这个顺序是写出正确 SQL 的基础。注意：SQL 的逻辑处理顺序与书写顺序完全不同。

列选择与表达式
SELECT 子句不仅用于选择列，还可以包含表达式、函数调用和条件逻辑。CASE 表达式是 SQL 中实现条件分支的标准方式。


const basicSelect = `
SELECT 
    user_id,
    username,
    email,
    EXTRACT(YEAR FROM created_at) AS register_year,
    CASE 
        WHEN status = 0 THEN '禁用'
        WHEN status = 1 THEN '正常'
        WHEN status = 2 THEN '审核中'
        ELSE '未知'
    END AS status_label,
    COALESCE(phone, '未填写') AS phone_display,
    LENGTH(username) AS name_length
FROM users;
`;

// CASE 的两种形式
const caseExpressions = `
-- Simple CASE：等值匹配
SELECT order_id,
    CASE payment_method
        WHEN 'credit_card' THEN '信用卡'
        WHEN 'debit_card' THEN '借记卡'
        WHEN 'alipay' THEN '支付宝'
        ELSE '其他'
    END AS payment_label
FROM orders;

-- Searched CASE：条件表达式
SELECT product_id, price,
    CASE 
        WHEN price < 100 THEN '低价'
        WHEN price < 500 THEN '中价'
        WHEN price < 2000 THEN '高价'
        ELSE '奢侈品'
    END AS price_tier
FROM products;
`;

聚合与 GROUP BY
GROUP BY 将行按指定列分组，配合聚合函数对每组进行计算。理解"组"的概念是掌握 GROUP BY 的关键——分组后，每组只输出一行结果。


const aggregationQueries = `
-- 基础聚合
SELECT 
    category_id,
    COUNT(*) AS product_count,
    AVG(price) AS avg_price,
    MIN(price) AS min_price,
    MAX(price) AS max_price,
    SUM(stock) AS total_stock
FROM products
GROUP BY category_id;

-- 多列分组
SELECT 
    EXTRACT(YEAR FROM order_date) AS year,
    EXTRACT(MONTH FROM order_date) AS month,
    payment_method,
    COUNT(*) AS order_count,
    SUM(amount) AS total_amount
FROM orders
GROUP BY 
    EXTRACT(YEAR FROM order_date),
    EXTRACT(MONTH FROM order_date),
    payment_method;

-- HAVING 过滤聚合结果
SELECT 
    category_id,
    COUNT(*) AS product_count,
    AVG(price) AS avg_price
FROM products
GROUP BY category_id
HAVING COUNT(*) >= 5 AND AVG(price) > 100;
`;
WHERE 与 HAVING 的区别是初学者常见的困惑点。WHERE 在分组前过滤行，HAVING 在分组后过滤组。从性能角度，尽量在 WHERE 中过滤可以减少参与分组的数据量。


DISTINCT 与去重策略
DISTINCT 用于消除结果集中的重复行。但 DISTINCT 的性能开销不可忽视——它通常需要排序或哈希操作。


const distinctQueries = `
-- 基础去重
SELECT DISTINCT category_id FROM products;

-- 多列去重
SELECT DISTINCT category_id, brand FROM products;

-- COUNT(DISTINCT ...) — 统计不重复值
SELECT 
    category_id,
    COUNT(*) AS total_products,
    COUNT(DISTINCT brand) AS brand_count,
    COUNT(DISTINCT supplier_id) AS supplier_count
FROM products
GROUP BY category_id;

-- 替代 DISTINCT 的方案：EXISTS 通常更高效
-- 低效：SELECT DISTINCT u.user_id FROM users u JOIN orders o ON ...
-- 高效：
SELECT u.user_id 
FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.user_id);
`;

类型转换与格式化
数据类型转换在查询中频繁出现，尤其在跨系统数据集成和报表生成场景中。SQL 提供 CAST 和数据库特定的类型转换函数。


const typeCasting = `
-- CAST 标准语法
SELECT 
    CAST(price AS INTEGER) AS price_int,
    CAST(created_at AS DATE) AS created_date,
    CAST(user_id AS VARCHAR(20)) AS user_id_str
FROM products;

-- PostgreSQL 简写 ::
SELECT 
    price::INTEGER,
    created_at::DATE,
    user_id::TEXT
FROM products;

-- 日期格式化
SELECT 
    TO_CHAR(created_at, 'YYYY-MM-DD HH24:MI:SS') AS formatted_date,
    TO_CHAR(amount, 'FM999,999,990.00') AS formatted_amount
FROM orders;

-- 字符串函数
SELECT 
    UPPER(username) AS upper_name,
    LOWER(email) AS lower_email,
    TRIM(BOTH ' ' FROM address) AS trimmed_addr,
    SUBSTRING(phone FROM 1 FOR 3) AS area_code,
    CONCAT(first_name, ' ', last_name) AS full_name
FROM users;
`;
隐式类型转换是常见的性能陷阱。当 WHERE 条件中对索引列进行了隐式转换，索引将失效。例如 WHERE varchar_col = 123 会导致全表扫描，应该写成 WHERE varchar_col = '123'。


小结
    

  • SELECT 的逻辑执行顺序是 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT，与书写顺序不同
    • 

  • CASE 表达式是 SQL 中实现条件分支的标准方式，支持 Simple 和 Searched 两种形式
    • 

  • NULL 遵循三值逻辑，任何涉及 NULL 的比较返回 UNKNOWN，用 COALESCE / NULLIF 处理
    • 

  • GROUP BY 将行分组后每组输出一行，WHERE 在分组前过滤，HAVING 在分组后过滤
    • 

  • DISTINCT 有性能开销，半连接场景中 EXISTS 通常比 DISTINCT + JOIN 更高效
    • 

  • 隐式类型转换是索引失效的常见原因，WHERE 条件中要保持类型一致
    •
