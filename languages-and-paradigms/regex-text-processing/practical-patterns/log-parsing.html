日志解析

日志格式概述

服务器日志和应用日志是正则解析最常见的目标。不同的日志系统使用不同的格式，但都遵循一定的结构规律。掌握日志解析的正则技巧，是后端开发和运维的必备技能。

const apacheLog = '192.168.1.1 - alice [01/Apr/2026:14:30:25 +0800] "GET /api/users HTTP/1.1" 200 1234';
const apachePattern =
  /^(?<ip>\S+)\s+\S+\s+(?<user>\S+)\s+\[(?<time>[^\]]+)\]\s+"(?<method>\w+)\s+(?<path>\S+)\s+\S+"\s+(?<status>\d+)\s+(?<size>\d+)/;
const result = apachePattern.exec(apacheLog);
result.groups.ip;
result.groups.status;
日志类型 格式特征 主要字段
Apache CLF 空格分隔，方括号时间 IP、时间、请求、状态
Nginx 类似 Apache，可自定义 IP、时间、请求、上游
JSON 日志 单行 JSON 对象 任意键值对
Syslog 标准系统日志格式 时间、主机、服务、消息
应用日志 自定义格式 时间、级别、模块、消息 


Apache/Nginx 访问日志
Web 服务器访问日志是最常见的日志格式，解析后可用于流量分析、错误排查和安全审计。


const combinedLog =
  '10.0.0.1 - - [01/Apr/2026:14:30:25 +0800] "POST /api/login HTTP/2.0" 401 256 "https://example.com/" "Mozilla/5.0"';
const combinedPattern =
  /^(?<ip>[\d.]+)\s+\S+\s+(?<user>\S+)\s+\[(?<time>[^\]]+)\]\s+"(?<method>\w+)\s+(?<url>\S+)\s+[^"]+"\s+(?<status>\d+)\s+(?<bytes>\d+)\s+"(?<referer>[^"]*)"\s+"(?<ua>[^"]*)"/;

const { groups } = combinedPattern.exec(combinedLog);
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10

rg '"(\w+)\s' -o --no-filename access.log | sort | uniq -c | sort -rn

awk '$9 >= 500 {print}' access.log

awk '$9 == 404 {print $7}' access.log | sort | uniq -c | sort -rn | head -20

应用日志解析
应用日志的格式多样，通常包含时间戳、日志级别、模块名和消息内容。


const appLog = '2026-04-01T14:30:25.123Z [ERROR] auth-service: Login failed for user alice@example.com (attempts: 3)';
const appPattern = /^(?<timestamp>[\d-]+T[\d:.]+Z)\s+\[(?<level>\w+)\]\s+(?<module>[\w-]+):\s+(?<message>.+)$/;
const { groups } = appPattern.exec(appLog);

const multiLevel = /^(?<ts>\S+)\s+(?<level>DEBUG|INFO|WARN|ERROR|FATAL)\s+(?<logger>\S+)\s+-\s+(?<msg>.+)$/;
rg '\[ERROR\]' app.log --count

rg '\[ERROR\]' app.log | awk -F: '{print $2}' | sort | uniq -c | sort -rn

rg '(?<=\[)\w+(?=\])' -o app.log | sort | uniq -c

多行日志与堆栈跟踪
堆栈跟踪和多行日志消息是日志解析的难点，需要特殊的处理策略。


const stackTrace = `2026-04-01 14:30:25 [ERROR] Unhandled exception:
TypeError: Cannot read property 'name' of undefined
    at UserService.getProfile (/app/services/user.js:42:15)
    at AuthMiddleware.handle (/app/middleware/auth.js:18:20)
    at Layer.handle (/app/node_modules/express/lib/router/layer.js:95:5)`;

const multilinePattern = /^(\d{4}-\d{2}-\d{2}\s+\d{2}:\d{2}:\d{2})\s+\[(\w+)\]\s+(.+?)(?=\n\d{4}-\d{2}-\d{2}|\n*$)/gs;

const stackPattern = /^\s+at\s+(?:(?<func>[^\s(]+)\s+)?(?:\((?<file>[^)]+)\)|(?<file2>\S+))/gm;
rg -U '^\d{4}.*ERROR[\s\S]*?(?=^\d{4}|\z)' --pcre2 app.log

awk '/^[0-9]{4}-[0-9]{2}-[0-9]{2}.*ERROR/{found=1} found{print} /^[0-9]{4}-[0-9]{2}-[0-9]{2}/&&!/ERROR/{found=0}' app.log

日志分析管道
将正则工具与管道组合，构建实时日志分析流水线。


tail -f app.log | grep --line-buffered '\[ERROR\]' | awk '{print strftime("%H:%M:%S"), $0}'

rg -o '(?<=status=)\d{3}' access.log | sort | uniq -c | awk '{printf "%s: %s (%.1f%%)\n", $2, $1, $1/NR*100}'

rg '(?<=request_time=)[\d.]+' -o access.log | awk '{sum+=$1; count++; if($1>max)max=$1} END{printf "avg=%.3f max=%.3f count=%d\n", sum/count, max, count}'

小结
    

  • 访问日志（Apache/Nginx）使用命名捕获组可以一次性提取 IP、时间、URL、状态码等全部字段。
    • 

  • 应用日志格式多样，核心是识别时间戳、级别、模块和消息四个基本要素。
    • 

  • 多行日志（堆栈跟踪）需要特殊处理，以时间戳或缩进作为记录分界。
    • 

  • 将 rg、awk、sort、uniq 通过管道组合，可以构建强大的日志分析流水线。
    • 

  • 实时日志监控使用 tail -f | grep --line-buffered 管道，错误告警可以接入通知脚本。
