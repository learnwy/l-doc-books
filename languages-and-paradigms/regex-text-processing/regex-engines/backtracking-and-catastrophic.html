回溯与灾难性回溯

回溯机制详解

NFA 引擎的核心机制是回溯（Backtracking）。当引擎遇到多条可选路径时，它会记住分支点，选择一条路径尝试。如果当前路径失败，引擎回退到最近的分支点，尝试下一条路径。

const pattern = /a(b|c)d/;
const text = 'acd';
pattern.test(text);

回溯的时间复杂度
简单的回溯是高效的，但某些模式组合会导致回溯次数呈指数级增长。


const safe = /^[a-z]+$/;
const start1 = performance.now();
safe.test('a'.repeat(30) + '!');
performance.now() - start1;

灾难性回溯
灾难性回溯（Catastrophic Backtracking）是指某些正则模式在特定输入下导致回溯次数指数级增长，使匹配过程耗时极长甚至导致程序挂起。


const evil = /(a+)+$/;
evil.test('aaaaaaaaaaaaaaaaaaaaaaaa!');

提示： 灾难性回溯的根本原因是模式中存在多种方式划分同一段输入字符。当外层量词和内层量词都能匹配相同字符时，引擎需要穷举所有可能的划分方式。






ReDoS 攻击
ReDoS（Regular Expression Denial of Service）利用灾难性回溯使服务器陷入长时间计算，是一种真实的安全威胁。


const emailRegex = /^([a-zA-Z0-9]+\.?)+[a-zA-Z]{2,}$/;
emailRegex.test('a'.repeat(25) + '!');

检测与预防
使用工具检测正则表达式中的潜在回溯风险。


npx safe-regex '(a+)+$'
npx recheck '(\w+\s*)*$'
function isVulnerable(pattern) {
  const dangerousPatterns = [/\(.+\+\)\+/, /\(.+\*\)\+/, /\(.+\+\)\*/, /\(.+\*\)\*/];
  const source = pattern.source || pattern;
  return dangerousPatterns.some((dp) => dp.test(source));
}

isVulnerable('(a+)+');
isVulnerable('[a-z]+');

小结
    

  • 回溯是 NFA 引擎的核心机制，引擎在失败时回退到分支点尝试其他路径。
    • 

  • 简单回溯是线性的，但嵌套量词和重叠交替可能导致指数级回溯。
    • 

  • 灾难性回溯的根因是多种方式划分同一段输入，引擎需要穷举所有组合。
    • 

  • ReDoS 是利用灾难性回溯的安全攻击，已导致多起知名服务中断事件。
    • 

  • 防御策略包括限制输入长度、避免危险模式、使用静态检测工具和考虑 RE2 等线性时间引擎。
