量词与贪婪模式

量词概述

量词（Quantifier）控制前一个元素的重复次数。正则表达式提供了简写量词和通用量词两种形式，它们是构建灵活匹配模式的关键。

const oneOrMore = /\d+/;
oneOrMore.exec('abc123def');

const zeroOrMore = /\d*/;
zeroOrMore.exec('abc');

const optional = /colou?r/;
optional.test('color');
optional.test('colour');
量词 含义 等价形式 示例匹配
* 零次或多次 {0,} /ab*c/ → ac、abbc
+ 一次或多次 {1,} /ab+c/ → abc、abbc
? 零次或一次 {0,1} /ab?c/ → ac、abc
{n} 恰好 n 次 — /a{3}/ → aaa
{n,} 至少 n 次 — /a{2,}/ → aa、aaa
{n,m} n 到 m 次 — /a{2,4}/ → aa 到 aaaa

贪婪模式

默认情况下，所有量词都是贪婪的——它们会尽可能多地匹配字符，然后在需要时回退（回溯）。

const greedy = /".*"/;
greedy.exec('"hello" and "world"');
贪婪匹配的结果是 "hello" and "world"，因为 .* 尽可能多地匹配，然后回溯到最后一个 " 停止。

惰性模式
在量词后添加 ? 将其变为惰性（非贪婪）模式——尽可能少地匹配字符。


const lazy = /".*?"/;
lazy.exec('"hello" and "world"');

const html = '<b>bold</b> and <i>italic</i>';
const greedyTag = /<.*>/g;
html.match(greedyTag);

const lazyTag = /<.*?>/g;
html.match(lazyTag);


提示： 惰性量词并不总是比贪婪量词快。在很多场景下，使用更精确的字符类（如 [^"]* 替代 .*?）比切换贪婪/惰性模式更高效。






独占量词与原子组
独占量词（Possessive Quantifier）在匹配后不回溯，匹配失败则直接报告失败。JavaScript 原生不支持独占量词，但可以通过原子组模拟。


import re
pattern = re.compile(r'"[^"]*+"')
const atomicLike = /"(?=[^"]*")[^"]*"/;

const efficient = /"[^"]*"/;
efficient.exec('"hello"');

量词的实际应用
合理选择量词模式直接影响匹配的正确性和性能。


const csvField = /([^,]*),/;
csvField.exec('hello,world,');

const quotedField = /"([^"]*)"/;
quotedField.exec('"hello world"');

const repeatingGroup = /(\d{3}-){2}\d{4}/;
repeatingGroup.test('123-456-7890');

const ipOctet = /\b(25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)\b/;
ipOctet.test('255');
ipOctet.test('256');
