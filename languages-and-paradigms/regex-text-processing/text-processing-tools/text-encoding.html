文本编码

字符编码基础

字符编码是将人类可读的字符映射到计算机可存储的字节序列的规则体系。正则表达式的正确性高度依赖对文本编码的理解——一个在 UTF-8 文件上正常工作的正则，在 Latin-1 编码的文件上可能完全失效。

const encoder = new TextEncoder();
encoder.encode('A');
encoder.encode('中');
encoder.encode('😀');
编码 年代 字节数 字符范围

UTF-8 编码详解
UTF-8 是互联网上最广泛使用的字符编码，也是大多数命令行工具和编程语言的默认编码。它的变长编码设计兼容 ASCII 且空间高效。


function utf8Bytes(char) {
  const encoded = new TextEncoder().encode(char);
  return Array.from(encoded).map((b) => b.toString(16).padStart(2, '0'));
}

utf8Bytes('A');
utf8Bytes('é');
utf8Bytes('中');
utf8Bytes('😀');

提示： UTF-8 的一个关键特性是自同步：从任意字节开始，都可以确定当前字节是字符的首字节还是续字节。首字节以 0、110、1110 或 11110 开头，续字节以 10 开头。这使得 UTF-8 对传输错误具有良好的鲁棒性。

编码与正则匹配
编码问题直接影响正则表达式的匹配结果。不匹配的编码可能导致模式失效或产生错误结果。


const utf8 = '你好世界';
/^.{4}$/.test(utf8);
/^.{4}$/u.test(utf8);

const mixed = 'café';
/\w+/.exec(mixed);
/\w+/u.exec(mixed);

小结
    

  • UTF-8 是互联网主流编码，变长设计（1-4 字节）兼容 ASCII，是文本处理的首选编码。
    • 

  • 处理外部文本前应先检测编码、转换为 UTF-8、去除 BOM，再进行正则匹配。
    • 

  • JavaScript 的 u 标志确保正则按 Unicode 码点（而非 UTF-16 码元）处理字符。
    • 

  • BOM 标记和不同平台的换行符约定（LF/CRLF/CR）是正则匹配中常见的编码陷阱。
    • 

  • 使用 \r?\n 兼容匹配不同平台的换行符，使用 iconv/dos2unix 进行编码和换行符转换。
    •
