纯函数与不可变性

什么是纯函数

纯函数（Pure Function）是函数式编程的基石。一个函数被称为"纯"的，当且仅当它满足两个条件：相同的输入永远返回相同的输出，且不产生任何可观察的副作用。

const add = (a: number, b: number): number => a + b;

const result1 = add(2, 3);
const result2 = add(2, 3);

上面的 add 函数是纯函数——无论调用多少次，add(2, 3) 永远返回 5。

以下是纯函数与非纯函数的对比：

特征 纯函数 非纯函数
返回值 仅由参数决定 可能依赖外部状态
副作用 无 可能修改外部状态
可预测性 完全可预测 依赖执行上下文
可测试性 极易测试 需要 mock 外部依赖
并发安全 天然线程安全 需要同步机制
可缓存性 可安全 memoize 不能缓存 


提示： 判断一个函数是否为纯函数的最简单方法：能否用它的返回值直接替换调用表达式，而不改变程序行为？这就是引用透明性的本质。






副作用的分类
副作用是函数式编程试图隔离和控制的核心问题。常见的副作用类型包括：


let counter = 0;

const impureIncrement = (): number => {
  counter += 1;
  return counter;
};

const pureIncrement = (n: number): number => n + 1;

函数式编程并不是消除所有副作用——一个没有副作用的程序无法与外界交互。关键在于将副作用推到程序边界，保持核心逻辑的纯粹性。




不可变数据
不可变性（Immutability）要求数据一旦创建就不能被修改。任何"修改"操作都返回一个新的数据副本。


const original = { name: 'Alice', age: 30 };

const updated = { ...original, age: 31 };

const numbers = [1, 2, 3];
const appended = [...numbers, 4];
-- Haskell 中所有值默认不可变
let xs = [1, 2, 3]
let ys = 0 : xs  -- [0, 1, 2, 3]，xs 不变


提示： TypeScript 中使用 readonly 修饰符和 Readonly<T> 工具类型可以在编译时保证不可变性，而运行时可以使用 Object.freeze() 进行浅冻结。

不可变性的实际收益
不可变数据配合纯函数，带来了多方面的工程收益：


const applyDiscount = (
  items: readonly { name: string; price: number }[],
  rate: number,
): { name: string; price: number }[] =>
  items.map((item) => ({
    ...item,
    price: item.price * (1 - rate),
  }));

提示： React 和 Redux 的设计哲学深度依赖不可变性。React 使用引用比较来决定是否重新渲染，Redux 要求 reducer 返回新的 state 对象——这些都是不可变性在工程中的经典应用。






小结
    

  • 纯函数保证相同输入产生相同输出且无副作用，是函数式编程的基本构件。
    • 

  • 副作用应被隔离到程序边界，核心业务逻辑保持纯粹。
    • 

  • 不可变数据通过禁止修改消除了一整类 bug，配合结构共享可避免性能开销。
    • 

  • 持久化数据结构利用结构共享实现 O(log n) 的不可变更新操作。
    • 

  • 不可变性是 React、Redux 等现代框架设计的基石，直接影响变更检测和状态管理的效率。
