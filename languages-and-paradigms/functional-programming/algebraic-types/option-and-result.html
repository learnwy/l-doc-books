Option 与 Result

空值问题

Tony Hoare 称 null 引用为他的"十亿美元错误"。传统语言使用 null/nil/None 表示值的缺失，但类型系统无法区分"一定有值"和"可能没有值"，导致空指针异常遍布运行时。

const users: Record<string, { name: string; age: number }> = {};

const name = users['alice']?.name;
const length = users['alice']?.name.length;
空值处理方式 类型安全 可组合性 语言示例
null/undefined ❌ ❌ Java, JS, C#
Optional chaining ⚠️ ⚠️ JS/TS, Swift, Kotlin
Option/Maybe ✅ ✅ Haskell, Rust, FP
哨兵值 ❌ ❌ C (-1, EOF)
异常 ❌ ❌ Java, Python 


提示： TypeScript 的 strictNullChecks 选项通过将 null 和 undefined 从所有类型中排除，部分实现了 Option 的编译时安全保证。但 Option 类型还提供了丰富的组合操作（map、flatMap 等），这是 ?. 运算符无法替代的。






Option / Maybe 类型
Option（Rust 中叫 Option，Haskell 中叫 Maybe）是一个和类型，表示值可能存在也可能缺失：


data Maybe a = Nothing | Just a

safeDivide :: Double -> Double -> Maybe Double
safeDivide _ 0 = Nothing
safeDivide a b = Just (a / b)
type Option<A> = { tag: 'none' } | { tag: 'some'; value: A };

const none: Option<never> = { tag: 'none' };
const some = <A>(value: A): Option<A> => ({ tag: 'some', value });

const safeDivide = (a: number, b: number): Option<number> => (b === 0 ? none : some(a / b));

const map =
  <A, B>(f: (a: A) => B) =>
  (opt: Option<A>): Option<B> =>
    opt.tag === 'none' ? none : some(f(opt.value));

const flatMap =
  <A, B>(f: (a: A) => Option<B>) =>
  (opt: Option<A>): Option<B> =>
    opt.tag === 'none' ? none : f(opt.value);

const getOrElse =
  <A>(defaultValue: A) =>
  (opt: Option<A>): A =>
    opt.tag === 'none' ? defaultValue : opt.value;

Result / Either 类型
Result（Rust）或 Either（Haskell）在 Option 基础上增加了错误信息，表示操作可能成功也可能失败：


data Either a b = Left a | Right b

parseAge :: String -> Either String Int
parseAge s = case reads s of
  [(n, "")] | n >= 0 && n <= 150 -> Right n
  _ -> Left ("Invalid age: " ++ s)
type Result<E, A> = { tag: 'err'; error: E } | { tag: 'ok'; value: A };

const ok = <A>(value: A): Result<never, A> => ({ tag: 'ok', value });
const err = <E>(error: E): Result<E, never> => ({ tag: 'err', error });

const mapResult =
  <E, A, B>(f: (a: A) => B) =>
  (result: Result<E, A>): Result<E, B> =>
    result.tag === 'err' ? result : ok(f(result.value));

const flatMapResult =
  <E, A, B>(f: (a: A) => Result<E, B>) =>
  (result: Result<E, A>): Result<E, B> =>
    result.tag === 'err' ? result : f(result.value);

const parseAge = (input: string): Result<string, number> => {
  const n = Number(input);
  if (Number.isNaN(n)) return err(`Invalid number: ${input}`);
  if (n < 0 || n > 150) return err(`Age out of range: ${n}`);
  return ok(n);
};

提示： Rust 的 ? 运算符让 Result 的使用变得极其简洁。let value = operation()?; 在 Ok 时解包值，在 Err 时提前返回错误。这种语法糖使得 Result 在 Rust 中完全替代了异常机制。






链式操作
Option 和 Result 的真正威力在于链式组合——多个可能失败的操作可以优雅地串联：


type User = { name: string; addressId: string };
type Address = { city: string; zip: string };

const findUser = (id: string): Option<User> => (id === '1' ? some({ name: 'Alice', addressId: 'a1' }) : none);

const findAddress = (id: string): Option<Address> => (id === 'a1' ? some({ city: 'Beijing', zip: '100000' }) : none);

const getUserCity = (userId: string): Option<string> => {
  const user = findUser(userId);
  const address = flatMap((u: User) => findAddress(u.addressId))(user);
  return map((a: Address) => a.city)(address);
};

const validateForm = (
  name: string,
  age: string,
  email: string,
): Result<string, { name: string; age: number; email: string }> => {
  const validName = name.length > 0 ? ok(name) : err('Name is required');
  const validAge = flatMapResult(parseAge)(ok(age));
  const validEmail = email.includes('@') ? ok(email) : err('Invalid email');

  if (validName.tag === 'err') return validName;
  if (validAge.tag === 'err') return validAge;
  if (validEmail.tag === 'err') return validEmail;

  return ok({
    name: validName.value,
    age: validAge.value,
    email: validEmail.value,
  });
};

小结
    

  • Option/Maybe 用和类型替代 null，在编译时强制处理值缺失的情况。
    • 

  • Result/Either 在 Option 基础上附加错误信息，是异常机制的类型安全替代。
    • 

  • map 变换内部值，flatMap 串联多个可能失败的操作，实现优雅的错误传播。
    • 

  • Rust 的 ? 运算符和 Haskell 的 do 语法为 Option/Result 提供了出色的语法支持。
    • 

  • 在 TypeScript 中可通过自定义类型或 fp-ts 库使用 Option 和 Either。
