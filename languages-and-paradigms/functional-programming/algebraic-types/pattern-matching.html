Part III · 范式与文本函数式编程 简介代数类型 简介模式匹配

模式匹配

模式匹配概述

模式匹配（Pattern Matching）是函数式编程中对代数数据类型进行分支处理的核心机制。它不仅仅是增强版的 switch——模式匹配可以解构数据、绑定变量，且编译器可以验证所有情况是否被穷尽处理。

data Shape = Circle Double | Rectangle Double Double | Triangle Double Double Double

area :: Shape -> Double
area (Circle r)        = pi * r * r
area (Rectangle w h)   = w * h
area (Triangle a b c)  = let s = (a + b + c) / 2
                          in sqrt (s * (s-a) * (s-b) * (s-c))
enum Shape {
    Circle(f64),
    Rectangle(f64, f64),
    Triangle(f64, f64, f64),
}

fn area(shape: &Shape) -> f64 {
    match shape {
        Shape::Circle(r) => std::f64::consts::PI * r * r,
        Shape::Rectangle(w, h) => w * h,
        Shape::Triangle(a, b, c) => {
            let s = (a + b + c) / 2.0;
            (s * (s - a) * (s - b) * (s - c)).sqrt()
        }
    }
}
特性 switch/case 模式匹配
解构绑定 ❌ ✅ 自动绑定变量
穷尽检查 ❌ ✅ 编译器强制
嵌套匹配 ❌ ✅ 任意深度
守卫条件 需要 if/else ✅ 原生支持
匹配值类型 相等比较 结构匹配 


提示： 模式匹配的穷尽检查（Exhaustiveness Check）是编译器的安全网。当你添加一个新的变体到和类型时，编译器会标记所有未处理新变体的 match 表达式，确保你不会遗漏任何分支。






模式的种类
模式匹配支持多种模式形式，从简单的字面量到复杂的嵌套结构：


-- 字面量模式
describe :: Int -> String
describe 0 = "zero"
describe 1 = "one"
describe _ = "other"

-- 构造器模式
unwrap :: Maybe a -> a -> a
unwrap (Just x) _ = x
unwrap Nothing  d = d

-- 元组模式
fst :: (a, b) -> a
fst (x, _) = x

-- 列表模式
head :: [a] -> Maybe a
head []    = Nothing
head (x:_) = Just x

-- 嵌套模式
deepMatch :: Maybe (Either String Int) -> String
deepMatch (Just (Right n)) = show n
deepMatch (Just (Left s))  = s
deepMatch Nothing          = "empty"

Rust 中的模式匹配
Rust 拥有最强大的模式匹配系统之一，match 表达式必须穷尽所有可能：


fn describe_number(n: i32) -> &'static str {
    match n {
        0 => "zero",
        1..=9 => "single digit",
        10..=99 => "double digit",
        _ => "large number",
    }
}

fn process_result(r: Result<i32, String>) -> String {
    match r {
        Ok(n) if n > 0 => format!("positive: {n}"),
        Ok(0) => "zero".to_string(),
        Ok(n) => format!("negative: {n}"),
        Err(e) => format!("error: {e}"),
    }
}

struct Point { x: f64, y: f64 }

fn classify_point(p: &Point) -> &'static str {
    match p {
        Point { x: 0.0, y: 0.0 } => "origin",
        Point { x, y: 0.0 } => "on x-axis",
        Point { x: 0.0, y } => "on y-axis",
        _ => "other",
    }
}

提示： Rust 编译器的穷尽检查是类型安全的重要保障。如果你在 enum 中添加新变体而忘记更新 match 表达式，编译器会直接报错——这在大型重构中尤其有价值。






TypeScript 中的模式匹配
TypeScript 没有原生模式匹配，但可以通过类型收窄和 switch 模拟：


type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'rectangle'; width: number; height: number }
  | { kind: 'triangle'; sides: [number, number, number] };

const area = (shape: Shape): number => {
  switch (shape.kind) {
    case 'circle':
      return Math.PI * shape.radius ** 2;
    case 'rectangle':
      return shape.width * shape.height;
    case 'triangle': {
      const [a, b, c] = shape.sides;
      const s = (a + b + c) / 2;
      return Math.sqrt(s * (s - a) * (s - b) * (s - c));
    }
  }
};

const exhaustiveCheck = (x: never): never => {
  throw new Error(`Unhandled case: ${x}`);
};

小结
    

  • 模式匹配是对代数数据类型进行分支处理的核心机制，远比 switch/case 强大。
    • 

  • 编译器的穷尽检查确保所有变体都被处理，是类型安全的重要保障。
    • 

  • Rust 的 match 表达式支持范围、守卫、Or 模式等丰富特性，是最强大的模式匹配实现之一。
    • 

  • TypeScript 通过 switch + never 类型或 ts-pattern 库模拟模式匹配。
    • 

  • 避免过度使用通配符 _，让编译器帮你发现未处理的新变体。
