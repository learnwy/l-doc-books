测试与属性

基于示例的测试 vs 基于属性的测试

传统测试通过手写具体的输入输出对来验证函数行为。基于属性的测试（Property-based Testing，PBT）则描述函数应满足的通用性质，由框架自动生成大量随机输入来验证这些性质。

// 基于示例的测试
test('reverse reverses array', () => {
  expect(reverse([1, 2, 3])).toEqual([3, 2, 1]);
  expect(reverse([])).toEqual([]);
  expect(reverse([1])).toEqual([1]);
});

// 基于属性的测试
test('reverse twice returns original', () => {
  fc.assert(
    fc.property(fc.array(fc.integer()), (arr) => {
      expect(reverse(reverse(arr))).toEqual(arr);
    }),
  );
});
维度 示例测试 属性测试
输入来源 手写 自动生成
覆盖范围 有限 统计覆盖（100+ 用例）
边界发现 靠经验 自动缩小（shrinking）
维护成本 随需求变更 性质稳定
表达力 具体行为 通用规律
理解门槛 低 中等 


提示： 属性测试不是示例测试的替代品，而是补充。示例测试适合验证具体的业务需求（"用户 Alice 的订单金额应该是 100"），属性测试适合验证通用的数学性质（"任何折扣后的价格不应超过原价"）。






常见属性模式
编写属性测试的关键是识别函数应满足的通用性质。以下是几种经典的属性模式：


import * as fc from 'fast-check';

fc.assert(
  fc.property(fc.array(fc.integer()), (arr) => {
    const sorted = [...arr].sort((a, b) => a - b);
    return sorted.length === arr.length;
  }),
);

fc.assert(
  fc.property(fc.string(), (s) => {
    return JSON.parse(JSON.stringify(s)) === s;
  }),
);

fc.assert(
  fc.property(fc.integer(), fc.integer(), (a, b) => {
    return add(a, b) === add(b, a);
  }),
);

提示： "往返"（Roundtrip）属性是最容易发现且最有价值的属性之一。如果你的代码中有编码/解码、序列化/反序列化、压缩/解压等配对操作，往返测试几乎一定能发现边界 bug。






fast-check 实战
fast-check 是 JavaScript/TypeScript 生态中最流行的属性测试框架：


import * as fc from 'fast-check';

const sort = (arr: number[]): number[] => [...arr].sort((a, b) => a - b);

describe('sort', () => {
  it('should preserve length', () => {
    fc.assert(
      fc.property(fc.array(fc.integer()), (arr) => {
        return sort(arr).length === arr.length;
      }),
    );
  });

  it('should produce ordered output', () => {
    fc.assert(
      fc.property(fc.array(fc.integer()), (arr) => {
        const sorted = sort(arr);
        return sorted.every((val, i) => i === 0 || sorted[i - 1] <= val);
      }),
    );
  });

  it('should contain same elements', () => {
    fc.assert(
      fc.property(fc.array(fc.integer()), (arr) => {
        const sorted = sort(arr);
        return arr.every((x) => sorted.includes(x)) && sorted.every((x) => arr.includes(x));
      }),
    );
  });
});

Shrinking：自动缩小反例
当属性测试发现失败用例时，框架会自动缩小（Shrink）输入，找到导致失败的最小反例：


fc.assert(
  fc.property(fc.array(fc.integer({ min: 1, max: 100 })), (arr) => {
    return arr.filter((x) => x > 50).length <= arr.length / 2;
  }),
);
// 失败时框架会报告最小反例，例如 [51, 51, 51]
// 而不是原始的 [73, 88, 52, 91, 67, 54, ...]




缩小策略
描述
示例





数字缩小
趋向 0
1000 → 500 → 100 → 51




数组缩小
减少长度
[a,b,c,d] → [a,b,c]




字符串缩小
减少长度和字符复杂度
"abc" → "ab" → "a"




对象缩小
逐字段缩小
{a:100,b:200} → {a:1,b:1}







提示： 好的 shrinking 是属性测试框架的核心竞争力。没有 shrinking，失败的反例可能是一个包含 100 个元素的复杂数组——有了 shrinking，你看到的是一个 3 个元素的最小反例，调试效率大幅提升。






函数式代码更易测试
纯函数和不可变数据使属性测试变得特别自然：


const add = (a: number, b: number): number => a + b;

fc.assert(fc.property(fc.integer(), fc.integer(), (a, b) => add(a, b) === add(b, a)));

fc.assert(fc.property(fc.integer(), fc.integer(), fc.integer(), (a, b, c) => add(add(a, b), c) === add(a, add(b, c))));

fc.assert(fc.property(fc.integer(), (a) => add(a, 0) === a));

小结
    

  • 属性测试通过自动生成随机输入验证函数的通用性质，是示例测试的有力补充。
    • 

  • 常见属性模式包括往返、幂等、交换律、结合律和不变量。
    • 

  • fast-check 是 TypeScript 中最流行的属性测试框架，内置丰富生成器和自动 shrinking。
    • 

  • Shrinking 自动将失败的复杂反例缩小为最小反例，大幅提升调试效率。
    • 

  • 函数式代码（纯函数、不可变、代数定律）天然适合属性测试，代数定律可直接转化为测试属性。
