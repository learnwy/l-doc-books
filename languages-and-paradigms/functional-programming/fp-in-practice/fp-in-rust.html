Rust 中的 FP

Rust 的函数式基因

Rust 虽然不是纯函数式语言，但它的设计深受函数式编程影响。所有权系统保证了安全的不可变性，Option/Result 替代了 null 和异常，模式匹配是一等特性，迭代器提供了惰性的函数式数据处理管道。

fn process_numbers(numbers: &[i32]) -> Vec<i32> {
    numbers
        .iter()
        .filter(|&&x| x > 0)
        .map(|&x| x * 2)
        .collect()
}

fn safe_divide(a: f64, b: f64) -> Option<f64> {
    if b == 0.0 { None } else { Some(a / b) }
}
FP 特性 Rust 支持 实现方式

提示： Rust 的所有权系统天然实现了函数式编程追求的不可变性——如果没有 mut，值就是不可变的。而借用检查器确保了在没有可变引用的情况下，数据不可能被意外修改。






Option 与 Result
Rust 的 Option<T> 和 Result<T, E> 是语言级的函数式错误处理机制：


fn find_user(id: u32) -> Option<User> {
    USERS.get(&id).cloned()
}

fn parse_config(path: &str) -> Result<Config, ConfigError> {
    let content = std::fs::read_to_string(path)
        .map_err(|e| ConfigError::IoError(e))?;
    toml::from_str(&content)
        .map_err(|e| ConfigError::ParseError(e))
}

fn get_user_email(id: u32) -> Option<String> {
    find_user(id)
        .filter(|u| u.is_active)
        .map(|u| u.email.clone())
}

迭代器
Rust 的 Iterator trait 是零成本抽象的函数式数据处理引擎。迭代器是惰性的——只有在消费时才真正计算：


let sum_of_squares: i32 = (1..=10)
    .filter(|x| x % 2 == 0)
    .map(|x| x * x)
    .sum();

let words: Vec<&str> = "hello world foo bar"
    .split_whitespace()
    .filter(|w| w.len() > 3)
    .collect();

struct Fibonacci {
    a: u64,
    b: u64,
}

impl Iterator for Fibonacci {
    type Item = u64;
    fn next(&mut self) -> Option<u64> {
        let result = self.a;
        self.a = self.b;
        self.b = result + self.b;
        Some(result)
    }
}

let first_10_fib: Vec<u64> = Fibonacci { a: 0, b: 1 }
    .take(10)
    .collect();

枚举与模式匹配
Rust 的 enum 是真正的代数数据类型，配合模式匹配构成了类型安全的控制流：


enum Expr {
    Lit(f64),
    Add(Box<Expr>, Box<Expr>),
    Mul(Box<Expr>, Box<Expr>),
    Neg(Box<Expr>),
}

fn eval(expr: &Expr) -> f64 {
    match expr {
        Expr::Lit(n) => *n,
        Expr::Add(a, b) => eval(a) + eval(b),
        Expr::Mul(a, b) => eval(a) * eval(b),
        Expr::Neg(e) => -eval(e),
    }
}

fn simplify(expr: Expr) -> Expr {
    match expr {
        Expr::Add(a, b) if matches!(*a, Expr::Lit(0.0)) => *b,
        Expr::Add(a, b) if matches!(*b, Expr::Lit(0.0)) => *a,
        Expr::Mul(a, _) if matches!(*a, Expr::Lit(0.0)) => Expr::Lit(0.0),
        Expr::Neg(e) if matches!(*e, Expr::Neg(_)) => {
            if let Expr::Neg(inner) = *e { *inner } else { unreachable!() }
        }
        other => other,
    }
}

Trait 与泛型
Rust 的 trait 系统在功能上接近 Haskell 的类型类（Type Class）：


trait Mappable {
    type Item;
    type Output<B>;
    fn map_over<B, F: Fn(Self::Item) -> B>(self, f: F) -> Self::Output<B>;
}

impl<A> Mappable for Option<A> {
    type Item = A;
    type Output<B> = Option<B>;
    fn map_over<B, F: Fn(A) -> B>(self, f: F) -> Option<B> {
        self.map(f)
    }
}

impl<A> Mappable for Vec<A> {
    type Item = A;
    type Output<B> = Vec<B>;
    fn map_over<B, F: Fn(A) -> B>(self, f: F) -> Vec<B> {
        self.into_iter().map(f).collect()
    }
}

提示： Rust 的 trait 单态化意味着泛型函数在编译后会为每个具体类型生成一份专用代码——这是"零成本抽象"的关键。你使用 trait 定义的 Functor-like 抽象，在运行时不会有任何额外开销。






小结
    

  • Rust 的所有权系统天然保证不可变性和内存安全，无需垃圾回收。
    • 

  • Option/Result + ? 运算符提供了类型安全的空值和错误处理，完全替代 null 和异常。
    • 

  • Iterator trait 提供惰性、零成本的函数式数据处理管道。
    • 

  • enum + match 是真正的代数数据类型 + 模式匹配，编译器强制穷尽检查。
    • 

  • trait 系统在功能上接近 Haskell 类型类，通过单态化实现零成本抽象。
