TypeScript 中的 FP

TypeScript 的 FP 能力

TypeScript 是一门多范式语言，它的类型系统虽然面向对象，但足够强大来表达许多函数式概念。一等函数、泛型、联合类型、类型推断——这些特性使 TypeScript 成为 FP 实践的可行平台。

const pipe =
  <A, B, C>(f: (a: A) => B, g: (b: B) => C) =>
  (a: A): C =>
    g(f(a));

const map =
  <A, B>(f: (a: A) => B) =>
  (xs: readonly A[]): B[] =>
    xs.map(f);
const filter =
  <A>(p: (a: A) => boolean) =>
  (xs: readonly A[]): A[] =>
    xs.filter(p);

type Option<A> = { _tag: 'None' } | { _tag: 'Some'; value: A };
type Either<E, A> = { _tag: 'Left'; left: E } | { _tag: 'Right'; right: A };
FP 特性 TypeScript 支持 备注
一等函数 ✅ 原生 箭头函数、闭包
泛型 ✅ 原生 类型参数、约束
联合类型（ADT） ✅ 原生 可辨识联合
模式匹配 ⚠️ switch 模拟 ts-pattern 库增强
不可变性 ⚠️ readonly 编译时，非运行时
高阶类型（HKT） ❌ 无原生 需要编码技巧
尾调用优化 ❌ 运行时不支持 Trampoline 替代
do 语法 ❌ 无 链式调用 / generator 


提示： TypeScript 最大的 FP 障碍是缺少高阶类型（Higher-Kinded Types）。在 Haskell 中你可以写 class Functor f where fmap :: (a -> b) -> f a -> f b，但 TypeScript 无法直接表达这种"类型参数也接受类型参数"的概念。fp-ts 通过 HKT 编码技巧绕过了这个限制。






fp-ts 生态
fp-ts 是 TypeScript 中最成熟的函数式编程库，它提供了完整的 Functor、Applicative、Monad 类型类体系：


import { pipe } from 'fp-ts/function';
import * as O from 'fp-ts/Option';
import * as E from 'fp-ts/Either';
import * as A from 'fp-ts/Array';

const processUsers = (users: Array<{ name: string; age: number }>) =>
  pipe(
    users,
    A.filter((u) => u.age >= 18),
    A.map((u) => u.name),
    A.sort(S.Ord),
  );

const safeDivide = (a: number, b: number): O.Option<number> => (b === 0 ? O.none : O.some(a / b));

const compute = pipe(
  O.some(100),
  O.flatMap((x) => safeDivide(x, 3)),
  O.flatMap((y) => safeDivide(y, 2)),
  O.getOrElse(() => 0),
);

Effect 生态
Effect 是 TypeScript FP 的新一代解决方案，提供统一的 Effect 类型处理所有计算效果：


import { Effect, pipe } from 'effect';

const divide = (a: number, b: number): Effect.Effect<number, Error> =>
  b === 0 ? Effect.fail(new Error('Division by zero')) : Effect.succeed(a / b);

const program = pipe(
  divide(100, 3),
  Effect.flatMap((x) => divide(x, 2)),
  Effect.map((x) => `Result: ${x}`),
  Effect.catchAll((e) => Effect.succeed(`Error: ${e.message}`)),
);

const result = Effect.runSync(program);

提示： Effect 的 Effect<Success, Error, Requirements> 三个类型参数分别表示成功值、错误类型和依赖要求。这相当于将 fp-ts 中需要多个 Monad Transformer 叠加的能力统一到了单一类型中。






实用 FP 模式
在 TypeScript 日常开发中，不必使用完整的 FP 库也可以应用函数式思维：


const createSlug = (title: string): string =>
  [title]
    .map((s) => s.toLowerCase())
    .map((s) => s.trim())
    .map((s) => s.replace(/[^\w\s-]/g, ''))
    .map((s) => s.replace(/\s+/g, '-'))[0];

type Validator<T> = (value: T) => string[];

const combine =
  <T>(...validators: Validator<T>[]): Validator<T> =>
  (value: T) =>
    validators.flatMap((v) => v(value));

const required: Validator<string> = (s) => (s.length === 0 ? ['Required'] : []);

const minLength =
  (n: number): Validator<string> =>
  (s) =>
    s.length < n ? [`Min length: ${n}`] : [];

const validateName = combine(required, minLength(2));

小结
    

  • TypeScript 原生支持一等函数、泛型和联合类型，是 FP 实践的可行平台。
    • 

  • fp-ts 提供完整的类型类体系（Functor、Monad 等），pipe 是其核心 API。
    • 

  • Effect 用统一的 Effect<A, E, R> 类型替代 Monad Transformer 栈，是更现代的选择。
    • 

  • 日常开发中可以不依赖 FP 库，通过 Array 链式调用、?. 和可辨识联合实践 FP 思维。
    • 

  • TypeScript 最大的 FP 限制是缺少高阶类型和尾调用优化。
