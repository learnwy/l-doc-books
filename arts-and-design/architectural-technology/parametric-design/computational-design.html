计算化设计方法 Computational Design

2008 年，Robert McNeel & Associates 的开发者 David Rutten 把一个名为 Grasshopper 的可视化编程插件挂进 Rhino 3D 的测试版本，原本只服务造船与珠宝行业的曲面建模软件，从此被建筑行业改写为算法设计的操作系统。此后十余年，计算化设计从先锋事务所的内部技能，演变为大型设计院招聘启事里的常规要求——它改变的不是「用什么软件画图」，而是设计对象的本体：从一张张固定的图纸，变为一个可被参数驱动的生成系统。

核心概念：从几何到关系

传统 CAD 的工作单元是几何体本身：一条线、一面墙、一根柱，各自独立存在，修改靠逐个点选。计算化设计的工作单元则是关系：墙的高度关联楼层参数，遮阳板的旋转角关联太阳入射角，梁的间距关联荷载组合。几何成了关系的输出结果——设计师编辑的是规则系统，几何随之自动更新。

这一转变的数学根基是非均匀有理 B 样条（NURBS）。NURBS 曲线由控制点加权定义，其基函数 Ni,p(u)N_{i,p}(u)Ni,p​(u) 按 Cox–de Boor 递推公式计算：

Ni,p(u)=u−uiui+p−uiNi,p−1(u)+ui+p+1−uui+p+1−ui+1Ni+1,p−1(u)N_{i,p}(u) = \frac{u - u_i}{u_{i+p} - u_i} N_{i,p-1}(u) + \frac{u_{i+p+1} - u}{u_{i+p+1} - u_{i+1}} N_{i+1,p-1}(u)Ni,p​(u)=ui+p​−ui​u−ui​​Ni,p−1​(u)+ui+p+1​−ui+1​ui+p+1​−u​Ni+1,p−1​(u)

对建筑师而言不必手算这个递推，但它的含义值得理解：移动一个控制点只影响局部区段的曲线形状，权重 wiw_iwi​ 则调节控制点的「引力」。正是这种局部可控性，让「参数化」成为可能——每个控制点都可以绑定一个滑块，成为设计变量。参数化设计的本质，就是把建筑几何表达为一组这样的可调变量及其关联逻辑。

flowchart LR
    A[参数输入<br/>滑块与数值] --> B[逻辑节点<br/>运算与条件]
    B --> C[几何生成<br/>曲线/曲面/构件]
    C --> D[性能评估<br/>日照/结构/能耗]
    D --> E{指标达标?}
    E -- 否 --> B
    E -- 是 --> F[输出方案<br/>图纸与数据]

这个闭环是计算化设计与传统制图的分水岭：评估结果反哺参数调整，迭代周期从「改一版图等一天」压缩到「拖一个滑块看一秒」。

工具生态的三条路线

计算化设计的工具版图沿三条路线展开，各有不同的设计哲学与适用场景。

路线 代表组合 编程范式 强项 典型插件/扩展
曲面建模 + 可视化编程 Rhino + Grasshopper 数据流节点 概念设计、自由曲面、性能分析集成 Kangaroo、Ladybug Tools、Karamba3D
BIM + 可视化编程 Revit + Dynamo 数据流节点 + Python 深化设计、构件自动化、批量修改 Dynamo Package Manager、Orkestra
影视级程序化建模 Houdini / Blender + Sverchok 节点 + VEX/Python 大规模几何生成、动态模拟 Solaris、Geometry Nodes

Rhino + Grasshopper 路线主导概念设计阶段。Grasshopper 采用纯数据流模型——数据从左向右流经节点，每个节点无副作用、可独立测试，这与函数式编程的思路一致。Kangaroo（Daniel Piker 开发）把粒子弹簧物理模拟嵌入其中，用于找形；Ladybug Tools（Mostapha Sadeghipour Roudsari 在宾夕法尼亚大学期间发起）接入 Radiance 与 EnergyPlus 模拟内核，让日照与能耗分析进入设计循环；Karamba3D（Clemens Preisinger 与 Bollinger + Grohmann 工程事务所联合开发）把有限元结构计算实时化。

Revit + Dynamo 路线主导深化与施工图阶段。Dynamo 同样是节点式，但直接操作 BIM 构件对象——批量生成参数化族、按房间数据自动布置设备、导出工程量清单。两条路线在实际项目中通常串联使用：概念形态在 Grasshopper 中敲定，再通过中间格式（IFC 或直接建模接口）进入 Revit 深化。

第三条路线正在抬头。Houdini 的程序化工作流擅长处理数十万构件级别的生成任务（例如整片立面的参数化遮阳单元），SideFX 与多家先锋事务所的合作案例显示其在响应式立面上的优势；Blender 凭借开源免费与 Geometry Nodes 的成熟，成为中小事务所和教学场景的低门槛选择。

性能驱动的工作流：定义、生成、评估、优化

一个工程上站得住的计算化设计流程包含四个阶段，缺一不可。

定义阶段回答三个问题：哪些量是变量（立面开口率、结构跨度、层高）；哪些是常量或约束（场地红线、日照法规、容积率上限）；优化目标是什么（年耗电量、结构用钢量、采光自主度）。这一步的产出是参数空间的形式化描述——它决定了后续搜索的边界。定义阶段的失误是整个流程中最昂贵的：漏掉一个硬约束（如消防登高面），后面生成的所有「最优解」都是废纸。

生成阶段把参数映射为几何。工程要点是建立稳健的关联逻辑：参数在合理区间内任意变化，模型不报错、不断裂。实践中常用「归一化 + 重映射」手法——把所有输入压到 0–1 区间再映射到实际尺寸，避免量纲混乱导致的逻辑崩溃。

评估阶段把几何翻译为性能指标。Ladybug 计算全年逐时日照与辐射，Karamba3D 输出结构利用率与挠度，EnergyPlus 估算年能耗。评估的代价差异极大：日照分析以分钟计，能耗模拟以十分钟计，这直接决定了优化的可行规模。

优化阶段在参数空间中搜索。单目标可用 Galapagos 的遗传算法，多目标用 Octopus 或 Wallacei 输出帕累托前沿（算法原理与文献锚点见 生成式算法与形态探索）。一个常被忽略的权衡是评估成本与搜索深度的乘积：如果单次评估需要 10 分钟，一万次迭代的进化优化就要跑 70 天——此时更合理的做法是先用代理模型（如响应面）近似性能函数，再做全局搜索。

经典案例：参数化如何兑现为建成结果

海达尔·阿利耶夫文化中心（巴库，Zaha Hadid Architects，2012 年竣工）常被当作「曲面炫技」，但真正值得记录的是其建造翻译链：连续曲面被离散为超过 1.2 万块尺寸各异的 GRC（玻璃纤维增强混凝土）与 GRP（玻璃纤维增强聚酯）面板，每一块的几何、编号与加工数据全部由参数化模型直接输出给工厂。没有参数化管线，这种「每块板都不同」的建造在经济上不可行。

阿布扎比卢浮宫（Atelier Jean Nouvel，2017 年竣工）的 180 米直径穹顶由八层几何图案交错叠加，形成约 7,850 个星形镂空。需要澄清一个流传甚广的错误：这座建筑的设计师是让·努维尔（Jean Nouvel），而非 Foster + Partners。设计团队用参数化工具逐一定位每个星形单元的角度与密度，使穹顶在正午强日晒下仍能筛出细碎光斑（「光之雨」），同时把穹顶下方的体感温度显著压低——形式与热性能在同一个模型里被联合求解。

VIA 57 West（纽约，BIG，2016 年竣工）展示了参数化在规范约束下的应变：三角形地块叠加日照退缩法规，BIG 把这些约束直接编码为生成规则，得到「北面是庭院住宅、南面是塔楼」的混合体量。约束越苛刻，参数化方法的相对优势越明显——因为它把「合规检查」从人工比对变成了模型内置条件。

反模式与局限

形式主义陷阱：工具让复杂曲面变便宜，但「能建」不等于「该建」。判断标准应当是性能增益能否覆盖造价与运维的增量——阿布扎比卢浮宫的穹顶同时解决遮阳与光环境，是形式服务性能；而某些项目把参数化等同于「扭曲立面」，只增加了模板成本与幕墙清洁难度。评审一个参数化方案的正确提问是：删掉参数化逻辑，这个方案的性能会不会变差？

定义文件的技术债：大型 Grasshopper 定义动辄数百节点，命名混乱、分组缺失的文件在三个月后连作者本人都无法维护。工程对策是把参数化定义当作软件项目管理——版本控制（有团队用 Grasshopper 版的 diff 工具）、输入输出端口注释、模块化封装（User Object）。

学习曲线与角色分工：节点式编程降低了门槛但没有消除它。务实的团队结构是「少数计算设计专员 + 多数会用的建筑师」，而非要求全员成为程序员。计算设计专员的价值不在炫技，而在把结构工程、热工、法规知识翻译成可复用的计算模板。

小结

  • 计算化设计把设计对象从几何改为关系，几何成为参数系统的输出；NURBS 的局部可控性是这一切的数学前提。
  • 工具生态三条路线各司其职：Rhino + Grasshopper 主攻概念与性能集成，Revit + Dynamo 主攻 BIM 深化自动化，Houdini/Blender 处理大规模程序化生成。
  • 完整工作流是「定义 → 生成 → 评估 → 优化」的闭环；评估成本决定优化策略，代理模型是大规模优化的前置手段。
  • 案例的共性不是形态复杂，而是参数化管线打通了从模型到工厂的数据链——面板编号、加工数据、规范合规都由模型直接输出。
