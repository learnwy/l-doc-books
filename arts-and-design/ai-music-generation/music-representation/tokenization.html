音乐 Token 化策略

Token 化的核心挑战

音乐 Token 化（Music Tokenization）是将连续或半连续的音乐数据转化为离散 Token 序列的过程——这是应用 Transformer 等序列模型的前提。挑战在于音乐的多维性：时间、音高、力度、音色需要同时编码到一维序列中：

Music→TokenizeToken Sequence=[t1,t2,…,tN]∈VN\text{Music} \xrightarrow{\text{Tokenize}} \text{Token Sequence} = [t_1, t_2, \ldots, t_N] \in \mathcal{V}^NMusicTokenize​Token Sequence=[t1​,t2​,…,tN​]∈VN

其中 V\mathcal{V}V 是词表（Vocabulary），NNN 是序列长度。词表大小和序列长度的权衡是设计的核心张力——词表越大每步信息越多但学习更难，序列越长覆盖越完整但计算成本更高。

REMI 表示法
REMI（REvamped MIDI-derived representation）是 Pop Music Transformer 提出的里程碑式 Token 化方案。它引入位置 Token 和 Bar/Position 概念，使模型能感知音乐的节拍结构：


REMI Sequence=[Bar,Position,Pitch,Duration,Velocity,…]\text{REMI Sequence} = [\text{Bar}, \text{Position}, \text{Pitch}, \text{Duration}, \text{Velocity}, \ldots]REMI Sequence=[Bar,Position,Pitch,Duration,Velocity,…]

REMI 的核心洞察是：通过显式编码位置信息，模型不需要从 delta-time 中"计算"节拍对齐，降低了学习难度。


Compound Word Token 化
Compound Word（复合词）策略将描述同一个音乐事件的多个属性合并为单个 Token 向量，而非展开为多个独立 Token。这大幅缩短序列长度：


Compound Tokeni=[typei,pitchi,durationi,velocityi,positioni]\text{Compound Token}_i = [\text{type}_i, \text{pitch}_i, \text{duration}_i, \text{velocity}_i, \text{position}_i]Compound Tokeni​=[typei​,pitchi​,durationi​,velocityi​,positioni​]
每个 Compound Token 是多维向量，各维度有独立嵌入，然后聚合为统一表示输入 Transformer：

音频 Token 化与 RVQ
音频 Token 化是近两年的突破性进展——通过神经音频编码器（如 EnCodec）将连续波形转换为离散 Token，使语言模型方法直接应用于音频生成：


Audio24kHz→Encoderz∈RT′×D→RVQCodes∈{0,...,1023}T′×Q\text{Audio}_{24\text{kHz}} \xrightarrow{\text{Encoder}} z \in \mathbb{R}^{T' \times D} \xrightarrow{\text{RVQ}} \text{Codes} \in \{0,...,1023\}^{T' \times Q}Audio24kHz​Encoder​z∈RT′×DRVQ​Codes∈{0,...,1023}T′×Q
其中 T′=T/320T' = T/320T′=T/320（下采样因子 320），QQQ 是 RVQ 层数（通常 8–32），每层有 1024 个码本条目。

RVQ 的层级结构自然对应"粗到细"的生成策略：先生成第一层（语义/结构），再逐层生成后续层（细节/质量），这也是 MusicGen 和 SoundStorm 的核心设计思路。


Token 化设计的权衡空间
不同任务和模型对 Token 化有不同偏好。设计 Token 化方案需要在多个维度做出权衡：

Token 化不是一次性决策——它与模型架构和训练目标共同演化。最佳实践是：先确定任务目标，再选择信息保留优先级，最后设计具体编码方案。Token 化质量直接决定模型的生成上限——再强大的模型也无法生成 Token 化过程中已经丢失的信息。
