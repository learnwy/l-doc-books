多格式交付与适配

概述

现代影视项目通常需要同时交付 HDR 和 SDR 多个版本，覆盖流媒体、蓝光、广播、影院等不同分发渠道。多格式交付的核心挑战在于：如何在保持创作者视觉意图的前提下，高效生成适配不同显示能力终端的多个输出版本。

本文系统介绍 HDR-to-SDR 色调映射、双母版工作流、IMF 包装格式、显示自适应交付策略，以及 OOTF/EOTF 传递函数链路的完整技术体系。

传递函数链路基础

OETF / EOTF / OOTF 三函数体系

理解多格式交付首先需要掌握三个核心传递函数的角色：

函数 全称 位置 作用
OETF Opto-Electronic Transfer Function 摄影机/编码端 将场景光线转换为电信号
EOTF Electro-Optical Transfer Function 显示端 将电信号转换为光输出
OOTF Opto-Optical Transfer Function 系统整体 场景光 → 显示光的整体映射

三者关系：OOTF = EOTF ∘ OETF

PQ 系统的传递函数链
在 PQ（ST 2084）系统中：


    

  • EOTF = ST 2084 反向曲线（代码值 → 绝对亮度）
    • 

  • Inverse EOTF = ST 2084 正向曲线（绝对亮度 → 代码值）
    • 

  • OOTF = 非定义（系统中不预设 OOTF，显示端直接输出 EOTF 结果）
    • 



PQ 系统假设内容已经过创意调色并包含最终显示意图，EOTF 仅做反向解码，不附加额外渲染。


HLG 系统的传递函数链
在 HLG 系统中：


    

  • OETF = HLG 曲线（场景光 → 信号值）
    • 

  • EOTF = HLG 反向 OETF + 系统伽马 OOTF
    • 

  • OOTF = 系统伽马渲染（γ = 1.2 标称，根据显示器峰值亮度调整）
    • 



HLG 的 OOTF 是自适应的关键——它允许同一信号在不同峰值亮度的显示器上自动调整对比度和饱和度。


HDR-to-SDR 色调映射
映射挑战
HDR 内容的亮度范围可达 0.0001–10,000 nits，而 SDR 显示器输出范围仅约 0.01–100 nits（BT.1886 参考）。将 HDR 压缩到 SDR 是一个有损过程，核心矛盾在于：


    

  • 线性压缩 → 整体变暗、对比度丧失
    • 

  • 保留高光 → 中间调和暗部被过度压缩
    • 

  • 保留暗部 → 高光全部裁切
    •

ITU-R BT.2390 参考色调映射
BT.2390 是 ITU 推荐的 HDR-to-SDR 色调映射参考方法，核心步骤：


    

  1. 将 PQ 信号转换为线性光（ST 2084 EOTF）
    2. 

  2. 归一化到 0–1 范围（除以源峰值亮度）
    3. 

  3. 应用 S 曲线压缩：保持中间调斜率接近 1，平缓压缩高光和暗部
    4. 

  4. 重新映射到 SDR 输出范围
    5. 

  5. 应用 BT.1886 Inverse EOTF编码
    6. 



BT.2390 定义了三个关键参数：


    

  • KneeStart：曲线开始压缩的亮度位置
    • 

  • KneeEnd：曲线完全饱和的亮度位置
    • 

  • MaxLum：映射后的最高输出亮度
    •

双母版工作流
工作流概述
双母版（Dual Master）工作流是当前高品质多格式交付的标准实践。其核心理念是：由调色师分别完成 HDR 母版和 SDR 母版的创意调色，而非简单的自动转换。


Trim Pass（修剪调色）
Trim Pass 是在 HDR 主调色完成后，针对 SDR 输出进行的微调过程：


    

  • 不重新从头调色，而是基于 HDR 调色数据进行修剪
    • 

  • 主要调整高光压缩、暗部提升、整体曝光偏移
    • 

  • DaVinci Resolve 支持在同一时间线上使用 Dolby Vision Trim 功能
    • 

  • 典型时间消耗：HDR 主调色的 20–30%
    •

IMF 包装格式
IMF 概述
IMF（Interoperable Master Format，SMPTE ST 2067）是好莱坞工作室和全球流媒体平台的标准交付格式。它将影片的不同版本要素（视频、音频、字幕、元数据）解耦存储，通过组合清单（CPL）定义不同版本。

Gain Map 技术
2024–2025 年兴起的 Gain Map（增益图）技术为静态图像和短视频提供了新的 HDR/SDR 兼容方案：


    

  • 存储一个 SDR 基础图 + 一个增益图（Gain Map）
    • 

  • SDR 设备直接显示基础图
    • 

  • HDR 设备根据增益图和显示能力动态渲染 HDR 版本
    • 

  • 已被 Apple（iPhone 14+ 照片）、Google（Ultra HDR）、Adobe 采用
    • 

  • ISO/TS 22028-5 标准化进程中
    •

端到端工作流实践
DaVinci Resolve 多格式输出
DaVinci Resolve 支持在一个项目中管理多个交付版本：


Dolby Vision 工作流：


    

  1. 项目设置 → Color Management → Dolby Vision
    2. 

  2. 在 HDR 色彩空间中完成主调色（P3-D65 ST 2084 或 Rec.2020 ST 2084）
    3. 

  3. 执行 Trim Pass 生成 SDR/低亮度目标版本
    4. 

  4. 导出时自动嵌入 Dolby CM 元数据
    5. 

  5. 同时输出 HDR10 兼容流
    6. 



ACES 2.0 多目标输出：


    

  1. 项目设置 → Color Science → ACEScct / ACEScg
    2. 

  2. 选择 ACES 2.0 Output Transform
    3. 

  3. 在同一时间线中切换不同 ODT 预设预览
    4. 

  4. 逐个渲染不同目标版本
    5. 



Premiere Pro 自动色调映射
Adobe Premiere Pro 2025 版本内置了自动色调映射功能：


    

  • 默认启用：iPhone HLG 素材在 Rec.709 序列中自动色调映射

  • 支持 PQ 和 HLG 格式到 SDR 的自动映射
    • 

  • 支持 Log 素材（Sony S-Log、Canon C-Log、Panasonic V-Log）的自动处理

Netflix HDR 交付规范要点
    

  • 母版必须在 1,000 nits 监视器上完成最终审看
    • 

  • MaxCLL 和 MaxFALL 必须基于实际内容精确计算（非估算）
    • 

  • HDR 与 SDR 版本必须帧对齐、镜头对齐
    • 

  • Dolby Vision 元数据必须覆盖全片无间隙
    • 

  • 建议在 4,000 nits 和 600 nits 监视器上分别验证映射效果
    • 



光敏性癫痫（PSE）测试
Warner Bros. Discovery 等主要平台要求：


    

  • 所有 HDR 内容需进行 Harding Flash & Pattern Analyzer 测试
    • 

  • 由于 HDR 专用测试工具尚未完全普及，建议对 HDR 内容进行色调映射后的 SDR 导出版本进行 PSE 测试
    • 

  • 遵循 ITU-R BT.1702-3 关于减少光敏性癫痫风险的指南
    • 



未来趋势
    

  • 统一交付格式演进：IMF 正在成为所有主要平台的标准交付格式，Netflix、Disney+、Amazon 均已要求或接受 IMF 交付
    • 

  • 自动化映射质量提升：AI 驱动的色调映射正在缩小自动派生与手动 Trim Pass 之间的质量差距
    • 

  • ACES 2.0 简化多目标输出：统一参数化输出变换使得"一次调色、多目标输出"的实际操作复杂度大幅降低
    • 

  • 端侧 AI 适配：Dolby Vision 2 和 HDR10+ Advanced 将部分适配智能从制作端移至播放端，利用 AI 根据内容类型和环境实时优化
    • 

  • Gain Map 扩展到视频：静态图像领域成功的 Gain Map 方案有望扩展到短视频/UGC 内容，降低 HDR 内容创作门槛
    •
