封装与流管理

封装（Muxing）基础概念

封装（Multiplexing，简称 Muxing）是将独立的视频流、音频流、字幕流和元数据合并为单一容器文件的过程。其逆过程称为解封装（Demuxing）——从容器中分离出各独立流。封装是视频生产流水线中连接编码与分发的关键环节。

封装器不改变流的编码内容，只负责将多条流按照容器格式的规范组织在一起。因此，纯封装操作（无重编码）的速度极快——通常可达到磁盘 I/O 的理论带宽上限。

一个视频文件可能包含多条轨道，每条轨道对应一个独立的 ES。轨道之间通过时间戳同步：

其中 PTSPTSPTS 为 Presentation Time Stamp（显示时间戳），Δthreshold\Delta_{threshold}Δthreshold​ 通常设为 40-80ms（人类对音画不同步的感知阈值）。


时间戳与同步机制
PTS 与 DTS
视频编码中存在两种时间戳：

对于纯 I 帧编码（如 ProRes），PTS 始终等于 DTS。但当存在 B 帧时，解码顺序与显示顺序不同：


显示顺序:I0, B1, B2, P3, B4, B5, P6\text{显示顺序}: I_0,\ B_1,\ B_2,\ P_3,\ B_4,\ B_5,\ P_6显示顺序:I0​, B1​, B2​, P3​, B4​, B5​, P6​
解码顺序:I0, P3, B1, B2, P6, B4, B5\text{解码顺序}: I_0,\ P_3,\ B_1,\ B_2,\ P_6,\ B_4,\ B_5解码顺序:I0​, P3​, B1​, B2​, P6​, B4​, B5​
编码器在 B 帧预测时需要参考未来帧（P 或 I），因此参考帧必须先解码。DTS 确保解码器按正确顺序接收帧数据，PTS 确保渲染器按正确顺序显示帧。

多轨道管理
轨道属性与映射
FFmpeg 中的轨道映射是封装操作的核心。-map 参数指定从输入文件中选择哪些流放入输出容器：






映射语法
含义





-map 0
输入文件 0 的所有流




-map 0:v
输入文件 0 的所有视频流




-map 0:a:1
输入文件 0 的第 2 条音频流




-map 1:s
输入文件 1 的所有字幕流




-map -0:a:2
排除输入文件 0 的第 3 条音频





复杂的多源封装示例：


ffmpeg -i movie.mp4 -i commentary.aac -i chinese.srt \
  -i english.ass -i cover.jpg \
  -map 0:v -map 0:a -map 1:a -map 2:s -map 3:s \
  -map 4 -disposition:a:0 default -disposition:a:1 comment \
  -metadata:s:a:0 language=chi -metadata:s:a:1 language=eng \
  -metadata:s:s:0 language=chi -metadata:s:s:1 language=eng \
  -c copy output.mkv

封装格式转换（Remuxing）
无损转封装
Remuxing（重封装）是在不重新编码的情况下改变容器格式。这是最快的格式转换方式：






转换方向
命令
限制条件





MKV → MP4
ffmpeg -i in.mkv -c copy out.mp4
编码必须 MP4 兼容




MP4 → MKV
ffmpeg -i in.mp4 -c copy out.mkv
几乎无限制




TS → MP4
ffmpeg -i in.ts -c copy out.mp4
需 H.264/H.265




MOV → MP4
ffmpeg -i in.mov -c copy out.mp4
ProRes 不兼容 MP4





转封装失败的常见原因：


    

  1. 编码不兼容：目标容器不支持源编码（如 ProRes → MP4）
    2. 

  2. 字幕格式不兼容：ASS → MP4 需转为 mov_text
    3. 

  3. 时间戳溢出：超长视频的 PTS 超出容器时间基准范围
    4. 

  4. DTS 非单调递增：损坏的源文件导致时间戳回跳

分片封装（Segmented Muxing）
流媒体分发需要将连续视频切割为固定时长的分片：


HLS 分片封装：


ffmpeg -i input.mp4 -c copy \
  -f hls -hls_time 4 -hls_segment_type fmp4 \
  -hls_fmp4_init_filename init.mp4 \
  -hls_segment_filename 'seg_%03d.m4s' \
  playlist.m3u8
关键参数：


    

  • -hls_time 4：每片 4 秒（必须是 GOP 的整数倍）
    • 

  • -hls_segment_type fmp4：使用 fMP4 分片（非 MPEG-TS）
    • 

  • 初始化段（init segment）包含编码参数，只需下载一次
    • 



高级封装操作
延迟偏移与同步修正
当音视频流来自不同源（如外录音频）时，可能存在偏移：


偏移修正:−itsoffset Δt −i audio.wav\text{偏移修正}: -itsoffset\ \Delta t\ -i\ audio.wav偏移修正:−itsoffset Δt −i audio.wav
正值表示延迟音频开始，负值表示提前。精确同步通常需要基于打板（Clapperboard）或时间码对齐。


流复制与选择性编码
封装操作中可以混合使用 "复制" 和 "编码"：


ffmpeg -i input.mkv \
  -map 0:v -c:v copy \          # 视频: 直接复制
  -map 0:a:0 -c:a:0 copy \     # 音频1: 直接复制
  -map 0:a:1 -c:a:1 aac -b:a:1 128k \  # 音频2: 重编码为AAC
  -map 0:s -c:s copy \          # 字幕: 直接复制
  output.mkv
这种混合模式常用于：


    

  • 保留视频不动，仅转换不兼容的音频编码
    • 

  • 保留主音轨，为次要音轨降低码率
    • 

  • 在不同容器间迁移时处理不兼容的字幕格式
    • 



实时封装与管道操作
FFmpeg 支持从标准输入读取和向标准输出写入，实现管道式封装：


编码器→pipe封装器→pipe分发系统\text{编码器} \xrightarrow{pipe} \text{封装器} \xrightarrow{pipe} \text{分发系统}编码器pipe​封装器pipe​分发系统
这在直播场景中尤为重要：编码器实时产出 ES，封装器实时切片，分发系统实时推送到 CDN。整个流水线无需落盘中间文件。
