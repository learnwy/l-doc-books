自然演绎

核心概念

自然演绎（Natural Deduction）是由根岑（Gerhard Gentzen）于 1934 年提出的证明系统，其核心思想是模拟人类自然推理的过程。与公理化方法不同，自然演绎没有预设公理，所有推理都通过引入规则（Introduction Rules）和消去规则（Elimination Rules）完成。

对程序员而言，自然演绎不仅是形式逻辑的核心方法，更是理解类型系统和程序验证的关键桥梁。Curry-Howard 同构（Curry-Howard Isomorphism）揭示了证明与程序之间的深刻对应：一个逻辑证明就是一个程序，一个命题就是一个类型。

引入规则与消去规则的对称性
自然演绎的美妙之处在于每个联结词都有一对对称的规则：引入规则说明如何构造包含该联结词的公式，消去规则说明如何使用该公式。这种对称性在类型论中对应着值的构造（Construction）和使用（Destruction）。


合取（∧）的规则：


    

  • ∧-引入（∧I）：如果已证明 A 和已证明 B，则可得 A ∧ B
    • 

  • ∧-消去（∧E）：如果已证明 A ∧ B，则可得 A（或 B）
    • 



这直接对应元组的构造和解构：


const pair: [A, B] = [a, b]; // ∧-引入
const first: A = pair[0]; // ∧-消去
蕴含（→）的规则：


    

  • →-引入（→I）：假设 A 成立，如果能推出 B，则得 A → B（假设被"消解"）
    • 

  • →-消去（→E，即 Modus Ponens）：如果有 A → B 和 A，则得 B
    • 



这对应函数的定义和调用：


const f = (a: A): B => {
  /* 从 a 推导出 b */
}; // →-引入
const result: B = f(a); // →-消去
析取（∨）的规则：


    

  • ∨-引入（∨I）：如果已证明 A，则可得 A ∨ B（或 B ∨ A）
    • 

  • ∨-消去（∨E）：如果有 A ∨ B，且从 A 能推出 C，从 B 也能推出 C，则得 C
    • 



这对应联合类型的构造和模式匹配：


type Result = Success | Failure;
function handle(r: Result): Output {
  if (r instanceof Success) return handleSuccess(r); // 分支 A → C
  if (r instanceof Failure) return handleFailure(r); // 分支 B → C
}
假设的管理与作用域
自然演绎的一个关键特征是假设（Hypothesis）的管理。在证明过程中，我们可以临时引入假设，使用假设推导出结论，然后通过 →-引入规则"消解"假设。被消解的假设不再是全局前提，而是被编码进了蕴含式中。


这与编程中变量作用域（Scope）的概念完美对应。函数参数在函数体内有效，在函数外部不可见。类似地，逻辑假设在证明的子推导中有效，消解后失去效力。


嵌套假设产生嵌套蕴含。例如，证明 A → (B → A)：


    

  1. 假设 A（外层假设）
    2. 

  2. 假设 B（内层假设）
    3. 

  3. 由假设 A 得 A（在两个假设的作用域内）
    4. 

  4. 消解假设 B，得 B → A
    5. 

  5. 消解假设 A，得 A → (B → A)
    6. 



对应的程序是柯里化函数：const f = (a: A) => (b: B) => a;


反证法与构造性推理
自然演绎系统中有两种处理否定的重要规则：


归谬法（Reductio ad Absurdum, RAA）：假设 ¬A，如果能推出矛盾（⊥），则得 A。这是经典逻辑中的反证法。


否定引入（¬I）：假设 A，如果能推出矛盾（⊥），则得 ¬A。


这两条规则看似相似，但存在本质区别。归谬法需要排中律的支持，它在构造性逻辑（Constructive Logic）中不被接受。构造性逻辑要求证明一个存在命题时必须给出具体的见证（Witness），而不仅仅是排除其否定的可能性。

TypeScript 的 never 类型





在 TypeScript 中，never 类型对应逻辑中的 ⊥（Falsity）。当一个函数的返回类型是 never 时，意味着该函数不可能正常返回——它要么抛出异常，要么无限循环。这正是 ⊥-消去规则（Ex Falso Quodlibet）的体现：从矛盾可以推出任何结论。


构造性推理的思想深刻影响了类型论和函数式编程。在 Haskell、Agda、Coq 等语言中，类型系统强制要求程序是全函数（Total Function），即对所有输入都有定义。这与构造性逻辑要求证明提供具体见证是同一原则的不同表现。


证明策略与调试思维
掌握自然演绎的证明策略，对程序员的调试和问题解决能力有直接帮助。


目标导向策略（Goal-Directed）：从要证明的结论出发，反向寻找需要的前提。这对应编程中的"从输出反推输入"的调试方法——如果函数输出不对，先看输出是由哪些中间值计算的，再往上追溯。


前向推理策略（Forward Reasoning）：从已知前提出发，逐步推导新结论。这对应"从输入跟踪到输出"的调试方法——跟踪数据流，看在哪一步变异出了问题。


分情况讨论策略（Case Analysis）：对应 ∨-消去规则。当前提包含析取时，分别讨论每种情况。这是编程中 switch-case 和模式匹配的逻辑基础。确保所有分支都被覆盖，对应逻辑上的穷举性（Exhaustiveness）。


TypeScript 的穷举检查是这一原理的工程实现：


type Shape = Circle | Square | Triangle;
function area(s: Shape): number {
  switch (s.kind) {
    case 'circle':
      return Math.PI * s.r ** 2;
    case 'square':
      return s.side ** 2;
    case 'triangle':
      return 0.5 * s.base * s.height;
    default:
      const _exhaustive: never = s;
      return _exhaustive;
  }
}

自然演绎是类型系统和程序验证的理论基础

小结
    

  • 自然演绎通过引入/消去规则对模拟自然推理，其对称结构对应类型系统中的构造与解构
    • 

  • 假设的作用域管理与编程中的变量作用域完美对应，消解假设等价于函数抽象
    • 

  • Curry-Howard 同构揭示了逻辑证明与程序之间的深刻统一，写类型安全的代码就是在做证明
    • 

  • 构造性推理要求提供具体见证，这一精神贯穿函数式编程和现代类型系统
    • 

  • 自然演绎的证明策略（目标导向、前向推理、分情况讨论）直接对应调试和问题解决方法
    •
