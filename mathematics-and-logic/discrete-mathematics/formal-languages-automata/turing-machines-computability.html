图灵机与可计算性

核心概念

图灵机（Turing Machine, TM）是计算理论的核心模型，由 Alan Turing 在 1936 年提出。图灵机定义了"可计算"的边界——一个问题是可计算的当且仅当存在图灵机能够解决它。Church-Turing 论题断言图灵机的计算能力等价于任何合理的计算模型（λ 演算、递归函数、寄存器机等）。

图灵机比有限自动机和下推自动机更强大，因为它拥有无限的读写带。这种无限存储能力使图灵机能够模拟任何算法过程。但即便如此，仍然存在图灵机无法解决的问题——停机问题就是最著名的不可判定问题。

图灵机的形式化定义
图灵机定义：M = (Q, Σ, Γ, δ, q₀, q_accept, q_reject)


    

  • Q：有限状态集
    • 

  • Σ：输入字母表（不含空白符 ⊔）
    • 

  • Γ：带字母表（Σ ⊂ Γ，⊔ ∈ Γ）
    • 

  • δ: Q × Γ → Q × Γ × {L, R}：转移函数
    • 

  • q₀：初始状态
    • 

  • q_accept：接受状态
    • 

  • q_reject：拒绝状态
    • 



interface TuringMachine {
  states: Set<number>;
  inputAlphabet: string[];
  tapeAlphabet: string[];
  transitions: Map<string, { nextState: number; write: string; move: 'L' | 'R' }>;
  startState: number;
  acceptState: number;
  rejectState: number;
  blank: string;
}

function simulateTM(
  tm: TuringMachine,
  input: string,
  maxSteps: number,
): { accepted: boolean; rejected: boolean; tape: string[] } {
  const tape: string[] = [...input, ...Array(100).fill(tm.blank)];
  let head = 0;
  let state = tm.startState;
  let steps = 0;

  while (steps < maxSteps) {
    if (state === tm.acceptState) return { accepted: true, rejected: false, tape };
    if (state === tm.rejectState) return { accepted: false, rejected: true, tape };

    const key = `${state},${tape[head]}`;
    const transition = tm.transitions.get(key);
    if (!transition) return { accepted: false, rejected: true, tape };

    tape[head] = transition.write;
    state = transition.nextState;
    head += transition.move === 'R' ? 1 : -1;

    if (head < 0) {
      tape.unshift(tm.blank);
      head = 0;
    }
    if (head >= tape.length) tape.push(tm.blank);

    steps++;
  }

  return { accepted: false, rejected: false, tape };
}
图灵机的计算过程：从初始状态开始，读写头位于输入的最左端。每一步根据当前状态和读写头下的符号，执行转移：写入新符号、移动读写头、转入新状态。当进入接受状态时接受，进入拒绝状态时拒绝。


通用图灵机与停机问题
通用图灵机（Universal Turing Machine, UTM）是一个特殊的图灵机，它将另一个图灵机的描述 ⟨M⟩ 和输入 w 作为输入，模拟 M 在 w 上的运行。UTM 的存在证明了"可编程计算机"的概念在理论上是可行的。


停机问题（Halting Problem）：给定图灵机 M 和输入 w，判定 M 在 w 上是否停机。Turing 通过对角化论证证明了停机问题不可判定。


function haltingProblemDemo(): void {
  const cannotDecideHalting = (machineDescription: string, input: string): 'halts' | 'loops' => {
    throw new Error('This function cannot exist - halting problem is undecidable');
  };

  const paradoxMachine = (input: string): void => {
    try {
      const result = cannotDecideHalting(input, input);
      if (result === 'halts') {
        while (true) {}
      }
    } catch {
      return;
    }
  };

  void paradoxMachine;
}
可判定性与归约
语言分类：


    

  • 递归语言（Decidable）：存在总是停机的图灵机判定之
    • 

  • 递归可枚举语言（R.E.）：存在图灵机识别之（接受时停机，不接受时可能不停机）
    • 

  • 非递归可枚举语言：不存在图灵机识别之
    • 



归约（Reduction）：问题 A 归约到问题 B（A ≤ B），意味着如果能解决 B 就能解决 A。归约用于证明不可判定性：如果 A 不可判定且 A ≤ B，则 B 也不可判定。

Rice 定理：图灵机的任何非平凡语义性质都是不可判定的。即如果性质 P 不是对所有 TM 都成立也不是对所有 TM 都不成立，则判定"给定 TM 是否满足 P"是不可判定的。

Chomsky 层次
Chomsky 层次将形式语言按表达能力从弱到强分为四类：


| 类型   | 语言类   | 文法限制      | 自动机  | 封闭性   |
| ------ | -------- | ------------- | ------- | -------- | --- | --- | --- | -------- |
| Type 3 | 正则语言 | A → aB, A → a | DFA/NFA | 全部封闭 |
| Type 2 | CFL      | A → α         | PDA     | 非交补   |
| Type 1 | CSL      |               | α       | ≤        | β   |     | LBA | 全部封闭 |
| Type 0 | RE       | 无限制        | TM      | 非补     |


每一层严格包含下一层。这个层次结构是计算理论和编译原理的理论基石。


小结
    

  • 图灵机定义了"可计算"的边界，Church-Turing 论题断言其计算能力等价于任何合理计算模型
    • 

  • 停机问题是第一个被证明不可判定的问题，对角化论证是其核心证明技术
    • 

  • Rice 定理表明图灵机的任何非平凡语义性质都不可判定，这限制了静态分析的能力
    • 

  • Chomsky 层次将形式语言分为四类，每一层对应不同的自动机模型和计算能力
    • 

  • 可判定性理论揭示了计算的根本限制，是理解算法可行性的理论基础
    •
