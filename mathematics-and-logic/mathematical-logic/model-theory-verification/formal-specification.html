形式化规约

核心概念

形式化规约（Formal Specification）是用数学精确的形式语言描述软件系统行为的方法。与自然语言需求文档不同，形式化规约具有无歧义、可机器检查和可推理的特性。它回答的核心问题是：系统"应该做什么"如何用逻辑语言精确表述？

形式化规约是连接数理逻辑与软件工程的桥梁。一阶逻辑、时序逻辑和类型理论提供了规约的表达框架；模型检测、定理证明和抽象解释提供了验证规约是否被满足的技术手段。从 Z 语言到 TLA+ 再到 Alloy，形式化方法已从学术研究走向工业实践——Amazon 使用 TLA+ 验证 AWS 分布式协议，微软使用 Dafny 验证系统核心组件。

前置条件与后置条件规约
契约式设计（Design by Contract，Meyer，1986）是最基本的形式化规约方法，为每个操作指定前置条件（调用者的义务）和后置条件（实现者的保证）。


Hoare 三元组 {P}S{Q}：如果在满足前置条件 P 的状态下执行语句 S，若 S 终止，则终止状态满足后置条件 Q。这是部分正确性——要保证总正确性（包括终止性），需要额外的终止证明。


interface ContractSpec<Input, Output> {
  precondition: (input: Input) => boolean;
  postcondition: (input: Input, output: Output) => boolean;
  invariant?: (state: unknown) => boolean;
}

const binarySearchSpec: ContractSpec<{ arr: number[]; target: number }, number> = {
  precondition: ({ arr }) => {
    for (let i = 0; i < arr.length - 1; i++) {
      if (arr[i] > arr[i + 1]) return false;
    }
    return true;
  },
  postcondition: ({ arr, target }, result) => {
    if (result === -1) {
      return arr.every((x) => x !== target);
    }
    return arr[result] === target;
  },
};

function verifyContract<I, O>(
  spec: ContractSpec<I, O>,
  implementation: (input: I) => O,
  testInputs: I[],
): { passed: number; failed: number; violations: string[] } {
  const violations: string[] = [];
  let passed = 0;
  let failed = 0;

  for (const input of testInputs) {
    if (!spec.precondition(input)) continue;
    const output = implementation(input);
    if (spec.postcondition(input, output)) {
      passed++;
    } else {
      failed++;
      violations.push(`Postcondition violation: input=${JSON.stringify(input)}`);
    }
  }

  return { passed, failed, violations };
}
循环不变式是 Hoare 逻辑中证明循环正确性的核心概念。不变式 I 必须满足三个条件：循环开始前 I 成立（初始化），每次迭代保持 I（保持），循环结束后 I ∧ ¬B 蕴含后置条件（终止，B 是循环条件）。


框架问题（Frame Problem）：后置条件只描述"什么变了"，但"什么没变"也需要规约。现代规约语言通过 modifies 子句或分离逻辑的框架规则解决这个问题。

时序逻辑规约
时序逻辑（Temporal Logic）扩展了经典逻辑，引入时间算子来描述系统随时间演化的行为。它是反应式系统（Reactive Systems）规约的标准语言。


**线性时序逻辑 LTL（Linear Temporal Logic）**在线性时间路径上推理：


    

  • □φ（Always/Globally）：φ 在当前和所有未来时刻都成立
    • 

  • ◇φ（Eventually）：φ 在当前或某个未来时刻成立
    • 

  • ○φ（Next）：φ 在下一时刻成立
    • 

  • φ U ψ（Until）：φ 持续成立直到 ψ 成立
    • 



**计算树逻辑 CTL（Computation Tree Logic）**在分支时间树上推理，量化路径：


    

  • A□φ：在所有路径上 φ 总成立（对所有运行都安全）
    • 

  • E◇φ：存在某条路径使 φ 最终成立（可达性）
    • 

  • A(φ U ψ)：在所有路径上 φ 持续到 ψ
    •

type LTLFormula =
  | { kind: 'prop'; name: string }
  | { kind: 'not'; sub: LTLFormula }
  | { kind: 'and'; left: LTLFormula; right: LTLFormula }
  | { kind: 'or'; left: LTLFormula; right: LTLFormula }
  | { kind: 'implies'; left: LTLFormula; right: LTLFormula }
  | { kind: 'next'; sub: LTLFormula }
  | { kind: 'always'; sub: LTLFormula }
  | { kind: 'eventually'; sub: LTLFormula }
  | { kind: 'until'; left: LTLFormula; right: LTLFormula };

function always(phi: LTLFormula): LTLFormula {
  return { kind: 'always', sub: phi };
}

function eventually(phi: LTLFormula): LTLFormula {
  return { kind: 'eventually', sub: phi };
}

function responsiveness(trigger: string, response: string): LTLFormula {
  return always({
    kind: 'implies',
    left: { kind: 'prop', name: trigger },
    right: eventually({ kind: 'prop', name: response }),
  });
}

function mutualExclusion(cs1: string, cs2: string): LTLFormula {
  return always({
    kind: 'not',
    sub: {
      kind: 'and',
      left: { kind: 'prop', name: cs1 },
      right: { kind: 'prop', name: cs2 },
    },
  });
}
TLA+ 与工业级规约
TLA+（Temporal Logic of Actions，Lamport）是目前工业应用最广泛的形式化规约语言，被 Amazon、Microsoft 和 Intel 用于验证分布式系统和硬件设计。


TLA+ 的核心思想是将系统行为建模为状态序列（行为），用初始状态谓词和下一状态关系（动作）描述系统：


    

  • 初始谓词 Init：描述系统的合法初始状态
    • 

  • 下一状态关系 Next：描述系统一步转移的所有可能方式
    • 

  • 规约 Spec = Init ∧ □[Next]_vars：系统从 Init 出发，每一步要么执行 Next 要么保持不变
    • 



不变式检查：验证 Spec → □Inv（在所有可达状态中 Inv 成立）。TLC 模型检测器通过穷举状态空间验证有限实例。


Amazon 的实践经验表明：TLA+ 帮助发现了 DynamoDB、S3 和 EBS 中多个微妙的分布式协议缺陷，这些缺陷通过传统测试极难发现。投资回报率极高——几周的建模工作避免了可能导致数据丢失的生产事故。

代数规约与抽象数据类型
代数规约（Algebraic Specification）用等式和条件等式描述抽象数据类型（ADT）的行为，不关注实现细节，只规定操作之间的关系。


代数规约的核心思想：通过初始语义或终态语义给出 ADT 的精确含义。初始语义中，两个表达式相等当且仅当它们可以从公理推导出等式；终态语义中，两个表达式相等当且仅当在所有模型中它们的解释相同。


等式推理在编译器优化中有直接应用——代数恒等式（如 x + 0 = x）是编译器常量折叠和强度削减的理论基础。Haskell 的类型类（Functor、Monad 等）的法则本质上就是代数规约。


interface AlgebraicSpec {
  sorts: string[];
  operations: Map<string, { params: string[]; result: string }>;
  axioms: Array<{ left: string; right: string; condition?: string }>;
}

const stackSpec: AlgebraicSpec = {
  sorts: ['Stack', 'Element', 'Boolean'],
  operations: new Map([
    ['empty', { params: [], result: 'Stack' }],
    ['push', { params: ['Stack', 'Element'], result: 'Stack' }],
    ['pop', { params: ['Stack'], result: 'Stack' }],
    ['top', { params: ['Stack'], result: 'Element' }],
    ['isEmpty', { params: ['Stack'], result: 'Boolean' }],
  ]),
  axioms: [
    { left: 'pop(push(s, e))', right: 's' },
    { left: 'top(push(s, e))', right: 'e' },
    { left: 'isEmpty(empty())', right: 'true' },
    { left: 'isEmpty(push(s, e))', right: 'false' },
  ],
};

小结
    

  • 形式化规约用数学精确的语言描述系统行为，是连接逻辑学与软件工程的桥梁
    • 

  • Hoare 逻辑的前后条件和循环不变式是最基本的规约方法，广泛用于程序正确性推理
    • 

  • 时序逻辑（LTL、CTL）扩展经典逻辑以描述时间行为，是反应式系统规约的标准语言
    • 

  • TLA+ 在 Amazon 等企业的工业实践中证明了形式化方法的实用价值
    • 

  • 代数规约通过等式公理描述抽象数据类型，其思想贯穿编译器优化和函数式编程
    •
