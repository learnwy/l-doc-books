模型检测

核心概念

模型检测（Model Checking）是一种自动化的形式验证技术，它通过穷举搜索系统的所有可能状态来验证系统是否满足给定的逻辑规约。与定理证明需要人工指导不同，模型检测是全自动的——给定系统模型 M 和时序逻辑公式 φ，模型检测器自动判断 M ⊨ φ 是否成立，若不成立则生成违反性质的反例路径。

模型检测由 Clarke、Emerson 和 Sifakis 于 1980 年代独立提出（2007 年图灵奖），已成为硬件验证的工业标准和软件验证的重要工具。Intel 的所有处理器设计都经过模型检测验证，航空电子和铁路信号系统的安全认证（如 DO-178C、EN 50128）也要求形式验证。

显式状态模型检测
显式状态模型检测是最直观的方法：将系统建模为有限状态转移系统（Kripke 结构），通过图遍历算法检查时序性质。


Kripke 结构 M = (S, S₀, R, L)：S 是有限状态集，S₀ ⊆ S 是初始状态集，R ⊆ S × S 是转移关系，L: S → 2^AP 是标记函数（将每个状态映射到其满足的原子命题集合）。


CTL 模型检测算法（Clarke-Emerson）：对 CTL 公式从子公式到顶层递归计算满足每个子公式的状态集合 Sat(φ)。


type State = string;
type AtomicProp = string;

interface KripkeStructure {
  states: Set<State>;
  initial: Set<State>;
  transitions: Map<State, Set<State>>;
  labeling: Map<State, Set<AtomicProp>>;
}

type CTLFormula =
  | { kind: 'atom'; name: string }
  | { kind: 'not'; sub: CTLFormula }
  | { kind: 'and'; left: CTLFormula; right: CTLFormula }
  | { kind: 'or'; left: CTLFormula; right: CTLFormula }
  | { kind: 'EX'; sub: CTLFormula }
  | { kind: 'AX'; sub: CTLFormula }
  | { kind: 'EF'; sub: CTLFormula }
  | { kind: 'AF'; sub: CTLFormula }
  | { kind: 'EG'; sub: CTLFormula }
  | { kind: 'AG'; sub: CTLFormula }
  | { kind: 'EU'; left: CTLFormula; right: CTLFormula }
  | { kind: 'AU'; left: CTLFormula; right: CTLFormula };

function checkCTL(model: KripkeStructure, formula: CTLFormula): Set<State> {
  switch (formula.kind) {
    case 'atom':
      return new Set([...model.states].filter((s) => model.labeling.get(s)?.has(formula.name)));
    case 'not': {
      const sub = checkCTL(model, formula.sub);
      return new Set([...model.states].filter((s) => !sub.has(s)));
    }
    case 'and': {
      const left = checkCTL(model, formula.left);
      const right = checkCTL(model, formula.right);
      return new Set([...left].filter((s) => right.has(s)));
    }
    case 'or': {
      const left = checkCTL(model, formula.left);
      const right = checkCTL(model, formula.right);
      return new Set([...left, ...right]);
    }
    case 'EX':
      return checkEX(model, checkCTL(model, formula.sub));
    case 'EF':
      return checkEF(model, checkCTL(model, formula.sub));
    case 'EG':
      return checkEG(model, checkCTL(model, formula.sub));
    case 'EU':
      return checkEU(model, checkCTL(model, formula.left), checkCTL(model, formula.right));
    case 'AX': {
      const notSub = new Set([...model.states].filter((s) => !checkCTL(model, formula.sub).has(s)));
      const exNot = checkEX(model, notSub);
      return new Set([...model.states].filter((s) => !exNot.has(s)));
    }
    case 'AF':
      return checkAF(model, checkCTL(model, formula.sub));
    case 'AG': {
      const notSub = new Set([...model.states].filter((s) => !checkCTL(model, formula.sub).has(s)));
      const efNot = checkEF(model, notSub);
      return new Set([...model.states].filter((s) => !efNot.has(s)));
    }
    case 'AU':
      return checkAU(model, checkCTL(model, formula.left), checkCTL(model, formula.right));
  }
}

function checkEX(model: KripkeStructure, targetStates: Set<State>): Set<State> {
  return new Set(
    [...model.states].filter((s) => {
      const succs = model.transitions.get(s);
      return succs && [...succs].some((t) => targetStates.has(t));
    }),
  );
}

function checkEF(model: KripkeStructure, targetStates: Set<State>): Set<State> {
  const result = new Set(targetStates);
  const queue = [...targetStates];
  while (queue.length > 0) {
    const current = queue.shift()!;
    for (const [s, succs] of model.transitions) {
      if (!result.has(s) && succs.has(current)) {
        result.add(s);
        queue.push(s);
      }
    }
  }
  return result;
}

function checkEG(model: KripkeStructure, targetStates: Set<State>): Set<State> {
  let result = new Set(targetStates);
  let changed = true;
  while (changed) {
    changed = false;
    const next = new Set(
      [...result].filter((s) => {
        const succs = model.transitions.get(s);
        return succs && [...succs].some((t) => result.has(t));
      }),
    );
    if (next.size < result.size) {
      changed = true;
      result = next;
    }
  }
  return result;
}

function checkEU(model: KripkeStructure, phiStates: Set<State>, psiStates: Set<State>): Set<State> {
  const result = new Set(psiStates);
  const queue = [...psiStates];
  while (queue.length > 0) {
    const current = queue.shift()!;
    for (const [s, succs] of model.transitions) {
      if (!result.has(s) && phiStates.has(s) && succs.has(current)) {
        result.add(s);
        queue.push(s);
      }
    }
  }
  return result;
}

function checkAF(model: KripkeStructure, targetStates: Set<State>): Set<State> {
  const notTarget = new Set([...model.states].filter((s) => !targetStates.has(s)));
  const egNot = checkEG(model, notTarget);
  return new Set([...model.states].filter((s) => !egNot.has(s)));
}

function checkAU(model: KripkeStructure, phiStates: Set<State>, psiStates: Set<State>): Set<State> {
  const notPsi = new Set([...model.states].filter((s) => !psiStates.has(s)));
  const notPhi = new Set([...model.states].filter((s) => !phiStates.has(s)));
  const notPhiOrPsi = new Set([...notPhi].filter((s) => notPsi.has(s)));
  const egNotPsi = checkEG(model, notPsi);
  const euNotPsiNotPhiPsi = checkEU(model, notPsi, notPhiOrPsi);
  const bad = new Set([...egNotPsi, ...euNotPsiNotPhiPsi]);
  return new Set([...model.states].filter((s) => !bad.has(s)));
}
CTL 模型检测的时间复杂度为 O(|φ| · (|S| + |R|))——与公式大小和状态空间线性。这使得它对有限状态系统极为高效。


符号化模型检测与 BDD
状态爆炸问题是显式状态模型检测的根本挑战：n 个布尔变量的系统有 2ⁿ 个状态。符号化模型检测（Symbolic Model Checking，McMillan，1993）用 BDD（有序二叉决策图）紧凑表示状态集合和转移关系。


BDD 的核心思想：布尔函数 f(x₁,...,xₙ) 用有向无环图表示，共享子树并省略冗余节点。一个 BDD 可以指数级地压缩状态集合——在许多实际系统中，10²⁰ 量级的状态集合只需几百个 BDD 节点。


符号化 CTL 模型检测：将状态集合表示为 BDD，转移关系表示为布尔函数。Sat(EX φ) = ∃x'. R(x, x') ∧ Sat(φ)(x')——一次 BDD 存在量化操作处理所有状态，而非逐个检查。


符号化模型检测的突破性贡献在于将硬件验证从玩具级别推向工业级别。IBM、Intel、Cadence 等公司的 EDA 工具链广泛集成了 BDD 基础的模型检测技术。


有界模型检测与 CEGAR
有界模型检测（Bounded Model Checking，BMC）（Biere et al., 1999）将模型检测问题编码为 SAT 问题：系统是否在 k 步之内违反性质？


BMC 将 k 步转移展开为命题公式：Init(s₀) ∧ T(s₀,s₁) ∧ T(s₁,s₂) ∧ ... ∧ T(sₖ₋₁,sₖ) ∧ ¬P(sₖ)。如果可满足，找到了 k 步反例；不可满足则增加 k。


BMC 的优势在于利用了现代 SAT 求解器的强大能力——CDCL 技术使得百万变量级的公式可以高效求解。在深度反例的查找上，BMC 通常比 BDD 方法更有效。


**CEGAR（Counterexample-Guided Abstraction Refinement）**是处理无限状态系统的关键技术：


    

  1. 抽象：构造系统的过近似抽象 M^α
    2. 

  2. 模型检测：在 M^α 上验证性质
    3. 

  3. 反例分析：如果发现违反，检查反例在原系统中是否真实
    4. 

  4. 精化：如果反例是虚假的（spurious），精化抽象消除该虚假反例
    5. 

  5. 重复直到找到真实反例或验证通过
    6.

IC3/PDR（Property Directed Reachability）（Bradley, 2011）是近年来最成功的模型检测算法创新。它不需要预设边界 k，而是增量式地构造不变式的过近似序列，直到找到足够强的归纳不变式或反例。


软件模型检测
软件模型检测将模型检测技术应用于程序源码，面临的核心挑战是：程序状态空间通常是无限的（无限递归、无界数据结构）。


CBMC（C Bounded Model Checker）：将 C 程序展开为 SAT 公式，验证断言、数组越界、空指针解引用等性质。循环展开有界次数，函数调用内联。


SPIN：使用 Promela 建模语言描述并发系统，通过偏序归约和位状态哈希处理状态爆炸，验证 LTL 性质。在通信协议验证（如 TCP/IP 实现）中有广泛应用。


Java PathFinder（JPF）：NASA 开发的 Java 程序模型检测器，直接执行 Java 字节码并系统化探索所有线程调度。发现了多个 NASA 任务软件中的并发缺陷。

小结
    

  • 模型检测是全自动的形式验证技术，通过穷举状态空间检查时序逻辑性质，违反时生成反例路径
    • 

  • CTL 模型检测算法通过不动点计算在线性时间内完成，对有限状态系统极为高效
    • 

  • 符号化模型检测用 BDD 紧凑表示状态集合，将验证能力从 10⁸ 提升到 10²⁰ 量级
    • 

  • 有界模型检测将验证问题编码为 SAT，利用现代求解器的强大能力处理深度反例
    • 

  • CEGAR 和 IC3/PDR 是处理无限状态系统的核心技术，推动了软件模型检测的实用化
    •
