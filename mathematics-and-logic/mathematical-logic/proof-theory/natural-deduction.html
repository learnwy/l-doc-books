自然演绎

核心概念

自然演绎（Natural Deduction）是 Gerhard Gentzen 于 1934 年创立的形式证明系统，其设计目标是让形式证明尽可能接近数学家的实际推理方式。与希尔伯特公理系统依赖大量公理不同，自然演绎没有公理，完全依靠推理规则——每个逻辑联结词配备一对引入规则和消去规则，形成了优雅的对称结构。

自然演绎的深远意义远超证明论本身。通过 Curry-Howard 同构，自然演绎的证明直接对应函数式程序，推理规则对应程序构造，证明化简对应程序执行。这一发现将逻辑学与计算机科学深度联结，是类型论、函数式编程和证明助手（Coq、Agda、Lean）的理论基石。

推理规则的完整体系
自然演绎的推理规则为每个逻辑联结词提供引入（I）和消去（E）两个方向，形成了哲学上的"意义理论"——联结词的意义完全由其引入和消去规则决定。


蕴含（→）规则：


→ 引入是最核心的规则：假设 φ 成立，在此假设下推导出 ψ，然后释放假设得到 φ → ψ。这对应于函数定义——给定类型为 φ 的参数，构造类型为 ψ 的返回值。


→ 消去就是 Modus Ponens：从 φ 和 φ → ψ 得到 ψ。这对应于函数应用。


合取（∧）规则：


∧ 引入：从 φ 和 ψ 构造 φ ∧ ψ。对应于构造有序对 (a, b)。


∧ 消去：从 φ ∧ ψ 提取 φ（左投影）或 ψ（右投影）。对应于 fst 和 snd 操作。


析取（∨）规则：


∨ 引入：从 φ 得到 φ ∨ ψ（左注入），或从 ψ 得到 φ ∨ ψ（右注入）。对应于 Either 类型的 Left 和 Right 构造。


∨ 消去（分情况讨论）：已知 φ ∨ ψ，在假设 φ 下推导出 χ，在假设 ψ 下也推导出 χ，则得到 χ。对应于模式匹配。


否定（¬）和矛盾（⊥）规则：


¬ 引入：假设 φ，推出矛盾 ⊥，则得 ¬φ。⊥ 消去（爆炸律）：从 ⊥ 得到任意 ψ。


量词规则：


∀ 引入：对任意 a 证明 φ(a)（a 不在活跃假设中），得 ∀xφ(x)。对应于多态函数。


∀ 消去：从 ∀xφ(x) 得 φ(t)。对应于类型实例化。


∃ 引入：从 φ(t) 得 ∃xφ(x)。对应于存在类型的打包。


∃ 消去：已知 ∃xφ(x)，假设 φ(a) 推导出 ψ（a 不在 ψ 和其他假设中），得 ψ。对应于存在类型的解包。


type ProofTerm =
  | { kind: 'var'; name: string }
  | { kind: 'lambda'; param: string; paramType: string; body: ProofTerm }
  | { kind: 'app'; func: ProofTerm; arg: ProofTerm }
  | { kind: 'pair'; left: ProofTerm; right: ProofTerm }
  | { kind: 'fst'; pair: ProofTerm }
  | { kind: 'snd'; pair: ProofTerm }
  | { kind: 'inl'; value: ProofTerm; rightType: string }
  | { kind: 'inr'; value: ProofTerm; leftType: string }
  | { kind: 'match'; scrutinee: ProofTerm; leftCase: ProofTerm; rightCase: ProofTerm }
  | { kind: 'absurd'; proof: ProofTerm; targetType: string };

function typeCheck(term: ProofTerm, ctx: Map<string, string>): string {
  switch (term.kind) {
    case 'var': {
      const t = ctx.get(term.name);
      if (!t) throw new Error(`Unbound variable: ${term.name}`);
      return t;
    }
    case 'lambda': {
      const newCtx = new Map(ctx);
      newCtx.set(term.param, term.paramType);
      const bodyType = typeCheck(term.body, newCtx);
      return `(${term.paramType} → ${bodyType})`;
    }
    case 'app': {
      const funcType = typeCheck(term.func, ctx);
      const argType = typeCheck(term.arg, ctx);
      const match = funcType.match(/^\((.+) → (.+)\)$/);
      if (!match || match[1] !== argType) throw new Error('Type mismatch');
      return match[2];
    }
    case 'pair': {
      const l = typeCheck(term.left, ctx);
      const r = typeCheck(term.right, ctx);
      return `(${l} ∧ ${r})`;
    }
    case 'fst': {
      const pairType = typeCheck(term.pair, ctx);
      const match = pairType.match(/^\((.+) ∧ (.+)\)$/);
      if (!match) throw new Error('Not a pair type');
      return match[1];
    }
    case 'snd': {
      const pairType = typeCheck(term.pair, ctx);
      const match = pairType.match(/^\((.+) ∧ (.+)\)$/);
      if (!match) throw new Error('Not a pair type');
      return match[2];
    }
    default:
      throw new Error(`Unhandled term kind`);
  }
}
Curry-Howard 同构
Curry-Howard 同构（也称命题即类型、证明即程序）是 20 世纪逻辑学与计算机科学最深刻的发现之一。它揭示了自然演绎证明与 λ 演算程序之间的精确对应。

Curry-Howard 同构的一个关键推论是：逻辑联结词对应程序构造器。例如，排中律 φ ∨ ¬φ 在构造性逻辑中不可证——这对应于不存在通用的"类型判定器"。经典逻辑的排中律对应于 call/cc（continuation 的捕获），Peirce 定律 ((φ → ψ) → φ) → φ 对应于 Scheme 中的 call-with-current-continuation。


这一对应在现代证明助手中得到了充分应用。在 Coq 中，证明一个定理等于编写一个通过类型检查的程序。Agda 和 Lean 直接在类型系统中编码数学定理，程序提取（extraction）可以从证明中自动生成可执行代码。


证明规范化与切消除
自然演绎中的证明可能包含"绕路"——先用引入规则构造再立刻用消去规则分解。证明规范化（normalization）消除这些冗余，得到最简形式的证明。


β 归约（引入-消去对消除）：


→ β 归约：先构造 φ → ψ 的证明（→I），然后立刻应用到 φ 的证明上（→E），可以直接将 φ 的证明代入。这精确对应 λ 演算的 β 归约 (λx.M)N →β M[x:=N]。


∧ β 归约：先构造 φ ∧ ψ 的证明（∧I），然后立刻投影（∧E），可以直接取出对应分量。对应 fst(a,b) →β a。


强规范化定理：简单类型 λ 演算（对应命题逻辑的自然演绎）的所有归约序列都终止。这意味着证明化简总是结束，不会陷入无限循环。对于更强的系统（System F，依赖类型），强规范化需要更精细的证明（如 Girard 的候选可约性方法）。


子公式性质：规范化证明中出现的所有公式要么是前提的子公式，要么是结论的子公式。这个性质极为重要——它意味着证明搜索的空间是有界的，不会引入任意复杂的中间公式。

自然演绎的变体与扩展
自然演绎有多种表现形式和扩展，适应不同的理论和实践需求。


Fitch 风格：证明写成缩进的线性序列，假设用竖线标记作用域。最适合教学和手工证明，易于检查假设的作用范围。


树状风格（Gentzen 原版）：证明是自底向上生长的树，叶子是假设，根是结论。最清晰地展示证明的逻辑结构。


项标注风格（Curry-Howard）：每个推导步骤标注对应的 λ 项，证明树变成类型推导。最适合编程语言理论和证明助手。


经典自然演绎 vs 直觉主义自然演绎：经典自然演绎额外包含双重否定消去规则（¬¬φ → φ）或排中律（φ ∨ ¬φ）。直觉主义自然演绎拒绝这些规则，对应于纯构造性证明。Griffin（1990）发现经典逻辑的排中律对应于 call/cc 操作，建立了经典逻辑与控制操作的 Curry-Howard 对应。


模态自然演绎：为模态逻辑（□、◇）添加引入消去规则。□φ 的引入要求在"空上下文"中证明 φ（只依赖必然真的假设），对应于阶段化计算（staged computation）。


线性自然演绎：线性逻辑的自然演绎版本，假设恰好使用一次。对应于资源管理——Rust 的所有权系统与线性逻辑有深层联系。

小结
    

  • 自然演绎通过引入/消去规则对模拟人类推理，无需公理，是最直观的形式证明系统
    • 

  • Curry-Howard 同构将自然演绎证明与 λ 演算程序精确对应，是类型论和函数式编程的理论基石
    • 

  • 证明规范化消除推理冗余，对应于程序优化；强规范化保证化简总终止
    • 

  • 子公式性质限制了证明中出现的公式复杂度，为证明搜索提供了有界空间
    • 

  • 经典、直觉主义、线性、模态等变体适应不同的逻辑体系和计算模型
