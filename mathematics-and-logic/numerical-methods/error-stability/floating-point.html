浮点数表示与运算

核心概念

浮点数是计算机表示实数的基本方式，其本质是用有限的二进制位来近似无限精度的数值。理解浮点数的表示方式和运算规则，是掌握数值计算的第一步。

浮点数由符号位、指数和尾数三部分构成，遵循科学计数法的二进制形式：(−1)s×M×2E(-1)^s \times M \times 2^E(−1)s×M×2E，其中 sss 是符号位，MMM 是尾数（有效数字），EEE 是指数。这种表示方式在提供巨大数值范围的同时，也引入了不可避免的表示误差。

IEEE 754 标准
IEEE 754 是当前几乎所有计算机硬件遵循的浮点数标准，它统一规定了浮点数的编码格式、舍入规则和特殊值处理。


在 IEEE 754 中，尾数采用隐含前导 1 的规格化形式，即实际尾数为 1.f1.f1.f，其中 fff 是存储的小数部分。这种设计额外获得了一位有效精度。指数采用偏移编码（biased exponent），单精度的偏移量为 127，双精度为 1023。

非规格化数（denormalized/subnormal）是 IEEE 754 的精妙设计。当数值接近零时，规格化表示无法覆盖到零之间的间隙，非规格化数通过去掉隐含前导 1，使浮点数系统在零附近实现渐进下溢（gradual underflow），避免了突然下溢到零。


import struct

def float_to_bits(f):
    packed = struct.pack('>f', f)
    bits = ''.join(f'{b:08b}' for b in packed)
    return f"{bits[0]} | {bits[1:9]} | {bits[9:]}"

print(float_to_bits(1.0))
print(float_to_bits(-0.125))
print(float_to_bits(float('inf')))
print(float_to_bits(float('nan')))
机器精度与舍入误差
机器精度（machine epsilon, εmach\varepsilon_{\text{mach}}εmach​）是浮点数系统最核心的参数，定义为满足 fl(1+ε)>1\text{fl}(1 + \varepsilon) > 1fl(1+ε)>1 的最小正浮点数 ε\varepsilonε。对于双精度，εmach≈2.22×10−16\varepsilon_{\text{mach}} \approx 2.22 \times 10^{-16}εmach​≈2.22×10−16。


机器精度的本质含义是：任何实数 xxx 在浮点表示后的相对误差不超过 εmach/2\varepsilon_{\text{mach}} / 2εmach​/2：


∣fl(x)−x∣/∣x∣≤εmach/2|\text{fl}(x) - x| / |x| \leq \varepsilon_{\text{mach}} / 2∣fl(x)−x∣/∣x∣≤εmach​/2

浮点运算陷阱
浮点运算中存在许多违反直觉的行为，这些行为源于有限精度表示的根本限制。


最经典的问题是结合律失效：浮点加法不满足结合律 (a+b)+c≠a+(b+c)(a + b) + c \neq a + (b + c)(a+b)+c=a+(b+c)。当参与运算的数值量级差异巨大时，小数可能被"吞噬"，这种现象称为灾难性抵消（catastrophic cancellation）。


a = 1e16
b = 1.0
c = -1e16

print(f"(a + b) + c = {(a + b) + c}")
print(f"a + (b + c) = {a + (b + c)}")

x = 1e-15
y = (1 + x) - 1
print(f"预期: {x}, 实际: {y}, 相对误差: {abs(y - x) / x:.2%}")
另一个常见陷阱是等值比较。由于舍入误差的累积，直接用 == 比较两个浮点数几乎总是错误的做法：


print(f"0.1 + 0.2 == 0.3: {0.1 + 0.2 == 0.3}")
print(f"0.1 + 0.2 = {0.1 + 0.2:.20f}")
print(f"0.3       = {0.3:.20f}")

def float_eq(a, b, rtol=1e-9, atol=1e-12):
    return abs(a - b) <= max(rtol * max(abs(a), abs(b)), atol)

print(f"float_eq(0.1 + 0.2, 0.3): {float_eq(0.1 + 0.2, 0.3)}")
Kahan 求和算法
针对浮点加法中大数吞小数的问题，Kahan 求和算法（补偿求和）是一种优雅的解决方案。它通过维护一个补偿变量来追踪被舍入丢弃的低位部分，将 nnn 个数求和的误差从 O(nε)O(n \varepsilon)O(nε) 降低到 O(ε)O(\varepsilon)O(ε)。


算法的核心思想是：每次加法后，计算被丢弃的误差补偿量，并在下次加法中补回。


def naive_sum(arr):
    s = 0.0
    for x in arr:
        s += x
    return s

def kahan_sum(arr):
    s = 0.0
    c = 0.0
    for x in arr:
        y = x - c
        t = s + y
        c = (t - s) - y
        s = t
    return s

data = [1.0] * 10_000_000 + [1e-8] * 10_000_000
print(f"朴素求和: {naive_sum(data):.15f}")
print(f"Kahan 求和: {kahan_sum(data):.15f}")
print(f"NumPy 求和: {sum(data):.15f}")
Kahan 求和的工作原理可以通过误差追踪来理解：变量 c 累积了每步运算中被舍入丢弃的部分，y = x - c 在下一步将这个误差补偿回来。整个过程只需要一个额外的浮点变量，时间复杂度与朴素求和相同。

小结
    

  • 浮点数由符号位、指数和尾数三部分组成，IEEE 754 标准统一了编码格式和运算规则
    • 

  • 机器精度 εmach\varepsilon_{\text{mach}}εmach​ 是浮点系统的核心参数，决定了单次运算的最大相对误差
    • 

  • 浮点运算不满足结合律，大数吞小数和灾难性抵消是最常见的精度陷阱
    • 

  • Kahan 求和通过误差补偿将累加误差从 O(nε)O(n\varepsilon)O(nε) 降至 O(ε)O(\varepsilon)O(ε)
    • 

  • 浮点数比较应使用相对容差和绝对容差的组合策略，避免直接等值比较
    • 

  • 理解浮点数的局限性是编写可靠数值程序的基础
