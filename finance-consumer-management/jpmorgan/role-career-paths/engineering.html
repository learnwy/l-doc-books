科技工程师成长路线：四大方向逐级晋升详解

摩根大通科技团队全景

摩根大通拥有全球金融行业最大的科技团队之一——超过 57,000 名技术员工，分布在纽约、伦敦、新加坡、班加罗尔、格拉斯哥、华沙等全球技术中心。2025 年全年技术投入达 180 亿美元（2026 年计划增至 198 亿美元），其中约一半用于战略性技术投资（而非仅仅维护现有系统）。

这个规模意味着：摩根大通不仅是一家银行，更是全球最大的科技雇主之一——其技术团队规模超过许多知名科技公司。

IC vs 管理路径的分叉决策
在 Associate 到 VP 的过渡期，工程师面临职业生涯中最关键的分叉决策：继续走 IC（Individual Contributor）路径，还是转向管理路径。


IC 路径的优势：


    

  • 保持技术深度，持续做技术决策
    • 

  • 不需要处理人事管理的复杂性
    • 

  • 在 AI/ML 等前沿领域，顶级 IC 的影响力可能超过管理者
    • 



管理路径的优势：


    

  • 更广的影响范围（通过团队放大个人影响力）
    • 

  • 更高的组织可见度
    • 

  • 在晋升到 ED/MD 时，管理路径通常有更多的位置
    •

方向一：Core Banking Tech（核心银行技术）
业务背景
Core Banking Tech 支撑着摩根大通最核心的银行业务——包括全球最大的 USD 支付处理系统（日交易量超过 10 万亿美元）、Chase Mobile App（美国最大的移动银行应用，月活用户超过 6,000 万）和 Treasury Services（全球企业现金管理）。


逐级晋升详解
Analyst（Software Engineer I-II）：0-3 年


    

  • 技术要求：Java 或 Python 熟练，理解数据库（Oracle/PostgreSQL）和消息队列（Kafka）
    • 

  • 日常工作：参与支付系统的微服务开发、编写单元测试、修复生产环境 bug、参与 code review
    • 

  • 成长目标：从"被指导写代码"到"能独立完成一个完整的 user story"
    • 

  • 晋升要做的 3 件事：
      

    1. 主导至少一个中等规模的技术任务（如一个新 API 的完整开发）
      2. 

    2. 建立对本团队代码库的深度理解
      3. 

    3. 开始参与 on-call 轮值，理解生产环境运维
      4. 

    

    • 



Associate（Senior Software Engineer）：3-5 年


    

  • 技术要求：能设计中等复杂度的系统、理解分布式系统基础、掌握性能优化技能
    • 

  • 日常工作：负责一个子系统的技术设计和实现、指导 Analyst、参与架构讨论
    • 

  • 成长目标：从"完成任务"到"定义任务"
    • 

  • 晋升要做的 3 件事：
      

    1. 独立设计并交付至少一个跨团队的技术方案
      2. 

    2. 成为本团队在某个技术领域的 go-to person
      3. 

    3. 在技术评审会议中展现系统性思维
      4. 

    

    • 



VP（Lead Engineer / Engineering Manager）：5-8 年


    

  • 技术要求（IC）：深度的架构设计能力、对整个支付系统链路的全面理解
    • 

  • 管理要求（Manager）：团队管理（6-15 人）、绩效评估、招聘面试
    • 

  • 日常工作：定义技术路线图、参与跨团队架构评审、与产品团队协作确定优先级
    • 

  • 晋升要做的 3 件事：
      

    1. 主导一个重大技术迁移或平台升级项目
      2. 

    2. 建立跨部门的技术影响力
      3. 

    3. 培养出至少一名能独当一面的 Associate
      4. 

    

    • 



ED（Principal / Sr. Engineering Manager）：8-12 年


    

  • 核心职责：定义整个领域的技术战略、管理多个团队或一个大型技术平台
    • 

  • 关键差异化：从"做好自己领域的事"到"影响相邻领域的决策"
    • 

  • 晋升关键：需要在公司层面的技术委员会或架构评审中有持续的贡献
    • 



MD（Fellow / Tech Director）：12+ 年


    

  • 核心职责：定义全公司级别的技术方向、代表公司在外部技术社区的声誉
    • 

  • 稀缺性：全 Core Banking 方向的 MD 级别技术领导可能只有个位数
    • 

  • 影响范围：直接影响公司数十亿美元的技术投资决策
    •

方向二：Capital Markets Tech（资本市场技术）
业务背景
Capital Markets Tech 支撑着摩根大通的交易和做市业务——这是公司最赚钱的业务之一（2025 年 Markets 收入超过 320 亿美元）。核心挑战是低延迟和高可靠性：一个毫秒级的延迟可能意味着数百万美元的差异。

逐级成长要点
Analyst → Associate：从掌握 C++ 和 Python 到能独立开发交易系统组件。需要学习金融市场微观结构——理解订单簿、做市逻辑和风险计算。


Associate → VP：从组件开发到系统架构。能设计一个完整的电子交易系统或风险计算引擎。开始与 quant（量化分析师）和交易员直接协作。


VP → ED：从系统架构到技术战略。需要理解业务 P&L，能够用技术语言和业务语言分别与工程师和交易桌沟通。这个阶段的关键差异化是业务理解深度。


ED → MD：从技术战略到业务领导。在这个级别，你不仅需要解决技术问题，还需要参与业务决策——例如是否进入新的交易品类、是否投资新的交易基础设施。

方向三：AI/ML Platform（人工智能平台）
业务背景
AI/ML Platform 是摩根大通增长最快的技术方向。截至 2025 年底，超过 25 万名员工使用 LLM Suite（公司自研的大语言模型平台），超过 450 个 AI 用例在生产环境运行，目标 2026 年扩展至 1,000 个。AI 每年为公司节省约 20 亿美元，同时创造了显著的收入增长。


三个子方向
LLM/GenAI Engineering：构建和维护 LLM Suite 平台。技术栈包括 OpenAI 和 Anthropic 的 API 集成、RAG（检索增强生成）架构、prompt engineering 工程化。这是当前最热门的子方向。


ML Ops / Model Platform：构建模型训练、部署、监控的全生命周期平台。技术栈包括 MLflow、Kubernetes、特征工程平台。关注模型的合规性（可解释性、公平性、隐私保护）是银行业 ML Ops 的独特要求。


Applied AI：将 AI 技术应用于具体业务问题——欺诈检测（每年避免 15 亿美元损失）、合同智能分析（Contract Intelligence）、客户行为预测等。


逐级成长要点
Analyst（ML Engineer I-II）：


    

  • 技术要求：Python 熟练、PyTorch/TensorFlow 基础、理解经典 ML 算法
    • 

  • 日常工作：数据预处理、模型训练、性能调优、编写评估报告
    • 

  • 关键学习：金融领域的 AI 应用特殊性——数据不均衡、监管约束、可解释性要求
    • 



Associate（Senior ML Engineer）：


    

  • 技术要求：能独立设计 ML pipeline、深度理解至少一个专业领域（NLP/CV/推荐）
    • 

  • 日常工作：设计 ML 解决方案、与业务团队沟通需求、主导模型上线
    • 

  • 关键差异化：能将业务问题转化为 ML 问题——这需要金融业务理解力
    • 



VP（Lead ML Engineer / Applied AI Manager）：


    

  • 技术要求：前沿 ML 技术（LLM、Agentic AI、GNN）+ 大规模 ML 系统设计
    • 

  • 日常工作：定义 AI 产品路线图、管理多个 ML 项目、与高管汇报 AI ROI
    • 

  • 薪酬参考：Base 165,000−260,000+Bonus，总包165,000-260,000 + Bonus，总包165,000−260,000+Bonus，总包350,000-500,000
    • 



ED / MD：


    

  • 核心职责：定义全公司 AI 战略、管理大型 AI 团队（50-200 人）、代表公司参与行业 AI 讨论
    • 

  • 关键人物参考：Derek Waldron（Chief Analytics Officer）是 AI 方向的最高技术领导者
    •

方向四：Cloud Infrastructure（云基础设施）
业务背景
摩根大通的云战略是金融行业最激进的之一。公司同时使用 AWS、Azure 和自建私有云，正在将核心业务系统逐步迁移到云原生架构。Cloud Infrastructure 团队负责为全公司 30 万员工和数十万应用程序提供可靠、安全、合规的基础设施。

VP → ED：从架构师到战略家。定义云迁移路线图、管理大型迁移项目（如将核心银行系统从物理数据中心迁移到云端）。

工程师的 AI 技能建设路径
无论你在哪个技术方向，以下 AI 技能在摩根大通都越来越重要：


基础层（所有工程师）：


    

  • 能有效使用 LLM Suite 等 AI 助手
    • 

  • 理解 prompt engineering 基础
    • 

  • 知道 AI 的能力边界和风险
    • 



应用层（Associate+）：


    

  • 能将 AI 工具集成到自己的开发流程中
    • 

  • 理解 RAG、微调等 LLM 应用模式
    • 

  • 能评估 AI 工具的输出质量
    • 



专家层（VP+）：


    

  • 能设计 AI 驱动的技术解决方案
    • 

  • 理解 AI 模型的合规和伦理考量
    • 

  • 能推动团队的 AI 采纳和文化变革
    •

维度

适合来摩根大通的工程师画像：


    

  • 喜欢解决有真实业务影响的复杂技术问题
    • 

  • 能在有约束的环境中找到创新空间
    • 

  • 看重长期职业稳定性和全面的福利体系
    • 

  • 对金融行业有兴趣或好奇心
    • 

  • 愿意接受相对正式的工作文化
    • 



可能不适合的工程师画像：


    

  • 追求最前沿的开源技术实验自由
    • 

  • 对流程和审批容忍度极低
    • 

  • 偏好 100% 远程工作
    • 

  • 对金融业务完全没有兴趣
    •
