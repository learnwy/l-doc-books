多显示器与工作流编排

概述

多显示器环境为开发者提供了更大的视觉空间，但如果不加以规划，反而会导致窗口散乱、注意力分散。真正高效的多显示器工作流不是简单地"把窗口铺开"，而是将物理屏幕空间与心智模型对齐——让每个屏幕承载特定的职责角色，结合工作区预设和自动化规则，实现"切换任务时无需手动重排窗口"的无摩擦体验。

本文讨论多显示器的空间分配策略、基于任务场景的工作区预设、与 Focus Mode 的联动，以及如何将布局方案纳入 dotfiles 实现跨设备一致性。

Hammerspoon 工作区预设
-- ~/.hammerspoon/init.lua — 工作区预设

local hyper = {"ctrl", "alt", "cmd", "shift"}

-- 获取屏幕
local function getScreens()
    local screens = hs.screen.allScreens()
    return {
        main = screens[1],
        secondary = screens[2] or screens[1]
    }
end

-- 预设：编码模式
hs.hotkey.bind(hyper, "F1", function()
    local s = getScreens()
    local mainFrame = s.main:frame()
    local secFrame = s.secondary:frame()

    -- 主屏：终端左半 + 编辑器右半
    local ghostty = hs.application.find("Ghostty")
    if ghostty then
        local win = ghostty:mainWindow()
        if win then
            win:moveToScreen(s.main)
            win:setFrame({
                x = mainFrame.x,
                y = mainFrame.y,
                w = mainFrame.w * 0.4,
                h = mainFrame.h
            })
        end
    end

    local vscode = hs.application.find("Code")
    if vscode then
        local win = vscode:mainWindow()
        if win then
            win:moveToScreen(s.main)
            win:setFrame({
                x = mainFrame.x + mainFrame.w * 0.4,
                y = mainFrame.y,
                w = mainFrame.w * 0.6,
                h = mainFrame.h
            })
        end
    end

    -- 副屏：浏览器全屏
    local firefox = hs.application.find("Firefox")
    if firefox then
        local win = firefox:mainWindow()
        if win then
            win:moveToScreen(s.secondary)
            win:maximize()
        end
    end

    hs.notify.new({title="Workspace", informativeText="Coding mode activated"}):send()
end)

-- 预设：会议模式
hs.hotkey.bind(hyper, "F3", function()
    local s = getScreens()

    -- 主屏：视频会议最大化
    local zoom = hs.application.find("zoom.us") or hs.application.find("Feishu")
    if zoom then
        local win = zoom:mainWindow()
        if win then
            win:moveToScreen(s.main)
            win:maximize()
        end
    end

    -- 副屏：笔记
    local obsidian = hs.application.find("Obsidian")
    if obsidian then
        local win = obsidian:mainWindow()
        if win then
            win:moveToScreen(s.secondary)
            win:maximize()
        end
    end

    hs.notify.new({title="Workspace", informativeText="Meeting mode activated"}):send()
end)
Focus Mode 联动
macOS Focus Mode 可以根据场景自动切换通知过滤，与工作区预设联动效果更佳：


-- Hammerspoon: 切换预设时同步 Focus Mode
-- 注意：macOS Focus 需要通过 Shortcuts.app 来程序化切换

-- 方案：使用 shortcuts CLI
local function setFocusMode(mode)
    -- 需要先在 Shortcuts.app 中创建对应快捷指令
    hs.execute("shortcuts run 'Set Focus " .. mode .. "'", true)
end

hs.hotkey.bind(hyper, "F1", function()
    -- ... 布局代码 ...
    setFocusMode("Coding")  -- 静音非紧急通知
end)

hs.hotkey.bind(hyper, "F3", function()
    -- ... 布局代码 ...
    setFocusMode("Meeting")  -- 静音所有通知
end)

环境感知自动切换
-- 根据连接的显示器数量自动调整布局
local function handleScreenChange()
    local screenCount = #hs.screen.allScreens()

    if screenCount == 1 then
        -- 单屏模式：工作区策略
        hs.notify.new({title="Display", informativeText="Single display mode"}):send()
    elseif screenCount == 2 then
        -- 双屏模式：应用预设布局
        hs.notify.new({title="Display", informativeText="Dual display mode"}):send()
        -- 自动触发 Coding preset
    end
end

hs.screen.watcher.new(handleScreenChange):start()

总结
多显示器工作流的核心不是"更多像素"而是"更清晰的空间语义"。将每个屏幕（或工作区）赋予明确的职责角色，配合自动化的窗口规则和预设切换，可以实现"任务切换时环境自动跟随"的流畅体验。通过 Aerospace 的应用绑定规则和 Hammerspoon 的预设脚本，这套体系可以完全写入 dotfiles，在任何新设备上一键恢复。关键洞察是：与其让窗口布局依赖于你的手动操作记忆，不如让它成为可声明、可版本控制、可自动化的基础设施。
