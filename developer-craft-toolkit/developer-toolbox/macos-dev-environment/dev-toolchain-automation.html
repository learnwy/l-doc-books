开发工具链安装自动化

概述

macOS 开发环境不仅需要 Homebrew 管理的 CLI 工具和 GUI 应用，还需要一整套开发工具链：Xcode CLI Tools 提供编译器基础、各语言运行时需要版本管理、编辑器需要插件和 LSP 配置、容器运行时和数据库也是日常开发的刚需。将这些组件的安装和版本管理自动化，是从"每次换机折腾两天"到"一键完成"的关键跨越。

本文聚焦于如何用 mise（前身为 rtx）统一管理多语言运行时版本，以及如何将完整开发工具链的安装编排为可复现的自动化流程。

.mise.toml 配置
每个项目根目录放一个 .mise.toml，声明该项目需要的运行时版本：


# .mise.toml（项目级）
[tools]
node = "22"
python = "3.13"
go = "1.23"

[env]
NODE_ENV = "development"
全局配置放在 ~/.config/mise/config.toml：


# ~/.config/mise/config.toml（全局）
[tools]
node = "lts"
python = "latest"
go = "latest"
usage = "latest"

[settings]
experimental = true
实战指南
Xcode Command Line Tools
这是一切的基础——Homebrew、Git、编译器都依赖它：


# 安装（会弹出系统对话框）
xcode-select --install

# 验证
xcode-select -p
# 输出: /Library/Developer/CommandLineTools

# 检查版本
clang --version
git --version
make --version
如果之前安装过完整 Xcode 需要切换：


# 切换到独立的 CLI Tools（不需要完整 Xcode）
sudo xcode-select --switch /Library/Developer/CommandLineTools
mise 完整配置
# 安装 mise
brew install mise

# Shell 集成（~/.zshrc）
eval "$(mise activate zsh)"

# 或 Fish（~/.config/fish/config.fish）
mise activate fish | source

# 安装运行时
mise use --global node@lts       # 全局 Node.js LTS
mise use --global python@3.13    # 全局 Python 3.13
mise use --global go@latest      # 全局最新 Go

# 项目级版本（在项目目录执行）
cd ~/projects/my-app
mise use node@20                  # 该项目使用 Node 20

# 查看当前激活的版本
mise ls

# 查看所有可用版本
mise ls-remote node

自动化安装脚本
将工具链安装编排为模块化函数：


#!/usr/bin/env bash
# install-toolchain.sh

install_runtimes() {
    step "Installing language runtimes via mise"

    # 确保 mise 已安装
    command_exists mise || brew install mise

    # 安装全局运行时
    mise use --global node@lts
    mise use --global python@3.13
    mise use --global go@latest

    # 验证
    node --version
    python3 --version
    go version
}

install_databases() {
    step "Installing databases"

    brew install postgresql@16
    brew install redis

    # 启动服务（可选）
    # brew services start postgresql@16
    # brew services start redis
}

install_containers() {
    step "Installing container runtime"

    if [[ "$(uname -m)" == "arm64" ]]; then
        # Apple Silicon 推荐 Colima（更轻量）
        brew install colima docker docker-compose
        # colima start --cpu 4 --memory 8
    else
        brew install --cask docker
    fi
}

configure_git() {
    step "Configuring Git"

    # 核心配置
    git config --global init.defaultBranch main
    git config --global pull.rebase true
    git config --global push.autoSetupRemote true
    git config --global core.editor nvim
    git config --global core.pager delta

    # Delta 配置
    git config --global delta.navigate true
    git config --global delta.light false
    git config --global delta.side-by-side true

    # 别名
    git config --global alias.co checkout
    git config --global alias.br branch
    git config --global alias.ci commit
    git config --global alias.st status
    git config --global alias.lg "log --oneline --graph --decorate -20"
}
Homebrew Services 管理
# 查看可管理的服务
brew services list

# 启动服务（开机自启）
brew services start postgresql@16
brew services start redis

# 停止服务
brew services stop postgresql@16

# 重启
brew services restart postgresql@16

# 一次性运行（不设开机自启）
brew services run postgresql@16

开发环境诊断清单
#!/usr/bin/env bash
# diagnose.sh — 快速检查开发环境状态

echo "=== System ==="
sw_vers
uname -m

echo -e "\n=== Homebrew ==="
brew --version
brew doctor 2>&1 | head -5

echo -e "\n=== Runtimes ==="
mise ls --current

echo -e "\n=== Key Tools ==="
for tool in git gh nvim docker node python3 go; do
    printf "%-10s %s\n" "$tool:" "$(command -v $tool 2>/dev/null && $tool --version 2>/dev/null | head -1 || echo 'NOT FOUND')"
done

echo -e "\n=== Services ==="
brew services list 2>/dev/null | grep started
总结
开发工具链自动化的核心理念是将隐式依赖变为显式声明。Xcode CLI Tools 提供编译基础，Homebrew 管理独立工具，mise 统一所有语言运行时的版本控制，Brewfile 声明环境全貌。这三层组合起来，加上 bootstrap 脚本的编排，实现了"新机器 → 完整开发环境"的全自动路径。关键习惯是：每次安装新工具后更新 Brewfile，每个新项目创建 .mise.toml——让环境状态始终可追踪、可复现。
