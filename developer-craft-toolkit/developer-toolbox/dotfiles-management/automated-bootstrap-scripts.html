自动化 Bootstrap 脚本

概述

一个成熟的 dotfiles 仓库最终要回答一个问题：拿到一台全新的机器，需要多久才能进入生产力状态？如果答案是"几个小时的手动安装和配置"，那么 dotfiles 管理只完成了一半。自动化 bootstrap 脚本是闭环的关键——它将"从裸机到完整开发环境"的过程浓缩为一条命令，实现真正的一键部署。

本文详解 bootstrap 脚本的架构设计、幂等性保证、跨平台兼容、错误处理，以及如何用容器化方式持续验证脚本的可靠性。

核心概念

什么是 Bootstrap 脚本

Bootstrap 脚本是一个可在裸机上运行的入口脚本，负责：

  1. 安装基础依赖（包管理器、Git）
  2. Clone dotfiles 仓库
  3. 部署配置文件（Stow/chezmoi）
  4. 安装开发工具（Homebrew packages、语言运行时）
  5. 配置系统偏好
  6. 验证安装结果

设计原则

原则 说明
幂等性 脚本可重复执行，不会重复安装或覆盖配置
原子性 每步操作成功后才继续，失败时提供清晰错误信息
最小权限 仅在必要时使用 sudo，且明确提示用户
可选步骤 支持选择性执行（如跳过 GUI 应用安装）
可观测性 清晰的日志输出，区分信息/警告/错误

实战指南

脚本框架

#!/usr/bin/env bash
# bootstrap.sh — 一键开发环境部署
# 用法: curl -fsSL https://raw.githubusercontent.com/user/dotfiles/main/bootstrap.sh | bash

set -euo pipefail

# === 工具函数 ===

BOLD='\033[1m'
GREEN='\033[0;32m'
YELLOW='\033[0;33m'
RED='\033[0;31m'
NC='\033[0m'

info() { echo -e "${GREEN}[INFO]${NC} $*"; }
warn() { echo -e "${YELLOW}[WARN]${NC} $*"; }
error() { echo -e "${RED}[ERROR]${NC} $*" >&2; }

step() {
    echo -e "\n${BOLD}===> $*${NC}"
}

command_exists() {
    command -v "$1" &>/dev/null
}

# === 平台检测 ===

detect_platform() {
    case "$(uname -s)" in
        Darwin) PLATFORM="macos" ;;
        Linux)  PLATFORM="linux" ;;
        *)      error "Unsupported platform: $(uname -s)"; exit 1 ;;
    esac

    case "$(uname -m)" in
        arm64|aarch64) ARCH="arm64" ;;
        x86_64)        ARCH="x86_64" ;;
        *)             error "Unsupported arch: $(uname -m)"; exit 1 ;;
    esac

    info "Platform: $PLATFORM ($ARCH)"
}

# === 包管理器安装 ===

install_homebrew() {
    if command_exists brew; then
        info "Homebrew already installed"
        return 0
    fi

    step "Installing Homebrew"
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

    # 配置 PATH
    if [[ "$PLATFORM" == "macos" && "$ARCH" == "arm64" ]]; then
        eval "$(/opt/homebrew/bin/brew shellenv)"
    fi
}

# === Dotfiles 部署 ===

DOTFILES_DIR="$HOME/dotfiles"
DOTFILES_REPO="https://github.com/username/dotfiles.git"

clone_dotfiles() {
    if [[ -d "$DOTFILES_DIR" ]]; then
        info "Dotfiles already cloned, pulling latest..."
        git -C "$DOTFILES_DIR" pull --rebase
    else
        step "Cloning dotfiles"
        git clone "$DOTFILES_REPO" "$DOTFILES_DIR"
    fi
}

deploy_dotfiles() {
    step "Deploying dotfiles with Stow"
    cd "$DOTFILES_DIR"

    # 核心模块（所有机器）
    local core_modules=(zsh git starship)
    for mod in "${core_modules[@]}"; do
        if [[ -d "$mod" ]]; then
            stow --restow "$mod" 2>/dev/null || warn "Stow conflict in $mod"
        fi
    done

    # GUI 模块（仅桌面环境）
    if [[ "$PLATFORM" == "macos" ]]; then
        local gui_modules=(ghostty aerospace)
        for mod in "${gui_modules[@]}"; do
            if [[ -d "$mod" ]]; then
                stow --restow "$mod" 2>/dev/null || warn "Stow conflict in $mod"
            fi
        done
    fi
}

# === 工具安装 ===

install_packages() {
    step "Installing packages from Brewfile"

    if [[ -f "$DOTFILES_DIR/Brewfile" ]]; then
        brew bundle install --file="$DOTFILES_DIR/Brewfile" --no-lock
    else
        warn "No Brewfile found, installing essentials..."
        brew install git stow starship eza bat fd ripgrep fzf zoxide mise jq
    fi
}

install_runtimes() {
    step "Installing language runtimes via mise"

    if command_exists mise; then
        mise install --yes
    else
        warn "mise not found, skipping runtime installation"
    fi
}

# === 系统配置 ===

configure_macos() {
    if [[ "$PLATFORM" != "macos" ]]; then return 0; fi

    step "Configuring macOS defaults"

    # Finder
    defaults write com.apple.finder AppleShowAllFiles -bool true
    defaults write com.apple.finder ShowPathbar -bool true

    # Dock
    defaults write com.apple.dock autohide -bool true
    defaults write com.apple.dock autohide-delay -float 0

    # 键盘
    defaults write NSGlobalDomain KeyRepeat -int 2
    defaults write NSGlobalDomain InitialKeyRepeat -int 15

    # 重启受影响的应用
    killall Finder Dock 2>/dev/null || true

    info "macOS defaults configured"
}

# === 验证 ===

verify_installation() {
    step "Verifying installation"

    local tools=(git brew stow starship nvim node python3)
    local failed=0

    for tool in "${tools[@]}"; do
        if command_exists "$tool"; then
            info "  ✓ $tool ($(command -v $tool))"
        else
            warn "  ✗ $tool not found"
            ((failed++))
        fi
    done

    if [[ $failed -gt 0 ]]; then
        warn "$failed tools not found (some may be optional)"
    else
        info "All tools verified successfully!"
    fi
}

# === 主流程 ===

main() {
    echo -e "${BOLD}🚀 Developer Environment Bootstrap${NC}"
    echo "=================================="

    detect_platform
    install_homebrew
    clone_dotfiles

    # Stow 需要通过 Homebrew 安装
    brew install stow 2>/dev/null || true

    deploy_dotfiles
    install_packages
    install_runtimes
    configure_macos
    verify_installation

    echo ""
    echo -e "${GREEN}${BOLD}✅ Bootstrap complete!${NC}"
    echo "Please restart your terminal or run: exec zsh"
}

main "$@"

幂等性保证

每个函数都应检查目标状态，已达到则跳过：

# 模式：检查 -> 跳过或执行

install_tool() {
    local tool=$1
    if command_exists "$tool"; then
        info "$tool already installed ($(${tool} --version 2>/dev/null | head -1))"
        return 0
    fi
    brew install "$tool"
}

容器化验证

用 Docker 定期测试 bootstrap 脚本在干净环境中的执行：

# Dockerfile.test
FROM ubuntu:24.04

RUN apt-get update && apt-get install -y curl git sudo

# 创建测试用户
RUN useradd -m -s /bin/bash testuser && \
    echo "testuser ALL=(ALL) NOPASSWD:ALL" >> /etc/sudoers

USER testuser
WORKDIR /home/testuser

# 运行 bootstrap
COPY bootstrap.sh /tmp/bootstrap.sh
RUN bash /tmp/bootstrap.sh
# 构建测试镜像
docker build -f Dockerfile.test -t dotfiles-test .

# 验证结果
docker run --rm dotfiles-test zsh -c "starship --version && git --version"

最佳实践

错误处理策略

# 方案 1：trap 全局捕获
trap 'error "Script failed at line $LINENO"; exit 1' ERR

# 方案 2：每步检查（更精细）
install_homebrew || { error "Homebrew install failed"; exit 1; }

# 方案 3：可恢复错误（警告但继续）
stow zsh 2>/dev/null || warn "Stow conflict in zsh, manual fix needed"

远程执行模式

支持从 URL 直接执行（新机器连 clone 都省了）：

# 用户只需运行一条命令
bash <(curl -fsSL https://raw.githubusercontent.com/user/dotfiles/main/bootstrap.sh)

# 或带参数
curl -fsSL https://raw.githubusercontent.com/user/dotfiles/main/bootstrap.sh | bash -s -- --minimal

参数化安装

# 支持不同模式
case "${1:-full}" in
    minimal)  INSTALL_GUI=false; INSTALL_RUNTIMES=false ;;
    server)   INSTALL_GUI=false; INSTALL_RUNTIMES=true ;;
    full)     INSTALL_GUI=true;  INSTALL_RUNTIMES=true ;;
esac

CI/CD 集成

# .github/workflows/test-bootstrap.yml
name: Test Bootstrap
on:
  push:
    paths: ['bootstrap.sh', 'Brewfile']
  schedule:
    - cron: '0 0 * * 1' # 每周一验证

jobs:
  test-macos:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - run: bash bootstrap.sh --minimal
      - run: |
          command -v starship
          command -v eza

工具与生态

Bootstrap 框架对比

方案 复杂度 特点
自写 Bash 脚本 中 完全控制、无依赖
chezmoi init 低 与 chezmoi 深度集成
Ansible playbook 高 声明式、可测试、适合团队
Nix/nix-darwin 高 纯函数式、完全可复现
Brewfile only 低 仅管理包安装，不管配置部署

推荐组合

对于个人开发者的典型场景：

bootstrap.sh（入口）
    ├── Homebrew 安装
    ├── Brewfile（包声明）
    ├── GNU Stow / chezmoi（配置部署）
    ├── mise（运行时版本）
    └── defaults write（macOS 偏好）

总结

Bootstrap 脚本是 dotfiles 管理的终极验证——如果你的脚本能在一台空白机器上无人干预地完成整个环境搭建，说明你的配置管理已经达到了基础设施即代码（Infrastructure as Code）的水平。关键是从小处开始：先写一个安装 Homebrew + 部署核心 dotfiles 的 30 行脚本，验证它在新机器上能正常工作；然后逐步扩展到完整的工具链安装和系统配置。定期用 Docker 或 CI 验证脚本的健壮性，确保它不会因为某个工具的版本变化而悄然失效。
