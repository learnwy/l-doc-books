SQLite 作为应用格式

概述

当你需要为个人应用选择数据存储格式时，面前通常有三条路：自定义二进制格式（性能最优但维护成本极高）、JSON/YAML 文件堆（人类可读但缺乏事务保证）、或者 SQLite。SQLite 提供了一个独特的甜点区——它既是一个完整的关系数据库引擎，又表现为磁盘上的单个文件。SQLite 官方明确将其定位为"应用文件格式"（Application File Format），而非服务端数据库的替代品。这个定位在 2026 年已被广泛验证：从 macOS 的核心服务到 Android 的 SMS 存储，从 Obsidian 的元数据到 1Password 的密码库，SQLite 文件承载着数十亿设备上的应用状态。

核心概念

应用文件格式的三种范式

SQLite 同时解决了前两种范式的核心缺陷：


    

  • 不像自定义格式那样需要专门的读写代码——任何 SQLite 命令行工具都能打开
    • 

  • 不像文件堆那样难以原子操作——SQLite 的事务保证断电不损坏
    • 

  • 压缩后与 ZIP 方案大小差异在 ±1% 以内
    •

application_id：注册你的文件类型
SQLite 提供 application_id pragma，让你为自己的格式注册唯一标识：


-- 设置应用 ID（32 位整数）
PRAGMA application_id = 0x4D594150;  -- "MYAP" 的 ASCII 编码

-- 读取应用 ID
PRAGMA application_id;
-- 返回: 1297564752

-- 配合 user_version 做版本管理
PRAGMA user_version = 3;  -- schema 版本 3
这使得 file(1) 命令和操作系统可以识别你的文件类型，也为未来的 schema 迁移提供了版本号追踪。


实战指南
设计你的应用 Schema
以个人笔记应用为例，展示 SQLite 作为应用格式的完整实践：


-- 应用元数据
PRAGMA application_id = 0x4E4F5445;  -- "NOTE"
PRAGMA user_version = 1;

-- 核心数据表
CREATE TABLE notes (
    id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
    title TEXT NOT NULL DEFAULT '',
    content TEXT NOT NULL DEFAULT '',
    format TEXT NOT NULL DEFAULT 'markdown' CHECK(format IN ('markdown', 'plaintext', 'html')),
    created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now')),
    updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now')),
    archived INTEGER NOT NULL DEFAULT 0,
    pinned INTEGER NOT NULL DEFAULT 0
);

-- 标签系统（多对多）
CREATE TABLE tags (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL UNIQUE COLLATE NOCASE,
    color TEXT DEFAULT '#808080'
);

CREATE TABLE note_tags (
    note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
    tag_id INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (note_id, tag_id)
);

-- 附件追踪
CREATE TABLE attachments (
    id TEXT PRIMARY KEY,
    note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
    filename TEXT NOT NULL,
    mime_type TEXT NOT NULL,
    size_bytes INTEGER NOT NULL,
    data BLOB NOT NULL,  -- 小文件直接存 BLOB（<100KB）
    created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ', 'now'))
);

-- 全文搜索
CREATE VIRTUAL TABLE notes_fts USING fts5(
    title, content,
    content=notes,
    content_rowid=rowid,
    tokenize='unicode61 remove_diacritics 2'
);

-- 自动同步 FTS 索引
CREATE TRIGGER notes_ai AFTER INSERT ON notes BEGIN
    INSERT INTO notes_fts(rowid, title, content) VALUES (new.rowid, new.title, new.content);
END;
CREATE TRIGGER notes_ad AFTER DELETE ON notes BEGIN
    INSERT INTO notes_fts(notes_fts, rowid, title, content) VALUES('delete', old.rowid, old.title, old.content);
END;
CREATE TRIGGER notes_au AFTER UPDATE ON notes BEGIN
    INSERT INTO notes_fts(notes_fts, rowid, title, content) VALUES('delete', old.rowid, old.title, old.content);
    INSERT INTO notes_fts(rowid, title, content) VALUES (new.rowid, new.title, new.content);
END;
Schema 版本迁移
SQLite 的 user_version pragma 配合迁移函数，实现安全的 schema 演进：


const CURRENT_VERSION = 3;

function migrate(db) {
  const version = db.pragma('user_version', { simple: true });

  if (version < 1) {
    db.exec(SCHEMA_V1); // 基础表
    db.pragma('user_version = 1');
  }

  if (version < 2) {
    // V2: 添加笔记链接表
    db.exec(`
      CREATE TABLE note_links (
        source_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
        target_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
        context TEXT,
        PRIMARY KEY (source_id, target_id)
      );
    `);
    db.pragma('user_version = 2');
  }

  if (version < 3) {
    // V3: 添加同步元数据
    db.exec(`
      ALTER TABLE notes ADD COLUMN sync_version INTEGER DEFAULT 0;
      ALTER TABLE notes ADD COLUMN last_synced_at TEXT;
    `);
    db.pragma('user_version = 3');
  }
}

初始化 Pragma 配置
每次打开数据库时应设置的 pragma：


PRAGMA journal_mode = WAL;         -- 并发读写
PRAGMA synchronous = NORMAL;       -- 性能/安全平衡
PRAGMA foreign_keys = ON;          -- 启用外键约束
PRAGMA busy_timeout = 5000;        -- 锁等待 5 秒
PRAGMA cache_size = -64000;        -- 64MB 页面缓存
PRAGMA auto_vacuum = INCREMENTAL;  -- 增量回收空间

总结
SQLite 作为应用文件格式的价值在于：它把"存储"从需要你操心的基础设施问题，变成了一个已解决的工程问题。你不需要设计文件格式、编写序列化代码、处理并发冲突或实现事务回滚——SQLite 在过去 20 年已经做到了极致。对个人开发者，这意味着你可以把全部精力放在应用逻辑上。用 .db 文件替代 JSON 文件堆，用 SQL 替代手写过滤逻辑，用 FTS5 替代自建搜索——每一个选择都是在减少你需要维护的代码量，同时增加数据的可靠性和可访问性。
