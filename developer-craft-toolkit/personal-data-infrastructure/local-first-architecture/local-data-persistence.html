本地数据持久化

概述

Local-first 应用的核心承诺是"客户端拥有自己的数据库"。这意味着数据不仅在内存中存活于 CRDT 结构，还必须可靠地持久化到本地存储——即使用户关闭浏览器标签页、重启设备或清理缓存，数据依然安全。2026 年，浏览器平台提供了三种截然不同的持久化路径：IndexedDB（异步键值存储）、Origin Private File System（高性能文件访问）和 SQLite WASM（完整关系引擎）。桌面应用则可以直接使用原生文件系统和 SQLite。选择正确的持久化策略，直接决定了应用的性能上限和用户数据的安全系数。

核心概念

浏览器存储层级

对 Local-first 应用而言，LocalStorage 和 Cache API 因容量和性能限制基本不可用。真正的竞争在 IndexedDB、OPFS 和 SQLite WASM 之间。

Storage Persistence API
浏览器默认将 IndexedDB/OPFS 视为"可驱逐"存储——在磁盘压力下可能被清除。必须调用 navigator.storage.persist() 请求持久化保护：


// 请求持久化存储——用户数据不会被自动清除
const isPersisted = await navigator.storage.persist();
if (!isPersisted) {
  console.warn('浏览器未授予持久化权限，数据可能在磁盘压力下丢失');
  // 建议：引导用户将站点添加为 PWA 或书签
}

// 检查配额使用情况
const estimate = await navigator.storage.estimate();
console.log(`已用: ${(estimate.usage / 1024 / 1024).toFixed(1)}MB`);
console.log(`配额: ${(estimate.quota / 1024 / 1024).toFixed(0)}MB`);
实战指南
IndexedDB：成熟的异步存储
IndexedDB 是浏览器中最成熟的大容量存储方案，支持事务、索引和游标查询。原生 API 冗长但功能完整，生产中通常通过包装库使用：


// 使用 idb 库简化 IndexedDB 操作
import { openDB } from 'idb';

const db = await openDB('personal-notes', 2, {
  upgrade(db, oldVersion) {
    if (oldVersion < 1) {
      const store = db.createObjectStore('notes', { keyPath: 'id' });
      store.createIndex('by-date', 'updatedAt');
      store.createIndex('by-tag', 'tags', { multiEntry: true });
    }
    if (oldVersion < 2) {
      db.createObjectStore('attachments', { keyPath: 'id' });
    }
  },
});

// 写入（事务内，原子性保证）
const tx = db.transaction('notes', 'readwrite');
await tx.store.put({
  id: 'note-2026-05-08',
  title: 'CRDT 学习笔记',
  content: '今天研究了 Yjs 的 YATA 算法...',
  tags: ['tech', 'crdt'],
  updatedAt: Date.now(),
});
await tx.done;

// 按索引查询
const recentNotes = await db.getAllFromIndex('notes', 'by-date', IDBKeyRange.lowerBound(Date.now() - 7 * 86400000));
IndexedDB 的局限：


    

  • 异步 API：所有操作返回 Promise，无法在同步代码路径中使用
    • 

  • 无 SQL：只有键值查询和索引范围扫描，复杂查询需要在应用层实现
    • 

  • 序列化开销：结构化克隆算法对大对象有可观的序列化成本
    • 



OPFS：高性能文件访问
Origin Private File System 是 2023 年标准化的新 API，提供类似原生文件系统的同步访问能力（仅限 Web Worker）：


// 在 Web Worker 中使用 OPFS 同步访问
// worker.js
const root = await navigator.storage.getDirectory();
const fileHandle = await root.getFileHandle('app.db', { create: true });

// 获取同步访问句柄（仅 Worker 可用）
const syncHandle = await fileHandle.createSyncAccessHandle();

// 高性能读写——无 Promise 开销
const buffer = new ArrayBuffer(4096);
const bytesRead = syncHandle.read(buffer, { at: 0 });
syncHandle.write(new Uint8Array([1, 2, 3]), { at: 0 });
syncHandle.flush(); // 确保写入持久化
syncHandle.close();
OPFS 的核心价值：为 SQLite WASM 提供了接近原生性能的存储后端。wa-sqlite 和 sql.js 都利用 OPFS 作为底层 VFS（Virtual File System），实现了浏览器中的高性能数据库。


SQLite WASM：浏览器中的完整数据库
2026 年，SQLite 官方提供了 WASM 构建（sqlite3.wasm），社区方案 wa-sqlite 和 sql.js 也在持续优化。SQLite WASM + OPFS 的组合，让浏览器应用拥有了真正的关系数据库：


// 使用 @sqlite.org/sqlite-wasm 官方包
import sqlite3InitModule from '@sqlite.org/sqlite-wasm';

const sqlite3 = await sqlite3InitModule();
const db = new sqlite3.oo1.OpfsDb('/personal-data.db');

// 完整的 SQL 能力
db.exec(`
  CREATE TABLE IF NOT EXISTS notes (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    content TEXT,
    tags JSON,
    created_at INTEGER DEFAULT (unixepoch()),
    updated_at INTEGER DEFAULT (unixepoch())
  );
  CREATE INDEX IF NOT EXISTS idx_notes_updated ON notes(updated_at);
`);

// 全文搜索
db.exec(`
  CREATE VIRTUAL TABLE IF NOT EXISTS notes_fts
  USING fts5(title, content, content=notes, content_rowid=rowid);
`);

// 查询
const results = db.exec({
  sql: `SELECT * FROM notes WHERE updated_at > ? ORDER BY updated_at DESC`,
  bind: [Date.now() / 1000 - 86400],
  returnValue: 'resultRows',
  rowMode: 'object',
});

  // 在打开后立即设置

// 批量插入用 transaction 包裹——性能提升 10-100x
const insertNote = db.prepare('INSERT OR REPLACE INTO notes (id, title, content) VALUES (?, ?, ?)');
const insertMany = db.transaction((notes) => {
  for (const note of notes) {
    insertNote.run(note.id, note.title, note.content);
  }
});

数据安全策略
    

  1. 调用 persist()：必须请求持久化存储，否则数据可能被浏览器清除
    2. 

  2. 双写策略：关键数据同时写入 IndexedDB 和 OPFS，互为备份
    3. 

  3. 导出功能：提供 JSON/SQLite 文件导出，让用户可以手动备份
    4. 

  4. 版本迁移：数据库 schema 变更使用版本号管理，提供向前迁移路径
    5. 



性能优化要点
    

  • 批量写入：将多个小写入合并为单个事务，SQLite 中可提升 10-100 倍
    • 

  • Worker 分离：将数据库操作放入 Web Worker，避免阻塞主线程 UI
    • 

  • 延迟写入：用 debounce 合并高频更新（如打字），减少磁盘 I/O
    • 

  • 索引策略：只为实际查询模式创建索引，过多索引拖慢写入
    •

总结
本地数据持久化是 Local-first 架构的地基。浏览器环境中，IndexedDB 成熟稳定适合 CRDT 文档存储，OPFS 提供高性能文件访问，SQLite WASM 带来完整的关系查询能力——三者可以按需组合。桌面应用直接使用原生 SQLite 绑定即可获得最优性能。无论选择哪条路径，核心原则不变：请求持久化权限、事务保护写入、Worker 隔离 I/O、定期备份导出。将这些基础打牢，你的个人数据才能真正"属于你"——不依赖任何云服务的可用性。
