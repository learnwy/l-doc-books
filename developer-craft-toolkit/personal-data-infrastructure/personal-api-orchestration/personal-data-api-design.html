个人数据 API 设计与实现

概述

前两篇文章解决了数据的入口问题：主动拉取（聚合多源数据）和被动接收（Webhook 管道）。现在所有个人数据都存储在本地 SQLite 中——GitHub 贡献、健康指标、阅读记录、时间分配、财务流水。但这些数据如果只能通过直接查询数据库来访问，就无法被你的各种个人项目复用。

Personal Data API 是将你的私有数据暴露为标准化 HTTP 接口的实践——让仪表盘、CLI 工具、移动 App、AI Agent 都能通过统一的 API 访问你的数据。本文从 REST 资源建模到 GraphQL 按需查询，从认证鉴权到缓存策略，提供基于 Hono 框架的完整实现方案。最终目标是：任何新项目启动时，个人数据唾手可得。

核心概念

为什么需要 Personal API

对于个人基础设施，推荐组合方案：Tailscale 网络层隔离 + API Key 应用层认证。


// API Key 认证中间件
import { createMiddleware } from 'hono/factory';

const apiKeyAuth = createMiddleware(async (c, next) => {
  const authHeader = c.req.header('Authorization');
  if (!authHeader?.startsWith('Bearer ')) {
    return c.json({ error: 'Missing API key' }, 401);
  }

  const apiKey = authHeader.slice(7);
  const keyRecord = await validateApiKey(apiKey);

  if (!keyRecord) {
    return c.json({ error: 'Invalid API key' }, 401);
  }

  // 注入认证上下文
  c.set('clientId', keyRecord.clientId);
  c.set('scopes', keyRecord.scopes);

  // 审计日志
  await logApiAccess(keyRecord.clientId, c.req.method, c.req.path);

  await next();
});
实战指南
基于 Hono 的完整实现
Hono 是 2026 年增长最快的 JavaScript Web 框架（每周 2000 万+ 下载量），14KB 体积、零依赖、多运行时支持（Node.js/Bun/Deno/Cloudflare Workers），是个人 API 的理想选择：


import { Hono } from 'hono';
import { cors } from 'hono/cors';
import { logger } from 'hono/logger';
import { prettyJSON } from 'hono/pretty-json';
import { zValidator } from '@hono/zod-validator';
import { z } from 'zod';
import Database from 'better-sqlite3';

const app = new Hono();
const db = new Database('./personal-data.db');

// 全局中间件
app.use('*', logger());
app.use('*', cors({ origin: ['http://localhost:3000'] }));
app.use('*', prettyJSON());
app.use('*', apiKeyAuth);

// === Events API ===
const eventsQuerySchema = z.object({
  source: z.string().optional(),
  type: z.string().optional(),
  since: z.string().datetime().optional(),
  until: z.string().datetime().optional(),
  limit: z.coerce.number().min(1).max(100).default(20),
  offset: z.coerce.number().min(0).default(0),
});

app.get('/v1/events', zValidator('query', eventsQuerySchema), (c) => {
  const { source, type, since, until, limit, offset } = c.req.valid('query');

  let sql = 'SELECT * FROM events WHERE 1=1';
  const params: unknown[] = [];

  if (source) {
    sql += ' AND source = ?';
    params.push(source);
  }
  if (type) {
    sql += ' AND type = ?';
    params.push(type);
  }
  if (since) {
    sql += ' AND timestamp >= ?';
    params.push(since);
  }
  if (until) {
    sql += ' AND timestamp <= ?';
    params.push(until);
  }

  sql += ' ORDER BY timestamp DESC LIMIT ? OFFSET ?';
  params.push(limit, offset);

  const events = db.prepare(sql).all(...params);
  const total = db
    .prepare(sql.replace('SELECT *', 'SELECT COUNT(*)').replace(/LIMIT.*$/, ''))
    .get(...params.slice(0, -2));

  return c.json({
    data: events,
    pagination: { total: total['COUNT(*)'], limit, offset },
  });
});

// === Health Metrics API ===
app.get('/v1/metrics/health', (c) => {
  const from = c.req.query('from') || todayStr();
  const to = c.req.query('to') || todayStr();

  const metrics = db
    .prepare(
      `
    SELECT date, steps, heart_rate, sleep_hours, active_minutes
    FROM health_metrics
    WHERE date BETWEEN ? AND ?
    ORDER BY date DESC
  `,
    )
    .all(from, to);

  return c.json({ data: metrics });
});

// === Today Summary API ===
app.get('/v1/summary/today', (c) => {
  const today = todayStr();
  const summary = {
    commits:
      db
        .prepare(
          `SELECT COUNT(*) as n FROM events 
       WHERE source='github' AND type='code.commit' AND date(timestamp)=?`,
        )
        .get(today)?.n ?? 0,
    meetings:
      db
        .prepare(
          `SELECT COUNT(*) as n FROM events 
       WHERE source='calendar' AND type='meeting' AND date(timestamp)=?`,
        )
        .get(today)?.n ?? 0,
    steps: db.prepare(`SELECT steps FROM health_metrics WHERE date=?`).get(today)?.steps ?? 0,
    tasksCompleted:
      db
        .prepare(
          `SELECT COUNT(*) as n FROM events 
       WHERE type='task.completed' AND date(timestamp)=?`,
        )
        .get(today)?.n ?? 0,
  };
  return c.json(summary);
});

export default app;
速率限制与缓存
即使是个人 API，也需要保护机制——防止调试时的死循环把数据库打爆：


import { rateLimiter } from 'hono-rate-limiter';

// 每个 API Key 每分钟 60 次请求
app.use(
  '/v1/*',
  rateLimiter({
    windowMs: 60 * 1000,
    limit: 60,
    keyGenerator: (c) => c.get('clientId') || c.req.header('x-forwarded-for'),
  }),
);

// 基于 ETag 的缓存
app.use('/v1/metrics/*', async (c, next) => {
  await next();

  if (c.res.status === 200) {
    const body = await c.res.text();
    const etag = `"${hashMD5(body)}"`;

    if (c.req.header('If-None-Match') === etag) {
      return c.body(null, 304);
    }

    c.res.headers.set('ETag', etag);
    c.res.headers.set('Cache-Control', 'private, max-age=300');
  }
});

import { OpenAPIHono, createRoute, z } from '@hono/zod-openapi';

const app = new OpenAPIHono();

const eventsRoute = createRoute({
  method: 'get',
  path: '/v1/events',
  request: {
    query: eventsQuerySchema,
  },
  responses: {
    200: {
      content: { 'application/json': { schema: eventsResponseSchema } },
      description: 'List of personal events',
    },
  },
});

app.openapi(eventsRoute, (c) => {
  // 类型安全的处理函数
  const query = c.req.valid('query');
  // ...
});

// Swagger UI
app.doc('/openapi.json', { openapi: '3.1.0', info: { title: 'Personal API', version: '1.0.0' } });
app.get('/docs', swaggerUI({ url: '/openapi.json' }));

// 基于 scope 的数据访问控制
const scopeGuard = (requiredScope: string) =>
  createMiddleware(async (c, next) => {
    const scopes = c.get('scopes') as string[];
    if (!scopes.includes(requiredScope)) {
      return c.json({ error: `Missing scope: ${requiredScope}` }, 403);
    }
    await next();
  });

app.get('/v1/finance/*', scopeGuard('finance:read'));
app.get('/v1/health/*', scopeGuard('health:read'));

响应格式标准化
统一的响应信封确保客户端处理一致：


// 成功响应
interface ApiSuccessResponse<T> {
  data: T;
  pagination?: { total: number; limit: number; offset: number };
  meta?: { cached: boolean; generatedAt: string };
}

// 错误响应
interface ApiErrorResponse {
  error: {
    code: string;
    message: string;
    details?: unknown;
  };
}

// 统一响应工厂
function ok<T>(c: Context, data: T, meta?: Record<string, unknown>) {
  return c.json({ data, meta: { ...meta, generatedAt: new Date().toISOString() } });
}

function fail(c: Context, code: string, message: string, status: number = 400) {
  return c.json({ error: { code, message } }, status);
}

总结
Personal Data API 是个人数据基础设施的对外门面。它将底层的 SQLite 存储、ETL 管道、Webhook 事件流封装为干净的 HTTP 接口，让每个新项目都能以最小成本接入你的个人数据。关键设计决策：


    

  1. Hono 是 2026 年个人 API 的最佳框架选择——14KB 体积、类型安全、多运行时、性能优异
    2. 

  2. REST 为主、GraphQL 为辅——REST 覆盖 80% 场景，GraphQL 用于复杂聚合查询
    3. 

  3. 认证分层：网络层 + 应用层——Tailscale 隔离网络 + API Key 控制权限
    4. 

  4. 数据安全分级暴露——不是所有数据都该通过 API 访问
    5. 

  5. OpenAPI 文档是 AI 时代的刚需——Agent 通过 spec 理解你的 API
    6. 



至此，个人数据基础设施的四大支柱已经搭建完成：Local-first 存储 → SQLite 数据层 → 自托管服务 → API 编排层。你拥有了一套完整的技术栈，将散落在互联网各处的个人数据聚合、存储、处理并对外提供服务——所有一切都在你自己的掌控之中。
