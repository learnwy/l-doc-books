域名与隧道配置

概述

Homelab 搭建完成后面临一个核心问题：如何从外部网络安全地访问家里的服务？传统方案需要公网 IP + 端口转发 + DDNS，但 2026 年更优雅的方案是 Cloudflare Tunnel——无需暴露任何端口、无需公网 IP，通过出站连接建立加密隧道即可实现安全的公网访问。本文从域名配置开始，对比各种远程访问方案，提供一套兼顾安全性和便利性的完整配置指南。

核心概念

远程访问方案对比

方案 安全性 配置复杂度 需要公网 IP 适用场景
端口转发 + DDNS 低 中 是 不推荐
Cloudflare Tunnel 高 低 否 Web 服务公网访问
Tailscale 高 极低 否 个人设备间访问
WireGuard (自建) 高 高 是 完全自主控制
ZeroTier 中 低 否 多设备组网

Cloudflare Tunnel 工作原理

关键优势：


    

  • 零端口暴露：路由器不需要开放任何入站端口
    • 

  • 无需公网 IP：即使在 NAT 后面也能工作
    • 

  • 自带 DDoS 防护：Cloudflare 的 Edge 网络天然屏蔽攻击
    • 

  • 自动 HTTPS：Cloudflare 管理证书，无需 Let's Encrypt
    • 



域名 DNS 架构
yourdomain.com (Cloudflare DNS)
├── A/AAAA     → Cloudflare Proxy (公网服务)
├── CNAME      → tunnel-id.cfargotunnel.com (隧道服务)
└── 本地 DNS   → Pi-hole/AdGuard Home (内网解析)
实战指南
步骤一：域名注册与 Cloudflare 配置
# 1. 在 Cloudflare 注册域名（或将现有域名 NS 切换到 Cloudflare）
# 推荐: .com / .dev / .app 后缀

# 2. 在 Cloudflare Dashboard 添加站点
# Zone Settings → SSL/TLS → Full (Strict)
# Zone Settings → Edge Certificates → Always Use HTTPS: ON

# 3. 获取 API Token (用于自动化)
# My Profile → API Tokens → Create Token
# Template: Edit zone DNS
步骤二：安装 Cloudflare Tunnel
# /opt/homelab/cloudflared/docker-compose.yml
services:
  cloudflared:
    image: cloudflare/cloudflared:latest
    container_name: cloudflared
    restart: unless-stopped
    command: tunnel run
    environment:
      - TUNNEL_TOKEN=${TUNNEL_TOKEN}
    networks:
      - proxy

networks:
  proxy:
    external: true
通过 Cloudflare Dashboard 创建隧道更方便（Zero Trust → Access → Tunnels → Create）：


# 或者用 CLI 创建
docker run cloudflare/cloudflared:latest tunnel login
docker run cloudflare/cloudflared:latest tunnel create homelab

# 获取 Tunnel Token 后设置到 .env
echo "TUNNEL_TOKEN=your-tunnel-token" >> /opt/homelab/.env

步骤四：Cloudflare Access 保护敏感服务
对不自带强认证的服务，添加 Cloudflare Access 策略：


Zero Trust → Access → Applications → Add Application
├── Self-hosted
├── Application domain: n8n.yourdomain.com
├── Policy: Allow
│   └── Include: Emails ending in @youremail.com
│   └── Require: One-time PIN (email verification)
└── Session duration: 24 hours
步骤五：Tailscale 内网组网
对不需要公网访问的管理服务，用 Tailscale 组建私有网络：


# /opt/homelab/tailscale/docker-compose.yml
services:
  tailscale:
    image: tailscale/tailscale:latest
    container_name: tailscale
    restart: unless-stopped
    hostname: homelab
    cap_add:
      - NET_ADMIN
      - SYS_MODULE
    volumes:
      - ./state:/var/lib/tailscale
      - /dev/net/tun:/dev/net/tun
    environment:
      - TS_AUTHKEY=${TAILSCALE_AUTHKEY}
      - TS_STATE_DIR=/var/lib/tailscale
      - TS_EXTRA_ARGS=--advertise-exit-node --advertise-routes=192.168.1.0/24
    network_mode: host
Tailscale 的优势：


    

  • 所有设备（手机、笔记本、服务器）自动组网
    • 

  • WireGuard 协议，性能接近直连
    • 

  • MagicDNS：用 homelab.tail-xxx.ts.net 访问服务
    • 

  • 无需域名和证书
    • 



步骤六：Let's Encrypt 通配符证书
如果使用 Traefik 而非 Cloudflare Tunnel（如纯内网场景）：


# Traefik 配置自动申请通配符证书
certificatesResolvers:
  letsencrypt:
    acme:
      email: your@email.com
      storage: /certs/acme.json
      dnsChallenge:
        provider: cloudflare
        resolvers:
          - '1.1.1.1:53'

# 通配符证书路由
http:
  routers:
    wildcard:
      rule: 'HostRegexp(`{subdomain:.+}.yourdomain.com`)'
      tls:
        certResolver: letsencrypt
        domains:
          - main: 'yourdomain.com'
            sans:
              - '*.yourdomain.com'

混合访问策略
外部访问（公网）:
  └── Cloudflare Tunnel → 需要公网可达的服务（密码管理器等）

个人设备访问:
  └── Tailscale → 管理面板、数据库、SSH

本地网络:
  └── 直连 → 高带宽服务（NAS、媒体流）

当 Cloudflare Tunnel 断开时：


    

  1. 公网服务暂时不可达（安全失败模式）

  2. 本地服务和 Tailscale 访问不受影响
    3. 

  3. cloudflared 会自动重连
    4. 

  4. 如需手动恢复：docker compose restart cloudflared

总结
域名与隧道配置是 Homelab 从"只能在家用"进化为"随时随地可用"的关键一步。2026 年的最佳实践是：Cloudflare Tunnel 处理需要公网访问的 Web 服务（密码管理、文件同步），Tailscale 处理个人设备间的管理访问（SSH、数据库、管理面板），纯本地直连处理大带宽场景（NAS、媒体流）。这套组合的核心安全优势是"零暴露"——你的路由器不开放任何端口，攻击面几乎为零，而你依然可以从世界任何角落访问自己的服务。
