fd 与 ripgrep 深度实践

概述

fd 和 ripgrep 是现代终端中使用频率最高的两款搜索工具。fd 替代 find 用于文件名搜索，ripgrep（命令行名 rg）替代 grep 用于文件内容搜索。两者均由 Rust 编写，默认尊重 .gitignore、自动跳过二进制文件、输出带颜色高亮。截至 2026 年，ripgrep 在 GitHub 获得 69.8k 星，fd 获得 34.2k 星——它们已经从「可选工具」变为「开发者默认配置」。

核心概念

fd 的设计哲学

fd 的核心理念是「合理的默认值」。传统 find 命令要求记忆路径在前还是表达式在前、需要 -name 还是 -path、大小写敏感还是不敏感。fd 把最常见的需求变成默认行为：

行为 find fd
递归搜索 默认 默认
忽略隐藏文件 需要手动排除 默认忽略
忽略 .gitignore 不支持 默认尊重
正则表达式 -regex（不同系统语法不同） 默认使用正则
彩色输出 不支持 默认启用
并行执行 -exec ... + -x 自动并行

ripgrep 的架构优势

ripgrep 快的原因不仅仅是 Rust 语言：

  1. 有限自动机优化：使用 regex crate 的 DFA/NFA 混合引擎，避免回溯导致的灾难性性能
  2. 内存映射：对大文件使用 mmap，减少系统调用
  3. 并行遍历：使用 ignore crate 并行遍历目录树
  4. SIMD 加速：利用 CPU 的 SIMD 指令进行字面量搜索
  5. 智能过滤：在搜索前就跳过不相关的文件，减少 I/O

实战指南

fd 高级用法

# 基础：按扩展名搜索
fd -e ts -e tsx              # 所有 TypeScript 文件
fd -e rs src/                # src/ 下的所有 Rust 文件

# 按类型过滤
fd -t f                      # 只显示文件
fd -t d                      # 只显示目录
fd -t l                      # 只显示符号链接
fd -t x                      # 只显示可执行文件

# 大小过滤
fd -S +1m                    # 大于 1MB 的文件
fd -S -10k -e log            # 小于 10KB 的日志文件

# 时间过滤
fd --changed-within 1d       # 过去 24 小时修改的文件
fd --changed-before 2weeks   # 两周前修改的文件

# 排除模式
fd -E node_modules -E target # 排除特定目录
fd -E '*.min.js'             # 排除压缩的 JS 文件

# 并行执行命令
fd -e png -x convert {} {.}.webp  # 批量转换 PNG 到 WebP
fd -e ts -x wc -l            # 统计每个 TS 文件的行数
fd -t f -0 | xargs -0 du -sh # 与 xargs 配合（空字符分隔）

# 正则表达式搜索
fd '^test_.*\.py$'           # 以 test_ 开头的 Python 文件
fd '2024-\d{2}-\d{2}'       # 包含日期格式的文件名

ripgrep 高级用法

# 智能大小写搜索
rg -S "useState"             # 小写精确匹配，有大写时大小写敏感
rg -i "error"               # 强制忽略大小写

# 文件类型过滤
rg --type ts "interface"    # TypeScript 文件
rg --type-add 'config:*.{yaml,yml,toml,json}' --type config "port"
rg -T test "TODO"           # 排除测试文件

# 上下文控制
rg -C 3 "panic!"            # 前后各 3 行
rg -A 5 "fn main"           # 匹配后 5 行
rg -B 2 "DEPRECATED"        # 匹配前 2 行

# 输出格式控制
rg -l "TODO"                # 只输出文件名
rg -c "console.log"         # 输出每个文件的匹配数
rg --json "error"           # JSON 结构化输出
rg -n "import"              # 显示行号（默认已启用）

# 替换（不修改文件，输出到 stdout）
rg "old_name" -r "new_name" # 替换预览
rg '(\d{4})-(\d{2})-(\d{2})' -r '$3/$2/$1'  # 正则捕获组替换

# 多模式搜索
rg -e "TODO" -e "FIXME" -e "HACK"  # 多模式 OR
rg "error.*timeout|timeout.*error"  # 单模式 OR

# 搜索压缩文件
rg -z "ERROR" /var/log/*.gz # 搜索 gzip 压缩的日志
rg -z "panic" --glob '*.zst' # 搜索 Zstandard 压缩文件

# 预处理器（搜索 PDF 等非文本格式）
rg --pre pdftotext "keyword" docs/  # 需要安装 poppler

# glob 过滤
rg "import" -g '*.ts' -g '!*.test.ts' -g '!*.d.ts'
rg "console" -g '!dist/**' -g '!node_modules/**'

配置文件

# ~/.ripgreprc（或设置 RIPGREP_CONFIG_PATH）
--smart-case
--hidden
--glob=!.git/
--glob=!node_modules/
--glob=!target/
--glob=!dist/
--glob=!.next/
--max-columns=200
--max-columns-preview
# fd 通过 .fdignore 文件配置忽略规则（语法同 .gitignore）
# 项目根目录下创建 .fdignore
node_modules/
target/
dist/
.next/
*.pyc

最佳实践

选择 fd 还是 ripgrep --files

两者都能列出文件，应用场景不同：

场景 推荐工具 原因
按文件名模式搜索 fd 语法更简洁，正则默认
列出特定类型的文件 fd 或 rg --files 都很快
搜索文件内容 rg 唯一选择
配合 fzf 做文件选择 fd 输出更干净
批量执行命令 fd -x 内建并行执行

性能调优建议

# 限制搜索深度（大型 monorepo）
fd --max-depth 3 -e ts
rg "pattern" --max-depth 5

# 使用 --files 替代 find | grep 模式
rg --files | rg "component"  # 在文件列表中搜索

# 利用 .rgignore 减少搜索范围
# 在大型项目根目录放置 .rgignore
# 比运行时 --glob 排除更高效（目录遍历阶段就跳过）

工具与生态

编辑器集成

  • VS Code：内建使用 ripgrep 作为搜索引擎
  • Neovim：telescope.nvim 默认使用 fd + ripgrep
  • Emacs：counsel-rg、projectile 支持 ripgrep
  • JetBrains：可配置外部搜索工具使用 ripgrep

相关工具

工具 用途 与 fd/rg 的关系
ast-grep AST 级别代码搜索 语义搜索，rg 是文本搜索
sd 流式查找替换 配合 rg 预览后实际修改文件
amber 代码搜索替换 类似 rg + sd 的组合
hyperpolyglot 语言检测 fd 的文件类型识别增强

总结

fd 和 ripgrep 是现代终端工具生态的基石。它们的设计原则——合理默认值、自动过滤、彩色输出、极致性能——代表了新一代 CLI 工具的核心理念。掌握它们的高级用法后，文件搜索和内容搜索不再是阻断工作流的瓶颈，而是流畅思考过程中自然发生的操作。配合后续章节的 fzf 交互式搜索，它们的能力还将进一步放大。
