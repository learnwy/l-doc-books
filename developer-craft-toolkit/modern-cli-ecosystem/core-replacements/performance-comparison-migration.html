性能对比与迁移策略

概述

从传统 coreutils 迁移到现代 Rust CLI 工具不仅仅是「换一个命令」那么简单。本文提供基于真实基准测试的性能数据对比、不同场景下的工具选择指南、以及从个人配置到团队协作的完整迁移路径。目标是让你有数据支撑地理解「为什么要换」，并有方法论支撑地完成「如何换」。

最佳实践
迁移策略：渐进式替换
第一阶段：别名替换（Day 1）
# ~/.zshrc 或 ~/.bashrc — 安全的别名，不影响脚本
alias cat='bat --paging=never'
alias ls='eza --group-directories-first'
alias ll='eza -l --git --icons'
alias la='eza -la --git --icons'
alias tree='eza --tree --icons'
alias grep='rg'
alias find='fd'
第二阶段：Shell 集成（Week 1）
# fzf 使用 fd 作为默认文件源
export FZF_DEFAULT_COMMAND='fd --type f --hidden --follow --exclude .git'
export FZF_CTRL_T_COMMAND="$FZF_DEFAULT_COMMAND"
export FZF_ALT_C_COMMAND='fd --type d --hidden --follow --exclude .git'

# bat 作为默认 pager
export BAT_THEME="TwoDark"
export MANPAGER="sh -c 'col -bx | bat -l man -p'"
第三阶段：Git 集成（Week 2）
# ~/.gitconfig
[core]
    pager = delta

[interactive]
    diffFilter = delta --color-only

[delta]
    navigate = true
    side-by-side = true
    line-numbers = true
    syntax-theme = TwoDark
脚本兼容性处理
核心原则：交互式使用现代工具，脚本中保留 POSIX 工具。


# 好的做法：通过别名只在交互式 shell 中替换
if [[ $- == *i* ]]; then
    # 只在交互式 shell 中设置别名
    alias cat='bat --paging=never'
    alias ls='eza'
fi

# 脚本中使用原始命令
#!/bin/bash
# 使用 command 绕过别名
file_count=$(command find . -name "*.py" | wc -l)

# 或者检测工具是否存在后选择性使用
if command -v rg &>/dev/null; then
    results=$(rg -l "pattern" .)
else
    results=$(grep -rl "pattern" .)
fi

工具与生态
一键安装全家桶
# macOS
brew install fd ripgrep bat eza zoxide fzf git-delta

# Ubuntu/Debian
sudo apt install fd-find ripgrep bat
# 注意：Debian/Ubuntu 中 fd 的二进制名为 fdfind，bat 为 batcat
# 需要手动创建链接或别名
ln -s $(which fdfind) ~/.local/bin/fd
ln -s $(which batcat) ~/.local/bin/bat

# Arch Linux
pacman -S fd ripgrep bat eza zoxide fzf git-delta

# Windows (Scoop)
scoop install ripgrep fd bat eza zoxide fzf delta

# Cargo（全平台，从源码编译）
cargo install ripgrep fd-find bat eza zoxide git-delta

总结
性能数据清晰地表明：在搜索场景（fd、ripgrep），现代工具提供 10-60 倍的速度提升，这是改变工作方式的级别；在显示场景（bat、eza），现代工具用毫秒级的额外开销换来显著的信息密度和视觉体验提升。迁移策略的核心是「交互式环境大胆替换，脚本环境保持兼容」。通过三阶段渐进迁移，你可以在不破坏任何现有工作流的前提下，逐步享受现代工具带来的效率提升。
