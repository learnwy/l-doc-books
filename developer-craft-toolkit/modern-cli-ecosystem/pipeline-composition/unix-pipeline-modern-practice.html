Unix 管道现代实践

概述

Unix 管道是 1973 年由 Ken Thompson 引入的概念，至今仍是命令行生产力的核心机制。但在 2026 年，现代工具对管道范式做出了本质性增强：ripgrep 的结构化输出可以被精确解析，fzf 在管道中引入交互式「断点」，bat 智能检测管道上下文切换行为，fd 实现并行管道执行。本文从管道基础出发，讲解这些现代增强如何改变管道设计思维。

核心概念

经典管道 vs 现代管道

传统管道将纯文本从一个命令传递到下一个，每个命令做简单的文本变换。现代工具在保持这一基础不变的同时，引入了新的能力层：

能力 经典管道 现代管道
数据格式 纯文本行 结构化输出（JSON、分隔符）
交互性 完全非交互 fzf 引入交互式选择节点
并行化 串行（左到右） fd -x 实现并行执行
颜色处理 管道中丢失 --color=always 保留 ANSI
错误处理 忽略（pipefail off） set -o pipefail + 工具级错误

管道中的颜色传递

现代工具默认行为：终端输出带颜色，管道输出无颜色。需要显式传递：

# 错误：颜色在管道中丢失
rg "pattern" | fzf         # fzf 看到的是无色文本

# 正确：显式保留颜色
rg "pattern" --color=always | fzf --ansi

# bat 的智能行为
bat file.py               # 终端：有高亮
bat file.py | head        # 管道：自动退化为纯文本
bat --color=always file.py | fzf --ansi  # 强制保留

实战指南

基础管道模式

# Pattern 1: 搜索 → 过滤 → 操作
rg -l "TODO" | fzf | xargs vim

# Pattern 2: 列出 → 筛选 → 批量执行
fd -e ts | fzf -m | xargs -I {} prettier --write {}

# Pattern 3: 生成 → 转换 → 输出
git log --oneline | fzf | awk '{print $1}' | xargs git show

# Pattern 4: 聚合 → 排序 → 展示
fd -e ts -x wc -l | sort -rn | head -20 | bat -l csv

结构化输出管道

ripgrep 的 JSON 输出让管道处理变得更精确：

# ripgrep JSON 输出 → jq 解析 → 精确提取
rg --json "TODO" | jq -r '
  select(.type == "match") |
  "\(.data.path.text):\(.data.line_number):\(.data.lines.text)"
' | head -20

# 按文件分组统计匹配数
rg --json "console.log" | jq -r '
  select(.type == "match") | .data.path.text
' | sort | uniq -c | sort -rn

# fd + stat 构建文件元信息管道
fd -e ts --exec stat -f '%z %N' {} | sort -rn | head -10

交互式管道节点

fzf 可以在管道的任意位置插入交互式选择，形成「人在回路中」的管道设计：

# 管道中间插入 fzf 选择
rg -l "deprecated" |          # 列出包含 deprecated 的文件
  fzf -m --preview 'rg --color=always "deprecated" {}' |  # 交互式选择
  xargs sed -i 's/deprecated/legacy/g'  # 批量替换

# 多次交互：选文件 → 选行 → 操作
file=$(fd -e py | fzf --preview 'bat --color=always {}')
line=$(rg -n "def " "$file" | fzf | cut -d: -f1)
${EDITOR:-vim} "$file" +$line

并行管道执行

# fd 内建并行执行（不经过管道）
fd -e png -x convert {} {.}.webp \;    # 并行转换所有 PNG

# xargs 并行
fd -e ts -0 | xargs -0 -P 4 prettier --write  # 4 进程并行

# GNU parallel 进阶（需安装）
fd -e log | parallel 'gzip {}'         # 并行压缩所有日志
rg -l "pattern" | parallel 'wc -l {}' | sort -rn

错误处理与健壮管道

# 启用 pipefail（推荐在所有脚本中使用）
set -o pipefail

# 管道中的错误短路
rg "pattern" src/ || { echo "No matches found"; exit 1; } |
  fzf || { echo "Selection cancelled"; exit 0; }

# 安全的管道：检查每一步
search_and_edit() {
  local file
  file=$(rg -l "$1" 2>/dev/null) || { echo "No files match"; return 1; }
  file=$(echo "$file" | fzf) || { echo "Cancelled"; return 0; }
  ${EDITOR:-vim} "$file"
}

最佳实践

管道设计原则

  1. 单向数据流：数据从左到右流动，每步做一个明确的变换
  2. 尽早过滤：把过滤条件放在管道前端，减少后续处理量
  3. 保持文本行格式：管道中的数据应该是「一行一条记录」
  4. 显式分隔符：用 -0/--null 处理含空格的文件名
  5. 颜色在末端：只在管道最后一步或 fzf 预览中使用颜色
# 好的管道设计
fd -e ts --max-depth 3 |    # 尽早限制范围
  grep -v "node_modules" |  # 尽早过滤
  fzf --preview 'bat --color=always {}'  # 颜色只在预览中

# 不好的管道设计
fd -e ts |                   # 搜索所有深度
  sort |                     # 不必要的排序
  fzf |                      # 然后筛选
  grep -v "test"             # 过滤放在了后面

空字符分隔（处理含空格文件名）

# 错误：文件名含空格时会断裂
fd -e txt | xargs rm        # "my file.txt" 会被拆成两个参数

# 正确：使用 null 分隔
fd -e txt -0 | xargs -0 rm  # 安全处理任何文件名
fd -e txt --print0 | xargs -0 wc -l

# fzf 也支持 null 输入输出
fd -0 | fzf --read0 --print0 | xargs -0 vim

工具与生态

管道增强工具

工具 功能 管道角色
jq JSON 处理 结构化数据变换
yq YAML 处理 配置文件管道
sd 流式替换 替代 sed 的现代版
choose 字段提取 替代 awk/cut
hck 高性能 cut 大文件字段提取
procs 进程列表 结构化 ps 输出

调试管道

# 使用 tee 在管道中间查看数据
fd -e ts |
  tee /dev/stderr |       # 打印到 stderr（不影响管道）
  fzf |
  tee /dev/stderr |       # 查看选择结果
  xargs vim

# 使用 pv 查看管道吞吐量（需安装）
fd -e log -0 | pv -l | xargs -0 gzip

总结

现代 CLI 工具没有抛弃 Unix 管道哲学，而是在三个维度上增强了它：结构化输出让解析更精确，交互式节点让人可以在管道中做决策，并行执行让批量操作更快。掌握这些增强模式后，你可以用管道组合表达几乎任何复杂的文件/文本处理任务——这比编写一次性脚本更快、更直观、更可组合。管道思维的本质是「把复杂任务分解为简单步骤的串联」，这不仅是一种技术技能，更是一种问题解决思维方式。
