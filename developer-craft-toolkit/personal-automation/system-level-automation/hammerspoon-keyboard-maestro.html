Hammerspoon 与 Keyboard Maestro

概述

在 macOS 系统级自动化的领域，Hammerspoon 和 Keyboard Maestro 代表了两种截然不同的哲学。Hammerspoon 是一个开源的 Lua 脚本桥接引擎，将 macOS 的几乎所有系统 API 暴露给 Lua 脚本——它给了你一块空白画布和一套完整的颜料。Keyboard Maestro 则是一个商业化的可视化宏引擎，通过图形界面组合上百种预制动作——它像一个功能丰富的乐高套装。

两者都能实现窗口管理、应用控制、文本处理、系统事件响应等自动化，但路径截然不同。本文将对比两种范式的适用场景，并提供各自的实战配置。

核心概念

Hammerspoon 架构

Hammerspoon 的本质是一个 Lua 解释器 + macOS Accessibility/系统 API 绑定：

┌───────────────────────────────┐
│     你的 Lua 脚本 (init.lua)   │
├───────────────────────────────┤
│     Hammerspoon 核心引擎       │
│  ├── hs.window    窗口管理     │
│  ├── hs.hotkey    热键绑定     │
│  ├── hs.application 应用控制   │
│  ├── hs.eventtap  事件拦截     │
│  ├── hs.timer     定时任务     │
│  ├── hs.wifi      网络事件     │
│  ├── hs.usb       USB 设备     │
│  ├── hs.caffeinate 电源管理    │
│  └── hs.ipc       进程间通信   │
├───────────────────────────────┤
│     macOS System APIs          │
└───────────────────────────────┘

Keyboard Maestro 架构

Keyboard Maestro 的核心是宏（Macro）系统：

Macro Group (作用域: 全局/特定应用)
└── Macro (一个自动化单元)
    ├── Trigger (触发方式)
    │   ├── Hot Key
    │   ├── Typed String
    │   ├── Application Trigger
    │   ├── USB Device Trigger
    │   └── Cron Trigger
    └── Actions (执行序列)
        ├── Move Window
        ├── Type Text
        ├── Execute Shell Script
        ├── Set Variable
        ├── If/Then/Else
        └── Repeat

选型决策矩阵

维度 Hammerspoon Keyboard Maestro
编程模型 纯代码（Lua） 可视化 + 可嵌代码
学习曲线 需要编程能力 低，拖拽即用
扩展性 无限（Lua 能做的都行） 受限于预制动作集
版本控制 天然友好（文本文件） 困难（二进制格式）
调试体验 Console 实时反馈 内置动作日志
价格 免费开源 一次性购买 $36
UI 操作 需手动编写坐标/Accessibility 录制 + 图像识别
社区 GitHub + Lua 脚本分享 官方论坛 + 宏分享

实战指南

Hammerspoon 窗口管理系统

-- ~/.hammerspoon/init.lua

-- 窗口管理模块
local function moveWindow(position)
  local win = hs.window.focusedWindow()
  if not win then return end
  local screen = win:screen():frame()
  local f = win:frame()

  if position == "left" then
    f.x = screen.x
    f.y = screen.y
    f.w = screen.w / 2
    f.h = screen.h
  elseif position == "right" then
    f.x = screen.x + screen.w / 2
    f.y = screen.y
    f.w = screen.w / 2
    f.h = screen.h
  elseif position == "top" then
    f.x = screen.x
    f.y = screen.y
    f.w = screen.w
    f.h = screen.h / 2
  elseif position == "bottom" then
    f.x = screen.x
    f.y = screen.y + screen.h / 2
    f.w = screen.w
    f.h = screen.h / 2
  elseif position == "maximize" then
    f = screen
  elseif position == "center" then
    f.w = screen.w * 0.7
    f.h = screen.h * 0.8
    f.x = screen.x + (screen.w - f.w) / 2
    f.y = screen.y + (screen.h - f.h) / 2
  end

  win:setFrame(f)
end

-- Hyper Key 绑定（⌃⌥⌘⇧）
local hyper = {"ctrl", "alt", "cmd", "shift"}

hs.hotkey.bind(hyper, "h", function() moveWindow("left") end)
hs.hotkey.bind(hyper, "l", function() moveWindow("right") end)
hs.hotkey.bind(hyper, "k", function() moveWindow("top") end)
hs.hotkey.bind(hyper, "j", function() moveWindow("bottom") end)
hs.hotkey.bind(hyper, "m", function() moveWindow("maximize") end)
hs.hotkey.bind(hyper, "c", function() moveWindow("center") end)

Hammerspoon 应用级自动化

-- Wi-Fi 事件响应
local wifiWatcher = hs.wifi.watcher.new(function()
  local network = hs.wifi.currentNetwork()
  if network == "HomeNetwork" then
    hs.notify.show("Home Mode", "", "Switched to home configuration")
    -- 自动连接家庭 NAS
    os.execute("open smb://nas.local/shared")
  elseif network == "OfficeNetwork" then
    hs.notify.show("Work Mode", "", "Switched to work configuration")
    -- 启动工作应用
    hs.application.launchOrFocus("Slack")
    hs.application.launchOrFocus("Arc")
  end
end)
wifiWatcher:start()

-- USB 设备事件
local usbWatcher = hs.usb.watcher.new(function(data)
  if data.eventType == "added" and data.productName == "YubiKey" then
    hs.notify.show("YubiKey", "", "Security key connected")
  end
end)
usbWatcher:start()

-- 应用切换时自动调整输入法
local appInputMethod = {
  ["Code"] = "com.apple.inputmethod.SCIM.ITABC",
  ["Terminal"] = "com.apple.keylayout.ABC",
  ["Slack"] = "com.apple.inputmethod.SCIM.ITABC",
}

local appWatcher = hs.application.watcher.new(function(name, event, app)
  if event == hs.application.watcher.activated then
    local targetIM = appInputMethod[name]
    if targetIM then
      hs.keycodes.currentSourceID(targetIM)
    end
  end
end)
appWatcher:start()

Keyboard Maestro 实战配置

宏 1：智能文本处理管道

Trigger: Hot Key ⌃⌥T
Actions:
1. Set Variable "selectedText" to System Clipboard
2. Execute Shell Script:
   echo "$KMVAR_selectedText" | sed 's/  */ /g' | tr -d '\n'
3. Set System Clipboard to %ExecuteResult%
4. Display Text: "Cleaned: %ExecuteResult%"

宏 2：项目上下文切换

Trigger: Typed String ";proj"
Actions:
1. Prompt for User Input (dropdown: Project A/B/C)
2. If variable "projectChoice" = "Project A"
   a. Activate "Arc" → Open URL "project-a.notion.site"
   b. Activate "VS Code" → Menu "File > Open Recent > ~/projects/project-a"
   c. Activate "Terminal" → Type "cd ~/projects/project-a && clear"
3. Set Variable "currentProject" to "Project A"
4. Display Notification: "Switched to Project A"

宏 3：基于图像识别的 UI 自动化

Trigger: Hot Key ⌃⌥R
Actions:
1. If Image Found "approve-button.png" on screen
   a. Click Found Image
   b. Pause 1 second
   c. If Image Found "confirm-dialog.png"
      → Click Found Image
2. Else
   a. Display Alert "Approve button not found"

Hammerspoon 模块化组织

-- ~/.hammerspoon/init.lua (入口文件，保持精简)
require("modules.window")      -- 窗口管理
require("modules.hotkeys")     -- 全局热键
require("modules.watchers")    -- 系统事件监听
require("modules.caffeine")    -- 防休眠控制
require("modules.clipboard")   -- 剪贴板增强

-- 自动重载配置
hs.loadSpoon("ReloadConfiguration")
spoon.ReloadConfiguration:start()

Keyboard Maestro 组织原则

  1. Macro Groups 按应用分类：每个应用一个 Group，设置"仅在该应用活跃时启用"
  2. 全局 Group 保持精简：只放真正跨应用的操作
  3. 变量命名规范：Local_xxx 表示宏内变量，Global_xxx 表示跨宏共享
  4. 禁用而非删除：暂时不用的宏 Disable 而非删除，便于恢复

混合使用策略

很多高手同时使用两者，各取所长：

  • Hammerspoon：窗口管理、系统事件响应、网络/USB 监听
  • Keyboard Maestro：UI 自动化（图像识别）、Typed String 触发、复杂宏录制

它们可以互相调用：

-- Hammerspoon 调用 Keyboard Maestro 宏
hs.hotkey.bind(hyper, "x", function()
  hs.osascript.applescript([[
    tell application "Keyboard Maestro Engine"
      do script "My Complex Macro"
    end tell
  ]])
end)

总结

Hammerspoon 和 Keyboard Maestro 是 macOS 系统级自动化的两大支柱。选择取决于你的技术偏好和场景需求：

  1. 纯代码控制、版本管理友好 → Hammerspoon
  2. 快速构建、UI 交互自动化 → Keyboard Maestro
  3. 最强组合：Hammerspoon 处理系统事件 + Keyboard Maestro 处理 UI 操作
  4. Hammerspoon 的 Wi-Fi/USB/电源事件监听是独家能力
  5. Keyboard Maestro 的图像识别是自动化"最后手段"——当没有 API 可用时
  6. 两者的配置都应纳入备份体系（Hammerspoon 天然 Git 友好）
