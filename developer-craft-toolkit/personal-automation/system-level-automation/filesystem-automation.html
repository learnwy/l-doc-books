文件系统自动化

概述

文件系统是操作系统中最基础也最被忽视的自动化领域。每天你在 Downloads 文件夹里堆积的文件、散落在桌面的截图、需要按日期归档的文档——这些重复性的文件整理工作消耗着大量的微决策能量。文件系统自动化的目标是让文件"自己找到正确的位置"。

macOS 提供了从简单到复杂的完整文件自动化工具链：Hazel 的规则引擎适合非技术用户、launchd 定时任务适合系统级调度、FSEvents 文件监控适合需要实时响应的场景、Apple Shortcuts 的文件夹触发器则是 2026 年最新的系统原生方案。

核心概念

文件自动化模式分类

模式 触发方式 延迟 适用场景
事件驱动 文件系统事件（创建/修改/删除） 实时 下载完成即分类
轮询驱动 定时检查目录状态 周期性 每小时清理临时文件
手动触发 用户启动脚本 即时 批量重命名/整理
条件驱动 文件属性匹配规则 实时 大于 100MB 的文件移动到外置硬盘

文件分类决策树

设计文件自动路由时，需要考虑的属性维度：

文件到达
├── 按扩展名分类
│   ├── .pdf → Documents/PDFs/
│   ├── .png/.jpg → Pictures/
│   └── .zip/.tar → Archives/
├── 按来源分类
│   ├── Safari 下载 → Downloads/Web/
│   ├── AirDrop 接收 → Downloads/AirDrop/
│   └── 邮件附件 → Downloads/Mail/
├── 按大小分类
│   ├── > 1GB → 外置硬盘
│   └── < 1GB → 本地存储
├── 按日期分类
│   └── 按年/月归档 → Archive/2026/05/
└── 按内容分类（AI）
    ├── 发票 → Finance/Invoices/
    ├── 合同 → Legal/Contracts/
    └── 简历 → HR/Resumes/

macOS 文件系统事件机制

macOS 通过 FSEvents API 提供文件系统变更通知：

内核层: kqueue / FSEvents
    ↓
系统服务: fseventsd
    ↓
用户空间 API:
├── FSEventStream (高层 API, 目录级别)
├── kqueue (低层 API, 文件级别)
├── DispatchSource.makeFileSystemObjectSource (Swift)
└── NSFileCoordinator (跨进程协调)

实战指南

Hazel 规则引擎配置

Hazel 是 macOS 上最流行的规则驱动文件管理器，通过条件匹配自动执行操作：

规则 1：Downloads 文件夹自动分类

Folder: ~/Downloads

Rule: "Sort PDFs"
  Conditions: Extension is pdf
  Actions:
    1. Move to ~/Documents/PDFs/
    2. Add color label: Blue

Rule: "Sort Images"
  Conditions: Kind is Image
  Actions:
    1. Move to ~/Pictures/Screenshots/ (if name starts with "Screenshot")
    2. Move to ~/Pictures/Downloads/ (otherwise)

Rule: "Archive Old Files"
  Conditions:
    - Date Added is not in the last 7 days
    - Kind is not Folder
  Actions:
    1. Move to ~/Archive/{Year}/{Month}/
    2. Display notification "Archived: {name}"

Rule: "Large File Alert"
  Conditions: Size is greater than 500 MB
  Actions:
    1. Display notification "Large file: {name} ({size})"
    2. Add tag: "review-size"

规则 2：桌面零收件箱

Folder: ~/Desktop

Rule: "Clear Desktop Daily"
  Conditions:
    - Date Added is not today
    - Kind is not Folder
    - Name does not contain "keep"
  Actions:
    1. Move to ~/Desktop/Archive/{Date Added}/{name}
    2. If folder ~/Desktop/Archive/{Date Added} is new
       → Sort by Kind

launchd 定时任务

macOS 的 cron 替代品，支持精细的调度和条件触发：

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.user.cleanup-downloads</string>
    <key>ProgramArguments</key>
    <array>
        <string>/bin/bash</string>
        <string>/Users/you/scripts/cleanup-downloads.sh</string>
    </array>
    <key>StartCalendarInterval</key>
    <dict>
        <key>Hour</key>
        <integer>2</integer>
        <key>Minute</key>
        <integer>0</integer>
    </dict>
    <key>StandardOutPath</key>
    <string>/tmp/cleanup-downloads.log</string>
    <key>StandardErrorPath</key>
    <string>/tmp/cleanup-downloads.err</string>
</dict>
</plist>

对应的清理脚本：

#!/bin/bash
# ~/scripts/cleanup-downloads.sh

DOWNLOADS=~/Downloads
ARCHIVE=~/Archive/Downloads/$(date +%Y/%m)

mkdir -p "$ARCHIVE"

# 移动超过 14 天的文件
find "$DOWNLOADS" -maxdepth 1 -type f -mtime +14 -exec mv {} "$ARCHIVE/" \;

# 删除空目录
find "$DOWNLOADS" -maxdepth 1 -type d -empty -delete

# 记录日志
echo "$(date): Cleaned up $(ls "$ARCHIVE" | wc -l) files" >> ~/logs/cleanup.log

安装 launchd 任务：

cp com.user.cleanup-downloads.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.user.cleanup-downloads.plist

FSEvents 实时监控脚本

使用 fswatch 工具实现实时文件监控：

#!/bin/bash
# ~/scripts/watch-downloads.sh

WATCH_DIR=~/Downloads

fswatch -0 --event Created "$WATCH_DIR" | while read -d "" event; do
  filename=$(basename "$event")
  extension="${filename##*.}"

  case "$extension" in
    pdf)
      mv "$event" ~/Documents/PDFs/
      osascript -e "display notification \"$filename → PDFs\" with title \"File Sorted\""
      ;;
    png|jpg|jpeg|gif)
      mv "$event" ~/Pictures/Downloads/
      ;;
    zip|tar|gz|7z)
      mv "$event" ~/Downloads/Archives/
      ;;
  esac
done

Apple Shortcuts 文件夹触发器（macOS 26）

最新的原生方案，无需第三方工具：

Automation Trigger: Folder (~/Downloads, when files are added)

1. Get [Shortcut Input]
2. Get Details of [file]: File Extension
3. If [extension] is "pdf"
   → Move [file] to ~/Documents/PDFs/
4. Otherwise If [extension] is any of ["png", "jpg", "heic"]
   → If [file size] > 5 MB
     → Move to ~/Pictures/Large/
   → Otherwise
     → Move to ~/Pictures/Downloads/
5. Otherwise If [file size] > 500 MB
   → Show Alert "Large file downloaded: [name]"
   → Move to ~/Downloads/Large/
6. Show Notification "Sorted: [name]"

最佳实践

文件命名规范

自动化的前提是可预测的命名。建立命名规范：

标准格式: YYYY-MM-DD_category_description.ext

示例:
  2026-05-08_invoice_aws-monthly.pdf
  2026-05-08_receipt_coffee-shop.jpg
  2026-05-08_screenshot_bug-report.png

批量重命名脚本：

#!/bin/bash
# 将无规律文件名转换为标准格式
for file in ~/Downloads/*.pdf; do
  date=$(stat -f "%Sm" -t "%Y-%m-%d" "$file")
  newname="${date}_unsorted_$(basename "$file")"
  mv "$file" ~/Documents/Inbox/"$newname"
done

防误操作设计

  • 预览模式：先 echo 操作而非直接执行，确认无误后再 mv
  • 回收站机制：移动到 .trash/ 而非直接删除，保留 30 天
  • 排除规则：永远不触碰 .git、node_modules、.env 文件
  • 文件锁检测：处理前检查文件是否被占用（lsof）

性能考量

  • 避免监控整个 home 目录：限定到具体文件夹
  • 防抖处理：大文件下载过程中会产生大量 FSEvents，等待文件写入完成
  • 资源限制：设置最大并行处理数，避免 CPU 尖峰
  • 日志轮转：定期清理自动化产生的日志文件

云同步与文件自动化

注意文件自动化与云同步的交互：

  • iCloud Drive：移动文件可能触发大量同步
  • Dropbox：Smart Sync 的"仅在线"文件不能被本地脚本处理
  • 策略：自动化规则应排除云同步的占位符文件

监控与告警

# 简单的健康检查：确保自动化仍在运行
if ! pgrep -f "watch-downloads.sh" > /dev/null; then
  osascript -e 'display notification "File watcher stopped!" with title "Automation Alert"'
  # 自动重启
  nohup ~/scripts/watch-downloads.sh &
fi

总结

文件系统自动化是"set and forget"型自动化的最佳代表——一次配置，长期受益。核心原则：

  1. Hazel 是大多数用户的最佳起点——规则引擎强大且零代码
  2. macOS 26 的 Shortcuts 文件夹触发器是免费的原生替代
  3. 建立文件命名规范是自动化的前提条件
  4. 防误操作设计（预览模式 + 回收站）是必须的安全网
  5. 不要监控过大的目录范围——精准定位到具体文件夹
  6. launchd 比 cron 更适合 macOS——它理解系统睡眠/唤醒状态
