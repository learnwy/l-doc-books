Alfred Workflows 实战

概述

Alfred 是 macOS 平台上历史最悠久的效率启动器，其 Workflow 系统自 2012 年推出以来已形成了庞大的生态。与 Raycast 的代码优先理念不同，Alfred Workflows 采用可视化节点编排模型——通过拖拽连接 Trigger、Input、Action 和 Output 节点来构建自动化逻辑。这种设计让非程序员也能快速构建复杂流程，同时为开发者保留了通过 Script Filter 和外部脚本深度定制的能力。

Alfred 5（2024 年至今的主力版本）在性能、Universal Actions 和 Automation Tasks 方面做了大量改进。本文将系统讲解 Workflow 的架构原理与高效构建方法。

核心概念

Workflow 节点模型

Alfred Workflow 的本质是一个有向无环图（DAG），由以下四类节点组成：

Trigger → Input → Action → Output

├── Hotkey          ├── Script Filter    ├── Run Script      ├── Post Notification
├── Keyword         ├── File Filter      ├── Open File       ├── Copy to Clipboard
├── Remote          ├── List Filter      ├── Open URL        ├── Write Text File
├── Snippet         │                    ├── Run NSAppleScript├── Play Sound
├── External        │                    ├── Terminal Command │
└── File Action     │                    └── Automation Task  │

Script Filter 协议

Script Filter 是 Alfred 最强大的 Input 节点，它通过 JSON 协议与外部脚本通信：

{
  "items": [
    {
      "uid": "unique-id",
      "title": "显示标题",
      "subtitle": "副标题描述",
      "arg": "传递给下游节点的参数",
      "icon": { "path": "icon.png" },
      "mods": {
        "cmd": { "subtitle": "⌘ 按下时的替代操作", "arg": "alt-arg" },
        "alt": { "subtitle": "⌥ 按下时的替代操作", "arg": "alt-arg2" }
      },
      "valid": true,
      "autocomplete": "自动补全文本"
    }
  ],
  "rerun": 1.0
}

关键字段说明：

  • uid：结果唯一标识，Alfred 用它学习用户偏好排序
  • arg：动作参数，传递给连接的 Action 节点
  • mods：修饰键变体，允许一个结果关联多个操作
  • rerun：秒数，Script Filter 会自动重新执行（适合轮询）

变量与数据流

Alfred 的变量系统分为三个作用域：

作用域 生命周期 设置方式
Workflow Environment 全局持久 Workflow 配置面板
Flow Variables 单次执行 {var:name} 占位符
Script Output 节点间传递 stdout / JSON

在脚本中设置流变量：

# 通过特殊 JSON 输出设置变量
cat << EOF
{"alfredworkflow": {
  "arg": "result",
  "variables": {"token": "abc123", "count": "42"}
}}
EOF

实战指南

构建一个项目切换器 Workflow

这个 Workflow 实现：输入关键字快速切换到任意代码项目目录并打开 IDE。

Step 1：创建 Script Filter

语言选择 /bin/bash，脚本内容：

# 搜索 ~/Projects 下的所有 git 仓库
query="$1"
items=""

while IFS= read -r dir; do
  name=$(basename "$dir")
  if [[ "$name" == *"$query"* ]] || [[ -z "$query" ]]; then
    items+="{\"title\":\"$name\",\"subtitle\":\"$dir\",\"arg\":\"$dir\",\"icon\":{\"path\":\"folder.png\"}},"
  fi
done < <(find ~/Projects -maxdepth 2 -name ".git" -type d | sed 's/\/.git$//')

echo "{\"items\":[${items%,}]}"

Step 2：连接 Action 节点

从 Script Filter 输出连接两个 Action：

  1. Run Script（默认回车）：code "{query}" 在 VS Code 打开
  2. Terminal Command（⌘+回车）：cd "{query}" && exec $SHELL 打开终端

Step 3：添加 Hotkey Trigger

设置 ⌥+P 作为全局热键，直接唤出项目列表。

外部脚本集成模式

对于复杂逻辑，推荐将核心逻辑写在独立脚本中：

#!/usr/bin/env python3
"""Alfred Script Filter: 搜索 Notion 数据库"""
import json
import sys
import urllib.request

query = sys.argv[1] if len(sys.argv) > 1 else ""
NOTION_TOKEN = os.environ.get("NOTION_TOKEN", "")
DATABASE_ID = os.environ.get("DATABASE_ID", "")

def search_notion(query):
    url = f"https://api.notion.com/v1/databases/{DATABASE_ID}/query"
    headers = {
        "Authorization": f"Bearer {NOTION_TOKEN}",
        "Notion-Version": "2022-06-28",
        "Content-Type": "application/json"
    }
    payload = json.dumps({
        "filter": {"property": "Name", "title": {"contains": query}}
    }).encode()

    req = urllib.request.Request(url, data=payload, headers=headers, method="POST")
    with urllib.request.urlopen(req) as resp:
        return json.loads(resp.read())

results = search_notion(query)
items = []
for page in results.get("results", []):
    title = page["properties"]["Name"]["title"][0]["plain_text"]
    url = page["url"]
    items.append({"title": title, "arg": url, "subtitle": "Open in Notion"})

print(json.dumps({"items": items}))

Automation Tasks（Alfred 5+）

Alfred 5 引入了 Automation Tasks，可直接调用 macOS 系统能力：

  • 剪贴板操作（获取/设置/清空）
  • 文件操作（移动/重命名/压缩）
  • 系统控制（暗黑模式/音量/亮度）
  • 通知中心（发送通知/设置勿扰）

这些 Task 无需编写脚本即可作为 Action 节点使用。

最佳实践

性能优化

  • 缓存结果：对不频繁变化的数据（如项目列表），写入 ~/Library/Caches/com.runningwithcrayons.Alfred/Workflow Data/
  • 增量搜索：使用 rerun 字段实现打字即搜，避免每次都执行完整查询
  • 延迟加载：对耗时操作使用 valid: false 先展示占位项，后续通过 rerun 更新

Workflow 设计原则

  1. 单一职责：每个 Workflow 解决一个明确问题
  2. 渐进式发现：基础功能用关键字触发，高级功能通过修饰键暴露
  3. 容错设计：脚本中处理网络失败、空结果等边界情况
  4. 变量隔离：敏感信息（API Key）放在 Workflow Environment Variables 中

分发与版本管理

  • 使用 .alfredworkflow 格式导出（本质是 zip）
  • 通过 GitHub Release 分发，附带 info.plist 的 README
  • 版本号遵循语义化版本，写在 Workflow 配置的 version 字段

总结

Alfred Workflow 的核心价值在于它的可视化编排范式——你可以像搭积木一样组装自动化逻辑，同时在需要时嵌入任意复杂度的脚本代码。关键收获：

  1. 掌握 Script Filter 的 JSON 协议是解锁 Alfred 高级能力的钥匙
  2. 利用修饰键（cmd/alt/ctrl/shift）为单个结果提供多维操作
  3. 将核心逻辑封装在独立脚本文件中，便于版本控制和调试
  4. Automation Tasks 是无代码实现系统级操作的最快路径
  5. 选择 Alfred 还是 Raycast 取决于你更偏好可视化编排还是代码控制
