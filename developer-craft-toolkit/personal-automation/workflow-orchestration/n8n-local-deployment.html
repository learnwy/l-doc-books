n8n 本地部署与编排

概述

n8n 是 2026 年最受技术团队欢迎的开源工作流自动化平台，在 GitHub 上拥有超过 186,000 颗星。它的核心定位是"开发者优先的自动化工具"——既提供可视化画布进行拖拽编排，又允许在任何节点中嵌入 JavaScript/Python 代码。与 Zapier、Make 等 SaaS 平台相比，n8n 的自托管模式意味着：无执行次数限制、完整数据所有权、以及深度定制能力。

本文将带你从零搭建一个生产级的 n8n 本地实例，并深入其工作流编排的核心机制。

核心术语

概念 说明

Execution Workflow 的一次运行实例
Credential 存储 API 密钥等敏感信息的加密容器
Webhook 接收外部 HTTP 请求的触发端点
Expression 节点间数据引用的语法（{{ $json.field }}）

数据流模型

n8n 中数据以 JSON 数组的形式在节点间流动。每个节点接收上游的 items[]，处理后输出新的 items[]：

// 每个 item 的结构
interface INodeExecutionData {
  json: Record<string, unknown>; // 主数据
  binary?: Record<string, IBinaryData>; // 二进制附件
  pairedItem?: { item: number }; // 上游关联
}

关键数据操作模式：

  • 映射（Map）：对每个 item 变换字段
  • 过滤（Filter）：根据条件保留或丢弃 item
  • 聚合（Aggregate）：多个 item 合并为一个
  • 拆分（Split）：一个 item 展开为多个

实战指南

Docker Compose 部署

生产级部署推荐使用 Docker Compose + PostgreSQL：

# docker-compose.yml
version: '3.8'

services:
  n8n:
    image: n8nio/n8n:latest
    restart: always
    ports:
      - '5678:5678'
    environment:
      - N8N_HOST=automation.yourdomain.com
      - N8N_PORT=5678
      - N8N_PROTOCOL=https
      - GENERIC_TIMEZONE=Asia/Shanghai
      - DB_TYPE=postgresdb
      - DB_POSTGRESDB_HOST=postgres
      - DB_POSTGRESDB_PORT=5432
      - DB_POSTGRESDB_USER=n8n
      - DB_POSTGRESDB_PASSWORD=${POSTGRES_PASSWORD}
      - DB_POSTGRESDB_DATABASE=n8n
      - N8N_ENCRYPTION_KEY=${ENCRYPTION_KEY}
      - EXECUTIONS_DATA_SAVE_ON_SUCCESS=none
      - EXECUTIONS_DATA_SAVE_ON_ERROR=all
      - EXECUTIONS_DATA_PRUNE=true
      - EXECUTIONS_DATA_MAX_AGE=168
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      - postgres

  postgres:
    image: postgres:16
    restart: always
    environment:
      - POSTGRES_USER=n8n
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
      - POSTGRES_DB=n8n
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  n8n_data:
  postgres_data:

环境变量文件：

# .env
POSTGRES_PASSWORD=your_secure_password_here
ENCRYPTION_KEY=your_32_char_encryption_key_here

启动命令：

docker compose up -d
# 验证运行状态
docker compose ps
# 查看日志
docker compose logs -f n8n

SSL 配置（Caddy 反向代理）

# Caddyfile
automation.yourdomain.com {
    reverse_proxy localhost:5678
}

Caddy 会自动申请和续期 Let's Encrypt 证书。

队列模式（水平扩展）

当工作流执行量增大时，启用队列模式：

# 追加到 docker-compose.yml
services:
  n8n:
    environment:
      - EXECUTIONS_MODE=queue
      - QUEUE_BULL_REDIS_HOST=redis
      - QUEUE_HEALTH_CHECK_ACTIVE=true

  n8n-worker:
    image: n8nio/n8n:latest
    command: worker
    environment:
      # 与主实例共享相同的数据库和 Redis 配置
      - EXECUTIONS_MODE=queue
      - QUEUE_BULL_REDIS_HOST=redis
    depends_on:
      - redis
      - postgres

  redis:
    image: redis:7-alpine
    restart: always
    volumes:
      - redis_data:/data

构建第一个工作流

场景：GitHub Star 事件 → Slack 通知 + Notion 记录

  1. 添加 Trigger 节点：GitHub Trigger → 监听 star 事件
  2. 添加 Function 节点：格式化消息
// Function 节点代码
const repo = $input.first().json.repository.full_name;
const user = $input.first().json.sender.login;
const stars = $input.first().json.repository.stargazers_count;

return [
  {
    json: {
      message: `⭐ ${user} starred ${repo} (total: ${stars})`,
      repo,
      user,
      stars,
      timestamp: new Date().toISOString(),
    },
  },
];
  1. 添加 Slack 节点：发送到指定频道
  2. 添加 Notion 节点：创建数据库记录

错误处理与重试

// 在 Function 节点中实现重试逻辑
const maxRetries = 3;
let attempt = 0;

while (attempt < maxRetries) {
  try {
    const response = await $http.request({
      method: 'POST',
      url: 'https://api.example.com/data',
      body: $input.first().json,
    });
    return [{ json: response }];
  } catch (error) {
    attempt++;
    if (attempt === maxRetries) throw error;
    await new Promise((r) => setTimeout(r, 1000 * attempt));
  }
}

最佳实践

工作流组织策略

  • 命名规范：[Domain] Action - Detail，如 [GitHub] Stars → Notify Slack
  • 标签分类：按领域（DevOps、Marketing、HR）或状态（Active、Draft、Archived）
  • 子工作流：将可复用逻辑封装为子工作流，通过 Execute Workflow 节点调用
  • 版本管理：导出 JSON 纳入 Git 管理，配合 CI/CD 自动部署

安全加固

  1. 加密密钥：设置 N8N_ENCRYPTION_KEY 保护 Credential 存储
  2. 基础认证：在反向代理层添加额外认证
  3. 网络隔离：n8n 容器仅暴露必要端口
  4. 定期备份：pg_dump 定时备份数据库 + 卷快照

性能优化

  • 对大数据量使用 Batch 节点分批处理
  • 避免在 Function 节点中使用同步阻塞操作
  • 设置 EXECUTIONS_DATA_SAVE_ON_SUCCESS=none 减少数据库写入
  • 使用 PostgreSQL 而非 SQLite（SQLite 不支持并发写入）

备份策略

#!/bin/bash
# backup.sh - 每日执行
DATE=$(date +%Y%m%d)
BACKUP_DIR=/backups/n8n

# 备份 PostgreSQL
docker exec postgres pg_dumpall -c -U n8n > $BACKUP_DIR/pg_$DATE.sql

# 备份 n8n 数据卷
docker run --rm -v n8n_data:/data -v $BACKUP_DIR:/backup \
  alpine tar czf /backup/n8n_data_$DATE.tar.gz /data

# 保留最近 30 天
find $BACKUP_DIR -mtime +30 -delete

监控方案

  • 健康检查：GET /healthz 端点返回 200
  • 执行监控：定期查询执行历史中的失败记录
  • 资源监控：Docker stats + Prometheus exporter

总结

n8n 自托管是个人和小团队实现无限自动化的最具性价比方案。Docker Compose 部署在 10 分钟内即可完成，PostgreSQL 提供了可靠的数据持久化，队列模式则为未来扩展留出了空间。核心要点：

  1. 生产环境必须使用 PostgreSQL + 加密密钥 + SSL
  2. 用子工作流和标签实现工作流的模块化管理
  3. 错误处理不是可选项——为每个外部 API 调用添加重试逻辑
  4. 定期备份数据库和数据卷是运维底线
  5. LangChain 原生集成使 n8n 成为 AI Agent 编排的理想平台
