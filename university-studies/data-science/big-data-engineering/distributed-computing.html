分布式计算框架

知识要点

分布式计算是将计算任务分解到多台机器上并行执行的技术范式。当数据规模超出单机处理能力时，分布式计算成为唯一可行的方案。核心挑战在于将数据并行和计算并行有效结合，同时处理网络通信、节点故障和数据一致性。

计算模式 代表框架 适用场景 延迟
批处理 MapReduce, Spark ETL、模型训练 分钟-小时
微批处理 Spark Streaming 准实时聚合 秒级
流处理 Flink, Kafka Streams 实时风控、推荐 毫秒-秒级
交互查询 Presto, SparkSQL Ad-hoc 分析 秒-分钟

详细讲解

MapReduce 编程模型

MapReduce 由 Google 在 2004 年提出，Hadoop 将其开源实现。核心思想是将计算分为 Map（分散处理）和 Reduce（聚合结果）两个阶段，中间由框架自动完成 Shuffle（按 Key 排序和分组）。

以词频统计为例：Map 将每行文本拆为 (word,1)(word, 1)(word,1) 对；Shuffle 将相同单词的计数收集在一起；Reduce 对每个单词求和。MapReduce 的局限包括：复杂计算需要链式串联多个 Job，中间结果写入磁盘带来高 I/O 开销，不适合迭代计算（如机器学习算法）。

Hadoop 生态

HDFS 是底层分布式文件系统。文件被切分为固定大小的块（默认 128 MB），每个块复制 3 份存储在不同节点上。NameNode 管理元数据，DataNode 存储数据块。

YARN 是资源调度层。ResourceManager 全局调度，NodeManager 管理节点资源，ApplicationMaster 协调单个应用。YARN 使同一集群可运行 MapReduce、Spark、Flink 等多种引擎。

Spark 核心

Spark 通过内存计算将迭代任务提速 10-100 倍。核心抽象是 RDD（Resilient Distributed Dataset），支持惰性求值和谱系容错。操作分为 Transformation（如 map、filter，返回新 RDD，不立即执行）和 Action（如 count、collect，触发计算）。

DataFrame API 提供了结构化数据接口，支持 Catalyst 查询优化器和 Tungsten 执行引擎。SparkSQL 允许用 SQL 查询分布式数据，支持 Hive 表、Parquet、JSON 等数据源，是最常用的 Spark 接口。

流处理

Spark Streaming 采用微批模式，将数据流切分为小时间窗口处理。优点是复用 Spark 生态，缺点是延迟受限于窗口大小。

Apache Flink 是逐条流处理引擎，以事件时间为基准，支持精确一次语义。核心概念包括 DataStream API、窗口函数（滚动、滑动、会话窗口）和 Checkpointing 状态管理机制。

容错机制

分布式系统中节点故障是常态。HDFS 通过 3 副本容忍存储故障。Spark 通过 RDD 谱系信息重新计算丢失分区。Flink 使用 Chandy-Lamport 分布式快照算法周期保存检查点，故障时从最近检查点恢复。

练习与思考

  1. 用伪代码实现 MapReduce 词频统计。Map 输出 (word,1)(word, 1)(word,1)，Reduce 输出 (word,count)(word, count)(word,count)。

  2. 比较 Spark RDD 和 Pandas DataFrame 的异同。在什么数据规模下应从 Pandas 切换到 Spark？

  3. 电商平台需要实时统计每分钟的订单量和 GMV。你会选择 Spark Streaming 还是 Flink？说明理由。

  4. 画出 3 节点 HDFS 集群的数据块分布图：一个 256 MB 文件（2 块），每块 3 副本。当一个 DataNode 宕机时如何恢复？

拓展阅读

  • Tom White,《Hadoop 权威指南》——Hadoop 生态的全面参考
  • Holden Karau,《Spark 快速大数据分析》——Spark 实战入门
  • Fabian Hueske,《Flink 基础教程》——流处理原理和 Flink 实践
  • Martin Kleppmann,《数据密集型应用系统设计》——分布式系统设计原则

小结

分布式计算框架是大数据工程的基石。从 MapReduce 到 Spark 的内存计算，再到 Flink 的实时流处理，框架演进围绕降低延迟、提升吞吐、简化编程三个目标。理解核心原理和适用场景是大数据工程师的必备能力。下一步可深入学习特定框架的高级特性和性能调优。
