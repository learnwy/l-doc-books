数据存储系统

知识要点

数据存储系统是大数据工程的基础设施层，负责持久化、组织和高效访问海量数据。不同的数据特征和访问模式要求不同的存储方案。选择合适的存储系统是数据工程师最重要的架构决策之一。

存储类型 数据模型 适用场景 代表系统
关系型数据库 表/行/列 事务处理、结构化查询 MySQL, PostgreSQL
文档数据库 JSON 文档 灵活 schema、内容管理 MongoDB
键值存储 Key-Value 缓存、会话管理 Redis, DynamoDB
列族存储 列族/行键 海量写入、时序数据 HBase, Cassandra
列式分析引擎 列式存储 OLAP 分析查询 ClickHouse, Druid

详细讲解

关系型数据库

MySQL 和 PostgreSQL 是最广泛使用的关系型数据库。它们基于关系模型（Relational Model），通过 SQL 语言操作，核心保证 ACID 事务特性（原子性、一致性、隔离性、持久性）。

MySQL 以高性能和易用性著称，是 Web 应用的默认选择。PostgreSQL 功能更丰富，支持 JSON、GIS、全文搜索等高级特性，在数据分析场景中更受青睐。关系型数据库的瓶颈在于垂直扩展的天花板——单机性能有限，水平分片（Sharding）增加了运维复杂度。

NoSQL 数据库

NoSQL 数据库放弃了关系模型的某些约束（如严格 schema、全局事务），换取更高的扩展性和灵活性。

MongoDB 以 JSON（实际是 BSON）文档为存储单元，每个文档可以有不同的字段结构（Schema-less），非常适合快速迭代的应用开发。支持丰富的查询语言、二级索引和聚合管道。

Redis 是内存键值存储，延迟可达微秒级。除基本的 Key-Value 操作外，还支持列表、集合、有序集合、哈希等丰富的数据结构。常用于缓存、排行榜、消息队列和分布式锁。

Cassandra 是面向写入优化的分布式列族数据库，采用去中心化架构（无单点故障），支持多数据中心部署。写入吞吐极高，适合物联网传感器数据、日志收集等写多读少的场景。

列式存储与 OLAP 引擎

传统行式存储按行组织数据，适合事务处理（OLTP）。列式存储按列组织数据，在分析查询（OLAP）中优势明显：只需读取查询涉及的列，大幅减少 I/O；同一列数据类型相同，压缩率更高。

HBase 是 Hadoop 生态的列族存储，构建在 HDFS 之上，支持亿级行数的随机读写。适合需要快速点查的海量数据存储。

ClickHouse 是 Yandex 开源的列式分析引擎，查询性能极强（亿级数据秒级响应），被广泛用于实时分析、用户行为分析和日志查询。

数据湖

数据湖（Data Lake）以原始格式存储海量数据（结构化、半结构化、非结构化），"先存储后处理"。与数据仓库的"先建模后加载"思路相反。

Delta Lake（Databricks）在 Parquet 文件之上增加了 ACID 事务、Schema 演化和时间旅行（Time Travel）能力。Apache Iceberg 和 Apache Hudi 提供了类似的表格式抽象，支持增量处理和高效的元数据管理。

数据湖解决了传统数据仓库 schema 僵化、无法存储非结构化数据的问题，但如果治理不当会退化为"数据沼泽"——数据堆积但无法有效利用。

数据仓库

数据仓库（Data Warehouse）面向分析场景，存储清洗和建模后的结构化数据。

Hive 是 Hadoop 生态的数据仓库，用 SQL 接口查询 HDFS 上的数据。适合离线批量分析，但查询延迟较高（分钟级）。Snowflake 是云原生数据仓库，计算与存储分离，按需弹性伸缩，支持多种云平台。BigQuery（Google）、Redshift（AWS）也是主流的云数据仓库选择。

存储格式

大数据存储格式直接影响查询性能和存储成本。

Parquet 是列式存储格式，支持嵌套数据结构和高效压缩，是 Spark 生态的默认格式。ORC（Optimized Row Columnar）是 Hive 优化的列式格式，压缩率更高，在 Hive 生态中性能最优。Avro 是行式存储格式，支持 Schema 演化，常用于 Kafka 消息序列化和数据交换。

练习与思考

  1. 设计一个电商平台的存储架构：用户信息用什么数据库？购物车数据用什么？商品搜索用什么？订单分析用什么？说明每个选择的理由。

  2. 比较 MySQL 和 MongoDB 在存储用户个人资料时的 Schema 设计差异。当需要增加一个新字段"社交账号列表"时，两者各需要做什么操作？

  3. 同一份 1 GB 的 CSV 数据，分别转换为 Parquet 和 JSON 格式，预估各自的文件大小和典型查询（SELECT 3 列 WHERE 1 列）的性能差异。

  4. 比较数据湖和数据仓库的适用场景。一个创业公司在数据基础设施初期应该选择哪种？为什么？

拓展阅读

  • Martin Kleppmann,《数据密集型应用系统设计》——存储引擎原理的深入讲解
  • Bill Inmon,《数据仓库》——数据仓库之父的经典著作
  • 林子雨,《大数据技术原理与应用》——国内大数据技术的系统教材

小结

数据存储系统的选择没有银弹，需要根据数据特征（结构化程度、规模、更新频率）和访问模式（事务 vs 分析、点查 vs 扫描、延迟要求）做出权衡。理解不同存储系统的设计取舍是大数据架构设计的核心能力。下一步可深入学习数据建模方法和存储系统的性能调优。
