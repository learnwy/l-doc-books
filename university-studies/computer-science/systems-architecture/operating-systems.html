大学计算机科学与技术 — 操作系统

知识要点

操作系统（Operating System, OS）是计算机系统中最核心的系统软件，充当硬件资源与上层应用之间的抽象层和管理者。它的两大使命是：为应用程序提供简洁一致的硬件抽象接口，以及在多个程序之间公平高效地分配 CPU、内存、磁盘和网络等有限资源。从单用户批处理到现代容器化微服务，操作系统的演进映射了半个世纪以来计算模式的根本性变革。

操作系统的核心子系统包括进程管理、内存管理、文件系统和 I/O 系统。每个子系统都体现了系统设计中经典的权衡：简单性与功能性、公平性与效率、安全隔离与资源共享。

子系统 核心抽象 关键机制 典型挑战
进程管理 进程/线程 调度、上下文切换、IPC 死锁、饥饿、优先级反转
内存管理 虚拟地址空间 分页、TLB、页面置换 碎片、抖动、安全隔离
文件系统 文件/目录 inode、日志、缓存 一致性、崩溃恢复、性能
I/O 系统 设备文件 中断、DMA、缓冲 延迟、吞吐、驱动兼容

详细讲解

进程与线程

进程是操作系统中资源分配的基本单位，是程序的一次运行实例。每个进程拥有独立的地址空间、文件描述符表和信号处理器。进程的状态在就绪（Ready）、运行（Running）和阻塞（Blocked）之间转换。

线程是 CPU 调度的基本单位，同一进程内的线程共享地址空间和文件描述符，但各自拥有独立的栈和寄存器上下文。上下文切换的代价：进程级切换需要刷新 TLB 和页表基址（CR3 寄存器），开销约 1-10  μs1\text{-}10\;\mu\text{s}1-10μs；线程级切换仅保存/恢复寄存器，开销约 0.1-1  μs0.1\text{-}1\;\mu\text{s}0.1-1μs。

CPU 调度算法决定哪个就绪进程获得 CPU：

算法 类型 特点 适用场景
FCFS 非抢占 简单但可能引起护航效应 批处理
SJF 非抢占/抢占 最优平均等待时间 已知作业长度
Round Robin 抢占 公平，响应时间取决于时间片 qqq 分时系统
MLFQ 抢占 多级反馈，自适应优先级 通用 OS
CFS 抢占 红黑树维护虚拟运行时间 Linux

Linux 的 完全公平调度器（CFS）使用虚拟运行时间（vruntime）概念：每个进程累计的 vruntime 按其权重反比增长，调度器总是选择 vruntime 最小的进程执行。对于权重为 wiw_iwi​ 的进程，其 vruntime 的增长率为：

Δvruntimei=Δt×w0wi\Delta\text{vruntime}_i = \Delta t \times \frac{w_0}{w_i}Δvruntimei​=Δt×wi​w0​​

其中 w0w_0w0​ 是基准权重（nice 0 对应的权重）。CFS 使用红黑树维护所有就绪进程，选择和插入操作均为 O(log⁡n)O(\log n)O(logn)。

内存管理与虚拟内存

现代操作系统通过虚拟内存为每个进程提供独立的、连续的地址空间假象。核心机制是分页（Paging）：虚拟地址被分割为固定大小的页（通常 4KB），通过页表映射到物理页框。

对于 64 位系统，直接使用单级页表需要 2522^{52}252 个页表项（假设 4KB 页），显然不可行。多级页表通过按需分配解决此问题。x86-64 使用 4 级页表：PML4 → PDPT → PD → PT，每级 29=5122^9 = 51229=512 个条目。

TLB（Translation Lookaside Buffer）是页表的硬件缓存，命中率通常 >99%> 99\%>99%。TLB 未命中时需要进行页表遍历（Page Table Walk），在 4 级页表下需要 4 次内存访问。

页面置换算法决定内存不足时淘汰哪个页面：

  • OPT（最优）：淘汰未来最久不被使用的页面。理论最优但不可实现，作为基准。
  • LRU（最近最少使用）：淘汰最久未被访问的页面。精确实现代价高（需要时间戳排序），Linux 使用近似 LRU 的 Clock 算法。
  • Clock（时钟）：使用引用位的循环扫描，未引用则淘汰，已引用则清零并跳过。实现简单，性能接近 LRU。

工作集模型描述了进程在时间窗口 Δ\DeltaΔ 内访问的页面集合 W(t,Δ)W(t, \Delta)W(t,Δ)。操作系统应确保每个进程的工作集驻留在内存中，否则会发生抖动（Thrashing）——系统大部分时间在处理缺页中断，有效吞吐急剧下降。

文件系统

文件系统将物理存储设备上的连续块组织为层次化的文件和目录结构。

Unix 文件系统的核心是 inode（索引节点），每个文件对应一个 inode，包含文件的元数据（大小、权限、时间戳）和数据块指针。为了支持不同大小的文件，inode 使用多级索引：

指针类型 数量 可寻址大小（4KB 块）
直接指针 12 48  KB48\;\text{KB}48KB
一级间接 1 4  MB4\;\text{MB}4MB
二级间接 1 4  GB4\;\text{GB}4GB
三级间接 1 4  TB4\;\text{TB}4TB

日志文件系统（如 ext4、NTFS）通过先将元数据修改写入日志再应用到磁盘，保证了崩溃一致性。日志策略分为三种：

  • Journal：数据和元数据都写日志，最安全但性能最低
  • Ordered：仅元数据写日志，数据先于元数据写入，平衡安全与性能
  • Writeback：仅元数据写日志，不保证数据先写，性能最高但可能丢数据

现代文件系统 Btrfs 和 ZFS 引入了写时复制（CoW）、校验和、快照和内置 RAID 等特性，将传统文件系统、卷管理和数据保护功能融为一体。

并发控制与同步

多线程共享资源时需要同步机制防止竞态条件。核心原语：

  • 互斥锁（Mutex）：保护临界区，同一时刻仅一个线程可持有
  • 信号量（Semaphore）：计数型同步原语，PPP 操作（等待）减计数，VVV 操作（信号）加计数
  • 条件变量：配合互斥锁使用，线程可在条件不满足时阻塞等待

死锁需要同时满足四个必要条件（Coffman 条件）：互斥、持有并等待、不可抢占、循环等待。打破任一条件即可防止死锁。银行家算法通过模拟资源分配检测安全状态，时间复杂度 O(n2m)O(n^2 m)O(n2m)，其中 nnn 为进程数，mmm 为资源类型数。

练习与思考

  1. 在 Round Robin 调度中，时间片 qqq 的选择如何影响系统性能？若 q→∞q \to \inftyq→∞ 退化为什么算法？若 q→0q \to 0q→0 又会出现什么问题？

  2. 一个系统有 3 个物理页框，访问序列为 1,2,3,4,1,2,5,1,2,3,4,51, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 51,2,3,4,1,2,5,1,2,3,4,5。分别用 FIFO 和 LRU 算法模拟页面置换过程，计算各自的缺页次数。验证此例是否出现了 Belady 异常。

  3. 解释为什么 fork() 系统调用返回两次。在 fork() 之后，父进程和子进程的地址空间是完全独立的吗？写时复制（Copy-on-Write）如何优化 fork() 的效率？

  4. 设计一个场景证明哲学家就餐问题中死锁的存在，并给出至少两种不同的死锁预防策略。分析各策略的优缺点。

  5. 对比 ext4 的 Ordered 日志模式和 Btrfs 的 CoW 机制在崩溃一致性保障方面的异同。在写入密集型负载下，哪种方案可能有更好的性能？为什么？

拓展阅读

  • 《Operating Systems: Three Easy Pieces》（Remzi & Andrea Arpaci-Dusseau）：免费在线教材，以对话式风格深入浅出地讲解操作系统的三大主题：虚拟化、并发和持久化。
  • 《Operating System Concepts》（Silberschatz, Galvin, Gagne，恐龙书）：经典教材，覆盖全面，适合系统性学习。
  • Linux 内核源码（kernel.org）：直接阅读 kernel/sched/fair.c（CFS 调度器）和 mm/vmscan.c（页面回收）是理解理论如何落地的最佳方式。
  • 《Linux Kernel Development》（Robert Love）：Linux 内核开发的入门指南，比直接读源码更容易上手。

小结

操作系统通过进程抽象实现 CPU 虚拟化，通过虚拟内存实现内存虚拟化，通过文件系统实现存储持久化。这三大支柱加上并发控制机制，构成了现代计算机系统的运行基座。理解操作系统不仅有助于编写高性能程序，更能培养系统级思维——从资源争用中寻求平衡，在复杂约束下做出设计决策。无论是容器编排、数据库引擎还是分布式系统，其底层都根植于操作系统的核心概念。
