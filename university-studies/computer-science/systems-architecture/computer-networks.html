大学计算机科学与技术 — 计算机网络

知识要点

计算机网络是连接世界的基础设施，从互联网到移动通信，从云计算到物联网，几乎所有现代计算都建立在网络之上。理解计算机网络的核心在于掌握分层架构的思想——将复杂的端到端通信分解为多个功能层次，每层通过定义良好的接口向上层提供服务。这种分层设计既是工程上的模块化实践，也是管理复杂性的思维框架。

网络体系结构的两大参考模型是 OSI 七层模型和 TCP/IP 四层模型。工业实践中 TCP/IP 模型占据主导，但 OSI 模型的分层概念仍是教学和理解网络协议的基石。

TCP/IP 层 对应 OSI 层 核心协议 关键功能
应用层 应用/表示/会话 HTTP, DNS, SMTP, FTP 用户交互、数据表示
传输层 传输层 TCP, UDP, QUIC 端到端可靠传输/多路复用
网络层 网络层 IP, ICMP, BGP, OSPF 路由寻址、分组转发
链路层 数据链路/物理 Ethernet, Wi-Fi, ARP 帧传输、介质访问控制

详细讲解

应用层协议

HTTP（HyperText Transfer Protocol）是 Web 的基石。HTTP/1.1 使用持久连接和管道化减少延迟，但存在队头阻塞（Head-of-Line Blocking）问题——一个慢响应阻塞同一连接上后续请求。HTTP/2 通过多路复用在单一 TCP 连接上并行传输多个流解决了应用层队头阻塞，但 TCP 层的队头阻塞仍然存在。HTTP/3 采用基于 UDP 的 QUIC 协议，彻底消除了传输层队头阻塞。

DNS（Domain Name System）将域名映射为 IP 地址，采用层次化的分布式数据库架构。域名解析过程从本地缓存出发，依次查询递归解析器、根域名服务器（13 组）、顶级域服务器和权威域名服务器。DNS 查询的典型延迟为 10-100  ms10\text{-}100\;\text{ms}10-100ms，缓存的 TTL（Time To Live）机制在新鲜度和负载之间取得平衡。

传输层：TCP 与拥塞控制

TCP（Transmission Control Protocol）提供可靠的、面向连接的字节流服务。其可靠性建立在以下机制之上：

  • 三次握手建立连接：SYN → SYN-ACK → ACK，确保双方的初始序列号（ISN）已交换
  • 序列号与确认号：每个字节分配序列号，接收方通过累积确认通知发送方已收到的数据
  • 超时重传与快速重传：RTO（Retransmission Timeout）基于 RTT 的指数加权移动平均估计：
SRTT=(1−α)⋅SRTT+α⋅RTTsample\text{SRTT} = (1-\alpha) \cdot \text{SRTT} + \alpha \cdot \text{RTT}_{\text{sample}}SRTT=(1−α)⋅SRTT+α⋅RTTsample​
RTO=SRTT+4⋅RTTVAR\text{RTO} = \text{SRTT} + 4 \cdot \text{RTTVAR}RTO=SRTT+4⋅RTTVAR

其中 α\alphaα 通常取 1/81/81/8。收到三个重复 ACK 时触发快速重传，无需等待超时。

TCP 拥塞控制是网络稳定运行的关键。经典算法包括：

阶段 行为 窗口变化
慢启动 每 RTT 窗口翻倍 cwnd←cwnd×2\text{cwnd} \leftarrow \text{cwnd} \times 2cwnd←cwnd×2
拥塞避免 每 RTT 窗口加 1 cwnd←cwnd+1\text{cwnd} \leftarrow \text{cwnd} + 1cwnd←cwnd+1
快速恢复 3 个重复 ACK 后 ssthresh←cwnd/2\text{ssthresh} \leftarrow \text{cwnd}/2ssthresh←cwnd/2

TCP 的吞吐量受限于带宽-延迟积（BDP）：

BDP=Bandwidth×RTT\text{BDP} = \text{Bandwidth} \times \text{RTT}BDP=Bandwidth×RTT

理想状态下，发送窗口应等于 BDP。例如，100 Mbps 链路、50 ms RTT 下，BDP = 100×106×0.05/8=625  KB100 \times 10^6 \times 0.05 / 8 = 625\;\text{KB}100×106×0.05/8=625KB。

现代拥塞控制算法 BBR（Bottleneck Bandwidth and Round-trip propagation time）由 Google 提出，通过主动探测瓶颈带宽和最小 RTT 来确定发送速率，避免了基于丢包的拥塞信号导致的缓冲膨胀（Bufferbloat）问题。

网络层：IP 与路由

IPv4 地址为 32 位，使用 CIDR（无类别域间路由）表示法，如 192.168.1.0/24192.168.1.0/24192.168.1.0/24 表示前 24 位为网络前缀。子网掩码决定了网络部分和主机部分的划分。IPv4 地址空间已耗尽，IPv6 将地址扩展到 128 位（2128≈3.4×10382^{128} \approx 3.4 \times 10^{38}2128≈3.4×1038）。

路由算法决定分组从源到目的地的转发路径：

  • 距离向量算法（如 RIP）：每个路由器维护到所有目的地的距离和下一跳，周期性与邻居交换路由表。收敛慢，存在计数到无穷问题。
  • 链路状态算法（如 OSPF）：每个路由器通过泛洪获取全局拓扑，本地运行 Dijkstra 算法计算最短路径树。收敛快但状态信息量大。
  • 路径向量算法（如 BGP）：互联网域间路由协议，携带完整 AS 路径防止环路，基于策略（而非最短路径）做路由决策。

NAT（网络地址转换）通过在网关处翻译内网地址和端口，让多台主机共享一个公网 IP。NAT 打破了端到端原则，但在 IPv4 地址紧缺的现实中不可或缺。

链路层与局域网

以太网（Ethernet）是最广泛使用的局域网技术。现代交换式以太网使用交换机（Switch）替代了早期的集线器和总线，每个端口独占带宽，通过 MAC 地址表实现帧的定向转发。

ARP（Address Resolution Protocol）将 IP 地址解析为 MAC 地址。当主机需要发送帧到同一子网内的目的 IP 时，先查询本地 ARP 缓存，未命中则广播 ARP 请求。

Wi-Fi（IEEE 802.11）使用 CSMA/CA（带冲突避免的载波侦听多路访问）协议：发送前先侦听信道，空闲则等待随机退避时间再发送。无线环境中无法检测冲突（隐藏终端问题），因此使用 RTS/CTS 握手机制预约信道。

网络安全基础

TLS（Transport Layer Security）在传输层之上提供加密、认证和完整性保护。TLS 1.3 将握手简化为 1-RTT（首次连接）或 0-RTT（恢复连接），大幅减少了延迟。握手过程使用 Diffie-Hellman 密钥交换协商会话密钥：

ga mod p←Alice→Bobgb mod pg^a \bmod p \xleftarrow{\text{Alice}} \xrightarrow{\text{Bob}} g^b \bmod pgamodpAlice​Bob​gbmodp

双方各自计算共享密钥 K=gab mod pK = g^{ab} \bmod pK=gabmodp，无需在网络上传输密钥本身。

  1. 假设 TCP 连接的 RTT 为 20  ms20\;\text{ms}20ms，初始 cwnd 为 1 MSS（146014601460 字节），慢启动阈值为 64  KB64\;\text{KB}64KB。计算从连接建立到拥塞窗口首次达到慢启动阈值所需的时间。

  2. 一个组织获得了 200.10.0.0/21200.10.0.0/21200.10.0.0/21 的 IP 地址块。请计算该块包含多少个可用主机地址。如果要将其划分为 4 个等大的子网，每个子网的 CIDR 表示是什么？

  3. 解释为什么 HTTP/2 的多路复用仍然受到 TCP 队头阻塞的影响。QUIC 协议如何通过在 UDP 之上实现独立流来解决这个问题？

  4. 比较距离向量路由和链路状态路由在收敛速度、带宽消耗和实现复杂度方面的差异。在一个有 100 个路由器的网络中，哪种算法更适合？为什么？

  5. 在公共 Wi-Fi 网络中，即使使用了 HTTPS，攻击者仍然可以获取哪些信息？请从 DNS 查询、TLS SNI（Server Name Indication）和流量分析三个角度讨论。

拓展阅读

  • 《Computer Networking: A Top-Down Approach》（Kurose & Ross）：自顶向下讲解网络协议栈，从应用层切入更符合直觉，配套 Wireshark 实验极具实践性。
  • 《TCP/IP Illustrated, Volume 1》（W. Richard Stevens）：TCP/IP 协议的权威参考，通过抓包分析逐字节解读协议行为。
  • RFC 文档：HTTP/2（RFC 7540）、QUIC（RFC 9000）、TLS 1.3（RFC 8446）是深入理解协议设计的一手资料。
  • Beej's Guide to Network Programming：免费在线指南，用 C 语言从 Socket API 入手学习网络编程。

小结

计算机网络的分层架构将端到端通信的复杂性分解为可管理的层次：应用层定义用户交互协议，传输层提供可靠或不可靠的端到端数据传输，网络层负责跨网路由与转发，链路层处理相邻节点间的帧传输。TCP 的拥塞控制保障了互联网在高负载下的稳定性，IP 路由协议实现了全球规模的分组交换网络。掌握这些基础概念和协议机制，是理解云计算、CDN、微服务通信和网络安全的必备前提。
