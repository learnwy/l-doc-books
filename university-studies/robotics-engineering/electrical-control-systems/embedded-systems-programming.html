嵌入式系统编程

知识要点

机器人嵌入式系统架构

机器人嵌入式系统是连接感知、决策与执行的硬件计算平台。与通用计算机不同，嵌入式系统强调实时性、确定性和资源约束下的高效运行。一个典型的机器人嵌入式架构采用分层设计：

常用嵌入式平台
STM32 系列是机器人关节控制器的主力平台：


    

  • STM32F4：Cortex-M4 内核，168MHz，适合中等复杂度控制
    • 

  • STM32H7：Cortex-M7 内核，480MHz，双精度浮点，支持复杂算法
    • 

  • STM32G4：专为电机控制优化，集成高速ADC和比较器
    • 



ESP32系列适合低成本物联网机器人：


    

  • 双核 240MHz，集成 Wi-Fi/BLE
    • 

  • 丰富外设但实时性不如 STM32
    • 



FPGA用于需要极低延迟的场景：


    

  • 并行处理能力，时钟级确定性延迟
    • 

  • 适合高频PWM生成、编码器接口、视觉预处理
    • 



实时操作系统（RTOS）
裸机编程（Bare-metal）适合简单控制回路，但多任务场景下需要 RTOS 保证时间确定性。


FreeRTOS 是机器人领域最广泛使用的 RTOS：


任务创建示例：


void vMotorControlTask(void *pvParameters) {
    TickType_t xLastWakeTime = xTaskGetTickCount();
    const TickType_t xPeriod = pdMS_TO_TICKS(1); // 1ms周期
    
    for(;;) {
        readEncoder();
        computePID();
        setMotorPWM();
        vTaskDelayUntil(&xLastWakeTime, xPeriod);
    }
}
RTOS 任务调度的核心概念：


    

  • 优先级抢占：高优先级任务可中断低优先级任务
    • 

  • 时间片轮转：同优先级任务共享CPU时间
    • 

  • 优先级反转：低优先级任务持有高优先级任务需要的资源
    • 

  • 优先级继承：解决优先级反转的机制
    • 



典型任务优先级分配：


电机控制(1kHz)>传感器采集(500Hz)>通信(100Hz)>状态监控(10Hz)\text{电机控制}(1\text{kHz}) > \text{传感器采集}(500\text{Hz}) > \text{通信}(100\text{Hz}) > \text{状态监控}(10\text{Hz})电机控制(1kHz)>传感器采集(500Hz)>通信(100Hz)>状态监控(10Hz)
中断管理
中断是实现实时响应的核心机制。STM32的嵌套向量中断控制器（NVIC）支持最多256级中断优先级。


关键设计原则：


    

  • 中断服务程序（ISR）尽量短：仅做数据搬运，计算放在任务中
    • 

  • 使用 DMA：传感器数据批量搬运不占CPU
    • 

  • 避免在 ISR 中调用浮点运算：保存/恢复 FPU 上下文开销大
    • 



中断延迟的组成：


tlatency=trecognition+tcontext_save+tvector_fetch+tISR_entryt_{\text{latency}} = t_{\text{recognition}} + t_{\text{context\_save}} + t_{\text{vector\_fetch}} + t_{\text{ISR\_entry}}tlatency​=trecognition​+tcontext_save​+tvector_fetch​+tISR_entry​
对于 STM32H7，典型中断响应延迟约为 12 个时钟周期（约 25ns @480MHz）。


工业通信协议
CAN 总线（Controller Area Network）：


    

  • 差分信号，抗干扰能力强
    • 

  • 多主站架构，支持优先级仲裁
    • 

  • 经典CAN速率：1Mbps，CAN FD：8Mbps
    • 

  • 适合关节间通信（报文短、实时性要求高）
    • 



EtherCAT（Ethernet for Control Automation Technology）：


    

  • 基于以太网物理层，速率100Mbps
    • 

  • 主从架构，"飞读飞写"极低延迟（< 1μ\muμs）
    • 

  • 分布式时钟同步精度 < 100ns
    • 

  • 适合多轴伺服系统的实时同步控制
    • 



SPI/I2C：


    

  • 用于板内芯片间通信
    • 

  • SPI 高速（数十MHz），全双工
    • 

  • I2C 低速（400kHz~3.4MHz），仅需2线
    • 



电机控制底层实现
BLDC 电机的 FOC（Field-Oriented Control，磁场定向控制）是现代伺服控制的基础：


    

  1. Clark 变换：三相 (ia,ib,ic)(i_a, i_b, i_c)(ia​,ib​,ic​) → 两相 (iα,iβ)(i_\alpha, i_\beta)(iα​,iβ​)
    2. 

  2. Park 变换：静止坐标 (iα,iβ)(i_\alpha, i_\beta)(iα​,iβ​) → 旋转坐标 (id,iq)(i_d, i_q)(id​,iq​)
    3. 

  3. 电流环 PI 控制：分别控制 idi_did​（励磁）和 iqi_qiq​（转矩）
    4. 

  4. 逆 Park 变换 + SVPWM：生成三相PWM驱动信号
    5.

其中 θe\theta_eθe​ 为电角度，通常由编码器测量机械角度后乘以极对数获得。


安全与看门狗机制
机器人嵌入式系统必须具备故障安全机制：


    

  • 硬件看门狗：MCU异常时自动复位
    • 

  • 心跳监测：主控与关节控制器定期通信确认
    • 

  • 过流保护：硬件比较器+软件双重保护
    • 

  • 急停电路：独立于软件的硬件切断回路
    • 



前沿动态
2025-2026年，机器人嵌入式系统正向更高集成度和更强算力方向演进。RISC-V 架构开始在机器人控制器中崭露头角——其开源特性允许定制指令集（如向量运算扩展），特别适合电机控制中的定点DSP运算。


此外，TSN（Time-Sensitive Networking）正在替代传统工业总线，实现千兆以太网级别的确定性通信。ROS2 与 TSN 的结合使得"上位机实时控制"成为可能，模糊了传统上下位机的边界。


基于 Rust 语言的嵌入式开发也在机器人社区中快速普及。Rust 的所有权系统在编译期消除了内存安全问题，对于安全关键的机器人系统具有重要价值。Embassy 框架已支持 STM32 全系列的异步嵌入式开发。

小结
嵌入式系统编程是将控制算法"落地"为可靠硬件系统的关键环节。从 MCU 选型、RTOS 调度到工业通信和电机控制底层实现，每个环节都直接影响机器人的实时性能和运行可靠性。掌握硬件抽象与实时编程思维，是从"算法仿真"走向"系统交付"的必经之路。
