ROS框架开发

知识要点

ROS2 概述与架构演进

ROS2（Robot Operating System 2）是面向机器人开发的开源中间件框架。相比 ROS1，ROS2 基于 DDS（Data Distribution Service）通信中间件重新设计，原生支持实时性、多机器人和工业级部署。

ROS2 的核心设计理念：

  • 去中心化：无需 ROS Master，节点自动发现
  • 实时性：支持实时调度和确定性通信
  • 跨平台：Linux/Windows/macOS/嵌入式RTOS
  • 安全性：内置 DDS Security（认证、加密、访问控制）
节点与通信机制
ROS2 提供四种核心通信模式：


Topic（话题）：发布-订阅模式，一对多异步通信


    

  • 发布者发送消息，订阅者接收
    • 

  • 适合连续数据流（传感器数据、状态信息）
    • 

  • QoS策略配置：可靠/尽力、持久/瞬态、历史深度
    • 



Service（服务）：请求-响应模式，同步调用


    

  • 客户端发送请求，服务端返回响应
    • 

  • 适合一次性查询/配置（如获取参数、触发动作）
    • 



Action（动作）：带反馈的异步任务


    

  • 客户端发送目标，服务端执行并定期反馈进度
    • 

  • 支持取消和抢占
    • 

  • 适合长时间任务（导航到目标点、抓取物体）
    • 



Parameter（参数）：运行时可修改的配置值


    

  • 支持回调监听参数变化
    • 

  • 可通过命令行、启动文件或程序动态修改
    • 



节点生命周期管理
ROS2 引入了生命周期节点（Lifecycle Node / Managed Node），通过状态机管理节点的初始化、激活和清理过程：


生命周期节点的价值：


    

  • 确定性启动：确保所有节点按正确顺序初始化
    • 

  • 热重载：可以 deactivate → cleanup → configure → activate 重新加载配置
    • 

  • 故障恢复：节点崩溃后可由管理器自动重启
    • 



Launch系统
ROS2 Launch 系统使用 Python 脚本或 XML/YAML 描述多节点启动配置：


from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        Node(
            package='robot_localization',
            executable='ekf_node',
            parameters=[{'use_sim_time': True}],
            remappings=[('/odom', '/wheel_odom')]
        ),
        Node(
            package='nav2_controller',
            executable='controller_server',
            parameters=['nav2_params.yaml']
        ),
    ])
关键特性：


    

  • 条件启动（IfCondition/UnlessCondition）
    • 

  • 事件驱动（OnProcessExit, OnStateTransition）
    • 

  • 命名空间和参数注入
    • 

  • 组合节点（Composition）减少进程间通信开销
    • 



消息与接口定义
ROS2 使用 .msg、.srv、.action 文件定义数据接口：


# 自定义消息: JointState.msg
std_msgs/Header header
string[] name
float64[] position
float64[] velocity
float64[] effort
常用标准消息包：


    

  • geometry_msgs：Pose, Twist, Transform, Wrench
    • 

  • sensor_msgs：Image, LaserScan, PointCloud2, Imu, JointState
    • 

  • nav_msgs：Odometry, Path, OccupancyGrid
    • 

  • tf2_msgs：坐标变换
    • 



TF2坐标变换
TF2是ROS2的坐标变换系统，维护整个机器人系统的坐标系树。


典型坐标系链：


map→odom→base_link→sensor_frame\text{map} \rightarrow \text{odom} \rightarrow \text{base\_link} \rightarrow \text{sensor\_frame}map→odom→base_link→sensor_frame
    

  • map → odom：SLAM/定位提供（低频，全局一致）
    • 

  • odom → base_link：里程计提供（高频，有漂移）
    • 

  • base_link → sensor_frame：静态标定（不变）
    • 



通过 TF2 可以查询任意两个坐标系之间的变换关系，支持时间插值。


导航框架 Nav2
Nav2 是 ROS2 的标准导航栈，提供完整的自主导航能力：


核心组件：


    

  • Map Server：加载和提供地图
    • 

  • AMCL：自适应蒙特卡洛定位
    • 

  • Planner Server：全局路径规划（NavFn/Smac Planner）
    • 

  • Controller Server：局部轨迹跟踪（DWB/TEB/MPPI）
    • 

  • Recovery Server：异常恢复行为（旋转、后退、清除代价地图）
    • 

  • Behavior Tree Navigator：基于行为树编排导航流程
    •

    •

    • 



rosbag2：数据录制与回放

  • 离线算法开发与测试
    • 



前沿动态
2025-2026年，ROS2 Kilted Kaiju（2026 LTS）发布，带来多项重要改进：共享内存零拷贝传输在同一进程内实现微秒级通信延迟；Type Adaptation 允许用户自定义消息的序列化/反序列化方式，适配GPU直接内存访问。


Micro-ROS 使 ROS2 真正进入嵌入式领域——在 STM32/ESP32 等 MCU 上运行精简版 ROS2 客户端，与主系统无缝通信。这消除了传统"上位机+下位机"分离架构中的协议转换开销。


ROS2 与AI的深度融合正在加速。NVIDIA Isaac ROS 提供了基于GPU加速的感知管线（NITROS零拷贝 pipeline），使 SLAM、目标检测、深度估计等AI算法能够以最小延迟集成到ROS2系统中。

小结
ROS2框架为机器人软件开发提供了标准化的通信、管理和工具生态。掌握节点通信模式、生命周期管理、坐标变换和导航栈的使用，是构建完整机器人系统的基础能力。ROS2不仅是一个"消息传递框架"，更是机器人软件工程的最佳实践载体——模块化、可测试、可部署的设计理念贯穿其中。
