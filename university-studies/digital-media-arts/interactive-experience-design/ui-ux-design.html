UI/UX 设计

知识要点

以用户为中心的设计思维

UI/UX 设计的核心信条是"为用户设计，而非为自己设计"。这一理念贯穿从需求发现到最终交付的全过程。

UX 设计与 UI 设计的关系：

  • UX（用户体验设计）：关注"产品好不好用"——用户能否顺畅完成任务、过程中情绪如何、整体满意度是否高
  • UI（用户界面设计）：关注"产品好不好看"——视觉表现是否美观、品牌调性是否一致、交互反馈是否清晰
  • 两者的关系：UX 定义"做什么"，UI 定义"怎么呈现"。优秀的产品需要两者协同

设计思维五步法（Stanford d.school）：

  1. 共情（Empathize）：深入理解用户的真实需求、痛点与使用情境
  2. 定义（Define）：将观察转化为清晰的问题陈述（How Might We...）
  3. 构思（Ideate）：发散思维产出多种解决方案，不过早收敛
  4. 原型（Prototype）：快速制作低成本可测试的方案原型
  5. 测试（Test）：与真实用户验证方案，收集反馈后迭代

用户研究方法

设计决策必须基于对用户的真实理解，而非假设：

定性研究：

  • 用户访谈：半结构化访谈获取用户目标、动机和痛点。关键技巧：开放性提问、追问"为什么"、避免诱导
  • 情境观察：在用户真实使用场景中观察行为，发现用户自己无法表达的隐性需求
  • 卡片分类：让用户对信息条目进行分组和命名，为信息架构设计提供依据

定量研究：

  • 问卷调查：大样本收集态度和偏好数据。李克特量表（1-5/7分）是最常用的测量方式
  • A/B 测试：对照实验验证设计假设。统计显著性判断需要足够样本量，通常 n>1000n > 1000n>1000 以上
  • 数据分析：通过埋点追踪用户行为路径、转化漏斗、留存曲线等产品指标
信息架构与交互设计
信息架构（Information Architecture）：


    

  • 层级结构：树状组织，适合内容明确、层级清晰的产品（如电商分类）
    • 

  • 矩阵结构：多维度交叉，适合同一内容需要从不同维度访问（如新闻网站：按时间/分类/地域）
    • 

  • 有序结构：线性流程，适合有明确步骤的任务（如注册流程、购买流程）
    • 



交互设计原则：


    

  • 可见性（Visibility）：功能的存在应该对用户可见，隐藏操作会增加认知负荷
    • 

  • 反馈（Feedback）：每个用户操作都应获得即时、明确的系统反馈
    • 

  • 一致性（Consistency）：同类元素在不同位置保持相同的交互行为
    • 

  • 容错性（Error Prevention）：设计应预防错误发生，而非依赖错误后的修正
    • 

  • 效率（Efficiency）：为专家用户提供快捷路径（快捷键、手势）
    • 



费茨定律（Fitts's Law）：


T=a+b⋅log⁡2(DW+1)T = a + b \cdot \log_2\left(\frac{D}{W} + 1\right)T=a+b⋅log2​(WD​+1)
其中 TTT 为完成点击所需时间，DDD 为目标距离，WWW 为目标宽度。这意味着——关键按钮应该既大又近，屏幕边缘和角落是"无限宽"的高效目标位置。


设计系统与组件化
规模化产品需要系统化的设计规范：


设计令牌（Design Tokens）：


    

  • 颜色令牌：--color-primary-500, --color-neutral-100
    • 

  • 间距令牌：--spacing-xs: 4px, --spacing-sm: 8px, --spacing-md: 16px
    • 

  • 字号令牌：--font-size-body: 14px, --font-size-h1: 32px
    • 

  • 圆角令牌：--radius-sm: 4px, --radius-md: 8px
    • 



组件层级（Atomic Design 方法论）：


    

  • 原子（Atoms）：最基础的 UI 元素——按钮、输入框、图标、标签
    • 

  • 分子（Molecules）：原子的简单组合——搜索栏（输入框+按钮）、列表项（头像+文字+时间）
    • 

  • 有机体（Organisms）：分子的复杂组合——导航栏、卡片组、表单
    • 

  • 模板（Templates）：页面级的布局框架
    • 

  • 页面（Pages）：填充真实内容的最终产出
    • 



可用性测试
设计方案需要与真实用户验证：


    

  • 测试计划：定义测试目标、目标用户画像、核心任务场景（通常3-5个典型任务）
    • 

  • 测试执行：邀请5-8名代表性用户，观察其完成任务的过程，记录困惑点和失败点
    • 

  • 核心指标：任务完成率、任务完成时间、错误次数、SUS评分（System Usability Scale, 满分100）
    • 

  • 启发式评估：尼尔森十大可用性原则作为专家审查框架
    • 



现代设计工具与协作
Figma 为中心的工作流：


    

  • Auto Layout：响应式组件自适应布局
    • 

  • Variables：变量系统管理设计令牌，一键切换亮暗模式
    • 

  • Components & Variants：组件变体管理，保持设计一致性
    • 

  • Dev Mode：设计稿自动生成开发标注和代码片段
    • 

  • FigJam：白板工具用于用户旅程图、亲和图等研究产出
    • 



前沿动态
2025—2026年，AI 正在从根本上重塑 UI/UX 设计工作流。Figma AI 可以根据文字描述自动生成界面原型、批量创建组件变体、智能建议布局优化。设计师的角色正在从"像素推动者"转向"体验策略师"——更多时间花在用户研究和战略思考上，而非重复性的视觉执行。


空间计算（Spatial Computing）正在开辟全新的 UI 范式。Apple Vision Pro 和 Meta Quest 的空间界面设计需要重新思考信息层级、注视交互（Eye Tracking）、手势交互和空间音频反馈，这些是二维屏幕时代 UI 规范无法覆盖的领域。


数据驱动设计（Data-Informed Design）成为主流实践——通过 A/B 测试平台、热力图分析、漏斗监控等工具，设计决策可以被量化验证。但业界也在警惕"数据至上"的陷阱：短期指标优化可能损害长期用户体验和品牌价值。


练习与思考
    

  1. 选择一个你经常使用但体验不佳的 App 功能，进行完整的 UX 改进设计：用户访谈（3人）→ 问题定义 → 3种解决方案 → 低保真线框图 → 高保真原型 → 可用性测试（3人）。撰写完整的设计文档。
    

    2. 

  2. 在 Figma 中构建一个简易设计系统：定义 color/spacing/typography tokens，创建 Button/Input/Card 三个基础组件（含多种变体状态），编写组件使用规范文档。
    

    3. 

  3. 运用费茨定律分析三款主流 App 的底部导航栏设计：计算各 Tab 图标的有效点击区域大小与手指起始位置的距离关系，评估哪款设计的交互效率最高。
    

    4. 

  4. 为一个虚拟的"校园二手交易平台"设计信息架构：进行卡片分类测试（邀请5位同学参与），根据结果设计导航结构，绘制站点地图（Site Map）。
    

    5. 

  5. 观看一段可用性测试视频录像（B站/YouTube有大量公开资源），记录你观察到的用户困惑点和设计问题，并提出改进方案。
    

    6. 



小结
UI/UX 设计是连接技术实现与人类需求的桥梁学科。从用户研究的共情能力到信息架构的逻辑思维，从视觉设计的审美表达到可用性测试的科学验证——这是一个需要左右脑协同工作的领域。在 AI 工具分担了大量执行性工作之后，设计师的核心竞争力更加集中在战略思维、用户洞察和创新能力上。
