GPU 架构基础

核心概念

图形处理器（GPU）是一种大规模并行处理器，其设计目标是同时处理数以千计的轻量级线程。与 CPU 将大量晶体管用于复杂的控制逻辑（乱序执行、分支预测、大型缓存）不同，GPU 将大部分面积分配给计算单元，以吞吐量为核心优化目标。NVIDIA H100 拥有超过 16000 个 CUDA 核心，峰值算力达到数百 TFLOPS，是同代 CPU 的数十倍。

GPU 的高吞吐量源自 SIMT（Single Instruction, Multiple Threads）执行模型。一条指令同时驱动一组线程（称为 Warp 或 Wavefront）执行相同操作，但作用于不同数据。这种模型非常适合数据并行计算——图形渲染、矩阵运算、深度学习训练中大量的同构计算正是 GPU 的理想负载。

SIMT 执行模型
SIMT 是 GPU 的核心执行范式。以 NVIDIA 架构为例，32 个线程组成一个 Warp，这 32 个线程在同一时刻执行同一条指令。Warp 是 GPU 调度的最小单位——硬件不会单独调度 Warp 内的某一个线程。


当 Warp 中的线程因条件分支走向不同路径时，会发生线程发散（Thread Divergence）。GPU 必须串行化执行两条路径——先执行 if 分支的线程（其余线程被掩码禁用），再执行 else 分支的线程，最后在汇合点重新合并。线程发散直接导致计算资源浪费，是 GPU 编程中最重要的性能陷阱之一。


每个 SM（Streaming Multiprocessor）包含多个 Warp 调度器。NVIDIA Hopper 架构的 SM 包含 4 个 Warp 调度器，每个调度器管理一组 Warp。当一个 Warp 因访存等待而停顿时，调度器立即切换到另一个就绪的 Warp。这种零开销上下文切换（Zero-Overhead Context Switch）依赖于大量寄存器——每个 SM 拥有 65536 个 32 位寄存器，所有 Warp 的状态同时驻留在寄存器文件中，无需保存和恢复。


SM 中的占用率（Occupancy）衡量活跃 Warp 数与最大可驻留 Warp 数的比例。高占用率意味着更多的 Warp 可供调度器选择，更有效地隐藏访存延迟。但占用率受三个因素限制：每线程寄存器使用量、每线程块共享内存使用量、以及线程块大小。实践中 50%-75% 的占用率通常已经足够，过度追求 100% 可能需要牺牲每线程的寄存器数。


显存层次与带宽
GPU 的内存层次与 CPU 有根本性的差异——GPU 设计以带宽为核心优化目标，而非延迟。这是因为 GPU 通过大量并发线程来隐藏延迟，但需要极高的带宽来喂饱数千个计算单元。


寄存器文件是 GPU 中最快的存储，也是容量最大的片上存储。NVIDIA H100 的每个 SM 有 256KB 的寄存器文件，整个 GPU 的寄存器总量超过 30MB。相比之下，同 SM 中的 L1 缓存/共享内存仅有 228KB。GPU 的寄存器文件实际上承担了 CPU 中 L1 缓存的角色。


共享内存（Shared Memory）是可编程的片上高速缓存，由同一线程块内的所有线程共享。它的延迟约 20-30 个周期，带宽远高于全局内存。共享内存是 GPU 编程中实现数据复用的核心机制——将频繁访问的数据从全局内存加载到共享内存，多个线程在共享内存中反复读取，避免重复的全局内存访问。


L1/L2 缓存在现代 GPU 中发挥越来越重要的作用。NVIDIA 从 Volta 开始将 L1 缓存和共享内存统一到同一物理 SRAM 中，可灵活分配比例。H100 的 L2 缓存高达 50MB，为 AI 推理中的权重复用提供了重要加速。


全局内存（显存/VRAM）通过高带宽接口连接。NVIDIA H100 使用 HBM3，提供 3.35 TB/s 的带宽，远超 CPU 的内存带宽。HBM（High Bandwidth Memory）通过硅中介层（Silicon Interposer）垂直堆叠多层 DRAM，使用数千个数据引脚实现极高的并行度。显存容量（如 H100 的 80GB）是大模型训练的关键约束——模型参数、激活值和梯度都必须驻留在显存中。

Tensor Core 与专用计算单元
Tensor Core 是 NVIDIA 从 Volta 架构开始引入的矩阵运算专用单元。它执行混合精度的矩阵乘累加（MMA）操作：D = A × B + C，其中 A 和 B 可以是 FP16/BF16/FP8/INT8，C 和 D 通常是 FP32。单条 Tensor Core 指令在一个周期内完成一个 4×4×4 的矩阵乘法。


H100 的每个 SM 包含 4 个第四代 Tensor Core，整个 GPU 共 528 个 Tensor Core，FP16 峰值算力达 989 TFLOPS（稀疏模式下翻倍）。相比 FP32 CUDA 核心的 67 TFLOPS，Tensor Core 提供了超过 10 倍的矩阵计算加速。


Transformer 引擎（Transformer Engine）是 H100 新增的功能，它在 Tensor Core 基础上增加了动态精度调整——在每层 Transformer 的前向和后向传播中，根据张量的数值范围自动选择 FP8 或 FP16 精度，在不损失模型精度的前提下进一步提升吞吐量。


除 Tensor Core 外，现代 GPU 还集成了其他专用单元： RT Core（光线追踪核心）加速 BVH（Bounding Volume Hierarchy）遍历和光线-三角形求交，将光线追踪的部分计算从着色器卸载到专用硬件。 Video Codec（NVENC/NVDEC）提供硬件视频编解码能力，不占用计算资源。


GPU 编程模型与线程层次
GPU 编程模型采用层次化的线程组织结构来映射硬件层次。理解软件抽象与硬件实现的映射关系是编写高效 GPU 代码的基础。


CUDA 编程模型的线程层次： Grid（网格）是最高层，对应一次 kernel 启动。 Block（线程块）是 Grid 的组成单元，映射到一个 SM 上执行。同一 Block 内的线程可以通过共享内存通信和同步。 Thread（线程）是最细粒度的执行单元，每个线程有独立的寄存器和局部变量。


Block 的大小选择直接影响性能。Block 过小导致占用率不足，Block 过大可能因寄存器和共享内存不足而降低并发 Block 数。实践中 128 或 256 个线程/Block 是常见的起点选择。


线程块的维度配置（blockDim.x/y/z）应与数据的空间结构对齐。二维图像处理适合使用 16×16 的二维 Block，一维向量运算适合使用 256×1 的一维 Block。维度配置还影响内存合并（Memory Coalescing）——同一 Warp 中的相邻线程应访问连续内存地址，以便硬件将多次访问合并为一次高效的宽内存事务。


内存合并是 GPU 性能优化的关键。如果 Warp 中 32 个线程访问连续的 32 个 float（128 字节），硬件会合并为一次 128 字节的内存事务。但如果 32 个线程访问的地址分散（如步长为 1024），则需要 32 次独立的内存事务，有效带宽降至峰值的 1/32。因此 GPU 编程中"数组的结构体"（SoA）通常优于"结构体的数组"（AoS）。


小结
    

  • GPU 通过大规模 SIMT 并行取代 CPU 的复杂控制逻辑，以吞吐量换延迟
    • 

  • Warp 是调度最小单位，线程发散会导致串行化执行，是 GPU 编程最关键的性能问题
    • 

  • GPU 的寄存器文件容量远超 CPU，承担了延迟隐藏和状态保持的双重角色
    • 

  • 共享内存和内存合并是 GPU 性能优化的两大核心技术
    • 

  • Tensor Core 提供超过 10 倍于通用 CUDA 核心的矩阵运算加速，是深度学习训练的基石
    • 

  • 线程层次（Grid/Block/Thread）到硬件层次（GPU/SM/Warp）的映射理解是编写高效 GPU 代码的前提
    •
