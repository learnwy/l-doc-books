Part III · 系统 (Systems)计算机组成原理 简介存储层次 简介缓存架构

缓存架构

核心概念

缓存（Cache）是位于处理器和主存之间的高速存储器，利用程序的时间局部性和空间局部性来弥合处理器速度和内存速度之间的巨大鸿沟。现代处理器的时钟周期约为 0.3ns，而主存访问延迟约为 50-100ns——这意味着每次缓存未命中（cache miss）将浪费 150-300 个时钟周期。缓存通过保存最近访问和临近的数据，使得大多数内存访问可以在 1-4 个周期内完成。

缓存的工作基于两个核心假设：时间局部性——最近访问的数据很快会再次被访问（如循环变量、函数栈帧）；空间局部性——访问某地址后，其相邻地址很快也会被访问（如数组遍历、顺序执行的指令）。统计表明，典型程序的 L1 缓存命中率可达 95%-99%，这意味着绝大多数内存访问都能在缓存中快速完成。

缓存组织方式
缓存的组织方式决定了地址到缓存位置的映射关系。内存地址被分解为三部分：标签（tag）、组索引（set index）和块内偏移（block offset）。组索引确定数据可能存放的组，标签用于在组内匹配具体的缓存行，块内偏移确定行内的字节位置。


直接映射缓存每个内存地址只能映射到一个固定的缓存行。组数等于缓存行数，每组只有一行。优点是查找简单快速（只需比较一个标签），缺点是冲突率高。当两个频繁访问的地址恰好映射到同一行时，会发生抖动（thrashing）——它们交替驱逐对方，命中率急剧下降。


全相联缓存允许任何内存块存放在任何缓存行中。没有冲突问题，但查找时需要并行比较所有标签，硬件开销随缓存大小线性增长。仅适用于容量很小的缓存（如 TLB）。


组相联缓存是直接映射和全相联的折中。缓存被分为多个组，每组包含 N 路缓存行（N-way set associative）。地址先映射到某个组，然后在组内的 N 路中并行查找。4-8 路组相联是现代 L1 缓存的标准选择，在命中率和查找延迟之间取得了良好平衡。


缓存替换与写策略
当缓存未命中且目标组已满时，需要选择一行淘汰以腾出空间。替换策略直接影响缓存的命中率。


LRU（Least Recently Used，最近最少使用）淘汰组内最久未被访问的行。LRU 在理论上接近最优，但精确实现需要为每组维护访问顺序，硬件开销随路数指数增长。4 路 LRU 需要保存 4!=24 种排列之一，用 5 位编码可以实现。高路数（16-20 路）通常使用伪 LRU（PLRU）来近似——用树形结构跟踪"大致最旧"的行。


RRIP（Re-Reference Interval Prediction）是 Intel 提出的改进策略。每个缓存行维护一个 2 位"重引用间隔预测值"，新装入的行获得较低优先级（假设不会很快再次使用）。只有被再次访问后才提升优先级。这避免了"流式访问污染缓存"的问题。


写策略决定了缓存写操作如何与主存同步：


**写直达（Write-Through）**每次写操作同时更新缓存和主存。数据一致性简单，但写操作延迟大。通常配合写缓冲区（Write Buffer）来隐藏写延迟。


**写回（Write-Back）**只更新缓存行，标记为"脏"（dirty）。脏行只在被替换时才写回主存。减少了内存写入次数，是现代处理器的主流选择。但增加了一致性维护的复杂度。


**写分配（Write-Allocate）**在写未命中时先将目标块加载到缓存再写入。 **非写分配（No Write-Allocate）**在写未命中时直接写入下一级存储。写回缓存通常配合写分配，写直达缓存通常配合非写分配。

缓存未命中分类
理解缓存未命中的原因对优化程序性能至关重要。未命中可分为三类（3C 模型）：


强制未命中（Compulsory Miss）——首次访问某块数据时必然未命中。也称冷启动未命中或首次引用未命中。这是无法消除的最小未命中集。预取技术（Prefetching）可以提前将数据加载到缓存来隐藏强制未命中的延迟。


容量未命中（Capacity Miss）——缓存容量不足以容纳程序工作集时发生。即使是全相联缓存也会发生容量未命中。增大缓存容量可以减少容量未命中，但会增加访问延迟和面积。程序优化（如循环分块 loop tiling）可以在不改变缓存大小的情况下减少容量未命中。


冲突未命中（Conflict Miss）——因为有限的关联度导致多个地址竞争同一组。增加关联度（如从 4 路增加到 8 路）可以显著减少冲突未命中。但更高的关联度意味着更多的比较器和更长的查找延迟。


程序员可以通过优化数据布局来减少缓存未命中。例如，将频繁同时访问的数据放在同一缓存行中（空间局部性优化）；使用结构体数组（Array of Structs）替代多个独立数组以提高空间局部性；或者反过来，当只需要结构体的一个字段时，使用数组的结构体（Struct of Arrays）避免加载无用数据。


循环分块（Loop Tiling/Blocking）是减少容量未命中的经典编译器优化。对于矩阵乘法等操作，将大矩阵分解为缓存大小的子块，在子块内完成全部计算后再处理下一个子块。这确保了工作数据集始终驻留在缓存中，将容量未命中转化为（更少的）强制未命中。未优化的矩阵乘法每次元素访问几乎都会缓存缺失，而分块后缺失率可降低到 1/B（B 为块大小）。


预取（Prefetching）技术分为硬件预取和软件预取两种。硬件预取器检测内存访问的步长模式（如连续的缓存行访问），自动将后续地址的数据提前加载到缓存。现代处理器的硬件预取器可以跟踪多种步长模式，包括流式（sequential）和跨步（strided）访问。软件预取通过专门的预取指令（如 x86 的 PREFETCHT0、ARM 的 PRFM）由程序员或编译器显式控制。软件预取的时机很关键——过早导致数据在使用前被替换，过晚则无法隐藏延迟。


多级缓存与包含关系
现代处理器使用 2-3 级缓存来平衡延迟和容量。L1 追求最低延迟（1-4 周期），通常分为独立的 L1-I（指令）和 L1-D（数据）。L2 是容量和延迟的折中（256KB-1MB，10-20 周期），每核私有。L3 是大容量的共享缓存（4-64MB，30-50 周期），所有核心共享。


缓存间的包含关系有三种策略：


包含式（Inclusive）——L2 包含 L1 的所有数据。当 L2 中某行被替换时，必须同时使 L1 中对应行失效（back-invalidation）。优点是一致性查询（snoop）只需查 L2；缺点是有效容量减少（L1 数据在 L2 中重复存储）。


排斥式（Exclusive）——L1 和 L2 没有重叠数据。L1 未命中时从 L2 取数据，同时 L2 中的该行被移除。有效容量等于 L1+L2 之和。AMD 的某些设计使用排斥式 L2-L3 关系。


非包含非排斥（NINE）——不强制任何包含关系。L1 的数据可能在 L2 中存在也可能不存在。Intel 自 Skylake 起在 L2-L3 之间采用此策略，以最大化有效缓存容量。


多级缓存的包含策略影响一致性协议的实现复杂度。包含式缓存（Inclusive Cache）保证 L1 中的每一行在 L2 中都有副本。这简化了一致性协议——外部窥探请求只需检查 L2 标签，如果 L2 未命中则 L1 一定也未命中。但包含式策略浪费了 L2 的容量（L1 的数据在 L2 中重复存储）。


排他式缓存（Exclusive Cache）保证每个缓存行只存在于一级缓存中。L1 驱逐的行被放入 L2（victim cache 方式），有效利用了 L2 的全部容量。AMD 的 Zen 系列使用 L2 对 L1 排他、L3 作为 victim cache 的策略。


非包含非排他（NINE，Non-Inclusive Non-Exclusive）是最灵活的策略。Intel 从 Skylake-SP 开始在服务器处理器中使用 NINE 策略的共享 L3 缓存。L3 不保证包含 L1/L2 的所有行，而是使用窥探过滤器（Snoop Filter）来跟踪哪些核心持有哪些缓存行。这在多核处理器中提供了最好的容量利用率和可扩展性。


小结
    

  • 缓存利用时间和空间局部性弥合处理器与内存之间 100-300 倍的速度差距
    • 

  • 组相联缓存（4-8 路）在命中率和查找延迟间取得平衡，是现代 L1 的标准选择
    • 

  • 写回+写分配策略减少内存写入次数，是高性能处理器的主流写策略
    • 

  • 3C 模型（强制/容量/冲突未命中）为性能分析提供了系统化的诊断框架
    • 

  • 多级缓存的包含关系（包含/排斥/NINE）影响有效容量和一致性维护的复杂度
    • 

  • 程序员通过优化数据布局和访问模式（如循环分块）可以显著提升缓存命中率
