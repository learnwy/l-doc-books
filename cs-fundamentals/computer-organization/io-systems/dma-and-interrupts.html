DMA 与中断机制

核心概念

DMA（Direct Memory Access，直接内存访问）和中断是现代 I/O 系统的两大核心机制。中断允许 I/O 设备在操作完成时主动通知处理器，避免处理器轮询等待。DMA 允许设备直接与主存交换数据，无需处理器逐字节参与传输。两者通常配合使用：处理器通过编程 DMA 控制器启动数据传输，DMA 完成后通过中断通知处理器。

中断机制详解
中断（Interrupt）是硬件设备向处理器发送的异步信号，请求处理器暂停当前执行并处理特定事件。中断机制使处理器无需轮询就能及时响应外部事件，是多任务操作系统的基础。


中断的处理流程包括以下步骤：设备通过中断请求线（IRQ）或消息信号中断（MSI）通知中断控制器。中断控制器根据优先级选择一个中断，将中断向量号发送给处理器。处理器完成当前指令后响应中断：保存 PC 和处理器状态（PSR）到栈上。处理器根据中断向量号查找中断向量表（IVT），跳转到对应的中断服务例程（ISR）。ISR 执行设备相关的处理后，执行中断返回指令恢复之前的执行现场。


Linux 的中断处理采用"上半部/下半部"（Top Half / Bottom Half）架构。上半部（硬中断处理）在中断上下文中执行，时间尽可能短——只做必要的硬件交互（如读取设备状态、清除中断标志）。耗时的处理（如协议解析、数据拷贝）被推迟到下半部执行，下半部可以被其他中断打断。下半部的实现方式包括 softirq、tasklet 和工作队列（workqueue），复杂度和灵活性依次递增。


中断控制器是管理多个中断源的硬件。x86 使用 APIC（Advanced Programmable Interrupt Controller），分为本地 APIC（每个核心一个）和 I/O APIC（连接外设中断线）。ARM 使用 GIC（Generic Interrupt Controller），GICv3/v4 支持 LPI（Locality-specific Peripheral Interrupt）用于大量 PCIe 设备。


中断优先级机制确保紧急事件得到优先处理。当高优先级中断到来时，可以抢占正在处理的低优先级中断。APIC 支持 16 个优先级等级（每个等级包含 16 个向量），GICv3 支持 256 个优先级。实时操作系统对中断延迟有严格要求——从中断触发到 ISR 开始执行的延迟通常需要在微秒级以内。


MSI（Message Signaled Interrupts）是 PCIe 设备使用的中断方式。传统中断通过物理中断线（边沿或电平触发）传递，线数有限且需要仲裁。MSI 将中断编码为一次特殊的 MMIO 写操作——设备向指定的内存地址写入一个特定值来触发中断。MSI-X 扩展支持每个设备最多 2048 个中断向量，使得多队列网卡等设备可以为每个队列分配独立中断。


中断合并（Interrupt Coalescing）是高速设备常用的优化技术。如果每个数据包到达都产生一次中断，高速网卡（10Gbps+）每秒会产生数百万次中断，中断处理开销将压垮处理器。中断合并让设备累积多个事件后只发一次中断，或在一定时间窗口内最多发一次中断。这在吞吐率和延迟之间做出权衡——合并减少中断数量但增加了单个事件的响应延迟。


中断合并的参数通常可由驱动程序配置。Linux 中 ethtool -C 命令可以调整网卡的中断合并参数： rx-usecs（接收中断延迟微秒数）和 rx-frames（接收帧计数阈值）。低延迟场景设置较小的合并窗口，高吞吐场景设置较大的合并窗口。


ethtool -C eth0 rx-usecs 50 rx-frames 64
自适应中断合并（Adaptive Interrupt Coalescing）根据当前流量动态调整合并参数。低流量时减小合并窗口以降低延迟，高流量时增大窗口以减少中断开销。Linux 的 ethtool -C eth0 adaptive-rx on 可以启用此功能。


中断亲和性（Interrupt Affinity）是多核系统中的中断优化技术。通过将不同设备或队列的中断绑定到不同的 CPU 核心，避免多个中断源竞争同一核心。 /proc/irq/<IRQ>/smp_affinity 文件允许为每个中断号指定处理核心的掩码。多队列网卡通常将每个接收队列的 MSI-X 中断绑定到不同核心，实现接收处理的并行化。

DMA 传输原理
DMA 控制器是一个专用硬件引擎，能够独立于处理器在 I/O 设备和主存之间传输数据。处理器只需要在传输开始时配置 DMA 控制器（源地址、目标地址、传输长度），然后就可以去执行其他任务。DMA 传输完成后，DMA 控制器通过中断通知处理器。


DMA 传输的步骤：处理器写 DMA 控制器的寄存器，设置源地址、目标地址和传输字节数。处理器写 DMA 控制器的命令寄存器，启动传输。DMA 控制器接管总线，逐块在设备和内存之间搬移数据。每传输一块数据后，DMA 控制器更新地址和计数器。传输完成后，DMA 控制器触发中断。


DMA 传输模式有三种： 突发模式（Burst Mode）——DMA 一次性传输整个数据块，期间独占总线。传输速度最快，但处理器在此期间无法访问内存。 周期窃取模式（Cycle Stealing）——DMA 每次只传输一个字/双字，然后释放总线让处理器使用。处理器和 DMA 交替使用总线，适合处理器和 I/O 都有持续需求的场景。 透明模式——DMA 仅在处理器不使用总线时传输数据。对处理器性能无影响，但传输速度最慢。


现代系统中 DMA 不再使用独立的 DMA 控制器芯片。高性能设备（NVMe SSD、网卡）内置了自己的 DMA 引擎。设备直接通过 PCIe 总线进行内存读写操作（Bus Mastering DMA）。这种方式比传统 DMA 更灵活，设备可以使用分散-聚集列表（Scatter-Gather List）实现非连续内存区域的 DMA 传输。


分散-聚集 DMA 的工作原理：驱动程序构建一个描述符链表，每个描述符包含一段物理内存的基地址和长度。DMA 引擎遍历链表，依次将各段数据传输到/从设备。这对于操作系统的分页内存非常重要——应用程序的连续虚拟地址在物理内存中可能不连续，分散-聚集 DMA 避免了将数据拷贝到连续的物理缓冲区的开销。


零拷贝（Zero-Copy）技术是 DMA 优化的终极目标。传统网络接收路径中，数据需要从网卡 DMA 到内核缓冲区，再从内核缓冲区拷贝到用户空间。零拷贝技术（如 Linux 的 sendfile()、splice() 或 io_uring）通过让 DMA 直接将数据传输到用户空间映射的内存页中，消除了中间拷贝。这对高性能网络和存储 I/O 性能至关重要。


DMA 与缓存一致性
DMA 引入了缓存一致性问题——DMA 控制器直接读写主存，但处理器缓存中可能有该内存区域的旧副本或未写回的新数据。


**DMA 读（设备从内存读数据）**时：如果处理器缓存中有脏数据（Modified 状态），DMA 将从主存读到过时的数据。必须先将缓存中的脏数据写回主存，再让 DMA 读取。


**DMA 写（设备向内存写数据）**时：DMA 直接修改主存，但处理器缓存中可能仍有该地址的旧副本。处理器后续读该地址时会命中缓存，得到过时的数据。必须使相关缓存行失效，强制处理器从主存重新读取。


解决 DMA 缓存一致性的方法：


软件管理——操作系统在启动 DMA 前手动刷新（flush）或失效（invalidate）相关缓存行。Linux 的 DMA API（dma_map_single、dma_sync_for_device）自动处理这些操作。缺点是需要操作系统精确跟踪 DMA 缓冲区的地址范围。


硬件一致性（Cache-Coherent DMA）——DMA 控制器参与缓存一致性协议。DMA 的内存访问经过与处理器相同的一致性机制（如通过窥探协议）。x86 系统默认提供硬件一致性 DMA，这使得驱动程序编写更简单。ARM 系统中需要通过 SMMU（System MMU）或特定的一致性端口来实现。


**IOMMU（I/O Memory Management Unit）**为 DMA 提供地址翻译和内存保护。没有 IOMMU 时，设备的 DMA 可以访问任意物理地址——这是严重的安全隐患。IOMMU 将设备的 DMA 地址翻译为物理地址，并施加访问权限检查。Intel VT-d 和 ARM SMMU 是两种主流 IOMMU 实现。IOMMU 也是虚拟化中设备直通（Device Passthrough）的关键技术。


在虚拟化场景中，虚拟机（VM）直接使用物理设备（如 SR-IOV 网卡的 VF）。IOMMU 将设备的 DMA 地址限制在该 VM 被分配的物理内存范围内，防止恶意或有缺陷的设备驱动程序访问其他 VM 或宿主机的内存。没有 IOMMU，设备直通将是不可接受的安全风险。Linux 的 VFIO（Virtual Function I/O）框架通过 IOMMU 提供安全的用户态设备访问。


小结
    

  • 中断使处理器无需轮询即可响应外部事件，MSI 通过 MMIO 写操作替代了物理中断线
    • 

  • DMA 让设备直接与主存交换数据，处理器仅在传输开始和结束时参与
    • 

  • 现代高速设备内置 DMA 引擎，支持分散-聚集列表实现灵活的非连续内存传输
    • 

  • DMA 与缓存一致性的矛盾通过软件刷新或硬件一致性协议解决
    • 

  • IOMMU 为 DMA 提供地址翻译和内存保护，是虚拟化和安全的关键硬件
    • 

  • 中断合并在高速设备场景下权衡吞吐率和延迟，是网络/存储性能调优的重要参数
    •
