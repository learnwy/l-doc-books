I/O 基本技术

核心概念

I/O（Input/Output，输入/输出）系统是处理器与外部世界交互的桥梁。键盘、显示器、磁盘、网卡、GPU 等所有外设都通过 I/O 系统与处理器通信。I/O 系统面临的核心挑战是速度不匹配——处理器以纳秒级运行，而 I/O 设备的速度从微秒到秒级不等。如何在不浪费处理器时间的前提下高效完成数据传输，是 I/O 系统设计的核心问题。

I/O 设备通过设备控制器（Device Controller）连接到系统总线。控制器内部包含数据寄存器、状态寄存器和控制寄存器。处理器通过读写这些寄存器来与设备交互——写控制寄存器发出命令，读状态寄存器检查设备状态，读写数据寄存器传输数据。I/O 地址空间的组织方式和数据传输技术共同决定了 I/O 系统的性能和编程复杂度。

I/O 地址空间
处理器访问 I/O 设备寄存器的方式分为两种架构：


**独立 I/O 编址（Port-mapped I/O）**为 I/O 设备分配专用的地址空间，使用专门的 I/O 指令访问。x86 架构使用 IN/OUT 指令访问 64K 个 I/O 端口地址。I/O 地址空间与内存地址空间完全独立，不会冲突。但专用指令增加了 ISA 的复杂度，且 I/O 操作无法利用内存指令的灵活寻址方式。


**内存映射 I/O（Memory-mapped I/O，MMIO）**将设备寄存器映射到内存地址空间的某个区域。处理器使用普通的 LOAD/STORE 指令访问设备寄存器，就像访问内存一样。ARM 架构全面使用 MMIO，x86 在高速设备（如 GPU 显存、NVMe）上也使用 MMIO。现代 x86 系统仍然保留 Port I/O 以兼容传统设备，但新设计的高速设备全部使用 MMIO。Linux 内核中 ioread32() / iowrite32() 等函数封装了 MMIO 访问，提供跨平台的设备寄存器操作接口。MMIO 的优势是统一了内存和 I/O 的编程模型，但需要在硬件层面确保 MMIO 区域绕过缓存。在 MMIO 模式下，指针运算和 C 语言的 volatile 关键字就是驱动程序与设备交互的基本工具：


volatile uint32_t *reg = (volatile uint32_t *)0xFE200000;
*reg = 0x01;          // 写设备寄存器
uint32_t val = *reg;  // 读设备寄存器
volatile 关键字告诉编译器：这个变量可能被外部硬件修改，不要将其值缓存到寄存器中，每次访问都必须真正执行内存操作。没有 volatile，编译器的优化可能消除看似"冗余"的读写操作，导致设备交互失败。


MMIO 区域必须被标记为不可缓存（Uncacheable）。如果设备寄存器被缓存，处理器可能读到过时的状态值或将写操作延迟在 Store Buffer 中。x86 使用页表中的 PAT（Page Attribute Table）标记来控制缓存属性。ARM 使用页表的内存类型字段将 MMIO 区域标记为 Device 类型。


内存属性类型对 MMIO 的正确性至关重要。x86 定义了多种内存类型：UC（Uncacheable，完全不缓存）、WC（Write Combining，合并写入但不缓存读取）、WT（Write Through，写穿透）、WB（Write Back，写回）和 UC-（弱不可缓存）。GPU 的帧缓冲区通常映射为 WC 类型——允许将多次写入合并为一次突发写入，提高帧渲染性能，但读取操作不经过缓存，直接从设备获取最新数据。


ARM 的内存类型分为 Normal（普通内存）和 Device（设备内存）两大类。Device 类型还细分为 nGnRnE、nGnRE、nGRE 和 GRE 四种，控制聚合（Gathering）、重排（Reordering）和提前完成（Early Acknowledgement）行为。这些细粒度控制使得 ARM 系统可以针对不同设备选择最优的 MMIO 访问语义。

PCIe 设备的 BAR（Base Address Register）定义了设备的 MMIO 地址范围。操作系统在启动时通过 PCIe 配置空间枚举设备，并为每个 BAR 分配唯一的物理地址范围。应用程序通过 mmap() 将 BAR 映射到用户空间虚拟地址，实现用户态直接设备访问（如 DPDK 的网络 I/O）。


编程 I/O 与轮询
编程 I/O（Programmed I/O，PIO）是最简单的 I/O 数据传输方式。处理器直接参与每个字节或每个字的传输——读取设备数据寄存器并写入内存，或从内存读取并写入设备数据寄存器。整个传输过程中处理器全程忙碌，无法执行其他任务。


x86 的 IN/OUT 指令可以传输 8 位、16 位或 32 位数据。REP INSB/OUTSB 指令支持字符串形式的批量端口 I/O，在每次迭代中自动递增内存地址。即使使用 REP 前缀，处理器仍然全程参与——每次总线事务都需要处理器发起。PIO 模式在 IDE 硬盘时代（PIO Mode 0-4）曾是主流，最大传输速率仅 16.7 MB/s。


轮询（Polling）是编程 I/O 中检测设备状态的方法。处理器反复读取设备的状态寄存器，检查设备是否就绪（忙等待 busy-waiting）。轮询的伪代码逻辑为：循环读取状态寄存器 → 如果设备就绪则传输数据 → 否则继续循环。


轮询的优点是实现简单、延迟可预测（没有中断处理的开销）。缺点是处理器在等待设备就绪期间完全浪费。如果设备操作需要 1ms，而处理器时钟为 3GHz，轮询将浪费 3000000 个时钟周期。


对于非常高速的设备（如高频交易网卡），轮询反而比中断更高效。中断处理需要保存上下文、调用中断服务例程、恢复上下文，开销约 1-10 微秒。如果数据到达的频率极高（每微秒多次），中断开销占比过大。此时使用轮询（或混合模式 NAPI）更为合适。


Linux 网络子系统的 NAPI（New API）就是轮询和中断的混合方案。正常情况下使用中断通知数据到达。当网络流量突增时，NAPI 切换为轮询模式——关闭中断，处理器主动轮询网卡收包队列。处理完所有待处理的包后，重新启用中断。这避免了高负载下的"中断风暴"，同时在低负载下保持中断的低延迟响应。


DPDK（Data Plane Development Kit）完全绕过内核网络协议栈，在用户态使用纯轮询模式驱动网卡。它通过 mmap() 将网卡的 MMIO 区域映射到用户空间，用户态程序直接读写设备寄存器。DPDK 可以实现 10-100Gbps 线速包处理，延迟低至数微秒，是高频交易和 NFV 的关键技术。


I/O 总线与互连
I/O 设备通过总线层次结构连接到处理器。现代系统采用层次化的总线结构，高速设备直连处理器，低速设备通过桥接芯片级联。这种层次化设计平衡了高速设备的带宽需求和低速设备的成本约束。


PCIe（PCI Express）是当前主流的高速 I/O 互连标准。PCIe 使用点对点的串行链路，每条链路（Lane）由一对差分信号线组成。设备可以使用 x1、x4、x8 或 x16 配置。PCIe 5.0 的单 Lane 带宽约 4 GB/s，x16 配置可达 64 GB/s。PCIe 6.0 将单 Lane 带宽翻倍至约 8 GB/s，采用 PAM4（4 级脉冲幅度调制）编码代替 NRZ 编码。


PCIe 协议栈分为三层：事务层（Transaction Layer）处理读写请求和完成包；数据链路层（Data Link Layer）提供流控和错误检测（CRC）；物理层（Physical Layer）处理串行化、均衡和时钟恢复。PCIe TLP（Transaction Layer Packet）是数据传输的基本单元，最大载荷（Max Payload Size）通常为 128-512 字节。


PCIe 的树形拓扑由 Root Complex（连接处理器）、Switch（扩展端口）和 Endpoint（设备）组成。Root Complex 通常集成在处理器或芯片组中，提供根端口（Root Port）。Switch 用于在多个设备之间共享有限的 PCIe Lane。


USB（Universal Serial Bus）是中低速外设的标准接口。USB 3.2 Gen 2x2 提供 20 Gbps 带宽，USB4 基于 Thunderbolt 3 提供 40 Gbps。USB 使用主从架构，所有传输由主机（Host）发起。USB 的层次化拓扑通过 Hub 扩展端口数量，最多支持 127 个设备。USB Type-C 物理接口统一了连接形态，支持 USB、Thunderbolt、DisplayPort 和 PD 充电的多协议复用。


CXL（Compute Express Link）构建在 PCIe 物理层之上，提供三种协议类型：CXL.io 兼容 PCIe 协议用于设备发现和配置；CXL.cache 允许设备缓存主机内存（加速器场景）；CXL.mem 允许主机访问设备内存（内存扩展场景）。CXL 3.0 引入了内存共享和热插拔能力，进一步推动了内存解耦和池化架构的发展。在数据中心场景下，CXL 允许将 DRAM 作为独立的可组合资源，按需分配给不同的计算节点。

小结
    

  • I/O 系统面临处理器与设备之间数十到数百万倍的速度差距，数据传输技术从 PIO 到中断到 DMA 逐步解放处理器
    • 

  • MMIO 统一了内存和 I/O 的编程模型，但 MMIO 区域必须标记为不可缓存以确保正确的设备交互语义
    • 

  • 不同设备类型需要不同的内存属性标记（UC、WC、Device-nGnRnE），选择错误会导致数据不一致或性能下降
    • 

  • 编程 I/O 在超高频数据到达场景（如高频交易）下因避免中断开销反而更优，DPDK 是极致轮询的代表
    • 

  • PCIe 是高速 I/O 的主流标准，点对点串行架构和分层协议提供高带宽和可扩展性
    • 

  • CXL 在 PCIe 物理层上构建了缓存一致性和内存访问协议，连接加速器和内存扩展设备
    • 

  • 理解 I/O 技术帮助开发者在性能敏感场景中选择正确的设备交互策略
    •
