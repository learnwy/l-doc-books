逻辑基础

核心概念

形式化方法的理论根基是数理逻辑。逻辑为推理提供了严格的语法规则和语义解释，使得我们能够以机械化的方式判断论证的有效性。在形式化方法中，逻辑不仅用于描述系统属性，还用于构造证明、定义规约语言的语义，以及驱动自动化验证工具。

理解逻辑基础对于掌握形式化方法至关重要——模型检测基于时序逻辑，定理证明基于高阶逻辑，程序验证基于 Hoare 逻辑。不同的逻辑体系为不同的验证任务提供了合适的表达框架。

命题逻辑与 SAT 求解
命题逻辑是最基础的逻辑系统，它研究命题之间通过逻辑联结词（¬, ∧, ∨, →, ↔）构成的复合命题的真值。命题逻辑的一个核心问题是可满足性问题（SAT）：给定一个命题公式，是否存在一组变量赋值使得公式为真。


SAT 问题虽然是 NP 完全问题，但现代 SAT 求解器通过 DPLL 算法及其改进（CDCL——冲突驱动子句学习）能够高效处理包含数百万变量的实例。SAT 求解是许多形式化验证工具的底层引擎。


DPLL 算法的核心流程：


function DPLL(φ):
    φ ← unit_propagation(φ)    // 单元传播
    φ ← pure_literal_assign(φ) // 纯文字赋值
    if φ is empty: return SAT
    if φ contains empty clause: return UNSAT
    l ← choose_literal(φ)      // 选择分支变量
    if DPLL(φ ∧ l) == SAT: return SAT
    return DPLL(φ ∧ ¬l)        // 回溯
CDCL 在此基础上增加了冲突分析和非时序回溯（non-chronological backtracking），通过学习导致冲突的子句来剪枝搜索空间。现代求解器如 MiniSat、Glucose 和 CaDiCaL 都基于 CDCL 框架。


SAT 求解在硬件验证中应用广泛。例如，验证两个电路是否等价可以转化为：构造一个命题公式，当且仅当两个电路在某个输入下输出不同时可满足。如果 SAT 求解器返回 UNSAT，则证明两个电路等价。


一阶谓词逻辑与 SMT
一阶谓词逻辑在命题逻辑基础上引入了变量、量词（∀, ∃）和谓词符号，极大地增强了表达能力。形式化规约语言（如 Z、VDM-SL、Alloy）本质上都是一阶逻辑的特化版本。


一阶逻辑的关键概念包括项（Term）、原子公式（Atomic Formula）、量化公式和自由变量/约束变量。一阶逻辑的推理系统通常基于自然演绎或相继式演算：


∀x. (Human(x) → Mortal(x))    // 所有人都是会死的
Human(Socrates)                 // 苏格拉底是人
─────────────────────────────── // Modus Ponens + ∀-消除
Mortal(Socrates)                // 苏格拉底是会死的
SMT（Satisfiability Modulo Theories）是 SAT 问题在一阶逻辑理论上的扩展。SMT 求解器不仅处理布尔逻辑，还能理解特定的数学理论，如线性算术、位向量、数组和未解释函数。

Z3 求解器是目前最强大的 SMT 求解器之一，广泛用于 Dafny、KLEE、Seahorn 等验证工具的后端。它支持多种理论的组合推理，能够自动处理复杂的约束求解问题。


Hoare 逻辑与程序验证
Hoare 逻辑（也称 Floyd-Hoare 逻辑）是 1969 年由 Tony Hoare 提出的程序正确性推理系统。它使用三元组 {P} S {Q}（Hoare Triple）来表达程序的部分正确性：如果程序 S 在满足前置条件 P 的状态下执行，且 S 终止，则终止状态满足后置条件 Q。


Hoare 逻辑的核心推理规则：


赋值规则:  {Q[x/E]} x := E {Q}

顺序规则:  {P} S1 {R}    {R} S2 {Q}
          ─────────────────────────
               {P} S1;S2 {Q}

条件规则:  {P ∧ B} S1 {Q}    {P ∧ ¬B} S2 {Q}
          ──────────────────────────────────
              {P} if B then S1 else S2 {Q}

循环规则:  {I ∧ B} S {I}
          ────────────────────
          {I} while B do S {I ∧ ¬B}

加强前置条件:  P → P'    {P'} S {Q}
              ───────────────────
                  {P} S {Q}
循环不变式（Loop Invariant）是 Hoare 逻辑中最关键也最困难的部分。不变式 I 必须满足三个条件：循环开始前成立（初始化）、每次循环体执行后仍然成立（保持）、与循环终止条件结合能推出后置条件（终止利用）。


以二分搜索为例的 Hoare 逻辑推理：


function binarySearch(a: number[], key: number): number {
  let lo = 0;
  let hi = a.length;
  // {lo = 0 ∧ hi = a.length ∧ sorted(a)}
  while (lo < hi) {
    // 不变式 I: 0 ≤ lo ≤ hi ≤ a.length ∧
    //           ∀i < lo. a[i] < key ∧
    //           ∀i ≥ hi. a[i] ≥ key
    const mid = lo + Math.floor((hi - lo) / 2);
    if (a[mid] < key) {
      lo = mid + 1;
    } else {
      hi = mid;
    }
  }
  // {I ∧ lo ≥ hi} → lo 是 key 的插入位置
  return lo;
}
现代程序验证工具如 Dafny、Frama-C 和 KeY 都基于 Hoare 逻辑的扩展。Dafny 允许程序员直接在代码中编写前置条件、后置条件和循环不变式，然后自动调用 Z3 进行验证。


分离逻辑与指针推理
分离逻辑（Separation Logic）是 Hoare 逻辑的重要扩展，专门用于推理指针操作和堆内存。它由 John Reynolds 和 Peter O'Hearn 在 2002 年提出，引入了分离合取（Separating Conjunction）* 和魔棒运算符（Magic Wand）-*。

分离逻辑最重要的推理规则是 Frame Rule（框架规则）：


      {P} S {Q}
─────────────────────
  {P * R} S {Q * R}
这个规则表明：如果程序 S 只操作 P 描述的堆区域，那么任何不相交的堆区域 R 在 S 执行前后保持不变。这使得局部推理（Local Reasoning）成为可能——我们只需要关注程序实际操作的内存部分。


Facebook（Meta）开发的 Infer 工具就是基于分离逻辑的自动化程序分析工具。Infer 能够在代码审查阶段自动检测空指针解引用、内存泄漏和数据竞争等问题，已经在 Facebook、Amazon 和 Uber 等公司的代码仓库中部署使用。


分离逻辑的发展方向包括并发分离逻辑（Concurrent Separation Logic）和 Iris 框架，它们为并发程序的形式化验证提供了强大的理论基础。Rust 语言的所有权系统在某种程度上就是分离逻辑思想在类型系统层面的体现。


小结
    

  • 命题逻辑和 SAT 求解是形式化验证的基础引擎，CDCL 算法使得大规模 SAT 实例的求解成为可能
    • 

  • 一阶谓词逻辑为规约语言提供了表达框架，SMT 求解器扩展了自动推理的理论范围
    • 

  • Hoare 逻辑通过前置条件、后置条件和循环不变式实现程序正确性的严格推理
    • 

  • 分离逻辑引入分离合取解决了指针和堆内存的推理难题，使局部推理成为可能
    • 

  • 不同逻辑体系在表达能力和可判定性之间存在权衡，选择合适的逻辑是形式化方法的关键决策
    • 

  • 现代工具（Z3、Dafny、Infer）将逻辑推理自动化，降低了形式化方法的使用门槛
    •
