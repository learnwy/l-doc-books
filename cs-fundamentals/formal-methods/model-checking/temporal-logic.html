时序逻辑

核心概念

时序逻辑（Temporal Logic）是一类能够表达随时间变化的属性的逻辑体系。在形式化方法中，时序逻辑是连接系统模型和期望属性的桥梁——它提供了精确描述"系统应该如何随时间演化"的形式化语言。时序逻辑最早由 Amir Pnueli 在 1977 年引入计算机科学领域，他因此获得了 1996 年图灵奖。

时序逻辑的两大分支是线性时序逻辑（LTL）和计算树逻辑（CTL）。LTL 关注单条执行路径上的属性，而 CTL 关注执行树中的分支结构。两者在表达能力上存在不可比较的关系——各自能表达对方无法表达的属性。

线性时序逻辑 LTL
LTL 在命题逻辑基础上增加了四个基本的时序算子：X（Next，下一时刻）、F（Finally，最终会）、G（Globally，全局始终）和 U（Until，直到）。LTL 公式在无限执行路径 π = s₀, s₁, s₂, ... 上解释。


LTL 算子的形式化语义：


π, i ⊨ Xφ     iff  π, i+1 ⊨ φ
π, i ⊨ Fφ     iff  ∃j ≥ i. π, j ⊨ φ
π, i ⊨ Gφ     iff  ∀j ≥ i. π, j ⊨ φ
π, i ⊨ φ U ψ  iff  ∃j ≥ i. (π, j ⊨ ψ ∧ ∀k. i ≤ k < j → π, k ⊨ φ)
通过这四个基本算子的组合，可以表达丰富的系统属性。常见的 LTL 属性模式：

LTL 模型检测的经典方法是将 LTL 公式转换为等价的 Büchi 自动机。Büchi 自动机是接受无限字（ω-字）的有限自动机，它的接受条件是：一条无限运行中，某个接受状态被无穷次访问。


转换算法（如 Gerth 等人的 LTL2BA 算法、Gastin-Oddoux 算法）的核心步骤：

  3. 构造广义 Büchi 自动机（LGBA）

SPIN 模型检测器使用 Promela 语言描述系统模型，使用 LTL 公式描述属性。SPIN 在通信协议验证领域有广泛应用，例如验证电话交换协议、网络路由协议等。


计算树逻辑 CTL
CTL 与 LTL 的根本区别在于：CTL 的时序算子必须紧跟路径量词。路径量词 A（All paths，所有路径）和 E（Exists a path，存在某条路径）决定了属性是在所有可能执行中成立还是在某条执行中成立。


CTL 的基本算子组合（共 8 个）：


AX φ  -- 在所有后继状态中 φ 成立
EX φ  -- 在某个后继状态中 φ 成立
AF φ  -- 在所有路径上最终 φ 成立
EF φ  -- 存在某条路径最终 φ 成立
AG φ  -- 在所有路径上始终 φ 成立
EG φ  -- 存在某条路径始终 φ 成立
A[φ U ψ]  -- 在所有路径上 φ 直到 ψ
E[φ U ψ]  -- 存在某条路径 φ 直到 ψ
CTL 模型检测算法基于不动点计算，核心思想是将 CTL 公式分解为嵌套的最大不动点（νZ）和最小不动点（μZ）计算：


EF φ = μZ. (φ ∨ EX Z)          // 最小不动点
AG φ = νZ. (φ ∧ AX Z)          // 最大不动点
E[φ U ψ] = μZ. (ψ ∨ (φ ∧ EX Z))  // 最小不动点
A[φ U ψ] = μZ. (ψ ∨ (φ ∧ AX Z ∧ EX true))  // 最小不动点 + 公平性
CTL 模型检测的复杂度是 O(|M| × |φ|)——与模型大小和公式大小的乘积成线性关系。这比 LTL 模型检测的 PSPACE 复杂度低得多，是 CTL 的重要优势之一。

CTL* 与 μ-演算
CTL* 是 LTL 和 CTL 的共同推广——它允许路径量词和时序算子的任意组合。在 CTL* 中，LTL 公式可以看作以 A 量化的路径公式，CTL 公式是 CTL* 的语法受限子集。


CTL* 的表达能力严格强于 LTL 和 CTL：


LTL 可表达但 CTL 不可: FGp（最终永远成立）
CTL 可表达但 LTL 不可: AG(EF reset)（总是可以到达 reset 状态）
CTL* 可表达两者均不可: A(GFp → GFq)（公平性条件下的活性）
μ-演算（mu-calculus）是时序逻辑中表达能力最强的逻辑，它直接使用不动点算子 μ（最小不动点）和 ν（最大不动点）来定义属性。所有 CTL* 属性都可以在 μ-演算中表达，但 μ-演算还能表达更复杂的递归属性。


μ-演算的语法通过不动点变量和模态算子构建：


μX. (p ∨ ◇X)     // 等价于 EF p —— 最终可达 p
νX. (p ∧ □X)     // 等价于 AG p —— 始终满足 p
νX. μY. ((p ∧ X) ∨ (q ∧ ◇Y))  // 嵌套不动点 —— CTL* 的 A(Gp ∨ Fq)
实时时序逻辑
实时时序逻辑扩展了经典时序逻辑，增加了对时间约束的定量表达能力。在实时系统（如汽车制动控制、心脏起搏器、航空电子设备）中，不仅需要保证"最终会响应"，还需要保证"在 10 毫秒内响应"。


TCTL（Timed CTL）是 CTL 的实时扩展，它在时间自动机模型上解释。TCTL 的时序算子带有时间区间约束：


AF≤5 alarm        // 在所有路径上，5 个时间单位内 alarm 成立
AG(req → AF≤10 ack)  // 每次请求后 10 个时间单位内必须响应
E[¬error U≤3 recovery]  // 存在路径在 3 个时间单位内从 ¬error 到 recovery
MTL（Metric Temporal Logic）是 LTL 的实时扩展，直接在 LTL 算子上添加时间区间：

UPPAAL 是最广泛使用的实时系统模型检测工具。它使用时间自动机网络作为建模语言，支持 TCTL 属性检查。UPPAAL 在工业中的应用包括飞利浦音频协议验证、Bang & Olufsen 多媒体协议验证等。


信号时序逻辑（STL, Signal Temporal Logic）将时序逻辑扩展到连续信号域，适合混合系统（Hybrid System）的验证。STL 的原子命题是实值信号上的不等式约束，如 G[0,10](speed < 60)表示在前 10 秒内速度始终低于 60。


小结
    

  • LTL 在单条执行路径上描述属性，适合表达安全性、活性和公平性
    • 

  • CTL 通过路径量词描述执行树的分支结构，模型检测复杂度更低
    • 

  • LTL 和 CTL 在表达能力上不可比较，各有独有能表达的属性
    • 

  • CTL* 统一了 LTL 和 CTL，μ-演算提供了最强的表达能力
    • 

  • 实时时序逻辑（TCTL、MTL）增加了定量时间约束，适合实时系统验证
    • 

  • UPPAAL 工具支持时间自动机建模和 TCTL 属性检查，在工业实时系统验证中广泛应用
    • 

  • 选择时序逻辑需要权衡表达能力、模型检测复杂度和工具支持
