Coq 与 Lean

核心概念

Coq 和 Lean 是当前最有影响力的两个基于依赖类型论的证明助手。Coq 由 INRIA 团队开发，拥有 30 多年的历史和丰富的工业验证成果；Lean 由 Leonardo de Moura 在微软研究院创建，以其现代化的设计和活跃的数学社区著称。两者都基于 Curry-Howard 对应，但在设计哲学和使用体验上存在显著差异。

对于程序员而言，理解 Coq 和 Lean 不仅有助于进行程序验证，还能深化对类型系统、函数式编程和逻辑推理的理解。这些知识在日常编程中也有实际价值——TypeScript 的条件类型、Rust 的生命周期系统都是依赖类型思想的简化体现。

Coq 深入实践
Coq 的核心语言 Gallina 是一种纯函数式编程语言，所有函数必须是全函数（Total Function）——即对所有合法输入都能终止并返回结果。这个限制保证了 Coq 作为逻辑系统的一致性（Consistency），但也意味着需要额外的技巧来处理部分函数和一般递归。


Coq 中定义自然数上的加法和证明其结合律：


Fixpoint add (n m : nat) : nat :=
  match n with
  | O => m
  | S n' => S (add n' m)
  end.

Theorem add_assoc : forall n m p : nat,
  add n (add m p) = add (add n m) p.
Proof.
  intros n m p.
  induction n as [| n' IHn'].
  - simpl. reflexivity.
  - simpl. rewrite IHn'. reflexivity.
Qed.
Coq 的归纳类型（Inductive Type）是其类型系统的核心特征。通过归纳类型可以定义自然数、列表、树等递归数据结构，以及逻辑连接词（合取、析取、存在量词等）：


Inductive list (A : Type) : Type :=
  | nil : list A
  | cons : A -> list A -> list A.

Inductive sorted : list nat -> Prop :=
  | sorted_nil : sorted nil
  | sorted_single : forall x, sorted (cons x nil)
  | sorted_cons : forall x y xs,
      x <= y -> sorted (cons y xs) -> sorted (cons x (cons y xs)).
Coq 的代码提取（Extraction）机制可以将 Coq 中验证过的程序提取为 OCaml、Haskell 或 Scheme 代码。CompCert 项目就是通过这一机制将 Coq 中验证的 C 编译器提取为可执行的 OCaml 程序。

Lean 4 深入实践
Lean 4 是 Lean 的完全重写版本，它不仅是一个证明助手，还是一门通用编程语言。Lean 4 的独特设计使得同一个语言既可以写数学证明，也可以写系统程序——甚至 Lean 4 的编译器本身就是用 Lean 4 编写的（自举）。


Lean 4 的语法现代且直观，结合了定理证明和函数式编程的优点：


def add : Nat → Nat → Nat
  | n, 0 => n
  | n, m + 1 => (add n m) + 1

theorem add_assoc (n m p : Nat) : add n (add m p) = add (add n m) p := by
  induction p with
  | zero => simp [add]
  | succ p ih => simp [add, ih]
Lean 4 的 Monad 和 do 记法使得带副作用的编程自然融入依赖类型框架：


def readAndParse (filename : String) : IO (Except String Nat) := do
  let content ← IO.FS.readFile filename
  let trimmed := content.trim
  match trimmed.toNat? with
  | some n => return .ok n
  | none => return .error s!"Cannot parse '{trimmed}' as natural number"
Lean 4 的宏系统和 elaboration 机制提供了强大的元编程能力。用户可以定义新的策略、语法扩展和自动化工具：


macro "trivial" : tactic =>
  `(tactic| first | assumption | simp | decide | omega)

example (h : P) : P := by trivial
example : 2 + 3 = 5 := by trivial
example : ¬(3 < 2) := by trivial
Lean 4 与 Coq 的一个关键区别是其对公理的灵活态度。Lean 4 默认包含排中律（Classical Logic）和选择公理，而 Coq 默认是构造性逻辑，需要显式导入经典公理。


程序验证实战
使用 Coq 或 Lean 进行程序验证的完整工作流包括：定义数据结构和函数、编写规约（定理声明）、构造证明。以下通过验证一个简单的排序算法来展示完整流程。


在 Lean 4 中定义和验证插入排序：


def insert (x : Nat) : List Nat → List Nat
  | [] => [x]
  | y :: ys =>
    if x ≤ y then x :: y :: ys
    else y :: insert x ys

def insertionSort : List Nat → List Nat
  | [] => []
  | x :: xs => insert x (insertionSort xs)

theorem insert_sorted (x : Nat) (xs : List Nat) (h : Sorted xs) :
    Sorted (insert x xs) := by
  induction xs with
  | nil => exact Sorted.single x
  | cons y ys ih =>
    simp [insert]
    split
    · exact Sorted.cons (by assumption) h
    · exact Sorted.cons (by omega) (ih (sorted_tail h))

theorem insertionSort_sorted (xs : List Nat) :
    Sorted (insertionSort xs) := by
  induction xs with
  | nil => exact Sorted.nil
  | cons x xs ih => exact insert_sorted x _ ih
实际的程序验证项目通常还需要证明排列性（Permutation）——即排序后的列表包含与输入相同的元素。这需要定义排列关系并证明每个操作保持这一关系。

小结
    

  • Coq 基于归纳构造演算，拥有成熟的工业验证生态，CompCert 是其标志性成果
    • 

  • Lean 4 是证明助手与通用编程语言的融合，编译到 C 语言可直接执行
    • 

  • 两者都支持策略式和项式证明，Lean 4 的语法更现代化
    • 

  • Coq 默认构造性逻辑，Lean 4 默认经典逻辑，各有适用场景
    • 

  • 程序验证需要定义函数、编写规约、构造证明三个步骤
    • 

  • 形式化验证的成本较高，通常用于安全关键系统或基础设施软件
    • 

  • Mathlib 和 mathcomp 分别是 Lean 和 Coq 生态中最重要的数学库
    •
