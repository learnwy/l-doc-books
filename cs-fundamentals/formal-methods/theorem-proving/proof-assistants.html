证明助手

核心概念

证明助手（Proof Assistant），也称为交互式定理证明器（Interactive Theorem Prover），是辅助人类构造和验证数学证明的软件系统。与模型检测不同，证明助手能够处理无限状态空间的系统，但通常需要人类提供证明策略的指导。证明助手已经被用于验证操作系统内核、编译器、数学定理等高度复杂的系统。

证明助手的理论基础是 Curry-Howard 对应（Curry-Howard Correspondence）——命题即类型、证明即程序。这一深刻的对应关系意味着：验证一个定理等价于构造一个具有特定类型的程序，而类型检查器可以自动验证证明的正确性。

在依赖类型系统中，类型可以依赖于值。例如，Vec n 表示长度为 n 的向量类型。这使得类型系统能够精确地表达程序的规约——如果一个函数的类型是 (xs : Vec n) → (ys : Vec m) → Vec (n + m)，那么类型检查器就自动保证了该函数将两个向量拼接后长度正确。


依赖类型的表达能力远超普通类型系统。在 Lean 中，可以直接在类型中编码复杂的逻辑属性：


def sort (xs : List Nat) : { ys : List Nat // Sorted ys ∧ Perm xs ys } :=
  -- 返回值的类型保证了：输出是有序的，且是输入的排列
  ...
这种"规约即类型"的编程风格使得程序的正确性成为编译时的类型检查问题，从根本上消除了运行时错误的可能。


策略式证明与项式证明
证明助手提供两种主要的证明构造方式：策略式证明（Tactic Proof）和项式证明（Term Proof）。


策略式证明通过一系列策略指令逐步转换证明目标，直到所有子目标都被解决。这种方式更接近人类的数学推理过程：


-- Coq 风格的策略式证明
Theorem add_comm : forall n m : nat, n + m = m + n.
Proof.
  intros n m.           (* 引入变量 *)
  induction n as [|n' IH].
  - simpl. rewrite add_0_r. reflexivity.
  - simpl. rewrite IH. rewrite add_succ_r. reflexivity.
Qed.
项式证明直接构造证明项（即具有目标类型的程序），更接近函数式编程的风格：


-- Lean 风格的项式证明
theorem add_comm (n m : Nat) : n + m = m + n := by
  induction n with
  | zero => simp [Nat.zero_add, Nat.add_zero]
  | succ n ih => simp [Nat.succ_add, Nat.add_succ, ih]
自动化策略是提高证明效率的关键。Isabelle 的 Sledgehammer 工具能够自动调用外部 ATP（自动定理证明器）和 SMT 求解器来搜索证明，然后将找到的证明翻译回 Isabelle 的证明语言。这种人机协作的方式大大提高了证明的效率。

形式化数学
证明助手在形式化数学领域取得了里程碑式的成果。形式化数学的目标是将数学定理的证明完全转化为机器可检验的形式，消除传统数学证明中可能存在的逻辑漏洞。


重要的形式化数学成果：


    

  • 四色定理（2005, Coq）：Georges Gonthier 使用 Coq 完成了四色定理的完全形式化证明。四色定理的传统证明依赖大量计算机辅助的案例检查，形式化版本确保了这些计算的正确性。
    

    • 

  • Feit-Thompson 定理（2012, Coq）：奇数阶定理的形式化证明，是数学史上最大的形式化证明项目之一，证明脚本超过 17 万行。
    

    • 

  • Kepler 猜想（2014, HOL Light + Isabelle）：Thomas Hales 的 Flyspeck 项目完成了 Kepler 猜想的完全形式化验证。
    

    • 

  • Liquid Tensor Experiment（2022, Lean）：Peter Scholze 提出的凝聚数学中的一个关键引理在 Lean 中被形式化验证。
    

    • 



Lean 的 Mathlib 库已经成为最大的形式化数学库之一，包含超过 10 万个定理和定义。Mathlib 覆盖了本科和研究生数学的大部分内容，包括线性代数、实分析、点集拓扑、代数数论等。


小结
    

  • 证明助手通过 Curry-Howard 对应将证明转化为程序，利用类型检查保证证明的正确性
    • 

  • 依赖类型系统能够在类型中编码复杂的逻辑属性，实现"规约即类型"
    • 

  • 策略式证明接近人类推理，项式证明接近函数式编程，两者互补使用
    • 

  • 自动化策略（如 Sledgehammer）通过调用 ATP 和 SMT 求解器提高证明效率
    • 

  • 形式化数学已验证了四色定理、奇数阶定理等重大数学成果
    • 

  • Lean 的 Mathlib 库正在快速增长，推动形式化数学的大规模发展
    • 

  • 证明助手是验证安全关键软件正确性的终极手段
    •
