实时约束与时序分析

核心概念

实时系统的正确性不仅取决于计算结果的逻辑正确性，还取决于结果产生的时间。硬实时系统（Hard Real-Time）要求所有任务必须在截止时间之前完成，违反即视为系统失败；软实时系统（Soft Real-Time）允许偶尔错过截止时间，但会导致服务质量下降。时序分析是验证系统能否满足所有实时约束的关键方法。

WCET 最坏执行时间分析
WCET（Worst-Case Execution Time）是实时系统时序分析的基石。所有调度理论都建立在已知每个任务 WCET 的前提上。WCET 分析分为静态分析和基于测量的两大方法。


静态分析方法
静态 WCET 分析通过程序控制流分析和硬件时序模型，在不执行程序的情况下推导执行时间上界：


// 示例：分析此函数的 WCET
void process_packet(uint8_t *buf, uint16_t len) {
    uint16_t checksum = 0;
    for (uint16_t i = 0; i < len; i++) {      // 循环上界：len ≤ MAX_PACKET_SIZE
        checksum += buf[i];
        if (buf[i] == ESCAPE_CHAR) {           // 条件分支
            checksum += buf[++i];              // 最坏路径
        }
    }
    if (checksum != expected) {
        retransmit_request();                  // WCET 更大的分支
    }
}
// WCET = 循环上界 × 最坏迭代时间 + 最坏分支时间

openocd -f target/stm32f4x.cfg -c "etm config trace_all"

# 软件插桩测量
# 在函数入口/出口读取 DWT Cycle Counter
// ARM Cortex-M DWT 周期计数器
#define DWT_CYCCNT (*(volatile uint32_t *)0xE0001004)
#define DWT_CONTROL (*(volatile uint32_t *)0xE0001000)

void enable_cycle_counter(void) {
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT_CYCCNT = 0;
    DWT_CONTROL |= 1;
}

uint32_t measure_wcet(void (*func)(void)) {
    uint32_t max_cycles = 0;
    for (int trial = 0; trial < 10000; trial++) {
        uint32_t start = DWT_CYCCNT;
        func();
        uint32_t elapsed = DWT_CYCCNT - start;
        if (elapsed > max_cycles) max_cycles = elapsed;
    }
    return max_cycles;  // 加安全裕度：max_cycles × 1.2
}

响应时间分析
响应时间分析（Response Time Analysis, RTA）是判定固定优先级系统可调度性的精确方法。任务的响应时间包括自身执行时间、高优先级任务的抢占时间和资源阻塞时间。


计算公式
Ri = Ci + Bi + Σ(⌈Ri/Tj⌉ × Cj)  对所有优先级高于 i 的任务 j

其中：
  Ri = 任务 i 的最坏响应时间
  Ci = 任务 i 的 WCET
  Bi = 任务 i 的最大阻塞时间（优先级反转）
  Tj = 高优先级任务 j 的周期
  Cj = 高优先级任务 j 的 WCET

可调度条件：Ri ≤ Di（响应时间 ≤ 截止时间）
迭代求解示例
任务集：τ1(T=10,C=2), τ2(T=20,C=5), τ3(T=50,C=10)

求 τ3 的响应时间：
R3^0 = C3 = 10
R3^1 = 10 + ⌈10/10⌉×2 + ⌈10/20⌉×5 = 10 + 2 + 5 = 17
R3^2 = 10 + ⌈17/10⌉×2 + ⌈17/20⌉×5 = 10 + 4 + 5 = 19
R3^3 = 10 + ⌈19/10⌉×2 + ⌈19/20⌉×5 = 10 + 4 + 5 = 19（收敛）

R3 = 19ms ≤ D3 = 50ms → 可调度

小结
    

  • 实时系统的正确性同时包含逻辑正确性和时间正确性，时序违反可能导致灾难性后果
    • 

  • WCET 分析是时序验证的基石，静态分析保证安全但可能过度悲观，测量法需要加安全裕度
    • 

  • 响应时间分析（RTA）是精确判定固定优先级系统可调度性的标准方法
    • 

  • 端到端延迟分析需要考虑完整任务链上的所有延迟分量，包括采样、计算、通信和执行延迟
    • 

  • 安全关键系统（DO-178C、ISO 26262）要求形式化的时序分析和 WCET 证据
    • 

  • 多核系统的时序分析需额外考虑核间通信延迟和共享资源争用
    •
