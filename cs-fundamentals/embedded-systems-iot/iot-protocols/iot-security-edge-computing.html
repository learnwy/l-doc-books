IoT 安全与边缘计算

核心概念

IoT 安全和边缘计算是物联网从原型走向规模化部署的两大关键挑战。IoT 设备因计算资源受限、物理环境暴露、大规模部署等特点，面临独特的安全威胁。边缘计算通过在靠近数据源的位置处理数据，降低延迟、减少带宽消耗并提升隐私保护。两者的结合是构建安全、高效 IoT 系统的基础。

设备安全
安全启动链
安全启动确保从上电到应用运行的每一步都经过验证——防止被篡改的固件运行：


// 安全启动流程
// 1. ROM Bootloader（芯片内置，不可篡改）
//    → 验证第一级 Bootloader 签名
// 2. 第一级 Bootloader
//    → 验证应用固件签名
// 3. 应用固件启动

// MCUboot（Zephyr/通用安全引导）
// 支持 RSA/ECDSA 签名验证
// 支持 A/B 双分区回退

// STM32 安全启动示例
// 使用 OTP 区域存储公钥哈希
// HAL_FLASH_OB_Lock() 锁定调试接口
硬件安全模块
// ARM TrustZone（Cortex-M33+）
// 将芯片分为安全区（Secure World）和非安全区（Non-Secure World）
// 密钥存储、加密操作在安全区执行

// 外部安全芯片
// ATECC608 (Microchip) — 硬件 ECC-P256
// SE050 (NXP) — Java Card 安全元件
// TPM 2.0 — 可信平台模块

// ATECC608 使用示例
atcab_init(&cfg_atecc608);
atcab_random(random_number);
atcab_sign(key_slot, digest, signature);
atcab_verify_extern(digest, signature, public_key, &verified);

OTA 固件更新
安全的 OTA（Over-The-Air）更新是 IoT 设备生命周期管理的核心能力：


// OTA 更新流程
// 1. 服务器签名固件镜像（ECDSA-P256）
// 2. 设备下载镜像到备用分区
// 3. 验证签名完整性
// 4. 设置引导标志，重启
// 5. Bootloader 验证新固件，切换启动分区
// 6. 新固件启动自检，确认后标记为有效
// 7. 自检失败则回退到旧固件

// 分区布局
// Flash 地址空间：
// [Bootloader] [App Slot A] [App Slot B] [Scratch]
//   16KB         240KB        240KB        16KB

边缘计算架构
边缘计算在设备端或网关处执行数据处理和推理，减少对云端的依赖：


// 边缘 AI 推理（TensorFlow Lite Micro）
#include "tensorflow/lite/micro/micro_interpreter.h"

constexpr int kTensorArenaSize = 10 * 1024;
uint8_t tensor_arena[kTensorArenaSize];

void runInference(float *input_data) {
    tflite::MicroInterpreter interpreter(model, resolver,
        tensor_arena, kTensorArenaSize);
    interpreter.AllocateTensors();

    TfLiteTensor *input = interpreter.input(0);
    memcpy(input->data.f, input_data, input->bytes);

    interpreter.Invoke();

    TfLiteTensor *output = interpreter.output(0);
    float anomaly_score = output->data.f[0];

    if (anomaly_score > THRESHOLD) {
        sendAlert();
    }
}

小结
    

  • IoT 安全需要从设备（安全启动、硬件安全模块）、通信（TLS/DTLS）和云端（认证授权）三层防护
    • 

  • 安全启动链确保从 ROM 到应用的每一步都经过签名验证，防止被篡改固件运行
    • 

  • OTA 更新采用 A/B 双分区策略实现失败回退，固件必须经过签名验证
    • 

  • 边缘计算在设备端执行推理和预处理，降低延迟和带宽消耗
    • 

  • TensorFlow Lite Micro 使 MCU 级设备也能运行轻量级 AI 推理（如异常检测）
    • 

  • IoT 平台选择取决于规模和控制需求——小规模自建（EMQX），大规模用云平台（AWS/Azure）
    •
