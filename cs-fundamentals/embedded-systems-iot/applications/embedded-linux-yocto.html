嵌入式 Linux 与 Yocto

核心概念

嵌入式 Linux 是将 Linux 操作系统裁剪并适配到资源受限硬件上的技术实践。与 MCU 上的 RTOS 不同，嵌入式 Linux 运行在具有 MMU 的处理器上（如 ARM Cortex-A 系列），提供完整的进程隔离、文件系统、网络协议栈和驱动模型。Yocto Project 是构建定制嵌入式 Linux 发行版的工业级框架，被 Intel、NXP、TI 等主要芯片厂商采用。

Yocto 构建系统
Yocto 使用 BitBake 构建引擎和分层配方（Recipe）系统来生成完整的 Linux 镜像：


# Yocto 项目初始化
git clone git://git.yoctoproject.org/poky
cd poky
git checkout scarthgap  # LTS 版本
source oe-init-build-env

# 配置目标硬件 (conf/local.conf)
# MACHINE = "raspberrypi4-64"
# DISTRO = "poky"
# IMAGE_INSTALL:append = " python3 nodejs mosquitto"

# 构建最小镜像
bitbake core-image-minimal

# 构建包含完整开发工具的镜像
bitbake core-image-full-cmdline
Yocto 层（Layer）架构：


# 层的组织结构
meta-poky/          # Poky 参考发行版
meta-openembedded/  # 社区软件包
meta-raspberrypi/   # 树莓派 BSP
meta-custom/        # 自定义应用层
  ├── conf/
  │   └── layer.conf
  ├── recipes-core/
  │   └── myapp/
  │       ├── myapp_1.0.bb
  │       └── files/
  │           └── myapp.service
  └── recipes-kernel/
      └── linux/
          └── linux-%.bbappend
配方（Recipe）示例：


# recipes-core/myapp/myapp_1.0.bb
SUMMARY = "My IoT Application"
LICENSE = "MIT"
LIC_FILES_CHKSUM = "file://LICENSE;md5=xxx"

SRC_URI = "git://github.com/example/myapp.git;branch=main;protocol=https"
SRCREV = "abc123"
S = "${WORKDIR}/git"

inherit cmake systemd

SYSTEMD_SERVICE:${PN} = "myapp.service"

do_install:append() {
    install -d ${D}${systemd_system_unitdir}
    install -m 0644 ${WORKDIR}/myapp.service ${D}${systemd_system_unitdir}/
}

设备树与驱动
Linux 使用设备树（Device Tree）描述硬件拓扑，替代了早期的硬编码板级信息：


// 设备树片段 (board.dts)
/ {
    model = "Custom IoT Gateway";

    leds {
        compatible = "gpio-leds";
        status-led {
            gpios = <&gpio1 5 GPIO_ACTIVE_HIGH>;
            label = "status";
            linux,default-trigger = "heartbeat";
        };
    };
};

&i2c1 {
    status = "okay";
    clock-frequency = <400000>;

    bme280@76 {
        compatible = "bosch,bme280";
        reg = <0x76>;
    };
};

&spi0 {
    status = "okay";

    spidev@0 {
        compatible = "spidev";
        reg = <0>;
        spi-max-frequency = <10000000>;
    };
};
Linux 驱动模型：


// 简单的平台驱动框架
static int my_sensor_probe(struct platform_device *pdev)
{
    struct device *dev = &pdev->dev;
    struct my_sensor_data *data;

    data = devm_kzalloc(dev, sizeof(*data), GFP_KERNEL);
    if (!data)
        return -ENOMEM;

    data->regmap = devm_regmap_init_i2c(to_i2c_client(dev), &regmap_config);
    platform_set_drvdata(pdev, data);

    return devm_iio_device_register(dev, data->indio_dev);
}

static const struct of_device_id my_sensor_of_match[] = {
    { .compatible = "vendor,my-sensor" },
    { }
};

static struct platform_driver my_sensor_driver = {
    .probe = my_sensor_probe,
    .driver = {
        .name = "my-sensor",
        .of_match_table = my_sensor_of_match,
    },
};
module_platform_driver(my_sensor_driver);

小结
    

  • 嵌入式 Linux 适用于有 MMU 的处理器（Cortex-A），提供完整的进程隔离和丰富的生态
    • 

  • Yocto 是工业级构建系统，通过 Layer + Recipe 模式实现高度可定制化
    • 

  • 设备树描述硬件拓扑，驱动通过 compatible 属性匹配设备
    • 

  • Buildroot 更简单快速，适合原型开发；Yocto 更完整，适合商业产品
    • 

  • 启动时间优化需要 Bootloader + 内核 + 用户空间三层联合优化
    • 

  • 嵌入式 Linux 与 RTOS 不是替代关系——复杂网关用 Linux，实时终端用 RTOS
    •
