嵌入式 C 与 Rust 开发

核心概念

嵌入式系统开发对编程语言有特殊要求：零成本抽象、确定性内存管理、直接硬件访问和可预测的执行时间。C 语言凭借其接近硬件的特性统治嵌入式领域数十年，而 Rust 作为新兴的系统级语言，通过所有权系统在编译期消除内存安全问题，正在成为嵌入式开发的有力替代选择。理解两者在嵌入式场景下的编程范式和工具链差异，有助于为项目做出正确的技术选型。

嵌入式 C 编程模式
寄存器抽象层
嵌入式 C 的核心是通过 volatile 指针访问内存映射的外设寄存器：


typedef struct {
    volatile uint32_t MODER;
    volatile uint32_t OTYPER;
    volatile uint32_t OSPEEDR;
    volatile uint32_t PUPDR;
    volatile uint32_t IDR;
    volatile uint32_t ODR;
    volatile uint32_t BSRR;
    volatile uint32_t LCKR;
    volatile uint32_t AFR[2];
} GPIO_TypeDef;

#define GPIOA ((GPIO_TypeDef *)0x40020000)

void led_toggle(void) {
    GPIOA->ODR ^= (1 << 5);
}

void led_on(void) {
    GPIOA->BSRR = (1 << 5);
}

void led_off(void) {
    GPIOA->BSRR = (1 << (5 + 16));
}
位操作与位带
// 设置位（不影响其他位）
REG |= (1 << BIT_POS);

// 清除位
REG &= ~(1 << BIT_POS);

// 切换位
REG ^= (1 << BIT_POS);

// 读取特定位
uint8_t val = (REG >> BIT_POS) & 0x01;

// 设置多位字段（如 GPIO 模式，每个引脚占 2 位）
GPIOA->MODER &= ~(0x3 << (pin * 2));
GPIOA->MODER |= (mode << (pin * 2));
中断服务例程
volatile uint32_t tick_count = 0;

void SysTick_Handler(void) {
    tick_count++;
}

void USART1_IRQHandler(void) {
    if (USART1->SR & USART_SR_RXNE) {
        uint8_t data = USART1->DR;
        ring_buffer_push(&rx_buf, data);
    }
}

// ISR 规则：

// 3. 共享变量必须 volatile
// 4. 多字节共享变量需要临界区保护

嵌入式 Rust 编程模式
no_std 环境
嵌入式 Rust 使用 #![no_std] 放弃标准库，只保留核心库（core）：


#![no_std]
#![no_main]

use cortex_m_rt::entry;
use panic_halt as _;
use stm32f4xx_hal::{pac, prelude::*};

#[entry]
fn main() -> ! {
    let dp = pac::Peripherals::take().unwrap();
    let rcc = dp.RCC.constrain();
    let clocks = rcc.cfgr.sysclk(84.MHz()).freeze();

    let gpioa = dp.GPIOA.split();
    let mut led = gpioa.pa5.into_push_pull_output();
    let mut delay = dp.TIM2.delay_ms(&clocks);

    loop {
        led.toggle();
        delay.delay_ms(500u32);
    }
}
类型安全的外设访问
Rust 的嵌入式 HAL（Hardware Abstraction Layer）通过类型系统在编译期强制正确的引脚配置：


use stm32f4xx_hal::gpio::{Output, PushPull, Pin};

fn blink(led: &mut Pin<'A', 5, Output<PushPull>>) {
    led.set_high();
}

// 编译错误：不能对输入引脚调用 set_high
// fn wrong(pin: &mut Pin<'A', 5, Input<Floating>>) {
//     pin.set_high();  // 类型系统阻止
// }
embedded-hal trait 抽象
use embedded_hal::digital::OutputPin;
use embedded_hal::delay::DelayNs;

fn blink_generic<P: OutputPin, D: DelayNs>(
    led: &mut P,
    delay: &mut D,
    times: u32,
) {
    for _ in 0..times {
        led.set_high().ok();
        delay.delay_ms(200);
        led.set_low().ok();
        delay.delay_ms(200);
    }
}

Rust 嵌入式安全特性
Rust 的所有权系统在嵌入式场景中提供了独特的安全保证：


// 外设单例：编译器保证外设只被获取一次
let dp = pac::Peripherals::take().unwrap();  // 第二次调用返回 None

// 中断安全的共享状态
use core::cell::RefCell;
use cortex_m::interrupt::{self, Mutex};

static SHARED: Mutex<RefCell<Option<Serial<USART1>>>> =
    Mutex::new(RefCell::new(None));

#[interrupt]
fn USART1() {
    interrupt::free(|cs| {
        if let Some(serial) = SHARED.borrow(cs).borrow_mut().as_mut() {
            if let Ok(byte) = serial.read() {
                serial.write(byte).ok();
            }
        }
    });
}

// DMA 安全：只有实现了 ReadBuffer/WriteBuffer 的类型才能用于 DMA
// 编译器保证 DMA 传输期间缓冲区不被移动或释放

小结
    

  • 嵌入式 C 通过 volatile 指针和内存映射直接操作硬件，是当前最成熟的嵌入式开发语言
    • 

  • 嵌入式 Rust 通过 #![no_std] 进入裸机模式，所有权系统在编译期消除内存安全和并发问题
    • 

  • embedded-hal trait 提供了硬件无关的外设抽象，使驱动代码可跨芯片复用
    • 

  • Rust 的类型系统将引脚状态（输入/输出）编码为类型，编译期阻止错误配置
    • 

  • C 生态极度成熟，Rust 生态快速增长（Embassy 异步框架是亮点）
    • 

  • 新项目如果团队具备 Rust 经验，嵌入式 Rust 在安全性和工程效率上具有明显优势
    •
