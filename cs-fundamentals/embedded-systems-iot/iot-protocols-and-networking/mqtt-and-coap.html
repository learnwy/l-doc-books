MQTT 与 CoAP 协议

核心概念

MQTT 和 CoAP 是物联网领域最主流的两种应用层协议。MQTT（Message Queuing Telemetry Transport）基于 TCP 的发布/订阅模型，适合需要可靠消息传递的场景；CoAP（Constrained Application Protocol）基于 UDP 的请求/响应模型，专为资源受限设备设计。两者在协议开销、传输可靠性和适用场景上各有侧重。

MQTT 协议深入
发布/订阅架构
MQTT 采用 Broker 中心化架构，发布者和订阅者通过 Broker 解耦。客户端无需知道对方的存在，只需关注主题（Topic）：


// ESP32 + MQTT 客户端示例（基于 ESP-IDF）
#include "mqtt_client.h"

esp_mqtt_client_config_t mqtt_cfg = {
    .broker.address.uri = "mqtt://broker.example.com:1883",
    .credentials.username = "device_001",
    .credentials.authentication.password = "secret",
    .session.keepalive = 60,
    .session.last_will.topic = "devices/001/status",
    .session.last_will.msg = "offline",
    .session.last_will.qos = 1,
    .session.last_will.retain = 1,
};

esp_mqtt_client_handle_t client = esp_mqtt_client_init(&mqtt_cfg);
esp_mqtt_client_register_event(client, ESP_EVENT_ANY_ID, mqtt_event_handler, NULL);
esp_mqtt_client_start(client);

void mqtt_event_handler(void *args, esp_event_base_t base,
                        int32_t event_id, void *event_data) {
    esp_mqtt_event_handle_t event = event_data;
    switch (event->event_id) {
        case MQTT_EVENT_CONNECTED:
            esp_mqtt_client_subscribe(client, "sensors/+/temperature", 1);
            break;
        case MQTT_EVENT_DATA:
            process_message(event->topic, event->topic_len,
                          event->data, event->data_len);
            break;
    }
}

CoAP 协议深入
RESTful 资源模型
CoAP 将每个传感器数据和执行器控制映射为 URI 资源，使用与 HTTP 类似的 GET/PUT/POST/DELETE 方法：


// CoAP 服务端示例（基于 libcoap）
#include <coap3/coap.h>

void temperature_handler(coap_resource_t *resource,
                        coap_session_t *session,
                        const coap_pdu_t *request,
                        const coap_string_t *query,
                        coap_pdu_t *response) {
    float temp = read_temperature_sensor();
    char buf[32];
    int len = snprintf(buf, sizeof(buf), "{\"temp\":%.1f}", temp);

    coap_pdu_set_code(response, COAP_RESPONSE_CODE_CONTENT);
    coap_add_option(response, COAP_OPTION_CONTENT_FORMAT,
                    coap_encode_var_safe(opt, sizeof(opt),
                    COAP_MEDIATYPE_APPLICATION_JSON), opt);
    coap_add_data(response, len, (uint8_t *)buf);
}

// 注册资源
coap_resource_t *r = coap_resource_init(coap_make_str_const("temperature"), 0);
coap_register_handler(r, COAP_REQUEST_GET, temperature_handler);
coap_resource_set_get_observable(r, 1);  // 支持 Observe
coap_add_resource(ctx, r);
Observe 机制
CoAP 的 Observe 扩展（RFC 7641）允许客户端订阅资源变化通知，弥补了请求/响应模型在实时推送方面的不足：


客户端                          服务端
  |--- GET /temperature ------->|    (Observe: 0)
  |<-- 2.05 Content ------------|    (Observe: 1, temp=25.3)
  |                              |    ... 温度变化 ...
  |<-- 2.05 Content ------------|    (Observe: 2, temp=26.1)
  |<-- 2.05 Content ------------|    (Observe: 3, temp=25.8)

小结
    

  • MQTT 基于 TCP 发布/订阅模型，适合需要可靠传递和大规模设备管理的场景
    • 

  • CoAP 基于 UDP RESTful 模型，专为资源受限设备设计，支持资源发现和 Observe 订阅
    • 

  • MQTT 的三级 QoS 提供从「至多一次」到「恰好一次」的传递保证
    • 

  • CoAP 的 Observe 机制弥补了请求/响应模型的实时推送不足
    • 

  • 实际部署常采用混合架构：设备端 CoAP/MQTT-SN → 边缘网关 → 云端 MQTT Broker
    • 

  • 主题/资源设计是 IoT 系统可维护性的关键，需遵循层级化、可通配的命名规范
    •
