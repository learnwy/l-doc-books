并发与并行的实现机制

概述

实现并发和并行有多种机制，从操作系统级的进程和线程，到用户级的协程和事件驱动模型，再到硬件级的多核 CPU、分布式系统和 GPU 并行计算。不同机制适用于不同场景，理解它们的特点和适用范围是做出正确技术选型的关键。

并发机制一：进程
进程（Process）是操作系统中资源分配的基本单位。每个进程拥有独立的地址空间、文件描述符、堆和栈，进程之间完全隔离。






特性
说明





隔离性
进程间内存完全隔离，一个进程崩溃不影响其他进程




通信方式
管道、消息队列、共享内存、Socket 等 IPC 机制




创建开销
高（需要复制地址空间，即使使用 COW）




切换开销
高（需要切换页表、刷新 TLB）




适用场景
需要强隔离的场景（如浏览器多标签页、微服务）





// 多进程并发模型
主进程:
    for i = 1 to N:
        子进程 = fork()
        if 子进程:
            处理任务(i)
            exit()
    等待所有子进程完成()
并发机制二：线程
线程（Thread）是 CPU 调度的基本单位。同一进程内的多个线程共享地址空间和文件描述符，但各自拥有独立的栈和寄存器。






特性
说明





共享内存
同一进程内的线程共享堆内存，通信高效




同步需求
共享数据需要锁、信号量等同步机制




创建开销
中等（约 1MB 栈空间）




切换开销
中等（内核态上下文切换）




适用场景
CPU 密集型任务的并行化、需要共享数据的并发





function workerTask(id: number, data: number[]): number {
  let sum = 0;
  for (const val of data) {
    sum += val;
  }
  return sum;
}

async function parallelSum(arr: number[], numThreads: number): Promise<number> {
  const chunkSize = Math.ceil(arr.length / numThreads);
  const promises: Promise<number>[] = [];
  for (let i = 0; i < numThreads; i++) {
    const chunk = arr.slice(i * chunkSize, (i + 1) * chunkSize);
    promises.push(runInWorker(workerTask, i, chunk));
  }
  const results = await Promise.all(promises);
  return results.reduce((a, b) => a + b, 0);
}
并发机制三：协程
协程（Coroutine）是用户级的轻量执行单元，由用户程序调度而非内核调度。协程的创建和切换开销极低，适合管理大量并发 I/O 任务。






特性
说明





调度方式
用户态协作式调度




创建开销
极低（约 2~8 KB）




切换开销
极低（纳秒级，用户态完成）




并发规模
可达百万级




适用场景
I/O 密集型高并发（Web 服务器、网络编程）





async function handleConnection(conn: Connection): Promise<void> {
  const request = await conn.readRequest();
  const data = await queryDatabase(request.query);
  const response = buildResponse(data);
  await conn.writeResponse(response);
}

async function server(): Promise<void> {
  const listener = createListener(8080);
  while (true) {
    const conn = await listener.accept();
    handleConnection(conn);
  }
}
并发机制四：事件驱动
事件驱动（Event-Driven）模型使用单线程 + I/O 多路复用来管理大量并发连接。核心是操作系统提供的 I/O 多路复用接口（如 epoll、kqueue、select），它们可以在单个线程中同时监听数千个文件描述符的 I/O 事件。

并行机制一：多核 CPU
多核 CPU 是实现并行最直接的硬件基础。操作系统可以将不同的线程/进程调度到不同核心上，实现真正的同时执行。






特性
说明





共享内存
多核共享主内存，通过缓存一致性协议保持数据同步




扩展性
受限于核心数和总线带宽




适用场景
通用并行计算





并行机制二：分布式系统
当单机的多核 CPU 无法满足计算需求时，可以将任务分配到多台机器上并行执行。分布式系统通过网络将多台计算机连接起来，协同完成大规模任务。






特性
说明





通信方式
通过网络（RPC、消息队列等）




扩展性
理论上无限（水平扩展）




复杂性
高（网络延迟、故障容错、数据一致性）




典型框架
MapReduce、Spark、Flink




适用场景
超大规模数据处理、高可用系统





并行机制三：GPU 并行计算
GPU（图形处理器）拥有数千个小型计算核心，擅长执行大量相同操作的并行任务（SIMT 模型）。

小结
    

  • 进程提供最强的隔离性，适合安全敏感和需要独立故障域的场景，但创建和切换开销最高。
    • 

  • 线程在同一进程内共享内存，通信高效但需要同步机制，适合 CPU 密集型并行任务。
    • 

  • 协程是用户级轻量执行单元，创建和切换开销极低，适合管理百万级 I/O 密集型并发连接。
    • 

  • 事件驱动通过 I/O 多路复用（epoll/kqueue）在单线程中管理大量连接，是高性能网络服务器的基础。
    • 

  • 多核 CPU 是并行的硬件基础，通过将线程/进程调度到不同核心实现真正的同时执行。
    • 

  • 分布式系统通过多台机器协同工作，实现理论上无限的水平扩展能力。
    • 

  • GPU 拥有数千个小核心，擅长大规模数据并行任务（图形渲染、深度学习等）。
    • 

  • 实际系统中，应根据瓶颈类型（I/O vs CPU）、并发规模、隔离需求等因素，选择合适的机制或组合使用。
