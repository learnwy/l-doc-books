并发与并行的核心思想

并发的核心思想：提升资源利用率

并发的核心目标不是让程序跑得更快，而是提升资源利用率。在实际系统中，CPU 和 I/O 设备的工作节奏差异巨大：CPU 运算以纳秒计，而磁盘读写以毫秒计，网络请求更可能以百毫秒计。如果程序只能串行执行，那么 CPU 在等待 I/O 完成的漫长时间里将完全空闲。

并发通过交替执行不同任务，让 CPU 在一个任务等待 I/O 时切换到另一个任务继续工作，从而"填满"CPU 的空闲时间。

CPU 与 I/O 的速度鸿沟

操作类型 典型耗时 相对 CPU 周期
CPU 寄存器访问 ~0.3 ns 1 个周期
L1 缓存访问 ~1 ns 3 个周期
L2 缓存访问 ~4 ns 12 个周期
主内存访问 ~100 ns 300 个周期
SSD 随机读取 ~100 μs 300,000 个周期
磁盘随机读取 ~10 ms 30,000,000 个周期
网络往返（同机房） ~0.5 ms 1,500,000 个周期
网络往返（跨地域） ~50 ms 150,000,000 个周期

CPU 执行一次加法运算约需 0.3 纳秒，而一次磁盘读取约需 10 毫秒——差距达到 3000 万倍。如果不使用并发，CPU 在 I/O 期间的闲置是巨大的浪费。

并行的核心思想：提升执行速度
并行的核心目标是提升执行速度。如果一个任务可以被拆分为多个独立的子任务，那么把这些子任务分配到多个 CPU 核心上同时执行，总耗时将大幅缩短。


任务拆分与并行加速
// 串行：对 1000 万个元素求和
函数 serialSum(arr):
    sum = 0
    for i = 0 to 9999999:
        sum += arr[i]
    return sum
// 耗时: T

// 并行：将数组分为 4 段，4 个核心同时求和
函数 parallelSum(arr):
    part1 = 核心1计算: sum(arr[0..2499999])        // T/4
    part2 = 核心2计算: sum(arr[2500000..4999999])   // T/4
    part3 = 核心3计算: sum(arr[5000000..7499999])   // T/4
    part4 = 核心4计算: sum(arr[7500000..9999999])   // T/4
    return part1 + part2 + part3 + part4
// 理论耗时: T/4（4倍加速）
阿姆达尔定律（Amdahl's Law）
并行加速并非无限的。程序中总有一些无法并行化的串行部分（如初始化、结果合并），这限制了并行的最大加速比。


阿姆达尔定律给出了理论上的最大加速比：


加速比 = 1 / (S + (1-S)/N)

S = 程序中串行部分的比例
N = 并行处理器（核心）数量

并发与并行的协同
在实际系统中，并发与并行通常协同工作。例如一个高性能 Web 服务器：


在这个模型中：


    

  • 并行层：多个工作线程运行在不同 CPU 核心上，实现真正的并行。
    • 

  • 并发层：每个工作线程内部运行多个协程，通过协作式调度实现并发。
    • 

  • 效果：既利用了多核加速，又在每个核心内高效处理大量 I/O 密集型请求。
    • 



// 高性能服务器：并行 + 并发
主函数():
    workers = 创建线程池(核心数)       // 并行：多个工作线程

    for each worker in workers:
        worker.run():
            event_loop = 创建事件循环()  // 并发：每个线程一个事件循环
            while true:
                conn = 接受连接()
                event_loop.spawn(处理请求(conn))  // 每个连接一个协程
小结
    

  • 并发的核心思想是提升资源利用率：通过交替执行多个任务，让 CPU 在 I/O 等待期间不闲置，充分利用 CPU 与 I/O 之间的速度差异。
    • 

  • 并行的核心思想是提升执行速度：将可独立执行的子任务分配到多个核心同时运行，缩短总执行时间。
    • 

  • 阿姆达尔定律告诉我们：并行加速受限于程序的串行部分比例，减少串行比例比增加核心数更重要。
    • 

  • I/O 密集型任务优先选择并发（协程、异步 I/O），CPU 密集型任务优先选择并行（多线程、多进程）。
    • 

  • 实际高性能系统通常将并发与并行协同使用：多核并行 + 核内协程并发，既利用多核加速又高效处理 I/O。
    •
