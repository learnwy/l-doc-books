原子操作的定义与核心概念

问题背景

在多线程环境中，多个线程可能同时访问和修改同一份数据。如果一个操作在执行过程中被其他线程打断，就会产生不一致的中间状态，导致数据损坏或程序行为异常。这类问题统称为竞态条件（Race Condition）。

考虑一个最简单的场景——两个线程同时对计数器执行加一操作：

// 线程 A 和 线程 B 同时执行
counter = counter + 1

这条看似简单的语句，在底层实际上分为三个步骤：

步骤 1: 读取 counter 的当前值到寄存器
步骤 2: 将寄存器的值加 1
步骤 3: 将结果写回 counter

当两个线程交错执行这三个步骤时，就可能出现丢失更新的问题。



两个线程各执行了一次加一操作，但最终结果只增加了 1。这就是竞态条件最经典的表现形式。






核心原理
什么是原子操作
原子操作（Atomic Operation） 是指一个操作要么完整执行，要么完全不执行，不存在被其他线程观察到的中间状态。"原子"一词借用了物理学中的概念——不可再分的最小单位。


在并发编程中，原子操作具备以下关键特性：






特性
说明





不可分割性
操作在执行过程中不会被任何其他线程打断或观察到中间状态




全有或全无
操作的效果对外界来说是瞬间生效的，没有"执行了一半"的可能




线程安全
多个线程同时执行原子操作时，每个操作都能正确完成，不会产生数据竞争





原子操作的目的
原子操作存在的核心目的可以归纳为两点：


    

  1. 避免竞态条件：确保对共享数据的操作不会因线程交错而产生错误结果
    2. 

  2. 保证数据一致性：任何时刻，其他线程观察到的数据都是某次操作完成后的完整状态
    3. 





分类与变体
原子变量
原子变量（Atomic Variable） 是对普通变量的封装，使得对该变量的所有操作（读取、写入、修改）都具备原子性。它是原子操作最常见的载体。


// 普通变量 —— 非线程安全
普通变量 counter = 0

// 原子变量 —— 线程安全
原子变量 atomicCounter = 0
原子变量通常支持以下操作：






操作
说明
示例





原子读取
读取变量的当前值，保证读到完整的值
value = atomicCounter.load()




原子写入
将新值写入变量，保证写入是完整的
atomicCounter.store(42)




原子加减
对变量进行加减运算，读-改-写一步完成
atomicCounter.fetchAdd(1)




比较并交换
只在当前值等于期望值时才更新
atomicCounter.compareAndSwap(old, new)




原子交换
设置新值并返回旧值，一步完成
old = atomicCounter.exchange(new)





原子操作 vs 非原子操作
下面通过一个具体场景对比原子操作与非原子操作的行为差异：


// 场景：两个线程各自对 counter 执行 1000 次加一

// ---- 非原子操作 ----
let counter = 0;

function incrementNonAtomic(): void {
  for (let i = 0; i < 1000; i++) {
    counter = counter + 1; // 读-改-写，可被打断
  }
}
// 两个线程并发执行后，counter 的值不确定
// 可能是 1000 ~ 2000 之间的任意值

// ---- 原子操作 ----
let atomicCounter = createAtomicInteger(0);

function incrementAtomic(): void {
  for (let i = 0; i < 1000; i++) {
    atomicCounter.fetchAdd(1); // 读-改-写，不可分割
  }
}
// 两个线程并发执行后，atomicCounter 的值一定是 2000

关键限制：两个独立的原子操作组合在一起不具有原子性。例如"先读取 A 再读取 B"不能保证 A 和 B 的值来自同一时刻。如果需要保护多个变量或多步操作，仍然需要使用锁。




// ⚠️ 非原子的组合
value1 = atomicA.load()     // 原子读取 A
value2 = atomicB.load()     // 原子读取 B
// 在这两次读取之间，其他线程可能已经修改了 A 或 B
// value1 和 value2 可能不一致

// ✅ 如果需要同时读取 A 和 B 的一致快照，需要使用锁
lock.acquire()
value1 = A
value2 = B
lock.release()


小结
    

  • 原子操作是并发编程中保证数据安全的基础机制，其核心特性是不可分割性
    • 

  • 它通过硬件指令支持，将"读取-修改-写回"等多步操作合并为一个不可被打断的整体
    • 

  • 原子变量是原子操作的常见载体，支持原子读写、加减、比较并交换等操作
    • 

  • 原子操作比锁更轻量，但只适用于单变量的简单操作
    • 

  • 多个原子操作的组合不具有原子性，复杂的同步需求仍需使用锁机制
    •
