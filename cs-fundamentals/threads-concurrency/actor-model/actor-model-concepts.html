Actor 模型的核心概念

核心思想

Actor 模型是一种并发计算模型，由 Carl Hewitt 于 1973 年提出。在该模型中，Actor（行为者）是最基本的计算单元——每个 Actor 都是独立的实体，拥有自己的状态和行为，并且只能通过消息传递进行通信，彼此之间不共享任何状态。

Actor 模型的核心哲学：一切皆 Actor。每个 Actor 独立运作，通过异步消息与外界交互，从根本上消除共享状态带来的并发问题。

与传统的共享内存并发模型不同，Actor 模型从设计层面避免了锁、竞态条件等问题——因为根本不存在需要保护的共享资源。




基本组件
Actor 模型由三个核心组件构成：Actor、消息（Message） 和 邮箱（Mailbox）。


Actor
Actor 是模型中的基本计算实体，每个 Actor 具备以下特征：






特征
说明





封装状态
拥有私有的内部状态，外部无法直接访问或修改




封装行为
定义了收到不同消息后的处理逻辑




异步通信
只通过发送和接收异步消息与其他 Actor 交互




串行处理
每次只处理一条消息，保证内部状态一致性




唯一标识
每个 Actor 拥有唯一的地址（Address），用于消息路由





type ActorAddress = string;

interface Actor {
  address: ActorAddress;
  state: unknown;
  behavior: (message: Message) => void;
}
消息（Message）
消息是 Actor 之间通信的唯一手段。消息具有以下特点：


    

  • 不可变：发送后不可修改，保证通信安全
    • 

  • 异步投递：发送方不阻塞等待接收方处理
    • 

  • 类型多样：可以携带任意数据
    • 



interface Message {
  sender: ActorAddress;
  receiver: ActorAddress;
  payload: unknown;
}
邮箱（Mailbox）
邮箱是每个 Actor 关联的消息队列，负责暂存待处理的消息。


邮箱的关键特性：






特性
说明





FIFO 顺序
默认按先进先出顺序处理消息




缓冲能力
当 Actor 正在处理消息时，新消息在邮箱中排队等候




解耦作用
发送者和接收者完全解耦，无需同步等待







工作机制
当一个 Actor 收到消息时，它可以执行以下三种操作的任意组合：


当 Actor 收到消息 msg 时:
    根据 msg.type 选择:
        情况 "请求":
            更新自身状态
            向 msg.sender 发送响应消息
        情况 "创建子任务":
            child = 创建新的 Actor(初始状态)
            向 child 发送工作消息
        情况 "切换模式":
            将自身行为切换为新的处理函数
这三种操作是 Actor 模型的全部原语，所有复杂的并发行为都可以通过这三种操作的组合来实现。

小结
Actor 模型提供了一种优雅的并发编程范式。其核心要素包括：


    

  • Actor 是基本计算单元，封装了状态和行为
    • 

  • 消息 是唯一的通信手段，保证不可变和异步投递
    • 

  • 邮箱 作为消息缓冲，实现发送者与接收者的解耦
    • 

  • 收到消息后，Actor 可以执行三种操作：发送消息、创建新 Actor、更新自身行为
    • 

  • 与线程模型相比，Actor 模型从根本上消除了共享状态，避免了锁和竞态条件
    • 

  • Actor 模型天然适合构建分布式、高并发、容错的系统
    •
