Part III · 系统 (Systems)线程与并发 简介进程 简介进程的实现机制

进程的实现机制

进程的创建

操作系统提供了多种系统调用来创建新进程。不同的创建方式在语义和效率上各有特点。

fork — 复制当前进程

fork 是 UNIX/Linux 系统中最经典的进程创建方式。它会创建一个当前进程的近乎完全的副本（子进程），子进程从 fork 调用之后继续执行。

FUNCTION fork_example():
    pid = fork()
    IF pid == 0 THEN
        // 子进程：fork 返回 0
        print("我是子进程，PID =", getpid())
    ELSE IF pid > 0 THEN
        // 父进程：fork 返回子进程的 PID
        print("我是父进程，子进程 PID =", pid)
    ELSE
        // fork 失败
        print("进程创建失败")
    END IF
END FUNCTION
spawn — 直接创建新进程
spawn（或 exec 系列调用）直接从指定的可执行文件创建新进程，不需要先复制再替换：


FUNCTION spawn_example():
    // 直接指定程序路径和参数创建新进程
    child_pid = spawn("/path/to/program", ["arg1", "arg2"])
    IF child_pid > 0 THEN
        print("成功创建子进程，PID =", child_pid)
        wait(child_pid)  // 等待子进程结束
    END IF
END FUNCTION

写时复制（Copy-On-Write）
现代操作系统在 fork 时并不会立即复制父进程的所有内存页，而是让父子进程共享同一份物理内存，仅在某一方尝试写入时才真正复制该内存页：


进程调度算法
操作系统需要决定在多个就绪进程中，下一个让哪个进程使用 CPU。不同的调度算法有不同的目标和适用场景。


先来先服务（FCFS）
按照进程到达就绪队列的先后顺序进行调度，最先到达的进程最先获得 CPU。


FUNCTION fcfs_schedule(ready_queue):
    WHILE ready_queue is not empty:
        process = ready_queue.dequeue()  // 取出队首进程
        run(process)                     // 执行直到完成或阻塞
    END WHILE
END FUNCTION
优点：实现简单，公平。 缺点：长作业会阻塞后续短作业（护航效应）。


最短作业优先（SJF）
优先调度预计执行时间最短的进程，以最小化平均等待时间。


FUNCTION sjf_schedule(ready_queue):
    WHILE ready_queue is not empty:
        process = ready_queue.find_shortest()  // 找到预估时间最短的
        ready_queue.remove(process)
        run(process)
    END WHILE
END FUNCTION
优点：平均等待时间最优。 缺点：难以准确预估执行时间；长作业可能饥饿。


优先级调度（Priority）
为每个进程赋予一个优先级数值，调度器选择优先级最高的进程执行。


FUNCTION priority_schedule(ready_queue):
    WHILE ready_queue is not empty:
        process = ready_queue.find_highest_priority()
        ready_queue.remove(process)
        run(process)
        // 可选：动态调整其他进程的优先级（老化机制）
        age_waiting_processes(ready_queue)
    END WHILE
END FUNCTION
优点：可以根据任务重要性分配资源。 缺点：低优先级进程可能饥饿（可通过老化机制缓解）。


时间片轮转（Round-Robin）
每个进程分配一个固定的时间片（quantum），时间片用完后切换到下一个进程。


FUNCTION round_robin_schedule(ready_queue, quantum):
    WHILE ready_queue is not empty:
        process = ready_queue.dequeue()
        run_for(process, quantum)  // 最多执行 quantum 时间
        IF process is not finished THEN
            ready_queue.enqueue(process)  // 放回队尾
        END IF
    END WHILE
END FUNCTION
优点：响应时间好，公平。 缺点：时间片过大退化为 FCFS，过小则上下文切换开销大。

进程间通信（IPC）
由于进程之间内存空间相互隔离，进程间的数据交换需要借助操作系统提供的**进程间通信（Inter-Process Communication, IPC）**机制。


管道（Pipe）
管道是最简单的 IPC 机制，提供一个单向的字节流通道。数据从一端写入，从另一端读出。


FUNCTION pipe_example():
    (read_end, write_end) = create_pipe()

    pid = fork()
    IF pid == 0 THEN
        // 子进程：从管道读取
        close(write_end)
        data = read(read_end)
        print("子进程收到:", data)
    ELSE
        // 父进程：向管道写入
        close(read_end)
        write(write_end, "Hello from parent!")
    END IF
END FUNCTION
消息队列（Message Queue）
消息队列允许进程以结构化的消息为单位进行通信，支持按类型选择性接收。


FUNCTION message_queue_example():
    queue = create_message_queue(key)

    // 发送方
    message = { type: 1, content: "任务数据" }
    send(queue, message)

    // 接收方
    received = receive(queue, type: 1)
    print("收到消息:", received.content)
END FUNCTION
共享内存（Shared Memory）
共享内存是效率最高的 IPC 方式——两个进程将同一块物理内存映射到各自的地址空间中，直接读写即可。


FUNCTION shared_memory_example():
    shm = create_shared_memory(size: 4096)

    pid = fork()
    IF pid == 0 THEN
        // 子进程：读取共享内存
        attach(shm)
        data = read_from(shm)
        print("子进程读到:", data)
    ELSE
        // 父进程：写入共享内存
        attach(shm)
        write_to(shm, "共享数据")
        wait(pid)
    END IF
END FUNCTION
信号量（Semaphore）
信号量主要用于同步和互斥，控制多个进程对共享资源的访问顺序。


FUNCTION semaphore_example():
    sem = create_semaphore(initial_value: 1)

    // 进程 A
    wait(sem)           // P 操作：信号量减 1，若为负则阻塞
    // 进入临界区，访问共享资源
    access_shared_resource()
    signal(sem)         // V 操作：信号量加 1，唤醒等待者

    // 进程 B
    wait(sem)           // 若进程 A 还在临界区，进程 B 将在此阻塞
    access_shared_resource()
    signal(sem)
END FUNCTION
套接字（Socket）
套接字是最通用的 IPC 机制，不仅支持同一台机器上的进程通信，还支持跨网络的进程通信。


// 服务端
FUNCTION socket_server():
    server = create_socket(port: 8080)
    bind(server)
    listen(server)
    client = accept(server)
    data = receive(client)
    send(client, "收到: " + data)

// 客户端
FUNCTION socket_client():
    client = create_socket()
    connect(client, "localhost", 8080)
    send(client, "Hello!")
    response = receive(client)
    print(response)
END FUNCTION

进程的终止
进程终止分为正常终止和异常终止两种情况。


正常终止
FUNCTION normal_exit():
    // 方式 1：main 函数返回
    return 0

    // 方式 2：主动调用退出
    exit(0)         // 正常退出，返回码 0

    // 方式 3：最后一个线程完成
    // 进程中所有线程执行完毕后自动终止
END FUNCTION
异常终止
FUNCTION abnormal_exit():
    // 方式 1：收到致命信号
    // 如 SIGSEGV（段错误）、SIGKILL（强制杀死）

    // 方式 2：未捕获的异常
    THROW uncaught_exception

    // 方式 3：调用 abort
    abort()         // 异常终止，产生 core dump
END FUNCTION

小结
    

  • 进程创建有两种主要方式：fork（复制当前进程）和 spawn（创建全新进程），现代系统通过写时复制优化 fork 的性能。
    • 

  • 操作系统通过调度算法（FCFS、SJF、优先级、时间片轮转）决定哪个进程获得 CPU，不同算法在公平性、响应时间和吞吐量之间做出不同权衡。
    • 

  • 进程间通信（IPC）提供了多种机制（管道、消息队列、共享内存、信号量、套接字），从简单到复杂，从本地到网络，满足不同的通信需求。
    • 

  • 进程终止后，操作系统负责回收其资源，父进程应通过 wait 调用回收子进程的状态信息，避免产生僵尸进程。
