协程的定义与核心概念

什么是协程

协程（Coroutine）是一种用户级别的轻量执行单元，由用户程序自行调度，而非由操作系统内核管理。与线程不同，协程的创建、切换和销毁完全在用户空间完成，不需要陷入内核态，因此开销极低。

一个程序可以轻松创建数百万个协程，而创建等量的线程则会迅速耗尽系统资源。协程的核心思想是：把调度权从操作系统交还给程序员，让程序员决定何时暂停、何时恢复执行。



操作系统负责调度线程，而协程调度器运行在用户空间的线程之上，负责在多个协程之间切换执行。




协程的关键特征
协程具有以下核心特征，使其区别于线程和进程：






特征
说明





用户级调度
由用户程序（运行时/框架）调度，不依赖 OS 内核




非抢占式
协程主动让出控制权（yield），而非被强制中断




极低开销
创建和切换成本远低于线程（无需内核态切换）




轻量级
单个协程仅占数 KB 内存，可创建百万级实例




协作式多任务
多个协程通过主动让出实现交替执行





非抢占式 vs 抢占式
操作系统对线程采用抢占式调度：内核可以在任意时刻中断一个线程，把 CPU 分配给另一个线程。而协程采用非抢占式（协作式）调度：一个协程必须主动执行 yield 或 await 操作，才会将控制权交给调度器。


// 抢占式调度（线程）
线程A 执行中...
  ← 内核定时器中断，强制切换 →
线程B 开始执行...

// 协作式调度（协程）
协程A 执行中...
协程A 执行 yield  // 主动让出
  ← 调度器选择下一个协程 →
协程B 开始执行...
这意味着协程内部的代码在两个 yield 点之间是不会被中断的，天然避免了许多并发竞争问题。

有栈协程与无栈协程
协程的实现可分为两大类：有栈协程（Stackful） 和 无栈协程（Stackless）。






维度
有栈协程
无栈协程





独立栈空间
是，每个协程有自己的调用栈
否，共享调用栈

只能在特定 yield 点挂起

协程的生命周期
协程从创建到销毁会经历多个状态。理解这些状态有助于正确使用协程。






状态
说明





已创建
协程对象已创建，但尚未开始执行




运行中
协程正在某个线程上执行代码




已挂起
协程执行了 yield/await，暂停执行并保存上下文




已完成
协程正常执行完毕，返回结果




已取消
协程被外部取消或因异常终止





一个简单的协程生命周期示例
function* simpleCoroutine(): Generator<string, string, void> {
  console.log('状态: 运行中');
  yield '第一次挂起';
  console.log('状态: 恢复运行');
  yield '第二次挂起';
  return '执行完成';
}

const co = simpleCoroutine(); // 已创建
console.log(co.next()); // 运行 → 挂起，输出 "第一次挂起"
console.log(co.next()); // 恢复 → 挂起，输出 "第二次挂起"
console.log(co.next()); // 恢复 → 完成，输出 "执行完成"
为什么需要协程
传统的线程模型在高并发场景下面临以下挑战：






挑战
线程模型的问题
协程的解决方案





资源消耗
每个线程占用 MB 级内存
协程仅占 KB 级内存




切换成本
内核态上下文切换耗时微秒级
用户态切换仅需纳秒级




并发上限
受限于系统线程数（通常数千）
可创建百万级协程




编程复杂度
需要大量锁和同步原语
通过 yield/await 简化异步逻辑





以一个典型的 Web 服务器为例：


// 传统线程模型：每个连接一个线程
对于每个客户端连接:
    创建新线程()          // 开销大
    线程处理请求()        // 大部分时间在等待 I/O

// 问题：10000 个连接 = 10000 个线程 = 约 10GB 内存

// 协程模型：每个连接一个协程
对于每个客户端连接:
    创建新协程()          // 开销极小
    协程处理请求()        // 遇到 I/O 等待时 yield

// 优势：10000 个连接 = 10000 个协程 = 约 40MB 内存
小结
    

  • 协程是一种用户级轻量执行单元，由用户程序调度，不依赖操作系统内核。
    • 

  • 协程的核心特征是非抢占式调度：协程必须主动让出控制权，两个 yield 点之间的代码不会被中断。
    • 

  • 与线程相比，协程的创建和切换开销极低，单个进程可轻松管理百万级协程。
    • 

  • 协程分为有栈协程（独立栈空间，灵活但占内存较多）和无栈协程（状态机实现，更轻量）。
    • 

  • 协程的生命周期包括：已创建 → 运行中 → 已挂起 → 已完成/已取消。
    • 

  • 协程特别适合 I/O 密集型 高并发场景，能够以极低的资源消耗处理大量并发连接。
    •
