协程的核心思想

用户控制调度：绕过内核上下文切换

协程最核心的思想是将调度权从操作系统内核转移到用户程序。传统线程模型中，操作系统内核负责在多个线程之间分配 CPU 时间片，每次切换都需要进入内核态、保存/恢复完整的 CPU 上下文（寄存器、栈指针、程序计数器等），开销显著。

协程则完全在用户空间完成切换，避免了昂贵的内核态陷入：

两者的开销对比非常明显：

协作式多任务：主动让出控制权
协程的第二个核心思想是协作式多任务（Cooperative Multitasking）。每个协程在执行过程中，必须在适当的时机主动调用 yield 或 await 来让出控制权，调度器才能切换到其他协程。

协作式调度的风险
协作式调度也有其风险：如果某个协程不主动 yield，它将独占执行权，其他协程永远无法运行。


// ❌ 危险：协程不让出控制权
协程 badCoroutine():
    while true:
        heavyComputation()     // 永远不 yield
        // 其他协程全部饿死！

// ✅ 正确：在适当位置让出
协程 goodCoroutine():
    while true:
        doSomeWork()
        yield                  // 定期让出，让其他协程有机会运行
I/O 密集型场景的高吞吐
协程最大的价值体现在 I/O 密集型任务中。在这类任务中，程序的大部分时间都在等待外部操作完成（网络请求、磁盘读写、数据库查询等），CPU 实际上处于空闲状态。


传统同步模型的浪费
// 传统同步模型：线程在 I/O 期间被阻塞
函数 handleRequest(request):
    data = 读取数据库(request.query)     // 阻塞等待 ~5ms
    template = 读取文件("template.html") // 阻塞等待 ~2ms
    result = 渲染模板(template, data)    // CPU 计算 ~0.1ms
    return result

// 总耗时 ≈ 7.1ms，其中 CPU 实际工作仅 0.1ms
// CPU 利用率 ≈ 1.4%
协程的异步 I/O 模型
// 协程模型：I/O 等待期间切换到其他协程
协程 handleRequest(request):
    data = await 读取数据库(request.query)     // 让出，切换到其他协程
    template = await 读取文件("template.html") // 让出，切换到其他协程
    result = 渲染模板(template, data)          // CPU 计算
    return result

// 等待 I/O 的同时，其他协程可以利用 CPU
// CPU 利用率大幅提升

协程通过 yield 和 await 两个关键操作实现挂起和恢复：

// yield：生成器模式，按需产出值
function* fibonacci(): Generator<number> {
  let a = 0;
  let b = 1;
  while (true) {
    yield a;
    [a, b] = [b, a + b];
  }
}

const fib = fibonacci();
console.log(fib.next().value); // 0
console.log(fib.next().value); // 1
console.log(fib.next().value); // 1
console.log(fib.next().value); // 2
// await：异步等待模式
async function fetchData(url: string): Promise<string> {
  const response = await fetch(url);
  const data = await response.text();
  return data;
}
协程与回调的对比
在协程出现之前，异步编程通常依赖回调函数（Callback）。协程的引入使得异步代码可以用接近同步的方式书写：


// 回调地狱：嵌套深、难以维护
function loadUserData(userId: string, callback: (data: any) => void) {
  fetchUser(userId, (user) => {
    fetchOrders(user.id, (orders) => {
      fetchProducts(orders[0].productId, (product) => {
        callback({ user, orders, product });
      });
    });
  });
}

// 协程风格：扁平、清晰、易于理解
async function loadUserData(userId: string) {
  const user = await fetchUser(userId);
  const orders = await fetchOrders(user.id);
  const product = await fetchProducts(orders[0].productId);
  return { user, orders, product };
}

小结
    

  • 协程的第一核心思想是用户控制调度，将调度权从内核转移到用户空间，避免昂贵的内核态上下文切换，性能提升 10~100 倍。
    • 

  • 协程的第二核心思想是协作式多任务，协程通过主动 yield/await 让出控制权，使得 yield 点之间的代码天然不会被中断。
    • 

  • 协程的最大价值在于 I/O 密集型场景，在等待 I/O 期间切换到其他协程执行，极大提升 CPU 利用率和系统吞吐量。
    • 

  • yield 用于主动让出并返回值（生成器模式），await 用于等待异步操作完成。
    • 

  • 协程使得异步代码可以用接近同步的方式书写，从根本上解决了回调地狱问题。
    •
