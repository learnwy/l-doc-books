协程的实现机制

概述

协程的实现方式主要分为两大类：无栈协程（Stackless Coroutine） 和 有栈协程（Stackful Coroutine）。两者在内存模型、灵活性和性能上各有取舍。此外，协程的运行离不开调度机制，常见的有事件循环（Event Loop）和多线程协程调度器（如 GMP 模型）。

无栈协程：状态机实现
无栈协程没有独立的调用栈，编译器将协程函数转换为一个状态机（State Machine）。每次 yield 或 await 对应状态机的一个状态转换，协程的局部变量被提升为状态机对象的字段。


转换原理
一个包含多个 await 点的异步函数，会被编译器拆分为多个状态：


// 原始协程代码
协程 fetchAndProcess():
    data = await 读取网络数据()     // 挂起点 1
    parsed = 解析数据(data)
    result = await 写入数据库(parsed) // 挂起点 2
    return result
编译器将其转换为：


// 编译器生成的状态机
类 FetchAndProcess_StateMachine:
    state = 0
    data = null
    parsed = null
    result = null

    函数 resume():
        switch this.state:
            case 0:
                启动异步读取网络数据()
                this.state = 1
                return PENDING
            case 1:
                this.data = 获取异步结果()
                this.parsed = 解析数据(this.data)
                启动异步写入数据库(this.parsed)
                this.state = 2
                return PENDING
            case 2:
                this.result = 获取异步结果()
                return COMPLETE(this.result)

无栈协程的所有状态存储在一个堆上分配的对象中，不需要独立的栈空间：


TypeScript 中的无栈协程
TypeScript/JavaScript 的 async/await 和 Generator 都是无栈协程的典型实现：


async function processItems(items: string[]): Promise<string[]> {
  const results: string[] = [];
  for (const item of items) {
    const processed = await transformItem(item);
    results.push(processed);
  }
  return results;
}

async function transformItem(item: string): Promise<string> {
  const response = await fetch(`/api/transform?input=${item}`);
  const data = await response.json();
  return data.result;
}
引擎在底层将上述代码转换为状态机。每个 await 点将函数执行切分为若干段，只有当异步操作完成时，状态机才推进到下一个状态。


有栈协程：独立栈实现
有栈协程为每个协程分配一块独立的栈空间，使其拥有完整的调用栈。这意味着有栈协程可以在任意嵌套调用深度处挂起和恢复，灵活性远超无栈协程。


栈切换原理
有栈协程的切换本质是栈指针的切换：保存当前协程的栈指针和寄存器，然后恢复目标协程的栈指针和寄存器。


函数 switch_coroutine(from, to):
    // 1. 保存当前协程的 CPU 状态
    from.saved_sp = 当前栈指针
    from.saved_pc = 当前程序计数器
    from.saved_registers = 当前寄存器组

    // 2. 恢复目标协程的 CPU 状态
    设置栈指针(to.saved_sp)
    设置寄存器组(to.saved_registers)
    跳转到(to.saved_pc)
    // 从目标协程上次挂起的位置继续执行

调度机制一：事件循环
事件循环（Event Loop）是单线程环境下调度协程的核心机制。它维护一个任务队列，不断从中取出就绪的协程并执行，直到协程遇到下一个挂起点。


事件循环的工作流程
事件循环伪代码
类 EventLoop:
    ready_queue = []        // 就绪队列
    io_watcher = 创建IO监视器()  // epoll / kqueue

    函数 run():
        while true:
            // 1. 执行所有就绪的协程
            while ready_queue 非空:
                task = ready_queue.取出()
                result = task.resume()
                if result == PENDING:
                    // 协程挂起，等待 I/O
                    io_watcher.注册(task.等待的fd, task)
                else:
                    // 协程完成
                    task.完成回调(result)

            // 2. 等待 I/O 事件
            events = io_watcher.等待事件()
            for event in events:
                ready_queue.加入(event.对应的协程)

    函数 spawn(协程):
        ready_queue.加入(协程)
事件循环在 Node.js、浏览器 JavaScript 运行时中是核心调度机制——所有 async/await 的调度都依赖事件循环。


调度机制二：GMP 模型
对于需要利用多核 CPU 的场景，单线程事件循环就不够了。GMP 模型是一种经典的多线程协程调度模型，将大量协程（M 个）映射到少量操作系统线程（N 个）上，实现 M:N 调度。

GMP 调度流程
GMP 调度策略
函数 schedule(P):
    while true:
        // 1. 优先从本地队列取 G
        g = P.本地队列.取出()

        // 2. 本地队列为空，从全局队列取一批
        if g == null:
            g = 全局队列.取出一批(P)

        // 3. 全局队列也为空，从其他 P 偷取一半
        if g == null:
            g = 从其他P偷取(P)

        // 4. 执行协程
        if g != null:
            执行(g)
            if g.状态 == 挂起:
                P.本地队列.加入(g)  // 放回本地队列等待恢复
工作窃取（Work Stealing）
GMP 模型中的核心优化策略是工作窃取：当某个 P 的本地队列为空时，它会尝试从其他 P 的本地队列中偷取一半的 G，实现负载均衡。

小结
    

  • 无栈协程通过编译器将协程转换为状态机实现，每个 await 点对应一个状态，局部变量提升为状态对象的字段，内存占用极小。
    • 

  • 有栈协程为每个协程分配独立的栈空间，通过栈指针切换实现挂起/恢复，可在任意嵌套调用处挂起，灵活性更高。
    • 

  • 事件循环是单线程协程调度的核心机制，通过就绪队列和 I/O 事件监听不断驱动协程执行，适合 I/O 密集型场景。
    • 

  • GMP 模型是多线程协程调度的经典方案，通过 G（协程）、M（线程）、P（逻辑处理器）三层结构实现 M:N 映射，配合工作窃取策略实现负载均衡。
    • 

  • 选择哪种实现取决于具体需求：单线程异步选事件循环，多核并行选 GMP 类调度器，轻量 I/O 选无栈协程，深层嵌套选有栈协程。
    •
