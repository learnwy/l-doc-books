Part III · 系统 (Systems)线程与并发 简介锁 简介锁的实现机制

锁的实现机制

问题背景

我们已经理解了锁的核心思想——互斥、等待策略、死锁预防。但锁在底层究竟是如何实现的？一个看似简单的"获取锁"操作，需要解决多个技术难题：如何保证锁的获取本身是原子的？线程等待时如何高效地管理？多种锁类型各自的实现有什么区别？



锁从上到下贯穿了应用层、标准库、操作系统和硬件四个层次。理解每一层的实现有助于做出正确的性能决策。






核心原理
互斥锁（Mutex）的实现
互斥锁是最基础的锁类型。其核心实现依赖于原子操作 + 操作系统的线程调度：


互斥锁 {
    状态: 0         // 0 = 未锁定, 1 = 已锁定
    等待队列: []     // 被阻塞的线程列表
}

函数 lock():
    如果 CAS(状态, 0, 1) 成功:   // 原子地尝试从 0 变为 1
        返回                       // 获取成功
    否则:
        将当前线程加入等待队列
        挂起当前线程               // 操作系统接管，让出 CPU

函数 unlock():
    状态 = 0                       // 释放锁
    如果 等待队列不为空:
        唤醒队列中的第一个线程     // 操作系统唤醒被阻塞的线程
自旋锁（Spinlock）的实现
自旋锁的实现比互斥锁简单得多——不涉及操作系统调度，纯粹在用户空间通过原子操作实现：


class Spinlock {
  private locked = new AtomicInteger(0);

  lock(): void {
    while (!this.locked.compareAndSwap(0, 1)) {
      // 获取失败，持续自旋
      // 不让出 CPU，不调用操作系统
    }
  }

  unlock(): void {
    this.locked.store(0);
  }
}
优化版本——TTAS（Test-and-Test-and-Set），减少缓存行争用：


class OptimizedSpinlock {
  private locked = new AtomicInteger(0);

  lock(): void {
    while (true) {
      while (this.locked.load() !== 0) {
        // 外层循环：只读检查（不产生缓存行写入）
        // 减少总线流量
      }
      if (this.locked.compareAndSwap(0, 1)) {
        return; // 获取成功
      }
    }
  }

  unlock(): void {
    this.locked.store(0);
  }
}


TTAS 优化的关键在于：先通过普通读取检查锁状态（不会产生缓存行独占请求），只有在锁看起来空闲时才执行 CAS（会产生缓存行独占请求）。这大大减少了多核之间的缓存一致性流量。






分类与变体
读写锁（Read-Write Lock）的实现
读写锁需要维护更复杂的状态——区分读者和写者：


读写锁 {
    读者计数: 0     // 当前持有读锁的线程数量
    写者标志: 假     // 是否有线程持有写锁
    等待写者队列: []
    等待读者队列: []
}

函数 read_lock():
    等待直到 写者标志 == 假
    读者计数 += 1    // 原子操作

函数 read_unlock():
    读者计数 -= 1    // 原子操作
    如果 读者计数 == 0 且 等待写者队列不为空:
        唤醒第一个等待的写者

函数 write_lock():
    等待直到 写者标志 == 假 且 读者计数 == 0
    写者标志 = 真

函数 write_unlock():
    写者标志 = 假
    如果 等待写者队列不为空:
        唤醒第一个等待的写者
    否则如果 等待读者队列不为空:
        唤醒所有等待的读者
递归锁（Recursive Lock）的实现
递归锁在互斥锁的基础上增加了线程标识和计数器：


class RecursiveMutex {
  private owner: number | null = null;
  private count = 0;
  private innerLock = new Mutex();

  lock(threadId: number): void {
    if (this.owner === threadId) {
      this.count += 1;
      return;
    }
    this.innerLock.lock();
    this.owner = threadId;
    this.count = 1;
  }

  unlock(threadId: number): void {
    if (this.owner !== threadId) {
      throw new Error('非锁持有者不能释放锁');
    }
    this.count -= 1;
    if (this.count === 0) {
      this.owner = null;
      this.innerLock.unlock();
    }
  }
}
条件变量（Condition Variable）
条件变量通常与互斥锁配合使用，实现"等待某个条件成立"的语义：


条件变量 {
    等待队列: []
}

函数 wait(互斥锁, 条件变量):
    将当前线程加入条件变量的等待队列
    释放互斥锁                    // 重要：等待前必须释放锁
    挂起当前线程
    // ——被唤醒后——
    重新获取互斥锁                // 唤醒后必须重新获取锁

函数 signal(条件变量):
    唤醒等待队列中的一个线程

函数 broadcast(条件变量):
    唤醒等待队列中的所有线程
生产者-消费者模式的实现：


class BoundedBuffer<T> {
  private buffer: T[] = [];
  private capacity: number;
  private lock = new Mutex();
  private notEmpty = new ConditionVariable();
  private notFull = new ConditionVariable();

  constructor(capacity: number) {
    this.capacity = capacity;
  }

  produce(item: T): void {
    this.lock.lock();
    try {
      while (this.buffer.length >= this.capacity) {
        this.notFull.wait(this.lock);
      }
      this.buffer.push(item);
      this.notEmpty.signal();
    } finally {
      this.lock.unlock();
    }
  }

  consume(): T {
    this.lock.lock();
    try {
      while (this.buffer.length === 0) {
        this.notEmpty.wait(this.lock);
      }
      const item = this.buffer.shift()!;
      this.notFull.signal();
      return item;
    } finally {
      this.lock.unlock();
    }
  }
}

锁的优化技术
在实际系统中，锁的实现通常会采用多种优化技术来提升性能：


锁粗化
// 优化前：频繁的加锁/解锁
函数 处理列表(列表):
    对于 列表中的每个元素:
        获取锁(锁)
        处理(元素)
        释放锁(锁)
    // 如果列表有 1000 个元素，就要加锁/解锁 1000 次

// 优化后：锁粗化，一次加锁处理所有元素
函数 处理列表(列表):
    获取锁(锁)
    对于 列表中的每个元素:
        处理(元素)
    释放锁(锁)
    // 只需加锁/解锁 1 次，但临界区变长了
锁消除
// 编译器优化：如果检测到锁保护的数据不会被其他线程访问，自动消除锁操作
函数 本地计算():
    局部变量 buffer = 新建列表()    // 局部变量，不会逃逸到其他线程
    获取锁(buffer.锁)                // 编译器检测到：这把锁是多余的
    buffer.添加(1)
    buffer.添加(2)
    释放锁(buffer.锁)                // 编译器自动移除这些锁操作
    返回 buffer

小结
    

  • 互斥锁基于 CAS 原子操作实现获取，通过操作系统的线程挂起/唤醒机制处理等待
    • 

  • 自旋锁纯粹在用户空间实现，通过 CAS 循环重试获取锁，适合极短的临界区；TTAS 优化可减少缓存行争用
    • 

  • 读写锁通过维护读者计数和写者标志，允许多个读者共存或独占一个写者
    • 

  • 递归锁在互斥锁基础上增加线程标识和重入计数，允许同一线程多次获取
    • 

  • 条件变量与互斥锁配合，实现"等待条件成立"的语义，是生产者-消费者模式的基础
    • 

  • 锁的优化技术包括无锁编程、锁粗化、锁消除、公平调度，需根据具体场景选择
    • 

  • 选择锁类型时应综合考虑临界区长度、读写比例、重入需求、公平性要求等因素
    •
