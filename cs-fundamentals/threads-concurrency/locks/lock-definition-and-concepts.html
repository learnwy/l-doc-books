Part III · 系统 (Systems)线程与并发 简介锁 简介锁的定义与核心概念

锁的定义与核心概念

问题背景

当多个线程需要访问和修改共享资源时，如果不加以控制，就会出现数据竞争——多个线程的操作相互交错，导致不可预期的结果。虽然原子操作可以保护单个变量的简单操作，但对于涉及多个变量或多步操作的场景，我们需要一种更通用的同步机制。

锁（Lock） 就是这样一种机制：它在共享资源周围建立一个"保护区"，一次只允许一个（或有限个）线程进入。

// 没有锁保护的转账操作 —— 可能出错
函数 转账(发送方, 接收方, 金额):
    如果 发送方.余额 >= 金额:        // 步骤 1：检查余额
        发送方.余额 -= 金额           // 步骤 2：扣款
        接收方.余额 += 金额           // 步骤 3：入账
    // ⚠️ 如果两个线程同时执行转账，可能在步骤 1 和步骤 2 之间被打断
    // 导致余额不一致

// 有锁保护的转账操作 —— 安全
函数 安全转账(发送方, 接收方, 金额):
    获取锁(账户锁)
    如果 发送方.余额 >= 金额:
        发送方.余额 -= 金额
        接收方.余额 += 金额
    释放锁(账户锁)
    // ✅ 整个操作在锁的保护下原子执行


核心原理
什么是锁
锁（Lock） 是一种同步原语，用于控制多个线程对共享资源的并发访问。锁的基本语义非常简单：


    

  1. 获取锁（Acquire / Lock）：线程在访问共享资源前，必须先获取锁。如果锁已被其他线程持有，当前线程需要等待
    2. 

  2. 释放锁（Release / Unlock）：线程完成对共享资源的访问后，释放锁，允许其他等待的线程获取
    3. 



获取锁和释放锁之间的代码区域称为临界区（Critical Section）——同一时刻只有持有锁的线程可以执行临界区内的代码。

互斥锁 vs 自旋锁
这是最基本的两种锁，区别在于等待策略：


// 互斥锁的使用
class MutexExample {
  private mutex = new Mutex();
  private sharedData = 0;

  safeUpdate(): void {
    this.mutex.lock(); // 获取失败则线程挂起
    this.sharedData += 1;
    this.mutex.unlock();
  }
}

// 自旋锁的使用
class SpinlockExample {
  private spinlock = new Spinlock();
  private sharedData = 0;

  safeUpdate(): void {
    this.spinlock.lock(); // 获取失败则循环重试
    this.sharedData += 1;
    this.spinlock.unlock();
  }
}

class ReadWriteLockExample {
  private rwLock = new ReadWriteLock();
  private cache = new Map<string, number>();

  read(key: string): number | undefined {
    this.rwLock.readLock();
    const value = this.cache.get(key);
    this.rwLock.readUnlock();
    return value;
  }

  write(key: string, value: number): void {
    this.rwLock.writeLock();
    this.cache.set(key, value);
    this.rwLock.writeUnlock();
  }
}
递归锁
普通互斥锁如果被同一线程重复获取会导致死锁。递归锁允许同一线程多次获取，内部维护一个计数器：


递归锁 {
    持有者: 无
    计数器: 0
}

获取(线程):
    如果 持有者 == 线程:
        计数器 += 1      // 同一线程再次获取，计数器加一
    否则:
        等待直到锁空闲
        持有者 = 线程
        计数器 = 1

释放(线程):
    计数器 -= 1
    如果 计数器 == 0:
        持有者 = 无       // 计数器归零才真正释放

锁粒度：粗粒度 vs 细粒度
锁粒度决定了锁保护的范围大小，直接影响并发度和复杂度：


// 粗粒度锁：一把锁保护整个 Map
class CoarseGrainedMap {
  private lock = new Mutex();
  private data = new Map<string, number>();

  get(key: string): number | undefined {
    this.lock.lock();
    const val = this.data.get(key);
    this.lock.unlock();
    return val;
  }

  set(key: string, value: number): void {
    this.lock.lock();
    this.data.set(key, value);
    this.lock.unlock();
  }
}

// 细粒度锁：按 key 的哈希分段加锁
class FineGrainedMap {
  private segments: Array<{ lock: Mutex; data: Map<string, number> }>;

  constructor(segmentCount: number) {
    this.segments = Array.from({ length: segmentCount }, () => ({
      lock: new Mutex(),
      data: new Map(),
    }));
  }

  private getSegment(key: string): { lock: Mutex; data: Map<string, number> } {
    const hash = this.hashCode(key);
    return this.segments[hash % this.segments.length];
  }

  get(key: string): number | undefined {
    const seg = this.getSegment(key);
    seg.lock.lock();
    const val = seg.data.get(key);
    seg.lock.unlock();
    return val;
  }

  set(key: string, value: number): void {
    const seg = this.getSegment(key);
    seg.lock.lock();
    seg.data.set(key, value);
    seg.lock.unlock();
  }

  private hashCode(s: string): number {
    let h = 0;
    for (let i = 0; i < s.length; i++) h = (h * 31 + s.charCodeAt(i)) | 0;
    return Math.abs(h);
  }
}

没有"最好的锁"，只有"最适合当前场景的锁"。选择锁类型时需要综合考虑操作时长、读写比例、竞争激烈程度等因素。






小结
    

  • 锁是并发编程中最通用的同步原语，通过"获取-执行-释放"的模式保护共享资源
    • 

  • 锁的核心作用是建立临界区，确保同一时刻只有有限数量的线程可以访问共享数据
    • 

  • 常见锁类型包括互斥锁、自旋锁、读写锁、递归锁、条件锁等，各有不同的等待策略和适用场景
    • 

  • 公平锁按请求顺序授予锁，避免饥饿；非公平锁允许插队，追求更高吞吐
    • 

  • 锁粒度的选择是性能与复杂度之间的权衡：粗粒度简单但并发度低，细粒度并发度高但实现复杂
    • 

  • 选择锁类型时需综合考虑操作时长、读写比例、竞争程度等因素
    •
