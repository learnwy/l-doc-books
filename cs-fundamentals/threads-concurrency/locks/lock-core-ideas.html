Part III · 系统 (Systems)线程与并发 简介锁 简介锁的核心思想

锁的核心思想

问题背景

锁作为并发编程中最基本的同步工具，其设计背后蕴含着几个关键思想。理解这些思想不仅有助于正确使用锁，更能帮助我们在面对复杂并发问题时做出正确的设计决策。

锁要解决的根本问题是：如何在多个线程之间协调对共享资源的访问，保证数据的一致性和程序的正确性。



核心原理
思想一：互斥（Mutual Exclusion）
互斥是锁最根本的思想——在同一时刻，只有一个线程可以进入临界区访问共享资源。所有其他试图进入的线程必须等待。


这个约束看似简单，但它是保证数据一致性的基石。没有互斥，多个线程可以同时修改同一数据，导致最终结果取决于线程调度的时序（即不确定性行为）。


// 互斥的本质：将并行操作串行化
// 没有互斥：线程 A 和 B 可能同时修改 balance
//           结果取决于谁先写回 → 不确定行为

// 有互斥：线程 A 和 B 的操作被强制排序
//         A 先完成，B 再执行 → 确定性行为

函数 取款(账户, 金额):
    获取锁(账户.锁)       // 进入临界区
    如果 账户.余额 >= 金额:
        账户.余额 -= 金额
        结果 = 成功
    否则:
        结果 = 余额不足
    释放锁(账户.锁)       // 离开临界区
    返回 结果

// 混合策略的伪实现
class AdaptiveLock {
  private locked = new AtomicInteger(0);
  private spinLimit = 100;

  lock(): void {
    for (let i = 0; i < this.spinLimit; i++) {
      if (this.locked.compareAndSwap(0, 1)) {
        return;
      }
    }
    this.blockingWait();
  }

  private blockingWait(): void {
    while (!this.locked.compareAndSwap(0, 1)) {
      parkThread();
    }
  }

  unlock(): void {
    this.locked.store(0);
    wakeWaitingThread();
  }
}
思想三：死锁预防
死锁（Deadlock） 是锁使用中最危险的问题——两个或多个线程互相等待对方释放锁，导致所有线程永久阻塞。


死锁的四个必要条件
死锁的发生需要同时满足以下四个条件。只要打破其中任何一个，就不会发生死锁：






条件
含义
打破方法





互斥
资源一次只能被一个线程使用
使用共享资源（如读写锁的读模式）




持有并等待
线程持有一个锁的同时等待另一个锁
一次性获取所有需要的锁




不可抢占
已获取的锁不能被其他线程强行夺取
使用 tryLock（超时放弃）




循环等待
线程之间形成锁的环形等待链
按固定顺序获取锁





经典的死锁场景：


// ❌ 死锁示例：两个线程以不同顺序获取两把锁
线程 A:
    获取锁(锁1)
    获取锁(锁2)    // 等待线程 B 释放 锁2
    ...
    释放锁(锁2)
    释放锁(锁1)

线程 B:
    获取锁(锁2)
    获取锁(锁1)    // 等待线程 A 释放 锁1
    ...
    释放锁(锁1)
    释放锁(锁2)

// 线程 A 持有 锁1 等待 锁2
// 线程 B 持有 锁2 等待 锁1
// → 循环等待 → 死锁！
预防死锁的策略
// ✅ 策略 1：固定加锁顺序
// 所有线程都按 锁1 → 锁2 的顺序获取
线程 A:
    获取锁(锁1)
    获取锁(锁2)
    ...

线程 B:
    获取锁(锁1)    // 不再先获取 锁2
    获取锁(锁2)
    ...

// ✅ 策略 2：使用 tryLock 超时机制
线程 A:
    获取锁(锁1)
    如果 尝试获取锁(锁2, 超时=100毫秒) 失败:
        释放锁(锁1)     // 放弃已持有的锁，避免死锁
        稍后重试

// ✅ 策略 3：一次性获取所有锁
函数 安全转账(账户A, 账户B, 金额):
    // 按账户 ID 排序，保证固定加锁顺序
    (先锁, 后锁) = 排序(账户A.锁, 账户B.锁)
    获取锁(先锁)
    获取锁(后锁)
    执行转账
    释放锁(后锁)
    释放锁(先锁)

线程 A:
    重复:
        获取锁(锁1)
        如果 尝试获取(锁2) 失败:
            释放锁(锁1)     // "让路"

    重复:

            释放锁(锁1)
            等待(随机时间)   // 随机退避打破同步

锁的安全使用模式
// ✅ 安全的锁使用模式：try-finally 保证释放
function safeOperation(lock: Mutex): void {
  lock.lock();
  try {
    doSomethingWithSharedResource();
  } finally {
    lock.unlock();
  }
}

// ✅ 使用 RAII 模式自动管理锁（推荐）
function withLock<T>(lock: Mutex, operation: () => T): T {
  lock.lock();
  try {
    return operation();
  } finally {
    lock.unlock();
  }
}

const result = withLock(mutex, () => {
  return readAndModifySharedData();
});

小结
    

  • 互斥是锁最核心的思想——确保同一时刻只有一个线程可以访问临界区
    • 

  • 等待策略决定了线程获取锁失败后的行为：阻塞等待适合长临界区，自旋等待适合短临界区，混合策略兼顾两者
    • 

  • 死锁是锁使用中最严重的问题，需要同时满足四个条件才能发生：互斥、持有并等待、不可抢占、循环等待
    • 

  • 通过固定加锁顺序、超时放弃、一次性获取所有锁等策略可以有效预防死锁
    • 

  • 除死锁外，还需关注活锁（不断重试但无法推进）和饥饿（长期无法获取锁）问题
    • 

  • 安全使用锁的关键原则：最小化临界区、固定加锁顺序、在 finally 中释放锁
