线程的实现机制

线程的创建

线程的创建方式因线程类型（用户级、内核级）和具体平台而异，但基本过程都包括：分配线程控制块（TCB）、分配独立的栈空间、设置初始上下文，然后将线程加入调度队列。

通用线程创建模型
FUNCTION create_thread(thread_function, arguments):
    tcb = allocate_TCB()
    tcb.thread_id = generate_unique_id()
    tcb.state = NEW
    tcb.stack = allocate_stack(default_stack_size)
    tcb.program_counter = address_of(thread_function)
    tcb.registers = initialize_registers()
    tcb.arguments = arguments

    tcb.state = READY
    add_to_ready_queue(tcb)

    RETURN tcb.thread_id
END FUNCTION
不同环境的创建示例
async function fetchData(url: string): Promise<string> {
  const response = await fetch(url);
  return response.text();
}

const worker = new Worker('worker.ts');
worker.postMessage({ type: 'start', data: [1, 2, 3] });

worker.onmessage = (event) => {
  console.log('收到结果:', event.data);
};

线程的调度
线程调度决定了在任意时刻哪个线程获得 CPU 执行权。根据线程类型的不同，调度可以发生在用户空间或内核空间。


内核级线程调度
内核级线程由操作系统内核直接调度，调度策略与进程调度类似（优先级、时间片轮转等），但调度粒度更细。


FUNCTION kernel_thread_scheduler():
    LOOP:
        IF timer_interrupt OR thread_blocked OR thread_yield THEN
            current = get_current_thread()
            save_context(current)
            current.state = READY  // 或 BLOCKED
            add_to_ready_queue(current)

            next = pick_next_thread(ready_queue)  // 按调度策略选择
            remove_from_ready_queue(next)
            next.state = RUNNING
            restore_context(next)
            switch_to(next)
        END IF
    END LOOP
END FUNCTION
用户级线程调度
用户级线程由用户空间的线程库自行调度，内核对此毫不知情。调度发生在用户态，切换速度更快，但无法利用多核。


FUNCTION user_thread_scheduler():
    LOOP:
        current = get_current_user_thread()
        IF current.yielded OR current.blocked THEN
            save_user_context(current)
            next = pick_next_from_user_queue()
            restore_user_context(next)
            jump_to(next.program_counter)
        END IF
    END LOOP
END FUNCTION

线程同步机制
当多个线程共享资源时，必须使用同步机制来保证数据一致性和执行顺序的正确性。以下是四种最基本的同步原语。


锁（Mutex / 互斥锁）
互斥锁是最基本的同步机制，保证在任意时刻最多只有一个线程进入临界区。


mutex = create_mutex()

FUNCTION thread_safe_increment():
    lock(mutex)
    // ─── 临界区开始 ───
    shared_counter = shared_counter + 1
    // ─── 临界区结束 ───
    unlock(mutex)
END FUNCTION
信号量（Semaphore）
信号量是一个维护计数器的同步原语，可以控制同时访问某资源的线程数量。互斥锁是计数器为 1 的特殊信号量。


// 信号量：允许最多 3 个线程同时访问
semaphore = create_semaphore(initial_value: 3)

FUNCTION access_limited_resource(thread_id):
    wait(semaphore)     // P 操作：计数器 - 1，若 < 0 则阻塞
    print(thread_id, "正在访问资源")
    use_resource()
    signal(semaphore)   // V 操作：计数器 + 1，唤醒等待者
END FUNCTION
条件变量（Condition Variable）
条件变量允许线程在某个条件不满足时挂起等待，当条件满足时被其他线程唤醒。通常与互斥锁配合使用。


mutex = create_mutex()
cond = create_condition_variable()
queue = []

// 生产者
FUNCTION producer(item):
    lock(mutex)
    queue.push(item)
    signal(cond)        // 通知消费者：有新数据了
    unlock(mutex)
END FUNCTION

// 消费者
FUNCTION consumer():
    lock(mutex)
    WHILE queue is empty:
        wait(cond, mutex) // 释放锁并等待通知，被唤醒后重新获取锁
    END WHILE
    item = queue.pop()
    unlock(mutex)
    RETURN item
END FUNCTION
屏障（Barrier）
屏障要求一组线程全部到达某个同步点后才能继续执行，常用于并行计算中阶段之间的同步。


barrier = create_barrier(thread_count: 4)

FUNCTION parallel_task(thread_id):
    // 阶段 1：各线程独立计算
    result = compute_phase_1(thread_id)

    wait_at_barrier(barrier)  // 等待所有 4 个线程都到达此处

    // 阶段 2：所有线程同步完成后才继续
    compute_phase_2(thread_id, all_results)
END FUNCTION

线程的生命周期管理
线程的终止
线程可以通过以下方式终止：


// 方式 1：线程函数正常返回
FUNCTION thread_task():
    do_work()
    RETURN result  // 线程自然结束

// 方式 2：线程主动退出
FUNCTION thread_task_with_exit():
    IF should_stop THEN
        thread_exit(0)
    END IF

// 方式 3：被其他线程取消
FUNCTION cancel_thread(target_thread):
    request_cancel(target_thread)
    // 目标线程在下一个取消点检查并退出
线程的合并（Join）
父线程（或创建者线程）可以调用 join 等待子线程完成，并获取其返回值：


FUNCTION main():
    t1 = create_thread(compute, data1)
    t2 = create_thread(compute, data2)

    result1 = join(t1)  // 阻塞直到 t1 完成
    result2 = join(t2)  // 阻塞直到 t2 完成

    final_result = combine(result1, result2)
END FUNCTION
线程的分离（Detach）
如果不需要等待线程完成或获取其返回值，可以将线程分离，让操作系统在线程结束时自动回收资源：


FUNCTION fire_and_forget():
    t = create_thread(background_task)
    detach(t)  // 不再等待，线程结束后自动清理
END FUNCTION

小结
    

  • 线程创建的核心步骤包括分配 TCB、分配栈空间、初始化上下文、加入调度队列，用户级和内核级线程在分配位置和是否需要系统调用上有所不同。
    • 

  • 线程调度分为内核级调度（由 OS 内核管理，可利用多核，支持抢占）和用户级调度（由线程库管理，切换快但无法利用多核），两者各有优劣。
    • 

  • 线程同步的四种基本机制——互斥锁（互斥访问）、信号量（控制并发数）、条件变量（条件等待）、屏障（阶段同步）——是构建正确多线程程序的基石。
    • 

  • 线程的生命周期管理（join、detach、cancel）决定了线程资源的回收方式，需根据业务场景选择合适的策略。
    •
