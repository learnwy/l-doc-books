Part III · 系统 (Systems)线程与并发 简介线程 简介线程的核心思想

线程的核心思想

轻量级并发——共享进程资源

线程最核心的设计思想是轻量级并发。与进程不同，线程不需要独立的地址空间和资源副本，而是共享所属进程的全部资源。这使得线程的创建、销毁和切换开销远小于进程，从而实现更高效的并发执行。

开销对比
创建一个新进程和创建一个新线程的开销差异是巨大的：

// 多进程方案：每个任务一个进程
FUNCTION multi_process_approach(tasks):
    FOR EACH task IN tasks:
        pid = fork()                    // 开销大：复制整个地址空间
        IF pid == 0 THEN
            execute(task)
            exit(0)
        END IF
    END FOR
    wait_all()

// 多线程方案：每个任务一个线程
FUNCTION multi_thread_approach(tasks):
    threads = []
    FOR EACH task IN tasks:
        t = create_thread(execute, task) // 开销小：只分配栈
        threads.append(t)
    END FOR
    join_all(threads)
为什么轻量很重要
在高并发场景下，线程的轻量特性直接影响系统的可扩展性：


场景：Web 服务器同时处理 1000 个请求

多进程方案：
  - 创建 1000 个进程
  - 每个进程约占 10MB 独立内存 → 总计 ~10GB
  - 进程切换需要刷新 TLB → 切换慢
  - 系统负载高，响应延迟大

多线程方案：
  - 创建 1000 个线程
  - 每个线程约占 1MB 栈空间 → 总计 ~1GB
  - 同进程线程切换无需刷新 TLB → 切换快
  - 系统负载低，响应延迟小
并行执行——充分利用多核
线程的第二个核心思想是并行执行。在多核处理器上，同一进程内的多个线程可以被分配到不同的 CPU 核心上真正同时执行，从而成倍提升计算能力。


并行加速的理论极限
并行加速并非无限——**阿姆达尔定律（Amdahl's Law）**指出，程序中必须串行执行的部分限制了整体加速比的上限：


加速比 S = 1 / (s + (1-s)/N)

其中：
  s = 程序中串行部分的比例
  N = 处理器核心数

示例：
  若程序有 10% 必须串行 (s = 0.1)：
    2 核加速比 = 1 / (0.1 + 0.9/2)  = 1.82x
    4 核加速比 = 1 / (0.1 + 0.9/4)  = 3.08x
    8 核加速比 = 1 / (0.1 + 0.9/8)  = 4.71x
    ∞ 核加速比 = 1 / 0.1            = 10x（理论极限）

适合并行的任务类型
✓ 适合多线程并行：
  - CPU 密集型计算（图像处理、数据分析、矩阵运算）
  - 可独立分割的批处理任务
  - 互不依赖的 I/O 请求

✗ 不适合多线程并行：
  - 高度依赖前序结果的串行计算
  - 数据依赖紧密、需要频繁同步的任务
  - 单步计算量极小但步骤极多的流水线
资源共享——降低通信成本
线程的第三个核心思想是资源共享。由于同一进程内的线程共享地址空间，线程间的数据交换无需通过操作系统中转，可以直接读写共享变量，通信效率远高于进程间通信（IPC）。

共享的代价——同步问题
资源共享虽然提高了通信效率，但也引入了数据一致性问题。当多个线程同时读写共享数据时，如果没有适当的同步机制，就会出现竞态条件（Race Condition）：


// 竞态条件示例
shared_variable counter = 0

THREAD_A:
    temp = counter      // 读取：temp = 0
    temp = temp + 1     // 计算：temp = 1
    counter = temp      // 写回：counter = 1

THREAD_B:               // 与线程 A 同时执行！
    temp = counter      // 读取：temp = 0（还没看到线程 A 的写入）
    temp = temp + 1     // 计算：temp = 1
    counter = temp      // 写回：counter = 1

// 预期结果：counter = 2
// 实际结果：counter = 1（丢失了一次更新！）

小结
    

  • 轻量级并发是线程区别于进程的核心特征：线程共享进程的地址空间和资源，创建和切换开销远小于进程，使得高并发场景更加高效。
    • 

  • 并行执行是多线程的关键收益：在多核处理器上，多个线程可以真正同时运行，但加速效果受限于阿姆达尔定律中程序的串行比例。
    • 

  • 资源共享是线程间高效通信的基础：线程可直接读写共享变量而无需内核中转，但同时引入了竞态条件等数据一致性问题，必须通过同步机制来保障正确性。
    • 

  • 三大核心思想相互关联、相互制约——轻量使并行成为可能，共享使通信更高效，但也带来了同步复杂性和故障隔离弱的代价。
