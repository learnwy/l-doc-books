Part III · 系统 (Systems)线程与并发 简介补充主题 简介竞态条件

竞态条件

问题描述

竞态条件（Race Condition） 是指多个并发执行的线程或进程，在没有适当同步的情况下，同时访问和操作共享数据，导致程序结果依赖于执行的先后顺序——而这个顺序是不确定的。

竞态条件是并发编程中最常见、最隐蔽的错误之一。程序可能在大部分时间"正常"运行，但偶尔产生错误结果，且难以稳定复现。

两个线程各自加 1，期望结果是 2，实际结果却是 1——因为线程 B 读取时还未看到线程 A 的写入。




核心概念
竞态条件的本质
竞态条件的根本原因在于非原子操作：一个逻辑上应该不可分割的操作，在实际执行时被分解为多个步骤，而这些步骤之间可能被其他线程插入。

典型场景
场景一：读-改-写（Read-Modify-Write）
这是最经典的竞态条件模式：


共享变量 balance = 1000

线程A（取款 500）:
    temp = 读取 balance          // temp = 1000
    // ⚠️ 此时线程B也在执行
    temp = temp - 500            // temp = 500
    写入 balance = temp          // balance = 500

线程B（取款 300）:
    temp = 读取 balance          // temp = 1000（读到了旧值！）
    temp = temp - 300            // temp = 700
    写入 balance = temp          // balance = 700 ❌

// 最终 balance = 700，但实际应该是 200
场景二：检查-执行（Check-Then-Act）
先检查某个条件，再基于检查结果执行操作。问题在于检查和执行之间存在时间窗口。


共享变量 tickets = 1   // 仅剩 1 张票

线程A:
    如果 tickets > 0:        // 检查: true
        // ⚠️ 线程B同时通过了检查
        tickets = tickets - 1 // 执行: tickets = 0
        打印 "购票成功"

线程B:
    如果 tickets > 0:        // 检查: true（此时还没减）
        tickets = tickets - 1 // 执行: tickets = -1 ❌
        打印 "购票成功"

// 两个线程都"成功"购票，但实际只有 1 张票
场景三：复合操作
多个操作需要作为整体执行，但中间被其他线程打断：


// 转账操作：应该是原子的
函数 transfer(from, to, amount):
    如果 from.balance >= amount:
        from.balance = from.balance - amount
        // ⚠️ 如果此处发生线程切换
        // 另一个线程可能看到不一致的状态
        // （钱已扣但未到账）
        to.balance = to.balance + amount

互斥锁

消息传递
用消息代替共享内存
从设计上消除竞态

线程局部存储
每个线程持有独立副本
无需同步
无法在线程间共享





使用锁保护的示例
共享变量 balance = 1000
互斥锁 balance_lock

线程A（取款 500）:
    获取锁(balance_lock)
        temp = 读取 balance        // temp = 1000
        temp = temp - 500
        写入 balance = temp        // balance = 500
    释放锁(balance_lock)

线程B（取款 300）:
    获取锁(balance_lock)           // 阻塞，等待线程A释放
        temp = 读取 balance        // temp = 500
        temp = temp - 300
        写入 balance = temp        // balance = 200 ✅
    释放锁(balance_lock)
使用原子操作的示例
interface AtomicCounter {
  value: number;
  compareAndSwap(expected: number, newValue: number): boolean;
}

function increment(counter: AtomicCounter): void {
  let success = false;
  while (!success) {
    const current = counter.value;
    success = counter.compareAndSwap(current, current + 1);
  }
}


小结
竞态条件是并发编程中最常见的正确性问题，核心要点如下：


    

  • 本质：非原子操作在并发执行时被交错，导致结果依赖于不确定的执行顺序
    • 

  • 两大经典模式：读-改-写（Read-Modify-Write）和检查-执行（Check-Then-Act）
    • 

  • 危害：程序表面运行正常，但偶尔产生不一致结果，极难复现和调试
    • 

  • 解决思路：互斥锁（加锁保护）、原子操作（硬件保证）、不可变数据（消除修改）、消息传递（消除共享）
    • 

  • 最根本的防御策略是减少共享可变状态——无共享则无竞态
