Part III · 系统 (Systems)线程与并发 简介补充主题 简介死锁、活锁与饥饿

死锁、活锁与饥饿

问题描述

在并发系统中，多个线程竞争有限资源时，可能出现三种典型的活性问题（Liveness Issues）：死锁（Deadlock）、活锁（Livelock） 和 饥饿（Starvation）。这三者都会导致线程无法正常推进工作，但其成因和表现形式各不相同。



核心概念
死锁（Deadlock）
死锁是指两个或多个线程互相持有对方需要的资源，同时又在等待对方释放资源，导致所有线程都无法继续执行的状态。


死锁的发生需要同时满足以下四个必要条件（Coffman 条件）：






条件
说明
示例





互斥（Mutual Exclusion）
资源一次只能被一个线程占用
一把锁同时只能一个线程持有




持有并等待（Hold and Wait）
线程持有至少一个资源，同时等待获取其他资源
持有锁 1，等待锁 2




不可剥夺（No Preemption）
资源只能由持有者主动释放，不能被强制回收
不能强制让线程释放锁




循环等待（Circular Wait）
存在线程的循环等待链
A 等 B，B 等 C，C 等 A







破坏其中任何一个条件，就可以避免死锁。




// 死锁示例
线程A:
    获取锁(锁1)         // ✅ 成功获取
    // ... 执行一些操作 ...
    获取锁(锁2)         // ❌ 阻塞！锁2被线程B持有

线程B:
    获取锁(锁2)         // ✅ 成功获取
    // ... 执行一些操作 ...
    获取锁(锁1)         // ❌ 阻塞！锁1被线程A持有

// 两个线程永远互相等待 → 死锁
活锁（Livelock）
活锁与死锁类似，线程也无法推进工作，但区别在于：活锁中的线程并没有阻塞，而是在持续地"做事"——只是做的事情没有意义。


活锁的经典比喻：两个人在窄走廊相遇，都想给对方让路，结果两人同时向左、又同时向右，谁也过不去。


// 活锁示例
线程A:
    循环:
        获取锁(锁1)
        如果 尝试获取锁(锁2) 失败:
            释放锁(锁1)        // "礼让"
            随机等待一小段时间
            继续循环             // 重试

线程B:
    循环:
        获取锁(锁2)
        如果 尝试获取锁(锁1) 失败:
            释放锁(锁2)        // "礼让"
            随机等待一小段时间
            继续循环             // 重试

// 如果两个线程总是同步重试，就会陷入活锁
饥饿（Starvation）
饥饿是指某个线程因为优先级低或调度不公平，始终无法获得所需资源，导致长期甚至永久无法执行。


饥饿的常见原因：






原因
说明





优先级调度不公平
高优先级线程不断抢占，低优先级线程永远无法执行




非公平锁
新到达的线程直接抢锁，排队等待的线程被忽略




贪婪线程
某线程长时间持有资源不释放




写者优先的读写锁
持续有写者时，读者永远无法获取读锁

三者对比




特征

饥饿

阻塞（完全卡住）
运行（但无意义）
就绪（但得不到执行）




CPU 使用
不消耗 CPU
消耗 CPU（空转）
不消耗 CPU




涉及线程
两个或多个
两个或多个
一个或多个




检测难度
较易（可检测等待图）
较难（线程表面活跃）

公平调度





经典场景：哲学家就餐问题
五位哲学家围坐圆桌，每人需要同时拿起左右两根筷子才能吃饭。这个经典问题可以同时展示死锁和饥饿。


// 死锁场景：每人先拿左边筷子
哲学家i:
    循环:
        思考()
        拿起(左边筷子)     // 所有人同时拿起左边
        拿起(右边筷子)     // 所有人都在等待右边 → 死锁！
        吃饭()
        放下(左边筷子)
        放下(右边筷子)


解决方案
死锁的解决策略




策略
方法
说明





锁排序
所有线程按相同顺序获取锁
破坏循环等待条件




超时获取
获取锁时设定超时时间
超时后释放已持有的锁并重试




一次性获取
一次获取所有需要的锁
破坏持有并等待条件




银行家算法
分配前检查是否安全
避免进入不安全状态





// 锁排序策略
全局约定: 锁1 的编号 < 锁2 的编号，总是先获取编号小的

线程A:
    获取锁(锁1)     // 先获取编号小的
    获取锁(锁2)     // 再获取编号大的
    // 安全执行
    释放锁(锁2)
    释放锁(锁1)

线程B:
    获取锁(锁1)     // 同样先获取编号小的（而非锁2）
    获取锁(锁2)     // 再获取编号大的
    // 安全执行
    释放锁(锁2)
    释放锁(锁1)

// 不会出现循环等待 → 不会死锁
活锁的解决策略
// 随机退避策略
线程A:
    循环:
        获取锁(锁1)
        如果 尝试获取锁(锁2) 失败:
            释放锁(锁1)
            等待(随机时间)     // 关键：随机化等待时间
            继续循环

// 随机等待时间使两个线程不再同步重试
饥饿的解决策略




策略
说明





公平锁
按请求顺序分配锁，FIFO 保证先到先得




优先级老化
等待时间越长，优先级自动提升




时间片轮转
每个线程分配固定时间片，轮流执行




资源配额
限制单个线程可持有的最大资源量







小结
死锁、活锁和饥饿是并发系统中三种典型的活性问题：


    

  • 死锁：线程互相持有对方需要的资源并等待，全部卡住。需要同时满足互斥、持有并等待、不可剥夺、循环等待四个条件。通过锁排序、超时获取或银行家算法预防和避免
    • 

  • 活锁：线程不断响应但没有实质进展，CPU 空转。通过引入随机退避来打破同步重试的循环
    • 

  • 饥饿：某些线程长期得不到资源。通过公平锁、优先级老化等机制保证调度公平性
    • 

  • 三者的共同点是线程无法正常推进工作；区别在于线程的状态和 CPU 消耗模式不同
    • 

  • 哲学家就餐问题是理解这三种问题的经典模型
    •
