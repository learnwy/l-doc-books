Part III · 系统 (Systems)线程与并发 简介补充主题 简介信号量与条件变量

信号量与条件变量

问题描述

在并发编程中，仅靠互斥锁（Mutex）只能实现"互斥访问"——即保证临界区一次只有一个线程执行。但很多场景还需要线程间的协调与通信：例如生产者需要通知消费者"有新数据了"，或者限制同时访问某个资源的线程数量。信号量（Semaphore） 和 条件变量（Condition Variable） 正是为此设计的同步原语。



核心概念
信号量（Semaphore）
信号量是一个维护内部计数器的同步原语，用于控制同时访问某个资源的线程数量。


基本操作：






操作
别名
说明





wait()
P 操作 / acquire / down
计数器减 1；若计数器 < 0，线程阻塞等待




signal()
V 操作 / release / up
计数器加 1；若有线程在等待，唤醒一个





信号量 sem(初始值 = N)

wait(sem):
    sem.count = sem.count - 1
    如果 sem.count < 0:
        将当前线程加入等待队列
        阻塞当前线程

signal(sem):
    sem.count = sem.count + 1
    如果 等待队列非空:
        唤醒队列中的一个线程

典型场景
条件变量（Condition Variable）
条件变量是一种允许线程在某个条件不满足时挂起等待，并在条件满足时被其他线程唤醒的同步机制。它必须与互斥锁配合使用。


基本操作：






操作
说明





wait(cond, mutex)
释放互斥锁，挂起等待；被唤醒后重新获取锁




signal(cond)
唤醒一个等待中的线程




broadcast(cond)
唤醒所有等待中的线程





条件变量 cond
互斥锁 mutex

// 等待方（消费者）
获取锁(mutex)
当 条件不满足 时:       // 必须用循环，防止虚假唤醒
    wait(cond, mutex)    // 原子地释放锁并挂起
// 被唤醒后，锁已重新获取
执行操作()
释放锁(mutex)

// 通知方（生产者）
获取锁(mutex)
修改共享状态使条件满足
signal(cond)             // 或 broadcast(cond)
释放锁(mutex)


虚假唤醒（Spurious Wakeup）：系统可能在没有 signal 的情况下唤醒等待线程。因此等待条件必须放在循环中，而非简单的 if 判断。






解决方案
生产者-消费者模式
这是信号量和条件变量最经典的应用场景。生产者生产数据放入缓冲区，消费者从缓冲区取出数据。


使用信号量实现
信号量 empty = N        // 缓冲区空位数量
信号量 full = 0         // 缓冲区已有数据数量
互斥锁 mutex            // 保护缓冲区的互斥访问

生产者:
    循环:
        item = 生产数据()
        wait(empty)          // 等待有空位
        获取锁(mutex)
            缓冲区.放入(item)
        释放锁(mutex)
        signal(full)         // 通知消费者有新数据

消费者:
    循环:
        wait(full)           // 等待有数据
        获取锁(mutex)
            item = 缓冲区.取出()
        释放锁(mutex)
        signal(empty)        // 通知生产者有空位
        消费数据(item)
使用条件变量实现
互斥锁 mutex
条件变量 not_full
条件变量 not_empty
队列 buffer（容量 N）

生产者:
    循环:
        item = 生产数据()
        获取锁(mutex)
        当 buffer.size == N 时:
            wait(not_full, mutex)    // 缓冲区满，等待
        buffer.放入(item)
        signal(not_empty)            // 唤醒等待的消费者
        释放锁(mutex)

消费者:
    循环:
        获取锁(mutex)
        当 buffer.size == 0 时:
            wait(not_empty, mutex)   // 缓冲区空，等待
        item = buffer.取出()
        signal(not_full)             // 唤醒等待的生产者
        释放锁(mutex)
        消费数据(item)

无此问题

TypeScript 风格的信号量抽象
interface Semaphore {
  readonly count: number;
  acquire(): Promise<void>;
  release(): void;
}

function createSemaphore(maxCount: number): Semaphore {
  let count = maxCount;
  const waitQueue: Array<() => void> = [];

  return {
    get count() {
      return count;
    },
    acquire() {
      return new Promise<void>((resolve) => {
        if (count > 0) {
          count--;
          resolve();
        } else {
          waitQueue.push(resolve);
        }
      });
    },
    release() {
      const next = waitQueue.shift();
      if (next) {
        next();
      } else {
        count++;
      }
    },
  };
}


小结
信号量与条件变量是并发编程中两种重要的同步原语：


    

  • 信号量通过内部计数器控制并发访问数量，分为计数信号量（限制 N 个并发）和二元信号量（类似互斥锁）
    • 

  • 条件变量允许线程在条件不满足时挂起等待，条件满足时被唤醒，必须与互斥锁配合使用
    • 

  • 等待条件必须放在循环中以防止虚假唤醒
    • 

  • 生产者-消费者是两者最经典的应用场景，信号量用计数器隐式表达条件，条件变量用显式条件判断
    • 

  • 信号量适合简单的并发数量控制，条件变量适合复杂的条件等待与通知
    •
