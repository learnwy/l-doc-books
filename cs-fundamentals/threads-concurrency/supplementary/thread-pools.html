Part III · 系统 (Systems)线程与并发 简介补充主题 简介线程池与任务调度

线程池与任务调度

问题描述

在并发程序中，频繁创建和销毁线程会带来显著的性能开销——每次创建线程都需要分配内存、初始化栈空间和系统资源，销毁时还需要回收这些资源。当任务数量大、单个任务执行时间短时，线程管理的开销甚至可能超过任务本身的执行时间。

线程池（Thread Pool） 通过预先创建一组线程并复用它们来执行任务，从而避免了反复创建和销毁线程的开销。



核心概念
线程池的组成
线程池由三个核心组件构成：






组件
说明





任务队列（Task Queue）
存放等待执行的任务，通常是 FIFO 队列




工作线程（Worker Threads）
预先创建的线程，从队列中取任务并执行




池管理器（Pool Manager）
控制线程池的生命周期、线程数量和调度策略





工作线程的执行循环
每个工作线程的核心逻辑非常简单：不断从任务队列中取出任务并执行。


函数 Worker线程执行循环(taskQueue):
    循环:
        task = taskQueue.阻塞取出()    // 队列为空时阻塞等待
        如果 task == 终止信号:
            退出循环
        尝试:
            task.执行()
        捕获异常 error:
            记录错误(error)
            // Worker 不会因为单个任务失败而终止

线程池大小策略
线程池大小的选择直接影响系统性能。过小会导致任务排队等待，过大会导致线程间竞争和上下文切换开销。






任务类型
推荐池大小
说明





CPU 密集型
CPU 核心数 + 1
线程主要做计算，多了反而增加上下文切换




IO 密集型
CPU 核心数 × 2 ~ 4
线程经常等待 IO，多线程可提高 CPU 利用率




混合型
根据 IO 等待比例调整
等待时间越长，可配置更多线程





// 池大小计算公式（参考值）
最优线程数 = CPU核心数 × (1 + 平均等待时间 / 平均计算时间)

// 示例：4 核 CPU，任务平均等 200ms、算 100ms
最优线程数 = 4 × (1 + 200 / 100) = 12

解决方案
拒绝策略
当任务队列已满且线程数达到上限时，需要执行拒绝策略：






策略
说明
适用场景





丢弃（Discard）
直接丢弃新任务
允许丢失非关键任务




调用者执行（Caller Runs）
由提交任务的线程自己执行
需要反压（back-pressure）机制




丢弃最旧（Discard Oldest）
丢弃队列中最旧的任务，加入新任务
新任务更重要




抛出异常（Abort）
抛出异常通知调用者
不允许任务丢失





线程池的 TypeScript 抽象
interface Task {
  id: string;
  execute(): Promise<void>;
}

interface ThreadPoolConfig {
  coreSize: number;
  maxSize: number;
  queueCapacity: number;
  idleTimeout: number;
}

interface ThreadPool {
  submit(task: Task): Promise<void>;
  shutdown(): Promise<void>;
  getActiveCount(): number;
  getQueueSize(): number;
}
函数 创建线程池(config):
    workers = []
    taskQueue = 新建有界队列(config.queueCapacity)

    // 创建核心线程
    重复 config.coreSize 次:
        worker = 新建 Worker线程(taskQueue)
        worker.启动()
        workers.添加(worker)

    返回 {
        submit(task):
            如果 taskQueue 未满:
                taskQueue.放入(task)
            否则如果 workers.数量 < config.maxSize:
                worker = 新建 Worker线程(taskQueue)
                worker.启动()
                workers.添加(worker)
                taskQueue.放入(task)
            否则:
                执行拒绝策略(task)

        shutdown():
            对于 workers 中的每个 worker:
                taskQueue.放入(终止信号)
            等待所有 worker 结束
    }
线程池的优缺点




方面
优点
缺点





性能
避免频繁创建/销毁线程
池大小不当会影响性能




资源控制
限制最大并发数
需要合理配置参数




响应速度
任务提交后可立即执行
队列满时任务可能被拒绝




管理
统一管理线程生命周期
增加了系统复杂度







小结
线程池是管理并发任务的核心基础设施：


    

  • 核心思想：预创建线程并复用，通过任务队列解耦任务提交和执行
    • 

  • 三大组件：任务队列（缓冲任务）、工作线程（执行任务）、池管理器（调度控制）
    • 

  • 池大小选择：CPU 密集型任务选择接近核心数的线程数，IO 密集型任务可适当增加
    • 

  • 动态调整：支持核心线程数和最大线程数的弹性配置，空闲线程可自动回收
    • 

  • 拒绝策略：队列满时需要明确的处理策略，如丢弃、调用者执行或抛出异常
    • 

  • 合理配置的线程池能显著提升系统吞吐量和资源利用率
    •
