Part III · 系统 (Systems)线程与并发 简介补充主题 简介消息传递

消息传递

问题描述

并发编程的核心挑战之一是：多个执行单元如何安全地交换信息？传统方式通过共享内存通信，但这带来了竞态条件、死锁等一系列问题。消息传递（Message Passing） 提供了一种替代方案——并发实体之间不共享内存，而是通过发送和接收消息来交换数据。

"不要通过共享内存来通信，而是通过通信来共享内存。"



核心概念
消息传递的基本模型
消息传递是指并发实体之间通过发送（send）和接收（receive）消息来进行通信和同步，不涉及共享状态。






要素
说明





发送者
构造消息并发出




接收者
接收并处理消息




消息
承载数据的不可变载体




通道/地址
消息的传输路径或目标标识





同步 vs 异步
消息传递根据发送者是否等待接收者，分为两种模式：






模式
发送者行为
优点
缺点





同步
阻塞直到接收者收到消息
简单可靠，确认送达
发送者被阻塞，吞吐量受限




异步
立即返回，不等待
高吞吐，发送者不阻塞
需要缓冲区，可能消息丢失





两大消息传递模型
消息传递有两种主要的实现范式：CSP 模型（基于 Channel）和 Actor 模型（基于 Mailbox）。




典型场景
CSP 模型（Communicating Sequential Processes）
在 CSP 模型中，并发实体（进程/协程）通过 Channel（通道） 进行通信。Channel 是独立的通信管道，发送者和接收者通过 Channel 解耦。


// CSP 模型示例
channel = 创建通道(缓冲区大小 = 0)    // 无缓冲通道 = 同步

进程A:
    data = 计算结果()
    channel.发送(data)     // 阻塞直到进程B接收
    打印 "数据已发送"

进程B:
    data = channel.接收()  // 阻塞直到进程A发送
    处理(data)
    打印 "数据已处理"
Channel 的类型：






类型
说明
行为





无缓冲 Channel
容量为 0
发送者和接收者必须同时就绪（同步）




有缓冲 Channel
容量为 N
缓冲区未满时发送不阻塞（异步）




单向 Channel
只读或只写
编译时保证通信方向





Actor 模型
在 Actor 模型中，每个 Actor 拥有自己的 Mailbox（邮箱）。发送者通过 Actor 的地址直接发送消息到其邮箱。


// Actor 模型示例
WorkerActor:
    私有状态 results = []

    收到 "compute(data)" 消息:
        result = 执行计算(data)
        results.添加(result)
        向 sender 回复 { type: "done", result: result }

    收到 "get_results" 消息:
        向 sender 回复 { type: "results", data: results }

消息传递模式


解决方案
扇出-扇入模式
这是消息传递中常用的并发处理模式：将一个大任务拆分为多个子任务（扇出），各子任务并行处理后汇总结果（扇入）。


// 扇出-扇入示例（CSP 风格）
taskChannel = 创建通道()
resultChannel = 创建通道()

// 扇出：启动多个 Worker
重复 3 次:
    启动进程:
        循环:
            task = taskChannel.接收()
            result = 处理(task)
            resultChannel.发送(result)

// 分发任务
对于 tasks 中的每个 task:
    taskChannel.发送(task)

// 扇入：收集结果
results = []
重复 tasks.数量 次:
    result = resultChannel.接收()
    results.添加(result)

TypeScript 风格的 Channel 抽象
interface Channel<T> {
  send(value: T): Promise<void>;
  receive(): Promise<T>;
  close(): void;
}

function createBufferedChannel<T>(capacity: number): Channel<T> {
  const buffer: T[] = [];
  const senders: Array<{ value: T; resolve: () => void }> = [];
  const receivers: Array<(value: T) => void> = [];

  return {
    async send(value: T) {
      if (receivers.length > 0) {
        const recv = receivers.shift()!;
        recv(value);
      } else if (buffer.length < capacity) {
        buffer.push(value);
      } else {
        return new Promise<void>((resolve) => {
          senders.push({ value, resolve });
        });
      }
    },
    async receive(): Promise<T> {
      if (buffer.length > 0) {
        const value = buffer.shift()!;
        if (senders.length > 0) {
          const s = senders.shift()!;
          buffer.push(s.value);
          s.resolve();
        }
        return value;
      }
      return new Promise<T>((resolve) => {
        receivers.push(resolve);
      });
    },
    close() {
      senders.length = 0;
      receivers.length = 0;
    },
  };
}


小结
消息传递是并发编程中一种安全且优雅的通信范式：


    

  • 核心思想：并发实体之间不共享内存，通过发送和接收消息交换数据
    • 

  • 同步 vs 异步：同步消息传递保证送达但会阻塞发送者；异步消息传递不阻塞但需要缓冲
    • 

  • CSP 模型：以 Channel 为中心，进程通过 Channel 通信，适合单进程内的并发协调
    • 

  • Actor 模型：以 Actor 为中心，通过地址直接发送消息到 Mailbox，天然支持分布式
    • 

  • 常见模式：点对点、发布-订阅、请求-响应、扇出-扇入等
    • 

  • 相比共享内存，消息传递天然避免竞态条件，更易于理解、调试和扩展到分布式环境
    •
