Linux 内核架构概览

内核的角色

Linux 内核是操作系统的核心，运行在 CPU 的最高特权级（Ring 0），直接管理硬件资源并为用户空间程序提供服务。



宏内核 vs 微内核




维度
宏内核（Monolithic）
微内核（Microkernel）





代表
Linux, FreeBSD
Minix, L4, QNX




内核空间
所有核心功能运行在内核态
仅基本功能在内核态，其余在用户态




性能
函数调用，无上下文切换开销
需要 IPC，有上下文切换开销




稳定性
一个模块崩溃可能导致整个内核崩溃
服务隔离，故障影响范围小




代码量
大（Linux 6.x 约 3000 万行）
小





Linux 选择宏内核是为了性能，但通过**可加载内核模块（LKM）**机制获得了微内核的部分灵活性。

可加载内核模块（LKM）
LKM 允许在运行时动态加载和卸载内核功能，无需重新编译或重启内核。


# 查看已加载模块
lsmod

# 加载模块
modprobe ext4

# 卸载模块
modprobe -r ext4

# 查看模块信息
modinfo ext4




命令
功能





lsmod
列出已加载模块




modprobe
智能加载模块（处理依赖）




insmod
直接加载模块（不处理依赖）




rmmod
卸载模块




modinfo
查看模块元信息

/proc 和 /sys 文件系统
Linux 通过伪文件系统向用户空间暴露内核信息。






文件系统
说明
示例





/proc
进程信息和内核参数
/proc/cpuinfo, /proc/meminfo




/sys
设备和驱动信息（结构化）
/sys/class/net/, /sys/block/




/dev
设备文件
/dev/sda, /dev/null





# 查看 CPU 信息
cat /proc/cpuinfo

# 查看内存使用
cat /proc/meminfo

# 查看特定进程信息
ls /proc/$$

# 查看内核版本
cat /proc/version


内核编译
# 获取内核源码
git clone https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git

# 配置内核
make menuconfig

# 编译
make -j$(nproc)

# 安装模块和内核
make modules_install
make install

小结
    

  • Linux 采用宏内核架构，所有核心子系统运行在内核态
    • 

  • 可加载内核模块提供了运行时动态扩展的能力
    • 

  • 系统调用是用户空间与内核之间的唯一接口，通过 syscall 指令触发
    • 

  • /proc 和 /sys 伪文件系统向用户空间暴露内核状态信息
    • 

  • 理解内核架构有助于系统级性能调优和故障排查
