系统监控与性能调优

性能分析方法论

在进行性能调优之前，首先需要确定瓶颈在哪里。系统性能的四大资源维度：

资源 关键指标 工具
CPU 使用率、负载、上下文切换 top, mpstat, perf
内存 使用率、缓存命中率、Swap free, vmstat, /proc/meminfo
磁盘 I/O IOPS、吞吐量、延迟 iostat, iotop, blktrace
网络 带宽、延迟、丢包率 sar, iftop, ss 


CPU 监控
top / htop
# top 基本用法
top

# 按 CPU 排序
top -o %CPU

# htop（增强版 top）
htop

字段
说明





us（user）
用户态 CPU 时间

内核态 CPU 时间




ni（nice）

空闲 CPU 时间




wa（iowait）
等待 I/O 的 CPU 时间




si/hi
软中断/硬中断 CPU 时间





负载（Load Average）
uptime
# 08:00:00 up 30 days, load average: 2.50, 1.80, 1.20
#                                     1min  5min  15min




负载值
含义（单核 CPU）





< 1.0
CPU 空闲




= 1.0
CPU 刚好满载




> 1.0
有任务在排队等待





多核系统中，负载值需要除以 CPU 核数来判断。

free -h

vmstat 1 5

perf — 性能剖析
perf 是 Linux 内核自带的性能分析工具，可以采样 CPU 执行热点。


# 实时查看 CPU 热点函数
perf top

# 对进程采样
perf record -g -p <PID> -- sleep 30

# 查看报告
perf report

# 统计系统调用
perf stat -e syscalls:sys_enter_* -p <PID> -- sleep 10
火焰图（Flame Graph）
火焰图是 perf 数据的可视化形式，直观展示函数调用栈和 CPU 时间分布。


# 生成火焰图
perf record -g -p <PID> -- sleep 30
perf script > perf.unfold
stackcollapse-perf.pl perf.unfold > perf.folded
flamegraph.pl perf.folded > flamegraph.svg


strace — 系统调用追踪
strace 跟踪进程的系统调用和信号。


# 追踪进程的系统调用
strace -p <PID>

# 追踪命令的系统调用
strace ls -l /tmp

# 统计系统调用耗时
strace -c -p <PID>

# 只追踪文件相关调用
strace -e trace=file ls




选项
说明





-p PID
附加到运行中的进程




-c
统计模式




-e trace=X
过滤特定类型（file/network/memory）




-f
跟踪子进程




-T
显示每个调用的耗时







sysctl — 内核参数调优
sysctl 用于查看和修改内核运行时参数。


# 查看所有参数
sysctl -a

# 查看特定参数
sysctl vm.swappiness

# 临时修改
sysctl -w vm.swappiness=10

# 永久修改（写入配置文件）
echo "vm.swappiness=10" >> /etc/sysctl.conf
sysctl -p
常用调优参数




参数
默认值
说明





vm.swappiness
60

vm.dirty_ratio

net.ipv4.tcp_max_syn_backlog
1024
SYN 队列最大长度




fs.file-max
系统级
系统最大打开文件数




net.ipv4.ip_local_port_range
32768-60999
可用临时端口范围

小结
    

  • 性能调优首先要定位瓶颈所在：CPU、内存、磁盘 I/O 还是网络
    • 

  • top/htop 提供系统级实时监控，vmstat/iostat 提供详细统计
    • 

  • perf 是 CPU 性能剖析的标准工具，配合火焰图可视化调用栈
    • 

  • strace 追踪系统调用，是诊断程序行为异常的利器
    • 

  • sysctl 调整内核参数，根据工作负载特征优化系统配置
    •
