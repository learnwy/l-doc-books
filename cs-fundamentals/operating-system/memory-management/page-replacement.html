Part III · 系统 (Systems)操作系统 简介内存管理 简介页面置换算法

页面置换算法

为什么需要页面置换

物理内存是有限的。当所有物理页帧都被占满时，操作系统必须选择一个页面换出（Swap Out）到磁盘，为新页面腾出空间。选择哪个页面换出，直接影响系统的缺页率和整体性能。



OPT（最优置换算法）
OPT 算法替换未来最长时间不会被访问的页面。它是理论最优算法，用作其他算法的性能基准。






特性
说明





策略
替换未来最久不被使用的页面




最优性
缺页率最低（可证明）




可实现性
不可实现（需要预知未来）




用途
作为对比基准







FIFO（先进先出）
FIFO 替换最早进入内存的页面。

Belady 异常
FIFO 存在一个反直觉的现象：增加物理帧数反而可能导致缺页率上升。






帧数
访问序列 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5

OPT 和 LRU 不会出现 Belady 异常，因为它们属于栈算法。




LRU（最近最少使用）
LRU 替换最长时间未被访问的页面，基于局部性原理：最近使用过的页面很可能再次被使用。

精确 LRU 的开销太大，实际操作系统使用近似 LRU 算法。




Clock 算法（时钟算法）
Clock 算法是 LRU 的高效近似，也称为 NRU（Not Recently Used）或二次机会算法。


工作原理
将所有页帧组织为环形链表，每个页面有一个 访问位（Reference Bit）。






步骤
操作





1
指针指向当前页面




2
若 R=0，替换该页面




3
若 R=1，将 R 置为 0，指针前移




4
重复直到找到 R=0 的页面

LFU 替换访问频率最低的页面。

工作集模型
工作集（Working Set）是进程在一段时间窗口内访问的页面集合。如果物理内存能容纳进程的工作集，缺页率会很低；否则会发生抖动（Thrashing）。






概念
说明





工作集 W(t, Δ)
时刻 t 前 Δ 时间内访问的页面集合




驻留集
进程当前在物理内存中的页面集合




抖动
驻留集 < 工作集，频繁缺页，CPU 利用率骤降

说明





Active/Inactive 链表

kswapd
后台内核线程，在空闲时回收页面




直接回收
内存极度不足时，在分配路径上同步回收

最后手段，杀死占内存最多的进程

小结
    

  • OPT 是理论最优但不可实现，用作其他算法的性能基准
    • 

  • FIFO 实现简单但存在 Belady 异常，实际很少使用
    • 

  • LRU 基于时间局部性，性能接近 OPT，但精确实现开销大
    • 

  • Clock 算法是 LRU 的高效近似，通过访问位和环形链表实现
    • 

  • 工作集概念解释了抖动现象，驻留集必须覆盖工作集才能避免频繁缺页
    • 

  • Linux 使用 Active/Inactive 双链表 + kswapd 后台回收的混合策略
