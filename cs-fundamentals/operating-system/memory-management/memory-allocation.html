内存分配与回收

内存分配的两个层面

操作系统的内存分配发生在两个层面：内核空间和用户空间。内核需要为自身数据结构分配内存，用户进程则通过 malloc 等接口申请堆内存。



伙伴系统（Buddy System）
伙伴系统是 Linux 内核管理物理页面的核心算法，负责分配和回收连续的物理页帧。


工作原理
将所有空闲物理页面按 2 的幂次组织为不同阶（order）的空闲链表。

伙伴系统的缺陷是内部碎片：申请 3 个页面需要分配 4 个（order=2），浪费 1 个页面。




Slab 分配器
内核频繁创建和销毁固定大小的小对象（如 task_struct、inode）。如果每次都向伙伴系统申请整页，效率和空间浪费都很严重。Slab 分配器在伙伴系统之上提供细粒度的对象级内存分配。

SLUB 分配器
Linux 从 2.6.22 起默认使用 SLUB 替代 SLAB。SLUB 简化了元数据管理，去掉了空闲链表，直接使用对象头部的指针串联空闲对象。

用户态内存分配：malloc
用户进程通过 malloc/free 管理堆内存。glibc 的 malloc 实现（ptmalloc2）在内部向内核申请大块内存，再细分给应用。

外部碎片

内存紧凑（Compaction）





Linux 内核通过 内存紧凑（Memory Compaction） 移动可迁移的页面来生成连续的大块物理内存。




小结
    

  • 伙伴系统以 2 的幂次为单位管理物理页面，通过分裂和合并减少外部碎片
    • 

  • Slab/SLUB 在伙伴系统之上为内核对象提供高效的小对象分配
    • 

  • 用户态 malloc 通过 brk 和 mmap 向内核申请内存，再通过 Bin 机制细分管理
    • 

  • jemalloc/tcmalloc 等替代分配器在高并发场景下性能优于 ptmalloc2
    • 

  • 内部碎片和外部碎片是内存分配的两大问题，需要不同策略应对
