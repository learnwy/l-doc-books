分布式文件系统

为什么需要分布式文件系统

当数据量超出单机存储容量，或需要高可用性和高吞吐量时，单机文件系统无法满足需求。分布式文件系统将数据分散存储在多台机器上，对外提供统一的文件访问接口。

需求 单机文件系统 分布式文件系统
存储容量 受限于单机磁盘 可线性扩展
吞吐量 单机 I/O 带宽上限 多节点并行 I/O
可用性 单点故障 数据多副本或纠删码
一致性 本地保证 需要分布式一致性协议

小结
    

  • HDFS 适合大文件顺序读写的批处理场景，但小文件和随机访问是短板
    • 

  • Ceph 通过 CRUSH 算法实现无中心数据放置，统一提供对象/块/文件三种接口
    • 

  • GlusterFS 采用完全去中心化架构，适合文件共享和归档
    • 

  • 分布式文件系统需要在一致性、可用性和分区容错性之间做出权衡（CAP 定理）
    • 

  • 副本和纠删码是两种主要的数据冗余策略，在可靠性和空间效率间取舍
