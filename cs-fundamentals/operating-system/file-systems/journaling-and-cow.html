日志文件系统与 CoW

为什么需要一致性保障

文件系统操作（如创建文件）涉及多个磁盘写入（分配 inode、更新目录、写入数据块）。如果在这些操作中途发生断电或崩溃，磁盘上的数据可能处于不一致状态。



一致性检查：fsck
早期文件系统在崩溃后依赖 fsck（File System Check）扫描整个磁盘来修复不一致。






特点
说明





工作方式
逐一检查 inode、块位图、目录等




时间开销
与磁盘容量成正比（TB 级磁盘需要数小时）




可靠性
可能丢失部分数据





现代文件系统通过日志（Journaling）或写时复制（CoW）替代全盘扫描。




日志文件系统（Journaling）
日志文件系统在执行实际操作之前，先将操作记录写入一个专用的日志区域。如果崩溃，系统可以重放日志恢复一致性。

写时复制（Copy-on-Write）
CoW 是一种完全不同的一致性策略：永远不覆盖已有数据，修改时将新数据写入新位置。


工作原理
修改数据块 B 时：


    

  1. 将新数据写入新位置（B'）
    2. 

  2. 创建新的中间节点指向 B'（未修改的 A 继续引用）
    3. 

  3. 创建新的根节点指向新中间节点
    4. 

  4. 原子更新超级块指向新根节点
    5.

快照（Snapshot）
CoW 文件系统天然支持快照。创建快照时只需保存当前的根节点引用，后续修改会写入新位置，快照仍指向原始数据。


# Btrfs 创建快照
btrfs subvolume snapshot /data /data/snapshot-2024

# Btrfs 创建只读快照
btrfs subvolume snapshot -r /data /data/snapshot-readonly

小结
    

  • fsck 全盘扫描恢复一致性，耗时长，已被现代机制取代
    • 

  • 日志文件系统通过预写日志保障崩溃一致性，ext4 默认使用 ordered 模式
    • 

  • 写时复制永不覆盖原数据，通过原子更新根指针实现一致性
    • 

  • CoW 天然支持零开销快照，但会带来碎片化和写放大问题
    • 

  • Btrfs 和 ZFS 是典型的 CoW 文件系统，提供校验和、快照和自修复等高级特性
    • 

  • 日志模式适合随机写入密集场景，CoW 适合需要快照和数据完整性的场景
    •
