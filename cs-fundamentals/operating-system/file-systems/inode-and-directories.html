inode 与目录管理

inode 概述

在 Unix/Linux 文件系统中，inode（索引节点）是描述文件元数据的核心数据结构。每个文件和目录都对应一个唯一的 inode，它存储了文件的所有属性信息，但不包含文件名。

inode 耗尽问题
inode 的数量在文件系统创建时确定（ext4）。即使磁盘空间充足，inode 耗尽也会导致无法创建新文件。


df -i
# 查看 inode 使用情况




解决方案
说明





创建时指定更多 inode
mkfs.ext4 -N 参数




使用动态 inode 的文件系统
XFS、Btrfs 按需分配 inode




清理小文件
大量小文件是 inode 耗尽的常见原因







小结
    

  • inode 存储文件的所有元数据和数据块指针，文件名存在目录中
    • 

  • ext4 使用 Extent 树替代间接块映射，提高大文件寻址效率
    • 

  • 目录是文件名到 inode 的映射表，ext4 使用 HTree 加速查找
    • 

  • 硬链接共享 inode，不能跨文件系统；软链接是独立文件，存储目标路径
    • 

  • dentry 缓存避免重复的路径解析开销
    • 

  • inode 数量有限，大量小文件场景需要关注 inode 耗尽问题
