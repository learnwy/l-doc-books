CPU 调度策略

调度的基本概念

CPU 调度器决定哪个就绪进程获得 CPU 执行权。调度算法在多个互相矛盾的目标之间做出权衡。

调度目标 说明 偏向场景
CPU 利用率 保持 CPU 忙碌 批处理系统
吞吐量 单位时间完成的进程数 服务器
周转时间 提交到完成的总时间 批处理
等待时间 在就绪队列中的等待时间 通用
响应时间 提交到首次响应的时间 交互式系统

多级反馈队列（MLFQ）
MLFQ 综合了多种调度策略，是实际操作系统中最常用的调度框架。






规则
说明





规则 1
优先级高的队列先调度




规则 2
同一队列内使用 Round Robin




规则 3
新进程进入最高优先级队列




规则 4
用完时间片的进程降级到下一队列




规则 5
定期将所有进程提升到最高优先级（防饥饿）







Linux CFS（完全公平调度器）
CFS 是 Linux 内核从 2.6.23 起使用的默认进程调度器。


核心思想
CFS 不使用固定时间片，而是跟踪每个进程的 vruntime（虚拟运行时间），始终选择 vruntime 最小的进程运行。






概念
说明





vruntime
加权后的虚拟运行时间




nice 值
-20~19，影响 vruntime 增长速度




红黑树
按 vruntime 排序的就绪队列




调度延迟
所有就绪进程都运行一轮的最小时间

小结
    

  • FCFS 最简单但有护航效应，SJF 平均等待时间最优但可能饥饿
    • 

  • Round Robin 通过时间片实现公平，时间片大小是关键参数
    • 

  • MLFQ 综合多种策略，是通用操作系统最常用的调度框架
    • 

  • Linux CFS 基于 vruntime 和红黑树实现公平调度，nice 值影响权重
    • 

  • 实时调度分硬实时和软实时，Linux 提供 SCHED_FIFO/RR/DEADLINE 策略
    • 

  • 没有"最好的"调度算法，只有最适合特定工作负载的算法
