线程模型与并发

为什么需要线程

进程是"重量级"的并发单元——创建、切换和通信的开销都很高。线程（Thread）在进程内部提供了更轻量级的并发执行路径，同一进程内的多个线程共享地址空间和系统资源。

对比维度 进程 线程
地址空间 独立 共享（同一进程）
创建开销 高（需复制页表等） 低（共享大部分资源）
切换开销 高（TLB 刷新） 低（无需切换页表）
通信方式 IPC（管道、共享内存等） 直接读写共享内存
隔离性 强（一个崩溃不影响另一个） 弱（一个崩溃可能影响整个进程）
资源管理 每个进程独立管理 共享文件描述符、堆等

内核线程 vs 用户线程
内核线程（Kernel Thread）
由操作系统内核管理和调度，每个线程在内核中有对应的调度实体。






优势
劣势





一个线程阻塞不影响其他线程
创建和切换开销相对较高




可利用多核 CPU
线程数受内核限制




调度由内核负责
系统调用开销





用户线程（User Thread）
完全在用户空间实现，内核不感知线程的存在。






优势
劣势





创建和切换极快
一个线程阻塞导致整个进程阻塞




无需内核介入
无法利用多核




可自定义调度策略
I/O 阻塞是致命问题





线程模型映射




模型
映射关系
代表实现





1:1
每个用户线程对应一个内核线程
Linux NPTL, Windows




N:1
所有用户线程映射到一个内核线程
早期 Green Threads




M:N
M 个用户线程映射到 N 个内核线程
Go goroutine, Erlang

线程安全问题
多线程共享数据时可能出现竞态条件（Race Condition）。






问题
描述
解决方案





竞态条件
多线程同时读写共享数据
互斥锁、原子操作




死锁
两个线程互相等待对方释放锁
按固定顺序加锁、超时机制




活锁
线程不断重试但无法推进
随机退避




优先级反转
高优先级线程被低优先级阻塞
优先级继承协议







小结
    

  • 线程是进程内的轻量级执行单元，共享地址空间但拥有私有栈和寄存器
    • 

  • 1:1 模型是 Linux 的主流实现，每个用户线程对应一个内核线程
    • 

  • M:N 模型（如 Go goroutine）结合了用户线程和内核线程的优势
    • 

  • POSIX pthread 是 Unix/Linux 的标准线程 API
    • 

  • 绿色线程/协程的创建和切换开销远低于内核线程，适合高并发场景
    • 

  • 多线程编程需要关注竞态条件、死锁和优先级反转等同步问题
    •
