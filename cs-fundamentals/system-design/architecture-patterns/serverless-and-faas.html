Serverless 与 FaaS

Serverless 的理念

Serverless（无服务器）并不意味着没有服务器，而是开发者不再需要管理服务器。基础设施的供给、扩展、维护完全由云平台负责——开发者只需编写和部署业务逻辑代码。

FaaS：函数即服务
FaaS（Function as a Service）是 Serverless 的核心计算模型。每个函数是一个独立的执行单元，处理单个事件：


Lambda 函数示例
interface APIGatewayEvent {
  httpMethod: string;
  path: string;
  pathParameters: Record<string, string> | null;
  queryStringParameters: Record<string, string> | null;
  body: string | null;
  headers: Record<string, string>;
}

interface LambdaResponse {
  statusCode: number;
  headers: Record<string, string>;
  body: string;
}

interface Context {
  functionName: string;
  memoryLimitInMB: number;
  getRemainingTimeInMillis(): number;
}

const handler = async (event: APIGatewayEvent, context: Context): Promise<LambdaResponse> => {
  const { httpMethod, pathParameters } = event;

  try {
    switch (httpMethod) {
      case 'GET': {
        const userId = pathParameters?.id;
        if (!userId) {
          return response(400, { error: 'Missing user ID' });
        }
        const user = await getUser(userId);
        return response(200, user);
      }
      case 'POST': {
        const body = JSON.parse(event.body ?? '{}');
        const user = await createUser(body);
        return response(201, user);
      }
      default:
        return response(405, { error: 'Method not allowed' });
    }
  } catch (error) {
    console.error('Lambda error:', error);
    return response(500, { error: 'Internal server error' });
  }
};

function response(statusCode: number, body: unknown): LambdaResponse {
  return {
    statusCode,
    headers: {
      'Content-Type': 'application/json',
      'Access-Control-Allow-Origin': '*',
    },
    body: JSON.stringify(body),
  };
}

async function getUser(id: string): Promise<Record<string, unknown>> {
  return { id, name: 'example' };
}

async function createUser(data: Record<string, unknown>): Promise<Record<string, unknown>> {
  return { id: 'new-id', ...data };
}

export { handler };

选型决策


小结
    

  • Serverless 将基础设施管理完全交给云平台，开发者专注于业务逻辑。
    • 

  • FaaS 是 Serverless 的核心计算模型，函数由事件触发、按需执行。
    • 

  • 冷启动是主要的性能挑战，可通过预热、减小包大小等策略优化。
    • 

  • Serverless 适合事件驱动、流量不稳定、短时执行的场景。
    • 

  • 对于长时间运行、高稳定流量的服务，容器/K8s 通常更经济。
