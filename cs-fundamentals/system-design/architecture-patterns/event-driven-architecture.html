事件驱动架构

从请求驱动到事件驱动

传统的请求-响应架构中，服务之间通过同步调用协作——服务 A 直接调用服务 B，等待响应后继续处理。事件驱动架构（Event-Driven Architecture, EDA）颠覆了这种模式：服务通过发布事件来通知状态变化，其他服务通过订阅事件来做出响应。

事件溯源（Event Sourcing）
传统方式存储的是数据的当前状态，而事件溯源存储的是导致状态变化的所有事件。当前状态通过回放事件来计算。


interface CartEvent {
  eventId: string;
  cartId: string;
  type: 'CartCreated' | 'ItemAdded' | 'ItemRemoved' | 'CartCheckedOut';
  data: Record<string, unknown>;
  timestamp: number;
}

interface CartState {
  id: string;
  items: Map<string, number>;
  status: 'active' | 'checked_out';
}

function rebuildCart(events: CartEvent[]): CartState {
  const state: CartState = {
    id: '',
    items: new Map(),
    status: 'active',
  };

  for (const event of events) {
    switch (event.type) {
      case 'CartCreated':
        state.id = event.cartId;
        break;
      case 'ItemAdded':
        const addItem = event.data as { productId: string; quantity: number };
        const existing = state.items.get(addItem.productId) ?? 0;
        state.items.set(addItem.productId, existing + addItem.quantity);
        break;
      case 'ItemRemoved':
        const removeItem = event.data as { productId: string };
        state.items.delete(removeItem.productId);
        break;
      case 'CartCheckedOut':
        state.status = 'checked_out';
        break;
    }
  }

  return state;
}

CQRS（命令查询职责分离）
CQRS 将系统的读操作和写操作使用不同的模型和存储来处理：


interface Command {
  type: string;
  payload: unknown;
}

interface Query {
  type: string;
  params: Record<string, unknown>;
}

class OrderCommandHandler {
  constructor(private eventStore: EventStore) {}

  async handle(command: Command): Promise<void> {
    switch (command.type) {
      case 'CreateOrder': {
        const event = {
          type: 'OrderCreated',
          data: command.payload,
          timestamp: Date.now(),
        };
        await this.eventStore.append('orders', event);
        break;
      }
    }
  }
}

class OrderQueryHandler {
  constructor(private readDb: ReadDatabase) {}

  async handle(query: Query): Promise<unknown> {
    switch (query.type) {
      case 'GetOrderById':
        return this.readDb.findById('orders', query.params.id as string);
      case 'GetUserOrders':
        return this.readDb.findByField('orders', 'userId', query.params.userId as string);
    }
  }
}

interface EventStore {
  append(stream: string, event: Record<string, unknown>): Promise<void>;
}

interface ReadDatabase {
  findById(collection: string, id: string): Promise<unknown>;
  findByField(collection: string, field: string, value: string): Promise<unknown>;
}
CQRS 的典型应用场景：读写比例极度不平衡（如电商商品页读写比 1000:1）、读写模型差异大（写入是事件，读取需要聚合视图）。

小结
    

  • 事件驱动架构通过事件实现服务间的松耦合异步协作。
    • 

  • 事件溯源存储所有状态变化事件，当前状态通过回放事件计算。
    • 

  • CQRS 将读写模型分离，分别优化读和写的性能。
    • 

  • Saga 模式通过补偿操作解决微服务中的分布式事务问题。
    • 

  • 事件驱动架构增加了系统的复杂度——只在真正需要解耦和异步的场景中使用。
