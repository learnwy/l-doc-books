关系型数据库

核心特性：ACID

关系型数据库（RDBMS）是大多数系统的主数据存储。其核心竞争力在于 ACID 事务保证——在并发和故障场景下确保数据的正确性。

MySQL InnoDB 默认使用 REPEATABLE READ，PostgreSQL 默认使用 READ COMMITTED。大多数系统在 READ COMMITTED 即可满足业务需求，更高的隔离级别带来的性能损失通常不值得。




索引原理
索引是数据库性能的关键。没有索引的查询需要全表扫描，索引将查找时间从 O(n) 降低到 O(log n)。


B+ 树索引
B+ 树是关系型数据库最常用的索引结构：


    

  • 所有数据存储在叶子节点
    • 

  • 叶子节点通过链表连接，支持范围查询
    • 

  • 树高通常为 3-4 层，千万级数据只需 3-4 次磁盘 IO
    •

索引优化原则
-- 复合索引遵循最左前缀原则
CREATE INDEX idx_user_status_created
ON orders (user_id, status, created_at);

-- 以下查询可以使用索引
SELECT * FROM orders WHERE user_id = 123;
SELECT * FROM orders WHERE user_id = 123 AND status = 'active';
SELECT * FROM orders WHERE user_id = 123 AND status = 'active' AND created_at > '2026-01-01';

-- 以下查询无法使用该索引（跳过了 user_id）
SELECT * FROM orders WHERE status = 'active';


读写分离
当读请求远多于写请求时（典型的 Web 应用读写比为 10:1 甚至 100:1），可以通过主从复制实现读写分离：


interface DatabasePool {
  primary: Connection;
  replicas: Connection[];
}

class ReadWriteSplitter {
  private pool: DatabasePool;
  private replicaIndex = 0;

  constructor(pool: DatabasePool) {
    this.pool = pool;
  }

  getWriteConnection(): Connection {
    return this.pool.primary;
  }

  getReadConnection(): Connection {
    const replica = this.pool.replicas[this.replicaIndex];
    this.replicaIndex = (this.replicaIndex + 1) % this.pool.replicas.length;
    return replica;
  }

  getStrongReadConnection(): Connection {
    return this.pool.primary;
  }
}

interface Connection {
  query(sql: string, params?: unknown[]): Promise<unknown>;
}
注意：异步复制存在复制延迟（通常毫秒到秒级）。对于"写后立即读"的场景（如用户修改资料后刷新页面），需要从主库读取以保证一致性。

数据库选型指南


小结
    

  • ACID 是关系型数据库的核心价值，事务隔离级别需要根据业务需求选择。
    • 

  • B+ 树索引是性能优化的关键，遵循最左前缀原则和覆盖索引策略。
    • 

  • 读写分离适合读多写少的场景，但要注意复制延迟导致的一致性问题。
    • 

  • 分库分表突破单机瓶颈，但引入了跨分片查询、分布式事务等复杂性。
    • 

  • 关系型数据库适合需要强一致性和复杂查询的核心业务数据。
    •
