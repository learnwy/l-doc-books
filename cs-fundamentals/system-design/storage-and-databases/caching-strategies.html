缓存策略

缓存的本质

缓存是用更快的存储介质来保存热点数据的副本，以减少对慢速后端存储的访问。在系统设计中，缓存是最常用也最有效的性能优化手段——一次 Redis 读取约 0.5ms，而一次 MySQL 查询可能需要 5-50ms。

核心缓存模式
Cache-Aside（旁路缓存）
最常用的缓存模式。应用层同时管理缓存和数据库：


class CacheAsideRepository {
  constructor(
    private cache: RedisClient,
    private db: DatabaseClient,
  ) {}

  async getUser(userId: string): Promise<User | null> {
    const cacheKey = `user:${userId}`;
    const cached = await this.cache.get(cacheKey);

    if (cached) {
      return JSON.parse(cached) as User;
    }

    const user = await this.db.query<User>('SELECT * FROM users WHERE id = $1', [userId]);

    if (user) {
      await this.cache.set(cacheKey, JSON.stringify(user), 'EX', 300);
    }

    return user;
  }

  async updateUser(userId: string, data: Partial<User>): Promise<void> {
    await this.db.query('UPDATE users SET name = $1 WHERE id = $2', [data.name, userId]);
    await this.cache.del(`user:${userId}`);
  }
}

interface RedisClient {
  get(key: string): Promise<string | null>;
  set(key: string, value: string, mode: string, duration: number): Promise<void>;
  del(key: string): Promise<void>;
}

interface DatabaseClient {
  query<T>(sql: string, params: unknown[]): Promise<T | null>;
}

interface User {
  id: string;
  name: string;
  email: string;
}

缓存淘汰策略
当缓存空间不足时，需要选择淘汰哪些数据：


class LRUCache<K, V> {
  private capacity: number;
  private cache: Map<K, V>;

  constructor(capacity: number) {
    this.capacity = capacity;
    this.cache = new Map();
  }

  get(key: K): V | undefined {
    if (!this.cache.has(key)) return undefined;

    const value = this.cache.get(key)!;
    this.cache.delete(key);
    this.cache.set(key, value);
    return value;
  }

  put(key: K, value: V): void {
    if (this.cache.has(key)) {
      this.cache.delete(key);
    } else if (this.cache.size >= this.capacity) {
      const firstKey = this.cache.keys().next().value!;
      this.cache.delete(firstKey);
    }
    this.cache.set(key, value);
  }
}

缓存常见问题
缓存穿透
查询一个不存在的数据，缓存永远不会命中，请求全部打到数据库：


解决方案：布隆过滤器预判 + 缓存空值


class CachePenetrationGuard {
  private bloomFilter: BloomFilter;
  private cache: RedisClient;
  private db: DatabaseClient;

  constructor(bloomFilter: BloomFilter, cache: RedisClient, db: DatabaseClient) {
    this.bloomFilter = bloomFilter;
    this.cache = cache;
    this.db = db;
  }

  async get(key: string): Promise<string | null> {
    if (!this.bloomFilter.mightContain(key)) {
      return null;
    }

    const cached = await this.cache.get(key);
    if (cached === 'NULL_PLACEHOLDER') return null;
    if (cached) return cached;

    const data = await this.db.query<string>('SELECT * FROM data WHERE key = $1', [key]);
    if (data) {
      await this.cache.set(key, data, 'EX', 300);
    } else {
      await this.cache.set(key, 'NULL_PLACEHOLDER', 'EX', 60);
    }

    return data;
  }
}

interface BloomFilter {
  mightContain(key: string): boolean;
}
缓存雪崩
大量缓存同时过期，请求瞬间涌向数据库：


解决方案：TTL 加随机抖动


function setWithJitter(cache: RedisClient, key: string, value: string, baseTTL: number): Promise<void> {
  const jitter = Math.floor(Math.random() * baseTTL * 0.2);
  const ttl = baseTTL + jitter;
  return cache.set(key, value, 'EX', ttl);
}
缓存击穿
热点 key 过期瞬间，大量并发请求同时查询数据库：


解决方案：互斥锁（Mutex Lock）


async function getWithMutex(cache: RedisClient, db: DatabaseClient, key: string): Promise<string | null> {
  const cached = await cache.get(key);
  if (cached) return cached;

  const lockKey = `lock:${key}`;
  const acquired = await cache.set(lockKey, '1', 'NX', 10);

  if (acquired) {
    try {
      const data = await db.query<string>('SELECT * FROM data WHERE key = $1', [key]);
      if (data) {
        await cache.set(key, data, 'EX', 300);
      }
      return data;
    } finally {
      await cache.del(lockKey);
    }
  }

  await new Promise((r) => setTimeout(r, 100));
  return getWithMutex(cache, db, key);
}


小结
    

  • Cache-Aside 是最通用的缓存模式，适合绝大多数读多写少的场景。
    • 

  • 缓存淘汰策略中 LRU 是最常用的选择。
    • 

  • 缓存穿透、雪崩、击穿是三个经典问题，各有对应的解决方案。
    • 

  • 缓存不是银弹——引入缓存意味着引入一致性问题，需要根据业务容忍度做权衡。
