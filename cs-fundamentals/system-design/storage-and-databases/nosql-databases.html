NoSQL 数据库

为什么需要 NoSQL

关系型数据库在处理结构化数据和复杂查询方面表现优异，但在某些场景下会遇到瓶颈：海量数据的水平扩展困难、固定 Schema 不适应快速变化的数据模型、高并发写入性能受限。NoSQL（Not Only SQL）数据库针对这些痛点提供了多种解决方案。



键值存储
键值存储是最简单的 NoSQL 模型：通过唯一的 key 来存取 value。它的优势在于极高的读写性能和简单的扩展模型。


interface KVStore {
  get(key: string): Promise<string | null>;
  set(key: string, value: string, ttl?: number): Promise<void>;
  delete(key: string): Promise<void>;
  increment(key: string): Promise<number>;
}

const SESSION_STORE_EXAMPLE = {
  key: 'session:user:abc123',
  value: JSON.stringify({
    userId: 'abc123',
    role: 'admin',
    loginAt: '2026-03-30T10:00:00Z',
    expiresAt: '2026-03-30T22:00:00Z',
  }),
  ttl: 43200,
};

const RATE_LIMIT_EXAMPLE = {
  key: 'ratelimit:ip:192.168.1.1:minute',
  operation: 'INCR + EXPIRE 60',
  threshold: 100,
};

文档数据库
文档数据库以 JSON-like 文档为存储单元，无需预定义 Schema。每个文档可以有不同的结构，非常适合快速迭代的应用开发。


interface Product {
  _id: string;
  name: string;
  category: string;
  price: number;
  attributes: Record<string, unknown>;
  reviews: Array<{
    userId: string;
    rating: number;
    comment: string;
    createdAt: Date;
  }>;
  tags: string[];
}

const electronicsProduct: Product = {

同一个集合中的两个产品有完全不同的 attributes 结构——这在关系型数据库中很难优雅地表达。


MongoDB 查询示例
const aggregationPipeline = [
  { $match: { category: 'electronics', price: { $gte: 1000 } } },
  { $unwind: '$reviews' },
  {
    $group: {
      _id: '$_id',
      name: { $first: '$name' },
      price: { $first: '$price' },
      avgRating: { $avg: '$reviews.rating' },
      reviewCount: { $sum: 1 },
    },
  },
  { $match: { avgRating: { $gte: 4.0 } } },
  { $sort: { avgRating: -1 } },
  { $limit: 10 },
];


列族数据库
列族数据库（Wide-Column Store）以行键和列族为组织方式，特别适合海量数据的高吞吐写入和时间序列查询。

图数据库
图数据库以节点（Node）和边（Edge）为核心模型，天然适合表达实体之间的复杂关系。


// Neo4j Cypher 查询：找到共同好友
MATCH (a:User {name: 'Alice'})-[:FOLLOWS]->(mutual)<-[:FOLLOWS]-(b:User {name: 'Bob'})
RETURN mutual.name

// 推荐可能认识的人（好友的好友，但不是自己的好友）
MATCH (me:User {name: 'Alice'})-[:FOLLOWS]->()-[:FOLLOWS]->(recommended)
WHERE NOT (me)-[:FOLLOWS]->(recommended) AND me <> recommended
RETURN recommended.name, COUNT(*) AS mutualFriends
ORDER BY mutualFriends DESC
LIMIT 10
关系型数据库处理这类多跳关系查询需要大量 JOIN 操作，性能随深度指数级下降。图数据库通过直接遍历边来完成查询，性能与数据总量无关，只与遍历的局部图大小有关。

小结
    

  • NoSQL 不是关系型数据库的替代品，而是互补方案。
    • 

  • 键值存储适合高性能缓存和简单 KV 操作。
    • 

  • 文档数据库适合 Schema 频繁变化的内容管理场景。
    • 

  • 列族数据库适合海量写入和时间序列数据。
    • 

  • 图数据库适合多跳关系查询和推荐系统。
    • 

  • 大型系统通常混合使用多种数据库（Polyglot Persistence）。
