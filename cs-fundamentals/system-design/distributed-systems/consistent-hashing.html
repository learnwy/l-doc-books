Part IV · 网络与分布式 (Networks & Distributed)系统设计 简介分布式系统 简介一致性哈希

一致性哈希

传统哈希的问题

在分布式缓存或数据库分片中，最直接的数据分布方式是取模哈希：server = hash(key) % N。但当节点数量 N 发生变化时（增加或移除节点），几乎所有的 key 都需要重新映射——这意味着大规模的数据迁移和缓存失效。

增加一个节点后，75% 的 key 需要迁移。在拥有数十亿 key 的系统中，这是不可接受的。




一致性哈希的原理
一致性哈希将哈希空间组织成一个环（0 到 2^32-1），节点和 key 都映射到环上的某个位置。每个 key 沿环顺时针方向找到的第一个节点，就是负责该 key 的节点。


当增加或移除一个节点时，只有该节点相邻的 key 需要重新映射，其他 key 不受影响。




基础实现
class ConsistentHash {
  private ring: Map<number, string> = new Map();
  private sortedKeys: number[] = [];
  private replicaCount: number;

  constructor(nodes: string[], replicaCount = 150) {
    this.replicaCount = replicaCount;
    for (const node of nodes) {
      this.addNode(node);
    }
  }

  addNode(node: string): void {
    for (let i = 0; i < this.replicaCount; i++) {
      const hash = this.hash(`${node}:${i}`);
      this.ring.set(hash, node);
      this.sortedKeys.push(hash);
    }
    this.sortedKeys.sort((a, b) => a - b);
  }

  removeNode(node: string): void {
    for (let i = 0; i < this.replicaCount; i++) {
      const hash = this.hash(`${node}:${i}`);
      this.ring.delete(hash);
      this.sortedKeys = this.sortedKeys.filter((k) => k !== hash);
    }
  }

  getNode(key: string): string {
    if (this.ring.size === 0) throw new Error('No nodes available');

    const hash = this.hash(key);
    let index = this.binarySearch(hash);

    if (index >= this.sortedKeys.length) {
      index = 0;
    }

    return this.ring.get(this.sortedKeys[index])!;
  }

  private binarySearch(target: number): number {
    let lo = 0;
    let hi = this.sortedKeys.length;

    while (lo < hi) {
      const mid = (lo + hi) >>> 1;
      if (this.sortedKeys[mid] < target) {
        lo = mid + 1;
      } else {
        hi = mid;
      }
    }

    return lo;
  }

  private hash(key: string): number {
    let hash = 0;
    for (let i = 0; i < key.length; i++) {
      hash = ((hash << 5) - hash + key.charCodeAt(i)) | 0;
    }
    return hash >>> 0;
  }
}


虚拟节点
如果每个物理节点只在环上有一个位置，数据分布可能极不均匀。虚拟节点（Virtual Node）通过为每个物理节点创建多个虚拟映射点来解决这个问题：

实际应用
分布式缓存（Memcached 客户端）
Amazon DynamoDB 的分区
DynamoDB 使用一致性哈希将数据分布到多个存储节点。每个分区键（Partition Key）经过哈希后映射到环上，由对应的节点负责存储。当负载增加时，DynamoDB 自动将热点分区拆分到新节点。


Cassandra 的 Token Ring
Cassandra 的数据分布也基于一致性哈希。每个节点负责环上的一段范围（Token Range），通过虚拟节点（vnodes）实现自动均衡。新节点加入时，它从相邻节点"借"一部分 Token Range，只需要迁移少量数据。




带复制的一致性哈希
在需要数据冗余的场景中，每个 key 不只存储在环上的第一个节点，而是存储在顺时针方向的前 N 个不同物理节点上：


class ReplicatedConsistentHash extends ConsistentHash {
  private replicationFactor: number;

  constructor(nodes: string[], replicationFactor = 3) {
    super(nodes);
    this.replicationFactor = replicationFactor;
  }

  getNodes(key: string): string[] {
    if (this.ring.size === 0) throw new Error('No nodes available');

    const nodes: string[] = [];
    const hash = this.hash(key);
    let index = this.binarySearch(hash);

    while (nodes.length < this.replicationFactor) {
      if (index >= this.sortedKeys.length) index = 0;

      const node = this.ring.get(this.sortedKeys[index])!;
      if (!nodes.includes(node)) {
        nodes.push(node);
      }
      index++;
    }

    return nodes;
  }

  private ring: Map<number, string> = new Map();
  private sortedKeys: number[] = [];

  protected hash(key: string): number {
    let h = 0;
    for (let i = 0; i < key.length; i++) {
      h = ((h << 5) - h + key.charCodeAt(i)) | 0;
    }
    return h >>> 0;
  }

  protected binarySearch(target: number): number {
    let lo = 0;
    let hi = this.sortedKeys.length;
    while (lo < hi) {
      const mid = (lo + hi) >>> 1;
      if (this.sortedKeys[mid] < target) lo = mid + 1;
      else hi = mid;
    }
    return lo;
  }
}


小结
    

  • 传统取模哈希在节点变更时导致大规模数据迁移，一致性哈希将影响范围降到最小。
    • 

  • 虚拟节点解决数据分布不均的问题，150-200 个虚拟节点是常用配置。
    • 

  • 一致性哈希被广泛应用于 DynamoDB、Cassandra、Memcached 等系统。
    • 

  • 结合复制机制，可以在一致性哈希的基础上实现高可用的数据存储。
