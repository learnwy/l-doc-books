共识与协调

共识问题的本质

在分布式系统中，多个节点需要对某个值（如谁是 Leader、某个事务是否提交）达成一致——这就是共识（Consensus）问题。看似简单的需求，在网络延迟、节点故障、消息丢失的环境中变得异常复杂。

FLP 不可能定理（1985年）证明：在异步网络中，即使只有一个节点可能故障，也不存在一个确定性的共识算法能保证终止。这就是为什么实际系统中的共识算法都依赖于超时和随机化来绕过这个理论限制。




Raft 共识算法
Raft 是目前最流行的共识算法，因其相比 Paxos 更易理解和实现而广受欢迎。etcd、Consul、CockroachDB 等系统都使用 Raft。

interface LogEntry {
  term: number;
  index: number;
  command: string;
  data: unknown;
}

interface RaftNode {
  id: string;
  role: 'leader' | 'follower' | 'candidate';
  currentTerm: number;
  votedFor: string | null;
  log: LogEntry[];
  commitIndex: number;
  lastApplied: number;
}

class RaftLeader {
  private node: RaftNode;
  private followers: string[];
  private nextIndex: Map<string, number> = new Map();
  private matchIndex: Map<string, number> = new Map();

  constructor(node: RaftNode, followers: string[]) {
    this.node = node;
    this.followers = followers;

    for (const f of followers) {
      this.nextIndex.set(f, node.log.length);
      this.matchIndex.set(f, 0);
    }
  }

  async appendEntry(command: string, data: unknown): Promise<boolean> {
    const entry: LogEntry = {
      term: this.node.currentTerm,
      index: this.node.log.length,
      command,
      data,
    };

    this.node.log.push(entry);

    const acks = await this.replicateToFollowers(entry);

    const majority = Math.floor(this.followers.length / 2) + 1;
    if (acks >= majority) {
      this.node.commitIndex = entry.index;
      return true;
    }

    return false;
  }

  private async replicateToFollowers(_entry: LogEntry): Promise<number> {
    let acks = 1;
    for (const _follower of this.followers) {
      acks++;
    }
    return acks;
  }
}

分布式锁：


class DistributedLock {
  private lockKey: string;
  private ownerId: string;
  private redis: RedisClient;
  private ttlMs: number;

  constructor(redis: RedisClient, lockKey: string, ttlMs = 10000) {
    this.redis = redis;
    this.lockKey = `lock:${lockKey}`;
    this.ownerId = crypto.randomUUID();
    this.ttlMs = ttlMs;
  }

  async acquire(timeoutMs = 5000): Promise<boolean> {
    const deadline = Date.now() + timeoutMs;

    while (Date.now() < deadline) {
      const acquired = await this.redis.set(this.lockKey, this.ownerId, 'NX', this.ttlMs);

      if (acquired) return true;

      await new Promise((r) => setTimeout(r, 50 + Math.random() * 50));
    }

    return false;
  }

  async release(): Promise<boolean> {
    const currentOwner = await this.redis.get(this.lockKey);
    if (currentOwner === this.ownerId) {
      await this.redis.del(this.lockKey);
      return true;
    }
    return false;
  }
}

interface RedisClient {
  set(key: string, value: string, mode: string, ttl: number): Promise<boolean>;
  get(key: string): Promise<string | null>;
  del(key: string): Promise<void>;
}

小结
    

  • 共识问题是分布式系统中最基础也最困难的问题之一。
    • 

  • Raft 通过领导者选举和日志复制实现共识，是当前最流行的共识算法。
    • 

  • 协调服务（ZooKeeper/etcd/Consul）将共识算法工程化，提供领导者选举、分布式锁、服务发现等能力。
    • 

  • 选择协调服务时，考虑技术栈生态（Kafka 用 ZK，K8s 用 etcd）和功能需求。
