复制与分区

数据复制

数据复制（Replication）是将同一份数据存储在多个节点上的策略。它的核心目标是：提升数据可用性（节点故障时不丢数据）、降低读取延迟（从最近的副本读取）、提升读吞吐量（多个副本分担读请求）。

半同步复制
实践中的折中方案——至少等待一个副本确认，其余异步：


interface ReplicationConfig {
  totalReplicas: number;
  syncReplicas: number;
  asyncReplicas: number;
  writeTimeout: number;
}

async function writeWithSemiSync(
  primary: Node,
  replicas: Node[],
  data: Record<string, unknown>,
  config: ReplicationConfig,
): Promise<boolean> {
  await primary.write(data);

  const syncPromises = replicas.slice(0, config.syncReplicas).map((r) => r.write(data));

  const asyncReplicas = replicas.slice(config.syncReplicas);
  asyncReplicas.forEach((r) => r.write(data).catch(() => {}));

  const results = await Promise.allSettled(syncPromises);
  const successCount = results.filter((r) => r.status === 'fulfilled').length;

  return successCount >= 1;
}

interface Node {
  write(data: Record<string, unknown>): Promise<void>;
}

数据分区
当单个节点无法容纳所有数据时，需要将数据分散到多个节点——这就是分区（Partitioning），也叫分片（Sharding）。


范围分区
interface RangePartition {
  id: number;
  startKey: string;
  endKey: string;
  node: string;
}

class RangePartitioner {
  private partitions: RangePartition[];

  constructor(partitions: RangePartition[]) {
    this.partitions = partitions.sort((a, b) => a.startKey.localeCompare(b.startKey));
  }

  getPartition(key: string): RangePartition {
    for (const partition of this.partitions) {
      if (key >= partition.startKey && key < partition.endKey) {
        return partition;
      }
    }
    return this.partitions[this.partitions.length - 1];
  }
}
哈希分区
class HashPartitioner {
  private nodeCount: number;

  constructor(nodeCount: number) {
    this.nodeCount = nodeCount;
  }

  getPartition(key: string): number {
    const hash = this.fnv1a(key);
    return hash % this.nodeCount;
  }

  private fnv1a(key: string): number {
    let hash = 0x811c9dc5;
    for (let i = 0; i < key.length; i++) {
      hash ^= key.charCodeAt(i);
      hash = (hash * 0x01000193) >>> 0;
    }
    return hash;
  }
}

热点问题与再平衡
热点检测与处理
interface PartitionMetrics {
  partitionId: number;
  requestRate: number;
  dataSize: number;
  cpuUsage: number;
}

function detectHotspot(metrics: PartitionMetrics[], threshold: number): PartitionMetrics[] {
  const avgRate = metrics.reduce((sum, m) => sum + m.requestRate, 0) / metrics.length;
  return metrics.filter((m) => m.requestRate > avgRate * threshold);
}

function rebalancePlan(
  hotPartitions: PartitionMetrics[],
  allPartitions: PartitionMetrics[],
): Array<{ from: number; to: number; keyRange: string }> {
  const coldPartitions = allPartitions
    .filter((p) => !hotPartitions.includes(p))
    .sort((a, b) => a.requestRate - b.requestRate);

  return hotPartitions.map((hot, i) => ({
    from: hot.partitionId,
    to: coldPartitions[i % coldPartitions.length].partitionId,
    keyRange: `split_${hot.partitionId}`,
  }));
}


小结
    

  • 复制提升可用性和读性能，核心权衡是一致性 vs 延迟。
    • 

  • 分区突破单节点的存储和计算瓶颈，核心权衡是查询灵活性 vs 数据均匀性。
    • 

  • 实际系统同时使用复制和分区——每个分区有多个副本。
    • 

  • 热点检测和再平衡是运维分布式存储系统的关键能力。
