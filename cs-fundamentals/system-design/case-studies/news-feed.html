新闻推送流

需求分析

设计一个类似 Twitter/微博的新闻推送流（News Feed）系统。用户可以发布动态，关注其他用户，并在首页看到已关注用户的最新动态（按时间倒序排列）。

功能需求

  • 用户可以发布文本/图片/视频动态
  • 用户可以关注/取消关注其他用户
  • 首页展示已关注用户的动态流（时间线）
  • 支持分页加载更多历史动态

非功能需求

维度 目标
日活用户 3 亿
平均关注数 200
每日新发布 5 亿条动态
Feed 刷新延迟 < 2 秒
可用性 99.99%

Feed 缓存设计
class FeedCache {
  private redis: RedisClient;
  private maxFeedSize: number;

  constructor(redis: RedisClient, maxFeedSize = 1000) {
    this.redis = redis;
    this.maxFeedSize = maxFeedSize;
  }

  async addToFeed(userId: string, postId: string, timestamp: number): Promise<void> {
    const key = `feed:${userId}`;
    await this.redis.zadd(key, timestamp, postId);
    await this.redis.zremrangebyrank(key, 0, -(this.maxFeedSize + 1));
  }

  async getFeed(userId: string, offset: number, limit: number): Promise<string[]> {
    const key = `feed:${userId}`;
    return this.redis.zrevrange(key, offset, offset + limit - 1);
  }

  async removeFromFeed(userId: string, postId: string): Promise<void> {
    await this.redis.zrem(`feed:${userId}`, postId);
  }
}

interface RedisClient {
  zadd(key: string, score: number, member: string): Promise<void>;
  zrevrange(key: string, start: number, stop: number): Promise<string[]>;
  zremrangebyrank(key: string, start: number, stop: number): Promise<void>;
  zrem(key: string, member: string): Promise<void>;
}
扇出服务
class FanOutService {
  constructor(
    private feedCache: FeedCache,
    private followStore: FollowStore,
    private postStore: PostStore,
  ) {}

  async fanOutPost(postId: string, authorId: string): Promise<void> {
    const post = await this.postStore.getPost(postId);
    if (!post) return;

    const followerCount = await this.followStore.getFollowerCount(authorId);

    if (followerCount > 10000) {
      return;
    }

    const batchSize = 500;
    let cursor = '';

    while (true) {
      const { followers, nextCursor } = await this.followStore.getFollowers(authorId, batchSize, cursor);

      await Promise.all(followers.map((followerId) => this.feedCache.addToFeed(followerId, postId, post.createdAt)));

      if (!nextCursor) break;
      cursor = nextCursor;
    }
  }
}

interface FollowStore {
  getFollowerCount(userId: string): Promise<number>;
  getFollowers(
    userId: string,
    limit: number,
    cursor: string,
  ): Promise<{
    followers: string[];
    nextCursor: string | null;
  }>;
}

interface PostStore {
  getPost(postId: string): Promise<Post | null>;
}

排序与推荐
简单的按时间排序可能并非最优的用户体验。现代推送流系统通常使用相关性排序：


interface FeedRankingSignals {
  recency: number;
  authorAffinity: number;
  engagementScore: number;
  contentType: string;
  isFromCloseFirend: boolean;
}

function calculateFeedScore(signals: FeedRankingSignals): number {
  const recencyDecay = Math.exp(-signals.recency / 86400000);
  const affinityWeight = signals.authorAffinity * 0.3;
  const engagementWeight = Math.log(signals.engagementScore + 1) * 0.2;
  const closeFriendBoost = signals.isFromCloseFirend ? 0.2 : 0;

  return recencyDecay * 0.3 + affinityWeight + engagementWeight + closeFriendBoost;
}


小结
    

  • Feed 系统的核心挑战是扇出策略——推模式写入成本高，拉模式读取成本高。
    • 

  • 混合策略（普通用户推、大 V 拉）是 Twitter 等大型平台的实践方案。
    • 

  • Redis Sorted Set 是 Feed 缓存的理想数据结构——按分数排序、高效分页。
    • 

  • 从时间排序演进到相关性排序是提升用户体验的关键。
