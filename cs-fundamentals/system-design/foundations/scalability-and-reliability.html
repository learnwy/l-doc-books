可扩展性与可靠性

可扩展性的本质

可扩展性（Scalability）描述的是系统应对负载增长的能力。一个可扩展的系统能够在用户数量、数据规模或请求频率增长时，通过增加资源来维持性能表现，而不需要重新设计架构。

在实际工程中，两种方式经常结合使用：先垂直扩展到合理水平，再通过水平扩展突破瓶颈。




无状态与有状态服务
水平扩展的关键前提是无状态设计（Stateless Design）。


import express from 'express';
import session from 'express-session';
import RedisStore from 'connect-redis';
import { createClient } from 'redis';

const redisClient = createClient({ url: 'redis://localhost:6379' });

const app = express();

app.use(
  session({
    store: new RedisStore({ client: redisClient }),
    secret: 'my-secret',
    resave: false,
    saveUninitialized: false,
    cookie: { maxAge: 3600000 },
  }),
);

app.get('/api/profile', (req, res) => {
  const userId = req.session.userId;
  res.json({ userId });
});
将会话状态外移到 Redis 后，任何一台 API 服务器都能处理任何用户的请求，实现了真正的无状态水平扩展。




可靠性的基本原则
可靠性（Reliability）描述的是系统在面临故障时继续正常运行的能力。现实世界中，硬件会损坏、网络会中断、软件会出 Bug——可靠的系统不是假设不会出故障，而是假设故障一定会发生，并为此做好准备。

优雅降级（Graceful Degradation）
当系统负载超出能力时，有选择地放弃非核心功能，保障核心功能可用：


interface DegradationConfig {
  level: 'normal' | 'degraded' | 'critical';
  disabledFeatures: string[];
}

const degradationLevels: Record<string, DegradationConfig> = {
  normal: {
    level: 'normal',
    disabledFeatures: [],
  },
  degraded: {
    level: 'degraded',
    disabledFeatures: ['recommendations', 'analytics', 'notifications'],
  },
  critical: {
    level: 'critical',
    disabledFeatures: ['recommendations', 'analytics', 'notifications', 'search', 'comments'],
  },
};

function shouldServeFeature(feature: string, systemLoad: number): boolean {
  let config: DegradationConfig;
  if (systemLoad < 0.7) {
    config = degradationLevels.normal;
  } else if (systemLoad < 0.9) {
    config = degradationLevels.degraded;
  } else {
    config = degradationLevels.critical;
  }
  return !config.disabledFeatures.includes(feature);
}
重试与超时
网络调用必须设置合理的超时和重试策略：


interface RetryConfig {
  maxRetries: number;
  baseDelayMs: number;
  maxDelayMs: number;
  backoffMultiplier: number;
}

async function fetchWithRetry(url: string, config: RetryConfig): Promise<Response> {
  let lastError: Error | null = null;

  for (let attempt = 0; attempt <= config.maxRetries; attempt++) {
    try {
      const controller = new AbortController();
      const timeoutId = setTimeout(() => controller.abort(), 5000);

      const response = await fetch(url, { signal: controller.signal });
      clearTimeout(timeoutId);

      if (response.ok) return response;
      throw new Error(`HTTP ${response.status}`);
    } catch (error) {
      lastError = error as Error;
      if (attempt < config.maxRetries) {
        const delay = Math.min(config.baseDelayMs * Math.pow(config.backoffMultiplier, attempt), config.maxDelayMs);
        const jitter = delay * (0.5 + Math.random() * 0.5);
        await new Promise((resolve) => setTimeout(resolve, jitter));
      }
    }
  }

  throw lastError;
}
指数退避（Exponential Backoff）加抖动（Jitter）是工业界的标准做法——避免大量客户端在同一时刻发起重试，形成"重试风暴"。




扩展性与可靠性的权衡
扩展性和可靠性并不总是同向的。增加组件数量提升了扩展能力，但也引入了更多的故障点和协调成本：


系统设计的核心就是在这些相互矛盾的目标之间找到最佳平衡点。Netflix 的混沌工程（Chaos Engineering）就是一个典型例子——主动注入故障来验证系统的可靠性，确保水平扩展后的系统仍然具备足够的容错能力。




小结
    

  • 垂直扩展简单但有上限，水平扩展无上限但需要分布式设计。
    • 

  • 无状态服务是水平扩展的前提——将状态外移到共享存储。
    • 

  • 可用性用"几个 9"量化，每多一个 9 成本指数增长。
    • 

  • 冗余设计消除单点故障，故障转移保障服务连续性。
    • 

  • 优雅降级在极端负载下保护核心功能。
    • 

  • 指数退避 + 抖动是重试策略的工业标准。
    •
