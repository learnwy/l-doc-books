DNS 与 CDN

DNS：互联网的电话簿

DNS（Domain Name System）将人类可读的域名转换为机器可用的 IP 地址。每一次在浏览器中输入 www.example.com，背后都有一系列 DNS 查询在默默工作。

DNS 在系统设计中的作用
DNS 不只是做域名解析——它是系统设计中实现负载均衡和故障转移的基础工具。


基于 DNS 的负载均衡：


基于地理位置的路由：


interface DNSRecord {
  domain: string;
  type: 'A' | 'AAAA' | 'CNAME';
  value: string;
  ttl: number;
  region: string;
}

const geoRouting: DNSRecord[] = [
  { domain: 'api.example.com', type: 'A', value: '10.0.1.1', ttl: 60, region: 'us-east' },
  { domain: 'api.example.com', type: 'A', value: '10.0.2.1', ttl: 60, region: 'eu-west' },
  { domain: 'api.example.com', type: 'A', value: '10.0.3.1', ttl: 60, region: 'ap-southeast' },
];

function resolveDNS(domain: string, clientRegion: string): string {
  const records = geoRouting.filter((r) => r.domain === domain);
  const regional = records.find((r) => r.region === clientRegion);
  return regional?.value ?? records[0].value;
}
DNS 缓存与 TTL
DNS 缓存是一把双刃剑：






TTL 值
优势
劣势





短（60s）
快速故障转移、灵活切换
DNS 查询压力大




长（1h）
减少 DNS 查询、降低延迟
变更生效慢





在需要快速故障转移的场景中，TTL 应设为较短值（如 60 秒）；在稳定的服务中，TTL 可以设为较长值以减少 DNS 查询开销。




CDN：让内容离用户更近
CDN（Content Delivery Network）是一组分布在全球各地的缓存服务器，将内容推送到离用户最近的边缘节点，从而大幅降低访问延迟。


CDN 工作原理
Push vs Pull CDN




类型
工作方式
优势
劣势

Push CDN
源站主动推送到边缘
首次访问零延迟
需要管理推送逻辑
静态资源、固定内容




Pull CDN
首次请求时从源站拉取
自动管理，简单
首次访问有回源延迟
动态缓存、长尾内容





CDN 缓存策略
interface CDNCacheConfig {
  path: string;
  maxAge: number;
  staleWhileRevalidate: number;
  staleIfError: number;
  varyHeaders: string[];
}

const cacheRules: CDNCacheConfig[] = [
  {
    path: '/static/*',
    maxAge: 31536000,
    staleWhileRevalidate: 0,
    staleIfError: 86400,
    varyHeaders: [],
  },
  {
    path: '/api/public/*',
    maxAge: 60,
    staleWhileRevalidate: 300,
    staleIfError: 3600,
    varyHeaders: ['Accept', 'Accept-Language'],
  },
  {
    path: '/images/*',
    maxAge: 604800,
    staleWhileRevalidate: 86400,
    staleIfError: 604800,
    varyHeaders: ['Accept'],
  },
];

function generateCacheHeader(config: CDNCacheConfig): string {
  return [
    `max-age=${config.maxAge}`,
    `stale-while-revalidate=${config.staleWhileRevalidate}`,
    `stale-if-error=${config.staleIfError}`,
  ].join(', ');
}
CDN 在系统架构中的位置


真实世界案例
Netflix 的 CDN 策略
Netflix 使用自建的 CDN（Open Connect）来分发视频内容：


    

  • 在全球 ISP 的数据中心部署专用缓存设备
    • 

  • 在非高峰时段预热热门内容到边缘节点
    • 

  • 单个边缘服务器可提供 100Gbps 的视频流量
    • 

  • 通过 DNS 将用户路由到最近的缓存节点
    • 



Cloudflare 的 Anycast DNS
Cloudflare 使用 Anycast 技术，同一个 IP 地址在全球多个位置广播。用户的请求自动被路由到地理位置最近的节点，无需在 DNS 层做地理路由——这大幅简化了全球负载均衡的复杂度。




小结
    

  • DNS 是互联网的寻址基础，也是实现全球负载均衡和故障转移的关键工具。
    • 

  • TTL 的选择需要权衡更新速度与查询开销。
    • 

  • CDN 通过边缘缓存将内容推送到离用户最近的位置，大幅降低延迟。
    • 

  • Push CDN 适合已知的静态资源，Pull CDN 适合动态和长尾内容。
    • 

  • DNS + CDN 的组合是几乎所有大规模系统的标配基础设施。
