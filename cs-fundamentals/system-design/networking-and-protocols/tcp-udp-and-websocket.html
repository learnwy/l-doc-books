TCP、UDP 与 WebSocket

核心概念

传输层的核心权衡是可靠性 vs 延迟。三种协议分别占据了这条权衡轴上的不同位置：

  • TCP：面向连接的可靠字节流——三次握手建连、四次挥手断连，靠序列号、确认应答、超时重传、滑动窗口、拥塞控制保证有序送达。
  • 拥塞控制：慢启动（指数增长）→ 拥塞避免（线性增长），丢包时超时则重置窗口、三次重复 ACK 则快恢复（窗口减半）。
  • UDP：无连接、无可靠性保证、无拥塞控制，头部仅 8 字节——适合容忍丢包的实时场景（游戏、视频、VoIP、DNS）。
  • WebSocket：通过 HTTP 升级握手（101 Switching Protocols）在 TCP 之上建立全双工通道，是聊天、游戏、协作编辑的首选。
  • 四种实时通信方案：短轮询、长轮询、SSE（服务端→客户端）、WebSocket（双向），延迟与服务器资源开销依次递增。

TCP：可靠的字节流

TCP（Transmission Control Protocol）是互联网最核心的传输层协议。它提供面向连接的、可靠的、有序的字节流传输。

三次握手

sequenceDiagram
    participant C as 客户端
    participant S as 服务器

    Note over C,S: TCP 三次握手
    C->>S: SYN (seq=x)
    Note over C: SYN_SENT
    S->>C: SYN-ACK (seq=y, ack=x+1)
    Note over S: SYN_RECEIVED
    C->>S: ACK (ack=y+1)
    Note over C,S: ESTABLISHED
    Note over C,S: 连接建立完成,可以传输数据

三次握手的目的是双方确认彼此的发送和接收能力，并同步初始序列号。这个过程需要 1.5 个 RTT（往返时间），在高延迟网络中会显著影响连接建立速度。

四次挥手

sequenceDiagram
    participant C as 客户端
    participant S as 服务器

    Note over C,S: TCP 四次挥手
    C->>S: FIN
    Note over C: FIN_WAIT_1
    S->>C: ACK
    Note over C: FIN_WAIT_2
    Note over S: CLOSE_WAIT
    S->>S: 处理剩余数据
    S->>C: FIN
    Note over S: LAST_ACK
    C->>S: ACK
    Note over C: TIME_WAIT(等待 2MSL)
    Note over S: CLOSED
    Note over C: CLOSED

TCP 的可靠性机制

机制 描述
序列号 每个字节都有编号，保证数据有序
确认应答 接收方确认已收到的数据
超时重传 未收到确认则重新发送
滑动窗口 控制发送速率，避免接收方溢出
拥塞控制 慢启动、拥塞避免、快重传、快恢复
校验和 检测传输中的数据损坏

拥塞控制

TCP 的拥塞控制是其最精妙也最影响性能的机制：

graph LR
    A[慢启动<br/>指数增长] -->|达到阈值| B[拥塞避免<br/>线性增长]
    B -->|检测到丢包| C{丢包类型}
    C -->|超时| D[重置窗口<br/>回到慢启动]
    C -->|三次重复 ACK| E[快恢复<br/>窗口减半]
    E --> B
    D --> A
interface TCPCongestionState {
  cwnd: number;
  ssthresh: number;
  phase: 'slow-start' | 'congestion-avoidance' | 'fast-recovery';
}

function simulateCongestionControl(initialState: TCPCongestionState, rounds: number): TCPCongestionState[] {
  const history: TCPCongestionState[] = [];
  let state = { ...initialState };

  for (let i = 0; i < rounds; i++) {
    history.push({ ...state });

    const packetLost = Math.random() < 0.05;

    if (packetLost) {
      state.ssthresh = Math.floor(state.cwnd / 2);
      state.cwnd = state.ssthresh;
      state.phase = 'fast-recovery';
    } else if (state.phase === 'slow-start') {
      state.cwnd *= 2;
      if (state.cwnd >= state.ssthresh) {
        state.phase = 'congestion-avoidance';
      }
    } else {
      state.cwnd += 1;
      state.phase = 'congestion-avoidance';
    }
  }

  return history;
}

UDP：轻量与速度

UDP（User Datagram Protocol）是一个极简的传输层协议。没有连接建立、没有可靠性保证、没有拥塞控制——就像寄明信片：发出去就不管了。

graph LR
    subgraph TCP
        T1[连接建立] --> T2[有序传输]
        T2 --> T3[确认重传]
        T3 --> T4[拥塞控制]
        T4 --> T5[连接关闭]
    end
    subgraph UDP
        U1[直接发送数据报] --> U2[接收方自行处理]
    end

TCP vs UDP

特性 TCP UDP
连接方式 面向连接（三次握手） 无连接
可靠性 保证送达和顺序 不保证
拥塞控制 有 无
头部大小 20-60 字节 8 字节
传输模式 字节流 数据报
延迟 较高（握手 + 重传） 较低
适用场景 Web、文件传输、邮件 视频、游戏、DNS

WebSocket：全双工通信

WebSocket 在 TCP 之上提供了全双工的通信通道。与 HTTP 的请求-响应模式不同，WebSocket 连接一旦建立，服务端和客户端可以随时向对方发送消息。

握手过程

WebSocket 通过 HTTP 升级握手来建立连接：

sequenceDiagram
    participant C as 客户端
    participant S as 服务器

    C->>S: HTTP GET /chat<br/>Upgrade: websocket<br/>Connection: Upgrade<br/>Sec-WebSocket-Key: dGhlIH...
    S->>C: HTTP 101 Switching Protocols<br/>Upgrade: websocket<br/>Connection: Upgrade<br/>Sec-WebSocket-Accept: s3pPLM...
    Note over C,S: WebSocket 连接已建立
    C->>S: WebSocket 帧(文本/二进制)
    S->>C: WebSocket 帧(文本/二进制)
    S->>C: WebSocket 帧(服务端主动推送)
    C->>S: Ping
    S->>C: Pong
    C->>S: Close
    S->>C: Close

实现示例

import { WebSocketServer, WebSocket } from 'ws';

interface ChatMessage {
  type: 'message' | 'join' | 'leave';
  userId: string;
  content: string;
  timestamp: number;
}

const wss = new WebSocketServer({ port: 8080 });
const clients = new Map<string, WebSocket>();

wss.on('connection', (ws, req) => {
  const userId = new URL(req.url!, `http://${req.headers.host}`).searchParams.get('userId')!;
  clients.set(userId, ws);

  broadcast({
    type: 'join',
    userId,
    content: `${userId} 加入了聊天室`,
    timestamp: Date.now(),
  });

  ws.on('message', (data) => {
    const message: ChatMessage = {
      type: 'message',
      userId,
      content: data.toString(),
      timestamp: Date.now(),
    };
    broadcast(message);
  });

  ws.on('close', () => {
    clients.delete(userId);
    broadcast({
      type: 'leave',
      userId,
      content: `${userId} 离开了聊天室`,
      timestamp: Date.now(),
    });
  });

  ws.on('pong', () => {
    (ws as any).isAlive = true;
  });
});

function broadcast(message: ChatMessage): void {
  const data = JSON.stringify(message);
  for (const client of clients.values()) {
    if (client.readyState === WebSocket.OPEN) {
      client.send(data);
    }
  }
}

setInterval(() => {
  for (const [userId, ws] of clients) {
    if ((ws as any).isAlive === false) {
      clients.delete(userId);
      ws.terminate();
      return;
    }
    (ws as any).isAlive = false;
    ws.ping();
  }
}, 30000);

小结

mindmap
  root((传输协议))
    TCP
      可靠有序
      拥塞控制
      三次握手
      适合 Web 文件传输
    UDP
      无连接
      低延迟
      适合实时音视频
      DNS 查询
    WebSocket
      全双工
      基于 TCP
      实时双向通信
      聊天 游戏 协作
  • TCP 提供可靠有序传输，是 Web 和文件传输的基础，但握手和拥塞控制带来延迟。
  • UDP 极简高效，适合容忍丢包的实时场景（游戏、视频、VoIP）。
  • WebSocket 在 TCP 之上提供全双工通信，是实时应用的首选方案。
  • 选择协议时，核心权衡是可靠性 vs 延迟——业务场景决定取舍。
