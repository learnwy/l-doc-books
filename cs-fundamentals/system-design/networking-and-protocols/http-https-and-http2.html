HTTP、HTTPS 与 HTTP/2

HTTP 协议基础

HTTP（HyperText Transfer Protocol）是 Web 通信的基石。它是一个基于请求-响应模型的应用层协议，运行在 TCP 之上。客户端发送请求，服务器返回响应——这个简单的模型支撑了整个互联网。

幂等性是系统设计中的关键概念——对同一请求重复执行多次，结果与执行一次相同。在网络不可靠的环境中，幂等性让客户端可以安全地重试失败的请求。

HTTPS 与安全
HTTPS 是 HTTP 的安全版本，通过 TLS（Transport Layer Security）协议对通信内容进行加密。在现代系统设计中，HTTPS 不是可选项，而是必选项。

TLS 1.3 将握手从 2 次往返缩减到 1 次，且支持 0-RTT 恢复——显著降低了 HTTPS 的延迟开销。




HTTP/1.1 的性能问题
HTTP/1.1 存在几个固有的性能瓶颈：


队头阻塞（Head-of-Line Blocking）：同一个 TCP 连接上的请求必须按顺序处理，前面的慢请求会阻塞后面的快请求。

HTTP/2 的核心改进
多路复用
HTTP/2 最重要的特性是多路复用（Multiplexing）：在单个 TCP 连接上并行传输多个请求和响应。


头部压缩（HPACK）

协议选择指南


小结
    

  • HTTP/1.1 简单成熟，但存在队头阻塞和连接数限制。
    • 

  • HTTPS 是现代系统的标配，TLS 1.3 将握手延迟降到 1-RTT。
    • 

  • HTTP/2 通过多路复用、头部压缩和服务端推送大幅提升性能。
    • 

  • HTTP/3 基于 QUIC 协议，彻底消除队头阻塞，适合弱网环境。
    • 

  • 协议选择取决于业务场景：高吞吐 API 首选 HTTP/2，弱网移动端首选 HTTP/3。
