REST、GraphQL 与 gRPC

API 设计范式概览

API 是系统组件之间通信的接口契约。选择合适的 API 设计范式直接影响系统的可维护性、性能和开发效率。当前主流的三种范式各有特色：



REST：资源导向的简单哲学
REST（Representational State Transfer）以资源为核心，通过 HTTP 方法表达对资源的操作。它的核心原则是：每个 URL 代表一种资源，使用标准 HTTP 方法进行 CRUD 操作。


RESTful API 设计
import express from 'express';

const app = express();
app.use(express.json());

interface User {
  id: string;
  name: string;
  email: string;
  createdAt: Date;
}

const users = new Map<string, User>();

app.get('/api/v1/users', (req, res) => {
  const page = Number(req.query.page) || 1;
  const limit = Number(req.query.limit) || 20;
  const offset = (page - 1) * limit;

  const allUsers = Array.from(users.values());
  const pageUsers = allUsers.slice(offset, offset + limit);

  res.json({
    data: pageUsers,
    pagination: {
      page,
      limit,
      total: allUsers.length,
      totalPages: Math.ceil(allUsers.length / limit),
    },
  });
});

app.get('/api/v1/users/:id', (req, res) => {
  const user = users.get(req.params.id);
  if (!user) {
    res.status(404).json({ error: 'User not found' });
    return;
  }
  res.json({ data: user });
});

app.post('/api/v1/users', (req, res) => {
  const { name, email } = req.body;
  const id = crypto.randomUUID();
  const user: User = { id, name, email, createdAt: new Date() };
  users.set(id, user);
  res.status(201).json({ data: user });
});

app.put('/api/v1/users/:id', (req, res) => {
  const existing = users.get(req.params.id);
  if (!existing) {
    res.status(404).json({ error: 'User not found' });
    return;
  }
  const updated = { ...existing, ...req.body };
  users.set(req.params.id, updated);
  res.json({ data: updated });
});

app.delete('/api/v1/users/:id', (req, res) => {
  if (!users.has(req.params.id)) {
    res.status(404).json({ error: 'User not found' });
    return;
  }
  users.delete(req.params.id);
  res.status(204).send();
});

GraphQL：客户端驱动的灵活查询
GraphQL 由 Facebook 于 2015 年开源，核心理念是让客户端精确描述需要的数据，服务端返回恰好满足需求的结果。


Schema 定义
type User {
  id: ID!
  name: String!
  email: String!
  avatar: String
  posts(limit: Int = 10): [Post!]!
  followers: [User!]!
  followersCount: Int!
}

type Post {
  id: ID!
  title: String!
  content: String!
  author: User!
  comments(limit: Int = 20): [Comment!]!
  createdAt: String!
}

type Comment {
  id: ID!
  text: String!
  author: User!
  createdAt: String!
}

type Query {
  user(id: ID!): User
  post(id: ID!): Post
  feed(page: Int, limit: Int): [Post!]!
}

type Mutation {
  createPost(title: String!, content: String!): Post!
  addComment(postId: ID!, text: String!): Comment!
}

gRPC：高性能二进制通信
gRPC 由 Google 开发，使用 Protocol Buffers 作为序列化格式，基于 HTTP/2 传输。它特别适合微服务之间的内部通信。


Protocol Buffers 定义
syntax = "proto3";

package userservice;

service UserService {
  rpc GetUser (GetUserRequest) returns (UserResponse);
  rpc ListUsers (ListUsersRequest) returns (ListUsersResponse);
  rpc CreateUser (CreateUserRequest) returns (UserResponse);
  rpc StreamUpdates (StreamRequest) returns (stream UserEvent);
}

message GetUserRequest {
  string id = 1;
}

message ListUsersRequest {
  int32 page = 1;
  int32 limit = 2;
}

message CreateUserRequest {
  string name = 1;
  string email = 2;
}

message UserResponse {
  string id = 1;
  string name = 2;
  string email = 3;
  int64 created_at = 4;
}

message ListUsersResponse {
  repeated UserResponse users = 1;
  int32 total = 2;
}

message StreamRequest {
  string filter = 1;
}

message UserEvent {
  string type = 1;
  UserResponse user = 2;
  int64 timestamp = 3;
}

选型决策树


混合使用策略
在实际大型系统中，三种范式往往共存：


Twitter 就采用了这种混合架构：对外提供 REST API（v2），内部微服务之间使用 gRPC 通信，部分客户端使用 GraphQL 来灵活获取数据。




小结
    

  • REST 简单成熟、生态丰富，适合公开 API 和简单 CRUD 场景。
    • 

  • GraphQL 解决了 REST 的过度获取和不足获取问题，适合多样化客户端场景。
    • 

  • gRPC 基于 HTTP/2 和 Protobuf，性能最优，适合微服务内部通信。
    • 

  • 大型系统通常混合使用三种范式——对外 REST/GraphQL，对内 gRPC。
    • 

  • 选型的核心考量：性能需求、客户端多样性、团队能力和生态支持。
