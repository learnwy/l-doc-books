数字签名

核心概念

数字签名（Digital Signature）是公钥密码学的"反向应用"——签名者用私钥签名，任何人用公钥验证。它提供完整性（消息未被篡改）+ 认证（确实来自签名者）+ 不可否认（签名者无法否认）。物理签名（手写）易伪造、不可机器验证；数字签名是数学上不可伪造（assuming 私钥 secure）、机器秒级验证、可批量处理。本节介绍数字签名的形式定义、RSA / ECDSA / EdDSA 三大签名算法对比、签名 + hash 的标准流程、不可否认性的法律意义、聚合签名（BLS）等高级技术。

签名算法 签名长度 验证速度 签名速度 RNG 依赖
RSA-PSS-2048 256 byte 快 慢 是
ECDSA P-256 64 byte 慢 快 致命依赖
Ed25519 64 byte 快 极快 无（deterministic）
BLS12-381 48 byte 慢 快 是
Schnorr 64 byte 快 快 致命依赖

数字签名的形式定义

Triple (Gen, Sign, Verify)：

  • Gen() → (pk, sk)：生成 key pair。
  • Sign(sk, m) → σ：私钥签名消息。
  • Verify(pk, m, σ) → {0, 1}：公钥验证。

安全要求（EUF-CMA：Existential Unforgeability under Chosen Message Attack）：

  • 攻击者即使能让签名者签 polynomially many 任意消息，也无法 forge 一个新消息的签名。
  • 即"无法伪造从未见过的签名"。

签名的 5 大用途

1. 软件分发：

  • macOS / iOS app 必须 Apple 签名。
  • Linux 包（apt/yum）签名验证。
  • Windows driver 需 Microsoft 签名。

2. SSL/TLS 证书：

  • 网站证书由 CA 签名。
  • 浏览器 trust CA → trust 证书 → trust 网站。

3. 区块链：

  • Bitcoin transaction 签名（ECDSA）。
  • Ethereum tx 签名。

4. 文档签名：

  • DocuSign、Adobe Sign。
  • 法律意义：电子签名法承认。

5. 代码签名 / 仓库：

  • Git commit signing（GPG / SSH）。
  • GitHub verified commits。

标准签名流程

直接签名 m 不实用——m 可能很长，签名也长。标准流程：

1. 计算 h = H(m)（hash, e.g. SHA-256）。
2. 签名 σ = Sign(sk, h)。
3. 验证：h' = H(m); Verify(pk, h', σ)。

为什么 hash：

  • 签名通常只能签固定大小数据（如 256 bit）。
  • Hash 把任意长度消息压缩到固定大小。
  • Hash 抗碰撞性 → 签名抗碰撞。

关键：hash 必须抗碰撞——若 H(m1) = H(m2) → m1 的签名也是 m2 的签名 → 攻击者可让签名者签 m1（看似无害）然后用 σ "签" m2（恶意）。SHA-1 carbon dated 因为这个原因弃用于签名。

RSA-PSS 签名
RSA-PSS（Probabilistic Signature Scheme）：


    

  • 用 RSA 私钥签 hash padding。
    • 

  • PSS padding 让签名 randomized（每次签同 m 产生不同签名）。
    • 

  • Provable security 在 random oracle model 下。
    • 



Sign：


1. 计算 H(m)。
2. 随机生成 salt。
3. PSS padding：encoded = construct(H(m), salt, MGF)。
4. σ = encoded^d mod n（RSA 私钥操作）。
Verify：


1. encoded' = σ^e mod n（RSA 公钥操作）。
2. 解构 encoded' 验证 padding 与 H(m)。
实战：现代 RSA 签名永远用 PSS。PKCS#1 v1.5 仍兼容但不推荐（无 random salt）。


ECDSA 签名
ECDSA（Elliptic Curve DSA）：


Sign(sk = d, m):
  z = H(m)
  k = random（关键！）
  (x, y) = k · G
  r = x mod n
  s = k⁻¹ · (z + r · d) mod n
  return (r, s)

Verify(pk = Q, m, (r, s)):
  z = H(m)
  u1 = z · s⁻¹ mod n
  u2 = r · s⁻¹ mod n
  (x, y) = u1 · G + u2 · Q
  return x mod n == r
致命问题：k 必须每次不同 + 不可预测。


    

  • 重用 k → 两次签名 (r, s1) 与 (r, s2) → 攻击者解线性方程还原私钥。
    • 

  • k 可预测（弱 RNG）→ 类似攻击。
    • 



历史案例：


    

  • Sony PS3 2010：硬编码 k（不是 random），私钥被还原，PS3 完全 jailbreak。
    • 

  • Bitcoin Android wallets 2013：Java RNG bug 让多 transaction 用同 k，私钥被推断、资金被盗。
    • 



RFC 6979 deterministic ECDSA：


    

  • k = HMAC(sk, H(m))——deterministic 不需 RNG。
    • 

  • 实现修复了 RNG 风险但仍兼容 ECDSA。
    • 



EdDSA / Ed25519
Ed25519：在 Edwards-form Curve25519 上的签名。


关键特性：


    

  • Deterministic：k 由 hash(sk, m) derived。无 RNG 风险。
    • 

  • 64 byte 签名。
    • 

  • 极快：~ 100k sign / 100k verify per second。
    • 

  • Constant-time：防 side channel。
    • 



算法：


Sign(sk, m):
  h = SHA-512(sk)
  prefix = h[32:]
  r = SHA-512(prefix || m)（deterministic k）
  R = r · G
  k = SHA-512(R || pk || m)
  s = (r + k · privkey_scalar) mod L
  return (R, s)
部署：


    

  • SSH（GitHub 默认）。
    • 

  • Tor v3。
    • 

  • Solana、Cardano。
    • 

  • WireGuard。
    • 



为什么 Ed25519 > ECDSA：


    

  • 无 RNG 风险（deterministic）。
    • 

  • 更快。
    • 

  • 更简单（少错误空间）。
    • 



Schnorr 签名
Schnorr 签名（1989，专利问题历史拖累）：


    

  • 与 ECDSA 数学上等价但更简洁。
    • 

  • Linear——支持聚合（多个签名合并）。
    • 

  • Bitcoin 2021 Taproot 启用 Schnorr。
    • 



优势：


    

  • Linearity → multisig / threshold 简单。
    • 

  • 可证明安全（ECDSA 没有同等证明）。
    • 



BLS 签名（聚合签名）
BLS（Boneh-Lynn-Shacham 2001）：在 pairing-friendly elliptic curve 上的签名。


关键特性：


    

  • 聚合：N 个签名可合并为单一 48 byte 签名。
    • 

  • 批量验证：N 签名一起验证比单独快。
    • 

  • Threshold：N-of-M 多签自然支持。
    • 



应用：


    

  • Ethereum 2.0：validator 签名聚合。
    • 

  • Chia：consensus。
    • 

  • Drand：randomness beacon。
    • 



缺点：


    

  • 验证慢（pairing 计算）。
    • 

  • key 管理复杂。
    • 



不可否认性（Non-Repudiation）
定义：签名者无法否认自己签了。


法律意义：


    

  • 大多数国家承认电子签名（EU eIDAS、US ESIGN Act、China 电子签名法）。
    • 

  • 签名 = 法律 binding 合同。
    • 



保证条件：


    

  • 私钥 secure 仅签名者持有。
    • 

  • 签名算法 secure。
    • 

  • 签名时间戳（trusted timestamp）。
    • 

  • PKI 验证身份。
    • 



反例：私钥被盗后所有签名"可否认"——所以保护私钥极重要。


私钥保护
1. 不存盘明文：


    

  • 加密存储（系统 keychain、KMS、HSM）。
    • 



2. HSM（Hardware Security Module）：


    

  • 硬件保护，私钥永不出 HSM。
    • 

  • 操作通过 API 让 HSM 内部 sign。
    • 

  • 高安全（CA、银行）必备。
    • 



3. 多签 / threshold：


    

  • N-of-M scheme。
    • 

  • 任意 N 把私钥协作签名。
    • 

  • 防单点泄露。
    • 



4. Key rotation：


    

  • 定期换 key。
    • 

  • 限制单 key 暴露窗口。
    • 



常见攻击
1. Hash collision：


    

  • 找 m1, m2 使 H(m1) = H(m2)。
    • 

  • 让签名者签 m1（无害）后 σ 用于 m2（恶意）。
    • 

  • 防御：用 SHA-256 / SHA-3（抗碰撞 2^128+）。
    • 



2. ECDSA k 失败：


    

  • 见上。
    • 

  • 防御：deterministic k 或 Ed25519。
    • 



3. Substitution：


    

  • 攻击者替换公钥。
    • 

  • 防御：PKI 验证。
    • 



4. Replay：


    

  • 重发旧签名。
    • 

  • 防御：sequence number、timestamp、nonce。
    • 



5. Side channel：


    

  • Timing、power analysis。
    • 

  • 防御：constant-time 实现。
    • 



实战 API
Ed25519（cryptography）：


from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey

sk = Ed25519PrivateKey.generate()
pk = sk.public_key()

signature = sk.sign(message)
pk.verify(signature, message)  # 失败抛异常
RSA-PSS（cryptography）：见 RSA 章节。


ECDSA：


from cryptography.hazmat.primitives.asymmetric.ec import generate_private_key, SECP256R1, ECDSA

sk = generate_private_key(SECP256R1())
signature = sk.sign(message, ECDSA(hashes.SHA256()))
sk.public_key().verify(signature, message, ECDSA(hashes.SHA256()))
选择推荐
新部署：


    

  • Ed25519：通用首选（无 RNG 风险、快、简洁）。
    • 

  • ECDSA P-256：需 NIST / FIPS 兼容时。
    • 

  • RSA-PSS-2048：legacy 兼容。
    • 



特殊：


    

  • BLS / Schnorr：聚合签名 / 区块链。
    • 



避免：


    

  • ECDSA 不用 deterministic k。
    • 

  • RSA PKCS#1 v1.5 签名。
    • 

  • 签 SHA-1 hash。
    • 



小结
数字签名提供完整性 + 认证 + 不可否认——签名者用私钥签名，任何人公钥验证。EUF-CMA 安全要求即使 chosen message attack 也无法 forge。5 大用途——软件分发、SSL/TLS 证书、区块链、文档签名、代码签名 / Git。标准流程——hash 后签名（hash 抗碰撞 → 签名抗碰撞）。RSA-PSS 用 RSA 私钥签 PSS-padded hash，randomized 签名。ECDSA 在 elliptic curve 上签名，致命依赖 k random + unique（Sony PS3 + Bitcoin Android 历史案例），RFC 6979 deterministic k 修复。Ed25519 是 EdDSA 在 Curve25519 上——deterministic（无 RNG 风险）、64 byte、~100k ops/s、constant-time——SSH / Tor / Solana / Cardano / WireGuard 主力。Schnorr 签名 linear 支持聚合，Bitcoin 2021 Taproot 启用。BLS 签名支持 N 个聚合到 48 byte，Ethereum 2.0 / Chia 用。不可否认性法律意义——eIDAS、ESIGN、电子签名法承认，保证条件包括私钥 secure、算法 secure、timestamp、PKI。私钥保护——加密存储、HSM、多签、key rotation。常见攻击——hash collision、ECDSA k 失败、substitution、replay、side channel。选择推荐——Ed25519 首选、ECDSA P-256（NIST 兼容）、RSA-PSS（legacy），避免 ECDSA 非 deterministic k 与 PKCS#1 v1.5。一个简单的检验：你能解释为什么"Sony PS3 ECDSA 签名失败让整个 console 被破"？如果不能，ECDSA k 的关键性还需巩固。数字签名是密码学的"信任基础设施"——上承 hash 与公钥密码，下接 PKI 与法律 framework，让数字世界有等同物理世界的"签名 binding"。
