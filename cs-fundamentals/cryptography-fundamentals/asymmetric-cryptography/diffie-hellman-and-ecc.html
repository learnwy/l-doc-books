Diffie-Hellman 与椭圆曲线密码

核心概念

Diffie-Hellman（DH，1976）是公钥密码学的"原初论文"——比 RSA 早 1 年——解决了 key exchange 问题：双方在公开信道上协商出共享 secret，即使被动监听也无法还原。它的安全性依赖离散对数问题（Discrete Logarithm Problem，DLP）的困难——给 g, p, g^a mod p，难以求 a。Elliptic Curve Cryptography（ECC，1985 Miller / Koblitz 各自独立提出）把 DH 与签名搬到 elliptic curve 群上——同等安全级别下 key 短得多（256 bit ECC ≈ 3072 bit RSA），让公钥密码进入移动 / IoT / 区块链时代。本节介绍 DH 协议、DLP 困难、ECC 数学基础、X25519 / Ed25519、为什么 ECC 取代 RSA。

算法 Key size 等价 RSA 用途
DH（mod p） 2048 bit 2048 bit Key exchange
ECDH（P-256） 256 bit 3072 bit Key exchange
ECDH（X25519） 256 bit 3072 bit Key exchange
ECDSA（P-256） 256 bit 3072 bit 签名
Ed25519 256 bit 3072 bit 签名
ECDSA（P-521） 521 bit 15360 bit 高安全签名

Diffie-Hellman Key Exchange

协议：

公开参数：大素数 p、生成元 g (g 在 Z_p* 中阶大)。

Alice：选私钥 a，发送 A = g^a mod p。
Bob：  选私钥 b，发送 B = g^b mod p。

Alice 计算 K = B^a mod p。
Bob   计算 K = A^b mod p。

K = g^(ab) mod p（两边等）。

安全性：被动攻击者看到 g, p, A, B，要还原 K = g^(ab) 需要解 DLP（从 g^a 求 a 或从 g^b 求 b）——困难。

Diffie-Hellman 假设（DDH / CDH）：

  • CDH（Computational DH）：给 g^a, g^b，难以计算 g^(ab)。
  • DDH（Decisional DH）：给 g^a, g^b, g^c，难以判断 c = ab 还是随机。

DDH 比 CDH 强。某些群（如普通 elliptic curve）DDH 不成立但 CDH 成立——影响协议设计。

DH 的弱点：MITM

纯 DH 不抵抗主动攻击：

  • 攻击者 Eve 拦截 A、B，自己生成 e。
  • 与 Alice 协商 g^(ae)，与 Bob 协商 g^(be)。
  • Eve 同时与双方有 secret，转发并 monitor 流量。

防御：DH + 认证——签名 DH（如 TLS handshake）或 PKI 验证身份。

离散对数问题

DLP：给 g, p, h = g^x mod p，求 x。

最佳已知算法：

  • 暴力穷举：O(p)——p 大时不可行。
  • Baby-step Giant-step：O(√p)。
  • Pollard rho：O(√p)，内存 O(1)。
  • Index calculus：O(exp(√(ln p · ln ln p)))——亚指数但仍困难。

1024 bit p 的 DLP ≈ 2009-2012 已破。

2048 bit p 仍安全到 2030。

ECC 数学基础

Elliptic Curve（在素数域 F_p 上）：

y² = x³ + ax + b (mod p)

满足 4a³ + 27b² ≠ 0（避免奇点）。

点加法：在曲线上定义"加法"——两点 P + Q 的几何意义是连两点的直线与曲线第三交点的对称：

  • P + Q 几何：连 P-Q 直线与曲线交第三点 R'，R = -R'。
  • P + P（doubling）：P 处切线与曲线交点。
  • 单位元 O：无穷远点（P + O = P）。

标量乘法：k · P = P + P + ... + P（k 次）——用 double-and-add 算法 O(log k)。

ECDLP（Elliptic Curve Discrete Log）：

  • 给定 P, Q = k · P，求 k。
  • 最佳已知算法是 Pollard rho，O(√n)。
  • 不存在亚指数算法（与普通 DLP 不同）。

这就是 ECC 的关键——同样安全级别下 key 短得多：

  • DLP 在 2048 bit 群——亚指数攻击让等价对称强度仅 112 bit。
  • ECDLP 在 256 bit 群——指数攻击让等价对称强度 128 bit。

标准 Curve

NIST P 曲线（FIPS 186-4）：

  • P-256（256 bit）：最常用。
  • P-384、P-521：高安全。
  • 历史问题：曲线参数选择被怀疑（NSA 的 Dual_EC_DRBG 后门疑虑）。

Curve25519（Bernstein 2005）：

  • 256 bit。
  • 设计 transparent，参数公开理性。
  • X25519（DH on Curve25519）速度极快。
  • TLS 1.3 推荐。

Edwards25519（Ed25519 签名）：

  • 同 Curve25519 数学基础。
  • 设计 deterministic（无需 RNG）。
  • 极快验证。

brainpool 曲线：

  • 欧洲设计，参数 verifiable。
  • 部分场景使用。
X25519：现代 ECDH
算法：在 Curve25519 上做 ECDH。


速度：~ 100k operations / second（软件，无硬件加速）。


TLS 1.3 默认：


    

  • ClientHello 包含 X25519 public key。
    • 

  • ServerHello 返回 X25519 public key。
    • 

  • 双方 derive shared secret。
    • 



X25519 vs P-256：


    

  • 相近安全。
    • 

  • X25519 速度略快、设计更 transparent。
    • 

  • TLS 1.3 默认 X25519，向后兼容 P-256。
    • 



Ed25519：现代签名
算法：在 Curve25519（Edwards form）上签名。


优势：


    

  • Deterministic：签名无需 RNG（避免 Sony PS3 那种 RNG 失败 → 私钥泄露）。
    • 

  • 极快：~ 100k sign / 100k verify / second。
    • 

  • 小：64 byte 签名 + 32 byte 公钥。
    • 

  • Constant-time：防 side channel。
    • 



部署：


    

  • SSH（GitHub 默认）。
    • 

  • Tor（v3 onion service）。
    • 

  • 区块链（Solana、Cardano）。
    • 

  • WireGuard。
    • 



Bitcoin / Ethereum：用 secp256k1 + ECDSA（不是 Ed25519）——历史选择，未来可能转 Schnorr / BLS。


ECDSA 与历史风险
ECDSA（FIPS 186-4）：用 ECC 实现的 DSA 签名：


1. 选随机 nonce k。
2. (x, y) = k · G。
3. r = x mod n。
4. s = k⁻¹ · (z + r · d) mod n（z 是 hash，d 是私钥）。
5. 签名 = (r, s)。
致命弱点：k 必须每次随机不同——k 重用 / 可预测 → 私钥被还原。


历史案例：


    

  • Sony PS3（2010）：硬编码 k → 私钥泄露 → 自由签名固件。
    • 

  • Bitcoin 钱包（2013）：Android Java RNG bug → 多 transaction 用同 k → 私钥被推断 → 资金被盗。
    • 



Ed25519 防御：deterministic（k 由 hash(privkey, message) derived）——天然无 RNG 风险。


ECC 的 quantum 风险
Shor 算法对 ECC 同 RSA：


    

  • Quantum 多项式时间破 ECDLP。
    • 

  • 256 bit ECC 与 2048 bit RSA 在 quantum 下都会失效。
    • 

  • 需 ~ 2000-3000 logical qubits 破 ECC。
    • 



Post-Quantum 替代：


    

  • NIST 2024 年标准化 ML-KEM（key exchange）、ML-DSA（签名）。
    • 

  • 基于 lattice。
    • 

  • Key 比 ECC 大（~ 1KB vs 32 byte）。
    • 



Hybrid 部署：


    

  • TLS 现代部署用 X25519 + ML-KEM 双重 key exchange。
    • 

  • 任一安全则整体安全。
    • 



ECC 实战
Python（cryptography）：


from cryptography.hazmat.primitives.asymmetric.x25519 import X25519PrivateKey
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey

# X25519 ECDH
alice = X25519PrivateKey.generate()
bob = X25519PrivateKey.generate()
alice_shared = alice.exchange(bob.public_key())
bob_shared = bob.exchange(alice.public_key())
# alice_shared == bob_shared

# Ed25519 签名
sk = Ed25519PrivateKey.generate()
signature = sk.sign(b"message")
sk.public_key().verify(signature, b"message")
OpenSSH：


ssh-keygen -t ed25519
# 生成 Ed25519 keypair
ECC 的常见攻击
1. 弱 curve：


    

  • 小余因子、奇异曲线、anomalous curve。
    • 

  • 用标准曲线（P-256、X25519）规避。
    • 



2. Invalid curve attack：


    

  • 攻击者发送不在曲线上的点。
    • 

  • 实现必须验证 point on curve。
    • 



3. Side channel：


    

  • Timing、power analysis。
    • 

  • 现代实现 constant-time。
    • 



4. ECDSA k 重用 / 可预测：


    

  • Sony / Bitcoin 案例。
    • 

  • 用 RFC 6979 deterministic k 或转 Ed25519。
    • 



5. Twist attack：


    

  • 攻击者用 twist of curve。
    • 

  • Curve25519 设计天然 twist-secure。
    • 



选择推荐
Key exchange：X25519（TLS 1.3 默认）或 P-256。


签名：Ed25519（新部署）或 ECDSA P-256（兼容）。


避免：自定义曲线、参数不透明的曲线、ECDSA 不当 RNG。


小结
Diffie-Hellman 1976 是公钥密码学第一篇论文——双方公开信道协商共享 secret，K = g^(ab) mod p，安全依赖 DLP。CDH（计算）vs DDH（决策）假设。纯 DH 不抗 MITM——需 + 认证（签名 DH 或 PKI）。Elliptic Curve（1985）把 DH 与签名搬到 elliptic curve 群——同等安全级别 key 短得多（256 bit ECC ≈ 3072 bit RSA），因为 ECDLP 没有亚指数算法。曲线方程 y² = x³ + ax + b (mod p)，定义点加法与标量乘法。标准曲线——NIST P-256/384/521、Curve25519（X25519 / Ed25519，Bernstein 设计 transparent）、brainpool。X25519 是 TLS 1.3 默认 ECDH。Ed25519 是现代签名——deterministic（无 RNG 风险）、极快、64 byte。ECDSA 致命弱点是 k 重用 / 可预测——Sony PS3 与 Bitcoin Android RNG bug 历史案例。Quantum 威胁——Shor 算法破 ECC，需 ~ 2000-3000 logical qubits，post-quantum hybrid（X25519 + ML-KEM）已部署。常见攻击——弱 curve、invalid curve、side channel、ECDSA RNG 失败、twist。选择推荐——X25519 + Ed25519 现代默认，P-256 / ECDSA 兼容。一个简单的检验：你能解释为什么 256 bit ECC ≈ 3072 bit RSA？如果不能，DLP 与 ECDLP 算法复杂度差异还需巩固。ECC 让公钥密码进入移动 / IoT / 区块链时代——key 短、签名快、移动设备友好，是 RSA 的现代继承者，直到 post-quantum 时代再次变革。
