现代协议与零知识证明

核心概念

现代密码学正经历"第二次革命"——zero-knowledge proof 让你证明知道某秘密但不透露秘密、Multi-Party Computation 让多方协作计算但都不知对方输入、Homomorphic Encryption 让密文上直接计算、Threshold Cryptography 让 N-of-M 多方持私钥不必聚合。这些技术让以前理论上不可能的应用成为现实——zk-rollup 给以太坊带来 100x 吞吐、Apple Private Compute Cloud 让 server 不知用户输入、Worldcoin 用 zero-knowledge 验证身份、Signal 用 Sealed Sender 让 server 不知谁发给谁。本节介绍这些"高级密码学原语"——zk-SNARK / zk-STARK、MPC、FHE、threshold signature、私密信息检索（PIR）、它们的工程化应用与限制。

技术 用途 性能 部署成熟度
zk-SNARK 简洁证明 Verify ms 级 Production
zk-STARK 不需可信 setup Proof 较大 Production
Bulletproofs Range proofs 中 Production
MPC 多方安全计算 慢（10x-1000x） Niche
FHE 密文计算 极慢（10000x） 研究 + 早期

Zero-Knowledge Proof

定义：证明者 P 让验证者 V 相信"我知道秘密 x 满足 R(x, y)"——但 V 不学到任何关于 x 的信息（除了 R(x, y) 真）。

三个性质：

  1. Completeness：x 满足 R → V 接受。
  2. Soundness：x 不满足 R → V 拒绝（除可忽略概率）。
  3. Zero-Knowledge：V 不学到 x 任何信息。

经典例子（Ali Baba 洞穴）：

  • 洞穴有 A、B 两支（左右环路）中间有密门。
  • P 说"我知道密门密码"。
  • V 在洞口等。
  • P 进洞随机走 A 或 B。
  • V 喊"从 A 出"或"从 B 出"。
  • 如果 P 真知道密码 → 任意从 A 或 B 出。
  • 如果 P 不知道 → 50% 概率失败。
  • 重复 N 次 → 错的概率 2^(-N)。

实战：

  • zk-SNARK / zk-STARK 把这种 interactive 协议 compile 成 non-interactive 证明。
  • 一个 ~1 KB 证明可证明任意 NP 陈述。

zk-SNARK

SNARK：Succinct Non-interactive Argument of Knowledge。

特点：

  • Succinct：证明很小（~ 200 byte）、验证快（~ ms）。
  • Non-interactive：单一证明，不需多轮交互。
  • 可信 setup：需要 trusted setup ceremony（一次性，随后不需）。

工程化：

  • Circom + snarkjs：DSL 描述 circuit + 自动生成证明。
  • Halo2、PLONK：第二代 SNARK，避免 per-circuit setup。

应用：

  • Zcash（2016）：private transaction（隐藏 sender / receiver / amount）。
  • zk-rollup（2020+）：Ethereum L2，把 1000 transaction 压缩成 1 个 SNARK 提交主链。Polygon zkEVM、zkSync、Scroll。
  • Login：用 zk-SNARK 证明"我知道密码 hash 对应的密码"——server 不存密码也能验证。

zk-STARK

STARK：Scalable Transparent Argument of Knowledge。

与 SNARK 区别：

  • Transparent：不需要 trusted setup。
  • Scalable：证明时间 quasi-linear（vs SNARK 准线性）。
  • 后量子：基于 hash（不依赖 elliptic curve），quantum-secure。
  • Proof 较大：~ 100 KB（vs SNARK 200 byte）。

应用：

  • StarkNet（Ethereum L2）：用 STARK rollup。
  • StarkEx：dYdX、ImmutableX 用。

Trade-off：

  • SNARK：小证明、需 setup、量子脆弱。
  • STARK：大证明、不需 setup、量子安全。
Multi-Party Computation（MPC）
定义：N 方各持 input x_i，希望共同计算 f(x_1, ..., x_n)，但每方只知 f 与自己 input。


经典例子：


    

  • N 个亿万富翁想知道谁最有钱，但都不愿透露具体财产 → MPC。
    • 

  • N 个医院想训练 ML model on combined data，但不能共享 patient data → MPC。
    • 



技术：


    

  • Yao's Garbled Circuit：两方协议。
    • 

  • GMW / SPDZ：多方协议。
    • 

  • Secret Sharing：把 input split 给 N 方，运算 share。
    • 



实战部署：


    

  • Private Set Intersection（PSI）：双方求 intersection 不暴露集合。
    • 

  • Apple Private Compute Cloud（2024）：iCloud 的 LLM 推理，server 不学用户 prompt。
    • 

  • Threshold signing：MPC 实现 N-of-M signing。
    • 

  • 联邦学习 + MPC：多医院协作 ML。
    • 



性能：


    

  • 简单运算（加法 / 比较）：通信开销 vs 单机 ~ 10x。
    • 

  • 复杂运算（神经网络推理）：~ 100-1000x 慢。
    • 



Homomorphic Encryption（FHE）
定义：密文上直接计算——Enc(a) ⊕ Enc(b) = Enc(a + b)。


类型：


    

  • Partially Homomorphic：仅 + 或 ×。RSA、ElGamal。
    • 

  • Somewhat Homomorphic：有限次运算后 noise 太大。
    • 

  • Fully Homomorphic（FHE）：任意次运算。Gentry 2009 首次构造。
    • 



关键技术：


    

  • Bootstrapping：refresh ciphertext noise。
    • 

  • Lattice-based：基于 LWE / RLWE。
    • 



库：


    

  • Microsoft SEAL、HElib、TFHE-rs、Concrete。
    • 



应用：


    

  • Encrypted ML：server 计算密文上的 model inference，不知 plaintext。
    • 

  • PIR（Private Information Retrieval）：用户查询数据库 server 不知查什么。
    • 

  • Zama Concrete ML：支持 FHE 的 ML library。
    • 



性能：


    

  • 单次加法：~ 1ms。
    • 

  • 神经网络推理：当前 ~ 10000x 慢于明文。
    • 

  • 实用化仍需 5-10 年硬件 + 算法进步。
    • 



Threshold Cryptography
定义：N-of-M 私钥——任意 N 把 share 协作可签名 / 解密，少于 N 不行。


经典构造：


    

  • Shamir Secret Sharing：把 secret 分成 M 份，任 N 份重构。
    • 

  • Threshold ECDSA：MPC 实现 N-of-M ECDSA 签名。
    • 

  • BLS threshold：BLS 签名天然支持。
    • 



应用：


    

  • Cryptocurrency 钱包：Fireblocks、Lit Protocol 用 MPC 钱包。
    • 

  • CA threshold key：Root CA 私钥分发给多人，需 N 人 quorum 才能签发。
    • 

  • DKG（Distributed Key Generation）：M 方共同生成无单点的私钥。
    • 



vs 传统多签：


    

  • 传统多签（Bitcoin multisig）：on-chain N 个签名。
    • 

  • Threshold：on-chain 1 个签名，off-chain MPC 协作。
    • 

  • Threshold 更 private（链上看不到 N-of-M 结构）。
    • 



Private Information Retrieval（PIR）
定义：客户端查询 database server，server 不知客户端查的是什么。


方案：


    

  • Trivial PIR：server 把整个 DB 发给客户端。
    • 

  • Single-server PIR：用 FHE 让 server 在加密 query 上计算。
    • 

  • Multi-server PIR：多个不 collude 的 server。
    • 



应用：


    

  • 私密 DNS 查询：用户查 DNS 不让 ISP 知道。
    • 

  • 私密 search：搜索引擎不知用户查什么。
    • 

  • 联系人发现：Signal 用 ORAM-like 让 server 不知用户查谁。
    • 



性能：仍是研究阶段，100MB DB 查一次需 ~ 秒。


现代协议案例
1. Signal Sealed Sender：


    

  • Signal server 不知谁发消息给谁。
    • 

  • 用 group element 加密 sender identity。
    • 

  • Server 只知"有人发给 X"，不知 sender。
    • 



2. Apple Private Relay（iCloud+）：


    

  • 两层 proxy，第一不知 destination，第二不知 source。
    • 

  • 用 Oblivious HTTP（OHTTP）协议。
    • 

  • 等价 Tor 但商业化。
    • 



3. WorldCoin Iris ZKP：


    

  • 用 zk-SNARK 证明"我是 unique human"。
    • 

  • Server 不学习 iris biometric。
    • 

  • Privacy-preserving identity。
    • 



4. Ethereum zk-rollup：


    

  • 1000 transaction 在 L2 执行。
    • 

  • 生成 zk-SNARK 证明所有 transaction 合法。
    • 

  • 提交主链一个 SNARK。
    • 

  • L2 吞吐 100x 主链。
    • 



5. Apple PCC（Private Compute Cloud）：


    

  • iCloud LLM 推理。
    • 

  • 用户 prompt 加密上传。
    • 

  • Server 在 trusted enclave + MPC + 远程证明。
    • 

  • Apple 不知用户 prompt。
    • 



量子计算的影响
zk-SNARK（基于 elliptic curve）：


    

  • Shor 算法破。
    • 

  • 需 post-quantum 重设计（lattice-based）。
    • 



zk-STARK（基于 hash）：


    

  • 量子安全。
    • 

  • 长期可用。
    • 



MPC：


    

  • 大部分协议需要密码学原语（加密 / 签名）。
    • 

  • 升级 underlying 原语后量子安全。
    • 



FHE（lattice-based）：


    

  • 天然量子安全。
    • 

  • post-quantum era 的核心技术。
    • 



未来趋势
1. zkVM：


    

  • 通用 VM 上的 zk 证明。
    • 

  • 任意程序可生成 zk-SNARK。
    • 

  • RISC0、SP1。
    • 



2. Verifiable computing：


    

  • Cloud server 计算后给客户端 zk 证明结果正确。
    • 

  • 不需重计算就 verify。
    • 



3. PCC（Privacy-Preserving Compute）：


    

  • MPC + FHE + TEE 组合。
    • 

  • AI 推理不暴露用户数据。
    • 



4. Decentralized identity：


    

  • zk + DID + verifiable credentials。
    • 

  • 用户控制自己 identity。
    • 



5. Post-quantum crypto：


    

  • NIST 2024 标准化 ML-KEM / ML-DSA。
    • 

  • 5-10 年完全替换 RSA / ECC。
    • 



工程实战建议
1. 不自实现：


    

  • 用经过审计的库（snarkjs、Circom、libsodium、Concrete）。
    • 



2. 性能优先量化：


    

  • zk-SNARK 验证 ms，证明生成秒-分。
    • 

  • MPC 通信开销大。
    • 

  • FHE 极慢——只在 absolutely 必要时用。
    • 



3. 设计 trade-off 明确：


    

  • Privacy ↔ performance。
    • 

  • Trustless ↔ user experience。
    • 



4. 监控 advance：


    

  • 该领域 6 个月一变。
    • 

  • 关注 ZK Summit、Real World Crypto。
    • 



小结
现代协议是密码学的"第二次革命"——zero-knowledge proof / MPC / FHE / threshold cryptography 让以前不可能的应用成为现实。Zero-knowledge 三性质 completeness + soundness + zero-knowledge。zk-SNARK（SNARK = succinct + non-interactive）证明 200 byte 验证 ms 级，需 trusted setup，应用 Zcash / zk-rollup（Polygon / zkSync）。zk-STARK 不需 setup + 后量子 + scalable，proof 100 KB 较大，应用 StarkNet。MPC 让 N 方协作计算不暴露 input——PSI、Apple PCC、threshold signing、联邦学习。FHE 密文上直接计算（lattice-based 量子安全），当前 10000x 慢实用化需 5-10 年。Threshold cryptography N-of-M 私钥（Shamir secret sharing、threshold ECDSA、BLS threshold），应用 Fireblocks / Lit / CA。PIR 客户端查 DB server 不知查什么，仍研究阶段。现代部署案例——Signal Sealed Sender、Apple Private Relay、WorldCoin Iris ZKP、Ethereum zk-rollup、Apple PCC。Quantum 影响——zk-SNARK 量子脆需重设计、zk-STARK 量子安全、FHE 天然量子安全。未来趋势——zkVM、verifiable computing、PCC、decentralized identity、post-quantum crypto。工程建议——不自实现、量化性能、明确 trade-off、监控 advance。一个简单的检验：你能解释 "zk-rollup 让以太坊吞吐 100x" 的工作原理？如果不能，zk 应用还需巩固。现代密码学协议是"密码学终结的开始"——以前需要可信第三方（CA、bank、社交平台）的事现在可用纯密码学实现，让"trustless"不只是口号而是工程现实。
