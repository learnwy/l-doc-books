One-Time Pad 一次性密码本

核心概念

One-Time Pad（OTP）是密码学唯一被数学证明 unconditionally secure 的对称密码——只要 key 满足三个条件（真随机、与 plaintext 等长、只用一次），密文不泄露 plaintext 任何信息（perfect secrecy）。Shannon 1949 年在 Communication Theory of Secrecy Systems 中证明这一点，奠定了信息论密码学的基础。OTP 在间谍、军事、外交（莫斯科-华盛顿 hotline）中真实使用过。但 OTP 的实际工程困难（key 分发、key 长度等于消息）让它不实用——这也是 modern symmetric cipher（AES）的研究动机：在"computational security"（计算安全）的妥协下取得 practical security。

维度 OTP AES
安全性证明 信息论 + 数学证明 经验 + 计算复杂度假设
Key 长度 = 消息长度 固定 128/256 bit
Key 重用 永远不能 可以（不同 IV / nonce）
Key 真随机性 必须 必须
实用 几乎不实用 极实用
安全级别 Unconditionally secure Computationally secure

OTP 算法

OTP 极简单：

加密：c = m ⊕ k（XOR）

解密：m = c ⊕ k（XOR）

由于 XOR 的自逆性（a ⊕ a = 0），加密与解密是同一操作。

def otp_encrypt(plaintext_bytes, key_bytes):
    assert len(plaintext_bytes) == len(key_bytes)
    return bytes(p ^ k for p, k in zip(plaintext_bytes, key_bytes))

例：

plaintext: 01001000 01001001 (= "HI")
key:       11010110 10101101 (random)
ciphertext: 10011110 11100100

接收方用相同 key XOR 密文得 plaintext。

Perfect Secrecy 的证明

Shannon 定义：Perfect secrecy——对任意 plaintext m 与 ciphertext c，P(M=m | C=c) = P(M=m)。即看到密文不增加任何关于 plaintext 的信息。

OTP 的证明（直觉）：

  • key 真随机均匀分布在 {0,1}^n 上。
  • 对任意 plaintext m 与任意 ciphertext c，存在唯一一个 key k = m ⊕ c 使 m 加密为 c。
  • 所有 plaintext 在所有 ciphertext 上的概率均匀。
  • 即使攻击者有无限算力，看到 c 也无法 prefer 一个 plaintext over another。

形式化：H(M | C) = H(M)——条件熵等于 prior 熵，密文不泄露信息。

OTP 的三个必要条件

1. Key 必须真随机：

  • 不能用伪随机数生成器（PRNG）。
  • 不能用人类挑选的"随机"。
  • 必须用物理随机源（thermal noise、量子事件、放射性衰变）。

反例：用 std::rand() 生成"key" → 攻击者预测 PRNG state → 全军覆没。

2. Key 必须与 plaintext 等长：

  • 1MB plaintext 需要 1MB key。
  • 不能"扩展"key（扩展破坏均匀性）。

3. Key 永远不能重用：

  • 用同一 key 加密两条消息 → "two-time pad" → 被攻击。

为什么不能重用：若 c1 = m1 ⊕ k, c2 = m2 ⊕ k，则 c1 ⊕ c2 = m1 ⊕ m2。攻击者得到两明文的 XOR——配合频率分析或已知 plaintext 即可还原。

Two-Time Pad 攻击：VENONA

二战后冷战期间美国情报人员发现苏联 KGB 重用 OTP key（生产压力让他们违反协议）。结果：

  • VENONA Project（1943-1980）：美国密码分析家利用重用 key 解密大量苏联间谍通讯。
  • 揭露 Klaus Fuchs（曼哈顿计划核间谍）、Julius and Ethel Rosenberg、Cambridge Five 等。
  • 战略意义巨大——这是 perfect cipher 因为人为 mistake 失败的经典案例。

教训：密码学的安全不仅依赖算法，还依赖正确使用。

OTP 的工程困难

1. Key 分发问题：

  • 1MB 消息需要 1MB key。
  • key 必须通过 secure channel 提前传输。
  • 如果有 secure channel 传 key，为什么不直接传消息？
  • 实际方案：信使（diplomatic pouch）、提前生成大量 key（可能用 years）。

2. Key 存储：

  • key 必须 secret 且 protected。
  • 物理介质（pad of paper、micro-film）。
  • 数字介质有泄露风险。

3. Key 销毁：

  • 用过的 key 必须立即销毁（"one-time"）。
  • 物理 OTP（小本子）烧掉、digital OTP secure delete。

4. Key 同步：

  • 双方 key 必须严格按顺序使用。
  • 失序导致解密失败。
OTP 的真实历史使用
1. 莫斯科-华盛顿 hotline（1963-）：


    

  • 古巴导弹危机后建立。
    • 

  • 用 OTP 保密。
    • 

  • 双方都信任 perfect secrecy。
    • 



2. 苏联间谍（VENONA 之前）：


    

  • 用 OTP（一次性密码本）传递情报。
    • 

  • 重用 key 让美国破解。
    • 



3. 二战盟军特别行动：


    

  • SOE（Special Operations Executive）特工用 OTP 与英国通讯。
    • 

  • key 印在 silk handkerchief 上（薄、易藏、易销毁）。
    • 



4. 现代外交：


    

  • 部分国家仍用 OTP 处理 top-secret 通讯。
    • 



OTP 与现代 Stream Cipher
现代 stream cipher（ChaCha20、AES-CTR）可看作"OTP 的实用版"：


    

  • 用 short key（256 bit）+ counter / nonce 通过 PRF 生成 long key stream。
    • 

  • key stream 不是真随机，但 computationally indistinguishable from random。
    • 

  • 与 plaintext XOR（同 OTP）。
    • 



妥协：


    

  • OTP：unconditionally secure（信息论）。
    • 

  • Stream cipher：computationally secure（依赖计算困难假设）。
    • 



Trade-off：


    

  • OTP key 长度 = 消息——不实用。
    • 

  • Stream cipher key 256 bit——任意长消息——实用但 computational security。
    • 



实际上，绝大多数应用 computational security 已 sufficient。


量子计算对 OTP 的意义
量子计算威胁 RSA / ECC（Shor 算法可分解大整数）但不威胁 OTP——OTP 是 information-theoretic secure，与计算能力无关。


未来 post-quantum 时代，OTP 仍然有效——只要 key 真随机、等长、一次使用。


OTP 的工程教训
1. Perfect security 是 minimal possible：


    

  • 没有 cipher 比 OTP 更安全。
    • 

  • 但 OTP 不实用。
    • 



2. Key 管理是密码学的核心难题：


    

  • OTP 把所有 difficulty 推到 key management。
    • 

  • 现代 cipher 用短 key + 数学结构，但 key management 仍是挑战。
    • 



3. 正确使用比算法更重要：


    

  • VENONA 案例：完美 cipher 因 key 重用失败。
    • 

  • 现代密码学：90% 漏洞是实现 / 使用错误，不是算法。
    • 



4. Trade-off 是密码学本质：


    

  • Security ↔ usability。
    • 

  • Information-theoretic ↔ computational。
    • 

  • 长 key ↔ 短 key。
    • 



5. 真随机的难度：


    

  • 软件 PRNG 几乎都不够 random for crypto。
    • 

  • 必须用 OS-provided CSPRNG（Linux /dev/urandom、macOS arc4random）。
    • 

  • 安全 keys 还要用 HSM（hardware security module）。
    • 



小结
One-Time Pad 是密码学唯一 unconditionally secure 的对称密码——Shannon 1949 信息论证明。算法极简——c = m ⊕ k（XOR）。三个必要条件——key 真随机、等长、一次使用。Perfect secrecy 形式化——P(M=m | C=c) = P(M=m)，看到密文不增加任何 plaintext 信息。Two-time pad 攻击——重用 key 时 c1 ⊕ c2 = m1 ⊕ m2 暴露明文异或。VENONA Project 利用苏联重用 key 解密大量间谍通讯，揭露 Klaus Fuchs 等。OTP 工程困难——key 分发（与 plaintext 等长）、key 存储、key 销毁、key 同步。真实使用——莫斯科-华盛顿 hotline、苏联间谍、SOE 二战、现代外交。Stream cipher（ChaCha20、AES-CTR）是 OTP 的实用版——用短 key + counter 生成 PRF key stream，妥协为 computational security。量子计算不威胁 OTP（信息论 secure）但威胁 RSA / ECC。工程教训——perfect security 是 minimum possible 但不实用、key management 是核心难题、正确使用比算法更重要（VENONA）、trade-off 是密码学本质、真随机难度（必须用 OS CSPRNG）。一个简单的检验：你能解释为什么"用伪随机数生成 OTP key"破坏了 perfect secrecy？如果不能，OTP 与 stream cipher 区别还没真正理解。OTP 是密码学的"理论上限"——所有现代 cipher 都是在 unconditional security 与 practical usability 间寻找最佳折中。
