流密码

核心概念

Stream Cipher（流密码）把 plaintext 看作 bit / byte 流，与同样长的 key stream 逐位 XOR——可看作"OTP 的实用版"，key stream 不再是真随机而是密码学伪随机序列（CSPRNG）。Stream cipher 的优势是简单（XOR）、快（无需 padding）、低延迟（每个 byte 立即输出）、constant-time（不依赖 cache lookup 的 S-box）。代表算法是 Salsa20 / ChaCha20（DJB 设计、TLS 1.3 / QUIC / WireGuard 选用）。RC4（曾经主流）已弃用。Block cipher 在 CTR 或 OFB 模式下也表现为 stream cipher——AES-CTR 是这种"hybrid"。本节介绍 stream cipher 的设计、key stream 生成、ChaCha20 内部、与 block cipher 对比、安全使用规则。

算法 Key 大小 Nonce 速度 状态
RC4 40-2048 无 中 已弃用（弱）
Salsa20 256 bit 64 bit 快 学术 + 实战
ChaCha20 256 bit 96 bit 快 TLS / QUIC 主力
AES-CTR 128/256 96 bit 极快（AES-NI） 实战

Stream Cipher 的两种类型

1. Synchronous Stream Cipher（同步流密码）：

  • key stream 仅依赖 key 与位置（不依赖 plaintext）。
  • 加密：c_i = m_i ⊕ k_i。
  • 解密：m_i = c_i ⊕ k_i。
  • 优势：bit error 不传播（错一 bit 影响一 bit）。
  • 缺点：丢失 sync 后无法解密。
  • 例：ChaCha20、AES-CTR。

2. Self-Synchronizing Stream Cipher（自同步流密码）：

  • key stream 依赖前 N 个 ciphertext bit。
  • 优势：丢失 sync 自恢复。
  • 缺点：bit error 传播 N bit。
  • 例：CFB 模式。

绝大多数现代应用用 synchronous（更简单更安全）。

RC4 的兴衰

RC4（1987 by RSA Security）曾是最广泛部署的 stream cipher——HTTPS、WEP、SSL/TLS 用过几十年：

优势：

  • 极快（软件实现）。
  • 简单（200 行 C 代码）。

致命弱点：

  • 早期 byte 有 bias——前 256 byte 不应使用（RC4-drop[256]）。
  • 2013 RC4 多个攻击发表（RC4 NoMore 等）。
  • TLS 1.3（2018）完全去除 RC4。
  • 2015 RFC 7465 forbid RC4 in TLS。

教训：

  • 算法即使 20 年无攻击也可能被新方法攻破。
  • 持续学术审查至关重要。
  • "曾经安全"不等于"现在安全"。

ChaCha20 算法

ChaCha20（2008 by Daniel J. Bernstein）是 Salsa20 的改进版。设计目标：

  • 256 bit key。
  • 高速软件实现（无需硬件加速）。
  • Constant-time（防 cache timing 攻击）。
  • 简洁（约 100 行 C）。

内部状态：4×4 的 32 bit word matrix（512 bit 总共）：

constant constant constant constant   ← "expand 32-byte k"
key      key      key      key
key      key      key      key
counter  nonce    nonce    nonce

核心操作：ARX——Add（mod 2^32）、Rotate（循环左移）、XOR。不依赖任何 lookup table——天然 constant-time。

Quarter Round：4 个 ARX 操作，更新 4 个 word。

ChaCha20 = 20 rounds = 10 double rounds——每 double round 包括 4 个 column quarter rounds + 4 个 diagonal quarter rounds。

Key stream 生成：

def chacha20_block(key, nonce, counter):
    state = init_state(key, nonce, counter)  # 4x4 matrix
    working = state.copy()
    for _ in range(10):  # 20 rounds = 10 double
        # Column rounds
        quarter_round(working, 0, 4, 8, 12)
        quarter_round(working, 1, 5, 9, 13)
        quarter_round(working, 2, 6, 10, 14)
        quarter_round(working, 3, 7, 11, 15)
        # Diagonal rounds
        quarter_round(working, 0, 5, 10, 15)
        quarter_round(working, 1, 6, 11, 12)
        quarter_round(working, 2, 7, 8, 13)
        quarter_round(working, 3, 4, 9, 14)
    return [(working[i] + state[i]) & 0xffffffff for i in range(16)]

加密：plaintext ⊕ key stream。

Counter mode：每 64 byte 一个 block，counter 递增——可生成最多 2^32 × 64 byte = 256 GB 的 key stream（之前必须换 nonce 或 key）。

ChaCha20-Poly1305

ChaCha20 单独不提供完整性。配合 Poly1305 MAC 形成 ChaCha20-Poly1305 AEAD（Authenticated Encryption with Associated Data）：

1. Poly1305：

  • 基于 prime 2^130 - 5 上的 polynomial evaluation。
  • 给定 key 与 message，输出 16 byte MAC。
  • 极快（与 ChaCha20 同步）。

2. AEAD：

  • 加密 + 完整性 + associated data 完整性（不加密但完整）。
  • 现代密码学的 gold standard。

3. 使用：

from cryptography.hazmat.primitives.ciphers.aead import ChaCha20Poly1305

key = ChaCha20Poly1305.generate_key()
nonce = os.urandom(12)
chacha = ChaCha20Poly1305(key)
ct = chacha.encrypt(nonce, plaintext, associated_data)
pt = chacha.decrypt(nonce, ct, associated_data)
Stream Cipher 的安全使用规则
1. Key 永远不重用 + nonce 不重用：


    

  • 同 key + 同 nonce → 同 key stream → two-time pad 攻击。
    • 

  • 致命错误。
    • 



2. Nonce 选择：


    

  • 推荐 96 bit random nonce（ChaCha20-Poly1305 标准）。
    • 

  • 或 counter（per-key 严格递增）。
    • 

  • 不要用 timestamp（精度问题、回溯）。
    • 



3. Key 通过 KDF derive：


    

  • 不直接用 password。
    • 

  • 用 HKDF / PBKDF2 / scrypt / Argon2。
    • 



4. 长消息分 chunk：


    

  • AES-GCM 单 message 限 64 GB（96 bit nonce）。
    • 

  • ChaCha20-Poly1305 单 message 限 256 GB。
    • 

  • 超过用多 chunk + 不同 nonce。
    • 



5. AEAD > 单纯加密：


    

  • 永远用 AES-GCM 或 ChaCha20-Poly1305。
    • 

  • 不用 raw stream cipher。
    •

量子计算的影响
Grover 算法可加速 brute force key search 从 2^N 到 2^(N/2)：


    

  • ChaCha20-256 在 quantum 下变 2^128（仍强）。
    • 

  • AES-256 同样。
    • 

  • AES-128 变 2^64（不够）。
    • 



post-quantum 推荐：用 256 bit key（AES-256 或 ChaCha20-256）。


常见反模式
反模式 1：用 RC4：已弃用 10+ 年。规避：用 ChaCha20 / AES-GCM。


反模式 2：Nonce 重用：同 key + 同 nonce 灾难。规避：random nonce 或 counter。


反模式 3：单纯加密无 MAC：不检测篡改。规避：用 AEAD（Poly1305 / GCM）。


反模式 4：硬编码 key：源码中 hardcode AES key。规避：KMS / 环境变量。


反模式 5：自实现 stream cipher：DON'T ROLL YOUR OWN。规避：用 libsodium / cryptography / OpenSSL。


小结
Stream Cipher 把 plaintext 看作 bit/byte 流与 key stream XOR——可看作"OTP 的实用版"，key stream 是密码学伪随机（CSPRNG）。两类——synchronous（key stream 仅依赖 key + 位置）与 self-synchronizing（依赖前 N ciphertext bit）。RC4 曾主流但 2015 在 TLS 中被禁，2013-2015 多攻击发表。ChaCha20（DJB 2008）是现代主力——256 bit key、ARX 操作（add/rotate/XOR 无 lookup table）、constant-time、20 rounds = 10 double rounds、每 64 byte 一 block 通过递增 counter。ChaCha20-Poly1305 是 AEAD，加密 + 完整性 + associated data 完整性。安全规则——key + nonce 永不重用、推荐 96 bit random nonce、KDF derive key、长消息分 chunk、AEAD > 单纯加密。Stream vs Block——stream 无 padding、不传播错误、移动优；block 有硬件加速（AES-NI 50x）。现代部署——ChaCha20-Poly1305 用于 TLS 1.3 / WireGuard / QUIC / WPA3 / Signal / SSH；AES-GCM 用于 TLS 1.2/1.3 / IPsec / 磁盘加密。Quantum 下 256 bit key（AES-256 / ChaCha20-256）仍强。常见反模式——RC4、nonce 重用、无 MAC、硬编码 key、自实现。一个简单的检验：你能解释为什么"ChaCha20 不需要 padding 但 AES-CBC 需要"？如果不能，stream vs block 区别还需巩固。Stream cipher 让加密变成"廉价的字符串异或"——简单 + 快 + 安全（在 AEAD 框架下），是现代加密协议的主力。
