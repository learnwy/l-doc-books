Block Cipher 与 AES

核心概念

Block Cipher 是把固定长度（block）的明文一起加密的对称密码——典型 block 大小 64 bit（DES）或 128 bit（AES）。AES（Advanced Encryption Standard）是 NIST 2001 年标准化的 Rijndael 算法，取代 1977 年的 DES，成为当代加密的事实标准——HTTPS、磁盘加密（FileVault、BitLocker）、Wi-Fi WPA2/3、TLS、SSH 都用 AES。本节介绍 block cipher 的设计原则（confusion + diffusion）、AES 的内部结构（SubBytes / ShiftRows / MixColumns / AddRoundKey 四步、10/12/14 轮）、为什么 AES 比 DES 安全、AES-NI 硬件加速。

算法 Block size Key size 轮数 状态
DES 64 bit 56 bit 16 已弃用（弱）
3DES 64 bit 168 bit (有效 112) 48 已弃用（慢）
AES-128 128 bit 128 bit 10 当代主力
AES-192 128 bit 192 bit 12 高安全场景
AES-256 128 bit 256 bit 14 高安全 + 长寿
ChaCha20 -（流） 256 bit 20 移动端 / TLS

Block Cipher 的设计原则

Shannon 1949 年提出两个设计原则：

1. Confusion（混淆）：

  • ciphertext 的每个 bit 应是 key 的复杂函数。
  • 改变 key 1 bit 应改变 ciphertext 大约一半 bits。
  • 实现：substitution box（S-box）——非线性查表。

2. Diffusion（扩散）：

  • plaintext 1 bit 改变应改变 ciphertext 大约一半 bits（avalanche effect）。
  • 实现：permutation、column mixing。

S-Box（Substitution Box）：非线性 lookup table，提供 confusion。AES S-box 是 8 bit → 8 bit 的查表，基于 GF(2^8) 中的 multiplicative inverse。

Permutation：bit / byte 重排，提供 diffusion。

SPN（Substitution-Permutation Network）：S-box + Permutation 反复迭代——AES 的结构。

Feistel network：DES 的结构——把 block 切两半，反复异或加密。

AES 算法概览

AES 把 128 bit block 看作 4×4 的 byte matrix（state）：

[a00 a01 a02 a03]
[a10 a11 a12 a13]
[a20 a21 a22 a23]
[a30 a31 a32 a33]

每轮做 4 个操作：

1. SubBytes：每个 byte 用 S-box 替换（confusion）。

2. ShiftRows：每行循环左移不同距离——row 0 不动、row 1 移 1、row 2 移 2、row 3 移 3（diffusion）。

3. MixColumns：每列乘 GF(2^8) 上的固定 matrix（diffusion）。

4. AddRoundKey：state ⊕ round key（key mixing）。

最后一轮省略 MixColumns（不影响安全，简化解密）。


轮数：


    

  • AES-128：10 轮。
    • 

  • AES-192：12 轮。
    • 

  • AES-256：14 轮。
    • 



Key Schedule
AES 用 master key 生成 N+1 个 round key（每个 128 bit）。AES-128 生成 11 个 round key（initial + 10 rounds）。


Key expansion 用 master key 反复 substitution + 异或扩展，确保每个 round key 不同。


AES 的安全性
AES 自 2001 年标准化，没有任何 academic break——25 年的 best attack 仍接近 brute force：


    

  • AES-128：最佳已知攻击约 2^126（vs brute force 2^128）。
    • 

  • AES-256：最佳已知攻击约 2^254（vs brute force 2^256）。
    • 



brute force AES-128 不可行：


    

  • 假设全球所有计算机（≈ 10^9 cores × 10^9 GHz）。
    • 

  • AES-128 需要 ≈ 10^21 年穷举（universe 年龄 1.4 × 10^10 年）。
    • 



AES-256 防 quantum：


    

  • Grover 算法可把暴力穷举从 2^N 加速到 2^(N/2)。
    • 

  • AES-128 在 quantum 下变成 2^64（弱）。
    • 

  • AES-256 在 quantum 下变成 2^128（仍强）——这是 post-quantum 推荐 AES-256 的原因。
    • 



AES 与 DES 对比
DES（1977）已弃用——为什么：


1. Key 太短：


    

  • DES key 56 bit。
    • 

  • 1998 年 EFF 用 $250k 设备 56 小时穷举。
    • 

  • 现代 GPU 几秒。
    • 



2. 替代品：


    

  • 3DES：用 DES 三次（K1/K2/K3）——慢。
    • 

  • AES：现代标准。
    • 



AES 优势：


    

  • Key 长度灵活（128/192/256）。
    • 

  • Block 大（128 bit vs DES 64 bit），抗 birthday attack。
    • 

  • SPN 结构 vs Feistel——更高效。
    • 

  • 硬件加速（AES-NI）。
    • 



AES-NI 硬件加速
Intel 2010 年引入 AES-NI 指令集——CPU 直接执行 AES round 操作：


    

  • AESENC、AESENCLAST、AESDEC、AESDECLAST：执行单轮加密 / 解密。
    • 

  • AESKEYGENASSIST：加速 key expansion。
    • 

  • AESIMC：inverse mix columns。
    • 



性能：


    

  • 软件 AES-128：~ 100 MB/s。
    • 

  • AES-NI：~ 5 GB/s（50x）。
    • 



ARM、AMD 也支持类似指令。现代 CPU 几乎都有硬件 AES。


ChaCha20 作为 AES 替代
某些场景 ChaCha20 优于 AES：


1. 无 AES-NI 硬件：


    

  • 移动设备（早期 ARM）。
    • 

  • ChaCha20 软件实现快（用 ARX——add / rotate / xor）。
    • 



2. Constant-time 实现：


    

  • AES 软件实现可能有 cache timing 攻击（S-box lookup）。
    • 

  • ChaCha20 设计为 constant-time。
    • 



3. TLS 1.3 默认：


    

  • TLS 1.3 cipher suite 包括 ChaCha20-Poly1305。
    • 

  • Google QUIC、WireGuard 用 ChaCha20。
    • 



AES 的常见使用错误
1. ECB 模式：


    

  • ECB 每个 block 独立加密——相同 plaintext 产生相同 ciphertext。
    • 

  • 暴露 pattern（ECB Penguin 经典例子）。
    • 

  • 永远不要用 ECB。
    • 



2. IV 重用：


    

  • CBC、CTR 模式需要 unique IV。
    • 

  • IV 重用泄露信息。
    • 



3. 不验证完整性：


    

  • 单独 AES-CBC / AES-CTR 不检测篡改。
    • 

  • 必须配 MAC 或用 AES-GCM。
    • 



4. 自定义 key derivation：


    

  • 用 SHA-256(password) 当 key——错。
    • 

  • 应用 PBKDF2 / scrypt / Argon2。
    • 



5. 用 password 作 key：


    

  • 直接用 user password 当 AES key——entropy 不够。
    • 

  • 应用 KDF（Key Derivation Function）。
    • 



AES 的实战 API
Python（cryptography library）：


from cryptography.hazmat.primitives.ciphers.aead import AESGCM
import os

key = AESGCM.generate_key(bit_length=256)
nonce = os.urandom(12)
aesgcm = AESGCM(key)
ciphertext = aesgcm.encrypt(nonce, b"Hello", associated_data=None)
plaintext = aesgcm.decrypt(nonce, ciphertext, associated_data=None)
Go（crypto/aes）：


block, _ := aes.NewCipher(key)
gcm, _ := cipher.NewGCM(block)
nonce := make([]byte, gcm.NonceSize())
io.ReadFull(rand.Reader, nonce)
ciphertext := gcm.Seal(nil, nonce, plaintext, nil)
关键：


    

  • 用 AES-GCM（authenticated encryption）。
    • 

  • 用 OS CSPRNG 生成 nonce。
    • 

  • key 用 KDF derive。
    • 

  • 永远不直接用 AES-ECB。
    • 



小结
Block Cipher 把固定长度（block）明文一起加密——AES 是当代标准。Shannon 设计原则——confusion（S-box 混淆 key）+ diffusion（permutation 扩散 plaintext bit）。AES 把 128 bit block 看作 4×4 byte matrix，每轮 SubBytes + ShiftRows + MixColumns + AddRoundKey，AES-128/192/256 分别 10/12/14 轮（最后轮省 MixColumns）。Key schedule 把 master key 扩展为 N+1 个 round key。AES 25 年无 academic break——最佳攻击 2^126（AES-128），暴力穷举不可行。AES-256 在 quantum 下仍 2^128（Grover 加速），是 post-quantum 推荐。AES 比 DES 强在 key 长度、block 大、SPN 结构、硬件加速（AES-NI 50x）。某些场景 ChaCha20 优于 AES（移动、constant-time、TLS 1.3）。常见使用错误——ECB 模式、IV 重用、不验证完整性、自定义 KDF、password 当 key。实战 API——用 AES-GCM（authenticated encryption）、OS CSPRNG nonce、KDF derive key、绝不 ECB。一个简单的检验：你能不查文档说出 AES-128 一轮的 4 个操作？如果不能，AES 内部还需巩固。AES 是密码学工程化的典范——由学术界设计、NIST 标准化、硬件 + 软件全栈支持，让加密成为基础设施而非奢侈品。
