Part V · 安全与密码学 (Security & Cryptography)密码学基础对称密码学运行模式

运行模式

核心概念

Block Cipher（如 AES）只能加密一个 block（16 byte）——加密任意长 plaintext 必须用 mode of operation（运行模式）把 plaintext 切 block 后用某种方式串联加密。不同模式有不同安全性、性能、错误传播特性——选错模式让 AES 变成 "AES Penguin"（ECB 暴露 pattern）。本节介绍 5 种主要模式（ECB、CBC、CFB、OFB、CTR）与现代 AEAD 模式（GCM、CCM、SIV、OCB），分析它们的优缺点、安全使用规则、为什么 GCM / SIV 是现代默认。

模式 并行加密 并行解密 需要 padding IV / nonce 完整性 推荐
ECB 是 是 是 无 无 永不
CBC 否 是 是 16 byte IV 无 历史
CFB 否 是 否 16 byte IV 无 历史
OFB 否 否 否 16 byte IV 无 历史
CTR 是 是 否 nonce 无 配 MAC
GCM 是 是 否 96 bit 是 现代默认
SIV 是 是 否 任意 是 nonce 误用安全

ECB（Electronic Codebook）

算法：每个 block 独立加密——c_i = AES(k, m_i)。

致命弱点：相同 plaintext block 产生相同 ciphertext block——暴露 plaintext pattern。

ECB Penguin：加密 Linux 企鹅图像后仍能看到企鹅形状（因为图像有大片相同颜色 = 相同 block）。

永远不要用 ECB——但教科书与某些 legacy 代码仍在用，是漏洞源。

CBC（Cipher Block Chaining）

算法：每个 block 加密前先与前一 block 的 ciphertext 异或：

  • c_0 = AES(k, m_0 ⊕ IV)
  • ci = AES(k, m_i ⊕ c(i-1))

优点：相同 plaintext block 产生不同 ciphertext（因为异或前一 block）。

缺点：

  • 加密必须串行（每 block 依赖前一）。
  • 解密可并行：mi = AES⁻¹(k, c_i) ⊕ c(i-1)。
  • 需要 padding（最后 block 凑够 16 byte，PKCS#7）。
  • 单独 CBC 不提供完整性——必须配 MAC。

Padding Oracle Attack：如果服务器在 padding 错误时 leak 信息（不同 error message 或 timing），攻击者可逐 byte 解密任意 ciphertext（POODLE、Lucky 13）。这就是为什么 CBC + MAC 必须用 "encrypt-then-MAC"。

CFB（Cipher Feedback）
算法：把 block cipher 用作 stream cipher——key stream 是前一 ciphertext 的 AES 加密：


    

  • ks_0 = AES(k, IV)
    • 

  • c_0 = m_0 ⊕ ks_0
    • 

  • ksi = AES(k, c(i-1))
    • 

  • c_i = m_i ⊕ ks_i
    • 



优点：


    

  • 不需 padding。
    • 

  • 可处理任意长流（不限 block 边界）。
    • 



缺点：


    

  • 加密串行。
    • 

  • Bit error 传播一 block。
    • 

  • 现代不推荐——CTR / GCM 更好。
    • 



OFB（Output Feedback）
算法：key stream 完全独立于 plaintext：


    

  • ks_0 = AES(k, IV)
    • 

  • ksi = AES(k, ks(i-1))
    • 

  • c_i = m_i ⊕ ks_i
    • 



优点：


    

  • 不需 padding。
    • 

  • Bit error 不传播（synchronous stream cipher）。
    • 



缺点：


    

  • 加密 / 解密都串行（ks 链式）。
    • 

  • IV 重用灾难（同 OTP 重用 key）。
    • 

  • 现代不推荐。
    • 



CTR（Counter Mode）
算法：把 counter 加密生成 key stream：


    

  • ks_i = AES(k, nonce ‖ counter_i)
    • 

  • c_i = m_i ⊕ ks_i
    • 



优点：


    

  • 加密 / 解密都可完全并行。
    • 

  • 不需 padding。
    • 

  • 任意位置 random access（解密第 N block 不需要前面）。
    • 

  • 现代推荐（配合 MAC 或用 GCM）。
    • 



关键约束：(key, nonce) 永不重用——重用 = two-time pad。


与 stream cipher 一致：CTR mode 下 AES 等价于 stream cipher。这是 ChaCha20 与 AES-CTR 在协议中可互换的根本。


GCM（Galois/Counter Mode）
算法：CTR 加密 + GHASH MAC——一个 pass 完成 AEAD：


    

  • 加密：用 CTR 模式生成 ciphertext。
    • 

  • 完整性：用 GHASH 在 GF(2^128) 上对 ciphertext + AAD 计算 MAC。
    • 

  • 输出：ciphertext + 16 byte tag。
    • 



优点：


    

  • 单一算法 = 加密 + 完整性。
    • 

  • 高速（CTR 并行 + GHASH 也可并行）。
    • 

  • 硬件加速（PCLMULQDQ 加速 GHASH）。
    • 

  • TLS 1.2/1.3 默认。
    • 



关键约束：


    

  • (key, nonce) 永不重用——重用比 CTR 更糟（不仅泄露明文还能 forge MAC）。
    • 

  • 推荐 96 bit nonce（保证 nonce uniqueness 在 2^32 messages）。
    • 

  • 单 message ≤ 64 GB。
    • 



实战 API：


from cryptography.hazmat.primitives.ciphers.aead import AESGCM

key = AESGCM.generate_key(bit_length=256)
nonce = os.urandom(12)
aesgcm = AESGCM(key)
ct = aesgcm.encrypt(nonce, plaintext, associated_data=None)
pt = aesgcm.decrypt(nonce, ct, associated_data=None)
SIV（Synthetic IV）
算法：用 plaintext + AAD + key 派生 nonce（不需要外部 nonce）：


    

  • siv = MAC(k, AAD ‖ m)
    • 

  • c = CTR-encrypt(k, m, siv)
    • 

  • 输出 c + siv。
    • 



优点：


    

  • Nonce-misuse resistant——即使重用同 nonce，安全性 degrade gracefully。
    • 

  • 适合 disk encryption、key wrapping。
    • 



缺点：


    

  • 慢于 GCM（两 pass）。
    • 

  • 复杂。
    • 



RFC 5297 标准化——用于 backup、key wrapping、wherever nonce uniqueness 难保证。


OCB（Offset Codebook）
算法：单 pass AEAD，专利问题历史拖累采用，现 free：


    

  • 加密 + 完整性单 pass。
    • 

  • 比 GCM 快（无 GHASH）。
    • 

  • 较少部署。
    • 



RFC 7253——但实战用得少。


选择推荐
现代默认：


    

  1. AES-GCM（有 AES-NI 硬件）：TLS、API、文件加密。
    2. 

  2. ChaCha20-Poly1305（无 AES-NI）：移动、嵌入式。
    3. 

  3. AES-SIV：nonce uniqueness 难保证场景（备份、KMS key wrapping）。
    4. 



永远不要：


    

  • ECB。
    • 

  • 单纯 CBC / CTR / CFB / OFB（无 MAC）。
    • 

  • 自实现 mode。
    • 



Padding 与 Padding Oracle 攻击
CBC / ECB 需要 padding 凑够 block 大小。常用 PKCS#7：


    

  • 缺 N byte → 填 N 个 byte 值为 N。
    • 

  • 例：缺 5 byte → 填 0x05 0x05 0x05 0x05 0x05。
    • 

  • 完整 block 时 → 填 16 个 0x10。
    • 



Padding Oracle Attack：


    

  • 服务器 decrypt 后检查 padding。
    • 

  • 错 padding 时返回 error（vs MAC 错的不同 error）。
    • 

  • 攻击者通过反复修改 ciphertext 观察 error 来逐 byte 还原 plaintext。
    • 



著名案例：


    

  • POODLE（2014）SSL 3.0 CBC 攻击。
    • 

  • Lucky 13（2013）TLS CBC 攻击。
    • 



防御：


    

  • Encrypt-then-MAC（先加密再 MAC，验证 MAC 后再 decrypt）。
    • 

  • 用 AEAD（GCM / Poly1305）——彻底避免 padding。
    • 



IV 与 Nonce
IV（Initialization Vector）：


    

  • CBC：必须 unpredictable random（否则 chosen plaintext 攻击）。
    • 

  • 16 byte。
    • 

  • 随 ciphertext 传输（不需保密）。
    • 



Nonce（Number used once）：


    

  • CTR / GCM：必须 unique（per key）。
    • 

  • 推荐 96 bit。
    • 

  • 不需 unpredictable（但 unique 必须）。
    • 



两者都不能保密——它们和 ciphertext 一起传输。但都不能重用。


模式选择决策树
小结
Mode of operation 把 block cipher 用于任意长 plaintext。ECB 每个 block 独立——暴露 pattern（ECB Penguin），永不使用。CBC 异或前 block 的 ciphertext——加密串行解密并行，需要 padding，padding oracle 攻击（POODLE、Lucky 13），必须配 MAC。CFB 用作 stream cipher——key stream 是前 ciphertext 加密。OFB key stream 独立——IV 重用灾难。CTR 加密 counter——加密解密都并行、不需 padding、任意 random access。GCM = CTR + GHASH MAC = AEAD——TLS 默认、硬件加速、key+nonce 永不重用。SIV 是 nonce-misuse resistant——适合 nonce uniqueness 难保证场景。OCB 单 pass 但实战用得少。现代默认——AES-GCM（有硬件）、ChaCha20-Poly1305（无硬件 / 移动）、AES-SIV（nonce uniqueness 难）。永远不要——ECB、单纯 CBC/CTR/CFB/OFB（无 MAC）、自实现 mode。Padding（PKCS#7）配合 padding oracle 攻击是历史多个 TLS CVE 的根源——AEAD 彻底解决。IV vs nonce——CBC 的 IV 必须 unpredictable random，CTR/GCM 的 nonce 必须 unique（不需 unpredictable）。一个简单的检验：你能解释为什么"AES-CBC 加密 ECB Penguin 不暴露 pattern 但 AES-ECB 暴露"？如果不能，模式区别还没真正理解。Mode of operation 是密码学的"使用层"——选错让最强 cipher（AES）变弱，选对让简单 cipher 也能 secure。
