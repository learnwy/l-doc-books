网格表示

核心概念

网格（Mesh）是三维物体在计算机中最常用的几何表示方式。它由一组顶点（Vertices）、连接顶点的边（Edges）和由边围成的面（Faces）组成。三角形网格是图形硬件和渲染管线的原生支持格式，几乎所有实时渲染的几何数据最终都以三角形网格的形式提交给 GPU。

网格不仅存储几何形状，还携带丰富的属性数据——法线、纹理坐标、颜色、切线等。这些属性在光栅化阶段被插值，传递给片元着色器用于光照和纹理计算。

网格数据的组织方式直接影响 GPU 的缓存效率和渲染性能。

理解网格的存储、拓扑和压缩技术，是图形编程和几何处理的基础。

顶点缓冲与索引缓冲
GPU 渲染使用的网格数据组织为顶点缓冲（Vertex Buffer Object, VBO）和索引缓冲（Index Buffer Object, IBO）两部分。顶点缓冲存储每个顶点的属性数据，索引缓冲存储三角形如何引用顶点。


不使用索引缓冲时，三个顶点定义一个三角形，共享顶点需要被重复存储。对于一个典型的封闭网格，每个顶点平均被约 6 个三角形共享，索引方案可以将顶点数据量减少到约 1/6。


顶点属性有两种布局方式：交错布局（Interleaved / Array of Structures）将一个顶点的所有属性连续存放；分离布局（Separate / Structure of Arrays）将同类属性连续存放。


交错布局的空间局部性更好（一个顶点的所有数据在一个缓存行内），是 GPU 渲染的首选。


交错布局 (AoS):
[pos₁|normal₁|uv₁] [pos₂|normal₂|uv₂] [pos₃|normal₃|uv₃] ...

分离布局 (SoA):
[pos₁|pos₂|pos₃|...] [normal₁|normal₂|normal₃|...] [uv₁|uv₂|uv₃|...]
顶点索引通常使用 16 位或 32 位无符号整数。16 位索引支持最多 65536 个顶点（足够大多数单个 Draw Call），内存带宽消耗仅为 32 位的一半。


网格处理工具通常会将大网格拆分为多个 65K 以内的子网格以使用 16 位索引。


Meshlet 是现代 GPU（Mesh Shader 管线）引入的几何组织单位。一个 Meshlet 包含一小组三角形（通常 64-126 个）和它们引用的顶点（最多 64-256 个），配合紧凑的局部索引。


Meshlet 的设计使得 Mesh Shader 的工作组可以高效地处理一个完整的小型几何块。


Meshlet 的生成是一个网格分区问题。Meshoptimizer 库的 meshopt_buildMeshlets 函数使用贪心算法将三角形分组为 Meshlet，优化目标包括：最小化每个 Meshlet 引用的唯一顶点数（提高顶点复用）、保持空间局部性（相邻三角形尽量在同一 Meshlet 中）。


每个 Meshlet 还会预计算一个包围锥（Bounding Cone），用于 Mesh Shader 中的背面剔除——如果整个 Meshlet 的法线都朝向远离相机的方向，可以直接跳过。


顶点格式优化在不同平台上有不同的最佳实践。移动 GPU 偏好紧凑的顶点格式（如 half-float 位置、int10 法线），因为显存带宽是主要瓶颈。


桌面 GPU 对格式不太敏感但仍受益于减少顶点大小。一个完整的 PBR 顶点（位置 + 法线 + UV + 切线）在优化后可以从 48 字节压缩到 24 字节，将顶点获取带宽减半。


半边数据结构
半边数据结构（Half-Edge Data Structure）是网格编辑和几何算法中最常用的拓扑表示。它将每条边拆分为两条方向相反的半边（Half-Edge），每条半边记录：它的起始顶点、它所属的面、下一条半边（同一面内逆时针方向）和对偶半边（方向相反的另一条半边）。


这种设计使得顶点周围面的遍历、边邻接查询等操作在 O(1) 时间内完成。


半边数据结构的核心引用关系:
HalfEdge {
    vertex:   指向起始顶点
    face:     指向所属面
    next:     同一面内的下一条半边
    twin:     方向相反的对偶半边
}
Vertex { halfedge: 从该顶点出发的一条半边 }
Face   { halfedge: 属于该面的一条半边 }
半边结构的强大之处在于支持 O(1) 的拓扑查询。从一个顶点出发，可以通过反复跟踪 twin→next 遍历该顶点的所有相邻面（称为"一环邻域"或 "1-ring"）；从一个面出发，可以通过 next 指针遍历该面的所有半边和顶点。


半边结构的缺点是内存占用较高——每条边需要存储两个半边对象。


对于纯渲染用途，将半边结构转换为索引三角形列表提交给 GPU；对于需要频繁拓扑修改的场景（如细分、简化、布尔运算），半边结构是最合适的选择。


处理非流形（Non-manifold）几何是半边结构的难点。非流形边（被超过两个面共享的边）或非流形顶点（邻域不构成单个扇形的顶点）无法直接用标准半边表示，需要扩展结构或在预处理阶段拆分。


网格修复（Mesh Repair）是处理真实世界 3D 数据时的常见需求。扫描数据、布尔运算结果和手工建模的网格经常包含各种缺陷：非流形边/顶点、退化三角形（面积为零）、翻转的法线、不连通的组件、自相交等。


自动修复工具（如 MeshFix、libigl 的修复功能）使用一系列启发式规则来检测和修复这些问题，但完美的自动修复仍是一个未解决的难题。


网格简化与 LOD
网格简化（Mesh Simplification）减少三角形数量以降低渲染开销，同时尽量保持视觉外观。层次细节（Level of Detail, LOD）系统根据物体与相机的距离选择不同细节级别的网格——近处使用高精度原始网格，远处使用简化版本。


二次误差度量（Quadric Error Metric, QEM）是最经典的网格简化算法。它将每个顶点关联一个 4×4 对称矩阵（二次误差矩阵），表示该顶点到所有相邻面的距离平方和。


边折叠（Edge Collapse）操作将一条边的两个端点合并为一个新顶点，新顶点的位置通过最小化合并后的二次误差来确定。


边折叠优先级队列:
1. 计算每条边折叠的误差代价
2. 选择代价最小的边执行折叠
3. 更新受影响的相邻边的代价
4. 重复直到达到目标三角形数量
LOD 的切换方式影响视觉体验。离散 LOD 在固定距离阈值处直接切换网格，可能产生可见的跳变（Popping）。混合 LOD 在切换过程中对两个级别进行 Alpha 混合（Dithering），平滑过渡。


连续 LOD（如 Nanite，UE5）使用自适应的三角形级别选择，在屏幕空间保证每个三角形的投影面积接近一个像素，实现无缝的细节过渡。

Nanite（UE5）代表了 LOD 技术的最新进展。它将整个网格组织为 DAG（有向无环图）形式的 Cluster 层级，每帧在 GPU 上通过计算着色器选择每个 Cluster 的最优 LOD 级别。选择标准是屏幕空间的投影误差——当 Cluster 的边折叠误差投影到屏幕上小于一个像素时，使用简化版本。这种逐 Cluster 的自适应选择产生了像素级别的无缝过渡。


网格压缩与传输
网格数据的压缩对于网络传输和存储至关重要。glTF 格式（GL Transmission Format）是 3D 模型的标准传输格式，它使用 JSON 描述场景结构，二进制缓冲区存储几何数据。


Draco 是 Google 开发的网格压缩库，可以将位置数据压缩 5-10 倍。它通过量化（将浮点坐标映射到整数网格）和预测编码（使用平行四边形预测器预测下一个顶点位置，只存储残差）实现高效压缩。


Meshopt 是另一种优化方案，侧重于 GPU 渲染效率。它重新排列顶点和索引的顺序以优化 GPU 的顶点缓存（Post-Transform Cache）——让连续的三角形尽可能共享已变换的顶点，减少重复的顶点着色器调用。典型的缓存优化可以将 ACMR（Average Cache Miss Ratio）从 1.0 降低到 0.6-0.7，相当于节省了 30-40% 的顶点处理开销。


顶点量化是压缩的关键步骤。位置通常可以从 32 位浮点量化到 16 位甚至 11 位整数（配合包围盒偏移和缩放），法线可以用 Oct 编码压缩到 2 个字节，纹理坐标通常 16 位半浮点即可。


这些量化不会产生人眼可见的质量损失，但大幅减少了数据量和显存带宽消耗。


Oct 编码（Octahedral Normal Encoding）是法线压缩的最佳方案。它将单位球上的法线映射到八面体表面，再展开为 2D 正方形。编码只需 2 个分量（通常各用 16 位 snorm），比存储 3 个 float32 节省 83% 的空间。解码在着色器中只需几条指令。


网格格式标准的选择也很重要。glTF 2.0 是实时渲染领域的标准交换格式，支持 PBR 材质、动画、骨骼和扩展机制。USD（Universal Scene Description，Pixar）在影视和 DCC 工具间的交换中占主导地位。FBX 仍然是 DCC 工具导出的常用格式但逐渐被 glTF 替代。对于 Web 场景，glTF + Draco 或 Meshopt 的组合提供最佳的文件大小和加载性能。

小结
    

  • 索引三角形列表是 GPU 渲染的标准格式，索引复用将顶点数据量减少到约 1/6
    • 

  • 交错顶点布局（AoS）提供更好的缓存局部性，是渲染的首选
    • 

  • Meshlet 将网格划分为小型几何块，适配 Mesh Shader 的工作组模型
    • 

  • 半边数据结构通过成对的方向半边支持 O(1) 拓扑查询，是网格编辑的标准
    • 

  • QEM 边折叠通过最小化二次误差实现高质量的网格简化
    • 

  • 连续 LOD（如 Nanite）通过逐三角形自适应选择实现无缝的细节过渡
    • 

  • Nanite 代表了 LOD 技术的前沿——逐 Cluster 的自适应选择实现了像素级无缝过渡
    • 

  • 顶点缓存优化通过重排索引顺序减少 GPU 顶点着色器的重复调用
    •
