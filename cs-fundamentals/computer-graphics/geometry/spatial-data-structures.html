空间数据结构

核心概念

空间数据结构是组织三维空间中几何对象的数据结构，用于加速各种空间查询操作——如射线相交测试、最近邻搜索、视锥体剔除和碰撞检测。没有空间数据结构，这些操作需要遍历场景中的所有对象，时间复杂度为 O(n)；使用适当的空间索引后可以降低到 O(log n) 甚至 O(1)。

空间数据结构的核心思想是分治——将空间递归划分为更小的区域，每个区域只包含少量对象。查询时只访问与查询相关的区域，跳过大量不相关的对象。不同的数据结构在划分方式、构建成本、查询效率和动态更新性能之间做出不同的权衡。

包围体层级
包围体层级（Bounding Volume Hierarchy, BVH）是当前最重要的空间数据结构，是硬件光线追踪和物理引擎的核心。它将对象组织为树形结构——叶节点包含实际的几何体（一个或少量三角形），内部节点存储其所有子节点的包围体（通常是 AABB，即轴对齐包围盒）。


BVH 的构建质量直接影响查询性能。表面积启发式（Surface Area Heuristic, SAH）是最有效的构建策略。它在每个划分步骤中，遍历所有可能的划分位置，选择使期望遍历成本最小的方案：


SAH 成本函数:
C(split) = C_traverse + (SA_left/SA_parent) × N_left × C_intersect
                      + (SA_right/SA_parent) × N_right × C_intersect

SA = 包围盒表面积（射线命中概率的代理）
N = 包含的几何体数量
C_traverse = 遍历一个节点的成本
C_intersect = 射线与一个几何体相交测试的成本
SAH 的直觉是：一个子节点的包围盒表面积越大，射线命中它的概率越高；因此应该让包含更多对象的子节点有更小的包围盒。SAH 构建的 BVH 在光线追踪中比简单的中位数划分或空间中值划分快 1.5-3 倍。


BVH 构建的分割策略有三种主要方法：中位数划分（将对象按选定轴的中心坐标排序，在中位数处二分）、空间中值划分（在包围盒的空间中心处二分）和SAH 划分。


中位数划分保证树的平衡性（每个子节点包含相同数量的对象），空间中值划分保证空间的均匀分割，SAH 划分最小化期望的遍历成本但不保证平衡。


在实际性能上，SAH 划分通常最优，因为光线追踪的瓶颈是遍历成本而非树的平衡性。


BVH 遍历使用栈式深度优先方法。射线先与根节点的 AABB 测试，如果命中则依次测试两个子节点，将命中的子节点压栈。优先访问距离更近的子节点可以更早找到交点，利用已知的最近交点距离裁剪后续的 AABB 测试。


现代 GPU（RTX 系列）内置了硬件 BVH 遍历单元（RT Core），可以在硬件层面并行执行射线-AABB 和射线-三角形测试，将光线追踪的性能提升一个数量级。


均匀网格与哈希网格
均匀网格（Uniform Grid）将空间划分为等大小的体素（Voxel）。每个体素维护一个指向与其重叠的对象的列表。查询时只需计算查询涉及的体素坐标，直接访问对应的列表。


均匀网格的优势是构建和查询极快——对象插入只需计算其包围盒覆盖的体素范围，射线遍历使用 3D-DDA（数字微分分析器）算法沿网格线步进。它的缺点是对非均匀分布的场景效率低——如果大部分对象集中在空间的一小块区域，绝大多数体素都是空的（浪费内存），而密集区域的体素包含过多对象（查询退化）。


空间哈希（Spatial Hashing）用哈希函数将体素坐标映射到固定大小的哈希表中，避免了为整个空间分配数组。


它特别适合无限或稀疏分布的场景——只为实际包含对象的体素分配存储。


哈希函数:
hash(x, y, z) = (x × P1 xor y × P2 xor z × P3) mod TABLE_SIZE
P1, P2, P3 = 大素数 (如 73856093, 19349663, 83492791)
均匀网格和空间哈希在粒子系统（邻域搜索）、流体模拟（SPH 邻域）和简单碰撞检测中非常流行，因为它们的构建是 O(n) 且可以高效并行化。

八叉树与 KD 树
八叉树（Octree）递归地将三维空间等分为 8 个子区域（象限）。只有包含对象的区域继续细分，空区域不分配子节点。它自然地适应对象的空间分布——密集区域被细分到更深的层级，稀疏区域保持粗粒度。


八叉树在场景管理中广泛使用：视锥体剔除时从根节点开始，如果一个节点的包围盒完全在视锥体外则跳过整个子树；碰撞检测时只需要比较位于同一个叶节点或相邻叶节点中的对象对。


松散八叉树（Loose Octree）是标准八叉树的变体。标准八叉树中跨越划分边界的对象需要存储在较高层级的节点中（因为它不完全属于任何一个子节点），这导致大对象聚集在根节点附近。


松散八叉树将每个节点的边界扩展为标准大小的 k 倍（k 通常为 2），使对象可以根据其中心点归入子节点，即使对象的包围盒超出了子节点的标准边界。


代价是查询时需要检查更多的重叠节点。


KD 树（K-Dimensional Tree）是一种轴对齐的二叉空间划分树。每个内部节点选择一个坐标轴和一个划分位置，将空间分为两半。与八叉树的均匀八分不同，KD 树的划分位置是优化选择的（通常基于 SAH 或中位数），使得树的平衡性更好。


KD 树的构建通常使用递归算法。在每一层选择一个坐标轴（常见策略是按 x→y→z 循环，或选择数据范围最大的轴），然后在该轴上选择中位数或 SAH 最优的划分位置。


对象被分配到划分平面的两侧，对跨越划分平面的对象可以选择裁剪或放入两侧（两种策略各有优劣）。


KD 树构建（递归）:
1. 选择划分轴（通常按 x→y→z 循环，或选择范围最大的轴）
2. 选择划分位置（中位数或 SAH 最优）
3. 将对象分配到左右子空间
4. 递归构建子树直到叶节点对象数 ≤ 阈值
KD 树在最近邻搜索（k-NN）中表现优异，是 k-NN 问题的经典数据结构。搜索时先沿树下降到目标点所在的叶节点，然后回溯时检查另一侧子树是否可能包含更近的点（通过比较到划分平面的距离）。


这种回溯修剪在高维空间中效率下降（"维度灾难"），但在二维和三维空间中表现优异。


BSP 树（Binary Space Partitioning）允许使用任意方向的平面进行二分，不限于轴对齐。这使得 BSP 树可以精确地沿场景中的墙壁或其他平面特征进行划分。


BSP 树在 id Software 的 Doom 和 Quake 引擎中用于室内场景的可见性计算（前后排序渲染），是计算机图形学历史上最有影响力的数据结构之一。


动态场景与更新策略
静态场景的空间数据结构可以在加载时一次性构建。但动态场景——物体移动、创建和销毁——需要高效的更新策略。


完全重建是最简单但最昂贵的方案。对于 BVH，使用 LBVH（Linear BVH）算法可以在 GPU 上并行构建，先用 Morton 码（Z-order curve）将三角形的空间位置编码为一维排序键，排序后自底向上构建树。


LBVH 的质量低于 SAH 构建，但速度快数个数量级，适合每帧重建。


增量更新只修改发生变化的部分。AABB 重新拟合（Refit）只更新移动对象所在的叶节点和向上的祖先节点的包围盒。


这保持了原有的树结构，如果对象移动距离不大，质量损失可控。但如果物体大范围移动导致包围盒重叠严重，需要周期性地重建以恢复质量。


双缓冲策略在动态场景中很常见——一份空间结构用于当前帧的查询，另一份在后台异步构建/更新。帧结束时交换两个缓冲区。

选择合适的空间数据结构需要综合考虑场景的特性。静态场景（如建筑内部）适合离线构建高质量的 BVH 或 KD 树。高度动态的粒子系统适合每帧重建的均匀网格或空间哈希。


混合场景（大量静态几何 + 少量动态物体）通常使用静态 BVH + 动态对象的每帧 Refit 组合方案。


空间数据结构的选择还受硬件特性影响。GPU 上的空间查询偏好内存访问连续、避免指针追踪的数据结构（如 LBVH 和均匀网格），因为 GPU 的内存延迟更高但带宽更大。


CPU 上的空间查询可以充分利用指针结构（如标准 BVH 和 KD 树），因为 CPU 的缓存层级和分支预测对树遍历更友好。


R 树（R-Tree）是数据库和 GIS 领域常用的空间索引，与 BVH 结构相似但支持高效的动态插入和删除操作。


R 树在需要频繁增删对象的场景中（如实时策略游戏的单位管理、动态加载的开放世界）比需要重建的 BVH 更合适。


小结
    

  • BVH 是光线追踪和碰撞检测的核心结构，SAH 启发式产生最高效的划分
    • 

  • 现代 GPU 的 RT Core 在硬件层面加速 BVH 遍历，极大提升光线追踪性能
    • 

  • 均匀网格和空间哈希适合分布均匀的大量粒子的邻域搜索，构建和查询都是 O(n)/O(1)
    • 

  • 八叉树自适应地细分空间，适合场景管理和视锥体剔除
    • 

  • KD 树是最近邻搜索的经典选择，通过回溯修剪实现高效的 k-NN 查询
    • 

  • LBVH 使用 Morton 码排序实现 GPU 并行构建，适合每帧重建的动态场景
    • 

  • Refit 策略只更新包围盒不改变树结构，适合物体小幅度移动的场景
    • 

  • R 树支持高效的动态插入和删除，适合需要频繁增删对象的交互式场景
    • 

  • 空间数据结构的选择需要综合考虑查询类型、场景动态性和目标硬件特性
