光栅化

核心概念

光栅化（Rasterization）是将连续的几何图元（主要是三角形）转换为离散像素片元的过程。它是实时渲染的核心算法，决定了屏幕上每个像素被哪些三角形覆盖，并为后续的片元着色提供输入数据。

光栅化的核心问题可以分解为两个子问题：覆盖判定——确定哪些像素在三角形内部；属性插值——计算每个被覆盖像素处的颜色、深度、纹理坐标等属性值。这两个问题的高效解决直接影响渲染性能和图像质量。

现代 GPU





现代 GPU 几乎全部使用基于边函数的光栅化方法，因为它天然适合并行计算——每个像素的内外判定完全独立，无需维护扫描线的全局状态。


光栅化的效率直接决定了渲染管线的吞吐量。一个典型的游戏场景每帧可能包含数百万个三角形，光栅化器需要在毫秒级时间内处理所有这些几何体。硬件光栅化器的并行度和内存带宽管理是 GPU 架构设计的核心挑战之一。


从信号处理的角度看，光栅化本质上是一个采样过程——用离散的像素网格对连续的几何信号进行采样。根据奈奎斯特-香农采样定理，采样频率（像素密度）必须至少是信号最高频率的两倍，否则就会产生混叠（Aliasing）。几何边缘是无限高频的阶跃信号，因此理论上无法完美采样，这就是光栅化固有锯齿的数学根源。抗锯齿技术的本质就是通过各种方式增加有效采样率或对采样结果进行低通滤波。


边函数与覆盖判定
边函数（Edge Function）是光栅化的数学核心。对于三角形的一条边（从顶点 V₀ 到 V₁），边函数定义为点 P 相对于该边的带符号面积：


E(P) = (V₁.x - V₀.x) × (P.y - V₀.y) - (V₁.y - V₀.y) × (P.x - V₀.x)
这本质上是一个二维叉积。当 E(P) > 0 时，P 在边的左侧（按逆时针绕序）；当 E(P) = 0 时，P 在边上；当 E(P) < 0 时，P 在右侧。一个点在三角形内部的条件是它同时在三条边的同一侧，即三个边函数值同号。


边函数有一个关键的增量特性：当像素位置沿 x 方向移动一个单位时，边函数值的变化量是常数 (V₁.y - V₀.y)；沿 y 方向移动时变化量为 -(V₁.x - V₀.x)。这意味着在遍历像素网格时，边函数可以通过简单的加法更新，而不需要重新计算完整的乘法表达式。


初始化: E₀ = edge_function(V₀, V₁, P_start)
水平步进: E_next_x = E₀ + (V₁.y - V₀.y)
垂直步进: E_next_y = E₀ - (V₁.x - V₀.x)
对于恰好落在三角形边上的像素，需要填充规则（Fill Rule）来避免共享边被重复渲染。DirectX 和 OpenGL 都采用左上规则（Top-Left Rule）：像素仅在位于三角形的左边或上边时被认为在内部。左边是指 y 方向递减的边，上边是指完全水平且 x 方向递减的边。


在实际的 GPU 实现中，边函数的计算使用定点数而非浮点数，以保证像素级别的精确判定。典型的实现使用 sub-pixel 精度——例如在 8 位 sub-pixel 精度下，每个像素被细分为 256×256 的子网格。这确保了极细三角形和接近水平/垂直的边也能被正确光栅化。


深度测试与 Z-Buffer
深度测试（Depth Test）解决了三维场景中物体前后遮挡关系的问题。Z-Buffer 算法为屏幕上每个像素维护一个深度值，记录当前最近的片元深度。每个新片元的深度值与缓冲区中的值比较，只有更近的片元才会更新颜色和深度。


Z-Buffer 的精度分布不是均匀的。在标准透视投影下，NDC 中的 z 值与视图空间深度呈非线性关系：


z_ndc = (far + near) / (far - near) + 2·far·near / ((far - near) · z_eye)
近平面附近的深度精度远高于远平面。这导致远处物体容易出现 Z-fighting——两个深度非常接近的表面交替闪烁。当 far/near 比值很大时（如 10000:1），远处几乎没有可用的深度精度。


缓解 Z-fighting 的方法包括：使用更高精度的深度缓冲（32 位浮点代替 24 位定点）、缩小远近平面的比值、使用反向 Z（Reversed-Z）技术。反向 Z 将近平面映射为 1.0、远平面映射为 0.0，配合浮点数的精度分布特性（小数点附近精度最高），可以显著改善远处的深度精度。


深度缓冲还涉及深度偏移（Polygon Offset / Depth Bias）技术。当两个几何面近乎重合时（如贴花 Decal 或阴影贴图），即使没有数学上的共面也可能出现 Z-fighting。深度偏移通过在光栅化阶段为片元深度添加一个小的常量偏移和斜率偏移来避免冲突。阴影映射中的 shadow bias 就是这一技术的典型应用。

提前深度测试（Early-Z）是现代 GPU 的重要优化。它在片元着色器执行之前进行深度比较，提前丢弃不可见片元，避免执行昂贵的着色计算。但如果片元着色器修改了深度值或执行了 discard 操作，Early-Z 必须被禁用，退回到传统的后期深度测试。


Hierarchical Z-Buffer（Hi-Z）进一步优化了深度测试。它维护深度缓冲的多级 mipmap，每一级存储对应区域的最大（或最小）深度值。在光栅化早期阶段，通过比较三角形的最近深度与 Tile 区域的最远已有深度，可以在不访问逐像素深度的情况下快速剔除整块被遮挡的区域。这种粗粒度的剔除对于大量前后重叠的场景（高深度复杂度）尤为有效。

抗锯齿技术
锯齿（Aliasing）是光栅化的固有缺陷。当连续的几何边缘被离散的像素网格采样时，边缘呈现阶梯状而非平滑线条。抗锯齿（Anti-Aliasing）技术通过增加采样或后处理来缓解这一问题。


超采样抗锯齿（SSAA）是概念最简单的方法：以更高分辨率渲染整个场景，然后下采样到目标分辨率。例如 4x SSAA 以 4 倍分辨率渲染再缩小，每个目标像素是 4 个子像素的平均。它提供了最高质量的抗锯齿效果，覆盖了几何锯齿和着色锯齿（如高光闪烁），但性能开销巨大——着色量和显存带宽都增加为原来的 4 倍。因此 SSAA 在实时渲染中很少使用，主要用于离线渲染和截图模式。


多重采样抗锯齿（MSAA）是对 SSAA 的重要优化。它仅在光栅化阶段使用多个采样点判断覆盖，但片元着色器只执行一次。每个像素有多个深度/模板/颜色样本，但着色结果被复制到所有被覆盖的样本。4x MSAA 的着色开销与无抗锯齿基本相同，仅显存和带宽增加。


MSAA 的采样点位置通常不是规则网格排列，而是使用旋转网格采样模式（Rotated Grid Super Sampling, RGSS）或其他优化的采样模式。不同的采样点分布模式会影响不同方向边缘的抗锯齿效果。GPU 厂商在驱动层面预定义了多种标准采样模式，开发者也可以通过自定义采样模式来优化特定场景。


后处理抗锯齿是另一类方法，在渲染完成后对图像进行边缘检测和模糊。FXAA（Fast Approximate Anti-Aliasing）通过分析亮度梯度来检测锯齿边缘并进行智能模糊，性能开销极低但会轻微模糊整体画面。SMAA（Subpixel Morphological Anti-Aliasing）在 FXAA 基础上增加了形态学分析和子像素偏移检测，可以恢复部分因光栅化丢失的亚像素信息，提供更高质量的边缘平滑效果。SMAA 通常结合边缘检测、模式识别和混合权重三个 Pass 完成处理。


时间抗锯齿（TAA）利用多帧之间的亚像素抖动来累积采样信息。每帧的投影矩阵被施加微小偏移，使得采样点在帧间覆盖不同的子像素位置。通过运动向量对历史帧进行重投影，TAA 可以在极低开销下达到接近 MSAA 的效果，是当前游戏引擎中最主流的方案。


TAA 的主要挑战在于鬼影（Ghosting）和模糊（Blur）。当物体快速运动或场景发生突变时，历史帧的信息可能不再准确。颜色裁剪（Color Clipping）和邻域限制（Neighborhood Clamping）技术通过将历史颜色约束在当前帧局部颜色范围内来抑制鬼影。更先进的 TAA 变体（如 DLSS、FSR 2）利用深度学习或手工设计的算法在时间超分辨率和抗锯齿之间取得更好的平衡。


分层光栅化与硬件优化
现代 GPU 的光栅化远非简单的逐像素遍历。分层光栅化（Hierarchical Rasterization）采用粗到细的策略：先在大块（如 8x8 或 16x16 像素的 Tile）级别测试三角形覆盖，快速排除完全不被覆盖的块；对于部分被覆盖的块，再细化到单个像素级别测试。这种策略对于覆盖大面积屏幕的三角形效果显著，可以跳过大量的空白像素测试。


对于极小的三角形（覆盖不到一个像素的微三角形），分层光栅化的优势消失，反而增加了额外开销。微三角形问题在高多边形模型和远景 LOD 中非常普遍，是现代 GPU 性能的重要瓶颈之一。Mesh Shader 管线中的 Meshlet 剔除和硬件级别的小三角形剔除是应对这一问题的方向。


基于 Tile 的渲染（Tile-Based Rendering, TBR）是移动 GPU（ARM Mali、Qualcomm Adreno、Apple GPU）的标志性架构。屏幕被划分为小的 Tile（通常 16x16 或 32x32 像素），每个 Tile 的渲染在 GPU 的高速片上缓存中完成，只有最终结果才写回主显存。这大幅减少了显存带宽消耗——移动设备中最宝贵的资源。


TBR 架构对渲染管线的使用方式有特殊要求。频繁切换渲染目标（Render Target）会触发 Tile 的 Load/Store 操作，产生大量带宽开销。因此移动 GPU 编程中应尽量在一个 Render Pass 内完成所有绘制，并使用 loadOp: clear 或 storeOp: dontcare 来避免不必要的数据传输。


桌面 GPU（NVIDIA、AMD）传统上使用即时模式渲染（Immediate Mode Rendering, IMR），但近年来也引入了 Tile-Based 的元素。NVIDIA 的 Tile-Based Caching 在内部将帧缓冲划分为 Tile 以优化缓存利用率，AMD 的 DSBR（Draw Stream Binning Rasterizer）也采用了类似的混合策略。


Visibility Buffer（V-Buffer）是一种新兴的光栅化管线优化策略。传统的延迟渲染将大量材质数据写入 G-Buffer，带宽消耗高。V-Buffer 方案在光栅化阶段只写入极少量的数据（三角形 ID + 重心坐标），后续的着色阶段根据这些 ID 重新获取材质属性。这种方法大幅减少了光栅化阶段的带宽需求，特别适合几何密度极高的场景。


小结
光栅化是实时渲染的基石，从数学上的边函数测试到硬件层面的 Tile-Based 架构，每个层次都在追求更高的吞吐量和更低的带宽消耗。理解这些机制有助于编写高效的渲染代码和针对目标平台进行优化。在移动 GPU 上避免频繁切换渲染目标，在桌面 GPU 上利用 Early-Z 和 Hi-Z 减少 overdraw，是跨平台渲染优化的基础实践。
