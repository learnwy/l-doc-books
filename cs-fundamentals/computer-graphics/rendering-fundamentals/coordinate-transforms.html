坐标变换

核心概念

坐标变换是计算机图形学的数学基础，它将物体从定义时的局部坐标系，经过一系列变换，最终映射到屏幕上的像素位置。整个渲染管线的几何处理阶段本质上就是一连串坐标空间的转换。

图形学中的坐标变换用 4×4 矩阵表示，使用齐次坐标（Homogeneous Coordinates）将平移、旋转、缩放和投影统一到矩阵乘法的框架下。一个三维点 (x, y, z) 表示为齐次坐标 (x, y, z, 1)，一个方向向量表示为 (x, y, z, 0)——w 分量的区别使得平移只对点生效，不影响方向向量。

理解每个坐标空间的物理含义和变换矩阵的构造方式，是正确实现渲染、光照计算、阴影映射和碰撞检测的前提。


基础仿射变换
仿射变换（Affine Transform）包含缩放、旋转和平移，它们保持直线的直线性和平行线的平行性。在齐次坐标下，仿射变换表示为：

其中左上 3×3 部分编码旋转和缩放，右列编码平移。


缩放矩阵是对角矩阵，各轴缩放因子放在对角线上。均匀缩放（所有轴相同因子）不影响法线方向，非均匀缩放会扭曲法线，需要使用逆转置矩阵变换法线。


旋转矩阵是正交矩阵（逆等于转置），行列式为 1。绕三个坐标轴的旋转分别用 Rx(θ)、Ry(θ)、Rz(θ) 表示，复合旋转通过矩阵连乘实现。但欧拉角表示存在万向锁（Gimbal Lock）问题——当两个旋转轴对齐时丢失一个自由度。


四元数（Quaternion）是旋转的更优表示方式。一个单位四元数 q = (w, x, y, z) 表示绕轴 (x, y, z)/||(x,y,z)|| 旋转 2·arccos(w) 角度。四元数旋转没有万向锁问题，支持平滑插值（Slerp），且仅需 4 个分量存储，是动画系统中的标准旋转表示。

变换的组合顺序至关重要。标准的 TRS（Translation × Rotation × Scale）顺序意味着先缩放、再旋转、最后平移。矩阵乘法不满足交换律，改变顺序会产生完全不同的结果。


视图变换与相机模型
视图变换将世界空间中的场景转换到以相机为原点的坐标系中。从数学上看，移动相机等价于反方向移动整个世界——视图矩阵是相机自身变换矩阵的逆矩阵。


经典的 LookAt 相机模型由三个参数定义：相机位置（eye）、观察目标点（center）、上方向参考（up）。从这三个参数可以构造出相机的三个基向量：


forward = normalize(center - eye)      // 观察方向
right   = normalize(cross(forward, up)) // 右方向
up'     = cross(right, forward)         // 校正后的上方向
视图矩阵 V:


[right.xright.yright.z−dot(right, eye)up’.xup’.yup’.z−dot(up’, eye)−forward.x−forward.y−forward.zdot(forward, eye)0001]\begin{bmatrix}
\text{right.x} & \text{right.y} & \text{right.z} & -\text{dot(right, eye)} \\
\text{up'.x} & \text{up'.y} & \text{up'.z} & -\text{dot(up', eye)} \\
-\text{forward.x} & -\text{forward.y} & -\text{forward.z} & \text{dot(forward, eye)} \\

注意 forward 取反放入矩阵的第三行，这是因为 OpenGL 惯例使用右手坐标系，相机看向 -Z 方向。DirectX 使用左手坐标系，相机看向 +Z 方向，forward 不取反。


除了 LookAt 模式，游戏引擎常用 FPS 相机模型——用欧拉角（Yaw 偏航角 + Pitch 俯仰角）控制相机方向。这种模型更适合键鼠操作，Yaw 控制水平旋转，Pitch 控制抬头低头，且 Pitch 通常限制在 ±89° 以避免翻转。


轨道相机（Orbit Camera）围绕目标点旋转，由目标位置、距离和两个旋转角定义，常用于 3D 建模软件和物体查看器。


投影变换
投影变换将三维视图空间映射到二维裁剪空间。图形学中使用两种主要的投影方式。


透视投影模拟人眼和相机的成像方式——近大远小。它由四个参数定义：垂直视场角（fov）、宽高比（aspect）、近平面（near）和远平面（far）。透视投影矩阵将视锥体（一个截头锥体）映射为标准立方体：

正交投影没有近大远小的效果，常用于 2D UI 渲染、CAD 软件和技术制图。它由六个参数定义边界框：left、right、bottom、top、near、far，将长方体视锥直接映射到标准立方体。

视口变换与 NDC
透视除法将裁剪空间坐标转换为 NDC（Normalized Device Coordinates）。在 OpenGL 中 NDC 范围是 [-1, 1]³，在 Vulkan/DirectX 中 x,y ∈ [-1, 1] 而 z ∈ [0, 1]。


视口变换是管线的最后一步几何变换，将 NDC 映射到屏幕窗口的像素坐标：


screen_x = (NDC_x + 1) / 2 × width + x_offset
screen_y = (NDC_y + 1) / 2 × height + y_offset
screen_z = (NDC_z + 1) / 2 × (far_depth - near_depth) + near_depth
不同 API 的 Y 轴方向有差异。OpenGL 的 NDC Y 轴向上（左下角为原点），Vulkan 的 NDC Y 轴向下（左上角为原点）。这个差异在跨 API 移植时经常导致图像上下翻转的问题，通常通过在投影矩阵中翻转 Y 分量来解决。


反向 Z（Reversed-Z）是现代渲染的重要技巧。标准投影将近平面映射为 z=0（或 z=-1）、远平面映射为 z=1。反向 Z 交换这个映射——近平面 z=1、远平面 z=0，同时将深度比较函数从 LESS 改为 GREATER。配合浮点数在 0 附近精度最高的特性，反向 Z 使远处的深度精度大幅提升，有效解决大场景的 Z-fighting 问题。


变换的组合与层级
在实际的渲染引擎中，变换通常组织为场景图（Scene Graph）形式的层级结构。每个节点有一个相对于父节点的局部变换，节点的世界变换是从根到该节点所有局部变换的级联。


world_transform = parent.world × local_transform
当父节点旋转时，所有子节点也随之旋转，但保持与父节点之间的相对关系不变。这种层级结构自然地表达了关节动画（手臂绕肩膀旋转带动前臂和手），车辆物理（车身运动带动车轮），以及骨骼绑定等场景。


变换矩阵的逆矩阵在图形学中频繁使用。视图矩阵是相机变换的逆矩阵，法线变换使用模型矩阵的逆转置，阴影映射需要将世界坐标变换到光源空间（光源视图矩阵的逆）。对于仅包含旋转和平移的刚体变换，逆矩阵可以高效计算——旋转部分取转置，平移部分取反并变换到旋转后的空间。

小结
    

  • 齐次坐标用 4×4 矩阵统一表示平移、旋转、缩放和投影变换
    • 

  • 四元数是旋转的优选表示，避免万向锁且支持平滑插值
    • 

  • LookAt 矩阵从相机位置、目标点和上方向构建视图变换
    • 

  • 透视投影产生近大远小效果，正交投影保持平行关系
    • 

  • 不同图形 API 的 NDC 范围和 Y 轴方向有差异，需要注意兼容性
    • 

  • 反向 Z 利用浮点精度分布特性，显著改善远处的深度精度
    • 

  • 场景图通过层级变换的级联实现复杂的父子空间关系
