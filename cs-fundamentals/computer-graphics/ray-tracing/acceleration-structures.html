加速结构

核心概念

加速结构（Acceleration Structure）是光线追踪中将射线-场景求交从暴力 O(n) 降低到 O(log n) 的关键数据结构。一个典型的场景包含数百万个三角形，如果每条射线都要逐一测试所有三角形，即使 GPU 的并行计算能力也远远不够。加速结构通过空间层级组织几何体，使射线快速跳过大量不相关的区域。

BVH（Bounding Volume Hierarchy，包围体层级）是当前光线追踪加速结构的绝对主流。NVIDIA 的 RT Core、AMD 的 RA（Ray Accelerator）和 Intel 的 Ray Tracing Unit 都在硬件层面实现了 BVH 遍历加速。

本节深入探讨 BVH 的构建策略、遍历优化和硬件实现。

光线追踪 API（DirectX Raytracing, Vulkan Ray Tracing）使用两级加速结构：BLAS（Bottom-Level Acceleration Structure，底层）包含单个 Mesh 的三角形，TLAS（Top-Level Acceleration Structure，顶层）包含 BLAS 实例的引用和变换矩阵。


这种两级设计允许同一个 BLAS 被多次实例化（如重复放置的树木模型），节省显存并支持每实例变换。


相同的 BLAS 可以被多个 TLAS 实例引用（不同的变换矩阵），实现了几何数据的复用——森林中的 1000 棵树只需要 1 个 BLAS 加上 1000 个不同变换的 TLAS 条目。


动态物体的变换矩阵变化时只需更新 TLAS（毫秒级），BLAS 保持不变。


SAH 优化构建
表面积启发式（Surface Area Heuristic, SAH）是高质量 BVH 构建的黄金标准。SAH 基于概率论推导：一条随机射线命中包围盒的概率与包围盒表面积成正比（假设射线分布均匀）。


完整的 SAH 构建流程在每个内部节点处执行以下步骤：


对每个坐标轴 (x, y, z):
    按该轴排序所有三角形
    从左到右扫描，计算每个分割点的成本:
    C(i) = C_trav + (SA_L / SA_parent) × count_L × C_isect
                  + (SA_R / SA_parent) × count_R × C_isect

选择所有轴上成本最小的分割点
如果分割成本 > 叶节点成本: 创建叶节点（不分割）
SAH 的一个重要细节是叶节点终止条件。当分割的期望成本大于直接测试叶节点中所有三角形的成本时，应停止分割创建叶节点。典型的叶节点包含 2-8 个三角形。过大的叶节点增加求交计算，过小的叶节点增加遍历步数——SAH 自然地在两者之间找到平衡。


Binned SAH 是加速 SAH 的标准优化。不是对所有 n 个三角形评估 O(n) 个分割点，而是将轴向范围均匀分为 K 个桶（通常 K=12-32），将三角形归入桶中，只评估 K-1 个桶边界的分割成本。Binned SAH 将构建时间从 O(n² log n) 降低到 O(n log n)，质量损失可忽略不计。


构建后可以进行 SAH 后优化。树旋转（Tree Rotation）检查每个内部节点，尝试将其子节点与孙节点交换位置以降低 SAH 成本。


Reinsertion 方法将随机选取的子树移除并重新插入到树中成本最低的位置。这些优化通常可以将遍历性能提升 5-15%。


BVH 遍历算法
BVH 遍历是光线追踪中执行频率最高的操作。高效的遍历实现对性能至关重要，不同的遍历策略在不同场景和硬件下表现各异。


栈式遍历是最基本的方法。维护一个显式栈（在 GPU 上使用寄存器或共享内存），从根节点开始，测试射线与当前节点的两个子 AABB。


如果两个都命中，将较远的压栈，继续遍历较近的；如果只命中一个，直接进入该子节点；如果都未命中，从栈中弹出下一个节点。


traverse(ray, bvh):
    stack = [root]
    closest_hit = INF

    while stack not empty:
        node = stack.pop()
        if ray-AABB test(node) miss or node.tmin > closest_hit:
            continue

        if node is leaf:
            for each triangle in node:
                t = ray-triangle test
                if t < closest_hit:
                    closest_hit = t
        else:
            (near, far) = sort children by distance
            stack.push(far)
            stack.push(near)

    return closest_hit
无栈遍历使用线索（threading）或跳过链接避免显式栈。每个节点存储额外的"miss 链接"——当射线未命中该节点时应跳转到的下一个节点。无栈遍历在 GPU 上节省寄存器压力，但会增加节点数据大小。


射线包遍历（Packet Traversal）利用相邻像素的射线方向相近的特性，将多条射线打包为一组同时遍历 BVH。如果包中所有射线都未命中某个节点，则整个包跳过该子树。对于主射线（Primary Ray）这种高相干性的射线，包遍历比逐射线遍历快 2-4 倍。但对于散射的次级射线，包中射线方向差异大，包遍历的优势消失甚至退化。包的大小通常为 4×4 或 8×8 条射线，与 GPU Warp 的大小对齐。


遍历的重新排序（Ray Reordering）是另一种优化策略。它将大量待处理的射线按空间方向或命中节点进行排序分组，使得同一批处理的射线具有高相干性，提高缓存命中率和 SIMT 效率。NVIDIA 在 Ada Lovelace 架构中引入了硬件级别的射线重排序单元（Shader Execution Reordering, SER）。


BVH 节点的内存布局影响缓存效率。将子节点紧邻父节点存储（深度优先布局）可以利用空间局部性，因为遍历通常沿深度优先路径前进。宽 BVH（4-ary 或 8-ary BVH）将多个子节点的 AABB 打包在一个缓存行中，可以在一次内存访问中获取所有子节点的包围盒。


硬件光线追踪
NVIDIA RTX 架构在 SM（Streaming Multiprocessor）中集成了专用的 RT Core。RT Core 处理两种操作：射线-AABB 测试（BVH 遍历）和射线-三角形测试。SM 将射线提交给 RT Core，在等待结果期间继续执行其他着色器工作，实现射线追踪和着色的流水线并行。


DirectX Raytracing（DXR）和 Vulkan Ray Tracing 定义了标准化的光线追踪管线：


    

  • Ray Generation Shader: 发射光线的起点，定义射线的起点和方向
    • 

  • Intersection Shader: 自定义几何体的求交（默认硬件处理三角形）
    • 

  • Any-Hit Shader: 每次找到交点时调用（用于 Alpha 测试等）
    • 

  • Closest-Hit Shader: 最近交点确定后调用（执行着色）
    • 

  • Miss Shader: 射线未命中任何几何体时调用（天空盒等）
    •

内联光线追踪（Inline Ray Tracing / Ray Query）允许在任意着色器阶段（包括计算着色器和片元着色器）中发射射线查询，无需使用专用的光线追踪管线。这使得将光线追踪集成到现有的光栅化渲染管线变得更加灵活——例如在片元着色器中发射反射射线。


内联光线追踪与完整的光追管线各有优势。完整管线（TraceRay）支持递归调用和完整的着色器绑定表，适合复杂的多弹射光照计算。内联查询（RayQuery）更轻量，避免了着色器绑定表的管理开销，适合简单的单次命中查询（如阴影测试、AO 采样）。在实践中，两种方式经常在同一帧中混合使用——反射和折射用完整管线，阴影和 AO 用内联查询。


动态场景加速结构更新
游戏场景中的物体每帧都在移动，加速结构需要相应更新。两级架构（TLAS + BLAS）的设计使得大部分更新只涉及 TLAS：


TLAS 重建：当实例的变换矩阵改变（物体移动/旋转）时，只需要重建 TLAS。由于 TLAS 的节点数量远少于总三角形数（每个实例一个节点），重建非常快速。


BLAS 更新：当几何体本身发生变形（如骨骼动画）时，需要更新 BLAS。Refit 操作只更新各级节点的 AABB 而不改变树结构，速度快但如果变形剧烈会导致包围盒重叠增大、遍历效率下降。完全重建恢复最优质量但更耗时。

实际引擎通常维护每个 BLAS 的"退化度"指标——当 Refit 后的 SAH 成本超过原始成本的某个阈值时，触发完全重建。这在每帧更新成本和遍历效率之间取得动态平衡。


压缩 BVH 是减少加速结构显存占用的重要技术。标准 BVH 的每个节点存储两个 AABB（各 6 个 float，共 48 字节）加上子节点指针。压缩方案将子节点的 AABB 存储为相对于父节点的量化偏移，可以将节点大小从 64 字节压缩到 16-32 字节。量化精度的损失通常可忽略，但显存节省使得更大的场景可以常驻 GPU 内存。


对于巨大的场景（如开放世界游戏），加速结构的流式加载也是必要的。场景被划分为区块（Chunk），每个区块有独立的 BLAS。随着玩家移动，远处的 BLAS 被卸载，近处新区域的 BLAS 被异步加载和构建。TLAS 在每帧重建时只包含当前已加载区块的 BLAS 引用。


小结
    

  • BVH 将射线-场景求交从 O(n) 降低到 O(log n)，是实时光追的基础
    • 

  • SAH 通过最小化期望遍历成本构建高质量 BVH，Binned SAH 将构建时间降至 O(n log n)
    • 

  • 两级架构（TLAS + BLAS）支持几何实例化和高效的动态场景更新
    • 

  • 射线包遍历利用射线相干性批量处理，主光线可获得 2-4 倍加速
    • 

  • RT Core 在硬件层面并行处理 BVH 遍历和射线-三角形测试
    • 

  • 内联光线追踪允许在任意着色器阶段发射射线查询，增加了集成灵活性
    • 

  • BLAS Refit 快速更新变形几何的包围盒，退化严重时回退到完全重建
    • 

  • BVH 节点的深度优先布局和宽树结构优化缓存命中率
    • 

  • 压缩 BVH 通过量化子节点 AABB 减少显存占用
    • 

  • 加速结构的流式加载支持超大场景的渐进式构建
    •
