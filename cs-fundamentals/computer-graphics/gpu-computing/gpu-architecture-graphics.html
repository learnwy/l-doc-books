GPU 架构与图形处理

核心概念

GPU（Graphics Processing Unit）是专为大规模并行计算设计的处理器。与 CPU 使用少量高性能核心优化单线程延迟不同，GPU 使用数千个简单核心同时执行相同的指令在不同的数据上——这种架构被称为 SIMT（Single Instruction, Multiple Threads）。这种设计完美匹配了图形渲染的特点：对数百万个像素或顶点执行相同的着色器程序。

现代 GPU 的峰值算力远超 CPU。一块消费级 GPU 可以提供数十 TFLOPS 的浮点计算能力和数百 GB/s 的显存带宽，而同时代的 CPU 通常只有个位数 TFLOPS 和不到 100 GB/s 的内存带宽。这种差距使得 GPU 不仅主导了图形渲染，还成为了深度学习、科学计算和密码学等领域的核心计算平台。

SIMT 执行模型
GPU 的执行模型与 CPU 有本质区别。以 NVIDIA 架构为例，线程被组织为线程束（Warp），每个 Warp 包含 32 个线程。Warp 中的所有线程在同一时钟周期执行相同的指令（SIMT），但操作不同的数据。这种设计与 CPU 的 SIMD 类似但有关键区别——SIMT 允许每个线程有独立的指令指针和栈，只是在同一时刻被强制执行相同的指令。


当 Warp 中的线程遇到条件分支时，如果不同线程需要走不同的路径（线程发散，Thread Divergence），Warp 必须串行执行两条路径——先执行 then 分支（不需要的线程被屏蔽），再执行 else 分支。


这意味着分支密集的代码在 GPU 上效率极低，最坏情况下吞吐量降为原来的 1/32。


Warp 执行示例（32 个线程）:

if (threadIdx < 16) {
    // 路径 A: 线程 0-15 执行，16-31 被屏蔽
} else {
    // 路径 B: 线程 16-31 执行，0-15 被屏蔽
}
// 两条路径总耗时 = 路径 A + 路径 B（非并行）
GPU 通过延迟隐藏（Latency Hiding）来掩盖内存访问的延迟。当一个 Warp 等待内存数据返回时，调度器立即切换到另一个就绪的 Warp 执行——这个切换是零开销的，因为每个 Warp 的寄存器状态始终驻留在 SM 上，不需要像 CPU 的上下文切换那样保存和恢复。


这要求 SM 上同时有大量活跃的 Warp（高占用率，High Occupancy），使调度器总有工作可做。占用率受限于每个线程使用的寄存器数量和共享内存大小——使用越多资源，可并发的 Warp 越少。


NVIDIA GPU 的 Warp 调度器采用双发射（Dual Issue）设计——每个时钟周期可以同时向两个 Warp 发射指令，进一步提升指令吞吐量。调度器使用贪心策略选择就绪的 Warp：优先选择有指令可执行且操作数就绪的 Warp。


SM（Streaming Multiprocessor）是 GPU 的基本计算单元。每个 SM 包含多个 Warp 调度器、大量 ALU（CUDA Core）、纹理单元（TMU）、特殊功能单元（SFU，负责 sin/cos/sqrt 等运算），以及可配置的共享内存和 L1 缓存。

GPU 内存层级
GPU 的内存系统分为多个层级，访问速度和容量差异巨大。理解内存层级是优化 GPU 程序性能的关键。


寄存器是每个线程私有的最快存储，访问延迟接近零。但寄存器总量有限（每个 SM 约 64K 个 32 位寄存器），由所有活跃线程共享。


当单个线程使用过多寄存器时，SM 上可并发的 Warp 数量减少。如果寄存器需求超过 SM 的物理容量，编译器会将多余的变量溢出到本地内存（Local Memory，实际位于全局内存中），访问延迟从零周期暴增到数百周期——这是 GPU 性能的灾难性退化。


共享内存（Shared Memory）是同一线程块（Block）内所有线程可共同访问的片上高速缓存，延迟约 20-30 个时钟周期。它通常与 L1 缓存共享同一物理存储（可配置分配比例），大小通常 48-100 KB/SM。


共享内存是实现线程间通信和数据复用的核心。例如在 Tile-Based 渲染中，一个 Tile 的像素数据加载到共享内存后可被同一线程块内的所有线程访问。


共享内存被组织为多个Bank（通常 32 个）。当同一 Warp 中的多个线程同时访问同一个 Bank 的不同地址时，会发生 Bank Conflict，访问必须串行化。避免 Bank Conflict 的常见方法是在数据布局中添加 padding，使相邻线程访问不同的 Bank。


广播（Broadcast）是例外——当多个线程读取同一个地址时，硬件可以一次性广播给所有线程而不产生冲突。


纹理缓存（Texture Cache）是 GPU 内存层级中的特殊组件。它针对 2D 空间局部性优化（Morton/Z-order 排列），使得相邻 UV 坐标的纹理采样大概率命中缓存。纹理缓存是只读的，与 L1 缓存物理分离，TMU 通过纹理缓存获取纹素数据后执行过滤计算。


L2 缓存是全芯片共享的缓存层级（4-96 MB），介于共享内存和全局内存之间。所有 SM 的全局内存访问都会经过 L2 缓存。在 Ampere 及以后的架构中，L2 缓存可以被配置为持久化模式——将频繁访问的数据锁定在 L2 中防止被换出。


全局内存（Global Memory）即显存（VRAM），容量最大（数 GB 到数十 GB）但延迟最高（400-800 个时钟周期）。所有线程都可以访问全局内存。


全局内存的访问模式至关重要——合并访问（Coalesced Access）要求同一 Warp 中相邻线程访问连续的内存地址，这样多个访问可以合并为一个宽内存事务（128 字节）。散列访问模式会导致多个独立的内存事务，带宽利用率暴跌。


图形管线的硬件映射
GPU 的硬件单元如何映射到渲染管线的各个阶段，对于理解性能瓶颈至关重要。


顶点处理阶段，每个顶点着色器实例在一个 CUDA Core 上执行，多个顶点作为 Warp 同时处理。GPU 维护一个顶点后变换缓存（Post-Transform Cache），最近变换过的顶点结果被缓存，避免相同顶点被重复处理。


光栅化在固定功能硬件中执行——专用的光栅化器比可编程单元更高效且功耗更低。光栅化器为每个 Tile（通常 8x8 或 16x16 像素）生成片元，交由 SM 执行片元着色器。NVIDIA GPU 中每个 GPC 包含一个光栅化引擎，负责将 Tile 中的片元分发到对应的 SM。


片元着色是 GPU 负载最重的阶段。片元着色器以 2x2 的 Quad 为最小调度单位（需要计算偏导数用于 Mipmap 选择和各向异性过滤），每个 Quad 作为 Warp 的一部分执行。当三角形很小（只覆盖少量像素）时，大量 Quad 中只有部分片元有效（Helper Lane 浪费），导致着色效率下降——这就是微三角形问题。


ROP（Render Output Unit）处理输出合并操作：深度测试、模板测试、混合和帧缓冲写入。ROP 是固定功能单元，通常与显存控制器关联。


ROP 的吞吐量在高分辨率渲染和大量透明混合的场景中可能成为瓶颈。

GPU 性能分析与瓶颈诊断
理解 GPU 的性能瓶颈是渲染优化的第一步。GPU 渲染管线是一个流水线系统，整体性能取决于最慢的阶段（木桶效应）。


正确识别瓶颈类型决定了优化方向——对着色器限制的场景做几何优化完全无效，反之亦然。


CPU 限制（CPU Bound）——CPU 无法足够快地生成 Draw Call 和更新数据。症状：GPU 利用率低，增加渲染分辨率不影响帧率。解决方案：合并 Draw Call（实例化渲染、间接绘制）、多线程命令录制、减少状态切换。


顶点处理限制——太多顶点或太复杂的顶点着色器。症状：降低屏幕分辨率不改善帧率。解决方案：LOD、减少骨骼数量、简化顶点着色器。


片元着色限制——最常见的瓶颈类型。症状：降低分辨率显著提升帧率。解决方案：简化片元着色器、使用 depth prepass 减少 overdraw、降低纹理采样数量。


显存带宽限制——纹理读取和帧缓冲读写消耗过多带宽。症状：减少纹理分辨率或使用更激进的压缩格式可提升帧率。解决方案：使用 BC/ASTC 压缩、减少 G-Buffer 大小、Tile-Based 渲染。


GPU 性能分析工具（如 NVIDIA Nsight Graphics、AMD Radeon GPU Profiler、Intel GPA）可以可视化管线各阶段的利用率和等待时间，精确定位瓶颈所在。


关键指标包括 SM 占用率（Occupancy）、ALU 和 TMU 吞吐量、L1/L2 缓存命中率、显存带宽利用率和 ROP 吞吐量。


GPU 时间戳查询（Timestamp Query）可以精确测量每个 Draw Call 或 Render Pass 的 GPU 执行时间。在 Vulkan/D3D12 中通过写入时间戳到查询池、CPU 端回读来实现。这是引擎内置性能面板（如 UE 的 Stat GPU）的基础。


需要注意的是，GPU 时间戳有一到两帧的延迟——查询结果需要等待 GPU 完成执行后才能回读到 CPU。


管线统计查询（Pipeline Statistics Query）可以报告各管线阶段的处理数量——输入顶点数、调用的片元着色器实例数、通过深度测试的片元数等。这些数据帮助定位 overdraw 程度和几何处理效率。


Tensor Core 和 RT Core 是现代 NVIDIA GPU 中的专用硬件单元。Tensor Core 执行混合精度矩阵乘法（如 FP16 输入、FP32 累加），最初为深度学习设计，但在图形中用于 DLSS 的超分辨率推理。


RT Core 加速光线追踪的 BVH 遍历和射线-三角形测试。这些专用单元与通用 CUDA Core 协同工作——着色器核心在等待 RT Core 返回求交结果时可以继续执行其他计算，最大化硬件利用率。


AMD 的 RDNA 架构采用不同的组织方式。RDNA 的基本计算单元是 Compute Unit（CU），每个 CU 包含两个 SIMD 单元，每个 SIMD 处理一个 32 线程的 Wave32。RDNA 3 进一步引入了 WMMA 指令用于 AI 加速。


移动端的 ARM Mali GPU 使用 Warp-based 架构但 Warp 大小更小（通常 4-16 线程），Apple GPU 的 Warp 大小为 32 线程。


统一着色器架构（Unified Shader Architecture）是现代 GPU 的基础设计原则。早期 GPU 有独立的顶点着色器单元和片元着色器单元，数量固定。统一架构将所有着色器单元统一为通用的 ALU（CUDA Core），由调度器根据负载动态分配给顶点、片元或计算任务。这消除了固定分配导致的利用率不均衡问题。


小结
    

  • GPU 使用 SIMT 架构在数千个核心上并行执行相同指令，通过大规模并行弥补单线程性能的不足
    • 

  • Warp 中的线程发散导致分支串行执行，GPU 代码应尽量避免发散的条件分支
    • 

  • 延迟隐藏通过零开销的 Warp 切换掩盖内存延迟，高占用率是前提条件
    • 

  • 共享内存是线程块内通信的核心，Bank Conflict 会导致串行化访问
    • 

  • 全局内存的合并访问模式对带宽利用率至关重要，散列访问模式性能急剧下降
    • 

  • 片元着色是 GPU 最大的计算负载，微三角形导致 Quad 中的 Helper Lane 浪费
    • 

  • ROP 处理深度测试和混合，高分辨率和大量透明物体场景中可能成为瓶颈
    • 

  • 性能分析工具通过时间戳查询和管线统计精确定位瓶颈类型
    • 

  • 现代 GPU 架构集成了 RT Core 和 Tensor Core 等专用单元，扩展了计算能力
    • 

  • 跨平台开发需要了解 NVIDIA/AMD/Apple GPU 在 Warp 大小和内存行为上的差异
