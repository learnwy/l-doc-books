实时渲染技术

核心概念

实时渲染是在严格的时间预算内（通常 16.67ms/帧 @ 60fps 或 8.33ms/帧 @ 120fps）生成高质量图像的技术体系。它需要在有限的 GPU 算力和显存带宽下，协调数百种渲染技术的执行顺序和资源分配，在视觉质量和帧率之间取得最佳平衡。

现代游戏引擎的一帧渲染包含数十个 Pass（渲染阶段），从几何处理、光照计算、后处理到 UI 叠加，每个 Pass 都需要精确的资源管理和时序控制。理解这些 Pass 的组织方式和它们之间的依赖关系，是进行渲染优化的基础。

延迟渲染管线
延迟渲染（Deferred Rendering）将几何处理和光照计算分离为两个独立阶段。几何阶段将场景的几何属性（位置、法线、材质参数）写入多个渲染目标（G-Buffer）；光照阶段在全屏 Pass 中读取 G-Buffer 数据，对每个光源执行光照计算。


这种分离使得光照计算的复杂度与场景几何量无关——100 万个三角形和 1000 万个三角形的光照计算开销相同。


G-Buffer 典型布局（4 个 RGBA8-RGBA16F 渲染目标）:
RT0: [Albedo.r | Albedo.g | Albedo.b | Metallic]       — RGBA8
RT1: [Normal.x | Normal.y | Roughness | AO]             — RGBA16F
RT2: [Emissive.r | Emissive.g | Emissive.b | Flags]     — R11G11B10F + A8
深度: [Depth 24 bit + Stencil 8 bit]                     — D24S8 / D32F
G-Buffer 的典型组成包括：


    

  • RT0：漫反射颜色（RGB）+ 金属度（A），格式 RGBA8
    • 

  • RT1：世界空间法线（RG，八面体编码）+ 粗糙度（B）+ 环境遮蔽（A），格式 RGBA16F
    • 

  • RT2：自发光颜色（RGB）+ 标志位（A），格式 R11G11B10F
    • 

  • 深度缓冲：24 位深度 + 8 位模板
    • 



延迟渲染的优势在于光照计算只对可见像素执行（几何阶段通过深度测试自动剔除了被遮挡的片元），且每个光源的计算独立于几何复杂度。100 个光源只需要 100 次全屏（或部分屏幕）Pass，而前向渲染需要 100 × 物体数次计算。


G-Buffer 的带宽消耗是延迟渲染的主要缺点。4 个 RGBA16F 渲染目标加深度缓冲，在 4K 分辨率下每帧读写的 G-Buffer 数据量超过 300MB。


法线编码使用 Oct 编码（2 个分量重建 3D 法线）和材质参数打包可以减少渲染目标数量。


延迟渲染不能直接处理半透明物体——G-Buffer 每个像素只存储一层数据。通常的做法是延迟渲染处理不透明物体，再用前向渲染处理透明物体。


这种混合方案是大多数 AAA 游戏引擎的标准做法。


阴影技术
阴影为场景提供深度感和空间关系的关键视觉线索。实时渲染中最常用的阴影技术是阴影贴图（Shadow Mapping）和级联阴影贴图（Cascaded Shadow Maps, CSM）。


阴影贴图的原理：从光源视角渲染场景的深度图（Shadow Map），渲染真实视角时，将每个片元变换到光源空间并与 Shadow Map 中的深度比较——如果片元深度大于 Shadow Map 深度，说明它被其他物体遮挡，处于阴影中。


阴影贴图的经典问题包括 Shadow Acne（自遮挡伪影，由深度精度不足导致）和 Peter Panning（偏移过大导致阴影与物体脱离）。常用的缓解方法：恒定深度偏移 + 法线偏移的组合，或使用法线方向偏移采样点而非偏移深度值。


级联阴影贴图（CSM）解决了方向光的阴影分辨率问题。视锥体按深度分为多个区间（Cascade），每个区间使用独立的 Shadow Map。近处 Cascade 覆盖范围小但分辨率高（阴影锐利），远处 Cascade 覆盖范围大但分辨率低（阴影模糊）。典型配置使用 3-4 个 Cascade。


CSM 分割策略:
对数分割: split_i = near × (far/near)^(i/N)
均匀分割: split_i = near + (far-near) × (i/N)
实际使用: 混合方案 = λ × log + (1-λ) × linear, λ ≈ 0.5-0.8
软阴影使物体看起来更自然。PCF（Percentage Closer Filtering）在 Shadow Map 中采样多个点取平均，模拟柔和的阴影边缘。PCSS（Percentage Closer Soft Shadows）通过估计遮挡物到接收面的距离来计算阴影的半影宽度——遮挡物越远，阴影越模糊。


PCSS 需要两次 Shadow Map 采样：第一次搜索遮挡物的平均深度，第二次根据计算出的半影宽度执行 PCF 滤波。

后处理管线
后处理（Post-Processing）在主渲染完成后对图像进行全局调整。现代引擎的后处理管线包含十几个效果，按固定顺序串联执行。


Bloom（辉光）模拟相机镜头对高亮度区域的散射效果。实现步骤：提取高于阈值的亮度区域，逐级下采样（生成多级模糊），再逐级上采样并叠加回原图。下采样使用 13-tap 滤波器避免闪烁，上采样使用双线性插值加混合。


色调映射（Tone Mapping）将 HDR（高动态范围）的渲染结果映射到 LDR（低动态范围）的显示器范围。常用的色调映射曲线包括 Reinhard、ACES（Academy Color Encoding System）和 Tony McMapface。ACES 是电影行业标准，提供良好的色彩保持和对比度。


自动曝光（Auto Exposure）根据画面平均亮度动态调整曝光值，模拟人眼对亮度变化的适应。实现方式通常是：将 HDR 图像逐级下采样到 1×1 计算平均对数亮度，再用 EMA（指数移动平均）平滑过渡避免突变。自动曝光的关键参数包括适应速度（从暗到亮的过渡速度通常比从亮到暗更快，模拟人眼的不对称适应特性）和目标亮度范围（防止曝光过度或不足）。


抗闪烁（Anti-Flicker）是后处理 Bloom 中需要特别注意的问题。高亮度的小面积区域（如金属表面的高光点）在下采样时可能被遗漏——上一帧采样到了高光，下一帧没有——导致可见的闪烁。使用足够大的下采样滤波核（如 13-tap 滤波器而非简单的 4-tap）可以有效缓解这个问题。


运动模糊（Motion Blur）模拟相机快门在曝光时间内物体移动产生的模糊。基于运动向量的后处理运动模糊是最常用的实时方案——为每个像素计算屏幕空间的运动向量（当前帧与上一帧的位置差），沿运动方向采样并平均多个位置的颜色。对象级运动模糊和相机运动模糊都可以用这种方法统一处理。


色彩分级（Color Grading）使用 3D LUT（查找表）对最终图像进行色彩风格化。美术在 DaVinci Resolve 或 Photoshop 中创建色彩风格，导出为 3D LUT（通常 32³ 或 64³），引擎在后处理管线中对每个像素进行 3D 纹理采样完成色彩变换。这个操作极其高效（单次纹理采样），但可以实现极其丰富的色彩风格效果。


景深（Depth of Field, DOF）模拟镜头光圈的聚焦效果——焦点处清晰，前景和背景模糊。近处模糊圈（Circle of Confusion, CoC）的大小取决于到焦平面的距离。实时景深通常使用可分离的散点滤波（Scatter-as-Gather）：先计算每个像素的 CoC 大小，然后根据 CoC 大小选择模糊强度。


帧图与资源管理
现代渲染引擎使用帧图（Frame Graph / Render Graph）来声明式地描述一帧内所有渲染 Pass 的依赖关系和资源需求。帧图系统根据依赖关系自动确定 Pass 的执行顺序，管理渲染目标的生命周期（分配和回收），并插入必要的资源屏障（Layout Transition）。


帧图的优势包括：自动检测不再被使用的资源并回收（内存复用）；将无依赖的 Pass 并行化到不同的 GPU 队列；生成优化的资源屏障减少 GPU 空闲等待；全局视角下的资源管理避免了手动管理的错误。

Frostbite（EA）、UE5、和 Bevy（Rust 游戏引擎）都采用了帧图架构。帧图的声明式设计使得添加或移除渲染 Pass 不需要手动管理资源的创建销毁和状态转换，极大地简化了渲染管线的维护和迭代。


遮挡剔除与场景管理
在一个复杂的游戏场景中，大量物体被其他物体遮挡而不可见。如果不加区分地全部提交渲染，会产生大量无效的 GPU 工作。遮挡剔除（Occlusion Culling）技术在渲染之前或期间识别并排除不可见的物体。


视锥体剔除（Frustum Culling）是最基础的剔除——测试物体的包围盒是否与相机视锥体相交，完全在视锥体外的物体直接跳过。这通常在 CPU 端完成，使用场景的空间数据结构（八叉树或 BVH）加速。


硬件遮挡查询（Occlusion Query）在 GPU 上渲染物体的包围盒（不写入颜色/深度），查询通过深度测试的像素数量。如果为 0，物体被完全遮挡。但遮挡查询有一帧延迟——查询结果在下一帧才可用，可能导致物体消失一帧（Popping）。


GPU-Driven 渲染是最新的趋势。场景数据存储在 GPU 缓冲区中，GPU 上的计算着色器执行视锥体剔除、遮挡剔除和 LOD 选择，直接生成间接绘制命令（Indirect Draw Commands）。


CPU 只需要提交一个 Dispatch + 一个 DrawIndirect 调用，几乎不参与逐物体的决策。


深度金字塔（Hi-Z Pyramid）是 GPU-Driven 遮挡剔除的核心。上一帧的深度缓冲被生成为 Mipmap 金字塔，每级存储该区域的最远深度。当前帧将物体包围盒投影到屏幕空间，在对应的 Mipmap 级别上查询深度——如果包围盒的最近深度远于金字塔中的最远深度，物体被遮挡。两阶段剔除（第一阶段用上一帧 Hi-Z 粗剔除 → 渲染通过的物体 → 构建当前帧 Hi-Z → 第二阶段精确剔除残余物体）进一步减少了延迟带来的误判。


小结
    

  • 延迟渲染将几何和光照分离，光照计算只对可见像素执行，适合多光源场景
    • 

  • G-Buffer 的带宽消耗是延迟渲染的主要瓶颈，需要紧凑的数据编码
    • 

  • CSM 按深度分割视锥体，近处高分辨率远处低分辨率，解决方向光阴影精度问题
    • 

  • PCSS 根据遮挡物距离动态调整模糊半径，产生物理上合理的软阴影
    • 

  • Bloom 通过多级下采样和上采样实现高效的大范围辉光效果
    • 

  • ACES 色调映射是行业标准，提供良好的色彩保持和对比度
    • 

  • 帧图以声明式方式描述渲染 Pass 依赖，自动管理资源生命周期和状态转换
    • 

  • 分簇前向渲染结合了前向和延迟的优点，是现代引擎的主流选择
    • 

  • GPU-Driven 渲染让 GPU 自主完成剔除和 LOD 选择，最小化 CPU 参与
    • 

  • 深度金字塔是 GPU 遮挡剔除的核心数据结构，支持高效的屏幕空间遮挡测试
    •
