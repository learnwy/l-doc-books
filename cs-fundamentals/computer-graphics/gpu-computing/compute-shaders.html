计算着色器

核心概念

计算着色器（Compute Shader）是在 GPU 上执行通用计算的可编程着色器阶段。与图形管线中的顶点着色器和片元着色器不同，计算着色器不绑定到特定的渲染管线阶段——它独立运行，直接读写缓冲区和纹理，不生成图形输出。

这使得 GPU 的海量并行计算能力可以用于任意类型的数据处理。

计算着色器在游戏和实时渲染中的应用极为广泛：后处理效果（模糊、色调映射、景深）、粒子系统更新、物理模拟（布料、流体）、光照剔除（Tile/Cluster Light Culling）、GPU 驱动的遮挡剔除、GPU 排序、直方图计算等。

许多传统上由 CPU 执行或由图形管线间接处理的任务，都被迁移到计算着色器以获得更高的性能和灵活性。

工作组与线程模型
计算着色器的线程组织为三级层次：工作组（Workgroup / Thread Group）是调度的基本单位，一个 Dispatch 调用发射一个三维网格的工作组；每个工作组包含用户定义数量的线程（通常 64-256 个）；工作组内的线程可以通过共享内存通信和同步。


layout(local_size_x = 16, local_size_y = 16, local_size_z = 1) in;

void main() {
    uvec3 globalID = gl_GlobalInvocationID;
    uvec3 localID  = gl_LocalInvocationID;
    uvec3 groupID  = gl_WorkGroupID;

    uint pixelX = globalID.x;
    uint pixelY = globalID.y;
}
工作组大小的选择影响性能。工作组大小应该是 Warp 大小（NVIDIA 32 / AMD 64）的整数倍，以避免 Warp 中有空闲线程。过小的工作组（如 32 线程）可能无法充分利用 SM 的调度能力；过大的工作组（如 1024 线程）可能因寄存器和共享内存消耗导致低占用率。太小的工作组无法充分利用 SM 的并行能力，太大的工作组消耗过多寄存器和共享内存导致占用率下降。经验法则是 64-256 线程为佳。


工作组之间没有执行顺序保证，也不能直接通信（除了通过全局内存的原子操作）。工作组内部可以使用共享内存（Shared Memory）和屏障同步（Barrier）。barrier() 确保工作组内所有线程在屏障点之前的工作都已完成，之后的操作可以安全地读取其他线程写入的共享内存数据。


shared float tileData[16][16];

void main() {
    uint lx = gl_LocalInvocationID.x;
    uint ly = gl_LocalInvocationID.y;

    tileData[ly][lx] = loadFromGlobalMemory(gl_GlobalInvocationID.xy);

    barrier();

    float neighborSum = tileData[ly][lx-1] + tileData[ly][lx+1]
                      + tileData[ly-1][lx] + tileData[ly+1][lx];
}
原子操作与同步
计算着色器中的多个线程可能同时读写相同的内存位置，产生数据竞争。原子操作（Atomic Operations）保证对单个内存位置的读-改-写操作是不可分割的，所有并发线程的操作按某种顺序串行化。


常用的原子操作包括：atomicAdd（原子加）、atomicMin/Max（原子最小/最大值）、atomicExchange（原子交换）、atomicCompSwap（比较并交换，CAS）。


原子操作的性能远低于普通读写——全局内存的原子操作可能慢 10-100 倍，因为它需要在显存控制器层面串行化。


共享内存上的原子操作比全局内存快得多（在 SM 的 L1 缓存层面处理）。常见的优化模式是先在共享内存中做局部原子归约（Reduction），再将每个工作组的结果通过一次全局原子操作合并：


shared uint localHistogram[256];

void main() {
    if (gl_LocalInvocationIndex < 256)
        localHistogram[gl_LocalInvocationIndex] = 0;
    barrier();

    uint value = texelFetch(inputImage, ivec2(gl_GlobalInvocationID.xy), 0).r;
    uint bin = uint(value * 255.0);
    atomicAdd(localHistogram[bin], 1);
    barrier();

    if (gl_LocalInvocationIndex < 256)
        atomicAdd(globalHistogram[gl_LocalInvocationIndex],
                  localHistogram[gl_LocalInvocationIndex]);
}
内存屏障（Memory Barrier）控制内存操作的可见性。memoryBarrier() 确保屏障前的内存写入对屏障后的读取可见。memoryBarrierShared() 只针对共享内存，memoryBarrierBuffer() 针对缓冲区，memoryBarrierImage() 针对图像。在工作组内，barrier() 隐含了完整的内存屏障。


groupMemoryBarrier（GLSL）或 GroupMemoryBarrierWithGroupSync（HLSL）确保工作组内所有线程对共享内存的写入在屏障之后对所有线程可见。


memoryBarrier / DeviceMemoryBarrier 确保对全局内存的写入对其他工作组可见——这在多工作组协作的算法中至关重要。

GPU 并行算法模式
计算着色器中常用的并行算法模式包括归约、扫描、排序和过滤。


并行归约（Parallel Reduction）将数组的 N 个元素合并为一个值（如求和、求最大值）。经典的树形归约在 log₂(N) 步内完成，每步将活跃线程减半。在实际实现中，一个工作组先在共享内存中归约到一个值，然后多个工作组的结果再做一次全局归约。


并行前缀和（Parallel Prefix Sum / Scan）计算数组的累积和——output[i] = Σ input[0..i]。这是许多并行算法的基础操作（如流压缩、基数排序、粒子系统分配）。GPU 上的高效 Scan 实现分为三个阶段：上扫（Up-Sweep，类似归约）、设置根值、下扫（Down-Sweep，逆向传播前缀和）。


GPU 排序中最常用的是基数排序（Radix Sort）——它将数字按位分组，每组内使用计数排序（通过 Scan 实现），时间复杂度 O(kn) 其中 k 是位数。


GPU 基数排序可以对数亿个 32 位整数在毫秒级完成排序，远快于 CPU 上的快排。CUB（CUDA）和 VkRadixSort（Vulkan）是成熟的 GPU 排序库。


双调排序（Bitonic Sort）是另一种适合 GPU 的排序算法。它的比较模式是固定的（不依赖数据），因此所有线程的行为完全一致，没有分支发散。双调排序的时间复杂度 O(n log²n)，比基数排序的 O(kn) 稍慢，但实现更简单且对小规模数据效率更高。在需要排序的元素数量不超过工作组大小时，双调排序可以完全在共享内存中完成。


流压缩（Stream Compaction）从数组中移除不满足条件的元素并紧凑化。实现方式是：对条件掩码执行 Prefix Sum 得到每个有效元素的输出位置，然后按位置写入输出数组。这在 GPU 剔除（将通过遮挡测试的 Draw Call 紧凑化为间接绘制命令）中大量使用。


计算着色器的工程实践
计算着色器的性能优化围绕几个核心原则：最大化并行度、最小化内存延迟、避免线程发散。


数据布局对性能影响巨大。图像处理类任务通常使用 2D 工作组（如 16×16），与纹理的 Tile 布局对齐以优化缓存命中。


对于需要访问邻域数据的算法（如卷积），先将数据块（含 halo 区域）加载到共享内存，再从共享内存中读取，避免全局内存的重复访问。


Warp 级操作（Wave/Subgroup Operations）是最新的优化手段。它们允许 Warp 内的线程直接交换数据，无需经过共享内存。


subgroupAdd() 在 Warp 内求和，subgroupBallot() 收集 Warp 中满足条件的线程掩码，subgroupShuffle() 在线程间传递数据。这些操作的延迟接近于寄存器访问，极大地加速了 Warp 级别的协作计算。


异步计算（Async Compute）利用 GPU 上不同类型的工作负载可以同时执行的特性。图形管线和计算管线使用不同的硬件资源——计算着色器主要使用 ALU，而光栅化和 ROP 使用固定功能单元。


通过将计算工作提交到异步计算队列，GPU 可以在渲染管线的 ROP 阶段（此时 ALU 空闲）同时执行计算着色器，提升整体 GPU 利用率。


间接调度（Indirect Dispatch）与间接绘制类似，从 GPU 缓冲区中读取计算着色器的调度参数（工作组数量）。这使得一个计算着色器的输出可以直接驱动另一个计算着色器的调度，无需 CPU 回读数据。GPU-Driven 渲染管线大量依赖间接调度来实现完全 GPU 端的决策链路。


在实际项目中，计算着色器的应用已经远超图形领域。GPU 加速的文本搜索、JSON 解析、图像编解码、数据库查询等 GPGPU（通用 GPU 计算）应用越来越多。理解计算着色器的线程模型和内存层级是利用 GPU 计算能力的基础，无论应用领域是图形渲染还是通用数据处理。

小结
    

  • 计算着色器独立于图形管线运行，可直接读写缓冲区和纹理
    • 

  • 工作组是调度单位，大小应为 Warp 大小的整数倍以避免线程浪费
    • 

  • 共享内存实现工作组内线程通信，barrier() 确保数据可见性
    • 

  • 原子操作保证并发内存访问的正确性，共享内存原子远快于全局内存原子
    • 

  • 并行前缀和是 GPU 并行算法的基础操作，支撑排序和流压缩等高级算法
    • 

  • Warp 级操作以寄存器级延迟实现线程间数据交换，是最新的高效通信手段
    • 

  • 异步计算在图形管线空闲时填充 GPU 计算能力，提升整体利用率
    • 

  • 数据布局与 GPU 缓存对齐是计算着色器性能优化的首要考虑
    • 

  • 间接调度实现了 GPU 端的完全自治决策链，无需 CPU 回读数据
    • 

  • 计算着色器的应用已扩展到图形之外的 GPGPU 领域
    • 

  • Halo 区域预加载避免了全局内存的重复访问，是卷积类算法的标准优化模式
