Part III · 系统 (Systems)系统性能与优化 简介内存性能优化 简介分配策略

分配策略

核心概念

内存分配是程序运行时最基础的操作之一，但也是隐藏性能问题的常见来源。通用内存分配器（如 glibc 的 malloc）需要处理各种大小的分配请求、线程安全、碎片化管理等复杂问题，这些通用性带来了性能开销。针对特定场景选择或设计合适的分配策略，可以将分配操作从微秒级降到纳秒级，同时减少内存碎片和缓存污染。

栈分配与堆分配的权衡
栈分配是最快的分配方式——只需移动栈指针，无需查找空闲块、无需加锁。栈上的数据天然具有时间局部性（函数返回即释放），对缓存非常友好。然而栈的大小有限（默认通常 1-8MB），不适合大对象或生命周期超出函数作用域的对象。


// 栈分配: 极快，但有大小限制
void process_small() {
    int buffer[1024];         // 4KB，栈上分配
    char temp[256];           // 256B，栈上分配
    // 函数返回自动释放，无需手动管理
}

// 堆分配: 灵活但较慢
void process_large(size_t n) {
    int* buffer = malloc(n * sizeof(int));
    // ... 使用 buffer ...
    free(buffer);  // 必须手动释放
}

// 变长数组 (VLA) 可以在栈上动态分配（C99，某些编译器支持）
void process_vla(int n) {
    if (n > 10000) return;    // 防止栈溢出
    float data[n];            // 栈上动态分配
    // ...
}
在性能关键路径中，用栈分配替代堆分配是常见的微优化手段。典型技巧是小缓冲区优化（Small Buffer Optimization, SBO）——在结构体内预留一小块栈内存，只有当数据超过这个阈值时才转向堆分配。C++ 的 std::string 就使用了这种技术（SSO, Small String Optimization）：


class SmallString {
    static constexpr size_t SSO_SIZE = 22;
    union {
        char sso_buffer[SSO_SIZE + 1];
        struct {
            char* heap_ptr;
            size_t capacity;
        };
    };
    size_t length;
    bool is_heap;

public:
    const char* data() const {
        return is_heap ? heap_ptr : sso_buffer;
    }
};
Arena 分配器
Arena 分配器（也叫 Bump Allocator 或 Linear Allocator）是最简单也最快的自定义分配器。它维护一块预分配的大内存区域，分配时只需将指针向前移动，不支持单个对象的释放——所有对象在 Arena 生命周期结束时一次性释放。


#include <stdlib.h>
#include <string.h>

typedef struct Arena {
    char *base;
    size_t size;
    size_t offset;
} Arena;

Arena arena_create(size_t size) {
    Arena a;
    a.base = malloc(size);
    a.size = size;
    a.offset = 0;
    return a;
}

void* arena_alloc(Arena *a, size_t size, size_t align) {
    size_t aligned_offset = (a->offset + align - 1) & ~(align - 1);
    if (aligned_offset + size > a->size) return NULL;
    void *ptr = a->base + aligned_offset;
    a->offset = aligned_offset + size;
    return ptr;
}

void arena_reset(Arena *a) {
    a->offset = 0;  // 一次性"释放"所有分配
}

void arena_destroy(Arena *a) {
    free(a->base);
}
Arena 分配器的典型应用场景：


在编译器中，每个编译阶段（词法分析、语法分析、类型检查）的中间数据都适合用 Arena 分配——阶段结束后所有中间数据一起丢弃。Rust 的 bumpalo、Go 的 arena（实验性）和 Zig 的 std.mem.Allocator 都原生支持 Arena 模式。


对象池与 Slab 分配
对象池（Object Pool）预先分配固定数量的相同大小的对象，通过空闲链表管理。分配和释放都是 O(1) 操作，完全消除了碎片化问题。适用于频繁创建/销毁相同类型对象的场景。


#define POOL_SIZE 4096

typedef struct PoolNode {
    struct PoolNode *next;
} PoolNode;

typedef struct ObjectPool {
    char *memory;
    PoolNode *free_list;
    size_t obj_size;
} ObjectPool;

ObjectPool pool_create(size_t obj_size) {
    ObjectPool pool;
    pool.obj_size = obj_size < sizeof(PoolNode) ? sizeof(PoolNode) : obj_size;
    pool.memory = malloc(pool.obj_size * POOL_SIZE);
    pool.free_list = NULL;

    for (int i = POOL_SIZE - 1; i >= 0; i--) {
        PoolNode *node = (PoolNode*)(pool.memory + i * pool.obj_size);
        node->next = pool.free_list;
        pool.free_list = node;
    }
    return pool;
}

void* pool_alloc(ObjectPool *pool) {
    if (!pool->free_list) return NULL;
    PoolNode *node = pool->free_list;
    pool->free_list = node->next;
    return node;
}

void pool_free(ObjectPool *pool, void *ptr) {
    PoolNode *node = (PoolNode*)ptr;
    node->next = pool->free_list;
    pool->free_list = node;
}
Linux 内核的 Slab 分配器是对象池思想的工业级实现。它为每种内核对象类型（task_struct、inode、dentry 等）维护独立的缓存池，利用 CPU 本地缓存（per-CPU cache）避免跨核锁竞争。

现代通用分配器
当无法使用场景化分配器时，选择一个优秀的通用分配器同样重要。现代通用分配器在多线程环境下的性能比传统 glibc malloc 有显著提升。


jemalloc（Facebook/Meta 出品）通过 Thread Cache + Arena 分级设计减少锁竞争。每个线程有独立的小对象缓存，大对象使用跨线程的 Arena 池。


tcmalloc（Google 出品）类似思路，Thread-Caching Malloc。每个线程维护固定大小类别的空闲链表，小对象分配无需加锁。


mimalloc（Microsoft 出品）强调极致的小对象分配性能，使用 Segment/Page 两级结构，在微基准测试中通常是最快的。


# 替换默认分配器（Linux）
# jemalloc
LD_PRELOAD=/usr/lib/libjemalloc.so ./myapp
# tcmalloc
LD_PRELOAD=/usr/lib/libtcmalloc.so ./myapp
# mimalloc
LD_PRELOAD=/usr/lib/libmimalloc.so ./myapp
// jemalloc 提供的高级 API
#include <jemalloc/jemalloc.h>

void *ptr = mallocx(4096, MALLOCX_ALIGN(64));  // 对齐分配
size_t actual = sallocx(ptr, 0);                // 查询实际分配大小
ptr = rallocx(ptr, 8192, 0);                    // 原地扩展
dallocx(ptr, 0);                                // 释放
小结
    

  • 栈分配是最快的分配方式，性能关键路径优先考虑栈分配和小缓冲区优化
    • 

  • Arena 分配器适合生命周期一致的批量对象（如请求处理、编译阶段），分配 O(1)，释放无开销
    • 

  • 对象池适合频繁创建/销毁的固定大小对象，完全消除碎片化和分配器开销
    • 

  • 现代通用分配器（jemalloc/tcmalloc/mimalloc）通过线程本地缓存大幅减少多线程竞争
    • 

  • 分配策略的选择应该基于对象大小、生命周期和访问模式的分析，而非一刀切
    • 

  • 分配性能优化的核心原则：减少分配次数 > 选择合适的分配器 > 优化分配路径
    •
