操作系统调优

核心概念

操作系统是应用程序和硬件之间的桥梁，其内核参数直接影响系统性能的上限。Linux 的默认配置针对通用场景，但对于高性能服务器、数据库或低延迟交易系统，通常需要针对性调优。操作系统调优涉及 CPU 调度、内存管理、文件系统、网络栈和资源限制等多个子系统，核心原则是减少内核干预、降低上下文切换、最大化硬件利用率。

CPU 调度与绑核
Linux 的 CFS（Completely Fair Scheduler）调度器在通用场景下表现良好，但在低延迟场景中，进程在 CPU 核心之间的迁移会导致缓存失效和延迟抖动。CPU 亲和性（CPU Affinity）可以将进程或线程绑定到特定的 CPU 核心，避免迁移。


# 查看进程的 CPU 亲和性
taskset -p $(pgrep myapp)

# 绑定进程到 CPU 0-3
taskset -c 0-3 ./myapp

# 运行时修改
taskset -p -c 4-7 $(pgrep myapp)
在代码中设置 CPU 亲和性：


#define _GNU_SOURCE
#include <sched.h>
#include <pthread.h>

void pin_thread_to_core(int core_id) {
    cpu_set_t cpuset;
    CPU_ZERO(&cpuset);
    CPU_SET(core_id, &cpuset);
    pthread_setaffinity_np(pthread_self(), sizeof(cpuset), &cpuset);
}

void setup_worker_threads(int num_workers) {
    for (int i = 0; i < num_workers; i++) {
        pthread_t thread;
        pthread_create(&thread, NULL, worker_fn, (void*)(long)i);
        cpu_set_t cpuset;
        CPU_ZERO(&cpuset);
        CPU_SET(i + 2, &cpuset);  // 保留 CPU 0-1 给系统和中断
        pthread_setaffinity_np(thread, sizeof(cpuset), &cpuset);
    }
}
中断亲和性同样重要。网络中断如果集中在一个 CPU 核心上，会导致该核心过载。使用 irqbalance 或手动分配中断到不同核心：


# 查看中断分布
cat /proc/interrupts | head -20

# 手动将网卡中断绑定到特定 CPU
echo 2 > /proc/irq/28/smp_affinity   # 绑定到 CPU 1 (bitmask: 10)

# 使用 RPS (Receive Packet Steering) 分散网络处理
echo "ff" > /sys/class/net/eth0/queues/rx-0/rps_cpus
对于延迟极度敏感的应用（如高频交易），可以使用 isolcpus 将 CPU 核心完全隔离，避免内核在这些核心上调度其他任务：


# 在 GRUB 启动参数中隔离 CPU 4-7
GRUB_CMDLINE_LINUX="isolcpus=4-7 nohz_full=4-7 rcu_nocbs=4-7"
# 然后用 taskset 将关键进程绑定到隔离的核心上
内存管理调优
Swap 的使用是性能调优中最常见的议题。swap 允许系统在物理内存不足时将页面交换到磁盘，但磁盘速度比内存慢几个数量级。对于内存充足的服务器，应将 swappiness 降低：


# 几乎不使用 swap（但不完全禁用，保留紧急情况的缓冲）
sysctl -w vm.swappiness=1

# 完全禁用 swap（数据库推荐）
swapoff -a
大页内存（Huge Pages）将默认的 4KB 内存页增大到 2MB 或 1GB，减少 TLB 条目数量和页表层级，对大内存应用（如数据库、JVM）有显著性能提升：


# 静态大页（预留 8GB = 4096 个 2MB 页）
echo 4096 > /proc/sys/vm/nr_hugepages
# 挂载 hugetlbfs
mkdir -p /mnt/hugepages
mount -t hugetlbfs nodev /mnt/hugepages

# 透明大页 THP（不需要应用修改）
# 但 THP 的后台碎片整理可能导致延迟抖动，数据库通常建议关闭
echo madvise > /sys/kernel/mm/transparent_hugepage/enabled
echo madvise > /sys/kernel/mm/transparent_hugepage/defrag
NUMA 感知在多路服务器上至关重要。非一致内存访问（NUMA）架构中，每个 CPU 插槽有本地内存，访问本地内存比远端内存快 30-50%。应用应尽量在本地 NUMA 节点上分配内存：


# 查看 NUMA 拓扑
numactl --hardware

# 绑定到特定 NUMA 节点
numactl --cpunodebind=0 --membind=0 ./myapp

# 查看 NUMA 统计
numastat -p $(pgrep myapp)
# 关注 numa_miss 和 numa_foreign：非零表示跨节点访问
文件描述符与系统限制
Linux 的资源限制（ulimit）默认值通常过低，在高并发场景下会成为瓶颈：


# 查看当前限制
ulimit -a

# 设置打开文件数限制（临时）
ulimit -n 1000000

# 永久设置（/etc/security/limits.conf）
# *    soft    nofile    1000000
# *    hard    nofile    1000000
# *    soft    nproc     500000
# *    hard    nproc     500000

# 系统级限制
sysctl -w fs.file-max=2000000
sysctl -w fs.nr_open=2000000

# inotify 限制（影响文件监控）
sysctl -w fs.inotify.max_user_watches=524288
sysctl -w fs.inotify.max_user_instances=1024
综合调优示例
以下是一个面向高性能 Web 服务的综合调优配置：


# /etc/sysctl.d/99-perf.conf

# 内存
vm.swappiness=1
vm.overcommit_memory=1
vm.dirty_ratio=40
vm.dirty_background_ratio=10

# 网络
net.core.somaxconn=65535
net.core.netdev_max_backlog=65535
net.ipv4.tcp_max_syn_backlog=65535
net.ipv4.tcp_tw_reuse=1
net.ipv4.tcp_fin_timeout=10
net.ipv4.tcp_keepalive_time=60
net.ipv4.tcp_keepalive_intvl=10
net.ipv4.tcp_keepalive_probes=6
net.ipv4.ip_local_port_range=1024 65535
net.core.rmem_max=16777216
net.core.wmem_max=16777216
net.ipv4.tcp_rmem=4096 1048576 16777216
net.ipv4.tcp_wmem=4096 1048576 16777216
net.ipv4.tcp_congestion_control=bbr
net.core.default_qdisc=fq

# 文件系统
fs.file-max=2000000
fs.inotify.max_user_watches=524288
小结
    

  • 操作系统调优的第一步是测量基准，而非盲目修改参数
    • 

  • CPU 亲和性和中断亲和性减少核心间迁移，对低延迟场景至关重要
    • 

  • 生产服务器应将 swappiness 降至 1-10，数据库建议完全禁用 swap
    • 

  • 透明大页（THP）对数据库可能有害——设为 madvise 让应用自行决定
    • 

  • NUMA 感知在多路服务器上可带来 30-50% 的内存访问性能差异
    • 

  • 文件描述符和连接队列的默认限制通常过低，高并发服务必须调整
    •
