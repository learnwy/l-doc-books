Part III · 系统 (Systems)系统性能与优化 简介CPU 性能优化 简介分支预测

分支预测

核心概念

现代 CPU 使用深度流水线（通常 15-20 级）来实现指令级并行。当遇到条件分支（if/else、switch、循环条件）时，CPU 必须在分支条件计算完成之前决定接下来执行哪条路径——这就是分支预测（Branch Prediction）。预测正确时，流水线保持满载运行；预测错误时，必须丢弃已经投机执行的所有结果并重新开始，代价是 15-20 个 CPU 周期的流水线冲刷（Pipeline Flush）。

分支预测失败的性能影响
分支预测失败（Branch Misprediction）在高性能代码中的影响可以非常显著。一个经典的例子是对排序数组和未排序数组的条件累加：


#include <algorithm>
#include <cstdlib>
#include <ctime>

void conditional_sum(int* data, int size) {
    long sum = 0;
    for (int i = 0; i < size; i++) {
        if (data[i] >= 128) {  // 分支条件
            sum += data[i];
        }
    }
}

int main() {
    const int SIZE = 32768;
    int data[SIZE];

    srand(time(nullptr));
    for (int i = 0; i < SIZE; i++) {
        data[i] = rand() % 256;
    }

    // 未排序: data[i] >= 128 的结果随机 → 预测准确率约 50%
    conditional_sum(data, SIZE);  // 慢

    // 排序后: 前半段全 false，后半段全 true → 预测准确率接近 100%
    std::sort(data, data + SIZE);
    conditional_sum(data, SIZE);  // 快 5-6 倍
}
在未排序数组上，分支条件的结果是随机的，CPU 的预测准确率只有约 50%。排序后，前半段都不满足条件，后半段都满足，预测器可以轻松学到这个模式。两者的性能差异可达 5-6 倍，而唯一的区别是数据的排列顺序。


使用硬件性能计数器可以量化分支预测失败：


perf stat -e branches,branch-misses ./myapp

# 输出示例 (未排序):
#   524,288,000  branches
#   261,120,000  branch-misses  # 49.8% 的分支预测失败

# 输出示例 (排序后):
#   524,288,000  branches
#       512,000  branch-misses  # 0.1% 的分支预测失败
无分支编程技术
当分支预测准确率低时，可以通过无分支编程（Branchless Programming）技术将条件分支转换为算术或位运算，完全消除分支预测的问题。


// 有分支版本
int abs_branchy(int x) {
    if (x < 0) return -x;
    return x;
}

// 无分支版本
int abs_branchless(int x) {
    int mask = x >> 31;       // 负数: 全1，正数: 全0
    return (x ^ mask) - mask; // 负数: 取反+1（补码取反），正数: 不变
}

// 条件赋值的有分支版本
int max_branchy(int a, int b) {
    if (a > b) return a;
    return b;
}

// 条件赋值的无分支版本
int max_branchless(int a, int b) {
    return a ^ ((a ^ b) & -(a < b));
}

// 条件累加的无分支版本
long conditional_sum_branchless(int* data, int size) {
    long sum = 0;
    for (int i = 0; i < size; i++) {
        // 条件转化为掩码: (data[i] >= 128) 为 true 时 mask = -1，false 时 mask = 0
        int mask = -(data[i] >= 128);
        sum += data[i] & mask;
    }
    return sum;
}
现代编译器也能将简单的条件转换为条件移动指令（CMOVcc），无需程序员手动编写无分支代码。但编译器的判断并不总是最优的，在性能关键路径上值得检查生成的汇编：


// 编译器通常会将此优化为 cmov 指令
int min(int a, int b) {
    return a < b ? a : b;
}

// gcc -O2 生成的汇编:
//   cmpl %esi, %edi
//   cmovle %edi, %esi    ← 条件移动，无分支
//   movl %esi, %eax
//   ret
编译器提示与代码组织
即使不使用无分支编程，也可以通过编译器提示和代码组织来提高分支预测的准确率。


likely/unlikely 提示告诉编译器分支的倾向性，影响代码布局（将高频路径放在直通路径上，减少跳转）：


// Linux 内核中广泛使用
#define likely(x)   __builtin_expect(!!(x), 1)
#define unlikely(x) __builtin_expect(!!(x), 0)

int process_packet(Packet *pkt) {
    if (unlikely(pkt == NULL)) {     // 错误路径: 罕见
        return -1;
    }
    if (likely(pkt->type == DATA)) { // 数据包: 最常见
        return handle_data(pkt);
    }
    return handle_control(pkt);
}
C++20 引入了标准化的属性语法：


int process(int value) {
    if (value > 0) [[likely]] {
        return fast_path(value);
    } else [[unlikely]] {
        return slow_path(value);
    }
}
减少分支深度是另一个重要策略。嵌套的 if-else 链创建了多层分支，每一层都有预测失败的风险。使用查找表可以将多重分支转换为单次内存访问：


// 多分支版本: 最多 4 次分支预测
const char* day_name(int day) {
    if (day == 0) return "Sunday";
    else if (day == 1) return "Monday";
    else if (day == 2) return "Tuesday";
    else if (day == 3) return "Wednesday";
    else if (day == 4) return "Thursday";
    else if (day == 5) return "Friday";
    else return "Saturday";
}

// 查找表版本: 零分支
static const char* DAYS[] = {
    "Sunday", "Monday", "Tuesday", "Wednesday",
    "Thursday", "Friday", "Saturday"
};

const char* day_name_lut(int day) {
    return DAYS[day];  // 单次内存访问，无分支
}
间接分支与虚函数开销
间接分支（Indirect Branch）是跳转目标在运行时才确定的分支，例如虚函数调用、函数指针、switch 跳转表等。间接分支比条件分支更难预测，因为 CPU 不仅需要预测"是否跳转"，还需要预测"跳转到哪里"。


在面向对象编程中，频繁的虚函数调用（特别是多态迭代）会产生大量间接分支：


struct Shape {
    virtual double area() const = 0;
};

struct Circle : Shape {
    double r;
    double area() const override { return 3.14159 * r * r; }
};

struct Rectangle : Shape {
    double w, h;
    double area() const override { return w * h; }
};

// 如果 shapes 中的类型随机混合，间接分支预测失败率很高
double total_area(const std::vector<Shape*>& shapes) {
    double sum = 0;
    for (auto s : shapes) {
        sum += s->area();  // 间接调用: 每次可能跳转到不同地址
    }
    return sum;
}

// 按类型分组后处理: 每组内的间接分支目标一致，预测准确率接近 100%
double total_area_sorted(std::vector<Shape*>& shapes) {
    std::sort(shapes.begin(), shapes.end(),
              [](Shape* a, Shape* b) { return typeid(*a).hash_code() < typeid(*b).hash_code(); });
    double sum = 0;
    for (auto s : shapes) {
        sum += s->area();  // 同类型连续调用，预测准确率高
    }
    return sum;
}

小结
    

  • 分支预测失败的代价是 15-20 个 CPU 周期的流水线冲刷，在热循环中影响巨大
    • 

  • 数据的排列顺序会显著影响分支预测准确率——排序后的数据对分支更友好
    • 

  • 无分支编程将条件转化为算术运算，在预测困难的场景下效果显著
    • 

  • 编译器提示（likely/unlikely）影响代码布局，帮助提高直通路径的命中率
    • 

  • 间接分支比条件分支更难预测，虚函数密集调用时考虑按类型排序或去虚化
    • 

  • 优化分支前先用 perf stat 测量 branch-misses 比率——只在预测失败率高时才需要优化
    •
