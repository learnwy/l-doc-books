磁盘 I/O 优化

核心概念

磁盘 I/O 是大多数应用系统中速度最慢的组件。即使是现代 NVMe SSD，其随机读取延迟（~100μs）仍然比 DRAM 访问（~100ns）慢三个数量级。对于数据库、日志系统、文件服务器等 I/O 密集型应用，磁盘 I/O 优化直接决定了系统的吞吐量上限。优化的核心思路是：减少 I/O 次数、增大每次 I/O 的效率、选择合适的存储策略。

顺序 I/O 与随机 I/O
理解顺序 I/O 和随机 I/O 的性能差异是磁盘优化的基础。对于 HDD，顺序读写可以达到 150MB/s，但随机读写只有约 1MB/s——差距超过 100 倍。即使对于 SSD，顺序读写的吞吐量也是随机读写的 3-5 倍。


原因在于存储设备的物理特性。HDD 需要机械寻道（磁头移动）和旋转等待，每次随机访问的寻道时间约 5-10ms。SSD 虽然没有机械部件，但 NAND Flash 的读写粒度是页（通常 4-16KB），擦除粒度是块（通常 256KB-4MB），随机小写入会触发读-改-写放大。


# 使用 fio 测试顺序 vs 随机 I/O 性能
# 顺序读
fio --name=seqread --rw=read --bs=128k --size=1G --numjobs=1 \
    --ioengine=libaio --direct=1 --runtime=30

# 随机读
fio --name=randread --rw=randread --bs=4k --size=1G --numjobs=1 \
    --ioengine=libaio --direct=1 --runtime=30

# 典型 NVMe SSD 结果:
# 顺序读: ~3200 MB/s
# 随机读: ~800 MB/s (4K), ~60万 IOPS
将随机 I/O 转换为顺序 I/O 的经典技术：


// WAL (Write-Ahead Log): 将随机写转换为顺序追加
struct WAL {
    int fd;
    char *buffer;
    size_t buf_size;
    size_t buf_offset;
};

int wal_append(struct WAL *wal, const void *data, size_t len) {
    if (wal->buf_offset + len > wal->buf_size) {
        write(wal->fd, wal->buffer, wal->buf_offset);  // 刷盘
        wal->buf_offset = 0;
    }
    memcpy(wal->buffer + wal->buf_offset, data, len);
    wal->buf_offset += len;
    return 0;
}
数据库系统广泛使用的 LSM-Tree（Log-Structured Merge Tree）就是基于这个思想：所有写入先追加到内存表（MemTable），写满后作为排序文件（SSTable）顺序刷盘，后台异步合并。这种设计将随机写转化为了顺序写。


缓冲与预读策略
操作系统的页缓存（Page Cache）是磁盘 I/O 最重要的优化层。Linux 会将读取过的文件数据缓存在内存中，后续对相同数据的读取直接从内存返回，不触发磁盘 I/O。同时，内核的预读（Read-Ahead）机制会在检测到顺序读模式时，提前将后续数据读入缓存。


# 查看页缓存使用情况
free -h | grep "buff/cache"

# 调整预读大小（默认通常 128KB）
blockdev --getra /dev/sda       # 查看当前预读大小（单位: 512B 扇区）
blockdev --setra 2048 /dev/sda  # 设置为 1MB (2048 * 512B)

# 使用 vmtouch 查看文件在页缓存中的状态
vmtouch -v /var/lib/mysql/data/mydb/mytable.ibd
应用层的缓冲策略同样重要：


#include <stdio.h>

void write_unbuffered(const char *path, int n) {
    FILE *f = fopen(path, "w");
    setvbuf(f, NULL, _IONBF, 0);  // 无缓冲
    for (int i = 0; i < n; i++) {
        fprintf(f, "%d\n", i);  // 每次 fprintf 触发一次系统调用
    }
    fclose(f);
}

void write_buffered(const char *path, int n) {
    FILE *f = fopen(path, "w");
    char buf[65536];
    setvbuf(f, buf, _IOFBF, sizeof(buf));  // 64KB 全缓冲
    for (int i = 0; i < n; i++) {
        fprintf(f, "%d\n", i);  // 缓冲区满才触发系统调用
    }
    fclose(f);
}
对于绕过页缓存的场景（如数据库引擎自己管理缓存），使用 O_DIRECT 标志直接读写磁盘：


int fd = open("/data/dbfile", O_RDWR | O_DIRECT);
void *buf;
posix_memalign(&buf, 4096, 4096);  // O_DIRECT 要求对齐的缓冲区
pread(fd, buf, 4096, offset);      // 绕过页缓存直接读取
I/O 调度与合并
Linux 内核的 I/O 调度器负责对应用提交的 I/O 请求进行排序和合并，以优化磁盘访问模式。不同的调度器适合不同的存储设备：

特点

公平带宽分配，低延迟
HDD, 桌面

不做排序，仅合并

kyber
轻量级，面向 SSD 优化

# 查看当前调度器
cat /sys/block/sda/queue/scheduler

# 切换调度器
echo "mq-deadline" > /sys/block/sda/queue/scheduler

# NVMe SSD 建议使用 none
echo "none" > /sys/block/nvme0n1/queue/scheduler

# 调整 I/O 合并参数
echo 256 > /sys/block/sda/queue/nr_requests     # 队列深度
echo 2 > /sys/block/sda/queue/rq_affinity       # I/O 完成在提交的 CPU 上处理
I/O 合并（I/O Merging）是调度器的关键优化。当两个相邻的 I/O 请求访问连续的磁盘地址时，调度器将它们合并为一个大请求，减少磁盘操作次数。使用 iostat 可以观察合并效果：


iostat -xz 1
# rrqm/s wrqm/s: 每秒合并的读/写请求数
# 如果 wrqm/s 很高，说明应用的写入模式适合合并
# 如果 wrqm/s 接近 0，可能需要在应用层做写入合并
文件系统选择与配置
文件系统是应用和磁盘之间的抽象层，不同文件系统在元数据管理、日志机制和分配策略上有显著差异。


# ext4: Linux 默认，成熟稳定
mkfs.ext4 -O ^has_journal /dev/sda1           # 禁用日志（纯读场景）
mount -o noatime,nodiratime,discard /dev/sda1  # 禁用访问时间记录

# XFS: 大文件和高并发场景优秀
mkfs.xfs -f /dev/sda1
mount -o noatime,logbufs=8 /dev/sda1

# 通用性能挂载选项
mount -o noatime       # 不更新文件访问时间（减少写入）
mount -o nodiratime    # 不更新目录访问时间
mount -o discard       # SSD TRIM 支持
mount -o barrier=0     # 禁用写屏障（危险但更快，需 UPS）

小结
    

  • 磁盘 I/O 是最慢的系统组件，顺序 I/O 比随机 I/O 快 10-100 倍（取决于设备类型）
    • 

  • 将随机写转换为顺序写（WAL、LSM-Tree）是数据库和日志系统的核心设计模式
    • 

  • 页缓存是最重要的 I/O 优化层，但数据库引擎通常使用 O_DIRECT 自己管理缓存
    • 

  • I/O 调度器应根据存储设备类型选择：HDD 用 mq-deadline，NVMe SSD 用 none
    • 

  • 文件系统和挂载选项对 I/O 性能有显著影响，noatime 和正确的调度器是基础配置
    • 

  • I/O 优化的思路：缓存 > 批量 > 顺序化 > 硬件升级
    •
