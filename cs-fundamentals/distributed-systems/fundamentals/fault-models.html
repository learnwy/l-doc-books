故障模型与容错

概述

分布式系统中的故障是不可避免的。网络会分区、节点会崩溃、磁盘会损坏，甚至节点可能因为软件 bug 或恶意攻击而表现出任意行为。故障模型为我们提供了分类和推理这些故障的理论框架，而容错策略则是在给定故障模型下保证系统正确性的工程方法。

崩溃故障模型
崩溃-停止（Crash-Stop）
节点一旦故障就永久停止，不会恢复，也不会发送错误消息。


崩溃-恢复（Crash-Recovery）
节点崩溃后可以重启恢复，但内存中的状态会丢失，只能依赖持久化存储恢复。

        self.wal = WriteAheadLog(wal_path)
        self.state = self.wal.recover()

    def process(self, operation):
        self.wal.append(operation)
        self.wal.fsync()
        self.state.apply(operation)
        return self.state.result()

Phi Accrual 故障检测器
基于概率的自适应故障检测，根据历史心跳间隔动态调整判定阈值：


import math

class PhiAccrualDetector:
    def __init__(self, threshold=8.0, window_size=100):
        self.threshold = threshold
        self.intervals = []
        self.window_size = window_size
        self.last_heartbeat = None

    def heartbeat(self, now):
        if self.last_heartbeat is not None:
            interval = now - self.last_heartbeat
            self.intervals.append(interval)
            if len(self.intervals) > self.window_size:
                self.intervals.pop(0)
        self.last_heartbeat = now

    def phi(self, now):
        if not self.intervals:
            return 0.0
        elapsed = now - self.last_heartbeat
        mean = sum(self.intervals) / len(self.intervals)
        return elapsed / mean

    def is_available(self, now):
        return self.phi(now) < self.threshold

FLP 不可能性定理
Fischer、Lynch 和 Paterson 于 1985 年证明：在异步系统中，即使只有一个进程可能崩溃，也不存在确定性共识算法能保证终止。

最佳实践
    

  • 明确系统的故障假设——崩溃故障和拜占庭故障的容错方案截然不同
    • 

  • 使用 WAL（预写日志）保证崩溃-恢复场景下的状态持久性
    • 

  • 故障检测宁可误报（false positive）也不要漏报（false negative）
    • 

  • 使用指数退避 + 抖动作为默认重试策略，避免惊群效应
    • 

  • 通过 Chaos Engineering（如 Netflix Chaos Monkey）主动注入故障验证系统韧性
    • 

  • 设计时区分可恢复故障和不可恢复故障，采用不同的处理路径
