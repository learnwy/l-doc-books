API 网关与 BFF

概述

API 网关是微服务架构的统一入口，负责请求路由、协议转换、认证鉴权、限流熔断等横切关注点。BFF（Backend For Frontend）模式进一步为不同前端（Web、Mobile、第三方）提供定制化的 API 层，避免通用 API 的臃肿和低效。

import time

class TokenBucket:
    def __init__(self, rate, capacity):
        self.rate = rate
        self.capacity = capacity
        self.tokens = capacity
        self.last_refill = time.time()

    def allow(self):
        now = time.time()
        elapsed = now - self.last_refill
        self.tokens = min(self.capacity, self.tokens + elapsed * self.rate)
        self.last_refill = now
        if self.tokens >= 1:
            self.tokens -= 1
            return True
        return False

请求聚合示例
网关将多个后端调用合并为一个前端响应：


import asyncio
import aiohttp

async def aggregate_user_dashboard(user_id):
    async with aiohttp.ClientSession() as session:
        user_task = session.get(f"http://user-svc/users/{user_id}")
        orders_task = session.get(f"http://order-svc/users/{user_id}/orders")
        notifications_task = session.get(f"http://notification-svc/users/{user_id}/unread")

        user, orders, notifications = await asyncio.gather(
            user_task, orders_task, notifications_task
        )

        return {
            "user": await user.json(),
            "recent_orders": await orders.json(),
            "unread_count": await notifications.json(),
        }

最佳实践
    

  • API 网关只做横切关注点（路由、认证、限流），不要放业务逻辑
    • 

  • 多端差异大时使用 BFF 模式，由前端团队维护各自的 BFF
    • 

  • 限流策略分层设置——网关全局限流 + 各服务自身限流
    • 

  • 熔断超时时间根据下游服务 P99 延迟设置
    • 

  • 使用 OpenAPI/Swagger 规范管理 API 文档
    • 

  • 网关自身必须高可用——多实例部署 + 无状态设计
