服务注册与发现

概述

在微服务架构中，服务实例的数量和网络地址是动态变化的——实例会因扩缩容、故障恢复而频繁增减。服务发现机制使得调用方无需硬编码服务地址，而是通过注册中心动态获取可用的服务实例列表，实现灵活的服务间通信。

import random

class WeightedRoundRobin:
    def __init__(self, instances):
        self.instances = instances
        self.weights = [inst.weight for inst in instances]
        self.current_weights = [0] * len(instances)

    def next(self):
        total = sum(self.weights)
        max_idx = 0
        for i in range(len(self.instances)):
            self.current_weights[i] += self.weights[i]
            if self.current_weights[i] > self.current_weights[max_idx]:
                max_idx = i
        self.current_weights[max_idx] -= total
        return self.instances[max_idx]

最佳实践
    

  • Kubernetes 环境优先使用内置的 Service + DNS 机制
    • 

  • 非 K8s 环境推荐 Consul 或 Nacos，支持多语言和多种健康检查
    • 

  • 客户端发现搭配连接池和重试逻辑，性能优于服务端发现
    • 

  • 健康检查应包含核心依赖（数据库、缓存）的探测
    • 

  • 大规模微服务考虑引入服务网格（Istio/Linkerd）统一流量管理
    • 

  • 注册中心选择 CP 还是 AP 取决于业务容忍度——金融场景用 CP，互联网场景用 AP
