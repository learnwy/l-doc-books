分片与一致性哈希

概述

当数据量超出单节点的存储或处理能力时，必须将数据分片（Sharding/Partitioning）到多个节点。分片策略决定了数据如何分布、查询如何路由以及系统如何扩缩容。一致性哈希是解决节点动态变化时数据迁移量最小化的经典方案。

分片策略

策略对比

策略 原理 优点 缺点
哈希分片 hash(key) % N 分布均匀 扩缩容需全量迁移

哈希分片

def hash_partition(key: str, num_nodes: int) -> int:
    return hash(key) % num_nodes

问题：当 num_nodes 变化时（如从 3 扩到 4），几乎所有 key 的映射都会改变。

一致性哈希

基本原理

将哈希空间组织成一个环（0 ~ 2³²-1），节点和数据 key 都映射到环上。每个 key 沿顺时针方向找到的第一个节点即为负责节点。

虚拟节点
真实节点映射到多个虚拟节点，解决节点数量少时的不均匀问题：


class ConsistentHash:
    def __init__(self, nodes, replicas=150):
        self.ring = {}
        self.sorted_keys = []
        self.replicas = replicas
        for node in nodes:
            self.add_node(node)

    def add_node(self, node):
        for i in range(self.replicas):
            key = self._hash(f"{node}:{i}")
            self.ring[key] = node
            self.sorted_keys.append(key)
        self.sorted_keys.sort()

    def get_node(self, data_key):
        h = self._hash(data_key)
        for key in self.sorted_keys:
            if h <= key:
                return self.ring[key]
        return self.ring[self.sorted_keys[0]]

    def _hash(self, key):
        import hashlib
        return int(hashlib.md5(key.encode()).hexdigest(), 16)
