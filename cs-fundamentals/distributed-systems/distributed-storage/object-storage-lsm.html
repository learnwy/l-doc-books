对象存储与 LSM-Tree

概述

LSM-Tree（Log-Structured Merge-Tree）是现代分布式存储系统中最重要的写优化数据结构。从 Google 的 Bigtable 到 LevelDB、RocksDB，再到 Cassandra 和 TiKV，LSM-Tree 为高吞吐写入场景提供了卓越的性能。本节还将介绍基于对象存储的分布式存储方案。

写放大计算
Leveled Compaction:
  每层大小比例 = 10
  最坏写放大 = 10 × 层数

  Level 0 → Level 1: 数据被合并写入
  Level 1 → Level 2: 与 L2 中重叠的 SSTable 合并

  一条数据从 L0 到 L6: 最多写入 10 × 6 = 60 次

import mmh3
from bitarray import bitarray

class BloomFilter:
    def __init__(self, size, num_hashes):
        self.size = size
        self.num_hashes = num_hashes
        self.bits = bitarray(size)
        self.bits.setall(0)

    def add(self, key):
        for i in range(self.num_hashes):
            idx = mmh3.hash(key, i) % self.size
            self.bits[idx] = 1

    def might_contain(self, key):
        return all(
            self.bits[mmh3.hash(key, i) % self.size]
            for i in range(self.num_hashes)
        )

最佳实践
    

  • 写密集场景优先选择 LSM-Tree 引擎（RocksDB），读密集考虑 B-Tree（InnoDB）
    • 

  • 根据读写比例选择 Compaction 策略——读多用 Leveled，写多用 Size-Tiered
    • 

  • Bloom Filter 是 LSM-Tree 点查性能的关键，务必启用
    • 

  • 监控写放大和空间放大指标，及时调整 Compaction 参数
    • 

  • 对象存储适合存储不可变的大文件（图片、视频、日志归档）
    • 

  • 冷热数据分离：热数据用高性能 SSD + LSM-Tree，冷数据下沉到对象存储
    •
