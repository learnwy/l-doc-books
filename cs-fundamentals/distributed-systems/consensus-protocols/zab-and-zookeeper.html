Zab 与 ZooKeeper

概述

ZAB（ZooKeeper Atomic Broadcast）是 Apache ZooKeeper 使用的原子广播协议。与 Paxos 和 Raft 不同，ZAB 专门为**主备（primary-backup）**系统设计，侧重于高效的状态复制和崩溃恢复。ZooKeeper 作为分布式协调服务，广泛用于配置管理、分布式锁、领导选举等场景。

ZXID 结构
ZXID 是 64 位事务 ID，由两部分组成：


ZXID = [epoch (高32位)] [counter (低32位)]

epoch:   Leader 轮次，每次新 Leader 选举 +1
counter: 当前 epoch 内的事务序号，从 0 开始

Leader 选举算法
ZooKeeper 使用 Fast Leader Election：


    

  1. 每个节点发起投票，初始投自己 (myid, zxid)
    2. 

  2. 收到其他投票后，比较 zxid（优先）和 myid
    3. 

  3. 更新投票为更优的候选人，重新广播
    4. 

  4. 当某个候选人获得多数派支持时，选举完成
    5. 



def compare_vote(vote_a, vote_b):
    if vote_a.zxid != vote_b.zxid:
        return vote_a.zxid > vote_b.zxid
    return vote_a.myid > vote_b.myid

Watch 特性：


    

  • 一次性：触发后需重新注册
    • 

  • 有序性：Watch 通知的顺序与事件发生顺序一致
    • 

  • 轻量级：只通知变化发生，不传递变化内容
    • 





最佳实践
    

  • 避免在 ZooKeeper 中存储大量数据——它是协调服务而非数据库
    • 

  • ZNode 数据量建议不超过 1MB
    • 

  • 使用 Curator 等高级客户端库简化分布式锁和选举的实现
    • 

  • Watch 是一次性的，务必在回调中重新注册
    • 

  • 读请求默认不保证线性一致，需要强一致读时使用 sync() + getData()
    • 

  • 新项目建议考虑 etcd 作为替代，其 API 更现代且支持线性一致读
