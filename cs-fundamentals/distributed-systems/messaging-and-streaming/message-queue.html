消息队列模型与选型

概述

消息队列（Message Queue）是分布式系统中实现异步通信的核心组件。它在生产者和消费者之间充当缓冲层，实现服务解耦、流量削峰和异步处理。不同的消息队列系统在消息模型、可靠性保证和性能特征上各有侧重，选型需要根据业务场景做出权衡。

消息模型

点对点（Queue）

每条消息只被一个消费者处理，消费后即从队列中移除。


发布/订阅（Pub/Sub）
每条消息被所有订阅者接收，每个订阅者独立消费。

At-Least-Once + 幂等
在实践中，最常用的方案是 At-Least-Once 投递 + 消费端幂等处理：


class IdempotentConsumer:
    def __init__(self, db):
        self.db = db

    def process(self, message):
        msg_id = message.id
        if self.db.exists("processed_messages", msg_id):
            return
        with self.db.transaction():
            self.handle_business(message)
            self.db.insert("processed_messages", msg_id)

    def handle_business(self, message):
        pass

选型决策树


最佳实践
    

  • 默认选择 At-Least-Once + 消费端幂等，Exactly-Once 成本过高且大多数场景不必要
    • 

  • 消息体尽量小（< 1MB），大数据通过引用传递（消息中只放 URL/ID）
    • 

  • 设置合理的消费超时和重试次数，配合死信队列兜底
    • 

  • 生产环境必须开启消息持久化和多副本复制
    • 

  • 监控消费者 Lag（堆积量），及时扩容消费者
    • 

  • 消息 key 选择要保证相同业务实体（如订单 ID）路由到同一分区，确保顺序性
