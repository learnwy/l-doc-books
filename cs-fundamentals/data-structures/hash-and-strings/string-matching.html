字符串匹配算法

字符串匹配（String Matching）是计算机科学中最经典的问题之一：给定文本串 TTT（长度为 nnn）和模式串 PPP（长度为 mmm），找出 PPP 在 TTT 中所有出现的位置。从文本编辑器的查找替换，到生物信息学中的 DNA 序列比对，字符串匹配无处不在。

暴力匹配（Brute Force）

基本思想

最直观的方法：从文本串的每个位置开始，逐字符与模式串进行比较。如果某个字符不匹配，就将模式串右移一位，从头开始重新比较。

TypeScript 实现
function bruteForce(text: string, pattern: string): number[] {
  const n = text.length;
  const m = pattern.length;
  const positions: number[] = [];
  for (let i = 0; i <= n - m; i++) {
    let j = 0;
    while (j < m && text[i + j] === pattern[j]) {
      j++;
    }
    if (j === m) {
      positions.push(i);
    }
  }
  return positions;
}

console.log(bruteForce('ABABDABACDABABCABAB', 'ABABCABAB'));
// 输出: [9]
复杂度
    

  • 时间复杂度：最坏 O(nm)O(nm)O(nm)，例如 T = "AAAAAA...A", P = "AAA...AB"，每次都要比较到最后才失败。
    • 

  • 空间复杂度：O(1)O(1)O(1)（不计输出）。
    • 





暴力法的核心缺陷在于：当失配发生时，它会丢弃已经比较过的信息，将模式串仅右移一位。KMP 算法正是为了解决这一问题而诞生的。




KMP 算法（Knuth-Morris-Pratt）
核心思想
KMP 算法的核心洞见：当在位置 jjj 发生失配时，我们已经知道 P[0..j−1]P[0..j-1]P[0..j−1] 与 TTT 中对应的字符是匹配的。利用模式串自身的前缀与后缀的重叠信息，可以避免不必要的回退，直接将模式串跳转到一个安全位置继续匹配。


部分匹配表（Failure Function）
部分匹配表 next[j] 表示：模式串 P[0..j]P[0..j]P[0..j] 中，最长的相等真前缀与真后缀的长度。

解读 next[3] = 2：子串 ABAB 的最长相等真前缀与真后缀为 AB，长度为 2。这意味着当 P[4]P[4]P[4] 失配时，可以直接跳到 P[2]P[2]P[2] 继续比较，因为 P[0..1]P[0..1]P[0..1] 已经与文本匹配。


KMP 匹配过程可视化
TypeScript 实现
function buildNext(pattern: string): number[] {
  const m = pattern.length;
  const nextTable = new Array<number>(m).fill(0);
  let j = 0;
  for (let i = 1; i < m; i++) {
    while (j > 0 && pattern[i] !== pattern[j]) {
      j = nextTable[j - 1];
    }
    if (pattern[i] === pattern[j]) {
      j++;
    }
    nextTable[i] = j;
  }
  return nextTable;
}

function kmpSearch(text: string, pattern: string): number[] {
  const n = text.length;
  const m = pattern.length;
  if (m === 0) {
    return [];
  }
  const nextTable = buildNext(pattern);
  const positions: number[] = [];
  let j = 0;
  for (let i = 0; i < n; i++) {
    while (j > 0 && text[i] !== pattern[j]) {
      j = nextTable[j - 1];
    }
    if (text[i] === pattern[j]) {
      j++;
    }
    if (j === m) {
      positions.push(i - m + 1);
      j = nextTable[j - 1];
    }
  }
  return positions;
}

console.log(kmpSearch('ABABDABACDABABCABAB', 'ABABCABAB'));
// 输出: [9]
复杂度
    

  • 预处理（构建 next 表）：O(m)O(m)O(m)
    • 

  • 匹配过程：O(n)O(n)O(n)
    • 

  • 总时间复杂度：O(n+m)O(n + m)O(n+m)
    • 

  • 空间复杂度：O(m)O(m)O(m)（存储 next 表）
    • 





KMP 之所以能做到 O(n+m)O(n+m)O(n+m)，关键在于文本指针 iii 永远不会回退。每次失配时，只有模式指针 jjj 通过 next 表跳转，而 iii 始终单调递增。




Rabin-Karp 算法（滚动哈希）
核心思想
Rabin-Karp 采用哈希的方式进行字符串匹配：先计算模式串的哈希值，然后用**滚动哈希（Rolling Hash）**在 O(1)O(1)O(1) 时间内依次计算文本中每个长度为 mmm 的子串的哈希值，只有哈希值相等时才逐字符验证。


滚动哈希公式
选择基数 ddd（通常取字符集大小，如 256）和大素数 qqq：


H(s[i..i+m−1])=(∑k=0m−1s[i+k]⋅dm−1−k) mod qH(s[i..i{+}m{-}1]) = \left(\sum_{k=0}^{m-1} s[i+k] \cdot d^{m-1-k}\right) \bmod qH(s[i..i+m−1])=(k=0∑m−1​s[i+k]⋅dm−1−k)modq
滚动更新（从位置 iii 滑动到 i+1i+1i+1）：


Hi+1=(d⋅(Hi−s[i]⋅dm−1)+s[i+m]) mod qH_{i+1} = \left(d \cdot (H_i - s[i] \cdot d^{m-1}) + s[i+m]\right) \bmod qHi+1​=(d⋅(Hi​−s[i]⋅dm−1)+s[i+m])modq
TypeScript 实现
function rabinKarp(text: string, pattern: string, d: number = 256, q: number = 101): number[] {
  const n = text.length;
  const m = pattern.length;
  if (m > n) {
    return [];
  }

  let h = 1;
  for (let i = 0; i < m - 1; i++) {
    h = (h * d) % q;
  }

  let pHash = 0;
  let tHash = 0;
  const positions: number[] = [];

  for (let i = 0; i < m; i++) {
    pHash = (d * pHash + pattern.charCodeAt(i)) % q;
    tHash = (d * tHash + text.charCodeAt(i)) % q;
  }

  for (let i = 0; i <= n - m; i++) {
    if (pHash === tHash) {
      if (text.substring(i, i + m) === pattern) {
        positions.push(i);
      }
    }
    if (i < n - m) {
      tHash = (d * (tHash - text.charCodeAt(i) * h) + text.charCodeAt(i + m)) % q;
      tHash = ((tHash % q) + q) % q;
    }
  }

  return positions;
}

console.log(rabinKarp('ABABDABACDABABCABAB', 'ABABCABAB'));
// 输出: [9]
复杂度
    

  • 平均时间复杂度：O(n+m)O(n + m)O(n+m)（哈希冲突极少时）
    • 

  • 最坏时间复杂度：O(nm)O(nm)O(nm)（所有位置都发生哈希冲突，退化为逐字符验证）
    • 

  • 空间复杂度：O(1)O(1)O(1)
    • 





Rabin-Karp 的最大优势在于多模式匹配场景——当需要同时搜索多个模式串时，只需预计算每个模式串的哈希值，然后在一次文本扫描中并行比较，效率远超其他算法。




Boyer-Moore 算法
Boyer-Moore 是实际应用中最快的单模式串匹配算法之一（如 GNU grep 的默认算法）。它从模式串的尾部向头部比较，利用两个启发规则实现大幅跳跃：


坏字符规则（Bad Character Rule）
当文本字符 T[i]T[i]T[i] 与模式字符 P[j]P[j]P[j] 失配时，在模式串中从右往左查找 T[i]T[i]T[i] 最后出现的位置 kkk：


    

  • 若 k<jk < jk<j：将模式串右移 j−kj - kj−k 位，使 P[k]P[k]P[k] 对齐 T[i]T[i]T[i]。
    • 

  • 若 kkk 不存在：将模式串整体移过失配位置。
    • 



好后缀规则（Good Suffix Rule）
当失配发生时，已匹配的后缀 P[j+1..m−1]P[j+1..m-1]P[j+1..m−1] 是一个"好后缀"。在模式串中寻找该好后缀的另一次出现（或其后缀作为模式串前缀的情况），并据此移动模式串。


简化版 TypeScript 实现（仅坏字符规则）
function boyerMooreBadChar(text: string, pattern: string): number[] {
  const n = text.length;
  const m = pattern.length;

  const badChar = new Map<string, number>();
  for (let i = 0; i < m; i++) {
    badChar.set(pattern[i], i);
  }

  const positions: number[] = [];
  let i = 0;
  while (i <= n - m) {
    let j = m - 1;
    while (j >= 0 && pattern[j] === text[i + j]) {
      j--;
    }
    if (j < 0) {
      positions.push(i);
      i += i + m < n ? m - (badChar.get(text[i + m]) ?? -1) : 1;
    } else {
      const shift = j - (badChar.get(text[i + j]) ?? -1);
      i += Math.max(1, shift);
    }
  }
  return positions;
}

console.log(boyerMooreBadChar('ABABDABACDABABCABAB', 'ABABCABAB'));
// 输出: [9]
复杂度
    

  • 最好时间复杂度：O(n/m)O(n/m)O(n/m)（亚线性！每次跳过整个模式串长度）
    • 

  • 最坏时间复杂度：O(nm)O(nm)O(nm)（仅坏字符规则），加上好后缀规则后为 O(n+m)O(n + m)O(n+m)
    • 

  • 空间复杂度：O(∣Σ∣)O(|\Sigma|)O(∣Σ∣)（∣Σ∣|\Sigma|∣Σ∣ 为字符集大小）
    • 





Boyer-Moore 的亚线性最优时间复杂度 O(n/m)O(n/m)O(n/m) 说明：文本越长、模式串越长，它反而可能越快——因为每次失配都可能跳过很多字符。这在处理大文本时具有显著优势。

小结
    

  • 暴力匹配是理解问题的起点，O(nm)O(nm)O(nm) 的复杂度在短串场景下完全可接受。
    • 

  • KMP 通过部分匹配表（failure function）消除了文本指针的回退，保证了严格的 O(n+m)O(n+m)O(n+m) 最坏复杂度，是理论上最优雅的解法。
    • 

  • Rabin-Karp 借助滚动哈希将匹配转化为数值比较，在多模式匹配场景中具有独特优势。
    • 

  • Boyer-Moore 利用从右向左匹配和两种跳跃规则，在实际大文本搜索中表现最优，是工业级工具（如 grep）的首选算法。
    • 

  • 选择算法时应综合考虑文本规模、模式串数量、字符集特征和最坏情况容忍度。
    •
