LRU/LFU 缓存

核心概念

缓存（Cache）是一种通过存储近期或高频访问数据来加速后续访问的技术。当缓存空间满时，需要**淘汰策略（Eviction Policy）**决定移除哪些数据。LRU（Least Recently Used，最近最少使用）和 LFU（Least Frequently Used，最不经常使用）是两种最经典的缓存淘汰策略，它们要求所有操作——get 和 put——都在 O(1)O(1)O(1) 时间内完成。

LRU 缓存：双向链表 + 哈希表
LRU 的核心数据结构是双向链表 + 哈希表的组合。双向链表按访问时间排序，最近访问的节点在链表头部，最久未访问的在尾部。哈希表提供 O(1)O(1)O(1) 的键到链表节点的映射。


class DLinkedNode {
  key: number;
  value: number;
  prev: DLinkedNode | null;
  next: DLinkedNode | null;

  constructor(key: number = 0, value: number = 0) {
    this.key = key;
    this.value = value;
    this.prev = null;
    this.next = null;
  }
}

class LRUCache {
  private capacity: number;
  private size: number;
  private cache: Map<number, DLinkedNode>;
  private head: DLinkedNode;
  private tail: DLinkedNode;

  constructor(capacity: number) {
    this.capacity = capacity;
    this.size = 0;
    this.cache = new Map();
    this.head = new DLinkedNode();
    this.tail = new DLinkedNode();
    this.head.next = this.tail;
    this.tail.prev = this.head;
  }

  get(key: number): number {
    const node = this.cache.get(key);
    if (!node) return -1;
    this.moveToHead(node);
    return node.value;
  }

  put(key: number, value: number): void {
    const node = this.cache.get(key);
    if (node) {
      node.value = value;
      this.moveToHead(node);
      return;
    }

    const newNode = new DLinkedNode(key, value);
    this.cache.set(key, newNode);
    this.addToHead(newNode);
    this.size++;

    if (this.size > this.capacity) {
      const removed = this.removeTail();
      this.cache.delete(removed.key);
      this.size--;
    }
  }

  private addToHead(node: DLinkedNode): void {
    node.prev = this.head;
    node.next = this.head.next;
    this.head.next!.prev = node;
    this.head.next = node;
  }

  private removeNode(node: DLinkedNode): void {
    node.prev!.next = node.next;
    node.next!.prev = node.prev;
  }

  private moveToHead(node: DLinkedNode): void {
    this.removeNode(node);
    this.addToHead(node);
  }

  private removeTail(): DLinkedNode {
    const node = this.tail.prev!;
    this.removeNode(node);
    return node;
  }
}
使用示例：


const lru = new LRUCache(2);
lru.put(1, 1);
lru.put(2, 2);
console.log(lru.get(1)); // 1
lru.put(3, 3);
console.log(lru.get(2)); // -1 (已被淘汰)
lru.put(4, 4);
console.log(lru.get(1)); // -1 (已被淘汰)
console.log(lru.get(3)); // 3
console.log(lru.get(4)); // 4

LFU 缓存：频率桶 + 双向链表
LFU 淘汰访问频率最低的元素。当多个元素频率相同时，淘汰最久未访问的（LRU 作为 tie-breaker）。实现 O(1)O(1)O(1) 的 LFU 需要更精巧的数据结构设计。


核心思路是维护一个频率到双向链表的映射：每个频率值对应一条双向链表，链表中存储该频率的所有缓存节点（按访问时间排序）。同时维护一个 minFreq 变量追踪当前最低频率。


class LFUNode {
  key: number;
  value: number;
  freq: number;
  prev: LFUNode | null;
  next: LFUNode | null;

  constructor(key: number = 0, value: number = 0) {
    this.key = key;
    this.value = value;
    this.freq = 1;
    this.prev = null;
    this.next = null;
  }
}

class FreqList {
  head: LFUNode;
  tail: LFUNode;
  size: number;

  constructor() {
    this.head = new LFUNode();
    this.tail = new LFUNode();
    this.head.next = this.tail;
    this.tail.prev = this.head;
    this.size = 0;
  }

  addFirst(node: LFUNode): void {
    node.prev = this.head;
    node.next = this.head.next;
    this.head.next!.prev = node;
    this.head.next = node;
    this.size++;
  }

  remove(node: LFUNode): void {
    node.prev!.next = node.next;
    node.next!.prev = node.prev;
    this.size--;
  }

  removeLast(): LFUNode {
    const node = this.tail.prev!;
    this.remove(node);
    return node;
  }

  isEmpty(): boolean {
    return this.size === 0;
  }
}

class LFUCache {
  private capacity: number;
  private size: number;
  private minFreq: number;
  private cache: Map<number, LFUNode>;
  private freqMap: Map<number, FreqList>;

  constructor(capacity: number) {
    this.capacity = capacity;
    this.size = 0;
    this.minFreq = 0;
    this.cache = new Map();
    this.freqMap = new Map();
  }

  get(key: number): number {
    const node = this.cache.get(key);
    if (!node) return -1;
    this.increaseFreq(node);
    return node.value;
  }

  put(key: number, value: number): void {
    if (this.capacity === 0) return;

    const node = this.cache.get(key);
    if (node) {
      node.value = value;
      this.increaseFreq(node);
      return;
    }

    if (this.size >= this.capacity) {
      const minList = this.freqMap.get(this.minFreq)!;
      const removed = minList.removeLast();
      this.cache.delete(removed.key);
      this.size--;
    }

    const newNode = new LFUNode(key, value);
    this.cache.set(key, newNode);
    this.getOrCreateFreqList(1).addFirst(newNode);
    this.minFreq = 1;
    this.size++;
  }

  private increaseFreq(node: LFUNode): void {
    const oldFreq = node.freq;
    const oldList = this.freqMap.get(oldFreq)!;
    oldList.remove(node);

    if (oldList.isEmpty() && this.minFreq === oldFreq) {
      this.minFreq++;
    }

    node.freq++;
    this.getOrCreateFreqList(node.freq).addFirst(node);
  }

  private getOrCreateFreqList(freq: number): FreqList {
    let list = this.freqMap.get(freq);
    if (!list) {
      list = new FreqList();
      this.freqMap.set(freq, list);
    }
    return list;
  }
}
使用示例：


const lfu = new LFUCache(2);
lfu.put(1, 1);
lfu.put(2, 2);
console.log(lfu.get(1)); // 1 (freq: 1→2)
lfu.put(3, 3);
console.log(lfu.get(2)); // -1 (freq=1, 被淘汰)
console.log(lfu.get(3)); // 3
lfu.put(4, 4);
console.log(lfu.get(1)); // -1 (freq=2, 但容量满时 freq=1 的 key3 被淘汰... key1 freq=2 保留)
console.log(lfu.get(3)); // -1
console.log(lfu.get(4)); // 4
工程中的缓存策略选择
在实际系统中，缓存策略的选择取决于访问模式的特征。






访问模式
最佳策略
原因





时间局部性强
LRU
最近访问的数据最可能再次访问




频率偏斜明显
LFU
热点数据频率远高于冷数据




扫描污染多
LFU / LRU-K
LRU 对顺序扫描极其脆弱




工作集稳定
LRU
简单高效，工作集自然保持在缓存中




频率变化快
LRU / LRFU
纯 LFU 对频率变化适应慢





**缓存污染（Cache Pollution）**是 LRU 的主要弱点：一次大规模顺序扫描会将大量低价值数据加载到缓存中，挤出真正的热点数据。LFU 对此天然免疫（低频数据很快被淘汰），但 LFU 的弱点是频率累积导致"历史热点"长期霸占缓存。


常见改进策略
LRU-K：只有当一个数据被访问 KKK 次后才进入缓存，有效抵御扫描污染。MySQL InnoDB 的 Buffer Pool 使用类似的 Young/Old 分代策略。


带频率衰减的 LFU：定期将所有频率减半，使旧热点的频率逐渐降低，让新热点有机会进入缓存。


W-TinyLFU（Caffeine 库采用）：结合 LRU 窗口 + LFU 主缓存 + 频率素描（Count-Min Sketch），是目前最先进的通用缓存策略之一。


小结
    

  • LRU 缓存通过双向链表 + 哈希表实现 O(1)O(1)O(1) 的 get 和 put，淘汰最久未访问的数据
    • 

  • LFU 缓存通过频率桶映射 + 双向链表 + 哈希表实现 O(1)O(1)O(1) 操作，淘汰访问频率最低的数据
    • 

  • LRU 的核心操作是移动到链表头部（标记为最近访问）和删除链表尾部（淘汰最久未访问）
    • 

  • LFU 的核心操作是频率提升（从旧频率桶移到新频率桶）和最低频率追踪（minFreq 变量）
    • 

  • LRU 对缓存污染敏感，LFU 对频率变化适应慢——实际系统常用混合策略如 W-TinyLFU
    • 

  • 这两种缓存是技术面试的高频考点，也是操作系统、数据库和 CDN 等基础设施的核心组件
