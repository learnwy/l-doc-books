平衡树

为什么需要平衡

在上一节中我们看到，普通二叉搜索树（BST）在最坏情况下会退化为链表，导致所有操作的时间复杂度从 O(log⁡n)O(\log n)O(logn) 退化为 O(n)O(n)O(n)。





场景
树高
查找/插入/删除





平衡 BST
O(log⁡n)O(\log n)O(logn)
O(log⁡n)O(\log n)O(logn)




退化 BST（链表）
O(n)O(n)O(n)
O(n)O(n)O(n)







当 n=106n = 10^6n=106 时，log⁡2n≈20\log_2 n \approx 20log2​n≈20，而 n=106n = 10^6n=106。平衡与否带来的是 20 次比较 vs 100 万次比较的差距。




自平衡二叉搜索树通过在插入和删除时自动调整树的结构，确保树的高度始终维持在 O(log⁡n)O(\log n)O(logn)，从而保证所有操作的最坏时间复杂度为 O(log⁡n)O(\log n)O(logn)。




AVL 树
AVL 树（以发明者 Adelson-Velsky 和 Landis 命名）是最早被提出的自平衡二叉搜索树（1962 年）。


平衡因子
AVL 树为每个节点维护一个平衡因子（Balance Factor）：


BF(node)=height(node.left)−height(node.right)\text{BF}(node) = \text{height}(node.left) - \text{height}(node.right)BF(node)=height(node.left)−height(node.right)
AVL 树要求：对于树中的每一个节点，其平衡因子的绝对值不超过 1，即 BF∈{−1,0,1}\text{BF} \in \{-1, 0, 1\}BF∈{−1,0,1}。




上图中每个节点的平衡因子均在 {−1,0,1}\{-1, 0, 1\}{−1,0,1} 范围内，是一棵合法的 AVL 树。




节点定义
class AVLNode<T> {
  value: T;
  left: AVLNode<T> | null;
  right: AVLNode<T> | null;
  height: number;

  constructor(value: T) {
    this.value = value;
    this.left = null;
    this.right = null;
    this.height = 1;
  }
}
辅助函数
function getHeight<T>(node: AVLNode<T> | null): number {
  return node ? node.height : 0;
}

function getBalance<T>(node: AVLNode<T> | null): number {
  return node ? getHeight(node.left) - getHeight(node.right) : 0;
}

function updateHeight<T>(node: AVLNode<T>): void {
  node.height = 1 + Math.max(getHeight(node.left), getHeight(node.right));
}
旋转操作
当插入或删除导致某个节点的平衡因子绝对值超过 1 时，需要通过旋转来恢复平衡。AVL 树共有四种旋转情况：


LL 型 — 右旋（Right Rotation）
失衡节点的 BF>1\text{BF} > 1BF>1，且左子节点 BF≥0\text{BF} \geq 0BF≥0（左子树的左侧偏重）。


function rightRotate<T>(z: AVLNode<T>): AVLNode<T> {
  const y = z.left!;
  const T3 = y.right;
  y.right = z;
  z.left = T3;
  updateHeight(z);
  updateHeight(y);
  return y;
}
RR 型 — 左旋（Left Rotation）
失衡节点的 BF<−1\text{BF} < -1BF<−1，且右子节点 BF≤0\text{BF} \leq 0BF≤0（右子树的右侧偏重）。


function leftRotate<T>(z: AVLNode<T>): AVLNode<T> {
  const y = z.right!;
  const T2 = y.left;
  y.left = z;
  z.right = T2;
  updateHeight(z);
  updateHeight(y);
  return y;
}
LR 型 — 先左旋再右旋
失衡节点的 BF>1\text{BF} > 1BF>1，且左子节点 BF<0\text{BF} < 0BF<0（左子树的右侧偏重）。先对左子节点做左旋，再对失衡节点做右旋。


function lrRotate<T>(z: AVLNode<T>): AVLNode<T> {
  z.left = leftRotate(z.left!);
  return rightRotate(z);
}
RL 型 — 先右旋再左旋
失衡节点的 BF<−1\text{BF} < -1BF<−1，且右子节点 BF>0\text{BF} > 0BF>0（右子树的左侧偏重）。先对右子节点做右旋，再对失衡节点做左旋。


function rlRotate<T>(z: AVLNode<T>): AVLNode<T> {
  z.right = rightRotate(z.right!);
  return leftRotate(z);
}
旋转判定总结
插入操作
function avlInsert<T>(root: AVLNode<T> | null, val: T): AVLNode<T> {
  if (!root) return new AVLNode(val);

  if (val < root.value) root.left = avlInsert(root.left, val);
  else if (val > root.value) root.right = avlInsert(root.right, val);
  else return root;

  updateHeight(root);
  const balance = getBalance(root);

  if (balance > 1 && val < root.left!.value) return rightRotate(root);

  if (balance < -1 && val > root.right!.value) return leftRotate(root);

  if (balance > 1 && val > root.left!.value) {
    root.left = leftRotate(root.left!);
    return rightRotate(root);
  }

  if (balance < -1 && val < root.right!.value) {
    root.right = rightRotate(root.right!);
    return leftRotate(root);
  }

  return root;
}
删除操作
function avlDelete<T>(root: AVLNode<T> | null, val: T): AVLNode<T> | null {
  if (!root) return null;

  if (val < root.value) root.left = avlDelete(root.left, val);
  else if (val > root.value) root.right = avlDelete(root.right, val);
  else {
    if (!root.left) return root.right;
    if (!root.right) return root.left;
    let successor = root.right;
    while (successor.left) successor = successor.left;
    root.value = successor.value;
    root.right = avlDelete(root.right, successor.value);
  }

  updateHeight(root);
  const balance = getBalance(root);

  if (balance > 1 && getBalance(root.left) >= 0) return rightRotate(root);

  if (balance > 1 && getBalance(root.left) < 0) {
    root.left = leftRotate(root.left!);
    return rightRotate(root);
  }

  if (balance < -1 && getBalance(root.right) <= 0) return leftRotate(root);

  if (balance < -1 && getBalance(root.right) > 0) {
    root.right = rightRotate(root.right!);
    return leftRotate(root);
  }

  return root;
}


红黑树
红黑树（Red-Black Tree）是另一种广泛使用的自平衡二叉搜索树，由 Rudolf Bayer 于 1972 年发明，后经 Guibas 和 Sedgewick 完善。它是 C++ std::map、Java TreeMap、Linux 内核调度器等系统底层的核心数据结构。


五大性质
红黑树通过节点着色和一组约束来维持近似平衡：


    

  1. 颜色性质：每个节点是 🔴 红色或 ⚫ 黑色
    2. 

  2. 根性质：根节点是 ⚫ 黑色
    3. 

  3. 叶性质：所有叶节点（NIL 哨兵节点）是 ⚫ 黑色
    4. 

  4. 红色性质：🔴 红色节点的两个子节点必须是 ⚫ 黑色（不能有连续的红节点）
    5. 

  5. 黑高性质：从任意节点到其所有后代 NIL 节点的路径上，⚫ 黑色节点数量相同
    6. 



为什么这些性质能保证平衡
由黑高性质可以推导出：红黑树的高度 h≤2log⁡2(n+1)h \leq 2 \log_2(n + 1)h≤2log2​(n+1)。


直观理解：由于不能有连续红节点（性质 4），在最长路径上红黑节点交替出现，因此最长路径长度最多是最短路径的 2 倍。这保证了树不会严重失衡。


插入和删除
红黑树的插入和删除操作需要通过变色（Recoloring） 和旋转（Rotation） 来维持五大性质。虽然实现较为复杂，但每次操作的旋转次数有上界：


    

  • 插入：最多 2 次旋转
    • 

  • 删除：最多 3 次旋转
    •

简单记忆：AVL 更适合查找密集型场景（因为树更矮），红黑树更适合频繁插入删除场景（因为调整开销更稳定）。






B 树与 B+ 树
AVL 树和红黑树都是二叉树，适合内存中的数据操作。但在磁盘存储（数据库、文件系统）场景下，需要减少磁盘 I/O 次数，此时引入多路平衡树 —— B 树和 B+ 树。


B 树（B-Tree）
B 树是一种 mmm 阶（每个节点最多 mmm 个子节点）的自平衡多路搜索树：


    

  • 每个内部节点存储 [⌈m/2⌉−1, m−1][\lceil m/2 \rceil - 1, \ m - 1][⌈m/2⌉−1, m−1] 个键
    • 

  • 所有叶节点在同一层
    • 

  • 节点内的键有序排列，子节点分布在键的间隔中
    • 



B+ 树（B+ Tree）
B+ 树是 B 树的变体，是关系型数据库索引（MySQL InnoDB、PostgreSQL）的标准实现：


    

  • 所有数据只存储在叶节点，内部节点只存储键（作为索引）
    • 

  • 叶节点之间通过链表相互连接，支持高效的范围查询
    • 

  • 内部节点可以存储更多的键（因为不存数据），树更加扁平
    •

小结
    

  • 平衡是二叉搜索树性能的关键保证，确保操作复杂度维持在 O(log⁡n)O(\log n)O(logn) 而非退化到 O(n)O(n)O(n)。
    • 

  • AVL 树通过平衡因子和四种旋转（LL、RR、LR、RL）实现严格平衡，适合查找密集型场景。
    • 

  • 红黑树通过节点着色和五大性质实现近似平衡，增删操作的旋转次数有常数上界，适合频繁修改的场景。
    • 

  • B 树 / B+ 树将二叉扩展为多路，大幅降低树高，专为磁盘 I/O 优化而设计，是数据库索引的基石。
    • 

  • 选择哪种平衡树取决于应用场景：内存中读多选 AVL，内存中读写均衡选红黑树，磁盘存储选 B/B+ 树。
