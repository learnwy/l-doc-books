Part II · 程序与算法 (Programs & Algorithms)数据结构 简介概率数据结构 简介频率估计与 Count-Min Sketch

频率估计与 Count-Min Sketch

"这个商品被搜索了多少次？""哪些 IP 地址访问最频繁？"——统计元素出现的次数（频率）是数据分析中极其常见的需求。当元素种类繁多、数据如流水般涌来时，为每个元素精确计数所需的内存会迅速失控。Count-Min Sketch 用一个小小的二维计数表，就能估计海量数据流中任意元素的出现频率，是频率估计领域最经典、最实用的概率数据结构。理解它，是掌握流式数据统计的关键一环。

频率估计问题

频率估计问题要求统计数据流中各个元素出现的次数。最直接的精确方法是用一张哈希表，为每个不同的元素维护一个计数器。然而，当不同元素的数量极其庞大时（如海量的搜索词、URL、IP 地址），这张哈希表会消耗大量内存，因为它必须为每一个出现过的元素都分配存储。

核心概念

频率估计用一块固定大小的二维计数表，估计海量数据流中任意元素（哪怕是从未见过的新元素）的出现次数。它的核心要素是：

  • 二维计数表 —— 若干行 × 若干列的计数器阵列，行数与哈希函数个数相同，大小固定、与元素种类无关。
  • 每行一个哈希函数 —— 更新时每个哈希函数在对应行定位一个格子并加计数。
  • 取最小值 —— 查询时读出各行对应格子，返回其中最小者，以剔除冲突带来的高估。
  • 单向误差 —— 哈希冲突只会让计数偏高，故估计只高估、不低估。
  • column/row 分工 —— 列数控制误差幅度，行数控制误差超标概率。
方案 内存 误差 支持删除 适用
精确哈希表计数 O(种类数)O(\text{种类数})O(种类数) 精确 是 种类不多时
Count-Min Sketch 固定（二维表） 只高估、可控 需变体支持 流式、海量种类
蓄水池 + 筛选 固定 取决于样本量 不适用 抽样估计

常见误解：Count-Min Sketch 对低频元素的估计误差可能非常大——因为它的噪声来自高频元素的冲突，一个几乎不出现的元素，其格子可能已被高频元素加到了很大的数值。它擅长回答"谁最高频"，不擅长精确追踪稀有元素。

在数据流场景下，这一问题尤为突出：数据持续不断地到来、规模无上限，无法预先知道会出现多少种元素，精确哈希表的内存可能无限增长。Count-Min Sketch 的目标，就是用一块固定大小的、远小于元素种类数的内存，对任意元素的出现频率给出估计。它特别适合回答"高频元素有哪些""某元素大约出现了多少次"这类在大数据中频繁出现的问题。

Count-Min Sketch 的结构

Count-Min Sketch 的结构是一张二维的计数器表，可以想象成若干行、每行若干列的格子，初始全为零。它配备多个相互独立的哈希函数，行数与哈希函数的个数相同——每一行对应一个哈希函数，该哈希函数把元素映射到这一行的某一列。

flowchart TD
    A["元素 x 到来, 计数加 c"] --> B["哈希函数1 → 第1行某列, 该格 += c"]
    A --> C["哈希函数2 → 第2行某列, 该格 += c"]
    A --> D["…每行各更新一格"]
    E["查询 x 的频率"] --> F["取各行对应格的值"]
    F --> G["返回其中的最小值"]

更新操作是：当某元素出现时，用每一个哈希函数分别定位到对应行的一个格子，把这些格子的计数都加上相应的增量。查询某元素的频率时，同样用各哈希函数定位到对应的各个格子，读出它们的计数值，然后返回其中的最小值作为该元素频率的估计。整个结构的大小由行数和列数固定，与数据流的长度、元素的种类数都无关。

为什么取最小值

Count-Min Sketch 的名字中"Min"（取最小）正是其精妙所在。由于不同元素可能被哈希到同一个格子，每个格子的计数实际上是所有映射到它的元素频率之和。因此，任何一个格子的计数都只会大于等于该元素的真实频率——哈希冲突只会使计数偏高，绝不会偏低。

这意味着对某元素，它在各行对应格子里的计数，每一个都是其真实频率加上一些来自冲突的"噪声"。由于不同行使用不同的哈希函数，冲突的来源各不相同，因此这几个计数中最小的那个，受冲突干扰最少、最接近真实值。取最小值，就是取"被污染最少"的那个估计。由此可知，Count-Min Sketch 的估计具有单向的误差特性——它只会高估、绝不会低估，且高估的幅度可以通过表的大小来控制。这种"只高估"的特性，对许多应用（如找出高频元素）是完全可以接受的。

误差与参数

Count-Min Sketch 的估计误差由表的两个维度决定。列数决定了每一行的"分辨率"——列越多，哈希冲突越少，单次估计的误差上界越小。行数（哈希函数个数）决定了估计的可靠性——行越多，取最小值时越有机会避开严重冲突，估计超出误差范围的概率越低。

二者与误差之间有清晰的数学关系：列数控制误差的"幅度"，行数控制误差超标的"概率"。使用者可以根据可接受的误差大小和置信水平，计算出所需的列数与行数，从而确定整个结构的内存占用。与精确哈希表不同，这一内存是固定的，不随元素种类增多而增长。需要注意的是，Count-Min Sketch 对高频元素的相对估计很准，但对低频元素，来自高频元素冲突的噪声可能占比较大，因此它最适合用于识别和估计"重要的高频元素"，而非精确追踪每一个稀有元素。

应用场景

Count-Min Sketch 在流式数据分析中应用广泛，核心用途是在有限内存下追踪海量数据流的频率分布。一个经典应用是"找出高频元素"——例如实时找出被搜索最多的热词、访问最频繁的网址、流量最大的 IP。借助 Count-Min Sketch 估计频率，再配合少量额外结构记录候选的高频项，就能在单遍扫描、固定内存下持续维护出近似的排行榜。

在网络监控中，它用于检测大流量的源或目标，辅助识别异常流量与攻击。在数据库与流处理系统中，它用于近似的频率统计、热点检测与负载均衡。它还常与其他结构配合——例如先用它快速估计频率、筛出可疑的高频项，再做精确核查。Count-Min Sketch 与基数估计的 HyperLogLog 一样，体现了流式计算的共同智慧：面对无法存储的数据洪流，用固定的小内存和可控的近似，提取出最有价值的统计信息。

小结

  • 频率估计统计数据流中各元素出现的次数，精确哈希表的内存随元素种类增多而失控。
  • Count-Min Sketch 用固定大小的二维计数表与多个哈希函数，更新时每行各加一格，查询时取各行对应格的最小值。
  • 哈希冲突只会使计数偏高不会偏低，故取最小值得到受冲突污染最少的估计，误差单向（只高估不低估）。
  • 列数控制误差幅度、行数控制误差超标概率，二者决定固定的内存占用，对高频元素估计准、对低频元素噪声大。
  • 它广泛用于找出高频元素（热词、热点 IP）、网络异常检测与流处理中的近似频率统计。
