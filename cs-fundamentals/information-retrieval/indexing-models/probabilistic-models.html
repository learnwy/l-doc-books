概率检索模型

核心概念

概率检索模型从概率论的角度定义信息检索问题：给定查询 q 和文档 d，计算 d 与 q 相关的概率 P(R=1|q,d)，并按照这个概率对所有文档进行排序。概率排序原理（Probability Ranking Principle，PRP）指出，按照相关概率降序排列文档可以最小化检索系统的期望损失——这是概率模型的理论基石。BM25 作为概率模型家族中最成功的成员，至今仍是工业界最广泛使用的排序基线。

BM25 排序算法
BM25（Best Matching 25）是由 Stephen Robertson 等人在 TREC 评测中提出的排序公式，它在概率模型的理论框架下融合了词频饱和、文档长度归一化和 IDF 权重三个关键机制。


BM25 对查询中每个词项 t 在文档 d 中的得分计算如下：对每个查询词项 t，其贡献分数 = IDF(t) × (tf(t,d) × (k1 + 1)) / (tf(t,d) + k1 × (1 - b + b × dl/avgdl))。其中 tf(t,d) 是词项 t 在文档 d 中的词频，dl 是文档长度，avgdl 是平均文档长度，k1 和 b 是可调参数。


interface BM25Config {
  readonly k1: number;
  readonly b: number;
}

interface CollectionStats {
  readonly totalDocs: number;
  readonly avgDocLength: number;
  readonly docFrequencies: Map<string, number>;
}

const bm25Score = (
  queryTerms: ReadonlyArray<string>,
  docTermFreqs: Map<string, number>,
  docLength: number,
  stats: CollectionStats,
  config: BM25Config = { k1: 1.2, b: 0.75 },
): number => {
  let score = 0;
  for (const term of queryTerms) {
    const tf = docTermFreqs.get(term) ?? 0;
    if (tf === 0) continue;
    const df = stats.docFrequencies.get(term) ?? 0;
    const idf = Math.log((stats.totalDocs - df + 0.5) / (df + 0.5) + 1);
    const tfNorm =
      (tf * (config.k1 + 1)) / (tf + config.k1 * (1 - config.b + (config.b * docLength) / stats.avgDocLength));
    score += idf * tfNorm;
  }
  return score;
};
k1 控制词频饱和的速度——k1 越大，高词频的边际收益越明显；k1=0 时退化为布尔模型（有没有这个词）。b 控制文档长度归一化的强度——b=1 时完全归一化（长文档被严格惩罚），b=0 时不做归一化。经验上 k1=1.2, b=0.75 是最常用的默认值。

Binary Independence Model
BIM（Binary Independence Model）是概率检索的理论基础模型。它假设词项在相关文档和不相关文档中的出现概率是独立的，通过贝叶斯定理推导出文档的相关性得分。


BIM 的推导起点是「概率排序原理」——我们希望按照 P(R=1|d,q) / P(R=0|d,q) 的比值对文档排序。通过贝叶斯展开和独立性假设，这个比值可以分解为每个查询词项的对数似然比之和。这个推导结果与 IDF 加权的直觉一致——在相关文档中出现概率高、在不相关文档中出现概率低的词项应获得更高权重。


interface BIMParameters {
  readonly pRelevant: Map<string, number>;
  readonly pNonRelevant: Map<string, number>;
}

const bimScore = (queryTerms: ReadonlyArray<string>, docTerms: Set<string>, params: BIMParameters): number => {
  let score = 0;
  for (const term of queryTerms) {
    const present = docTerms.has(term);
    const pR = params.pRelevant.get(term) ?? 0.5;
    const pNR = params.pNonRelevant.get(term) ?? 0.5;
    if (present) {
      score += Math.log(pR / pNR);
    } else {
      score += Math.log((1 - pR) / (1 - pNR));
    }
  }
  return score;
};

const estimateFromFeedback = (
  term: string,
  relevantDocs: ReadonlyArray<Set<string>>,
  nonRelevantDocs: ReadonlyArray<Set<string>>,
): { pR: number; pNR: number } => {
  const rContaining = relevantDocs.filter((d) => d.has(term)).length;
  const nrContaining = nonRelevantDocs.filter((d) => d.has(term)).length;
  const pR = (rContaining + 0.5) / (relevantDocs.length + 1);
  const pNR = (nrContaining + 0.5) / (nonRelevantDocs.length + 1);
  return { pR, pNR };
};
BM25 的变体与改进
BM25 的基础公式在实践中衍生出多个变体以适应不同场景。


BM25F（BM25 for Fields）扩展了 BM25 以处理结构化文档——标题、摘要和正文等不同字段可以拥有不同的权重和参数。BM25F 的核心思想是将多个字段的词频加权合并为一个「虚拟词频」，然后使用标准 BM25 公式计算。


BM25+ 修正了 BM25 的一个理论缺陷——当 b>0 时，BM25 的 TF 归一化可能导致长文档中的匹配词项获得过低的分数。BM25+ 通过在分子中添加一个常数 δ 来提供一个分数下界。


interface BM25FConfig {
  readonly fields: ReadonlyArray<{
    name: string;
    boost: number;
    k1: number;
    b: number;
  }>;
}

const bm25fScore = (
  queryTerms: ReadonlyArray<string>,
  fieldTermFreqs: ReadonlyArray<{ field: string; termFreqs: Map<string, number>; length: number }>,
  stats: CollectionStats,
  config: BM25FConfig,
): number => {
  let score = 0;
  for (const term of queryTerms) {
    const df = stats.docFrequencies.get(term) ?? 0;
    const idf = Math.log((stats.totalDocs - df + 0.5) / (df + 0.5) + 1);
    let combinedTF = 0;
    for (const fieldData of fieldTermFreqs) {
      const fieldConfig = config.fields.find((f) => f.name === fieldData.field);
      if (!fieldConfig) continue;
      const tf = fieldData.termFreqs.get(term) ?? 0;
      const normalizedTF = tf / (1 - fieldConfig.b + (fieldConfig.b * fieldData.length) / stats.avgDocLength);
      combinedTF += fieldConfig.boost * normalizedTF;
    }
    const k1 = config.fields[0]?.k1 ?? 1.2;
    score += idf * (combinedTF / (k1 + combinedTF));
  }
  return score;
};

小结
    

  • 概率检索模型基于概率排序原理，按相关概率降序排列文档以最小化期望损失
    • 

  • BM25 融合词频饱和、文档长度归一化和 IDF 三大机制，是工业界的标准基线算法
    • 

  • k1 控制 TF 饱和速度，b 控制文档长度归一化强度，典型值为 k1=1.2, b=0.75
    • 

  • BIM 通过贝叶斯推导和独立性假设，为概率检索提供了坚实的理论基础
    • 

  • BM25F 通过多字段加权扩展处理结构化文档，BM25+ 修正长文档的分数下界问题
    • 

  • BM25 虽然是经典方法，但在现代搜索系统中仍是不可替代的基线和混合检索的关键组件
    •
