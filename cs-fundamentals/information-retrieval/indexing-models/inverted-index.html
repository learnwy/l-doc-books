倒排索引

核心概念

倒排索引（Inverted Index）是信息检索系统中最核心的数据结构，几乎所有现代搜索引擎都基于倒排索引构建。它的设计思想简单而强大：将「给定文档找包含的词项」这一正向映射关系反转为「给定词项找包含它的文档」。这种反转使得关键词检索从需要遍历全部文档的 O(N) 操作变为常数时间或对数时间的高效查找。

倒排索引的数据结构
倒排索引由两部分组成：词典（Dictionary）和倒排列表（Posting Lists）。词典存储所有唯一词项及其指向倒排列表的指针，通常使用哈希表或 B 树实现。倒排列表存储包含该词项的所有文档 ID，通常按文档 ID 排序以支持高效的合并操作。


增强的倒排列表还可以存储额外信息：词频（TF）用于 BM25 等排序计算，位置信息（Position）用于短语检索和近邻查询，偏移量（Offset）用于结果高亮。


interface Dictionary {
  readonly terms: Map<string, DictionaryEntry>;
}

interface DictionaryEntry {
  readonly term: string;
  readonly documentFrequency: number;
  readonly collectionFrequency: number;
  readonly postingListOffset: number;
}

interface PostingList {
  readonly term: string;
  readonly postings: ReadonlyArray<Posting>;
}

interface Posting {
  readonly docId: number;
  readonly termFrequency: number;
  readonly positions?: ReadonlyArray<number>;
  readonly fieldLengthNorm?: number;
}

const buildInvertedIndex = (
  documents: ReadonlyArray<{ id: number; tokens: ReadonlyArray<string> }>,
): Map<string, PostingList> => {
  const index = new Map<string, Map<number, { tf: number; positions: number[] }>>();
  for (const doc of documents) {
    doc.tokens.forEach((token, position) => {
      if (!index.has(token)) index.set(token, new Map());
      const termMap = index.get(token)!;
      if (!termMap.has(doc.id)) termMap.set(doc.id, { tf: 0, positions: [] });
      const entry = termMap.get(doc.id)!;
      entry.tf++;
      entry.positions.push(position);
    });
  }
  const result = new Map<string, PostingList>();
  for (const [term, docs] of index) {
    const postings = [...docs.entries()]
      .sort(([a], [b]) => a - b)
      .map(([docId, { tf, positions }]) => ({
        docId,
        termFrequency: tf,
        positions,
      }));
    result.set(term, { term, postings });
  }
  return result;
};
索引压缩技术
大规模文档集合的倒排索引可能占用大量存储空间。索引压缩通过编码优化来减少存储开销，同时尽量不影响查询性能。压缩策略利用了倒排列表的两个统计特性：文档 ID 通常是递增整数，差值编码（Delta Encoding）可以大幅缩小数值范围；词频通常是较小的整数，变长编码（Variable-Length Encoding）可以用更少的字节表示。


差值编码（Gap Encoding）将有序文档 ID 列表转换为相邻 ID 之间的差值列表。例如 [3, 7, 12, 25] 变为 [3, 4, 5, 13]，差值通常远小于原始 ID，压缩效果显著。


const deltaEncode = (docIds: ReadonlyArray<number>): ReadonlyArray<number> => {
  if (docIds.length === 0) return [];
  const gaps = [docIds[0]];
  for (let i = 1; i < docIds.length; i++) {
    gaps.push(docIds[i] - docIds[i - 1]);
  }
  return gaps;
};

const deltaDecode = (gaps: ReadonlyArray<number>): ReadonlyArray<number> => {
  if (gaps.length === 0) return [];
  const docIds = [gaps[0]];
  for (let i = 1; i < gaps.length; i++) {
    docIds.push(docIds[i - 1] + gaps[i]);
  }
  return docIds;
};

const vbyteEncode = (value: number): ReadonlyArray<number> => {
  const bytes: number[] = [];
  while (value >= 128) {
    bytes.push(value & 0x7f);
    value >>= 7;
  }
  bytes.push(value | 0x80);
  return bytes;
};

索引构建与更新
大规模索引构建面临内存限制的挑战——当文档集合超出内存容量时，需要使用外排序（External Sorting）策略。BSBI（Blocked Sort-Based Indexing）算法将文档分成固定大小的块，每个块在内存中构建部分倒排索引并排序后写入磁盘，最后通过多路归并合并所有块。


索引更新有两种策略。原地更新直接修改已有的倒排列表，实现简单但会导致磁盘碎片和锁竞争。增量合并维护一个内存中的增量索引，定期将增量索引与主索引合并。Elasticsearch 采用的 Lucene 使用段（Segment）机制——新文档写入新段，定期通过段合并来优化索引。

跳表与索引加速
跳表（Skip List）是加速倒排列表遍历的重要数据结构。在处理 AND 查询的双指针合并时，如果两个倒排列表的长度差异很大，短列表的指针可能需要在长列表中跳过大量不匹配的文档。跳表通过在列表中添加多级快速跳转指针，将跳过操作从 O(n) 优化为 O(√n)。


跳表的构建策略需要平衡跳跃步长和存储开销。步长过小则跳表退化为顺序扫描，步长过大则命中率低。经验法则是步长设为列表长度的平方根。


interface SkipListNode {
  readonly docId: number;
  readonly posting: Posting;
  readonly skipTo?: SkipListNode;
  readonly skipDistance: number;
}

const intersectWithSkip = (
  short: ReadonlyArray<SkipListNode>,
  long: ReadonlyArray<SkipListNode>,
): ReadonlyArray<Posting> => {
  const result: Posting[] = [];
  let si = 0;
  let li = 0;
  while (si < short.length && li < long.length) {
    if (short[si].docId === long[li].docId) {
      result.push(short[si].posting);
      si++;
      li++;
    } else if (short[si].docId < long[li].docId) {
      si++;
    } else {
      if (long[li].skipTo && long[li].skipTo!.docId <= short[si].docId) {
        while (long[li].skipTo && long[li].skipTo!.docId <= short[si].docId) {
          li += long[li].skipDistance;
        }
      } else {
        li++;
      }
    }
  }
  return result;
};
小结
    

  • 倒排索引通过反转文档-词项映射关系，将关键词检索时间从 O(N) 降低到 O(1) 或 O(log V)
    • 

  • 倒排列表存储文档 ID、词频和位置信息，支持排序计算、短语检索和结果高亮
    • 

  • 差值编码和 VByte 等压缩技术在保持快速解压的同时显著减少索引存储开销
    • 

  • BSBI 算法通过分块排序和多路归并解决了大规模文档集合的内存限制问题
    • 

  • 段合并机制实现了索引的增量更新，避免了全量重建的开销
    • 

  • 跳表将倒排列表的跳过操作从线性优化为亚线性，加速长列表的合并运算
    •
