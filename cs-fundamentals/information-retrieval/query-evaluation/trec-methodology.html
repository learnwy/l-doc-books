TREC 与评测方法论

核心概念

TREC（Text REtrieval Conference）是由美国国家标准与技术研究院（NIST）自 1992 年起主办的信息检索评测会议，是 IR 领域最权威的评测平台。TREC 建立了系统性的评测方法论——标准化的评测数据集、统一的评价指标和公开的排名比较，使得不同系统之间的性能比较成为可能。TREC 的评测范式深刻影响了整个信息检索和自然语言处理领域的研究方法。

Cranfield 评测范式
TREC 遵循的评测方法论源自 1960 年代 Cleverdon 在 Cranfield 实验中建立的范式。Cranfield 范式的三个核心要素是：固定的文档集合（Corpus）——所有系统在相同的数据上评测；预定义的查询集（Topics）——标准化的信息需求描述；人工相关性标注（Qrels）——由评审员判定每个查询-文档对的相关性。


这种范式的核心假设是相关性判定的稳定性——不同评审员对同一查询-文档对的判断应该大致一致。实验表明，虽然个体评审员之间存在差异，但在系统层面的排名上，不同评审员组的标注结果高度一致。


interface TRECTopic {
  readonly id: string;
  readonly title: string;
  readonly description: string;
  readonly narrative: string;
}

interface TRECQrel {
  readonly topicId: string;
  readonly docId: string;
  readonly relevance: number;
}

interface TRECRun {
  readonly systemName: string;
  readonly results: Map<string, ReadonlyArray<{ docId: string; rank: number; score: number }>>;
}

const loadQrels = (lines: ReadonlyArray<string>): Map<string, Map<string, number>> => {
  const qrels = new Map<string, Map<string, number>>();
  for (const line of lines) {
    const [topicId, , docId, relevance] = line.split(/\s+/);
    if (!qrels.has(topicId)) qrels.set(topicId, new Map());
    qrels.get(topicId)!.set(docId, parseInt(relevance));
  }
  return qrels;
};

const evaluateRun = (
  run: TRECRun,
  qrels: Map<string, Map<string, number>>,
  metrics: ReadonlyArray<string>,
): EvaluationResult => {
  const perQueryMetrics = new Map<string, Record<string, number>>();
  for (const [topicId, results] of run.results) {
    const relevanceMap = qrels.get(topicId) ?? new Map();
    const rankedDocs = results.sort((a, b) => a.rank - b.rank).map((r) => r.docId);
    const relevant = new Set([...relevanceMap.entries()].filter(([, r]) => r > 0).map(([id]) => id));
    const queryMetrics: Record<string, number> = {};
    if (metrics.includes('map'))
      queryMetrics.map = averagePrecision(
        results.map((r) => ({ docId: r.docId, rank: r.rank, score: r.score })),
        relevant,
      );
    if (metrics.includes('ndcg@10')) queryMetrics['ndcg@10'] = ndcg(rankedDocs, relevanceMap, 10);
    perQueryMetrics.set(topicId, queryMetrics);
  }
  return { systemName: run.systemName, perQueryMetrics, aggregateMetrics: aggregateMetrics(perQueryMetrics) };
};
Pooling 与标注方法
TREC 使用 Pooling 方法来解决大规模文档集合中的标注可行性问题。由于不可能标注每个查询-文档对的相关性（百万级文档集合 × 50 个查询 = 数千万对），Pooling 方法从所有参赛系统的 Top-K 结果中收集文档形成候选池，只标注池中的文档。


Pooling 的假设是：如果一个相关文档没有被任何系统检索到 Top-K，那么它被遗漏的影响可以忽略。这个假设在足够多系统参评时大致成立，但对于使用全新检索范式（如 Dense Retrieval）的系统可能不公平——它们可能检索到池外的相关文档。

现代评测挑战
现代 IR 系统面临传统评测范式难以完全覆盖的新挑战。


神经检索模型的 Pooling 偏置：Dense Retrieval 系统可能检索到与传统 BM25 系统完全不同的文档集合，而这些文档可能不在基于传统系统构建的候选池中。TREC Deep Learning Track 通过增加更多参赛系统和更深的 Pooling 深度来缓解这个问题。


生成式搜索评估：RAG 系统不再返回文档列表，而是直接生成答案。传统的文档级评价指标（MAP、NDCG）无法直接应用。新的评估框架需要同时评估检索质量（是否检索到正确的证据）和生成质量（答案是否准确、完整、忠实）。


多样性评估：传统指标假设每个相关文档是独立的，但实际上用户希望搜索结果覆盖查询的不同方面。α-NDCG 和 ERR-IA 等意图感知指标通过惩罚冗余来鼓励结果多样性。


interface ModernEvalMetrics {
  alphaNCDG(rankedDocs: ReadonlyArray<string>, intents: ReadonlyArray<Intent>, alpha: number, k: number): number;

  ragEval(
    query: string,
    generatedAnswer: string,
    retrievedDocs: ReadonlyArray<string>,
    groundTruth: string,
  ): RAGEvalResult;
}

interface Intent {
  readonly id: string;
  readonly probability: number;
  readonly relevantDocs: Set<string>;
}

interface RAGEvalResult {
  readonly retrievalQuality: { ndcg: number; recall: number };
  readonly answerQuality: { faithfulness: number; relevance: number; completeness: number };
  readonly overall: number;
}
小结
    

  • TREC 建立了 IR 评测的标准方法论，包括固定语料、标准查询和人工标注三个核心要素
    • 

  • Cranfield 范式的核心假设是相关性判定的稳定性，在系统排名层面得到了实验验证
    • 

  • Pooling 方法通过从参赛系统的 Top-K 结果中构建候选池来解决标注可行性问题
    • 

  • 神经检索模型引入了 Pooling 偏置问题，Deep Learning Track 通过更深的 Pooling 缓解
    • 

  • 生成式搜索需要同时评估检索质量和答案质量的新评估框架
    • 

  • 多样性评估通过意图感知指标鼓励结果覆盖查询的不同方面
