查询处理与优化

核心概念

查询处理是信息检索系统中将用户的原始查询转换为可执行的检索计划并高效获取结果的过程。从用户输入的几个关键词到最终排序的搜索结果，中间经历查询解析、查询规范化、查询扩展和检索执行四个主要阶段。查询处理的质量直接影响用户体验——不仅是结果的相关性，还包括响应速度。

查询解析与规范化
查询解析的第一步是分词（Tokenization），将连续的查询文本切分为独立的词项。对于英文，分词相对简单（按空格和标点切分），但需要处理缩写（"don't"）、连字符（"state-of-the-art"）和 URL/邮箱等特殊格式。对于中文和日文等没有显式分词符的语言，需要使用统计分词或词典分词。


interface QueryProcessor {
  process(rawQuery: string): ProcessedQuery;
}

interface ProcessedQuery {
  readonly originalQuery: string;
  readonly tokens: ReadonlyArray<string>;
  readonly normalizedTokens: ReadonlyArray<string>;
  readonly expandedTerms: ReadonlyArray<ExpandedTerm>;
  readonly queryType: 'keyword' | 'phrase' | 'boolean' | 'natural_language';
}

interface ExpandedTerm {
  readonly term: string;
  readonly weight: number;
  readonly source: 'original' | 'synonym' | 'stemming' | 'embedding';
}

const normalize = (token: string): string => {
  let normalized = token.toLowerCase();
  normalized = normalized.normalize('NFKC');
  return normalized;
};

const removeStopwords = (tokens: ReadonlyArray<string>, stopwords: Set<string>): ReadonlyArray<string> =>
  tokens.filter((t) => !stopwords.has(t));

const stem = (token: string): string => {
  const suffixes = ['ing', 'ed', 'ly', 'es', 's'];
  for (const suffix of suffixes) {
    if (token.endsWith(suffix) && token.length > suffix.length + 2) {
      return token.slice(0, -suffix.length);
    }
  }
  return token;
};
词干提取（Stemming）和词形还原（Lemmatization）是规范化的两种策略。词干提取通过规则去除词缀（如 Porter Stemmer 将 "computing"、"computed"、"computer" 都还原为 "comput"），速度快但可能过度还原（"organization" 和 "organ" 被还原为相同词干）。词形还原使用词典和语法分析还原到词典形式（"computing" → "compute"），更准确但更慢。

查询扩展技术
查询扩展通过向原始查询添加相关词项来提高召回率。用户的查询通常很短（平均 2-3 个词），可能无法覆盖所有表达同一概念的词汇。


基于词典的扩展使用同义词词典（如 WordNet）为查询词项添加同义词。这种方法的优势是可控性强——只有明确的同义关系才会被使用。劣势是词典的覆盖率有限，特别是对于专业术语和新词。


基于嵌入的扩展利用 Word2Vec 或 BERT 等模型找到查询词项在向量空间中的近邻词。这种方法不受词典覆盖率限制，但可能引入语义漂移——"bank"的近邻可能同时包含"金融"和"河岸"相关的词汇。


interface QueryExpander {
  expand(query: ProcessedQuery, config: ExpansionConfig): Promise<ProcessedQuery>;
}

interface ExpansionConfig {
  readonly maxTermsPerOriginal: number;
  readonly synonymWeight: number;
  readonly embeddingWeight: number;
  readonly pseudoFeedbackDocs: number;
}

const expandWithSynonyms = (
  token: string,
  synonymDict: Map<string, ReadonlyArray<string>>,
  maxTerms: number,
  weight: number,
): ReadonlyArray<ExpandedTerm> => {
  const synonyms = synonymDict.get(token) ?? [];
  return synonyms.slice(0, maxTerms).map((syn) => ({
    term: syn,
    weight,
    source: 'synonym' as const,
  }));
};

const expandWithEmbeddings = async (
  token: string,
  embeddingModel: EmbeddingModel,
  vocabulary: ReadonlyArray<string>,
  maxTerms: number,
  weight: number,
): Promise<ReadonlyArray<ExpandedTerm>> => {
  const tokenEmb = await embeddingModel.encode(token);
  const similarities = vocabulary.map((word) => ({
    word,
    similarity: cosineSimilarity(tokenEmb, embeddingModel.getWordVector(word)),
  }));
  return similarities
    .sort((a, b) => b.similarity - a.similarity)
    .slice(0, maxTerms)
    .map(({ word, similarity }) => ({
      term: word,
      weight: weight * similarity,
      source: 'embedding' as const,
    }));
};
查询执行优化
查询执行优化的目标是在保证结果质量的前提下最小化检索延迟。关键的优化策略包括查询计划选择、提前终止和缓存。


提前终止（Early Termination）在已经找到足够多高质量结果后停止遍历剩余的倒排列表。WAND（Weak AND）和 MaxScore 是两种经典的提前终止算法——它们利用每个词项的最大可能贡献来跳过不可能进入 Top-K 的文档。


interface QueryPlanner {
  plan(query: ProcessedQuery): QueryPlan;
  execute(plan: QueryPlan): Promise<ReadonlyArray<RetrievalResult>>;
}

interface QueryPlan {
  readonly strategy: 'full_scan' | 'wand' | 'max_score' | 'block_max_wand';
  readonly termOrder: ReadonlyArray<string>;
  readonly estimatedCost: number;
  readonly cacheKey?: string;
}

const selectStrategy = (queryTerms: ReadonlyArray<string>, index: InvertedIndex, topK: number): QueryPlan => {
  const termFreqs = queryTerms.map((t) => ({
    term: t,
    df: index.getPostings(t)?.docFrequency ?? 0,
  }));
  const totalPostings = termFreqs.reduce((sum, t) => sum + t.df, 0);
  if (totalPostings < 10000) {
    return { strategy: 'full_scan', termOrder: queryTerms, estimatedCost: totalPostings };
  }
  if (queryTerms.length <= 3) {
    return {
      strategy: 'wand',
      termOrder: termFreqs.sort((a, b) => a.df - b.df).map((t) => t.term),
      estimatedCost: Math.min(totalPostings, topK * 100),
    };
  }
  return {
    strategy: 'block_max_wand',
    termOrder: termFreqs.sort((a, b) => a.df - b.df).map((t) => t.term),
    estimatedCost: Math.min(totalPostings, topK * 50),
  };
};
缓存策略在查询处理中至关重要。查询缓存存储完整的查询结果，命中时直接返回。倒排列表缓存将高频词项的倒排列表保留在内存中。结果缓存和列表缓存的组合通常可以将平均查询延迟降低 50-70%。

小结
    

  • 查询处理管道包括解析、规范化、扩展和执行优化四个阶段，各环节协同影响检索质量和速度
    • 

  • 分词和规范化处理语言差异，词干提取以召回率换精确率，词形还原更为精确
    • 

  • 查询扩展通过同义词、嵌入近邻和伪反馈三种策略提升召回率
    • 

  • WAND 和 MaxScore 等提前终止算法通过跳过低分文档显著降低查询延迟
    • 

  • 多级缓存策略（查询缓存 + 列表缓存）可将平均查询延迟降低 50-70%
    • 

  • 查询处理优化需要在结果质量和响应速度之间找到最佳平衡点
    •
