问答系统与对话检索

核心概念

问答系统（Question Answering，QA）是信息检索的高级形态——它不再返回文档列表让用户自行寻找答案，而是直接从文档中提取或生成精确的答案。从 IR 到 QA 的演进代表了信息访问范式的根本转变：从「给你相关文档」到「给你答案」。现代问答系统结合了信息检索、自然语言理解和自然语言生成三大技术。

抽取式问答
抽取式问答（Extractive QA）从给定的文档段落中精确定位答案的起始和结束位置。这个任务被形式化为机器阅读理解（Machine Reading Comprehension，MRC）——给定一个问题和一段上下文，模型需要预测答案在上下文中的起始和结束 token 位置。


SQuAD（Stanford Question Answering Dataset）是推动抽取式 QA 发展的里程碑数据集。SQuAD 1.1 中每个问题都有答案（从对应段落中提取），SQuAD 2.0 增加了无答案问题，要求模型能判断「段落中没有答案」。


interface ExtractiveQA {
  answer(question: string, context: string): Promise<ExtractedAnswer>;
}

interface ExtractedAnswer {
  readonly text: string;
  readonly startIndex: number;
  readonly endIndex: number;
  readonly confidence: number;
  readonly isNoAnswer: boolean;
}

interface QAPipeline {
  readonly retriever: DocumentRetriever;
  readonly reader: ExtractiveQA;
  answer(question: string): Promise<PipelineAnswer>;
}

interface PipelineAnswer {
  readonly answer: string;
  readonly confidence: number;
  readonly sourceDocument: string;
  readonly sourcePassage: string;
}

const createQAPipeline = (retriever: DocumentRetriever, reader: ExtractiveQA, topK: number = 5): QAPipeline => ({
  retriever,
  reader,
  answer: async (question) => {
    const docs = await retriever.retrieve(question, topK);
    const candidates: Array<{
      answer: ExtractedAnswer;
      docId: string;
      passage: string;
    }> = [];
    for (const doc of docs) {
      const passages = splitIntoPassages(doc.content, 512);
      for (const passage of passages) {
        const answer = await reader.answer(question, passage);
        if (!answer.isNoAnswer) {
          candidates.push({ answer, docId: doc.id, passage });
        }
      }
    }
    candidates.sort((a, b) => b.answer.confidence - a.answer.confidence);
    const best = candidates[0];
    return best
      ? {
          answer: best.answer.text,
          confidence: best.answer.confidence,
          sourceDocument: best.docId,
          sourcePassage: best.passage,
        }
      : { answer: '', confidence: 0, sourceDocument: '', sourcePassage: '' };
  },
});
Retriever-Reader 架构是开放域 QA 的标准范式——先用 Retriever 从大规模文档集中检索相关段落，再用 Reader 从候选段落中抽取答案。DPR（Dense Passage Retriever）使用双塔 BERT 模型进行密集检索，显著超越了 BM25 在开放域 QA 中的召回性能。


生成式问答与 RAG
生成式问答不再局限于从文档中抽取现有文本，而是利用 LLM 基于检索到的知识生成自然语言答案。RAG 是当前最主流的生成式 QA 架构。


生成式 QA 的优势在于答案的自然度和完整度——它可以综合多个段落的信息生成一个连贯的回答，而抽取式方法只能返回单个文本片段。但生成式 QA 也引入了新的风险：幻觉——LLM 可能生成看似合理但不忠于检索上下文的内容。

interface GenerativeQA {
  answer(question: string, contexts: ReadonlyArray<string>): Promise<GeneratedAnswer>;
}

interface GeneratedAnswer {
  readonly text: string;
  readonly citations: ReadonlyArray<Citation>;
  readonly confidence: number;
}

interface Citation {
  readonly contextIndex: number;
  readonly excerpt: string;
  readonly relevance: number;
}

const createRAGQA = (retriever: DocumentRetriever, llm: LLMClient, verifier: AnswerVerifier): GenerativeQA => ({
  answer: async (question, contexts) => {
    const prompt = buildQAPrompt(question, contexts);
    const rawAnswer = await llm.complete(prompt);
    const citations = extractCitations(rawAnswer, contexts);
    const verification = await verifier.verify(rawAnswer, contexts);
    return {
      text: verification.correctedAnswer ?? rawAnswer,
      citations,
      confidence: verification.faithfulness,
    };
  },
});
对话式检索
对话式检索（Conversational Search）将多轮对话的上下文引入检索过程。与单轮搜索不同，对话式检索需要处理指代消解（"它的性能怎么样" → 明确 "它" 指代什么）、话题延续（用户追问的细节应基于之前的讨论）和话题切换（识别用户开始了新话题）。


对话式查询重写是解决对话检索核心挑战的关键技术——将依赖上下文的对话查询重写为自包含的完整查询。例如对话历史 "Q1: React 是什么, A1: React 是一个 UI 框架, Q2: 它的虚拟 DOM 是怎么工作的"，重写器将 Q2 重写为 "React 的虚拟 DOM 是怎么工作的"。


interface ConversationalSearch {
  search(turn: ConversationTurn): Promise<ReadonlyArray<SearchResult>>;
}

interface ConversationTurn {
  readonly query: string;
  readonly history: ReadonlyArray<{
    query: string;
    response: string;
  }>;
  readonly conversationId: string;
}

interface QueryRewriter {
  rewrite(turn: ConversationTurn): Promise<string>;
}

const createConversationalSearch = (rewriter: QueryRewriter, searchEngine: SearchEngine): ConversationalSearch => ({
  search: async (turn) => {
    const rewrittenQuery = await rewriter.rewrite(turn);
    return searchEngine.search(rewrittenQuery, { topK: 10 });
  },
});

多跳问答
多跳问答（Multi-hop QA）需要从多个文档中推理组合才能得出答案。例如 "谁是 React 的创始人就职公司的 CEO"——需要先找到 React 的创始人（Jordan Walke），再找到他所在的公司（Meta/Facebook），最后找到该公司的 CEO（Mark Zuckerberg）。


多跳推理的挑战在于推理链路的构建和验证。Retrieve-and-Read 管道需要多次迭代：第一跳检索回答部分问题，利用部分答案构建新查询进行第二跳检索，如此迭代直到收集到足够的信息。


interface MultiHopQA {
  answer(question: string, maxHops: number): Promise<MultiHopAnswer>;
}

interface MultiHopAnswer {
  readonly finalAnswer: string;
  readonly hops: ReadonlyArray<HopResult>;
  readonly confidence: number;
}

interface HopResult {
  readonly query: string;
  readonly retrievedPassage: string;
  readonly intermediateAnswer: string;
  readonly hopNumber: number;
}
小结
    

  • 问答系统将 IR 从「返回文档」提升到「返回答案」，代表信息访问范式的根本转变
    • 

  • Retriever-Reader 架构是开放域抽取式 QA 的标准范式，DPR 显著提升了检索阶段的性能
    • 

  • RAG 是当前最主流的生成式 QA 架构，答案验证机制是控制幻觉风险的关键
    • 

  • 对话式检索通过查询重写技术解决指代消解和上下文依赖问题
    • 

  • 多跳问答需要多轮迭代检索和推理组合，是 QA 系统中最具挑战性的形式
    • 

  • QA 系统的评估需要同时考量答案准确性、完整性、可溯源性和响应延迟
