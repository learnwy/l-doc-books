MAP 与 NDCG

核心概念

MAP（Mean Average Precision）和 NDCG（Normalized Discounted Cumulative Gain）是信息检索中衡量排序质量的两个核心指标。与精确率和召回率关注「返回了什么」不同，MAP 和 NDCG 关注的是「排序对不对」——相关文档是否被排在了高位。这对现代搜索系统至关重要，因为用户从上到下浏览结果，排在前面的结果获得更多注意力。

Average Precision 与 MAP
Average Precision（AP）是单个查询的排序质量指标。对于排序结果列表中的每个位置 k，如果该位置的文档是相关的，就计算在该位置的精确率 P@k 并纳入平均。最终 AP 等于所有相关文档位置的 P@k 之和除以相关文档总数 |Rel|。


AP 的直觉是：如果所有相关文档都排在结果的最前面，AP = 1.0；如果相关文档散布在列表各处，AP 会因为非相关文档的插入而下降。AP 自然地给予排在高位的相关文档更多权重。


interface RankedResult {
  readonly docId: string;
  readonly rank: number;
  readonly relevance: number;
}

function computeAveragePrecision(rankedDocs: ReadonlyArray<string>, relevant: ReadonlySet<string>): number {
  let relevantSoFar = 0;
  let sumPrecision = 0;

  for (let i = 0; i < rankedDocs.length; i++) {
    if (relevant.has(rankedDocs[i])) {
      relevantSoFar++;
      sumPrecision += relevantSoFar / (i + 1);
    }
  }

  return relevant.size > 0 ? sumPrecision / relevant.size : 0;
}

function computeMAP(
  queries: ReadonlyArray<{
    queryId: string;
    rankedDocs: ReadonlyArray<string>;
    relevant: ReadonlySet<string>;
  }>,
): number {
  if (queries.length === 0) return 0;

  let totalAP = 0;
  for (const query of queries) {
    totalAP += computeAveragePrecision(query.rankedDocs, query.relevant);
  }
  return totalAP / queries.length;
}
MAP（Mean Average Precision）是 AP 在多个查询上的平均值。MAP 是 TREC 评测中最常用的主指标，它综合了精确率、召回率和排序位置三个维度的信息，被认为是二元相关性下最全面的单一评估指标。


MAP 的一个重要性质是它等价于 PR 曲线下面积（AUC-PR）的离散近似。因此 MAP 越高，PR 曲线越靠近右上角，系统在所有召回率水平上的精确率表现都越好。


DCG 与 NDCG
DCG（Discounted Cumulative Gain）引入了两个关键创新：支持分级相关性（不仅是相关/不相关的二元判断）和对数位置折损（排在后面的文档增益被折扣）。


DCG 的标准公式为 DCG@k = Σ_{i=1}^{k} (2^rel_i - 1) / log_2(i + 1)。分子 2^rel_i - 1 将相关性等级映射为增益值（rel=0 → 0, rel=1 → 1, rel=2 → 3, rel=3 → 7），使高相关文档的增益指数增长。分母 log_2(i+1) 实现位置折损，排位越靠后折损越大。


interface GradedRelevance {
  readonly docId: string;
  readonly relevanceLevel: number;
}

function computeDCG(rankedDocs: ReadonlyArray<GradedRelevance>, cutoff: number): number {
  let dcg = 0;
  const k = Math.min(cutoff, rankedDocs.length);

  for (let i = 0; i < k; i++) {
    const gain = Math.pow(2, rankedDocs[i].relevanceLevel) - 1;
    const discount = Math.log2(i + 2);
    dcg += gain / discount;
  }

  return dcg;
}

function computeIDCG(relevanceLevels: ReadonlyArray<number>, cutoff: number): number {
  const sorted = [...relevanceLevels].sort((a, b) => b - a);
  const idealDocs = sorted.slice(0, cutoff).map((rel, i) => ({
    docId: `ideal_${i}`,
    relevanceLevel: rel,
  }));
  return computeDCG(idealDocs, cutoff);
}

function computeNDCG(
  rankedDocs: ReadonlyArray<GradedRelevance>,
  allRelevanceLevels: ReadonlyArray<number>,
  cutoff: number,
): number {
  const dcg = computeDCG(rankedDocs, cutoff);
  const idcg = computeIDCG(allRelevanceLevels, cutoff);
  return idcg > 0 ? dcg / idcg : 0;
}

interface NDCGEvaluation {
  readonly queryId: string;
  readonly ndcgAt5: number;
  readonly ndcgAt10: number;
  readonly ndcgAt20: number;
  readonly dcgAt10: number;
  readonly idcgAt10: number;
}

function evaluateQuery(
  queryId: string,
  rankedDocs: ReadonlyArray<GradedRelevance>,
  allRelevanceLevels: ReadonlyArray<number>,
): NDCGEvaluation {
  return {
    queryId,
    ndcgAt5: computeNDCG(rankedDocs, allRelevanceLevels, 5),
    ndcgAt10: computeNDCG(rankedDocs, allRelevanceLevels, 10),
    ndcgAt20: computeNDCG(rankedDocs, allRelevanceLevels, 20),
    dcgAt10: computeDCG(rankedDocs, 10),
    idcgAt10: computeIDCG(allRelevanceLevels, 10),
  };
}
NDCG（Normalized DCG）通过除以理想排序的 DCG（IDCG）将 DCG 归一化到 [0, 1] 范围。IDCG 是将所有文档按相关性从高到低排列时的 DCG 值，代表完美排序的效果上限。NDCG = 1.0 意味着系统的排序与理想排序完全一致。


NDCG 的工程实践
NDCG@k 是工业搜索系统中最常用的评估指标，k 的选择取决于产品形态：Web 搜索通常用 NDCG@10（一页结果），移动搜索用 NDCG@5（屏幕有限），商品搜索可能用 NDCG@20（用户会翻页浏览）。


在线评估中，NDCG 需要与点击模型结合。由于在线场景无法获得全面的人工相关性判定，通常使用点击数据作为隐式反馈：被点击的文档赋予较高的相关性分数，展示但未点击的赋予较低分数，未展示的文档不参与计算。这种基于点击的 NDCG 存在位置偏差（高位文档更容易被点击），需要通过 IPW（Inverse Propensity Weighting）等方法校正。

MRR 与其他排序指标
MRR（Mean Reciprocal Rank）适用于只关心第一个正确答案的场景，如导航型查询和问答系统。RR（Reciprocal Rank）等于第一个相关文档排位的倒数：如果第一个相关文档排在第 3 位，RR = 1/3。MRR 是多个查询的 RR 均值。


function computeReciprocalRank(rankedDocs: ReadonlyArray<string>, relevant: ReadonlySet<string>): number {
  for (let i = 0; i < rankedDocs.length; i++) {
    if (relevant.has(rankedDocs[i])) {
      return 1 / (i + 1);
    }
  }
  return 0;
}

function computeMRR(
  queries: ReadonlyArray<{
    rankedDocs: ReadonlyArray<string>;
    relevant: ReadonlySet<string>;
  }>,
): number {
  if (queries.length === 0) return 0;
  let totalRR = 0;
  for (const q of queries) {
    totalRR += computeReciprocalRank(q.rankedDocs, q.relevant);
  }
  return totalRR / queries.length;
}
ERR（Expected Reciprocal Rank）是 NDCG 的概率模型替代，它模拟用户从上到下浏览结果并在某个位置停止的行为。ERR 考虑了文档之间的依赖关系：如果排在前面的文档已经满足了用户需求，后续文档即使相关，其贡献也会被折扣。这比 NDCG 假设文档独立评估更接近真实用户行为。


小结
    

  • AP 衡量单个查询的排序质量，MAP 是 AP 在多查询上的平均
    • 

  • MAP 等价于 PR 曲线下面积，是二元相关性下最全面的评估指标
    • 

  • DCG 引入分级相关性和对数位置折损，NDCG 通过除以 IDCG 归一化到 [0, 1]
    • 

  • NDCG@k 是工业搜索系统最常用的评估指标，k 取决于产品形态
    • 

  • 在线评估中基于点击的 NDCG 需要 IPW 校正位置偏差
    • 

  • MRR 适用于只关心首个正确答案的场景
    • 

  • 不同指标适用于不同检索场景，选择时需考虑相关性类型和用户行为模型
