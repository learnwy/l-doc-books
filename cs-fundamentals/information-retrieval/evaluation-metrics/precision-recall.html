精确率与召回率

核心概念

精确率（Precision）和召回率（Recall）是信息检索评估中最基础的两个指标，它们从不同维度衡量检索系统的效果。精确率衡量系统返回的结果中有多少是真正相关的（「返回的有多准」），召回率衡量所有相关文档中有多少被系统成功检索到（「该找的找回了多少」）。两者之间存在天然的张力——提高精确率往往会降低召回率，反之亦然。

集合检索中的 P/R 计算
在布尔检索模型中，系统返回一个无序的文档集合，精确率和召回率的计算直截了当。设相关文档集合为 Rel，返回结果集为 R，则 P = |R ∩ Rel| / |R|，R = |R ∩ Rel| / |Rel|。


实际计算需要「相关性判定」（Relevance Judgment）作为基准。在标准评测中，评估者会对查询-文档对标注二元相关性（相关/不相关）或分级相关性（0-4 分）。TREC（Text REtrieval Conference）使用「pooling」方法：将多个系统的 top-k 结果合并，人工标注该池中的文档相关性。


interface RelevanceJudgment {
  readonly queryId: string;
  readonly docId: string;
  readonly relevance: number;
}

interface RetrievalResult {
  readonly queryId: string;
  readonly rankedDocs: ReadonlyArray<string>;
}

interface PrecisionRecallResult {
  readonly precision: number;
  readonly recall: number;
  readonly f1: number;
  readonly fBeta: number;
  readonly tp: number;
  readonly fp: number;
  readonly fn: number;
}

function computePrecisionRecall(
  retrieved: ReadonlyArray<string>,
  relevant: ReadonlySet<string>,
  beta: number = 1,
): PrecisionRecallResult {
  let tp = 0;
  let fp = 0;

  for (const docId of retrieved) {
    if (relevant.has(docId)) {
      tp++;
    } else {
      fp++;
    }
  }

  const fn = relevant.size - tp;
  const precision = retrieved.length > 0 ? tp / retrieved.length : 0;
  const recall = relevant.size > 0 ? tp / relevant.size : 0;
  const f1Denom = precision + recall;
  const f1 = f1Denom > 0 ? (2 * precision * recall) / f1Denom : 0;
  const betaSq = beta * beta;
  const fBetaDenom = betaSq * precision + recall;
  const fBeta = fBetaDenom > 0 ? ((1 + betaSq) * precision * recall) / fBetaDenom : 0;

  return { precision, recall, f1, fBeta, tp, fp, fn };
}
需要注意的是，精确率和召回率在不同截断点（cutoff）下表现不同。P@10 表示只看前 10 个结果时的精确率，是 Web 搜索中最常用的指标，因为大多数用户只关注首页的 10 个结果。P@k 随 k 增大通常下降，R@k 随 k 增大而上升。


精确率-召回率曲线
精确率-召回率曲线（PR Curve）描绘了系统在不同召回率水平下的精确率表现。对于有序的检索结果列表，从 top-1 到 top-N 逐步扩大结果集，在每个位置计算 P 和 R 并绘制曲线。理想系统的 PR 曲线紧贴右上角，随机系统的 PR 曲线近似于水平线 P ≈ |Rel|/|D|。


插值精确率（Interpolated Precision）用于消除 PR 曲线的锯齿。在标准 11 点插值中，对 11 个标准召回率水平（0, 0.1, 0.2, ..., 1.0）计算插值精确率：P_interp(r) = max(P(r')) for r' ≥ r。这意味着在每个召回率水平，取该水平及更高召回率的最大精确率。


interface PRCurvePoint {
  readonly recall: number;
  readonly precision: number;
  readonly rank: number;
  readonly docId: string;
  readonly isRelevant: boolean;
}

function computePRCurve(rankedDocs: ReadonlyArray<string>, relevant: ReadonlySet<string>): ReadonlyArray<PRCurvePoint> {
  const points: PRCurvePoint[] = [];
  let relevantSoFar = 0;

  for (let i = 0; i < rankedDocs.length; i++) {
    const docId = rankedDocs[i];
    const isRelevant = relevant.has(docId);
    if (isRelevant) relevantSoFar++;

    points.push({
      recall: relevant.size > 0 ? relevantSoFar / relevant.size : 0,
      precision: i + 1 > 0 ? relevantSoFar / (i + 1) : 0,
      rank: i + 1,
      docId,
      isRelevant,
    });
  }
  return points;
}

function interpolatePrecision(
  points: ReadonlyArray<PRCurvePoint>,
  recallLevels: ReadonlyArray<number>,
): ReadonlyArray<{ recall: number; interpolatedPrecision: number }> {
  return recallLevels.map((targetRecall) => {
    const eligiblePoints = points.filter((p) => p.recall >= targetRecall);
    const maxPrecision = eligiblePoints.length > 0 ? Math.max(...eligiblePoints.map((p) => p.precision)) : 0;
    return { recall: targetRecall, interpolatedPrecision: maxPrecision };
  });
}
F-Measure：精确率与召回率的综合
F-Measure（F 值）通过调和平均数将精确率和召回率综合为单一指标。调和平均数相比算术平均数更偏向较低的值，因此 F1 = 0.8 要求 P 和 R 都不能太低——即使一个很高（如 0.99），如果另一个很低（如 0.01），F1 也会很低（约 0.02）。


Fβ 允许调整精确率和召回率的相对权重。β < 1 时更重视精确率（如 F0.5 常用于搜索质量评估），β > 1 时更重视召回率（如 F2 常用于法律检索和医学诊断）。β 的含义是：召回率的重要性是精确率的 β 倍。

在多查询评估中，F 值有两种平均方式：宏平均（Macro-F1，先算每个查询的 F1 再取平均）和微平均（Micro-F1，先汇总所有 TP/FP/FN 再算 F1）。宏平均对每个查询同等权重，微平均受高频查询影响更大。


实际评估中的陷阱
精确率和召回率在实际使用中存在若干常见陷阱。首先是「不完整判定偏差」：当相关性判定不完整时（只标注了部分文档的相关性），召回率的分母 |Rel| 是未知的。标准做法是假设未判定文档为不相关，但这会系统性地低估新系统发现新相关文档的能力。


其次是「评价者间一致性」问题：不同评价者对同一文档的相关性判定可能不一致。Cohen's Kappa 系数用于衡量评价者间一致性，TREC 评测中典型的 Kappa 值在 0.4-0.6 之间（中等一致）。这意味着基于人工判定的 P/R 指标本身就存在固有噪音。


interface EvaluationConfig {
  readonly unjudgedStrategy: 'non-relevant' | 'remove' | 'condensed';
  readonly minRelevanceLevel: number;
  readonly binarize: boolean;
}

function computeWithUnjudged(
  rankedDocs: ReadonlyArray<string>,
  judgments: ReadonlyMap<string, number>,
  config: EvaluationConfig,
): PrecisionRecallResult {
  const filtered = config.unjudgedStrategy === 'remove' ? rankedDocs.filter((d) => judgments.has(d)) : rankedDocs;

  const relevant = new Set<string>();
  for (const [docId, rel] of judgments) {
    if (rel >= config.minRelevanceLevel) {
      relevant.add(docId);
    }
  }

  return computePrecisionRecall(filtered, relevant);
}
第三是「精确率和召回率的尺度不对称」：在大规模文档集合中（如十亿级 Web 索引），即使召回率仅提升 0.1%，绝对数量上也可能意味着发现了数千篇新的相关文档。因此在大规模场景中，召回率的微小变化可能比看起来更有意义。


小结
    

  • 精确率衡量返回结果的纯度，召回率衡量相关文档的覆盖度
    • 

  • P@k 是 Web 搜索最常用指标，因用户通常只看前 k 个结果
    • 

  • PR 曲线描绘了精确率随召回率变化的完整图景，插值消除锯齿
    • 

  • F-Measure 通过调和平均综合 P 和 R，β 参数控制两者权重
    • 

  • 不完整判定、评价者不一致和尺度不对称是实际评估中的常见陷阱
    • 

  • 宏平均和微平均 F1 在多查询场景中适用于不同需求
    • 

  • 精确率和召回率虽然基础，但理解其局限性对正确使用高级指标至关重要
