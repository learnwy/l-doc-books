评估方法论

核心概念

评估方法论是信息检索研究和工程实践的方法论基础，解决的核心问题是：如何设计科学、可复现、可比较的评估实验。一个检索系统的好坏不能凭直觉判断，而需要在标准化的测试集上，使用规范的评估流程，得出统计显著的结论。从 TREC（Text REtrieval Conference）到现代搜索引擎的 A/B 测试，评估方法论贯穿了 IR 领域的全部历史。

测试集构建
标准 IR 测试集由三部分组成：文档集合（Corpus）、查询集（Query Set）和相关性判定（Relevance Judgments，简称 Qrels）。这三者共同构成了评估的「黄金标准」。


文档集合的规模和类型决定了评估的适用范围。TREC 使用过多种文档集合：早期的 AP Newswire（约 25 万篇新闻）、后来的 GOV2（约 2500 万网页）、以及近年的 MS MARCO（约 880 万段落）。文档集的选择需考虑领域覆盖度、文档长度分布和内容质量。


查询集的设计同样关键。好的查询集应该覆盖不同的查询类型（导航型、信息型、事务型）、不同的长度（短查询 1-3 词、长查询 5+ 词）和不同的难度级别。TREC 查询集通常由信息需求描述（Topic）、简短查询（Title）和详细描述（Description）三部分组成。


interface TestCollection {
  readonly name: string;
  readonly corpus: CorpusInfo;
  readonly queries: ReadonlyArray<Query>;
  readonly qrels: ReadonlyMap<string, ReadonlyMap<string, number>>;
}

interface CorpusInfo {
  readonly documentCount: number;
  readonly avgDocLength: number;
  readonly domain: string;
  readonly language: string;
}

interface Query {
  readonly queryId: string;
  readonly title: string;
  readonly description: string;
  readonly narrative: string;
  readonly type: 'navigational' | 'informational' | 'transactional';
}

interface RelevanceAnnotation {
  readonly queryId: string;
  readonly docId: string;
  readonly relevance: number;
  readonly annotatorId: string;
  readonly confidence: number;
}

function buildQrels(
  annotations: ReadonlyArray<RelevanceAnnotation>,
  aggregation: 'majority' | 'average' | 'max',
): ReadonlyMap<string, ReadonlyMap<string, number>> {
  const grouped = new Map<string, Map<string, number[]>>();

  for (const ann of annotations) {
    if (!grouped.has(ann.queryId)) {
      grouped.set(ann.queryId, new Map());
    }
    const queryMap = grouped.get(ann.queryId)!;
    if (!queryMap.has(ann.docId)) {
      queryMap.set(ann.docId, []);
    }
    queryMap.get(ann.docId)!.push(ann.relevance);
  }

  const qrels = new Map<string, Map<string, number>>();
  for (const [qid, docMap] of grouped) {
    const aggregated = new Map<string, number>();
    for (const [did, scores] of docMap) {
      switch (aggregation) {
        case 'majority':
          aggregated.set(did, majorityVote(scores));
          break;
        case 'average':
          aggregated.set(did, scores.reduce((a, b) => a + b, 0) / scores.length);
          break;
        case 'max':
          aggregated.set(did, Math.max(...scores));
          break;
      }
    }
    qrels.set(qid, aggregated);
  }
  return qrels;
}

function majorityVote(scores: number[]): number {
  const counts = new Map<number, number>();
  for (const s of scores) {
    counts.set(s, (counts.get(s) ?? 0) + 1);
  }
  let maxCount = 0;
  let result = 0;
  for (const [score, count] of counts) {
    if (count > maxCount) {
      maxCount = count;
      result = score;
    }
  }
  return result;
}
Pooling 方法与标注效率
当文档集合包含数百万甚至数十亿文档时，不可能对每个查询的所有文档进行相关性标注。Pooling 方法通过汇集多个检索系统的 top-k 结果形成候选池，只对池中文档进行标注。TREC 典型的 pool 深度为 100（取每个参赛系统 top-100 的并集）。


Pooling 的关键假设是：如果没有任何系统检索到某个文档，那么该文档大概率是不相关的。这个假设在系统多样性足够时成立，但对于采用全新方法的系统可能不公平——新方法发现的相关文档可能不在 pool 中，导致被错误标记为不相关。

动态 Pooling（如 Move-to-Front Pooling）根据已标注结果动态调整后续标注优先级：如果某系统贡献了更多相关文档，则优先标注该系统排位更深的结果。这可以在相同标注预算下发现更多相关文档。


统计显著性检验
比较两个检索系统的效果时，不能仅凭 MAP 或 NDCG 的数值差异下结论——差异可能来自随机波动。统计显著性检验用于判断观测到的效果差异是否具有统计学意义。


配对 t 检验（Paired t-test）是 IR 评估中最常用的统计检验方法。对于 n 个查询，系统 A 和 B 分别产生 n 个 AP 值，检验两组 AP 值的差异是否显著。零假设是「两系统效果无差异」，当 p 值小于显著性水平（通常 α = 0.05）时拒绝零假设。


interface SignificanceTestResult {
  readonly testName: string;
  readonly statistic: number;
  readonly pValue: number;
  readonly significant: boolean;
  readonly effectSize: number;
  readonly confidenceInterval: [number, number];
}

function pairedTTest(
  scoresA: ReadonlyArray<number>,
  scoresB: ReadonlyArray<number>,
  alpha: number = 0.05,
): SignificanceTestResult {
  const n = scoresA.length;
  const diffs = scoresA.map((a, i) => a - scoresB[i]);
  const meanDiff = diffs.reduce((sum, d) => sum + d, 0) / n;
  const variance = diffs.reduce((sum, d) => sum + (d - meanDiff) ** 2, 0) / (n - 1);
  const stdError = Math.sqrt(variance / n);
  const tStat = stdError > 0 ? meanDiff / stdError : 0;

  const pooledStd = Math.sqrt(variance);
  const effectSize = pooledStd > 0 ? meanDiff / pooledStd : 0;

  return {
    testName: 'Paired t-test',
    statistic: tStat,
    pValue: approximatePValue(tStat, n - 1),
    significant: Math.abs(tStat) > criticalValue(alpha, n - 1),
    effectSize,
    confidenceInterval: [
      meanDiff - criticalValue(alpha, n - 1) * stdError,
      meanDiff + criticalValue(alpha, n - 1) * stdError,
    ],
  };
}

function approximatePValue(tStat: number, df: number): number {
  const x = df / (df + tStat * tStat);
  return x;
}

function criticalValue(alpha: number, df: number): number {
  if (df >= 120) return 1.96;
  if (df >= 30) return 2.042;
  return 2.093;
}
Bonferroni 校正用于多重比较场景：当同时比较 m 个系统对时，将显著性水平调整为 α/m，以控制 Family-Wise Error Rate。Bootstrap 检验是另一种选择，通过对查询集重采样估计指标差异的分布，不要求数据服从正态分布。


在线评估与 A/B 测试
离线评估（基于固定测试集）和在线评估（基于实时用户行为）各有优劣。离线评估可复现但与真实用户体验存在 gap，在线评估直接反映用户偏好但成本高且难复现。现代搜索系统通常先用离线评估筛选候选方案，再用在线 A/B 测试做最终决策。


A/B 测试将用户随机分为对照组（现有系统）和实验组（新系统），对比两组的关键指标（如点击率、查询成功率、会话时长）。关键设计要素包括：样本量计算（确保统计功效）、随机化策略（用户级 vs 会话级）、指标选择（短期行为 vs 长期留存）和实验持续时间（通常 1-4 周）。


Interleaving 是一种比 A/B 测试更灵敏的在线评估方法。它将两个系统的结果交错混合在同一个结果页中展示给用户，通过用户点击行为推断哪个系统更好。Team Draft Interleaving 和 Multileaved Comparisons 是两种主流的交错策略。实验表明 Interleaving 比 A/B 测试需要少一个数量级的流量就能达到相同的检测灵敏度。


小结
    

  • Cranfield 范式（标准测试集 + 离线评估）是 IR 评估的基石
    • 

  • 测试集由文档集合、查询集和相关性判定三部分组成
    • 

  • Pooling 方法解决大规模集合中相关性标注的可行性问题
    • 

  • 统计显著性检验（配对 t 检验、Bootstrap）确保效果差异的可靠性
    • 

  • 在线 A/B 测试直接反映用户偏好，是工业系统的最终评判标准
    • 

  • Interleaving 比 A/B 测试灵敏度高一个数量级
    • 

  • 完整的评估体系应结合离线和在线方法，科学地指导系统迭代
