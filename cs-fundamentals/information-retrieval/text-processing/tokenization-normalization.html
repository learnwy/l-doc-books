分词与归一化

核心概念

分词（Tokenization）和归一化（Normalization）是信息检索文本处理流水线的第一步，负责将原始文本转化为可索引的标准化词项（Term）序列。分词将连续的字符流切分为离散的词项单元，归一化则将形态各异的词项统一为标准形式。这两个步骤的质量直接决定了下游索引和检索的效果——如果分词错误或归一化不当，后续的 TF-IDF 权重、倒排索引和查询匹配都会受到连锁影响。

英文分词策略
英文分词看似简单（按空格切分），实际包含大量需要仔细处理的边界情况。最基础的空白符分词器（Whitespace Tokenizer）按空格和制表符切分文本，但无法正确处理标点符号、缩写、连字符和特殊格式。


标准分词器（Standard Tokenizer）在空白符分词的基础上增加了标点处理规则：移除句末标点、保留缩写中的撇号（如 don't → don't 或 do n't）、处理数字中的逗号和小数点（如 1,000.50）。Lucene 和 Elasticsearch 默认使用的 Standard Tokenizer 基于 Unicode Text Segmentation 标准（UAX #29）实现。


interface TokenizerConfig {
  readonly type: 'whitespace' | 'standard' | 'pattern' | 'ngram' | 'subword';
  readonly maxTokenLength: number;
  readonly preserveCase: boolean;
  readonly handleHyphen: 'split' | 'keep' | 'both';
  readonly handleApostrophe: 'split' | 'keep';
}

interface Token {
  readonly term: string;
  readonly startOffset: number;
  readonly endOffset: number;
  readonly position: number;
  readonly type: 'word' | 'number' | 'email' | 'url' | 'cjk';
}

function standardTokenize(text: string): ReadonlyArray<Token> {
  const tokens: Token[] = [];
  const pattern = /[\p{L}\p{N}][\p{L}\p{N}'·-]*/gu;
  let match: RegExpExecArray | null;
  let position = 0;

  while ((match = pattern.exec(text)) !== null) {
    tokens.push({
      term: match[0],
      startOffset: match.index,
      endOffset: match.index + match[0].length,
      position: position++,
      type: /^\d/.test(match[0]) ? 'number' : 'word',
    });
  }
  return tokens;
}
子词分词（Subword Tokenization）是近年来随着深度学习兴起的重要技术。BPE（Byte Pair Encoding）、WordPiece 和 Unigram 等算法通过数据驱动的方式学习子词词表，能够处理 OOV（Out-of-Vocabulary）问题。BERT 使用的 WordPiece 将 playing 切分为 play + ##ing，既保留了词根信息又能处理未见过的词汇。


中文分词技术
中文没有天然的词边界标记，分词是中文信息检索的核心挑战。中文分词方法分为三大流派：基于词典的方法、基于统计的方法和基于深度学习的方法。


基于词典的方法（如正向最大匹配 FMM 和逆向最大匹配 BMM）使用预定义词典进行贪心匹配。FMM 从左向右扫描文本，每次匹配词典中最长的词。BMM 则从右向左匹配。双向最大匹配（BM）同时运行两个方向并比较结果，选择分词数更少的方案。


基于统计的方法（如 HMM、CRF）将分词视为序列标注任务，通过训练数据学习字符到标签（B-词首/M-词中/E-词尾/S-单字词）的映射。jieba 分词器结合了词典匹配和 HMM 模型，是中文 IR 系统中最常用的工具。


interface ChineseSegmenter {
  segment(text: string): ReadonlyArray<string>;
  addWord(word: string, freq?: number, tag?: string): void;
  suggestFreq(segment: string): number;
}

interface SegmentResult {
  readonly words: ReadonlyArray<string>;
  readonly method: 'fmm' | 'bmm' | 'hmm' | 'crf' | 'bert';
  readonly confidence: ReadonlyArray<number>;
}

function forwardMaxMatch(text: string, dict: Set<string>, maxLen: number): ReadonlyArray<string> {
  const result: string[] = [];
  let i = 0;
  while (i < text.length) {
    let matched = false;
    for (let len = Math.min(maxLen, text.length - i); len > 1; len--) {
      const candidate = text.slice(i, i + len);
      if (dict.has(candidate)) {
        result.push(candidate);
        i += len;
        matched = true;
        break;
      }
    }
    if (!matched) {
      result.push(text[i]);
      i++;
    }
  }
  return result;
}

Unicode 归一化与大小写折叠
Unicode 归一化解决同一字符存在多种编码表示的问题。例如，é 可以用单个码位 U+00E9（NFC 形式）表示，也可以用 e + 组合重音符 U+0301（NFD 形式）表示。如果不做归一化，同一个词在索引和查询中可能因为编码不同而无法匹配。


NFC（Canonical Decomposition followed by Canonical Composition）和 NFD（Canonical Decomposition）是最常用的两种归一化形式。IR 系统通常选择 NFC，因为它产生最紧凑的表示。NFKC 和 NFKD 进一步将兼容等价字符统一，例如将全角字母 Ａ 转为半角 A。


interface NormalizationPipeline {
  readonly unicodeForm: 'NFC' | 'NFD' | 'NFKC' | 'NFKD';
  readonly caseFolding: 'lower' | 'upper' | 'aggressive' | 'none';
  readonly accentHandling: 'keep' | 'strip';
  readonly widthNormalization: boolean;
}

function normalizeToken(token: string, config: NormalizationPipeline): string {
  let result = token.normalize(config.unicodeForm);

  if (config.widthNormalization) {
    result = result.replace(/[\uFF01-\uFF5E]/g, (ch) => String.fromCharCode(ch.charCodeAt(0) - 0xfee0));
  }

  if (config.accentHandling === 'strip') {
    result = result.normalize('NFD').replace(/[\u0300-\u036f]/g, '');
    result = result.normalize(config.unicodeForm);
  }

  if (config.caseFolding === 'lower') {
    result = result.toLowerCase();
  } else if (config.caseFolding === 'aggressive') {
    result = result.toLocaleLowerCase('tr');
  }

  return result;
}
大小写折叠（Case Folding）将大写字母转为小写，使 Apple 和 apple 匹配同一个词项。但简单的 toLowerCase() 在某些语言中存在问题：德语的 ß 应折叠为 ss，土耳其语的 İ 应折叠为 i 而非英语的 I → i 规则。Unicode Case Folding 标准（CaseFolding.txt）定义了语言无关的完整折叠规则。


停用词过滤
停用词（Stop Words）是在文档集合中出现频率极高但携带极少语义信息的词汇，如英语的 the、is、at 和中文的「的」「了」「在」。移除停用词可以减少索引大小（通常减少 25-30%）、降低噪音并提升检索效率。


停用词表的构建有两种策略：基于频率的自动生成和人工编辑的标准列表。基于频率的方法统计语料库中每个词的文档频率（DF），将 DF 超过阈值（如出现在 80% 以上文档中）的词标记为停用词。人工列表如 NLTK 的英文停用词表（179 词）和百度的中文停用词表提供了经过验证的通用方案。

需要注意的是，现代搜索系统对停用词过滤越来越谨慎。在短语查询（"to be or not to be"）和位置感知检索中，停用词包含重要的句法信息。许多系统选择在索引时保留停用词，仅在查询扩展和相关性计算时降低其权重。


小结
    

  • 分词将连续文本切分为离散词项，英文基于空白符和标点规则，中文需要专门的分词算法
    • 

  • 子词分词（BPE/WordPiece）解决 OOV 问题，是深度学习时代的重要补充
    • 

  • 中文分词三大流派各有优劣：词典方法快、统计方法准、深度学习方法全面但慢
    • 

  • Unicode 归一化消除同一字符的多种编码表示，IR 系统通常采用 NFC 形式
    • 

  • 大小写折叠需考虑多语言差异，简单的 toLowerCase() 不够健壮
    • 

  • 停用词过滤在减小索引和降低噪音之间权衡，现代系统趋向保留停用词并降低权重
    • 

  • 文本处理流水线的每个步骤都需要根据应用场景和目标语言进行定制化配置
