布尔检索模型

核心概念

布尔检索模型（Boolean Retrieval Model）是信息检索中最早和最基础的检索模型，它将检索问题建模为集合论运算。在布尔模型中，每个文档被表示为一个词项（term）集合，查询被表示为由 AND、OR、NOT 运算符连接的布尔表达式。文档与查询的匹配是一个精确的布尔判定——文档要么满足条件（相关），要么不满足（不相关），没有中间状态。

倒排索引与布尔操作
布尔检索的效率依赖于倒排索引（Inverted Index）。倒排索引为每个词项维护一个倒排列表（posting list），记录包含该词项的所有文档 ID，通常按文档 ID 排序以支持高效的集合运算。


AND 运算对应两个有序列表的交集操作。由于倒排列表是有序的，可以使用双指针法在 O(n+m) 时间内完成交集计算，其中 n 和 m 分别是两个列表的长度。


interface PostingList {
  readonly term: string;
  readonly docIds: ReadonlyArray<number>;
  readonly docFrequency: number;
}

interface InvertedIndex {
  getPostings(term: string): PostingList | null;
  getDocCount(): number;
}

const intersect = (list1: ReadonlyArray<number>, list2: ReadonlyArray<number>): ReadonlyArray<number> => {
  const result: number[] = [];
  let i = 0;
  let j = 0;
  while (i < list1.length && j < list2.length) {
    if (list1[i] === list2[j]) {
      result.push(list1[i]);
      i++;
      j++;
    } else if (list1[i] < list2[j]) {
      i++;
    } else {
      j++;
    }
  }
  return result;
};

const union = (list1: ReadonlyArray<number>, list2: ReadonlyArray<number>): ReadonlyArray<number> => {
  const result: number[] = [];
  let i = 0;
  let j = 0;
  while (i < list1.length && j < list2.length) {
    if (list1[i] === list2[j]) {
      result.push(list1[i]);
      i++;
      j++;
    } else if (list1[i] < list2[j]) {
      result.push(list1[i]);
      i++;
    } else {
      result.push(list2[j]);
      j++;
    }
  }
  while (i < list1.length) result.push(list1[i++]);
  while (j < list2.length) result.push(list2[j++]);
  return result;
};
NOT 运算需要特别注意——它计算的是一个词项文档集合相对于整个文档集合的补集。直接计算补集的代价很高（需要遍历全部文档），因此实践中通常将 NOT 操作重写为与其他集合的差集运算。


查询优化策略
布尔查询的执行效率与词项处理顺序密切相关。考虑查询 "A AND B AND C"，如果 A 出现在 10000 个文档中、B 出现在 100 个文档中、C 出现在 5000 个文档中，最优策略是先处理 B（最短的倒排列表），再与 A 求交集，最后与 C 求交集。这种优化称为「从短到长」策略，它最小化了中间结果的大小。


对于包含 OR 的复杂查询，优化策略更加复杂。一般方法是将查询转换为析取范式（DNF）或合取范式（CNF），然后根据每个子句的预估代价选择执行计划。


interface BooleanQuery {
  readonly type: 'AND' | 'OR' | 'NOT' | 'TERM';
  readonly children?: ReadonlyArray<BooleanQuery>;
  readonly term?: string;
}

const optimizeAndQuery = (terms: ReadonlyArray<string>, index: InvertedIndex): ReadonlyArray<string> => {
  return [...terms].sort((a, b) => {
    const freqA = index.getPostings(a)?.docFrequency ?? 0;
    const freqB = index.getPostings(b)?.docFrequency ?? 0;
    return freqA - freqB;
  });
};

const evaluateBoolean = (query: BooleanQuery, index: InvertedIndex): ReadonlyArray<number> => {
  switch (query.type) {
    case 'TERM': {
      const postings = index.getPostings(query.term ?? '');
      return postings ? [...postings.docIds] : [];
    }
    case 'AND': {
      const childResults = (query.children ?? []).map((c) => evaluateBoolean(c, index));
      const sorted = childResults.sort((a, b) => a.length - b.length);
      return sorted.reduce((acc, curr) => intersect(acc, curr));
    }
    case 'OR': {
      const childResults = (query.children ?? []).map((c) => evaluateBoolean(c, index));
      return childResults.reduce((acc, curr) => union(acc, curr));
    }
    case 'NOT': {
      const childResult = evaluateBoolean((query.children ?? [])[0], index);
      const allDocs = Array.from({ length: index.getDocCount() }, (_, i) => i);
      return allDocs.filter((d) => !childResult.includes(d));
    }
    default:
      return [];
  }
};
扩展布尔模型
标准布尔模型的最大局限是缺少排序能力。扩展布尔模型通过引入权重和模糊匹配来缓解这个问题。


P-Norm 模型将 AND 和 OR 运算泛化为 p-范数距离，当 p=1 时退化为向量空间模型的行为，当 p→∞ 时退化为标准布尔模型。通过调整 p 值，可以在精确匹配和模糊匹配之间平滑过渡。


模糊布尔模型使用模糊集合论取代经典集合论，允许文档以 [0, 1] 之间的隶属度属于某个词项集合，而非简单的 0 或 1。这使得 AND 运算变为取最小值（min），OR 运算变为取最大值（max），NOT 运算变为 1 减去隶属度。

布尔检索的现代应用
尽管布尔模型在通用搜索引擎中已被排序模型取代，但它在特定领域仍然是不可替代的。法律检索要求极高的精确性和可解释性——律师需要确切知道为什么某个判例被检索到或被排除。布尔查询的逻辑透明性满足了这一需求。专利检索同样需要布尔逻辑来构建复杂的检索策略，确保不遗漏任何相关专利。


现代搜索引擎实际上在底层大量使用布尔运算——倒排索引的查找本质上就是布尔操作。BM25 等排序模型通常在布尔匹配的结果集上进行评分，布尔检索充当了粗筛阶段。结构化过滤（日期范围、类别筛选）也本质上是布尔运算。


小结
    

  • 布尔检索模型将文档和查询建模为词项集合，通过 AND/OR/NOT 集合运算实现精确匹配
    • 

  • 倒排索引的有序列表支持双指针法在 O(n+m) 时间内完成高效集合运算
    • 

  • 查询优化的核心策略是从最短倒排列表开始处理，最小化中间结果规模
    • 

  • 扩展布尔模型（P-Norm、模糊布尔）通过引入连续权重弥补了标准模型缺乏排序的缺陷
    • 

  • 布尔检索在法律、专利等需要精确控制和可解释性的领域仍不可替代
    • 

  • 现代搜索引擎在底层仍然依赖布尔运算作为倒排索引操作和结构化过滤的基础
