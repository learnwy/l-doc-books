信息检索概述

核心概念

信息检索（Information Retrieval，IR）是研究如何从大规模非结构化数据（主要是文本）集合中找到满足用户信息需求的文档的学科。IR 的核心问题可以概括为：给定一个查询 q 和一个文档集合 D，找到 D 中与 q 最相关的文档子集，并按相关性排序返回。这个看似简单的问题背后隐藏着「相关性」定义和度量的深层复杂性。

IR 系统基本组成
一个完整的 IR 系统由四个核心组件构成：文档处理管道、索引系统、查询处理器和排序引擎。


文档处理管道负责将原始文档转换为可索引的内部表示。处理步骤包括文本提取（从各种格式中提取纯文本）、分词（将连续文本切分为独立词项）、归一化（大小写转换、Unicode 规范化）、停用词过滤（移除 the、is 等高频无意义词）和词干提取（将词的变形还原为基本形式）。


interface IRSystem {
  index(documents: ReadonlyArray<Document>): Promise<void>;
  search(query: string, topK: number): Promise<ReadonlyArray<SearchResult>>;
  explain(query: string, docId: string): Promise<ScoreExplanation>;
}

interface Document {
  readonly id: string;
  readonly title: string;
  readonly content: string;
  readonly metadata: Record<string, unknown>;
}

interface SearchResult {
  readonly docId: string;
  readonly score: number;
  readonly snippet: string;
}

interface ScoreExplanation {
  readonly totalScore: number;
  readonly termScores: ReadonlyArray<{ term: string; score: number; tf: number; idf: number }>;
  readonly model: string;
}
索引系统是 IR 的核心数据结构，它将文档集合转换为支持高效检索的索引。最基本的索引类型是倒排索引——对于每个词项，记录包含该词项的所有文档及其位置。倒排索引使得从「给定文档找词」的正向查找转变为「给定词找文档」的反向查找，将检索时间从 O(N) 降低到 O(1)（通过哈希表）或 O(log N)（通过 B 树）。


相关性概念
相关性（Relevance）是 IR 的核心概念，也是最难精确定义的概念。直觉上，一个文档对一个查询「相关」意味着该文档包含了能满足用户信息需求的内容。但相关性是主观的——同一个查询对不同用户可能有不同的相关文档。


IR 研究中通常使用三级相关性标注：完全相关（文档直接回答了查询）、部分相关（文档包含相关信息但不完全满足需求）和不相关。更精细的标注使用 0-4 的五级量表。


相关性判定的困难在于「词汇鸿沟」问题——用户可能使用与文档中不同的词汇来表达相同的信息需求。例如用户查询「汽车」但相关文档使用「轿车」或「机动车辆」。这个问题驱动了从精确匹配到语义匹配的技术演进。

检索模型分类
IR 的核心理论是检索模型（Retrieval Model），它定义了查询和文档之间相关性的数学表示和计算方法。经典的检索模型分为三大流派。


集合论模型以布尔模型为代表，将文档和查询都表示为词项集合，通过集合运算（交集、并集、补集）来判定相关性。布尔模型的优势是精确控制——用户可以通过 AND、OR、NOT 精确指定检索条件。但它的致命缺陷是没有排序能力——文档要么满足布尔条件要么不满足，无法区分「非常相关」和「略微相关」。


代数模型以向量空间模型（VSM）为代表，将文档和查询都表示为高维向量空间中的向量，通过向量之间的角度（余弦相似度）来度量相关性。VSM 的革命性在于引入了连续的相关性度量，使得搜索结果可以按相关性排序。


概率模型以 BM25 和语言模型为代表，从概率论的角度定义相关性——给定查询 q，文档 d 相关的概率 P(R|q,d)。概率模型的理论基础最为扎实，BM25 至今仍是工业界最广泛使用的基线排序算法。


type RetrievalModel = BooleanModel | VectorSpaceModel | ProbabilisticModel | LanguageModel;

interface BooleanModel {
  readonly type: 'boolean';
  match(query: BooleanQuery, doc: Document): boolean;
}

interface VectorSpaceModel {
  readonly type: 'vsm';
  score(queryVector: ReadonlyArray<number>, docVector: ReadonlyArray<number>): number;
}

interface ProbabilisticModel {
  readonly type: 'probabilistic';
  score(query: ReadonlyArray<string>, doc: Document, collectionStats: CollectionStats): number;
}

interface LanguageModel {
  readonly type: 'language_model';
  score(query: string, docModel: DocumentLanguageModel): number;
}
现代 IR 的发展趋势
现代 IR 正在经历从词汇匹配到语义理解的范式转变。预训练语言模型（BERT、GPT）使得 IR 系统能够理解查询和文档的深层语义，而不仅仅是表面的词汇匹配。Dense Retrieval 使用双塔模型将查询和文档编码为稠密向量，通过 ANN 索引实现亚线性时间的语义检索。


另一个重要趋势是检索与生成的融合——RAG（Retrieval-Augmented Generation）将传统 IR 的检索能力与 LLM 的生成能力结合，创造了一种全新的信息访问范式。用户不再需要从检索结果中自行提取答案，系统能够直接生成精准的回答。


小结
    

  • 信息检索解决从大规模文本集合中找到满足用户信息需求的文档的问题
    • 

  • IR 系统由文档处理、索引构建、查询处理和排序引擎四个核心组件构成
    • 

  • 相关性是 IR 的核心概念，从主题相关性到功能相关性有多个层次
    • 

  • 检索模型分为集合论、代数和概率三大流派，BM25 是当前工业界的基线
    • 

  • 词汇鸿沟问题驱动了从精确匹配到语义匹配的技术演进
    • 

  • 现代 IR 正在经历预训练模型驱动的语义化和检索-生成融合两大变革
