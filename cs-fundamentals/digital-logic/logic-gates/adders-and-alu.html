加法器与 ALU

核心概念

加法器是数字电路中最基本的算术运算模块，而算术逻辑单元（ALU）则是在加法器基础上扩展而成的多功能运算核心。CPU 执行的每一条算术和逻辑指令最终都由 ALU 完成。理解加法器到 ALU 的构建过程，就是理解"数学运算如何被物理电路实现"的核心路径。

加法器设计的核心挑战是进位传播——低位的进位必须传递到高位才能得到正确结果，而这个串行传播过程是加法器速度的瓶颈。围绕加速进位传播产生了多种架构创新，从行波进位到超前进位再到并行前缀加法器，性能逐步提升。

Sum = A ⊕ B ⊕ Cᵢₙ，Cₒᵤₜ = AB + Cᵢₙ(A ⊕ B)


定义两个关键信号：


    

  • 生成信号（Generate）：G = A · B，表示该位自身产生进位
    • 

  • 传播信号（Propagate）：P = A ⊕ B，表示该位传递低位进位
    • 



则 Cₒᵤₜ = G + P · Cᵢₙ，这个公式是所有高速加法器设计的基础。


行波进位与超前进位加法器
行波进位加法器（Ripple Carry Adder，RCA） 是最简单的多位加法器——将 n 个全加器串联，每个全加器的进位输出连接到下一个全加器的进位输入。


RCA 的问题是延迟与位宽成线性关系。对于 32 位加法，进位需要从第 0 位逐级传播到第 31 位，总延迟约为 32 × tFA（全加器延迟）。在高频处理器中这是不可接受的。


超前进位加法器（Carry Lookahead Adder，CLA） 通过预计算进位来打破串行依赖。利用 G 和 P 信号，每一位的进位可以直接计算：


C₁ = G₀ + P₀·C₀
C₂ = G₁ + P₁·G₀ + P₁·P₀·C₀
C₃ = G₂ + P₂·G₁ + P₂·P₁·G₀ + P₂·P₁·P₀·C₀
C₄ = G₃ + P₃·G₂ + P₃·P₂·G₁ + P₃·P₂·P₁·G₀ + P₃·P₂·P₁·P₀·C₀
每个进位只依赖 G、P 和初始进位 C₀，可以并行计算，延迟仅为 O(1)——实际是两级门延迟（一级产生 G/P，一级计算进位）。


但 CLA 的硬件复杂度随位宽快速增长——4 位 CLA 的进位逻辑还可接受，但 32 位 CLA 的扇入会非常大。实际中使用分组 CLA：将 32 位分为 8 组，每组 4 位使用 CLA，组间再用一级 CLA 加速，总延迟约为 O(log n)。


减法器与补码运算
减法可以通过加法实现：A - B = A + (-B)。在二进制补码表示下，-B = B' + 1（按位取反再加 1）。这意味着减法器不需要独立的硬件——只需在加法器的一个输入端增加可控反相器，并将进位输入设为 1：


当控制信号 Sub=0 时执行加法：Result = A + B + 0 当控制信号 Sub=1 时执行减法：Result = A + B' + 1 = A + (-B) = A - B

补码表示的关键优势在于加法器不需要区分有符号数和无符号数——同一个硬件加法器可以正确处理两种情况。差别仅在于溢出检测逻辑：


    

  • 无符号溢出：最高位进位输出为 1
    • 

  • 有符号溢出：最高两位的进位不一致（Cₙ ⊕ Cₙ₋₁ = 1）
    • 



function addWithOverflow(a: number, b: number, bits: number) {
  const mask = (1 << bits) - 1;
  const result = (a + b) & mask;
  const signA = (a >> (bits - 1)) & 1;
  const signB = (b >> (bits - 1)) & 1;
  const signR = (result >> (bits - 1)) & 1;
  const overflow = signA === signB && signR !== signA;
  const carry = ((a + b) >> bits) & 1;
  return { result, overflow, carry };
}
ALU 的功能与结构
ALU 将加法/减法、逻辑运算、移位等功能集成在一个模块中，通过功能选择信号（ALU opcode）决定执行哪种运算。

SLT（Set Less Than）操作是比较运算的硬件实现：A < B 等价于 A - B < 0，即减法结果的符号位为 1。


ALU 还产生状态标志位（Flags），供后续的条件跳转指令使用：


    

  • Z（Zero）：结果为全零
    • 

  • N（Negative）：结果的最高位为 1
    • 

  • C（Carry）：最高位进位输出
    • 

  • V（Overflow）：有符号溢出
    • 



在 RISC-V 等现代指令集中，ALU 的操作码直接对应指令编码的特定位段。例如 RISC-V 的 R 型指令中，funct3 和 funct7 字段共同决定 ALU 执行 ADD、SUB、AND、OR、XOR 还是 SLT。


type AluOp = 'AND' | 'OR' | 'ADD' | 'SUB' | 'SLT';

function alu(a: number, b: number, op: AluOp, bits: number) {
  const mask = (1 << bits) - 1;
  let result: number;
  switch (op) {
    case 'AND':
      result = a & b;
      break;
    case 'OR':
      result = a | b;
      break;
    case 'ADD':
      result = (a + b) & mask;
      break;
    case 'SUB':
      result = (a - b + (1 << bits)) & mask;
      break;
    case 'SLT':
      result = (a - b) & (1 << (bits - 1)) ? 1 : 0;
      break;
  }
  const zero = result === 0;
  const negative = Boolean((result >> (bits - 1)) & 1);
  return { result, zero, negative };
}
小结
    

  • 全加器是多位加法器的基本构件，G/P 信号定义了进位的生成和传播
    • 

  • 行波进位加法器简单但延迟 O(n)，超前进位加法器通过预计算实现 O(log n)
    • 

  • 减法通过补码运算统一为加法，硬件加法器可同时处理加减法
    • 

  • ALU 将算术和逻辑运算集成，通过操作码选择功能
    • 

  • 状态标志位（Z/N/C/V）是条件分支指令的判断依据
    • 

  • 从半加器到 ALU 的构建过程体现了数字系统的层次化设计方法
    •
