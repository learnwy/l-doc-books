有限状态机设计

核心概念

有限状态机（Finite State Machine，FSM）是数字系统设计中最强大的抽象工具。它用有限个状态来描述系统行为——系统在任意时刻处于某个状态，根据当前输入决定输出和下一个状态。从 CPU 的控制单元到网络协议处理器，从交通灯控制器到 USB 接口，几乎所有需要"按步骤执行"的数字逻辑都可以建模为 FSM。

FSM 分为两种基本类型：Moore 型（输出仅取决于当前状态）和 Mealy 型（输出取决于当前状态和当前输入）。这个区别看似理论化，实际上直接影响电路的时序特性和设计复杂度。

状态编码策略
状态编码（State Encoding）是将抽象状态映射为二进制编码的过程。不同的编码策略对电路面积、速度和可靠性有显著影响。

二进制编码用最少的触发器表示所有状态。例如 4 个状态：S0=00, S1=01, S2=10, S3=11。触发器少但状态转移的组合逻辑较复杂。


独热编码为每个状态分配一个触发器——同一时刻恰好只有一个触发器为 1。例如 4 个状态：S0=0001, S1=0010, S2=0100, S3=1000。虽然触发器多，但状态判断极其简单——只需检查对应位是否为 1，组合逻辑大幅简化。


在 FPGA 中，独热编码通常是最优选择。因为 FPGA 的触发器（FF）相对廉价（每个 LUT 旁边都有一个 FF），而 LUT 数量有限。独热编码用更多 FF 换取更少 LUT，正好匹配 FPGA 的资源特点。


对于 ASIC 设计，二进制编码通常更优，因为触发器面积是真实成本。


type StateEncoding = 'binary' | 'oneHot' | 'gray';

function encodeStates(numStates: number, encoding: StateEncoding): string[] {
  switch (encoding) {
    case 'binary':
      return Array.from({ length: numStates }, (_, i) => i.toString(2).padStart(Math.ceil(Math.log2(numStates)), '0'));
    case 'oneHot':
      return Array.from({ length: numStates }, (_, i) => '0'.repeat(i) + '1' + '0'.repeat(numStates - i - 1));
    case 'gray':
      return Array.from({ length: numStates }, (_, i) =>
        (i ^ (i >> 1)).toString(2).padStart(Math.ceil(Math.log2(numStates)), '0'),
      );
  }
}
FSM 的硬件实现流程
从状态表到物理电路的实现流程是固定的：


    

  1. 状态最小化：合并等价状态（输出相同且后继状态相同）
    2. 

  2. 状态编码：选择编码策略并分配二进制编码
    3. 

  3. 推导转移方程：用布尔代数表示每个触发器的下一状态逻辑
    4. 

  4. 推导输出方程：用布尔代数表示每个输出信号
    5. 

  5. 化简实现：用卡诺图或 EDA 工具化简方程
    6. 

  6. 画电路图：连接触发器和组合逻辑
    7.

FSM 在控制单元中的应用
CPU 的控制单元是 FSM 最重要的应用。单周期处理器的控制单元是一个纯组合电路（可视为只有一个状态的 Mealy 型 FSM），而多周期处理器的控制单元则是一个具有多个状态的 Moore 型 FSM——每个状态对应指令执行的一个阶段（取指、译码、执行、访存、写回）。

每条指令类型（R 型、I 型、分支、访存）走过的状态路径不同。R 型指令不经过 MEMORY 状态，分支指令不经过 WRITEBACK 状态。这些不同的路径在状态转移图中表示为不同的分支。


流水线处理器虽然不使用传统 FSM 控制（因为每个阶段在每个周期都同时活跃），但流水线中的冒险检测、前递控制等逻辑仍然是 FSM 的变体。


FSM 的思想对软件设计也有深远影响。状态模式、正则表达式引擎、网络协议栈都是 FSM 概念在软件中的直接应用。理解 FSM 的硬件根源有助于更深刻地运用这些模式。


type State = 'IDLE' | 'HEADER' | 'PAYLOAD' | 'CHECKSUM' | 'ERROR';

小结
    

  • Moore 型输出仅取决于状态（无毛刺），Mealy 型还取决于输入（响应快）
    • 

  • 状态设计从状态转移图开始，经状态表、编码、方程推导最终映射为电路
    • 

  • 独热编码适合 FPGA（FF 廉价），二进制编码适合 ASIC（面积敏感）
    • 

  • CPU 控制单元是 FSM 最经典的应用——多周期处理器的每个状态对应一个执行阶段
    • 

  • FSM 概念延伸到软件领域的状态模式、正则表达式和协议栈
    • 

  • 状态最小化通过合并等价状态减少电路复杂度
