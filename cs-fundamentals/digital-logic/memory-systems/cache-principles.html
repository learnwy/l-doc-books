Part I · 理论基础 (Theory)数字逻辑与电路 简介存储系统 简介缓存原理

缓存原理

核心概念

缓存（Cache）是位于处理器和主存之间的小而快的存储器，它利用程序的局部性原理（Locality）来弥合处理器速度和主存速度之间不断扩大的差距。现代处理器典型的 L1 缓存命中时间约为 1ns（4 个时钟周期），而主存访问约为 50-100ns——一次缓存未命中的代价相当于 50-100 次缓存命中。

局部性原理包含两个维度：时间局部性（最近访问的数据很可能再次被访问）和空间局部性（与最近访问地址相邻的数据很可能被访问）。缓存的设计本质上就是如何最大化利用这两种局部性。

缓存映射策略
缓存映射策略决定了"主存中的某个块可以放在缓存的哪些位置"。这个决策直接影响命中率、硬件复杂度和访问速度。


直接映射（Direct Mapped）：每个主存块只能放在缓存的一个固定位置。位置由地址的中间位决定：Cache Index = (Block Address) mod (Number of Cache Lines)。


优点：查找简单（只需检查一个位置），硬件最小。缺点：冲突未命中率高——两个频繁访问的地址如果映射到同一位置，会不断互相驱逐（ping-pong effect）。


全相联（Fully Associative）：任何主存块可以放在缓存的任何位置。


优点：冲突未命中最少。缺点：每次查找需要并行比较所有缓存行的标签，硬件成本极高。仅用于 TLB 等小容量场景。


组相联（Set Associative）：折中方案。缓存分为多组（Set），每组有 N 路（Way）。主存块先映射到固定的组，然后可以放在组内的任意一路。

替换策略
当缓存组已满且发生未命中时，必须选择一个受害者（victim）驱逐。替换策略决定了驱逐哪一路。


LRU（Least Recently Used）：驱逐最近最少使用的行。LRU 基于时间局部性假设——长时间未被使用的行未来也不太可能被使用。


精确 LRU 需要为每一路维护访问时间戳并排序，硬件成本随相联度增大而急剧增加。对于 8 路组相联，精确 LRU 需要每路 3 位（log₂8）的排序信息，并在每次访问时更新。


伪 LRU（Pseudo-LRU）：使用二叉树结构近似 LRU 行为。每个内部节点存储一位指示"左子树或右子树更近被访问"。查找受害者时沿"最不近"的方向遍历到叶节点。伪 LRU 仅需 N-1 位（N 路需要 7 位），硬件成本远低于精确 LRU。


随机替换（Random）：随机选择一路驱逐。看似粗暴，但在高相联度下性能仅比 LRU 略差，且硬件最简单——只需一个计数器或线性反馈移位寄存器。

function pseudoLruEvict(treeBits: boolean[], ways: number): number {
  let node = 0;
  let victim = 0;
  const depth = Math.ceil(Math.log2(ways));
  for (let level = 0; level < depth; level++) {
    if (treeBits[node]) {
      victim = victim * 2 + 1;
      node = node * 2 + 2;
    } else {
      victim = victim * 2;
      node = node * 2 + 1;
    }
  }
  return victim;
}
写策略与一致性
缓存的写操作比读操作复杂，因为必须确保缓存和主存中数据的一致性。


写命中策略：


    

  • 写直达（Write-Through）：每次写操作同时更新缓存和主存。简单但主存带宽消耗大。通常配合写缓冲区（Write Buffer）来缓解。
    • 

  • 写回（Write-Back）：只写缓存，用脏位（Dirty Bit）标记被修改的行。仅当脏行被驱逐时才写回主存。减少主存写流量，但复杂度高。
    • 



写未命中策略：


    

  • 写分配（Write-Allocate）：未命中时先将目标块从主存读入缓存，再在缓存中写入。利用空间局部性。
    • 

  • 写不分配（No-Write-Allocate）：未命中时直接写主存，不读入缓存。适合写直达策略。
    • 



通常写回搭配写分配，写直达搭配写不分配。


在多核处理器中，缓存一致性（Cache Coherence）是更复杂的问题。每个核心有自己的 L1/L2 缓存，当一个核心修改了某个地址的数据，其他核心的缓存中的旧副本必须被无效化或更新。MESI 协议是最常用的一致性协议：

多级缓存与包容性
现代处理器通常有三级缓存：L1（最快最小，分指令/数据）、L2（较大较慢）、L3（最大最慢，多核共享）。

包容性策略决定了各级缓存之间的数据关系：


    

  • 包容式（Inclusive）：L2 包含 L1 的所有数据。L2 驱逐时必须同时驱逐 L1 中的副本（反向无效化）。简化一致性但浪费容量。
    • 

  • 排他式（Exclusive）：L1 和 L2 不存储重复数据。容量利用率最高但一致性管理复杂。
    • 

  • 非包容非排他（NINE）：不强制任何关系。最灵活，是现代处理器的主流选择。
    • 



对于程序员来说，理解缓存层次的核心价值在于编写缓存友好的代码——按缓存行大小对齐数据结构、优先使用顺序访问模式、避免 false sharing（不同核心写同一缓存行的不同字段）。


const CACHE_LINE = 64;

interface CacheFriendlyArray {
  readonly data: Float64Array;
  readonly stride: number;
}

function sumRowMajor(matrix: number[][], rows: number, cols: number): number {
  let sum = 0;
  for (let i = 0; i < rows; i++) for (let j = 0; j < cols; j++) sum += matrix[i][j];
  return sum;
}

function sumColMajor(matrix: number[][], rows: number, cols: number): number {
  let sum = 0;
  for (let j = 0; j < cols; j++) for (let i = 0; i < rows; i++) sum += matrix[i][j];
  return sum;
}
上述代码中 sumRowMajor 的性能通常远优于 sumColMajor，因为行优先遍历具有完美的空间局部性——连续访问的元素在同一缓存行中。列优先遍历则每次访问跳过整行，造成大量缓存未命中。


小结
    

  • 缓存利用局部性原理弥合处理器和主存的速度差距
    • 

  • 组相联是直接映射和全相联的折中，是现代缓存的主流选择
    • 

  • 替换策略在命中率和硬件成本之间权衡，伪 LRU 是实践中最常用的方案
    • 

  • 写回策略减少主存流量，写直达策略简化一致性
    • 

  • MESI 协议通过四种状态跟踪缓存行的共享和修改状态
    • 

  • 编写缓存友好的代码是软件性能优化中最重要的底层技能之一
    •
