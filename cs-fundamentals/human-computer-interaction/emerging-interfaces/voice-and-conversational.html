语音与对话式交互

核心概念

语音界面与对话式交互是 2010 年代 Siri/Alexa 主流化、2022 年 ChatGPT 让大语言模型进入消费市场的产物——与图形界面的视觉 + 空间交互不同，语音没有悬停、滚动、点击，依赖轮流对话。大语言模型让对话式人工智能从刻板指令（"嘿 Siri，播放歌曲某"）进化到自由对话（"给我一个某功能的 Python 函数"）。但语音/聊天设计有独特挑战——输入空间无边界、错误恢复难、隐私顾虑、认知负荷高（无视觉参考）。本节介绍语音界面设计原则、对话设计框架、错误恢复、轮流机制、基于大语言模型的聊天界面挑战。

维度 图形界面 语音/聊天
输入 点击/输入 有边界 开放式
输出 视觉丰富 顺序文本/音频
可发现性 高（可见） 低（隐藏）
错误恢复 视觉 对话式
认知负荷 低（可见） 高（需记忆）
隐私 本地 云端处理
无障碍 不一致 解放双手的优势

语音界面历史

1961 年 IBM Shoebox：识别 16 个单词 + 数字。

1990 年代 Dragon NaturallySpeaking：听写软件。

2011 年 Siri：主流语音助手。

2014 年 Amazon Echo/Alexa：家用语音设备。

2016 年 Google Assistant：多轮对话。

2022 年 ChatGPT：大语言模型对话式产品主流化。

2024 年 Claude/Gemini/GPT-4o：多模态语音 + 图像。

语音的独特设计挑战

1. 可发现性低：

  • "我能做某功能吗？"
  • 用户不知道系统能力。
  • 图形界面：按钮可见。
  • 语音：必须知道唤醒词 + 指令语法。

2. 认知负荷高：

  • 没有视觉提醒。
  • 用户需在工作记忆中保持选项。

3. 错误恢复难：

  • 语音识别错误后修正困难。
  • "你是说某吗？"。

4. 延迟：

  • 语音识别 + 处理 + 语音合成：1-3 秒延迟。
  • 触控操作 < 0.5 秒。

5. 隐私：

  • 始终监听的设备。
  • 数据发送到云端。
  • 用户担忧。

6. 多用户：

  • 多人共用一个家庭设备。
  • 区分声音 + 个人上下文困难。

对话设计原则

1. 简洁：

  • 短回答。
  • 不朗读大段文字。
  • 关键信息优先。

2. 确认意图：

  • "我为您订购 2 份披萨。确认吗？"
  • 防止误解。

3. 逐步提供选项：

  • 不朗读 10 个选项。
  • "您想要 A 还是 B？或者听更多选项？"

4. 优雅降级：

  • 听不懂时："抱歉，我没听清。您能再……？"

5. 人格一致：

  • 声音 + 语气一致。
  • Apple Siri 与 Google Assistant 人格不同。

6. 关注上下文：

  • 多轮对话。
  • 记住上一轮内容。

轮流机制

对话流程：

  • 用户 → 系统 → 用户 → ……
  • 每轮要短。

轮流信号：

  • 话语结束检测（语音识别端点）。
  • 平均 200-500 毫秒静音。
  • 但用户思考时也静音 → 误触发。

打断机制：

  • 用户打断系统发言。
  • 现代系统支持。
  • 提升效率。

确认时机：

  • 不每轮都确认（烦人）。
  • 高风险操作需确认（如"发送 500 元"）。

错误恢复

语音识别错误：

  • 误识别率约 5-15%（口音、噪音）。
  • 用户通过语音纠正困难。
  • 长句整句失败后令人烦躁。

策略：

1. 置信度阈值：

  • 低置信度 → 请求澄清。
  • "您说的是'披萨'还是'广场'？"

2. 优雅恢复：

  • 不只说"我没听懂"。
  • 提示能力："我可以帮您查天气、放音乐、看新闻。您需要哪个？"

3. 让用户自定义词汇：

  • 人名、家庭成员名字。

4. 多模态回退：

  • "或者打开应用查看选项"。
  • 不强制纯语音。
对话设计流程
1. 定义用户意图：


    

  • "设置计时器"。
    • 

  • "查天气"。
    • 



2. 列出话术变体：


    

  • "设置 5 分钟计时器"。
    • 

  • "5 分钟后叫醒我"。
    • 

  • "5 分钟计时器"。
    • 



3. 设计正常路径：


    

  • 标准成功流程。
    • 



4. 设计异常路径：


    

  • 误识别、超时、歧义、错误。
    • 



5. 人格/语气：


    

  • 友好/正式/俏皮。
    • 



6. 与真实用户测试：


    

  • 发现边缘案例。
    • 



语音 + 大语言模型（现代）
大语言模型之前的语音：


    

  • 基于规则的意图分类。
    • 

  • 词汇有限。
    • 

  • 脆弱易出错。
    • 



大语言模型语音：


    

  • 开放式理解。
    • 

  • 自由形式回答。
    • 

  • 但会幻觉。
    • 

  • 延迟高。
    • 



混合模式：


    

  • 简单意图 → 规则处理快。
    • 

  • 复杂查询 → 大语言模型。
    • 



多模态语音 + 屏幕：


    

  • iPhone"通过键盘向 Siri 提问"。
    • 

  • 语音提问，视觉 + 文字回答。
    • 

  • 两全其美。
    • 



聊天界面（文本对话）
ChatGPT 风格：


    

  • 文本输入 + 文本回复。
    • 

  • 流式输出（感知更快）。
    • 

  • 多轮上下文窗口。
    • 



设计原则：


1. 流式回复：


    

  • 立即开始输出。
    • 

  • 用户看到进展。
    • 



2. 停止按钮：


    

  • 用户可中断。
    • 



3. 编辑/重新生成：


    

  • 不满意 → 重新生成。
    • 

  • 历史消息可编辑。
    • 



4. 引用/来源：


    

  • 减少幻觉。
    • 

  • 让用户核实。
    • 



5. 建议追问：


    

  • 帮助用户探索。
    • 



6. 系统提示 + 人格：


    

  • 设定行为风格。
    • 



对话记忆
短期：


    

  • 会话内多轮。
    • 

  • 现代大语言模型支持长上下文。
    • 



长期：


    

  • 跨会话记忆。
    • 

  • ChatGPT 记忆功能。
    • 

  • 隐私顾虑。
    • 



用户控制：


    

  • 显示存储的记忆。
    • 

  • 编辑/删除。
    • 

  • 清除对话。
    • 



错误/幻觉
大语言模型会幻觉：


    

  • 编造事实。
    • 

  • 自信但错误。
    • 



设计缓解措施：


    

  • 显示置信度。
    • 

  • 提供引用。
    • 

  • "我不确定，但……"。
    • 

  • 可验证的来源链接。
    • 

  • 用户反馈按钮（点赞/点踩）。
    • 



信任校准：


    

  • 让用户知道人工智能不可靠。
    • 

  • 避免过度信任。
    • 



隐私
始终监听的设备：


    

  • 唤醒词检测在设备端。
    • 

  • 但误触发会录音上传云端。
    • 

  • 合理担忧。
    • 



缓解措施：


    

  • 本地处理（Apple 设备端 Siri）。
    • 

  • 可见指示器（监听时亮灯）。
    • 

  • 简单静音（物理按键）。
    • 

  • 易于删除历史。
    • 



大语言模型隐私：


    

  • 用户输入可能用于训练模型（除非关闭）。
    • 

  • 敏感信息担忧。
    • 

  • Apple 私有云计算是模式（云端 + 隐私保护）。
    • 



无障碍
语音是无障碍功能：


    

  • 视障用户受益于屏幕阅读器 + 语音控制。
    • 

  • 运动障碍用户受益于语音控制。
    • 

  • 阅读障碍用户受益于语音替代文字。
    • 



但语音也可能排斥：


    

  • 语言障碍者。
    • 

  • 重口音者（识别差）。
    • 

  • 聋哑用户（语音无效）。
    • 



包容性设计：


    

  • 语音 + 视觉 + 键盘多模回退。
    • 

  • 不假设纯语音使用。
    • 



实战案例
Alexa 订购：


    

  • "Alexa，订购纸巾"。
    • 

  • 多轮确认（"从您常用的品牌？"）。
    • 

  • 确认（"已下单，金额某元"）。
    • 

  • 失败恢复（"我没找到。要我搜索吗？"）。
    • 



ChatGPT 编程助手：


    

  • 用户输入自然语言。
    • 

  • 代码回复附带解释。
    • 

  • 流式输出。
    • 

  • 编辑代码 → 重新生成。
    • 

  • 引用文档。
    • 



Apple"通过键盘向 Siri 提问"：


    

  • 无声输入（公共场所）。
    • 

  • 语音可选。
    • 



反模式
1. 长语音回复：


    

  • 听 30 秒令人烦躁。
    • 

  • 先短回复，再提供详情。
    • 



2. 纯语音：


    

  • 其他方式可行时强迫用语音。
    • 



3. 始终监听无指示器：


    

  • 用户不知道正在录音。
    • 

  • 必须有可见指示器。
    • 



4. 无撤销：


    

  • 语音命令不可逆 → 危险。
    • 

  • 关键操作必须确认。
    • 



5. 人格不一致：


    

  • 不同模块声音不同。
    • 

  • 令人困惑。
    • 



6. 幻觉无提示：


    

  • 大语言模型自信地输出假信息。
    • 

  • 让用户错误信任。
    • 



现代趋势
1. 多模态语音：


    

  • 语音 + 视觉回复。
    • 

  • iPhone Siri、Google Assistant。
    • 



2. 设备端大语言模型：


    

  • Apple Intelligence、Gemini Nano。
    • 

  • 隐私 + 低延迟。
    • 



3. 实时语音：


    

  • GPT-4o、Gemini Live。
    • 

  • 自然对话。
    • 

  • 可打断 + 情感语调。
    • 



4. 人工智能代理：


    

  • 语音 → 动作链（"订机票去纽约"）。
    • 

  • 复杂任务。
    • 

  • 可靠性仍是挑战。
    • 



小结
语音界面与对话式交互已主流化（Siri 2011/Alexa 2014/ChatGPT 2022/GPT-4o 2024 多模态语音）。独特挑战——可发现性低（无可见按钮）、认知负荷高（无视觉提醒）、错误恢复难（语音识别误识率 5-15%）、延迟 1-3 秒、隐私担忧、多用户区分难。对话设计原则——简洁短回复、确认意图、逐步提供选项、优雅降级、人格一致、关注上下文。轮流机制——话语结束 200-500 毫秒静音、支持打断、仅高风险操作确认。错误恢复——置信度阈值、具体澄清、自定义词汇、多模回退。设计流程——定义意图 + 话术变体 + 正常路径 + 异常路径 + 人格 + 测试。大语言模型语音让理解开放但会幻觉/延迟，混合模式（规则简单 + 大语言模型复杂）。多模态语音 + 屏幕（iPhone Siri）两全其美。聊天界面设计——流式回复 + 停止按钮 + 编辑重新生成 + 引用 + 建议追问 + 系统提示。记忆分短期多轮和长期跨会话（隐私顾虑），用户可控制。幻觉缓解——置信度 + 引用 + "我不确定" + 可验证链接 + 反馈按钮。隐私——始终监听唤醒词在设备端、可见指示器、简单静音、删除历史、Apple 私有云计算模式。无障碍——语音是视障运动障碍阅读障碍受益的无障碍功能，但排斥语言障碍/重口音/聋哑用户。包容性多模回退。反模式——长回复、纯语音、无指示器、无撤销、人格不一致、幻觉无提示。现代趋势——多模态、设备端大语言模型、实时语音（GPT-4o）、人工智能代理。一个简单的检验：你能为"设置计时器"设计对话流程 + 错误恢复吗？如果不能，对话设计还需练习。语音 + 聊天界面是下一个十年的关键交互范式——理解独特设计挑战让你构建不困扰用户的产品。
