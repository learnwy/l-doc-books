认知负荷

核心概念

Cognitive load（认知负荷）是用户处理信息时占用的工作记忆——人类工作记忆容量约 7±2 chunk（Miller 1956）、保持 ~ 20 秒（不 rehearsal）、且会被 distraction 清空。过载（overload）让用户 confused、出错、放弃。Sweller's Cognitive Load Theory（1988）把负荷分 3 类——intrinsic（任务本身复杂度）、extraneous（UI 设计造成额外负荷）、germane（学习 / understanding 投入）。好 UX 减少 extraneous load 让用户专注 intrinsic + germane。这是为什么 Google 搜索仅一个 input 框（minimal extraneous）、为什么 Apple 强调 simplicity、为什么 progressive disclosure 把复杂信息分层展示。本节介绍 cognitive load 三类、人类 working memory 限制、information architecture 原则、design tactics 减少 load。

Load 类型 来源 减少策略
Intrinsic 任务本身复杂度 拆任务 / 分阶段
Extraneous UI 设计 problem 简化 / 一致 / clear
Germane Learning 投入 Schema 帮助

Working Memory 限制

Miller 7±2（1956）：

  • 短期记忆 chunk 容量 ~ 7。
  • "chunk" = meaningful unit（不是 raw bit）。
  • "555-1234" 是 1 chunk（电话格式）非 7 个 digit。

Cowan 4 limit（2001）：

  • 现代 research 修正到 ~ 4 chunk。
  • 但仍依赖 chunk 大小 + complexity。

保持时间：

  • ~ 20 秒不 rehearsal。
  • Distraction 立即清空。

实战：

  • 不要让用户 hold 多 piece info in mind。
  • 用 UI 把 info 显示出来（recognition > recall）。

Sweller's Cognitive Load Theory

Intrinsic load：

  • 任务本身固有复杂度。
  • 学微积分 intrinsic 高、加法 low。
  • 不能 reduce by UI——只能拆分 / 顺序。

Extraneous load：

  • UI / 设计造成的 unnecessary load。
  • 复杂 navigation、混乱 layout、不一致 interaction。
  • 设计师可控的部分——好 UX 减 extraneous。

Germane load：

  • 学习 / 理解 schema 的投入。
  • "Productive" load——帮 long-term memory。
  • 例：Tutorial 让用户 build mental model。

Total load = intrinsic + extraneous + germane——不能超过 working memory。

Recognition vs Recall
Recall（让用户 remember）：


    

  • 高 cognitive load。
    • 

  • 例：让用户记 password、记菜单 options。
    • 



Recognition（让用户 see + identify）：


    

  • 低 cognitive load。
    • 

  • 例：menu 显示 options、autocomplete suggest。
    • 



Nielsen heuristic #6："Recognition rather than recall"。


实战：


    

  • Login UI show recently logged-in account。
    • 

  • 搜索 autocomplete。
    • 

  • File picker（vs ask for filename）。
    • 



Progressive Disclosure
Idea：把复杂 info 分层 reveal——简单先 expose, 复杂在 demand。


例：


    

  • 设置：基本 simple defaults，"advanced" toggle reveal more。
    • 

  • 表单：简单 fields visible，"more options" expand。
    • 

  • 错误：简短 message + "details" link。
    • 



好处：


    

  • 减少 initial cognitive load。
    • 

  • 但 power user 仍能 access 完整 functionality。
    • 



反例：


    

  • 一次显示 100 个 settings。
    • 

  • 用户找不到要的、放弃。
    • 



Chunking
把多 item 组成 meaningful group：


    

  • "1234567890" → "(123) 456-7890"。
    • 

  • Form fields group 成 sections。
    • 

  • Menu items 分 categories。
    • 



好处：


    

  • 减少 effective N（Hick's Law）。
    • 

  • 提升 short-term memory（chunk count）。
    • 



Spacing / divider 帮 chunk visible。


Hick's Law
T = a + b · log₂(N + 1)
决策时间 ∝ log(选项数)。


实战：


    

  • Menu items ≤ 7±2。
    • 

  • 若多，分类（reduce effective N）。
    • 

  • Show recent / favorite first（user only choose from few）。
    • 

  • Default + "other"（让用户 default 选 default）。
    • 



减少 Extraneous Load 的设计 tactics
1. 简化 visual：


    

  • 删除 unnecessary decoration。
    • 

  • White space 让 important pop。
    • 

  • Minimal color palette。
    • 



2. Consistent：


    

  • 同 action 同 location 同 result。
    • 

  • 保持 design language。
    • 

  • Cross-platform：尊重 iOS HIG vs Material。
    • 



3. 明确 hierarchy：


    

  • Visual weight（size、color、position）。
    • 

  • F-pattern 或 Z-pattern reading。
    • 



4. Clear labels：


    

  • 不用 jargon。
    • 

  • "Save" 而非 "Persist"。
    • 

  • "Confirm" 而非 "Submit"。
    • 



5. Reduce 决策点：


    

  • Smart default（用户不需选）。
    • 

  • Auto-detect（地区、语言）。
    • 

  • Pre-fill 已知 info。
    • 



6. 反馈即时：


    

  • Loading state 即时显示。
    • 

  • Form validation real-time。
    • 

  • 不让用户怀疑。
    • 



7. Group related：


    

  • Form sections。
    • 

  • Menu categories。
    • 

  • Spacing as separator。
    • 



Cognitive load 在不同 context
Mobile：


    

  • Small screen → less info shown。
    • 

  • Walking / driving → 不能 attend 长 task。
    • 

  • 设计：极简、单 task focus。
    • 



Desktop：


    

  • Large screen → more info OK。
    • 

  • Sustained attention。
    • 

  • 设计：information-dense OK（dashboard、IDE）。
    • 



Voice / Audio：


    

  • Cannot show options。
    • 

  • Working memory more taxed。
    • 

  • 设计：少 options、structured。
    • 



AR/VR：


    

  • Spatial info 自然映射。
    • 

  • 但 motion sickness、attention 分散。
    • 

  • 设计：clear focal point。
    • 



Information Architecture
IA 是 organize info 的 art：


1. Hierarchy：


    

  • Tree-like。
    • 

  • Top level ≤ 7。
    • 

  • Drill down for detail。
    • 



2. Faceted：


    

  • Multiple dimension filtering。
    • 

  • 电商（price + brand + category）。
    • 



3. Linear：


    

  • Sequential（onboarding flow）。
    • 

  • Reduce decision。
    • 



4. Hub-and-spoke：


    

  • 中心 + spokes（home + tabs）。
    • 

  • 简单 navigation。
    • 



5. Tag-based：


    

  • 不强 hierarchy。
    • 

  • 多维 navigation。
    • 



好 IA：


    

  • 用户能快速找 info。
    • 

  • 不需 mental map 太复杂。
    • 



Card Sort + Tree Test 验证 IA
Card sort：


    

  • 给用户 cards（content）让分类。
    • 

  • 揭示用户 mental model。
    • 



Open card sort：用户自定义类。


Closed card sort：预定义类。


Tree test：


    

  • 给 navigation tree。
    • 

  • 让用户找 specific content。
    • 

  • 检测 IA 是否 work。
    • 



Simplicity vs Power
Trade-off：


    

  • 极简（如 iPhone）：低 cognitive load 但 functionality 受限。
    • 

  • 强大（如 Photoshop）：高 cognitive load 但 power user 满意。
    • 



Strategy：


    

  • Power user mode / advanced setting。
    • 

  • Sensible default for novice。
    • 

  • Progressive disclosure。
    • 



Onboarding
Onboarding 帮新用户 build mental model（germane load）：


1. Tooltip：


    

  • 第一次 hover/click 显示 hint。
    • 



2. Tutorial：


    

  • 引导 step-by-step。
    • 

  • 但 majority skip——注意 don't 强迫。
    • 



3. Empty state：


    

  • 第一次打开 app 显示 example / suggestion。
    • 

  • 教育 + 减少 friction。
    • 



4. Progressive onboarding：


    

  • 不 front-load。
    • 

  • 在 user encounter feature 时 introduce。
    • 



Accessibility 与 cognitive load
Cognitive disability（dyslexia、ADHD、autism）：


    

  • 标准 WCAG 2.2 mostly visual / motor focused。
    • 

  • Cognitive accessibility 仍 evolving。
    • 



实战：


    

  • 简单 language（avoid jargon）。
    • 

  • Consistent layout。
    • 

  • Clear error message + recovery。
    • 

  • Avoid timing constraint。
    • 

  • Reduce flashing / animation。
    • 



Anti-patterns
1. Wall of text：


    

  • 大段文字 dense。
    • 

  • 用户 skim、漏关键。
    • 

  • 修：分段、bullet、heading。
    • 



2. 过度选择：


    

  • 100 个 settings 一次显示。
    • 

  • 修：progressive disclosure。
    • 



3. Inconsistent：


    

  • 同 action 不同 UI。
    • 

  • 修：design system + 一致性。
    • 



4. Hidden state：


    

  • 不显示 system 当前状态。
    • 

  • 修：visible feedback。
    • 



5. Interruption：


    

  • Modal 突然出现 break flow。
    • 

  • 修：non-modal alert。
    • 



6. Dark pattern：


    

  • Misleading UI 让 user 做不愿事。
    • 

  • 修：transparent design。
    • 



实战 metric
Time on task：


    

  • 高 = 高 cognitive load 或 unclear UI。
    • 



Error rate：


    

  • 高 = unclear UI / high load。
    • 



Abandonment：


    

  • 离开未完成 = 受不了 cognitive load。
    • 



SUS（System Usability Scale）：


    

  • 10 question survey 量化 usability。
    • 



NASA-TLX：


    

  • Multidimensional 量化 cognitive load。
    • 



小结
Cognitive load 是 working memory 占用——Miller 7±2 chunk、Cowan 修正 ~ 4、保持 20s 不 rehearsal、distraction 清空。Sweller's CLT 三类 load——intrinsic（任务难度，不可降）、extraneous（UI 缺陷，设计师可降）、germane（学习投入，设计师 facilitate）。Recognition > recall（Nielsen #6）—— autocomplete、recent account、file picker。Progressive disclosure 把复杂分层 reveal（设置 advanced toggle、表单 more options）。Chunking 让 7±2 仍能 hold 多 info。Hick's Law T = a + b · log₂(N+1)——menu ≤ 7、grouping、smart default。减少 extraneous tactics——简化 visual + consistent + clear hierarchy + clear label + reduce decision + immediate feedback + group related。不同 context（mobile 极简、desktop dense OK、voice 少 options、AR/VR clear focal）。Information Architecture 5 patterns——hierarchy / faceted / linear / hub-spoke / tag。Card sort + tree test 验证 IA。Simplicity vs power trade-off——sensible default + progressive disclosure。Onboarding（tooltip / tutorial / empty state / progressive）帮 build mental model。Accessibility cognitive disability（dyslexia / ADHD / autism）—— 简单 language + consistent + clear error + avoid timing + reduce flash。Anti-patterns——wall of text、过度选择、inconsistent、hidden state、interruption、dark pattern。Metric——time on task、error rate、abandonment、SUS、NASA-TLX。一个简单的检验：你能识别一个 product 的 extraneous load？如果不能，CLT 三类区分还需巩固。Cognitive load 是 UX 的"重力"——所有设计 ultimately 服务于 reduce extraneous + facilitate germane，让用户 attention 集中在 task itself。
