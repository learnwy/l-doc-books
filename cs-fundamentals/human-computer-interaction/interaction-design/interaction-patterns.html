Part VI · 工程与交互 (Engineering & Interfaces)人机交互交互设计交互模式

交互模式

核心概念

交互模式是可复用的设计方案——对常见问题（如导航、选择、表单输入、反馈）的标准答案。它们让用户实现迁移学习（学一次用多处）、让设计师和工程师不重复发明轮子、让平台保持一致。本节覆盖六大类模式——导航（标签栏、汉堡菜单、面包屑）、选择（复选框、单选、下拉）、表单输入（文本、校验、提交）、反馈（轻提示、对话框、加载）、空状态、错误处理，以及暗黑模式反面教材。

类别 模式 用例
导航 标签栏、汉堡菜单、面包屑 应用主结构
选择 复选框、单选按钮、下拉菜单 单/多选
表单 文本输入、校验、向导 数据录入
反馈 轻提示、对话框、加载状态 系统状态
空状态 空列表、欢迎页 无内容
错误处理 行内提示、整页错误、恢复 异常处理

导航模式

标签栏（底部导航）：

  • 移动端主流。
  • 3-5 个主要分区。
  • 始终可见。
  • 例：Twitter、Instagram。

汉堡菜单：

  • 隐藏次要导航。
  • 解决小屏幕空间问题。
  • 但隐藏导致可发现性差。
  • 现代趋势：避免用于主导航。

顶部标签：

  • 子导航。
  • 在分区内切换。
  • 例：Twitter 关注/推荐。

面包屑：

  • 显示层级结构和路径。
  • 让用户回到父级。
  • 适合深层级结构。

返回按钮：

  • 移动端标准导航。
  • iOS 滑动返回手势。

抽屉（侧滑面板）：

  • 隐藏直到激活。
  • 适合次要导航。
选择模式
单选：


    

  • 单选按钮：从 N 项中选 1，所有选项可见。
    • 

  • 下拉菜单：从 N 项中选 1，默认显示已选项。
    • 

  • 分段控件：从 2-4 项中选 1，所有选项可见（移动端）。
    • 



多选：


    

  • 复选框：从 M 项中选 N 项。
    • 

  • 标签药丸：选中项显示为可见标签。
    • 

  • 多选下拉：节省空间。
    • 



开关：


    

  • 二元开/关。
    • 

  • 即时生效（对比复选框 + 提交按钮）。
    • 



实战规则：


    

  • 单选按钮用于 ≤ 5 个选项且需全部可见。
    • 

  • 下拉菜单用于 ≥ 6 个选项或文本较长。
    • 

  • 复选框用于多选场景。
    • 



表单模式
字段类型：


    

  • 文本输入：单行/多行。
    • 

  • 数字输入：带步进器。
    • 

  • 日期选择器：日历组件。
    • 

  • 组合框：文本输入 + 建议列表。
    • 



校验方式：


    

  • 行内实时校验：每次输入变化即校验（最佳体验）。
    • 

  • 失焦校验：焦点离开时校验。
    • 

  • 提交时校验：传统方式但摩擦大。
    • 



最佳实践：


    

  • 实时校验密码强度。
    • 

  • 失焦校验邮箱格式。
    • 

  • 提交时校验需服务端验证的内容（如用户名唯一性）。
    • 



错误消息：


    

  • 显示在字段下方（靠近错误处）。
    • 

  • 使用日常语言。
    • 

  • 建议修正方法。
    • 



提交：


    

  • 主按钮视觉突出。
    • 

  • 无效时禁用（或点击后显示错误）。
    • 

  • 提交过程中显示加载状态。
    • 



向导/多步表单：


    

  • 长表单分步骤。
    • 

  • 进度指示器。
    • 

  • 保存进度（避免意外丢失）。
    • 



反馈模式
轻提示（Toast / Snackbar）：


    

  • 屏幕底部短暂消息。
    • 

  • 自动消失（3-5 秒）。
    • 

  • 可选操作（如"撤销"）。
    • 

  • 适合确认消息。
    • 



对话框（Modal / Dialog）：


    

  • 阻断主界面。
    • 

  • 强制用户回应。
    • 

  • 谨慎使用（摩擦大）。
    • 

  • 适合关键确认（如删除账户）。
    • 



横幅提示（Banner / Alert）：


    

  • 顶部持续显示。
    • 

  • 不阻断操作。
    • 

  • 适合持续状态（如离线、警告）。
    • 



加载状态：


    

  • 旋转器：不确定时长。
    • 

  • 进度条：已知进度（显示百分比）。
    • 

  • 骨架屏：布局占位（推荐做法）。
    • 

  • 乐观更新：界面立即显示预期结果。
    • 



空状态：


    

  • 首次看到空列表。
    • 

  • 展示插画 + 说明 + 行动按钮（如"添加第一个项目"）。
    • 



确认反馈：


    

  • "邮件已发送 ✓"。
    • 

  • 轻提示通常足够。
    • 



加载模式选择
旋转器（< 1 秒任务）：


    

  • 简单指示器。
    • 

  • 但 < 1 秒实际可不显示（避免闪烁）。
    • 



进度条（已知时间）：


    

  • 上传、下载场景。
    • 

  • 让用户估算等待时间。
    • 



骨架屏（内容列表）：


    

  • 显示布局占位（灰色色块）。
    • 

  • 给予速度感知。
    • 

  • 现代网页应用主流做法。
    • 



乐观更新（用户操作）：


    

  • 立即反映用户操作结果。
    • 

  • 服务端失败时回滚。
    • 

  • 如点赞、评论。
    • 



避免：


    

  • 长时间旋转且无上下文提示。
    • 

  • 用户无法判断系统是否仍在工作。
    • 



空状态
目的：


    

  • 用户首次看到空页面时不困惑。
    • 

  • 引导用户采取行动。
    • 



组成要素：


    

  • 插画/图标：视觉吸引。
    • 

  • 标题：状态描述（如"暂无任务"）。
    • 

  • 副文本：解释说明。
    • 

  • 行动按钮：让用户执行操作（如"创建第一个任务"）。
    • 



变体：


    

  • 首次为空（引导时机）。
    • 

  • 筛选为空（"无结果"，建议修改筛选条件）。
    • 

  • 错误为空（"加载失败，重试"）。
    • 



错误处理模式
行内错误：


    

  • 表单字段校验错误。
    • 

  • 显示在字段下方或旁边。
    • 



整页错误：


    

  • 全页错误（网络、服务器问题）。
    • 

  • 展示发生了什么 + 重试按钮。
    • 



恢复：


    

  • "重试"按钮。
    • 

  • "联系客服"。
    • 

  • 保留用户输入（不丢失表单数据）。
    • 



语气：


    

  • 不责怪用户。
    • 

  • "出了点问题，请重试"而非"你做错了"。
    • 



严重程度：


    

  • 信息：蓝色。
    • 

  • 警告：黄色。
    • 

  • 错误：红色。
    • 

  • 成功：绿色。
    • 



常见模式陷阱
汉堡菜单做主导航：


    

  • 隐藏会降低参与度。
    • 

  • 标签栏直接可见效果更好。
    • 



轮播做主要内容：


    

  • 自动轮播让用户迷失位置。
    • 

  • 多数点击率极低。
    • 

  • 替代方案：网格 + 分页。
    • 



对话框陷阱：


    

  • 过多对话框让用户烦躁。
    • 

  • 尤其是营销弹窗。
    • 



无限滚动无分页：


    

  • 用户无法回到特定位置。
    • 

  • 适合社交信息流，不适合商品列表。
    • 



选项墙：


    

  • 过多下拉/设置选项。
    • 

  • 应使用渐进式披露。
    • 



暗黑模式（反面教材）
暗黑模式：设计故意误导用户。


1. 羞辱式确认：


    

  • "不了，我不想省钱"。
    • 

  • 让拒绝看起来愚蠢。
    • 



2. 蟑螂旅馆：


    

  • 注册简单，取消极难。
    • 

  • 例：某些订阅服务。
    • 



3. 隐私收割：


    

  • 默认隐私设置不保护用户。
    • 



4. 偷梁换柱：


    

  • 点击一个东西触发别的操作。
    • 



5. 伪装广告：


    

  • 广告看起来像正常内容。
    • 



6. 强制续费：


    

  • 试用结束自动扣费。
    • 



法律打击：


    

  • 欧盟《数字服务法》。
    • 

  • 加州《消费者隐私法案》。
    • 

  • 越来越多司法管辖区立法禁止。
    •

行业标准：


    

  • Apple HIG。
    •

    • 

  • Microsoft Fluent。
    • 

  • IBM Carbon。
    •

    • 

  • 设计令牌。
    •

  • 公司自建设计系统。
    • 

  • 减少产品团队的决策负担。
    • 



实战应用
案例：Spotify：


    

  • 底部标签栏导航（移动端）。
    • 

  • 搜索框顶部突出。
    • 

  • 正在播放持续栏（状态可见性）。
    • 

  • 骨架屏加载专辑列表。
    • 

  • 轻提示"已添加到播放列表"。
    • 



案例：Notion：


    

  • 侧栏导航（桌面端密集信息）。
    • 

  • 行内编辑（直接操纵）。
    • 

  • 斜杠命令（高级用户加速）。
    • 

  • 空状态带示例引导。
    • 



案例：Google 表单：


    

  • 向导式长表单。
    • 

  • 行内校验。
    • 

  • 自动保存指示器（状态可见性）。
    • 

  • 提交成功页。
    • 



跨平台差异
iOS 模式：


    

  • 底部标签栏。
    • 

  • 返回按钮在左上 + 滑动手势。
    • 

  • 底部弹出操作表。
    • 



Android 模式：


    

  • 底部导航或抽屉。
    • 

  • 系统级返回按钮。
    • 

  • 底部弹出面板。
    • 



Web 模式：


    

  • 顶部导航 + 侧栏。
    • 

  • 悬停状态。
    • 

  • 浏览器返回按钮。
    • 



跨平台应用：


    

  • 尊重平台惯例。
    • 

  • 不强制 iOS/Android 完全一致。
    • 



小结
交互模式是可复用的设计方案——让迁移学习容易、不重复发明、保持一致性。导航——标签栏（移动端主导航）、汉堡菜单（避免做主导航）、顶部标签（子导航）、面包屑（层级结构）、返回（移动端标准）、抽屉（次要导航）。选择——单选按钮（≤ 5 项可见）、下拉菜单（≥ 6 项或长文本）、复选框（多选）、分段控件（2-4 项）、开关（二元开关）。表单——文本/数字/日期/组合框输入、实时校验 vs 失焦校验 vs 提交校验、错误显示在字段下方、向导式长表单。反馈——轻提示（自动消失确认）、对话框（阻断关键确认）、横幅（持续提示）、加载变体（旋转器/进度条/骨架屏/乐观更新）。空状态——插画 + 标题 + 副文本 + 行动按钮。错误处理——行内/整页、恢复选项、保留用户输入、严重程度颜色（信息蓝/警告黄/错误红/成功绿）。常见陷阱——汉堡做主导航、轮播自动播放、对话框陷阱、无限滚动无分页、选项墙。暗黑模式（羞辱确认/蟑螂旅馆/隐私收割/偷梁换柱/伪装广告/强制续费）已受法律打击。模式库行业标准（Apple HIG、Material、Fluent、Carbon、Atlassian）+ 工具（Figma、Storybook）+ 内部设计系统。案例 Spotify/Notion/Google 表单展示综合应用。跨平台尊重平台惯例（iOS 标签栏、Android 抽屉、Web 顶部导航 + 侧栏）。一个简单的检验：你能在常用应用中识别出暗黑模式吗？如果不能，对模式与反模式的敏感度还需加强。交互模式是设计师的"词汇表"——熟练运用让设计既标准又高效。
