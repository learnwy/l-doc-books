启发式评估

核心概念

启发式评估（Nielsen & Molich 1990）是一种用户体验专家审查方法——3-5 名评估者使用 Nielsen 十大启发规则独立审查界面、寻找违规之处，然后汇总发现、评定严重程度、建议修复方案。它不能替代用户测试（用户行为不可预测），但快速、低成本、可发现约 75% 的问题（Nielsen）。本节给出启发式评估的流程、严重程度评级、与用户测试的对比、现代适应形式（认知走查、AI 辅助评估）以及实战案例研究。

方法 时间 成本 发现问题比例
启发式评估（5名评估者） 几天 低 约 75%
用户测试（5名用户） 1-2 周 中 约 80%
认知走查 几天 低 约 50-60%
眼动追踪实验室 数周 高 深度洞察
A/B 测试 数周 中 定量数据

流程

第一步：规划：

  • 选择评估者（3-5 人）——理想情况下是用户体验专家，但产品经理和开发者也能参与。
  • 确定任务场景。
  • 准备启发规则列表（Nielsen 十原则）。

第二步：独立评估：

  • 每位评估者独立审查界面。
  • 按任务场景逐步走查。
  • 记录违规：位置 + 对应规则 + 描述。
  • 每位评估者 1-2 小时。

第三步：汇总：

  • 合并所有发现。
  • 去除重复项。
  • 按频率和严重程度排列。

第四步：严重程度评级：

  • 0 - 无问题。
  • 1 - 外观问题（低优先级）。
  • 2 - 轻微问题（有一定影响）。
  • 3 - 严重问题（影响大）。
  • 4 - 灾难性问题（必须修复）。

第五步：报告：

  • 按严重程度排序列出违规。
  • 建议修复方案。
  • 分享给团队。

为什么需要 3-5 名评估者

Nielsen 1992 年研究：

  • 1 名评估者发现约 35% 的问题。
  • 3 名评估者发现约 60%。
  • 5 名评估者发现约 75%。
  • 超过 5 人收益递减。

最佳平衡点：3-5 名评估者性价比最高。

不同视角：

  • 多名评估者能发现不同问题（个人存在盲区）。
  • 多人一致发现的问题严重程度更高。
严重程度评级详解
0 - 无可用性问题：


    

  • 无需修复。
    • 



1 - 仅外观问题：


    

  • 不影响任务完成。
    • 

  • 例：轻微的视觉对齐偏差。
    • 

  • 有时间再修复。
    • 



2 - 轻微可用性问题：


    

  • 频率低或影响低。
    • 

  • 例：容易令人困惑的标签但用户最终能弄清。
    • 

  • 低优先级修复。
    • 



3 - 严重可用性问题：


    

  • 影响多数用户或高影响。
    • 

  • 例：用户找不到关键功能。
    • 

  • 必须修复。
    • 



4 - 灾难性问题：


    

  • 阻断任务完成。
    • 

  • 合规/法律风险。
    • 

  • 必须立即修复。
    • 



严重程度 = 频率 + 影响 + 持续性：


    

  • 频率：用户遇到的频繁程度。
    • 

  • 影响：克服难度多大。
    • 

  • 持续性：重复出现时多令人痛苦。
    • 



Nielsen 十大启发规则应用
1. 系统状态的可见性：


    

  • 加载状态可见？
    • 

  • 保存指示器？
    • 

  • 导航中的当前页位置？
    • 



2. 系统与现实世界的匹配：


    

  • 使用用户语言还是行话术语？
    • 

  • 是否运用熟悉隐喻（文件夹、垃圾桶）？
    • 



3. 用户控制与自由：


    

  • 有取消按钮？撤销功能？
    • 

  • 能轻松退出？
    • 



4. 一致性与标准：


    

  • 内部一致性（同一应用内）。
    • 

  • 外部一致性（平台惯例）。
    • 



5. 错误预防：


    

  • 危险操作有确认？
    • 

  • 校验阻止无效输入？
    • 



6. 识别而非回忆：


    

  • 展示选项而非要求记忆？
    • 

  • 自动补全、最近使用项？
    • 



7. 灵活性与使用效率：


    

  • 高级用户有快捷键？
    • 

  • 支持自定义？
    • 



8. 美观与极简设计：


    

  • 有无必要的视觉杂乱？
    • 

  • 留白是否恰当？
    • 



9. 错误恢复：


    

  • 错误消息使用日常语言？
    • 

  • 建议修复方案？
    • 



10. 帮助与文档：


    

  • 帮助文档可搜索？
    • 

  • 有上下文提示？
    • 



实战案例：Slack 消息界面
任务：用户在会话线程中回复消息。


评估者发现：


问题 1：回复按钮隐藏在鼠标悬停区域（桌面端）。


    

  • 对应规则：可见性、识别而非回忆。
    • 

  • 严重程度 3（严重）：首次用户难以发现。
    • 

  • 修复建议：始终显示行内按钮。
    • 



问题 2：移动端回复和表情回应使用相同的滑动手势。


    

  • 对应规则：一致性、错误预防。
    • 

  • 严重程度 2（轻微）：用户偶尔误触表情回应当想回复。
    • 

  • 修复建议：使用不同手势或按钮。
    • 



问题 3：会话线程侧栏推挤主消息列。


    

  • 对应规则：美观、用户控制。
    • 

  • 严重程度 3：打断阅读流程。
    • 

  • 修复建议：使用浮层覆盖代替推挤。
    • 



汇总报告：


    

  • 共发现 23 个问题。
    • 

  • 3 个灾难性、8 个严重、9 个轻微、3 个外观。
    • 



启发式评估的局限
1. 依赖专家：


    

  • 评估者须具备用户体验专业知识。
    • 

  • 新手会遗漏细微问题。
    • 



2. 偏见：


    

  • 评估者过往经验有影响。
    • 

  • 多名评估者可缓解。
    • 



3. 无法预测用户特有行为：


    

  • 不能预测真实用户行为。
    • 

  • 用户测试是必要补充。
    • 



4. 静态评估：


    

  • 无法捕捉上下文（多任务、长时间使用）。
    • 



5. 严重程度评级主观：


    

  • 不同评估者评级不同。
    • 

  • 需要校准。
    • 



与用户测试的对比
启发式评估：


    

  • 快速且便宜。
    • 

  • 发现约 75% 问题。
    • 

  • 专家驱动。
    • 

  • 最适合早期原型。
    • 



用户测试：


    

  • 较慢且较贵。
    • 

  • 发现约 80% 问题。
    • 

  • 用户驱动。
    • 

  • 最适合验证阶段。
    • 



最佳实践：


    

  • 两者结合使用。
    • 

  • 启发式评估先行，捕获明显问题。
    • 

  • 用户测试随后，捕获细微问题。
    • 



认知走查
替代方法：


    

  • 关注首次用户。
    • 

  • 按照特定任务逐步走查。
    • 

  • 对每一步提问：
      

    • "用户知道这个操作存在吗？"
      • 

    • "用户知道该用哪个控件吗？"
      • 

    • "用户能将操作与目标关联吗？"
      • 

    • "用户能看到进展吗？"
      • 

    

    • 



适合场景：


    

  • 新手引导流程。
    • 

  • 特定功能。
    • 

  • 不需要专家评估者。
    • 



现代适应形式
1. AI 辅助评估：


    

  • 基于大语言模型的用户体验评审。
    • 

  • 自动发现常见问题。
    • 

  • 但缺乏上下文判断力。
    • 



2. 包容性启发评估：


    

  • 增加无障碍相关启发规则。
    • 

  • WCAG 检查 + 通用用户体验。
    • 



3. 移动端专项：


    

  • 增加移动端特有规则（拇指热区、屏幕方向）。
    • 



4. 语音/AR/VR 专项：


    

  • 语音界面无法"可见"。
    • 

  • VR 有不同的认知负荷。
    • 



工具
Figma 插件：


    

  • Stark：无障碍启发检查。
    • 

  • WAVE：WCAG 评估。
    • 



浏览器扩展：


    

  • axe DevTools：无障碍评估。
    • 

  • Lighthouse：性能 + 无障碍 + SEO。
    • 



启发式评估追踪：


    

  • 电子表格（NN/g 提供模板）。
    • 

  • 问题追踪工具（Jira、Linear）。
    • 



何时跳过启发式评估
1. 早期头脑风暴阶段：


    

  • 概念还不稳定。
    • 

  • 先测试想法本身。
    • 



2. 定量问题：


    

  • "用户多常点击某功能？" → 用分析工具而非启发式评估。
    • 



3. 已有用户测试数据：


    

  • 用户数据比专家推断更准确。
    • 



但仍可快速做 15 分钟启发检查以捕获明显问题。


实战建议
1. 充分告知评估者：


    

  • 提供任务场景。
    • 

  • 启发规则列表。
    • 

  • 限定时间（避免过度思考）。
    • 



2. 使用多名评估者：


    

  • 至少 3 人，理想 5 人。
    • 

  • 不同背景（产品经理、开发者、设计师、用户）。
    • 



3. 仔细汇总：


    

  • 关注频繁出现的问题（多名评估者都发现）。
    • 

  • 去除重复项。
    • 



4. 统一严重程度评级：


    

  • 校准团队评级标准。
    • 

  • 使用示例案例。
    • 



5. 以行动为导向：


    

  • 不仅列出问题。
    • 

  • 提出修复方案。
    • 

  • 排列优先级。
    • 



启发式评估融入冲刺
冲刺规划：


    

  • 每个冲刺对关键流程做启发式评估。
    • 

  • 将主要问题纳入待办事项。
    • 



上线前：


    

  • 发布前做最终启发式评估。
    • 

  • 捕获最后时刻的问题。
    • 



上线后：


    

  • 结合分析数据和用户反馈。
    • 

  • 持续改进。
    • 



与其他方法配合
启发式评估 + 用户测试：


    

  • 启发式评估先行（快速且低成本）。
    • 

  • 修复明显问题。
    • 

  • 用户测试验证并发现细微问题。
    • 



启发式评估 + 数据分析：


    

  • 评估推断问题所在。
    • 

  • 分析数据验证假设（流失是否发生在问题处？）。
    • 



启发式评估 + 无障碍审计：


    

  • 一轮同时完成两者。
    • 

  • 时间效率高。
    • 



小结
启发式评估（Nielsen & Molich 1990）是用户体验专家审查方法——3-5 名评估者用 Nielsen 十大启发规则找违规，汇总 + 评级严重程度 + 建议修复。流程——规划 + 独立评估 + 汇总 + 严重程度 + 报告。3-5 名评估者是最佳平衡点（1 人发现 35%、3 人 60%、5 人 75%、超过 5 人收益递减），不同视角发现各自盲区。严重程度评级 0-4（外观/轻微/严重/灾难性），= 频率 + 影响 + 持续性。Nielsen 十原则各覆盖一类问题（可见性/与现实匹配/用户控制/一致性/错误预防/识别优于回忆/灵活性/美观/错误恢复/帮助文档）。Slack 案例展示综合应用。局限——依赖专家、偏见、无法预测用户行为、静态评估、严重程度主观。与用户测试对比——启发式快便宜 75%，用户测试慢贵 80%，最佳实践两者结合。认知走查是面向首次用户的替代方法。现代适应——AI 辅助（大语言模型评审）、包容性（加无障碍规则）、移动端专项、语音/AR/VR 专项。工具——Figma 插件（Stark、WAVE）、浏览器扩展（axe、Lighthouse）、追踪（电子表格、Jira）。适合跳过的场景——早期概念、定量问题、已有用户数据，但快速检查仍有帮助。建议——充分告知 + 多名评估者 + 仔细汇总 + 统一评级 + 以行动为导向。融入冲刺——每个冲刺关键流程评估 + 上线前最终检查 + 上线后结合数据。配合其他方法——用户测试、数据分析、无障碍审计。一个简单的检验：你能在 30 分钟内用 Nielsen 十原则在常用应用中找出 5 个问题吗？如果不能，启发式评估还需要练习。启发式评估是用户体验工程师的"第一道防线"——快速、低成本、高回报，让明显问题在用户测试之前被捕获。
