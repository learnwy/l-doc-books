Part VI · 工程与交互 (Engineering & Interfaces)人机交互可用性与用户研究可用性测试

可用性测试

核心概念

可用性测试是用户体验研究中最基础的方法——观察真实用户使用产品完成任务，寻找问题。Jakob Nielsen 1993 年的经典发现——5 名用户可找到约 80% 的问题——让可用性测试具有极高的性价比。本节给出可用性测试的完整步骤——招募、方案设计、主持、观察、分析、报告，以及有主持 vs 无主持、远程 vs 现场的权衡。

维度 有主持测试 无主持测试
成本 高 低
速度 慢 快
深度 高 中
探索性 强 弱
工具 Zoom + 屏幕 UserTesting、Maze
适合场景 复杂流程 快速验证

为什么 5 名用户

Nielsen 1993 年研究：

  • 1 名用户发现约 31%。
  • 3 名用户约 65%。
  • 5 名用户约 80%。
  • 超过 5 人收益递减。

数学原理：

  • 单用户发现概率 p ≈ 0.31。
  • N 名用户至少一人发现：1 - (1-p)^N。
  • N=5 → 1 - 0.69^5 ≈ 84%。

权衡：

  • 5 人一轮 vs 15 人一轮。
  • 前者加 3 轮（修复后再测）可发现更多问题。
  • 多轮测试优于大样本。

规划

1. 定义目标：

  • "验证新手引导流程是否清晰"。
  • 避免"泛泛的可用性测试"。

2. 定义任务场景：

  • 真实且具体。
  • 例："尝试注册新账户并添加第一个项目"。
  • 不要："测试注册功能"。

3. 招募：

  • 目标用户画像。
  • 筛选器筛选符合标准的用户。
  • 每轮 5-8 人（预留缺席缓冲）。

4. 试运行：

  • 内部做一次试跑检测方案问题。
  • 正式测试前优化。
招募
用户来源：


    

  • 内部用户池（营销列表）。
    • 

  • 招募平台（User Interviews、Respondent.io）。
    • 

  • 社交媒体。
    • 

  • 现有用户群（注意：偏向高级用户）。
    • 



筛选问题：


    

  • 筛选符合目标用户画像的人。
    • 

  • 例：电商测试 → "每月至少网购一次"。
    • 

  • 排除行业内部人员（有偏见）。
    • 



报酬：


    

  • 每场 50-150 美元（美国标准）。
    • 

  • 重要——不是无偿劳动。
    • 



缺席缓冲：


    

  • 多安排 1 人（约 20% 缺席率）。
    • 



测试方案
有主持（远程/现场）：


    

  • 5-15 分钟介绍 + 热身。
    • 

  • 30-45 分钟任务场景。
    • 

  • 5-10 分钟总结访谈。
    • 

  • 总计约 1 小时。
    • 



无主持：


    

  • 预录指引。
    • 

  • 用户自行操作。
    • 

  • 工具录制屏幕 + 语音。
    • 

  • 通常 15-30 分钟。
    • 



任务设计：


    

  • 3-5 个主要任务。
    • 

  • 真实顺序（匹配用户实际流程）。
    • 

  • 开放式场景——不告诉"怎么做"。
    • 



出声思维
方法：


    

  • 要求用户"持续描述你在想什么"。
    • 

  • 呈现用户心智模型。
    • 

  • 在用户自行解决之前捕获困惑。
    • 



变体：


    

  • 同步出声思维（CTA）：边做边说。
    • 

  • 回溯出声思维（RTA）：事后看录像回顾。
    • 



同步出声的优点：


    

  • 实时洞察。
    • 

  • 成本低。
    • 



同步出声的缺点：


    

  • 降低用户操作速度。
    • 

  • 改变自然行为。
    • 



回溯的优点：


    

  • 保留自然行为。
    • 



回溯的缺点：


    

  • 记忆偏差。
    • 

  • 事后合理化。
    • 



主持技巧
技能：


    

  • 主动倾听。
    • 

  • 中性语言。
    • 

  • 不引导用户。
    • 



差的提问：


    

  • "你觉得这里困惑吗？"（引导性）。
    • 

  • "你喜欢这个设计的什么？"（引导性）。
    • 



好的提问：


    

  • "告诉我你现在在想什么。"
    • 

  • "你期望会发生什么？"
    • 

  • "带我走一遍你刚才做了什么。"
    • 



追问：


    

  • 不要立即插话。
    • 

  • 用户停顿后等 5-10 秒。
    • 

  • 让用户自己呈现洞察。
    • 



禁忌：


    

  • 为产品辩护（"其实这样设计是因为……"）。
    • 

  • 帮助用户完成任务（除非完全卡住）。
    • 

  • 表达个人意见。
    • 



观察
不只是录屏：


    

  • 任务是否完成？
    • 

  • 所用时间。
    • 

  • 错误/犹豫。
    • 

  • 用户原话。
    • 

  • 情绪反应（沮丧、微笑）。
    • 



多名观察者：


    

  • 同一场次 1-2 名观察者。
    • 

  • 不同角度。
    • 

  • 事后对比笔记。
    • 



录制：


    

  • 始终录制（获得许可）。
    • 

  • 回看发现遗漏的洞察。
    • 

  • 作为精选视频的素材。
    • 



分析
1. 亲和图：


    

  • 每个问题写在便签上。
    • 

  • 按主题/相似性分组。
    • 

  • 按频率和严重程度排列。
    • 



2. 严重程度评级：


    

  • 与启发式评估相同的 0-4 分制。
    • 

  • 多名评估者达成共识。
    • 



3. 模式识别：


    

  • 某问题影响多名用户 → 高优先级。
    • 

  • 仅单一用户遇到 → 可能是个人特殊情况。
    • 



4. 根因分析：


    

  • 不只列出症状。
    • 

  • 用户为什么卡住？
    • 

  • 例：用户点错按钮 → 因为按钮标签令人困惑 → 根因 = 标签问题。
    • 



报告
面向利益相关者的报告：


    

  • 执行摘要（前 5 个问题）。
    • 

  • 严重程度评级。
    • 

  • 改进建议。
    • 

  • 视频片段（用户实际挣扎的画面）。
    • 

  • 不超过 5 页。
    • 



面向团队的报告：


    

  • 详细问题列表。
    • 

  • 根因分析。
    • 

  • 优先级排列。
    • 

  • 关联到问题追踪系统。
    • 



精选视频：


    

  • 5-10 分钟视频。
    • 

  • 向利益相关者展示真实用户的痛苦。
    • 

  • 最有说服力的交付物。
    • 



远程 vs 现场
远程有主持（Zoom + 屏幕共享）：


    

  • 疫情后成为主流。
    • 

  • 节省差旅，更大用户池。
    • 

  • 质量通常可以。
    • 



现场：


    

  • 适合移动端原型。
    • 

  • 更容易读取肢体语言。
    • 

  • 硬件相关（AR/VR、穿戴设备）。
    • 



实验室：


    

  • 眼动追踪 + 生理指标。
    • 

  • 设备成本高。
    • 

  • 适用于特定研究问题。
    • 



工具
有主持：


    

  • Zoom、Google Meet。
    • 

  • Lookback（专门用户研究工具）。
    • 

  • Otter.ai（自动转录）。
    • 



无主持：


    

  • UserTesting.com（招募 + 工具）。
    • 

  • Maze（设计 + 测试）。
    • 

  • UserZoom。
    • 



记录整理：


    

  • Dovetail（研究知识库）。
    • 

  • Reduct（视频分析）。
    • 

  • 电子表格（简单场景）。
    • 



招募：


    

  • User Interviews。
    • 

  • Respondent.io。
    • 

  • Userlytics。
    • 



特殊场景
移动应用测试：


    

  • 用真机（非模拟器）。
    • 

  • 用户保持自然姿势。
    • 

  • 摄像头同时捕获手机屏幕和面部。
    • 



语音/VR 测试：


    

  • 实验室设置最理想。
    • 

  • 录制音频 + 屏幕 + 肢体。
    • 



无障碍测试：


    

  • 招募残障用户。
    • 

  • 使用他们自己的辅助技术（屏幕阅读器、开关控制）。
    • 

  • 不要模拟（不具代表性）。
    • 



反模式
1. 仅用团队成员测试：


    

  • 有偏见（已了解产品）。
    • 

  • 用新鲜用户。
    • 



2. 引导用户：


    

  • "你觉得这里困惑吗？"
    • 

  • 让用户认同你的预期。
    • 



3. 卡住时帮助：


    

  • 帮助会违背目的（寻找问题）。
    • 

  • 让用户自行挣扎（在合理范围内）。
    • 



4. 防御性解读：


    

  • "用户只是不懂我们优秀的设计"。
    • 

  • 用户才是事实来源。
    • 



5. 只做一轮：


    

  • 测完一次就发布。
    • 

  • 应该修复 → 再测 → 迭代。
    • 



6. 定量执念：


    

  • "多少用户完成了任务X？"
    • 

  • N=5 无法做定量声明。
    • 

  • 应关注定性洞察。
    • 



偏差来源
1. 招募偏差：


    

  • 现有用户 → 倾向正面评价。
    • 

  • 给高额报酬 → 过于配合。
    • 



2. 霍桑效应：


    

  • 被观察会改变行为。
    • 

  • 缓解：让用户放松，"没有对错"。
    • 



3. 主持人偏差：


    

  • 通过语气或措辞引导。
    • 

  • 缓解：标准化方案。
    • 



4. 确认偏差：


    

  • 寻找支持假设的证据。
    • 

  • 缓解：保持开放心态，多名观察者。
    • 



5. 自我报告不可靠：


    

  • "你觉得容易吗？" → 用户礼貌性回答是。
    • 

  • 行为比自我报告更重要。
    • 



实战案例
案例：新手引导流程测试：


设置：


    

  • 5 名新用户。
    • 

  • 任务：注册 + 完成第一个操作。
    • 

  • 远程有主持，30 分钟。
    • 



发现：


    

  • 5/5 用户在第 3 步（验证）困惑。
    • 

  • 3/5 在第 4 步（同意条款）放弃。
    • 

  • 原话："我不明白这是什么意思"。
    • 



分析：


    

  • 第 3 步灾难性（5/5 受影响）。
    • 

  • 第 4 步严重（高放弃率）。
    • 



行动：


    

  • 重新设计第 3 步并添加清晰说明。
    • 

  • 简化第 4 步同意条款。
    • 

  • 下个冲刺重新测试。
    • 



持续研究
研究运营：


    

  • 专门团队负责研究基础设施。
    • 

  • 招募流水线。
    • 

  • 工具许可证。
    • 

  • 知识库。
    • 



持续发现：


    

  • Teresa Torres 方法。
    • 

  • 每周客户访谈。
    • 

  • 把研究融入日常。
    • 



原子化研究：


    

  • 每条发现是原子笔记。
    • 

  • 组合复用于多个项目。
    • 



投资回报
可用性测试投入：


    

  • 每轮 5 名用户：约 1500-3000 美元（招募 + 主持人）。
    • 



节省：


    

  • 避免构建错误功能。
    • 

  • 减少上线后修复成本。
    • 

  • 提升转化率。
    • 



投资回报通常 10-100 倍——研究是回报最高的设计活动。


小结
可用性测试是用户体验研究最基础的方法——观察真实用户使用产品完成任务。Nielsen 1993——5 名用户发现约 80% 问题，多轮测试优于大样本。规划——定义目标 + 定义任务 + 招募 + 试运行。招募来源（内部池/平台/社交媒体）+ 筛选器 + 报酬 50-150 美元 + 缺席缓冲。方案：有主持 1 小时（介绍 + 任务 + 总结）vs 无主持 15-30 分钟。任务 3-5 个真实的开放式场景。出声思维——同步实时但降速，回溯自然但有记忆偏差。主持技巧——主动倾听 + 中性语言 + 不引导 + 等待追问。观察——多名观察者 + 始终录制。分析——亲和图 + 严重程度 0-4 + 模式识别 + 根因分析。报告——执行摘要 + 团队报告 + 精选视频。远程（Zoom 主流）vs 现场（移动端/AR/VR/实验室）权衡。工具——Zoom/Lookback（有主持）、UserTesting/Maze（无主持）、Dovetail（分析）、User Interviews（招募）。特殊场景——移动真机、语音/VR 实验室、无障碍招募残障用户。反模式——仅用团队测试、引导用户、帮助卡住用户、防御性解读、只做一轮、对 N=5 做定量声明。偏差来源——招募/霍桑/主持人/确认/自我报告。新手引导案例展示完整流程。持续研究/研究运营/原子化研究是现代实践。投资回报通常 10-100 倍，研究是最高回报的设计活动。一个简单的检验：你能在一周内规划并执行 5 人可用性测试吗？如果不能，流程还需练习。可用性测试是用户体验工程师的"基本功"——让设计假设在接触现实中被验证。
