Part VI · 工程与交互 (Engineering & Interfaces)人机交互可用性与用户研究UX 研究方法

UX 研究方法

核心概念

用户体验研究不只是可用性测试——还包含生成式研究（探索用户需求、发现机会）、评价式研究（验证设计）、定量（度量）与定性（理解）的混合方法。本节介绍六类核心方法——访谈、问卷、田野观察、日记研究、卡片分类、树状测试，以及方法选择框架（取决于问题和阶段）。Erika Hall《恰到好处的研究》与 Steve Portigal《用户访谈》是经典参考。

方法 类型 阶段 发现
访谈 定性 生成式 需求、动机
问卷 定量 两者 规模化验证
田野观察 定性 生成式 真实场景
日记研究 定性 生成式 长期行为
卡片分类 混合 信息架构 心智模型
树状测试 定量 信息架构验证 可查找性
可用性测试 定性 评价式 界面问题
A/B 测试 定量 评价式 优化方向
数据分析 定量 全程 行为数据

生成式 vs 评价式

生成式研究：

  • "该解决什么问题？"
  • 发现阶段。
  • 开放式探索。
  • 方法：访谈、田野观察、日记研究。

评价式研究：

  • "设计是否有效？"
  • 验证阶段。
  • 聚焦特定问题。
  • 方法：可用性测试、A/B 测试、问卷。

混合型：

  • 卡片分类（生成式 + 评价式）。
  • 问卷（取决于问题类型）。

用户访谈

目的：

  • 深入理解用户。
  • 动机、痛点、目标、使用场景。

类型：

  • 结构化：固定问题。
  • 半结构化：核心问题 + 追问。
  • 非结构化：自由对话。

多数用户体验研究使用半结构化访谈。

最佳实践：

  • 开放式问题："跟我讲讲……"、"你通常怎么……"。
  • 不问是否题。
  • 不问引导性问题。
  • 5 秒沉默法则（让用户展开）。
  • 追问细节："多说一点"、"能举个例子吗？"。

差的提问：

  • "你会使用类似某功能吗？"（假设性问题，通常不准确）。
  • "你喜欢这个吗？"（引导性）。

样本量：

  • 每个细分群体 5-8 人。
  • 多群体累加。
  • 达到饱和（不再有新洞察）= 停止。

问卷调查

定量方法：

  • 大样本。
  • 可做统计声明。
  • 比较不同群体。

适用场景：

  • 验证访谈中的假设。
  • 度量态度变化。
  • 理解用户分群。

问题类型：

  • 李克特量表（1-5）：满意度、认同度。
  • 单选题：选择一个。
  • 多选题：选择多个。
  • 开放文本：少用（难分析）。
  • NPS：0-10 推荐意愿。

陷阱：

  • 过长（疲劳导致放弃）。
  • 引导性问题。
  • 一题问两事。
  • 量表不均衡。

样本量：

  • 统计功效计算。
  • 通常 200+ 人才可做可靠声明。

工具：

  • Typeform、SurveyMonkey、Google 表单。
  • Qualtrics（企业级）。

田野观察

在自然环境中观察用户：

  • 家中、工作场所、零售店。
  • 几小时到几天。
  • "一日生活"研究。

适合场景：

  • 理解使用场景（用户在哪里实际使用产品？）。
  • 发现未被满足的需求（用户自己说不出来）。

方法：

  • 跟随用户。
  • 记录环境细节。
  • 不干预（自然观察）。
  • 偶尔询问澄清。

产出：

  • 照片/视频。
  • 现场笔记。
  • 关于场景的洞察。

成本：

  • 高（时间密集）。
  • 但独特洞察难以替代。

日记研究

纵向方法：

  • 用户在一段时间内自行报告（天到周）。
  • 每日记录体验。

适合场景：

  • 长期行为（运动、饮食类应用）。
  • 低频事件（月度账单、旅行）。
  • 时间敏感场景（通勤）。

方法：

  • 给用户工具（应用、日记本、短信）。
  • 定期提醒。
  • 汇总分析。

工具：

  • dscout、Indeemo（日记研究平台）。
  • WhatsApp/短信（低技术方案）。

报酬：

  • 200-500 美元（多日研究）。

卡片分类

目的：

  • 理解用户心智模型。
  • 为信息架构提供依据。

类型：

开放式卡片分类：

  • 用户将卡片分到自定义类别中。
  • 揭示心智模型。

封闭式卡片分类：

  • 预定义类别。
  • 用户将卡片分配到类别。
  • 测试信息架构是否匹配。

混合式：

  • 部分预定义 + 允许用户添加新类别。

产出：

  • 分组相似度矩阵。
  • 聚类分析。
  • 重命名建议（用户术语）。

工具：

  • OptimalSort。
  • UserZoom。
  • 实体卡片（现场）。

树状测试

目的：

  • 验证信息架构。
  • 测试用户查找特定内容的容易程度。

方法：

  • 给用户导航树（仅标签，无设计）。
  • 任务："找到修改密码的位置"。
  • 测量成功率和路径。

指标：

  • 任务成功率。
  • 直达率（直接到达目标不返回）。
  • 用时。

工具：

  • Treejack（OptimalSort）。
  • UserZoom。

常见工作流：

  • 卡片分类 → 提出信息架构方案 → 树状测试 → 优化 → 实现。
A/B 测试
定量评价方法：


    

  • 部署 A 版本 vs B 版本。
    • 

  • 度量指标。
    • 

  • 选择胜出版本。
    • 



统计要求：


    

  • 统计显著性（通常 p < 0.05）。
    • 

  • 效果量。
    • 

  • 基于流量计算样本量。
    • 



适合场景：


    

  • 单一变量变化。
    • 

  • 可量化指标。
    • 

  • 有流量。
    • 



不适合场景：


    

  • 概念性变化（变动太大产生混淆）。
    • 

  • 长期效果。
    • 

  • 小流量（统计功效不足）。
    • 



工具：


    

  • Optimizely、VWO。
    • 

  • LaunchDarkly（特性开关）。
    • 

  • 自建系统（大公司）。
    • 



数据分析
定量行为数据：


    

  • 用户流程。
    • 

  • 流失点。
    • 

  • 功能使用率。
    • 

  • 转化率。
    • 



工具：


    

  • Google Analytics、Adobe Analytics。
    • 

  • Mixpanel、Amplitude（产品分析）。
    • 

  • PostHog（开源）。
    • 

  • Hotjar（热力图 + 录屏）。
    • 



适合场景：


    

  • "发生了什么？"
    • 

  • 发现流失点。
    • 

  • 量化问题严重程度。
    • 



不适合场景：


    

  • "为什么？" → 需要定性方法。
    • 

  • 因果声明（相关性 ≠ 因果性）。
    • 



方法选择框架
问题决定方法：


    

  • "用户为什么卡住？" → 访谈/可用性测试。
    • 

  • "多少用户卡住？" → 数据分析。
    • 

  • "内容放在哪里？" → 树状测试/卡片分类。
    • 

  • "设计是否有效？" → 可用性测试/A/B 测试。
    • 

  • "用户需要什么？" → 访谈/田野观察。
    • 



阶段决定方法：


    

  • 发现 → 访谈、田野观察、问卷。
    • 

  • 设计 → 卡片分类、原型测试。
    • 

  • 验证 → 可用性测试、A/B 测试。
    • 

  • 生产 → 数据分析、问卷。
    • 



资源决定方法：


    

  • 快速且低成本 → 无主持测试、问卷。
    • 

  • 深度洞察 → 访谈、田野观察。
    • 



混合方法
最佳实践：


    

  • 结合定性和定量。
    • 

  • 定量给出"是什么/有多少"。
    • 

  • 定性给出"为什么"。
    • 



示例：


    

  • 分析数据显示第 3 步流失。
    • 

  • 访谈揭示用户对同意条款困惑。
    • 

  • 现在你既知道修复什么，也知道为什么。
    • 



三角验证：


    

  • 多种方法确认同一发现。
    • 

  • 单一方法偏差得到缓解。
    • 



研究知识库
原子化研究：


    

  • 每条洞察是原子笔记。
    • 

  • 加标签、可搜索。
    • 

  • 跨项目复用。
    • 



工具：


    

  • Dovetail。
    • 

  • Notion/Confluence（自建）。
    • 

  • EnjoyHQ。
    • 



好处：


    

  • 避免重复研究。
    • 

  • 新成员更快上手。
    • 

  • 展示研究价值。
    • 



研究运营
研究运营团队：


    

  • 招募流水线。
    • 

  • 工具许可证。
    • 

  • 流程标准化。
    • 

  • 知识库。
    • 



为什么需要：


    

  • 让研究者专注于研究本身，而非后勤。
    • 

  • 规模化研究能力。
    • 



伦理
知情同意：


    

  • 用户知情并同意。
    • 

  • 可随时退出。
    • 

  • 录制需获许可。
    • 



隐私：


    

  • 数据匿名化。
    • 

  • 安全存储。
    • 

  • 符合 GDPR/CCPA 合规。
    • 



报酬公平：


    

  • 支付合理报酬。
    • 

  • 不偏向"免费"用户。
    • 



不欺骗：


    

  • 不误导用户关于研究目的。
    • 



现代挑战
1. AI/大语言模型应用于研究：


    

  • 大语言模型自动摘要访谈记录。
    • 

  • AI 生成洞察存在幻觉风险。
    • 

  • 仍需研究者判断。
    • 



2. 远程优先：


    

  • 疫情后远程成为主流。
    • 

  • 但田野观察受限。
    • 



3. 隐私法规：


    

  • GDPR、CCPA、APPI 等。
    • 

  • 招募和数据处理须合规。
    • 



4. 规模化：


    

  • 持续发现。
    • 

  • 研究速度跟上产品节奏。
    • 



投资回报
研究投入：


    

  • 单次研究：5千至5万美元取决于方法。
    • 

  • 研究运营团队：每年 20万至100万美元。
    • 



回报：


    

  • 避免构建错误功能。
    • 

  • 提升产品-市场契合度。
    • 

  • 减少上线后修复成本。
    • 



最佳实践：


    

  • 将研究嵌入产品周期。
    • 

  • 不做一次性研究。
    • 



小结
用户体验研究不只是可用性测试——生成式（发现阶段，访谈/田野观察/日记研究）+ 评价式（验证阶段，可用性测试/A/B 测试）+ 定性（理解）+ 定量（度量）混合使用。用户访谈以半结构化为主流，开放式问题 + 5 秒沉默 + 追问，每群体 5-8 人直到饱和。问卷用于定量规模化验证，李克特/单选/开放文本，陷阱包括过长/引导/一题两问，需 200+ 人做可靠声明。田野观察在自然环境中观察（家/工作场所），跟随 + 现场笔记。日记研究是纵向多日自行报告，适合长期/低频场景。卡片分类（开放/封闭/混合）用于信息架构心智模型生成。树状测试验证信息架构的可查找性，指标为成功率/直达率/用时，工作流为卡片分类 → 提出方案 → 树状测试 → 优化。A/B 测试是单变量定量验证，需要统计显著性和样本量。数据分析（GA/Mixpanel/Amplitude/PostHog/Hotjar）量化行为但无法回答"为什么"。方法选择——问题/阶段/资源决定。混合方法三角验证关键——定量给出"什么" + 定性给出"为什么"。研究知识库（Dovetail）原子化研究实现复用。研究运营实现规模化。伦理——知情同意 + 隐私 + 公平报酬 + 不欺骗。现代挑战——AI 摘要/幻觉/远程优先/隐私法规/规模化。投资回报高——将研究嵌入产品周期。一个简单的检验：你能为特定问题选对研究方法吗？如果不能，方法与问题的匹配还需练习。用户体验研究是设计质量的根源——好设计来自好的用户理解，好的用户理解来自好的研究。
