Part VI · 工程与交互 (Engineering & Interfaces)人机交互可用性与用户研究度量与分析

度量与分析

核心概念

用户体验度量让设计量化——从轶事走向数据驱动。Google HEART 框架（幸福感、参与度、采纳率、留存率、任务成功率）是行业标准的产品体验度量方案。SUS（系统可用性量表）让可用性量化（10 道问卷给出 0-100 分）。NPS 测量满意度与忠诚度。行为分析工具（PostHog、Mixpanel、Amplitude）让用户实际行为可见——漏斗、群组、留存曲线。本节介绍核心度量框架、工具，以及反度量模式（如暗黑模式优化短期指标损害长期价值）。

度量指标 类型 目的
SUS 问卷 整体可用性
NPS 问卷 满意度
HEART 综合 产品体验全局
漏斗 行为 转化流失
留存曲线 行为 长期价值
任务用时 行为 效率
错误率 行为 有效性

SUS（系统可用性量表）

John Brooke 1986：

  • 10 道李克特量表题（1-5）。
  • 得分范围 0-100。
  • 高于 68 = 超过平均。
  • 高于 80 = 优秀。

10 道问题（正负交替）：

  1. 我认为我会经常使用这个系统。
  2. 我觉得这个系统不必要地复杂。
  3. 我觉得这个系统容易使用。
  4. 我觉得需要技术人员帮助才能使用。
  5. 我觉得系统中各功能整合得很好。
  6. 我觉得系统内有太多不一致的地方。
  7. 我觉得大多数人能很快学会使用。
  8. 我觉得这个系统用起来很笨重。
  9. 我使用时感觉很自信。
  10. 我需要学很多东西才能上手。

计算方式：

  • 奇数题：答案减 1。
  • 偶数题：5 减答案。
  • 总和 × 2.5 = SUS 分数。

适用：

  • 任何产品。
  • 可跨产品比较。
  • 基线评估 + 重设计后对比。

NPS（净推荐值）

Frederick Reichheld 2003：

  • 1 道题："你有多大可能推荐？0-10"。
  • 9-10 为推荐者。
  • 7-8 为被动者。
  • 0-6 为贬损者。
  • NPS = 推荐者百分比 - 贬损者百分比。
  • 范围 -100 到 100。

基准：

  • 高于 50 为优秀。
  • 0-30 为平均。
  • 低于 0 有问题。

优点：

  • 简单。
  • 行业标准。
  • 有长期历史数据。

缺点：

  • 单一问题不够细致。
  • 文化差异（亚洲用户打分偏低）。
  • 不区分原因。

实战建议：

  • 搭配追问开放题："为什么？"。
  • 长期追踪趋势。
  • 不执着于绝对数字。

HEART 框架

Google Kerry Rodden 2010：

H - 幸福感：

  • 主观满意度。
  • 度量方式：问卷、NPS、CSAT。

E - 参与度：

  • 活跃互动程度。
  • 度量方式：日活、会话时长、操作次数。

A - 采纳率：

  • 新用户获取。
  • 度量方式：新账号/活跃增量。

R - 留存率：

  • 回访用户。
  • 度量方式：N 日留存曲线。

T - 任务成功率：

  • 有效性 + 效率。
  • 度量方式：任务完成率、用时、错误率。

目标-信号-指标框架：

  • 目标："让用户更快找到内容"。
  • 信号：搜索 → 点击 → 停留时间（成功）。
  • 指标：搜索后首次点击的平均用时。
行为分析
漏斗分析：


    

  • 多步流程。
    • 

  • 每步用户数。
    • 

  • 每步流失率。
    • 

  • 适用：新手引导、结账、订阅。
    • 



群组分析：


    

  • 按注册时间分组。
    • 

  • 追踪长期行为。
    • 

  • 适用：留存、功能采纳。
    • 



留存曲线：


    

  • N 日留存（第 1 天、第 7 天、第 30 天）。
    • 

  • "微笑曲线"为健康表现。
    • 

  • "死亡曲线"为严重问题。
    • 



热力图/滚动图：


    

  • 用户点击和滚动的位置。
    • 

  • 揭示注意力模式。
    • 

  • 工具：Hotjar、Crazy Egg、FullStory。
    • 



会话录屏：


    

  • 观看用户实际操作。
    • 

  • 注意隐私合规。
    • 

  • 识别困惑之处。
    • 



定量可用性
任务用时：


    

  • 完成任务所需时间。
    • 

  • 比较不同设计版本。
    • 



错误率：


    

  • 每任务的错误次数。
    • 

  • 区分失误（粗心）和错误（误解）。
    • 



任务成功率：


    

  • 无帮助完成的百分比。
    • 



SUS（见上文）。


选择指标的框架
与 OKR 对齐：


    

  • 指标必须对齐产品 OKR。
    • 

  • 例：OKR"提升用户留存 30%" → 指标：30 日留存。
    • 



结果优于产出：


    

  • 产出：功能上线、页面浏览。
    • 

  • 结果：用户价值实现。
    • 

  • 优先度量结果。
    • 



先行 vs 滞后：


    

  • 先行指标：预测未来（第一周内用户激活）。
    • 

  • 滞后指标：结果（收入）。
    • 

  • 先行指标允许更早行动。
    • 



唯一关键指标（OMTM）：


    

  • 单一北极星指标。
    • 

  • 聚焦团队方向。
    • 

  • 例：Airbnb 的"预定间夜数"。
    • 



A/B 测试统计
假设：


    

  • H0（零假设）：A = B。
    • 

  • H1（备选假设）：A ≠ B。
    • 



P 值：


    

  • < 0.05 拒绝零假设。
    • 

  • 差异具有统计显著性。
    • 



统计功效：


    

  • 1 - β（通常 0.8）。
    • 

  • 检测到真实差异的概率。
    • 



样本量：


    

  • 根据效果量和功效计算所需人数。
    • 

  • 工具：Optimizely 计算器。
    • 



实际显著性：


    

  • 统计显著 ≠ 商业显著。
    • 

  • 0.1% 提升统计显著但不值得发布。
    • 



常见陷阱：


    

  • 偷看数据（未达目标样本量前多次检查）→ 假阳性。
    • 

  • 多重比较（多指标/多分群）→ p 值膨胀。
    • 



工具
网站分析：


    

  • Google Analytics 4（免费）。
    • 

  • Adobe Analytics（企业级）。
    • 



产品分析：


    

  • Mixpanel。
    • 

  • Amplitude。
    • 

  • PostHog（开源）。
    • 



行为录屏：


    

  • Hotjar、FullStory、Crazy Egg。
    • 



A/B 测试：


    

  • Optimizely。
    • 

  • VWO。
    • 

  • LaunchDarkly + Eppo（现代方案）。
    • 



问卷：


    

  • Typeform。
    • 

  • Qualaroo（产品内嵌）。
    • 

  • Pendo（产品分析 + 问卷）。
    • 



隐私与伦理
追踪透明度：


    

  • 告知用户。
    • 

  • 允许退出。
    • 

  • GDPR 需要 Cookie 同意。
    • 



匿名化：


    

  • 未经同意不存储个人信息。
    • 

  • IP 匿名化。
    • 



删除权：


    

  • 用户可删除自己的数据。
    • 



Cookie 横幅：


    

  • 清晰明确 + 简洁。
    • 

  • 不用暗黑模式强制接受。
    • 



暗黑模式风险
优化错误指标：


    

  • "停留时间" → 成瘾性设计。
    • 

  • "转化率" → 羞辱式确认。
    • 



长期伤害：


    

  • 短期指标上升，长期留存下降。
    • 

  • 用户倦怠/后悔。
    • 



对冲指标：


    

  • 添加用户福利指标。
    • 

  • 例：用户反馈、取消原因、流失动机。
    • 



Apple 屏幕使用时间 / Google 数字健康：


    

  • 让用户的时间使用可见。
    • 

  • 反对不惜代价最大化参与度。
    • 



现代用户体验度量
"时间花得值"：


    

  • Tristan Harris 运动。
    • 

  • 优化用户价值而非参与度。
    • 



净参与度评分：


    

  • NPS 的替代方案，关注真实参与。
    • 



用户自定义的成功：


    

  • "这位用户达到了他的目标吗？"
    • 

  • 而非泛泛的参与度。
    • 



定性 + 定量：


    

  • 数据 + 访谈。
    • 

  • 不只看指标。
    • 



反度量模式
1. 古德哈特定律：


    

  • "当一个度量变成目标，它就不再是好的度量。"
    • 

  • 团队玩弄指标而不改善实质。
    • 



2. 虚荣指标：


    

  • 大数字听起来好但不可行动。
    • 

  • 例：页面浏览（vs 参与时长）。
    • 



3. 单一指标执念：


    

  • 一个指标驱动所有决策。
    • 

  • 失去细微差别。
    • 



4. 短期思维：


    

  • 优化季度表现损害长期。
    • 

  • 例：A/B 测试发布短期提升但长期留存下降的功能。
    • 



仪表盘
运营仪表盘：


    

  • 每日监控。
    • 

  • 日活、转化率、错误率。
    • 



战略仪表盘：


    

  • 每周/月度。
    • 

  • OKR 进展、留存群组。
    • 



调查分析：


    

  • 临时深入挖掘。
    • 

  • 非标准视图。
    • 



工具：


    

  • Looker、Tableau、PowerBI。
    • 

  • Mode、Hex（SQL 友好）。
    • 



持续发现
Teresa Torres 方法：


    

  • 每周客户访谈。
    • 

  • 每周更新机会树。
    • 

  • 持续验证假设。
    • 



与指标结合：


    

  • 指标显示"什么" + 访谈解释"为什么"。
    • 

  • 双轨道研究。
    • 



实战案例
Spotify HEART 度量示例：


    

  • 幸福感：应用商店评分、NPS。
    • 

  • 参与度：每日收听时长、点赞/收藏操作。
    • 

  • 采纳率：每周新注册。
    • 

  • 留存率：30 日留存（按群组）。
    • 

  • 任务成功：搜索到播放在 30 秒内。
    • 



流失分析案例：


    

  • 漏斗显示第 3 步（验证）30% 流失。
    • 

  • 热力图显示用户点错按钮。
    • 

  • 访谈揭示标签令人困惑。
    • 

  • 修复 → 重新度量 → 提升 10%。
    • 



投资回报
分析投入：


    

  • 工具订阅：每年 1千至10万美元。
    • 

  • 分析团队：每年 20万至100万美元。
    • 



回报：


    

  • 避免构建错误功能。
    • 

  • 识别流失点。
    • 

  • 量化用户体验工作的影响。
    • 



最佳方式：


    

  • 将分析嵌入团队。
    • 

  • 不设独立的"数据团队"。
    • 



小结
用户体验度量让设计量化——SUS（10 道李克特，0-100，高于 68 超平均）、NPS（0-10 推荐意愿，推荐者减贬损者）、Google HEART（幸福感/参与度/采纳率/留存率/任务成功率）+ 目标-信号-指标框架。行为分析——漏斗（流失）、群组（时间维度）、留存曲线（微笑 vs 死亡）、热力图、会话录屏。定量可用性——任务用时/错误率/任务成功率/SUS。选择指标——OKR 对齐 + 结果优于产出 + 先行 vs 滞后 + 唯一关键指标北极星。A/B 测试统计——p 值 < 0.05、功效 0.8、样本量、实际显著性，避免偷看和多重比较。工具——GA4/Adobe（网站）、Mixpanel/Amplitude/PostHog（产品）、Hotjar/FullStory（录屏）、Optimizely/VWO（A/B）、Typeform/Qualaroo（问卷）。隐私伦理——追踪透明 + 匿名化 + 删除权 + Cookie 横幅不暗黑模式。暗黑模式风险——优化错误指标伤害用户，用对冲指标关注用户福利，Apple 屏幕使用时间/Google 数字健康反对最大化参与度。现代度量——"时间花得值"（Tristan Harris）、净参与度评分、用户定义的成功、定性 + 定量结合。反度量模式——古德哈特定律（目标 ≠ 度量）、虚荣指标、单一指标执念、短期思维。仪表盘——运营/战略/调查分析。持续发现（Teresa Torres）每周访谈 + 指标。Spotify HEART 案例展示全局度量，流失分析案例展示漏斗 + 热力图 + 访谈 + 修复 → 度量循环。投资回报：将分析嵌入团队。一个简单的检验：你能列出你产品的北极星指标吗？如果不能，度量框架还需巩固。度量是用户体验与利益相关者的"共同语言"——让设计决策有数据支撑，而非主观偏好。
