DNS 系统

DNS 概述

DNS（Domain Name System）是互联网的"电话簿"，将人类可读的域名（如 www.example.com）转换为机器可识别的 IP 地址（如 93.184.216.34）。DNS 采用分层分布式架构，是全球最大的分布式数据库系统之一。

域名层次结构

                    . (根域)
                   / | \
               com  org  cn  ...        （顶级域 TLD）
              / | \
         google  github  example        （二级域）
          / \
       www  mail                        （子域/主机名）

完整域名（FQDN）：www.example.com.
                   │     │      │  │
                 主机名  二级域 TLD 根域（通常省略）

DNS 解析过程

用户输入 www.example.com

① 浏览器 DNS 缓存 → 未命中
② 操作系统 DNS 缓存 → 未命中
③ 本地 DNS 服务器（递归解析器）
    │
    │  ④ 查询根域名服务器（.）
    │  ← 返回 .com 的 NS 地址
    │
    │  ⑤ 查询 .com 顶级域服务器
    │  ← 返回 example.com 的 NS 地址
    │
    │  ⑥ 查询 example.com 权威服务器
    │  ← 返回 www.example.com = 93.184.216.34
    │
④ 本地 DNS 服务器缓存结果
⑤ 返回 IP 地址给客户端

递归查询 vs 迭代查询

特性 递归查询 迭代查询
查询方式 客户端 → 本地 DNS → 代为查询 本地 DNS → 逐级询问
查询负担 集中在本地 DNS 服务器 分散在各级 DNS 服务器
使用场景 客户端到本地 DNS 本地 DNS 到各级权威 DNS 
递归查询：
  客户端 → 本地DNS："帮我查 www.example.com"
  本地DNS 自己去逐级查询，最终返回结果

迭代查询：
  本地DNS → 根DNS："www.example.com 在哪？"
  根DNS → "我不知道，去问 .com 服务器"
  本地DNS → .com DNS："www.example.com 在哪？"
  .com DNS → "去问 example.com 的权威服务器"

DNS 记录类型

类型 名称 值 用途
A 域名 IPv4 地址 域名到 IPv4 映射
AAAA 域名 IPv6 地址 域名到 IPv6 映射
CNAME 别名 规范域名 域名别名（CDN 常用）
MX 域名 邮件服务器域名 邮件路由
NS 域名 权威 DNS 服务器 委派 DNS 管理
TXT 域名 文本信息 SPF、DKIM、域名验证
SRV 服务名 主机+端口 服务发现
PTR IP 地址 域名 反向解析
SOA 域名 区域权威信息 区域配置 
dig www.example.com A +short
# 93.184.216.34

dig example.com MX +short
# 10 mail.example.com.

dig example.com NS +short
# ns1.example.com.
# ns2.example.com.

dig example.com TXT +short
# "v=spf1 include:_spf.google.com ~all"

DNS 缓存

DNS 缓存存在于多个层级，TTL（Time To Live）控制缓存时间。

缓存层级：
  浏览器缓存      → TTL 通常较短（~60s）
  操作系统缓存    → 遵循 DNS 响应中的 TTL
  本地 DNS 缓存   → 遵循 TTL，通常 300-3600s
  CDN 边缘缓存    → 自定义缓存策略
TTL 设置 优点 缺点
短 TTL 快速生效 DNS 变更 DNS 查询量大
长 TTL 减少 DNS 查询 变更生效慢 
# 查看 DNS 记录的 TTL
dig www.example.com +nocmd +noall +answer
# www.example.com.    300    IN    A    93.184.216.34
#                     ↑ TTL = 300秒

DNS 与 CDN

CDN（Content Delivery Network）通过 DNS 的 CNAME 记录和智能解析将用户引导到最近的边缘节点。

用户请求 www.example.com

① DNS 解析 www.example.com
   → CNAME: www.example.com.cdn.cloudflare.net
② DNS 解析 cdn.cloudflare.net
   → 智能 DNS 根据用户 IP 返回最近的边缘节点 IP
③ 用户连接最近的 CDN 边缘节点

用户（北京）→ CDN 北京节点（命中缓存）→ 直接返回
用户（纽约）→ CDN 纽约节点（命中缓存）→ 直接返回
CDN 节点未命中 → 回源到 Origin Server

DNS 安全

威胁 描述 防御措施
DNS 劫持 篡改 DNS 响应返回恶意 IP DNSSEC
DNS 缓存投毒 向缓存注入虚假记录 随机化源端口和ID
DDoS 大量查询淹没 DNS 服务器 Anycast、限速
DNS 隧道 利用 DNS 协议进行数据传输 深度包检测

DNSSEC 通过数字签名验证 DNS 响应的完整性和来源，防止篡改。

小结

  • DNS 是互联网基础设施的核心，采用分层分布式架构实现全球域名解析。
  • 解析过程涉及递归查询和迭代查询，多级缓存减少查询延迟和负载。
  • 常用记录类型包括 A/AAAA（地址）、CNAME（别名）、MX（邮件）、NS（委派）。
  • CDN 依赖 DNS 的 CNAME 和智能解析将用户引导到最近的节点。
  • DNSSEC 是保障 DNS 安全的重要机制，防止劫持和缓存投毒攻击。
