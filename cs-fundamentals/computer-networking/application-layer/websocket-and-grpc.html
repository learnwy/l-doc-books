WebSocket 与 gRPC

为什么需要实时通信

传统 HTTP 是请求-响应模型，客户端必须主动发起请求才能获取数据。对于实时聊天、股票行情、协同编辑等场景，需要服务器能主动向客户端推送数据。



WebSocket 协议
WebSocket 握手
WebSocket 通过 HTTP Upgrade 机制建立连接，握手后切换为 WebSocket 协议。


客户端请求：
  GET /chat HTTP/1.1
  Host: example.com
  Upgrade: websocket
  Connection: Upgrade
  Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==
  Sec-WebSocket-Version: 13

服务端响应：
  HTTP/1.1 101 Switching Protocols
  Upgrade: websocket
  Connection: Upgrade
  Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=
握手完成后，连接从 HTTP 升级为 WebSocket，双方可以自由地双向发送消息。


WebSocket 帧格式
WebSocket 客户端示例
const ws = new WebSocket('wss://example.com/chat');

ws.onopen = () => {
  ws.send(JSON.stringify({ type: 'join', room: 'general' }));
};

ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  console.log('收到消息:', data);
};

ws.onclose = (event) => {
  console.log(`连接关闭: ${event.code} ${event.reason}`);
};

ws.onerror = (error) => {
  console.error('WebSocket 错误:', error);
};


gRPC 协议
gRPC 是 Google 开发的高性能 RPC 框架，基于 HTTP/2 和 Protocol Buffers（Protobuf）。


Protobuf 定义
syntax = "proto3";

package chat;

service ChatService {
  rpc SendMessage (MessageRequest) returns (MessageResponse);
  rpc Subscribe (SubscribeRequest) returns (stream ChatMessage);
  rpc Chat (stream ChatMessage) returns (stream ChatMessage);
}

message MessageRequest {
  string room_id = 1;
  string content = 2;
  string sender = 3;
}

message MessageResponse {
  string message_id = 1;
  int64 timestamp = 2;
}

message ChatMessage {
  string sender = 1;
  string content = 2;
  int64 timestamp = 3;
}

流式处理
WebSocket 流式处理
const WebSocket = require('ws');
const wss = new WebSocket.Server({ port: 8080 });

wss.on('connection', (ws) => {
  const interval = setInterval(() => {
    if (ws.readyState === WebSocket.OPEN) {
      ws.send(
        JSON.stringify({
          type: 'ticker',
          price: (Math.random() * 1000).toFixed(2),
          timestamp: Date.now(),
        }),
      );
    }
  }, 1000);

  ws.on('close', () => clearInterval(interval));
});
gRPC 优势：强类型与代码生成
自动生成类型安全的客户端和服务端代码




选型建议


小结
    

  • WebSocket 通过 HTTP Upgrade 建立全双工连接，适合浏览器端的实时双向通信。
    • 

  • gRPC 基于 HTTP/2 和 Protobuf，提供高性能、强类型的 RPC 通信，适合微服务间调用。
    • 

  • SSE 是最简单的服务器推送方案，内置自动重连，适合单向数据流场景。
    • 

  • gRPC 的四种通信模式（Unary、流式）覆盖了各种通信需求。
    • 

  • 选型需综合考虑通信方向、浏览器兼容性、性能要求和类型安全需求。
