HTTP 协议

HTTP 协议概述

HTTP（HyperText Transfer Protocol）是应用层最核心的协议，定义了客户端与服务器之间的请求-响应通信模型。从 1991 年的 HTTP/0.9 到如今的 HTTP/3，HTTP 协议经历了多次重大演进。

HTTP 版本演进

版本 年份 传输层 关键特性
HTTP/0.9 1991 TCP 仅支持 GET，无头部
HTTP/1.0 1996 TCP 头部、状态码、Content-Type
HTTP/1.1 1997 TCP 持久连接、管线化、Host 头
HTTP/2 2015 TCP 多路复用、头部压缩、服务器推送
HTTP/3 2022 QUIC/UDP 0-RTT、无队头阻塞

HTTP/1.1 核心特性

持久连接（Keep-Alive）

HTTP/2 核心特性
二进制分帧
HTTP/1.1 使用文本协议（如 GET /index.html HTTP/1.1\r\n），而 HTTP/2 使用二进制帧格式：


多路复用
HPACK 头部压缩
请求 1: GET /page1  Host: example.com  Accept: text/html
请求 2: GET /page2  Host: example.com  Accept: text/html

HPACK 压缩后，请求 2 只需发送 /page2（其余字段引用静态/动态表索引）
压缩率可达 90%+


HTTP/3 与 QUIC
优势：0-RTT 连接恢复、无队头阻塞、连接迁移

Cache-Control 常用指令：
  max-age=3600       → 缓存 1 小时
  no-cache           → 每次都需要协商验证
  no-store           → 禁止任何缓存
  public             → 允许 CDN 等中间缓存
  private            → 仅浏览器可缓存
  immutable          → 资源永不变化


小结
    

  • HTTP 从文本协议演进到二进制协议，从 TCP 迁移到 QUIC/UDP，持续追求更低延迟和更高吞吐。
    • 

  • HTTP/2 的多路复用和头部压缩解决了 HTTP/1.1 的队头阻塞和冗余头部问题。
    • 

  • HTTP/3 基于 QUIC 彻底消除了传输层队头阻塞，支持 0-RTT 和连接迁移。
    • 

  • 合理使用缓存机制（强缓存 + 协商缓存）是 Web 性能优化的关键手段。
    • 

  • 理解 HTTP 方法的语义（幂等性、安全性）是设计 RESTful API 的基础。
