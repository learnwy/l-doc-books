VPN 与隧道

VPN 概述

VPN（Virtual Private Network）通过公共网络建立加密的私有通信通道，使远程用户或分支机构能够安全地访问内部网络资源，如同在局域网中一样。

传统方案（专线）：
  总部 ════════════════ 分部（昂贵的物理专线）

VPN 方案（加密隧道）：
  总部 ──→ [加密隧道] ──→ 互联网 ──→ [加密隧道] ──→ 分部
  成本低、灵活部署

VPN 类型

类型 使用场景 协议 特点
站点到站点 分支机构互联 IPSec, GRE 永久连接
远程访问 员工远程办公 SSL VPN, L2TP 按需连接
客户端到站点 个人设备接入企业网络 WireGuard, OpenVPN 简单部署

IPSec VPN

IPSec 在网络层提供安全服务，包括加密（ESP）和认证（AH）两种协议。

IPSec 工作模式

传输模式（Transport Mode）：
  [原始 IP 头] [ESP/AH 头] [TCP/UDP 头] [数据]
  仅加密负载，保留原始 IP 头
  适用：主机到主机通信

隧道模式（Tunnel Mode）：
  [新 IP 头] [ESP/AH 头] [原始 IP 头] [TCP/UDP 头] [数据]
  加密整个原始 IP 包，添加新 IP 头
  适用：网关到网关（站点到站点 VPN）

IKE 密钥交换

Phase 1（建立安全通道）：
  协商加密算法 → DH 密钥交换 → 身份认证
  → 建立 IKE SA（安全关联）

Phase 2（建立 IPSec 隧道）：
  协商 IPSec 参数 → 生成会话密钥
  → 建立 IPSec SA（数据通道）
组件 功能 协议/算法
AH 完整性+认证 SHA-256, SHA-384
ESP 加密+完整性 AES-256, ChaCha20
IKE 密钥协商 DH, ECDH

WireGuard

WireGuard 是新一代 VPN 协议，以极简的代码量（约 4000 行，对比 OpenVPN 60 万行）实现了高性能和高安全性。

WireGuard 特点

特性 WireGuard OpenVPN IPSec
代码量 ~4,000 行 ~600,000 行 极为复杂
加密算法 ChaCha20, Curve25519 可配置多种 可配置多种
性能 极高（内核态） 中（用户态） 高
配置复杂度 极简 中 高
状态 无状态（密码学路由） 有连接状态 有 SA 状态

WireGuard 配置示例

# 服务端配置 /etc/wireguard/wg0.conf
[Interface]
PrivateKey = <server-private-key>
Address = 10.0.0.1/24
ListenPort = 51820

[Peer]
PublicKey = <client-public-key>
AllowedIPs = 10.0.0.2/32
# 客户端配置
[Interface]
PrivateKey = <client-private-key>
Address = 10.0.0.2/24
DNS = 1.1.1.1

[Peer]
PublicKey = <server-public-key>
Endpoint = vpn.example.com:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
wg-quick up wg0
wg show

SSL VPN

SSL VPN 基于 TLS 协议，通过浏览器或轻量客户端提供远程访问，无需安装专用 VPN 客户端。

SSL VPN 两种模式：

Web 模式（无客户端）：
  浏览器 → HTTPS → SSL VPN 网关 → 反向代理 → 内部 Web 应用
  仅支持 Web 应用访问

隧道模式（需要客户端）：
  VPN 客户端 → TLS 隧道 → SSL VPN 网关 → 内部网络
  支持所有网络应用

GRE 隧道

GRE（Generic Routing Encapsulation）是通用路由封装协议，可以在 IP 网络上封装任意协议的数据包。

GRE 封装格式：
  [外层 IP 头] [GRE 头] [内层 IP 头] [TCP/UDP] [数据]
  │            │        │
  隧道端点IP   封装协议  原始数据包

GRE 隧道特点：
  ✓ 支持组播（IPSec 不支持）
  ✓ 可封装非 IP 协议
  ✗ 不提供加密（通常与 IPSec 组合使用）

GRE over IPSec

  [外层 IP 头] [ESP 头] [GRE 头] [内层 IP 头] [数据] [ESP 尾]
  │             │        │        │
  隧道端点      加密      封装    原始包

  GRE 提供封装能力 + IPSec 提供加密能力 = 完整的安全隧道

零信任网络

零信任（Zero Trust）模型颠覆了传统的"边界安全"理念，核心原则是"永不信任，始终验证"。

传统网络安全（城堡模型）：
  互联网 ──→ [防火墙] ──→ 内部网络（内部默认信任）
  问题：一旦攻破边界，内部畅通无阻

零信任模型：
  每次访问 ──→ [身份验证] ──→ [设备健康检查] ──→ [最小权限] ──→ 资源
  无论内外网，每次访问都需要验证

零信任核心原则

原则 描述
最小权限 仅授予完成任务所需的最小访问权限
持续验证 每次访问都需要身份验证和授权
微分段 将网络划分为细粒度的安全区域
设备信任 验证设备的安全状态和合规性
加密一切 所有通信都加密，无论内外网

零信任架构组件

用户/设备
    │
    ↓
[身份提供商 IdP]  ← SSO、MFA
    │
    ↓
[策略引擎]  ← 访问策略（身份+设备+上下文）
    │
    ↓
[零信任代理/网关]  ← BeyondCorp, Zscaler, Cloudflare Access
    │
    ↓
[应用/资源]  ← 最小权限访问

VPN 协议对比

协议 加密 速度 配置难度 防火墙穿越 推荐场景
WireGuard 强 极快 简单 良好 首选方案
OpenVPN 强 中等 中等 优秀(443) 跨平台兼容
IPSec 强 快 复杂 一般 站点到站点
L2TP/IPSec 强 中等 中等 一般 移动设备内置支持
PPTP 弱(已破解) 快 简单 一般 不推荐使用

小结

  • VPN 通过加密隧道在公共网络上建立安全的私有通信通道。
  • IPSec 提供网络层的端到端加密，适合站点到站点的 VPN 部署。
  • WireGuard 以极简设计实现高性能 VPN，是现代 VPN 的首选协议。
  • GRE 隧道提供协议封装能力，通常与 IPSec 组合使用以获得安全性。
  • 零信任网络颠覆了传统边界安全模型，通过持续验证和最小权限实现更强的安全保障。
