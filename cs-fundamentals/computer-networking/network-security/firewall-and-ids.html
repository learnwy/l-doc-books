防火墙与 IDS

核心概念

防火墙是流量的"准入策略执行点"：按规则决定哪些连接可以通过。它的能力随工作层级上升而增强——L3/L4 只看 IP 与端口，L7 能读懂应用协议内容，代价是性能与复杂度。IDS/IPS 则是"行为检测点"，前者旁路监听告警、后者串联阻断，用来发现放行流量中的恶意行为。

graph TD
    NET[流量] --> FW{防火墙: 规则允许?}
    FW -->|否| DROP[丢弃 + 记录]
    FW -->|是| IDS{IDS/IPS: 是否为攻击?}
    IDS -->|是| BLOCK[告警 or 阻断]
    IDS -->|否| PASS[放行到内网]
能力层级 检查深度 典型产品 本文对应小节
包过滤 IP / 端口 iptables, pf 防火墙类型
状态防火墙 连接状态 企业级防火墙 防火墙类型
L7 / NGFW 应用协议内容 WAF, Palo Alto 防火墙类型
行为检测 已知特征 / 异常 IDS（告警）、IPS（阻断） IDS 与 IPS

核心取舍在安全与性能/可用性之间：检查越深越安全但越慢，IPS 串联部署还承担误判阻断正常业务的风险。因此实践中不靠单点，而是"纵深防御"——从 CDN 到边界防火墙到主机安全层层设防，每层只解决自己边界内的问题。

防火墙概述

防火墙是网络安全的第一道防线，通过预定义的安全规则控制进出网络的流量。防火墙根据工作层级和检测方式分为多种类型。

flowchart LR
    A["互联网"] --> B["防火墙<br>规则引擎<br>允许/拒绝<br>日志/告警"]
    B --> C["内部网络"]

防火墙类型

包过滤防火墙（Packet Filter）

工作在网络层（L3/L4），基于 IP 地址、端口、协议进行过滤。

规则示例：
  允许  TCP  任意来源  →  内网:80   （允许 HTTP）
  允许  TCP  任意来源  →  内网:443  （允许 HTTPS）
  拒绝  TCP  任意来源  →  内网:22   （禁止 SSH）
  拒绝  所有                        （默认拒绝）

状态防火墙（Stateful Firewall）

跟踪连接状态，只允许属于已建立连接的数据包通过。

状态表示例：
| 源 IP         | 目标 IP        | 源端口 | 目标端口 | 协议 | 状态         |
| 192.168.1.10  | 93.184.216.34  | 54321  | 443      | TCP  | ESTABLISHED  |
| 192.168.1.20  | 8.8.8.8        | 12345  | 53       | UDP  | NEW          |

入站数据包 → 检查是否匹配已有连接 → 是 → 放行
                                      否 → 检查规则 → 拒绝/允许

应用层防火墙（Application Gateway）

工作在应用层（L7），能够理解和检查应用协议内容。

防火墙类型 工作层级 检查深度 性能 典型产品
包过滤 L3/L4 IP/端口 高 iptables, pf
状态防火墙 L3/L4 连接状态 较高 企业级防火墙
应用层防火墙 L7 应用协议内容 较低 WAF, 代理防火墙
NGFW L3-L7 全栈检测 中 Palo Alto, Fortinet

iptables / nftables

iptables 基础

iptables 是 Linux 最经典的防火墙工具，基于 Netfilter 框架。

flowchart TD
    IN["入站数据包"] --> PRE["PREROUTING"]
    PRE --> ROUTE{"路由判断"}
    ROUTE -->|"本地"| INPUT["INPUT"]
    INPUT --> LOCAL["本地进程"]
    ROUTE -->|"转发"| FWD["FORWARD"]
    FWD --> POST["POSTROUTING"]
    LOCAL --> OUTPUT["OUTPUT"]
    OUTPUT --> POST
    POST --> OUT["出站数据包"]
# 允许已建立的连接
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# 允许 SSH
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# 允许 HTTP/HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# 允许本地回环
iptables -A INPUT -i lo -j ACCEPT

# 默认拒绝所有入站
iptables -P INPUT DROP

# 查看规则
iptables -L -n -v

nftables（iptables 的继任者）

nft add table inet filter
nft add chain inet filter input { type filter hook input priority 0 \; policy drop \; }
nft add rule inet filter input ct state established,related accept
nft add rule inet filter input tcp dport { 22, 80, 443 } accept
nft add rule inet filter input iif lo accept

IDS 与 IPS

特性 IDS（入侵检测系统） IPS（入侵防御系统）
工作模式 旁路监听（被动） 串联部署（主动）
响应方式 告警通知 实时阻断
对业务影响 无 误判可能阻断正常流量
部署位置 镜像端口 网络链路中间

检测方法

方法 描述 优点 缺点
签名检测 匹配已知攻击特征库 准确率高 无法检测未知攻击
异常检测 建立基线，检测偏离行为 可检测未知攻击 误报率较高
协议分析 分析协议合规性 深度检测 计算开销大

WAF（Web 应用防火墙）

WAF 专门保护 Web 应用，工作在 HTTP 层，能识别和阻断 SQL 注入、XSS、CSRF 等攻击。

正常请求：
  GET /api/users?id=123 → WAF 放行 → 后端服务器

恶意请求：
  GET /api/users?id=1' OR '1'='1 → WAF 拦截（SQL 注入）
  POST /comment body="<script>alert('xss')</script>" → WAF 拦截（XSS）
WAF 类型 部署方式 代表产品
云 WAF DNS 代理 / CDN Cloudflare, AWS WAF
硬件 WAF 网络串联 F5, Imperva
软件 WAF Web 服务器插件 ModSecurity, OpenResty

纵深防御架构

flowchart TD
    A["互联网"] --> B["CDN/云 WAF<br>第一层:DDoS 防护 + Web 攻击过滤"]
    B --> C["边界防火墙<br>第二层:网络层访问控制"]
    C --> D["IPS<br>第三层:入侵检测与防御"]
    D --> E["内部防火墙/微分段<br>第四层:东西向流量控制"]
    E --> F["主机安全<br>第五层:端点防护"]

小结

  • 防火墙按工作层级分为包过滤、状态、应用层三类，NGFW 提供全栈检测能力。
  • iptables/nftables 是 Linux 系统最常用的防火墙工具，基于规则链进行流量过滤。
  • IDS 被动检测并告警，IPS 主动阻断恶意流量，两者互补使用效果最佳。
  • WAF 专注于 Web 应用安全，防御 SQL 注入、XSS 等 OWASP Top 10 攻击。
  • 纵深防御（Defense in Depth）通过多层安全措施实现全面的网络保护。
