TLS 与 HTTPS

HTTPS 概述

HTTPS = HTTP + TLS，在 HTTP 和 TCP 之间插入 TLS（Transport Layer Security）加密层，为 Web 通信提供机密性、完整性和身份验证。

HTTP（明文）：
  浏览器 ──→ [HTTP 请求明文] ──→ 服务器
  中间人可以窃听、篡改

HTTPS（加密）：
  浏览器 ──→ [TLS 加密的 HTTP 请求] ──→ 服务器
  中间人无法解密、无法篡改

TLS 握手过程

TLS 1.2 握手（2-RTT）

客户端                                        服务端
  │                                             │
  │  ① ClientHello                              │
  │  (支持的加密套件、随机数)                     │
  │  ─────────────────────────────→              │
  │                                             │
  │  ② ServerHello                              │
  │  (选定的加密套件、随机数)                     │
  │  ② Certificate (服务器证书)                   │
  │  ② ServerKeyExchange                        │
  │  ② ServerHelloDone                          │
  │  ←─────────────────────────────              │
  │                                             │
  │  ③ ClientKeyExchange                        │
  │  ③ ChangeCipherSpec                         │
  │  ③ Finished (加密)                           │
  │  ─────────────────────────────→              │
  │                                             │
  │  ④ ChangeCipherSpec                         │
  │  ④ Finished (加密)                           │
  │  ←─────────────────────────────              │
  │                                             │
  │  [开始加密通信]                               │

TLS 1.3 握手（1-RTT）

客户端                                        服务端
  │                                             │
  │  ① ClientHello + KeyShare                   │
  │  ─────────────────────────────→              │
  │                                             │
  │  ② ServerHello + KeyShare                   │
  │  ② EncryptedExtensions                      │
  │  ② Certificate + CertificateVerify          │
  │  ② Finished                                 │
  │  ←─────────────────────────────              │
  │                                             │
  │  ③ Finished                                 │
  │  ─────────────────────────────→              │
  │                                             │
  │  [仅 1 个 RTT，即可开始加密通信]              │

TLS 1.2 vs TLS 1.3

特性 TLS 1.2 TLS 1.3
握手延迟 2 RTT 1 RTT（0-RTT 恢复）
密钥交换 RSA / ECDHE 仅 ECDHE / DHE
对称加密 AES-CBC, AES-GCM 等 仅 AEAD（AES-GCM, ChaCha20）
前向保密 可选 强制
握手加密 明文握手 加密握手（从 ServerHello 开始）
0-RTT 不支持 支持（会话恢复时）

证书链

根证书（Root CA）        → 内置于操作系统/浏览器
      │ 签发
中间证书（Intermediate CA）→ 由根 CA 签发
      │ 签发
服务器证书（End Entity）  → 绑定域名和公钥

验证过程：
  浏览器收到服务器证书
  → 用中间 CA 的公钥验证服务器证书签名
  → 用根 CA 的公钥验证中间 CA 证书签名
  → 根 CA 在信任列表中 → 验证通过
# 查看网站的证书链
openssl s_client -connect example.com:443 -showcerts

# 查看证书详情
openssl x509 -in cert.pem -text -noout

加密套件

加密套件命名格式：
TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384
│    │      │        │    │    │    │
│    │      │        │    │    │    └─ MAC 算法
│    │      │        │    │    └────── 密钥长度
│    │      │        │    └─────────── 模式
│    │      │        └────────────── 对称加密算法
│    │      └─────────────────────── 认证算法
│    └────────────────────────────── 密钥交换算法
└─────────────────────────────────── 协议
组件 推荐选择 避免使用
密钥交换 ECDHE, DHE RSA（无前向保密）
认证 ECDSA, RSA —
对称加密 AES-256-GCM, ChaCha20-Poly1305 RC4, DES, 3DES
哈希 SHA-256, SHA-384 MD5, SHA-1

HSTS（HTTP 严格传输安全）

HSTS 强制浏览器只通过 HTTPS 访问站点，防止 SSL 剥离攻击。

服务器响应头：
  Strict-Transport-Security: max-age=31536000; includeSubDomains; preload

效果：
  1. 浏览器在 max-age 期间自动将 HTTP 请求升级为 HTTPS
  2. includeSubDomains：所有子域名也强制 HTTPS
  3. preload：加入浏览器内置 HSTS 预加载列表

证书类型

类型 验证级别 颁发时间 费用 适用场景
DV 域名验证 分钟级 免费/低 个人站点、API
OV 组织验证 天级 中 企业网站
EV 扩展验证 周级 高 金融、电商 
# 使用 Let's Encrypt 免费获取 DV 证书
certbot certonly --nginx -d example.com -d www.example.com

常见 TLS 配置问题

问题 风险 解决方案
使用 TLS 1.0/1.1 已知漏洞 最低要求 TLS 1.2
弱加密套件 可被破解 禁用 RC4、3DES
证书过期 浏览器警告 自动续期（certbot renew）
混合内容 部分资源走 HTTP 全站 HTTPS + CSP 策略
无 HSTS SSL 剥离攻击 配置 HSTS 头

小结

  • TLS 为 HTTP 通信提供加密、完整性保护和身份验证三大安全保障。
  • TLS 1.3 将握手压缩到 1 RTT，强制前向保密，淘汰了不安全的算法。
  • 证书链通过信任锚（根 CA）实现层级验证，Let's Encrypt 使免费证书普及化。
  • HSTS 防止 SSL 剥离攻击，是 HTTPS 部署的必备配置。
  • 定期检查和更新 TLS 配置，禁用过时的协议和弱加密套件。
