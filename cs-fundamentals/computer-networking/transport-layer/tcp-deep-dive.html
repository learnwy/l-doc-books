TCP 深入

TCP 协议概述

TCP（Transmission Control Protocol）是传输层的核心协议，提供面向连接、可靠、有序的字节流传输服务。TCP 通过序列号、确认机制、重传策略和流量控制等机制保障数据的可靠交付。

TCP 报文段格式



三次握手
TCP 使用三次握手建立连接，确保双方都准备好进行数据传输。


为什么是三次而非两次？两次握手无法防止历史重复连接的建立——如果旧的 SYN 报文延迟到达服务端，服务端会误以为是新连接请求。




四次挥手
TCP 使用四次挥手关闭连接，因为 TCP 是全双工的，每个方向需要独立关闭。


TIME_WAIT 状态持续 2MSL（Maximum Segment Lifetime，通常 60 秒），目的是确保最后一个 ACK 能到达对方，并防止旧连接的延迟报文干扰新连接。




半连接队列与全连接队列
SYN Flood 攻击通过大量伪造 SYN 请求填满半连接队列。防御手段包括 SYN Cookie 和增大队列长度。




滑动窗口
滑动窗口机制实现了 TCP 的流量控制，允许发送方在收到确认之前连续发送多个报文段。


零窗口探测：当接收方通告窗口为 0 时，发送方定期发送探测报文，避免死锁。




拥塞控制概览
TCP 的拥塞控制通过调节拥塞窗口（cwnd）来避免网络过载。发送方的实际窗口为 min(cwnd, rwnd)。

Nagle 算法
Nagle 算法减少网络中小报文的数量，将多个小数据合并为一个较大的报文段发送。


没有 Nagle：
  发送 "H" → 1 个报文
  发送 "e" → 1 个报文
  发送 "l" → 1 个报文
  发送 "l" → 1 个报文
  发送 "o" → 1 个报文
  共 5 个报文（每个 40+ 字节头部）

使用 Nagle：
  发送 "H" → 1 个报文（立即发送，因为没有未确认的数据）
  收集 "ello" → 等待 "H" 的 ACK 到达
  发送 "ello" → 1 个报文
  共 2 个报文
在低延迟场景（如实时游戏、交互式终端）中，通常需要禁用 Nagle 算法：


int flag = 1;
setsockopt(sockfd, IPPROTO_TCP, TCP_NODELAY, &flag, sizeof(flag));

小结
    

  • 三次握手建立连接，四次挥手关闭连接，TIME_WAIT 等待 2MSL 防止报文混淆。
    • 

  • 滑动窗口实现流量控制，拥塞窗口实现拥塞控制，实际窗口取两者最小值。
    • 

  • Nagle 算法通过合并小报文提高网络效率，但可能增加延迟。
    • 

  • 半连接队列和全连接队列是 TCP 连接管理的关键数据结构，也是攻击的目标。
    • 

  • 理解 TCP 状态机是调试连接问题的基础。
