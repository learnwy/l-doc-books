容器网络

容器网络基础

容器技术（Docker、Kubernetes）改变了应用的部署方式，也带来了全新的网络挑战。每个容器都需要网络连接、IP 地址分配和服务发现，同时还要保证隔离性和安全性。

  • 传统部署：物理机/虚拟机 → 固定 IP → 长生命周期
  • 容器部署：容器 → 动态 IP → 短生命周期 → 频繁创建销毁，需要动态网络配置、服务发现、负载均衡

Docker 网络模式

网络模式 描述 IP 分配 隔离性 使用场景
bridge 默认模式，docker0 虚拟网桥 Docker 分配私有 IP 中 单机容器通信
host 容器共享宿主机网络栈 使用宿主机 IP 无 高性能网络
none 无网络配置 无 完全 安全敏感场景
overlay 跨主机容器网络 虚拟网络 IP 高 Swarm/K8s 集群
macvlan 容器拥有独立 MAC 地址 与宿主机同网段 高 需要直接接入物理网络

Bridge 网络原理



    

  • 容器间通信：通过 docker0 网桥二层转发
    • 

  • 容器访问外网：通过 iptables NAT
    • 

  • 外网访问容器：通过 iptables DNAT（端口映射）
    • 







Kubernetes 网络模型
Kubernetes 网络模型要求满足三个基本条件：


    

  1. 所有 Pod 可以不通过 NAT 直接互相通信
    2. 

  2. 所有节点可以不通过 NAT 直接与所有 Pod 通信
    3. 

  3. Pod 看到自己的 IP 就是别人看到的 IP
    4.

Service Mesh
Service Mesh 是微服务间通信的基础设施层，通过 Sidecar 代理处理服务间的所有网络通信。

eBPF 与 Cilium
eBPF（extended Berkeley Packet Filter）允许在 Linux 内核中运行沙箱程序，Cilium 利用 eBPF 实现高性能的容器网络和安全策略。




eBPF/Cilium 减少数据路径跳数，O(1) 复杂度的策略匹配






小结
    

  • Docker 提供 bridge、host、overlay 等多种网络模式，bridge 是默认的单机容器网络方案。
    • 

  • Kubernetes 网络模型要求所有 Pod 可直接互通，通过 CNI 插件实现。
    • 

  • Calico 使用 BGP 路由实现高性能的纯三层网络，Cilium 使用 eBPF 实现内核级网络处理。
    • 

  • Service Mesh 通过 Sidecar 代理透明地处理微服务间的通信、安全和可观测性。
    • 

  • eBPF 是容器网络的未来方向，提供更高性能和更灵活的可编程能力。
    •
