RBAC 与权限模型

权限模型概述

权限模型定义了系统中"谁可以对什么资源执行什么操作"的规则。选择正确的权限模型直接影响系统的安全性、灵活性和可维护性。

模型 全称 核心思想
ACL Access Control List 直接为用户分配资源权限
RBAC Role-Based Access Control 通过角色间接分配权限
ABAC Attribute-Based Access Control 基于属性的动态策略决策
ReBAC Relationship-Based Access Control 基于资源关系的权限判断

ACL（访问控制列表）

ACL 为每个资源维护一个访问列表，直接记录哪些用户拥有哪些权限。

优点 缺点
概念简单直观 用户多时管理困难
精确控制到个人 权限变更需逐个修改
适合小规模系统 无法表达复杂的策略逻辑

RBAC（基于角色的访问控制）

RBAC 是最广泛使用的权限模型，通过"角色"作为用户和权限之间的桥梁。

ABAC（基于属性的访问控制）
ABAC 通过评估主体、资源、操作和环境的属性来做出访问决策，提供比 RBAC 更强的表达能力。

操作属性
读取、写入、删除、审批




环境属性
时间、IP 地址、设备类型

小结
    

  • RBAC 通过角色间接管理权限，是最广泛使用的权限模型
    • 

  • ABAC 基于属性做动态决策，适合复杂、细粒度的权限场景
    • 

  • 推荐 RBAC + ABAC 混合模型：RBAC 覆盖常见场景，ABAC 处理动态需求
    • 

  • OPA 和 Casbin 是两个主流的开源策略引擎
    • 

  • 最小权限原则和职责分离是权限设计的两条核心原则
