密码存储与密钥管理

密码存储原则

密码是用户认证的第一道防线，其存储方式直接决定了系统在数据泄露事件中的损害程度。核心原则是：永远不要存储明文密码，也不要使用通用哈希函数。

存储方式 安全性 说明
明文存储 ❌ 数据泄露即全部暴露
可逆加密 ❌ 密钥泄露等同于明文
通用哈希 ⚠️ SHA-256 太快，GPU 暴力破解
加盐哈希 ⚠️ 盐值防彩虹表，但速度仍然太快
专用密码哈希 ✅ bcrypt/argon2id 刻意设计为慢速

密码哈希算法详解

argon2id

argon2id 是 2015 年密码哈希竞赛（PHC）的冠军，综合了 CPU 密集和内存密集两种抵御策略。

参数 说明 推荐值
time 迭代次数 3（至少 2）
memory 内存使用量 64 MB（至少 19 MB）
parallelism 并行度 1-4
output 输出长度 32 bytes

bcrypt

bcrypt 基于 Blowfish 加密算法，通过 cost factor 控制计算成本：

cost factor 耗时（约） 适用场景
10 ~100ms 在线登录
12 ~400ms 标准推荐
14 ~1.5s 高安全场景

bcrypt 的限制：最大输入长度为 72 字节，超长密码需先做 SHA-256 预哈希。

小结
    

  • 密码必须使用 argon2id 或 bcrypt 等专用哈希函数存储
    • 

  • NIST 最新指南建议注重密码长度而非复杂度，并对照泄露密码库
    • 

  • HashiCorp Vault 是密钥管理的行业标准，支持动态密钥和自动轮换
    • 

  • 密钥轮换需要支持多版本并存，实现零停机的平滑过渡
    • 

  • 绝不硬编码密钥，绝不提交密钥到代码仓库，绝不在日志中打印密钥
    •
