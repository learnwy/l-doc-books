依赖安全与 SCA

依赖安全概述

现代软件项目平均 80% 以上的代码来自开源依赖。2021 年 Log4Shell（CVE-2021-44228）漏洞影响了数百万 Java 应用，深刻证明了依赖安全的重要性。软件组成分析（Software Composition Analysis，SCA）是管理依赖安全风险的核心手段。

一个中等规模的 Node.js 项目通常包含 300-800 个直接和传递依赖。npm 生态中曾发生多次供应链事件：event-stream 恶意代码注入（2018）、ua-parser-js 包劫持（2021）、colors/faker 作者自毁包（2022）。这些事件说明依赖安全不仅是漏洞管理问题，更涉及软件供应链的信任体系。



SBOM（软件物料清单）
SBOM 是软件中所有组件的完整清单，类似于食品的配料表。美国联邦政府在 2021 年的行政令 14028 中要求所有向联邦机构供应软件的厂商必须提供 SBOM，推动了 SBOM 在全球范围内的普及。

VEX（Vulnerability Exploitability eXchange）是 SBOM 的补充文档，用于说明某个已知漏洞在特定产品中是否实际可被利用。例如 Log4Shell 漏洞虽然影响了使用 Log4j 的项目，但如果项目未使用 JNDI 功能，VEX 文档可以标记该漏洞为"不受影响"。

CVE 编号格式为 CVE-YYYY-NNNNN（如 CVE-2021-44228），由 MITRE 统一分配。NVD 在 CVE 基础上增加了 CVSS 评分、受影响版本范围和参考链接。OSV 的优势在于统一了不同生态系统的漏洞格式，支持通过 package URL（purl）精确查询。

Dependabot 工作流程
Renovate 相比 Dependabot 提供更细粒度的更新策略：可以按包名模式设置自动合并规则、按组批量更新相关依赖、设置更新时间窗口避免在业务高峰期发起变更。对于大型项目，Renovate 的分组更新能力可以将数十个 PR 合并为几个按主题分组的更新。

许可证合规的隐藏风险在于传递依赖：项目直接依赖的包使用 MIT 许可证，但该包的传递依赖可能包含 GPL 组件，从而"传染"整个项目。SCA 工具的许可证扫描功能会递归检查所有层级的依赖许可证，标记存在冲突的组合。常见冲突包括 GPL 与 Apache 2.0 的不兼容、SSPL 对 SaaS 部署的特殊限制等。




小结
    

  • SCA 通过 SBOM 和漏洞数据库实现依赖安全的自动化管理
    • 

  • SBOM 是依赖管理的基础，SPDX 和 CycloneDX 是两大主流格式，VEX 补充可利用性分析
    • 

  • Dependabot/Renovate 实现依赖更新自动化，Renovate 支持更灵活的分组和调度策略
    • 

  • 引入新依赖前必须评估维护活跃度、安全历史和许可证兼容性
    • 

  • 使用 lock 文件锁定版本，私有镜像防止供应链污染
    • 

  • 许可证合规需递归检查传递依赖，警惕 GPL 的"传染"效应
    •
