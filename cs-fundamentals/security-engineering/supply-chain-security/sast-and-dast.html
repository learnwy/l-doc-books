SAST 与 DAST 工具

CI/CD 管道安全概述

CI/CD 管道是软件从代码到生产的自动化通道，也是供应链攻击的高价值目标。攻击者可以通过篡改构建脚本、注入恶意依赖或伪造制品来入侵整个软件交付链。保护 CI/CD 管道的安全是供应链安全的核心环节。



SAST 在 CI/CD 中的集成
SAST（Static Application Security Testing）在不运行代码的前提下分析源码，识别 SQL 注入、XSS、路径遍历等常见漏洞模式。它的核心优势是在代码提交阶段就能发现安全问题，成本远低于运行时修复。

SAST 工具的核心挑战在于误报率（False Positive）。高误报率会导致开发者忽视扫描结果，形成"狼来了"效应。建议初期配置较宽松的规则集，逐步收紧；同时建立误报反馈机制，将确认的误报添加到抑制列表，持续优化扫描精度。




DAST 在 CI/CD 中的集成
DAST（Dynamic Application Security Testing）通过向运行中的应用发送恶意请求来发现漏洞。它模拟真实攻击者的视角，能够发现 SAST 无法检测的运行时问题，如错误的 CORS 配置、不安全的 HTTP 头、会话管理缺陷等。

DAST 扫描通常有两种模式：主动扫描和被动扫描。主动扫描会主动构造恶意输入进行测试，覆盖面广但耗时长；被动扫描作为代理拦截正常测试流量，分析响应中的安全问题，速度快但覆盖有限。在 CI 中推荐将被动扫描嵌入 E2E 测试流程，主动扫描安排在每夜构建中执行。

制品签名与验证
Sigstore 是 CNCF 孵化的软件制品签名框架，提供无密钥的签名和验证能力。






Sigstore 组件
说明





Cosign

Fulcio

Rekor
不可变的签名透明度日志





Sigstore 的核心创新在于"无密钥签名"（Keyless Signing）：开发者通过 OIDC 身份提供商（如 GitHub、Google）进行身份验证，Fulcio 基于验证结果颁发短期证书（有效期仅 20 分钟），签名记录写入 Rekor 透明度日志。这种方式彻底消除了长期密钥管理的负担和泄露风险。

SLSA 框架
SLSA（Supply-chain Levels for Software Artifacts）是 Google 提出的供应链安全成熟度框架。






SLSA 级别
要求





Level 1
构建过程有文档记录




Level 2
使用托管的构建服务，可生成出处声明




Level 3
构建平台经过安全加固，防篡改




Level 4
两人审核，密封构建，依赖完整





SLSA 框架的实施路径建议从 Level 1 起步——为每次构建生成 provenance 文件（记录源码来源、构建命令、依赖版本），然后逐步提升构建环境的隔离性和可验证性。GitHub Actions 和 Google Cloud Build 已原生支持生成 SLSA Level 3 的 provenance 声明。




小结
    

  • SAST 集成到 CI 实现代码安全的自动化检测，推荐增量扫描模式
    • 

  • DAST 在测试环境中模拟攻击，发现运行时安全漏洞
    • 

  • Sigstore/Cosign 提供无密钥的制品签名和验证能力
    • 

  • CI/CD 管道安全需遵循最小权限、不可变环境、密钥隔离三大原则
    • 

  • SLSA 框架提供从 Level 1 到 Level 4 的供应链安全成熟度路线图
    • 

  • SAST 和 DAST 互为补充：SAST 覆盖代码逻辑缺陷，DAST 覆盖运行时配置问题
    •
