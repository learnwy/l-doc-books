类型推导

核心概念

类型推导（Type Inference）是编译器自动确定表达式类型的能力，无需程序员显式标注。当你写 let x = 42 时，编译器能推导出 x 的类型是整数——这就是类型推导在工作。

类型推导的理论基础是 Hindley-Milner（HM）类型系统，它提供了一种算法，能为大多数程序自动找到最一般的类型（Principal Type）。HM 系统最初为 ML 语言家族设计，后来影响了 Haskell、Rust、TypeScript 等众多现代语言。

类型推导在编译器中的位置介于语法分析和代码生成之间。它不仅消除了冗余的类型标注（提高开发者体验），还能发现隐含的类型错误。

合一算法
合一（Unification）是类型推导的核心算法。给定两个类型表达式（可能包含类型变量），合一算法找到一个替换（Substitution），使得两个表达式在替换后变得相同。


例如，合一 List<α> 和 List<Int> 得到替换 {α → Int}。合一 α → β 和 Int → String 得到替换 {α → Int, β → String}。合一 Int 和 String 失败——两个不同的具体类型无法统一。


Robinson 合一算法（1965）是标准实现：


unify(T1, T2):
    T1 = apply(substitution, T1)
    T2 = apply(substitution, T2)

    if T1 == T2: return

    if T1 is TypeVar:
        if T1 occurs in T2: error("infinite type")
        substitution[T1] = T2
        return

    if T2 is TypeVar:
        if T2 occurs in T1: error("infinite type")
        substitution[T2] = T1
        return

    if T1 and T2 are both constructed types:
        if T1.constructor != T2.constructor: error("type mismatch")
        for (a, b) in zip(T1.args, T2.args):
            unify(a, b)

    else: error("type mismatch")
发生检查（Occurs Check）是防止构造无限类型的关键步骤。例如，合一 α 和 List<α> 会产生替换 {α → List<α>}，展开后是 List<List<List<...>>>——一个无限类型。发生检查通过拒绝这种情况来保证类型的有限性。


Hindley-Milner 类型推导
Hindley-Milner（HM）系统是带参数多态的类型推导的黄金标准。它由三个关键组件构成：


    

  1. 类型变量：代表未知类型，在推导过程中被逐步具体化
    2. 

  2. let 多态：let 绑定的表达式可以被泛化为多态类型
    3. 

  3. 合一：通过约束求解确定类型变量的值
    4. 



HM 推导的经典算法是 Algorithm W：


W(Γ, e):
    case e of:
        x (变量):
            return instantiate(Γ(x))

        λx. body (函数):
            α = freshTypeVar()
            τ = W(Γ ∪ {x: α}, body)
            return α → τ

        f(arg) (应用):
            τ_f = W(Γ, f)
            τ_arg = W(Γ, arg)
            α = freshTypeVar()
            unify(τ_f, τ_arg → α)
            return α

        let x = e1 in e2:
            τ1 = W(Γ, e1)
            σ1 = generalize(Γ, τ1)
            return W(Γ ∪ {x: σ1}, e2)
泛化（Generalize）将自由类型变量转换为全称量化类型。例如，identity 的推导类型是 α → α，泛化后变为 ∀α. α → α。每次使用 identity 时，都会实例化（Instantiate）一个新的类型变量。


HM 推导的关键性质：


    

  • 完备性：如果程序有类型，Algorithm W 一定能找到
    • 

  • 主类型性：推导出的类型是最一般的（任何其他合法类型都是它的实例）
    • 

  • 可判定性：推导过程一定终止（但在病态情况下可能指数级慢）
    • 



双向类型检查
双向类型检查（Bidirectional Type Checking）是 HM 推导的实用替代方案。它将类型信息分为两个方向流动：


    

  • 推导模式（Synthesis）：自底向上，从子表达式推导出类型
    • 

  • 检查模式（Checking）：自顶向下，用期望的类型检查表达式
    • 



synthesize(Γ, e) → T:
    case e of:
        42           → Int
        "hello"      → String
        x            → Γ(x)
        f(arg)       → let T_f = synthesize(Γ, f)
                        check(Γ, arg, paramType(T_f))
                        return returnType(T_f)

check(Γ, e, T):
    case (e, T) of:
        (λx.body, A → B) → check(Γ ∪ {x: A}, body, B)
        (if c t e, T)     → check(Γ, c, Bool)
                            check(Γ, t, T)
                            check(Γ, e, T)
        _                 → let T' = synthesize(Γ, e)
                            if T' != T: error
双向检查的优势：


    

  • 只在需要时要求类型标注（例如函数参数类型）
    • 

  • 实现比完整 HM 推导简单得多
    • 

  • 更好的错误消息（知道期望的类型，可以与实际类型对比）
    • 

  • 容易扩展到更复杂的类型特性
    • 



TypeScript、Scala 3、Rust 的类型系统都使用双向检查的变体。Rust 中，你必须标注函数签名的类型（检查模式的入口点），但函数体内的局部变量类型可以自动推导。

约束生成与求解
现代类型推导器通常将过程分为两个阶段：约束生成和约束求解。这种分离使得推导逻辑更清晰、更容易调试。


约束生成阶段遍历 AST，为每个节点生成类型约束：


表达式: x + y * 2

约束生成:
  α_x = typeof(x)        -- 变量 x 的类型
  α_y = typeof(y)        -- 变量 y 的类型
  α_mul = typeof(y * 2)  -- 乘法结果类型
  α_add = typeof(x + ...)-- 加法结果类型

  约束:
  C1: α_y = Int  (因为 * 2 要求左操作数是 Int)
  C2: α_mul = Int (乘法的结果类型)
  C3: α_x = Int  (因为 + 要求左操作数与右操作数同类型)
  C4: α_add = Int (加法的结果类型)
约束求解阶段使用合一算法解这些约束。如果所有约束都能被满足，推导成功；否则报告类型错误。


OCaml 和 Haskell 的编译器使用这种约束生成-求解架构。Rust 的 trait 系统也基于约束求解——trait bound 本质上是对类型的约束。


小结
    

  • 类型推导自动确定表达式类型，减少冗余标注
    • 

  • 合一算法是类型推导的核心，通过替换使两个类型表达式相等
    • 

  • HM 系统提供完备的、具有主类型性的多态类型推导
    • 

  • 双向类型检查结合推导和检查两个方向，更实用且错误消息更好
    • 

  • 约束生成-求解架构将推导分为两个清晰的阶段
    • 

  • 现代语言通常混合使用多种推导策略，在标注负担和推导能力之间平衡
    • 

  • 理解类型推导是掌握高级类型系统（泛型、trait、生命周期）的基础
    •
