作用域与名字绑定

核心概念

作用域（Scope）定义了程序中一个名字（变量、函数、类型等）可见和可访问的区域。名字绑定（Name Binding）是将一个名字与它所代表的实体（变量、函数定义等）关联起来的过程。这两个概念是语义分析中名字解析（Name Resolution）的基础。

编译器在语义分析阶段需要回答的核心问题是：程序中每次使用一个名字时，它指的是哪个定义？这个问题的答案取决于语言的作用域规则。作用域规则的设计直接影响语言的可读性、模块化能力和编译器的实现复杂度。

词法作用域与作用域链
词法作用域（Lexical Scope，也称静态作用域）是现代编程语言的标准选择。在词法作用域中，一个名字的绑定由其在源码文本中的位置决定——内层作用域可以访问外层作用域的名字。


const x = 10;

function outer() {
  const y = 20;

  function inner() {
    const z = 30;
    console.log(x + y + z);
  }

  inner();
}
在上面的例子中，inner 函数可以访问三个变量：


    

  • z 在自己的作用域中定义
    • 

  • y 在外层函数 outer 的作用域中定义
    • 

  • x 在全局作用域中定义
    • 



这种从内到外的查找链称为作用域链（Scope Chain）。


闭包（Closure）是词法作用域的重要产物。当一个函数引用了其定义时（而非调用时）的外层变量，并且该函数可以在外层函数返回后被调用时，就形成了闭包。闭包要求编译器捕获外层变量的引用（或值），这通常通过在堆上分配环境记录来实现。


function makeCounter(): () => number {
  let count = 0;
  return () => {
    count += 1;
    return count;
  };
}
编译器处理闭包时需要：


    

  1. 分析哪些变量被内层函数引用（逃逸分析）
    2. 

  2. 将这些变量从栈上"提升"到堆分配的闭包环境中
    3. 

  3. 在闭包调用时通过环境指针访问这些变量

符号表实现
符号表（Symbol Table）是编译器存储名字绑定信息的核心数据结构。它记录了每个名字的类型、作用域、声明位置等元数据。


符号表的常见实现方式：


嵌套哈希表：每个作用域对应一个哈希表，作用域之间通过父指针链接。查找时先搜索当前作用域的哈希表，未找到则沿父指针向上搜索。


全局作用域 (parent: null)
├── x: Int
├── foo: (Int) → Int
│
└── foo 的作用域 (parent: 全局)
    ├── a: Int (参数)
    │
    └── if 块作用域 (parent: foo)
        └── b: String
作用域栈：使用一个栈来追踪当前的作用域层次。进入新作用域时压栈，退出时弹栈。查找时从栈顶向栈底搜索。


type SymbolTable = {
  scopes: Map<string, SymbolInfo>[]

  enterScope(): void {
    this.scopes.push(new Map())
  }

  exitScope(): void {
    this.scopes.pop()
  }

  define(name: string, info: SymbolInfo): void {
    this.scopes[this.scopes.length - 1].set(name, info)
  }

  lookup(name: string): SymbolInfo | undefined {
    for (let i = this.scopes.length - 1; i >= 0; i--) {
      const info = this.scopes[i].get(name)
      if (info) return info
    }
    return undefined
  }
}

名字解析策略
不同编程语言使用不同的名字解析策略，这些策略直接影响编译器的实现。


前向声明（Forward Declaration）：某些语言要求名字在使用前必须先声明。C 和 Pascal 采用这种策略。编译器可以单遍扫描完成名字解析——遇到名字使用时，当前符号表中一定已经有它的定义。


使用前声明（Declaration Before Use）：同一作用域内，名字可以在声明后的任意位置使用。这是最常见的策略。


声明提升（Hoisting）：JavaScript 的 var 和函数声明会被"提升"到所在作用域的顶部。这意味着编译器需要两遍扫描——第一遍收集声明，第二遍解析引用。


console.log(x);
var x = 42;
相互递归（Mutual Recursion）：某些语言允许函数或类型相互引用，无需前向声明。Haskell、OCaml（let rec ... and ...）和 Rust（同一模块内的项）支持这种特性。编译器需要在解析名字前先收集同一作用域内的所有声明。


模块系统与可见性
模块系统将作用域的概念扩展到文件和包的层次。它定义了名字如何在模块间共享和隐藏。


导入/导出模型（如 JavaScript/TypeScript 的 ESM）：模块通过 export 显式声明公开的名字，通过 import 引入外部模块的名字。编译器需要在模块图的层面上进行名字解析。


可见性修饰符（如 Rust 的 pub、Java 的 public/private/protected）：在同一编译单元内，通过修饰符控制名字的可访问范围。


Rust 可见性层次:
- pub         → 完全公开
- pub(crate)  → 本 crate 可见
- pub(super)  → 父模块可见
- pub(in path)→ 指定路径可见
- (默认)       → 仅当前模块可见
模块系统对编译器的挑战包括：


    

  • 循环依赖：模块 A 导入 B，B 又导入 A
    • 

  • 名字冲突：两个模块导出同名的符号
    • 

  • 延迟解析：模块的类型可能依赖于另一个模块的类型
    •

小结
    

  • 作用域定义了名字的可见区域，词法作用域是现代语言的标准选择
    • 

  • 符号表是编译器存储名字绑定信息的核心数据结构
    • 

  • 名字解析策略（前向声明、提升、相互递归）决定了编译器需要几遍扫描
    • 

  • 闭包是词法作用域的产物，编译器需要逃逸分析和环境捕获来实现它
    • 

  • 模块系统将作用域扩展到文件/包层次，引入了循环依赖等新挑战
    • 

  • 作用域和名字解析的正确性是编译器语义分析阶段的基石
    •
