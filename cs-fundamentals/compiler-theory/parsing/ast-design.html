抽象语法树设计

核心概念

抽象语法树（Abstract Syntax Tree, AST）是源代码的树形结构化表示。与具体语法树（CST/解析树）不同，AST 省略了语法上必要但语义上无关的元素——括号、分号、逗号等标点符号被丢弃，只保留程序的语义骨架。

AST 是编译器前端和后端之间的核心接口。语法分析器生成 AST，语义分析器在 AST 上进行类型检查和名字解析，代码生成器从 AST 出发生成中间表示或目标代码。AST 的设计质量直接影响后续所有阶段的实现复杂度。

AST 节点类型设计
AST 的核心是节点类型系统。每种语法结构对应一种节点类型，节点之间的父子关系反映了程序的层次结构。


常见的 AST 节点类型体系：


type Program = {
  type: 'Program';
  body: Statement[];
};

type Statement =
  | ExpressionStatement
  | IfStatement
  | WhileStatement
  | ReturnStatement
  | FunctionDeclaration
  | VariableDeclaration
  | BlockStatement;

type Expression =
  | BinaryExpression
  | UnaryExpression
  | CallExpression
  | MemberExpression
  | Identifier
  | NumericLiteral
  | StringLiteral
  | AssignmentExpression;

type BinaryExpression = {
  type: 'BinaryExpression';
  operator: '+' | '-' | '*' | '/' | '==' | '!=';
  left: Expression;
  right: Expression;
};

type IfStatement = {
  type: 'IfStatement';
  test: Expression;
  consequent: BlockStatement;
  alternate: BlockStatement | IfStatement | null;
};

type FunctionDeclaration = {
  type: 'FunctionDeclaration';
  name: Identifier;
  params: Identifier[];
  returnType: TypeAnnotation | null;
  body: BlockStatement;
};
节点类型设计的几个关键原则：


表达式与语句分离。表达式（Expression）产生值，语句（Statement）执行动作。在 AST 中区分二者有助于类型检查——类型系统只需要处理表达式节点。


使用联合类型（Tagged Union）。每个节点有一个 type 字段作为判别标签。这使得 AST 遍历可以通过 switch(node.type) 实现类型安全的分派。


可选字段用 null/undefined。例如 IfStatement.alternate 可以是 null（没有 else 分支）。这比为每种组合创建不同的节点类型更简洁。


位置信息与源码映射
AST 节点需要携带源码位置信息，用于：


    

  • 编译错误和警告的精确定位
    • 

  • IDE 的跳转和高亮功能
    • 

  • Source Map 生成（用于调试转译后的代码）
    • 



位置信息通常包含起始和结束位置：


type SourceLocation = {
  start: Position;
  end: Position;
  source?: string;
};

type Position = {
  line: number;
  column: number;
  offset: number;
};

type BaseNode = {
  type: string;
  loc: SourceLocation;
  range?: [number, number];
};
ESTree 规范是 JavaScript AST 的事实标准。Babel、ESLint、Prettier 等工具都遵循 ESTree，这使得它们可以共享 AST。ESTree 定义了每种 JS 语法结构的精确节点类型和字段。


Span/Range 表示法比行列号更适合内部处理。span 是源码中的字节偏移范围 [start, end)。行列号需要时可以从 span 和源码文本反算，避免在每个节点上存储冗余信息。


访问者模式与 AST 遍历
AST 的遍历和变换是编译器最频繁的操作。 访问者模式（Visitor Pattern）是实现 AST 遍历的标准设计模式。


type Visitor = {
  visitBinaryExpression?: (node: BinaryExpression) => void;
  visitIfStatement?: (node: IfStatement) => void;
  visitIdentifier?: (node: Identifier) => void;
  // ... 每种节点类型一个方法
};

function traverse(node: ASTNode, visitor: Visitor): void {
  const method = visitor[`visit${node.type}`];
  if (method) method(node);

  for (const child of getChildren(node)) {
    traverse(child, visitor);
  }
}
访问者模式有两个变体：


前序遍历（Pre-order）：先访问当前节点，再递归访问子节点。适用于收集信息、构建符号表。


后序遍历（Post-order）：先递归访问子节点，再访问当前节点。适用于类型推导（子表达式的类型决定父表达式的类型）。


Babel 的插件系统就是基于访问者模式构建的。每个 Babel 插件定义一组 visitor 方法，可以在遍历过程中修改 AST 节点。这使得代码转换的编写变得模块化——每个插件只关注自己负责的语法结构。


AST 变换与不可变性
AST 变换是编译器和代码工具的核心操作。两种主要策略是就地修改（In-Place Mutation）和不可变变换（Immutable Transformation）。


就地修改直接修改 AST 节点的属性。优点是简单高效，缺点是修改可能影响其他引用同一节点的代码。


不可变变换创建新节点代替旧节点。每次变换产生一棵新的 AST（共享未修改的子树）。这使得变换可以安全地组合，不会产生意外的副作用。


function constantFold(node: Expression): Expression {
  if (node.type !== 'BinaryExpression') return node;

  const left = constantFold(node.left);
  const right = constantFold(node.right);

  if (left.type === 'NumericLiteral' && right.type === 'NumericLiteral') {
    return {
      type: 'NumericLiteral',
      value: evaluate(node.operator, left.value, right.value),
      loc: node.loc,
    };
  }

  return { ...node, left, right };
}
上面的常量折叠示例展示了不可变变换的典型模式。递归处理子节点，如果可以求值就返回新的字面量节点，否则返回包含新子节点的新父节点。


Rust 编译器（rustc）的 AST 变换大量使用这种模式。函数式语言编译器（如 GHC）天然适合不可变 AST，因为不可变数据结构是语言的基础。


实际 AST 设计案例
不同编译器的 AST 设计反映了各自的设计哲学：


Babel AST（ESTree 风格）：


    

  • 节点类型丰富（70+ 种）
    • 

  • 每个节点包含完整的位置信息
    • 

  • 松散类型（JavaScript 对象）
    • 

  • 优化可读性和易修改性
    • 



Rust 编译器 AST：


    

  • 强类型（Rust enum 建模联合类型）
    • 

  • 使用 NodeId 和 Span 标识
    • 

  • AST → HIR → MIR 多层降低
    • 

  • 每层 IR 删除更多语法糖
    • 



TypeScript AST：


    

  • 所有节点继承 Node 基类
    • 

  • 使用 SyntaxKind 枚举区分类型
    • 

  • 保留完整的 trivia（空白和注释）
    • 

  • 支持增量解析
    •

小结
    

  • AST 是源码的语义骨架，省略了标点等语法噪音
    • 

  • 节点类型使用联合类型（Tagged Union）设计，便于类型安全的模式匹配
    • 

  • 位置信息对错误报告和 IDE 功能至关重要
    • 

  • 访问者模式是 AST 遍历和变换的标准设计模式
    • 

  • 不可变变换比就地修改更安全，适合多阶段编译流水线
    • 

  • 工业级编译器通常有多层 AST/IR（如 rustc 的 AST → HIR → MIR）
    • 

  • AST 设计需要在表达力、性能和易用性之间找到平衡
    •
