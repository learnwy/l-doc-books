自顶向下解析

核心概念

自顶向下解析（Top-Down Parsing）从文法的起始符号出发，尝试通过反复应用产生式规则来推导出输入的 token 序列。解析过程构造的是一棵最左推导的解析树——从根节点（起始符号）开始，逐步展开左侧的非终结符，直到叶节点全部匹配输入 token。

自顶向下解析的核心挑战是预测问题：面对当前非终结符和下一个输入 token，如何选择正确的产生式？如果每一步都能确定唯一的产生式，就是确定性的自顶向下解析。否则就需要回溯。

实践中，递归下降（Recursive Descent）是最常用的自顶向下解析技术。手写编译器几乎都采用递归下降，因为它直觉、灵活、容易实现高质量的错误恢复。

递归下降解析器
递归下降解析器为文法中的每个非终结符定义一个解析函数。每个函数根据当前的前看 token 决定使用哪条产生式，然后按产生式右部的顺序调用其他解析函数或匹配终结符。


以算术表达式文法为例：


expr   → term (("+" | "-") term)*
term   → factor (("*" | "/") factor)*
factor → "(" expr ")" | NUMBER | IDENT
对应的递归下降代码：


function parseExpr(): ASTNode {
  let left = parseTerm();
  while (current() === PLUS || current() === MINUS) {
    const op = advance();
    const right = parseTerm();
    left = { type: 'BinaryExpr', op, left, right };
  }
  return left;
}

function parseTerm(): ASTNode {
  let left = parseFactor();
  while (current() === STAR || current() === SLASH) {
    const op = advance();
    const right = parseFactor();
    left = { type: 'BinaryExpr', op, left, right };
  }
  return left;
}

function parseFactor(): ASTNode {
  if (current() === LPAREN) {
    advance();
    const expr = parseExpr();
    expect(RPAREN);
    return expr;
  }
  if (current() === NUMBER) return { type: 'NumLit', value: advance() };
  if (current() === IDENT) return { type: 'Ident', name: advance() };
  throw new ParseError('unexpected token');
}
注意这个实现使用了循环代替左递归。原始文法 E → E + T | T 是左递归的，直接翻译为递归函数会导致无限递归。消除左递归后改写为 E → T (+ T)*，然后用 while 循环实现重复部分。


递归下降的优势在于代码即文法——解析函数的结构直接映射文法规则。这使得阅读、调试和修改解析器变得非常自然。


FIRST 集与 FOLLOW 集
LL 解析器通过 FIRST 和 FOLLOW 集来确定性地选择产生式。


FIRST(α) 是符号串 α 可能推导出的所有第一个终结符的集合。如果 α 可以推导出空串 ε，则 ε ∈ FIRST(α)。


FOLLOW(A) 是非终结符 A 之后可能出现的所有终结符的集合。如果 A 可以出现在输入末尾，则 ∈FOLLOW(A)（∈ FOLLOW(A)（∈FOLLOW(A)（ 表示输入结束符）。


计算规则：


FIRST 集计算:
- 终结符 a: FIRST(a) = {a}
- 产生式 A → a...: a ∈ FIRST(A)
- 产生式 A → B...: FIRST(B) ⊆ FIRST(A)
- 产生式 A → ε: ε ∈ FIRST(A)
- 产生式 A → B₁B₂...Bₙ: 如果 ε ∈ FIRST(B₁...Bᵢ₋₁)，
  则 FIRST(Bᵢ) \ {ε} ⊆ FIRST(A)

FOLLOW 集计算:
- $ ∈ FOLLOW(S)  (S 是起始符号)
- 产生式 A → αBβ: FIRST(β) \ {ε} ⊆ FOLLOW(B)
- 产生式 A → αB 或 A → αBβ 且 ε ∈ FIRST(β):
  FOLLOW(A) ⊆ FOLLOW(B)
FIRST 和 FOLLOW 集用于构造 LL(1) 解析表：对产生式 A → α，将其填入表格 M[A, t] 中所有 t ∈ FIRST(α) 的位置。如果 ε ∈ FIRST(α)，还要填入 M[A, t] 中所有 t ∈ FOLLOW(A) 的位置。


如果任何表格项有多个产生式，则文法不是 LL(1) 的。


LL(1) 解析表与驱动程序
LL(1) 解析器使用预测解析表 M 和一个显式的栈来模拟最左推导过程。"LL(1)"含义：从Left 到右扫描输入，构造Leftmost 推导，使用 1 个前看符号。


LL(1) 驱动程序:

stack = [S, $]
input = token 序列 + $

while stack.top() != $:
    X = stack.top()
    a = current input token

    if X == a:                    // 终结符匹配
        stack.pop()
        advance()
    else if X 是终结符:           // 不匹配
        error()
    else if M[X, a] == X → Y₁Y₂...Yₖ:  // 查表
        stack.pop()
        push Yₖ, ..., Y₂, Y₁   // 逆序压栈
    else:
        error()

LL(1) 的限制是只看一个前看符号，这导致很多实用文法不是 LL(1) 的。例如 C 语言中的声明和表达式语句在语法上共享前缀 IDENT。


LL(k) 与 ALL(*) 解析
为了克服 LL(1) 的限制，可以增加前看符号的数量。


LL(k) 使用 k 个前看符号。解析表的列从单个 token 扩展为 k 个 token 的序列。k 增大使得更多文法可以被确定性解析，但解析表的大小以 |Σ|^k 增长。


LL(*) 是 ANTLR 3 引入的概念，允许根据需要前看任意多个 token。当有限个前看符号不够时，LL(*) 会在多条候选产生式的前缀上构造 DFA 来选择。


ALL(*) （Adaptive LL()）是 ANTLR 4 的核心算法，进一步增强了 LL()。ALL(*) 在运行时动态分析输入来选择产生式，缓存分析结果供后续使用。它能处理包括间接左递归在内的几乎所有上下文无关文法（通过自动改写左递归）。

Pratt 解析与运算符优先级
Pratt 解析（也称为优先级攀升解析）是处理表达式中运算符优先级和结合性的优雅技术。它是递归下降的变体，核心思想是为每个运算符分配一个绑定力（Binding Power）。


Pratt 解析只需要一个主解析函数，通过绑定力控制递归深度：


function parseExpression(minBP: number): ASTNode {
  let left = parsePrefix();

  while (true) {
    const op = current();
    const bp = getInfixBP(op);
    if (bp === undefined || bp.left < minBP) break;

    advance();
    const right = parseExpression(bp.right);
    left = { type: 'BinaryExpr', op, left, right };
  }
  return left;
}

// 绑定力定义
// 左结合: left < right (如 +: left=1, right=2)
// 右结合: left > right (如 =: left=4, right=3)
Pratt 解析的优势是优先级和结合性通过数值配置，添加新运算符只需添加一条配置。这比为每个优先级层级创建独立的解析函数（如 parseExpr、parseTerm、parseFactor）更灵活。


许多现代编译器在表达式解析部分使用 Pratt 技术。Rust 编译器（rustc）的表达式解析就采用了优先级攀升方法。


小结
    

  • 自顶向下解析从起始符号出发构造最左推导
    • 

  • 递归下降是最实用的自顶向下技术，主流编译器均采用
    • 

  • FIRST 和 FOLLOW 集用于确定性地选择产生式
    • 

  • LL(1) 只看一个前看符号，限制较多但实现简单
    • 

  • ALL(*) 通过自适应运行时分析几乎能处理所有 CFG
    • 

  • Pratt 解析通过绑定力优雅地处理运算符优先级
    • 

  • 自顶向下解析的错误恢复通常比自底向上解析更容易实现
    • 

  • 手写递归下降 + Pratt 表达式解析是工业级编译器的主流组合
    •
