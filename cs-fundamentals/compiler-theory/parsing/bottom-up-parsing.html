自底向上解析

核心概念

自底向上解析（Bottom-Up Parsing）从输入的 token 序列出发，逐步将 token 组合（归约）为更高层次的语法结构，最终归约到起始符号。这个过程构造的是最右推导的逆过程——从叶节点开始向上构建解析树。

与自顶向下解析相比，自底向上解析能处理更大的文法类——LR 文法严格包含 LL 文法。LR 解析是自底向上解析的主要代表，它是大多数解析器生成器（如 yacc/bison）的理论基础。

自底向上解析的核心操作只有两个：移入（Shift，将下一个 token 压入栈）和归约（Reduce，将栈顶的符号序列替换为产生式左部的非终结符）。

移入-归约解析
移入-归约解析器使用一个栈和一个输入缓冲区。解析器在每一步执行四种动作之一：


    

  1. 移入（Shift）：将下一个输入 token 移入栈顶
    2. 

  2. 归约（Reduce）：将栈顶的 n 个符号（匹配某产生式右部）替换为该产生式的左部
    3. 

  3. 接受（Accept）：栈中只剩起始符号，输入已消耗完毕
    4. 

  4. 报错（Error）：无法执行任何合法动作
    5. 



以文法 E → E + T | T, T → T * F | F, F → ( E ) | id 解析 id + id * id：


栈              输入            动作
$               id + id * id $  移入
$ id            + id * id $     归约 F → id
$ F             + id * id $     归约 T → F
$ T             + id * id $     归约 E → T
$ E             + id * id $     移入
$ E +           id * id $       移入
$ E + id        * id $          归约 F → id
$ E + F         * id $          归约 T → F
$ E + T         * id $          移入
$ E + T *       id $            移入
$ E + T * id    $               归约 F → id
$ E + T * F     $               归约 T → T * F
$ E + T         $               归约 E → E + T
$ E             $               接受
关键观察：归约 T → T * F 发生在归约 E → E + T 之前。这正确地反映了 * 的优先级高于 +。自底向上解析器通过延迟归约来自然地处理运算符优先级。


LR(0) 项与项集
LR 解析器的核心构造是项（Item）和项集（Item Set）。一个 LR(0) 项是在产生式右部的某个位置放置一个点（·），表示解析的进度。


例如产生式 E → E + T 有四个 LR(0) 项：


E → · E + T    (尚未开始识别)
E → E · + T    (已识别 E，期望 +)
E → E + · T    (已识别 E +，期望 T)
E → E + T ·    (完全识别，可以归约)
项集是一组项的集合，表示解析器在某一时刻的所有可能状态。构造项集时需要计算闭包（Closure）：如果项集中包含 A → α · Bβ，则需要将 B 的所有产生式以 B → · γ 的形式加入。


GOTO 函数定义了项集之间的转移：GOTO(I, X) 是项集 I 中所有 A → α · Xβ 形式的项，将点移过 X 后的项集的闭包。


所有项集及其 GOTO 关系构成了 LR(0) 自动机。这个自动机是 LR 解析表的基础。


SLR、LALR 与 LR(1) 解析
基于 LR(0) 自动机，可以构造不同精度的解析表。三种主要的 LR 解析方法按能力递增排列：SLR < LALR < LR(1)。


SLR（Simple LR）在构造解析表时，对归约项 A → α· 使用 FOLLOW(A) 来决定在哪些前看符号下执行归约。SLR 简单但能力有限——某些无二义文法仍会产生冲突。


LR(1) 在项中加入前看符号，构成 LR(1) 项 [A → α · β, a]。前看符号 a 精确地指定了在哪个 token 下执行归约。LR(1) 项集的数量远大于 LR(0)（通常大 10 倍以上），导致解析表很大。


LALR(1)（Look-Ahead LR）是 LR(1) 的压缩版本。它将具有相同核心（忽略前看符号后相同的）LR(1) 项集合并。LALR(1) 的解析表大小与 SLR 相同，但解析能力接近 LR(1)。yacc/bison 生成的就是 LALR(1) 解析器。

冲突处理与优先级声明
LR 解析表构造过程中可能出现两类冲突：


移入-归约冲突（Shift-Reduce Conflict）：某个状态下，既可以移入下一个 token，又可以执行归约。经典案例是 if-then-else 的悬挂 else 问题。


归约-归约冲突（Reduce-Reduce Conflict）：某个状态下，可以用两条不同的产生式执行归约。这通常意味着文法设计有问题。


yacc/bison 提供了优先级和结合性声明来解决移入-归约冲突：


%left '+' '-'
%left '*' '/'
%right '='
%nonassoc '<' '>' EQ NEQ
%left 声明左结合，遇到移入-归约冲突时选择归约。 %right 声明右结合，遇到冲突时选择移入。优先级由声明顺序决定，后声明的优先级更高。


对于悬挂 else，标准做法是声明 else 优先于 then（选择移入），使 else 关联最近的 if。


%nonassoc THEN
%nonassoc ELSE   // ELSE 优先级高于 THEN → 移入 ELSE

GLR 解析
GLR（Generalized LR）解析是 LR 解析的扩展，能处理二义文法。当遇到冲突时，GLR 不是报错，而是分裂解析栈，同时沿所有可能的路径继续解析。


GLR 使用图结构栈（Graph-Structured Stack, GSS）来高效地表示多条并行的解析路径。当两条路径最终归约到相同状态时，它们被合并回一个栈。


GLR 的时间复杂度对无二义文法是 O(n)，对二义文法是 O(n³)。它特别适用于需要容忍二义性的场景，例如：


    

  • 自然语言处理（NLP）中的句法分析
    • 

  • C++ 的解析（模板和类型名导致的歧义）
    • 

  • 语言原型设计（先写二义文法，后消歧）
    • 



Bison 的 %glr-parser 指令可以启用 GLR 模式。tree-sitter 也使用 GLR 技术来处理实际编程语言中的歧义情况。


小结
    

  • 自底向上解析从 token 出发逐步归约到起始符号
    • 

  • LR 解析器通过状态机和栈实现确定性的移入-归约操作
    • 

  • LR(0) 项和项集构成了 LR 解析表的基础
    • 

  • LALR(1) 是实践中最常用的 LR 变体，yacc/bison 生成 LALR 解析器
    • 

  • 优先级和结合性声明可以解决大部分移入-归约冲突
    • 

  • GLR 解析通过栈分裂处理二义文法，适用于 NLP 和复杂语言
    • 

  • LR 解析能力严格强于 LL，但错误恢复和调试相对困难
    • 

  • 工业界趋势是手写递归下降（自顶向下）取代生成器驱动的 LR 解析
    •
