解析器生成器

核心概念

解析器生成器（Parser Generator）是一种工具，它读取文法的声明式描述，自动生成语法分析器的源代码。开发者只需编写文法规则和语义动作，解析器生成器负责构造解析表和驱动程序。

解析器生成器是编译器自动化的核心组件。它将形式语言理论（CFG、LR 解析）转化为可执行的工程工具，极大降低了构建语法分析器的门槛。

从 1970 年代的 yacc 到今天的 ANTLR 4 和 tree-sitter，解析器生成器经历了半个世纪的演进。每一代工具都在解析能力、可用性和性能之间做出不同的权衡。

yacc/bison 的文法格式
yacc（Yet Another Compiler Compiler）于 1975 年由 Stephen Johnson 在贝尔实验室开发。bison 是 GNU 版本的 yacc，功能更强（支持 GLR、位置跟踪等）。


yacc/bison 的输入文件分为三段，用 %% 分隔：


%{
/* C 声明 */
#include "ast.h"
%}

%token IDENT NUMBER STRING
%token IF ELSE WHILE RETURN
%token PLUS MINUS STAR SLASH
%token EQ NEQ GE LE

%left PLUS MINUS
%left STAR SLASH
%right ASSIGN

%%

program
    : declaration_list
    ;

declaration_list
    : declaration
    | declaration_list declaration
    ;

expression
    : expression PLUS expression   { $$ = make_binop('+', $1, $3); }
    | expression STAR expression   { $$ = make_binop('*', $1, $3); }
    | IDENT                        { $$ = make_ident($1); }
    | NUMBER                       { $$ = make_number($1); }
    | '(' expression ')'           { $$ = $2; }
    ;

%%
/* C 用户代码 */
$1、$2、$3 引用产生式右部的语义值。 `


` 是产生式左部的语义值。 `%left`、`%right` 声明解决移入-归约冲突。

bison 生成一个 `yyparse()` 函数，内部包含 LALR(1) 解析表和移入-归约驱动循环。它调用 `yylex()` 获取下一个 token（通常由 flex 生成）。

## ANTLR 4 的文法格式

ANTLR（ANother Tool for Language Recognition）是当前最流行的解析器生成器。ANTLR 4 使用 ALL(\*) 算法，能处理几乎所有上下文无关文法。

```
grammar Expr;

program : statement+ ;

statement
    : ifStmt
    | whileStmt
    | exprStmt
    | returnStmt
    ;

ifStmt : 'if' '(' expr ')' block ('else' block)? ;
whileStmt : 'while' '(' expr ')' block ;
block : '{' statement* '}' ;

expr : expr ('*' | '/') expr       # MulDiv
     | expr ('+' | '-') expr       # AddSub
     | expr ('==' | '!=') expr     # Compare
     | IDENT '(' exprList? ')'     # FuncCall
     | IDENT                       # Identifier
     | NUMBER                      # Number
     | '(' expr ')'                # Parens
     ;

exprList : expr (',' expr)* ;

IDENT  : [a-zA-Z_][a-zA-Z0-9_]* ;
NUMBER : [0-9]+ ('.' [0-9]+)? ;
WS     : [ \t\r\n]+ -> skip ;
```

ANTLR 4 的关键特性：

- **自动左递归改写**：上面的 `expr` 规则是左递归的，ANTLR 4 自动将其改写为优先级攀升
- **标签**（`# MulDiv` 等）为每个备选项生成独立的 visitor/listener 方法
- **skip 通道**：`-> skip` 丢弃空白但保留在 token 流中供错误恢复使用
- **生成 Visitor 和 Listener**：两种遍历模式供选择

ANTLR 4 vs yacc/bison 的核心区别在于解析方向：

| 特性     | yacc/bison (LR) | ANTLR 4 (LL)     |
| -------- | --------------- | ---------------- |
| 解析方向 | 自底向上        | 自顶向下         |
| 左递归   | 天然支持        | 自动改写         |
| 语义动作 | 嵌入式 ($1,
) | Visitor/Listener |
| 错误恢复 | 较弱            | 强大的自动恢复   |
| 调试能力 | 弱              | 强（ANTLRWorks） |


PEG 与 Packrat 解析
PEG（Parsing Expression Grammar）是 Bryan Ford 于 2004 年提出的一种文法形式。与 CFG 的关键区别在于 PEG 的选择运算符 / 是有序的——尝试第一个备选项，只在失败时才尝试第二个。


expr    <- term (('+' / '-') term)*
term    <- factor (('*' / '/') factor)*
factor  <- '(' expr ')' / number / ident
number  <- [0-9]+
ident   <- [a-zA-Z_][a-zA-Z0-9_]*
PEG 的有序选择消除了文法的二义性（因为总是选第一个成功的匹配）。但这也意味着规则的书写顺序会影响语义——交换两个备选项可能改变匹配结果。


Packrat 解析是 PEG 的高效实现，通过记忆化（Memoization）保证 O(n) 的线性时间。它缓存每个 (规则, 位置) 对的解析结果，避免重复计算。代价是 O(n × |G|) 的内存开销（|G| 是规则数量）。


PEG/Packrat 的优势是简单、无歧义、线性时间。劣势是左递归处理复杂、错误信息质量较差、内存消耗大。


tree-sitter 与增量解析
tree-sitter 是一种新型的解析框架，专为代码编辑器设计。它的核心特性是增量解析——当用户编辑代码时，只重新解析受影响的部分。


tree-sitter 的文法用 JavaScript DSL 编写：


module.exports = grammar({
  name: 'example',
  rules: {
    program: ($) => repeat($.statement),
    statement: ($) => choice($.if_statement, $.expression_statement),
    if_statement: ($) => seq('if', '(', $.expression, ')', $.block, optional(seq('else', $.block))),
    expression: ($) =>
      choice(
        prec.left(1, seq($.expression, '+', $.expression)),
        prec.left(2, seq($.expression, '*', $.expression)),
        $.identifier,
        $.number,
      ),
  },
});
tree-sitter 使用 GLR 算法处理二义文法（通过 prec 声明消歧）。增量解析的关键是维护一棵具体语法树（CST），编辑时只需要重新构建受影响的子树。


tree-sitter 在 IDE 领域的影响深远：


    

  • 语法高亮：基于解析树的精确高亮，替代正则匹配
    • 

  • 代码折叠：基于 AST 节点的结构化折叠
    • 

  • 符号大纲：从解析树提取函数/类定义
    • 

  • 错误容忍：即使代码有语法错误也能产生部分解析树
    • 



小结
    

  • 解析器生成器将文法声明自动转化为可执行的语法分析器
    • 

  • yacc/bison 是 LALR 的经典实现，侧重性能和 C 集成
    • 

  • ANTLR 4 使用 ALL(*) 算法，易用性和解析能力都很强
    • 

  • PEG 通过有序选择消除二义性，Packrat 保证线性时间
    • 

  • tree-sitter 的增量解析能力使其成为 IDE 场景的首选
    • 

  • 选择工具取决于目标语言的复杂度、性能需求和生态集成
    • 

  • 现代趋势是手写解析器 + 生成器辅助的混合方案
    •
