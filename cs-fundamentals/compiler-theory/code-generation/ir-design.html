中间表示设计

核心概念

中间表示（Intermediate Representation, IR）是编译器在源语言和目标机器码之间使用的内部数据结构。IR 是编译器架构的核心抽象层——它将前端（语法分析、语义分析）与后端（优化、代码生成）解耦。一个好的 IR 设计能让编译器同时支持多种源语言和多种目标架构。

IR 的层次通常介于 AST（高层、接近源码）和机器码（低层、接近硬件）之间。许多现代编译器使用多层 IR：每一层删除更多的高层抽象，逐步向机器码靠近。

SSA 形式
静态单赋值形式（Static Single Assignment, SSA）是现代编译器 IR 的核心设计。在 SSA 形式中，每个变量只被赋值一次。当原始程序中一个变量被多次赋值时，SSA 会为每次赋值创建不同的版本。


原始代码:              SSA 形式:
x = 1                 x₁ = 1
x = x + 1             x₂ = x₁ + 1
y = x * 2             y₁ = x₂ * 2
当控制流汇合时（如 if-else 的合并点），需要使用 φ 函数（Phi Function）来选择来自不同路径的值：


原始代码:              SSA 形式:
if (cond)              if (cond)
  x = 1                 x₁ = 1
else                   else
  x = 2                 x₂ = 2
y = x + 3             x₃ = φ(x₁, x₂)
                       y₁ = x₃ + 3
φ 函数 φ(x₁, x₂) 的语义是：如果控制流从 then 分支到达，取 x₁；如果从 else 分支到达，取 x₂。


SSA 的关键优势在于简化了数据流分析：


    

  • 到达定义：每个使用点只有一个定义到达，无需计算复杂的到达定义集
    • 

  • 常量传播：直接检查定义处是否为常量
    • 

  • 死代码消除：没有使用者的定义可以安全删除
    • 

  • 寄存器分配：变量的生命周期不重叠时可以共享寄存器
    • 



LLVM IR、GCC GIMPLE、Java HotSpot 的 Sea of Nodes 都是 SSA 形式的 IR。


控制流图
控制流图（Control Flow Graph, CFG）是 IR 中表示程序执行流程的图结构。CFG 的节点是基本块（Basic Block），边是控制流转移。


基本块是一个顺序执行的指令序列，满足：


    

  • 只有第一条指令可以被外部跳转到
    • 

  • 只有最后一条指令可以跳转到其他基本块
    • 



function gcd(a, b):
  while b != 0:
    t = a % b
    a = b
    b = t
  return a
CFG 上的重要概念：


支配关系（Dominance）：如果从入口到节点 B 的所有路径都必须经过节点 A，则 A 支配 B。支配树是优化分析的基础数据结构。


支配边界（Dominance Frontier）：节点 A 的支配边界是 A 所支配区域的"边缘"节点集合。SSA 构造算法使用支配边界来确定 φ 函数的插入位置。


LLVM IR 设计
LLVM IR 是当前最有影响力的编译器 IR 设计。它是一种类型化的、SSA 形式的、接近汇编但与目标架构无关的低层 IR。


LLVM IR 有三种等价表示：人可读的文本格式（.ll）、内存中的 C++ 对象、紧凑的二进制位码（.bc）。


define i32 @factorial(i32 %n) {
entry:
  %cmp = icmp eq i32 %n, 0
  br i1 %cmp, label %base, label %recurse

base:
  ret i32 1

recurse:
  %n_minus_1 = sub i32 %n, 1
  %result = call i32 @factorial(i32 %n_minus_1)
  %product = mul i32 %n, %result
  ret i32 %product
}
LLVM IR 的关键设计决策：


强类型：每个值都有明确的类型（i32、i64、float、指针等）。类型信息帮助优化器做出更好的决策。


显式控制流：使用 br（分支）和 switch 指令，没有隐式的 fall-through。每个基本块以终结器指令（terminator）结束。


无限虚拟寄存器：LLVM IR 使用无限数量的虚拟寄存器（%0、%1、%name）。实际的寄存器分配由后端负责。


目标无关：LLVM IR 不绑定特定的目标架构。同一份 IR 可以被编译到 x86、ARM、RISC-V 等不同架构。

三地址码与栈式 IR
除了 SSA 形式，还有两种经典的 IR 风格：


三地址码（Three-Address Code）是 IR 的经典形式。每条指令最多包含三个操作数：一个目标和两个源。


三地址码示例 (a = b * c + d):

t1 = b * c
t2 = t1 + d
a = t2
三地址码简单直观，是教科书中最常见的 IR 形式。GCC 的 GIMPLE 就是三地址码的变体。


栈式 IR（Stack-Based IR）使用隐式的操作数栈。指令从栈顶弹出操作数，将结果压入栈顶。


栈式 IR 示例 (a = b * c + d):

push b
push c
mul        // 弹出 b, c; 压入 b*c
push d
add        // 弹出 b*c, d; 压入 b*c+d
store a    // 弹出结果; 存入 a
Java Bytecode 和 WebAssembly（部分）使用栈式 IR。栈式 IR 的优点是指令编码紧凑（无需指定操作数名字），缺点是优化困难（操作数之间的关系是隐式的）。

小结
    

  • IR 是编译器前端和后端之间的核心抽象层
    • 

  • SSA 形式通过单赋值和 φ 函数简化了几乎所有的数据流分析
    • 

  • 控制流图的基本块和支配关系是优化分析的基础
    • 

  • LLVM IR 是当前最有影响力的 IR 设计，兼具类型安全和目标无关性
    • 

  • 不同 IR 风格（寄存器式、三地址码、栈式）在紧凑性和可优化性之间做出权衡
    • 

  • 多层 IR 设计允许在每一层应用最适合该抽象级别的优化
    •
