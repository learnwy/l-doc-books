优化遍

核心概念

优化遍（Optimization Pass）是编译器对中间表示执行的一系列变换操作，目的是在保持程序语义不变的前提下提升执行性能或减小代码体积。每个优化遍专注于一种特定的优化模式，多个遍按特定顺序组合形成优化流水线。

优化是编译器中最复杂、也最有价值的部分。一个好的优化器可以将程序的运行速度提升数倍甚至数十倍。LLVM 的优化流水线包含超过 100 个独立的优化遍。

优化的正确性至关重要——任何改变程序可观察行为的"优化"都是 bug。因此，每个优化遍都必须有严格的安全性证明或充分的测试覆盖。

常量传播与常量折叠
常量折叠（Constant Folding）在编译期计算常量表达式的值：


优化前:                 优化后:
x = 3 + 4              x = 7
y = x * 2              y = 14
常量传播（Constant Propagation）将变量替换为其已知的常量值。在 SSA 形式中，常量传播特别高效——每个变量只有一个定义，如果定义处是常量，则所有使用处都可以替换。


条件常量传播（Conditional Constant Propagation, CCP）是更强大的变体。它同时执行常量传播和不可达代码消除：


x = 3
if (x > 5)      // 常量折叠: 3 > 5 = false
  y = x + 1     // 不可达，删除
else
  y = x - 1     // 常量传播: y = 3 - 1 = 2
z = y * 2       // z = 2 * 2 = 4
CCP 使用格理论（Lattice Theory）来追踪每个变量的状态：


每个变量从 ⊤（未知）开始。如果发现它总是被赋予同一个常量 c，则状态变为 c。如果发现它可能被赋予不同的值，则状态变为 ⊥（非常量）。状态只能沿格的方向下降，保证算法终止。


死代码消除与公共子表达式消除
死代码消除（Dead Code Elimination, DCE）删除不影响程序可观察行为的代码。在 SSA 中，如果一个定义没有任何使用者，且没有副作用，它就是死代码。


优化前:                 优化后:
x₁ = a + b             y₁ = a * c
y₁ = a * c             return y₁
z₁ = x₁ + y₁
return y₁              // x₁ 和 z₁ 是死代码
公共子表达式消除（Common Subexpression Elimination, CSE）识别并消除重复计算的表达式：


优化前:                 优化后:
a = b + c               t = b + c
d = b + c               a = t
e = a + d               d = t
                         e = t + t
全局值编号（Global Value Numbering, GVN）是 CSE 的增强版本。它为每个计算赋予一个"值编号"，相同值编号的计算可以被合并。GVN 能发现更多的等价关系，包括跨基本块的冗余计算。

循环优化
循环是程序中最耗时的部分，因此循环优化对性能影响最大。


循环不变代码外提（Loop-Invariant Code Motion, LICM）将循环体内不随迭代变化的计算移到循环外：


优化前:                 优化后:
for i in 0..n:          t = a * b
  x = a * b + i         for i in 0..n:
                           x = t + i
循环展开（Loop Unrolling）减少循环的迭代次数和分支开销：


优化前:                 优化后:
for i in 0..4:          body(0)
  body(i)               body(1)
                        body(2)
                        body(3)
循环向量化（Loop Vectorization）将标量循环转换为使用 SIMD 指令的向量化循环：


优化前:                 优化后 (伪 SIMD):
for i in 0..n:          for i in 0..n step 4:
  a[i] = b[i] + c[i]     a[i:i+4] = vadd(b[i:i+4], c[i:i+4])
强度削减（Strength Reduction）将循环中的昂贵运算替换为廉价运算：


优化前:                 优化后:
for i in 0..n:          t = 0
  x = i * 4             for i in 0..n:
  a[x] = ...              a[t] = ...
                           t = t + 4
函数内联与过程间优化
函数内联（Function Inlining）将被调用函数的代码体复制到调用点，消除函数调用的开销。


内联的收益：


    

  • 消除调用/返回的开销（压栈、跳转、恢复）
    • 

  • 开放了新的优化机会（内联后常量传播可以跨越原来的函数边界）
    • 

  • 消除了调用约定的限制
    • 



内联的代价：


    

  • 代码体积膨胀（code bloat）
    • 

  • 指令缓存压力增加
    • 

  • 编译时间增加
    • 



内联决策是一个启发式问题。常见的策略：


    

  • 小函数（函数体小于阈值）总是内联
    • 

  • 热路径上的函数优先内联
    • 

  • 递归函数不内联（或限制内联深度）
    • 

  • inline 关键字作为提示（编译器不一定遵守）
    • 



过程间优化（Inter-Procedural Optimization, IPO）在整个程序范围内进行分析和优化。


链接时优化（Link-Time Optimization, LTO）是 IPO 的实现方式之一。编译器在编译每个源文件时输出 IR（而非机器码），链接器在链接阶段对所有 IR 执行全局优化。LLVM 的 ThinLTO 是一种可扩展的 LTO 实现，它在保持大部分优化效果的同时显著减少了链接时间。

小结
    

  • 优化遍在保持语义不变的前提下提升程序性能
    • 

  • 常量传播和死代码消除是最基础、最高效的优化
    • 

  • 循环优化（外提、展开、向量化）对性能影响最大
    • 

  • 函数内联消除调用开销并开放新的优化机会
    • 

  • LTO/ThinLTO 将优化范围扩展到整个程序
    • 

  • SSA 形式极大地简化了大多数优化的实现
    • 

  • 优化遍的顺序和组合策略对最终效果有显著影响
    •
