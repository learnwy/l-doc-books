上下文无关语言

核心概念

上下文无关语言（Context-Free Language, CFL）是乔姆斯基层级中 Type 2 文法所生成的语言类。上下文无关文法（Context-Free Grammar, CFG）的产生式形式为 A → γ，其中 A 是单个非终结符，γ 是终结符和非终结符组成的任意串。关键特征是：非终结符 A 的替换不依赖于它在句型中的上下文位置，因此称为"上下文无关"。

上下文无关语言在编译器中的地位至关重要——几乎所有编程语言的语法结构都可以用 CFG 描述。嵌套的括号表达式、递归的控制流结构、函数定义与调用的层次关系，这些超出正则语言能力的结构恰好落在上下文无关语言的表达范围内。CFG 是语法分析器的理论基础。

CFL 的核心能力来自递归——CFG 允许非终结符在自身的产生式右部出现，这使得它能描述任意深度的嵌套结构。与正则语言相比，CFL 的计算模型（下推自动机）多了一个栈，正是这个栈提供了追踪嵌套层级的能力。

下推自动机
下推自动机（Pushdown Automaton, PDA）是识别上下文无关语言的计算模型。相比有限自动机，PDA 多了一个无限容量的栈，正是这个栈赋予了它处理嵌套结构的能力。


PDA 由七元组 (Q, Σ, Γ, δ, q₀, Z₀, F) 定义：Q 是状态集，Σ 是输入字母表，Γ 是栈字母表，δ 是转移函数，q₀ 是初始状态，Z₀ 是栈底符号，F 是接受状态集。


PDA 的转移函数 δ(q, a, X) 根据当前状态 q、输入符号 a（可以是 ε）和栈顶符号 X 决定下一步动作——转移到新状态并用一串符号替换栈顶。这种"读输入+看栈顶→改栈"的操作模式使得 PDA 能够追踪嵌套深度。


识别 {aⁿbⁿ | n ≥ 1} 的 PDA 工作过程：


输入: aaabbb
栈变化: Z₀ → aZ₀ → aaZ₀ → aaaZ₀ → aaZ₀ → aZ₀ → Z₀ (接受)

策略:
- 读到 a：压入 a
- 读到 b：弹出 a
- 输入结束时栈为空：接受
确定性下推自动机（DPDA）是 PDA 的受限版本，要求每一步最多有一个可选动作。DPDA 识别的语言类严格小于 PDA——这与 NFA/DFA 的等价性形成对比。LR 解析器本质上就是 DPDA 的一种高效实现。


DPDA 无法识别的 CFL 包括回文语言 {ww^R | w ∈ {a,b}*}——因为识别回文需要在读到"中间点"时从压栈切换到弹栈，而中间点的位置是不确定的。这一限制意味着存在一些理论上可解析但无法用确定性方法高效处理的文法结构。


文法范式与化简
实际应用中，CFG 通常需要化简为标准形式以便于分析算法处理。两种最重要的范式是乔姆斯基范式（CNF）和格雷巴赫范式（GNF）。


乔姆斯基范式要求每条产生式的形式为 A → BC 或 A → a，即右部要么是两个非终结符，要么是一个终结符。任何 CFG（不生成空串 ε 的）都可以转换为 CNF。CNF 的关键性质：推导一个长度为 n 的字符串恰好需要 2n-1 步，这使得 CYK 算法可以在 O(n³) 时间内完成通用 CFG 解析。


格雷巴赫范式要求产生式形式为 A → aα，其中 a 是终结符，α 是非终结符串（可为空）。GNF 保证每一步推导至少消耗一个输入字符，因此不会出现无限推导。GNF 在 LL 解析理论中有重要意义，因为每一步推导都以终结符开头，可以直接与输入进行匹配。


CFG 化简的步骤包括：


    

  1. 消除 ε 产生式（A → ε）
    2. 

  2. 消除单元产生式（A → B）
    3. 

  3. 消除不可达符号和无用符号
    4. 

  4. 转换为 CNF 或 GNF
    5. 



原始文法:
S → AB | ε
A → aA | ε
B → bB | b

消除 ε 产生式后:
S → AB | A | B
A → aA | a
B → bB | b

转 CNF 后:
S → AB | XA | XB | a | b
A → XA | a
B → XB | b
X → a (辅助非终结符替换终结符)
CYK 解析算法
CYK（Cocke-Younger-Kasami）算法是上下文无关语言最重要的通用解析算法。它要求文法为 CNF 形式，采用动态规划策略，时间复杂度为 O(n³|G|)，其中 n 是输入长度，|G| 是文法大小。


算法核心思想：构造一个三角形表格 T[i][j]，其中 T[i][j] 记录能推导出输入子串 w[i..j] 的所有非终结符。


输入: a b a b
文法 (CNF):
S → AB | CB    A → a
C → SB         B → b

CYK 表格 (自底向上填充):

长度4: T[1][4] = {S, C}        ← 整个串可由 S 推导 ✓
长度3: T[1][3] = {S}   T[2][4] = {S, C}
长度2: T[1][2] = {S,C} T[2][3] = {}  T[3][4] = {S,C}
长度1: T[1][1] = {A}   T[2][2] = {B} T[3][3] = {A} T[4][4] = {B}
CYK 算法虽然时间复杂度不如 LR/LL 的 O(n)，但它可以处理任何 CFG（只要是 CNF 形式），包括二义文法。在需要通用解析能力的场景（如自然语言处理、部分编程语言工具）中非常有用。


Earley 算法是另一种通用 CFG 解析算法，不要求 CNF 形式，一般情况 O(n³)，对无二义文法 O(n²)，对 LR 文法 O(n)。

上下文无关语言的闭包与判定
上下文无关语言在某些运算下封闭，在另一些运算下不封闭，这一性质直接影响编译器设计中的文法组合策略。


封闭的运算：并（L₁ ∪ L₂）、连接（L₁L₂）、克林闭包（L*）、与正则语言的交（L ∩ R）。特别是最后一项——CFL 与正则语言的交仍是 CFL——在编译器中很有用，因为很多约束可以通过正则表达式附加到 CFG 上。


不封闭的运算：交（两个 CFL 的交不一定是 CFL）、补（CFL 的补不一定是 CFL）。这意味着不能简单地通过组合两个文法来表达"同时满足两种语法规则"的语言。


CFG 的泵引理用于证明某些语言不是上下文无关的。例如 {aⁿbⁿcⁿ | n ≥ 0} 不是 CFL，因为栈只能追踪一种嵌套关系，无法同时匹配三种符号的数量。这就是为什么编程语言中"变量使用前必须声明"这类约束无法在文法层面表达，需要在语义分析阶段单独处理。


可判定问题：给定 CFG G 和字符串 w，判断 w ∈ L(G) 是可判定的（CYK 算法）。判断 L(G) 是否为空也是可判定的。


不可判定问题：两个 CFG 是否生成相同语言？一个 CFG 是否是二义的？一个 CFL 是否等于 Σ*（全集）？这些不可判定性意味着编译器设计中的某些问题无法自动化解决，需要人工分析。


实际编程语言与 CFG
现代编程语言的语法通常"几乎"是上下文无关的——核心语法结构可以用 CFG 描述，但存在一些上下文相关的边缘情况需要在语义分析阶段处理。


典型的编程语言 CFG 片段：

program      → decl_list
decl_list    → decl decl_list | ε
decl         → func_decl | var_decl
func_decl    → type ID "(" params ")" block
var_decl     → type ID "=" expr ";"
block        → "{" stmt_list "}"
stmt_list    → stmt stmt_list | ε
stmt         → if_stmt | while_stmt | return_stmt | expr_stmt
if_stmt      → "if" "(" expr ")" block else_clause
else_clause  → "else" block | ε
expr         → expr "+" term | term
term         → term "*" factor | factor
factor       → "(" expr ")" | ID | NUM
CFG 无法表达的编程语言特性包括：类型检查（变量类型是否匹配）、作用域规则（变量是否已声明）、函数签名匹配（参数个数和类型是否正确）。这些都属于上下文相关的语义约束，由编译器的语义分析阶段通过符号表和类型系统来处理。


值得注意的是，某些语言的语法本身就不是严格的上下文无关。C 语言中的 typedef 使得同一个标识符在不同上下文中可能是类型名或变量名，导致解析依赖于前面的声明——这是经典的"lexer hack"。C++ 的模板语法中 >> 可能是右移运算符或两个模板参数的闭合尖括号，这种歧义在 C++11 之前需要语义信息才能消解。


小结
    

  • 上下文无关文法的产生式形式为 A → γ，替换不依赖上下文
    • 

  • 下推自动机通过栈实现嵌套结构的识别能力
    • 

  • CNF 是通用解析算法（CYK、O(n³)）的基础
    • 

  • CFL 在交和补运算下不封闭，这限制了文法组合的可能性
    • 

  • 编程语言的核心语法用 CFG 描述，上下文相关部分由语义分析处理
    • 

  • LL 和 LR 解析器在 O(n) 时间内处理 CFG 的确定性子集
    • 

  • 理解 CFL 的能力边界有助于正确划分编译器各阶段的职责
