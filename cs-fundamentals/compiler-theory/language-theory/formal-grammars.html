形式文法

核心概念

形式文法（Formal Grammar）是描述形式语言的数学工具。一个形式文法 G 由四元组 (V, Σ, P, S) 组成：V 是非终结符集合，Σ 是终结符集合，P 是产生式规则集合，S 是起始符号。通过反复应用产生式规则，从起始符号 S 出发可以推导出该文法所定义的所有合法字符串，这些字符串的集合即为该文法生成的语言 L(G)。

形式文法的核心价值在于它为编程语言的语法定义提供了精确的数学框架。编译器前端的词法分析和语法分析阶段分别依赖不同类型的文法：词法规则通常用正则文法描述，而语法结构则用上下文无关文法定义。理解文法的分类与能力边界，是设计编译器的第一步。

乔姆斯基层级体系
1956 年，诺姆·乔姆斯基提出了文法的四级分类体系，按照产生式规则的约束强度从弱到强排列。每一级文法生成的语言类严格包含下一级，形成一个层级结构。


Type 0（无限制文法） 的产生式形式为 α → β，其中 α 和 β 是任意符号串（α 至少包含一个非终结符）。这类文法的生成能力等价于图灵机，可以描述所有可计算的语言。


Type 1（上下文相关文法） 要求产生式 αAβ → αγβ，即非终结符 A 只能在特定上下文 α 和 β 中被替换为 γ，且 |γ| ≥ 1。这保证了推导过程中句型长度不递减。自然语言中的一些上下文相关结构（如主谓一致）属于这一层级。


Type 2（上下文无关文法） 要求产生式形式为 A → γ，其中 A 是单个非终结符，γ 是任意符号串。这意味着 A 的替换不依赖其上下文。大多数编程语言的语法可以用上下文无关文法描述，它是语法分析器的核心理论基础。


Type 3（正则文法） 是最受约束的一类。右线性文法的产生式形式为 A → aB 或 A → a，左线性文法则为 A → Ba 或 A → a。正则文法等价于正则表达式和有限自动机，用于词法分析。


产生式规则与推导
产生式规则是文法的核心操作机制。给定一个句型 αAβ，如果存在产生式 A → γ，就可以将该句型改写为 αγβ，记作 αAβ ⇒ αγβ。从起始符号开始反复应用产生式，最终得到仅包含终结符的字符串，这一过程称为推导（Derivation）。


推导有两种标准策略。最左推导（Leftmost Derivation）每一步替换当前句型中最左边的非终结符，记作 ⇒_lm。最右推导（Rightmost Derivation）每一步替换最右边的非终结符，记作 ⇒_rm。这两种策略在语法分析中分别对应自顶向下和自底向上两种解析方法。


以算术表达式文法为例：


E → E + T | T
T → T * F | F
F → ( E ) | id
推导字符串 id + id * id 的最左推导过程：


E ⇒ E + T ⇒ T + T ⇒ F + T ⇒ id + T ⇒ id + T * F ⇒ id + F * F ⇒ id + id * F ⇒ id + id * id
每一步推导都选择最左侧的非终结符进行替换。这个推导序列唯一地对应一棵解析树，解析树的叶子节点从左到右拼接就得到原始字符串。


对应的最右推导过程则相反，每一步替换最右侧的非终结符：


E ⇒ E + T ⇒ E + T * F ⇒ E + T * id ⇒ E + F * id ⇒ E + id * id ⇒ T + id * id ⇒ F + id * id ⇒ id + id * id
尽管最左推导和最右推导的中间步骤不同，但对于无二义文法，它们对应同一棵解析树。理解这一点对后续学习语法分析至关重要：LL 解析器构造最左推导，LR 解析器构造最右推导的逆过程。


文法的二义性
如果一个文法对某个字符串存在两棵不同的解析树（等价地，存在两个不同的最左推导），则称该文法是二义的（Ambiguous）。二义性是文法设计中必须避免的问题，因为它意味着同一段代码可能有多种不同的语义解释。


经典的二义性例子是简化的表达式文法：


E → E + E | E * E | ( E ) | id
对于字符串 id + id * id，这个文法可以产生两棵不同的解析树：一棵让 + 先结合（错误的优先级），另一棵让 * 先结合（正确的优先级）。


消除二义性的标准方法是引入优先级和结合性。通过将文法拆分为多个非终结符层级（如 E → T, T → F），可以强制高优先级运算符在解析树的更深层，从而消除二义性。这正是前面算术表达式文法的设计思路：* 绑定在 T 层级，比 +（E 层级）更紧密。


另一个经典的二义性问题是"悬挂 else"（dangling else）：


S → if E then S else S | if E then S | other
对于 if E1 then if E2 then S1 else S2，else 可以关联到内层或外层 if。解决方案通常是引入"匹配-未匹配"语句的区分，或者像 Python/Go 那样要求强制使用大括号。

BNF 与 EBNF 表示法
BNF（Backus-Naur Form）是最广泛使用的文法表示法，由 John Backus 和 Peter Naur 在描述 ALGOL 60 语言时提出。BNF 用 ::= 表示产生式，| 表示选择，<> 包裹非终结符。


<expr>   ::= <expr> "+" <term> | <term>
<term>   ::= <term> "*" <factor> | <factor>
<factor> ::= "(" <expr> ")" | <id>
EBNF（Extended BNF）在 BNF 基础上增加了重复 { } 、可选 [ ] 和分组 ( ) 三种元语法符号，使文法书写更加紧凑。


expr   = term { "+" term } ;
term   = factor { "*" factor } ;
factor = "(" expr ")" | id ;
EBNF 的表达能力与 BNF 完全等价——任何 EBNF 文法都可以机械地转换为 BNF。但 EBNF 在实际工程中更受欢迎，原因有三：消除了许多辅助非终结符（如表示重复的递归规则）、更接近实际代码中的循环结构、更易于被解析器生成器处理。


现代语言规范大多采用 EBNF 或其变体。例如 Python 的语法规范使用一种类似 EBNF 的 PEG（Parsing Expression Grammar）记法，Rust 和 Go 的官方文档也采用 EBNF 风格的文法定义。


if_stmt    = "if" expr block { "else" "if" expr block } [ "else" block ] ;
block      = "{" { statement } "}" ;
statement  = if_stmt | for_stmt | expr_stmt | return_stmt ;
理解 BNF 和 EBNF 不仅是阅读语言规范的基础能力，也是使用 ANTLR、Bison 等解析器生成器时必须掌握的记法。


文法变换技术
在实际编译器实现中，原始文法往往需要经过变换才能被特定的解析算法处理。两种最重要的变换是消除左递归和提取左公因子。


左递归是指产生式 A → Aα 的情况。自顶向下解析器（如递归下降）无法处理左递归文法，因为它会导致无限递归。消除左递归的标准方法是将其改写为右递归加尾部规则：


原始：A → Aα | β
改写：A  → βA'
      A' → αA' | ε
对于算术表达式中的 E → E + T | T，消除左递归后变为：


E  → T E'
E' → + T E' | ε
左公因子是指多个产生式共享相同前缀的情况，如 S → if E then S else S | if E then S。提取左公因子后：


S  → if E then S S'
S' → else S | ε
这两种变换保证了文法适用于 LL 类解析算法，即可以通过向前看一个（或有限个）终结符来确定使用哪条产生式。


小结
    

  • 形式文法通过四元组 (V, Σ, P, S) 和产生式规则精确定义语言
    • 

  • 乔姆斯基层级将文法分为四类，表达能力逐级增强
    • 

  • 编译器主要使用 Type 2（语法）和 Type 3（词法）两个层级
    • 

  • 二义性文法需要通过优先级分层、结合性规则等方法消除
    • 

  • BNF 与 EBNF 是描述文法的标准表示法，EBNF 更紧凑
    • 

  • 消除左递归和提取左公因子是适配 LL 解析器的必要变换
    • 

  • 理解文法理论是掌握词法分析和语法分析的前提
