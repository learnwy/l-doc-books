正则语言

核心概念

正则语言（Regular Language）是乔姆斯基层级中最底层、也是约束最严格的一类形式语言。它可以通过三种等价的形式化方式定义：正则文法（Type 3）、正则表达式和有限自动机（Finite Automaton）。这三者之间的等价性是形式语言理论中最优雅的结论之一——无论用哪种方式描述，所能表达的语言集合完全相同。

正则语言在编译器中扮演着关键角色：词法分析阶段的所有 token 规则（标识符、数字、字符串字面量、运算符等）都是用正则表达式定义的。词法分析器本质上就是一个有限自动机，逐字符扫描输入源码，将其切分为 token 序列。正则语言之所以适合词法分析，是因为它的识别算法在时间和空间上都非常高效——DFA 对每个输入字符仅需 O(1) 的查表操作。

正则表达式与运算
正则表达式由三种基本运算构成，它们的组合可以描述所有正则语言。这三种运算既是数学定义，也直接对应了正则引擎的实现机制：


连接（Concatenation）：将两个表达式首尾相接。如果 L₁ = {ab} 且 L₂ = {cd}，则 L₁L₂ = {abcd}。连接是隐式运算——两个表达式直接拼接即表示连接，无需额外的运算符号。


选择（Union / Alternation）：取两个语言的并集，用 | 表示。L₁ | L₂ = {ab, cd}。选择运算使得一个正则表达式可以匹配多种模式中的任意一种。


克林闭包（Kleene Star）：零次或多次重复，用 * 表示。如果 L = {a}，则 L* = {ε, a, aa, aaa, ...}。


这三种运算的优先级和结合性是形式化定义的一部分。克林闭包的优先级最高（与一元运算符类似），连接次之，选择最低。所有运算都是左结合的。空串 ε 是连接运算的单位元（Lε = εL = L），空集 ∅ 是选择运算的单位元（L | ∅ = L）。


在这三种基本运算之上，实际的正则表达式引擎还提供了语法糖：+ 表示一次或多次，? 表示零次或一次，[a-z] 表示字符类，{n,m} 表示重复次数范围。这些扩展不增加表达能力——它们都可以用三种基本运算改写。


编译器词法规则中典型的正则表达式定义：


identifier   = [a-zA-Z_][a-zA-Z0-9_]*
integer      = [0-9]+
float        = [0-9]+"."[0-9]+([eE][+-]?[0-9]+)?
string       = \"([^\"\\]|\\.)*\"
whitespace   = [ \t\n\r]+
line_comment = "//"[^\n]*
block_comment = "/*"([^*]|"*"[^/])*"*/"
keyword      = "if"|"else"|"while"|"return"|"int"|"void"
operator     = "+"|"-"|"*"|"/"|"="|"=="|"!="|"<"|">"
正则表达式的代数性质对优化很重要。例如 r|r = r（幂等性）、r|s = s|r（交换律）、(rs)t = r(st)（结合律）、r(s|t) = rs|rt（分配律）。这些性质允许在构造自动机之前对正则表达式进行化简。


运算符优先级从高到低为：克林闭包 * > 连接 > 选择 |。因此表达式 ab|cd* 被解析为 (a)(b) | (c)(d*)，而非 (ab|cd)*。这种优先级约定与算术运算中乘法优先于加法的惯例一致。


在词法分析器中，多个 token 规则通常被组合为一个大的选择表达式：keyword | identifier | number | string | operator。当输入匹配多个规则时，采用最长匹配（Maximal Munch）策略——选择消耗最多输入字符的规则；若长度相同，则按规则定义顺序选择（优先级匹配）。这两条策略决定了词法分析器的消歧行为。


NFA 与 DFA
NFA（Nondeterministic Finite Automaton）由五元组 (Q, Σ, δ, q₀, F) 定义：Q 是有限状态集，Σ 是输入字母表，δ: Q × (Σ ∪ {ε}) → P(Q) 是转移函数（返回状态集合），q₀ 是初始状态，F ⊆ Q 是接受状态集。NFA 的关键特性是"非确定性"——在某个状态下读入一个字符，可能转移到多个不同状态；还允许不消耗输入的 ε 转移。


NFA 接受一个输入字符串当且仅当存在至少一条从初始状态到某个接受状态的转移路径。在模拟 NFA 时，可以同时追踪所有可能的状态（并行模拟），也可以通过回溯逐一探索（串行模拟）。并行模拟的时间复杂度是 O(n × |Q|)，而回溯策略在最坏情况下可能是指数级的。


DFA（Deterministic Finite Automaton）的定义类似，但转移函数 δ: Q × Σ → Q 是确定的——每个状态在每个输入字符上恰好转移到一个状态，且不允许 ε 转移。


NFA 和 DFA 的表达能力完全等价。这意味着任何 NFA 都可以转换为识别相同语言的 DFA。但在状态数量上存在巨大差异：一个 n 个状态的 NFA 对应的最小 DFA 最坏情况下可能有 2ⁿ 个状态。

在实际工程中，许多现代正则引擎采用混合策略：先构造 NFA，然后按需（lazily）将频繁访问的 NFA 状态集合缓存为 DFA 状态。这种方法避免了预先构造完整 DFA 的指数膨胀风险，同时在常见路径上获得接近 DFA 的性能。Google 的 RE2 引擎就是这种混合策略的典型实现。


值得注意的是，许多编程语言中的"正则表达式"（如 Perl、JavaScript、Python 的 re 模块）实际上支持超出理论正则语言能力的特性，包括反向引用（backreference）、前瞻断言（lookahead）和后顾断言（lookbehind）。带反向引用的匹配问题是 NP 完全的，这解释了为什么这些引擎在某些模式上表现出指数级的匹配时间。编译器的词法分析器通常不使用这些扩展特性，而是严格限制在理论正则表达式的范围内，以保证线性时间的匹配性能。


Thompson 构造法
Thompson 构造法是将正则表达式转换为 NFA 的标准算法，由 Ken Thompson 于 1968 年提出。该算法按正则表达式的结构递归地构造 NFA，每种运算对应一种固定的 NFA 组合方式。


对于单个字符 a，构造一个包含起始状态和接受状态的简单 NFA，两者之间有一条标记为 a 的转移边。


对于连接 rs，将 r 的 NFA 的接受状态通过 ε 转移连接到 s 的 NFA 的起始状态。r 的接受状态不再是接受状态，s 的接受状态成为整体的接受状态。


对于选择 r|s，创建新的起始状态，通过 ε 转移分别连接到 r 和 s 的起始状态；创建新的接受状态，r 和 s 的接受状态分别通过 ε 转移连接到它。


对于克林闭包 r*，创建新的起始和接受状态，起始状态通过 ε 转移连接到 r 的起始状态和新接受状态（允许零次匹配），r 的接受状态通过 ε 转移连接回 r 的起始状态（允许重复）和新接受状态（退出循环）。


Thompson 构造的关键性质：构造出的 NFA 状态数为 O(n)（n 为正则表达式长度），且每个状态最多有两条出边。这保证了后续子集构造的输入规模可控。


正则表达式: (a|b)*abb

Thompson NFA 结构:
→ [q0] --ε--> [q1] --a--> [q2] --ε--> [q5]
         --ε--> [q3] --b--> [q4] --ε--> [q5]
  [q5] --ε--> [q0]  (循环)
  [q5] --ε--> [q6]
  [q6] --a--> [q7] --b--> [q8] --b--> [q9] (接受)
子集构造与 DFA 最小化
子集构造算法（Subset Construction，又称幂集构造）将 NFA 转换为 DFA。核心思想是：DFA 的每个状态对应 NFA 的一个状态子集。


算法从 NFA 起始状态的 ε-闭包开始（ε-闭包是从该状态出发仅通过 ε 转移可达的所有状态集合），将其作为 DFA 的起始状态。然后对每个已发现的 DFA 状态（NFA 状态集合）和每个输入字符，计算所有可达的 NFA 状态的 ε-闭包，将其作为新的 DFA 状态。重复直到没有新状态产生。如果某个 DFA 状态（NFA 状态集合）包含 NFA 的接受状态，则该 DFA 状态也是接受状态。


子集构造: NFA → DFA
ε-closure({q0}) = {q0, q1, q3, q6}  → DFA 状态 A
δ(A, a) = ε-closure({q2, q7}) = {q2, q5, q0, q1, q3, q6, q7}  → DFA 状态 B
δ(A, b) = ε-closure({q4}) = {q4, q5, q0, q1, q3, q6}  → DFA 状态 C
...继续直到闭包完成
子集构造后得到的 DFA 可能不是最小的——可能存在行为完全相同的冗余状态。Hopcroft 算法通过状态划分（Partition Refinement）找到最小 DFA：初始将状态分为接受状态和非接受状态两组，然后迭代地检查每组中的状态是否在所有输入上都转移到同一组，如果不是则细分。最终每个不可再分的组合并为一个状态。


Hopcroft 算法的时间复杂度为 O(n log n)，其中 n 是 DFA 状态数。最小化后的 DFA 是唯一的（同构意义下），这一性质称为 Myhill-Nerode 定理。


最小化 DFA 在词法分析器中的意义是双重的：一方面减少了状态转移表的内存占用，另一方面唯一性保证了不同构造路径最终得到相同的自动机，这简化了测试和验证。


正则语言的局限性
正则语言虽然高效，但表达能力有限。理解这些局限性对编译器设计至关重要。


泵引理（Pumping Lemma）是证明一个语言不是正则语言的标准工具：如果 L 是正则语言，则存在常数 p（泵长度），使得 L 中任何长度 ≥ p 的字符串 s 都可以分解为 s = xyz，满足 |xy| ≤ p，|y| > 0，且对所有 i ≥ 0，xy^iz ∈ L。


利用泵引理可以证明以下语言不是正则语言：


    

  • {aⁿbⁿ | n ≥ 0} — 括号匹配的抽象模型，需要计数
    • 

  • {ww^R | w ∈ {a,b}*} — 回文，需要记忆前半部分
    • 

  • {aⁿ | n 是素数} — 需要数论判断
    • 



以 {aⁿbⁿ} 为例，假设它是正则语言，取泵长度 p，考虑字符串 s = aᵖbᵖ。无论如何分解 s = xyz（|xy| ≤ p），y 只包含 a。泵送 y 两次得到 xy²z，其中 a 的数量大于 b 的数量，不属于语言 L——矛盾。因此 {aⁿbⁿ} 不是正则语言。


这些局限性直接影响编译器设计：嵌套括号、匹配的 begin-end 块、递归结构等都无法用正则表达式描述，必须用上下文无关文法处理。这就是编译器需要在词法分析之上再加一层语法分析的根本原因。


正则语言的边界也解释了为什么词法分析器通常不处理嵌套注释（如 /* /* ... */ */）——嵌套结构本质上需要栈来追踪层级。某些语言（如 Swift、Rust）支持嵌套注释，它们的词法分析器在处理这种结构时实际上使用了超出纯正则语言能力的技术（手工编写的计数逻辑）。


正则语言对闭包运算（并、交、补、连接、克林星）封闭，这一性质在词法分析器设计中很有用。例如，"不包含子串 */ 的注释内容"可以通过正则语言的补运算来构造。

这种完全的闭包性质意味着正则语言在组合和变换操作下非常稳定，任何有限次的布尔和正则运算都不会逃出正则语言的范畴。这是词法分析阶段可以在理论上完全自动化的根本保证。


小结
    

  • 正则语言由正则表达式、NFA、DFA 三种等价方式描述
    • 

  • 三种基本运算（连接、选择、克林闭包）构成正则表达式的完整表达能力
    • 

  • Thompson 构造法将正则表达式转为 NFA（O(n) 状态）
    • 

  • 子集构造法将 NFA 转为 DFA（最坏 2ⁿ 状态膨胀）
    • 

  • Hopcroft 算法将 DFA 最小化（O(n log n)），结果唯一
    • 

  • DFA 是词法分析器的核心执行引擎，每个字符 O(1) 转移
    • 

  • 现代引擎采用混合 NFA/DFA 策略平衡构造开销和匹配性能
    • 

  • 正则语言在所有布尔运算和正则运算下封闭，适合词法分析的自动化
    • 

  • 正则语言无法描述嵌套结构，这是引入上下文无关文法的根本动机
    •
