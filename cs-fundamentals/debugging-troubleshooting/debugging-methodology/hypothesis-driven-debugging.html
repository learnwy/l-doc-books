假设驱动调试

概述

假设驱动调试是科学调试流程中最核心的思维技能。它要求调试者在动手修改代码之前，先明确地提出"我认为问题的原因是什么"，然后设计最小化的实验来验证这个假设。这种方法的关键洞察是：永远不要在没有假设的情况下做出代码变更。

随机调试就像在黑暗中随机走动寻找钥匙；假设驱动调试则是系统地搜索每个房间，搜完标记为"已检查"后再去下一个。两者最终都能找到答案，但后者在复杂系统中的效率高出数个数量级。

核心概念

假设的质量标准

一个好的调试假设必须满足三个条件：

具体性（Specific）：指明确切的代码位置、数据条件或环境因素。


# 差的假设：不具体
"数据库有问题"

# 好的假设：具体
"当 user_profile 表的 bio 字段超过 10000 字符时，
 UserService.getProfile() 的 SQL 查询超时（>5s），
 因为该字段没有建索引且触发了全表扫描"
可证伪性（Falsifiable）：必须存在一种实验结果能否定这个假设。


# 不可证伪的假设（无意义）
"可能是某个竞态条件"  # 太模糊，无法设计针对性实验

# 可证伪的假设
"线程 A 在 mutex.unlock() 和 counter += 1 之间被抢占，
 导致线程 B 读到了未更新的 counter 值"
# 验证：加锁保护 counter 更新，如果问题消失则确认
可测试性（Testable）：验证实验可以在合理的时间和资源内完成。


概率排序策略
当面对多个可能的假设时，应按预期概率从高到低排序，优先测试最可能的原因：

# 贝叶斯式假设更新
class HypothesisTracker:
    def __init__(self):
        self.hypotheses = []

    def add(self, description, prior_probability, evidence=""):
        self.hypotheses.append({
            "description": description,
            "probability": prior_probability,
            "status": "untested",
            "evidence": evidence,
            "experiments": []
        })

    def test(self, hypothesis_id, experiment, result):
        h = self.hypotheses[hypothesis_id]
        h["experiments"].append({"experiment": experiment, "result": result})
        if result == "confirmed":
            h["status"] = "confirmed"
            h["probability"] = 0.95
        elif result == "eliminated":
            h["status"] = "eliminated"
            h["probability"] = 0.0
        else:  # partially confirmed
            h["probability"] *= 1.5  # 增加可信度
            h["probability"] = min(h["probability"], 0.95)

    def next_to_test(self):
        """返回概率最高的未测试假设"""
        untested = [h for h in self.hypotheses if h["status"] == "untested"]
        return max(untested, key=lambda h: h["probability"], default=None)

案例一：API 响应间歇性 500 错误
症状：订单服务 /api/orders/{id} 接口在高峰期约 2% 的请求返回 500。


# 步骤 1：形成假设
tracker = HypothesisTracker()
tracker.add(
    "数据库连接池耗尽：高峰期并发超过连接池上限",
    prior_probability=0.5,
    evidence="500 错误集中在 QPS > 1000 时段"
)
tracker.add(
    "某些 order_id 对应的数据异常触发未处理异常",
    prior_probability=0.3,
    evidence="错误日志显示 NullPointerException"
)
tracker.add(
    "下游支付服务超时导致级联失败",
    prior_probability=0.2,
    evidence="支付团队最近做了部署"
)

// 假设 1：goroutine 泄漏（每个 goroutine 占用栈空间）

import "runtime"
import "expvar"

func monitorGoroutines() {
    for {
        goroutineCount.Set(int64(runtime.NumGoroutine()))

团队协作模式
结对调试：两人协作时，一人负责操作（键盘），一人负责假设管理和记录。这种分工避免了陷入"只顾操作忘记思考"的陷阱。


总结
假设驱动调试的核心纪律是：在动手之前先想清楚你在验证什么。这看似增加了步骤，实际上大幅减少了总调试时间——因为每次操作都有明确目标，永远不会"白忙活"。


培养这种习惯的最简单方法：每次遇到 bug，先在纸上（或注释里）写下三个可能的原因，按概率排序后再开始验证。坚持两周，你会发现自己的调试速度和准确率都有显著提升。
