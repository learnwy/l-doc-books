CPU 与内存 Profiling

概述

CPU 和内存 Profiling 是量化分析程序运行时资源消耗的核心技术。CPU Profiling 回答"程序把时间花在了哪些函数上"，内存 Profiling 回答"程序的内存被什么对象占用"。掌握这两种分析技术是性能优化的基础——没有数据支撑的优化都是盲目猜测。

CPU Profiling 工作原理
采样型 CPU profiler 的工作流程：


1. 以固定频率（如 99Hz）发送信号中断程序
2. 在中断处理中记录当前线程的完整调用栈
3. 运行一段时间后收集所有样本
4. 统计每个函数出现在栈顶的次数 → CPU 时间占比
5. 统计每个函数出现在栈中的次数 → 含子调用的总时间
# Linux perf: 系统级 CPU profiling
perf record -F 99 -p $(pidof myapp) -g -- sleep 30
# -F 99: 采样频率 99Hz（避免与系统时钟对齐）
# -p: 目标进程
# -g: 记录调用栈

perf report --stdio  # 文本报告
perf script > out.perf  # 导出用于火焰图
// Go: 内置 pprof CPU profiling
import (
    "os"
    "runtime/pprof"
)

func main() {
    // 开始 CPU profile
    f, _ := os.Create("cpu.prof")
    pprof.StartCPUProfile(f)
    defer pprof.StopCPUProfile()

    // ... 程序逻辑 ...
}

内存 Profiling 技术
// Go: Heap profiling
import "runtime/pprof"

func analyzeMemory() {
    // 获取当前 heap profile
    f, _ := os.Create("mem.prof")
    runtime.GC()  // 先 GC 以获得准确快照
    pprof.WriteHeapProfile(f)
    f.Close()
}

// 分析命令
// go tool pprof mem.prof
// (pprof) top          → 内存占用最大的函数
// (pprof) list funcName → 逐行内存分配
// (pprof) web          → 可视化调用图

内存泄漏检测
# Python: 使用 tracemalloc 追踪内存分配
import tracemalloc

tracemalloc.start()

# ... 执行可疑代码 ...

snapshot1 = tracemalloc.take_snapshot()
# ... 继续执行 ...
snapshot2 = tracemalloc.take_snapshot()

# 对比两个快照，找到增长的分配
top_stats = snapshot2.compare_to(snapshot1, 'lineno')
print("[ Top 10 memory increases ]")
for stat in top_stats[:10]:
    print(stat)

原因

单次采集不超过 60s
避免数据量过大

限制并发 profile 数

总结
CPU 和内存 Profiling 是性能优化的"显微镜"——它让你看到程序内部的资源消耗分布，用数据而非直觉指导优化。关键实践：选择采样型工具用于生产、建立优化前后的量化对比、将持续 Profiling 集成到监控体系中。记住：未经测量的优化是过早优化。
