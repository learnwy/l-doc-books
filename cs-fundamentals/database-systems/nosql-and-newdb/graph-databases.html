图数据库

核心概念

图数据库以**节点（Node）和关系（Relationship）**为核心数据模型，专门用于存储和查询高度关联的数据。在社交网络、推荐系统、知识图谱等场景中，图数据库的性能远超关系数据库的多表 JOIN。





特性
图数据库
关系数据库





数据模型
节点 + 关系 + 属性
表 + 行 + 列




关联查询
遍历关系（O(1) 每步）
JOIN（O(n) 扫描）




深度关联
多跳遍历高效
多表 JOIN 性能骤降




Schema
灵活标签
严格模式




适用场景
高度关联数据
结构化事务数据







属性图模型
属性图（Property Graph）是最常用的图数据模型，由节点、关系和属性三要素组成。






要素
说明
示例





节点
实体，可有标签（Label）
(:User {name: "Alice"})




关系
有向连接，有类型和属性
-[:FOLLOWS {since: 2024}]->




属性
键值对，附着在节点或关系上
name: "Alice", age: 28




标签
节点的分类标记
:User, :Post, :Product







Neo4j 与 Cypher 查询
Neo4j 是最流行的图数据库，Cypher 是其声明式查询语言。


基本 CRUD
// 创建节点
CREATE (alice:User {name: 'Alice', age: 28, email: 'alice@example.com'})
CREATE (bob:User {name: 'Bob', age: 32})
CREATE (post:Post {title: '图数据库入门', content: '...', createdAt: datetime()})

// 创建关系
MATCH (a:User {name: 'Alice'}), (b:User {name: 'Bob'})
CREATE (a)-[:FOLLOWS {since: date('2024-01-15')}]->(b)

MATCH (a:User {name: 'Alice'}), (p:Post {title: '图数据库入门'})
CREATE (a)-[:WROTE {at: datetime()}]->(p)

// 查询
MATCH (u:User {name: 'Alice'})-[:FOLLOWS]->(friend)
RETURN friend.name, friend.age

// 更新
MATCH (u:User {name: 'Alice'})
SET u.age = 29, u.updatedAt = datetime()

// 删除（先删关系再删节点）
MATCH (u:User {name: 'temp'})-[r]-()
DELETE r, u
图遍历查询
// 二度好友（朋友的朋友）
MATCH (me:User {name: 'Alice'})-[:FOLLOWS]->()-[:FOLLOWS]->(fof:User)
WHERE fof <> me
  AND NOT (me)-[:FOLLOWS]->(fof)
RETURN DISTINCT fof.name

// 可变长度路径：1到3度关系
MATCH (me:User {name: 'Alice'})-[:FOLLOWS*1..3]->(distant:User)
RETURN DISTINCT distant.name, length(shortestPath((me)-[:FOLLOWS*]->(distant))) AS distance

// 最短路径
MATCH p = shortestPath(
    (a:User {name: 'Alice'})-[:FOLLOWS*..6]-(b:User {name: 'Dave'})
)
RETURN p, length(p) AS hops

社交网络用例
// 共同好友推荐
MATCH (me:User {name: 'Alice'})-[:FOLLOWS]->(mutual)<-[:FOLLOWS]-(recommended:User)
WHERE NOT (me)-[:FOLLOWS]->(recommended)
  AND recommended <> me
RETURN recommended.name, COUNT(mutual) AS mutualFriends
ORDER BY mutualFriends DESC
LIMIT 10

// 影响力分析：某用户的关注者网络
MATCH (influencer:User {name: 'Bob'})<-[:FOLLOWS*1..2]-(follower:User)
RETURN COUNT(DISTINCT follower) AS reach

// 社区检测：紧密连接的群组
CALL gds.louvain.stream('social-graph')
YIELD nodeId, communityId
RETURN gds.util.asNode(nodeId).name AS user, communityId
ORDER BY communityId


推荐系统用例
// 协同过滤：买了X的人也买了Y
MATCH (target:User {name: 'Alice'})-[:PURCHASED]->(p:Product)<-[:PURCHASED]-(other:User)
      -[:PURCHASED]->(rec:Product)
WHERE NOT (target)-[:PURCHASED]->(rec)
RETURN rec.name, COUNT(DISTINCT other) AS score
ORDER BY score DESC
LIMIT 5

// 基于图的商品推荐
MATCH (u:User {name: 'Alice'})-[:PURCHASED]->(p:Product)-[:BELONGS_TO]->(cat:Category)
      <-[:BELONGS_TO]-(rec:Product)
WHERE NOT (u)-[:PURCHASED]->(rec)
  AND rec.rating > 4.0
RETURN DISTINCT rec.name, rec.rating, cat.name AS category
ORDER BY rec.rating DESC
LIMIT 10


知识图谱用例
// 构建知识图谱
CREATE (py:Tech {name: 'Python'})-[:USED_FOR]->(:Domain {name: '机器学习'})
CREATE (py)-[:HAS_FRAMEWORK]->(:Framework {name: 'PyTorch'})
CREATE (py)-[:HAS_FRAMEWORK]->(:Framework {name: 'TensorFlow'})

// 查询技术关联
MATCH path = (start:Tech {name: 'Python'})-[*1..3]-(related)
RETURN path

索引与性能
// 创建索引
CREATE INDEX FOR (u:User) ON (u.name)
CREATE INDEX FOR (u:User) ON (u.email)

// 复合索引
CREATE INDEX FOR (p:Product) ON (p.category, p.rating)

// 全文索引
CREATE FULLTEXT INDEX searchIndex FOR (n:Post) ON EACH [n.title, n.content]

// 约束
CREATE CONSTRAINT FOR (u:User) REQUIRE u.email IS UNIQUE


小结
    

  • 图数据库以节点和关系为核心，遍历关联数据的性能远超关系数据库的 JOIN。
    • 

  • Cypher 是 Neo4j 的声明式查询语言，模式匹配语法直观表达图结构。
    • 

  • 社交网络（共同好友、影响力分析）和推荐系统（协同过滤）是图数据库的典型应用。
    • 

  • 图数据库的关联查询性能不随数据量增长而下降，因为遍历是局部操作。
    • 

  • 图数据库适合关联密集的数据，结构化事务数据仍应使用关系数据库。
