列族存储

核心概念

列族存储（Column-Family Store）是一种面向大规模分布式场景的 NoSQL 数据模型。数据按列族（Column Family）组织，同一列族的数据物理上存储在一起。这种设计特别适合写密集型工作负载和宽表模型。





特性
列族存储
关系数据库





数据模型
行键 → 列族 → 列
表 → 行 → 列




Schema
列族预定义，列动态
严格预定义




扩展方式
水平扩展（原生）
主要垂直扩展




写入性能
极高（LSM-Tree）
中等（B+ 树）




查询方式
按行键范围扫描
SQL 灵活查询




适用场景
海量数据、高吞吐写入
复杂查询、事务







Apache Cassandra
Cassandra 是一个高可用、无中心的分布式列族数据库，最初由 Facebook 开发。


数据模型
-- Cassandra CQL（类 SQL 语法）
CREATE KEYSPACE ecommerce
WITH replication = {
    'class': 'NetworkTopologyStrategy',
    'dc1': 3, 'dc2': 3
};

USE ecommerce;

CREATE TABLE user_activity (
    user_id     UUID,
    activity_ts TIMESTAMP,
    event_type  TEXT,
    details     MAP<TEXT, TEXT>,
    PRIMARY KEY (user_id, activity_ts)
) WITH CLUSTERING ORDER BY (activity_ts DESC);

-- 插入数据
INSERT INTO user_activity (user_id, activity_ts, event_type, details)
VALUES (uuid(), toTimestamp(now()), 'page_view',
    {'page': '/products/123', 'duration': '45s'});

-- 查询：按用户查询最近活动
SELECT * FROM user_activity
WHERE user_id = ? AND activity_ts > '2024-01-01'
LIMIT 50;

Apache HBase
HBase 是基于 Hadoop HDFS 的分布式列族数据库，适合超大规模数据存储和实时随机访问。


HBase 数据模型
RowKey → Column Family → Column Qualifier → Timestamp → Value

示例：
Row: "user:1001"
  CF "info":
    "name" → "alice" (ts: 1704067200)
    "age"  → "28"    (ts: 1704067200)
  CF "contact":
    "email" → "alice@example.com" (ts: 1704067200)
    "phone" → "138xxxx"           (ts: 1704153600)

宽表模型设计
列族存储的表设计与关系数据库截然不同——需要根据查询模式来设计表结构。


设计原则




原则
说明





查询驱动设计
先确定查询模式，再设计表结构




反规范化
为不同查询创建不同的表（数据冗余）




行键设计至关重要
行键决定数据分布和查询效率




避免热点
行键不要以时间戳开头（导致写入热点）





-- Cassandra：为不同查询创建不同的表
-- 查询1：按用户查订单
CREATE TABLE orders_by_user (
    user_id    UUID,
    order_id   UUID,
    order_date TIMESTAMP,
    total      DECIMAL,
    PRIMARY KEY (user_id, order_date)
) WITH CLUSTERING ORDER BY (order_date DESC);

-- 查询2：按日期查订单
CREATE TABLE orders_by_date (
    order_date DATE,
    order_id   UUID,
    user_id    UUID,
    total      DECIMAL,
    PRIMARY KEY (order_date, order_id)
);


时间序列数据
列族存储天然适合时间序列数据场景。


-- Cassandra 时间序列表设计
CREATE TABLE sensor_data (
    sensor_id  TEXT,
    bucket     DATE,
    event_ts   TIMESTAMP,
    temperature DOUBLE,
    humidity   DOUBLE,
    PRIMARY KEY ((sensor_id, bucket), event_ts)
) WITH CLUSTERING ORDER BY (event_ts DESC)
  AND compaction = {'class': 'TimeWindowCompactionStrategy',
                    'compaction_window_size': 1,
                    'compaction_window_unit': 'DAYS'};

-- 查询某传感器某天的数据
SELECT * FROM sensor_data
WHERE sensor_id = 'S001' AND bucket = '2024-06-15'
AND event_ts >= '2024-06-15 08:00:00'
AND event_ts < '2024-06-15 18:00:00';

说明

小结
    

  • 列族存储以列族组织数据，LSM-Tree 引擎使其写入性能极高。
    • 

  • Cassandra 采用无中心架构和可调一致性，适合高可用写密集场景。
    • 

  • HBase 基于 HDFS 提供强一致性，适合 Hadoop 大数据生态。
    • 

  • 表设计必须查询驱动——为每种查询模式设计专用的表。
    • 

  • 行键设计是性能的关键，必须避免写入热点（不要以时间戳开头）。
