文档数据库

核心概念

文档数据库以"文档"为基本存储单元，文档通常是 JSON/BSON 格式的半结构化数据。与关系数据库的行不同，文档可以包含嵌套结构和数组，不需要预定义模式，天然适合存储复杂的业务对象。

MongoDB
MongoDB 是最流行的文档数据库，使用 BSON（Binary JSON）格式存储数据。


基本操作
// 插入文档
db.users.insertOne({
  name: 'alice',
  email: 'alice@example.com',
  age: 28,
  tags: ['developer', 'reader'],
  address: {
    city: '北京',
    district: '海淀',
  },
  createdAt: new Date(),
});

// 批量插入
db.orders.insertMany([
  { userId: ObjectId('...'), items: [{ name: '手机', qty: 1, price: 4999 }], total: 4999 },
  { userId: ObjectId('...'), items: [{ name: '耳机', qty: 2, price: 299 }], total: 598 },
]);

// 查询
db.users.find({ age: { $gte: 25 }, 'address.city': '北京' });

// 更新
db.users.updateOne({ name: 'alice' }, { $set: { age: 29 }, $push: { tags: 'writer' } });

// 删除
db.users.deleteMany({ status: 'inactive' });

嵌入 vs 引用
文档数据库中处理关联数据有两种核心策略：






策略
数据存储方式
优点
缺点





嵌入
嵌套在父文档中
一次读取，无 JOIN
文档过大，数据冗余




引用
存储 ObjectId 引用
避免冗余

// 嵌入模式：订单包含完整商品信息
{
  _id: ObjectId("..."),
  userId: ObjectId("..."),
  items: [
    { productId: "P001", name: "手机", price: 4999, qty: 1 },
    { productId: "P002", name: "保护壳", price: 49, qty: 2 }
  ],
  total: 5097,
  status: "completed"
}

// 引用模式：订单引用商品 ID
{
  _id: ObjectId("..."),
  userId: ObjectId("..."),
  items: [
    { productId: ObjectId("..."), qty: 1 },
    { productId: ObjectId("..."), qty: 2 }
  ],
  total: 5097
}

聚合管道
MongoDB 聚合管道是一系列数据处理阶段，类似于 Unix 管道。


// 统计每个城市的用户数和平均年龄
db.users.aggregate([
  { $match: { status: 'active' } },
  {
    $group: {
      _id: '$address.city',
      count: { $sum: 1 },
      avgAge: { $avg: '$age' },
    },
  },
  { $sort: { count: -1 } },
  { $limit: 10 },
]);

// 订单分析：按月统计销售额
db.orders.aggregate([
  { $match: { status: 'completed' } },
  { $unwind: '$items' },
  {
    $group: {
      _id: { $dateToString: { format: '%Y-%m', date: '$createdAt' } },
      totalRevenue: { $sum: { $multiply: ['$items.price', '$items.qty'] } },
      orderCount: { $sum: 1 },
    },
  },
  { $sort: { _id: 1 } },
]);

索引策略
// 单字段索引
db.users.createIndex({ email: 1 }, { unique: true });

// 复合索引
db.orders.createIndex({ userId: 1, createdAt: -1 });

// 文本索引
db.articles.createIndex({ title: 'text', content: 'text' });

// TTL 索引：自动过期删除
db.sessions.createIndex({ expireAt: 1 }, { expireAfterSeconds: 0 });


小结
    

  • 文档数据库以 JSON 文档为存储单元，灵活的 Schema 适合快速迭代。
    • 

  • 嵌入适合一对少量且一起读取的数据，引用适合独立更新的大量关联数据。
    • 

  • 聚合管道是 MongoDB 的数据分析利器，支持复杂的多阶段数据处理。
    • 

  • 模式设计需要根据查询模式而非数据关系来组织文档结构。
    • 

  • MongoDB 支持丰富的索引类型，TTL 索引可自动清理过期数据。
