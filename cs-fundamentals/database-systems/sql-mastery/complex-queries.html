复杂查询与子查询

子查询概述

子查询（Subquery）是嵌套在另一个 SQL 语句内部的查询。根据执行方式和返回结果的不同，子查询可以分为多种类型。

非关联子查询
非关联子查询可以独立于外层查询执行，执行引擎只需运行一次子查询即可。


-- 标量子查询：查找工资高于平均值的员工
SELECT name, salary
FROM employee
WHERE salary > (SELECT AVG(salary) FROM employee);

-- 表子查询：查找属于研发部门的员工
SELECT name, dept_id
FROM employee
WHERE dept_id IN (SELECT dept_id FROM department WHERE dept_name = '研发');


关联子查询
关联子查询引用了外层查询的列，因此对外层查询的每一行都会执行一次子查询。


-- 查找每个部门工资最高的员工
SELECT e.name, e.dept_id, e.salary
FROM employee e
WHERE e.salary = (
    SELECT MAX(e2.salary)
    FROM employee e2
    WHERE e2.dept_id = e.dept_id
);
关联子查询的执行代价通常较高，当外层结果集较大时应考虑改写为 JOIN。




EXISTS 与 IN
EXISTS 和 IN 都可以判断子查询中是否存在匹配的数据，但语义和性能特性不同。

-- IN：查找有订单的客户
SELECT name FROM customer
WHERE customer_id IN (SELECT customer_id FROM orders);

-- EXISTS：等价写法
SELECT name FROM customer c
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id);

-- NOT EXISTS：查找没有订单的客户
SELECT name FROM customer c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id);


CTE（公用表表达式）
CTE（Common Table Expression）用 WITH 关键字定义，是子查询的命名版本，提升了复杂查询的可读性和可维护性。


WITH high_salary AS (
    SELECT dept_id, AVG(salary) AS avg_salary
    FROM employee
    GROUP BY dept_id
    HAVING AVG(salary) > 10000
)
SELECT d.dept_name, hs.avg_salary
FROM high_salary hs
JOIN department d ON hs.dept_id = d.dept_id;

递归 CTE
递归 CTE 用于处理层级或图结构的数据，由锚定成员（初始条件）和递归成员（迭代条件）组成。


-- 组织架构：查找某经理下的所有下属
WITH RECURSIVE subordinates AS (
    SELECT emp_id, name, manager_id, 1 AS level
    FROM employee
    WHERE emp_id = 1001

    UNION ALL

    SELECT e.emp_id, e.name, e.manager_id, s.level + 1
    FROM employee e
    JOIN subordinates s ON e.manager_id = s.emp_id
)
SELECT emp_id, name, level
FROM subordinates
ORDER BY level, name;

连续日期

-- 生成连续日期序列
WITH RECURSIVE date_series AS (
    SELECT DATE('2024-01-01') AS dt
    UNION ALL
    SELECT DATE_ADD(dt, INTERVAL 1 DAY)
    FROM date_series
    WHERE dt < '2024-01-31'
)
SELECT dt FROM date_series;


子查询改写技巧
复杂子查询有时可以改写为 JOIN 以获得更好的性能：


-- 改写前：关联子查询
SELECT name, salary FROM employee e
WHERE salary > (SELECT AVG(salary) FROM employee e2 WHERE e2.dept_id = e.dept_id);

-- 改写后：JOIN + 聚合
SELECT e.name, e.salary
FROM employee e
JOIN (
    SELECT dept_id, AVG(salary) AS avg_salary
    FROM employee
    GROUP BY dept_id
) dept_avg ON e.dept_id = dept_avg.dept_id
WHERE e.salary > dept_avg.avg_salary;


小结
    

  • 非关联子查询独立执行一次，关联子查询逐行执行，性能差异显著
    • 

  • EXISTS 适合外层结果集小的场景，IN 适合子查询结果集小的场景
    • 

  • CTE 极大提升了复杂查询的可读性，推荐在多步骤查询中使用
    • 

  • 递归 CTE 是处理层级数据的利器，替代了传统的多次自连接
    • 

  • 善于将关联子查询改写为 JOIN 是 SQL 性能优化的重要技巧
