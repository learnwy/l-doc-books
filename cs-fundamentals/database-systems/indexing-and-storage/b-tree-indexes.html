B 树索引

核心概念

B+ 树是关系数据库中最核心的索引结构。它是一种平衡多路搜索树，所有数据存储在叶子节点，叶子节点之间通过链表相连，非常适合磁盘存储和范围查询。





特性
B+ 树
B 树





数据位置
仅在叶子节点
所有节点都可存数据




叶子链表
有，支持范围扫描
无




查询稳定性
每次查询都走到叶子，路径等长
路径长度不固定




扇出（Fan-out）
更高，非叶节点不存数据
较低




范围查询
高效，沿叶子链表遍历
需要中序遍历







聚簇索引与非聚簇索引
聚簇索引决定了表中数据的物理存储顺序。每个表只能有一个聚簇索引。






特性
聚簇索引
非聚簇索引（二级索引）





数据存储
叶子节点直接存储完整行数据
叶子节点存储主键值（回表）




数量限制
每表只能一个
每表可以有多个




查询效率
主键查询最快
需要回表查数据




插入性能
顺序插入最优（自增主键）
插入需维护索引




InnoDB 默认
主键即聚簇索引
其他索引均为二级索引





-- InnoDB 自动以主键创建聚簇索引
CREATE TABLE users (
    user_id BIGINT PRIMARY KEY,
    username VARCHAR(50),
    email VARCHAR(100)
);

-- 二级索引（非聚簇）
CREATE INDEX idx_username ON users(username);

-- 查询过程：
-- 1. 在 idx_username 中找到 username='alice' 对应的 user_id
-- 2. 用 user_id 回表到聚簇索引获取完整行（回表操作）
SELECT * FROM users WHERE username = 'alice';


复合索引
复合索引（联合索引）是在多个列上建立的索引，遵循最左前缀原则。


CREATE INDEX idx_composite ON orders(user_id, status, created_at);




查询条件
是否命中索引
说明





WHERE user_id = 1
✅ 完全命中
最左前缀




WHERE user_id = 1 AND status = 'active'
✅ 完全命中
前两列




WHERE user_id = 1 AND status = 'active' AND created_at > '2024-01-01'
✅ 完全命中
全部三列




WHERE status = 'active'
❌ 未命中
跳过了 user_id




WHERE user_id = 1 AND created_at > '2024-01-01'
⚠️ 部分命中
跳过了 status





索引列顺序设计原则
高选择性列优先 > 等值查询列优先 > 范围查询列靠后
-- 推荐：等值条件在前，范围条件在后
CREATE INDEX idx_optimized ON orders(status, user_id, created_at);
-- 适用于：WHERE status = 'active' AND user_id = 1 AND created_at > '2024-01-01'


覆盖索引
当索引包含了查询所需的全部列时，数据库可以直接从索引中返回结果，无需回表——这就是覆盖索引（Index Only Scan）。


CREATE INDEX idx_covering ON orders(user_id, status, total);

-- 覆盖索引：所有列都在索引中，无需回表
SELECT user_id, status, total FROM orders WHERE user_id = 1001;

-- 非覆盖：需要 created_at 列，必须回表
SELECT user_id, status, total, created_at FROM orders WHERE user_id = 1001;


索引选择策略




场景
建议





主键查询
默认有聚簇索引，无需额外创建




WHERE 等值过滤
在过滤列上创建索引




JOIN 连接列
在外键列上创建索引




ORDER BY 排序
索引顺序与排序方向一致




高基数列
适合建索引（如 user_id）




低基数列
不适合 B+ 树索引（如 gender）




频繁更新列
谨慎建索引，增加写入开销





索引维护
-- 查看索引使用情况（PostgreSQL）
SELECT indexrelname, idx_scan, idx_tup_read
FROM pg_stat_user_indexes
WHERE schemaname = 'public'
ORDER BY idx_scan ASC;

-- 删除未使用的索引
DROP INDEX IF EXISTS idx_unused;

-- 重建索引（消除碎片）
REINDEX INDEX idx_orders_user_id;

小结
    

  • B+ 树是关系数据库最核心的索引结构，叶子链表使其擅长范围查询。
    • 

  • 聚簇索引决定物理存储顺序，InnoDB 中主键即聚簇索引。
    • 

  • 复合索引遵循最左前缀原则，列顺序设计至关重要。
    • 

  • 覆盖索引避免回表操作，是查询优化的高效手段。
    • 

  • 索引不是越多越好，需要在读取加速和写入开销之间权衡。
