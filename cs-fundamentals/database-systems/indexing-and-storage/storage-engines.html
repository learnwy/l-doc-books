存储引擎

核心概念

存储引擎是数据库管理系统中负责数据存储、检索和管理的核心组件。不同的存储引擎在数据组织方式、事务支持、并发控制和性能特性上有显著差异，选择合适的引擎直接影响系统的整体表现。

SHOW TABLE STATUS LIKE 'orders'\G

CREATE TABLE logs (

    message TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

-- 修改已有表的引擎
ALTER TABLE legacy_table ENGINE=InnoDB;
InnoDB 架构


LSM-Tree
LSM-Tree（Log-Structured Merge-Tree）是一种针对写入优化的数据结构，被 RocksDB、LevelDB、Cassandra、HBase 等广泛采用。


LSM-Tree 工作原理
    

  1. 写入：数据先写入内存中的 MemTable（通常是跳表或红黑树）
    2. 

  2. 刷盘：MemTable 写满后转为 Immutable MemTable，刷写到磁盘的 SSTable
    3. 

  3. 合并：后台 Compaction 线程将多个 SSTable 合并，消除重复和删除标记
    4. 

  4. 读取：先查 MemTable → 再查各层 SSTable（Bloom Filter 加速）
    5.

WAL 是数据库保证持久性和崩溃恢复的核心机制：先写日志，后写数据。

页面管理
数据库以**页（Page）**为最小 I/O 单位管理数据，通常为 8KB（PostgreSQL）或 16KB（InnoDB）。






概念
说明





数据页
存储表数据的基本单位




索引页
存储 B+ 树索引节点




页分裂
页满时分裂为两个页，影响插入性能




页合并
页利用率过低时合并，减少空间浪费




填充因子
预留空间比例，减少页分裂频率





-- PostgreSQL：设置填充因子
CREATE TABLE hot_data (
    id SERIAL PRIMARY KEY,
    value TEXT
) WITH (fillfactor = 80);

-- MySQL：查看 InnoDB 页大小
SHOW VARIABLES LIKE 'innodb_page_size';


缓冲池（Buffer Pool）
缓冲池是数据库最重要的内存组件，缓存频繁访问的数据页，减少磁盘 I/O。






参数
说明
推荐值





innodb_buffer_pool_size
缓冲池总大小
物理内存的 70-80%




innodb_buffer_pool_instances
缓冲池实例数
CPU 核心数




effective_cache_size
PostgreSQL 缓存估算
物理内存的 50-75%




shared_buffers
PostgreSQL 共享缓冲区
物理内存的 25%





-- MySQL：查看缓冲池状态
SHOW STATUS LIKE 'Innodb_buffer_pool%';

-- 关键指标
-- Innodb_buffer_pool_read_requests  缓冲池读请求数
-- Innodb_buffer_pool_reads          需要从磁盘读取的次数
-- 命中率 = 1 - reads / read_requests（应 > 99%）

-- PostgreSQL：查看缓冲区命中率
SELECT
    sum(heap_blks_hit) / (sum(heap_blks_hit) + sum(heap_blks_read)) AS hit_ratio
FROM pg_statio_user_tables;


小结
    

  • InnoDB 是 MySQL 的默认引擎，支持事务、行级锁和 MVCC，适合 OLTP 场景。
    • 

  • LSM-Tree 通过顺序写优化写入性能，适合日志、时序等写密集场景。
    • 

  • WAL 机制（先写日志后写数据）是数据库保证持久性和崩溃恢复的基石。
    • 

  • 缓冲池命中率应保持在 99% 以上，是性能调优的关键指标。
    • 

  • 存储引擎的选择应根据读写比例、事务需求和数据规模综合决定。
