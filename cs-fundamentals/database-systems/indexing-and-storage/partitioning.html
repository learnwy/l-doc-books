分区与分片

核心概念

当单表数据量增长到千万甚至亿级时，查询性能和维护效率会显著下降。分区（Partitioning）和分片（Sharding）是解决大数据量问题的两种关键策略：分区在单机内拆分表，分片跨多机分布数据。

概念 作用域 对应用透明 扩展方式
分区 单数据库内 是 垂直扩展
分片 跨数据库 通常否 水平扩展 


水平分区与垂直分区

-- 垂直分区示例：将大字段分离
-- 原表
CREATE TABLE articles (
    id BIGINT PRIMARY KEY,
    title VARCHAR(200),
    content TEXT,
    author_id BIGINT,
    created_at TIMESTAMP
);

-- 垂直拆分
CREATE TABLE article_meta (
    id BIGINT PRIMARY KEY,
    title VARCHAR(200),
    author_id BIGINT,
    created_at TIMESTAMP
);

CREATE TABLE article_content (
    id BIGINT PRIMARY KEY REFERENCES article_meta(id),
    content TEXT
);


分区类型
范围分区（Range Partitioning）
按连续值范围划分，最适合时间序列数据。


-- PostgreSQL：按时间范围分区
CREATE TABLE orders (
    order_id    BIGSERIAL,
    user_id     BIGINT NOT NULL,
    total       DECIMAL(12, 2),
    created_at  TIMESTAMP NOT NULL
) PARTITION BY RANGE (created_at);

CREATE TABLE orders_2024_q1 PARTITION OF orders
    FOR VALUES FROM ('2024-01-01') TO ('2024-04-01');
CREATE TABLE orders_2024_q2 PARTITION OF orders
    FOR VALUES FROM ('2024-04-01') TO ('2024-07-01');
CREATE TABLE orders_2024_q3 PARTITION OF orders
    FOR VALUES FROM ('2024-07-01') TO ('2024-10-01');
CREATE TABLE orders_2024_q4 PARTITION OF orders
    FOR VALUES FROM ('2024-10-01') TO ('2025-01-01');

-- 查询自动路由到对应分区
SELECT * FROM orders WHERE created_at >= '2024-04-01' AND created_at < '2024-07-01';
哈希分区（Hash Partitioning）
按哈希值均匀分布，适合数据分布不均的场景。


-- PostgreSQL：哈希分区
CREATE TABLE user_events (
    event_id BIGSERIAL,
    user_id  BIGINT NOT NULL,
    event    VARCHAR(50),
    ts       TIMESTAMP
) PARTITION BY HASH (user_id);

CREATE TABLE user_events_p0 PARTITION OF user_events FOR VALUES WITH (MODULUS 4, REMAINDER 0);
CREATE TABLE user_events_p1 PARTITION OF user_events FOR VALUES WITH (MODULUS 4, REMAINDER 1);
CREATE TABLE user_events_p2 PARTITION OF user_events FOR VALUES WITH (MODULUS 4, REMAINDER 2);
CREATE TABLE user_events_p3 PARTITION OF user_events FOR VALUES WITH (MODULUS 4, REMAINDER 3);
列表分区（List Partitioning）
按离散值列表划分，适合枚举类型字段。


-- PostgreSQL：列表分区
CREATE TABLE customers (
    id      BIGSERIAL,
    name    VARCHAR(100),
    region  VARCHAR(20) NOT NULL
) PARTITION BY LIST (region);

CREATE TABLE customers_east  PARTITION OF customers FOR VALUES IN ('华东', '华南');
CREATE TABLE customers_west  PARTITION OF customers FOR VALUES IN ('西北', '西南');
CREATE TABLE customers_north PARTITION OF customers FOR VALUES IN ('华北', '东北');

-- Snowflake ID 生成示例（PostgreSQL）
CREATE SEQUENCE global_id_seq;

CREATE OR REPLACE FUNCTION snowflake_id() RETURNS BIGINT AS $$
DECLARE
    epoch BIGINT := 1704067200000;
    seq_id BIGINT;
    now_ms BIGINT;
    shard_id INT := 1;
    result BIGINT;
BEGIN
    SELECT nextval('global_id_seq') % 4096 INTO seq_id;
    SELECT FLOOR(EXTRACT(EPOCH FROM clock_timestamp()) * 1000) INTO now_ms;
    result := (now_ms - epoch) << 22;
    result := result | (shard_id << 12);
    result := result | seq_id;
    RETURN result;
END;
$$ LANGUAGE plpgsql;


小结
    

  • 分区在单机内拆分大表，对应用透明，是处理亿级数据的第一选择。
    • 

  • 范围分区最适合时间序列数据，哈希分区保证数据均匀分布。
    • 

  • 分片跨多个数据库实例分布数据，是水平扩展的核心手段。
    • 

  • 分片键选择至关重要：高基数、高查询频率、避免热点。
    • 

  • 一致性哈希是生产环境中最常用的分片算法，扩容时只需迁移少量数据。
