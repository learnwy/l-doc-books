锁机制

核心概念

锁是数据库实现并发控制的基本手段，用于协调多个事务对同一数据的访问。锁的设计需要在数据一致性和并发性能之间取得平衡。

-- Record Lock：精确行锁
SELECT * FROM accounts WHERE id = 1 FOR UPDATE;

-- Gap Lock：间隙锁（REPEATABLE READ 下）
-- 假设 id 有值 1, 5, 10
SELECT * FROM accounts WHERE id BETWEEN 3 AND 7 FOR UPDATE;
-- 锁定间隙 (1, 5) 和 (5, 10)，阻止在此范围内插入

-- Next-Key Lock：InnoDB 默认行为
-- 锁定记录 + 之前的间隙
SELECT * FROM accounts WHERE id > 5 FOR UPDATE;
行锁与索引的关系
-- 有索引：行级锁
SELECT * FROM users WHERE id = 100 FOR UPDATE;

-- 无索引：退化为表锁（全表扫描需锁定所有行）
SELECT * FROM users WHERE name = 'alice' FOR UPDATE;
-- 如果 name 列无索引，InnoDB 会锁定所有扫描到的行

死锁
当两个或多个事务互相等待对方释放锁时，形成死锁（Deadlock）。


-- 死锁示例
-- 事务 A                          -- 事务 B
BEGIN;                             BEGIN;
UPDATE accounts SET balance = 100
    WHERE id = 1;                  UPDATE accounts SET balance = 200
                                       WHERE id = 2;
UPDATE accounts SET balance = 100
    WHERE id = 2;                  UPDATE accounts SET balance = 200
-- 等待事务 B 释放 id=2 的锁          WHERE id = 1;
                                   -- 等待事务 A 释放 id=1 的锁
-- 死锁！

避免死锁的实践
-- 实践1：按固定顺序访问表和行
-- 总是先锁 id 小的，再锁 id 大的
BEGIN;
SELECT * FROM accounts WHERE id = 1 FOR UPDATE;
SELECT * FROM accounts WHERE id = 2 FOR UPDATE;
COMMIT;

-- 实践2：缩小事务范围
-- 不要在事务中做耗时操作（如网络请求）

-- 实践3：使用合适的索引避免锁升级
CREATE INDEX idx_status ON orders(status);

悲观锁实现
-- FOR UPDATE：排他锁
BEGIN;
SELECT stock FROM products WHERE id = 100 FOR UPDATE;
-- 其他事务读取该行会被阻塞
UPDATE products SET stock = stock - 1 WHERE id = 100;
COMMIT;

-- FOR SHARE：共享锁（允许其他事务读，但不能写）
BEGIN;
SELECT * FROM products WHERE id = 100 FOR SHARE;
-- 其他事务可以 FOR SHARE，但不能 FOR UPDATE
COMMIT;

-- SKIP LOCKED：跳过已锁定的行（队列场景）
SELECT * FROM tasks WHERE status = 'pending'
ORDER BY created_at
LIMIT 1
FOR UPDATE SKIP LOCKED;
乐观锁实现
-- 方案1：版本号
ALTER TABLE products ADD COLUMN version INT DEFAULT 0;

-- 读取
SELECT id, stock, version FROM products WHERE id = 100;
-- 返回 stock=10, version=5

-- 更新时检查版本号
UPDATE products
SET stock = stock - 1, version = version + 1
WHERE id = 100 AND version = 5;
-- 如果受影响行数 = 0，说明被其他事务修改过，需要重试

-- 方案2：CAS（Compare And Swap）
UPDATE products SET stock = 9
WHERE id = 100 AND stock = 10;


锁粒度选择指南


小结
    

  • 行锁是 InnoDB 的默认锁粒度，加在索引上，无索引退化为表锁。
    • 

  • 间隙锁防止幻读，是 InnoDB REPEATABLE READ 的关键机制。
    • 

  • 死锁不可避免，应通过固定加锁顺序、缩小事务范围来降低发生概率。
    • 

  • 悲观锁适合高冲突场景，乐观锁适合读多写少的低冲突场景。
    • 

  • SKIP LOCKED 是实现并发任务队列的高效手段。
    •
