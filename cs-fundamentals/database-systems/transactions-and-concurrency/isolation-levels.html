Part IV · 网络与分布式 (Networks & Distributed)数据库系统 简介事务与并发控制 简介隔离级别

隔离级别

核心概念

SQL 标准定义了四种事务隔离级别，从低到高依次增强隔离性但降低并发性能。隔离级别的选择是正确性与性能之间的权衡。

隔离级别 脏读 不可重复读 幻读 性能
READ UNCOMMITTED ✅ ✅ ✅ 最高
READ COMMITTED ❌ ✅ ✅ 高
REPEATABLE READ ❌ ❌ ✅ 中
SERIALIZABLE ❌ ❌ ❌ 最低

✅ 表示可能发生，❌ 表示不会发生

READ UNCOMMITTED（读未提交）

最低的隔离级别，事务可以读取其他事务尚未提交的数据（脏读）。

-- 事务 A
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
BEGIN;
SELECT balance FROM accounts WHERE id = 1;
-- 返回 1000

-- 事务 B（尚未提交）
BEGIN;
UPDATE accounts SET balance = 500 WHERE id = 1;

-- 事务 A 再次读取
SELECT balance FROM accounts WHERE id = 1;
-- 返回 500（脏读：读到了未提交的数据）

-- 事务 B 回滚
ROLLBACK;
-- 事务 A 读到的 500 是无效数据

实际应用中几乎不使用此级别，仅用于特殊的只读统计场景。

READ COMMITTED（读已提交）

只能读取已提交事务的数据，避免了脏读，但同一事务内两次读取可能得到不同结果（不可重复读）。

-- 事务 A
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
BEGIN;
SELECT balance FROM accounts WHERE id = 1;
-- 返回 1000

-- 事务 B
BEGIN;
UPDATE accounts SET balance = 500 WHERE id = 1;
COMMIT;

-- 事务 A 再次读取
SELECT balance FROM accounts WHERE id = 1;
-- 返回 500（不可重复读：同一事务内两次读结果不同）
COMMIT;
数据库 默认隔离级别
PostgreSQL READ COMMITTED
Oracle READ COMMITTED
SQL Server READ COMMITTED
MySQL/InnoDB REPEATABLE READ

REPEATABLE READ（可重复读）

保证同一事务内多次读取同一行的结果一致，但范围查询可能出现幻读。

-- 事务 A
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
BEGIN;
SELECT COUNT(*) FROM orders WHERE user_id = 1;
-- 返回 5

-- 事务 B
BEGIN;
INSERT INTO orders (user_id, total) VALUES (1, 99.00);
COMMIT;

-- 事务 A 再次查询
SELECT COUNT(*) FROM orders WHERE user_id = 1;
-- 标准 SQL：可能返回 6（幻读）
-- InnoDB：仍返回 5（通过间隙锁/MVCC 防止幻读）
COMMIT;

InnoDB 的 REPEATABLE READ

MySQL InnoDB 的 REPEATABLE READ 实际上通过 MVCC + 间隙锁 解决了大部分幻读问题，比 SQL 标准更严格。

操作类型 InnoDB REPEATABLE READ 行为
快照读（SELECT） MVCC，读取事务开始时的快照
当前读（SELECT FOR UPDATE） 加间隙锁，阻止其他事务插入
INSERT 检查间隙锁，可能被阻塞

SERIALIZABLE（串行化）

最高隔离级别，完全避免所有并发问题，等效于事务串行执行。

SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
BEGIN;
SELECT * FROM accounts WHERE balance > 1000;
-- 此查询会对满足条件的范围加锁
-- 其他事务无法在此范围内插入或修改
COMMIT;
实现方式 说明 数据库
两阶段锁（2PL） 读写都加锁，锁到事务结束 MySQL SERIALIZABLE
SSI（可串行化快照） 基于 MVCC + 冲突检测 PostgreSQL

MVCC（多版本并发控制）

MVCC 是实现隔离级别的核心技术，允许读操作不阻塞写操作、写操作不阻塞读操作。

ReadView 机制
事务启动时创建 ReadView，包含：
- creator_trx_id: 当前事务 ID
- m_ids: 活跃事务 ID 列表
- min_trx_id: 最小活跃事务 ID
- max_trx_id: 下一个将分配的事务 ID

可见性判断规则：
1. 行的 trx_id < min_trx_id → 可见（已提交）
2. 行的 trx_id >= max_trx_id → 不可见（未来事务）
3. 行的 trx_id 在 m_ids 中 → 不可见（活跃未提交）
4. 行的 trx_id 不在 m_ids 中 → 可见（已提交）

小结
    

  • READ COMMITTED 是 PostgreSQL 和 Oracle 的默认级别，适合大多数 OLTP 场景。
    • 

  • REPEATABLE READ 是 MySQL 的默认级别，InnoDB 通过 MVCC + 间隙锁额外防止幻读。
    • 

  • MVCC 是现代数据库实现隔离性的核心技术，通过多版本实现读写不互相阻塞。
    • 

  • SERIALIZABLE 保证最强隔离性，但并发性能最低，仅在对数据一致性要求极高时使用。
    • 

  • 隔离级别的选择需根据业务容忍度和性能要求综合决定。
