ACID 特性

核心概念

ACID 是关系数据库事务的四大基本特性，保证了数据在并发访问和系统故障下的正确性和可靠性。ACID 是数据库区别于普通文件系统的核心优势。

特性 英文 含义
原子性 Atomicity 事务中的操作要么全部成功，要么全部回滚
一致性 Consistency 事务前后数据库从一个一致状态转到另一个
隔离性 Isolation 并发事务之间互不干扰
持久性 Durability 已提交事务的结果永久保存 


原子性（Atomicity）
原子性确保事务是一个不可分割的工作单元。如果事务中任何操作失败，所有已执行的操作都会被回滚。


-- 转账事务：要么全部成功，要么全部回滚
BEGIN;

UPDATE accounts SET balance = balance - 1000 WHERE account_id = 'A001';
UPDATE accounts SET balance = balance + 1000 WHERE account_id = 'B001';

INSERT INTO transaction_log (from_acct, to_acct, amount, txn_time)
VALUES ('A001', 'B001', 1000, NOW());

COMMIT;

-- 回滚示例
BEGIN;
UPDATE products SET stock = stock - 1 WHERE product_id = 100;
-- 发现库存不足，回滚
ROLLBACK;

-- SAVEPOINT：部分回滚
BEGIN;
UPDATE accounts SET balance = balance - 500 WHERE account_id = 'A001';
SAVEPOINT sp1;
UPDATE accounts SET balance = balance + 500 WHERE account_id = 'B001';
-- 发现 B001 账户冻结
ROLLBACK TO sp1;
UPDATE accounts SET balance = balance + 500 WHERE account_id = 'C001';
COMMIT;


一致性（Consistency）
一致性确保事务将数据库从一个有效状态转换到另一个有效状态。所有定义的约束（主键、外键、CHECK 等）在事务前后都必须满足。

隔离性（Isolation）
隔离性确保并发执行的事务彼此不受影响，就像串行执行一样。不同的隔离级别在性能和正确性之间做出不同的权衡。






并发问题
描述





脏读
读到其他事务未提交的数据




不可重复读
同一事务内两次读取同一行结果不同




幻读
同一事务内两次范围查询结果集不同




丢失更新
两个事务同时修改同一行，一个覆盖另一个





-- 脏读示例
-- 事务A                          -- 事务B
BEGIN;                             BEGIN;
UPDATE accounts SET balance = 500
    WHERE id = 1;
                                   SELECT balance FROM accounts WHERE id = 1;
                                   -- 读到 500（未提交数据）= 脏读
ROLLBACK;
                                   -- 实际 balance 未变，但 B 已读到错误值


持久性（Durability）
持久性保证一旦事务提交成功，其结果就是永久的，即使系统发生崩溃也不会丢失。

事务生命周期
-- 完整事务生命周期
BEGIN;

UPDATE inventory SET quantity = quantity - 1 WHERE product_id = 100;

IF (SELECT quantity FROM inventory WHERE product_id = 100) < 0 THEN
    ROLLBACK;
ELSE
    INSERT INTO order_items (order_id, product_id, quantity) VALUES (1, 100, 1);
    COMMIT;
END IF;

小结
    

  • 原子性通过 Undo Log 实现，保证事务的"全有或全无"。
    • 

  • 一致性是最终目标，由数据库约束和应用逻辑共同保证。
    • 

  • 隔离性通过锁机制和 MVCC 实现，不同隔离级别有不同的性能权衡。
    • 

  • 持久性通过 WAL + fsync 保证，innodb_flush_log_at_trx_commit=1 是最安全的配置。
    • 

  • 崩溃恢复遵循分析 → 重做 → 撤销三阶段流程。
