Part IV · 网络与分布式 (Networks & Distributed)数据库系统 简介关系模型基础 简介数据完整性

数据完整性

核心概念

数据完整性（Data Integrity）是指数据库中数据的准确性、一致性和可靠性。关系数据库通过多种约束机制来保障数据完整性，防止无效数据进入系统。

完整性类型 保障对象 机制
实体完整性 主键唯一且非空 PRIMARY KEY
参照完整性 外键引用有效 FOREIGN KEY
域完整性 列值在合法范围 CHECK、NOT NULL、数据类型
用户定义完整性 业务规则 触发器、存储过程

实体完整性

实体完整性要求每个表都有主键，且主键值唯一且不为空。

CREATE TABLE employee (
    emp_id    INT PRIMARY KEY,
    name      VARCHAR(50) NOT NULL,
    email     VARCHAR(100) UNIQUE
);

-- 复合主键
CREATE TABLE order_item (
    order_id   BIGINT,
    product_id BIGINT,
    quantity   INT NOT NULL,
    PRIMARY KEY (order_id, product_id)
);
约束 作用 允许 NULL 允许重复
PRIMARY KEY 唯一标识每一行 否 否
UNIQUE 确保列值唯一 是（单个） 否
NOT NULL 确保列不为空 否 是

参照完整性

参照完整性通过外键约束确保表之间引用关系的有效性——外键值必须在被引用表的主键中存在，或者为 NULL。

CREATE TABLE department (
    dept_id   INT PRIMARY KEY,
    dept_name VARCHAR(50) NOT NULL
);

CREATE TABLE employee (
    emp_id  INT PRIMARY KEY,
    name    VARCHAR(50) NOT NULL,
    dept_id INT,
    FOREIGN KEY (dept_id) REFERENCES department(dept_id)
        ON DELETE SET NULL
        ON UPDATE CASCADE
);

级联操作

当被引用表的记录发生变更时，外键约束可以指定不同的级联行为：

级联策略 ON DELETE 行为 ON UPDATE 行为
RESTRICT 拒绝删除（默认） 拒绝更新（默认）
CASCADE 同步删除引用行 同步更新外键值
SET NULL 将外键设为 NULL 将外键设为 NULL
SET DEFAULT 将外键设为默认值 将外键设为默认值
NO ACTION 延迟检查，事务结束时验证 延迟检查，事务结束时验证 
-- 级联删除：删除部门时同步删除所有员工
CREATE TABLE employee_cascade (
    emp_id  INT PRIMARY KEY,
    name    VARCHAR(50),
    dept_id INT,
    FOREIGN KEY (dept_id) REFERENCES department(dept_id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);

-- 置空策略：删除部门时员工的 dept_id 设为 NULL
CREATE TABLE employee_setnull (
    emp_id  INT PRIMARY KEY,
    name    VARCHAR(50),
    dept_id INT,
    FOREIGN KEY (dept_id) REFERENCES department(dept_id)
        ON DELETE SET NULL
);

域完整性

域完整性确保列的值满足数据类型和取值范围约束。

CREATE TABLE product (
    product_id   SERIAL PRIMARY KEY,
    name         VARCHAR(100) NOT NULL,
    price        DECIMAL(10, 2) CHECK (price > 0),
    stock        INT DEFAULT 0 CHECK (stock >= 0),
    status       VARCHAR(20) CHECK (status IN ('active', 'inactive', 'discontinued')),
    created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
约束方式 用途 示例
数据类型 限制值的基本类型 INT、VARCHAR、DATE
CHECK 自定义取值条件 CHECK (age BETWEEN 0 AND 150)
DEFAULT 提供默认值 DEFAULT CURRENT_TIMESTAMP
ENUM/域类型 限制为预定义值集合 ENUM('M', 'F')

用户定义完整性

当内置约束无法满足复杂业务规则时，使用触发器实现自定义完整性检查。

触发器实现业务规则

-- 确保订单总额不超过用户信用额度
CREATE OR REPLACE FUNCTION check_credit_limit()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.total_amount > (
        SELECT credit_limit FROM users WHERE user_id = NEW.user_id
    ) THEN
        RAISE EXCEPTION '订单金额超出信用额度';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_credit_check
    BEFORE INSERT OR UPDATE ON orders
    FOR EACH ROW
    EXECUTE FUNCTION check_credit_limit();

触发器类型对比

触发时机 行级 / 语句级 典型用途
BEFORE INSERT 行级 数据校验、自动填充
AFTER INSERT 行级 审计日志、同步更新
BEFORE UPDATE 行级 检查变更合法性
AFTER DELETE 行级 级联清理、归档
INSTEAD OF 行级 视图上的 DML 操作（可更新视图）

综合约束设计示例

CREATE TABLE bank_account (
    account_id   BIGINT PRIMARY KEY,
    owner_name   VARCHAR(100) NOT NULL,
    balance      DECIMAL(15, 2) NOT NULL DEFAULT 0.00
                 CHECK (balance >= 0),
    account_type VARCHAR(20) NOT NULL
                 CHECK (account_type IN ('savings', 'checking', 'credit')),
    status       VARCHAR(10) NOT NULL DEFAULT 'active'
                 CHECK (status IN ('active', 'frozen', 'closed')),
    created_at   TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    branch_id    INT NOT NULL,
    FOREIGN KEY (branch_id) REFERENCES branch(branch_id)
        ON DELETE RESTRICT
        ON UPDATE CASCADE
);

CREATE TABLE transaction_log (
    txn_id       BIGSERIAL PRIMARY KEY,
    from_account BIGINT NOT NULL,
    to_account   BIGINT NOT NULL,
    amount       DECIMAL(15, 2) NOT NULL CHECK (amount > 0),
    txn_time     TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (from_account) REFERENCES bank_account(account_id),
    FOREIGN KEY (to_account) REFERENCES bank_account(account_id),
    CHECK (from_account <> to_account)
);

约束策略选择

策略 优点 缺点 适用场景
数据库约束 强制执行，不可绕过 灵活性低，迁移复杂 核心数据一致性
应用层校验 灵活，可定制 可被绕过 用户输入验证
触发器 能实现复杂逻辑 调试困难，隐式执行 跨表业务规则
应用 + 数据库 双重保障 维护成本高 金融等高可靠场景

小结

    

  • 实体完整性通过主键保证每行的唯一标识。
    • 

  • 参照完整性通过外键和级联策略维护表间引用关系的有效性。
    • 

  • 域完整性通过 CHECK、NOT NULL 等约束限制列的取值范围。
    • 

  • 触发器是实现复杂业务规则的利器，但应谨慎使用避免隐式行为。
    • 

  • 推荐采用数据库约束 + 应用层校验的双重保障策略。
