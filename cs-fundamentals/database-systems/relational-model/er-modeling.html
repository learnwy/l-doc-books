ER 建模

核心概念

实体-关系模型（Entity-Relationship Model，简称 ER 模型）是数据库概念设计的标准方法。它使用实体、属性和联系三个基本概念来描述现实世界的数据结构，是从需求分析到逻辑设计的桥梁。



基本要素
实体与实体集
实体是现实世界中可以区分的对象。同类实体的集合称为实体集。






要素
说明
示例





强实体
可独立存在，有自己的主键
学生、课程、部门




弱实体
依赖于强实体才能存在
家属（依赖于员工）




实体集
同类型实体的集合
所有学生构成"学生"实体集





属性类型




属性类型
定义
示例





简单属性
不可再分的原子值
年龄、性别




复合属性
可拆分为更小的部分
地址 → 省、市、区




多值属性
一个实体可有多个值
电话号码（可有多个）




派生属性
由其他属性计算得出
年龄（由出生日期推导）




键属性
唯一标识实体的属性
学号、身份证号





联系与联系集
联系描述实体之间的语义关联。




联系的基数
基数（Cardinality）描述联系中实体参与的数量比例，是 ER 建模中最关键的决策之一。






基数类型
含义
示例





一对一
每个实体最多关联一个对方实体
员工 ↔ 工位




一对多
一个实体关联多个对方实体
部门 → 员工




多对多
双方实体可关联多个对方实体
学生 ↔ 课程





参与约束




约束类型
含义
ER 图表示





全参与
实体集中每个实体都参与
双线连接




部分参与
仅部分实体参与联系
单线连接

ER 到关系模型转换
ER 模型设计完成后，需要转换为关系数据库中的表结构。






ER 元素
转换规则





强实体
直接映射为一张表，键属性作为主键




弱实体
映射为表，主键 = 自身部分键 + 所属强实体主键




一对一联系
任一方添加外键，或合并为一张表




一对多联系
"多"方添加外键指向"一"方




多对多联系
创建中间表（关联表），包含双方主键作为外键




多值属性
创建独立的表




复合属性
展开为多个简单属性列





转换示例
-- 强实体 → 表
CREATE TABLE department (
    dept_id   INT PRIMARY KEY,
    dept_name VARCHAR(50) NOT NULL
);

-- 一对多联系 → 外键
CREATE TABLE employee (
    emp_id    INT PRIMARY KEY,
    name      VARCHAR(50) NOT NULL,
    dept_id   INT,
    FOREIGN KEY (dept_id) REFERENCES department(dept_id)
);

-- 弱实体 → 复合主键
CREATE TABLE dependent (
    emp_id         INT,
    dependent_name VARCHAR(50),
    relationship   VARCHAR(20),
    PRIMARY KEY (emp_id, dependent_name),
    FOREIGN KEY (emp_id) REFERENCES employee(emp_id)
);

-- 多对多联系 → 中间表
CREATE TABLE student_course (
    student_id VARCHAR(10),
    course_id  VARCHAR(10),
    grade      INT,
    PRIMARY KEY (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES student(student_id),
    FOREIGN KEY (course_id) REFERENCES course(course_id)
);


建模常见陷阱




陷阱
描述
解决方案





扇形陷阱
从一个实体通过两个一对多联系
调整联系路径或增加直接联系




裂缝陷阱
联系路径不完整导致信息丢失
添加缺失的联系




过度设计
将简单属性建模为独立实体
遵循 KISS 原则




冗余联系
可通过现有联系推导的重复联系
删除冗余联系







小结
    

  • ER 模型使用实体、属性、联系三要素描述数据结构，是概念设计的核心工具。
    • 

  • 基数约束（一对一、一对多、多对多）决定了表之间的关联方式。
    • 

  • ER 到关系模型的转换规则明确，多对多联系必须通过中间表实现。
    • 

  • 弱实体的主键由自身部分键和所属强实体的主键共同组成。
    • 

  • 设计时需警惕扇形陷阱和裂缝陷阱，确保联系路径的完整性。
    •
