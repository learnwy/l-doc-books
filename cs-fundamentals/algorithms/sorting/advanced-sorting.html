高效排序

高效排序算法是算法学习的核心内容。与基础排序（冒泡、选择、插入）的 O(n2)O(n^2)O(n2) 时间复杂度相比，本章介绍的三种算法都能在 O(nlog⁡n)O(n \log n)O(nlogn) 的时间内完成排序，是工程实践中最常用的排序方案。

flowchart LR
    A["Efficient Sorting Algorithms"] --> B["Merge Sort<br/>Divide & Conquer + Stable"]
    A --> C["Quick Sort<br/>Partition + In-place"]
    A --> D["Heap Sort<br/>Heap + In-place"]
    B --> E["O(n log n)<br/>Stable ✅"]
    C --> F["O(n log n) avg<br/>Unstable ❌"]
    D --> G["O(n log n)<br/>Unstable ❌"]

核心概念

高效排序算法围绕三个关键维度展开，理解它们即可把握三种算法的取舍：

  • O(nlog⁡n)O(n \log n)O(nlogn) 是比较排序的理论下界：任何仅靠元素两两比较来确定顺序的排序算法，最坏情况都不可能低于 Ω(nlog⁡n)\Omega(n \log n)Ω(nlogn)（基于决策树模型）。归并、快排、堆排都达到了这一下界，因此都是"最优"的比较排序。想要再快，就必须像非比较排序那样利用数据本身的额外信息。
  • 分治 vs 原地调整：归并排序用"分治 + 合并"的框架，把问题层层二分后合并有序子数组，逻辑清晰但需要 O(n)O(n)O(n) 的额外空间；快排与堆排则在原数组上就地调整，空间开销为 O(1)O(1)O(1)。
  • 稳定性：归并排序在合并时保证相等元素的相对顺序，因而稳定；快排的划分与堆排的交换都可能跨过相等元素，因而不稳定。
  • 最坏情况的确定性：归并排序与堆排序在任何输入下都严格是 O(nlog⁡n)O(n \log n)O(nlogn)；快排的性能取决于枢轴（pivot）选择，选得不好会退化到 O(n2)O(n^2)O(n2)（可用随机化或三数取中缓解）。

常见误解：归并排序"总是比快排慢"并不成立——快排的常数更小、缓存更友好，因而在平均情况下通常更快，但它没有最坏情况保证；归并排序的稳定性与确定性在需要严格保证时反而关键。

归并排序（Merge Sort）

核心思想

归并排序是**分治法（Divide and Conquer）**的经典应用。其策略是：

  1. 分（Divide）：将数组从中间一分为二，递归地对左右两半分别排序。
  2. 治（Conquer）：将两个已排序的子数组合并为一个有序数组。

由于每次合并时，相等元素的相对顺序保持不变，归并排序是稳定排序。

    A --> C[[9, 82, 10]"]
    B --> D[[38, 27]"]
    B --> E[[43, 3]"]
    C --> F[[9, 82]"]
    C --> G[[10]"]
    D --> H[[27, 38]"]
    E --> I[[3, 43]"]
    F --> J[[9, 82]"]
    G --> K[[10]"]
    H --> L[[3, 27, 38, 43]"]
    I --> L
    J --> M[[9, 10, 82]"]
    K --> M
    L --> N[[3, 9, 10, 27, 38, 43, 82]"]
    M --> N

TypeScript 实现

function mergeSort(arr: number[]): number[] {
  if (arr.length <= 1) return arr;

  const mid = Math.floor(arr.length / 2);
  const left = mergeSort(arr.slice(0, mid));
  const right = mergeSort(arr.slice(mid));

  return merge(left, right);
}

function merge(left: number[], right: number[]): number[] {
  const result: number[] = [];
  let i = 0;
  let j = 0;

  while (i < left.length && j < right.length) {
    if (left[i] <= right[j]) {
      result.push(left[i++]);
    } else {
      result.push(right[j++]);
    }
  }

  while (i < left.length) result.push(left[i++]);
  while (j < right.length) result.push(right[j++]);

  return result;
}

复杂度分析

指标 复杂度 说明
时间（最好） O(nlog⁡n)O(n \log n)O(nlogn) 无论输入如何，始终需要分割和合并
时间（平均） O(nlog⁡n)O(n \log n)O(nlogn) 分割深度 log⁡n\log nlogn 层，每层合并 O(n)O(n)O(n)
时间（最坏） O(nlog⁡n)O(n \log n)O(nlogn) 与输入顺序无关，性能非常稳定
空间 O(n)O(n)O(n) 合并过程需要额外的辅助数组
稳定性 ✅ 稳定 合并时 left[i] <= right[j] 保证等值元素不交换

归并排序的最大优点是时间复杂度始终为 O(nlog⁡n)O(n \log n)O(nlogn)，不受输入数据分布的影响。缺点是需要 O(n)O(n)O(n) 的额外空间。

快速排序（Quick Sort）

核心思想

快速排序同样基于分治思想，但与归并排序的"先分后合"不同，快速排序是"先分区后递归"：

  1. 选基准（Pivot）：从数组中选取一个元素作为基准。
  2. 分区（Partition）：将数组重排，使得所有小于基准的元素在左侧，大于基准的元素在右侧。
  3. 递归：对基准左右两部分分别递归排序。
flowchart TD
    A[[3, 6, 8, 10, 1, 2, 1]<br/>pick pivot = 3"] --> B["Partition"]
    B --> C[[1, 2, 1]"]
    B --> D[[3]"]
    B --> E[[6, 8, 10]"]
    C --> F["Recursively sort left half"]
    E --> G["Recursively sort right half"]
    F --> H[[1, 1, 2]"]
    G --> I[[6, 8, 10]"]
    H --> J[[1, 1, 2, 3, 6, 8, 10]"]
    D --> J
    I --> J

基准选择策略

基准的选择直接影响快速排序的性能：

策略 实现方式 优缺点
取首元素 pivot = arr[low] 简单，但对有序数组退化为 O(n2)O(n^2)O(n2)
取末元素 pivot = arr[high] 同上
随机选取 pivot = arr[randomIndex] 概率上避免最坏情况，实际应用最广泛
三数取中 median(arr[low], arr[mid], arr[high]) 效果好，常用于工程实现

TypeScript 实现

function quickSort(arr: number[], low = 0, high = arr.length - 1): void {
  if (low >= high) return;

  const pivotIndex = partition(arr, low, high);
  quickSort(arr, low, pivotIndex - 1);
  quickSort(arr, pivotIndex + 1, high);
}

function partition(arr: number[], low: number, high: number): number {
  const randomIdx = low + Math.floor(Math.random() * (high - low + 1));
  [arr[randomIdx], arr[high]] = [arr[high], arr[randomIdx]];

  const pivot = arr[high];
  let i = low - 1;

  for (let j = low; j < high; j++) {
    if (arr[j] <= pivot) {
      i++;
      [arr[i], arr[j]] = [arr[j], arr[i]];
    }
  }

  [arr[i + 1], arr[high]] = [arr[high], arr[i + 1]];
  return i + 1;
}

复杂度分析

指标 复杂度 说明
时间（最好） O(nlog⁡n)O(n \log n)O(nlogn) 每次分区都恰好均分
时间（平均） O(nlog⁡n)O(n \log n)O(nlogn) 随机选取基准时的期望复杂度
时间（最坏） O(n2)O(n^2)O(n2) 每次分区极度不均衡（如已排序数组取首元素）
空间 O(log⁡n)O(\log n)O(logn) 递归调用栈深度，最坏 O(n)O(n)O(n)
稳定性 ❌ 不稳定 分区过程中元素交换可能改变等值元素的相对顺序

快速排序在平均情况下是最快的通用排序算法，因为它的常数因子极小、缓存友好，且可以原地排序。这也是为什么大多数语言标准库的排序都以快速排序（或其变体）为基础。

堆排序（Heap Sort）

核心思想

堆排序利用**二叉堆（Binary Heap）**这种数据结构来实现排序。具体步骤：

  1. 建堆（Build Max-Heap）：将无序数组构造成一个最大堆，即每个父节点的值都大于等于其子节点。
  2. 排序（Sort）：反复将堆顶（最大值）与堆尾元素交换，然后缩小堆的范围并重新调整堆。
flowchart TD
    subgraph Max-Heap Structure
        N1((82)) --> N2((43))
        N1 --> N3((38))
        N2 --> N4((27))
        N2 --> N5((10))
        N3 --> N6((9))
        N3 --> N7((3))
    end

二叉堆用数组表示时，对于下标为 iii 的节点：父节点为 ⌊(i−1)/2⌋\lfloor(i-1)/2\rfloor⌊(i−1)/2⌋，左子节点为 2i+12i+12i+1，右子节点为 2i+22i+22i+2。

堆排序流程

flowchart LR
    A["Unsorted Array"] -->|"Build Max-Heap O(n)"| B["Max-Heap"]
    B -->|"Swap root with last"| C["Max value placed"]
    C -->|"Heap size - 1<br/>Re-heapify O(log n)"| D["Adjusted heap"]
    D -->|"Repeat n-1 times"| E["Sorted Array"]

TypeScript 实现

function heapSort(arr: number[]): void {
  const n = arr.length;

  for (let i = Math.floor(n / 2) - 1; i >= 0; i--) {
    heapify(arr, n, i);
  }

  for (let i = n - 1; i > 0; i--) {
    [arr[0], arr[i]] = [arr[i], arr[0]];
    heapify(arr, i, 0);
  }
}

function heapify(arr: number[], heapSize: number, rootIndex: number): void {
  let largest = rootIndex;
  const left = 2 * rootIndex + 1;
  const right = 2 * rootIndex + 2;

  if (left < heapSize && arr[left] > arr[largest]) {
    largest = left;
  }

  if (right < heapSize && arr[right] > arr[largest]) {
    largest = right;
  }

  if (largest !== rootIndex) {
    [arr[rootIndex], arr[largest]] = [arr[largest], arr[rootIndex]];
    heapify(arr, heapSize, largest);
  }
}

复杂度分析

指标 复杂度 说明
时间（最好） O(nlog⁡n)O(n \log n)O(nlogn) 即使数组已有序，仍需建堆和逐一提取
时间（平均） O(nlog⁡n)O(n \log n)O(nlogn) 建堆 O(n)O(n)O(n) + 排序 O(nlog⁡n)O(n \log n)O(nlogn)
时间（最坏） O(nlog⁡n)O(n \log n)O(nlogn) 与输入顺序无关
空间 O(1)O(1)O(1) 原地排序，仅使用常数额外空间
稳定性 ❌ 不稳定 堆顶与堆尾交换会破坏等值元素的相对顺序

堆排序的最大优势在于最坏情况也是 O(nlog⁡n)O(n \log n)O(nlogn) 且只需 O(1)O(1)O(1) 额外空间。但由于它对数组的访问模式跳跃性强，缓存命中率较低，实际运行速度通常不如快速排序。

如何选择

flowchart TD
    Q1{"Need stable sort?"}
    Q1 -->|Yes| A1["✅ Merge Sort"]
    Q1 -->|No| Q2{"Memory constrained?"}
    Q2 -->|Yes| Q3{"Accept worst case O(n²)?"}
    Q2 -->|No| A1
    Q3 -->|Yes| A2["✅ Quick Sort(randomized)"]
    Q3 -->|No| A3["✅ Heap Sort"]
  • 需要稳定性（如按多关键字排序）→ 选归并排序。
  • 追求平均速度最优（通用场景）→ 选快速排序，搭配随机化基准或三数取中策略。
  • 内存极度受限，且需要最坏情况保证 → 选堆排序。
  • 工程实践中，很多语言采用混合策略（如 Timsort = 归并 + 插入排序；Introsort = 快排 + 堆排 + 插入排序）来兼顾各种场景。

小结

  • 归并排序、快速排序、堆排序是三种核心的 O(nlog⁡n)O(n \log n)O(nlogn) 排序算法，各有优劣。
  • 归并排序通过分治与合并实现稳定的 O(nlog⁡n)O(n \log n)O(nlogn) 排序，代价是 O(n)O(n)O(n) 的额外空间。
  • 快速排序通过分区操作实现原地排序，平均性能最优，但最坏情况为 O(n2)O(n^2)O(n2)，可通过随机化避免。
  • 堆排序利用堆结构在 O(1)O(1)O(1) 额外空间内实现最坏 O(nlog⁡n)O(n \log n)O(nlogn)，但缓存性能不佳。
  • 理解这三种算法的原理与权衡，是掌握更复杂算法设计思想（分治、贪心、优先队列等）的重要基础。
