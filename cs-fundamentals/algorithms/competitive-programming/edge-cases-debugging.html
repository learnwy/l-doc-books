边界条件与调试

核心概念

边界条件处理和调试能力是区分"能写出来"和"能写对"的关键分水岭。在算法竞赛和面试中，绝大多数的提交失败不是因为算法选错了，而是因为遗漏了某个边界条件、整数溢出、或者对空输入的处理不当。系统化地识别和处理边界条件，配合高效的调试方法，可以大幅提升代码的首次通过率。

整数溢出与大数处理
JavaScript 中 Number 类型使用 64 位双精度浮点数，安全整数范围为 [−253+1,253−1][-2^{53}+1, 2^{53}-1][−253+1,253−1]（即 ±9007199254740991\pm 9007199254740991±9007199254740991）。超出这个范围会丢失精度。


const MAX_SAFE = Number.MAX_SAFE_INTEGER;

function safeAdd(a: number, b: number): number | bigint {
  if (a > MAX_SAFE - b) {
    return BigInt(a) + BigInt(b);
  }
  return a + b;
}
常见的溢出场景和解决方案：


function multiply(a: number, b: number, mod: number): number {
  return Number((BigInt(a) * BigInt(b)) % BigInt(mod));
}

function factorialMod(n: number, mod: number): number {
  let result = 1;
  for (let i = 2; i <= n; i++) {
    result = Number((BigInt(result) * BigInt(i)) % BigInt(mod));
  }
  return result;
}

Off-by-one 错误
Off-by-one（差一错误）是最常见也最难察觉的 Bug 之一。它通常出现在循环边界、数组索引和区间计算中。


常见的差一错误场景：


const offByOneTraps = {
  loop_upper: 'for (i = 0; i <= n) vs for (i = 0; i < n)',
  array_last: 'arr[arr.length] vs arr[arr.length - 1]',
  substring: 'slice(0, n) 不包含索引 n',
  binary_search: 'left <= right vs left < right',
  prefix_sum: 'prefix[r+1] - prefix[l] vs prefix[r] - prefix[l-1]',

二分搜索的边界是重灾区——搜索左边界和右边界的微妙差异：


function lowerBound(arr: number[], target: number): number {
  let left = 0;
  let right = arr.length;

  while (left < right) {
    const mid = left + ((right - left) >> 1);
    if (arr[mid] < target) {
      left = mid + 1;
    } else {
      right = mid;
    }
  }

  return left;
}

function upperBound(arr: number[], target: number): number {
  let left = 0;
  let right = arr.length;

  while (left < right) {
    const mid = left + ((right - left) >> 1);
    if (arr[mid] <= target) {
      left = mid + 1;
    } else {
      right = mid;
    }
  }

  return left;
}

function testEdgeCases(fn: (arr: number[]) => number): void {
  const cases = [
    { input: [], name: '空数组' },
    { input: [1], name: '单元素' },
    { input: [1, 1, 1], name: '全相同' },

    }
  }
}

对拍测试
对拍（Stress Testing）是竞赛中发现隐藏 Bug 的终极武器：用暴力解和优化解对同一组随机数据运行，比较结果是否一致。


function stressTest(
  optimized: (arr: number[]) => number,
  brute: (arr: number[]) => number,
  iterations: number = 10000,
): void {
  for (let i = 0; i < iterations; i++) {
    const size = Math.floor(Math.random() * 20) + 1;
    const arr = Array.from({ length: size }, () => Math.floor(Math.random() * 201) - 100);

    const input = [...arr];
    const expected = brute([...arr]);
    const actual = optimized([...arr]);

    if (expected !== actual) {
      console.log(`MISMATCH on test ${i}!`);
      console.log(`Input: [${input}]`);
      console.log(`Expected: ${expected}`);
      console.log(`Actual: ${actual}`);
      return;
    }
  }

  console.log(`All ${iterations} tests passed!`);
}

  1. 随机数据的规模要小（便于手动验证），但测试轮数要多

  2. 暴力解不需要快，但必须绝对正确
    3. 

  3. 发现不一致后，手动分析最小反例

小结
    

  • 整数溢出是最隐蔽的 Bug，乘法运算中间结果超过 2532^{53}253 时必须用 BigInt
    • 

  • Off-by-one 错误最常出现在二分搜索的边界条件中，掌握 lowerBound 和 upperBound 的模板
    • 

  • 每次提交前都应该手动验证空输入、单元素、极值和大规模输入
    • 

  • 对拍测试是发现隐藏 Bug 的最可靠方法，暴力解作为参照基准
    • 

  • 调试的核心思路：先构造最小反例，再逐步定位错误
    • 

  • 预防优于调试——养成在编码时就考虑边界条件的习惯
