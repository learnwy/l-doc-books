贪心策略与证明

概述

贪心算法（Greedy Algorithm）是一种在每一步都选择局部最优解，期望最终得到全局最优解的算法设计范式。与动态规划不同，贪心算法不会回溯或重新考虑已经做出的选择 —— 一旦选定，便不再更改。



贪心算法的本质：每一步都做出当下看来最好的选择，且永不反悔。它是所有算法范式中最高效、最简洁的，但也是最难证明正确性的。






什么是贪心算法
从直觉到算法
想象你在超市找零。需要找给顾客 63 分钱，手边有 25 分、10 分、5 分、1 分的硬币。你会怎么做？


    

  • 先拿尽可能多的 25 分硬币 → 2 枚（50 分）
    • 

  • 再拿尽可能多的 10 分硬币 → 1 枚（60 分）
    • 

  • 再拿 1 枚 1 分硬币不够，拿 5 分 → 0 枚
    • 

  • 最后拿 3 枚 1 分硬币 → 3 枚（63 分）
    • 



总共 6 枚硬币。这就是贪心策略 —— 每一步都选最大面额。


贪心算法的一般流程


两个关键性质
一个问题能够用贪心算法求解，必须满足以下两个性质：


1. 贪心选择性质（Greedy Choice Property）
全局最优解可以通过一系列局部最优（贪心）选择来达到。也就是说，在做每一步选择时，我们不需要知道未来子问题的解 —— 只需根据当前信息做出最优决策即可。


这与动态规划形成鲜明对比：DP 在做选择时需要考虑所有子问题的解，而贪心只看当下。


2. 最优子结构（Optimal Substructure）
原问题的最优解包含子问题的最优解。当我们做出贪心选择后，剩下的子问题仍然是一个结构相同但规模更小的优化问题，且其最优解与原问题的最优解一致。




贪心算法和动态规划都要求最优子结构，但区别在于：贪心只需要做一次选择就能确定子问题，而 DP 需要枚举所有选择再取最优。






贪心正确性的证明：交换论证法
贪心算法的最大难点不在于设计，而在于证明正确性。最常用的证明技术是交换论证法（Exchange Argument）。


交换论证法的步骤
直觉理解
交换论证的核心思想是：如果我们总能把最优解中与贪心不同的部分替换成贪心选择，而不使结果变差，那么贪心解至少和最优解一样好。




经典例题一：活动选择问题（Activity Selection）
问题描述
给定 nnn 个活动，每个活动有开始时间 sis_isi​ 和结束时间 fif_ifi​。同一时刻只能参加一个活动（活动不能重叠）。求最多能参加多少个活动。


贪心策略
按结束时间从早到晚排序，每次选择结束最早且不与已选活动冲突的活动。


为什么选结束最早的？因为结束越早，留给后面活动的时间就越多。


TypeScript 实现
interface Activity {
  start: number;
  end: number;
  name: string;
}

function activitySelection(activities: Activity[]): Activity[] {
  const sorted = [...activities].sort((a, b) => a.end - b.end);
  const selected: Activity[] = [];
  let lastEnd = -Infinity;

  for (const activity of sorted) {
    if (activity.start >= lastEnd) {
      selected.push(activity);
      lastEnd = activity.end;
    }
  }

  return selected;
}

const activities: Activity[] = [
  { start: 1, end: 3, name: 'A' },
  { start: 2, end: 5, name: 'B' },
  { start: 4, end: 6, name: 'C' },
  { start: 5, end: 8, name: 'D' },
  { start: 7, end: 9, name: 'E' },
];

const result = activitySelection(activities);
console.log(result.map((a) => a.name)); // ["A", "C", "E"]
console.log(result.length); // 3

正确性证明（交换论证）
命题：按结束时间贪心选择的活动集合是最优的（活动数量最多）。


证明：


设贪心解为 G={g1,g2,…,gk}G = \{g_1, g_2, \ldots, g_k\}G={g1​,g2​,…,gk​}（按结束时间排序），假设存在一个最优解 O={o1,o2,…,om}O = \{o_1, o_2, \ldots, o_m\}O={o1​,o2​,…,om​}，其中 m>km > km>k。


    

  1. 考虑 GGG 和 OOO 的第一个不同位置 iii。此时 gi≠oig_i \neq o_igi​=oi​。
    

    2. 

  2. 由于贪心选择结束时间最早的活动，必有 gi.end≤oi.endg_i.\text{end} \leq o_i.\text{end}gi​.end≤oi​.end。
    

    3. 

  3. 将 OOO 中的 oio_ioi​ 替换为 gig_igi​。由于 gig_igi​ 结束更早，它不会与 oi+1o_{i+1}oi+1​ 冲突（因为 gi.end≤oi.end≤oi+1.startg_i.\text{end} \leq o_i.\text{end} \leq o_{i+1}.\text{start}gi​.end≤oi​.end≤oi+1​.start）。
    

    4. 

  4. 替换后 OOO 仍然合法，且活动数量不变。
    

    5. 

  5. 重复此过程，可以将 OOO 逐步转化为 GGG，因此 k≥mk \geq mk≥m。与假设 m>km > km>k 矛盾。
    

    6. 



结论：贪心解 GGG 是最优解。■\blacksquare■




经典例题二：分数背包问题（Fractional Knapsack）
问题描述
有 nnn 件物品和一个容量为 WWW 的背包。第 iii 件物品重量 wiw_iwi​，价值 viv_ivi​。与 0-1 背包不同，每件物品可以取一部分（取 0 到 100% 之间的任意比例）。求装入背包的物品的最大总价值。


贪心策略
按单位重量价值（性价比 vi/wiv_i / w_ivi​/wi​）从高到低排序，优先装性价比最高的物品。如果某件物品装不下，就装它能装的那一部分。


TypeScript 实现
interface Item {
  weight: number;
  value: number;
}

interface FractionalResult {
  totalValue: number;
  fractions: { item: Item; fraction: number }[];
}

function fractionalKnapsack(items: Item[], capacity: number): FractionalResult {
  const indexed = items.map((item, i) => ({
    ...item,
    ratio: item.value / item.weight,
    index: i,
  }));

  indexed.sort((a, b) => b.ratio - a.ratio);

  let remaining = capacity;
  let totalValue = 0;
  const fractions: { item: Item; fraction: number }[] = [];

  for (const item of indexed) {
    if (remaining <= 0) break;

    if (item.weight <= remaining) {
      totalValue += item.value;
      remaining -= item.weight;
      fractions.push({ item: { weight: item.weight, value: item.value }, fraction: 1 });
    } else {
      const fraction = remaining / item.weight;
      totalValue += item.value * fraction;
      remaining = 0;
      fractions.push({ item: { weight: item.weight, value: item.value }, fraction });
    }
  }

  return { totalValue, fractions };
}

const items: Item[] = [
  { weight: 10, value: 60 },
  { weight: 20, value: 100 },
  { weight: 30, value: 120 },
];

const result = fractionalKnapsack(items, 50);
console.log(result.totalValue); // 240
result.fractions.forEach((f) => {
  console.log(`物品(w=${f.item.weight}, v=${f.item.value}): 取 ${(f.fraction * 100).toFixed(0)}%`);
});
// 物品(w=10, v=60): 取 100%
// 物品(w=20, v=100): 取 100%
// 物品(w=30, v=120): 取 67%

正确性证明（交换论证）
命题：按性价比贪心装入物品可以获得最大总价值。


证明：


设物品已按性价比降序排列：r1≥r2≥…≥rnr_1 \geq r_2 \geq \ldots \geq r_nr1​≥r2​≥…≥rn​，其中 ri=vi/wir_i = v_i / w_iri​=vi​/wi​。


设贪心解中各物品的装入比例为 x1,x2,…,xnx_1, x_2, \ldots, x_nx1​,x2​,…,xn​，假设存在一个最优解 y1,y2,…,yny_1, y_2, \ldots, y_ny1​,y2​,…,yn​，使得总价值严格大于贪心解。


    

  1. 找到第一个 jjj，使得 yj≠xjy_j \neq x_jyj​=xj​。由于贪心尽可能多地装性价比高的物品，必有 yj<xjy_j < x_jyj​<xj​。
    

    2. 

  2. 由于 yj<xjy_j < x_jyj​<xj​，最优解少装了物品 jjj，因此它多装了某个排在后面的物品 kkk（k>jk > jk>j），即 yk>xky_k > x_kyk​>xk​。
    

    3. 

  3. 将少装的物品 jjj 多装 ϵ\epsilonϵ 单位重量（ϵ\epsilonϵ 足够小），同时将物品 kkk 少装 ϵ\epsilonϵ 单位重量。价值变化为 ϵ⋅(rj−rk)≥0\epsilon \cdot (r_j - r_k) \geq 0ϵ⋅(rj​−rk​)≥0，因为 rj≥rkr_j \geq r_krj​≥rk​。
    

    4. 

  4. 交换不会降低总价值，重复此过程可将最优解转化为贪心解。
    

    5. 



结论：贪心解的价值等于最优解的价值。■\blacksquare■




贪心 vs 动态规划
贪心算法和动态规划经常被放在一起比较，因为它们都用于求解最优化问题，并且都要求最优子结构。






对比维度
贪心算法
动态规划

每步选局部最优，不回退

子问题求解
只产生一个子问题
可能产生多个重叠子问题

通常 O(n2)O(n^2)O(n2) 或更高

通常 O(1)O(1)O(1) ~ O(n)O(n)O(n)

经典对比：0-1 背包 vs 分数背包
同样是背包问题，为什么分数背包可以用贪心，而 0-1 背包不行？


function greedyKnapsack01(items: Item[], capacity: number): number {
  const sorted = [...items].sort((a, b) => b.value / b.weight - a.value / a.weight);

  let remaining = capacity;
  let totalValue = 0;

  for (const item of sorted) {
    if (item.weight <= remaining) {
      totalValue += item.value;
      remaining -= item.weight;
    }
  }

  return totalValue;
}

const knapsackItems: Item[] = [
  { weight: 10, value: 60 },
  { weight: 20, value: 100 },
  { weight: 30, value: 120 },
];

console.log(greedyKnapsack01(knapsackItems, 50));
// 贪心结果: 160（选 A + B）
// 最优结果: 220（选 B + C）—— 贪心在此处失败！
原因分析：


    

  • 分数背包：可以取物品的一部分，因此总能把背包填满。按性价比排序后，每一步的局部最优确实导向全局最优。
    • 

  • 0-1 背包：物品不可分割。按性价比选了高价值小物品后，可能浪费了大量背包空间，反而不如选其他物品组合。贪心选择性质不成立。
    •

硬币找零的反例
function greedyCoinChange(coins: number[], amount: number): number {
  const sorted = [...coins].sort((a, b) => b - a);
  let remaining = amount;
  let count = 0;

  for (const coin of sorted) {
    while (remaining >= coin) {
      remaining -= coin;
      count++;
    }
  }

  return remaining === 0 ? count : -1;
}

console.log(greedyCoinChange([25, 10, 5, 1], 63)); // 6 ✅ 正确（美元体系）
console.log(greedyCoinChange([1, 3, 4], 6)); // 3（4+1+1）❌ 最优是 2（3+3）
面额为 [1, 3, 4]，金额为 6 时：


    

  • 贪心选择：4+1+1=34 + 1 + 1 = 34+1+1=3 枚
    • 

  • 最优解：3+3=23 + 3 = 23+3=2 枚
    • 



贪心失败了！这是因为 [1, 3, 4] 面额体系不满足贪心选择性质。




如何判断能否使用贪心
在面试或刷题时，可以用以下思路判断：


实用技巧：


    

  1. 先试着构造反例。如果你能找到一个贪心策略不工作的输入，就不要用贪心。
    2. 

  2. 排序是贪心的好朋友。大多数贪心算法的第一步都是排序 —— 按结束时间、按性价比、按截止日期等。
    3. 

  3. 如果问题涉及"不可分割"的选择（如 0-1 背包），通常需要 DP 而非贪心。
    4. 

  4. 如果问题涉及"可连续/可分割"的选择（如分数背包），贪心更有可能适用。
    5. 





小结
    

  • 贪心算法在每一步做出局部最优选择，期望得到全局最优解。它高效但适用范围较窄。
    • 

  • 贪心正确性依赖于两个性质：贪心选择性质（局部最优导向全局最优）和最优子结构（最优解包含子问题最优解）。
    • 

  • 交换论证法是证明贪心正确性的核心技术：假设存在更好的解，通过逐步替换证明贪心解不差于它。
    • 

  • 活动选择问题（按结束时间排序）和分数背包问题（按性价比排序）是两个经典的贪心应用。
    • 

  • 贪心与 DP 的核心区别：贪心做一次选择就确定子问题，DP 需要枚举所有选择。当贪心选择性质不成立时（如 0-1 背包），必须使用 DP。
    • 

  • 实战建议：先构造反例验证贪心策略，找不到反例再尝试用交换论证法证明正确性。
    •
