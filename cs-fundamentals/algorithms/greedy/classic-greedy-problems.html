经典贪心问题

概述

贪心算法的核心在于：每一步都做出当前看来最优的选择，并期望这些局部最优选择能组合成全局最优解。本节将深入讲解六大经典贪心问题，涵盖跳跃问题、区间调度、编码优化、任务规划和资源管理等常见场景，是面试与竞赛的高频考点。



贪心 vs 动态规划：贪心算法不回溯、不保存子问题结果，一旦做出选择就不再改变。而 DP 会穷举所有子问题。贪心能成立的关键在于证明贪心选择性质和最优子结构。






一、跳跃游戏（Jump Game）
问题描述
给定一个非负整数数组 nums，其中 nums[i] 表示从位置 i 最多可以跳跃的步数。判断是否能够从数组第一个位置到达最后一个位置。


例如：nums = [2, 3, 1, 1, 4] → 可以到达（0→1→4）；nums = [3, 2, 1, 0, 4] → 无法到达。


贪心策略
维护一个变量 maxReach，表示当前能到达的最远位置。从左到右遍历数组，对于每个可达位置 i（即 i <= maxReach），更新 maxReach = max(maxReach, i + nums[i])。如果 maxReach >= n - 1，则可以到达终点。


TypeScript 实现
function canJump(nums: number[]): boolean {
  let maxReach = 0;

  for (let i = 0; i < nums.length; i++) {
    if (i > maxReach) return false;
    maxReach = Math.max(maxReach, i + nums[i]);
    if (maxReach >= nums.length - 1) return true;
  }

  return true;
}
跳跃游戏 II（求最少跳跃次数）：


function jump(nums: number[]): number {
  let jumps = 0;
  let currentEnd = 0;
  let farthest = 0;

  for (let i = 0; i < nums.length - 1; i++) {
    farthest = Math.max(farthest, i + nums[i]);
    if (i === currentEnd) {
      jumps++;
      currentEnd = farthest;
      if (currentEnd >= nums.length - 1) break;
    }
  }

  return jumps;
}
正确性证明
贪心选择性质：如果位置 i 可达且 i + nums[i] >= j，则位置 j 也可达。因此我们只需要贪心地维护最远可达位置，不需要记录每一步的具体路径。


最优子结构：如果从 0 能到达 n-1，那么一定存在一个中间位置 k，使得从 0 能到达 k，且从 k 能到达 n-1。

二、区间调度 / 会议室问题（Interval Scheduling）
问题描述
给定 nnn 个区间 [starti,endi][start_i, end_i][starti​,endi​]，选出最多的互不重叠的区间。


等价问题（会议室 II）：给定一组会议时间，求最少需要多少间会议室才能安排所有会议。


贪心策略
最多不重叠区间：按结束时间升序排列，每次贪心选择结束时间最早的区间，这样给后续区间留下最多的空间。


TypeScript 实现
最多不重叠区间数（等价于求最少移除区间数）：


function eraseOverlapIntervals(intervals: number[][]): number {
  if (intervals.length === 0) return 0;

  intervals.sort((a, b) => a[1] - b[1]);

  let count = 1;
  let prevEnd = intervals[0][1];

  for (let i = 1; i < intervals.length; i++) {
    if (intervals[i][0] >= prevEnd) {
      count++;
      prevEnd = intervals[i][1];
    }
  }

  return intervals.length - count;
}
会议室 II（最少会议室数量）：


function minMeetingRooms(intervals: number[][]): number {
  const starts = intervals.map((i) => i[0]).sort((a, b) => a - b);
  const ends = intervals.map((i) => i[1]).sort((a, b) => a - b);

  let rooms = 0;
  let endPtr = 0;

  for (let i = 0; i < starts.length; i++) {
    if (starts[i] < ends[endPtr]) {
      rooms++;
    } else {
      endPtr++;
    }
  }

  return rooms;
}
正确性证明
交换论证法（Exchange Argument）：假设存在一个最优解 OOO 没有选择结束时间最早的区间 aaa，而选择了另一个区间 bbb（endb≥endaend_b \geq end_aendb​≥enda​）。我们可以用 aaa 替换 bbb，由于 aaa 的结束时间不晚于 bbb，替换后不会增加与其他区间的冲突，因此新方案仍然是最优解。通过对每个选择重复此论证，可以证明按结束时间贪心选择一定能获得最优解。

三、哈夫曼编码（Huffman Coding）
问题描述
给定一组字符及其出现频率，构建一棵最优前缀编码树（哈夫曼树），使得所有字符的加权编码总长度最短。


例如：字符频率 { a: 5, b: 9, c: 12, d: 13, e: 16, f: 45 }。


贪心策略
每次从候选集中取出频率最小的两个节点合并为一个新节点（频率为两者之和），将新节点放回候选集，重复此过程直到只剩一个根节点。


更清晰的构建步骤如下：


TypeScript 实现
class HuffmanNode {
  char: string | null;
  freq: number;
  left: HuffmanNode | null;
  right: HuffmanNode | null;

  constructor(char: string | null, freq: number) {
    this.char = char;
    this.freq = freq;
    this.left = null;
    this.right = null;
  }
}

class MinHeap {
  private heap: HuffmanNode[] = [];

  size(): number {
    return this.heap.length;
  }

  push(node: HuffmanNode): void {
    this.heap.push(node);
    this.bubbleUp(this.heap.length - 1);
  }

  pop(): HuffmanNode {
    const min = this.heap[0];
    const last = this.heap.pop()!;
    if (this.heap.length > 0) {
      this.heap[0] = last;
      this.sinkDown(0);
    }
    return min;
  }

  private bubbleUp(i: number): void {
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (this.heap[parent].freq > this.heap[i].freq) {
        [this.heap[parent], this.heap[i]] = [this.heap[i], this.heap[parent]];
        i = parent;
      } else {
        break;
      }
    }
  }

  private sinkDown(i: number): void {
    const n = this.heap.length;
    while (true) {
      let smallest = i;
      const left = 2 * i + 1;
      const right = 2 * i + 2;
      if (left < n && this.heap[left].freq < this.heap[smallest].freq) smallest = left;
      if (right < n && this.heap[right].freq < this.heap[smallest].freq) smallest = right;
      if (smallest !== i) {
        [this.heap[smallest], this.heap[i]] = [this.heap[i], this.heap[smallest]];
        i = smallest;
      } else {
        break;
      }
    }
  }
}

function buildHuffmanTree(chars: string[], freqs: number[]): HuffmanNode {
  const heap = new MinHeap();

  for (let i = 0; i < chars.length; i++) {
    heap.push(new HuffmanNode(chars[i], freqs[i]));
  }

  while (heap.size() > 1) {
    const left = heap.pop();
    const right = heap.pop();
    const merged = new HuffmanNode(null, left.freq + right.freq);
    merged.left = left;
    merged.right = right;
    heap.push(merged);
  }

  return heap.pop();
}

function generateCodes(
  root: HuffmanNode | null,
  prefix: string = '',
  codes: Map<string, string> = new Map(),
): Map<string, string> {
  if (!root) return codes;

  if (root.char !== null) {
    codes.set(root.char, prefix || '0');
    return codes;
  }

  generateCodes(root.left, prefix + '0', codes);
  generateCodes(root.right, prefix + '1', codes);

  return codes;
}
正确性证明
贪心选择性质：频率最小的两个字符在最优编码中一定位于树的最深层，且互为兄弟节点。反证法：若频率最低的字符 xxx 不在最深层，可以将 xxx 与最深层的某个字符交换，由于 xxx 频率更低、编码更长，总编码长度不会增加。


最优子结构：合并频率最低的两个节点 x,yx, yx,y 得到新节点 zzz（频率为 fx+fyf_x + f_yfx​+fy​），将原问题转化为字符集少一个的子问题，该子问题的最优解加上 x,yx, yx,y 的编码就是原问题的最优解。

四、任务调度器（Task Scheduler）
问题描述
给定一组用字母表示的 CPU 任务，以及一个冷却时间 nnn。两个相同任务之间必须至少间隔 nnn 个时间单位（可以执行其他任务或空闲）。求完成所有任务所需的最少时间单位。


例如：tasks = ["A","A","A","B","B","B"]，n = 2，最少需要 8 个时间单位：A B _ A B _ A B。


贪心策略
    

  1. 统计每个任务的出现次数，找出最高频任务的频率 maxFreq。
    2. 

  2. 计算有多少个任务具有最高频率 maxCount。
    3. 

  3. 最少时间 = max⁡(tasks.length, (maxFreq−1)×(n+1)+maxCount)\max(\text{tasks.length},\ (\text{maxFreq} - 1) \times (n + 1) + \text{maxCount})max(tasks.length, (maxFreq−1)×(n+1)+maxCount)。
    4. 



核心思想：频率最高的任务决定了"框架"的大小，其他任务填入空槽。


TypeScript 实现
function leastInterval(tasks: string[], n: number): number {
  const freq = new Array(26).fill(0);
  for (const task of tasks) {
    freq[task.charCodeAt(0) - 65]++;
  }

  const maxFreq = Math.max(...freq);
  const maxCount = freq.filter((f) => f === maxFreq).length;

  const minTime = (maxFreq - 1) * (n + 1) + maxCount;

  return Math.max(tasks.length, minTime);
}
正确性证明
框架论证：最高频任务 AAA 出现 maxFreqmaxFreqmaxFreq 次，相邻两个 AAA 之间至少需要 nnn 个时间槽。这形成了 (maxFreq−1)(maxFreq - 1)(maxFreq−1) 个长度为 (n+1)(n + 1)(n+1) 的"桶"，最后一个桶只放频率等于 maxFreqmaxFreqmaxFreq 的任务（共 maxCountmaxCountmaxCount 个）。


    

  • 如果空槽足够放下所有其他任务，总时间 = 框架大小。
    • 

  • 如果空槽不够，说明所有空闲时间都被任务填满，总时间 = 任务总数。
    • 



因此取两者的最大值一定是正确答案。

五、加油站（Gas Station）
问题描述
在一条环形路线上有 nnn 个加油站，第 iii 个加油站可以加 gas[i] 升油，从第 iii 站到第 i+1i+1i+1 站需要消耗 cost[i] 升油。汽车油箱容量无限，初始油量为 0。判断是否存在一个出发站，使得汽车能顺时针绕一圈。如果存在，返回出发站编号；否则返回 -1。


贪心策略
    

  1. 如果 sum(gas) < sum(cost)，则无论从哪里出发都不可能绕一圈，返回 -1。
    2. 

  2. 否则，答案一定存在。从头遍历，维护当前油量 tank。当 tank < 0 时，说明从当前起点出发无法到达此处，于是将起点设为下一站，重置 tank = 0。
    3. 



TypeScript 实现
function canCompleteCircuit(gas: number[], cost: number[]): number {
  let totalTank = 0;
  let currentTank = 0;
  let startStation = 0;

  for (let i = 0; i < gas.length; i++) {
    const diff = gas[i] - cost[i];
    totalTank += diff;
    currentTank += diff;

    if (currentTank < 0) {
      startStation = i + 1;
      currentTank = 0;
    }
  }

  return totalTank >= 0 ? startStation : -1;
}
正确性证明
存在性：若 ∑gasi≥∑costi\sum gas_i \geq \sum cost_i∑gasi​≥∑costi​，则总油量充足，一定存在解。


贪心选择性质：若从站点 AAA 出发，在到达站点 BBB 时油量首次变为负数，则从 AAA 到 BBB 之间的任何站点出发，到达 BBB 时油量都不会为正——因为从 AAA 出发到达中间任何站点 CCC 时，油量 ≥0\geq 0≥0（否则早在 CCC 之前就失败了），所以从 CCC 出发到 BBB 的油量只会比从 AAA 出发少（少了 A→CA→CA→C 的盈余）。因此可以安全跳过 AAA 到 BBB 之间的所有站点，将起点设为 B+1B+1B+1。

六、用最少数量的箭引爆气球（Minimum Number of Arrows to Burst Balloons）
问题描述
在二维空间中，许多气球贴在墙上，每个气球用区间 [xstart,xend][x_{start}, x_{end}][xstart​,xend​] 表示其水平直径。沿 xxx 轴垂直射箭，若箭的位置 xxx 满足 xstart≤x≤xendx_{start} \leq x \leq x_{end}xstart​≤x≤xend​，则该气球被引爆。求最少需要多少支箭才能引爆所有气球。


例如：points = [[10,16],[2,8],[1,6],[7,12]] → 最少 2 支箭。


贪心策略
按右端点升序排序。贪心地在当前组的最右端（即最小的右端点）射箭，能引爆尽可能多的气球。如果下一个气球的左端点超过了当前箭的位置，就需要一支新箭。


TypeScript 实现
function findMinArrowShots(points: number[][]): number {
  if (points.length === 0) return 0;

  points.sort((a, b) => a[1] - b[1]);

  let arrows = 1;
  let arrowPos = points[0][1];

  for (let i = 1; i < points.length; i++) {
    if (points[i][0] > arrowPos) {
      arrows++;
      arrowPos = points[i][1];
    }
  }

  return arrows;
}
正确性证明
贪心选择性质：将箭射在当前未被引爆的气球中右端点最小的位置，能保证"覆盖"尽可能多的后续气球。若箭射在更左的位置，不会引爆更多气球（可能引爆更少）；若箭射在更右的位置，可能错过当前这个右端点最小的气球，需要额外一支箭。


交换论证：假设最优解中某支箭射在位置 ppp，且 ppp 不是当前组的最小右端点 rrr。由于所有被 ppp 引爆的气球都包含 rrr（因为它们的右端点 ≥r\geq r≥r 且已经按右端点排序），所以将箭移到 rrr 不会减少引爆的气球数。因此贪心解不会比最优解更差。

小结
    

  • 跳跃游戏是最直观的贪心问题，核心是"能到达的最远位置"这一单一变量的维护。掌握此思路后可推广到"最少跳跃次数"等变体。
    • 

  • 区间调度是贪心算法的经典范例。按结束时间排序是处理区间问题的黄金法则，无论是"最多不重叠区间"还是"最少会议室"，都可以从此策略出发。
    • 

  • 哈夫曼编码展示了贪心与数据结构（最小堆）的完美结合。它不仅是算法题，更是信息论和数据压缩的基石（ZIP、JPEG 等格式的核心）。
    • 

  • 任务调度器的难点在于从"框架"角度思考问题：最高频任务决定了时间下界，其他任务只是填充空闲槽位。
    • 

  • 加油站的精妙之处在于一次遍历即可确定唯一的起点。当油量不足时"重置起点"的操作看似简单，但其正确性需要严谨的前缀和论证。
    • 

  • 射气球本质上是区间调度的变体。理解了区间调度的交换论证，射气球问题便迎刃而解。
    • 

  • 贪心算法的核心方法论：识别贪心策略 → 证明贪心选择性质（交换论证 / 反证法） → 验证最优子结构 → 编写高效实现。掌握这一流程，面对新的贪心问题时便能从容应对。
    •
