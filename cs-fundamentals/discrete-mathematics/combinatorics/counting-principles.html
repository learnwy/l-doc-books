计数原理

核心概念

计数原理是组合数学的基石，解决的是"有多少种可能"这一基本问题。在计算机科学中，计数能力直接关系到算法复杂度分析（搜索空间有多大）、概率计算（某事件发生的概率是多少）、以及系统设计（需要多少位来编码所有可能状态）。

两个最基本的计数原理——加法原理和乘法原理——几乎可以用来分析所有复杂计数问题。它们看似简单，但正确应用的关键在于准确识别问题中的"或"和"且"关系。

加法原理与乘法原理
加法原理：如果完成一个任务有两类互斥的方案，第一类有 m 种，第二类有 n 种，则总共有 m + n 种方案。关键词是"或"——选择第一类或第二类。


加法原理的前提是方案互斥——两类方案之间没有重叠。如果方案有重叠，就需要用容斥原理（本章第三节详述）修正。一个常见的错误是在方案不互斥时直接相加，导致重复计数。


在算法分析中，分支结构对应加法原理。一个 if-else 语句的两个分支分别有不同的执行路径，总路径数是两个分支路径数之和。


function countPaths(node: TreeNode): number {
  if (!node.left && !node.right) return 1;
  let paths = 0;
  if (node.left) paths += countPaths(node.left);
  if (node.right) paths += countPaths(node.right);
  return paths;
}
乘法原理：如果完成一个任务需要依次经过 k 步，第 1 步有 n₁ 种选择，第 2 步有 n₂ 种选择，...，第 k 步有 nₖ 种选择，则总方案数为 n₁ × n₂ × ... × nₖ。关键词是"且"——需要完成第一步且第二步且...。


乘法原理的前提是各步选择相互独立——某一步的选择数不受其他步选择的影响。如果后续步骤的选择数依赖于前面的选择（如"从 n 个球中不放回地取 r 个"），那么各步的选择数分别为 n, n-1, n-2, ..., n-r+1，乘法原理仍然适用，只是每步的选择数不同。


在算法分析中，嵌套循环对应乘法原理。一个双重循环，外层 m 次、内层 n 次，总迭代次数为 m × n。


密码学中的密钥空间分析直接使用乘法原理。如果密码长度为 8，每位可以是 26 个字母或 10 个数字（36 种），则密钥空间大小为 36⁸ ≈ 2.8 × 10¹²。如果每位还区分大小写（62 种），则为 62⁸ ≈ 2.2 × 10¹⁴。


更现实的密码策略分析：要求至少包含大写、小写、数字各一个的 8 位密码数 = 全部 - 不含大写的 - 不含小写的 - 不含数字的 + 既不含大写也不含小写的 + ... 这就需要容斥原理（下一节详述）。


const keySpaceSize = (charsetSize: number, length: number): number => Math.pow(charsetSize, length);

const lowercase = keySpaceSize(26, 8);
const alphanumeric = keySpaceSize(36, 8);
const mixedCase = keySpaceSize(62, 8);
减法原理与补集计数
减法原理（补集计数）：当直接计算满足条件的方案数很困难时，转而用"全集大小 - 不满足条件的方案数"。这与逻辑中"证逆否"的思路一致——正面难以处理时从反面入手。


经典应用：计算"至少有一个"的情况数。"至少有一个偶数"的方案数 = 全部方案数 - "全部是奇数"的方案数。


// 从 n 个骰子中至少有一个 6 的情况数
const atLeastOneSix = (n: number): number => {
  const total = Math.pow(6, n);
  const noSix = Math.pow(5, n);
  return total - noSix;
};
在概率论中，P(至少一个事件发生) = 1 - P(没有事件发生)。这在系统可靠性分析中常用：如果每个组件独立失败的概率为 p，则 n 个组件至少有一个失败的概率为 1 - (1-p)ⁿ。这就是为什么分布式系统在节点数增加时，部分故障几乎不可避免。


对于独立事件 A₁, A₂, ..., Aₙ，至少一个发生的概率：


P(A₁ ∪ ... ∪ Aₙ) = 1 - P(Ā₁) × P(Ā₂) × ... × P(Āₙ) = 1 - ∏(1 - P(Aᵢ))


在编程中，"至少"条件的判断往往比"恰好"条件更容易通过补集计数来分析。例如，分析"随机生成的 UUID 中至少出现一次碰撞的概率"就用了这个方法（即生日问题的分析思路）。


除法原理与多重计数
除法原理：如果一组对象的每种无序选择恰好对应 k 种有序排列，则无序选择数 = 有序排列数 / k。


最典型的应用：从 n 个元素中选 r 个的组合数 C(n,r) = P(n,r) / r!。因为同一组 r 个元素有 r! 种排列方式，所以无序组合数等于有序排列数除以 r!。


除法原理要求每种无序选择恰好对应相同数量的有序排列。如果不同选择对应不同数量的排列（即不均匀），除法原理就不能直接使用，需要更精细的分析（如 Burnside 引理处理旋转等价类）。


Burnside 引理的典型应用：用 k 种颜色给正方形的 4 个顶点着色，不考虑旋转的方案数。直接计数是 k⁴ 种，但考虑 4 种旋转等价后，实际方案数 = (k⁴ + k³ + k² + k²)/4。当 k=2 时，方案数 = (16+8+4+4)/4 = 8。


多重集计数涉及允许重复元素的计数。从 {a, a, b, b, b, c} 这样的多重集中选取 r 个元素，计数方法需要考虑元素的重复性。多项式系数 n!/(n₁! × n₂! × ... × nₖ!) 给出了多重集排列数。


在编程中，anagram 问题（判断两个字符串是否为字母重排）的解法数量就涉及多重集排列。"mississippi" 的排列数不是 11!（因为有重复字母），而是 11!/(4! × 4! × 2! × 1!) = 34650。


多重集排列在自然语言处理中也有应用。文本中词频向量的不同排列数对应可能的文本数量，这与信息论中文本的信息熵直接相关。信息熵 H = log₂(n!/(n₁!×n₂!×...×nₖ!)) 给出了编码这些排列所需的最小比特数。

计数原理在算法分析中的应用
计数原理是算法复杂度分析的数学基础。理解"搜索空间有多大"是评估算法可行性的第一步。


暴力搜索的可行性评估：如果搜索空间大小为 N，暴力搜索的时间复杂度为 O(N)。利用计数原理可以快速估算 N：


    

  • 子集搜索：2ⁿ（幂集大小）——用于背包问题、集合覆盖
    • 

  • 排列搜索：n!——用于旅行商、任务调度
    • 

  • 组合搜索：C(n,r)——用于委员会选举、特征选择
    • 

  • 多重选择：nʳ——用于密码暴力破解、配置枚举
    • 



当 n = 20 时，2²⁰ ≈ 10⁶（可接受），20! ≈ 2.4 × 10¹⁸（不可接受）。这就是为什么子集枚举在 n ≤ 20 时可行，而全排列在 n ≤ 12 左右就达到极限。

哈希碰撞概率（生日问题）：将 k 个元素随机放入 n 个桶，至少有一对碰撞的概率约为 1 - e^(-k²/(2n))。当 k ≈ √n 时碰撞概率约 50%。这意味着 128 位哈希值在约 2⁶⁴ 个输入后就有 50% 的碰撞概率。


生日问题的直觉解释：23 个人中至少两人同一天生日的概率超过 50%，这远比大多数人的直觉预期要高。原因在于配对数 C(23, 2) = 253 已经很大，每对碰撞的独立概率虽小但累积效应显著。


随机算法的成功概率：如果一个随机化算法在每次尝试中成功的概率为 p，独立重复 k 次后至少成功一次的概率为 1 - (1-p)ᵏ。利用补集计数，当 k = ⌈ln(1/δ) / p⌉ 时，失败概率降至 δ 以下。


编码理论：用 n 位二进制编码 m 种状态，需要 n ≥ ⌈log₂m⌉ 位。这是乘法原理的直接推论——n 位二进制有 2ⁿ 种组合。ASCII 用 7 位编码 128 个字符，Unicode UTF-8 用可变长度（1-4 字节）编码超过 14 万个字符。


树的计数：n 个节点的不同标记树有 nⁿ⁻² 棵（Cayley 公式），这个结果可以通过 Prüfer 序列（长度为 n-2 的序列，每个位置有 n 种选择）用乘法原理解释。


分配问题：将 n 个不同的球放入 k 个不同的盒子，如果不限制每盒数量，方案数为 kⁿ（乘法原理：每个球独立选择盒子）。如果要求每盒恰好一个球且 n = k，方案数为 n!（排列数）。这两种模型分别对应哈希表的插入和完美哈希。


const collisionProbability = (k: number, n: number): number => 1 - Math.exp(-(k * k) / (2 * n));

const trialsForConfidence = (p: number, delta: number): number => Math.ceil(Math.log(1 / delta) / p);

const birthdayThreshold = (n: number): number => Math.ceil(Math.sqrt(2 * n * Math.log(2)));
上述 birthdayThreshold 函数计算在 n 个桶的情况下，碰撞概率达到 50% 时大约需要的样本数。对于 2⁶⁴ 空间，阈值约为 2³²，对于 2¹²⁸ 空间，阈值约为 2⁶⁴。这直接影响了密码学哈希函数所需输出长度的选择。


小结
    

  • 加法原理处理"或"（互斥分支），乘法原理处理"且"（独立步骤）
    • 

  • 减法原理将"至少一个"问题转化为"一个都没有"的补集计数
    • 

  • 除法原理消除顺序导致的重复计数，组合数就是排列数除以排列方式数
    • 

  • 搜索空间估算是评估暴力搜索可行性的第一步：2ⁿ vs n! 决定了问题规模上限
    • 

  • 生日问题揭示了哈希碰撞比直觉预期更早发生（√n 量级）
    • 

  • 计数原理是算法分析、密码学密钥空间评估和系统可靠性分析的共同数学工具
    • 

  • 多重集排列处理有重复元素的计数问题，直接关联字符串组合分析
    • 

  • 编码理论中，位数需求 ⌈log₂m⌉ 是乘法原理的直接推论
    • 

  • Cayley 公式 nⁿ⁻² 给出了标记树的计数，通过 Prüfer 序列可用乘法原理解释
    • 

  • 四大计数原理（加法、乘法、减法、除法）的灵活组合可以解决绝大多数计数问题
    • 

  • 正确识别"或"与"且"的关系，是避免重复计数和遗漏计数的关键
    • 

  • 互斥性检查是应用加法原理前的必要步骤，非互斥情况需要容斥原理修正
    •
