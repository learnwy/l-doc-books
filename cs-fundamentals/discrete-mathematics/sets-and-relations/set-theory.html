集合论基础

核心概念

集合（Set）是数学中最基本的概念之一，是由一些确定的、互不相同的对象构成的整体。集合论由 Georg Cantor 在 19 世纪末创立，后来发展成为整个现代数学的基础语言。在计算机科学中，集合的概念无处不在——编程语言中的 Set 类型、数据库的关系模型、类型系统中的类型集合，都建立在集合论的基础之上。

集合的表示有两种基本方式：枚举法直接列出所有元素，如 A = {1, 2, 3}；描述法通过性质描述元素，如 B = {x | x 是偶数且 0 < x < 10}。编程中的数组字面量对应枚举法，而 filter 操作对应描述法。

集合中元素的顺序和重复不影响集合本身：{1, 2, 3} = {3, 1, 2} = {1, 1, 2, 3}。这与编程中的 Set 数据结构完全一致——自动去重且不保证顺序。

集合运算与代数律
集合运算遵循一组优雅的代数律，这些律与命题逻辑的等价律存在精确的对应关系。这不是巧合——集合的特征函数将集合运算映射为逻辑运算。


核心运算律：


    

  • 交换律：A ∪ B = B ∪ A，A ∩ B = B ∩ A
    • 

  • 结合律：(A ∪ B) ∪ C = A ∪ (B ∪ C)
    • 

  • 分配律：A ∩ (B ∪ C) = (A ∩ B) ∪ (A ∩ C)
    • 

  • 德摩根律：(A ∪ B)ᶜ = Aᶜ ∩ Bᶜ，(A ∩ B)ᶜ = Aᶜ ∪ Bᶜ
    • 

  • 吸收律：A ∪ (A ∩ B) = A
    • 

  • 幂等律：A ∪ A = A，A ∩ A = A
    • 



const union = <T>(a: Set<T>, b: Set<T>): Set<T> => {
  const result = new Set(a);
  for (const elem of b) result.add(elem);
  return result;
};

const intersection = <T>(a: Set<T>, b: Set<T>): Set<T> => {
  const result = new Set<T>();
  for (const elem of a) {
    if (b.has(elem)) result.add(elem);
  }
  return result;
};

const difference = <T>(a: Set<T>, b: Set<T>): Set<T> => {
  const result = new Set<T>();
  for (const elem of a) {
    if (!b.has(elem)) result.add(elem);
  }
  return result;
};
集合运算在编程中的典型应用包括：数据库的 UNION、INTERSECT、EXCEPT 操作直接对应集合的并、交、差运算；权限系统中用户的有效权限是角色权限集合的并集；缓存失效策略中需要计算"过期键集合与活跃键集合的差集"。


德摩根律在集合运算中同样重要。当需要计算"不在 A 中且不在 B 中的元素"时，可以先计算 A ∪ B 再取补，这在数据库查询优化中对应 NOT IN 子查询的改写。


幂集与笛卡尔积
幂集（Power Set）P(A) 是 A 的所有子集构成的集合。如果 |A| = n，则 |P(A)| = 2ⁿ。幂集的大小随原集合呈指数增长，这与暴力搜索所有子集的时间复杂度 O(2ⁿ) 直接相关。


function powerSet<T>(set: T[]): T[][] {
  if (set.length === 0) return [[]];
  const [first, ...rest] = set;
  const subsetsWithoutFirst = powerSet(rest);
  const subsetsWithFirst = subsetsWithoutFirst.map((s) => [first, ...s]);
  return [...subsetsWithoutFirst, ...subsetsWithFirst];
}
幂集在实际中的应用场景包括：配置项的所有可能组合（n 个开关的 2ⁿ 种状态）、特性标志系统的测试矩阵、子集和问题（背包问题的暴力解法）。


笛卡尔积（Cartesian Product）A × B = {(a, b) | a ∈ A, b ∈ B}。笛卡尔积生成所有可能的配对，|A × B| = |A| × |B|。在关系数据库中，FROM 子句列出多个表时的初始结果就是这些表的笛卡尔积，然后通过 WHERE 或 JOIN 条件过滤。


笛卡尔积可以推广到多个集合：A₁ × A₂ × ... × Aₙ。n 元笛卡尔积中的每个元素是一个 n 元组 (a₁, a₂, ..., aₙ)。这与编程中参数的组合测试（每个参数有若干可选值）直接对应。


function cartesianProduct<T>(...sets: T[][]): T[][] {
  return sets.reduce<T[][]>((acc, set) => acc.flatMap((combo) => set.map((item) => [...combo, item])), [[]]);
}
集合的基数与无限集
两个集合的基数（Cardinality）相同，当且仅当它们之间存在双射。对有限集合，基数就是元素个数。但对无限集合，基数的概念变得微妙而深刻。


Cantor 证明了自然数集 ℕ 和有理数集 ℚ 具有相同的基数（都是可数无限，记为 ℵ₀），而实数集 ℝ 的基数严格大于 ℵ₀（不可数无限）。这个证明使用了著名的对角线论证（Diagonalization Argument）。


对角线论证在计算机科学中有深远影响：


    

  • 停机问题的不可判定性证明本质上是对角线论证的变体
    • 

  • 可计算函数的集合是可数的，但所有函数的集合是不可数的，因此存在不可计算的函数
    • 

  • 这解释了为什么不是所有问题都能用算法解决
    •

在编程中，虽然我们处理的都是有限集合，但无限集的概念通过惰性求值得到了部分实现。JavaScript 的生成器可以表示潜在的无限序列：


function* naturals(): Generator<number> {
  let n = 0;
  while (true) yield n++;
}
集合论在编程语言中的体现
TypeScript 的类型系统与集合论有着深刻的对应：


    

  • 联合类型 A | B 对应集合的并 A ∪ B
    • 

  • 交叉类型 A & B 对应集合的交 A ∩ B
    • 

  • never 类型对应空集 ∅（没有任何值属于 never）
    • 

  • unknown 类型对应全集 U（所有值都属于 unknown）
    • 

  • 子类型关系 A extends B 对应子集 A ⊆ B
    • 



理解这些对应关系能帮助开发者更直觉地理解 TypeScript 的类型推导行为。例如，string & number 为 never，因为字符串集合和数字集合没有交集。


数据库的关系模型也完全建立在集合论之上。一张表是元组的集合，SELECT 是集合的投影操作，WHERE 是子集选择，JOIN 建立在笛卡尔积的基础上。理解集合论就是理解关系数据库的数学基础。


小结
    

  • 集合是由确定的、互不相同的对象构成的整体，是数学和计算机科学的基础语言
    • 

  • 集合运算律（交换律、分配律、德摩根律）与命题逻辑等价律精确对应
    • 

  • 幂集的大小为 2ⁿ，直接关联子集枚举问题的指数复杂度
    • 

  • 笛卡尔积是关系数据库 JOIN 操作的数学基础
    • 

  • Cantor 的对角线论证不仅揭示了无限集的层次，也是停机问题不可判定性证明的核心思想
    • 

  • TypeScript 的联合类型、交叉类型、never 和 unknown 精确对应集合的并、交、空集和全集
    • 

  • 集合论是理解数据结构、数据库和类型系统的共同理论根基
    •
