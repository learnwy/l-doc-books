图着色与匹配

核心概念

图着色（Graph Coloring）和匹配（Matching）是图论中两个重要的优化问题。图着色为图的顶点（或边）分配颜色，使得相邻元素颜色不同；匹配在图中找到不共享顶点的最大边集。这两个问题看似抽象，却在编译器的寄存器分配、任务调度、资源分配等领域有直接应用。

图着色：给图 G 的每个顶点分配一种颜色，使得相邻顶点颜色不同。使 G 可以被正确着色的最少颜色数称为色数 χ(G)。

匹配：图中没有公共顶点的边的集合。最大匹配是边数最多的匹配。如果匹配覆盖了所有顶点，则称为完美匹配。

图着色与色数
图着色问题的核心是确定色数 χ(G)。虽然精确计算色数是 NP 困难的，但对特殊图类有已知结果：


    

  • 完全图 Kₙ：χ(Kₙ) = n（每个顶点都相邻，需要 n 种颜色）
    • 

  • 二部图：χ = 2（当且仅当图是二部图时可以用 2 种颜色着色）
    • 

  • 奇环 C₂ₖ₊₁：χ = 3
    • 

  • 偶环 C₂ₖ：χ = 2
    • 

  • 树：χ = 2（树是二部图）
    • 

  • 平面图：χ ≤ 4（四色定理）
    • 



四色定理是图论最著名的结果之一：任何平面图都可以用 4 种颜色着色。这意味着任何地图都只需 4 种颜色就能使相邻区域颜色不同。四色定理的证明（1976 年）是第一个依赖计算机验证的重大数学定理。


贪心着色算法：按某种顺序依次给顶点着色，每个顶点选择编号最小的且与已着色邻居不冲突的颜色。贪心着色不一定得到最优解，但保证使用的颜色数不超过 Δ(G)+1，其中 Δ(G) 是图的最大度数。


function greedyColoring(graph: Map<number, number[]>, vertices: number[]): Map<number, number> {
  const color = new Map<number, number>();

  for (const v of vertices) {
    const usedColors = new Set<number>();
    for (const neighbor of graph.get(v) ?? []) {
      if (color.has(neighbor)) {
        usedColors.add(color.get(neighbor)!);
      }
    }

    let c = 0;
    while (usedColors.has(c)) c++;
    color.set(v, c);
  }

  return color;
}
Brooks 定理更精确地限定了色数：对于连通图（非完全图且非奇环），χ(G) ≤ Δ(G)。这意味着贪心着色在大多数情况下可以达到或接近最优。


寄存器分配与区间图着色
编译器中的寄存器分配是图着色最经典的工程应用。编译器需要将程序中的变量分配到有限的 CPU 寄存器中。如果两个变量的"活跃区间"重叠（同时需要存储），它们不能使用同一个寄存器。


将每个变量视为顶点，活跃区间重叠的变量之间连边，就构成了一个干涉图（Interference Graph）。寄存器分配问题就变成了：用 k 种颜色（k 个寄存器）对干涉图进行着色。如果 k < χ(G)，某些变量需要"溢出"到内存。


区间图（Interval Graph）是一类特殊的图，其中每个顶点对应数轴上的一个区间，两个顶点相邻当且仅当对应区间重叠。区间图的着色问题可以在 O(n log n) 时间内最优求解——按区间左端点排序后贪心分配颜色。


区间图着色的一个直接应用是会议室调度：给定 n 个会议的时间区间，需要多少个会议室？答案就是区间图的色数，等于最大重叠数（同一时刻开会的最多数量）。


function minMeetingRooms(intervals: [number, number][]): number {
  const events: [number, number][] = [];
  for (const [start, end] of intervals) {
    events.push([start, 1]);
    events.push([end, -1]);
  }
  events.sort((a, b) => a[0] - b[0] || a[1] - b[1]);

  let maxRooms = 0;
  let currentRooms = 0;
  for (const [, delta] of events) {
    currentRooms += delta;
    maxRooms = Math.max(maxRooms, currentRooms);
  }
  return maxRooms;
}
课程表安排也是区间图着色的变体：多门课程的考试不能在同一时段，如果两门课有共同学生。将课程视为顶点，有共同学生的课程连边，色数就是最少需要的考试时段。


二部图匹配
匹配问题在二部图上尤其重要且有高效算法。Hall 定理给出了二部图存在完美匹配的充要条件：对于 U 的每个子集 S，S 的邻居集 N(S) 的大小不小于 |S|。直觉上，"每组候选人都有足够多的不同职位可选"。


匈牙利算法（Hungarian Algorithm）通过交替路径找到最大匹配，时间复杂度 O(nm)。更高效的 Hopcroft-Karp 算法可以达到 O(m√n)。


function hungarianMatch(graph: Map<number, number[]>, leftSize: number): Map<number, number> {
  const matchRight = new Map<number, number>();

  const augment = (u: number, visited: Set<number>): boolean => {
    for (const v of graph.get(u) ?? []) {
      if (visited.has(v)) continue;
      visited.add(v);
      if (!matchRight.has(v) || augment(matchRight.get(v)!, visited)) {
        matchRight.set(v, u);
        return true;
      }
    }
    return false;
  };

  for (let u = 0; u < leftSize; u++) {
    augment(u, new Set());
  }

  return matchRight;
}

König 定理：在二部图中，最大匹配的大小等于最小顶点覆盖的大小。这个定理将匹配问题与覆盖问题联系起来，在优化问题的对偶分析中非常有用。


加权匹配：在加权二部图中，找到总权值最大（或最小）的完美匹配。匈牙利算法的加权版本可以在 O(n³) 时间内求解。加权匹配用于最优分配问题——如将 n 个任务分配给 n 个工人，使总效率最大。


稳定匹配（Stable Matching）是另一种重要的匹配问题。Gale-Shapley 算法解决"稳定婚姻问题"：n 个男性和 n 个女性各有偏好排序，找到一个匹配使得不存在"更愿意在一起但没有被配对"的一对。这个算法在医院住院医分配系统中被实际使用。


小结
    

  • 图着色使相邻顶点颜色不同，色数 χ(G) 是所需最少颜色数
    • 

  • 四色定理保证平面图最多需要 4 种颜色，是计算机辅助证明的里程碑
    • 

  • 贪心着色使用不超过 Δ(G)+1 种颜色，对大多数实际问题接近最优
    • 

  • 寄存器分配是图着色在编译器中的经典应用，干涉图的色数决定所需寄存器数
    • 

  • 区间图着色（会议室调度）可以在 O(n log n) 时间内最优求解
    • 

  • 二部图最大匹配可用匈牙利算法在 O(nm) 时间求解
    • 

  • Hall 定理和 König 定理建立了匹配与覆盖之间的深刻联系
    • 

  • 加权匹配和稳定匹配是基础匹配问题的重要扩展，在实际分配系统中广泛使用
    • 

  • 图着色和匹配虽然是 NP 困难问题，但在特殊图类上（区间图、二部图）有多项式时间算法
    •
