谓词逻辑

核心概念

谓词逻辑（Predicate Logic），也称一阶逻辑（First-Order Logic, FOL），是命题逻辑的扩展。命题逻辑只能处理完整命题的真假，无法表达"对于所有 x"或"存在某个 x"这类对个体的量化描述。谓词逻辑通过引入谓词、量词和个体变量，极大地增强了逻辑系统的表达能力。

在计算机科学中，谓词逻辑是数据库查询语言（SQL 的 WHERE 子句）、程序规约（前置条件/后置条件）、类型系统（依赖类型）以及定理证明器的理论基础。理解谓词逻辑，就是理解如何用数学语言精确描述程序的行为和性质。

谓词、量词与约束变量
谓词是一个从个体域到真值集合的函数。P(x) 表示"x 具有性质 P"，例如 IsEven(x) 表示"x 是偶数"。多元谓词如 LessThan(x, y) 表示"x 小于 y"。谓词的参数被称为项（term），可以是常量、变量或函数的结果。


全称量词 ∀ 表示"对个体域中的所有个体"。∀x P(x) 读作"对所有 x，P(x) 成立"。在编程中，这对应数组的 every() 方法。


存在量词 ∃ 表示"个体域中至少存在一个个体"。∃x P(x) 读作"存在某个 x，使得 P(x) 成立"。在编程中，这对应数组的 some() 方法。


const isEven = (x: number): boolean => x % 2 === 0;

// ∀x ∈ arr: isEven(x) — 全称量化
const allEven = (arr: number[]): boolean => arr.every(isEven);

// ∃x ∈ arr: isEven(x) — 存在量化
const someEven = (arr: number[]): boolean => arr.some(isEven);
约束变量与自由变量的区分至关重要。在 ∀x P(x, y) 中，x 是被量词约束的约束变量，y 是自由变量。公式的真值取决于自由变量的赋值。当公式中没有自由变量时，称为闭公式（sentence），其真值在给定解释下是确定的。


量词的作用域类似编程中变量的作用域。就像函数参数在函数体内有效一样，量词约束的变量仅在该量词的辖域内有效。量词嵌套时需要特别注意变量遮蔽（shadowing）问题。


个体域（Domain of Discourse）决定了量词的范围。∀x P(x) 中 x 遍历的集合就是个体域。同一公式在不同个体域上可以有不同的真值。例如 ∀x (x² ≥ 0) 在实数域上为真，但如果个体域不明确，公式的含义就不确定。在数据库中，个体域就是表中的所有行。


谓词逻辑的解释（Interpretation）由三部分组成：个体域、谓词的具体含义、常量的指代对象。只有在给定解释下，谓词逻辑公式才有确定的真值。这种"含义分离"的设计使得同一公式可以复用于不同场景，类似编程中接口（interface）与实现（implementation）的分离。


量词的否定与等价变换
量词与否定的交互遵循一组重要的等价律，它们是德摩根律在谓词逻辑中的推广：


    

  • ¬∀x P(x) ≡ ∃x ¬P(x)（"并非所有 x 满足 P"等价于"存在 x 不满足 P"）
    • 

  • ¬∃x P(x) ≡ ∀x ¬P(x)（"不存在 x 满足 P"等价于"所有 x 都不满足 P"）
    • 



这两条规则在编程中直觉上非常自然：


// ¬∀x P(x) ≡ ∃x ¬P(x)
const notAllPositive = (arr: number[]): boolean => arr.some((x) => x <= 0);

// ¬∃x P(x) ≡ ∀x ¬P(x)
const nonePositive = (arr: number[]): boolean => arr.every((x) => x <= 0);
量词交换的规则需要谨慎对待。同类量词可以交换顺序而不改变含义：∀x∀y P(x,y) ≡ ∀y∀x P(x,y)。但不同类量词的顺序不可随意交换：


    

  • ∀x∃y P(x,y)："对每个 x，都存在一个 y"（y 可以依赖 x）
    • 

  • ∃y∀x P(x,y)："存在一个固定的 y，对所有 x 都成立"
    • 



这个区别在编程中对应于：前者相当于"每次调用函数都可以返回不同的结果"，后者相当于"存在一个固定常量满足所有输入"。两者在逻辑强度上有本质差异：后者蕴含前者，但前者不蕴含后者。


多重量词的嵌套在实际问题中经常出现。例如数据库约束"每个订单至少有一个商品"表达为 ∀o (Order(o) → ∃p (Contains(o, p) ∧ Product(p)))。在程序规约中，"对于任意两个不同的键，哈希值不同"表达为 ∀x∀y (x ≠ y → hash(x) ≠ hash(y))，这正是完美哈希函数的定义。


量词与蕴含的组合也有重要的等价关系：


    

  • ∀x (P(x) → Q(x)) 不等价于 ∀x P(x) → ∀x Q(x)
    • 

  • ∃x (P(x) ∧ Q(x)) 不等价于 ∃x P(x) ∧ ∃x Q(x)
    • 



第一个反例：考虑 P(x) = "x 是偶数"，Q(x) = "x 是 2 的倍数"。∀x (P(x) → Q(x)) 为真，但 ∀x P(x) 为假（因为有奇数）。第二个反例：存在偶数且存在奇数，但不存在既是偶数又是奇数的数。


谓词逻辑的推理规则
谓词逻辑在命题逻辑的推理规则基础上，增加了专门处理量词的四条规则：






规则
名称
形式
说明

UI
∀x P(x) ⊢ P(c)

全称概括

P(c) 对任意 c ⊢ ∀x P(x)
对任意个体成立则全称成立




存在实例化
EI
∃x P(x) ⊢ P(c) 某特定 c

存在概括
EG
P(c) ⊢ ∃x P(x)
特定个体满足则存在性成立





全称实例化（UI）是最直观的规则：如果"所有整数都可比较大小"，那么"整数 5 可以比较大小"。在类型系统中，泛型函数的实例化就是 UI 的体现：


// ∀T: Comparable<T> 意味着可以对任意具体类型实例化
function sort<T>(arr: T[], compare: (a: T, b: T) => number): T[] {
  return [...arr].sort(compare);
}

// UI: 将 T 实例化为 number
const sorted = sort([3, 1, 2], (a, b) => a - b);
存在实例化（EI）的限制较严格：引入的常量 c 必须是之前未使用过的新名称（Skolem 常量），避免与其他变量混淆。在证明中，存在实例化相当于"取一个满足条件的见证者，给它一个名字"。


结合命题逻辑的推理规则和量词规则，可以构造完整的谓词逻辑证明。典型的证明策略是：先用 UI 将全称前提实例化，再用命题逻辑推理得出中间结论，最后用 UG 或 EG 重新量化。


值得注意的是，全称概括（UG）有严格的使用条件：用于推导的 c 不能是 EI 引入的特定常量，也不能在任何前提中出现。违反这一限制会导致错误推理。例如，不能从"Alice 是程序员"推导出"所有人都是程序员"。


// Skolem 化：消除存在量词
// ∀x ∃y P(x, y) → ∀x P(x, f(x))
// 存在量词被替换为一个依赖于外层全称变量的函数
type SkolemFunction<A, B> = (a: A) => B;

const findMatch: SkolemFunction<number, number> = (x) => x * 2;
Skolem 化是将存在量词系统地消除的方法，在自动定理证明中广泛使用。∃y P(y) 替换为 P(c)（c 为新常量），而 ∀x ∃y P(x,y) 替换为 ∀x P(x, f(x))（f 为新函数符号，称为 Skolem 函数）。


谓词逻辑在工程中的应用
SQL 与关系代数：SQL 的 WHERE 子句本质上是谓词。SELECT * FROM users WHERE age > 18 AND active = true 对应 ∀(符合条件的行) 返回。EXISTS 子查询直接对应存在量词 ∃。


程序规约：Hoare 三元组 {P} S {Q} 中，前置条件 P 和后置条件 Q 通常用谓词逻辑表达。例如，排序函数的后置条件是 ∀i (0 ≤ i < n-1 → a[i] ≤ a[i+1])，即"对所有相邻元素，前者不大于后者"。


类型系统：TypeScript 的泛型约束 <T extends Comparable> 表达的是"对所有满足 Comparable 的类型 T"，这就是全称量化。而依赖类型系统（如 Idris、Agda）可以直接在类型中编码谓词逻辑公式。


定理证明器：Coq、Lean 等定理证明器的核心逻辑是高阶逻辑（谓词逻辑的推广），用户通过构造程序来完成证明。这些工具已被用于验证编译器（CompCert）、操作系统（seL4）等关键软件的正确性。


API 契约验证：RESTful API 的请求/响应约束也可以用谓词逻辑描述。例如"对于所有包含 Authorization 头的请求（∀r），如果 token 有效（Valid(r.token)），则响应状态码为 200（Status(r) = 200）"。OpenAPI 规范和 JSON Schema 本质上是谓词逻辑约束的受限子集。


ORM 查询构建：现代 ORM 框架（如 Prisma、TypeORM）的查询接口将谓词逻辑的 where 子句映射为类型安全的 API。where: { age: { gt: 18 }, active: true } 就是 ∃x (Age(x) > 18 ∧ Active(x)) 的程序化表达。


小结
    

  • 谓词逻辑通过谓词和量词扩展了命题逻辑，能够表达对个体集合的量化描述
    • 

  • ∀ 对应 every()，∃ 对应 some()，量词否定遵循德摩根律的推广
    • 

  • 不同类量词的顺序不可交换，∃y∀x 强于 ∀x∃y，这是初学者常见的理解盲区
    • 

  • 约束变量与自由变量的区分类似编程中的变量作用域
    • 

  • 泛型实例化是全称实例化（UI）在类型系统中的直接体现
    • 

  • 谓词逻辑是 SQL、程序规约、泛型类型系统和定理证明器的共同理论基础
    • 

  • 谓词逻辑的一阶片段是可判定的（如命题逻辑），但完整的一阶逻辑是半可判定的——存在证明可以找到，但不存在证明可能永远无法确认
    •
