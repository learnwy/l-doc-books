证明技术

核心概念

数学证明是从公理和已知定理出发，通过逻辑推理得出新命题为真的过程。对于程序员来说，掌握证明技术不是为了成为数学家，而是为了获得一种严密的推理习惯——证明算法的正确性、分析递归的终止性、论证数据结构的不变量。

证明技术可以按策略分为几大类：直接从前提推导结论的直接证明、通过否定结论导出矛盾的反证法、从基础情形逐步推广的数学归纳法，以及通过实际构造来证明存在性的构造性证明。每种技术都有其最适合的问题类型。

直接证明与反证法
直接证明是最自然的证明策略：要证 p → q，假设 p 为真，通过一系列逻辑推导得出 q 为真。


经典示例：证明"两个偶数之和为偶数"。设 a = 2m, b = 2n（偶数的定义），则 a + b = 2m + 2n = 2(m + n)，这是 2 的整数倍，因此 a + b 为偶数。


function sumOfEvens(a: number, b: number): number {
  // 前提: a 和 b 都是偶数
  // 直接推导: a = 2m, b = 2n, a+b = 2(m+n)
  // 结论: 结果也是偶数
  return a + b;
}
反证法（Proof by Contradiction）的策略是：假设要证明的命题 P 为假（即假设 ¬P 为真），然后推导出矛盾。既然 ¬P 导致矛盾，那么 P 必为真。


经典示例：证明 √2 是无理数。假设 √2 = p/q（最简分数），则 2q² = p²，所以 p² 为偶数，进而 p 为偶数（设 p = 2k），代入得 q² = 2k²，q 也为偶数。但 p 和 q 都是偶数与"最简分数"矛盾。因此 √2 是无理数。


反证法在计算机科学中的典型应用包括：证明停机问题不可判定、证明某些问题没有多项式时间算法（在假设 P ≠ NP 下）。


归谬法（Proof by Contrapositive）是反证法的变体：要证 p → q，转而证明等价的 ¬q → ¬p。这通常在直接从 p 推导 q 很困难，但从 ¬q 推导 ¬p 相对容易时使用。


例如：证明"如果 n² 是偶数，则 n 是偶数"。直接证明需要从 n² 的偶数性推导 n 的偶数性，不太直观。用归谬法：假设 n 是奇数（¬q），则 n = 2k+1，n² = 4k²+4k+1 = 2(2k²+2k)+1 是奇数（¬p）。因此逆否命题成立，原命题也成立。


分情况证明（Proof by Cases）也是一种重要的策略：将命题的条件分为若干互不遗漏的情况，分别证明每种情况下结论都成立。在编程中，这对应 switch-case 或 pattern matching 的逻辑。例如证明 |xy| = |x||y|，需要分四种情况讨论 x 和 y 的正负性。


数学归纳法
数学归纳法是证明对所有自然数 n（或所有满足某条件的整数 n）成立的命题的标准方法。它包含两步：


    

  1. 基础步（Base Case）：证明 P(0)（或 P(1)）成立
    2. 

  2. 归纳步（Inductive Step）：证明对任意 k，若 P(k) 成立，则 P(k+1) 也成立
    3. 



归纳步中的假设 P(k) 被称为归纳假设（Inductive Hypothesis）。归纳法的正确性基于自然数的良序性质——每个非空自然数子集都有最小元素。


经典示例：证明 1 + 2 + ... + n = n(n+1)/2。


    

  • 基础步：n = 1 时，1 = 1×2/2 = 1 ✓
    • 

  • 归纳步：假设对 k 成立，即 1+2+...+k = k(k+1)/2。则 1+2+...+k+(k+1) = k(k+1)/2 + (k+1) = (k+1)(k+2)/2 ✓
    • 



// 数学归纳法与递归的对应
function sumTo(n: number): number {
  if (n === 1) return 1; // 基础步
  return sumTo(n - 1) + n; // 归纳步: 假设 sumTo(n-1) 正确
}
强归纳法（Strong Induction）允许在归纳步中假设 P(0), P(1), ..., P(k) 全部成立来推导 P(k+1)。强归纳法在分析分治算法时尤为有用，因为分治往往不是从 n-1 递推到 n，而是从 n/2 等多个子问题推导。


结构归纳法（Structural Induction）将归纳法推广到递归定义的数据结构上。对树的性质做归纳时，基础步是叶节点的情形，归纳步是假设子树满足性质后证明整棵树也满足。这与递归遍历树结构的逻辑完全一致。


结构归纳法的一个经典应用是证明"满二叉树中叶节点数 = 内部节点数 + 1"：


    

  • 基础步：只有一个叶节点的树，叶节点数 = 1 = 0 + 1 ✓
    • 

  • 归纳步：假设左子树 L_leaves = L_internal + 1，右子树 R_leaves = R_internal + 1。整棵树的叶节点数 = L_leaves + R_leaves = (L_internal + 1) + (R_internal + 1) = (L_internal + R_internal + 1) + 1 = 内部节点数 + 1 ✓
    • 



interface TreeNode<T> {
  value: T;
  left?: TreeNode<T>;
  right?: TreeNode<T>;
}

function countLeaves<T>(node: TreeNode<T>): number {
  if (!node.left && !node.right) return 1;
  return (node.left ? countLeaves(node.left) : 0) + (node.right ? countLeaves(node.right) : 0);
}
构造性证明与反例法
构造性证明用于证明存在性命题（∃x P(x)）。与单纯论证"必定存在"不同，构造性证明要求实际给出满足条件的对象。


经典示例：证明"存在两个无理数 a 和 b，使得 a^b 是有理数"。考虑 √2^√2，如果它是有理数，则 a = b = √2 即可。如果它是无理数，则令 a = √2^√2, b = √2，则 a^b = (√2^√2)^√2 = √2^2 = 2，是有理数。无论哪种情况，存在性都得到证明。


在软件工程中，构造性证明对应于"实现即证明"的思想。如果需要证明某种数据转换是可能的，最直接的方法就是写出转换代码。这也是 Curry-Howard 同构的实际意义：一个正确的程序就是对应命题的构造性证明。


反例法用于否证全称命题（∀x P(x)）。只需找到一个不满足 P 的具体 x 即可。在编程实践中，这对应于单元测试——如果找到一个使函数行为不符预期的输入，就证明了函数实现有误。


// 反例法: 否证"所有排序算法都是稳定的"
// 反例: 快速排序是不稳定的
const data = [
  { key: 1, order: 'first' },
  { key: 1, order: 'second' },
];
// 快排后相同 key 的元素顺序可能改变 → 反例成立
属性基测试（Property-Based Testing）工具如 fast-check 自动化了反例搜索的过程：随机生成大量输入，检查某个全称性质是否总是成立，一旦发现反例则自动缩小到最简反例。


非构造性证明与构造性证明相对，它证明某对象存在但不给出具体构造。前面提到的 √2^√2 示例实际上是非构造性的——我们不知道 √2^√2 究竟是有理数还是无理数，只知道两种情况下都有满足条件的例子。在可计算性理论中，非构造性证明的结论有时无法转化为算法，这就是直觉主义逻辑和经典逻辑之间分歧的根源。

在算法分析的实际场景中，这些证明技术以组合方式出现：


    

  • 循环不变量：用数学归纳法证明每次迭代后某性质保持成立
    • 

  • 算法终止性：构造一个严格递减的非负整数序列（良序原理）
    • 

  • 下界证明：用反证法证明某问题不存在更快的算法
    • 

  • 递归正确性：结构归纳法验证递归函数对所有合法输入产生正确输出
    • 



掌握这些技术后，你会发现"证明"不再是纸上的数学练习，而是分析代码、设计测试、论证架构决策时不可或缺的思维工具。


小结
    

  • 直接证明最自然：假设前提为真，逐步推导出结论
    • 

  • 反证法在证明不可能性和否定性命题时最为有力
    • 

  • 数学归纳法是递归程序正确性论证的数学基础，强归纳法对应分治策略
    • 

  • 结构归纳法将归纳推理推广到树等递归数据结构
    • 

  • 构造性证明体现"实现即证明"的 Curry-Howard 精神
    • 

  • 反例法对应单元测试的思想：一个反例足以否证全称命题
    • 

  • 证明技术的选择取决于命题类型，实际中常组合使用
    •
