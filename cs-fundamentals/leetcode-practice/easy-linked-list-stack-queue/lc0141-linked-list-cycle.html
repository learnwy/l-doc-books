LeetCode 141 环形链表

题目描述

给你一个链表的头节点 head，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 next 指针再次到达，则链表中存在环。为了表示给定链表中的环，评测系统内部使用整数 pos 来表示链表尾连接到链表中的位置（索引从 0 开始）。注意：pos 不作为参数进行传递。仅仅是为了标识链表的实际情况。

如果链表中存在环，则返回 true；否则，返回 false。

约束条件：

  • 链表中节点的数目范围是 [0, 10⁴]
  • -10⁵ <= Node.val <= 10⁵
  • pos 为 -1 或者链表中的一个有效索引

示例 1：

输入：head = [3,2,0,-4], pos = 1
输出：true
解释：链表中有一个环，其尾部连接到第二个节点

示例 2：

输入：head = [1,2], pos = 0
输出：true
解释：链表中有一个环，其尾部连接到第一个节点

示例 3：

输入：head = [1], pos = -1
输出：false
解释：链表中没有环

解题思路

判断链表是否有环是经典的链表问题，有两种主要方法。

方法一：哈希表

遍历链表，将每个访问过的节点存入哈希集合（Set）。如果遇到已存在于集合中的节点，说明存在环；如果遍历到 null，说明无环。

这种方法直观但需要 O(n) 额外空间。

方法二：快慢指针（Floyd 判圈法）

这是本题最经典的解法，也被称为"龟兔赛跑"算法：

  1. 设置两个指针：慢指针 slow 每次走一步，快指针 fast 每次走两步
  2. 如果链表无环，fast 会先到达 null
  3. 如果链表有环，fast 和 slow 最终会在环内相遇

为什么一定会相遇？ 当两个指针都进入环后，每次迭代 fast 比 slow 多走一步，相当于 fast 以每步 1 的速度追赶 slow。设环长为 C，两者进入环时的距离差为 d，那么经过 C - d 步后 fast 一定会追上 slow。

方法 时间复杂度 空间复杂度 优点 缺点
哈希表 O(n) O(n) 直观易理解 需要额外空间
快慢指针 O(n) O(1) 空间最优 需要理解数学证明

代码实现

方法一：快慢指针（推荐）

function hasCycle(head: ListNode | null): boolean {
  let slow = head;
  let fast = head;

  while (fast !== null && fast.next !== null) {
    slow = slow!.next;
    fast = fast.next.next;

    if (slow === fast) {
      return true;
    }
  }

  return false;
}

注意循环条件 fast !== null && fast.next !== null 确保 fast.next.next 不会出现空指针异常。slow 每次走一步，fast 每次走两步，如果存在环，它们一定会相遇。

方法二：哈希表

function hasCycleHash(head: ListNode | null): boolean {
  const visited = new Set<ListNode>();
  let current = head;

  while (current !== null) {
    if (visited.has(current)) {
      return true;
    }
    visited.add(current);
    current = current.next;
  }

  return false;
}

哈希表方法注意要存储节点引用而非节点值，因为不同位置的节点可能有相同的值。

复杂度分析

方法 时间复杂度 空间复杂度 说明
快慢指针 O(n) O(1) 无环时遍历 n 步；有环时最多 n + C 步（C 为环长）
哈希表 O(n) O(n) 最多存储 n 个节点引用

快慢指针的时间复杂度分析：无环情况下，fast 最多走 n/2 次循环。有环情况下，slow 进入环后，fast 最多再走 C 步追上（C 为环长，C ≤ n），所以总步数不超过 2n。

本题是 Floyd 算法的基础应用。进阶题 LC #142（环形链表 II）要求找到环的入口节点，需要在两指针相遇后进行第二阶段分析——从相遇点和头节点同时出发，以相同速度行走，再次相遇点即为环入口。这个结论的证明涉及简单的数学推导。
