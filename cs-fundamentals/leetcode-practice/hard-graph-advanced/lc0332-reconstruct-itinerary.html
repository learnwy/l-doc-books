LeetCode 332 重新安排行程

题目描述

给定一个航班列表 tickets，其中 tickets[i] = [fromi, toi] 表示一张从 fromi 飞往 toi 的机票。请按照以下规则重新安排行程：

  1. 行程必须从 "JFK" 出发
  2. 所有机票恰好使用一次
  3. 如果存在多种有效行程，返回字典序最小的那个

约束条件：

  • 1 <= tickets.length <= 300
  • tickets[i].length == 2
  • fromi.length == 3
  • toi.length == 3
  • fromi 和 toi 由大写英文字母组成
  • fromi != toi

示例 1：

输入：tickets = [["MUC","LHR"],["JFK","MUC"],["SFO","SJC"],["LHR","SFO"]]
输出：["JFK","MUC","LHR","SFO","SJC"]

示例 2：

输入：tickets = [["JFK","SFO"],["JFK","ATL"],["SFO","ATL"],["ATL","JFK"],["ATL","SFO"]]
输出：["JFK","ATL","JFK","SFO","ATL","SFO"]
解释：另一种有效行程为 ["JFK","SFO","ATL","JFK","ATL","SFO"]，但字典序更大。

解题思路

本题的本质是在有向多重图中寻找欧拉路径（Eulerian Path）——一条恰好经过每条边一次的路径。

关键洞察：

  1. 题目保证至少存在一个合理的行程（即欧拉路径一定存在）
  2. 要求字典序最小，所以在选择下一个目的地时应优先选字典序最小的
  3. 起点固定为 "JFK"

Hierholzer 算法 是寻找欧拉路径/回路的标准算法。其核心思想是：

  • 从起点出发进行 DFS
  • 每次贪心地选择字典序最小的邻居
  • 当一个节点没有未使用的出边时，将其加入结果的头部
  • 最终得到的逆序结果就是欧拉路径

为什么要"后序"加入结果？考虑一种情况：从当前节点出发，有多条出边，其中一条边通往一个"死胡同"（只有入边没有未用出边的子图）。如果先走死胡同，DFS 会先返回，该节点先被加入结果。然后继续走其他分支。最后反转整个结果，死胡同节点就在路径末尾，确保了路径的正确性。

代码实现
Hierholzer 算法（递归版）：


function findItinerary(tickets: string[][]): string[] {
  const graph: Map<string, string[]> = new Map();

  for (const [from, to] of tickets) {
    if (!graph.has(from)) graph.set(from, []);
    graph.get(from)!.push(to);
  }

  for (const [, dests] of graph) {
    dests.sort();
  }

  const result: string[] = [];

  const dfs = (node: string) => {
    const dests = graph.get(node);
    while (dests && dests.length > 0) {
      const next = dests.shift()!;
      dfs(next);
    }
    result.push(node);
  };

  dfs('JFK');
  return result.reverse();
}
Hierholzer 算法（迭代版）：


function findItineraryIterative(tickets: string[][]): string[] {
  const graph: Map<string, string[]> = new Map();

  for (const [from, to] of tickets) {
    if (!graph.has(from)) graph.set(from, []);
    graph.get(from)!.push(to);
  }

  for (const [, dests] of graph) {
    dests.sort();
  }

  const stack: string[] = ['JFK'];
  const result: string[] = [];

  while (stack.length > 0) {
    const top = stack[stack.length - 1];
    const dests = graph.get(top);
    if (dests && dests.length > 0) {
      stack.push(dests.shift()!);
    } else {
      result.push(stack.pop()!);
    }
  }

  return result.reverse();
}
易错点分析：


一个常见的错误是使用简单的贪心 DFS——总是选择字典序最小的目的地并直接加入结果。这在存在"死胡同"时会出错。例如：


JFK → [A, B]
A → [JFK]
B → []
简单贪心会走 JFK→A→JFK→B，但如果先走 B 就会卡住。Hierholzer 的后序插入巧妙地解决了这个问题：B 是死胡同，DFS 先返回 B，然后继续处理其他边，最终 B 在路径末尾。

时间复杂度详解： 排序邻接表需要 O(E log E)，DFS 遍历每条边恰好一次需要 O(E)。总计 O(E log E)。在本题中 E ≤ 300，非常快速。


空间复杂度详解： 邻接表 O(E)，递归栈或显式栈最深 O(E)（最坏情况下路径长度等于边数+1），结果数组 O(E)。总计 O(V + E)。


实战建议： 欧拉路径问题在面试中不算高频，但一旦出现就需要知道 Hierholzer 算法。关键记忆点是"后序插入 + 最终反转"。迭代版更安全，不会有栈溢出风险。
