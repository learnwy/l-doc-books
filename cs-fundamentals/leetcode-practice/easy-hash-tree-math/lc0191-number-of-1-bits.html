LeetCode 191 位 1 的个数

题目描述

给定一个正整数 n，编写一个函数，返回其二进制表示中数字位为 1 的个数（也被称为汉明重量）。

约束条件：

  • 1 <= n <= 2^31 - 1

示例 1：

输入：n = 11（二进制：1011）
输出：3
解释：输入的二进制 1011 中，共有三位为 1

示例 2：

输入：n = 128（二进制：10000000）
输出：1

示例 3：

输入：n = 2147483645（二进制：01111111111111111111111111111101）
输出：30

进阶： 如果多次调用这个函数，你将如何优化你的算法？

汉明重量（Hamming Weight）是位运算中的基础概念，在密码学、纠错编码、数据压缩等领域有广泛应用。本题将介绍多种计算汉明重量的方法，从基础的逐位检查到高效的 Brian Kernighan 算法。

解题思路

方法一：逐位检查

最直接的方法是检查整数的每一位是否为 1。通过将 n 与 1 进行按位与（AND）运算，可以判断最低位是否为 1。然后将 n 右移一位，重复这个过程，直到 n 变为 0。

方法二：Brian Kernighan 算法

这是一种更高效的方法，其核心思想是：n & (n - 1) 会将 n 的最低位的 1 变为 0。

为什么？因为 n - 1 会将 n 的最低位 1 及其右边所有位取反。例如：

  • n = 1100，n - 1 = 1011，n & (n - 1) = 1000

每执行一次这个操作，就消除一个 1。因此，执行的次数就等于 1 的个数。

方法 循环次数 核心操作 适用场景
逐位检查 固定 32 次 n & 1，右移 通用，固定开销
Brian Kernighan k 次（k 为 1 的个数） n & (n-1) 1 较少时更快
查表法 O(1) 预计算表 高频调用场景

方法三：查表法

对于高频调用场景，可以预计算一张查找表。例如将 32 位整数拆分为 4 个 8 位段，每段通过查表获取其 1 的个数，最后累加。这种方法的时间复杂度为 O(1)，适用于需要大量计算汉明重量的场景。

Brian Kernighan 算法的优势

当整数中 1 的个数较少时，Brian Kernighan 算法的循环次数远少于 32。例如对于 n = 128（只有 1 个 1），逐位检查需要 8 次循环（右移到 0 为止），而 Brian Kernighan 只需要 1 次。

代码实现

逐位检查法

function hammingWeight(n: number): number {
  let count = 0;

  while (n !== 0) {
    count += n & 1;
    n >>>= 1;
  }

  return count;
}

Brian Kernighan 算法（推荐）

function hammingWeight(n: number): number {
  let count = 0;

  while (n !== 0) {
    n &= n - 1;
    count++;
  }

  return count;
}

Brian Kernighan 执行过程：

以 n = 11（二进制 1011）为例：

步骤 n（二进制） n - 1（二进制） n & (n-1)（二进制） count
1 1011 1010 1010 1
2 1010 1001 1000 2
3 1000 0111 0000 3

循环 3 次后 n = 0，退出循环，返回 count = 3。恰好等于 1011 中 1 的个数。

查表法

const TABLE = new Uint8Array(256);
for (let i = 1; i < 256; i++) {
  TABLE[i] = TABLE[i & (i - 1)] + 1;
}

function hammingWeight(n: number): number {
  return TABLE[n & 0xff] + TABLE[(n >>> 8) & 0xff] + TABLE[(n >>> 16) & 0xff] + TABLE[(n >>> 24) & 0xff];
}

逐位检查执行过程：

以 n = 11（二进制 1011）为例：

步骤 n（二进制） n & 1 count n >>>= 1
1 1011 1 1 0101
2 0101 1 2 0010
3 0010 0 2 0001
4 0001 1 3 0000

需要 4 次循环才结束，而 Brian Kernighan 只需 3 次。

复杂度分析

方法 时间复杂度 空间复杂度 说明
逐位检查 O(log n) O(1) 最多 32 次循环
Brian Kernighan O(k) O(1) k 为 1 的个数
查表法 O(1) O(1) 常数次查表

时间复杂度分析： 逐位检查法的循环次数等于 n 的二进制位数，最多 32 次（对于 32 位整数）。Brian Kernighan 法的循环次数等于 1 的个数 k，最少 0 次（n=0），最多 32 次。查表法固定 4 次查表操作。

空间复杂度分析： 逐位检查和 Brian Kernighan 都只用了常数个变量，空间 O(1)。查表法需要 256 字节的预计算表，但这是常数空间。

JavaScript 中的位运算注意事项： JavaScript 中的位运算符会将操作数转换为 32 位有符号整数。使用 >>> （无符号右移）而非 >> （有符号右移），可以确保高位补 0 而不是补符号位。这在处理大正整数时尤为重要。此外，n & (n - 1) 这个技巧不仅用于计数，还广泛应用于判断一个数是否是 2 的幂（n > 0 && (n & (n - 1)) === 0），是位运算中最重要的基础模式之一。
