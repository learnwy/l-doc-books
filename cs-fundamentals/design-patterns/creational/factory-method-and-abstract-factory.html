工厂方法与抽象工厂

核心概念

工厂方法模式（Factory Method）和抽象工厂模式（Abstract Factory）是两个紧密相关的创建型模式。它们的共同目标是将对象的创建与使用分离——让代码依赖抽象而非具体类，使得新增产品类型时不需要修改已有代码。

工厂方法模式
结构
实现
interface Notification {
  send(message: string): void;
}

class EmailNotification implements Notification {
  send(message: string): void {
    console.log(`📧 Email: ${message}`);
  }
}

class SMSNotification implements Notification {
  send(message: string): void {
    console.log(`📱 SMS: ${message}`);
  }
}

class PushNotification implements Notification {
  send(message: string): void {
    console.log(`🔔 Push: ${message}`);
  }
}

abstract class NotificationCreator {
  abstract createNotification(): Notification;

  notify(message: string): void {
    const notification = this.createNotification();
    notification.send(message);
  }
}

class EmailNotificationCreator extends NotificationCreator {
  createNotification(): Notification {
    return new EmailNotification();
  }
}

class SMSNotificationCreator extends NotificationCreator {
  createNotification(): Notification {
    return new SMSNotification();
  }
}

class PushNotificationCreator extends NotificationCreator {
  createNotification(): Notification {
    return new PushNotification();
  }
}

function sendAlert(creator: NotificationCreator): void {
  creator.notify('System alert: CPU usage exceeds 90%');
}

sendAlert(new EmailNotificationCreator());
sendAlert(new SMSNotificationCreator());
sendAlert(new PushNotificationCreator());
sendAlert 函数无需知道具体使用哪种通知方式。新增一种通知类型（如 Slack 通知），只需新建一个 Creator 子类和对应的 Product 类。




简单工厂（非 GoF 模式）
在实际 TypeScript 项目中，完整的工厂方法类层次往往过于繁重。更常见的是使用简单工厂：


type NotificationType = 'email' | 'sms' | 'push';

class NotificationFactory {
  static create(type: NotificationType): Notification {
    switch (type) {
      case 'email':
        return new EmailNotification();
      case 'sms':
        return new SMSNotification();
      case 'push':
        return new PushNotification();
    }
  }
}

const notification = NotificationFactory.create('email');
notification.send('Hello from simple factory');
简单工厂不是 GoF 模式，但在中小型项目中非常实用。它的缺点是新增类型需要修改 switch 语句，违反了开放封闭原则。


用注册表解决扩展性
class NotificationRegistry {
  private static registry = new Map<string, () => Notification>();

  static register(type: string, factory: () => Notification): void {
    this.registry.set(type, factory);
  }

  static create(type: string): Notification {
    const factory = this.registry.get(type);
    if (!factory) throw new Error(`Unknown notification type: ${type}`);
    return factory();
  }
}

NotificationRegistry.register('email', () => new EmailNotification());
NotificationRegistry.register('sms', () => new SMSNotification());
NotificationRegistry.register('push', () => new PushNotification());

const n = NotificationRegistry.create('sms');
n.send('Hello from registry factory');


抽象工厂模式
结构
当你需要创建一族相关对象时，抽象工厂是正确的选择。


实现：UI 组件库主题
interface Button {
  render(): string;
}

interface Input {
  render(): string;
}

interface Modal {
  render(): string;
}

interface UIFactory {
  createButton(): Button;
  createInput(): Input;
  createModal(): Modal;
}

class LightButton implements Button {
  render(): string {
    return "<button class='light-btn'>Light Button</button>";
  }
}

class LightInput implements Input {
  render(): string {
    return "<input class='light-input' />";
  }
}

class LightModal implements Modal {
  render(): string {
    return "<div class='light-modal'>Light Modal</div>";
  }
}

class DarkButton implements Button {
  render(): string {
    return "<button class='dark-btn'>Dark Button</button>";
  }
}

class DarkInput implements Input {
  render(): string {
    return "<input class='dark-input' />";
  }
}

class DarkModal implements Modal {
  render(): string {
    return "<div class='dark-modal'>Dark Modal</div>";
  }
}

class LightThemeFactory implements UIFactory {
  createButton(): Button {
    return new LightButton();
  }
  createInput(): Input {
    return new LightInput();
  }
  createModal(): Modal {
    return new LightModal();
  }
}

class DarkThemeFactory implements UIFactory {
  createButton(): Button {
    return new DarkButton();
  }
  createInput(): Input {
    return new DarkInput();
  }
  createModal(): Modal {
    return new DarkModal();
  }
}

function renderPage(factory: UIFactory): void {
  const button = factory.createButton();
  const input = factory.createInput();
  const modal = factory.createModal();

  console.log(button.render());
  console.log(input.render());
  console.log(modal.render());
}

renderPage(new LightThemeFactory());
renderPage(new DarkThemeFactory());
抽象工厂确保了同一主题下的所有 UI 组件在视觉风格上的一致性——你不会混用 Light 主题的按钮和 Dark 主题的输入框。




工厂方法 vs 抽象工厂




维度
工厂方法
抽象工厂





产品数量

一族相关产品




扩展方向
新增产品类型（纵向）
新增产品族（横向）




复杂度
较低
较高




典型场景
创建单一对象的变体
创建风格一致的一组对象







常见误区
误区一：所有 new 都要用工厂
只有当对象的创建逻辑需要被封装和复用，或者需要根据条件选择不同实现时，才值得引入工厂。简单对象直接 new 即可。


误区二：混淆工厂方法和简单工厂
简单工厂用一个静态方法和条件分支来创建对象。工厂方法通过继承和多态来创建对象，更符合开放封闭原则但更复杂。


误区三：抽象工厂适合所有多产品场景
抽象工厂专门解决"产品族"问题——一组必须配套使用的相关产品。如果产品之间没有关联性，不需要抽象工厂。




小结
    

  • 工厂方法将对象创建委托给子类，适合单个产品的创建。
    • 

  • 抽象工厂创建一族相关对象，确保产品之间的一致性。
    • 

  • 简单工厂在实际项目中最常用，注册表模式可改善其扩展性。
    • 

  • 选择工厂模式的信号：创建逻辑复杂、需要根据条件创建不同类型、希望解耦创建与使用。
