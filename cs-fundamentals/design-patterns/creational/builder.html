建造者模式

核心概念

建造者模式（Builder Pattern）将一个复杂对象的构建过程与其表示分离，使得同样的构建过程可以创建不同的表示。当一个对象有大量可选参数或需要多步骤构建时，Builder 模式是优雅的解决方案。

classDiagram
    class Builder {
        <<interface>>
        +setPartA(value): Builder
        +setPartB(value): Builder
        +setPartC(value): Builder
        +build(): Product
    }
    class ConcreteBuilder {
        -product: Product
        +setPartA(value): Builder
        +setPartB(value): Builder
        +setPartC(value): Builder
        +build(): Product
    }
    class Product {
        +partA: string
        +partB: number
        +partC: boolean
    }
    class Director {
        +construct(builder: Builder): Product
    }

    Builder <|.. ConcreteBuilder
    ConcreteBuilder ..> Product : creates
    Director --> Builder : uses

问题背景：伸缩构造函数

class HttpRequest {
  constructor(
    url: string,
    method?: string,
    headers?: Record<string, string>,
    body?: string,
    timeout?: number,
    retries?: number,
    cache?: boolean,
    auth?: { username: string; password: string },
  ) {}
}

new HttpRequest(
  'https://api.example.com',
  'POST',
  { 'Content-Type': 'application/json' },
  '{"key":"value"}',
  5000,
  3,
  false,
  undefined,
);

参数列表冗长、顺序容易搞错、可读性极差。这就是经典的"伸缩构造函数"问题。构造方式的选择可以对照下表：

构造方式 可读性 可选参数支持 参数校验时机 适用规模
多参数构造函数 差，靠位置记忆 需传 undefined 占位 构造时 参数 ≤3 个
参数对象 中，靠字段名 天然支持 构造时 参数 4+ 但无链式需求
Builder 好，链式赋值 天然支持 build() 时集中校验 参数多且需分步/复用

链式 Builder 实现

interface HttpRequestConfig {
  url: string;
  method: string;
  headers: Record<string, string>;
  body?: string;
  timeout: number;
  retries: number;
  cache: boolean;
  auth?: { username: string; password: string };
}

class HttpRequestBuilder {
  private config: HttpRequestConfig;

  constructor(url: string) {
    this.config = {
      url,
      method: 'GET',
      headers: {},
      timeout: 30000,
      retries: 0,
      cache: true,
    };
  }

  method(method: string): this {
    this.config.method = method;
    return this;
  }

  header(key: string, value: string): this {
    this.config.headers[key] = value;
    return this;
  }

  body(body: string): this {
    this.config.body = body;
    return this;
  }

  timeout(ms: number): this {
    this.config.timeout = ms;
    return this;
  }

  retries(count: number): this {
    this.config.retries = count;
    return this;
  }

  cache(enabled: boolean): this {
    this.config.cache = enabled;
    return this;
  }

  auth(username: string, password: string): this {
    this.config.auth = { username, password };
    return this;
  }

  build(): HttpRequestConfig {
    return { ...this.config };
  }
}

const request = new HttpRequestBuilder('https://api.example.com')
  .method('POST')
  .header('Content-Type', 'application/json')
  .body(JSON.stringify({ key: 'value' }))
  .timeout(5000)
  .retries(3)
  .cache(false)
  .build();

链式调用让每个参数的含义一目了然，且可选参数可以自由省略。

Director 模式

当某些构建流程是固定的、可复用的，可以引入 Director 来封装构建步骤：

class HttpRequestDirector {
  static createJsonPost(url: string, data: unknown): HttpRequestConfig {
    return new HttpRequestBuilder(url)
      .method('POST')
      .header('Content-Type', 'application/json')
      .header('Accept', 'application/json')
      .body(JSON.stringify(data))
      .timeout(10000)
      .retries(2)
      .build();
  }

  static createAuthenticatedGet(url: string, username: string, password: string): HttpRequestConfig {
    return new HttpRequestBuilder(url).method('GET').auth(username, password).timeout(15000).cache(true).build();
  }

  static createFileUpload(url: string, fileContent: string): HttpRequestConfig {
    return new HttpRequestBuilder(url)
      .method('PUT')
      .header('Content-Type', 'application/octet-stream')
      .body(fileContent)
      .timeout(60000)
      .retries(3)
      .cache(false)
      .build();
  }
}

const postRequest = HttpRequestDirector.createJsonPost('https://api.example.com/users', {
  name: 'Alice',
  email: 'alice@example.com',
});

const getRequest = HttpRequestDirector.createAuthenticatedGet('https://api.example.com/me', 'admin', 'secret');

实际应用：查询构建器

class QueryBuilder {
  private table = '';
  private conditions: string[] = [];
  private orderByClause = '';
  private limitValue?: number;
  private offsetValue?: number;
  private selectedFields: string[] = ['*'];

  from(table: string): this {
    this.table = table;
    return this;
  }

  select(...fields: string[]): this {
    this.selectedFields = fields;
    return this;
  }

  where(condition: string): this {
    this.conditions.push(condition);
    return this;
  }

  orderBy(field: string, direction: 'ASC' | 'DESC' = 'ASC'): this {
    this.orderByClause = `ORDER BY ${field} ${direction}`;
    return this;
  }

  limit(value: number): this {
    this.limitValue = value;
    return this;
  }

  offset(value: number): this {
    this.offsetValue = value;
    return this;
  }

  build(): string {
    if (!this.table) throw new Error('Table is required');

    const parts = [`SELECT ${this.selectedFields.join(', ')}`, `FROM ${this.table}`];

    if (this.conditions.length > 0) {
      parts.push(`WHERE ${this.conditions.join(' AND ')}`);
    }
    if (this.orderByClause) {
      parts.push(this.orderByClause);
    }
    if (this.limitValue !== undefined) {
      parts.push(`LIMIT ${this.limitValue}`);
    }
    if (this.offsetValue !== undefined) {
      parts.push(`OFFSET ${this.offsetValue}`);
    }

    return parts.join(' ');
  }
}

const query = new QueryBuilder()
  .from('users')
  .select('id', 'name', 'email')
  .where('age > 18')
  .where("status = 'active'")
  .orderBy('name', 'ASC')
  .limit(20)
  .offset(40)
  .build();

console.log(query);

带验证的 Builder

class EmailBuilder {
  private from = '';
  private to: string[] = [];
  private subject = '';
  private bodyText = '';
  private attachments: string[] = [];

  setFrom(from: string): this {
    this.from = from;
    return this;
  }

  addTo(to: string): this {
    this.to.push(to);
    return this;
  }

  setSubject(subject: string): this {
    this.subject = subject;
    return this;
  }

  setBody(body: string): this {
    this.bodyText = body;
    return this;
  }

  addAttachment(path: string): this {
    this.attachments.push(path);
    return this;
  }

  build(): Email {
    if (!this.from) throw new Error('From is required');
    if (this.to.length === 0) throw new Error('At least one recipient is required');
    if (!this.subject) throw new Error('Subject is required');

    return {
      from: this.from,
      to: [...this.to],
      subject: this.subject,
      body: this.bodyText,
      attachments: [...this.attachments],
    };
  }
}

interface Email {
  from: string;
  to: string[];
  subject: string;
  body: string;
  attachments: string[];
}

const email = new EmailBuilder()
  .setFrom('sender@example.com')
  .addTo('recipient1@example.com')
  .addTo('recipient2@example.com')
  .setSubject('Meeting Tomorrow')
  .setBody('Please confirm your attendance.')
  .addAttachment('agenda.pdf')
  .build();

build() 方法中的验证确保了对象在创建时就处于有效状态，将"运行时错误"提前到"构建时错误"。

常见误区

误区一：所有对象都用 Builder

只有参数较多（通常 4 个以上）且有多个可选参数时，Builder 才值得引入。简单对象直接用构造函数即可。

误区二：忽略不可变性

Builder 构建出的对象应该是不可变的。一旦 build() 完成，外部不应该能修改其内部状态。使用 Readonly 和对象展开来确保不可变性。

误区三：Builder 和 Fluent Interface 是同一回事

链式调用（Fluent Interface）是 Builder 模式常用的实现手段，但不是 Builder 的本质。Builder 的核心是"将复杂构建过程分步骤完成"。

小结

mindmap
  root((建造者模式))
    意图
      分步构建复杂对象
      同样的过程不同表示
    核心要素
      Builder 链式方法
      Director 封装固定流程
      build 验证与创建
    适用场景
      参数多且可选
      构建过程多步骤
      需要不同表示
    实际应用
      HTTP 请求构建
      SQL 查询构建
      邮件构建
  • Builder 模式通过链式调用分步构建复杂对象，解决了伸缩构造函数问题。
  • Director 封装常见的构建流程，提升复用性。
  • Builder 构建的对象应该是不可变的，build() 方法应包含验证逻辑。
  • 适用于参数多、可选参数多、构建过程复杂的场景。
