单例模式

核心概念

单例模式（Singleton Pattern）确保一个类只有一个实例，并提供全局访问点。它是最简单也是最具争议的设计模式之一——简单在于实现直观，争议在于它本质上是一种受控的全局变量，容易被滥用。

单例模式要解决的核心问题有两个：


    

  1. 唯一性：确保某个类在整个应用中只有一个实例
    2. 

  2. 可访问性：提供一种全局方式来获取该实例
    3. 





经典实现
饿汉式（Eager Initialization）
class EagerSingleton {
  private static readonly instance = new EagerSingleton();

  private constructor() {}

  static getInstance(): EagerSingleton {
    return EagerSingleton.instance;
  }

  log(message: string): void {
    console.log(`[EagerSingleton] ${message}`);
  }
}

const a = EagerSingleton.getInstance();
const b = EagerSingleton.getInstance();
console.log(a === b);
类加载时就创建实例。优点是实现简单且线程安全（在 TypeScript/JavaScript 的单线程环境中），缺点是即使从未使用也会占用资源。


懒汉式（Lazy Initialization）
class LazySingleton {
  private static instance: LazySingleton | null = null;

  private constructor() {}

  static getInstance(): LazySingleton {
    if (!LazySingleton.instance) {
      LazySingleton.instance = new LazySingleton();
    }
    return LazySingleton.instance;
  }

  log(message: string): void {
    console.log(`[LazySingleton] ${message}`);
  }
}
首次调用时才创建实例，节约资源。JavaScript 是单线程的，所以不用担心并发问题，但在多线程语言中需要加锁。




实际应用
配置管理器
interface AppConfig {
  apiBaseUrl: string;
  logLevel: 'debug' | 'info' | 'warn' | 'error';
  maxRetries: number;
  timeout: number;
}

class ConfigManager {
  private static instance: ConfigManager | null = null;
  private config: AppConfig;

  private constructor() {
    this.config = {
      apiBaseUrl: 'https://api.example.com',
      logLevel: 'info',
      maxRetries: 3,
      timeout: 5000,
    };
  }

  static getInstance(): ConfigManager {
    if (!ConfigManager.instance) {
      ConfigManager.instance = new ConfigManager();
    }
    return ConfigManager.instance;
  }

  get<K extends keyof AppConfig>(key: K): AppConfig[K] {
    return this.config[key];
  }

  set<K extends keyof AppConfig>(key: K, value: AppConfig[K]): void {
    this.config[key] = value;
  }

  getAll(): Readonly<AppConfig> {
    return { ...this.config };
  }
}

const config = ConfigManager.getInstance();
console.log(config.get('apiBaseUrl'));
config.set('logLevel', 'debug');
日志服务
type LogLevel = 'debug' | 'info' | 'warn' | 'error';

class Logger {
  private static instance: Logger | null = null;
  private level: LogLevel = 'info';
  private logs: string[] = [];

  private constructor() {}

  static getInstance(): Logger {
    if (!Logger.instance) {
      Logger.instance = new Logger();
    }
    return Logger.instance;
  }

  setLevel(level: LogLevel): void {
    this.level = level;
  }

  private shouldLog(level: LogLevel): boolean {
    const levels: LogLevel[] = ['debug', 'info', 'warn', 'error'];
    return levels.indexOf(level) >= levels.indexOf(this.level);
  }

  private write(level: LogLevel, message: string): void {
    if (!this.shouldLog(level)) return;
    const entry = `[${new Date().toISOString()}] [${level.toUpperCase()}] ${message}`;
    this.logs.push(entry);
    console.log(entry);
  }

  debug(message: string): void {
    this.write('debug', message);
  }
  info(message: string): void {
    this.write('info', message);
  }
  warn(message: string): void {
    this.write('warn', message);
  }
  error(message: string): void {
    this.write('error', message);
  }

  getHistory(): readonly string[] {
    return [...this.logs];
  }
}


现代替代方案
模块单例
在 TypeScript/JavaScript 的模块系统中，每个模块只会被执行一次，导出的对象天然是单例：


const config = {
  apiBaseUrl: 'https://api.example.com',
  logLevel: 'info' as const,
  maxRetries: 3,
};

function getConfig() {
  return config;
}

function setConfig(key: keyof typeof config, value: string | number) {
  (config as Record<string, unknown>)[key] = value;
}

export { getConfig, setConfig };
这种方式更简洁，且不需要 getInstance() 的仪式感。在现代 TypeScript 项目中，模块单例往往是比类单例更好的选择。


依赖注入容器
在大型项目中，与其使用全局单例，不如通过依赖注入容器来管理对象的生命周期：


class Container {
  private singletons = new Map<string, unknown>();
  private factories = new Map<string, () => unknown>();

  registerSingleton<T>(key: string, factory: () => T): void {
    this.factories.set(key, factory);
  }

  resolve<T>(key: string): T {
    if (this.singletons.has(key)) {
      return this.singletons.get(key) as T;
    }
    const factory = this.factories.get(key);
    if (!factory) throw new Error(`No registration for: ${key}`);
    const instance = factory();
    this.singletons.set(key, instance);
    return instance as T;
  }
}

const container = new Container();
container.registerSingleton('logger', () => Logger.getInstance());
container.registerSingleton('config', () => ConfigManager.getInstance());


常见误区
误区一：一切全局状态都用单例
单例是全局状态的一种形式。过多的单例会让系统中充满隐式依赖，导致代码难以测试和推理。只在对象确实需要全局唯一时才使用。


误区二：单例等于静态类
静态类的所有方法都是静态的，无法实现接口、无法被继承。单例是一个普通对象，可以实现接口、可以被 mock，在可测试性上优于静态类。


误区三：忽视单例对测试的影响
单例在测试间共享状态，容易导致测试之间相互影响。解决方案是为单例提供 reset 方法（仅在测试中使用），或者改用依赖注入。




小结
    

  • 单例模式确保类只有一个实例并提供全局访问点。
    • 

  • 在 TypeScript 中，模块单例是比类单例更简洁的选择。
    • 

  • 适用于配置管理器、日志服务等确实需要全局唯一的场景。
    • 

  • 过度使用单例会引入隐式全局依赖，降低可测试性。
    • 

  • 在大型项目中，考虑用依赖注入容器替代直接的单例访问。
