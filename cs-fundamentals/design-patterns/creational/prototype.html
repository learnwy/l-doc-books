原型模式

核心概念

原型模式（Prototype Pattern）通过复制已有对象来创建新对象，而不是通过类的构造函数。当对象的创建成本高昂（如涉及数据库查询、网络请求）或需要动态决定创建类型时，原型模式提供了一种高效的替代方案。

原型模式的核心思想：不问"你是什么类"再去创建，而是说"给我一个跟你一样的"。




浅拷贝与深拷贝
理解原型模式，首先要理解拷贝的两种方式：


interface Address {
  city: string;
  street: string;
}

interface Person {
  name: string;
  age: number;
  address: Address;
  hobbies: string[];
}

const original: Person = {
  name: 'Alice',
  age: 30,
  address: { city: 'Shanghai', street: 'Nanjing Road' },
  hobbies: ['reading', 'coding'],
};

const shallowCopy: Person = { ...original };

shallowCopy.name = 'Bob';
shallowCopy.address.city = 'Beijing';

console.log(original.name);
console.log(original.address.city);
浅拷贝中，address 对象被共享——修改副本的 address 也影响了原始对象。


深拷贝实现
function deepClone<T>(obj: T): T {
  return structuredClone(obj);
}

const deepCopy = deepClone(original);
deepCopy.address.city = 'Guangzhou';

console.log(original.address.city);
console.log(deepCopy.address.city);
现代 JavaScript 提供了 structuredClone API，可以方便地实现深拷贝。




原型接口实现
interface Cloneable<T> {
  clone(): T;
}

class GameCharacter implements Cloneable<GameCharacter> {
  constructor(
    public name: string,
    public health: number,
    public attack: number,
    public defense: number,
    public skills: string[],
    public equipment: Map<string, string>,
  ) {}

  clone(): GameCharacter {
    return new GameCharacter(
      this.name,
      this.health,
      this.attack,
      this.defense,
      [...this.skills],
      new Map(this.equipment),
    );
  }

  toString(): string {
    return `${this.name} [HP:${this.health} ATK:${this.attack} DEF:${this.defense}]`;
  }
}

const warrior = new GameCharacter(
  'Warrior',
  1000,
  150,
  80,
  ['Slash', 'Shield Bash'],
  new Map([
    ['weapon', 'Sword'],
    ['armor', 'Plate'],
  ]),
);

const eliteWarrior = warrior.clone();
eliteWarrior.name = 'Elite Warrior';
eliteWarrior.health = 2000;
eliteWarrior.attack = 300;
eliteWarrior.skills.push('Whirlwind');

console.log(warrior.toString());
console.log(eliteWarrior.toString());


原型注册表
原型模式经常与注册表（Registry）配合使用，存储一组预配置好的原型对象：


class PrototypeRegistry<T extends Cloneable<T>> {
  private prototypes = new Map<string, T>();

  register(key: string, prototype: T): void {
    this.prototypes.set(key, prototype);
  }

  create(key: string): T {
    const prototype = this.prototypes.get(key);
    if (!prototype) throw new Error(`Prototype not found: ${key}`);
    return prototype.clone();
  }

  list(): string[] {
    return Array.from(this.prototypes.keys());
  }
}

const characterRegistry = new PrototypeRegistry<GameCharacter>();

characterRegistry.register(
  'warrior',
  new GameCharacter('Warrior', 1000, 150, 80, ['Slash'], new Map([['weapon', 'Sword']])),
);
characterRegistry.register(
  'mage',
  new GameCharacter('Mage', 600, 200, 40, ['Fireball'], new Map([['weapon', 'Staff']])),
);
characterRegistry.register(
  'archer',
  new GameCharacter('Archer', 700, 180, 50, ['Arrow Shot'], new Map([['weapon', 'Bow']])),
);

const newWarrior = characterRegistry.create('warrior');
newWarrior.name = 'Player Warrior';

const newMage = characterRegistry.create('mage');
newMage.name = 'Player Mage';

console.log(newWarrior.toString());
console.log(newMage.toString());


实际应用：文档模板系统
interface DocumentTemplate extends Cloneable<DocumentTemplate> {
  title: string;
  sections: Section[];
  metadata: Record<string, string>;
  render(): string;
}

interface Section {
  heading: string;
  content: string;
}

class Report implements DocumentTemplate {
  constructor(
    public title: string,
    public sections: Section[],
    public metadata: Record<string, string>,
  ) {}

  clone(): Report {
    return new Report(
      this.title,
      this.sections.map((s) => ({ ...s })),
      { ...this.metadata },
    );
  }

  render(): string {
    const header = `# ${this.title}\n`;
    const meta = Object.entries(this.metadata)
      .map(([k, v]) => `> ${k}: ${v}`)
      .join('\n');
    const body = this.sections.map((s) => `## ${s.heading}\n${s.content}`).join('\n\n');
    return `${header}${meta}\n\n${body}`;
  }
}

const weeklyReportTemplate = new Report(
  'Weekly Report',
  [
    { heading: 'Summary', content: '' },
    { heading: 'Achievements', content: '' },
    { heading: 'Challenges', content: '' },
    { heading: 'Next Week Plan', content: '' },
  ],
  { type: 'weekly', department: '', author: '' },
);

const templateRegistry = new PrototypeRegistry<DocumentTemplate>();
templateRegistry.register('weekly', weeklyReportTemplate);

const myReport = templateRegistry.create('weekly');
myReport.title = 'Week 13 Report - Engineering Team';
myReport.metadata.department = 'Engineering';
myReport.metadata.author = 'Alice';
myReport.sections[0].content = 'Completed the design patterns hub.';

console.log(myReport.render());

常见误区
误区一：忽略深拷贝需求
浅拷贝是原型模式中最常见的 bug 来源。如果原型对象包含引用类型字段，clone() 方法必须处理深拷贝，否则原型和克隆对象会共享内部状态。


误区二：所有对象都需要 clone
原型模式适合创建成本高或需要基于模板生成变体的场景。普通对象直接 new 通常更简单直观。


误区三：克隆后忘记定制
克隆的意义在于快速获得一个基础版本，然后根据需要进行定制。如果每次克隆后都要修改大量属性，也许直接用 Builder 更合适。




小结
    

  • 原型模式通过复制已有对象来创建新对象，避免重复的初始化开销。
    • 

  • 实现 clone() 方法时必须注意深拷贝，防止共享引用导致的 bug。
    • 

  • 原型注册表是常见的搭配模式，存储一组预配置好的原型对象。
    • 

  • 适用于创建成本高、需要基于模板生成变体、运行时动态决定类型的场景。
