外观模式

核心概念

外观模式（Facade Pattern）为一个复杂的子系统提供一个统一的、简化的高层接口。客户端不需要了解子系统的内部细节，只需通过外观对象就能完成常见操作。外观模式不是封装子系统——子系统仍然可以被直接使用——它只是提供了一条捷径。



基础实现
class VideoDecoder {
  decode(file: string): string {
    return `decoded_${file}`;
  }
}

class AudioDecoder {
  decode(file: string): string {
    return `audio_${file}`;
  }
}

class SubtitleLoader {
  load(file: string): string[] {
    return [`subtitle_line_1`, `subtitle_line_2`];
  }
}

class VideoRenderer {
  render(video: string, audio: string, subtitles: string[]): string {
    return `Rendering: ${video} + ${audio} + ${subtitles.length} subtitle lines`;
  }
}

class VideoPlayerFacade {
  private videoDecoder = new VideoDecoder();
  private audioDecoder = new AudioDecoder();
  private subtitleLoader = new SubtitleLoader();
  private renderer = new VideoRenderer();

  play(filename: string): string {
    const video = this.videoDecoder.decode(filename);
    const audio = this.audioDecoder.decode(filename);
    const subtitles = this.subtitleLoader.load(filename);
    return this.renderer.render(video, audio, subtitles);
  }

  playWithoutSubtitles(filename: string): string {
    const video = this.videoDecoder.decode(filename);
    const audio = this.audioDecoder.decode(filename);
    return this.renderer.render(video, audio, []);
  }
}

const player = new VideoPlayerFacade();
console.log(player.play('movie.mp4'));
客户端只需调用 player.play()，无需了解视频解码、音频解码、字幕加载、渲染等子系统的交互细节。




实际应用：电商订单系统
class InventoryService {
  check(productId: string, quantity: number): boolean {
    console.log(`Checking inventory for ${productId}: ${quantity}`);
    return true;
  }

  reserve(productId: string, quantity: number): string {
    return `reservation_${productId}_${Date.now()}`;
  }
}

class PaymentService {
  process(amount: number, method: string): { transactionId: string; success: boolean } {
    console.log(`Processing payment: ¥${amount} via ${method}`);
    return { transactionId: `pay_${Date.now()}`, success: true };
  }
}

class ShippingService {
  calculate(address: string, weight: number): number {
    return weight * 5 + 10;
  }

  createShipment(orderId: string, address: string): string {
    return `shipment_${orderId}`;
  }
}

class NotificationService {
  sendOrderConfirmation(email: string, orderId: string): void {
    console.log(`Sending confirmation for ${orderId} to ${email}`);
  }

  sendShippingNotification(email: string, trackingId: string): void {
    console.log(`Sending shipping notification: ${trackingId} to ${email}`);
  }
}

interface OrderRequest {
  productId: string;
  quantity: number;
  amount: number;
  paymentMethod: string;
  shippingAddress: string;
  customerEmail: string;
}

interface OrderResult {
  orderId: string;
  transactionId: string;
  reservationId: string;
  shipmentId: string;
  shippingCost: number;
}

class OrderFacade {
  private inventory = new InventoryService();
  private payment = new PaymentService();
  private shipping = new ShippingService();
  private notification = new NotificationService();

  placeOrder(request: OrderRequest): OrderResult {
    if (!this.inventory.check(request.productId, request.quantity)) {
      throw new Error('Product out of stock');
    }

    const reservationId = this.inventory.reserve(request.productId, request.quantity);

    const shippingCost = this.shipping.calculate(request.shippingAddress, request.quantity * 0.5);
    const totalAmount = request.amount + shippingCost;

    const paymentResult = this.payment.process(totalAmount, request.paymentMethod);
    if (!paymentResult.success) {
      throw new Error('Payment failed');
    }

    const orderId = `order_${Date.now()}`;
    const shipmentId = this.shipping.createShipment(orderId, request.shippingAddress);

    this.notification.sendOrderConfirmation(request.customerEmail, orderId);
    this.notification.sendShippingNotification(request.customerEmail, shipmentId);

    return {
      orderId,
      transactionId: paymentResult.transactionId,
      reservationId,
      shipmentId,
      shippingCost,
    };
  }
}

const orderFacade = new OrderFacade();
const result = orderFacade.placeOrder({
  productId: 'PROD-001',
  quantity: 2,
  amount: 199,
  paymentMethod: 'wechat',
  shippingAddress: 'Shanghai, China',
  customerEmail: 'customer@example.com',
});
console.log(result);


外观模式的层次
外观可以嵌套使用。PaymentService 本身可能也是一个外观，内部封装了多个支付网关的交互细节。




外观 vs 相关模式




模式
关系





Adapter
转换已有接口。Facade 定义新的简化接口




Mediator
协调同级对象的交互。Facade 简化子系统对外的接口




Singleton
外观对象通常只需要一个实例，可以结合单例







常见误区
误区一：外观成为"上帝对象"
外观应该只包含编排逻辑，不应该包含业务逻辑。如果外观变得越来越庞大，说明职责需要进一步拆分。


误区二：外观禁止直接使用子系统
外观是一种便利，不是一种限制。高级用户在需要时仍然可以直接使用子系统。外观不应该隐藏子系统。


误区三：每个子系统都需要外观
只有当子系统的使用方式确实复杂，且有常见的使用模式可以封装时，才值得引入外观。简单的子系统直接使用即可。




小结
    

  • 外观模式为复杂子系统提供简化的高层接口。
    • 

  • 外观只包含编排逻辑，不包含业务逻辑。
    • 

  • 外观不限制直接使用子系统——它是便利，不是限制。
    • 

  • 常见于多个服务协同的业务流程编排场景。
