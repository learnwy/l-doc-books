装饰器模式

核心概念

装饰器模式（Decorator Pattern）动态地为对象添加额外的职责。与继承相比，装饰器提供了一种更灵活的方式来扩展功能——你可以在运行时自由组合多个装饰器，而不会产生类爆炸。

装饰器模式的精髓在于"包装"：每个装饰器持有一个被装饰对象的引用，在调用被装饰对象方法的前后添加自己的逻辑。




基础实现
interface DataSource {
  write(data: string): void;
  read(): string;
}

class FileDataSource implements DataSource {
  private content = '';

  write(data: string): void {
    this.content = data;
  }

  read(): string {
    return this.content;
  }
}

abstract class DataSourceDecorator implements DataSource {
  constructor(protected wrapped: DataSource) {}

  write(data: string): void {
    this.wrapped.write(data);
  }

  read(): string {
    return this.wrapped.read();
  }
}

class EncryptionDecorator extends DataSourceDecorator {
  private encrypt(data: string): string {
    return Buffer.from(data).toString('base64');
  }

  private decrypt(data: string): string {
    return Buffer.from(data, 'base64').toString('utf-8');
  }

  write(data: string): void {
    super.write(this.encrypt(data));
  }

  read(): string {
    return this.decrypt(super.read());
  }
}

class CompressionDecorator extends DataSourceDecorator {
  write(data: string): void {
    const compressed = `[compressed:${data.length}]${data}`;
    super.write(compressed);
  }

  read(): string {
    const raw = super.read();
    const match = raw.match(/^\[compressed:\d+\](.+)$/);
    return match ? match[1] : raw;
  }
}

class LoggingDecorator extends DataSourceDecorator {
  write(data: string): void {
    console.log(`[LOG] Writing ${data.length} chars`);
    super.write(data);
    console.log(`[LOG] Write complete`);
  }

  read(): string {
    console.log(`[LOG] Reading data`);
    const result = super.read();
    console.log(`[LOG] Read ${result.length} chars`);
    return result;
  }
}

let source: DataSource = new FileDataSource();
source = new CompressionDecorator(source);
source = new EncryptionDecorator(source);
source = new LoggingDecorator(source);

source.write('Hello, Design Patterns!');
const result = source.read();
console.log(result);
装饰器像洋葱一样层层包裹：写入时从外向内（Logging → Encryption → Compression → File），读取时从内向外。




实际应用：HTTP 中间件
interface HttpHandler {
  handle(request: HttpRequest): Promise<HttpResponse>;
}

interface HttpRequest {
  method: string;
  url: string;
  headers: Record<string, string>;
  body?: string;
}

interface HttpResponse {
  status: number;
  headers: Record<string, string>;
  body: string;
}

class ApiHandler implements HttpHandler {
  async handle(request: HttpRequest): Promise<HttpResponse> {
    return {
      status: 200,
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ message: 'OK', url: request.url }),
    };
  }
}

class AuthMiddleware implements HttpHandler {
  constructor(private next: HttpHandler) {}

  async handle(request: HttpRequest): Promise<HttpResponse> {
    if (!request.headers['authorization']) {
      return { status: 401, headers: {}, body: 'Unauthorized' };
    }
    return this.next.handle(request);
  }
}

class CorsMiddleware implements HttpHandler {
  constructor(private next: HttpHandler) {}

  async handle(request: HttpRequest): Promise<HttpResponse> {
    const response = await this.next.handle(request);
    response.headers['Access-Control-Allow-Origin'] = '*';
    response.headers['Access-Control-Allow-Methods'] = 'GET, POST, PUT, DELETE';
    return response;
  }
}

class TimingMiddleware implements HttpHandler {
  constructor(private next: HttpHandler) {}

  async handle(request: HttpRequest): Promise<HttpResponse> {
    const start = performance.now();
    const response = await this.next.handle(request);
    const duration = performance.now() - start;
    response.headers['X-Response-Time'] = `${duration.toFixed(2)}ms`;
    return response;
  }
}

let handler: HttpHandler = new ApiHandler();
handler = new AuthMiddleware(handler);
handler = new CorsMiddleware(handler);
handler = new TimingMiddleware(handler);

handler
  .handle({
    method: 'GET',
    url: '/api/users',
    headers: { authorization: 'Bearer token123' },
  })
  .then(console.log);
这就是 Express、Koa 等框架中间件的核心思想——每个中间件是一个装饰器，可以在请求处理的前后添加逻辑。




函数装饰器
TypeScript 中，函数本身也可以被装饰：


type AsyncFn<T> = (...args: unknown[]) => Promise<T>;

function withRetry<T>(fn: AsyncFn<T>, maxRetries: number): AsyncFn<T> {
  return async (...args: unknown[]) => {
    let lastError: Error | undefined;
    for (let i = 0; i <= maxRetries; i++) {
      try {
        return await fn(...args);
      } catch (err) {
        lastError = err as Error;
        if (i < maxRetries) {
          console.log(`Retry ${i + 1}/${maxRetries}...`);
        }
      }
    }
    throw lastError;
  };
}

function withCache<T>(fn: AsyncFn<T>, ttlMs: number): AsyncFn<T> {
  const cache = new Map<string, { value: T; expiresAt: number }>();

  return async (...args: unknown[]) => {
    const key = JSON.stringify(args);
    const cached = cache.get(key);
    if (cached && cached.expiresAt > Date.now()) {
      return cached.value;
    }
    const value = await fn(...args);
    cache.set(key, { value, expiresAt: Date.now() + ttlMs });
    return value;
  };
}

async function fetchUser(id: string): Promise<{ id: string; name: string }> {
  console.log(`Fetching user ${id}...`);
  return { id, name: 'Alice' };
}

const resilientFetch = withRetry(withCache(fetchUser as AsyncFn<{ id: string; name: string }>, 60000), 3);


常见误区
误区一：装饰器层数过多
过多的装饰器层会让调用栈变深，调试时难以追踪。如果需要超过 3-4 层装饰器，考虑是否有更好的设计方案。


误区二：混淆装饰器与继承
装饰器用组合实现功能扩展，可以在运行时动态添加；继承在编译时确定，且无法自由组合。当需要灵活组合多种功能时，装饰器优于继承。


误区三：装饰器改变接口
装饰器应该与被装饰对象实现相同的接口。如果装饰器添加了新方法或改变了方法签名，它就不是装饰器，而更像适配器了。




小结
    

  • 装饰器模式通过包装对象来动态添加功能，比继承更灵活。
    • 

  • 装饰器必须与被装饰对象实现相同的接口。
    • 

  • HTTP 中间件是装饰器模式最广泛的实际应用。
    • 

  • 在 TypeScript 中，函数装饰器（高阶函数）往往比类装饰器更简洁。
