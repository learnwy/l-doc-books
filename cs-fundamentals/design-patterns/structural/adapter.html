适配器模式

核心概念

适配器模式（Adapter Pattern）将一个类的接口转换成客户端期望的另一个接口。它让原本因接口不兼容而无法协同工作的类能够一起工作。适配器就像现实生活中的电源转换器——你的设备是美标插头，但墙上的插座是国标，适配器让两者能够配合。



对象适配器
对象适配器通过组合（持有被适配对象的引用）来实现适配：


interface PaymentProcessor {
  charge(amount: number, currency: string): Promise<PaymentResult>;
}

interface PaymentResult {
  success: boolean;
  transactionId: string;
  message: string;
}

class StripeAPI {
  createCharge(amountInCents: number, cur: string): Promise<{ id: string; status: string }> {
    return Promise.resolve({
      id: `stripe_${Date.now()}`,
      status: 'succeeded',
    });
  }
}

class StripeAdapter implements PaymentProcessor {
  constructor(private stripe: StripeAPI) {}

  async charge(amount: number, currency: string): Promise<PaymentResult> {
    const amountInCents = Math.round(amount * 100);
    const result = await this.stripe.createCharge(amountInCents, currency);
    return {
      success: result.status === 'succeeded',
      transactionId: result.id,
      message: result.status === 'succeeded' ? 'Payment successful' : 'Payment failed',
    };
  }
}

class PayPalAPI {
  sendPayment(value: string, currencyCode: string): Promise<{ orderId: string; state: string }> {
    return Promise.resolve({
      orderId: `paypal_${Date.now()}`,
      state: 'approved',
    });
  }
}

class PayPalAdapter implements PaymentProcessor {
  constructor(private paypal: PayPalAPI) {}

  async charge(amount: number, currency: string): Promise<PaymentResult> {
    const result = await this.paypal.sendPayment(amount.toFixed(2), currency.toUpperCase());
    return {
      success: result.state === 'approved',
      transactionId: result.orderId,
      message: result.state === 'approved' ? 'Payment successful' : 'Payment failed',
    };
  }
}

async function processOrder(processor: PaymentProcessor, amount: number): Promise<void> {
  const result = await processor.charge(amount, 'USD');
  console.log(`Transaction ${result.transactionId}: ${result.message}`);
}

const stripeProcessor = new StripeAdapter(new StripeAPI());
const paypalProcessor = new PayPalAdapter(new PayPalAPI());

processOrder(stripeProcessor, 49.99);
processOrder(paypalProcessor, 29.99);
processOrder 函数只依赖 PaymentProcessor 接口，完全不知道底层是 Stripe 还是 PayPal。




函数适配器
在 TypeScript 中，适配器不一定需要类——函数也可以做适配：


type OldLogger = (level: string, msg: string, timestamp: number) => void;
type NewLogger = (entry: { level: string; message: string; time: Date }) => void;

function adaptLogger(oldLogger: OldLogger): NewLogger {
  return (entry) => {
    oldLogger(entry.level, entry.message, entry.time.getTime());
  };
}

const legacyLog: OldLogger = (level, msg, ts) => {
  console.log(`[${level}] ${new Date(ts).toISOString()} - ${msg}`);
};

const modernLog = adaptLogger(legacyLog);

modernLog({
  level: 'INFO',
  message: 'User logged in',
  time: new Date(),
});


实际应用：数据格式适配
interface InternalUser {
  id: string;
  fullName: string;
  email: string;
  role: 'admin' | 'user' | 'guest';
  createdAt: Date;
}

interface ExternalAPIUser {
  user_id: number;
  first_name: string;
  last_name: string;
  email_address: string;
  permission_level: number;
  registration_date: string;
}

class ExternalUserAdapter {
  private roleMap = new Map<number, InternalUser['role']>([
    [0, 'guest'],
    [1, 'user'],
    [2, 'admin'],
  ]);

  toInternal(external: ExternalAPIUser): InternalUser {
    return {
      id: String(external.user_id),
      fullName: `${external.first_name} ${external.last_name}`,
      email: external.email_address,
      role: this.roleMap.get(external.permission_level) ?? 'guest',
      createdAt: new Date(external.registration_date),
    };
  }

  toExternal(internal: InternalUser): ExternalAPIUser {
    const [firstName = '', lastName = ''] = internal.fullName.split(' ');
    const reverseRoleMap = new Map<string, number>([
      ['guest', 0],
      ['user', 1],
      ['admin', 2],
    ]);
    return {
      user_id: Number(internal.id),
      first_name: firstName,
      last_name: lastName,
      email_address: internal.email,
      permission_level: reverseRoleMap.get(internal.role) ?? 0,
      registration_date: internal.createdAt.toISOString(),
    };
  }
}

const adapter = new ExternalUserAdapter();

const externalUser: ExternalAPIUser = {
  user_id: 42,
  first_name: 'Alice',
  last_name: 'Wang',
  email_address: 'alice@example.com',
  permission_level: 2,
  registration_date: '2025-01-15T08:00:00.000Z',
};

const internalUser = adapter.toInternal(externalUser);
console.log(internalUser);
这种双向适配器在前后端数据交互、微服务间通信中极为常见。

常见误区
误区一：为相似接口创建适配器
如果两个接口只有细微差别（如方法名不同但参数和语义一致），一个简单的包装函数就够了，不需要正式的适配器类。


误区二：适配器中添加业务逻辑
适配器的职责是接口转换，不应该包含业务逻辑。如果你发现适配器中有大量的计算或条件判断，说明职责划分有问题。


误区三：不考虑双向适配
只做单向适配可能在后续需求中带来问题。在设计适配器时，评估是否需要双向转换。




小结
    

  • 适配器模式将不兼容的接口转换为客户端期望的接口。
    • 

  • 在 TypeScript 中，函数适配器比类适配器更简洁轻量。
    • 

  • 适配器的职责严格限于接口转换，不应包含业务逻辑。
    • 

  • 常见于第三方库集成、遗留系统对接、数据格式转换等场景。
