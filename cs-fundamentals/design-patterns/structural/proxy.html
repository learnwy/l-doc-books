代理模式

核心概念

代理模式（Proxy Pattern）为另一个对象提供一个替身或占位符来控制对它的访问。代理对象与目标对象实现相同的接口，客户端无法区分两者——所有操作都通过代理转发，代理可以在转发前后添加额外的行为。

代理模式有多种变体，每种解决不同的问题：

虚拟代理（延迟加载）
interface Image {
  display(): string;
  getSize(): number;
}

class HighResImage implements Image {
  private data: Uint8Array;

  constructor(private filename: string) {
    this.data = new Uint8Array(1024 * 1024 * 10);
    console.log(`Loading high-res image: ${filename} (${this.data.length} bytes)`);
  }

  display(): string {
    return `Displaying ${this.filename}`;
  }

  getSize(): number {
    return this.data.length;
  }
}

class LazyImageProxy implements Image {
  private realImage: HighResImage | null = null;

  constructor(private filename: string) {}

  private loadImage(): HighResImage {
    if (!this.realImage) {
      this.realImage = new HighResImage(this.filename);
    }
    return this.realImage;
  }

  display(): string {
    return this.loadImage().display();
  }

  getSize(): number {
    return this.loadImage().getSize();
  }
}

const images: Image[] = [
  new LazyImageProxy('photo1.jpg'),
  new LazyImageProxy('photo2.jpg'),
  new LazyImageProxy('photo3.jpg'),
];

console.log(images[0].display());
只有 photo1.jpg 被真正加载了，其他两张图片的 HighResImage 实例从未创建。




缓存代理
interface WeatherService {
  getWeather(city: string): Promise<WeatherData>;
}

interface WeatherData {
  city: string;
  temperature: number;
  humidity: number;
  description: string;
}

class RealWeatherService implements WeatherService {
  async getWeather(city: string): Promise<WeatherData> {
    console.log(`Calling weather API for ${city}...`);
    await new Promise((resolve) => setTimeout(resolve, 100));
    return {
      city,
      temperature: 20 + Math.random() * 15,
      humidity: 40 + Math.random() * 40,
      description: 'Sunny',
    };
  }
}

class CachingWeatherProxy implements WeatherService {
  private cache = new Map<string, { data: WeatherData; expiresAt: number }>();

  constructor(
    private service: RealWeatherService,
    private ttlMs: number = 60000,
  ) {}

  async getWeather(city: string): Promise<WeatherData> {
    const cached = this.cache.get(city);
    if (cached && cached.expiresAt > Date.now()) {
      console.log(`Cache hit for ${city}`);
      return cached.data;
    }

    console.log(`Cache miss for ${city}`);
    const data = await this.service.getWeather(city);
    this.cache.set(city, { data, expiresAt: Date.now() + this.ttlMs });
    return data;
  }

  clearCache(): void {
    this.cache.clear();
  }
}

const weatherService = new CachingWeatherProxy(new RealWeatherService(), 30000);

async function demo() {
  await weatherService.getWeather('Shanghai');
  await weatherService.getWeather('Shanghai');
  await weatherService.getWeather('Beijing');
}

demo();


JavaScript Proxy 对象
JavaScript 原生提供了 Proxy 对象，可以拦截几乎所有对象操作：


interface UserRecord {
  name: string;
  email: string;
  role: string;
  [key: string]: string;
}

function createValidatedProxy<T extends Record<string, unknown>>(
  target: T,
  validators: Partial<Record<keyof T, (value: unknown) => boolean>>,
): T {
  return new Proxy(target, {
    set(obj, prop: string, value: unknown) {
      const validator = validators[prop as keyof T];
      if (validator && !validator(value)) {
        throw new Error(`Invalid value for ${prop}: ${value}`);
      }
      (obj as Record<string, unknown>)[prop] = value;
      return true;
    },
    get(obj, prop: string) {
      const value = (obj as Record<string, unknown>)[prop];
      if (value === undefined) {
        console.warn(`Accessing undefined property: ${prop}`);
      }
      return value;
    },
  });
}

const user = createValidatedProxy<UserRecord>(
  { name: 'Alice', email: 'alice@example.com', role: 'admin' },
  {
    email: (v) => typeof v === 'string' && /^[^@]+@[^@]+$/.test(v),
    role: (v) => ['admin', 'user', 'guest'].includes(v as string),
  },
);

user.name = 'Bob';
user.email = 'bob@example.com';


保护代理
interface Document {
  read(): string;
  write(content: string): void;
  delete(): void;
}

class SecureDocument implements Document {
  constructor(
    private content: string,
    private title: string,
  ) {}

  read(): string {
    return `[${this.title}] ${this.content}`;
  }

  write(content: string): void {
    this.content = content;
  }

  delete(): void {
    this.content = '';
    this.title = '[deleted]';
  }
}

type Permission = 'read' | 'write' | 'delete';

class AccessControlProxy implements Document {
  constructor(
    private document: Document,
    private userPermissions: Set<Permission>,
  ) {}

  read(): string {
    this.checkPermission('read');
    return this.document.read();
  }

  write(content: string): void {
    this.checkPermission('write');
    this.document.write(content);
  }

  delete(): void {
    this.checkPermission('delete');
    this.document.delete();
  }

  private checkPermission(required: Permission): void {
    if (!this.userPermissions.has(required)) {
      throw new Error(`Access denied: missing '${required}' permission`);
    }
  }
}

const doc = new SecureDocument('Confidential data', 'Secret Report');
const readOnlyProxy = new AccessControlProxy(doc, new Set(['read']));

console.log(readOnlyProxy.read());

try {
  readOnlyProxy.write('hacked!');
} catch (e) {
  console.error((e as Error).message);
}


代理 vs 装饰器 vs 适配器
三者的结构非常相似（都是"包装另一个对象"），区别在于意图：


    

  • Proxy：控制对目标对象的访问（延迟加载、权限检查、缓存）
    • 

  • Decorator：动态添加新功能（日志、重试、压缩）
    • 

  • Adapter：转换接口使不兼容的类能协同工作
    • 





常见误区
误区一：代理应该对客户端完全透明
虽然理想状态下代理对客户端透明，但在实践中，代理可能抛出额外的异常（如权限不足、缓存失效）。客户端需要了解可能的异常情况。


误区二：过度使用 JavaScript Proxy
Proxy 对象虽然强大，但性能开销不容忽视。在性能敏感的代码路径中，避免使用 Proxy，改用显式的代理类。


误区三：缓存代理忽略失效策略
缓存代理必须有明确的失效策略（TTL、LRU 等）。永不失效的缓存会导致数据陈旧，内存持续增长。




小结
    

  • 代理模式在不改变接口的前提下控制对目标对象的访问。
    • 

  • 常见变体包括虚拟代理、缓存代理、保护代理、日志代理。
    • 

  • JavaScript 的 Proxy 对象是实现代理模式的强大工具。
    • 

  • 与装饰器的区别在于意图：代理控制访问，装饰器增强功能。
    •
