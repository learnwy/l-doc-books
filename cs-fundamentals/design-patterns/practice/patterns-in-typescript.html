TypeScript 中的模式实践

核心概念

TypeScript 的类型系统为设计模式带来了独特的优势。泛型、联合类型、映射类型、装饰器语法等特性让很多经典模式有了更类型安全、更简洁的实现方式。本文探讨如何充分利用 TypeScript 的语言特性来优化设计模式的实现。



泛型增强的模式
类型安全的事件系统
type EventMap = Record<string, unknown>;

class TypedEventEmitter<Events extends EventMap> {
  private handlers = new Map<keyof Events, Set<(data: unknown) => void>>();

  on<K extends keyof Events>(event: K, handler: (data: Events[K]) => void): () => void {
    if (!this.handlers.has(event)) {
      this.handlers.set(event, new Set());
    }
    this.handlers.get(event)!.add(handler as (data: unknown) => void);
    return () => this.handlers.get(event)?.delete(handler as (data: unknown) => void);
  }

  emit<K extends keyof Events>(event: K, data: Events[K]): void {
    this.handlers.get(event)?.forEach((handler) => handler(data));
  }
}

interface AppEvents {
  'user:login': { userId: string; timestamp: number };
  'user:logout': { userId: string };
  'cart:update': { items: string[]; total: number };
  error: { code: number; message: string };
}

const emitter = new TypedEventEmitter<AppEvents>();

emitter.on('user:login', (data) => {
  console.log(`User ${data.userId} logged in at ${data.timestamp}`);
});

emitter.on('cart:update', (data) => {
  console.log(`Cart: ${data.items.length} items, total: ¥${data.total}`);
});

emitter.emit('user:login', { userId: 'u1', timestamp: Date.now() });
emitter.emit('cart:update', { items: ['book'], total: 99 });
泛型 Events 确保事件名称和数据类型严格对应——拼错事件名或传错数据类型会在编译时报错。


泛型 Builder
class TypedBuilder<T extends Record<string, unknown>> {
  private data: Partial<T> = {};

  set<K extends keyof T>(key: K, value: T[K]): this {
    this.data[key] = value;
    return this;
  }

  build(defaults: T): T {
    return { ...defaults, ...this.data };
  }
}

interface ServerConfig {
  host: string;
  port: number;
  debug: boolean;
  maxConnections: number;
}

const config = new TypedBuilder<ServerConfig>()
  .set('host', 'localhost')
  .set('port', 8080)
  .set('debug', true)
  .build({ host: '0.0.0.0', port: 3000, debug: false, maxConnections: 100 });

console.log(config);


联合类型实现状态模式
TypeScript 的联合类型和类型收窄（narrowing）提供了状态模式的另一种实现：


type ConnectionState =
  | { status: 'disconnected' }
  | { status: 'connecting'; attempt: number }
  | { status: 'connected'; sessionId: string }
  | { status: 'error'; error: string; retryAfter: number };

function handleConnection(state: ConnectionState): string {
  switch (state.status) {
    case 'disconnected':
      return 'Click to connect';
    case 'connecting':
      return `Connecting... (attempt ${state.attempt})`;
    case 'connected':
      return `Connected: ${state.sessionId}`;
    case 'error':
      return `Error: ${state.error}. Retry in ${state.retryAfter}s`;
  }
}

function transition(state: ConnectionState, action: string): ConnectionState {
  switch (state.status) {
    case 'disconnected':
      if (action === 'connect') return { status: 'connecting', attempt: 1 };
      return state;
    case 'connecting':
      if (action === 'success') return { status: 'connected', sessionId: `sess_${Date.now()}` };
      if (action === 'failure') return { status: 'error', error: 'Timeout', retryAfter: 5 };
      return state;
    case 'connected':
      if (action === 'disconnect') return { status: 'disconnected' };
      return state;
    case 'error':
      if (action === 'retry') return { status: 'connecting', attempt: 1 };
      return state;
  }
}

let conn: ConnectionState = { status: 'disconnected' };
console.log(handleConnection(conn));

conn = transition(conn, 'connect');
console.log(handleConnection(conn));

conn = transition(conn, 'success');
console.log(handleConnection(conn));
编译器确保每个状态分支都被处理，且每个分支中只能访问该状态对应的属性。




映射类型实现代理
type Promisify<T> = {
  [K in keyof T]: T[K] extends (...args: infer A) => infer R ? (...args: A) => Promise<R> : T[K];
};

interface SyncService {
  getData(id: string): string;
  setData(id: string, value: string): void;
  deleteData(id: string): boolean;
}

function createAsyncProxy<T extends object>(target: T): Promisify<T> {
  return new Proxy(target, {
    get(obj, prop) {
      const value = (obj as Record<string | symbol, unknown>)[prop];
      if (typeof value === 'function') {
        return async (...args: unknown[]) => {
          return (value as Function).apply(obj, args);
        };
      }
      return value;
    },
  }) as Promisify<T>;
}
映射类型 Promisify<T> 自动将所有方法的返回值包装为 Promise，这在 TypeScript 中实现代理模式时极为有用。




模板字面量类型
type HttpMethod = 'GET' | 'POST' | 'PUT' | 'DELETE';
type ApiPath = '/users' | '/orders' | '/products';
type ApiRoute = `${HttpMethod} ${ApiPath}`;

type RouteHandler = (params: Record<string, string>) => unknown;

class TypedRouter {
  private routes = new Map<string, RouteHandler>();

  register(route: ApiRoute, handler: RouteHandler): void {
    this.routes.set(route, handler);
  }

  handle(route: ApiRoute, params: Record<string, string>): unknown {
    const handler = this.routes.get(route);
    if (!handler) throw new Error(`No handler for: ${route}`);
    return handler(params);
  }
}

const router = new TypedRouter();

router.register('GET /users', (params) => ({ users: [] }));
router.register('POST /orders', (params) => ({ orderId: 'new' }));

console.log(router.handle('GET /users', {}));


装饰器语法
TypeScript 5.0+ 的装饰器语法与装饰器模式天然契合：


function logged<T extends (...args: unknown[]) => unknown>(originalMethod: T, context: ClassMethodDecoratorContext): T {
  const methodName = String(context.name);

  function replacementMethod(this: unknown, ...args: unknown[]): unknown {
    console.log(`[${methodName}] called with:`, args);
    const result = originalMethod.call(this, ...args);
    console.log(`[${methodName}] returned:`, result);
    return result;
  }

  return replacementMethod as unknown as T;
}

function cached<T extends (...args: unknown[]) => unknown>(
  originalMethod: T,
  _context: ClassMethodDecoratorContext,
): T {
  const cache = new Map<string, unknown>();

  function replacementMethod(this: unknown, ...args: unknown[]): unknown {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = originalMethod.call(this, ...args);
    cache.set(key, result);
    return result;
  }

  return replacementMethod as unknown as T;
}

class MathService {
  @logged
  @cached
  fibonacci(n: number): number {
    if (n <= 1) return n;
    return this.fibonacci(n - 1) + this.fibonacci(n - 2);
  }
}


模块单例
TypeScript 的模块系统天然支持单例——模块只执行一次：


interface AppConfiguration {
  apiUrl: string;
  debug: boolean;
  version: string;
}

const defaultConfig: AppConfiguration = {
  apiUrl: 'https://api.example.com',
  debug: false,
  version: '1.0.0',
};

let currentConfig = { ...defaultConfig };

export function getConfig(): Readonly<AppConfiguration> {
  return currentConfig;
}

export function updateConfig(partial: Partial<AppConfiguration>): void {
  currentConfig = { ...currentConfig, ...partial };
}

export function resetConfig(): void {
  currentConfig = { ...defaultConfig };
}
无需 getInstance()，import 本身就保证了单例语义。

常见误区
误区一：TypeScript 项目必须用类
TypeScript 完全支持函数式风格。很多模式用函数和类型就能优雅实现，不必强行使用类。


误区二：类型体操替代运行时检查
类型系统在编译时消除一类错误，但运行时验证（如 API 输入校验）仍然必要。两者互补而非替代。


误区三：过度泛型化
泛型应该服务于实际的类型复用需求。如果一个泛型参数只在一处使用，很可能不需要泛型。




小结
    

  • TypeScript 的泛型让容器模式（EventEmitter、Builder 等）类型安全。
    • 

  • 联合类型 + 类型收窄是状态模式的优雅替代。
    • 

  • 映射类型和条件类型可以在类型层面实现代理和适配。
    • 

  • 优先选择 TypeScript 惯用实现（函数、模块、联合类型），而非机械照搬 Java 风格的类层次。
