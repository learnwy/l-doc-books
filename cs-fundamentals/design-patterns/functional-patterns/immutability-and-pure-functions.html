不可变性与纯函数

核心概念

不可变性（Immutability）意味着数据一旦创建就不能被修改。纯函数（Pure Function）是相同输入总产生相同输出且无副作用的函数。这两个概念是函数式编程的核心支柱，它们让代码更可预测、更易测试、更安全。



纯函数
纯函数 vs 非纯函数
let discount = 0.1;
function impureCalculatePrice(price: number): number {
  return price * (1 - discount);
}

function pureCalculatePrice(price: number, discountRate: number): number {
  return price * (1 - discountRate);
}

console.log(pureCalculatePrice(100, 0.1));
console.log(pureCalculatePrice(100, 0.1));
非纯函数依赖外部变量 discount，如果它被修改，相同输入会产生不同输出。纯函数将所有依赖显式声明为参数。


纯函数的特征
function add(a: number, b: number): number {
  return a + b;
}

function toUpperCase(str: string): string {
  return str.toUpperCase();
}

function filterEven(numbers: readonly number[]): number[] {
  return numbers.filter((n) => n % 2 === 0);
}

function sortDescending(numbers: readonly number[]): number[] {
  return [...numbers].sort((a, b) => b - a);
}
注意 sortDescending 先用展开运算符创建副本再排序，避免修改输入数组——这保证了纯函数不产生副作用。




不可变性
TypeScript 类型级不可变
interface MutableUser {
  name: string;
  email: string;
  settings: {
    theme: string;
    language: string;
  };
}

type ImmutableUser = Readonly<MutableUser>;

type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};

type StrictImmutableUser = DeepReadonly<MutableUser>;

const user: StrictImmutableUser = {
  name: 'Alice',
  email: 'alice@example.com',
  settings: {
    theme: 'dark',
    language: 'zh-CN',
  },
};
不可变更新
function updateUserName(user: StrictImmutableUser, name: string): StrictImmutableUser {
  return { ...user, name };
}

function updateTheme(user: StrictImmutableUser, theme: string): StrictImmutableUser {
  return {
    ...user,
    settings: { ...user.settings, theme },
  };
}

const updated = updateTheme(updateUserName(user, 'Bob'), 'light');

console.log(user.name);
console.log(updated.name);
console.log(updated.settings.theme);
原始对象未被修改——每次更新都返回新的对象。




不可变集合操作
class ImmutableList<T> {
  private constructor(private readonly items: readonly T[]) {}

  static of<T>(...items: T[]): ImmutableList<T> {
    return new ImmutableList(items);
  }

  static empty<T>(): ImmutableList<T> {
    return new ImmutableList<T>([]);
  }

  push(item: T): ImmutableList<T> {
    return new ImmutableList([...this.items, item]);
  }

  pop(): [T | undefined, ImmutableList<T>] {
    if (this.items.length === 0) return [undefined, this];
    const last = this.items[this.items.length - 1];
    return [last, new ImmutableList(this.items.slice(0, -1))];
  }

  map<R>(fn: (item: T, index: number) => R): ImmutableList<R> {
    return new ImmutableList(this.items.map(fn));
  }

  filter(predicate: (item: T) => boolean): ImmutableList<T> {
    return new ImmutableList(this.items.filter(predicate));
  }

  reduce<R>(fn: (acc: R, item: T) => R, initial: R): R {
    return this.items.reduce(fn, initial);
  }

  get(index: number): T | undefined {
    return this.items[index];
  }

  get size(): number {
    return this.items.length;
  }

  toArray(): readonly T[] {
    return this.items;
  }
}

const list1 = ImmutableList.of(1, 2, 3);
const list2 = list1.push(4);
const list3 = list2.filter((n) => n > 2);

console.log(list1.toArray());
console.log(list2.toArray());
console.log(list3.toArray());


实际应用：状态管理
interface AppState {
  todos: readonly Todo[];
  filter: 'all' | 'active' | 'completed';
  nextId: number;
}

interface Todo {
  id: number;
  text: string;
  completed: boolean;
}

type Action =
  | { type: 'ADD_TODO'; text: string }
  | { type: 'TOGGLE_TODO'; id: number }
  | { type: 'REMOVE_TODO'; id: number }
  | { type: 'SET_FILTER'; filter: AppState['filter'] };

function reducer(state: AppState, action: Action): AppState {
  switch (action.type) {
    case 'ADD_TODO':
      return {
        ...state,
        todos: [...state.todos, { id: state.nextId, text: action.text, completed: false }],
        nextId: state.nextId + 1,
      };
    case 'TOGGLE_TODO':
      return {
        ...state,
        todos: state.todos.map((todo) => (todo.id === action.id ? { ...todo, completed: !todo.completed } : todo)),
      };
    case 'REMOVE_TODO':
      return {
        ...state,
        todos: state.todos.filter((todo) => todo.id !== action.id),
      };
    case 'SET_FILTER':
      return { ...state, filter: action.filter };
  }
}

let state: AppState = { todos: [], filter: 'all', nextId: 1 };

state = reducer(state, { type: 'ADD_TODO', text: 'Learn immutability' });
state = reducer(state, { type: 'ADD_TODO', text: 'Practice pure functions' });
state = reducer(state, { type: 'TOGGLE_TODO', id: 1 });

console.log(state);
这就是 Redux 的核心思想：纯函数 reducer + 不可变状态。




结构共享
不可变更新并不意味着完全复制——未修改的部分通过引用共享。{ ...obj, name: "Bob" } 只创建了一个新的顶层对象，settings 和 permissions 仍然指向同一个引用。




常见误区
误区一：不可变性意味着性能差
结构共享让不可变更新的开销远小于深拷贝。现代 JavaScript 引擎对对象创建有很好的优化。


误区二：所有数据都必须不可变
性能关键路径中（如动画、大数据处理），可变操作可能是更好的选择。不可变性是默认选择，但不是绝对规则。


误区三：纯函数不能有任何 I/O
纯函数的关键是"可预测性"。实际应用中，I/O 被隔离到系统边界，核心业务逻辑保持纯函数。




小结
    

  • 纯函数让代码可预测、可测试、可缓存。
    • 

  • 不可变性消除共享状态带来的副作用问题。
    • 

  • 结构共享让不可变更新性能可接受。
    • 

  • Redux 的 reducer 是纯函数 + 不可变性的典型应用。
