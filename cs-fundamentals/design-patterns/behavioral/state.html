状态模式

核心概念

状态模式（State Pattern）让对象在内部状态改变时改变其行为，对象看起来好像修改了它的类。状态模式将与特定状态相关的行为封装到独立的状态类中，避免了大量的条件分支。



问题背景
没有状态模式时，状态相关的逻辑散布在大量条件分支中：


class OrderBad {
  private status = 'pending';

  process(): string {
    if (this.status === 'pending') {
      this.status = 'processing';
      return 'Order is now being processed';
    } else if (this.status === 'processing') {
      this.status = 'shipped';
      return 'Order has been shipped';
    } else if (this.status === 'shipped') {
      this.status = 'delivered';
      return 'Order has been delivered';
    } else if (this.status === 'delivered') {
      return 'Order already delivered';
    }
    return 'Unknown state';
  }

  cancel(): string {
    if (this.status === 'pending' || this.status === 'processing') {
      this.status = 'cancelled';
      return 'Order cancelled';
    }
    return 'Cannot cancel at this stage';
  }
}
每新增一个状态或操作，都需要在所有方法中添加新的分支——维护成本随状态数量指数增长。




状态模式实现
interface OrderState {
  process(order: Order): string;
  cancel(order: Order): string;
  getStatus(): string;
}

class Order {
  private state: OrderState;

  constructor() {
    this.state = new PendingState();
  }

  setState(state: OrderState): void {
    this.state = state;
  }

  process(): string {
    return this.state.process(this);
  }

  cancel(): string {
    return this.state.cancel(this);
  }

  getStatus(): string {
    return this.state.getStatus();
  }
}

class PendingState implements OrderState {
  process(order: Order): string {
    order.setState(new ProcessingState());
    return 'Order is now being processed';
  }

  cancel(order: Order): string {
    order.setState(new CancelledState());
    return 'Order cancelled';
  }

  getStatus(): string {
    return 'pending';
  }
}

class ProcessingState implements OrderState {
  process(order: Order): string {
    order.setState(new ShippedState());
    return 'Order has been shipped';
  }

  cancel(order: Order): string {
    order.setState(new CancelledState());
    return 'Order cancelled during processing';
  }

  getStatus(): string {
    return 'processing';
  }
}

class ShippedState implements OrderState {
  process(order: Order): string {
    order.setState(new DeliveredState());
    return 'Order has been delivered';
  }

  cancel(_order: Order): string {
    return 'Cannot cancel: order already shipped';
  }

  getStatus(): string {
    return 'shipped';
  }
}

class DeliveredState implements OrderState {
  process(_order: Order): string {
    return 'Order already delivered';
  }

  cancel(_order: Order): string {
    return 'Cannot cancel: order already delivered';
  }

  getStatus(): string {
    return 'delivered';
  }
}

class CancelledState implements OrderState {
  process(_order: Order): string {
    return 'Cannot process: order is cancelled';
  }

  cancel(_order: Order): string {
    return 'Order already cancelled';
  }

  getStatus(): string {
    return 'cancelled';
  }
}

const order = new Order();
console.log(order.getStatus());
console.log(order.process());
console.log(order.process());
console.log(order.cancel());
console.log(order.process());


状态转换图
每个状态类只关心自己的行为和可能的转换目标，状态转换逻辑分散在各个状态类中而非集中在一个巨大的条件分支里。




实际应用：媒体播放器
interface PlayerState {
  play(player: MediaPlayer): void;
  pause(player: MediaPlayer): void;
  stop(player: MediaPlayer): void;
  getStateName(): string;
}

class MediaPlayer {
  private state: PlayerState;
  private track = '';
  private position = 0;

  constructor() {
    this.state = new StoppedPlayerState();
  }

  setState(state: PlayerState): void {
    console.log(`State: ${this.state.getStateName()} → ${state.getStateName()}`);
    this.state = state;
  }

  loadTrack(track: string): void {
    this.track = track;
    this.position = 0;
    console.log(`Loaded: ${track}`);
  }

  play(): void {
    this.state.play(this);
  }
  pause(): void {
    this.state.pause(this);
  }
  stop(): void {
    this.state.stop(this);
  }

  getInfo(): string {
    return `[${this.state.getStateName()}] ${this.track} @ ${this.position}s`;
  }

  setPosition(pos: number): void {
    this.position = pos;
  }
  getPosition(): number {
    return this.position;
  }
}

class StoppedPlayerState implements PlayerState {
  play(player: MediaPlayer): void {
    player.setPosition(0);
    player.setState(new PlayingPlayerState());
  }
  pause(_player: MediaPlayer): void {
    console.log('Already stopped');
  }
  stop(_player: MediaPlayer): void {
    console.log('Already stopped');
  }
  getStateName(): string {
    return 'Stopped';
  }
}

class PlayingPlayerState implements PlayerState {
  play(_player: MediaPlayer): void {
    console.log('Already playing');
  }
  pause(player: MediaPlayer): void {
    player.setState(new PausedPlayerState());
  }
  stop(player: MediaPlayer): void {
    player.setPosition(0);
    player.setState(new StoppedPlayerState());
  }
  getStateName(): string {
    return 'Playing';
  }
}

class PausedPlayerState implements PlayerState {
  play(player: MediaPlayer): void {
    player.setState(new PlayingPlayerState());
  }
  pause(_player: MediaPlayer): void {
    console.log('Already paused');
  }
  stop(player: MediaPlayer): void {
    player.setPosition(0);
    player.setState(new StoppedPlayerState());
  }
  getStateName(): string {
    return 'Paused';
  }
}

const player = new MediaPlayer();
player.loadTrack('song.mp3');
player.play();
console.log(player.getInfo());
player.pause();
console.log(player.getInfo());
player.play();
player.stop();
console.log(player.getInfo());


状态模式 vs 策略模式




维度
状态模式
策略模式





意图
根据内部状态改变行为
在运行时选择算法




状态转换
状态之间有明确的转换关系
策略之间无关联




谁决定切换
状态对象自身触发转换
客户端或 Context 决定切换




典型场景
有限状态机、工作流
算法选择、行为配置







常见误区
误区一：状态太少时使用状态模式
如果只有 2-3 个状态且转换简单，一个 switch 语句可能更清晰。状态模式在状态数量较多或转换逻辑复杂时才有优势。


误区二：状态类之间直接耦合
状态类应该通过 Context 来触发状态转换，而不是直接引用其他状态类。这样更容易替换和测试单个状态。


误区三：忽略状态转换的合法性验证
并非所有状态转换都是合法的。状态类应该明确拒绝非法的转换请求，而不是默默忽略。




小结
    

  • 状态模式将与状态相关的行为封装到独立的状态类中。
    • 

  • 每个状态类只关心自己的行为和可能的转换。
    • 

  • 适用于对象行为随状态变化而变化的场景，尤其是有限状态机。
    • 

  • 与策略模式的区别在于：状态之间有明确的转换关系。
    •
