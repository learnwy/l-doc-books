观察者模式

核心概念

观察者模式（Observer Pattern）定义了对象之间一对多的依赖关系。当一个对象（Subject/被观察者）的状态发生变化时，所有依赖于它的对象（Observer/观察者）都会被自动通知并更新。它是事件驱动架构的基石。



基础实现
type EventHandler<T> = (data: T) => void;

class EventEmitter<EventMap extends Record<string, unknown>> {
  private listeners = new Map<string, Set<EventHandler<unknown>>>();

  on<K extends keyof EventMap & string>(event: K, handler: EventHandler<EventMap[K]>): () => void {
    if (!this.listeners.has(event)) {
      this.listeners.set(event, new Set());
    }
    this.listeners.get(event)!.add(handler as EventHandler<unknown>);

    return () => this.off(event, handler);
  }

  off<K extends keyof EventMap & string>(event: K, handler: EventHandler<EventMap[K]>): void {
    this.listeners.get(event)?.delete(handler as EventHandler<unknown>);
  }

  emit<K extends keyof EventMap & string>(event: K, data: EventMap[K]): void {
    this.listeners.get(event)?.forEach((handler) => handler(data));
  }

  once<K extends keyof EventMap & string>(event: K, handler: EventHandler<EventMap[K]>): () => void {
    const wrapper: EventHandler<EventMap[K]> = (data) => {
      handler(data);
      this.off(event, wrapper);
    };
    return this.on(event, wrapper);
  }
}
这是一个类型安全的 EventEmitter，通过泛型 EventMap 确保事件名称和数据类型的对应关系。




实际应用：状态管理 Store
interface StoreEvents<T> {
  change: { prev: T; next: T };
  reset: T;
}

class Store<T> extends EventEmitter<StoreEvents<T>> {
  private state: T;
  private initialState: T;

  constructor(initialState: T) {
    super();
    this.state = structuredClone(initialState);
    this.initialState = structuredClone(initialState);
  }

  getState(): Readonly<T> {
    return this.state;
  }

  setState(updater: (prev: T) => T): void {
    const prev = this.state;
    this.state = updater(prev);
    this.emit('change', { prev, next: this.state });
  }

  reset(): void {
    this.state = structuredClone(this.initialState);
    this.emit('reset', this.state);
  }
}

interface AppState {
  user: string | null;
  count: number;
  theme: 'light' | 'dark';
}

const store = new Store<AppState>({
  user: null,
  count: 0,
  theme: 'light',
});

const unsubscribe = store.on('change', ({ prev, next }) => {
  console.log('State changed:', JSON.stringify(prev), '->', JSON.stringify(next));
});

store.setState((s) => ({ ...s, user: 'Alice' }));
store.setState((s) => ({ ...s, count: s.count + 1 }));
store.setState((s) => ({ ...s, theme: 'dark' }));

unsubscribe();
store.setState((s) => ({ ...s, count: 99 }));


实际应用：DOM 事件系统
浏览器的 DOM 事件系统本身就是观察者模式的典型实现：


class DomEventSimulator {
  private handlers = new Map<string, Set<(event: CustomEvent) => void>>();

  addEventListener(type: string, handler: (event: CustomEvent) => void): void {
    if (!this.handlers.has(type)) {
      this.handlers.set(type, new Set());
    }
    this.handlers.get(type)!.add(handler);
  }

  removeEventListener(type: string, handler: (event: CustomEvent) => void): void {
    this.handlers.get(type)?.delete(handler);
  }

  dispatchEvent(type: string, detail?: unknown): void {
    const event = { type, detail, timestamp: Date.now() } as CustomEvent;
    this.handlers.get(type)?.forEach((handler) => handler(event));
  }
}

interface CustomEvent {
  type: string;
  detail?: unknown;
  timestamp: number;
}

const button = new DomEventSimulator();

button.addEventListener('click', (e) => {
  console.log(`Button clicked at ${e.timestamp}`);
});

button.addEventListener('click', (e) => {
  console.log(`Analytics: click event recorded`, e.detail);
});

button.dispatchEvent('click', { x: 100, y: 200 });


发布-订阅 vs 观察者




维度
观察者模式
发布-订阅模式





耦合度
Subject 知道 Observer
Publisher 不知道 Subscriber




中间层
无
有 Event Bus / Message Broker




适用场景
组件内部、简单通知
跨模块、跨服务通信







常见误区
误区一：忘记取消订阅
观察者不取消订阅会导致内存泄漏——Subject 持有 Observer 的引用，Observer 无法被垃圾回收。始终在适当的时机调用 unsubscribe。


误区二：通知顺序依赖
不应假设观察者被通知的顺序。如果业务逻辑依赖通知顺序，说明设计有问题——观察者应该是独立的。


误区三：同步通知阻塞
如果某个观察者的处理逻辑耗时较长，会阻塞其他观察者的通知。对于耗时操作，考虑异步通知机制。




小结
    

  • 观察者模式实现一对多的通知机制，是事件驱动架构的基础。
    • 

  • TypeScript 中可以通过泛型实现类型安全的 EventEmitter。
    • 

  • on() 方法返回 unsubscribe 函数是最佳实践。
    • 

  • 与发布-订阅的区别在于是否有中间层。
