策略模式

核心概念

策略模式（Strategy Pattern）定义一系列算法，将每个算法封装起来，并使它们可以互换。策略模式让算法的变化独立于使用算法的客户端。

策略模式的本质是将"做什么"和"怎么做"分离。Context 知道"做什么"（排序、压缩、验证……），Strategy 决定"怎么做"（具体的算法实现）。




经典实现
interface SortStrategy<T> {
  sort(data: T[]): T[];
  name: string;
}

class BubbleSort<T> implements SortStrategy<T> {
  name = 'BubbleSort';

  sort(data: T[]): T[] {
    const arr = [...data];
    for (let i = 0; i < arr.length; i++) {
      for (let j = 0; j < arr.length - i - 1; j++) {
        if (arr[j] > arr[j + 1]) {
          [arr[j], arr[j + 1]] = [arr[j + 1], arr[j]];
        }
      }
    }
    return arr;
  }
}

class QuickSort<T> implements SortStrategy<T> {
  name = 'QuickSort';

  sort(data: T[]): T[] {
    if (data.length <= 1) return [...data];
    const pivot = data[0];
    const left = data.slice(1).filter((x) => x <= pivot);
    const right = data.slice(1).filter((x) => x > pivot);
    return [...this.sort(left), pivot, ...this.sort(right)];
  }
}

class Sorter<T> {
  constructor(private strategy: SortStrategy<T>) {}

  setStrategy(strategy: SortStrategy<T>): void {
    this.strategy = strategy;
  }

  sort(data: T[]): T[] {
    console.log(`Sorting with ${this.strategy.name}`);
    return this.strategy.sort(data);
  }
}

const sorter = new Sorter<number>(new BubbleSort());
console.log(sorter.sort([5, 3, 8, 1, 9]));

sorter.setStrategy(new QuickSort());
console.log(sorter.sort([5, 3, 8, 1, 9]));


函数式策略
在 TypeScript 中，策略不一定需要类——函数本身就是最轻量的策略：


type PricingStrategy = (basePrice: number, quantity: number) => number;

const regularPricing: PricingStrategy = (price, qty) => price * qty;

const bulkPricing: PricingStrategy = (price, qty) => {
  const discount = qty >= 100 ? 0.8 : qty >= 50 ? 0.9 : 1;
  return price * qty * discount;
};

const premiumPricing: PricingStrategy = (price, qty) => {
  return price * qty * 1.2;
};

const seasonalPricing = (season: string): PricingStrategy => {
  const multiplier = season === 'holiday' ? 1.5 : season === 'clearance' ? 0.6 : 1;
  return (price, qty) => price * qty * multiplier;
};

class ShoppingCart {
  private items: { name: string; price: number; quantity: number }[] = [];
  private pricing: PricingStrategy;

  constructor(pricing: PricingStrategy = regularPricing) {
    this.pricing = pricing;
  }

  setPricing(pricing: PricingStrategy): void {
    this.pricing = pricing;
  }

  addItem(name: string, price: number, quantity: number): void {
    this.items.push({ name, price, quantity });
  }

  getTotal(): number {
    return this.items.reduce((total, item) => total + this.pricing(item.price, item.quantity), 0);
  }
}

const cart = new ShoppingCart(bulkPricing);
cart.addItem('Widget', 10, 100);
console.log(`Bulk total: ¥${cart.getTotal()}`);

cart.setPricing(seasonalPricing('holiday'));
console.log(`Holiday total: ¥${cart.getTotal()}`);


实际应用：表单验证
type Validator = (value: string) => string | null;

const required: Validator = (value) => (value.trim() === '' ? 'Field is required' : null);

const minLength =
  (min: number): Validator =>
  (value) =>
    value.length < min ? `Minimum ${min} characters required` : null;

const maxLength =
  (max: number): Validator =>
  (value) =>
    value.length > max ? `Maximum ${max} characters allowed` : null;

const pattern =
  (regex: RegExp, message: string): Validator =>
  (value) =>
    !regex.test(value) ? message : null;

const email: Validator = pattern(/^[^\s@]+@[^\s@]+\.[^\s@]+$/, 'Invalid email format');

function compose(...validators: Validator[]): Validator {
  return (value: string) => {
    for (const validator of validators) {
      const error = validator(value);
      if (error) return error;
    }
    return null;
  };
}

interface FieldConfig {
  name: string;
  value: string;
  validate: Validator;
}

function validateForm(fields: FieldConfig[]): Map<string, string> {
  const errors = new Map<string, string>();
  for (const field of fields) {
    const error = field.validate(field.value);
    if (error) errors.set(field.name, error);
  }
  return errors;
}

const fields: FieldConfig[] = [
  {
    name: 'username',
    value: 'ab',
    validate: compose(required, minLength(3), maxLength(20)),
  },
  {
    name: 'email',
    value: 'invalid-email',
    validate: compose(required, email),
  },
  {
    name: 'password',
    value: '12345678',
    validate: compose(required, minLength(8)),
  },
];

const errors = validateForm(fields);
errors.forEach((error, field) => console.log(`${field}: ${error}`));


策略注册表
class StrategyRegistry<T extends (...args: never[]) => unknown> {
  private strategies = new Map<string, T>();

  register(name: string, strategy: T): void {
    this.strategies.set(name, strategy);
  }

  get(name: string): T {
    const strategy = this.strategies.get(name);
    if (!strategy) throw new Error(`Strategy not found: ${name}`);
    return strategy;
  }

  list(): string[] {
    return Array.from(this.strategies.keys());
  }
}

type CompressionFn = (data: string) => string;

const compressionRegistry = new StrategyRegistry<CompressionFn>();
compressionRegistry.register('gzip', (data) => `gzip(${data})`);
compressionRegistry.register('brotli', (data) => `brotli(${data})`);
compressionRegistry.register('none', (data) => data);

const compress = compressionRegistry.get('gzip');
console.log(compress('Hello World'));


常见误区
误区一：只有两种策略也用策略模式
如果只有两种选择且不太可能增加，一个简单的 if/else 可能更直接。策略模式在选择项较多或频繁变化时才体现价值。


误区二：策略之间有状态依赖
策略应该是无状态的纯函数（或接近纯函数的对象）。如果策略之间有复杂的状态依赖，可能需要考虑状态模式。


误区三：客户端需要了解所有策略
策略模式的目标之一是让客户端不需要了解具体策略的实现。通过工厂或注册表来创建策略，进一步隔离客户端与具体策略。




小结
    

  • 策略模式将算法封装为独立的可互换单元。
    • 

  • 在 TypeScript 中，函数策略比类策略更简洁实用。
    • 

  • compose 函数可以将多个策略组合为一个复合策略。
    • 

  • 策略应该是无状态的，避免策略间的依赖关系。
