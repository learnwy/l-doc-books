依赖注入

核心概念

依赖注入（Dependency Injection, DI）是一种将对象的依赖从内部创建改为外部提供的技术。它是依赖倒置原则（DIP）的具体实现手段。DI 的核心思想：不要在类内部创建依赖，而是从外部注入依赖。



三种注入方式
构造函数注入（推荐）
interface Logger {
  log(message: string): void;
}

interface UserRepository {
  findById(id: string): Promise<User | null>;
  save(user: User): Promise<void>;
}

interface User {
  id: string;
  name: string;
  email: string;
}

class UserService {
  constructor(
    private readonly userRepo: UserRepository,
    private readonly logger: Logger,
  ) {}

  async getUser(id: string): Promise<User | null> {
    this.logger.log(`Getting user: ${id}`);
    return this.userRepo.findById(id);
  }

  async createUser(name: string, email: string): Promise<User> {
    const user: User = { id: crypto.randomUUID(), name, email };
    await this.userRepo.save(user);
    this.logger.log(`Created user: ${user.id}`);
    return user;
  }
}
构造函数注入是最推荐的方式——依赖在对象创建时就确定，对象始终处于有效状态。


属性注入
class NotificationService {
  emailProvider!: EmailProvider;
  smsProvider!: SMSProvider;

  async notify(userId: string, message: string): Promise<void> {
    await this.emailProvider.send(userId, message);
    await this.smsProvider.send(userId, message);
  }
}

interface EmailProvider {
  send(to: string, message: string): Promise<void>;
}

interface SMSProvider {
  send(to: string, message: string): Promise<void>;
}
属性注入更灵活但不安全——对象可能在依赖未注入时被使用。仅在框架要求（如某些装饰器场景）时使用。


方法注入
class ReportGenerator {
  generate(data: unknown[], formatter: DataFormatter, exporter: DataExporter): string {
    const formatted = formatter.format(data);
    return exporter.export(formatted);
  }
}

interface DataFormatter {
  format(data: unknown[]): string;
}

interface DataExporter {
  export(data: string): string;
}
方法注入适合依赖只在特定方法中使用且每次调用可能不同的场景。




手动 DI 容器
type Factory<T> = () => T;

class Container {
  private singletons = new Map<string, unknown>();
  private factories = new Map<string, Factory<unknown>>();
  private isSingleton = new Set<string>();

  register<T>(token: string, factory: Factory<T>, singleton = false): void {
    this.factories.set(token, factory);
    if (singleton) {
      this.isSingleton.add(token);
    }
  }

  resolve<T>(token: string): T {
    if (this.singletons.has(token)) {
      return this.singletons.get(token) as T;
    }

    const factory = this.factories.get(token);
    if (!factory) {
      throw new Error(`No registration for: ${token}`);
    }

    const instance = factory() as T;

    if (this.isSingleton.has(token)) {
      this.singletons.set(token, instance);
    }

    return instance;
  }
}

class ConsoleLogger implements Logger {
  log(message: string): void {
    console.log(`[${new Date().toISOString()}] ${message}`);
  }
}

class InMemoryUserRepo implements UserRepository {
  private users = new Map<string, User>();

  async findById(id: string): Promise<User | null> {
    return this.users.get(id) ?? null;
  }

  async save(user: User): Promise<void> {
    this.users.set(user.id, user);
  }
}

const container = new Container();

container.register<Logger>('Logger', () => new ConsoleLogger(), true);
container.register<UserRepository>('UserRepository', () => new InMemoryUserRepo(), true);
container.register<UserService>(
  'UserService',
  () => new UserService(container.resolve<UserRepository>('UserRepository'), container.resolve<Logger>('Logger')),
);

const userService = container.resolve<UserService>('UserService');


类型安全的 DI 容器
type TokenMap = {
  Logger: Logger;
  UserRepository: UserRepository;
  UserService: UserService;
};

class TypedContainer {
  private singletons = new Map<string, unknown>();
  private factories = new Map<string, Factory<unknown>>();
  private singletonKeys = new Set<string>();

  register<K extends keyof TokenMap>(token: K, factory: () => TokenMap[K], singleton = false): void {
    this.factories.set(token, factory);
    if (singleton) this.singletonKeys.add(token);
  }

  resolve<K extends keyof TokenMap>(token: K): TokenMap[K] {
    if (this.singletons.has(token)) {
      return this.singletons.get(token) as TokenMap[K];
    }

    const factory = this.factories.get(token);
    if (!factory) throw new Error(`No registration for: ${token}`);

    const instance = factory();
    if (this.singletonKeys.has(token)) {
      this.singletons.set(token, instance);
    }

    return instance as TokenMap[K];
  }
}

const typedContainer = new TypedContainer();
typedContainer.register('Logger', () => new ConsoleLogger(), true);
typedContainer.register('UserRepository', () => new InMemoryUserRepo(), true);
typedContainer.register(
  'UserService',
  () => new UserService(typedContainer.resolve('UserRepository'), typedContainer.resolve('Logger')),
);


DI 的测试优势
class MockLogger implements Logger {
  logs: string[] = [];
  log(message: string): void {
    this.logs.push(message);
  }
}

class MockUserRepo implements UserRepository {
  users = new Map<string, User>();

  async findById(id: string): Promise<User | null> {
    return this.users.get(id) ?? null;
  }

  async save(user: User): Promise<void> {
    this.users.set(user.id, user);
  }
}

async function testUserService() {
  const mockLogger = new MockLogger();
  const mockRepo = new MockUserRepo();
  const service = new UserService(mockRepo, mockLogger);

  const user = await service.createUser('Test', 'test@example.com');
  console.assert(user.name === 'Test');
  console.assert(mockLogger.logs.length === 1);
  console.assert(mockRepo.users.size === 1);
  console.log('All tests passed!');
}

testUserService();
通过 DI，测试时注入 Mock 对象，无需真实的日志系统和数据库。




DI 与相关模式




概念
含义





DIP
原则：依赖抽象而非具体




DI
技术：从外部注入依赖




IoC
思想：控制反转，框架调用你的代码




Container
工具：自动管理依赖的创建和注入







常见误区
误区一：到处都用 DI 容器
简单的应用手动 new 并传入依赖就够了。DI 容器在大型应用中才体现价值，小项目中反而增加复杂度。


误区二：DI 等于 IoC 容器
DI 只是将依赖从外部传入的做法。最简单的 DI 就是在构造函数中接受参数。IoC 容器是自动化的工具，不是 DI 的必要条件。


误区三：所有依赖都注入
工具类（如 Math.random()、Date.now()）通常不需要注入。只注入"可能变化"或"需要 mock"的依赖。




小结
    

  • 依赖注入将对象的创建与使用分离，是实现松耦合的关键技术。
    • 

  • 构造函数注入是最推荐的方式，确保对象始终处于有效状态。
    • 

  • DI 容器自动管理依赖关系，大型项目中价值显著。
    • 

  • 最大收益是可测试性——测试时注入 Mock 对象即可。
