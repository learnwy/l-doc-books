小世界网络

核心概念

小世界现象（Small-World Phenomenon）最初由社会心理学家 Stanley Milgram 在 1967 年的实验中揭示：美国任意两个人之间平均只需要 6 步就能通过熟人链相连——这就是著名的"六度分隔"。Duncan Watts 和 Steven Strogatz 在 1998 年将这个现象形式化为小世界网络模型，证明了在规则网络中引入少量随机"捷径"就能产生小世界特性。

小世界网络的两个定义性特征是：高聚类系数（如规则网格）和短平均路径长度（如随机网络）。这两个特征在纯规则网络和纯随机网络中是矛盾的，但小世界网络同时实现了两者。

理论模型





Watts-Strogatz 模型的核心参数是重连概率 p。当 p=0 时，网络是纯规则的；当 p=1 时，网络完全随机。小世界特性出现在 p 很小（约 0.01-0.1）的范围内——少量捷径就足以大幅缩短平均路径长度，同时基本不破坏聚类结构。


Watts-Strogatz 模型
Watts-Strogatz 模型从一个环形规则网络开始：N 个节点排成环，每个节点与左右各 k/2 个邻居相连。然后对每条边，以概率 p 将其一端随机重连到一个新的节点。


interface SmallWorldModel {
  nodes: number;
  k: number;
  p: number;
}

const generateWattsStrogatz = (model: SmallWorldModel): Map<number, Set<number>> => {
  const { nodes: n, k, p } = model;
  const graph = new Map<number, Set<number>>();

  for (let i = 0; i < n; i++) graph.set(i, new Set());

  for (let i = 0; i < n; i++) {
    for (let j = 1; j <= k / 2; j++) {
      const neighbor = (i + j) % n;
      graph.get(i)!.add(neighbor);
      graph.get(neighbor)!.add(i);
    }
  }

  for (let i = 0; i < n; i++) {
    for (let j = 1; j <= k / 2; j++) {
      if (Math.random() < p) {
        const oldNeighbor = (i + j) % n;
        graph.get(i)!.delete(oldNeighbor);
        graph.get(oldNeighbor)!.delete(i);

        let newNeighbor: number;
        do {
          newNeighbor = Math.floor(Math.random() * n);
        } while (newNeighbor === i || graph.get(i)!.has(newNeighbor));

        graph.get(i)!.add(newNeighbor);
        graph.get(newNeighbor)!.add(i);
      }
    }
  }
  return graph;
};

软件系统中的小世界结构
现代软件系统展现出典型的小世界结构。微服务架构中，同一域的服务之间紧密耦合（高聚类），但通过 API 网关和事件总线形成的"捷径"连接了不同域的服务（短路径）。代码库的模块依赖图也常常是小世界的——同一目录下的文件高度互引（高聚类），但通过共享库和工具模块形成跨包的短路径。


小世界特性对软件系统有重要影响。高聚类意味着功能域内的服务可以高效协作，域内的修改通常只影响域内服务。短平均路径意味着任何两个服务之间的调用链不会太长，端到端延迟可控。但小世界也意味着看似遥远的服务可能通过短路径相连，一个服务的故障可能通过"捷径"快速传播到远处。

搜索与导航
小世界网络的另一个关键问题是可导航性（Navigability）：在只知道自己邻居信息的情况下，节点能否高效地将消息路由到任意目标？Milgram 的实验表明人类可以做到这一点，但 Watts-Strogatz 模型并不天然支持高效的分布式搜索。


Jon Kleinberg 在 2000 年证明：只有当长程连接的概率按距离的特定幂律衰减时，分布式贪心搜索才能在 O(log²N) 步内到达目标。具体来说，在二维网格中，当连接概率与距离的 -2 次方成正比时（P(距离 d 的连接) ~ d^(-2)），贪心路由最高效。


这个结果对分布式系统的路由设计有直接启示。P2P 网络中的 DHT（分布式哈希表）如 Chord、Kademlia 都利用了类似的指数递减的邻居选择策略——近邻多、远邻少，但远邻按特定间隔分布。这种结构使得在仅知道局部信息的情况下，O(logN) 步即可到达任意目标。


interface RoutingMetrics {
  averageHops: number;
  maxHops: number;
  routingEfficiency: number;
}

const greedyRouting = (
  graph: Map<number, Set<number>>,
  source: number,
  target: number,
  coordinates: Map<number, [number, number]>,
): number => {
  let current = source;
  let hops = 0;
  const visited = new Set<number>();

  while (current !== target && !visited.has(current)) {
    visited.add(current);
    const neighbors = graph.get(current) ?? new Set();
    let bestNeighbor = -1;
    let bestDistance = Infinity;

    const [tx, ty] = coordinates.get(target)!;
    for (const neighbor of neighbors) {
      const [nx, ny] = coordinates.get(neighbor)!;
      const dist = Math.sqrt((nx - tx) ** 2 + (ny - ty) ** 2);
      if (dist < bestDistance) {
        bestDistance = dist;
        bestNeighbor = neighbor;
      }
    }

    if (bestNeighbor === -1) break;
    current = bestNeighbor;
    hops++;
  }
  return current === target ? hops : -1;
};
