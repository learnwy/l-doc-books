图的分类

核心概念

图可以按照多个维度进行分类，每种类型适用于建模不同类型的关系。理解图的分类对于选择正确的数据结构、算法和分析方法至关重要。在软件系统中，不同类型的关系需要用不同类型的图来建模。

主要图类型的对比：


| 图类型 | 边的特征       | 数学表示      | 软件映射               | 典型算法             |
| ------ | -------------- | ------------- | ---------------------- | -------------------- | ------------------ | -------- |
| 无向图 | 对称关系       | (u,v) = (v,u) | 好友关系、局域网       | BFS、DFS、最小生成树 |
| 有向图 | 非对称关系     | (u,v) ≠ (v,u) | API 调用、关注关系     | 拓扑排序、SCC        |
| 加权图 | 边带数值       | w(u,v) ∈ R    | 延迟、带宽、成本       | Dijkstra、Floyd      |
| 二部图 | 两类节点       | V = V₁ ∪ V₂   | 用户-商品、Worker-Task | 匈牙利算法           |
| DAG    | 有向无环       | 无环路        | 构建系统、数据管线     | 拓扑排序             |
| 超图   | 边连接多个节点 | e ⊆ V (       | e                      | ≥ 2)                 | 多方事务、标签系统 | 超图分割 |


有向图与依赖关系
有向图（Directed Graph/Digraph）中每条边有方向，(u, v) 表示从 u 到 v 的单向关系。有向图是建模因果关系、依赖关系和流程的核心工具。


有向无环图（DAG）是有向图中最重要的子类，因为它保证了不存在循环依赖。包管理器的依赖解析、CI/CD 管线的任务编排、数据处理的 DAG 引擎（如 Apache Airflow）都依赖 DAG 的无环性质。


interface DirectedGraph<V> {
  vertices: Map<string, V>;
  adjacency: Map<string, Set<string>>;
}

const topologicalSort = <V>(graph: DirectedGraph<V>): string[] | null => {
  const inDegree = new Map<string, number>();
  for (const id of graph.vertices.keys()) inDegree.set(id, 0);

  for (const neighbors of graph.adjacency.values()) {
    for (const to of neighbors) {
      inDegree.set(to, (inDegree.get(to) ?? 0) + 1);
    }
  }

  const queue = [...inDegree.entries()].filter(([, d]) => d === 0).map(([id]) => id);

  const result: string[] = [];

  while (queue.length > 0) {
    const current = queue.shift()!;
    result.push(current);

    const neighbors = graph.adjacency.get(current) ?? new Set();
    for (const next of neighbors) {
      const newDeg = (inDegree.get(next) ?? 1) - 1;
      inDegree.set(next, newDeg);
      if (newDeg === 0) queue.push(next);
    }
  }

  return result.length === graph.vertices.size ? result : null;
};
拓扑排序的结果为 null 表示图中存在环，即循环依赖。在软件系统中，循环依赖的检测和消除是架构治理的重要任务。

加权图与网络优化
加权图中每条边附带一个数值（权重），表示关系的强度、成本或距离。在网络系统中，权重可以是延迟、带宽、成本或可靠性。


最短路径问题是加权图上最经典的优化问题。Dijkstra 算法解决单源最短路径（从一个起点到所有终点），适用于非负权图。Bellman-Ford 算法支持负权边。Floyd-Warshall 算法计算所有顶点对之间的最短路径。


在网络路由中，OSPF（开放最短路径优先）协议使用 Dijkstra 算法计算路由路径。在 CDN 中，请求路由算法在加权图上寻找到最近边缘节点的最优路径，权重综合考虑延迟、负载和成本。


最小生成树（MST）是加权无向图上的另一个经典问题——找到连接所有顶点的总权重最小的边集合。MST 在网络设计中有直接应用：用最小的总线缆长度连接所有数据中心。Kruskal 算法和 Prim 算法是两种主要的 MST 算法。

二部图与匹配
二部图（Bipartite Graph）的顶点集可以分为两组 V₁ 和 V₂，所有边都连接不同组的顶点。二部图建模的是"两类实体之间的关系"：用户-商品、工人-任务、学生-课程。


推荐系统的协同过滤本质上是在用户-商品二部图上的运算。如果用户 A 和用户 B 在二部图上有很多共同邻居（购买了相同的商品），那么 A 购买但 B 未购买的商品就是给 B 的推荐候选。


interface BipartiteGraph<L, R, E> {
  leftVertices: Map<string, L>;
  rightVertices: Map<string, R>;
  edges: Map<string, Map<string, E>>;
}

const commonNeighbors = <L, R, E>(graph: BipartiteGraph<L, R, E>, leftId1: string, leftId2: string): string[] => {
  const neighbors1 = new Set(graph.edges.get(leftId1)?.keys() ?? []);
  const neighbors2 = new Set(graph.edges.get(leftId2)?.keys() ?? []);

  return [...neighbors1].filter((n) => neighbors2.has(n));
};

const recommendForLeft = <L, R, E>(
  graph: BipartiteGraph<L, R, E>,
  targetId: string,
  similarIds: string[],
): string[] => {
  const targetNeighbors = new Set(graph.edges.get(targetId)?.keys() ?? []);
  const candidates = new Map<string, number>();

  for (const similarId of similarIds) {
    const neighbors = graph.edges.get(similarId)?.keys() ?? [];
    for (const rightId of neighbors) {
      if (!targetNeighbors.has(rightId)) {
        candidates.set(rightId, (candidates.get(rightId) ?? 0) + 1);
      }
    }
  }

  return [...candidates.entries()].sort((a, b) => b[1] - a[1]).map(([id]) => id);
};
最大匹配问题——在二部图中找到最多不共享顶点的边集合——在任务分配中有直接应用。匈牙利算法（Hungarian Algorithm）解决带权二部图的最优匹配问题：将 N 个任务分配给 N 个工人，使总成本最小。在微服务调度中，将请求分配给最合适的服务实例就是一个在线匹配问题。


特殊图结构
除了上述基本类型，还有几种在软件系统中常见的特殊图结构。


**树（Tree）**是连通无环图，具有 V-1 条边。DOM 树、AST（抽象语法树）、B+ 树索引都是树结构。树的简单性使其成为最常用的数据组织形式。


**完全图（Complete Graph）**中每对顶点之间都有边。在 N 个微服务需要互相通信的场景中，完全连接的服务网格有 N(N-1)/2 条边，这解释了为什么微服务数量增长时通信复杂度急剧上升。


**平面图（Planar Graph）**可以在平面上绘制而边不交叉。电路布局和网络拓扑设计中需要关注图的平面性。

小结
    

  • 图按方向性分为有向图和无向图，按权重分为加权图和无权图
    • 

  • DAG（有向无环图）保证无循环依赖，是构建系统、数据管线和包管理的基础
    • 

  • 加权图上的最短路径和最小生成树算法在网络路由和基础设施设计中有直接应用
    • 

  • 二部图建模两类实体关系，推荐系统的协同过滤基于二部图操作
    • 

  • 树、完全图、星形图等特殊结构在软件架构中频繁出现
    • 

  • 选择正确的图类型是建模问题的第一步
