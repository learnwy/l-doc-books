图的度量指标

核心概念

图的度量指标（Graph Metrics）是量化网络结构特征的数值工具。这些指标从不同角度描述了网络的全局特性（密度、直径）和局部特性（聚类系数、中心性），为比较不同网络、监控网络演化和指导架构设计提供了数据基础。

密度与稀疏性
网络密度 D = 2|E| / (|V|(|V|-1))（无向图）度量了实际连接占所有可能连接的比例。密度为 1 的网络是完全图（每对节点都连接），密度接近 0 的网络是稀疏网络。


大多数真实世界的网络都是稀疏的。互联网的路由器网络、社交网络、代码依赖图的密度通常远小于 0.1。这种稀疏性有深刻的原因——维持每一条边都有成本（带宽、维护、认知负担），因此系统自然倾向于保持稀疏连接。


interface GraphMetrics {
  density: number;
  diameter: number;
  averagePathLength: number;
  averageClusteringCoefficient: number;
}

const calculateDensity = <V, E>(graph: Graph<V, E>, directed: boolean = false): number => {
  const v = graph.getVertices().length;
  const e = graph.getEdgeCount();

  if (v <= 1) return 0;
  const maxEdges = directed ? v * (v - 1) : (v * (v - 1)) / 2;
  return e / maxEdges;
};

const interpretDensity = (density: number, vertexCount: number): { level: string; recommendation: string } => {
  if (density > 0.3) {
    return {
      level: '高密度',
      recommendation: '考虑引入中间层（API 网关、事件总线）减少直接连接',
    };
  }
  if (density > 0.1) {
    return {
      level: '中等密度',
      recommendation: '监控关键路径，确保无不必要的直接依赖',
    };
  }
  return {
    level: '低密度',
    recommendation: '当前耦合度合理，确保连通性满足业务需求',
  };
};
在微服务架构中，监控依赖图的密度变化趋势很有价值。密度持续上升可能表示服务间耦合在恶化——新增的服务倾向于直接调用已有服务而非通过抽象层。密度突然下降可能是因为引入了事件总线或 API 网关等间接通信方式。


聚类系数
聚类系数（Clustering Coefficient）度量节点邻居之间的连接紧密程度。节点 v 的聚类系数 C(v) = 2T(v) / (k(v)(k(v)-1))，其中 T(v) 是 v 的邻居之间实际存在的边数，k(v) 是 v 的度。


高聚类系数意味着"你的朋友也是朋友"——节点的邻居之间形成了紧密的群组。在软件系统中，高聚类系数的服务集群通常对应一个功能域（如订单域、支付域），域内服务交互频繁、紧密耦合。


const clusteringCoefficient = <V, E>(graph: Graph<V, E>, nodeId: string): number => {
  const neighbors = graph.getNeighbors(nodeId).map((n) => n.id);
  const k = neighbors.length;

  if (k < 2) return 0;

  let triangles = 0;
  for (let i = 0; i < neighbors.length; i++) {
    for (let j = i + 1; j < neighbors.length; j++) {
      if (graph.hasEdge(neighbors[i], neighbors[j]) || graph.hasEdge(neighbors[j], neighbors[i])) {
        triangles++;
      }
    }
  }

  return (2 * triangles) / (k * (k - 1));
};

const averageClusteringCoefficient = <V, E>(graph: Graph<V, E>): number => {
  const vertices = graph.getVertices();
  const total = vertices.reduce((sum, v) => sum + clusteringCoefficient(graph, v), 0);
  return total / vertices.length;
};

中心性分析
中心性（Centrality）是度量节点在网络中重要程度的一族指标。不同的中心性指标捕捉了"重要性"的不同方面。


度中心性是最简单的中心性指标——节点的度越高越重要。在社交网络中，度中心性高的用户有更多的直接联系人。在微服务中，度中心性高的服务有更多的直接依赖方和被依赖方。


介数中心性（Betweenness Centrality）度量了一个节点作为"桥梁"的程度——经过该节点的最短路径越多，其介数中心性越高。介数中心性高的节点是网络中的通信枢纽，其移除可能导致网络断裂。


接近中心性（Closeness Centrality）度量了节点到网络中所有其他节点的平均距离。接近中心性高的节点可以最快地到达网络中的任何位置，适合作为信息传播的起点。

度量指标的实践应用
将图度量指标应用于软件架构的持续监控，可以建立架构健康度的定量评估体系。


interface ArchitectureHealth {
  density: number;
  maxDegree: number;
  avgPathLength: number;
  clusteringCoeff: number;
  topBetweenness: Array<{ service: string; score: number }>;
}

const assessArchitectureHealth = (
  metrics: ArchitectureHealth,
): Array<{ area: string; status: string; action: string }> => {
  const findings: Array<{ area: string; status: string; action: string }> = [];

  if (metrics.density > 0.2) {
    findings.push({
      area: '耦合度',
      status: '⚠️ 高密度',
      action: '审查是否有不必要的直接依赖',
    });
  }

  if (metrics.maxDegree > 15) {
    findings.push({
      area: '核心服务',
      status: '⚠️ 度过高',
      action: '考虑拆分或引入代理层',
    });
  }

  if (metrics.topBetweenness[0]?.score > 0.5) {
    findings.push({
      area: '瓶颈风险',
      status: '🔴 高介数节点',
      action: '该服务需要冗余部署和熔断保护',
    });
  }

  return findings;
};
建议的架构指标监控面板应包含：密度趋势（月度变化）、Top-10 度中心性服务、Top-5 介数中心性服务（瓶颈预警）、聚类分析（识别功能域边界）。


小结
    

  • 网络密度度量整体耦合程度，密度持续上升是架构耦合恶化的信号
    • 

  • 聚类系数度量邻居间的紧密程度，高聚类区域通常对应功能域
    • 

  • 度中心性、介数中心性和接近中心性分别衡量连接广度、桥梁作用和传播效率
    • 

  • 低度高介数的节点是最需要冗余设计的关键桥梁
    • 

  • 将图指标纳入持续监控可以建立架构健康度的定量评估体系
    • 

  • 综合多种指标才能全面评估节点在网络中的角色和风险
