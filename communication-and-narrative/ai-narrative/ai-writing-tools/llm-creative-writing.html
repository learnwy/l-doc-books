大语言模型与创意写作

核心概念

大语言模型（Large Language Model, LLM）的创意写作能力不是它被设计出来的——它是一种涌现现象。当一个语言模型在数万亿 token 的文本上训练到足够大的规模时，它"学会"了人类文本中隐含的叙事模式：故事弧线的张力节奏、角色对话的语气变化、描写与叙述的交替节奏、甚至特定作家风格的微妙指纹。

这种能力在2022年末 ChatGPT（基于 GPT-3.5）发布时首次进入公众视野。虽然早期输出质量参差不齐——角色前后不一致、情节逻辑链断裂、倾向于"安全"的老生常谈式情节——但它已经展示了一个惊人的事实：一个没有真实生命经验的数学模型，可以写出让人读得下去的故事。到2024年，GPT-4、Claude 3 Opus 和 Gemini 1.5 Pro 的出现让这一能力发生了质的飞跃：长上下文窗口（100K-1M token）意味着模型可以保持整部小说级别的叙事一致性；更精细的指令跟随能力意味着创作者可以给出复杂的风格和结构要求。

LLM 在创意写作中的定位不是"自动写作机"，而是一个极其博学但缺乏人格的协作者——它读过的小说比任何人类作家都多，能模仿几乎任何风格，但它没有自己想说的话。理解这一点，是有效使用 LLM 进行创意写作的前提。

主流模型的叙事能力对比

截至2025年，创意写作领域最常被使用的 LLM 形成了一个差异化的生态。每个模型有自己的"叙事人格"——这不是官方宣传的特性，而是大量创作者在实践中总结出的经验：

模型 叙事特长 典型弱点 适用场景
GPT-4o / GPT-4.5 多样性高，风格切换灵活，擅长对话体 长文本中角色一致性偶有漂移；默认倾向"安全"的叙事选择 短篇创作、剧本对话、风格探索
Claude 3.5 Sonnet / Claude 4 散文质量高，情感细腻，擅长长段描写 有时"过于文学化"；倾向于反思性叙事 文学小说、人物内心独白、深度描写
Gemini 1.5 Pro / 2.0 超长上下文（1M token），擅长保持跨章节一致性 创意性偏保守；对话有时偏书面化 长篇小说全局规划、系列作品一致性维护
Sudowrite (Story Engine) 专为小说创作设计，支持节拍表、角色数据库 底层模型能力受限于其供应商；价格较高 全流程小说创作
NovelAI (Kayra) 微调于创意小说数据集，二次创作社区活跃 指令跟随能力弱于通用模型；上下文窗口较短 类型小说、同人创作

一个值得注意的趋势是：通用模型（GPT、Claude、Gemini）正在通过更好的提示工程和"创意模式"设置逐步蚕食专业创意写作工具的领地。2025年初 Claude 引入的"创意写作模式"（通过 System Prompt 中的特定指令激活）让它在盲评中首次在多个维度上超过了 Sudowrite 的默认输出质量。这迫使专业工具转向工作流整合（而非单纯的生成质量）作为差异化竞争点。

LLM 叙事能力的技术基础

理解 LLM 为什么"能"写故事，需要理解几个关键的技术机制：

注意力机制与叙事记忆——Transformer 的自注意力机制让模型能够在生成每一个新 token 时"回顾"之前的所有 token。这在叙事语境中意味着：模型在写第三章的场景时，理论上可以"记住"第一章埋下的伏笔。但实际效果受限于上下文窗口大小和注意力的稀释效应。2024年之前，4K-8K token 的窗口让长篇创作几乎不可能保持一致性。128K（GPT-4 Turbo）和 200K（Claude 3）的窗口终于让"一次性载入整部中篇小说"成为现实，但超长上下文中的注意力分配问题仍然存在——模型对上下文中间部分的"遗忘"现象（"Lost in the Middle"问题）在叙事创作中表现为：中间章节的情节线索比开头和结尾更容易被忽略。

RLHF 与叙事偏好——通过人类反馈的强化学习（RLHF）塑造了模型的"叙事品味"。这既是优势也是枷锁。优势在于：RLHF 后的模型倾向于生成结构完整、情感适度的文本，避免了纯预训练模型的混乱输出。枷锁在于：RLHF 引入了系统性的偏好——追求"有帮助、无害"的文本倾向于规避冲突、软化暴力、添加道德说教，而这些恰恰是许多伟大叙事的核心要素。2024年的一项研究（Ippolito et al., "Creative Writing with Large Language Models: A Human-AI Collaboration Study"）发现，RLHF 后的模型生成的故事在"安全性"上得分更高，但在"惊喜性"和"情感冲击力"上显著低于预训练模型的精选输出。

温度参数与创意光谱——温度（Temperature）是控制 LLM 输出随机性的关键参数。温度为0时，模型总是选择概率最高的下一个 token，输出最"安全"但也最无聊。温度越高，低概率 token 被选中的机会越大，输出越"有创意"但也越不可预测。在创意写作中，温度设置是一种叙事决策：低温适合需要精确性的技术描写和逻辑推理段落，高温适合需要出人意料的比喻、意象和情节转折。经验丰富的创作者会在同一部作品的不同段落使用不同的温度设置——这本身就是一种新的"写作技巧"。

LLM 生成叙事的系统性缺陷

在赞叹 LLM 叙事能力的同时，理解其系统性缺陷同样重要——这些不是"当前版本的 bug"，而是基于 LLM 架构的根本性局限：

缺乏真实经验的"体感"——LLM 可以精确描述"从悬崖边缘向下看时的眩晕感"，因为它读过无数这样的描写。但它的描写是模式匹配，不是经验回忆。这导致 LLM 生成的感官描写在统计上"正确"但在情感上"空洞"——它知道应该提到"心跳加速"和"手心出汗"，但它不知道那种让你腿软的具体的、私人的恐惧感。优秀的人类作家之所以能写出让人"感同身受"的段落，是因为他们在写作中注入了自己独特的身体记忆和情感记忆。这是 LLM 无法复制的。

"均值回归"倾向——LLM 的训练过程使其输出倾向于训练数据的统计均值。在叙事语境中，这意味着：它更容易生成"大多数故事是怎样的"，而不是"一个独特的故事应该怎样"。一个向 GPT-4 请求"写一个爱情故事开头"的实验（重复1000次）会发现：超过60%的开头涉及"一个下雨天的咖啡馆"或"机场的偶遇"——因为这些是训练数据中最常见的浪漫叙事起点。打破这种均值回归需要精确的提示工程（第三节详述），或者需要人类创作者提供独特的起点和方向。

叙事"遗忘"与矛盾——即使在长上下文窗口中，LLM 也会在复杂叙事中产生自相矛盾。一个角色在第二章是蓝色眼睛，到第五章可能变成棕色。这不是简单的"记忆错误"——LLM 没有类似人类的"角色心理模型"，它处理的是 token 序列之间的统计关联，而不是持久的实体概念。2025年的多项基准测试（如 StorySense Benchmark 和 NarrativeConsistency-1K）表明：即使是最先进的模型，在超过50K token 的叙事中，角色一致性错误率仍在5-15%——这在专业出版标准下是不可接受的。

道德与叙事冲突的矛盾——伟大的叙事往往建立在道德困境之上：《罪与罚》的拉斯柯尔尼科夫、《洛丽塔》的亨伯特、《绝命毒师》的沃尔特·怀特。但 RLHF 后的模型被训练为规避"有害内容"，这在叙事创作中造成了一种系统性的张力——模型倾向于为反派角色添加"善良的一面"、为暴力场景添加道德谴责、为悲剧结局添加希望的尾巴。这种"安全化"倾向是专业创作者使用 LLM 时最常抱怨的问题之一。

创作者社群的实践演化

AI 写作工具的采用并非单向的"技术推广"过程，而是一个创作者社群内部持续博弈和演化的复杂现象。

2023年初，创作者社群的主流态度是两极化的：科幻/类型小说圈对 AI 工具好奇且积极尝试，文学小说圈则普遍抵制。美国科幻与奇幻作家协会（SFWA）在2023年专门修改了入会标准，要求作品必须是"由人类创作"的。2024年《纽约时报》对美国出版业的调查显示，约38%的作家承认在创作流程中至少使用了一次 AI 工具——但使用方式差异巨大：从头脑风暴、研究辅助到初稿生成、风格修改。

到2025年，一种更务实的共识正在形成：AI 工具的价值不在于替代写作，而在于压缩创作流程中的低价值环节。类型小说作家 Brandon Sanderson 公开表示他使用 AI 辅助世界观一致性检查，但从不让 AI 生成叙事文本。独立出版平台上出现了一种新的标注惯例——"AI-assisted"标签，类似音乐行业的"featuring"标记，表明 AI 参与了创作但人类保持主导权。

使用模式 描述 社群接受度 典型场景
研究辅助 用 AI 检索和整理背景资料 广泛接受 历史小说考证、科幻世界观设定
头脑风暴 让 AI 提供情节走向建议 较高接受 克服写作瓶颈、探索另类发展方向
初稿生成 让 AI 生成初稿后人类深度改写 争议较大 商业类型小说批量生产
风格润色 用 AI 修改语言风格和节奏 中等接受 非母语写作、跨文化改编
完全生成 AI 生成最终文本仅做少量编辑 普遍不接受 极少数低端内容农场

小结

  • LLM 的创意写作能力是规模涌现的结果，不是被专门设计的特性
  • 不同模型有不同的"叙事人格"：GPT 偏多样灵活、Claude 偏文学细腻、Gemini 擅长长篇一致性
  • LLM 的叙事缺陷是架构性的：缺乏体感经验、均值回归倾向、长文本遗忘、安全化过度
  • 创作者社群正在形成务实共识：AI 压缩低价值环节，人类掌控核心叙事决策
  • 上下文窗口的扩大（4K → 128K → 1M）是最影响创意写作体验的单一技术进展
  • 专业化工具（Sudowrite）与通用模型（GPT、Claude）的竞争正在从"生成质量"转向"工作流整合"
