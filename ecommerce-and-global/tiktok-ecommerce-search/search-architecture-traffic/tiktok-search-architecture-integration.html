主站搜索与电商搜索的架构融合

核心概念

TikTok 作为内容优先的短视频平台，其搜索系统的诞生逻辑与传统电商截然不同。Amazon 和 Shopee 从第一天起就是围绕商品搜索构建的，搜索即核心入口。而 TikTok 的搜索系统最初完全服务于内容发现——用户搜索的是创作者、话题标签、音乐和视频。当 TikTok Shop 业务启动后，电商搜索并非另起炉灶，而是作为一个垂直领域嵌入到已有的主站搜索框架中。这种"内容搜索中长出电商搜索"的架构模式，是理解 TikTok 电商搜索体系的根基。

主站搜索与电商搜索的融合意味着：用户在同一个搜索框输入关键词，系统需要同时理解内容意图和商业意图，并在一个统一的结果页中混合展示短视频、直播、商品卡片、店铺等多种结果类型。这种融合架构既带来了独特的流量优势——电商搜索天然获得主站搜索的流量辐射，也带来了巨大的技术挑战——如何在一个查询中平衡娱乐需求和购物需求。

从内容搜索到内容+电商搜索的演进路径
TikTok 搜索系统的演进经历了三个明确的阶段，每个阶段的架构复杂度和商业价值都有质的跃升。


第一阶段是纯内容搜索期。搜索系统仅索引视频、创作者和话题，核心技术是文本匹配和内容理解。这一阶段的搜索排序主要依据内容质量（点赞、评论、分享）和相关性，没有任何商业化组件。搜索框的定位是"帮用户找到想看的视频"。


第二阶段是电商搜索萌芽期。随着 TikTok Shop 上线，系统开始在搜索结果中插入商品卡片。初期采用的是"硬插位"策略——当查询命中商品关键词时，在内容结果中固定位置插入商品卡片。这一阶段的电商搜索本质上是内容搜索的附属模块，商品索引、召回和排序相对简单，更多依赖规则而非算法。


第三阶段是架构融合期。电商搜索从附属模块演变为与内容搜索平级的核心子系统。统一的 Query 理解层同时输出内容意图标签和电商意图标签，意图路由层根据意图强度分配召回权重，混排层在统一的候选集中完成跨类型排序。这一阶段的标志是电商搜索拥有独立的索引、召回和排序能力，但通过统一的入口和混排层与内容搜索深度融合。

统一 Query 理解层的设计
Query 理解层是整个融合架构的第一道关卡。用户输入一个查询词后，系统需要在毫秒级别完成一系列理解任务，为下游的意图路由和召回提供结构化信号。


在 TikTok 的场景下，Query 理解层需要同时输出两套信号：内容理解信号和电商理解信号。当用户搜索"防晒霜推荐"时，内容理解模块会识别出这是一个美妆护肤类的测评话题，电商理解模块则会识别出这是一个防晒产品的购买需求。两套信号的置信度差异构成了后续意图路由的核心输入。


Query 理解层的核心子模块包括：Query 改写（纠错、同义词扩展、缩写展开）、实体识别（品牌、品类、属性、型号）、意图分类（内容浏览、商品购买、店铺查找、直播观看）和 Query 标签化（品类标签、价格区间推断、场景标签）。在 TikTok 的多语言环境下，这些子模块需要覆盖英语、泰语、越南语、印尼语、马来语、西班牙语等多种语言，每种语言的 Query 改写规则和实体库都有差异。


电商 Query 理解有几个 TikTok 特有的挑战。首先是"内容化表达"——用户在 TikTok 上搜索商品时，更倾向使用口语化、场景化的表达（如"约会穿什么"而非"女装连衣裙"），系统需要将这类内容化表达映射到标准的电商品类体系。其次是"跨域消歧"——"苹果"在内容域指水果或科技公司话题，在电商域指 Apple 品牌电子产品或水果品类，系统需要结合用户历史行为和平台当前热点来消歧。


意图路由与多源召回机制
意图路由是融合架构的核心决策点。它根据 Query 理解层输出的意图信号，决定如何在内容搜索引擎和电商搜索引擎之间分配召回配额。


TikTok 的意图路由采用的是"软路由"而非"硬路由"策略。软路由的含义是：不是简单地将查询分为"内容查询"或"电商查询"两个离散类别，而是为每个查询计算一个连续的"电商意图强度"分数（通常在 0-1 之间），然后根据这个分数动态调整两个引擎的召回配额。


当电商意图强度低于 0.2 时（如用户搜索"搞笑猫咪"），系统几乎完全走内容召回，电商结果池仅保留极少量的长尾匹配。当强度在 0.2-0.6 之间时（如用户搜索"好用的蓝牙耳机"），系统进入混合召回模式，两个引擎各自按配额返回候选集。当强度高于 0.6 时（如用户搜索"iPhone 16 手机壳"），电商召回获得主导权，内容结果主要保留与商品评测相关的视频。


多源召回是 TikTok 电商搜索区别于传统电商搜索的关键特性。传统电商只有商品索引一个召回源，而 TikTok 的电商召回至少包含四个独立的索引：商品索引（商品标题、描述、属性）、直播索引（正在直播的带货直播间）、视频索引（带有商品锚点的短视频）和店铺索引（商家店铺信息）。每个索引有独立的召回策略和相关性计算逻辑，最终汇入统一的候选集。

统一混排层与跨类型排序
当多源召回返回来自不同索引的候选集后，混排层负责在统一的框架下对这些异构结果进行排序和展示决策。这是融合架构中技术难度最高的模块之一——如何公平地比较一个商品卡片、一条带货视频和一个直播间的"排序得分"。


混排层的核心挑战在于"度量统一"。商品卡片的价值可以用预估点击率（pCTR）和预估转化率（pCVR）来衡量，带货视频的价值可以用预估完播率和预估互动率来衡量，直播间的价值可以用预估进入率和预估停留时长来衡量。这些指标的量纲完全不同，需要通过一个统一的价值函数映射到可比较的分数空间。


TikTok 混排层的价值函数通常采用多目标加权的形式，综合考虑以下几个维度：用户体验价值（满足用户搜索需求的程度）、商业转化价值（产生 GMV 的概率）、生态健康价值（结果多样性、新品曝光、商家公平性）和内容消费价值（视频和直播的内容质量）。不同维度的权重会根据查询的意图强度动态调整——纯电商意图的查询中，商业转化价值的权重会提高；混合意图的查询中，用户体验价值和内容消费价值的权重更大。


混排层还需要处理"布局决策"——在搜索结果页的有限空间中，决定不同类型结果的排列方式。例如，是将直播间卡片以大图形式置顶展示，还是与商品卡片混排。布局策略直接影响用户的点击分布和整体体验，通常通过 A/B 实验持续优化。


小结
    

  • TikTok 电商搜索并非独立系统，而是嵌入主站搜索框架中的垂直领域子系统，用户通过同一个搜索框同时触达内容和商品
    • 

  • 融合架构经历了三个阶段：纯内容搜索→电商硬插位→深度架构融合，当前处于第三阶段，电商搜索拥有独立的索引和排序能力
    • 

  • 统一 Query 理解层同时输出内容信号和电商信号，TikTok 特有的挑战包括内容化表达映射和跨域消歧
    • 

  • 意图路由采用"软路由"策略，根据电商意图强度连续值动态分配内容和电商的召回配额
    • 

  • 多源召回从商品、直播、视频、店铺四个独立索引并行获取候选集，每个索引有独立的召回策略
    • 

  • 混排层通过统一价值函数将异构结果映射到可比较的分数空间，在用户体验、商业转化、生态健康和内容消费四个维度间动态平衡
    •
