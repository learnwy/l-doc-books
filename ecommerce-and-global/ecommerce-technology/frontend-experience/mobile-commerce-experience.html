移动端电商体验优化

核心概念

移动端已成为电商交易的主要入口，国内主流电商平台超过 80% 的流量和 70% 的交易额来自移动设备。移动端电商体验优化面临独特的挑战：屏幕空间有限、网络环境不稳定、设备性能差异巨大、触控交互模式与桌面端截然不同。优化目标不仅是让页面加载更快，更是让用户在移动场景下的购物体验更加流畅自然。

不同的移动端技术方案在性能、开发效率和平台能力之间各有取舍。电商平台通常采用多端并行策略：核心购物体验由原生 App 承载，营销活动页使用 H5 快速上线，社交分享通过小程序触达用户。

响应式设计与自适应布局
电商页面需要适配从 320px 到 430px 宽度的各种手机屏幕，以及从 768px 到 1024px 的平板设备。响应式设计通过弹性布局和媒体查询实现一套代码适配多种屏幕，自适应设计则为不同设备提供不同的布局方案。

  if (width < breakpoints.tablet.min) return 'mobile';
  if (width < breakpoints.desktop.min) return 'tablet';
  return 'desktop';
}
移动端电商特有的布局挑战包括：瀑布流商品列表的高度计算、商品 SKU 选择器的底部弹出面板、图片轮播的手势切换、以及底部 Tab 栏与页面滚动的协调。商品详情页的布局需要特别注意：商品图片区域占据首屏的 60% 以上，价格和购买按钮需要始终可见（吸底或固定位置）。


触控交互与手势优化
移动端的交互模式以触控手势为主，手指的精度和速度远不如鼠标。电商页面的每个交互元素都需要针对触控进行优化：点击区域不小于 44×44pt、手势冲突处理、触觉反馈和滑动流畅性。

PWA 与离线能力
PWA（Progressive Web App）通过 Service Worker 为电商 H5 页面增加类 App 的体验：离线访问、后台同步、推送通知和主屏幕快捷方式。对于不想下载 App 的用户，PWA 提供了一个轻量级但功能完整的购物入口。


Service Worker 的缓存策略直接影响 PWA 的离线体验和加载速度。电商 PWA 的缓存策略需要根据资源类型差异化配置：App Shell（HTML 骨架和核心 JS/CSS）使用 Cache-First 策略保证离线可用，商品数据使用 Network-First 策略保证实时性，商品图片使用 Stale-While-Revalidate 策略兼顾速度和新鲜度。


interface CacheStrategyConfig {
  name: string;

  maxAge: number;
  maxEntries: number;
}

interface OfflineCartSync {
  pendingItems: Array<{ skuId: string; quantity: number; addedAt: number }>;
  syncStatus: 'synced' | 'pending' | 'error';
  lastSyncAt: number;
}

async function syncOfflineCart(cart: OfflineCartSync): Promise<void> {
  if (cart.pendingItems.length === 0) return;
  try {
    await fetch('/api/cart/batch-add', {
      method: 'POST',
      body: JSON.stringify({ items: cart.pendingItems }),
      headers: { 'Content-Type': 'application/json' },
    });
    cart.pendingItems = [];
    cart.syncStatus = 'synced';
    cart.lastSyncAt = Date.now();
  } catch {
    cart.syncStatus = 'error';
  }
}
离线购物车是电商 PWA 的核心功能：用户在地铁等弱网环境下可以浏览已缓存的商品并加入购物车，网络恢复后自动同步。Background Sync API 使得同步操作即使在页面关闭后也能在后台完成。

function calculateVisibleRange(
  scrollTop: number,
  containerHeight: number,
  itemHeights: number[],
  overscan: number,
): { startIndex: number; endIndex: number } {
  let startIndex = 0;
  let accHeight = 0;
  for (let i = 0; i < itemHeights.length; i++) {
    if (accHeight + itemHeights[i] > scrollTop) {
      startIndex = Math.max(0, i - overscan);
      break;
    }
    accHeight += itemHeights[i];
  }

  let endIndex = startIndex;
  let visibleHeight = 0;
  for (let i = startIndex; i < itemHeights.length; i++) {
    visibleHeight += itemHeights[i];
    endIndex = i;
    if (visibleHeight > containerHeight + scrollTop - accHeight) break;
  }
  endIndex = Math.min(itemHeights.length - 1, endIndex + overscan);

  return { startIndex, endIndex };
}
WebView 预创建和预热是 App 内 H5 页面秒开的关键技术。App 启动时预先创建一个 WebView 实例并加载通用的 HTML 骨架和 JS 运行时，当用户进入 H5 页面时只需要注入具体的页面数据和组件，避免了 WebView 初始化（通常需要 300-500ms）的延迟。
