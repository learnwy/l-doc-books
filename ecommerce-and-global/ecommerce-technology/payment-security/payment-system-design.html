支付系统架构设计

核心概念

支付系统是电商平台中对可靠性和安全性要求最高的子系统。一笔支付交易涉及用户、商户、支付渠道和清结算系统四方协作，任何环节的失败都可能导致资金损失或用户体验崩塌。支付系统设计的核心挑战在于：在分布式环境下保证资金操作的幂等性和一致性，同时支持多渠道接入和高并发处理。

支付系统的核心流程从收银台发起，经过风控校验、渠道路由、支付执行、异步回调到最终的清结算和对账。每个环节都有严格的状态管理和异常处理机制。

支付流程与状态管理
支付交易的状态管理是整个系统的核心。一笔支付从创建到最终完成，经历多个状态转换，每个状态转换都有严格的前置条件和触发动作。状态机设计必须考虑各种异常场景：用户关闭支付页面、渠道超时无响应、重复回调等。


支付单号的设计直接影响系统的追踪和对账能力。支付单号需要全局唯一、趋势递增、可以从中解析出时间和业务类型信息。常见的编码规则是：时间戳（14 位）+ 业务类型（2 位）+ 机器标识（2 位）+ 序列号（4 位）+ 校验位（2 位），总长度 24 位。

function generatePaymentId(bizType: string, machineId: string): string {
  const timestamp = new Date()
    .toISOString()
    .replace(/[-:T.Z]/g, '')
    .slice(0, 14);
  const sequence = String(getNextSequence()).padStart(4, '0');
  const checksum = computeChecksum(`${timestamp}${bizType}${machineId}${sequence}`);
  return `${timestamp}${bizType}${machineId}${sequence}${checksum}`;
}

function getNextSequence(): number {
  return Math.floor(Math.random() * 10000);
}
function computeChecksum(input: string): string {
  let sum = 0;
  for (const ch of input) sum += ch.charCodeAt(0);
  return String(sum % 100).padStart(2, '0');
}
幂等性与防重复支付
幂等性是支付系统最关键的设计原则。网络抖动、用户重复点击、回调重复投递等场景都可能导致同一笔支付被处理多次。如果没有幂等保护，用户可能被多次扣款，资金损失将无法挽回。


支付幂等的实现依赖全局唯一的幂等键（Idempotency Key）。每次支付请求携带幂等键，系统在处理前先查询该键是否已存在：如果存在则直接返回上次的处理结果，如果不存在则正常处理并记录幂等键和结果。


interface IdempotencyRecord {
  key: string;
  status: 'processing' | 'completed' | 'failed';
  response: string;
  createdAt: Date;
  expiresAt: Date;
}

async function processPaymentWithIdempotency(
  idempotencyKey: string,
  paymentRequest: PaymentRequest,
): Promise<PaymentResponse> {
  const existing = await idempotencyStore.get(idempotencyKey);
  if (existing) {
    if (existing.status === 'processing') {
      throw new Error('PAYMENT_IN_PROGRESS');
    }
    return JSON.parse(existing.response) as PaymentResponse;
  }

  await idempotencyStore.set(idempotencyKey, {
    key: idempotencyKey,
    status: 'processing',
    response: '',
    createdAt: new Date(),
    expiresAt: new Date(Date.now() + 24 * 60 * 60 * 1000),
  });

  try {
    const response = await executePayment(paymentRequest);
    await idempotencyStore.update(idempotencyKey, {
      status: 'completed',
      response: JSON.stringify(response),
    });
    return response;
  } catch (error) {
    await idempotencyStore.update(idempotencyKey, {
      status: 'failed',
      response: JSON.stringify({ error: (error as Error).message }),
    });
    throw error;
  }
}

渠道路由与智能选路
大型电商平台通常对接多个支付渠道，不同渠道在费率、成功率、结算周期和限额方面各有差异。渠道路由引擎根据当前交易的特征（金额、银行卡类型、地域）和渠道的实时状态（成功率、延迟）智能选择最优渠道。

interface ChannelConfig {
  channelId: string;
  name: string;
  enabled: boolean;
  feeRate: number;
  minAmount: number;
  maxAmount: number;
  settlementCycle: 'T0' | 'T1' | 'T2';
  supportedCardTypes: string[];
}

interface ChannelMetrics {
  channelId: string;
  successRate1h: number;
  avgLatencyMs: number;
  currentTps: number;
  maxTps: number;
}

function selectOptimalChannel(
  amount: number,
  cardType: string,
  channels: ChannelConfig[],
  metrics: Map<string, ChannelMetrics>,
): ChannelConfig | null {
  const eligible = channels.filter((ch) => {
    if (!ch.enabled) return false;
    if (amount < ch.minAmount || amount > ch.maxAmount) return false;
    if (!ch.supportedCardTypes.includes(cardType)) return false;
    const m = metrics.get(ch.channelId);
    if (m && m.currentTps >= m.maxTps * 0.9) return false;
    return true;
  });

  return (
    eligible.sort((a, b) => {
      const metricsA = metrics.get(a.channelId);
      const metricsB = metrics.get(b.channelId);
      const scoreA = (metricsA?.successRate1h ?? 0.8) * 100 - a.feeRate * 1000;
      const scoreB = (metricsB?.successRate1h ?? 0.8) * 100 - b.feeRate * 1000;
      return scoreB - scoreA;
    })[0] ?? null
  );
}
渠道降级策略在渠道故障时自动切换。当某个渠道的成功率在 5 分钟窗口内降到 80% 以下，路由引擎自动将流量切换到备用渠道，并发出告警通知运维人员排查。渠道恢复后通过灰度方式逐步恢复流量，避免突然涌入大量请求导致再次故障。


对账与资金安全
对账是支付系统的最后防线，确保平台记录的每一笔交易与支付渠道的记录完全一致。对账差异可能意味着资金损失、重复扣款或系统 Bug，必须在 T+1 日内发现并处理。


对账流程分为三步：单边账检查（只在一方有记录）、金额差异检查（双方都有记录但金额不一致）和状态差异检查（双方状态不一致，如平台记录成功但渠道记录失败）。


interface ReconciliationRecord {
  paymentId: string;
  platformAmount: number;
  platformStatus: string;
  channelAmount: number;
  channelStatus: string;
  reconcileStatus: 'matched' | 'amount_mismatch' | 'status_mismatch' | 'platform_only' | 'channel_only';
  difference: number;
}

function reconcile(
  platformRecords: Map<string, { amount: number; status: string }>,
  channelRecords: Map<string, { amount: number; status: string }>,
): ReconciliationRecord[] {
  const results: ReconciliationRecord[] = [];
  const allIds = new Set([...platformRecords.keys(), ...channelRecords.keys()]);

  for (const paymentId of allIds) {
    const platform = platformRecords.get(paymentId);
    const channel = channelRecords.get(paymentId);

    if (platform && !channel) {
      results.push({
        paymentId,
        platformAmount: platform.amount,
        platformStatus: platform.status,
        channelAmount: 0,
        channelStatus: '',
        reconcileStatus: 'platform_only',
        difference: platform.amount,
      });
    } else if (!platform && channel) {
      results.push({
        paymentId,
        platformAmount: 0,
        platformStatus: '',
        channelAmount: channel.amount,
        channelStatus: channel.status,
        reconcileStatus: 'channel_only',
        difference: channel.amount,
      });
    } else if (platform && channel) {
      const diff = platform.amount - channel.amount;
      let status: ReconciliationRecord['reconcileStatus'] = 'matched';
      if (Math.abs(diff) > 0.01) status = 'amount_mismatch';
      else if (platform.status !== channel.status) status = 'status_mismatch';
      results.push({
        paymentId,
        platformAmount: platform.amount,
        platformStatus: platform.status,
        channelAmount: channel.amount,
        channelStatus: channel.status,
        reconcileStatus: status,
        difference: diff,
      });
    }
  }

  return results;
}
资金安全还需要建立多层防护：交易流水的实时监控（异常交易金额告警）、资金池余额的定时巡检（余额低于阈值告警）、以及定期的资金审计（人工核查大额交易和异常账户）。


小结
    

  • 支付系统从收银台到清结算经历六个核心环节，每个环节有严格的状态管理和异常处理
    • 

  • 支付状态机定义了从待支付到退款完成的完整生命周期，覆盖超时、重试和退款等异常场景
    • 

  • 幂等性通过全局唯一幂等键实现，前后端配合防止重复支付，分布式锁保证并发安全
    • 

  • 渠道路由根据成功率、费率和限额智能选路，降级策略在渠道故障时自动切换备用渠道
    • 

  • 对账系统在 T+1 日完成单边账、金额差异和状态差异三维检查，资金安全依赖多层监控防护
