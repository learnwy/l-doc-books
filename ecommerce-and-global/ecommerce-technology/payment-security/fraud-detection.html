反欺诈与风控系统

核心概念

电商反欺诈系统是保护平台和用户免受恶意行为侵害的安全屏障。欺诈行为贯穿电商交易的全链路：注册环节的虚假账号、营销环节的薅羊毛、交易环节的盗刷信用卡、售后环节的恶意退款。风控系统需要在毫秒级完成风险评估，既不能放过欺诈交易，也不能误伤正常用户。

风控系统的设计遵循「分层防御」原则：第一层是规则引擎处理已知的确定性欺诈模式，第二层是机器学习模型发现未知的可疑行为，第三层是人工审核处理边界案例。三层协作保证了覆盖率和准确率的平衡。

规则引擎与实时决策
规则引擎是风控系统的第一道防线，处理已知的、可以明确定义的欺诈模式。规则引擎的优势在于可解释性强、响应速度快（微秒级）、业务人员可以直接配置，不需要等待模型训练。


电商场景的典型规则包括：单用户每日下单超过 N 次触发限制、同一 IP 短时间内创建多个账号触发拦截、订单金额超过用户历史最高消费 M 倍触发人审、同一优惠券被不同账号在同一设备使用触发封禁。


interface RiskRule {
  ruleId: string;
  name: string;
  priority: number;
  conditions: RuleCondition[];
  action: 'pass' | 'block' | 'review' | 'verify' | 'limit';
  enabled: boolean;
  effectiveTime: { start: Date; end: Date };
}

interface RuleCondition {
  field: string;
  operator: 'eq' | 'gt' | 'lt' | 'gte' | 'lte' | 'in' | 'not_in' | 'regex';
  value: unknown;
  timeWindow?: number;
  aggregation?: 'count' | 'sum' | 'avg' | 'max' | 'distinct_count';
}

const sampleRules: RiskRule[] = [
  {
    ruleId: 'R001',
    name: '单用户高频下单',
    priority: 1,
    conditions: [{ field: 'user.order_count_1h', operator: 'gt', value: 10, timeWindow: 3600, aggregation: 'count' }],
    action: 'review',
    enabled: true,
    effectiveTime: { start: new Date('2024-01-01'), end: new Date('2099-12-31') },
  },
  {
    ruleId: 'R002',
    name: '异常金额交易',
    priority: 2,
    conditions: [
      { field: 'order.amount', operator: 'gt', value: 50000 },
      { field: 'user.max_order_amount_30d', operator: 'lt', value: 5000 },
    ],
    action: 'verify',
    enabled: true,
    effectiveTime: { start: new Date('2024-01-01'), end: new Date('2099-12-31') },
  },
  {
    ruleId: 'R003',
    name: '同设备多账号优惠券',
    priority: 1,
    conditions: [
      { field: 'device.account_count_7d', operator: 'gt', value: 3, timeWindow: 604800, aggregation: 'distinct_count' },
      { field: 'order.has_coupon', operator: 'eq', value: true },
    ],
    action: 'block',
    enabled: true,
    effectiveTime: { start: new Date('2024-01-01'), end: new Date('2099-12-31') },
  },
];

function evaluateRules(event: RiskEvent, rules: RiskRule[]): RiskDecision {
  const sortedRules = rules.filter((r) => r.enabled).sort((a, b) => a.priority - b.priority);
  for (const rule of sortedRules) {
    if (matchAllConditions(event, rule.conditions)) {
      return { ruleId: rule.ruleId, action: rule.action, confidence: 1.0 };
    }
  }
  return { ruleId: '', action: 'pass', confidence: 0 };
}

interface RiskEvent {
  [key: string]: unknown;
}
interface RiskDecision {
  ruleId: string;
  action: string;
  confidence: number;
}
function matchAllConditions(_event: RiskEvent, _conditions: RuleCondition[]): boolean {
  return false;
}
规则引擎的挑战在于规则膨胀和冲突管理。随着业务发展，规则数量可能达到数百条，规则之间的优先级和冲突需要仔细管理。最佳实践是建立规则的分层体系：全局规则（适用所有场景）、业务规则（适用特定业务线）和临时规则（应对突发事件），每层内部按优先级排序，高优先级规则命中后不再评估低优先级规则。


机器学习风控模型
机器学习模型是风控系统发现未知欺诈模式的核心能力。与规则引擎处理已知模式不同，ML 模型通过学习历史欺诈样本的特征分布，能够识别之前未见过的欺诈变种。电商风控模型通常采用 XGBoost 或 LightGBM 等梯度提升树模型，兼顾性能和可解释性。

    scrollBehavior: number;
    typingSpeed: number;

interface ModelPrediction {
  riskScore: number;
  riskLevel: 'low' | 'medium' | 'high' | 'critical';
  topRiskFactors: Array<{ feature: string; contribution: number }>;
}

function classifyRisk(score: number): ModelPrediction['riskLevel'] {
  if (score >= 0.9) return 'critical';
  if (score >= 0.7) return 'high';
  if (score >= 0.4) return 'medium';
  return 'low';
}

function decideAction(ruleDecision: RiskDecision, modelPrediction: ModelPrediction): string {
  if (ruleDecision.action === 'block') return 'block';
  if (modelPrediction.riskLevel === 'critical') return 'block';
  if (modelPrediction.riskLevel === 'high') return 'review';
  if (ruleDecision.action === 'review') return 'review';
  if (modelPrediction.riskLevel === 'medium') return 'verify';
  return 'pass';
}
模型特征工程是风控效果的关键。除了基础的用户属性和交易属性外，行为序列特征（用户在下单前的浏览轨迹）和社交网络特征（与已知欺诈账号的关联度）能显著提升模型的识别能力。实时特征（最近 1 小时的操作频率）和离线特征（过去 30 天的消费习惯）需要融合使用。


设备指纹与环境感知
设备指纹技术通过采集终端设备的硬件信息、软件环境和浏览器特征，生成唯一的设备标识。即使用户更换账号或清除 Cookie，设备指纹仍然能关联到同一台设备，是反欺诈的重要信号源。

设备指纹在电商风控中的核心应用包括：关联同一设备上的多个账号（发现薅羊毛团伙）、检测设备环境异常（模拟器、Root 设备风险高）、以及跟踪设备在不同交易中的行为一致性。当同一设备短时间内切换多个账号下单使用优惠券时，系统可以高度确信这是薅羊毛行为。


风险评分与动态策略
风控系统的最终输出是一个综合风险评分和对应的处置策略。评分模型融合了规则引擎的确定性判断、ML 模型的概率预测和实时上下文信息，输出 0-100 的风险分数。不同分数区间对应不同的处置策略，阈值根据业务容忍度动态调整。


interface RiskAssessment {
  eventId: string;
  riskScore: number;
  action: 'pass' | 'verify' | 'review' | 'block';
  reasons: string[];
  timestamp: Date;
  responseTimeMs: number;
}

interface RiskThresholds {
  passThreshold: number;
  verifyThreshold: number;
  reviewThreshold: number;
  blockThreshold: number;
}

const defaultThresholds: RiskThresholds = {
  passThreshold: 30,
  verifyThreshold: 50,
  reviewThreshold: 75,
  blockThreshold: 90,
};

function determineAction(score: number, thresholds: RiskThresholds): RiskAssessment['action'] {
  if (score >= thresholds.blockThreshold) return 'block';
  if (score >= thresholds.reviewThreshold) return 'review';
  if (score >= thresholds.verifyThreshold) return 'verify';
  return 'pass';
}
动态阈值调整是风控系统的重要能力。在大促期间，正常用户的行为模式会发生变化（高频下单、大额消费），如果阈值不调整会导致大量误拦。风控运营人员需要提前为大促配置专用规则集和宽松阈值，活动结束后恢复常规配置。


小结
    

  • 风控系统采用规则引擎、ML 模型和人工审核三层防御架构，在毫秒级完成风险评估
    • 

  • 规则引擎处理已知欺诈模式，支持业务人员直接配置，需要建立分层规则体系避免规则膨胀
    • 

  • 机器学习模型通过行为序列和设备特征发现未知欺诈变种，XGBoost 是工业界主流选择
    • 

  • 设备指纹通过硬件、浏览器和行为特征生成唯一标识，是关联多账号欺诈的核心技术
    • 

  • 风险评分融合规则和模型输出，动态阈值根据业务场景（大促/常规）灵活调整
