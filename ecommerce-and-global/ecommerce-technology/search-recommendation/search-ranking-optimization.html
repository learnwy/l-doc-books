搜索排序与结果优化

核心概念

搜索排序是决定用户看到什么商品的最终裁判。即使召回阶段找到了所有相关商品，如果排序不当——将低质量商品排在前面、将最匹配的商品埋在第三页——用户体验和转化率都会大打折扣。电商搜索排序的目标不仅是相关性最大化，还需要兼顾商业价值（GMV）、用户满意度和生态公平性之间的多目标平衡。

搜索排序从简单的 TF-IDF 文本匹配发展到基于机器学习的 Learning to Rank（LTR），再到深度学习驱动的端到端排序模型。现代电商搜索排序已经是一个融合了信息检索、机器学习和业务策略的复杂系统。

Learning to Rank 排序模型
Learning to Rank（LTR）将搜索排序建模为监督学习问题：给定查询和商品对，训练模型预测排序得分。LTR 方法根据损失函数的不同分为三类：Pointwise（预测单个商品的绝对得分）、Pairwise（预测商品对的相对顺序）和 Listwise（直接优化整个列表的排序指标）。


Pairwise 方法在电商搜索中最为常用。LambdaMART 是工业界广泛采用的 LTR 模型，它结合了 LambdaRank 的梯度计算和 GBDT（Gradient Boosting Decision Tree）的强大表达能力。LambdaMART 的训练数据来源于搜索日志：用户点击的商品构成正样本，展示但未点击的商品构成负样本，点击位置的差异被编码为样本权重。

interface TrainingSample {
  queryId: string;
  features: RankingFeature;
  label: number;
  weight: number;
}

function generateTrainingSamples(searchLog: SearchLogEntry[]): TrainingSample[] {
  const samples: TrainingSample[] = [];
  for (const entry of searchLog) {
    for (const result of entry.results) {
      const label = computeLabel(result.actions);
      const weight = computePositionWeight(result.position);
      samples.push({
        queryId: entry.queryId,
        features: extractFeatures(entry.query, result.itemId, entry.userId),
        label,
        weight,
      });
    }
  }
  return samples;
}

function computeLabel(actions: string[]): number {
  if (actions.includes('purchase')) return 4;
  if (actions.includes('cart')) return 3;
  if (actions.includes('click')) return 2;
  if (actions.includes('impression')) return 0;
  return 0;
}

function computePositionWeight(position: number): number {
  return 1 / Math.log2(position + 2);
}

interface SearchLogEntry {
  queryId: string;
  query: string;
  userId: string;
  results: Array<{ itemId: string; position: number; actions: string[] }>;
}

特征工程是 LTR 模型效果的关键。电商搜索排序的特征可以分为四大类：查询-商品匹配特征（BM25 得分、标题匹配度、品类匹配）、商品质量特征（销量、转化率、评分、退货率）、用户偏好特征（品类亲和度、品牌偏好、价格偏好）和上下文特征（是否促销、库存水平、配送速度）。


个性化搜索排序
相同的搜索词对不同用户应该呈现不同的排序结果。搜索「笔记本电脑」时，学生用户应该优先看到性价比高的产品，商务用户应该优先看到轻薄高性能的产品。个性化搜索排序将用户画像特征融入排序模型，实现千人千面的搜索体验。


个性化信号主要来自三个维度：长期偏好（过去 30 天的品类购买分布、品牌偏好）、短期兴趣（最近 3 天的浏览和搜索行为）和实时意图（当前会话的点击序列）。三个维度的信号按不同权重融合：实时意图权重最高因为最能反映当前需求，长期偏好作为兜底保证推荐的稳定性。


interface PersonalizationProfile {
  longTermPreferences: {
    categoryDistribution: Record<string, number>;
    brandPreference: Record<string, number>;
    priceRange: { min: number; max: number; median: number };
    qualitySensitivity: number;
  };
  shortTermInterests: {
    recentViewCategories: string[];
    recentSearchQueries: string[];
    recentCartItems: string[];
  };
  sessionContext: {
    clickSequence: string[];
    dwellTimeDistribution: Record<string, number>;
    currentIntent: string;
  };
}

function computePersonalizationScore(
  item: ItemFeatures,
  profile: PersonalizationProfile,
  weights: { longTerm: number; shortTerm: number; session: number },
): number {
  const longTermScore = computeLongTermAffinity(item, profile.longTermPreferences);
  const shortTermScore = computeShortTermRelevance(item, profile.shortTermInterests);
  const sessionScore = computeSessionRelevance(item, profile.sessionContext);

  return weights.longTerm * longTermScore + weights.shortTerm * shortTermScore + weights.session * sessionScore;
}

interface ItemFeatures {
  categoryId: string;
  brand: string;
  price: number;
  tags: string[];
}

function computeLongTermAffinity(item: ItemFeatures, prefs: PersonalizationProfile['longTermPreferences']): number {
  const categoryScore = prefs.categoryDistribution[item.categoryId] ?? 0;
  const brandScore = prefs.brandPreference[item.brand] ?? 0;
  const priceScore = item.price >= prefs.priceRange.min && item.price <= prefs.priceRange.max ? 1 : 0.5;
  return (categoryScore + brandScore + priceScore) / 3;
}

function computeShortTermRelevance(
  item: ItemFeatures,
  interests: PersonalizationProfile['shortTermInterests'],
): number {
  const categoryMatch = interests.recentViewCategories.includes(item.categoryId) ? 1 : 0;
  return categoryMatch;
}

function computeSessionRelevance(item: ItemFeatures, session: PersonalizationProfile['sessionContext']): number {
  return session.clickSequence.length > 0 ? 0.5 : 0;
}
个性化排序需要避免过度个性化——如果用户买了一台冰箱后持续推荐冰箱，体验反而很差。需要建立商品的购买周期模型：高频消费品（食品、日化）可以反复推荐，耐用品（家电、家具）购买后应该降低权重并推荐互补品。

function evaluateNDCG(rankedItems: string[], relevanceLabels: Map<string, number>, k: number): number {
  let dcg = 0;
  for (let i = 0; i < Math.min(k, rankedItems.length); i++) {
    const relevance = relevanceLabels.get(rankedItems[i]) ?? 0;
    dcg += (Math.pow(2, relevance) - 1) / Math.log2(i + 2);
  }

  const sortedRelevances = [...relevanceLabels.values()].sort((a, b) => b - a);
  let idcg = 0;
  for (let i = 0; i < Math.min(k, sortedRelevances.length); i++) {
    idcg += (Math.pow(2, sortedRelevances[i]) - 1) / Math.log2(i + 2);
  }

  return idcg === 0 ? 0 : dcg / idcg;
}
搜索质量的日常监控需要建立完整的指标看板，涵盖核心搜索词的 NDCG 变化趋势、无结果率的实时告警、以及低质量搜索结果的自动抽样审核。当核心指标出现异常下降时，需要快速定位是索引更新问题、模型退化还是数据异常。


商业化排序与流量分配
电商搜索排序不仅是技术问题，还涉及商业化的流量分配策略。搜索广告（竞价排名）和自然搜索结果如何共存、新品和长尾商品如何获得曝光、平台自营商品和第三方商品的公平排序，都是需要在技术和商业之间平衡的议题。


搜索广告通常采用 GSP（广义第二价格拍卖）机制：广告主为关键词出价，实际扣费为下一位广告主的出价加一个最小增量。广告排序分数 = 出价 × 质量分，质量分由广告的点击率、相关性和落地页体验综合评估。这种机制确保出价高但不相关的广告不会排在前面。


新品流量扶持策略在生态健康和短期收益之间取得平衡。新品因为缺少点击和销量数据，在基于历史数据的排序模型中天然劣势。电商平台通常为新品提供流量补贴：在新品上架后的 7-14 天内，给予排序加权，通过初始曝光收集行为数据，再逐步过渡到数据驱动的排序。
