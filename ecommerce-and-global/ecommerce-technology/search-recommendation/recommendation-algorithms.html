推荐算法与个性化

核心概念

推荐系统是电商平台提升用户体验和商业转化的核心引擎。不同于搜索系统响应用户的显式需求，推荐系统通过分析用户行为和偏好，主动将可能感兴趣的商品呈现给用户。电商场景中，推荐系统贡献了 30-40% 的交易额，首页推荐、商品详情页「猜你喜欢」、购物车推荐和邮件推送都是典型的推荐入口。

推荐系统的技术架构通常分为离线训练、近线更新和在线服务三个层次。离线层负责模型训练和特征工程，近线层处理实时行为信号更新用户兴趣，在线层完成多路召回、融合排序和策略干预。

协同过滤与矩阵分解
协同过滤（Collaborative Filtering）是推荐系统最经典的方法。其核心假设是：过去有相似行为的用户，未来也会有相似的偏好。基于用户的协同过滤（User-CF）找到与目标用户行为相似的用户群体，将他们喜欢但目标用户未接触的商品推荐出来。基于物品的协同过滤（Item-CF）则计算物品之间的相似度，推荐与用户历史交互物品相似的商品。


在电商场景中，Item-CF 比 User-CF 更受欢迎。原因在于：商品之间的相似关系相对稳定（手机壳和手机总是相关的），而用户兴趣变化较快；商品数量通常远少于用户数量，计算相似度的开销更小；Item-CF 的推荐结果可解释性更好（「购买了 X 的用户也买了 Y」）。


interface UserItemMatrix {
  userId: string;
  itemId: string;
  score: number;
  timestamp: number;
}

function computeItemSimilarity(
  interactions: UserItemMatrix[],
  targetItem: string,
  topK: number,
): Array<{ itemId: string; similarity: number }> {
  const itemUsers = new Map<string, Set<string>>();
  for (const interaction of interactions) {
    if (!itemUsers.has(interaction.itemId)) {
      itemUsers.set(interaction.itemId, new Set());
    }
    itemUsers.get(interaction.itemId)!.add(interaction.userId);
  }

  const targetUsers = itemUsers.get(targetItem);
  if (!targetUsers) return [];

  const similarities: Array<{ itemId: string; similarity: number }> = [];
  for (const [itemId, users] of itemUsers) {
    if (itemId === targetItem) continue;
    const intersection = new Set([...targetUsers].filter((u) => users.has(u)));
    const cosineSim = intersection.size / Math.sqrt(targetUsers.size * users.size);
    if (cosineSim > 0) {
      similarities.push({ itemId, similarity: cosineSim });
    }
  }

  return similarities.sort((a, b) => b.similarity - a.similarity).slice(0, topK);
}
矩阵分解（Matrix Factorization）将稀疏的用户-商品交互矩阵分解为两个低秩矩阵的乘积，用户和商品各自被映射到同一个低维向量空间中。两个向量的内积代表用户对商品的偏好得分。ALS（Alternating Least Squares）和 SVD++ 是最常用的矩阵分解算法。在电商场景中，矩阵分解能有效处理数据稀疏性问题，百万级用户和商品规模下的训练时间在小时级别。


深度学习推荐模型
深度学习推荐模型通过神经网络自动学习特征交叉和非线性关系，大幅超越了传统方法的精度上限。电商推荐领域的标志性模型包括 Wide & Deep、DeepFM、DIN（Deep Interest Network）和多任务学习框架。


DIN（Deep Interest Network）是阿里巴巴提出的电商推荐模型，其核心创新是引入注意力机制来建模用户兴趣的多样性和与候选商品的局部相关性。传统模型将用户的所有历史行为等权求和得到一个固定的用户兴趣向量，DIN 则根据候选商品动态计算用户历史行为的权重——当推荐手机时，用户浏览手机壳的行为权重高于浏览零食的行为。


interface RecommendationFeatures {
  userFeatures: {
    userId: string;
    age: number;
    gender: string;
    city: string;
    memberLevel: number;
    recentCategories: string[];
  };
  itemFeatures: {
    itemId: string;
    categoryId: string;
    brand: string;
    price: number;
    salesCount: number;
    rating: float;
    tags: string[];
  };
  contextFeatures: {
    timestamp: number;
    deviceType: string;
    pageSource: string;
    queryKeyword?: string;
  };
  behaviorSequence: Array<{
    itemId: string;
    action: 'view' | 'click' | 'cart' | 'purchase';
    timestamp: number;
  }>;
}

type float = number;

interface ModelPrediction {
  itemId: string;
  clickProbability: number;
  conversionProbability: number;
  expectedRevenue: number;
}

function rankCandidates(candidates: RecommendationFeatures[], model: DeepRankingModel): ModelPrediction[] {
  const predictions = candidates.map((features) => ({
    itemId: features.itemFeatures.itemId,
    clickProbability: model.predictClick(features),
    conversionProbability: model.predictConversion(features),
    expectedRevenue: model.predictRevenue(features),
  }));
  return predictions.sort((a, b) => b.expectedRevenue - a.expectedRevenue);
}

interface DeepRankingModel {
  predictClick(features: RecommendationFeatures): number;
  predictConversion(features: RecommendationFeatures): number;
  predictRevenue(features: RecommendationFeatures): number;
}
多任务学习（Multi-Task Learning）在电商推荐中至关重要。用户的转化漏斗包含曝光→点击→加购→购买多个阶段，不同阶段的优化目标不同。MMOE（Multi-gate Mixture-of-Experts）模型通过共享专家网络和独立门控网络，同时优化点击率（CTR）和转化率（CVR），比单独优化单一目标效果更好。


实时推荐与特征更新
用户的兴趣是动态变化的——刚刚浏览了一款笔记本电脑的用户，接下来应该推荐电脑配件而不是上周关注的零食。实时推荐要求系统能在毫秒级捕获用户行为变化并更新推荐结果。


实时特征系统通常采用 Lambda 架构或 Kappa 架构。Lambda 架构同时维护离线批处理和实时流处理两条链路：离线特征每天批量计算（用户近 30 天购买品类分布、商品历史 CTR），实时特征通过 Kafka + Flink 流计算秒级更新（用户当次会话浏览序列、实时点击计数）。在线服务时将离线特征和实时特征拼接送入排序模型。

  userId: string,
  triggerItem: string,
  featureStore: FeatureStore,

    itemId: candidates[idx],
    score: computeScore(userFeatures, itemFeatures, model),
  }));
  return scores
    .sort((a, b) => b.score - a.score)
    .map((s) => s.itemId)
    .slice(0, 20);
}

用户冷启动是推荐系统面临的永恒挑战。新用户没有行为历史，无法进行协同过滤和个性化排序。电商平台的冷启动策略包括：基于热门商品推荐（最安全的兜底策略）、基于注册信息推荐（年龄、性别、城市）、基于流量来源推荐（从搜索引擎进入的用户可能有明确购买意图）、以及交互式冷启动（引导用户选择感兴趣的品类）。


推荐多样性与探索利用
推荐系统如果只追求点击率最大化，会陷入信息茧房——反复推荐用户已知的品类，限制用户发现新品的机会，长期来看损害用户体验和平台生态。多样性策略和探索-利用（Exploration-Exploitation）平衡是解决这一问题的关键。

interface DiversityConfig {
  maxSameCategoryCount: number;
  minCategoryCount: number;
  explorationRate: number;
  newItemBoost: number;
}

function applyDiversity(
  ranked: Array<{ itemId: string; score: number; categoryId: string; isNew: boolean }>,
  config: DiversityConfig,
): Array<{ itemId: string; score: number }> {
  const result: Array<{ itemId: string; score: number; categoryId: string; isNew: boolean }> = [];
  const categoryCount = new Map<string, number>();

  for (const item of ranked) {
    const currentCount = categoryCount.get(item.categoryId) ?? 0;
    if (currentCount >= config.maxSameCategoryCount) continue;

    let adjustedScore = item.score;
    if (item.isNew) {
      adjustedScore *= 1 + config.newItemBoost;
    }
    if (Math.random() < config.explorationRate) {
      adjustedScore *= 0.5 + Math.random();
    }

    result.push({ ...item, score: adjustedScore });
    categoryCount.set(item.categoryId, currentCount + 1);
  }

  return result.sort((a, b) => b.score - a.score);
}
A/B 测试是评估推荐策略的黄金标准。每次算法迭代都需要通过线上 A/B 实验验证效果，核心指标包括点击率（CTR）、加购率、转化率（CVR）、客单价（AOV）和人均 GMV。需要注意的是，短期指标提升不一定代表长期收益——过度追求点击率可能导致推荐低价商品，虽然点击多了但客单价下降。
