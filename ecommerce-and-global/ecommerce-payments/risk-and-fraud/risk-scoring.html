风险评分与决策引擎

核心概念

风险评分（Risk Scoring）将每笔交易的多维度风险信号综合为一个可量化的分数（通常 0-100 或 0-1000），用于驱动自动化的通过/拒绝/审核决策。评分引擎是连接数据采集层和业务决策层的核心枢纽，需要平衡欺诈防控和用户体验两个相互冲突的目标。

评分模型架构
评分模型通常采用集成学习（Ensemble）架构，将多个子模型的输出加权融合为最终评分。子模型各有侧重：规则子评分覆盖已知欺诈模式，ML 子评分捕捉复杂的非线性关系，速率子评分检测异常频率，网络子评分识别关联风险。


interface RiskScoreComponents {
  ruleScore: {
    score: number;
    weight: 0.25;
    triggeredRules: string[];
  };
  mlScore: {
    score: number;
    weight: 0.35;
    modelVersion: string;
    topFeatures: { name: string; shap: number }[];
  };
  velocityScore: {
    score: number;
    weight: 0.2;
    anomalies: string[];
  };
  networkScore: {
    score: number;
    weight: 0.2;
    riskFactors: string[];
  };
  finalScore: number;
  confidence: number;
}

const calculateFinalScore = (components: RiskScoreComponents): number => {
  const weighted =
    components.ruleScore.score * components.ruleScore.weight +
    components.mlScore.score * components.mlScore.weight +
    components.velocityScore.score * components.velocityScore.weight +
    components.networkScore.score * components.networkScore.weight;
  return Math.round(Math.min(100, Math.max(0, weighted)));
};
模型的可解释性至关重要。当交易被拒绝或触发人工审核时，审核人员需要知道是哪些因素导致了高分。SHAP（SHapley Additive exPlanations）值为每个特征提供量化的贡献度，让风控团队理解模型的决策逻辑。

决策引擎设计
决策引擎根据风险评分和业务规则执行最终的交易处置。决策策略需要在"通过率"和"欺诈率"之间找到最优平衡点。通过率过低会丢失合法订单（误拒成本），欺诈率过高会产生拒付和赔付损失。


决策阈值的设定方法：首先确定业务可接受的欺诈率上限（如 0.1%），然后在历史数据上调整阈值使欺诈率不超过上限的同时最大化通过率。不同业务线可能有不同的风险容忍度——数字商品（即时交付、不可追回）比实物商品需要更严格的阈值。


interface DecisionPolicy {
  name: string;
  merchantCategory: string;
  thresholds: {
    autoApprove: number;
    softDecline: number;
    hardDecline: number;
  };
  actions: {
    approve: { executeCapture: boolean };
    challenge: {
      methods: ('3ds' | 'otp' | 'manual_review')[];
      timeout: number;
      fallbackAction: 'approve' | 'decline';
    };
    decline: {
      responseCode: string;
      retryAllowed: boolean;
      blacklistDevice: boolean;
    };
  };
  overrides: {
    trustedCustomers: { maxScore: number; action: 'approve' };
    highValueOrders: { minAmount: number; additionalVerification: boolean };
    newCustomers: { scoreAdjustment: number };
  };
}
软拒绝（Soft Decline）是平衡体验和风控的重要策略。当评分处于灰色地带时，不直接拒绝交易，而是要求额外验证（如触发 3DS 挑战、发送 OTP、要求上传证件照）。通过验证的交易正常处理，验证失败则拒绝。软拒绝可以将误拒率降低 30-50%。


动态阈值与自适应策略
固定阈值无法应对欺诈模式的变化和业务的季节性波动。动态阈值根据实时数据自动调整决策边界——当检测到欺诈攻击激增时自动收紧阈值，攻击消退后逐步放松。


interface DynamicThresholdConfig {
  baselineWindow: '7d' | '30d';
  adjustmentFactors: {
    fraudRateSpike: {
      threshold: number;
      tightenBy: number;
      cooldownMinutes: number;
    };
    declineRateSpike: {
      threshold: number;
      loosenBy: number;
      maxLoosen: number;
    };
    seasonalAdjustment: {
      blackFriday: { modifier: number };
      christmas: { modifier: number };
      doubleEleven: { modifier: number };
    };
  };
  monitoring: {
    alertOnThresholdChange: boolean;
    maxAutoAdjustment: number;
    requireApprovalBeyond: number;
  };
}

interface ThresholdAuditLog {
  timestamp: number;
  previousThreshold: number;
  newThreshold: number;
  reason: string;
  triggeredBy: 'auto' | 'manual';
  approvedBy?: string;
  metrics: {
    currentFraudRate: number;
    currentDeclineRate: number;
    currentApprovalRate: number;
  };
}
大促期间（如双十一、黑色星期五）的风控策略需要特别调整。交易量激增 5-10 倍，正常用户的行为模式也会偏离日常（如深夜下单、异常高金额），如果不调整阈值会导致大量误拒。通常做法是提前切换到"大促模式"——适当放宽通过阈值、增加人工审核人力、实时监控欺诈率并保留快速回调能力。

人工审核与案件管理
人工审核处理机器无法确定的中等风险交易。审核效率直接影响用户等待时间和运营成本。优秀的审核工作台应在一个界面上聚合所有决策所需的信息：交易详情、风险评分明细、用户历史、关联交易图谱、设备信息。


interface ReviewCase {
  caseId: string;
  transactionId: string;
  priority: 'urgent' | 'high' | 'medium' | 'low';
  assignedTo: string | null;
  status: 'pending' | 'in_review' | 'approved' | 'declined' | 'escalated';
  riskScore: number;
  riskFactors: string[];
  customerProfile: {
    accountAge: number;
    totalOrders: number;
    chargebackHistory: number;
    verificationLevel: string;
  };
  linkedTransactions: {
    sameCard: number;
    sameDevice: number;
    sameAddress: number;
  };
  slaDeadline: number;
  reviewerNotes: string[];
  decision?: {
    action: 'approve' | 'decline';
    reason: string;
    reviewer: string;
    timestamp: number;
  };
}

审核结果应反馈到模型训练系统中形成闭环。审核员标注的"确认欺诈"和"确认正常"数据成为模型迭代的重要标签来源。长期目标是通过模型迭代不断提升自动化比率，将人工审核聚焦在最复杂的案件上。


小结
    

  • 风险评分将多维度信号综合为 0-100 的量化分数，驱动自动通过/验证/拒绝决策
    • 

  • 集成评分模型融合规则、ML、速率和网络四类子评分，SHAP 值提供样本级的可解释性
    • 

  • 决策引擎通过软拒绝（3DS/OTP 验证）平衡风控和用户体验，可将误拒率降低 30-50%
    • 

  • 动态阈值根据实时欺诈率和业务场景自动调整，大促期间需切换宽松模式防止误拒
    • 

  • 人工审核处理灰色地带交易，审核结果反馈到模型训练形成持续优化闭环
    • 

  • 核心指标是欺诈率、误拒率和审核效率的三角平衡
