支付欺诈检测

核心概念

支付欺诈每年给全球电商造成超过 400 亿美元的损失。欺诈检测是在不影响正常用户体验的前提下，识别和拦截恶意交易。现代欺诈检测系统融合规则引擎、机器学习模型和实时行为分析，在毫秒级响应窗口内做出准确判断。

设备指纹与行为分析
设备指纹（Device Fingerprinting）通过采集浏览器/设备的技术特征组合来唯一标识一台设备，即使用户更换 IP 地址或清除 Cookie 也能追踪。采集的信号包括：User-Agent、屏幕分辨率、时区、已安装字体、WebGL 渲染器、Canvas 指纹、AudioContext 指纹等。


interface DeviceFingerprint {
  fingerprintId: string;
  confidence: number;
  signals: {
    userAgent: string;
    screenResolution: string;
    timezone: string;
    language: string;
    platform: string;
    webglRenderer: string;
    canvasHash: string;
    audioHash: string;
    installedPlugins: string[];
    touchSupport: boolean;
    colorDepth: number;
    hardwareConcurrency: number;
  };
  riskIndicators: {
    isVPN: boolean;
    isProxy: boolean;
    isTor: boolean;
    isEmulator: boolean;
    isBot: boolean;
    isIncognito: boolean;
    ipGeolocationMismatch: boolean;
  };
}
行为生物识别（Behavioral Biometrics）分析用户在页面上的交互模式——打字节奏、鼠标移动轨迹、滑动速度、点击力度等。这些特征像指纹一样独特，难以被机器人或欺诈者模仿。当检测到行为模式偏离历史基线时（如突然从中国变为美国 IP、打字速度异常快），系统触发增强验证。

规则引擎
规则引擎是欺诈检测的第一道防线，通过预定义的条件逻辑快速过滤明显的欺诈交易。规则通常基于领域专家的经验制定，覆盖金额阈值、频率限制、地理围栏和黑名单匹配等维度。


interface FraudRule {
  id: string;
  name: string;
  priority: number;
  enabled: boolean;
  conditions: {
    field: string;
    operator: 'eq' | 'gt' | 'lt' | 'in' | 'not_in' | 'regex';
    value: string | number | string[];
  }[];
  conditionLogic: 'AND' | 'OR';
  action: 'block' | 'review' | 'challenge' | 'allow';
  score: number;
  metadata: {
    author: string;
    reason: string;
    lastModified: number;
    falsePositiveRate?: number;
  };
}

规则引擎的局限在于：规则数量增长后互相冲突难以维护；固定阈值无法适应变化的欺诈模式；新型攻击手法绕过现有规则。因此规则引擎通常作为基础层，复杂判断交给机器学习模型。


机器学习风控模型
机器学习模型通过分析历史交易数据中的欺诈模式，自动学习区分正常和异常交易的特征组合。常用的模型包括 XGBoost/LightGBM（表格数据表现优异）、孤立森林（Isolation Forest，擅长异常检测）和图神经网络（GNN，分析关联关系）。


特征工程是风控模型的核心。有效特征分为三类：交易维度（金额、时间、支付方式）、用户维度（注册时间、历史交易、设备数量）、关联维度（同一卡/设备/地址的其他交易）。时间窗口聚合特征尤为重要——"该卡过去 1 小时内的交易次数"比"该卡的总交易次数"更能识别盗卡行为。


interface FraudFeatures {
  transaction: {
    amount: number;
    amountDeviation: number;
    currency: string;
    paymentMethod: string;
    isFirstPurchase: boolean;
    hourOfDay: number;
    dayOfWeek: number;
  };
  velocity: {
    cardTransactions1h: number;
    cardTransactions24h: number;
    deviceTransactions1h: number;
    ipTransactions1h: number;
    uniqueCardsPerDevice24h: number;
    uniqueDevicesPerCard24h: number;
  };
  user: {
    accountAgeDays: number;
    totalTransactions: number;
    averageOrderValue: number;
    chargebackCount: number;
    addressChangeRecent: boolean;
  };
  network: {
    ipRiskScore: number;
    emailDomainAge: number;
    phoneVerified: boolean;
    billingShippingMatch: boolean;
    socialMediaLinked: boolean;
  };
}

interface ModelPrediction {
  fraudProbability: number;
  riskLevel: 'low' | 'medium' | 'high';
  topRiskFactors: { feature: string; contribution: number }[];
  recommendation: 'approve' | 'challenge' | 'decline' | 'manual_review';
  modelVersion: string;
  inferenceLatency: number;
}

实时风控架构
生产级风控系统需要在 50-200ms 内完成风险评估。架构通常采用"快慢结合"策略：快路径使用规则引擎和轻量级模型做实时拦截，慢路径使用复杂模型和人工审核处理中等风险交易。


实时特征计算依赖流处理框架（如 Apache Flink、Kafka Streams）。将交易事件流入 Flink 作业，实时聚合速率特征（过去 1 小时同一卡的交易次数、同一 IP 的不同卡数量等），结果写入 Redis 或 Feature Store 供推理服务查询。

小结
    

  • 支付欺诈主要包括盗卡欺诈（40%）、账户接管（25%）和友好欺诈（20%），每种需要不同的检测策略
    • 

  • 设备指纹和行为生物识别提供用户身份的持续验证，难以被欺诈者伪造
    • 

  • 规则引擎作为第一道防线快速过滤明显欺诈，但无法应对新型和复杂的攻击模式
    • 

  • 机器学习模型（XGBoost + 孤立森林 + GNN）通过特征工程和模式学习实现更精准的风险判断
    • 

  • 实时风控架构采用"快慢结合"策略，在 50-200ms 内完成评估的同时保证准确率
    • 

  • 风控效果的核心指标是欺诈检出率和误拒率的平衡——过于激进会伤害正常用户体验
    •
