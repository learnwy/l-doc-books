归因模型与渠道评估

核心概念

归因模型（Attribution Model）解决的是电商营销中最根本的问题：当一个用户经过多个渠道触点最终完成购买时，每个渠道应该分得多少功劳？用户可能先通过搜索引擎看到品牌广告，三天后在社交媒体上看到种草内容，最后通过品牌 App 直接搜索下单。这三个触点对最终转化的贡献如何量化，直接影响数十亿级别的营销预算分配。

归因模型的选择直接决定了渠道 ROI 的评估结果和预算分配方向。不同的归因模型可能得出截然相反的结论——最后点击归因可能显示搜索广告效果最好（因为用户最后一步是搜索），而首次点击归因可能显示信息流广告更有价值（因为它是用户首次了解品牌的触点）。

规则型归因模型实现
规则型归因模型按预定义的规则分配转化功劳，实现简单、结果可预期。电商平台通常先用规则型归因快速起步，积累足够数据后再过渡到数据驱动归因。


interface TouchPoint {
  channel: string;
  campaign: string;
  timestamp: number;
  eventType: 'impression' | 'click' | 'visit';
}

interface ConversionEvent {
  userId: string;
  orderId: string;
  revenue: number;
  timestamp: number;
  touchPoints: TouchPoint[];
}

interface AttributionResult {
  channel: string;
  campaign: string;
  attributedConversions: number;
  attributedRevenue: number;
  weight: number;
}

type AttributionModel = (conversion: ConversionEvent) => AttributionResult[];

const lastClickAttribution: AttributionModel = (conversion) => {
  const lastTouch = conversion.touchPoints
    .filter((t) => t.eventType === 'click')
    .sort((a, b) => b.timestamp - a.timestamp)[0];
  if (!lastTouch) return [];
  return [
    {
      channel: lastTouch.channel,
      campaign: lastTouch.campaign,
      attributedConversions: 1,
      attributedRevenue: conversion.revenue,
      weight: 1.0,
    },
  ];
};

const linearAttribution: AttributionModel = (conversion) => {
  const touches = conversion.touchPoints.filter((t) => t.eventType === 'click');
  if (touches.length === 0) return [];
  const weight = 1 / touches.length;
  return touches.map((t) => ({
    channel: t.channel,
    campaign: t.campaign,
    attributedConversions: weight,
    attributedRevenue: conversion.revenue * weight,
    weight,
  }));
};

const timeDecayAttribution: AttributionModel = (conversion) => {
  const touches = conversion.touchPoints.filter((t) => t.eventType === 'click');
  if (touches.length === 0) return [];
  const halfLifeMs = 7 * 86400000;
  const weights = touches.map((t) => {
    const timeDiff = conversion.timestamp - t.timestamp;
    return Math.pow(2, -timeDiff / halfLifeMs);
  });
  const totalWeight = weights.reduce((sum, w) => sum + w, 0);
  return touches.map((t, i) => ({
    channel: t.channel,
    campaign: t.campaign,
    attributedConversions: weights[i] / totalWeight,
    attributedRevenue: conversion.revenue * (weights[i] / totalWeight),
    weight: weights[i] / totalWeight,
  }));
};

const positionBasedAttribution: AttributionModel = (conversion) => {
  const touches = conversion.touchPoints.filter((t) => t.eventType === 'click');
  if (touches.length === 0) return [];
  if (touches.length === 1) {
    return [
      {
        channel: touches[0].channel,
        campaign: touches[0].campaign,
        attributedConversions: 1,
        attributedRevenue: conversion.revenue,
        weight: 1.0,
      },
    ];
  }
  const weights = touches.map((_, i) => {
    if (i === 0) return 0.4;
    if (i === touches.length - 1) return 0.4;
    return 0.2 / (touches.length - 2);
  });
  return touches.map((t, i) => ({
    channel: t.channel,
    campaign: t.campaign,
    attributedConversions: weights[i],
    attributedRevenue: conversion.revenue * weights[i],
    weight: weights[i],
  }));
};
数据驱动归因
数据驱动归因（Data-Driven Attribution, DDA）通过算法自动计算每个触点的真实贡献，不依赖预设规则。核心思想是比较「有某个触点」和「没有某个触点」两种场景下的转化概率差异（反事实推理），差异越大说明该触点的贡献越大。


Shapley 值是数据驱动归因中最常用的算法，源自合作博弈论。它将每个触点视为「玩家」，计算该玩家加入不同子集时带来的边际贡献的加权平均值。


interface ShapleyAttributionResult {
  channel: string;
  shapleyValue: number;
  marginalContribution: number;
  conversionLift: number;
}

function calculateShapleyValues(
  conversionPaths: Array<{ touchPoints: string[]; converted: boolean }>,
  channels: string[],
): ShapleyAttributionResult[] {
  const pathConversionRates = new Map<string, number>();

  const subsets = generateSubsets(channels);
  for (const subset of subsets) {
    const subsetKey = subset.sort().join(',');
    const matchingPaths = conversionPaths.filter((path) => {
      const pathChannels = new Set(path.touchPoints);
      return subset.every((ch) => pathChannels.has(ch)) && subset.length === new Set(path.touchPoints).size;
    });
    const convRate =
      matchingPaths.length > 0 ? matchingPaths.filter((p) => p.converted).length / matchingPaths.length : 0;
    pathConversionRates.set(subsetKey, convRate);
  }

  return channels.map((channel) => {
    let shapleyValue = 0;
    const otherChannels = channels.filter((c) => c !== channel);
    const coalitions = generateSubsets(otherChannels);

    for (const coalition of coalitions) {
      const withChannel = [...coalition, channel].sort().join(',');
      const withoutChannel = coalition.sort().join(',');
      const marginal = (pathConversionRates.get(withChannel) ?? 0) - (pathConversionRates.get(withoutChannel) ?? 0);

      const weight =
        (factorial(coalition.length) * factorial(channels.length - coalition.length - 1)) / factorial(channels.length);
      shapleyValue += weight * marginal;
    }

    return {
      channel,
      shapleyValue,
      marginalContribution: shapleyValue,
      conversionLift: shapleyValue * 100,
    };
  });
}

function generateSubsets(items: string[]): string[][] {
  const result: string[][] = [[]];
  for (const item of items) {
    const newSubsets = result.map((subset) => [...subset, item]);
    result.push(...newSubsets);
  }
  return result;
}

function factorial(n: number): number {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}
数据驱动归因的挑战在于数据量要求高（每个渠道至少需要数千次转化路径）和计算复杂度高（渠道数量增加时 Shapley 值的计算呈指数增长）。实践中通常对渠道数量进行合并简化（如将所有付费搜索渠道合并为一个），并使用蒙特卡洛采样近似计算 Shapley 值。


多触点归因与渠道预算优化
多触点归因（Multi-Touch Attribution, MTA）的最终目标是指导渠道预算的最优分配。基于归因结果，可以计算每个渠道的真实 ROI 和边际效益，将预算从边际收益递减的渠道转移到边际收益递增的渠道。

归因模型的选择本身也需要通过实验验证。一种方法是「归因预测回测」：用历史数据训练归因模型，然后用模型结果调整预算分配，预测调整后的 GMV 变化，再与实际结果对比。如果数据驱动归因的预测误差显著低于最后点击归因，说明其对渠道贡献的估计更准确。


增量测试（Incrementality Testing）是验证渠道真实价值的黄金标准。选择某个地区暂停特定渠道的投放（地理分割实验），或将同一渠道的用户随机分为投放组和不投放组，比较两组的转化差异。增量效果才是渠道的真实贡献，去除了自然转化和其他渠道的交叉影响。


小结
    

  • 归因模型解决多触点转化功劳分配问题，直接影响数十亿级别的营销预算决策
    • 

  • 规则型归因（最后点击、线性、时间衰减、位置基准）实现简单但有主观假设
    • 

  • 数据驱动归因通过 Shapley 值计算每个触点的真实边际贡献，结果更客观
    • 

  • 归因结果指导渠道预算优化，从边际收益递减的渠道转移到递增的渠道
    • 

  • 增量测试是验证渠道真实价值的黄金标准，去除自然转化和交叉影响
