群组分析与留存建模

核心概念

群组分析（Cohort Analysis）是电商数据分析中最强大的纵向分析方法。它将用户按共同特征（通常是首次购买时间）分组，追踪每个群组在后续时间段内的行为表现。与快照式指标（如「本月活跃用户数」）不同，群组分析能揭示用户行为随时间的演变趋势——这是判断业务健康度和预测未来表现的关键视角。

群组分析的核心价值在于消除「辛普森悖论」的影响。整体留存率上升可能掩盖了一个问题：不是老用户的留存在改善，而是新用户中有更高比例的高活跃用户。群组分析能将这两种情况区分开来。

留存率计算与曲线分析
留存率是群组分析最核心的指标。N 日留存率（Day-N Retention）定义为：在特定时间群组中，第 N 天仍然活跃的用户占群组总用户的比例。「活跃」的定义因场景而异——电商中通常定义为「有浏览或购买行为」。


interface RetentionConfig {
  cohortType: 'daily' | 'weekly' | 'monthly';
  activityDefinition: 'any_visit' | 'product_view' | 'purchase';
  maxPeriods: number;
  minCohortSize: number;
}

interface RetentionTable {
  cohortPeriod: string;
  cohortSize: number;
  retentionByPeriod: Array<{
    periodOffset: number;
    activeUsers: number;
    retentionRate: number;
  }>;
}

function calculateRetentionTable(
  users: Array<{ userId: string; cohortPeriod: string; activePeriods: string[] }>,
  config: RetentionConfig,
): RetentionTable[] {
  const cohorts = new Map<string, Array<{ userId: string; activePeriods: Set<string> }>>();

  for (const user of users) {
    if (!cohorts.has(user.cohortPeriod)) cohorts.set(user.cohortPeriod, []);
    cohorts.get(user.cohortPeriod)!.push({
      userId: user.userId,
      activePeriods: new Set(user.activePeriods),
    });
  }

  const results: RetentionTable[] = [];
  for (const [period, members] of cohorts) {
    if (members.length < config.minCohortSize) continue;

    const retentionByPeriod: RetentionTable['retentionByPeriod'] = [];
    for (let offset = 0; offset <= config.maxPeriods; offset++) {
      const targetPeriod = addPeriods(period, offset, config.cohortType);
      const activeCount = members.filter((m) => m.activePeriods.has(targetPeriod)).length;

      retentionByPeriod.push({
        periodOffset: offset,
        activeUsers: activeCount,
        retentionRate: activeCount / members.length,
      });
    }

    results.push({ cohortPeriod: period, cohortSize: members.length, retentionByPeriod });
  }

  return results;
}

function addPeriods(period: string, offset: number, type: string): string {
  const date = new Date(period);
  if (type === 'daily') date.setDate(date.getDate() + offset);
  else if (type === 'weekly') date.setDate(date.getDate() + offset * 7);
  else date.setMonth(date.getMonth() + offset);
  return date.toISOString().slice(0, 10);
}
健康的电商留存曲线呈「快速下降 → 趋于稳定」的 L 形。首月留存率通常在 20-40%（大量一次性用户流失），6 个月后趋于稳定在 10-20%。如果曲线持续下降不趋稳，说明产品缺乏核心留存力；如果不同月份群组的曲线差异很大，说明产品或运营策略的变化对用户留存有显著影响。


流失预测模型
流失预测（Churn Prediction）通过分析用户的行为模式，在用户真正流失前识别出高风险用户，从而有针对性地进行挽留干预。电商的流失定义通常是「超过 N 天未产生任何活跃行为」，N 的选择取决于品类特征——高频品类（食品日化）N = 30 天，低频品类（家电数码）N = 90 天。


interface ChurnFeatures {
  userId: string;
  daysSinceLastVisit: number;
  daysSinceLastPurchase: number;
  visitFrequencyDecline: number;
  purchaseFrequencyDecline: number;
  avgSessionDurationTrend: number;
  cartAbandonmentRate: number;
  recentSearchCount: number;
  recentBrowseCount: number;
  daysSinceLastAppOpen: number;
  pushNotificationOpenRate: number;
  couponRedemptionRate: number;
  customerServiceContacts: number;
}

interface ChurnPrediction {
  userId: string;
  churnProbability: number;
  riskLevel: 'low' | 'medium' | 'high' | 'critical';
  topRiskFactors: Array<{ factor: string; weight: number }>;
  recommendedAction: string;
  expectedResponseRate: number;
}

function predictChurn(features: ChurnFeatures): ChurnPrediction {
  const riskSignals = [
    { factor: '最近访问间隔', weight: features.daysSinceLastVisit > 30 ? 0.3 : 0.05 },
    { factor: '访问频率下降', weight: features.visitFrequencyDecline > 0.5 ? 0.25 : 0.05 },
    { factor: '购买频率下降', weight: features.purchaseFrequencyDecline > 0.5 ? 0.2 : 0.05 },
    { factor: '购物车放弃率', weight: features.cartAbandonmentRate > 0.7 ? 0.15 : 0.05 },
    { factor: '推送打开率低', weight: features.pushNotificationOpenRate < 0.05 ? 0.1 : 0.02 },
  ];

  const churnProbability = Math.min(
    1,
    riskSignals.reduce((sum, s) => sum + s.weight, 0),
  );
  const riskLevel =
    churnProbability >= 0.8
      ? 'critical'
      : churnProbability >= 0.6
        ? 'high'
        : churnProbability >= 0.3
          ? 'medium'
          : 'low';

  const topFactors = riskSignals.sort((a, b) => b.weight - a.weight).slice(0, 3);
  const action =
    riskLevel === 'critical'
      ? '发送高额优惠券 + 专属客服触达'
      : riskLevel === 'high'
        ? '发送中额优惠券 + Push 推送'
        : riskLevel === 'medium'
          ? '个性化推荐邮件'
          : '常规运营触达';

  return {
    userId: features.userId,
    churnProbability,
    riskLevel,
    topRiskFactors: topFactors,
    recommendedAction: action,
    expectedResponseRate: riskLevel === 'critical' ? 0.05 : riskLevel === 'high' ? 0.1 : 0.2,
  };
}
流失预测模型的训练数据需要特别处理时间窗口。观察窗口（用于提取特征的时间段）和预测窗口（预测用户是否在此期间流失）必须严格分开，否则会产生数据泄漏。典型的设置是用过去 30 天的行为数据预测未来 30 天是否流失。


留存提升策略与生命周期管理
用户生命周期管理将用户划分为新手期、成长期、成熟期、沉默期和流失期五个阶段，针对每个阶段设计差异化的运营策略。留存提升的核心思想是在用户进入沉默期之前进行干预。

留存提升的效果评估需要严格的实验设计。发送挽留优惠券后，不能简单地用「收到优惠券后有购买行为的用户比例」来衡量效果——这些用户中有一部分即使不收到优惠券也会购买。正确的评估方法是通过随机对照实验（RCT）比较发送组和不发送组的购买率差异，只有差异部分才是优惠券真正带来的增量。


小结
    

  • 群组分析按共同特征将用户分组纵向追踪，消除辛普森悖论，揭示真实的留存趋势
    • 

  • 留存率计算需要明确活跃定义和群组周期，健康的留存曲线呈 L 形最终趋稳
    • 

  • 流失预测模型通过行为特征在用户真正流失前识别高风险用户，观察窗口和预测窗口必须严格分离
    • 

  • 用户生命周期分为新手、成长、成熟、沉默、流失五个阶段，在沉默期之前干预是关键
    • 

  • 留存策略的效果评估必须通过随机对照实验，避免自然回归导致的效果高估
