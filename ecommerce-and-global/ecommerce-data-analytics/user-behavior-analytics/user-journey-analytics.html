用户旅程与行为追踪

核心概念

用户旅程（User Journey）是用户在电商平台上从第一次触达到完成购买、再到复购或流失的完整行为路径。行为追踪（Behavioral Tracking）是捕获和记录用户在平台上每一个操作的技术体系。二者结合构成了电商数据分析的基础数据层——没有精确的行为数据，所有的分析和优化都是空中楼阁。

电商用户旅程不是线性的——用户可能从搜索引擎进入查看某个商品后离开，三天后通过 App 推送回来加入购物车，一周后在大促时完成支付。完整的旅程追踪需要跨设备、跨渠道、跨会话地将用户的所有触点串联起来。

事件追踪体系设计
电商事件追踪体系定义了哪些用户行为需要被记录、以什么格式记录、以及如何保证数据质量。一套完善的事件体系通常包含 50-200 种事件类型，覆盖浏览、交互、交易和系统事件四大类。

数据采集方案通常分为三种模式：代码埋点（手动在关键位置添加采集代码）、可视化埋点（通过可视化工具圈选页面元素自动生成采集代码）和无埋点/全量采集（自动记录所有用户交互事件）。电商平台通常采用混合模式：核心业务事件用代码埋点保证精确性，辅助分析事件用无埋点覆盖。

  mode: 'code' | 'visual' | 'auto' | 'hybrid';
  autoTrackEvents: string[];
  codeTrackEvents: string[];
  samplingRate: number;
  batchSize: number;
  flushInterval: number;
  maxRetries: number;
}

const trackingConfig: TrackingConfig = {
  mode: 'hybrid',
  autoTrackEvents: ['page_view', 'click', 'scroll', 'visible'],
  codeTrackEvents: ['add_to_cart', 'purchase', 'search', 'sign_up'],
  samplingRate: 1.0,
  batchSize: 20,
  flushInterval: 5000,
  maxRetries: 3,
};

class EventTracker {
  private queue: Array<Record<string, unknown>> = [];
  private config: TrackingConfig;

  constructor(config: TrackingConfig) {
    this.config = config;
    this.startFlushTimer();
  }

  track(eventName: string, properties: Record<string, unknown>): void {
    if (Math.random() > this.config.samplingRate) return;
    const event = {
      event: eventName,
      ...properties,
      timestamp: Date.now(),
      session_id: this.getSessionId(),
      user_id: this.getUserId(),
      device_id: this.getDeviceId(),
    };
    this.queue.push(event);
    if (this.queue.length >= this.config.batchSize) this.flush();
  }

  private flush(): void {
    if (this.queue.length === 0) return;
    const batch = this.queue.splice(0, this.queue.length);
    navigator.sendBeacon('/api/collect', JSON.stringify(batch));
  }

  private startFlushTimer(): void {
    setInterval(() => this.flush(), this.config.flushInterval);
  }

  private getSessionId(): string {
    return 'session_placeholder';
  }
  private getUserId(): string {
    return 'user_placeholder';
  }
  private getDeviceId(): string {
    return 'device_placeholder';
  }
}

热力图与会话回放
热力图（Heatmap）将用户在页面上的点击、滚动和注意力分布可视化。电商场景中，热力图帮助发现页面设计问题：重要的促销信息是否被用户看到、加购按钮的点击密度如何、用户滚动到页面哪个位置就停止了。

会话回放能逐帧还原用户的操作过程，是定位可用性问题的最直观工具。但需要注意隐私合规：输入框的内容需要脱敏处理，密码字段禁止录制，回放数据的存储需要符合 GDPR 要求。


跨设备与跨渠道用户识别
电商用户在多个设备（手机、电脑、平板）和多个渠道（App、小程序、H5、线下门店）之间切换，准确识别同一用户的跨设备行为是数据分析的基础挑战。如果无法关联，一个用户可能被计为多个独立用户，DAU 被虚高，转化率被低估。

interface UserIdentityGraph {
  canonicalUserId: string;
  identities: Array<{
    type: 'login' | 'device_id' | 'cookie' | 'email' | 'phone' | 'wechat_openid';
    value: string;
    firstSeen: Date;
    lastSeen: Date;
    confidence: number;
  }>;
  deviceHistory: Array<{
    deviceId: string;
    deviceType: string;
    os: string;
    firstSeen: Date;
    lastSeen: Date;
    sessionCount: number;
  }>;
}

function mergeUserIdentities(
  identityPairs: Array<{ idA: string; typeA: string; idB: string; typeB: string; confidence: number }>,
): Map<string, string[]> {
  const graph = new Map<string, Set<string>>();

  for (const pair of identityPairs) {
    const keyA = `${pair.typeA}:${pair.idA}`;
    const keyB = `${pair.typeB}:${pair.idB}`;
    if (!graph.has(keyA)) graph.set(keyA, new Set());
    if (!graph.has(keyB)) graph.set(keyB, new Set());
    if (pair.confidence > 0.8) {
      graph.get(keyA)!.add(keyB);
      graph.get(keyB)!.add(keyA);
    }
  }

  const visited = new Set<string>();
  const clusters = new Map<string, string[]>();
  let clusterId = 0;

  for (const node of graph.keys()) {
    if (visited.has(node)) continue;
    const cluster: string[] = [];
    const queue = [node];
    while (queue.length > 0) {
      const current = queue.shift()!;
      if (visited.has(current)) continue;
      visited.add(current);
      cluster.push(current);
      for (const neighbor of graph.get(current) ?? []) {
        if (!visited.has(neighbor)) queue.push(neighbor);
      }
    }
    clusters.set(`user_${clusterId++}`, cluster);
  }

  return clusters;
}
ID 图谱的构建是一个持续迭代的过程。当用户在手机上登录后，手机的设备 ID 与用户账号关联；当该用户在电脑上登录同一账号，电脑的 Cookie ID 也被关联。通过传递性关系，手机设备 ID 和电脑 Cookie ID 被间接关联到同一用户。
