客户生命周期价值分析

核心概念

客户生命周期价值（LTV，Lifetime Value，又称 CLV — Customer Lifetime Value）是衡量单个客户在整个与平台关系存续期间为企业创造的总利润。LTV 是电商最重要的战略级指标之一，它将客户从「一次性交易对象」提升为「长期资产」，驱动企业从追求短期 GMV 转向构建长期客户关系。

LTV 分析在电商运营中有三个核心应用：评估获客渠道的 ROI（LTV/CAC 比值）、指导用户分层运营策略（高 LTV 用户享受 VIP 服务）、以及预测业务的长期财务健康度。

历史 LTV 计算方法
历史 LTV 基于客户过去的实际消费数据计算，是最直观也是最基础的计算方法。简单历史 LTV = 总消费金额 × 毛利率；更精确的版本考虑货币的时间价值，引入折现率将未来收益折算为现值。


interface CustomerTransactionHistory {
  userId: string;
  transactions: Array<{
    orderId: string;
    amount: number;
    profit: number;
    date: Date;
    category: string;
  }>;
  firstPurchaseDate: Date;
  lastPurchaseDate: Date;
}

interface HistoricalLtv {
  userId: string;
  totalRevenue: number;
  totalProfit: number;
  orderCount: number;
  avgOrderValue: number;
  avgOrderProfit: number;
  customerLifespanDays: number;
  monthlyRevenue: number;
  simpleLtv: number;
  discountedLtv: number;
}

function calculateHistoricalLtv(customer: CustomerTransactionHistory, discountRate: number = 0.1): HistoricalLtv {
  const totalRevenue = customer.transactions.reduce((sum, t) => sum + t.amount, 0);
  const totalProfit = customer.transactions.reduce((sum, t) => sum + t.profit, 0);
  const orderCount = customer.transactions.length;
  const lifespanDays = Math.max(
    1,
    (customer.lastPurchaseDate.getTime() - customer.firstPurchaseDate.getTime()) / 86400000,
  );
  const lifespanMonths = lifespanDays / 30;

  const monthlyDiscount = discountRate / 12;
  let discountedProfit = 0;
  for (const transaction of customer.transactions) {
    const monthsSinceFirst = (transaction.date.getTime() - customer.firstPurchaseDate.getTime()) / (30 * 86400000);
    discountedProfit += transaction.profit / Math.pow(1 + monthlyDiscount, monthsSinceFirst);
  }

  return {
    userId: customer.userId,
    totalRevenue,
    totalProfit,
    orderCount,
    avgOrderValue: totalRevenue / orderCount,
    avgOrderProfit: totalProfit / orderCount,
    customerLifespanDays: lifespanDays,
    monthlyRevenue: totalRevenue / Math.max(1, lifespanMonths),
    simpleLtv: totalProfit,
    discountedLtv: discountedProfit,
  };
}
历史 LTV 的局限在于它只能评估已发生的价值，无法预测未来。一个上个月刚注册的新客户历史 LTV 很低，但如果其行为模式与高价值老客户相似，未来可能贡献很大价值。因此需要引入预测模型来估算客户的未来价值。


群组 LTV 分析
群组分析（Cohort Analysis）将客户按首次购买时间分组，追踪每个群组在后续月份的消费表现。群组 LTV 曲线能揭示客户价值随时间的累积轨迹，帮助判断不同获客批次的质量差异和复购模式变化。


interface CohortLtvData {
  cohortMonth: string;
  cohortSize: number;
  monthlyData: Array<{
    monthOffset: number;
    activeUsers: number;
    revenue: number;
    orders: number;
    cumulativeRevenue: number;
    cumulativeLtv: number;
    retentionRate: number;
  }>;
}

function buildCohortLtvTable(
  customers: CustomerTransactionHistory[],
  startMonth: string,
  months: number,
): CohortLtvData[] {
  const cohorts = new Map<string, CustomerTransactionHistory[]>();

  for (const customer of customers) {
    const cohortKey = formatMonth(customer.firstPurchaseDate);
    if (!cohorts.has(cohortKey)) cohorts.set(cohortKey, []);
    cohorts.get(cohortKey)!.push(customer);
  }

  const results: CohortLtvData[] = [];
  for (const [cohortMonth, members] of cohorts) {
    if (cohortMonth < startMonth) continue;
    const cohortStart = parseMonth(cohortMonth);
    const monthlyData: CohortLtvData['monthlyData'] = [];
    let cumulativeRevenue = 0;

    for (let offset = 0; offset < months; offset++) {
      const monthStart = addMonths(cohortStart, offset);
      const monthEnd = addMonths(cohortStart, offset + 1);

      let activeUsers = 0;
      let revenue = 0;
      let orders = 0;

      for (const member of members) {
        const monthTransactions = member.transactions.filter((t) => t.date >= monthStart && t.date < monthEnd);
        if (monthTransactions.length > 0) {
          activeUsers++;
          revenue += monthTransactions.reduce((s, t) => s + t.amount, 0);
          orders += monthTransactions.length;
        }
      }

      cumulativeRevenue += revenue;
      monthlyData.push({
        monthOffset: offset,
        activeUsers,
        revenue,
        orders,
        cumulativeRevenue,
        cumulativeLtv: cumulativeRevenue / members.length,
        retentionRate: activeUsers / members.length,
      });
    }

    results.push({ cohortMonth, cohortSize: members.length, monthlyData });
  }
  return results;
}

function formatMonth(date: Date): string {
  return `${date.getFullYear()}-${String(date.getMonth() + 1).padStart(2, '0')}`;
}
function parseMonth(month: string): Date {
  return new Date(`${month}-01`);
}
function addMonths(date: Date, months: number): Date {
  const result = new Date(date);
  result.setMonth(result.getMonth() + months);
  return result;
}
群组 LTV 曲线的典型特征是「快速增长 → 减速 → 趋平」：客户在前 3 个月的消费增长最快（新鲜期），3-12 个月逐步减速（稳定期），12 个月后趋于稳定（成熟期）。如果某个群组的曲线在早期就趋平，说明复购率不足，需要加强留存运营。


BG/NBD 概率预测模型
BG/NBD（Beta-Geometric/Negative Binomial Distribution）模型是电商 LTV 预测的经典概率模型，专门针对非合约型（non-contractual）业务场景——用户可以随时沉默（流失）而不需要显式取消订阅。


BG/NBD 模型基于两个核心假设：活跃客户的购买行为服从泊松过程（购买间隔是随机的），客户的流失时间服从几何分布（每次购买后有一定概率永远离开）。模型的四个输入参数来自 RFM 框架：Recency（最近一次购买距今天数）、Frequency（历史购买次数）、T（客户关系持续天数）和 Monetary（平均每次消费金额）。


interface RfmFeatures {
  userId: string;
  recency: number;
  frequency: number;
  tenure: number;
  monetary: number;
}

interface LtvPrediction {
  userId: string;
  aliveProb: number;
  expectedPurchases: number;
  expectedMonetary: number;
  predictedLtv: number;
  confidenceInterval: { lower: number; upper: number };
  ltvSegment: 'high' | 'medium' | 'low' | 'at_risk';
}

function extractRfmFeatures(customer: CustomerTransactionHistory, asOfDate: Date): RfmFeatures {
  const recency = (asOfDate.getTime() - customer.lastPurchaseDate.getTime()) / 86400000;
  const frequency = customer.transactions.length - 1;
  const tenure = (asOfDate.getTime() - customer.firstPurchaseDate.getTime()) / 86400000;
  const monetary = customer.transactions.reduce((sum, t) => sum + t.amount, 0) / customer.transactions.length;
  return { userId: customer.userId, recency, frequency, tenure, monetary };
}

function segmentByLtv(
  predictions: LtvPrediction[],
  thresholds: { high: number; medium: number },
): Map<string, LtvPrediction[]> {
  const segments = new Map<string, LtvPrediction[]>();
  for (const pred of predictions) {
    if (pred.predictedLtv >= thresholds.high) pred.ltvSegment = 'high';
    else if (pred.predictedLtv >= thresholds.medium) pred.ltvSegment = 'medium';
    else if (pred.aliveProb < 0.3) pred.ltvSegment = 'at_risk';
    else pred.ltvSegment = 'low';

    if (!segments.has(pred.ltvSegment)) segments.set(pred.ltvSegment, []);
    segments.get(pred.ltvSegment)!.push(pred);
  }
  return segments;
}
LTV 驱动的运营策略
LTV 分析的最终目的是指导差异化运营策略。高 LTV 用户需要 VIP 服务保持忠诚度，中 LTV 用户需要激励提升消费等级，低 LTV 用户需要控制获客成本，「沉睡」用户需要唤醒营销。

LTV/CAC 比值是评估获客渠道质量的黄金指标。如果某个渠道的 LTV/CAC < 1，意味着这个渠道获取的客户终身价值无法覆盖获客成本。健康的电商业务 LTV/CAC 应 ≥ 3，即客户终身价值是获客成本的 3 倍以上。


小结
    

  • LTV 将客户视为长期资产，驱动企业从短期 GMV 导向转为长期客户关系导向
    • 

  • 历史 LTV 基于实际消费计算，群组 LTV 追踪不同批次客户的价值累积轨迹
    • 

  • BG/NBD 概率模型专为非合约型电商设计，基于 RFM 特征预测存活概率和未来购买次数
    • 

  • LTV 分层运营将客户分为高价值、成长型、大众型和沉睡用户，差异化分配运营资源
    • 

  • LTV/CAC ≥ 3 是业务健康的基准线，指导获客渠道的投入产出评估
