电商数据仓库设计

核心概念

数据仓库（Data Warehouse）是电商企业进行数据分析的核心基础设施。它将分散在订单系统、用户系统、商品系统、支付系统等多个业务数据库中的数据，经过抽取、清洗、转换后统一存储在面向分析的结构化存储中。与业务数据库面向事务处理（OLTP）不同，数据仓库面向联机分析处理（OLAP），为报表、指标计算、用户画像、推荐系统等下游场景提供高效查询能力。

电商数据仓库的核心挑战在于：数据量大（每天数亿条行为日志）、数据源多（几十个业务系统）、时效性要求高（大促期间需要分钟级别的 GMV 刷新）、维度复杂（商品有品类、品牌、规格等多级维度）。

维度建模方法论
维度建模是数据仓库设计的核心方法论，由 Ralph Kimball 提出。它围绕"事实"和"维度"两个核心概念组织数据。事实表（Fact Table）记录业务过程中的度量值（如订单金额、数量），维度表（Dimension Table）描述分析的角度（如时间、商品、用户、渠道）。


电商场景中，最核心的事实表是订单事实表。围绕订单，可以从时间、用户、商品、店铺、渠道、地域等多个维度切入分析。


星型模型（Star Schema）中，事实表通过外键直接关联维度表，查询时只需一次 JOIN。雪花模型（Snowflake Schema）将维度表进一步归一化（如商品→品类→一级类目），减少冗余但增加 JOIN 次数。电商实践中通常采用星型模型，牺牲少量存储换取查询性能。

数仓分层架构
电商数据仓库通常采用 ODS → DWD → DWS → ADS 四层架构。每一层有明确的职责边界，层与层之间通过 ETL/ELT 任务连接。


ODS 贴源层（Operational Data Store）：原始数据的镜像，保持与源系统一致的结构。通过 Binlog 同步（MySQL CDC）、API 拉取、日志采集等方式导入。ODS 层不做任何清洗和转换，保证数据可追溯。


DWD 明细层（Data Warehouse Detail）：对 ODS 数据进行清洗（去重、空值处理、格式统一）、维度关联（将业务键替换为维度键）、数据标准化。DWD 是最细粒度的分析数据，每一行对应一个业务事件。


DWS 汇总层（Data Warehouse Summary）：按主题域预聚合。例如按天、按用户汇总订单金额；按商品汇总浏览次数和转化率。DWS 层的设计取决于下游分析需求，通常按"谁+什么时候+做了什么"的模式建表。


ADS 应用层（Application Data Store）：面向具体应用场景的数据集。如 BI 看板的宽表、推荐系统的特征表、用户画像的标签表。ADS 层直接服务终端消费者。

分层设计的核心价值在于：复用（DWD/DWS 供多个 ADS 使用）、一致性（相同指标只在一个层计算）、可维护性（上游变更只影响相邻层）。


ETL 与 ELT 管道设计
ETL（Extract-Transform-Load）和 ELT（Extract-Load-Transform）是数据仓库的两种主要数据加工模式。传统 ETL 在数据加载前完成转换，适合数据量可控的场景。现代 ELT 先将原始数据加载到数仓，再利用仓库自身的计算能力做转换，适合大数据量场景。


电商场景的数据管道通常包含以下环节：

数据质量保障是 ETL 管道的关键。每个任务执行后需要进行数据质量检查：行数校验（与源表对比）、空值率检查（关键字段不能超过阈值）、唯一性检查（主键不重复）、时效性检查（数据是否按时到达）。

任务调度采用 DAG（有向无环图）模式。上游表就绪后触发下游任务，确保依赖关系正确。Airflow、DolphinScheduler 是主流的调度引擎。大促期间需要提前预估数据量增长，调整并行度和资源分配。


电商数仓主题域划分
电商数据仓库按业务域划分主题，每个主题域包含完整的事实表和维度表。主题域的划分直接影响数仓的可维护性和分析灵活性。


交易域：核心主题，包括订单事实表、退款事实表、支付事实表。关联时间、用户、商品、店铺、渠道维度。支撑 GMV、客单价、退款率等核心指标。


流量域：页面浏览事实表、搜索事实表、点击事实表。关联时间、用户、页面、设备维度。支撑 PV/UV、跳出率、搜索转化率等流量指标。


营销域：优惠券使用事实表、促销活动事实表、广告投放事实表。关联时间、用户、活动、渠道维度。支撑 ROI、优惠券核销率、活动转化率等营销指标。


供应链域：库存快照事实表、物流事实表、采购事实表。关联时间、商品、仓库、供应商维度。支撑库存周转率、缺货率、配送时效等运营指标。

主题域之间通过共享维度表（Conformed Dimension）实现跨域分析。例如时间维度和用户维度在所有主题域中保持一致的定义和粒度，使得"某用户在某天通过某个营销活动购买了某个商品"这样的跨域查询成为可能。


小结
    

  • 数据仓库是电商数据分析的基础设施，核心解决多源异构数据的统一存储和高效分析问题
    • 

  • 维度建模（星型/雪花模型）是数仓设计的核心方法论，围绕事实表和维度表组织数据
    • 

  • 分层架构（ODS → DWD → DWS → ADS）确保数据复用、一致性和可维护性
    • 

  • ETL/ELT 管道需要完善的数据质量保障机制，覆盖完整性、准确性、一致性、及时性和唯一性
    • 

  • 主题域划分（交易、流量、营销、供应链）决定数仓的分析能力边界
    • 

  • 共享维度表（Conformed Dimension）是跨主题域分析的关键，保证指标口径统一
    •
