行业特定隐私规则

核心概念

通用数据保护法律（如 GDPR、PIPL）为个人数据处理设定了基线标准，但特定行业因其数据类型的特殊性、处理活动的高风险性或公共利益的重要性，往往需要更严格或更具体的规则。行业特定隐私规则可以理解为"基线之上的叠加层"——它们不取代通用法律，而是在通用法律的框架内增加额外的要求和限制。

对于技术团队而言，行业特定规则的实务影响在于：同一套数据处理系统，在不同行业场景下可能需要满足完全不同的合规标准。健康数据的处理、金融数据的共享、儿童数据的收集，各自有独立的规则体系和监管机构。

行业领域 代表性法规 核心关注 特殊要求
医疗健康 HIPAA（美国）、GDPR 第9条 健康数据的高敏感性 去标识化标准、最小必要原则、审计追踪
金融服务 GLBA（美国）、PSD2（欧盟） 金融数据安全与消费者保护 数据共享规则、Open Banking 标准
儿童保护 COPPA（美国）、UK Age Code 未成年人认知能力有限 家长同意、年龄验证、默认高保护
电信通信 ePrivacy 指令（欧盟） 通信秘密与追踪技术 Cookie 规则、元数据保护
广告与营销 PECR（英国）、CAN-SPAM 直接营销的干扰性 退出机制、发送者标识
员工数据 各国劳动法 + 隐私法 雇佣关系中的权力不平衡 知情权增强、监控限制

医疗健康数据保护

医疗健康数据是所有个人数据中敏感度最高的类别之一。一个人的疾病诊断、基因信息、心理健康记录一旦泄露，可能导致就业歧视、保险拒保、社会偏见等不可逆的伤害。因此，全球隐私法律体系对健康数据的保护标准远高于一般个人数据。

美国 HIPAA 体系：健康保险可携带性和责任法案（HIPAA）是美国医疗数据保护的基石。它适用于"受保护实体"（Covered Entities）——包括医疗服务提供者、健康保险计划和医疗信息交换中心——及其"业务伙伴"（Business Associates）。HIPAA 的核心要求包括：

  • 隐私规则（Privacy Rule）：规定受保护的健康信息（PHI）的使用和披露条件。关键原则是"最小必要"——实体只能使用或披露完成特定目的所必需的最少信息量。
  • 安全规则（Security Rule）：为电子 PHI（ePHI）设定管理、物理和技术保护标准。要求实施风险分析、访问控制、审计日志、加密传输等措施。
  • 泄露通知规则：要求在发现涉及未加密 PHI 的安全事件后60天内通知受影响的个人和 HHS。

GDPR 下的健康数据：GDPR 第9条将健康数据归类为"特殊类别个人数据"，原则上禁止处理，除非满足第9(2)条列举的例外条件（如数据主体的显式同意、公共卫生领域的重大利益、预防医学或职业医学目的等）。

对比维度 HIPAA GDPR 第9条
适用范围 受保护实体及其业务伙伴 所有处理健康数据的控制者和处理者
核心原则 最小必要、PHI 使用限制 显式同意 + 额外法律依据
去标识化标准 专家认定法或安全港方法（18项标识符） 无统一去标识化标准，参照 WP29 匿名化意见
泄露通知 60天内通知 HHS 和个人 72小时内通知监管机构
患者权利 获取和修改 PHI 的权利 完整的 GDPR 数据主体权利

金融数据保护与 Open Banking

金融数据的保护面临双重压力：一方面需要保护消费者的财务隐私，另一方面需要促进金融创新和竞争——这正是 Open Banking 运动的核心张力。

美国的 GLBA（格拉姆-里奇-布莱利法案）要求金融机构保护消费者的非公开个人信息（NPI），包括发布隐私通知、提供退出数据共享的选择权，以及实施保障措施保护信息安全。

欧盟的 PSD2（第二支付服务指令）则走得更远——它不仅保护数据，还要求银行向经授权的第三方支付服务提供商开放客户账户数据（在客户明确同意的前提下）。这催生了 Open Banking 生态：金融科技公司可以通过标准化 API 获取银行数据，为消费者提供账户聚合、智能理财、便捷支付等服务。

维度 传统金融数据保护 Open Banking 模式
数据流向 金融机构内部保留 在客户授权下向第三方流动
控制权归属 金融机构主导 消费者主导（数据可携带）
监管逻辑 限制数据共享以保护安全 促进数据共享以增进竞争
同意模型 退出机制（opt-out） 主动授权（opt-in）
安全标准 金融行业安全标准（如 PCI DSS） API 安全 + 强客户认证（SCA）

儿童数据保护

儿童数据保护是全球隐私执法中增长最快的领域之一。监管机构的共识是：儿童的认知发展水平使其无法像成年人一样理解数据处理的含义和后果，因此需要更高水平的保护。

美国 COPPA：儿童在线隐私保护法适用于面向13岁以下儿童的在线服务，或明知收集13岁以下儿童个人信息的运营商。核心要求包括：在收集前获得可验证的家长同意（Verifiable Parental Consent）、提供清晰的隐私通知、允许家长审查和删除儿童数据、不以数据收集作为参与活动的条件。

英国 Age Appropriate Design Code（儿童守则）：这是全球最具影响力的儿童数据保护设计标准。它要求面向可能被儿童访问的在线服务遵守15项设计原则，包括：默认最高隐私设置、地理定位默认关闭、禁止使用"nudge techniques"引导儿童降低隐私设置、在设计阶段考虑儿童的最大利益。

法规 年龄范围 同意机制 设计要求 执法
COPPA（美国） <13岁 可验证的家长同意 无具体设计要求 FTC 执法
UK Age Code <18岁 年龄适当的告知 + 家长参与 15项设计原则 ICO 执法
GDPR（欧盟） 13-16岁（各国不同） 家长同意或授权 Privacy by Design 各国 DPA
PIPL（中国） <14岁 监护人单独同意 专门的个人信息处理规则 网信办

常见误区

误区 正确理解
HIPAA 适用于所有处理健康数据的组织 HIPAA 仅适用于受保护实体及其业务伙伴，健身 App 等不在范围内（除非另有州法规制）
Open Banking 意味着银行必须无条件共享数据 数据共享以客户的明确授权为前提，且仅限于经监管审批的第三方
只有专门面向儿童的应用才需要遵守 COPPA 如果运营商"实际知道"其用户中包含13岁以下儿童，同样适用
金融数据加密后就满足了 GLBA 要求 GLBA 要求全面的安全保障计划，加密只是技术措施之一
行业法规覆盖了通用隐私法的所有要求 行业法规是叠加层而非替代品，通用法律的义务仍需独立满足

小结

  • 行业特定隐私规则是通用数据保护法律之上的叠加层，为高敏感或高风险的数据处理场景提供更严格的标准
  • 医疗健康数据保护以 HIPAA 和 GDPR 第9条为代表，核心是最小必要原则和严格的处理限制
  • 金融数据保护在传统的安全保护之外引入了 Open Banking 模式，数据控制权从机构向消费者转移
  • 儿童数据保护是全球执法增长最快的领域，英国 Age Appropriate Design Code 设定了设计标准的新基线
  • 技术团队需要针对具体行业场景叠加合规要求，不能仅依赖通用法律的基线标准
