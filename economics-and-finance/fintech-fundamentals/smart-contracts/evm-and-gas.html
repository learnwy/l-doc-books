EVM 与 Gas 机制

核心概念

以太坊虚拟机（Ethereum Virtual Machine，EVM）是以太坊智能合约的执行引擎，它是一个基于栈的虚拟机，所有以太坊节点都运行相同的 EVM 实例来确保交易执行结果的确定性。Gas 机制是 EVM 的经济调节器——每个操作码（Opcode）消耗固定数量的 Gas，用户必须为交易支付足够的 Gas 费用，防止网络被无限循环或资源滥用攻击。

理解 EVM 的内部机制对于智能合约的 Gas 优化、安全审计和底层调试至关重要。EVM 兼容性也成为新兴区块链的重要特性，BSC、Polygon、Avalanche 等链都实现了 EVM 兼容层。

操作码与执行模型
EVM 定义了约 140 个操作码，涵盖算术运算、逻辑运算、栈操作、内存操作、存储操作、控制流和环境信息获取等类别。每个操作码消耗特定数量的 Gas，这些 Gas 成本在以太坊黄皮书和后续 EIP 中精确定义。

interface EVMState {
  stack: bigint[];
  memory: Uint8Array;
  storage: Map<string, string>;
  pc: number;
  gas: bigint;
  returnData: Uint8Array;
}

class SimpleEVM {
  private state: EVMState;
  private bytecode: Uint8Array;

  constructor(bytecode: Uint8Array, gasLimit: bigint) {
    this.bytecode = bytecode;
    this.state = {
      stack: [],
      memory: new Uint8Array(0),
      storage: new Map(),
      pc: 0,
      gas: gasLimit,
      returnData: new Uint8Array(0),
    };
  }

  step(): boolean {
    if (this.state.pc >= this.bytecode.length) return false;

    const opcode = this.bytecode[this.state.pc];

    switch (opcode) {
      case 0x00:
        return false;
      case 0x01: {
        const a = this.state.stack.pop()!;
        const b = this.state.stack.pop()!;
        this.state.stack.push((a + b) % 2n ** 256n);
        this.consumeGas(3n);
        break;
      }
      case 0x02: {
        const a = this.state.stack.pop()!;
        const b = this.state.stack.pop()!;
        this.state.stack.push((a * b) % 2n ** 256n);
        this.consumeGas(5n);
        break;
      }
      case 0x60: {
        const value = BigInt(this.bytecode[this.state.pc + 1]);
        this.state.stack.push(value);
        this.state.pc += 1;
        this.consumeGas(3n);
        break;
      }
      default:
        throw new Error(`Unknown opcode: 0x${opcode.toString(16)}`);
    }

    this.state.pc += 1;
    return true;
  }

  private consumeGas(amount: bigint): void {
    if (this.state.gas < amount) {
      throw new Error('Out of gas');
    }
    this.state.gas -= amount;
  }

  getGasUsed(initialGas: bigint): bigint {
    return initialGas - this.state.gas;
  }
}
EIP-1559 费用市场
EIP-1559 彻底改革了以太坊的 Gas 费用机制，引入了基础费用（Base Fee）和优先费用（Priority Fee/Tip）的双层结构。基础费用根据网络拥堵程度自动调整并被销毁，优先费用支付给验证者作为激励。


interface EIP1559Transaction {
  maxFeePerGas: bigint;
  maxPriorityFeePerGas: bigint;
  gasLimit: bigint;
  to: string;
  value: bigint;
  data: string;
}

interface BlockFeeInfo {
  baseFeePerGas: bigint;
  gasUsed: bigint;
  gasLimit: bigint;
}

const calculateNextBaseFee = (parent: BlockFeeInfo): bigint => {
  const TARGET_GAS = parent.gasLimit / 2n;

  if (parent.gasUsed === TARGET_GAS) {
    return parent.baseFeePerGas;
  }

  if (parent.gasUsed > TARGET_GAS) {
    const delta = parent.gasUsed - TARGET_GAS;
    const adjustment = (parent.baseFeePerGas * delta) / TARGET_GAS / 8n;
    return parent.baseFeePerGas + (adjustment > 1n ? adjustment : 1n);
  }

  const delta = TARGET_GAS - parent.gasUsed;
  const adjustment = (parent.baseFeePerGas * delta) / TARGET_GAS / 8n;
  return parent.baseFeePerGas - adjustment;
};

const calculateEffectiveFee = (
  tx: EIP1559Transaction,
  baseFee: bigint,
): { effectiveGasPrice: bigint; burned: bigint; tip: bigint } => {
  const effectivePriorityFee =
    tx.maxFeePerGas - baseFee < tx.maxPriorityFeePerGas ? tx.maxFeePerGas - baseFee : tx.maxPriorityFeePerGas;

  return {
    effectiveGasPrice: baseFee + effectivePriorityFee,
    burned: baseFee,
    tip: effectivePriorityFee,
  };
};

const estimateTransactionCost = (
  gasUsed: bigint,
  baseFee: bigint,
  priorityFee: bigint,
  ethPrice: number,
): { gasWei: bigint; ethCost: number; usdCost: number } => {
  const gasWei = gasUsed * (baseFee + priorityFee);
  const ethCost = Number(gasWei) / 1e18;
  const usdCost = ethCost * ethPrice;

  return { gasWei, ethCost, usdCost };
};

存储布局与 Gas 优化
EVM 的存储模型是一个 2^256 大小的键值映射，每个存储槽（Slot）为 32 字节。Solidity 编译器按声明顺序依次分配存储槽，理解存储布局是 Gas 优化的关键。


// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract StorageLayout {
    uint256 public a;
    uint128 public b;
    uint128 public c;
    uint256 public d;
    address public e;
    uint96 public f;
}
interface StorageSlot {
  slot: number;
  offset: number;
  size: number;
  variable: string;
  type: string;
}

const analyzeStorageLayout = (
  variables: Array<{
    name: string;
    type: string;
    size: number;
  }>,
): StorageSlot[] => {
  const slots: StorageSlot[] = [];
  let currentSlot = 0;
  let currentOffset = 0;

  for (const variable of variables) {
    if (variable.size === 32 || currentOffset + variable.size > 32) {
      if (currentOffset > 0 && variable.size === 32) {
        currentSlot++;
        currentOffset = 0;
      } else if (currentOffset + variable.size > 32) {
        currentSlot++;
        currentOffset = 0;
      }
    }

    slots.push({
      slot: currentSlot,
      offset: currentOffset,
      size: variable.size,
      variable: variable.name,
      type: variable.type,
    });

    currentOffset += variable.size;
    if (currentOffset >= 32) {
      currentSlot++;
      currentOffset = 0;
    }
  }

  return slots;
};

const STORAGE_GAS_COSTS = {
  SLOAD_COLD: 2100,
  SLOAD_WARM: 100,
  SSTORE_SET: 20000,
  SSTORE_RESET: 2900,
  SSTORE_CLEAR_REFUND: 4800,
} as const;

const estimateStorageCost = (
  operations: Array<{
    type: 'read' | 'write';
    isWarm: boolean;
    fromZero: boolean;
  }>,
): number => {
  return operations.reduce((total, op) => {
    if (op.type === 'read') {
      return total + (op.isWarm ? STORAGE_GAS_COSTS.SLOAD_WARM : STORAGE_GAS_COSTS.SLOAD_COLD);
    }
    return total + (op.fromZero ? STORAGE_GAS_COSTS.SSTORE_SET : STORAGE_GAS_COSTS.SSTORE_RESET);
  }, 0);
};
EIP-2929 引入了"冷/热"访问概念：首次访问某个存储槽（冷访问）消耗 2100 Gas，同一交易中后续访问（热访问）仅消耗 100 Gas。这意味着将频繁访问的变量放在同一个存储槽中可以显著降低成本。


小结
    

  • EVM 是基于栈的确定性虚拟机，约 140 个操作码各有固定 Gas 消耗
    • 

  • EIP-1559 引入 Base Fee + Priority Fee 双层费用结构，Base Fee 被销毁
    • 

  • 存储操作是最昂贵的 EVM 操作（写入最高 20,000 Gas），优化存储布局是 Gas 优化的核心
    • 

  • 冷热访问机制（EIP-2929）使得首次存储访问成本是后续访问的 21 倍
    • 

  • EVM 兼容性成为新兴 L1/L2 的标配，理解 EVM 具有广泛的技术通用性
    • 

  • Gas 估算和费用预测对 DApp 用户体验至关重要
