订单类型与路由

核心概念

订单管理是量化交易执行层的入口，正确理解和使用不同订单类型直接影响策略的实际成交质量。订单类型决定了交易的执行方式、价格确定性和时间优先级之间的权衡。订单路由则决定了订单被发送到哪个交易所或暗池执行，影响成交速度、价格和信息泄露。

现代市场结构中，同一证券可能在多个交易所和暗池同时交易。智能订单路由（Smart Order Routing, SOR）通过算法选择最优执行场所，是量化交易系统的核心组件。

订单生命周期管理
从策略生成订单信号到最终成交确认，一笔订单经历多个状态转换。订单管理系统（OMS）需要跟踪每笔订单的完整生命周期，处理各种异常情况。


type OrderStatus =
  | 'created'
  | 'pending_submit'
  | 'submitted'
  | 'partially_filled'
  | 'filled'
  | 'cancelled'
  | 'rejected'
  | 'expired';

interface OrderState {
  orderId: string;
  symbol: string;
  side: 'buy' | 'sell';
  orderType: 'market' | 'limit' | 'stop' | 'stop_limit' | 'iceberg';
  quantity: number;
  filledQuantity: number;
  remainingQuantity: number;
  limitPrice?: number;
  stopPrice?: number;
  status: OrderStatus;
  createdAt: number;
  updatedAt: number;
  fills: FillRecord[];
  avgFillPrice: number;
  venue: string;
}

interface FillRecord {
  fillId: string;
  price: number;
  quantity: number;
  timestamp: number;
  venue: string;
  fee: number;
}

interface OrderManagementSystem {
  orders: Map<string, OrderState>;
  createOrder(params: CreateOrderParams): OrderState;
  submitOrder(orderId: string): Promise<SubmitResult>;
  cancelOrder(orderId: string): Promise<boolean>;
  onFill(fill: FillRecord): void;
  getOpenOrders(): OrderState[];
  getOrdersBySymbol(symbol: string): OrderState[];
}

interface CreateOrderParams {
  symbol: string;
  side: 'buy' | 'sell';
  orderType: OrderState['orderType'];
  quantity: number;
  limitPrice?: number;
  stopPrice?: number;
  timeInForce: 'GTC' | 'IOC' | 'FOK' | 'DAY';
  displayQuantity?: number;
}

interface SubmitResult {
  success: boolean;
  orderId: string;
  venue: string;
  error?: string;
}

const createOMS = (): OrderManagementSystem => {
  const orders = new Map<string, OrderState>();
  let nextId = 1;

  return {
    orders,
    createOrder: (params) => {
      const order: OrderState = {
        orderId: `ORD-${nextId++}`,
        symbol: params.symbol,
        side: params.side,
        orderType: params.orderType,
        quantity: params.quantity,
        filledQuantity: 0,
        remainingQuantity: params.quantity,
        limitPrice: params.limitPrice,
        stopPrice: params.stopPrice,
        status: 'created',
        createdAt: Date.now(),
        updatedAt: Date.now(),
        fills: [],
        avgFillPrice: 0,
        venue: '',
      };
      orders.set(order.orderId, order);
      return order;
    },
    submitOrder: async (orderId) => {
      const order = orders.get(orderId);
      if (!order) return { success: false, orderId, venue: '', error: 'not found' };
      order.status = 'submitted';
      order.updatedAt = Date.now();
      return { success: true, orderId, venue: 'primary' };
    },
    cancelOrder: async (orderId) => {
      const order = orders.get(orderId);
      if (!order || order.status === 'filled') return false;
      order.status = 'cancelled';
      order.updatedAt = Date.now();
      return true;
    },
    onFill: (fill) => {
      for (const [, order] of orders) {
        if (order.status === 'submitted' || order.status === 'partially_filled') {
          order.fills.push(fill);
          order.filledQuantity += fill.quantity;
          order.remainingQuantity -= fill.quantity;
          const totalCost = order.fills.reduce((s, f) => s + f.price * f.quantity, 0);
          order.avgFillPrice = totalCost / order.filledQuantity;
          order.status = order.remainingQuantity <= 0 ? 'filled' : 'partially_filled';
          order.updatedAt = Date.now();
          break;
        }
      }
    },
    getOpenOrders: () => [...orders.values()].filter((o) => ['submitted', 'partially_filled'].includes(o.status)),
    getOrdersBySymbol: (symbol) => [...orders.values()].filter((o) => o.symbol === symbol),
  };
};
智能订单路由
智能订单路由（SOR）是在多个执行场所之间寻找最优成交机会的算法。SOR 需要实时跟踪各场所的报价深度、延迟特性和费率结构，做出毫秒级的路由决策。


interface Venue {
  id: string;
  name: string;
  type: 'exchange' | 'dark_pool' | 'ats';
  makerFee: number;
  takerFee: number;
  latencyMs: number;
  minOrderSize: number;
}

interface VenueQuote {
  venueId: string;
  bidPrice: number;
  bidSize: number;
  askPrice: number;
  askSize: number;
  lastUpdated: number;
}

interface RoutingDecision {
  venue: string;
  quantity: number;
  expectedPrice: number;
  expectedCost: number;
  reason: string;
}

interface SmartOrderRouter {
  venues: Venue[];
  route(order: CreateOrderParams, quotes: VenueQuote[]): RoutingDecision[];
}

const createSOR = (venues: Venue[]): SmartOrderRouter => ({
  venues,
  route: (order, quotes) => {
    const decisions: RoutingDecision[] = [];
    let remaining = order.quantity;

    const sortedQuotes = [...quotes].sort((a, b) => {
      if (order.side === 'buy') return a.askPrice - b.askPrice;
      return b.bidPrice - a.bidPrice;
    });

    for (const quote of sortedQuotes) {
      if (remaining <= 0) break;
      const venue = venues.find((v) => v.id === quote.venueId);
      if (!venue) continue;

      const availableSize = order.side === 'buy' ? quote.askSize : quote.bidSize;
      const price = order.side === 'buy' ? quote.askPrice : quote.bidPrice;
      const fillQty = Math.min(remaining, availableSize);

      if (fillQty >= venue.minOrderSize) {
        const fee = fillQty * price * venue.takerFee;
        decisions.push({
          venue: venue.id,
          quantity: fillQty,
          expectedPrice: price,
          expectedCost: fillQty * price + fee,
          reason: `最优价格 ${price} @ ${venue.name}`,
        });
        remaining -= fillQty;
      }
    }

    return decisions;
  },
});
订单流分析与信息泄露
大额订单的执行面临信息泄露风险——当市场参与者识别到大额买入意图时，价格会提前上涨，增加执行成本。理解订单流动力学有助于设计更隐蔽的执行策略。


信息泄露的主要渠道包括：订单簿中的大额限价单暴露交易意图、频繁的小额市价单形成可识别的交易模式、以及同一方向的持续交易行为。


interface OrderFlowMetrics {
  orderImbalance: number;
  tradeIntensity: number;
  toxicFlowProbability: number;
  informationLeakageScore: number;
}

const calculateOrderImbalance = (
  trades: { price: number; volume: number; side: 'buy' | 'sell' }[],
  window: number,
): number => {
  const recent = trades.slice(-window);
  const buyVolume = recent.filter((t) => t.side === 'buy').reduce((s, t) => s + t.volume, 0);
  const sellVolume = recent.filter((t) => t.side === 'sell').reduce((s, t) => s + t.volume, 0);
  const totalVolume = buyVolume + sellVolume;
  return totalVolume > 0 ? (buyVolume - sellVolume) / totalVolume : 0;
};

const estimateVPIN = (trades: { volume: number; side: 'buy' | 'sell' }[], bucketSize: number): number => {
  let buyVolume = 0;
  let sellVolume = 0;
  let bucketCount = 0;
  let totalImbalance = 0;
  let currentVolume = 0;

  for (const trade of trades) {
    if (trade.side === 'buy') buyVolume += trade.volume;
    else sellVolume += trade.volume;
    currentVolume += trade.volume;

    if (currentVolume >= bucketSize) {
      totalImbalance += Math.abs(buyVolume - sellVolume);
      bucketCount++;
      buyVolume = 0;
      sellVolume = 0;
      currentVolume = 0;
    }
  }

  return bucketCount > 0 ? totalImbalance / (bucketCount * bucketSize) : 0;
};
VPIN（Volume-Synchronized Probability of Informed Trading）是度量信息驱动交易活跃程度的指标。高 VPIN 意味着知情交易者活跃，此时大额订单面临更大的逆向选择风险，应降低执行积极性或延迟交易。


小结
    

  • 不同订单类型在价格确定性、执行确定性和信息泄露之间提供不同权衡
    • 

  • 订单管理系统需要跟踪订单完整生命周期，处理部分成交、拒绝和超时等异常
    • 

  • 智能订单路由在多个执行场所间寻找最优成交，综合考虑价格、深度和费率
    • 

  • VPIN 等订单流指标帮助识别知情交易活跃期，动态调整执行策略
    • 

  • 大额订单的信息泄露是执行成本的重要来源，需要通过拆单和暗池路由来控制
    • 

  • 执行质量分析（TCA）是评估路由效果的标准方法，应纳入日常监控
