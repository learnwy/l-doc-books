过拟合防范

核心概念

过拟合是量化策略开发中最大的陷阱。当策略对历史数据的噪声而非真实规律进行了学习，回测表现优异但实盘一败涂地。过拟合的本质是模型复杂度超过了数据所能支撑的范围——参数越多、优化次数越多、策略越复杂，过拟合的风险就越高。

量化策略的过拟合问题比机器学习更为隐蔽，因为金融数据的信噪比极低（典型的日收益率信噪比约为0.05），而可用于验证的独立样本极其有限。一个看似优秀的回测结果可能只是数千次参数搜索中的偶然发现。

样本划分策略
正确的样本划分是防止过拟合的第一道防线。与机器学习中简单的训练集/测试集划分不同，金融时间序列的时间依赖性要求采用特殊的划分策略。


时间序列划分：必须按时间顺序划分，不能随机打乱。训练集用于策略开发，验证集用于参数调优，测试集用于最终评估且只能使用一次。


组合交叉验证（CPCV）：将时间序列分成多个连续的子段，通过不同的训练-测试组合生成多个回测结果，减少对特定时期的依赖。


interface SampleSplit {
  trainStart: number;
  trainEnd: number;
  validationStart: number;
  validationEnd: number;
  testStart: number;
  testEnd: number;
}

const timeSeriesSplit = (totalDays: number, trainPct = 0.6, validPct = 0.2): SampleSplit => {
  const trainEnd = Math.floor(totalDays * trainPct);
  const validEnd = Math.floor(totalDays * (trainPct + validPct));
  return {
    trainStart: 0,
    trainEnd,
    validationStart: trainEnd,
    validationEnd: validEnd,
    testStart: validEnd,
    testEnd: totalDays,
  };
};

interface CPCVConfig {
  numGroups: number;
  numTestGroups: number;
}

const combinatorialPurgedCV = (
  totalDays: number,
  config: CPCVConfig,
  purgeGap: number,
): { train: [number, number][]; test: [number, number] }[] => {
  const groupSize = Math.floor(totalDays / config.numGroups);
  const groups: [number, number][] = [];

  for (let i = 0; i < config.numGroups; i++) {
    groups.push([i * groupSize, Math.min((i + 1) * groupSize, totalDays)]);
  }

  const folds: { train: [number, number][]; test: [number, number] }[] = [];
  for (let testIdx = 0; testIdx < config.numGroups; testIdx++) {
    const trainGroups = groups
      .filter((_, i) => i !== testIdx)
      .filter((g) => {
        const testGroup = groups[testIdx];
        return g[1] + purgeGap < testGroup[0] || g[0] > testGroup[1] + purgeGap;
      });

    folds.push({ train: trainGroups, test: groups[testIdx] });
  }

  return folds;
};
多重检验校正
当在同一数据集上测试多个策略或多组参数时，纯属偶然也会产生看起来显著的结果。这就是多重比较问题——测试次数越多，出现假阳性的概率越高。


Bonferroni 校正是最保守的方法，将显著性水平除以测试次数。如果测试了100组参数，p值阈值从0.05降低到0.0005。


Holm-Bonferroni 方法是逐步校正，比 Bonferroni 更强大但仍然保守。Deflated Sharpe Ratio (DSR) 是专门为量化策略设计的校正方法，考虑了策略回测次数、收益偏度和峰度。


interface MultipleTestingResult {
  originalPValue: number;
  adjustedPValue: number;
  isSignificant: boolean;
  method: string;
}

const bonferroniCorrection = (pValues: number[], alpha = 0.05): MultipleTestingResult[] => {
  const m = pValues.length;
  return pValues.map((p) => ({
    originalPValue: p,
    adjustedPValue: Math.min(p * m, 1),
    isSignificant: p * m < alpha,
    method: 'bonferroni',
  }));
};

const deflatedSharpeRatio = (
  observedSharpe: number,
  numTrials: number,
  skewness: number,
  kurtosis: number,
  sampleSize: number,
): { dsr: number; pValue: number; isLikelyOverfit: boolean } => {
  const expectedMaxSharpe =
    Math.sqrt(2 * Math.log(numTrials)) -
    (Math.log(Math.PI) + Math.log(Math.log(numTrials))) / (2 * Math.sqrt(2 * Math.log(numTrials)));

  const sharpeStdErr = Math.sqrt(
    (1 + 0.5 * observedSharpe ** 2 - skewness * observedSharpe + ((kurtosis - 3) / 4) * observedSharpe ** 2) /
      (sampleSize - 1),
  );

  const zStat = (observedSharpe - expectedMaxSharpe) / (sharpeStdErr || 1);
  const pValue = 1 - normalCDF(zStat);

  return {
    dsr: zStat,
    pValue,
    isLikelyOverfit: pValue > 0.05,
  };
};

const normalCDF = (x: number): number => {
  const a1 = 0.254829592;
  const a2 = -0.284496736;
  const a3 = 1.421413741;
  const a4 = -1.453152027;
  const a5 = 1.061405429;
  const p = 0.3275911;
  const sign = x < 0 ? -1 : 1;
  const absX = Math.abs(x);
  const t = 1.0 / (1.0 + p * absX);
  const y = 1.0 - ((((a5 * t + a4) * t + a3) * t + a2) * t + a1) * t * Math.exp((-absX * absX) / 2);
  return 0.5 * (1.0 + sign * y);
};
参数稳定性分析
参数稳定性分析检验策略性能对参数变化的敏感程度。如果微小的参数调整导致性能剧变，说明策略很可能是过拟合的产物。


网格搜索热力图将两个关键参数的不同取值组合的策略表现可视化。理想情况下，最优参数周围应该形成一个"高原"而非"山峰"——高原意味着策略对参数不敏感，山峰意味着严重过拟合。


interface ParameterSensitivity {
  paramName: string;
  values: number[];
  performances: number[];
  sensitivity: number;
  isStable: boolean;
}

const analyzeParameterSensitivity = (
  basePerformance: number,
  paramName: string,
  paramValues: number[],
  performances: number[],
  stabilityThreshold = 0.3,
): ParameterSensitivity => {
  const maxPerf = Math.max(...performances);
  const minPerf = Math.min(...performances);
  const range = maxPerf - minPerf;
  const sensitivity = basePerformance > 0 ? range / basePerformance : Infinity;

  return {
    paramName,
    values: paramValues,
    performances,
    sensitivity,
    isStable: sensitivity < stabilityThreshold,
  };
};

interface GridSearchResult {
  param1Name: string;
  param2Name: string;
  param1Values: number[];
  param2Values: number[];
  performanceMatrix: number[][];
  optimalParam1: number;
  optimalParam2: number;
  plateauRatio: number;
}

const evaluateGridPlateau = (performanceMatrix: number[][], optimalPerformance: number, tolerancePct = 0.1): number => {
  const threshold = optimalPerformance * (1 - tolerancePct);
  let totalCells = 0;
  let plateauCells = 0;
  for (const row of performanceMatrix) {
    for (const perf of row) {
      totalCells++;
      if (perf >= threshold) plateauCells++;
    }
  }
  return plateauCells / totalCells;
};
当高原比率（plateauRatio）低于15%时，策略大概率存在过拟合。稳健的策略通常在30%以上的参数空间中保持接近最优的表现。


白色现实检验
White's Reality Check 和 Hansen's Superior Predictive Ability (SPA) 测试是检验策略是否显著优于基准的统计方法。它们通过 Bootstrap 重采样生成基准策略的表现分布，然后检验目标策略是否显著优于该分布。


interface RealityCheckResult {
  testStatistic: number;
  pValue: number;
  bootstrapDistribution: number[];
  isSignificant: boolean;
  numBootstraps: number;
}

const whitesRealityCheck = (
  strategyReturns: number[],
  benchmarkReturns: number[],
  numBootstraps = 1000,
  blockSize = 10,
): RealityCheckResult => {
  const excessReturns = strategyReturns.map((r, i) => r - benchmarkReturns[i]);
  const observedMean = excessReturns.reduce((a, b) => a + b, 0) / excessReturns.length;

  const bootstrapMeans: number[] = [];
  const n = excessReturns.length;

  for (let b = 0; b < numBootstraps; b++) {
    const sample: number[] = [];
    while (sample.length < n) {
      const start = Math.floor(Math.random() * (n - blockSize));
      sample.push(...excessReturns.slice(start, start + blockSize));
    }
    const bMean = sample.slice(0, n).reduce((a, b) => a + b, 0) / n;
    bootstrapMeans.push(bMean);
  }

  bootstrapMeans.sort((a, b) => a - b);
  const pValue = bootstrapMeans.filter((m) => m >= observedMean).length / numBootstraps;

  return {
    testStatistic: observedMean,
    pValue,
    bootstrapDistribution: bootstrapMeans,
    isSignificant: pValue < 0.05,
    numBootstraps,
  };
};
小结
    

  • 过拟合是量化策略开发中最大的陷阱，金融数据的低信噪比使问题更加隐蔽
    • 

  • 正确的时间序列样本划分和只能使用一次的测试集是基本防线
    • 

  • 多重检验校正（特别是 Deflated Sharpe Ratio）可以量化策略发现的统计可靠性
    • 

  • 参数稳定性分析通过高原比率判断策略是否对参数过度敏感
    • 

  • White's Reality Check 通过 Bootstrap 检验策略是否显著优于随机基准
    • 

  • 保持策略简单性、限制参数数量、要求经济学逻辑支撑是最有效的防过拟合原则
    •
