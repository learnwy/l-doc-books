回测框架

核心概念

回测框架是量化交易系统的核心基础设施，它通过历史数据模拟策略的实际运行来评估策略的有效性。一个高质量的回测框架需要在历史重现的准确性和计算效率之间取得平衡，同时避免各种偏差的引入。

回测的本质是"如果过去使用这个策略会怎样"的反事实推理。关键挑战在于让模拟尽可能接近真实交易环境——包括成交价格、交易成本、市场冲击、流动性约束和信息时序。

事件驱动回测引擎
事件驱动回测引擎是生产级量化系统的标准架构。它将回测过程建模为一系列按时间排序的事件（行情事件、信号事件、订单事件、成交事件），通过事件队列驱动策略逻辑的执行。


事件驱动架构的核心优势在于：回测代码和实盘代码可以共用同一套策略逻辑，只需替换数据源和执行模块。


type EventType = 'market_data' | 'signal' | 'order' | 'fill' | 'timer';

interface Event {
  type: EventType;
  timestamp: number;
  payload: unknown;
}

interface MarketDataEvent extends Event {
  type: 'market_data';
  payload: {
    symbol: string;
    price: number;
    volume: number;
    bid: number;
    ask: number;
  };
}

interface BacktestEngine {
  eventQueue: Event[];
  strategy: Strategy;
  broker: SimulatedBroker;
  portfolio: Portfolio;
  run(startDate: Date, endDate: Date): BacktestResult;
}

interface Strategy {
  onMarketData(event: MarketDataEvent, portfolio: Portfolio): Order[];
  onFill(fill: Fill, portfolio: Portfolio): void;
  onTimer(timestamp: number, portfolio: Portfolio): Order[];
}

interface SimulatedBroker {
  submitOrder(order: Order, marketData: MarketDataEvent): Fill | null;
  slippageModel: SlippageModel;
  commissionModel: CommissionModel;
}

interface Portfolio {
  cash: number;
  positions: Map<string, Position>;
  equity: number;
  history: PortfolioSnapshot[];
}

interface Position {
  symbol: string;
  quantity: number;
  avgCost: number;
  marketValue: number;
  unrealizedPnl: number;
}

const createBacktestEngine = (strategy: Strategy, config: BacktestConfig): BacktestEngine => {
  const broker: SimulatedBroker = {
    slippageModel: config.slippageModel,
    commissionModel: config.commissionModel,
    submitOrder: (order, marketData) => {
      const price = simulateFillPrice(order, marketData, config.slippageModel);
      const commission = config.commissionModel.calculate(order, price);
      return {
        orderId: order.id,
        symbol: order.symbol,
        quantity: order.quantity,
        price,
        commission,
        timestamp: marketData.timestamp,
      };
    },
  };

  const portfolio: Portfolio = {
    cash: config.initialCapital,
    positions: new Map(),
    equity: config.initialCapital,
    history: [],
  };

  return {
    eventQueue: [],
    strategy,
    broker,
    portfolio,
    run: (startDate, endDate) => runBacktest(strategy, broker, portfolio, config, startDate, endDate),
  };
};
成交模拟与成本建模
回测结果的可信度很大程度上取决于成交模拟的真实性。过于乐观的成交假设会导致回测结果远好于实盘表现，这是量化新手最常犯的错误。


滑点模型模拟实际成交价格与信号价格的偏差。常见的滑点模型包括固定滑点、比例滑点和基于成交量的冲击模型。


interface SlippageModel {
  calculate(order: Order, marketData: MarketDataEvent): number;
}

interface CommissionModel {
  calculate(order: Order, fillPrice: number): number;
}

const fixedSlippage = (bps: number): SlippageModel => ({
  calculate: (order, md) => {
    const direction = order.side === 'buy' ? 1 : -1;
    return md.payload.price * (1 + (direction * bps) / 10000);
  },
});

const volumeImpactSlippage = (impactCoeff: number): SlippageModel => ({
  calculate: (order, md) => {
    const participation = order.quantity / (md.payload.volume || 1);
    const impact = impactCoeff * Math.sqrt(participation);
    const direction = order.side === 'buy' ? 1 : -1;
    return md.payload.price * (1 + direction * impact);
  },
});

const spreadSlippage = (): SlippageModel => ({
  calculate: (order, md) => {
    return order.side === 'buy' ? md.payload.ask : md.payload.bid;
  },
});

interface Fill {
  orderId: string;
  symbol: string;
  quantity: number;
  price: number;
  commission: number;
  timestamp: number;
}

interface Order {
  id: string;
  symbol: string;
  side: 'buy' | 'sell';
  quantity: number;
  type: 'market' | 'limit';
  limitPrice?: number;
}

interface BacktestConfig {
  initialCapital: number;
  slippageModel: SlippageModel;
  commissionModel: CommissionModel;
  dataFrequency: 'tick' | 'minute' | 'daily';
}

const simulateFillPrice = (order: Order, md: MarketDataEvent, slippageModel: SlippageModel): number => {
  if (order.type === 'limit' && order.limitPrice !== undefined) {
    const canFill = order.side === 'buy' ? md.payload.price <= order.limitPrice : md.payload.price >= order.limitPrice;
    return canFill ? order.limitPrice : -1;
  }
  return slippageModel.calculate(order, md);
};
回测偏差识别与消除
回测中的偏差是导致策略实盘表现远逊于回测结果的主要原因。识别和消除这些偏差是构建可靠回测系统的关键。


前视偏差（Look-Ahead Bias）：使用了回测时间点之后才能获得的信息。例如使用当天收盘价计算信号并以收盘价成交，或使用未来才发布的财报数据。


幸存者偏差（Survivorship Bias）：只使用存续至今的资产数据，忽略了退市、被收购的资产。这会导致历史表现被高估。


数据窥探偏差（Data Snooping Bias）：反复在同一数据集上测试和优化策略参数，最终找到的"最优"参数可能只是对历史数据的过拟合。

interface PointInTimeData {
  asOfDate: Date;
  reportDate: Date;
  symbol: string;
  field: string;
  value: number;
}

const getFactorValue = (
  pitDatabase: PointInTimeData[],
  symbol: string,
  field: string,
  asOfDate: Date,
): number | null => {
  const available = pitDatabase
    .filter((d) => d.symbol === symbol && d.field === field && d.reportDate <= asOfDate)
    .sort((a, b) => b.reportDate.getTime() - a.reportDate.getTime());

  return available.length > 0 ? available[0].value : null;
};
回测报告生成
一份完整的回测报告不仅展示收益曲线，还需要包含风险指标、交易统计、时期分析和压力测试结果，为策略决策提供全面信息。


interface BacktestResult {
  equityCurve: { date: Date; equity: number }[];
  trades: TradeRecord[];
  metrics: PerformanceMetrics;
  monthlyReturns: Map<string, number>;
  drawdowns: DrawdownRecord[];
}

interface PerformanceMetrics {
  totalReturn: number;
  annualizedReturn: number;
  sharpeRatio: number;
  sortinoRatio: number;
  maxDrawdown: number;
  maxDrawdownDuration: number;
  winRate: number;
  profitFactor: number;
  averageTrade: number;
  totalTrades: number;
  annualizedTurnover: number;
}

interface TradeRecord {
  symbol: string;
  side: 'buy' | 'sell';
  entryDate: Date;
  exitDate: Date;
  entryPrice: number;
  exitPrice: number;
  quantity: number;
  pnl: number;
  holdingDays: number;
}

interface DrawdownRecord {
  startDate: Date;
  endDate: Date;
  recoveryDate: Date | null;
  depth: number;
  duration: number;
}

const generateReport = (result: BacktestResult): string => {
  const m = result.metrics;
  const lines = [
    `年化收益率: ${(m.annualizedReturn * 100).toFixed(2)}%`,
    `夏普比率: ${m.sharpeRatio.toFixed(2)}`,
    `索提诺比率: ${m.sortinoRatio.toFixed(2)}`,
    `最大回撤: ${(m.maxDrawdown * 100).toFixed(2)}%`,
    `最长回撤天数: ${m.maxDrawdownDuration}`,
    `胜率: ${(m.winRate * 100).toFixed(1)}%`,
    `盈亏比: ${m.profitFactor.toFixed(2)}`,
    `总交易次数: ${m.totalTrades}`,
    `年化换手率: ${(m.annualizedTurnover * 100).toFixed(1)}%`,
  ];
  return lines.join('\n');
};
小结
    

  • 事件驱动回测引擎是生产级系统的标准架构，可实现回测与实盘代码复用
    • 

  • 成交模拟的真实性直接决定回测结果的可信度，需要建模滑点、手续费和市场冲击
    • 

  • 前视偏差、幸存者偏差和数据窥探偏差是最危险的三类回测偏差
    • 

  • Point-in-time 数据库是消除前视偏差的关键技术手段
    • 

  • 完整的回测报告应包含收益指标、风险指标、交易统计和时期分析
    • 

  • 对回测结果保持怀疑态度，实盘表现通常低于回测结果20-40%
